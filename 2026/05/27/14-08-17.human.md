This is the 5th patch in Christian Couder's 8-part series adding URL-based auto-configuration for promisor remotes, building on the previously approved LOP (Large Object Promisors) series. The patch introduces the core functionality for `promisor.acceptFromServerUrl` configuration.

The patch adds infrastructure to:
- Parse and validate URL patterns with optional remote name prefixes
- Store the parsed patterns in a new `allowed_url` struct
- Handle memory management for the pattern data
- Add basic test coverage for invalid configurations

Key technical details:
- URL patterns can optionally be prefixed with a remote name (e.g. "myremote=https://example.com/*")
- Strict validation ensures remote names and URLs are well-formed
- The new `url_normalize_pattern()` helper handles glob patterns in URLs
- Warnings are emitted for invalid configurations
- Test case verifies rejection of invalid remote names with spaces

The implementation is clean and well-structured, with proper error handling and memory management. The test case provides good coverage of the validation logic. This is a solid technical foundation for the subsequent patches that will implement the actual URL matching and remote creation.

As part of a larger effort to improve promisor remote functionality, this patch series has already undergone multiple rounds of review and appears ready for merging. The changes since v3 were minor documentation fixes that have now been addressed.
