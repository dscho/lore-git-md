This is a brief maintainer comment on the proposed `git mv --index-only` feature. Junio C Hamano weighs in on the technical discussion, confirming Chris Torek's observation that the same effect can be achieved with existing `git add`/`git rm` commands. 

Junio clarifies the efficiency aspect - noting that while a dedicated flag might save one index write operation, it wouldn't fundamentally change the rename detection behavior. He draws a parallel to the existing `git rm --cached` workflow for correcting accidental filesystem deletions, suggesting the proposed feature could serve a similar "morning-after" purpose for moves.

The maintainer's tone suggests openness to the feature as a convenience wrapper, though he doesn't explicitly endorse it. His framing positions this as a potential quality-of-life improvement rather than a technical necessity, while acknowledging the conceptual similarity to existing correction mechanisms in Git. The comment keeps the door open for further discussion while reinforcing that the core functionality already exists.
