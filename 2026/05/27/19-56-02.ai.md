This is the fifth patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem, introducing an object position cache to reduce repeated lookups during bitmap generation.

The patch adds a direct-mapped cache that stores object ID to bit position mappings, sized dynamically based on repository size (between 1K and 2M entries). The cache shows a 9.4% speed improvement in the test repository (~57M objects), reducing runtime from 324.8s to 294.1s. The implementation includes:
- A 40-byte cache entry struct storing OID and position
- Cache hit/miss counters tracked via trace2 metrics
- Bounded memory usage (max 80MB for largest repos)
- Careful handling of cache invalidation and position storage

The change builds on previous optimizations in the series (tree recursion elimination and bitmap reuse) by targeting the hot path of object position lookups. As with earlier patches, Jeff King has reviewed the technical approach. This is a mechanical but impactful optimization that enables further reductions in the remaining patches of the series.
