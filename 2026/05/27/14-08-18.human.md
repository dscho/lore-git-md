This is part 6/8 of Christian Couder's URL-based auto-configuration series for promisor remotes, now in its final version (v4) and ready for merging. The patch implements URL pattern matching to securely allow updates from trusted promisor remotes even when the default security setting (`promisor.acceptFromServer=none`) would otherwise reject them.

The key addition is a new `url_matches_accept_list()` helper that checks server-advertised URLs against configured glob patterns in `promisor.acceptFromServerUrl`. The matching is strict:
- Scheme and port must match exactly
- Host and path components use wildmatch() with proper boundary constraints
- URLs are normalized before comparison to prevent bypass attempts
- Credentials in URLs are ignored to allow rotation

The patch also:
- Documents the security implications and best practices for URL patterns
- Explains the precedence rules between `acceptFromServer` and `acceptFromServerUrl`
- Adds comprehensive tests for various matching scenarios
- Maintains strict security by rejecting URL mismatches even for allowlisted patterns

This enables organizations to configure broad URL patterns (like `https://my-org.com/*`) while keeping the default security level, rather than having to relax to `acceptFromServer=knownUrl` globally. The implementation is now complete with all prior review feedback addressed, including proper URL normalization, clear documentation, and thorough test coverage.
