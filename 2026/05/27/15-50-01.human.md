Performance optimization for revision walking (part 2/3).

This patch from Kristofer Karlsson introduces a `rev_walk_mode` enum to clarify the dispatch logic in `get_revision_1()`, which currently uses a combination of `rev_info` flags to select different walk strategies. The change makes the code more maintainable by:

1. Consolidating the mode selection into a single `get_walk_mode()` helper
2. Using the same mode variable for both commit selection and parent expansion
3. Making it obvious that all modes are handled consistently

The patch is purely a refactoring with no functional changes, preparing for the upcoming priority queue conversion in patch 3. The enum clearly shows the four walk strategies: reflog, topological, limited, and streaming. This structural improvement should make the subsequent performance optimization easier to verify and maintain.

The change follows the pattern established in the first patch of the series (a memory leak fix) by being careful and incremental. It demonstrates good attention to code quality while working toward the larger goal of optimizing revision walking performance.
