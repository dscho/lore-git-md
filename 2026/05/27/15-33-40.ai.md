This is a follow-up to the promisor remote configuration series, specifically Junio's naming consistency feedback on the auto-generated remote name handling.

Christian Couder responds to Junio's review of v3 patch 4/8, which added local name tracking for promisor remotes. Junio had noted the naming inconsistency where the same helper function's return value was stored in variables called both "remote_name" and "local" in different parts of the code, suggesting `promisor_info_local_name()` would be clearer than `promisor_info_internal_name()`.

Christian confirms he has addressed this in v4 by:
1. Renaming the helper function to `promisor_info_local_name()`
2. Consistently using "remote_name" as the variable name in both call sites

This change improves code clarity while maintaining the same functionality. The response is brief and to-the-point, indicating this was a straightforward naming polish in an otherwise technically complete series. The thread context shows this was one of the final refinements before merging, with both the LOP and URL-based auto-configuration series now fully reviewed and approved.
