Feature patch (4/8) in Christian Couder's URL-based promisor remote auto-configuration series, now ready for merging. This patch introduces a `local_name` field to `struct promisor_info` to handle cases where the locally configured remote name differs from the server-advertised name.

The change prepares for upcoming commits that will auto-generate remote names (prefixed with `promisor-auto-`) when using URL pattern matching. A new helper function `promisor_info_local_name()` returns the appropriate name (local if set, otherwise the advertised name), which is used consistently for configuration lookups. The patch updates documentation to clarify the distinction between advertised and local names.

This is a mechanical but necessary change in the series that has already been reviewed and approved. It follows the same careful approach seen in previous patches, with clear documentation updates and thorough consideration of all code paths that need to handle the name distinction. The implementation maintains security by ensuring configuration operations use the correct remote name in all contexts.
