This RFC proposes a new `--word-diff-align` option to better highlight small edits within moved code blocks, addressing a gap between Git's existing `--word-diff` and `--color-moved` features. The author presents compelling real-world examples where current diff output obscures meaningful edits within relocated code, such as CPython metadata changes and Git test table modifications.

The prototype takes a language-neutral approach, tokenizing lines and scoring matches within a 5-line window to pair similar deleted/inserted lines. The RFC includes core matching logic, a temporary visualization renderer, and test cases, while acknowledging several rough edges in the current implementation. Initial testing shows the technique detects meaningful edits in about 13% of sampled diffs from major projects.

The author is specifically seeking feedback on whether this direction warrants further development in core Git. The thorough presentation - with both implementation details and visual examples - makes this an easy proposal to evaluate. While the scoring model and UI would need refinement, the core concept appears well-motivated and the technical approach seems sound for an initial prototype.
