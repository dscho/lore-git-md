This is a platform compatibility patch addressing a macOS linker warning. The change initializes the `packet_buffer` global variable in pkt-line.c to avoid alignment-related warnings during linking on macOS. The warning occurs because the uninitialized large buffer (LARGE_PACKET_MAX is 65520 bytes) triggers alignment constraints that exceed macOS segment limits.

The fix is straightforward - changing from an uninitialized declaration to an explicitly zero-initialized array. This appears to be a legitimate platform-specific issue rather than a theoretical concern, as evidenced by the multiple repeated warnings shown in the build output. The patch is small, focused, and clearly motivated by an actual build-time observation.

For future reference in this thread: the change touches the pkt-line subsystem's global buffer used for network packet handling, modifying the declaration in pkt-line.c to initialize the array to zeros. This may be relevant if follow-up discussion questions whether zero-initialization has any behavioral impact (though the existing code appears to always write to the buffer before reading).
