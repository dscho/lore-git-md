This is an RFC proposal for a new diff feature that aims to better highlight edited lines within moved blocks of code. The series introduces a prototype `--word-diff-align` option that attempts to pair similar deleted and inserted lines within moved sections, making small edits more visible during code review.

The key motivation is addressing the gap between `--word-diff` (which shows word-level changes) and `--color-moved` (which highlights moved blocks) - when a block is moved with small internal edits, those edits can get lost in the noise. The author provides several real-world examples where this occurs, including CPython metadata renumbering and Git's own test output tables.

The implementation takes a language-agnostic approach, tokenizing lines and scoring pairs based on token overlap within a 5-line window. The RFC includes:
1. Core line pairing logic
2. A temporary renderer to visualize the matches
3. A focused test case

The author acknowledges several limitations in the current state, including rough edges in the UI and scoring thresholds, and is specifically seeking feedback on whether this direction is worth pursuing in core Git. The prototype has shown promising results in initial testing, detecting meaningful edits in about 13% of sampled diffs from Git, CPython and Rust.

This appears to be a well-motivated contribution with clear real-world use cases. The RFC is thorough, including both technical details and visual examples, making it easy to evaluate the proposal. The implementation approach seems reasonable for an initial prototype, though the scoring model and UI would likely need refinement based on community feedback.
