This is the 7th patch in Christian Couder's 8-part series adding URL-based auto-configuration for promisor remotes, now in its 4th iteration. The series is technically complete and ready for merging, having addressed all prior review feedback.

The patch implements automatic remote creation when a server advertises an unknown promisor remote whose pattern matches the `promisor.acceptFromServerUrl` config. Key features:

- New helpers sanitize URLs into valid remote names (prefixed with "promisor-auto-") and handle name collisions by appending numeric suffixes
- The system preserves the originally advertised name in `remote.<name>.advertisedAs` for debugging
- Comprehensive tests verify auto-creation, named remotes, collision handling, and reuse of existing remotes with matching URLs
- Documentation explains the naming rules and security implications

The implementation builds on earlier patches in the series that introduced URL pattern matching and validation. This final piece eliminates the manual configuration burden while maintaining the security constraints established in previous patches.

The series has received thorough review from Patrick Steinhardt, Toon Claes, and Junio Hamano, with all technical feedback addressed. This patch in particular completes the user-facing functionality while keeping the robust security model intact.
