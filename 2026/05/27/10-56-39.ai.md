Bugfix discussion regarding zombie processes in containerized Git operations.

Jeff King (Peff) follows up on SURA's report about zombie processes accumulating during `git fetch` in container environments where Git runs as PID 1. While agreeing that using an init process like `tini` is the correct solution, Peff investigates whether recent Git changes have increased zombie generation.

The analysis traces behavior changes through Git versions: pre-2.29 used `git gc --auto` which would check before detaching, 2.29-2.47 used `git maintenance` without immediate detach, and post-2.47 `git maintenance` detaches immediately before checking tasks. This means every fetch now spawns a detached maintenance process that must be reaped by the init system, whereas previously many cases would complete synchronously.

Peff suggests a potential optimization where `git maintenance` could check task necessity before detaching, similar to the old `git gc` behavior, but notes this may not be practical for all maintenance tasks. The current behavior is deemed acceptable when using a proper init process, though it does represent a minor performance regression in fork frequency compared to pre-2.47 versions.

This is a substantive technical follow-up that identifies the specific version transitions affecting process handling while maintaining that the root issue (running as PID 1 without a proper init) should be addressed at the container configuration level rather than within Git itself.
