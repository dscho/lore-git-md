Performance optimization follow-up for `git fetch` connectivity checks.

Jeff King (Peff) raises a technical question about the recently proposed `git fetch` optimization patch from Kristofer Karlsson. While agreeing with the principle of the change, Peff notes that the `self_contained_and_connected` optimization flag is only set during clone operations, not regular fetches. This suggests the optimization may not actually activate in the fetch case as intended, despite the transport parameter being made available.

The question probes whether there's an undocumented code path enabling this optimization for fetches, or if the patch's benefits might be limited to clone scenarios. This is a substantive technical review point - Peff is tracing the control flow of the optimization flag through the transport layer to verify the claimed behavior actually occurs in practice.

The exchange represents the final quality check before this performance improvement can be merged. Kristofer will need to either identify the fetch-specific code path that enables the optimization, or clarify that the patch is preparatory work for future fetch optimizations rather than an immediate win. Either way, this is exactly the sort of deep technical review that helps ensure Git changes work as intended across all scenarios.
