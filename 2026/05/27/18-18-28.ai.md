This is a bugfix series addressing network address handling issues in Git's daemon mode, now in its second version. The patches fix three related problems in `daemon.c`:

1. IPv6 address corruption when `getaddrinfo()` returns IPv6 results but the code incorrectly assumes IPv4, reading from the wrong struct offset. The fix properly handles both AF_INET and AF_INET6 address families.

2. IPv6 address truncation where the sockaddr struct size was incorrectly used as the output buffer size for `inet_ntop()`, causing silent truncation of long IPv6 addresses. The fix uses the proper buffer size constant.

3. A NULL pointer safety issue when logging connection details if the REMOTE_PORT environment variable is unset, adding a NULL check and fallback string.

Changes since v1 include splitting the single patch into three commits (as suggested by Patrick Steinhardt), deduplicating address family handling in `lookup_hostname()`, and adding explicit handling for unexpected address families. The series maintains IPv4 behavior while fixing IPv6 issues and touches only `daemon.c` with straightforward changes.

The fixes address clear correctness issues that could cause misbehavior on IPv6-only hosts or crashes from NULL pointer dereferences. Both Junio C Hamano and Patrick Steinhardt have reviewed the technical approach positively in previous iterations, with Junio noting the `(void *)` casting style as "cute" but valid. The series appears ready for merging pending any final verification on IPv6-only configurations.
