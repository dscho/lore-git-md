Final version of promisor remote auto-configuration feature

This is the fourth and final iteration of Christian Couder's series that adds URL-based auto-configuration for promisor remotes. The feature allows clients to automatically configure promisor remotes based on URL patterns via a new `promisor.acceptFromServerUrl` config option, rather than requiring manual pre-configuration.

The series has undergone thorough review from multiple contributors (Toon Claes, Patrick Steinhardt, Junio C Hamano) and is now technically complete. Key security aspects include strict URL pattern matching rules, auto-generated remote name sanitization, and collision handling to prevent remote hijacking. The implementation touches `promisor-remote.[ch]` and `urlmatch.[ch]` with extensive test coverage in `t5710-promisor-remote-capability.sh`.

Changes since v3 are minor - renaming a function for clarity (`promisor_info_internal_name` to `promisor_info_local_name`) and fixing some documentation formatting. The series is rebased on master and ready for merging, representing a significant usability improvement for promisor remote workflows while maintaining strong security defaults.

This completes the URL-based auto-configuration feature alongside the previously approved LOP (Large Object Promisors) series, marking substantial progress in promisor remote functionality. Only two minor documentation formatting issues identified by Kristoffer Haugsbakk remain as optional fixes.
