This is the second patch in a bugfix series addressing network address handling issues in Git's daemon mode. The patch specifically fixes IPv6 address truncation in logging by correcting the buffer size passed to `inet_ntop()`.

The key change replaces the use of `ai_addrlen` (which is the size of the sockaddr struct) with `sizeof(ip)` (the actual buffer size) when calling `inet_ntop()`. This prevents silent truncation of IPv6 addresses, which require a 46-byte buffer (INET6_ADDRSTRLEN) rather than the 28-byte sockaddr_in6 struct size. The patch also simplifies the `ip2str()` function by removing its now-unused length parameter and updates all callers accordingly.

This is a straightforward technical correction that improves correctness when logging IPv6 connections. The change has already received positive reviews from both Junio C Hamano and Patrick Steinhardt in previous iterations of the series. The patch maintains backward compatibility with IPv4 while properly handling IPv6 addresses, and since it only affects logging output, there's no protocol or on-disk format impact.

The series appears to be in good shape, with this patch representing one of three focused fixes for daemon mode network handling. The only remaining open question from reviewers is whether additional test coverage for IPv6-only configurations would be valuable.
