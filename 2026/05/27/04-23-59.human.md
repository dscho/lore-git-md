This is an RFC proposal for a new diff feature that aims to better highlight edited lines within moved blocks of code. The series from Keita ODA introduces a prototype `--word-diff-align` option that attempts to pair similar deleted and inserted lines within moved sections, making small edits more visible during code review.

The core motivation is addressing a gap between `--word-diff` (which shows word-level changes) and `--color-moved` (which highlights moved blocks) - when a block is moved with small internal edits, those edits can get lost in the noise. The author provides several real-world examples where this occurs, including CPython metadata renumbering and Git's own test output tables.

The implementation takes a language-agnostic approach, tokenizing lines and scoring potential matches based on token overlap within a 5-line window. The RFC includes:
1. Core line-pairing logic
2. A temporary renderer to visualize the matches
3. A focused test case

The author acknowledges several limitations in the current state (debug output, handling of boilerplate-heavy code) and is specifically seeking feedback on whether this direction is worth pursuing in core Git, and if so, how it should integrate with existing diff options. Example outputs are provided at an external link for comparison with current diff modes.

This appears to be a well-motivated proposal with clear technical merit, particularly for code review scenarios where moved-and-modified blocks are common. The 13% trigger rate in the author's sample suggests it would provide value across a meaningful portion of real-world diffs. The RFC approach - with its explicit separation of experimental components - seems well-considered for gathering early feedback.
