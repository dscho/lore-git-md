Feature patch that completes the promisor remote auto-configuration functionality, now ready for merging.

This is the 7th patch in Christian Couder's 8-part series adding URL-based auto-configuration for promisor remotes. The series builds on the previously approved LOP (Large Object Promisors) work and has undergone thorough review from Patrick Steinhardt, Toon Claes, and Junio C Hamano.

The patch implements automatic remote creation when a server advertises an unknown remote whose URL matches a `promisor.acceptFromServerUrl` pattern. Key technical components include:

- `sanitize_remote_name()` helper that safely converts URLs into valid remote names by replacing non-alphanumeric characters and prepending "promisor-auto-"
- `promisor_remote_name_from_url()` that normalizes URLs and extracts host+port+path components
- Collision handling that appends numeric suffixes (-1, -2) when names conflict
- Configuration of `remote.<name>.advertisedAs` to track the server's original name
- Comprehensive test coverage in t5710 for various auto-configuration scenarios

The implementation maintains strict security by:
- Requiring explicit URL pattern matching
- Preventing remote name hijacking through collision detection
- Preserving existing remote configurations when URLs differ
- Documenting security considerations in promisor.adoc

Changes since previous versions are minimal, focused on final documentation polish and test coverage. The series is now technically complete and ready for integration alongside the previously approved LOP work.
