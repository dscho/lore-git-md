Thread identity: Refactoring patch to commit-reach.c removing redundant sorting in `paint_down_to_common()`, authored by René Scharfe.

Core problem: The commit reachability function `paint_down_to_common()` was performing an unnecessary date-based sort of its result list, even though none of its three callers (`merge_bases_many()`, `remove_redundant_no_gen()`, and `repo_in_merge_bases_many()`) require sorted output. This was wasted computation.

Current status: Single patch removing one line of code (the sort operation). Jeff King (Peff) has reviewed the change positively noting it as an "easy win" while suggesting potential follow-up to optimize further by having callers pass NULL when they don't need the result list, though he acknowledges merge base lists are typically small so gains would be minimal.

Key technical details: Touches `commit-reach.c`, specifically the `paint_down_to_common()` function which is part of Git's commit graph traversal machinery. The change removes a `commit_list_sort_by_date()` call that was redundant because:
1. `merge_bases_many()` re-sorts the list anyway
2. The other two callers don't care about list order
Peff's review suggests the API could potentially be refined further to avoid list allocation when callers don't need results.
