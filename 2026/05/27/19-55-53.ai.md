This is the second patch in Taylor Blau's 8-part performance optimization series for the pack-bitmap-write subsystem. The patch builds on the previous commit's refactoring of `fill_bitmap_tree()` to now check subtree bits before recursing, avoiding unnecessary stack frame setup when a tree's bit position is already set.

The key optimization moves the bitmap check earlier in the traversal path, which yields a 3.4% speedup (582.4s->562.8s) in test repositories by reducing instruction count by 2.8% (2.415B->2.348B). The change is particularly effective because it optimizes a hot path in the bitmap generation code.

The patch modifies both `fill_bitmap_tree()` and its caller `fill_bitmap_commit()` to check bitmap positions before proceeding with tree parsing and recursion. This follows naturally from the first patch's introduction of position lookups before tree loading, and enables further optimizations in the series while providing standalone benefits.

Jeff King (Peff) has already reviewed the v1 version of this series, confirming the performance improvements while noting some surprise at their magnitude given the change's theoretical neutrality. The v2 iteration maintains the same core optimizations with minor refinements. The patch demonstrates Taylor's deep expertise in the pack/bitmap subsystems and continues his ongoing work to improve large repository performance.
