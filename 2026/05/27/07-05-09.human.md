This is a performance optimization patch from Kristofer Karlsson that revives an older discussion about improving `git branch --contains` performance. The patch enables a cached DFS algorithm (`contains_tag_algo`) for branch operations when commit-graph generation numbers are available, which was previously only used for tags.

The key improvements are substantial speedups in large repositories:
- In git.git (69K commits), a 3.7x speedup for deep commits (1.08s → 292ms)
- In a large monorepo, 15-16x speedup for deep history queries (4.14s → 272ms)

The optimization is particularly effective when querying many refs (performance scales with ref count) and for deeper commits. Kristofer provides detailed benchmark methodology and shows the cached algorithm is never worse than the current implementation when generation numbers exist. The patch builds on Jeff King's earlier investigation into this optimization opportunity.

This appears to be a well-motivated optimization with clear, measurable benefits for a real-world use case (large monorepos with many remote branches). The analysis is thorough testing across different repository sizes and ref counts, and the implementation leverages existing infrastructure (commit-graph generation numbers) in a way that maintains correctness while improving performance.
