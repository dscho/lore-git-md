This is the first patch in a 3-part RFC series proposing a new `--word-diff-align` feature for Git's diff output. The feature aims to better highlight edits within moved blocks of code by pairing similar deleted and inserted lines.

The core implementation in this patch:
- Adds line pairing logic that tokenizes lines and scores potential matches based on token overlap within 5-line windows
- Uses a fingerprinting system to efficiently find candidate pairs without full all-pairs scanning
- Scores matches using a window similarity score (W) plus a weighted line similarity score (4L)
- Currently marks matches with debug-style comments showing the alignment details

The approach is language-agnostic, working at the token level rather than understanding specific languages. The patch includes extensive infrastructure for tokenization, fingerprinting, scoring, and matching, though the actual UI for displaying the alignments will come in subsequent patches.

Key technical aspects:
- Operates as a post-process on the diff output rather than modifying the core diff algorithm
- Uses EWAH bitmaps for efficient set operations
- Has tunable parameters for window size, scoring thresholds, and weights
- Handles both exact matches and edited lines within moved blocks

The implementation appears thorough and well-structured, with clear separation between the matching logic and display components. The scoring model seems reasonable for an initial prototype, though likely needs refinement based on real-world usage. The patch maintains good separation from existing diff functionality while reusing appropriate infrastructure like the emitted symbols system.

This represents a significant addition to Git's diff capabilities, filling a noticeable gap between word-level diffs and block movement detection. The implementation approach shows careful consideration of both accuracy and performance tradeoffs.
