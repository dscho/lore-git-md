This is the seventh patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem, focusing on pseudo-merge bitmap handling. The series has already demonstrated significant speedups (60.1% faster bitmap generation) and storage reductions (72% smaller bitmaps) in previous patches.

The current patch restructures how pseudo-merge parent bitmaps are handled during bitmap generation. Rather than building temporary bitmaps during the write phase, it now stores them persistently on the bitmapped_commit struct. This change doesn't affect the on-disk format but prepares for future optimizations where pseudo-merge bitmaps will be built earlier in the process.

The patch:
1. Adds a new pseudo_merge_parents field to bitmapped_commit
2. Updates bitmap_writer_free() to clean up the new field
3. Modifies write_pseudo_merges() to store parent bitmaps earlier
4. Maintains all existing functionality while simplifying the code

This continues the series' pattern of well-instrumented, incremental changes that build logically on each other. Jeff King has been providing thorough technical validation throughout the series, and there are no signs of controversy or outstanding issues here. The change appears ready for integration as part of the larger optimization effort.
