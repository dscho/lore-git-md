Feature patch (4/8) in Christian Couder's URL-based promisor remote auto-configuration series, adding support for locally-generated remote names.

This patch introduces a `local_name` field to `struct promisor_info` to handle cases where the locally configured remote name differs from the server-advertised name. The change enables the upcoming auto-generated remote names (prefixed with `promisor-auto-`) while maintaining backward compatibility with existing configurations.

Key technical changes:
- Adds `local_name` field to track locally-used names separately from server-advertised names
- Introduces `promisor_info_local_name()` helper to abstract name selection
- Updates `promisor_store_advertised_fields()` and `filter_promisor_remote()` to use the local name for configuration lookups
- Includes proper memory management for the new field in `promisor_info_free()`

The patch is part of the larger effort to enable secure URL-based promisor remote configuration, with this change specifically preparing the plumbing for auto-generated remote names. The implementation is clean and focused, with clear documentation of the struct fields and their purposes.

This continues the series' pattern of careful, well-documented changes to the promisor remote infrastructure, building on the previously approved LOP series. The patch has already been reviewed by Patrick Steinhardt and others, with no outstanding technical concerns.
