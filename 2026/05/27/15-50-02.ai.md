Performance optimization for revision walking using priority queues (final patch).

This third patch in Kristofer Karlsson's series completes the conversion of Git's revision walking machinery to use priority queues instead of O(w) linked-list insertions. The change targets the streaming (non-limited) walk in `get_revision_1()`, replacing `commit_list_insert_by_date()` with an O(log w) priority queue operation.

The implementation maintains compatibility by:
1. Adding a `commit_queue` field to `rev_info` alongside the existing commit list
2. Making the two representations mutually exclusive (callers see no change)
3. Providing `rev_info_commit_list_to_queue()` for early conversion when needed
4. Adding `REV_WALK_NO_WALK` to distinguish from streaming cases

The patch removes the now-unused `commit_list_insert_by_date()` function and updates all `process_parents()` callers to use the queue. Benchmarks in the cover letter showed a 5.3x speedup for merge-heavy repositories, with queue maintenance dropping from 79% to 16% of runtime.

This completes the elimination of O(w) sorted linked-list insertions from revision walking, following the same successful pattern as the earlier `limit_list()` optimization. The changes are well-scoped and maintain existing behavior while providing significant performance wins for wide walk frontiers.
