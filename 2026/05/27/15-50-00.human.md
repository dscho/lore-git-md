This is the first patch in a 3-part series optimizing revision walking performance by introducing priority queues. It's a prerequisite memory leak fix that becomes necessary for the subsequent optimization.

The patch fixes a memory leak in `pack-objects.c` where `enumerate_and_traverse_cruft_objects()` initializes a `rev_info` structure but fails to call `release_revisions()` to clean it up. While this leak is currently hidden on master (likely because the structures are stack-allocated), it would become visible once the revision walking machinery starts using dynamically allocated structures in the upcoming changes.

The fix is straightforward - adding a single `release_revisions(&revs)` call after the traversal completes. This shows the author's attention to detail in cleaning up prerequisite issues before making more substantial changes. The patch is small, focused, and clearly motivated by the needs of the larger series.
