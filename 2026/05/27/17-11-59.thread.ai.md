Thread subject: [PATCH] pkt-line: initialize packet_buffer to avoid macOS linker warning. Core issue is a macOS/Xcode 16.3+ linker warning about alignment constraints when linking large uninitialized global arrays (65520-byte packet_buffer in pkt-line.c). Two solutions were considered: zero-initializing the buffer or using `-fno-common` compiler flag.

Technical details: the packet_buffer in pkt-line.c is used for Git's network protocol implementation. The warning occurs only on newer macOS/Xcode toolchains. Testing confirmed both approaches work, but compiler flag avoids potential object file bloat from initialization.

Current status: Harald Nordgren has provided concrete implementation details for Junio C Hamano's suggested `-fno-common` solution - a Makefile snippet that conditionally adds the flag when linker version is 1167+ (matching problematic Xcode releases). This maintains cross-platform consistency while addressing the build warning without source modifications.
