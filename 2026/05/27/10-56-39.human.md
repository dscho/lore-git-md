Bugfix discussion about zombie processes in containerized Git operations.

Jeff King (Peff) follows up on SURA's report of zombie processes accumulating during `git fetch` in container environments where Git runs as PID 1. While agreeing that using an init process like `tini` is the proper solution, Peff investigates whether recent Git changes might have exacerbated the issue.

The analysis traces the evolution of Git's maintenance behavior: pre-2.29 used `git gc --auto` which would check for work before detaching, while post-2.47 `git maintenance --detach` always detaches immediately before checking sub-tasks. This means every fetch now spawns a maintenance process that must be reaped by the init system, rather than being able to exit synchronously when no work is needed.

Peff suggests this change in behavior could explain increased zombie process generation when moving from pre-2.47 versions, though notes it's not problematic in systems with proper init processes. He floats the idea of making maintenance more like the old gc behavior by checking task needs before detaching, but acknowledges this might be complex to implement and of limited practical impact.

This is a substantive technical follow-up that identifies a specific behavioral difference in maintenance task handling that could contribute to the reported issue, while maintaining that proper init process configuration remains the correct solution. The analysis provides useful historical perspective on Git's evolution in this area.
