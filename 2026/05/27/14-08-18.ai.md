Bugfix patch (6/8 in series) that implements URL-based allowlisting for promisor remote updates, completing the security model for promisor remotes.

This patch adds the core functionality to trust known remotes when their URLs match patterns in `promisor.acceptFromServerUrl`. The key technical aspects:

1. Introduces `url_matches_accept_list()` helper that:
   - Normalizes URLs before comparison
   - Performs component-wise matching (exact scheme/port, wildmatch for host/path)
   - Returns the first matching allowed_url entry

2. Modifies `should_accept_remote()` to:
   - Check URL allowlist first when both configs are set
   - Maintain strict security by rejecting URL mismatches
   - Preserve existing `ACCEPT_KNOWN_URL` behavior as fallback

3. Updates documentation with:
   - Clear precedence rules between config options
   - Security guidelines for URL patterns
   - Detailed matching behavior (normalization, component rules)

4. Adds comprehensive tests covering:
   - Basic allowlist matching
   - Multiple patterns
   - URL mismatch cases
   - Edge cases from previous security reviews

The implementation builds on the URL pattern validation from earlier patches while maintaining the series' security focus. The documentation improvements are particularly thorough, providing clear guidance on safe pattern usage.

This completes the core functionality of the URL-based auto-configuration series, with only the auto-creation of unknown remotes remaining in the final patches. The changes have been reviewed by Patrick Steinhardt and incorporate feedback from earlier rounds.
