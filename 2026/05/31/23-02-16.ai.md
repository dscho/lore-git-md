This is patch 3/12 in a bugfix series for git-gui, focusing on environment variable handling for repository and worktree detection. The patch addresses a specific issue where git-gui was unconditionally exporting GIT_DIR and GIT_WORK_TREE variables even in invalid states (like empty worktree paths in bare repositories).

The key changes introduce two new helper functions:
1. `set_gitdir_vars` - Safely sets GIT_DIR and (only if non-empty) GIT_WORK_TREE
2. `unset_gitdir_vars` - Cleans up both variables using catch to avoid errors

The patch replaces all direct environment variable manipulation with these safer wrappers, particularly in the gitk and git-gui submodule handling paths. This prevents invalid empty GIT_WORK_TREE exports while maintaining necessary cases where these variables must be set (like when core.worktree is configured).

The change is part of a larger effort to make git-gui's repository discovery more robust by aligning with core Git's behavior. This specific fix handles edge cases that could previously cause cryptic errors, particularly in bare repository and submodule scenarios. The implementation shows careful attention to maintaining backward compatibility while fixing the underlying issues.
