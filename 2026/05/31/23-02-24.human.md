This is the 11th patch in a 12-part bugfix series for git-gui, focused on improving argument validation for the browser and blame subcommands. The series has already been reviewed and approved by maintainer Johannes Sixt.

The patch tightens up argument parsing for `git gui browser` and `git gui blame` to match core Git's behavior. Key changes:

1. Removes the problematic "path-before-rev" argument ordering that could silently show wrong content
2. Adds proper validation that paths exist in the specified revision (using `git ls-tree`)
3. Ensures revisions are valid (using `git rev-parse`)
4. Improves error messages when arguments are invalid
5. Makes the behavior consistent with core Git's blame command regarding worktree files

The changes prevent confusing cases where git-gui would show empty windows or wrong content when given invalid paths or revisions. The implementation now properly checks that:
- Revisions resolve to valid commits
- Paths exist in the specified revision (as directories for browser, files for blame)
- Worktree files are only used in the specific case where blame targets HEAD with no worktree

This completes one of the last major behavioral gaps between git-gui and core Git's command-line behavior for these subcommands. The patch maintains backward compatibility while fixing long-standing edge cases.
