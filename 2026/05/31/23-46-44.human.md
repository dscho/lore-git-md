This is a follow-up to the `git describe` pattern matching bugfix, addressing an edge case in remote branch name handling.

Tuomas Ahola responds to Junio C Hamano's observation about inconsistent CI failures where `git describe --contains --all` outputs full remote ref names ("remotes/origin/remote_branch_A") when the test expects shortened names ("branch_A"). While noting this is outside his usual area of expertise, Ahola proposes a one-line change switching from `QSORT` to `STABLE_QSORT` in `builtin/name-rev.c` that appears to resolve the issue on Alpine Linux.

The proposed change suggests the test failure might stem from unstable sorting behavior rather than the pattern matching logic itself. This would explain why the same input sometimes produces different outputs across CI jobs. The patch is minimal and focused on the sort stability, leaving the broader question of remote ref name handling for further discussion if needed.

This appears to be a pragmatic fix for the immediate CI issue, though it doesn't yet address whether the test's expectation of shortened branch names is the correct behavior when using `--all` with remote refs. The thread remains open for further input on whether this solution fully resolves the underlying problem or if additional changes to the pattern matching logic are needed.
