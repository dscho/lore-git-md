Bugfix follow-up for `git describe` pattern matching stability.

Tuomas Ahola responds to Junio C Hamano's observation about inconsistent CI failures in Jacob Keller's `git describe` pattern matching fix. The test failure shows remote branch names appearing when they should be excluded, with the output showing "remotes/origin/remote_branch_A" instead of the expected "branch_A".

Ahola proposes a simple change to use `STABLE_QSORT` instead of `QSORT` in `builtin/name-rev.c`, noting this at least resolves the failure on Alpine Linux. This suggests the issue may be related to sorting stability when processing ref names, though it's unclear if this fully addresses the remote ref matching problem Junio identified.

The patch is minimal - just a one-line change to the sorting algorithm - and appears to be a speculative fix rather than a deep analysis of the pattern matching logic. Given the thread context, this seems to be targeting a secondary symptom (test instability) rather than the core remote ref matching issue. The change would make the test output consistent across platforms but may not fully resolve the underlying exclude pattern behavior with remote branches.
