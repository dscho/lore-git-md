Thread identity: Build system cleanup patch series from Harald Nordgren addressing duplicate library references in Makefile link recipes, with focus on maintaining correct linker behavior while eliminating macOS build warnings.

Core problem: Multiple Makefile recipes (test helpers, fuzz targets, unit tests) contain duplicate library references - both explicit archive listings and via $(LIBS) variable - causing macOS warnings. The deeper issue involves maintaining left-to-right linker symbol resolution where object files must precede archives, which the current duplication pattern enforces despite its warning side effects.

Current status: After Junio Hamano's review of v1 identified that simply removing duplicates would break symbol resolution, Harald Nordgren has proposed a comprehensive solution modifying $(LIBS) to explicitly include prerequisite archives first while maintaining correct ordering. This represents progress toward a systematic fix rather than isolated warning suppression.

Key technical details: The solution restructures $(LIBS) to:
1. Explicitly list prerequisite archive files first
2. Follow with other libraries
3. Maintain required object-file-before-archive ordering
4. Eliminate duplicate .a references triggering macOS warnings
Affects ~10 locations across test helper, fuzz target, and unit test build rules. The approach preserves critical linker behavior while cleaning up the build output.
