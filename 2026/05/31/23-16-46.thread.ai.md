Thread identity: Build system cleanup patch series from Harald Nordgren addressing macOS linker warnings about duplicate library references in Makefile link recipes. The series explores two architectural approaches: Makefile restructuring (v2) versus linker flag suppression. Thread type is patch series with architectural discussion.

Core problem: macOS linker emits warnings (`ld: warning: ignoring duplicate libraries`) when the same library appears multiple times in link commands, yet Git's build system sometimes intentionally lists libraries multiple times to handle circular dependencies between archives. The challenge is to eliminate warnings without breaking symbol resolution or maintainability.

Current status: v2 patch (Makefile restructuring) has been proposed and reviewed, but Junio C Hamano now advocates for an alternative solution: suppressing the warning at the linker level via `-Wl,-no_warn_duplicate_libraries` in `config.mak.uname`. This approach preserves the existing Makefile logic while addressing the cosmetic issue. The thread is now at a decision point between these two architectural directions.

Key technical details:
- Files touched: `Makefile`, `config.mak.uname`
- New symbols/flags: `-Wl,-no_warn_duplicate_libraries` (macOS linker flag)
- Linker behavior: macOS ld warns on duplicate libraries; GNU ld silently accepts them
- Circular dependency handling: listing the same library multiple times is sometimes necessary for correct symbol resolution (e.g., libA.a -> libB.a -> libA.a)
- Alternative syntax: GNU ld's `--start-group`/`--end-group` is less portable
- Build configurations: macOS-specific linker flag, version-gating for XCode 15+
- Test coverage: repeated test executions (e.g., rebase workflows) where warnings accumulate

Open questions and loose ends:
- Which architectural approach will be adopted: Makefile restructuring (v2) or linker flag suppression?

- Are there other platforms with similar linker behaviors that should be addressed?
