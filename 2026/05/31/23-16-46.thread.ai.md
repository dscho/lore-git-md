Thread identity: Build system cleanup patch series from Harald Nordgren addressing macOS linker warnings about duplicate library references in Makefile link recipes, now expanded to include Meson build considerations and historical context. Thread type remains a patch series with build system focus, now with additional precedent for the chosen architectural approach.

Core problem: macOS linker emits warnings (`ld: warning: ignoring duplicate libraries`) when the same library appears multiple times in link commands, despite Git's build system sometimes intentionally listing libraries multiple times to handle circular dependencies between archives. The challenge is to eliminate the cosmetic warning without breaking symbol resolution or build system maintainability, affecting both Makefile and Meson builds. The solution must be maintainable and precedent-backed.

Current status: The series has concluded with the v3 patch implementing Junio C Hamano’s proposed solution for Makefile builds: suppressing the warning at the linker level via `-Wl,-no_warn_duplicate_libraries` in `config.mak.uname`, version-gated for XCode 15+ (ld64-907+, dyld-1009.5+) using `LD_MAJOR_VERSION`. This patch is ready for merging after D. Ben Knoble confirmed successful testing on an older macOS system (Xcode 14.2) with both Makefile and Meson builds. Patrick Steinhardt subsequently noted that the same warning appears in Meson builds, though Meson partially mitigates it by suppressing warnings when `--fatal-warnings` is used. Junio C Hamano has now provided historical context: the linker flag suppression approach was directly inspired by a prior Meson maintainer effort (commit `7c901d7a8af2` by Paolo Bonzini) to address the same warning, reinforcing the architectural soundness of the solution. The question of whether to extend suppression to Meson builds remains open but orthogonal to the immediate thread; the original patch remains actionable as-is.

Key technical details:
- Files touched: `config.mak.uname` (Makefile), potential future Meson configuration
- New symbols/flags: `-Wl,-no_warn_duplicate_libraries` (macOS linker flag), version-gated via `LD_MAJOR_VERSION` regex matching ld, ld64, and dyld versions (ld64-907+, dyld-1009.5+)
- Linker behavior: macOS ld warns on duplicate libraries; GNU ld silently accepts them. The flag suppresses the warning without affecting symbol resolution. Meson builds exhibit the same warning but suppress it when `--fatal-warnings` is used
- Circular dependency handling: listing the same library multiple times remains necessary for correct symbol resolution (e.g., libA.a -> libB.a -> libA.a)
- Version gating: flag only applied to Xcode 15+ linkers, avoiding errors on older macOS versions. The regex now matches ld, ld64, and dyld to ensure robustness
- Precedent: the same linker flag (`-Wl,-no_warn_duplicate_libraries`) was previously adopted by Meson maintainer Paolo Bonzini in commit `7c901d7a8af2` to address the same warning, reinforcing the approach as well-trodden and architecturally sound
- Alternative syntax: GNU ld's `--start-group`/`--end-group` remains less portable and was not adopted
- Build configurations: macOS-specific linker flag, version-gated using existing `LD_MAJOR_VERSION` infrastructure. Compatibility confirmed for both Makefile and Meson build systems
- Test coverage: implicit in repeated test executions (e.g., rebase workflows) where warnings previously accumulated. Explicit testing now includes Xcode 14.2 (Makefile and Meson) and newer systems (Makefile only, with warnings suppressed)

Open questions and loose ends:

- What precedent does this set for handling platform-specific linker behaviors in Git's build system, particularly for cross-build-system consistency?
- Are there other platforms with similar linker behaviors that might benefit from analogous suppression?
