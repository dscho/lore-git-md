This thread is about a performance optimization for Git's priority queue implementation, specifically targeting the `prio_queue_get()` operation with a cascade-down algorithm. Kristofer Karlsson (Spotify) proposed the change in a two-patch series: first refactoring the code to extract `sift_up()`, then introducing the cascade-down optimization for unfused `prio_queue_get()` calls. While the optimization reduces comparison counts by 14–17% and shows a ~2% end-to-end improvement on some hardware, it introduces a 1% slowdown on Apple silicon (M1/M5), creating a hardware-dependent performance regression.

The technical consensus on correctness is solid—René Scharfe confirmed the optimization never requires more comparisons than the existing sift-down algorithm, even after exhaustive testing. However, the Apple silicon slowdown complicates the decision. Kristofer has addressed all prior feedback and prepared a v3 series, but the maintainer must now weigh the tradeoffs: a small but measurable improvement on some hardware against a regression on another widely used platform. The code change itself is modest (20 lines added), but the performance inconsistency makes this no longer an uncontroversial win.

René, who initially strongly endorsed the patch, now acknowledges the regression but still supports the optimization, arguing the slowdown may be a measurement artifact rather than an algorithmic flaw. Junio C Hamano, the maintainer, has not yet weighed in on the regression. The latest email from René suggests a potential follow-up micro-optimization to reduce writes in `sift_up()` and `sift_down_root()`, but this is purely hypothetical and doesn’t address the current decision point. The thread is now waiting on the maintainer’s call.
