This thread is about a two-part performance optimization for Git's priority queue implementation, specifically targeting the `prio_queue_get()` operation. The series, now at version 3, comes from Kristofer Karlsson at Spotify and has reached technical consensus after thorough review.

The core change introduces a "cascade-down" optimization for cases where `prio_queue_get()` isn't immediately followed by a `prio_queue_put()`. This replaces the standard sift-down algorithm with a more efficient approach that cascades the vacancy down to a leaf before sifting up, reducing the number of comparisons needed. René Scharfe's exhaustive testing confirms this is strictly faster for extract-min operations, with no regressions. The implementation is minimal—just 20 lines added to `prio-queue.c`—and preserves API compatibility.

The optimization shows a ~2% end-to-end improvement on large repositories with thousands of active branches, particularly benefiting wide commit graphs where priority queues grow deeper. While the improvement is modest, it comes with minimal code complexity. The series has been split into two commits: the first (a refactoring to extract `sift_up()`) is uncontroversial, and the second (this patch) is ready to merge if Junio approves. The only remaining question is whether the 1-2% performance gain justifies the change, given that most `get+put` pairs are already handled by the merged lazy-fold optimization. Both Kristofer and René support merging the patch, but Kristofer acknowledges the tradeoff is marginal.
