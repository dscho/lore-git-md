This is a bugfix patch in the git-gui repository detection series, specifically addressing unnecessary directory changes when launching gitk. The patch comes from maintainer Johannes Sixt and is part of the now-merged v3 series that fixed various edge cases in git-gui's repository handling.

The change removes a redundant `cd` operation in the `do_gitk` procedure that was unnecessarily changing directories even when already in the correct location. The patch explains this is either redundant (in non-bare repos where we're already in the worktree) or meaningless (in bare repos where there is no worktree). The change also simplifies the submodule case by making the directory change logic more straightforward.

This is a small but clean improvement that eliminates unnecessary operations while maintaining all existing functionality. As part of the larger series, it helps make git-gui's behavior more consistent with core Git's repository handling.
