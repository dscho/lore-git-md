This is patch 9/12 in a merged bugfix series for git-gui, focusing on worktree detection from gitdir locations. The patch addresses cases where git-gui fails to properly identify the worktree when launched from within a repository directory.

The key changes in this patch:

1. Adds a new `find_worktree_from_gitdir` procedure that handles three worktree discovery scenarios:
   - When core.worktree is set (already handled by git rev-parse)
   - When the gitdir is embedded as a .git subdirectory
   - When the gitdir is a worktree-specific directory (under mainrepo/worktrees/)

2. Implements robust validation to ensure the discovered worktree actually points back to the correct gitdir, protecting against filesystem inconsistencies or misconfigurations.

3. Maintains backward compatibility while fixing edge cases that have been broken since Git 2.19 (2019).

The patch represents the culmination of extensive review and iteration, with all maintainer feedback addressed. It's part of a larger architectural shift to standardize git-gui's repository discovery on `git rev-parse` behavior, making it more robust and consistent with core Git.

Technical note: The implementation carefully handles POSIX filesystem edge cases and validates all discovered paths against Git's own repository detection logic, preventing potential issues from manual worktree moves or misconfigured bare repositories.
