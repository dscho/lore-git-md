This is the first patch in a merged 12-part bugfix series for git-gui, addressing edge cases in repository and worktree detection. The patch fixes a regression where git-gui's browser subcommand would fail when run from a detached HEAD state.

The change restores special-case handling for detached HEAD states that was lost when git-gui switched from direct file access to using `git branch --show-current` (a change made for reftable compatibility). When HEAD is detached, `git branch --show-current` returns an empty string, but git-gui browser expects "HEAD" in this case. The patch adds back this special case logic while maintaining the reftable-compatible approach.

This is a straightforward fix that aligns git-gui's behavior with core Git's handling of detached HEAD states. The patch is small (3 lines added) and clearly motivated by a specific regression. As part of a larger series that has already been reviewed and merged, this change represents a well-vetted improvement to edge case handling.
