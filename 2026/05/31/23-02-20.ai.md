This is patch 7/12 in a bugfix series for git-gui, focusing on worktree discovery. The patch standardizes git-gui's worktree detection to use `git rev-parse --show-toplevel` and `--show-prefix` exclusively, replacing a mix of Tcl code and Git invocations. This ensures consistent behavior with core Git's repository handling.

Key changes in this patch:
1. Moves worktree discovery immediately after repository discovery to catch configuration errors early
2. Simplifies the logic by relying entirely on `git rev-parse` for path resolution
3. Maintains error handling for filesystem issues while removing redundant checks
4. Preserves the ability to operate without a worktree for blame/browser commands
5. Reorders configuration loading to occur after worktree validation

The implementation now properly propagates errors from Git's own validation rather than implementing parallel checks in Tcl. This is part of the series' broader effort to align git-gui's behavior with core Git's repository handling conventions.

Technical details:
- Introduces centralized error handling via `is_gitvars_error`
- Removes manual path manipulation in favor of Git's built-in resolution
- Keeps bare repository checks but makes them more robust
- Maintains backward compatibility while fixing edge cases

The patch follows the series' architectural direction of using core Git plumbing for all repository state discovery, reducing the maintenance surface for git-gui's custom logic.
