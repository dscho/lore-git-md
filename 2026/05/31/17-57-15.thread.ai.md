Thread identity: Performance optimization patch for Git's priority queue implementation by Kristofer Karlsson (Spotify), focusing on the `prio_queue_get()` operation.

Core problem: The current sift-down algorithm in `prio_queue_get()` performs unnecessary comparisons and data movements when extracting the minimum element, particularly noticeable in Git's common case of ascending-key workloads.

Key technical details: The patch replaces the standard sift-down with a cascade-down approach that:
1. Promotes the smaller child upward at each level (one comparison + one copy)
2. Lets the vacancy sink to a leaf
3. Places the last array element there with a potential sift-up
Also simplifies `prio_queue_replace()` to use get+put operations since the new sift approach doesn't cleanly support the previous implementation.

Current status: Initial version showing significant benchmark improvements:
- 15-23% faster for typical ascending-key workloads
- 1-4% faster for worst-case descending keys
- ~4% speedup on real-world `rev-list` operations with wide DAGs
- No regressions in any scenario
- 22 lines modified, well-covered by existing unit tests

Open questions: None raised yet in this initial submission. The patch appears ready for review, particularly from performance-conscious contributors familiar with Git's priority queue usage patterns.
