This thread is about a build system cleanup that eliminates annoying macOS linker warnings during Git development. Harald Nordgren sent a v2 patch that restructures how libraries are linked in the Makefile, addressing duplicate archive references that trigger warnings like `ld: warning: ignoring duplicate libraries` during repeated test runs—particularly noticeable in workflows like rebasing with test execution.

The solution takes a systematic approach by redefining the `$(LIBS)` variable to explicitly list prerequisite archives first, then filter duplicates from the remaining libraries. This preserves the critical left-to-right linker ordering (where object files must precede archives) while making the build system more maintainable. The patch covers test helpers, fuzz programs, and unit tests consistently, showing clear improvement over the v1 iteration by tackling the root cause rather than just patching individual call sites.

Junio Hamano’s review helped shape the solution, and Harald’s v2 demonstrates deep engagement with both the technical constraints and broader build system context. The patch is now mature and ready, though there’s still room to verify it on less common build configurations. This cleanup could serve as a pattern for similar build system improvements elsewhere in Git.
