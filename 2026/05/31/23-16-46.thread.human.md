This thread began with Harald Nordgren’s patch series addressing macOS linker warnings about duplicate library references in Git’s Makefile builds. The series concluded with a v3 patch that suppresses the cosmetic warning at the linker level using `-Wl,-no_warn_duplicate_libraries`, version-gated for Xcode 15+ to avoid breaking older macOS systems. The solution preserves the existing Makefile logic for handling circular dependencies while improving developer experience, and it has been confirmed to work across both Makefile and Meson builds on older and newer macOS versions.

The latest email from Patrick Steinhardt notes that the same duplicate-library warning also appears in Meson builds, though Meson partially mitigates it by suppressing warnings when `--fatal-warnings` is used. He suggests the warning could be unconditionally disabled in Git’s Meson configuration, as it serves no practical purpose, and has looped in a Meson maintainer for input. This observation doesn’t affect the readiness of the v3 patch, which remains focused on Makefile builds and is still on track for merging. However, it opens a tangential discussion about whether to extend the same suppression approach to Meson builds, though this would be a separate effort. The thread’s core goal—eliminating the warning in Makefile builds—has been achieved.
