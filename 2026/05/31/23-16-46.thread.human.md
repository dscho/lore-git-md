Harald Nordgren’s patch series to clean up macOS linker warnings about duplicate library references has reached its final form. The thread began with a proposal to restructure the Makefile to eliminate redundant library listings, but after discussion—particularly from Junio C Hamano—it converged on a simpler solution: suppressing the warning at the linker level. The now-merged approach adds `-Wl,-no_warn_duplicate_libraries` to `config.mak.uname`, version-gated for Xcode 15+ linkers (ld64-907 or newer). This preserves the existing Makefile logic, which sometimes intentionally lists the same library multiple times to handle circular dependencies, while eliminating the cosmetic noise that accumulated during test runs.

The patch is minimal and platform-specific, touching only `config.mak.uname` and reusing the `LD_MAJOR_VERSION` probe infrastructure introduced for an earlier alignment fix. The version gate ensures the flag is only passed to linkers that understand it, avoiding errors on older macOS versions. Harald’s responsiveness to review feedback—particularly Junio’s emphasis on correctness and maintainability—helped shape the final solution, which balances developer experience with build system robustness. The thread leaves open whether this pattern might be extended to other platform-specific linker behaviors, but for now, the issue is resolved.
