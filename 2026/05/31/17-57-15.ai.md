This is a performance optimization patch for Git's priority queue implementation. The author, Kristofer Karlsson from Spotify, proposes replacing the standard sift-down algorithm in `prio_queue_get()` with a more efficient cascade-down approach.

The key insight is that the current implementation performs unnecessary comparisons and data movements when extracting the minimum element. The new approach:
1. Promotes the smaller child upward at each level (one comparison + one copy)
2. Lets the vacancy sink to a leaf
3. Places the last array element there with a potential sift-up

Benchmarks show significant improvements:
- 15-23% faster for typical ascending-key workloads (Git's common case)
- 1-4% faster for worst-case descending keys
- No regressions in any scenario
- Real-world `rev-list` operations show ~4% speedup on wide DAGs

The patch also simplifies `prio_queue_replace()` to use get+put operations since the new sift approach doesn't cleanly support the previous implementation. The author notes this shouldn't impact performance as replace operations aren't in hot paths.

The change is small (22 lines modified) and well-tested by existing unit tests. While the priority queue isn't a major bottleneck, the optimization provides measurable gains with minimal risk, particularly for repositories with wide commit graphs.
