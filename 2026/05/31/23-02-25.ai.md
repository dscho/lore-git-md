This is the final patch in a merged bugfix series for git-gui, adding explicit subcommands for repository selection behavior. The patch introduces two new subcommands:

1. `gui` - Runs the GUI only if repository/worktree discovery succeeds, failing with an error message rather than launching the repository picker
2. `pick` - Always runs the repository picker first before starting the GUI

The change maintains backward compatibility while giving users more control over when the repository picker appears. Previously, the picker would automatically launch on repository discovery failures, which could be surprising. The implementation adds new option flags (`picker` and `gitdir_discovery`) to control this behavior while keeping the existing default behavior when no subcommand is specified.

This completes the architectural improvements to git-gui's repository handling that were the focus of the 12-patch series. The changes align with the thread's goal of making git-gui's behavior more predictable and consistent with core Git's expectations. Maintainer Johannes Sixt has already approved and merged the series.
