This is the final patch in a merged bugfix series for git-gui, adding explicit subcommands to control repository/worktree discovery behavior. The patch comes from Mark Levedahl with sign-off from maintainer Johannes Sixt.

The change introduces two new subcommands to git-gui:
- `gui`: Runs the GUI only if repository/worktree discovery succeeds, failing with an error message rather than falling back to the repository picker
- `pick`: Always runs the repository picker first before starting the GUI

This gives users explicit control over when the repository picker appears, addressing cases where the picker would previously trigger unintentionally. The implementation maintains backward compatibility while adding the new options, with the default behavior remaining unchanged unless the new subcommands are used.

The patch modifies git-gui.sh to:
1. Add new option flags for picker and gitdir discovery
2. Parse the new subcommands and set appropriate options
3. Update the usage message
4. Ensure proper error handling when gitdir discovery fails

This completes the series' goal of making git-gui's repository handling more robust and predictable while aligning with core Git's behavior. The changes are well-contained and maintain the architectural improvements from earlier patches in the series.
