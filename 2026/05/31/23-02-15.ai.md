This is a bugfix patch in the git-gui repository detection series, specifically addressing unnecessary directory changes when launching gitk. The patch comes from maintainer Johannes Sixt and is part of the now-merged v3 series.

The change removes a redundant `cd` operation in the `do_gitk` procedure that was previously changing to the worktree directory. Johannes explains this is unnecessary because either: (1) the startup code already put us in the correct directory (for non-bare repos), or (2) there's no worktree to change to (for bare repos). The only remaining case that needs directory handling is submodules, which is preserved.

The patch demonstrates the series' focus on cleaning up edge cases and aligning git-gui's behavior with core Git's repository handling. It's a straightforward removal of redundant code that doesn't change observable behavior, just makes the implementation more correct and maintainable. The sign-off from both Johannes Sixt and Mark Levedahl indicates this was collaboratively reviewed and approved.
