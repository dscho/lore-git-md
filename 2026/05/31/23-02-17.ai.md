This is the fourth patch in a 12-part bugfix series for git-gui, focusing on repository and worktree detection. The patch refactors the repository picker (choose_repository::pick) to avoid modifying global state variables (_gitdir, _prefix) directly, instead relying on the caller to perform proper repository validation after selection.

The key change is making the picker return success/failure status while leaving the current directory at the worktree root, where the caller can then use `git rev-parse --git-dir` to properly discover and validate the repository. This eliminates several edge cases where global state could be left inconsistent. The patch also renames the `clone_ok` field to `pick_ok` to better reflect its purpose.

This change is part of a larger architectural shift to align git-gui's repository discovery with core Git's behavior, particularly around bare repositories and worktree handling. The implementation maintains backward compatibility while fixing long-standing issues with repository validation. The patch has already been reviewed and approved by git-gui maintainer Johannes Sixt as part of the complete series.
