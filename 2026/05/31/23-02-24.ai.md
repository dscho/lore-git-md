This is the 11th patch in a 12-part bugfix series for git-gui, focusing on robust argument validation for the browser and blame subcommands. The patch completes the architectural shift to using `git rev-parse` for repository discovery while fixing several edge cases in argument handling.

The key changes in this patch:

1. Removes the problematic "path-before-rev" argument ordering that could silently produce incorrect results, bringing git-gui behavior in line with core Git conventions.

2. Implements strict validation for both revision and path arguments:
   - Uses `git rev-parse --verify` to validate revisions
   - Uses `git ls-tree` to verify paths exist in the specified revision
   - For blame without a revision, properly checks worktree file existence

3. Improves error handling with clear messages when:
   - Invalid revisions are provided
   - Paths don't exist in the specified revision
   - Worktree files are missing for blame operations

4. Maintains backward compatibility while fixing long-standing issues:
   - Still supports the `--line=<num>` option for blame
   - Preserves the ability to blame worktree changes when no revision is given
   - Continues to handle the special case of "." as a path

The patch represents the culmination of extensive review and iteration, with all maintainer feedback addressed. It resolves edge cases that could previously lead to blank windows or incorrect displays, particularly around bare repositories and worktree operations. The changes focus on making git-gui's core behavior more robust rather than introducing new features.

This is part of a larger effort to align git-gui's repository and worktree handling with core Git's behavior, particularly important for the reftable backend integration. The series has been reviewed and approved by git-gui maintainer Johannes Sixt.
