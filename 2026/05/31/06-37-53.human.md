This is a documentation patch follow-up addressing the maintainer's feedback about `[no-]` variants in merge options. The author, Brandon, responds to Junio's observation that `--no-message` is missing from the documentation by noting this appears to be a consistent stylistic choice across Git's documentation.

Brandon points out that while the `-h` output automatically includes `[no-]` variants, the handwritten documentation typically only mentions them for boolean flags or when the behavior needs explanation. They provide examples from `git-commit`, `git-notes`, `git-svn`, and `git-tag` documentation where string-valued options like `--message` don't document their `--no` variants either, suggesting the merge docs should follow this precedent rather than being an exception.

The response makes a reasonable case for consistency with existing documentation style, though it doesn't directly address Junio's point about other undocumented `[no-]` variants in merge options. The thread now hinges on whether the project wants to maintain the current documentation convention or expand it to be more complete.
