This is the third version of a bugfix patch addressing an edge case in Git's `--update-refs` rebase feature. The issue occurs when `rebase.instructionFormat` includes `%d` (showing all ref decorations), causing the rebase machinery to incorrectly generate `update-ref` instructions for non-branch refs like HEAD.

The patch filters decorations to only process `DECORATION_REF_LOCAL` types, preventing invalid instructions for non-branch refs. The v3 iteration merges two if statements into one for cleaner logic while maintaining the same behavior. A regression test verifies the fix by ensuring only branch refs appear in the update-ref instructions.

Phillip Wood has reviewed and confirmed this approach correctly handles the intended branch refs through existing filtering in `sequencer.c`. The discussion has also identified a related issue in `make_script_with_merges()` that needs similar decoration filtering, though that will be addressed separately.

This appears to be a well-scoped fix for a real edge case in the relatively new `--update-refs` feature (introduced in Git 2.38). The patch is ready for inclusion with Phillip Wood's Reviewed-by, though the author may choose to incorporate the additional `make_script_with_merges()` fix in a follow-up.
