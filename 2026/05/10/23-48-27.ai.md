This is a documentation patch series (now at v3) addressing the `--follow` and `--no-follow` options for `git log`. The thread has reached a key point where maintainer Junio Hamano provides additional technical context about the limitations of the `--follow` implementation.

Junio notes that `--follow` was never designed to properly handle complex cases - it fundamentally only works with a single filename in linear history, not general pathspecs. While the rename-tracking feature exists, its implementation is simplistic: it tracks one rename path at a time without handling merge scenarios where a file may have multiple rename histories. This explains why the documentation must be precise about stating the single-file limitation.

The author Tamir Duberstein had already incorporated Junio's previous feedback in v3, clarifying that `--follow` only works with one pathspec and follows individual files rather than directories. Junio's latest comment suggests the documentation should go further by being explicit about the linear-history assumption and not implying broader pathspec support exists. This reflects Git's philosophy of documenting actual behavior rather than aspirational features.
