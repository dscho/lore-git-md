This is the final step in Johannes Schindelin's series to remove the unmaintained nedmalloc allocator from Git's Windows builds. Maintainer Junio Hamano has now applied the complete v3 series to the integration branches, marking the conclusion of this effort.

The series addressed GCC 16 compatibility issues by fully excising the obsolete nedmalloc code, which Git for Windows had already replaced with mimalloc years ago. The v3 iteration incorporated Junio's feedback about integration mechanics, with the last four patches reworded to clearly indicate they should be squashed during application.

With no outstanding technical concerns and explicit approval from both Junio and Patrick Steinhardt, this change represents the logical endpoint of the nedmalloc deprecation path. The removal was carefully structured to first disable usage, then remove build system references, and finally delete the implementation files in manageable chunks.

This change is now part of Git's main development line and will appear in the next release. It's a straightforward cleanup that removes technical debt while maintaining existing runtime behavior, as Git for Windows has been successfully using mimalloc for years.
