This is a CI configuration patch from Junio C Hamano that modifies when expensive tests run in GitHub Actions. It builds upon Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB), specifically adjusting the CI strategy from the final patch in that series.

Junio argues that the current approach of only running expensive tests on integration branches (next/master/main/maint) is inefficient, as it forces maintainers to catch issues only after patches are merged. His change enables expensive tests (including the >4GB clone tests) for pull request builds as well, while keeping them for integration branch pushes. This shifts more testing burden to contributors early in the process while still maintaining merge-time validation.

The implementation modifies `ci/lib.sh` to set `GIT_TEST_LONG=YesPlease` for both PR events and integration branch pushes. The commit message makes a strong case for this change as a scalability improvement, noting it will help catch problems before they reach the mailing list. This appears to be a well-reasoned adjustment to the CI strategy that maintains the series' goals while improving contributor workflow.
