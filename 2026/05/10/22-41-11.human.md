This is a bugfix patch addressing an edge case in Git's `--update-refs` rebase feature when used with `rebase.instructionFormat` containing `%d` decorations. The patch is now in its third iteration with Phillip Wood's Reviewed-by tag, confirming the technical approach.

The issue occurs when `%d` in the instruction format causes non-branch refs (like HEAD) to appear in the decoration table, leading to invalid `update-ref` instructions being generated. The fix filters decorations to only process `DECORATION_REF_LOCAL` types, preventing these invalid instructions while still handling branch refs correctly.

The patch includes a regression test that fails without the fix, demonstrating the problem when using `rebase.instructionFormat="%s%d"`. The test verifies only branch refs appear in the update-ref instructions.

While this version remains unchanged from v2, Phillip Wood has identified a related issue in `make_script_with_merges()` that needs similar decoration filtering. That follow-up work will likely be addressed separately, as the current patch stands as a complete solution for its specific context in `sequencer.c`.

This is a well-scoped fix for a real edge case in the relatively new `--update-refs` feature (introduced in Git 2.38). The discussion has been thorough, with the sequencer expert's approval, this appears ready for inclusion.
