This thread reports a bug in `git-svn` where a recent change in Perl's Getopt::Long module (version 2.55) now warns about case-sensitive duplicate option specifications. The issue involves both `--id` and `-i` flags mapping to the same variable in `git-svn.perl`, which the updated Getopt::Long considers a duplicate when case-insensitive matching is enabled. While this currently only triggers a warning, future Getopt::Long releases will treat it as a fatal error.

The reporter (on Fedora 43 aarch64) has helpfully identified the exact location in the code and linked to the relevant Getopt::Long changelog entry. This appears to be a straightforward fix - likely just needs removing one of the duplicate option mappings while preserving the existing functionality. Since this is a compatibility issue that will break in future Perl releases, it should be addressed before that happens. No discussion or disagreement is noted; this seems ready for someone to pick up and prepare a simple patch.
