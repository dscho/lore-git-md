This is a documentation patch finalizing the `--no-follow` option for `git log`, now in its third iteration. The patch has been through thorough review and is nearly ready for merging, with Junio Hamano providing the final round of feedback.

The discussion has centered on how precisely to document the limitations of the `--follow` option (and its config `log.follow`). While previous versions described some behaviors as "not working well", Junio suggests stronger language - that the behavior is effectively "undefined" when used outside its intended scope (with non-linear history or directory pathspecs). This reflects the reality that the feature was designed specifically for single-file linear history traversal.

The patch represents a collaborative effort between Tamir Duberstein and Junio to accurately document long-standing but previously implicit behavior. With this final clarification about undefined behavior, the documentation should be technically complete and ready for inclusion. The exchange demonstrates Git's commitment to precise documentation that matches implementation reality rather than aspirational descriptions.
