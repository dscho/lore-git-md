This is a bugfix patch addressing edge cases in Git's `--update-refs` rebase feature, now in its third iteration. The patch ensures that non-branch refs (like HEAD or tags) are properly ignored when `rebase.instructionFormat` includes `%d` decorations.

The discussion has clarified that the current implementation correctly handles branch refs through `load_branch_decorations()`, addressing Junio Hamano's initial concern about local tag handling. Phillip Wood has identified a related issue in `make_script_with_merges()` that needs the same decoration filtering, though this follow-up work isn't included in the current patch series.

The v3 patch simplifies the implementation by merging conditionals as suggested in review, while maintaining the same core fix that prevents invalid update-ref instructions for non-branch refs. The test coverage remains robust, verifying both that legitimate branch updates work and non-branch refs are ignored.

This appears to be a well-considered solution to a subtle edge case in the relatively new `--update-refs` feature.
