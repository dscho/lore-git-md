This is a bugfix addressing terminal output corruption in Git's remote message handling. The patch from René Scharfe moves an ANSI clear sequence from the end to the beginning of line output in sideband.c, fixing a character truncation issue that occurred when remote messages exactly matched the terminal width.

Junio Hamano's reply confirms the technical approach, noting that clearing the line before printing (rather than after) achieves the same goal of preventing leftover characters while avoiding the truncation edge case. He observes this makes the behavior more predictable across different terminal implementations.

The change maintains backward compatibility and preserves the original 2007-era progress line cleanup functionality. While there are broader terminal handling concerns raised earlier in the thread (like color attribute persistence), this focused fix cleanly addresses the immediate issue without introducing new problems. Junio's response suggests the patch is likely to be accepted as-is, with other terminal quirks potentially addressed separately.
