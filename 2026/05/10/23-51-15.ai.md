This is a CI configuration patch from Junio C Hamano that modifies the test execution strategy for Johannes Schindelin's series handling large objects (>4GB) on Windows. The patch changes when expensive tests run in CI, expanding coverage to pull request builds rather than just integration branch pushes.

Junio argues that the current approach - where expensive tests only run after merging to integration branches - is inefficient because it shifts the burden of identifying issues to the maintainer. The patch modifies `ci/lib.sh` to run expensive tests (including the >4GB object tests from earlier in the series) on both PR builds and integration branch pushes. This ensures contributors catch problems earlier while still maintaining merge-time validation.

The change represents a philosophical shift in CI strategy - prioritizing early detection over CI resource conservation. The implementation cleanly extends the existing pattern with clear documentation of the rationale. This appears to be the final tweak needed before the series can be integrated, addressing the last remaining concern about test coverage timing.
