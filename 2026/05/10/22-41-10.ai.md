This is a bugfix patch addressing edge cases in Git's `--update-refs` rebase feature, now in its third iteration. The patch series remains focused on ensuring the rebase machinery correctly handles ref decorations when `rebase.instructionFormat` includes `%d` (show all ref decorations).

The key development in v3 is the discussion around local tag handling and the realization that the existing `load_branch_decorations()` call already provides the necessary branch filtering. Phillip Wood has confirmed the current approach is correct for its context in `sequencer.c`'s `todo_list_add_update_ref_commands()`, while also identifying a parallel issue in `make_script_with_merges()` that needs the same treatment.

The patch itself remains unchanged from v2 - it still filters decorations to only process `DECORATION_REF_LOCAL` types to prevent invalid instructions for non-branch refs like HEAD. The author is now considering whether to handle the newly identified `make_script_with_merges()` case in this patch or separately, with Phillip Wood having provided a suggested diff for that follow-up work.

This appears to be a well-scoped fix for a real edge case in the relatively new `--update-refs` feature (introduced in Git 2.38). The discussion has clarified the behavior around local tags and identified related code paths that may need attention, but the current patch stands as a complete solution for its specific context.
