This is a bugfix addressing terminal output corruption when displaying remote messages in Git. The patch modifies how Git clears progress lines when printing remote content (like GitLab merge request URLs) in terminals where the line width exactly matches the terminal width.

René Scharfe's solution moves the ANSI clear sequence ("\033[K") from being a suffix to a prefix, fixing the character truncation issue while maintaining the original purpose of clearing progress line remnants. The change is well-motivated by the reported bug and Chris Torek's earlier analysis, with a clear demonstration of the problem and solution using printf examples.

The patch touches the sideband.c file, modifying the demultiplex_sideband() function to handle the clear sequence differently. While this addresses the immediate truncation issue, the thread discussion indicates there may be related terminal attribute management concerns (like color persistence) that aren't fully resolved by this change. However, Scharfe's approach cleanly solves the original problem with minimal risk, making it a pragmatic improvement.

The change is backward compatible, maintaining the same behavior for dumb terminals while only altering smart terminal handling. The patch demonstrates good attention to detail, with careful handling of both prefixed and non-prefixed output cases. While Mikael Magnusson raised valid concerns about terminal attribute handling, this focused fix appears ready for inclusion as it solves the concrete issue without introducing new problems.
