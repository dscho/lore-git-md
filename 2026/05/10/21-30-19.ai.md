This is a bug report about a warning message in `git-svn` related to a duplicate option specification in the Perl code. The issue stems from a recent change in Getopt::Long 2.55 that now detects and warns about case-sensitive duplicate options, which will become a fatal error in future releases.

The problem occurs in `git-svn.perl` where the options `--id` and `-i` are both mapped to the same variable `$Git::SVN::default_ref_id`. While functionally correct (both options do the same thing), the new Getopt::Long behavior considers this a duplicate specification since they differ only in case when `ignore_case` is enabled.

The reporter notes this currently only produces a warning but will break in future versions of Getopt::Long. The issue appears on Fedora 43 aarch64 with git 2.54.0 and util-linux 2.41.4-7. The bug is clearly identified with links to both the problematic code and the Getopt::Long changelog explaining the new behavior.

This is a straightforward bug that needs fixing before the Getopt::Long change becomes fatal. The patch would be simple - likely just removing one of the duplicate option specifications while maintaining the same functionality. The report provides all necessary details for someone to prepare a fix.
