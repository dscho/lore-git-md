This is the final version (v3) of a documentation patch clarifying the `--follow` and `--no-follow` options for `git log`. The patch has evolved through three iterations with maintainer feedback, now accurately documenting behavior that has existed since 2012 but was previously undocumented.

The patch makes several key clarifications:
- Explicitly states that `--follow` tracks renames for single files (not directory pathspecs)
- Documents that `--no-follow` can override the `log.follow` config
- Explains how directory pathspecs affect traversal differently from file pathspecs
- Follows standard documentation conventions by listing `--no-follow` before `--follow`

The changes are well-motivated and precisely capture Git's actual behavior, which was implemented in 2012 (aebbcf5797) and enhanced in 2015 (076c98372e). Maintainer Junio Hamano provided substantive review that helped shape the final wording, particularly around the subtle distinction between file and directory pathspec handling. The patch is now in excellent shape for merging, representing a clear improvement that will help users understand this long-standing but poorly documented feature.
