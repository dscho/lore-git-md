This is a bugfix addressing terminal output corruption when displaying remote messages in Git. The patch modifies how Git clears progress lines when printing remote content (like GitLab merge request URLs) in terminals where the line width exactly matches the terminal width.

The issue occurs because Git currently adds an ANSI clear-to-end sequence (`\033[K`) at the end of remote messages, which can truncate the last character when lines fill the terminal width. René Scharfe's solution moves this clear sequence to the start of the line instead, while maintaining the same progress-clearing functionality that was originally added in 2007.

The change is well-motivated by the reported bug and Chris Torek's analysis, showing a clear before/after improvement in terminal output behavior. The patch handles both smart terminals (using ANSI codes) and dumb terminals (falling back to spaces) appropriately. While the solution doesn't address all possible terminal edge cases (like color attribute persistence during line wrapping), it cleanly solves the specific truncation issue while preserving the original progress-clearing purpose. The implementation is straightforward and maintains backward compatibility.
