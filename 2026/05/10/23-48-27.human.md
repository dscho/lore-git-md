This is a documentation patch series (now at v3) about the `--follow` and `--no-follow` options for `git log`. Maintainer Junio Hamano provides additional technical context about the limitations of the `--follow` feature, which tracks file renames but has implementation constraints.

Junio notes that `--follow` was never designed to handle complex cases - it only properly tracks a single file's rename history and breaks down with non-linear histories where a file might have multiple rename sources. He suggests the documentation should be more explicit about these limitations rather than implying broader pathspec support.

The author Tamir Duberstein had already incorporated Junio's earlier feedback about single-file tracking in v3, but this email reveals deeper technical constraints that weren't previously documented. The exchange shows how Git's documentation process surfaces subtle implementation details that might otherwise remain obscure, even for long-existing features.

This thread demonstrates the project's commitment to accurate documentation that reflects actual behavior rather than idealized functionality. The patch appears ready to merge once these final clarifications about `--follow`'s linear-history limitation are incorporated.
