This is a documentation patch (v2) clarifying the behavior of `push.default=simple` in triangular workflows, following maintainer feedback. The patch restructures the explanation to be more technically precise while maintaining clarity.

The v2 version drops the explicit mention of "triangular workflow" terminology in favor of a more general description that covers both centralized and triangular cases. It now states that `simple` mode always pushes the current branch to a same-named remote branch, but only enforces the strict upstream tracking requirement when pushing to the same remote used for pulling. This aligns with Junio Hamano's suggestion to make the documentation self-contained while accurately reflecting the safety constraints implemented in `builtin/push.c`.

The changes from v1 include:
1. Rewriting the commit message to focus on the general behavior rather than specifically calling out triangular workflows
2. Restructuring the documentation text to first establish the general rule before the exception case
3. Adding Junio's Suggested-by tag after incorporating his feedback

The patch remains focused on documenting existing behavior rather than changing functionality, and the new wording should help users better understand when the upstream tracking requirement applies. This continues the project's broader effort to improve documentation clarity under Jean-Noël Avila's synopsis-style conversion initiative.
