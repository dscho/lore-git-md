Frieder Hannenheim has floated an RFC proposing a new `git mv --index-only` option that would update Git's index to reflect file moves without performing the actual filesystem operation. This would help when files have been renamed outside Git and users want to record the move after the fact. The initial message left several design questions open around flag naming, edge cases, and directory support.

Chris Torek has now responded with a substantive technical review, pointing out that the same index updates can already be achieved by combining `git add` and `git rm` commands. While acknowledging the convenience factor, he notes that Git's rename detection would work identically either way - the proposed flag would mainly save some redundant object lookups rather than enable fundamentally new functionality. This suggests the feature's value lies more in workflow ergonomics than technical necessity. The discussion now turns on whether the ergonomic improvement justifies adding a new flag to core Git.
