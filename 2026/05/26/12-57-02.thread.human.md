Frieder Hannenheim proposed adding a `git mv --index-only` flag to explicitly record file moves in Git's index without touching the filesystem, motivated by cases where Git's automatic rename detection failed after manual file operations. The discussion has centered on whether this convenience feature is justified given existing alternatives.

Chris Torek provided substantive technical review, noting the same index state can be achieved through `git add`/`git rm` sequences. D. Ben Knoble reinforced this point, observing that `git add old new` alone would suffice. Both reviewers acknowledge the use case but question whether it warrants a new flag when current commands already provide the functionality, albeit less conveniently.

The thread remains open questions include whether the workflow improvement justifies the change, what the flag should be named, and how it would interact with other `git mv` options. Frieder's original motivation - addressing cases where unstaged changes interfere with rename detection - stands as the primary argument for the feature, while multiple reviewers have noted the technical equivalence to existing approaches. The discussion now awaits maintainer input on whether the convenience benefits outweigh the added complexity.
