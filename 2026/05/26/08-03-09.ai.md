This is a bugfix addressing a preload-index issue with `--really-refresh` and assume-unchanged entries. The patch is part of a two-patch series introducing a new `--refresh-stat-only` option for `git update-index`, but this first patch stands alone as a necessary fix.

The bug occurs when preload-index runs before the main refresh loop in `refresh_index()`. Currently, preload-index honors the assume-unchanged bit even when `--really-refresh` is specified, causing modified files marked assume-unchanged to be incorrectly marked as up-to-date. The subsequent refresh loop then skips these entries, failing to report needed updates.

The fix plumbes refresh flags through to preload threads and adds `CE_MATCH_IGNORE_VALID` when `REFRESH_REALLY` is active. This ensures preload pass respects the `--really-refresh` override of assume-unchanged. The change is tested by forcing preload with `GIT_TEST_PRELOAD_INDEX=1` and verifying a modified assume-unchanged file is properly reported as needing update.

The patch appears well-constructed with:
1. Clear explanation of the bug scenario
2. Minimal code changes focused on the specific issue
3. A regression test that fails without the fix
4. Preservation of existing behavior when `--really-refresh` isn't used

This seems like a straightforward improvement that should be uncontroversial to merge. The fix is particularly relevant given the series' broader context of improving stat-handling behavior in CI/container workflows.
