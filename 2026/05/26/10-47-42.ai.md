This is a feature patch series (v2) extending `git commit --fixup` functionality to support more message specification options. The series follows up on feedback from Junio Hamano and Phillip Wood on v1, with two main changes:

1. A refactor to handle message sources more cleanly by routing all `--fixup` variants through `prepare_to_commit()` rather than special-casing `-F` handling. This addresses Junio's concern about losing message origin information and Phillip's suggestion for better code reuse.

2. Expanded scope to include `-c/-C` options for all `--fixup` variants, not just `-m/-F` as in v1. The author notes this makes the behavior more consistent across all message specification methods, though they're open to dropping this change if reviewers prefer.

The cover letter explains some subtle behavior around `-c/-C` with amend-style messages, where the source commit's "amend!" line is stripped to match the behavior of interactive editing. The author also lists smaller fixes from v1 review feedback, including softened terminology and test improvements.

The implementation appears well-considered, with thorough test coverage and careful attention to backward compatibility. Both substantive reviews from Junio and Phillip in v1 have been addressed, and the author's responses demonstrate good technical understanding of the feedback. The patch series remains focused on its core goal of enabling non-interactive workflows for fixup commits while maintaining the existing behavior when no message options are provided.
