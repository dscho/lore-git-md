This is a test patch that plugs a gap in the test coverage for `git init` when used with the `GIT_OBJECT_DIRECTORY` environment variable. The patch is part of a larger 8-part series (v2) focused on centralizing object database creation.

The test verifies that when `GIT_OBJECT_DIRECTORY` is set, `git init` correctly creates the object directory at the specified path rather than the default `.git/objects` location. This behavior is documented but was previously untested, leaving room for potential regressions. The new test creates a custom object directory, initializes a repository with the environment variable set, and verifies the object files are created in the expected location while being absent from the default path.

The patch comes from Patrick Steinhardt, a major contributor who frequently works on object storage and refactoring efforts. The test follows Git's standard test patterns using `test_path_is_missing` and `test_path_is_dir` assertions, and includes proper cleanup via `test_when_finished`. This is a straightforward but important test addition that will help prevent future regressions in repository initialization behavior.
