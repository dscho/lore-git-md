This is a v2 of a shell completion patch that modifies how Git handles dotfiles in path completion for `git rm`, `git mv`, and `git ls-files`. The change aligns Git's completion behavior with standard shell conventions by hiding dotfiles (like .gitignore) unless explicitly requested with a leading dot.

The key technical changes in this version:
- Adds a new `hide-dotfiles` parameter to the internal `__git_index_files` helper
- Modifies AWK processing to filter dotfiles when completing empty path components
- Still shows dotfiles when explicitly completing paths starting with dot (e.g. `git rm .` completes to `.gitignore`)
- Updates the test suite to verify both the new default behavior and explicit dot completion
- Removes four TODO comments from t/9902-completion.sh that had been expecting this behavior since 2013

The patch addresses Junio C Hamano's feedback from v1 by:
- Expanding the commit message to better explain the rationale and standard shell behavior
- Keeping the explicit dot completion capability
- Adding historical context about the long-standing TODO comments

The implementation appears thorough, passing both shell syntax checking and the completion test suite. This remains a somewhat opinionated change - while it matches shell conventions, it does modify existing Git behavior that some users may have come to expect. The discussion in the thread suggests this may need further justification or consideration of whether tracked dotfiles should be treated differently.
