This is patch 6/8 in Patrick Steinhardt's series refactoring repository initialization and object database setup. The patch fixes an edge case where Git was unnecessarily initializing an object database even when no repository existed, which could happen when the GIT_DIR_EXPLICIT environment variable pointed to a non-existent directory.

The key change moves object database initialization inside the conditional block that checks for a valid repository, rather than doing it unconditionally. This makes logical sense since there's no need for an object database if there's no repository. The patch also updates commit-graph handling to check for the presence of an object database rather than checking gitdir, which better reflects the actual dependency.

The only functional impact is fixing a corner case where git-index-pack could fail when run outside a repository due to commit parsing attempting to access a non-existent commit-graph. The changes are focused and well-explained, touching just two files with minimal diffs. This continues the series' pattern of careful, incremental improvements to the initialization code.
