This is a documentation patch for the proposed `git son` command, part of Evan Haque's RFC series introducing a new way to create loosely-coupled child repositories. The patch adds a man page (`git-son.adoc`) following Git's standard AsciiDoc format, explaining the command's purpose, options, and usage examples.

The documentation clearly differentiates `git son` from submodules by emphasizing the child repository's independence - it's not tracked in the parent's index, just linked via a "parent" remote. The man page covers the two main options (`--inherit` to fetch parent history and `--branch` to specify which branch to inherit) and includes practical examples showing both basic and advanced usage.

The patch integrates cleanly with Git's build system by adding the man page to `Documentation/meson.build`. The documentation appears thorough and well-structured, matching the quality seen in established Git commands. As this is part of an RFC series, the content may evolve based on feedback, but the current version provides a solid foundation for discussion.

The "Assisted-by" trailer for Claude Opus 4.6 suggests AI assistance was used in crafting the documentation, though the content reads as professionally as any human-written Git man page.
