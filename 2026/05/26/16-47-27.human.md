This is the first implementation patch in Evan Haque's series proposing a new `git son` command, which creates independent child repositories with loose parent-child relationships. The command differs from submodules by not tracking the child in the parent's index - instead it simply adds the child directory to `.gitignore` and sets up a "parent" remote in the child pointing back to the original repository.

The shell script implementation handles:
- Basic argument parsing for `--inherit` (to pull parent history) and `--branch` options
- Directory creation and `.gitignore` updating
- Repository initialization with proper remote configuration
- Graceful error handling and cleanup

The patch appears well-structured with clear error messages and edge case handling. The implementation matches the design described in the cover letter, focusing on establishing repository lineage without tight coupling. The use of standard Git plumbing commands (`git init`, `git remote`, etc.) suggests the author understands Git's internal conventions.

This introduces new functionality that could be useful for workflows needing related-but-independent repositories, though reviewers will likely question whether it merits a new porcelain command versus being a `contrib/` script. The "son" naming metaphor is also novel for Git's CLI and may prompt discussion about consistency with existing commands.
