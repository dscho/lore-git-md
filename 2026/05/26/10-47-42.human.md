This is a feature patch series (v2) extending `git commit --fixup` functionality to support more message specification options. The series builds on feedback from Junio Hamano and Phillip Wood on the initial version.

The first patch now allows `-m` and `-F` options to work with all `--fixup` variants (plain, amend, and reword), refactoring the message handling to flow through `prepare_to_commit()` rather than special-casing file reading. This addresses Junio's concern about losing message origin information and Phillip's suggestion for better code reuse.

The second patch extends support to `-c` and `-C` options, which the author found naturally fell out of the refactoring. There's one subtle behavior where `-c/-C` will strip "amend!" lines from source commit messages to match the behavior of interactive amend fixups. The author notes this could be changed if reviewers prefer.

The series includes thorough test updates and documentation improvements. The author has incorporated all substantive feedback from v1, including:
- Softening "unusable" to "poorly suited" in documentation
- Correcting the claim about `-m` being a no-op with plain `--fixup`
- Using Phillip's suggested `test_commit_message` helper
- Standardizing test output expectations

The changes enable more flexible non-interactive workflows, particularly for automated tools that want to specify commit messages programmatically. The implementation appears well-considered, with clear attention to backward compatibility and edge cases. Both patches build on the same refactoring to provide a more flexible interface while maintaining the existing behavior when no message options are provided.
