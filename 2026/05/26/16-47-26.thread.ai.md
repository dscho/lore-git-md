Thread subject: [RFC PATCH 0/3] git-son: Introduce child repository creation command. Thread type: feature proposal. Originating author: Evan Haque via GitGitGadget.

Core proposal: A new `git son` command to create independent child repositories with loose parent-child relationships, distinct from submodules. Key characteristics:
- Child gets parent remote pointing to original repo (named "parent" in current implementation)
- Parent's .gitignore updated to exclude child directory
- No index tracking in parent (unlike submodules)
- Child repositories remain fully self-contained
- Optional `--inherit` fetches parent history into child
- `--branch` specifies which parent branch to inherit from

Implementation details:
- Shell script (`git-son.sh`) using `git-sh-setup` for core functionality
- Handles both remote and local parent repositories
- Robust error checking for existing directories and invalid flag combinations
- Cleanup on failure follows Git conventions
- Documentation and man page in Documentation/git-son.txt
- Test coverage in t/t9999-git-son.sh covering creation, remote setup, .gitignore handling, flag validation

Open questions:
- Whether this functionality merits a new porcelain command vs being a contrib script
- Naming consistency with existing Git commands ("son" metaphor is new to Git CLI)
- "parent" remote naming (alternatives like "upstream" could be considered)
- Potential overlap with existing workflows using submodules or subtrees
- Shell implementation robustness and portability concerns
