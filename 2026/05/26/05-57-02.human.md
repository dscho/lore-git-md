This is patch 7/8 in Patrick Steinhardt's series refactoring repository initialization and object database setup. The patch eliminates a redundant call to `repo_read_loose_object_map()` during repository initialization.

The change is straightforward - during repo initialization, the loose object map was being read twice: once via `repo_set_compat_hash_algo()` (called by `apply_repository_format()`) and again directly in `repo_init()`. This patch removes the second, redundant call while maintaining the same functionality.

This is a small but meaningful cleanup that follows logically from the series' goal of centralizing and streamlining repository setup code. The change touches only `repository.c` and doesn't affect user-visible behavior. It demonstrates Patrick's attention to detail in eliminating unnecessary operations during critical initialization paths.

The patch has already been reviewed and approved as part of the complete series, which is now ready for integration. This particular change is a mechanical improvement that builds on the more substantial architectural refactoring done in the earlier patches.
