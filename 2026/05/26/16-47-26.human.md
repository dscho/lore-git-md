This is a feature proposal introducing a new `git son` command to create independent child repositories. The command aims to provide a lightweight alternative to submodules when creating related but independent projects.

Evan Haque proposes `git son` as a porcelain command that creates a new repository inside the current working tree, establishing a one-way relationship where the child knows about its parent (via a `parent` remote) but the parent only tracks the child's directory in `.gitignore`. This avoids the tight coupling of submodules while still preserving the lineage connection.

The implementation comes as a shell script with options to optionally inherit parent history (`--inherit`) and check out a specific parent branch (`--branch`). The series includes full documentation and a test suite covering creation, remote configuration, `.gitignore` updates, and various edge cases.

The motivation is clear - this automates a common manual workflow (init + remote add + gitignore) while establishing a convention for parent-child relationships. The design appears well-considered, with attention to edge cases like local-only parents and clear validation of flag combinations. The test coverage looks thorough for the core functionality.

As a new user-facing command, this would need careful review of the interface design and documentation. The implementation being in script form rather than C may raise questions about long-term maintenance, though the functionality seems well-suited to shell. The concept seems useful for workflows where submodules are too heavy but some lineage tracking is desired.
