# Performance optimization for sparse index in `git restore` (v2 patch 2/2)

This is the second patch in Derrick Stolee's series optimizing `git restore --staged` to avoid unnecessary sparse index expansion. The changes build on the test coverage established in patch 1 by implementing the actual optimization.

The key technical change is the introduction of a new `try_update_sparse_directory()` helper function that handles sparse directory entries at the tree level rather than expanding them. The function makes intelligent decisions based on whether the operation is in overlay mode (like checkout) or non-overlay mode (like restore --staged), updating sparse directory OIDs directly when possible to avoid expansion.

The patch also switches from `index_name_pos()` to `index_name_pos_sparse()` for individual file lookups, preventing unwanted index expansion when files are already tracked. Test expectations in t1092 are updated to verify the sparse index remains unexpanded during these operations.

This version cleanly incorporates Junio's feedback from v1 by extracting the sparse-directory logic into a dedicated function while maintaining all performance benefits. The changes demonstrate Stolee's characteristic thoroughness in sparse-index optimizations - narrowly scoped, well-tested, and preserving existing behavior while improving efficiency. The series appears ready for merging.
