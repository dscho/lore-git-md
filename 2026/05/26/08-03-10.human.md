This is the second patch in a two-part series introducing a new `--refresh-stat-only` option to `git update-index`. The feature targets CI and container workflows where filesystem metadata (like inodes and device numbers) may change while file contents remain identical.

The patch builds on the preload-index fix from part 1, adding the new flag that updates only stat information without rehashing file contents. The implementation carefully addresses historical concerns about similar proposals by:
- Making this a one-shot operation rather than a sticky configuration
- Explicitly documenting the failure mode (stale object IDs if content changes)
- Ignoring assume-unchanged bits to ensure stat data stays accurate

The tests verify key behaviors: object ID preservation, assume-unchanged handling, missing file scenarios, and quiet output. Documentation clearly warns about the tradeoffs, positioning this as a tool for automated workflows rather than interactive use.

The patch appears well-considered, with thorough test coverage and clear documentation. It solves a real pain point in modern CI environments while avoiding the pitfalls of earlier similar proposals. Given its narrow, well-motivated scope and careful implementation, this seems likely to be uncontroversial.
