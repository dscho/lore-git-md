This is a feature proposal adding a new `--refresh-stat-only` option to `git update-index`. The patch series addresses a specific workflow pain point in CI and container environments where filesystem metadata (inodes, device numbers) changes while file contents remain identical.

The cover letter makes a strong case for the feature by:
1. Identifying concrete scenarios where current solutions (full rehashing or `core.checkStat=minimal`) are suboptimal
2. Contrasting with a 2017 proposal for similar functionality while explaining how this approach is more constrained/safer
3. Explicitly documenting the failure mode (stale object IDs) and intended use cases

The series is well-structured with:
- A preparatory bugfix (patch 1) for preload-index behavior with `--really-refresh`
- The main feature implementation (patch 2) with comprehensive test coverage
- Clear documentation of both the new flag and its interaction with assume-unchanged

The author demonstrates awareness of Git's security model by designing the feature as a one-shot operation rather than a persistent state, and by carefully considering the failure modes. The test coverage appears thorough, including edge cases around missing files and assume-unchanged handling.

This looks like a well-motivated, carefully implemented feature that could significantly improve performance in containerized CI workflows while maintaining Git's safety guarantees. The patch quality and commit message clarity suggest it's likely to receive serious consideration.
