This is the third patch in Patrick Steinhardt's 8-part series refactoring repository initialization and object database setup. The patch focuses on consolidating duplicate logic for applying repository formats across multiple code paths.

The key change introduces a new `apply_repository_format()` function that centralizes the logic for configuring a repository with its format settings (hash algorithm, ref storage format, extensions, etc.). This replaces three separate implementations that were previously scattered across the codebase. The patch also renames `check_repository_format()` to `check_and_apply_repository_format()` to better reflect its dual purpose of both validating and applying the format.

The changes touch core repository setup code in `repository.c` and `setup.c`, with corresponding updates to the header file. While this is primarily an internal refactoring, it lays important groundwork for future work on pluggable object storage backends by making the format application logic more maintainable and consistent.

The patch follows Patrick's characteristic style - carefully structured with clear commit messages explaining both the technical changes and their motivation. This is a mechanical but important step in the larger effort to clean up repository initialization code.
