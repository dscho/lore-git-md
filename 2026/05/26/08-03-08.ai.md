This is a feature proposal adding a new `--refresh-stat-only` option to `git update-index`. The two-patch series addresses a specific workflow pain point in CI and container environments where filesystem stat data (inodes, device numbers) may change while file contents remain identical.

The cover letter makes a strong case for the feature by identifying concrete problems with current workarounds (full rehashing or setting `core.checkStat=minimal`). It also thoughtfully addresses historical concerns about similar proposals by designing the feature to be one-shot rather than sticky, with explicit documentation of failure modes.

The first patch fixes a latent bug in preload-index's handling of `--really-refresh` with assume-unchanged entries, adding test coverage. The second introduces the new flag with thorough testing of edge cases (missing files, assume-unchanged behavior, quiet output).

Key technical details:
- New `REFRESH_STAT_ONLY` flag added to skip content hashing while updating stat data
- Preload-index thread handling updated to respect refresh flags
- Tests cover object ID preservation and assume-unchanged interactions
- Documentation clearly warns about potential stale-object-ID risks

The implementation appears well-considered, with clear separation of concerns between the bugfix and feature addition. The test coverage is comprehensive, including both new scenarios (t2109) and regression protection for existing behavior (t2106). The proposal seems likely to be uncontroversial given its narrow, well-motivated scope and careful handling of historical concerns.
