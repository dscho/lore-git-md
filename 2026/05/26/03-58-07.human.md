This is a documentation patch clarifying the behavior of `push.default=simple` in triangular workflows. It's the second version of a patch that originally sought to document how Git falls back to 'current' behavior when pushing to a remote different from the upstream (triangular workflow case).

The v2 patch incorporates feedback from maintainer Junio Hamano, restructuring the documentation to make the 'simple' mode explanation more self-contained. Rather than specifically calling out triangular workflows, it now clearly states that the strict upstream tracking requirement only applies when pushing back to the same remote being pulled from. This maintains technical accuracy while improving clarity.

The changes are minimal but meaningful - replacing three lines of workflow-specific explanation with four lines that capture the general rule and its exception. The commit message has also been refined to better reflect the documentation improvement's scope. This appears ready for inclusion as a straightforward documentation clarification that will help users understand push behavior in both centralized and triangular workflows.
