This is the first patch in a 2-part series extending `git commit --fixup` functionality. The patch enables non-interactive message specification via `-m` and `-F` options for all `--fixup` variants (plain, amend, and reword), addressing historical limitations that made these modes poorly suited for non-interactive workflows.

The changes include:
- Removing artificial restrictions that prevented `-m`/`-F` usage with amend/reword fixups
- Refactoring message handling to route all `--fixup` variants through `prepare_to_commit()`
- Updating documentation to reflect the expanded capabilities
- Adding comprehensive test coverage in `t/t7500-commit-template-squash-signoff.sh`

The implementation maintains backward compatibility (the editor still launches when no message options are provided) while enabling new workflows. The patch demonstrates careful attention to historical context and edge cases, with test cases verifying both the new functionality and preservation of existing behavior.

This change builds on prior feedback from Junio Hamano and Phillip Wood, who had suggested better code reuse through `prepare_to_commit()` and raised concerns about message origin tracking. The author has addressed all substantive feedback from the previous iteration while expanding the solution's scope. The patch appears well-considered and ready for final review.
