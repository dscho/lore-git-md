This is the third patch in a series introducing `git son`, a new command for creating independent child repositories with loose parent-child relationships. The patch is a straightforward addition to `command-list.txt` to make `git son` appear in the standard `git help` output as a mainporcelain command.

The change is minimal - just a single line addition to register the new `git-son` command alongside other mainporcelain commands like `git-sparse-checkout` and `git-stash`. This follows Git's standard pattern for making new commands discoverable through the help system.

The patch continues the series' clean, focused approach - each change is small and well-contained. This particular patch doesn't introducing any functionality itself, but properly integrates the new command into Git's help infrastructure. The inclusion as a mainporcelain command (rather than ancillary or plumbing) signals the author's intent for this to be a user-facing feature rather than a low-level tool.

As with the rest of the series, the key design question remains whether this functionality merits a new porcelain command versus being a contrib script, but this patch simply handles the mechanical integration assuming the command will be accepted.
