This is the second patch in a two-part series introducing a new `--refresh-stat-only` option for `git update-index`. The feature targets CI and container workflows where filesystem metadata (inodes, device numbers) may change while file contents remain identical, avoiding unnecessary content rehashing.

The patch builds on the preload-index fix from part 1, adding the new flag with comprehensive test coverage. Key aspects:

1. Implementation adds `REFRESH_STAT_ONLY` flag that skips content hashing while updating stat data (mtime/ctime/inode/device)
2. Carefully documents the tradeoff: faster refreshes at the cost of potentially stale object IDs if contents change without stat updates
3. Includes tests verifying:
   - Object ID preservation across stat-only refreshes
   - Interaction with assume-unchanged entries
   - Missing file handling (with/without --ignore-missing)
   - Quiet output behavior
4. Maintains thread safety by extending preload-index handling to respect the new flag
5. Explicitly warns in documentation about the failure mode (stale object IDs) to prevent misuse

The design addresses historical concerns from a 2017 discussion by making this a one-shot operation rather than a sticky configuration, and targeting it specifically at automated workflows rather than interactive use. The implementation appears cleanly separated from existing refresh logic and well-tested.

This seems likely to be uncontroversial given its narrow, well-motivated scope and careful handling of edge cases. The thorough test coverage (including both new scenarios and regression protection) suggests the author has done their homework on this change.
