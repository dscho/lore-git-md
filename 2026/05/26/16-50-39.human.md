This is a follow-up in the discussion about adding an index-only move option to `git mv`. Frieder Hannenheim provides additional context about their specific use case where they manually modified a patch file's name and commit message, making the move undetectable by Git's automatic rename detection. They note they may not have staged the files properly, which could have affected detection.

The exchange clarifies that while the proposed `--index-only` flag would be more convenient, the same result can already be achieved through existing `git add`/`git rm` commands. Chris Torek's earlier review pointed out this alternative path while acknowledging the potential CPU efficiency benefits of a dedicated flag.

This reply doesn't introduce new technical arguments but provides a concrete example where the proposed functionality might be useful, helping ground the abstract discussion in real-world usage. The thread remains open on whether the convenience justifies adding a new flag to `git mv`.
