This is a feature patch (part 1 of 2) that expands the message specification capabilities for `git commit --fixup` variants. The patch allows using `-m` and `-F` options with all `--fixup` types (plain, amend, and reword), addressing a limitation where previously only plain `--fixup` supported `-m` and the amend/reword variants required interactive editing.

The changes refactor message handling to route all `--fixup` cases through `prepare_to_commit()`, improving code reuse while maintaining backward compatibility (the editor still launches when no message options are provided). Documentation is updated to reflect the new capabilities, and tests are added to verify the behavior with various message specification methods.

The patch builds on prior feedback from Junio Hamano and Phillip Wood, who had suggested better code organization in the v1 review. The implementation appears clean and well-tested, with careful attention to edge cases like empty messages and consecutive amend commits. This change makes `--fixup` more useful in non-interactive workflows while preserving all existing behavior.
