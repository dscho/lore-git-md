This is the first implementation patch in Evan Haque's series proposing a new `git son` command, which creates independent child repositories with loose parent-child relationships. The patch introduces the core functionality as a shell script that:

1. Creates a new repository inside the current working directory
2. Adds the child directory to the parent's .gitignore
3. Configures a "parent" remote in the child pointing back to the parent's origin URL or local path
4. Supports optional `--inherit` (to fetch parent history) and `--branch` flags

The implementation handles edge cases you'd expect - checking for existing directories, validating flag combinations, cleaning up on failure - and provides clear user output. The script uses Git's standard shell library (`git-sh-setup`) and follows typical Git command patterns.

Key technical details:
- The child is fully independent (no parent tracking like submodules)
- Works with both remote and local parent repositories
- Defaults to creating an empty repo unless `--inherit` is used
- Attempts to determine the parent's HEAD branch when inheriting history

The patch appears well-structured and focused on the core use case. Reviewers will likely examine:
- The shell implementation's robustness (error handling, portability)
- Whether this belongs in core vs contrib
- The "parent" remote naming (vs alternatives like "upstream")
- The interaction model with existing Git commands

This is a concrete implementation of the concept introduced in the cover letter, showing the command's viability while leaving design questions open for discussion.
