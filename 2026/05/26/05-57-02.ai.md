This is patch 7/8 in Patrick Steinhardt's series refactoring repository initialization and object database setup. The patch eliminates a redundant call to `repo_read_loose_object_map()` during repository initialization.

The change is straightforward: when initializing a repository, Git was reading the loose object map twice - once through `apply_repository_format()` (via `repo_set_compat_hash_algo()`) and again directly in `repo_init()`. This patch removes the second, redundant call in `repo_init()`.

The patch touches only 3 lines in `repository.c`, removing the duplicate call while maintaining all functionality since the loose object map is still read through the first path. This continues the series' theme of cleaning up redundant initialization code and centralizing object database setup logic.

This is a mechanical cleanup that doesn't change behavior but makes the initialization sequence more efficient and easier to reason about. It builds on the earlier patches in the series that reorganized repository format application and object database creation.
