# Performance optimization for sparse index in `git restore` (v2)

This is the second version of Derrick Stolee's two-patch series optimizing `git restore --staged` to better handle sparse index operations. The changes focus on avoiding unnecessary index expansion when using `..` pathspecs in sparse checkouts.

The key improvement in v2 is the extraction of sparse-directory handling logic from `update_some()` into a new helper function `try_update_sparse_directory()`. This refactoring addresses Junio Hamano's review feedback from v1, making the code more readable while maintaining the same functionality.

The series continues Stolee's ongoing work on sparse-index optimizations, following his characteristic test-first approach. The first patch adds comprehensive test coverage in t1092 that demonstrates both the current behavior and the optimization opportunity. The second patch implements the actual change to operate directly on tree entries rather than expanding to blob paths when possible.

The changes specifically target `restore --staged` operations where `SKIP_WORKTREE` paths would be ignored anyway, allowing the sparse index to remain collapsed. Performance improvements come from avoiding the in-memory expansion of the index while maintaining identical end behavior.

This version appears ready for merging, having incorporated the maintainer's feedback while demonstrating clear test coverage and measurable performance benefits for sparse checkout users. The changes are narrowly scoped to the sparse-index integration without affecting other `git restore` functionality.
