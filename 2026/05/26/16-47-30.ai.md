This is a documentation patch for the proposed `git son` command, part of Evan Haque's RFC series introducing a new porcelain command for creating independent child repositories. The patch adds a man page (`git-son.adoc`) following Git's standard documentation format and integrates it with the meson build system.

The documentation clearly explains the command's purpose - creating a child repository with a loose parent relationship (distinct from submodules) - and covers all options (`--inherit` to fetch parent history, `--branch` to specify which parent branch to use). It includes practical examples showing basic usage, inheritance, and branch selection. The man page follows Jean-Noël Avila's ongoing synopsis-style conversion effort, using AsciiDoc markup consistently.

The implementation appears thorough, with proper integration into the build system and clear, well-structured documentation that matches the command's functionality as described in earlier patches. This completes the series' documentation component, leaving only the test additions (presumably coming in patch 5/5) remaining. The patch maintains the series' focus on establishing repository lineage without tight coupling, presenting the feature as a lightweight alternative to submodules when full independence is desired.
