# Performance optimization for sparse index in `git restore` (v2 patch 2)

This is the second patch in Derrick Stolee's two-part series optimizing `git restore --staged` to avoid unnecessary sparse index expansion. The changes specifically target operations using `..` pathspecs in sparse checkouts.

The patch introduces a new helper function `try_update_sparse_directory()` that handles sparse directory entries at the tree level rather than expanding them. The function implements three key behaviors:
1. Skips directories entirely when the OID matches the source tree
2. Updates sparse directory entry OIDs directly in non-overlay mode (used by `restore --staged`)
3. Falls back to recursive descent in overlay mode (used by checkout)

The implementation also switches from `index_name_pos()` to `index_name_pos_sparse()` for individual file lookups to prevent triggering full index expansion. Test expectations in t1092 are updated to verify the sparse index remains unexpanded during these operations.

This version cleanly incorporates Junio Hamano's feedback from v1 by extracting the sparse-directory logic into a dedicated function while maintaining all the performance benefits. The changes demonstrate Stolee's characteristic attention to both optimization and code organization in the sparse-index subsystem. With comprehensive test coverage and the maintainer's requested refactoring addressed, this appears ready for merging.
