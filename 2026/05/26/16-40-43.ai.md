Review of a technical alternative to the proposed `git mv` feature.

Chris Torek responds to Frieder Hannenheim's RFC about adding an index-only move option to `git mv`, pointing out that the same effect can already be achieved through existing commands. He notes that combining `git add` and `git rm` would produce identical index changes to the proposed feature, though acknowledges the convenience factor of a dedicated flag.

The review highlights that Git's rename detection would work the same way regardless of whether the move is recorded via separate commands or a hypothetical new flag. Torek's technical assessment suggests the proposed feature would offer ergonomic improvements rather than fundamentally new functionality, with the main benefit being slightly reduced CPU overhead from avoiding redundant object database lookups.

This is a substantive review that engages with the technical merits of the proposal by comparing it to existing capabilities. The response doesn't reject the idea outright but provides important context about how rename tracking already works in Git's object model. The observation about rename detection working equivalently either way may influence how the proposal evolves in subsequent iterations.
