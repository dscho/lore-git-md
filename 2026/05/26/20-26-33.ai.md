# Test coverage for sparse index behavior in `git restore`

This is the first patch in Derrick Stolee's two-part series optimizing `git restore --staged` for sparse checkouts. It establishes test coverage demonstrating the current behavior where `git restore --staged` unnecessarily expands the sparse index when using certain pathspecs.

The tests verify several scenarios:
- Restoring staged changes within the sparse checkout definition
- Restoring staged changes that include paths outside the sparse definition
- Wildcard pathspec handling
- Confirmation that the sparse index currently expands in these cases

The test structure follows Stolee's established pattern for sparse-index work, using the `t1092-sparse-checkout-compatibility.sh` test infrastructure he previously created. The tests carefully compare behavior between full checkouts and sparse checkouts while verifying index state consistency.

This test-first approach is characteristic of Stolee's sparse-index optimizations, ensuring any implementation changes in the subsequent patch will have clear behavioral expectations. The tests demonstrate that while the current implementation works correctly, it could be more efficient by avoiding index expansion when SKIP_WORKTREE paths are involved.
