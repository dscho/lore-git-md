This is a UX improvement patch for the config subsystem, finalizing the series that improves error messages when users mistakenly use `=` syntax in `git config` commands. The v4 patch from Harald Nordgren responds to Junio's feedback from v3 with several key refinements:

1. The error messaging now clearly identifies the root problem (missing value) rather than just reporting "invalid key" or "wrong number of arguments". This makes it immediately clear what went wrong when users type commands like `git config pull.rebase=false`.

2. The "did you mean" hint is now more selective - it only appears when the part before the `=` is a valid config key (like `pull.rebase`), avoiding false positives for invalid syntax like `foo=bar`. This prevents misleading suggestions when the input is clearly malformed.

3. The implementation handles all command variants consistently - explicit `set` subcommand, implicit form, and 2-arg cases - through a new `die_missing_set_value()` helper that centralizes the error handling logic.

4. Comprehensive test coverage verifies edge cases including invalid keys, numeric components, valid subsection syntax, and cases where hints should/should not appear. The tests confirm the behavior aligns with Git's existing config key validation rules.

The patch appears to address all of Junio's v3 concerns while maintaining the original goal of helping users who accidentally use `=` syntax. With the improved key validation and clearer error messages, this seems ready for final review and potential merging. The changes are well-contained to the config command implementation and its tests, with no impact on other subsystems.
