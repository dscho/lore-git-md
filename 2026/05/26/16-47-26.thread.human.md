Evan Haque has proposed a new `git son` command to create independent child repositories with loose parent-child relationships. Unlike submodules, these child repos would be fully self-contained but maintain a lightweight connection to their parent through a configured remote. The initial RFC patch series introduces the concept and provides a working shell script that handles creation, .gitignore updates, and remote setup, with options to inherit parent history or start fresh.

The first implementation patch demonstrates how the command would work in practice: creating a new repo, adding it to the parent's .gitignore, and setting up a "parent" remote. It supports both local and remote parents and includes basic error handling. The approach seems technically sound, though questions remain about whether this belongs in core Git versus the contrib directory, and whether the "son" metaphor aligns with Git's existing command naming conventions.

This is the thread's first substantive reply (the initial patch), so discussion is just getting started. Key points for reviewers to weigh in on include the shell implementation's robustness, the remote naming choice, and how this feature compares to existing alternatives like submodules or subtrees.
