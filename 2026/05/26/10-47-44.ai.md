This is the second patch in Erik Cervin-Edin's v2 series extending `git commit --fixup` functionality. The patch completes the work started in the first patch by adding support for `-c` and `-C` message specification options across all `--fixup` variants (plain, amend, and reword).

The key technical change removes the artificial restriction that previously blocked `-c/-C` with `--fixup`, routing these cases through the same `prepare_to_commit()` path used for other message sources. The implementation carefully handles amend-style messages by stripping "amend!" lines when copying from source commits, maintaining consistency with the interactive editing behavior.

The patch includes comprehensive test coverage verifying:
- Basic `-C` functionality with plain `--fixup`
- `-c` behavior with amend-style fixups
- Message equivalence between `-C` and interactive editing paths
- Proper handling of nested fixup/squash scenarios
- Documentation updates reflecting the expanded capabilities

This builds on the v1 feedback from Junio Hamano and Phillip Wood, with all their substantive concerns addressed. The implementation appears robust, with thorough test coverage and careful attention to edge cases. The changes maintain backward compatibility while making message specification more flexible for non-interactive workflows.

The patch series as a whole now provides consistent support matrix for all message specification methods (`-m`, `-F`, `-c`, `-C`) across all `--fixup` variants, completing the feature enhancement originally proposed.
