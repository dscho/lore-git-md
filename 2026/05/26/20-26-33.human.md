This is the first patch in Derrick Stolee's v2 series optimizing `git restore --staged` for sparse index operations. It establishes test coverage demonstrating the current behavior where the sparse index unnecessarily expands when using certain pathspecs.

The patch adds five new test cases to t1092-sparse-checkout-compatibility.sh that verify:
1. Basic `restore --staged` behavior within the sparse checkout definition
2. Handling of staged changes outside the sparse definition
3. Wildcard pathspec behavior
4. Current sparse index expansion behavior (which the series will address)
5. Expansion behavior with `--source` option

The tests follow Stolee's characteristic thorough approach to sparse-index testing, carefully comparing behavior between full and sparse checkouts. This provides a solid baseline for the optimization coming in patch 2/2, where the unnecessary index expansion will be eliminated while maintaining all the tested behaviors.

As the first part of a performance optimization series, this patch does exactly what it should: clearly document the current state before making changes. The test coverage is comprehensive and will help ensure the optimization doesn't introduce regressions.
