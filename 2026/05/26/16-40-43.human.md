Feature proposal discussion for `git mv` index-only updates.

Chris Torek responds to Frieder Hannenheim's RFC about adding an index-only` flag to `git mv`. He notes that the same effect can already be achieved by combining `git add` and `git rm`, though acknowledges a dedicated flag would be more convenient and slightly more efficient by avoiding redundant object database checks.

The reply suggests the proposed feature is essentially a quality-of-life improvement rather than enabling fundamentally new functionality. Torek points out Git's rename detection would work the same way regardless of whether the move is recorded via the proposed flag or the existing two-command sequence.

This early feedback indicates the proposal may face questions about necessity given existing workflows, though the efficiency argument (avoiding duplicate object checks) could provide technical justification. The discussion hasn't yet touched on the specific design questions raised in the original RFC (flag naming, edge case handling, etc.).
