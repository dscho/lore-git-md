Thread summary:

Frieder Hannenheim proposes a new `git mv` feature to update Git's index for file moves without performing the actual filesystem move. The core use case is when files have been renamed outside Git (e.g., by external tools or manual operations) and the user wants Git to recognize the move after the fact. The proposal is at an early RFC level with no implementation yet provided.

Key open questions needing design decisions:
- Flag naming (`--index-only` vs `--no-move` being candidates)
- Behavior when source file still exists
- Interaction with existing `git mv` flags like `--force`
- Whether directory moves should be supported

Implementation would modify builtin/mv.c and require documentation updates. The thread begins with this exploratory message to assess community interest before proceeding with a patch series. No reviewers have commented yet on the concept's viability or suggested alternative approaches. The proposal appears motivated by practical workflow needs though specific real-world scenarios driving the feature aren't detailed in this initial post.
