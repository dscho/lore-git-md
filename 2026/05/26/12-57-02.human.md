Feature proposal for `git mv` to support post-move index updates.

Frieder Hannenheim suggests adding a new flag to `git mv` that would update Git's index to reflect a file move/rename without actually moving the file on disk. This would be useful when:
1. A file has already been moved manually or by an external tool
2. The user wants Git to recognize the move after the fact

The proposal is straightforward and addresses a real workflow gap - currently users must either use `git rm`/`git add` or accept that Git won't track the rename properly. The use case seems valid, though the email doesn't specify the exact flag name or implementation details that would be needed.

This appears to be a well-motivated quality-of-life improvement for users who work with external tools that rename files. The simplicity of the proposal suggests it could be uncontroversial, though reviewers may want to discuss whether this belongs in `git mv` or as a separate plumbing command.
