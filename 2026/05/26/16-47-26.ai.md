This is a feature proposal introducing a new `git son` command to create independent child repositories with a lightweight parent-child relationship, distinct from submodules. The series comes from Evan Haque via GitGitGadget.

The command automates creating a new repository inside an existing one while maintaining loose coupling - the child gets a "parent" remote pointing back to the original repo, and the parent's .gitignore is updated to exclude the child directory. Unlike submodules, there's no index tracking in the parent. The implementation includes:
- A shell script (`git-son.sh`) with `--inherit` (to fetch parent history) and `--branch` options
- Documentation and man page
- Comprehensive tests covering creation, remote setup, .gitignore handling, and flag validation

The design emphasizes independence - the child is fully self-contained with only the parent remote linking them. The proposal is well-structured with clear motivation (avoiding submodule overhead for independent projects), thorough documentation, and test coverage. The implementation appears clean and focused on the narrow use case of establishing repository lineage without tight coupling.

This would be the first introduction of the "son" metaphor into Git's command set, which may warrant discussion about naming consistency with existing commands. The technical approach seems sound, though reviewers may question whether this functionality merits a new porcelain command versus being a script in `contrib/`.
