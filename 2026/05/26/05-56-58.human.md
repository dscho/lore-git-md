This is the third patch in Patrick Steinhardt's 8-part series refactoring repository initialization and object database setup. The patch focuses on consolidating duplicate logic for applying repository formats.

The key change introduces a new `apply_repository_format()` function that centralizes the scattered logic for applying repository format settings (hash algorithm, ref storage, extensions, etc.) to a repository. Previously this logic was duplicated across three different locations. The patch also renames `check_repository_format()` to `check_and_apply_repository_format()` to better reflect its dual purpose.

The changes touch core setup code in `repository.c` and `setup.c`, with corresponding updates to the header file. While this is primarily a refactoring with no user-visible behavior changes, it's an important step in Patrick's larger effort to clean up repository setup logic and prepare for future extensions like pluggable object storage backends.

The patch follows Patrick's typical careful style - each change is well-motivated in the commit message, and the diff shows thorough attention to both functionality and error handling. This is solid groundwork that makes the codebase more maintainable while paving the way for future work in this area.
