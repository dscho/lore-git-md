This is the first of two patches in Harald Nordgren's v13 series adding `--track=fetch` functionality to `git checkout`/`git switch`. The patch refactors branch.c to expose two key functions that handle remote lookup for tracking branches:

1. `find_tracking_remote_for_ref()` - Identifies which remote a tracking ref belongs to by examining fetch refspecs across all configured remotes. This centralizes the logic previously embedded in `setup_tracking()`.

2. `advise_ambiguous_fetch_refspec()` - Provides consistent advice when multiple remotes match a tracking ref, moving this messaging out of `setup_tracking()`.

The refactoring enables the second patch to reuse these helpers for the new `--track=fetch` feature, ensuring checkout/switch behave identically to `git branch --track` when resolving ambiguous remote configurations. The changes are purely structural - no behavior changes in existing functionality.

Key technical details:
- Moves `struct tracking` to branch.h for cross-file use
- Updates callback to work with external string_list storage
- Preserves all existing error handling and advice messages
- Maintains identical behavior for `git branch --track`
- Prepares for checkout/switch to share the same remote resolution logic

The patch follows Git's convention of splitting refactoring from feature work, making the actual `--track=fetch` implementation in patch 2/2 a straightforward consumer of these new helpers. This version addresses the thread's final polish point by ensuring checkout/switch will produce the same messages as `git branch --track` when encountering ambiguous remote configurations.
