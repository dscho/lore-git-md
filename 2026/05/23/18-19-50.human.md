This is a bugfix patch in the git-gui series, specifically addressing how the blame subcommand handles uncommitted changes in worktrees. The patch corrects git-gui's behavior to match core Git's `git blame` when dealing with uncommitted files.

The key changes:
- Fixes a discrepancy where git-gui would show full unannotated content for unknown files (those not in worktree but present in current branch), while `git blame` would report them as unknown
- Properly implements worktree content usage for blame by setting `use_worktree` flag when appropriate
- Maintains the existing behavior of using HEAD as default when no revision is specified
- Adds explicit type checking for worktree files when in blame mode

The patch will be squashed into patch 11/11 in the next version of the series. This completes the alignment of git-gui's blame behavior with core Git's handling of worktree files, resolving a long-standing inconsistency dating back to 2007. The maintainer (Johannes Sixt) has already approved the broader series, and this fix addresses one of the final behavioral mismatches.
