This is a bugfix patch in the git-gui series addressing argument parsing inconsistencies between git-gui's blame/browser commands and core Git's behavior. Johannes Sixt (the git-gui maintainer) provides detailed feedback on Mark Levedahl's proposed changes to align the subcommands with core Git's argument handling.

The discussion centers around several key issues:
1. The current git-gui implementation incorrectly handles `--` argument delimiters in some cases, producing behavior that diverges from core Git's blame command
2. There's disagreement about whether to use `git rev-parse` (Johannes' suggestion) versus `git ls-tree` (Mark's implementation) for repository-based path validation
3. The patch currently breaks the ability to blame uncommitted changes in the worktree, which Johannes identifies as a regression
4. Johannes points out that core Git's documentation has stated since 2006 that the path should always come last in blame commands, though the implementation wasn't fully adjusted

Johannes provides specific technical guidance:
- Argument parsing should delegate to `git rev-parse` rather than reimplementing the logic
- The `--line=` parameter validation should be preserved
- The behavior with and without a worktree doesn't need to be identical
- The current patch's removal of error checking for non-existent paths is problematic

This feedback indicates the patch needs revision before final acceptance, particularly around the argument parsing implementation and worktree behavior preservation. The thread shows the maintainer engaging deeply with the details of the change to ensure git-gui maintains compatibility with core Git's established behavior patterns.
