This is the final patch in a 4-part series introducing support for external commands to display Git notes. The patch implements the core functionality that allows configuring an external command (via `notes.externalCommand`) which Git will execute to fetch notes content, with the command receiving commit object IDs as input.

The implementation includes:
- A new protocol where Git sends commit IDs to the helper and receives either "missing" or the note content
- Timeout handling for the external process (configurable via `notes.externalCommandTimeoutMs`)
- Configuration options for the notes header label (`notes.externalCommandName`) and grep integration (`notes.externalCommandForGrep`)
- Integration with commands like `git log`, `git range-diff`, and `git format-patch`
- Extensive test coverage (400+ lines across 6 test scripts)

The motivation is to allow more flexible notes display, particularly for large repositories where keeping local notes refs synchronized can be expensive. The external command approach lets users implement their own freshness policy while maintaining Git's standard notes display formatting.

Security considerations:
- The command can only be configured in protected configuration (not per-repo)
- Timeouts prevent hanging on slow commands
- Input/output is strictly validated

The patch builds on preparatory work in earlier patches (timeout infrastructure, test coverage for existing notes behavior) and has evolved through review feedback, dropping earlier approaches like force-killing helpers in favor of simpler timeout mechanisms.
