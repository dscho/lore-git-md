Subject: git log --follow improvement for subtree merges

Miklos Vajna proposes fixing a limitation in `git log --follow` where it fails to follow renames across subtree merges, only showing history from the outer repository. The current implementation in `log_tree_diff()` doesn't properly handle cases where a path is unchanged in all parents except one during subtree merges.

The patch modifies the rename-following logic to detect when:
1. A path is unchanged in all parents except one (treating file additions as "unchanged")
2. There's a clear single parent with changes
In such cases, it follows the rename from the changed parent. This handles the common subtree merge case where a file is added in one parent and renamed in another, while preserving existing behavior for ambiguous cases with multiple rename sources.
