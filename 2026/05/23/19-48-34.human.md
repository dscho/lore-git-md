This is the second patch in Harald Nordgren's series adding a `--track=fetch` mode to `git checkout` and `git switch`. The feature allows automatically fetching from the remote when creating a tracking branch, addressing the common workflow pain point where users must manually fetch before checking out remote branches.

The patch implements the actual `--track=fetch` functionality, building on the refactoring from patch 1/2 which exposed the shared remote lookup logic. Key behaviors:
- When given a remote/branch name (e.g. `origin/foo`), it fetches just that branch before checkout
- When given a bare remote name (e.g. `origin`), it follows the remote's HEAD to determine which branch to fetch
- Fails cleanly if the remote isn't configured, the refspec is ambiguous, or the fetch fails (unless the ref already exists locally)
- Integrates with existing tracking modes (`direct` and `inherit`) via comma-separated syntax
- Includes comprehensive test coverage (276 lines of new tests) for all edge cases

The implementation appears solid, with careful attention to error handling and maintaining consistent behavior with `git branch --track`. Junio and Phillip Wood had already approved the technical approach in v12, and this version addresses the final polish point by fully sharing the remote resolution logic. The feature looks ready for merging.
