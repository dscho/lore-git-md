This is the second patch in Harald Nordgren's series adding `--track=fetch` functionality to `git checkout`/`git switch`. The feature allows automatically fetching from the remote when creating a tracking branch, addressing the common workflow pain point where users must manually fetch before checking out remote branches.

The implementation builds on the refactoring from patch 1/2, using the exposed `find_tracking_remote_for_ref()` function to consistently handle remote resolution across commands. Key behaviors:

- When given a remote/branch (e.g. `origin/foo`), fetches just that branch
- For bare remote names (e.g. `origin`), follows `refs/remotes/<remote>/HEAD`
- Fails cleanly when no remote matches or when multiple remotes could apply
- Falls back to existing refs when fetch fails but the ref exists locally
- Includes comprehensive test coverage (276 lines) for all edge cases
