This thread introduces a 4-patch series by Siddh Raman Pant that adds support for external commands to display Git notes content, allowing custom storage backends or transformation logic. The series (now at v3) has been awaiting review for three weeks despite two pings, and while technically mature—with robust test coverage and integration across multiple Git commands—it has received no substantive feedback until now.

Johannes Sixt (Hannes) has just raised a fundamental objection to the entire approach. He argues that the problem motivating this feature—stale notes in large repositories—could be better solved by improving Git’s native notes implementation or by tracking review metadata outside Git entirely (e.g., in a database). Hannes dismisses the external command design as "overengineered" and questions whether it aligns with Git’s principles, framing the kernel workflow use case as too niche to justify the complexity. His critique focuses solely on the architectural decision, not the implementation details, and is likely to shift the discussion toward whether Git should support extensibility patterns like external helpers for core features.

The series itself introduces a new protocol where external commands receive commit OIDs via stdin and return length-prefixed notes content, with configurable timeouts, input validation, and CLI flags for opt-in/out. It integrates with `log`, `range-diff`, `describe`, and `name-rev`, and includes 448 lines of tests covering edge cases like timeouts and malformed responses. However, the lack of prior review—combined with Hannes’ objection—means the path forward is now uncertain. If the thread pivots to a design debate, the series may need significant rework or could stall entirely.
