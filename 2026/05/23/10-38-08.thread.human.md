This thread is about a 4-patch series (v3) by Siddh Raman Pant that adds support for external commands to display Git notes content. The goal is to let Git delegate notes retrieval to external programs, enabling custom storage backends or transformation logic—originally motivated by TOCTOU (time-of-check-to-time-of-use) issues with stale notes in large repositories like the Linux kernel.

The series has sparked an architectural debate. Johannes Sixt (Hannes) criticized the premise, arguing the problem could be solved by improving Git’s native notes implementation or tracking review metadata externally (e.g., in a database). Siddh has now responded, defending the design. He contends that Git’s ref-based storage makes native improvements impractical for historical notes, and that external tracking sacrifices the coherence of displaying notes alongside commits. He also broadened the motivation, citing a 2022 thread from an Oracle Linux colleague and a kernel tool that annotates commits with external data, framing the feature as a general solution for such use cases.

No technical review of the implementation has occurred yet. The series itself is well-structured, with robust test coverage, configurable timeouts, and integration into commands like `log` and `range-diff`. Key open questions include whether the use cases justify the complexity, how to handle security risks (e.g., malicious helpers), and whether the protocol is sufficiently robust. The thread remains in early stages, with no other reviewers weighing in despite two prior pings. The outcome may hinge on whether the community sees this as a pragmatic extension or an over-engineered solution for a niche problem.
