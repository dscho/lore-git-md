This thread introduced a 4-patch series (v3) by Siddh Raman Pant to add support for external commands to display Git notes, aiming to address TOCTOU issues in large repositories and enable custom storage backends. The series has stalled due to an unresolved architectural debate with Johannes Sixt (Hannes), who argued the problem could be solved by improving Git's native notes implementation or tracking metadata externally. Despite three pings over four weeks, Hannes and other reviewers remained silent, leading the author to conclude the series is effectively rejected with a resigned "Assuming a NACK then."

The implementation itself—introducing a protocol for external commands to return length-prefixed notes content, new configuration options (`notes.externalCommand`, `notes.externalCommandTimeoutMs`), and CLI flags (`--external-notes`)—has not received any technical review. Key concerns remain unaddressed, including security risks (malicious helpers, input validation), edge cases (timeout behavior, signal handling), and performance overhead. The author defended the design as a pragmatic middle ground, but without broader discussion or alternative reviewers stepping in, the thread appears to have reached a quiet end. The unresolved question of whether external commands are an appropriate solution for Git's notes system may resurface if the use case gains traction elsewhere.
