This is a fixup patch for the git-gui bugfix series, addressing behavior of the blame subcommand with uncommitted changes. The patch corrects how git-gui handles blame operations when working with files that exist in the worktree but not in the repository.

The key change aligns git-gui's blame behavior with core Git's by:
1. Properly handling uncommitted worktree files by passing an empty head rev to the blame constructor when appropriate
2. Changing the error behavior for unknown files (now shows an error rather than displaying unannotated content)
3. Adding explicit worktree file checking when operating in non-bare repositories

The patch fixes a discrepancy where git-gui previously showed unannotated content for files removed from the worktree but present in HEAD, while core Git's blame would error in this case. The implementation now properly queries the worktree state and matches the CLI behavior exactly.

This will be squashed into patch 11/11 in the next version of the series, correcting an earlier incorrect claim that blame's worktree usage was unaffected. The change represents the final alignment of git-gui's behavior with core Git's blame command, completing the series' goal of consistent repository handling across all subcommands.
