This is a follow-up discussion in the git-gui bugfix series, specifically about patch 09/11 which handles path normalization in the browser subcommand. Johannes Sixt (the git-gui maintainer) questions whether the "./" prefix is actually necessary when handling the root directory case, noting that plain "." works fine in his Linux testing.

The original patch from Mark Levedahl modified the `normalize_relpath` function to return "./" when the path elements list is empty (which happens at the root directory), arguing this maintains consistency with command-line behavior and works cross-platform via Git for Windows' POSIX path handling. Johannes' reply suggests this might be over-engineering - if "." works reliably, the extra "./" prefix may not be needed.

This is a minor implementation detail in an otherwise approved series, but it's the kind of final polish that maintainers often catch before merging. The discussion doesn't indicate any disagreement about the fundamental approach - just a question about whether the specific solution is more complex than necessary. Given Johannes' role as maintainer, his observation will likely lead to a revised version unless Mark can demonstrate why "./" is truly required.
