This is a follow-up in the git-gui bugfix series, specifically addressing the path normalization behavior in the browser subcommand (patch 09/11). Mark Levedahl responds to Johannes Sixt's question about whether "./" is truly necessary versus just using "." for root directory paths. 

Mark acknowledges that his initial insistence on "./" may have been due to an interaction with other in-progress changes, and now finds that both forms work correctly. He plans to revert to using the simpler "." notation if it passes Windows testing, as it's more consistent with typical directory naming conventions that avoid adding unnecessary slashes. This resolves the last open question about the patch's implementation details, clearing the way for finalization of the series. The exchange demonstrates the kind of careful cross-platform validation that occurs during git-gui development, particularly when addressing edge cases in path handling.
