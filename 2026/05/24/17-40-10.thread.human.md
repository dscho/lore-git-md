Derrick Stolee continues his work optimizing sparse-index behavior, this time focusing on `git restore`. The two-part series addresses unnecessary index expansion when using `--staged` with pathspecs, a common operation that shouldn't require expanding the sparse index since it only deals with staged changes.

The first patch established test coverage, demonstrating the current behavior where the index expands unnecessarily. The newly submitted second patch implements the actual optimization in `builtin/checkout.c`, modifying `update_some()` to handle sparse directory entries at the tree level. It introduces careful distinctions between overlay and non-overlay modes, using `index_name_pos_sparse()` to prevent unwanted expansions while maintaining all existing functionality.

Stolee, as the primary driver of sparse-index optimizations, follows his characteristic test-first approach here. The implementation builds on his extensive prior work in this area and includes thorough test coverage of edge cases. While no reviews have been posted yet, the patch follows established patterns for sparse-index optimizations that have been well-received in the past. The changes should provide measurable performance improvements for users working with large repositories in sparse-checkout mode.
