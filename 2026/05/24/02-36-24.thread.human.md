Zakariyah Ali’s patch series to hide dotfiles by default in Git’s shell completion has reached its third iteration, aligning Git’s behavior with standard shell conventions. The series now covers all Git commands and has addressed earlier feedback on code duplication and consistency. However, Junio C Hamano’s latest review raises two key technical concerns that must be resolved before merging.

First, Junio finds the patch progression unclear: the second patch in v3 reworks logic already introduced in the first, creating a confusing back-and-forth rather than a clean refactor. He suggests a cleaner two-patch approach—first improving the AWK script’s readability without changing behavior, then implementing dotfile hiding on top of that. Second, he asks for clearer documentation of the design rationale, particularly how the patch decides which completion contexts should hide dotfiles and which should not. This was a point of confusion in earlier reviews, and Junio expects the cover letter to explain it explicitly.

The series remains conceptually approved, but these implementation details now block its progress. Zakariyah will need to restructure the patches and clarify the design before the maintainer can merge them. The thread is now focused on these technical adjustments rather than the original behavior change.
