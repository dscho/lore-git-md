This thread introduces a patch to make Git's shell completion behavior for certain commands (`git rm`, `git mv`, `git ls-files`) more consistent with standard shell conventions regarding dotfiles. Currently, Git's completion shows dotfiles (like `.gitignore`) even when the user hasn't started typing a dot, which differs from typical shell behavior.

The proposed change modifies the completion logic to hide dotfiles by default, only showing them when the user explicitly starts typing a dot (e.g., completing `git rm .` would show `.gitignore`). The implementation adds a `hide-dotfiles` parameter to an internal helper function and updates the AWK processing to handle this filtering. The patch includes thorough test coverage to verify both the new default behavior and the explicit dotfile completion case.

This appears to be a focused, well-tested quality-of-life improvement that aligns Git's completion behavior with user expectations from other shell tools, while maintaining backward compatibility for cases where dotfiles need to be explicitly completed.
