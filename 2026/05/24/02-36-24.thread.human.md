Zakariyah Ali’s patch series to align Git’s path completion with shell conventions by hiding dotfiles by default is now complete. The series, now at v3, started by modifying `git rm`, `git mv`, and `git ls-files` to hide dotfiles unless explicitly requested with a leading dot (e.g., `git rm .`). The just-arrived second patch extends this behavior to all path completion contexts by making dotfile hiding the default in the `__git_index_files` helper, removing the need for callers to manage a `hide-dotfiles` parameter.

Junio C Hamano, the maintainer, had previously raised concerns about code duplication and consistency, which Zakariyah addressed by consolidating the dotfile filtering logic in a single place and simplifying the API. The test suite now verifies that dotfiles are hidden by default but completable when explicitly requested, and the long-standing 2013 TODO comments about this inconsistency have been removed. The series is now clean, well-tested, and appears ready for merging.

The only loose end is whether the behavior change warrants explicit documentation, but this is a minor point given the clear alignment with shell conventions. The change preserves explicit access to dotfiles while making the default behavior more intuitive for users accustomed to standard shell completion.
