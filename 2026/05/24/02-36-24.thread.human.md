This thread discusses a patch series from Zakariyah Ali that changes how Git's shell completion handles dotfiles (like `.gitignore`) for commands including `git rm`, `git mv`, and `git ls-files`. The current behavior shows dotfiles by default, which differs from standard shell conventions. The proposed change would hide dotfiles unless explicitly requested with a leading dot, better matching typical shell behavior while still allowing access to dotfiles when needed.

The second version of the patch addresses maintainer feedback by expanding the rationale in the commit message and removing outdated TODO comments from 2013 that anticipated this change. The implementation adds a `hide-dotfiles` parameter and modifies the completion logic to filter dotfiles while preserving the ability to complete them when explicitly requested (e.g., by typing `git rm .`).

Junio Hamano, the Git maintainer, has now acknowledged that the conceptual direction makes sense, agreeing that aligning with shell conventions is reasonable. While he accepts the rationale, he notes that he lacks deep expertise in bash completion code to evaluate the implementation details, leaving that review to shell completion specialists. With this maintainer approval of the approach, the patch appears ready to proceed pending any final technical review from those more familiar with the completion subsystem. The change would resolve a long-standing inconsistency that was first identified nearly a decade ago.
