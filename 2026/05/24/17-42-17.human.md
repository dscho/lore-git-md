Performance optimization series targeting the commit-reach.c algorithms used by `git merge-base` and ahead/behind calculations.

This 3-patch series from Kristofer Karlsson replaces an O(n) queue scan in `paint_down_to_common()` and `ahead_behind()` with an O(1) counter-based approach. The key insight is that these functions currently check for stale commits by scanning the entire priority queue on each iteration, which becomes expensive when the queue is large.

Benchmarks show significant speedups (up to 2.5x) in monorepo scenarios with wide commit frontiers, while showing no regression for linear histories. The first patch deduplicates queue entries, while the next two convert the stale-checking logic to use a counter rather than scanning.

The changes are well-motivated with clear performance data showing both the wins (wide frontier cases) and confirming no regression in simpler cases. The implementation appears straightforward - adding a counter to replace the linear scan while maintaining the same semantics. This looks like a solid optimization that should provide real-world benefits for large repository operations without introducing complexity or risk.
