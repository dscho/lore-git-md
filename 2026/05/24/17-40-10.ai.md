# Performance optimization for sparse index in `git restore`

This is a two-patch series from Derrick Stolee that improves `git restore`'s integration with the sparse-index feature. The changes focus on avoiding unnecessary index expansion when using `--staged -- ..` pathspecs.

The first patch adds test coverage in t1092 to demonstrate the current behavior where the index expands unnecessarily when using `..` pathspecs with `git restore --staged`. The tests verify both correct behavior across different sparsity cases and the undesirable index expansion.

The second patch modifies the `git restore` implementation in builtin/checkout.c to avoid expanding the sparse index when processing `..` pathspecs. The key insight is that since `SKIP_WORKTREE` paths will be ignored anyway, we can operate directly on the tree entries rather than expanding to blob paths. The patch maintains all existing functionality while improving performance for sparse checkouts.

The changes touch the sparse-checkout/sparse-index subsystem, an area where Stolee has substantial expertise from his prior work on sparse-index optimizations. The patch series follows his typical pattern of first demonstrating the issue with tests before providing the optimization.
