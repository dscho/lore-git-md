This is a performance optimization patch for `git fetch` that fixes a missed optimization opportunity in the connectivity check. The patch addresses a case where `check_connected()` could skip verifying objects that are already known to be in a self-contained pack, but wasn't being given the transport information needed to do so.

The author, Kristofer Karlsson from Spotify, found this while working on improving fetch times in a large monorepo (2.4M commits, 374K files,  The key insight is that while `clone` operations were already using this optimization, `fetch` operations weren't passing the transport through to the connectivity checker. The fix is straightforward - just thread the transport parameter through one additional function call.

The performance impact is significant: on their test repository, the connectivity check time drops from 22s to 5s when fetching 200 new commits, with total fetch time improving from 36s to 14s. The remaining 5s is spent checking refs not contained in the new pack.

The change is minimal (just 3 lines modified) and low-risk since it's enabling an optimization path that already existed in the codebase. The patch appears well-motivated and clearly explains both the problem and solution. This seems like a straightforward improvement that should benefit any repository doing fetches with self-contained packs.
