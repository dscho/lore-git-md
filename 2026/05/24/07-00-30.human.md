This is the final patch in a git-gui bugfix series that improves repository and worktree detection. The patch adds two explicit subcommands to control startup behavior:

1. `gui` - Runs the GUI only if repository/worktree succeeds, failing with an error message rather than falling back to the repository picker
2. `pick` - Forces the repository picker to run first before starting the GUI

The changes maintain backward compatibility while giving users more control over when the repository picker appears. Johannes Sixt (the git-gui maintainer) has reviewed the patch and given his approval, noting that the implementation looks good. This was the last outstanding issue in the series, which has now addressed all feedback and is ready for merging.

The series as a whole fixes long-standing edge cases in git-gui's handling of bare repos, missing worktrees, and .git directory launches. This final patch completes the architectural shift to align git-gui's behavior with core Git's conventions while providing more predictable startup behavior.
