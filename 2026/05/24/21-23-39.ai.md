Bugfix for `git subtree split` command in contrib/subtree.

This patch addresses a specific edge case where `git subtree split` would fail with "fatal: cache for <hash> already exists!" when processing merge commits that make the same commit reachable through multiple paths in the commit graph. The issue occurs in the script's internal mapping cache when it encounters the same (oldrev -> newrev) pair multiple times.

The fix makes the cache_set() function idempotent by first checking if an existing cache entry matches the new mapping being added. If they match, it silently continues; if they conflict, it still raises the error. The change is small (7 lines added, 1 removed) and focused specifically on the described issue.

This appears to be a well-motivated fix for a real edge case that could affect users working with complex repository structures containing merge commits. The patch targets a clear problem with a straightforward solution and maintains the existing behavior for legitimate error cases. The commit message explains both the failure scenario and solution approach clearly.
