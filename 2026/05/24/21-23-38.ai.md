Bugfix for `git subtree split` command.

This is a patch addressing a specific error case in `git subtree split` where the command would fail with "fatal: cache for <hash> already exists!" when processing merge commits that make the same commit reachable via multiple paths in the DAG. The error occurs because the command's internal caching mechanism wasn't handling duplicate path cases properly.

The patch modifies the `contrib/subtree/git-subtree.sh` script to prune these duplicate paths before attempting to cache commits. The change is relatively small (7 lines added, 1 removed) and appears focused on the specific issue described. The commit message clearly explains both the problem scenario and the solution approach.

This looks like a straightforward fix for a real edge case that could affect users managing complex repository structures with multiple merge points. The patch targets a well-defined problem and provides a clear solution without introducing obvious new complexity.
