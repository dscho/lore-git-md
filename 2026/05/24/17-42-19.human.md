This is the second patch in a performance optimization series for commit-reach.c algorithms. It follows up on the preparatory changes from patch 1/3 by implementing the core optimization - replacing an O(n) queue scan with an O(1) counter in `paint_down_to_common()`.

The change introduces a `nonstale_count` that tracks how many non-STALE commits are in the priority queue, eliminating the need for the previous linear scan. The counter is maintained through:
1. Incrementing in `maybe_enqueue()` when adding a new non-STALE commit
2. Decrementing when dequeuing a non-STALE commit
3. Decrementing via `mark_stale()` when a queued commit becomes STALE

The patch shows careful attention to edge cases, like handling the STALE flag transition while a commit is still in the queue. The optimization is particularly impactful for wide commit graphs where the queue grows large, as shown in the cover letter's benchmarks (2.5x speedup on a 2.4M commit monorepo). The next patch will apply this same optimization to `ahead_behind()`.

The implementation looks clean and well-motivated, with clear performance wins demonstrated for the target case. The changes are focused on the commit-reach algorithms without introducing broader architectural changes.
