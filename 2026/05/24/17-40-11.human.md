# Test coverage for sparse-index behavior in `git restore`

This is the first patch in a two-part series from Derrick Stolee that establishes test coverage for `git restore`'s interaction with the sparse index feature. The tests demonstrate current behavior where `git restore --staged` unnecessarily expands the sparse index when using certain pathspecs.

The patch adds five new test cases to t1092-sparse-checkout-compatibility.sh that verify:
1. Basic `restore --staged` behavior within the sparse checkout definition
2. Behavior when restoring staged changes outside the sparse definition
3. Wildcard pathspec handling
4. Current sparse index expansion behavior with simple `restore --staged`
5. Current sparse index expansion behavior with `--source --staged`

The tests follow Stolee's typical thorough approach to sparse-index testing, carefully comparing behavior between full and sparse checkouts. The commit message notes that while the current expansion behavior is "somewhat natural" for pathspecs like `.`, it's actually avoidable since `SKIP_WORKTREE` paths don't need processing. This sets up the optimization that will come in patch 2/2.

As the first part of a performance optimization series, this patch does exactly what it should - it establishes the current behavior as a baseline before making changes. The test coverage looks comprehensive, covering both the expected correct behavior and the suboptimal index expansion that the series aims to fix.
