# Performance optimization for sparse index in `git restore`

This is the second patch in Derrick Stolee's two-part series optimizing `git restore`'s behavior with sparse indexes. The patch implements the actual optimization that avoids unnecessary index expansion when using `--staged -- ..` pathspecs, building on the test coverage added in the first patch.

The key changes modify `update_some()` in builtin/checkout.c to handle sparse directory entries at the tree level rather than expanding the index. The logic distinguishes between overlay mode (e.g., `checkout <tree> -- .`) and non-overlay mode (e.g., `restore --staged`), with different handling for each case. The patch also switches from `index_name_pos()` to `index_name_pos_sparse()` for individual file lookups to prevent unwanted expansions.

The implementation demonstrates Stolee's characteristic attention to sparse-index edge cases, with careful handling of directory OID comparisons and mode checks. The accompanying test updates verify that the sparse index remains unexpanded in the targeted scenarios, matching the behavior demonstrated in the first patch's tests.

This change continues Stolee's ongoing work optimizing command behavior for sparse checkouts, following the established pattern of first demonstrating the issue with tests before implementing the solution. The patch touches core checkout/restore functionality but maintains all existing behavior while improving performance for sparse checkouts.
