# Performance optimization for sparse index in `git restore`

This is the second patch in Derrick Stolee's two-part series optimizing `git restore`'s behavior with sparse indexes. The patch implements the actual performance improvement after the first patch established test coverage.

The key change modifies `update_some()` in builtin/checkout.c to handle sparse directory entries at the tree level rather than expanding the index. It introduces three cases for directory handling: skipping unchanged directories, updating directory OIDs in non-overlay mode (like `--staged`), and falling back to recursive descent in overlay mode. The patch also switches to `index_name_pos_sparse()` for file lookups to avoid unnecessary index expansion.

The implementation appears carefully considered, maintaining all existing functionality while improving performance. Stolee's expertise in sparse-index optimizations shows in the thorough handling of edge cases and the clear separation of overlay vs non-overlay modes. The accompanying test updates confirm the index no longer expands unnecessarily during `restore --staged` operations.

This continues Stolee's pattern of methodical sparse-index improvements, building on his prior work in this area. The changes are focused and well-contained, touching only the necessary parts of checkout.c while demonstrating measurable benefits through the test suite.
