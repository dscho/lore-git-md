Bugfix for `git subtree split` command in contrib/subtree.

This patch addresses a specific edge case where `git subtree split` fails with a "cache already exists" error when processing merge commits that make the same commit reachable through multiple paths in the commit graph. The issue occurs in the script's internal caching mechanism, which wasn't properly handling duplicate path cases.

The fix makes the cache_set() function idempotent - it now checks if an existing cache entry contains the same mapping before erroring out. The change is small (7 lines added, 1 removed) and well-contained to the caching logic in git-subtree.sh. The commit message clearly explains both the failure scenario and solution.

This appears to be a straightforward fix for a real edge case that could affect users working with complex repository structures containing merge commits. The patch targets a specific problem without introducing new complexity, and the implementation looks clean. As a contrib/ script rather than core Git, this change is lower-risk but still provides a concrete improvement for subtree users.
