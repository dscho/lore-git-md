This is a follow-up discussion on a shell completion patch that modifies dotfile handling in path completion for `git rm`, `git mv`, and `git ls-files`. The original patch aimed to align Git's completion behavior with shell conventions by hiding dotfiles unless explicitly requested with a leading dot.

Junio C Hamano raises two concerns about the proposed change:
1. The commit message's wording ("path with ..") could be clearer if written as "path with '.'"
2. He questions the fundamental premise of hiding dotfiles, suggesting that tracked files (whether dotfiles or not) should be treated equally in completion

The maintainer also notes the patch description appears misplaced - the detailed explanation belongs in the commit message proper, not below the three-dash line where it currently sits.

This appears to be the first substantive review of the patch, indicating the change may need stronger justification or reconsideration of its design approach. The discussion is just beginning, with Junio signaling potential disagreement with the patch's core premise about dotfile treatment.
