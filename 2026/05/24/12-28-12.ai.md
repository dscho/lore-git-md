Performance optimization patch for `git fetch` connectivity checks.

Kristofer Karlsson from Spotify identifies and fixes a missed optimization opportunity in the post-fetch connectivity check. When fetching with a transport that provides self-contained packs (like index-pack` does), `check_connected()` can skip verifying objects that are already in the new pack by using `find_pack_entry_one()`. However, the transport parameter wasn't being passed through `store_updated_refs()`, making this optimization dead code for normal fetches.

The patch threads the transport parameter through the call chain, enabling the optimization. Benchmark results show significant improvement - on a large repository (2.4M commits, 374K files, 10.9K refs), the connectivity check time drops from 22s to 5s when fetching 200 new commits, with total fetch time improving from 36s to 14s. The remaining 5s is spent verifying refs not contained in the new pack.

The change is minimal (3 lines added, 1 modified) and well-motivated by profiling data. It follows the pattern already established in `builtin/clone.c` and brings fetch behavior in line with clone's more optimized path. The commit message clearly explains both the problem and solution, including concrete performance numbers from a real-world large repository scenario.
