This is a performance optimization patch series from Derrick Stolee, focused on better integrating the `git restore` command with Git's sparse index feature. The sparse index is part of the ongoing sparse-checkout/sparse-index effort to improve performance in large repositories where only a subset of files is checked out.

The series addresses a case where `git restore --staged -- ..` unnecessarily expands the sparse index in memory when operating on pathspecs, even though it could intelligently handle trees directly. The first patch adds test coverage to demonstrate the current behavior, while the second implements the optimization to avoid index expansion while maintaining the same end-user behavior.

The changes touch `builtin/checkout.c` (where `git restore` is implemented) and add tests to the sparse-checkout compatibility test suite. The optimization appears well-motivated and follows the established pattern for sparse index integrations - the commit message clearly explains the performance benefit while noting the functional behavior remains unchanged.

This is a focused, technical improvement from a domain expert (Stolee being one of the primary drivers of the sparse-index work) that should provide measurable speedups for users of sparse-checkout in large repositories. The patch structure follows Git conventions with a test-first approach and clean separation of concerns.
