This is the third and final patch in Kristofer Karlsson's performance optimization series for commit-reach.c algorithms. The series targets the graph traversal code used by `git merge-base` and ahead-behind calculations, specifically replacing O(n) queue scans with O(1) counter-based tracking.

This patch applies the same nonstale_count optimization from the previous commit (which optimized paint_down_to_common()) to the ahead_behind() function. The key changes are:
- Removes queue_has_nonstale() entirely since it's no longer needed
- Modifies insert_no_dup() to maintain a nonstale_count when adding commits
- Updates ahead_behind() to use the counter instead of scanning the queue
- Uses PARENT2 flag (already present for deduplication) as the queued_flag for mark_stale()

The implementation maintains the same behavior while improving performance, particularly for repositories with wide commit graphs. This completes the series' goal of eliminating O(n) queue scans from these algorithms. The cover letter showed 2.5x speedups in a 2.4M commit monorepo benchmark, with no regression for simpler cases. The changes are focused and well-contained to commit-reach.c, building logically on the preparatory work in the first two patches.
