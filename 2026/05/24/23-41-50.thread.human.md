The thread investigates why Git appears to maintain a connection between two different commits (dda8db1 and fda7769) that were sequentially tagged as 1.20.0. Junio C Hamano suspected this might involve Git's legacy grafts mechanism, and Jens Tröger has now confirmed this by sharing `git log` output showing the rewritten commit marked as "(grafted, HEAD)". This suggests the behavior stems from either explicit use of the grafts file or an interaction with shallow clone operations, which Jens notes was performed with `--depth=1`.

The discussion has narrowed to understanding how grafts - a largely deprecated feature replaced by replace-refs - could produce this effect in shallow clones. Junio's initial hypothesis appears validated by the log evidence, though the exact mechanism by which the shallow clone might create or expose this graft relationship remains to be explained. The thread has moved from general speculation about Git's object model to focused analysis of how grafts interact with limited-history repositories. Practical implications for users who rewrite tags after publication remain an open consideration.
