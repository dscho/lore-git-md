# Test coverage for sparse-index behavior in `git restore`

This is the first patch in a two-part series from Derrick Stolee that establishes test coverage for `git restore` behavior with sparse indexes. The tests demonstrate the current suboptimal behavior where `git restore --staged` unnecessarily expands the sparse index when processing pathspecs.

The patch adds five new test cases to t1092-sparse-checkout-compatibility.sh that verify:
1. Basic `restore --staged` behavior within the sparse definition
2. Behavior when restoring staged changes outside the sparse definition
3. Wildcard pathspec handling
4. Current sparse-index expansion behavior with simple `restore --staged`
5. Current sparse-index expansion behavior with `--source --staged`

The tests follow Stolee's typical thorough approach to sparse-index testing, carefully comparing behavior between full checkouts, sparse checkouts with full indexes, and sparse checkouts with sparse indexes. The test names explicitly call out where the sparse index currently expands, setting up the optimization that will follow in patch 2.

This test-first approach is characteristic of Stolee's work on the sparse-index subsystem, where he consistently establishes behavioral baselines before making changes. The tests cover both the happy path (where optimization should be possible) and edge cases that need to remain correct.
