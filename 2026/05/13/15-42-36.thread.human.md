A short documentation patch from an unnamed contributor clarifies how `--word-diff` actually works in Git: it is a two-stage process where Git first produces a line-level diff and then performs word-level comparison only within changed lines. This means that identical words on lines that Git considers structurally different can still appear as word changes -- a behavior that has confused users. The patch adds a five-line note to the `--word-diff` man page entry explaining this relationship. The commit message is well-written and cites Vincent Lefevre and Johannes Sixt as the contributors who surfaced the confusion. This is a small, uncontroversial fix that addresses a real documentation blind spot and should land without fuss.
