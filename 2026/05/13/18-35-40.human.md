This is a follow-up from Derrick Stolee, responding to Taylor Blau's review question on patch 07/12 of the `--path-walk` + `--filter` series.

The exchange is brief and cordial. Blau asked whether the new `blob:limit=<size>` filter implementation should avoid on-demand fetches in partial clones by temporarily disabling `fetch_if_missing` or using `OBJECT_INFO_SKIP_FETCH_OBJECT`. Stolee answers that they *could* do this, but it is not necessarily the right choice: a user running `git pack-objects --filter=blob:<size>` from a blobless partial clone is already asking for something inefficient, and the current behavior is technically correct. For `git backfill` specifically, Stolee notes that a size-limit filter does not make sense because the client cannot know blob sizes in advance of downloading, and the server protocol does not support size-filtered requests anyway.

This is a routine back-and-forth between co-authors, not a disagreement. Blau raised a legitimate technical point, Stolee gave a reasoned response, and nothing here changes the patch design -- the behavior stands as-is, with no follow-up action or open question. The thread on this patch is effectively resolved.
