This is a reply from Junio C Hamano, the maintainer, to the v8 cover letter of Harald Nordgren's series adding `git branch --prune-merged`. In this email Junio gives his first response since the v8 redesign was submitted -- and it is a split decision: he strongly approves of the core safety model redesign, but flags one design choice as a bad idea.

Junio begins by quoting the new description of `--prune-merged` from the cover letter (the upstream-reachability safety model) and says simply "that matches my understanding of the original motivation of this topic a lot better than the previous round." This is an unambiguous endorsement of the v8 redesign, and with Junio being the maintainer, this essentially resolves the design question that has been the sticking point since v7. The core feature is on solid ground.

However, Junio then pushes back on the `--force` behavior for `--prune-merged`. The current patch allows `--force` to skip the reachability check entirely and delete every branch in the candidate set, effectively giving `git branch -D --prune-merged <remote>` the same effect as `git branch -D $(git branch --forked <remote>)`. Junio argues that this is a bad idea: the command is called `prune-merged`, so mergedness should be what drives deletion regardless of `--force`. He suggests that if someone wants the nuclear option, they should have to explicitly use the shell combination above, not get it by confusing `--prune-merged` with `--prune-forked`. This is a substantive design objection, but it is narrow and mechanically fixable -- it affects only the `--force` interaction in patch 3, not the overall architecture.

The review is substantive: Junio engages with what the code does, identifies a specific design problem, and gives a clear technical rationale. He does not report testing.

The takeaway for someone following this thread is: the series is essentially accepted in principle, with one concrete issue to resolve in the next iteration. Harald needs to remove or rework the `--force` override on `--prune-merged` so that the mergedness check is not bypassed. That is a small change to patch 3, and v9 should be straightforward. No other concerns were raised about any of the five patches.
