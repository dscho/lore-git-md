This is patch 5 of 5 in Harald Nordgren's v9 series adding `git branch --prune-merged`. It adds the `--all-remotes` convenience flag that, when combined with either `--forked` or `--prune-merged`, acts on every configured remote in addition to any explicit `<remote>` arguments given.

This is the capstone of the series, tying together the `--forked` listing and `--prune-merged` deletion modes with a convenience flag that saves the user from having to name every remote. The implementation is straightforward plumbing: a new `collect_remote_name()` callback iterates over all configured remotes via `for_each_remote()`, and the resulting list is merged into the existing remote-names collection before the candidate loop runs. The internal `collect_forked_set()`, `list_forked_branches()`, and `prune_merged_branches()` functions all gain an `all_remotes` parameter. On its own, `--all-remotes` errors out with a clear message saying it requires one of the two parent flags.

The patch looks clean and well-scoped. The diff is 81 lines across documentation, C code, and tests. The three new tests confirm that `--forked --all-remotes` covers every configured remote, that an explicit (wrong) remote name still produces an error even with `--all-remotes`, and that `--all-remotes` on its own is rejected. The `--prune-merged --all-remotes` test is more elaborate: it sets up a second remote, creates branches tracking it, and verifies they are all cleaned up.

This is the kind of finishing touch that makes the feature feel complete -- the series now offers a clean workflow where you can run `git branch --prune-merged --all-remotes` and clean up everything at once.
