This is a bugfix / design correction to a patch in an in-flight series. Stolee replies to Blau's inline question about why `/tagged-trees` pseudo-path logic in patch 10/12 ("path-walk: support tree:0 filter") was applied to directly-listed trees. His answer is that the confusion is well-founded: the current handling is actually **buggy**, not just unusual.

Stolee reports that the path-walk API has "major flaws" in how it treats tagged trees. The problem was not caught by the existing test setup because the tagged trees in the test data happened to also be root trees from commits, so the test passed despite the bug. He says the fix will require a **setup patch** that updates the test harness (and verifies the rest of the series is unaffected) and that the `tree:0` patch itself will need a "substantial" rewrite in v4.

This is a substantive self-identified correctness issue that escaped both co-authors' review and the test suite. It means patch 10/12 is not ready as-is and will need significant rework. The series is not as close to the finish line as Blau's sign-off suggested.
