This is a follow-up from Harald Nordgren sent as a new thread root (not a reply-in-thread to the `--prune-merged` v8 review, but a separate email) proposing a new concept: a `fetch.pruneLocalBranches` config option. The email is a single-paragraph response to something Junio said in the parent review, but it is not itself a patch -- it is a brief conceptual proposal.

Harald explains the origin of the feature: he originally intended a more general "prune local branches" mechanism, which then evolved into the `--prune-merged` design. He acknowledges Junio's point that the `--force` override was a foot-gun, saying he already lost work to it once. He agrees to remove the `--force` functionality from `--prune-merged`.

The key development is that Harald reveals a separate, latent concept that was not part of the `--prune-merged` series but is now being floated independently: a `fetch.pruneLocalBranches` config knob that, when enabled, would automatically delete local branches during `git fetch` when their upstream counterpart has been removed. This is a significant expansion of scope -- it moves from an explicit `git branch` command to automatic behavior triggered by fetch, which is a fundamentally different safety proposition.

The email is a proposal rather than a patch, so there is no code to review. It does not specify details such as what safety checks would apply, how it would interact with `fetch.prune`, or whether per-branch opt-out would be supported. It is a preliminary idea being floated for discussion.

For someone following the thread: the `--prune-merged` series is still the main action, and Harald's agreement to fix the `--force` issue is good news for getting that series merged. This separate `fetch.pruneLocalBranches` idea is a new and separate topic; it may or may not end up replacing or supplementing the `--prune-merged` series, but for now it is just a concept being aired.
