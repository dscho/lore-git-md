This is patch 06/13 of Derrick Stolee's v4 series integrating `--path-walk` with `--filter` options. It wires up the new `path_walk_filter_compatible()` API (introduced in patch 05/13) into `builtin/backfill.c`, so that `git backfill` can distinguish between filters that are compatible with path-walk and filters that are not.

The patch is straightforward: the existing `reject_unsupported_rev_list_options()` function in `cmd_backfill()` used to reject *any* `--filter` option with a hard `die()`. Now it calls `path_walk_filter_compatible()` instead, which will accept `blob:none` (already wired in patch 05/13) and later, as the series progresses, the other filters that get ported to the path-walk API. The error message changes from the specific `"'--filter' cannot be used with 'git backfill'"` to the more generic `"cannot backfill with these filter options"`, which will become more informative as the set of supported filters grows.

Two test cases are added to `t5620-backfill.sh`: one rejecting `--filter=tree:1` and one rejecting `--filter=blob:limit=10m`. These are filters that cannot be applied by path-walk in the backfill context, and the tests verify the new error message.

This is a small, mechanical patch -- essentially plumbing that makes `git backfill` participate in the same compatibility-checking framework the rest of the series is building. It is clean and well-scoped. No behavioral change for users yet, since `blob:none` is the only currently supported filter; the real effect will be seen as more filters are ported later in the series.
