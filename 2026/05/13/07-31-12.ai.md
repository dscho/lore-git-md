This is a v3 cover letter for a two-patch bugfix series from Patrick Steinhardt, targeting the maintenance subsystem. The series addresses two distinct issues: stale lockfiles when running `git maintenance run --detach`, and a regression where `gc.auto=0` no longer suppressed automatic maintenance after the transition from `git gc` to the newer `git maintenance` machinery.

In this iteration, the first patch has been substantially reworked on the lockfile issue. Patrick has adopted the alternative approach that Taylor Blau proposed off-list and defended on-list: rather than handling lockfile ownership at the call site, the `daemonize()` function now automatically transfers ownership of all open tempfiles and lockfiles to the child process, so that the parent's death does not release them. This is a cleaner design that matches the project's preferred pattern, and Taylor has offered Co-authored-by and Signed-off-by if the approach is used. The second patch is unchanged from v2 and appears fully settled.

This is a well-run series -- each iteration has absorbed feedback cleanly, the design disagreement is resolved, and the author is signaling readiness for merge by sending a v3 cover letter rather than re-soliciting review. The `gc.auto` fix in particular fixes a user-reported regression where maintenance became effectively impossible to disable through configuration after the subsystem overhaul. Anyone following the maintenance subsystem should take note, as both patches are likely destined for `next` and eventually `master`.
