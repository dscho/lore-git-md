This is patch 3/5 in Harald Nordgren's v9 series adding `git branch --prune-merged`, the core implementation patch. The series was substantively accepted in v8; the only remaining objection (from Junio C Hamano) was that `--force` should not bypass the mergedness check. That objection is fully addressed here -- `--force` is gone from this subcommand entirely.

The patch adds about 140 lines of C implementing `prune_merged_branches()` in `builtin/branch.c`, plus documentation and six tests. The logic is straightforward: collect all local branches that are "forked" from a given remote (i.e., whose configured upstream is a tracking branch of that remote), then delete only those whose tip is reachable from their upstream tracking ref. Branches whose upstream no longer resolves locally are silently skipped. The currently-checked-out branch in any worktree is always preserved, as is the local branch that shares a name with the remote's default branch. The error message for skipped-but-not-merged branches now says "delete it with `git branch -D` if you are sure" rather than the old "re-run with --force" language.

The implementation is clean and follows the established pattern of reusing `delete_branches()` with the refactored parameters from patch 2. The six new tests cover the happy path, the "not merged" case (including the plural error message), the missing-upstream case, the checked-out branch case, the default-branch protection, and the subtlety that protection only applies to the branch with the same name as the default, not to a differently-named branch tracking the same remote ref.

This patch is the meat of the series, and it looks well-crafted. The safety model is conservative by design -- silently skipping branches with unresolvable upstreams rather than failing, and the default-branch-by-name heuristic is a deliberate choice that matches Junio's earlier approval. There does not appear to be any remaining controversy.
