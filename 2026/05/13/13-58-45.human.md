This is a small user-experience improvement for the `git config` command. When a user accidentally types `git config pull.rebase=false` (using an equals sign as if it were an INI-file or `--flag=value` assignment), they currently get a generic "invalid key" error with no guidance on what to do instead. This patch adds a one-line hint in the standard `(did you mean ...?)` format that suggests the correct form, `git config set pull.rebase false`.

The change is tiny -- four lines in `config.c` -- and is well-scoped: it only triggers the hint when the offending character is `=`, leaving other invalid-key errors unchanged. The code correctly only matches the first `=` character in the key, and points the user at the part before and after it. The commit message explains the motivation clearly and gives a concrete example.

This is a straightforward, uncontroversial quality-of-life improvement with no downside (the hint is purely additive and only fires on an already-fatal error path). It should be quick to review and easy to merge.
