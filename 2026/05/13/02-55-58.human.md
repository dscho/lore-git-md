This is a patch series (v3, 2/2) from Chen Linxuan, adding `includeIf worktree:` and `includeIf worktree/i:` conditions to Git's config mechanism, which let users include config files based on a worktree's checkout path rather than its `.git` directory location.

**Why this matters.** The existing `includeIf gitdir:` condition matches against the `.git` directory, which is problematic for worktrees because linked worktrees all store their gitdirs under the main repository's `.git/worktrees/` -- meaning they all match the same pattern. This patch gives users a way to match on the working directory instead, enabling path-based config selection in multi-worktree setups.

**The author just responded to Phillip Wood's motivation question**, which has been the sticking point holding up this series. Junio had already weighed in, calling the question "excellent" and raising the bar for v4 -- requiring the author to articulate concrete use cases and document the trade-offs between the new `includeIf worktree:` approach and the existing `extensions.worktreeConfig` mechanism. Chen's reply is brief but direct: they work on the Linux kernel both as an employee and as an individual, and want to automatically use their company email when working under a specific directory. That is a clear, concrete use case -- matching on checkout path rather than manually running `git config --worktree` in each worktree.

**The patch itself** looks well-structured. Patch 1 refactors `include_by_gitdir()` into a generic `include_by_path()` helper; patch 2 wires it up with `worktree` and `worktree/i` conditions, supporting glob patterns and `~` expansion. Patrick Steinhardt gave it a substantive review, calling patch 1 a "good preparatory step" and patch 2 "sensible," with three minor action items (deduplicate documentation for pattern-matching rules, add two tests for edge cases). Those are straightforward and expected in the next iteration.
