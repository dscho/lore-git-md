This is a tidy refactoring patch from René Scharfe, the project's go-to person for code hygiene improvements. It introduces a new helper function `strbuf_add_oid_hex()` that appends the hex representation of an object ID directly into a strbuf, and then applies a Coccinelle semantic patch to convert all existing call sites that were doing the same thing via the slower `strbuf_addstr(sb, oid_to_hex(...))` pattern.

The motivation is straightforward and well-explained: the new function is thread-safe (the old `oid_to_hex()` writes to a static buffer, which is not safe in threaded contexts) and marginally faster because it avoids an extra string-length calculation in `strbuf_addstr()` and the intermediate copy from that static buffer. René includes benchmark numbers for `git log --format=%H` showing a 1% speedup -- tiny, but consistent.

The patch touches 13 files across a broad range of subsystems (bisect, cat-file, refs, sequencer, pretty, fsck, shallow, transport-helper, etc.), all in mechanical, trustable ways. The Coccinelle rule catches the pattern and will prevent reintroductions. This is exactly the kind of patch that René is known for: small, clearly scoped, well-tested-in-principle, and touching many files in a low-risk way.

For a human reader tracking Git development, this is a low-priority but good-to-know-about change. It makes the codebase slightly cleaner and slightly faster without any user-visible effect. It is uncontroversial and likely to merge quickly. The only point to note is that the new function is deliberately kept lightweight -- it does not handle the abbreviated form (use `strbuf_add_unique_abbrev()` for that), just the full hex OID.
