This is a follow-up email from Jeff King (Peff) to his own earlier message in the thread about the `strbuf_add_uint()` implementation. It is a small correction, not a review that changes anything.

Peff points out a bug in the alternative implementation he sketched in his previous email: the line `p = sb->buf + digits` should be `p = sb->buf + sb->len + digits`. Without `sb->len`, the code would write digits starting from the wrong position when the strbuf is not empty. He adds a self-deprecating note that this off-by-one was in the part he wrote by hand (rather than the ChatGPT-generated `decimal_length_u64()` helper) — the kind of low-key humor that is typical of Peff's emails.

He observes that the bug did not matter for the `cat-file` benchmark in patch 2 (which formats into an empty buffer where `sb->len` is 0) but would matter for the `ls-files` padding case in patch 3.

That is the entire content of this email. It is a minor errata, not a substantive change to the thread's trajectory. The series remains ready for pickup with no outstanding issues. If a maintainer were to pick up Peff's alternative implementation (which nobody is asking for), they would need to fix this arithmetic; but since the whole point of the thread is that René's on-stack-buffer version is the chosen approach, this email is of essentially no consequence.
