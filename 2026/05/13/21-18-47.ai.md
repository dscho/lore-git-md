This is patch 05/13 in the `--path-walk`/`--filter` integration series, and it wires up the simplest and most practically important filter -- `blob:none` -- into the path-walk API. This is the first filter integration patch of the series and represents the point at which the series starts producing user-visible improvements: `blob:none` is one of the most common filter options for large-repository pack operations.

The core mechanism is a new static function `prepare_filters()` in `path-walk.c`. For `blob:none`, it sets `info->blobs = 0` (instructing the walk to skip all blob objects) and releases the filter from `revs` so that `prepare_revision_walk()` does not reject the configuration. The function doubles as the backend for a new public API function `path_walk_filter_compatible()`, which lets command code check compatibility without actually mutating state. This function replaces the old blanket-rejection check in `builtin/pack-objects.c`: instead of rejecting any filter, it now accepts `blob:none` and rejects everything else (for now). The documentation in `git-pack-objects.adoc` is updated to list `blob:none` as the sole supported filter, removing `--filter` from the list of incompatible options.

On the test side, the patch makes several changes. The test helper `test-path-walk` gains `--filter=<spec>` support (via `OPT_PARSE_LIST_OBJECTS_FILTER`), and its revision initialization is switched from `REV_INFO_INIT` with manual repo assignment to `repo_init_revisions()`, which is needed for proper filter strbuf setup. Two new tests in `t6601-path-walk.sh` exercise `blob:none` with `--all` and with a single branch, checking that no blob objects appear in the output. The three `GIT_TEST_PACK_PATH_WALK=0` workarounds that were added in patch 01/13 to `t5620-backfill.sh` are reverted, since backfill now works correctly under `--path-walk` with `blob:none`.

The performance data -- 16% smaller packfiles for blobless packs in the Git repo itself, at the cost of about 70% more CPU time -- is included and aligns with the overall trade-off the series has been showing: path-walk produces more compressible packs by arranging objects by filename, but the two-pass delta compression costs time.

This is a well-structured, scoped patch. It adds a single filter type, provides the extensibility pattern (`prepare_filters()` with a switch statement that other patches in the series will extend), and updates both the command code and the test infrastructure in one clean step. The test workaround reverts in `t5620` are a nice touch that show the integration is actually working. The one remaining concern from earlier versions -- whether the `GIT_TEST_PACK_PATH_WALK` CI flag placement is right -- is not addressed here, but that is an operations question, not a patch correctness question.
