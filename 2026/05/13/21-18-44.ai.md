This is a small preparatory refactoring patch, part 2 of 13 in Derrick Stolee and Taylor Blau's v4 series to make `--path-walk` work with `--filter` options.

The patch does one simple thing: when `--path-walk` is enabled in `builtin/pack-objects.c`, the code now explicitly passes `--objects` to the revision machinery. The `--path-walk` API had been relying on `--objects` being implicitly set (and in fact the old code had a stale comment about "removing" some options that were never actually removed), but upcoming patches that wire filters into `path-walk.c` will cause the revision machinery to emit a fatal error unless `--objects` is present. This patch preemptively adds it. It also keeps `--boundary`, which was already being passed.

The diff is five lines changed in one file. No tests are added or updated because there is no observable behavior change yet -- the fix is purely about making the revision machinery happy before the filter logic lands later in the series. The patch is mechanical and clearly motivated; the commit message explains both the "why now" (the fatal error that will otherwise trigger) and the "why not before" (the old comment was misleading). Nothing controversial or surprising here.
