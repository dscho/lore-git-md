- Thread by Jeff King on sideband.c handling of ANSI SGR sequences. The sideband code in `handle_ansi_sequence()` parses SGR escape codes (e.g., `\e[31m`) in progress messages (e.g., from `git push`), but only accepts semicolons (`;`) as separators between numeric parameters. The ECMA-48 specification allows colons (`:`) as sub-parameter separators within a single numeric parameter, which are required for 256-color (`\e[38:5:NNm`) and true-color (`\e[38:2:R:G:Bm`) escape codes. Many terminals emit these colon-containing sequences, and Git's current parser leaves them as raw garbage in the output.

- Jeff King's patch (originally authored by Mantas Mikulėnas) makes a one-character change in `sideband.c` line 217: adding `src[i] != ':'` to the character-class check in the SGR parsing loop. No tests are included.
