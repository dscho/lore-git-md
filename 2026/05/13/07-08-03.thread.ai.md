- Thread by Jeff King on sideband.c handling of ANSI SGR sequences. The
  sideband code in handle_ansi_sequence() parses SGR escape codes like
  \e[31m in progress messages (e.g., from git push), but only accepts
  semicolons (;) as separators between numeric parameters, rejecting any
  sequence containing colons (:). The official ECMA-48 specification for
  SGR uses colons as sub-parameter separators within a single numeric
  parameter, which is needed for 256-color (\e[38:5:NNm) and true-color
  (\e[38:2:R:G:Bm) escape codes. Many real-world terminals emit these
  colon-containing sequences, and Git's current parser leaves them as raw
  garbage in the output.

- Jeff King's patch makes a one-character change in sideband.c line 217:
  adding src[i] != ':' to the character-class check in the SGR parsing
  loop. The commit message cites the upstream xterm source code to support
  the claim about the standard encoding. No tests are added, but the change
  is additive (accepting more input) and does not alter handling of
  previously accepted sequences.
