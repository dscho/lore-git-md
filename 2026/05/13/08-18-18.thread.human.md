This is a well-structured bug report from Alexander Sandström about a subtle issue on case-insensitive filesystems (macOS APFS/HFS+) affecting linked worktrees. On such filesystems, `git rev-parse HEAD` correctly resolves to a linked worktree's HEAD via the per-worktree ref at `.git/worktrees/<name>/HEAD`, but lowercase `head` falls through to general ref resolution, accidentally matching `.git/HEAD` -- which is the main worktree's HEAD, not the linked one's. The practical impact is that `git reset --soft head~1` in a linked worktree silently operates on the wrong commit, staging unexpected changes with no warning. The reporter is not a C programmer and is not submitting a patch, but offers two possible fixes: reject lowercase `head` with an error (matching Linux behavior where it already fails), or normalize it to `HEAD` and route through the per-worktree codepath. The bug only manifests with linked worktrees on case-insensitive filesystems -- two conditions that together are relatively uncommon, which may affect how seriously the project treats it.
