This is a cover letter for a two-patch series adding a `worktree` condition to Git's `includeIf` configuration mechanism. The series is now in its fourth iteration.

The `includeIf` directive in gitconfig already supports conditional inclusion based on the `.git` directory path (`gitdir:<pattern>`) and the current branch (`onbranch:<pattern>`). This series extends that with `worktree:<pattern>` and `worktree/i:<pattern>` (the case-insensitive variant) which match against the realpath of the current working tree's working directory using glob patterns. In multi-worktree setups where the `.git` directory of a linked worktree points into the main repository's `.git/worktrees/` area, this addresses the awkwardness of trying to use `gitdir` patterns to distinguish between worktrees based on their checkout path.

The series is small and well-documented with a clear motivation. The first patch is a preparatory refactoring that renames and generalizes the internal `include_by_gitdir()` function to `include_by_path()`, making room for a second condition that also operates by path matching. The second patch adds the actual `worktree`/`worktree/i` conditions plus the supporting documentation and test coverage.

The changes-in-v4 notes show Patrick Steinhardt and Junio C Hamano gave previous feedback that was incorporated: deduplication of the pattern documentation (referencing the `gitdir` syntax), a comparison of `worktree:` with `extensions.worktreeConfig` including a concrete use-case example, and several additional tests covering early config reading, the nongit scenario, and the case-insensitive variant. These are signs of a response to careful technical review.

The v3-to-v4 delta (documentation additions and edge-case tests) suggests this has gone through substantive iteration and is converging. On the surface this looks like a clean, incremental addition to the config system that solves a real pain point for multi-worktree users without touching any other subsystem. Worth a skim from anyone who maintains config-heavy workflows.
