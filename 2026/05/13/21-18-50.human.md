This is patch 08/13 of Derrick Stolee's `pack-objects --path-walk --filter` series.

The patch adds a `pl_sparse_trees` flag to the path-walk API's `path_walk_info` struct. When nonzero (as set by `git backfill --sparse` and the `--stdin-pl` test helper), the existing behavior is preserved: the sparse-checkout patterns prune both trees and blobs. When zero, trees are not pruned -- only blobs are filtered. This is the behavior needed for the upcoming `sparse:<oid>` filter support, which should restrict blobs while retaining all reachable trees for correct pack output.

The patch also fixes an important subtle bug in how the `SEEN` flag is assigned to tree entries. Previously, the flag was set immediately upon discovering an object, before checking whether its path matched the sparse patterns. If the same object appeared at multiple paths (e.g., sibling directories with identical contents), the first path encountered -- which might be outside the sparse cone -- would mark the object as SEEN, causing it to be skipped at its in-cone path as well. The fix moves the `SEEN` assignment to after the sparse-pattern and pathspec checks, so objects skipped at one path remain discoverable at another.

This is a clean, focused patch. The bug fix is real (though it presumably only matters in combination with sparse patterns), and the new flag is well-documented in the header. The test in `t6601-path-walk.sh` exercises `--no-pl-sparse-trees` and shows that trees outside the sparse cone (like `right/`) are still reported while their blobs are not, which is exactly the intended behavior for the downstream `sparse:oid` use case. The commit message explains the motivation clearly. No apparent issues.
