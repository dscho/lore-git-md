This is a test-only preparatory patch in a 13-patch series (patch 10/13) that Derrick Stolee is leading on path-walk/filter integration. It revises the test setup in `t6601-path-walk.sh` to create tagged tree objects that are truly unreachable from any commit, rather than accidentally reachable through the repo's commit history. The fix matters because Stolee discovered while working on the tree:0 filter bug (patches 11/13 and earlier) that the test suite had been masking a correctness issue: tagged trees that should have been tested in isolation were being emitted anyway because they happened to also be reachable from commits. The commit message is honest about this -- Stolee calls it out directly rather than burying it.

The mechanical change replaces the old approach (commit, tag a tree from the commit, abandon the commit) with explicit object construction using `git hash-object`, `git mktree`, and `git tag`. The new trees point to blobs created with distinct content to guarantee they are not reachable through the commit history. The diff also drops the `git commit --amend -m "first"` in favor of a clean `git commit -m "first"`, which is a nice side-fix: no longer amending the abandoned commit.

The patch is small and focused -- 11 insertions, 13 deletions, purely test infrastructure. No behavior change for any existing test case, which Stolee notes explicitly. This is a sign of a conscientious patch author catching a latent test gap before it could hide the real bug in the following patch.

For a busy reader: this is worth knowing about because the tree:0 bug it enables detection of was the main correctness concern raised by Taylor Blau in v3 review. If you are tracking whether the path-walk series is solid, this patch is evidence that Stolee has been thorough about closing that gap. The patch itself is not controversial and needs a quick sanity check more than deep review.
