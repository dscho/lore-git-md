This is a brief review reply from Junio C Hamano, the maintainer, responding inline to Patrick Steinhardt's v3 patch fixing the `git maintenance run --detach` lockfile bug.

Junio does not review the code itself -- he simply agrees with the design philosophy underlying Taylor Blau's approach that Patrick adopted: namely, that when a process daemonizes, the surviving child is logically the same process continuing to execute the same service, so it is natural and correct for it to take over responsibility for any tempfiles or lockfiles the original process had open. He calls it "the right wy [way] to look at it."

This is a lightweight endorsement from the maintainer, not a detailed review. It signals that Junio sees no architectural objection to the approach. For a patch that already incorporates Taylor's reviewed design and has a well-received test, this is effectively the last sign-off needed before it lands in Junio's tree. There is nothing new here for anyone following the thread -- just the maintainer affirming that the current direction is fine.
