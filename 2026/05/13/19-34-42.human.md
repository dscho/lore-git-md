This is a well-structured, no-surprise patch.

The config key `branch.<name>.pruneMerged` defaults to true. When set to false, it exempts a branch from `--prune-merged` -- useful for keeping a topic branch around between review rounds. Explicit `git branch -d` is unaffected, so you can still manually delete an exempted branch. The implementation is straightforward: in `prune_merged_branches()`, after the existing safety checks (not checked out, resolvable upstream, not the remote's default branch), it reads `branch.<name>.pruneMerged` via `repo_config_get_bool` and skips the branch with a "Skipping" message if the value is false. The two new tests cover the opt-out behavior (branch is skipped by `--prune-merged` but deletable via `-d`). The documentation in `branch.adoc` and `git-branch.adoc` is clear and consistent with the existing style.

The patch is clean, the tests are sensible, and the feature is conservative -- a per-branch escape hatch that complements rather than undermines the safety model.
