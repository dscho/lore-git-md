**Bugfix for `git maintenance --detach` stale lockfiles, v3.**

This is the first patch of a well-known two-patch series that is now in its third iteration and signaling readiness for merge. The design disagreement from earlier rounds has been resolved, and this patch has a Co-authored-by and Signed-off-by from Taylor Blau.

The problem is straightforward: when you run `git maintenance --detach`, the parent process creates a lockfile, then forks and immediately exits -- but exiting releases the lock, so the backgrounded child runs without protection against concurrent maintenance processes. The fix takes the approach Taylor Blau argued for in v2: rather than adding a special function at the lone call site, the `daemonize()` function itself now automatically transfers ownership of all open tempfiles (and lockfiles, which are a subclass of tempfile) from the parent to the child, so that the parent's death no longer cleans them up. The child process continues to run with proper ownership, and the lockfile is cleaned up only when the child truly finishes its work.

The diff is clean and well-contained. About half the lines are an elaborate FIFO-based test that uses pipes to synchronize with the background process and verify that the lockfile is held for the entire duration of the child's lifecycle. The `reassign_tempfile_ownership()` function added to `tempfile.c` is a simple linear walk of the tempfile list, which should be fine given that the number of active tempfiles at any point is typically small.

The commit message is well-motivated and properly credits the reporter, helpers, and co-author. The only minor thing is that the setup.h documentation block is now a substantial comment for `daemonize()` that lists all of its side effects -- this is a good improvement, as the function was previously undocumented.

This looks ready for `next`. The test is thorough, the fix is architecturally cleaner than the rejected alternative, and any lingering unease about FIFO-based synchronization in tests is unlikely to block it given Taylor's thumbs-up on the v2 test approach.
