This is the second and final patch of Chen Linxuan's series adding a `worktree` condition to Git's conditional config inclusion mechanism.

The patch introduces `worktree:<pattern>` and `worktree/i:<pattern>` keywords for `includeIf` in `.gitconfig`, matching on the working tree's checkout path rather than the `.git` directory. This solves a real pain point in multi-worktree setups where `gitdir` patterns become useless because linked worktrees all share the same `.git` directory. A developer who wants different `user.email` for work and personal checkouts on the same repository can now express that with a single global config: `[includeIf "worktree:/home/user/work/"] path = work.inc`.

The implementation itself is minimal -- about half a dozen lines in `config.c`. It passes the worktree path (obtained from `repo_get_work_tree()`) into the `include_by_path()` helper that was extracted in the previous patch, and returns NULL for bare repositories or during early config reading when no repository object is available. The documentation is good: it explains the relationship to `extensions.worktreeConfig` and gives a concrete example, which is a clear improvement in response to earlier review feedback.

The test coverage is thorough: bare repo, multiple worktrees (including a nested path with trailing-`/` prefix matching), symlinked worktree paths, case-insensitive matching, early config reads, and non-repository scenarios. 113 new lines of test for 6 lines of implementation is a healthy ratio.
