Subject: `[PATCH v4 10/13] t6601: tag otherwise-unreachable trees`

This is a test infrastructure patch, the tenth in a thirteen-patch series
making `git pack-objects --path-walk` work with `--filter` options. The
patch is a preparatory step for the `tree:0` filter fix coming in patch
11/13.

The commit message explains that the existing tagged-tree tests in
`t6601-path-walk.sh` were accidentally passing because the tagged trees
were also reachable from commits included in the path-walk -- so the
test was not actually testing what it thought it was testing. Stolee
discovered this while working on the behavior of directly-requested
objects in the `tree:0` case. The fix rewrites the test setup to create
tree objects that are reachable only through tags, by using `git mktree`
to build the trees from scratch on objects written with `git hash-object
-w`, rather than extracting them from a commit's tree via `HEAD^{tree}`.

Mechanically, the diff replaces the old approach -- which committed files,
tagged the resulting tree, then amended the commit (retaining the tree from
the first commit) and tagged that tree too -- with a new approach that
creates standalone tree objects with no commit ancestry. The blob contents
are also changed from simple "file"/"file2" to "child blob content" and
"tagged tree file2" so the test objects become recognizably distinct. The
old `rm -fr child file file2` is narrowed to `rm -fr file file2` since the
`child/` directory is no longer created in the working tree at all. One
minor change: a prior commit in the setup now uses `git commit -m "first"`
instead of `git commit --amend -m "first"` because there is no earlier
commit to amend after the tagged-tree setup was rewritten. Stolee notes
that this does not meaningfully change any other test case, demonstrating
that the bug went undetected before.

This is a well-motivated, focused test fix. The bug it guards against --
silently dropping tagged trees under `tree:0` -- was the correctness
concern that prompted the v4 rewrite of the `tree:0` patch. Adding test
coverage for the uncovered case (tagged trees that are not also reachable
from commits) is the right approach and follows standard practice for
regression prevention. The implementation is clean and the commit message
explains the motivation clearly. No review feedback has been received on
this patch.
