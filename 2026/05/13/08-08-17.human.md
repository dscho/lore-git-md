This is the first patch of a two-patch series that adds a `worktree` condition to Git's `includeIf` configuration mechanism. It is a pure refactoring patch, preparing the ground for the functional change that follows in patch 2/2.

The patch renames `include_by_gitdir()` to `include_by_path()` and changes its signature so that instead of taking a `struct config_options *` and extracting `opts->git_dir` internally, it takes a bare `const char *path`. The two existing callers (for `gitdir:` and `gitdir/i:`) are updated to pass `opts->git_dir` explicitly. The logic is otherwise untouched -- no behavior change.

This is a textbook preparatory refactoring: small, mechanical, well-scoped, and clearly motivated by the need to reuse the same path-matching logic for a different path (the worktree's working directory) in the next patch. The commit message says exactly what changed and why. The diff is only 19 lines, which makes it easy to verify. This is the kind of patch that should be uncontroversial and quick to merge once the series is accepted.

For a human reader: there is nothing to see here unless you want to check that the function body was not accidentally modified during the rename. The interesting substance is all in patch 2/2.
