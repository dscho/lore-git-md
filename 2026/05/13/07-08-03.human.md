**Classification:** Bugfix / terminal compatibility

This is a narrow but correctness-focused patch from Mantas Mikulėnas (grawity@gmail.com) that fixes Git's ANSI escape code parser in the sideband machinery — the code that handles progress and status messages from remote operations like pushes and fetches.

The issue is that when Git strips or processes ANSI SGR (Select Graphic Rendition) escape sequences in sideband output, it currently only recognizes semicolons as valid parameter separators inside the sequence. But the official ECMA-48 / ISO 6429 standard defines the subparameters in sequences like `\e[38:5:XXm` (256-color) and `38:2:R:G:Bm` (true-color) using colons, not semicolons. The common convention of writing `\e[38;5;XXm` with semicolons is technically a workaround, adopted because older terminals couldn't handle colon-separated subfields — and it works because both conventions happen to produce the same visual result on most terminals.

The practical consequence is small: if a terminal or tool sends the officially correct colon-separated variant, Git's sideband parser will break on it rather than letting it through properly. The patch simply adds `:` to the list of recognized characters alongside `;` in the escape sequence parser, with a corresponding comment update to document the two-format reality.

The change itself is minimal — five lines added, one line changed in `sideband.c` — and is clearly motivated. The commit message cites the reference implementation (xterm's source code) and explains the background concisely. This is the kind of patch that is trivially correct and unlikely to be controversial; it fixes a real-but-rare mismatch between what Git expects and what some modern terminals may actually send. It would be surprising if this did not get picked up quickly.
