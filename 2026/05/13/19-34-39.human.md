**Feature -- part of a new `git branch --prune-merged` series (patch 1/5).**

This is the first of five patches adding safe, automated local branch cleanup to `git branch`. It introduces `git branch --forked <remote>`, which lists local branches whose configured upstream belongs to the given remote -- either a full remote name (e.g. `origin`, matching any `refs/remotes/origin/*` branch) or a specific remote-tracking branch (e.g. `origin/master`). Multiple `<remote>` arguments are unioned.

The implementation is straightforward: a new option and a new action in `cmd_branch`. Parsing handles both configured remote names and DWIMmed refs under `refs/remotes/`. The `branch_is_forked()` helper uses the existing `branch_get()` and `branch_get_upstream()` infrastructure. The output is just sorted branch names printed to stdout. Tests cover the three main cases (remote name, single tracking branch, union of both) plus error handling.

This is the building block for the rest of the series: `--prune-merged` will use the same "forked" concept as a filter before applying upstream-reachability checks for safe deletion. The patch itself looks clean and well-tested, with good error messages and thorough test coverage.
