This is a small refactoring/simplification patch from René Scharfe, one of the project's most regular contributors of clean-up work.

The patch adds a new function `strbuf_add_oid_hex()` to Git's `hex` subsystem that appends the full hexadecimal hash of an object ID directly to a `strbuf`. The motivation is twofold: it is thread-safe (unlike `oid_to_hex()`, which returns a pointer to a static buffer) and slightly more efficient, because it avoids the overhead of determining the string length and copying from the intermediate buffer that `strbuf_addstr(oid_to_hex(...))` requires. The implementation uses the existing `hash_to_hex_algop_r()` internal helper to write the hex string directly into the `strbuf`'s buffer and then adjusts the length.

The real substance of the patch is a Coccinelle semantic patch (in `tools/coccinelle/strbuf.cocci`) that mechanically replaces every instance of `strbuf_addstr(sb, oid_to_hex(oid))` with the new function across the codebase. The diff shows 14 files changed and 17 call sites converted, spanning `bisect.c`, `builtin/cat-file.c`, `pretty.c`, `sequencer.c`, `shallow.c`, and several others. The changes are entirely mechanical -- one-liner substitutions with no behavioral impact.

René provides a performance benchmark showing a 1% speedup on `git log --format=%H`, which is tiny but consistent with what one would expect from saving a string-length pass and a copy.

This is a textbook René Scharfe patch: a small, well-motivated, obviously correct refactoring that improves internal consistency and removes a minor inefficiency. The Coccinelle rule means no manual review of each call site is needed, and the conversion is exhaustive. It is unlikely to be controversial and will almost certainly be picked up into `next` quickly. The only point worth noting is that the new function is declared in `hex.h` with a forward declaration of `struct strbuf`, which requires callers to include `strbuf.h` -- the patch handles this by adding the include in `hex.c` itself, but since the function declaration is in a header that predates `strbuf.h` in the include chain, any new code that uses the declaration without already having `strbuf.h` included might need adjustment; the Coccinelle rule only converts existing call sites, so all of those already have the include.
