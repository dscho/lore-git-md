This is patch 2 of 5 in v9 of Harald Nordgren's series adding `git branch --prune-merged` for safe local branch cleanup. It's an internal refactoring that sets up infrastructure the later patches will use.

The patch reworks `delete_branches()` and the helper `check_branch_commit()` to accept two new parameters: `warn_only` causes the function to downgrade the per-branch "not fully merged" refusal from a hard error (with its four-line hint about `git branch -D`) to a one-line warning, and `n_not_merged` provides a counter so a bulk caller can summarize refusals instead of printing individual messages. Importantly, when `warn_only` is active the function no longer sets a non-zero exit code for refused branches -- the caller can decide the overall exit status.

All existing call sites pass `0` and `NULL`, so the behavior of `git branch -d` on the command line is completely unchanged. This is purely plumbing for the upcoming `--prune-merged` command, which will delete many branches in one shot and shouldn't barrage the user with a separate error per branch.

The patch is clean and well-motivated. It's a straightforward mechanical refactoring that adds no behavioral change on its own, which is exactly the right way to stage this kind of internal prep work. No tests change, no new functionality is exposed. Ready for merging as far as this patch goes; the real interest is in what uses it (patches 3-5).
