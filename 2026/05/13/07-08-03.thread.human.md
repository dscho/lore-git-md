This thread is about a small but important fix to Git’s sideband protocol parser. The patch, originally written by Mantas Mikulėnas and sent by Jeff King, updates `sideband.c` to accept colons (`:`) as sub-parameter separators in ANSI SGR escape sequences, which are used in terminal progress messages (like those from `git push`). Without this change, sequences for 256-color (`\e[38:5:NNm`) and true-color (`\e[38:2:R:G:Bm`) output are treated as garbage, making progress messages harder to read.

Johannes Schindelin reviewed the patch positively, calling it "well-motivated and well-executed," and Junio C Hamano has now confirmed that this review counts as an **Acked-by**. Junio’s only note of hesitation was about the project’s long-standing practice of whitelisting narrow cases (like only allowing semicolons as separators) rather than blacklisting known-bad patterns, but he didn’t object to the patch itself. The fix is additive—it doesn’t change how existing sequences are handled—and is uncontroversial. It’s now effectively approved for merging, though Junio hasn’t yet queued it. The only remaining question is whether he’ll request test coverage, though given the patch’s simplicity, that seems unlikely. The thread is essentially wrapped up, with no further revisions or technical feedback expected.
