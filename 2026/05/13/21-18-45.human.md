This is the third patch in a 13-patch series from Derrick Stolee and Taylor Blau that makes `--path-walk` work with `--filter` options in `pack-objects`.

It adds a new performance test script, `t/perf/p5315-pack-objects-filter.sh`, that benchmarks `git pack-objects --revs --all` under three filter scenarios (no filter, `blob:none`, and `sparse:oid`) with and without `--path-walk`. The test is designed to give paired before/after measurements as the remaining patches in the series wire up the filter logic. Right now the behavior is identical between the two modes because the filter integration has not landed yet, but the infrastructure is there to show the delta once it does.

The setup code is worth noting: it automatically generates a cone-mode sparse-checkout definition by sampling depth-2 directories from the test repository. This is a reasonable approach to making the test work with any large repo passed via `GIT_PERF_LARGE_REPO`, but it is elaborate (about 45 lines of shell script including fallback paths and a flat-repo skip via prerequisite). That complexity is unavoidable for a general-purpose perf test, but means there are several moving parts that could silently misbehave on unusual repository structures.

The current baseline numbers on git.git show that `blob:none` is already substantially faster than a full repack (13.63s vs 27.91s) and that `--path-walk` does not change the numbers much at this stage -- which makes sense, since the filter integration is not yet wired up. The sparse-oid case is dramatically slower than blob:none (72.67s), which is exactly the problem the rest of the series aims to fix.

A clean, well-contained preparatory patch that adds measurement infrastructure without touching any production code. It does what it says, and the design of making the sparse-oid setup dynamic rather than hardcoding a particular repo is appropriate for a performance test that others are meant to run.
