This thread addresses a user-friendly improvement to `git config`'s error messages when users mistakenly use `=` instead of a space in the key-value syntax (`git config foo.key=value` vs the correct `git config foo.key value`). Harald Nordgren's v5 patch series implements this through core parser enhancements in `config.c`, adding validation modes while maintaining backward compatibility. The series appeared merge-ready after addressing Junio's earlier validation concerns.

Junio has now reviewed the v5 patch and, while not objecting to the functionality, suggests a cleaner API design. He proposes splitting the modified `git_config_parse_key()` into a file-scoped helper and introducing a new public validation function, arguing this would better separate concerns than the current parameter-based approach. This is a substantive architectural review from the maintainer, indicating the series will likely need a v6 iteration to refine the interface before merging. The core idea - improving syntax hints for common user errors - remains uncontested, but the implementation needs polishing to meet Git's API design standards.
