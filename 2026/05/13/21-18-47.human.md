This is patch 05/13 of Derrick Stolee's v4 series adding `--filter` support to `git pack-objects --path-walk`. This patch teaches the path-walk API to handle the `blob:none` filter natively, which is the simplest and most useful filter for large repositories.

The mechanism is clean: a new `prepare_filters()` static function in `path-walk.c` checks for `LOFC_BLOB_NONE` and, when it finds it, sets `info->blobs = 0` (telling the path-walk to skip all blob objects) and clears the filter from `revs` so that `prepare_revision_walk()` does not reject the configuration that now has `--path-walk` but no filter. A companion public API function `path_walk_filter_compatible()` lets `builtin/pack-objects.c` check whether a given filter is compatible before complaining about the `--filter` / `--path-walk` conflict. The documentation in `git-pack-objects.adoc` is updated to say that `--path-walk` now supports `blob:none`, and the previous blanket warning about `--filter` incompatibility is removed for this case.

The patch also includes test helper improvements: `test-path-walk` gains a `--filter` option and is switched from manual `REV_INFO_INIT` to `repo_init_revisions()` for proper filter-spec initialization. Three tests in `t5620-backfill.sh` that used `GIT_TEST_PACK_PATH_WALK=0` workarounds are reverted since those now work with filter. Two new tests in `t6601-path-walk.sh` verify the output for `blob:none` with `--all` and with a single branch.

The performance data is interesting. On the Git repo itself, `--path-walk` with `blob:none` produces a packfile that is 16% smaller (115.2M vs 137.7M), but takes 73% longer (23.43s vs 13.51s). The commit message attributes this to "two compression passes" when `--no-reuse-delta` forces fresh deltas. For a feature whose primary value proposition is speed, this result is worth noting -- the space savings are real, but the time tradeoff is not obviously a win for the Git repo. The series' earlier cover-letter data showed much more dramatic speedups on larger repos (nodejs/node, azure-devops-docs), so the picture is likely that `blob:none`'s time penalty is amortized away on repos large enough that `--path-walk`'s better delta compression really matters.

Structurally the patch looks well-constructed. The `prepare_filters()` / `path_walk_filter_compatible()` split is a sensible design that lets callers query compatibility without paying for the side effects. The `default:` case that errors out on unsupported filters is a reasonable forward-compatibility stance. No review has appeared on this v4 patch or its predecessors.
