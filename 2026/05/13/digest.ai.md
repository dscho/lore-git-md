# Git Mailing List Daily Digest — 2026/05/13 (Wednesday)

**The day in brief.** A moderately busy day with 65 emails across 22 active threads. The standout development is the arrival of v4 of Derrick Stolee and Taylor Blau's `--path-walk`/`--filter` integration series (13 patches), which includes a substantial rewrite of the `tree:0` filter handling to fix a correctness bug that escaped detection in v3. Harald Nordgren's `git branch --prune-merged` series also reached v9, addressing Junio's final objection by removing the `--force` override. Several smaller series appear ready for merge, including Patrick Steinhardt's maintenance-mode lockfile fix and René Scharfe's `strbuf_add_oid_hex()` cleanup.

## Notable threads

**`--path-walk`/`--filter` integration reaches v4 with `tree:0` rewrite.** Derrick Stolee posted v4 of the 13-patch series making `--path-walk` work with all major `--filter` options in `pack-objects`. The headline change is a substantial rewrite of the `tree:0` filter handling (patch 11/13): Stolee discovered that tagged trees could be silently dropped when they were not also reachable from any commit, a bug that escaped detection because the existing test data happened to use tagged trees that were also root trees. A new preparatory test (patch 10/13) creates trees reachable only through tags to prevent regression. The series also adds `object:type=<type>` filter support (patch 12/13) with careful handling of the "trees off, blobs on" case, and a `combine` filter (patch 13/13) that composes multiple filter specifications via recursive descent. Performance data continues to show dramatic speedups -- 60% time reduction and 14% smaller packs for `sparse:oid` on the Git repo itself. The series has received no independent review across all four versions; the only reviewer is co-author Taylor Blau, whose comments have been surface-level. The `tree:0` rewrite in particular would benefit from a second pair of eyes.

**`git branch --prune-merged` v9 ready for `next`.** Harald Nordgren sent v9 of the five-patch series adding safe, automated local branch cleanup, addressing Junio C Hamano's sole remaining objection from v8. The fix is narrow but decisive: `--force` no longer bypasses the mergedness check -- the reachability check is always enforced, and the synopsis drops `[-f]`. The safety model (never delete the checked-out branch, never delete the local default-branch name matching the remote's HEAD, skip branches with unresolvable upstreams) was approved by Junio in v8 and is preserved intact. Patches 1-2 (the `--forked` listing infrastructure and the `delete_branches()` refactoring) are unchanged. Patch 4 adds a `branch.<name>.pruneMerged` per-branch opt-out, and patch 5 adds the `--all-remotes` convenience flag. The series looks ready for `next`. Separately, Harald floated a `fetch.pruneLocalBranches` config concept that would automatically delete local branches during fetch -- a fundamentally different safety proposition that has not been reviewed.

**Maintenance-mode lockfile and `gc.auto` fixes ready to merge.** Patrick Steinhardt's v3 two-patch series for the maintenance subsystem is now settled. Patch 1 fixes a real bug where `git maintenance run --detach` created a lockfile that was released when the parent exited immediately after forking, leaving the background work unprotected. The fix, which incorporates Taylor Blau's alternative design, makes `daemonize()` automatically transfer ownership of all open tempfiles and lockfiles to the child process. Junio C Hamano endorsed the design direction, calling the daemonized child "a logical continuation of the original process." Patch 2 restores `gc.auto=0` behavior after the transition from `git gc` to `git maintenance` broke it -- a user-reported regression. Both patches have received substantive review and maintainer concurrence.

**`includeIf worktree:` series converges.** Chen Linxuan's v4 two-patch series adding `worktree:<pattern>` and `worktree/i:<pattern>` conditions to Git's `includeIf` config mechanism received a positive review from Phillip Wood ("this looks good to me"). The series addresses a genuine pain point in multi-worktree setups where `gitdir` patterns are useless because linked worktrees share the same `.git` directory. The implementation is minimal -- about six lines of C in `config.c` -- with thorough test coverage (113 lines) covering bare repos, symlinked worktree paths, case-insensitive matching, and early config reads. All prior review feedback from Patrick Steinhardt and Junio has been incorporated. The series is ready for maintainer pickup.

**`strbuf_add_oid_hex()` cleanup reviewed and benchmarked.** René Scharfe's single-patch cleanup introducing `strbuf_add_oid_hex()` to replace `strbuf_addstr(sb, oid_to_hex(oid))` received a strong endorsement from Jeff King, who called it worth doing "solely for removing more instances of global buffers." A Coccinelle semantic patch mechanically converts all 17 existing call sites across 14 files. René provided follow-up benchmarks on Apple M1 and M5 showing a consistent ~7-8% speedup on `git cat-file --batch-all-objects --batch-check='%(objectname)'`. The patch is ready for `next`.

**`git status` push-branch advice fix.** Harald Nordgren sent v2 of a single patch fixing a usability gap in `git status`: when the local branch is behind or has diverged from a *push* branch, the advice text now says `git pull <remote> <branch>` instead of a bare `git pull`, which would follow the upstream remote -- potentially a completely different remote. The v2 narrows scope from v1 by removing the divergence advice from the push-branch path, which the author found undesirable in practice. No reviews have been posted yet.
