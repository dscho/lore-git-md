This is the first patch (01/13) in Derrick Stolee's v4 series to integrate `--path-walk` with `--filter` options in `pack-objects`. It is purely mechanical: when the `GIT_TEST_PACK_PATH_WALK` test variable is enabled globally (causing `git pack-objects` to use `--path-walk` by default), some tests in `t5620-backfill.sh` fail because `--path-walk` is currently incompatible with `--filter` and emits a warning over stderr. The tests in question (`backfill with prefix pathspec`, `backfill with multiple pathspecs`, `backfill with wildcard pathspec`) check `test_must_be_empty err`, so any stderr output from the incompatibility warning causes a spurious failure.

The fix is simple: each affected test invocation of `git backfill` is prefixed with `GIT_TEST_PACK_PATH_WALK=0` to disable path-walk for those specific tests, along with a brief comment explaining why. This is a temporary shim -- the comment says "until these options work together", meaning later patches in this series are expected to remove the incompatibility.
