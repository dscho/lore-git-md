This is patch 1 of 5 in Harald Nordgren's v9 series adding `git branch --forked <remote>` as the first building block for the eventual `--prune-merged` cleanup feature. The series is substantively accepted; v9 fixes the final objection Junio C Hamano raised against v8 (that `--force` should not bypass the mergedness check), and this patch is unchanged from v8.

`--forked <remote>` lists local branches whose configured upstream (`branch.<name>.merge`) falls within the given remote or remote-tracking branch. The argument can be a configured remote name (e.g. `origin`, matching all `refs/remotes/origin/*` refs) or a specific remote-tracking branch (e.g. `origin/master`). Multiple arguments are unioned. Internally, `parse_forked_args` distinguishes remotes from specific refs by trying `remote_get()` first, then falling back to `repo_dwim_ref()`, dying with a clear error if neither matches. `branch_is_forked()` checks both the remote name and exact tracking ref against the branch's configured upstream.

The implementation lives in `builtin/branch.c` with a new `list_forked_branches()` function and about 110 lines of C. It uses `refs_for_each_branch_ref()` with a callback to collect matching branches. The six tests in `t/t3200-branch.sh` cover setup (a three-remote test repository), matching by remote name, matching by specific tracking branch, union behavior, rejection of unknown arguments, and the required-argument check. The test organization is straightforward and the coverage is adequate for a plumbing feature.

This is a clean, well-structured patch.
