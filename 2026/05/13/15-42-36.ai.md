This is a documentation patch for the `--word-diff` option.

The current docs describe the output modes (color, plain, porcelain) and the word-regex mechanism, but they assume the user understands that word-diff is a two-stage process: first Git computes a traditional hunk-level diff on lines, then within each changed line it applies word-level comparison. That means the line-level alignment can produce word changes even when the actual words in the two files are identical -- a counterintuitive behavior that has confused users.

The patch adds a short note to the `--word-diff` man-page entry explaining this line-then-word relationship. It is five lines long, clearly motivated, and cites two contributors who presumably surfaced the confusion (Vincent Lefevre and Johannes Sixt, CC'd on the commit). The commit message is well-written and explains both the gap and the fix.

This is small, uncontroversial, and addresses a real documentation blind spot. Should land without fuss.
