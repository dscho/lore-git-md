This is a follow-up review from Patrick Steinhardt on patch 2/2 of Chen Linxuan's series adding `worktree` and `worktree/i` `includeIf` conditions.

Patrick is responding to the author's note that the feature does not work with early-config parsing, and the question of whether that needs to be fixed before the series can land. Patrick pushes back gently but clearly: even if the early-config limitation is accepted as a known shortcoming, a test for the current behavior should be part of the patch. Specifically, he recommends that the test either pass (`test_expect_success`) if the limitation is intentional, or be marked as a known failure (`test_expect_failure`) if the author plans to fix it later. The key point is that the behavior should be documented in code by a test, one way or the other.

This is a substantive but narrow review comment that clarifies and sharpens one of the three action items from Patrick's earlier review. It is not a blocker in the sense that Patrick is demanding the early-config fix, but it is a practical requirement: the patch needs an explicit test for the early-config case rather than leaving the gap undocumented. This should be straightforward to address in v4 alongside the other two items (documentation dedup and the nongit test).
