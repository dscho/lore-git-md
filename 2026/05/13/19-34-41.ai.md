This is patch 3 of 5 in Harald Nordgren's v9 series adding `git branch --prune-merged`, implementing the core deletion logic. It builds on patch 1's `--forked` listing infrastructure and patch 2's refactored `delete_branches()` and `check_branch_commit()` machinery. The sole change from v8 is the removal of the `--force` bypass: the reachability check is now always enforced (and patch 5 will update the synopsis accordingly to drop `[-f]` from `--prune-merged`). The v8 safety model -- never delete the checked-out branch in any worktree, never delete the local default-branch name that mirrors the remote's HEAD, skip branches whose upstream ref no longer resolves locally -- is preserved intact. The "not fully merged" warning message was updated from "re-run with --force to delete it anyway" to "delete it with 'git branch -D' if you are sure", reflecting the removal of the `--force` override.

The implementation is self-contained in `builtin/branch.c`. A new `collect_forked_set()` helper factors out the collection logic previously specific to `--forked` list, adding a `protected_default_refs` output that resolves each remote's `refs/remotes/<name>/HEAD` target. The `prune_merged_branches()` function then iterates over the collected candidate branches, filtering out any that fail the three safety checks, and passes the survivors to `delete_branches()` with `warn_only=1` (which was prepared by patch 2's refactoring). The `strvec.h` include is newly needed for the `deletable` vector.

The diff is 226 insertions across three files. Documentation update adds the `--prune-merged` synopsis line and a detailed explanation of the safety semantics. Test coverage is thorough: eight new tests cover basic deletion, skipping un-integrated branches (with a "not fully merged" warning), skipping branches with unresolvable upstreams (silently, because the upstream is gone), never deleting the checked-out branch (even when merged), sparing the local default branch by name-matching against the remote's HEAD, confirming that a differently-named branch tracking the same upstream *is* deletable, and a required-argument check.

This is a targeted, well-tested feature patch for an already-approved series. The v8 safety model was reviewed and accepted by Junio C Hamano; v9's sole fix addresses his only remaining objection. The code is clean, the commit message is explanatory, and the test structure covers the important edge cases. The patch looks ready for `next`.
