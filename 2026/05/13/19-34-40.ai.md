This is patch 2/5 of Harald Nordgren's v9 series adding `git branch --prune-merged`. It is a pure refactoring patch that prepares the deletion machinery for bulk use, with no behavioral change for existing call sites.

The patch adds two new parameters to the internal functions `check_branch_commit()` and `delete_branches()`: `warn_only` and `n_not_merged`. When `warn_only` is set, the per-branch refusal message drops from a multi-line error with advice ("the branch 'X' is not fully merged" plus a hint about `git branch -D`) to a single-line warning, and the branch is skipped without setting the exit code. The `n_not_merged` pointer, when non-null, is incremented for each skipped branch so a bulk caller can produce a summary at the end rather than printing per-branch advice. All existing callers pass 0/NULL, so no existing behavior changes.

This is a straightforward and well-scoped intermediate step. The approach is conservative: it introduces the mechanism but keeps all current behavior identical. The commit message explains the purpose clearly, the C code is clean -- two new function parameters threaded through existing paths with minimal branches -- and the diff is only 29 lines in a single file. The patch looks mechanically correct and is exactly the sort of preparation that makes the later `--prune-merged` logic cleaner.

Nothing here is likely to be controversial. This patch is part of a series that is substantively accepted; v9 was a narrow mechanical fix to Junio's one remaining objection, which was in patch 3 (the `--force` behavior). This patch is unchanged from v8.
