This is a reply from D. Ben Knoble to Alexander Sandström's bug report about lowercase `head` resolving to the wrong worktree's HEAD on case-insensitive filesystems. The email is not a patch; it is a brief contextual response placing the bug report into the project's known-issues history.

Knoble acknowledges that the bug is real and links to two prior discussions from 2024 that already identified the same underlying problem: because Git still treats refs as named files on disk, the ref-store layer performs a case-insensitive file lookup on filesystems that allow it, causing `head` to match `.git/HEAD` (the main worktree's HEAD) instead of the per-worktree `.git/worktrees/<name>/HEAD`. The comment "I don't think we're going to solve [this] in the ref store where refs are just named files" suggests that Knoble considers the filesystem-backed ref store fundamentally incapable of fixing this without a design-level change. He then notes that switching to the reftable backend should eliminate these paper cuts -- presumably because reftable does not delegate name lookup to the filesystem.

This is a surface-level reply: it provides useful context (pointers to prior discussion) but does not engage with the technical content of the bug report or evaluate the fix options proposed by Alexander. Knoble does not say whether he thinks the project should reject lowercase `head` or normalize it; he simply notes that the problem is already known and effectively blocked on the reftable transition. For readers following the thread, this response essentially marks the bug as "won't-fix for the files backend" and redirects attention to the reftable effort as the eventual solution.
