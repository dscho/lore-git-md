This thread is about adding a `worktree:<pattern>` condition to Git's
conditional config inclusion mechanism (`includeIf` in `.gitconfig`). In
multi-worktree setups where linked worktrees all share the same `.git`
directory, the existing `gitdir:<pattern>` condition cannot distinguish
worktrees by their checkout path. The proposed `worktree:` condition
solves that, letting a developer set different `user.email` for work and
personal checkouts of the same repository.

Chen Linxuan is the author -- the series switched from Kohei Enami between
v3 and v4, though the relationship between them is unclear. The series is
now in its fourth iteration, incorporating review feedback from Patrick
Steinhardt and Junio C Hamano on v3. Two patches make up the series: the
first is a mechanical refactoring that renames `include_by_gitdir()` to
`include_by_path()` and gives it a generic path parameter; the second
adds the actual `worktree:` condition.

The implementation is minimal: about six lines of new code in `config.c`
that pass the worktree path into the refactored helper. Tests are thorough
-- 113 new lines covering bare repos, multiple worktrees, symlinked paths,
case-insensitive matching, early config reads, and non-repository
scenarios. Documentation was improved from earlier versions to explain the
relationship to `extensions.worktreeConfig` and provide a concrete example.
No objections or remaining open questions have been raised on v4; the
series looks ready for Junio to pick up.
