Documentation patch. Michael Montalbo follows up on an earlier exchange with Vincent Lefevre, who had reported confusion about `git diff --word-diff` showing word-level changes when two files differ only in whitespace. The author had previously proposed adding a clarifying paragraph to the documentation, and Vincent replied "yes, this would be useful." Montalbo now confirms that he has submitted a formal patch implementing that suggestion.

The patch itself is a single paragraph added to `Documentation/diff-options.adoc` explaining that word diff first computes a line-level diff and then finds word-level changes within each hunk; the line-level alignment therefore determines what gets compared at the word level, which can produce unexpected output from whitespace-only changes. There is no code change, no new behavior, and no attempt to alter how word diff works -- just an explanation so that the current behavior is no longer surprising.
