This is patch 06/13 of Stolee's v4 series integrating `--path-walk` with `--filter`, which applies the `path_walk_filter_compatible()` API introduced in the previous patch to the `git backfill` command.

The change is small and mechanical. Until now, `git backfill` rejected *any* `--filter` option outright with a hard die message. This patch replaces the blanket rejection with a call to `path_walk_filter_compatible()`, which returns true for filters that the path-walk backend can actually handle (currently just `blob:none`). Incompatible filters still die, but with a more generic error message that no longer names `--filter` specifically. A new test confirms that `tree:1` and `blob:limit=10m` are correctly rejected.

This is a necessary piece of plumbing -- without it, users who have a `--filter` alias or script that works with `pack-objects` would hit an unconditional failure if they tried the same with `backfill`. It is not a user-facing feature on its own; the interesting part is that `blob:none` now theoretically works with `backfill` as well, though Stolee does not demonstrate or claim that here.

The patch is straightforward, well-scoped, and adds appropriate test coverage. One minor observation: the test uses `test_must_fail ... --objects --filter=tree:1` without supplying any repository or object source -- that works because the failure happens during argument validation before any repo access, and the test does not call `test_commit` or set up a repo. This is fine for a unit-style check but worth noting if someone later reorganizes the command's option parsing.

The commit message is clean and the motivation is clear. No controversy expected.
