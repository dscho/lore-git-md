Type: documentation patch

Core problem or goal: The --word-diff documentation describes the output modes and
word-regex mechanism but omits the crucial fact that word-diff is a two-stage
process: Git first computes a traditional hunk-level diff on lines, and then
within each changed line it applies word-level comparison. This means the
line-level alignment can produce word changes even when the actual words in the
two files are identical -- a counterintuitive behavior that has confused users.
The patch adds a short note to the --word-diff man-page entry explaining this
line-then-word relationship.
