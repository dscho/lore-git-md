This is the first patch in a 13-patch v4 series from Derrick Stolee (with Taylor Blau as co-author) that makes `--path-walk` work with `--filter` in `git pack-objects`. This particular patch is a piece of supporting infrastructure rather than a substantive change to the main effort.

The patch is a test fix for `t5620-backfill.sh`, a script that exercises `git backfill`. It disables `GIT_TEST_PACK_PATH_WALK=1` (a test variable that enables `--path-walk` by default in `git pack-objects`) in three tests that use both `backfill` and `--filter` together. The reason is straightforward: until the rest of this series is applied, `--path-walk` and `--filter` are incompatible, and `backfill` internally calls `pack-objects` with both, causing a warning on stderr that makes the existing `test_must_be_empty err` assertions fail.

The change is small -- three instances of `GIT_TEST_PACK_PATH_WALK=0` inserted before existing `git backfill` invocations, each with a brief comment explaining why. This is standard test-administration work that you would expect to see in any series that adds a new feature behind a `GIT_TEST_*` flag: old tests need to opt out of the new default behavior before the incompatible bits land.

One typo in the comment ("overs stderr" instead of "over stderr") is present in all three instances. Minor, but worth noting if you are one of the people who routinely spots nits.

This patch is uninteresting in isolation -- it only makes sense as part of the larger series. It has no technical content to evaluate beyond the one-line fix. Any discussion this patch generates is likely to be about the spelling error in the comments or about how the series handles the `GIT_TEST_PACK_PATH_WALK` flag generally (a point that the cover letter identifies as still open).
