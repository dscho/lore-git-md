This is a documentation/hint patch touching the config subsystem. The author addresses a common user error: typing `git config foo.key=value` (using INI-file or `--flag=value` syntax) instead of the correct `git config set foo.key value`. When `git_config_parse_key()` encounters an invalid character in the key, it currently prints only a bare "error: invalid key: ..." with no guidance. The patch adds a one-line suggestion, `(did you mean "git config set ..."?)`, emitted specifically when the offending character is `=`. The heuristic is narrow by design—it does not fire for other invalid characters — so it should not produce false positives.

The implementation is minimal: four lines added inside the existing error path in `config.c`. The hint is only shown when `c == '='`, the pointer arithmetic in the `%.*s`/`%s` pair splits the key at the `=` to reconstruct the intended call with space-separated key and value. The diff is clear and trivially correct from a code perspective.

This is a small, well-scoped user-experience improvement. The reasoning is clearly explained in the commit message (the common mistake, the analogy with the existing "did you mean" style), and the patch restricts itself intentionally to avoid overreaching. No tests are added, which is a minor shortcoming for a change affecting user-facing error output; the project typically expects new error messages to be covered. However, the patch is otherwise clean and non-controversial. Worth quick attention if you care about config UX or first-time-user friction.
