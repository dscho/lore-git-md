**Thread identity** -- Subject: `[PATCH] strbuf: add strbuf_add_oid_hex() and use it`. Single cleanup/refactoring patch from Rene Scharfe. Type: patch (cleanup).

**Core problem or goal** -- Introduce `strbuf_add_oid_hex()` to append an object ID's full hex representation directly to a `strbuf`, replacing the pattern `strbuf_addstr(sb, oid_to_hex(oid))`. This eliminates two issues with the old pattern: (1) thread-unsafety from `oid_to_hex()`'s static buffer; (2) minor inefficiency from an extra copy through an intermediate buffer.

**Current status** -- First (and only) version. Patch has received a positive substantive review from Jeff King (Peff) and is ready for Junio to pick up.

**Key technical details** -- New function declared in `hex.h` (with forward declaration of `struct strbuf`); implemented in `hex.c` (includes `strbuf.h`). Uses `hash_to_hex_algop_r()` to write directly into the strbuf's buffer and adjusts the length. A Coccinelle semantic patch in `tools/coccinelle/strbuf.cocci` mechanically converts all 17 existing call sites across 14 files (including `bisect.c`, `builtin/cat-file.c`, `pretty.c`, `sequencer.c`, `shallow.c`). Note on include ordering: `hex.h` uses a forward declaration of `struct strbuf`, so callers need `strbuf.h` included. All converted call sites already have the include; future code using the declaration without `strbuf.h` would need adjustment. Rene's benchmark showed ~1% speedup on `git log --format=%H`; Peff independently tested with the extreme case `git cat-file --batch-all-objects --batch-check='%(objectname)'` and observed a similar ~3% (within noise).
