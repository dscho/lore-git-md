This is a bugfix and UI improvement for `git status`, part of the push-branch tracking feature (`status.compareBranches`). It is the second iteration (v2) of a single patch from Harald Nordgren.

The patch addresses a usability gap: when `git status` reports that the local branch is behind or has diverged from a *push* branch (as opposed to the upstream branch), the advice text used to say a bare `git pull`. That `git pull` would follow the upstream remote -- which can be a completely different remote from the push target -- making the hint actively misleading for anyone using `push.default = current` or `remote.pushDefault`. This patch changes those hints to say `git pull <remote> <branch>` instead, so they actually help.

The change is in `remote.c`. The internal `format_branch_comparison()` function gains two new parameters for the push remote name and push branch name. When formatting a push-branch comparison, `format_tracking_info()` now extracts those names: it calls `pushremote_for_branch()` to get the remote, then strips the `refs/remotes/<remote>/` prefix from the full ref to recover the branch name the user would type. Both the "behind" and "diverged" advice paths are covered, with a graceful fallback to the bare `git pull` when the extraction fails (e.g. for unusual refspecs). The patch also enables the pull advice flag (`ENABLE_ADVICE_PULL`) for push-branch comparisons; previously it was only set for upstream comparisons.

Two new tests in `t/t6040-tracking-info.sh` validate the output: one for the basic "behind" case with a standard pushrefspec, and one with a remapped push refspec (`refs/heads/feature14:refs/heads/remapped14`) to confirm that the extracted branch name matches the push target, not the local branch name.

**Changes from v1:** This iteration removes the divergence advice (`ENABLE_ADVICE_DIVERGENCE`) from the push-branch path that v1 had added. The commit message now only promises to enable the pull advice, not the divergence advice. The author's cover note explains this: "Remove the message only when diverged from push-branch, because it was in the way when I used it now on my real branch." This is a meaningful narrowing of scope -- the divergence advice, which suggests `git pull` to integrate a diverged branch, is apparently undesirable for push-branch comparisons in practice -- and the v1 test for the diverged case is gone.

The patch remains small and well-scoped, with a clear motivation and targeted tests. The narrowing from v1 is a sensible refinement based on real usage. No reviews have been posted yet, but the approach is straightforward and unlikely to be controversial.
