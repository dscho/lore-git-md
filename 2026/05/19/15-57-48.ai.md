This is patch 4/16 in Taylor Blau's incremental MIDX repacking series, which refactors the `keep_hashes` array handling in the MIDX writing code to use `strvec` instead of manual memory management. The change simplifies the code by replacing manual array allocation and cleanup with the more ergonomic `strvec` interface, while maintaining the same behavior for tracking which files should be preserved during MIDX chain pruning.

The patch converts the `keep_hashes` array (used to store checksums of MIDX files that should be retained) from a manually managed array of strings to a `strvec`. This eliminates the need for pre-counting elements and manual memory cleanup, while making the control flow clearer. The ordering remains important as it determines the contents of the `multi-pack-index-chain` file when writing incrementally.

Key changes include:
- Replacing `CALLOC_ARRAY` and manual string management with `strvec_push`
- Simplifying cleanup via `strvec_clear`
- Updating related functions to accept a `strvec` instead of raw array+count
- Maintaining the same forward-ordering behavior when building the array

The change is a straightforward refactoring with no behavior modification, building on the incremental MIDX infrastructure established in earlier patches. It follows a similar pattern to previous conversions in the series, continuing the trend of modernizing the codebase's string handling patterns. The patch appears well-contained and low-risk, with no open questions or obvious issues.
