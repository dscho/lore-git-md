This is part 4 of a 9-patch series introducing external command support for Git notes. The patch adds timeout handling to the run-command infrastructure, which the notes feature will later hook into.

The change introduces a new `finish_command_with_timeout()` function that allows callers to specify both a timeout duration and a signal to send if the child doesn't exit in time. The implementation carefully handles edge cases like interrupted system calls and avoids sleeping for the full timeout period when the process might exit sooner. The timeout is specified in nanoseconds for precision, though the actual sleep granularity is 10ms to balance responsiveness with system call overhead.

The patch appears well-considered, with clear documentation and attention to details like proper cleanup registration when timeouts occur. It maintains backward compatibility by keeping the original `finish_command()` as a wrapper. The changes are focused on the run-command subsystem but serve the broader goal of making Git's process management more robust, particularly for the upcoming notes external command feature.
