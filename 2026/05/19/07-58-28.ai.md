This is version 11 of Harald Nordgren's feature patch series adding a `--track=fetch` mode to `git checkout` and `git switch`. The feature automatically fetches from the remote when creating a tracking branch, eliminating the need for a separate `git fetch` step.

**Key changes in v11.** This version addresses Junio C Hamano's v10 review comments by completely rewriting the remote resolution logic. The new implementation properly handles custom refspec mappings (like fetching into `refs/remotes/upstream/*` from `origin`) by querying all remotes' fetch refspecs rather than assuming the remote name matches the start-point prefix. It also adds support for bare namespace names (like `origin`) by first checking `<namespace>/HEAD`.

**Implementation details.** The core changes are in `resolve_fetch_target()`, which now uses a callback to match against all remotes' refspecs. The function also properly follows symbolic refs for bare remote names. The patch adds two new test cases: one for custom refspec mappings and one for bare namespace handling. Documentation remains clear about the behavior with both branch and remote-name start points.

**Assessment.** This version appears to fully address the technical concerns from previous reviews. The implementation is now more flexible and handles edge cases that were problematic in earlier versions. The test coverage is thorough, with 18 test cases covering hierarchical remotes, custom refspecs, error conditions, and combinations with other tracking modes. The feature looks ready for inclusion pending final maintainer approval.
