This is the 7th patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem. The series aims to speed up bitmap generation for large repositories, building on his previous pseudo-merge bitmap work.

The current patch refactors how pseudo-merge parent bitmaps are handled during bitmap generation. Instead of creating temporary bitmaps for parent sets during the write phase and then discarding them, the patch stores these parent bitmaps directly on the bitmapped_commit structure. This change:

1. Adds a new pseudo_merge_parents field to struct bitmapped_commit
2. Moves parent bitmap creation earlier in the process
3. Ensures proper cleanup of these bitmaps
4. Maintains the same on-disk output while changing the internal organization

The change appears to be a preparatory refactoring that will enable further optimizations in the final patch of the series. It doesn't introduce new performance improvements itself but sets up the infrastructure for more significant gains in the pseudo-merge handling that will follow.

The patch continues the series' pattern of focused, well-structured changes to the pack-bitmap-write.c internals. As with previous patches, this appears to be a low-risk change given its internal nature and the author's deep expertise in this subsystem.
