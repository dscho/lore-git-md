This is a follow-up to a bugfix patch that makes `git log --follow` correctly track file renames across subtree merges. The original patch from Miklos Vajna fixed an inconsistency where `git log --follow` would miss pre-merge history for files that were introduced via subtree merges, while `git blame --follow` already handled this case correctly.

The patch itself is straightforward - it adds rename detection logic in `log-tree.c` to match the existing behavior in `blame.c`, along with a test case. The author notes that the initial submission received no negative feedback, suggesting the approach is sound. He's now following up directly with Junio Hamano to check on next steps, as the patch appears ready for review and likely merge.
