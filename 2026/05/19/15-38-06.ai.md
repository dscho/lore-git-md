This is part 6/8 of Christian Couder's v3 series adding URL-based auto-configuration for promisor remotes, building on the previously approved LOP (Large Object Promisors) series. The patch implements the core URL matching logic that allows clients to trust known remotes whose URLs match patterns in `promisor.acceptFromServerUrl`.

The key technical additions are:
- A new `url_matches_accept_list()` helper that checks URLs against the allowlist patterns with strict component-wise matching (exact scheme/port, wildmatch for host/path)
- Integration of this check into `should_accept_remote()` to allow field updates for known remotes even when `acceptFromServer=none`
- Security-conscious URL normalization before matching to prevent bypasses
- Documentation of the precedence rules between `acceptFromServer` and `acceptFromServerUrl`

The implementation includes comprehensive tests verifying:
- Basic allowlist functionality
- Multiple pattern support
- URL mismatch protection
- Edge cases around URL normalization

The patch maintains the series' strong security posture while enabling practical workflows where organizations can whitelist their own infrastructure. With all technical review feedback addressed, this brings the URL-based configuration feature closer to completion alongside the LOP series.
