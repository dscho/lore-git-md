This is patch 15/16 in Taylor Blau's incremental MIDX repacking series, introducing the `--write-midx=incremental` option for `git repack`. The patch exposes the incremental MIDX repacking mode that was implemented in earlier patches, allowing Git to maintain a chain of MIDX layers that are compacted over time using a geometric merging strategy.

Key aspects of this patch:
- Adds `incremental` as a recognized argument to `--write-midx`
- Introduces two new configuration options to control compaction behavior: `repack.midxSplitFactor` (default 2) and `repack.midxNewLayerThreshold` (default 8)
- Implements comprehensive test coverage in `t/t7705-repack-incremental-midx.sh` that exercises various scenarios including threshold-based compaction, layer preservation, and error cases
- The incremental mode maintains a chain where newer layers contain small packs with few objects, while older layers contain fewer, larger packs
- Compaction occurs when a layer's object count exceeds 1/splitFactor of the next layer's count
- Only packs in the tip layer are considered for geometric repacking unless they fall below the new layer threshold

The implementation appears solid with thorough test coverage. This represents the culmination of Taylor's work on improving Git's scalability for large repositories through incremental MIDX maintenance. The series has received positive review from Jeff King and others, with all prior feedback incorporated.
