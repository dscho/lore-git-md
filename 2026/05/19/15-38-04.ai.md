This is a preparatory patch in Christian Couder's URL-based auto-configuration series for promisor remotes. The patch adds infrastructure to handle cases where the local name for a promisor remote differs from the name advertised by the server.

The key changes are:
1. Adds a `local_name` field to `struct promisor_info` to track locally-generated remote names (which will be prefixed with `promisor-auto-` in later patches)
2. Introduces a helper function `promisor_info_internal_name()` that returns the appropriate name (local if set, advertised otherwise)
3. Updates configuration storage and lookup functions to use this helper, ensuring consistent name handling

The patch is a straightforward refactoring that enables the subsequent auto-naming functionality while maintaining backward compatibility. It follows the series' pattern of careful, incremental changes to the promisor remote infrastructure.

This is part of the larger effort to improve promisor remote configuration by allowing URL-based pattern rules, with all security considerations and naming conventions already established in earlier patches. The changes are minimal and focused, touching only the necessary parts of promisor-remote.c to support the new naming scheme.
