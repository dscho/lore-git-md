This is the final version (v3) of Christian Couder's feature patch series that adds URL-based auto-configuration for promisor remotes. The series builds on previous work to enhance Git's promisor remote functionality.

The key addition is a new `promisor.acceptFromServerUrl` config option that allows clients to automatically configure promisor remotes based on URL patterns, rather than requiring manual pre-configuration. This is particularly useful for organizations that want to allow certain trusted servers to advertise promisor remotes.

The series has gone through multiple rounds of review (now addressing all feedback from Toon Claes, Patrick Steinhardt and Junio C Hamano) and is technically complete. Key security aspects include:

- URL patterns can include globs (`*`) with strict matching rules (scheme/port must match exactly, host matching prevents path boundary crossing)
- Auto-generated remote names use a `promisor-auto-` prefix with URL sanitization
- Collision handling prevents remote name hijacking
- Comprehensive documentation of security considerations

The implementation touches `promisor-remote.[ch]`, `urlmatch.[ch]`, and adds extensive test coverage in `t5710-promisor-remote-capability.sh`. The series is now rebased on master and ready for merging, representing a significant usability improvement for promisor remote workflows while maintaining strong security defaults.

Changes since v2 include:
- Removal of WM_PATHNAME flag from host matching
- Simplified wildmatch() logic
- Clearer documentation of configuration precedence rules
- Explicit handling of username/password components in URLs
- Final technical refinements from reviews

This completes the URL-based auto-configuration feature alongside the previously approved LOP (Large Object Promisors) series, marking substantial progress in promisor remote functionality.
