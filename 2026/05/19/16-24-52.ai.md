This is patch 5/8 in Derrick Stolee's series introducing new negotiation controls for fetch/push operations. The patch adds a key interface to the negotiator subsystem that enables the upcoming `--negotiation-include` feature.

The patch introduces a new `have_sent()` callback in the fetch_negotiator interface, which will be used to inform the negotiator when commits are explicitly included via `--negotiation-include`. This allows the negotiator to avoid redundantly sending those commits (or their ancestors) while still maintaining its optimization logic. The implementation marks these commits as "common" in both the default and skipping negotiators, while the noop negotiator remains unchanged.

This is a well-contained change that cleanly extends the negotiator interface without disrupting existing behavior. The patch has already been reviewed by Matthew Cheetham and carries his Reviewed-by tag. It serves as the technical foundation for the include/restrict negotiation features that follow in the series.
