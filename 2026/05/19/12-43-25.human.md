Performance optimization for `git stash -p` that preserves cached index entries when creating the temporary index used for interactive selection. Currently, `stash -p` creates a fresh index via `git read-tree HEAD`, discarding all cached stat data and fsmonitor-valid bits. This forces a full re-check of all tracked files when the index is refreshed.

The patch changes this to create the temporary index in-process using `unpack_trees()`, which preserves valid cache entries via `oneway_merge()`. This allows fsmonitor to skip unchanged files during the subsequent refresh, dramatically improving performance in large repositories - from 34.7s to 0.6s in the reported 206k-file test case.

The change is well-motivated and appears carefully implemented, with:
- A new helper function `create_index_from_tree()` that handles the in-process index creation
- Updated test coverage verifying the behavior with unmodified files
- Clear performance measurements showing the improvement

This seems like a straightforward win for users of `stash -p` in large repositories with fsmonitor enabled. The approach mirrors how `git restore -p` already works, suggesting it's a proven optimization path.
