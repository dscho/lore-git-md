Subject: [PATCH] stash -p: avoid fsmonitor refresh on unchanged files via unpack_trees()

Core problem: `git stash -p` performs unnecessary full filesystem refreshes when starting interactive selection with fsmonitor enabled, due to shelling out to `git read-tree HEAD` which discards cached stat data and fsmonitor-valid bits.

Solution approach: Replace external `read-tree` with in-process `unpack_trees()` using `oneway_merge()` to preserve cached entries for unchanged files, allowing fsmonitor to skip them during refresh.

Key technical details:
- New `create_index_from_tree()` helper in `builtin/stash.c` implements optimized index creation
- Uses `unpack_trees_options` with `oneway_merge` callback to maintain existing index entries
- Current implementation fails if `refresh_index()` returns non-zero (unlike original behavior)
- Performance improvement demonstrated (34.774s -> 0.659s in 206k file repo with one change)
- Behavior aligns with `git restore -p`'s existing fsmonitor optimization
- Test case added in `t/t3904-stash-patch.sh` verifies unchanged files aren't refreshed
