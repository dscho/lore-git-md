Subject: [PATCH] stash -p: avoid fsmonitor refresh on unchanged files via unpack_trees()]

Core problem: `git stash -p` performs a full filesystem refresh when starting interactive selection, even with fsmonitor enabled, because it shells out to `git read-tree HEAD` to create a temporary index. This discards all cached stat data and fsmonitor-valid bits, forcing unnecessary work.

Solution: Replace the `read-tree` subprocess with an in-process `unpack_trees()` call that preserves cached entries for unchanged files via `oneway_merge()`. This allows fsmonitor to skip unchanged files during refresh.

Key technical details:
- New helper function create_index_from_tree()` in `builtin/stash.c` implements the optimized index creation
- Uses `unpack_trees_options` with `oneway_merge` callback to preserve existing index entries
- Performance improvement from 34.774s to 0.659s in a 206k file repo with one change
- Behavior matches `git restore -p`'s existing fsmonitor optimization
- Test case added in `t/t3904-stash-patch.sh` verifies unchanged files aren't refreshed
