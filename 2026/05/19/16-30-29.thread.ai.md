Thread identity: Feature patch series introducing external command support for Git notes (9 parts), authored by Siddh Raman Pant.

Core problem/goal: Enable Git to fetch notes content from a long-running external process via a defined protocol, rather than only from refs. This solves TOCTOU race conditions in large distributed repos where notes updates may not propagate quickly enough, while maintaining security constraints through protected config options.

Current status: Version 1 of the series, with patches 2/9 through 7/9 now submitted. Changes since initial submission:
- Patch 2/9: Converted `raw` parameter in notes formatting functions from `int` to `bool` (mechanical cleanup)
- Patch 3/9: Added `sleep_nanosec()` wrapper function with platform-specific implementations and proper EINTR handling
- Patch 4/9: Added `finish_command_with_timeout()` API in run-command.c with 10ms-granularity timeout checking
- Patch 5/9: Introduced timeout variants of core I/O functions
- Patch 6/9: Added baseline test coverage for existing notes display behavior
- Patch 7/9: Implemented core external notes functionality with:
  - New config options: `notes.externalCommand`, `notes.externalCommandTimeoutMs`
  - New command-line option: `--external-notes`
  - Protocol where Git sends commit OIDs to helper, receives either "missing" or note content
  - Integration with existing notes display logic
  - Windows compatibility considerations

Key technical details:
- Comprehensive timeout handling:
  - Nanosecond-precision sleeping (`sleep_nanosec`)
  - Process termination with timeout (`finish_command_with_timeout`)
  - I/O operations with deadlines (`xread_timeout`, etc.)
  - File descriptor readiness polling (`wait_for_fd`)
- Edge case handling for signals, non-blocking I/O, invalid FDs
- Implementation spans notes, run-command, wrapper, strbuf, and revision subsystems
- 500+ lines of new test coverage (across series)
- Documentation updates (range-diff man page fix, new API docs)
- Security model restricts config options to protected config
- Protocol design avoids shell interpretation of note content

Open questions/loose ends:
- No reviews or feedback yet on the approach
- Performance impact of timeout checking overhead
- Windows implementation of `sleep_nanosec()` currently returns 0 unconditionally (POSIX compliance question)
- Whether timeout API should be more generally exposed beyond notes use case
- Need to verify external notes feature maintains compatibility with baseline display behavior tested in patch 6/9
- Two remaining patches in series still to be reviewed (8/9 and 9/9)
