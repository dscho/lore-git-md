This is a performance optimization patch for `git stash -p` that improves its speed when fsmonitor is enabled. The patch changes how the temporary index is created during interactive stash selection.

Currently, `git stash -p` creates a temporary index by shelling out to `git read-tree HEAD`, which discards all cached stat data and fsmonitor-valid bits. This forces a full refresh of every tracked file when the interactive selection begins. The patch instead creates the temporary index in-process using `unpack_trees()`, which preserves cached entries for unchanged files via `oneway_merge()`. This allows fsmonitor to skip unchanged files during the subsequent refresh.

The performance impact is substantial - in a 206k file repository with one changed file, the time to first prompt drops from 34.774 seconds to 0.659 seconds when fsmonitor is enabled. The change is well-motivated by comparing to `git restore -p`'s behavior, which already benefits from fsmonitor optimizations.

The implementation:
1. Adds a new `create_index_from_tree()` helper that uses `unpack_trees()` to create an index while preserving cached entries
2. Replaces the `read-tree` subprocess call with this new function
3. Includes a test case verifying the behavior with unmodified files

The patch touches `builtin/stash.c` and adds a test in `t/t3904-stash-patch.sh`. It's a focused change that addresses a clear performance bottleneck while maintaining the existing behavior. The commit message clearly explains the problem, solution, and measured improvement.
