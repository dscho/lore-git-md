This is patch 3/16 in Taylor Blau's incremental MIDX repacking series, a performance-focused effort to improve Git's handling of large repositories. The patch refactors how the `keep_hashes` array is populated during MIDX (multi-pack-index) writing.

The change replaces a somewhat convoluted reverse-indexing approach with a clearer two-step process: first collecting MIDX layers into a temporary array, then iterating backwards through that array to fill `keep_hashes` sequentially. This makes the control flow more straightforward and prepares for a future change to use `strvec` for the array.

The patch is a pure refactoring with no behavior change - it just reorganizes the code to be more maintainable. The implementation appears solid, with proper memory allocation handling via `ALLOC_GROW` and includes an assertion to verify the final array count matches expectations. This is a typical preparatory change in a larger series, making the code more amenable to subsequent modifications while standing as a clear improvement on its own.
