This is a refactoring patch from Jeff King (Peff) that improves the type safety and clarity of Git's connection handling code. The patch addresses a confusing aspect of the `git_connect()` function where a "name" parameter was ambiguously used to specify the type of operation (like upload-pack or receive-pack) rather than the program to run.

The key changes are:
1. Replaces the string-based "name" parameter with an explicit `enum git_connect_service` that clearly defines the valid service types (UPLOAD_PACK, RECEIVE_PACK, UPLOAD_ARCHIVE)
2. Renames variables and parameters from "name" to "service" throughout the codebase for clarity
3. Maintains backward compatibility by converting the enum to the well-known string names when needed for protocol communication

The change originated from a discussion about protocol version handling a few months prior. Peff notes this is a pure refactoring with no intended behavior change - it simply makes the code more type-safe and self-documenting. The compiler will now catch invalid service types rather than silently accepting any string.

The patch touches several files across the codebase since the connection interface is widely used, but the changes are mechanical in nature - updating callers to use the new enum rather than strings. The implementation includes a `connect_service_cmd()` helper to convert the enum back to strings when needed for the remote helper protocol.
