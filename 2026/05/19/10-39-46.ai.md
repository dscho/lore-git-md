This is a follow-up discussion in Pablo Sabater's `git log --graph` visualization improvement series, now focusing on implementation details after the design decision to use cascading indentation for root commits. Chandra Pratap weighs in on the visual tradeoffs between different indentation approaches.

The implementation has settled on cascading indentation for root commits (those without parents), which:
- Indents each subsequent root commit progressively to the right
- Maintains vertical alignment only for true parent-child relationships
- Uses diagonal connection lines when needed
- Preserves the invariant that vertical alignment indicates ancestry

Chandra notes that while cascading indentation can create a "shower of commits" effect in some merge scenarios, it provides clearer visualization of merge relationships compared to alternative approaches. The discussion confirms that merge commit clarity is prioritized since they appear more frequently in typical repositories.

The technical implementation in `graph.c` now includes:
- A depth counter for managing progressive indentation of consecutive roots
- Preserved `is_placeholder` logic for excluded parents
- Unmodified diagonal connection logic for existing graph edges
- Test coverage in `t4215-log-skewed-merges.sh` to verify the behavior
