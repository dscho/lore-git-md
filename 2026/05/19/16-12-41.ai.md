This is the third patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem. The patch focuses on reusing stored bitmaps during commit traversal to avoid redundant work.

The key optimization here is teaching `fill_bitmap_commit()` to detect when it encounters an ancestor commit that already has a stored bitmap. When this happens, it can OR that existing bitmap into the current one and skip walking the commit's tree and parents. In testing, this change provides a 42% speedup (562.8s -> 324.8s) for bitmap generation in a large repository (~4.8M commits).

The patch adds counters to track how often this optimization triggers - in the test case, about 9.5% of `fill_bitmap_commit()` calls (131 out of 1,382) were able to short-circuit. The implementation is straightforward, checking for existing bitmaps in the writer's bitmap map and skipping the walk when found.

This continues the series' pattern of focused, measurable optimizations to the bitmap generation process. The change is low-risk as it only affects internal bitmap generation behavior without changing any user-facing functionality. The performance gains are substantial, particularly for large repositories where bitmap generation is expensive.
