Performance optimization in pack-bitmap-write subsystem.

This is the first patch in Taylor Blau's 8-patch series optimizing bitmap generation for large repositories. The series builds on his previous pseudo-merge bitmap work and shows significant performance gains.

This particular patch prepares for future optimizations by restructuring how `fill_bitmap_tree()` handles tree objects. The key change is reordering operations to first find a tree's bit position before loading its contents, rather than doing the lookup after loading. Surprisingly, this simple reordering yields measurable performance improvements even before the full optimization is in place.

Testing on a large repository (~4.8M commits, ~37.1M trees) shows:
- 4.9% reduction in elapsed time (612.5s -> 582.4s)
- 5% reduction in CPU cycles
- 5.1% improvement in cycles-per-instruction ratio

The patch modifies `pack-bitmap-write.c` to pass the object position into `fill_bitmap_tree()` rather than having it look up the position internally. This is a mechanical change that sets up for more significant optimizations in subsequent patches while already providing a small but measurable speedup. The commit message includes detailed performance measurements showing the benefits of this reordering.
