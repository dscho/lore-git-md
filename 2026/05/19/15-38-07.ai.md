This is the 7th patch in Christian Couder's v3 series adding URL-based auto-configuration for promisor remotes, building on the previously approved LOP (Large Object Promisors) series. The patch enables automatic creation of remote configurations when a server advertises an unknown promisor remote whose URL matches an allowlist pattern.

The key additions are:

1. New helper functions to sanitize and generate remote names from URLs, with collision handling (appending "-1", "-2" etc. if needed)
2. Auto-configuration logic that writes `remote.<name>.url`, `remote.<name>.promisor`, and `remote.<name>.advertisedAs` entries when matching an allowlisted URL
3. Integration with the existing URL matching infrastructure from earlier patches
4. Comprehensive documentation updates explaining the auto-creation behavior, name generation rules, and security implications
5. Extensive test coverage of various scenarios (new remotes, named remotes, collisions, reusing existing remotes)

The implementation touches `promisor-remote.c` (adding the new name handling and auto-configuration logic) and updates the test suite with new cases. The documentation changes clarify the interaction between this feature and existing promisor remote mechanisms.

This patch completes the URL-based auto-configuration feature alongside the previously approved LOP series, representing the final technical piece of this functionality. It has already received thorough review rounds from Patrick Steinhardt, Toon Claes and Junio C Hamano with all feedback addressed. The series is now ready for merging.
