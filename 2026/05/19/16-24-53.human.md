This is patch 6/8 in Derrick Stolee's series introducing new negotiation options for fetch/push operations. The patch adds the `--negotiation-include` option to `git fetch`, which ensures specified refs are always sent as "have" lines during negotiation, regardless of what the negotiation algorithm would normally select.

The key motivation is to prevent inefficient object transfers in monorepos with many branches. For example, if a critical release branch gets dropped from negotiation, it could trigger a full download of its parallel commit history (60+ GB in one real case). The new option complements `--negotiation-restrict` (added earlier in the series) by allowing certain refs to be guaranteed while still letting the algorithm opportunistically include others.

The implementation:
- Accepts exact ref names or glob patterns (silently ignoring non-existent refs)
- Sends the specified objects as haves before the negotiator's algorithm runs
- Uses the new `have_sent()` negotiator interface (added in patch 5/8) to avoid duplicates
- Includes thorough test coverage for various scenarios (glob patterns, duplicates, protocol versions)
- Adds passthrough support to `git pull`

The patch is well-structured with clear documentation and comprehensive tests. It builds on the series' earlier work while introducing the complementary include functionality.
