This is the second patch in Derrick Stolee's 8-part series improving fetch/push negotiation. The patch renames the existing `--negotiation-tip` option to `--negotiation-restrict` to better reflect its behavior as a maximum set of refs to consider, not a minimum set. The old name is kept as an alias for compatibility.

The change makes the option's semantics clearer in preparation for introducing the complementary `--negotiation-include` option in later patches. The patch updates documentation, warning messages, and tests to use the new name while maintaining backward compatibility. Test cases verify that both names work and can be used together.

This is a straightforward renaming patch that doesn't change functionality, just improves clarity. It's part of a well-reviewed series that addresses inefficient object transfer in large repositories by giving users more control over negotiation behavior. The patch carries a Reviewed-by from Matthew Cheetham and appears ready for inclusion.
