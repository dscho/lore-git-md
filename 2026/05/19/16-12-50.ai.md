This is the sixth patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem, focusing on reducing the size of generated bitmap files through smarter sorting.

The patch addresses a key inefficiency in how reachability bitmaps are stored - currently they can be XOR'd against nearby bitmaps (up to 10 commits away) to save space, but the selection order of commits can prevent optimal XOR pairings. By sorting the selected commits by date before computing XOR offsets, the writer can find better ancestor/descendant pairs for compression.

The results are substantial: in the test repository (with 1,261 bitmaps), this change reduces the bitmap file size from ~635MB to ~176MB (72% reduction) while maintaining the same query coverage. The generation time also decreased slightly by ~3.7 seconds, though the author notes this is likely noise.

The implementation adds a date-based comparison function and uses QSORT to order the commits before processing them for XOR offsets. Pseudo-merge bitmaps are left alone as they'll be handled separately in later patches. The change is focused entirely on the bitmap generation internals (pack-bitmap-write.c) with no user-facing impact.

This continues the series' pattern of well-motivated, data-driven optimizations that build on Taylor's deep expertise in the pack/bitmap subsystems. The patch appears straightforward and low-risk while delivering significant space savings.
