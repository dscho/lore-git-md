This is a follow-up discussion in Pablo Sabater's `git log --graph` visualization improvement series, now focusing on implementation details after the design direction was settled. Chandra Pratap weighs in on the final visual representation choices for root commits (those without parents) in the graph output.

The key points from this email:

1. The thread has moved from design debate to implementation, with consensus on using cascading indentation to visually distinguish root commits. This approach maintains clear parent-child relationships while handling independent roots.

2. Chandra agrees with keeping the cascading indentation style, noting it provides better clarity for merge commits (which are more common than root commits in typical workflows). The alternative "blank line" approach was considered but would require more invasive changes to the graphing logic.

3. The implementation will use a `is_parentless` flag in the `git_graph` struct to track root commits, allowing the rendering logic to adjust indentation appropriately without needing placeholder commits.

4. Examples show the cascading indentation produces cleaner output for merge-heavy histories compared to the "shower of commits" effect seen with other approaches. The visual distinction helps users immediately recognize when commits are not ancestrally related.

The patch appears well-considered, with the design thoroughly vetted through multiple iterations and now moving into straightforward implementation. The visual improvements address a real usability pain point in interpreting complex histories.
