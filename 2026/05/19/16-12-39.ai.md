Performance optimization in the pack-bitmap-write subsystem, part 2 of Taylor Blau's series to speed up bitmap generation for large repositories. This patch builds on the previous optimization (which passed tree positions to `fill_bitmap_tree()`) by checking subtree bits before recursing, avoiding unnecessary stack frame setup when a tree's bit position is already set.

The change moves the bitmap check from inside `fill_bitmap_tree()` to its callers, which allows skipping the function call entirely in cases where the tree is already marked. This yields measurable improvements: 3.4% reduction in elapsed time (582.4s->562.8s), 3.4% fewer CPU cycles, and 2.8% fewer instructions executed in the test repository (~4.8M commits, ~37.1M trees).

The patch modifies `pack-bitmap-write.c` to perform the bitmap check at two call sites (for trees and commits) rather than inside `fill_bitmap_tree()`. This is a focused optimization that maintains the same behavior while reducing overhead in this hot path. The change is low-risk as it doesn't affect user-visible behavior, only the internal bitmap generation performance.
