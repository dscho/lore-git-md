This is a follow-up in a thread about a `git describe` bugfix regarding pattern matching with `--contains --all`. 

Tuomas Ahola reports hitting the same issue that Jacob Keller's original patch aimed to fix - where `git describe --contains --all` silently ignores `--match` and `--exclude` patterns rather than erroring out. He confirms the unexpected behavior still exists in current Git and asks if Jacob plans to revive the patch, which was never merged.

The thread shows this remains a real-world pain point, with multiple users independently encountering the confusing behavior. While Jacob's original patch was untested, the straightforward fix (adding an explicit error for this invalid combination) appears uncontroversial based on Eric Sunshine's earlier surface-level feedback. 

This serves as a useful reminder that even small, well-motivated fixes can fall through the cracks without active shepherding. The issue persists nearly a year after the initial report, suggesting the patch may need a champion to push it through with tests added.
