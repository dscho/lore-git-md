This is patch 2/16 in Taylor Blau's v4 series on incremental MIDX repacking, which aims to improve Git's handling of large repositories through more efficient multi-pack-index management. The series has already addressed all substantive feedback and appears ready for merging.

The patch refactors how MIDX files are tracked during cleanup operations, replacing a hand-rolled array with a `strset` for storing filenames that should be preserved. This change:

1. Simplifies the code by removing manual memory management of the `keep` array and its length parameter
2. Uses the existing `strset` abstraction for string collections
3. Maintains the same functionality while making the code more maintainable

The performance impact is negligible since the number of kept MIDX files is typically small, but the change makes the code more idiomatic. The patch includes thorough updates to both `clear_midx_files_ext()` and `clear_incremental_midx_files_ext()` functions, with proper initialization and cleanup of the new `strset` structure.

This is a straightforward refactoring that follows the series' pattern of careful, incremental improvements to the MIDX infrastructure. The change is well-contained and unlikely to be controversial given the series' advanced state.
