This is part 4/8 of Derrick Stolee's series to improve fetch/push negotiation in monorepos, introducing config support for the `--negotiation-restrict` option. The patch adds `remote.<name>.negotiationRestrict` as a multi-valued config option that serves as the default for restricting which refs are advertised during negotiation.

The implementation:
- Adds config parsing in remote.c to populate a new `negotiation_restrict` string list in the remote struct
- Modifies fetch.c to use these config values when no CLI `--negotiation-restrict` is specified
- Includes proper warning when the transport protocol doesn't support negotiation restrictions
- Adds tests verifying config behavior including:
  - Multi-value accumulation
  - Empty value reset semantics
  - CLI override precedence
  - Protocol v2 compatibility

The patch maintains consistency with the CLI option's glob pattern matching and follows the established pattern for multi-valued remote config options. It's a straightforward addition that completes the configuration surface for this negotiation control, complementing the CLI option introduced earlier in the series.
