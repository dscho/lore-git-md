This is the third patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem. The patch focuses on reusing stored bitmaps during commit traversal to avoid redundant work.

The key optimization here teaches `fill_bitmap_commit()` to recognize when it encounters an ancestor commit that already has a stored bitmap (from being selected earlier in the process). When this happens, it can OR in the existing bitmap and skip walking that commit's tree and parents. In testing, this change provides a 42% speedup (562.8s -> 324.8s) for bitmap generation in a large test repository (~4.8M commits).

The patch adds instrumentation to track how often this optimization triggers - in the test case, about 9.5% of calls to `fill_bitmap_commit()` can be short-circuited. The implementation is straightforward, checking for existing bitmaps in the writer's bitmap hashmap and skipping the walk when found.

This continues the series' pattern of focused, measurable optimizations to the pack bitmap generation code. The changes are internal to the bitmap writing process and don't affect user-facing behavior. Given Taylor's expertise in this area and the clear performance wins demonstrated, this appears to be a solid incremental improvement.
