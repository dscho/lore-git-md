This thread addresses a memory leak in HTTP pack index handling, specifically in `fetch_and_setup_pack_index()`, where verification failures were skipping cleanup of both the pack index and the `new_pack` structure. Lorenzo Pegorari's initial patch fixed this by ensuring proper cleanup in error paths while leaving the success path unchanged.

Jeff King (Peff) has now up with additional observations about tempfile cleanup behavior. While confirming the original fix correctly addresses the memory leak, he points out an inconsistency in how tempfiles are handled—they're unlinked on parse failure but not verification failure, possibly a legacy from before tempfile registration was introduced. Peff suggests two potential improvements: either relying entirely on process-exit cleanup (removing the manual unlink) or extending the cleanup to verification failures. He also raises the possibility of returning the tempfile struct from `fetch_pack_index()` to use the proper `delete_tempfile()` API.

The discussion continues to focus on proper resource cleanup in HTTP pack handling, with Peff's thorough analysis highlighting both the immediate issue and related cleanup opportunities. While the original memory leak fix stands as correct, this may lead to additional cleanup patches addressing the tempfile handling inconsistencies.
