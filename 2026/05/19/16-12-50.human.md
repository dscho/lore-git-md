This is the sixth patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem. The patch focuses on reducing the on-disk size of bitmap files by improving how they're compressed.

The key change is sorting selected commits by date before computing XOR offsets between bitmaps. Currently, the bitmap writer may miss good compression opportunities when commits are provided in arbitrary order. By sorting commits chronologically first, the patch achieves a dramatic 72% reduction in bitmap size (from 635MB to 176MB) in the test repository, with negligible impact on generation time.

The implementation adds a date-based comparison function and uses Git's QSORT to order commits before the XOR compression pass. The change is focused entirely on the bitmap generation internals (pack-bitmap-write.c) and maintains all existing behavior - it just produces more efficiently compressed output.

This continues the series' pattern of well-motivated, data-driven optimizations that build on Taylor's deep knowledge of the bitmap subsystem. The substantial space savings make this particularly valuable for large repositories where bitmap size can be a concern.
