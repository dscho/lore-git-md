This is patch 7/8 in Derrick Stolee's series introducing configurable negotiation controls for fetch/push operations. The patch adds `remote.<name>.negotiationInclude` as a config counterpart to the `--negotiation-include` command-line option introduced earlier in the series.

The config option works similarly to the existing `remote.<name>.negotiationRestrict` - it provides default values for the include list when the CLI option isn't specified. Values can be exact refs or glob patterns, and an empty value resets the list (useful for ignoring system/global configs). The implementation mirrors the CLI behavior where included refs are additive to the normal negotiation process.

The patch includes thorough test coverage of key scenarios:
- Basic config usage as default when CLI option isn't specified
- Glob pattern matching behavior
- CLI option overriding the config values
- Empty value reset semantics

This is a straightforward addition that completes the pattern established by the restrict config, providing users with persistent configuration for the include feature. The implementation is clean and well-tested, with Matthew Cheetham's Reviewed-by indicating it has been thoroughly vetted. As part of the final iteration of this series, it's ready for integration.
