This is version 11 of Harald Nordgren's feature patch adding a `--track=fetch` option to `git checkout` and `git switch`. The feature automatically fetches from the remote when creating a tracking branch, eliminating the need for a separate `git fetch` step.

**Key changes in v11.** This version addresses Junio C Hamano's feedback from v10 by completely rewriting the remote name resolution logic. The new implementation properly handles custom refspec mappings (like fetching into `refs/remotes/upstream/*` from `origin`) and follows `<remote>/HEAD` when given a bare remote name. The test suite has been expanded with new cases covering these scenarios.

**Implementation details.** The core of the change is in `resolve_fetch_target()`, which now uses a callback-based approach to find the correct fetch mapping rather than assuming the remote name matches the start of the refspec. The patch also adds proper test coverage for hierarchical remote names and custom refspec configurations.

**Assessment.** This appears to be a well-considered response to the v10 feedback, with thorough test coverage (now 16 test cases) and careful handling of edge cases. The feature has been through 11 iterations and seems technically sound at this point. The remaining path to inclusion likely depends on maintainer approval rather than any outstanding technical issues.
