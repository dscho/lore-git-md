Performance optimization in the pack-bitmap subsystem, part 1/8 of Taylor Blau's series to speed up bitmap generation for large repositories. This first patch prepares for future optimizations by restructuring how `fill_bitmap_tree()` handles tree objects, requiring callers to pass in the tree's bit position rather than having the function look it up internally.

The change provides an immediate 4.9% speedup (612.5s to 582.4s) in bitmap generation for a large test repository (~4.8M commits, ~37.1M trees), with CPU cycles dropping by 5%. The improvement comes from reordering operations to first find the tree's bit position before loading the tree object, which appears to help with CPU cache/pipeline efficiency. The patch is cleanly focused on internal bitmap generation logic and shows measurable benefits even as a preparatory change. Given Taylor's expertise in this area and the clear performance data, this looks like a solid foundation for the rest of the optimization series.
