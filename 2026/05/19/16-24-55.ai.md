This is the final patch in Derrick Stolee's series introducing negotiation controls for fetch/push operations. The patch completes the push integration by passing the `--negotiation-include` and `--negotiation-restrict` configurations from the transport layer to the underlying `git fetch --negotiate-only` process that powers push negotiation.

Key technical details:
- Extends `send_pack_args` struct to carry negotiation configs from transport
- Modifies `get_commons_through_negotiation()` to handle both include and restrict lists
- Adds comprehensive tests verifying config-based negotiation during push
- Updates remote.adoc documentation to clarify push integration

The implementation ensures that when `push.negotiate` is enabled, the configured `negotiationInclude` and `negotiationRestrict` values are properly passed through to the negotiation process, maintaining the same behavior as direct fetch operations. The tests demonstrate this by pushing to repositories with hidden refs, showing the negotiation controls successfully limit the object transfer.

This patch represents the series' completion after thorough review, with all feedback addressed in previous iterations. It provides the final piece needed for consistent negotiation control across both fetch and push operations in monorepo scenarios.
