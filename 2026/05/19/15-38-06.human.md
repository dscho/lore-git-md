This is part 6/8 of Christian Couder's v3 series adding URL-based auto-configuration for promisor remotes, building on previous work to enhance Git's promisor remote functionality. The series is now technically complete and ready for merging.

The patch introduces a security mechanism that allows known remotes to be trusted for field updates (like authentication tokens) when their URLs match patterns in the new `promisor.acceptFromServerUrl` config. This works even when the stricter `promisor.acceptFromServer=none` is set, providing a way to selectively allow updates from trusted sources while maintaining security.

Key technical aspects:
- URL patterns are matched component-wise (exact scheme/port, wildmatch for host/path)
- Normalization prevents bypass attempts via case/encoding/path tricks
- Precedence rules clearly documented (URL patterns override base acceptFromServer setting)
- Security constraints prevent URL hijacking of existing remotes
- Comprehensive tests verify the matching behavior

The implementation adds a new `url_matches_accept_list()` helper and updates the core acceptance logic in `promisor-remote.c`, while documenting the feature and its security implications. This represents a significant usability improvement for organizations that want to securely manage promisor remote configurations at scale.

The patch has already received thorough review from Patrick Steinhardt, Toon Claes and Junio C Hamano, with all feedback addressed. It's part of a coordinated effort with the previously approved LOP (Large Object Promisors) series to enhance promisor remote functionality.
