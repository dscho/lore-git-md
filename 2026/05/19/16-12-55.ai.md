This is the final patch in Taylor Blau's performance optimization series targeting the pack-bitmap-write subsystem. The series focuses on speeding up bitmap generation for large repositories, with this particular patch addressing inefficiencies in pseudo-merge bitmap handling.

The key change is restructuring how pseudo-merges are built - rather than mixing them with regular commits during bitmap generation (which caused significant slowdowns), they are now processed in a separate pass after regular bitmaps are complete. This provides substantial performance improvements:

- Reduces pseudo-merge bitmap generation time from 575s to 328.4s (43% faster)
- Maintains the same on-disk format and query performance benefits
- Preserves the ability to reuse existing pseudo-merge bitmaps
- Adds proper handling for commits only reachable via pseudo-merges

The implementation involves:
1. Excluding pseudo-merges from the initial bitmap_builder_init()
2. Adding new build_pseudo_merge_bitmaps() function for the second pass
3. Teaching fill_bitmap_commit() to handle unparsed commits from pseudo-merges
4. Maintaining all existing bitmap reuse and parent tracking

The patch includes detailed performance measurements showing the optimization brings pseudo-merge overhead down to just 11.7% compared to no pseudo-merges, while still providing the same 20x speedup during traversal. The changes are focused entirely on the bitmap generation internals with no user-facing impact.

This completes the series' goal of significantly improving bitmap generation performance while maintaining all existing functionality. The changes demonstrate Taylor's deep expertise in the pack/bitmap subsystems and provide measurable benefits for large repositories using pseudo-merges.
