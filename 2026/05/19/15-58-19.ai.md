This is patch 14/16 in Taylor Blau's incremental MIDX repacking series, implementing the core functionality for incremental MIDX chain maintenance during geometric repacking.

The patch introduces `write_midx_incremental()`, which builds and maintains an incremental MIDX chain by:

1. Always writing a new MIDX layer containing newly created packs and any surviving packs from the previous tip layer if it was rewritten
2. Merging adjacent MIDX layers when the accumulated object count exceeds half the next deeper layer's objects (controlled by `repack.midxSplitFactor`)
3. Evaluating remaining layers pairwise to compact or copy them
4. Atomically moving the new chain into place

The implementation uses a new `midx_compaction_step` struct to represent each operation (write, compact, or copy) and executes them in sequence with `--no-write-chain-file` to avoid partial updates. The final chain file is written atomically after all steps complete.

Key technical details:
- New configuration knobs with defaults: `repack.midxSplitFactor` (2) and `repack.midxNewLayerThreshold` (8)
- Lockfile protection for the multi-pack-index-chain file
- Comprehensive trace2 instrumentation for debugging
- Handles both rewritten and unmodified packs from previous MIDX layers
- Preserves preferred pack selection during compaction

This is the main implementation patch that enables the incremental MIDX strategy described in earlier patches. The functionality isn't yet exposed to users - that comes in a later patch. The implementation appears thorough, with careful attention to atomicity and error handling.
