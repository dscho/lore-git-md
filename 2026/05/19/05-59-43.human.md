This is the final implementation decision in Pablo Sabater's series improving `git log --graph` visualization for root commits (those without parents). The thread had debated two approaches for displaying these commits: fixed indentation (all root commits aligned at same level) versus cascading indentation (each root commit indents further right).

Junio Hamano weighed in strongly favoring cascading indentation, as it preserves the critical invariant that vertical alignment always indicates true parent-child relationships. Pablo confirms this approach avoids ambiguity - when commits are vertically aligned without indentation, they must be related, while indented commits are clearly marked as independent roots.

The implementation will track a depth counter to determine indentation levels, with special handling when no further commits need rendering below. While multiple consecutive root commits are rare, the cascading approach provides clear visual semantics. This concludes the design discussion, with the series now ready for final implementation following Junio's guidance.
