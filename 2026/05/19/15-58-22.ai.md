This is patch 15/16 in Taylor Blau's incremental MIDX repacking series, introducing the `--write-midx=incremental` option for `git repack`. The patch exposes the incremental MIDX repacking mode that was implemented in earlier patches, allowing users to maintain incrementally growing and shrinking MIDX chains.

Key technical additions:
- Adds "incremental" as a recognized argument to `--write-midx`
- Introduces two new configuration options to control compaction behavior:
  - `repack.midxSplitFactor` (default 2) - geometric merging condition for MIDX layers
  - `repack.midxNewLayerThreshold` (default 8) - minimum packs in tip layer before considering for repacking
- Extends the test suite with comprehensive coverage of the new mode, including:
  - Layer threshold behavior
  - Geometric rollup scenarios
  - Compaction of older layers
  - Handling of kept packs
  - Edge cases and error conditions

The implementation builds on the MIDX chain maintenance infrastructure from previous patches, adding the user-facing interface and configuration options. The test suite verifies the behavior across various scenarios including multi-layer compaction, threshold-based behavior, and pack preservation.

This represents the final user-visible piece of the incremental MIDX repacking functionality, completing the series' goal of improving Git's scalability for large repositories through incremental MIDX maintenance. The series has received only minor surface-level feedback so far, suggesting the design is sound and implementation thorough.
