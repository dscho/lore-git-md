This is the fifth patch in Taylor Blau's performance optimization series for the pack-bitmap-write subsystem. It introduces an object position cache to speed up bitmap generation in large repositories.

The patch adds a direct-mapped cache that stores mappings from object IDs to their bit positions, sized dynamically based on repository size (with bounds of 1K-2M entries). The cache reduces redundant packlist and MIDX lookups during bitmap generation, providing a 9.4% speedup (from 324.8s to 294.1s) in the test repository (~57M objects). The implementation includes:

1. A 40-byte cache entry struct holding an OID and position
2. Cache initialization and sizing logic
3. Lookup/store operations with hit/miss tracking
4. Integration with the existing `find_object_pos()` function
5. Trace2 metrics for cache performance monitoring

The cache shows good effectiveness in the test case, with 1.024B hits vs 59.957M misses when operating at its maximum size of 80MB. This continues the series' pattern of targeted optimizations to the bitmap generation hot paths, building on the previous commits that reduced tree recursion and reused computed bitmaps.
