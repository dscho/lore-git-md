This is a documentation patch follow-up from Jean-Noël Avila in the ongoing man page standardization effort, responding to Junio C Hamano's review of the git-bisect.adoc conversion.

The discussion centers on the scope of the [synopsis] formatting - while Junio expected it to be limited to formal SYNOPSIS sections, Jean-Noël explains it was already being used more broadly in diff-generate-patch.adoc to format any model syntax containing <placeholders>. He acknowledges the '$' prompt in examples was an error that will be fixed, but defends using [synopsis] for in-body command syntax examples (like "git bisect old [<rev>]") since they contain the same placeholder notation as the SYNOPSIS section.

The exchange reveals a need to clarify the documentation style guidelines - whether [synopsis] should be strictly for SYNOPSIS sections or can extend to other syntax examples. Jean-Noël suggests the "synopsis style" name may be reconsidered if the formatting is broader than originally intended. This is a substantive discussion about documentation conventions that will affect how hundreds of man pages are formatted going forward.
