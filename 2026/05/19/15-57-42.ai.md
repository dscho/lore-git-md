This is patch 2/16 in Taylor Blau's v4 series on incremental MIDX repacking, which refactors how MIDX files are tracked during cleanup operations. The patch replaces hand-rolled string arrays with a `strset` for tracking which MIDX files to retain when pruning stale ones.

The change affects two functions that clear MIDX files: `clear_midx_files_ext()` and `clear_incremental_midx_files_ext()`. Previously, these used arrays to store filenames to keep, requiring manual memory management and linear lookups. The new version uses Git's `strset` type, which simplifies the code by handling memory automatically and providing constant-time lookups (though the performance impact is negligible given the small typical size of these sets).

The implementation is straightforward - it initializes a `strset`, adds filenames to it via `strbuf` formatting, and uses `strset_contains()` for lookups. The cleanup is also simpler since `strset_clear()` handles all the freeing automatically. This is a clean refactoring that improves code structure without changing behavior, fitting well with the series' focus on MIDX maintenance infrastructure.

As part of the larger incremental MIDX repacking effort, this change helps maintain the integrity of MIDX chains by ensuring proper cleanup of stale files. The patch has no outstanding review concerns and appears ready for inclusion.
