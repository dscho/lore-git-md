This is a follow-up in the thread about `git describe`'s handling of `--contains --all` with pattern matching options.

Tuomas Ahola reports hitting the same issue that Jacob Keller's original patch aimed to fix - where `git describe --contains --all` silently ignores `--match` and `--exclude` patterns rather than erroring out. He confirms the unexpected behavior still exists in current Git, showing that both `--match=bogus` and `--exclude="*"` have no effect when combined with `--contains --all`.

The email serves as a gentle nudge to revive Jacob's patch from earlier in the thread, which would make this invalid combination fail with an error rather than silently ignoring the patterns. Tuomas provides reproduction steps showing the problem persists, indicating this remains a live issue worth addressing.

This adds real-world validation to the original bug report - another user independently encountered the same confusing behavior, suggesting the fix would have practical value beyond just theoretical correctness.
