This is a performance optimization discussion continuing the work on using priority queues in revision walking. Jeff King (Peff) responds to Kristofer Karlsson's comparison of their two approaches for extending the queue-based optimizations beyond the recently merged `limit_list()` changes.

Jeff acknowledges Kristofer's architectural approach of keeping a linked list for setup while adding a separate priority queue for walking, but expresses concern about code that might need to interact with the commit list during traversal. He notes this would require awareness of whether to use the queue or list.

The discussion focuses on tradeoffs between Kristofer's more incremental approach (touching 4 files) versus Jeff's comprehensive conversion (12 files). Jeff examines Kristofer's proposed vtable-based walk strategy system, remaining undecided on whether it simplifies or obscures the logic. He suggests a possible middle ground for `limit_list()` that could avoid queue rebuilds while maintaining simplicity.

Benchmarks show both approaches deliver 3-5x speedups in a 2.4M-commit monorepo, with Kristofer's showing a slight 4% edge in limited walks. Jeff identifies potential complications in functions like `cherry_pick_list()` that consume intermediate lists, where order preservation might matter. The exchange represents a thoughtful technical debate between two strong contributors about how to best evolve this performance-critical code path while balancing maintainability and correctness.
