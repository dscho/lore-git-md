This is the final version (v3) of Christian Couder's feature patch series that enhances Git's promisor remote functionality with URL-based auto-configuration. The series builds on previous work around Large Object Promisors (LOP) and has undergone thorough review.

The key addition is a new `promisor.acceptFromServerUrl` config option that allows clients to automatically configure promisor remotes based on URL patterns, rather than requiring manual pre-configuration. This is particularly useful for organizations that want to allow trusted servers to advertise promisor remotes.

The implementation includes robust security measures:
- URL patterns support globs (`*`) with strict matching rules
- Auto-generated remote names use a `promisor-auto-` prefix with sanitization
- Collision handling prevents remote name hijacking
- Comprehensive documentation of security considerations

The series has been rebased on master and incorporates all feedback from reviewers (Toon Claes, Patrick Steinhardt, and Junio C Hamano). Notable changes in v3 include:
- Removal of WM_PATHNAME flag from host matching
- Simplified wildmatch() logic
- Clearer documentation about configuration precedence
- Explicit documentation about ignoring username/password components

All CI tests pass, and the series appears technically complete and ready for merging. This represents a significant usability improvement for promisor remote workflows while maintaining strong security defaults. The ability to auto-configure remotes based on URL patterns should reduce configuration overhead in organizational settings.
