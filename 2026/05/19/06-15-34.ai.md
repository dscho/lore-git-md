This is a bugfix patch from Jeff King (Peff) addressing an edge case in Git's commit-graph handling. The issue occurs when lazy-loading tree objects from commit-graphs interacts poorly with `git clone --dissociate`. Peff's solution adds a fallback path that reads the commit object directly from disk when graph-based lookup fails, parsing just enough to find the tree OID.

The patch has evolved through review feedback from Junio C Hamano, who raised two substantive technical points: (1) suggested reusing `parse_commit_buffer()` logic rather than duplicating tree-parsing code, and (2) identified a potential hash algorithm handling issue. Peff has incorporated the second point by switching to `parse_oid_hex_algop()` to properly respect repository-specific hash algorithms (important for SHA-256 repos), but explains why sharing more parsing logic would introduce complexity.

The fix includes a robust test case that reproduces the failure scenario where `git clone --dissociate` would previously fail to check out the working tree after closing the object database. The solution is carefully considered against alternative approaches, with Peff explaining why directly loading the tree from disk on demand is more robust than pre-loading all trees at graph-close time.

This continues the high-quality technical discussion between two of Git's most experienced contributors, with the patch now addressing both the original bug and the maintainer's correctness concerns while maintaining its original purpose of fixing the clone/dissociate edge case.
