This is the fifth patch in Christian Couder's v3 series adding URL-based auto-configuration for promisor remotes. The patch introduces the core infrastructure for `promisor.acceptFromServerUrl` configuration.

The patch adds:
- A new `struct allowed_url` to store parsed URL patterns and optional remote name prefixes
- Validation functions to check URL patterns and remote name formats
- Configuration loading via `load_accept_from_server_url()`
- Initial test cases for invalid configurations

Key technical details:
- URL patterns can include globs (`*`) with strict validation
- Optional remote name prefixes (before `=`) are validated using existing remote name rules
- Invalid configurations emit warnings but don't fail the operation
- The infrastructure is wired into the existing promisor remote filtering logic

The implementation builds on Git's existing `urlmatch` infrastructure while adding new pattern-specific handling. The test demonstrates rejection of invalid remote names in the configuration.

This is a foundational patch that sets up the configuration parsing needed for the actual URL matching and remote creation that will follow in subsequent patches. The code follows Git's established patterns for configuration handling and error reporting.
