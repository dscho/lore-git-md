This is part 4/8 of Derrick Stolee's series to improve fetch/push negotiation in monorepos, now in its final form after review. The patch adds config support for the `--negotiation-restrict` option introduced earlier in the series.

The change allows setting default negotiation restrictions via `remote.<name>.negotiationRestrict` config, which behaves like the CLI option - restricting which refs are advertised as "have" lines during negotiation. The config is multi-valued, supports glob patterns, and can be overridden by CLI flags. An empty value resets the list, allowing config hierarchy management.

Key implementation details:
- Adds new config option to remote.* namespace with thorough documentation
- Integrates with existing transport infrastructure
- Maintains CLI override behavior (any CLI use ignores config)
- Includes comprehensive tests for config and CLI interaction

The patch carries Matthew Cheetham's Reviewed-by and fits cleanly into the series' architecture. It's a well-contained addition that completes the configuration story for negotiation restrictions, following the pattern established by earlier patches. The test coverage is particularly thorough, verifying both basic usage and edge cases like empty-value resets.
