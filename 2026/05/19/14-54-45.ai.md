Bugfix for a memory leak in the HTTP pack index handling code.

The patch fixes a case where `fetch_and_setup_pack_index()` would fail to clean up a pack index structure when verification fails. The issue occurs when `verify_pack_index()` returns an error - the code skips both closing the pack index (via `close_pack_index()`) and freeing the `new_pack` structure. The fix ensures these cleanup steps happen regardless of verification success.

The change is straightforward: moves `close_pack_index()` before the error check and adds the missing `free(new_pack)` in the error path. The diff shows this affects only the error handling flow - the success path remains unchanged. This appears to be a well-scoped fix for a clear resource leak, though the commit message could be slightly more specific about which functions perform the mmap operations mentioned.
