This is patch 14/16 in Taylor Blau's incremental MIDX repacking series, implementing the core functionality for maintaining an incremental MIDX chain during geometric repacking.

The patch introduces `write_midx_incremental()`, which builds and maintains MIDX layers in a way that preserves the geometric repacking strategy. Key aspects:

- New MIDX layers are written containing newly created packs and any surviving packs from rewritten layers
- Adjacent layers are merged when their combined object count exceeds half the next layer's count (controlled by `repack.midxSplitFactor`)
- The process uses `--no-write-chain-file` for atomic assembly of the new chain
- Locking ensures safe concurrent operations
- Comprehensive trace2 instrumentation is added for debugging

The implementation handles several edge cases:
- Preserving preferred packs during compaction
- Properly tracking object counts to avoid overflow
- Maintaining the chain structure when tip layers are rewritten
- Configurable thresholds for layer splitting and new layer creation

This is a mechanical but complex part of the series, building on the infrastructure added in earlier patches. The implementation appears thorough, with careful attention to memory management and error handling. Test coverage was added in previous patches of the series.

The patch maintains the series' focus on improving scalability for large repositories by keeping MIDX chains compact while preserving fast object lookup performance. It completes the core functionality needed for the `--write-midx=incremental` mode that will be exposed to users in a later patch.
