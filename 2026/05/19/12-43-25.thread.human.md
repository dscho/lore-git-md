Currently, the command creates a temporary index by shelling out to `git read-tree HEAD`, which discards all cached file status information and forces a full refresh of every tracked file. The patch replaces this with an in-process approach using `unpack_trees()` that preserves cached entries for unchanged files, allowing fsmonitor to skip them during refresh.

The change aligns `stash -p`'s behavior with `git restore -p`, which already benefits from fsmonitor optimizations. The implementation is cleanly contained to `builtin/stash.c` and includes a test case verifying the improved behavior with unmodified files. This appears to be a well-motivated optimization that addresses a clear performance bottleneck without changing user-visible behavior.
