This patch series optimizes `git stash -p` to avoid unnecessary filesystem refreshes when fsmonitor is enabled. The current implementation shells out to `git read-tree HEAD`, which discards cached stat data and forces a full refresh of all tracked files. The new version replaces this with an in-process `unpack_trees()` call that preserves cached entries for unchanged files, allowing fsmonitor to skip them.

Performance improvements are dramatic - in a 206k file repository with one change, time to first prompt drops from 35 seconds to under 1 second. The v2 patch addresses all feedback from Junio Hamano, maintaining the original lenient error handling while keeping the optimization. A new performance test demonstrates the speedup. With the review concerns resolved and clear benefits shown, this appears ready for merging. The change is well-contained in `builtin/stash.c` and builds on Paul Tarjan's fsmonitor work.
