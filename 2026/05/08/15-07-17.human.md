Performance optimization for `git merge-base` in large repositories.

Kristofer Karlsson from Spotify contributes a patch that significantly speeds up `git merge-base` (without `--all`) when generation numbers are available in the commit-graph. The key insight is that when only one merge base is needed, we can exit early once we find the first valid merge base in generation order, skipping the expensive STALE commit traversal that would otherwise dominate runtime.

The patch adds a `find_all` parameter to thread through the merge-base calculation machinery, allowing the early exit when only one result is needed. Performance improvements are dramatic - from ~5000ms to ~50ms in a 2.2M-commit monorepo. The change comes with extensive test coverage verifying the optimization works across different commit-graph configurations and maintains correctness.

This appears to be a well-motivated optimization targeting a clear performance bottleneck in large repositories. The patch is cleanly implemented with thorough testing and documentation. The RFC note suggests the author is open to feedback, but the technical approach seems sound.
