This is a usability improvement for the `git-jump` contrib script, which helps navigate to interesting code locations in an editor. The patch makes the script more convenient by automatically selecting the most likely mode when run without arguments.

Currently, `git jump` with no arguments shows usage and exits. The patch adds smart detection to choose between:
1. `git jump merge` if there are unmerged paths in the index
2. `git jump diff` if there are unstaged changes in the working tree
3. Falls back to showing usage if neither condition applies

The change is well-contained, touching only the script and its README. The implementation checks the worktree status using standard Git plumbing commands (`git ls-files -u` for unmerged files and `git diff --quiet` for unstaged changes). This matches the script's existing behavior of using Git's porcelain for its operations.

The patch comes with a clear commit message explaining the motivation and behavior, and includes corresponding documentation updates. As a quality-of-life improvement for an existing tool, it seems unlikely to be controversial. The change is small and focused, with no apparent downsides or compatibility concerns.
