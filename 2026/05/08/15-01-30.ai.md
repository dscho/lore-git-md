This is a documentation patch series (v2) from Kristoffer Haugsbakk that finalizes improvements to the git-interpret-trailers man page. The series has already gone through review and iteration, with all feedback addressed - this email is just adding Ben Knoble to the CC list for the final version that was previously sent.

The 9-patch series systematically documents git-interpret-trailers' behavior regarding trailer key formats (ASCII alphanumeric + hyphen only), trailer block parsing rules, and comment handling. It removes outdated RFC 822 references, standardizes terminology ("metadata", "trailer block"), and adds concrete examples showing both valid usage and failure cases (like keys containing periods).

The series is merge-ready, having incorporated all maintainer feedback from Junio Hamano and Ben Knoble. Key improvements include:
- Clear documentation of the strict key format requirements
- Standardized "blank line" terminology
- Examples demonstrating complete block rejection when format rules are violated
- Note about core.commentString line handling
- Better pedagogical flow with concepts defined upfront

This concludes the documentation effort that originated from a bug report about period-containing keys being rejected. The series makes the parser's intentionally strict behavior explicit while improving usability through clearer documentation.
