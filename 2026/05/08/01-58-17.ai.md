Bugfix for the rebase machinery's `--update-refs` feature, addressing an edge case when `rebase.instructionFormat` includes `%`d decorations. This v2 patch incorporates Phillip Wood's review feedback to simplify the test case.

The core issue remains the same: when `rebase.instructionFormat` shows all ref decorations (`%d`), the rebase machinery could incorrectly generate `update-ref` instructions for non-branch refs like HEAD. The fix filters decorations to only process `DECORATION_REF_LOCAL` types, preventing invalid instructions while maintaining correct behavior for branch updates.

Key changes in v2:
- Simplified test case as suggested by Phillip Wood, removing redundant branch checks
- Now verifies the complete `update-ref` list rather than individual grep patterns
- Maintains the same focused fix in sequencer.c while making the test more robust

The patch remains small and well-contained, with a clear commit message explaining both the problem and solution. The test case now provides cleaner verification that non-branch refs are properly ignored while legitimate branch updates still work. This appears ready for inclusion as a straightforward correctness fix for the relatively new `--update-refs` feature.
