Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the seventh iteration of Harald Nordgren's proposal to streamline the workflow of fetching before creating a tracking branch. The patch has evolved significantly in response to technical feedback, though the maintainer's philosophical objections remain unresolved.

Key technical improvements in v7:
1. Rejects invalid mode combinations (`inherit,direct`) that were previously allowed
2. Implements "last one wins" behavior for multiple `--track` flags
3. Converts fetch failures to warnings when an existing ref exists, only aborting when no ref is available
4. Respects configured remote fetch refspecs when resolving refs
5. For bare remote names (e.g. `origin`), fetches only the remote's default branch rather than everything
6. Adds comprehensive tests covering all these edge cases

The implementation now includes:
- A new `resolve_fetch_target()` helper that properly handles refspec resolution
- More robust error handling in `fetch_remote_for_start_point()`
- Updated documentation clarifying the refined behavior
- 12 new test cases verifying the various scenarios

While the technical execution is thorough, the patch still doesn't address the maintainer's core workflow concerns from earlier rounds. The author appears to be focusing on making the implementation as robust as possible in hopes that technical polish might overcome the philosophical objections. The parallel `--autostash` work mentioned in the thread context remains unsubmitted.

This remains a well-crafted feature addition that would provide concrete workflow improvements, but its acceptance likely depends on whether the maintainer can be convinced to reconsider the earlier objections based on the improved implementation.
