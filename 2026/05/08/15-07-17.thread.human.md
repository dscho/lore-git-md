This thread discusses a performance optimization for `git merge-base` that provides dramatic speedup (100x in some cases) when calculating a single merge base in large repositories. The patch series, now at v4, modifies `paint_down_to_common()` to exit early when generation numbers are available and only one merge-base is needed (the common case without `--all`).

The optimization was split into two commits per Patrick Steinhardt's suggestion - first a pure refactoring to introduce an `enum merge_base_flags`, then the actual optimization logic. All substantive feedback from Junio Hamano and Patrick has been addressed across the iterations, with v4 focusing on API improvements and better commit organization. The patches demonstrate thorough test coverage and maintain correctness while delivering significant performance benefits, particularly for monorepos with deep histories.

The series appears merge-ready with no outstanding objections. The optimization builds on existing generation number infrastructure and complements other performance work in commit-reach.c, providing immediate value for a common operation in large codebases. Both the original author and reviewers have been engaged throughout the process, resulting in a technically sound solution that follows Git's conventions.
