This is the first patch in Johannes Schindelin's v3 series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch specifically targets truncation issues in index-pack and unpack-objects caused by 32-bit `unsigned long` types on Windows.

The key changes in this version:
- Changes the object size variable to `size_t` (64-bit on 64-bit platforms)
- Makes the per-byte continuation variable `c` also `size_t` to match Git's canonical varint decoder
- Adds overflow guards when shifting would exceed platform limits
- Improves error messaging to clarify when an object size exceeds platform capabilities rather than implying malformed input

The patch responds to Torsten Bögershausen's review feedback from v2 by making the type changes more precise and adding the overflow checks. This is a foundational change for the series, fixing one of the critical paths where large objects get corrupted during cloning on Windows.

The changes appear well-considered and focused, with clear attention to type safety and platform compatibility. The patch maintains the same test infrastructure improvements from v2 (unsafe SHA-1 hashing mode, precomputed test packs) while addressing the specific review feedback about type handling.
