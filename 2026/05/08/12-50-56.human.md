This is the first patch in a platform compatibility series from Johannes Schindelin, removing the obsolete nedmalloc allocator from Git's Windows builds. The change is motivated by GCC 16 compatibility issues that cause build failures due to new compiler warnings on unused variables in the unmaintained nedmalloc code.

The patch disables nedmalloc usage across all build systems (Make, CMake, and Meson) while maintaining the same technical approach as previous versions. Since Git for Windows already switched to mimalloc years ago with no performance advantage over platform allocators, this represents the logical next step in deprecating nedmalloc.

The commit message provides thorough context, including:
- Historical background on nedmalloc's unmaintained status
- Specific GCC 16 build failure details
- Evidence that the platform allocator works fine as a replacement
- Links to relevant CI failures and SDK updates

This is a well-justified change that cleans up technical debt while solving an immediate build problem. The patch appears mechanically sound and follows the series' structured approach of first disabling usage before removing the code in subsequent patches. No technical concerns remain - the only outstanding question is about integration mechanics (squashing vs direct pull) for the later deletion patches.
