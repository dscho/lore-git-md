This is a documentation patch from D. Ben Knoble that corrects the gitignore(5) man page to accurately reflect where per-repository ignore patterns are stored. The patch follows up on his earlier proposal for per-worktree ignore patterns, which received mixed feedback from reviewers including Phillip Wood and Junio C Hamano.

The key change fixes the documentation inaccuracy that claimed ignore patterns were read from `$GIT_DIR/info/exclude` when in fact they come from `$GIT_COMMON_DIR/info/exclude`. This matters because in a worktree setup, `$GIT_DIR` points to the worktree-specific metadata while `$GIT_COMMON_DIR` points to the main repository's metadata. The patch updates both the synopsis and description sections of the man page.

The v2 notes explain that the author is scaling back from his original per-worktree ignore feature proposal due to maintainer skepticism about the use case and suggestions that a more general solution for worktree-specific files would be preferable. He provides one concrete use case involving LLM tooling but acknowledges the feedback indicates this may not justify the complexity.

This is a straightforward documentation correction that improves accuracy without changing behavior. The patch is minimal and well-contained, addressing only the immediate discrepancy while leaving the larger per-worktree ignore discussion for potential future work.
