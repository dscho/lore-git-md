This is a platform compatibility patch series from Johannes Schindelin, finalizing the removal of the unmaintained nedmalloc allocator from Git's Windows (MINGW) builds. The v3 iteration incorporates maintainer feedback on integration mechanics while maintaining the core technical approach.

The series addresses GCC 16 compatibility issues by fully removing the vendored nedmalloc code that fails to build with new compiler warnings. Since Git for Windows already switched to mimalloc years ago (with benchmarks showing no significant advantage over platform allocators), the series takes the opportunity to completely excise nedmalloc rather than just disable it.

Key changes in v3:
- Reworded the last 4 patches as recommended by Junio to clearly indicate they should be squashed during integration
- Maintains the same technical content as v2, which:
  - First disables nedmalloc usage (patch 1)
  - Removes build system references (patch 2)
  - Deletes auxiliary files (patch 3)
  - Splits the large malloc.c.h deletion across patches 4-6 due to mailing list size limits

The patch structure demonstrates thoughtful handling of technical constraints while following natural dependency order. The commit messages provide clear rationale and the changes appear mechanically sound. This represents the logical conclusion of the nedmalloc deprecation path that began with Git for Windows' earlier switch to mimalloc.

The only remaining question is integration mechanics - whether to squash the split deletion patches (as the commit messages now explicitly request) or use a direct repository pull for the large file deletion. No technical concerns remain unresolved.
