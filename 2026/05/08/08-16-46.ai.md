This is a test optimization patch (8/11) in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The patch introduces a fast path for generating test packs containing 4GB+1 NUL-filled blobs by using precomputed constants rather than computing hashes on the fly.

The key optimization replaces SHA-1 hashing of 8GB of NUL bytes with direct writing of a deterministic pack structure. The pack consists of:
- A 25-byte constant prefix (pack/object/zlib headers)
- Periodic 5-byte deflate block headers around zero-filled blocks
- A 513-byte constant suffix (tree, commits, pack checksum)

This reduces test runtime from 75-80 seconds to 19-21 seconds (3.5-5.4x speedup) by making the operation I/O-bound rather than CPU-bound. The precomputed structure is stored in a `fast_pack` array keyed by hash algorithm, allowing future SHA-256 support through additional entries.

The patch maintains safety by only applying the optimization to known test data patterns (all-NUL 4GB+1 blobs) and includes verification that the generated packs match the generic path's output. This directly addresses performance concerns raised in earlier reviews while preserving test reliability.

As part of the larger series fixing Windows' 32-bit type truncation issues, this test optimization helps make the 4GB+ object validation practical for CI timeouts. The approach demonstrates careful engineering tradeoffs between thorough testing and resource constraints.
