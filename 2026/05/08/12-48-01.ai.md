Bugfix discussion regarding `git diff --word-diff` whitespace handling. Johannes Sixt responds to Vincent Lefevre's bug report about incorrect whitespace highlighting, explaining this is expected behavior rather than a bug. The key clarification is that `--word-diff` inherits Git's standard whitespace sensitivity unless explicitly overridden with `-w`. This matches the underlying line-diff behavior that word-diff builds upon.

The response provides important context that wasn't in the original report: the word-diff output is working as designed by respecting Git's whitespace rules by default. Johannes notes users wanting whitespace-agnostic comparison should use `-w` to suppress whitespace differences, similar to regular diff behavior. This appears to resolve the reported issue by clarifying the intended interaction between word-diff and whitespace handling flags.
