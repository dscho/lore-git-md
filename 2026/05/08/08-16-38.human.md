This is the third version of Johannes Schindelin's platform compatibility patch series addressing Windows-specific issues with large objects (>4GB) during cloning. The series systematically replaces 32-bit `unsigned long` types with 64-bit `size_t` across several subsystems to prevent object size truncation.

Key improvements in v3:
1. Proper type safety for varint decoding in index-pack/unpack-objects (patch 1/11), now using `size_t` consistently and adding overflow guards
2. Explicit size checks when narrowing `size_t` to `unsigned long` in pack-objects (patch 3/11), preventing silent truncation
3. Maintains all test optimizations from v2 (precomputed packs, unsafe SHA-1 hashing) while marking the large-object tests as EXPENSIVE

The series remains focused on the most critical paths that prevent large objects from surviving clones at all, specifically targeting:
- zlib wrapper BUG() assertions
- Pack streaming truncation
- Delta header size handling
- Index-pack/unpack-objects size tracking

Schindelin has incorporated feedback from Torsten Bögershausen, particularly around type safety, and the series appears technically sound. The changes are well-motivated given Windows' platform limitations and include thorough regression tests. While this doesn't yet address all large-object handling (cat-file and loose objects remain future work), it solves the immediate blocking issues for cloning large objects on Windows.
