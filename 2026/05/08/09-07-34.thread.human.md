Greg Hurrell has proposed improving the `git-jump` contrib script by making it automatically select between "merge" and "diff" modes when run without arguments, based on repository state (unmerged paths trigger merge mode, unstaged changes trigger diff mode). The initial implementation is technically sound, using standard Git plumbing commands to detect state while maintaining backward compatibility.

Jeff King (Peff) has reviewed the patch substantively, acknowledging its technical merits but raising a thoughtful UX concern. He questions whether silently changing behavior based on repository state might confuse new users who expect explicit mode selection, suggesting an alternative "git jump auto" command that would preserve discoverability while still providing convenience. Peff notes the implementation is reasonable performance-wise, though not optimal - a tradeoff he considers acceptable for this use case. While he personally uses shell aliases for common operations, he recognizes the value in reducing cognitive load for others.

The discussion now hinges on whether to proceed with the original automatic behavior or adopt Peff's more explicit alternative. No other participants have weighed in yet on this design question. The patch remains in its first iteration while this UX consideration is resolved.
