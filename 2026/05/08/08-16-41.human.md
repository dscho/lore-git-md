This is the third patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch focuses on fixing truncation issues in the object database (ODB) and packfile streaming code paths.

The key change replaces `unsigned long` with `size_t` for object sizes in the `odb_read_stream` structure and related functions, since Windows' 32-bit `unsigned long` would truncate sizes over 4GB. The patch introduces explicit `cast_size_t_to_ulong()` checks where size_t values must still flow into unsigned long parameters, making these truncation points visible rather than silent.

Notable technical changes:
- Updates `odb_read_stream.size` to use `size_t` instead of `unsigned long`
- Adds temporary variables to handle API compatibility where callers still expect `unsigned long`
- Introduces explicit casting at boundary points in pack-objects.c
- Modifies header parsing functions to use `size_t` for sizes
- The changes are focused on the most critical paths for large object handling during cloning
- Includes careful documentation of remaining truncation points
- Maintains backward compatibility while paving the way for future 64-bit support

The patch builds on prior work from git-for-windows#6076 and represents an important step in Windows platform support. It responds directly to Torsten Bögershausen's review feedback from v2 by making type conversions more explicit and safer. The changes appear well-considered and maintain compatibility while addressing the core issue.

This is part of a broader effort to improve Windows support for large repositories, with more work still needed in other areas like cat-file and loose object handling. The patch series as a whole demonstrates careful attention to platform-specific issues while maintaining cross-platform compatibility.
