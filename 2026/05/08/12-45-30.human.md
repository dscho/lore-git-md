This is a review of patch 6/8 in Christian Couder's URL-based promisor remote configuration series. The patch implements security mechanisms for trusting known remotes when their URLs match patterns in `promisor.acceptFromServerUrl`.

Toon Claes provides a substantive review, raising three technical points:

1. Questions whether `WM_PATHNAME` is needed for host matching since the host part is already isolated via `xstrndup()`. This suggests the flag might be redundant given the current implementation.

2. Notes the intentional omission of user/password comparison in URL matching, correctly inferring this allows servers to update those fields when the URL matches.

3. Asks for verification that advertised servers are only stored to local config when `promisor.AcceptFromServer` is set to None, indicating attention to the security implications.

The review also observes a minor inconsistency in test setup between this and other tests regarding `initialize_server` calls. While not a functional issue, it shows careful reading of the test suite.

This is a thorough review that engages with the security implications and implementation details of the URL matching system. The questions raised are reasonable and show the reviewer understands both the code and its security context. The patch author will likely want to address these points in a follow-up, particularly clarifying the `WM_PATHNAME` usage and confirming the storage behavior.
