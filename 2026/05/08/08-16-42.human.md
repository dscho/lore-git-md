This is patch 4/11 in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The focus here is on delta header size handling, where 32-bit `unsigned long` types on Windows cause truncation problems.

The patch introduces new `size_t` variants of delta header parsing functions (`get_delta_hdr_size_sz()` and `get_size_from_delta_sz()`) to properly handle 64-bit sizes, while maintaining the existing `unsigned long` versions for compatibility. The key changes are:

1. Adding new functions that preserve full 64-bit sizes for delta headers
2. Modifying `packed_object_info_with_index_pos()` to use the new functions when determining object sizes for streaming decisions
3. Explicitly noting where truncation to `unsigned long` may occur (but is acceptable for the streaming code's purposes)

The changes respond directly to Torsten Bögershausen's review feedback from v2 about type safety. The patch appears well-considered, with clear documentation of the tradeoffs and careful attention to maintaining both correctness and backwards compatibility. This is part of the broader effort to make Git properly handle large objects on Windows platforms.
