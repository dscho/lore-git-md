This is part 9/11 of Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The patch adds SHA-256 support to the test infrastructure's precomputed pack optimization.

The change extends the existing `fast_packs[]` table with a SHA-256 variant, maintaining the same pack structure but accommodating the 32-byte OIDs and different checksum format. The constants were generated by running the generic path in a SHA-256 repository, ensuring correctness while preserving the test speedup benefits.

This builds on the test optimization approach introduced in earlier patches (7/11 and 8/11) that precompute pack structures for common test cases to avoid expensive runtime hashing. The SHA-256 version follows the same pattern as the SHA-1 implementation, just with the appropriate OID length and checksum adjustments.

The patch is a straightforward extension of the test infrastructure to support SHA-256 testing, which is important given Git's ongoing work toward SHA-256 interoperability. It demonstrates careful attention to maintaining the same performance benefits across hash algorithms while keeping the test validation robust.
