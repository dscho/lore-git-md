This is the fifth patch in Johannes Schindelin's series removing the nedmalloc allocator from Git's Windows builds. The patch continues the mechanical deletion of the nedmalloc implementation by removing 1699 lines from `compat/nedmalloc/malloc.c.h`, specifically targeting the system allocation components.

The change is part of a well-structured series that first disabled nedmalloc usage, then removed build system references, and is now deleting the implementation in chunks. This particular patch focuses on removing the core memory management infrastructure including segment handling, bin operations, and system allocation logic.

Since Git for Windows has already been using mimalloc for years with no performance regressions, this removal is a straightforward cleanup to eliminate unmaintained code that causes build issues with newer GCC versions. The patch follows the series' pattern of careful, incremental deletion with clear commit messages indicating the squashing strategy.

No new technical concerns are introduced - this is simply continuing the mechanical removal of code that is no longer used. The patch appears to be correctly focused on its narrow deletion task without introducing any functional changes.
