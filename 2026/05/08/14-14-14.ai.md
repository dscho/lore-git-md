This is a documentation patch from D. Ben Knoble that corrects the gitignore(5) man page to accurately reflect where per-repository ignore patterns are stored. The patch changes references from `$GIT_DIR/info/exclude` to `$GIT_COMMON_DIR/info/exclude` since that's where Git actually looks for these patterns, particularly in worktree contexts.

The v1 of this series had proposed implementing per-worktree ignore patterns via a new config option, but based on feedback from brian m. carlson, Phillip Wood, and Junio C Hamano, the author has scaled back to just fixing the documentation. The maintainer feedback expressed skepticism about the need for per-worktree ignores, with Junio noting that shared patterns are generally more useful in practice. Phillip Wood raised technical concerns about path handling and design scalability, while brian m. carlson suggested a more general approach for worktree-specific files.

The v2 patch is minimal change that simply updates the documentation to match reality, dropping the feature implementation. The commit message explains the rationale and includes a concrete use case that motivated the original proposal (managing different sets of ignored files for LLM tool skill files across worktrees), while acknowledging the community's preference against the feature.

This appears to be a straightforward documentation correction that aligns the man page with Git's actual behavior. The patch is clean and focused, addressing only the discrepancy between documented and actual paths for exclude files.
