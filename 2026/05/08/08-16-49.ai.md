This is the final patch (11/11) in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The patch focuses on CI configuration, implementing Derrick Stolee's suggestion to run expensive tests only on push builds to integration branches rather than every PR iteration.

The change modifies `ci/lib.sh` to set `GIT_TEST_LONG=YesPlease` specifically for push events targeting the main integration branches (next, master, main, maint). This ensures the EXPENSIVE tests (including the >4GB clone tests added earlier in the series) will run when changes are merged to these branches, but not during PR validation where the extra runtime (200-850s per test) would be too costly.

The patch cleanly concludes the series by addressing the CI performance concern raised in earlier discussions, while maintaining test coverage where it matters most - on the integration branches where changes are being cooked for release. The implementation follows Git's standard CI patterns and includes appropriate documentation of the rationale in the commit message.

This change complements the test optimizations made in patches 5/11-10/11, completing the practical compromise between thorough validation and CI resource constraints that has been a theme throughout the series. With this final piece in place, the series appears ready for integration.
