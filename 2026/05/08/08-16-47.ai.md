This is patch 9/11 in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The patch extends the test infrastructure to support SHA-256 repositories by adding a precomputed pack structure for 4GB+1 NUL-filled blobs in SHA-256 format.

The key technical aspects are:
- Adds a SHA-256 variant to the `fast_packs[]` table alongside the existing SHA-1 version
- Maintains identical pack prefix and deflate block structure (since the pack format doesn't encode the hash algorithm in headers)
- Differs in suffix length (609 bytes vs 513 for SHA-1) due to 32-byte OIDs and different pack checksum
- Constants were generated by running the generic path in a SHA-256 repository
- Follows the same optimization approach as the SHA-1 version (patch 8/11) to avoid expensive runtime hashing

This continues the series' pattern of careful platform compatibility work while maintaining test coverage across hash algorithms. The change is straightforward and well-contained, building on the test infrastructure improvements from earlier patches. It demonstrates consideration for SHA-256 users while keeping the test optimizations that make the large-object tests practical to run.
