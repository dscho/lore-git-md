This is the second patch in Johannes Schindelin's v3 series addressing Windows platform limitations with large objects (>4GB). The patch specifically targets zlib wrapper issues where Windows' 32-bit `uLong` type causes truncation of stream sizes during compression/decompression.

The key change replaces zlib's 32-bit `total_in`/`total_out` tracking with 64-bit `size_t` counters in Git's `git_zstream` wrapper, while maintaining compatibility with zlib's API through careful masking. The patch:
1. Introduces `ULONG_MAX_VALUE` to handle platform-specific `uLong` sizes
2. Modifies `zlib_pre_call()`/`zlib_post_call()` to properly convert between 64-bit and 32-bit counters
3. Updates sanity checks to compare only the relevant low-order bits
4. Fixes a format string in `object-file.c` to properly handle 64-bit sizes

The changes appear well-considered, with clear attention to cross-platform compatibility and type safety. The patch builds on prior work from git-for-windows#6076 and represents an important step in making Git's compression layer properly handle large objects on Windows. The modifications are localized to the zlib wrapper interface while maintaining the existing API contract.
