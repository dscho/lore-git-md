This is a brief technical discussion about integration mechanics for the nedmalloc removal series, now that the technical merits have been settled.

Jeff King (Peff) suggests using `--irreversible-delete` when applying the large deletion patches to avoid carrying the full content of the deleted malloc.c.h file in Git's history. This flag would record only that the file was deleted, not its full contents, which is reasonable given the file is being completely removed and its contents are not meaningful to preserve (they're just the unmaintained allocator implementation being dropped).

The suggestion comes after Junio had already proposed two alternative approaches to handle the large file deletion - either squashing the split patches during integration or pulling directly from the author's repository. Peff's idea offers a third option that would keep the logical commit structure while minimizing repository bloat from the large deletion.

This is a low-stakes coordination discussion between experienced contributors about the cleanest way to handle a mechanical change that has already been technically approved. No new concerns are raised about the actual nedmalloc removal - the thread is just working out the final integration details.
