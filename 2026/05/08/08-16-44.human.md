This is a regression test patch (6/11) in Johannes Schindelin's series fixing Windows platform issues with large (>4GB) objects during cloning. The test verifies that the fixes for 32-bit truncation bugs in index-pack and unpack-objects work correctly.

The test creates a synthetic repository with a 4GB+ blob using the new `test-tool synthesize pack` helper introduced earlier in the series. It then performs two clone operations - one forcing unpack-objects path and another forcing index-pack path - and verifies the large blob survives intact in both cases by comparing OIDs rather than sizes (since size reporting still uses unsigned long on Windows).

This is a key validation point for the series, demonstrating the core fixes work as intended. The test is marked SIZE_T_IS_64BIT to skip on platforms where the fixes wouldn't apply. The approach shows careful consideration of Windows limitations while still providing thorough verification.
