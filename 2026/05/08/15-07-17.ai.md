This is a performance optimization patch for the merge-base calculation in large repositories. The key change is that when only a single merge-base is needed (the common case when not using `--all`), the algorithm can exit early once it finds the first valid merge-base when generation numbers are available, rather than continuing to process the entire STALE commit frontier.

The patch modifies `paint_down_to_common()` to take a new `find_all` parameter and adds corresponding plumbing through the call stack. When `find_all` is false and generation numbers are available, the function can exit immediately after finding the first merge-base candidate, as generation ordering ensures no later commit can dominate it. This provides dramatic speedups in large repositories - the commit message shows examples going from 5 seconds to 24ms (100x improvement).

The change is well-tested with new test cases that verify:
1. The optimization works with and without commit-graphs
2. Results match between --all and non--all cases
3. Behavior is correct in both shallow and deep commit histories

The implementation appears careful to maintain correctness while enabling the optimization - it only applies when generation numbers are available and the found commit has a finite generation number. The extensive test coverage helps verify this doesn't introduce regressions.

This seems like a well-motivated optimization that could benefit users of large monorepos, particularly those making frequent merge-base queries. The patch is cleanly structured and thoroughly tested.
