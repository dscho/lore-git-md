This is a test infrastructure patch (7/11) in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB). The patch optimizes the test-synthesize helper by using unsafe SHA-1 hashing for generating test packs, providing significant speed improvements when hardware acceleration is available.

The change responds to Jeff King's observation that the 4GB+ test cases were dominating the test suite runtime (160-850 seconds). By switching from the collision-detecting SHA1DC to unsafe_hash_algo() (which uses OpenSSL or Apple CommonCrypto when available), the patch achieves a 3.5-5.4x speedup in test pack generation. Benchmarks show runtime dropping from 75-80s to 19-21s for 4GB packs on x86_64.

The optimization is safe for test data since the helper generates known content where collision detection isn't needed. The change is a no-op on platforms without unsafe backend support (like default builds on Windows). The patch maintains the series' careful balance between thorough testing and practical CI constraints.
