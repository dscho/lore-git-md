This is the third patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch focuses on fixing truncation issues in the object database (ODB) and packfile streaming code by replacing 32-bit `unsigned long` with 64-bit `size_t` for object sizes.

The key changes in this iteration:
1. The `odb_read_stream` structure now uses `size_t` for object sizes instead of `unsigned long`
2. Introduces `unpack_object_header_sz()` to handle sizes via `size_t` pointers
3. Makes explicit the remaining `size_t` to `unsigned long` conversions in `builtin/pack-objects.c` using `cast_size_t_to_ulong()`
4. Updates related functions in packfile.c and other subsystems to use `size_t` where possible

The patch acknowledges this is a stop-gap solution - while it widens the producers to `size_t`, some consumers remain `unsigned long` due to API compatibility constraints. The explicit casting at conversion points makes these truncation boundaries visible and will assert if objects exceed 4GB on Windows.

Test infrastructure changes from previous iterations remain, including optimized test pack generation methods. The changes respond directly to Torsten Bögershausen's review feedback from v2 about type safety and precision.

This represents an important step in Windows platform support while deferring complete type widening to a future series. The careful attention to type safety and clear documentation of remaining limitations make this a well-considered change.
