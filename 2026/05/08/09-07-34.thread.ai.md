Thread identity: Feature patch for `git-jump` contrib script by Greg Hurrell, adding automatic mode selection when run without arguments.

Core problem/goal: Improve usability of `git-jump` by automatically detecting and selecting between "merge" mode (when unmerged paths exist) and "diff" mode (when unstaged changes exist) when no arguments are provided, while maintaining backward compatibility with explicit mode specification.

Current status: Initial patch version proposing the change, with documentation updates explaining the new behavior. Jeff King (Peff) has provided substantive technical review raising UX concerns about silent behavior changes, to which Greg Hurrell has responded with concrete workflow examples supporting the automatic approach.

Key technical details:
- Uses `git ls-files -u` to detect unmerged paths (merge mode)
- Uses `git diff --quiet` to detect unstaged changes (diff mode)
- Falls back to showing usage if neither condition is met
- Maintains backward compatibility with explicit mode specification
- Changes are confined to the `git-jump` script in contrib/
- Documentation updates explain the new automatic behavior

Open questions/loose ends:
- Ongoing discussion about UX tradeoffs between implicit behavior (Greg's preference for typing efficiency) versus explicit commands (Peff's discoverability concern)
- Whether to keep automatic behavior as default or introduce an explicit "auto" subcommand
- Impact of wider distribution via Homebrew making the script more visible to users who may not read documentation
- Greg's specific workflow patterns (always merge mode during conflicts, diff mode for unstaged changes) as concrete use case
