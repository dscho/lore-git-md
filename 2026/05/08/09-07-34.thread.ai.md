Thread identity: Feature patch for `git-jump` contrib script by Greg Hurrell, adding automatic mode selection when run without arguments.

Core problem/goal: Improve usability of `git-jump` by automatically detecting and selecting between "merge" mode (when unmerged paths exist) and "diff" mode (when unstaged changes exist) when no arguments are provided, while maintaining backward compatibility.

Current status: Initial patch version proposing the change, with documentation updates explaining the new behavior. Jeff King (Peff) has provided substantive technical review raising UX concerns about silent behavior changes.

Key technical details:
- Uses `git ls-files -u` to detect unmerged paths (merge mode)
- Uses `git diff --quiet` to detect unstaged changes (diff mode)
- Falls back to showing usage if neither condition is met
- Maintains backward compatibility with explicit mode specification
- Changes are confined to the `git-jump` script in contrib/
- Documentation updates explain the new automatic behavior

Open questions/loose ends:
- Discoverability concern raised by Peff: whether silent behavior changes based on repo state might confuse users
- Alternative UX proposal ("git jump auto") to maintain explicit user intent while providing convenience
- Minor performance consideration (tradeoff deemed acceptable)

Participant positions:
- Greg Hurrell (author): Proposed initial implementation with automatic mode selection
- Jeff King (Peff): Provided substantive review acknowledging technical soundness but raising UX concerns; suggested alternative approach while recognizing value of reducing cognitive load

Related work: Standalone change to a contrib script, not part of any larger ongoing effort. Peff notes personal use of shell aliases for common `git-jump` operations as context.
