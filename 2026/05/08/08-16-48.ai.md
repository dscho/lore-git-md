This is the 10th patch in Johannes Schindelin's 11-part series addressing Windows platform issues with large objects (>4GB) during cloning. The patch marks the >4GB clone tests as EXPENSIVE to reduce their impact on developer workflows and CI resources.

The key change is adding the EXPENSIVE prereq to three test cases in t5608-clone-2gb.sh that deal with >4GB objects. Even after previous optimizations (like precomputed pack constants) reduced test runtime from minutes to seconds, these tests still take 200-850 seconds in CI due to the inherent cost of transporting, unpacking and indexing 4GB+ of test data. The change responds to Jeff King's observation that these tests alone took longer than the rest of the test suite combined on his machine.

The patch maintains the SIZE_T_IS_64BIT prereq (ensuring tests only run on 64-bit systems) while adding EXPENSIVE to require explicit opt-in via GIT_TEST_LONG. This follows the series' pattern of balancing thorough validation with practical constraints, as seen in earlier patches that introduced test optimizations like unsafe SHA-1 hashing and precomputed packs.

The change is straightforward and uncontroversial, representing a pragmatic solution to a known performance pain point while preserving the ability to run these important edge-case tests when needed. It fits naturally with the series' overall goal of making large-object handling robust on Windows without unduly burdening developers.
