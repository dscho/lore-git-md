This is a bugfix for the `rebase --update-refs` feature, addressing an edge case where non-branch refs like HEAD could incorrectly appear in the rebase todo list when `rebase.instructionFormat` includes `%d` decorations.

The patch has now reached its second version, having incorporated review feedback from Phillip Wood (a recognized expert on rebase/sequencer code). The core fix remains unchanged - it ensures the decoration table only processes `DECORATION_REF_LOCAL` types when generating update-ref instructions, preventing invalid instructions for non-branch refs.

Key improvements in v2:
- The test case has been simplified per Phillip's suggestion, removing redundant branch checks
- Verification now checks the complete update-ref list rather than using individual grep patterns
- The test explicitly confirms tags are ignored while maintaining correct behavior for legitimate branch updates

Phillip Wood has now given his approval ("this looks great"), indicating the patch is ready for inclusion. The fix is well-contained and maintains the documented contract of `--update-refs` - only moving branch refs under refs/heads/ while leaving display-only decorations (HEAD, tags) untouched. This addresses a real edge case in the relatively new `--update-refs` feature (introduced in Git 2.38) without introducing new complexity.
