Platform compatibility patch from Johannes Schindelin (Dscho) continuing the removal of the unmaintained nedmalloc allocator. This is patch 5/6 in the v3 series, which should be squashed into patch 3/6 as indicated in the subject line.

The patch removes the second large chunk (1699 lines) from `compat/nedmalloc/malloc.c.h`, continuing the systematic deletion of the nedmalloc implementation. The removed code includes core memory management structures and algorithms:
- Tree-based chunk management for larger allocations
- Segment handling for non-contiguous memory regions
- The main malloc state structure tracking all allocations
- System allocation interfaces (MORECORE/MMAP)

This continues the series' approach of splitting the large file deletion across multiple patches to accommodate mailing list size constraints. The change is mechanical - Git for Windows has already switched to mimalloc, so this is purely removing dead code that fails to build with GCC 16's new warnings.

The series has maintained a clear dependency order: first disabling usage, then removing build system references, and finally deleting the implementation in chunks. No functional changes are introduced, just removal of unused code. The patch appears well-structured and follows the established pattern from earlier in the series.

With this patch, the nedmalloc removal is nearly complete - only one more chunk deletion remains in patch 6/6. The series has seen no new objections since v3 incorporated Junio's feedback about squashing the final deletion patches.
