This is a test infrastructure patch (5/11) in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB). The patch introduces a new test helper `test-synthesize` that generates synthetic packfiles containing very large objects for testing Git's handling of >4GB objects.

The new test helper provides a fast way to create test repositories with large objects by directly writing uncompressed zlib streams, bypassing Git's normal object creation machinery. This is significantly faster than using standard Git commands - reducing generation time for a 4GB test case from 10+ hours to ~2.5 minutes.

Key technical aspects:
- Implements direct zlib stream writing with proper headers and checksums
- Generates a minimal commit history containing a single large blob (>4GB)
- Includes trees and commits to make the large object reachable
- Outputs a packfile that can be used to test clone operations
- Uses NUL bytes for the blob content to avoid SHA-1 calculation overhead

The implementation carefully handles:
- Proper zlib block formatting (64KB max blocks)
- Adler-32 checksum calculation
- Packfile checksumming
- Object header generation
- Minimal commit history construction

This test tool will be used in subsequent patches to verify the Windows-specific fixes for large object handling. The approach represents a practical compromise between test fidelity and execution speed, enabling reliable testing of the >4GB object cases that were previously difficult to validate.
