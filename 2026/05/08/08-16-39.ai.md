This is the first patch in Johannes Schindelin's v3 series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch focuses on fixing truncation issues in index-pack and unpack-objects caused by 32-bit `unsigned long` types on Windows.

The key changes in this version:
- Changes the object size variable to `size_t` (64-bit on 64-bit platforms) to prevent overflow when handling large objects
- Also updates the per-byte continuation variable `c` to `size_t` to match Git's canonical varint decoder implementation
- Adds explicit overflow guards when shifting would exceed platform limits, similar to protections in `unpack_object_header_buffer()`
- Improves error messaging to clarify when an object size exceeds platform capabilities rather than implying malformed input

The patch responds directly to Torsten Bögershausen's review feedback from v2 by making the type changes more comprehensive and adding the overflow protection. The changes are focused on the most critical paths where truncation would completely prevent large objects from being unpacked correctly.

This represents a well-considered fix for a real Windows platform limitation, with clear attention to type safety and proper error handling. The patch maintains compatibility while enabling proper handling of large objects that would otherwise be corrupted or rejected during clone operations.
