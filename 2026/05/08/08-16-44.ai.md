This is a test patch (6/11) in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB). The patch adds regression tests for cloning repositories containing objects larger than 4GB, specifically verifying the fixes for truncation bugs in index-pack and unpack-objects.

The test creates a synthetic packfile containing a 4GB+ blob using the new `test-tool synthesize pack` helper introduced earlier in the series. It then verifies successful cloning through both the unpack-objects and index-pack paths by comparing object IDs rather than sizes (since size reporting still uses unsigned long on Windows). The test is properly marked as SIZE_T_IS_64BIT to only run on platforms where size_t can handle the large objects.

This test demonstrates the practical application of the test infrastructure added in patch 5/11, providing concrete validation that the type-safety fixes in the critical object streaming paths actually work for the intended use case. The careful test design avoids direct size comparisons that would still fail on Windows, instead using content identity (via OIDs) to verify correctness.
