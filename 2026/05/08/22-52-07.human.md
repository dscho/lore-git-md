Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the seventh iteration of Harald Nordgren's proposal to streamline the workflow of fetching before creating a tracking branch. The patch has evolved significantly in response to technical feedback, though the maintainer's philosophical objections remain unresolved.

Key improvements in v7:
1. Rejects invalid mode combinations (`inherit,direct`) while maintaining the "last one wins" behavior for multiple `--track` flags
2. Makes offline behavior more graceful - now proceeds with existing refs when fetch fails (with warning) rather than aborting
3. Better handles custom fetch refspecs by resolving through configured remotes
4. For bare remote names (e.g. `origin`), now fetches the remote's default branch rather than everything
5. Adds comprehensive tests covering all these edge cases

The implementation remains technically solid with thorough test coverage. The documentation clearly explains the new behavior in both `git-checkout` and `git-switch` man pages. While the patch doesn't address the maintainer's workflow model concerns, it does make the feature more robust by handling real-world scenarios like offline work and custom refspecs.

The parallel `--autostash` work mentioned in earlier iterations doesn't appear in this version, suggesting it may be deferred to a future patch series. This version focuses solely on refining the `--track=fetch` behavior.
