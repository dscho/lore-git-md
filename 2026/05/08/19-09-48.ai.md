This is a technical discussion about type safety in the Windows large-object handling series, specifically addressing byte-level memory access patterns.

Torsten Bögershausen follows up on Johannes Schindelin's response about variable typing in the object unpacking code. While agreeing with the move to `size_t` for object sizes, Torsten raises a more subtle architecture-specific issue: reading multi-byte values from unaligned memory addresses. He explains that some processor architectures (unlike x86) cannot safely dereference misaligned `long` or `size_t` values, potentially causing exceptions.

The key technical point is that the code should:
1. Read individual bytes (as `uint8_t`) when processing varint-encoded data
2. Avoid architecture-dependent assumptions about unaligned memory access
3. Only widen to `size_t` after safely accumulating the bytes

This refinement doesn't change the patch's core functionality but ensures correct behavior across all platforms.
