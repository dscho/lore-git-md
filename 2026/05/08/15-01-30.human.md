This is the final patch in a documentation series clarifying git-interpret-trailers' behavior, particularly around trailer key formatting rules. The series stemmed from a bug report about silent failures when using keys containing periods (like "My-6.11-Version"), which the maintainer confirmed was intentionally strict parsing for reliability.

Kristoffer Haugsbakk's 9-patch series has now been through multiple rounds of review, with this version incorporating all feedback. The changes systematically improve the man page by:

1. Removing outdated RFC 822 references that confused the email-header origins
2. Standardizing on "metadata" terminology
3. Clarifying broader applicability beyond commit messages
4. Explicitly documenting key restrictions (ASCII alphanumeric + hyphen only)
5. Adding concrete valid/invalid key examples
6. Explaining comment line handling
7. Defining "trailer block" mechanics

The series is merge-ready, having addressed maintainer feedback about terminology and accessibility. This final patch fixes a typo in the subject line ("intepret" to "interpret") caught in last-minute review. The documentation now provides complete coverage of the command's behavior, making the strict parsing rules clear while improving usability through better examples and structure.
