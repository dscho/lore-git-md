This is a follow-up discussion in the `git-jump` usability improvement thread, where Greg Hurrell responds to Jeff King's UX concerns about automatic mode selection. The patch proposes making the `git-jump` contrib script automatically choose between "merge" or "diff" mode when run without arguments, based on repository state.

Greg clarifies his motivation - it's primarily about reducing typing effort rather than cognitive load, since he already knows which mode he wants in different scenarios (merge mode during conflicts, diff mode for unstaged changes). He shares that he's been using a personal alias for this behavior for years, but Homebrew's recent decision to install `git-jump` by default broke his workflow since aliases can't shadow builtin commands.

The exchange reveals an interesting tension between discoverability (Peff's concern about new users not seeing usage instructions) and convenience (Greg's desire for muscle-memory efficiency). Greg's response suggests the automatic behavior aligns with his established mental model, where the repository state strongly implies the intended action. He provides concrete examples showing how the automatic selection would match his expectations in common workflows.

This follow-up helps contextualize the original proposal by showing the author's real-world usage patterns and the specific pain point (Homebrew's change breaking existing aliases) that motivated the patch.
