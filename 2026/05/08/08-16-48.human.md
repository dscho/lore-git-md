This is patch 10/11 in Johannes Schindelin's series addressing Windows platform issues with large objects (>4GB) during cloning. The patch marks the >4GB clone tests as EXPENSIVE to avoid running them in normal test runs.

The key points:
- Even with earlier optimizations (precomputed pack constants) that reduced test runtime from minutes to seconds, these tests still take 200-850 seconds in CI due to the inherent cost of handling 4GB+ data during clone operations.
- The tests also consume significant disk space (4GB source repo plus two clones), which is problematic for developers using RAM disks.
- Jeff King noted that t5608 alone takes longer than the rest of the test suite combined on his laptop.
- The patch adds the EXPENSIVE prereq (requiring GIT_TEST_LONG to be set) alongside the existing SIZE_T_IS_64BIT check, keeping these resource-intensive tests out of normal test runs while still allowing them to run in CI and when explicitly requested.

This is a pragmatic change that balances thorough testing with developer workflow concerns, following up on earlier performance optimizations in the series. The patch is straightforward and uncontroversial, simply adjusting test prerequisites without changing any test logic.
