This is a bugfix for the submodule configuration system, addressing how `submodule.fetchJobs` is read from `.gitmodules`. The v2 patch follows up on review feedback by improving the commit message to clearly explain the pointer indirection issue that was causing the parallel fetch jobs setting to be ignored.

The core fix remains the same - removing an incorrect `&` operator when passing the `max_jobs` parameter to `config_from_gitmodules()`. The patch now includes a more detailed commit message explaining that the original code was writing the setting to the wrong memory location due to this pointer mismatch.

A new test case verifies the fix by checking that a configured `submodule.fetchJobs` value in `.gitmodules` is properly respected during submodule updates. The test uses `GIT_TRACE` to confirm the expected number of parallel tasks (67 in this case) are actually being used.

The change is small but important for users who configure parallel submodule fetching. The v2 addresses the documentation concerns raised in review while maintaining the technically sound solution from v1. This appears ready for final review and potential merging.
