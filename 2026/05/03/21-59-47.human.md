This is a technical clarification from Junio C Hamano about Git's rename detection limitations, specifically regarding the ongoing discussion about Ruby files moved between namespaces.

Junio responds to Phillip Wood's earlier suggestion of splitting namespace moves into two commits (first a pure rename, then indentation changes). While acknowledging this is a common recommendation, Junio points out its limitations - it only helps certain Git operations (`git log -M`, `git rebase`) but fails for others like `git diff` or `git merge` across non-adjacent commits.

The maintainer's intervention serves to temper expectations about the workaround's effectiveness, emphasizing that Git's snapshot-based model fundamentally limits rename detection to pairwise commit comparisons. This keeps the discussion grounded in Git's architectural constraints while still acknowledging the validity of the reported issue with Ruby namespace moves.

The email doesn't propose alternative solutions but provides important context for evaluating any future proposals to improve rename detection for this case. It suggests the problem may require deeper consideration of Git's core design tradeoffs rather than simple workarounds.
