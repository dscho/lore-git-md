This is a review comment on the `git url-parse` feature series, specifically addressing Windows UNC path handling. Torsten Bögershausen raises a question about whether the new URL parser should handle Windows UNC paths (\\server\share\repo) in addition to the file://server/share/repo format that was previously implemented in Git for Windows.

The review notes that the v3 series already includes Windows-specific fixes for DOS drive prefixes and cross-platform path assertions, but doesn't explicitly mention UNC path support. Torsten references his 2019 commit that added UNC support to Git's clone functionality, suggesting this might need to be considered for the new URL parser as well.

The comment is constructive but non-blocking - Torsten frames it as "a question to myself" about whether this needs addressing now or in follow-up work. This reflects the series' current state as otherwise complete and well-tested, with UNC paths being a potential enhancement rather than a gap. The author has demonstrated responsiveness to Windows-specific feedback throughout the series' iterations.

From a technical perspective, the review highlights an important Windows filesystem convention that could reasonably be included in a comprehensive URL parser, though the current implementation already handles the core Git URL formats. The reference to prior work provides clear context about how such support was previously implemented.
