This is a bugfix addressing how `submodule.fetchJobs` is read from `.gitmodules`. The v3 patch finalizes the fix after incorporating all review feedback from previous versions.

The core issue was a pointer indirection bug where `update_clone_config_from_gitmodules()` incorrectly passed `&max_jobs` to `config_from_gitmodules()`, when `max_jobs` was already a pointer. This caused the parallel fetch jobs setting to be written to the wrong memory location and ignored. The fix simply removes the erroneous `&` operator.

The patch now includes a new test case that verifies the fix by:
1. Setting `submodule.fetchJobs` to 67 in `.gitmodules`
2. Using `GIT_TRACE` to confirm that exactly 67 parallel tasks are spawned during submodule update

The commit message has been refined through the review process to clearly explain the pointer issue while maintaining technical accuracy. All substantive feedback has been addressed, and the change appears ready for merging. This is a small but important fix for users who configure parallel submodule fetching.
