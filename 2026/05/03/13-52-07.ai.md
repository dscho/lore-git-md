This is a bugfix for the submodule configuration system, addressing how `submodule.fetchJobs` is read from `.gitmodules`. The v3 patch represents the final iteration of this fix, with only minor commit message refinements from v2.

The core issue remains a pointer indirection problem where `update_clone_config_from_gitmodules()` was incorrectly passing `&max_jobs` to `config_from_gitmodules()` when `max_jobs` was already a pointer. This caused the parallel fetch jobs setting to be written to the wrong memory location and ignored. The fix simply removes the erroneous `&` operator.

The patch includes a new test case that verifies the fix by:
1. Setting `submodule.fetchJobs` to 67 in `.gitmodules`
2. Using `GIT_TRACE` to confirm the submodule update actually spawns 67 parallel tasks

The commit message has been refined through review to more precisely describe the pointer issue while maintaining technical accuracy. The changes from v2 to v3 are purely documentation improvements to the commit message - the code and test remain unchanged from the v2 version that had already addressed all substantive review feedback.

This appears ready for merging, having gone through multiple review cycles with all technical concerns addressed and only minor wording polish remaining. The fix is small but important for users who configure parallel submodule fetching via `.gitmodules`.
