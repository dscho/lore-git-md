Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the sixth iteration of Harald Nordgren's proposal to streamline the workflow of fetching before creating a tracking branch. Despite the maintainer's philosophical objections in previous rounds, the author persists with technical refinements:

1. The commit message has been restructured to focus purely on the convenience aspect, dropping earlier framings about "wrong/stale" start points that the maintainer rejected.
2. The implementation remains technically solid, with thorough test coverage of the `--track=fetch` mode and its combinations with other tracking modes.
3. Documentation updates clearly explain the new behavior in both `git-checkout` and `git-switch` man pages.

The patch demonstrates responsiveness to prior feedback by:
- Maintaining the integrated `--track=fetch` approach from v5
- Adding comprehensive tests for edge cases
- Ensuring backward compatibility of the comma-separated mode syntax

However, the fundamental philosophical disagreement with the maintainer remains unresolved. While the technical execution is polished, the patch does not address the core workflow model concerns raised in previous rejections. The author appears to be hoping that framing the feature purely as a convenience (rather than a correctness fix) might overcome the objections, but the maintainer's position seemed quite firm in the last round.

Key technical details:
- New `fetch_remote_for_start_point()` helper handles the conditional fetching
- `parse_opt_checkout_track()` extended to handle comma-separated modes
- Tests verify:
  - Narrow fetches don't disturb other tracking branches
  - Failure cases abort cleanly
  - Mode combinations work as expected
  - Both `checkout` and `switch` commands support the feature

The patch remains in good technical shape, but its fate likely depends on whether the maintainer can be convinced to reconsider the workflow objections, or whether the author can find an alternative framing that aligns with Git's distributed model.
