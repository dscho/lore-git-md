Platform compatibility patch removing the unmaintained nedmalloc allocator from Windows builds.

Johannes Schindelin (Git for Windows maintainer) proposes dropping the long-unmaintained nedmalloc memory allocator from MinGW builds. The immediate motivation is a build failure with GCC 16, which now treats an unused-but-set variable in nedmalloc's code as an error. Git for Windows has already switched to mimalloc internally, making this change low-risk.

The patch removes the `USE_NED_ALLOCATOR` setting from `config.mak.uname` for MinGW builds, falling back to the system allocator (which is what non-Windows builds already use). The vendored nedmalloc code remains in the tree for now but could be removed in a follow-up.

This is a straightforward build system change that unblocks GCC 16 adoption in Git for Windows' CI. The patch appears well-motivated and low-risk, coming from the platform expert who has already validated the approach in Git for Windows. The commit message provides thorough background on the technical context and build failure details.
