This is a platform compatibility patch targeting Windows (MINGW) builds. Johannes Schindelin proposes removing the long-unmaintained nedmalloc allocator from Git's Windows configuration, as it causes build failures with GCC 16 due to a new `-Wunused-but-set-variable` warning being treated as an error.

The patch notes that Git for Windows already switched to mimalloc years ago, and the current issue surfaced when the Git for Windows SDK upgraded to GCC 16. The build failure occurs in the vendored nedmalloc code, which hasn't been updated since 2014. Rather than patch the unmaintained code, the solution is to stop using nedmalloc on Windows altogether, falling back to the platform allocator (which is what non-Windows builds already use).

The change is minimal - it simply removes the `USE_NED_ALLOCATOR` setting from `config.mak.uname` for MINGW builds. The actual nedmalloc code remains in the tree for now, though it could be removed in a follow-up. Schindelin mentions longer-term plans to properly integrate mimalloc support, but considers this a necessary first step to unblock GCC 16 adoption in CI.

The patch appears straightforward and well-justified, addressing a concrete build problem with a minimal change. The commit message provides thorough context about the issue's history and the rationale for this solution.
