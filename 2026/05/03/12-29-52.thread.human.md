Johannes Schindelin (Dscho) has successfully completed the removal of Git's unmaintained nedmalloc allocator, with Junio C Hamano merging the final patch series. This technical cleanup was prompted by GCC 16 compatibility issues and the fact that Git for Windows had already switched to mimalloc years ago without performance regressions.

The series followed a methodical approach: first disabling nedmalloc usage across all build systems (Makefile, CMake, Meson), then removing all build system references, and finally deleting the implementation code in three patches totaling over 5,700 lines. The v3 iteration incorporated maintainer feedback by clearly marking the deletion patches for squashing during integration. Patrick Steinhardt explicitly endorsed the complete removal approach, while Jeff King suggested using --irreversible-delete for repository optimization of the large file deletions.

With no outstanding technical concerns, Junio has now applied the series, closing the book on nedmalloc in Git's codebase. This maintains current runtime performance while removing unmaintained code that had become a build burden. The change particularly benefits Windows/MINGW builds but cleans up code paths across all platforms.
