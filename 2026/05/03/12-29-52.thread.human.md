Johannes Schindelin continues his systematic removal of the unmaintained nedmalloc allocator from Git's MINGW builds, addressing GCC 16 compatibility issues. The series has progressed methodically: first disabling usage across all build systems, then removing configuration, and now deleting the implementation in reviewable chunks.

Patch 5/6 removes 1699 lines covering the allocator's core data structures and algorithms - free chunk management (using both linked lists and trees), segment handling, and internal metadata tracking. This follows patch 4's deletion of the file's first section. The changes are purely deletions with no runtime impact, since Git for Windows long ago switched to mimalloc. The careful, structured approach - splitting the large file along logical boundaries - has drawn no objections, with Patrick Steinhardt having previously endorsed the full removal direction.

One final patch remains to complete the cleanup by removing malloc.c.h's remaining sections. The series exemplifies a well-executed deprecation: first establishing the replacement (mimalloc), then systematically removing the obsolete component while maintaining bisectability.
