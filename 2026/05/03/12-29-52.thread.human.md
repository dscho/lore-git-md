Johannes Schindelin has expanded his initial Windows build fix into a full removal of the unmaintained nedmalloc allocator. The original patch simply disabled nedmalloc for MINGW builds with GCC 16, but the new version (v2) takes the opportunity to completely excise the code. This makes sense since Git for Windows has used mimalloc for years without issues, and benchmarks show no advantage over platform allocators.

The six-patch series follows a careful removal sequence: first disabling usage, then build system references, auxiliary files, and finally the large malloc.c.h in chunks. Johannes has updated all build systems (Makefile, CMake, Meson) in parallel. The change is well-structured and clearly motivated by both the immediate GCC 16 compatibility issue and the longer-term maintenance burden of keeping unmaintained code.

Patrick Steinhardt had previously suggested this full removal as a natural follow-up, and Johannes has now implemented it. The change is low-risk since the code hasn't been actively used in years, and the structured removal approach minimizes disruption. This completes the nedmalloc deprecation that began when Git for Windows switched to mimalloc.
