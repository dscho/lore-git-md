Johannes Schindelin (Dscho) has completed a series removing the obsolete nedmalloc allocator from Git's Windows builds. The removal was necessary because the unmaintained code (last updated in 2014) fails to build with GCC 16's new warnings, and Git for Windows has used mimalloc as its default allocator for years anyway.

The series followed a careful, step-by-step approach: first disabling nedmalloc usage across all build systems, then removing all build system references, and finally deleting the implementation files in chunks to work around mailing list size limits. The final patch just landed, removing the last 1827 lines of core allocator code from compat/nedmalloc.

There are no technical concerns remaining - the changes are low-risk since the code was already unused in production. The only open question is the integration mechanics: whether to squash the split deletion patches as requested or use a direct repository pull for the large file deletion. Junio Hamano and Patrick Steinhardt have previously signaled approval of the removal direction, and no new objections have been raised to the final version. This cleanup marks the completion of a deprecation path that began when Git for Windows first switched to mimalloc years ago.
