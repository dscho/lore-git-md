The thread concerns Johannes Schindelin's (Dscho) series removing the obsolete nedmalloc allocator from Git's codebase, prompted by GCC 16 compatibility issues. Git for Windows had already switched to mimalloc years ago, making this cleanup long overdue. The v3 series systematically disables and removes all nedmalloc code across all build systems (Makefile, CMake, Meson) in six carefully structured patches, with the implementation deletion split into three parts due to mailing list size constraints.

The technical work is complete and has received explicit approval from both Patrick Steinhardt and Junio Hamano. The current discussion has shifted to integration mechanics - Jeff King (Peff) suggests using `--irreversible-delete` when applying the patches to optimize repository storage, since preserving the 196KB of deleted allocator code in history isn't valuable. This reflects Git's pragmatic approach to history management for large, obsolete code removals.

No technical concerns remain, and the series is ready for integration with the maintainer's preferred approach to handling the split deletion patches. The work completes a deprecation path started years ago when Git for Windows switched allocators.
