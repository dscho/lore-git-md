This is a follow-up in Johannes Schindelin's ongoing series to fix Windows platform limitations with large objects (>4GB), specifically addressing size truncation issues caused by 32-bit types. The email responds to Torsten Bögershausen's observation that this work supersedes GitHub PR #2179 for Git for Windows.

Schindelin provides context about the challenges of splitting up the original PR into reviewable chunks that can be accepted upstream, mentioning this is part of a longer-term effort to incrementally fix the 32-bit size limitations. He references prior work (f9ba6acaa934) and another pending PR (#3533) as steps toward the same goal. The strategy of duplicating function signatures (using legacy types alongside new size_t variants) is noted as an intentional approach to make the changes more reviewable and mergeable.

The email underscores both the complexity of the underlying issue and the careful, incremental approach being taken to address it. While this particular exchange doesn't introduce new technical content, it provides useful background about the series' development context and the broader effort to improve large object handling on Windows.
