Thread identity: Windows (MINGW) build configuration patch from Johannes Schindelin, addressing a GCC 16 compatibility issue with the nedmalloc allocator.

Core problem: The vendored nedmalloc allocator, long unmaintained (last updated 2014), causes build failures with GCC 16's new -Wunused-but-set-variable warning being treated as error. Git for Windows already switched to mimalloc years ago.

Current status: Patch removes USE_NED_ALLOCATOR setting from config.mak.uname for MINGW builds, falling back to platform allocator (consistent with non-Windows builds). Nedmalloc code remains in tree but unused; potential future removal noted.

Technical details: Changes limited to build configuration (config.mak.uname). No runtime behavior change expected since Git for Windows already uses mimalloc. Windows-specific issue affecting MINGW builds with GCC 16.

Open questions: None raised in initial patch. Longer-term mimalloc integration mentioned as future direction but not blocking this change.
