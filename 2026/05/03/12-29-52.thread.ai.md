Thread identity: Windows (MINGW) build configuration patch from Johannes Schindelin, addressing a GCC 16 compatibility issue with the nedmalloc allocator.

Core problem: The vendored nedmalloc allocator, long unmaintained (last updated 2014), causes build failures with GCC 16's new -Wunused-but-set-variable warning being treated as error. Git for Windows already switched to mimalloc years ago.

Current status: Patch removes USE_NED_ALLOCATOR setting from config.mak.uname for MINGW builds, falling back to platform allocator (consistent with non-Windows builds). Nedmalloc code remains in tree but unused. Patrick Steinhardt has now raised the possibility of complete nedmalloc removal as a follow-up.

Technical details: Changes limited to build configuration (config.mak.uname). No runtime behavior change expected since Git for Windows already uses mimalloc. Windows-specific issue affecting MINGW builds with GCC 16. The compat/nedmalloc/ subtree is now orphaned with no active users.

Open questions: Whether to completely remove the unused nedmalloc code from the tree, flagged by Steinhardt as a natural follow-up but not requiring immediate action. Longer-term mimalloc integration remains a separate consideration.

Participant positions: Johannes Schindelin (author) provided detailed rationale based on Git for Windows experience. Patrick Steinhardt concurs with the approach and identifies the next potential cleanup step (full nedmalloc removal) while making clear this doesn't block the current change.

Related work: Git for Windows' prior switch to mimalloc referenced as context. Potential future work now includes both complete nedmalloc removal and proper mimalloc integration support.
