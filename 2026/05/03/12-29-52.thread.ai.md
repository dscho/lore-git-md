Thread identity: Windows (MINGW) build configuration patch series from Johannes Schindelin, completing removal of unmaintained nedmalloc allocator due to GCC 16 compatibility issues.

Core problem: The vendored nedmalloc allocator (last updated 2014) fails to build with GCC 16's new -Wunused-but-set-variable warning. Git for Windows already switched to mimalloc years ago, making nedmalloc obsolete. The series systematically removes all nedmalloc code rather than just disabling it.

Current status: v2 series progresses through removal steps. Patch 1 disabled nedmalloc usage across all build systems (Makefile, CMake, Meson). Patch 2 removed build system configuration and rules. Patch 3 deleted smaller auxiliary files (license, readme, wrapper implementation). Patch 4 removed first 2235 lines of malloc.c.h (version info, config, declarations, platform code, locking, chunk management). Patch 5 (this email) removes next 1699 lines covering "Overlaid data structures" through "System allocation" sections (memory management internals, segment handling, malloc_state, debugging). Final patch (6/6) will delete remaining implementation code.

Technical details: Changes span all build systems. Removal follows strict dependency order: disable usage first, then build system references, auxiliary files, and finally core implementation in reviewable chunks. Patch 5 specifically removes from malloc.c.h:
- Free chunk data structures (small bins as doubly-linked lists, larger chunks in trees)
- Segment management for non-contiguous regions
- malloc_state structure tracking allocation metadata
- Configuration parameters and initialization
- Debugging and statistics support
- Operations on bins and trees
No runtime behavior change (Git for Windows already uses mimalloc). Windows-specific issue affecting MINGW builds with GCC 16.
