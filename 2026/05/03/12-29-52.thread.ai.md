Thread identity: Windows (MINGW) build configuration patch series from Johannes Schindelin, completing removal of unmaintained nedmalloc allocator due to GCC 16 compatibility issues.

Core problem: The vendored nedmalloc allocator (last updated 2014) fails to build with GCC 16's new -Wunused-but-set-variable warning. Git for Windows already switched to mimalloc years ago, making nedmalloc obsolete. The series now fully removes all nedmalloc code rather than just disabling it.

Current status: v2 expands the approach from v1's single-patch disablement to complete code removal. Patches are split across 6 commits due to mailing list size constraints, following dependency order: first disable usage (patch 1), then remove build system references (patch 2), auxiliary files (patch 3), and finally the large malloc.c.h in chunks (patches 4-6).

Technical details: Changes span Makefile, CMake and Meson configurations. The removal is comprehensive - all nedmalloc-related code is excised from the tree. No runtime behavior change expected (Git for Windows already uses mimalloc). Windows-specific issue affecting MINGW builds with GCC 16. The compat/nedmalloc/ subtree is now fully removed.

Open questions: None remaining - the series addresses both the immediate GCC 16 compatibility issue and the longer-term code cleanup opportunity identified in the initial discussion. Proper mimalloc integration remains a separate consideration.

Participant positions: Johannes Schindelin (author) provides detailed rationale and structured patch series. Patrick Steinhardt had previously concurred with the approach and identified full removal as the logical next step - this series now implements that vision.
