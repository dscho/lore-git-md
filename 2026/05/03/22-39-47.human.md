Maintainer feedback on branch pruning proposal.

Junio C Hamano responds to Harald Nordgren's proposal for automatic local branch pruning during fetch operations. While appreciating the goal of keeping local branches clean, Junio suggests a more modular approach that would:

1. Separate the branch identification logic from fetch operations entirely, proposing new `git branch --forked` and `--prune-merged` options that could work independently or be triggered by fetch
2. Support more flexible remote specifications (single branches, all remotes) rather than just per-remote pruning
3. Accommodate complex workflows where branches might need to persist across multiple development phases

The maintainer raises a key architectural concern - that branch management should be decoupled from fetch operations - while acknowledging the value of the underlying functionality. He also identifies an important use case the current design doesn't address: multi-phase development where branches need to be preserved between merge rounds.

This suggests the proposal may need restructuring to provide more fundamental building blocks before implementing the fetch integration. Junio's feedback indicates the concept has merit but the implementation should be more composable and workflow-aware.
