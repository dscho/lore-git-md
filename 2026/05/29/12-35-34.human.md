This is a reply from Claus Schneider in the ongoing discussion about the proposed `git son` command. The email suggests an alternative approach focused on improving `git submodule` behavior rather than introducing a new command.

Claus proposes modifying `git submodule` to better support "loose" tracking by making ignored submodules truly ignored in both `git status` and `git add` (Currently, `git add` still stages them unless explicitly forced.) He references a pull request (#1987) that implements this change, allowing developers to track submodule branches without the constant staging friction.

The key argument is that enhancing submodules could address the original motivation for `git son` - providing a way to maintain repository relationships without tight coupling. Claus invites the thread participants to try his submodule modifications and identify any remaining gaps that would still justify a new `git son` command.

This positions as a potential middle ground between Ben Knoble's skepticism about needing a new command and Evan Haque's original proposal. The suggestion shifts focus from creating new porcelain to improving existing functionality, though it remains to be seen whether this would fully satisfy the use cases `git son` aimed to address.
