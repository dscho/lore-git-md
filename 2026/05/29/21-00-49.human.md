This is a documentation discussion about Git hook behavior, specifically around argument passing in config-based hooks. The thread continues from Wesley Schwengle's report of unexpected behavior when using npm commands as pre-push hooks.

Jeff King (Peff) responds to Wesley's concerns about hook contracts, clarifying that while the documentation shows a simplified example, real-world usage requires more awareness of hook contexts. He points out that the current `git-hook(1)` man page examples are potentially misleading, particularly for pre-push hooks which need to handle both arguments and stdin data. The pre-commit hook example works because it doesn't require arguments, but pre-push hooks have more complex requirements.

Peff acknowledges the documentation could be clearer about these nuances and cc's Adrian Ratiu (the original documentation author) for visibility.
