This is a documentation refinement in the ongoing `diff.<driver>.process` series, which introduces an external diff driver protocol similar to `filter.<driver>.process`. The patch author Michael Montalbo responds to Junio Hamano's feedback about clarifying the terminology around how the protocol handles files that the external tool considers equivalent.

The key clarification is replacing the potentially confusing "zero hunks" phrasing with "no hunks with status=success" to better describe the protocol behavior when an external diff tool considers two files equivalent. This avoids ambiguity about whether it's a special protocol message versus simply the absence of output.

The exchange shows the series is in its final stages of polishing, with Junio focusing on precise documentation wording after earlier technical reviews addressed the core implementation, test coverage, and integration concerns. Michael acknowledges the feedback and plans to update the documentation accordingly.

This refinement doesn't change the underlying functionality - the protocol still skips diff output and blame attribution when the external tool returns no hunks (now more clearly documented as such). The change primarily improves maintainability and user understanding of the feature's behavior.
