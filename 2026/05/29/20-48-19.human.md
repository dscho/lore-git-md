This is the final patch in a series introducing `diff.<driver>.process`, which allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch focuses on integrating this capability with `git blame`.

The key addition is that blame will now consult the configured diff process when determining whether a commit changed a file. If the external tool reports no hunks (indicating it considers the changes equivalent), blame will skip that commit and attribute lines to earlier commits. This is particularly useful for ignoring reformat-only changes while still catching semantic changes.

The implementation:
- Adds a new `diff_hunks_xpp()` variant that accepts pre-populated xdiff parameters
- Modifies `pass_blame_to_parent()` to use `diff_process_fill_hunks()` first, falling back to the builtin diff only if needed
- Includes comprehensive tests showing:
  - Blame attribution based on tool-provided hunks
  - Skipping reformat-only commits when the tool reports no hunks
  - Proper bypass behavior with `--no-ext-diff`

The patch maintains the series' long-running process model (one subprocess per blame session) but notes the performance impact (~17% overhead due to per-commit roundtrips). An OID-based optimization is mentioned as future work.

This completes the RFC series with all requested refinements from previous reviews, including improved error handling, bypass mechanisms, and thorough test coverage (now 106 new test lines in this patch alone). The implementation appears solid and well-tested, with clear documentation of both the happy path and edge cases.
