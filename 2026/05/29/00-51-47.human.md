This is a technical response to Junio Hamano's review of the `diff.<driver>.process` feature, which enables external tools to generate diffs for Git's diff/blame pipelines. The patch is part of an ongoing RFC series proposing structural/AST-based diff capabilities.

Michael Montalbo acknowledges Junio's concerns about global state management and error handling in the current implementation. Key points addressed:

1. **Global variables**: Agrees to refactor the subprocess_map and initialization flag to avoid globals, likely attaching them to existing structures like `userdiff_driver` or `diff_options`.

2. **Error handling**: Commits to:
   - Adding validation for negative size parameters in `send_file_content`
   - Properly distinguishing between configuration absence (normal case) vs actual failures
   - Making process startup failures visible to users rather than silently falling back
   - Improving error reporting for cases where users need to fix their configuration

3. **Protocol behavior**: Will clarify the distinction between:
   - Normal cases (no process configured)
   - Capability mismatches (not errors)
   - True failures that require user attention

The response indicates the technical approach remains sound but needs refinement in state management and error communication. The author appears receptive to addressing the concerns in a follow-up revision.
