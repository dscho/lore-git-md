This is a documentation discussion about Git hook behavior, specifically around argument passing in config-based hooks. Jeff King (Peff) responds to Wesley Schwengle's concerns about the clarity of hook contracts in the documentation.

Peff clarifies that while the example in `git-hook(1)` shows a made-up hook (`mywrapper-start-tests`) where the contract is defined by the wrapper tool, the documentation could be clearer about the expectations for native Git hooks like `pre-push`. He points out that the current example using `pre-commit` with a linter is somewhat acceptable since `pre-commit` doesn't take arguments, but the same pattern shown with `pre-push` is misleading as it doesn't address how the script would handle the hook's expected inputs.

The discussion reveals a gap in the manual where the distinction between native Git hooks (with well-defined contracts) and custom wrapper hooks (where contracts are tool-defined) isn't sufficiently explained. Peff suggests expanding the documentation to better explain these nuances and CCs Adrian Ratiu, who originally wrote these docs, for awareness.

This continues the thread's theme of balancing backward compatibility with clearer documentation, while acknowledging that some of the current examples may unintentionally suggest patterns that don't properly account for native hook contracts. The email doesn't propose specific changes but identifies areas where the documentation could be improved to prevent confusion.
