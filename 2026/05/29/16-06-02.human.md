This is a performance optimization patch targeting the delta resolution phase in `index-pack`. The change addresses a suboptimal behavior where reconstructed delta bases that are needed for resolving child deltas were being immediately freed, forcing them to be reconstructed again later.

The patch modifies `builtin/index-pack.c` to keep these intermediate delta bases in the existing cache rather than freeing them prematurely, letting the normal cache eviction policy decide when to release them. The author reports significant speedups (15-16% faster) when processing large delta-compressed packs like the Linux kernel repository, with minimal memory overhead (+1.9% RSS in the worst case).

The change is small (a single line removal) but well-motivated, with clear benchmark results showing the improvement across multiple repositories. The patch passes existing tests and includes detailed performance measurements from both synthetic and real-world repositories. This looks like a straightforward win for clone/fetch performance in delta-heavy scenarios.
