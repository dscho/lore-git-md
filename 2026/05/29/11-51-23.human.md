This is a bug report about Git's date parsing for small Unix timestamps. Luna Schwalbe found that when setting `GIT_AUTHOR_DATE` or `GIT_COMMITTER_DATE` with timestamps below 100000000 (9 digits), Git rejects them with "invalid date format", while larger timestamps work fine. The issue appears specific to the internal date format parsing - the `--date` option accepts these small timestamps but produces incorrect results (sometimes defaulting to current time, sometimes showing garbled dates).

The bug affects timestamps representing dates before March 3, 1973 (100000000 seconds since Unix epoch). The report includes clear reproduction steps and notes the behavior is consistent regardless of timezone offset or zero-padding. This looks like a legitimate parsing edge case that slipped through, likely in the date validation logic. The bug report is well-formed with specific test cases and Git commit hash for reproducibility.
