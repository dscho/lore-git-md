This is a documentation patch review from Junio C Hamano, the Git maintainer, regarding a proposed update to the `git-merge` man page. The original patch from Brandon Dong aimed to add the long-form `--message` option to match the existing short `-m` option, bringing consistency with both the implementation and other commands' documentation.

Junio points out that the documentation still doesn't fully match reality - the actual implementation also supports `--no-message` variants, which aren't mentioned in either the original or updated documentation. He notes this isn't the patch author's fault, as several other merge options with similar `[no-]` prefixes are also undocumented despite appearing in the command-line help.

The review identifies a gap between the documented interface and actual behavior, suggesting the documentation fix should be more comprehensive. Junio's observation implies the patch might need to be expanded to cover the `--no-message` case, and potentially other similarly undocumented options, to truly bring the docs in line with the implementation.

This is a substantive review that goes beyond surface-level concerns, identifying a real documentation completeness issue that affects user understanding of the command's capabilities. The original patch was well-intentioned but incomplete according to the maintainer's assessment.
