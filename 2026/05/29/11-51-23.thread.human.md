This thread documents a bug in Git's handling of very old Unix timestamps (below 100000000, corresponding to dates before 1973). Luna Schwalbe originally reported that Git inconsistently processes these small timestamps - rejecting them in environment variables like GIT_AUTHOR_DATE while sometimes accepting (but misinterpreting) them via the `--date=raw` option. 

Kristoffer Haugsbakk identified a workaround: using the `@` prefix syntax (e.g. `@0 +0000`) successfully bypasses the problematic code path. Luna's follow-up suggests documenting this workaround in the official date formats documentation, shifting the discussion toward improving user guidance while the underlying technical inconsistency remains. 

The exchange confirms the core issue appears limited to numeric parsing of small timestamps, with the `@` syntax providing a reliable alternative. While not a complete fix, this workaround gives users needing to work with pre-1973 dates a practical solution until the parsing behavior can be made consistent across all interfaces.
