The thread documents a long-standing but previously undocumented behavior in Git's date parsing - specifically how to handle very old timestamps (pre-1973) that fall below 100,000,000 in Unix time. Luna Schwalbe originally reported that Git inconsistently handles these small timestamps, with environment variables rejecting them while the `--date=raw` option sometimes produces incorrect results.

Kristoffer Haugsbakk identified that using an `@` prefix (e.g. `@0 +0000`) works around the issue, and Junio C Hamano confirmed this was an intentional but undocumented feature added back in 2012. The current email contains Junio's proposed documentation patch that formally explains this behavior in `date-formats.adoc` and adds test cases to demonstrate the correct usage. The patch doesn't fix the underlying parsing inconsistency but properly documents the intended solution, closing the 12-year documentation gap.

The key participants - Luna as reporter, Kristoffer for the workaround, and Junio providing historical context and the fix - have converged on this documentation improvement as the appropriate first step. While the core parsing behavior remains inconsistent between different timestamp input methods, that appears to be a separate issue that may be addressed later if someone chooses to tackle it. For now, users needing to work with very old timestamps have clear, tested documentation on how to properly specify them.
