This thread documents an inconsistency in Git's handling of very old Unix timestamps (those below 100000000, representing dates before 1973). When users try to specify such dates via environment variables (GIT_AUTHOR_DATE/GIT_COMMITTER_DATE) or the `--date=raw` option, Git may reject the timestamp or silently fall back to the system time. 

Luna Schwalbe reported this behavior and, with help from Kristoffer Haugsbakk and Junio C Hamano, identified a workaround: prefixing the timestamp with `@` (e.g., `@0 +0000`). This syntax was added in 2012 but never documented. Junio confirmed this was the intended solution and suggested documenting it properly. Luna has taken on writing this documentation patch, which will be their first submission to the Git project. The patch will explain the `@` prefix in `date-formats.adoc` and add test cases in `t0006-date.sh`. While the underlying parsing inconsistency remains, the documentation will make the expected behavior clear to users needing to work with ancient timestamps.
