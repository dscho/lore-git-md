The thread began with Luna Schwalbe reporting an inconsistency in how Git handles very old Unix timestamps (below 100000000, representing dates before 1973). While environment variables reject these small timestamps, the `--date=raw` option sometimes produces incorrect results. Kristoffer Haugsbakk identified a reliable workaround: using the `@` prefix syntax (e.g., `@0 +0000` for Unix epoch) which bypasses the problematic parsing path.

In the latest update, maintainer Junio C Hamano confirms the `@` prefix syntax was intentionally added in 2012 to handle ancient timestamps cleanly, though this feature was never documented. He endorses Luna's proposal to document this workaround in `Documentation/date-formats.adoc` and invites them to submit the patch. While the underlying technical inconsistency in date parsing remains unresolved, the thread now has a clear path forward to improve user documentation, with Junio encouraging Luna to contribute the change themselves. This collaborative approach addresses the immediate user-facing issue while leaving the deeper implementation quirk for potential future investigation.
