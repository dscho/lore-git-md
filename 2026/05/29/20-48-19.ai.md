This is the final patch in the v3 series introducing `diff.<driver>.process` support, focusing on blame integration. The patch enables blame to consult the external diff process when configured, allowing tools to influence blame attribution by indicating when commits should be considered "no-op" changes (like reformatting).

Key technical aspects:
- Adds `diff_hunks_xpp()` as a variant of `diff_hunks()` that accepts pre-populated xdiff parameters
- Modifies `pass_blame_to_parent()` to first consult the diff process via `diff_process_fill_hunks()`
- If the process returns no hunks (DIFF_PROCESS_EQUIVALENT), blame skips the commit entirely
- Maintains the long-running subprocess model from earlier patches
- Adds comprehensive tests showing:
  - Selective hunk reporting affecting blame attribution
  - Skipping reformat-only commits
  - `--no-ext-diff` bypass behavior

The implementation demonstrates how this could be used to make blame ignore whitespace-only or reformatting changes while still catching semantic modifications. Performance remains a consideration due to per-commit roundtrips, though the series notes potential for OID-based optimizations.

This completes the core functionality of the RFC, with all major components now implemented and tested. The patch appears technically sound with thorough test coverage (106 new test lines). The main outstanding items from earlier reviews (performance optimization and final documentation polish) would presumably be addressed before merging, but this patch represents the last major functional piece.
