This is a refactoring patch in the `diff.<driver>.process` RFC series, which aims to enable external tools to inject diff hunks into Git's diff and blame pipelines. The patch focuses on the sub-process machinery that manages child processes.

The key change splits the existing `subprocess_start()` and `subprocess_stop()` functions into two layers:
1. Lower-level `subprocess_start_command()` and `subprocess_stop_command()` that handle the core process lifecycle (setup, handshake, teardown)
2. Higher-level wrappers that maintain the existing hashmap-based process management

This separation allows callers that manage process lifetime through their own data structures (like the upcoming diff-process implementation) to reuse the process management logic without being forced into the hashmap model. The change is purely internal - existing callers like the convert subsystem continue working exactly as before.

The patch follows Git's typical refactoring style: small, focused, with clear commit message explaining the motivation. It maintains backward compatibility while enabling the new use case needed for the diff-process feature. The implementation looks straightforward and the diff shows careful attention to error handling paths.

This is a foundational piece for the larger diff-process effort, separating concerns in the sub-process API before it gets used by the new diff driver infrastructure in subsequent patches. The change appears well-considered and low-risk, with no functional changes to existing code paths.
