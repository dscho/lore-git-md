This is a documentation refinement in the ongoing `diff.<driver>.process` RFC series, which proposes allowing external tools to inject diff hunks into Git's diff and blame pipelines. The patch author, Michael Montalbo, is responding to Junio Hamano's feedback about unclear terminology in the documentation.

The key issue centers on how to describe the case where an external diff tool considers two files equivalent. Junio pointed out that the original phrasing "zero hunks" was ambiguous - it could be misinterpreted as a special protocol message rather than simply the absence of diff hunks. Michael acknowledges this and agrees to update the documentation to use clearer phrasing like "no hunks with status=success" throughout.

This exchange shows the series moving into the polishing phase, where precise wording becomes important even as the core technical implementation appears sound. The change is straightforward but meaningful for maintainability and user understanding. The thread context reveals this is part of a larger effort to enable structural/AST-based diffs while preserving Git's existing diff display capabilities.
