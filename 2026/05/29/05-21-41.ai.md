This is a technical response about Git hook argument handling, continuing a thread about config-based pre-push hooks.

Jeff King (Peff) confirms that the current behavior of passing remote name/URL arguments to config-based hooks during `git push` is expected - the `git hook` command itself doesn't know about hook-specific argument conventions. He suggests this could be better documented as a gotcha.

For the immediate need (running a command without arguments), Peff offers two shell-based workarounds: 
1) Using a comment character (#`) to discard all arguments
2) Writing a shell function wrapper to selectively process arguments

The response emphasizes that config-based hooks are primarily a scripting interface where the caller controls argument passing, rather than Git enforcing hook-specific argument patterns. This maintains consistency with the hook subsystem's design philosophy while providing practical solutions for the reported use case.

The thread remains open for further input about whether the documentation should be enhanced or if additional configuration knobs might be warranted for argument control in config-based hooks.
