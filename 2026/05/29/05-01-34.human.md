This is a question about Git's hook configuration, specifically regarding argument handling in custom hooks.

Wesley Schwengle reports that when configuring a `pre-push` hook via `git config` (setting both the event and command), the hook receives different arguments when run directly via `git hook run` versus during an actual `git push`. The direct invocation works as expected, but during a push, the hook receives remote/location arguments that break the intended `npm run test` command.

The core question is whether there's a way to configure the hook to run without any parameters, just executing the plain command as defined. The email notes this appears undocumented in `man git-hook`.

This touches on an ongoing effort to make hooks more configurable (led by contributors like Adrian Ratiu), but the specific case of argument suppression doesn't seem to have a built-in solution yet. The behavior difference between direct hook execution and automatic triggering during operations may warrant a documentation clarification or potential enhancement to the hook configuration syntax.
