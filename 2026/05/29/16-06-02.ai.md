Performance optimization for index-pack's delta resolution.

This patch addresses an inefficiency in how index-pack handles delta bases during pack indexing. Currently, when resolving a delta that itself has child deltas, the reconstructed base object is immediately freed after being queued for the next resolution pass. This forces the same base to be reconstructed again when processing those child deltas.

The change is simple - removing a single `free_base_data()` call - but the impact is significant. Benchmark results show 15-16% faster wall times for large repositories like linux.git, with minimal memory overhead (RSS increased by just 1.9% in the worst case). The patch leverages the delta base cache that's already in place rather than bypassing it.

This appears to be a well-motivated optimization that doesn't introduce new complexity - it simply removes an unnecessary premature free while letting the existing cache policy do its job. The change is focused (just 1 line removed) and the testing/benchmarking is comprehensive.
