Wesley Schwengle reported unexpected behavior when using gitconfig-configured pre-push hooks - while manual `git hook run` works as expected, automatic execution during `git push` passes remote name/URL arguments that interfere with their test command. Jeff King (Peff) confirmed this is expected behavior, explaining that config-based hooks don't enforce hook-specific argument patterns since they're designed as a general scripting interface. 

Peff provided two practical shell-based workarounds: using a comment character to discard arguments or writing a wrapper function. The core issue remains a documentation gap about argument handling differences between traditional and config-based hooks. While the immediate need can be addressed with scripting, the thread remains open for discussion about whether the documentation should be enhanced or if additional configuration options for argument control might be warranted. This could interest Adrian Ratiu, who has been working on hook configuration features.
