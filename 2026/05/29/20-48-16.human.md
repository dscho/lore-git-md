This is a refactoring patch from Michael Montalbo that's part of the larger `diff.<driver>.process` RFC series. The series aims to allow external tools to inject diff hunks into Git's diff and blame pipelines, primarily for structural/AST-based diffs.

This particular patch (3/6) separates the process lifecycle management from hashmap operations in the sub-process API. The key changes are:

1. It extracts new `subprocess_start_command()` and `subprocess_stop_command()` functions that handle just the process management (setup, handshake, teardown) without hashmap operations.

2. The existing `subprocess_start()` and `subprocess_stop()` become thin wrappers that add hashmap management on top of these new functions.

The motivation is that some callers (like the upcoming diff-process code) want to manage processes through their own data structures rather than a hashmap. This change makes the API more flexible while maintaining backward compatibility for existing users like convert.c.

The patch appears clean and focused - it's a straightforward refactoring with no functional changes to existing behavior. The commit message clearly explains the rationale, and the changes themselves are mechanical splits of existing functionality. This is preparatory work for the diff-process feature that follows in later patches.
