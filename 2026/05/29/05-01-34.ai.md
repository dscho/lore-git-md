This is a question about Git's hook configuration, specifically regarding argument handling in the `pre-push` hook when configured via `git config`.

Wesley Schwengle reports that while their configured `pre-push` hook (`npm run test`) works correctly when run manually via `git hook run pre-push`, it receives unexpected arguments when triggered automatically during `git push`. The hook gets the remote name and URL as arguments, unlike the standard pre-push hook which receives ref/object pairs. They're asking if there's a way to configure the hook to run without any parameters.

The question touches on the behavior of config-based hooks versus traditional hook scripts, particularly around argument passing. This appears to be a documentation gap rather than a bug - the man page for `git-hook` doesn't mention how to control argument passing for config-based hooks. The thread may attract attention from contributors familiar with the hook subsystem, particularly Adrian Ratiu who has been working on hook-related features.

Key technical details: the hook is configured via `hook.<name>.event` and `hook.<name>.command` directives in gitconfig, and the observed behavior shows Git passing remote information as arguments when the hook runs during push operations. The core question is about suppressing these arguments when they're not needed by the command.
