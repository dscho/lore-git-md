This is the third version of an RFC patch series introducing a new `diff.<driver>.process` feature that enables external tools to inject diff hunks into Git's diff and blame pipelines. The main motivation is to allow language-aware diff tools (like Difftastic) to provide structural/AST-based diffs while preserving Git's output formatting features like word-diff and color-moved.

The series has evolved significantly since v2 based on feedback, with key changes including:

1. Extracting subprocess management from hashmap infrastructure (new patch 3)
2. Storing the subprocess on the userdiff_driver struct rather than using global variables
3. Improved error handling with distinct warning behaviors for different failure modes
4. A single public entry point (`diff_process_fill_hunks()`) that handles all driver lookup and error reporting
5. More robust protocol documentation with packet diagrams
6. Split out bypass knobs (--no-ext-diff, format-patch) into a separate commit
7. Added SIGPIPE protection and stricter input validation
8. Changed terminology from "zero hunks" to "no hunks" throughout

The core functionality remains: an external tool can mark specific line ranges as changed while Git handles the output formatting. When the tool returns no hunks with status=success, Git treats the files as equivalent (affecting both diff output and blame attribution).

The blame integration (patch 6) shows how this can be used to skip reformat-only commits in history analysis. Performance remains a consideration - each blame commit requires a roundtrip to the tool, though an OID-based optimization is noted as future work.

The series appears technically sound with thorough test coverage (660 lines of tests). Junio Hamano's latest review focused on documentation precision, which has been addressed. Remaining work includes finalizing error handling refinements and performance optimizations before potential acceptance.
