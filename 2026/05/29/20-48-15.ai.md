This is a technical infrastructure patch (part 2/6) in Michael Montalbo's RFC series introducing the `diff.<driver>.process` configuration. The patch adds the core plumbing to store and manage the external diff processor configuration in the `userdiff_driver` struct, following the same pattern used for other driver-specific configurations like textconv and algorithm.

The changes are straightforward:
1. Adds `process` and `process_owned` fields to `struct userdiff_driver` to store the configured command
2. Teaches `userdiff_config()` to parse `diff.<driver>.process` values using the standard `git_config_string()` pattern

This is a foundational piece for the larger feature that will allow external tools to inject diff hunks into Git's diff/blame pipelines. The implementation follows Git's established configuration patterns and maintains consistency with how similar driver configurations are handled. As part of the RFC series, this change is well-contained and appears technically sound, though its full utility will only become apparent when integrated with the protocol implementation in subsequent patches.
