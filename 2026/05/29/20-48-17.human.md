This is the fourth patch in a six-part series introducing a new `diff.<driver>.process` configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines. The key feature enables tools like AST-based diff utilities to participate in Git's diff processing while preserving downstream features like word-diff and color-moved.

The patch implements the core diff process backend that communicates with external tools via a pkt-line protocol. Key aspects:

- Tools can mark specific line ranges as changed while Git controls the display formatting
- Uses long-running process model similar to Git's filter subsystem
- Handles textconv-transformed content when configured
- Includes robust error handling with fallback to builtin diff
- When tools return no hunks (status=success), files are treated as equivalent (affecting both diff output and blame attribution)
- Comprehensive test coverage (538 lines) verifies hunk handling, error recovery, and integration with features like --word-diff

The implementation appears technically sound with careful attention to edge cases. Performance considerations remain (noted ~17% overhead for blame operations), but the core protocol and integration look well-designed. This is a significant but well-contained change that could enable new diff tooling while maintaining Git's existing diff pipeline behavior.
