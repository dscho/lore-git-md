This is the fourth patch in a v3 series introducing a new `diff.<driver>.process` configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch implements the core protocol and integration with Git's diff machinery.

Key technical aspects:
- Adds a new `diff-process.c` implementing the pkt-line protocol for communicating with external diff tools
- Tools can mark specific line ranges as changed while Git handles display formatting (word-diff, color, etc)
- Supports textconv integration - tools receive transformed content if textconv is configured
- Implements graceful fallback to builtin diff on errors or invalid responses
- Includes comprehensive test coverage (538 lines) for success/error paths and feature interactions

The protocol allows tools to:
- Mark files as unchanged (no hunks with status=success)
- Provide custom hunk ranges (old/new start/count)
- Signal errors (status=error) or voluntary withdrawal (status=abort)
- Handle binary files and unmatched drivers appropriately

Notable refinements since v2:
- Subprocess management refactored to store on userdiff_driver struct
- Error handling now differentiates tool failures vs voluntary aborts
- Added SIGPIPE protection and stricter input validation
- Documentation expanded with packet diagrams and hunk format specification

The implementation appears robust with thorough test coverage. Performance considerations remain (notably ~17% blame overhead), but the core protocol and integration look technically sound. This enables use cases like AST-based diffs while preserving Git's display features.
