This is a technical response about Git hook argument handling, specifically addressing how to suppress unwanted parameters in config-based hooks.

Jeff King (Peff) responds to Wesley Schwengle's question about unexpected arguments being passed to a `pre-push` hook configured via gitconfig. While traditional hook scripts receive ref/object pairs, config-based hooks get remote name/URL arguments during automatic push operations. 

Peff clarifies this isn't a bug but rather an expected behavior - the `git hook` command is designed for scripting where callers provide appropriate arguments. He suggests two workarounds to ignore unwanted arguments:
1. Using a comment character (`#`) to discard all arguments
2. Writing a shell function wrapper for more controlled argument handling

The response highlights a documentation gap around config-based hook argument behavior that could be improved. Peff's suggestions provide practical solutions while maintaining the current hook subsystem design, avoiding the need for new configuration knobs. This keeps the solution lightweight rather than proposing architectural changes to the hook mechanism.
