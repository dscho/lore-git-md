This is a technical discussion about config-based pre-push hooks and their argument handling behavior. Jeff King (Peff) responds to Wesley Schwengle's follow-up about workarounds for suppressing unwanted arguments in hook commands.

Peff clarifies that the suggested `#` comment approach wasn't working because the config parser was interpreting it as a comment. The solution is proper quoting: `command = "npm run test #"` will preserve the comment character to discard arguments. He also explains that the shell function approach failed due to unquoted semicolons being treated as comments.

The discussion touches on to deeper design questions about whether config-based hooks should receive arguments via stdin (like traditional hooks) rather than command-line. Peff argues this would break the contract for hooks that do need the arguments, and notes that stdin is already used for ref updates in pre-push hooks, which could cause its own issues if not handled.

This continues an ongoing tension between making hooks flexible for general scripting while maintaining consistency with existing hook conventions. The immediate issue has a clear solution (proper quoting), but the thread surfaces broader questions about hook design that may need addressing in future iterations of the hook subsystem.
