This is a workflow question about optimizing Git usage in large repositories with many collaborators. The author describes their current approach of selectively fetching only `main` and their own prefixed branches (`mhughes-*`) to avoid the overhead of fetching hundreds of active branches. They're looking for a smoother way to occasionally fetch colleagues' branches without permanently adding them to their fetch config (which causes errors when those branches are eventually deleted).

The core tension is between minimizing fetch overhead and maintaining flexibility to access colleagues' work. The author has considered but rejected several approaches:
1. Explicit one-off fetches (current workflow) which don't track updates
2. Permanent fetch config entries that break when branches are deleted
3. Wildcard patterns that might accumulate cruft over time

This isn't a patch submission but rather a request for community wisdom about managing workflows in high-activity repositories. The question is well-framed and shows the author has already put thought into balancing performance with collaboration needs. Responses will likely suggest refinements to their fetch configuration or alternative commands like `git fetch --no-tags origin <branch>` for one-time access.
