This is a technical patch in the `diff.<driver>.process` RFC series, which aims to enable external tools to inject diff hunks into Git's diff and blame pipelines. The patch adds configuration plumbing for the new `diff.<driver>.process` setting, storing it in the `userdiff_driver` struct alongside existing fields like `textconv` and `algorithm`.

The change is straightforward: it's adding a new `process` field to the `userdiff_driver` struct and teaching the config parser to populate it from `diff.<driver>.process`. This is foundational work for the larger feature that will allow external diff processors to participate in Git's diff generation.

The patch itself is small (9 lines added) and mechanical, following the same pattern as existing configuration fields in the userdiff subsystem. It's part of a well-structured series that has already gone through several iterations with thorough review, including feedback from Junio Hamano. The series as a whole appears technically sound, with this particular patch being one of the simpler infrastructure pieces that enables the more complex protocol and integration work in later patches.
