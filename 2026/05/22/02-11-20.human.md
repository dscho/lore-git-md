This is the first patch in a series proposing a new `diff.<driver>.process` feature that would allow external tools to inject diff hunks into Git's diff and blame pipelines. The patch modifies xdiff internals to support externally-provided hunks.

The core change adds a new `xdl_hunk` struct and fields in `xpparam_t` to accept pre-computed hunks from callers. When these are provided, `xdl_diff()` skips its normal diff algorithm and instead populates the change markers directly from the supplied hunks. The patch includes thorough validation of the external hunks - checking bounds, ordering, and synchronization invariants - with a fallback to the built-in diff if validation fails.

This foundational change enables the rest of the series (not shown here) to implement the process protocol that would let tools like syntax-aware diff utilities participate in Git's diff pipeline while still benefiting from downstream processing like word-diff and blame. The implementation appears careful, with clear attention to safety through validation and fallback behavior.

As the first in a series, this patch focuses narrowly on the xdiff modifications needed to support the feature. The subsequent patches will build on this to add the configuration plumbing, process management, and integration with blame. The thorough test coverage (430 lines in later patches) suggests the author has considered edge cases.
