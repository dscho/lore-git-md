This is a performance optimization patch for `git stash -p` that improves its speed when fsmonitor is enabled. The patch is now in its second version, having incorporated feedback from Junio C Hamano.

The key improvement replaces the external `git read-tree HEAD` call with an in-process `unpack_trees()` operation when creating the temporary index for interactive stash selection. This preserves cached stat data and fsmonitor-valid bits for unchanged files, allowing subsequent refreshes to skip them. The change brings `stash -p`'s behavior in line with `git restore -p`'s efficient handling of unchanged files.

Performance impact is dramatic - in a 206k file repository with one changed file, time to first prompt drops from 34.774 seconds to 0.659 seconds when fsmonitor is enabled. The v2 patch adds a new performance test showing similar improvements (6.9s to 0.55s without fsmonitor, 6.83s to 0.28s with fsmonitor).

Changes from v1:
- Added unconditional `refresh_index()` call to maintain original lenient error handling
- Replaced behavioral test with performance-focused test
- Added more detailed performance measurements to commit message

The patch is well-motivated, clearly explained, and addresses all review feedback. It touches `builtin/stash.c` and adds a new performance test file. The optimization is particularly valuable for large repositories where fsmonitor can now work effectively with `stash -p`.
