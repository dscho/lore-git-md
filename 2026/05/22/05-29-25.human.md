This is a review from Junio Hamano on the first patch of a series introducing `diff.<driver>.process`, which would allow external tools to generate diffs for Git. The patch modifies xdiff to accept pre-computed hunks.

Junio raises several technical concerns about the implementation:

1. The memory handling around the `changed[]` arrays is "horrible" and brittle, though he acknowledges this may be an unavoidable consequence of xdiff's existing design.

2. He questions the fallback behavior when external hunks are invalid, suggesting:
   - The duplicate diff logic should be consolidated to avoid maintenance drift
   - Failed hunks should generate warnings (when tracing is enabled)
   - Repeated failures should perhaps disable the external processor

The review is substantive - Junio engages with the technical details of the implementation rather than just surface issues. He doesn't reject the approach outright but flags areas that need refinement, particularly around error handling and code structure. His comments suggest he's willing to consider the feature if these concerns are addressed, though his earlier thread feedback indicates he remains skeptical about the overall value proposition compared to existing textconv mechanisms.

This continues the thread's theme of the implementation being technically sound but needing stronger justification for why this new mechanism is necessary beyond what textconv already provides. Junio's focus here is on ensuring the plumbing is robust if the feature does proceed.
