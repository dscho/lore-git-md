This is Junio C Hamano's review of the `--prune-merged` documentation in Harald Nordgren's v10 patch series. The maintainer raises a significant concern about the proposed behavior where `--prune-merged` would automatically run `git fetch` for remote-tracking branch arguments.

Junio argues this creates inconsistency with Git's existing behavior - particularly with how `git branch -d` operates by checking against the current local state rather than fetching updates. He notes this automatic fetch could invalidate prior safety checks a user might have performed with `git branch --no-merged`, and prevents offline use of the feature.

The critique focuses on the principle of least surprise, suggesting the command should maintain consistency with Git's existing branch deletion semantics. This is a substantive review that goes to the heart of the feature's safety model and user expectations, coming from the project's authoritative maintainer.

The feedback implies the documentation should be revised to remove the automatic fetch behavior, making `--prune-merged` work purely against the repository's current state like other branch operations. This would align with the series' overall safety goals while maintaining consistency with Git's established patterns for destructive operations.
