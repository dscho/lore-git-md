This is part 6 of a 13-patch series (v5) enabling `--path-walk` and `--filter` interaction in `pack-objects`, with co-authorship from Derrick Stolee and Taylor Blau. The series is building on previous work in the `en/backfill-fixes-and-edges` branch.

The current patch focuses on the `git backfill` command, ensuring it properly rejects incompatible filter options. The change replaces a generic "--filter" rejection with a more precise check using the new `path_walk_filter_compatible()` function introduced earlier in the series. This ensures `backfill` only allows filters that work correctly with its path-walk-based object enumeration.

The patch adds test coverage verifying that problematic filters like `tree:1` and `blob:limit=10m` are properly rejected, while maintaining the command's core functionality. This is a defensive change that prevents users from accidentally using filters that would break `backfill`'s object-finding mechanism.

The implementation is straightforward - it swaps out the old blanket filter rejection for the new compatibility check and adds corresponding tests. This continues the series' pattern of methodically ensuring filter support works correctly across all related commands.
