This is the third patch in a 5-part series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The series follows the established pattern of Git's long-running filter process protocol.

This patch implements the core diff process protocol, enabling external tools to communicate with Git via pkt-line to provide custom diff hunk information. The tool receives file pairs and returns hunk descriptors indicating which lines changed, which Git then feeds into its standard diff pipeline. This allows specialized tools (like syntax-aware diff tools) to participate in Git's diff processing while still benefiting from downstream features like word-diff and color-moved.

Key aspects of this implementation:
- Uses the same long-running process protocol as `filter.<driver>.process`
- Handles negotiation of capabilities (currently just `hunks`)
- Includes thorough error handling with silent fallback to built-in diff
- Preserves all existing diff features by feeding external hunks into xdiff
- Adds extensive test coverage (338 lines) verifying various scenarios:
  - Correct hunk boundary handling
  - Error recovery (tool errors, crashes, invalid hunks)
  - Session state management (capability disabling after abort)
  - Integration with other Git features (--word-diff, git log -p)
  - Zero-hunk special case (suppressing diff output)

The implementation appears technically sound, following established patterns from Git's filter process protocol. The test coverage is particularly thorough, exercising both happy paths and error conditions. The patch maintains backward compatibility by falling back silently to the external tool fails or returns invalid data.

This continues the series' clear technical direction while adding the meat of the implementation. The remaining patches will cover blame integration and provide a reference implementation. The RFC status suggests the author is still seeking feedback on the approach, though this implementation appears well-considered.
