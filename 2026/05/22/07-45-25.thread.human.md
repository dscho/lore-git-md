**Thread Summary**

This thread addresses a bug where `git fetch` running as PID 1 in containerized environments (common with Go services) fails to reap terminated child processes (`git-remote-https`, `git-index-pack`), leading to zombie processes that eventually exhaust PID resources. The issue was introduced in Git 2.53.0, though the exact commit is still unknown. SURA initially reported the problem with detailed reproduction steps showing zombie accumulation in Docker containers, noting that using `tini` as an init process serves as a workaround.

D. Ben Knoble has since joined the discussion, pointing to a related February 2026 thread that may contain relevant context or solutions, though no specific fix has been proposed yet. The thread remains in the diagnostic phase, with the next steps likely involving bisecting to identify the regression commit and exploring fixes for Git's subprocess handling when running as PID 1. While not urgent due to the `tini` workaround, this is a genuine resource leak that needs addressing in Git's core process management logic.
