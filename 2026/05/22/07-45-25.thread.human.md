This thread discusses a `git fetch` issue where child processes become zombies when Git runs as PID 1 in container environments, particularly affecting fast-terminating subprocesses like `git-remote-https`. SURA originally reported the problem with a detailed reproduction case, noting it was introduced in Git 2.53.0. D. Ben Knoble later pointed to a potentially related discussion from February 2026 about similar process handling issues.

brian m. carlson has now responded, arguing this isn't a Git-specific problem that needs fixing but rather a standard characteristic of PID 1 behavior in containers. They recommend using an init process like `tini` as the reporter's workaround already does - rather than changing Git's process management. While this provides useful context about container best practices, it leaves the core technical question unanswered: whether Git's subprocess handling could be improved to avoid zombie accumulation even when running as PID 1. The thread remains open with no proposed code changes, though the discussion has clarified that the solution may lie in container configuration rather than Git modifications.
