This thread reports a zombie process issue in `git fetch` when running in containerized environments where Git becomes PID 1 (common in Go-based services). The reporter, SURA, documents how `git-remote-https` and `git-index-pack` subprocesses can remain as zombies after the parent `git fetch` exits, eventually exhausting PID resources. The problem appears to have been introduced in Git 2.53.0, though the exact commit hasn't been identified yet.

While not urgent (the reporter already worked around it using `tini` as an init process), this represents a real resource leak in containerized deployments. The issue seems most likely to occur with fast-terminating fetch subprocesses that the parent doesn't properly wait for. The report provides clear reproduction steps but doesn't propose a solution, instead focusing on documenting the behavior for maintainers to investigate.
