This is the second patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch adds the configuration plumbing for the new feature, following the same pattern as Git's existing `filter.<driver>.process` protocol.

The changes are minimal and focused - just adding a new `process` field to the `userdiff_driver` struct and the corresponding config parsing logic in `userdiff_config()`. The implementation mirrors how textconv and algorithm settings are handled in the same file, suggesting it's following established patterns.

This is a straightforward infrastructure patch that enables the core functionality to be built in subsequent patches. The RFC status from the cover letter indicates the series is still seeking architectural review, but this particular patch looks uncontroversial plumbing work. The next patches will implement the actual process protocol and integration with diff/blame.
