This is a test infrastructure patch in the ongoing `pack-objects --path-walk --filter` series. Patch 10/13 modifies the test setup in `t/t6601-path-walk.sh` to create tagged tree objects that are truly unreachable from any commit, rather than being reachable from abandoned commits as in the previous version.

The key technical change replaces the old approach (creating commits and then amending them away while keeping tags on their trees) with direct creation of tree objects via `git mktree` that are only referenced by tags. This better isolates the behavior being tested - specifically how path-walk handles tagged trees that aren't reachable via commits.

The patch demonstrates careful attention to test coverage by ensuring the scenario being tested (handling of unreachable tagged trees) is properly isolated. This was motivated by discovering a bug in earlier versions where such trees were being silently dropped when using `tree:0` filters. The new test setup makes this edge case explicit while maintaining all other test conditions.

This is a preparatory change that doesn't modify the core functionality but strengthens the test coverage for the filter integration work in the rest of the series. The commit message clearly explains both the change and why it matters for testing the path-walk behavior.
