This is a performance optimization patch for `git stash -p` that improves its speed when fsmonitor is enabled. The patch is version 2 of a series that has already undergone review from Junio C Hamano, with all concerns addressed.

The core issue is that `git stash -p` currently creates a temporary index by shelling out to `git read-tree HEAD`, which discards all cached stat data and fsmonitor-valid bits. This forces a full refresh of every tracked file when interactive selection begins. The patch replaces this with an in-process `unpack_trees()` call using `oneway_merge()`, which preserves cached entries for unchanged files, allowing fsmonitor to skip them during refresh.

Performance improvements are substantial - in a 206k file repository with one changed file, time to first prompt drops from 34.774 seconds to 0.659 seconds when fsmonitor is enabled. The v2 patch adds a new performance test showing similar improvements (6.90s to 0.55s without fsmonitor, 6.83s to 0.28s with fsmonitor).

Key changes in v2:
1. Added unconditional `refresh_index()` call to maintain original lenient error handling behavior
2. Replaced the behavioral test with a performance test
3. Added more detailed measurements to the commit message

The implementation is clean and focused, touching only `builtin/stash.c` and adding the new performance test. The patch builds on fsmonitor optimizations by Paul Tarjan and aligns with similar optimizations in `git restore -p`. With all review feedback addressed, this appears ready for inclusion.
