This is the first patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch modifies xdiff (Git's diff engine) to accept pre-computed hunks from callers via new `xpparam_t` fields.

The key changes:
- Adds `xdl_hunk` struct to represent diff hunks with old/new line ranges
- Extends `xpparam_t` with `external_hunks` and `external_hunks_nr` fields
- Implements validation logic for externally-provided hunks (bounds checking, ordering, sync invariants)
- Falls back to built-in diff algorithm if validation fails
- Skips `trim_common_tail()` when using external hunks since they reference original line numbers

The implementation appears thorough, with careful attention to edge cases and safety. The validation ensures external hunks can't corrupt Git's internal state, and the graceful fallback maintains backward compatibility. This foundational change enables the subsequent patches to build the process protocol plumbing.

As the first technical piece of a larger RFC proposal, this patch focuses narrowly on the xdiff integration while leaving the higher-level protocol and configuration for later in the series. The changes are well-contained to xdiff internals with minimal interface impact.
