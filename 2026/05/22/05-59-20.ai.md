This is a follow-up in the external notes helper thread, where Siddh Raman Pant responds to feedback from Jeff King (Peff) and Johannes Sixt regarding timeout handling in the proposed feature.

Pant acknowledges the clear consensus against implementing timeouts in core Git for the external notes helper, agreeing to remove the controversial timeout commit (patch 4/9) from the next version of the series. This comes after Peff reinforced Sixt's position by drawing parallels to existing Git features like textconv filters and batch operations that handle long-running processes without timeouts, citing concerns about non-determinism and signal handling risks.

The exchange demonstrates the project's preference for consistency with established patterns over introducing new process management mechanisms, even when the proposed timeouts were intended as a robustness measure. Pant's response indicates the series will proceed in v2 without the timeout functionality, though the broader architectural discussion about failure recovery in external processes remains unresolved.
