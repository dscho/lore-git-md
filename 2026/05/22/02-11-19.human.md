This is an RFC proposal for a new feature that would allow external tools to provide diff hunks to Git's diff and blame pipelines via a long-running subprocess protocol. The patch series introduces a `diff.<driver>.process` configuration that works similarly to `filter.<driver>.process`, enabling tools that understand code structure (like tree-sitter parsers or format-aware analyzers) to integrate with Git's existing diff features (word diff, function context, color-moved, etc.) rather than having to bypass them entirely.

The key idea is that external tools can now participate in Git's diff pipeline by implementing a protocol that exchanges file pairs and hunk descriptors over stdin/stdout. When configured, Git will use the tool's hunk output for operations like `git diff` and `git blame`, falling back silently to built-in diff if the tool fails. The series includes a built-in example tool (`git diff-process-normalize`) that implements whitespace-ignoring comparison similar to `git diff -w`.

This appears to be a well-constructed proposal with thorough documentation (including new sections in config and gitattributes manpages) and comprehensive test coverage (a new 430-line test script). The implementation touches core diff infrastructure (xdiff, userdiff, blame) but seems carefully scoped to avoid disrupting existing behavior. The RFC status suggests the author is seeking feedback on the design approach before further iteration.

The feature fills a notable gap - currently external diff tools must replace Git's entire diff pipeline rather than augmenting it. This could enable richer integration with structural diff tools while preserving Git's existing diff features, though the performance implications of process overhead would need evaluation for large-scale use.
