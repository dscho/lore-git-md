This is a documentation patch clarifying the behavior of `push.default=simple` in triangular workflows (where the push remote differs from the upstream remote). The patch adds a note to the `push.adoc` man page explaining that in such cases, Git falls back to the 'current' behavior, which pushes the current branch to a branch of the same name on the remote. This aligns the documentation with the actual implementation in `builtin/push.c`.

The change is straightforward and uncontroversial - it documents existing behavior rather than introducing new functionality. The commit message clearly explains the motivation (preventing user confusion) and the patch itself is minimal and focused. This appears to be a useful clarification for users working with triangular workflows who might otherwise be surprised by the behavior.
