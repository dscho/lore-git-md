This is a review comment from Johannes Sixt on the first patch of Harald Nordgren's series adding `git branch --forked` functionality. The patch introduces infrastructure for identifying local branches that track specified upstreams, which will later support safe automated branch cleanup via `--prune-merged`.

Johannes suggests making `--forked` a filter for `--list` mode rather than a standalone operation, proposing that it should:
- Take a single argument per option (allowing globs)
- Be repeatable to combine multiple patterns
- Work naturally with other filters like `--merged`

He provides concrete wording suggestions for the documentation, noting the current phrasing could be clearer about the filtering behavior. The review is substantive - it engages with the design of the user interface rather than just surface-level issues, though it doesn't dig into implementation details.

The comment hints at the useful combination of `--forked` with `--merged` that would become possible with this change, showing how the feature could be used in practice. This is part of an ongoing discussion about the best way to structure this functionality, with Junio C Hamano also providing feedback on the series organization.
