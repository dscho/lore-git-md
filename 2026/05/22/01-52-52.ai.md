This is Junio C Hamano's review of the first patch in Harald Nordgren's v10 series adding `git branch --prune-merged` functionality. The review focuses on the foundational `--forked` option that identifies local branches tracking specified upstreams.

Junio identifies several technical concerns with the implementation:

1. The patch unnecessarily modifies `check_branch_commit()` and `delete_branches()` functions when they aren't directly relevant to the `--forked` feature. He questions why these changes are included in this patch rather than being split out.

2. He suggests the warning messages about unmerged branches could be improved to specify which upstream branch they're expected to merge with, though acknowledges this is outside the current scope.

3. The review notes the `n_not_merged` counter parameter seems redundant since callers could track failures themselves.

4. For the glob pattern matching, Junio suggests optimizing by tracking which patterns need wildcard matching during initial parsing rather than always using `wildmatch()`.

The core `--forked` implementation (pattern parsing and branch matching logic) receives no substantive objections, indicating the architectural approach is sound. However, Junio's feedback implies the patch needs restructuring to:
- Remove unrelated changes to deletion logic
- Optimize the pattern matching
- Potentially improve warning messages

This review will require Harald to revise the patch to address these concerns while maintaining the core functionality that enables the series' safe branch pruning goals.
