This is part 4 of a 13-patch series (v5) enabling `--path-walk` to work with various `--filter` options in `git pack-objects`. The series is a collaboration between Derrick Stolee and Taylor Blau.

The current patch fixes a subtle issue where directly-requested objects (like blob targets in partial clones) could be incorrectly filtered out when using path-walk with filters. The key change ensures objects explicitly requested (marked with paths starting with '/') bypass type filters, while still applying filters to objects discovered during tree traversal.

The patch adds documentation explaining this behavior and introduces a helper function `path_is_for_direct_objects()` to make the special handling of these paths explicit. The implementation modifies `walk_path()` and `setup_pending_objects()` to respect this distinction, while maintaining backward compatibility.

This appears to be a well-considered fix for an edge case that could cause data loss in filtered partial clones. The changes are focused and come with clear documentation updates. As part of a carefully reviewed series that has gone through multiple iterations, this patch seems ready for inclusion.
