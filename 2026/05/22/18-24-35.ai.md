This is patch 11/13 in the fifth iteration of a series enabling `--path-walk` to work with various `--filter` options in `git pack-objects`. The patch specifically adds support for the `tree:0` filter, which omits all trees and blobs from the output while keeping commits and tags.

The key technical changes involve:
- Setting `info->trees = 0` and `info->blobs = 0` in `prepare_filters()` when `LOFC_TREE_DEPTH` is requested
- Fixing how the path-walk API handles directly-requested trees and trees requested through lightweight tags
- Rejecting non-zero tree-depth filters with a helpful error message
- Adding comprehensive test coverage in t6601-path-walk.sh for both `--all` and single-branch cases

The patch demonstrates careful attention to edge cases, particularly around tagged tree objects that aren't reachable from commits. The test changes show improved isolation by using `git mktree` to create truly unreachable trees rather than relying on abandoned commits. This builds on the series' earlier fixes for the `tree:0` filter case where tagged trees were being silently dropped.

The implementation maintains compatibility with existing sparse-checkout workflows while establishing infrastructure for potential future filter types. With this patch, the series now supports all major filter types (`blob:none`, `blob:limit`, `sparse:oid`, `tree:0`, `object:type`, and `combine`) in combination with `--path-walk`.

Co-authored by Taylor Blau and Derrick Stolee, this version appears to be the final refinement before potential merging, with only minor implementation details remaining open in later patches of the series.
