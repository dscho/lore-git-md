This is the final patch in a series introducing a new `diff.<driver>.process` feature, which allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch adds a built-in whitespace normalizer tool (`git diff-process-normalize`) that detects and suppresses whitespace-only changes, serving as a reference implementation for the new protocol.

The tool uses the same whitespace comparison logic as `git diff -w` (via `xdiff_compare_lines()` with `XDF_IGNORE_WHITESPACE`). When configured via `diff.cdiff.process`, it will:
- Return zero hunks for files with only whitespace changes (making them appear unchanged in `git diff` and `git blame`)
- Trigger fallback to Git's built-in diff algorithm for files with non-whitespace changes

The implementation includes thorough test coverage demonstrating:
- Suppression of whitespace-only diffs
- Proper fallback behavior for real changes
- Handling of mixed whitespace/content changes
- Integration with the diff and blame pipelines

This completes the RFC series, providing both the infrastructure and a practical example of how the new diff process protocol can be used. The whitespace normalizer is particularly useful for skipping reformatting commits in blame output without requiring a `.git-blame-ignore-revs` file. The series appears well-tested and ready for final review, with this patch serving as documentation of intended usage patterns through its built-in example.
