This is the final patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The series has already landed the core infrastructure in previous patches (xdiff modifications, configuration plumbing, and blame integration).

Patch 5 adds a built-in demonstration tool called `git diff-process-normalize` that detects whitespace-only changes. When configured as a diff process, it will:
- Return zero hunks for files that only have whitespace differences (making them appear unchanged in diffs and skipped in blame)
- Fall back to Git's normal diff algorithm when non-whitespace changes exist

The implementation uses Git's existing `xdiff_compare_lines()` with `XDF_IGNORE_WHITESPACE` (same logic as `git diff -w`). The patch includes thorough documentation and test cases showing:
- Whitespace-only changes being suppressed
- Non-whitespace changes falling back to normal diff
- Mixed whitespace/content changes being properly detected

This provides a practical use case for the new diff-process feature, particularly useful for skipping reformatting commits in blame without needing a `.git-blame-ignore-revs` file. The implementation follows the same protocol pattern established in earlier patches and maintains the series' high standard of test coverage.

With this final piece, the series appears complete and well-tested, demonstrating both the infrastructure and a compelling use case. The whitespace normalizer serves as both a useful tool and a reference implementation for other potential diff processors.
