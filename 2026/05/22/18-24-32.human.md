This is part 8 of a 13-patch series (v5) from Derrick Stolee and Taylor Blau that enables `--path-walk` to work with various `--filter` options in `git pack-objects`. The series is building towards full interoperability between path walking and object filtering.

This particular patch introduces a new `pl_sparse_trees` flag in the path_walk_info struct to control whether sparse patterns should prune trees in addition to blobs. The motivation is to support both `git backfill --sparse` (which needs to prune trees) and future sparse-oid filters (which should only filter blobs while keeping all trees).

The key changes are:
1. Adding the flag and setting it in `builtin/backfill.c` to maintain current behavior
2. Moving the SEEN flag assignment in `add_tree_entries()` to after sparse/path checks, fixing an edge case where identical objects at multiple paths could be incorrectly skipped
3. Adding test coverage that demonstrates the difference in behavior when the flag is toggled

The patch shows careful attention to edge cases, particularly around the interaction between sparse patterns and object marking. The test additions are thorough and help document the expected behavior. This continues the series' pattern of methodical, well-tested changes to the path-walk infrastructure.
