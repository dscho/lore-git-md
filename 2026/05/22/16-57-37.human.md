This is a discussion thread about a bugfix for git-gui's worktree detection logic. The conversation clarifies the specific edge case where the issue occurs and confirms the current behavior is actually working as intended.

Mark Levedahl responds to Shroom Moo's detailed reproduction scenario, explaining that when GIT_DIR is manually set to point to a worktree's gitdir while running from a different directory, Git's documented behavior is to use the current directory as the worktree. This means the original issue Shroom identified isn't actually a bug - the system is behaving as designed when GIT_DIR is explicitly set this way.

The key takeaway is that git-gui's current worktree detection logic correctly follows Git's core behavior in this edge case. While the scenario is unusual (requiring manual GIT_DIR manipulation and running from a non-repo directory), the behavior aligns with Git's documented expectations. This thread serves to clarify the intended behavior rather than proposing any code changes.
