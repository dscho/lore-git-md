Junio C Hamano has raised a critical design concern about the `--prune-merged` functionality in Harald Nordgren's branch cleanup series. The maintainer objects to the automatic `git fetch` behavior when pruning remote-tracking branches, arguing it creates inconsistency with Git's existing behavior and user expectations.

The core issue is that `git branch -d` checks reachability against the current local state, while the proposed `--prune-merged` would fetch updates first, potentially changing what's considered "merged" without the user. This could invalidate prior safety checks done with `git branch --no-merged` and prevents offline use of the feature.

This is a significant architectural feedback that will likely require redesign of the remote-tracking branch handling in the series. Junio's position suggests the command should work purely against the repository's current state rather than fetching updates, maintaining consistency with Git's existing branch deletion semantics. The comment implies the current approach may not be mergeable without addressing this fundamental design mismatch.
