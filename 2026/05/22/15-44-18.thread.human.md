This thread addresses a bug in `receive-pack` where environment variable leakage between `push_to_checkout()` and `push_to_deploy()` operations was causing issues, particularly when `core.worktree` was configured. The regression was introduced by commit a8cc594333 ("hooks: fix an obscure TOCTOU 'did we just run a hook?' race"), which changed hook execution flow without accounting for environment variable side effects.

Alyssa Ross submitted a fix (v2) that moves the `GIT_WORK_TREE` environment variable setting to only affect hook execution rather than the shared environment. The change is minimal but well-targeted, accompanied by a new test case that verifies the fix works with `core.worktree` configurations. Junio C Hamano confirmed the technical correctness of the solution and suggested improving the commit message, which Alyssa incorporated in v2. The test case provides solid regression protection, and there are no outstanding technical concerns about the fix. This resolves a specific but important edge case in the receive-pack workflow.
