The reference (lore.kernel.org/git/202602231615147.3294516-1-cshung@gmail.com) appears to document another instance where Git's subprocess management interacts poorly with container init systems.

This adds context to SURA's original report by showing the zombie process issue isn't entirely novel, though the specific manifestation in `git fetch` appears to be a regression since Git 2.53.0. The connection to prior discussions could help identify whether this stems from the same root cause or represents a distinct bug in the fetch machinery.

The thread remains in an investigative phase - no proposed fix yet, but the cross-referencing of related issues suggests contributors are working to understand the scope of the problem. Container users running Git as PID 1 should be aware of this behavior, with `tini` remaining the current workaround.
