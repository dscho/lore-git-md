Thread identity: Bug report about `git fetch` process handling in container environments where Git runs as PID 1, causing zombie processes when child processes (`git-remote-https`, `git-index-pack`) terminate before being reaped. Introduced in Git 2.53.0 (exact commit unknown). Reported by SURA.

Core problem: When `git fetch` runs as PID 1 in containerized environments (common with Go services), terminating child processes become zombies that aren't reaped, eventually exhausting PID resources. The issue specifically affects fast-terminating fetch subprocesses that the parent doesn't wait for properly.

Current status: Unfixed, though reporter has a workaround using `tini` as init process. No patch proposed yet.

Key technical details: Affects `git fetch` subprocess handling, particularly `git-remote-https` and `git-index-pack`. Reproduction steps provided show zombie process accumulation in Docker containers where the service acts as PID 1.

Open questions: Exact commit that caused regression needs bisecting. Solution approach not yet proposed - could involve proper signal handling when running as PID 1 or changes to process waiting logic.

Participant positions: Only SURA has commented so far, providing detailed bug report but no proposed fix.
