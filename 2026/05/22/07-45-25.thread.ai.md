Thread identity: Bug report about `git fetch` process handling in container environments where Git runs as PID 1, causing zombie processes when child processes (`git-remote-https`, `git-index-pack`) terminate before being reaped. Introduced in Git 2.53.0 (exact commit unknown). Reported by SURA, with follow-up from D. Ben Knoble, brian m. carlson, and Jeff King.

Core problem: When `git fetch` runs as PID 1 in containerized environments (common with Go services), terminating child processes become zombies that aren't reaped, eventually exhausting PID resources. The issue specifically affects fast-terminating fetch subprocesses that the parent doesn't wait for properly. Recent Git version changes (2.29, 2.47) altered process detachment behavior, increasing zombie generation frequency.
