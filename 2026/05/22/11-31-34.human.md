This is patch 2/6 in Harald Nordgren's v11 series adding `git branch --prune-merged` and `--forked` for safe automated branch cleanup. The patch modifies the error handling when deleting branches that aren't fully merged, allowing bulk operations to continue with warnings rather than failing on the first unmerged branch.

The key change introduces a `warn_only` flag to `delete_branches()` and `check_branch_commit()`. When set, unmerged branches trigger a one-line warning instead of the full error message with deletion advice. This maintains the safety checks while making bulk operations more usable - the caller can see which branches would need `-D` to force deletion, but the operation continues rather than aborting.

The patch builds on the series' safety focus by preserving all existing validation (checked-out branch protection, missing upstream detection) while making the interface more practical for automated cleanup. The implementation is clean, with clear separation between the warning and error paths, and maintains backward compatibility by defaulting `warn_only` to 0 for existing callers like `git branch -d`.

This appears to be a well-considered refinement addressing real-world usability needs while keeping the safety guarantees that have been carefully built up through the series' 11 iterations. The change is focused and clearly motivated as part of the larger `--prune-merged` effort.
