This is the fourth patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch focuses on integrating this capability with `git blame`.

The key addition is that `git blame` will now consult the configured diff process when determining whether a commit changed a file. If the diff process returns zero hunks (indicating it considers the files equivalent), blame will skip that commit and attribute lines to earlier commits instead. This is particularly useful for cases like whitespace-only changes or reformatting where the semantic content hasn't changed.

The implementation:
- Modifies the `diff_hunks()` function in blame.c to optionally use the diff process
- Adds proper cleanup of allocated hunk data
- Includes a test case showing how blame skips a reformatting commit when the diff process reports no semantic changes

The patch maintains backward compatibility by falling back to the built-in diff when no process is configured. The test coverage is thorough, demonstrating both the normal blame behavior and the new zero-hunk skipping behavior.

This continues the series' pattern of careful integration with existing Git features while adding new capabilities. The implementation appears technically sound, following established patterns for process-based integrations. The zero-hunk detection in blame is a natural extension of the diff process functionality introduced earlier in the series.
