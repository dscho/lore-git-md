This is a technical discussion about timeout handling in Git's external notes helper infrastructure, with Jeff King (Peff) weighing in to support Johannes Sixt's position.

Peff reinforces Sixt's argument against implementing timeouts in core Git by drawing parallels to several existing Git mechanisms that handle long-running processes without timeouts:
- Textconv filters and external diffs during git-log
- Long-lived clean/smudge filters
- `cat-file --batch` operations

He expresses concern about the non-determinism introduced by timeouts and highlights technical risks in the run-command changes, referencing past issues with child process cleanup that led to reverts in Git 2.54. Peff notes particular worry about signal handling when shells are involved between Git and the subprocess.

While Peff takes no position on the external notes feature itself, he strongly advocates for consistency with Git's existing approach to similar process interactions. His intervention carries weight given his deep experience with Git's process management and past cleanup work.

This continues the architectural debate without resolution, but adds significant technical credibility to Sixt's position through Peff's examples of analogous Git features that don't use timeouts. The exchange remains focused on whether timeouts belong in core Git or should be handled at a higher level.
