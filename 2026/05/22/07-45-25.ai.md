Bugfix targeting `git fetch`'s process handling in container environments.

SURA reports a zombie process issue in `git fetch` when running in Docker containers where the application service acts as PID 1 (common in Go services). The problem manifests when child processes terminate but aren't properly reaped, eventually exhausting PID resources. The report includes clear reproduction steps showing how `git-remote-https` and `git-index-pack` subprocesses can become zombies when the parent `git fetch` exits.

The issue appears to have been introduced in Git 2.53.0, though the exact commit isn't identified. While not urgent (the reporter has already worked around it using `tini` as an init process), this does represent a real resource leak in containerized environments. The problem seems most likely to occur with fast-terminating fetch subprocesses that the parent doesn't wait for properly.

This is a legitimate bug report with good technical details, though it would benefit from bisecting to identify the exact regression point. The container-specific nature of the issue means it might not affect most users, but it's still worth fixing for those running Git in PID 1 scenarios. The report stops short of proposing a solution, instead just documenting the behavior.
