This is a bug report about zombie processes left behind by `git fetch` in Docker containers where the main process (PID 1) doesn't handle process reaping. The reporter, SURA, provides clear reproduction steps showing how child processes from `git fetch` become zombies when running in a container with an application service as PID 1 (like a Go service).

The issue appears to have been introduced in Git 2.53.0, though the reporter notes it's not urgent since they've already worked around it by using `tini` as the init process. The report is well-documented with process listings showing the zombie processes persisting after fetch completes.

This seems like a legitimate edge case in process handling that could affect containerized environments, particularly those using non-traditional init systems. While not critical (given the workaround), it's the kind of subtle system interaction that might warrant a fix to make Git more robust in container scenarios. The report doesn't propose a solution, just documents the behavior.
