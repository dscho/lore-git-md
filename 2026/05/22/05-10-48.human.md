This is a technical discussion about timeout mechanism design for Git's external notes helper feature, with Jeff King (Peff) weighing in to support Johannes Sixt's position against core-level timeouts.

Peff reinforces Sixt's argument by drawing parallels to several existing Git features that handle long-running external processes without timeouts: textconv filters, clean/smudge filters, and `cat-file --batch`. He notes these features rely on the external commands being well-behaved rather than Git enforcing timeouts. 

The review raises two key technical concerns about the proposed timeout mechanism:
1. The non-determinism introduced by timeouts could cause problems
2. The interaction with shell processes and signal handling (particularly SIGKILL) is tricky, referencing recent issues with child process cleanup that led to a revert

Peff's position aligns with Sixt's view that Git should treat external helpers consistently across all similar features, rather than introducing special timeout handling for notes. While he doesn't oppose the external notes feature itself, he strongly questions the architectural choice to implement timeouts at the Git core level.

This review adds significant technical credibility to the anti-timeout position, bringing concrete examples from existing Git behavior and pointing to recent pain points in process management. As a respected contributor with deep knowledge of Git's internals, Peff's concerns about signal handling and consistency with other features will likely carry weight in the ongoing discussion.
