This is patch 4/6 in Harald Nordgren's v11 series adding `git branch --prune-merged` for safe automated local branch cleanup. The patch implements the core functionality to delete local branches that are merged into their upstream, with several safety mechanisms.

The new `--prune-merged` option builds on the `--forked` functionality from earlier patches to identify candidate branches, then applies additional checks before deletion:
- Branches must be reachable from their configured upstream (checked locally without fetching)
- Three types of branches are preserved: checked-out branches, those with missing upstreams, and branches where push destination equals upstream (to protect trunk branches)
- Uses warn-only mode so unmerged branches don't abort the entire operation
- Disables HEAD fallback to focus on upstream-merged status

The implementation refactors the branch collection logic from `--forked` into a reusable `collect_forked_set()` function shared between both commands. It then adds the actual pruning logic in `prune_merged_branches()` which:
- Collects candidate branches using the shared function
- Applies the safety checks
- Calls `delete_branches()` with appropriate flags (warn-only, no HEAD fallback)
- Includes comprehensive tests covering all edge cases

Key technical details:
- Uses existing `delete_branches()` infrastructure with new flags
- Compares `@{push}` vs `@{upstream}` to identify trunk branches
- Preserves all prior safety checks from earlier versions
- Maintains identical behavior between dry-run and actual execution
- Test coverage includes:
  - Literal and glob pattern matching
  - Local vs remote upstreams
  - Checked-out protection

  - Warning messages
