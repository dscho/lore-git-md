This is a follow-up review comment on a git-gui bugfix series that has already received maintainer approval. The patch in question (v2 03/11) simplifies repository path handling by using `git rev-parse --absolute-git-dir` instead of manual path resolution.

Johannes Sixt (git-gui maintainer) confirms the technical approach is sound with a "Very good!" but notes that a comment about `.git` directory behavior needs updating to reflect the new implementation. The original comment warns that `--git-dir` returns "." when run from the .git directory, but with `--absolute-git-dir` this edge case no longer exists.

This is a minor documentation tweak to an otherwise approved patch. The series as a whole addresses long-standing git-gui issues with repository and worktree detection, and this particular change makes the path resolution more robust by relying on Git's built-in absolute path handling rather than manual conversion. The maintainer's feedback suggests the patch will be ready for merging once this small comment update is made.
