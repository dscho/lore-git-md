This is patch 3/6 in Harald Nordgren's v11 series adding `git branch --prune-merged` for safe automated branch cleanup. The patch prepares the underlying `delete_branches()` function for bulk operations by adding two new flags: `no_head_fallback` and `dry_run`.

The key changes are:
1. `no_head_fallback` allows callers to skip the implicit HEAD fallback check when determining if a branch is merged, which is important for the bulk pruning case where we only care about upstream merges.
2. `dry_run` adds a preview mode that shows what would be deleted without actually deleting anything, matching the output format of real deletions.

The patch modifies `branch_merged()` to skip the "merged to upstream but not HEAD" warning when `head_rev` is NULL (which happens with `no_head_fallback`), since that warning is irrelevant for bulk operations. It also updates the ref deletion logic to either show dry-run messages or perform actual deletions based on the flag.

Existing callers (like `git branch -d`) continue working unchanged by passing 0 for both new parameters. The changes maintain all existing protections while enabling the new bulk pruning functionality to be built on top in subsequent patches.

This is a technical refactoring that enables the core safety features of the series - particularly the ability to preview deletions and avoid HEAD-based warnings during bulk operations. The implementation is clean with focused changes to the branch deletion machinery.
