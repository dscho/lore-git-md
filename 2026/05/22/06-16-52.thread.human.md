This thread examines a Windows compatibility patch that modifies signal handling in Git's Windows port. The core question is whether Git's Windows emulation layer should distinguish between Unix signals like SIGTERM and SIGKILL when the underlying Windows API (`TerminateProcess`) treats all termination requests identically.

Siddh Raman Pant has provided key technical clarification, citing Microsoft documentation showing Windows lacks Unix-style signal semantics - processes cannot block termination, and SIGTERM exists only for ANSI compatibility. This supports the patch's approach of treating all termination signals the same way via `TerminateProcess()`.

While the technical justification appears solid, the discussion remains open pending review from Windows experts Johannes Sixt and Johannes Schindelin (Git for Windows maintainer). Their input is needed to confirm whether this interpretation holds for all edge cases Git might encounter, or if there are platform-specific considerations the documentation doesn't capture. Junio C Hamano's original questions about future signal handling (like SIGQUIT) also remain open, though the current patch focuses only on termination signals.
