This thread examines how Git should handle Unix signals like SIGTERM and SIGKILL on Windows, where the native process model differs significantly. The discussion began with a patch proposing to treat all termination signals identically via TerminateProcess(), justified by Microsoft's documentation showing Windows lacks Unix-style signal semantics. 

Johannes Schindelin (Git for Windows maintainer) has now revealed that Git for Windows already implements more nuanced behavior - distinguishing SIGTERM by allowing atexit() handlers to run, while other signals trigger immediate termination. This existing implementation, which better preserves Unix expectations, was never upstreamed. Schindelin has committed to preparing those patches, making the current proposal obsolete.

The thread now awaits Schindelin's submission of Git for Windows' more complete signal emulation. Once those patches arrive, they'll need review from both Windows experts (like Johannes Sixt) and core maintainers to ensure the approach works across Git's codebase. The original question about Windows signal handling has been answered: while the platform's native API is simpler, Git can and should maintain Unix-compatible behavior where practical.
