This thread explores how Git should handle process termination signals on Windows, where the native API differs from Unix semantics. The discussion began with a proposal to unify SIGTERM and SIGKILL handling via Windows' TerminateProcess(), but took an unexpected turn when Johannes Schindelin (Git for Windows maintainer) revealed his fork already implements more nuanced behavior - allowing atexit() handlers to run for SIGTERM while using immediate termination for SIGKILL. 

After examining Windows API documentation (provided by Siddh Raman Pant) confirming the platform lacks true Unix signal semantics, maintainer Junio C Hamano has now accepted Schindelin's plan to upstream the existing Git for Windows implementation. This puts the original patch on hold and shifts focus to reviewing Schindelin's upcoming submission, which will bring the more sophisticated signal handling already working in Git for Windows into the main project. The thread is now in a holding pattern awaiting these patches, at which point reviewers can evaluate whether this solution meets all needs while maintaining compatibility.
