This thread discusses a proposed change to Windows signal handling in Git's compatibility layer. The original patch would modify `mingw_kill()` to treat both `SIGTERM` and `SIGKILL` identically via `TerminateProcess()`, removing platform conditionals in calling code. While technically sound given Windows' process model, the patch lacked context about specific use cases.

Junio Hamano has now weighed in, seeking Windows expertise to evaluate whether the change properly accounts for Windows' termination semantics. He questions whether Windows programs can distinguish between graceful and forced termination (as Unix systems do) and whether other signals like `SIGQUIT` might need consideration. The discussion is now awaiting input from Windows maintainers Johannes Sixt and Johannes Schindelin, who can speak to whether Git's emulation layer should preserve any meaningful distinctions in Windows' process termination API.
