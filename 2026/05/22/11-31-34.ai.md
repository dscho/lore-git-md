This is patch 2/6 in Harald Nordgren's v11 series adding `git branch --prune-merged` functionality. The patch modifies the branch deletion logic to support warning rather than erroring when encountering unmerged branches during bulk operations.

The change introduces a `warn_only` flag to `delete_branches()` and `check_branch_commit()` that allows bulk operations (like the upcoming `--prune-merged`) to continue processing after encountering unmerged branches, rather than stopping with an error. The existing single-branch deletion path remains unchanged, still showing the full error message and advice about using `-D`.

Key technical details:
- Adds parameter to control warning vs error behavior
- Preserves existing error+advice for single-branch deletion
- Uses simpler warnings for bulk operations
- Maintains same underlying merge check logic
- Follows the series' pattern of incremental, focused changes

This is a preparatory change for the `--prune-merged` functionality coming in later patches, allowing it to report problems non-fatally while processing multiple branches. The implementation is clean and maintains all existing safety checks while adding the new warning mode.
