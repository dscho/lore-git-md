This is the fourth patch in a series introducing a new `diff.<driver>.process` feature that allows external tools to inject diff hunks into Git's diff and blame pipelines. The series is currently in RFC status, seeking architectural review.

This patch specifically focuses on integrating the diff process with `git blame`. When a diff process is configured and reports zero hunks for a commit's changes to a file, blame will now skip that commit and attribute lines to earlier commits instead. This is particularly useful for cases like whitespace-only changes or reformatting commits that shouldn't affect blame attribution.

The implementation:
- Modifies `blame.c` to consult the diff process during per-commit diffing
- Adds a new test case showing how blame skips reformatting commits when the diff process reports no semantic changes
- Documents the behavior in gitattributes.adoc

The patch follows the established pattern from earlier in the series, maintaining the long-running subprocess model to amortize startup costs across the blame traversal. Test coverage is thorough, demonstrating both the normal blame behavior and the new zero-hunk skipping behavior.

This appears to be a well-constructed piece of the larger diff process feature, with clear motivation and careful attention to integration with existing blame behavior. The RFC status suggests the author is still seeking feedback on the overall approach, but the implementation looks technically sound.
