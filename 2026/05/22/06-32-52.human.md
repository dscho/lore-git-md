This is a platform compatibility patch discussion about Windows signal handling. Junio C Hamano, the Git maintainer, is seeking input from Windows experts (cc'ing Johannes Sixt and Johannes Schindelin) on a proposed change to `mingw_kill()` that would make it accept both `SIGTERM` and `SIGKILL` signals with identical behavior.

The original patch from Siddh Raman Pant aimed to simplify calling code by removing platform conditionals, treating both signals the same way on Windows (via `TerminateProcess()`). Junio acknowledges this seems like an improvement over the current EINVAL behavior for non-SIGTERM signals, but raises a thoughtful question about whether Windows has meaningful distinctions between different termination signals that Git should preserve.

The discussion is just starting, with no responses yet from the Windows specialists. The technical question at hand is whether Windows' process termination model (which doesn't natively distinguish between graceful and forced termination) justifies treating SIGTERM and SIGKILL identically in Git's compatibility layer. This is a low-risk change but touches subtle cross-platform behavior differences.
