This RFC thread proposes `diff.<driver>.process`, a mechanism for external tools to inject diff hunks into Git's diff and blame operations while preserving standard features like word-diff and color-moved. The primary use case is enabling structural/AST-based diffs that understand code semantics rather than just text changes.

The series is now in its fourth revision with comprehensive test coverage (708+ lines) and has addressed all major technical concerns. Core functionality includes a pkt-line protocol for tool communication, graceful fallback to builtin diff on errors, and blame integration that can skip reformat-only commits when tools report no semantic changes (currently adding ~17% overhead). Windows compatibility issues have been resolved by transitioning to a C-based test helper, as Junio Hamano recommended.

A remaining gap identified in this revision involves certain diff flags (`-L` for line ranges and stat-related flags) that currently bypass the external process. The author suggests these should ideally consult the external provider for consistency with blame behavior, indicating the need for clearer documentation on which flags interact with the process versus falling back to builtin behavior. 

Junio Hamano has endorsed the technical direction, with the path to merging now depending on finalizing flag behavior documentation and potentially extending support for additional flags. The blame integration demonstrates the value - it can correctly attribute semantic changes while skipping purely reformatting commits, a significant improvement for code history analysis. Performance optimizations (like OID-based caching) remain as future work but don't block the core functionality.
