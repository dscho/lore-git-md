This thread is about an RFC proposal for `diff.<driver>.process`, a new Git configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess. The goal is to enable structural or AST-based diffing while preserving all downstream features like word diff, color-moved detection, function context, and integration with `git blame` and `git log -L`. The series, now at version 5 with 9 patches, has addressed all prior technical feedback and is technically complete.

The key participants are Michael Montalbo (the author), who has implemented the entire series, including subprocess management, xdiff integration, blame and range-tracking support, and comprehensive test coverage. Junio Hamano (the maintainer) has reviewed the series and is satisfied with the core implementation but recently reported a merge conflict with the `mm/line-log-limited-ops` topic in `next`, specifically in `line-log.c`. This conflict is the sole remaining blocker. Montalbo has committed to rebasing the series onto `mm/line-log-limited-ops` to resolve the conflict, after which the series will be re-sent as v6. Johannes Schindelin had previously recommended a C-based test helper, which has since been implemented.

The series introduces a forward-compatible pkt-line protocol, robust hunk validation, and unified bypass mechanisms (e.g., `--no-ext-diff` now disables both the command and process drivers). All diff and blame features are now wired to consult the external tool, with only combined diffs (`--cc`) remaining unsupported due to protocol limitations. The rebase is expected to focus on the `git log -L` integration in Patch 9 but should not alter the series' core design or functionality. Once the rebase is complete, the series will be ready for final review and merging.
