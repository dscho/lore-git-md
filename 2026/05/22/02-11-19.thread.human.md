This RFC thread explores a proposed `diff.<driver>.process` mechanism that would allow external tools to inject diff hunks into Git's diff and blame pipelines, primarily aimed at enabling structural/AST-based diffs while preserving Git's native display capabilities. The 6-patch series has seen productive technical iteration, with the core infrastructure (Patches 1-4) now considered sound after refinements to xdiff's hunk handling and configuration plumbing. A demo implementation shows whitespace normalization as a proof of concept.

Recent discussion has focused on implementation polish, with Michael Montalbo incorporating Junio Hamano's suggestion to encapsulate the `changed[]` array manipulation behind cleaner xdiff helper functions. This improves maintainability without changing functionality. While the technical foundations appear solid - with 768 lines of test coverage and careful attention to edge cases - Junio remains neutral-to-skeptical about merging until two key concerns are addressed: demonstrating sufficient performance optimization (particularly for blame, currently showing a 17% slowdown) and more clearly articulating the value proposition beyond AST diffs. The thread shows the feature progressing toward readiness, with the remaining barriers being documentation polish and performance tuning rather than technical soundness.
