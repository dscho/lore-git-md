This thread is an RFC proposing a **diff provider interface** for Git, allowing alternate sources of diff hunks to be consulted before falling back to Git's builtin xdiff computation. The series (11 patches, v7) introduces a repository-owned chain of providers, with two example backends: an **in-process cache** (`diff-hunks` store) and an **external process driver** (`diff.<driver>.process`). The goal is to unify diff/blame integration under a single interface while preserving downstream features like word-diff, color-moved, function context, `--stat`, `git blame`, and `git log -L`.

Michael Montalbo is the author and has restructured the series as a unified framework with robust validation, error handling, and documentation. The interface (`diff-provider.h`) and internal contract (`diff-provider-internal.h`) are complete, and both example providers are implemented. The `diff-hunks` store (Patches 3-6) is a non-authoritative cache with a chunked binary format, atomic flush, deduplication, and a warming mechanism for stat output. The external process provider (Patches 7-11) supports identity-only requests, per-command opt-in, and authoritative answers, with integration into `git blame` and summary formats. Patch output and `git log -L` remain builtin due to the lack of content-carrying requests in the current protocol.

Junio Hamano has acknowledged the series as "technically complete" for its scope, with no outstanding objections after resolving a merge conflict in v6. The latest patch (10/11 in v7) fixes a portability issue in the external process provider, ensuring the build works on platforms where `size_t` differs from `unsigned long`. The series is ready for design feedback on the framework direction, not for merging as a single unit. If accepted, the work will return as separate series for the interface, `diff-hunks` store, and external process provider. Open questions remain about the scope of future content-carrying requests and patch output integration. Test coverage is extensive (2340+ lines), and performance measurements show no overhead for the default path and significant speedups for warmed caches.
