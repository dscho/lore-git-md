This thread is about an RFC proposal for `diff.<driver>.process`, a new Git feature that allows external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess. The series, now at version 5 with nine patches, aims to enable structural or AST-based diffing while preserving Git's downstream features like word diff, color-moved detection, and function context.

The core infrastructure is now complete, with key changes including xdiff modifications to accept pre-computed hunks, a pkt-line protocol for subprocess communication, and robust validation logic to ensure hunk correctness. The series also integrates with `git blame` and supports all diff summary formats (`--stat`, `--numstat`, etc.), addressing earlier limitations of the existing `diff.<driver>.command` mechanism. Documentation has been expanded to clarify the differences between the new process driver and the older command driver, setting clear expectations for users.

Michael Montalbo, the author, has addressed all substantive review feedback, including refactoring the subprocess API to separate lifecycle management from hashmap operations—a change requested by reviewers to avoid redundant lookups in the diff-process driver. Junio Hamano, the maintainer, has endorsed the technical direction, including the shift to a C-based test helper, and confirmed Windows compatibility. Johannes Schindelin also supported the C-based test approach.

The series is now technically complete, with all diff and blame features integrated and comprehensive test coverage. The remaining open items are minor: final documentation refinements, verification of the Windows fix, and Junio's sign-off on the overall justification. The path to merging appears clear, pending these last steps.
