This thread is about an RFC proposal for `diff.<driver>.process`, a mechanism allowing external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess. The series, now at version 5 with 9 patches, aims to enable structural/AST-based diff capabilities while preserving Git's downstream features like word-diff, color-moved, and function context. The author, Michael Montalbo, has addressed all substantive review feedback, including subprocess API refactoring, unified bypass mechanisms, and integration with summary formats (`--stat`, `--numstat`, `--shortstat`), `git blame`, and `git log -L` range tracking.

Key participants include Junio Hamano, the maintainer, who has endorsed the technical direction and addressed Windows compatibility concerns, and Johannes Schindelin, who recommended the C-based test helper approach now implemented. The series is technically complete, with comprehensive test coverage (1113+ lines) and documentation, and all diff/blame features are now wired to consult the external process. The protocol is forward-compatible, and the implementation includes robust error handling and validation.

The latest development is a merge conflict reported by Junio between this series and the `mm/line-log-limited-ops` topic, which is currently cooking in `next`. The conflict affects `line-log.c`, specifically the `collect_diff()` function, which both series modify. This blocks the `diff.<driver>.process` series from progressing until the conflict is resolved, either through a rebase or coordinated resolution with the other topic's author. The series is otherwise ready for merging, pending final documentation refinements and maintainer sign-off on the justification.
