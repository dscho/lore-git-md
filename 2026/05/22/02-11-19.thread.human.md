This thread is about an RFC series proposing `diff.<driver>.process`, a new Git configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess protocol. The series, now at version 5 with nine patches, aims to enable structural or AST-based diffing while preserving Git's downstream features like word diff, color-moved detection, and function context.

The thread has made significant progress. The core infrastructure is complete, with robust validation in the xdiff layer to ensure external hunks are well-formed, and graceful fallbacks to built-in diffing when issues arise. The protocol now includes blob OIDs for future caching optimizations, and all major diff and blame features—including `--stat`, `--numstat`, `git log -L`, and `git blame`—are integrated. Documentation has been expanded to clearly contrast the new process driver with the existing `command` driver, which only replaces textual patch output and lacks integration with most Git features.

Michael Montalbo, the author, has addressed all substantive review feedback, including transitioning the test backend to C (as recommended by Johannes Schindelin) and ensuring Windows compatibility. Junio Hamano, the maintainer, has endorsed the technical direction and is now awaiting final sign-off on the overall justification. The remaining open items are minor: final documentation refinements, verification of the Windows fix, and a planned optimization for blame performance using OID-based caching.

The series is technically complete and ready for merging once Junio signs off on the justification. No major objections or unresolved technical concerns remain.
