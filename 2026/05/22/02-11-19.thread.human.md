This RFC thread proposes a new `diff.<driver>.process` mechanism that would allow external tools to inject diff hunks into Git's diff and blame pipelines, with structural/AST-based diffs being the primary use case. The series has undergone significant technical refinement through review feedback, with core xdiff changes now well-encapsulated and a robust pkt-line protocol implementation in place.

Michael Montalbo has led the implementation, addressing memory management concerns and adding comprehensive test coverage (now over 370 lines). The latest patch completes the blame integration, allowing `git blame` to skip commits where the external tool reports no meaningful changes (zero hunks) - particularly useful for ignoring reformat-only commits in history analysis.

While the technical implementation is now complete and well-tested, Junio Hamano remains neutral-to-skeptical about merging until two key concerns are addressed: (1) performance optimization (currently showing ~17% blame slowdown), and (2) stronger documentation justifying the feature's value beyond what textconv already provides. The thread shows productive collaboration on the implementation details, but the higher-level questions about the feature's necessity remain unresolved.
