This thread is about an RFC series proposing `diff.<driver>.process`, a mechanism allowing external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess. The series, now at version 5 with nine patches, aims to provide structural/AST-based diff capabilities while preserving Git's downstream features like word-diff, color-moved, and function context. The author, Michael Montalbo, has addressed all substantive review feedback, including core infrastructure changes, subprocess API refactoring, and comprehensive integration with diff and blame operations.

Key participants include Junio Hamano, the maintainer, who has technically endorsed the core implementation and addressed Windows compatibility concerns, and Johannes Schindelin, who recommended a C-based test helper approach. The latest patch wires `git log -L` range tracking to consult the external diff process, ensuring that the commits selected for display match the diff output. This completes the series' goal of making every "which lines changed" operation consult the external tool, with the exception of combined diffs, which would require protocol extensions.

The implementation now includes robust validation, graceful fallbacks, and unified bypass mechanisms under `--no-ext-diff`. Test coverage has expanded to over 1,000 lines, and the documentation has been updated to reflect the new capabilities and limitations. The series is technically complete, with the path to merging dependent on final documentation refinements and Junio's sign-off on the overall justification. The only remaining open questions involve minor documentation tweaks and verification of the Windows fix's effectiveness.
