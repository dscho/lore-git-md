Here’s the human-readable summary of the thread so far:

This thread is an RFC for a new **diff provider interface** in Git, proposed by Michael Montalbo. The goal is to create a unified abstraction layer that lets Git consult alternate sources of diff hunks—like caches or external processes—before falling back to its built-in xdiff computation. The series (10 patches, v7) introduces a repository-owned chain of providers, each queried in turn until one answers or fails, with the builtin xdiff as the terminal provider. Two example providers are included: an **in-process cache** (`diff-hunks` store) and an **external process driver** (`diff.<driver>.process`), both answering by object identity alone.

The core infrastructure (Patches 1-2) defines the interface (`diff-provider.h`) and an internal contract (`diff-provider-internal.h`) for implementors. The `diff-hunks` store (Patches 3-6) is a non-authoritative cache at `$GIT_DIR/objects/info/diff-hunks`, keyed by `(old_blob, new_blob, xdl_opts)` and recorded only when the pair’s trimmed and untrimmed diffs agree. This ensures one entry serves both blame (zero context) and stat formats (any context). The external process provider (Patches 7-10) uses a long-running pkt-line protocol to let external tools answer diff requests by object identity, with Git validating hunks for bounds, overlap, and alignment before use.

The latest update (Patch 4) teaches stat output (`--stat`, `--numstat`, `--shortstat`) to record precomputed hunks into the `diff-hunks` store when writing is enabled. A warming run now fills the cache as a side effect, but only for "trim-stable" pairs—those whose zero-context and untrimmed diffs match—so one entry works for both blame and stat formats. The patch excludes certain flags (`--ignore-blank-lines`, `-I`, `--anchored`, `-B`) that could break stability, and skips working-tree sides, textconv output, and gitlinks. Tests confirm the store is built correctly, refreshed in place, and handles edge cases like binary pairs or corruption.

Junio Hamano has acknowledged the series as "technically complete" after resolving a merge conflict in v6, and no new objections have been raised. The RFC is explicitly seeking design feedback on the framework direction, not a merge of the 10 patches as one. If accepted, the work will return as separate series: one for the interface and `diff-hunks` store, another for the external process provider, and a third for content-carrying requests (deferred to future work). The series preserves all downstream features (word-diff, color-moved, function context, `--stat`, `git blame`, `git log -L`) and adds no overhead when providers are disabled. Performance tests show warmed caches speed up `log --stat -5000` by ~1.9x and `blame` by ~1.26x.
