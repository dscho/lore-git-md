This thread is an RFC proposal by Michael Montalbo for a **diff provider interface** in Git, now at version 7 with 11 patches. The goal is to create a unified abstraction layer that lets Git consult alternate sources for diff hunks—such as an in-process cache or an external process—before falling back to its built-in xdiff computation. This would unify and extend how external diff sources integrate with Git’s full feature set, including `git blame`, `git log -L`, and summary formats like `--stat`.

The series introduces two example providers: an **in-process cache** (`diff-hunks` store) and an **external process driver** (`diff.<driver>.process`). The cache is a non-authoritative, opt-in store at `$GIT_DIR/objects/info/diff-hunks` that records hunks only when the built-in diff’s trimmed (blame) and untrimmed (stat) outputs agree, ensuring one entry serves both formats. It’s warmed during stat output runs and delivers speedups of 1.26–1.9× for warmed workloads. The external process provider, implemented in the final patch of the series, speaks a pkt-line protocol over stdin/stdout, answering requests by object names alone (no content sent). It’s authoritative—its answers override the cache—and is opt-in per command, with failures degrading gracefully to the built-in diff.

Key technical details include a repository-owned provider chain, robust hunk validation (order, overlap, alignment), and graceful error handling. The interface is designed to be forward-compatible, with identity-only requests in this series and content-carrying requests deferred to future work. The series also refines Git’s subprocess API to handle optional processes gently (e.g., protocol errors don’t abort the command) and decouples process lifecycle management from the global hashmap.

Junio Hamano has acknowledged the series as technically complete, resolving the prior merge conflict with `mm/line-log-limited-ops`. The RFC explicitly seeks design feedback on the framework direction, not a merge of the 11 patches as one. If accepted, the work will return as separate series: one for the interface and `diff-hunks` store, another for the external process provider, and later work for content enrichment. All substantive review feedback from v6 has been addressed, including documentation clarifications, stat/blame integration details, and subprocess API refinements. The series is ready for broader design discussion.
