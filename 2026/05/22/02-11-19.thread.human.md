This RFC thread explores a proposed `diff.<driver>.process` mechanism that would allow external tools to inject diff hunks into Git's diff and blame pipelines, primarily aimed at enabling structural/AST-based diffs while preserving standard formatting. The series has evolved through technical refinements, with the first four patches establishing core infrastructure (xdiff modifications, configuration plumbing, and blame integration) and a fifth patch demonstrating a whitespace-normalizing implementation.

Junio Hamano has engaged in detailed technical review, initially expressing skepticism about the feature's justification compared to existing textconv mechanisms but acknowledging the technical soundness of the implementation. Recent discussion with Michael Montalbo has focused on improving the xdiff integration code - specifically encapsulating the awkward `changed[]` array manipulation behind cleaner interfaces while preserving necessary sentinel value handling. This reflects Git's typical pattern of hiding implementation details even when working with legacy constraints.

Key open questions center on performance (particularly for blame, where preliminary measurements show ~17% overhead) and whether the primary use case of structural diffs sufficiently justifies the feature. The author has proposed OID-based optimizations to address performance concerns and promised expanded documentation. While the technical foundation appears solid, the feature's inclusion likely hinges on demonstrating clearer value beyond textconv and validating the performance improvements. The thread shows productive collaboration on implementation quality while leaving higher-level justification for future discussion.
