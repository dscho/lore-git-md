This thread is an RFC proposing a **diff provider interface** for Git, allowing alternate sources of diff hunks (like caches or external processes) to integrate seamlessly with Git’s built-in features. The latest update adds a small but critical piece of plumbing: the `process` field to `struct userdiff_driver`, enabling configuration of long-running hunk provider processes via `diff.<driver>.process`. This sets the stage for the external process provider, which will be introduced in the next patch.

The series is now **technically complete** for its scope, with all substantive feedback from earlier versions addressed. It introduces a unified abstraction layer (`diff-provider.h`) that consults a repository-owned chain of providers before falling back to Git’s built-in xdiff. Two example providers are included: an **in-process cache** (`diff-hunks` store) that speeds up `git blame` and stat formats by 1.26–1.9x when warmed, and an **external process driver** that can override the cache with authoritative answers. The interface preserves downstream features like word diff, function context, and `git log -L`, and handles errors gracefully (e.g., protocol errors degrade to the built-in diff).

Junio Hamano has already declared the prior version "technically complete" and ready for merging after resolving a merge conflict. The current patch is uncontroversial and simply prepares the config system for the external process provider. The RFC is now seeking **design feedback** on the framework direction—whether the abstraction is sound—before splitting the series into reviewable topics. If accepted, the work will return as separate series for the interface, cache, and external process provider. Open questions remain about future extensions (e.g., content-carrying requests for patch output), but the core infrastructure is stable and well-tested.
