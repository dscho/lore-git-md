This thread is about an RFC patch series (v6, 9 patches) proposing `diff.<driver>.process`, a mechanism allowing external tools to inject diff hunks into Git's diff and blame pipelines via a long-running subprocess. The goal is to enable structural/AST-based diff capabilities while preserving all downstream features like word-diff, color-moved, function context, `--stat`, `git blame`, and `git log -L`.

The series is now complete, with all major diff and blame operations wired to consult the external tool. Key participants include Michael Montalbo (author), who implemented all requested refinements—subprocess API refactoring, bypass mechanism unification, stat/range tracking integration, and blame integration—and addressed a merge conflict with `mm/line-log-limited-ops` via rebase. Junio Hamano (maintainer) has endorsed the technical direction, with only minor documentation refinements and final sign-off pending. Johannes Schindelin recommended the C-based test helper approach, which was implemented.

The core infrastructure includes xdiff integration (allowing external hunks to replace Git's builtin diff algorithm), a long-running pkt-line protocol (version 1, capability "hunks"), and tight coupling with Git's existing pipelines. The protocol handles edge cases like empty file sides, overlapping hunks, and malformed responses, with graceful fallbacks to the builtin diff. Bypass mechanisms (`--no-ext-diff`, `--diff-algorithm`, whitespace-ignoring flags) ensure consistent behavior, and `format-patch` unconditionally uses Git's builtin diff for reliable patch generation.

The latest patch (9/9) wires `git log -L` range tracking to the external process, ensuring commits are selected based on the tool's hunks. This completes the series' goal, with the only remaining cases using the builtin algorithm being combined diffs (`--cc` and merge diffs), which would require protocol extensions for multiple parent comparisons. The series is ready for merging, pending Junio's final review.
