This RFC thread proposes a new `diff.<driver>.process` mechanism that would allow external tools to inject diff hunks into Git's diff and blame pipelines. The primary motivation is to support structural/AST-based diffs while preserving Git's native display capabilities like word-diff and color-moved.

The series has evolved through three versions, with the latest patch completing blame integration. The implementation now allows external tools to mark commits as "no-op" changes (like reformatting), which blame can then skip entirely. Core components include xdiff modifications to accept pre-computed hunks, configuration plumbing following textconv patterns, and a pkt-line protocol for tool communication. The design maintains backward compatibility with existing workflows through bypass mechanisms like `--no-ext-diff`.

Junio Hamano has been closely reviewing the series, focusing on documentation precision and implementation soundness. While technically satisfied with the core approach, he has raised questions about performance overhead (particularly for blame) and requested final refinements to error handling. The author, Michael Montalbo, has addressed most feedback through successive iterations, including global state refactoring and enhanced test coverage (now 570 lines).

The main outstanding considerations are whether the proposed OID optimization sufficiently address blame performance concerns and whether Junio will be satisfied with the overall justification for the feature. With this final blame integration now implemented and tested, the series appears ready for final review pending these remaining items.
