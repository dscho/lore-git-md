RFC proposal for `diff.<driver>.process` enabling external tools to inject diff hunks into Git's diff/blame pipelines via a long-running subprocess protocol. The series (9 patches, v5) introduces structural/AST-based diff capabilities while preserving downstream features (word-diff, color-moved, function context) and adds comprehensive integration with diff/blame operations. The thread root established the goal: a process-based driver that integrates with Git's full diff pipeline, contrasting with the existing `command` driver that only replaces textual patch output.

**Core infrastructure (Patches 1-6):**
- Configuration plumbing (Patch 3) extending `userdiff_driver` struct with `process`/`process_owned` fields and teaching `userdiff_config()` to populate them from Git configuration (7 lines in `userdiff.c`, 2 in `userdiff.h`). This inert change enables later protocol/subprocess integration.
- Subprocess API refactoring (Patch 4): extracted `subprocess_start_command()` and `subprocess_stop_command()` to separate process lifecycle management from hashmap operations, enabling the diff-process driver to manage its own process lifetime via `userdiff_driver` struct without redundant hashmap lookups. The original `subprocess_start()`/`subprocess_stop()` remain as thin wrappers.
- **Bypass mechanism unification (Patch 6):** Extended `--no-ext-diff` to disable both command and process drivers via a single option, replacing the boolean `--ext-diff` with a callback that sets `allow_external` and `no_diff_process`. Unconditionally disables the diff process in `git format-patch` to ensure generated patches use Git's builtin diff algorithm, guaranteeing reliable application by recipients. Documentation updated to reflect the unified control and note that `--diff-algorithm` also bypasses the process driver. Test coverage added for new bypass behaviors, including verification that `format-patch` does not invoke external tools.
- xdiff modifications accepting pre-computed hunks (xdl_hunk struct, per-gap alignment validation) via `xpparam_t` fields (`external_hunks` and `external_hunks_nr`)
  * Validation checks for out-of-bounds line numbers, overlapping/out-of-order hunks, and misaligned unchanged runs between hunks (must match lengths on both sides)
  * Graceful fallback to builtin diff on validation failure with warnings
  * Skips `trim_common_tail()` when external hunks present (line numbers reference original content)
  * `xdl_clear_changed()` helper resets changed arrays before marking external hunks
  * Maintains xdiff's compaction/emission paths for downstream features (word diff, color-moved)
- Protocol carrying old-oid/new-oid for blob-based caching (future optimization)
- `diff-process.c` implementing pkt-line protocol with SIGPIPE protection, including:
  * Long-lived subprocess management on `userdiff_driver` struct
  * Forward-compatible pkt-line protocol (version=1, capability=hunks)
  * Per-file requests with pathname, optional blob object names (old-oid/new-oid), and file contents
  * Hunk validation for bounds, overlap, and per-gap alignment
  * Error handling with warnings and fallbacks to builtin diff
  * Bypass mechanisms for binary files, unmatched drivers, and unsupported options
  * OID handling for blob-based caching (omitted under textconv or for working-tree sides without stored objects)
  * Edge case handling for empty file sides, trailing-newline-only changes, and mid-file pure insertions/deletions
  * Unified fallback paths with enhanced error handling
