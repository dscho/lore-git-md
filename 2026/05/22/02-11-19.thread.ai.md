RFC proposal for `diff.<driver>.process` enabling external tools to inject diff hunks into Git's diff/blame pipelines via a long-running subprocess protocol. The series (9 patches, v6) introduces structural/AST-based diff capabilities while preserving downstream features (word-diff, color-moved, function context, `--stat`, `git blame`, `git log -L`) and adds comprehensive integration with diff/blame operations. The thread root established the goal: a process-based driver that integrates with Git's full diff pipeline, contrasting with the existing `command` driver that only replaces textual patch output.

**Core infrastructure (Patches 1-6):**
- **Documentation foundation (Patch 1):** Added explicit documentation in `gitattributes(5)` contrasting `diff.<driver>.command` limitations:
  * Replaces only textual patch output, not integrated with word-diff, `-W`, `--color-moved`, or coloring
  * Summary formats (`--stat`, `--numstat`, `--shortstat`, `--dirstat`), `git blame`, and `git log -L` bypass the command driver entirely
  * Sets clear expectations for the process driver's expanded scope (addressed in later patches)
  * Updated "Which features consult the diff process" section to include `git log -L` and stat formats, noting that combined diffs (`--cc`) remain on the builtin algorithm as future work
  * Change is minimal (10 lines) and targeted, serving as a prerequisite for the series by documenting the command driver's limitations
- **xdiff integration (Patch 2):** Extended `xpparam_t` with `external_hunks` (array of `xdl_hunk` structs) and `external_hunks_nr` (array length). When set, `xdl_diff()` populates `changed[]` arrays from supplied hunks instead of running the builtin diff algorithm, then continues through compaction/emission for downstream features (word-diff, color-moved, function context). Includes thorough validation:
  * Out-of-bounds line numbers (start/count)
  * Overlapping or out-of-order hunks
  * Misaligned unchanged runs between hunks (must match lengths on both sides)
  * Graceful fallback to builtin diff on validation failure with warnings
  * Skips `trim_common_tail()` when external hunks present (line numbers reference original content)
  * `xdl_clear_changed()` helper resets changed arrays before marking external hunks
  * Caller preconditions enforced via `BUG()`: 1-based line numbers, non-negative counts
- **Configuration plumbing (Patch 3):** Extended `userdiff_driver` struct with `process`/`process_owned` fields (mirroring existing `command`/`textconv` patterns) and taught `userdiff_config()` to populate them from Git configuration (7 lines in `userdiff.c`, 2 in `userdiff.h`). This inert change enables later protocol/subprocess integration by providing the configuration hooks needed to launch the long-running subprocess. No behavior changes occur yet; the patch is purely preparatory.
- **Subprocess API refactoring (Patch 4):** Extracted `subprocess_start_command()` and `subprocess_stop_command()` from the existing hashmap-based API to separate process lifecycle management from hashmap operations. The new functions handle process setup/teardown and handshake, while the original `subprocess_start()`/`subprocess_stop()` remain as thin wrappers for backward compatibility. This refactoring enables the diff-process driver to manage its subprocess lifetime via the `userdiff_driver` struct without redundant hashmap lookups, addressing a prior review request. The change is purely internal, touching only `sub-process.c`/`sub-process.h` (23 lines added, 6 removed), and introduces no behavior changes.
- **Protocol implementation (Patch 5):** Introduces `diff-process.c` and `diff-process.h`, implementing the long-running pkt-line protocol (version=1, capability=hunks) over stdin/stdout. The handshake negotiates version/capability, then per-file requests send pathname, optional blob object names (old-oid/new-oid), and file contents. The tool responds with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) and a status packet (success/error/abort). Git validates hunks for bounds, overlap, and per-gap alignment before feeding them into xdiff. On error/abort, Git falls back to the builtin diff for that file or the entire session, respectively. Key details:
  * Subprocess stored on `userdiff_driver` struct and launched on first use; failures cached to avoid retrying
  * Blob object names (old-oid/new-oid) sent only for raw blobs (omitted under textconv or for working-tree sides without stored objects)
  * Hunks must be ordered, non-overlapping, and keep unchanged runs aligned on both sides; misaligned gaps trigger fallback
  * Tool can report files as equivalent (no hunks + status=success), causing `git diff` to produce no output and `git blame` to skip the commit
  * Bypass mechanisms include `--no-ext-diff`, `--diff-algorithm`, whitespace-ignoring flags, and `format-patch`
  * Test backend (`test-diff-process-backend.c`) exercises all response modes (success, error, abort, crash, malformed hunks) and edge cases (empty file sides, mid-file insertions, overlapping hunks)
- **Bypass mechanism unification (Patch 6):** Extended `--no-ext-diff` to disable both command and process drivers via a single option, replacing the boolean `--ext-diff` with a callback that sets `allow_external` and `no_diff_process`. Unconditionally disables the diff process in `git format-patch` to ensure generated patches use Git's builtin diff algorithm, guaranteeing reliable application by recipients. Documentation updated to reflect the unified control and note that `--diff-algorithm` also bypasses the process driver. Test coverage added for new bypass behaviors, including verification that `format-patch` does not invoke external tools. This patch addresses a prior review request to unify control of external diff tools, ensuring consistent user experience and reliable patch generation.

**Blame integration (Patch 7):**
- Introduces `xdi_diff_process()` helper in `diff-process.c` to consult external diff process, run xdiff on tool-provided hunks, and return `DIFF_PROCESS_EQUIVALENT` for zero-hunk responses. This helper is reused by `git log -L` in Patch 9.
- `pass_blame_to_parent()` uses this helper to skip commits when the process reports no semantic changes, enabling blame to attribute lines to earlier commits. The integration is tight: blame calls `xdi_diff_process()` with the parent path (matching `builtin_diff()`’s driver resolution), and skips the commit when the tool reports equivalence.
- Long-running subprocess maintained across entire blame operation, with per-commit round-trips to the tool. Whitespace-ignoring options (`-w`, `-b`, etc.) bypass the process entirely (tool cannot honor them).
- Blob object names omitted in protocol for blame (each blob pair diffed only once, making per-invocation cache key unnecessary).
- Performance note: ~17% overhead in blame operations; OID-based caching identified as future optimization.
