The series (reverted to v6 framing, now targeting 4-5 patches) abandons the "diff provider" abstraction (v7) in favor of a simpler, advisory interface that lets users plug in external tools (e.g., `diff.<driver>.process`) without granting them authority over hunk computation. **Core problem and motivation (reframed):**
The series aims to address two primary needs without introducing complexity:
1. **Extensibility:** Enable users to configure external diff tools (e.g., language servers, AI-assisted diffing) that integrate with Git’s built-in features (e.g., word diff, `--color-moved`, function context) via a consistent pkt-line interface. This builds on the existing `diff.<driver>.process` plumbing but extends it to support hunk headers (coordinates) for `git blame` and summary formats (`--stat`, `--numstat`, `--shortstat`).
2. **Performance:** Allow xdiff-interface callers (e.g., `git blame`, `--stat`) to operate on OIDs alone when only hunk headers are needed, avoiding redundant blob loads. The external tool’s hunks are advisory, with xdiff remaining the final arbiter for content rendering, ensuring deterministic behavior.

The pivot responds to Phillip Wood’s review by:
- Dropping the "diff provider" abstraction (a unified chain of authoritative/non-authoritative providers) as overly complex and unclear.
- Replacing invented terminology ("coordinates," "trim-stable pairs") with established Git terms.
- Ejecting the `diff-hunks` store (in-process cache) from the RFC to avoid cache-keying concerns (e.g., storing `xdl_opts` directly).
- Clarifying that external tools are advisory, not authoritative, resolving concerns about non-deterministic behavior (e.g., external tools differing from xdiff).

**Core infrastructure (proposed):**
- **Interface design:** A "cousin" to `xdiff-interface.h` that exposes a pkt-line protocol for external tools to provide hunk headers (offsets/lengths) without replacing xdiff’s content rendering. The interface will:
  - Let consumers (e.g., `git blame`, `--stat`) query external tools for hunk headers via OIDs alone, avoiding blob loads when possible.
  - Preserve xdiff as the final arbiter for content rendering, ensuring deterministic behavior (e.g., for `git patch-id`).
  - Support opt-in integration (like `textconv`), with failures degrading to xdiff.
- **Protocol:** A long-running pkt-line protocol (version=1, capability=hunks) over stdin/stdout, sending OIDs (`old-oid`/`new-oid`) and xdiff options. The tool responds with hunk lines (`hunk <old_start> <old_count> <new_start> <new_count>`) and a status packet (success/error/abort). Git validates hunks for bounds, overlap, and per-gap alignment before using them. Protocol errors degrade to xdiff for the affected file or session.
- **Integration scope:** The external process provider will be wired into `git blame` and summary formats (`--stat`, `--numstat`, `--shortstat`). Patch output and `git log -L` will remain builtin, as the protocol currently lacks content-carrying requests.
