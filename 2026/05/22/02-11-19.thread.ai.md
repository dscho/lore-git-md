RFC proposal for `diff.<driver>.process` enabling external tools to inject diff hunks into Git's diff/blame pipelines via a long-running subprocess protocol. The series (9 patches, v6) introduces structural/AST-based diff capabilities while preserving downstream features (word-diff, color-moved, function context, `--stat`, `git blame`, `git log -L`) and adds comprehensive integration with diff/blame operations. The thread root established the goal: a process-based driver that integrates with Git's full diff pipeline, contrasting with the existing `command` driver that only replaces textual patch output.

  * Sets clear expectations for the process driver's expanded scope (addressed in later patches)

When set, `xdl_diff()` populates `changed[]` arrays from supplied hunks instead of running the builtin diff algorithm, then continues through compaction/emission for downstream features (word-diff, color-moved, function context). Includes thorough validation:
  * Out-of-bounds line numbers (start/count)
  * Overlapping or out-of-order hunks
  * Misaligned unchanged runs between hunks (must match lengths on both sides)
  * Graceful fallback to builtin diff on validation failure with warnings
  * Skips `trim_common_tail()` when external hunks present (line numbers reference original content)
  * `xdl_clear_changed()` helper resets changed arrays before marking external hunks
  * Caller preconditions enforced via `BUG()`: 1-based line numbers, non-negative counts

No behavior changes occur yet; the patch is purely preparatory.
- Subprocess API refactoring (Patch 4): extracted `subprocess_start_command()` and `subprocess_stop_command()` to separate process lifecycle management from hashmap operations, enabling the diff-process driver to manage its own process lifetime via `userdiff_driver` struct without redundant hashmap lookups. Unconditionally disables the diff process in `git format-patch` to ensure generated patches use Git's builtin diff algorithm, guaranteeing reliable application by recipients. Documentation updated to reflect the unified control and note that `--diff-algorithm` also bypasses the process driver. Test coverage added for new bypass behaviors, including verification that `format-patch` does not invoke external tools.
- Protocol carrying old-oid/new-oid for blob-based caching (future optimization)
- `diff-process.c` implementing pkt-line protocol with SIGPIPE protection, including:
  * Long-lived subprocess management on `userdiff_driver` struct
  * Forward-compatible pkt-line protocol (version=1, capability=hunks)
  * Per-file requests with pathname, optional blob object names (old-oid/new-oid), and file contents
  * Hunk validation for bounds, overlap, and per-gap alignment
  * Error handling with warnings and fallbacks to builtin diff
  * Bypass mechanisms for binary files, unmatched drivers, and unsupported options
  * OID handling for blob-based caching (omitted under textconv or for working-tree sides without stored objects)
  * Edge case handling for empty file sides, trailing-newline-only changes, and mid-file pure insertions/deletions
  * Unified fallback paths with enhanced error handling
