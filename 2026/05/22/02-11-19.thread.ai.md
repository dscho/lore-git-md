RFC proposal for `diff.<driver>.process` enabling external tools to inject diff hunks into Git's diff/blame pipelines. The 6-patch series introduces a protocol mirroring `filter.<driver>.process` while preserving downstream features like word-diff and color-moved. Current state:

- Infrastructure landed (Patches 1-4):
  * xdiff modifications to accept pre-computed hunks (xdl_hunk struct, validation logic)
  * Configuration plumbing following textconv/algorithm patterns
  * Core diff implementation with capability negotiation and error recovery
  * Blame integration with zero-hunk skipping and memory management
  * 768 lines of test coverage across success/error paths

- Demo implementation (Patch 5):
  * Built-in whitespace normalizer (`git diff-process-normalize`)
  * Uses XDF_IGNORE_WHITESPACE logic
  * Returns zero hunks for whitespace-only changes

Maintainer feedback (Junio Hamano) raises concerns:
1. Existing `textconv` may suffice for simple normalization
2. Real value lies in structural/AST-based diffs - needs clearer documentation
3. Performance impact on `git blame` (subprocess per commit)
4. Implementation complexity tradeoffs
5. Neutral-to-skeptical stance ("I dunno") about merging as-is

Open questions:
- How to better articulate unique value beyond textconv
- Whether to optimize blame performance (e.g., caching)
- If additional motivating use cases are needed
- If documentation should emphasize AST/structural diff scenarios

The series remains technically complete but requires addressing maintainer concerns about justification and performance before likely progressing. The whitespace normalizer demo, while useful, may not sufficiently demonstrate the feature's full potential.
