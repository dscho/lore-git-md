This is patch 4/13 in a series enabling `--path-walk` and `--filter` interaction in `git pack-objects`. The patch focuses on ensuring directly-requested objects (like ref tips) are always emitted, even when filters would otherwise exclude them.

The key change introduces `path_is_for_direct_objects()` to identify paths starting with '/' (e.g., "/tags") as directly-referenced objects that should bypass type filters. This prevents silent dropping of objects explicitly requested through revision input while still applying filters to objects discovered during tree traversal.

The patch modifies `path-walk.c` to:
1. Always process pending objects regardless of type filters
2. Only apply path-based filtering to non-direct objects
3. Document this behavior in the API docs

This addresses a subtle issue where filters could incorrectly drop needed objects in partial clone scenarios. The change maintains backward compatibility while enabling proper filter integration - a careful balance that shows the series' attention to edge cases.

The implementation demonstrates thoughtful consideration of Git's object model, with clear documentation of the direct-vs-discovered object distinction. This foundational work will support the subsequent filter integration in the series.
