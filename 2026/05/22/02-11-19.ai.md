This is an RFC proposal for a new feature that would allow external tools to provide diff hunks to Git's diff and blame pipelines. The core idea is a new `diff.<driver>.process` configuration that works similarly to `filter.<driver>.process`, establishing a long-running subprocess protocol where external tools can describe line changes that Git then feeds into its standard diff processing pipeline.

The motivation is clear: while Git currently allows replacing the entire diff pipeline (via `diff.<driver>.command`) or selecting among built-in algorithms, there's no way for specialized tools (like syntax-aware diff tools or formatters) to participate in the middle of Git's diff processing while still benefiting from downstream features like word-diff, blame, and color-moved. The proposal would enable tools that understand code structure to integrate more deeply with Git's diff machinery.

The series includes 5 patches:
1. Xdiff modifications to support external hunk providers
2. Configuration plumbing for the new process protocol
3. Core diff process implementation
4. Blame integration for zero-hunk detection
5. A built-in whitespace normalizer as a reference implementation

The implementation appears thorough, with good test coverage (a 430-line test script). The design follows established patterns from Git's existing filter process protocol, which suggests it's likely to be technically sound. The RFC status indicates the author is seeking feedback on the approach before finalizing the implementation.

This could be a valuable extension for tools that need deeper diff integration, though the complexity of the protocol and potential maintenance burden may warrant discussion. The fact that it's opt-in via config and falls back gracefully suggests good forward compatibility.
