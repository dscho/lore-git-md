This is a response to maintainer feedback on the RFC proposal for `diff.<driver>.process`, a mechanism to let external tools inject diff hunks into Git's diff/blame pipelines.

Michael Montalbo acknowledges Junio Hamano's point that the whitespace normalization demo was confusing since similar functionality exists via `textconv`. He clarifies the real goal is enabling structural/ast-based diffs while preserving original content display, and commits to updating the documentation to make this clearer.

The response includes performance measurements showing a ~17% slowdown for `git blame` when using the process (0.57s -> 0.67s on diff.c test case), with 5 whitespace-only commits correctly skipped. The author suggests a potential optimization - extending the protocol to accept OIDs directly, allowing tools to read objects without serialization overhead.

This moves the discussion forward by:
1. Confirming the AST/structural diff use case as primary motivation
2. Providing concrete performance data showing the current impact
3. Proposing a specific optimization path (OID-based object access)
4. Committing to documentation improvements

The exchange suggests the feature may progress if the author can:
- Clearly articulate the structural diff use case in docs
- Demonstrate the OID optimization reduces blame overhead
- Possibly find additional motivating examples beyond AST diffs

The technical foundation appears sound, but the feature's fate likely hinges on addressing both the performance and justification concerns raised by the maintainer.
