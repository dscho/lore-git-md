This is the v8 cover letter for Harald Nordgren's `git branch --prune-merged` series, a five-patch feature that adds safe, explicit local-branch cleanup for when upstream branches have been deleted. The series has been in active development since at least v1, with design concerns from Junio C Hamano shaping each iteration.

The headline change in v8 is a complete redesign of the safety model in patch 3, which is the core of the series. In v7, Harald had refactored the merged-ness checking to fall back to the remote's default branch when a branch's upstream was gone -- a design Junio immediately questioned as unsound, arguing that a remote's default branch is not expected to disappear and that fallback logic for that case was misguided. Harald has now abandoned the fallback approach entirely. The new semantics are simpler and more defensible: `--prune-merged` deletes only branches whose tip is reachable from their configured upstream remote-tracking branch, and leaves alone any branch whose upstream no longer resolves locally, even with `--force`. No fallback, no `no_head_fallback` parameter, no remote-HEAD logic. The range-diff shows this is a substantial rework of patch 3's logic and tests.

The rest of the series is otherwise stable. Patch 1 adds `--forked <remote>` for enumerating branches by remote; patch 2 is a warning infrastructure change for bulk deletes; patch 4 adds the per-branch `branch.<name>.pruneMerged` opt-out, and patch 5 adds `--all-remotes`. The documentation has been rewritten to match the new semantics, dropping references to `branch_get_push` in favor of plain English about upstream reachability. The test suite has been completely revised to exercise the new model: branches are now set up with explicit `--set-upstream-to` rather than relying on push-ref semantics, and the old tests covering fallback-to-default and push-ref-differs scenarios have been removed.

This looks like a promising reset. The new model -- "delete only what is reachable from its own upstream, never guess" -- is cleaner than anything in v6 or v7, and specifically addresses the core objection Junio raised. Whether it is sound in practice (a branch whose upstream ref disappears on fetch is a real scenario, and this design leaves those branches alone by design) is the question for the next round of review. The series is otherwise well-structured, well-tested, and documented at this point.
