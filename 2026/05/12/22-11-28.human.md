This is a small but practical improvement to the advice shown by `git status`. When a local branch is behind its push target (as opposed to its upstream), the status output currently suggests a bare `git pull`, which follows the upstream -- potentially pulling from the wrong remote. Harald Nordgren's patch makes the advice say `git pull <remote> <branch>` instead, using the push branch's actual remote and ref name.

The patch modifies the `format_tracking_info` machinery in `remote.c` to pass the push remote and branch name through to the advice messages for both the "behind and fast-forwardable" and "diverged" cases. It also flips on the divergence advice for push-branch comparisons, which the existing code only enabled for upstream comparisons -- a sensible fix that keeps the two paths consistent.

Two new tests are added to `t6040-tracking-info.sh`, one for the basic qualified-suggestion case and one for a remapped push refspec, which exercises the logic that strips the remote prefix from the full ref name to get the branch part.

This is a small, well-scoped patch. The motivation is clear, the change is localized, and the tests cover both the straightforward and remapped-refspec scenarios. Should be straightforward to review and unlikely to be controversial.
