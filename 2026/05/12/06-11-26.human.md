A refactoring patch that simplifies the octopus merge up-to-date check in `builtin/merge.c`. The current code calls `repo_get_merge_bases()` to compute full merge bases between each remote head and HEAD, then compares OIDs to see if the remote head is already an ancestor. This is overkill for a simple yes/no reachability question.

The fix replaces that with `repo_in_merge_bases()`, which is the standard is-ancestor check. The commit message traces the history: the comment about having to "calculate individual merge_bases again" dates back to 2008 when `in_merge_bases()` cost the same as computing full merge bases. But generation number work in 2018 made the direct check significantly cheaper, and this call site was never updated. Adds a test case for the octopus-already-up-to-date scenario.

This is a straightforward, well-motivated cleanup. The diff is clean (-14/+4 lines), the commit message explains both *what* changed and *why* it wasn't done before, and the author helpfully cites the relevant historical commits. The practical benefit is modest (only matters for octopus merges on repos with deep history), but this is a clear improvement with no downside. Worth a quick read.
