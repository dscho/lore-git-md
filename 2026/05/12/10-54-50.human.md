This is a brief review comment (part of Toon Claes's reply to patch 4/5 of the `git history` merge-support RFC series) on the test infrastructure helper being introduced. The review is surface-level -- it comments on the DSL syntax design, not on code correctness, behavior, or edge cases.

Toon likes the idea of the `test-tool historian` helper and is surprised nobody wrote one before. His feedback is about the command-line interface of the DSL. He makes two points. First, he finds the mixing of named arguments like `from=PARENT` with the `PATH=BLOB` file mappings visually ambiguous, and suggests either a double-dash separator or a different syntax like `PATH:BLOB` to distinguish them. Second, he proposes a more explicit design based on what Gitaly uses internally: drop the mandatory `BRANCH` argument in favor of an optional `branch=` tag, replace `from=` and `merge=` with a single repeatable `parent=` keyword that can appear zero or more times (allowing root commits and unrelated histories), and make the parent and branch specifications all named arguments with the file mappings using a different delimiter. He provides a rewritten version of one of the test scenarios as an illustration.

He acknowledges his suggestion moves away from the `git fast-import`-like syntax that Johannes chose, and says he would understand if the idea is rejected. This is a lightweight, polite suggestion from an interested reviewer who is not blocking the patch. The design point is unlikely to be controversial -- it's a matter of taste for a test-only tool, and Johannes is free to take it or leave it.
