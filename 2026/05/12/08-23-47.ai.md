This is patch 3/5 of Harald Nordgren's v7 series adding standalone branch-pruning commands, and it's the core feature patch: `git branch --prune-merged <remote>`.

The patch introduces a new subcommand that finds local branches whose upstream push destination has been deleted (the branch was pushed to the remote, then the remote branch was pruned), checks that the local branch's commits are safe to drop, and deletes them. The safety logic is the same Junio C Hamano's v6 objection already addressed: first try the branch's own upstream tracking branch, then fall back to the remote's default branch if the upstream is gone, and refuse the branch if neither is available. The `no_head_fallback` parameter added in patch 2 is threaded through `branch_merged()` and `check_branch_commit()` to implement this.

The implementation is in `prune_merged_branches()`, a new function that reuses `collect_forked_set()` from patch 1 to enumerate candidates, then filters them through two gates. A candidate is skipped if the push destination ref still exists (the branch is still upstream), or if the push ref is the remote's default branch (protecting the default branch's local counterpart). It uses `branch_get_push()` to determine the push destination rather than the upstream tracking ref, which is the right semantic: a branch that was pushed under a different name should be pruned by its push ref, not its tracking ref. Branches checked out in any worktree are excluded via `branch_checked_out()`, and the bulk-deletion calls `delete_branches()` with the `warn_only` flag from patch 2, replacing the old per-branch `error()` + multi-line advice with a single summary line.

The test suite is thorough and well-structured. Fourteen test cases cover the mainline case, in-flight branches, unpushed commits (with and without `--force`), the upstream-gone fallback, both-upstream-and-HEAD-gone, checked-out protection, push-ref-differs-from-upstream semantics, default-branch protection by name, and a tricky case where a custom `remote.origin.push` config makes the push ref equal to the default branch even though the upstream is gone. The test for the fallback scenario correctly detaches HEAD to an unrelated commit to force the check to rely on the remote default branch rather than local HEAD.

The documentation is a single paragraph under the synopsis entry. It explains the push-destination semantics and the safety fallback clearly, though it uses the phrase "branch_get_push semantics" which reads as a code reference rather than user-facing explanation. This is a minor documentation nit.

This is a well-structured, well-tested feature patch. The design has been iterated seven times, the single outstanding technical concern from v6 has been addressed, and the test coverage is unusually complete for a Git feature patch. The patch is likely on track for integration once the remaining two patches in the series (the `branch.<name>.pruneMerged` config opt-out and `--all-remotes`) arrive and pass review.
