With patch 6 in this same series now correctly classifying commits as unstable rather than stable, that code path is exercised for the first time, making the bug reachable. The fix is a one-character change in the range check (`0 <=` to `0 <`), a corresponding documentation update, and promoting the relevant test from `test_expect_failure` to `test_expect_success`. This is a narrow, well-motivated, correct fix that has been expected since the thread summary noted this test was left as a placeholder. No drama, no controversy. Four lines of actual code change.
