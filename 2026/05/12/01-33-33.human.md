This is a review reply from Taylor Blau to patch 07/12, which adds `blob:limit=<size>` support to the path-walk API. Blau raises a single substantive technical question about whether the implementation is too aggressive about downloading missing blobs in a partial clone.

The patch's approach is to call `odb_read_object_info()` to check each blob's size. In a partial clone, this call causes Git to download the blob from the remote if it is missing locally. Blau asks whether the patch should instead use `OBJECT_INFO_SKIP_FETCH_OBJECT` to avoid that download -- either by temporarily disabling `fetch_if_missing` or by calling the extended variant of the read function with the skip-fetch flag.

Blau explicitly hedges his question by saying he does not know enough about `git backfill` to be sure which behavior is better, and asks Stolee to let him know if he is missing something.

This is a short review (three sentences of substance) with a clear, well-framed question about a concrete code detail. It is substantive in that it engages with a real behavioral trade-off (on-demand download vs. skipping), but the reviewer acknowledges limited domain knowledge and does not press for a change -- he is genuinely asking. The rest of the patch gets a sign-off ("The rest looks good to me").

The question touches on an interaction the commit message already flagged: the patch added an explicit guard in `builtin/backfill.c` to reject `blob:limit` there, because on-demand downloading defeats backfill's batch-download purpose. Blau's question is essentially whether that guard should have been in `path-walk.c` instead, or whether the download should be suppressed at the source. A reader familiar with the thread will also note that this is the first time Blau has reviewed a patch from the back half of the series with anything beyond a surface-level comment -- the previous six patches (07/12 through 12/12) got no comment at all, including from the co-author.
