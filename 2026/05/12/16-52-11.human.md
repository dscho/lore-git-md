This is a review of patch 2/3 in Tuomas Ahola's series fixing edge cases in Git's approxidate parser, sent by maintainer Junio C Hamano. The review is substantive.

Junio raises a few points on the commit message and the patch itself, none of them showstoppers. On the commit message, he suggests reorganizing the opening examples so that the reader first sees cases where the "wrap to previous day" behavior is *correct* (like `git log --since=tea`), before showing the problematic cases where it fires despite an explicit day-of-month. This would make the logic easier to follow. He also helpfully notes that the `last Friday` example would benefit from explicitly stating what Friday of that week was, so a reader can see at a glance why the output is wrong.

On the code: Junio mildly prefers the comment that Jeff King had suggested in the v1 review over the one the author wrote here. This is a polish preference, not a blocker. More significantly, he flags a real concern about the `"today"` alias addition: `git log --since=today` would then parse as the current instant, whereas the user might reasonably expect it to mean the most recent midnight, i.e., the start of today. The current behavior without the alias would reject `"today"` as an unrecognized date string. So the alias would change a silent refusal into a potentially surprising but successful parse that returns no output. Junio's tone is questioning rather than conclusive, but this is worth the author's attention before a v3.

The review does not object to the core fix (the three-line `tm_mday < 0` guard in `date_time()`), nor does it suggest any structural rework. The overall impression is that Junio is reading carefully but is largely satisfied with the direction.
