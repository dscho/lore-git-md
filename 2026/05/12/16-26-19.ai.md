This is a bugfix for `http-walker.c` from Jeff King (Peff).

**The problem.** When Git fetches from a dumb HTTP server that advertises alternate object stores with absolute paths (like `/parent.git`), it constructs the full URL by combining the server's root with that path. The code finds the server root by scanning for the first `/` after `://`. But when the URL has no path component at all — for example `http://example.com` with no trailing slash — `strchr()` returns NULL, producing a garbage length value. This has been broken since the feature was added in 2005 (b3661567cf).

**The fix** is a one-character change: replace `strchr()` with `strchrnul()`, which returns a pointer to the NUL terminator instead of NULL when no slash is found, giving the correct length (everything after `://` is the host portion). Peff's detailed security analysis shows the worst-case outcome of the current bug is a denial of service (failed clone) or, in a narrow scenario, a misleading truncation that is already possible by other means — no exploitable vulnerability.

**The test** is a genuine integration test that sets up a repository served at the root of the HTTP document root (no path component) and verifies that an alternate with an absolute path is correctly resolved. The test setup involves some maneuvering to make the absolute path meaningful from the HTTP server's perspective.

**Assessment.** This is a well-presented, minimal fix from a trusted author. The commit message is exemplary: it states the bug, shows the root cause, explains why an attacker cannot profit from the existing behavior, acknowledges the real-world unlikeliness of the scenario, and still fixes it cleanly. The test is honest about being "a little gross." The patch is six lines of change. It should be uncontroversial and easy to integrate.
