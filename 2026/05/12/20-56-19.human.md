This is a documentation patch. Michael Montalbo proposes clarifying the `--word-diff` documentation in `Documentation/diff-options.adoc`.

The patch is a reply to a bug report from Vincent Lefèvre, who observed that `git diff --word-diff` can show word-level differences when only whitespace has changed (for example, a line break being inserted between two words). Vincent argued this is surprising behavior because `git --word-diff` is not documented as operating on hunks from the line-level diff. The proposed documentation addition addresses that gap head-on, explaining that word diff works within each hunk of the line-level diff and that the line-level alignment determines which changed lines are compared, which can affect the word-level output.

This is a small, single-commit documentation change. It is not part of any larger series. The motivation is clearly stated (the existing documentation is confusing), and the proposed text is precise and accurate -- it describes what Git actually does rather than what some users might expect. This looks like a sensible clarification. If there is any controversy, it would be about whether the current behavior (showing word-diff output for whitespace-only changes) is itself a bug, but this patch sidesteps that question by documenting the current behavior rather than changing it.
