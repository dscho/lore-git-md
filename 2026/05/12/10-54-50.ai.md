This is a substantive review (patch 4/5) of Johannes Schindelin's new `test-tool historian` subcommand, part of the RFC series adding merge commit support to `git history`.

Toon Claes provides thoughtful feedback on the DSL (domain-specific language) that the `test-tool historian` helper uses to declaratively build test repositories. He raises two design concerns.

First, he flags the confusion of mixing keyword arguments like `from=PARENT` and `merge=PARENT` with the `PATH=BLOB` file-tree specifications in the same space-separated token stream. He suggests either a `--` separator before file paths or using `PATH:BLOB` syntax to visually distinguish the two kinds of key-value pairs.

Second, he proposes a different design philosophy: instead of the special `from=` and `merge=` keywords (which mirror how `git fast-import` thinks about commit creation), he would prefer a uniform `parent=` keyword that can appear zero or more times, along with making the branch argument optional and accessible via e.g. `branch=`. This would be more flexible -- allowing root commits with no parents, or unrelated histories -- and more explicit. He illustrates with a concrete rewrite of the test scenario from the follow-up patch, showing how his syntax would look compared to Dscho's.

The review also contains a friendly note that Toon is surprised no one has built this kind of helper before, acknowledging it fills a real gap.

This is a thoughtful, low-key design discussion about a test infrastructure DSL. It raises real clarity and flexibility trade-offs but is not blocking the series; the reviewer explicitly acknowledges the tool's purposes and shows understanding of why Dscho might prefer the current design (closer to fast-import conventions). The final tone is collegial -- "I'd understand if you'd reject this idea."
