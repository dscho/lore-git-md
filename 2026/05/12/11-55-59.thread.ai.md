Thread type: patch series (4 patches)

Core problem or goal: Replace four existing uses of `strbuf_addf(sb, "%"PRIuMAX, (uintmax_t)value)` with a specialized function `strbuf_add_uint()` that formats an unsigned integer directly via a simple division loop, avoiding the overhead of the full printf machinery. This is a performance optimization for high-volume output commands.

Current status: v1 submitted. Expected to land quickly given the small, clean scope and lack of user-visible change.

Key technical details:
- Files touched: `strbuf.h`, `strbuf.c`, `builtin/cat-file.c`, `builtin/ls-files.c`, `builtin/ls-tree.c`
- New function: `void strbuf_add_uint(struct strbuf *sb, unsigned int value)` added to strbuf interface. Formats the integer as a decimal string using a loop of `x / 10` and `x % 10` operations, writing the digits to a temporary buffer in reverse then appending to the strbuf. Located in `strbuf.c` with declaration in `strbuf.h`.
- Call sites converted (patch 2-4): `cat-file.c`, `ls-files.c`, `ls-tree.c` -- all replace `strbuf_addf(... PRIuMAX ...)` with `strbuf_add_uint()`.
- Overall delta: 38 insertions, 14 deletions across 5 files.
- No test changes needed (behavior is identical).
- No new symbols, config keys, CLI options, or on-disk format changes.
