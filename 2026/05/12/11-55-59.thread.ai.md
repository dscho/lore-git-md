**Thread identity** -- Subject: [PATCH 0/4] Add and use strbuf_add_uint() convenience function [v1]. Series v1. Originating author: Rene Scharfe. Thread type: patch series.

**Core problem or goal** -- Replace four uses of `strbuf_addf(sb, "%"PRIuMAX, (uintmax_t)value)` with a dedicated `strbuf_add_uint()` that formats an unsigned integer via a division-and-pointer loop into an on-stack buffer, avoiding printf machinery. Target: high-volume commands like `git cat-file --batch-all-objects --batch-check='%(objectsize)'`.

**Current status** -- v1 submitted. All review feedback was conversational; no actionable requests were made. Both author and reviewer independently confirmed performance equivalence of all implementation variants. The series is ready for maintainer pickup.

**Key technical details** -- New function in `strbuf.h` and `strbuf.c`: `void strbuf_add_uint(struct strbuf *sb, unsigned int value)`. Formats via `x / 10` and `x % 10` into an on-stack buffer, then appends with `memcpy()`. Call-sites converted: `builtin/cat-file.c`, `builtin/ls-files.c`, `builtin/ls-tree.c` (patches 2-4). Overall delta: 38 insertions, 14 deletions. Benchmark on `git cat-file --batch-all-objects --batch-check='%(objectsize)'` from 751.7ms to 720.4ms (approx. 4% speedup). Patch 3 (ls-tree.c) handles field-width padding via `strbuf_insert()` with `memmove()` -- marginal gain. No test changes, no new config keys, no on-disk format changes, no CLI options.

**Open questions and loose ends** -- None. The design choice is settled. Peff's idle speculations about a custom `vsnprintf()` and `__builtin_add_overflow()` are explicitly non-requests for action and have no bearing on this series.
