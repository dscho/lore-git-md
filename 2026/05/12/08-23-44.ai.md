This is a cover letter for v7 of the `branch: prune-merged` series by Harald Nordgren. This series adds standalone `git branch` commands for pruning local branches whose upstream counterparts have been deleted, a feature that has been under iterative discussion since v1.

The key change in this iteration is a direct response to Junio C Hamano's design concern in the previous round. Junio flagged that v6's merged-ness checking -- which compared every candidate branch against the remote's default branch (`refs/remotes/<remote>/HEAD`) -- was wrong for branches that track a non-default remote branch. Harald has now refactored the logic: `--prune-merged` first checks if a branch is merged into its own specific upstream remote-tracking branch (via `branch_get_upstream()`), and only falls back to the remote's default branch when that upstream is gone. This is implemented through a new `no_head_fallback` parameter threaded through `branch_merged()` and `check_branch_commit()`. The v6 approach of passing an array of `head_rev_override` structs has been removed entirely. The range-diff shows the `resolve_remote_head()` helper is gone, and the merged-ness logic is now inside `branch_merged()` itself rather than in the `prune_merged_branches()` iterator.

The test suite has also been revised to match the new semantics. The previous test verifying merged-ness against `<remote>/HEAD` independently of local HEAD has been replaced by a test that explicitly exercises the fallback scenario: upstream tracking branch deleted, remote default branch still present. A new test verifies that when both the upstream and the remote default branch are gone, the branch is refused rather than silently deleted.

The series itself is five patches: `--forked <remote>`, a warning infrastructure change, `--prune-merged <remote>`, the `branch.<name>.pruneMerged` opt-out configuration, and `--all-remotes`. The cover letter identifies that this is the resolution of the single contested design point from the previous round. If the refactored merged-ness logic holds up under review, the series is likely ready to progress.
