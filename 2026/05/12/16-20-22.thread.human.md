This is a cleanup patch from Jeff King (Peff) that removes a single line from `pretty.c`. The line in question presizes a strbuf before encoding email headers per RFC 2047, an optimization from 2007 that was useful before the code was converted to use strbufs that same year. The sizing calculation (`len * 3 + strlen(encoding) + 100`) could overflow on 32-bit systems when processing extremely large input -- about a 1.4GB author name would trigger it. Peff argues convincingly that even in that pathological case, removing the line produces no measurable slowdown, and for typical inputs the strbuf's amortized growth handles it perfectly. Deleting the line eliminates the integer overflow concern. No tests are needed since this changes no observable behavior. The patch is trivially correct and should be uncontroversial.
