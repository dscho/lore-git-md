Jeff King sent a small cleanup patch to remove a dead `strbuf_grow()` call in `pretty.c`'s RFC 2047 encoder, a line that became useless after the code was converted to use `strbuf` years ago. Junio C Hamano welcomed it with "Very nice." and went further, suggesting a broader housekeeping effort across the whole codebase to audit and remove all `strbuf_grow()` calls that are immediately followed by a `strbuf_addX()` which would grow the buffer anyway.

Peff then agreed with the idea, noting it could be a `#leftoverbits` item. He added a practical warning: anyone tackling this should read the full function context, not just the two-line pattern, because removing the grow call can reveal entire pre-computation loops that become dead code. He illustrated this with a sketch from `builtin/fast-import.c`, where deleting a `strbuf_grow()` would let you also remove a `maxlen` accumulation loop entirely, netting a satisfying reduction in lines. No changes were requested to Peff's original patch, which is already accepted. The thread is now concluded.
