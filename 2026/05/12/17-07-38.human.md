This is the fifth and final patch in Harald Nordgren's v8 series adding `git branch --prune-merged` for automated local branch cleanup. This patch adds `--all-remotes`, which lets `--forked` or `--prune-merged` operate on every configured remote at once, rather than requiring the user to list remotes individually.

The implementation is straightforward plumbing: a helper callback `collect_remote_name()` enumerates all configured remotes, and when `--all-remotes` is set, those names are added to the remote list before the existing logic runs. The patch also adjusts error messages -- `--forked` and `--prune-merged` now accept either a remote argument or `--all-remotes`, and `--all-remotes` alone is rejected with a clear error. The test suite adds four tests: one confirming `--forked --all-remotes` lists every forked branch across two remotes, one checking that an explicit invalid remote still errors when combined with `--all-remotes`, one for the standalone rejection, and one for `--prune-merged --all-remotes` cleaning up branches across two remotes.

This is a small, clean patch -- about 40 lines of C and 45 lines of tests -- that completes the feature set of the series. The design is conventional: there are no surprises, the error conditions are handled, and the tests cover the expected scenarios. It is not a controversial or interesting patch on its own; it is the capstone that makes the feature practical for users with multiple remotes. There are no outstanding concerns specific to this patch, and the only open question for the series is whether Junio and other reviewers accept the upstream-reachability safety model introduced in patch 3.
