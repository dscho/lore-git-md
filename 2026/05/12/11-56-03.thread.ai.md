Subject: [PATCH v1] ls-tree: use strbuf_add_uint() for %(objectsize) fields

Series version: part of a larger series introducing a common `strbuf_add_uint()` helper and applying it in callers (parent patch not seen). No cover letter observed in this invocation.

Originating author: René Scharfe.

Thread type: patch series (single patch).

Core problem or goal: optimize `git ls-tree` when formatting with the `%(objectsize)` and `%(objectsize:padded)` fields by replacing the general-purpose `strbuf_addf()` with a specialized `strbuf_add_uint()` helper.

Current status: patch is submitted and under review. No decisions or objections reported. Likely ready for `next` after review.

Key technical details:
- File: `builtin/ls-tree.c`
- Function replaced: `expand_objectsize()` changed from `strbuf_addf()` with `PRIuMAX` format to `strbuf_add_uint()`.
- Padding handling: `strbuf_insert()` with a static space string replaces `%7s` format.
- Performance: ~1% speedup on `ls-tree -r` of the Linux kernel repo (295ms -> 291ms), measured over 10 runs for both padded and unpadded variants.
- No behavioral change; faithful conversion.
- Minor observation: the hardcoded `padding[]` string of seven spaces is tied to the existing `%7s` format width; would need updating if the field width ever changes, but is correct for this single call site.
