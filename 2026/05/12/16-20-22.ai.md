This is a small cleanup patch from Jeff King targeting the `pretty.c` code that handles RFC 2047 encoding of email headers (e.g., encoding non-ASCII author names in commit output).

The change is straightforward: it removes a single line that pre-sizes a strbuf before encoding. The pre-sizing line (`strbuf_grow(sb, len * 3 + strlen(encoding) + 100)`) could overflow on 32-bit systems when handling extremely large input (a ~1.4GB author name), since the multiplication by 3 could exceed `SIZE_MAX`. The line was originally a direct buffer sizing from 2007 that became a pure optimization when the code was converted to use strbufs later that same year.

The commit message makes a convincing case that this optimization is pointless: even for the pathological 1.4GB input case, removing it produces no measurable slowdown, and for typical inputs the strbuf's built-in amortized growth handles it fine. Deleting the line eliminates the integer overflow concern and simplifies the code.

This is a classic Peff patch -- a small, precisely scoped fix with an excellent commit message that explains the history, the reasoning, and why the obvious "just use checked arithmetic" alternative is not the right approach. No tests are added because this is removing dead optimization code, not changing observable behavior. The patch is trivially correct and should be uncontroversial.
