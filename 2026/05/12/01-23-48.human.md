This is a brief review from Taylor Blau on patch 04/12 of Derrick Stolee's
`--path-walk --filter` integration series.

Blau raises a design concern about the core fix in the patch: the new
`path_is_for_direct_objects()` helper, which checks whether a path string
starts with `'/'` to identify directly-requested objects (as opposed to
tree-discovered ones). He calls it "somewhat brittle" and asks whether
there is a better alternative, while explicitly noting that he is not
familiar enough with `path-walk.c` internals to suggest one himself. This
is a genuine openness to being convinced rather than a blocking objection.

The review also flags a secondary concern: if the approach is kept, the
helper should have a NULL guard on the `path` pointer -- at minimum an
assertion, since a NULL here would indicate a programming error and dying
with a message is better than a segfault.

This is a light review -- Blau identifies a legitimate design smell without
proposing an alternative, and the NULL-guard suggestion is a straightforward
correctness observation. Neither concern is likely to block the patch, but
Stolee may need to either improve the helper's design or add an explicit
rationale for why the `'/'` convention is not brittle in practice. The
review is cooperative in tone and does not require a re-roll on its own.
