Michael Montalbo's documentation patch -- adding a paragraph to explain that
`git diff --word-diff` works in two phases (line-level diff first, then
word-level within each hunk) -- has received its first maintainer response.
Junio C Hamano is unconvinced that the explanation helps. He does not dispute
the text's accuracy, but questions whether describing the internal algorithm
actually reduces the confusion of a user who sees unexpected word-level output
from whitespace-only changes. He suggests, implicitly, that the patch should
focus on what the user can *do* about the situation (e.g., normalizing
whitespace or using `--word-diff-regex=`) rather than on how the machinery
works under the hood.

The thread remains small: Vincent Lefevre (the original bug reporter) endorsed
the idea early on, but no one else has weighed in. Junio's review is the first
from a maintainer and the only substantive technical feedback the patch has
received. The author has not yet replied or posted a revised patch. The
original procedural nudge from Montalbo is now moot -- the patch is no longer
ignored, but its path forward depends on whether the author can reframe the
documentation to provide user-facing guidance rather than algorithmic
explanation.
