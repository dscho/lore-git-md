This is a straightforward thread on a documentation improvement for `git diff --word-diff`. The root is a bug report from Vincent Lefevre noting that word diff can show changes when the only difference between files is whitespace, which is confusing because the documentation doesn't explain why.

Michael Montalbo responded with a small patch adding a paragraph to `Documentation/diff-options.adoc` explaining the internals: word diff works by first computing a line-level diff, then finding word-level changes within each hunk. The line-level alignment therefore determines which lines are compared, and that alignment can affect the word-level output.

This is a narrowly-scoped documentation fix that does not change any behavior or defend the current one -- it simply explains the mechanics. No one has opposed it or raised concerns. The patch is still awaiting maintainer decision on whether the clarification is worth including.
