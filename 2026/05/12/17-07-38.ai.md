This is the fifth and final patch in Harald Nordgren's v8 series, adding a `--all-remotes` flag for use with `--forked` or `--prune-merged`. It is a quality-of-life convenience: instead of typing every configured remote name on the command line, the user can say `--all-remotes` and the tool automatically enumerates all remotes via `for_each_remote()`. Use of `--all-remotes` alone (without either `--forked` or `--prune-merged`) is rejected with a clear error message.

The implementation is straightforward and follows the pattern of similar "all remotes" flags in Git. A small callback `collect_remote_name()` inserts each remote into a string list, which is then merged with any explicit `<remote>` arguments in `collect_forked_set()`. The effect is additive: if the user passes both `origin` and `--all-remotes`, the set of remotes checked is the union of explicit arguments and the full configuration. The diff is about 80 lines across documentation, C, and tests, with the C changes mostly mechanical plumbing to thread the `all_remotes` parameter through `list_forked_branches()` and `prune_merged_branches()`. The test exercises the basic happy path (all remotes covered), the validation of explicit arguments alongside `--all-remotes`, rejection of `--all-remotes` standalone, and a cross-remote prune scenario.

This patch looks uncontentious. It builds directly on the infrastructure introduced across patches 1-3, and the design is the same as in v7 with only mechanical updates for the v8 upstream-reachability safety model. For a reader following the thread, this is the final piece that completes the feature -- no new surprises.
