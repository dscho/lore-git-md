Classification: review of a refactoring patch.

Jeff King (Peff) sends a lightweight review of René Scharfe's `strbuf_add_uint()` patch. He doesn't object or request changes -- this is a quick read-and-think-aloud reply, more conversational than thorough.

The core of the message is Peff anticipating and then dismissing a natural review question: why does the patch build the decimal string in a scratch buffer and then copy it into the strbuf, rather than writing directly into the strbuf after pre-growing it? Peff reasons through it aloud -- you want to format right-to-left, which means you don't know how many digits you'll have until you've finished the division loop, so you either precompute the digit count (possible but fiddly with log-10 and off-by-one pitfalls) or use the temp-buffer approach René took. He concludes that "the extra memcpy() is not that big a deal," which is effectively an Ack for the implementation as-is.

This is a surface-level review in useful disguise: Peff read the code, understood the tradeoff, and confirms the reasoning is sound. He does not test or benchmark, but given the scale of the patch (one function, four call sites), that is entirely appropriate. No changes are requested, no issues raised. The series remains on track for a quick merge.
