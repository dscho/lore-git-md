This is **patch 1 of 4** in Michael Montalbo's bugfix series for negative diff option values. The series is complete and ready for merging.

The patch converts `--inter-hunk-context` from `OPT_INTEGER_F` to `OPT_UNSIGNED`, changing the underlying type from `int` to `unsigned int` for both the option variable and the static default. This is a clean, mechanical fix: when the option was migrated from a custom parser (which used `isdigit()` and silently rejected negatives) to the standard option-parsing API, validation was lost, and negative values now produce structurally invalid hunks. The config variable `diff.interHunkContext` already rejects negatives, so this brings the CLI into alignment.

The commit message is well-written: it reproduces the bug concretely (overlapping hunks that `git apply` cannot consume) and explains the root cause precisely. The fix is minimal -- the config parsing code needs a small intermediate variable since `unsigned int` cannot directly take `git_config_int()`, but that is handled cleanly with a local `int val` and a return-on-negative guard. A test case is added that confirms the rejection and checks the error message.

This is a small, well-scoped patch in a series that is technically complete and has already been accepted in principle by Junio. No surprises here.
