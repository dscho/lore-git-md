This is a review of patch 6/7 in Derrick Stolee's negotiation-control series. The patch adds a `remote.<name>.negotiationInclude` config option that mirrors the `--negotiation-include` command-line flag, letting users specify ref patterns whose tips are always advertised during fetch/push negotiation. The implementation follows the same design as the `negotiationRestrict` config added earlier in the series, including multi-valued support, glob patterns, empty-value reset, and CLI-over-config precedence.

Matthew Cheetham's review is surface-level to mildly substantive. He notes three points: the config parser could reuse `parse_transport_option()` instead of inline resetting (same concern raised on patch 4/7), the documentation cross-references `--negotiation-restrict` when it should reference `--negotiation-include`, and the test for empty-value reset is missing a negative assertion -- it only checks that both expected refs appear, but does not verify that a ref that *should* have been cleared by the reset is absent. The test would pass even if the reset logic was broken, as long as the CLI option and the remaining config value each contribute one ref.

None of these are blockers; the missing test assertion is the most concrete issue. The review reinforces that the series' design is consistent and that its tests, while thorough in coverage, could be tightened.
