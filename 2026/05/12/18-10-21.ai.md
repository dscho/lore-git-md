This is a bugfix, the second patch in a four-part series by Michael Montalbo that fixes a real and well-demonstrated bug: passing negative values to `-U`/`--unified` is silently accepted and produces malformed hunk headers like `@@ -503,999- +503,999- @@` that `git apply` cannot handle.

This patch converts `diff_options.context` and its static default from `int` to `unsigned int`, matching the treatment of `--inter-hunk-context` in the preceding patch. The structural challenge is that `-U` cannot simply use `OPT_UNSIGNED` because bare `-U` with no value is a valid form (it enables patch output with the default context), which requires `PARSE_OPT_OPTARG` and therefore `OPT_CALLBACK_F`. So the validation is done manually in the callback: `strtol()` returns a `long`, and the code checks for negative values before assigning to the now-unsigned field. The config variable `diff.context` gets the same treatment -- it already had a `< 0` check, but the intermediate variable needs to be `int` so the comparison works before assigning to the unsigned default.

A test case is added to `t4055-diff-context.sh` confirming that `-U-1` is rejected with the expected error message. The test file exists already, so this is not a new file but an extension of existing coverage.

This patch is technically sound and follows the pattern established in the series' first patch. The trade-off -- using `OPT_CALLBACK_F` with manual validation rather than the simpler `OPT_UNSIGNED` -- is well-explained and justified by the special behavior of bare `-U`. The config-parsing glue is correctly rewritten to avoid assigning a negative `int` to an `unsigned int` without an intermediate check.
