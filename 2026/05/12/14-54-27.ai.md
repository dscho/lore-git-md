**Classification:** Bugfix series targeting the approxidate date-parsing subsystem (date.c).

This is a cover letter for a three-patch v2 series by Tuomas Ahola. The thread was previously worked on by a different author under the same subject line (the earlier "two-patch series" summarized above); this new v2 is a fresh submission from a new author, not a revision by the same person.

The series addresses long-standing oddities in Git's "approxidate" parser, which handles fuzzy human-friendly date inputs like "yesterday", "noon", "tea" (5 PM), "last Friday", and combinations thereof. The cover letter references an old bug report by Linus Torvalds from 2006, indicating these edge cases have been known for two decades.

The three-patch structure has changed from the original v1: a new preparatory patch (1/3) adds test infrastructure to `t0006-date.sh` allowing the test environment to control the current "now" time for approxidate tests. This lets the tests exercise behaviors that depend on the time of day (such as whether "noon" should land on today or roll over to tomorrow). Patch 2/3 fixes time-based specials ("noon", "tea") so they respect an explicit day-of-month when provided alongside them. Patch 3/3 addresses how `tm_mday` is set for "now" and "yesterday" — the deferred-adjustment approach mentioned in the earlier thread appears to be the author's answer to the field-management questions that Jeff King had raised in the previous iteration.

The total delta is modest — 45 insertions, mostly in tests, and 37 lines changed in `date.c` spread across three patches. The base commit is a recent tip from 2026. This is clearly a narrow, well-scoped bugfix series rather than a broad refactoring.

For a reader: this is a cleanly presented series with a clear motivation, a reasonable amount of test coverage (including the new test-time infrastructure), and a light touch on the code. The fact that it references a 2006 report suggests these are genuinely long-unfixed quirks rather than hypotheticals. The earlier thread saw active review from Jeff King, so it is likely this v2 will receive similar attention. If you have ever been bitten by `git log --after="last week noon"` producing the wrong day, this series is directly relevant to you. If you work on the date-parsing code or review patches in date.c, this is worth a close look.
