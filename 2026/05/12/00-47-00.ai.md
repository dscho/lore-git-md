This patch (5/9) fixes three compounding bugs in the extended pseudo-merge lookup table, which is used when a commit belongs to more than one pseudo-merge group. The first bug is on the write side in `write_pseudo_merges()`: the offset calculation for where the extended table starts undercounted each commit lookup entry as 8 bytes instead of 12, so the extended table was written on top of the normal lookup table instead of after it. The second bug is on the read side in `nth_pseudo_merge_ext()`: the function was parsing a stored offset through `read_pseudo_merge_commit_at()`, which treats it as a 12-byte struct, when it only needed to store the offset directly. The third bug is a latent off-by-one in `apply_pseudo_merges_for_commit()`: the error check tests `< -1` instead of `< 0`, which would silently swallow an `error()` return on corrupt data.

The net effect is that any code path exercising pseudo-merge lookups for commits in multiple groups would either produce garbage or silently fall back to non-pseudo-merge behavior. With the first two bugs fixed, the corresponding test in `t/t5333` is promoted from `test_expect_failure` to `test_expect_success`.

The changes are tiny -- four lines of functional code across two files, plus moving one test marker in `t/t5333`. The commit message clearly documents each bug independently, which is helpful for review. This is a straightforward correctness fix in a narrow, recently-added code path; no controversy expected.
