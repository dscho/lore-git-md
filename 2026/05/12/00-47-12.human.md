**Classification**: Bugfix (memory leak) in the pseudo-merge bitmap subsystem. This is patch 9/9 of Taylor Blau's pseudo-merge bitmap bugfix series.

**Summary**: This is the final patch of the series, fixing a memory leak that occurs when `bitmapPseudoMerge.*.pattern` is specified more than once for the same group. When `pseudo_merge_config()` encounters a duplicate pattern for an existing group, it frees the old `regex_t *` pointer but never calls `regfree()` on it first, leaking the internal state that `regcomp()` allocated. The fix is straightforward: guard the replacement with a NULL check and call `regfree()` before `free()` when the pointer is non-NULL.

The test in patch 9 is the one that was still marked as an expected failure in v2 -- it gets promoted to a regular `test_expect_success` here. The test constructs a scenario where the same pattern is set twice for a pseudo-merge group, then generates a bitmap and verifies the group still produces exactly one pseudo-merge. This also addresses the test-hygiene feedback from v2: the test now places `test_when_finished` before `git init` and avoids piping Git output directly into a comparison.

This is a small, contained patch -- five lines of functional code in `pseudo-merge.c` and a new test in `t5333`. The leak is real but unlikely to cause problems in practice, since it requires the same group to appear twice in the config (unusual but not impossible). With this patch applied and all review feedback incorporated across the series, the entire nine-patch series is ready for merging.
