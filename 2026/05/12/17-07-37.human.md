This is patch 4 of 5 in Harald Nordgren's v8 series adding `git branch --prune-merged`. It introduces the `branch.<name>.pruneMerged` configuration option that lets users exempt individual branches from bulk pruning.

The config key is straightforward: setting `branch.<name>.pruneMerged=false` for a branch prevents `git branch --prune-merged` from deleting it, even with `--force`. The commit message gives the motivating use case -- keeping a topic branch around between rounds after its initial round has been merged upstream. Explicit deletion with `git branch -d` continues to work unaffected, which is the right boundary for this kind of opt-out.

Mechanically this is about 20 lines of new C code in `builtin/branch.c`, inserted into the candidate loop in `prune_merged_branches()`. It reads the config, checks the boolean, and if it's explicitly false, prints a "Skipping" message (unless `--quiet` is given) and continues past the deletion. The placement makes sense -- the config check happens after the default-branch-name protection but before the branch is added to the deletable list. This is clean infrastructure work; the code is simple and the integration point is well-chosen.

The test coverage is thorough: a basic opt-out test where a protected branch survives while a sibling is pruned, a test confirming that `--force` does not override the config (important -- this is a genuine override that even force cannot bypass, unlike the reachability check), and a test confirming that `git branch -d` still works on opted-out branches. All three are well-structured and test distinct scenarios.

The commit message is crisp and the documentation addition is clear. This is a small, focused, well-executed patch that directly addresses a realistic user need without over-engineering the mechanism.
