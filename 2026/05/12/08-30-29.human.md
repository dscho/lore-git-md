Second version of a two-patch series from Patrick Steinhardt fixing
maintenance-mode bugs. v2 addresses all the feedback from v1: the lockfile
ownership comment has been clarified, and the `gc.auto` config key is now
read as an integer (with `repo_config_get_int()`) instead of incorrectly
as a boolean -- the critical correctness issue Jeff King and Junio C Hamano
caught in v1. Patrick's range-diff shows the changes are exactly what was
asked for.

Patch 1 fixes a lockfile leak when `git maintenance` runs in `--detach`
mode: the parent process was exiting without relinquishing ownership of
the lockfile, making subsequent maintenance runs fail. The fix uses a new
`lock_file_reassign_owner()` helper to transfer lock ownership to the
child process before the parent exits. A comment change requested by Junio
now correctly says "drop ownership" rather than "assign ownership". Junio
also noted some `#ifdef` duplication in the `daemonize_without_exit()`
wrapper, but Patrick has deferred cleanup of that to a follow-up series.

Patch 2 fixes a user-reported regression where auto-maintenance stopped
respecting the `gc.auto` threshold -- maintenance was either not running
when expected, or running when the user had set `gc.auto=0` to disable it.
The fix checks both `gc.auto` (the legacy setting) and `maintenance.auto`
(the newer setting) with proper precedence, matching the behavior users
saw before the transition from `git gc` to `git maintenance`.

The series is straightforward, well-scoped, and now appears correct after
the v2 fix. It touches `builtin/gc.c`, `lockfile.c/h`, `run-command.c`,
`setup.c/h`, and adds 83 lines of tests in `t7900-maintenance.sh`. Based
on the v1 reviews this should be ready to move forward unless Derrick
Stolee or Taylor Blau raise something new.
