This is **patch 3 of 5 in v8** of Harald Nordgren's series adding `git branch --prune-merged` for safe automated local branch cleanup -- and it is the one that matters most this round because it contains a complete redesign of the safety model.

**What changed.** The previous version (v7) checked whether a branch's *push destination* still existed on the remote. If it did, the branch was left alone -- a confusing criterion that Junio C Hamano found questionable. V8 throws that out entirely. The new safety check is simple and intuitive: a branch is safe to delete only if its tip is reachable from its configured *upstream* remote-tracking branch (`branch.<name>.merge`). If the upstream ref no longer resolves locally (e.g., the remote-tracking branch was deleted), the branch is left alone. The previous fallback-to-remote-default logic and the `no_head_fallback` parameter that Junio objected to are both gone.

**How it works.** The patch adds `prune_merged_branches()`, which uses `git branch --forked` infrastructure (from patch 1) to build a candidate set of local branches, then filters them through commit-reachability against their upstream. Branches that are checked out in any worktree are skipped, as is the local branch that mirrors the remote's default branch (`refs/remotes/<remote>/HEAD`). With `--force`, the reachability check is skipped entirely and every candidate is deleted. The commit message spells out the intended workflow: `git fetch <remote>` first, then `git branch --prune-merged <remote>`.

**The diff is large** (241 lines added across `builtin/branch.c`, the docs, and tests), but much of the bulk is the new `prune_merged_branches()` function and supporting plumbing. The core loop is about 30 lines of C.

**Tests are thorough** -- seven new test cases covering: integrated branches get deleted, unintegrated branches are refused with a clean summary message (no per-branch error noise), `--force` bypasses the check, branches whose upstream has been deleted are skipped, checked-out branches are protected, the local default branch is protected, and a name-matching edge case (a branch named `trunk` tracking `origin/main` is not protected because it does not match the remote's default by name). This is better test coverage than many series land with.

**The review situation.** Junio asked for this redesign on v7; Harald turned around v8 in one day. Junio has not yet responded. No other reviewer has commented either. If the upstream-reachability model holds up -- and it is hard to see what objection remains -- this series may finally be on track to move past `seen`.

**One thing to watch.** The `delete_branches()` call site in `prune_merged_branches()` passes `no_head_fallback=1`, which means `head_rev` is left as NULL and the `branch_merged()` function will not perform the legacy merge-base check it does for regular `git branch -d`. That is intentional -- the new code has its own reachability check -- but it means `--prune-merged` and `-d` now use different criteria for "merged," which could cause confusion if some future developer tries to reason across both paths. The commit message does not flag this, and it is worth noting as a latent maintenance concern, not a bug.
