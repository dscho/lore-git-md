Harald Nordgren has proposed a patch to improve the `git status` advice when a local branch tracks a push branch (configured via pushremote or push.default). Currently, the status output suggests a bare `git pull` that would follow the upstream remote, which can be misleading when the push target differs. The patch modifies the advice to show the correct remote and branch for pulling.

In the second version, Harald narrowed the scope to only affect pull advice (removing divergence advice that was in v1) and added tests for both standard and remapped push refspecs. Junio Hamano raised a substantive review point: the verbose pull advice should likely be conditional, only showing the full `git pull <remote> <branch>` form when the push and pull remotes actually differ (triangular workflow case), rather than always showing it.

Harald has agreed with Junio's suggestion and indicated he'll send a v3 patch implementing this refinement. The thread is now waiting for that updated version, which will make the advice more context-sensitive - detailed when needed for triangular workflows, but simpler when push and pull remotes match. This addresses the core issue while avoiding unnecessary verbosity in common cases. No other reviewers have commented yet on this specific version.
