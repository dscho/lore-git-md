This is a single-patch bugfix from Harald Nordgren, now at v2, that makes `git status` show a useful `git pull <remote> <branch>` hint instead of a bare `git pull` when the local branch is behind a *push* branch (configured via `branch.<name>.pushremote` or `remote.pushDefault`). The original advice was actively misleading because an unqualified `git pull` would follow the upstream remote, which could be completely different from the push target.

The change lives in `remote.c`: `format_branch_comparison()` gets two new parameters, and `format_tracking_info()` now extracts the push remote and branch name — calling `pushremote_for_branch()` for the remote and stripping `refs/remotes/<remote>/` from the full ref to get the human-readable branch name. Both the "behind" and "diverged" advice paths are covered, with a graceful fallback to a bare `git pull` for unusual refspecs. Two new tests in `t/t6040-tracking-info.sh` validate the output, including one with a remapped push refspec.

The key change from v1 to v2 is a meaningful scope reduction: the first iteration also enabled the divergence advice (`ENABLE_ADVICE_DIVERGENCE`) for push-branch comparisons, but the author found that got in the way when actually using the feature, so v2 drops it entirely. The commit message now only promises to fix the pull advice. No reviews have been posted yet, but the patch is small, well-scoped, and unlikely to be controversial.
