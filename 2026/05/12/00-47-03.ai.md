**Patch 6 of a nine-patch pseudo-merge bitmap bugfix series (v3).**

This is a straightforward bugfix that addresses a silent classification error in `find_pseudo_merge_group_for_ref()` in `pseudo-merge.c`. The function calls `lookup_commit()` to get a commit from an OID, but `lookup_commit()` does not parse the commit object -- it only retrieves an unparsed object. An unparsed commit has its `date` field set to zero, so every commit is classified as "stable" (older than any reasonable threshold), rendering the `bitmapPseudoMerge.*.threshold` and `stableThreshold` configuration options completely inert. The fix is a single two-line change: adding a `repo_parse_commit()` call after `lookup_commit()` and returning early if parsing fails.

The consequence of the bug is that pseudo-merge groups are always partitioned by `stableSize` rather than by the intended decay-based sizing, and the `sampleRate` knob -- which is only applied in the unstable path -- is never exercised. This is a real silent correctness bug in how pseudo-merge bitmaps are constructed.

The patch also promotes the "pseudo-merge commits are correctly classified by date" test from `test_expect_failure` to `test_expect_success`, and demotes the "sampleRate=0 does not cause division by zero" test in the opposite direction, because fixing the date classification now exposes the sample-rate bug which will be addressed in a later patch in the series. The test uses `GIT_TEST_DATE_NOW` set to `$test_tick` to align Git's notion of "now" with the test timestamps, a clean approach.

As with the rest of this series, the patch is cleanly written, the commit message explains the bug clearly with both the root cause and the observable symptom, and the test arrangement is careful. The maintainer has already signaled readiness to merge this series once the test-hygiene issues from v2 were resolved, and this patch continues the pattern established by the earlier fixes. Nothing here should be controversial.
