This is the first patch (1/9) in Taylor Blau's third-iteration bugfix series for pseudo-merge bitmaps. As the series cover letter makes clear, all substantive issues have been resolved in earlier rounds -- the v3 changes are strictly test-hygiene fixups called out by Elijah Newren -- and Junio has signaled the series is nearly ready to merge.

This patch introduces a new `test-tool bitmap write` subcommand that gives tests fine-grained control over which commits receive bitmaps and which don't. Currently there is no standard way to do this, making it hard to write targeted tests for the pseudo-merge code path. The helper reads a pack basename and a list of commit OIDs from stdin, then writes a bitmap for that pack covering only the specified commits. It also respects `bitmapPseudoMerge.*` config, so pseudo-merge bitmaps can be produced alongside the regular ones. The patch includes one integration test exercising the helper.

This is pure test infrastructure -- it adds no new behavior to any end-user command. The diff is about 140 lines, mostly a new `bitmap_write()` function in `test-bitmap.c` that wires up the pack-object traversal, type index, pseudo-merge selection, and bitmap-writing machinery that already exists in the main codebase. The implementation looks clean and uses existing APIs idiomatically. The test follows the usual patterns.

For a casual reader: this patch is unremarkable in isolation. It will be judged on whether the subsequent eight patches actually find bugs, which is where the weight of the series lies.
