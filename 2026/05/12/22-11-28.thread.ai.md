**Thread identity** -- single-patch bugfix/UX improvement for `git status`. Author: Harald Nordgren. Thread subject is the patch subject: making the `git pull` advice in `git status` quote the correct remote and branch when a local branch is compared against a push branch. Currently at v2.

**Core problem** -- when `git status` shows that a local branch is behind or has diverged from its push branch (configured via `branch.<name>.pushremote`, `remote.pushDefault`, or `push.default = current`), the advice text suggests a bare `git pull` with no arguments. That `git pull` follows the upstream remote, which can be a different remote from the push target. This makes the hint misleading and useless for anyone using push-branch tracking.

**Current status** -- thread consists of this single patch, currently at v2. No reviews posted. No merge or maintainer action.

**Changes from v1** -- v2 removes the divergence advice (`ENABLE_ADVICE_DIVERGENCE`) from the push-branch path that v1 had added. The commit message now only promises to enable the pull advice (`ENABLE_ADVICE_PULL`), not the divergence advice. The author explains: "Remove the message only when diverged from push-branch, because it was in the way when I used it now on my real branch." The v1 test for the diverged case has been removed. This is a meaningful narrowing of scope.

**Key technical details** -- modification to `remote.c`. The internal `format_branch_comparison()` function gains two new parameters (push remote name, push branch name). In `format_tracking_info()`, when processing a push-branch comparison: calls `pushremote_for_branch()` to get the remote, then strips the `refs/remotes/<remote>/` prefix from the full ref to recover the branch name the user would type. Both "behind" and "diverged" advice paths now use the qualified `git pull <remote> <branch>` form. Graceful fallback to bare `git pull` when extraction fails (e.g. unusual refspecs). The pull advice flag `ENABLE_ADVICE_PULL` is now set for push-branch comparisons; previously it was only set for upstream comparisons.

Two new tests in `t/t6040-tracking-info.sh`: one for basic "behind" case with standard pushrefspec, one with a remapped push refspec (`refs/heads/feature14:refs/heads/remapped14`) to confirm the extracted branch name matches the push target, not the local branch name.

**Open questions and loose ends** -- none. The code degrades gracefully for unusual refspecs. The narrowing from v1 appears to reflect real usage experience.
