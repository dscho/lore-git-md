**Thread identity** -- single-patch bugfix/UX improvement for `git status`. Author: Harald Nordgren. Thread subject is the patch subject: making the `git pull` advice in `git status` quote the correct remote and branch when a local branch is compared against a push branch. Now at v3.

**Core problem** -- when `git status` shows that a local branch is behind or has diverged from its push branch (configured via `branch.<name>.pushremote`, `remote.pushDefault`, or `push.default = current`), the advice text suggests a bare `git pull` with no arguments. That `git pull` follows the upstream remote, which can be a different remote from the push target. This makes the hint misleading for triangular workflows.

**Current status** -- patch is now at v3, implementing Junio Hamano's suggestion from v2 review. The verbose `git pull <remote> <branch>` advice is now conditional on push/pull remotes differing, falling back to simple `git pull` when they match. Ready for final review.

**Changes from v2** -- v3 adds the conditional advice logic requested by Junio. New test cases verify both triangular (different remotes) and standard (same remote) workflows. The implementation now compares push and upstream remotes in `format_tracking_info()`, only showing qualified pull advice when they differ.

**Key technical details** -- modification to `remote.c`. The internal `format_branch_comparison()` function has two parameters (push remote name, push branch name). In `format_tracking_info()`: calls `pushremote_for_branch()` to get remote, strips `refs/remotes/<remote>/` prefix. New logic compares push and pull remotes before generating advice. 2. Remapped push refspecs
3. Push branch tracking with no upstream
4. Common case where upstream and push match (simple `git pull`)
