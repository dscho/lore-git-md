**Thread identity** -- single-patch bugfix/UX improvement for `git status`. Author: Harald Nordgren. Thread subject is the patch subject: making the `git pull` advice in `git status` quote the correct remote and branch when a local branch is compared against a push branch. Now at v3 with final review feedback.

**Core problem** -- when `git status` shows that a local branch is behind or has diverged from its push branch (configured via `branch.<name>.pushremote`, `remote.pushDefault`, or `push.default = current`), the advice text suggests a bare `git pull` with no arguments. That `git pull` follows the upstream remote, which can be a different remote from the push target. This makes the hint misleading for triangular workflows.

**Current status** -- patch is at v3 with Junio Hamano's latest review identifying one remaining edge case. The verbose `git pull <remote> <branch>` advice is conditional on push/pull remotes differing, but may incorrectly suggest a bare `git pull` when push remote parsing fails. Awaiting author's response to Junio's suggestion to suppress advice in such cases.

**Changes from v2** -- v3 added the conditional advice logic requested by Junio. New test cases verify both triangular (different remotes) and standard (same remote) workflows. The implementation compares push and upstream remotes in `format_tracking_info()`, only showing qualified pull advice when they differ. Junio's v3 review notes an edge case where NULL push remote could still generate misleading advice.

**Key technical details** -- modification to `remote.c`. The internal `format_branch_comparison()` function has two parameters (push remote name, push branch name). In `format_tracking_info()`: calls `pushremote_for_branch()` to get remote, strips `refs/remotes/<remote>/` prefix. New logic compares push and pull remotes before generating advice. Four test cases in `t/t6040-tracking-info.sh` cover:
1. Upstream and push branches both behind (different advice for each)
2. Remapped push refspecs
3. Push branch tracking with no upstream
4. Common case where upstream and push match (simple `git pull`)

**Open questions and loose ends** -- Junio identified that when `format_tracking_info()` cannot determine the push remote name (due to ref parsing failures), it falls back to NULL and may still suggest an incorrect bare `git pull`. The author needs to decide whether to suppress advice in this case or find another solution.
