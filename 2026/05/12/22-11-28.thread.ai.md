**Thread identity** -- single-patch bugfix/UX improvement for `git status`. Author: Harald Nordgren. Thread subject is the patch subject: making the `git pull` advice in `git status` quote the correct remote and branch when a local branch is compared against a push branch. Currently at v2.

**Core problem** -- when `git status` shows that a local branch is behind or has diverged from its push branch (configured via `branch.<name>.pushremote`, `remote.pushDefault`, or `push.default = current`), the advice text suggests a bare `git pull` with no arguments. That `git pull` follows the upstream remote, which can be a different remote from the push target. This makes the hint misleading and useless for anyone using push-branch tracking.

**Current status** -- thread consists of this single patch, currently at v2. Junio C Hamano has raised a substantive review questioning whether the verbose `git pull <remote> <branch>` advice should be unconditional. No merge or maintainer action yet.

**Changes from v1** -- v2 removed the divergence advice (`ENABLE_ADVICE_DIVERGENCE`) from the push-branch path that v1 had added, narrowing the scope to only the pull advice (`ENABLE_ADVICE_PULL`). The v1 test for the diverged case was removed based on real usage experience.

**Key technical details** -- modification to `remote.c`. The internal `format_branch_comparison()` function gains two new parameters (push remote name, push branch name). In `format_tracking_info()`, when processing a push-branch comparison: calls `pushremote_for_branch()` to get the remote, then strips the `refs/remotes/<remote>/` prefix from the full ref to recover the branch name the user would type. Both "behind" and "diverged" advice paths now use the qualified `git pull <remote> <branch>` form. Graceful fallback to bare `git pull` when extraction fails (e.g. unusual refspecs). The pull advice flag `ENABLE_ADVICE_PULL` is now set for push-branch comparisons; previously was only set for upstream comparisons.

Two new tests in `t/t6040-tracking-info.sh`: one for basic "behind" case with standard pushrefspec, one with a remapped push refspec (`refs/heads/feature14:refs/heads/remapped14`) to confirm the extracted branch name matches the push target, not the local branch name.

**Open questions and loose ends** -- Junio's review raises whether the verbose pull advice should be conditional, only showing when push and pull remotes differ (triangular workflows). The patch unconditionally shows the verbose form, which may be unnecessarily verbose for standard workflows where `branch.<name>.merge` is set. This needs resolution in a v3.

**Participant positions** -- Junio C Hamano has provided substantive feedback suggesting the advice could be more nuanced. The patch's correctness remains unverified by other reviewers. Author will likely need to respond to Junio's concern.

**Related work** -- follow-up to the existing push-branch tracking feature (`status.showBranchComparison` or `status.compareBranches`), fixing a usability gap in the hint it provides.
