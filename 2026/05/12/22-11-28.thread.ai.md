**Thread identity** -- single-patch bugfix/UX improvement for `git status`. Author: Harald Nordgren. Thread subject is the patch subject: making the `git pull` advice in `git status` quote the correct remote and branch when a local branch is compared against a push branch. Currently at v2 with v3 expected.

**Core problem** -- when `git status` shows that a local branch is behind or has diverged from its push branch (configured via `branch.<name>.pushremote`, `remote.pushDefault`, or `push.default = current`), the advice text suggests a bare `git pull` with no arguments. That `git pull` follows the upstream remote, which can be a different remote from the push target. This makes the hint misleading for triangular workflows.

**Current status** -- thread consists of this single patch, currently at v2 with v3 planned. Junio C Hamano raised a substantive review questioning whether the verbose `git pull <remote> <branch>` advice should be unconditional. Author agrees and will modify for v3 to make it conditional on push/pull remotes differing.

**Changes from v1** -- v2 removed the divergence advice (`ENABLE_ADVICE_DIVERGENCE`) from the push-branch path that v1 had added, narrowing the scope to only the pull advice (`ENABLE_ADVICE_PULL`). The v1 test for the diverged case was removed based on real usage experience.

**Key technical details** -- modification to `remote.c`. The internal `format_branch_comparison()` function has two new parameters (push remote name, push branch name). In `format_tracking_info()`, when processing a push-branch comparison: calls `pushremote_for_branch()` to get the remote, then strips the `refs/remotes/<remote>/` prefix from the full ref to recover the branch name the v3 change will add logic to compare push and pull remotes, only showing verbose pull advice when they differ. Two existing tests in `t/t6040-tracking-info.sh` cover basic and remapped pushrefspec cases; v3 will likely add a triangular workflow test.
