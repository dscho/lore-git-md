Subject: [PATCH] builtin/merge: replace roundabout octopus up-to-date check with repo_in_merge_bases()

Thread author: Kristofer Karlsson (Spotify)

Type: refactoring patch

Core change: In builtin/merge.c, the octopus merge strategy's up-to-date check for each remote head was calling `repo_get_merge_bases()` to compute all merge bases between HEAD and the remote head, then extracting the first result and comparing its OID to the remote head -- a complex way of asking "is this remote head already an ancestor of HEAD?" The patch replaces this with `repo_in_merge_bases(base_commit, heads[i])`, which directly answers the reachability question. Diff is -14/+4 lines.

Performance: `repo_in_merge_bases()` uses `can_all_from_reach()` when generation numbers (commit-graph) are available -- a DFS that stops as soon as the target is found or ruled out -- rather than running the full `paint_down_to_common()` with its STALE drain and `remove_redundant()` pass. Without generation numbers, the new code still benefits from a tighter min_generation floor compared to the old approach. Derrick Stolee (expert in commit-graph performance) has requested benchmark data to quantify the improvement, though the original commit message noted gains would be small and mainly for octopus merges in deep histories.

Testing: Adds a single test case for the octopus up-to-date scenario to `t6408-merge-up-to-date.sh`.

History context: The original code dates to Junio C Hamano's 2008 builtin-merge conversion. Derrick Stolee's 2018 generation number work made `repo_in_merge_bases()` possible via `can_all_from_reach()`, but this call site was never updated.
