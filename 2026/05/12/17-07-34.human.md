This is the first patch of five in v8 of Harald Nordgren's series adding safe automated local branch cleanup. It introduces a new building-block subcommand: `git branch --forked <remote>`.

`--forked` lists local branches whose configured upstream (`branch.<name>.merge`) belongs to a given remote. The argument can be either a remote name (like `origin`, matching all branches tracking any `refs/remotes/origin/*` ref) or a specific remote-tracking branch (like `origin/master`). Multiple arguments are unioned. The implementation is straightforward: it parses each argument, resolves it as either a configured remote or a fully qualified remote-tracking ref, then iterates all local refs and checks each one's upstream. Branches that match are printed.

The patch is clean and well-structured. The commit message explains the purpose clearly. The code is organized into a new `list_forked_branches()` entry point with a helper `parse_forked_args()` and a `branch_is_forked()` predicate. Error handling covers the expected cases -- missing argument, unknown remote or ref. The test suite creates a small multi-remote repository and exercises the basic cases: listing by remote name, by specific tracking branch, unioning, and error paths. The tests look thorough and correct.

This is a solid first step. It is a purely additive feature (it introduces a new option and does not touch existing behavior), and the implementation is self-contained and easy to follow. As noted in the thread summary, this patch is unchanged from v7 and is the foundation on which the core `--prune-merged` logic (patch 3) depends. Readers primarily interested in the overall effort may want to move quickly through this patch and focus on patch 3, where the real design work happened.
