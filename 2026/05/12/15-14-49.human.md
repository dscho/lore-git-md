This is a final patch (patch 7/7) in Derrick Stolee's series that adds
`--negotiation-include` and `--negotiation-restrict` controls to fetch and
push. The series is complete and ready for integration; this patch covers the
push side.

The core change is in `send-pack.c`: when `push.negotiate` is enabled and the
user has configured `remote.<name>.negotiationInclude` or
`remote.<name>.negotiationRestrict`, those values are now forwarded to the
child `git fetch --negotiate-only` process that handles push negotiation. When
no restrict pattern is configured, the code falls back to listing all remote
refs as negotiation tips (converted from the old `--negotiation-tip` option
to the new `--negotiation-restrict` synonym, as part of the rename done
earlier in the series).

The patch is clean, well-structured, and includes tests in
`t/t5516-fetch-push.sh` for both config options. Reviewer Matthew Cheetham
read it through and had no further comments beyond a positive "nice!" about
the option rename in the implementation, and "I've got no other comments on
this patch" -- two surface-level documentation cross-reference and test-
robustness observations from his review of patch 6/7 were noted separately,
but this patch itself passed without issues.

This is a straightforward wiring patch that completes the series' stated goal.
No controversy, no open questions remaining on this particular patch. If any
potential trouble remains for the series as a whole, it would be in patch 5/7
(the implementation of `--negotiation-include`), where a subtle v0/v1
protocol bug and a design-layer consistency question from Cheetham are still
awaiting Stolee's response.
