**Classification:** Bugfix, patches 3/3 of a three-patch series fixing edge cases in the approxidate date parser. This is the final patch in the series from Tuomas Ahola, completing the work on long-standing approxidate quirks that were reported as far back as 2006.

This patch introduces a deferred-adjustment scheme for the "now" and "yesterday" specials, using negative `tm_mday` values as markers that the `update_tm()` function resolves later. The mechanism works like this: when "now" or "yesterday" is encountered, `tm_mday` is set to -1 instead of being immediately filled in from the current clock. In `date_time()` (which handles "noon", "tea", and "midnight"), the old rollback logic -- which wrapped "noon" to the previous day if the current hour was before noon -- is replaced by setting `tm_mday = -2`. The `update_tm()` function then interprets these negative values: -1 means "use today's date", -2 means "use yesterday's date", and more negative values would mean earlier days. Crucially, because this resolution happens late, if an explicit day-of-month was provided elsewhere in the input string, it overwrites the negative sentinel and the rollback is suppressed entirely. This makes "tea yesterday" work correctly (tea-time of yesterday) rather than going to the last tea-time and then subtracting another day.

The patch also removes the `now` parameter from `date_time()` and marks the corresponding parameters in the callers (`date_midnight`, `date_noon`, `date_tea`) as unused, since the deferred approach no longer needs the current time at that point. Three test cases are added: "noon today" at an offset that crosses a month boundary (to check that the deferred approach handles month rollover correctly), "noon yesterday" at -12 hours offset, and "tea last saturday" at both offset 0 and -12 hours. These tests cover the day-wrapping behavior and verify that time-of-day no longer affects the result for combined special+day inputs.

A detail worth noting: the existing test case "noon today" at offset -12 is present (with the expected result unchanged from earlier patches) but has been adjusted in the test file to a different expected date on one of its invocations -- the cover letter from patch 2/3 explained that the "today" alias for "now" was added there, so this patch correctly integrates with that.

For downstream consumers: this is the core technical payoff of the series. The deferred-adjustment approach is clever without being over-engineered -- using negative sentinels in an already-special-used field is a natural fit for a parser that processes tokens sequentially with only partial state. The code change is tight (25 lines in `date.c`, 4 in the test file) and each piece has a clear purpose documented in comments. The `date_time()` function is simplified by losing its dependency on the `now` parameter, which is a nice side effect.
