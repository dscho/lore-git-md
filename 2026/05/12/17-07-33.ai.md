This is the cover letter for v8 of Harald Nordgren's five-patch series adding `git branch --prune-merged` for safe automated local branch cleanup. A v8 so soon after v7 -- just one day -- is a strong signal that Harald is directly addressing Junio C Hamano's design concerns from the v7 review.

The most consequential change is in patch 3, the core pruning logic, and it represents a fundamental redesign of the safety model. V7 checked whether a branch's *push destination* ref still existed on the remote -- if it did, the branch was left alone, regardless of whether its work had been merged. V8 throws that entire approach out. Instead, v8 checks whether the branch's tip is reachable from its configured *upstream* remote-tracking branch (the `branch.<name>.merge` setting, not `branch.<name>.push`). This is a much more intuitive and defensible safety check: a local branch that is fully contained in the upstream branch it tracks has probably been integrated and is safe to delete. Branches whose upstream ref no longer resolves locally are simply skipped -- their disappearance does not prove integration. The previous push-ref existence check and the upstream-gone-fallback-to-remote-default logic that Junio questioned are both gone. The range-diff confirms that the test suite has been rewritten to match these new semantics.

This redesign directly addresses the two core concerns Junio raised. First, the safety model is now based on a clear and intuitive criterion: "is this branch already consumed by its upstream?" rather than "does upstream still exist somewhere on disk?" Second, the `no_head_fallback` parameter and the associated fallback-to-remote-HEAD logic that Junio found questionable have been removed entirely -- the code no longer tries to fall back to anything when the upstream is gone; it just skips the branch (with a message). The test for the upstream-gone case also changed: v7 tested that the fallback would still delete the branch using the remote default; v8 tests that the branch is left alone when its upstream is gone, which is the new behavior.

Patches 4 (`branch.<name>.pruneMerged` opt-out) and 5 (`--all-remotes`) have been updated to match the v8 semantics, with documentation and test adjustments that are mechanical consequences of the core redesign. The documentation for `--prune-merged` has been rewritten entirely -- the earlier version that mentioned `branch_get_push` is gone, replaced by a clearer explanation of the upstream-reachability check. Patch 2 (the `warn_only` change to `delete_branches`) and patch 1 (`--forked`) are unchanged from v7.

If this design holds up, the series resolves the open design question that has been the sticking point since v7. The tests cover the key scenarios: integrated branches are deleted, unintegrated branches are refused, `--force` bypasses the check, checked-out branches and the remote default branch are protected, the opt-out config overrides even `--force`, and `--all-remotes` works across multiple remotes. The test suite is thorough and the commit messages are well-structured. The only remaining question is whether the maintainer and reviewers find the new upstream-reachability model acceptable, or whether a different set of concerns emerges on this iteration.
