This is patch 4/5 in Harald Nordgren’s v7 series for branch pruning, adding a per-branch configuration opt-out: `branch.<name>.pruneMerged`.

The commit message is clear and the motivation is immediately understandable.  If you have a topic branch that you want to keep around between review rounds, setting this config to `false` prevents `--prune-merged` from deleting it, even with `--force`.  Explicit `git branch -d` is unaffected, so the user isn’t locked out of cleaning it up manually.

The implementation is straightforward.  In the `prune_merged_branches()` loop, it reads the config for each candidate branch and skips it (with a diagnostic message) if the setting is false.  The test coverage is solid and mirrors what you’d expect: a basic test that the opt-out works, a test that `--force` doesn’t override it, and a test that `git branch -d` still acts as normal.  These are the right cases to check.

This patch is uncontentious.  It’s a logical and well-defined extension of the `--prune-merged` feature, and the implementation is clean and self-contained.  It looks ready for `next`.
