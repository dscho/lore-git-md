This is a performance optimization patch from René Scharfe, part of the overall `the_repository` removal effort. It is patch 4/4, and the preceding patches in this series appear to have been about introducing the `strbuf_add_uint()` function and cleaning up related infrastructure; this patch puts that function to use.

The change is in `builtin/ls-tree.c`, in the `expand_objectsize()` function. Previously, printing object sizes used the general-purpose `strbuf_addf()` with format strings like `%7"PRIuMAX"` for padded output or `%"PRIuMAX"` for unpadded. This patch replaces that with `strbuf_add_uint()` for the unpadded case, and then handles the padded case manually -- if the resulting string is shorter than the padding width (7 characters for objects), it inserts spaces at the beginning using `strbuf_insert()`.

The commit message includes benchmark results from the Linux kernel repository showing a modest but consistent speedup: about 1% faster for both the plain objectsize and the padded variant, across ten runs each. The numbers are tight and the confidence intervals look good for a micro-optimization of this kind.

This is exactly the sort of tidy, low-risk refactoring René is known for. The patch is small, well-explained, and includes real benchmark data rather than hand-waving. It will almost certainly be picked up without controversy. A 1% speedup on a command like `ls-tree --recursive` over a kernel-sized tree is not earth-shattering, but these incremental improvements add up over time, and in the context of automated or CI-heavy workflows they could be noticeable.
