Classification: Bugfix series -- test infrastructure patch for the approxidate subsystem.

Patch 1/3 (this email) is a preparatory change that does not fix any bugs itself. It modifies `t/t0006-date.sh` so that the `check_approxidate` helper accepts an optional fourth argument: an hour offset relative to the test's fixed "now" time. The patch wraps calls to `test-tool date approxidate` with `GIT_TEST_DATE_NOW`, an environment variable that the date code honors to override the current clock. After setting the variable, the helper tests the approximation, then restores the original value.

The patch also demonstrates the new feature with two test cases for `"January 5th yesterday"`: one at zero offset (which should produce `2009-01-29`, the day before January 5 from the test's epoch in late August) and one at a +48-hour offset (which should roll the result back to the previous year, `2008-12-31`, because pushing "now" forward by two days causes January 5 to already be in the past relative to the new "now").

The change is small and well-scoped: 11 lines added to the test file, no changes to production code. It directly addresses a concern Jeff King raised in the v1 review -- that tests for day-rollover behavior need to control whether "now" is morning or afternoon to be reliable.

This is the kind of infrastructure addition that makes later bugfix patches testable with confidence. The implementation is straightforward and follows existing patterns (the variable `GIT_TEST_DATE_NOW` already exists in the codebase; this patch just wires it into the test helper). No controversy expected here.
