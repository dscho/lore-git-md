This is a preparatory infrastructure patch, the first in a three-patch series targeting long-standing bugs in Git’s date approximation logic. The author, Tuomas Ahola, is a relatively new contributor taking over a series that was previously worked on by a different author under the same subject line.

The patch adds a mechanism to `t/t0006-date.sh` that lets individual `check_approxidate` tests override the “current time” used as a reference for fuzzy dates. It does this by accepting an optional fourth argument (an hour offset) and wrapping the test in a `GIT_TEST_DATE_NOW` environment variable. Two demonstration tests are added showing that “January 5th yesterday” produces different absolute dates depending on how many hours you offset the clock — a case that previously could not be tested reliably because the test harness used a single frozen “now”.

This is a clean, well-motivated change. The existing test infrastructure used a hardcoded `GIT_TEST_DATE_NOW` for the whole file, which meant that tests involving time-of-day rollovers (like whether “noon” lands on today or tomorrow) could not be exercised from both sides of the boundary. The patch solves that by saving and restoring the variable around each test call. Jeff King raised this exact concern in the v1 review, so this is a direct response to reviewer feedback.

The delta is small — 11 lines, with the demonstration tests accounting for most of the insertions. The approach is straightforward and introduces no new concepts beyond a shell variable with a short-lived override. If anything, the patch is almost too minimal: it does not document the new argument in the function header comment, and the caption logic uses an unquoted variable check (`[ ! -z $4 ]`) that some shell style guides would flag, though neither is a blocker.

For a reader: this is the easy patch of the series. It sets the stage so that patches 2/3 and 3/3 can actually test their fixes at both ends of the day. Worth a quick look if you have an opinion on test infrastructure design, otherwise unobjectionable.
