This is **patch 2 of 5 in Harald Nordgren's v8 series** adding `git branch --prune-merged`. It is a mechanical preparation patch: it adds `warn_only` and `n_not_merged` parameters to `delete_branches()` (and its helper `check_branch_commit()`) so that a bulk-deletion caller can downgrade "not fully merged" refusals from errors to warnings and skip setting the exit code for those refusals. All existing call sites pass 0/NULL and are completely unaffected. The patch is clean, well-explained, and exactly what you would expect for a refactoring step before introducing the new pruning command in patch 3 -- nothing controversial here.

Patches 1 and 2 lay groundwork; patch 3 (the core pruning logic) is the interesting one. Junio C Hamano's v7 concerns about the safety model appear to have been addressed in the v8 redesign of that patch, but he has not yet responded to v8. This series is worth a look if you care about safe automated branch cleanup or about the design of `git branch`'s bulk-deletion interface.
