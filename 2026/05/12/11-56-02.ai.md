This is a performance patch from René Scharfe, replacing a `strbuf_addf()` call in `builtin/ls-files.c` with the more specialized `strbuf_add_uint()` plus `strbuf_insert()` for padding. The change affects `ls-files --format='%(objectsize)'` and the padded variant `%(objectsize:padded)`.

The benchmark numbers are included and convincing -- roughly 1.5% speedup on a Linux kernel tree for the objectsize format. The numbers for the padded variant are similar. This is a small but measurable win, achieved by avoiding the overhead of printf-formatted formatting when all you need is a decimal integer and, optionally, right-padding with spaces.

There is nothing controversial here. The patch is mechanically straightforward, the performance improvement is real and well-measured, and René is known for precisely this kind of tidy optimization. The single-line logic change (the `else` branch for non-blobs now always appends `"-"` rather than having a separate `padded` branch) is a nice side-benefit: it simplifies the control flow slightly. The commit message is clear and self-contained.

This looks ready to apply.
