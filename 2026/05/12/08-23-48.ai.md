**Classification**: This is the fourth patch in a five-patch series (v7) implementing a `--prune-merged` option for `git branch`. Specifically, this patch adds a per-branch config opt-out: `branch.<name>.pruneMerged`.

This is a straightforward feature patch. It introduces a new configuration option that lets users exempt individual branches from automated pruning. The implementation is clean and proportional to the feature: a config lookup in the `prune_merged_branches()` loop, a test suite with three cases, and documentation updates in both the config man page and the `git branch` man page.

The design is simple but well-motivated. The commit message identifies the use case directly: keeping a topic branch between review rounds when the main pruning logic would otherwise delete it. The opt-out is absolute -- `--force` does not override it, which is explicitly tested. Normal `git branch -d` is unaffected, which is also tested.

The patch also includes a minor but real documentation improvement: the `--prune-merged` synopsis paragraph in `git-branch.adoc` is revised to replace an inline parenthetical reference to `branch_get_push` semantics (an internal function name not meaningful to users) with a plain-English parenthetical. This is a nice touch that the author did not call out in the commit message but that users will benefit from.

The three tests cover the opt-out in-action, the opt-out being respected under `--force`, and the opt-out not interfering with explicit deletion. This is complete coverage for the feature surface.

This is the kind of patch that is unlikely to generate controversy. The config knob is optional, the semantics are obvious, the implementation is contained, and the tests are thorough. If the rest of the series holds up, this patch should merge without issue.
