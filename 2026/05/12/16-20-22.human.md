This is a small cleanup patch from Jeff King targeting `add_rfc2047()` in `pretty.c`. That function handles encoding email headers (like author names) using RFC 2047 quoted-printable encoding.

The patch removes a single `strbuf_grow()` call that pre-sizes the output buffer. The pre-sizing formula has a potential integer overflow on 32-bit systems with unusually large input (roughly 1.4GB author names), and while it was originally a genuine optimization when the code used raw arrays, it was rendered purely cosmetic back in 2007 when the code was converted to use `strbuf`. Peff argues convincingly that the optimization isn't doing anything measurable -- even for the absurd 1.4GB case, removing it makes no difference. The commit message is excellent: it traces the history of the line, explains why the overflow isn't actually exploitable (the buffer just grows on the next write), but acknowledges it *looks* like a vulnerability and is therefore worth fixing cleanly by just deleting the line rather than adding checked-arithmetic machinery.

This is a three-second read from a trusted contributor: well-motivated, clearly explained, no behavioral change, and trivially correct. It should be entirely uncontroversial and likely to land quickly.
