This is patch 6 of 9 in Taylor Blau's pseudo-merge bitmap bugfix series, which the maintainer has signaled is nearly ready to merge. This patch fixes a bug where `find_pseudo_merge_group_for_ref()` was calling `lookup_commit()` without also parsing the commit. Because an unparsed commit has its date field set to zero, every commit was being classified as "stable" (i.e., older than any plausible threshold), making the `bitmapPseudoMerge.*.threshold` and `stableThreshold` configuration options completely inoperative. The stable/unstable split was effectively determined by `stableSize` alone, and the `sampleRate` knob (which only applies to the unstable path) was never exercised.

The fix is a two-line addition in `pseudo-merge.c`: a call to `repo_parse_commit()` after `lookup_commit()`, with a bail-out if parsing fails. The corresponding test in `t5333` is promoted from `test_expect_failure` to `test_expect_success`, using `GIT_TEST_DATE_NOW` aligned with `test_tick` to make the freshly-created commits appear younger than one month so only the catch-all group matches them.

This is a clean, well-motivated fix with a straightforward commit message that thoroughly explains the symptom, root cause, and test strategy. The patch also demotes another test (the `sampleRate=0` division-by-zero scenario) to `test_expect_failure`, acknowledging it as a separate bug that patch 7 will address -- a good organizational choice that keeps each fix self-contained.

No surprises here; this patch follows the established pattern of the series and looks ready to go.
