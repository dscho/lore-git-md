This is the third patch in a four-part bugfix series from Michael Montalbo. It adds defensive `BUG()` checks inside xdiff's `xdl_get_hunk()` to catch negative context lengths at runtime.

The reasoning is straightforward: the previous two patches in the series converted `--inter-hunk-context` and `-U`/`--unified` to unsigned types so that the command-line parser rejects negative values before they ever reach xdiff. But the xdiff layer itself still uses signed `long` for its context fields -- and cannot switch to unsigned because its arithmetic (e.g., `XDL_MAX(xch->i1 - xecfg->ctxlen, 0)`) relies on signed subtraction that would silently wrap if the types were changed. So instead of changing types in xdiff, this patch places explicit `BUG()` guards at the entry to `xdl_get_hunk()`, which is the single function called by both xdiff output paths (`xdl_emit_diff()` and `xdl_call_hunk_func()`). Should a negative value somehow make it through in the future -- from a different code path or a programming mistake -- the process will abort immediately rather than producing garbled hunks.

The commit message is well-explained and correctly identifies why converting xdiff's types is not an option, making the defense-in-depth justification clear. This is a clean, minimal change that does exactly what it needs to do.
