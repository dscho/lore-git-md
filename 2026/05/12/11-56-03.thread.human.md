This thread is about a performance optimization by René Scharfe for `git ls-tree` when formatting with `%(objectsize)` and `%(objectsize:padded)` fields. The patch is part of a small series that introduces a common `strbuf_add_uint()` helper and then applies it in several callers.

The change is straightforward: in `builtin/ls-tree.c`, the `expand_objectsize()` function is replaced from using the general-purpose `strbuf_addf()` with a `PRIuMAX` format specifier over to `strbuf_add_uint()`, with padding handled by `strbuf_insert()` using a static space string rather than a `%7s` format. René included measured performance numbers: roughly a 1% speedup on `ls-tree -r` of the Linux kernel repo for both padded and unpadded variants (from about 295ms to 291ms, based on 10 runs each). The numbers are clean and the direction consistent.

The code appears correct and follows René's typical pattern: a small, self-contained improvement with no behavioral change, a clean diff, and clear before-and-after benchmarking. The only minor observation is that the static `padding[]` string of seven spaces mirrors the existing `%7s` format behavior, which would need updating if the field width ever changes, but that is not a problem for this patch as it is a faithful conversion. The patch is uncontroversial, received only surface-level review, and is likely ready for `next` — though the thread should note that the code's correctness was verified only by the author's existing test coverage, not by substantive independent review.
