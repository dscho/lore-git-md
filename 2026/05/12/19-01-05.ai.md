This is a reply from Jeff King reviewing patch 3 of René Scharfe's strbuf_add_uint() series.

The review is substantive but informal -- Peff acknowledges the performance gain (modest here, less impressive than in the earlier cat-file patch), then digs into the code structure. He expresses mild dissatisfaction with the way padding is handled: the patch formats the number into the strbuf, then calls strbuf_insert() to shift the content right if padding is needed. He notes that this involves a memmove() that could potentially eat into the performance gains.

He then sketches two alternatives: a helper that pre-computes the decimal digit count so padding can be inserted before the number, or some formatter struct that accumulates state across calls. He dismisses both as over-engineering for this use case, acknowledging that a single format string like "%7d" is "nice and concise." The tone suggests he has no intention of blocking the patch over this -- these are musings, not demands for a v2.

The last paragraph is an idle speculation about writing a custom vsnprintf() for Git, tagged with a ";)" -- Peff is not proposing that, just thinking out loud about the problem space. This is the kind of offhand observation that might plant a seed for a future contributor, but has no bearing on the current series.

Bottom line: Peff's reply is not a review that requires action. He finds the code less elegant than the earlier patches, but he is not asking for changes. The series remains ready for the maintainer.
