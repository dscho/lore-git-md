This is utility refactoring (patch 2/5 in Harald Nordgren's `--prune-merged` series) that retrofits `delete_branches()` and its helper `check_branch_commit()` with two new parameters -- `warn_only` and `n_not_merged` -- so a bulk caller can suppress the per-branch "not fully merged" error messages and instead count silent refusals. The change is entirely mechanical: all existing call sites pass `0` and `NULL` and are unaffected. About 20 lines of C in `builtin/branch.c`.

The motivation is straightforward: when `git branch --prune-merged` is running in bulk across many branches, printing a multi-line error with advice about `-D` for each skipped branch would be noisy and unhelpful. The `warn_only` flag downgrades the error to a one-line warning and prevents the function from setting a non-zero exit code, while `n_not_merged` lets the caller tally refusals and report a summarized count at the end.

This is a clean, narrowly scoped prep patch. The commit message explains both parameters clearly, the diff is small and easy to verify, and the existing callers are left untouched. It is the kind of infrastructure addition that should be uncontroversial: it does exactly what it says, nothing more. If the overall series is going to land, this patch is a straightforward building block that should not hold things up.
