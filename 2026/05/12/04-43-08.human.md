This is the maintainer's wrap-up of the alias regression thread. Not a code
patch, but a procedural signal: Junio C Hamano is satisfied with the
discussion and is merging the fix into the `next` integration branch.

The technical solution that was debated over several rounds -- restoring
support for dotted hierarchical aliases (like `pull.sub`) that broke in Git
2.54.0, while reserving certain names for structured configuration -- has
reached consensus. The final unresolved question was about how to handle
deprecation wording in the documentation. Jonatan Holmgren clarified that
his earlier mention of deprecation was a documentation concern, not a
technical proposal, and Junio accepted that the current patch strikes the
right balance: it restores backward compatibility without painting the
project into a corner for the future.

The thread is effectively resolved. Readers who care about the alias
regression can expect the fix to hit `next` shortly and eventually
`master`. Anyone following the deprecation debate can consider it settled
for now -- the dotted-alias syntax will be presented as a legacy feature in
the documentation, with possible future deprecation after Git 3.0.
