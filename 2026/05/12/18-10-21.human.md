This is the second patch in a four-part bugfix series from Michael Montalbo, converting `-U`/`--unified` to reject negative values, which currently produce corrupt unified diff output with malformed hunk headers.

The patch changes `diff_options.context` and its static default from `int` to `unsigned int`, matching the analogous change for `--inter-hunk-context` in the preceding patch. Unlike that option (which could be converted directly to `OPT_UNSIGNED`), `-U` needs `OPT_CALLBACK_F` because bare `-U` with no value enables patch output, so validation is added as a range check inside the callback instead. The config variable `diff.context` already rejected negatives, but the config parsing is reworked to validate into a local `int` before assigning to the now-unsigned field. A test case is added for negative `-U` rejection.

The patch is clean, well-motivated, and follows the pattern established by patch 1/4. The type change is minimal and type-safe, the error message for the new rejection matches the one from the config path, and the test confirms the behavior. The `PARSE_OPT_OPTARG` interaction (bare `-U` enabling patch output) is noted and handled correctly. The series as a whole has been reviewed by Junio and looks ready for `next`. This patch in particular is straightforward, well-explained, and should merge without controversy.
