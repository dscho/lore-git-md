This is the second patch in Taylor Blau's v3 nine-patch series fixing bugs in Git's pseudo-merge bitmap implementation. It adds tests that demonstrate the bugs that subsequent patches will fix.

Specifically, the patch adds five tests to `t/t5333-pseudo-merge-bitmaps.sh`:

The first test exercises `apply_pseudo_merges_for_commit()` during a fill-in traversal -- the code path that Jeff King (Peff) noticed was never tested. It creates a repo with 64 commits, tags them all, and writes a bitmap for only the oldest commit. When pseudo-merge groups are configured, the fill-in traversal should find and use the pseudo-merge, but this test is currently marked as failing.

The second test extends this to multiple pseudo-merge groups: it creates two branches of 64 commits each and merges them, configures separate pseudo-merge groups for each, and tests that both groups are used during fill-in. Marked as failing.

The third test creates overlapping pseudo-merge groups (two groups with the same pattern) to exercise the extended lookup table within `apply_pseudo_merges_for_commit()`. Also marked as failing.

The fourth test verifies that commits are correctly classified by date when the pseudo-merge group has a `threshold` setting. This exercises the code path in `find_pseudo_merge_group_for_ref()` that must parse a commit before inspecting its committer date. Marked as failing.

The fifth test, for `sampleRate=0`, is the only one marked as passing. It describes a latent division-by-zero bug that is currently unreachable because it's masked by a separate bug. A future commit will fix the masking bug, causing this test to start failing, and a later commit will then fix the sample-rate bug and re-mark it as passing. This is carefully orchestrated.

This is a well-constructed test-first patch. The tests are clearly explained (each has an inline comment describing what it exercises), they target specific known bugs, and the `test_expect_failure` / `test_expect_success` marking is done with clear forethought about how the series will progress. The commit message is honest about the orchestration needed for the `sampleRate=0` test. For a series that Junio has described as "so close to the finish line," this patch does exactly what it needs to: it sets up the demonstrations of the bugs so that the rest of the series can prove they are fixed.
