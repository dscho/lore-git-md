This is the cover letter for v7 of Harald Nordgren's `--prune-merged` patch series, which introduces standalone `git branch` commands for safely cleaning up local branches whose upstream counterparts have been deleted.

The thread context shows that this series stalled over a specific design disagreement flagged by Junio in the v6 review. The v6 version had changed the merged-ness check from comparing a branch against its own upstream (via `branch_get_upstream()`) to comparing it against the remote's default branch (`refs/remotes/<remote>/HEAD`). Junio argued this was a regression: a branch tracking `refs/remotes/origin/todo` should not be compared to `refs/remotes/origin/HEAD` (typically `origin/master`). Harald conceded the point in the thread, stating he would take another look.

The key detail is in patch 3's range-diff. The v7 redesign reworks the `branch_merged()` function to add a `no_head_fallback` parameter. The new logic now checks against the branch's own upstream first (the original correct behavior from `branch_merged()`). If that upstream is gone, it then falls back to the remote's default branch. If neither exists, the branch is refused with a "not fully merged" warning unless `--force` is used. This directly addresses Junio's concern by restoring the upstream-first approach while preserving the useful fallback for cases where the upstream has been deleted from the remote.

The rest of the series remains structurally unchanged from v6: `--forked <remote>` for branches that exist locally but not upstream, `--prune-merged <remote>` for branches already integrated upstream, a `branch.<name>.pruneMerged` config opt-out, and `--all-remotes` to apply these across all configured remotes.

This looks like a well-crafted response to concrete maintainer feedback. The core design question has been resolved in a way that satisfies Junio's concern while preserving the safety mechanisms the series introduces. If the tests in v7 cover the scenario Junio flagged (a branch tracking a non-default remote branch whose upstream is gone), this should be close to ready for `next`.
