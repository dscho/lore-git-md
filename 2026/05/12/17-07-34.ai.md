This is a feature patch, part 1 of 5 of Harald Nordgren's v8 series adding `git branch --prune-merged`. This patch introduces the `--forked <remote>` option, which lists local branches whose configured upstream falls within a given remote -- the building block for the prune logic that follows.

`--forked` takes one or more arguments, each either a configured remote name (matching all of its remote-tracking branches) or a specific remote-tracking ref. It collects the branches by iterating all local refs, checking each one's `branch.<name>.remote` and `branch.<name>.merge` against the provided arguments. The patch adds about 110 lines to `builtin/branch.c`, the documentation, and the test suite.

The implementation is clean and straightforward. `parse_forked_args()` resolves each argument: if it is a configured remote, it is added to a `remote_names` list; if it can be resolved to a ref under `refs/remotes/`, it is added to a `tracking_refs` list; otherwise it dies. `branch_is_forked()` checks each local branch against both lists. The test suite covers the basic cases: listing all branches tracking `origin`, filtering to a single tracking branch, unioning multiple arguments, rejection of unknown remotes, and the required-argument error.

This is unchanged from v7 and functions as pure infrastructure -- no behavior change for end users not using `--forked`. It is well-tested and the commit message clearly explains the purpose. Worth attention only if you are reviewing the series as a whole; as a standalone patch it is unremarkable.
