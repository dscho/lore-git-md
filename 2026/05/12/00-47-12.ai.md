This is patch 9 of 9 in Taylor Blau's v3 pseudo-merge bitmap bugfix series and the previously expected final patch. It fixes a memory leak when a `bitmapPseudoMerge.*.pattern` config key appears more than once for the same group. When `pseudo_merge_config()` encounters a duplicate pattern, it frees the old `regex_t *` pointer but never calls `regfree()` first, leaking whatever internal state `regcomp()` allocated. The fix is a short guard that calls `regfree()` before `free()` when the pointer is non-NULL. The final cleanup path in `pseudo_merge_group_release()` already does this correctly, so only the intermediate-replacement path was affected.

The patch touches two files. In `pseudo-merge.c`, five lines replace a bare `free(group->pattern)` with a NULL-checked block that calls `regfree()` first. The test in `t/t5333-pseudo-merge-bitmaps.sh` creates a repository with 64 commits, configures the same pattern twice via `git config` and `git config --add`, builds a pseudo-merge bitmap using `test-tool bitmap write`, and asserts that exactly one pseudo-merge is produced. The test also runs under `test_when_finished` cleanup, consistent with the v3 test-hygiene fixups mentioned in the cover letter.
