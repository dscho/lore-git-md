A developer has found one small but longstanding bug in `http-walker.c`: when Git tries to fetch from a dumb HTTP server that advertises alternate object stores with absolute paths (e.g., `/parent.git`), it constructs the full URL by finding the first `/` after `://` in the server URL. If the server URL has no path component -- for example, `http://example.com` with no trailing slash -- the code's `strchr()` call returns NULL, producing a garbage length. This has been there since the feature was introduced in 2005.

Jeff King (Peff) sent a one-character fix to replace `strchr()` with `strchrnul()`, which returns a pointer to the end of the string instead of NULL, along with a new test. Peff's security analysis concluded the worst case is a failed clone or a misleading truncation already possible by other means -- no exploitable vulnerability. Junio C Hamano, who introduced the original code 20 years ago and facetiously wished he could kill off the dumb HTTP walker entirely, accepted the fix immediately ("Absolutely, thank you").

In the follow-up, Peff recalled that the idea of dropping dumb HTTP support was discussed a few years ago and tabled because Eric Sunshine pointed out that dumb clones are less server-intensive for large public-inbox repositories where old history lives in one big, never-updated pack. Peff noted that `git fetch`'s verbatim pack-reuse was meant to close that gap, but he has not measured whether it has. This is interesting project history but does not affect the patch at hand -- the fix is accepted and ready for integration. No one has independently verified the patch's correctness.
