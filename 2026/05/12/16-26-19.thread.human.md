This is a bugfix from Jeff King (Peff) for `http-walker.c` fixing a long-standing crash when Git fetches from a dumb HTTP server whose URL has no path component (e.g., `http://example.com` with no trailing slash). When resolving alternates advertised with absolute paths like `/parent.git`, the code tried to find the server root by scanning for the first `/` after `://` — but `strchr()` returns NULL when there's no path at all, producing a garbage length and a failed clone. The fix is a one-character change to `strchrnul()`. Peff's security analysis found no exploitable vulnerability, only a denial of service or misleading truncation already possible by other means. The patch also includes a genuine integration test that sets up a repository at the root of a HTTP document root. The fix is minimal (six lines of change), uncontroversial, and from a trusted author — it should be straightforward to integrate.
