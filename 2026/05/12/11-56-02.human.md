This is a small performance optimization patch, part of a series (3/4) from René Scharfe.

**What it does.** In `git ls-files --format=%(objectsize)` (and the `:padded` variant), the current code uses the general-purpose `strbuf_addf()` to format the integer as a string. This patch replaces that with `strbuf_add_uint()`, a specialized integer-to-string function, and handles padding with `strbuf_insert()` instead of a `printf` width specifier.

**Performance numbers.** René reports a roughly 1.5% speedup in wall-clock time when listing files in the Linux kernel repo: about 257 ms before, 253 ms after. On a 197 ms user-time job, that is a ~4 ms saving from removing the format-string overhead. For the padded variant the improvement is similar.
