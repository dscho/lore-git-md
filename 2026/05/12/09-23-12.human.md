This is a "What's cooking" report, the project rhythm email from Junio Hamano that surveys every topic currently in flight. It is not a patch -- it is the maintainer's status board, and it is by far the most efficient way for a busy developer to orient themselves in the Git project right now.

**What changed since the last report.** The first batch of topics has been merged to `master` after a long quiet period following 2.54-rc2. That batch includes the resurrected sideband sanitization topic (jc/neuter-sideband-fixup), which was merged in a stricter form so the project can see if the tighter restrictions work before deciding whether to postpone the loosening until Git 3.0. Several test fixes and a reverted regression (the transport-helper clean_on_exit change that broke mksh users) also graduated.

**The biggest new topics worth attention.**

Taylor Blau's tb/pseudo-merge-bugfixes is a nine-patch series fixing what the description calls "many bugs" in the pseudo-merge code, backed by a new test helper. Given how long pseudo-merges have been cooking and how subtle the bugs around binary search and shared-commit lookup are, this is likely worth a review from anyone who has touched that area.

The path-walk filters topic (ds/path-walk-filters) finally integrates `--path-walk` with object filters -- blobless, sparse, blob-size limits, and tree-depth filters. This is the intersection of two ambitious features and could produce some surprising interactions. It builds on en/backfill-fixes-and-edges, which already graduated to `next`.

Patrick Steinhardt's maintenance daemonize lockfix (ps/maintenance-daemonize-lockfix) fixes a real concurrent-process race where `git maintenance --detach` was not using the lockfile, so two maintenance runs could step on each other. That is a clear bugfix.

The in-memory ODB source (ps/odb-in-memory) from Patrick is a big 18-patch series introducing a new "in-memory" object store for tentative objects. It is waiting on the transaction write base topic (jt/odb-transaction-write), which itself has a leakfix needed. This is foundational plumbing that will matter for several downstream features (like `git blame` working with virtual objects), but it is deep water.

**A couple of things to watch for the debate potential.**

Han-Wen Nienhuys's branch pruning topic (hn/branch-prune-merged) is a substantial new feature -- automatically deleting local branches that have been merged upstream -- and Junio says "expecting a reroll" with a reference to his own follow-up comment. Feature additions to `git branch` are always a bit fraught because the existing command is so widely used.

The subcommand autocorrection topic (js/parseopt-subcommand-autocorrection) has a SQUASH commit flagged and Junio has already asked for a reroll. Automatically fixing user typos in commands like `git rmeote` is a nice idea but the implementation details around how to decide what to correct and when to prompt are always contentious.

**The discards are worth noting.** Three topics were dropped for inactivity -- a promisor lazy-fetch recursion prevention, a config lock retry timeout, and a per-URL default object filter for clone. If any of those mattered to you, someone would need to pick them up again.

**Bottom line.** The project is in a steady state -- the merge window for the next release has opened, topics are flowing into `next` and `master` at a healthy clip, and there is no drama flagged. The things that need careful attention this week are the pseudo-merge fixes (a genuine bug hunt) and the path-walk filter integration (two features colliding). Everything else is either cleanup, plumbing, or early-stage discussion.
