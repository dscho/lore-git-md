This is the first of four patches in a small, well-scoped bugfix series from Michael Montalbo targeting a real problem: negative values for `--inter-hunk-context` are silently accepted but produce structurally broken diff output (overlapping hunks that `git apply` cannot consume).

The root cause is cleanly diagnosed. When the option was converted from a custom parser that used `isdigit()` (implicitly rejecting negatives) to a standard `OPT_INTEGER_F`, the validation was lost. The fix switches to `OPT_UNSIGNED` and changes the field type from `int` to `unsigned int`, which rejects negatives at parse time and enforces the invariant at compile time through `BARF_UNLESS_UNSIGNED`. The config variable `diff.interHunkContext` already rejects negatives, so this brings the CLI into alignment.

The patch is minimal and mechanical, touching only three files. The config parsing (`git_diff_ui_config`) gets a small refactor to avoid assigning a negative intermediate value to an unsigned variable -- the check-and-then-assign pattern is correct. A test is added for the rejection case, following the existing test convention in the file.

This is a clean, low-risk fix. The commit message is clear, the change is type-safe, the motivation is real and demonstrable, and the work is part of a well-organized series where each of the four patches addresses one aspect of a single underlying problem. Ready for integration.
