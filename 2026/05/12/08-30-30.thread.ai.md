Subject: [PATCH v1 1/2] builtin/maintenance: fix lock file lifetime when daemonizing

Series version: v1, 2 patches, sent as a single unit (no cover letter).

Author: Patrick Steinhardt (Steinhardt at GitLab).

Thread type: Bugfix patch series.

Core problem: `git maintenance run --detach` creates a lockfile to prevent concurrent maintenance processes, but the lock's lifetime is broken by the daemonization pattern itself. The parent process creates the lock, then forks and calls `exit(0)` immediately. The parent's atexit handler cleans up the lockfile -- the lock only covers the brief interval before the child takes over, not the full duration of maintenance work. A second maintenance invocation can run concurrently, defeating the purpose of the lock.

Fix (two patches):

1.  Introduces `daemonize_without_exit()` -- a variant of `daemonize()` that returns the child PID to the parent instead of calling `exit(0)` in the parent. The existing `daemonize()` is reimplemented as a wrapper around `daemonize_without_exit()` for backward compatibility.

2.  Introduces `lock_file_reassign_owner()` -- transfers ownership of a lockfile's tempfiles from one PID to another, so the atexit handler of the old owner (the parent) will not unlink them.
3.  The maintenance code then uses these together: after forking with `daemonize_without_exit()`, both the parent and child reassign the lockfile's ownership to the child PID; the parent then exits without cleaning up the lock, and the child now owns it and cleans it up when *it* exits.

Files and subsystems touched:
- `daemon.c` / `daemon.h` -- new function `daemonize_without_exit()`; `daemonize()` reimplemented as a wrapper.
- `lockfile.c` / `lockfile.h` -- new function `lock_file_reassign_owner()`.
- `builtin/gc.c` -- maintenance code updated to use the new primitives.
- `t/t7900-maintenance.sh` -- new test using FIFOs to precisely sequence the parent exit and verify lock-file lifetime.

New symbols:
- In `daemon.h`: `daemonize_without_exit()`
- In `lockfile.h`: `lock_file_reassign_owner()`

Behavior change: No user-visible change; the fix corrects an internal bug where concurrent maintenance runs could proceed when they should have been blocked.
