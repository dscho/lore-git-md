This is a review from Jeff King of patch 3 in René Scharfe's four-patch series that adds a `strbuf_add_uint()` convenience function and converts call sites. Peff is replying specifically to the `ls-files` conversion.

Peff opens by noting that the speedup here (257ms → 253ms, about 1.5%) is much smaller than the `cat-file` patch's 4%. Then he examines the code, which uses a post-hoc `strbuf_insert()` with a static `padding` string to right-justify the number — a natural replacement for the old `%7"PRIuMAX` format specifier.

His reaction is mixed. The code works, but the extra `memmove()` from `strbuf_insert()` is inelegant. He muses aloud about ways to handle padding more cleanly — pre-computing the digit count and padding before formatting, or a stateful formatting helper — but dismisses each idea as overly complex for the problem at hand. The aside about implementing a custom `vsnprintf()` to add short format specifiers is clearly speculative and not a serious suggestion.

This is a **substantive review** with a light, conversational tone — Peff engages with the tradeoffs honestly ("OK, so here the improvement is less impressive...the code is...also less nice") but ultimately finds no real objection. The review does not request any changes; it reads more like thinking out loud about how the problem could be solved differently in a hypothetical future with more infrastructure. The fact that the earlier `cat-file` patch got an unconditional endorsement from Peff in the same thread confirms that the series as a whole is ready to go.
