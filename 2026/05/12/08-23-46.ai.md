This is **patch 2/5 of Harald Nordgren's v7 branch-pruning series**. It is a mechanical refactoring of the existing `delete_branches()` path that lays the groundwork for the bulk-deletion behavior required by the later `--prune-merged` and `--all-remotes` patches.

The change is straightforward and well-framed. Today, when `git branch -d` refuses to delete a branch because it is not fully merged, it prints an `error()` and a multi-line advice hint per branch, and sets a non-zero exit code. Once you are pruning dozens of branches in a single command, that approach becomes noisy and misleading -- the user does not need a per-branch `git branch -D X` hint for every single skipped branch. Harald adds two optional parameters to `check_branch_commit()` and `delete_branches()`: `warn_only` replaces the multi-line error+advice with a single `warning()` line and skips the exit-code increment, and `n_not_merged` counts the total refusals so a caller can print a summary if it wants one.

Both parameters default to `0` / `NULL` at the sole existing call site in `cmd_branch()`, so this patch has zero effect on current behavior. It is cleanly factored: a single-file change to `builtin/branch.c`, a function signature extension, and no surprises. The commit message is clear about what changes and why, and the diff is tight -- 20 insertions, 9 deletions, all mechanical.

This is the sort of careful preparation that makes a series reviewers tend to trust. No controversy here; this patch is essentially ready to go as-is. The interesting design decisions live elsewhere in the series (the merged-ness fallback logic in the `--prune-merged` patch), but this plumbing patch is a necessary and well-executed step toward them.
