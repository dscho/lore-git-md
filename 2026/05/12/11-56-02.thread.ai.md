Subject: [PATCH] ls-files: replace strbuf_addf with strbuf_add_uint for objectsize format
Series version: 1, originating author: René Scharfe
Thread type: patch (single patch)

Core problem: `ls-files --format='%(objectsize)'` uses `strbuf_addf()` to format a decimal integer and optional right-padding with spaces. `strbuf_addf()` carries printf overhead that is disproportionate to the simple formatting needed.

Current status: single patch, v1, no review or acknowledgment yet. Appears ready for merge.

Key technical details:
- File: `builtin/ls-files.c`
- Changes: replaces `strbuf_addf(&sb, "%"PRIuMAX, (uintmax_t)sz)` with `strbuf_add_uint(&sb, sz)` for the `%(objectsize)` format; replaces separate `padded` branch logic with `strbuf_add_uint()` followed by `strbuf_insert()` for space-padding. The `else` branch for non-blobs now always appends `"-"` rather than having a separate condition for the padded case.
- Performance: ~1.5% speedup on Linux kernel tree for objectsize format; similar for padded variant.
- Test coverage: existing tests cover the format options; no new tests needed for this mechanical refactoring.

Open questions and loose ends: none. Simple, uncontroversial optimization.
