This is a follow-up email from Jeff King replying to Junio's maintainer response. It adds project-memory context about the dumb HTTP protocol but does not change the patch's status.

**Thread identity** -- "http-walker.c: fix missing slash detection in absolute alternate URL parsing" by Jeff King (Peff). Single-patch bugfix. v1.

**Core problem or goal** -- When Git fetches from a dumb HTTP server that advertises alternate object stores with absolute paths (e.g., `/parent.git`), the code in `http-walker.c` constructs the full URL by scanning for the first `/` after `://`. When the URL has no path component (e.g., `http://example.com`), `strchr()` returns NULL, producing a garbage length. Bug present since the feature was introduced in 2005 (commit b3661567cf).

**Current status** -- Patch accepted by maintainer. One character change: `strchr(url, '/')` to `strchrnul(url, '/')`. Test added. Ready for integration. No version history.

**Key technical details** -- Files touched: `http-walker.c`. Peff's security analysis: worst-case is denial of service (failed clone) or, in a narrow scenario, misleading truncation already possible by other means -- no exploitable vulnerability.

**Open questions and loose ends** -- None regarding the patch. Peff adds project-memory context: the dumb HTTP walker has been a persistent source of bugs. Dropping dumb protocol support was discussed years ago; Eric Sunshine countered that dumb clones are less server-intensive for large public-inbox repositories where old history lives in one big, never-updated pack. Peff notes `git fetch`'s verbatim pack-reuse was intended to close that gap for smart clones, but he has not measured whether it succeeded. This context may matter if someone revives the deprecation discussion but has no bearing on the current fix.
