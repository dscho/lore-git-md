**Thread identity** -- "http-walker.c: fix missing slash detection in absolute alternate URL parsing" by Jeffking (Jeff King). Patch series (single patch). v1. Bug fix.

**Core problem or goal** -- When Git fetches from a dumb HTTP server that advertises alternate object stores with absolute paths (e.g., `/parent.git`), the code in `http-walker.c` constructs the full URL by combining the server's root with that path. It finds the server root by scanning for the first `/` after `://` in the URL. When the URL has no path component (e.g., `http://example.com` with no trailing slash), `strchr()` returns NULL, producing a garbage length value. The bug has existed since the feature was introduced in 2005 (commit b3661567cf).

**Current status** -- Patch sent. One character change: replace `strchr()` with `strchrnul()`, which returns a pointer to the NUL terminator instead of NULL when no slash is found, giving the correct length (everything after `://` is the host portion). No version history.

**Key technical details** -- Files touched: `http-walker.c`. Change: `strchr(url, '/')` to `strchrnul(url, '/')` in the function that parses absolute alternate URLs. Test added that sets up a repository served at the root of the HTTP document root (no path component) and verifies alternate resolution. Peff's security analysis concludes worst-case is denial of service (failed clone) or, in a narrow scenario, a misleading truncation already possible by other means -- no exploitable vulnerability.
