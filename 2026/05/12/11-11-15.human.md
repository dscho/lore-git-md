This is patch 2/7 of Derrick Stolee's v3 series adding negotiation control
options for `git fetch` and `git push` to support monorepo workflows. It
renames the existing `--negotiation-tip` option to `--negotiation-restrict`,
keeping the old name as a backward-compatible alias. The point is
terminological precision: `--negotiation-tip` sounds like it specifies a
minimum set of refs to advertise, but what it actually does is set a
maximum (the server is told about *only* the refs you specify, not all
local refs). The new name `--negotiation-restrict` makes that restriction
semantic clearer, and clears the naming space for the complementary
`--negotiation-include` option that appears later in the series.

The patch itself is straightforward plumbing: an `OPT_ALIAS` in the option
table, `OPT_PASSTHRU_ARGV` entries in `builtin/pull.c` for the new name,
updated man-page documentation that marks `--negotiation-restrict` as the
preferred name, three new test cases exercising the new option, and a minor
cleanup that makes warning messages translatable by pulling the option name
out of the translation string. The underlying variable (`negotiation_tip`)
is intentionally not renamed in this patch to keep the diff small.

Matthew Cheetham provides a substantive review that confirms the approach
and calls out two small remaining references to `--negotiation-tip` in the
documentation (`Documentation/fetch-options.adoc` under `--negotiate-only`
and `Documentation/config/fetch.adoc`) that could be updated for
consistency. He frames this as a nit and notes that the old name still
works, so the oversight is minor. Otherwise the review is positive -- he
approves of the rename-before-new-feature ordering, the i18n improvements,
and the decision to defer the variable rename for reviewability.

A straightforward, well-reviewed preparatory patch in a thoroughly
discussed series. Nothing controversial here; the two documentation nits
are the only follow-up needed.
