**Thread identity**: Bug report originally from Daniel Mach at SUSE (`git clone --dissociate is failing when the alternate has a commit-graph`). Standalone bug report -- not a patch series. Jeff King (Peff) has now confirmed this is the same bug he independently discovered just over a week earlier.

**Core problem**: `git clone --dissociate --reference <old-repo>` crashes during checkout with `fatal: unable to parse commit <SHA>` when the reference repository has a commit-graph. With `--dissociate`, Git repacks objects from the alternate and removes the `objects/info/alternates` file, but the clone process has already opened the alternate's commit-graph. After the alternate is no longer valid, the clone does not invalidate or reload the object store, so it attempts to parse commits using a commit-graph that references the now-unlinked alternate, causing parse failure.

**Current status**: Root cause independently confirmed by Jeff King, who identified the same bug in a separate investigation. Two candidate fix approaches have been described but no polished patch has been submitted or reviewed. The design decision between approaches remains open.

**Key technical details**: Subsystems: `builtin/clone.c` (dissociate logic), `commit-graph.c` (commit-graph loading and invalidation), and likely `object-store.h`. The fix will involve either (a) a lazy fallback -- when a commit-graph is closed or invalidated, fall back to manual object-reading rather than failing, or (b) an aggressive approach -- when dissociating, close the commit-graph and pre-fill all tree lookups that in-memory commits depend on. No new symbols, config keys, or on-disk format changes involved. The reproducer is Jeff King's shell script from the earlier thread (cross-referenced but not reproduced in Peff's reply).

**Open questions and loose ends**: The design question between the two approaches is unresolved. Peff notes the tradeoff depends on how many commits are examined after the close: if most are, pre-filling is cheaper; if only a few are, the lazy fallback wins.
