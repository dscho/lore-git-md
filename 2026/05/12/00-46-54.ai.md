This is patch 3 of 9 in Taylor Blau's pseudo-merge bitmap bugfix series, which Junio has indicated is nearly ready to merge. This patch fixes a concrete binary-search bug in the pseudo-merge commit lookup table.

The issue is in `pack-bitmap-write.c`: when writing the pseudo-merge commit lookup table, the commits were sorted lexically by OID via `oid_array_sort()`, but the reader's `find_pseudo_merge()` expects the table to be sorted by bit position (pack order) so it can binary-search correctly. The result is that pseudo-merge application during fill-in traversal -- the code path that looks for satisfied pseudo-merges after walking an object graph -- is effectively broken, because the binary search never finds the right entry. The commit message is well written and carefully explains why this does not produce *wrong* results (it just silently falls back to non-pseudo-merge fill-in), and why the initial-phase pseudo-merge application via `cascade_pseudo_merges_1()` was unaffected. It also notes that this changes on-disk format compliance but does not break any existing properly-generated bitmaps, since no correctly-functioning writer existed before this fix.

The change itself is straightforward: replace `oid_array_sort()` with a `QSORT_S()` using a new comparator `pseudo_merge_commit_pos_cmp()`, which resolves each entry's pack position via `find_object_pos()` and orders accordingly. The diff is about 20 lines plus a test expectation change: one of the previously-`test_expect_failure` tests introduced in patch 2 is now promoted to `test_expect_success`, since this patch makes it pass.

This is one of the core fixes in the series; the remaining patches address the other broken test cases (overlapping groups, multiple groups, date classification, and the division-by-zero hazard). The commit is clean, well-motivated, and addresses a genuine correctness issue in a relatively recent feature.
