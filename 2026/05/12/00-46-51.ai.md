This is patch 2/9 in Taylor Blau's nine-patch pseudo-merge bitmap bugfix series, which is essentially ready to merge (Junio has signaled the series is "so close to the finish line" in his What's cooking draft, and v3 only changed test-hygiene details). This is the test infrastructure patch that adds failing tests to demonstrate the bugs that the rest of the series fixes.

The patch is substantial -- it adds 198 lines of test code to the existing `t/t5333-pseudo-merge-bitmaps.sh` script. It introduces five new test scenarios, four of which are deliberately marked as expected failures (`test_expect_failure`). The fifth, a sample-rate-zero test, passes now but is known to mask a latent bug that a later commit will expose and then fix.

The four failing tests cover: applying pseudo-merges during fill-in traversal (the main code path that was never exercised), applying pseudo-merges from multiple groups during fill-in, applying pseudo-merges with overlapping groups (to exercise the extended lookup table path in `apply_pseudo_merges_for_commit()`), and verifying that pseudo-merge commits are correctly classified by date (which requires parsing commits before inspecting their timestamp in `find_pseudo_merge_group_for_ref()`). The passing test covers `sampleRate=0` not causing a division-by-zero -- but the commit message explicitly notes this is only passing because a separate bug prevents reaching that code path, so it will be reclassified as failing in a later commit and then fixed.
