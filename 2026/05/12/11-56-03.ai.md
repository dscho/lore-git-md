This is a performance patch from René Scharfe optimizing `git ls-tree` when formatting with the `%(objectsize)` and `%(objectsize:padded)` fields. It is part of a four-patch series (cover letter not seen) that apparently introduces a common `strbuf_add_uint()` helper and then applies it in several callers.

The change is surgical and well-measured: in `builtin/ls-tree.c`, the `expand_objectsize()` function is replaced from using the general-purpose `strbuf_addf()` with a `PRIuMAX` format specifier over to `strbuf_add_uint()`, and padding is handled by `strbuf_insert()` with a static space string rather than a `%7s` format. The performance numbers are included and show roughly a 1% speedup on a `ls-tree -r` of the Linux kernel repo for both the padded and unpadded variants, from about 295ms to 291ms. The numbers are clean, the methodology sound (10 runs each), and the effect direction consistent.

The code itself looks correct and follows the mechanical pattern one expects from René: a small, self-contained improvement with no behavioral change, clean diff, and a clear before-and-after benchmark. The only minor observation is that the hardcoded `padding[]` string of seven spaces is tied to the existing `%7s` format behavior, which is fine for this single call site but would need updating if the field width ever changes. That is not a problem for this patch -- it is a faithful conversion. The patch is uncontroversial and likely ready for `next` after a brief review.
