This is patch 3/5 of Harald Nordgren’s v8 series adding `git branch --prune-merged`. This is the core redesign that addresses Junio C Hamano’s v7 concerns.

The patch introduces `prune_merged_branches()`, about 140 lines of new C code in `builtin/branch.c`. The safety model has been fundamentally overhauled from v7: instead of checking whether a branch’s push destination still exists on the remote, v8 checks whether the local branch’s tip is reachable from its configured upstream remote-tracking branch (`branch.<name>.merge`). If the upstream ref cannot be resolved locally (because the remote-tracking branch was deleted, for instance), the branch is silently skipped — the upstream’s disappearance is not treated as evidence of integration. The previous fallback-to-remote-HEAD logic is gone entirely.

The internal plumbing is straightforward: `collect_forked_set()` (extracted from the existing `--forked` infrastructure) builds the candidate set of local branches that track branches on the given remote(s). A new helper `collect_default_branch_refs()` resolves each remote’s `refs/remotes/<remote>/HEAD` so that the remote’s default branch is protected by name. The candidate loop then applies three safeguards before offering a branch for deletion: it must not be checked out in any worktree, it must have a resolvable upstream, and if that upstream happens to be the remote’s default branch, the local branch must not share the same name. Branches that pass all checks are collected into a `strvec` and handed to `delete_branches()` with the `warn_only` flag introduced in patch 2.

The patch also adjusts the existing `branch_merged()` helper, changing `head_rev != reference_rev` to `head_rev && head_rev != reference_rev` — a small correctness fix that avoids calling `repo_in_merge_bases()` on a NULL revision, though this is dead code not reached in the new prune path.

The documentation in `git-branch.adoc` is rewritten to describe the new upstream-reachability semantics clearly, including a suggested workflow of `git fetch <remote>` followed by `git branch --prune-merged <remote>`. The test suite adds seven new tests covering: basic integrated-branch deletion, sparing unintegrated branches (with the summarized warning message), `--force` override, sparing branches with a gone upstream, sparing the checked-out branch, sparing the local default branch by name, and confirming that a differently-named tracking branch of the default is *not* protected. The test infrastructure uses a shared upstream repo with branches at different merge-base distances.

This is a clean, well-structured patch that directly addresses the maintainer’s stated concerns from v7. The test coverage is thorough and the commit message explains both the reasoning and the edge cases. If this design holds, the series is likely on track to move beyond `seen`.
