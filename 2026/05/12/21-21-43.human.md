This is a documentation fix from D. Ben Knoble, now in its third iteration. The patch corrects Git's documentation and code comments to accurately reflect that the per-repository exclude file lives at `$GIT_COMMON_DIR/info/exclude` rather than the historically documented `$GIT_DIR/info/exclude`. This is a pure documentation adjustment -- the actual behavior has been this way since Git 2.20, and no code changes are involved.

The backstory matters here: this thread began with a proposal to add genuine per-worktree ignore files -- a feature that would let different worktrees in the same repository have their own ignore patterns. The response, notably from Junio and Phillip Wood, was skeptical. Junio questioned whether per-worktree ignores were actually useful, and Wood raised design concerns. The author wisely accepted the community's judgment and scaled back to the v2 goal of simply fixing the documentation to match reality. The commit message includes a concrete use case (a colleague's LLM skill-file tool) that motivated the original idea, which is good practice.

This v3 expands coverage beyond `gitignore.adoc` to include five additional files that Wood's `git grep` found still referencing the old path: `git-ls-files.adoc`, `git-svn.adoc`, `gitformat-index.adoc`, `dir.c`, and `dir.h`. The v2 had only touched `gitignore.adoc`, which Wood rightly flagged as incomplete. The author has now addressed all instances in those six files -- thirteen changes total, all mechanical `$GIT_DIR` -> `$GIT_COMMON_DIR` substitutions.

This is a clean, well-scoped patch from an experienced contributor who listened to feedback and produced exactly what the project needed. It is uncontroversial, ready to merge, and has already received Wood's sign-off. The only remaining question is whether there are additional documentation files beyond these six that still use the old path; the author notes that a separate pass would handle those, which is a reasonable approach -- it keeps this patch focused and mergeable rather than scope-creeping into a project-wide grep.
