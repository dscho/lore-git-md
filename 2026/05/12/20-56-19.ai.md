This is a documentation patch in response to a bug report about `git diff --word-diff` behavior.

The bug report (from Vincent Lefevre) noted that `git diff --word-diff` can show word-level changes even when the only difference between files is whitespace -- which is confusing because the existing documentation does not explain why. The email being summarized here (from Michael Montalbo) does not address the behavior itself; it simply proposes adding a note to the documentation explaining how word diff works internally.

The proposed patch adds a paragraph to `Documentation/diff-options.adoc` stating that word diff works by first computing a line-level diff, then finding word-level changes within each hunk. The line-level alignment therefore determines which lines are compared for word differences, and that alignment can affect the word-level output.

This is a small, narrowly-scoped documentation fix. It does not change any behavior, and it does not attempt to justify or defend the current behavior -- it simply explains the mechanics to reduce user confusion. The motivation is clear and the reasoning is sound: users who see unexpected word-diff output because of line-alignment differences can now understand why. No review depth is applicable since this is a documentation suggestion rather than a code review. The patch looks like it would be uncontroversial if the maintainer agrees the clarification is worth adding.
