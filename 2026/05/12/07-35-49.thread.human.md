This is a bug report from Daniel Mach at SUSE about a crash when `git clone --dissociate` is used with a reference repository that has a commit-graph. The clone fails during checkout with `fatal: unable to parse commit <SHA>`, leaving the repository in an incomplete but recoverable state -- `git status` works, and running `git checkout` manually succeeds, confirming the repository itself is sound.

The reporter provides a shell reproducer and a plausible root cause: during dissociation, Git repacks objects from the alternate and removes the `objects/info/alternates` file, but the clone process already has the alternate's commit-graph open in memory. After the alternate is no longer valid, the commit-graph is not invalidated or reloaded, so Git tries to parse commits from a graph that now references a dangling alternate, causing the parse failure. The author caveats that this diagnosis came from an AI assistant.

Two workarounds exist: omit `--dissociate`, or pass `-c core.commitGraph=false`. No one has yet responded, reviewed the reproducer, or proposed a fix. The fix will likely involve invalidating the commit-graph or reloading the object store after the dissociate operation completes.
