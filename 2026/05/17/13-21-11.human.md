This is a revised bugfix patch from Jörg Thalheim addressing config file locking contention, following up on a previously abandoned thread. The patch introduces a retry mechanism with configurable timeout (default 1000ms) when acquiring config file locks, similar to the existing packed-refs timeout mechanism.

Key improvements in v2:
- Makes timeout configurable via `core.configLockTimeout`
- Bumps default timeout to 1000ms (from 100ms) to better handle slow filesystems like NTFS
- Adds tests verifying both immediate failure (with timeout=0) and successful retry behavior
- Documents the read-after-lock semantics and last-writer-wins behavior

The patch is well-constructed with clear commit message explanations and test coverage. It builds on prior discussion where Johannes Schindelin confirmed the technical feasibility of this approach in Microsoft's fork, though the original maintainer concerns about fundamental race conditions remain valid. The author has thoughtfully addressed previous feedback while maintaining the pragmatic approach of improving the status quo rather than solving all possible edge cases.
