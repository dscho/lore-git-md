Jean-Noël Avila continues his documentation standardization effort with a batch of five man page conversions (bisect, grep, am, apply, and imap-send) to the new AsciiDoc synopsis style. Junio C Hamano has reviewed the changes and raised an important distinction: the [synopsis] formatting should be reserved for formal SYNOPSIS sections rather than applied to in-body command examples, particularly those containing shell prompts. 

A new wrinkle has emerged with a CI failure in the automated documentation pipeline, though the exact cause isn't yet clear. This suggests the conversion may need both stylistic refinements (to properly scope the [synopsis] usage per Junio's guidance) and technical adjustments to ensure the AsciiDoc processing works reliably across build environments. The discussion now centers on establishing clearer guidelines for when to use different markup types, with Junio's latest input reinforcing that shell prompts in examples should not receive [synopsis] formatting since they aren't part of the actual command syntax.
