This is a bugfix patch (v3) from Karthik Nayak addressing lock file handling in the files ref backend's consistency checks. The patch follows up on substantive feedback from Junio C Hamano, Christian Couder, and Patrick Steinhardt in previous iterations.

The core issue is that lock files (`.lock`) were being inconsistently processed during ref verification - some checks skipped them while others didn't. The solution moves the lock file detection logic higher up to `files_fsck_refs_dir()`, ensuring all validation checks consistently skip lock files. The patch includes thorough test coverage verifying three scenarios: proper skipping of valid lock files, rejection of invalid refnames ending in ".lock", and validation of actual ref contents.
