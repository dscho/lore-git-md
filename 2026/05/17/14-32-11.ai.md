This is a technical response to Phillip Wood's substantive review of Johannes Schindelin's RFC patch series adding merge commit support to `git history`. The email acknowledges and addresses a key edge case in the merge replay logic where new conflicts could be silently introduced.

Schindelin confirms Wood's identified issue - when one merge parent is rebased (E') and the other (D) is not, new conflicts between E' and D that don't overlap with the original merge's conflicts would be silently accepted rather than flagged. This particularly affects the upcoming `fixup` subcommand.

The response indicates Schindelin is reworking the patches to address this, following Elijah Newren's original design notes, though he expresses uncertainty about whether the conflict output will be sufficiently clear for interactive use in `git history`. The email maintains the technical focus while acknowledging the review's value in surfacing this edge case.

Key technical points:
- The fix involves extending the merge algorithm to properly detect new conflicts between rebased and unmodified parents
- Conflict marker clarity in complex cases remains an open question
- The solution will need to handle both the replay plumbing and interactive history use cases
- The response shows the author engaging deeply with the technical challenge while maintaining the RFC spirit of the series
