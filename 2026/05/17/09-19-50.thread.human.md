Phillip Wood has identified a more likely root cause for the segfault during `git rebase --continue` with signing. Rather than being a NULL-dereference bug in merge-ort as initially suspected, this appears to be a case of repository corruption caused by parallel repacks during rebase - a known issue that was recently fixed. Phillip notes this same bug corrupted his own repository under similar circumstances, and suggests checking pack file counts and timestamps to confirm. The fix is expected in Git 2.54.1. While the original backtrace clearly showed a NULL-dereference in `repo_parse_tree_gently()`, this now appears to be a symptom of underlying object store corruption rather than a merge-ort-specific bug. The discussion has shifted from examining merge-ort's tree parsing to investigating maintenance operation interactions during rebase sequences.
