Bug report: `git rebase --continue` segfault during signing operation

Alex Naidenkov reports a segmentation fault occurring during `git rebase --continue` when attempting to sign a commit. The crash happens in the merge machinery, specifically in `repo_parse_tree_gently()` when passed a NULL tree object during the rebase operation.

The backtrace shows the crash originates from the ORT merge strategy (merge-ort.c) while processing a commit with hash db33c0f (subject "fix"). The immediate cause appears to be a NULL tree object being passed to the tree-walking code. The reporter was in the middle of a large rebase operation when the crash occurred after entering their GPG signing PIN.

Technical details provided include:
- Git version 2.54.0 (commit 94f057755b)
- Full backtrace showing the call chain from merge-ort through sequencer to rebase
- System configuration including OpenSSL 3.6.2 and zlib-ng 2.3.3
- Enabled pre-commit hook (though unlikely related to this crash)

This appears to be a legitimate crash in the rebase/merge machinery rather than a configuration or environment issue. The NULL tree object suggests either corruption in the rebase state or a missing tree object that should have been present. The report provides sufficient debugging information for maintainers to investigate further.
