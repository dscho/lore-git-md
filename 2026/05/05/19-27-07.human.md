This is a follow-up in Kristoffer Haugsbakk's `git format-rev` series, addressing stream processing concerns in patch 5/5. The discussion focuses on making the experimental command's stdin/stdout handling more production-ready.

Phillip Wood had previously identified two key issues: potential deadlocks from buffered I/O and the need for proper message delimiters when handling multi-line output. Kristoffer now confirms understanding of both points and proposes implementing NUL-termination (-z/--null) for input and output streams, following Git's established conventions. He also suggests adding more granular --null-input and --null-output options for flexibility.

The exchange shows the command maturing through substantive technical review, with Kristoffer thoughtfully considering edge cases like multi-line commit names and trailer formatting. The proposed solution aligns with similar fixes in other Git commands (notably merge-tree) while maintaining the feature's experimental status until these robustness concerns are fully addressed.
