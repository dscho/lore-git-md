This is a build system patch addressing a compatibility issue between Clang and glibc 2.43's use of C11's `_Generic` feature. The problem surfaces when building with `DEVELOPER=1` which enforces C99 mode (-std=gnu99), causing Clang to warn about the glibc headers' use of C11 features.

Patrick Steinhardt's patch works around this by:
1. Only applying -std=gnu99 for GCC in config.mak.dev (not Clang)
2. Adding -Wno-c11-extensions to silence the warning in Meson builds

The commit message thoroughly explains the technical background - glibc's feature detection doesn't work properly with Clang's extensions, and there's no clean way to fix it at the header level. The solution is pragmatic rather than perfect, preserving C99 checking for GCC while accommodating Clang's behavior.

This appears to be a well-motivated fix for actual CI failures (triggered by Ubuntu 26.04 upgrades) that doesn't introduce new complexity. The patch is focused and comes with clear explanations of both the problem and the chosen solution.
