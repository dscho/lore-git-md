Feature: Finalized `fetch.pruneBranches` implementation with naming and terminology refinements.

Harald Nordgren's v3 series completes the automatic local branch pruning functionality, now with consistent "remote-tracking branches" terminology throughout (addressing Kristoffer Haugsbakk's review) and a new `--all-remotes` flag for convenience. The series maintains the decomposed architecture from v2 with standalone `git branch` plumbing commands that `fetch` composes:

1. `git branch --forked <remote>` lists local branches tracking the remote
2. `git branch --prune-merged <remote>` deletes branches whose upstream tracking refs are gone
3. `fetch --prune-merged` automates this after fetching

Key changes from v2:
- Terminology standardized to "remote-tracking branches" (not "refs")
- New `--all-remotes` flag processes all configured remotes at once
- Per-branch opt-out via `branch.<name>.pruneMerged=false` preserved
- Checked-out branch protection remains multi-worktree aware
- The series appears ready for merging with thorough test coverage and documentation, though Johannes Sixt's concern about the `--prune-merged` name potentially misleading users (since it checks upstream status rather than merge status) remains unresolved. The implementation is solid and the feature will be useful for automating cleanup of merged topic branches while protecting unpushed work.
