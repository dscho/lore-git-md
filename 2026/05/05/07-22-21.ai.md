Feature: v3 of `fetch.pruneBranches` series with terminology refinements and new `--all-remotes` flag.

Harald Nordgren's v3 patch series builds on the decomposed architecture from v2 (which implemented local branch pruning via new `git branch` plumbing commands) with several refinements:

1. Terminology updates throughout to use "remote-tracking branches" consistently instead of "remote-tracking refs", addressing Kristoffer Haugsbakk's documentation feedback from v2.

2. The new `--all-remotes` flag (patch 6/6) extends both `--forked` and `--prune-merged` to operate across all configured remotes at once, while maintaining the ability to specify particular remotes when needed.

3. The series remains architecturally sound with:
   - `git branch --forked` for listing branches
   - `git branch --prune-merged` for safe deletion
   - `branch.<name>.pruneMerged` opt-out config
   - `fetch --prune-merged` integration

The changes from v2 to v3 are purely additive and non-controversial - no behavioral changes beyond the terminology updates. The implementation appears thorough with comprehensive test coverage for all scenarios including multi-remote cases. The documentation clearly explains the new `--all-remotes` flag's interaction with explicit remote arguments.

The outstanding naming concern from Johannes Sixt regarding `--prune-merged` potentially implying commit reachability (when it actually checks upstream status) remains unaddressed in this revision. This semantic distinction may need clarification in future iterations.
