This is a bugfix discussion for git-gui's handling of repository detection, continuing from previous iterations. Mark Levedahl responds to Johannes Sixt's proposal for a backward-compatible solution that preserves the ability to run git-gui from a `.git` directory.

Mark reports that his attempts to restructure the startup code to properly handle GIT_DIR and GIT_WORK_TREE environment variables have hit a wall - git-gui's blame and browser commands fundamentally require a valid worktree to function. The issues appear deep enough that debugging would require reverting to pre-2019 Git versions, which isn't practical.

The email effectively concedes that Johannes Sixt's simpler approach - erroring out except when in a `.git` directory - is the most viable path forward, despite leaving some dead code in place. This represents a pragmatic retreat from earlier attempts at a comprehensive solution, acknowledging technical constraints in git-gui's architecture.

The discussion highlights the tension between maintaining backward compatibility (the `.git` directory use case from 2010) and properly handling modern Git features like worktrees and environment variables. The resolution appears to favor stability over completeness, accepting some technical debt to avoid breaking existing workflows.
