Feature: `git branch --prune-merged` for cleaning up local branches with deleted upstreams.

This patch introduces a new `--prune-merged` flag to `git branch` that safely deletes local branches whose upstream tracking branches have been deleted. It's part of Harald Nordgren's v3 series to automate branch cleanup, following Junio's architectural feedback to decompose the functionality into standalone plumbing commands.

The new flag:
- Lists local branches tracking specified remotes (reusing the `--forked` plumbing from earlier patches)
- Checks if the push destination ref (what `git push` would update) no longer exists
- By default, requires the local tip to be reachable from upstream (protecting unpushed work)
- Allows forced deletion with `-f` (bypassing reachability checks)
- Always** preserves checked-out branches across all worktrees

The implementation includes comprehensive tests covering:
- Basic pruning when upstream branches disappear
- Protection for branches with unpushed commits (unless forced)
- Multi-worktree safety (never deletes checked-out branches)
- Edge cases like differing push vs. upstream refs

This builds cleanly on the decomposed architecture from v2, with the outstanding naming concern about `--prune-merged` (which checks upstream status rather than commit reachability) still unresolved. The implementation appears solid with thorough test coverage for the core safety mechanisms.
