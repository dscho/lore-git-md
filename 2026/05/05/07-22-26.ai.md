Feature: Per-branch opt-out for `--prune-merged` functionality in v3 branch pruning series.

This patch introduces a new `branch.<name>.pruneMerged` configuration option that allows individual branches to be exempted from automatic pruning via `git branch --prune-merged` and `git fetch --prune-merged`. The setting persists even when using `--force`, providing a way to protect topic branches that are being actively developed across multiple rounds of upstream integration.

The implementation is thorough, with clear documentation updates explaining the new configuration option and its interaction with both the low-level `git branch` plumbing and higher-level `git fetch` integration. The tests cover all key scenarios:
- Basic opt-out behavior
- Interaction with `--force`
- Preservation of the setting during explicit `git branch -d` operations
- Safety mechanisms remain intact:
  - Checked-out branches are still protected (tested in previous patches)
  - The default behavior remains conservative (pruning enabled)
  - Explicit deletion via `git branch -d` bypasses the setting

This patch completes the safety story for the branch pruning functionality, giving users fine-grained control over which branches should be considered for automatic cleanup. The implementation appears solid with comprehensive test coverage and clear documentation.

The patch fits cleanly into the v3 series' architecture, building on the decomposed design where `git branch` provides the core plumbing that `git fetch --prune-merged` then leverages. All safety mechanisms from earlier patches remain in place while adding this new opt-out capability.
