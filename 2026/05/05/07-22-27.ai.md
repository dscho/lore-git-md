Feature: Final patch in v3 series adding `--all-remotes` convenience flag for branch pruning automation.

This patch completes Harald Nordgren's v3 series by introducing a `--all-remotes` flag that works with both the `--forked` and `--prune-merged` options in `git branch`. When specified, it automatically includes all configured remotes in the operation while still allowing explicit remote arguments for finer control. The implementation:

1. Adds the new flag to both commands' documentation and usage strings
2. Implements remote collection via `for_each_remote()` when the flag is set
3. Validates that the flag is only used with `--forked` or `--prune-merged`
4. Includes comprehensive tests covering:
   - Basic functionality with `--forked`
   - Error cases (invalid remotes, standalone usage)
   - Integration with `--prune-merged` across multiple remotes

The patch maintains all existing safety mechanisms from previous iterations (checked-out branch protection, per-branch opt-out via `branch.<name>.pruneMerged`) while making the commands more convenient for multi-remote setups. The implementation appears clean and well-tested, with clear documentation of the new behavior.

This completes the technical implementation of the series, leaving only Johannes Sixt's naming concern about `--prune-merged` (which may imply commit reachability rather than upstream status) as an outstanding issue. The series now provides both low-level plumbing (`git branch --prune-merged`) and high-level automation (`git fetch --prune-merged`) for local branch cleanup, with comprehensive safety controls and multi-remote support.
