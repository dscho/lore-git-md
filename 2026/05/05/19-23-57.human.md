Feature: Per-branch opt-out for `fetch.pruneBranches` functionality.

This patch (5/6 in the v4 series) introduces a configuration option `branch.<name>.pruneMerged` that allows users to exempt specific branches from automatic pruning, even when using `--force`. The setting is designed for topic branches that may go through multiple development cycles after initial upstream merging.

Key aspects:
- The opt-out is respected by both `git branch --prune-merged` and `git fetch --prune-merged`
- Explicit deletion via `git branch -d` remains unaffected
- The implementation includes clear documentation updates and comprehensive test coverage
- When skipping a protected branch, a message is shown (unless `--quiet` is used)

The patch builds on the series' existing safety mechanisms (default branch protection, unpushed work detection) while adding this new opt-out capability. It maintains the architectural separation between the low-level plumbing (`git branch`) and higher-level automation (`git fetch`).

This appears to be a well-considered addition to the feature set, addressing a real workflow need while preserving all existing safety checks. The implementation is thorough, including tests for both normal and `--force` scenarios, plus verification that `branch -d` remains unaffected.

The series continues to show careful attention to edge cases and user experience, with this patch specifically addressing the "intermediate state" workflow where branches may need temporary preservation between development cycles.
