Feature patch finalizing the `--max-count-oldest` option for revision walks, representing the sixth and likely final iteration of this work. Mirko Faina has incorporated all feedback from previous rounds, including Junio C Hamano's preference for this interface over the original `--reverse=before` approach.

The patch adds a new `--max-count-oldest=<number>` option that shows the oldest N commits in a history, complementing the standard `--max-count` that shows the newest N commits. The implementation preserves the optimized sliding window algorithm (O(K) space, O(N) time) from earlier versions while adopting Johannes Sixt's suggested interface naming.

Key technical details:
- Adds new `max_count_type` and `max_count_stage` flags to `struct rev_info`
- Implements core logic in `retrieve_oldest_commits()` using a two-queue approach
- Maintains compatibility with `--reverse` while preventing invalid combinations with `--skip`
- Includes comprehensive tests verifying both direct and reversed output modes

The documentation has been refined to clearly explain the new option's behavior compared to `--max-count`. This represents a clean solution to the original problem of efficiently showing the oldest commits without requiring complex shell pipelines. With maintainer approval pending only final commit message polish, this feature is implementation-complete and ready for inclusion.
