Feature: `fetch --prune-merged` integration for automated local branch cleanup.

This patch (4/6 in the v3 series) adds the high-level `fetch --prune-merged` option that automatically runs `git branch --prune-merged` after a successful fetch. The implementation:

1. Adds the new `--prune-merged` flag to `git fetch` which:
   - Only operates on configured remotes (not direct URLs)
   - Runs after successful fetch operations
   - Fails the entire fetch if pruning fails
   - Preserves the currently checked-out branch

2. Includes comprehensive tests that verify:
   - Local branches are deleted when their upstream is pruned
   - Unmerged local branches (with unpushed work) are preserved
   - Error messages are shown for unmerged branches
   - The feature works alongside existing `--prune` functionality

The patch builds on the earlier plumbing commands in the series (`git branch --forked` and `git branch --prune-merged`) to provide a convenient automated workflow. The implementation appears solid with thorough test coverage of edge cases.

This completes the high-level integration of the feature while leaving the naming concern about `--prune-merged` (raised by Johannes Sixt in earlier reviews) still open for future discussion. The series as a clean separation between the low-level branch commands and this fetch integration.
