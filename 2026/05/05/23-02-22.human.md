This is the second patch in a bugfix series addressing negative diff context values. It follows the same pattern as the first patch (which fixed `--inter-hunk-context`) by converting the `-U`/`--unified` option to reject negative values.

The patch changes the type of `diff_options.context` from `int` to `unsigned int` to match the previous change to `interhunkcontext`. It adds validation in both the config parsing and command-line callback to ensure negative values are rejected with an error message. The test suite is updated to verify this behavior.

Unlike `--inter-hunk-context`, `-U` requires special handling with `OPT_CALLBACK_F` since it supports an optional argument (bare `-U` enables patch output). The validation is therefore done in the callback rather than through `OPT_UNSIGNED`.

The changes are straightforward and maintain consistency with the existing config variable `diff.context` which already rejects negatives. This continues the series' goal of preventing malformed diff output from negative context values.
