This is a maintainer response in the ongoing discussion about Git's rename detection limitations with Ruby namespace moves. Junio C Hamano clarifies and expands on Chris Torek's technical explanation of the issue.

Key points:
- Junio qualifies Torek's statement about the split-commit workaround, noting it only helps in step-wise comparisons (like `git log -M` or rebase) but fails for direct comparisons (diff/merge)
- He confirms the fundamental limitation stems from Git's snapshot-based model
- Suggests the attributes system could be a pathway for implementing language-specific rename detection heuristics
- Preserves Git's flexibility to improve detection without changing historical data

The response maintains Git's philosophical stance while acknowledging the technical possibility of smarter rename detection. Junio's position as maintainer gives this email particular weight in the discussion - he's signaling openness to improvements but within Git's existing architectural constraints. The attributes system suggestion provides a concrete direction for future work that aligns with Git's design principles.
