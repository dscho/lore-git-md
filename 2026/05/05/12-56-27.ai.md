This is a technical clarification from Junio C Hamano regarding Git's clean/smudge filter behavior with binary files.

Junio responds to Randall Becker's question about how filters handle binary files that match filter patterns, making three key points:

1. Binary data passing through stdin/stdout is normal Git behavior, citing the example of JPEG files processed by exif textconv filters. This directly addresses Randall's portability concern.

2. The "filter" attribute operates independently of other attributes like "text" or "diff". Filters are designed to process binary content when needed, so they don't automatically skip files marked as binary.

3. The proper way to exclude binary files from filtering is through precise .gitattributes patterns (e.g., `*.txt filter=mytextfilter`) rather than relying on binary detection within the filter itself.

The response maintains Git's current design philosophy where filters are expected to handle whatever content they're given, with file selection controlled at the .gitattributes level. Junio doesn't propose changing the filter infrastructure but reinforces the existing pattern-based approach to scope filtering.

This clarifies that Randall's desired behavior (having filters skip binary files) would need to be implemented through careful .gitattributes configuration rather than changes to the filter mechanism itself. The exchange highlights a tension between Git's flexible filter design and Randall's goal of making the system more forgiving of configuration errors.
