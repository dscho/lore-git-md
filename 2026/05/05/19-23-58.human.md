Feature: Final patch in v4`fetch.pruneBranches` series adds `--all-remotes` convenience flag.

This is the concluding patch in Harald Nordgren's series to automate local branch pruning when upstream branches are deleted. The series has evolved through multiple iterations with feedback from Junio C Hamano and others, now reaching a mature state with comprehensive safety checks and configuration options.

The key addition in this patch is the `--all-remotes` flag for both `git branch --forked` and `git branch --prune-merged`. When specified, it automatically includes all configured remotes in the operation, while still allowing explicit remote arguments for finer control. The implementation:
- Adds the flag to command documentation
- Implements remote collection via `for_each_remote()`
- Maintains all existing safety checks (default branch protection, unpushed work detection)
- Includes thorough test coverage for both success and error cases

The patch completes the series by providing a convenient way to operate across all remotes without manual enumeration, while preserving the decomposed architecture that separates listing (`--forked`) from deletion (`--prune-merged`). The only remaining open question is Johannes Sixt's concern about the `--prune-merged` naming potentially misleading users about its upstream-based behavior rather than commit reachability.

With this addition, the feature set is complete and production-ready, offering both granular control and convenient automation for local branch cleanup. The implementation appears solid, with careful attention to edge cases and comprehensive test coverage.
