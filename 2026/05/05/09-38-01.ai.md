This is a follow-up in the thread about terminal output corruption when displaying remote messages. Mikael Magnusson confirms the same behavior occurs in `grep --color` when lines exactly match terminal width, attributing it to the same ANSI escape sequence issue. He notes that while urxvt terminals support an extension (`\e[3K`) that could avoid this problem, xterm doesn't implement it, making this a non-portable solution.

Magnusson questions Git's use of the clear-to-end escape sequence (`\033[K`) in this context, speculating whether it's truly necessary to clear potential background colors from scrolled content. He suggests the current behavior of truncating the last character might be worse than any hypothetical display artifacts the sequence was meant to prevent.

This adds another data point to the discussion, showing the issue isn't Git-specific but stems from fundamental terminal behavior. The email doesn't propose a specific fix but raises important questions about whether the current clearing behavior provides enough benefit to justify the edge case it breaks.
