Bugfix follow-up for `git fetch --deepen` regression.

Samo Pogačnik builds on René Scharfe's earlier fix for the `fetch --deepen` regression by proposing an alternative solution that moves the shallow repository check into `shallow.c` rather than `builtin/fetch.c`. This addresses René's concern that the original fix "felt like cheating" by handling the edge case at a lower level in the codebase.

The key change modifies `get_shallow_commits()` in `shallow.c` to return NULL when dealing with a non-shallow repository (when `cur_shallow_depth` is 0), rather than proceeding with the deepen operation. This maintains the same behavior as René's fix - preventing history truncation in non-shallow repos - but does so at the level where the shallow logic is implemented.

The patch also adds a test case that verifies `fetch --deepen` doesn't truncate history in a full clone, mirroring the original bug report scenario. This builds on the existing test infrastructure from earlier in the thread.

This appears to be a more architecturally sound solution than the original workaround, though both approaches would solve the immediate regression. The change is focused and maintains the thread's consensus that `--deepen` should be a no-op in non-shallow repositories. No maintainer feedback on this version yet.
