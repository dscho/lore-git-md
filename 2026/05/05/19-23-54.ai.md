Feature: Bulk branch deletion improvements for `fetch.pruneBranches` series.

This patch from Harald Nordgren's v4 series enhances the bulk branch deletion machinery to be more suitable for automated use cases like `fetch --prune-merged`. The key changes:

1. Adds `warn_only` parameter to suppress error messages and advice when branches can't be deleted due to unmerged changes, instead emitting a single-line warning. This prevents verbose output during bulk operations.

2. Introduces `n_not_merged` counter to track skipped branches, allowing callers to provide a summary rather than per-branch details.

The implementation modifies `delete_branches()` and its helper `check_branch_commit()` while maintaining backward compatibility - existing callers pass the default values (0/NULL) and see no behavior change. The changes are specifically designed to support the new `git branch --prune-merged` functionality where bulk operations are common and detailed per-branch messages would be noisy.

This is a technical improvement that builds on the series' architectural foundation, providing the necessary plumbing for the higher-level `fetch --prune-merged` feature to operate cleanly in bulk scenarios. The patch maintains the project's careful balance between safety (still preventing actual deletion of branches with unmerged changes) and usability (reducing noise in automated contexts).
