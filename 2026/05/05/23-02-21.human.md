This is the first patch in a bugfix series addressing invalid diff output from negative context values. The patch focuses on `--inter-hunk-context`, which currently accepts negative numbers but produces malformed hunks with overlapping line ranges.

The change switches the option from `OPT_INTEGER_F` to `OPT_UNSIGNED` to properly reject negative values at parse time, matching how the equivalent `diff.interHunkContext` config already behaves. The patch includes a test showing the new error message when negative values are provided.

This is a straightforward correctness fix that prevents a subtle edge case where negative context values could generate unapplyable diffs. The change is well-contained, touching only the option parsing and adding a test case, while maintaining compatibility with existing valid usage. The commit message clearly demonstrates the problem with example output showing overlapping hunks.
