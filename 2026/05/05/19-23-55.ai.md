Feature: Implementation of `git branch --prune-merged` for safe local branch cleanup.

This patch introduces the core `--prune-merged` functionality to complement the previously added `--forked` command in the `fetch.pruneBranches` series. The new option safely deletes local branches that track remote branches which have been deleted upstream, while protecting work in progress and default branches.

Key behaviors implemented:
- Only deletes branches where the push destination no longer exists in the remote (checked via `branch_get_push`)
- By default refuses to delete branches with unpushed commits (reachability check from upstream)
- Always preserves currently checked-out branches across all worktrees
- Adds default branch protection (matching local branch name to remote's HEAD ref)
- Includes `--force` option to override reachability checks
- Comprehensive test coverage for edge cases (renamed branches, push refs, worktrees)

The implementation builds on the shared `collect_forked_set()` function from the previous `--forked` patch, adding:
- Default branch identification via remote HEAD refs
- Push ref consideration in protection logic
- Bulk deletion with improved messaging (counts skipped branches)
- Integration with existing branch deletion machinery

The patch maintains the series' architectural separation between listing (`--forked`) and pruning (`--prune-merged`) while adding the safety checks needed for practical use. Test cases verify all major scenarios including:
- Basic pruning of deleted upstream branches
- Protection of unpushed work
- Default branch safety
- Push ref vs upstream ref handling
- Worktree awareness

Notably, this completes the core branch plumbing needed for the higher-level `fetch --prune-merged` integration while leaving the naming concern about `--prune-merged` (raised by Johannes Sixt) unresolved. The implementation itself appears thorough and well-tested, providing the promised functionality with appropriate safeguards.
