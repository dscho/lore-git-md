This is a bugfix series addressing an issue where negative values for diff context parameters (-U/--unified and --inter-hunk-context) were being silently accepted, leading to malformed diff output. The patches come from Michael Montalbo via GitGitGadget.

The series fixes a regression introduced in 2019 when these options were converted to use OPT_INTEGER_F/OPT_CALLBACK, which lost the implicit negative number rejection that existed when they used opt_arg(). The changes:

1. Convert --inter-hunk-context to use OPT_UNSIGNED
2. Add explicit validation for -U/--unified values
3. Add a defensive BUG() check in xdiff's hunk generation
4. Clarify parse-options documentation about PARSE_OPT_NONEG

The motivation is clear - negative values produce nonsensical diff output (like showing line 503 of a 106-line file with a count of "999-") and can cause patch application failures. The series brings CLI behavior in line with the existing config variables (diff.context/diff.interHunkContext) which already reject negatives.

This appears to be a well-scoped and justified fix. The patches include tests and documentation updates, and the changes are appropriately defensive (adding both input validation and internal assertions). The series looks ready for review, addressing a clear bug without introducing new complexity.
