Feature: Implementation of `git branch --prune-merged` for safe local branch cleanup.

This patch (3/6 in the v4 series) introduces the core `--prune-merged` command to `git branch`, which safely deletes local branches that were forked from now-deleted remote branches. The command builds on the `--forked` plumbing from earlier patches and adds several safety mechanisms:

1. **Default branch protection**: Automatically identifies and preserves branches matching the remote's default branch name (e.g. local `main` when remote's HEAD is `origin/main`).

2. **Unpushed work safety**: By default refuses to delete branches with commits not reachable from their upstream, requiring `--force` to override.

3. **Checked-out branch protection**: Never deletes a branch that's currently checked out in any worktree.

4. **Push ref consideration**: Checks both the tracking ref and push destination when determining branch status.

The implementation includes comprehensive tests covering edge cases like renamed default branches, differing push refs, and worktree protection. The command integrates with the existing branch deletion infrastructure while adding new safeguards specific to this use case.

This is a key piece of the larger effort to automate branch cleanup while preventing accidental data loss. The protection mechanisms address real-world concerns that emerged during testing, though the naming debate around `--prune-merged` (which actually checks upstream status rather than commit reachability) remains unresolved from earlier discussion.
