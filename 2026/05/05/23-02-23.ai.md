This is the third patch in a bugfix series addressing negative context values in diff options. The patch adds defensive `BUG()` check in xdiff's hunk generation to catch negative context lengths that might slip through, even though the previous patches (1-2) already reject negative values at the CLI/config parsing level.

The change is necessary because xdiff's arithmetic relies on signed subtraction for context window calculations, so the fields must remain `long` (signed) rather than being converted to unsigned like the diff_options fields were. The patch adds explicit validation at the start of `xdl_get_hunk()`, which covers all xdiff consumers through both `xdl_emit_diff()` and `xdl_call_hunk_func()`.

The commit message clearly explains the technical constraint (signed arithmetic requirement) and positions this as defense-in-depth rather than primary validation. The change is minimal and focused, touching only `xdiff/xemit.c` with straightforward guard conditions. This continues the series' systematic approach to hardening diff context validation.
