This is the final version of the `--max-count-oldest` feature patch, implementing a new revision walking option to show the oldest commits. After six iterations of review and refinement, the patch has reached implementation completeness with maintainer approval pending only minor commit message polish.

The patch introduces `--max-count-oldest=<N>` as a complement to `--max-count`, showing the last N commits in history rather than the first N. This solves a real usability pain point - previously users needed complex shell pipelines to achieve this. The implementation preserves the optimized sliding window algorithm (O(K) space, O(N) time) from earlier versions while adopting Johannes Sixt's suggested interface name over the original `--reverse=before` approach.

Key technical aspects:
- Adds new `max_count_type` and `max_count_stage` flags to `struct rev_info`
- Implements core logic in `retrieve_oldest_commits()` using two queues
- Maintains compatibility with `--reverse` while preventing invalid combinations with `--skip`
- Includes comprehensive tests verifying both direct and reversed output modes

The patch touches critical revision walking code in `revision.c` and has been thoroughly reviewed by multiple core contributors. It represents a successful example of iterative development - starting from Mirko Faina's original proposal, incorporating Jeff King's algorithmic improvements and Tian Yuchen's edge case analysis, and finally converging on Junio C Hamano's preferred interface design. The feature is now ready for inclusion pending final documentation tweaks.
