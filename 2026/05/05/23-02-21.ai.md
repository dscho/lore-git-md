This is the first patch in a bugfix series addressing invalid diff output from negative context values. The patch specifically targets the `--inter-hunk-context` option, which currently accepts negative numbers despite producing malformed output with overlapping hunks.

The change converts the option to use `OPT_UNSIGNED` instead of `OPT_INTEGER_F`, ensuring negative values are rejected during parsing. This aligns the CLI behavior with the existing config variable `diff.interHunkContext` which already rejects negatives. The patch includes:
- Type change from `int` to `unsigned int` for the option and default value
- Updated config parsing to maintain consistency
- A new test case verifying negative value rejection

The fix is straightforward and well-contained, touching only the diff machinery's option parsing and adding clear test coverage. This appears to be a solid first step in the series to properly validate diff context values.
