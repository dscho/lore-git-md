Feature: Final patch in v3 series adds `--all-remotes` convenience flag for branch pruning.

This patch completes Harald Nordgren's v3 series implementing automated local branch cleanup when upstream branches are deleted. The new `--all-remotes` flag extends both the `--forked` (listing) and `--prune-merged` (deletion) operations to work across all configured remotes at once, while still allowing explicit remote specification when needed.

Key aspects:
- The flag is only valid when combined with either `--forked` or `--prune-merged`
- Maintains all existing safety checks (unpushed work protection, checked-out branch preservation, per-branch opt-out via `branch.<name>.pruneMerged`)
- Includes comprehensive tests covering both listing and deletion scenarios
- Documentation clearly explains the flag's behavior and constraints

The implementation builds on the decomposed architecture from earlier patches, reusing the core plumbing commands while adding the new remote-collection logic. The series remains technically sound with thorough test coverage, though the outstanding naming concern about `--prune-merged` (raised by Johannes Sixt) remains unaddressed.

This final piece provides a convenient automation path for users who want to clean up branches across all their remotes rather than specifying them individually. The series as a whole offers a well-considered solution to the problem of stale local branches after upstream deletions.
