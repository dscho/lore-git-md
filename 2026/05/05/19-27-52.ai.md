Bugfix follow-up proposing an alternative solution for the `fetch --deepen` regression.

Samo Pogačnik responds to René Scharfe's proposed fix for the `git fetch --deepen` regression with an alternative approach that modifies `shallow.c` rather than `builtin/fetch.c`. The key change is in `get_shallow_commits()` where it now checks if the current shallow depth is non-zero before applying the relative deepen operation, returning NULL (effectively a no-op) for non-shallow repositories.

The patch includes a modified test case that verifies `fetch --deepen` doesn't truncate history in a full clone, maintaining the same repository state before and after the operation. This aligns with the thread's consensus that `--deepen` should be a no-op in non-shallow repositories.

This approach addresses René's earlier concern about the "cheating" nature of the `fetch.c` fix by moving the logic to the more appropriate `shallow.c` location. The change is still minimal but provides a more architecturally sound solution to prevent the history truncation issue introduced in Git 2.54.0. The test case ensures this specific regression won't recur.
