Feature: Per-branch opt-out for `--prune-merged` functionality in v3 of the branch cleanup series.

This patch adds a `branch.<name>.pruneMerged` configuration option that allows specific branches to be exempted from automatic pruning, even when using `--force`. The option defaults to true, maintaining the default behavior for most branches, but can be set to false for branches that should persist even after their upstream counterparts are deleted.

Key aspects:
- The configuration is checked during `--prune-merged` operations (both standalone and via `fetch --prune-merged`)
- Explicit deletion with `git branch -d` bypasses this protection
- The implementation includes comprehensive tests covering:
  - Basic opt-out behavior
  - Interaction with `--force`
  - Preservation of the setting during explicit deletion
  - Proper warning messages when skipping protected branches

This completes the safety mechanisms for the branch pruning feature, giving users fine-grained control over which branches should be automatically cleaned up. The implementation appears thorough, with clear documentation and test coverage for all edge cases.

This is patch 5/6 in the v3 series, which builds on the decomposed architecture approach suggested by Junio Hamano and addresses previous documentation feedback from Kristoffer Haugsbakk. The series remains technically sound while leaving the naming concern about `--prune-merged` (raised by Johannes Sixt) for future discussion.
