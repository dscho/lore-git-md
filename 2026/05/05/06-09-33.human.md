This is a follow-up discussion on a Windows build configuration patch from Johannes Schindelin that removes the unmaintained nedmalloc allocator from MINGW builds. Patrick Steinhardt agrees with the change as an intermediate step but raises the question of whether to completely drop the now-unused nedmalloc code from the Git tree.

The original patch addressed a GCC 16 compatibility issue by removing the `USE_NED_ALLOCATOR` setting for MINGW builds, since Git for Windows had already switched to mimalloc years ago. Patrick's response suggests this might be the right time to consider removing the entire nedmalloc subtree, as it appears to have no remaining users after this change.

The exchange is brief and constructive - Patrick explicitly states this doesn't need to block the current patch, but flags the broader cleanup as worth considering in a follow-up. This keeps the discussion moving forward while identifying a potential next step for maintainers to consider.
