This thread is about refining the build system for Git’s Rust components on macOS, specifically to support Universal Binaries and fix a parallel build race condition. The latest version of the patch series from Shardul Natu and Koji Nakamaru is now in its third iteration, split into three focused commits: one to ensure the macOS credential helper links against Rust libraries, another to introduce Universal Binary support via the `RUST_TARGETS` environment variable, and a final cleanup commit.

The key technical change is enabling Universal Binary builds for Rust components by allowing users to specify multiple target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`). The build system compiles separate static libraries for each target and combines them into a single Universal Binary using `lipo`. This addresses a gap between Apple’s C toolchain (which natively supports multi-architecture builds via `-arch` flags) and Cargo (which requires separate invocations per target). The first patch in the series also fixes a parallel build race condition by ensuring Cargo builds the required Rust library before linking the credential helper. These changes are wrapped in `ifndef NO_RUST` blocks to maintain backward compatibility when Rust is disabled.

The series has converged significantly. Junio C Hamano’s latest feedback is purely stylistic—minor Makefile tweaks—and Patrick Steinhardt’s earlier architectural concerns about Universal Binary completeness have been addressed in principle, though not fully resolved. The current design is now accepted as sufficient for practical use cases like macOS distribution and CI. The patches touch only the `Makefile`, introduce no on-disk format changes, and are implicitly covered by existing build tests. With the minor style feedback incorporated, the series is effectively ready to proceed.
