This thread is about a build system adjustment for Git’s Rustification effort, specifically enabling macOS Universal Binary support for the `git-credential-osxkeychain` helper and fixing a parallel build race condition. The series, now at v3, is authored by Shardul Natu and Koji Nakamaru (Google) and splits into three logical commits: (1) a fix for a parallel build race, (2) Universal Binary support via the `RUST_TARGETS` environment variable, and (3) a minor cleanup.

The first patch, which ensures the credential helper links against Rust libraries when Rust is enabled, is uncontroversial and ready to proceed. The second patch, introducing Universal Binary support, remains under discussion due to Patrick Steinhardt’s architectural concerns. Patrick questioned whether the patch fully delivers its intended benefit, as it only handles Rust libraries—not the final binaries—leaving the C build’s Universal Binary support unaddressed. Shardul clarified that Apple’s C toolchain natively supports multi-architecture builds via `-arch` flags, while Cargo requires separate invocations per target triple, so the patch bridges this gap by combining Rust static libraries into a universal archive. However, Patrick’s concern about whether the C build also needs Universal Binary treatment to realize the full benefit remains unresolved. The third patch, a cleanup, is non-controversial.

Junio C Hamano’s feedback on directory creation and variable redundancy has been addressed, and Kristoffer Haugsbakk’s low-weight suggestions on commit message clarity were incorporated. The series touches only the `Makefile`, introduces no on-disk format changes, and relies on existing build tests for coverage. The thread’s next steps hinge on resolving Patrick’s concerns about the Universal Binary implementation’s completeness and practical utility.
