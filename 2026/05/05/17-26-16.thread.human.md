This thread is about adjusting Git’s build system to better support Rust components on macOS, specifically enabling Universal Binary (multi-architecture) builds for the `git-credential-osxkeychain` helper. The series, now at version 3, is authored by Shardul Natu and Koji Nakamaru and has evolved in response to feedback from Junio Hamano and Patrick Steinhardt.

The key changes in v3 split the work into three logical commits. The first fixes a parallel build race condition by ensuring the Rust library (`libgitcore.a`) is built before linking the credential helper. The second introduces Universal Binary support for Rust libraries via the `RUST_TARGETS` environment variable, allowing users to specify multiple target architectures (e.g., `aarch64-apple-darwin x86_64-apple-darwin`). The third is a minor cleanup commit. The first and third patches are uncontroversial and ready to proceed, while the second has been the focus of discussion.

Patrick Steinhardt initially raised architectural concerns about whether the feature’s value is fully realized without corresponding changes to the C build, which natively supports multi-architecture builds via `-arch` flags. However, in his latest reply, Patrick accepted the technical rationale for focusing on Rust libraries—Cargo requires separate invocations per target, unlike the C toolchain—and only requested that this context be added to the commit message. Shardul’s explanation clarified that the patch bridges this gap by combining target-specific Rust static libraries into a universal archive using `lipo`, which is then linked into the final Git executables. This approach delivers practical benefits for macOS distribution and CI, even if the C build isn’t explicitly configured for Universal Binaries.

The series is now close to resolution, with only a commit message update needed for the second patch. No new test coverage was introduced, as the changes are implicitly covered by existing build tests. The thread highlights the challenges of integrating Rust into Git’s build system while maintaining backward compatibility and platform-specific requirements.
