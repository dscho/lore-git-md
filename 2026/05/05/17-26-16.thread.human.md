This thread is about a patch series from Shardul Natu and Koji Nakamaru that adjusts Git’s build system to better support Rust code, specifically for the macOS credential helper (`git-credential-osxkeychain`). The series aims to simplify Rust library handling by removing a redundant `RUST_LIBS` variable and adding native support for macOS Universal Binaries—multi-architecture builds that combine, for example, `aarch64` and `x86_64` binaries into a single file using `lipo`.

The patch has seen two iterations, with Junio Hamano’s review in the first round focusing on a potential build-time race condition (missing directory creation for the `$(RUST_LIB)` target). That concern was addressed, and the series appeared close to merging. However, Patrick Steinhardt’s recent review raises deeper questions. He argues the two changes—Rust library linking and Universal Binary support—should be split into separate commits, as they solve unrelated problems. More critically, he questions whether Universal Binaries are even necessary for Git, noting that the patch only handles Rust libraries, not the final binaries (which are mostly C). Without Universal Binary support for the entire executable, the Rust library’s multi-architecture build may not provide any practical benefit. He also flags a potential platform-compatibility issue: whether `lipo` can be assumed to be available on all macOS systems.

The thread is now at a crossroads. The authors will need to clarify the motivation for Universal Binaries—what problem they solve for Git users or developers—and decide whether to split the patch or expand it to cover the entire build process. Until these questions are resolved, the series is unlikely to proceed. Key participants include the authors (Natu and Nakamaru), Junio (who previously approved the design), and Patrick (whose review has shifted the discussion toward architectural concerns).
