This thread covers a build system adjustment for Git’s Rustification effort, focusing on macOS Universal Binary support for the `git-credential-osxkeychain` helper. The series, now at version 3, is authored by Shardul Natu and Koji Nakamaru and consists of three patches: one fixing a parallel build race condition, another introducing Universal Binary support via the `RUST_TARGETS` environment variable, and a final cleanup commit.

The key change enables users to specify multiple Rust target triples (e.g., `aarch64-apple-darwin x86_64-apple-darwin`) to compile separate static libraries and combine them into a single Universal Binary using `lipo`. This addresses Cargo’s requirement for separate invocations per target triple, bridging the gap with Apple’s C toolchain, which natively supports multi-architecture builds. The build system now guarantees Cargo runs before linking the credential helper, resolving a race condition in parallel builds. The series maintains backward compatibility with conditional compilation (`ifndef NO_RUST` blocks) and avoids on-disk format changes.

Junio C Hamano, the maintainer, requested minor style tweaks—removing a redundant `@` prefix and replacing `if [` with `if test`—which have now been addressed in the latest iteration. Patrick Steinhardt initially raised architectural concerns about the completeness of Universal Binary support and platform assumptions, but these were resolved in principle after the authors clarified the technical rationale in the commit message. D. Ben Knoble later confirmed the long-term availability of `lipo` on macOS, reinforcing the validity of the build system’s assumptions. With all feedback incorporated, the series is effectively ready to proceed, pending Junio’s final review. No new test coverage was introduced, as the changes are implicitly covered by existing build tests.
