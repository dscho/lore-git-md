This thread is about a patch series refining the build system for Git’s Rust components, specifically adding macOS Universal Binary support for the `git-credential-osxkeychain` helper and fixing a parallel build race condition. The series is now at **v4**, with two patches: one ensuring the credential helper links against Rust libraries, and another introducing Universal Binary support via the `RUST_TARGETS` environment variable.

The first patch resolved a race condition in parallel builds by making the credential helper depend on `$(RUST_LIB)`, but Patrick Steinhardt raised a substantive question about whether it should instead depend on `$(GITLIBS)`, which already bundles both C and Rust libraries. This remains unresolved and could require a revision. The second patch, which implements Universal Binary support, is now under scrutiny for its build artifact layout. Patrick argues that the current structure mixes two organizational schemes (`target/release/` for universal libraries and `target/<triple>/release/` for per-architecture artifacts), which could complicate maintenance. He proposes unifying the layout under `target/$BUILD_CONFIG/` with subdirectories for each architecture.

The authors, Shardul Natu and Koji Nakamaru, have addressed prior feedback, including Junio’s style tweaks and minor cosmetic fixes. The series is otherwise uncontroversial, with no new test coverage needed—changes are implicitly validated by existing build tests. The thread is now focused on these two design questions: the dependency structure for the first patch and the artifact layout for the second. Resolution of Patrick’s concerns will determine whether the series moves forward or requires another iteration. No merge date is set, but if the open questions are resolved, the series is likely to land in the current cycle.
