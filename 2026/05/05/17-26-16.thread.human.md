This thread is about refining Git’s build system to better support Rust components on macOS, specifically enabling Universal Binaries for the `git-credential-osxkeychain` helper. The series, now at version 8, is functionally complete and has been under review in Junio Hamano’s integration branches since version 6, which is currently in `next`. The key changes—fixing a parallel build race condition, adding Universal Binary support via the `RUST_TARGETS` environment variable, and ensuring CI verification—are all resolved, with only a minor open question about the layout of Rust build artifacts remaining.

Shardul Natu and Koji Nakamaru have addressed all blocking issues, including Junio’s concerns about duplicate `main()` symbols and a missing `config.mak.uname` include in the CI verification patch. The Universal Binary support, introduced in this patch, allows Git to be distributed as a single binary supporting both Intel and Apple Silicon Macs, matching standard macOS distribution practices. The build system now compiles separate static libraries for each target triple (e.g., `aarch64-apple-darwin`, `x86_64-apple-darwin`) and combines them into a Universal Binary using `lipo`. The implementation is clean, with no on-disk format changes, and remains a no-op when `RUST_TARGETS` is unset or `NO_RUST=1` is specified.

The series is effectively ready for integration, with Junio having queued version 6 in `next`. The only unresolved topic is Patrick Steinhardt’s suggestion to adjust the `target/` directory structure for Rust artifacts, but this is not a blocker. The thread has seen substantive reviews from Junio and Patrick, with minor feedback from Kristoffer Haugsbakk and D. Ben Knoble incorporated.
