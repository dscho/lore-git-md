This thread wraps up a focused two-patch series from Shardul Natu and Koji Nakamaru that adjusts Git’s build system to better support Rust components on macOS. The goal was twofold: first, to fix a parallel build race condition that could cause `git-credential-osxkeychain` to fail when linking against Rust libraries in a clean tree, and second, to add Universal Binary support so Rust components can be built for multiple architectures (e.g., Intel and Apple Silicon) in a single build.

The first patch ensures the credential helper links against Rust libraries by adding `$(RUST_LIB)` as a prerequisite, wrapped in `ifndef NO_RUST` for backward compatibility. The second patch, which is the focus of this latest email, introduces the `RUST_TARGETS` environment variable, allowing users to specify multiple Rust target triples. The build system then compiles separate static libraries for each target and combines them into a Universal Binary using `lipo`, Apple’s tool for creating multi-architecture binaries. This approach bridges the gap between Apple’s C toolchain, which natively supports multi-architecture builds, and Cargo, which requires separate invocations per target.

All review feedback has been addressed, including Junio’s style tweaks and Patrick Steinhardt’s earlier concerns about the completeness of Universal Binary support. While Patrick noted that the C build itself doesn’t yet support multi-architecture builds, the current design is accepted as sufficient for practical use cases like distribution and CI. The series is now converged, with no outstanding objections, and is ready for Junio to pick up into his integration branches. The changes are build-time only, with no on-disk format changes or new tests required.
