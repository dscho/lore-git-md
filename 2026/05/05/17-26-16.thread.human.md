This thread is about a build system adjustment for Git’s macOS credential helper (`git-credential-osxkeychain`) as part of the broader Rustification effort. The patch series, now at **v5**, aims to fix a parallel build race condition and add Universal Binary support for Rust components on macOS. The current focus is on the first patch, which ensures the credential helper links against Rust libraries when Rust is enabled.

The series has been under review by Patrick Steinhardt and others, with most feedback addressed in the latest iteration. However, **Junio C Hamano has raised a critical new issue**: the patch’s use of `$(GITLIBS)` as a prerequisite for `git-credential-osxkeychain` introduces a duplicate `main()` symbol conflict, since `$(GITLIBS)` includes `common-main.o` (which provides `main()`), while the credential helper defines its own `main()`. This is a blocking regression that must be resolved before the patch can proceed.

The second patch in the series, which implements Universal Binary support via the `RUST_TARGETS` environment variable, remains unaffected by this issue. The series is otherwise technically complete, with only a medium-weight design question about Rust artifact layout still open. The authors, Shardul Natu and Koji Nakamaru, will need to revise the patch to avoid the `main()` conflict while preserving the fix for the parallel build race. Until then, the series is stalled.
