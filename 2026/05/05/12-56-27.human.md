This is a technical clarification from Junio C Hamano about Git's clean/smudge filter behavior with binary files.

Junio responds to Randall Becker's question about how filters handle binary files that match filter patterns in .gitattributes. He makes three key points:

1. Passing binary data through stdin/stdout is normal Git behavior and works reliably (citing the example of JPEG files processed by exif filters).

2. The filter attribute operates independently of other attributes like "text" or "diff" - filters don't automatically skip binary files because some filters are specifically designed to process binary content.

3. The proper way to limit filter application is by carefully specifying patterns in .gitattributes (e.g., `*.txt filter=mytextfilter`) rather than relying on binary detection within the filter itself.

Junio's response suggests the current behavior is working as designed and that the solution to Randall's use case lies in more precise .gitattributes patterns rather than modifying filter behavior. This maintains Git's flexibility to handle both text and binary filtering while providing a clear path for Randall to achieve his goal of stable filtering in frequently-changed directories.
