This is the final patch in a bugfix series addressing negative context values in diff options. The patch clarifies documentation for `PARSE_OPT_NONEG` in `parse-options.h` to explicitly state that the flag only prevents boolean negation (--no-* forms) and does not reject negative numeric values. 

The commit explains that the clarification is motivated by previous conversions of `--inter-hunk-context` and `-U/--unified` to use `OPT_INTEGER_F` with `PARSE_OPT_NONEG`, which inadvertently lost the implicit negative value rejection that existed in the old parser. The patch adds documentation to prevent similar misunderstandings in the future, recommending `OPT_UNSIGNED` for options that must reject negative numbers.

This is a straightforward documentation improvement that completes the series by ensuring the parse-options behavior is clearly documented. The change is minimal (4 lines added, 1 line modified) and focused solely on the header file documentation.
