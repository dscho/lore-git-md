Refactoring: Bulk branch deletion warning improvements in `fetch.pruneBranches` series.

This patch modifies the branch deletion machinery to support bulk operations more cleanly by adding two new parameters to `delete_branches()` and its helper `check_branch_commit()`:

1. `warn_only` - When set, converts the error message about unmerged branches into a one-line warning and prevents the function from returning an error status for those cases. The branches are still skipped from deletion, but the caller can continue processing other branches.

2. `n_not_merged` - An optional counter that tracks how many branches were skipped due to being unmerged, allowing bulk callers to provide a single summary rather than per-branch advice.

The changes maintain backward compatibility by defaulting both parameters to their original behavior (error messages and no counting). The implementation appears cleanly isolated to the branch deletion logic, with comprehensive error handling preserved. This prepares the plumbing for the series' upcoming `--prune-merged` functionality where bulk operations will be common.

The patch follows the series' architectural direction of decomposing functionality into reusable components, in this case making the branch deletion machinery more flexible for both interactive and automated use cases. The changes are mechanical rather than behavioral - existing callers continue working exactly as before.
