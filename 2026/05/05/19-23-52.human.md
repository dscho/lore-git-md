Feature: v4 of `fetch.pruneBranches` series adds default branch protection.

Harald Nordgren's v4 patch series introduces a safety mechanism to prevent accidental deletion of local default branches when using the new `--prune-merged` functionality. This comes after a real-world incident where the command wiped out a local master branch unexpectedly.

Key changes in v4:
1. Special handling for default branches (like `main` or `master`) that match their remote counterparts - these are now never pruned automatically
2. Protection extends to branches whose push target is a remote's default branch
3. Added test cases verifying the new protection behavior while still allowing pruning of non-default branches

The series maintains all previous functionality from v3 including:
- `git branch --forked` and `--prune-merged` plumbing
- `--all-remotes` convenience flag
- Per-branch `branch.<name>.pruneMerged` opt-out
- `fetch --prune-merged` integration

The implementation appears thorough, using a `protected_default_refs` set to track which branches should be preserved. The protection logic considers both upstream and push relationships to avoid false positives where a branch might coincidentally share a name with a remote's default branch.

This revision addresses a real usability concern while maintaining the series' original goal of automating branch cleanup. The changes are additive and don't affect existing behavior for non-default branches. The outstanding naming concern about `--prune-merged` (raised by Johannes Sixt in previous rounds) remains unaddressed but doesn't block this safety improvement.
