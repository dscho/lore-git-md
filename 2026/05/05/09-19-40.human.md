Security hardening patch for Git's HTTP proxy handling, now in its second iteration. This addresses a vulnerability where Git would silently accept invalid proxy URL schemes (e.g. "htpp://") by treating them as HTTP proxies. The patch now rejects such URLs with clear error messages.

The v2 changes incorporate Junio's feedback by:
1. Replacing string comparisons with a table-driven approach for SOCKS proxy types
2. Centralizing scheme validation in a new `set_curl_proxy_type()` function
3. Making the test case more robust with `test_must_fail` and focused error checking

The implementation maintains backward compatibility with host:port format while adding proper validation for scheme-based URLs. The changes touch `http.c` (93 lines) and add a regression test. This appears to be a well-considered security fix that addresses a real vulnerability while following Git's conservative approach to networking changes. The patch seems ready for merging after addressing the maintainer's concerns about code organization and test quality in v1.
