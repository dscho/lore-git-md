Feature: Refinement of branch deletion warnings in `fetch.pruneBranches` series.

This patch modifies the branch deletion machinery to support bulk operations more cleanly. It adds two new options to `delete_branches()` and its helper `check_branch_commit()`:

1. `warn_only` - converts the traditional error + advice about unmerged branches into a simple warning, while still skipping deletion of those branches
2. `n_not_merged` - allows callers to track how many branches were skipped due to unmerged changes

The changes are backward-compatible, with existing callers passing the default values (0 and NULL respectively). The implementation appears solid, with clear handling of both the warning/error distinction and the counting mechanism. This prepares the plumbing for the upcoming `--prune-merged` functionality where bulk operations will be common.

The patch is part of Harald Nordgren's v3 series implementing automatic branch cleanup when upstream branches are deleted. While this particular change is non-controversial (it's purely an internal improvement to support the larger feature), the series still has one open question about the naming of the `--prune-merged` flag that Johannes Sixt raised in earlier reviews.
