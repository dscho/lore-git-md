Build system patch addressing a compatibility issue between Clang and glibc 2.43's use of C11's `_Generic` feature. The problem surfaces when building with `DEVELOPER=1` which enforces C99 mode (-std=gnu99), causing Clang to fail on glibc headers that now use type-generic expressions.

Patrick Steinhardt identifies that glibc's feature gating doesn't work properly with Clang because it checks for extensions rather than core language features. The patch works around this by:
1. Not enforcing C99 mode for Clang builds in the Makefile
2. Adding `-Wno-c11-extensions` to suppress warnings in Meson builds

The commit notes this isn't ideal but maintains GCC's ability to catch misuse of newer standards. It also mentions bumping to C11 as a potential alternative, though acknowledges some platforms may not support it. The change was prompted by CI failures after upgrading to Ubuntu 26.04.

This is a targeted platform compatibility fix that affects developer builds, particularly those using Clang with newer glibc versions. The patch demonstrates awareness of build system nuances across different compilers and platforms.
