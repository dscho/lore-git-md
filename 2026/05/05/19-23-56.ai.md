Feature: `fetch --prune-merged` integration for automated local branch cleanup.

This patch (4/6 in the v4 series) implements the high-level `fetch --prune-merged` option that builds on the foundational `git branch --prune-merged` plumbing command introduced earlier in the series. When enabled, it automatically deletes local branches that track a remote branch that was just deleted during fetch pruning.

Key aspects:
- Runs `git branch --prune-merged <remote>` after a successful fetch
- Only operates on configured remotes (not URL-based fetches)
- Preserves all safety checks from the underlying plumbing:
  - Skips branches with unpushed work (reachability check)
  - Protects checked-out branches across all worktrees
  - Honors per-branch `branch.<name>.pruneMerged` configuration
  - Includes default branch protection from previous patches

The implementation verifies:
- Basic functionality (deletes properly merged local branches)
- Safety mechanisms (preserves branches with unpushed work)
- Error handling (reports unmerged branches appropriately)

This completes the series' goal of providing both low-level plumbing (`git branch --prune-merged`) and convenient high-level automation (`fetch --prune-merged`). The only remaining open question is Johannes Sixt's concern about the `--prune-merged` naming potentially misleading users about its upstream-based (rather than commit-reachability) behavior.

The patch appears well-structured with:
- Clear documentation of the new option
- Straightforward integration into fetch's existing flow
- Comprehensive tests covering both success and safety cases
- Proper error propagation when the underlying command fails

This represents the final user-facing piece of the functionality, with the previous patches having established all the necessary plumbing and safety mechanisms.
