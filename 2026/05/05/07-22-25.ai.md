Feature: `fetch --prune-merged` integration for automated local branch cleanup.

This patch (4/6 in the v3 series) adds the high-level `fetch --prune-merged` option that automatically runs `git branch --prune-merged` after a successful fetch. The implementation:

1. Adds the new `--prune-merged` flag to `git fetch` which:
   - Only operates on configured remotes (not direct URLs)
   - Runs after successful fetch operations
   - Fails the entire fetch if pruning fails
   - Preserves the current branch across all worktrees

2. Includes comprehensive tests verifying:
   - Deletion of local branches when upstream branches are pruned
   - Skipping branches with unpushed work (with warning)
   - Proper error handling when pruning fails

The change builds on the decomposed architecture from earlier patches, using the new `git branch --prune-merged` plumbing command (added in patch 3/6) while maintaining all its safety mechanisms:
- Reachability checks prevent data loss
- Checked-out branch protection
- Per-branch opt-out via `branch.<name>.pruneMerged=false`

The implementation appears thorough with clear documentation and test coverage for both success and edge cases. This completes the automated workflow for cleaning up local branches when their upstream counterparts are deleted, while preserving unpushed work through the existing safety checks from the underlying branch plumbing.

The patch maintains consistency with the series' terminology updates (using "remote-tracking branches") and leaves the outstanding naming concern about `--prune-merged` (raised by Johannes Sixt) for future discussion.
