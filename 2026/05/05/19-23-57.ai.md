Feature: Per-branch opt-out for `--prune-merged` functionality in v4 series.

This patch introduces a new `branch.<name>.pruneMerged` configuration option that allows individual branches to be exempted from automatic pruning via `git branch --prune-merged` and `git fetch --prune-merged`. The setting is `false` by default, meaning branches will be pruned unless explicitly opted out.

Key aspects:
1. The opt-out persists even when using `--force`, maintaining protection for branches marked as "don't prune"
2. Explicit deletion via `git branch -d` remains unaffected by this setting
3. The implementation includes comprehensive test coverage for:
   - Basic opt-out functionality
   - Interaction with `--force`
   - Preservation of traditional branch deletion behavior
   - User feedback when skipping protected branches

The patch is part of Harald Nordgren's v4 series implementing local branch pruning functionality, building on previous work that established the `--prune-merged` plumbing and its integration with `git fetch`. This particular addition addresses a practical workflow need - keeping topic branches around between development rounds even after their upstream counterparts have been deleted.

The implementation appears clean and well-tested, with careful attention to edge cases and clear documentation updates. It maintains the series' architectural separation between listing (`--forked`) and pruning (`--prune-merged`) operations while adding this new configuration dimension.

The only remaining open question in the series is Johannes Sixt's concern about the `--prune-merged` flag name potentially misleading users about its upstream-based behavior rather than commit reachability semantics.
