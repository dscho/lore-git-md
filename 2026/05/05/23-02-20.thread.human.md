This thread is about a bug where negative values for `-U`/`--unified` and `--inter-hunk-context` are silently accepted but produce garbage hunk headers (e.g., `@@ -503,999- +503,999- @@`) that `git apply` cannot use. Michael Montalbo found that when these options were converted from a custom parser that used `isdigit()` (which implicitly rejects negatives) to standard `OPT_INTEGER_F`/`OPT_CALLBACK`, the validation was lost.

The fix is a four-patch series that converts both options to unsigned types with proper validation, adds a defensive `BUG()` check in xdiff itself, and clarifies the `PARSE_OPT_NONEG` documentation (it only blocks `--no-*` forms, not negative numbers). The approach aligns CLI behavior with the existing config variables `diff.context` and `diff.interHunkContext`, which already reject negatives.

The series is technically sound with test coverage and has been reviewed. This is v2, with revised commit messages that no longer incorrectly link `PARSE_OPT_NONEG` to the bug. Junio C Hamano accepted the solution and the final documentation clarification was adjusted per his feedback. The only remaining item is an administrative note: Montalbo acknowledged Junio's feedback about cover letter formatting and committed to cleaner presentation in future submissions. The series is ready for `next` with no outstanding technical blockers.
