Feature: Core implementation of `git branch --prune-merged` for safe local branch cleanup.

This patch (3/6 in the v3 series) implements the core functionality for safely pruning local branches that track deleted upstream branches. The command checks both that the push ref is gone (indicating the branch was deleted upstream) and that the local tip is reachable from the upstream (protecting unpushed work by default, with `--force` override). The implementation builds on the `--forked` plumbing from earlier patches and adds:

1. Safety mechanisms:
   - Reachability check prevents deleting branches with unpushed commits
   - Explicit protection for checked-out branches across all worktrees
   - Configurable per-branch opt-out via `branch.<name>.pruneMerged`

2. Comprehensive test coverage for:
   - Basic pruning when upstream branch is deleted
   - Protection of branches with unpushed work
   - `--force` override behavior
   - Checked-out branch protection
   - Cases where push ref differs from upstream

The implementation appears thorough and well-tested, with clear documentation of the safety checks. This provides the foundation for the higher-level `fetch --prune-merged` integration in later patches. The outstanding naming concern about `--prune-merged` potentially misleading users about the upstream-based (rather than commit-reachability) behavior remains unaddressed, but the technical implementation itself looks solid.
