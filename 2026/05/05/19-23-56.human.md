Feature: `fetch --prune-merged` integration for automated local branch cleanup.

This patch (4/6 in the v4 series) adds the high-level `fetch --prune-merged` option that builds on the foundational `git branch --prune-merged` plumbing command introduced earlier in the series. When enabled, it automatically deletes local branches that track a remote branch that was just pruned, provided the local branch's tip is reachable from its upstream.

Key aspects:
- Runs after a successful fetch from a configured remote
- Preserves the currently checked-out branch
- Only operates on branches tracking the fetched remote
- Integrates with existing `--prune` behavior
- Includes tests demonstrating:
  - Deletion of merged local branches
  - Skipping unmerged branches (with warning)
  - Protection of checked-out branches

The implementation is cleanly separated from core fetch logic, using a child process to run the branch plumbing command. This maintains the series' architectural approach while providing convenient automation of the branch cleanup process.

This completes the user-facing portion of the feature, complementing the earlier plumbing commands. The only remaining open question is Johannes Sixt's concern about the `--prune-merged` naming potentially misleading users about its upstream-based behavior rather than commit reachability.
