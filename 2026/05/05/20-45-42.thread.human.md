Kristoffer Haugsbakk has proposed a documentation patch to clarify that Git's commit-graph optimization is disabled when either replace objects (managed via `git-replace`) or commit grafts are present. While this behavior was previously documented in technical notes, it wasn't mentioned in the user-facing man pages. The patch adds clear "CAVEATS" sections to both `git-commit-graph` and `git-replace` manuals with cross-references between them.

Derrick Stolee, an expert on Git's performance optimizations including the commit-graph feature, has reviewed the patch positively. He agrees with the documentation improvement but suggests strengthening the wording to explicitly mention the performance impact - noting that disabling commit-graph functionality can cause measurable slowdowns. This refinement would help users better understand the practical consequences of using replace objects. The thread shows consensus on the need for this documentation clarification, with Stolee's feedback focused on making the information more actionable for end users.
