This is a bugfix discussion for git-gui's handling of repository detection and worktree validation. Mark Levedahl responds to Johannes Sixt's proposed solution for maintaining backward compatibility with `.git` directory usage while improving error handling.

Mark reports that his attempts to restructure git-gui's startup code to properly handle GIT_DIR and GIT_WORK_TREE environment variables have hit fundamental limitations - git-gui's blame and browser commands simply don't work without a valid worktree. He notes that debugging these issues would require reverting to Git 2.24 or earlier to work around changes in `--show-toplevel` behavior, which isn't practical due to version compatibility issues.

The email effectively concedes that Johannes Sixt's simpler approach - preserving the special case for `.git` directories while otherwise requiring a valid worktree - is the most viable path forward, despite leaving some "dead code" in place. This represents a pragmatic retreat from Mark's earlier position advocating for more comprehensive environment variable handling.

The discussion continues to balance correctness against backward compatibility, with the consensus now favoring Johannes Sixt's position that preserving the historical `.git` directory behavior is more important than attempting to fully support all possible environment variable configurations. The thread remains focused on finding a minimally disruptive solution to the original bare repository detection problem.
