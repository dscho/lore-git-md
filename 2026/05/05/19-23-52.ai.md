Feature: v4 of `fetch.pruneBranches` series with default branch protection.

Harald Nordgren's v4 patch series introduces a key safety enhancement to the local branch pruning functionality by protecting default branches from accidental deletion. This builds on the v3 implementation which provided decomposed plumbing commands (`git branch --forked` and `--prune-merged`) with `--all-remotes` support.

The main changes in v4:
1. Default branch protection:
   - Automatically identifies each remote's HEAD ref (e.g. `origin/main`)
   - Skips pruning when:
     * Local branch name equals the default branch's leaf name (e.g. local `main` tracking `origin/main`)
     * Branch's push ref points to a protected default branch
   - Includes comprehensive tests for edge cases (renamed branches, push refs)

2. Maintains all v3 functionality:
   - Per-branch opt-out via `branch.<name>.pruneMerged`
   - `--all-remotes` convenience flag
   - `fetch --prune-merged` integration
   - Bulk deletion improvements

The implementation appears thorough with careful handling of edge cases through:
- String list collection of protected refs
- Leaf name matching for default branch protection
- Push ref consideration
- Comprehensive test coverage including multi-remote scenarios

The series remains architecturally sound with clear separation between:
- `git branch --forked` for listing
- `git branch --prune-merged` for safe deletion
- `fetch --prune-merged` for automation

Notable that Johannes Sixt's naming concern about `--prune-merged` potentially misleading users about commit reachability vs upstream status remains unaddressed, though this doesn't affect the technical correctness of the implementation.

The default branch protection addresses a real-world usability concern that emerged from testing, demonstrating the author's responsiveness to practical feedback while maintaining the series' core design goals.
