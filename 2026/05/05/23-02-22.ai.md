This is the second patch in a bugfix series addressing negative diff context values. It converts the `-U`/`--unified` option to use unsigned values with proper validation, following the same approach as the first patch did for `--inter-hunk-context`.

The patch changes:
- Converts `diff_options.context` and its default from `int` to `unsigned int`
- Adds validation in the config parser to reject negative values for `diff.context`
- Implements range checking in the `-U` callback (which needs special handling due to `OPT_CALLBACK_F` for optional arguments)
- Adds a test case verifying rejection of negative `-U` values

The changes mirror the treatment of `interhunkcontext` from patch 1, maintaining consistency between CLI and config behavior. The test coverage demonstrates the fix prevents malformed hunk headers that could previously occur with negative values. This continues the series' systematic approach to hardening the context value validation.
