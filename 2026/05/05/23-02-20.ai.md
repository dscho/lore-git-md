This is a bugfix series addressing an issue where negative context values in diff options produce malformed output. The cover letter explains that negative values for `-U`/`--unified` and `--inter-hunk-context` are silently accepted but generate invalid diff hunks (with negative line counts) and can cause patch application failures.

The series consists of four patches:
1. Converts `--inter-hunk-context` to use `OPT_UNSIGNED` to reject negatives
2. Adds validation for `-U`/`--unified` values (converting to unsigned and adding callback checks)
3. Adds a defensive `BUG()` in xdiff's hunk generation as a last resort
4. Documents that `PARSE_OPT_NONEG` doesn't handle negative numbers (only `--no-*` forms)

The changes bring CLI behavior in line with the config variables (`diff.context` and `diff.interHunkContext`) which already reject negatives. The patches appear well-structured with clear commit messages and include test coverage. This looks like a straightforward correctness fix for an edge case that could cause subtle problems with diff output.
