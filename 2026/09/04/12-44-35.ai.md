This is a documentation patch, the second part of a two-patch series that originally included a test addition. The author has now dropped the test patch (part 1) after review feedback, focusing solely on clarifying the existing behavior in the man page.

The patch updates `Documentation/git-cherry-pick.adoc` to explicitly document that `CHERRY_PICK_HEAD` is *not* created when `git cherry-pick --no-commit` encounters conflicts. This behavior, introduced in 2011 (commit d7e5c0cbfb), was previously undocumented, leaving users unaware of the asymmetry with `git revert --no-commit` (which *does* write `REVERT_HEAD`). The new documentation explains the implications for `git commit`: without `CHERRY_PICK_HEAD`, a plain commit will record the current user as the author, not the original commit’s author, and suggests using `git commit -c <commit>` to preserve authorship when picking a single commit.

The commit message is clear and well-motivated, citing the 2011 commit and explaining the user-facing consequences of the undocumented behavior. The patch itself is minimal and focused, adding a bullet point to the conflict-handling list and a dedicated paragraph under `--no-commit`. The change is uncontroversial and directly addresses the gap identified in the thread. With the test patch now dropped, this documentation update stands alone as a straightforward improvement.
