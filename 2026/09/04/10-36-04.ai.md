This is the third patch in Patrick Steinhardt’s 11-patch series unifying Git’s terminology for "ref storage." It mechanically renames the `--ref-format=` option to `--ref-storage=` in the `git refs` built-in command, retaining the old name as a hidden backward-compatibility alias. The patch touches the man page (`Documentation/git-refs.adoc`), the command implementation (`builtin/refs.c`), the fetch error message (`builtin/fetch.c`), and three test scripts (`t/t1423-ref-backend.sh`, `t/t1460-refs-migrate.sh`, `t/t7424-submodule-mixed-ref-formats.sh`). All test updates are search-and-replace: every occurrence of `--ref-format=` is changed to `--ref-storage=`, and the usage strings are updated accordingly.

The change is purely terminological and does not alter behavior. The backward-compatibility alias ensures that scripts or users still using `--ref-format=` will not break, though the old name is now hidden in help output. The patch is part of a larger effort to prepare for an analogous "object storage" extension, and it follows the same pattern established in the first two patches (for `git init` and `git clone`). Reviewers are likely to focus on whether the alias is sufficient for backward compatibility and whether any edge cases in URI handling or error messages were overlooked.
