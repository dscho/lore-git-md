This is a refactoring and consistency cleanup series targeting Git's reference storage terminology. The 11-patch series, authored by Patrick Steinhardt, addresses long-standing inconsistencies in how Git refers to the "ref storage format" across command-line options, environment variables, configuration keys, and documentation. Currently, the same concept is called `--ref-format=` on the command line, `refStorage` as a repository extension, and `GIT_REFERENCE_BACKEND` in environment variables, creating confusion—especially as the project prepares to introduce an analogous "object storage" extension.

The series systematically renames all occurrences of "ref format" to "ref storage" for consistency: `--ref-format=` becomes `--ref-storage=`, the environment variable `GIT_REFERENCE_BACKEND` is renamed to `GIT_REF_STORAGE`, and the config key `init.defaultRefFormat` becomes `init.defaultRefStorage`. It also refactors the setup code to centralize URI parsing for reference storage backends, allowing `--ref-storage=` to accept URIs like `files://path/to/repo`—a capability already present in other parts of the codebase but not exposed here. The changes touch built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), documentation, test scripts, and shell completions across 39 files.

The motivation is clear: the current terminology is a "huge mess" that will only worsen with the upcoming object storage extension, and the series aims to preemptively clean it up. The commit messages are detailed and the scope is well-justified, though the sheer number of mechanical changes (314 deletions, 407 insertions) suggests this is primarily a search-and-replace effort with some structural refactoring in `setup.c`. The series is marked as v1, indicating it is ready for review but not yet final.

Key technical details for follow-up discussion: the new `parse_ref_storage_uri()` function in `refs.c`/`refs.h`, the renamed environment variables (`GIT_REF_STORAGE` and `GIT_TEST_REF_STORAGE`), and the config key `init.defaultRefStorage`. The series also updates all relevant tests, which should help catch any behavioral regressions. Given Patrick's role as a primary driver of the reftable backend and ODB abstraction efforts, this cleanup is likely to be uncontroversial in direction, though reviewers may scrutinize edge cases in URI handling or backward compatibility. The BreakingChanges.adoc update signals that this is intentionally breaking for consistency.
