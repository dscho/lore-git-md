This is the third and final patch in a v2 series that completes the auto-maintenance deferral effort for the sequencer. It prevents `git commit`, `git merge`, and any command run via `exec` from triggering auto maintenance during a sequencer-driven operation (`rebase`, `cherry-pick`, `revert`), ensuring maintenance runs exactly once at sequence completion.

The patch adds a new `disable_auto_maintenance()` helper that builds and caches a `GIT_CONFIG_PARAMETERS` string in the `replay_ctx` struct. This string disables auto maintenance (`maintenance.auto=false`, `gc.auto=0`) for all spawned commands, overriding any user `-c` settings. The helper is called in `run_git_commit()`, `do_merge()`, and `do_exec()`, and the cached string is released when the context is freed. Test coverage in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh` verifies that no maintenance runs occur during intermediate steps and exactly one runs at sequence end.

The implementation is clean and addresses all prior feedback: the config-parameter logic is factored into a reusable helper, the string is cached to avoid repeated construction, and the scope now covers all three sequencer commands. The patch is technically complete and ready for integration. No open technical objections remain, and the only watch item is a hypothetical edge case about very long sequences where mid-sequence repacking might be beneficial—something Phillip Wood wants to monitor in real-world usage rather than block on.
