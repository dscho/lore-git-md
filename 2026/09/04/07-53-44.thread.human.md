This thread is about a two-patch series (v2) by Thomas Bachem that adjusts when Git's auto maintenance runs during sequencer-driven operations like `git rebase`, `git cherry-pick`, and `git revert`. The goal is to defer maintenance until the sequence completes, matching the behavior of the apply backend and avoiding interference with intermediate steps. The series is technically complete and addresses all prior feedback from reviewers Phillip Wood and Patrick Steinhardt.

The key change is that auto maintenance now runs exactly once at sequence completion, after autostash is applied, instead of during intermediate commits or merges. This is achieved by disabling auto maintenance for individual commands during the sequence via `GIT_CONFIG_PARAMETERS` and invoking `git maintenance run --auto` at the end. The series touches the sequencer, auto maintenance, and config subsystems, and includes test coverage for rebase and cherry-pick scenarios.

The only remaining open item is a hypothetical edge case about very long sequences where mid-sequence repacking might improve performance, but this is noted as a watch item rather than a blocker. Phillip Wood and Patrick Steinhardt have reviewed the series, and all feedback has been addressed. Junio C Hamano recently suggested a minor code clarity improvement—using a `const char *` instead of a `struct strbuf` to store the cached config string in `replay_ctx`—but this is a surface-level tweak that doesn’t affect functionality. The series is otherwise ready for integration.
