This is the final patch in Patrick Steinhardt’s 11-patch series that unifies Git’s terminology around "ref storage" and centralizes URI parsing for reference backends. Patch 11/11 teaches `git init --ref-storage=` and `git clone --ref-storage=` to accept a URI-style payload (`<format>://<payload>`), matching the syntax already supported by the `extensions.refStorage` config key and `GIT_REF_STORAGE` environment variable. The payload allows backend-specific configuration—for example, specifying an alternate directory for the "files" backend or a database connection string for "reftable".

The patch updates the man pages to document the new URI syntax and the optional payloads for both backends, then modifies `builtin/clone.c` and `builtin/init-db.c` to pass the raw `--ref-storage=` string (rather than a parsed enum) into `init_db()`. The core logic moves to `setup.c`, where `repository_format_configure()` now uses the existing `ref_storage_format_by_uri()` helper to parse the URI and extract the payload. A new test in `t/t1423-ref-backend.sh` verifies that the URI is correctly stored in `extensions.refStorage`, that the refs are created in the specified directory, and that reinitializing the repository with a different payload is rejected (enforcing the immutability rule introduced in patch 8).

This is a natural extension of the earlier patches: it removes the last place where URIs were not supported, completes the symmetry between CLI, config, and environment variables, and enables users to configure backend-specific options at init/clone time without editing config files afterward. The implementation is clean, the test coverage is thorough, and the backward-compatibility story remains intact. If the series lands, this patch will be the user-facing capstone.
