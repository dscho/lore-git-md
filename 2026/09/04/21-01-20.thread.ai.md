Subject: [PATCH 0/2] Fix --force-if-includes to check the correct reflog
Series version: v1 (initial submission)
Originating author: Tyler Cipriani
Thread type: bugfix patch series

Core problem or goal
The `--force-if-includes` safety mechanism in `git push` incorrectly checks the reflog of the *local* branch whose name matches the *remote* destination branch, rather than the branch actually being pushed. This flaw can cause false rejections (e.g., pushing from a differently named local branch or detached HEAD) or unintended data loss (e.g., pushing an unrelated branch that happens to share a name with a local branch containing the remote tip).

Current status
Under review (no prior versions). The series consists of two patches:
1. Fixes the core logic to consult the reflog of the pushed ref.
2. Adjusts the advice message for detached HEAD scenarios, adding a new `advice.forceIfIncludesDetachedHead` config knob.

Key technical details
- Files touched: `builtin/push.c`, `remote.c`, `send-pack.c`, `advice.c`, `t/t5533-push-cas.sh`.
- New symbols: `advice.forceIfIncludesDetachedHead` config key.
- Behavior change: `--force-if-includes` now checks the reflog of the pushed ref, not the local branch named after the destination.
- Test coverage: five new test cases in `t/t5533-push-cas.sh` covering mismatched local/remote names, HEAD-based pushes, and detached HEAD states.
- On-disk format: unchanged.

Open questions and loose ends
- Whether detached HEAD pushes should be rejected or allowed (author leans toward rejection to avoid surprising behavior).

Participant positions
- Tyler Cipriani (author): argues for rejecting detached HEAD pushes to prevent unintended data loss.
