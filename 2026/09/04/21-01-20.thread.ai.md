Subject: [PATCH 0/2] Fix --force-if-includes to check the correct reflog
Series version: v1 (initial submission)
Originating author: Tyler Cipriani
Thread type: bugfix patch series

Core problem or goal
The `--force-if-includes` safety mechanism in `git push` incorrectly checks the reflog of the *local* branch whose name matches the *remote* destination branch (e.g., `main` when pushing to `origin/main`), rather than the branch actually being pushed (e.g., `src` when pushing `src:main`). This flaw can cause false rejections (e.g., pushing from a differently named local branch or detached HEAD) or unintended data loss (e.g., pushing an unrelated branch that happens to share a name with a local branch containing the remote tip).

Current status
Under review (no prior versions). The series consists of two patches, both now submitted:
1. Fixes the core logic in `remote.c` to consult the reflog of the pushed ref (`ref->peer_ref->name`) instead of the destination ref (`ref->name`). Adds special handling for `HEAD`-based pushes (resolving the symref) and detached HEAD states (rejecting the push by default). Explicitly allows deletions via `is_null_oid(&remote->peer_ref->new_oid)`.
2. Adjusts the advice message for detached HEAD scenarios, introducing a new `advice.forceIfIncludesDetachedHead` config knob (exposed as `advice.pushRefUnverifiable` in documentation) and a `ref->unverifiable` flag to distinguish detached HEAD rejections from remote-update rejections. The advice now instructs users to specify the expected remote tip with `--force-with-lease=<ref>:<expect>` or bypass the check with `--no-force-if-includes`. All transport layers (direct pushes, transport helpers, send-pack) are updated for consistency.

Key technical details
- Files touched: `builtin/push.c`, `remote.c`, `remote.h`, `send-pack.c`, `transport-helper.c`, `transport.c`, `advice.c`, `advice.h`, `t/t5533-push-cas.sh`.
- New symbols: `advice.forceIfIncludesDetachedHead` config key (documented as `advice.pushRefUnverifiable`), `ADVICE_PUSH_REF_UNVERIFIABLE` enum, `ref->unverifiable` flag.
- Behavior change: `--force-if-includes` now checks the reflog of the pushed ref, not the local branch named after the destination. Detached HEAD pushes are rejected by default (configurable via the new advice knob). Advice messages are actionable and consistent across transport layers.
- Test coverage: eight new test cases in `t/t5533-push-cas.sh` covering mismatched local/remote names, `HEAD`-based pushes, detached HEAD states, and the new advice message.
- On-disk format: unchanged.

Open questions and loose ends
- None remaining. The prior question about whether detached HEAD pushes should be rejected or allowed was resolved in the first patch (reject by default), and the second patch made this behavior configurable.

Participant positions
- Tyler Cipriani (author): argues for rejecting detached HEAD pushes by default to prevent unintended data loss, with the behavior configurable via `advice.forceIfIncludesDetachedHead`. Implements the fix, test coverage, and advice message updates across all transport layers.

Related work
- Cites two prior reports of false rejections (2023, 2025) with the same root cause. No external dependencies. The fix does not affect `--force-with-lease` behavior.
