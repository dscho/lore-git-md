This is the first patch in a two-part series targeting the sequencer subsystem to adjust when auto maintenance runs during a `git rebase`. The goal is to make the merge backend defer auto maintenance until the end of the rebase, aligning its behavior with the apply backend.

The patch modifies `sequencer.c` to run `git maintenance run --auto` once the rebase completes, specifically after the autostash is applied. This ensures both backends (apply and merge) handle auto maintenance consistently. The change is motivated by prior discussion where Phillip Wood and Patrick Steinhardt suggested deferring maintenance to avoid interference with intermediate rebase steps. The implementation is straightforward: it adds a call to `run_auto_maintenance()` in the sequencer’s cleanup path, ignoring errors to avoid masking user-facing issues.

The test coverage in `t/t3418-rebase-continue.sh` verifies the new behavior by checking that `git maintenance run --auto` is invoked at the end of a rebase. The test uses `GIT_TRACE2_EVENT` to capture the command execution and confirms the expected subcommand is run. This patch does not affect cherry-pick or revert operations, nor does it change the apply backend’s existing behavior.
