This is the fifth patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology for "ref storage" (previously called "ref format"). It renames the `--show-ref-format` option in `git rev-parse` to `--show-ref-storage` and retains the old name as a backward-compatible alias. The patch touches `builtin/rev-parse.c`, its documentation, shell completions (`contrib/completion/git-prompt.sh`), and seven test scripts (`t0001-init.sh`, `t0610-reftable-basics.sh`, `t1460-refs-migrate.sh`, `t1500-rev-parse.sh`, `t5601-clone.sh`, `t7424-submodule-mixed-ref-formats.sh`, and `t/perf/perf-lib.sh`).

The change is mechanical: every occurrence of `--show-ref-format` is replaced with `--show-ref-storage`, and the old option name is kept as an alias in the command-line parser. The test updates are similarly straightforward, updating assertions to match the new option name. The patch does not alter behavior—only the user-facing name of the option—so there is no risk of functional regression. The backward-compatible alias ensures scripts and users relying on the old name will continue to work.

This patch is part of the broader effort to clean up inconsistent terminology ahead of the upcoming "object storage" extension. The series has already updated `git init`, `git clone`, `git refs`, and `git submodule` in earlier patches; this one extends the same change to `git rev-parse`. The files touched are consistent with the series’ goal: built-in commands, documentation, shell completions, and tests. No new edge cases or open questions are introduced by this patch—it is a pure rename with backward compatibility.
