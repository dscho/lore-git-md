This is a substantive review comment on the second patch of the v5 series adding path-related keys to `git repo info`. Junio C Hamano identifies a correctness bug in the implementation of `path.superproject-root.absolute` and `path.superproject-root.relative`: the underlying `get_superproject_working_tree()` function ignores the `repo` parameter and instead relies on the current working directory, which breaks the expected behavior when invoked from a submodule’s `.git` directory (e.g., via `--git-dir`). The bug causes `path.superproject-root.absolute` to return an empty string in contexts where it should return the superproject’s working tree path, such as when running `git --git-dir="$GIT_DIR" repo info` from a submodule.

The fix requires updating `get_superproject_working_tree()` to accept a `struct repository *` parameter and use it to determine the correct working directory, rather than relying on `xgetcwd()`. This change would align the function’s behavior with the rest of the series, where all path keys operate on the specified repository object. The patch is otherwise mechanically clean and uncontroversial, but this issue must be addressed before the series can proceed. The author, K Jayatheerth, will need to revise the patch to pass the `repo` parameter through to `get_superproject_working_tree()` and update its internals to use the repository’s working directory instead of the process’s current directory. The test suite already covers the expected behavior, so the fix should be straightforward to verify.
