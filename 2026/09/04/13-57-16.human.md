This is a documentation patch for `git cherry-pick` that clarifies a long-standing but undocumented edge case. The patch adds a note to the `git-cherry-pick` man page explaining that `CHERRY_PICK_HEAD` is *not* created when `git cherry-pick --no-commit` fails due to conflicts, contrasting this with `git revert --no-commit` (which *does* write `REVERT_HEAD`). The behavior, introduced in 2011 and confirmed as intentional by Phillip Wood, has implications for users: for example, `git commit` will not preserve authorship unless explicitly told to use `git commit -c <commit>`.

The patch itself is uncontroversial and well-motivated. It touches only `Documentation/git-cherry-pick.adoc`, adding a bullet point to the conflict-handling list and a dedicated paragraph under `--no-commit` to explain the asymmetry and its practical consequences. The commit message is clear and references the historical context (commit d7e5c0cbfb). No code changes, new options, or on-disk format changes are involved.
