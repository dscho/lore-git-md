This is the first patch in Karthik Nayak’s four-part series introducing the `receive-report` hook, a new server-side feature for Git. This specific patch is purely documentation: it adds an eight-line `PROC-RECEIVE HOOK` section to `git-receive-pack(1)` to document the existing `proc-receive` hook, which was previously undocumented in this man page.

The change plugs a small but real gap in the documentation. The `proc-receive` hook is already part of Git’s push protocol (used when `receive.procReceiveRefs` is configured), but until now it was only documented in `githooks(5)`. Adding it here makes the `git-receive-pack` man page complete, listing all hooks that fire during a push. The new section explains the hook’s purpose—executing commands that match configured ref names instead of the internal `execute_commands()` function—and links back to `githooks(5)` for protocol details.

If you care about server-side hooks or GitLab’s use of Git, this patch is worth noting for completeness, but it’s not the main event of the series—that comes in patch 4.
