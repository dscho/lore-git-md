This is the first patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology around "ref storage" instead of the current inconsistent mix of "ref format," "ref backend," and "reference backend." The patch renames the `--ref-format=` command-line option in `git init` to `--ref-storage=`, updates all related documentation, and ensures backward compatibility by keeping the old option name as a hidden alias.

The change is mechanical but thorough: every test script, man page, and usage string that previously used `--ref-format=` now uses `--ref-storage=`. The patch also updates environment variable references in the documentation (though the actual environment variable rename comes in a later patch). The backward-compatibility shim (`OPT_STRING_F` with `PARSE_OPT_HIDDEN`) means scripts using the old option will still work, but the new name is now the official interface.

This is a refactoring patch with no functional changes—it simply aligns the CLI with the terminology already used in repository extensions and documentation. The motivation is clear: the current naming is confusing, especially as the project prepares to introduce an analogous "object storage" extension. Given Patrick’s role as the primary driver of the reftable backend and ODB abstraction efforts, this cleanup is likely uncontroversial in principle, though reviewers may focus on edge cases in URI handling or overlooked references in less common code paths. The patch is well-explained and the test updates suggest good coverage.
