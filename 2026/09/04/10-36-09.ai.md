This is the eighth patch in Patrick Steinhardt’s 11-patch series unifying Git’s reference storage terminology. It refactors the logic in `setup.c` that determines which ref storage format a repository should use, splitting the tangled precedence and validation steps into a clear, extensible sequence.

The patch addresses a real bug: when a repository initialized with one ref storage format (e.g., files) is reinitialized with `GIT_REFERENCE_BACKEND` set to a different format (e.g., reftable), Git silently changes the format and corrupts the repository. The new code enforces a strict check that prevents this by treating the existing repository format as immutable once set. It also reorders precedence so that the `--ref-storage=` command-line option overrides the environment variable, aligning with Git’s usual precedence rules.

The refactoring is clean and well-motivated. The commit message explains the problem, the fix, and the new precedence order in detail. The test additions (`t/t0001-init.sh`) verify both the error message for invalid formats and the refusal to reinitialize with a different format. This patch is a substantive improvement, not just a mechanical rename, and it prepares the codebase for the URI-based ref storage configuration that later patches will introduce.
