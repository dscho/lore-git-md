This is a **maintainer follow-up** in the thread fixing a heap-buffer-overflow in pathspec handling. Junio C Hamano endorses Elijah Newren’s observation that the existing regression test, while effective under AddressSanitizer, does not deterministically fail without ASan. He illustrates a second, independent bug: when the common prefix derived from positive pathspecs is incorrectly applied to a negative pathspec of sufficient length, the matching logic produces false positives. Using a minimal reproduction (`git ls-files a/b ':!x/b' a/c`), he shows that the current `master` branch incorrectly excludes `a/b/m` because the prefix-stripped negative pathspec `b` (from `:!x/b`) incorrectly matches the prefix-stripped path `b/m`. This scenario is distinct from the heap-buffer-overflow and demonstrates that the fix restores both memory safety and logical correctness. Junio’s example provides a clear, deterministic test case that could be added to the test suite. The discussion remains focused on test coverage and does not reopen the design or implementation of the fix itself.
