This is a review exchange in the ongoing bugfix series for Git's pathspec handling. Junio C Hamano (the maintainer) replies to Elijah Newren's proposed alternative commit message for the second patch in Yannik Tausch's series, which fixes how `common_prefix()` calculates the shared directory prefix when exclude pathspecs appear first.

Junio clarifies that the patch does *not* restore a lost optimization, contrary to Elijah's framing. The function `common_prefix_len()` has always correctly ignored exclude pathspecs when computing the prefix length; the bug lies in `common_prefix()`, which blindly used the first pathspec's string (even if it was an exclude) as the prefix string. For example, with pathspecs `":!x/b" "a/b" "a/c"`, the length was correctly computed as 2 (for `"a/"`), but the string returned was `"!x"` instead of `"a/"`. This mismatch caused downstream code (like `overlay_tree_on_index()` in `git ls-files --with-tree`) to operate on the wrong prefix, though the exact user-visible impact remains unclear.

The patch fixes this by tracking the first *non-exclude* pathspec and returning its string alongside the prefix length. Junio emphasizes that the change is narrower than Elijah's commit message suggests: it doesn’t affect traversal performance (since `common_prefix_len()` already worked correctly) but ensures the prefix string matches the computed length. The discussion is purely about commit message accuracy—no code changes are requested or needed. The series remains queued for merging, with this feedback serving to sharpen the historical context for future readers.
