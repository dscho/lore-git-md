This is the sixth patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology around "ref storage" instead of the inconsistent "ref format" phrasing. The series is part of a broader effort to clean up naming ahead of the upcoming object storage extension and the planned switch to reftable as the default backend in Git 3.0.

This patch updates the build-info output (`git version --build-options`) to rename the `default-ref-format` field to `default-ref-storage`, matching the new terminology introduced in earlier patches. The change is minimal—just two lines in `help.c` and one test adjustment in `t/t0001-init.sh`—but it closes the last remaining gap where the old terminology was still exposed to users. The test update ensures that the new field name is correctly parsed and compared against the repository’s actual ref storage setting.

The motivation is straightforward: consistency. The commit message notes that this is the only place left where Git still refers to "ref format," and the rename aligns it with the rest of the series. There’s no functional change—just a label update—but it’s a necessary step for clarity, especially as the project prepares for Git 3.0’s default backend switch.

Given the series’ scope and Patrick’s role as the primary driver of the reftable and ODB abstraction efforts, this patch is unlikely to be controversial. Reviewers may check for any overlooked instances of the old terminology, but the change itself is mechanical and well-justified. The patch is part of a larger, well-structured cleanup, and the test coverage ensures the new field name works as expected.
