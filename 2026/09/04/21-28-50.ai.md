This is the second patch in Karthik Nayak’s four-patch series introducing the `receive-report` hook for `git-receive-pack`. It refactors the static variables `report_status` and `report_status_v2` into a new `enum report_status_version`, making the protocol-version tracking more explicit and extensible. The patch is a targeted refactoring that prepares the codebase for the hook’s introduction in patch 4/4 by eliminating redundant state tracking.

The change replaces two boolean flags with a single enum that can take three values: `REPORT_STATUS_UNKNOWN` (a sentinel value that triggers a `BUG()` if neither v0 nor v2 is set), `REPORT_STATUS_V0`, and `REPORT_STATUS_V2`. The enum is passed by reference through the call chain, starting in `cmd_receive_pack()` and propagating to `read_head_info()`, where the client’s feature requests are parsed. The `if/else` chain that previously dispatched to `report()` or `report_v2()` is now a `switch` statement, addressing Patrick Steinhardt’s subjective preference for this style in his v6 review.

The patch touches only `builtin/receive-pack.c` and is purely internal: no user-visible behavior changes, no new configuration, and no test coverage (the existing tests in `t/t5412-receive-report-hook.sh` implicitly validate the refactoring). The commit message credits Junio C Hamano for the `Helped-by`, likely reflecting his earlier maintainability concern about the `detailed_reports` boolean parameter that this patch resolves. The sentinel value (`REPORT_STATUS_UNKNOWN`) is a defensive programming measure that ensures the enum is always initialized to a valid state.

This patch is uncontroversial and ready for integration. It is a prerequisite for the core hook implementation in patch 4/4, where the unified `report()` helper (introduced in patch 3/4) will use the enum to dispatch the correct protocol version. The series as a whole remains queued in `seen` and is feature-complete.
