This is the first patch in the v2 series that refactors config-parameter handling to support deferring auto maintenance in sequencer operations. It introduces `git_config_append_parameter()`, a helper function that appends a single `key=value` pair to a `strbuf` in the format expected by `GIT_CONFIG_PARAMETERS`, with proper shell quoting. The existing `git_config_push_split_parameter()` is updated to use this helper, reducing code duplication.

The motivation is clear: the sequencer needs to build a `GIT_CONFIG_PARAMETERS` string to pass to child processes (like `git commit` or `git merge`) during rebase, cherry-pick, and revert operations, and this helper allows it to do so without duplicating the quoting logic. The implementation is straightforward, moving the core formatting logic into a reusable function while preserving the existing behavior. The new function is well-documented in the header, explaining its purpose and the handling of boolean entries (where `value` is `NULL`).

This patch is purely refactoring with no behavior change. It touches `config.c` and `config.h`, adding the new helper and updating the existing function to use it. The change is small and focused, addressing Phillip Wood’s feedback from v1 about factoring out reusable logic. The code looks clean and the commit message clearly explains the purpose. No test coverage is added here, as the functionality is exercised by the sequencer tests in later patches. This is a solid foundation for the series’ goal of deferring auto maintenance.
