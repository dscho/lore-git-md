This is the fourth patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology for "ref storage" (previously inconsistently called "ref format"). This patch specifically updates `git submodule` and its helper to use `--ref-storage=` instead of `--ref-format=`, while retaining the old option as a hidden backward-compatibility alias.

The changes are mechanical but slightly more involved than in earlier patches because the submodule codebase has multiple layers: the shell script (`git-submodule.sh`), the C helper (`builtin/submodule--helper.c`), and the documentation (`Documentation/git-submodule.adoc`). The patch updates all three, ensuring that both the CLI interface and internal variable names (`ref_storage_format`, `ref_storage`) use the new terminology. It also propagates the change to the `git clone` built-in when it invokes submodule operations. Test coverage is updated in `t/t7424-submodule-mixed-ref-formats.sh`, replacing all instances of `--ref-format=` with `--ref-storage=`.

The patch is well-scoped and follows the same pattern established in the earlier patches (e.g., `git init`, `git clone`). The backward-compatibility alias (`--ref-format=`) is preserved as a hidden option, which should mitigate disruption for scripts or users still using the old name. The commit message is clear and concise, and the diff is straightforward—primarily search-and-replace with minor adjustments for shell script variable names. No new edge cases or behavioral changes are introduced here; this is purely a terminology cleanup. Given the series’ goal of consistency ahead of the object storage extension, this patch is uncontroversial and likely to be merged as-is.
