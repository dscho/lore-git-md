This is the first patch in Patrick Steinhardt's 11-patch series to unify Git's terminology around "ref storage" (previously inconsistently called "ref format"). It focuses on the `git init` command, renaming the `--ref-format=` option to `--ref-storage=` and adding a hidden backward-compatibility alias (`--ref-format=`) that maps to the new option. The patch also updates all related documentation (man pages, config documentation, and Git's main documentation) and adjusts 14 test scripts to use the new option name.

The change is mechanical: every instance of `--ref-format=` in help text, error messages, and test invocations is replaced with `--ref-storage=`, and the internal variable `ref_format` is renamed to `ref_storage`. The backward-compatibility alias ensures scripts or users still using the old option name will not break. The patch touches 15 files, primarily test scripts and documentation, with the core logic change in `builtin/init-db.c`.

This is a straightforward refactoring with no behavioral changes. The motivation—consistency ahead of the upcoming object storage extension—is clear, and the implementation is careful to maintain backward compatibility. Reviewers are likely to focus on whether the alias is sufficient for all edge cases (e.g., scripts that parse help output or error messages) and whether any references to the old terminology were missed. The patch is well-scoped for its position in the series and sets the stage for the subsequent patches that will rename environment variables and config keys.
