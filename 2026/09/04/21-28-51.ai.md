This is the third patch in Karthik Nayak’s four-patch series introducing the `receive-report` hook for `git-receive-pack`. It refactors the status-report generation logic into a reusable `generate_report()` helper, unifying the previously separate `report()` and `report_v2()` functions. The patch is purely internal and does not change user-visible behavior, but it prepares the codebase for the upcoming hook implementation by centralizing the report-generation logic.

The refactoring extracts the common pkt-line formatting logic from `report()` and `report_v2()` into a new `generate_report()` function, which takes an `enum report_status_version` parameter to handle protocol-version differences. The `report()` function is now a thin wrapper around `generate_report()`, passing the version-specific details to the helper. This eliminates redundancy and makes the code more maintainable, addressing Patrick Steinhardt’s substantive review feedback from v6.

The patch touches only `builtin/receive-pack.c` and is a straightforward mechanical change. The `generate_report()` helper handles both v0 and v2 protocol versions, with the latter including additional per-ref details (e.g., `option refname`, `option old-oid`). The `report()` function now delegates to `generate_report()` and retains its sideband-handling logic. The `report_v2()` function is removed entirely, as its functionality is now covered by the unified helper.

This refactoring is a prerequisite for the next patch, which introduces the `receive-report` hook. The hook will reuse `generate_report()` to produce the initial status report, which it then passes to the hook for potential modification. The patch includes a `Helped-by` credit to Patrick Steinhardt for identifying the refactoring opportunity.

No test coverage is added or modified, as the patch does not change behavior. The series remains queued in `seen` and is ready for integration into `next`.
