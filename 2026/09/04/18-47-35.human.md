This is the final patch in Erik Cervin-Edin’s two-part series extending `git commit --fixup` to support non-interactive message specification. The patch adds `-c`/`--edit` and `-C`/`--reuse-message` support for `--fixup=amend:` and `--fixup=reword:`, completing the feature matrix that already includes `-m` and `-F` from the first patch.

The implementation is clean and well-tested, with all prior feedback incorporated. Junio Hamano’s review flagged a minor code hygiene issue: the patch removes `--fixup` from one compatibility check (`die_for_incompatible_opt3`) but leaves a redundant check in place (`die_for_incompatible_opt4`), which already covers the same combinations. Erik acknowledges this and plans to address it after returning from travel. This is a trivial cleanup, not a functional concern.

The series as a whole is production-ready. It maintains backward compatibility (the editor still launches when no message option is provided) and handles edge cases like stripping “amend!” lines when reusing messages. Erik reports dogfooding the feature for months with good results. Junio is actively soliciting final review, and the only remaining question is whether to tidy the redundant check before merging. For anyone interested in interactive rebase workflows, this is a small but useful quality-of-life improvement.
