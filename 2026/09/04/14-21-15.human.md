This is a **maintainer follow-up** in the thread fixing a memory-safety bug and edge case in Git’s pathspec handling. Junio C Hamano endorses Elijah Newren’s suggestion to add a deterministic regression test for the heap-buffer-overflow bug, even when AddressSanitizer is not in use. He demonstrates that the bug has a second, more fundamental consequence: when a negative pathspec is longer than the common prefix derived from positive pathspecs, stripping that prefix still produces incorrect matching results. Using a minimal reproduction script, Junio shows that the current `master` branch incorrectly excludes `a/b/m` when the pathspec is `a/b :!x/b a/c`, while the fixed version (on the `jch` integration branch) correctly includes it. This confirms that the bug is not just a memory-safety issue but also a logical error in pathspec matching, and that a deterministic test case is both feasible and valuable. The discussion remains focused on test coverage and does not revisit the patch’s design or readiness; the series is still queued for merging.
