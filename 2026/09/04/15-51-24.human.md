This is a refactoring patch that extracts a helper function for building `GIT_CONFIG_PARAMETERS` strings. It is the first patch in the v2 series "sequencer: defer auto maintenance until rebase completion," which aims to make auto maintenance run only once at the end of sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`) rather than during intermediate steps.

The patch introduces `git_config_append_parameter()`, a function that appends a single `key=value` pair to a `strbuf`, properly quoting both key and value so they can be parsed by `git_config_from_parameters()`. This helper is factored out of the existing `git_config_push_split_parameter()` function, which now uses it internally. The change is mechanical and does not alter behavior; it simply makes the logic reusable for the sequencer, which will use it to construct the environment variable that disables auto maintenance for spawned commands.

The commit message is clear and explains the motivation: the sequencer needs to build a `GIT_CONFIG_PARAMETERS` string without knowing the quoting rules, and this helper encapsulates that knowledge. The code itself is straightforward and well-contained, touching only `config.c` and `config.h`. This looks like a clean, uncontroversial refactoring that supports the larger goal of the series.
