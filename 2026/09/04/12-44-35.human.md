This is a documentation patch, the second part of a two-patch series that began as a test-and-doc pair. The author has dropped the test patch (part 1) after reviewers questioned its necessity and design, keeping only this clarification of the existing `--no-commit` behavior in `git-cherry-pick.adoc`.

The patch adds two small but important notes: one in the bullet-point list of what happens on conflict (clarifying that `CHERRY_PICK_HEAD` is *not* set when `--no-commit` is used), and a new paragraph under the `--no-commit` option itself explaining that a plain `git commit` afterward will record the current user as the author rather than the original commit’s author. The documentation now explicitly tells users to use `git commit -c <commit>` if they want to preserve the original authorship and log message when picking a single commit.

The motivation is clear: the asymmetry with `git revert --no-commit` (which *does* write `REVERT_HEAD`) has confused users, and the current man page could be read as implying `CHERRY_PICK_HEAD` is always set. The patch simply documents the long-standing, intentional behavior introduced in 2011 (commit d7e5c0cbfb). No code changes are proposed, and the patch is uncontroversial—it merely makes the existing design visible to users. If the series lands, this will be a straightforward improvement to the man page.
