This is patch 9/11 in Patrick Steinhardt’s v1 series unifying Git’s reference storage terminology. It renames the environment variables `GIT_REFERENCE_BACKEND` and `GIT_DEFAULT_REF_FORMAT` to `GIT_REF_STORAGE` and `GIT_DEFAULT_REF_STORAGE`, respectively, while retaining the old names as backward-compatible aliases. The patch touches `setup.c`, documentation, and six test scripts (`t/t0001-init.sh`, `t/t1419-exclude-refs.sh`, `t/t1423-ref-backend.sh`, `t/t7424-submodule-mixed-ref-formats.sh`, and `t/test-lib.sh`), updating all references to the old variables and adjusting error messages and test logic accordingly.

The changes are mechanical: every occurrence of the old variable names is replaced, and the precedence logic in `setup.c` is updated to check both the new and old environment variables. The test scripts are updated to reflect the new variable names, including in error messages and BUG assertions. The patch also adds the new `GIT_REF_STORAGE` macro to `environment.h` for consistency. No functional changes are introduced beyond the renaming and aliasing, and the backward-compatibility layer ensures that scripts or tools relying on the old variable names continue to work. This is a straightforward but necessary step in the broader effort to standardize terminology ahead of the upcoming object storage extension.
