This is a follow-up in the thread fixing a long-standing bug in Git’s pathspec handling. The series is already queued for merging, but Elijah Newren and Junio C Hamano are clarifying a subtle point about the exact nature of the bug and how the fix works.

The discussion centers on the second patch in the series, which corrects what `common_prefix()` returns when an exclude pathspec (like `:!x/b`) appears first in the list. Before the fix, the function would return a zero-length prefix, which caused Git to traverse from the root unnecessarily. The fix ensures that `common_prefix()` returns the correct common directory (e.g., `a/` from `a/b` and `a/c`) even when the first pathspec is an exclude item.

Elijah initially thought the patch was restoring a performance optimization (avoiding root traversal), but Junio clarified that the optimization was already present—the bug was purely about the incorrect string returned by `common_prefix()`. The string is used by distant callers like `overlay_tree_on_index()` in `git ls-files --with-tree`, where its effect is unclear but clearly unintended. The fix tracks the first non-exclude item and returns its match string alongside the prefix length, ensuring correctness without changing which paths are selected or traversed.

The exchange is purely editorial and does not affect the patch’s readiness. The series remains queued in Junio’s tree, and no further changes are expected. This clarification helps future readers understand the bug’s scope and the fix’s intent, but it does not introduce new technical concerns.
