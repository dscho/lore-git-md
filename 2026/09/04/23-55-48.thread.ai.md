Key technical details
- **ODB abstraction**: Patrick Steinhardt’s ps/odb-* series (13, 8, and 10 patches respectively) remove ad-hoc APIs for in-memory alternate object sources, defer alternates setup to ODB creation time, and move fsck checks into backend-specific layers, enabling pluggable object storage formats.
- **Line-log and diff improvements**: mm/line-log-limited-ops (7 patches) teaches `git log -L<range>:<path>` to limit `--stat`, `--check`, and `-G` to the specified range; mm/diff-process-hunks (11 patches) introduces `diff.<driver>.process` to allow external tools to act as hunk providers.
- **Hooks and server-side features**: kn/receive-report-hook (4 patches) introduces a new `receive-report` hook for server-side filtering of packet-line status reports.
- **Memory safety**: jk/rev-info-argv-to-free (2 patches) fixes memory ownership in the revision machinery; ds/trace2-tolerate-failed-timestamp improves robustness.
- **Performance**: tc/last-modified-bloom (6 patches) optimizes `git last-modified` with Bloom filters; ps/tune-rerere-gc (2 patches) adjusts `rerere gc` heuristics to avoid interference with `git rebase`; dk/use-nsec-runtime (3 patches) converts the build-time `USE_NSEC` knob into a runtime `core.useNanosec` configuration, exposing a Meson build knob for xmlto relative links and touching `core/` and `environment.c`.
- **Documentation**: kh/doc-datamodel (4 patches) adds cross-references from `git(1)` and `glossary(7)` to the new `gitdatamodel(7)` tutorial, improving discoverability of the data model documentation. No new behavior or code is introduced; changes are limited to the `Documentation/` directory.
- **Retracted series**: kh/format-patch-range-diff-notes (3 patches) introduced `--[no-]range-diff-notes` to `git format-patch`, allowing separate configuration of notes for range-diff output. The series included preparatory refactoring: renaming a struct member in `revision.h` (likely `notes_opt` -> `range_diff_notes_opt`) and simplifying the `get_notes_arg` parameter list. The retraction was due to documentation clarity concerns, not technical objections.
