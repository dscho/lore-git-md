This is a review comment from Junio C Hamano on the final patch of Thomas Bachem’s v2 series that defers auto maintenance until sequencer operations (`rebase`, `cherry-pick`, `revert`) complete. The series is otherwise technically complete and addresses all prior feedback from Phillip Wood and Patrick Steinhardt.

Junio’s comment is narrowly focused on the implementation detail of how the `GIT_CONFIG_PARAMETERS` string is stored in the `replay_ctx` struct. The patch currently uses a `struct strbuf` field, but Junio suggests switching to a `const char *` instead. His rationale is that the string, once built in `disable_auto_maintenance()`, never changes, so a pointer better expresses the immutability and avoids the overhead of a dynamic buffer. He provides a sketch of how the helper function would look with this change: initialize a local `strbuf`, build the string, detach it into the `const char *` field, and free the temporary buffer.

The comment is surface-level — it does not question the overall design, test coverage, or edge cases, but rather a single line of code and its type. It is a minor stylistic suggestion that would make the intent clearer without affecting functionality. The author can address it with a one-line change to the struct definition and a small adjustment to the helper function.
