This is the second patch in Yannik Tausch’s three-patch bugfix series for pathspec handling, now queued for merging. Elijah Newren replies to the v2 iteration of this patch (the core fix) with a proposed alternative commit message that more clearly explains the optimization being restored: when an exclude pathspec appears first, `common_prefix_len()` currently returns zero, forcing Git to traverse from the root even if all non-exclude items share a directory. The new message frames the change as preserving the intended optimization rather than merely fixing a logic error.

The code itself is unchanged from v2 and remains technically sound. It implements Junio’s output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`), tracks the first non-exclude item explicitly, and returns its match string so that `common_prefix()` and `fill_directory()` use the correct base. The unit test added in this patch covers the edge case of an unrelated exclude item followed by two non-exclude items sharing a directory (`foo/`).

Elijah’s feedback is purely editorial—he does not request code changes, identify bugs, or question the design. His proposed commit message is more explicit about the performance impact and the intent to restore an optimization, which could help future readers understand the change’s purpose. The patch is otherwise ready for integration, and the series as a whole is queued in Junio’s tree with a synthetic merge base.
