Thread identity
Subject: [PATCH 0/2] Modernize test scripts: replace `test -f` with `test_path_is_file`
Series version: v1 (initial submission; now rejected in current form)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (test modernization)

Core problem or goal
Replace older shell test idioms (`test -f`, `! test -f`, `test -d`) with more semantic helper functions (`test_path_is_file`, `test_path_is_missing`, `test_path_is_dir`) in 63 test scripts under `t/`. The goal is syntactic modernization, aligning with the project’s test guidelines; no behavioral changes or performance improvements are intended.

Current status
Rejected in its current form. Junio C Hamano reviewed the first patch and found that the mechanical replacement of `test -f` with `test_path_is_file` is incorrect when the test is used in control-flow logic (e.g., checking for platform-specific files like `/proc/$shell_pid/winpid`). The helper functions are designed for assertions, not silent conditionals. The series is now blocked until the approach is rethought. No integration status; no prior versions.

Key technical details
- Files touched: 63 test scripts in `t/` (exact list recoverable from the patches).
- New symbols: `test_path_is_file`, `test_path_is_missing`, `test_path_is_dir`, and related `test_path_is_*` helpers.
- Old-vs-new behavior: the patch as submitted would change silent conditionals into loud assertion failures, altering test semantics.
- Specific example: `t/t0031-lockfile-pid.sh` checks `/proc/$shell_pid/winpid` only on MINGW; the conversion would turn this into an error message on non-MINGW platforms.
- Base commit: `2c3adbb2c475981e340c79fdc5e7f4f9b5d9054e`.
- Change ID: `20260904-file-tests-use-shell-functions-e0d6c545d56c`.

Open questions and loose ends
- How to distinguish between `test -f` used for assertions (where `test_path_is_file` is appropriate) and `test -f` used for control flow (where it is not).
- Whether the series should be split into smaller, targeted patches that address only assertion contexts.
- The author has not yet responded to the rejection or indicated next steps.

Participant positions
- Junio C Hamano: rejects the patch as submitted, citing incorrect conversions in control-flow contexts. Emphasizes that each `test -f` must be analyzed for its semantic purpose. Notes the absence of a Signed-off-by trailer as a secondary issue.

Related work
Part of the ongoing community-wide test modernization effort (e.g., `! test -f` → `test_path_is_missing`, `test -f` → `test_path_is_file`). No dependencies on other in-flight topics.
