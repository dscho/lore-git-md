This is the author's reply to Phillip Wood's substantive review of the v2 locking patch in the `rerere` race-condition series. The patch is part of a two-part bugfix targeting a deadlock introduced in Git 2.54, where background maintenance (`git rerere gc`) races with an in-progress rebase to acquire the `MERGE_RR.lock`.

Thomas Bachem clarifies a key technical point: the `MERGE_RR` lock is per-worktree, so writers in different worktrees don’t contend for it directly. The shared resource is the `rr-cache`, which background maintenance prunes under its own lock. This distinction refines the problem’s scope—it’s not cross-worktree contention but rather any `git rerere gc` (from `git gc`, maintenance runs, or auto-maintenance) racing with conflict recording. The v3 commit message now reflects this more precisely.

He addresses Phillip’s feedback directly: the `git rerere`, `git rerere forget`, and `git rerere clear` commands now wait for the full timeout before failing (rather than failing immediately), aligning with their purpose of requiring rerere access. A `BUG()` assertion was added to catch incompatible flag combinations (`RERERE_NOWAIT` with `RERERE_LOCK_OR_DIE`, and `RERERE_READONLY` with either). The commit message has been trimmed significantly for clarity.

On user experience, Thomas explains that background maintenance runs are daemonized, closing standard descriptors and redirecting output to `/dev/null`, so warnings from `rerere gc` don’t mix with foreground output. On Windows, where daemonization isn’t possible, maintenance runs in the foreground of the triggering commit, avoiding the race entirely. The visible warning comes from the foreground command (e.g., rebase) when it gives up waiting, not from the background task.

The patch is now more robust and better documented, with all of Phillip’s technical suggestions incorporated. The unresolved design questions—whether garbage collection is useful mid-rebase, and whether the fork-based maintenance model is suitable for interactive workflows—remain outside this patch’s scope. The series is ready for final review, with the sequencer config-override patch (disabling maintenance during rebase) still pending.
