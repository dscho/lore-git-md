This thread is about Patrick Steinhardt’s 11-patch series to unify Git’s terminology around "ref storage," replacing inconsistent terms like "ref format" and "reference backend" across CLI options, environment variables, config keys, and documentation. The goal is to prepare for an analogous "object storage" extension and to fix a bug where reinitializing a repository with a different ref storage format silently corrupts it.

The series is under review in its first version. It introduces `--ref-storage=` as the new CLI option (replacing `--ref-format=`), updates environment variables (`GIT_REF_STORAGE` replacing `GIT_REFERENCE_BACKEND`), and renames the config key `init.defaultRefStorage` (from `init.defaultRefFormat`). Backward-compatible aliases are retained for all three. The series also centralizes URI parsing for ref storage backends, allowing `--ref-storage=` to accept URIs like `files://path/to/repo` with payloads, and enforces immutability of the existing repository format to prevent silent corruption.

Karthik Nayak, a frequent collaborator on ref backend work, reviewed the first patch and raised a minor but important consistency issue: the `argh` value (placeholder text in help output) for `--ref-storage=` still uses `"format"` instead of `"ref-storage"`, which could confuse users or tools parsing help text. This feedback is actionable and aligns with the series’ goal of consistency. No other reviews or objections have been posted yet, and the series remains in its initial review phase. Open questions include URI handling edge cases and the impact of immutability enforcement on existing workflows.
