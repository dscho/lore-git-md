This thread is about Patrick Steinhardt’s 11-patch series to unify Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent terms like `--ref-format=` and `init.defaultRefFormat` with `--ref-storage=` and `init.defaultRefStorage`, while also centralizing URI parsing for ref backends and fixing a bug where reinitializing a repository with a different format could silently corrupt it. The series is part of a broader effort to prepare for an upcoming "object storage" extension.

The patches touch nearly every part of Git that deals with ref storage: CLI tools (`git init`, `git clone`, `git refs`, `git submodule`), environment variables (`GIT_REF_STORAGE`, `GIT_DEFAULT_REF_STORAGE`), config keys (`init.defaultRefStorage`), build-info output, and documentation. A key technical change is the introduction of URI support for `--ref-storage=`, allowing payloads like `files://path/to/alt-refs` to specify alternative directories for the "files" backend. The series also enforces immutability of the ref storage format once set, preventing the corruption bug.

Karthik Nayak’s review is positive, calling the series "relatively quite an easy read" despite its length. He raises two minor nits: the help text for `--ref-storage=` still shows `<format>` instead of `<ref-storage>`, and a missing macro in `environment.h`. Neither is a functional issue, and both are straightforward to fix. No substantive objections or edge cases were raised, suggesting the series is on track for merging after these small tweaks. The only open questions are about backward compatibility for tools parsing help text or error messages, but the series already retains backward-compatible aliases for the old option names, environment variables, and config keys.
