This thread is about Patrick Steinhardt’s 11-patch series to standardize Git’s terminology around “ref storage,” replacing the inconsistent “ref format” phrasing currently used in CLI options, environment variables, and documentation. The goal is to pave the way for a future “object storage” extension by making the naming consistent and introducing URI support for reference backends.

The first patch, which just arrived, focuses on `git init`. It renames the `--ref-format=` option to `--ref-storage=` and adds a hidden backward-compatibility alias so existing scripts won’t break. The change is purely mechanical—every mention of “ref format” in help text, error messages, and tests is updated—with no behavioral changes. So far, the series is under review with no feedback yet; reviewers will likely focus on whether the alias covers all edge cases and whether any old terminology was missed.

The full series will touch 39 files across built-ins, documentation, and tests, centralizing URI parsing for reference backends and enabling `--ref-storage=` to accept URIs like `files://path/to/repo`. No on-disk format changes are involved, but the series does update `BreakingChanges.adoc` to document the intentional CLI and environment variable changes. The main open questions are around URI handling edge cases and backward compatibility for scripts or third-party tools that might rely on the old names.
