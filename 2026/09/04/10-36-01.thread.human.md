This thread is a cleanup series from Patrick Steinhardt that aims to unify Git’s terminology for "ref storage" across the codebase, CLI options, environment variables, and documentation. The series, now at v1 with 11 patches, renames `--ref-format=` to `--ref-storage=` (while retaining backward-compatible aliases in key commands like `git init`, `git clone`, and `git submodule`), updates environment variables (`GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE`), and prepares for future work like the object storage extension. The latest patch (6/11) updates the `git version --build-options` output to reflect the new terminology, ensuring consistency in how Git reports its configuration.

The series is under active review, with no prior versions or merge status reported. Key changes so far include updates to 31 test scripts, shell completions, and documentation, as well as a new `parse_ref_storage_uri()` function to handle URI-based backend selection. Open questions remain about backward compatibility, particularly for scripts relying on old environment variables or config keys, and edge cases in URI handling. So far, only Patrick has weighed in, and no substantive review feedback has been incorporated yet. The work is foundational for Patrick’s broader efforts on the reftable backend and ODB abstraction.
