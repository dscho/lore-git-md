This thread is a cleanup and refactoring series from Patrick Steinhardt that unifies Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The series, now at v1 with 11 patches, replaces inconsistent terms like `--ref-format=` and `GIT_REFERENCE_BACKEND` with `--ref-storage=` and `GIT_REF_STORAGE`, while retaining backward-compatible aliases. The final patch (11) extends the `--ref-storage=` option to accept URIs (e.g., `files://path/to/alt-refs`), enabling richer configuration at initialization time and matching the existing capabilities of the `extensions.refStorage` config key and `GIT_REF_STORAGE` environment variable.

The series is under active review, with no prior versions or merge status reported. Key changes include renaming CLI options, environment variables, and config keys; centralizing URI parsing logic; and enforcing immutability of the existing repository format to prevent silent corruption during reinitialization. The patches touch a wide range of files, including built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), documentation, shell completions, and 39 test scripts. The series also fixes a bug where reinitializing a repository with a different ref storage format could corrupt it.

Patrick’s motivation is to prepare for an analogous "object storage" extension, and the series is well-tested, with thorough coverage for URI payload handling and error cases. Open questions remain about URI edge cases (e.g., malformed URIs) and the impact of immutability enforcement on existing workflows, but the series is mechanically sound and ready for review feedback.
