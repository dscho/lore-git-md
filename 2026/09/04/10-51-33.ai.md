This is a reply in the `git repack --drop-filtered` series, specifically addressing Samuel Bronson’s usability concern about the index validation guard in patch 6/6. The author (Siddharth Shrimali) agrees with Bronson’s proposal to change the fatal error into a warning that skips index-referenced blobs, acknowledging that aborting after a full `enumerate_promisor_blobs()` walk is a poor user experience. The discussion now focuses on implementation details: Shrimali notes that `oidset_remove()` would mutate the `drop_oids` set in place, which would break `--dry-run` output (it should still report skipped blobs as candidates). The solution is to collect index-referenced OIDs into a separate "skip-set" that both the dry-run printer and the real drop logic consult, preserving the original `drop_oids` for reporting. The author also flags a follow-up consideration: the planned drop-log must not record skipped blobs as dropped. No test updates or `--filter=blob:none` support are included yet, but the direction is clear—this change will likely land in v6, resolving the last substantive feedback before the series is marked for `next`.
