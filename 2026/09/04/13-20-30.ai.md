This is patch 9/11 in Patrick Steinhardt’s v1 series to unify Git’s reference storage terminology. The patch renames the environment variables `GIT_REFERENCE_BACKEND` and `GIT_DEFAULT_REF_FORMAT` to `GIT_REF_STORAGE` and `GIT_DEFAULT_REF_STORAGE`, respectively, while retaining the old names as backward-compatible aliases. Karthik Nayak’s review is **surface-level**: he notes that the patch omits the corresponding `GIT_DEFAULT_REF_STORAGE_ENVIRONMENT` macro in `environment.h`, which would be needed for consistency with the rest of the codebase. The rest of the changes—documentation updates, test script adjustments, and the backward-compatibility layer—are uncontroversial and mechanically correct.

The patch itself is a straightforward but necessary step in the series, touching `setup.c`, documentation, and six test scripts. It updates all references to the old variables, adjusts error messages, and ensures the new variables are checked alongside the old ones for backward compatibility. The omission of the `GIT_DEFAULT_REF_STORAGE_ENVIRONMENT` macro is the only identified issue, and it’s a minor oversight that doesn’t affect functionality. The broader series aims to standardize terminology ahead of an upcoming object storage extension, and this patch aligns environment variables with the new `--ref-storage=` CLI option introduced earlier in the series.

No functional changes are introduced beyond the renaming, and the backward-compatibility layer ensures scripts or tools relying on the old variable names continue to work. The patch is part of a well-motivated refactoring effort, and the review feedback is narrowly scoped to a single missing macro. The series as a whole is under active review, with no prior versions, and this patch is unlikely to be a point of contention.
