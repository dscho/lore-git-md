This is the third patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The series is now in its seventh iteration and is queued in `seen`, with all prior feedback addressed.

This patch refactors the status-report generation logic in `builtin/receive-pack.c` by extracting it into a reusable `generate_report()` helper. Previously, the code had two nearly identical functions, `report()` and `report_v2()`, which differed only in whether they included detailed per-ref update information (v2 protocol). The new helper unifies them, taking an `enum report_status_version` parameter to control the output format. This change eliminates redundancy and prepares the codebase for the upcoming `receive-report` hook, which will reuse this logic to generate the status report it receives on stdin.

The patch is a clean refactoring with no user-visible behavior changes. It replaces the two static functions with a single helper, updates the `report()` function to call it, and removes the now-unused `report_v2()`.
