This is the second patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology around "ref storage" instead of the inconsistent "ref format." It updates the `git clone` command to rename the `--ref-format=` option to `--ref-storage=`, while keeping the old name as a hidden backward-compatibility alias.

The change is mechanical: the patch touches the `git-clone` man page, the `builtin/clone.c` implementation, and five test scripts that exercise the option. The new `--ref-storage=` option behaves identically to the old `--ref-format=`, so no functional changes are introduced—only the name and help text are updated. The backward-compatibility alias ensures scripts using the old name continue to work, though users will see the new name in help output and error messages.

This patch is a straightforward part of the larger cleanup effort described in the cover letter. The motivation is clear: eliminating inconsistent terminology before introducing an analogous "object storage" extension. Given Patrick’s role as the primary driver of the reftable backend and ODB abstraction efforts, the direction is unlikely to be controversial, though reviewers may check for overlooked references in less common code paths (e.g., shell completions or third-party integrations). The updated tests suggest good coverage of the affected areas.
