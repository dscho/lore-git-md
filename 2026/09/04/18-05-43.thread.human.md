This thread began when Ramkumar Ramachandra reported three seemingly unrelated regressions in Git 2.55.0 on macOS—`git pull` failing with "dangling remote ref," `git diff` exiting silently despite a dirty worktree, and `git checkout -` erroring with "invalid ref"—all isolated to the massive `llvm/llvm-project.git` repository. Initial suspicion fell on Git itself, particularly the ref backend or race conditions tied to repository scale. However, after thorough investigation, Ramkumar identified the root cause as interference from CrowdStrike Falcon security software. The real-time file scanning in Falcon races against Git’s high-frequency operations—ref updates, worktree changes, and network fetches—triggering the observed failures in large, rapidly changing repositories like LLVM. The thread is now closed, with no action required from the Git project. Ben Knoble’s earlier observation that smaller repositories or different Git builds (e.g., self-compiled from `next`) didn’t exhibit the same symptoms aligns with this explanation, highlighting how repository size and update frequency can exacerbate the issue.
