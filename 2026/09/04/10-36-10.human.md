This is the ninth patch in Patrick Steinhardt’s 11-patch series to unify Git’s terminology for "ref storage" across CLI options, environment variables, and documentation. This specific patch renames the environment variables `GIT_REFERENCE_BACKEND` and `GIT_DEFAULT_REF_FORMAT` to `GIT_REF_STORAGE` and `GIT_DEFAULT_REF_STORAGE`, respectively, while retaining the old names as aliases for backward compatibility.

The changes are mechanical but thorough: the patch updates `setup.c` to check both the new and old environment variables, ensuring precedence rules remain consistent (command-line options override environment variables, which override config settings). It also updates documentation (`git.adoc`, `init.adoc`), test scripts (`t0001-init.sh`, `t1419-exclude-refs.sh`, `t1423-ref-backend.sh`, `t7424-submodule-mixed-ref-formats.sh`), and test infrastructure (`test-lib.sh`) to reflect the new variable names. The test updates are particularly detailed, covering edge cases like invalid formats, reinitialization attempts, and submodule interactions.

The motivation is clear: the old names were inconsistent with the new `--ref-storage=` CLI option introduced earlier in the series, and this patch aligns the environment variables with the broader terminology cleanup. The backward-compatibility aliases should mitigate disruption, though third-party scripts or tools relying on the old variable names may need updates. The patch is well-scoped and appears uncontroversial, though reviewers may scrutinize the test coverage for edge cases (e.g., malformed URIs or interactions with submodules). No functional changes are introduced—this is purely a refactoring and consistency fix.
