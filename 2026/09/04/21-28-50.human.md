This is the second patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. It is a refactoring patch that replaces two static boolean variables (`report_status` and `report_status_v2`) with a single `enum report_status_version`, making the code more explicit and easier to extend.

The patch drops the static variables and introduces an enum with three values: `REPORT_STATUS_UNKNOWN`, `REPORT_STATUS_V0`, and `REPORT_STATUS_V2`. The enum is passed by reference through the call chain, starting in `cmd_receive_pack()` and into `read_head_info()`, where the client’s advertised capabilities determine which version is set. A `switch` statement in `cmd_receive_pack()` now dispatches to the appropriate report function, replacing the previous `if/else` chain. The `REPORT_STATUS_UNKNOWN` sentinel triggers a `BUG()` if neither v0 nor v2 is set, ensuring the invariant is enforced at runtime.

This change addresses Junio C Hamano’s earlier maintainability concern about the boolean parameters and incorporates Patrick Steinhardt’s subjective preference for a `switch` statement over `if/else`. The patch is purely internal and does not alter behavior; it is a prerequisite for the later patches that introduce the `receive-report` hook. The commit message is concise and the diff is clean, touching only `builtin/receive-pack.c`. No test failures are expected, and the patch is already queued in `seen` alongside the rest of the series.
