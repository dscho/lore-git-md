Thread identity
Subject: [PATCH v1 00/11] refs: unify terminology for "ref storage"
Series version: v1
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/cleanup)

Core problem or goal
Git currently uses inconsistent terminology for the "ref storage format" across CLI options (`--ref-format=`), repository extensions (`refStorage`), environment variables (`GIT_REFERENCE_BACKEND`), build-info output, and documentation. This series renames all instances to "ref storage" for consistency, preparing for an analogous "object storage" extension. It also centralizes URI parsing for reference storage backends, enabling `--ref-storage=` to accept URIs like `files://path/to/repo`.

Current status
Under review (v1 posted). No prior versions. No merge status reported.

Key technical details
- CLI options:
  - `--ref-format=` → `--ref-storage=` (with backward-compatibility alias `--ref-format=` retained in `git init`, `git clone`, `git refs`, `git submodule`, and `git rev-parse`)
  - Files touched: `builtin/init-db.c`, `builtin/clone.c`, `builtin/refs.c`, `builtin/submodule--helper.c`, `builtin/rev-parse.c`, `git-submodule.sh`, `Documentation/git-*.adoc`, shell completions (`contrib/completion/git-prompt.sh`), and 31 test scripts (14 in patch 1, 6 in patch 2, 3 in patch 3, 1 in patch 4, 7 in patch 5, 1 in patch 6)
- Environment variables: `GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE`, `GIT_TEST_REFERENCE_BACKEND` → `GIT_TEST_REF_STORAGE` (addressed in later patches)
- Config key: `init.defaultRefFormat` → `init.defaultRefStorage` (addressed in later patches)
- Build-info output: `default-ref-format` → `default-ref-storage` (patch 6, `help.c` and `t/t0001-init.sh`)
- New function: `parse_ref_storage_uri()` in `refs.c`/`refs.h` (addressed in later patches)
- On-disk format: no changes
- Test coverage: updated across all affected areas (31 test scripts across patches 1–6)
- BreakingChanges.adoc: updated to document intentional breaking changes
- Symbols: `ref_format` → `ref_storage` (internal variables in `builtin/init-db.c`, `builtin/clone.c`, `builtin/refs.c`, `builtin/submodule--helper.c`, and `builtin/rev-parse.c`)
- Error messages: updated in `builtin/fetch.c` to use `--ref-storage=` terminology
- Submodule-specific: updates to `git-submodule.sh` and `builtin/submodule--helper.c` propagate the new terminology to submodule operations, including when `git clone` invokes submodule initialization
- Shell completions: updated in `contrib/completion/git-prompt.sh` to reflect the new option name

Open questions and loose ends
- URI handling edge cases (e.g., malformed URIs, unsupported schemes) (addressed in later patches)
- Backward compatibility concerns:
  - Sufficiency of backward-compatibility aliases for `--ref-format=` (now implemented in `git init`, `git clone`, `git refs`, `git submodule`, and `git rev-parse`)
  - Scripts relying on old environment variables or config keys (not yet addressed)
  - Parsing help output/error messages (e.g., third-party tools expecting specific wording in `git version --build-options`)
  - Potential for overlooked references in less common code paths (e.g., contrib/, third-party integrations, or submodule helper scripts not covered in this patch)
