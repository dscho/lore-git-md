Subject: [PATCH v1 00/11] refs: unify terminology for "ref storage"
Series version: v1
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/cleanup with functional fixes)

Core problem or goal
Git currently uses inconsistent terminology for the "ref storage format" across CLI options (`--ref-format=`), repository extensions (`refStorage`), environment variables (`GIT_REFERENCE_BACKEND`), config keys (`init.defaultRefFormat`), build-info output, and documentation. This series renames all instances to "ref storage" for consistency, preparing for an analogous "object storage" extension. It also centralizes URI parsing for reference storage backends, enabling `--ref-storage=` to accept URIs like `files://path/to/repo` with payloads (e.g., alternative directories for the "files" backend). Additionally, the series fixes a bug where reinitializing a repository with a different ref storage format silently corrupts the repository.

- Test coverage: updated across all affected areas (41 test scripts total; patch 11 adds 2 new tests in `t/t1423-ref-backend.sh` for URI payload handling and reinitialization with mismatched payloads)
- BreakingChanges.adoc: updated to document intentional breaking changes (e.g., immutability of existing repository format)

- Error messages: updated in `builtin/fetch.c`, `setup.c`, and test scripts to use `--ref-storage=` terminology and include full URIs in diagnostics; patch 8 adds new error messages for invalid formats and reinitialization attempts; patch 11 improves clarity for URI-related errors; **new detail**: Karthik Nayak notes pre-existing inconsistency in error messages (e.g., "unknown ref storage format" despite `--ref-format=` option name)
- Submodule-specific: updates to `git-submodule.sh` and `builtin/submodule--helper.c` propagate the new terminology and URI support to submodule operations
- Shell completions: updated in `contrib/completion/git-prompt.sh` to reflect the new option name
- Precedence rules: patch 8 reorders precedence so that `--ref-storage=` overrides environment variables, aligning with Git’s usual precedence rules; patch 9 ensures backward-compatible environment variable handling by checking both old and new names; patch 10 extends precedence rules to the config key, ensuring `--ref-storage=` overrides both environment variables and config
- Bug fix: patch 8 prevents silent corruption when reinitializing a repository with a different ref storage format by treating the existing format as immutable

Open questions and loose ends
- **New**: Inconsistency in help text placeholder (`argh`) for `--ref-storage=` in `builtin/init-db.c` (reported by Karthik Nayak): the placeholder uses `"format"` instead of `"ref-storage"`, leading to `--ref-storage=<format>` in help output. This could confuse users or tools parsing help text.
- URI handling edge cases (e.g., malformed URIs, unsupported schemes, or ambiguous payloads for backends other than "files" and "reftable")
- Backward compatibility concerns:
  - Sufficiency of backward-compatibility aliases for `--ref-format=`, environment variables, and config keys (now implemented for all three)
  - Scripts relying on old environment variables or config keys (old names are retained as aliases, but third-party tools may still break if they parse help output or error messages)
  - Parsing help output/error messages (e.g., third-party tools expecting specific wording in `git version --build-options` or `git init` diagnostics)
  - Potential for overlooked references in less common code paths (e.g., contrib/, third-party integrations, or submodule helper scripts not covered in this patch)
  - Impact of immutability enforcement on existing workflows (e.g., scripts or tools that reinitialize repositories with different formats)
- Documentation gaps: URI syntax is documented for "files" and "reftable" backends, but other backends (e.g., "packed") may need similar documentation if they support payloads in the future
