This is a refactoring and consistency cleanup series from Patrick Steinhardt, targeting Git’s reference storage format terminology. The series addresses a long-standing inconsistency in how Git refers to the backend used for storing references (e.g., reftable vs. traditional files-based refs). Currently, the command-line option is `--ref-format`, the repository extension is `refStorage`, and the environment variable is `GIT_REFERENCE_BACKEND`—none of which align with the documentation’s preferred term, "ref storage format."

The motivation is twofold: first, to clean up the existing mess before it gets worse, and second, to prepare for an upcoming "object storage" extension (analogous to the ref storage extension). Without this cleanup, introducing a new `--object-storage` option would clash with the existing `--object-format` (which controls the hash function, not storage), creating even more confusion. The series renames all CLI options, environment variables, and config keys to use "ref-storage" consistently, and extends the `--ref-storage` option to accept URIs (e.g., `files://path`), matching existing functionality elsewhere.

The patch touches 39 files across built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), documentation, tests, and core setup code. It’s a mechanical but far-reaching change, with most patches being straightforward renames. The series is well-motivated and clearly explained in the cover letter, and the timing—before the object storage work lands—makes sense. Given Patrick’s deep involvement in the ref backend and reftable work, this is a credible cleanup effort that’s likely to be uncontroversial in principle, though the sheer number of files touched may invite nitpicking on specific renames or test updates.

If you care about ref backends, repository initialization, or the upcoming object storage abstraction, this series is worth skimming, especially the setup.c refactoring (patch 8) and the URI parsing changes (patch 7). For everyone else, the takeaway is that `--ref-format` is now `--ref-storage`, and the environment variable is `GIT_REF_STORAGE` instead of `GIT_REFERENCE_BACKEND`.
