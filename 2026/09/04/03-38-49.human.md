This is the final patch in Christian Couder’s six-part series introducing `early_scan_options()`, a new `parse-options` sub-API designed to fix early argument-scanning bugs. This patch converts `git fast-import` to use the new API, addressing a real bug where `--allow-unsafe-features` was silently ignored when it appeared after an option with a separate value (e.g., `--depth 5 --allow-unsafe-features`).

Junio’s reply is brief but positive. He acknowledges the improvement: the old hand-rolled scan stopped at the first non-option argument (like `5` in `--depth 5`), missing `--allow-unsafe-features`, while the new API correctly skips option values and finds the flag. He also notes that the new implementation safely handles malformed input like `--depth hello`—the real `parse_options()` will catch the error later, so the early scan doesn’t need to validate values. The patch is well-executed, with clear documentation and thorough tests, and Junio’s feedback suggests no further changes are needed here.

The broader series, however, remains under active discussion. Junio has raised **substantive design concerns** about the new API’s long-term viability, questioning whether it replaces one set of fragile scans with another rather than addressing the root problem—a unified early-scan mechanism within `parse_options()` itself. He has also challenged the practical value of the `git bisect` and `git rev-parse` fixes, suggesting the series might be more compelling if it focused solely on the `git fast-import` bug. These issues will need to be resolved before the series can progress, but this patch itself looks ready.
