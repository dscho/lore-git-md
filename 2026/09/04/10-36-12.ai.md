This is the final patch in Patrick Steinhardt’s 11-patch series unifying Git’s reference storage terminology. Patch 11 extends the `--ref-storage=` option (introduced in earlier patches) to accept URIs with payloads, matching the existing capability of the `extensions.refStorage` config key and `GIT_REF_STORAGE` environment variable. For example, users can now run `git init --ref-storage=files://path/to/alt-refs` to initialize a repository with references stored in a non-default directory. The patch also documents the URI syntax for the "files" and "reftable" backends and updates the relevant code paths in `builtin/clone.c`, `builtin/init-db.c`, and `setup.c` to parse and pass the full URI rather than just the format name.

The change is a natural extension of the series’ goal: eliminating inconsistent terminology while enabling richer configuration at initialization time. The implementation is straightforward—replacing `ref_storage_format_by_name()` with `ref_storage_format_by_uri()` and propagating the URI string through the call chain—but the added test coverage in `t/t1423-ref-backend.sh` is thorough, verifying that payloads are correctly stored in the repository config, that reinitialization with mismatched payloads fails (preventing silent corruption), and that the refs are actually created in the specified directory. The patch also updates error messages to be more descriptive, now including the full URI in diagnostics.

This patch completes the series’ functional scope. Earlier patches renamed CLI options, environment variables, and config keys; this one enables the URI syntax that those options were designed to support. The only remaining loose ends are edge cases in URI parsing (e.g., malformed URIs or unsupported schemes), which are likely to be addressed in follow-up discussion or later patches. The series as a whole is well-motivated, mechanically sound, and thoroughly tested, making it a strong candidate for merging once review feedback is incorporated.
