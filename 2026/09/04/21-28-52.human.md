This is the final patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The series is now feature-complete, well-tested, and ready for integration into `next`.

The patch implements the core hook, which allows server administrators to intercept and modify the status report sent to clients after ref updates are committed but before the response is finalized. The hook receives the pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via sideband. A non-zero exit code discards the hook’s output and rewrites all ref status lines to `"receive-report hook failed"`, effectively treating the push as failed—though server-side ref changes are *not* rolled back. This creates a deliberate divergence between the reported status and the actual repository state, a trade-off explicitly justified by GitLab’s MVCC use case, where conservative client-side behavior (not updating remote-tracking branches when the hook reports `ng`) is the desired outcome.

The implementation is clean and well-documented. The hook is invoked after `execute_commands()` but before the report is sent, and its design as a single-script filter (not integrated with the config-based hook infrastructure) is consistent with the existing `proc-receive` hook. The patch adds 224 lines of test coverage in `t/t5412-receive-report-hook.sh`, exercising edge cases like sideband relay, non-zero exits, and the hook’s ability to modify the `unpack` status line. Documentation in `githooks.adoc` and `git-receive-pack.adoc` is thorough, explaining the hook’s purpose, input/output semantics, and the three ways it can affect push outcome: rewriting ref status lines, aborting the push, or modifying the `unpack` status.

All prior feedback has been addressed, including Patrick Steinhardt’s substantive review of the refactoring patches and Junio’s maintainability concern about the `detailed_reports` boolean parameter (now replaced with an `enum`). The series is rebased onto `master` and resolves conflicts with Justin Tobler’s concurrent "pluggable writes" series. Junio’s philosophical concern—about the hook’s ability to report a state divergent from the actual repository—remains a documented design choice rather than a blocker. The patch is queued in `seen` and looks ready for `next`.
