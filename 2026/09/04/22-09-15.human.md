This is the second patch in the v5 series adding path-related keys to `git repo info`. Junio C Hamano identifies a **substantive correctness issue** in the implementation of `path.superproject-root.absolute` and `path.superproject-root.relative`. The current code calls `get_superproject_working_tree()` without passing the repository (`repo`) parameter, causing it to rely on the process's current working directory rather than the repository being queried. This leads to incorrect behavior when querying a submodule's superproject from outside the submodule's working tree (e.g., using `--git-dir`).

The example in the email demonstrates the bug: when querying `path.superproject-root.absolute` from a submodule's `.git` directory (not its working tree), the function returns an empty string instead of the superproject's working tree path. The fix requires updating `get_superproject_working_tree()` to accept a `struct repository *` parameter and use it to determine the correct working directory context.

This issue affects only the `path.superproject-root` keys and does not impact the rest of the series. The patch is otherwise mechanically clean and aligns with the series' design patterns. The fix is straightforward but essential for correctness, and it may require a v6 iteration to address. The architectural duplication concern raised earlier in the thread remains unresolved, but this issue is independent of that discussion.
