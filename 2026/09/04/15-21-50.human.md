This is a **tooling follow-up** in the now-closed `git checkout -m` autostash conflict handling series. The series itself is already approved and queued for `next`; this exchange clarifies a minor but persistent point about Git’s style enforcement.

Junio examines Git’s `.clang-format` configuration and discovers that the `RemoveBracesLLVM: true` setting—intended to remove optional braces from single-statement bodies—does not enforce the project’s desired consistency for `if/else if/else` cascades. Specifically, it cannot add braces to all branches when only one branch requires them, which is the style rule Junio and Phillip Wood had previously flagged in `stash.c`. The example diff shows that `clang-format` removes braces from both branches of a simple `if/else`, but it does not address the more complex case where one branch in a multi-branch cascade uses braces and the others do not. This explains why GitHub CI (which runs `git clang-format` via `.github/workflows/check-style.yml`) does not flag the inconsistent brace usage that reviewers noted earlier. The discussion remains purely mechanical and does not affect the integration status of the autostash series.
