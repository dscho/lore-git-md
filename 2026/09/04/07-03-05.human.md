This is the first patch in Patrick Steinhardt’s v2 series improving the `git maintenance` heuristic for `rerere gc`. It refactors the staleness-checking logic in `rerere.c` to make it reusable for the upcoming dynamic heuristic in patch 2/2.

The patch extracts two new helper functions: `rerere_gc_cutoffs()` computes the expiration timestamps for resolved and unresolved `rerere` entries (replacing inline logic that previously lived in `rerere_gc()`), and `rerere_id_is_stale()` encapsulates the logic that determines whether a given `rerere` entry is stale based on those cutoffs. The existing `prune_one()` function is updated to call `rerere_id_is_stale()` instead of duplicating the staleness check.

No behavior changes are introduced; this is pure refactoring. The patch is clean, well-motivated by the follow-up work, and touches only `rerere.c`. Derrick Stolee’s review of v1 focused on stylistic preferences (e.g., the ternary logic in `rerere_id_is_stale()`), which were addressed in v2. The patch is ready for integration alongside its companion.
