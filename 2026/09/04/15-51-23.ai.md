This is a v2 patch series (now 3 patches) targeting the sequencer subsystem. It extends the auto-maintenance deferral logic—previously scoped to `git rebase`—to also cover `git cherry-pick` and `git revert`, ensuring all three commands now behave consistently: auto maintenance runs exactly once at sequence completion, not during intermediate steps.

The series introduces a new helper, `git_config_append_parameter()`, extracted from `config.c` to build the `GIT_CONFIG_PARAMETERS` string that disables auto maintenance for spawned commands. This string is now cached in the `replay_ctx` struct to avoid repeated construction. The implementation touches `sequencer.c`, `config.c`, and adds test coverage in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh`.

Key changes since v1:
- Cherry-pick and revert now defer auto maintenance to sequence completion, matching rebase.
- The config-parameter logic is factored into a reusable helper and cached per run.
- Commit messages are rewritten for clarity, addressing Phillip Wood’s feedback about dense phrasing.

The series is based on `master` and remains independent of the rerere lock race fix. It addresses all prior review feedback: the code is cleaner, the scope is now consistent across all sequencer-driven commands, and the test coverage verifies both the presence of the final maintenance run and the absence of mid-sequence runs. This looks like a well-motivated, thoroughly reviewed improvement.
