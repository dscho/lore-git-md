This is the first patch in a two-part series refactoring when auto maintenance runs during a `git rebase`. The goal is to make the merge backend behave like the apply backend: deferring auto maintenance until the rebase completes, rather than running it during intermediate steps.

The patch modifies `sequencer.c` to trigger `git maintenance run --auto` in the sequencer’s cleanup phase, right after the autostash is applied. This matches the existing behavior in `finish_rebase()` for the apply backend and ensures both backends handle maintenance consistently. The change is small—just five lines added to `sequencer.c`—and includes a test in `t/t3418-rebase-continue.sh` that verifies the new behavior by checking for the `git maintenance run --auto` command in trace output.

The motivation is clear: intermediate maintenance can interfere with the rebase process, and deferring it to the end avoids that disruption. The commit message explains the reasoning well, noting that the sequencer is the natural place for this logic since it already handles autostash and state cleanup. The test coverage is minimal but sufficient for the change.
