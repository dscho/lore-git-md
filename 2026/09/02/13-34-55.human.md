This is the seventh patch in Patrick Steinhardt’s 13-patch v2 series refactoring the object database (ODB) subsystem to remove the ad-hoc mechanism for registering submodule sources. The patch is a clean deletion: it removes the infrastructure that allowed submodule object databases to be registered as in-memory sources, now that all real-world callers have been eliminated by earlier patches in the series.

The commit message explains that the mechanism was introduced in 2021 (commit a35e03dee0) as a transitional crutch while migrating submodule object access away from treating submodule ODBs as alternates of `the_repository`. With the last two users removed in preceding patches, the infrastructure is now dead code. The patch deletes the `submodule_source_paths` string list from `struct object_database`, the registration function `odb_add_submodule_source_by_path()`, the helper `register_all_submodule_sources()`, and the logic in `do_oid_object_info_extended()` that retried lookups after registering submodule sources. It also removes the now-obsolete `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test mode from documentation and test scripts, since the mechanism it guarded no longer exists.

The diff is mechanical: 36 lines removed from `odb.c`, 14 from `odb.h`, and 3-line deletions from seven test scripts and `t/README`. No behavior changes are expected; the patch is purely a cleanup. The series as a whole is part of Patrick’s ongoing ODB abstraction effort and the broader `the_repository` removal work, and this patch represents the final step in eliminating the transitional submodule ODB registration mechanism. Junio C Hamano’s earlier substantive approval of related patches suggests this deletion is uncontroversial.
