This is the v2 revision of Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove the mechanism for registering in-memory sources. The series is part of the ongoing ODB abstraction effort and continues the `the_repository` removal work.

The core goal remains unchanged: eliminating the dual-use of the ODB sources list for both alternates and temporary in-memory sources (primarily submodules). This simplifies the codebase by ensuring the sources list contains only alternates, paving the way for future migration of alternate handling into the "files" backend. The series removes ~80 lines of code while maintaining functionality, with no behavioral changes expected beyond a memory leak fix (patch 9/13) and stricter enforcement of an existing constraint in `git multi-pack-index --object-dir=` (patch 10/13).

Key changes in v2 center on patch 1/13, which now adapts `cache_tree_fully_valid()` to take a `struct index_state *` instead of a repository and cache tree, addressing Junio C Hamano’s feedback from v1. This encapsulates the repository dependency within `cache-tree.c` while preserving the external interface. The patch also resolves two correctness issues Junio identified: ensuring `write_in_core_index_as_tree()` uses `index_state->repo` and fixing a lingering `the_repository` reference in `unpack_trees.c`. The remaining 12 patches are unchanged from v1, including the removal of the ad-hoc source linking API (patch 13/13), updates to test helpers, and incidental cleanups in `submodule-config` and `builtin/grep`.

Files touched span the ODB subsystem (`odb.c`/`odb.h`), submodule handling (`submodule-config.c`, `builtin/grep.c`), cache-tree logic (`cache-tree.c`/`cache-tree.h`), and test infrastructure (`t/helper/test-read-midx.c`, `t/helper/test-ref-store.c`). The series is built on `master` (as of 2026-08-31) with minor merge conflicts resolved in the cover letter. Junio’s earlier substantive approval of patch 6/13 ("Yay. Very nice.") suggests the core refactoring is uncontroversial, but the correctness fixes in patch 1/13 will likely determine whether the series is ready for `next`.
