This is the first patch in a **bugfix and API refactoring series** that introduces `early_scan_options()`, a new sub-API for Git’s `parse-options` infrastructure. The patch adds the core function and its supporting types, enabling commands to perform a fast, limited scan of their command-line arguments before full parsing begins. This addresses a recurring class of bugs where hand-rolled early scans (looking for `--` or special flags) fail to account for option values that appear as separate arguments, leading to misparsing or silent misbehavior.

The implementation is clean and well-scoped. The new `early_scan_options()` function takes an array of `struct early_scan_option` descriptors, which specify which long options to look for, whether they take values, and whether they should trigger a callback. The function stops at `--` or non-option arguments if requested, and deliberately ignores abbreviated options to avoid inconsistent resolution between the early scan and the full parse. The patch includes a new test helper (`test-parse-options`) and thorough test coverage in `t/t0040-parse-options.sh`, exercising the API’s behavior with stuck values, separate values, skipped options, and stopping conditions.

This is a **substantive, well-crafted contribution** that lays the foundation for the rest of the series. The design is minimal but flexible, and the implementation is careful to avoid over-engineering. The patch touches core argument-parsing infrastructure, so it will likely attract close review, but the approach looks sound. If the rest of the series maintains this quality, the effort is **worth attention** from anyone interested in Git’s command-line interface or the affected commands (`git bisect`, `git rev-parse`, and `git fast-import`).
