This is a review reply in the `git imap-send --draft` feature thread. Junio C Hamano raises two substantive points about the patch’s design and behavior.

The first is a question about default behavior: whether email clients that currently send messages from the Drafts folder without the `\Draft` flag would misbehave if they encounter messages that *are* marked with it. This is a forward-compatibility concern—if clients break when they see the flag, then defaulting to `--draft` could cause problems for existing workflows. Junio suggests that if clients are robust, the default could eventually be flipped to `--draft`, with `--no-draft` as an escape hatch.

The second point is about error handling on older libcurl versions. The patch currently issues a warning when `--draft` is used with libcurl < 8.13.0 but continues the upload without the flag. Junio expresses a mild preference for failing fast (erroring out) rather than silently ignoring the option, though he acknowledges that a warning is better than nothing. He also floats the idea of a configuration variable to control the behavior, though he does not insist on it.
