This is the fourth iteration of a two-patch series that refines how `git checkout -m` handles autostash conflicts. The series now cleanly separates the autostash conflict advice from the branch-switch confirmation message, making the output easier to read, and aligns exit codes with Git’s established conventions (exit code 1 for conflicts, 128 for errors).

The first patch (`stash: reserve exit status 1 for conflicts`) updates the stash subsystem to use exit code 1 exclusively for conflicts, following the same convention as `git merge-tree` and the merge strategies. It introduces an `enum stash_apply_result` to distinguish between clean application (`STASH_APPLY_CLEAN`), conflicts (`STASH_APPLY_CONFLICT`), and errors (`STASH_APPLY_ERROR`). The patch also updates the documentation to reflect these changes and ensures that `git stash apply`, `pop`, and `branch` now exit with 1 for conflicts and 128 for other failures. The in-process autostash helpers (`apply_save_autostash_oid` and `apply_save_autostash_ref`) now use the same enum, allowing them to distinguish between conflicts and other failures and provide clearer error messages.

The second patch (`checkout: separate autostash conflict advice from branch-switch message`) modifies `git checkout -m` to print a blank line between the autostash conflict advice and the branch-switch confirmation message, eliminating the visual clutter that previously made the two messages hard to distinguish. It also skips the autostash retry loop when there are no tracked local changes, avoiding unnecessary work.

The series touches `sequencer.c`, `builtin/checkout.c`, `builtin/stash.c`, `stash.h`, and the test suite (`t/t3903-stash.sh` and `t/t7201-co.sh`). The tests now use `test_cmp` to validate the full output, including the new blank line for conflicts and the updated error messages. The series is based on `master` and is uncontroversial, with all prior review feedback addressed. Junio C Hamano and Phillip Wood have both endorsed the design, and the only remaining work was mechanical adjustments, which this version implements. The patch looks well-crafted, with clear commit messages and thorough test coverage.
