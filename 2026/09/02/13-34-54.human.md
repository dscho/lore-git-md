This is part of Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. This specific patch (6/13) removes the registration of submodule object databases as in-memory sources in `git grep`, a cleanup that is now safe because the command already passes submodule repositories directly to worker threads.

The patch deletes 20 lines from `builtin/grep.c`, eliminating the call to `odb_add_submodule_source_by_path()` and the associated object-read lock that was previously needed to prevent races with concurrent object lookups. The commit message explains that while the object-read lock is still required (due to thread-safety issues in subrepository initialization), the alternate registration itself is no longer necessary. This aligns with the series’ broader goal of simplifying the ODB sources list to contain only alternates, not temporary in-memory sources.

The change is mechanical and well-motivated, with no behavioral impact expected. Junio C Hamano’s earlier substantive review of this patch in v1 ("Yay. Very nice.") signals clear approval, and the patch remains unchanged in v2. The only remaining thread-safety concern (the object-read lock) is explicitly documented in the updated code comment, making it clear this is a separate issue from the ODB source registration being removed.

This patch is uncontroversial and appears ready for integration. It touches only `builtin/grep.c` and is part of a larger, well-reviewed refactoring effort.
