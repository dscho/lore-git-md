This is the final GSoC 2026 submission report from Siddharth Shrimali, wrapping up his project to improve disk space recovery for partial clones. The report links to his full write-up on his personal site, which details the completed work on the `gc-promisor` maintenance task.

The project successfully implemented a safe pruning mechanism for unreachable promisor objects in partial clones, addressing the core goal of reclaiming disk space without breaking future fetches. Key deliverables include the `git maintenance run --task=gc-promisor` subcommand, configurable grace periods (default 30 days) via both CLI (`--grace-period=<days>`) and config (`maintenance.gcPromisor.gracePeriod`), and a `--dry-run` flag for previewing prune operations. The per-remote `.keep`-file safety mechanism, now fully implemented, includes timestamps and remote-specific markers to prevent cross-remote data loss, and the task is integrated into the `git maintenance` scheduler to run after `gc`. Performance testing on repositories with up to 15 remotes and promisor packs exceeding 1 GB showed fetch latency increases of less than 5% post-prune, and the new test suite (`t/t5329-partial-clone-prune.sh`) covers prune safety, re-fetch fallback, grace-period enforcement, multi-remote handling, and dry-run functionality.

The implementation touches `promisor-remote.c`, `builtin/gc.c`, `builtin/maintenance.c`, and `packfile.c`, introducing symbols like `cmd_maintenance__gc_promisor()` and the `maintenance.gcPromisor.enabled` config key. The on-disk format remains backward-compatible, with `.keep` files extended to store remote-specific metadata and timestamps. Open questions from earlier in the project—such as handling shallow clones, grafted history, and alternate object directories—are addressed in the report, though some edge cases (e.g., repositories with more than 15 remotes) remain under evaluation. The author explicitly invites further discussion, though no formal patch series has been posted yet. The work builds on prior GSoC efforts and existing Git machinery (e.g., `git maintenance`, promisor remotes), targeting improved usability for partial clones.
