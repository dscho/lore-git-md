This is a substantive review of Elijah Newren’s `git push` performance patch for shallow clones. Derrick Stolee identifies a critical edge case where the current implementation could corrupt a receiver’s repository during a non-atomic push. The scenario involves a shallow graft that the receiver rejects (because it would create a new shallow root), while another ref in the same push depends on objects excluded by that graft. The patch’s logic for excluding shallow boundaries would over-trim the pack, causing the second ref to succeed with an incomplete object set.

Stolee’s proposed fix is simpler: instead of introducing a new config (`push.shallowExcludeBoundary`), he suggests enabling `push.negotiate` automatically when the local repository is shallow. This leverages existing negotiation logic to avoid redundant transfers without the risk of over-exclusion. His alternative passes all but one of Elijah’s tests, and he provides a modified version of the failing test to demonstrate how negotiation handles the edge case correctly. The tradeoff is that negotiation requires an extra round-trip, but it avoids the complexity of tracking graft boundaries and the potential for corruption.

The review includes a detailed test case that reproduces the failure, showing how the current patch could break a receiver’s repository. Stolee’s feedback is constructive and technically grounded, focusing on correctness over performance. The discussion now hinges on whether to adopt the negotiation-based approach or refine Elijah’s boundary-exclusion logic to handle multi-ref pushes safely. This is a clear example of a substantive review that uncovers a real problem and offers a viable alternative.
