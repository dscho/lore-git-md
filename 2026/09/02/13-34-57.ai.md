This is a bugfix patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. It targets the packed ODB source backend, fixing memory leaks that occur when freeing a packed source that is not linked to the main object database.

The issue arises because the `odb_source_packed_free()` function does not close the source’s packs or multi-pack indices before freeing them. Historically, this was not a problem because all packed sources were linked to the main ODB, which handled cleanup. However, the series’ goal of removing ad-hoc source linking means some packed sources will no longer be linked, exposing the leak. The fix is a one-line addition: calling `odb_source_close(source)` before freeing the packs, ensuring resources are properly released.

The patch is a prerequisite for later patches in the series (notably patch 13/13, which removes the ad-hoc source linking API entirely). It touches only `odb/source-packed.c` and has no behavioral impact beyond fixing the leak. The commit message clearly explains the context and motivation, tying the fix to the broader refactoring effort. No test failures or regressions are expected, as the leak only surfaces in the new, unlinked scenario introduced by the series.

This is a low-risk, mechanical fix that aligns with the series’ goal of simplifying ODB internals. It has not drawn review comments yet, but given the series’ prior approval from Junio C Hamano on related patches, this patch is likely uncontroversial. The fix is necessary to avoid regressions when the ad-hoc source linking mechanism is removed.
