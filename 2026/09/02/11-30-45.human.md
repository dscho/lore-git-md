This is a refactoring patch that moves the global `grafts_keep_true_parents` configuration variable into Git's repository-specific `repo_config_values` struct. It's the first patch in a two-patch series from Yuvraj Singh Chauhan.

The patch eliminates the global variable and replaces it with a repository-aware getter function, `repo_grafts_keep_true_parents()`, which checks whether the repository is initialized before accessing the value. This aligns with the ongoing effort to remove global state and make Git's internals more repository-aware. The change touches two key call sites: `commit.c` (where the value controls whether grafted commits hide their true parents) and `builtin/pack-objects.c` (where the `--keep-true-parents` command-line option is bound to the new struct field).

The implementation is careful about NULL repository contexts, particularly in `cmd_pack_objects`, where it falls back to `the_repository` when no repository is provided. This ensures that help text (`git pack-objects -h`) and other non-repository operations don't crash. The patch is small, focused, and appears well-motivated by the broader `the_repository` removal effort. No behavioral changes are introduced—this is purely a mechanical refactoring.
