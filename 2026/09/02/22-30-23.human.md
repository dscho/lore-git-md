This is a focused exchange in the ongoing discussion about Christian Couder’s six-patch series introducing a new `parse-options` sub-API for early argument scanning. The thread centers on the second patch, which fixes a specific bug in `git bisect start` where a term name of `--` (e.g., `git bisect start --term-good --`) is mistakenly treated as the revision/path separator, causing the command to reject subsequent arguments as invalid revisions.

Junio C Hamano questions the **practical value** of this fix, calling it "theoretically true" but unlikely to be used in real workflows. He contrasts it with `git grep -e --`, which has clear utility, and suggests that while `refs/bisect/--` is technically allowed, users are unlikely to choose `--` as a term name. His skepticism here mirrors broader concerns he raised in the cover letter about whether the series overreaches by addressing edge cases with limited real-world impact.

The test coverage is thorough, adding a new test in `t/t6030-bisect-porcelain.sh` to verify the fix works as intended. The commit message is exemplary, clearly explaining the bug, its root cause, and why the fix is necessary without over-engineering the solution.
