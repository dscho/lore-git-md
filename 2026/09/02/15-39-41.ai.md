This is the fourth patch in Elijah Newren’s **v4 bugfix series** (4/5), which extends Git’s existing protection against unsafe `git commit --amend` operations during conflict resolution to cover `git am`, `git revert`, and all forms of `git rebase`. The patch introduces a new helper function, `sequencer_ongoing_operation()`, that consolidates logic for detecting active operations that record their results as new commits on top of HEAD (rather than rewriting HEAD). This allows the code to distinguish between conflict stops (where amending would corrupt state) and clean interactive rebase stops (where amending is expected, e.g., for `squash` or `edit` directives).

Phillip Wood’s **surface-level review** confirms the patch is ready for integration, explicitly stating "This looks good now that it is using `rebase_path_*()` rather than hard coding the paths." This addresses the maintainability concern he raised in earlier iterations about hardcoded paths in the rebase state directory. The patch is **technically complete** and uncontroversial, with all substantive feedback from Junio C Hamano and Phillip Wood already addressed in prior versions. The series is now **ready for `next`**, pending resolution of the UI consistency question raised in patch 2/5 (about allowing partial commits during rebase but not cherry-pick for empty commits), which does not affect this patch.

Key technical details:
- **Files touched**: `builtin/commit.c`, `sequencer.c`, `sequencer.h`, and test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, and `t4151-am-abort.sh`.
- **New behavior**: Blocks `git commit --amend` during conflict resolution for `git am`, `git revert`, and all `git rebase` variants, with tailored error messages for each operation (e.g., "You are resolving conflicts during a rebase -- cannot amend."). The logic correctly allows amending during clean interactive rebase stops (e.g., `edit`, `reword`, `break`) by checking for the presence of `stopped-sha` and the absence of `amend` in the rebase-merge directory.
- **New symbols**: `enum ongoing_operation` and `sequencer_ongoing_operation()` in `sequencer.h`/`sequencer.c`, which consolidate detection logic for active operations. The helper function uses on-disk state (e.g., `REVERT_HEAD`, `rebase-apply/applying`, `rebase-merge/stopped-sha`) to distinguish between conflict stops and clean stops.
- **Test coverage**: Adds comprehensive tests for both the merge and apply backends of rebase, as well as for `git am` and `git revert`. The tests verify that amending is blocked during conflict resolution but allowed during clean interactive rebase stops.
