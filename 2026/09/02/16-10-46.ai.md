This is the **fifth patch in a six-patch series** introducing a new `parse-options` sub-API for early argument scanning. The series targets a recurring class of argument-parsing bugs where hand-rolled early scans (looking for `--` or special flags) fail to account for option values that appear as separate arguments, causing misparsing or silent misbehavior.

This patch adds `early_scan_options_from_options()`, a helper that bridges the new early-scanning API with existing `struct option` arrays. The helper constructs a `struct early_scan_option` array from a `struct option` array, ensuring the early scanner and the main parser agree on which options take arguments. This eliminates the need for commands to maintain a separate, hardcoded list of options for early scanning, reducing duplication and the risk of drift when options are added or modified.

The implementation is deliberately minimal, ignoring short options, conditional values (`PARSE_OPT_OPTARG`, `PARSE_OPT_LASTARG_DEFAULT`), abbreviated options, and negated options (`--no-<name>`). These limitations are explicitly documented and justified as trade-offs to keep the scan simple and fast. The patch includes thorough test coverage: a new test helper (`test-parse-options --early-scan-from-options`) exercises the helper, and dedicated tests in `t/t0040-parse-options.sh` verify that the derived `takes_value` flags are correct and that the scanner properly skips option values.

The patch touches core argument-parsing infrastructure (`parse-options.c`, `parse-options.h`) and adds a new test helper, but does not change any user-visible behavior. It is a **refactoring and API extension** that prepares the ground for the next patch (6/6), which will convert `git fast-import` to use the new API. The design is sound and the implementation is clean, with clear documentation of the helper's limitations and a BUG() to catch misconfiguration (e.g., requesting an option not present in the `struct option` array).

This patch is **well-crafted and uncontroversial**, addressing a real maintenance pain point without over-engineering. It is worth attention from reviewers interested in Git's command-line parsing infrastructure, particularly those familiar with the `parse-options` API. The series as a whole is a substantive, well-motivated contribution that fixes concrete bugs in `git bisect`, `git rev-parse`, and `git fast-import`.
