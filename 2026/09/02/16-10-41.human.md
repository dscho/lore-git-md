This is a six-patch series from Christian Couder that introduces a new "early-scan" sub-API in Git's `parse-options` system to standardize and fix argument parsing bugs in several commands. The core issue is that many Git commands perform hand-rolled early scans of their arguments to detect flags or separators like `--`, but these scans are fragile and often fail to account for options that take separate values (e.g., `--depth 5`). This leads to inconsistencies between the early scan and the later `parse_options()` pass, causing subtle bugs.

The series adds `early_scan_options()`, a lightweight scanner that safely skips option values during early argument inspection. It has some limitations (e.g., ignoring short options, not handling abbreviated options), but these are deemed acceptable trade-offs for simplicity. The API is designed to work even for commands that don’t yet use `parse-options`, via a helper function (`early_scan_options_from_options()`) that bridges the two systems.

Three commands are fixed in this series:
- `git bisect start --term-good -- <not-a-rev>` previously mistook `--` (a term name) for the revision/path separator, causing `<not-a-rev>` to be rejected as an invalid revision.
- `git rev-parse --default -- <not-a-rev>` had the same issue, producing a confusing "bad revision" error instead of the usual "ambiguous argument" message.
- `git fast-import --depth 5 --allow-unsafe-features` silently ignored `--allow-unsafe-features` because the early scan failed to skip the `--depth 5` argument.

The patches are well-motivated, with clear examples of the bugs and how the new API resolves them. The commit messages are detailed, and the series includes new tests for all three fixes. CI tests pass, and the changes are confined to argument parsing logic, avoiding broader behavioral changes. This looks like a solid, incremental improvement to Git’s option-handling infrastructure.
