This is a CI/build system patch, part of Jeff King’s two-patch series (`peff/ci-asciidoctor-bump`) to modernize GitLab CI’s Asciidoctor installation. The series is now complete and uncontroversial, with this email marking the final acknowledgment from Patrick Steinhardt.

The patch replaces the manual `gem install asciidoctor -v 1.5.8` with `apt-get install asciidoctor`, using the Ubuntu image’s default version (2.0.20). This eliminates an outdated version pin (1.5.8, from 2018) and simplifies CI configuration by relying on the system-provided package. The change aligns CI with user environments, where newer Asciidoctor versions are standard, and reduces maintenance overhead. Jeff King’s earlier validation via GitHub Actions confirms the system version works without regressions.

Patrick’s reply closes two tangential discussions. First, he agrees with Jeff that testing compatibility with Asciidoctor 1.5.8 is unnecessary—its age and the lack of known issues make reactive bug fixes sufficient. Second, he acknowledges the `concurrent-ruby` gem’s purpose was explained in Jeff’s cover letter, though the gem’s necessity remains undocumented in the thread. This loose end doesn’t block the patch but may warrant follow-up if its role isn’t clarified elsewhere.

The patch is ready for merging. Junio C Hamano’s earlier endorsement and the absence of technical objections suggest no further changes are needed. The only remaining question—the `concurrent-ruby` gem—is orthogonal to this patch’s goal.
