This is the second iteration of Patrick Steinhardt’s refactoring series to remove the object database’s (ODB) ability to register in-memory sources. The series is part of his ongoing ODB abstraction effort and also continues the broader `the_repository` removal work.

The core goal remains unchanged: eliminate the dual-use of the ODB sources list for both alternates and temporary in-memory sources (primarily used for submodules). This simplifies the codebase by ensuring the sources list contains only alternates, making it easier to migrate alternate handling into the "files" backend in a future series. The series removes ~80 lines of code while maintaining functionality, with no expected behavioral changes beyond a memory leak fix (patch 9/13) and a breaking change in `git multi-pack-index --object-dir=` (patch 10/13), which now rejects non-alternate directories as documented since 2021.

Key changes in this version are confined to the first patch, which addresses Junio C Hamano’s feedback on the previous iteration. The updated patch reworks `cache_tree_fully_valid()` to take a `struct index_state` instead of a repository and cache tree, encapsulating the repository dependency within `cache_tree.c`. This is a cleaner approach than the v1 proposal, which would have required callers to pass both a repository and a cache tree. The rest of the series is unchanged, including the core refactoring (patches 5–7) that removes submodule ODB source registration, the memory leak fix in the packed ODB source (patch 9), and the final removal of the ad-hoc source linking API (patch 13).

The series is well-structured and appears to be a natural progression of prior work, including the removal of submodule sources from the main ODB and the switch to ODB transactions in `builtin/receive-pack`. The commit messages are detailed and the changes are narrowly scoped, suggesting a focused and maintainable refactoring. No substantive objections have been raised beyond the correctness issues addressed in v2, and Junio’s approval of patch 6/13 ("Yay. Very nice.") signals strong support for the direction. The series is now 13 patches (up from 12 in v1) due to the split of the `cache_tree_fully_valid()` changes into a separate patch.
