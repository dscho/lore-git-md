The key takeaway is that the `text` attribute—not the `diff=lfclean` filter—is the immediate culprit. When a file is marked as `text`, Git normalizes line endings in the working tree, converting LF to CRLF on Windows (unless `core.autocrlf=input` is set). This normalization corrupts binary files like PNGs, which contain CR bytes early in their content. Knoble confirms that Git’s `diff` filters are *not* applied during checkout, debunking CoPilot’s earlier hypothesis and narrowing the focus to line-ending conversion.

The email also reinforces Randall Becker’s advice: avoid marking all files as `text` (e.g., `* text`), and instead use `* text=auto` to let Git decide whether a file is text. This is a practical workaround, but Knoble does not address the deeper usability issues—such as whether Git should warn users about global `*` rules or automatically detect binary files.
