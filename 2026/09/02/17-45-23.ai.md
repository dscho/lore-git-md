This is a feature patch introducing the `hooks.allowNoVerify` configuration option, now at v4. It builds on the v3 submission by adding coverage for `git am --no-verify` (previously missing from the test suite) while keeping the same core design: an opt-in workflow guardrail that prevents accidental bypass of client-side hooks via `--no-verify` (`-n`) in `git commit`, `git push`, `git merge`, `git rebase`, and `git am`.

The patch remains self-contained and well-documented, with a new config file (`Documentation/config/hooks.adoc`), updates to the five affected built-in commands, and a comprehensive test script (`t/t7599-hooks-allownoverify.sh`) that now exercises all five commands. The emergency override mechanisms (`GIT_ALLOW_NO_VERIFY=1` and `-c hooks.allowNoVerify=true`) are preserved, and the commit message continues to emphasize that this is not a security boundary but an ergonomic guardrail for managed environments. The v4 change is minimal and focused: it plugs a test gap without altering the patch’s scope or design.
