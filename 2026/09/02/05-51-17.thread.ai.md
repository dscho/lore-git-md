Core problem or goal
Plug a memory leak in the submodule error path where a URL string allocated during repository setup was not freed when setup failed. The leak was flagged by Coverity after nearby code movement made it newly visible, but likely existed for some time. Additionally, Peff explored a deeper cleanup of the `parsed_object_pool` API asymmetry (allocating via `new` without a corresponding `free`, and a redundant `repo` pointer in the pool structure) but concluded both the asymmetry and the redundancy are too invasive to address in the current series due to circular header dependencies and code churn.

Current status
Under review. Two-patch series:
1. Make `repo_clear()` idempotent (defensive groundwork, patch 1/2 posted and uncontroversial).
2. Add the missing `free()` call in `submodule--helper` and add a test in `t/t7426-submodule-get-default-remote.sh` (patch 2/2 posted).
No merge status changes; remains in review.

Key technical details
Files touched: `builtin/submodule--helper.c`, `repository.c`, `t/t7426-submodule-get-default-remote.sh` (bugfix); `alloc.c`, `alloc.h`, `commit.c`, `commit.h`, `object.c`, `object.h` (exploratory discussion only).
New symbols: none (internal plumbing only).
Behavior change: none (bugfix only).
On-disk format: unchanged.
Test coverage: new test in `t/t7426-submodule-get-default-remote.sh` verifies the leak is plugged by triggering the error path with an uninitialized submodule and checking for the expected error message under `SANITIZE=leak`.
Idempotency note: `repo_clear()` now safely handles double-calls due to a NULL guard on `parsed_objects`.
API asymmetry note: `parsed_object_pool` is allocated via `new` without a corresponding `free`; the pool also holds a redundant `repo` pointer that is only used to access `repo->parsed_objects`, which is always the pool itself. Both issues are noted as potential future cleanups but are left out of scope due to circular dependencies between `repository.h`, `object.h`, and `hash.h` (when `USE_THE_REPOSITORY_VARIABLE` is set) and the risk of exposing hidden dependencies in approximately 9 files.
Fix mechanics: `get_default_remote_submodule()` now uses a dedicated `out` path with `goto` to ensure `repo_clear(&subrepo)` and `free(url)` are called even when `repo_submodule_init()` fails, preserving the function's error-reporting behavior.
