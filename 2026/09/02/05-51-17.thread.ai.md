Core problem or goal
Plug a memory leak in the submodule error path where a URL string allocated during repository setup was not freed when setup failed. The leak was flagged by Coverity after nearby code movement made it newly visible, but likely existed for some time. Additionally, Peff explored a deeper cleanup of the `parsed_object_pool` API asymmetry (allocating via `new` without a corresponding `free`) but concluded it was too invasive for the current series due to circular header dependencies.

Current status
Under review. Two-patch series:
1. Make `repo_clear()` idempotent (defensive groundwork, patch 1/2 posted and uncontroversial).
2. Add the missing `free()` call in `submodule--helper` and add a test in `t/t7426-submodule-get-default-remote.sh` (patch 2/2 now posted).
No merge status changes; remains in review.

Key technical details
Files touched: `builtin/submodule--helper.c`, `repository.c`, `t/t7426-submodule-get-default-remote.sh`.
New symbols: none (internal plumbing only).
Behavior change: none (bugfix only).
On-disk format: unchanged.
Test coverage: new test in `t/t7426-submodule-get-default-remote.sh` verifies the leak is plugged by triggering the error path with an uninitialized submodule and checking for the expected error message under `SANITIZE=leak`.
Idempotency note: `repo_clear()` now safely handles double-calls due to a NULL guard on `parsed_objects`; the asymmetry in the object pool API (`alloc` without `free`) is noted as a potential future cleanup but left out of scope.
Fix mechanics: `get_default_remote_submodule()` now uses a dedicated `out` path with `goto` to ensure `repo_clear(&subrepo)` and `free(url)` are called even when `repo_submodule_init()` fails, preserving the function's error-reporting behavior.
Header dependency context: Circular dependencies between `repository.h`, `object.h`, and `hash.h` (when `USE_THE_REPOSITORY_VARIABLE` is set) make decoupling `the_hash_algo` from `the_repository` or splitting `the_repository` into a forward-declaration header non-trivial. Approximately 9 files would need explicit `repository.h` includes if the latter approach were pursued.
