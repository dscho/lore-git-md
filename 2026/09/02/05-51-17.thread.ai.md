Subject: [PATCH 0/2] fix memory leak in submodule error path
Series version: v1 (initial submission)
Originating author: Jeff King (Peff)
Thread type: patch series (bugfix)

Core problem or goal
Plug a memory leak in the submodule error path where a URL string allocated during repository setup was not freed when setup failed. The leak was flagged by Coverity after nearby code movement made it newly visible, but likely existed for some time. Additionally, Peff explored a deeper cleanup of the `parsed_object_pool` API asymmetry (allocating via `new` without a corresponding `free`, and a redundant `repo` pointer in the pool structure) but concluded both the asymmetry and the redundancy are too invasive to address in the current series due to circular header dependencies and code churn. Patrick Steinhardt later engaged in the exploratory discussion, advocating for a more decisive refactoring to eliminate the redundant `repo` pointer and reduce subsystem coupling, but no actionable patches have emerged from this discussion.

Current status
Under review. Two-patch series:
1. Make `repo_clear()` idempotent (defensive groundwork, patch 1/2 posted and uncontroversial).
2. Add the missing `free()` call in `submodule--helper` and add a test in `t/t7426-submodule-get-default-remote.sh` (patch 2/2 posted). Patrick Steinhardt provided a **substantive but non-blocking** review of patch 2/2, suggesting a minor robustness improvement: initialize the `ret` variable at declaration to silence compiler warnings and make control flow more explicit. The suggestion is framed as a "nit" and can be ignored without blocking the series.
No merge status changes; remains in review.

Key technical details
Files touched: `builtin/submodule--helper.c`, `repository.c`, `t/t7426-submodule-get-default-remote.sh` (bugfix); `alloc.c`, `alloc.h`, `commit.c`, `commit.h`, `object.c`, `object.h` (exploratory discussion only).
New symbols: none (internal plumbing only).
Behavior change: none (bugfix only).
On-disk format: unchanged.
Test coverage: new test in `t/t7426-submodule-get-default-remote.sh` verifies the leak is plugged by triggering the error path with an uninitialized submodule and checking for the expected error message under `SANITIZE=leak`.
Idempotency note: `repo_clear()` now safely handles double-calls due to a NULL guard on `parsed_objects`.
API asymmetry note: `parsed_object_pool` is allocated via `new` without a corresponding `free`; the pool also holds a redundant `repo` pointer that is only used to access `repo->parsed_objects`, which is always the pool itself. Both issues are noted as potential future cleanups but are left out of scope due to circular dependencies between `repository.h`, `object.h`, and `hash.h` (when `USE_THE_REPOSITORY_VARIABLE` is set) and the risk of exposing hidden dependencies in approximately 9 files.
Refactoring proposal: Peff suggested introducing pool-based lookup functions (e.g., `lookup_commit_via_pool()`) alongside existing repository-based wrappers to avoid rewriting all callers, but Patrick Steinhardt argued for a more decisive approach—either eliminating the redundant `repo` pointer entirely or abandoning the refactoring to avoid diluting the benefit. The discussion aligns with broader efforts to reduce global state in Git, where passing explicit repositories is a first step, but the ultimate goal is to pass only the state each subsystem actually needs.
Fix mechanics: `get_default_remote_submodule()` now uses a dedicated `out` path with `goto` to ensure `repo_clear(&subrepo)` and `free(url)` are called even when `repo_submodule_init()` fails, preserving the function's error-reporting behavior. Patrick Steinhardt's review suggests initializing the `ret` variable to `0` at declaration to make the control flow more explicit and silence compiler warnings.
