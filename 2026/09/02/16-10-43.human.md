This is the **second patch in a six-part bugfix and API refactoring series** that introduces a new `parse-options` sub-API for early argument scanning. The series targets a recurring class of argument-parsing bugs where hand-rolled early scans (looking for `--` or special flags) fail to account for option values that appear as separate arguments.

This patch fixes a specific bug in `git bisect start`: when a term name is `--` (e.g., `git bisect start --term-good --`), the first argument-scanning loop mistakenly treats the term value `--` as the revision/path separator, causing the command to reject subsequent arguments as invalid revisions. The fix replaces the hand-rolled loop with the new `early_scan_options()` API, which correctly skips option values (including `--`) when scanning for the separator.

The change is minimal and focused: it adds a small array of `early_scan_option` entries for the four term-related options that take separate arguments, then replaces the manual `--` detection with a call to `early_scan_options()`. The test coverage is thorough, adding a new test case that verifies the fix works when `--` is used as a term name.

The implementation is clean, the commit message explains the issue and solution clearly, and the test coverage is appropriate.
