This is the **third patch in a six-patch series** introducing a new `parse-options` sub-API (`early_scan_options()`) to fix argument-parsing bugs where hand-rolled early scans misinterpret option values as special flags like `--`. This patch specifically addresses `git rev-parse`, fixing a case where `--default -- <arg>` incorrectly treats the `--` (intended as the option value) as the revision/path separator, causing a misleading "bad revision" error instead of the usual "ambiguous argument" message.

The patch replaces `rev-parse`'s manual argument loop with a call to `early_scan_options()`, passing a static array of options (`--default`, `--prefix`, `--resolve-git-dir`) that take their values as separate arguments. The new API correctly skips these values, preventing `--` from being misidentified as the separator. The fix is minimal and idiomatic, mirroring the approach used in the earlier `bisect` patch. A new test in `t/t1500-rev-parse.sh` verifies the corrected behavior.
