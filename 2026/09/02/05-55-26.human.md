This is the first patch in Jeff King’s two-patch bugfix series targeting a memory leak in the submodule error path. The patch makes `repo_clear()` idempotent by adding a NULL check before calling `parsed_object_pool_clear()`. This is a defensive change that simplifies error cleanup in callers, including the leak fix in the next patch.

The change is minimal—just two lines in `repository.c`—and aligns with the principle of least surprise. Peff notes that the rest of `repo_clear()` is already idempotent, so this patch completes the pattern. He also observes that the `parsed_object_pool` API is oddly asymmetric (allocating but not deallocating the struct), but leaves that for a future cleanup.

The patch is well-motivated and uncontroversial. It doesn’t change behavior on its own but paves the way for the actual leak fix in patch 2. No objections or reviews have appeared yet, but given Peff’s track record, this is likely to be merged as-is.
