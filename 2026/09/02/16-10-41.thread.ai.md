Subject: [PATCH 0/6] parse-options: new sub-API for early argument scanning
Series version: v1 (initial submission)
Originating author: Christian Couder <christian.couder@gmail.com>
Thread type: patch series (bugfix and API refactoring)

Core problem or goal
Introduce a new `parse-options` sub-API (`early_scan_options()`) to fix a class of argument-parsing bugs where hand-rolled early scans (looking for `--` or special flags) fail to account for option values that appear as separate arguments. The new API performs a fast, limited scan of `argv` to locate specific long options, ignoring short options, abbreviations, and edge-case option types like `PARSE_OPT_OPTARG`. The series converts three commands (`git bisect`, `git rev-parse`, and `git fast-import`) to the new API, fixing concrete bugs in each:
- `git bisect start --term-good -- <not-a-rev>` previously mistook the term name `--` for the revision/path separator, rejecting `<not-a-rev>` as an invalid revision.
- `git rev-parse --default -- <not-a-rev>` made the same mistake, producing a confusing "bad revision" error.
- `git fast-import --depth 5 --allow-unsafe-features` silently ignored `--allow-unsafe-features`, refusing unsafe features from the input stream.

Current status
Under review (v1 posted). Junio C Hamano has raised **substantive design concerns** about the long-term viability of the new API, questioning whether it merely replaces one set of fragile hand-rolled scans with another rather than addressing the root problem: the lack of a unified, reusable early-scan mechanism within `parse_options()` itself. Junio is skeptical of the `git bisect` and `git rev-parse` fixes, seeing "little practical value," but acknowledges the `git fast-import` bug as a real issue. He suggests a future refactoring of `parse-options` to support a "dry-run" prescan mode and hints that the current design—introducing a separate `early_scan_option` structure—may be seen as technical debt. The series is **not yet ready for `next`** and will require at least one more iteration. No merge status reported; CI passed cleanly on v1.

Key technical details
- New functions: `early_scan_options()`, `early_scan_options_from_options()`, `parse_options_takes_argument()`
- New types: `struct early_scan_option`, `early_scan_fn`, `enum early_scan_flags`
- New macros: `EARLY_SCAN_SKIP_VALUE`, `EARLY_SCAN_WANT`, `EARLY_SCAN_WANT_VALUE`, `EARLY_SCAN_END`
- Files touched: `parse-options.h`, `parse-options.c`, `builtin/bisect.c`, `builtin/rev-parse.c`, `fast-import.c`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`, `t/t6030-bisect-porcelain.sh`, `t/t1502-rev-parse-disambiguate.sh`, `t/t9300-fast-import.sh`
- Subsystems: argument parsing, command-line interface
- New test helper: `test-parse-options --early-scan-options` and `test-parse-options --early-scan-from-options` (exercises the new API and helper)
- Test coverage: new tests for each bug in `t/t6030-bisect-porcelain.sh` (bisect), `t/t1502-rev-parse-disambiguate.sh` (rev-parse), and `t/t9300-fast-import.sh` (fast-import), plus dedicated API tests in `t/t0040-parse-options.sh` covering both the core API and the new helper
- Behavior changes: fixes misparsing of `--` and special flags when option values appear as separate arguments; no changes to on-disk format or option semantics beyond the bugfixes. The `git fast-import` conversion adds a safety requirement that `--allow-unsafe-features` must be spelled in full (no abbreviations).
- Refactoring: `parse_options_takes_argument()` helper extracted from `show_gitcomp()` to avoid code duplication and prepare for `early_scan_options()`; `early_scan_options_from_options()` helper bridges the new early-scanning API with existing `struct option` arrays, eliminating the need for commands to maintain separate, hardcoded lists of options for early scanning.

Open questions and loose ends

- **Scope of fixes**: Junio questions the practical value of the `git bisect` and `git rev-parse` fixes, suggesting the series might be more compelling if it focused solely on the `git fast-import` bug.
