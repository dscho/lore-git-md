This is the **fifth patch in a six-patch series** that introduces a new `parse-options` sub-API for early argument scanning. The series as a whole fixes a class of argument-parsing bugs where hand-rolled early scans fail to account for option values that appear as separate arguments, causing misparsing or silent misbehavior in commands like `git bisect`, `git rev-parse`, and `git fast-import`.

This patch specifically adds `early_scan_options_from_options()`, a helper that builds a `struct early_scan_option` array from an existing `struct option` array. This is a **practical refactoring** that eliminates the need for commands to manually duplicate option metadata (like which options take values) when adopting the new early-scanning API. The helper ensures the early scanner and the main parser agree on which options take arguments, preventing drift between the two and making it easier to maintain commands that use both.

The implementation is **deliberately minimal** to keep the early scan fast and simple. It ignores short options, conditional values (like `PARSE_OPT_OPTARG`), abbreviated options, and negated variants (`--no-<name>`). The commit message clearly explains these limitations and why they were chosen, noting that they can be addressed later if needed. This approach avoids over-engineering while still solving the immediate problem for the commands being converted in this series.

The patch includes **thorough test coverage**, adding a new test helper (`test-parse-options --early-scan-from-options`) and two new tests in `t/t0040-parse-options.sh`. These tests verify that the helper correctly derives `takes_value` flags and skips option values as expected. The tests are well-designed and cover the core functionality without being overly complex.

This is a **well-crafted, uncontroversial patch** that fits neatly into the series. It addresses a real maintenance pain point (duplicating option metadata) without introducing new complexity or risk. The limitations are clearly documented, and the implementation is clean and idiomatic. The patch is **ready for review** and should attract little debate, as it builds on the solid foundation laid by the earlier patches in the series.
