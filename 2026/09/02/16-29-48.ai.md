This is a brief follow-up in the ongoing discussion about refactoring Git’s `parsed_object_pool` API, specifically the relationship between the parsed object pool and the repository instance. Junio C Hamano (the maintainer) responds to Patrick Steinhardt’s suggestion that the parsed object pool should be an implementation detail of the object database rather than tied to the repository.

Junio’s reply is measured and cautious. He points out that Patrick’s proposal directly contradicts an existing design choice: Git’s hash algorithm (SHA-1 or SHA-256) is a property of the repository instance, and the parsed object pool currently depends on this. This dependency is intentional and not easily decoupled. However, Junio acknowledges the broader goal Patrick is advocating—making subsystems more self-contained and flexible—without endorsing or rejecting the specific refactoring. His response is a technical note rather than a directive, leaving the discussion open for further exploration.

The exchange does not propose actionable changes or affect the original bugfix series (which remains uncontroversial and under review). It serves as a reminder of the tension between subsystem decoupling and existing architectural commitments, particularly around repository-scoped properties like the hash algorithm. No new technical details or objections are introduced; the thread remains exploratory.
