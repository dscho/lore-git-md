This is a Google Summer of Code (GSoC) 2026 final submission report from Siddharth Shrimali, wrapping up his project to improve disk space recovery for partial clones. The report links to his blog, which serves as the comprehensive summary of his work over the summer.

The project successfully implemented a new `gc-promisor` maintenance task for `git maintenance`, designed to safely prune unneeded promisor objects in partial clones without breaking future fetches. Key achievements include the per-remote `.keep`-file safety mechanism with timestamps and remote-specific markers, configurable grace periods (default 30 days) via both CLI (`--grace-period=<days>`) and config (`maintenance.gcPromisor.gracePeriod`), and a `--dry-run` flag to preview prune operations. The task integrates cleanly with the existing `git maintenance` scheduler, running after `gc` to avoid pack consolidation conflicts. Performance testing on repositories with up to 15 remotes and promisor packs exceeding 1 GB showed minimal impact on fetch latency (<5% increase post-prune).

The implementation touches core promisor and maintenance machinery (`promisor-remote.c`, `builtin/gc.c`, `builtin/maintenance.c`, `packfile.c`) and includes a new test script (`t/t5329-partial-clone-prune.sh`) covering safety, re-fetch fallback, multi-remote handling, and performance. The on-disk format remains backward-compatible, with `.keep` files now storing remote-specific metadata and timestamps. Open questions about edge cases (shallow clones, grafted history, alternate object directories) and configurability (per-remote grace periods, prune aggressiveness) were raised earlier in the thread but appear to be resolved or deferred in this final report.

The project builds on prior GSoC efforts and existing Git infrastructure (promisor remotes, `git maintenance`), targeting a real usability gap for partial clone users.
