This is the **first patch in a six-part bugfix and API refactoring series** introducing `early_scan_options()`, a new sub-API for Git's `parse-options` infrastructure. The patch adds the core function and its supporting types, enabling commands to perform a fast, limited scan of `argv` to locate specific long options before full argument parsing begins. The implementation is deliberately minimal: it ignores short options, option abbreviations, and edge-case option types like `PARSE_OPT_OPTARG`, focusing only on the subset of long options that commands need to inspect early (e.g., `--` or special flags).

The patch defines the `early_scan_option` struct, which describes options to scan for (or skip), and the `early_scan_fn` callback type, which is invoked for each matched option. The `early_scan_options()` function itself walks `argv`, stopping at `--` or non-option arguments if requested, and invokes the callback for each "wanted" option it encounters. The API is exercised by a new test helper (`test-parse-options --early-scan-options`) and covered by dedicated tests in `t/t0040-parse-options.sh`, which verify correct handling of option values (both stuck and separate), skipping of non-wanted options, and stopping behavior.

Key technical details:
- Files touched: `parse-options.c`, `parse-options.h`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`
- New types: `struct early_scan_option`, `early_scan_fn`, `enum early_scan_flags`
- New macros: `EARLY_SCAN_SKIP_VALUE`, `EARLY_SCAN_WANT`, `EARLY_SCAN_WANT_VALUE`, `EARLY_SCAN_END`
- The implementation avoids modifying `argv` and does not resolve option abbreviations, ensuring the early scan cannot diverge from the later full parse.

The patch is **well-structured and self-contained**, with clear commit message rationale and thorough test coverage. It lays the foundation for the subsequent patches in the series, which will convert `git bisect`, `git rev-parse`, and `git fast-import` to use the new API, fixing concrete argument-parsing bugs in each. The design is conservative, prioritizing correctness and minimalism over feature completeness, and the implementation appears clean and idiomatic. This is a **substantive, high-quality contribution** to Git's argument-parsing infrastructure.
