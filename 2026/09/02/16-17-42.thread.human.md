This thread introduces a new configuration option, `hooks.allowNoVerify`, designed to let administrators prevent users from bypassing client-side hooks with the `--no-verify` (`-n`) flag across several Git commands. The patch, now at version 4, is a workflow guardrail for managed environments or CI pipelines where hook execution must be enforced. It defaults to permissive behavior for backward compatibility and includes emergency overrides via environment variables or CLI flags.

Junio C Hamano has rejected the patch, ending the discussion for now. His objection centers on the feature’s narrow scope: it targets only hooks, not the broader class of verification steps (including built-in checks like pre-commit format validation). He also warns against creating a "slippery slope" of increasingly complex configuration layers to block CLI overrides. The rejection is conceptual, not technical—Junio did not critique the implementation, tests, or documentation—but it leaves little room for incremental revision. Unless the design is rethought to address the broader problem, the patch is unlikely to move forward. No other reviewers have weighed in.
