This thread introduces a new configuration option, `hooks.allowNoVerify`, proposed by Alessio Attilio to prevent accidental bypass of Git hooks via the `--no-verify` (`-n`) flag. The feature is designed for managed environments or CI workflows where hook execution must be enforced, though it defaults to `true` (allowing bypass) to maintain backward compatibility.

The patch touches several built-in commands (`commit`, `push`, `merge`, `rebase`) and includes documentation and a comprehensive test suite. It’s an opt-in workflow feature that doesn’t alter Git’s server-side security model. So far, the implementation appears well-structured, with clear documentation and thorough test coverage, addressing a practical need in controlled environments. No reviews or objections have been posted yet, so the discussion is still in its early stages.
