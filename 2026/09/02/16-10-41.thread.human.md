This thread introduces a new `parse-options` sub-API to fix a class of argument-parsing bugs where hand-rolled early scans misinterpret option values (like `--`) as special separators. The series, now at its initial v1, is authored by Christian Couder and targets three Git commands: `bisect`, `rev-parse`, and `fast-import`.

The second patch in the series demonstrates the problem and solution clearly. In `git bisect start`, when a term name is `--` (e.g., `git bisect start --term-good --`), the command mistakenly treats the term value `--` as the revision/path separator, rejecting subsequent arguments. The fix replaces the manual `--` detection with the new `early_scan_options()` API, which correctly skips option values. The patch is minimal, well-tested, and fixes a real user-facing issue without introducing new design questions.

So far, the series has passed CI and is under review. No objections or requests for changes have been raised yet, and the implementation is clean and idiomatic. The new API is deliberately scoped to address the immediate bugs without over-engineering, making this a straightforward and well-motivated contribution.
