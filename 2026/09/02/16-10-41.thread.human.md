This thread introduces a new `parse-options` sub-API (`early_scan_options()`) to fix bugs where hand-rolled early argument scans misparse option values that appear as separate arguments. Christian Couder’s six-patch series targets three commands—`git bisect`, `git rev-parse`, and `git fast-import`—fixing concrete issues like `git bisect start --term-good -- <not-a-rev>` rejecting valid paths and `git fast-import --allow-unsafe-features` being silently ignored.

Junio’s feedback, however, casts doubt on the design. He sees the new API as another ad-hoc prescan that doesn’t align with the real `parse_options()` machinery and questions whether it merely replaces one fragile approach with another. While he acknowledges the `git fast-import` fix as the most compelling, he suggests the root issue might have been a simpler oversight in the existing prescan logic. His long-term vision is a unified `parse-options` refactoring that could handle prescans internally, possibly via a “dry-run” mode, and he hints that the current design—introducing a separate `early_scan_option` structure—may create technical debt.

The thread is now at a decision point: Christian will need to either defend the current design as a pragmatic step or propose a broader refactoring of `parse-options()`. Until then, the series remains under review and is not yet queued for integration. No other participants have weighed in yet, so the discussion is currently between the author and the maintainer.
