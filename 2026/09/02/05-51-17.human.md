This is a two-patch bugfix series from Jeff King targeting a memory leak in the submodule error path.

The leak was flagged by Coverity and involves a submodule URL that wasn’t freed when repository setup failed. The first patch makes `repo_clear()` idempotent (safe to call multiple times), which is a prerequisite for the second patch. The second patch then plugs the leak by ensuring the URL is freed in the error path. The series also adds a new test in `t/t7426-submodule-get-default-remote.sh` to verify the fix.

The commit messages are clear and the changes are small and focused. Jeff is a long-time contributor with deep knowledge of Git’s internals, so the patches are likely well-vetted. The leak itself is minor but worth fixing, and the idempotency change in `repo_clear()` is a sensible cleanup. No controversy is expected.
