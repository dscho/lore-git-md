Subject: [PATCH] dir: fix common prefix calculation with leading exclude pathspec
Series version: standalone patch (no series)
Originating author: Yannik Tausch
Thread type: bugfix patch

Core problem or goal
Fix a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes the function to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs (e.g., `foo/bar` and `foo/baz`) share a directory (`foo/`). The bug occurs because the function uses the first pathspec item as the comparison baseline regardless of exclusion status, and skips excluded items only after initializing the comparison.

Current status
Under review; no prior versions. Patch introduces a new `pathspec_prefix` struct to track the first *positive* pathspec item and its common prefix length, updates `common_prefix()` and `fill_directory()` to use this return value, and adds a unit test in `t/unit-tests/u-dir.c` verifying the fix.

Key technical details
- Files touched: `dir.c`, `t/unit-tests/u-dir.c`
- New symbol: `pathspec_prefix` struct (contains match string and common prefix length)
- Subsystem: pathspec handling and directory traversal
- Behavior change: `common_prefix_len()` now correctly returns the common prefix of positive pathspecs even when an exclude pathspec appears first
- Test coverage: new unit test in `t/unit-tests/u-dir.c` covering the edge case

Open questions and loose ends
None identified; the patch is self-contained and addresses the described edge case without introducing new questions.
