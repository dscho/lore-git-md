Core problem or goal
Fix a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes the function to incorrectly return an empty string instead of the common prefix of positive pathspecs (e.g., `a/` from `a/b` and `a/c`). The bug occurs because the function uses the first pathspec item as the comparison baseline regardless of exclusion status, and skips excluded items only after initializing the comparison. Additionally, the series addresses a memory-safety issue in `match_pathspec_with_flags()` where negative pathspecs shorter than the common prefix derived from positive pathspecs trigger a heap-buffer-overflow when `match_pathspec_item()` reads out-of-bounds memory, and a second logical bug where the common prefix derived from positive pathspecs is incorrectly applied to negative pathspecs, producing false positives (e.g., `git ls-files a/b ':!x/b' a/c` incorrectly excludes `a/b/m`). Junio C Hamano has clarified that the bug is narrower than initially described: the traversal optimization (avoiding root traversal when positive pathspecs share a directory) is already present and unaffected; the issue is purely about the incorrect string returned by `common_prefix()`.

- Subsystem: pathspec handling and directory traversal
- Behavior change: `common_prefix()` now correctly returns the common prefix string of positive pathspecs even when an exclude pathspec appears first (addressed in patch 3); `match_pathspec_with_flags()` no longer applies the common prefix to negative pathspecs, preventing both out-of-bounds reads and false positives in negative pathspec matching (addressed in patch 2)
- Test coverage: new functional test in `t/t6132-pathspec-exclude.sh` (covering the memory-safety issue, the common prefix edge case, and the false-positive bug in negative pathspec matching) and unit tests in `t/unit-tests/u-dir.c` (covering the edge case with an unrelated exclude item followed by two non-exclude items sharing a directory, and the heap-buffer-overflow regression). The third patch adds a unit test specifically for the edge case where an exclude pathspec precedes two positive pathspecs sharing a directory. Junio C Hamano has provided deterministic test cases for both the heap-buffer-overflow (using an exclude pathspec whose length matches the common prefix of positive pathspecs) and the false-positive bug (`git ls-files a/b ':!x/b' a/c`).
- Alternative design: Junio's output-parameter approach (`common_prefix_len(pathspec, &matched_prefix)`) is the agreed-upon solution
- Preparatory refactoring: `struct pathspec_item` fields `match` and `original` are now `const char *` to reflect immutability and enable warning-free unit test initialization

The fix only corrects the string returned by `common_prefix()`, which is used by distant callers (e.g., `overlay_tree_on_index()` in `git ls-files --with-tree`) for unclear purposes.
