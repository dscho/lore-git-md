Core problem or goal
Fix a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes the function to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs (e.g., `foo/bar` and `foo/baz`) share a directory (`foo/`). The bug occurs because the function uses the first pathspec item as the comparison baseline regardless of exclusion status, and skips excluded items only after initializing the comparison. Additionally, the series addresses a memory-safety issue in `match_pathspec_with_flags()` where negative pathspecs shorter than the common prefix derived from positive pathspecs trigger a heap-buffer-overflow when `match_pathspec_item()` reads out-of-bounds memory.

Current status
Ready for merging; v3 integrates Junio C Hamano's preparatory refactoring (declaring `match` and `original` fields in `struct pathspec_item` as `const char *`) with the two existing patches (memory-safety fix and core fix). The series is now structured as three patches: (1) preparatory refactoring, (2) memory-safety fix (this patch), and (3) core `common_prefix_len()` refactor. The output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`) remains the agreed-upon solution. No further technical changes are expected.
