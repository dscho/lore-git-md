This is a follow-up in the `git imap-send --draft` feature thread. Wolfgang Faust responds to Junio C Hamano’s review, agreeing with the default `--no-draft` choice but pushing back on flipping it later. He argues that `--draft` should remain opt-in because `git imap-send` is also used by `git send-email --imap-sent-folder` (which should *not* mark messages as drafts) and because the feature depends on a recent libcurl version, making a default `--draft` impractical—it would either silently fail on older systems or break the command entirely unless users explicitly opt out.

On the libcurl version check, Wolfgang agrees to change the current warning to an error when `--draft` is used with an unsupported version, aligning with Junio’s preference for failing fast. He declines to add a configuration variable (`imap.draft`), citing the same workflow concerns and noting that Git’s convention is to introduce flags first and only add configuration if demand emerges later. The patch remains under review; no code changes have been posted yet.
