This is the **v4** revision of a two-patch series that refines `git checkout -m` behavior when autostash is involved. The series now cleanly separates the **exit code convention** (patch 1) from the **advice formatting** (patch 2), addressing all prior review feedback.

The core change is that `git stash apply`, `pop`, and `branch` now exit with **status 1** when conflicts occur (mirroring `git merge-tree` and merge strategies), and **status 128** (or another non-zero value) for other failures. This replaces the previous ambiguous exit code (1 for both conflicts and errors) and is documented in `git-stash.adoc`. The new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) makes the distinction explicit in the codebase, and the in-process autostash helpers (`apply_save_autostash_oid()`, `apply_save_autostash_ref()`) now use this enum to distinguish conflicts from other failures.

Patch 2 updates `git checkout -m` to print a blank line between the autostash conflict advice and the branch-switch confirmation message, eliminating visual clutter. The test suite (`t/t3903-stash.sh`, `t/t7201-co.sh`) is updated to validate the new exit codes and output formatting, including coverage for `stash branch` (previously missing).

The series is **uncontroversial** and **ready for merging**. All design questions (exit code convention, correctness of conflict detection, API design) have been resolved by Junio C Hamano and Phillip Wood. The remaining changes in v4 are mechanical: splitting the stash exit code logic into its own commit, adjusting exit codes to match Git’s established convention, and improving error messages (e.g., clarifying that stashed changes are preserved on failure). The code is well-tested and touches only the stash and checkout subsystems.
