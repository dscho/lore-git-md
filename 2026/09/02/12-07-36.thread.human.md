This thread is about a bugfix for the `git history` command, submitted by an author from the University of Science and Technology of China. The patch prevents a NULL-pointer dereference crash in `write_ondisk_index()` when the parent commit's tree object is missing from the object store—something that can happen due to repository corruption, object removal, or incomplete restores. The fix is minimal: it adds a guard to check the return value of `repo_parse_tree_indirect()` and error out gracefully, following Git's established pattern for handling unloadable objects.

The issue was reported through Git's security contact but was deemed non-security-sensitive, as the crash requires a missing object in a local repository. The reproduction steps are simple: create a commit, remove its parent tree object from `.git/objects/`, and run `git history split HEAD`. Without the patch, this triggers a SIGSEGV; with it, the command fails with a clear error message. The patch touches only `builtin/history.c` and introduces no new dependencies or behaviors. While no test is included, the provided reproduction steps could easily be adapted into a regression test.

The fix is uncontroversial and addresses a real crash, so it’s likely to be merged once reviewed.
