This is a bugfix for the `git history` command. The patch prevents a NULL-pointer dereference crash in `write_ondisk_index()` when the parent commit's tree object is missing from the object store (e.g., due to repository corruption, object removal, or incomplete restore). The fix adds a guard to check the return value of `repo_parse_tree_indirect()` and error out gracefully, following Git's established pattern for handling unloadable objects.

The issue was reported via Git's security contact but deemed non-security-sensitive, as the crash requires a missing object in a local repository. The reproduction steps are straightforward: create a commit, remove its parent tree object from `.git/objects/`, and run `git history split HEAD`. Without the patch, this triggers a SIGSEGV; with the patch, it fails with a clear error message.

The patch itself is minimal and focused, touching only `builtin/history.c`. It introduces a NULL check and an error return, matching the codebase's convention for similar cases. The commit message is clear and includes reproduction steps, which is helpful for reviewers and future maintainers. No test is included, but the provided reproduction steps could easily be adapted into a regression test.

This is a standalone patch, not part of a larger series. The fix is uncontroversial and addresses a real crash, so it is likely to be merged once reviewed. The author followed the security team's guidance to post the fix publicly, which is the correct process for non-security issues.
