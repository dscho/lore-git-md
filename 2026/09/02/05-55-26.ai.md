This is the first patch in Jeff King’s two-patch bugfix series targeting a memory leak in the submodule error path. The patch makes `repo_clear()` idempotent by adding a NULL check before calling `parsed_object_pool_clear()`, preventing a segfault if the function is called twice on the same repository object. The change is minimal (two lines in `repository.c`) and defensive, preparing the ground for the actual leak fix in the next patch.

The commit message explains the motivation clearly: simplifying error cleanup by removing the need for callers to track whether `repo_clear()` has already been called. Peff notes that while the rest of `repo_clear()` is already idempotent, the `parsed_objects` field was an exception due to the asymmetric design of the object pool API (which allocates but does not deallocate). He flags this asymmetry as a potential future cleanup but leaves it out of scope here.

The patch is uncontroversial and well-motivated. It touches only internal plumbing (`repository.c`) and introduces no new symbols or behavior changes. The NULL check is a standard defensive pattern, and the change aligns with the series’ goal of plugging a leak without introducing side effects. No reviews or objections have appeared yet, but given Peff’s track record and the patch’s simplicity, it is likely to be accepted as-is. The next patch in the series will build on this by fixing the actual leak in `submodule--helper`.
