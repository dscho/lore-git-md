This is the first patch in Harald Nordgren’s two-patch series (v4) that refines how `git stash` exit codes work. The patch introduces an explicit `enum stash_apply_result` to distinguish between three outcomes: clean application (`STASH_APPLY_CLEAN`), conflicts (`STASH_APPLY_CONFLICT`), and other errors (`STASH_APPLY_ERROR`). The stash subcommands now exit with status 1 only for conflicts, matching the convention used by `git merge-tree` and merge strategies, while other failures return 128 or another non-zero value. The documentation in `git-stash.adoc` is updated to reflect this change.

The patch touches `builtin/stash.c`, `sequencer.c`, `sequencer.h`, and adds a new header `stash.h` for the enum definition. The in-process autostash helpers (`apply_save_autostash_oid()` and `apply_save_autostash_ref()`) now use the enum to distinguish conflicts from other failures, and `cmd_stash()` maps negative return values to 128 while passing through positive values (1 for conflicts). Junio’s review suggests a small style nit about brace consistency in `cmd_stash()` and proposes a helper function to clean up the `run_command()` return value handling in `apply_save_autostash_oid()`, but these are minor mechanical adjustments.

This patch is uncontroversial and ready for merging. All design questions—exit code conventions, conflict detection correctness, and API design—were resolved in earlier iterations by Junio and Phillip Wood. The changes are mechanical, well-tested, and focus on the stash subsystem without altering the underlying conflict resolution logic. The new enum and exit code convention are a clear improvement over the previous ambiguous behavior. The second patch in the series will use this foundation to refine the advice formatting in `git checkout -m`.
