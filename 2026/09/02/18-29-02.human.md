This is the first patch in a two-part **bugfix** series that refines how `git stash` and `git checkout -m` handle autostash conflicts. The patch reserves exit status **1** specifically for conflicts, aligning `git stash apply`, `pop`, and `branch` with Git’s established convention (used by `git merge-tree` and merge strategies) and making it possible for callers to distinguish between conflicts and other failures.

The core change introduces a new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) and updates the in-process autostash helpers (`apply_save_autostash_oid()`, `apply_save_autostash_ref()`) to return this enum instead of an `int`. The `cmd_stash()` dispatcher now maps negative return values (errors) to exit code **128** (matching `die()`), while positive values (conflicts) are passed through as **1**. This ensures that conflicts are unambiguously signaled to callers, and the stash entry is preserved in all failure cases.

The patch also improves error messaging: when autostash application fails for reasons other than conflicts (e.g., a crash or signal), users now see a clear message that their changes are safe in the stash, rather than being left to wonder. Documentation in `git-stash.adoc` is updated to reflect the new exit status conventions.

Files touched include `builtin/stash.c`, `sequencer.c`/`sequencer.h`, a new `stash.h` header, and tests in `t/t3903-stash.sh`. The test suite is expanded to validate the new exit codes, including coverage for `stash pop` (which now exits with **1** on conflicts but keeps the stash entry) and `stash branch` (which exits with **128** on errors).

This patch is **uncontroversial** and **ready for merging**. All design questions—exit code conventions, conflict detection logic, and API design—were resolved in prior iterations by Junio C Hamano and Phillip Wood. The remaining changes in this version are mechanical: splitting the exit code logic into its own commit, adjusting return values to match Git’s conventions, and clarifying error messages. The code is well-tested and touches only the stash and sequencer subsystems.
