This thread reports an inconsistency in how Git handles commit message newlines between `git commit` and `git merge`. Simon Cheng describes a scenario where `git commit -m MSG` appends an extra newline to the message before cleanup, but `git merge --no-ff -m MSG` does not. This difference is usually hidden under the default `commit.cleanup = whitespace` setting, but when using `commit.cleanup = strip` alongside a `prepare-commit-msg` hook, the missing newline causes the hook’s output to concatenate with the merge message, breaking cleanup and leaving unwanted text in the final commit.

The issue is reproducible in Git 2.55.0 and affects non-interactive merge commits. While Simon doesn’t propose a patch, they argue that `git merge` should match `git commit`’s behavior by appending a newline for consistency. The thread is still open, with no responses or decisions yet—this is the first email in the discussion. If this resonates with contributors who prioritize consistency in Git’s plumbing, it could lead to a small but meaningful fix.
