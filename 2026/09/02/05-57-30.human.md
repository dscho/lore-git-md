This is the second patch in Jeff King’s two-patch bugfix series targeting a memory leak in the submodule error path. The series was introduced earlier with a cover letter explaining the problem and the defensive groundwork laid by the first patch (making `repo_clear()` idempotent).

This patch fixes the leak itself: when `repo_submodule_init()` fails in `get_default_remote_submodule()`, the function returns an error without freeing the `url` string allocated earlier. The fix is straightforward: restructure the error path to ensure `free(url)` and `repo_clear()` are called before returning. The patch also adds a new test in `t/t7426-submodule-get-default-remote.sh` that triggers the error case by querying an uninitialized submodule, verifying the leak is plugged.

The changes are minimal and focused, touching only `builtin/submodule--helper.c` and the test suite. The commit message is clear and concise, and the test coverage is thorough. Jeff’s patches are typically well-crafted, and this one follows that pattern. The leak is not critical, but it is a real bug that should be fixed. No controversy or objections have surfaced yet, and the patch looks ready for review. If you care about submodule plumbing or memory hygiene, this is worth a quick look.
