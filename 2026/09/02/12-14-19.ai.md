Knoble’s email **corrects a key misconception** in the thread: the `diff=lfclean` filter is *not* the direct cause of binary file corruption during checkout. Instead, the `text` attribute in the global `.gitattributes` rule (`* text diff=lfclean`) triggers Git’s line-ending normalization, which converts LF to CRLF in the working tree—corrupting binary files like PNGs. This distinction is critical: the `diff` filter only affects `git diff` output (as seen in the earlier textconv issue), while the `text` attribute affects *all* file operations, including checkout. Knoble’s explanation aligns with Git’s documented behavior (`git help attributes`) and confirms that the root cause is the overly broad `* text` rule, not the `diff` filter itself.

The email also **validates Becker’s configuration advice** (`core.autocrlf=input`, `* text=auto`) and adds a nuanced recommendation: `text=auto` is safer than `text` because it lets Git decide whether a file is text (using its heuristic, which checks the first "hunk" for non-text characters). This addresses the thread’s core usability concern—silent corruption of binaries—by reducing the risk of misclassification.
