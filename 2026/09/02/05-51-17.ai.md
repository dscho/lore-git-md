This is a two-patch bugfix series from Jeff King (Peff) that plugs a memory leak in the submodule error path. The leak was flagged by Coverity after nearby code movement made it newly visible, though Peff notes it has likely existed for some time.

The first patch makes `repo_clear()` idempotent by ensuring it safely handles being called multiple times on the same repository object. This is a defensive change that prepares the ground for the actual fix.

The second patch fixes the leak itself: when repository setup fails in `submodule--helper`, the URL string allocated earlier in the function was not being freed. The patch adds the missing `free()` call and includes a new test in `t/t7426-submodule-get-default-remote.sh` to verify the fix.

The series touches `builtin/submodule--helper.c`, `repository.c`, and the test suite. The changes are small and focused, with a clear commit message explaining the motivation. Peff’s patches are typically well-tested and precise, and this one follows that pattern. The leak is not catastrophic, but it is a real bug that should be fixed.
