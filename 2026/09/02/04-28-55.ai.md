This is a follow-up in the `git imap-send --draft` feature thread. The author, Wolfgang Faust, responds to Junio C Hamano’s review with clarifications and proposed adjustments.

Wolfgang agrees that defaulting to `--no-draft` is the right choice to avoid breaking existing workflows, particularly for tools like `git send-email --imap-sent-folder` that upload already-sent messages. He argues that flipping the default to `--draft` would introduce inconsistency, as the behavior would vary depending on the user’s libcurl version—either silently ignoring the flag (on older libcurl) or erroring out (if the version check were made strict). He also notes that external tooling relying on the current behavior would need updates to avoid unintended draft marking.

On error handling, Wolfgang concedes that failing fast (erroring out) when `--draft` is used with an unsupported libcurl version is preferable to issuing a warning, and he is willing to update the patch accordingly. Regarding Junio’s suggestion of a configuration variable (e.g., `imap.draft`), Wolfgang is hesitant, citing the same workflow concerns as with the default behavior and the project’s general preference for introducing flags before configuration. No new code is proposed in this reply; the discussion remains focused on design trade-offs. The thread is still under review, with no additional feedback from other participants.
