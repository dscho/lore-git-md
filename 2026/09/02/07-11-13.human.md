This is a CI/build system patch series follow-up, proposing to update GitLab CI’s Asciidoctor version pin from 1.5.8 (2018) to a more recent release. Jeff King (Peff) sends a two-patch series on top of Patrick Steinhardt’s earlier fix (which added `ruby` to the dependency list to restore `gem install asciidoctor` functionality). The first patch removes the explicit version pin, letting CI install whatever Asciidoctor version the system package manager provides. The second patch updates the CI script to install Asciidoctor via Ubuntu’s `apt` (the `asciidoctor` package) instead of `gem`, eliminating the need for Ruby’s `gem` tool entirely.

Peff’s motivation is straightforward: the original blocker for Asciidoctor 2.0.0 (resolved in 2019) is long gone, and the current pin tests an outdated version that few users are likely to encounter. He argues that CI should prioritize testing versions people actually use, and that installing from Ubuntu’s repositories is simpler and more maintainable. He also notes that Patrick’s earlier fix (adding `ruby`) becomes redundant if Asciidoctor is installed via `apt`, since the system package already pulls in Ruby as a dependency. However, he acknowledges that Patrick’s patch remains harmless and keeps the door open for `gem`-based workflows.

The series is small and targeted, touching only the CI dependency installation script. It carries no risk of breaking the documentation build, as Peff confirms he builds the docs locally without the `concurrent-ruby` gem (introduced in 2024 for synopsis typesetting) and questions whether it is still necessary. Jean-Noël Avila is CC’d for input on the gem’s relevance, but the patches themselves do not depend on his reply. The series is ready for review and uncontroversial in its goal; the only open question is whether the `concurrent-ruby` gem can be dropped, which is a minor detail rather than a blocker.
