This is patch 6/13 in the v2 series refactoring the object database (ODB) subsystem to remove ad-hoc in-memory source registration. The patch removes the now-unnecessary registration of submodule object databases as alternates in `git grep`.

The change is straightforward: `builtin/grep.c` no longer calls `odb_add_submodule_source_by_path()` to register the submodule’s ODB with the main repository’s ODB. This cleanup is possible because earlier work (commit 0693806bf8, 2021) ensured that `git grep` passes submodule repositories directly to worker threads, allowing them to look up objects in the correct repository without relying on alternates. The patch also updates a NEEDSWORK comment to reflect the remaining thread-safety concern (initializing the subrepository still requires the object-read lock due to `get_main_ref_store()`).

The diff removes 20 lines and adds 6, simplifying the code while preserving functionality. Junio C Hamano’s substantive review of this patch in v1 ("Yay. Very nice.") suggests the change is uncontroversial. The patch is part of the broader ODB abstraction effort and the `the_repository` removal initiative, but it stands alone as a targeted cleanup in `git grep`. No behavioral changes are expected, and the patch does not introduce new dependencies. The only remaining thread-safety issue (the `obj_read_lock()`) is noted but not addressed here, as it is outside the scope of this series.
