This thread is about a two-patch series from Jeff King (Peff) that fixes a memory leak in Git’s submodule error path. The leak, flagged by Coverity after nearby code changes made it visible, occurs when a URL string allocated during repository setup isn’t freed if the setup fails. The series also includes defensive groundwork to make `repo_clear()` idempotent.

The patches themselves are uncontroversial: the first makes `repo_clear()` safe to call twice, and the second adds the missing `free()` call in `submodule--helper` along with a test to verify the fix. No objections or alternative proposals have been raised, and the series is under review with no merge status changes. Patrick Steinhardt’s recent review focused on a minor robustness improvement—initializing the `ret` variable to silence compiler warnings—but framed it as a non-blocking nit. The patch remains ready for merging once this suggestion is addressed or declined.

The thread also included an exploratory discussion between Peff and Patrick about deeper cleanup opportunities, such as eliminating a redundant `repo` pointer in the `parsed_object_pool` API or addressing circular header dependencies. While both agreed on the goal of reducing subsystem coupling, they differed on approach: Peff favored incremental changes (e.g., pool-based lookup functions), while Patrick advocated for a more decisive refactoring. No actionable patches have emerged from this discussion, and it remains a technical note for future work rather than a blocker for the current series.
