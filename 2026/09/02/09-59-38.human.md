This is a CI/build system patch, part of Jeff King’s two-patch series (`peff/ci-asciidoctor-bump`) to modernize GitLab CI’s Asciidoctor installation. The series is now complete and uncontroversial, with this email marking the final acknowledgment from Patrick Steinhardt.

The patch replaces the manual `gem install asciidoctor -v 1.5.8` with `apt-get install asciidoctor`, using the Ubuntu image’s default version (2.0.20). This eliminates an outdated version pin (1.5.8, from 2018) and simplifies CI configuration by relying on the system-provided package. The change aligns CI with user environments, where newer Asciidoctor versions are standard, and reduces maintenance overhead. Jeff King’s earlier validation (via GitHub Actions) confirms the system version works without issues.

Patrick’s email addresses two tangential concerns raised earlier: forward compatibility with older Asciidoctor versions and the unexplained `concurrent-ruby` gem dependency. On compatibility, he agrees with Jeff that testing 1.5.8 is unnecessary, as the only significant breaking changes occurred in 2.0.0. Bug reports from users on outdated versions can be handled reactively. The `concurrent-ruby` gem, introduced in September 2024 for Jean-Noël Avila’s synopsis-style documentation conversion, remains installed but its purpose is still undocumented. Jeff refers Patrick to his cover letter for context, but the explanation isn’t repeated here. This loose end doesn’t block the patch but may warrant follow-up if its necessity remains unclear.

The patch itself is a straightforward, low-risk update. Junio C Hamano’s earlier endorsement and the lack of technical objections suggest it’s ready for merging. The only remaining step is Junio’s review, which is expected to be a formality given the series’ alignment with project goals (simplifying CI, testing modern versions).
