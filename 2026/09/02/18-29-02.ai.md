This is the first patch in a two-patch series (v4) that refines exit code conventions for `git stash apply`, `pop`, and `branch`. The patch introduces an explicit `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) to distinguish between clean application, conflicts, and other errors. It updates the stash subcommands to exit with status 1 for conflicts (mirroring `git merge-tree` and merge strategies) and status 128 (or another non-zero value) for other failures, replacing the previous ambiguous exit code (1 for both conflicts and errors). The documentation in `git-stash.adoc` is updated to reflect this convention.

The patch touches `builtin/stash.c`, `sequencer.c`, `sequencer.h`, and introduces a new header `stash.h` to define the enum. The in-process autostash helpers (`apply_save_autostash_oid()`, `apply_save_autostash_ref()`) now use the enum to distinguish conflicts from other failures, and `cmd_stash()` maps negative return values to 128 while passing through positive values (1 for conflicts). The test suite (`t/t3903-stash.sh`) is updated to validate the new exit codes, including coverage for `stash pop` and `stash branch`.

This patch is uncontroversial and ready for merging. All design questions (exit code convention, correctness of conflict detection, API design) were resolved in prior iterations by Junio C Hamano and Phillip Wood. The changes are mechanical and well-tested, focusing on the stash subsystem without altering the underlying conflict resolution logic. The new enum and exit code convention are a clear improvement over the previous ambiguous behavior.
