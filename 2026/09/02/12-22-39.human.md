This is a bugfix patch that plugs a memory-safety hole in Git’s pathspec matching logic.

The bug surfaces when a negative pathspec (marked with `PATHSPEC_EXCLUDE`) is shorter than the common prefix derived from positive pathspecs. The code then reads past the end of the negative pathspec’s buffer, potentially causing a crash or incorrect results. The patch reproduces the issue with a simple test case: a deep directory tree and a short exclude pattern (`:(exclude)xy`) that triggers the out-of-bounds read.

The fix itself is a one-line change in `dir.c`: when matching negative pathspecs, the code now passes a zero prefix instead of the common prefix derived from positive pathspecs. A new regression test in `t/t6132-pathspec-exclude.sh` verifies that the fix works and that the bug does not reappear.
