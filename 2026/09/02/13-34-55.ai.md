This is the seventh patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove the ad-hoc mechanism for registering submodule sources. The patch is a cleanup step that deletes the now-unused infrastructure for registering submodule ODBs as in-memory sources, following the removal of its last two callers in earlier patches.

The patch removes the `odb_add_submodule_source_by_path()` function, the `submodule_source_paths` string list from `struct object_database`, and the `register_all_submodule_sources()` helper from `odb.c`. It also deletes the `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test mode, which was introduced as a transitional safeguard to catch any lingering uses of the mechanism. The test mode is now obsolete, so the patch removes its documentation from `t/README` and its exports from seven test scripts (`t/t5526-fetch-submodules.sh`, `t/t5531-deep-submodule-push.sh`, `t/t5545-push-options.sh`, `t/t5572-pull-submodule.sh`, `t/t6437-submodule-merge.sh`, `t/t7418-submodule-sparse-gitmodules.sh`, and `t/t7814-grep-recurse-submodules.sh`).

The changes are mechanical and uncontroversial: the commit message explains that the mechanism was a transitional crutch (introduced in commit a35e03dee0, 2021) to migrate submodule object access away from implicitly linking submodule ODBs as alternates of `the_repository` toward explicitly passing submodule repositories. With that migration complete, the infrastructure is no longer needed. The patch touches only the ODB internals and test scripts, with no behavioral changes or on-disk format implications. The test suite continues to pass, confirming the cleanup is safe. This patch is a prerequisite for the final removal of the ad-hoc source linking API in patch 13/13.
