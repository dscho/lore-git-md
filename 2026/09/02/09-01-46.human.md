This is a CI/build system patch, part of Jeff King’s two-patch series (`peff/ci-asciidoctor-bump`) that modernizes GitLab CI’s Asciidoctor version handling. The series is a follow-up to Patrick Steinhardt’s earlier fix (`ps/ci-depends-on-ruby`), which restored Ruby availability after a transitive dependency removal broke the documentation build.

The patch itself is uncontroversial and ready for merging. It replaces the manual installation of Asciidoctor 1.5.8 (a version from 2018) with the system-provided package in the Ubuntu CI image, currently version 2.0.20. This eliminates an outdated version pin and simplifies the CI script, aligning the tested version with what users are likely to have installed locally. The change is low-risk: the system version is known to work, and GitHub Actions already tests with the same version.

Jeff’s reply here addresses two tangential concerns Patrick raised in his review. First, Patrick worried that using a modern Asciidoctor version might introduce dependencies on features unavailable in older versions, silently breaking builds for users with outdated installations. Jeff dismisses this as unlikely to be a practical problem, noting that v1.5.8 is very old and the next version (2.0.0) was the only one with a significant risk of breaking changes. Second, Patrick questioned why the `concurrent-ruby` gem is still installed even though Ruby itself is no longer needed for Asciidoctor. Jeff points to his cover letter for context, but the cover letter does not explain the gem’s purpose either—it was introduced in September 2024 for Jean-Noël Avila’s synopsis-style documentation conversion, but the rationale remains unclear.

The patch is a straightforward maintenance update with no technical blockers. The concerns Patrick raised are valid but orthogonal to the immediate change and do not require action before merging. The series has already received Junio C Hamano’s endorsement, and the only remaining step is his formal review before merging to `master`.
