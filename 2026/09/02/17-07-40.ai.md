This is a review reply from Junio C Hamano to a bugfix patch targeting Git's directory traversal logic. The patch fixes an edge case in `common_prefix_len()` where an exclude pathspec appearing first in the list incorrectly causes the function to return zero as the common prefix length, even when subsequent positive pathspecs share a directory.

Junio's review is substantive and technical. He raises two main concerns: first, the patch's use of "based on" in the commit message is ambiguous, and he clarifies that this phrasing should only be used when a patch depends on another (not merely when it follows one). Second, and more significantly, he questions the design of the new `pathspec_prefix` struct and its return-by-value, suggesting instead that the function should return the common prefix length directly and pass the match string via an output parameter. This approach would minimize changes to existing callers, which currently assume they can use `pathspec->items[0].match` as the common prefix.

The review does not reject the patch but proposes a simpler alternative implementation that would reduce churn in the calling code. The discussion is now focused on whether the struct-based approach is justified or whether the output-parameter alternative would be cleaner. No other reviewers have weighed in yet, and the patch remains under active discussion.
