This is the **sixth and final patch** in Christian Couder's series introducing the new `early_scan_options()` API for early argument scanning in Git's `parse-options` subsystem. This patch converts `git fast-import` to use the new API, fixing a bug where `--allow-unsafe-features` was silently ignored when it appeared after an option whose value was given as a separate argument (e.g., `--depth 5 --allow-unsafe-features`).

The bug occurs because `git fast-import` processes "feature" lines at the start of its input stream before parsing command-line options, so it must scan `argv` early to detect `--allow-unsafe-features`. The old hand-rolled scan stopped at the first non-option argument (like `5` in `--depth 5`), missing the flag entirely. The new API, built from the same `struct option` array used by `parse_options()`, correctly handles option values separated by spaces, ensuring the early scan and full parsing agree.

The patch also updates the documentation to clarify that `--allow-unsafe-features` must be spelled in full (unambiguous abbreviations like `--allow-unsafe` are rejected for safety). The implementation is clean: it defines a minimal `early_wanted` list and a callback (`option_parse_early_allow_unsafe`) to set the flag, then replaces the manual loop with a call to `early_scan_options_from_options()`. New tests in `t/t9300-fast-import.sh` verify the fix and the full-spelling requirement.
