This is a refactoring patch that moves the global `grafts_keep_true_parents` configuration variable into the repository-specific `repo_config_values` struct as part of the ongoing `the_repository` removal effort. The patch introduces a new getter function `repo_grafts_keep_true_parents(repo)` to safely access the value, falling back to 0 if the repository is uninitialized. It updates two call sites: `commit.c` now uses the repository-aware getter, while `builtin/pack-objects.c` binds the `--keep-true-parents` option directly to the config struct and adds a NULL guard to handle invocations outside a repository context.

The change is mechanical and well-scoped, touching only the environment and configuration layers. The commit message clearly explains the motivation (repository-specific configuration) and the safety measures (NULL guard, fallback value). The patch itself is clean: it removes the global variable, adds the field to the config struct, and updates the callers with minimal disruption. No behavior change is introduced, and the test coverage for graft handling should continue to apply.

This is the first patch in a two-patch series; the cover letter or second patch is not included here, so the broader goal of the series remains unclear. The patch stands on its own as a small but meaningful step toward eliminating global state.
