This patch introduces a new configuration option `hooks.allowNoVerify` that acts as a guardrail to prevent accidental bypass of hooks via the `--no-verify` (`-n`) flag in commands like `git commit`, `git push`, `git merge`, and `git rebase`. The setting defaults to `true` (allowing `--no-verify` as before) but can be set to `false` to enforce hook execution, which is useful in managed environments or CI workflows where hook bypass should be controlled. The patch includes documentation, updates to the relevant built-in commands, and a comprehensive test suite covering edge cases like CLI overrides, local vs. global config precedence, and hook failure scenarios.

The implementation touches multiple subsystems (`builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/push.c`, `builtin/rebase.c`) and adds a new config file (`Documentation/config/hooks.adoc`). The tests verify that the setting works as expected across all affected commands and that it does not interfere with normal hook execution when `--no-verify` is not used. The commit message clarifies that this is an opt-in workflow feature and does not alter Git’s server-side security model. The patch is well-structured, with clear documentation and thorough test coverage, suggesting it addresses a real need in controlled environments.
