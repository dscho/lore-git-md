This thread is about a proposed `--draft` option for `git imap-send`, allowing uploaded messages to be marked with the IMAP `\Draft` flag so clients treat them as editable drafts rather than sent mail. Wolfgang Faust sent a single-patch implementation that adds the flag, updates the man page, and uses a compatibility macro to guard the new libcurl feature (`CURLOPT_UPLOAD_FLAGS`). The default is `--no-draft` to avoid breaking existing workflows.

Junio C Hamano reviewed the patch and suggested design improvements, including failing fast (erroring out) rather than warning when `--draft` is used with older libcurl versions—a change Wolfgang agreed to make. Junio also floated the idea of a configuration variable (`imap.draft`) but didn’t insist on it, noting the project’s preference for introducing behavior via flags first. Aditya Garg raised a forward-compatibility concern about the libcurl 8.13.0 dependency, citing a 2024 precedent where a similar requirement was rejected. Junio’s latest reply clarifies that the patch fails fast on older versions, addressing Aditya’s objection about silent breakage, but the broader question of whether the version requirement is acceptable remains unresolved. The thread is still under review, with no consensus on a configuration variable or a potential future default flip to `--draft`.
