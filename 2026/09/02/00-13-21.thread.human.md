This thread is about adding a `--draft` option to `git imap-send` so that messages uploaded to an IMAP server can be marked with the `\Draft` flag, making them editable in email clients. Wolfgang Faust proposed the feature in a single patch that touches `imap-send.c`, its man page, and a compatibility header, introducing a new `--[no-]draft` flag (defaulting to `--no-draft`) and using libcurl’s `CURLOPT_UPLOAD_FLAGS` when available.

Junio C Hamano reviewed the patch and raised two concerns: whether defaulting to `--draft` could break existing workflows (e.g., tools like `git send-email --imap-sent-folder` that upload already-sent messages), and whether the tool should fail fast or just warn when `--draft` is used with an older libcurl version. Wolfgang responded by agreeing that `--no-draft` is the safer default to avoid disrupting current behavior, and he now prefers failing fast over issuing a warning for unsupported libcurl versions. He remains hesitant about adding a configuration variable, citing workflow consistency and the project’s preference for flags over configuration. The patch is still under review, with no additional feedback from other participants.
