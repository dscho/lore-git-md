This thread is about a small but useful feature for `git imap-send`: adding a `--draft` flag to mark uploaded messages with the IMAP `\Draft` flag, so IMAP clients treat them as editable drafts rather than sent mail. Wolfgang Faust proposed the patch, which touches only `imap-send.c`, its man page, and a compatibility header. The patch is under review and hasn’t been revised yet.

The implementation is straightforward—it adds a new `--[no-]draft` option (defaulting to off to avoid breaking existing workflows) and uses libcurl’s `CURLOPT_UPLOAD_FLAGS` (introduced in libcurl 8.13.0) to set the draft flag. Junio C Hamano reviewed it and suggested failing fast if `--draft` is used with an older libcurl, which Wolfgang agreed to implement. Junio also floated the idea of a future configuration variable (`imap.draft`) but didn’t push for it, noting the project’s preference for flags-first.

The only open question is whether the libcurl version requirement (8.13.0, released April 2025) is too recent. Aditya Garg raised this in a brief reply, citing a 2024 precedent where a similar dependency was rejected. His feedback is cautious but doesn’t propose alternatives or challenge the feature itself. The rest of the discussion—default behavior, error handling, and configuration—remains settled for now. No other reviewers have weighed in yet.
