This thread is about adding a `--draft` option to `git imap-send` so that uploaded messages can be marked with the IMAP `\Draft` flag, making them editable in IMAP clients. Wolfgang Faust proposed the feature in a single patch that touches `imap-send.c`, its man page, and a compatibility header. The patch introduces a new `--[no-]draft` flag (defaulting to `--no-draft` to avoid breaking existing workflows) and uses libcurl’s `CURLOPT_UPLOAD_FLAGS` to set the `\Draft` flag when available.

Junio C Hamano reviewed the patch and raised design concerns, particularly about error handling. Wolfgang agreed to update the patch to fail fast (error out) rather than warn when `--draft` is used with libcurl versions older than 8.13.0, addressing Junio’s preference. Junio also clarified that this fail-fast behavior distinguishes the patch from a 2024 precedent where a similar version requirement was rejected for silent breakage. The patch remains under review, with no merge status reported.

The main open questions are whether to introduce a configuration variable (e.g., `imap.draft`) to control the behavior (Junio suggested it, but Wolfgang is hesitant, citing workflow consistency concerns) and whether the libcurl 8.13.0 requirement is acceptable for a new feature. Aditya Garg raised a surface-level concern about the version requirement, but Junio’s clarification about the fail-fast behavior addressed it. No consensus has been reached on these points, and the thread is stalled on the version requirement and design questions. Wolfgang and Junio are the key participants, with Aditya’s input limited to the version requirement.
