This thread is about a bugfix series from Yannik Tausch that addresses edge cases in Git's pathspec handling, specifically around how exclude pathspecs (like `:!unwanted/path`) interact with common prefix calculations. The series has evolved into three logical patches: a preparatory refactoring by Junio C Hamano, a memory-safety fix, and the core fix for the common prefix logic. The patches are now queued for merging, with Junio creating a synthetic merge base to apply them cleanly.

The bug occurs when an exclude pathspec appears first in the list, causing `common_prefix_len()` to incorrectly return zero as the common prefix length even when subsequent positive pathspecs share a directory. The fix ensures the function correctly computes the common prefix of positive pathspecs and avoids applying this prefix to negative pathspecs, preventing both memory-safety issues and false positives in matching. The series includes comprehensive test coverage, including regression tests for the heap-buffer-overflow and deterministic test cases for the false-positive bug.

Key participants include Yannik (the author), Junio (the maintainer), and Elijah Newren, who provided substantive reviews. Junio recently clarified the technical intent of the core fix, noting that the bug was narrower than initially described—it affects the string returned by `common_prefix()` rather than traversal behavior. This clarification doesn’t change the patch’s readiness for merging but helps future readers understand its scope. The series is now fully queued, with no further changes expected.
