This thread is a bugfix series for a long-standing edge case in Git's pathspec handling, authored by Yannik Tausch and now queued for merging by maintainer Junio C Hamano. The series fixes three related issues: a memory-safety bug (heap-buffer-overflow) in `match_pathspec_with_flags()` when negative pathspecs are shorter than the common prefix of positive pathspecs, a logical bug where the common prefix derived from positive pathspecs was incorrectly applied to negative pathspecs (causing false positives), and an edge case in `common_prefix_len()` where an exclude pathspec appearing first in the list caused the function to return an empty string instead of the common prefix of positive pathspecs (e.g., `a/` from `a/b` and `a/c`).

The series is effectively a three-patch sequence in Junio's queue, though the author sent it as two patches (v3). The first patch is a preparatory refactoring to declare `match` and `original` fields in `struct pathspec_item` as `const char *`, resolving a compiler warning in the unit tests. The second patch fixes the memory-safety and false-positive bugs in `match_pathspec_with_flags()`, while the third corrects the `common_prefix()` edge case. Junio created a synthetic merge base (`d66ac2af30`) to apply the two-patch series cleanly on top of the preparatory patch, and the author has confirmed the v3 iteration is unchanged from v2 and ready for integration. Elijah Newren's review identified a gap in the regression test for the heap-buffer-overflow (it only fails deterministically under AddressSanitizer), but this does not block the series from merging, as the existing test coverage is sufficient for regression detection.

The latest email clarifies a minor point about the pre-patch behavior: `common_prefix_len()` returned an empty string—not a bogus string derived from the exclude pathspec—when the first pathspec item was excluded. This refines the bug's description but does not affect the fix's correctness. The series touches `dir.c`, `pathspec.c`, and related test files, with new functional and unit tests covering all three bugs. No further technical changes or author action are expected, and the series is now fully queued for integration.
