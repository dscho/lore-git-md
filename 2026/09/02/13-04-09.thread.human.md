This thread is about a bugfix patch from Yannik Tausch that corrects a long-standing edge case in Git's pathspec handling. The issue occurs in `common_prefix_len()` when an exclude pathspec (like `:!unrelated/path`) appears first in the list—this would incorrectly cause the function to return zero as the common prefix length, even if later positive pathspecs (such as `foo/bar` and `foo/baz`) share a directory (`foo/`). The fix rewrites the logic to track the first *positive* pathspec explicitly, using a new `pathspec_prefix` struct to return both the match string and the common prefix length. The patch updates `common_prefix()` and `fill_directory()` to use this new structure and includes a unit test in `t/unit-tests/u-dir.c` to verify the fix.

The change is narrowly scoped to `dir.c` and the unit test file, with no broader behavior changes outside the fixed edge case. The commit message is clear, and the test coverage is appropriate. So far, there’s been no review feedback on the patch, so its status remains under initial review. If you’ve encountered issues with pathspec excludes interfering with directory traversal, this fix may resolve them.
