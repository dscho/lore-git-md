This is the second patch in a two-patch **v4** series refining `git checkout -m` behavior when autostash is involved. The series is uncontroversial and ready for merging, with all prior review feedback addressed.

This patch focuses on **visual separation of autostash conflict advice** from the branch-switch confirmation message. When `git checkout -m` applies an autostash and encounters conflicts, the advice on resolving them is currently printed directly above the "Switched to branch ..." message, making the two hard to distinguish. The patch adds a blank line between them by checking the return value of `apply_autostash_ref()` (now an `enum stash_apply_result`) and printing a newline to `stderr` only when conflicts occur (`STASH_APPLY_CONFLICT`).

The change is minimal and targeted: it touches only `builtin/checkout.c` (adding the newline logic) and updates the test in `t/t7201-co.sh` to validate the new output format using `test_cmp`. The test now explicitly checks for the blank line and the full advice message, ensuring the visual separation is preserved. The patch does not alter the underlying conflict resolution logic or exit codes (those are handled in patch 1).

The motivation is purely ergonomic: reducing visual clutter for users who encounter conflicts during `checkout -m`. The implementation is straightforward and leverages the new `enum stash_apply_result` introduced in patch 1 to distinguish conflicts from other outcomes. The test coverage is thorough, including the full screen output and edge cases.

This patch is a clean, well-motivated improvement to the user experience of `git checkout -m`. It complements patch 1 (which aligns exit codes with Git’s conventions) and completes the series. No further changes are expected.
