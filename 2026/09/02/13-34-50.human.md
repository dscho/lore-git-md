This is the second patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. It focuses on the cache-tree subsystem, removing its dependency on the `the_repository` global variable by adapting it to use repositories provided via context (either as a new parameter or through `struct index_state`).

The patch is a targeted refactoring that eliminates implicit global state dependencies in `cache-tree.c` and related callers. It updates functions like `update_one()`, `write_one()`, and `read_one()` to accept a `struct repository *` parameter, ensuring they operate on the correct repository context rather than `the_repository`. The `must_prefetch_predicate` callback type is also extended to include a `void *cb_data` parameter, allowing repository context to be passed through. The changes touch five files (`cache-tree.c`, `cache-tree.h`, `read-cache-ll.h`, `read-cache.c`, and `unpack-trees.c`), with no behavioral changes expected—this is purely a cleanup to support the broader ODB abstraction effort.

This patch is part of the ongoing `the_repository` removal effort (driven by René Scharfe) and is a prerequisite for later patches in the series that remove the mechanism for registering submodule ODB sources. The commit message highlights a key correctness improvement: the patch ensures that reading gitmodules from a submodule’s index no longer implicitly depends on `the_repository`, which was previously masked by the now-obsolete submodule ODB registration mechanism. The author notes that tests with `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB=true` now pass, confirming the dependency has been eliminated.

The patch is well-motivated and aligns with the series’ goal of simplifying the ODB subsystem. It builds on the v2 revision of patch 1/13 (which addressed Junio C Hamano’s feedback on correctness issues) and sets the stage for the remaining patches, which remove the ad-hoc source linking API entirely. No new objections or design concerns have surfaced, and the changes are mechanical and self-contained. The series as a whole remains under review, but this patch looks uncontroversial and ready for integration.
