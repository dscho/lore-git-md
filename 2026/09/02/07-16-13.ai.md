This is the second patch in Jeff King’s two-patch CI/build system series (`peff/ci-asciidoctor-bump`). It proposes switching GitLab CI’s documentation build from a pinned, manually installed Asciidoctor version (1.5.8) to the version provided by the Ubuntu system package manager. The change removes the explicit `gem install` step and instead installs `asciidoctor` via `apt-get`, relying on the Ubuntu image’s default version (2.0.20 in the GitHub Actions test run). The patch is small, mechanical, and directly addresses the outdated version pin discussed in the earlier thread.

The motivation is clear: the current pin (1.5.8, from 2018) is no longer necessary, as Git’s documentation has been compatible with Asciidoctor 2.0.x since 2019. Using the system package simplifies the CI script, reduces maintenance burden, and ensures the build tests a version closer to what users are likely to have installed locally. Jeff’s commit message and test confirmation (GitHub Actions using 2.0.20) demonstrate that the change is low-risk and well-validated.

This patch is uncontroversial and ready for merging. It complements the first patch in the series (which removed dead code from the retired Azure Pipelines CI) and completes the modernization of the Asciidoctor installation logic. The only remaining loose end from the thread—whether the `concurrent-ruby` gem is still needed—is unrelated to this patch and does not block its progress. The series as a whole is a straightforward, high-value maintenance update.
