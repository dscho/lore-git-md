This is the second patch in a two-part series that tidies up the output of `git checkout -m` when autostash conflicts occur. The goal is purely visual: when Git stashes your local changes, switches branches, and then fails to reapply the stash cleanly, it currently prints the conflict advice ("Your local changes are stashed...") immediately above the branch-switch confirmation ("Switched to branch..."), making the two messages hard to distinguish. This patch inserts a blank line between them so the advice stands out clearly.

The change is small and focused. It adds a single `fputc('\n', stderr)` call in `builtin/checkout.c` when the autostash helper reports a conflict (`STASH_APPLY_CONFLICT`). The test in `t/t7201-co.sh` is updated to verify the exact screen output, including the new blank line, using `test_cmp` against a carefully constructed expected string. The patch is uncontroversial; all design questions were settled in earlier iterations, and this version incorporates the final mechanical adjustments requested by reviewers.

This is a quality-of-life improvement for users who encounter conflicts during `git checkout -m`. The underlying conflict resolution logic is unchanged, so there is no risk of regressing behavior. The patch is well-tested and ready for merging.
