Core problem or goal
Introduce a new configuration option `hooks.allowNoVerify` that allows administrators to prevent accidental or intentional bypass of client-side hooks via the `--no-verify` (`-n`) flag in `git commit`, `git push`, `git merge`, `git rebase`, and `git am`. The setting is opt-in (defaults to `allow` for backward compatibility) and is intended for managed environments or CI workflows where hook execution must be enforced. The v2 patch adds three-tiered control (`allow`/`warn`/`error`) and emergency override mechanisms to address feedback from the initial submission.
