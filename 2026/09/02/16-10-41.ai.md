This is a **bugfix and API refactoring series** introducing a new `parse-options` sub-API for early argument scanning. The series targets a recurring class of argument-parsing bugs where hand-rolled early scans (looking for `--` or special flags) fail to account for option values that appear as separate arguments, causing misparsing or silent misbehavior.

The core of the series is a new `early_scan_options()` function that performs a fast, limited scan of `argv` to locate specific long options, ignoring short options, abbreviations, and some edge-case option types (like `PARSE_OPT_OPTARG`). A helper, `early_scan_options_from_options()`, bridges the new API with existing `struct option` arrays, allowing commands that already use `parse-options` to adopt the early scan without rewriting their option tables. The series converts three commands (`git bisect`, `git rev-parse`, and `git fast-import`) to the new API, fixing concrete bugs in each:

- `git bisect start --term-good -- <not-a-rev>` previously mistook the term name `--` for the revision/path separator, rejecting `<not-a-rev>` as an invalid revision.
- `git rev-parse --default -- <not-a-rev>` made the same mistake, producing a confusing "bad revision" error instead of the usual "ambiguous argument" message.
- `git fast-import --depth 5 --allow-unsafe-features` silently ignored `--allow-unsafe-features`, refusing unsafe features from the input stream.

The series is well-motivated and clearly scoped. The commit messages explain the bugs, the limitations of the new API, and why a full refactor of `parse_options()` was avoided. Test coverage is thorough, with new tests for each bug and a dedicated test helper (`test-parse-options`) exercising the new API. The CI run (linked in the cover letter) passed cleanly.

This is a **substantive, well-crafted contribution** that addresses a real problem without over-engineering. The new API is deliberately minimal, and the series confines itself to fixing the immediate bugs rather than attempting a broader refactor. The patches touch core argument-parsing infrastructure, so they will likely attract close review, but the design looks sound and the implementation is clean. The series is **worth attention** from anyone interested in Git's command-line parsing or the affected commands.
