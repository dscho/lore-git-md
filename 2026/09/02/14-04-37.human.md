This is a bug report about an inconsistency in how Git handles commit messages between `git commit` and `git merge`. The author, Simon Cheng, describes a scenario where a `prepare-commit-msg` hook behaves differently for merge commits compared to regular commits due to a missing trailing newline in the merge case.

The issue arises when using `commit.cleanup = strip` and a `prepare-commit-msg` hook that appends comments to the commit message file. For regular commits, Git appends a newline to the message before cleanup, ensuring the hook's comments are on a new line and thus stripped. However, for merge commits created with `git merge --no-ff -m "MSG"`, no newline is appended, causing the hook's comments to be concatenated with the message and preserved after cleanup. The author provides clear reproduction steps and demonstrates the unexpected behavior with `git show`.

The report is well-structured, with a concise explanation of the problem, expected vs. actual behavior, and system details. While the author acknowledges the issue might be edge-casey (their hook could handle the newline), they argue the inconsistency is surprising and worth fixing. The patch itself isn't provided here, but the report makes a compelling case for why this behavior should be unified. Worth attention from anyone working on commit or merge internals.
