This is a bugfix for the `git history` command, which was introduced in Git 2.46. The patch prevents a crash when the parent commit's tree object is missing from the object store (e.g., due to repository corruption, tooling removal, or an incomplete restore). Without the fix, `git history split` dereferences a NULL pointer returned by `repo_parse_tree_indirect()`, causing a SIGSEGV in release builds or a UBSan null-pointer access report.

The fix is minimal and follows Git's established pattern for handling missing objects: it checks the return value of `repo_parse_tree_indirect()` and errors out gracefully with a descriptive message. The reproduction steps are clear and demonstrate the issue reliably. The commit message and in-email explanation are both thorough, including the security team's guidance that this isn't considered a security issue.
