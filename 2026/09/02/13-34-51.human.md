This is part of Patrick Steinhardt’s ongoing ODB abstraction and `the_repository` removal effort. Specifically, this is patch 3/13 in the v2 series refactoring the object database subsystem to remove ad-hoc source linking.

The patch removes implicit dependencies on `the_repository` in the `submodule-config` subsystem. It updates several functions to accept a `struct repository *` parameter instead of relying on the global `the_repository`. Callers are adapted to pass `the_repository` explicitly, though the patch notes this is a transitional step—future work may pass more specific repositories where available. The changes touch seven files: `builtin/fetch.c`, `builtin/grep.c`, `builtin/submodule--helper.c`, `submodule-config.c`, `submodule-config.h`, `submodule.c`, and `t/helper/test-submodule.c`.

The refactoring is mechanical and well-scoped, with no behavioral changes expected. It continues the pattern established in earlier patches (e.g., patches 1 and 2 in this series) of encapsulating repository dependencies within subsystems rather than exposing them globally. The patch is part of a larger goal to simplify the ODB codebase by eliminating dual-use of the ODB sources list for both alternates and temporary in-memory sources (like submodules).

No substantive review feedback has surfaced yet for this patch, but the series as a whole has Junio C Hamano’s approval on earlier patches, suggesting this is uncontroversial cleanup. The patch is a clear step toward the series’ goal and looks ready for integration.
