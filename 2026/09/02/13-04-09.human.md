This is a bugfix patch targeting the directory traversal logic in Git.

The patch addresses a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list would cause the function to incorrectly return zero as the common prefix length, even when all *positive* pathspecs share a directory. The bug occurs because the function uses the first pathspec item (regardless of whether it is excluded) as the comparison base and skips excluded items only after initializing the loop.

Yannik Tausch refactors the logic to explicitly track the first *positive* pathspec item, returning both the match string and the common prefix length in a new `pathspec_prefix` struct. The fix touches `dir.c` (the core directory traversal code) and adds a unit test in `t/unit-tests/u-dir.c` that verifies the behavior with an exclude pathspec followed by two positive pathspecs sharing a directory (`foo/bar` and `foo/baz`).

The commit message is clear and the test coverage is thorough. The change is narrowly scoped and does not appear to introduce new edge cases. This looks like a well-crafted fix for a real, if obscure, bug.
