This is a bugfix patch targeting the directory traversal logic in Git's pathspec handling.

The patch addresses a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list would cause the function to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs (e.g., `foo/bar` and `foo/baz`) share a directory (`foo/`). The bug occurs because the function uses the first pathspec item as the comparison baseline regardless of whether it is excluded, and skips excluded items only after initializing the comparison.

Yannik Tausch rewrites the logic to explicitly track the first *positive* pathspec item, returning both the match string and the common prefix length in a new `pathspec_prefix` struct. The patch updates `common_prefix()` and `fill_directory()` to use this new return value, ensuring they operate on the correct string. A new unit test in `t/unit-tests/u-dir.c` verifies the fix with a scenario where an unrelated exclude pathspec precedes two positive pathspecs that share a directory.

The commit message is clear and the test coverage is appropriate. The change is localized to `dir.c` and the unit test file, with no behavior changes outside the fixed edge case. This looks like a well-motivated, low-risk fix for a subtle but real bug.
