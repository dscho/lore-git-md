Subject: [PATCH] imap-send: add --draft option to mark uploaded messages as drafts
Series version: single patch (no series)
Originating author: Wolfgang Faust <contrib-git@wolfgangfaust.com>
Thread type: feature patch

Core problem or goal
Add a `--draft` option to `git imap-send` so that uploaded messages can be marked with the IMAP `\Draft` flag. This closes a usability gap: the tool is documented for uploading draft emails, but until now lacked a way to signal draft status to IMAP clients, causing some clients to treat the messages as uneditable or unsendable even when stored in a "Drafts" folder.

Current status
Under review; no prior versions. The patch is self-contained, touching only `imap-send.c`, its man page, and a compatibility header (`git-curl-compat.h`). It introduces a new command-line flag (`--[no-]draft`), updates the documentation with libcurl version requirements (8.13.0+), and uses a compatibility macro to guard the new `CURLOPT_UPLOAD_FLAGS` feature. The IMAP code path passes the flag as part of the APPEND command; the libcurl path uses `CURLULFLAG_DRAFT` when available. Wolfgang has agreed to update the patch to fail fast (error out) rather than warn when `--draft` is used with libcurl < 8.13.0, addressing Junio’s preference. Junio C Hamano’s follow-up clarified that the patch’s **fail-fast behavior** (erroring out on older libcurl versions) distinguishes it from a 2024 precedent where a similar version requirement was rejected for silent breakage. The compatibility macro ensures the code compiles on older versions, and the runtime check prevents misuse. The default remains `--no-draft` to avoid breaking existing workflows. No merge status reported; the thread remains under review.

Key technical details
- Files touched: `Documentation/git-imap-send.txt`, `git-curl-compat.h`, `imap-send.c`
- New CLI option: `--[no-]draft` (defaults to `--no-draft`)
- New symbol: compatibility macro for `CURLOPT_UPLOAD_FLAGS` and `CURLULFLAG_DRAFT`

Open questions and loose ends

Wolfgang expressed hesitation, citing concerns about workflow consistency. No consensus has been reached, and the thread remains flag-only for now.
2. **Libcurl version requirement**: The dependency on libcurl 8.13.0 (released April 2025) remains a potential blocker. While Junio’s clarification addressed Aditya Garg’s concern about silent breakage by highlighting the fail-fast behavior, the broader question of whether this version requirement is acceptable for new features remains unresolved. No alternative implementation or fallback mechanism has been proposed. Aditya’s follow-up did not re-engage with this distinction or propose a path forward.
3. **Default flip**: The discussion remains open on whether a future version could flip the default to `--draft` if client robustness is established. No concrete plans or timelines have been proposed.
