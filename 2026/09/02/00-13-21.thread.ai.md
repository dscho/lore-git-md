Subject: [PATCH] imap-send: add --draft option to mark uploaded messages as drafts
Series version: single patch (no series)
Originating author: Wolfgang Faust <contrib-git@wolfgangfaust.com>
Thread type: feature patch

Core problem or goal
Add a `--draft` option to `git imap-send` so that uploaded messages can be marked with the IMAP `\Draft` flag. This closes a usability gap: the tool is documented for uploading draft emails, but until now lacked a way to signal draft status to IMAP clients, causing some clients to treat the messages as uneditable or unsendable even when stored in a "Drafts" folder.

Current status
Under review; no prior versions. The patch is self-contained, touching only `imap-send.c`, its man page, and a compatibility header (`git-curl-compat.h`). It introduces a new command-line flag (`--[no-]draft`), updates the documentation with libcurl version requirements (8.13.0+), and uses a compatibility macro to guard the new `CURLOPT_UPLOAD_FLAGS` feature. The IMAP code path passes the flag as part of the APPEND command; the libcurl path uses `CURLULFLAG_DRAFT` when available, falling back to a warning on older libcurl versions. Wolfgang has agreed to update the patch to fail fast (error out) rather than warn when `--draft` is used with libcurl < 8.13.0, addressing Junio’s preference. The default remains `--no-draft` to avoid breaking existing workflows.

Key technical details
- Files touched: `Documentation/git-imap-send.txt`, `git-curl-compat.h`, `imap-send.c`
- New CLI option: `--[no-]draft` (defaults to `--no-draft`)
- New symbol: compatibility macro for `CURLOPT_UPLOAD_FLAGS` and `CURLULFLAG_DRAFT`
- On-disk format: unchanged; the change affects only IMAP server-side flags
- Test coverage: none; manual testing recommended by the author

Open questions and loose ends
1. **Configuration variable**: Junio C Hamano suggested a configuration variable (e.g., `imap.draft`) to control the behavior, but Wolfgang expressed hesitation, citing the project’s preference for introducing flags before configuration and concerns about workflow consistency. No consensus has been reached on this point.
2. **Forward compatibility**: The default behavior (`--no-draft`) is now settled, but the discussion remains open on whether a future version could flip the default to `--draft` if client robustness is established. No concrete plans or timelines have been proposed.

Participant positions
- **Wolfgang Faust**: Proposes the feature and has agreed to update the patch to fail fast on older libcurl versions. Prefers `--no-draft` as the default to avoid breaking existing workflows and is hesitant about introducing a configuration variable at this stage.
- **Junio C Hamano**: Reviewed the patch and raised design-level concerns about default behavior and error handling. Prefers failing fast over warning when `--draft` is used with older libcurl versions. Suggested a configuration variable but did not insist on it. No objections to the current default (`--no-draft`).
