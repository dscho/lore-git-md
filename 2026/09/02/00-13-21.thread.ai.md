Subject: [PATCH] imap-send: add --draft option to mark uploaded messages as drafts
Series version: single patch (no series)
Originating author: Wolfgang Faust <contrib-git@wolfgangfaust.com>
Thread type: feature patch

Core problem or goal
Add a `--draft` option to `git imap-send` so that uploaded messages can be marked with the IMAP `\Draft` flag. This closes a usability gap: the tool is documented for uploading draft emails, but until now lacked a way to signal draft status to IMAP clients, causing some clients to treat the messages as uneditable or unsendable even when stored in a "Drafts" folder.

Current status
Under review; no prior versions. The patch is self-contained, touching only `imap-send.c`, its man page, and a compatibility header (`git-curl-compat.h`). It introduces a new command-line flag (`--[no-]draft`), updates the documentation with libcurl version requirements (8.13.0+), and uses a compatibility macro to guard the new `CURLOPT_UPLOAD_FLAGS` feature. The IMAP code path passes the flag as part of the APPEND command; the libcurl path uses `CURLULFLAG_DRAFT` when available. Wolfgang has agreed to update the patch to fail fast (error out) rather than warn when `--draft` is used with libcurl < 8.13.0, addressing Junio’s preference. The default remains `--no-draft` to avoid breaking existing workflows. Junio C Hamano’s follow-up reinforces the project’s preference for introducing behavior via flags before configuration, noting that Wolfgang’s adherence to this guideline is a positive exception, though the thread remains flag-only for now.

Open questions and loose ends
1. **Configuration variable**: Junio C Hamano suggested a configuration variable (e.g., `imap.draft`) to control the behavior but acknowledged the project’s guideline of introducing flags first. Wolfgang expressed hesitation, citing concerns about workflow consistency. No consensus has been reached, and the thread remains flag-only for now.
2. **Forward compatibility**: The libcurl version requirement (8.13.0, released April 2025) has been flagged as a potential blocker by Aditya Garg, who cites a 2024 precedent where a patch was rejected for depending on a similarly recent libcurl version. No alternative implementation or fallback mechanism has been proposed, and the discussion remains open on whether this requirement is acceptable. The default behavior (`--no-draft`) is settled, but the viability of the feature itself may hinge on this unresolved dependency.
3. **Default flip**: The discussion remains open on whether a future version could flip the default to `--draft` if client robustness is established. No concrete plans or timelines have been proposed.
