This is a surface-level review from Junio C Hamano on the test added in patch 6/6 of Toon Claes’s `git last-modified` Bloom filter optimization series. The patch itself restores `bloom_filter_settings` after `prepare_revision_walk()` clears it for wildcard pathspecs (e.g., `*.c`) and adds trace2 instrumentation to verify the Bloom filter fast-path is triggered.

The issue is a test environment interaction: the test script exports `GIT_TEST_COMMIT_GRAPH=1` globally, which overrides the `-c core.commitGraph=false` setting in the test case. Junio points out that the test needs to explicitly unset `GIT_TEST_COMMIT_GRAPH` (to `0`) when testing the commit-graph-disabled baseline, and should be consistent about setting it (to `1`) when testing the commit-graph-enabled case. The fix is a one-line change to each of the two `git` invocations in the test, replacing implicit environment inheritance with explicit control.

This is a minor but necessary correction to ensure the test reliably exercises both code paths. The review is pragmatic and focused on test correctness rather than the patch’s core functionality. The series remains complete and ready for integration once this test fix is applied.
