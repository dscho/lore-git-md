This is the fifth and final iteration of a test infrastructure bugfix series that makes two CGI test helpers in `t/lib-httpd/` concurrency-safe. The series targets a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests triggered a race condition in the state management logic of `apply-one-time-script.sh`, causing an HTTP 500 error and a fetch failure. The fix replaces non-atomic shell operations (`test -f` followed by `rm` or `touch`) with atomic alternatives (`rm` without `-f` for the one-shot marker, `mkdir` for the first-request election), eliminating the race window. The cover letter links to recent CI failures in GitGitGadget and GitHub’s Git mirror that appear to be caused by the same issue, reinforcing the urgency.

The series is now complete. The only change since v4 is a minor rewording in the documentation patch (patch 3) to clarify that atomic operations like `rm` should be chained with "the logic guarded by the marker" rather than "the logic that claims the marker," addressing Patrick Steinhardt’s editorial feedback. The technical substance of the patches is unchanged, and all prior feedback—including Junio C Hamano’s critique of commit message verbosity and Patrick Steinhardt’s preference for contextual documentation placement—has been addressed. Junio previously marked the series as ready for integration in v2, and Patrick endorsed it as "good enough" in v3 and "a lot better now" in v4.

The patches are narrowly scoped to the test infrastructure (`t/` directory) and include a new deterministic test (`t5567-one-time-script.sh`) that directly exercises the fixed helper without a web server. The documentation update in `t/lib-httpd.sh` is a thoughtful addition, generalizing the atomic patterns for future test helpers. The series looks well-crafted, thoroughly tested, and unlikely to be controversial. It is ready for integration into `next`.
