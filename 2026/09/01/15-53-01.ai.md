This is the first patch in a three-patch bugfix series targeting test infrastructure. It fixes a race condition in `t/lib-httpd/apply-one-time-script.sh`, a CGI helper used in HTTP daemon tests. The helper is supposed to execute a "one-time script" exactly once, but under concurrent requests (e.g., during a partial fetch that lazily retrieves a promisor object), multiple instances of the script can race on a shared state file, leading to HTTP 500 errors or duplicate modified responses. The patch replaces the non-atomic `test -f`/`rm` sequence with an atomic `rm` operation chained to the script execution, ensuring only one request can consume the marker.

The patch also adds a new test, `t5567-one-time-script.sh`, which directly exercises the helper without a web server, making the race deterministic. The test uses a stub `git-http-backend` to simulate concurrent requests and verifies that only one modified response is served. The fix is minimal and confined to the test infrastructure (`t/` directory), with no impact on production code. The commit message clearly explains the race, the atomicity fix, and the rationale for suppressing `stderr` (to avoid noise when the script is removed by a concurrent request).

This patch addresses all feedback from earlier iterations: it simplifies the logic by using `rm` instead of `mv`, adds a comment explaining the `stderr` redirection, and includes the new test to verify the fix. The series is ready for integration into `next`, with no open questions or loose ends. The fix is well-motivated by observed CI flakes (e.g., `t5616.47` on macOS runners) and unlikely to be controversial. Key files touched: `t/lib-httpd/apply-one-time-script.sh`, `t/meson.build` (to register the new test), and `t/t5567-one-time-script.sh`. The atomic idiom (`rm` without `-f`) is documented in patch 3 for future test helpers.
