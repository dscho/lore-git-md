This is a UX-focused bugfix for `git checkout -m` that refines how autostash conflict advice is displayed. The patch implements the v3 iteration of a previously discussed series, addressing all prior review feedback by introducing an `enum` API to distinguish between clean stash application, conflicts, and errors.

The core change separates the autostash conflict advice from the branch-switch confirmation message by printing a blank line when conflicts occur. This is achieved by modifying the return semantics of `apply_save_autostash_oid()`, `apply_save_autostash_ref()`, and related functions to use an `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) instead of an `int`. The caller in `builtin/checkout.c` now checks for `STASH_APPLY_CONFLICT` and prints the blank line, while `STASH_APPLY_ERROR` triggers a new error message ("could not apply autostash").

Key technical details include:
- Files touched: `sequencer.c`/`sequencer.h` (return-value semantics), `builtin/checkout.c` (advice formatting), `builtin/stash.c` (exit code handling), `stash.h` (new enum definition), and tests (`t/t3903-stash.sh`, `t/t7201-co.sh`).
- The patch documents the new exit codes in `git-stash.adoc`: `apply`, `pop`, and `branch` now exit with status 2 on conflicts (stash entry preserved), while other failures exit with 1.
- Tests validate the full output, including the blank line for conflicts and the new error message for non-conflict failures, using `test_cmp` for precise comparison.

The patch resolves the correctness issue raised in v2 by properly distinguishing between conflicts (`ret == 1` -> `STASH_APPLY_CONFLICT`) and other errors (`ret > 1` or negative -> `STASH_APPLY_ERROR`). It avoids changes to `builtin/stash.c`'s core logic, instead relying on the enum to encode the three states. All prior objections (API design, performance, and correctness) are addressed, and the patch is now a minimal, uncontroversial UX refinement. The series is ready for final review and likely inclusion in `next`.
