This is a test infrastructure bugfix targeting a race condition in Git’s HTTP daemon test helpers. The patch fixes a flaky failure in `apply-one-time-script.sh`, a CGI helper used to simulate repository changes between HTTP requests. Under concurrent requests (e.g., during a partial fetch that lazily retrieves promisor objects), the script’s non-atomic state management (`test -f` followed by `rm`) can cause HTTP 500 errors when multiple requests race to execute the one-time script. The fix replaces the racy sequence with an atomic `rm` operation chained to the script’s execution, ensuring only one request modifies the response.

The patch is well-motivated by real-world CI flakiness (notably `t5616.47` on macOS runners) and includes a new test (`t5567-one-time-script.sh`) that forces the race deterministically using FIFOs. The test verifies neither request emits an empty body (which would trigger HTTP 500) and confirms only one modified response is served. The implementation is minimal: it redirects `stderr` to `/dev/null` to suppress expected errors when the script is removed concurrently, adds process ID suffixes (`$$`) to scratch files to avoid clobbering, and documents the atomic idiom in the code. The changes are confined to the test suite (`t/lib-httpd/`) and have no impact on user-visible behavior.

This is the first patch in a three-part series (v4) that addresses similar races in another helper (`http-429.sh`) and documents the atomic patterns. Earlier versions received substantive review from Junio C Hamano and Patrick Steinhardt, with Junio marking the series as ready for integration in v2. The v4 revision addresses only commit message verbosity, not technical content. The fix is uncontroversial and unlikely to regress, as it targets a narrow, well-understood problem in test infrastructure. The series is complete and awaits integration into `next`.
