This is the third patch in the v4 series optimizing the experimental `git last-modified` command by reusing Git’s Bloom filter machinery. The patch adds a new private helper, `bloom_filter_contains_any_vec()`, to `bloom.c` and exposes it in `bloom.h`. The helper answers a key question for `--show-trees` support: whether *any* key in a Bloom key vector (representing a path and its parent directories) is present in the filter, indicating the path or one of its parent directories *might* have changed.

The implementation is straightforward: a 12-line loop over the key vector that returns `1` as soon as any key is found in the filter, and `0` only if none are present. This complements the existing `bloom_filter_contains_vec()`, which checks if *all* keys are present. The new helper is the technical foundation for patch 4/6, which introduces `revs_maybe_changed_in_bloom_with_parents()` to enable `--show-trees` to report changes to parent directories without false negatives. No callers are added yet; the helper is purely preparatory.

The patch is clean, well-scoped, and directly addresses the correctness issue identified in earlier iterations (the `--show-trees` bug). The commit message clearly explains the motivation and the distinction between the new helper and the existing one. This is a refactoring with no behavior change on its own, but it is critical for the performance and correctness goals of the series. The code is ready for integration.
