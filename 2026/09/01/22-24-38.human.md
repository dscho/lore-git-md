This is the second patch in Elijah Newren’s five-part bugfix series, now in its fourth iteration. It removes an overly strict restriction that prevented users from making partial commits (`git commit <paths>`) when a rebase operation resulted in an empty commit. The change is straightforward and uncontroversial: since an empty commit introduces no conflicts, allowing a partial commit poses no risk to repository integrity.

The patch deletes two lines from `builtin/commit.c` that previously triggered a fatal error when attempting a partial commit during a rebase where the commit became empty. It also updates a test in `t/t3404-rebase-interactive.sh` to reflect the new behavior—replacing a test that expected the error with one that confirms the partial commit succeeds. The test name is adjusted to match the new expectation.

This change directly addresses a usability issue raised in earlier iterations of the series. Junio C Hamano noted that blocking partial commits in this scenario was unnecessary because the result would still be an empty commit, making the restriction harmless but confusing. The patch aligns with the series’ broader goal of preventing unsafe commit operations during conflict resolution while avoiding false positives for benign cases. All substantive feedback has been resolved, and the patch is ready for integration.
