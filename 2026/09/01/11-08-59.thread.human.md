Patrick Steinhardt’s 12-patch series to remove ad-hoc ODB source linking—primarily used for submodules—continues under review. The goal is to simplify the object database (ODB) subsystem by eliminating dual-use of the ODB sources list for both alternates and temporary sources, while also advancing the broader effort to remove `the_repository` global state. The series, posted on August 31, includes incidental cleanups (removing `the_repository` dependencies in `cache-tree`, `submodule-config`, and related callers), core refactoring (removing submodule ODB source registration), a memory leak fix in the packed ODB source, and enforcement of an existing constraint in `git multi-pack-index --object-dir=` to reject non-alternate directories.

Junio C Hamano provided feedback on patch 1/12, identifying two correctness issues in the handling of repository context and suggesting a refactoring to encapsulate the dependency within `cache-tree.c`. Patrick has now replied, accepting the suggestion but proposing a slightly different implementation: renaming the existing `cache_tree_fully_valid()` to `cache_tree_fully_valid_recursive()` (making it file-scoped static) and adapting the current function to take a `struct index_state *` directly, preserving the external interface. This change is mechanical and doesn’t alter the patch’s core goal. Junio also gave unqualified approval to patch 6/12 with *“Yay. Very nice.”* The remaining patches have not yet received substantive review, but the series remains on track, with a v2 of patch 1/12 expected to incorporate this feedback before the rest of the series proceeds. No design objections have been raised, and the test suite passes, confirming the cleanup is complete.
