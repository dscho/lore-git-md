This thread is a 13-patch series from Patrick Steinhardt that refactors Git’s object database (ODB) subsystem to remove ad-hoc source linking, a mechanism previously used to register in-memory sources like submodules and temporary object directories. The goal is to simplify the codebase and prepare for future ODB abstraction work. The series is now at v2, posted on September 5, 2026, with patches 1, 3, and 7 revised or expanded to address feedback from Junio C Hamano, who gave unqualified approval to two key patches in v1.

The core changes include removing implicit dependencies on the global `the_repository` in `cache-tree` and `submodule-config` subsystems, eliminating the last uses of submodule ODB source registration in `git grep` and `submodule-config`, and cleaning up unused infrastructure like `tmp_objdir_add_as_alternate()`. Patch 10, the latest addition, enforces a long-documented constraint in `git multi-pack-index --object-dir=`: the specified object directory must now be an alternate of the current repository, aligning behavior with documentation and removing the last real-world caller of the ad-hoc source mechanism. This is a breaking change but one that resolves a contradiction between code and documentation.

The series is under review and remains uncontroversial, with no new objections or questions raised in v2. Junio’s earlier feedback suggests the refactoring is on solid ground, though there’s no indication yet whether he intends to merge it to `next`. The only loose end is a thread-safety note in `git grep` about initializing subrepositories, which is outside the scope of this series. The patches are self-contained, with no external dependencies, and the test suite passes, confirming the cleanup is complete.
