This thread is Patrick Steinhardt’s second revision of a 13-patch series refactoring Git’s object database (ODB) subsystem to remove an ad-hoc mechanism that allowed submodules to register their object databases as in-memory sources of the main repository. The goal is to simplify the codebase and eliminate implicit dependencies on global state, paving the way for future ODB abstraction work.

The series is under active review, with v2 posted on September 5, 2026. The first four patches saw updates in this revision: patch 1/13 was revised to address Junio C Hamano’s feedback from v1, encapsulating repository dependencies in `cache-tree.c`; patch 2/13 (new in v2) removed the last implicit dependency on submodule ODB registration in the `cache-tree` subsystem; patch 3/13 mechanically refactored `submodule-config` to use explicit repository parameters; and patch 4/13 eliminated remaining uses of the global `the_hash_algo` in `submodule-config.c`. The latest email covers patch 5/13, which removes the final call to `odb_add_submodule_source_by_path()` in `submodule-config.c`, completing the cleanup of submodule ODB registration. The remaining patches (6-13/13) are unchanged from v1 and include incidental cleanups, a memory leak fix, test helper updates, and the final removal of the ad-hoc source linking API.

Junio provided substantive reviews of patches 1/13 and 6/13 in v1, signaling approval of the core refactoring, but has not yet engaged with v2. The series is self-contained, with no external dependencies or related in-flight topics, and all tests pass, confirming the cleanup is complete. The only open question is whether Junio intends to merge the series to `next` or await further feedback.
