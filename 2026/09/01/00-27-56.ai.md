This is the final patch in a three-patch bugfix series targeting race conditions in Git’s HTTP daemon test helpers. It adds documentation to `t/lib-httpd.sh` to guide future contributors writing concurrency-safe CGI scripts for the test suite.

The patch inserts a concise comment block explaining why state management in these scripts must be atomic and providing concrete examples of safe and unsafe patterns. It highlights the use of `mkdir` for first-request election (as implemented in `http-429.sh`), `rm` (without `-f`) for consuming one-shot markers (as in `apply-one-time-script.sh`), and process IDs (`$$`) in scratch file names to prevent clobbering. The examples are cross-referenced to the actual scripts fixed in the series, making the advice actionable.

This is a documentation patch with no code changes. The placement in `t/lib-httpd.sh` (rather than `t/README`) keeps the guidance close to the helpers it describes, addressing earlier reviewer feedback. The content reflects the atomic idioms introduced in patches 1 and 2, ensuring consistency. The patch is uncontroversial and completes the series, which is now ready for integration into `next`.
