This is the first patch in a two-part CI/build system series that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. The patch addresses a critical compatibility issue: when Git is built under MSYS2/MinGW with Rust support, the default Rust toolchain (installed via `rustup` on GitHub’s Windows runners) targets the MSVC ABI, producing a `.lib` file that MinGW’s `ld.exe` cannot link. Instead, the patch configures Cargo to target a GCC-compatible ABI (`*-pc-windows-gnu` or `*-pc-windows-gnullvm`), ensuring the resulting `libgitcore.a` is linkable by MinGW GCC.

The changes are focused on the build system: the `Makefile` is updated to respect a new `CARGO_TARGET` variable, and `config.mak.uname` is extended to derive the correct target triple from the `MSYSTEM` environment variable. The logic handles both 32-bit and 64-bit x86 systems, as well as ARM64 (which uses `gnullvm` since no MinGW-GCC port exists for that architecture). The patch is well-motivated and surgically targets the root cause of the linking failure observed in GitHub Actions runs.

This is a practical, low-risk fix that directly enables the broader goal of the series: removing the Rust opt-out in Windows CI.
