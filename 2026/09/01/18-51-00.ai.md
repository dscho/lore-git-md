This is the final implementation of the `--missing-only` option for `git rev-list`, completing a feature requested by GitLab for partial clone workflows. The patch is part of a well-converged thread where all design concerns have been resolved, and this version incorporates every piece of review feedback from Phillip Wood, Derrick Stolee, Patrick Steinhardt, and others.

The implementation adds a clean, script-friendly way to list only missing objects without post-processing. It introduces the `--missing-only` flag in `builtin/rev-list.c`, which filters output to show only missing objects while preserving the format selected by `--missing=` (either bare OIDs or `path=`/`type=` fields). The patch explicitly rejects incompatible options (`--count`, `--disk-usage`) and includes thorough tests that verify both the filtering behavior and error conditions. Documentation is clear and complete, covering flag semantics, option interactions, and use cases.

Key technical details for follow-up: the new helper `should_collect_missing()` replaces the previous `missing_action_prints()` check, and the output format omits the leading `?` prefix for script-friendliness. Tests use `test_cmp` for direct OID verification, covering edge cases like incompatible option combinations and the `print-info` mode. The patch touches only three files (`builtin/rev-list.c`, `Documentation/rev-list-options.adoc`, and `t/t6022-rev-list-missing.sh`) and maintains backward compatibility with existing `--missing=` modes.
