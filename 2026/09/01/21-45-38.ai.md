This is a **platform compatibility and usability discussion** about silent binary file corruption in Git on Windows, specifically caused by misconfigured global `.gitattributes` rules. Randall S. Becker (the NonStop port maintainer) replies to Skybuck Flying’s detailed bug report with practical advice and shared frustration about Git’s handling of text vs. binary files.

The email is **not a patch or code change**, but a **substantive discussion** of the underlying issues. Becker’s key points:
- **Configuration recommendations**: He suggests `core.autocrlf=input` (not `false`), `core.ignorecase=true`, and `core.filemode=false` as safer defaults for Windows users. This directly addresses the thread’s root cause—misapplied text filters—by reducing Git’s tendency to treat files as text.
- **Binary file detection**: Git’s heuristic (checking only the first "hunk" for non-text characters) is unreliable, especially for files with CR bytes early in their content. Becker emphasizes that users *must* explicitly declare binary files (e.g., `*.png binary`) to avoid corruption, as Git’s automatic detection is not trustworthy.
- **Filter pitfalls**: Clean/smudge and textconv filters are fragile when handling binary data. He warns that some platforms open files in text mode (`"r"` instead of `"rb"`), which can mangle binary content, and that poorly written filters (e.g., using `fgets()` in C) may crash on NUL bytes. His workaround—using `%f` in textconv commands—is a practical tip for Windows users.
- **Design critique**: Becker implies that Git’s attribute system is inherently risky, as global rules (e.g., `* text diff=lfclean`) can silently corrupt files without warnings. His tone suggests this is a long-standing pain point for Windows users.

**What’s new here**:
- Becker’s email **validates Skybuck’s core concern** (binary corruption from global `.gitattributes`) while shifting focus from "Git is broken" to "Git’s defaults and heuristics are unsafe for Windows." His recommendations (`autocrlf=input`, explicit binary declarations) are actionable workarounds.
- He **highlights a gap in Git’s design**: the lack of safeguards for binary files when text filters are misconfigured. Unlike earlier dismissals of the textconv issue as a "Windows problem," Becker treats this as a **systemic usability issue** that affects all platforms.
- The discussion of filter behavior (`"r"` vs. `"rb"`, NUL bytes) adds technical depth, explaining *why* textconv filters fail on binaries and how to mitigate it.

**Open questions**:
