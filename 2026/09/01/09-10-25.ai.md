This is the fifth patch in the v4 series optimizing the experimental `git last-modified` command by reusing Bloom filters. The patch adds a pre-filter in `maybe_changed_path()` that checks whether a commit *might* have changed any path matching the user’s pathspec before proceeding to per-path diffs. For `--show-trees`, it uses the new `revs_maybe_changed_in_bloom_with_parents()` helper to also check parent directories, avoiding false negatives when a commit touches a sibling file (e.g., `a/other` for pathspec `a/b/c`). The test verifies that the Bloom-filter fast-path works correctly with `--show-trees` and that the results match the commit-graph-disabled baseline.

The change is a targeted performance optimization: it discards commits early if the Bloom filter rules them out, reducing the number of expensive tree diffs. The logic is cleanly split between the two new public helpers introduced in earlier patches (`revs_maybe_changed_in_bloom` and `revs_maybe_changed_in_bloom_with_parents`), and the test ensures the pre-filter does not alter correctness. The patch is ready for integration; all prior feedback on the series has been addressed, and the instrumentation in the final patch will confirm the fast-path is triggered as expected.
