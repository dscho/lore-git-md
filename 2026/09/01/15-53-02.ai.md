This is the second patch in a three-patch bugfix series targeting test infrastructure. It makes the `http-429.sh` CGI helper in `t/lib-httpd/` concurrency-safe by replacing a non-atomic "check-and-set" (`test -f` followed by `touch`) with a single atomic `mkdir` operation. The helper is used to test Git's retry logic when receiving HTTP 429 (Too Many Requests) responses, and the fix prevents a race condition where concurrent requests could both incorrectly return 429 instead of forwarding one to `git-http-backend`.

The patch also corrects a latent correctness issue in the "permanent" mode (where every request should return 429): the original implementation used a create-then-remove pattern that left a race window, while the new version skips the `mkdir` entirely to ensure no state marker is left behind. The commit message clearly explains the atomicity rationale and the edge case, and the code comment now reflects the change in behavior for "permanent" mode.

This patch is part of a well-motivated, thoroughly reviewed series that addresses a real, observed flake in `t5616.47` on macOS CI runners. The fix is minimal, confined to the test infrastructure, and unlikely to be controversial. The series as a whole is ready for integration into `next`, with all substantive and editorial feedback from v1–v5 addressed. The atomic `mkdir` idiom introduced here is documented in patch 3 for future test helpers.
