This is the third patch in the v4 series that speeds up the experimental `git last-modified` command by reusing Git’s Bloom filters. The series as a whole is now complete, well-tested, and ready for integration.

This patch adds a new helper function, `bloom_filter_contains_any_vec()`, to Git’s Bloom filter machinery. The helper answers a slightly different question than the existing `bloom_filter_contains_vec()`: instead of checking whether *all* keys in a vector are present (which proves a path *might* have changed), it checks whether *any* key is present (which proves the path *or any of its parent directories* might have changed). This is exactly what the `--show-trees` option in `git last-modified` needs to avoid false negatives when querying directories.

The implementation is straightforward: a 12-line loop over the key vector that returns as soon as any key is found in the Bloom filter. The patch includes a clear docstring explaining the semantics and adds the function to `bloom.h` so it can be called from other files. There are no callers yet; the next patch in the series will use it.

The change is a clean, targeted addition to the Bloom filter API. It does not alter existing behavior, and the new function is narrowly scoped to the specific use case of directory-aware queries. The commit message explains the motivation clearly and provides a concrete example of why the existing helper is insufficient. This is a well-crafted building block for the performance optimizations that follow.
