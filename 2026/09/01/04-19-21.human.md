This is a surface-level review comment from Junio C Hamano on the test added in patch 6/6 of Toon Claes’s `git last-modified` Bloom filter optimization series. The patch restores Bloom filter settings after `prepare_revision_walk()` clears them, ensuring wildcard pathspecs like `*.c` continue to benefit from the 3.7× speedup.

The issue is a test environment interaction: the test script exports `GIT_TEST_COMMIT_GRAPH=1` (a standard Git test environment variable), which forces `core.commitGraph=true` regardless of the `-c` flag. Junio points out that the test’s `git -c core.commitGraph=false` is therefore ineffective, and suggests explicitly overriding the environment variable with `GIT_TEST_COMMIT_GRAPH=0` to ensure the commit-graph is truly disabled. The same override should be applied when re-enabling the commit-graph to keep the test consistent.

This is a minor but necessary fix to make the test reliable. The change is mechanical and does not affect the patch’s core logic or performance claims. The series is otherwise complete and ready for integration once this test nit is addressed.
