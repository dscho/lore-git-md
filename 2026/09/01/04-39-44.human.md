This is a substantive review from Jeff King (Peff) on the `git ident` patch series. Peff questions whether introducing a new command (`git ident`) is the right approach, suggesting instead that the existing `git var` command could be extended to provide the same functionality. His feedback is technical and constructive, focusing on minimizing command proliferation while achieving the same user goals.

Peff proposes teaching `git var` to output broken-down identity components (e.g., `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`) instead of the current full ident string. He notes these names are already used for environment variables, making them a natural fit. For composable output (e.g., mixing name and email), he suggests allowing `git var` to accept multiple variables and output them one per line (or NUL-terminated with `-z`), which would simplify scripting. He also floats the idea of a `--format` option (similar to `git for-each-ref`) but acknowledges it might overcomplicate the interface.

The review covers all of `git ident`'s key features: identity scope selectors (`-a`/`--author`, `-c`/`--committer`), component selectors (`-n`/`--name`, `-e`/`--email`), verbose labels (`-v`), signing key resolution (`-s`), and machine-readable output (`--porcelain`, `-z`). Peff argues each could be implemented in `git var` without introducing a new command. His critique is not about the implementation quality of `git ident`—which he doesn’t address—but about whether the problem justifies a new command at all.

This feedback is likely to spark further discussion about Git’s command-line design philosophy. The patch author will need to either defend the necessity of a dedicated command or pivot to extending `git var` as Peff suggests. The thread’s next steps hinge on whether the maintainer (Junio) or other reviewers find Peff’s alternative compelling.
