This is a test infrastructure bugfix (patch 1/3 in the v4 series) that fixes a race condition in the `apply-one-time-script.sh` CGI helper used by Git's HTTP daemon tests. The patch replaces a non-atomic check-and-remove sequence (`test -f` followed by `rm`) with an atomic `rm` operation chained directly to script execution, preventing concurrent requests from both running the one-time script and causing HTTP 500 errors. The fix is motivated by flaky macOS CI failures (e.g., `t5616.47`) where promisor fetches fail with "The requested URL returned error: 500".

The patch touches `t/lib-httpd/apply-one-time-script.sh` and adds a new test (`t5567-one-time-script.sh`) that uses FIFOs to force the race deterministically. The test verifies that only one request returns a modified response and neither emits an empty body. Key technical details include the use of `$$` (process ID) in scratch file names to avoid clobbering, redirection of `stderr` to `/dev/null` to suppress expected errors when the script is removed concurrently, and a comment explaining why the `rm` is chained to the script execution. The patch also updates `t/meson.build` to include the new test.

This is a well-scoped, low-risk fix confined to the test suite. The atomic idiom (`rm` without `-f`) is now documented in patch 3/3, making it reusable for future test scripts. The series is ready for integration into `next`, with all substantive feedback addressed in earlier versions. The v4 revision only rewrites commit messages for conciseness, with no technical changes. The patch is unlikely to be controversial, as it targets a real-world flakiness issue with minimal, targeted changes.
