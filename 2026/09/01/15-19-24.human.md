This is the refactoring patch in Karthik Nayak’s three-part series introducing the `receive-report` hook. It extracts the status-report generation logic from `report()` and `report_v2()` into a shared helper, `generate_report()`, so the next patch can reuse it for the hook’s output.

The patch is mechanical: it moves the pkt-line formatting code into the new helper, adds a boolean parameter (`detailed_report`) to control v2-specific reports, and updates the callers to pass a pre-allocated `strbuf`. No behavior changes are introduced. The commit message now explicitly states the refactoring’s purpose—preparing for the hook’s failure handling—and clarifies the difference between `report()` and `report_v2()`.

All prior feedback from Patrick Steinhardt has been incorporated: the helper is renamed from `generate_response()` to `generate_report()`, the boolean parameter is renamed from `add_reports` to `detailed_report`, and the commit message is more precise.
