This is a brief follow-up in the `git checkout -m` autostash conflict handling thread. Junio C Hamano acknowledges that his earlier feedback on the patch’s return-value design was unclear and agrees with Phillip Wood’s critique: Git’s established convention is to use exit code 1 for conflicts and other non-zero values for errors. The current patch (v3) uses exit code 2 for conflicts, which Junio now concedes is inconsistent and should be revised to match the rest of Git.

The thread’s core goal—visually separating autostash conflict advice from the branch-switch message—remains uncontroversial and well-motivated. However, the exit code design is now the sole sticking point. Junio’s endorsement of Phillip’s position makes it likely the author will need to adjust the patch to use exit code 1 for conflicts, simplifying the code and aligning with commands like `merge-tree`, `grep`, and `diff`. The rest of the series (enum API, advice formatting, and test coverage) is already settled.
