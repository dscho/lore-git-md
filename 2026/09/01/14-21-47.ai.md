This is a CI/build system patch series targeting the Windows CI jobs, specifically to enable Rust compilation in Git’s GitHub Actions workflows. The series consists of two patches that adjust the build environment to use Rust pre-installed on GitHub’s Windows runners, avoiding the need to include Rust in the minimal Git for Windows SDK (which would significantly increase its size).

The motivation is straightforward: since Git 2.55.0, Rust is required by default, but Windows CI jobs currently opt out due to the lack of Rust in the minimal SDK. The patches work around this by configuring the pre-installed Rust toolchain on GitHub’s runners to target GCC (used by Git for Windows) instead of the default Visual C. The first patch ensures Cargo picks a GCC-compatible target under MSYS2/MinGW, while the second removes the Rust opt-out in the CI workflow and adds steps to set up the Rust environment.

The series is narrowly scoped to GitHub Actions; the cover letter explicitly asks for help testing on GitLab’s Windows runners, as the author couldn’t confirm whether Rust is pre-installed there. The changes are minimal and focused on the CI configuration (`.github/workflows/main.yml`, `ci/lib.sh`, and `config.mak.uname`), with no impact on core Git functionality.

The patches look well-motivated and practical, addressing a clear gap in the CI setup without introducing unnecessary complexity. The request for testing on GitLab is a sensible caveat, and the series is unlikely to be controversial—assuming the GitLab runners behave as expected. If this works, it would unblock the eventual removal of the Rust opt-out in Git’s CI.
