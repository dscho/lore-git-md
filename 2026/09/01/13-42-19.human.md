This is a **UX-focused bugfix** for `git checkout -m` that refines how autostash conflict advice is displayed. The patch is the **final iteration (v3)** of a series that addresses all prior review feedback, including a correctness fix for conflict detection logic and an `enum`-based API to distinguish between clean stash application, conflicts, and errors.

The core change visually separates autostash conflict advice from the branch-switch confirmation message by printing a blank line when conflicts occur. This improves readability without altering the underlying conflict resolution logic. The patch also documents the new exit codes for `git stash apply`, `pop`, and `branch`: status 2 for conflicts (stash entry preserved) and 1 for other failures.

Key technical details:
- Files touched: `sequencer.c`/`sequencer.h` (return-value semantics), `builtin/checkout.c` (advice formatting), `builtin/stash.c` (exit code handling), `stash.h` (new `enum stash_apply_result`), and tests (`t/t3903-stash.sh`, `t/t7201-co.sh`).
- The `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) replaces the previous `int` return type for `apply_save_autostash_oid()` and related functions.
- Tests now use `test_cmp` to validate the full output, including the blank line for conflicts and the new error message for non-conflict failures.
