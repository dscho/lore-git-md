This is a CI/build system patch series from Johannes Schindelin, targeting the Windows CI jobs to enable Rust support now that Git requires Rust by default (with an opt-out that is planned to be removed soon).

The series addresses a gap in the Windows CI setup: the "minimal Git for Windows SDK" used in CI does not include Rust, so Rust support was explicitly disabled in CI. However, GitHub's Windows runners already have Rust pre-installed, just configured for Visual C rather than GCC (which the Windows CI uses). The patches adjust the GitHub workflow to install and configure the necessary Rust components for GCC compatibility, allowing Rust to be enabled in the Windows CI builds.

The first patch modifies the build system to select a GCC-compatible Cargo target under MSYS2/MinGW, while the second patch updates the GitHub workflow to build with Rust enabled. The series also removes the opt-out for Rust in the CI configuration. Johannes notes that the GitLab CI situation is unclear and requests help from someone with access to confirm whether the changes work there as well.

The patches look practical and well-motivated, directly addressing the CI limitation that was put in place when Rust support was first introduced. The request for GitLab CI testing is a sensible precaution. If this works, it will bring the Windows CI in line with the project's Rust requirements without bloating the minimal SDK.
