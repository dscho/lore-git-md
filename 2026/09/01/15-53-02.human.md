This is the second patch in a three-patch bugfix series targeting race conditions in Git's HTTP daemon test helpers. The series is ready for integration into `next` and addresses a real, observed flake in `t5616.47` on macOS CI runners.

The patch makes `http-429.sh` concurrency-safe by replacing its non-atomic state management (`test -f` followed by `touch` or `rm`) with an atomic `mkdir` operation. The script is used to test retry logic by returning HTTP 429 (Too Many Requests) responses, and its original implementation could race when multiple concurrent requests checked for the existence of a state file, leading to HTTP 500 errors. The fix ensures that only one request will "win" the race to create the state directory, while others will forward to `git-http-backend` as intended.

The change also corrects a subtle correctness issue in the "permanent" mode (where every request should return 429): the original implementation would create and then remove the state file, leaving a race window where concurrent requests could both incorrectly return 429. The new version skips the `mkdir` entirely in "permanent" mode, ensuring no state marker is left behind.

The patch is minimal, well-explained, and confined to the test infrastructure (`t/lib-httpd/`). It complements the first patch in the series, which fixes a similar race in `apply-one-time-script.sh`, and the third patch, which documents the atomic idioms for future test helpers. The series has been thoroughly reviewed and revised across five iterations, with all substantive and editorial feedback addressed.
