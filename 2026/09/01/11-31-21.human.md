This is a review comment on the first patch in Junio’s eight-patch series refactoring the `git checkout` internals. Karthik Nayak questions whether the `cb_option` variable is even needed, given that its only purpose is to customize error messages in `parse_remote_branch()`—and those messages could instead key off the existing `enum checkout_command` (which distinguishes `git checkout`, `git switch`, and `git restore`).

The review is substantive but narrow: it targets a single piece of state and suggests a simpler alternative. Karthik’s point is that `cb_option` is redundant with information already available in the command enum, so removing it entirely would reduce complexity without changing behavior. The patch currently replaces a file-scope static with an explicit parameter; Karthik argues that the parameter itself may not be necessary.

This is a classic refactoring trade-off: the patch makes state explicit, while Karthik’s suggestion eliminates it. Neither approach changes what the user sees, but the latter would make the code slightly smaller and simpler. The discussion is still open—no reply from Junio yet—and the outcome could ripple through the rest of the series, since later patches assume `cb_option` exists. If Karthik’s suggestion is adopted, those patches would need minor adjustments to use the command enum instead.
