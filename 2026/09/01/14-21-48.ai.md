This is the first patch in a two-part CI/build system series that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. It addresses a critical compatibility issue: when Git is built under MSYS2/MinGW with Rust support, the default Rust toolchain (installed via `rustup` on GitHub’s Windows runners) targets the MSVC ABI, producing a `.lib` file that MinGW’s `ld.exe` cannot link. The patch ensures Cargo builds a GCC-compatible static library by setting the correct target triple (`*-pc-windows-gnu` for MinGW, `*-pc-windows-gnullvm` for Clang/LLVM subsystems) based on the `MSYSTEM` environment variable.

The changes are confined to the build system: `Makefile` gains a conditional to append the target triple to the `RUST_LIB` path and `CARGO_ARGS`, while `config.mak.uname` expands the `HOST_CPU` logic to derive the correct Rust target. The patch is well-motivated, with a clear error message and a link to a failed CI run demonstrating the problem. It avoids environment variables not present in Git for Windows’ minimal SDK, making it robust for CI use.

This is a practical, narrowly scoped fix that directly enables the broader goal of unblocking Rust in Windows CI. The logic is straightforward and unlikely to be controversial, though the GitLab Windows runner question from the cover letter remains open. The patch looks ready for review, with no obvious gaps in testing or edge-case handling.
