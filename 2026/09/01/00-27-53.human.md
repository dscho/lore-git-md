This is a test infrastructure bugfix series targeting race conditions in Git’s HTTP daemon test helpers. The v4 reroll is a pure prose rewrite of the commit messages and code comments—no technical changes were made since v3, which already addressed all substantive feedback from Junio C Hamano and Patrick Steinhardt.

The series fixes two CGI scripts in `t/lib-httpd/` (`apply-one-time-script.sh` and `http-429.sh`) that manage shared state using non-atomic shell operations (`test -f` followed by `rm` or `touch`). Because Apache serves requests concurrently, these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails, causing an HTTP 500 error. The fixes replace the non-atomic checks with atomic operations: `rm` (without `-f`) for the one-shot marker in `apply-one-time-script.sh` and `mkdir` for the first-request election in `http-429.sh`. The new commit messages are now concise and clearly explain the problem, the atomic idioms used, and the reasoning behind the changes.

Patch 1 also adds a new test (`t5567-one-time-script.sh`) that directly exercises `apply-one-time-script.sh` without a web server, using FIFOs to force the race deterministically. Patch 3 documents the atomic patterns in `t/lib-httpd.sh`, providing concrete examples of safe and unsafe state management for future test helpers. The series is well-motivated by a real, observed flake in `t5616.47` on macOS CI runners, and the fixes are minimal and targeted. It is unlikely to be controversial, as the changes are confined to test infrastructure and do not affect user-visible behavior. The series is ready for integration into `next`.
