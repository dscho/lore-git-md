This is the first patch in a 12-part refactoring series targeting the object database (ODB) subsystem. The patch removes the `cache-tree` subsystem's dependency on the `the_repository` global variable, replacing it with explicit repository parameters passed via context or `struct index_state`. This is part of Patrick Steinhardt’s broader effort to eliminate `the_repository` and prepare the ODB for further abstraction work.

The changes are mechanical but non-trivial: every function in `cache-tree.c` that previously used `the_repository` or `the_hash_algo` now takes a `struct repository *` parameter. The patch also updates callers in `builtin/checkout.c`, `builtin/commit.c`, `sequencer.c`, `sparse-index.c`, and `unpack-trees.c` to pass the correct repository instance. A small but important side effect is the removal of the last implicit dependency on registering submodule ODB sources with the main object database, which the commit message verifies with a test flag (`GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB`).

The patch is well-scoped and clearly motivated: it eliminates a long-standing design wart where submodule objects were incorrectly read via `the_repository` and then registered with the main ODB. The test coverage (t1092) confirms the change doesn’t break existing functionality. This is a solid, incremental step toward the series’ goal of removing ad-hoc ODB source linking, and the commit message does a good job explaining both the "what" and the "why." No behavioral changes are expected, and the patch looks ready for review.
