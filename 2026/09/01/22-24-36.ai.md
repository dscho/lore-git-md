This is the **v4 iteration of a bugfix series** targeting the merge machinery. Elijah Newren extends Git's existing protection against unsafe commit operations (`git commit --amend` and `git commit <paths>`) during conflict resolution to cover `git am`, `git revert`, and all forms of `git rebase`. The series is **technically complete** and ready for integration, with all substantive feedback addressed in earlier iterations.

The only change since v3 is a **purely mechanical rename** to clarify intent: `FROM_REBASE_EMPTY` becomes `FROM_REBASE_NOW_EMPTY`, `is_from_rebase_empty()` becomes `is_from_rebase_now_empty()`, and `ONGOING_REBASE_EMPTY` becomes `ONGOING_REBASE_NOW_EMPTY`. This addresses Junio C Hamano's stylistic feedback about whether the original names adequately conveyed that the commit *became* empty (rather than being empty from the start). The rename is applied consistently across `builtin/commit.c`, `sequencer.c`, and `wt-status.h`, with no functional changes.

The series consists of five patches:
1. **Preparatory refactoring** (patch 1/5): renames enum values and helper functions to clarify they refer to commits that *became* empty during rebase.
2. **Behavioral change** (patch 2/5): removes the restriction on `git commit <paths>` during conflict resolution for empty commits, as the result is still an empty commit and thus harmless.
3. **Error message rewording** (patch 3/5): replaces the generic "You are in the middle of a rebase -- cannot amend." with the more precise **"The now-empty commit has been dropped -- cannot amend."** for cases where an empty commit was dropped during rebase.
4. **Core protection** (patch 4/5): extends the refusal of `git commit --amend` to `git am`, `git revert`, and all `git rebase` variants during conflict resolution, using the new `sequencer_ongoing_operation()` helper to detect active operations.
5. **Core protection** (patch 5/5): extends the refusal of `git commit <paths>` to the same operations, with careful exceptions for non-conflict cases (e.g., interactive rebase directives like `squash` or `edit`).

Key technical details:
- **Files touched**: `builtin/commit.c`, `sequencer.c`, `sequencer.h`, `wt-status.h`, and test coverage in `t3404-rebase-interactive.sh`, `t3507-cherry-pick-conflict.sh`, `t4151-am-abort.sh`, and `t3403-rebase-skip.sh`.
- **New behavior**: blocks `git commit --amend` and `git commit <paths>` during conflict resolution for `git am`, `git revert`, and all `git rebase` variants, except for interactive rebase directives (`squash`, `reword`, `edit`, `break`). The restriction on `git commit <paths>` for empty commits has been removed.
- **New symbols**: `enum ongoing_operation` and `sequencer_ongoing_operation()` consolidate logic for detecting active operations, distinguishing between conflict stops (marked by `stopped-sha` in `rebase-merge/`) and clean interactive rebase stops (marked by `amend`).
- **Error messages**: "The now-empty commit has been dropped -- cannot amend." (for `--amend` after an empty commit is dropped), "cannot amend while resolving conflicts" (for `--amend` during conflict resolution), and "cannot do a partial commit while resolving conflicts" (for `<paths>` during conflict resolution).

The series has received explicit approval from Junio C Hamano for all substantive changes, including the error message rewording ("Much less awkward than the previous round") and the structural improvements in patch 5/5. The only unresolved feedback is the naming preference for `FROM_REBASE_NOW_EMPTY` vs. `FROM_REBASE_EMPTY`, which is purely stylistic and does not affect functionality. The series is **ready for `next`** and aligns with the project's ongoing efforts to improve user safety during conflict resolution.
