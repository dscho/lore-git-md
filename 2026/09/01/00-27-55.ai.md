This is the second patch in a three-patch bugfix series (v4) targeting race conditions in Git’s HTTP daemon test helpers. The series addresses flaky test failures caused by non-atomic state management in CGI scripts under concurrent requests.

This patch replaces the racy "check-and-set" pattern in `t/lib-httpd/http-429.sh` with an atomic `mkdir` operation to elect the first request that should return HTTP 429 (Too Many Requests). The original implementation used `test -f` followed by `touch` to create a state file, which could race under concurrent requests, causing both to incorrectly return 429 instead of forwarding one to `git-http-backend`. The fix also corrects a latent bug in the "permanent" mode (where every request should return 429) by skipping the `mkdir` entirely, ensuring no state marker is left behind. The change is minimal and confined to the test helper, with no impact on user-visible behavior or on-disk formats.

The patch is well-motivated by the thread’s earlier discussion, where Junio C Hamano and Patrick Steinhardt reviewed the atomicity concerns and the "permanent" mode logic. The commit message clearly explains the problem, the atomic idiom (`mkdir`), and the reasoning behind the "permanent" mode fix. The diff is clean, replacing the state file logic with a state directory and adding explanatory comments. No regression test is included because the race cannot be forced deterministically, but the new test in patch 3 (`t5567-one-time-script.sh`) indirectly validates the atomicity pattern.

This patch is ready for integration. The v4 revision addresses only commit message verbosity, with no technical changes from v3. Earlier versions received substantive review, and the series as a whole is marked as ready for `next`. The atomic `mkdir` idiom is now documented in `t/lib-httpd.sh` (patch 3), making it reusable for future test scripts. The fix is unlikely to be controversial, as it targets a clear correctness issue with a minimal, well-understood solution. Key technical details include the use of `$$` (process ID) in scratch file names to avoid clobbering and the removal of the racy "create-then-remove" pattern in "permanent" mode.
