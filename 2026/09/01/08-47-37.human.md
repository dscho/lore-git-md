This is a CI/build system discussion, not a new patch. Jeff King (Peff) replies to Patrick Steinhardt’s recent fix for a GitLab CI documentation job failure, where the `gem` command (needed to install Asciidoctor) became unavailable due to a missing Ruby dependency. Peff’s comment is a tangential observation about the version of Asciidoctor being pinned in CI: 1.5.8, which is eight years old.

Peff notes that the version was pinned in 2019 due to issues with Asciidoctor 2.0.0 at the time, but argues that modern versions (2.0.x) are now widely used and work fine. He suggests updating the CI configuration to use a newer version, reasoning that if compatibility testing is needed, it should focus on versions users are actually running, not an outdated one. He acknowledges the possibility of building with both versions but dismisses it as unnecessary overhead given the age of 1.5.8.

The comment is substantive but not a review of Patrick’s patch itself—it’s a separate suggestion for future improvement. It doesn’t challenge the correctness of the current fix, which remains uncontroversial and ready for merging. However, Peff’s point could lead to a follow-up patch if others agree that updating the Asciidoctor version is worthwhile. For now, this is just an offhand observation from a senior contributor, not a call to action.
