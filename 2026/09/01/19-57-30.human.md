This is Junio C Hamano, the Git maintainer, replying to Siddharth Asthana’s v2 patch series that adds a `--missing-only` option to `git rev-list`. The patch itself is well-crafted, thoroughly reviewed, and ready for integration, but Junio is stepping back to ask a higher-level question about the workflow this feature enables.

The question is straightforward: how does GitLab’s Gitaly actually *use* the list of missing objects produced by `--missing-only`? The commit message and earlier discussion describe the feature’s mechanics (filtering output to show only missing objects without the `?` prefix), but Junio wants to understand the broader backfill strategy. His tone is curious rather than skeptical, but the implication is clear: if the workflow is inherently inefficient, the feature’s utility might be limited.

This is not a request for code changes or a rejection of the patch. It is a maintainer-level inquiry about real-world usage, and the answer could inform future design decisions (e.g., whether to extend the feature to support more sophisticated backfill strategies).
