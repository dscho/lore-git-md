This is the fourth iteration of a performance optimization for the experimental `git last-modified` command, now complete and ready for integration. The series reuses Git’s Bloom filter machinery to speed up queries about the last commit that modified files matching a pathspec (including wildcards like `*.c`), achieving a 3.7× speedup without `--show-trees` and a 1.95× speedup with `--show-trees` on the ziglang/zig repository. The v4 reroll addresses the last remaining blocker: a test environment interaction in `t8020-last-modified.sh` where `GIT_TEST_COMMIT_GRAPH=1` was overriding the `-c core.commitGraph=false` setting, causing the test to fail under standard Git test environment variables. The fix is minimal and pragmatic—explicitly unsetting `GIT_TEST_COMMIT_GRAPH` (to `0`) when testing the commit-graph-disabled baseline and setting it (to `1`) when testing the commit-graph-enabled case.

The series touches `revision.c`, `revision.h`, `bloom.c`, `bloom.h`, `builtin/last-modified.c`, and the test suite, introducing two new public helpers (`revs_maybe_changed_in_bloom` and `revs_maybe_changed_in_bloom_with_parents`) and two private helpers (`bloom_filter_contains_path` and `bloom_filter_contains_any_vec`). The `--show-trees` correctness bug is fixed by filtering out ancestor tree entries not covered by the original pathspec in `add_path_from_diff()` using `match_pathspec()`, and the new `revs_maybe_changed_in_bloom_with_parents()` function enables `--show-trees` to report changes to parent directories by checking all keys in the path’s key vector. Patch 6/6 restores `bloom_filter_settings` after `prepare_revision_walk()` clears it, ensuring Bloom filter lookups succeed for wildcard pathspecs, and adds a trace2 counter (`bloom_queries`) to instrument per-path Bloom filter invocations. The test suite now includes a trace2-based test to verify that the per-path Bloom filter logic is invoked exactly twice for a top-level wildcard query (e.g., `*.c`).

All technical feedback from earlier iterations is resolved, including the public API refactor, `--show-trees` correctness fix, wildcard pathspec support, and trace2 instrumentation. The maintainability concern about patch 6/6’s approach of restoring `bloom_filter_settings` after `prepare_revision_walk()` clears it remains acknowledged but non-blocking; Jeff King accepted the current approach as sufficient. The series is well-motivated, thoroughly tested, and delivers measurable performance gains without changing on-disk formats or introducing external dependencies. It looks ready for `next`.
