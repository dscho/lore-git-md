This is a test infrastructure bugfix series (v4) targeting race conditions in Git’s HTTP daemon test helpers. The series fixes non-atomic state management in two CGI scripts (`apply-one-time-script.sh` and `http-429.sh`) that can cause HTTP 500 errors under concurrent requests, as observed in flaky macOS CI failures (e.g., `t5616.47`). The fixes replace racy shell operations (`test -f` followed by `rm` or `touch`) with atomic alternatives (`rm` without `-f` for one-shot markers, `mkdir` for first-request election) and add a new test (`t5567-one-time-script.sh`) to verify the fix deterministically. The changes are confined to the test suite (`t/` directory) and include updated documentation in `t/lib-httpd.sh` to guide future contributors.

The v4 revision addresses feedback on commit message verbosity from v3, rewriting all prose manually to focus on the technical problem and solution. The core logic remains unchanged: patch 1 chains the `rm` of the one-shot marker with its execution to prevent concurrent requests from both running the script, patch 2 replaces the non-atomic "check-and-set" in `http-429.sh` with an atomic `mkdir`, and patch 3 documents the atomic idioms in `t/lib-httpd.sh`. The new test uses FIFOs to force the race, ensuring neither request emits an empty body (which would trigger HTTP 500). The series is complete, with no open technical questions, and is ready for integration into `next`.

Key technical details include the use of `$$` (process ID) in scratch file names to avoid clobbering, redirection of `stderr` to `/dev/null` to suppress expected errors when scripts are removed concurrently, and the "permanent" mode fix in `http-429.sh` (skipping `mkdir` entirely to ensure no state marker is left). The documentation patch now emphasizes that scratch file names *should* include `$$` and provides concrete examples of safe and unsafe patterns. The series is well-motivated by real-world flakiness and unlikely to be controversial, as the fixes are minimal and targeted.
