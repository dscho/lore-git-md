This is a substantive review from Jeff King (Peff) proposing an alternative design for the `git ident` feature. Peff suggests extending the existing `git var` command to expose the same functionality rather than introducing a new built-in. His critique centers on two points: the proliferation of Git commands and the potential to improve `git var` for both identity queries and its existing use cases.

Peff’s counter-proposal would add new `git var` keys like `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, and `GIT_COMMITTER_DATE`, mirroring the environment variables Git already uses internally. He acknowledges that `git var` currently lacks support for multiple values or NUL-terminated output, but argues these are general improvements that would benefit all `git var` users, not just identity queries. For the signing-key resolution (`-s/--signing-key`) and verbose role labels (`-v/--verbose`), he suggests these could also be added as `git var` features, making the existing command more versatile.

The review is detailed and technical, walking through each of `git ident`’s flags and explaining how they could map to `git var` extensions. Peff’s tone is constructive, framing the discussion as a design question rather than a rejection of the feature itself. His alternative would avoid adding a new command while making `git var` more script-friendly, which aligns with Git’s historical preference for consolidating related functionality. The ball is now in Andrew Pleeter’s court to either defend the standalone `git ident` design or explore a `git var`-based approach.
