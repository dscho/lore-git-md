This is a **bugfix** patch from Jeff King that addresses the use-after-free regression in `git stash show` with `--src-prefix`/`--dst-prefix` reported by Nicolas Le Cam. The fix targets the root cause: `setup_revisions()` frees `argv` elements while `struct diff_options` still holds dangling pointers to those strings.

The patch takes a centralized approach by introducing a new `strvec argv_to_free` field in `struct rev_info` to delay freeing "freed" `argv` elements until `release_revisions()` is called. This ensures that any references stored in `diff_options` (like `a_prefix`/`d_prefix`) remain valid for the lifetime of the `rev_info` struct. The change is minimal and non-disruptive—no callers need modification, and it preserves the leak-fix from commit cd43948798 while eliminating the use-after-free.

Key technical details:
- **Files touched**: `revision.c` (core logic), `revision.h` (new field in `struct rev_info`), and `t/t3903-stash.sh` (new test for prefix handling).
- **Behavior change**: No user-visible change; the fix restores correct diff header output (e.g., `diff --git a/f.txt b/f.txt` instead of garbage).
- **Memory management**: The patch trades immediate freeing for delayed cleanup, avoiding leaks while preventing dangling pointers.
- **Test coverage**: Adds a regression test for `stash show --src-prefix/--dst-prefix`, verifying the fix and guarding against future regressions.

The patch is well-motivated and clearly explains the trade-offs (e.g., why not copy strings per-option). It’s targeted at the regression’s source (commit 3ea35c64b) and should be suitable for `maint`. The only open question is whether to apply it closer to the original leak-fix (cd43948798) for minimal backporting, but the current version is correct and self-contained. No controversy is evident; this looks like a straightforward fix for a real bug.
