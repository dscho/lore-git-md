This is the second patch in Junio C Hamano’s eight-patch refactoring series for `git checkout`, `git switch`, and `git restore`. The patch moves branch name validation logic (`validate_branchname()` and `validate_new_branchname()`) from the monolithic `checkout_main()` helper into `checkout_branch()`, where it logically belongs.

The change is a clean, mechanical refactoring with no behavior changes. Karthik Nayak’s review confirms it is straightforward and sensible: since `checkout_paths()` (used for path-based operations) does not create branches, validating branch names there was unnecessary. The patch relocates the validation block—unchanged except for indentation—into `checkout_branch()`, which handles branch creation and switching. The commit message and Karthik’s feedback both note that `checkout_paths()` already checks for `.new_branch` and fails early, making this move safe and improving code locality.

This patch is uncontroversial and could be merged independently if the rest of the series is deferred. It reduces `checkout_main()`’s size by 11 lines and aligns with the series’ broader goal of eliminating the "cheating" pattern where `git switch` and `git restore` were bolted onto `git checkout` via a shared helper. The test suite passes, and the change touches only `builtin/checkout.c` with no dependencies on later patches.

Karthik’s review is brief but substantive, explicitly endorsing the patch’s design and correctness. There are no open questions or objections, and the patch is ready for integration. If the series stalls due to unresolved design questions in later patches (e.g., the `cb_option` debate in the first patch), this one could proceed on its own.
