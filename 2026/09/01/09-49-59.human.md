This is a UX-focused bugfix for `git checkout -m` that improves the readability of autostash conflict messages. The patch addresses a long-standing visual clutter issue where conflict advice and the branch-switch confirmation message ("Switched to branch...") run together, making them hard to distinguish.

The core change introduces an `enum stash_apply_result` to clearly distinguish between three states: success (`STASH_APPLY_CLEAN`), conflicts (`STASH_APPLY_CONFLICT`), and errors (`STASH_APPLY_ERROR`). This replaces the previous integer return values, which conflated conflicts with other failures. The patch updates `git stash apply`, `pop`, and `branch` to exit with status 2 on conflicts (documented in the man page), while other failures retain status 1. In `git checkout -m`, a blank line is now printed between the conflict advice and the branch-switch message when conflicts occur, improving visual separation.

Files touched include `sequencer.c` and `sequencer.h` (return type changes and conflict detection logic), `builtin/checkout.c` (advice formatting), `builtin/stash.c` (exit code handling), and new test coverage in `t/t3903-stash.sh` and `t/t7201-co.sh`. The patch also adds a new `stash.h` header to define the enum. The implementation follows Phillip Wood’s proposed fix for the correctness issue raised by Junio, distinguishing between conflicts (`ret == 1`) and other errors (`ret > 1` or negative).

This is a well-scoped, uncontroversial change that addresses a real usability pain point. The commit message is clear, the test coverage is thorough, and the patch has already resolved prior review feedback. It should be ready for merging once Junio picks it up.
