This is a feature patch introducing `--missing-only` to `git rev-list`, a new option designed to streamline partial clone workflows. The patch is the second iteration of a proposal that began as `--missing=print-only` but evolved into a separate filter flag based on reviewer feedback.

The change addresses a real-world need at GitLab's Gitaly service, which currently uses `--missing=print` and post-processes the output to extract missing object IDs. With `--missing-only`, users can directly obtain a clean list of missing OIDs without the `?` prefix or present objects, eliminating the need for external filtering. The option must be paired with either `--missing=print` or `--missing=print-info` to specify the output format, and it explicitly rejects incompatible options like `--count` and `--disk-usage`.

The implementation is clean and well-scoped, touching only `builtin/rev-list.c`, the documentation, and test files. Reviewers—including Phillip Wood, Patrick Steinhardt, and Derrick Stolee—have already weighed in on the design, and the current version reflects their consensus: a separate flag is preferable to extending the `--missing=` enum. The tests use direct OID comparisons (`test_cmp`) for clarity, and the documentation clearly explains the option's behavior and constraints.

This looks like a straightforward quality-of-life improvement for partial clone users, with no obvious red flags. The patch is ready for final review and likely to be merged once any remaining nits are addressed.
