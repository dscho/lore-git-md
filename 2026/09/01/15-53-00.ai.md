This is the final version (v5) of a test infrastructure bugfix series that makes two CGI test helpers in `t/lib-httpd/` concurrency-safe. The series targets a real, observed flake in `t5616.47` on macOS CI runners, where concurrent HTTP requests to the same endpoint could race on shared state, causing HTTP 500 errors.

The core issue is that `apply-one-time-script.sh` and `http-429.sh` use non-atomic shell operations (`test -f` followed by `rm` or `touch`) to manage state in `HTTPD_ROOT_PATH`. Because Apache serves requests concurrently, and a single Git operation (e.g., a partial fetch) can open multiple requests to the same endpoint, these scripts can race: both requests pass the `test -f` check, one removes or creates the marker, and the other fails. The series fixes this by replacing the non-atomic checks with atomic operations: `rm` (without `-f`) for the one-shot marker in `apply-one-time-script.sh` and `mkdir` for the first-request election in `http-429.sh`.

Patch 1 fixes `apply-one-time-script.sh` and adds a new test (`t5567-one-time-script.sh`) that directly exercises the helper without a web server, making the race deterministic. Patch 2 makes `http-429.sh` atomic in the same way. Patch 3 documents the atomic idioms in `t/lib-httpd.sh`, incorporating feedback from Patrick Steinhardt to clarify the relationship between the marker file and the guarded logic ("guarded by the marker" instead of "claims the marker"). The documentation now also mentions `rm` (without `-f`) as an atomic alternative to `mv` for consuming one-shot markers, reflecting the change in patch 1.

The series is ready for integration into `next`. All substantive and editorial feedback from v1–v4 has been addressed, including Junio C Hamano’s concerns about commit message verbosity and Patrick Steinhardt’s documentation wording tweaks. The fixes are minimal, targeted, and confined to the test infrastructure (`t/` directory). The new test provides a deterministic way to verify the fix, and the documentation patch generalizes the pattern for future test helpers. The series is well-motivated, well-tested, and unlikely to be controversial. Recent CI failures linked in the cover letter reinforce the urgency of the fix.
