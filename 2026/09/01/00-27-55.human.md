This is the second patch in a three-patch bugfix series targeting race conditions in Git’s HTTP daemon test helpers. The series is ready for integration into `next` and has no open technical questions.

This patch makes the state management in `t/lib-httpd/http-429.sh` atomic by replacing a non-atomic "check-and-set" (`test -f` followed by `touch`) with a single `mkdir` operation. The script is used to test retry logic by returning HTTP 429 (Too Many Requests) responses, and the original implementation could race under concurrent requests, causing both to incorrectly return 429 instead of forwarding one to `git-http-backend`. The fix also corrects a latent issue in the "permanent" mode (which returns 429 to every request) by skipping the `mkdir` entirely, ensuring no state marker is left behind.

The change is minimal and surgical: it replaces the state file logic with a state directory, adds explanatory comments, and removes the now-unnecessary `touch` and `rm` operations. The commit message clearly explains the problem, the atomic idiom, and the reasoning behind the "permanent" mode fix. No regression test is included because the race cannot be forced deterministically, but the atomicity guarantees correctness under concurrency.

This patch is well-motivated and unlikely to be controversial. The atomic `mkdir` pattern is a standard shell idiom, and the fix aligns with the series’ goal of making test helpers robust against concurrent execution. The documentation update in patch 3 will make this pattern reusable for future test scripts.
