This is a documentation patch, the first of three in Karthik Nayak’s `receive-report` hook series (v5). It adds a missing section to `git-receive-pack(1)` that explains the existing `proc-receive` hook, which runs during push processing but was previously undocumented in the man page. The new `PROC-RECEIVE HOOK` section describes when the hook is triggered (when `receive.procReceiveRefs` is set and commands match the configured refs) and what it does (executes commands instead of the internal `execute_commands()` function, then reports results back to `receive-pack`).

The patch is purely additive and mechanical, touching only `Documentation/git-receive-pack.adoc`. It addresses prior feedback by using `linkgit:git-receive-pack[1]` for cross-referencing and copying the first paragraph from `githooks(5)` to avoid redundancy. The commit message is clear and concise, and the change itself is uncontroversial. This patch is already applied in the series and serves as preparatory work for the upcoming `receive-report` hook, ensuring the man page covers all hooks in the `git-receive-pack` lifecycle. No further action is needed here; it’s ready for `next`.
