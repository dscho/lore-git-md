This is the final patch in a three-part test-infrastructure bugfix series that makes HTTP daemon test helpers concurrency-safe. It adds documentation to `t/lib-httpd.sh` explaining the atomic patterns used in the previous two patches (`apply-one-time-script.sh` and `http-429.sh`) so future developers can write race-free CGI helpers.

The new comment block in `t/lib-httpd.sh` gives concrete examples of safe and unsafe idioms: use `mkdir` for exclusive access, chain `rm` (without `-f`) with the guarded logic instead of separate `test -f`/`rm` steps, and include the process ID (`$$`) in scratch filenames. The wording reflects all feedback from earlier rounds—most recently Patrick Steinhardt’s suggestion to say the logic is “guarded by the marker” rather than “claims the marker.”

This patch is purely documentation and carries no code risk. It rounds out the series by generalizing the atomic patterns for future test helpers, making the fix self-documenting. The series as a whole is ready for `next`.
