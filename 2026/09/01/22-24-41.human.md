This is the final patch in Elijah Newren’s five-part bugfix series, which extends Git’s existing protections against unsafe commit operations during conflict resolution. Specifically, this patch blocks partial commits (`git commit <paths>`) during conflict resolution for `git am`, `git revert`, and all forms of `git rebase`, mirroring the protection already in place for merges and cherry-picks.

The change reuses the `sequencer_ongoing_operation()` helper introduced earlier in the series to detect active operations and refuse partial commits with clear error messages: *"cannot do a partial commit during a merge"*, *"cannot do a partial commit during a cherry-pick"*, and so on, including a new message for rebase conflicts (*"cannot do a partial commit while resolving conflicts during a rebase"*). The patch deliberately permits partial commits during a rebase that stopped because a pick became empty (handled by `ONGOING_REBASE_NOW_EMPTY`), as this is not a conflict scenario.

The implementation touches `builtin/commit.c` and updates `sequencer.h` to clarify the purpose of `enum ongoing_operation`. Test coverage is thorough, adding new cases to `t3404-rebase-interactive.sh` (for both interactive and apply backends), `t3507-cherry-pick-conflict.sh` (revert), and `t4151-am-abort.sh` (am). The tests verify that partial commits are rejected with the correct error message during conflict resolution.

This patch is uncontroversial and technically sound. All substantive feedback from earlier iterations has been addressed, and Junio C Hamano has explicitly approved the series’ structural improvements. The only change since v3 is a mechanical rename (`ONGOING_REBASE_EMPTY` → `ONGOING_REBASE_NOW_EMPTY`) to clarify intent, with no functional impact. The series is ready for integration and aligns with Git’s ongoing efforts to improve user safety during conflict resolution.
