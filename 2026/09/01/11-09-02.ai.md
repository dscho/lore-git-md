This is a refactoring patch that removes implicit use of the global `the_hash_algo` variable in `submodule-config.c`. It is the third patch in Patrick Steinhardt’s 12-patch series removing ad-hoc ODB source linking, and it continues the broader `the_repository` removal effort.

The patch addresses two sites where `the_hash_algo` is used. The first is a trivial conversion in `gitmodules_cb`, where the caller already has a `struct repository *` available, so the hash algorithm can be taken from there instead. The second is in `hash_oid_string`, where the hashmap key for an object ID is computed. The patch updates this function to use the hash algorithm embedded in the object ID itself, adding a defensive check to ensure the object ID is properly initialized (though the commit message notes this case should never occur).

The change is small (4 insertions, 2 deletions) and mechanical, touching only `submodule-config.c`. It introduces no behavioral changes and is a straightforward cleanup that aligns with the project’s goal of eliminating global state. The defensive check in `hash_oid_string` is a minor robustness improvement. This patch is a prerequisite for later changes in the series that remove ODB source registration for submodules.
