This is the first patch in the v4 series optimizing `git last-modified` performance by reusing Bloom filters. It refactors the Bloom filter precondition check in `revision.c` to simplify the code.

The patch moves the `revs->bloom_keyvecs_nr` check from the two callsites (`rev_compare_tree` and `rev_same_tree_as_empty`) into `check_maybe_different_in_bloom_filter` itself. This is a small, mechanical refactoring that reduces duplication. The change makes `bloom_ret` return `-1` when no Bloom key vectors are present, which prevents `count_bloom_filter_false_positive` from being incremented in that case. The commit message notes this is unobservable since Bloom statistics are only reported when key vectors exist.

The diff is minimal (7 lines changed) and confined to `revision.c`. This patch sets up later changes in the series by cleaning up the Bloom filter logic before introducing new helpers. The refactoring is uncontroversial and aligns with the series' goal of making Bloom filter reuse more maintainable. No behavior changes are introduced; this is purely a code organization improvement.
