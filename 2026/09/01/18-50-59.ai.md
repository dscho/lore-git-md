This is a feature patch implementing the `--missing-only` option for `git rev-list`, addressing GitLab's Gitaly use case for partial clones. The v2 patch incorporates all review feedback from the thread, shifting from an enum-based approach (`--missing=print-only`) to a separate filter flag (`--missing-only`) that works alongside existing `--missing=` modes.

The implementation is clean and well-motivated. It adds the new flag to `builtin/rev-list.c`, updates documentation, and includes thorough tests using `test_cmp` for direct OID verification. The patch enforces clear separation of concerns: `--missing=` controls output format (with or without `path=`/`type=` fields), while `--missing-only` filters the output to show only missing objects. The leading `?` prefix is omitted for script-friendliness, and the patch explicitly rejects incompatible options (`--count`, `--disk-usage`).

- Output format: one OID per line (no prefixes), or `path=`/`type=` fields if `--missing=print-info` is used
