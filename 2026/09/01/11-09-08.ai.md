This is the ninth patch in Patrick Steinhardt’s 12-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. The patch tightens the behavior of `git multi-pack-index` when given the `--object-dir=` option: instead of silently constructing an in-memory ODB source for any directory (even one unrelated to the current repository), it now refuses to operate on directories that are not registered alternates. The change aligns the code with the documented requirement that `--object-dir=` must point to an alternate, and it removes the last real-world caller of the ad-hoc source linking mechanism outside test helpers.

The patch updates `builtin/multi-pack-index.c` to call `odb_find_source()` and, if no source is found, die with an error message rather than falling back to `odb_add_to_alternates_memory()`. The test suite (`t/t5319-multi-pack-index.sh`) is adjusted to retain and reuse a temporary repository (`repo64`) that holds the alternate link, ensuring the object directory remains a valid alternate throughout the test chain. The change is small (3 insertions, 3 deletions in the C file; 6 insertions, 6 deletions in the test script) and self-contained.

This is a breaking change in behavior, but one that was already documented as a restriction since 2021. The patch is a logical step in the series: by removing the last non-test caller of the ad-hoc source mechanism, it clears the way for the final patches that remove the mechanism entirely. No new design questions are raised; the patch simply enforces an existing constraint.
