Thread identity
Subject: [PATCH 0/13] odb: remove ad-hoc source linking
Series version: v2 (revision of v1; patch 1/13 revised, patches 2-5/13 and 8/13 new in this update, patch 6/13 unchanged from v1 except for context adjustments, patch 7/13 updated to remove now-unused submodule ODB registration infrastructure, patches 9-13/13 unchanged except for context)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove the mechanism allowing registration of in-memory sources (primarily used for submodules and temporary object directories). This eliminates dual-use of the ODB sources list for both alternates and temporary sources, simplifying the codebase and preparing for future migration of alternate handling into the "files" backend. The series also continues the broader `the_repository` removal effort by eliminating implicit dependencies on global state in the `cache-tree`, `submodule-config`, and related subsystems.

Current status
Under review; v2 posted 2026-09-05. Patch 1/13 revised to address Junio C Hamano’s feedback from v1, encapsulating the repository dependency within `cache-tree.c` and resolving two correctness issues: ensuring `write_in_core_index_as_tree()` uses `index_state->repo` and fixing a lingering `the_repository` reference in `unpack_trees.c`. Patch 2/13 (new in v2) removes the last implicit dependency on submodule ODB source registration in the `cache-tree` subsystem by adapting functions to use repositories passed via context (either as a new parameter or via `struct index_state`) instead of the global `the_repository`. Patch 3/13 (updated in v2) mechanically refactors the `submodule-config` subsystem to accept an explicit `struct repository *` parameter instead of implicitly using `the_repository`, updating all functions in `submodule-config.c` and adjusting callers in `builtin/fetch.c`, `builtin/grep.c`, `builtin/submodule--helper.c`, `submodule.c`, and `t/helper/test-submodule.c` to pass `the_repository` (preserving behavior during migration). Patch 4/13 (new in this update) eliminates two remaining uses of the global `the_hash_algo` in `submodule-config.c` by using the repository's hash algorithm (`repo->hash_algo`) and the hash algorithm embedded in the object ID (`hash_algos[oid->algo].rawsz`), respectively. Patch 5/13 (new in this update) removes the last remaining call to `odb_add_submodule_source_by_path()` in `submodule-config.c`, deleting the conditional block that registered a submodule’s ODB path with `the_repository->objects` when reading `.gitmodules` from a blob in a non-main repository. Patch 6/13 (unchanged from v1 except for context adjustments) removes the now-unnecessary registration of submodule object databases as alternates in `git grep`, a cleanup made possible by prior work (commit 0693806bf8, 2021) that ensured `git grep` passes submodule repositories directly to worker threads. The patch updates a NEEDSWORK comment to reflect the remaining thread-safety concern (initializing the subrepository still requires the object-read lock due to `get_main_ref_store()`). Patch 7/13 (updated in this revision) removes the now-unused infrastructure for registering submodule ODBs as in-memory sources, deleting `odb_add_submodule_source_by_path()`, the `submodule_source_paths` string list from `struct object_database`, `register_all_submodule_sources()`, and the `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test mode. The test mode is removed from `t/README` and its exports from seven test scripts (`t/t5526-fetch-submodules.sh`, `t/t5531-deep-submodule-push.sh`, `t/t5545-push-options.sh`, `t/t5572-pull-submodule.sh`, `t/t6437-submodule-merge.sh`, `t/t7418-submodule-sparse-gitmodules.sh`, and `t/t7814-grep-recurse-submodules.sh`). Patch 8/13 (new in this update) removes the now-unused `tmp_objdir_add_as_alternate()` function from `tmp-objdir.c` and its declaration from `tmp-objdir.h`, a cleanup made possible by prior work (commit bdee7b3013, July 2026) that switched `builtin/receive-pack` to use ODB transactions instead of registering temporary object directories as alternates. Patch 9/13 (unchanged except for context) fixes a memory leak in the packed ODB source backend by ensuring `odb_source_close(source)` is called before freeing the source, addressing a leak that surfaces when packed sources are not linked to the main ODB (a scenario introduced by the series' removal of ad-hoc source linking). Patch 10/13 (updated in this revision) enforces a long-documented constraint in `git multi-pack-index --object-dir=`: the specified object directory must be an alternate of the current repository. Previously, Git would silently create an ad-hoc source and link it to the main ODB, contradicting the documentation and creating the last real-world caller of the ad-hoc source mechanism outside test helpers. The patch replaces this behavior with an explicit error message and updates one test chain in `t5319-multi-pack-index.sh` to retain a temporary repository (`repo64`) that provides the required alternate relationship. The remaining 3 patches (11-13/13) are unchanged from v1. Series consists of 13 patches: incidental cleanups (removing `the_repository`/`the_hash_algo` dependencies in `cache-tree`, `submodule-config`, and related callers), core refactoring (removing submodule ODB source registration in `submodule-config`, `builtin/grep`, and ODB infrastructure), a bugfix for a memory leak in the packed ODB source (patch 9/13), enforcement of an existing constraint in `git multi-pack-index --object-dir=` (patch 10/13), test helper updates (patches 11/13 and 12/13), and final removal of the ad-hoc source linking API (patch 13/13). Junio C Hamano provided **substantive reviews** of patches 1/13 and 6/13 in v1, signaling unqualified approval with *“Yay. Very nice.”* No new reviews or objections in v2; the series remains self-contained with no external dependencies.
