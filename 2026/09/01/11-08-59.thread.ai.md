Subject: [PATCH 0/13] odb: remove ad-hoc source linking
Series version: v2 (revision of v1; patch 1/13 revised, patch 2/13 new in this update, patches 3-5/13 updated in this revision, patches 6-13/13 unchanged)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove the mechanism allowing registration of in-memory sources (primarily used for submodules). This eliminates dual-use of the ODB sources list for both alternates and temporary sources, simplifying the codebase and preparing for future migration of alternate handling into the "files" backend. The series also continues the broader `the_repository` removal effort by eliminating implicit dependencies on global state in the `cache-tree`, `submodule-config`, and related subsystems.

Current status
Under review; v2 posted 2026-09-05. Patch 1/13 revised to address Junio C Hamano’s feedback from v1, encapsulating the repository dependency within `cache-tree.c` and resolving two correctness issues: ensuring `write_in_core_index_as_tree()` uses `index_state->repo` and fixing a lingering `the_repository` reference in `unpack_trees.c`. Patch 2/13 (new in v2) removes the last implicit dependency on submodule ODB source registration in the `cache-tree` subsystem by adapting functions to use repositories passed via context (either as a new parameter or via `struct index_state`) instead of the global `the_repository`. Patch 3/13 (updated in v2) mechanically refactors the `submodule-config` subsystem to accept an explicit `struct repository *` parameter instead of implicitly using `the_repository`, updating all functions in `submodule-config.c` and adjusting callers in `builtin/fetch.c`, `builtin/grep.c`, `builtin/submodule--helper.c`, `submodule.c`, and `t/helper/test-submodule.c` to pass `the_repository` (preserving behavior during migration). Patch 4/13 (new in this update) eliminates two remaining uses of the global `the_hash_algo` in `submodule-config.c` by using the repository's hash algorithm (`repo->hash_algo`) and the hash algorithm embedded in the object ID (`hash_algos[oid->algo].rawsz`), respectively. Patch 5/13 (new in this update) removes the last remaining call to `odb_add_submodule_source_by_path()` in `submodule-config.c`, deleting the conditional block that registered a submodule’s ODB path with `the_repository->objects` when reading `.gitmodules` from a blob in a non-main repository. This cleanup is now safe because earlier patches ensure all object lookups use the submodule’s repository context. The remaining 8 patches (6-13/13) are unchanged from v1. Series consists of 13 patches: incidental cleanups (removing `the_repository`/`the_hash_algo` dependencies in `cache-tree`, `submodule-config`, and related callers), core refactoring (removing submodule ODB source registration in `submodule-config`, `builtin/grep`, and ODB infrastructure), a bugfix for a memory leak in the packed ODB source (patch 9/13), enforcement of an existing constraint in `git multi-pack-index --object-dir=` (patch 10/13), test helper updates (patches 11/13 and 12/13), and final removal of the ad-hoc source linking API (patch 13/13). Patch 10/13 enforces an existing documented constraint, removing the last real-world caller of the ad-hoc source linking mechanism outside test helpers. Junio C Hamano provided a **substantive review** of patch 6/13 in v1, signaling unqualified approval with *“Yay.
