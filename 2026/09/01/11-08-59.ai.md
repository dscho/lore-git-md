This is a refactoring patch series targeting the object database (ODB) subsystem. The series removes the mechanism that allows registering in-memory sources (primarily used for submodules) in the ODB, simplifying the codebase by eliminating dual-use of the sources list for both alternates and temporary sources. The goal is to make the ODB easier to reason about and pave the way for migrating alternate handling into the "files" backend in a future series.

The series consists of 12 patches, with the first few addressing incidental cleanups (removing dependencies on `the_repository` and `the_hash_algo` in `cache-tree` and `submodule-config`). The core changes begin in patch 4, where `submodule-config` stops registering submodule ODB sources, followed by similar removals in `builtin/grep` and the ODB infrastructure itself. The series concludes by removing the ability to link sources ad-hoc entirely, leaving only the quarantine directory mechanism (an implementation detail of the "files" backend) as an exception.

Key files touched include `odb.c`/`odb.h` (removing the registration API), `submodule-config.c` (adapting to the new model), and `builtin/grep.c` (stopping submodule ODB registration). Tests and helpers (`t/helper/test-read-midx.c`, `test-ref-store.c`) are updated to reflect the removal of the ad-hoc source linking mechanism. The series is built on top of `master` (as of 2026-08-31) with a minor merge conflict resolution shown in the cover letter.

The motivation is clear: the dual-use of the sources list has long been a design wart, and recent refactoring (e.g., submodule sources no longer needing to link into the main ODB) makes this cleanup feasible. The series is well-scoped and appears to be a natural progression of Patrick Steinhardt’s ongoing ODB abstraction work. The removal of ~80 lines of code while maintaining functionality suggests a net improvement in maintainability. No behavioral changes are expected, but the cover letter notes that this sets the stage for future performance fixes in alternate handling.
