This is a bugfix patch in Patrick Steinhardt's 12-patch ODB refactoring series. It plugs a memory leak in the "packed" object database source that surfaces when freeing an ad-hoc source that is not linked to the main object database. The leak occurs because the source's packs and multi-pack indices are not closed before freeing the source.

The patch is small (one line) and surgical: it adds a call to `odb_source_close(source)` in `odb_source_packed_free()` to ensure all resources are released. The commit message explains the context clearly: the leak was masked until now because all packed sources were previously linked to the main ODB, but the ongoing refactoring (specifically, the removal of ad-hoc source linking) will expose it. This fix is a prerequisite for the later patches in the series that stop linking sources.

The change is in `odb/source-packed.c`, a low-level file that handles the packed object storage backend. No other files are touched, and the patch does not affect behavior or on-disk formats. The fix is well-motivated and narrowly scoped, addressing a latent issue that would otherwise become visible in subsequent commits. The series as a whole is part of Patrick Steinhardt's ongoing ODB abstraction effort, and this patch is a necessary cleanup to keep the refactoring safe.
