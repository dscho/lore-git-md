This thread began with a quick fix to restore GitLab CI’s documentation build after a dependency change broke the Asciidoctor installation, then evolved into a small but useful modernization. Patrick Steinhardt’s initial patch ensured Ruby was available for `gem install asciidoctor`, while Jeff King followed up with a two-patch series that removed an outdated version pin and switched to the system-provided Asciidoctor package. The original fix is already in `master`, and Jeff’s series is now complete and uncontroversial, with only Junio’s final review remaining.

The key change replaces `gem install asciidoctor -v 1.5.8` with `apt-get install asciidoctor`, using the Ubuntu image’s default version (2.0.20). This matches what users are likely to have installed locally and eliminates maintenance overhead. The thread also clarified that the original version pin was unnecessary after a 2019 compatibility fix, and that even older enterprise distributions like Debian 11 and RHEL 8 ship Asciidoctor 2.x. Todd Zullinger added context about RHEL’s packaging—Asciidoctor lives in EPEL, not the base OS, and the package is currently unmaintained—but this doesn’t affect the patch, which targets Ubuntu-based CI jobs.

The only loose end was the purpose of the `concurrent-ruby` gem, but this was resolved in Jeff’s cover letter and doesn’t block the series. The patch is ready to merge.
