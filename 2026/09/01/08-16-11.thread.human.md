This thread is about a small but necessary fix to Git's GitLab CI configuration to restore the ability to build documentation after a dependency change broke the Asciidoctor installation. The patch itself—a one-line addition to `ci/install-dependencies.sh` to explicitly install Ruby—is uncontroversial and effectively resolved. Patrick Steinhardt posted the fix, which was verified in a linked CI pipeline, and while he acknowledged a minor typo in the commit message, he opted not to send a new version just for that.

The discussion then expanded to the broader question of why the CI configuration still pins Asciidoctor to version 1.5.8, a release from 2018. Jeff King provided historical context, noting that the original blocker (compatibility with Asciidoctor 2.0.0) was resolved in 2019, but the pin was never updated. Junio Hamano endorsed this view, agreeing that testing an eight-year-old version is no longer useful and that CI should focus on versions people actually use. Patrick Steinhardt concurred but chose to keep the original fix minimal, leaving the version-pinning question as a forward-looking maintenance opportunity rather than a blocker. The thread is now effectively closed on the bugfix side, while the version-pinning discussion remains open-ended but non-urgent.
