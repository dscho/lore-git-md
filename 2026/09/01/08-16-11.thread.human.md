This thread began with Patrick Steinhardt’s quick fix to restore Ruby availability in GitLab CI after a transitive dependency removal broke the documentation build. That patch is effectively done and ready to merge. The discussion then broadened to address an outdated Asciidoctor version pin (1.5.8 from 2018), which Jeff King has now tackled in a two-patch series.

Jeff’s follow-up series first removed dead code left over from the retired Azure Pipelines CI, then proposed switching from a manually installed, pinned Asciidoctor version to the one provided by Ubuntu’s system package manager. The second patch, just posted, is a small, mechanical change that installs `asciidoctor` via `apt-get` instead of `gem install`, letting the CI environment use its default version (2.0.20 in the test run). This simplifies the build script, reduces maintenance, and ensures the CI tests a version closer to what users actually have. The change is uncontroversial, well-documented, and validated by a successful test run.

The original fix and Jeff’s series are both complete and ready for merging. The only loose end—a question about whether the `concurrent-ruby` gem is still needed—doesn’t block either patch and hasn’t drawn a response from Jean-Noël Avila, who was cc’d for input. This is a straightforward maintenance update that modernizes the CI configuration with minimal risk.
