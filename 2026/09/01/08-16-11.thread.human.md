This thread began with Patrick Steinhardt’s quick fix to restore Ruby availability in GitLab CI after a transitive dependency removal broke the documentation build. That patch is already merged. The focus then shifted to Jeff King’s two-patch follow-up series, which modernizes the CI configuration by replacing the manual installation of Asciidoctor 1.5.8 (a version pinned since 2018) with the system-provided package in Ubuntu, currently version 2.0.20. This change simplifies the CI setup, aligns it with what users are likely to have installed locally, and removes an outdated version constraint.

The series is now complete and uncontroversial. The first patch removed dead code left over from the retired Azure Pipelines CI, while the second replaced the manual `gem install` with an `apt-get install asciidoctor`. Jeff King validated the change with a GitHub Actions test run, and Junio Hamano endorsed the direction, noting that newer Asciidoctor versions work fine and that CI should prioritize testing versions people actually use. Patrick Steinhardt raised two tangential concerns—whether the CI build might rely on features unavailable in older Asciidoctor versions, and why the `concurrent-ruby` gem is still installed—but neither blocks the current patch. Jeff dismissed the forward-compatibility concern as unnecessary, and the gem’s necessity remains unexplained but is orthogonal to this update. The series is ready for merging.
