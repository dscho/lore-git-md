This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI workflows, introduced by Johannes Schindelin (Dscho) via a two-part patch series. The immediate goal is to resolve a compatibility issue where Rust’s default MSVC-targeting toolchain on GitHub’s Windows runners produces libraries incompatible with MinGW’s linker, breaking the build. The first patch addresses this by configuring Cargo to build a GCC-compatible static library, using the correct target triple derived from the `MSYSTEM` environment variable.

The changes are minimal and focused on the build system (`Makefile` and `config.mak.uname`), with no impact on core Git functionality or user-facing features. The patch is well-justified, with a clear error message and a link to a failed CI run demonstrating the problem. While the patch itself appears ready for review, one open question remains: whether GitLab’s Windows runners also have Rust pre-installed, which Dscho couldn’t confirm. No objections or requests for changes have been raised yet, but the series is still in its early stages (v1). If this lands, it will unblock the default Rust requirement introduced in Git 2.55.0 for Windows CI.
