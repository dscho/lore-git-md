This thread is about a two-patch series from Johannes Schindelin that enables Rust compilation in Git’s GitHub Actions Windows CI workflows. The goal is to configure the Rust toolchain to target the GCC ABI (used by Git for Windows) rather than the default MSVC ABI, ensuring compatibility with MinGW’s linker. The series is currently under initial review, with no prior versions or merge status.

Junio C Hamano has raised a substantive but narrow technical question about an inconsistency in the Rust target triple mapping for the UCRT64 MSYS2 environment. The `Makefile` logic assigns `x86_64-pc-windows-gnu` to UCRT64, while the shell script in the second patch maps it to `x86_64-pc-windows-gnullvm`. Junio asks whether this divergence is intentional or an oversight, as UCRT64 does not match the `CLANG%` pattern in the `Makefile`, causing it to fall through to the GNU target. This feedback is focused on build configuration logic and does not challenge the overall approach, but it will need to be addressed before the series can move forward.

The series touches CI/build system files (`.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and `Makefile`) and is a prerequisite for the broader Rustification effort in Git. It does not introduce Rust code into the codebase but removes the `NO_RUST` opt-out in the second patch, directly unblocking future Rust-related CI changes. No objections or requests for changes beyond Junio’s question have been raised yet, and the author has requested testing on GitLab’s Windows runners to confirm Rust availability there.
