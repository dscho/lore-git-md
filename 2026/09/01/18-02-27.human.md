This is a small but welcome refactoring patch that tidies up the `mark_argv_for_free()` helper in `revision.c`. It builds directly on Jeff King’s earlier fix for the `git stash show` use-after-free regression, which introduced a `strvec argv_to_free` field in `struct rev_info` to delay freeing of `argv` elements until `release_revisions()` is called.

The patch moves the `free_removed_argv_elements` flag check into `mark_argv_for_free()` itself, eliminating redundant checks in all callers. This makes the code cleaner and less error-prone, as the logic for when to free elements is now centralized in one place. The change is purely internal and has no user-visible impact—it simply consolidates a small but recurring pattern. Junio’s quick endorsement ("I like it") suggests this is a straightforward improvement that should be uncontroversial.

The one exception is `setup_revisions_from_strvec()`, which wasn’t previously checking the flag but always sets it explicitly. The patch handles this case safely, as the flag will always be set when the helper is called. The updated helper now takes a `const struct setup_revision_opt *` parameter, which is a minor but logical adjustment to reflect its new responsibility.

This is part of a two-patch series targeting the regression introduced in Git 2.52.0. The earlier patch fixed the bug, and this one improves the code’s maintainability. Both are ready for `maint` and should be picked up together. The patch is well-explained, touches only one file, and aligns with the project’s preference for small, focused cleanups. If you’re tracking the `stash show` regression, this is a natural follow-up worth noting.
