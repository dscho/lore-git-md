This is a **bug report and usability discussion** about silent corruption of binary files in Git on Windows (and cross-platform) due to misconfigured global `.gitattributes` rules. The author, Skybuck Flying, reports that a global `.gitattributes` file containing `* text diff=lfclean` forces Git to treat *all* files—including binaries like PNGs—as text, then applies a textconv filter (`sed -e s/\r//`) that corrupts them during checkout. The issue is reproducible and stems from overly broad attribute rules, not a Git code defect.

The email provides a detailed diagnosis: the global `.gitattributes` rule `* text diff=lfclean` applies to every file, while the `lfclean` diff driver strips carriage returns (`\r`) via `sed`. When Git checks out a binary file (e.g., a PNG), the filter rewrites its content, corrupting it. The author confirms this by comparing a Git-downloaded file with a curl-downloaded version (intact) and demonstrates that the raw blob in Git’s object database is uncorrupted—proving the corruption occurs during checkout. The fix is straightforward: restrict the `.gitattributes` rule to text files (e.g., `*.txt text diff=lfclean`) or explicitly mark binaries as `binary` (e.g., `*.png binary`).

While the root cause is user misconfiguration, the email argues for Git-side safeguards, such as warnings when global attributes force text filters onto known binary formats. The author’s proposed solutions include:
1. **Documentation improvements**: Highlight the risks of global `*` rules in `gitattributes(5)`.
2. **Diagnostics**: Add warnings when textconv filters are applied to files Git detects as binary.
3. **Safeguards**: Prevent or warn about overly broad attribute rules (e.g., `* text`).
