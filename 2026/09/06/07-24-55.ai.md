This is the first patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It is a preparatory refactoring that improves error reporting in `unpack-objects.c` by distinguishing missing objects from type mismatches. Currently, when `receive.fsckObjects` is enabled and an object is missing from the pushed pack, Git reports “object of unexpected type,” which misleadingly suggests corruption rather than a missing object. This patch aligns the diagnostics with `index-pack`, reporting “did not receive expected object <oid>” for missing objects and reserving the type-mismatch message for actual type errors.

The change is small but important for the series’ usability goals: clearer error messages help users understand why a push failed and how to recover, which is especially relevant for the later patches that introduce a tri-state config option (`push.shallowExcludeBoundary`) with a false-positive failure mode. The patch touches `builtin/unpack-objects.c` and updates a test in `t/t5504-fetch-receive-strict.sh` to verify the new error message. The implementation is straightforward, using `odb_read_object_info()` to check for object existence before comparing types, and the test ensures the old misleading message is no longer emitted.

This is a well-motivated, low-risk refactoring that directly supports the series’ broader goal of making `git push` from shallow clones more user-friendly. It does not change behavior—only the clarity of error messages—but it is a necessary foundation for the later patches, which rely on precise diagnostics to guide users through edge cases. The patch is unlikely to be controversial, as it aligns with existing patterns in `index-pack` and improves the user experience without introducing new failure modes.
