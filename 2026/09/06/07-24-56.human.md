This is the second patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It is a small but important usability improvement: it prevents `receive-pack` from spamming the user with duplicate connectivity errors when rejecting multiple refs.

When `receive-pack` detects that a push is missing objects, it first runs a bulk connectivity check that already reports the full diagnostic (e.g., “fatal: Failed to traverse parents”). It then checks each ref individually to determine which ones to reject, but these per-ref checks repeat the same diagnostic for every broken ref. This patch silences the per-ref checks’ stderr while preserving their exit status and the per-ref rejection logic. The result is cleaner output: the user sees the diagnostic once, not once per rejected ref.

The change is minimal: a single line setting `opt.quiet = 1` before the per-ref checks, plus a test update to verify that stderr is now empty. The test also switches from `actual` to `actual.raw` to avoid confusion with the packet-line framing that `receive-pack` uses for its ref-status output. This is a clear win for usability with no downside; it simply removes noise that was already redundant. The patch is well-motivated and uncontroversial, and it directly addresses feedback from earlier rounds that the error output was unnecessarily verbose.
