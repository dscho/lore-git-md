This is a performance optimization for `git push` from shallow clones, now expanded into a six-patch series at v3. Elijah Newren addresses the long-standing inefficiency where `git push` from a shallow clone resends the entire toplevel tree (gigabytes in large repos) even for tiny changes, due to walking back to shallow grafts and assuming the server lacks them. The series introduces a new tri-state config option, `push.shallowExcludeBoundary`, which defaults to `false` for now but is argued to be safer and more efficient as `true` in a later patch.

The first three patches improve error handling in related areas: `unpack-objects` now distinguishes missing objects from type mismatches, `receive-pack` avoids repeating connectivity errors, and `shallow.c` rejects missing boundaries without disconnecting. These lay the groundwork for the core change in patch 4, which adds the `push.shallowExcludeBoundary` option (values: `true`, `false`, or `abort`). Patch 5 argues for changing the default to `true`, and patch 6 adds advice for retrying problematic multi-ref pushes separately.

The implementation is careful and well-tested, with new tests in `t5538-push-shallow.sh` covering edge cases like a rejected ref not over-excluding objects needed by an accepted ref, and the interaction with `receive.shallowUpdate`. The series also addresses feedback from Stolee and Patrick Steinhardt, including clearer error messages and a more nuanced config option. This looks like a mature, well-crafted solution to a real-world performance pain point, with thorough attention to backward compatibility and edge cases. The discussion around defaults and trade-offs is still open, but the core mechanism is solid.
