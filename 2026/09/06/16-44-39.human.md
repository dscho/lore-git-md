This is a follow-up in the now-closed `[PATCH 0/3] format-patch: add --[no-]range-diff-notes` thread. Kristoffer Haugsbakk responds to D. Ben Knoble’s surface-level review of the rewritten documentation snippet for the abandoned feature.

Kristoffer clarifies the intended semantics of the `--range-diff-notes` option, particularly the "override behavior" that allows users to revert to the default notes list after suppressing or customizing range-diff notes. He provides a concrete example: an alias that applies four notes to patches but only one to the range-diff, and then shows how `--no-range-diff-notes --range-diff-notes` would revert the range-diff to displaying all four notes again. The explanation is detailed and includes edge cases, such as the special meaning of a bare `--range-diff-notes` when the range-diff notes list is empty. He also notes that the current implementation does not use the default notes ref for `--range-diff-notes` (unlike `--notes`), arguing that `format-patch` should demand more intentionality for email-bound output.

The exchange remains purely about documentation clarity and option semantics; no technical issues are raised, and the thread is still closed with no expectation of further changes. Kristoffer’s response confirms that the implementation already followed the design Junio sketched (separate control for patch notes and range-diff notes), but the original documentation failed to make this clear. The discussion is niche and unlikely to attract broader attention, but it provides a complete record of the intended behavior for anyone who might revisit the feature later.
