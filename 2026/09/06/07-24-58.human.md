This is the fourth patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It implements the core optimization: a new config option, `push.shallowExcludeBoundary`, that lets users omit shallow boundary objects from the pack when pushing, reducing redundant data transfer.

The patch adds the tri-state config (`true`/`false`/`abort`) and the logic to walk from pushed refs to their shallow grafts, adding those grafts as negative tips. This stops the pack generation from walking back to the full toplevel tree, cutting transfer size dramatically in large repos. The walk stops early at commits the server already has, keeping it efficient. The default remains `false` for backward compatibility, but the series argues for switching it to `true` in a later patch.

Tests cover the three config modes: `true` (optimization on, avoids sending the full tree), `false` (historical behavior, sends the full tree), and `abort` (refuses the push if a shallow graft is reached). They also verify the optimization doesn’t over-exclude objects needed by other refs and that pushes to `receive.shallowUpdate` receivers are correctly rejected when the boundary is omitted.

This is a well-crafted solution to a real performance pain point, with thorough test coverage and clear documentation of the trade-offs. The tri-state config gives users explicit control, and the preparatory patches in the series (already summarized) ensure the error handling is robust. The only open question is whether the project will accept changing the default to `true` in the future.
