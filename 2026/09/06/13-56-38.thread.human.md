This thread is an RFC from Nicolas Jeanmonod proposing a new `git clean` feature: persistent exclude patterns via configuration. The idea is to add a `clean.exclude` multi-valued config key that would automatically protect specified untracked paths from deletion by `git clean`, even when using `-x` (which normally removes ignored files). This would spare users from having to remember to pass `-e <pattern>` each time, addressing a common pain point where irreplaceable untracked directories (like local metadata or build artifacts) are accidentally wiped during aggressive cleaning.

The proposal is purely conceptual at this stage—no implementation has been posted. The goal is to validate the use case and gather feedback on the design approach, particularly whether the config-based solution aligns with Git’s existing semantics. Key questions likely to emerge include whether this overlaps with `.gitignore` or `core.excludesFile` (which serve different purposes), and whether a config-based approach is preferable to a dedicated exclude file. The thread’s outcome will determine if this moves forward as a patch series.
