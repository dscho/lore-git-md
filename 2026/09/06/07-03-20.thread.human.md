This thread is a meta-discussion about the version numbering for Git’s next major release after 2.56, which is expected to conclude around the end of September 2026. Junio C Hamano, the project’s maintainer, has outlined four possible paths forward: a big version bump to **Git 3.0**, a transitional **Git 2.99** release to signal an impending 3.0 in 2027, a delayed decision with **Git 2.98 or 2.97**, or simply continuing with **Git 2.57** as business as usual.

Junio’s email is not a vote but an invitation to assess the project’s readiness for a major version bump. The key question is whether the `BreakingChanges` document reflects sufficient foundational work or breaking changes to justify a 3.0 release. While Junio’s tone suggests a preference for a deliberate transition—likely favoring a 2.99 or similar intermediate step—no decision has been made yet. The discussion will likely revolve around what remaining work or breaking changes are needed before the project can confidently move to 3.0. So far, only Junio has weighed in, and the thread is just getting started.
