This is the fifth patch in Elijah Newren’s six-patch series optimizing `git push` from shallow clones. It flips the default of the new `push.shallowExcludeBoundary` config option from `false` to `true`, meaning the optimization (omitting redundant shallow boundary objects) will now apply by default.

The patch updates the documentation to reflect the new default, changes the fallback value in `send-pack.c` when the config is unset, and adjusts the test suite to explicitly set `push.shallowExcludeBoundary=false` in the few places where the old behavior is still required. The commit message argues that the performance benefit — avoiding gigabytes of unnecessary tree transfer in large repos — outweighs the rare edge cases where the server lacks the shallow boundary. Those edge cases either fail fast (preferable to accidental success) or can be worked around by retrying the push with individual refs, as advised in the next patch.

This is a deliberate trade-off: the project is choosing faster, smaller pushes for the common case at the cost of occasional false-positive rejections in rare scenarios. The change looks well-justified and the documentation is clear about the implications, but the default flip may still draw scrutiny from reviewers who prioritize backward compatibility or worry about usability regressions. The patch itself is small and mechanical, touching only documentation, a single config lookup, and test expectations.
