This is the fourth patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It implements the core optimization: a new config option, `push.shallowExcludeBoundary`, that lets users omit shallow boundary objects from the pack when pushing, reducing redundant data transfer. The patch adds the config key (with tri-state values `true`/`false`/`abort`), the logic to walk from pushed refs to their shallow grafts and add those grafts as negative tips, and thorough test coverage for edge cases like over-exclusion and interaction with `receive.shallowUpdate`.

The implementation is careful: it only excludes shallow grafts reachable from the pushed refs, stops early at commits the server already has, and ensures the connectivity check will reject the push if the assumption (that the server has the graft) is wrong. The default remains `false` for backward compatibility, but the series’ fifth patch will argue for switching it to `true`. The new `abort` option lets users opt out entirely if they prefer not to choose between performance and correctness. This patch is the technical centerpiece of the series and looks well-crafted, with clear documentation and robust test coverage for the edge cases raised in review.
