This is the third patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It targets a specific edge case in the shallow boundary handling: when an incomplete shallow push refers to a boundary commit the receiver does not have, `receive-pack` currently aborts with a fatal error, leaving the client with a cryptic "remote hung up" message. The patch changes this behavior to treat missing boundary commits as the end of the traversal path rather than a fatal error, allowing the connectivity check to reject the affected refs cleanly with "missing necessary objects" messages.

The change is in `shallow.c`, where `paint_down()` now uses `repo_parse_commit_gently()` and checks for object existence with `odb_has_object()` before dying. If the commit is missing (rather than corrupt), the function skips it and continues processing the remaining commits. The test in `t/t5538-push-shallow.sh` verifies that the server rejects the affected refs without disconnecting and that the error messages are clear and actionable. This is a preparatory patch for the core optimization in patch 4, ensuring that the connectivity checks are robust enough to handle the edge cases introduced by excluding shallow grafts from the pack boundary.

The patch is well-motivated and addresses a real usability issue: the current behavior leaves users with no clue why their push failed, while the new behavior provides clear error messages and preserves the connection for further diagnostics. The test coverage is thorough, including a scenario that mimics an incomplete shallow push without relying on `send-pack` to create it. This looks like a clean, low-risk improvement that paves the way for the more ambitious changes later in the series.
