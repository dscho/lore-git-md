This is the seventh patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort, which aims to simplify the object database interface by making alternates an implementation detail of the backend.

This patch wires up the new `odb_create_on_disk_options` mechanism introduced earlier in the series. It removes the last direct use of `odb_add_to_alternates_file()` in `git clone` by passing the collected alternates paths directly to `create_object_database()` via a `strvec`. The change is mechanical and consolidates alternates setup into a single step during ODB creation, replacing the manual loop that previously wrote each alternate to the `info/alternates` file. The patch touches only `builtin/clone.c`, `setup.c`, and `setup.h`, and preserves backward compatibility with existing callers (e.g., `init_db()`) by allowing a `NULL` alternates parameter.

Justin Tobler’s review is brief but substantive, confirming that the patch correctly shifts alternates handling into `create_object_database()` and aligns with the series’ design goals. The patch is well-motivated and unlikely to be controversial, as it merely connects the new alternates-handling infrastructure to the existing codepath. Its correctness depends on the earlier patches, particularly the lockfile API adoption in patch 6, which ensures atomic writes to the `info/alternates` file.

No user-visible behavior changes are expected, and the patch is a straightforward integration of the refactoring work done in patches 1–6. Reviewers may focus on edge cases (e.g., empty or `NULL` alternates vectors), but the implementation appears robust. The series is now technically complete, with the lockfile API adoption resolving the primary blocker raised by Junio C Hamano in v1. The remaining patches (notably patch 8, which removes the unused `write_alternates()` infrastructure) will finalize the transition to the new design.
