This is the sixth patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the broader ODB abstraction effort, aiming to simplify the interface by removing the ability to write alternates after repository creation. This patch introduces the `odb_create_on_disk_options` struct and implements atomic alternates writing during ODB creation using Git’s lockfile API, addressing a TOCTOU race concern raised in v1.

Justin Tobler’s reply raises a forward-looking question about the ODB abstraction’s design implications. He notes that the new interface still exposes alternates to backends, even though some backends (e.g., a future in-memory or cloud-based ODB) may not use alternates at all. His question is whether `git clone --shared` and similar options should remain tied to the "files" backend or if their behavior should become backend-specific. This isn’t a critique of the current patch—it works as intended for the "files" backend—but rather a probing question about how the abstraction will handle feature compatibility as more backends are introduced.

The question touches on a key tension in the ODB abstraction effort: whether to preserve user-visible features like `--shared` across all backends or to allow backends to define their own semantics. Justin’s phrasing ("should only be allowed" vs. "backend specific") suggests he’s thinking about maintainability and user expectations. The patch itself doesn’t answer this, but the question is likely to resurface as the abstraction matures. For now, the series remains focused on the "files" backend, and this patch is a necessary step toward making alternates an implementation detail rather than a core ODB concern.

The reply is substantive but not a blocker. It engages with the patch’s architectural implications without challenging its correctness or implementation. Reviewers focused on the ODB abstraction (e.g., Karthik Nayak) may weigh in, but the patch itself is technically sound and ready for integration.
