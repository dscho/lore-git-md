This is the second patch in Elijah Newren’s six-patch v3 series optimizing `git push` performance from shallow clones. It addresses a minor but noticeable usability issue in `receive-pack`: when a bulk connectivity check fails, the subsequent per-ref checks redundantly repeat the same error messages (e.g., "fatal: Failed to traverse parents") for every broken ref. The patch silences stderr during the per-ref checks while preserving their exit status and the per-ref rejection logic.

The change is small and focused: it sets `opt.quiet = 1` in `set_connectivity_errors()` before running the per-ref connectivity checks, ensuring that only the bulk check’s diagnostics are shown. The test updates (`t/t5410-receive-pack.sh`) verify that the error messages now appear in the packetized output (not stderr) and that stderr remains empty. This aligns with the series’ broader goal of improving error handling and user experience, particularly for the shallow-clone optimization in later patches.

The patch is uncontroversial and well-motivated. It doesn’t alter behavior—just reduces noise—and the test coverage ensures the change doesn’t break existing functionality. This is a clean, surface-level improvement that supports the series’ larger performance goals without introducing new risks.
