This is a CI/build system follow-up from Jeff King (Peff) in the ongoing thread about updating Git's CI to use Debian 12 instead of Debian 11. The original patch is already queued in `seen` with intent to merge, but Peff now raises a tangential but related concern about the project's use of outdated Ubuntu images in other CI jobs.

Peff notes that the `linux32` build job is still using Ubuntu 20.04, which has been out of LTS support for a year. He explains that bumping this job to a newer Ubuntu version isn't feasible because Ubuntu dropped i386 platform support, and Debian has done the same. His inclination is to leave the job as-is unless it starts causing problems, reasoning that while 32-bit platforms are niche, they still matter for some use cases (e.g., small ARM chips). He suggests that an ARM image (like `armhf`) might be a viable alternative if the project wants to maintain 32-bit coverage, but he doesn't propose a concrete change here.

He also points out that the `linux-TEST-vars` job uses Ubuntu 20.04, and while it could theoretically be updated to `ubuntu-latest`, it might be serving a dual purpose: testing exotic configurations *and* testing on an older platform. He doesn't push for an immediate change but flags it as something worth considering if the project wants to align this job with the "oldest in-scope LTS" practice.

The tone is pragmatic and low-key: Peff isn't demanding action, just surfacing the issue for future discussion. This isn't a blocker for the Debian 12 patch, but it does highlight a broader question about how aggressively the project should update (or retire) CI jobs for older platforms. If someone cares about 32-bit or older Ubuntu coverage, this email is a nudge to speak up before the jobs become unmaintainable.
