This is a follow-up in the ongoing discussion about how to attribute LLM-assisted contributions in Git. Kristoffer Haugsbakk shares an update from the Linux kernel project, which recently simplified its LLM attribution policy to use a generic `Assisted-by: LLM` trailer instead of naming specific models or versions. He suggests Git might adopt a similar approach, noting that tracking exact LLM versions (e.g., "Codex gpt-5.5") offers little long-term value to the project and risks becoming outdated or irrelevant.

The email is brief and factual, pointing to a concrete precedent in a related project. It doesn’t revisit the technical merits of the `ls-files` optimization patch (which appear settled) but instead focuses on the metadata question raised earlier. The tone is neutral and constructive, framing the Linux kernel’s decision as a reasonable model for Git to consider. This could prompt further discussion about formalizing Git’s own policy on LLM attribution, though no immediate action is proposed.
