This is the sixth and final patch in Elijah Newren’s v3 series optimizing `git push` from shallow clones. It adds user-facing advice to split multi-ref pushes when a shallow boundary exclusion causes the push to fail, addressing the false-positive failure mode identified by Derrick Stolee in earlier reviews.

The patch introduces a new advice message (`advice.pushShallowBoundary`) that appears when a multi-ref push is rejected due to an omitted shallow boundary. The message suggests pushing refs one at a time to avoid interactions where one ref’s excluded boundary strips objects needed by another. The advice is gated on the existing `advice.pushShallowBoundary` config (default: enabled) and only triggers when the pack contains multiple contributing refs and the optimization was active (`push.shallowExcludeBoundary=true`).

The implementation is straightforward: `send-pack.c` now tracks whether shallow boundaries were excluded (`excluded_boundary`) and how many refs contributed to the pack (`pack_contributing_refs`). If the push fails and both conditions are met, the advice is shown. The test (`t5538-push-shallow.sh`) verifies the message appears in a scenario where two refs share a pack, one ref’s boundary exclusion omits an object needed by the other, and the push is rejected.

This patch directly responds to Stolee’s concern about usability by providing a clear recovery path for the rare false-positive case. It doesn’t change the core optimization (that’s in patch 4) or the default behavior (patch 5 proposes changing the default), but it makes the trade-off more palatable by ensuring users know how to proceed when the assumption fails. The advice is narrowly targeted—it won’t appear for single-ref pushes or when the optimization is disabled—and the test coverage ensures it works as intended. This looks like a well-considered addition to the series, closing the loop on the usability discussion.
