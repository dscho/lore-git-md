This is the first patch in Elijah Newren’s six-part v3 series optimizing `git push` performance from shallow clones. It is a preparatory bugfix for `unpack-objects` that improves error messages when objects are missing during a push with `receive.fsckObjects` enabled.

Currently, when the server expects an object that the client did not send, `unpack-objects` reports “object of unexpected type” — a misleading message that suggests corruption rather than a simple missing object. This patch aligns the diagnostics with `index-pack`: it now reports “did not receive expected object <oid>” when the object is absent, and reserves the type-mismatch message for cases where the object exists but has the wrong type. The change touches `builtin/unpack-objects.c` and updates the test in `t/t5504-fetch-receive-strict.sh` to verify the new error message.

This is a small but meaningful usability improvement that directly addresses feedback from the v2 review: clearer error messages make it easier for users to diagnose incomplete pushes, which is especially important for the later patches in the series that introduce new failure modes. The patch is well-motivated, narrowly scoped, and unlikely to be controversial. It looks like a solid foundation for the rest of the series.
