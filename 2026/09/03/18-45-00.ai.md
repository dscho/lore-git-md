This is the second patch in a three-patch bugfix series targeting Git's pathspec handling. It addresses a memory-safety issue in `match_pathspec_with_flags()` where negative pathspecs shorter than the common prefix derived from positive pathspecs trigger a heap-buffer-overflow. The fix is minimal: when matching negative pathspecs, the function now passes a zero prefix instead of the common prefix, preventing `match_pathspec_item()` from reading out-of-bounds memory. The patch also adds a regression test in `t/t6132-pathspec-exclude.sh` that verifies the fix by combining a positive pathspec with a longer common prefix and a shorter, unrelated negative pathspec.

The bug is well-documented in the commit message, including a reproducer that triggers the issue under AddressSanitizer. The fix itself is straightforward and aligns with the series' agreed-upon design (using an output-parameter approach for `common_prefix_len()`). The test coverage is appropriate, covering both the memory-safety issue and the edge case that motivated the series. This patch is a clear bugfix with no behavioral changes beyond fixing the overflow, and it carries minimal risk of regression.

This patch depends on the preparatory refactoring in the first patch (which declares `match` and `original` fields in `struct pathspec_item` as `const char *`), but does not depend on the third patch (which refactors `common_prefix_len()` to correctly handle exclude pathspecs appearing first). The series is now ready for merging, with no further technical changes expected. The unresolved minor detail about the output parameter type (`char **` vs. `const char **`) does not affect this patch.
