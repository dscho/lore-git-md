This is a documentation patch that clarifies a long-standing inaccuracy in the `partial-clone` technical design document. The current text claims that dynamic object fetching is slow because objects are fetched "one at a time," but this is only true for a single fallback code path—most callers batch their requests. Aleksei Sviridkin audits all eleven call sites of `promisor_remote_get_direct()`, shows that ten of them pass an array of object IDs to a single fetch subprocess, and narrows the "one at a time" limitation to the eleventh (the fallback in `odb.c`). The patch rewrites the bullet to describe the batch path where the fallback is introduced and updates the subprocess name from the outdated "fetch-pack" to the actual "git fetch" that the code forks. The commit message is exceptionally thorough, walking through the history, the call-site inventory, and even providing reproduction recipes. It also flags several pre-existing inaccuracies in the same file that are deliberately left untouched because they would require separate patches. The patch itself is clean, applies to `maint`, and passes the documentation linter. For anyone working with partial clones or promisor remotes, this is a worthwhile correction.
