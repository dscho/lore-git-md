This is a documentation patch, part 2 of Aleksei Sviridkin’s two-patch series. It updates `git-cherry-pick.adoc` to clarify that `--no-commit` deliberately skips setting `CHERRY_PICK_HEAD`, a behavior that was introduced in commit d7e5c0cbfb (2011) but never documented. The new text explains the consequence: a subsequent `git commit` will record the committer as the author unless `git commit -c <commit>` is used to restore the original authorship and log message. The patch also notes that this workaround only applies to single-commit cherry-picks, since multiple picks leave no single original author to restore.

The change is a straightforward addition to the existing bullet list describing what happens when a cherry-pick encounters conflicts, plus a short paragraph under the `--no-commit` option itself. The commit message provides sharp context: the current documentation unconditionally states that `CHERRY_PICK_HEAD` is set, which can mislead users into expecting authorship preservation that does not occur. The patch does not alter behavior—only surfaces the existing asymmetry between `--no-commit` and the default mode. It also deliberately leaves `git-revert.adoc` untouched, since `revert --no-commit` *does* write `REVERT_HEAD`, making the two commands asymmetric in this respect.
