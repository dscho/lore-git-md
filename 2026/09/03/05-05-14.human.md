This is the second patch in Michael Montalbo’s v3 series extending `git log -L` to support range-scoped diff stat, whitespace checking, and `-G` pickaxe. It is a **bugfix and refactoring** targeting the line-range filter in `diff.c`.

The patch fixes a long-standing bug where deletions just outside the tracked line range could leak into the patch output. The root cause was the filter’s two-buffer design: preimage removal lines were buffered separately and only flushed when a postimage line arrived, creating a race condition at range boundaries. The fix simplifies the logic by classifying removals immediately based on the postimage position of the following line, eliminating the separate “pending removal” buffer. This change also corrects the symmetric case—leading deletions just before the tracked range are now correctly included if the following line is in-range.

The refactoring is mechanical and conservative: it removes 74 lines of state-tracking code, replaces them with 48 lines of simpler logic, and renames a few struct fields for clarity (`old_count`/`new_count` are now calculated on flush rather than stored). The new `begin_range_hunk()` helper consolidates hunk initialization, and the line callback now processes all line types (`-`, `+`, ` `) in a single pass. Test coverage is expanded with a new `t/t4211-line-log.sh` case that verifies the trailing-deletion bug is fixed.

The patch is well-motivated, clearly explained, and touches only the line-range filter internals—no user-visible behavior changes beyond the bugfix. It is a solid stepping stone for the later feature patches in the series.
