This is a brief follow-up from Junio C Hamano in the `dk/use-nsec-runtime` thread, now cooking in `next`. The series itself is technically complete and ready to graduate, but Junio voices a forward-looking concern about the architectural constraint introduced by the new call to `repo_config_values()` in `is_racy_stat()`. That function currently only works for `the_repository`, so any future feature that operates on a submodule’s index without spawning a subprocess (e.g., recursive diff or status) could trigger a BUG() when it encounters a racy-clean entry. Junio is not asking for a reroll—he explicitly says he is not worried about the current code—but he wants the limitation documented so that future developers know they cannot safely reuse `is_racy_stat()` in a submodule context without first refactoring the config subsystem. The note is aimed at the project’s collective memory rather than the current patch author.
