This is a **documentation patch** that clarifies the limitations of Git's partial clone dynamic object fetching, specifically narrowing the scope of a misleading claim in `Documentation/technical/partial-clone.adoc`. The patch addresses feedback from Elijah Newren on the original submission, which was praised for its thoroughness but criticized for an overly verbose cover letter.

The core change updates two paragraphs to specify that the "one-at-a-time" fetch limitation applies only to the fallback path in `odb.c` (the 11th call site of `promisor_remote_get_direct()`), while the other ten call sites batch multiple objects into a single `git fetch --stdin` subprocess. The patch also corrects the subprocess name from "fetch-pack" to "git fetch" to match the implementation. These adjustments are well-justified by the author’s detailed analysis of call sites, release history, and reproduction steps, though the original cover letter’s length (over 1,000 lines) was deemed excessive by Newren.

Elijah’s review is **substantive** but brief: he confirms the commit message is acceptable (though could be shorter) and approves the actual changes as clear and accurate. His feedback focuses on the patch’s readability and relevance, not its technical correctness. The revised patch itself is small (9 insertions, 7 deletions) and applies cleanly to both `maint` and `master`. No new tests are added, as this is purely documentation.

This patch is part of a broader effort to improve accuracy in Git’s technical documentation, particularly around partial clone behavior. It is unlikely to be controversial, as it corrects a long-standing inaccuracy without altering code behavior. The author’s decision to leave adjacent inaccuracies (e.g., protocol V0 vs. V2 behavior) untouched avoids scope creep and keeps the change focused. The patch is now ready for maintainer consideration, with no open technical questions.
