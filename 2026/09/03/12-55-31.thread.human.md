This thread is about a small but important documentation fix for Git's partial clone feature. Aleksei Sviridkin posted a patch to correct a misleading claim in the technical documentation: the existing text overstated the performance limitations of dynamic object fetching, implying it always fetches objects one at a time. In reality, only one of eleven call sites (a fallback path in `odb.c`) lacks batching; the other ten batch objects efficiently.

Elijah Newren reviewed the patch and gave it a thumbs-up, though he suggested the original cover letter was overly long. The patch itself is concise and focused, changing just two paragraphs to clarify the scope of the limitation and update a subprocess name to match the implementation. It applies cleanly to both the maintenance and master branches, and there are no open technical questions or objections. The change is purely documentation—no code behavior is altered—and it avoids addressing adjacent inaccuracies to keep the scope tight. The patch is now waiting for maintainer attention.
