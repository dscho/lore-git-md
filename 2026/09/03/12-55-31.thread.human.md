This thread is about a small but important documentation fix for Git’s partial clone feature. Aleksei Sviridkin identified and corrected a long-standing inaccuracy in `Documentation/technical/partial-clone.adoc`, which had overstated the performance limitations of dynamic object fetching. The original text claimed that objects are fetched one at a time, but this was only true for one of eleven call sites—the fallback path in `odb.c`. The other ten call sites batch objects efficiently, so the documentation was misleading. The patch narrows the scope of the limitation and updates the subprocess name from "fetch-pack" to "git fetch" to match the actual implementation.

Elijah Newren reviewed the patch and gave it a **Reviewed-by**, praising its accuracy and clarity. His only feedback was that the cover letter was overly verbose, which Aleksei addressed by rewriting it to be much shorter and more focused. The patch itself is unchanged, applies cleanly to both `maint` and `master`, and has no open technical questions. It’s a straightforward, well-scoped change that improves documentation accuracy without touching code or on-disk formats.
