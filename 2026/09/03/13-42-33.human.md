This is a **maintainer clarification** in the `git imap-send --draft` thread. Junio C Hamano responds directly to Aditya Garg’s forward-compatibility concern about the libcurl 8.13.0 dependency, drawing a key distinction between the current patch and the 2024 precedent Aditya cited.

Junio points out that the rejected 2024 patch lacked any mechanism to build with older libcurl versions, whereas the current patch includes a compatibility layer (`git-curl-compat.h`) that guards the new `CURLOPT_UPLOAD_FLAGS` feature. This means the feature is effectively opt-in: users with older libcurl versions can still build and run `git imap-send`, but the `--draft` option will error out rather than silently warn. The patch’s design thus avoids the hard dependency that led to the earlier rejection, aligning with the project’s preference for graceful degradation.

The clarification does not resolve the broader question of whether the libcurl version requirement is acceptable, but it narrows the discussion to the patch’s implementation rather than its mere existence. No new objections or suggestions are raised, and the thread’s prior focus on error handling (fail-fast vs. warning) and configuration variables remains unchanged. The tone is matter-of-fact, framing the distinction as a technical detail rather than a policy shift.
