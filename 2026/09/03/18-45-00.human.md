This is the second patch in a three-part bugfix series that addresses a memory-safety issue in Git's pathspec handling. The patch prevents a heap-buffer-overflow in `match_pathspec_with_flags()` when a negative pathspec (e.g., `:(exclude)xy`) is shorter than the common prefix derived from positive pathspecs (e.g., `sub/sub/`). The bug occurs because the function incorrectly applies the common prefix to negative pathspecs, causing `match_pathspec_item()` to read out-of-bounds memory. The fix is simple and surgical: pass a zero prefix when matching negative pathspecs, ensuring they are matched against the full pathname.

The patch includes a clear regression test that reproduces the issue with `git ls-files -- sub/sub/ ":(exclude)sub2"`, demonstrating the heap-buffer-overflow under AddressSanitizer. The test verifies that the fix works and that the output matches expectations. The commit message is well-written, explaining the bug's cause, its consequences (including potential memory corruption), and the reproduction steps. The fix itself is minimal and targeted, touching only one line in `dir.c` and adding the test.

This patch is part of a larger series that also fixes a related edge case in `common_prefix_len()` (where an exclude pathspec appearing first in the list incorrectly returns zero as the common prefix length).
