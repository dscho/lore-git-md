This is a bugfix patch for the `git history` command. It prevents a NULL-dereference crash when the parent commit's tree object is missing from the repository (e.g., due to corruption, tooling removal, or incomplete restore).

The patch adds a simple NULL check after `repo_parse_tree_indirect()` in `write_ondisk_index()`. If the tree cannot be parsed, it errors out gracefully with a message following Git's conventions for unloadable objects. The fix is minimal—just four lines in `builtin/history.c`—and matches the codebase's existing error-handling patterns.
