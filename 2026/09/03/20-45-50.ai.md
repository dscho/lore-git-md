This is the final version of the `--missing-only` feature for `git rev-list`, now approved and ready for integration. The patch itself is unchanged from v2; only the commit message has been strengthened to clarify the workflow motivation.

The update addresses Junio’s request for a clearer explanation of how GitLab’s Gitaly uses the missing-object list: it’s a **one-shot walk** during transaction packing, not a fetch loop. The `?` prefix is stripped by callers (Gitaly and tests) to identify objects that must already exist in the main repository; `--missing-only` simply omits the prefix entirely, making the output script-friendly without requiring post-processing.

Key technical details remain as in v2: the new `--missing-only` flag filters output to show only missing objects, requires `--missing=print` or `--missing=print-info`, and rejects incompatible options (`--count`, `--disk-usage`).
