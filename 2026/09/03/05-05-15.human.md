This is the third patch in Michael Montalbo’s v3 series extending `git log -L` to support range-scoped diff stat, whitespace checking, and `-G` pickaxe. The patch fixes an off-by-one inconsistency in hunk headers emitted by the line-range filter.

The line-range filter (`git log -L`) previously implemented its own hunk-header formatting, which differed from xdiff’s native output when one side of the diff had zero lines. For example, a pure insertion would show `@@ -24,0 +24,1 @@` in a normal diff but `@@ -23,0 +24,1 @@` in the line-range filter. This patch removes the custom formatting and exposes xdiff’s own `xdl_emit_hunk_hdr()` via a new helper, `xdiff_emit_hunk_header()`, ensuring consistent headers across all diff output.

The change touches `diff.c` and adds the helper to `xdiff-interface.c`/`xdiff-interface.h`. Test fixtures in `t/t4211-line-log.sh` are updated to match the corrected headers. The patch is a targeted refactoring with no behavior change beyond the header format; it prepares the ground for later patches that route line-filtered output through standard diff consumers like `diffstat_consume()` and `checkdiff_consume()`.

The commit message is clear and the implementation is straightforward. No new technical feedback has appeared since v2, and the series remains under review. This patch is a sensible cleanup that eliminates a minor but visible inconsistency.
