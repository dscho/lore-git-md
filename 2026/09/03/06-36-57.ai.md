This is a bugfix patch for the `git history` command, part of the ongoing `git history` effort (a new built-in command introduced in Git 2.46). The patch prevents a NULL-dereference crash in `write_ondisk_index()` when the parent commit's tree object is missing from the object store. The fix adds a guard to check the return value of `repo_parse_tree_indirect()` and error out gracefully with a descriptive message, following Git's established pattern for handling missing objects.

The crash scenario occurs in corrupt repositories, after objects are removed by tooling, or during incomplete restores. The patch touches only `builtin/history.c` and is a minimal, targeted fix with no behavior changes beyond avoiding the segfault. The commit message is clear and concise, and the code follows Git's conventions for error handling.

This is the second iteration of the patch (v2), with no functional changes from v1—only the commit message was tweaked to remove a parenthetical note about UBSan diagnostics, as suggested in review. The patch is well-motivated and addresses a real edge case in the new `git history` command. It looks ready for integration and is unlikely to be controversial.
