This is a documentation patch that clarifies the limitations of Git's partial clone dynamic object fetching. The patch narrows the scope of a long-standing claim in `Documentation/technical/partial-clone.adoc` that "dynamic object fetching invokes fetch-pack once for each item" and "tends to be slow because objects are fetched one at a time." The author demonstrates that this description applies only to the fallback path in `odb.c` (which fetches one object at a time) and not to the ten other call sites of `promisor_remote_get_direct()`, which batch multiple objects into a single `git fetch --stdin` subprocess.

The patch rewrites the relevant bullet point to specify that the one-at-a-time limitation applies only to the fallback path, describes the batching mechanism where the fallback is introduced, and updates the subprocess name from "fetch-pack" to "git fetch" to match the actual implementation. The commit message is exceptionally thorough, citing specific call sites, release versions, and reproduction steps to justify the change. It also notes several pre-existing inaccuracies in the document (e.g., protocol V0 vs. V2 behavior) that are deliberately left untouched to avoid scope creep.

The patch is well-researched and targets a real source of confusion in the partial clone design doc. It applies cleanly to both `maint` and `master` and passes basic checks (`git show --check`, `lint-docs`). The author’s decision to limit the change to the fallback path while leaving adjacent inaccuracies for future patches is pragmatic and avoids introducing new contradictions. This is a clear improvement to the documentation and unlikely to be controversial.
