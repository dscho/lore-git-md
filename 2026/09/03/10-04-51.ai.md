This is the second patch in Yannik Tausch’s v2 two-patch bugfix series for pathspec handling in `dir.c`. It implements Junio C Hamano’s output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`) to fix the edge case where an exclude pathspec appearing first in the list causes `common_prefix_len()` to incorrectly return zero, even when subsequent positive pathspecs share a directory. The patch refactors the function to track the first *non-exclude* pathspec item explicitly, returning its match through the output parameter so that `common_prefix()` and `fill_directory()` use the correct string. A new unit test in `t/unit-tests/u-dir.c` verifies the fix with an unrelated exclude item followed by two non-exclude items that share a directory (`foo/`).

The implementation is clean and minimal: it touches only `dir.c` and the unit-test file, avoids introducing new symbols, and preserves the existing API. The commit message clearly explains the bug and the fix, and the test coverage is thorough. The patch is narrowly scoped to the pathspec subsystem and carries no risk of broader regression. Discussion with Junio has settled the design approach, and the remaining open question (whether to use `char **` or `const char **` for the output parameter) is a minor detail that does not affect correctness. The series is now effectively ready for merging, pending final review.
