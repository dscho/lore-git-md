This is a clarification in response to Junio’s "What’s cooking" report. Yoichi Nakayama points out that the description Junio attached to the `yn/worktree-ambiguous-remote-advice` topic is incorrect: it actually describes a different, already-merged series (`yn/worktree-add-no-dwim-with-b`), not the one Junio listed.

The `yn/worktree-ambiguous-remote-advice` series (four patches) improves error messages and advice when `git worktree add` or `git checkout` encounters an ambiguous remote branch name. It treats multiple matches with `--guess-remote` as an error, makes the advice text clearer, and extracts the advice logic into a reusable function. The series is already in `next` and was slated for `master`, but the commit message in the report mistakenly described the unrelated `yn/worktree-add-no-dwim-with-b` series, which prevents DWIM behavior when `-b` or `-B` is given.

No code changes are proposed here; this is purely a metadata correction. The patch itself looks uncontroversial and well-scoped, but the mislabeling could have caused confusion for anyone scanning the report.
