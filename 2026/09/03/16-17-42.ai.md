This is a platform-compatibility bugfix for Git GUI, specifically targeting Windows. The patch addresses a long-standing issue where `git-gui` fails to commit when amending a commit with a long message (roughly 9 KiB or larger) on Windows, while the same operation succeeds on Linux.

The root cause is a pipe-handling difference between platforms: `commit_committree` in `lib/commit.tcl` opens a pipe to `git cat-file commit <parent>` to read the tree line for an empty-commit check, but only reads the first line before closing the pipe. On Linux, the child process dies silently from SIGPIPE when it continues writing, but on Windows, the broken pipe causes `git.exe` to exit with a non-zero status, which Tcl surfaces as "child process exited abnormally," aborting the commit.

The fix is simple and surgical: add a `read $fd_ot` call to drain the pipe before closing it, mirroring what the amend path already does when loading the parent commit's message. The change is contained to a single file (`lib/commit.tcl`) and adds only four lines of code. The commit message is thorough, explaining the platform-specific behavior, the failure threshold, and the harmlessness of the fix on POSIX systems.

This is a clear case of a cross-platform bug that only manifests under specific conditions (long commit messages on Windows), and the fix is minimal and well-justified. The patch is likely to be uncontroversial and should be a straightforward merge. It does not touch core Git code, only the Tcl-based GUI component maintained by Johannes Sixt (Hannes).
