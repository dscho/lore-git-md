This is a bugfix for `git pack-objects` in partial clones. The patch corrects a subtle ordering bug in the prefetch logic that causes missing objects to be fetched one at a time rather than in a single batch when loose objects are present locally.

The issue stems from a mismatch between two arrays: `get_object_details()` sorts objects by pack and offset, but `prefetch_to_pack()` incorrectly treats the sorted index as if it were the original traversal order. When loose objects sort ahead of missing ones, the prefetch batch starts too late and misses the missing objects entirely. The fix adds an explicit pointer to the sorted array so the batch covers the correct objects.

The commit message is exceptionally clear, walking through the problem, the fix, and the alternatives considered. It includes synthetic benchmark results showing the improvement: a case that previously required eight separate fetches now completes in one. A new test in `t/t5300-pack-object.sh` verifies the fix under both SHA-1 and SHA-256.

The patch itself is small (13 lines changed) and focused, touching only the prefetch logic in `builtin/pack-objects.c` and adding a test. The author, Aleksei Sviridkin, has done a thorough job documenting edge cases and explaining why nearby code was left untouched. This looks like a well-crafted, low-risk fix for a real performance regression in partial clones.
