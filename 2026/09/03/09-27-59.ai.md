This is the second patch in the v6 series introducing the `receive-report` hook. It refactors the static variables `report_status` and `report_status_v2` into a new `enum report_status_version`, making the protocol-version tracking more explicit and easier to extend. The change is a direct response to Junio C Hamano’s feedback about maintainability and replaces the boolean flags with an enum that clearly distinguishes between unknown, v0, and v2 status reporting.

The patch touches only `builtin/receive-pack.c`, replacing the two static variables with a single `enum report_status_version` that is passed through the call chain. The logic remains functionally identical—clients still receive the same status reports—but the code is now more readable and less prone to accidental misuse of the flags. The enum also includes a `REPORT_STATUS_UNKNOWN` sentinel value, which triggers a `BUG()` if neither v0 nor v2 is set, adding a safety check that was missing before.

This is a pure refactoring patch with no behavior change, so it carries no risk of regressions. The enum-based approach is a clear improvement over the previous boolean flags, aligning with Git’s coding style and making future protocol extensions easier. The patch is uncontroversial and ready for integration.
