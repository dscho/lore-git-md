This is patch 3/7 in Michael Montalbo’s v3 resend of the line-log series, targeting the diff subsystem. The patch addresses a long-standing inconsistency in hunk header formatting between `git log -L` (line-range filter) and the standard `git diff` output.

The core issue is that the line-range filter’s custom hunk header logic does not match xdiff’s native behavior for edge cases where one side of the diff has zero lines. For example, a pure insertion (`@@ -5,0 +6,3 @@`) or deletion (`@@ -5,3 +5,0 @@`) would previously emit slightly different headers under `-L` than in a regular diff. The patch resolves this by exposing xdiff’s internal `xdl_emit_hunk_hdr()` function through a new helper, `xdiff_emit_hunk_header()`, and routing all hunk header output through it. This ensures that `-L` headers now match `git diff` exactly, including the off-by-one correction for zero-line sides (the begin line is now the line *before* the change, and a count of 1 is omitted).

The change touches `diff.c` (replacing the custom header formatting with the new helper) and adds the helper to `xdiff-interface.c`/`xdiff-interface.h`. Test fixtures in `t/t4211-line-log.sh` are updated to reflect the corrected headers, with adjustments to expected output for edge cases like pure insertions (`no-assertion-error`) and deletions (`vanishes-early`). The patch is a refactoring with no behavior change for most cases, but it fixes subtle discrepancies that could confuse users or tools parsing diff output.

The implementation is straightforward: the new `xdiff_emit_hunk_header()` wraps xdiff’s emitter with a `strbuf`-compatible callback, and the line-range filter’s `flush_range_hunk()` now delegates to it. The patch also updates the hunk callback to handle zero-line counts correctly, ensuring the `lno_in_postimage`/`lno_in_preimage` fields are set to the line before the change when no lines are present. This aligns with xdiff’s own logic and resolves the off-by-one in the test fixtures.

No new technical feedback or objections have surfaced since v2, and the patch is part of a series that has already seen review from Junio on other parts. The change is uncontroversial and improves consistency without introducing new complexity.
