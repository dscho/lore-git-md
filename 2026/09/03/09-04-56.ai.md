This is a two-patch series from Patrick Steinhardt targeting the `git maintenance` builtin and the `rerere` subsystem. The goal is to improve the heuristic used by `git maintenance` when running the `rerere gc` task.

The series starts by extracting the logic that determines whether `rerere` entries are stale into a reusable function in `rerere.c`. The second patch then modifies `builtin/gc.c` to use this new function, replacing the existing hard-coded 60-day cutoff with a more dynamic heuristic that considers both the last access time and the number of entries. The commit message for the second patch explains that the new heuristic avoids deleting recently accessed entries even if they are numerous, while still allowing older entries to be pruned regardless of count.

The changes touch `rerere.c`, `rerere.h`, `builtin/gc.c`, and the maintenance configuration documentation. The test file `t/t7900-maintenance.sh` is updated to cover the new behavior, including edge cases where the number of entries or their age triggers pruning.

This is a refactoring with a behavioral change: the `rerere gc` task will now make more nuanced decisions about which entries to prune. The motivation comes from a previously reported issue (linked as GitGitGadget PR 2214), though the exact problem isn't detailed in the cover letter. The series appears well-structured, with the first patch isolating the logic and the second applying it, and includes test coverage for the new behavior.
