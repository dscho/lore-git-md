This is a platform-compatibility bugfix for Git GUI, specifically targeting Windows.

The patch addresses a long-standing but intermittent failure in `git-gui` when amending commits with long messages. The root cause is a pipe-handling quirk: `commit_committree` reads only the first line of a `git cat-file commit` output (to extract the tree line) and then closes the pipe while the rest of the commit object remains unread. On Linux, this is harmless because the child process dies silently from SIGPIPE. On Windows, however, the child process exits with a non-zero status, causing Tcl’s `close` to report "child process exited abnormally" and abort the commit.

The fix is minimal and surgical: it adds a `read $fd_ot` call to drain the pipe before closing it, mirroring what the amend path already does when loading the parent commit’s message. The change is contained to a single file (`lib/commit.tcl`) and adds only four lines. Testing on Git for Windows 2.52 confirms the fix works reliably for large commits (9 KiB and up) while remaining harmless on POSIX platforms. The patch is well-motivated and clearly explains both the problem and the solution.
