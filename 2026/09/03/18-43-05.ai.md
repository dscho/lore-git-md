This is the v3 cover letter for a three-patch bugfix series targeting Git's pathspec handling. The series fixes a long-standing edge case in `common_prefix_len()` where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes the function to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs share a directory. It also addresses a memory-safety issue in `match_pathspec_with_flags()` where negative pathspecs shorter than the common prefix derived from positive pathspecs trigger a heap-buffer-overflow.

The series now includes Junio C Hamano's preparatory refactoring patch, which declares the `match` and `original` fields in `struct pathspec_item` as `const char *` to reflect their immutability and resolve a compiler warning in the unit test. The two core patches remain unchanged from v2: the first ensures exclude pathspecs are matched against the full pathname (not the common prefix), and the second refactors `common_prefix_len()` to correctly derive the common prefix from the first *non-exclude* pathspec item. The output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`) is unchanged and remains the agreed-upon solution.

Files touched include `dir.c`, `pathspec.c`, `pathspec.h`, and test files `t/t6132-pathspec-exclude.sh` (functional test) and `t/unit-tests/u-dir.c` (unit test). The series is narrowly scoped to pathspec handling and directory traversal, with no broader subsystem changes. Test coverage is thorough, addressing both the memory-safety issue and the common prefix edge case.
