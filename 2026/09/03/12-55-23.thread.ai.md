Core problem or goal
Document and test the edge case in `git cherry-pick --no-commit` where `CHERRY_PICK_HEAD` is *not* created when the operation fails due to conflicts, contrasting with `git revert --no-commit` (which *does* write `REVERT_HEAD`). The goal is to clarify this asymmetry for users and ensure the behavior is explicitly covered by tests, as the current implementation (introduced in 2011) was never documented.

Current status
Under review; v1 posted. Junio’s reply to the test patch (part 1) revealed a misunderstanding about the intended behavior, elevating the importance of the documentation patch (part 2) as a defense of the existing design. No prior versions.
