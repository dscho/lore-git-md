Core problem or goal
Add test coverage and documentation for an edge case in `git cherry-pick --no-commit`: when the operation fails due to conflicts, `CHERRY_PICK_HEAD` is *not* created, which can affect subsequent `git commit` behavior (e.g., authorship preservation). The goal is to document this asymmetry between `--no-commit` and the default cherry-pick mode, as well as the asymmetry with `git revert --no-commit` (which *does* write `REVERT_HEAD`).
