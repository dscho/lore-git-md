This is a bugfix series targeting Git's pathspec handling in directory traversal, now in its third iteration. The series fixes a long-standing edge case where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes `common_prefix_len()` to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs (e.g., `foo/bar` and `foo/baz`) share a directory (`foo/`). It also addresses a memory-safety issue where negative pathspecs shorter than the common prefix derived from positive pathspecs trigger a heap-buffer-overflow.

The series now consists of three patches. The first, authored by Junio C Hamano, is a preparatory refactoring that declares the `match` and `original` fields in `struct pathspec_item` as `const char *`, resolving a compiler warning in the unit test. The second patch ensures exclude pathspecs are matched against the full pathname (not the common prefix), preventing out-of-bounds reads. The third patch refactors `common_prefix_len()` to correctly derive the common prefix from the first *non-exclude* pathspec item, fixing the core bug. The output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`) remains unchanged and is the agreed-upon solution.

Files touched include `dir.c`, `pathspec.c`, `pathspec.h`, and test files `t/t6132-pathspec-exclude.sh` (functional test) and `t/unit-tests/u-dir.c` (unit test). The series is narrowly scoped to pathspec handling and directory traversal, with no broader subsystem changes. Test coverage is thorough, addressing both the memory-safety issue and the common prefix edge case. The commit messages clearly explain the bugs and fixes, and the patches are well-motivated.

The series is ready for merging. The only unresolved detail—whether to use `char **` or `const char **` for the output parameter in `common_prefix_len()`—does not affect correctness and is not a blocker. Junio's preparatory patch has been integrated, and the core fixes remain unchanged from v2. No further technical changes are expected. This looks like a clean, well-tested fix for a real (if niche) bug.
