This is a test patch, part 1 of a 2-patch series. It adds a missing test case in `t3507-cherry-pick-conflict.sh` to verify that `CHERRY_PICK_HEAD` is *not* set when a `git cherry-pick --no-commit` operation fails due to conflicts. The commit message explains that the gap was discovered when a user encountered the issue by accident: a conflicting cherry-pick with `--no-commit` left no `CHERRY_PICK_HEAD` ref, which could affect subsequent `git commit` behavior.

The patch itself is small and focused: it adds a single 6-line test case that detaches HEAD, attempts a conflicting cherry-pick with `--no-commit`, and checks that `CHERRY_PICK_HEAD` does not exist. The test follows the same pattern as the existing tests for clean cherry-picks and conflicting cherry-picks without `--no-commit`.

The motivation is clear and practical: the absence of `CHERRY_PICK_HEAD` in this scenario is not currently guarded by any other test, so this patch plugs that hole. The commit message does not speculate about whether the current behavior is correct, only that it should be explicitly tested. The patch is well-scoped and appears to be a straightforward addition to the test suite.
