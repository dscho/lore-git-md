This is a bugfix patch series targeting Git's pathspec handling and directory traversal logic. The series, now in its second iteration (v2), addresses a long-standing edge case where an exclude pathspec (e.g., `:!unrelated/path`) appearing first in the list causes `common_prefix_len()` to incorrectly return zero as the common prefix length, even when subsequent positive pathspecs (e.g., `foo/bar` and `foo/baz`) share a directory (`foo/`).

The series consists of two patches. The first patch ensures exclude pathspecs are matched against the full pathname rather than a potentially incorrect prefix. The second patch fixes the core issue by modifying `common_prefix_len()` to start its comparison with the first *non-exclude* pathspec item, returning both the prefix length and the matched string via an output parameter. This approach avoids introducing a new struct and minimizes caller churn, aligning with Junio C Hamano's feedback on v1.

The implementation touches `dir.c` and adds test coverage in both the traditional test suite (`t/t6132-pathspec-exclude.sh`) and the unit test framework (`t/unit-tests/u-dir.c`).
