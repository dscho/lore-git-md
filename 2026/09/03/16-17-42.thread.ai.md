Subject: [PATCH] git-gui: fix commit with long messages on Windows
Series version: standalone patch
Originating author: chib via GitGitGadget
Thread type: bugfix for a platform-specific component (Git GUI)

Core problem or goal
Git GUI fails to commit when amending a commit with a long message (≈9 KiB or larger) on Windows, while the same operation succeeds on Linux. The failure is caused by a pipe-handling difference: on Windows, a broken pipe causes `git.exe` to exit with a non-zero status, which Tcl surfaces as an error, whereas on Linux the child process dies silently from SIGPIPE.

Current status
Under review. The patch remains a minimal, surgical fix confined to `lib/commit.tcl` (Git GUI's Tcl code), adding four lines to drain the pipe before closing it. No prior versions exist; this is the initial submission. The patch is **not yet ready for merging** due to a **reproducibility gap**: Johannes Sixt (Git GUI maintainer) reports being unable to reproduce the failure on his Windows setup (custom build, not Git for Windows) and questions whether the fix is necessary.

Key technical details
- File touched: `lib/commit.tcl` (Git GUI component)
- Function modified: `commit_committree`
- New behavior: explicit pipe drain (`read $fd_ot`) before closing the pipe to `git cat-file commit <parent>`
- Old behavior: pipe closed after reading only the first line, risking broken-pipe errors on Windows
- Alternative suggested: wrap the pipe close in a `catch` block to suppress errors
- On-disk format: unchanged
- Test coverage: none; the bug is platform-specific and requires manual reproduction on Windows
