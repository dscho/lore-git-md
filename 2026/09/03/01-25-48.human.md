This is Junio’s "What’s cooking" report for early September 2026, summarizing the state of the Git integration branches. The report lists 604 non-merge commits in `master` since Git 2.55, with 49 topics cooking in `next` and 213 in `seen`.

### Graduated to `master`

Two small but useful patches graduated: a typo fix in the rerere technical documentation (`jc/rerere-doc-typofix`) and a libification step that moves the global `fetch_if_missing` variable into `struct repository` (`ty/repository-fetch-if-missing`), continuing the effort to make Git’s internals more modular and submodule-aware.

### New topics likely to land soon

Several patches look ready for `next` and are likely to graduate in the next cycle:

- **Memory safety in revision parsing** (`jk/rev-info-argv-to-free`): The revision machinery now keeps "freed" argv elements alive until the `rev_info` struct is released, preventing use-after-free bugs when options store references to them. Jeff King’s patch is concise and addresses a real edge case; the discussion confirms the fix is robust.
- **CI fixes** (`ps/ci-depends-on-ruby` and `jk/ci-use-system-asciidoctor`): Two independent fixes for the CI "documentation" job, which broke because the `asciidoc` package no longer pulls in Ruby as a dependency. Both patches install Ruby explicitly; Junio seems inclined to take the simpler one (`jk/ci-use-system-asciidoctor`), which also drops an obsolete Azure Pipelines variable.
- **Submodule memory leaks** (`jk/submodule-error-leak`): A small fix that plugs a leak in `submodule--helper` when repository setup fails, leveraging an idempotent `repo_clear()`.
- **Worktree and checkout improvements** (`rs/worktree-add-basename-fixes` and `yn/worktree-repair-relative`): The former fixes out-of-bounds reads and improper slash handling in `git worktree add`; the latter corrects `git worktree repair`’s handling of relative paths in `.git` files. Both are small, well-scoped, and have received positive feedback.
- **Zsh completion** (`ll/zsh-complete-git-potty-options`): The zsh completion script now correctly skips global options like `-C <path>` when locating the Git command, matching bash completion behavior. This is a quality-of-life fix for zsh users.
- **IMAP draft flag** (`wf/imap-send-draft`): `git imap-send` now supports a `--draft` option to mark uploaded messages as drafts, helping email clients render them properly for editing.

### Larger efforts needing review

Two substantial series from Patrick Steinhardt are in flight:

- **Removing in-memory alternate registration** (`ps/odb-stop-registering-in-memory-sources`): This 13-patch series removes the mechanism for registering in-memory alternate object sources, as submodule object databases are now accessed natively via their own repository structures. The series simplifies object database management and prepares for migrating alternate tracking into the files backend. It builds on the graduated `ty/repository-fetch-if-missing` patch and looks like a natural next step in the ODB abstraction effort.
- **Pluggable fsck checks** (`ps/odb-pluggable-fsck`): This 10-patch series moves fsck consistency checks into the backend-specific object source layers, making them pluggable for different storage formats. The series is part of the broader ODB abstraction work and has received some feedback from Elijah Newren, but needs broader review.

### Controversial or stalled topics

- **`sa/rev-list-missing-only`**: This patch adds a `--missing-only` option to `git rev-list` to filter output to only show missing objects. The discussion suggests the implementation may need a reroll to handle edge cases better.
- **`cc/early-scan-options`**: A 6-patch series unifying early option scanning in commands like `git bisect` and `git rev-parse`. Junio raised questions about the API design, and the author has not yet responded.
- **`tb/pack-with-duplicates`**: A 5-patch series hardening the handling of packfiles with duplicate object entries. The discussion suggests the series may be too invasive for the problem it solves, and it has been marked for discard if no further activity occurs.
- **`ps/libgit-in-subdir`**: A stalled effort to move `libgit.a` sources into a separate `lib/` directory. The series causes too many merge conflicts with other topics and has been ejected for now.

### Notable ongoing efforts

- **`en/no-amend-during-conflicts`**: A 5-patch series teaching `git commit --amend` and partial commits to refuse to run during conflict resolution, just like `git cherry-pick` and `git merge` already do. The series is well-motivated and has received positive feedback; a reroll (v4) addresses earlier concerns.
- **`hn/history-squash`**: An 8-patch series adding a `git history squash` subcommand to fold a range of commits into a single commit. The series is experimental but looks like a useful addition to the `git history` command, which is shaping up as a more user-friendly alternative to `git rebase -i`.
- **`mm/diff-process-hunks`**: An ambitious 11-patch series introducing a `diff.<driver>.process` configuration to allow external tools to act as hunk providers. The series is part of a larger effort to make Git’s diff machinery more extensible, but needs a reroll to address feedback.

### Summary

The report shows a healthy mix of small fixes, CI improvements, and larger architectural efforts. The ODB abstraction work (`ps/odb-*`) and the `git history` command (`hn/history-*`) are the most significant ongoing efforts. Junio’s tone suggests he is ready to merge several of the smaller topics in the next cycle, while the larger series will need more review and iteration.
