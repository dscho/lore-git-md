This is the third patch in Karthik Nayak’s four-patch v6 series introducing the `receive-report` hook for `git-receive-pack`. It refactors the existing status-report generation logic into a reusable `generate_report()` helper function, preparing the codebase for the upcoming hook implementation in the next patch.

The patch extracts the nearly identical logic from `report()` and `report_v2()` into a shared function that takes an `enum report_status_version` parameter to control whether to include detailed per-ref reports (v2 protocol) or just the basic status (v0). This refactoring is a direct response to Junio C Hamano’s earlier feedback about maintainability: the previous version used a boolean `detailed_reports` parameter, which the maintainer found less explicit than an enum. The new `enum` (introduced in patch 2/4) includes a `REPORT_STATUS_UNKNOWN` sentinel value that triggers a `BUG()` if neither v0 nor v2 is set, adding a safety check that was missing before.

The change is purely internal and does not alter behavior. The diff shows the extracted logic moving into `generate_report()`, while the original `report()` and `report_v2()` functions become thin wrappers that call the helper with the appropriate enum value. The patch touches only `builtin/receive-pack.c` and is well-motivated by the need to reuse the report-generation logic in the upcoming hook implementation. Test coverage is provided by the existing test suite and the new `t/t5412-receive-report-hook.sh` script in patch 4/4.

This refactoring is uncontroversial and addresses all prior feedback. The patch is part of a series that is queued in `seen` and ready for integration into `next`.
