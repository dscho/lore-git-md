This is the first patch in a two-part bugfix series targeting a subtle but serious bug in Git's pathspec handling. The issue occurs when an exclude pathspec (e.g., `:!unrelated/path`) appears first in the list and is shorter than the common prefix of subsequent positive pathspecs. In this case, `match_pathspec_with_flags()` incorrectly applies the common prefix to the exclude pathspec, causing it to read beyond the allocated memory and potentially dereference an out-of-bounds pointer. The bug can trigger a heap buffer overflow, as demonstrated by the included AddressSanitizer reproduction case.

The fix itself is minimal: a one-line change in `dir.c` that ensures exclude pathspecs are matched with a zero prefix, preventing the out-of-bounds access. The patch also adds a regression test in `t/t6132-pathspec-exclude.sh` that verifies the fix works when a positive pathspec with a long common prefix (e.g., `sub/sub/`) is combined with a shorter, unrelated exclude pathspec (e.g., `:!sub2`). The test is straightforward and clearly demonstrates the edge case.

This patch is a prerequisite for the second patch in the series, which refactors `common_prefix_len()` to correctly derive the common prefix from the first *non-exclude* pathspec. The series as a whole is well-motivated and addresses a real bug with clear security implications. The commit message is detailed and includes both a technical explanation and a reproduction case, making it easy for reviewers to understand the problem and verify the fix.
