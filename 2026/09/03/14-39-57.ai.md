This is the first patch in a two-patch series (v5) that refines `git stash` exit status conventions, now queued for merging to `next`. The patch reserves exit status 1 exclusively for conflicts during stash application, aligning with Git’s established convention (e.g., `git merge-tree`), while using other non-zero values (notably 128) for errors. This resolves the long-standing ambiguity where `git stash apply`, `pop`, and `branch` previously returned 1 for both conflicts and failures, making it impossible for callers to distinguish between them.

The core change introduces a new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) in `stash.h`, replacing the `int` return type of `do_apply_stash()` and related autostash helpers in `sequencer.c` and `builtin/stash.c`. The patch updates `cmd_stash()` to map negative return values to 128 (the status `die()` uses) and pass through positive values, ensuring exit status 1 unambiguously signals conflicts. Documentation in `git-stash.adoc` is updated to reflect the new convention, and tests in `t/t3903-stash.sh` validate the behavior for all three return states, including edge cases like `stash branch` with invalid refs.

Key symbols introduced or modified include `do_stash_apply()` (a new helper function for `run_command()` enum handling), `enum stash_apply_result`, and the updated return types of `apply_save_autostash_oid()`, `apply_save_autostash_ref()`, and their callers. The patch also removes redundant error handling logic and improves code clarity by addressing nested ternaries and indentation issues. All prior review feedback—including Phillip Wood’s advocacy for the enum return type and Junio’s correctness concerns about conflict detection—has been addressed, and the series is uncontroversial and ready for integration. The second patch in the series (not shown here) focuses on advice formatting for `git checkout -m`.
