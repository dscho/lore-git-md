This thread is about a Windows-specific bug in Git GUI where amending a commit with a long message (around 9 KiB or larger) fails due to a pipe-handling difference between Windows and Linux. The author, chib, submitted a minimal fix in `lib/commit.tcl` that drains the pipe before closing it, preventing broken-pipe errors on Windows while remaining harmless on POSIX systems.

The patch itself is uncontroversial, but Git GUI maintainer Johannes Sixt has raised a reproducibility concern: he cannot reproduce the failure on his Windows setup (a custom build, not Git for Windows). He questions whether the fix is necessary, suggests an alternative `catch`-based workaround, and requests the author use their full name for the sign-off. Until the bug can be reliably reproduced—likely requiring the author to provide exact steps, such as commit message size or Git for Windows version—the patch is not ready for merging. No other reviews have been posted yet. The fix is confined to Git GUI and poses no risk to core Git functionality.
