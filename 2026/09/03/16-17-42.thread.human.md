This thread is about a platform-specific bugfix for Git GUI on Windows. Chib has identified and fixed a long-standing issue where `git-gui` fails when amending commits with long messages (around 9 KiB or larger) on Windows, while the same operation works fine on Linux. The problem stems from a pipe-handling difference between platforms: on Windows, a broken pipe causes `git.exe` to exit with an error, aborting the commit, whereas Linux handles it silently.

The fix is minimal and targeted, adding just four lines to `lib/commit.tcl` to drain the pipe before closing it, mirroring existing behavior in the amend path. The change is well-explained in the commit message and is confined to the Tcl-based GUI component, which is maintained by Johannes Sixt (Hannes). Given the narrow scope and clear justification, this patch is likely to be uncontroversial and should merge smoothly. No objections or alternative approaches have been raised yet.
