This is a bugfix patch addressing a buffer overflow in Git’s pathspec-matching logic. The author, Yannik Tausch (a first-time contributor), has sent a **v2** of the patch after the initial submission. The issue occurs when a negative pathspec (marked with `PATHSPEC_EXCLUDE`) is shorter than the common prefix derived from positive pathspecs, causing `match_pathspec_item()` to read out-of-bounds memory and potentially crash.

The fix itself is simple and targeted: it ensures negative pathspecs are matched with a zero prefix, preventing the function from advancing beyond the allocated buffer. The v2 patch includes a regression test that reproduces the issue using `git ls-files` with a long positive pathspec and a short negative pathspec, verifying the crash no longer occurs. The commit message is clear, explaining the problem, the fix, and how to reproduce it with AddressSanitizer.

This is a **standalone patch** (not part of a series) and appears to be well-crafted. The issue is real and affects common commands like `git ls-files`, `git add`, and `git grep` when using pathspec exclusions. The patch looks ready for further review and should be uncontroversial. If you care about pathspec handling or memory safety, this is worth a look.
