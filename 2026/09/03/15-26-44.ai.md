This is a bug report identifying a memory leak in the `git history reword` command. The leak surfaces when running the command under AddressSanitizer (ASan) and appears to have been introduced by the merge of `ps/receive-pack-shallow-optim` (commit `13763ecf`, 2026-03-02). The reporter, Kristoffer Haugsbakk, bisected the issue to this merge commit and confirmed the leak is present in `master`, `next`, and `seen` branches as of 2026-09-02.

The leak occurs in the object database (ODB) layer, specifically in `unpack_compressed_entry()` in `packfile.c`, where 283 bytes are leaked during a `git history reword --dry-run` operation. The stack trace shows the leak originates from `repo_get_commit_buffer()` -> `odb_read_object()` -> `packfile_store_read_object_info()`, suggesting the issue is triggered when Git reads and decodes commit objects. The reporter notes the leak does not occur on the commit that introduced `git history reword` (`d205234c`), implying the regression was introduced later in the ODB or packfile subsystem.

Kristoffer attempted to reproduce the issue in a minimal test but found it requires a "real repo" with packfiles and/or a commit graph, indicating the leak is tied to specific repository conditions. The bisect script and log are provided, showing the regression was narrowed down to the merge of Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch, though the exact culprit within that merge is not pinpointed. The leak is consistent and reproducible in the reporter’s environment, suggesting it is not a flaky or platform-specific issue.

This report is well-documented, with clear reproduction steps, a bisect log, and a stack trace, making it actionable for a developer familiar with the ODB or packfile code. The leak is likely a missing `free()` in the object unpacking path, possibly related to changes in how shallow commits or packfile entries are handled. The fact that it affects `git history reword`—a command that reads and rewrites commits—aligns with the stack trace pointing to commit buffer handling. No fixes or patches are proposed in this email; it is purely a bug report.
