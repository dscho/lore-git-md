This is a refactoring patch in Junio’s eight-part series to libify reusable logic from `git checkout`, `git switch`, and `git restore`. The series aims to eliminate the monolithic `checkout_main()` helper and extract standalone utility functions that accept a `struct repository *` parameter, aligning with the ongoing `the_repository` removal effort.

The third patch moves the validation of `--ours`, `--theirs`, `--force`, and `--merge` option compatibility from `checkout_main()` into `checkout_paths()`. Karthik Nayak’s review identified a correctness issue: the original code gated the check on `opts->pathspec.nr`, but the new version runs it unconditionally when `checkout_paths()` is called—including for `--patch` mode without pathspecs. Junio confirms this change is safe because `--patch` mode already rejects incompatible options earlier in the function, and the commit message will be updated to document the reasoning. The discussion also reveals a minor behavioral change: error message precedence now differs between `--patch` and non-`--patch` modes, but this is deemed acceptable.

Karthik’s feedback is substantive, focusing on the guard condition change and its implications, though the patch itself is now technically sound. His follow-up here is brief but endorses the series’ overall value, arguing it leaves the codebase in a better state even if the refactoring doesn’t fully enable programmatic reuse. Junio remains skeptical about the effort’s utility, calling it a "surface scratch" that doesn’t address finer-grained control needs, but this doesn’t block the patch’s progress.

The patch touches only `builtin/checkout.c` and is mechanical, with no CLI or on-disk format changes. It’s part of a larger uncontroversial refactoring (the first seven patches could merge independently if the eighth is deferred), but Junio’s lukewarm assessment may dampen reviewer enthusiasm. The unresolved design question about the `cb_option` parameter in the first patch doesn’t affect this one. The series is explicitly not intended for `seen` yet due to potential conflicts with in-flight topics.
