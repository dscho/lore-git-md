This is a small but well-executed **bugfix and UX improvement** for `git checkout -m` when autostash is involved. The series is now in its final form (v4) and has been accepted by Junio C Hamano for merging to `next`.

The core issue is visual clutter: when `git checkout -m` stashes local changes and then encounters conflicts while applying them, the advice about how to resolve those conflicts appears directly above the "Switched to branch..." message, making the two hard to distinguish. Patch 2/2 fixes this by printing a blank line between them, a simple but effective UX tweak.

Patch 1/2 is the more substantial change. It refines the exit code semantics of `git stash apply`, `pop`, and `branch` to follow Git’s established convention: **exit code 1 for conflicts** (mirroring `git merge-tree` and merge strategies), and **exit code 128 (or another non-zero value) for other failures**. This replaces the previous ambiguous behavior where both conflicts and errors returned exit code 1. The change is implemented by introducing a new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) and updating the in-process autostash helpers to use it. The commit message is thorough and explains the rationale clearly, including how the new exit codes map to the old behavior and why the change is necessary.
