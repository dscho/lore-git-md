This is the final version of a feature patch that adds `--missing-only` to `git rev-list`, targeting GitLab's Gitaly workflow for partial clones. The patch itself is unchanged from v2; only the commit message has been strengthened to clarify the intended use case.

The feature is now approved and ready for integration. Junio C Hamano has signed off on the workflow explanation: `--missing-only` is designed for a one-shot walk, not a fetch loop. Gitaly uses it to pack a quarantine transaction, treating missing objects as dependencies that must already exist in the main repository rather than fetching them. The commit message now explicitly states this, addressing the only remaining question from the review thread.

The implementation remains clean and well-tested. It adds a filter flag that works alongside existing `--missing=` modes, omitting the `?` prefix for script-friendly output. The patch touches `builtin/rev-list.c`, updates documentation, and includes thorough tests that verify edge cases and option interactions. All review feedback from Derrick Stolee, Patrick Steinhardt, Phillip Wood, and Kristoffer Haugsbakk has been incorporated.

This is a small but useful addition that eliminates a post-processing step for GitLab's partial-clone workflow. The topic is queued for `next` and should land in the next release cycle.
