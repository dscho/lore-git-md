This is a bugfix for the `git-contacts` contrib script, a tool that suggests reviewers for a patch by analyzing who last modified the affected lines. The patch addresses a long-standing issue where the script incorrectly includes "boundary" commits—commits where `git blame` stopped its traversal without actually attributing any lines to them—when calculating potential reviewers.

The problem arises because `git blame` marks such commits with a `boundary` line in its porcelain output, but the script has been ignoring this marker since its introduction in 2013. As a result, authors of unrelated commits (e.g., a commit that only touched `builtin/fetch.c` but appears as a boundary when blaming `builtin/receive-pack.c`) are incorrectly suggested as reviewers, while the actual contributors are missed. The patch fixes this by tracking boundary commits during blame parsing and excluding them from the contact list.

The commit message is exceptionally thorough, explaining the bug's impact (27% of tested commits lose a reviewer, 9% become empty), the technical rationale for the fix (including why `--root` is now passed to `git blame`), and even documenting unrelated but notable defects in the script that are intentionally left untouched. The patch itself is small and focused, modifying only the blame-parsing logic and updating the documentation to clarify the boundary-commit behavior.

This is a well-motivated, clearly explained fix for a real problem in a contrib tool. The author’s attention to edge cases (e.g., shallow clones, SHA-256 repositories) and their decision to scope the patch narrowly (avoiding unrelated fixes) make it a strong candidate for merging. The change is unlikely to be controversial, though users of `git-contacts` should note that some patches may now return empty reviewer lists when no relevant contributors exist within the five-year window.
