This is the sixth patch in Michael Montalbo’s v3 series extending `git log -L` (line-log) to support range-scoped `--check` whitespace checking. The series is part of an ongoing effort to make common diff options work consistently with line-range filters.

The patch enables `--check` to honor tracked line ranges by reusing the `line_range_filter` infrastructure introduced earlier in the series. It adds an `orig_hunk_fn` field to the filter struct so that `checkdiff_consume_hunk()` receives hunk headers with accurate file line numbers (counting from the start of the file, not the range hunk). The trailing blank-at-eof check is now gated on whether the blank line falls within any tracked range, preventing false positives when the blank lies outside the range. Documentation is updated to list `--check` as a supported option, and tests verify that whitespace errors are reported only for in-range lines, that file line numbers are accurate even across gaps within a range, and that the blank-at-eof check respects the tracked ranges.

The implementation is clean and well-tested, touching `diff.c`, `revision.c`, and `t/t4211-line-log.sh`. No new technical concerns have surfaced in the thread; the series remains under review and is not yet in Junio’s integration branches. If you care about precise line-range filtering for whitespace checks, this patch is worth watching.
