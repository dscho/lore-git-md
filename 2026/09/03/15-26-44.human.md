This is a bug report about a memory leak in the new `git history reword` command. Kristoffer Haugsbakk has identified that running `git history reword` (even with `--dry-run`) triggers a 283-byte leak detected by AddressSanitizer. The leak surfaces in the object database layer (`odb.c`, `packfile.c`) when Git reads a commit's buffer, specifically in the path that unpacks a compressed object from a packfile.

The bisect log points to the merge commit `13763ecf` (Merge branch 'ps/receive-pack-shallow-optim', 2026-03-02) as the first bad commit. The leak does *not* occur on the commit that introduced `git history reword` itself, suggesting it is a regression in the ODB or packfile code that `git history` now exercises. The report includes a minimal reproduction recipe (build with `SANITIZE=address`, run `GIT_EDITOR=true git history reword <commit>`) and a bisect script, though the author notes the leak only appears in "real repos" with packfiles or commit-graphs present.

The report is well-structured: it provides exact reproduction steps, a bisect log, and a clear stack trace. The leak is small but real, and the fact that it is triggered by a new user-facing command makes it worth attention. No fix is proposed yet, but the bisect result gives a clear starting point for debugging.
