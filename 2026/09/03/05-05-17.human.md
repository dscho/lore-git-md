This is the fifth patch in Michael Montalbo’s v3 series extending `git log -L` (line-log) to support range-scoped diff stat formats. The patch enables `--stat`, `--numstat`, and `--shortstat` to work with `-L`, so that the stat counters reflect only the changes within the tracked line ranges. The implementation reuses the `line_range_filter` infrastructure introduced earlier in the series, routing its output through `diffstat_consume()`.

The patch updates the documentation to clarify that stat formats now count only lines within the tracked range and explains why `--dirstat` remains unsupported (its default mode measures whole-file churn, not per-range counts). The error message for unsupported formats is also updated to remove the misleading "yet" that implied all rejected formats were merely awaiting implementation.

Test coverage is extensive: new tests verify that stat counts align with the tracked range (not the whole file), that renames and multiple commits are handled correctly, and that multiple tracked ranges exclude untracked changes. The tests also confirm that the updated error message for `--dirstat` no longer includes "yet".

This patch is a straightforward and well-tested feature addition that builds cleanly on the earlier refactoring. The commit message and documentation are clear, and the implementation avoids duplicating code by reusing the existing `line_range_filter`. No controversy or open questions are evident; the patch looks ready for integration.
