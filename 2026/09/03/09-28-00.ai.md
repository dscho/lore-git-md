This is the third patch in Karthik Nayak’s four-patch v6 series introducing the `receive-report` hook for `git-receive-pack`. It refactors the status-report generation logic into a reusable `generate_report()` helper function, preparing the codebase for the upcoming hook implementation in patch 4/4. The patch is a pure refactoring with no behavior change: it consolidates the nearly identical `report()` and `report_v2()` functions into a single helper that takes an `enum report_status_version` parameter to control protocol-specific details.

The refactoring extracts the common pkt-line formatting logic from both functions, reducing code duplication and making the protocol-version switch more explicit. The new `generate_report()` function writes the status report into a caller-provided `strbuf`, which the existing `report()` and `report_v2()` functions now invoke before sending the buffer to the client. The patch also introduces a small safety improvement: the `enum` parameter ensures that the protocol version is always explicitly set, whereas the previous boolean `detailed_reports` flag could be misinterpreted.

Files touched: only `builtin/receive-pack.c` (45 insertions, 40 deletions). The patch is a direct response to Junio C Hamano’s maintainability feedback on v5, which suggested replacing the boolean flag with an `enum` to make the protocol-version switch more explicit and extensible. All prior feedback on this patch has been addressed, and the series is queued in `seen` with no blocking concerns. The refactoring is a prerequisite for the hook implementation in the next patch, which will reuse `generate_report()` to produce the status report passed to the `receive-report` hook on stdin.
