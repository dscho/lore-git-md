This is a bugfix patch targeting the push machinery, specifically the `--force-if-includes` safety check.

The patch fixes an uninitialized variable bug in `is_reachable_in_reflog()` that was introduced in 2020. When a remote-tracking ref has no reflog (which happens with the files backend after a fresh clone), the code reads an uninitialized timestamp from the stack, causing the reflog walk to stop prematurely. On the author’s machine this causes `--force-if-includes` to reject pushes that should be allowed, because the walk never reaches the “Created from” entry that records the initial checkout.

The fix is a one-line initialization to zero, plus an 18-line test that exercises the scenario: clone, expire all reflogs, reset the local branch, and verify that `--force-if-includes` still permits the push. The test is careful to note that the bug only surfaces with the files backend, not reftable.

The commit message is clear and the test is self-contained; the patch looks well-crafted and addresses a real edge case.
