This is a **bugfix** for the `pack-objects` subsystem, specifically addressing a performance regression in partial clones where missing objects are fetched inefficiently.

The patch fixes a logic error in `prefetch_to_pack()` where the function incorrectly interprets the sorted index as a traversal-order index, causing it to skip missing objects that should be batched together. The issue manifests when loose objects are present locally: these sort ahead of missing objects in the prefetch array, causing the batch to start at the wrong offset and forcing individual fetches for each missing object. The fix adds an explicit pointer to the sorted array, ensuring the batch includes all remaining missing objects regardless of their position in the traversal order.

The commit message is exceptionally thorough, explaining the bug's origin (commit `e00549aa9b`), providing synthetic benchmark results (before: 8 fetches for 8 objects; after: 1 fetch), and discussing rejected alternatives. A new test (`t5300-pack-object.sh`) verifies the fix under both SHA-1 and SHA-256, with careful precondition checks to avoid false positives.

The change is minimal (13 lines added, 5 removed) and targeted, touching only `builtin/pack-objects.c` and the test file. The patch appears well-motivated and addresses a real performance pain point for partial clones, though the synthetic test case suggests the issue may be more noticeable in edge cases than in typical workflows.
