This is a brief follow-up in the ongoing discussion about Git’s `parsed_object_pool` API and its relationship to the repository. Patrick Steinhardt acknowledges Junio C Hamano’s reminder that the parsed object pool currently depends on the repository’s hash algorithm—a deliberate design choice—but questions whether propagating the *entire* repository instance is necessary. He suggests that passing only the relevant pieces (e.g., the hash algorithm and compatibility hash) might be a cleaner approach than exposing the full repository structure to subsystems like the object database.

This exchange remains exploratory and does not propose concrete changes or block the original bugfix series (which plugs a memory leak in the submodule error path). Patrick notes he ultimately discarded the idea, so no immediate refactoring is planned. The discussion highlights a recurring tension in Git’s architecture: balancing subsystem decoupling with the practical need to access repository-scoped properties. For now, the status quo holds, but the thread keeps the door open for future reconsideration.
