This is a feature patch series (v6, 4 patches) introducing the `receive-report` hook for `git-receive-pack`. The hook allows server administrators to intercept and modify the status report sent to the client after ref updates are committed but before the response is finalized. This version addresses Junio C Hamano’s maintainability concern by replacing the `detailed_reports` boolean parameter with an `enum report_status_version`, making the protocol-version switch more explicit and extensible. The series also strengthens the documentation and commit messages to clarify why the `reference-transaction` hook cannot meet GitLab’s requirements and to explicitly acknowledge the consistency trade-off: the hook’s ability to report a state divergent from the actual repository state violates Git’s traditional principle that remote-tracking branches reflect the server’s state.

The series is now split into four patches: (1) documentation for the existing `proc-receive` hook, (2) a new refactoring patch that replaces static variables tracking report status version with an `enum`, (3) the refactoring of status-report generation into a reusable helper, and (4) the core hook implementation. The new `enum` patch is a direct response to Junio’s feedback and improves code clarity without changing behavior. The commit message for the hook patch now explicitly states that the hook owner is responsible for undoing ref changes if needed and documents the divergence between reported status and actual repository state, justifying it with GitLab’s MVCC use case where conservative client-side behavior is desired.

Files touched include `builtin/receive-pack.c`, `Documentation/githooks.adoc`, `Documentation/git-receive-pack.adoc`, and a new test script `t/t5412-receive-report-hook.sh` (224 lines). The hook’s exit semantics remain unchanged: non-zero exit rewrites all ref status lines to `"receive-report hook failed"` and overwrites all `cmd->error_string` fields. The hook is not integrated with the config-based hook infrastructure, and the test suite exercises edge cases like sideband relay and the hook’s ability to modify the `unpack` status line. The series is ready for integration into `next`; all prior feedback has been addressed, and the manual conflict resolution with Justin Tobler’s "pluggable writes" series has been confirmed correct.
