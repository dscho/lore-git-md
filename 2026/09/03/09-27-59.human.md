This is the second patch in the v6 series introducing the `receive-report` hook for `git-receive-pack`. It refactors how the code tracks the status report version by replacing two static boolean variables (`report_status` and `report_status_v2`) with a single `enum report_status_version`. This change makes the protocol-version switch more explicit and extensible, directly addressing Junio C Hamano’s maintainability concern from earlier review.

The patch is a pure refactoring with no behavior change. It touches only `builtin/receive-pack.c`, replacing the static variables with an enum that has three states: `REPORT_STATUS_UNKOWN` (initial state), `REPORT_STATUS_V0` (basic status reporting), and `REPORT_STATUS_V2` (enhanced status reporting). The enum is passed by pointer through the call chain, making the flow easier to follow. The patch also adds a `BUG()` call to catch any future case where the version is not set, which was not possible with the previous boolean flags.

This is a well-motivated cleanup that improves code clarity without introducing risk. The change is small, self-contained, and has no test coverage because it does not alter behavior. It is a direct response to maintainer feedback and is ready for integration.
