This is patch 6/7 in Michael Montalbo’s v3 resend of the line-log enhancement series. It enables `git log -L` to support the `--check` option, making whitespace and formatting errors report only within the tracked line ranges.

The patch extends the `line_range_filter` struct (introduced in patch 4) with an optional `orig_hunk_fn` callback so that `checkdiff_consume_hunk` receives hunk headers even when the filter discards out-of-range lines. The `builtin_checkdiff` function is updated to accept an optional `line_ranges` parameter; when present, it wraps the xdiff output in the line-range filter. A new helper `idx_in_ranges` checks whether a line falls within any tracked range, and the trailing blank-at-eOF check is gated on that predicate to avoid false positives. Documentation is updated to list `--check` among the supported formats, and the test suite verifies that error messages report real file line numbers (counting from the start of the file) and that only in-range whitespace errors are flagged.
