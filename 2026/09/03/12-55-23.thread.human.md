This thread is a two-patch series from Aleksei Sviridkin that closes a small but long-standing documentation and test gap around `git cherry-pick --no-commit`.

The first patch adds a test in `t3507-cherry-pick-conflict.sh` to verify that `CHERRY_PICK_HEAD` is *not* created when a conflicting `git cherry-pick --no-commit` fails. The second patch updates the `git-cherry-pick` man page to document this behavior, explaining that a subsequent `git commit` will record the committer as the author unless `git commit -c <commit>` is used to restore the original authorship. The documentation also notes that this workaround only applies to single-commit cherry-picks, since multiple picks leave no single original author to restore.

The series is under review with no replies yet. It is purely additive—no behavior changes, just test coverage and documentation for an edge case that has existed since 2011 but was never explicitly documented. The asymmetry with `git revert --no-commit` (which *does* write `REVERT_HEAD`) is left as-is, with the documentation patch calling it out rather than attempting to harmonize the two commands.
