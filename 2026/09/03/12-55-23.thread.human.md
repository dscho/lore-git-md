This thread is about a two-patch series from Aleksei Sviridkin that documents and tests a long-standing but undocumented edge case in `git cherry-pick --no-commit`: when the operation fails due to conflicts, `CHERRY_PICK_HEAD` is *not* created, unlike `git revert --no-commit` (which *does* write `REVERT_HEAD`). The goal is to clarify this asymmetry for users and ensure the behavior is explicitly covered by tests.

The series is under review, with the documentation patch (part 2) uncontested but the test patch (part 1) facing scrutiny. Junio initially misinterpreted the test as proposing a behavioral change, but Phillip Wood clarified that the current behavior is intentional. Patrick Steinhardt then questioned the necessity of the test, arguing it adds maintenance overhead without clear justification. Phillip’s latest review doubles down on this concern, proposing a tighter integration with an existing test to avoid redundancy and strengthen the test’s robustness. This directly engages with the open question of whether the test is justified or merely adds overhead.

Key participants include Aleksei (the author), Junio (the maintainer), Patrick (who questions the test’s value), and Phillip (who accepts the behavior but critiques the test design). The discussion has shifted from whether the behavior is correct to whether the test is necessary and how it should be structured. Aleksei will need to address these concerns in a v2 of the test patch, which may require rethinking its scope or purpose. The documentation patch remains uncontested but is now implicitly tied to the broader discussion about the test’s justification.
