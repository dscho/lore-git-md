This is the **second patch in a two-patch series** that refines how `git checkout -m` presents autostash conflict advice. The series is **queued for merging to `next`** and addresses a long-standing UX papercut: when autostash application results in conflicts, the advice message ("Your local changes are stashed...") currently appears directly above the branch-switch confirmation ("Switched to branch..."), making the two hard to distinguish visually.

This patch **inserts a blank line between the conflict advice and the branch-switch message** when the stash application returns `STASH_APPLY_CONFLICT`. The change is purely presentational—no logic or exit codes are altered—and relies on the new `enum stash_apply_result` introduced in patch 1/2. The code touches only `builtin/checkout.c` and the corresponding test in `t/t7201-co.sh`, which now uses `test_cmp` to validate the exact screen output, including the blank line.

The implementation is minimal: a single `fputc('\n', stderr)` call guarded by the conflict check and the `--quiet` flag. The test update replaces loose `test_grep` checks with a full expected output template, ensuring the blank line is preserved in future iterations. All prior review feedback—particularly around exit code conventions and conflict detection—was resolved in earlier versions, and this patch is uncontroversial.
