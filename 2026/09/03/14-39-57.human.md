This is the first patch in a now-merged two-patch series refining how `git checkout -m` handles autostash conflicts. The patch reserves exit status 1 exclusively for merge conflicts during stash application, aligning Git’s behavior with the established convention used by `git merge-tree` and the merge strategies. Previously, `git stash apply`, `pop`, and `branch` all exited with status 1 for *any* failure, making it impossible for callers to distinguish between true conflicts and other errors.

The core change introduces a new `enum stash_apply_result` (`STASH_APPLY_CLEAN`, `STASH_APPLY_CONFLICT`, `STASH_APPLY_ERROR`) and updates the stash subsystem’s internal APIs to return this enum instead of a bare `int`. The `cmd_stash()` dispatcher now maps negative return values to exit code 128 (matching `die()`’s convention) and passes through positive values, ensuring exit code 1 unambiguously signals conflicts. The patch also adds a new header (`stash.h`) to define the enum, updates `Documentation/git-stash.adoc` to document the exit statuses, and touches `sequencer.c` to use the new return values in autostash logic.

Test coverage is thorough: updated tests in `t/t3903-stash.sh` verify that `stash apply`, `pop`, and `branch` now exit with 1 for conflicts (and leave the stash entry intact) and with 128 for other errors (e.g., invalid refs). The tests also confirm that the stash entry is preserved in both cases, and that the new exit code convention is respected.

The patch is uncontroversial and ready for integration. All prior review feedback—including exit code conventions, conflict detection logic, and code clarity—has been addressed.
