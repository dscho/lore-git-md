This is a **documentation patch** correcting a long-standing inaccuracy in `Documentation/technical/partial-clone.adoc` about the performance of Git’s partial clone dynamic object fetching. The patch itself remains unchanged from the previous version, but the author has revised the cover letter to be significantly shorter and more focused, addressing Elijah Newren’s feedback about excessive length.

The core issue is that the existing documentation overgeneralized the "one-at-a-time" fetch limitation, implying it applied universally when in fact it only affects the fallback path in `odb.c` (1 of 11 call sites for `promisor_remote_get_direct()`). The other ten call sites batch objects into a single `git fetch --stdin` subprocess, making the original claim misleading. The patch narrows the scope of the limitation and updates the subprocess name from "fetch-pack" to "git fetch" to match the implementation. No code changes are involved, and the patch applies cleanly to both `maint` and `master`.
