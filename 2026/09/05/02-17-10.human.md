This is a review of the first patch in Mark C. Chu-Carroll’s test modernization series. Junio C Hamano, the Git maintainer, has rejected the patch outright, calling it "Wrong" and halting further review of the series.

The core issue is conceptual: the patch mechanically replaces `test -f` with `test_path_is_file` even when the test is part of a conditional expression whose purpose is not to assert file existence but to branch on it. Junio points out that `test_path_is_file` is designed to *assert* a condition (and fail loudly if it is not met), whereas `test -f` in a conditional is merely checking a state. The example he cites—`if test_have_prereq MINGW && test -f /proc/$shell_pid/winpid`—is not testing for a broken system but deciding whether to run a Windows-specific code path. Converting it to `test_path_is_file` would turn a silent branch into a test failure, which is incorrect.

Junio’s feedback is blunt: the conversion requires understanding *why* each `test -f` is present, not just replacing it. He declines to review the rest of the series, noting that the patches lack sign-offs and that sifting through them for salvageable bits is not a good use of his time. The series is now effectively blocked until the author revisits the approach.
