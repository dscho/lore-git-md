Core problem or goal
Correct a factual error in the `git-merge(1)` man page: the example diagram incorrectly claimed that `ORIG_HEAD` was set to the tip of the current branch (`C`) before a merge, whereas it should point to the tip of the branch being merged (`G`).

Current status
**Resolved.** The correction was merged to `master` in commit 953049ee ("docs: correct ORIG_HEAD example in 'git merge' documentation", 2025-07-05) and released in Git 2.51.0. No further action is needed.

Key technical details
- File touched: `Documentation/git-merge.txt`
- Symbols involved: `ORIG_HEAD`, branch names `master` and `topic`, commit labels `C` and `G`
- Old behavior: man page stated `ORIG_HEAD` → `C`
- New behavior: man page states `ORIG_HEAD` → `G`
- No on-disk format, CLI option, or test coverage changes
