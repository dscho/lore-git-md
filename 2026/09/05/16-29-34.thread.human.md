This thread is about a small but clear documentation fix in the `git-merge(1)` man page. Fabian Kratz originally reported that an example diagram incorrectly stated `ORIG_HEAD` would point to the tip of the current branch (`C`) before a merge, when in fact it should point to the tip of the branch being merged (`G`). The thread is now closed: Kristoffer Haugsbakk confirmed the issue was already fixed in Git 2.51.0 with commit `953049ee`, which updated the man page to match the correct behavior. No further changes are needed.
