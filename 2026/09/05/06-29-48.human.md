This is a documentation patch series from Kristoffer Haugsbakk, part of the ongoing effort to improve Git's conceptual documentation. The series adds cross-references to the new `gitdatamodel(7)` man page from several key documentation files (`git(1)`, the glossary, and the datamodel page itself), making it easier for users to discover and navigate Git's data model explanation.

The series consists of four small patches that link the datamodel tutorial from `git(1)`, add reciprocal links from the glossary to the datamodel page, and ensure internal consistency. Junio had tentatively marked it for `next`, but Kristoffer has requested it not be merged yet, as Julia Evans provided review feedback that will require a reroll. The review thread (linked in Junio's report) shows the discussion is still active, so this is a normal part of the process rather than a sign of trouble.

The work is well-motivated: Git's data model is famously opaque to newcomers, and the `gitdatamodel(7)` page (originally contributed by Julia Evans and later refined by others) is a significant step toward addressing that. These patches make the tutorial more discoverable, which should help users who are struggling to understand how Git represents history, trees, and blobs. The changes are purely additive and non-controversial in principle; the reroll will likely focus on wording or link placement rather than substance.

For a busy reader, this is a low-risk, high-value documentation improvement that doesn't touch code or behavior. It's worth noting if you care about Git's usability or documentation quality, but there's no urgency to review it until the reroll arrives. The series is part of a broader trend of making Git's internals more accessible, which has been a recurring theme in recent years.
