This is a CI/build system patch. Jeff King updates the Git project's continuous integration configurations to replace Debian 11 with Debian 12 in both GitHub Actions and GitLab CI workflows. The change is motivated by Debian 11 reaching the end of its LTS (Long Term Support) period, making it unmaintained by the Debian project. The patch updates the `jobname` and `image` fields in `.github/workflows/main.yml` and `.gitlab-ci.yml` to point to `debian:12` instead of `debian:11`, and updates the comments to reflect the new support window (until 2028-06-30).

The commit message references an earlier commit (`ac112fd4f0`) that introduced the Debian 11 job to cover older LTS releases, and explains that bumping to Debian 12 maintains this coverage for the next two years. Peff notes that he encountered an `apt` failure in a Debian 11 job, which prompted this change, though he acknowledges the failure might have been transient. He tested the GitHub job but not the GitLab one, though he expects it to work since both use the same Docker images.

The patch touches only CI configuration files and is a straightforward, mechanical change. It is well-motivated and aligns with the project's practice of tracking supported LTS distributions. The change is unlikely to be controversial, though someone might ask whether the project should also retain a job for an older LTS release (e.g., Debian 11) to catch compatibility regressions, or whether the AlmaLinux 8 job (supported until 2029) already provides sufficient coverage for older environments. The patch does not introduce new functionality or behavior changes, but it does affect the CI environment in which Git is tested.
