This is the test half of a two-patch series that documents and verifies a long-standing but undocumented edge case in `git cherry-pick --no-commit`. The patch adds a single-line check (`test_ref_missing CHERRY_PICK_HEAD`) to an existing test in `t3507-cherry-pick-conflict.sh`, ensuring the test suite explicitly verifies that `CHERRY_PICK_HEAD` is *not* created when a conflicting `--no-commit` cherry-pick fails.

The test addresses a gap in coverage: the logic in `do_pick_commit()` that determines whether `CHERRY_PICK_HEAD` is written depends on a complex condition combining the command, merge state, and `--no-commit` flag. While the test suite already verifies the clean `--no-commit` case, it previously did not check the conflicting case, leaving the behavior untested despite being intentional and documented in the companion patch. Phillip Wood argued this omission was worth fixing, citing the "tricky" logic as justification for a minimal guard against regressions.

The patch itself is uncontroversial in substance—it simply adds an assertion to an existing test—but its inclusion remains debated. Junio C Hamano and Patrick Steinhardt oppose it on grounds of test suite overhead, arguing that adding tests for long-standing edge cases requires stronger justification than completeness alone. The author revived the test in v3 after Phillip Wood’s latest feedback, but the broader policy question—whether the test’s value outweighs its maintenance cost—is still unresolved. The test’s fate may hinge on whether the author can tie it to a larger effort (e.g., test modernization) or demonstrate a concrete risk of regression.

This patch is narrowly scoped and well-motivated, but its inclusion is not yet settled. The companion documentation patch (part 2) clarifies the behavior for users and is uncontroversial. If the test is dropped, the documentation will still stand on its own, but the test suite will continue to lack explicit coverage for this edge case. The series as a whole addresses a real (if niche) user confusion point, and the test patch’s minimal footprint makes it a low-risk addition—if the policy debate swings in its favor.
