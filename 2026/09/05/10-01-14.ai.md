This is the second patch in the v5 series adding path-related keys to `git repo info`. The author, K Jayatheerth, acknowledges a correctness bug in the `path.superproject-root` implementation: the underlying `get_superproject_working_tree()` function ignores its repository parameter and instead uses the process’s current working directory (`xgetcwd()`). This breaks expected behavior when the command is invoked from a submodule’s `.git` directory (e.g., `git --git-dir="$GIT_DIR" repo info`), causing `path.superproject-root.absolute` to return an empty string instead of the superproject’s working tree path.

The fix is straightforward: update `get_superproject_working_tree()` to accept and use the `repo` parameter, replacing `xgetcwd()` with the repository’s working directory. The author plans to include this change in v6, along with additional test coverage for the `--git-dir` case. This bug is the primary blocker for the series; once resolved, the patch should be ready for further substantive review. The rest of the series remains mechanically clean and uncontroversial.
