This is the revived test patch for the `git cherry-pick --no-commit` documentation series. Aleksei Sviridkin has reintroduced the one-line test (`test_ref_missing CHERRY_PICK_HEAD`) in v3 after initially withdrawing it in v2. The test verifies that `CHERRY_PICK_HEAD` is *not* created when `git cherry-pick --no-commit` fails due to conflicts, addressing a gap in the existing test suite (`t3507-cherry-pick-conflict.sh`).

The justification for the test hinges on the "tricky" logic in `do_pick_commit()`, where the absence of `CHERRY_PICK_HEAD` depends on three conditions: the command type, whether the merge started, and the `--no-commit` flag. Aleksei argues that this complexity warrants a minimal safeguard against regressions, even though the behavior has been stable since 2011. The test itself is narrowly scoped—just one line added to an existing test case—so it adds negligible runtime or maintenance overhead.

This patch directly responds to the earlier debate about test suite policy. Phillip Wood had previously argued for the test’s necessity, while Junio C Hamano and Patrick Steinhardt opposed it on grounds of overhead. Aleksei’s v3 commit message now explicitly adopts Phillip’s phrasing about the "tricky" condition, framing the test as a targeted guard rather than a "random" addition. The unresolved question is whether this justification will satisfy reviewers who prioritize test suite minimalism.

The patch is part of a two-patch series, but the documentation update (part 2/2) remains uncontroversial. The focus here is purely on the test’s inclusion, which could influence future discussions about when edge-case tests are justified. If this test is accepted, it may set a precedent for similar minimal coverage of long-standing but undocumented behaviors.
