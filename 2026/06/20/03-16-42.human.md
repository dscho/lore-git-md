This is the second patch in the v6 series introducing standardized path formatting in Git. It refactors `git rev-parse` to use the new `append_formatted_path()` helper introduced in the first patch, eliminating ~44 lines of duplicated path-formatting logic while preserving exact backward compatibility.

The patch replaces the body of `print_path()` with a simple mapping from `rev-parse`'s existing `format_type`/`default_type` enums to the shared `path_format` enum, then delegates the actual formatting work to the new helper. This keeps all call sites and local enums untouched, addressing Phillip Wood's design concern about not leaking `rev-parse`-specific details into the shared API. The implementation is clean and minimal: the new version of `print_path()` is just 29 lines (down from 73) and focuses solely on the enum conversion.

The change is well-motivated and technically sound. The commit message clearly explains the refactoring goal, and the code itself is straightforward. Test coverage from the series (not shown in this patch) verifies that all path variants continue to work as before, including edge cases like shared repositories and worktrees.
