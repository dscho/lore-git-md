This is a follow-up in the ongoing performance investigation of `` `git diff` `` slowdowns in secondary worktrees. D. Ben Knoble reports that building Git with `USE_NSEC` (nanosecond-precision timestamps) eliminates the 200 ms delay he originally observed, confirming the root cause as racy-git timestamp collisions at second granularity.

He digs into the code and discovers that `` `git diff` `` already calls `refresh_index_quietly`, but the call is gated by a condition that appears to have been effectively dead since 2007. The guard `(1 < !!diff_auto_refresh_index)` evaluates to false on his system, meaning the index refresh never happens despite the intent. This raises the question whether the conditional is truly broken or if some other code path is supposed to flip the flag.

Knoble plans to send a small patch that exposes `USE_NSEC` as a Meson build knob, but he now views this as a stopgap rather than a proper fix. The thread’s momentum has already shifted toward runtime configuration of timestamp precision, so this email serves mainly to confirm the diagnosis and to flag the possibly dormant refresh logic as a separate issue worth investigating.
