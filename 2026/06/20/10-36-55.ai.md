This is the second patch in Tian Yuchen’s six-patch series optimizing `paint_down_to_common()` for one-sided histories. It introduces a new `paint_queue` struct that replaces the old `nonstale_queue` abstraction with explicit per-side counters (`p1_count`, `p2_count`, and `pending_merge_bases`). The counters track how many commits are queued for each paint state (PARENT1-only, PARENT2-only, or both), enabling the later optimization in patch 3 to terminate the walk early when one side’s queue is exhausted.

The patch is a refactoring with no functional change: the loop still drains the queue until all counters reach zero, mirroring the old `max_nonstale` pointer logic. The core logic is moved into `paint_count_transition()`, which updates the counters whenever a commit’s paint flags change. The helper functions `paint_queue_put()` and `paint_queue_get()` handle enqueueing and dequeueing while maintaining the counters, and the `ENQUEUED` flag is now managed internally rather than by the caller.

Key symbols introduced: `struct paint_queue`, `paint_count_transition()`, `paint_queue_put()`, `paint_queue_get()`. The patch touches only `commit-reach.c` and is purely preparatory for the optimization in patch 3. The commit message and code are clear, and the refactoring is well-motivated by the need to track per-side state for the early termination logic. No test coverage is added here, as the behavior remains unchanged.
