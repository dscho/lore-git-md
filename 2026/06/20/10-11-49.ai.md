This is the sixth version of Pablo Sabater's feature patch series implementing cascading indentation for visual roots in `git log --graph`. The series now consists of three patches instead of two, adding a new intermediate commit that introduces abstraction functions in `revision.c` to insulate `graph.c` from the walker's internal data structures.

The key architectural change in v6 is the addition of two new helper functions in `revision.c`: `revision_has_more_commits()` and `revision_peek_next_commit()`. These functions abstract the traversal model (linked list vs prio-queue vs future changes) and allow `graph.c` to remain agnostic to how commits are stored internally. This directly addresses the critical fragility identified in earlier versions where `graph_peek_next_visible()` directly accessed `revs->commits`, making it vulnerable to Jeff King's planned removal of that field.

The series now demonstrates a clear path forward for the architectural concern that was blocking v5. The new abstraction appears to be the lightweight solution Kristofer Karlsson proposed, and Pablo has implemented it while maintaining the core visualization logic. The three patches are:

1. A cleanup moving a common test helper function to a shared location
2. The new abstraction layer in `revision.c` with peek functions
3. The main implementation adding visual root indentation

The documented edge case about imperfect lookahead remains (where cascading indentation might be missed if a commit's parents haven't been simplified yet), but this is now properly marked as NEEDSWORK and appears to be a secondary concern compared to the architectural fragility that v6 addresses. The test coverage has expanded with a new test for unrelated branches with merges, suggesting thorough validation of the visualization rules.

This version appears to resolve the primary technical blocker that was preventing the series from progressing. The abstraction layer should make the code robust against future changes in revision.c's traversal model, including Jeff King's planned removal of `revs->commits`. The series now looks technically sound and ready for final review, with the remaining NEEDSWORK item being a known limitation rather than a correctness issue.
