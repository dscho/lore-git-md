Core problem or goal
Optimize the `paint_down_to_common()` function in Git’s commit-reach subsystem to terminate early when one side of a merge-base query exhausts its commit queue, eliminating unnecessary traversal of large one-sided histories (e.g., repositories with import grafts or shallow histories). The optimization yields **100-1000x speedups** for asymmetric queries. The series is **technically complete, fully reviewed, and procedurally unblocked**, with **review bandwidth remaining the primary bottleneck** for advancement beyond its current queued state.

- **Core optimization (patch 8/8, prior update)**: Implements early termination in `paint_queue_get()` when one side of the history is exhausted (`(!state->parent1_count || !state->parent2_count) && !state->mb_candidate_count && state->last_gen < GENERATION_NUMBER_INFINITY`). The optimization is **skipped in the INFINITY region** (where commit-date ordering can violate topological guarantees) to ensure correctness. The patch updates the documentation to clarify the "side-exhaustion" termination condition and its applicability.
- **Performance impact**: The optimization reduces step counts from **81 to 9** in the `merge-base --all commit-9-9 commit-9-1` test (full commit-graph mode), demonstrating the **100-1000x speedup** in asymmetric queries. Test expectations are updated to reflect these reduced step counts across all commit-graph modes (none/full/half/no-gdat).
- **Refactoring (patch 7/8, prior update)**: Introduces a `paint_state` struct to track per-side commit counters (`parent1_count`, `parent2_count`, `mb_candidate_count`) during the paint walk, replacing the old `max_nonstale` pointer-based termination logic with explicit counters. The change is a **non-behavioral refactoring** that improves code clarity and maintainability. The new `paint_queue_put()`, `paint_queue_get()`, and `paint_count_update()` helpers manage the counters via a signed delta system, adjusting the appropriate bucket when commits are enqueued or dequeued. The termination condition now checks whether all counters are zero, functionally equivalent to the old logic but more explicit. The patch removes redundant functions (`nonstale_queue_put_dedup()`, `nonstale_queue_get_dedup()`) and updates the documentation to reflect the counter-based approach.
  - **Minor test impact**: The "pop first" logic in `paint_queue_get()` causes the loop to exit one iteration earlier in some topologies (e.g., `pending-stale` and `se2-*`), reducing step counts by one in affected test cases. The test suite has been updated to account for this change.
- **New refactoring (patch 9/8, prior update)**: Moves the generation-number cutoff check into `paint_queue_get()`, consolidating all termination conditions (stale entries, side exhaustion, and `min_generation`) in one place. The change hoists `last_gen` into the `paint_state` struct so that `commit_graph_generation()` is called exactly once per dequeued commit, eliminating redundant calls and sharing the result across termination checks and the monotonicity BUG assertion. The patch is a **mechanical cleanup with no intended behavior change**, improving code clarity by centralizing termination logic and reducing redundant work. It touches only `commit-reach.c`, moving 13 lines of logic into the helper function and adding two fields (`min_generation` and `last_gen`) to `paint_state`.
- **Fallback removal (patch 9/9, prior update)**: Removes the commit-date ordering fallback entirely, replacing it with a **topological ceiling** (`GENERATION_NUMBER_V1_MAX`) for v1 commit-graphs. The fallback was originally added to avoid performance regressions in v1 graphs but introduced correctness issues by violating topological invariants. The side-exhaustion optimization (introduced earlier in the series) now handles the performance problem more elegantly, reducing step counts from **167k to 5.7k** (v1 graph) and **3.9k** (v2 graph) in the Linux kernel repo. The patch removes the `gen_ordered` flag from `paint_state`, adds `topo_ceiling` to enforce the ceiling for v1 graphs, and updates the technical documentation to remove the obsolete "date-ordering fallback" section. Test expectations are adjusted to reflect the reduced step counts (e.g., `test_paint_down_steps 81 9 57 37` instead of `81 9 57 81`).
