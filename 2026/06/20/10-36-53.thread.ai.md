Core problem or goal
Optimize the `paint_down_to_common()` function in Git’s commit-reach subsystem to terminate early when one side of a merge-base query exhausts its commit queue, eliminating unnecessary traversal of large one-sided histories (e.g., repositories with import grafts or shallow histories). The optimization targets a known performance bottleneck where asymmetric histories force full traversal of one side even after the other side is exhausted.

Current status
Series is **technically complete for v2**; all design, technical, and procedural feedback has been resolved. The **core optimization (patch 3)** is functionally correct and endorsed by Derrick Stolee. The **structural dispute** over patch 1 is resolved: `nonstale_queue` is preserved for `ahead_behind()` in v2, eliminating patch 1 entirely. The **termination condition** is finalized as `(!queue.p1_count || !queue.p2_count) && !queue.pending_merge_bases`, with the side-exhaustion check gated by `last_gen < GENERATION_NUMBER_INFINITY` to ensure it only triggers in the finite-generation region. The **finite-generation guard** (patch 3) is confirmed as critical for correctness, and its activation timing is explicitly tied to the finite-generation region. **Patch ordering** is settled: the documentation patch (patch 6) appears first, followed by tests (patches 4–5) as regression checks, and then the optimization (patch 3). **Performance instrumentation** is fully agreed: **hyperfine** benchmarks `git merge-base` end-to-end timing between builds, and **trace2_data_intmax()** exposes the "commits walked" metric for testable validation.

The **last implementation detail**—state encapsulation in the `paint_state` struct (renamed from `paint_queue` in v2)—is now resolved. Stolee and Kristofer Karlsson agree to store `last_gen` directly in the struct, making `paint_queue_get()` self-contained and eliminating the need for external parameters. This simplifies the loop’s termination condition in `paint_down_to_common()`. The **fast-exit optimization** for single-merge-base queries (controlled by `mb_flags`) is confirmed for removal in v2, as its value is diminished by the new side-exhaustion logic and its correctness is questionable for callers that should detect multiple merge bases. The series is ready to land with no remaining open questions.

The loop’s termination condition now relies entirely on `paint_queue_get()` returning `NULL`, simplifying control flow.
- On-disk format: no changes.
- Test coverage: new tests for edge cases (patch 4: self/duplicate/pending-stale/infinity-both-sides; patch 5: diamond topology with redundant merge-base candidates, mixed finite/INFINITY generation numbers, criss-cross merges, grafts, shallow histories) and regression scenarios; benchmarks using **hyperfine** measure `git merge-base` performance between builds, and **trace2_data_intmax()** exposes the "commits walked" metric for testable validation. - Style changes in v2: `switch` statement formatting aligned with `.clang-format`, `pq` field renamed to `queue`, addition-based termination condition replaced with `(!count)` idiom, inline comment added to clarify `case 0` logic (serving as a "not in the queue" marker), early-exit check moved to `paint_queue_get()`, cross-reference comment added in `commit-reach.c` linking to `Documentation/technical/paint-down-to-common.adoc`, documentation patch reordered to appear first.
- Performance instrumentation: **hyperfine** is the baseline tool for end-to-end timing of `git merge-base` between builds, with the command `hyperfine --warmup=3 -n 'old' "~/git-old/bin-wrappers/git -C $repo merge-base $A $B" -n 'new' "~/git-new/bin-wrappers/git -C $repo merge-base $A $B"`. **Trace2 region markers** are available as a fallback if external noise (e.g., `repo_parse_commit` overhead) obscures the signal.
- State encapsulation: `last_gen` is now stored directly in the `paint_state` struct, making `paint_queue_get()` self-contained and eliminating the need for external parameters. This simplifies the loop’s termination condition in `paint_down_to_common()`. The `mb_flags` field (for the older fast-exit optimization) is not internalized in v2, as the optimization is removed.
