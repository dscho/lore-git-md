Core problem or goal
Optimize the `paint_down_to_common()` function in Git’s commit-reach subsystem to terminate early when one side of a merge-base query exhausts its commit queue, eliminating unnecessary traversal of large one-sided histories (e.g., repositories with import grafts or shallow histories). The optimization targets a known performance bottleneck where asymmetric histories force full traversal of one side even after the other side is exhausted, yielding **100-1000x speedups** for asymmetric queries.

Current status
Series is **technically complete and ready to land** in v2. All design, technical, and procedural feedback from v1 has been resolved. The **core optimization (patch 7/7)** is functionally correct and endorsed by Derrick Stolee, Kristofer Karlsson, and Elijah Newren. The **structural dispute** over patch 1 from v1 is resolved: `nonstale_queue` is preserved for `ahead_behind()`, eliminating the decoupling patch entirely. The **termination condition** is finalized as `(!state->p1_count || !state->p2_count) && !state->pending_merge_bases`, with the side-exhaustion check gated by `last_gen < GENERATION_NUMBER_INFINITY` to ensure it only triggers in the finite-generation region. The **finite-generation guard** is confirmed as critical for correctness, and its activation timing is explicitly tied to the finite-generation region. **Patch ordering** is settled: the documentation patch (1/7) appears first, followed by regression tests (2-3/7), trace2 instrumentation (4/7), refactoring (5-6/7), and then the optimization (7/7). **Performance instrumentation** is fully agreed: **trace2_data_intmax()** exposes the "commits walked" metric for testable validation, and **hyperfine** benchmarks `git merge-base` end-to-end timing between builds.

The **last implementation detail**—state encapsulation in the `paint_state` struct—is resolved. `last_gen` is derived from the dequeued commit in `paint_queue_get()`, making the function self-contained and eliminating external parameters. The **fast-exit optimization** for single-merge-base queries (controlled by `mb_flags`) is removed in v2, as its value is diminished by the new side-exhaustion logic and its correctness is questionable for callers that should detect multiple merge bases. The series is ready to land with no remaining open questions.

Key technical details
- Subsystem: commit-reach (merge-base calculation).
- Files touched: `commit-reach.c` (core logic), `Documentation/technical/paint-down-to-common.adoc` (new documentation), test scripts `t6099-merge-base-side-exhaustion.sh` and `t6600-test-reach.sh`.
- New/renamed symbols: `paint_state` struct (replaces `paint_queue` in v2), per-side counters (`p1_count`, `p2_count`, `pending_merge_bases`), `paint_count_update()`, `paint_queue_put()`, `paint_queue_get()` (self-contained, with `last_gen` derived from the dequeued commit).
- Behavior change: walk terminates early when `(!state->p1_count || !state->p2_count) && !state->pending_merge_bases` and the dequeued commit’s generation is finite (`last_gen < GENERATION_NUMBER_INFINITY`). The early-exit check is encapsulated in `paint_queue_get()` and gated by the finite-generation guard. The loop’s termination condition now relies entirely on `paint_queue_get()` returning `NULL`, simplifying control flow.
- On-disk format: no changes.
- Test coverage: new tests for edge cases (patch 2: self/duplicate/pending-stale/infinity-both-sides; patch 3: diamond topology with redundant merge-base candidates, mixed finite/INFINITY generation numbers, criss-cross merges, grafts, shallow histories) and regression scenarios; benchmarks using **hyperfine** measure `git merge-base` performance between builds (e.g., `7.26s -> 88ms` for a 2.6M-commit monorepo), and **trace2_data_intmax()** exposes the "commits walked" metric for testable validation (e.g., `paint_down_to_common steps 9` vs. `80` in git.git). Tests precede the optimization in v2.
- Style changes in v2: `switch` statement formatting aligned with `.clang-format`, `pq` field renamed to `queue`, addition-based termination condition replaced with `(!count)` idiom, inline comment added to clarify `case 0` logic (serving as a "not in the queue" marker), early-exit check moved to `paint_queue_get()`, cross-reference comment added in `commit-reach.c` linking to `Documentation/technical/paint-down-to-common.adoc`, documentation patch reordered to appear first.
- Performance instrumentation: **hyperfine** is the baseline tool for end-to-end timing of `git merge-base` between builds, with the command `hyperfine --warmup=3 -n 'old' "~/git-old/bin-wrappers/git -C $repo merge-base $A $B" -n 'new' "~/git-new/bin-wrappers/git -C $repo merge-base $A $B"`. **Trace2 region markers** expose the "commits walked" metric for deterministic validation, and **trace2_data_intmax()** is used to log step counts (e.g., `paint_down_to_common steps 9`).
- State encapsulation: `last_gen` is derived from the dequeued commit in `paint_queue_get()`, making the function self-contained and eliminating external parameters. The `mb_flags` field (for the older fast-exit optimization) is removed in v2.
