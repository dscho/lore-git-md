This is the second patch in Pablo Sabater's v6 series implementing cascading indentation for `git log --graph`. It introduces the abstraction layer in `revision.c` that resolves the architectural fragility blocking earlier versions.

The patch adds two new functions to `revision.h` and `revision.c`: `revision_peek_next_commit()` and `revision_has_commits_after()`. These functions abstract the traversal model so that `graph.c` no longer needs to know whether commits are stored in a linked list (`revs->commits`) or a priority queue (`revs->topo_walk_info->topo_queue`). This directly addresses Jeff King's planned removal of `revs->commits` and makes the graph code robust against future changes in revision.c's internal data structures.

The implementation is clean and minimal: `revision_peek_next_commit()` returns the next commit without consuming it, while `revision_has_commits_after(n)` checks whether there are at least `n` more commits to be shown. Both functions dispatch based on the walk mode (topological vs linear) and handle the visibility filtering (`commit_show`) correctly. The patch touches only `revision.c` and `revision.h`, adding 38 lines of implementation and 10 lines of declarations.
