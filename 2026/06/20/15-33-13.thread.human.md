The macOS CI hang fix thread has reached a stable technical consensus but now faces a strategic question about CI resource allocation. The thread began when Michael Montalbo reported hangs in `t5551` and `t5559` tests caused by Apache’s `mod_http2` bug 70131, which triggers timeouts or protocol errors during `ls-refs` advertisements of 100,000 loose refs. Jeff King (Peff) proposed a 3-patch series to address this: increasing Apache’s `Timeout` directive from 300 to 600 seconds, isolating the expensive test case into its own repository, and enabling `GIT_TEST_LONG` for GitLab CI on pull-request events. The first two patches—directly fixing the root cause and optimizing test runtime—are uncontested and ready for merging, with all key participants (Peff, Patrick Steinhardt, Junio) agreeing to drop the initially proposed ref-packing optimization as redundant.

The open question now centers on Patrick’s third patch, which aligns GitLab CI’s behavior with GitHub’s by enabling long-running tests for pull requests and pushes to integration branches. Junio endorsed the patch’s correctness but raised a broader policy concern: if CI resources are limited, should GitLab duplicate GitHub’s test coverage or prioritize running *additional* tests or events not already covered by GitHub? For example, GitHub already enables `GIT_TEST_LONG` for pull requests to any branch and pushes to `next`, `master`, and `maint`; GitLab could instead focus on scheduled runs or tag pushes. This is a strategic discussion, not a technical blocker, and the thread remains open pending input on GitLab’s capacity or alternative coverage priorities. Until resolved, the series as a whole is not yet ready to merge.
