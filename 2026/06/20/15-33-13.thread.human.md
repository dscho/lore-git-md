The macOS CI hang in `t5551` and `t5559`—caused by Apache’s `mod_http2` bug 70131—has been resolved and merged for Git 2.55. The fix, a two-patch series from Jeff King, increased Apache’s `Timeout` directive to 600 seconds and isolated the many-tags test case in a bare repository, reducing runtime and eliminating CI hangs. A follow-up patch adding a GitLab CI status badge to the `README.md` was also accepted, improving visibility of CI results.

The thread then shifted to performance optimizations in Git’s reftable backend, where Jeff King identified a quadratic-time scalability issue during bulk ref deletion and re-creation. The root cause was tombstone-based deletion, which forced redundant scans in both refname verification and transaction preparation. Kristofer Karlsson proposed a fix exposing tombstones to iterator bounds checks, enabling early termination and reducing runtime from O(n²) to O(n)—for example, 8,000 refs now complete in 0.145 seconds instead of 14.93 seconds. Patrick Steinhardt reviewed the patch, acknowledging its effectiveness but noting the added complexity of tombstone filtering at call sites. The fix is now actionable, with Kristofer encouraged to submit it formally.

Open questions remain about whether the performance gain justifies the code complexity, especially given the reftable backend’s design trade-offs. The CI resource allocation discussion—whether GitLab should mirror GitHub’s `GIT_TEST_LONG` coverage—is still unresolved, though the badge addition improves visibility. Other low-hanging optimizations, such as buffering reflog writes and reducing redundant `stat()` calls, were identified but not yet addressed. The thread demonstrates how a CI flake investigation can uncover deeper architectural opportunities, with the reftable performance work now poised for further review.
