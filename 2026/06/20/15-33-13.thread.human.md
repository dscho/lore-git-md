This thread is about a macOS CI timeout issue on GitHub Actions runners, where the `t5551` and `t5559` tests hang during an `ls-refs` advertisement of 100,000 loose refs. Michael Montalbo diagnosed the problem as an HTTP/2 flow-control stall in GitHub’s virtualized macOS environment, which doesn’t self-resolve like it does on bare-metal macOS or Linux.

Montalbo proposes a two-part fix: first, packing the refs in `t5551` to drastically reduce advertisement time (from ~1.2 seconds to ~24 ms on macOS), and second, aligning the `$JOBS` setting on GitHub macOS runners with the core count, matching existing behavior in the meson build and GitLab CI. Testing on a branch (`mm/macos-ci-hang-fix`) showed consistent success, with all eight `EXPENSIVE` runs completing in 30–44 minutes instead of timing out at 6 hours. The patch is now up for review if the maintainers want to merge it. No responses or objections have been raised yet.
