This thread began when Michael Montalbo reported CI hangs in Git’s macOS and Linux test suites (`t5551` and `t5559`), traced to an upstream Apache `mod_http2` bug (70131) that caused HTTP/2 stalls or mid-transfer aborts (`curl 18`) when the server’s 300-second timeout was hit. Jeff King (Peff) quickly proposed and implemented a two-patch fix: increasing Apache’s `Timeout` directive to 600 seconds and isolating the problematic test case in a bare repository. Both patches were merged for Git 2.55, resolving the immediate CI failures.

The discussion then expanded to broader CI policy and performance optimizations. Patrick Steinhardt added a GitLab CI status badge to the project’s `README.md` (now merged), while his proposal to enable `GIT_TEST_LONG` on GitLab remains on hold pending resource allocation decisions. A deeper dive into reftable backend performance revealed a quadratic-time scalability issue during bulk ref deletion and re-creation, caused by tombstone iteration inefficiencies. Kristofer Karlsson’s patch, which exposes tombstones to iterator bounds checks, eliminated the O(n²) bottleneck (e.g., reducing runtime for 8,000 refs from 14.93s to 0.145s) and is now merged. Peff and Patrick also identified smaller optimization opportunities—redundant `stat()` calls and unbuffered reflog writes—but these remain unaddressed.

In the latest update, Montalbo preserved diagnostic context by submitting a public patch to Apache’s GitHub mirror, documenting the original bug for future contributors. While this doesn’t affect Git’s codebase, it ensures the root cause remains accessible for debugging similar issues. The thread is now effectively closed, with all actionable items resolved.
