This is the final patch in a four-part GSoC series that adds standardized path formatting to `git repo info`. This patch specifically introduces `path.gitdir.absolute` and `path.gitdir.relative` fields, mirroring the `path.commondir` fields added in the previous patch. The implementation reuses the shared `append_formatted_path()` helper introduced earlier in the series, ensuring consistent behavior with `rev-parse` and other Git commands.

The patch is small (36 lines) and focused: it adds two new getter functions (`get_path_gitdir_absolute` and `get_path_gitdir_relative`) to `builtin/repo.c`, documents the new fields in `git-repo.adoc`, and extends the test suite to verify both standard and environment-override scenarios. The test coverage is thorough, including cases where `GIT_DIR` is explicitly set, which ensures the feature works correctly in worktree setups.

This completes the series' goal of making repository paths scriptable without parsing `rev-parse` output. The design is clean and aligns with Git's philosophy of explicit over implicit for plumbing commands. The series has undergone six iterations with substantive review from Phillip Wood, Justin Tobler, and others, and all design concerns have been resolved. The implementation is ready for maintainer pickup and should graduate to `next` soon. If you care about scriptable Git tooling or worktree support, this is worth a quick look.
