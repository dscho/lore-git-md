Core problem or goal
Add feature parity between Meson and Autotools/Makefile for sub-second file timestamp tracking via the `USE_NSEC` macro. The thread has evolved into a comprehensive re-evaluation of `USE_NSEC`'s necessity, reliability, interoperability, configuration level (build-time vs. runtime), auto-detection feasibility, and deprecation. Jeff King’s testing demonstrated that historical "racy Git" concerns about filesystem timestamp granularity are obsolete on modern Linux (ext4, ext2, XFS, vfat, CIFS, NTFS, FUSE), but interoperability risks emerge when mixing `USE_NSEC` and non-`USE_NSEC` implementations (e.g., Git and JGit). The discussion has converged on an **incremental path forward** proposed by Patrick Steinhardt and endorsed by Jeff King and Junio C Hamano:
- **Always compile nanosecond timestamp support into Git** when the platform provides the necessary APIs (e.g., modern Linux), eliminating the need for a build-time knob to enable the feature.
- **Expose the feature via a runtime config knob** (e.g., `core.useNsec`), making it more accessible than the current build-time knob.
- **Retain the current build-time default** (`USE_NSEC` disabled) for backward compatibility, but allow users to opt into the feature via the runtime config.
- **Deprecate and eventually remove the `USE_NSEC` build knob** (Meson and Makefile) once the runtime config is available, as retaining it to tweak the unconfigured default would add unnecessary complexity.
