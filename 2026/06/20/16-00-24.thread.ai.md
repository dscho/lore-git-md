Core problem or goal
Add a `nanosec` Meson build option that defines the `USE_NSEC` macro, matching the existing Autotools/Makefile knob for sub-second file timestamp tracking. The thread has evolved into a comprehensive re-evaluation of `USE_NSEC` necessity, reliability, interoperability, configuration level (build-time vs. runtime), auto-detection feasibility, and deprecation. Jeff King’s testing demonstrated that historical "racy Git" concerns about filesystem timestamp granularity are obsolete on modern Linux (ext4, ext2, XFS, vfat, CIFS, NTFS, FUSE), but interoperability risks emerge when mixing `USE_NSEC` and non-`USE_NSEC` implementations (e.g., Git and JGit). Proposals include (1) flipping the default to `true` (Brian M. Carlson), (2) deprecating/removing the knob (Patrick Steinhardt’s earlier position), (3) converting it to runtime-configurable (Patrick Steinhardt’s latest proposal, now endorsed by Peff), and (4) retaining the build-time option for parity (D. Ben Knoble’s latest position). The discussion centers on whether the original patch should proceed, whether runtime configuration is justified, and whether the knob’s existence is warranted.

Current status
The original patch remains queued for merging by Junio C Hamano with no changes requested. The discussion has converged on an **incremental path forward** proposed by Patrick Steinhardt and endorsed by Jeff King:
- **Always compile nanosecond timestamp support into Git** when the platform provides the necessary APIs (e.g., modern Linux), eliminating the need for a build-time knob to enable the feature.
- **Expose the feature via a runtime config knob** (e.g., `core.useNsec`), making it more accessible than the current build-time knob.
- **Retain the current build-time default** (`USE_NSEC` disabled) for backward compatibility, but allow users to opt into the feature via the runtime config.
- **Deprecate and eventually remove the `USE_NSEC` build knob** (Meson and Makefile) once the runtime config is available, as retaining it to tweak the unconfigured default would add unnecessary complexity. This aligns with Peff’s skepticism about the knob’s value but contrasts with Knoble’s defense of build-time parity for power users.

Key technical details remain unchanged from the prior summary, with these additions:

No auto-detection will be implemented initially, sidestepping Peff’s earlier concerns about its feasibility.
