Subject: [PATCH] meson: add `nanosec` option to mirror Autotools `USE_NSEC`
Series version: standalone patch
Originating author: D. Ben Knoble
Thread type: patch (build system parity)

Core problem or goal
Add a `nanosec` Meson build option that defines the `USE_NSEC` macro, matching the existing Autotools (and Makefile-based) `USE_NSEC` knob. This enables Git to track sub-second file modification and change times (mtimes and ctimes) when the option is enabled, ensuring feature parity between all build systems. The patch addresses build system consistency but does not alter the underlying trade-offs of enabling sub-second timestamp tracking.

Current status
Patch has been reviewed, accepted, and queued for merging by Junio C Hamano. It will likely graduate to the `next` branch soon. No prior versions; Autotools and Makefile sides remain unchanged.

Key technical details
- Files touched: `meson_options.txt`, `meson.build`
- New Meson option: `nanosec` (boolean, default `false`)
- Macro defined: `USE_NSEC` (when `nanosec=true`)
- Subsystem: build system (Meson)
- On-disk or runtime behavior: none directly; enabling `USE_NSEC` increases Git’s sensitivity to sub-second timestamps, which can cause "racy Git" issues on filesystems with coarse timestamp granularity or network filesystems (e.g., CEPH, CIFS, NTFS, UDF)
- Test coverage: none added; existing Autotools/Makefile tests already cover the functionality

Open questions and loose ends
- Junio noted a minor reservation about the discoverability of the `-Dnanosec=true` option name but did not consider it a blocker.
- The commit message does not explain the *purpose* or *trade-offs* of `USE_NSEC` (why a user might want it or the risks of enabling it), only that it mirrors the existing knob.
- D. Ben Knoble acknowledged the Makefile-based build also uses `USE_NSEC` but retained "Autotools-style" phrasing in the commit message for caution.
- Jeff King (Peff) raised a **substantive technical concern** about `USE_NSEC`’s reliability on filesystems with coarse timestamp granularity or network filesystems, citing `Documentation/technical/racy-git.adoc`. He noted that while the issue was partially fixed in Linux 2.6.11 (2005), some filesystems may still be affected. Peff did not block the patch but suggested that a deeper investigation could justify flipping the default in `config.make.uname` in the future.
- Future discussion might arise about whether all Autotools/Makefile knobs should be mirrored in Meson or if some should be deprecated, but this patch does not itself raise that question.
