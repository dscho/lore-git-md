Subject: [PATCH] meson: add `nanosec` option to mirror Autotools `USE_NSEC`
Series version: standalone patch
Originating author: D. Ben Knoble
Thread type: patch (build system parity, now expanded to platform compatibility discussion)

Core problem or goal
Add a `nanosec` Meson build option that defines the `USE_NSEC` macro, matching the existing Autotools and Makefile-based `USE_NSEC` knob for sub-second file timestamp tracking. The patch initially aimed for build system parity, but follow-up discussion has expanded to question whether `USE_NSEC` should exist at all due to reliability concerns on filesystems with coarse timestamp granularity or network filesystems.

Current status
Patch remains queued for merging by Junio C Hamano, with no changes requested. However, the thread has shifted from a straightforward review to a deeper technical debate about the value and risks of `USE_NSEC`. No new patch versions or deprecation proposals have been submitted yet. The original goal of Meson/Autotools/Makefile parity is still achieved by the patch, but its long-term viability is now in question.

Key technical details
- Files touched: `meson_options.txt`, `meson.build` (original patch)
- New Meson option: `nanosec` (boolean, default `false`)
- Macro defined: `USE_NSEC` (when `nanosec=true`)
- Subsystem: build system (Meson), with implications for filesystem compatibility
- On-disk or runtime behavior: enabling `USE_NSEC` increases Git’s sensitivity to sub-second timestamps, which can trigger "racy Git" issues on filesystems with coarse granularity (e.g., CEPH, CIFS, NTFS, UDF) or network filesystems. The issue was partially addressed in Linux 2.6.11 (2005) but may persist on some platforms.
- Test coverage: none added; existing Autotools/Makefile tests cover the functionality
- Documentation reference: `Documentation/technical/racy-git.adoc` (cited by Peff)

Open questions and loose ends
- **Should `USE_NSEC` exist at all?** Patrick Steinhardt argues that if the knob is subtly broken on some filesystems, it may not be worth exposing—even for parity. This challenges the original patch’s premise.
- **Trade-offs of `USE_NSEC`:** The commit message still omits rationale and risks (e.g., why a user might want it, or the "racy Git" pitfalls). Peff’s concerns about coarse timestamp granularity remain unresolved.
- **Future of build system knobs:** The discussion could extend to whether all Autotools/Makefile knobs should be mirrored in Meson or if some should be deprecated. No concrete proposals yet.
- **Default values:** Peff suggested a deeper investigation could justify flipping the default in `config.make.uname` in the future, but this is not currently actionable.
