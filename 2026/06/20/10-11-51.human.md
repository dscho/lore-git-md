This is the second patch in Pablo Sabater’s three-part v6 series implementing cascading indentation for `git log --graph`. It introduces the abstraction layer that resolves the architectural fragility that blocked earlier versions.

The patch adds two new functions to `revision.c` and exports them in `revision.h`: `revision_peek_next_commit()` and `revision_has_commits_after()`. These functions let the graph renderer look ahead without knowing whether the walker is using the old linked-list (`revs->commits`) or the newer priority-queue (`revs->topo_walk_info`). The implementation is straightforward: each function dispatches to the appropriate data structure, counting only commits that are actually going to be shown (`commit_show`).

This is a pure refactoring with no user-visible behavior change. The commit message is concise and the code is clean, with no obvious edge cases or missing error handling. The patch directly addresses Jeff King’s planned removal of `revs->commits` and Kristofer Karlsson’s earlier suggestion for a lightweight abstraction. It looks ready for review and should be uncontroversial.
