This is a feature patch series (v6) from Pablo Sabater improving `git log --graph` rendering by adding cascading indentation to visual root commits. The series now consists of three patches, up from two in v5, reflecting a significant architectural change.

The core problem remains: when history simplification filters out some parents, unrelated commits can appear vertically adjacent in the graph, creating false visual relationships. The solution now includes a new abstraction layer in `revision.c` to insulate the graph code from the revision walker's internal data structures, addressing the critical fragility identified in previous versions.

Patch 1/3 is a cleanup moving a test helper function to a shared location. Patch 2/3 introduces the new abstraction layer with `revision_has_more_commits()` and `revision_peek_next_commit()` functions, which should make the graph code more robust against future changes to the revision walker. Patch 3/3 implements the actual indentation logic, now using these new abstraction functions.

The series appears well-crafted and addresses the architectural concerns raised in v5. The new abstraction layer is particularly important as it future-proofs the code against Jeff King's planned removal of `revs->commits`. Test coverage looks thorough with a new dedicated test file (t4218) and updates to existing tests. The known edge case with lookahead limitations is documented with a NEEDSWORK comment, but the core functionality seems sound.

This version looks like a significant step forward and appears ready for final review, especially from Jeff King and Kristofer Karlsson who raised the architectural concerns in v5. The series seems likely to be merged once any remaining review feedback is addressed.
