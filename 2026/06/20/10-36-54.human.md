This is the first patch in Tian Yuchen’s six-part performance series optimizing `paint_down_to_common()` for one-sided histories, but it is authored by Kristofer Karlsson and sent via GitGitGadget. It refactors the `ahead_behind()` helper to stop using the shared `nonstale_queue` abstraction, replacing it with a plain `prio_queue` and a local `max_nonstale` pointer. The change is purely preparatory: it decouples the ahead/behind logic from the non-stale tracking machinery so that later patches can introduce a `paint_queue` struct that tracks per-side commit counts. There is no behavior change, and the patch touches only `commit-reach.c`. The commit message is clear and the diff is clean, making this a straightforward refactoring step toward the series’ larger goal.
