This is the fourth patch in Tian Yuchen’s six-patch series optimizing `paint_down_to_common()` for one-sided histories. It adds 111 lines of test coverage to `t/t6600-test-reach.sh`, exercising four edge cases that the side-exhaustion optimization must handle correctly: a commit that is both the query tip and one of the merge-base candidates (`in_merge_bases_many:self`), duplicate entries in the input list (`get_merge_bases_many:duplicate-twos`), the STALE-paint transition on an already-painted commit (`get_merge_bases_many:pending-stale`), and a scenario where both tips lie outside the commit-graph and have non-monotonic dates (`get_merge_bases_many:infinity-both-sides`).

The patch is authored by Elijah Newren and co-signed by Kristofer Karlsson, reflecting prior feedback and test-case contributions from Elijah’s parallel work (PR #2150). The test topologies are carefully constructed to trigger specific code paths: the `ps-*` diamond topology forces the (PARENT1|PARENT2) → (PARENT1|PARENT2|STALE) transition, while the `pi-*` topology ensures the INFINITY-gate activates when both tips lack generation numbers. Each test case feeds input to `test_all_modes`, which verifies the optimization behaves identically across all reachability backends (commit-graph, full history, and no commit-graph).

This is a substantive, tested review contribution: the tests are narrowly targeted at the new early-exit logic introduced in patch 3, and the commit message explains the rationale for each topology. The patch itself is mechanical—no code changes, only test scaffolding—but the value lies in the thoroughness of the edge-case coverage, which should help reviewers assess whether the halt condition in patch 3 is both correct and sufficiently general.
