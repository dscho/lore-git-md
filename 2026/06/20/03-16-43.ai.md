This is the third patch in the v6 series introducing standardized path formatting for `git repo info`. It adds two new fields—`path.commondir.absolute` and `path.commondir.relative`—to expose the repository’s common directory in both canonical and relative formats, addressing a gap where scripts working with worktrees had no reliable way to discover this path.

The implementation is straightforward: it adds two new getter functions (`get_path_commondir_absolute` and `get_path_commondir_relative`) that call the shared `append_formatted_path()` helper introduced in patch 1/4, passing the appropriate `path_format` enum value. The functions handle error cases (e.g., `repo_get_common_dir()` returning NULL) and integrate cleanly into the existing `repo_info_field` array. Documentation updates in `git-repo.adoc` describe the new fields, and the test suite verifies both absolute and relative paths in standard repositories, shared setups (via `GIT_COMMON_DIR`), and edge cases like `GIT_DIR`-only overrides.

The patch is well-motivated and technically sound. The design aligns with earlier maintainer feedback requiring explicit `.absolute`/`.relative` variants rather than a single default field, and the implementation reuses the shared helper introduced earlier in the series. Test coverage is thorough, including worktree-relevant scenarios like environment variable overrides. No new symbols are exposed outside the translation unit, and the changes are isolated to `builtin/repo.c` and its documentation. This patch is ready for integration and should graduate to `next` alongside the rest of the series.
