This is a CI/platform-compatibility discussion about the recurring macOS CI job hangs on GitHub Actions.

Michael Montalbo identifies the likely culprit: the `t5551` and `t5559` tests under the `EXPENSIVE` flag. The jobs that finish (reftable and meson builds) differ from the ones that hang (clang and gcc) in two key ways: the reftable backend advertises 100,000 refs much faster than loose refs, and the meson build uses all available CPU cores for parallel testing instead of a fixed `--jobs=10` on a 3-core runner. The hangs manifest as an HTTP/2 flow-control stall in `upload-pack`, where the process blocks indefinitely on `write()` during the `ls-refs` advertisement.

Montalbo proposes a two-part fix in a test branch: packing the refs in `t5551` to avoid re-reading 100,000 loose files, and using the actual core count for parallel jobs on macOS runners. He reports that eight test runs with these changes all finished in 30–44 minutes instead of hanging. The fix is narrowly targeted at the CI environment and does not change the wire protocol or the test’s intent. If this holds up, it could resolve a long-standing flakiness that has been a thorn in the project’s CI reliability.
