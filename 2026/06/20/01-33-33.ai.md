This is Junio C Hamano’s "What’s cooking in git.git" report for June 2026 (#07), summarizing the state of integration branches and in-flight topics as the Git 2.55 release cycle winds down. The tree is now feature-frozen; only regression fixes and review-ready topics will graduate to `master` before the final release.

Key technical highlights likely to surface in follow-up discussion:

- **New `git refs` subcommands** (Patrick Steinhardt): `git refs create|delete|update|rename` now exist as low-level plumbing counterparts to `git branch` and `git tag`. These are part of the ongoing ref-backend refactoring and will be referenced by name in future patches touching reference creation or deletion.

- **`git cat-file --batch-command` gains `remote-object-info`** (Patrick Steinhardt): Clients can now request object metadata (currently only size) from a remote server without downloading the object. The feature is gated by a dynamic allow-list that filters format placeholders based on server-advertised capabilities (`object-info`). Expect discussion around additional metadata (type, mtime, etc.) and security implications of exposing more fields.

- **`git history squash` and `git history drop`** (Hannes Nägele & Patrick Steinhardt): The experimental `git history` command now supports folding a range of commits into a single commit (`squash`) and removing a commit while replaying its descendants (`drop`). Both subcommands reuse the sequencer machinery and will be referenced in sequencer-related threads.

- **`git log -L` learns `--stat`, `--check`, and `-G`** (Matthias Aßhauer): The line-log machinery now limits diff operations to the specified range:path, avoiding unnecessary work on unrelated hunks. The new behavior is controlled by the same diff machinery used by `git diff` and `git show`, so expect follow-up patches that touch diffcore or pickaxe.

- **`git branch --delete-merged`** (Hannes Nägele): The new option removes local branches already merged into their upstream. It introduces a per-branch opt-out (`branch.<name>.deleteMerged`) and a `--dry-run` flag. Likely points of contention: whether to default to `--force` and how to handle symref aliases.

- **`git checkout --track=...` learns `--fetch`** (Hannes Nägele): When creating a new tracking branch, the command can now optionally fetch the start-point from the remote. This touches the same code paths as `git switch --track` and `git fetch`, so expect discussion around fetch configuration and error handling.

- **`diff.<driver>.process`** (Matthias Aßhauer): A new configuration allows an external long-running process to act as a hunk provider, letting tools like language servers control which lines Git considers changed. The feature is gated by a new `userdiff` config key (`diff.<driver>.process`) and will be referenced in threads about external diff tools or blame.

- **`fetch.followRemoteHEAD`** (Michael Haggerty): The new configuration variable provides a default for `remote.<name>.followRemoteHEAD`, controlling whether `git fetch` updates `FETCH_HEAD` to the remote’s HEAD. This is a small but user-visible change that may generate discussion around backward compatibility and default behavior.

- **Windows CI migration away from Chocolatey** (Patrick Steinhardt): The GitLab CI pipeline now installs dependencies without Chocolatey, addressing reliability issues. This is a build-system change that will be referenced in future CI-related patches.

- **`core.ignorecase`, `core.filemode`, and `core.protectHFS/NTFS` migrated to `repo_config_values`** (Tyler Yep): These repository-scoped configuration variables are now tied to a specific repository instance, continuing the effort to eliminate global state. Expect follow-up patches that touch repository initialization or configuration parsing.

- **`git replay --linearize`** (Toon Claes): The new option drops merge commits and linearizes the replayed history, mimicking `git rebase --no-rebase-merges`. This is part of the ongoing `git replay` effort and will be referenced in sequencer-related threads.

- **`git multi-pack-index write --incremental --base`** (Taylor Blau): The command now correctly honors the `--base` option, fixing a reachability closure bug for bitmaps. This touches the same code paths as `git repack` and `git pack-objects`, so expect discussion around bitmap correctness and performance.

- **`git branch` and `git tag` prefix-scoped iteration** (Tao Klerks): Both commands now pass the namespace prefix when initializing their ref iterator, avoiding a loose-ref scaling regression in repositories with many unrelated loose references. This is a small but important performance fix that will be referenced in threads about loose-ref iteration or namespace handling.

- **`git log --graph` root commit indentation** (Patrick Steinhardt): Root commits (and commits that become roots due to history simplification) are now visually indented to prevent them from appearing falsely related to unrelated commits rendered immediately above them. This is a small but user-visible change that may generate discussion around graph aesthetics and backward compatibility.

- **`git config` documentation fixes** (Tao Klerks & others): Various AsciiDoc markup fixes ensure lists and formatting are rendered correctly. These are documentation-only changes that will not generate technical discussion but may be referenced in threads about documentation style or tooling.

- **`git describe` tag iteration** (Tao Klerks): The command now passes the `refs/tags/` prefix down to the ref iterator when `--all` is not requested, avoiding unnecessary iteration over non-tag refs. This is a small performance fix that will be referenced in threads about ref iteration or `git describe` behavior.

- **`git ls-files --modified` and `--deleted` pathspec prefilter** (Tao Klerks): Both options now filter with pathspec before calling `lstat()` when there is only a single pathspec item, avoiding unnecessary filesystem access. This is a small performance fix that will be referenced in threads about `git ls-files` or pathspec handling.

- **`git fetch` follow-remote-head configuration** (Michael Haggerty): The new `fetch.followRemoteHEAD` configuration variable provides a default for the per-remote `remote.<name>.followRemoteHEAD` setting, controlling whether `git fetch` updates `FETCH_HEAD` to the remote’s HEAD.
