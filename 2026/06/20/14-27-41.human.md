This is the maintainer’s reply to the first patch in a GSoC series that introduces a shared path-formatting helper. The series aims to eliminate duplicated logic in `rev-parse` and `git repo info` by consolidating path formatting into a new `append_formatted_path()` function in `path.c`.

Junio’s concern is structural: the patch adds 99 lines of new code without removing any existing code or demonstrating that the helper can replace the logic it’s meant to consolidate. He suggests the series should start by refactoring existing code to use the new helper, proving it’s capable of reproducing current behavior before exposing it for new use cases. This would ensure the helper is both sufficient and bug-compatible with the existing implementation.

The thread context confirms this is the final design after substantive review, but Junio’s feedback indicates the *order* of patches may need adjustment. The helper itself is well-structured, with clear documentation and robust error handling, but the series currently introduces it as unused infrastructure rather than as a direct replacement for existing logic. No technical flaws in the implementation are raised—this is purely about patch organization and proving the helper’s correctness through immediate use.
