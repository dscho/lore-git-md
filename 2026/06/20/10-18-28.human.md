This is the second patch in Pablo Sabater’s v6 series implementing cascading indentation for `` `git log --graph` ``. The patch introduces a clean abstraction layer in `revision.c` that lets the graph renderer peek ahead at pending commits without depending on the internal `revs->commits` linked list. That list is slated for removal, so this insulation future-proofs the code. The implementation is minimal—two new functions, `revision_peek_next_commit()` and `revision_has_commits_after()`, that dispatch based on the walk mode (topological vs linear) and handle visibility filtering. The patch itself is small, touches only `revision.c` and `revision.h`, and does not change any existing behavior; it simply provides the infrastructure the next patch will use.

The series’ main architectural blocker is now resolved. Earlier versions were rejected because `graph.c` directly accessed `revs->commits`, which Jeff King plans to remove. This patch follows Kristofer Karlsson’s proposal and appears to be exactly the lightweight solution the thread was looking for. The only remaining technical question is whether Phillip Wood will confirm that the abstraction sufficiently insulates `graph.c` from `revision.c` internals.
