This is the third patch in a four-patch GSoC series that adds standardized path formatting to `git repo info`. The series is now technically complete and ready for merging, with all design feedback incorporated in earlier iterations.

This patch introduces two new fields to `git repo info`: `path.commondir.absolute` and `path.commondir.relative`. These expose the repository’s common directory (the shared `.git` directory containing objects, refs, and global configuration) in both canonical absolute and relative-to-current-directory formats. The implementation reuses the `append_formatted_path()` helper introduced in patch 1/4, eliminating the need for duplicated path-formatting logic.

The motivation is clear: scripts working with worktree setups currently have no way to discover the common directory, which diverges from the git directory when multiple worktrees are in use. The design follows Git’s philosophy of explicit over implicit for plumbing commands, as confirmed by maintainer Junio C Hamano in earlier feedback. By providing both `.absolute` and `.relative` variants, the patch avoids ambiguity for scripts that require predictable output.

The patch touches three files: `Documentation/git-repo.adoc` (documentation for the new fields), `builtin/repo.c` (the implementation), and `t/t1900-repo-info.sh` (comprehensive test coverage). The test helper `test_repo_info_path` verifies both absolute and relative paths in standard repositories, with environment overrides (`GIT_COMMON_DIR` and `GIT_DIR`), and edge cases like bare repositories. The implementation is robust, handling NULL common directory cases and preserving backward compatibility.

This is a well-crafted, thoroughly reviewed contribution that addresses a real gap in Git’s scripting interface. The patch is uncontroversial and ready for maintainer pickup.
