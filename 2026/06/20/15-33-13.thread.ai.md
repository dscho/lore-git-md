Subject: macOS CI hang in t5551/t5559 – root cause and fix
Series version: v1 (3-patch series from Jeff King)
Originating author: Michael Montalbo (initial report), Jeff King (patch author)
Thread type: bug report with proposed fix

Core problem or goal
Git’s CI jobs on GitHub’s macOS and Linux runners fail due to hangs or protocol errors in the `t5551` and `t5559` tests during an `ls-refs` advertisement of 100,000 loose refs. The root cause is **Apache’s `mod_http2` bug 70131**, which triggers either a mid-transfer abort (`curl 18`) or an indefinite HTTP/2 stall when the server-side 300-second timeout is hit. The goal is to eliminate these failures by addressing the underlying timeout or protocol issue through a combination of test optimizations and Apache configuration adjustments.

Current status
The **3-patch series by Jeff King has been fully implemented and is ready for final review**. The series directly addresses the root cause by **increasing Apache’s `Timeout` directive from 300 to 600 seconds** in `t/lib-httpd/apache.conf` (patch 1/3), a change endorsed by Junio C Hamano, Patrick Steinhardt, and Peff. This is paired with two complementary optimizations: **isolating the expensive test case into its own repository** (`t5551: put many-tags case into its own repo`, patch 2/3), reducing runtime for subsequent tests, and **packing refs after creating many tags** (`t5551: pack refs after creating many tags`, patch 3/3), which reduces `ls-refs` advertisement time from ~1.2 seconds to 24 ms. Peff now **explicitly questions the necessity of the third patch**, noting that the timeout increase alone resolves the immediate CI failures and that the ref-packing optimization may not justify its maintenance overhead. The series is **expected to be merged quickly**, with the first two patches uncontroversial and the third likely to be dropped if reviewers agree it is redundant.

Key technical details
- Files touched: `t/lib-httpd/apache.conf` (Apache `Timeout` directive), `t/t5551-http-fetch-smart.sh` (test isolation and ref-packing logic), `.github/workflows/main.yml` (CI configuration, though no changes are made in this series).
- Subsystems: test suite, CI configuration, HTTP/2 and HTTP/1.1 transport, libcurl, Apache `h2_mod` and `mod_cgi`, timeout handling.
- New behavior:
  - Apache’s `Timeout` directive increased from 300 to 600 seconds (patch 1/3), directly addressing the root cause of CI hangs.
  - The `t5551` many-tags test case now runs in an isolated repository (patch 2/3), reducing runtime for the entire test script from ~2.7 seconds to ~1.9 seconds (normal runs) and from ~95 seconds to ~37 seconds (EXPENSIVE runs).
  - Refs are packed after creating many tags (patch 3/3), reducing `ls-refs` advertisement time from ~1.2 seconds to 24 ms on macOS.

  - Failure modes:
    - HTTP/1.1 (`t5551`): `curl 18 transfer closed with outstanding read data remaining` (mid-transfer abort).
    - HTTP/2 (`t5559`): indefinite stall (hang).
- On-disk format: none.
- Test coverage: `t5551`, `t5559` (expensive tests).
- Related precedent: commit 8f2146dbf1 (HTTP/2 flow-control stall fix), Apache bug 70131.
