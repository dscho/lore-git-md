Subject: macOS CI hang in t5551/t5559 – root cause and fix
Series version: v1 (2-patch series from Jeff King)
Originating author: Michael Montalbo (initial report), Jeff King (patch author)

Core problem or goal
Git’s CI jobs on GitHub’s macOS and Linux runners fail due to hangs or protocol errors in the `t5551` and `t5559` tests during an `ls-refs` advertisement of 100,000 loose refs. The root cause is **Apache’s `mod_http2` bug 70131**, which triggers either a mid-transfer abort (`curl 18`) or an indefinite HTTP/2 stall when the server-side 300-second timeout is hit. The goal is to eliminate these failures by addressing the underlying timeout or protocol issue through a combination of test optimizations and Apache configuration adjustments.

Current status
The **2-patch series by Jeff King is ready for merging**. The series consists of: (1) **increasing Apache’s `Timeout` directive from 300 to 600 seconds** in `t/lib-httpd/apache.conf`, directly addressing the root cause of CI hangs, and (2) **isolating the expensive test case into its own repository** (`t5551: put many-tags case into its own repo`), reducing runtime for subsequent tests. The ref-packing optimization (originally proposed as patch 3/3) was dropped by consensus as redundant after the timeout increase and test isolation resolved the immediate CI failures.

Key technical details
- Files touched: `t/lib-httpd/apache.conf` (Apache `Timeout` directive), `t/t5551-http-fetch-smart.sh` (test isolation logic).
- Subsystems: test suite, CI configuration, HTTP/2 and HTTP/1.1 transport, libcurl, Apache `h2_mod` and `mod_cgi`, timeout handling.
- New behavior:
  - Apache’s `Timeout` directive increased from 300 to 600 seconds (patch 1/2), directly addressing the root cause of CI hangs.
  - The `t5551` many-tags test case now runs in an isolated repository (patch 2/2), reducing runtime for the entire test script from ~2.7 seconds to ~1.9 seconds (normal runs) and from ~95 seconds to ~37 seconds (EXPENSIVE runs). The isolated repository is initialized as a non-bare repository, unlike other test repositories in the script, but this difference is cosmetic and does not affect behavior.

  - Apache `h2_mod` and `mod_cgi`: default `Timeout 300` was being hit; logs showed `AH01220: Timeout waiting for output from CGI script` and `AH00574: ap_content_length_filter: apr_bucket_read() failed`.
