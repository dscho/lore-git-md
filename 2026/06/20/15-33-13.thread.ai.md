Subject: macOS CI hang in t5551/t5559 – root cause and fix
Series version: none (standalone patch)
Originating author: Michael Montalbo
Thread type: bug report with proposed fix

Core problem or goal
Git’s CI jobs on GitHub’s macOS runners frequently time out because the `t5551` and `t5559` tests hang during an `ls-refs` advertisement of 100 000 loose refs. The hang is an HTTP/2 flow-control stall that occurs only on GitHub’s virtualized macOS environment, not on bare-metal macOS or Linux. The goal is to eliminate the timeout by reducing the test’s wall-clock time and aligning the CI job’s parallelism with the runner’s actual core count.

Current status
Proposed fix is implemented on a test branch (`mm/macos-ci-hang-fix`) off `master`; eight `EXPENSIVE` runs completed in 30–44 minutes (down from 360-minute timeout). No maintainer decision yet; patch offered for review.

Key technical details
- Files touched: `t/t5551-protocol-v2.sh` (pack the 100 000 refs), `.github/workflows/main.yml` (set `$JOBS` to actual core count on GitHub macOS runners).
- Subsystems: test suite, CI configuration.
- New behavior: `t5551`’s enormous-ref-negotiation test now advertises packed refs (24 ms vs 1.2 s on macOS), `$JOBS` on GitHub macOS runners matches the runner’s actual core count.
- On-disk format: none.
- Test coverage: `t5551`, `t5559` (expensive tests).
