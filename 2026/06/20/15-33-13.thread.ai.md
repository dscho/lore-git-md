Subject: macOS CI hang in t5551/t5559 – root cause and fix
Series version: none (standalone patch)
Originating author: Michael Montalbo
Thread type: bug report with proposed fix

Core problem or goal
Git’s CI jobs on GitHub’s macOS and Linux runners fail due to hangs or protocol errors in the `t5551` and `t5559` tests during an `ls-refs` advertisement of 100,000 loose refs. The root cause is **Apache’s `mod_http2` bug 70131**, which triggers either a mid-transfer abort (`curl 18`) or an indefinite HTTP/2 stall when the server-side 300-second timeout is hit. The goal is to eliminate these failures by addressing the underlying timeout or protocol issue through a combination of test optimizations and Apache configuration adjustments.

Current status
A **consensus has emerged** among maintainers and reviewers (Junio C Hamano, Jeff King, Patrick Steinhardt) to **increase Apache’s `Timeout` directive** (e.g., from 300 to 600 seconds) as the primary fix for the CI failures. This approach directly addresses the root cause—Apache’s 300-second timeout being hit during slow `ls-refs` advertisements—while avoiding client-side workarounds that merely mask flakes. Jeff King’s latest email solidifies this consensus, providing timing data that shows cold-cache `upload-pack` advertisements of 100,000 loose refs take nearly 10 seconds on a local SSD, explaining why CI runners under I/O pressure consistently hit the timeout. The exact timeout value remains under discussion (Peff suggests 600 seconds as a "fine mitigation"), but the approach is now the leading candidate. **Ref-packing** (Michael Montalbo’s earlier optimization) is now endorsed as a complementary optimization that reduces timeout risk while improving test efficiency. The series is at the **finalization stage**: the technical direction is agreed, and the remaining work is to settle on the timeout value and integrate both changes into the test environment.

Key technical details
- Files touched: `t/lib-httpd.sh` (Apache `Timeout` directive adjustment), `t/t5551-protocol-v2.sh` (ref-packing logic), `.github/workflows/main.yml` (CI configuration).
- Subsystems: test suite, CI configuration, HTTP/2 and HTTP/1.1 transport, libcurl, Apache `h2_mod` and `mod_cgi`, timeout handling.
- New behavior:
  - Apache’s `Timeout` directive increased from 300 to a value between 600 and 3600 seconds (exact value pending; Peff proposes 600).
  - `t5551`’s enormous-ref-negotiation test now advertises packed refs (24 ms vs 1.2 s on macOS), reducing timeout risk.
  - `$JOBS` on GitHub macOS runners matches the runner’s actual core count (already implemented).
- Environment details:
  - libcurl: 8.6.0 (GitHub) vs 8.7.1 (GitLab); bug persists across versions.
  - macOS build image: 14 (GitHub) vs 15 (proposed).
  - Linux CI: failures now observed, logs truncated; same Apache bug suspected.
  - Apache `h2_mod` and `mod_cgi`: default `Timeout 300` is being hit; logs show `AH01220: Timeout waiting for output from CGI script` and `AH00574: ap_content_length_filter: apr_bucket_read() failed`.
  - Upstream Apache bug 70131: confirmed as the source of hangs/stalls; affects both HTTP/1.1 (`t5551`) and HTTP/2 (`t5559`); reproducible without Git.
  - Timing data: cold-cache `upload-pack` advertisement of 100,000 loose refs takes ~10 seconds on a local SSD; warm-cache or packed-ref scenarios complete in <0.5 seconds.
  - Failure modes:
    - HTTP/1.1 (`t5551`): `curl 18 transfer closed with outstanding read data remaining` (mid-transfer abort).
    - HTTP/2 (`t5559`): indefinite stall (hang).
- On-disk format: none.
- Test coverage: `t5551`, `t5559` (expensive tests).
- Related precedent: commit 8f2146dbf1 (HTTP/2 flow-control stall fix), Apache bug 70131.

Open questions and loose ends
- **Exact timeout value**: The Apache `Timeout` directive needs to be set to a value that balances reliability and practicality (Peff proposes 600 seconds; Michael tested 3600 but suggested 5–10 minutes as reasonable).
- **Linux CI specifics**: Exact error and conditions for Linux failures remain unclear due to truncated logs; whether the same Apache bug is being hit is unconfirmed but suspected.
- **Implementation details**: No concrete patch has been proposed yet for the timeout adjustment in `t/lib-httpd.sh`; integration with ref-packing logic is pending.
- **Upstream Apache fix**: No timeline for a fix to Apache bug 70131; the Git project’s willingness to wait for upstream remains unresolved, but the consensus is to proceed with the timeout adjustment regardless.
