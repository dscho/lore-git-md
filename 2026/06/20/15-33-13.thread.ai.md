Subject: macOS CI hang in t5551/t5559 – root cause and fix
Series version: none (standalone patch)
Originating author: Michael Montalbo
Thread type: bug report with proposed fix

Core problem or goal
Git’s CI jobs on GitHub’s macOS runners frequently time out because the `t5551` and `t5559` tests hang during an `ls-refs` advertisement of 100 000 loose refs. The hang is an HTTP/2 flow-control stall that occurs only on GitHub’s virtualized macOS environment, not on bare-metal macOS or Linux. The goal is to eliminate the timeout by addressing the underlying stall, either by reducing the test’s wall-clock time or by resolving the environmental factors causing the deadlock.

Current status
The proposed fix (packing refs and aligning `$JOBS` with runner core count) is implemented on `mm/macos-ci-hang-fix` and reduces CI runtime from a 360-minute timeout to 30–44 minutes. However, **maintainer-level skepticism** has emerged: Jeff King (Peff) and Junio C Hamano both **substantively question** whether the fix eliminates the underlying HTTP/2 deadlock risk or merely masks it. Patrick Steinhardt diagnosed a **libcurl version mismatch** (8.6.0 on GitHub runners vs 8.7.1 on GitLab) and suggested updating the macOS build image to version 15 as a potential mitigation. No maintainer decision yet; the patch remains under review, with root-cause analysis ongoing and environment version checks now prioritized.

Key technical details
- Files touched: `t/t5551-protocol-v2.sh` (pack the 100 000 refs), `.github/workflows/main.yml` (set `$JOBS` to actual core count on GitHub macOS runners).
- Subsystems: test suite, CI configuration, HTTP/2 transport.
- New behavior: `t5551`’s enormous-ref-negotiation test now advertises packed refs (24 ms vs 1.2 s on macOS), `$JOBS` on GitHub macOS runners matches the runner’s actual core count.
- Environment details: libcurl 8.6.0 (GitHub) vs 8.7.1 (GitLab), macOS build image version 14 (GitHub) vs 15 (proposed).
- On-disk format: none.
- Test coverage: `t5551`, `t5559` (expensive tests).
- Related precedent: commit 8f2146dbf1 (HTTP/2 flow-control stall fix).

Open questions and loose ends
- **Maintainer acceptance**: Junio and CI maintainers have not yet weighed in on merging the patch.
- **Environment resolution**: Whether updating libcurl and the macOS build image will resolve the stall or merely mask it.
- **Root cause**: Is the hang due to a bug in Git’s curl usage, curl itself, or Apache’s h2_mod?
- **Alternative approaches**: None yet proposed beyond the existing fix and environment updates.
