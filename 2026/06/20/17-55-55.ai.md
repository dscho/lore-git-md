This is the first patch in Zakariyah Ali’s v3 shell completion series. It implements the core behavior change—hiding dotfiles by default—specifically for `git rm`, `git mv`, and `git ls-files`, while preserving explicit dotfile completion (e.g., `git rm .` still completes to `.gitignore`).

The patch modifies the `__git_index_files` and `__git_complete_index_file` helpers in `contrib/completion/git-completion.bash` to accept a new optional `hide-dotfiles` parameter. When this parameter is passed and the current path component is empty, the AWK processing filters out any path whose first component starts with a dot. The three commands (`git rm`, `git mv`, `git ls-files`) are updated to pass this parameter, and the test suite (`t/t9902-completion.sh`) is adjusted to reflect the new behavior: dotfiles no longer appear in empty-path completion, but remain completable when the path starts with a dot. The four TODO comments from 2013 are removed.

This patch is the targeted, uncontroversial half of the series. It directly addresses Junio C Hamano’s feedback from v2 by implementing the behavior change in a focused way, without yet extending it to all path completion contexts (that is the job of the second patch). The implementation is clean, the tests are thorough, and the commit message clearly explains the motivation and the alignment with shell conventions. For reviewers, this patch is the easier lift: it is self-contained, well-tested, and conceptually approved.
