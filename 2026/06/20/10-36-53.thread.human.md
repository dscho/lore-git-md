This thread is about a performance optimization for Git’s merge-base calculation, specifically the `paint_down_to_common()` function in the commit-reach subsystem. The series, now in its third iteration (v3), is a post-merge follow-up—all patches from v2 are already merged, and this version adds cleanup, hardening, instrumentation, and documentation. The core optimization, introduced in this patch (7/8), terminates the merge-base walk early when one side’s commit queue is exhausted, yielding **100-1000x speedups** for asymmetric queries, such as those involving import grafts or shallow histories.

The key contributors are Tian Yuchen (the series author), Kristofer Karlsson (who co-authored test cases and added the technical documentation), and Derrick Stolee (who provided detailed review feedback). Elijah Newren contributed edge-case test cases, and Junio C Hamano, the maintainer, endorsed the technical documentation as clear and well-written. The optimization itself is low-risk: it gates the early-exit condition on the finite-generation region (where topological ordering is reliable) and widens a BUG assertion to enforce correct generation ordering. Performance is validated via trace2 step-count instrumentation, with benchmarks showing dramatic reductions in steps (e.g., 72,264 → 44,589 for a large query in `git.git`).
