This thread is about a performance optimization for Git’s `paint_down_to_common()` function, which calculates merge bases between commits. The series, now at version 8, is authored by Tian Yuchen and co-developed with Kristofer Karlsson. It introduces an early-termination optimization that skips unnecessary traversal when one side of a merge-base query exhausts its commit queue, yielding 100-1000x speedups for asymmetric histories (e.g., repositories with import grafts or shallow histories).

The series is technically complete and fully reviewed, with Junio Hamano having queued it in his integration tree. The core change—early termination when one side of the history is exhausted—is hardened against clock-skew edge cases and instrumented with Trace2 step counters for observable performance measurement. The refactoring replaces the old `max_nonstale` pointer logic with a `paint_state` struct and explicit counters, improving clarity and maintainability. The commit-date ordering fallback has been removed entirely, replaced by a topological ceiling for v1 commit-graphs, which resolves long-standing correctness issues while preserving performance gains.

The only remaining task is editorial: updating the technical documentation to adopt "ordered" and "unordered" region terminology (replacing "finite" and "infinite") to better reflect the semantic boundary between regions where topological ordering holds and where it doesn’t. Kristofer Karlsson has also agreed to add a code comment in `paint_queue_get()` to document a critical ordering invariant—checking counters before decrementing to avoid premature termination—though this is purely for maintainability and not blocking.
