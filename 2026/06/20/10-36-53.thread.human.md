This thread is about optimizing Git’s `paint_down_to_common()` function to speed up merge-base calculations in repositories with one-sided histories, such as those with import grafts or shallow histories. The series, now at version 2, is authored by Tian Yuchen and has resolved all major design and technical feedback. The core change—early termination when one side of the commit queue is exhausted—has been endorsed by Derrick Stolee, a key reviewer, and is now finalized with a robust termination condition and a finite-generation guard to ensure correctness.

The only remaining open question is whether the finite-generation guard could activate earlier in edge cases like criss-cross merges or grafts, though this hasn’t been challenged yet. The series has also settled on using **hyperfine** to benchmark `git merge-base` performance and **trace2_data_intmax()** to measure commits walked, with tests and documentation reordered to appear before the optimization. Kristofer Karlsson, who co-authored the core patch, has agreed to these changes and will use hyperfine as the baseline for performance validation, reserving custom instrumentation for later if needed. The thread is now focused on finalizing v2 with these agreed-upon benchmarks.
