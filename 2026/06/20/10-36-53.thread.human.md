This thread is about a now-complete performance optimization series for Git’s `paint_down_to_common()` function, which computes merge bases. The series, authored by Tian Yuchen and co-developed with Kristofer Karlsson, achieves **100-1000x speedups** for asymmetric queries (e.g., repositories with import grafts or shallow histories) by terminating early when one side of the commit queue is exhausted. The final version (v8) is fully reviewed, procedurally unblocked, and queued in Junio’s tree.

Key changes include replacing the commit-date ordering fallback with pure generation-number ordering, introducing per-side counters (`parent1_count`, `parent2_count`) to track exclusive commits, and adding a `topo_ceiling` field to handle v1 commit-graph saturation. The series also includes a new technical document (`paint-down-to-common.adoc`) explaining the algorithm’s invariants, edge cases, and termination conditions, along with extensive test coverage for clock-skew, mixed-generation commits, and diamond topologies. Trace2 instrumentation now provides observable step counts (e.g., `paint_down_to_common steps 9` vs. `80` in git.git), replacing wall-clock benchmarks.

The final patch in the series, just posted by Kristofer Karlsson, removes the legacy commit-date fallback entirely. This cleanup was made possible by the side-exhaustion optimization, which reduces step counts far below the fallback’s performance (e.g., 5.7k steps for v1 graphs vs. 167k baseline). The patch simplifies the code by eliminating conditional queue ordering and updates the technical document to reflect the modern approach.
