This thread is about a performance optimization to Git’s `paint_down_to_common()` function, which speeds up merge-base calculations in repositories with asymmetric histories (such as those with import grafts or shallow histories). The series, now at version 8, is authored by Tian Yuchen and has been fully reviewed and approved by key contributors, including Elijah Newren, Derrick Stolee, and SZEDER Gábor. It is currently queued in Junio Hamano’s integration tree and is procedurally ready for advancement.

The optimization achieves **100-1000x speedups** in asymmetric queries by terminating early when one side of the merge-base calculation exhausts its commit queue. For example, in a 2.6-million-commit monorepo, the number of steps drops from 2.1 million to just 3. The series includes a new technical document (`Documentation/technical/paint-down-to-common.adoc`) that explains the algorithm, its invariants, and the "ordered/unordered region" terminology now used consistently across the codebase. It also removes the commit-date fallback entirely, replacing it with a topological ceiling for v1 commit-graphs, which further reduces step counts in large repositories like the Linux kernel.

The latest email in the thread adds a regression test (`t6099-merge-base-side-exhaustion.sh`) to verify that the side-exhaustion optimization correctly handles cases where multiple merge-base candidates exist, and one is an ancestor of another. The test ensures that the `remove_redundant()` safety net works as intended, returning only the shallowest candidate. This patch is a targeted addition with no code changes and addresses a prior review concern about edge-case coverage. The series as a whole is technically complete, with all open questions resolved, and is awaiting integration into the `next` branch.
