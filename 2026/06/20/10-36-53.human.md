This is a performance optimization targeting the merge-base machinery in Git’s commit-reach subsystem. Kristofer Karlsson proposes a six-patch series that teaches `paint_down_to_common()` to terminate early when one side of the walk has no more exclusive commits left to paint. The motivation is clear: repositories with large one-sided histories (e.g., imports that graft a separate root) currently force the walk to drain millions of commits even when no further merge-base candidates can appear. Benchmarks on a 2.6 M-commit monorepo show speed-ups of 400–700× for `git merge-base --all` and `git merge-tree` across such grafts, with no measurable regression on linux.git.

The series is well-structured: the first two patches refactor the existing code to introduce per-side counters and a dedicated paint queue, patch 3 implements the actual optimization, and patches 4–6 add regression tests and technical documentation. Elijah Newren independently discovered the same optimization and contributed test cases, which are incorporated in patch 4. The halt condition is carefully designed to trigger only after the walk enters the finite-generation region, ensuring correctness. The commit messages are detailed and include ASCII-art diagrams that clarify the problem and solution.

This looks like a serious, well-motivated contribution. The refactoring is clean, the behavior change is minimal and targeted, and the benchmarks are compelling. The series is part of an ongoing discussion (RFC thread and GitHub PR #2150), but the code is now concrete enough for review. If the design holds up under scrutiny, this could be a significant quality-of-life improvement for users working with repositories that have large, disjoint histories.
