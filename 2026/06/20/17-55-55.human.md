This is the first patch in Zakariyah Ali’s v3 shell completion series. It implements the core behavior change discussed in earlier rounds: hiding dotfiles (like `.gitignore`) by default during path completion for `git rm`, `git mv`, and `git ls-files`, while preserving explicit dotfile completion (e.g., `git rm .` still completes to `.gitignore`).

The patch modifies the `__git_index_files` and `__git_complete_index_file` helpers in `contrib/completion/git-completion.bash` to accept a new optional `hide-dotfiles` parameter. When this parameter is passed and the current path component is empty, the AWK processing filters out any path whose first component starts with a dot. The three commands are updated to pass `hide-dotfiles` when completing an empty path, and the test suite (`t/t9902-completion.sh`) is adjusted to verify both the default hiding and the explicit dot completion. The four TODO comments from 2013 are removed, as the expected behavior is now implemented.

This patch is a direct response to Junio C Hamano’s feedback on v2, where he approved the behavior change but asked for a cleaner implementation. The logic is now centralized in the helper functions, avoiding code duplication, and the test updates confirm the change works as intended. The patch is well-motivated, touches only the completion scripts and tests, and appears technically sound. If the second patch in the series (which extends this behavior to all path completion contexts) is equally clean, the series looks ready for merging.
