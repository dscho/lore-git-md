This is the first patch in the v6 series introducing a new `append_formatted_path()` helper in Git's path-handling code. The patch extracts the path-formatting logic previously hardcoded in `git rev-parse` into a reusable function in `path.c`, making it available to other commands like the upcoming `git repo info` enhancements.

The new helper supports four formatting modes via an enum: unmodified output, relative paths (to a given prefix), relative paths only if the path shares a root with the prefix, and fully canonicalized absolute paths. The implementation handles edge cases like relative path calculation, shared repository detection, and memory management through `strbuf` usage. A `BUG()` call guards against invalid enum values, ensuring robustness.

This is a refactoring patch that doesn't change any user-visible behavior but lays the foundation for the rest of the series. The commit message clearly explains the motivation—eliminating duplicated logic—and the code itself is cleanly structured with well-documented enum values. The patch touches only `path.c` and `path.h`, introducing the new function and its supporting enum without modifying existing APIs.

The series as a whole has undergone thorough review, and this patch reflects the final design consensus reached with Phillip Wood and Justin Tobler. It's a well-crafted piece of infrastructure work that aligns with Git's design principles.
