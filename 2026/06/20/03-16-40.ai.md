This is the v6 iteration of a GSoC feature series that teaches `git repo info` to output path-related fields (`gitdir` and `commondir`) in both absolute and relative formats. The series is now technically complete, with all design concerns resolved after substantive review from Phillip Wood, Justin Tobler, and others.

The core work introduces a new `append_formatted_path()` helper in `path.c` that standardizes path formatting logic previously duplicated in `rev-parse`. This helper supports four formatting modes (unmodified, relative, relative-if-shared, and canonical) and is now used by both `rev-parse` and `repo info`. The implementation preserves exact backward compatibility while eliminating ~80 lines of redundant code.

Key changes in v6 address Phillip Wood's final design refinement: the shared `path_format` enum no longer includes a `DEFAULT` variant, and `rev-parse`'s local enums remain untouched. Instead, `print_path()` in `rev-parse.c` now maps its existing enums to the shared ones internally. This keeps the API clean while avoiding leakage of `rev-parse`-specific concerns into the shared helper.

The series adds four new fields to `git repo info`:
- `path.commondir.absolute` (canonical path)
- `path.commondir.relative` (relative to current directory)
- `path.gitdir.absolute`
- `path.gitdir.relative`

Tests cover edge cases like shared repositories, worktrees, and environment overrides. The implementation aligns with Git's design philosophy of explicit over implicit for plumbing commands, as confirmed by maintainer Junio C Hamano in earlier feedback.

Files touched: `path.c`/`path.h` (new helper), `builtin/rev-parse.c` (refactor), `builtin/repo.c` (new fields), `Documentation/git-repo.adoc` (docs), and `t/t1900-repo-info.sh` (tests). New symbols: `append_formatted_path()` and `path_format` enum. The series is ready for maintainer pickup and graduation to `next`.
