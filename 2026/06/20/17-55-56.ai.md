This is the second patch in Zakariyah Ali’s v3 shell completion series, completing the effort to hide dotfiles by default in Git’s path completion. It extends the behavior introduced in the first patch (which targeted `git rm`, `git mv`, and `git ls-files`) to all path completion contexts by making dotfile hiding the default in the `__git_index_files` helper.

The patch removes the `hide-dotfiles` parameter from `__git_complete_index_file` and `__git_index_files`, simplifying the API: dotfiles are now always hidden unless the user explicitly types a leading dot (e.g., `git add .`). The AWK logic in `__git_index_files` is refactored to check the dotfile condition in a single place after path dequoting, eliminating the previous duplication. Callers no longer need to pass the `hide-dotfiles` flag, and the patch updates all invocations of `__git_complete_index_file` to match the new signature.

The test suite (`t/t9902-completion.sh`) is extended to verify that dotfiles are hidden by default but completable when explicitly requested (e.g., `git commit .` completes to `.gitignore`). The patch also removes the 2013 TODO comments from the test file, marking the resolution of this long-standing inconsistency.

This patch directly addresses Junio C Hamano’s feedback on code duplication and consistency, and it completes the alignment with shell conventions. The implementation is clean and well-tested, and the series now appears ready for merging. The only remaining open question is whether the behavior change needs explicit documentation, but that is a minor concern given the clear user-facing benefit.
