This is the sixth and likely final version of a Google Summer of Code patch series that teaches `git repo info` to output repository paths in both absolute and relative formats. The series introduces a new `append_formatted_path()` helper in `path.c` and refactors `git rev-parse` to use it, eliminating duplicated path-formatting logic while preserving exact backward compatibility.

The key change since v5 is a design refinement suggested by Phillip Wood: the shared `path_format` enum no longer includes a `PATH_FORMAT_DEFAULT` value, and `rev-parse` keeps its existing local enums (`format_type` and `default_type`) untouched. Instead, `print_path()` now maps these local enums to the shared `path_format` values internally. This keeps the shared API clean while avoiding leakage of `rev-parse`-specific concerns into the global path-formatting helper.

The series is now technically complete. It adds four new fields to `git repo info` output: `path.commondir.absolute`, `path.commondir.relative`, `path.gitdir.absolute`, and `path.gitdir.relative`. The implementation is well-tested, with coverage for edge cases like worktrees, shared repositories, and environment overrides. The commit messages are clear and the code is cleanly structured.

This looks like a solid contribution that addresses a real need (reliable, scriptable access to repository paths) without breaking existing behavior. The design has converged after several iterations of review, and the series is ready for maintainer pickup. If you care about repository introspection or plumbing commands, this is worth a look.
