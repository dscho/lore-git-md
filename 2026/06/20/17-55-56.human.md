This is the second patch in Zakariyah Ali’s v3 shell completion series, completing the effort to hide dotfiles by default in Git’s path completion. The patch makes dotfile hiding the default behavior in the `__git_index_files` helper, removing the need for callers to pass a `hide-dotfiles` flag. This extends the behavior introduced in the first patch (which targeted `git rm`, `git mv`, and `git ls-files`) to all path completion contexts, including `git add` and `git commit`.

The implementation is straightforward: the `__git_index_files` function now unconditionally hides dotfiles when no match pattern is provided, and the AWK logic is refactored to check for dotfiles in a single place after path dequoting. Callers like `_git_rm`, `_git_mv`, and `_git_ls_files` are updated to drop the now-redundant `hide-dotfiles` argument. Tests verify that dotfiles remain completable when explicitly requested (e.g., `git commit .` still completes to `.gitignore`).

This patch directly addresses Junio C Hamano’s feedback from earlier rounds, particularly the concern about inconsistent behavior across commands. By centralizing the logic in `__git_index_files`, the change ensures uniformity while keeping the code cleaner. The series now appears technically sound, with tests covering both the default hiding and explicit dotfile completion. The only remaining open question is whether the behavior change needs explicit documentation, but the patch itself is well-motivated and ready for review.
