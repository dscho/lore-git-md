This thread began with D. Ben Knoble’s patch to add a `nanosec` option to Meson, mirroring the Autotools `USE_NSEC` knob for sub-second file timestamp tracking. The patch was initially accepted but later withdrawn by Junio C Hamano as the discussion evolved into a broader re-evaluation of `USE_NSEC`’s necessity and configuration model. Jeff King’s testing showed that modern Linux filesystems (ext4, XFS, etc.) reliably preserve nanosecond timestamps, making the historical "racy Git" concerns obsolete, but interoperability risks emerged when mixing `USE_NSEC` and non-`USE_NSEC` implementations (e.g., Git and JGit).

The thread has now converged on an incremental path forward, proposed by Patrick Steinhardt and endorsed by Jeff King and Junio: replace the build-time `USE_NSEC` knob with a runtime config option (`core.useNsec`), always compile nanosecond support into Git when the platform supports it, and retain the current build-time default (`USE_NSEC` disabled) for backward compatibility. The `USE_NSEC` build knob will be deprecated and eventually removed once `core.useNsec` is implemented. Knoble’s latest email acknowledges Junio’s withdrawal of the original patch, confirming the shift to the runtime-configurable approach. The next step is a new patch series implementing `core.useNsec`, with open questions remaining about its default value, interaction with existing repositories, and platform coverage beyond Linux. The discussion has not addressed potential resistance from power users who rely on build-time configuration, but the runtime config approach aims to make the feature more accessible.
