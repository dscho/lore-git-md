This thread began as a simple patch to add a `nanosec` Meson build option mirroring Autotools' `USE_NSEC` for sub-second timestamp tracking. What started as a build system parity effort has evolved into a deeper debate about whether `USE_NSEC` should exist at all. The patch itself remains queued for merging, but the discussion has shifted to the technical viability and necessity of the knob.

Jeff King's recent testing has upended long-standing assumptions about `USE_NSEC`'s reliability. His work confirms that modern Linux filesystems (ext4, ext2, vfat, and even CIFS) preserve nanosecond timestamps correctly, contradicting historical concerns about "racy Git" issues on coarse-grained filesystems. Kernel fixes from 2015 appear to have resolved these problems, suggesting the knob may no longer be needed as a safety measure. However, Peff also uncovered a new consideration: interoperability risks when mixing Git implementations with different timestamp resolutions. While correctness is preserved, performance could degrade if a non-`USE_NSEC` Git (or JGit) writes an index that an `USE_NSEC`-enabled Git later reads—everything would appear stat-dirty, forcing unnecessary re-reads.

The thread now centers on three questions: Should `USE_NSEC` be deprecated? Should its default be flipped to `true`? Or should it remain as-is, given its minimal real-world usage?
