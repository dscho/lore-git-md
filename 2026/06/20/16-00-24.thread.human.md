This thread began with D. Ben Knoble’s patch to add a `nanosec` Meson build option that mirrors the existing Autotools and Makefile `USE_NSEC` knob, ensuring build system parity. The patch was reviewed, accepted, and queued for merging by Junio C Hamano, with only minor concerns about option discoverability resolved by Patrick Steinhardt.

The discussion took a substantive turn when Jeff King (Peff) raised a technical caution about `USE_NSEC`’s reliability on filesystems with coarse timestamp granularity or network filesystems like CEPH, CIFS, NTFS, and UDF. While Peff did not block the patch, he suggested that a deeper investigation could justify flipping the default in the future. Patrick Steinhardt’s latest reply questions whether the `nanosec` option should exist at all if `USE_NSEC` remains subtly broken on some filesystems. He argues that propagating a rarely-used or problematic knob to Meson adds no value and leans toward removing it entirely, though he acknowledges this goes beyond the original patch’s scope.

The thread now centers on whether `USE_NSEC` should be deprecated or investigated further, rather than just how to add the Meson option. The patch itself remains queued, but Patrick’s comments could reignite broader discussion about the knob’s future. For now, the key open question is whether the technical debt around `USE_NSEC` warrants revisiting its design or defaults.
