The thread started as a simple patch to add a `nanosec` Meson build option mirroring Autotools’ `USE_NSEC`, but it’s since grown into a broader debate about whether `USE_NSEC` itself is still useful—or even harmful. The original patch, by D. Ben Knoble, remains queued for merging, but the discussion has shifted to fundamental questions about the knob’s design and default behavior.

Jeff King’s testing showed that modern Linux filesystems reliably preserve nanosecond timestamps, making the historical "racy Git" concerns obsolete. However, he also highlighted a new problem: mixing `USE_NSEC` and non-`USE_NSEC` implementations (like Git and JGit) can cause performance-degrading stat-dirty re-reads. Brian M. Carlson proposed flipping the default to `true` for most users, with a config knob for overrides, but this risks breaking interoperability for edge cases.

Patrick Steinhardt now argues that the build-time option is the wrong approach entirely. Since filesystem behavior varies at runtime, not build time, he suggests removing the Meson option and treating `USE_NSEC` like `core.ignoreCase`: a runtime-configurable setting, ideally auto-detected during repository initialization. This would let Git enable nanosecond resolution by default on safe platforms while retaining a fallback for problematic ones. No one has submitted a patch yet, but the thread is now focused on whether the project prefers runtime flexibility or build-time simplicity.
