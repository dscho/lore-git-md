This thread began as a simple patch to add a `nanosec` Meson build option mirroring the existing Autotools `USE_NSEC` knob, which controls whether Git tracks sub-second file timestamps. What started as a build-system parity effort has grown into a broader discussion about the viability, necessity, and future of `USE_NSEC` itself.

The original patch by D. Ben Knoble remains queued for merging, but the conversation has shifted toward a more fundamental rethink. Jeff King’s testing showed that modern Linux filesystems (ext4, ext2, XFS, vfat, CIFS, NTFS, FUSE) reliably preserve nanosecond timestamps, undermining the historical "racy Git" concerns that originally motivated `USE_NSEC` as a safety measure. This finding sparked proposals to flip the default to `true`, deprecate the knob entirely, or make it runtime-configurable. The latest consensus leans toward Patrick Steinhardt’s incremental proposal: always compile nanosecond support into Git (when the platform allows) and expose it via a runtime config knob like `core.useNsec`, while keeping the build-time default disabled for now. Jeff King endorsed this approach and suggested eventually removing the `USE_NSEC` build knob entirely, arguing that runtime configuration makes it redundant.

Key participants remain divided on some details. Knoble still defends the original patch as a necessary parity measure for distributors like Gentoo, while Patrick and Peff see the build-time knob as increasingly unnecessary. Brian M. Carlson’s proposal to flip the default to `true` remains unresolved, as does the question of what the default for `core.useNsec` should be. Interoperability risks—such as mixing `USE_NSEC` and non-`USE_NSEC` implementations like Git and JGit—are acknowledged but not yet addressed in any concrete proposal. The next step is likely a patch implementing `core.useNsec`, followed by deprecation of the build-time knob. Until then, the original patch remains in limbo, awaiting either a broader consensus or a decision to proceed despite the open questions.
