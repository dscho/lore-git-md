This thread began with D. Ben Knoble’s patch to add a `nanosec` Meson build option mirroring the Autotools `USE_NSEC` knob, which controls whether Git tracks file timestamps with nanosecond precision. What started as a simple build-system parity effort has grown into a broader re-evaluation of `USE_NSEC` itself—its necessity, reliability, interoperability, and configuration model.

Jeff King’s testing showed that modern Linux filesystems (ext4, XFS, vfat, CIFS, NTFS, FUSE) reliably preserve nanosecond timestamps, undermining the original “racy Git” concerns that led to the knob’s creation. This finding sparked proposals to flip the default to `true` (Brian M. Carlson), deprecate the knob entirely (Patrick Steinhardt’s earlier stance), or make it runtime-configurable (Patrick’s latest proposal, now endorsed by Peff). The discussion has converged on an incremental path: always compile nanosecond support into Git when the platform allows it, expose it via a new `core.useNsec` runtime config knob, and deprecate the `USE_NSEC` build knob once the runtime mechanism is in place. Junio C Hamano has withdrawn the original patch from his integration tree, signaling that the next step is a patch series implementing `core.useNsec` and the deprecation plan.

Key questions remain unresolved: what should the default for `core.useNsec` be, how will it interact with existing repositories, and whether the added complexity of runtime configuration is justified. The original patch’s goal of build-system parity is now secondary to the larger design effort, and Knoble’s defense of the build-time knob for power users is at odds with the emerging consensus on deprecation. The thread is effectively paused, awaiting a new patch series that implements the runtime-configurable approach.
