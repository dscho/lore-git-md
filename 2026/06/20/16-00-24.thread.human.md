This thread began as a simple patch to add a `nanosec` Meson build option mirroring the Autotools `USE_NSEC` knob, but has evolved into a broader debate about the necessity, reliability, and interoperability of sub-second timestamp tracking in Git. The original patch by D. Ben Knoble remains queued for merging, but the discussion has shifted toward whether `USE_NSEC` should be enabled by default, deprecated, or removed entirely.

Jeff King’s testing demonstrated that modern Linux filesystems (ext4, ext2, vfat, CIFS) reliably preserve nanosecond timestamps, undermining the historical "racy Git" concerns that originally motivated the knob. However, he also identified interoperability risks when mixing `USE_NSEC` and non-`USE_NSEC` implementations (e.g., Git and JGit), which could degrade performance. Brian M. Carlson has now proposed flipping the default to `true` for most users, with a config knob to override it and a future `statfs`-based auto-detection mechanism for problematic filesystems. This approach prioritizes performance for the majority while retaining a fallback for edge cases, though it introduces platform-specific complexity.

The key participants are divided: Knoble’s patch achieves build system parity but lacks a clear rationale for the knob’s existence; Junio has accepted the patch without engaging in the deeper debate; Peff’s findings challenge the knob’s necessity but highlight interoperability trade-offs; Patrick Steinhardt has questioned whether the knob should exist at all; and Brian’s proposal shifts the focus toward flipping the default rather than deprecating it. No new patches have been submitted, and the thread remains open on whether the default should change, whether auto-detection is worth the complexity, and whether the knob should be a build-time or runtime setting. The original goal of Meson/Autotools parity is now overshadowed by these larger questions.
