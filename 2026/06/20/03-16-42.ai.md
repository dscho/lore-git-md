This is the second patch in the v6 series introducing standardized path formatting for Git commands. It refactors `builtin/rev-parse.c` to use the new `append_formatted_path()` helper introduced in patch 1/4, eliminating ~44 lines of duplicated path-formatting logic while preserving exact backward compatibility.

The patch replaces the body of `print_path()` with a simple mapping from `rev-parse`'s existing `format_type`/`default_type` enums to the shared `path_format` enum, then delegates the actual formatting to `append_formatted_path()`. The local enums and all call sites in `cmd_rev_parse()` remain unchanged, maintaining the existing API surface. This approach resolves Phillip Wood's design concern about avoiding leakage of `rev-parse`-specific concepts into the shared helper.

Key technical details:
- The mapping logic handles all four formatting cases (unmodified, relative, relative-if-shared, canonical) exactly as before
- Error handling and edge cases (like relative path calculation) are now handled by the shared helper
- The patch preserves the existing behavior where `FORMAT_DEFAULT` falls back to different formats based on `default_type`
- No new symbols are introduced; the patch only consumes the helper added in 1/4

This is a clean refactoring that demonstrates the value of the shared infrastructure while maintaining Git's design principle of explicit over implicit for plumbing commands. The implementation is straightforward and well-tested (covered by existing `t1090-*` tests), making it a low-risk change that delivers immediate code deduplication. The series is now technically complete and ready for maintainer pickup.
