This is the third and final patch in Pablo Sabater's v6 series implementing cascading indentation for visual roots in `git log --graph`. It contains the core visualization logic that was previously validated in v5 but is now protected by the abstraction layer introduced in patch 2/3.

The patch adds 271 lines to `graph.c` and a new 468-line test file (`t4218-log-graph-indentation.sh`) that thoroughly validates the new behavior. The implementation introduces several new concepts to the graph renderer: a `GRAPH_PRE_ROOT` state to connect indented visual roots to their children, an `is_visual_root` flag to identify commits that need indentation, and a `visual_root_depth` counter to handle cascading indentation when multiple visual roots appear consecutively. The lookahead mechanism (`graph_peek_next_visible`) attempts to detect upcoming visual roots to avoid redundant indentation, though it has a documented NEEDSWORK edge case with filtered parents.

Key technical details include:
- New state `GRAPH_PRE_ROOT` that prints an edge row to connect a child commit to its indented visual root parent
- Visual root detection logic that excludes merge parents (non-first parents of merges) and boundary commits
- Cascading indentation that increases by two characters per consecutive visual root
- Special handling for the last commit in the graph to avoid unnecessary indentation
- The documented limitation where filtered parents can cause redundant indentation due to lookahead timing issues

The test coverage is comprehensive, including cases for:
- Single visual roots vs unrelated branches
- Merge parents that shouldn't be indented
- Cascading indentation with multiple consecutive visual roots
- Edge cases with filtered parents (including the known limitation)
- Boundary commits (which correctly don't get indented)
- `--first-parent` filtering scenarios
- Complex merge structures with unrelated branches

The implementation appears technically sound and maintains the correct visualization behavior from v5 while now being insulated from revision.c's internal traversal model. The remaining NEEDSWORK item (filtered parent lookahead) is properly documented and has its own test case marked as `test_expect_failure`. This patch should be ready for final review, with Phillip Wood's pending review of the abstraction layer (patch 2/3) being the primary remaining blocker.
