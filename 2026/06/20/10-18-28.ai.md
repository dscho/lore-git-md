This is the second patch in Pablo Sabater's v6 series implementing cascading indentation for `git log --graph`. The patch introduces a clean abstraction layer in `revision.c` to insulate the graph code from the revision walker's internal data structures, specifically addressing the fragility of direct access to `revs->commits`.

The patch adds two new functions—`revision_peek_next_commit()` and `revision_has_commits_after()`—that allow `graph.c` to look ahead in the commit stream without knowing whether the commits are stored in a linked list (`revs->commits`) or a priority queue (`revs->topo_walk_info->topo_queue`). This abstraction directly resolves the architectural blocker that stalled earlier versions of the series, making the graph code robust against Jeff King's planned removal of `revs->commits`. The implementation is minimal and well-scoped, dispatching based on the walk mode (topological vs. linear) while correctly handling visibility filtering.

The patch itself is technically sound and ready for review. It touches only `revision.c` and `revision.h`, adding 38 lines of implementation and 10 lines of declarations, with no behavior changes—only the infrastructure needed for the subsequent visualization patch. The commit message clearly explains the motivation and design, and the code follows the lightweight approach proposed by Kristofer Karlsson. The only open question is whether Phillip Wood will confirm that the abstraction sufficiently insulates `graph.c` from `revision.c` internals, which is now the primary remaining blocker for the series.
