This is a CI/platform-compatibility investigation and proposed fix targeting the macOS GitHub Actions runners.

Michael Montalbo identifies the root cause of frequent macOS CI job timeouts: the `t5551` and `t5559` tests (part of the expensive test suite) reliably hang when run under GitHub’s macOS runners. The hang occurs during an `ls-refs` advertisement of 100,000 loose refs, where `upload-pack` blocks in `write()` and `curl` blocks in `select()`, suggesting an HTTP/2 flow-control stall that self-resolves on bare-metal macOS and Linux but not on GitHub’s virtualized runners.

The proposed fix has two parts: (1) pack the refs in `t5551`’s enormous-ref-negotiation test (reducing the advertisement time from ~1.2 s to ~24 ms on macOS) and (2) use the actual core count for `$JOBS` on GitHub macOS runners, matching the behavior already used by the meson build and the GitLab CI path. A test branch (`mm/macos-ci-hang-fix`) off `master` has been run eight times under `EXPENSIVE`; all runs finished in 30–44 minutes instead of timing out at 360 minutes. The patch is offered for review if the maintainers want to merge it.
