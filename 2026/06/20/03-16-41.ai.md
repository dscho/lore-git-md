This is the first patch in the v6 iteration of a GSoC feature series introducing a shared path-formatting helper. It adds `append_formatted_path()` to `path.c` and exposes the `path_format` enum in `path.h`. The helper standardizes path formatting logic previously duplicated in `rev-parse`, supporting four modes: unmodified, relative, relative-if-shared, and canonical.

The implementation is clean and well-structured, with clear documentation and robust error handling (a `BUG()` for invalid formats). The switch-based logic in `append_formatted_path()` mirrors the original `rev-parse` behavior while generalizing it for reuse. The patch touches only `path.c` and `path.h`, adding 99 lines of new code with no behavior changes—this is purely infrastructure for later patches in the series.

Thread context confirms this is the final design after substantive review, particularly Phillip Wood’s refinement to avoid exposing `DEFAULT` in the shared enum. The helper is now ready for use by both `rev-parse` and `git repo info` in subsequent patches. No controversies or unresolved concerns remain; this patch is a straightforward refactoring that lays the groundwork for eliminating ~80 lines of duplication.
