This is the fifth patch in Patrick Steinhardt’s 13-patch **refactoring** series to separate repository discovery from setup in Git’s core code. The patch introduces a new `struct repo_discovery` to hold the results of repository discovery (gitdir and worktree paths), replacing the current practice of partially configuring the repository object during discovery. This is a key step toward consolidating repository initialization into `repo_init()` and eliminating scattered setup logic.

The patch rewrites `setup.c` to split the discovery and setup phases cleanly. It replaces the old `setup_explicit_git_dir()`, `setup_discovered_git_dir()`, and `setup_bare_git_dir()` functions with new `repo_discover_*()` variants that populate a `struct repo_discovery` instead of directly configuring the repository. The main `setup_git_directory_gently()` function now uses this structure to defer all repository configuration until after discovery is complete. The changes are mechanical but foundational: they introduce no behavior changes but enable future patches to move more logic into the discovery phase.

The commit message is clear and well-structured, explaining both the problem (intermixed discovery and setup logic) and the solution (explicit discovery phase with a dedicated struct). The patch itself is focused and touches only `setup.c`, with no test or documentation changes. The new `struct repo_discovery` is minimal for now but is designed to be extended in later patches (e.g., to include prefix or repository format details).

This patch is a critical building block for the series’ goal of making repository setup more modular and self-contained. It looks well-crafted and aligns with Patrick’s long-term refactoring efforts (e.g., ODB abstraction, `the_repository` removal). Reviewers will likely focus on the API design of `struct repo_discovery` and whether the new function boundaries handle edge cases (e.g., environment variable overrides, bare repositories) correctly.
