This is the second patch in a two-patch bugfix series from Jeff King that plugs a memory leak in `git format-patch`. The leak occurs in the `prepare_bases()` function in `builtin/log.c`, where a `rev_info` struct allocated for a custom revision walk is not freed after use. The fix is a single-line addition of `release_revisions(&revs)` to properly clean up the struct.

The leak has been present since the `--base` option was added in 2016, but it only became detectable after other leaks were fixed, making this one stand out in LeakSanitizer (LSan) reports. The patch is low-risk and mechanical, touching only one line in a well-understood code path. Jeff demonstrates the leak with a reproducible test case using `GIT_TEST_COMMIT_GRAPH=1` and confirms the fix resolves the LSan errors.

This patch complements the first patch in the series, which fixes a test harness issue where LSan output was misdirected to stdout, causing TAP parse errors. Together, the series addresses two small but real annoyances—one in Git itself and one in the test infrastructure—without changing user-visible behavior. The fixes are well-scoped and unlikely to introduce regressions. If you care about memory hygiene or test suite reliability, this series is worth a quick look.
