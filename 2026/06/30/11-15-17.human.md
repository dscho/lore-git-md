This is a user experience report about `git blame` output formatting. Laszlo Ersek points out an inconsistency: when the `-b` (or `blame.blankBoundary`) option is used, `git blame` still reserves space for the caret (`^`) that marks boundary commits, even though the caret is not shown. This forces commit hashes to be one nibble longer than the user’s `core.abbrev` setting, making it awkward to copy-paste them into a `git rebase` todo list.

The workaround—passing `--abbrev=11` explicitly—is clunky, and Ersek suggests a `blame.abbrev` config key would be a cleaner solution. The report is clear and practical, focusing on a small but real friction point in daily workflows. No patch is attached; this is just a request for discussion or a future change. Worth a glance for anyone who uses `git blame` frequently.
