This is a **bugfix patch** in a two-patch series from Jeff King (Peff) targeting memory leaks in Git. This specific patch fixes a leak in `git format-patch` where a `rev_info` struct allocated in `prepare_bases()` was never freed. The leak has existed since the `--base` option was introduced in 2016 but only became detectable after other leaks were fixed, making it stand out in LeakSanitizer (LSan) reports.

Patrick Steinhardt’s reply is a **substantive review** that confirms the fix is correct and well-motivated. He notes that the `rev_info` struct is always initialized before the exit path, so the added `release_revisions(&revs)` call is safe. Patrick also observes that while the patch resolves this leak, six test suites still fail due to unrelated leaks—primarily in `git-history` (missing `repo_unuse_commit_buffer()` calls) and bloom filter handling. These are acknowledged as separate issues not addressed by this patch.

The patch itself is **minimal and low-risk**, touching only one line in `builtin/log.c`. It requires no new tests, as the existing `t4014-format-patch.sh` suite demonstrates the fix when run with `GIT_TEST_COMMIT_GRAPH=1`. Patrick’s review also sparks a tangential discussion about enabling LSan in CI for the `linux-TEST-vars` job to catch similar leaks earlier, though he notes the ~3x performance overhead makes it impractical for all jobs.

This patch is **ready for merging**—it’s a straightforward, well-explained fix with no open questions or dependencies. The unrelated test failures Patrick mentions are outside its scope and likely to be addressed in follow-up work. If you’re tracking memory leaks or `format-patch` behavior, this is worth noting but not urgent.
