This is the seventh patch in Phillip Wood’s 11-patch series fixing how `git rebase` handles dropped commits. It removes a redundant null check in `pick_one_commit()` in `sequencer.c`.

The patch is a small, targeted refactoring. The commit message explains that `item->commit` is always non-NULL at this point because `pick_one_commit()` would not know which commit to pick otherwise, and `do_pick_commit()` (called earlier in the function) unconditionally dereferences it. The change is mechanical: the `item->commit` check is removed from the `else if` condition, leaving only the `is_rebase_i(opts)` check.

This patch is part of the preparatory work for the core behavioral change in patch 11. It does not alter Git’s behavior, but it simplifies the control flow, making the code easier to reason about before introducing the new `PICK_DROPPED` enum value. The series as a whole is well-structured, and this patch fits cleanly into the progression.

There is nothing controversial here; it is a straightforward cleanup. The patch is ready for review and should be uncontroversial. If you are following the series, this is a minor but necessary step toward the final fix.
