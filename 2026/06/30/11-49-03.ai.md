This is the cover letter for the **v3 reroll** of Patrick Steinhardt’s five-patch series adding reference-writing subcommands (`delete`, `update`, `create`, and `rename`) to the `git refs` builtin. The series is now **merged into Junio’s `next` branch** and proposed for the next release cycle.

The only change in v3 is a **typo fix** in the `git refs create` subcommand’s error message: it now correctly says "null new object ID" instead of "null old object ID". The rest of the series is unchanged from v2, which already addressed all prior review feedback (naming consistency, return value conventions, test coverage, and reflog edge cases). The series consolidates reference manipulation functionality under a unified interface, improving discoverability and reducing fragmentation in Git’s CLI.

Key technical details remain as previously summarized: the `refs/` subsystem is extended with new subcommands, new test scripts (`t1464-refs-delete.sh` through `t1467-refs-rename.sh`), and updates to `Documentation/git-refs.adoc`. The `create` subcommand enforces atomic "must not exist" semantics, while `update` mirrors `git update-ref`’s implicit creation behavior for backwards compatibility. The `rename` subcommand migrates reflogs but does not automatically create them if the source lacks one (a documented edge case deferred for future work).

This reroll is a **final polish step** before integration. The series is technically complete, uncontroversial, and ready for release. No further changes are expected.
