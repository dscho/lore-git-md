This is the second patch in a two-patch bugfix series from Jeff King addressing memory leaks. The series as a whole targets small, self-contained leaks in `git format-patch` and the test harness, discovered opportunistically rather than through a systematic audit.

This patch plugs a memory leak in `prepare_bases()` (in `builtin/log.c`), where a `rev_info` struct allocated for a custom revision walk was never freed. The fix is a single line: adding a `release_revisions(&revs)` call at the end of the function. The leak has existed since the `--base` option was introduced in 2016 (commit `fa2ab86d18`), but only became detectable after other leaks were fixed, making this one stand out in LeakSanitizer (LSan) reports. The patch demonstrates the leak using existing tests by enabling commit-graph support (`GIT_TEST_COMMIT_GRAPH=1`), which triggers allocation in the revision machinery’s topological walk.

The commit message is thorough, tracing the leak’s origin, explaining why it went unnoticed for years, and providing a clear reproduction case. No new tests are added, as the existing test suite suffices to demonstrate the fix when run with LSan. The patch is mechanical and low-risk, touching only one line in a well-understood code path. The series’ cover letter links this fix to an ongoing leak discussion, but the patch itself is standalone and ready for merging.

Key technical details for follow-up discussion:
- **File modified**: `builtin/log.c` (one line added).
- **Function**: `prepare_bases()` (leak fixed via `release_revisions()`).
- **Symbol**: `rev_info` struct (previously leaked).
- **Trigger condition**: commit-graph presence (allocates `topo_walk_info`).
- **Related commit**: `fa2ab86d18` (introduced `--base` option in 2016).
- **Test coverage**: existing `t4014-format-patch.sh` with `GIT_TEST_COMMIT_GRAPH=1`.
