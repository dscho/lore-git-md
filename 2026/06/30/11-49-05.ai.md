This is the second patch in Patrick Steinhardt’s merged five-patch series introducing reference-writing subcommands to the `git refs` builtin. It adds the `git refs delete` subcommand, which mirrors the functionality of `git update-ref -d`.

The patch extends the `refs/` subsystem by implementing the `delete` subcommand in `builtin/refs.c`, adding a new test script (`t1464-refs-delete.sh`), and updating the documentation (`Documentation/git-refs.adoc`). The subcommand supports the same options as `git update-ref -d`, including `--message=<reason>` for reflog entries and `--no-deref` to operate on symbolic references directly. The implementation enforces atomicity by allowing an optional `<old-value>` argument to verify the reference’s current state before deletion, matching `git update-ref`’s behavior.

The test coverage is thorough, spanning 130 lines and validating deletion, old-value verification, symref handling, reflog updates, and error cases (e.g., invalid object IDs, empty messages, and incorrect argument counts). The patch is uncontroversial and aligns with the series’ goal of consolidating reference manipulation under a unified interface. No behavioral changes to existing commands are introduced; this is purely additive. The series is already merged into Junio’s `next` branch, and this patch is ready for release.
