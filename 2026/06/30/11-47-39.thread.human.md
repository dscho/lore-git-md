Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup in Git’s core code has now concluded with the removal of `set_git_work_tree()` from the public API. The series aimed to untangle the intertwined phases of finding a repository (discovery) and configuring it (setup), introducing a new `struct repo_discovery` to hold discovery results and consolidating setup logic into `repo_init()` and related functions. All 13 patches have been submitted as v2, with minor updates to commit messages but no code changes, and the series remains under active review.

Key progress includes substantive reviews from Justin Tobler on patches 1–7 and 12, covering the introduction of `struct repo_discovery`, the move of the repository prefix from global state to `struct repository`, and the consolidation of worktree configuration into `init_db()`. Junio C Hamano queued patch 2/13 after fixing a typo in its commit message, but no other patches have been merged yet. The series builds on prior work like `ps/setup-drop-global-state` and `jk/repo-info-path-keys`, and its architectural changes—such as embedding `struct repository_format` into `struct repo_discovery` and eliminating redundant state—are designed to reduce scattered setup logic without altering user-visible behavior.

Open questions remain about ordering dependencies in patch 2/13, the use of environment variables for global state in patch 3/13, and the broader implications of the new `struct repo_discovery` API for edge cases like environment variable overrides or reinitialization. The final patch (13/13) marks `set_git_work_tree()` as static, completing the series’ goal of making worktree configuration an internal detail of `setup.c`. While the patch itself is uncontroversial, its removal from the public API signals a shift toward more centralized repository setup, which may require follow-up work to ensure compatibility with other subsystems like `git submodule`. The series is now poised for final review, with no major objections raised so far.
