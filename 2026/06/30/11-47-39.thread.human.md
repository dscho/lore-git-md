Patrick Steinhardt has sent a 13-patch series refactoring Git’s repository setup code to cleanly separate *discovery* (finding the repository location and format) from *setup* (configuring the repository object). The series introduces a new `struct repo_discovery` to hold discovery results, eliminating scattered setup logic and reducing reliance on global state. Key changes include embedding `struct repository_format` into `repo_discovery`, moving the repository prefix from a global struct into the repository object, extracting discovery logic into a self-contained `repo_discover()` function, and consolidating worktree configuration into `init_db()`.

The final patch (13/13) marks `set_git_work_tree()` as `static` in `setup.c` and removes its public declaration, as all external callers were eliminated in the previous patch. This is a mechanical cleanup that reinforces the series’ architectural goals—no behavior changes are intended, and the patch is uncontroversial. The series builds on recent work like `ps/setup-drop-global-state` and `jk/repo-info-path-keys`, aligning with broader efforts to remove `the_repository` globals and abstract the object database.

No reviews have been posted yet, but maintainers (Junio C Hamano) and contributors familiar with repository setup (e.g., Jeff King, Taylor Blau, René Scharfe) are likely to weigh in. Open questions include whether the new `repo_discovery` API handles edge cases like environment variable overrides, worktree configuration, and prefix propagation, as well as how it integrates with ongoing refactoring efforts.
