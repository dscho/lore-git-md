Patrick Steinhardt’s 13-patch series to refactor Git’s repository discovery and setup code continues with the fourth installment, further untangling the logic in `setup.c`. The series aims to cleanly separate the phases of finding a repository (discovery) from configuring it (setup), a change that should make the codebase more modular and easier to maintain as ongoing efforts like `the_repository` removal and ODB abstraction progress.

This latest patch splits the monolithic `setup_git_env_internal()` into two focused functions: `apply_gitdir_and_environment()`, which handles gitdir configuration and environment variable propagation, and `setup_environment()`, which sets up global parameters like replace refs and lazy fetching. The latter is moved to `init_git()` since it only needs to run once, while the former stays in `setup.c` to handle gitdir changes. The change is purely mechanical, with no behavior changes, but it’s a key step toward the series’ goal of consolidating repository setup logic and reducing global state. So far, the first four patches have landed without review feedback, but the groundwork they lay—particularly the new function boundaries and the relocation of environment setup—will likely draw scrutiny from reviewers like Jeff King or Taylor Blau, who are familiar with the intricacies of repository initialization.
