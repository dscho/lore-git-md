Patrick Steinhardt’s v2 refactoring series (13 patches) continues to decouple repository discovery from setup in Git’s core code, introducing a `struct repo_discovery` to hold discovery results and streamline initialization. The series has now garnered broad conceptual support: Justin Tobler signed off on the v2 updates (typos, commit message clarifications, and an unused parameter removal), and Toon Claes has added his endorsement, calling the architectural direction "sensible" and "accurate." Junio C Hamano has indicated he will "replace" the series in his integration branches, placing it under integration testing (likely in `next` or `seen`), though it has not yet merged to `master`.

The refactoring touches `setup.c` and related files, moving repository prefix management from global `startup_info` to `struct repository`, eliminating redundant state (e.g., the static `cwd` buffer), and consolidating worktree configuration into `init_db()`. While the changes are mechanical and preserve existing behavior, several design questions remain unresolved from earlier reviews. Justin Tobler raised concerns about environment variable design (patch 3/13), ordering dependencies in misconfiguration checks (patch 2/13), and the implications of single-application semantics for repository configuration (patch 5/13). Patrick Steinhardt addressed some of these—clarifying that environment variables override repository configuration and that the `--shallow-file` option’s precedence is preserved—but others, like the lack of safeguards for ordering assumptions, remain open. Toon’s review did not engage with these details, focusing instead on the high-level design.

The series builds on prior work (`ps/setup-drop-global-state`, `jk/repo-info-path-keys`) and aligns with broader efforts like `the_repository` removal and ODB abstraction. Downstream consumers should expect the series to appear in Junio’s "What’s cooking" report soon, possibly with notes about the unresolved edge cases. Follow-up patches may address these, particularly enforcing single-application semantics or documenting ordering assumptions. For now, the series is on track for integration, with no new code changes introduced in v2—only clarifications and cleanup.
