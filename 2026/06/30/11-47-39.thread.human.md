This thread covers Patrick Steinhardt’s 13-patch refactoring series to separate repository discovery from setup in Git’s core code. The goal is to cleanly decouple the phases of finding a repository’s location and format from configuring its internal state, making the codebase more modular and easier to maintain. The series has now reached a key milestone: Junio C Hamano has acknowledged Justin Tobler’s sign-off on the v2 updates and will queue the full series in his integration branches.

The series is technically complete, with all patches submitted and no code changes in v2—only minor fixes to commit messages and the removal of an unused parameter. Justin Tobler provided substantive reviews on several patches in v1, raising questions about design choices (e.g., environment variable usage, ordering dependencies) and edge cases. While Patrick addressed some of these concerns in replies, others remain unresolved, such as whether the series’ assumptions about call order or global state could break in future refactoring. Junio’s silence on these points suggests they’re either accepted as-is or deferred for later.

The refactoring touches primarily `setup.c` and introduces new structures like `struct repo_discovery` and functions like `repo_discover()` to encapsulate the discovery phase. No user-visible behavior changes are intended, but the separation could expose subtle edge cases in repository initialization or worktree handling. The series builds on earlier work like `ps/setup-drop-global-state` and aligns with broader efforts to remove global state (e.g., `the_repository` removal) and abstract the object database.
