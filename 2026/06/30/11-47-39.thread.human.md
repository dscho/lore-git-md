Patrick Steinhardt’s refactoring series to separate repository discovery from setup in Git’s core code continues to progress under active review. The 13-patch series, which introduces a new `struct repo_discovery` to hold discovery results and consolidate scattered setup logic, has seen substantive engagement from Justin Tobler on several key patches, including the latest exchange about patch 3/13.

In this reply, Patrick addressed Justin’s concerns about shallow file configuration precedence and environment variable design. He clarified that the `--shallow-file` command-line option has always overridden the `GIT_SHALLOW_FILE` environment variable, and this patch preserves that behavior while simplifying the code. On the broader design question, Patrick acknowledged the suboptimal use of environment variables for global state but defended it as consistent with existing patterns, noting that a more principled refactoring would require a much larger effort. The discussion leaves the patch’s core design intact, though Patrick agreed the commit message should document the precedence behavior more clearly.

The series remains under review, with no merge decisions yet. Justin’s substantive feedback on patches 1/13, 2/13, 3/13, 5/13, and 7/13 has surfaced several open questions—particularly around ordering dependencies, single-application semantics, and API design—but none have blocked progress. Junio C Hamano queued patch 2/13 after a minor typo fix, and Patrick has responded to all review comments so far. The refactoring aims to decouple discovery and setup phases without changing user-visible behavior, though the separation may expose edge cases in repository initialization. Key milestones include extracting the discovery phase into `repo_discover()`, embedding `struct repository_format` into `struct repo_discovery`, and removing redundant global state like the static `cwd` buffer. The series builds on recent work like `ps/setup-drop-global-state` and aligns with broader efforts to remove `the_repository` and abstract the object database.
