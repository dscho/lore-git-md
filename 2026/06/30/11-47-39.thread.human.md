Patrick Steinhardt’s 13-patch series to refactor Git’s repository setup code continues with the ninth installment, further untangling discovery from configuration. The series aims to clean up `setup.c` by introducing a new `struct repo_discovery` that holds the results of finding a repository—its location, format, and now its prefix—before any configuration is applied. This patch propagates the repository prefix through that struct, removing a static variable and making the API more consistent. The three discovery functions no longer return the prefix as a separate value but instead populate it directly in the discovery struct, which `setup_git_directory_gently()` then reads.

The work so far has been methodical: earlier patches split `setup_git_env_internal()` into distinct phases, embedded `struct repository_format` into `repo_discovery`, and moved the prefix out of the global `startup_info` struct into `struct repository`. This patch builds on those changes, eliminating another static buffer and further reducing global state. No behavior changes are intended, but the shift to storing the prefix in `repo_discovery` could expose edge cases in how bare repositories or worktree overrides interact with the new API. Reviewers familiar with repository setup—Jeff King, Taylor Blau, or René Scharfe—are likely to weigh in on whether the new boundaries are clear and robust, especially for callers that rely on the prefix’s availability. The series remains on track, with four patches still to come.
