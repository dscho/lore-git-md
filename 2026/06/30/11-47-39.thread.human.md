Patrick Steinhardt’s v2 patch series to refactor Git’s repository setup code continues to make progress, with the latest update moving the repository prefix out of the global `startup_info` struct and into `struct repository`. This change, the seventh of thirteen patches, is a key step in disentangling repository discovery from configuration and consolidating state into the repository object itself.

The series aims to clean up `setup.c` by introducing a new `struct repo_discovery` to hold the results of finding a repository’s location and format, allowing the discovery and setup phases to operate independently. Earlier patches in the series have already extracted discovery logic into dedicated functions, embedded repository format information into `repo_discovery`, and split environment setup into distinct phases. This latest patch removes one of the last remnants of global state by tying the repository prefix to its logical owner, `struct repository`, rather than the global `startup_info`. Justin Tobler’s review of the change was positive, calling it a “good change” that aligns the prefix with where it belongs.

The series remains under active review, with patches 1–7 now having received substantive feedback from Justin Tobler. While the changes are mechanical and intended to preserve existing behavior, some open questions linger—particularly around the handling of environment variables and the assumption that `apply_repository_format()` is always called after `setup_explicit_git_dir()`. Patrick has addressed some of these concerns in replies, but others, like the broader design of environment variable usage, remain unresolved. No merge decisions have been made yet, and the series is still cooking in Junio’s integration branches. The next steps will likely focus on the remaining patches, which further consolidate setup logic and remove redundant state.
