This thread is Patrick Steinhardt’s second version of a 13-patch series refactoring Git’s repository discovery and setup code. The goal is to cleanly separate the *discovery* phase (finding the repository location and format) from the *setup* phase (configuring the repository object), eliminating scattered state and consolidating logic into `repo_init()`. The series is now complete with v2, which includes minor commit-message fixes but no code changes from v1.

Key progress: Justin Tobler has given substantive reviews to patches 1–7 and 11, with no major objections raised. Junio queued patch 2/13 after fixing a typo, and Patrick addressed Justin’s questions about behavioral invariants and design choices in patches 2, 3, and 5. The latest patch (12/13) passes the worktree path as an explicit parameter to `init_db()`, removing the last indirect call to `set_git_work_tree()` and completing the series’ architectural goal. The final patch (13/13) will remove `set_git_work_tree()` from the public API entirely.

Open questions remain about ordering dependencies (patch 2/13), environment variable design (patch 3/13), and whether the new function boundaries handle edge cases like environment variable propagation or gitdir changes during `chdir` notifications. The series builds on recent work like `ps/setup-drop-global-state` and `jk/repo-info-path-keys` and aligns with broader efforts to remove `the_repository` and abstract the object database. No merge decisions have been made yet, but the series is under active review and appears to be converging.
