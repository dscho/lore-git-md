This thread is Patrick Steinhardt’s second iteration of a 13-patch refactoring series to cleanly separate repository *discovery* (finding the repository location and format) from *setup* (configuring the repository object) in Git’s core code. The series introduces a new `struct repo_discovery` to hold discovery results, enabling distinct, self-contained phases and reducing scattered setup logic. Version 2 of the series was resent with minor updates to commit messages but no code changes.

The second patch, which just arrived, moves the detection of misconfigured worktrees (where both `core.worktree` and `core.bare` are set) from `setup_explicit_git_dir()` to `apply_repository_format()`. This is a preparatory step for later patches that will remove the repository parameter from `setup_explicit_git_dir()`. The patch preserves existing behavior: when `GIT_WORK_TREE` is set, it overrides repository configuration and suppresses warnings about misconfigurations. Junio C Hamano queued the first version of this patch after fixing a minor typo in its commit message, and Justin Tobler’s substantive review raised two questions—one about behavioral changes (addressed by Patrick) and another about an ordering dependency between `apply_repository_format()` and `setup_explicit_git_dir()`. The latter remains unresolved, leaving a potential risk for future refactoring.

Five of the 13 patches (including this one) have received substantive reviews from Justin Tobler, who affirmed the architectural direction in patches like the move of the repository prefix from `startup_info` to `struct repository`. The series remains under active review with no merge decisions. Key milestones include extracting the discovery phase into `repo_discover()`, embedding `struct repository_format` into `struct repo_discovery`, and removing `set_git_work_tree()` from the public API. No behavior changes are intended, but the separation may expose edge cases in repository initialization, particularly around environment variable overrides and worktree configuration. The series builds on recent work like `ps/setup-drop-global-state` and `jk/repo-info-path-keys` and aligns with broader efforts like `the_repository` removal and ODB abstraction.
