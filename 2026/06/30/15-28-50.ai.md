This is a **bugfix series** targeting the sequencer subsystem, specifically addressing the long-standing issue where `git rebase` incorrectly copies notes from dropped commits to the current HEAD. Phillip Wood takes ownership of the broader problem exposed by Uwe Kleine-König’s earlier patch, delivering a systemic overhaul of how the rebase machinery handles dropped commits.

The series consists of 11 patches, structured as a gradual refactoring followed by the core fix. The first patch restores test coverage lost when the default rebase backend switched from "apply" to "merge," ensuring the regression is caught in CI. Patches 2–9 are preparatory refactorings that simplify control flow in `pick_one_commit()` and `do_pick_commit()`, making the codebase more maintainable and paving the way for the behavioral change. Patch 10 introduces an enum to represent the result of picking a commit, replacing a boolean return value with a more expressive type. The final patch (11) adds a new enum member for dropped commits and modifies the sequencer to avoid recording them as rewritten, which prevents notes from being incorrectly copied.

Key technical details include the removal of the `dropped_commit` output parameter proposed in Uwe’s patch, replaced by a return value from `do_pick_commit()`. The series touches `sequencer.c` extensively, with test additions in `t3400-rebase.sh`, `t3404-rebase-interactive.sh`, and `t5407-post-rewrite-hook.sh`. The behavioral change is narrow but critical: notes are no longer copied from commits dropped due to empty changes, and post-rewrite hooks no longer receive misleading information about rewritten commits. The on-disk format remains unchanged.

Phillip’s approach is methodical, addressing not just the immediate bug but also the systemic issues identified in his earlier review. The series fixes the fixup-commit edge case (where notes could be mis-mapped in sequences with dropped fixups) and resolves three additional rebase bugs: final fixup cleanup, edit command handling, and skip command handling. The cover letter explicitly ties this work to the prior discussion, making it clear this is the promised follow-up to Uwe’s patch. Junio’s earlier concerns about documentation and test location are addressed: the test is integrated into `t3400-rebase.sh`, and the commit messages provide clear rationale for the behavioral change.
