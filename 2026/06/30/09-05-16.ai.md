This is a **CI/build system** follow-up in the ongoing thread about macOS CI hangs in `t5551` and `t5559`. Patrick Steinhardt responds to Junio C Hamano’s visibility concern by proposing a small but concrete improvement: adding a GitLab CI status badge to the project’s `README.md`.

The patch Patrick suggests is a one-line addition that inserts a GitLab CI badge alongside the existing GitHub badge. The badge links directly to the pipelines page for the `master` branch on GitLab’s official mirror. This is a low-cost, non-technical change that directly addresses Junio’s stated barrier — maintainers not knowing where to find GitLab CI results. The proposal is pragmatic and aligns with the earlier consensus that GitLab CI should be a first-class part of the project’s workflow.

No new policy questions are raised; the email is purely about implementation. The third patch in the original series (enabling `GIT_TEST_LONG` for GitLab CI) remains on hold, but this small documentation tweak could be merged independently and would make GitLab CI results more discoverable without requiring any CI configuration changes.
