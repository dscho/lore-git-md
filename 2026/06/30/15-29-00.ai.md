This is the **tenth patch in Phillip Wood’s 11-patch series** that overhauls how the sequencer handles dropped commits during rebase. The patch introduces an `enum pick_result` to replace the integer return values from `do_pick_commit()`, making the code more expressive and preparing for the addition of a `PICK_DROPPED` value in the next patch.

The enum defines three states: `PICK_RESULT_ERROR` (-1), `PICK_RESULT_OK` (0), and `PICK_RESULT_CONFLICTS` (1). The patch updates `do_pick_commit()` to return the enum instead of an integer, and propagates this change through `pick_one_commit()` and `single_pick()`. The conversion is mechanical but clarifies the control flow, especially in `pick_one_commit()`, where the logic for handling conflicts, fixups, and edits is now easier to follow. The patch also fixes a latent bug in `pick_one_commit()`: the `to_amend` logic previously passed `res` (the integer return value) to `error_with_patch()`, but now passes `1` explicitly, since the only positive return value from `do_pick_commit()` is `PICK_RESULT_CONFLICTS`.

This is a **refactoring patch** with no behavior change. It is well-motivated by the need to introduce `PICK_DROPPED` in the next patch, and the enum makes the code more maintainable. The patch is small, focused, and builds cleanly on the preparatory refactorings in patches 2–9. The commit message clearly explains the motivation and the technical details, including the note about C’s lax enum typing. The only minor quirk is the continued use of `return error(...)` for errors, which is consistent with Git’s coding style but slightly at odds with the enum’s type safety. This patch is a necessary step toward the core fix in patch 11 and looks ready for review.
