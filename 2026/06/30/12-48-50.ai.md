This is a bugfix patch targeting Git's config file parser. It addresses a long-standing case-sensitivity mismatch when updating values in old-style `[section.subsection]` config headers.

The issue occurs because Git's config parser unconditionally lowercases subsections in old-style headers during parsing, but preserves the original case when matching keys from the command line. This causes `git config section.Subsection.key value` to fail to match an existing `[section.subsection]` entry if the subsection contains uppercase letters, resulting in duplicate entries rather than value updates. The patch tracks whether the current section was parsed case-sensitively (new-style quoted headers) or case-insensitively (old-style headers) and uses this information to perform appropriate case-sensitive or case-insensitive comparison of the subsection segment.

The implementation adds a `subsection_case_sensitive` flag to `struct config_store_data` and modifies the `matches()` function to use either `strncmp` or `strncasecmp` based on this flag. The change removes the now-obsolete BUGS section from `git-config.adoc` that documented this limitation, and updates the test suite to reflect the fixed behavior.

The patch touches core config handling (`config.c`), documentation (`git-config.adoc`), and tests (`t1300-config.sh`). The commit message clearly explains the problem, the solution, and the rationale for the approach. The code changes are minimal and focused, with good in-code comments explaining the case-sensitivity logic.
