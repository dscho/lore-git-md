This is a **substantive review reply** in the ongoing ODB abstraction effort, specifically addressing the second patch of Justin Tobler’s six-patch series converting `git-receive-pack` to use ODB transactions. The email is from Patrick Steinhardt to Justin, clarifying design choices and architectural implications after Justin’s response to Patrick’s earlier feedback.

Patrick’s reply focuses on three key areas:
1. **Code organization**: He acknowledges Justin’s explanation for why the "files" transaction functions remain in `object-file.c` (due to entangled object-write paths) and agrees this is a temporary state that will be cleaned up in a follow-up series.
2. **Error handling**: He endorses Justin’s plan to maintain backward compatibility by allowing callers to handle missing temporary directories gracefully, rather than treating it as a hard error. This preserves existing resilience while still surfacing errors for cases like `git-receive-pack` that expect strict behavior. Patrick notes this trade-off should be documented in the commit message.
3. **Architectural limitations**: He reaffirms the preexisting constraint that only one ODB transaction can exist per ODB (due to the global `tmp_objdir` and `atexit()` cleanup), contrasting it with reference transactions’ multi-transaction design. Both agree this is a target for future refactoring once all `tmp_objdir` callers are converted to ODB transactions.

The tone is collaborative, with Patrick explicitly agreeing that Justin’s proposed v2 changes (e.g., preserving backward compatibility, documenting error-handling behavior) are the right path forward. No new blocking issues are raised, and the discussion reinforces the series’ goal of advancing ODB-backend agnosticism while deferring deeper architectural changes to follow-up work.

Key technical details for future reference:
- **Symbols**: `odb_transaction_files_prepare()`, `odb_transaction_files_commit()`, `odb_transaction_files_begin()`, `flush_loose_object_transaction()` (renamed to `odb_transaction_files_flush()` in v2).
- **Files**: `object-file.c`, `odb/source-files.c` (future target for refactoring).
- **Design tension**: Error handling (strict vs. resilient) and single-transaction-per-ODB limitation.
- **Follow-up work**: Detangling object-write paths, removing `tmp_objdir` global, enabling multiple transactions.
