This is a gentle follow-up to an RFC proposing a new feature for `git clone`: the ability to specify sparse-checkout paths directly during clone using `--only` (inclusion) and `--except` (exclusion) options.

The original proposal, sent a few days ago, targets monorepo workflows where developers only need a subset of the repository. Currently, this requires two steps (`git clone --sparse` followed by `git sparse-checkout set`), which the author argues is cumbersome. The feature would reuse Git's existing sparse-checkout machinery, avoiding the need for a separate configuration step after cloning. The author is seeking feedback on whether the feature addresses a real pain point, which interface style is preferred (comma-separated values vs. repeated options), and any potential concerns before proceeding with implementation.

So far, there has been no response from the community. This follow-up is a simple ping to check if anyone has thoughts on the proposal or whether it seems worth pursuing. The thread remains in the early RFC stage, with no implementation yet. If you're interested in sparse-checkout workflows or monorepo tooling, this might be worth a look.
