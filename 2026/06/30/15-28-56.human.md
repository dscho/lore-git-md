This is the sixth patch in Phillip Wood’s 11-patch series that overhauls how `git rebase` handles dropped commits. It simplifies the control flow in `pick_one_commit()` by removing a redundant conditional check that became unnecessary after earlier refactorings.

The patch targets a specific edge case in the sequencer: when a fixup commit encounters a conflict, the code previously checked whether the return value (`res`) was `1` before calling `intend_to_amend()`. However, earlier patches in the series (notably patch 5/11) ensured that the only positive value `res` can take is `1`, making the conditional redundant. The patch removes the check and directly calls `error_with_patch()`, passing `1` as the final argument to indicate the commit should be treated as a conflict.

The change is small—just three lines removed—but it cleans up the logic in `pick_one_commit()`, making the code easier to follow. This is part of a broader effort to simplify the sequencer’s control flow before introducing the core behavioral change (in patch 11) that prevents notes from being copied from dropped commits. The patch is well-motivated and directly tied to the series’ goal of making the rebase machinery more robust and maintainable.

No new behavior is introduced here, and the patch does not touch tests or documentation. It is a pure refactoring that prepares the ground for the enum-based return values introduced in later patches. The commit message clearly explains the rationale, referencing the earlier commit (`e032abd5a0`) that made the conditional unnecessary. This is a solid, uncontroversial step in the series.
