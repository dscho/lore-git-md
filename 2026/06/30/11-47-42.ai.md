This is the **third patch in Patrick Steinhardt's 13-patch refactoring series** to separate repository discovery from setup in Git's core code. The patch unifies the handling of the shallow file configuration, which can currently be set via either the `GIT_SHALLOW_FILE` environment variable or the `--shallow-file` command-line option. Previously, these mechanisms were handled in two different places (`setup_git_env_internal()` and `handle_options()`, respectively).

The change moves the shallow file logic entirely into `apply_repository_format()`, the function responsible for configuring a discovered Git directory. This is done by having the `--shallow-file` option set the `GIT_SHALLOW_FILE` environment variable instead of directly calling `set_alternate_shallow_file()`. The environment variable is then processed in `apply_repository_format()`, aligning with how other global options (like object directories) are handled.

**Key technical details**:
- The patch modifies `git.c` to replace the direct call to `set_alternate_shallow_file()` with a `setenv()` call for `GIT_SHALLOW_FILE_ENVIRONMENT`.
- In `setup.c`, the shallow file logic is removed from `setup_git_env_internal()` and added to `apply_repository_format()` under the `APPLY_REPOSITORY_FORMAT_HONOR_ENV` flag.
- Files touched: `git.c` (1 line changed) and `setup.c` (5 lines changed, 5 lines removed).
- The change is part of a broader effort to ensure `the_repository` contains no relevant state before `apply_repository_format()` is called, enabling future cleanup (e.g., discarding and repopulating `the_repository`).

This is a **clean, mechanical refactor** that improves consistency in how global options are handled. It aligns with the series' goal of making repository setup more modular and paves the way for later patches that will further separate discovery and setup logic. No behavior changes are intended, and the patch is unlikely to be controversial. The commit message clearly explains the motivation and the technical approach.
