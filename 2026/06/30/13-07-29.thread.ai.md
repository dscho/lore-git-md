Thread identity
Subject: [PATCH] Makefile: remove spurious $(LIB_FILE) dependency from $(RUST_LIB)
Series version: standalone patch
Originating author: Jan Palus
Thread type: patch (build system, Rustification effort)

Core problem or goal
Remove an incorrect Makefile dependency that forces the Rust static library to rebuild whenever the main Git C library changes. The patch claims this dependency is unnecessary because the Rust code does not link against or use the C library at build time.

Current status
Patch sent; no prior iterations. Review from Brian m. carlson identifies the dependency as intentional and necessary for `cargo test` to work, as the Rust code in `src/hash.rs` does link against C functions from `libgit.a`. The absence of this dependency in the Meson build system is now considered an oversight rather than confirmation of the claim.

Key technical details
- Files touched: Makefile, `src/hash.rs`
- Symbols: $(RUST_LIB) (Rust static library), $(LIB_FILE) (main Git C library, `libgit.a`)
- Behavior change: Rust library rebuilds when C library changes (currently enforced; patch proposes removing this)
- Linkage: Rust code in `src/hash.rs` calls C functions from `libgit.a`, requiring the dependency for `cargo test`
- No on-disk format or runtime behavior changes; purely a build-time linkage concern
- Meson build system lacks this dependency, which is now considered incorrect

Open questions and loose ends
- Should the Meson build system be fixed to include the dependency?
- Is there a way to restructure the Rust code to avoid linking against `libgit.a` during `cargo test`?
- What future Rust code will rely on the C library, and how should this be documented or handled?

Participant positions
- **Jan Palus**: Proposed removing the dependency, arguing it was spurious.
- **Brian m. carlson**: High-weight review; opposes the patch, explaining the dependency is necessary for `cargo test` and that future Rust code will rely even more on the C library. Position is substantive and technical, shifting the patch from a cleanup to a potential build-breaker.

Related work
Part of the broader Rustification effort (introducing Rust code into Git’s C codebase). The discussion highlights the growing interdependence between Rust and C code in the project.
