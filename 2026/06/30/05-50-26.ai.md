This is a follow-up in the `git history reword` memory leak thread, now expanding the diagnostic scope. Jeff King reports that enabling `GIT_TEST_COMMIT_GRAPH=1` and running the full test suite with `SANITIZE=leak` exposes additional leaks beyond the already-fixed `git history reword` issue. The failures in the `t345x` test scripts all appear related to the same slab-cache bypass mechanism (commit-graph loading bypassing raw object parsing). However, `t4014` fails with a distinct leak: the topological walk slab (`init_topo_walk`) is not being freed. This suggests the original fix, while correct for its narrow scope, is part of a broader pattern of slab management gaps in Git’s codebase, particularly when commit-graph is enabled. The message does not propose a solution but flags the new leak as a separate issue requiring its own investigation.
