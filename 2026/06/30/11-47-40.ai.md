This is the **first patch in a 13-patch refactoring series** from Patrick Steinhardt, targeting Git's repository setup code. The patch renames `check_repository_format_gently()` to `read_and_verify_repository_format()` to better reflect its dual role: reading the repository format *and* verifying its consistency. The change also reorders the function's parameters to place the `repository_format` struct first, aligning with other functions in the codebase.

The patch is purely mechanical—no behavior changes are introduced. It touches only `setup.c`, updating 7 call sites to use the new function name and parameter order. The commit message clearly explains the motivation: the old name could mislead readers into thinking the function only *checks* the format, when it actually *reads* it first. This is a foundational step for the larger goal of separating repository discovery from setup, as outlined in the series' cover letter.

Key technical details for follow-up discussion:
- The renamed function now takes `struct repository_format *` as its first parameter.
- All callers in `setup.c` are updated, including `setup_explicit_git_dir()`, `setup_discovered_git_dir()`, and `init_db()`.
- The patch preserves the function's existing logic, including handling of `nongit_ok`, worktree config, and bare repository detection.
- This is part of Patrick's broader effort to clean up `setup.c` and prepare for ODB abstraction and `the_repository` removal.

The patch is well-motivated and uncontroversial, but its value will become clearer in later patches where the new `repo_discovery` struct is introduced. Reviewers may focus on whether the new name sufficiently clarifies the function's purpose or if further documentation is needed.
