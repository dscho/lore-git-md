This is the third patch in Patrick Steinhardt’s 13-patch **refactoring** series that separates repository discovery from setup in Git’s core code. It unifies the handling of the shallow file (used for shallow clones) by moving its configuration from the command-line option handler (`handle_options()`) into `apply_repository_format()`, where other repository-format settings are applied.

The change is small (6 lines added, 6 removed) but meaningful: instead of calling `set_alternate_shallow_file()` directly when `--shallow-file` is passed, the patch sets the `GIT_SHALLOW_FILE` environment variable, which is then read later in `apply_repository_format()`. This aligns shallow-file handling with other global options (like `GIT_OBJECT_DIRECTORY`) and paves the way for the series’ larger goal—eliminating `the_repository` as a global state container before repository setup completes.

The patch is clean and well-motivated, with a clear tie to the series’ broader objectives. It touches only `git.c` and `setup.c`, and the commit message explains the rationale clearly. No behavior changes are introduced, but the refactoring could expose edge cases in how shallow files interact with repository initialization. This is a foundational step in Patrick’s ongoing effort to modularize Git’s setup code, and it looks like a sensible cleanup.
