This is the first patch in Phillip Wood’s 11-patch series fixing how `git rebase` handles dropped commits. It restores test coverage that was lost when the default rebase backend switched from "apply" to "merge" in Git 2.26. The patch is a small, targeted change to `t/t3400-rebase.sh`: it replaces the `-m` flag (which now invokes the merge backend) with `--apply` in a test that verifies notes are correctly copied during rebase.

The change is mechanical and uncontroversial. It ensures the test suite continues to exercise the apply backend’s note-copying behavior, which is important because the bug being fixed (notes incorrectly copied from dropped commits) affects both backends. The patch sets the stage for the rest of the series by guaranteeing that regressions in either backend will be caught in CI. No new functionality is introduced; this is purely about maintaining existing test coverage. The commit message is clear and concise, explaining the rationale without overstating the scope.
