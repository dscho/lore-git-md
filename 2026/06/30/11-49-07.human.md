This is the fourth patch in Patrick Steinhardt’s now-merged five-part series that adds reference-writing subcommands to `` `git refs` ``. This patch introduces the `` `git refs create` `` subcommand, which provides an explicit, atomic way to create a new reference that must not already exist.

The subcommand plugs a gap in the series’ symmetry: while `` `git refs delete` `` offers a convenient shortcut for deletion, there was no equivalent for creation. `` `git refs create` `` enforces “must not exist” semantics, rejecting the operation if the reference already exists. It supports the same options as the other new subcommands—``--message=<reason>`` for reflog entries, ``--no-deref`` for symbolic reference handling, and ``--create-reflog`` to force reflog creation—plus thorough error checking for invalid object IDs, null values, and empty messages. The patch includes a new 151-line test script (``t1466-refs-create.sh``) that validates all these behaviors, including edge cases like symref targets and reflog handling.

The only change since v2 is a one-line typo fix in the error message: it now correctly says “null new object ID” instead of “null old object ID.” The rest of the implementation is unchanged and has already been reviewed and approved. This patch is now part of Junio’s ``next`` branch and is slated for the next release.
