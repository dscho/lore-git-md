This is the third patch in Patrick Steinhardt’s merged five-patch series adding reference-writing subcommands to the `git refs` builtin. It introduces the `git refs update` subcommand, which mirrors the behavior of `git update-ref` exactly, including its implicit creation semantics. The patch is part of the broader effort to consolidate Git’s reference manipulation commands under a unified interface.

The implementation adds a new subcommand handler in `builtin/refs.c`, updates the documentation in `Documentation/git-refs.adoc`, and includes a comprehensive test script (`t1465-refs-update.sh`) with 268 lines of coverage. The subcommand supports all key features of `git update-ref`: atomic updates via `<old-value>`, deletion with `$ZERO_OID`, `--no-deref` for symbolic reference handling, `--create-reflog` to force reflog creation, and `--message` for custom reflog entries. Error handling is thorough, with clear messages for invalid object IDs, empty messages, and argument count mismatches.

The patch is technically complete and uncontroversial. It was approved after addressing Junio’s feedback in earlier iterations, including the addition of a test for atomic creation checks (using `$NULL_OID`). The only change in the final v3 reroll was a typo fix in the `git refs create` subcommand (patch 4/5), unrelated to this patch. The series is now merged into Junio’s `next` branch and ready for release.

Key technical details:
- **Files touched**: `builtin/refs.c`, `Documentation/git-refs.adoc`, `t/meson.build`, and the new test script `t/t1465-refs-update.sh`.
- **New CLI**: `git refs update [--message=<reason>] [--no-deref] [--create-reflog] <ref> <new-value> [<old-value>]`.
- **Behavior**: Mirrors `git update-ref` exactly, including implicit creation when `<old-value>` is `$NULL_OID` and deletion when `<new-value>` is `$ZERO_OID`.
- **Test coverage**: Validates creation, modification, deletion, atomic checks, symref handling, reflog behavior, and error cases (e.g., invalid object IDs, empty messages). The test for atomic creation (`$NULL_OID`) was added in response to review feedback.
