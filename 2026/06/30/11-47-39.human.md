This is a refactoring series from Patrick Steinhardt targeting Git's repository setup code. The goal is to cleanly separate the two phases of repository setup—discovery (finding the repository location and format) and configuration (applying that information to initialize the repository)—which are currently intertwined in `setup.c`. The series introduces a new `struct repo_discovery` to hold discovery results, making the process more modular and paving the way for consolidating repository configuration into `repo_init()`.

The series is substantial: 13 patches touching 13 files, with 283 insertions and 241 deletions. It builds on three recent branches, including Patrick's own `ps/setup-drop-global-state` (part of the ongoing `the_repository` removal effort) and Junio's `jk/repo-info-path-keys`. The changes are mechanical but far-reaching, affecting core commands like `git clone`, `git init`, and `git rev-parse`, as well as low-level plumbing like `setup_git_env_internal()`.

Patrick's motivation is clear: the current code leaves repositories in a partially-configured state, making the logic hard to follow. This refactoring is a stepping stone toward unifying repository configuration in `repo_init()`, which would simplify the codebase further. The commit messages are detailed and the changes appear well-scoped, though the sheer number of files touched suggests this will need careful review to catch subtle interactions.

This is not a user-facing feature or bugfix, but it’s a foundational cleanup that could make future work—like pluggable repository backends or multi-repo improvements—easier. If you’re interested in Git’s internals or the `the_repository` removal effort, this series is worth following. For most readers, it’s safe to skip unless you’re directly working on repository setup or related subsystems.
