This is the eighth patch in Phillip Wood’s 11-patch series that overhauls how `git rebase` handles dropped commits. The series as a whole fixes a bug where notes from dropped commits were incorrectly copied to the current HEAD, and this patch is a **refactoring** that simplifies the control flow in `pick_one_commit()` in `sequencer.c`.

The change is straightforward: if the operation is not an interactive rebase (`!is_rebase_i(opts)`), the function now returns early after calling `do_pick_commit()`, avoiding repeated calls to `is_rebase_i()` in the rest of the function. The remaining logic is restructured with `else if` chains to make the mutual exclusivity of the conditions clearer. The patch does not alter behavior—it just makes the code easier to follow and maintain.

This refactoring is part of a larger effort to clean up the sequencer’s control flow before introducing the core fix in later patches. It’s a small, well-motivated change that doesn’t stand out on its own but is a necessary step in the series. If you’re following the rebase-dropped-commit thread, this patch is worth noting as part of the preparatory work, but it’s not the main event. The real action comes in patches 10 and 11, where the behavioral change is introduced.
