This is the **second patch in Patrick Steinhardt's 13-patch refactoring series** to separate repository discovery from setup in Git's core code. The patch moves the logic for marking a worktree as "bogus" (due to conflicting `core.bare` and `core.worktree` settings) from `setup_explicit_git_dir()` into `apply_repository_format()`. This prepares for later patches where `setup_explicit_git_dir()` will no longer receive a `struct repository` as input, making it impossible to set the "bogus" flag there.

Key changes:
- The patch explicitly unsets `core.worktree` when the `GIT_WORK_TREE` environment variable is set, preventing false warnings about bogus configurations (since the environment variable overrides the repo config).
- The warning message and bogus-flag logic are now handled in `apply_repository_format()`, which is called earlier in the setup process.
- The diff touches only `setup.c`, with 21 insertions and 16 deletions, primarily reordering conditional blocks and adding a comment to clarify the environment variable override.

The change is mechanical but critical for the series' goal of decoupling discovery and setup. It introduces no behavior changes but ensures the "bogus worktree" flag is set at the right phase. The commit message clearly explains the rationale and edge case (environment variable override), though the typo in "exlicitly" (should be "explicitly") is a minor nit.

This patch is unlikely to be controversial but may prompt discussion about whether `apply_repository_format()` is the right place for this logic long-term, given the series' broader refactoring goals. The new `struct repo_discovery` (introduced in later patches) could further clarify this separation.
