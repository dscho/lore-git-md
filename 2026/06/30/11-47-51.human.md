This is the **twelfth patch in Patrick Steinhardt's 13-patch refactoring series** to separate repository discovery from setup in Git's core code. The series is part of the broader `the_repository` removal effort and aims to consolidate repository configuration logic.

This patch **adds an explicit `worktree` parameter to `init_db()`**, eliminating the need to propagate the worktree via `set_git_work_tree()` before calling `init_db()`. The change aligns with the series' goal of centralizing repository configuration: now, all setup (gitdir, worktree, and repository format) happens in one place. The patch updates callers in `builtin/clone.c` and `builtin/init-db.c` to pass the worktree directly, simplifying the code and removing redundant state management.

The diff is straightforward: `init_db()` gains a `worktree` parameter, and the function calls `set_git_work_tree()` internally if the worktree is provided. The patch also cleans up edge cases in `cmd_init_db()`, such as handling bare repositories with `--separate-git-dir` (now properly rejected) and computing the default worktree path (now passed directly to `init_db()` instead of being set globally first).

This is a **well-motivated cleanup** that fits neatly into the series. The commit message clearly explains the rationale, and the changes are minimal and focused. No behavior changes are intended, but the patch reduces the risk of partially configured repositories by ensuring all setup happens in one place. The patch looks ready for review, though it may spark discussion about whether `init_db()`'s growing parameter list (now 9 arguments) should be refactored into a struct in the future.
