This is the **cover letter for an 11-patch series** that fixes the same bug as Uwe Kleine-König’s earlier patch—incorrectly copying notes from dropped commits during rebase—but takes a different technical approach. Phillip Wood, who previously identified systemic issues in the rebase machinery, now delivers the first batch of his broader audit.

The series targets a long-standing bug: when `git rebase` drops a commit (e.g., because its changes are already upstream), the sequencer incorrectly records it as "rewritten" to the current HEAD, causing notes from the dropped commit to be copied to the wrong commit. This corrupts the repository’s note history and can confuse post-rewrite hooks. Phillip’s solution avoids adding a new function parameter (as Uwe did) by instead extending the return value of `do_pick_commit()` to signal when a commit is dropped.

The patches are structured to minimize disruption. The first half (patches 1–9) are preparatory: restoring lost test coverage, fixing edge cases in external merge handling, and simplifying control flow in `pick_one_commit()`. The core fix arrives in patch 11, which introduces an enum to distinguish dropped commits and stops them from being recorded as rewritten. The series touches only `sequencer.c` and test scripts, with no on-disk format changes.

Phillip’s approach is well-motivated and addresses the same issues Uwe raised, plus additional edge cases (e.g., fixup sequences, external merge failures). The series is **tested-level**: it includes new tests for the apply backend (patch 1), post-rewrite hooks (patch 4), and interactive rebase (patch 3). The commit messages are detailed, explaining both the "what" and the "why" of each change.

This looks like a **serious, well-crafted effort** to fix a real bug while improving the sequencer’s robustness. The series is likely to supersede Uwe’s standalone patch, though it’s unclear whether Junio will merge it before or after Phillip’s follow-ups for the remaining rebase-dropped-commit bugs (edit commands, skip operations, final fixup cleanup). If you care about rebase correctness or notes handling, this series is worth following.
