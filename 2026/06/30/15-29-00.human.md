This is the **tenth patch in Phillip Wood’s 11-patch series** that overhauls how `git rebase` handles dropped commits. The series targets a long-standing bug where notes from dropped commits are incorrectly copied to the current HEAD, corrupting note history.

This patch replaces the integer return value of `do_pick_commit()` (where `-1` means error, `0` means success, and `1` means conflicts) with an **enum-based type** (`enum pick_result`). The new enum (`PICK_RESULT_ERROR`, `PICK_RESULT_OK`, `PICK_RESULT_CONFLICTS`) makes the code more readable and prepares the ground for the next patch, which will add a `PICK_DROPPED` value to represent commits that are dropped because they become empty. The change is purely internal: no user-visible behavior is altered yet.

The patch touches only `sequencer.c`, updating the function signatures and return-value handling in `do_pick_commit()`, `pick_one_commit()`, and `single_pick()`. The conversion is mechanical but thorough, replacing every integer check with the corresponding enum value. The commit message notes that the code still uses `return error(...)` for errors, leveraging C’s lax enum typing.

This is a **refactoring patch** that looks clean and well-motivated. It directly addresses the maintainability concerns raised in earlier review and sets up the final patch in the series to introduce the `PICK_DROPPED` state. The patch is part of a larger, well-structured effort that has already addressed Junio’s earlier feedback, so it is likely to land as-is.
