This is **patch 5/13** in Patrick Steinhardt’s refactoring series to separate repository discovery from setup in Git’s core code. The patch introduces `struct repo_discovery`, a new data structure that holds the results of repository discovery (gitdir and worktree paths) before they are applied to the repository object. This is the first concrete step toward splitting repository setup into two distinct phases: discovery (finding the repository location and format) and configuration (applying those results to the repository object).

The patch replaces the existing `setup_explicit_git_dir()`, `setup_discovered_git_dir()`, and `setup_bare_git_dir()` functions with new `repo_discover_*` variants that populate a `struct repo_discovery` instead of partially configuring the repository. The main entry point, `setup_git_directory_gently()`, now uses these new functions to populate the discovery structure, then applies the results to the repository object in a single, explicit step at the end. This eliminates the interleaved discovery-and-setup pattern that made the code hard to follow and distributed repository configuration across multiple functions.

Key technical details:
- New symbols: `struct repo_discovery`, `repo_discovery_release()`, `repo_discovery_set_gitdir()`, `repo_discovery_set_worktree()`, `repo_discover_explicit_gitdir()`, `repo_discover_implicit_gitdir()`, `repo_discover_bare_gitdir()`, `repo_discovery_find_dir()` (renamed from `setup_git_directory_gently_1()`).
- Files touched: `setup.c` (155 lines changed, 98 insertions, 57 deletions).
- The patch does not change behavior but lays the groundwork for consolidating repository configuration into `repo_init()` in later patches.
- The `struct repo_discovery` is currently minimal (gitdir and worktree), but the commit message hints that it will be extended to include prefix and other discovery results in future patches.

The patch is well-structured and aligns with the series’ goal of making repository setup more modular and self-contained. The commit message clearly explains the motivation and the new two-phase approach, and the code changes are mechanical but thorough. The main open question is whether the `struct repo_discovery` API will be sufficient for future setup logic, particularly around edge cases like `nongit_ok`, worktree configuration, and shallow file interactions. Reviewers familiar with repository setup (e.g., Jeff King, Taylor Blau, René Scharfe) are likely to focus on these aspects.
