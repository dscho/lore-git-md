This is the fourth patch in Patrick Steinhardt’s now-merged five-patch series adding reference-writing subcommands to `git refs`. It introduces the `git refs create` subcommand, which provides an explicit atomic way to create a new reference that must not already exist.

The patch adds 52 lines to `builtin/refs.c` to implement the subcommand, 5 lines to `Documentation/git-refs.adoc` to document it, and 151 lines of new test coverage in `t/t1466-refs-create.sh`. The implementation mirrors the design decisions already settled in the series: it supports `--message=<reason>` for reflog entries, `--no-deref` for symbolic reference handling, and `--create-reflog` to force reflog creation. The subcommand rejects creation if the reference already exists, enforcing atomic "must not exist" semantics that complement the implicit creation behavior of `git refs update`.

The test script thoroughly validates the subcommand’s behavior, including edge cases like invalid object IDs, null object IDs, empty messages, and symbolic reference handling. The only change in the v3 reroll was a typo fix in the error message ("null new object ID" instead of "null old object ID"), which was the sole reason for the reroll. The patch is uncontroversial and technically complete, with no open questions or deferred work specific to this subcommand.
