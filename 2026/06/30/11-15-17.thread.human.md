The issue centers on how `git blame -b` (which shows boundary commits as blank rather than with a caret) still reserves an extra nibble in commit hash abbreviations, causing non-boundary commits to display one character longer than the user's `core.abbrev` setting. The author works around this with an alias but suggests a `blame.abbrev` config key would be a cleaner fix.

The report is framed as a question—whether `git blame` should stop reserving the extra nibble—but effectively serves as a feature request for more consistent abbreviation behavior. It’s a narrow, self-contained issue touching only the output formatting logic in `git blame`, with no prior discussion or patches provided.
