This is a bugfix patch from Jeff King (Peff) that adjusts the test harness to redirect LeakSanitizer (LSan) error output from stdout to stderr. It is the first patch in a two-patch series targeting memory leaks in Git.

The patch fixes a minor but annoying issue where LSan reports were being misinterpreted as invalid TAP output when running tests under `prove`, causing the harness to complain about syntax errors. The change is small—just three lines in `t/test-lib.sh`—and purely infrastructural, with no impact on Git's user-visible behavior. The fix ensures LSan errors now go to stderr (specifically, descriptor 4, which respects verbose output settings), making test failures easier to diagnose.

This is a well-scoped, low-risk cleanup. The commit message clearly explains the problem and the solution, and Peff confirmed the fix works as intended with manual testing. The patch is part of an ongoing effort to address memory leaks, though this particular issue was discovered opportunistically rather than through a systematic audit. No controversy or open questions are evident; this looks like a straightforward improvement.
