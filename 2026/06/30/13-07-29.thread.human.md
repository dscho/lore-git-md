This thread is about a patch from Jan Palus that removes what he believed was a spurious Makefile dependency, preventing the Rust static library from rebuilding unnecessarily when the main Git C library changes. The patch was initially seen as a straightforward build optimization, but Brian m. carlson’s review has upended that view.

Brian explains that the dependency is not spurious at all: the Rust code in `src/hash.rs` actually relies on C functions from `libgit.a`, and removing the dependency would break `cargo test`. He also notes that future Rust code will depend even more on the C library, making the dependency intentional and necessary. The absence of this dependency in the Meson build system is now considered an oversight rather than confirmation of the patch’s correctness.

The thread is now at a crossroads. The patch as written would introduce a build regression, so it cannot proceed without addressing the linkage issue—either by fixing the Rust code to avoid the dependency or by ensuring the Meson build system also enforces it. No further reviews or alternative solutions have been proposed yet, leaving the next steps unresolved. The broader Rustification effort remains the context, but this specific patch will need reworking before it can move forward.
