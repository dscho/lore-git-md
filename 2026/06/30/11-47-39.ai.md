This is a **refactoring** series from Patrick Steinhardt, part of the ongoing effort to clean up Git's repository setup code. The goal is to separate repository *discovery* (finding the repository location and format) from *setup* (configuring the repository object), which are currently intertwined in `setup.c`. The series introduces a new `struct repo_discovery` to hold discovery results, making the two phases distinct and self-contained.

The motivation is to eventually consolidate repository configuration into `repo_init()`, reducing scattered setup logic. The series touches core files like `setup.c`, `repository.c`, and several built-ins (`clone`, `init-db`, `rev-parse`), with 13 patches totaling ~280 lines changed. It builds on recent work like `ps/setup-drop-global-state` (part of the `the_repository` removal effort) and `jk/repo-info-path-keys`.

Key changes include:
- Renaming `check_repository_format_gently()` to clarify its role.
- Moving the prefix and worktree configuration into the discovery phase.
- Making `setup_git_env_internal()` more modular.
- Dropping redundant global state (e.g., the static `cwd` variable).

The series is well-structured, with each patch addressing a specific concern. The commit messages are clear, and the changes align with Patrick's long-term refactoring goals (e.g., ODB abstraction, `the_repository` removal). No behavior changes are intended, but the separation could expose edge cases in repository initialization.

**Technical details for follow-up discussion**:
- New `struct repo_discovery` holds discovery results (format, paths, prefix).
- `apply_repository_format()` now marks bogus worktrees explicitly.
- `init_db()` gains a worktree parameter.
- `set_git_work_tree()` is marked file-local.
- Files touched: `setup.c` (major rewrite), `repository.h` (new fields), and built-ins for call-site adjustments.
- Related prior work: `ps/setup-drop-global-state`, `jk/repo-info-path-keys`.

This is a foundational refactor likely to generate discussion about the new `repo_discovery` API and its implications for future setup logic.
