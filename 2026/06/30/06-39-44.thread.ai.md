Subject: [PATCH 0/2] fix memory leaks in format-patch and test harness
Series version: v1 (initial submission)
Originating author: Jeff King (Peff)
Thread type: bugfix patch series

Core problem or goal
Fix two memory leaks: one in `git format-patch` (`prepare_bases()` in `builtin/log.c`) and one in the test harness (LSan error output misdirected to stdout instead of stderr, causing TAP parse errors with `prove`). The leaks are small, self-contained, and discovered opportunistically rather than as part of a systematic audit. The `format-patch` leak has existed since the `--base` option was introduced in 2016 (commit `fa2ab86d18`) but only became detectable after other leaks were fixed, making it stand out in LeakSanitizer (LSan) reports.

Current status
Series is at v1; no prior iterations. Both patches are mechanical, low-risk, and touch only two files (`builtin/log.c` and `t/test-lib.sh`). The test harness fix (patch 1/2) addresses an infrastructural annoyance where LSan reports were misinterpreted as invalid TAP output, cluttering test summaries. The `format-patch` fix (patch 2/2) adds a single `release_revisions()` call to free a `rev_info` struct allocated in `prepare_bases()`. Patrick Steinhardt’s review confirms the fix is correct and notes no other early returns need adjustment. No user-visible behavior changes.

Key technical details
- Files: `builtin/log.c` (one line: `release_revisions(&revs)` call in `prepare_bases()`), `t/test-lib.sh` (three lines: redirect LSan output to stderr via descriptor 4).
- Functions: `prepare_bases()`, `release_revisions()`, `check_test_results_san_file_()`.
- Symbols: `rev_info` struct (leaked, now freed via `release_revisions()`), `topo_walk_info` (allocated when commit-graph is present).
- Trigger condition: commit-graph support (`GIT_TEST_COMMIT_GRAPH=1`) exercises the revision machinery’s topological walk, exposing the leak.
- Related commits: `fa2ab86d18` (introduced `--base` option in 2016), `389c83025d` (recent `prove` TAP parsing change affecting test harness).
- No new CLI options, config keys, or on-disk format changes.
- Test coverage: existing test suite (`t4014-format-patch.sh`) exercises the fixed paths; no new tests added. The test harness change preserves verbose-logging behavior while fixing TAP parse errors.
- CI proposal: Patrick Steinhardt suggests enabling LSan for the `linux-TEST-vars` CI job to catch similar leaks earlier, noting a ~3x slowdown but deeming it feasible for targeted use.

Open questions and loose ends
None identified for the patches themselves. The series is complete and self-contained; no follow-up work or conditional approvals are mentioned. Patrick’s CI proposal (enabling LSan for `linux-TEST-vars`) is a process improvement suggestion, not a blocker for merging.
