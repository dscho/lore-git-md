Subject: [PATCH 0/2] fix memory leaks in format-patch and test harness
Series version: v1 (initial submission)
Originating author: Jeff King (Peff)
Thread type: bugfix patch series

Core problem or goal
Fix two memory leaks: one in `git format-patch` (`prepare_bases()` in `builtin/log.c`) and one in the test harness (LSan error output misdirected to stdout instead of stderr, causing TAP parse errors with `prove`). The leaks are small, self-contained, and discovered opportunistically rather than as part of a systematic audit. The `format-patch` leak has existed since the `--base` option was introduced in 2016 (commit `fa2ab86d18`) but only became detectable after other leaks were fixed, making it stand out in LeakSanitizer (LSan) reports. The broader context is an ongoing effort to improve Git's memory hygiene, including CI infrastructure for leak detection and fixes for related leaks in bloom filters, OpenSSL SHA-1/SHA-256 contexts, and other subsystems.

Current status
Series is at v1; no prior iterations. Both patches are merged in principle: the test harness fix (patch 1/2) and the `format-patch` fix (patch 2/2) are mechanical, low-risk, and touch only two files (`builtin/log.c` and `t/test-lib.sh`). The discussion has expanded to CI infrastructure improvements for leak detection and is now fully converged. The proposal to consolidate the `linux-reftables-leaks` and `linux-TEST-vars` jobs into a single job (`linux-TEST-vars-leaks`) and drop the redundant non-leak `linux-reftable` job is agreed upon by Jeff King, Patrick Steinhardt, and Junio Hamano. The `linux-TEST-vars` job will be renamed to `linux-exotic-flags` for clarity. Junio endorsed the minimalist approach, and Peff clarified that while compiler diversity in CI can occasionally reveal latent undefined behavior (UB), such cases are rare and tools like UBSan are more effective for systematic UB detection. The original patches remain ready for merging; CI changes are procedural follow-up.

Key technical details
- Files: `builtin/log.c` (one line: `release_revisions(&revs)` call in `prepare_bases()`), `t/test-lib.sh` (three lines: redirect LSan output to stderr via descriptor 4).
- Functions: `prepare_bases()`, `release_revisions()`, `check_test_results_san_file_()`, proposed `git_hash_discard()`.
- Symbols: `rev_info` struct (leaked, now freed via `release_revisions()`), `topo_walk_info` (allocated when commit-graph is present), OpenSSL SHA-1/SHA-256 context leaks (in `csum-file.c` during aborted hash operations).
- Trigger conditions: commit-graph support (`GIT_TEST_COMMIT_GRAPH=1`) exercises the revision machinery’s topological walk, exposing the `format-patch` leak; OpenSSL SHA-1 leaks surface when Git is built with `OPENSSL_SHA1_UNSAFE` and hash operations are aborted.
- Related commits: `fa2ab86d18` (introduced `--base` option in 2016), `389c83025d` (recent `prove` TAP parsing change affecting test harness).
- CI proposal: merge `linux-reftables-leaks` and `linux-TEST-vars` into `linux-TEST-vars-leaks`, drop the redundant non-leak `linux-reftable` job, and rename `linux-TEST-vars` to `linux-exotic-flags`. Overhead benchmarked at ~3x slowdown, deemed acceptable for targeted use. SHA-256/OpenSSL leaks and compiler-specific jobs (clang/gcc) are excluded from CI expansion as too niche. Peff noted that while compiler diversity can occasionally reveal UB, such cases are rare and UBSan is a more effective tool for systematic UB detection.
- No new CLI options, config keys, or on-disk format changes.
- Test coverage: existing test suite (`t4014-format-patch.sh`) exercises the fixed paths; no new tests added. The test harness change preserves verbose-logging behavior while fixing TAP parse errors.

Open questions and loose ends

- **OpenSSL SHA-1/SHA-256 leaks**: Peff has draft patches for exposing a `git_hash_discard()` primitive in each hash implementation’s API to free OpenSSL contexts. The patches need polishing, and SHA-256 support is untested under LSan. This is follow-up work, not part of the current series.
- **Bloom filter leaks**: Peff reports patches for these have already been sent (affecting `t0095`, `t4013`, `t4211`), but their status is not detailed in this thread.
- **Unrelated LSan failures**: Patrick Steinhardt noted leaks in `t3451`, `t3452`, `t3453` (attributed to `git-history` and missing `repo_unuse_commit_buffer()` calls), but these are outside the scope of this series.
