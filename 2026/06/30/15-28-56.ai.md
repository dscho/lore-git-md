This is the sixth patch in Phillip Wood’s 11-patch **bugfix series** targeting the sequencer’s handling of dropped commits during rebase. The patch **simplifies control flow** in `pick_one_commit()` by removing a redundant conditional check that became unnecessary after earlier refactorings.

The change is small and surgical: after patches 4 and 5 eliminated all positive return values from `do_pick_commit()` except `1`, the `if (res == 1)` guard around `intend_to_amend()` is no longer needed. The patch removes the guard and updates `error_failed_squash()` to pass `1` (indicating an error) as the final argument to `error_with_patch()`, matching the new control flow. This is a **pure refactoring** with no behavior change; the intent is to reduce cognitive overhead before introducing the `PICK_DROPPED` enum in later patches.

The patch touches only `sequencer.c` and is well-motivated by the series’ overall goal of making the sequencer’s logic more maintainable. The commit message clearly explains the reasoning: the early return introduced by commit `e032abd5a0` (2023-09-06) ensures that `res` is positive when entering the conditional block, and the prior patches guarantee that the only positive value is `1`. This is a **substantive cleanup** that directly supports the series’ core behavioral change, and it reflects Phillip’s thorough understanding of the sequencer’s control flow. No test changes are needed because the patch does not alter behavior.
