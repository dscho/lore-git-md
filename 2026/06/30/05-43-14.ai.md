This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Jeff King (Peff) responds to Patrick Steinhardt’s proposal to convert `USE_NSEC` from a build-time option to a runtime-configurable setting (like `core.ignoreCase`). Peff agrees in principle but highlights a key technical hurdle: **there is no reliable, portable way to auto-detect whether a filesystem preserves nanosecond timestamps**. The proposed detection sequence—writing a file, flushing the kernel’s inode cache, and re-reading the timestamp—is impractical for routine use (e.g., during `git init`), and Peff was unable to reproduce timestamp truncation even on filesystems where it was historically problematic. While he endorses the idea of a runtime config knob (e.g., `core.useNsec`) as more user-friendly than a build-time option, he does not propose a concrete implementation or address how to handle the default value (e.g., `true` on modern Linux, `false` elsewhere). The discussion now hinges on whether the project is willing to accept the complexity of runtime configuration without auto-detection, or if the build-time knob should remain as a simpler (if less flexible) solution.

Key technical details:
- **Subsystems touched**: `git-config` machinery, `git-init`, and potentially filesystem detection code (though Peff’s testing suggests the latter is not currently feasible).
- **Proposed runtime config knob**: `core.useNsec` (boolean, default TBD).
- **Auto-detection challenge**: No portable way to flush the kernel’s inode cache or verify timestamp preservation without disruptive operations (e.g., unmounting/re-mounting).
- **Behavior change**: If implemented, `USE_NSEC` would no longer be a build-time macro but a runtime setting, enabling users to opt into nanosecond resolution on a per-repository basis.
- **Unresolved questions**: Should the default be `true` on platforms where Peff’s testing showed no issues (e.g., modern Linux), or `false` to avoid interoperability risks? How would this interact with existing build-time settings (e.g., Autotools/Makefile `USE_NSEC`)?

The thread remains in the design phase, with no patch yet submitted for runtime configuration. Peff’s feedback suggests that while the goal is desirable, the implementation may require trade-offs between flexibility and simplicity. The discussion is now focused on whether the project prefers a runtime knob with a conservative default (to avoid breaking edge cases) or retains the build-time option as a simpler (if less user-friendly) solution.
