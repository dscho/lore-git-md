This thread is about a bugfix patch that addresses a long-standing case-sensitivity issue in Git's config parser. The problem occurs when updating values in old-style `[section.subsection]` config headers: the parser lowercases subsections during parsing but preserves original case when matching keys from the command line, causing `git config section.Subsection.key value` to fail if the subsection contains uppercase letters. This results in duplicate entries instead of value updates.

The patch, which touches `config.c`, `git-config.adoc`, and `t1300-config.sh`, introduces a `subsection_case_sensitive` flag in `struct config_store_data` and modifies the `matches()` function to use case-sensitive or case-insensitive comparison based on the flag. It also removes the now-obsolete BUGS section from the documentation and updates tests to reflect the fixed behavior. Junio C Hamano, the maintainer, has redirected the review to Johannes Schindelin (Dscho), who originally authored the affected code around 2018. This suggests Dscho's feedback may be particularly influential.

So far, the patch has no review trailers or maintainer decisions, and Junio's routing message did not include technical feedback. The patch remains unchanged and appears well-motivated, with clear commit messaging and focused changes. The next step is awaiting substantive review from Dscho or other domain experts. If no objections are raised, this fix is likely to proceed smoothly toward integration.
