This is the latest exchange in Justin Tobler’s six-patch series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The thread is now in **v2 planning** with all blocking feedback addressed; this email is Patrick Steinhardt’s **substantive follow-up review** of the final patch (6/6), focusing on two narrow but important design points.

Patrick questions whether the `ODB_TRANSACTION_RECEIVE` flag — introduced to preserve `receive-pack`’s eager directory creation and “incoming” prefix naming — is truly necessary. He suggests that the internal naming of temporary directories is not part of Git’s stable interface and could be simplified in a future series, removing the need for the flag. Justin agrees the flag is only needed to retain existing prefixes, but defers the discussion to keep the current series focused.

The second point is about **parameter-passing consistency**: the patch sometimes passes the transaction as an explicit parameter and sometimes accesses it via `the_repository`. Patrick finds this inconsistent; Justin acknowledges the churn of wiring the parameter through all call sites and suggests using a file-local global variable instead. Patrick’s reaction is initially negative but softens when he realizes the global would be confined to `builtin/receive-pack.c`, making it a reasonable compromise.

Both issues are now **resolved in principle** for v2: the flag stays for now, and the transaction will be managed via a file-local global. No new technical concerns are raised; this is a **clean, collaborative wrap-up** of the review cycle. The series remains on track for `next` once v2 is posted.
