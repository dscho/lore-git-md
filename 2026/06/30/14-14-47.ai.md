This is a short follow-up in the ODB transaction refactoring series, specifically about error-handling in patch 2/6. Justin Tobler acknowledges Patrick Steinhardt’s concern that `odb_transaction_files_prepare()` failures are silently ignored by existing callers, preserving backward compatibility but leaving a latent design flaw. Both agree this is suboptimal—transactions should fail hard if setup fails—but explicitly defer fixing it to a future series to avoid scope creep. Justin notes that the lazy directory creation (triggered during object writes) complicates error handling and plans to investigate removing it in follow-up work, though he cautions this may have performance implications.

The exchange confirms that **v2 of the series will not change runtime behavior**, only documenting the inert error propagation as a trade-off. This removes a potential blocker for integration, as the current behavior poses no regression risk. The discussion also reinforces an architectural tension: the ODB transaction layer’s single-transaction-per-ODB design (with implicit `atexit()` cleanup) contrasts with reference transactions’ multi-transaction support, a limitation flagged for later refactoring. Key technical details for future work include the `odb_transaction_files_prepare()` function, its ignored return value, and the lazy directory creation mechanism.
