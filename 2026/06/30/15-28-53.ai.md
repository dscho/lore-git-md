This is the **third patch in Phillip Wood’s 11-patch series** that overhauls how the sequencer handles dropped commits during rebase. This specific patch targets a subtle but important edge case in the external merge strategy logic.

The patch fixes a bug where the sequencer misinterprets a non-zero exit code from an external merge tool. Currently, any non-zero exit code—including codes other than 1—is treated as a conflict, which is incorrect. Some external merge tools exit with codes like 2 to indicate a failure (e.g., due to an untracked file conflict) rather than a merge conflict. In these cases, the sequencer should **reschedule the pick** rather than proceeding as if a conflict occurred. The patch also ensures that if the commit message cannot be written, the pick is rescheduled immediately rather than attempting the merge.

The change is small but precise: it modifies `do_pick_commit()` in `sequencer.c` to check the exit code of `try_merge_command()` and treat any non-1 exit code as a failure, returning -1 to trigger rescheduling. The test in `t/t3404-rebase-interactive.sh` verifies this behavior by simulating a merge tool that exits with code 2, confirming that the pick is correctly rescheduled rather than being treated as a conflict.

This patch is a **substantive bugfix** that improves the robustness of interactive rebase when using external merge strategies. It directly addresses a real-world edge case and is well-tested, making it a clear improvement over the current behavior. The change is narrowly scoped and does not introduce new complexity, fitting cleanly into the broader series’ goal of making the sequencer more reliable.
