This is the fourth patch in Phillip Wood’s 11-patch series fixing how `git rebase` handles dropped commits. It addresses a specific edge case in the sequencer: when `git commit` fails to execute (e.g., due to a missing or broken Git installation), the sequencer incorrectly reschedules the current command instead of treating the pick as successful.

The patch is a small but important robustness fix. The sequencer already writes all necessary state files before attempting to commit, so the pick itself is complete even if the commit command fails. By converting a `-1` return value from `run_git_commit()` to `1`, the patch ensures the sequencer behaves consistently with `do_merge()`, which already handles failures this way. The change is minimal—just six lines in `sequencer.c`—and does not affect the on-disk format or user-visible behavior beyond preventing an unnecessary reschedule.

This patch is part of the series’ broader refactoring of `do_pick_commit()`, which later patches will build on to introduce the `PICK_DROPPED` enum and fix the note-copying bug. The fix is well-motivated and aligns with the series’ goal of making the sequencer’s control flow more predictable. No controversy is expected, and the patch looks ready for merging as part of the larger effort.
