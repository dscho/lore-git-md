This is the second patch in Kristoffer Haugsbakk’s five-part documentation series updating the `SubmittingPatches` guidelines for trailer conventions. It explicitly discourages the use of Linux-specific trailers (`Fixes:` and `Link:`) in Git patches, explaining why they are unnecessary and how Git handles similar needs differently.

The patch adds a short but clear section to `Documentation/SubmittingPatches` that contrasts Git’s workflow with the Linux kernel’s. It explains that Git has fewer trees and less need for cherry-picking fixes (which `Fixes:` trailers help with in Linux), and that Git already tracks patch submissions via `refs/notes/amlog` rather than `Link:` trailers. The rationale is well-supported by references to Linux’s own documentation and Git’s existing practices.

This is a straightforward, uncontroversial documentation improvement. The commit message is thorough and the change itself is minimal (four lines added). It directly addresses a recurring point of confusion for contributors coming from the Linux kernel, making it a practical addition to the contributor guidelines.
