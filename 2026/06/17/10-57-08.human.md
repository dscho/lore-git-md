This is a feature patch adding the `--create-if-missing` option to both `git switch` and `git checkout`. It directly addresses the maintainer feedback from the v1 patch (`--ensure`/`-e`) by adopting the clearer long-option name and extending the feature to both commands.

The patch implements an idempotent branch-switching operation: if the target branch exists, it switches to it without resetting the tip; if the branch doesn’t exist, it creates it from the given start-point (or the current branch). The implementation handles all the edge cases raised in the earlier discussion: it rejects pathspec usage with `git checkout`, fails gracefully in detached-HEAD state when no start-point is available, and updates upstream tracking configuration when `--track` is supplied. Tests cover every scenario mentioned in the commit message, including branch creation, existing-branch switching, tracking updates, and error conditions.

The motivation remains the same as in v1—simplifying workflows where users frequently switch between topic branches of uncertain existence—but the patch now aligns with Junio’s naming preference and extends the feature to `git checkout`, which should reduce the inconsistency he flagged. The implementation is thorough, the tests are comprehensive, and the documentation is clear. This looks like a well-crafted, uncontroversial quality-of-life improvement.
