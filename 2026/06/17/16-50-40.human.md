This is a documentation patch that updates contributor guidelines to encourage more explicit discussion of review feedback before sending new patch versions. The patch modifies two key documents: `MyFirstContribution.adoc` and `SubmittingPatches`.

The change aims to make the review process more collaborative by asking contributors to explain their planned changes in email replies rather than letting code speak for itself. This helps reviewers understand the author's reasoning before seeing the next version, potentially saving time and fostering better discussion. The patch adds guidance about responding to each comment with either acceptance, rejection, or alternative proposals.

This is the first patch in a two-patch series (v2) that has already seen substantive discussion. While the `SubmittingPatches` changes in the second patch have gained consensus, this particular update to `MyFirstContribution.adoc` remains controversial. Patrick Steinhardt has pointed out that it largely restates existing content with more words, and the author is actively seeking input on whether to keep these changes.

The patch demonstrates the very practice it advocates - the author has engaged thoughtfully with review feedback and is now explicitly asking for community input before proceeding. This makes it worth watching, as the resolution will set a precedent for how Git documents its review expectations. The changes are modest but touch two of the most important documents for new contributors.
