This is the fourth patch in Patrick Steinhardt’s five-part series adding reference-writing subcommands to `git refs`. It introduces the `git refs create` subcommand, which enforces atomic "must not exist" semantics for reference creation. The patch touches the `refs/` subsystem (`builtin/refs.c`), adds a new test script (`t/t1466-refs-create.sh`), and updates the documentation (`Documentation/git-refs.adoc`).

The implementation is straightforward: `git refs create` wraps `refs_update_ref()` with a `null_oid()` check for the old value, ensuring the reference does not already exist. It supports the same options as `git refs update` (`--message`, `--no-deref`, `--create-reflog`) but rejects implicit creation or deletion via all-zero object IDs. The 151-line test script covers basic functionality (creation, error cases), symref handling, reflog behavior, and argument validation. Error messages are consistent with the rest of the series (quoted object IDs, clear failure reasons).

This patch directly addresses Junio C Hamano’s v1 feedback by providing an explicit atomic creation mechanism, resolving the asymmetry between `delete` and `create` subcommands. The implementation is uncontroversial—it mirrors the design of `git refs delete` and avoids the backwards-compatibility debate surrounding `git refs update`. The only open question is whether `--create-reflog` should be enabled by default (currently it is opt-in), but this is a minor detail compared to the broader atomicity discussion. Test coverage is thorough for the advertised behavior, though edge cases like concurrent creation attempts are not explicitly tested (likely deferred to the ref backend).

The patch is ready for review and likely to be merged as-is, pending resolution of the larger design questions in the series. Contributors interested in ref backend atomicity or the `the_repository` removal effort (Patch 1/5) may want to cross-reference this work.
