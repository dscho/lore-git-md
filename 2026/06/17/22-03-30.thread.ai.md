Subject: t4216-log-bloom.sh: TAP parse errors on non-x86 due to char signedness assumption
Series version: none (standalone bug report)
Originating author: Todd Zullinger
Thread type: bug report

Core problem or goal
The test `t4216-log-bloom.sh` assumes `char` is signed by default (true on x86) and uses `test_cmp` output to set the `SIGNED_CHAR_BY_DEFAULT` prerequisite. On architectures where `char` is unsigned, the diff output from `test_cmp` leaks into the TAP stream, causing parse errors that break the test harness. The goal is to eliminate the TAP parse errors by removing the redundant prerequisite, which is unused outside this test and whose outcome (`highbit1` runs `true` regardless) does not affect test logic.

Current status
The fix has been submitted as `[PATCH v1]` by Patrick Steinhardt, removing the `SIGNED_CHAR_BY_DEFAULT` prerequisite and its associated `test_cmp` check from `t/t4216-log-bloom.sh`. Junio C Hamano, Jeff King (Peff), and Patrick Steinhardt all agree this is the correct approach. The issue existed since mid-2024 but only became visible after the June 2026 commit `389c83025d` tightened TAP parsing strictness. No objections have been raised, and the patch is expected to be merged without further iteration.

Key technical details
- Files touched: `t/t4216-log-bloom.sh` (test script only)
