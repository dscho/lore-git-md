Subject: t4216-log-bloom.sh: TAP parse errors on non-x86 due to char signedness assumption
Series version: none (standalone bug report)
Originating author: Todd Zullinger
Thread type: bug report

Core problem or goal
The test `t4216-log-bloom.sh` assumes `char` is signed by default (true on x86) and uses `test_cmp` output to set the `SIGNED_CHAR_BY_DEFAULT` prerequisite. On architectures where `char` is unsigned, the diff output from `test_cmp` is not suppressed, causing TAP parse errors that break the test harness. The underlying question is whether the test’s behavior is correct (i.e., the Bloom filter logic is architecture-dependent) or if the test or the `test-tool read-graph bloom-filters` code is broken.

Current status
Patrick Steinhardt proposed a fix that converts the `test_cmp` check into a `test_lazy_prereq`, suppressing the diff output while preserving the current behavior (the test remains skipped on non-x86). An alternative of dropping the check entirely was also suggested but not pursued. The patch is targeted and low-risk, addressing only the TAP parse errors without altering the test’s logic or the underlying Bloom filter code. No objections or further discussion have been raised yet.

Key technical details
- Files touched: `t/t4216-log-bloom.sh` (test script only)
- Subsystem: commit-graph Bloom filters (path-change tracking in `git log`)
- Symbols: `SIGNED_CHAR_BY_DEFAULT` prerequisite, `test_lazy_prereq`, `test_cmp`, `highbit1` test case
- Behavior: On x86, `test_cmp` shows no diff and the prerequisite is set; on non-x86, the diff output (`52a9` vs. `c01f`) triggers TAP parse errors. The fix suppresses this output via `test_lazy_prereq`.
- On-disk format: none (runtime behavior issue)
- Test coverage: `t4216-log-bloom.sh` (specifically the `highbit1` test case)

Open questions and loose ends
1. Is the test’s assumption about `char` signedness correct (i.e., should the Bloom filter logic vary by platform)? This remains unresolved but is orthogonal to the immediate TAP parse error fix.
2. Could the `SIGNED_CHAR_BY_DEFAULT` prerequisite be dropped entirely, given it is only used by one test? Patrick noted this as an alternative but did not advocate for it.
