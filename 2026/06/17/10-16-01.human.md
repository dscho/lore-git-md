This is the fourth patch in Patrick Steinhardt’s five-part series adding reference-writing subcommands to `git refs`. It introduces the new `git refs create` command, which enforces atomic "must not exist" semantics for reference creation. The patch is a clean, well-tested implementation that directly addresses Junio C Hamano’s earlier concern about the lack of explicit atomic creation in the `update` subcommand.

The new subcommand mirrors the existing `delete` subcommand in structure and option handling, offering `--message`, `--no-deref`, and `--create-reflog` flags. It rejects attempts to create a reference that already exists, uses a null object ID, or has an invalid object ID, with clear error messages. The 151-line test script (`t/t1466-refs-create.sh`) covers all these cases, including symref handling, reflog creation, and message recording. The implementation delegates to `refs_update_ref()` with the appropriate flags, ensuring consistency with the rest of the ref backend.

This patch is uncontroversial in its current form and appears ready to merge. It doesn’t resolve the broader debate about whether `update` should retain its implicit creation behavior, but it provides a clear alternative for users who want atomic creation. The only minor loose end is whether error messages should consistently quote reference names (the thread summary notes this as unclear), but the patch itself is technically sound and well-documented.
