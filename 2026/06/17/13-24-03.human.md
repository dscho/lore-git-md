This is a bugfix patch addressing a long-standing issue in the sequencer subsystem where `git rebase` incorrectly copies notes from commits that are dropped during rebase. Junio C Hamano, the maintainer, has replied to the patch with a detailed review that is both substantive and surface-level.

Junio praises the core logic of the patch as "very reasonable" but raises a critical edge case: if a commit is followed by a *dropped* fixup commit, the current implementation might incorrectly map the note from the original commit to the wrong rewritten commit. This is a substantive concern that could reintroduce the very bug the patch aims to fix, albeit in a different scenario. The review is tested—Junio walks through the call chain and provides a concrete example to illustrate the potential regression.

On the surface level, Junio points out several style nits: redirection operators should not have spaces (`>file`, not `> file`), shell scripts should avoid semicolons, and tests should not write outside `$TRASH_DIRECTORY`. He also suggests using `test_must_fail` instead of manual error checking for controlled command failures. Most notably, he reiterates Phillip Wood’s earlier suggestion to integrate the test into `t3400-rebase.sh` rather than creating a new test script (`t3322-notes-rebase.sh`), framing this as a matter of test organization rather than functionality.

Junio also flags a missing documentation update: users should be informed that notes may be lost during rebase and under what conditions. This is a minor but important point for user-facing clarity.

The patch is now at a crossroads: the core fix is sound, but the edge case Junio identified needs addressing, and the test infrastructure could be streamlined. Uwe Kleine-König will likely need to send a v2 to resolve these points. The patch remains a well-motivated, focused fix for a real bug, but the review highlights that even small changes in the sequencer can have subtle ripple effects.
