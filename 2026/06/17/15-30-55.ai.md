This is a zsh completion bugfix for the `git -C <path>` global option. The patch addresses a long-standing gap in zsh's Git completion where typing `git -C <path> <command> <TAB>` would fail to offer completions for the command or its arguments. The issue stems from three hard-coded assumptions in the zsh wrapper (`__git_zsh_main`): it doesn’t recognize `-C` in its `_arguments` spec, it assumes the command is always the first argument (index 1), and it doesn’t collect `-C` paths for use by the bash helpers.

The fix adds `-C` to the `_arguments` spec, scans past leading `-C <path>` pairs to correctly set `__git_cmd_idx`, and accumulates `-C` arguments into `__git_C_args` so the bash helpers run `git` in the intended directory. The commit message notes this is intentionally scoped to `-C` but the underlying problem (hard-coded command index) affects other global options like `--git-dir`, `--work-tree`, and `-c`; the author offers to extend the fix in a follow-up if desired.

The patch touches only `contrib/completion/git-completion.zsh` (9 lines added) and is well-motivated: it restores expected behavior for a common workflow (`git -C` is widely used) and the technical approach mirrors the existing bash implementation. The code is clean and the commit message clearly explains both the immediate fix and the broader issue.
