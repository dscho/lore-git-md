This is the eighth patch in Patrick Steinhardt’s 17-part ODB abstraction series, which is completing the conversion of Git’s packed object storage into a proper `struct odb_source`. The patch is a small, targeted refactoring that replaces a direct call to the low-level `find_pack_entry()` function with the higher-level `packfile_store_read_object_info()` interface in `has_object_pack()`.

The change is functionally equivalent but future-proofs the code: `find_pack_entry()` will eventually be made file-local to `odb/source-packed.c`, so this patch ensures `has_object_pack()` continues to work without relying on an internal implementation detail. The new interface (`packfile_store_read_object_info()`) already calls `find_pack_entry()` internally and simply returns early if no object info pointer is provided, which matches the original behavior exactly.

This is a clean, mechanical adjustment that aligns with the series’ broader goal of encapsulating packed object storage behind the ODB abstraction. The commit message clearly explains the motivation and the equivalence of the old and new approaches. No behavioral changes or edge cases are introduced, and the patch is unlikely to be controversial. It’s a straightforward step toward the larger architectural cleanup.
