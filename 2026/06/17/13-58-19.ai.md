This is a bugfix patch for the sequencer subsystem, addressing a regression in how Git handles notes during rebase when commits are dropped because their changes are already present. The patch is a follow-up to Junio C Hamano’s review, in which Uwe Kleine-König responds to feedback but does not yet resolve all outstanding issues.

Uwe acknowledges Junio’s concerns about the fixup-commit edge case—where a non-dropped commit followed by a dropped fixup could incorrectly map notes to the wrong rewritten commit—but expresses uncertainty about how to address it, suggesting the problem might be better handled by someone with deeper Git internals knowledge. He also concedes the test script style issues (redirection spacing, avoiding `@` for `HEAD`, and not writing outside `$TRASH_DIRECTORY`) and adopts Junio’s suggestion to use `test_must_fail` for asserting command failure. However, he pushes back on the need for documentation, arguing that it should be self-evident that notes disappear when their commits are dropped, though he acknowledges this may be subjective.

The patch still touches `sequencer.c` and the test script (now with style fixes), but the core logic remains unchanged. The unresolved edge case and lack of documentation updates mean the patch is not yet ready for merging, despite the underlying issue being real and the approach generally sound. The test script’s location (whether to keep it in `t3322-notes-rebase.sh` or move it to `t3400-rebase.sh`) is still open, though Uwe now agrees with Junio’s reasoning for consolidation.

Key technical details remain: the `dropped_commit` flag in `do_pick_commit()`, the skipped note-copying logic, and the test coverage for the already-present-changes edge case. The fixup-commit scenario is still untested and unresolved.
