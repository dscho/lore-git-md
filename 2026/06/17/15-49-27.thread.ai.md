Subject: [PATCH 0/2] libify `ignore_case` into `struct repo_config_values`
Series version: v3 (cover letter plus two patches), now merged
Originating author: Justin Tobler (patch 1/2), Tian Yuchen (patch 2/2)
Thread type: patch series (refactoring / libification)

Core problem or goal
Move the global `ignore_case` variable into `struct repo_config_values` to eliminate a global and tie the configuration value to the repository instance it was read from. This continues the `the_repository` removal initiative by encapsulating another piece of repository-specific state without altering its eager-parsing behavior.

Current status
Series is **merged** (Junio C Hamano accepted v3 with "Looks good" on YYYY-MM-DD). The two patches introduce the `repo_ignore_case()` getter, add the `ignore_case` field to `struct repo_config_values`, and migrate all usage sites. All prior review feedback has been addressed: the getter uses `repo->initialized` to match the pattern established by `protect_hfs` and `protect_ntfs`, and the cover letter was updated to clarify the rationale behind the getter approach and the reasons Derrick Stolee’s earlier attempt failed. The Windows compatibility layer’s dependency on `repository.h` was explicitly approved by the maintainer and confirmed as correct by Johannes Schindelin (Dscho), the Git for Windows maintainer. The procedural follow-up confirmed that CC’ing Dscho on changes to `compat/win32/path-utils.c` was the correct etiquette. The series is fully aligned with project conventions and ready for integration.

Key technical details
- New symbol: `repo_ignore_case()` getter function
- Files touched: `environment.c`, `environment.h`, `read-cache.c`, `name-hash.c`, `dir.c`, `compat/win32/path-utils.c`, and 9 built-in commands (`fetch`, `mv`, `add`, `checkout`, `diff`, `ls-files`, `merge`, `reset`, `rm`)
- Subsystems affected: index, filesystem operations, Windows compatibility layer, built-in commands
- No new tests added; existing test coverage retained
- Builds on prior work migrating `protect_hfs` and `protect_ntfs`
- Introduces a dependency on `repository.h` in `compat/win32/path-utils.c` (approved by maintainer and confirmed by Dscho)
- Performance note: repeated getter calls in `dir.c` (e.g., in `git_fspathcmp`, `fspatheq`, `directory_exists_in_index`) may introduce measurable overhead, but the authors justify this as a necessary trade-off for eliminating global state
- Design resolution: the getter includes a `repo->initialized` check, returning the default value (0) when `repo->initialized` is false, matching the behavior of the other three getters. All four getters now consistently check `repo->initialized` instead of `repo->gitdir`.
