Originating author: Justin Tobler
Thread type: patch series (refactoring / libification)

Core problem or goal
Move the global `ignore_case` variable into `struct repo_config_values` to eliminate a global and tie the configuration value to the repository instance it was read from. This continues the `the_repository` removal initiative by encapsulating another piece of repository-specific state without altering its eager-parsing behavior.

Current status
Series is at v1, unmerged. Patch 1/2 (this email) introduces the new field and getter; patch 2/2 will update all call sites. The author has addressed one of the three RFC questions (correctness of fallback logic during early initialization) by clarifying the getter’s design in the commit message.

Key technical details
- New symbol: `repo_get_ignore_case()` getter function
- Files touched so far: `environment.c`, `environment.h`
- Files to be touched in patch 2/2: 13 more, including `read-cache.c`, `name-hash.c`, `dir.c`, `compat/win32/path-utils.c`, and commands like `git fetch` and `git mv`
- Subsystems affected: index, filesystem operations, Windows compatibility layer
- No new tests added; existing test coverage retained
