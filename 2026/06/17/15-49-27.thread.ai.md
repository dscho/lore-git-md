Subject: [PATCH 0/2] libify `ignore_case` into `struct repo_config_values`
Series version: v1 (complete; both patches now posted)
Originating author: Justin Tobler (patch 1/2), Tian Yuchen (patch 2/2)
Thread type: patch series (refactoring / libification)

Core problem or goal
Move the global `ignore_case` variable into `struct repo_config_values` to eliminate a global and tie the configuration value to the repository instance it was read from. This continues the `the_repository` removal initiative by encapsulating another piece of repository-specific state without altering its eager-parsing behavior.

Current status
Series is at v1, unmerged, and now complete. Patch 1/2 introduces the new field and getter; patch 2/2 updates all 14 call sites across core Git subsystems, the Windows compatibility layer, and built-in commands. The author has addressed two of the three RFC questions (early-initialization robustness and Windows layering) in the commit messages; the remaining question (performance overhead in `dir.c`) is acknowledged but not mitigated in this iteration.

Key technical details
- New symbol: `repo_get_ignore_case()` getter function
- Files touched: `environment.c`, `environment.h`, `read-cache.c`, `name-hash.c`, `dir.c`, `compat/win32/path-utils.c`, and 9 more built-in commands (`fetch`, `mv`, etc.)
- Subsystems affected: index, filesystem operations, Windows compatibility layer, built-in commands
- No new tests added; existing test coverage retained
- Builds on prior work migrating `protect_hfs` and `protect_ntfs`
- Introduces a dependency on `repository.h` in `compat/win32/path-utils.c` to avoid refactoring function signatures
- Performance note: repeated getter calls in `dir.c` may introduce measurable overhead, but the author justifies this as a necessary trade-off for eliminating global state

Open questions and loose ends
1. Performance overhead in `dir.c` due to repeated getter calls (acknowledged but not addressed in this version)
2. Whether the getter’s current design (skipping `repo->gitdir` checks) is the most robust approach for early initialization (author argues it is sufficient in the commit message)
