This is Junio's biweekly "What's cooking in git.git" report for June 2026, summarizing the state of all in-flight topics. The Git 2.55 release cycle is in its final stabilization phase, with -rc1 already tagged, so the focus is on reviewing and merging important fixes rather than new features.

Several topics graduated to 'master' this cycle, including performance optimizations like `ab/index-pack-retain-child-bases` (retaining child bases in the delta cache) and `kk/streaming-walk-pqueue` (using a priority queue for non-limited streaming walks). The `the_repository` removal effort continues with `jd/unpack-trees-wo-the-repository`, and Windows compatibility saw improvements in `js/win-kill-child-more-gently` (gentler child process killing) and `js/osxkeychain-build-wo-rust` (build fix for OSX keychain without Rust).

New topics of note include `mh/fetch-follow-remote-head-config`, which adds a `fetch.followRemoteHEAD` configuration to control whether `git fetch` should set `FETCH_HEAD` to the remote's HEAD ref. This is a user-facing feature that may interest those working with remote tracking branches. `ps/refs-writing-subcommands` extends the `git refs` toolbox with new subcommands (`create`, `delete`, `update`, `rename`) for managing refs programmatically, which could be useful for scripting and automation.

The `po/hash-object-size-t` and `js/objects-larger-than-4gb-on-windows-more` topics address long-standing limitations around handling objects larger than 4GB on Windows and other LLP64 platforms, converting various size-related variables from `unsigned long` to `size_t`. These are important correctness fixes for repositories with very large objects.

Several refactoring efforts are in progress, including `ps/setup-drop-global-state` (continuing the removal of global state in setup.c) and `ps/refs-avoid-chdir-notify-reparent` (converting ref backends to use absolute paths). The `ps/odb-source-packed` topic refactors the packed object source into a proper `struct odb_source`, part of Patrick Steinhardt's ongoing ODB abstraction work.

Notable stalled topics include `jt/config-lock-timeout` (configurable lock retry timeout) and `ds/config-no-includes` (ignoring config includes via environment variable or CLI option), both of which have seen review feedback but no recent updates. The `ps/cat-file-remote-object-info` topic, which adds a `remote-object-info` command to `git cat-file --batch-command`, is awaiting a reroll after review feedback.

The `mm/diff-process-hunks` topic introduces a `diff.<driver>.process` configuration to allow external tools to act as hunk providers, which could enable interesting integrations with external diff tools. This is a potentially powerful but complex feature that may generate discussion.

For those following the experimental `git history` command, `ps/history-drop` adds a new `drop` subcommand to remove a commit and replay its descendants, similar to `git rebase --no-rebase-merges`. This is part of the ongoing effort to provide more flexible history editing tools.

The report also includes several documentation updates, including `kh/submittingpatches-trailers` (updates to trailer documentation in SubmittingPatches) and `ps/doc-recommend-b4` (recommending the use of `b4` for patch submission).

Overall, this "What's cooking" report shows a project in a stabilization phase, with a mix of performance optimizations, platform compatibility fixes, and ongoing refactoring efforts. The most user-visible changes are likely to be the new `fetch.followRemoteHEAD` configuration and the extended `git refs` subcommands.
