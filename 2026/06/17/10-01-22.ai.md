This is the latest review feedback in Harald Nordgren’s `git branch --delete-merged` series (v15), which has been evolving for 15 iterations to provide safe, automated cleanup of local branches whose work has landed upstream. Phillip Wood’s email is a procedural and technical checkpoint rather than a deep code review: he flags two specific issues that must be fixed before the series can move forward, and he advises Harald to wait for further feedback before sending another version to avoid list churn.

The blocking issues are both in the **API consistency** layer:

1. **Flags unpacking in `delete_branches()`**: The function currently unpacks all flags except `force` at the start, which Phillip calls “a bad idea”. The intent of the flags-based API was to future-proof the function by making every flag visible at the top, so the rest of the function doesn’t need to know about changes in the argument list. Leaving `force` unpacked later violates that principle and risks accidental regressions if the API evolves further.

2. **Boolean `dry_run` parameter in `delete_merged_branches()`**: The function still takes a boolean `dry_run` argument instead of using the flags-based API that `delete_branches()` now expects. This inconsistency forces callers to know about two different calling conventions, which Phillip has previously identified as a blocker.

Both issues are mechanical and uncontroversial; they simply need to be aligned with the rest of the series’ flags-based design. Once these are fixed, the series will be ready for final test integration and review. The test suite overhaul (shared fixtures, consolidated assertions, realistic workflows) is already scoped and in progress, so the only remaining work is the API cleanup.
