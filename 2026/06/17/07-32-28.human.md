This is a documentation patch discussion about Git’s commit message trailer conventions. The email is a reply in the ongoing thread updating `Documentation/SubmittingPatches` to clarify trailer usage.

Patrick Steinhardt responds to Kristoffer Haugsbakk’s proposal to either drop or simplify the mention of non-identity trailers (e.g., `Closes: <bug>`). Kristoffer had argued these trailers are rare in Git’s history and mostly relevant to downstream projects, backing this with `git log` analysis showing only `Change-Id`, `Message-ID`, and `Fixes` appear frequently. Patrick now agrees: since Git itself doesn’t use trailers like `Closes:` or issue-tracker links, the documentation should omit them entirely rather than risk confusing newcomers with irrelevant examples.

The exchange resolves one of the last open questions in the series. The v2 revision will likely remove the vague reference to non-identity trailers, keeping the focus on Git’s actual practices. This aligns with the series’ goal of providing clear, actionable guidance while avoiding over-generalization. The remaining work for v2 is now limited to previously agreed typo fixes and clarifications.
