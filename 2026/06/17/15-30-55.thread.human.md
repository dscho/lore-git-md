This thread fixes a long-standing bug in Git’s zsh completion script, where commands or arguments wouldn’t complete correctly when global options like `-C <path>` or `--git-dir` were used. The issue was that the zsh wrapper (`git-completion.zsh`) hardcoded assumptions about command positions, unlike the bash implementation, which handles global options flexibly.

Lutz Lengemann’s v2 patch resolves this by scanning past all global options (not just `-C`) and their arguments to set the correct command index, mirroring the bash script’s behavior. The fix is small (25 lines) but effective, enabling completions for constructs like `git -C <path> checkout <TAB>` or `git -p checkout <TAB>`. D. Ben Knoble’s thorough review confirmed the patch works as intended, with no regressions, though he noted minor quirks (e.g., incomplete `-C` entries in edge cases) that match the bash implementation’s behavior. Junio’s earlier feedback about architectural alignment was fully addressed in v2.

Two documented limitations remain: (1) the `-c` option is still missing from the zsh `_arguments` spec, and (2) `--git-dir` only supports `--git-dir=<path>` (not `--git-dir <path>`). Both are deferred to follow-ups, as is directory completion for chained `-C` options (e.g., `git -C dir -C <TAB>`). An unrelated pre-existing bug (`git -<TAB>` producing redundant output) is also left for a separate patch. The patch is now effectively unblocked, with no further changes needed before merging. It’s a targeted, high-impact improvement for zsh users.
