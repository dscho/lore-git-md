The zsh Git completion script had a long-standing bug where it failed to complete commands or arguments when global options like `-C <path>`, `--git-dir`, or `-p` were used. Lutz Lengemann posted a patch to fix this by making the zsh wrapper (`contrib/completion/git-completion.zsh`) handle these options consistently with the bash implementation. After two iterations, the patch is now effectively complete: it scans past all global options and their arguments to correctly set the command index, ensuring completions work for constructs like `git -p checkout <TAB>` or `git --git-dir=<path> checkout <TAB>`.

Junio C Hamano has queued the patch for integration testing in the `next` branch, meaning it’s on track to be included in the next Git release unless issues arise during broader testing. The patch addresses all substantive feedback from earlier reviews, including architectural concerns from Junio and technical testing from D. Ben Knoble. Two minor limitations remain—`-c` is still missing from the zsh wrapper’s option spec, and `--git-dir` only accepts `--git-dir=<path>` (not `--git-dir <path>`)—but these are documented and left for follow-up work. The unrelated `git -<tab>` bug (redundant output) is confirmed as pre-existing and will also be addressed separately.
