This thread is about a small but long-standing bug in Git’s zsh completion script: it fails to complete commands or arguments when global options like `-C`, `--git-dir`, or `-p` are used (e.g., `git -C <path> checkout <TAB>`). Lutz Lengemann’s patch, now at v2, fixes this by making the zsh script’s behavior match the bash implementation, which already handles these cases correctly. The 25-line change scans past all global options and their arguments to correctly identify the Git command being completed, ensuring constructs like `git -p checkout <TAB>` work as expected.

The patch is effectively ready to merge. Junio C Hamano’s initial review raised an architectural concern about the zsh wrapper’s incomplete handling of global options, which the v2 patch fully addressed by expanding its scope to cover all such options, not just `-C`. D. Ben Knoble’s technical review surfaced minor limitations—like the inability to complete chained `-C` options (e.g., `git -C dir -C <TAB>`)—but these were documented as known gaps, and Knoble confirmed the patch works as intended with no regressions. The latest exchange between Junio and Knoble clarified a tangential POSIX shell detail (empty `case` actions are valid), but this doesn’t affect the patch’s readiness.

Two small follow-ups are noted: adding `-c` to the `_arguments` spec and fixing `--git-dir`’s syntax to accept `--git-dir <path>` (not just `--git-dir=<path>`). These are explicitly deferred, as is a pre-existing bug with `git -<TAB>` producing redundant output. The patch itself touches only `contrib/completion/git-completion.zsh`, reusing existing variables and logic to avoid introducing new complexity. No test coverage or on-disk changes are involved—this is purely a shell-script behavior fix.
