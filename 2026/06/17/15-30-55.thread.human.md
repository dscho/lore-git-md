This thread is about a small but long-overdue fix to Git’s zsh completion script. The issue is that completions like `git -C <path> checkout <TAB>` or `git -p branch <TAB>` simply don’t work, because the zsh wrapper (`contrib/completion/git-completion.zsh`) hard-codes assumptions about where the Git command name appears in the argument list. Lutz Lengemann’s v2 patch—now 25 lines—scans past all global options (`-C`, `--git-dir`, `-p`, etc.) and their arguments, mirroring how the bash completion script already works. Junio and D. Ben Knoble reviewed the first version; their feedback (architectural alignment with bash, variable propagation, and a few edge cases) is fully addressed in v2.

The patch is effectively ready: it fixes the core problem, documents two minor gaps (the `-c` option isn’t in the `_arguments` spec, and `--git-dir` only accepts `--git-dir=<path>`, not `--git-dir <path>`), and leaves directory completion for chained `-C` options (`git -C dir -C <TAB>`) as a known limitation.
