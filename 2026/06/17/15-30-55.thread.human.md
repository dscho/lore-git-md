This thread is about a bugfix for zsh Git completion that makes it handle global options like `-C`, `--git-dir`, and `-p` consistently with the bash implementation. The issue was that the zsh script hard-coded assumptions about command position, breaking completions for commands like `git -C <path> checkout <TAB>` or `git -p checkout <TAB>`.

Lutz Lengemann posted a v2 patch that expands the fix to cover all global options, not just `-C`. The patch scans past these options and their arguments to correctly identify the command index, mirroring the logic in the bash completion script. It also collects `-C` paths to ensure aliases and refs resolve properly. The 25-line change is clean, well-documented, and addresses all substantive feedback from Junio and D. Ben Knoble. Junio noted the architectural inconsistency in the zsh wrapper, while Knoble tested the patch and identified technical gaps, all of which were resolved in v2.

The patch is effectively ready for merging, with only a procedural step—resending it to the mailing list—remaining. It’s a low-risk, high-impact fix that improves a common workflow frustration. Two minor limitations are documented but deferred to follow-ups: the missing `-c` option in the `_arguments` spec and the broken directory completion for chained `-C` options (e.g., `git -C dir -C <tab>`). The unrelated `git -<tab>` bug is confirmed as pre-existing and will be addressed separately.
