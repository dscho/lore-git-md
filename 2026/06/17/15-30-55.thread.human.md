This thread is about a small but long-standing bug in Git’s zsh completion script: it fails to complete commands or arguments when global options like `-C <path>` or `--git-dir` are used. Lutz Lengemann’s v2 patch fixes this by making the zsh wrapper scan past all global options (not just `-C`) and their arguments, mirroring how the bash completion script already works. The 25-line change has been reviewed by Junio C Hamano and D. Ben Knoble, who both confirmed the fix works as intended and addresses their earlier feedback.

The patch is now effectively unblocked. It documents two minor gaps left for follow-ups: `-c` is still missing from the zsh `_arguments` spec, and `--git-dir` only accepts `--git-dir=<path>` (not `--git-dir <path>`). Directory completion for chained `-C` options (e.g., `git -C dir -C <tab>`) also remains broken, but this is explicitly noted in the commit message. D. Ben Knoble’s latest review confirms no functional regressions, and Junio’s follow-up—while clarifying a tangential POSIX shell detail—didn’t introduce new requirements. The patch is ready for Junio to pick up.
