This thread is about a small but long-standing bug in Git’s zsh completion script: it fails to complete commands or arguments when global options like `-C`, `--git-dir`, or `-p` are used. For example, `git -C some/dir checkout <TAB>` would previously offer no completions, while the equivalent bash completion worked fine.

Lutz Lengemann posted a 25-line fix (v2) that aligns the zsh script with the bash implementation by scanning past all global options and their arguments before determining the command index. Junio Hamano and D. Ben Knoble reviewed the patch; their feedback—architectural consistency and technical edge cases—was fully addressed in v2. The patch is now effectively unblocked and ready for final review or merge. Two minor gaps remain: `-c` is still missing from the zsh spec, and `--git-dir` only accepts the stuck form (`--git-dir=<path>`), but both are documented and agreed to be follow-ups. Directory completion for chained `-C` options (e.g., `git -C dir -C <TAB>`) is also still broken, but this is explicitly noted in the commit message and not a regression. The unrelated `git -<TAB>` bug (redundant output) is confirmed as pre-existing and left for a separate patch.
