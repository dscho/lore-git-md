This thread is about a bugfix for zsh Git completion, where the script fails to complete commands or arguments when the `-C <path>` option is used. Lutz Lengemann sent a 9-line patch (v1) that adds `-C` to the completion spec and adjusts command indexing, but it doesn’t address other global options like `--git-dir` or `-c`, leaving the zsh wrapper’s handling inconsistent with the bash implementation.

Junio C Hamano and D. Ben Knoble provided substantive feedback. Junio noted the broader design gap—other global options remain broken—and suggested aligning the zsh wrapper with the bash script. Knoble tested the patch and found two issues: local variables (`__git_C_args` and `i`) appear unused in the zsh wrapper, and directory completion for chained `-C` options (e.g., `git -C dir -C <tab>`) doesn’t work as expected. He also reported a separate but related bug: `git -<tab>` produces redundant and malformed output. The thread has stalled since Knoble’s review three weeks ago, and his recent ping—while not adding new technical details—signals continued interest in seeing the patch move forward. No response from the author has been received, leaving the open questions (extending the fix to other global options, resolving variable propagation, and addressing the `git -<tab>` bug) unanswered. The patch improves the status quo but remains incomplete.
