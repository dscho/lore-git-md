This thread is about a small but long-standing bug in Git’s zsh completion script: when you type `git -C <path> <command> <TAB>`, the completion system fails to offer any suggestions for the command or its arguments. Lutz Lengemann sent a nine-line patch that fixes the issue by teaching the zsh script to recognize the `-C` option, skip past it to find the actual command, and pass the chosen directory to the underlying bash helpers. The patch mirrors how the bash completion script already handles `-C`, so the behavior is now consistent across both shells.

So far only D. Ben Knoble has replied, and his feedback is purely stylistic: he prefers that the commit message describe the bug in present tense (“does not handle”) rather than imperative mood (“Add -C”), while keeping the bullet-point change list in imperative. No technical objections have been raised, and the patch remains unchanged. Lutz also noted in the commit message that the same hard-coded command-index assumption affects other global options (`--git-dir`, `--work-tree`, `-c`), but chose to keep this iteration small; he offered to tackle those in a follow-up if the community wants. The thread is still young, so more substantive reviews may yet arrive.
