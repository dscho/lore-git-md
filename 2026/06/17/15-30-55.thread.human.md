This thread is about a long-standing bug in Git’s zsh completion script, where commands like `git -C <path> <command>` fail to complete properly. Lutz Lengemann initially sent a small patch (v1) that fixed only the `-C` option, but after feedback from Junio C Hamano and D. Ben Knoble, he has now posted a much broader v2 that handles *all* global options (`--git-dir`, `--work-tree`, `-p`, etc.) by aligning the zsh wrapper with the bash completion script’s logic.

The v2 patch is a clear improvement: it now correctly skips global options and their arguments when determining the command index, so completions work for constructs like `git -p checkout <TAB>` or `git --git-dir=<path> checkout <TAB>`. Lutz addressed Knoble’s earlier concerns about variable propagation (zsh’s dynamic scoping handles it) and documented the remaining limitation—chained `-C` options (e.g., `git -C dir -C <tab>`) still don’t complete directories relative to the prior path. He also confirmed that the unrelated `git -<tab>` bug (producing redundant output) predates this patch and is out of scope.

Junio’s feedback about architectural consistency has been fully incorporated, and the patch is now technically sound and well-tested. The thread is no longer stalled, and the patch looks ready to merge, pending final review. This fixes a real usability pain point while leaving room for future polish.
