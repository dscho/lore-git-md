The zsh Git completion script has a long-standing bug where it fails to complete commands or arguments when the `-C <path>` option is used. Lutz Lengemann sent a patch to fix this by adjusting the `_arguments` spec and command index calculation in `contrib/completion/git-completion.zsh`. Junio C Hamano reviewed the patch and pointed out that while it fixes `-C`, it doesn’t address other global options like `--git-dir` or `--work-tree`, suggesting the zsh wrapper should align with the more robust bash implementation.

D. Ben Knoble tested the patch and found it improves the `-C` case but still has issues: local variables meant for the bash helpers don’t seem to propagate correctly, and directory completion for chained `-C` options (e.g., `git -C dir -C <tab>`) doesn’t work as expected. He also noticed a separate bug where `git -<tab>` produces redundant and messy output, hinting at deeper inconsistencies in the zsh script. The patch is a step forward but may need another iteration to fully resolve these edge cases. No one has objected to the direction, but the feedback suggests the fix isn’t yet complete.
