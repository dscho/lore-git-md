Subject: [PATCH] completion: zsh: fix completion for `git -C <path> <command>`
Series version: standalone patch
Originating author: Lutz Lengemann
Thread type: bugfix

Core problem or goal
The zsh Git completion script (`contrib/completion/git-completion.zsh`) has three hard-coded assumptions that break completion when the global `-C <path>` option is used: (1) the `_arguments` spec omits `-C`, (2) the command index is always 1, and (3) `-C` paths are not collected for the bash helpers. This prevents `git -C <path> <command> <TAB>` from offering completions for the command or its arguments.

Current status
Patch v1 sent; no prior iterations. The 9-line fix adds `-C` to the `_arguments` spec, scans past leading `-C <path>` pairs to set `__git_cmd_idx`, and accumulates `-C` arguments into `__git_C_args` so the bash helpers run `git` in the intended directory. The patch mirrors the existing bash implementation and touches only `contrib/completion/git-completion.zsh`.

Key technical details
- File: `contrib/completion/git-completion.zsh`
- New variables: `__git_C_args` (array of `-C <path>` pairs)
- Modified logic: `_arguments` spec extended, `__git_cmd_idx` calculation adjusted
- Behavior change: completion now works for `git -C <path> <command> <TAB>`
- No on-disk format, CLI, or test coverage changes; purely shell-script behavior
