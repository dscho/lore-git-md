Core problem or goal
The zsh Git completion script (`contrib/completion/git-completion.zsh`) has three hard-coded assumptions that break completion when the global `-C <path>` option is used: (1) the `_arguments` spec omits `-C`, (2) the command index is always 1, and (3) `-C` paths are not collected for the bash helpers. As a result, typing `git -C <path> <command> <TAB>` fails to offer completions for the command or its arguments.

Current status
Patch v1 sent; no prior iterations. The fix adds `-C` to the `_arguments` spec, scans past leading `-C <path>` pairs to set `__git_cmd_idx`, and accumulates `-C` arguments into `__git_C_args` so the bash helpers run `git` in the intended directory. The patch is 9 lines, touches only `contrib/completion/git-completion.zsh`, and mirrors the existing bash implementation.

Key technical details
- File: `contrib/completion/git-completion.zsh`
- New variables: `__git_C_args` (array of `-C <path>` pairs)
- Modified logic: `_arguments` spec extended, `__git_cmd_idx` calculation adjusted
- Behavior change: completion now works for `git -C <path> <command> <TAB>`
- No on-disk format or CLI changes; purely shell-script behavior
