Subject: [PATCH] completion: zsh: fix completion for `git -C <path> <command>`

Originating author: Lutz Lengemann
Thread type: bugfix

Core problem or goal
The zsh Git completion script (`contrib/completion/git-completion.zsh`) fails to complete commands or arguments when the global `-C <path>` option is used, due to three hard-coded assumptions: (1) the `_arguments` spec omits `-C`, (2) the command index is always 1, and (3) `-C` paths are not collected for the bash helpers. The broader issue, highlighted by Junio C Hamano, is that the zsh wrapper inconsistently handles global options compared to the bash implementation, leaving other options like `--git-dir`, `--work-tree`, and `-c` similarly broken.

Current status
Patch v1 sent; no prior iterations. The 9-line fix adds `-C` to the `_arguments` spec, scans past leading `-C <path>` pairs to set `__git_cmd_idx`, and accumulates `-C` arguments into `__git_C_args` so the bash helpers run `git` in the intended directory. Junio’s feedback identifies a design gap: the patch addresses `-C` but not other global options, and suggests aligning the zsh wrapper with the bash implementation (`__git_main` in `git-completion.bash`), which scans all global options before determining the command index. The author has not yet responded to this feedback.
