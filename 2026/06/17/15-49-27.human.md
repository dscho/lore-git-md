This is a refactoring patch series (2 patches) that moves the global `ignore_case` variable into Git’s repository-specific configuration structure (`repo_config_values`). The goal is to continue the ongoing libification effort by encapsulating this filesystem capability flag within the repository instance it belongs to, rather than leaving it as a global.

The series introduces a new getter function, `repo_get_ignore_case()`, to safely retrieve the value while preserving the existing fallback logic. The author raises a few RFC questions about correctness (early initialization access to `gitdir`) and performance overhead, and flags a potential layering concern in `compat/win32/path-utils.c` where `repository.h` is included.

The patches touch 14 files across core Git (apply, fetch, mv, dir, read-cache, etc.), indicating this is a low-level plumbing change with broad but mechanical impact. The commit message cites prior art and a stalled attempt by Derrick Stolee, suggesting the approach has been discussed and is generally aligned with project direction. The series looks well-scoped and motivated, though the RFC questions hint at unresolved edge cases that may need review attention.
