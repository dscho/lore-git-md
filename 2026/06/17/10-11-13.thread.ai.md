Subject: [PATCH] credential/osxkeychain: fix link error with Rust support
Series version: standalone patch (merged to master)
Originating author: Toon Claes
Thread type: bug fix (build system regression)

Core problem or goal
The macOS keychain credential helper (`contrib/credential/osxkeychain`) fails to link when Git is built with Rust support enabled (`NO_RUST` undefined). The linker cannot resolve Rust-implemented varint symbols (e.g., `git_varint_decode`, `git_varint_encode`) pulled in indirectly via `libgit.a`, even though the helper itself does not use Rust. This is a regression introduced in Git v2.55.0, blocking the release candidate. The issue affects only the Makefile-based build; the Meson build system handles the dependency correctly.

Current status
Patch v1 merged directly to `master` by Junio C Hamano ahead of Git v2.55.0-rc1. The fix is a one-line Makefile change replacing `$(LIB_FILE) $(EXTLIBS)` with `$(LIBS)` to ensure the Rust library is included when needed. This aligns the build rule with other Git components and resolves the immediate regression, though it does not address the underlying coarse-grained dependency issue in the build system.

Key technical details
- Files touched: `contrib/credential/osxkeychain/Makefile` (one line)
- Subsystems: build system, credential helpers, Rustification
- Symbols: Rust varint functions (`decode_varint`, `encode_varint`) resolved via `$(LIBS)`
- Behavior: restores successful linking of `git-credential-osxkeychain` when Rust support is enabled; no runtime changes. The regression was specific to the Makefile build; Meson was unaffected.
- Test coverage: none added; the issue was a build-time error, and the fix was verified manually
- Root cause: `libgit.a` pulls in Rust symbols even for components that do not logically need them, due to coarse-grained dependencies. The Makefile rule for `osxkeychain` omitted `RUST_LIB`, while Meson handled it correctly.

Open questions and loose ends
- The underlying issue of coarse-grained dependencies in the build system remains unresolved. This may resurface in other credential helpers or non-Rust components if Rust symbols continue to propagate through `libgit.a`.
- The regression went unnoticed in GitHub Actions CI because it relies on Meson, which was unaffected. This suggests gaps in build coverage for Rust-enabled Makefile configurations.
- No follow-up work is planned yet to address the broader dependency problem, though the commit message references a prior stalled attempt to tackle a similar issue.
