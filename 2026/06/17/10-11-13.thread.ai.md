Subject: [PATCH] credential/osxkeychain: fix link error with Rust support
Series version: standalone patch
Originating author: Toon Claes
Thread type: bug fix (build system regression)

Core problem or goal
The macOS keychain credential helper (`contrib/credential/osxkeychain`) fails to link when Git is built with Rust support enabled (`NO_RUST` undefined). The linker cannot resolve Rust-implemented varint symbols pulled in indirectly via `libgit.a`, even though the helper itself does not use Rust. This is a regression introduced in Git v2.55.0.

Current status
Patch v1 sent; no prior iterations. The fix is a one-line Makefile change replacing `$(LIB_FILE) $(EXTLIBS)` with `$(LIBS)` to ensure the Rust library is included when needed. The change aligns the build rule with how other Git components are linked and sidesteps the deeper issue of coarse-grained dependencies in the build system.

Key technical details
- Files touched: `contrib/credential/osxkeychain/Makefile` (one line)
- Subsystems: build system, credential helpers, Rustification
- Symbols: none renamed; the fix ensures Rust varint symbols (e.g., `git_varint_decode`) are resolved at link time
- Behavior: restores successful linking of `git-credential-osxkeychain` when Rust support is enabled
- Test coverage: none added; the fix addresses a build-time error, not runtime behavior

Open questions and loose ends
- The patch does not address the underlying issue of coarse-grained dependencies in the build system, where `libgit.a` pulls in Rust symbols even for components that do not logically need them. This may resurface in other credential helpers or non-Rust components.
- No review feedback yet; the patch is straightforward but may prompt discussion about long-term build system improvements.
