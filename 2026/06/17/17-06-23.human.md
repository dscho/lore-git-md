This is Junio’s biweekly "What’s cooking in git.git" report for June 2026, summarizing the state of the integration branches as Git 2.55-rc1 has just been tagged. The tree is now feature-frozen, so the focus shifts to polishing what is already in 'next' and fixing regressions.

The most notable new topics are three that Junio is actively soliciting feedback on:

- **mh/fetch-follow-remote-head-config** (7 commits) adds a global `fetch.followRemoteHEAD` configuration that sets the default for the per-remote `remote.<name>.followRemoteHEAD` setting. This is a small but user-facing feature that lets users control whether `git clone` and `git fetch` should automatically set up the remote’s HEAD symref locally. The series is clean, well-motivated, and has already received positive review comments; it looks ready to graduate to 'next'.

- **ps/refs-writing-subcommands** (5 commits) extends the `git refs` toolbox with new `create`, `delete`, `update`, and `rename` subcommands. This is part of Patrick Steinhardt’s ongoing effort to provide a stable, scriptable interface for reference manipulation. The series drops the implicit `the_repository` dependency and is structured as a series of small, focused patches. It is a clear refactoring win and a building block for future work on the ref backend abstraction.

- **po/hash-object-size-t** (6 commits) fixes a long-standing limitation on Windows and other LLP64 platforms where Git could not hash objects larger than 4 GB. The fix converts object header buffers and data-handling functions from `unsigned long` to `size_t`, adds test cases for >4 GB objects, and demonstrates the problem with filtered input. This is a platform-compatibility bugfix with thorough test coverage; it should be uncontroversial.

On the performance front, **kk/streaming-walk-pqueue** (3 commits) has graduated to 'master'. It uses a priority queue for date-sorting commits in non-limited streaming revision walks, speeding up traversals in repositories with many merges. The change is internal and does not affect user-facing behavior.

Two other graduated topics are worth noting for their impact:

- **en/commit-graph-timestamp-fix** (1 commit) fixes a 32-bit truncation bug in `compute_reachable_generation_numbers()` that could corrupt generation numbers for commits with committer timestamps beyond 2106. This is a silent data corruption issue that affects generation number v2; the fix is minimal and targeted.

- **tb/midx-incremental-custom-base** (3 commits) fixes a bug in `git multi-pack-index write --incremental` where the `--base` option was ignored, causing packs above the custom base to be incorrectly excluded and breaking reachability closure for bitmaps. The series also exposes a shared `nth_line()` helper for tests. This is a correctness fix for the repack machinery.

The stalled topics section is short: only **jt/config-lock-timeout** (1 commit) remains, waiting for a response to review comments. The rest of the "Cooking" section is a mix of small fixes, documentation updates, and larger efforts that are still under review.

Among the larger efforts, **ps/odb-source-packed** (18 commits) is the most ambitious. It refactors the packed object source into a proper `struct odb_source`, continuing Patrick Steinhardt’s ODB abstraction work. The series is still in early review, but it is clearly structured and well-motivated.

**mm/diff-process-hunks** (6 commits) introduces a new `diff.<driver>.process` configuration that allows an external long-running process to act as a hunk provider. This is a powerful extension point for tools that want to control which lines Git considers changed while leaving output formatting to Git. The series has received detailed review feedback and is expected to be rerolled.

**hn/branch-prune-merged** (7 commits) adds a `--delete-merged` option to `git branch` that removes local branches already merged to their remote-tracking counterparts. The series also adds a `--dry-run` mode and a per-branch opt-out mechanism. It is a user-facing feature with clear use cases, but it has sparked some discussion about edge cases and backward compatibility.

Overall, the report shows a project in good shape as it approaches the 2.55 release. The new topics are focused, well-explained, and address real problems. The integration branches are stable, and the remaining work is mostly polishing and review.
