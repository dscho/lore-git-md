This thread is about a platform-compatibility issue in the Git test suite where `t4216-log-bloom.sh` fails on non-x86 architectures due to a `char` signedness assumption. Todd Zullinger reported the problem, noting that the test uses `test_cmp` output to set the `SIGNED_CHAR_BY_DEFAULT` prerequisite, but on architectures where `char` is unsigned, the diff output triggers TAP parse errors.

Patrick Steinhardt initially proposed a targeted fix to suppress the diff output using `test_lazy_prereq`, preserving the test’s current behavior (skipping on non-x86). However, Junio C Hamano later weighed in, questioning why the issue wasn’t caught earlier and arguing that the `SIGNED_CHAR_BY_DEFAULT` prerequisite serves no functional purpose—it’s only used by one test that runs `true` regardless of the outcome. Junio favors simply removing the check entirely, as it’s unused elsewhere and the test’s behavior doesn’t justify the complexity. No objections have been raised, and the discussion suggests this will likely be resolved by dropping the prerequisite and its associated `test_cmp` check. The fix remains confined to the test script, with no changes to the underlying Bloom filter logic.
