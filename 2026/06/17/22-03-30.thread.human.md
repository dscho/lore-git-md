The `t4216-log-bloom.sh` test has been failing on non-x86 architectures (like ARM and PowerPC) due to TAP parse errors caused by a long-standing assumption that `char` is signed by default. The test used a `test_cmp` check to set a `SIGNED_CHAR_BY_DEFAULT` prerequisite, but on platforms where `char` is unsigned, the diff output from `test_cmp` leaked into the TAP stream, breaking the test harness. This issue only became visible after a June 2026 change tightened TAP parsing strictness.

The fix is straightforward: remove the redundant `SIGNED_CHAR_BY_DEFAULT` prerequisite and its associated `test_cmp` check, as the `highbit1` test case it guarded runs `true` regardless of the outcome. Todd Zullinger reported the issue, and Junio C Hamano, Jeff King, and Patrick Steinhardt all agreed this was the right approach. Patrick has now sent the final patch, which touches only the test script and leaves the Bloom filter logic untouched. No objections have been raised, and the patch is expected to be merged soon. The broader question of whether the Bloom filter logic should vary by platform remains unresolved but is separate from this fix.
