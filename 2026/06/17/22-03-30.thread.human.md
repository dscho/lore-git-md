This thread is about a test suite bug in `t4216-log-bloom.sh` that causes TAP parse errors on non-x86 architectures due to an assumption that `char` is signed by default. The issue, which existed since mid-2024, only became visible after a June 2026 change (`389c83025d`) tightened the TAP harness to fail on invalid output. The problem stems from a redundant `SIGNED_CHAR_BY_DEFAULT` prerequisite that uses `test_cmp` output to set a condition, but the diff output leaks into the TAP stream on platforms where `char` is unsigned, breaking the test harness.

The fix is straightforward: remove the `SIGNED_CHAR_BY_DEFAULT` prerequisite and its associated `test_cmp` check from the test script. This solution has been agreed upon by Junio C Hamano, Patrick Steinhardt, and Jeff King (Peff), as the prerequisite is unused elsewhere and the test’s behavior (skipping on non-x86) doesn’t justify the complexity. The patch will touch only the test script, leaving the Bloom filter logic and on-disk format unchanged. While the thread briefly considered whether the Bloom filter logic should vary by platform, this question remains unresolved but is not blocking the immediate fix.

The issue affects non-x86 architectures like ARM and PowerPC but is not a regression in the Bloom filter code itself. The thread has no outstanding objections, and the fix is expected to be uncontroversial. Todd Zullinger initially reported the issue, and the discussion has since focused on confirming the agreed-upon solution.
