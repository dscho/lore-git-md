This thread reports a **platform compatibility issue** in Git 2.55.0-rc1’s test suite, specifically in `t4216-log-bloom.sh`, which exercises Bloom filter logic for `git log`. The failure occurs on non-x86 architectures where `char` is unsigned by default, breaking a long-standing assumption in the test that `char` is signed (true on x86). The test uses `test_cmp` to compare files and set the `SIGNED_CHAR_BY_DEFAULT` prerequisite, but on non-x86 platforms, the diff output—unexpectedly interpreted as TAP tokens—causes TAP parse errors, disrupting the test harness.

The issue is **not a regression** but an unaddressed portability gap: older builds also failed to set the prerequisite on non-x86, suggesting the test (or the `test-tool read-graph bloom-filters` code it exercises) may be fundamentally broken for these platforms. The proposed fix—silencing `test_cmp` output—would mask the TAP errors but not resolve the underlying assumption about `char` signedness. Key questions remain: *Should the test fail on non-x86 (i.e., is the behavior correct)?* Or is the test setup (or the Bloom filter logic) flawed?

For end users, the impact is likely minimal—the test is skipped, not failed—but the TAP errors could obscure other CI failures.
