This is a zsh completion bugfix that addresses feedback from Junio C Hamano on the initial patch. The original patch fixed completion for `git -C <path> <command> <TAB>` by adding `-C` support to the zsh wrapper, but Junio points out that the fix is incomplete: while the `_arguments` spec now recognizes `-C`, the argument-parsing logic still only handles `-C` and ignores other global options like `--git-dir`, `--work-tree`, and `-c`.

Junio’s review is substantive. He notes that the zsh wrapper’s argument-parsing logic is inconsistent with the bash implementation (`git-completion.bash`), which already handles all global options uniformly. The review includes a direct code excerpt from the bash helper showing how it scans past every global option, not just `-C`, before identifying the command. This suggests the zsh wrapper should adopt the same approach rather than hard-coding `-C` alone.

The patch author has not yet responded, so the thread is still open. The ball is in their court to either extend the fix to cover all global options or explain why `-C` deserves special treatment. Until that happens, the patch remains a partial fix. For a busy reader, this is a small but real usability improvement that is likely to land once the parsing logic is brought into line with the bash implementation.
