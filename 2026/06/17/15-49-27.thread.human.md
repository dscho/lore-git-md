This thread is about moving Git’s global `ignore_case` variable into `struct repo_config_values`, eliminating a piece of global state and tying the configuration value to the repository instance it came from. The series, now in its third version, has been merged by maintainer Junio C Hamano and is cooking in the `next` branch, meaning it’s on track for the next release.

The two patches introduce a `repo_ignore_case()` getter, add the field to the repository configuration structure, and update all usage sites across the index, filesystem operations, and nine built-in commands. The design follows the pattern set by earlier migrations of `protect_hfs` and `protect_ntfs`, including a repository state check in the getter. The Windows compatibility layer’s dependency on `repository.h` was explicitly approved by both Junio and Johannes Schindelin, the Git for Windows maintainer, resolving the last procedural question.

No open issues remain. The series is fully aligned with project conventions, and all prior review feedback—including maintainer concerns about the getter’s design—has been addressed. The thread is now closed.
