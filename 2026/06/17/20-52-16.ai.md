This is the second patch in Kristoffer Haugsbakk’s five-part documentation series updating `SubmittingPatches` to standardize Git’s trailer conventions. It explicitly discourages the use of common Linux Kernel trailers (`Fixes:` and `Link:`) in Git commit messages, explaining why they are irrelevant to Git’s workflow.

The patch adds a short but clear section to `Documentation/SubmittingPatches` that contrasts Git’s practices with those of the Linux Kernel. For `Fixes:`, it notes that Git’s simpler tree structure (few downstream trees, minimal cherry-picking) makes the trailer unnecessary—fixes are instead documented inline in the commit message. For `Link:`, it points out that Git already uses `refs/notes/amlog` to track patch submissions, and footnotes are handled within the commit message body. The explanation is concise, well-reasoned, and grounded in Git’s existing conventions, making it a natural complement to the broader trailer guidelines introduced in the series.

This patch is uncontroversial and aligns with the series’ goal of reducing ambiguity for contributors.
