This is a feature patch adding the `--create-if-missing` option to both `git switch` and `git checkout`. It is the second iteration of a patch series that originally proposed `--ensure` (`-e`) but was revised in response to maintainer feedback.

The patch implements an idempotent branch-switching operation: if the target branch exists, it switches to it without resetting the branch tip; if the branch does not exist, it creates it from a start-point (defaulting to the current branch). The implementation handles edge cases such as detached HEAD state, tracking configuration, and pathspec rejection for `git checkout`. It includes thorough test coverage for both commands, verifying branch creation, existing-branch switching, tracking updates, and failure modes.

Key technical details:
- The option is named `--create-if-missing` (no short form) to avoid conflict with `--editor`.
- It works with both `git switch` and `git checkout`, maintaining consistency with each command's existing semantics.
- Tracking behavior integrates with existing `--track`/`--no-track` options.
- The implementation reuses existing branch-creation and switching machinery, avoiding code duplication.
- Shell completion is updated to support the new option.
- Tests cover both happy paths and error conditions (e.g., detached HEAD without a start-point).

The patch directly addresses the maintainer's feedback from v1 by:
1. Renaming the option from `--ensure` to `--create-if-missing` for clarity and to avoid short-option conflicts.
2. Extending the feature to `git checkout` (which was explicitly requested).
3. Adding pathspec rejection for `git checkout` to prevent mixed branch/path operations.

The implementation appears solid: the code is clean, edge cases are handled, and tests are comprehensive. The main open question remains whether the feature itself is desirable (as raised in the maintainer's feedback about use-case validity), but the patch itself is technically well-crafted.
