This is a maintainer review of a bugfix patch for the sequencer subsystem, addressing a notes-handling regression during rebase.

Junio C Hamano reviews Uwe Kleine-König’s patch that prevents Git from incorrectly copying notes from commits dropped during rebase. The core fix—adding a `dropped_commit` flag to `do_pick_commit()` and skipping note copying when the flag is set—is acknowledged as reasonable, but Junio raises two substantive concerns. First, he questions whether the patch might break the `record_in_rewritten()` logic for sequences involving fixup commits: if a non-dropped commit is followed by a dropped fixup, the patch could prevent flushing the pending commit list, potentially mapping notes to the wrong rewritten commit. Second, he requests documentation updates to clarify when users can expect notes to be lost during rebase.

The review also includes surface-level feedback on test script style (redirection spacing, avoiding `@` for `HEAD`, not writing outside `$TRASH_DIRECTORY`) and reiterates Phillip Wood’s earlier suggestion to integrate the test into `t3400-rebase.sh` rather than creating a new script. Junio’s tone is constructive but firm, particularly on the test script location and the need to address the fixup-commit edge case before merging. The patch’s current implementation is not yet ready for `next`, but the underlying issue is real and the approach is sound if the identified gaps are closed.
