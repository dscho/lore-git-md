This is the final patch in Patrick Steinhardt’s 17-part ODB abstraction series, completing the conversion of the packed object storage backend into a standalone `struct odb_source`. The patch removes the last vestige of coupling between the packed and loose sources by dropping the `files` parent pointer from `struct odb_source_packed`, making the packed source fully independent.

The change is mechanical: the constructor signature for `odb_source_packed_new()` is updated to take the same parameters as the loose source (`struct object_database *`, `path`, and `local` flag), and all internal callers are adjusted to pass the correct values. The `prepare_packed_git_one()` helper and its supporting `prepare_pack()` callback are updated to work directly on the packed source rather than downcasting to the parent. The diff is small (19 lines changed across four files) and preserves all existing behavior; it simply removes the now-unnecessary parent relationship that was introduced earlier in the series to ease the transition.

This patch lands on top of the MIDX interface refactoring in patch 16/17, which already updated all MIDX-related functions to use the concrete packed source type. With the parent pointer gone, the packed source’s interface is now fully aligned with the loose source’s precedent: both use an embedded `struct odb_source` as a base, share identical constructor signatures, and carry no parent pointers. The series as a whole is now callback-complete, with all 13 required callbacks wired up and symbol encapsulation finalized.

The patch has received surface-level mechanical approval from Justin Tobler, who confirmed the interface alignment in earlier iterations. No deeper review of the ODB design or callback logic has occurred yet, and the series remains blocked by unresolved refdb lifecycle issues that Patrick is addressing in a separate 11-patch fix series. Those fixes depend on the “ps/setup-centralize-odb-creation” series, so this work will not progress until that dependency is merged. For now, this patch represents the last step in Patrick’s planned large-scale ODB restructuring; future changes should be incremental.
