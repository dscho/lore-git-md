This is a documentation patch series (v2 of 2 patches) that refines Git’s contributor guidelines around patch review etiquette. The series updates two key files: `Documentation/MyFirstContribution.adoc` and `Documentation/SubmittingPatches`.

The first patch encourages contributors to discuss review feedback in the email thread before sending a new version of their patches. This makes the author’s reasoning explicit and fosters more direct interaction between contributors. The v2 update adds a note about “social interactions” to the commit message, but the author is now reconsidering whether this patch adds meaningful value, as Patrick Steinhardt pointed out that the existing text already covers the core idea.

The second patch, originally inspired by Patrick Steinhardt’s email, advises contributors to batch feedback and avoid sending multiple rerolls of the same series in a single day. The v2 update incorporates Junio C Hamano’s suggestions: it now mentions that waiting between rerolls gives reviewers across time zones a fair chance to participate and encourages authors to polish patches before sending them. The patch also properly attributes Patrick’s contribution with a `Helped-by` trailer.

The series is well-motivated and addresses real friction points for new contributors. The changes to `SubmittingPatches` look ready to land, while the first patch may be dropped due to redundancy. The author is actively engaging with feedback and modeling the very practices the documentation aims to promote. This is a low-risk, high-value update that should help smooth the on-ramp for new contributors.
