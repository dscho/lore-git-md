This is the ninth patch in Patrick Steinhardt’s 17-part ODB abstraction series (v3), targeting the packed object storage backend. It wires up the `read_object_info()` callback for the packed source, moving the logic from `packfile.c` into `odb/source-packed.c` and exposing `find_pack_entry()` as a supporting function. The patch is a mechanical step in the ODB interface alignment effort, ensuring the packed source’s behavior matches the loose source’s precedent.

The core change relocates the `read_object_info()` implementation—including the `find_pack_entry()` helper—into the packed source’s compilation unit. This maintains functional equivalence while preparing for future encapsulation: `find_pack_entry()` remains exposed for now but is slated to become file-local once all callers in `packfile.c` are migrated. The callback registration follows the established pattern (`packed->base.read_object_info = odb_source_packed_read_object_info`), and the implementation handles the `OBJECT_INFO_SECOND_READ` flag by triggering a reprepare if the first read fails.

The diffstat (79 insertions, 78 deletions) reflects the code movement, with most deletions coming from `packfile.c` and corresponding additions in `odb/source-packed.c`. The patch also updates `odb/source-files.c` to use the new ODB-prefixed interface and renames `fill_pack_entry()` to `packfile_fill_entry()` to avoid a naming conflict. No behavioral changes are introduced, and the MIDX and packfile traversal logic remains unchanged.

This patch is part of the final large-scale ODB restructuring Patrick plans, with future work expected to be incremental. It depends on earlier patches in the series (notably the packfile list split and lifecycle management wiring) and remains blocked by unresolved refdb lifecycle issues requiring an 11-patch fix series. Justin Tobler’s surface-level review of the mechanical changes in v2/v3 has not yet engaged with the callback logic’s correctness or edge cases (e.g., `do_not_close` packs, error handling in `packed_object_info()`). The exposed `find_pack_entry()` symbol is noted as temporary, pending further encapsulation.
