This is a **test suite regression report** for Git 2.55.0-rc1. Todd Zullinger reports that the `t4216-log-bloom.sh` test script is producing invalid TAP (Test Anything Protocol) output on all non-x86 architectures, causing the test harness to fail to parse the results. The issue stems from `test_cmp` output (a diff) being emitted directly to stdout during a prereq check, which the TAP parser interprets as malformed test data.

The failing test is part of the commit-graph/Bloom filter test suite and appears to be checking whether the platform’s `char` type is signed by default (a prerequisite for certain Bloom filter behavior). The test is *intentionally* designed to skip if the platform doesn’t meet this requirement, but the current implementation leaks the `test_cmp` diff into the TAP stream, breaking the parser. Todd notes that this has likely been happening for some time (older builds also failed to set the prereq), but the TAP parser is now strict enough to treat the diff output as an error.

The report is observational and diagnostic rather than proposing a fix, but it raises a clear question: should the test be rewritten to avoid the TAP violation, or is the underlying assumption about `char` signedness itself flawed on non-x86 platforms? The issue looks well-contained and unlikely to affect end users, but it’s a real nuisance for CI and platform maintainers. If you care about test suite robustness or non-x86 compatibility, this is worth following.
