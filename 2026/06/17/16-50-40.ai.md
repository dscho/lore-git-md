This is a documentation patch (v2 1/2) refining Git's contributor guidelines, specifically the review etiquette section. It updates both `MyFirstContribution.adoc` and `SubmittingPatches` to explicitly encourage contributors to discuss review feedback in the mailing list thread before sending a new patch version.

The patch makes two key changes: first, it adds guidance in `MyFirstContribution.adoc` suggesting that contributors reply to each review comment with their planned approach (implement, keep original, or pursue alternative) rather than letting the next patch version be their only response. Second, it makes similar changes to `SubmittingPatches`, emphasizing that contributors should engage in discussion about which suggestions they'll implement before preparing updated patches.

This iteration remains unchanged from v1 for this specific patch, despite Patrick Steinhardt's feedback about potential redundancy with existing content. The author has kept these changes while actively seeking input on whether they add value or should be dropped. The patch touches core contributor documentation files and reflects ongoing discussion about improving the review workflow, particularly around making implicit norms explicit for new contributors. The unresolved question about redundancy in `MyFirstContribution.adoc` remains the primary open issue for this patch.
