This is the thirteenth patch in Patrick Steinhardt’s 17-part series completing the ODB abstraction for Git’s packed object storage. It wires up the `find_abbrev_len()` callback for the packed source, moving the logic from `packfile.c` to `odb/source-packed.c` and registering it in the packed source’s constructor. The change is purely mechanical: the implementation remains identical, including the MIDX and packfile traversal logic, prefix-length calculation, and error handling. The only difference is the relocation of the code and the switch to the ODB-prefixed interface (`odb_source_find_abbrev_len()`).

The patch follows the established pattern of the series: relocate a callback’s implementation to the source-specific file, register it in the constructor, and update callers to use the new ODB interface. Justin Tobler’s earlier reviews of similar patches (for `read_object_info()`, `read_object_stream()`, `for_each_object()`, and `count_objects()`) suggest this will be uncontroversial, though no review of this specific patch has yet occurred. The diffstat (+114/-117) reflects the straightforward code movement, with no behavioral changes introduced.

This leaves only the `freshen_object()` callback unwired; once that is done, the packed source’s interface will be fully aligned with the loose source’s precedent. The series remains blocked by unresolved refdb lifecycle issues, but this patch is a necessary step toward completing the ODB abstraction.
