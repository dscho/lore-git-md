This is the ninth patch in Patrick Steinhardt’s 17-part ODB abstraction series (v3), which completes the conversion of Git’s packed object storage into a proper `struct odb_source`. This patch wires up the `read_object_info()` callback for the packed source, moving the logic from `packfile.c` into `odb/source-packed.c` and exposing the supporting `find_pack_entry()` function to maintain compatibility with existing callers.

The change is mechanical but important: it relocates the packed object lookup logic into the ODB subsystem, aligning the packed source’s interface with the loose source’s precedent. The patch also renames `fill_pack_entry()` to `packfile_fill_entry()` and makes it public so that callers in `packfile.c` can continue to use it until they are migrated into the ODB layer in later patches. The diffstat (79 insertions, 78 deletions) reflects the straightforward code movement, with no functional changes—just the relocation of existing logic into the new abstraction layer.

Justin Tobler’s earlier surface-level review of the mechanical changes in this series is now complete, but no deeper technical engagement with the callback logic or edge cases has occurred yet. The patch is part of a larger effort to decouple Git’s object storage backends, and while it looks clean and well-structured, the series as a whole remains blocked by unresolved refdb lifecycle issues that Patrick is addressing in a separate 11-patch fix series. If you’re tracking the ODB abstraction work, this patch is a key step in the interface alignment, but the broader effort won’t progress until the refdb fixes land.
