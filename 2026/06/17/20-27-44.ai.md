This is a **substantive review** from Jeff King (Peff) on the second patch of Pablo Sabater’s v5 series improving `git log --graph` rendering of commits with excluded parents. Peff identifies a **critical interaction issue** with the prio-queue refactoring introduced in commit `dd4bc01c0a` (revision: use priority queue for non-limited streaming walks, 2026-05-27).

The problem: `graph_peek_next_visible()` iterates over `graph->revs->commits`, but since `dd4bc01c0a`, the revision traversal moves commits into `revs->commit_queue` (a prio-queue) during traversal. As a result, `revs->commits` no longer contains the full queue, causing the lookahead logic to miss commits that are already in the prio-queue. Peff’s instrumentation confirms this: the function sees only one commit in `revs->commits` while the queue holds many more.

Peff notes that prio-queues only support peeking at the first entry, making it impossible to scan ahead through the queue in its current form. While the existing tests do not fail, this is likely due to either incomplete test coverage or the issue being masked by the `NEEDSWORK` edge case already documented in the patch. The interaction becomes visible when Peff’s in-progress topic (which removes `revs->commits` entirely) is merged with this series.

The review is **tested**: Peff built the code, instrumented it, and ran `git log --graph --oneline -- Makefile` to observe the behavior. This is a **high-impact finding**—it affects the core correctness of the lookahead logic and could lead to incorrect graph rendering in certain traversal scenarios. The patch will need a redesign of the lookahead mechanism to work with the prio-queue, or a reversion to the older traversal model for graph-specific code paths. The issue is now a blocker for merging the series until resolved.
