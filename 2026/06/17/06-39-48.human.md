This is the fifth patch in Patrick Steinhardt’s 17-part ODB abstraction series, converting the packed object storage backend into a proper `struct odb_source`. This patch focuses on lifecycle management: it embeds the base `struct odb_source` into `struct odb_source_packed`, assigns it the new `ODB_SOURCE_PACKED` type, and wires up the `free` callback. It also registers a `chdir_notify` callback to handle path reparenting, preparing for a future change where the packed source will use its own path instead of borrowing from the parent files source.

The patch is mechanical and preparatory, laying the groundwork for subsequent commits that will implement the remaining ODB callbacks. The diffstat (60 insertions, 22 deletions) reflects the addition of the `free` and `chdir_notify` callbacks, the downcast helper, and the removal of the now-redundant `packfile_store_free()` function. The changes are confined to the ODB subsystem (`odb/source-packed.{c,h}`, `odb/source-files.c`, `odb/source.h`) and `packfile.{c,h}`, with no functional impact yet -- the packed source remains non-operational until the callbacks are fully wired up.

This patch is part of the final large-scale ODB restructuring Patrick plans, and it directly addresses a technical debt item noted in the cover letter: the need for consistent lifecycle management across ODB sources. The chdir notification handling is a forward-looking change that anticipates future path-handling refactoring. Justin Tobler’s earlier surface-level review of the mechanical changes in v2 suggests this patch is uncontroversial, but the series as a whole remains blocked by unresolved refdb lifecycle issues that Patrick is addressing in a separate 11-patch fix series.
