This is the second patch in Patrick Steinhardt’s 17-part ODB abstraction series (v3), a refactoring patch that splits the packfile list logic into a separate compilation unit (`packfile-list.c`/`packfile-list.h`) to break a cyclic header dependency. The change is purely mechanical: it moves the existing `packfile_list_*` functions and their supporting structs out of `packfile.c`/`packfile.h` into new files, leaving the behavior unchanged. The diffstat (117 insertions, 105 deletions) reflects this relocation, and the build system updates (`Makefile`, `meson.build`) ensure the new unit is compiled.

The motivation is clear: the upcoming introduction of `struct odb_source_packed` (patch 1/17 already renamed `struct packfile_store`) will embed a `struct packfile_list`, requiring `packfile.h` to be included in `odb/source-packed.h`. This would create a circular include chain that forward declarations cannot resolve, so the packfile list logic is extracted first. The patch is a prerequisite for the ODB abstraction work and has no standalone user-visible impact. Justin Tobler’s review of the v2 mechanical changes (which included this split) was surface-level and confirmed the alignment with the series’ goals, but no deeper technical scrutiny of the list logic itself has occurred yet. The patch is uncontroversial and appears well-executed, though its significance lies entirely in enabling the larger ODB restructuring.
