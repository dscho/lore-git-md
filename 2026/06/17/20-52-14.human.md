This is the v2 submission of Kristoffer Haugsbakk’s documentation patch series updating the `SubmittingPatches` guidelines for trailer usage. The series is now down to five patches (from six in v1) and is ready for review.

The core goal remains the same: standardize Git’s trailer conventions to ensure legal compliance (DCO sign-off) and practical usability, while resolving prior ambiguity. The v2 iteration incorporates all feedback from Junio C Hamano and Patrick Steinhardt, including the decision to **omit non-identity trailers entirely**—a key change from v1. Kristoffer’s data showed that Git’s history contains only downstream-specific trailers like `Change-Id`, `Message-ID`, and `Fixes`, which are irrelevant to the project’s workflow.

Key updates in v2:
- **Dropped the non-identity trailers patch** after agreement that Git does not use trailers like `Closes:` or `Link:` (unlike the Linux kernel).
- **Strengthened DCO sign-off requirements** for the `Based-on-patch-by` trailer, now explicitly requiring the original author’s sign-off for non-trivial contributions.
- **Clarified trailer ordering** to emphasize chronological sequence (e.g., testing/reviewing trailers before `Signed-off-by`).
- **Fixed typos and line-wrapping** (e.g., "encouragement", "At the same time") and improved commit messages.

The series is well-motivated, addressing recurring mailing-list questions about trailers. It codifies existing practices (e.g., `Helped-by` vs. `Based-on-patch-by`) and aligns with broader documentation efforts like Jean-Noël Avila’s man-page standardization. The patches are focused, non-controversial, and likely to merge smoothly. For anyone contributing to Git, these updates will make the trailer conventions clearer and more consistent.
