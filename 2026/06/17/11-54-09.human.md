This is a build system bugfix for the macOS keychain credential helper. Junio C Hamano has merged Johannes Schindelin’s patch directly into `master` ahead of the Git v2.56.0-rc1 release.

The patch resolves a link error that occurs when building Git with Rust support enabled. The `osxkeychain` helper does not itself use Rust, but it indirectly depends on Rust-implemented varint encoding/decoding functions via `libgit.a`. The linker fails to resolve these symbols because the Rust library is not included in the link step. The fix replaces `$(LIB_FILE) $(EXTLIBS)` with `$(LIBS)` in the Makefile, ensuring the Rust library is included when needed. This aligns the build rule with how other Git components are linked and sidesteps the deeper issue of coarse-grained dependencies in the build system.

The patch is minimal (one line) and well-motivated, addressing a regression introduced in Git v2.55.0. Junio’s decision to merge it directly suggests the fix is uncontroversial and the problem is urgent enough to bypass the usual `next` branch staging. No test coverage was added, as the issue is purely a build-time error, but the fix restores successful linking of `git-credential-osxkeychain` when Rust support is enabled.

The commit message notes that the `osxkeychain` helper does not logically need index-related functionality, but the build system does not currently allow fine-grained control over these dependencies. This patch does not address that underlying issue, which may resurface in other credential helpers or non-Rust components. However, it is a pragmatic solution that resolves the immediate problem without complicating the build system further.

If you use macOS and build Git from source with Rust support, this patch is worth noting—it ensures the keychain helper will link correctly. For everyone else, it is a quiet but necessary fix for a subtle build regression.
