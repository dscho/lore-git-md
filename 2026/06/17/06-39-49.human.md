This is the sixth patch in Patrick Steinhardt’s 17-part ODB abstraction series, which is completing the conversion of Git’s packed object storage into a proper `struct odb_source`. This patch wires up the `close()` callback for the packed source, moving the logic from the old `packfile_store_close()` function into the new ODB interface and updating the files source to call it through the generic `odb_source_close()` wrapper.

The change is mechanical and straightforward: the `close()` callback is implemented in `odb/source-packed.c`, registered in the packed source’s constructor, and the files source now delegates to it instead of calling the old `packfile_store_close()` directly. The diff removes the now-redundant `packfile_store_close()` function and its declaration, completing the interface alignment with the loose source. The callback itself is unchanged in behavior—it still closes all packfiles and the multi-pack index—but is now part of the ODB abstraction layer.

This patch is a small but necessary step in the larger ODB refactoring. It looks clean and uncontroversial, following the established pattern from earlier patches in the series. The only minor note is that the callback still uses the `do_not_close` BUG check, which suggests there may be lingering edge cases in packfile lifecycle management, but those are outside the scope of this patch. Justin Tobler’s earlier surface-level review of the mechanical changes in this series has already covered similar ground, so this patch is likely to be accepted as-is once the blocking refdb issues are resolved.
