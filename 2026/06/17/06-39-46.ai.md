This is the third patch in Patrick Steinhardt’s 17-part ODB abstraction series (v3), a refactoring effort that moves the packed object storage implementation into the `odb/` subsystem. The patch mechanically relocates the `struct odb_source_packed` definition and its constructor from `packfile.{c,h}` to new files `odb/source-packed.{c,h}`, mirroring the structure already used for loose and in-memory sources. The change is purely organizational: it detaches the packed source’s implementation from the generic packfile code without altering any logic or interfaces. The diffstat (87 insertions, 75 deletions) reflects the file-level move, and the patch updates both the Makefile and Meson build files to include the new source file.

The patch is a straightforward preparatory step for the larger ODB abstraction goal. By isolating the packed source’s code in the `odb/` directory, it establishes a consistent pattern across all object database sources (files, in-memory, loose, and now packed). The constructor `odb_source_packed_new()` is moved verbatim, and the only functional change is updating `odb/source-files.c` to call the new constructor instead of the old `packfile_store_new()`. No callbacks are wired up yet; that work happens in later patches. The commit message is minimal but clear, framing the move as a prerequisite for converting `struct odb_source_packed` into a proper `struct odb_source`.

This patch has already received surface-level review from Justin Tobler in v2, who confirmed the mechanical alignment with the loose source precedent. There are no unresolved technical questions here, and the change is uncontroversial. The series remains blocked by deeper refdb lifecycle issues (memory leaks, duplicate refdb creation) that Patrick is addressing in a separate 11-patch fix series, but this patch itself is ready to proceed once its dependencies are resolved. The move sets the stage for the callback wiring and interface alignment that follow in patches 4–17.
