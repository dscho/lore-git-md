This is a bugfix patch for the sequencer subsystem, addressing a long-standing issue where `git rebase` incorrectly copies notes from commits that are dropped because their changes are already present in the target branch. The patch is in active review and currently on its first iteration.

Uwe Kleine-König responds to Junio C Hamano’s review, agreeing to relocate the test script from `t3322-notes-rebase.sh` to `t3400-rebase.sh` to avoid creating a new test file. On the substantive side, Uwe pushes back slightly on the need for documentation, arguing that losing notes when a commit disappears is intuitive and doesn’t require explicit user-facing explanation. However, he expresses uncertainty about the fixup-commit edge case Junio identified—where a dropped fixup commit might prevent flushing the pending commit list in `record_in_rewritten()`, potentially mapping notes to the wrong rewritten commit. Uwe suggests this complexity might be better handled by someone with deeper Git internals knowledge, hinting at a possible roadblock for the patch’s progress.

The patch itself remains well-motivated and technically sound for its core case, but the fixup-commit scenario is a real concern that could complicate the implementation.
