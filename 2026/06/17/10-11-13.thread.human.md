The macOS keychain credential helper (`git-credential-osxkeychain`) in `contrib/` broke when Git is built with Rust support enabled, failing to link due to unresolved Rust varint symbols pulled in via `libgit.a`. Toon Claes sent a one-line fix replacing `$(LIB_FILE) $(EXTLIBS)` with `$(LIBS)` in the helper’s Makefile, ensuring the Rust library is included when needed. Junio C Hamano has now merged this directly to `master` ahead of the Git v2.55.0-rc1 release, treating it as a regression fix.

The root cause is that `libgit.a` now includes Rust code (e.g., varint encoding/decoding) even for components like the credential helper that don’t use it, exposing a long-standing build system limitation where dependencies are too coarse-grained. While the patch restores linking, it doesn’t address the deeper issue, which may resurface in other non-Rust components. The fix aligns with how other Git binaries are linked and is considered low-risk, though it highlights the growing friction between Rust integration and the existing build system. No test coverage was added, as the problem was purely a build-time regression.
