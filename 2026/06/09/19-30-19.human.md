This is a discussion about the behavior of the experimental `git history reword` command when no changes are made to a commit message. Junio C Hamano is responding to Justin Tobler's concerns about aborting rewording operations.

Junio clarifies that he wants the command to succeed quietly when no changes are made, rather than aborting with an error. The discussion reveals an important design principle emerging: silent handling of no-op cases is preferred over explicit failure. Junio emphasizes this should be a smooth operation rather than an error condition, even drawing a distinction between "not rewriting" versus "aborting" as different user experiences.
