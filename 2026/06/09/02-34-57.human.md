This is a performance bugfix targeting the ref-filter subsystem, addressing a regression in `git branch`, `git branch --remotes`, and `git tag` commands introduced by commit dabecb9db2 in Git 2.51.0.

The patch restores prefix-scoped iteration for these commands, fixing a performance issue where they were unnecessarily reading all loose refs before applying their namespace filters. The regression occurred when ref iteration was changed to use `ref_iterator_seek()` after construction rather than passing the prefix during iterator creation. The files backend's loose-ref cache priming meant this caused O(n) scaling with unrelated loose refs.

Performance measurements show dramatic improvements - from ~2.8 seconds to ~0.1 seconds for commands listing branches/tags when there are 10,000 unrelated loose refs. The fix maintains the existing `--start-after` functionality while optimizing the common case where no cursor position is needed.

The patch includes new REFFILES-gated performance tests that demonstrate the improvement by creating a repository with one branch, one remote-tracking branch, one tag, and 10,000 unrelated loose refs. The change has been reviewed by Patrick Steinhardt and Junio C Hamano, with Junio noting this doesn't affect the dormant `start_after` functionality but properly fixes the immediate regression.

This is a well-motivated fix with clear performance data, addressing a real regression that affects common commands. The patch is focused and comes with appropriate test coverage.
