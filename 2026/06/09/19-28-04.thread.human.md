This thread discusses a clean-up patch that removes a redundant reachability function from Git's commit-reach.c. The patch eliminates `get_reachable_subset()` in favor of the newer `tips_reachable_from_bases()`, which provides equivalent functionality with better performance when commit-graph is available. 

The original function used BFS while the replacement uses DFS with generation number pruning for efficiency. The only caller in remote.c has been updated to use the new function, requiring some flag adjustments (switching from bit 0 to TMP_MARK). Test cases have been renamed to reflect testing the new function instead.

The commit message makes a strong case for the change, noting that while the BFS approach might have minor advantages without commit-graph, this edge case doesn't justify maintaining two implementations. The patch appears well-constructed with proper test updates and clear flag transition documentation. This seems like a straightforward improvement that simplifies the codebase while maintaining or improving performance characteristics.
