This is v14 of Harald Nordgren's series adding `git branch --prune-merged` for safe automated local branch cleanup, now addressing a critical regression that was preventing merge. The series has evolved through 14 iterations with extensive review and refinement.

The key fix in this version resolves a regression where the new warn-only mode was incorrectly affecting the behavior of existing `git branch -d -r` commands. The issue stemmed from the remotes path setting a local force variable but not setting the DELETE_BRANCH_FORCE bit that check_branch_commit() checks, causing it to wrongly run merge checks on remote-tracking branches. The fix makes flags the single source of truth in delete_branches() to prevent such mismatches.

While the author notes the changes work locally, there are still CI failures that may or may not be related to this series (referencing PR #2313 failures). The core functionality remains:
- Safe branch pruning based on merged status
- Configurable opt-out via branch.<name>.pruneMerged
- Dry-run support showing what would be deleted
- Protection for checked-out branches and other safety mechanisms

The series appears technically sound and ready for final review, having addressed Junio C Hamano's blocking concern about the remote-tracking branch regression. The remaining CI issues may need investigation but don't appear to be fundamental to the feature's correctness.
