This is a feature patch from Junio C Hamano adding a `--rename` option to `git update-ref`. The new option allows renaming refs (including their reflogs) with the syntax `git update-ref --rename <old-ref> <new-ref>`. 

The implementation warns users to prefer `git branch --rename` when operating on branch refs (under `refs/heads/`), since `update-ref` doesn't handle worktree HEAD updates or branch tracking configuration like the higher-level command does. The rename operation fails if the old ref doesn't exist or the new ref already exists.

Notably, this doesn't yet support renames in `--stdin` batch mode, as that would require deeper ref transaction API changes to handle atomic renames. The patch includes tests verifying the basic functionality, error cases, and reflog preservation.

The changes touch the update-ref documentation, command-line parsing, and core rename logic, plus new test cases. This appears to be a well-considered plumbing addition that fills a gap in the low-level ref manipulation toolkit while deferring more complex transactional integration for future work.
