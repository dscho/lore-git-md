This is a substantive review from Junio Hamano on Pablo Sabater's RFC patch series for the experimental `git history reword` command. Junio strongly disagrees with the premise that the current behavior of rewriting commits even when messages don't change is "wrong", calling this attitude "totally wrong".

Junio clarifies his position that while avoiding unnecessary rewrites might be a good optional behavior (similar to how `rebase -i`'s `pick` avoids no-op changes), the current always-rewrite behavior is not inherently incorrect. He suggests a more comprehensive approach: adding a new `--avoid-unnecessary-rewrite` option that would work across all history-modifying commands (`git history`, `rebase -i`, and `commit --amend`), not just for message changes but for any case where the only difference would be timestamp/committer info.

The review makes several key points:
1. The current behavior is not wrong - it's just one possible approach
2. Any new behavior should be implemented consistently across all related commands
3. Changes should be introduced as optional first, with potential default-flipping only after real-world validation
4. The scope should expand beyond just message changes to cover all types of no-op rewrites

Junio also rejects the idea of aborting on identical messages as a valid mode, preferring instead to either silently skip or proceed with the rewrite based on user preference. This review significantly raises the bar for the proposed changes, moving the discussion from a focused `git history reword` tweak to a cross-command design consideration about history rewriting behavior.
