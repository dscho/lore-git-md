Thread identity: Performance regression fix for ref-filter subsystem affecting `git branch`, `git branch --remotes`, and `git tag` commands, introduced in Git 2.51.0 by commit dabecb9db2.

Core problem: A performance degradation occurred when listing refs with prefixes (e.g. `refs/heads/`), the ref iteration was changed to read all loose refs before applying the prefix filter, rather than doing prefix-scoped iteration. This caused significant slowdowns when many unrelated loose refs exist.

Current status: The patch has been reviewed by Patrick Steinhardt and Junio C Hamano. It restores the original prefix-scoped iteration behavior for normal cases while maintaining the unscoped iteration behavior for `--start-after` cases (though no current commands use this combination). Benchmarks show ~25x speed improvement (2.8s -> 0.11s) with 10,000 loose refs.

Key technical details: 
- Fixes regression from dabecb9db2 in ref-filter.c
- Restores prefix-scoped iteration for files backend
- Maintains unscoped iteration for `--start-after` cases
- Adds REFFILES-gated performance tests
- Touches refs/files-backend.c and ref-filter.c

Participant positions:
- Patrick Steinhardt: Reviewed the fix
- Junio C Hamano: Reviewed, noted the patch preserves future `--start-after`+prefix capability while fixing immediate issue

Related work: Builds on original ref iteration changes from dabecb9db2. Performance impact similar to other ref backend optimizations in recent releases.
