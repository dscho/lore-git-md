Thread identity: Performance regression fix for ref-filter subsystem affecting `git branch`, `git branch --remotes`, and `git tag` commands, introduced in Git 2.51.0 by commit dabecb9db2.

Core problem: A performance degradation occurred when listing refs with prefixes (e.g. `refs/heads/`), where ref iteration was changed to read all loose refs before applying the prefix filter rather than doing prefix-scoped iteration. This caused significant slowdowns when many unrelated loose refs exist.

Current status: The patch has been reviewed by Patrick Steinhardt and Junio C Hamano. It restores the original prefix-scoped iteration behavior for normal cases while maintaining unscoped iteration behavior for `--start-after` cases. Benchmarks show ~25x speed improvement (2.8s -> 0.11s) with 10,000 loose refs. Karthik Nayak has proposed an alternative implementation approach that would maintain the current code structure more closely by modifying `refs_ref_iterator_begin()` to take the prefix directly during construction when `start_after` isn't used, avoiding IO-intensive loose ref caching.

Key technical details: 
- Fixes regression from dabecb9db2 in ref-filter.c
- Two implementation approaches now under discussion:
  - Original: introduces new `refs_for_each_ref_ext()` call
  - Karthik's alternative: modifies `refs_ref_iterator_begin()` to take prefix earlier
- Maintains unscoped iteration for `--start-after` cases
- Adds REFFILES-gated performance tests
- Touches refs/files-backend.c and ref-filter.c
