This is a performance bugfix targeting the ref-filter subsystem, addressing a regression introduced in Git 2.51.0. The patch restores prefix-scoped iteration for `git branch`, `git branch --remotes`, and `git tag` commands, which had been inadvertently slowed down by reading all loose refs unnecessarily.

The regression occurred when commit dabecb9db2 changed how ref iteration worked, moving from prefix-scoped construction to unscoped iteration with later seeking. This caused the files backend to read all loose refs before applying the prefix filter, leading to poor performance when many unrelated loose refs exist. The fix restores the original behavior for cases without `--start-after` while maintaining the new behavior for that option.

Performance impact is substantial: benchmarks show the commands running ~25x faster (from ~2.8s to ~0.11s) when there are 10,000 unrelated loose refs. The patch includes new REFFILES-gated performance tests to verify the improvement and prevent regression.

The change was reviewed by Patrick Steinhardt and Junio C Hamano, with the latter noting that while current commands don't combine `--start-after` with prefix filtering, the patch preserves that future capability. The solution carefully avoids changing the dormant `--start-after` behavior while fixing the immediate performance issue.
