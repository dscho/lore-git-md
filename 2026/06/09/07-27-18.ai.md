This is a technical discussion about path handling in Git's object database (ODB) infrastructure, specifically around the `chdir_notify_register()` mechanism. The exchange is part of Patrick Steinhardt's ongoing ODB abstraction series (patch 4/16).

Patrick responds to Karthik Nayak's observation about the `name` parameter in `chdir_notify_register()` being unused in most cases. While acknowledging there are some callers that do use it (notably `chdir_notify_reparent()` and reference backends), Patrick suggests the entire chdir notification infrastructure may be misguided. His key insight is that storing absolute paths would eliminate the need for path reparenting when directories change.

More significantly, Patrick outlines a broader architectural direction: he plans to make paths an internal implementation detail of ODB backends rather than exposing them through `struct odb_source::path`. This is because some storage backends may not have meaningful filesystem paths at all. He indicates this change will come in a separate patch series, starting with reference backends.

The discussion reveals an important design tension in the ODB abstraction - the balance between exposing implementation details (like paths) for compatibility versus keeping them properly encapsulated. Patrick's proposed solution would both simplify the code (by removing chdir notifications) and better support future pluggable storage backends. This is a substantive architectural discussion that goes beyond the immediate patch, showing how the ODB abstraction work is uncovering deeper design questions.
