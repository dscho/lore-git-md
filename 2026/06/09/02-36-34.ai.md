This is the first patch in a two-part performance optimization series that extends Git's memoized commit traversal to handle cycles safely. The patch focuses on making the `--contains` traversal robust against cycles introduced by replacement refs.

The key technical contribution is adding cycle detection to the commit-reach.c contains walk. The patch introduces a new `CONTAINS_IN_PROGRESS` state to track active commits during traversal. When a cycle is detected (by encountering an in-progress commit), the code safely falls back to Git's cycle-safe reachability walk after clearing the potentially corrupted cache.

The implementation includes thorough test coverage, with a new test case that explicitly creates a cyclic replacement ref history and verifies `git tag --contains` handles it correctly. The changes are backward-compatible and maintain the existing performance characteristics while adding safety.

This patch lays the groundwork for the second patch in the series, which will extend memoized `--contains` queries to other commands like `git branch` and `git for-each-ref`. The cycle handling is particularly important as it ensures the optimization remains correct even in edge cases.
