This is the first patch in a two-part performance optimization series that extends Git's memoized commit traversal to more commands. The patch focuses on making the traversal safe to use with replacement refs by adding cycle detection.

The key change is introducing a new `CONTAINS_IN_PROGRESS` state to track commits currently being processed during traversal. When the algorithm encounters a commit that's already marked as in-progress (indicating a cycle caused by replacement refs), it falls back to a slower but cycle-safe reachability check. The patch includes tests that verify this handles cyclic replacement histories correctly.

This is a preparatory change that enables the performance optimization in the second patch, which will extend memoized traversal to commands like `git branch --contains`. The approach is careful and well-tested, with clear commit messages explaining both the problem and solution. The changes are focused on the commit-reach.c internals and don't affect user-facing behavior yet.
