This is part 5/6 of Harald Nordgren's `git branch --prune-merged` series, which adds configurable branch cleanup functionality. The patch introduces a new `branch.<name>.pruneMerged` configuration option that allows users to exempt specific branches from automatic pruning.

Key points:
- When set to `false`, the branch will be skipped during `git branch --prune-merged` operations
- The setting is reported to the user (unless `--quiet` is used) to explain why a branch was preserved
- Explicit deletions via `git branch -d` ignore this setting and use the normal merge check
- The implementation includes comprehensive tests verifying both the opt-out behavior and that regular deletions remain unaffected

This completes the safety mechanisms for the new pruning feature, giving users fine-grained control over which branches should be considered for automatic cleanup. The patch maintains the series' careful approach to backward compatibility and user visibility.

The change fits naturally into the existing branch configuration options and follows the pattern of similar Git features that respect per-branch settings. With this addition, the series now provides all the major components needed for safe, configurable branch maintenance.
