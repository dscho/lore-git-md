Performance optimization for `git describe` that limits ref iteration to tags by default. This is a v2 patch from Tamir Duberstein that builds on an earlier 2008 optimization, further improving performance by avoiding iteration over non-tag refs when `--all` isn't specified.

The key change is adding a `refs/tags/` prefix filter to the ref iteration in `builtin/describe.c` when `--all` isn't used. The patch includes a new performance test showing dramatic improvements - from ~172ms to ~10ms (17x faster) when describing an exactly-tagged commit in a repository with 120,532 refs (only 330 of which are tags).

The v2 changes include:
- Testing with both ref backends
- Keeping ref count local to test setup
- Reporting native hyperfine benchmark output
- Adding a performance test case for the exact-tag scenario

The optimization is particularly relevant for large repositories with many non-tag refs, where the current implementation would waste time examining irrelevant refs before rejecting them. The patch maintains the same behavior while being significantly more efficient.
