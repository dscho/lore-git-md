This is a substantive review of a refactoring patch in the `the_repository` removal effort, focusing on moving HFS/NTFS protection configuration from global to repository-specific storage. Christian Couder provides detailed technical feedback on Tian Yuchen's initial patch, building on the thread's established context.

The review addresses all three questions raised in the original patch. Couder recommends:
1. Keeping default values in `environment.c` via new helper functions (`repo_protect_ntfs()`/`repo_protect_hfs()`) rather than in `repo_config_values_init()`
2. Preferring getter functions over macros for type safety and maintainability
3. Following Glen Choo's prior recommendation to use struct fields rather than Derrick Stolee's rejected `get_int_config_global` approach

The review maintains focus on the technical merits while providing clear guidance. Couder suggests the author help reviewers by explaining why previous approaches were rejected, indicating this is part of mentoring the contribution. The feedback is constructive and grounded in the project's architectural direction, particularly the ongoing effort to properly encapsulate repository state.

This continues the thread's substantive technical discussion about how to best eliminate these remaining globals while maintaining filesystem protection behavior, especially on Windows.
