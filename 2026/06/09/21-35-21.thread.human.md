Junio Hamano has proposed adding a `--rename` option to `git update-ref`, enabling direct ref renaming (including reflog preservation) through the low-level plumbing command. The new syntax `git update-ref --rename <old-ref> <new-ref>` provides atomic rename capability, though it deliberately excludes branch refs (recommending `git branch --rename` instead) since it doesn't handle associated worktree and tracking configuration. The implementation currently lacks batch mode support, as that would require deeper transaction API changes, but includes comprehensive tests for the basic functionality. This fills a useful gap in Git's ref manipulation toolkit while leaving room for future expansion.
