Junio C Hamano has proposed adding a `--rename` option to `git update-ref` to enable low-level ref renaming while preserving reflogs, now in its third iteration. The primary use case is Junio's workflow for managing "evil merges" stored under `refs/merge-fix/` that need repointing when topic merge orders change.

The core functionality remains stable: the command atomically renames refs with their reflogs, failing if the old ref doesn't exist or the new ref already exists. Version 3 focuses on documentation improvements following Patrick Steinhardt's review, making it clearer that this is plumbing meant for specialized cases like Junio's merge tracking, with `git branch -m` remaining the preferred way to rename branches. The implementation still excludes batch mode due to transaction API limitations, which Junio notes will need future work.

The patch has matured through substantive technical review, with v3 addressing final documentation concerns about properly framing the command's scope. Test coverage verifies the rename operation, error cases, and reflog preservation. With the remaining issues resolved, this appears ready for inclusion in the next cycle.
