Maintainer feedback on `git switch --ensure` proposal.

Junio C Hamano responds to the proposed `--ensure` (`-e`) flag for `git switch`, expressing reservations about the feature's design while offering concrete suggestions for improvement. His key points:

1. **Use case concerns**: Questions whether the proposed behavior should be supported at all, listing four distinct scenarios where blindly switching to an existing branch could be problematic (only one of which matches the patch's intended use case). Argues that the current behavior - where `-c` fails if the branch exists - provides a valuable safety check.

2. **Naming issues**: Strongly objects to `-e` as the short option, noting it conflicts with existing `--editor` expectations. Suggests starting with a more descriptive long option like `--create-if-missing` and letting the community propose a short form.

3. **Command parity**: Points out the inconsistency of adding this only to `git switch` without matching `git checkout` support, given that `switch` was originally meant to supersede `checkout` but both remain in active use.

The feedback maintains the project's characteristic balance between technical rigor and mentorship - while skeptical of the feature's value proposition, Junio provides clear guidance on how to improve the patch if the author chooses to pursue it. His response suggests the proposal needs stronger justification for why the potential footguns are worth the convenience gain.
