This is a feature patch from Git maintainer Junio C Hamano that adds a `--rename` option to `git update-ref`. The new option allows renaming refs (including their reflogs) with the syntax `git update-ref --rename <old-ref> <new-ref>`.

The implementation includes several key behaviors:
- It warns users to use `git branch --rename` instead when renaming branch refs (under `refs/heads/`), since `update-ref` doesn't handle worktree HEAD updates or branch tracking configs
- It properly validates refname formats and checks for existence/non-existence of old/new refs
- The rename operation is atomic at the filesystem level but not supported in `--stdin` batch mode yet (that would require deeper ref transaction changes)

The patch includes thorough test coverage of error cases (nonexistent source ref, existing destination ref) and success cases (including reflog preservation). The implementation looks clean and well-considered, as expected from the maintainer. This provides plumbing-level rename functionality that complements the porcelain `git branch --rename` command.
