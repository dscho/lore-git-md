This is the second patch in a performance optimization series that extends Git's memoized commit traversal to more commands. The key changes in this patch:

**Core change**: The patch enables memoized commit traversal (previously only used by `git tag --contains`) for all ref-filter` commands like `git branch --contains` and `git for-each-ref --contains` when generation numbers are available. This avoids redundant graph walks when checking multiple refs against the same commit.

**Performance impact**: Benchmark results show dramatic improvement - from 104 seconds down to 467ms for checking 62,174 remote-tracking refs against a commit. The speedup comes from reusing traversal results rather than walking the graph separately for each ref.

**Safety mechanisms**: The patch maintains the existing breadth-first walk as a fallback when generation numbers are unavailable, and properly handles error cases where ancestry cannot be determined (exiting rather than silently treating errors as matches).

**Testing**: Includes both functional tests (verifying correct behavior with missing ancestors) and performance tests (measuring the speedup with/without generation numbers). The test coverage is thorough, including edge cases for divergent refs and packed refs.

This builds on the first patch's cycle detection work to provide a complete solution for safely memoizing `--contains` queries across Git's ref-filter interface. The implementation appears well-considered, with clear commit messages and comprehensive testing showing both correctness and performance benefits.
