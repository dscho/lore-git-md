This is a discussion thread about the behavior of the experimental `git history reword` command, specifically handling cases where no changes are made to a commit message. Justin Tobler is weighing in on Junio C Hamano's earlier comments about whether unchanged messages should trigger an abort.

Justin sees value in allowing users to abort a reword operation by leaving the message unchanged, as it provides an escape hatch when users change their mind during editing. However, he agrees with Junio that an error message isn't necessary - the silent no-op behavior would be sufficient. He also argues against checking committer identity as part of the abort condition, since that would prevent aborting rewrites of commits by other authors.

The discussion has evolved from Pablo Sabater's original RFC patch (which proposed aborting on unchanged messages) toward a more nuanced approach where:
1. The command would silently skip rewriting when messages are unchanged
2. This would serve as a way to abort the operation if desired
3. Committer identity would not be part of the no-op detection

This aligns with Junio's preference for silent handling of no-op cases while still providing the functionality Justin describes. The thread shows the community converging on behavior that balances user control with quiet operation, though the exact implementation details (like whether to add a short `-r` option) remain open.
