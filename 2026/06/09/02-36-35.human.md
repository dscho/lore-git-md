This is the second patch in a performance optimization series that extends Git's memoized commit traversal to more commands. The patch focuses on enabling memoization for `--contains` queries in `git branch` and `git for-each-ref` when generation numbers are available, building on the cycle-safe traversal infrastructure added in the first patch.

The key change is modifying `commit_contains()` to use the memoized depth-first walk (previously only used by `git tag`) when generation numbers are enabled, falling back to the traditional breadth-first walk otherwise. The patch also fixes error handling - when the traditional walk fails to determine ancestry (returning -1), it now exits rather than treating it as a match.

Performance testing shows dramatic improvements: a 200x speedup (104s -> 467ms) when checking `--contains` across 62,174 remote-tracking refs with generation numbers enabled. The patch includes new performance test cases covering both the memoized path (with generation numbers) and the fallback path (without them), plus verification tests confirming correct behavior with missing parent commits.

The implementation is clean and well-tested, with clear commit messages linking to prior discussion. This appears ready to merge as a significant performance win for repositories with many refs, particularly given the preparatory work in the first patch to ensure cycle safety. The only open question might be whether to make the memoization unconditional (rather than generation-number-dependent), but the current conservative approach seems reasonable given the performance characteristics described.
