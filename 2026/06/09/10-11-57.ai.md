This is the final patch in Harald Nordgren's 14-iteration series adding `git branch --prune-merged` functionality, now introducing a `--dry-run` mode for previewing deletions. The patch completes the series' goal of providing safe, configurable local branch cleanup by allowing users to see what would be deleted before actually performing the operation.

The implementation adds a new `DELETE_BRANCH_DRY_RUN` flag that shows the same output format as actual deletions ("Would delete branch <name>") without modifying any refs. The dry-run output respects all the same safety checks and filters as the real operation, including the `--forked` filter, `branch.<name>.pruneMerged` config opt-outs, and protection for checked-out branches. The mode is explicitly tied to `--prune-merged` and rejected when used alone.

The patch includes comprehensive tests verifying that:
1. Dry-run shows exactly what would be deleted without making changes
2. The output correctly filters based on upstream matching and merge status
3. The command properly rejects standalone `--dry-run` usage

This completes the series' evolution from initial concept through multiple rounds of safety mechanisms (warn-only mode, per-branch config, HEAD protection) to this final usability polish. The dry-run capability addresses the last practical need for safely previewing bulk operations before execution.
