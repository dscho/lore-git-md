This is patch 3/6 in Harald Nordgren's v14 series introducing `git branch --delete-forked` (formerly `--prune-merged`), which provides safe automated local branch cleanup with configurable protections. The series has undergone extensive review over 14 iterations.

The current patch prepares the `delete_branches()` function for bulk operations by adding two new modes:
1. `DELETE_BRANCH_NO_HEAD_FALLBACK` - Skips the fallback to HEAD when checking if a branch is merged, used when the caller has already established the branch has an upstream
2. `DELETE_BRANCH_DRY_RUN` - Enables rehearsal mode that shows what would be deleted without actually removing refs

Key implementation details:
- Maintains backward compatibility for existing callers
- Adds proper flag handling for the new modes via bitflags
- Updates the branch merge check logic to respect the no-HEAD-fallback mode
- Implements dry-run output that matches the style of actual deletion messages
- Preserves all existing safety checks and error handling

The changes are focused on enabling the bulk branch cleanup functionality while keeping the existing behavior for direct `git branch -d` calls intact. This is part of the series' overall goal to provide safe, configurable branch management with protections against accidental data loss.

The patch builds on previous iterations that addressed remote-tracking branch behavior and introduced warn-only mode, now completing the core functionality needed for the `--delete-forked` feature. All major technical concerns from earlier reviews appear to have been addressed at this point.
