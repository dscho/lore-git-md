This is a follow-up discussion about the recently merged typo-fix patch series. Kristoffer Haugsbakk reflects on the process of handling typo fixes, particularly when they relate to topics that will be backported to maintenance branches.

The key observation is that while Tuomas Ahola's typo fixes were correctly based on master branch (since the related `kh/name-rev-custom-format` topic wasn't destined for maint), there are cases where typo fixes might need to target the original topic branch instead. This would be relevant when the base topic is scheduled for backporting to maint, ensuring the fixes propagate to both master and maintenance branches.

Kristoffer notes this doesn't apply to the current case since Junio has already merged the patch, but raises it as a consideration for future similar situations. The discussion remains at a process level - no new technical changes are proposed, just a refinement in how contributors might approach typo fixes for topics with different merge trajectories.
