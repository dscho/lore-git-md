This is a discussion about the behavior of the experimental `git history reword` command when no changes are made to a commit message. The thread focuses on whether the command should silently skip unchanged commits or require explicit user confirmation, particularly when the committer identity differs from the current user.

Junio responds to Pablo Sabater's position that unchanged commits should be preserved as-is, even if the committer identity differs. He presents two common scenarios where users would want to rewrite committer identity without changing the message:
1. New users correcting initial commits made with incorrect identity
2. Users managing multiple identities (work vs personal) who need to fix misattributed commits

The discussion has evolved from purely technical implementation to considering real-world workflows where silent rewriting of committer information would be desirable. This represents a shift from the earlier focus on message-only changes, now acknowledging that identity correction is a valid use case that should be handled gracefully.

The thread continues to refine the behavior of this experimental command while establishing principles that may eventually apply to other history-modifying operations like `rebase -i` and `commit --amend`. The current consensus appears to favor silent handling of no-op cases when explicitly requested, though the scope of what constitutes a "no-op" (message-only vs including committer identity) remains under discussion.
