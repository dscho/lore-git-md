This thread addresses a performance regression in Git's ref-filter subsystem that significantly slowed down common commands like `git branch`, `git branch --remotes`, and `git tag` when many loose refs exist. The issue was introduced in Git 2.51.0 by commit dabecb9db2, which changed ref iteration to read all loose refs before applying prefix filters, causing up to 25x slowdowns with 10,000 loose refs.

Tamir Duberstein has now sent v3 of the fix, implementing Karthik Nayak's suggested approach that modifies `refs_ref_iterator_begin()` to take the prefix directly during construction. This restores the efficient prefix-scoped iteration while maintaining the unscoped iteration needed for `--start-after` functionality. Benchmarks show dramatic improvement, reducing runtime from ~2.8s to ~0.11s in the problematic case. The patch includes new REFFILES-gated performance tests to prevent regression.

The fix has been reviewed by key contributors: Patrick Steinhardt examined the original approach, Junio C Hamano confirmed it preserves future capabilities, and Karthik Nayak provided the crucial implementation suggestion that shaped v3. With the performance issue resolved and tests added, this fix is ready for inclusion in the maint branch to address the regression in released versions.
