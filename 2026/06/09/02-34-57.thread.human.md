This thread documents the resolution of a performance regression in Git's ref-filter subsystem that affected common commands like `git branch`, `git branch --remotes`, and `git tag`. The issue, introduced in Git 2.51.0, caused a 25x slowdown when listing refs with prefixes (e.g., `refs/heads/`) by unnecessarily reading all loose refs before applying the prefix filter.

Tamir Duberstein authored the fix, which restores prefix-scoped iteration behavior while maintaining compatibility with the `--start-after` option. The solution modifies `refs_ref_iterator_begin()` to take the prefix earlier when possible, avoiding the I/O overhead of reading irrelevant refs. Benchmarks show dramatic improvement - from ~2.8s to ~0.11s when operating with 10,000 loose refs.

The patch went through four iterations, incorporating feedback from Karthik Nayak (who proposed the implementation approach) and Patrick Steinhardt (who reviewed the technical details). Junio Hamano has reviewed previous versions and noted the patch preserves future capabilities. The current version addresses all technical and documentation concerns, with proper historical context in the commit message and backend-agnostic performance tests. The fix is targeted for the maint branch as it addresses a regression in released versions, and appears ready for merging with consensus from all involved reviewers.
