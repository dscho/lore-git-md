Performance optimization for `ls-files` with pathspecs.

This patch optimizes `git ls-files --deleted` and `--modified` by applying pathspec filtering before expensive `lstat()` calls when there's only a single pathspec. The change avoids unnecessary filesystem operations for non-matching entries while preserving the existing behavior for multiple pathspecs where the matching cost would outweigh the benefit.

The commit includes thorough performance measurements showing dramatic improvements for single-pathspec cases (60.7s -> 1.1s in one test case), while carefully avoiding regressions for multiple pathspecs. Jeff King helped identify and address a potential performance pitfall with many pathspecs that was present in v1.

New test cases verify both the optimization and the preserved behavior for wildcard pathspecs and error handling. The patch appears well-considered with clear benchmarks showing the tradeoffs and careful attention to edge cases.
