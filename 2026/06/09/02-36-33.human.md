Performance optimization patch series that improves `--contains` traversal efficiency across multiple Git commands.

This two-part series from Tamir Duberstein aims to reuse graph traversal results when checking if commits are contained in references, similar to how `git tag` already optimizes this. The key changes:

1. First patch makes the commit-reach machinery safely handle cycles that can occur with replacement refs (like those from `git replace`). This is a prerequisite for the optimization.

2. Second patch extends the memoization technique used by `git tag` to other ref-filter users (`for-each-ref`, `branch`, etc.), avoiding redundant graph walks when multiple refs share history.

The series includes tests verifying both the cycle handling and performance improvements. Benchmark results show significant speedups (40-50% reduction in some cases) for commands like `git branch --contains` on repos with many refs.

The changes look well-structured with clear commit messages and thorough testing. This appears to be a solid optimization that builds on existing patterns while properly handling edge cases. The v2 revision addresses potential cycle issues upfront and splits the work into logical steps.
