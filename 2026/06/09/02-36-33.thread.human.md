This thread introduces a performance optimization that extends Git's memoized commit traversal from just `git tag --contains` to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The optimization reuses commit traversal results across multiple `--contains` queries, yielding dramatic speedups—100x with generation numbers (104s → 468ms for 62k refs) and 10x without.

The series has evolved through multiple versions with substantive feedback from Jeff King (Peff), all addressed by Tamir Duberstein. The current implementation consists of three well-separated patches: (1) robust cycle detection for safety with replacement refs, (2) the core optimization for all ref-filter commands, and (3) improved error reporting. The second patch, now under discussion, enables the memoized walk for all frontends while preserving existing behavior, with comprehensive tests covering both correctness and performance.

The changes touch `commit-reach.c` and `ref-filter.c`, maintaining fallback paths when optimizations aren't available. Reviewers have validated the approach's safety against cycles, performance gains, and test coverage. With all open items resolved, the series appears ready to merge, offering significant benefits for repositories with many refs.
