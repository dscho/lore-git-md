This is patch 8/17 in Patrick Steinhardt's v2 series converting packed object storage to use `struct odb_source` as part of the ODB abstraction effort. The patch refactors `has_object_pack()` to use the higher-level `packfile_store_read_object_info()` interface rather than directly calling the low-level `find_pack_entry()`.

The change is mechanical but important for the architectural goal - it moves the packed object storage implementation one step closer to being fully encapsulated within the odb/source-packed.c file. The new version maintains identical behavior while using the intended public API surface rather than reaching into internal implementation details.

Key technical points:
- Replaces direct `find_pack_entry()` call with `packfile_store_read_object_info()`
- Functionally equivalent since the latter internally calls the former when no info pointer is provided
- Part of preparing `find_pack_entry()` to become file-local to source-packed.c
- Touches only packfile.c (6 lines changed)
- Follows the series' pattern of moving implementation details behind the odb_source interface

This continues the series' steady progress toward completing the packed storage backend's conversion to the odb_source abstraction. The change is straightforward and unlikely to be controversial given it's a mechanical refactor with no behavior change.
