Performance optimization for `git describe`. This patch limits the default ref iteration in `git describe` to only tags unless `--all` is specified, avoiding unnecessary work when scanning repositories with many non-tag refs.

The change builds on a 2008 optimization that already skipped object lookup for non-tag refs, but now prevents those refs from being enumerated in the first place. The performance impact is substantial: in a test repository with 120,532 refs (only 330 of which are tags), the patch makes `describe --exact-match` run ~17x faster (from 171.7ms to 9.9ms mean time).

The patch includes a new performance test that creates 10,000 unrelated refs to demonstrate the improvement. The implementation is straightforward - just setting the `prefix` field of the ref iteration options to "refs/tags/" when `--all` isn't used. This is v2 of the patch, which adds more thorough benchmarking across ref backends and cleans up some test details from v1 submission.
