Bugfix addressing a thread sanitizer (TSAN) race condition in the transport helper's debug logging, now in its third iteration. This version incorporates Jeff King's (Peff) suggestion to add a `BUG()` check for uninitialized state rather than silently treating it as disabled.

The patch continues to move initialization of the debug flag (`transfer_debug_enabled`) from the racy `transfer_debug()` function to `bidirectional_transfer_loop()`, ensuring thread safety by setting the flag before worker threads are created. The key addition in v3 is the explicit `BUG()` check when the flag is uninitialized (-1), making programming errors immediately visible rather than silently ignored. This maintains the debug behavior while being more defensive about incorrect usage.

The change remains low-risk as it only affects debugging scenarios when `GIT_TRANSLOOP_DEBUG` is set, but the thread shows careful attention to thread safety in concurrent code paths. With this iteration addressing Peff's substantive review, the patch appears well-vetted and ready for inclusion. The corresponding TSAN suppression is removed since the race condition is now properly fixed at the source.
