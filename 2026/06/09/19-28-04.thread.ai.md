This thread discusses Kristofer Karlsson's effort to consolidate two reachability functions in commit-reach.c (`get_reachable_subset()` and `tips_reachable_from_bases()`) into a unified implementation with configurable traversal modes (DFS or priority queue). The v2 patch series attempted to address prior feedback from Junio Hamano and Derrick Stolee, the original author of both functions.

Key technical details:
- Unified function uses `prio_queue` for both modes (LIFO stack for DFS, min-heap for PQ)
- DFS mode defers commit parsing until pop time for efficiency
- Merge commit revisits reduced (2-parent merges now require 1 visit instead of 3)
- First-parent traversal order preserved in DFS mode
- Remote.c caller updated to use PQ mode (matching original behavior)
- New exhaustive tests exercise all commits as tips
- 126 lines removed across 5 files (commit-reach.c, remote.c, test files)

Derrick Stolee has now provided a substantive review pushing back on the consolidation approach, raising several concerns:
1. The unified implementation creates unnecessary complication by maintaining two algorithms in one function
2. The commit message lacks adequate justification for merging the implementations
3. Potential performance regressions for repositories without commit-graphs
4. Suggests splitting into two logical steps if pursued (first adding new mode, then migrating callers)
5. Recommends discussing major direction changes in thread before implementing

Stolee provides historical context that the functions were intentionally kept separate due to different performance characteristics in different repository states (with/without commit-graphs). His feedback indicates the v2 approach may not be mergeable in current form and suggests either reverting to v1 with better performance documentation or engaging in more discussion before proceeding.

Performance measurements in v2 showed 1.09-1.14x speedups in some real-world cases, though the primary goal was code consolidation. Junio Hamano had initially questioned the rationale but was previously satisfied by the dual-mode approach and Stolee's real-world usage justification. However, Stolee's new objections have reopened the discussion and may require substantial revision or abandonment of the consolidation approach.

Key participants are Kristofer Karlsson (author), Junio Hamano (maintainer), and Derrick Stolee (original implementer). The thread now awaits either a revised approach from the author or further discussion addressing Stolee's concerns before proceeding.
