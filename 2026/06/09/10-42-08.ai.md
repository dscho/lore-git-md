This is the second patch in Pablo Sabater's v2 RFC series modifying the experimental `git history reword` command, part of Patrick Steinhardt's larger `git history` feature effort. The patch implements Junio's suggested approach from the v1 discussion - making the abort-on-identical-message behavior opt-in via a flag rather than the default.

The technical changes:
- Adds `COMMIT_TREE_ABORT_ON_SAME_MESSAGE` flag to control the new behavior
- Modifies `commit_tree_ext()` to return 1 when messages match and the flag is set
- Updates `cmd_history_reword` to use the flag while leaving `fixup` unchanged
- Includes tests verifying both the abort behavior for `reword` and the unchanged behavior for `fixup --reedit-message`

The patch maintains backward compatibility with existing commands like `git commit --amend` while establishing the more careful behavior for the new `git history` subcommand. The implementation cleanly separates the abort logic from the core commit rewriting, making it easy to extend to other subcommands if desired.

The test coverage is thorough, including both the positive case (aborting when messages match) and the negative case (allowing fixup to proceed). The use of `GIT_EDITOR=true` optimizes the tests as suggested in previous reviews.

This appears to be a well-executed response to the v1 feedback, implementing the requested changes while keeping the scope focused. The patch builds on the preparatory refactoring from patch 1/2 and leaves room for future discussion about output patterns and flag naming.
