This is patch 5/6 in Harald Nordgren's v14 series adding `git branch --prune-merged` functionality, which provides safe automated cleanup of merged local branches. The patch introduces a new `branch.<name>.pruneMerged` configuration option that allows users to exempt specific branches from being pruned.

The key addition is a per-branch opt-out mechanism where setting `branch.<name>.pruneMerged=false` prevents that branch from being deleted by `--prune-merged`, while still allowing explicit deletion via `git branch -d`. This is particularly useful for topic branches that may have some commits merged upstream but are still being actively developed. The patch includes comprehensive documentation updates and test coverage.

The implementation checks the config setting during branch pruning and skips any branches marked with `pruneMerged=false`, emitting a warning message unless `--quiet` is specified. The tests verify both the opt-out behavior and that explicit deletion still works regardless of the setting. This completes one of the final safety features for the series, giving users fine-grained control over which branches are eligible for automated cleanup.

The patch, like the rest of the series, maintains careful backward compatibility and follows Git's established patterns for branch configuration. It builds on the extensive safety mechanisms developed in previous iterations while adding this new layer of user control.
