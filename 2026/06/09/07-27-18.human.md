This is a technical discussion about path handling in Git's object database (ODB) abstraction effort, specifically regarding the `chdir_notify_register()` mechanism.

Patrick Steinhardt responds to Karthik Nayak's observation about the unused `name` parameter in `chdir_notify_register()` calls. While acknowledging some callers do use the name parameter (notably `chdir_notify_reparent()` and reference backends), Patrick suggests the entire notification infrastructure may be unnecessary if paths were stored as absolute rather than relative. 

He connects this to ongoing ODB work, noting that exposing paths in `struct odb_source` is problematic since some storage backends may not have disk paths at all. Patrick plans to:
1. Make paths an internal implementation detail of each backend
2. Convert paths to absolute where possible
3. Send a separate patch series for reference backends

The exchange shows Patrick thinking ahead about architectural implications beyond the immediate patch, while Karthik's review continues to surface useful tangential observations. This is part of Patrick's larger 16-patch series converting packed object storage to use `struct odb_source`, which is progressing well through review.
