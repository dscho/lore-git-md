This is the second patch in Pablo Sabater's v2 RFC series for the experimental `git history reword` command, part of Patrick Steinhardt's larger `git history` feature effort. The patch implements Junio's suggested approach from earlier discussion - making `git history reword` abort when the commit message is unchanged, but only when explicitly requested via a new flag.

The key technical changes:
- Introduces `COMMIT_TREE_ABORT_ON_SAME_MESSAGE` flag to control the abort behavior
- Modifies `commit_tree_ext()` to return 1 when messages match and the flag is set
- Updates `cmd_history_reword` to use the flag while leaving other subcommands like `fixup` unaffected
- Adds tests verifying the abort behavior for `reword` and confirming `fixup --reedit-message` remains unchanged

The implementation cleanly separates the new behavior from existing commands like `git commit --amend` to maintain backward compatibility, as Junio requested. The patch shows good attention to detail with comprehensive test coverage of both the new abort case and the preserved behavior of related commands.
