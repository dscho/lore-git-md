This is a performance optimization patch series that extends Git's memoized commit traversal to more commands. The key points:

**Overall goal**: The series aims to reuse commit traversal results across multiple `--contains` queries, similar to how `git tag --contains` already works, but extending this optimization to other ref-filter users like `git branch --contains` and `git for-each-ref --contains`.

**Technical approach**: 
1. The first patch adds cycle detection to the commit-reach.c contains walk to handle replacement refs safely.
2. The second patch introduces memoization of `--contains` results using generation numbers, building on the now-safe traversal.

**Changes from v1**: The author split out the cycle handling into a preparatory patch and added more test coverage, including exercising the cycle handling through the existing `git tag` path.

**Testing**: The series includes both functional tests (verifying cycle handling) and performance tests showing the speedup from memoization. The performance tests show a 2-3x improvement for repeated `--contains` queries on large repositories.

**Context**: This builds on Git's existing generation numbers infrastructure and the memoization already used by `git tag`. The changes are relatively focused - mainly adding the cycle safety and then plumbing through the memoization to other commands.

The patches appear well-structured with clear commit messages and thorough testing. The performance motivation is compelling for repositories with many refs, and the approach seems sound given Git's existing traversal infrastructure.
