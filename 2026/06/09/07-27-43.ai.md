This is a technical response in Patrick Steinhardt's ongoing series to abstract Git's packed object storage as part of the ODB (object database) backend effort. The exchange specifically addresses patch 2/16, which moves packed source functionality into the new "odb/" subsystem.

Patrick acknowledges Karthik Nayak's earlier review about the awkward split of `struct packfile_list` and related declarations between headers. While agreeing with the current organization isn't ideal, Patrick identifies a cyclic dependency issue between "packfile.h" and the new "odb/source-packed.h" as the root cause. 

Rather than keeping the structures in "packfile.h" as Karthik suggested, Patrick proposes a different solution: moving this code into a new standalone "packfile-list.{c,h}" to break the cyclic dependency while keeping related functionality together. This shows Patrick is considering both the architectural concerns raised and the technical constraints of header dependencies.

The response indicates the series will see a revision to address this header organization issue, though the core ODB abstraction work remains unchanged. This is part of the broader effort to decouple packed object storage from the files backend while maintaining compatibility with other subsystems like the transport layer that also use packfiles.
