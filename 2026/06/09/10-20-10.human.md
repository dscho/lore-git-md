This is a review comment on a refactoring patch in the `the_repository` removal effort. Christian Couder suggests improvements to Tian Yuchen's patch that moves HFS/NTFS protection configs from global variables to repository-specific storage.

The review is substantive, proposing helper functions to cleanly handle the temporary fallback to `the_repository` while maintaining the architectural direction. Couder suggests wrapping the conditional access pattern in `repo_protect_ntfs()` and `repo_protect_hfs()` functions, which would:
1. Centralize the fallback logic
2. Make the default values explicit
3. Prepare for future where callers can pass repository pointers other than `the_repository`

The review also notes the `gitdir` check prevents calling config functions before config is loaded, suggesting this be documented. This shows attention to initialization ordering - a subtle but important consideration when moving global state.

The feedback is constructive and clearly aligned with the patch's goals, offering concrete improvements while acknowledging the transitional nature of the changes. The suggested approach would make the code more maintainable as the `the_repository` removal effort progresses.
