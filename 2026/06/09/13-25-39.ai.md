This is a review from Phillip Wood on Pablo Sabater's v2 patch for the experimental `git history reword` command, which is part of Patrick Steinhardt's larger `git history` feature effort. The patch currently makes `git history reword` abort when the commit message is unchanged (as suggested by Junio in earlier feedback), but Phillip raises an important additional consideration.

Phillip suggests expanding the no-op detection to also check for unchanged committer identity, since users might run `reword` to fix incorrect committer information. This would make the behavior more comprehensive by catching another common case where a rewrite would be unnecessary. The suggestion aligns with Junio's broader push for consistent handling of no-op rewrites across Git commands.

The review is substantive - it engages with the technical implementation and proposes a meaningful extension to the patch's logic. Phillip doesn't just comment on the current code but thinks ahead to real-world usage patterns that could affect the feature's behavior. This continues the thread's theme of carefully considering when history modifications should be considered no-ops.

The suggestion would require modifying the `COMMIT_TREE_ABORT_ON_SAME_MESSAGE` check to also compare committer info, which could be done by storing and comparing the original committer ident alongside the message. This would maintain the patch's clean separation of concerns while making the no-op detection more thorough.
