This is a v2 RFC patch series from Pablo Sabater proposing changes to the experimental `git history reword` command, part of Patrick Steinhardt's larger `git history` feature effort. The series has evolved significantly from v1 based on Junio's feedback, now focusing narrowly on aborting reword operations when the commit message is unchanged.

Key changes in v2:
- Introduces an explicit flag to control the abort behavior rather than making it default
- Drops the feedback output proposal (moved to a future series)
- Optimizes tests using `GIT_EDITOR=true` per D. Ben Knoble's suggestion
- Clarifies rationale for not changing `git commit --amend` behavior (backward compatibility)

The implementation now modifies `commit_tree_ext()` to support abort-on-identical-message when requested, while allowing other subcommands like `fixup` to proceed regardless. The series maintains its focus on the new `git history` command rather than trying to change established behaviors in amend/rebase.

Technical changes affect `builtin/history.c` and its test files, with the abort behavior gated behind a new flag. The cover letter raises an open question about whether similar behavior should apply to `git history fixup --reedit-message`, though the current patches don't address this.

This version shows good responsiveness to prior feedback while maintaining the core goal of preventing no-op rewrites in the new command. The narrow technical scope and clear version-to-version progression suggest the author is following Git development norms effectively for a relatively new contributor.
