Junio C Hamano has raised substantive concerns about Lei Zhu's proposed `git switch --ensure` feature, which would combine branch creation and switching into a single idempotent operation. While acknowledging the intent to simplify workflow, Junio questions whether the feature's design adequately addresses the full range of branch-switching scenarios users encounter. He particularly objects to the `-e` short option as conflicting with existing conventions (`--editor`) and suggests `--create-if-missing` as a clearer alternative. 

The maintainer also highlights an inconsistency in only implementing this for `git switch` without matching `git checkout` support, given that many users still rely on the older command. Most fundamentally, Junio suggests the current explicit failure when switching to a non-existent branch may actually be preferable—it forces users to consciously choose their next action rather than making assumptions. This feedback indicates the proposal will require significant revision to address use case analysis and command parity before implementation details like naming can be settled.
