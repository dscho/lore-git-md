This thread is an RFC proposal by Pushkar Singh to add `--only` and `--except` options to `git clone`, letting users specify sparse-checkout paths upfront instead of running `git sparse-checkout set` afterward. The goal is to streamline monorepo workflows where developers only need a subset of the repository.

The discussion so far has centered on two designs: Pushkar’s CLI flags (e.g., `--only=README.md,frontend`) and Jeff King’s suggestion to allow providing a patterns file (like `.git/info/sparse-checkout`) at clone time. Pushkar clarified that his proposal is a convenience layer over the existing `git sparse-checkout set` workflow, not a replacement for the patterns file, and that the feature’s value is ergonomic rather than performance-related. No implementation exists yet, and the thread is waiting for input from sparse-checkout domain experts like Derrick Stolee or Elijah Newren to gauge whether the feature is worth pursuing. The open questions remain interface design, usefulness, and integration with the existing sparse-checkout logic.
