This thread is an early-stage proposal from Pushkar Singh to add `--only` and `--except` options to `git clone`, letting users specify sparse-checkout paths upfront instead of running a separate `git sparse-checkout set` afterward. The idea targets monorepo workflows where developers only need a subset of the repository.

So far, there’s been no community feedback—the author’s recent follow-up is just a ping asking whether the proposal seems worth pursuing. The original RFC suggested reusing Git’s existing sparse-checkout machinery and floated two interface designs (comma-separated values or repeated flags), but no one has weighed in on usefulness, edge cases, or implementation details. Until substantive discussion begins, the feature’s prospects remain uncertain.
