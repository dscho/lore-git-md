This thread is about a proposed new feature for `git clone` that would let users specify sparse-checkout paths directly during the clone operation, eliminating the need for a separate `git sparse-checkout set` step afterward. The proposal comes from Pushkar Singh and targets developers working with monorepos who typically only need a subset of the repository.

The idea introduces two new options: `--only` for inclusion patterns and `--except` for exclusion patterns. These would internally enable sparse-checkout mode and configure the pathspecs automatically. The author suggests either comma-separated values (`--only=README.md,frontend`) or repeated options (`--only=frontend --only=tests`) as possible interfaces, with a preference for the comma-separated form. The implementation would extend `builtin/clone.c` to parse these options and reuse Git's existing sparse-checkout logic.

So far, the thread is just the initial RFC seeking feedback on whether this feature would be useful, which interface style is preferable, and what potential concerns might arise. No implementation work has started, and no responses from other contributors have been posted yet. The proposal focuses specifically on the `clone` command and doesn't mention any changes to other Git operations.
