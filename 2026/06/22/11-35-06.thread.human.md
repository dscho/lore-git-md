Pushkar Singh proposed adding `--only` and `--except` options to `git clone` to let users specify sparse-checkout paths up front, avoiding a separate `git sparse-checkout set` step. The idea targets monorepo workflows where developers only need a subset of the repository. So far, the thread has received no feedback—until now.

Jeff King (Peff) just weighed in with a cautious but constructive review. He suggests an alternative design: instead of new CLI flags, users could provide a patterns file (like `.git/info/sparse-checkout`) at clone time, reusing existing sparse-checkout machinery more directly. This sidesteps new pathspec parsing logic but might feel less intuitive than CLI options. Peff also clarifies that the feature wouldn’t enable partial clones of specific paths—servers typically disable path-based filters for performance reasons—so the benefit would be purely ergonomic. He recommends cc’ing Derrick Stolee and others with sparse-checkout expertise to get deeper feedback.

The thread is still in the early design phase, with no implementation yet. The key open questions are whether the feature solves a real pain point, what interface (CLI flags vs. file-based patterns) works best, and how to cleanly integrate it with existing sparse-checkout logic. The proposal’s fate likely depends on whether other contributors—especially those familiar with sparse-checkout—see value in it. For now, Peff’s review keeps the conversation alive but doesn’t tip the scales either way.
