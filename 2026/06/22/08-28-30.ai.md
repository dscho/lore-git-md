This is the **eighth patch in Patrick Steinhardt's v5 refactoring series** for Git's reference backend, implementing the **lazy-loading design** to resolve recursive initialization issues caused by "onbranch" configuration conditions. This patch specifically targets the "files" backend, deferring the parsing of write-related configuration (`core.preferSymlinkRefs` and `core.logAllRefUpdates`) until the first write operation, eliminating the chicken-and-egg problem where early config reads could trigger recursive ref store access.

The patch introduces a new `files_ref_store_write_options` struct within `struct files_ref_store` to hold deferred write configuration, replacing the direct fields previously parsed during initialization. The `files_ref_store_write_options()` function lazily parses and caches these settings only when first accessed, using `repo_config()` to ensure consistent behavior with "onbranch" includes. The change touches `files_ref_store_config()`, `files_ref_store_init()`, `log_ref_setup()`, and `files_transaction_finish()`, updating them to use the deferred configuration. Test coverage in `t/t0600-reffiles-backend.sh` verifies that `core.preferSymlinkRefs` can now be set via an "onbranch" condition without triggering recursion.

This is a **well-motivated and technically sound refactoring** that directly addresses the root cause of the initialization-order issue. The lazy-loading approach is clean, with minimal behavior changes (only the timing of config parsing is altered) and no user-facing regressions. The patch is part of the larger v5 series, which has already received architectural approval from Jeff King (Peff) for its redesign. The "files" backend changes here are straightforward and unlikely to introduce edge cases, though the reftable backend refactor in later patches (9–11/11) may attract closer scrutiny due to its dynamic write option handling.
