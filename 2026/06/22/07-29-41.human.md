This is the **v17** revision of Harald Nordgren’s long-running series adding `git branch --delete-merged`, a safe automated local branch cleanup command. The series is now **feature-complete** and ready for final review, addressing all prior feedback including the critical stacked-branch safety requirement.

The headline change in v17 is the **stacked-branch protection**: if a branch is used as an upstream for any other branch (e.g., `feature2` stacks on `feature1`), it will **abort deletion by default** with a clear error message. This prevents breaking `@{u}` references and implicit `git rebase` workflows. The implementation is deliberately simple—it spares the base branch and repeats the check until no more branches are spared—avoiding edge cases like recursion or self-referential upstreams while preserving backward compatibility for future enhancements (e.g., `--retarget-upstreams`).

Other key improvements in v17:
- **Split `--dry-run` and `branch.<name>.deleteMerged` opt-out into their own commits** for clearer history.
- **Memory efficiency**: Reuses a single `strbuf` across the config loop.
- **Test suite**: Comprehensive integration tests now verify stacked-branch protection, per-branch opt-out, and `--dry-run` functionality in a single reusable repository setup.

The series provides **multiple safety mechanisms**:
- Never deletes checked-out branches (any worktree).
- Skips branches with missing upstreams or where `push == upstream` (e.g., `main` tracking `origin/main`).
- Silently skips unmerged branches (non-fatal).
- Per-branch opt-out via `branch.<name>.deleteMerged=false`.
- `--dry-run` preview mode (mirrors actual deletion logic).

The implementation is **well-structured**: unified flags-based API, precise `--forked` filtering, and natural CLI integration with existing `--merged`/`--no-merged` filters. The stacked-branch protection resolves the last major design debate, with Junio C Hamano and Phillip Wood now aligned on the abort-and-notify default.

This looks like a **mature, well-crafted contribution** that addresses a real workflow pain point while prioritizing safety. The series appears ready for merging pending final review.
