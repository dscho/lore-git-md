This is a refactoring and feature patch series targeting the connectivity check subsystem, specifically to make promisor object handling work generically across different object database (ODB) backends. The series consists of three patches that collectively extract and generalize the logic for searching promisor objects, removing a direct dependency on packfile internals.

The motivation is clear: currently, Git’s connectivity checks (which verify that all objects reachable from a set of refs are present) assume a packfile-based ODB, but the ongoing ODB abstraction effort (driven by Patrick Steinhardt) aims to support alternative backends that may not use packfiles at all. This series is a necessary step toward that goal, ensuring that connectivity checks remain functional in such repositories.

Patch 1 extracts logic to skip certain packs from `odb/source-packed.c`, likely to avoid redundant work or irrelevant packs during iteration. Patch 2 adds support for flags when iterating over an object prefix, which appears to be the mechanism by which the caller (in this case, the connectivity check) can influence iteration behavior—such as limiting the search to promisor objects. Patch 3 then modifies `connected.c` to use this new generic interface instead of directly accessing packfile internals, making the promisor object search backend-agnostic.

The series is part of Patrick Steinhardt’s broader ODB abstraction work, and the base commit and dependencies are explicitly noted. The changes are confined to two files (`connected.c` and `odb/source-packed.c`), with a net increase in code size, suggesting the addition of new functionality rather than pure refactoring. The commit messages and cover letter are concise but sufficient to understand the purpose and scope.
