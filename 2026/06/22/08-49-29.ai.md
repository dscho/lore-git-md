This is the third and final patch in a three-patch series refactoring Git’s connectivity checks to generalize promisor object handling, removing a direct dependency on packfile internals. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, which aims to make Git’s object storage layer pluggable and backend-agnostic.

The patch replaces the current packfile-specific logic in `connected.c` with a generic ODB iteration mechanism. Previously, the code iterated through all packfiles in the repository, checking each one for the presence of a given object using `find_pack_entry_one()`. Now, it uses `odb_for_each_object_ext()` with the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag and an object prefix filter, delegating the search to the ODB layer. This change ensures that connectivity checks work regardless of the underlying ODB backend (e.g., reftable, custom storage), not just packfiles.

The new implementation introduces a callback function `promised_object_cb()` that simply returns `1` when an object is found, signaling that the object is a promisor object. The iteration options (`opts`) are configured to limit the search to promisor objects and to match the full object ID. Error handling is preserved: if `odb_for_each_object_ext()` fails, the error is propagated; if it succeeds but finds no object, the code falls back to the traditional rev-list-based connectivity check.
