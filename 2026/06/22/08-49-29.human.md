This is the third and final patch in a three-patch series that refactors Git’s connectivity checks to remove their dependency on packfile internals, making them work generically across different object database (ODB) backends. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, which aims to support alternative storage backends (e.g., reftable) that may not use packfiles at all.

The patch replaces the current packfile-specific logic for checking whether an object is a promisor object with a generic ODB iteration mechanism. Previously, the code iterated through all packfiles in the repository and searched each one for the object using `find_pack_entry_one()`. Now, it uses `odb_for_each_object_ext()` with the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag and an object prefix filter, which yields all objects matching the given name that are part of a promisor pack. This approach is backend-agnostic and does not assume the ODB uses packfiles.

The change is confined to `connected.c` and introduces a new callback function, `promised_object_cb()`, which simply returns 1 to indicate that the object was found in a promisor pack. The patch also removes the explicit call to `odb_reprepare()`, as the new iteration mechanism handles pack loading internally. Error handling is preserved, with the iteration’s return value propagated to the caller.

This is a clean, well-motivated refactoring that directly addresses the architectural goal of making connectivity checks work with non-packfile backends. The patch is unlikely to be controversial, though reviewers may check for edge cases such as performance regressions or interactions with other ODB flags. The series as a whole looks like a necessary and well-executed step toward ODB abstraction.
