This is the fourth iteration of Toon Claes's feature patch series introducing a `--linearize` option to `` `git replay` ``. The series is now merged to Junio Hamano's `next` branch (as noted in the thread summary), but this v4 submission addresses a minor test infrastructure concern: replacing a bare `grep` call with `test_grep` to comply with upcoming `mm/test-grep-lint` checks.

The series consists of three patches: two preparatory refactors (converting `enum replay_mode` to a boolean and adding a helper for commit mapping) and the main implementation of `--linearize`. This option flattens merge commits by walking only first parents, replicating `` `git rebase --no-rebase-merges` `` behavior on the server side. The implementation is complete, with all prior feedback incorporated: documentation now includes `--linearize` in the SYNOPSIS, notes its incompatibility with `--revert`, and clarifies terminology ("drop merge commits"). Tests cover root commit handling, `--linearize`/`--advance` combinations, mutual exclusion with `--revert`, and patch preservation via `` `git range-diff` ``.

This v4 makes no functional changes—only a mechanical test adjustment to future-proof the suite.
