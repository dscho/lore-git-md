This is the sixth patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, now in its seventeenth iteration. It adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` configuration setting.

The patch introduces a new config key that, when set to `false`, exempts the named branch from automatic deletion by `git branch --delete-merged`. The exemption is reported to the user unless `--quiet` is given, so the reason for skipping is clear. Explicit deletion via `git branch -d` still works normally and ignores the setting, preserving the existing merge-check behavior.

The implementation is straightforward: during the candidate-filtering loop in `delete_merged_branches()`, the code checks for the config key and skips any branch that has it set to `false`. The test suite verifies that the opt-out works, that the skip message appears, and that explicit deletion still succeeds.

This is a well-motivated safety valve for iterative topic-branch workflows. The commit message and documentation are clear, the code is clean, and the tests cover the advertised behavior. There are no red flags; the patch looks ready for final review.
