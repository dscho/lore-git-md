This is the first patch in the v4 series introducing `git replay --linearize`. It refactors the `enum replay_mode` into a boolean `reverse` flag, simplifying the code by eliminating redundant checks and BUG() calls for invalid enum values. The change is purely internal and does not alter behavior; it prepares the codebase for the `--linearize` feature in patch 3 by reducing the complexity of mode handling.

The patch touches only `replay.c`, replacing all instances of `enum replay_mode` with a `bool reverse`. The `create_commit` and `pick_regular_commit` functions are updated to use the boolean flag, and the ternary logic for determining the replay base (`reverse ? last_commit : onto`) is preserved. The diff is mechanical and well-contained, with no functional changes or new edge cases introduced.

This refactoring was previously reviewed by Justin Tobler, who raised a forward-looking design concern about extensibility if additional replay modes are introduced later. Toon addressed this in the v3 cover letter by noting that the current two-mode design (pick/revert) is stable and future modes would require a separate flag. Justin has not replied to confirm whether this resolves his concern, but the refactoring itself is uncontroversial and aligns with the series' goal of simplifying the code before adding `--linearize`.

The patch is part of a larger effort to implement `--linearize` as a simpler alternative to Johannes Schindelin’s merge-replay work (pull.2106). It is the first of three patches, with the next two introducing no behavior changes (helper extraction) and the core feature, respectively. No conflicts or merge status are reported; the series remains under review.
