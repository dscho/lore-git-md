This is the fourth patch in Patrick Steinhardt’s 11-part **v5 refactoring series** for Git’s reference backend. It fixes a **lifecycle management bug** in the `chdir_notify` subsystem by ensuring reference stores are properly unregistered when released.

The patch addresses a long-standing issue where reference stores (for the main repository, submodules, and worktrees) were registered with `chdir_notify` to handle relative path updates during directory changes, but never unregistered. This could lead to two problems: (1) memory leaks for the main repository’s reference database (which is never freed), and (2) dangling pointers for submodule/worktree reference databases (freed in `repo_clear()` but still registered). While these issues were latent (Git rarely changes directories mid-process), they represent clear correctness flaws.

The fix replaces one-way `chdir_notify_reparent()` calls with full registration/unregistration using `chdir_notify_register()` and `chdir_notify_unregister()`. Each backend (`files`, `packed`, and `reftable`) now implements its own reparenting callback to update paths when the working directory changes. The changes are mechanical and confined to the backend initialization/release functions, with no behavior changes for users. The patch is a prerequisite for later commits that will address the main reference database leak.

This is a **clean, well-scoped bugfix** that plugs a subtle but real hole in the reference backend’s lifecycle management. It’s unlikely to be controversial, though reviewers may check for edge cases in concurrent directory changes or interactions with the upcoming lazy-loading design in later patches. The patch is part of the uncontroversial cleanup portion of the series (patches 1–7/11) and should merge smoothly once the full series lands.
