This is the third patch in the v4 series adding a `--linearize` option to `git replay`. The patch itself is complete and well-executed: it implements the core functionality, updates the documentation, and expands the test suite to cover edge cases like `--advance` compatibility and `--revert`/`--linearize` mutual exclusivity.

Patrick Steinhardt’s review here is substantive but narrowly focused. He raises a forward-looking design question: whether `git replay` should mirror `git rebase`’s three-mode interface (`--no-rebase-merges`, `--rebase-merges`, and `--rebase-merges=rebase-cousins`) instead of exposing a simple boolean `--linearize`. This is not a rejection of the current patch, but it suggests the interface might need revisiting if the feature grows. His other comments are surface-level (a lowercase error message nit) and a brief approval of the merge-skipping logic.

The patch is ready for final review and looks uncontroversial. The only open question is whether the CLI design should be more ambitious now to avoid future churn, but that is a design-level discussion rather than a blocker for this series.
