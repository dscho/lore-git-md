This is the fourth patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, now in its seventeenth iteration. It prepares the internal `delete_branches()` function for the upcoming `--delete-merged` feature by adding two new modes: one that skips the HEAD fallback when a branch has no upstream, and another that will later support `--dry-run` (though the dry-run flag itself is introduced in patch 7/7).

The patch extends the flags-based API introduced in patch 2/7, adding `DELETE_BRANCH_NO_HEAD_FALLBACK` to the `enum delete_branch_flags`. This flag prevents the function from falling back to HEAD when checking whether a branch is merged, which is necessary for `--delete-merged` because the command should only consider branches merged into their upstream, not into HEAD. The change is mechanical: existing callers (like `git branch -d`) continue to use the HEAD fallback, while the new `--delete-merged` caller will pass the flag to disable it.

The patch also tweaks the logic in `branch_merged()` to avoid printing a "not fully merged" warning when `head_rev` is NULL, which happens when the caller opts out of the HEAD fallback. This is a minor UX improvement to prevent confusing output during bulk operations.

No behavior changes are introduced for existing commands, and the patch is a prerequisite for the core `--delete-merged` implementation in patch 5/7. The test suite for this patch is minimal, as the real validation comes in later patches that exercise the new flags. The patch is uncontroversial and aligns with the series’ goal of refactoring the deletion API for consistency.
