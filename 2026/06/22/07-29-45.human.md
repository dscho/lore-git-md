This is the fourth patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, now in its seventeenth iteration. The patch prepares the internal `delete_branches()` function for the upcoming `--delete-merged` feature by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that disables the traditional fallback to HEAD when a branch has no upstream.

The change is straightforward: when the new flag is set, the function skips the HEAD-fallback check entirely, relying solely on the branch’s upstream to determine merge status. This is a prerequisite for `--delete-merged`, which must ignore HEAD and consider only the configured upstream. Existing callers (like `git branch -d`) continue to behave as before, so there is no user-visible change in this patch.

The patch is clean and mechanical, touching only the flag-handling logic in `builtin/branch.c`. It builds on the flags-based API introduced in earlier patches and is clearly motivated by the needs of the `--delete-merged` implementation. No controversy or open questions are evident here; this is a well-scoped preparatory step.
