This is the first patch in Harald Nordgren’s seven-part v17 series implementing `git branch --delete-merged`. It introduces the `--forked` filter for `git branch --list`, which lists only branches whose configured upstream matches a given ref, remote name, or shell glob. The filter is designed to be composable with existing list filters like `--merged` and `--no-merged`, and serves as the foundation for the `--delete-merged` functionality in later patches.

The implementation adds a new `ref_filter_forked_add()` function in `ref-filter.c` that resolves ref arguments to their full refnames (e.g., `origin/main` → `refs/remotes/origin/main`) or accepts shell-style globs (e.g., `origin/*`). The filter logic in `filter_forked_match()` checks each branch’s upstream against the registered patterns, using exact matching for full refnames and wildmatch for globs. The patch also updates the CLI plumbing in `builtin/branch.c` to parse `--forked` arguments and pass them to the ref filter.

Test coverage is thorough, verifying that the filter works with:
- Exact refnames (e.g., `origin/one`).
- Remote shorthand (e.g., `origin` for the branch `origin/HEAD` points at).
- Shell globs (e.g., `origin/*` or `*/*`).
- Repeated arguments to widen the filter.
- Composition with other filters like `--no-merged`.
- Error handling for invalid arguments.

The patch is a refactoring-free building block for the series, with no behavior changes to existing commands. It is well-tested and aligns with the project’s expectations for list-filter extensions. The `--forked` filter will be used in patch 5 to identify branches eligible for deletion under `--delete-merged`.
