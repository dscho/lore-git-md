This is a usability-focused bugfix patch from Harald Nordgren’s two-part series, currently under review by Junio C Hamano. The patch aims to improve error messages when users accidentally omit the slash between remote and branch in `git branch --set-upstream-to`.

Junio’s reply questions whether the current error message—“branch 'main' does not exist”—is actually misleading in the scenario Harald describes. He points out that if the local branch doesn’t exist, Git fails early and correctly, regardless of what follows the `--set-upstream-to` option. The only time the argument parsing reaches the remote/branch part is when the local branch *does* exist, and in that case the existing error message already explains that the upstream branch doesn’t exist and suggests fetching or pushing with `-u`. Junio’s examples show that the current behavior is consistent and, in his view, already helpful.

The core of the disagreement is whether users commonly expect `git branch --set-upstream-to origin main` to mean “set upstream to origin/main” when the local branch is named something else. Junio hasn’t observed this mistake pattern himself and asks for clearer examples of when the current error message is genuinely unhelpful. Without that, he’s not yet convinced the patch addresses a real problem rather than a hypothetical one.
