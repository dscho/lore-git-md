This is the sixth and final patch in Tian Yuchen’s six-part performance series optimizing `paint_down_to_common()` for one-sided commit histories. The email is a **substantive review** from Derrick Stolee on the new technical documentation (`Documentation/technical/paint-down-to-common.adoc`) added by the patch.

Stolee endorses the idea of documenting the algorithm but raises two concerns. First, he notes the risk of the documentation drifting out of sync with the implementation and suggests adding a comment in `commit-reach.c` to remind contributors to update the document when the code changes. Second, he proposes an alternative workflow for future series: introduce the documentation *first* (as patch 1) to describe the *current* algorithm, then update both the code and the document in subsequent patches. This would make the behavioral changes more transparent and help reviewers track how the algorithm evolves.

The review does not challenge the content of the document itself, which remains a clear and thorough explanation of the algorithm, its use cases, paint flags, queue ordering, and termination conditions (including the new side-exhaustion optimization). Stolee’s feedback is procedural rather than technical, focusing on how to maintain alignment between code and documentation over time. The author has not yet responded to these suggestions.
