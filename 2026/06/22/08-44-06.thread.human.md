This thread is about a small but critical build fix for Git on 32-bit MinGW (Windows) using GCC 14.1. Johannes Schindelin ("Dscho") identified that `archive-zip.c` fails to compile because `localtime_r()`—a POSIX function used in the ZIP archive backend—isn’t declared due to missing feature macros in `compat/posix.h`. His patch ensures the function is properly exposed by defining `_POSIX_C_SOURCE` for both 32-bit and 64-bit MinGW builds.

Patrick Steinhardt reviewed the patch and confirmed its correctness, noting that while the fix could technically rely on `__MINGW32__` alone (as it covers both architectures), explicitly checking both constants improves clarity. The change is purely mechanical, with no functional impact, and directly addresses a build breakage that would otherwise block Git for Windows’ upcoming v2.55.0 release. Dscho also mentioned that this is a short-term fix, as Git for Windows plans to drop 32-bit support after v2.55.0. With no objections or open questions, the patch is ready to be merged.
