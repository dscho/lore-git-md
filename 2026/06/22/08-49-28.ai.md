This is the second patch in a three-patch series refactoring Git’s connectivity checks to generalize promisor object handling, making it independent of the ODB backend. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, which aims to support alternative backends (e.g., reftable) that may not use packfiles.

This patch enables `odb_for_each_object()` to accept flags even when an object prefix is specified, removing a previous restriction that forced callers to choose between the two. The change is implemented in `odb/source-packed.c`, where the function `for_each_prefixed_object_in_midx()` now checks whether a pack should be excluded based on the caller’s flags (e.g., `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`) using the helper `should_exclude_pack()`, which was introduced in Patch 1. The same logic is applied to non-multi-pack-index packs in `odb_source_packed_for_each_prefixed_object()`. If any pack fails to open, the function now propagates the error to the caller, ensuring failures are not silently ignored.

The patch is a small but necessary step toward making connectivity checks backend-agnostic. It introduces no new behavior but removes a technical limitation that would otherwise block the generalization work in Patch 3. The changes are confined to a single file and are well-explained in the commit message, though the rationale for propagating pack errors (rather than continuing silently) could be clearer. Reviewers may focus on whether the new logic handles all edge cases, such as interactions between flags or midx/packfile inconsistencies.

This patch is unlikely to be controversial, but it sets the stage for the more substantive changes in Patch 3. It is ready for review and appears to be a clean, incremental improvement. The series as a whole is a logical and well-structured contribution to the ODB abstraction effort.
