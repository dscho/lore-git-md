This is the seventh patch in Patrick Steinhardt’s 11-part **v5 refactoring series** for Git’s reference backend, which implements a lazy-loading design to resolve recursive initialization issues caused by "onbranch" configuration conditions. This patch is a **mechanical refactoring** that moves the parsing of `core.logAllRefUpdates` back into the individual ref backends (files and reftable), reversing a prior centralization in `repo-settings.c`.

The change is preparatory for the lazy-loading redesign introduced in later patches (8–11/11). By handling `core.logAllRefUpdates` in the backends—where other backend-specific configuration is already parsed—Patrick ensures all backend configuration follows the same deferred-parsing pattern. The patch touches nine files, primarily shuffling logic between `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c`, and `repo-settings.c`, with no behavior changes. The `enum log_refs_config` and its parsing function (`refs_parse_log_all_ref_updates_config`) are moved from `repo-settings.h` to `refs.h`, and the backends now initialize `log_all_ref_updates` to `LOG_REFS_UNSET` before parsing their own configuration via `repo_config()`.

This patch is uncontroversial and aligns with the series’ broader goal of decoupling read-critical and write-critical config parsing. It has no user-facing impact and is unlikely to face objections, though reviewers may check for edge cases in the reftable backend’s config parsing (e.g., whether `reftable_be_config` correctly handles the new `core.logallrefupdates` case). The patch is a necessary step toward the lazy-loading design, which addresses Jeff King’s concerns about config cache inconsistencies and recursive initialization.
