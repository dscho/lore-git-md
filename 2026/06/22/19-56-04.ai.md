This is a substantive review from Junio C Hamano on the first patch in Harald Nordgren’s usability-improvement series. Junio questions the fundamental premise of the patch: whether the current error message (“branch 'main' does not exist”) is actually misleading when the user types `git branch --set-upstream-to origin main` and the local branch `main` is missing. He argues that the command’s semantics require the local branch to exist first, so the error message is accurate and the user’s expectation (that `origin main` should be parsed as a remote-tracking branch) is not what the command is designed to do. Junio’s examples show that the existing error handling already gives clear feedback for other common mistakes (e.g., misspelled upstream branch names), and he suggests that the real issue may be a mismatch between user expectations and the command’s behavior rather than a deficiency in the error message itself. The review leaves the series’ motivation in doubt and signals that the patch may need a clearer problem statement or a different approach.
