Subject: [RFC PATCH] clone: add --only/--except for sparse-checkout paths
Series version: RFC (not yet a patch series)
Originating author: Pushkar Singh
Thread type: feature proposal (RFC)

Core problem or goal
Allow users to specify sparse-checkout inclusion/exclusion paths directly during `git clone`, eliminating the need for a separate `git sparse-checkout set` step afterward. Targets monorepo workflows where developers only need a subset of the repository.

Current status
Proposal stage; no implementation yet. Author is seeking feedback on usefulness, interface design (comma-separated values vs repeated options), and potential concerns before proceeding.

Key technical details
- Files touched: `builtin/clone.c` (option parsing, integration with existing sparse-checkout logic)
- New CLI options: `--only=<pathspecs>` (inclusion), `--except=<pathspecs>` (exclusion)
- Reuses existing sparse-checkout machinery; does not modify or replace it
- Scope limited to `git clone`; no mention of affecting `git fetch` or `git pull`
- Proposed interface styles: comma-separated values (`--only=README.md,frontend`) or repeated options (`--only=frontend --only=tests`); author prefers comma-separated form

Open questions and loose ends
- Interface design: comma-separated values vs repeated options (community preference unknown)
- Usefulness: whether the feature addresses a real pain point for enough users
- Potential concerns: edge cases in pathspec parsing, interaction with existing `--sparse` flag, backwards compatibility
- Implementation details: how to cleanly integrate with existing sparse-checkout initialization logic

Participant positions
None yet; this is the initial RFC email.
