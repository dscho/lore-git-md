This is the first patch in Phillip Wood's two-patch bugfix series (v3) targeting `git status` display correctness during interactive rebase. It refactors the todo command parsing logic in `sequencer.c` by extracting it into a new shared function `sequencer_parse_todo_command()`, which will be reused in the next patch to fix display issues in `git status`.

The patch moves the command-parsing loop and comment-line detection from `parse_insn_line()` into the new function, which now handles NUL-terminated input (rather than requiring an explicit end-of-line pointer). This changes behavior slightly for lines starting with CR but not followed by LF—previously treated as comments, they are now considered invalid. The new function is declared in `sequencer.h` and simplifies the calling code in `parse_insn_line()` by consolidating command validation and comment handling.

This is a preparatory refactoring with no user-visible changes, but it lays the groundwork for the second patch’s fix. The implementation is clean and aligns with the series’ goal of shared parsing logic. Reviewers (Junio C Hamano, Elijah Newren) have already validated this approach in prior iterations, and the change is uncontroversial. The patch touches only `sequencer.c` and `sequencer.h`, with no test modifications.
