This is the third and final patch in the v4 series introducing the `--linearize` option to `git replay`. It implements the core functionality: when `--linearize` is specified, `git replay` drops merge commits and replays only non-merge commits, matching the behavior of `git rebase --no-rebase-merges`.

The patch updates the documentation (`Documentation/git-replay.adoc`) to include `--linearize` in the SYNOPSIS and usage array, adds a clear description of the option, and documents its mutual exclusivity with `--revert`. The implementation adds a new boolean flag `linearize` to the `replay_revisions_options` struct and enforces the `--revert`/`--linearize` incompatibility via `die_for_incompatible_opt2` in `builtin/replay.c`.

In `replay.c`, the main replay loop (`replay_revisions`) now skips merge commits when `--linearize` is active, leaving `last_commit` unchanged so that subsequent commits are reparented onto the previous non-merge commit. The `pick_regular_commit` helper is extended to accept an optional `replayed_base` parameter, allowing it to handle the linearized topology. A clarifying comment explains the `last_commit` handling during merge linearization, and a BUG check ensures `--linearize` is not used with `--reverse`.

The test suite (`t3650-replay-basics.sh`) is expanded with four new tests: verifying `--linearize` with `--advance`, confirming `--revert`/`--linearize` incompatibility, replaying down to the root commit, and using `git range-diff` to confirm patch equivalence between the original and linearized commit chains. The tests reuse the existing history setup and cover edge cases like root commits and merge commit rejection.

This patch is well-motivated, thoroughly tested, and addresses all prior review feedback. The implementation is clean, the documentation is clear, and the test coverage is comprehensive.
