This is the **substantive review** of the stacked-branch protection design in Harald Nordgren’s `git branch --delete-merged` series, now in its final (v17) form. Phillip Wood engages directly with the retargeting proposal raised in the parent email, offering a concrete algorithm to resolve recursive dependencies (e.g., `b1→b2→b3`) and addressing self-referential upstreams (e.g., `b3→b3`).

Key technical details for the summarizer:
- **Subsystem**: Branch management (`builtin/branch.c`).
- **Behavior change**: Proposed **iterative resolution** for stacked branches during deletion, avoiding recursion edge cases.
- **Algorithm**:
  1. For each branch, check if its upstream is in the deletion set.
  2. If yes, remove the upstream from the deletion set and repeat the check for the upstream’s upstream (iteratively, not recursively).
  3. This ensures chains like `b1→b2→b3` are fully protected in a single pass.
- **Self-references**: Suggests **clearing the upstream config** of merged branches (e.g., `b2@{u} → unset`) rather than retargeting, with a warning. Notes this is safe because merged branches are unlikely to be rebased or checked out.
- **Implementation**: Proposes handling this logic within the `refs_for_each_branch_ref()` callback, avoiding the need for a separate upstream traversal pass.
- **Safety**: Explicitly limits retargeting to **unmerged branches only**, preserving the integrity of merged branches’ upstreams.

Phillip’s feedback **resolves the last major design ambiguity** in the series by:
1. Providing a **deterministic, single-pass algorithm** for recursive dependencies, eliminating the "luck of traversal order" concern.
2. Offering a **pragmatic solution** for self-references (clearing upstreams) that avoids complexity while maintaining safety.
3. **Aligning with Junio’s earlier preference** for abort-and-notify by implicitly endorsing a hybrid approach: protect unmerged branches via retargeting, but clear upstreams for merged branches (which are less critical).

This email is the **linchpin of the v17 design**, as it directly informs the stacked-branch protection implementation (now finalized as abort-and-notify with iterative `strset` tracking). The discussion here also clarifies that the `--dry-run` flag (patch 7/7) will need to reflect these edge-case behaviors. No further technical objections are expected; the next steps are documentation updates and test coverage for the edge cases described.
