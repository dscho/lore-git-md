This is the second patch in Phillip Wood's two-patch bugfix series (v3) targeting `git status` display correctness during interactive rebase. It implements the core logic to fix two long-standing display issues: failing to abbreviate commit object IDs for "fixup -C" and "merge -C" commands, and incorrectly replacing refnames (like "reset main") with their pointed-to object IDs.

The patch replaces the old `abbrev_oid_in_line()` function with a new `format_todo_line()` that uses the shared parsing function introduced in patch 1/2. The new implementation first parses the command type, then applies command-specific logic to determine which arguments should be treated as object IDs (and thus abbreviated) versus labels or refnames (which should be preserved verbatim). For commands that accept labels (like "merge" and "reset"), it checks for label existence via `refs/rewritten/` before attempting to abbreviate. The code handles edge cases like tag or branch names containing only hex digits by only abbreviating when the argument starts with the abbreviated OID.

Test coverage in `t/t7512-status-help.sh` is significantly expanded, now exercising a wider variety of commands including "fixup -C", "merge -C", "reset", and "update-ref". The tests verify that refnames remain intact while object IDs are properly abbreviated.
