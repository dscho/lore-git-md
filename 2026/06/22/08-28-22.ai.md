This is the **v5 rewrite** of Patrick Steinhardt's refactoring series targeting Git's reference backend infrastructure, now addressing the root cause of recursive initialization issues with "onbranch" configuration conditions. The series abandons the v4 workaround (selectively blocking "onbranch" includes) in favor of a **lazy-loading design** that defers write-config parsing until the first write operation, eliminating the fragile dependency on early config reads that could trigger recursive ref store access.

The 11-patch series is built on top of Patrick's `ps/setup-centralize-odb-creation` branch and spans `refs/` (files, packed, and reftable backends), `repository.c`, `setup.c`, `chdir-notify.c`, and test infrastructure. Patches 1–7 are carry-overs from v4, covering uncontroversial cleanups: inlining `check_and_apply_repository_format()` (1/11), eliminating redundant repository format application (2/11), deferring `GIT_REFERENCE_BACKEND` environment variable handling (3/11), fixing `chdir_notify` lifecycle management (4–5/11), freeing the main reference database (6/11), and moving `core.logAllRefUpdates` parsing back into ref stores (7/11). These patches are technically complete and unlikely to face objections.

The **core architectural shift** begins with patch 8/11, which refactors the "files" backend to lazy-load configuration, avoiding early reads that could trigger recursion. Patch 9/11 splits the reftable backend's write options into a separate struct, preparing for dynamic configuration parsing. Patch 10/11 applies the lazy-loading design to the reftable backend, decoupling stack construction from write-config parsing. Finally, patch 11/11 adds a safeguard against recursive ref store initialization, ensuring the lazy-loading mechanism cannot be bypassed.

The redesign addresses Jeff King's (Peff) concerns about config cache inconsistencies and user-facing regressions (e.g., `git commit` failing to respect `onbranch`-scoped `core.logAllRefUpdates`). By deferring write-config parsing to uncached paths like `repo_config()`, the series ensures consistent behavior while eliminating the root cause of recursion. The reftable backend's refactor is the most complex change, requiring dynamic write option passing and stack construction adjustments. Test coverage in `t/t0600-reffiles-backend.sh` and `t/t0613-reftable-write-options.sh` verifies that deferred config is correctly applied in write operations.

This series represents a **foundational shift** in how ref backends interact with configuration, with implications for future backend work (e.g., ODB-based ref stores). The lazy-loading design aligns with Peff's advocacy for minimizing early config loading and may serve as a template for other subsystems. While the reftable backend refactor could introduce edge cases, the overall approach is technically sound and resolves long-standing initialization-order constraints. The series is likely to attract close review from Karthik Nayak, Junio C Hamano, and Justin Tobler, particularly around the reftable backend's dynamic write option handling and backward compatibility.
