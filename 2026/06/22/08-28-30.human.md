This is the eighth patch in Patrick Steinhardt’s 11-part **v5 refactoring series** for Git’s reference backend, implementing the **lazy-loading design** that resolves the chicken-and-egg problem with "onbranch" configuration conditions. The patch targets the "files" backend, deferring the parsing of write-related configuration (`core.preferSymlinkRefs` and `core.logAllRefUpdates`) until the first write operation, eliminating early config reads that could trigger recursive ref store access.

The change restructures `struct files_ref_store` to introduce a nested `write_opts_lazy_loaded` struct that tracks whether write configuration has been parsed and holds the deferred settings. A new helper function, `files_ref_store_write_options()`, ensures the configuration is parsed on-demand using `repo_config()`, avoiding the cached config paths that caused inconsistencies in earlier versions. The patch updates all write operations (`log_ref_setup()`, `files_transaction_finish()`) to use the deferred configuration, while preserving the existing behavior for read operations.

The commit message clearly explains the motivation: the "files" backend’s early config reads could fail when "onbranch" conditions required access to the reference store, creating a circular dependency. By deferring write-config parsing, the patch eliminates this fragility without sacrificing functionality. The added test in `t/t0600-reffiles-backend.sh` verifies that `core.preferSymlinkRefs` can now be set via an "onbranch" condition, confirming the fix works as intended.

The implementation is clean, with no behavior changes for read operations, and the test coverage is appropriate.
