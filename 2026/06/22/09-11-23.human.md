This is a platform compatibility bugfix for Windows (MinGW) builds. Patrick Steinhardt reviews Johannes Schindelin’s patch that fixes a compilation error in GCC 14.1 on 32-bit MinGW by ensuring `localtime_r()` is properly declared. The patch adjusts `compat/posix.h` to check for both `__MINGW32__` and `__MINGW64__` when defining `_POSIX_C_SOURCE`, which exposes the POSIX function declaration.

The review is brief but substantive. Patrick confirms the technical rationale—`__MINGW32__` is defined for both 32-bit and 64-bit builds, so the original guard was insufficient—and agrees the explicit check for both constants improves clarity. He also notes that `localtime_r()` is available via `_POSIX_C_SOURCE` (not C23, which isn’t used here). The patch itself is minimal (one line) and directly addresses the build breakage without changing behavior.

This is a straightforward, well-motivated fix with no controversy. The error occurs in `dos_time()`, a helper function in the ZIP archive backend, and is reproducible by building with GCC 14.1 on 32-bit MinGW. Git for Windows plans to drop i686 support after v2.55.0, making this a short-term fix, but it’s still necessary for the upcoming release. No test coverage is included, but the change is mechanical and unlikely to need it. The patch is ready to merge.
