This is the second patch in Harald Nordgren’s seven-part v17 series introducing `git branch --delete-merged`. It refactors the internal `delete_branches()` function to use a flags-based API instead of two separate boolean arguments (`force` and `quiet`). The change is purely mechanical—no behavior changes—and prepares the codebase for the new deletion flags (`DELETE_BRANCH_SKIP_UNMERGED`, `DELETE_BRANCH_NO_HEAD_FALLBACK`, and `DELETE_BRANCH_DRY_RUN`) that later patches will add.

The patch defines an `enum delete_branch_flags` with two bits (`DELETE_BRANCH_FORCE` and `DELETE_BRANCH_QUIET`) and updates `delete_branches()` and its helper `check_branch_commit()` to accept an `unsigned int flags` parameter. Inside the functions, the flags are unpacked into local `bool` variables to keep the existing logic readable. The call site in `cmd_branch()` is updated to pass the flags as a bitmask.

This is a clean, well-motivated refactoring that aligns with Git’s established pattern for evolving APIs. The commit message is clear, the diff is minimal, and the change is fully backward-compatible. It’s a necessary stepping stone for the safety checks and stacked-branch protection that follow in later patches.
