This is the final patch in Harald Nordgren’s v17 series implementing `git branch --delete-merged`. It adds `--dry-run` support, completing the safety toolkit for the new command.

The patch is small and focused: it introduces a `DELETE_BRANCH_DRY_RUN` flag that, when set, prints “Would delete branch <name>” for each candidate branch and exits without touching any refs. The same filtering, safety checks, and stacked-branch protection apply, so the output exactly matches what a real deletion would do. The option is rejected unless `--delete-merged` is also given, preventing accidental misuse.

The implementation is straightforward: the flag is plumbed through the existing `delete_branches()` API, and the ref-deletion call is simply skipped when `dry_run` is true. Documentation and a new test case round out the change, verifying both the happy path and the error case.

This is a well-crafted finishing touch to a mature series. The patch itself is uncontroversial; the only open question is whether the series as a whole is ready for final review, and this patch does nothing to change that status.
