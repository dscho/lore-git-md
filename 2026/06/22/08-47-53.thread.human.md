Patrick Steinhardt has sent a two-patch series refactoring the ODB subsystem’s `reprepare()` callback into a more flexible `prepare()` API, part of his ongoing effort to enable pluggable object database backends. The series is currently at v1, with no prior iterations or reviews.

The refactoring introduces an `enum odb_prepare_flags` parameter to control cache invalidation, decoupling it from ODB preparation. This change allows `git grep` to work generically with pluggable ODBs by avoiding the current dependency on the "files" backend’s `odb_source_packed_prepare()` function. The patches touch 11 files, primarily in the `odb/` directory, with minor updates to `builtin/grep.c`, `midx.c`, and `packfile.c`. The new API preserves backward compatibility by wrapping the old `reprepare()` behavior.

No substantive feedback has been posted yet, leaving open questions about whether the flag-based design is sufficiently future-proof or if the commit messages could better articulate the edge cases motivating this change. The series is built on Patrick’s recent ODB work (`ps/odb-source-packed`) and directly supports the goal of making `git grep` backend-agnostic.
