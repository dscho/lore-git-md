This is a small but important **bugfix patch** in Patrick Steinhardt’s ongoing refactoring series to modernize Git’s reference backend. It plugs a **memory leak** in `repo_clear()`: the main reference database (`repo->refs_private`) was never freed, even though worktree and submodule reference databases were. The leak was masked by the `chdir_notify` subsystem, which kept the pointer alive.

The fix is straightforward: add a block in `repo_clear()` that calls `ref_store_release()` on `repo->refs_private` and then frees the pointer. The change is confined to `repository.c` and introduces no behavior changes—just proper resource cleanup. This patch is part of the uncontroversial cleanup portion of the series (patches 1–7/11) and is unlikely to face objections.

For a busy reader, this is a clear example of a **well-scoped, low-risk fix** that addresses a latent issue without disrupting functionality. It’s worth noting only if you’re tracking the broader refactoring effort or memory management in Git’s repository lifecycle. The patch itself is trivial, but its inclusion in the series helps ensure the larger architectural changes don’t introduce regressions.
