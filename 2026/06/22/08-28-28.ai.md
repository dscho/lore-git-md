This is the sixth patch in Patrick Steinhardt’s 11-part v5 refactoring series modernizing Git’s reference backend infrastructure. It plugs a **memory leak** in `repository.c` by ensuring the main reference database (`repo->refs_private`) is freed when clearing a repository. The leak was masked by the `chdir_notify` subsystem, which kept the pointer alive even after repository cleanup. The fix is a straightforward addition to `repo_clear()`: it calls `ref_store_release()` and `FREE_AND_NULL()` on `repo->refs_private`, mirroring the existing cleanup logic for submodule reference databases. The change is confined to a single file and introduces no behavior changes—it is purely a housekeeping fix to prevent memory from being leaked during repository teardown. Given the uncontroversial nature of the patch and its alignment with existing cleanup patterns, it is unlikely to face objections. This patch is a carry-over from v4 and serves as a prerequisite for the lazy-loading design introduced later in the series.
