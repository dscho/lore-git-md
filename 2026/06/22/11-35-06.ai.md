This is an RFC proposing a new feature for `git clone`: allowing users to specify sparse-checkout paths directly during clone, rather than requiring a separate `git sparse-checkout set` step afterward.

The author, Pushkar Singh, motivates this with the common monorepo workflow where developers only need a subset of the repository. Currently, this requires two steps (`git clone --sparse` followed by `git sparse-checkout set`), which the author finds cumbersome. The proposal introduces two new options: `--only` (for inclusion patterns) and `--except` (for exclusion patterns), which would internally initialize sparse-checkout mode and configure the pathspecs automatically.

The email suggests two interface styles: comma-separated values (`--only=README.md,frontend`) or repeated options (`--only=frontend --only=tests`). The author expresses a preference for the comma-separated form but is open to alternatives. Implementation would involve extending `builtin/clone.c` to parse these options and invoke existing sparse-checkout logic.

Key technical details: the feature would reuse Git's existing sparse-checkout machinery, not replace it. The proposal targets the `clone` command specifically, with no mention of affecting other commands like `git fetch` or `git pull`. The author is seeking feedback on usefulness, interface design, and potential concerns before proceeding with implementation.
