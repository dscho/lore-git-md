This is the **tenth patch in Patrick Steinhardt’s v5 refactoring series**, applying the lazy-loading design to the reftable backend to resolve the same chicken-and-egg initialization problem that patch 8/11 fixed for the files backend. The patch ensures that write-related configuration (e.g., `reftable.blockSize`, `core.logAllRefUpdates`) is parsed only during the first write operation, avoiding early config reads that could trigger recursive ref-store initialization via `includeif.onbranch` conditions.

The core change is the introduction of a new `reftable_be_write_options()` accessor that lazily initializes the `write_opts_lazy_loaded` struct in `struct reftable_ref_store`. This struct holds both the `reftable_write_options` and the `log_all_ref_updates` setting, mirroring the approach taken in the files backend. The patch moves all write-config parsing from `reftable_be_init()` into this accessor, ensuring that configuration is only read when a write operation (e.g., `reftable_stack_add()`, `reftable_stack_compact_all()`) is performed. The `should_write_log()` function is updated to use the lazy-loaded config, and all direct accesses to `refs->write_options` are replaced with calls to `reftable_be_write_options(refs)->opts`.

Test coverage is expanded in two places: `t/t0613-reftable-write-options.sh` verifies that `reftable.blockSize` can be set via an `onbranch` condition, and `t/t1400-update-ref.sh` adds a generic test confirming that `core.logAllRefUpdates` works with `onbranch` includes. The patch is technically sound, with clear commit message rationale and thorough test coverage. It directly addresses Jeff King’s concerns about config cache inconsistencies and user-facing regressions, and it aligns with the series’ goal of eliminating recursive initialization issues. The reftable backend refactor is the most complex part of the series, but this patch is a straightforward application of the lazy-loading pattern established in patch 8/11. No major objections are expected, though reviewers may scrutinize the dynamic write option handling for edge cases in concurrent write operations.
