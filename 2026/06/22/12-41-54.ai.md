This is the v4 iteration of Toon Claes's feature patch series introducing a `--linearize` option to `git replay`. The series is now complete and ready for final review before merging, with only minor test adjustments since v3.

The `--linearize` option flattens merge commits into linear history by walking only first parents, providing server-side functionality equivalent to `git rebase --no-rebase-merges`. This v4 makes a small but important test change: replacing a bare `grep` with `test_grep` in the range-diff verification test to comply with upcoming `mm/test-grep-lint` requirements. This is the only substantive change from v3, which already addressed all prior review feedback (documentation, test coverage, and code clarity).

The series consists of three patches: two preparatory refactors (converting `enum replay_mode` to a boolean and adding a `put_mapped_commit()` helper) and the main implementation. The implementation touches `replay.c` (commit mapping logic and merge handling), `replay.h` (option definition), the man page, and the test file `t/t3650-replay-basics.sh`. All patches carry Johannes Schindelin's Signed-off-by, indicating his support for the approach.

This version appears technically complete. The collaborative review process—including input from Junio Hamano, Elijah Newren, Justin Tobler, and Dscho—has produced a well-tested implementation with clear documentation and no outstanding technical concerns. The series is part of the broader effort to enhance `git replay`'s capabilities, complementing Patrick Steinhardt's `git history drop` and Kristoffer Haugsbakk's documentation improvements. Toon has volunteered to reconcile this work with Dscho's alternative merge-replay series if needed.
