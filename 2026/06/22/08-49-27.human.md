This is the first patch in a three-part series refactoring Git’s connectivity checks to generalize promisor object handling, making it independent of the ODB backend. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort, which aims to support alternative backends like reftable or pluggable storage.

This patch extracts logic that skips certain packs during object iteration into a new helper function, `should_exclude_pack()`. The function consolidates four separate conditional checks that previously lived inline in `odb_source_packed_for_each_object()`, each filtering packs based on flags like `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` or `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`. The change is purely preparatory—it doesn’t alter behavior but sets the stage for the next patch, which will lift the current limitation that prevents flags from being used when iterating with an object prefix.

The diff is small and focused, touching only `odb/source-packed.c`. The extracted logic is straightforward and mirrors the existing inline checks, so the risk of introducing bugs is low. This looks like a clean, well-motivated refactoring that aligns with the series’ goal of making connectivity checks backend-agnostic. Reviewers will likely focus on whether the helper function’s name and placement are appropriate, but the change itself is uncontroversial.
