This is the cover letter for Phillip Wood’s two-patch series that fixes long-standing display bugs in `git status` during an interactive rebase.

The series targets two specific issues: (1) `git status` fails to abbreviate commit object IDs when the rebase todo line begins with “fixup -C” or “merge -C”, and (2) it incorrectly replaces refnames (e.g., “reset main”) with the raw object ID they point to. The first patch factors out the sequencer’s todo-command parser into a reusable function; the second patch uses that parser in `wt-status.c` to decide which tokens are object IDs that should be abbreviated and which are refnames that should be left alone.

Phillip is a well-known expert in the sequencer and rebase subsystems, and the series has already received substantive review from Elijah Newren, Tian Yuchen, and Junio C Hamano. All edge cases—such as label/OID collisions, dual-position OID handling in “merge -C”, and compiler warnings—have been addressed in this v3. The CI failures noted in the cover letter are due to an old base commit, not the patches themselves; a test merge with current master passes cleanly. The series looks ready for merging.
