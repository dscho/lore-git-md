This is the v17 submission of Harald Nordgren’s `git branch --delete-merged` series, now technically complete with all previously discussed safety mechanisms implemented. The series adds a safe, automated local-branch cleanup command that deletes branches whose work has been merged into their upstream, while preserving branches that are checked out, missing their upstream, pushing back to their upstream (like `main` tracking `origin/main`), or opted out via `branch.<name>.deleteMerged` config.

The key new feature in v17 is **stacked-branch protection**: if a branch is used as an upstream for any other branch (e.g., `feature2` stacks on `feature1`), deletion is aborted with a clear error message. This check repeats until no further branches are spared, so a chain like `b1→b2→b3` is fully protected. The implementation uses `refs_for_each_branch_ref()` to collect upstreams and a `strset` to track deletable branches, iterating until the set stabilizes. This simpler approach avoids the complexity of retargeting (e.g., recursion or self-references) while preserving backward compatibility for future enhancements.

The series is structured as seven patches:
1. Adds the `--forked` filter for `--list` mode (unchanged from v16).
2. Converts `delete_branches()` to use an unsigned int flags argument (unchanged).
3. Adds `DELETE_BRANCH_SKIP_UNMERGED` to skip unmerged branches on bulk refusal (unchanged).
4. Prepares `delete_branches()` for bulk callers by adding `DELETE_BRANCH_NO_HEAD_FALLBACK` (unchanged).
5. Implements `--delete-merged` with all safety checks, including the new stacked-branch protection.
6. Adds the `branch.<name>.deleteMerged` opt-out mechanism (moved to its own commit).
7. Adds `--dry-run` support for `--delete-merged` (moved to its own commit).

The test suite has been expanded to cover stacked-branch protection, verifying that branches used as upstreams are preserved and that chains of upstreams are fully protected. The implementation is now ready for final review, with no known blocking issues remaining. Phillip Wood’s high-weight feedback on stacked-branch safety has been addressed, and the series aligns with the project’s API consistency expectations.
