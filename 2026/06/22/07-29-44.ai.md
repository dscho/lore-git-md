This is the third patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, which is now technically complete and ready for final review. The patch adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the internal branch-deletion API, allowing bulk callers (like the upcoming `--delete-merged` command) to silently skip unmerged branches instead of failing with the usual "use `git branch -D`" advice. Existing callers remain unchanged.

The change is a straightforward extension of the flags-based API introduced in patch 2/7. The new flag is plumbed through `check_branch_commit()` and `delete_branches()`, where it suppresses the error message and advice for unmerged branches, letting the caller continue processing the remaining branches. This is essential for `--delete-merged`, which needs to handle mixed lists of merged and unmerged branches without aborting on the first refusal.

The implementation is minimal and mechanical: the flag is extracted into a local boolean, and the error path in `check_branch_commit()` is guarded by a conditional. The patch does not alter behavior for any existing code paths, so there are no functional changes outside the new flag. Test coverage for this patch is handled in later patches (5/7 and 7/7) that exercise the bulk-deletion logic.

This is a refactoring patch that prepares the API for the core `--delete-merged` functionality. It is uncontroversial and aligns with the series’ goal of providing a clean, composable interface for branch deletion. The patch itself is small (12 insertions, 5 deletions) and focused, touching only the branch-deletion plumbing in `builtin/branch.c`.
