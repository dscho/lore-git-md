This is the core implementation patch (5/7) in Harald Nordgren’s `git branch --delete-merged` series, now in its seventeenth iteration. The patch adds the new `--delete-merged` subcommand to `git branch`, which safely deletes local branches whose work has already been merged into their upstream. The command is built on the `--forked` filter (introduced in patch 1/7) and the flags-based deletion API (refactored in patches 2–4/7), and it includes all the safety mechanisms discussed in the thread: protection for checked-out branches, missing upstreams, push-equals-upstream branches, per-branch opt-out via `branch.<name>.deleteMerged`, and—most notably—**stacked-branch protection**.

The implementation is straightforward: `delete_merged_branches()` filters candidate branches using the `--forked` machinery, applies the safety checks, and then iteratively spares any branch that another surviving branch tracks as its upstream. This ensures that a chain like `b1→b2→b3` is fully protected, not just the immediate upstream. The stacked-branch check uses `refs_for_each_branch_ref()` to collect upstreams and a `strset` to track deletable branches, iterating until the set stabilizes. The code is clean, memory-efficient (single `strbuf` reuse), and well-tested: the test suite verifies that merged branches are deleted, unmerged/checked-out/protected branches are spared, and chains of upstreams are fully preserved.
