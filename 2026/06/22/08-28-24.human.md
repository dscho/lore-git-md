This is the second patch in Patrick Steinhardt’s 11-part v5 series refactoring Git’s reference backend to eliminate recursive initialization issues. It removes redundant application of repository format settings during repository discovery.

The patch targets `setup.c`, where the code currently applies the repository format twice: once via `repository_format_configure()` (which updates both `struct repository_format` and `struct repository`) and again via `apply_repository_format()` (which copies settings from `struct repository_format` to `struct repository`). The redundancy exists because `repository_format_configure()` is called *after* `apply_repository_format()`, forcing it to reapply settings to the repository struct.

Patrick’s change reorders the calls so that `repository_format_configure()` runs first, allowing `apply_repository_format()` to handle the final propagation of settings to the repository. This eliminates the need for `repository_format_configure()` to directly modify the repository, simplifying the function’s signature and reducing the risk of inconsistencies. The diff removes the redundant `repo_set_hash_algo()` and `repo_set_ref_storage_format()` calls from `repository_format_configure()` and adjusts the call order in `init_db()`.

This is a straightforward refactoring with no behavior change—just cleaner initialization flow. It’s part of the uncontroversial cleanup patches (1–7/11) carried over from v4, so it’s unlikely to face objections. The patch is well-motivated and aligns with the series’ broader goal of making reference backend initialization more robust. If you’re tracking the series for its lazy-loading redesign (patches 8–11), this patch is a minor but necessary step.
