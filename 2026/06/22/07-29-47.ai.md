This is the sixth patch in Harald Nordgren’s seven-patch `git branch --delete-merged` series (v17). It adds a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` configuration key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The implementation is straightforward: during the candidate-filtering phase of `delete_merged_branches()`, the code checks for `branch.<name>.deleteMerged=false` and skips the branch if found, printing a non-quiet message to explain why. The opt-out is ignored by the traditional `git branch -d` command, which continues to use the normal merge check. Documentation updates cover both the new config key and its effect on the safety conditions listed in the `git-branch` man page.

The patch touches four files: `Documentation/config/branch.adoc` (new config entry), `Documentation/git-branch.adoc` (updated safety list), `builtin/branch.c` (config lookup and skip logic), and `t/t3200-branch.sh` (two new tests). The tests verify that a branch with `deleteMerged=false` is spared by `--delete-merged` but can still be deleted explicitly with `-d`. The implementation is clean, memory-safe (single `strbuf` reused), and consistent with the flags-based API introduced earlier in the series.
