Subject: [PATCH] compat/posix.h: fix compilation with GCC 14.1 on 32-bit MinGW
Series version: standalone patch
Originating author: Johannes Schindelin (Dscho)
Thread type: bugfix (platform compatibility)

Core problem or goal
Fix a compilation error in GCC 14.1 on 32-bit MinGW builds caused by an implicit declaration of `localtime_r()` in `archive-zip.c`. The error occurs in `dos_time()`, a helper function in the ZIP archive backend, where `localtime_r()` converts a timestamp to a `struct tm`. The fix ensures the POSIX function is declared by adjusting the `_POSIX_C_SOURCE` definition in `compat/posix.h` for both `__MINGW32__` and `__MINGW64__`.

Current status
Patch is unmerged but ready for merging. The change is minimal (one line) and directly addresses a build breakage with no behavioral impact. Git for Windows plans to drop i686 support after v2.55.0, making this a short-term fix. Patrick Steinhardt’s review confirms the technical correctness and suggests the explicit check for both `__MINGW32__` and `__MINGW64__` improves readability, though `__MINGW32__` alone would suffice.

Key technical details
- **File modified**: `compat/posix.h`
- **Subsystem**: Windows compatibility layer (MinGW)
- **Function affected**: `dos_time()` in `archive-zip.c`
- **Symbol**: `localtime_r()` (POSIX function, standardized in C23 but controlled by `_POSIX_C_SOURCE` in older standards)
- **Behavior**: No functional change; purely a build fix
- **Test coverage**: None included; error is reproducible by building with GCC 14.1 on 32-bit MinGW
- **GCC version**: 14.1

None. The patch is mechanical, well-motivated, and uncontroversial. Patrick Steinhardt’s review did not raise concerns or request changes.
