This is the second patch in Patrick Steinhardt’s 11-part v5 refactoring series for Git’s reference backend. It eliminates redundant application of repository format settings during repository initialization.

The patch targets `setup.c`, where the current flow applies the repository format twice: once via `repository_format_configure()` (which sets the hash algorithm and ref storage format in both `struct repository_format` and `struct repository`) and again via `apply_repository_format()` (which copies those settings from `struct repository_format` to `struct repository`). The redundancy exists because `repository_format_configure()` is called *after* `apply_repository_format()`, so any changes it makes to `struct repository_format` are never propagated to the repository.

The fix is straightforward: reorder the calls so that `repository_format_configure()` runs *before* `apply_repository_format()`, allowing the latter to apply the fully configured format in a single step. The patch also removes the now-unnecessary direct updates to `struct repository` from `repository_format_configure()`, simplifying the function’s signature and logic. The diff is minimal (9 lines changed) and purely mechanical, with no behavior change—just cleaner initialization flow.

This patch is a carry-over from v4 and addresses a minor inefficiency rather than a bug. It’s uncontroversial and unlikely to draw objections, serving as a preparatory step for the larger lazy-loading refactor in later patches. The change is well-motivated in the commit message, which clearly explains the redundancy and the reordering rationale. No new test coverage is needed, as the patch preserves existing behavior.
