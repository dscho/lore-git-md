This is a **CI/platform-compatibility** update in the ongoing macOS CI hang thread. Patrick Steinhardt reports a new failure mode in the same test (`t5551`) that previously hung: instead of stalling, the test now fails with a curl error (`transfer closed with outstanding read data remaining`). This suggests the underlying HTTP/2 flow-control issue is not fully resolved and may be surfacing differently as the environment or test conditions vary.

The error occurs during a `` `git fetch` `` operation advertising 100,000 loose refs, the same scenario that triggered the original hang. The curl error code (18) indicates a premature connection closure, which aligns with the earlier diagnosis of an HTTP/2 flow-control stall. This new failure reinforces the maintainers’ skepticism that the proposed fix (packing refs and aligning `$JOBS`) may mask rather than eliminate the root cause.

Patrick’s observation strengthens the case for investigating environment differences, particularly libcurl versions (8.6.0 on GitHub vs. 8.7.1 on GitLab) and the macOS build image (version 14 vs. 15). The thread remains focused on root-cause analysis, with no new patch proposed—just a data point that the problem persists in a different form. If you care about macOS CI reliability, this is worth watching; the discussion is now centered on whether the fix needs to be environmental (upgrading dependencies) or deeper (addressing Git’s HTTP/2 usage).
