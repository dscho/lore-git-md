This is the third patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, which aims to provide safe automated cleanup of local branches. This patch adds a new flag, `DELETE_BRANCH_SKIP_UNMERGED`, to the internal `delete_branches()` API. When set, the function silently skips any branch that is not fully merged instead of erroring out with the usual "use `git branch -D`" advice. This is a purely mechanical change that prepares the API for bulk callers (specifically the upcoming `--delete-merged` command) while leaving existing behavior unchanged.

The implementation is straightforward: the new flag is plumbed through `check_branch_commit()` and `delete_branches()`, and the error message is suppressed when `skip_unmerged` is true. The patch touches only `builtin/branch.c` and adds no new tests, as the existing test suite already verifies that the unmerged-branch check works; the new flag simply changes whether it is treated as a fatal error.

This is a well-motivated refactoring that keeps the API consistent with the flags-based design introduced in patch 2/7. The change is small, self-contained, and clearly documented in the commit message. There is no controversy here—it is a necessary building block for the later `--delete-merged` implementation.
