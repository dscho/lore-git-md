This is the second patch in Patrick Steinhardt’s two-patch refactoring series for the ODB subsystem, part of the ongoing ODB abstraction effort. It introduces `odb_prepare()` as a new public API and updates `git grep` to use it, replacing the manual alternates-and-sources loop with a single call.

The patch touches three files: `builtin/grep.c`, `odb.c`, and `odb.h`. In `odb.c`, the existing `odb_reprepare()` function is generalized into `odb_prepare()`, which now accepts an `enum odb_prepare_flags` parameter to control whether caches are flushed. The old `odb_reprepare()` is preserved as a thin wrapper around the new function for backward compatibility. The commit message explains that this change allows `git grep` to prepare the ODB without flushing caches, though the specific motivation for that flexibility is not detailed here.

The implementation is straightforward and confined to the ODB layer, with no functional changes—only API reshaping. The new flag-based design appears clean and extensible, though reviewers may question whether the flag name (`ODB_PREPARE_FLUSH_CACHES`) is sufficiently precise or if future use cases might require additional flags. The patch is small and self-contained, making it easy to review in isolation.

This is the final piece of the series, completing the refactoring begun in patch 1/2. Given Patrick’s track record with ODB work, the patch is likely technically sound, but the real test will be whether the new API proves flexible enough for future pluggable ODB backends.
