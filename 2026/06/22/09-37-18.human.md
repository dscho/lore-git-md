This is the latest update in Harald Nordgren’s long-running series to add `git branch --delete-merged`, now at version 17. The email confirms that Harald has implemented Phillip Wood’s latest suggestion for stacked-branch protection: instead of aborting or attempting to reassign upstreams, the command will now **clear the upstream configuration** of merged branches that cannot be deleted because they are upstreams of unmerged branches. This approach avoids the complexity of recursive retargeting while still preventing stale references, and it handles edge cases like self-referential upstreams and dependency chains uniformly.

The series is now feature-complete, with all planned safety mechanisms in place: per-branch opt-out via `branch.<name>.deleteMerged=false`, `--dry-run` preview, and the newly implemented upstream-clearing logic. The core command safely deletes local branches merged into their upstream while preserving branches that are checked out, missing upstreams, or protected by push divergence or opt-out config. The `--forked` filter (introduced in patch 1/7) provides precise branch selection, and the flags-based API (patches 2-4/7) unifies deletion behavior across the codebase.

This version looks ready for final review. The implementation is pragmatic, well-tested, and addresses the last open design question (stacked-branch protection) with a simple, backward-compatible solution. The commit messages and test coverage appear thorough, and the safety architecture is comprehensive without being overly complex.
