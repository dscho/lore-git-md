This is the first patch in Patrick Steinhardt’s **v5 refactoring series** for Git’s reference backend infrastructure, focusing on a small but necessary cleanup to prepare for the larger lazy-loading redesign. The patch inlines the `check_and_apply_repository_format()` helper function into its two callsites in `setup.c` (`enter_repo()` and `init_db()`), as the helper will no longer be a good fit once the series modifies the order of repository format reading and application in a later patch.

The change is mechanical and uncontroversial: the helper’s logic is preserved verbatim, with only minor adjustments to variable declarations and error handling to match the callsite context. The patch touches only `setup.c` and does not alter behavior, serving purely as a refactoring step to enable future changes. This aligns with the series’ goal of decoupling read-critical and write-critical config parsing, as the inlined code will later be adapted to avoid early config reads that could trigger recursive ref store initialization.

Given the patch’s preparatory nature and lack of functional changes, it is unlikely to face objections. It is a carry-over from v4 and has already been reviewed in earlier iterations, with Justin Tobler approving similar initialization logic in v3. The patch’s value lies in setting the stage for the lazy-loading design introduced in later patches (8–11/11), which address the root cause of recursive initialization issues with "onbranch" configuration conditions. Reviewers focused on the reftable backend or deferred config parsing may skip this patch, as it does not yet introduce those mechanisms.
