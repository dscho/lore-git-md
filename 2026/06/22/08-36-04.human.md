This is the second patch in Phillip Wood's two-patch bugfix series (v3) targeting `git status` display correctness during interactive rebase. It directly addresses the core issues described in the cover letter: failing to abbreviate commit object IDs for "fixup -C" and "merge -C" commands, and incorrectly replacing refnames (like "reset main") with their pointed-to object IDs.

The patch replaces the previous simplistic line-splitting approach with a proper todo command parser (`sequencer_parse_todo_command()`) that was introduced in the first patch. This allows the status display logic to distinguish between commands that take object IDs (like `pick`, `fixup -C`, `merge -C`) and those that take labels or refnames (like `reset`, `update-ref`). For each command, it first checks if the argument is a label (via `refs/rewritten/` lookup) before attempting to abbreviate it as an object ID, ensuring refnames are preserved. The implementation also handles edge cases like tag or branch names that consist only of hex digits by only abbreviating if the argument starts with the abbreviated OID.

The test updates in `t/t7512-status-help.sh` expand coverage to include a wider variety of commands (`fixup -C`, `merge`, `reset`, `update-ref`) and demonstrate the corrected behavior. The new tests use direct todo list manipulation rather than `FAKE_LINES` to exercise more complex scenarios, including multi-command sequences and label resolution.

This patch is well-crafted and addresses a clear usability issue. The refactoring is minimal and focused, with good test coverage and clear commit message documentation. The series appears ready for merging, with all substantive review feedback incorporated in v3.
