This is the first patch in Phillip Wood’s two-patch bugfix series (v3) for `git status` display during interactive rebase. It refactors the todo-command parsing logic in `sequencer.c` into a new helper function, `sequencer_parse_todo_command()`, so that the same parsing can be reused by the status-display code in the next patch.

The change is mechanical: it moves the existing parsing loop and comment-line detection into a standalone function that takes a pointer-to-pointer and an output enum. The new function uses `starts_with()` instead of `starts_with_mem()` and tests for NUL, CR, or LF to detect blank lines, which slightly alters behavior for malformed lines containing a lone CR (now treated as invalid rather than a comment). The commit message and code comments clearly explain these edge cases.

This patch is a clean refactoring with no functional change; the real payoff comes in patch 2/2, where the shared parser ensures consistent handling of object IDs and refnames. All review feedback on the refactoring itself has been addressed, and the patch is ready for merging.
