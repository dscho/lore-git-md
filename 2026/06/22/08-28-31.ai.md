This is the ninth patch in Patrick Steinhardt’s **v5 refactoring series** for Git’s reference backend, focusing on the **reftable backend’s write option separation**. The patch splits the `reftable_write_options` struct into two distinct structures: `reftable_stack_options` (for stack-level configuration like hash ID and reload callbacks) and `reftable_write_options` (for write-specific settings like block size and compression). This decouples stack initialization from write operations, enabling dynamic write option passing and deferring write-config parsing until the first write—key to the series’ lazy-loading design.

The changes touch 14 files, primarily in `reftable/` (including `reftable-stack.h`, `reftable-writer.h`, and `stack.c`), with adjustments to the Git-facing `refs/reftable-backend.c` and test files. The patch introduces new APIs like `reftable_stack_new_addition()` and `reftable_stack_add()`, which now accept explicit write options, and updates all callers to pass the correct structs. The reftable backend’s `struct reftable_ref_store` gains a `stack_options` field to store stack-level settings, while write options are passed dynamically to functions like `reftable_stack_add()`.

Test coverage is extensive, with updates to unit tests (`t/unit-tests/u-reftable-*.c`) and helper code to reflect the new APIs. The patch maintains backward compatibility by providing default values for missing options (e.g., `REFTABLE_HASH_SHA1` for hash ID) and ensures the lazy-loading design remains intact. This refactor is a critical enabler for patches 10–11/11, which apply the lazy-loading pattern to the reftable backend. The changes are mechanical but foundational, with no behavior changes—only structural improvements to support deferred config parsing.
