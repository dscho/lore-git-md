This is the first patch in Toon Claes’s three-part series adding a `--linearize` option to `git replay`. The patch itself is a **refactoring**: it replaces the two-value `enum replay_mode` (PICK vs REVERT) with a simple boolean `reverse` flag. The change is purely internal—no behavior is altered—and touches only `replay.c`.

The motivation is straightforward: with only two modes, the enum feels like overkill, and the boolean eliminates redundant BUG() checks for invalid values. The patch is small, clean, and mechanically sound. However, Patrick Steinhardt raises a valid concern: while the code is shorter, the boolean parameter may make the callsites harder to read, and it could complicate future expansion if a third mode is ever needed. This is not a rejection—just a question about long-term maintainability.

The series as a whole is ready to merge (Junio has already said “Will merge to 'next'”), and this patch is a prerequisite for the `--linearize` feature in patch 3/3. If the boolean approach sticks, it will be a minor but useful cleanup; if not, the enum can be restored without affecting the rest of the series. Either way, the discussion here is unlikely to derail the feature.
