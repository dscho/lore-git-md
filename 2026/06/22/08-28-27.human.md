This is a cleanup patch in Patrick Steinhardt’s **v5 refactoring series** for Git’s reference backend. It removes the now-unused `chdir_notify_reparent()` function from `chdir-notify.c` and updates the header file to reflect its removal.

The patch is a direct follow-up to the previous commit (4/11 in the series), which replaced all calls to `chdir_notify_reparent()` with proper registration/unregistration of `chdir_notify` callbacks. That earlier patch fixed a latent memory safety issue by ensuring reference stores (files, packed, and reftable backends) properly manage their lifecycle with `chdir_notify`. With no remaining callers, this patch simply deletes the obsolete function and its documentation.

The change is mechanical and uncontroversial—it’s a textbook example of removing dead code after its last user is gone. The diff is small (26 lines removed from `.c`, 5 from `.h`) and confined to the `chdir-notify` subsystem. There’s no behavior change, just a cleanup that tidies up the API surface. This patch is unlikely to attract discussion, as it’s a natural consequence of the prior fix. If the series lands, this will be a quiet but necessary part of the larger ref backend modernization.
