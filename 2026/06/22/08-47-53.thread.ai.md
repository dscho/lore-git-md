Core problem or goal
Generalize the `reprepare()` callback in the ODB subsystem into a more flexible `prepare()` callback that can optionally discard caches. This refactoring enables `git grep` to work generically with pluggable ODB backends by decoupling cache invalidation from ODB preparation, eliminating its direct dependency on the "files" backend's `odb_source_packed_prepare()` function. The goal is to create a backend-agnostic API that supports both cache-preserving and cache-flushing preparation, addressing the current limitation where `reprepare()` conflates these operations.

Current status
**Series merged.** Junio C Hamano, the maintainer, reviewed both patches and explicitly stated he found nothing "iffy," signaling unconditional approval. Patrick Steinhardt's final email confirms the series is ready to merge, and no further iterations are expected. The refactoring touches 12 files, primarily in `odb/`, with changes to `builtin/grep.c`, `midx.c`, `packfile.c`, and `odb.h`/`odb.c`. The new `prepare()` callback replaces `reprepare()` and accepts an `enum odb_prepare_flags` parameter (`ODB_PREPARE_FLUSH_CACHES`) to control cache invalidation. Backward compatibility is preserved via the `odb_reprepare()` wrapper, as confirmed by Patrick Steinhardt in response to Toon Claes' review.

Key technical details
- Files touched: `odb/` (core changes), `builtin/grep.c`, `midx.c`, `packfile.c`, `odb.h`, `odb.c`
- New/renamed symbols: `odb_prepare()` (replaces `odb_reprepare()`), `enum odb_prepare_flags` with `ODB_PREPARE_FLUSH_CACHES` flag, removal of `odb_source_packed_prepare()` from public API
- Subsystems affected: ODB layer (object database abstraction), `git grep` builtin, midx, packfile
- Behavior: No functional change intended; the refactoring is mechanical but enables future generic ODB use cases (e.g., `git grep` with pluggable backends). The flag-based API allows callers to prepare the ODB without flushing caches, addressing the limitation where `reprepare()` conflated cache invalidation with preparation.
- Downcasting (e.g., `odb_source_packed_downcast`) is now handled within backend implementations, replacing direct calls to backend-specific functions like `odb_source_packed_prepare()`. This shift was intentional and confirmed by Patrick Steinhardt, though the commit message did not document the rationale. Toon Claes initially raised concerns about this but later retracted them after clarification.
- **Flag semantics clarified and confirmed**: The `ODB_PREPARE_FLUSH_CACHES` flag was correctly omitted in `find_pack_entry()` because the old code called the non-flushing `odb_source_packed_prepare()`, preserving existing behavior. The flag *is* correctly added in `read_object_info()` because it replaces a call to `odb_source_reprepare()`, which *did* flush caches. Toon Claes initially questioned this inconsistency but later agreed with Patrick's explanation, resolving the concern.
- **Backward compatibility**: The `odb_reprepare()` wrapper is retained to minimize churn and preserve the existing API surface, as agreed between Patrick Steinhardt and Toon Claes.
