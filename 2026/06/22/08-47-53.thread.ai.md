Subject: [PATCH v1 0/2] odb: generalize reprepare() callback for pluggable ODBs
Series version: v1
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring, part of ODB abstraction effort)

Core problem or goal
Generalize the `reprepare()` callback in the ODB subsystem into a more flexible `prepare()` callback that can optionally discard caches. This refactoring enables `git grep` to work generically with pluggable ODB backends by decoupling cache invalidation from ODB preparation, eliminating its direct dependency on the "files" backend's `odb_source_packed_prepare()` function.

Current status
First iteration (v1). The series consists of 2 patches touching 12 files (updated count), primarily in `odb/`, with changes to `builtin/grep.c`, `midx.c`, `packfile.c`, and `odb.h`/`odb.c`. The refactoring replaces the existing `reprepare()` callback with a new `prepare()` callback that accepts an `enum odb_prepare_flags` parameter (`ODB_PREPARE_FLUSH_CACHES`) to control cache invalidation. The old `reprepare()` behavior is preserved as a wrapper around the new API for backward compatibility. No prior versions exist; this is the initial submission.

Key technical details
- Files touched: `odb/` (core changes), `builtin/grep.c`, `midx.c`, `packfile.c`, `odb.h`, `odb.c`
- New/renamed symbols: `odb_prepare()` (replaces `odb_reprepare()`), `enum odb_prepare_flags` with `ODB_PREPARE_FLUSH_CACHES` flag, removal of `odb_source_packed_prepare()` from public API
- Subsystems affected: ODB layer (object database abstraction), `git grep` builtin
- Behavior: No functional change; the refactoring is mechanical but enables future generic ODB use cases (e.g., `git grep` with pluggable backends)
- The flag-based API allows callers (e.g., `git grep`) to prepare the ODB without flushing caches, addressing the limitation where `reprepare()` conflated cache invalidation with preparation
- Built on recent ODB work (`ps/odb-source-packed`)
