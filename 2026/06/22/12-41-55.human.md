This is the first patch in the v4 series introducing `--linearize` to `git replay`. It refactors the existing `enum replay_mode` into a simple boolean `reverse` flag, eliminating the need for an enum with only two values (`REPLAY_MODE_PICK` and `REPLAY_MODE_REVERT`). The change is purely internal and does not alter behavior—it just simplifies the code by removing redundant checks for invalid enum values and shortening ternary operations.

The patch touches only `replay.c`, replacing all instances of `enum replay_mode` with `bool reverse`. The logic for handling `--revert` (which processes commits in reverse order and applies inverse changes) and `--onto`/`--advance` (which apply changes as-is) remains identical; the only difference is that the mode is now determined by a boolean flag set via `reverse = !!revert`. This refactoring was previously reviewed and is now stable, with no further changes since v3.

This is a clean, mechanical change that prepares the ground for the `--linearize` feature in patch 3. The author has addressed all prior feedback, including Justin Tobler’s design concern about extensibility, by noting that the current two-mode design is stable and future modes would require a separate flag. The patch is uncontroversial and ready for integration.
