This is a **CI/platform-compatibility** update in the ongoing macOS CI hang investigation. Patrick Steinhardt reports a new twist: the same `t5551` test that previously hung on GitHub’s macOS runners now fails outright with a `curl 18 transfer closed with outstanding read data remaining` error, and a similar failure appears in a Linux CI job (though logs are truncated). The error suggests the HTTP/2 transfer is being aborted mid-stream, reinforcing the suspicion that the underlying protocol or environment issue is not fully resolved by Michael Montalbo’s proposed fix (packing refs and aligning `$JOBS` with runner core count).

The new failure mode shifts the focus from deadlock diagnosis to transfer-abort analysis. Patrick does not propose a code change here; instead, he highlights the risk of simply disabling the test, which could mask a real bug in Git’s HTTP/2 handling, libcurl, or Apache’s `h2_mod`. The thread remains in root-cause investigation mode, with environment version checks (libcurl, macOS build image) and protocol-level debugging still the priority. No maintainer has yet weighed in on merging the existing patch, and the new failures may further delay acceptance.
