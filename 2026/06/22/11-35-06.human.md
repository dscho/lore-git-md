This is a feature proposal for `git clone` that would allow users to specify sparse-checkout paths directly during the initial clone, rather than as a separate step. The author, Pushkar Singh, suggests adding new `--only` and `--except` options to `git clone` to streamline the workflow for monorepo users who only need a subset of the repository.

The motivation is clear: the current two-step process (`git clone --sparse` followed by `git sparse-checkout set`) feels cumbersome, especially for newcomers. The proposed interface (`--only=README.md,frontend,tests/frontend`) is intuitive and aligns with how users think about the problem ("I only want these directories"). The author also suggests supporting exclusions (`--except=tests/backend`) for more complex use cases.

The implementation plan is straightforward: extend `builtin/clone.c` to parse the new options, enable sparse mode automatically, and pass the pathspecs to the existing sparse-checkout machinery. This avoids reinventing the wheel and leverages the well-tested sparse-checkout logic. The author is not proposing to replace sparse-checkout but rather to make it more accessible during clone.

This is a well-motivated and practical suggestion. The proposed interface is clean and addresses a real pain point for monorepo users. The fact that it builds on existing infrastructure rather than introducing new complexity is a plus. Whether the exact option names (`--only`/`--except`) are the best choice may be worth discussing, but the core idea seems sound.

For anyone working with large repositories, this could be a meaningful quality-of-life improvement. The proposal is worth paying attention to, especially if you’re involved in monorepo workflows or sparse-checkout development.
