This is the final patch in a three-part feature series adding a `--linearize` option to `git replay`. The option flattens merge commits, matching the default behavior of `git rebase --no-rebase-merges`. This patch implements the core functionality, updates the documentation, and expands test coverage.

The change is straightforward: the new `--linearize` flag is added to the CLI, enforced as mutually exclusive with `--revert`, and documented in the man page. Internally, the patch modifies `replay_revisions` to skip merge commits when `--linearize` is active, leaving `last_commit` unchanged so that subsequent commits are reparented onto the previous non-merge commit. The `pick_regular_commit` helper is updated to accept an optional `replayed_base` parameter, allowing it to handle the linearized topology.

Test coverage is thorough: the patch verifies `--linearize` with `--advance`, tests the `--revert`/`--linearize` incompatibility, and uses `git range-diff` to confirm that the replayed commits produce identical patches to the originals. The documentation is clear and complete, including the option in the SYNOPSIS and usage array, and explaining the mutual exclusivity with `--revert`.
