This is the final patch in Toon Claes's three-part series introducing the `--linearize` option to `git replay`. The patch implements the core functionality that flattens merge commits into linear history by walking only first parents, effectively replicating `git rebase --no-rebase-merges` on the server side.

The implementation touches five files: the man page (`Documentation/git-replay.adoc`) documents the new `--linearize` option and its incompatibility with `--revert`; `builtin/replay.c` adds the CLI option and enforces mutual exclusion; `replay.c` contains the main logic for dropping merge commits and reparenting their children onto the previous non-merge commit; `replay.h` adds the `linearize` field to the options struct; and the test file (`t/t3650-replay-basics.sh`) expands coverage with four new tests verifying root commit handling, `--linearize`/`--advance` combinations, and patch preservation via `range-diff`.
