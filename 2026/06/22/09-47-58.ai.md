This is a **CI/platform-compatibility** follow-up in the ongoing macOS CI hang thread. Patrick Steinhardt reports a new failure mode in the same `t5551` test: instead of hanging, the job now fails with `curl 18 transfer closed with outstanding read data remaining` and `fatal: expected flush after ref listing`. This error surfaced in a recent `osx-clang` CI run and affects the same enormous-ref-negotiation test that previously deadlocked.

The new failure provides fresh evidence that the underlying HTTP/2 flow-control issue is not fully resolved by Michael Montalbo’s proposed fix (packing refs and aligning `$JOBS` with runner core count). The error suggests the transfer is being aborted mid-stream, which may point to a timeout or protocol-level disagreement between Git’s HTTP/2 usage and the runner’s libcurl (8.6.0) or Apache (h2_mod) stack. Patrick does not propose a code change here; the email is purely observational, adding another data point to the root-cause investigation. The thread remains focused on diagnosing environment factors (libcurl version, macOS build image, Apache configuration) before deciding whether the existing patch is sufficient or needs revision.
