This is the final patch in Harald Nordgren’s `git branch --delete-merged` series (v17, 7/7). It adds `--dry-run` support to the new `--delete-merged` subcommand, allowing users to preview which branches would be deleted before committing to the action.

The implementation is straightforward: when `--dry-run` is specified alongside `--delete-merged`, the command prints "Would delete branch <name>" for each branch that matches the deletion criteria (merged into its upstream, not checked out, not missing its upstream, not pushing back to its upstream, not opted out via `branch.<name>.deleteMerged`, and not used as an upstream for another branch). The same filtering logic applies as in the real deletion path, so the output exactly matches what would be deleted. The flag is rejected if used without `--delete-merged`.

The patch touches three files: `Documentation/git-branch.adoc` (adds a short `--dry-run` entry under `--delete-merged`), `builtin/branch.c` (adds the `DELETE_BRANCH_DRY_RUN` flag, propagates it through the deletion API, and modifies the output path to print "Would delete" messages instead of performing deletions), and `t/t3200-branch.sh` (adds tests verifying `--dry-run` output matches real deletion output and that the flag is rejected without `--delete-merged`). The test coverage is minimal but sufficient for the feature’s scope.

This patch completes the series’ safety architecture by giving users a zero-risk way to preview the effect of a wide deletion pattern (e.g., `'origin/*'`) before executing it. The implementation is clean and follows the established pattern of the flags-based API introduced earlier in the series. No substantive issues are apparent; the patch is ready for final review.
