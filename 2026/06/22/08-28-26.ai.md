This is the fourth patch in Patrick Steinhardt’s **v5 refactoring series** for Git’s reference backend, addressing a **lifecycle management bug** in the `chdir_notify` subsystem. The patch fixes a long-standing issue where reference stores (files, packed, and reftable backends) were registered with `chdir_notify` but never unregistered, leading to potential use-after-free or memory leaks.

The problem stems from the one-way nature of `chdir_notify_reparent()`, which lacks an unregistration mechanism. The patch replaces it with `chdir_notify_register()` and adds corresponding `chdir_notify_unregister()` calls in the `*_ref_store_release()` functions for all three backends (files, packed, and reftable). Each backend now provides its own reparenting callback (`files_ref_store_reparent()`, `packed_ref_store_reparent()`, `reftable_be_reparent()`) to handle path updates when the working directory changes. The changes are confined to the refs subsystem (`refs/files-backend.c`, `refs/packed-backend.c`, `refs/reftable-backend.c`) and introduce no behavior changes—only proper cleanup.

This is a **bugfix with no user-visible impact** under normal conditions, as Git rarely changes directories mid-process. However, it eliminates a latent memory safety issue, particularly for submodule and worktree reference stores that *are* freed during operation. The patch is a carry-over from v4 and aligns with Justin Tobler’s earlier approval of similar lifecycle fixes in the series. The only technical note is that the new callbacks use `UNUSED` annotations to suppress compiler warnings for the `name` parameter, a minor stylistic detail.

The fix is **uncontroversial** and likely to be merged as-is. It sets the stage for patch 6/11, which will address the leak of the main reference database. No follow-up discussion is expected beyond routine review.
