This is the second patch in Toon Claes's three-part series introducing the `--linearize` option to `git replay`. The series is now in its fourth iteration and is considered technically complete, with Junio Hamano indicating it is ready for merging.

This patch is a refactoring that prepares the codebase for the `--linearize` feature by improving the clarity of the commit mapping logic in `replay.c`. It introduces a new helper function, `put_mapped_commit()`, to encapsulate the logic for adding entries to the `replayed_commits` khash map, and renames the existing `mapped_commit()` function to `get_mapped_commit()` to create a clear getter/setter pair. The changes are purely internal and do not alter behavior, but they make the code easier to read and maintain by reducing duplication and improving encapsulation.

The patch touches only `replay.c` and is small in scope, changing just 20 lines while removing 11. The refactoring was motivated by the length and complexity of the `replay_revisions()` function, which this patch helps streamline. The new `put_mapped_commit()` helper is immediately used to replace inline khash operations, making the mapping logic more explicit and less error-prone.

This patch has already incorporated all review feedback from earlier iterations, including architectural input from Justin Tobler and Elijah Newren. The getter/setter pattern was well-received as a clarity improvement, and the patch carries Johannes Schindelin's Signed-off-by, indicating his support. There are no outstanding technical concerns or objections.

For readers following the series, this patch is a necessary but unexciting step toward the main event: the `--linearize` implementation in patch 3/3. It is a good example of the kind of preparatory refactoring that often precedes new features in Git, ensuring the codebase remains maintainable as functionality grows. The series as a whole is now ready for merging to `next`.
