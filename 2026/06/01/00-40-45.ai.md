Maintainer response on `git describe` pattern matching stability.

Junio C Hamano responds to Tuomas Ahola's proposed fix for the unstable test output in the `git describe --exclude` series. While acknowledging that switching to `STABLE_QSORT` would make the test pass by producing consistent output, Junio argues this would actually make real-world behavior worse by introducing an arbitrary ordering preference where multiple equally valid answers exist.

The core issue remains that the test expects exactly one output ("branch_A") when multiple refs ("branch_A" and "remotes/origin/remote_branch_A") are equally valid matches. Junio suggests two alternative approaches that would better preserve the command's intended semantics: either modify the test to avoid creating ambiguous cases where multiple refs have equal priority, or adjust the test to accept any valid answer rather than requiring an exact match.

This response indicates the sorting stability fix doesn't address the underlying design question about how `--exclude` should handle remote ref names. The thread now faces a decision between making the implementation more rigid (with stable sorting) versus making the test more flexible to accept multiple correct outcomes. Junio's preference clearly leans toward the latter approach that maintains the command's flexible matching behavior while adapting the test to properly validate it.
