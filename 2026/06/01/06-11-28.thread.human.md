The thread explores adding mirror fallback support to handle fetch failures, originally proposed specifically for submodules but now being reconsidered as a more general repository feature after maintainer feedback. Benson Muite's initial patch suggested submodule-specific alternate URLs, but Junio Hamano pushed back, arguing the solution should work at the repository level since mirroring needs extend beyond submodules.

New input from Simon Richter of Debian provides concrete motivation: their archive server struggles to maintain self-contained mirrors of projects using submodules, as external or relative submodule URLs break when mirrored. This reinforces Junio's position that the problem is broader than submodules alone. While no technical details are proposed yet, the Debian use case makes clear that reliable mirroring requires handling repository identity and references in a way that survives mirroring operations. The discussion now needs to either justify why submodules need special treatment or converge on a general mechanism that would help both submodules and other mirroring scenarios.
