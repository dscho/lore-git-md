This thread explores how to improve Git's submodule mirroring capabilities, particularly for archival use cases like Debian's package repositories. The core tension lies between maintaining immutable repository identities while allowing flexible location mapping - a design issue Simon Richter highlighted. Three technical approaches have emerged: repository-wide URL rewriting (Junio's preferred solution), transitional submodule fallback URLs (Benson Muite's proposal), and Matt Hunter's suggestion to unify these via Git's existing remote URL infrastructure.

Peff's latest contribution clarifies why Git's current design favors decentralized workflows, where submodules may have no administrative relationship to their superproject. While Debian's relative URL approach works for their coordinated mirroring setup, Git must also support independent mirroring scenarios. The discussion now centers on how to enhance URL rewriting capabilities (like `insteadOf`) to serve both cases, while leaving the actual mirror discovery and distribution problem to higher-level tools. This maintains Git's flexibility while acknowledging that institutional users will need to build their own mapping systems on top. The thread remains active as participants work to balance immediate archival needs with sustainable architectural solutions.
