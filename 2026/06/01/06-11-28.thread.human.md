The thread explores solutions for reliable submodule mirroring, particularly for archival purposes like Debian's needs. The core tension is between immediate practical fixes (adding fallback URLs in .gitmodules) and Junio's architectural preference for repository-wide solutions. Benson Muite originally proposed transitional submodule fallback URLs, while Jeff King noted scaling challenges with URL rewriting approaches.

Simon Richter's latest contribution reframes the problem more fundamentally, arguing that Git currently conflates a submodule's identity (what it is) with its location (where to fetch it). As a Debian maintainer, he highlights the real-world consequences: when original URLs die, maintainers face unbuildable old versions, history rewrites, or fragile workarounds. His analysis strengthens the case for separating location metadata from version-controlled data.

Meanwhile, Matt Hunter identified a potential unification path through Git's existing but underused multi-URL remote configuration. This could satisfy both immediate mirroring needs and long-term architecture by leveraging infrastructure that already exists. The discussion now focuses on evaluating this approach's security implications and activation mechanisms, particularly for large-scale archival scenarios with dozens of submodules. Junio remains firm that any solution should work at the repository level rather than just for submodules.
