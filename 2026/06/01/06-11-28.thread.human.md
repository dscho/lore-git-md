This thread explores how to handle repository mirroring when primary submodule sources become unavailable, particularly for archival use cases like Debian's. The discussion has evolved through several phases, with Benson Muite originally proposing submodule-specific fallback URLs in .gitmodules, while Junio Hamano maintains that any solution should work at the general repository level rather than being submodule-specific.

The latest exchange, Benson acknowledges the maintainer's architectural preference while keeping both approaches in play. They note that while their original proposal addressed immediate submodule pain points (particularly for recursive cloning when primary sources disappear), a repository-wide solution would also meet their needs if it can handle complex submodule graphs. The technical challenge lies in creating a mirroring system that scales to repositories with 50+ submodules from different origins while maintaining security and repository identity.

Key participants have staked out positions: Junio insists on general repository mechanisms, Jeff King supports URL rewriting but recognizes its scaling limitations, and Simon Richter from Debian continues emphasizing archival security requirements. The discussion now appears to be shifting toward exploring repository-level solutions that can accommodate submodule use cases, with open questions remaining about how to implement this without compromising security or creating maintenance burdens for complex submodule hierarchies. The thread remains active as participants work to reconcile these competing requirements.
