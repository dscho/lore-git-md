Bugfix for subprocess communication in Git's filter mechanism. This v2 patch from Michael Montalbo improves error handling when filter subprocesses fail to start, particularly when their paths contain spaces. The fix addresses Junio C Hamano's feedback from the initial version by more carefully distinguishing between error conditions and expected flush packets during the subprocess handshake.

The core issue occurs when a filter command path contains spaces (common on Windows with "Program Files" paths) and the tool doesn't exist. Previously, Git would crash with an opaque "remote end hung up" message. The patch replaces `packet_read_line()` calls with `packet_read_line_gently()` throughout the handshake process in `sub-process.c`, allowing proper error propagation instead of abrupt termination.

Key improvements in v2:
- More precise error state tracking during negotiation phases
- Clearer error reporting that distinguishes between read failures and expected flush packets
- Additional test case verifying behavior with spaced paths
- Better error messages showing initialization failures rather than just "hung up"

The changes make Git more robust when dealing with filter processes, particularly in edge cases where the subprocess fails during startup. The patch appears well-tested and addresses all the edge cases identified in review.
