This is the second patch in Patrick Steinhardt's series to deprecate the `git-init-db` command alias in favor of `git-init`. The patch focuses on the documentation and build system changes needed to mark `git-init-db` as deprecated while maintaining backward compatibility.

The changes include:
- Adding a deprecation notice to `BreakingChanges.adoc`
- Creating a redirect man page for `git-init-db` that warns about the deprecation
- Updating build systems (Makefile and meson.build) to handle the deprecation
- Modifying test scripts to use `git-init` instead of `git-init-db`
- Conditionally compiling out `init-db` when `WITH_BREAKING_CHANGES` is set

The patch provides historical context, noting that `git-init-db` was originally for initializing just the object database, while `git-init` (introduced in 2007) better reflects the command's current functionality of initializing all repository structures. The changes are low-risk since they maintain backward compatibility while steering users toward the preferred command name.

This is a clean, well-motivated change that continues Git's ongoing effort to standardize command names and clean up historical aliases. The patch touches multiple build systems and documentation files but doesn't modify any core functionality.
