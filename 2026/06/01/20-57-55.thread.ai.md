Thread identity: RFC proposal from Skybuck Flying (Harald Houppermans) for major Git extensions to support modern development workflows, focusing on dependency management, security metadata, multi-repo coordination, and now specifically repository UUIDs for stable identification.

Core problem: Git lacks built-in mechanisms for stable repository identification, dependency resolution, security metadata tracking, and cross-repository project management. The expanded proposal now details how repository-level UUIDs could address URL fragility and provenance tracking while enabling better dependency management and security advisory handling.

Key technical proposals:
- `.gitdeps` and `.gitdeps.lock` files for declarative dependency specification and locking
- `.gitorigin` for tracking repository provenance across moves/renames  
- `.gitsecurity` for vulnerability reporting metadata
- `.gitproject` for multi-repo project configuration
- New `.git/identity` file containing 128-bit UUID as permanent repository identifier
- Potential `git clone uuid:...` syntax and UUID-based URLs
- All features designed as optional additions to avoid breaking changes

Current status: Proposal remains at RFC stage with no implementation patches. The UUID-specific follow-up provides concrete examples of breakage scenarios this would prevent (Go imports, security advisories, organizational migrations) and suggests implementation approaches.

Key technical details:
- UUIDs would survive repository moves/renames
- Could enable stable import paths and dependency references
- Optional parent UUID tracking for fork/mirror relationships
- Backward compatibility through opt-in adoption
- Hosting provider cooperation would enhance the system

Open questions:
- Technical feasibility and implementation complexity of UUID system
- Whether these features belong in core Git versus higher-level tooling
- Hosting provider adoption requirements for full effectiveness  
- Performance implications for large repositories
- Maintenance burden of new metadata formats
- Potential overlap/conflict with existing systems like submodules

Participant positions: Still only Skybuck Flying's proposals at this stage; no reviews or responses yet recorded. The comprehensive nature suggests this may generate significant discussion about Git's scope and role in the modern development ecosystem.

Related work: Implicitly compares to external systems like Go modules, Cargo, and other language-specific package managers that implement similar features outside Git. The proposal positions these additions as bringing such capabilities into Git itself while avoiding URL fragility through UUIDs.
