Thread identity: RFC proposal from Skybuck Flying (Harald Houppermans) for major Git extensions to support modern development workflows, focusing on dependency management, security metadata, and multi-repo coordination.

Core problem: Git lacks built-in mechanisms for dependency resolution, security metadata tracking, and cross-repository project management, forcing ecosystems to implement these separately (e.g., Go modules, Cargo). The proposal aims to add optional, backward-compatible systems to address these gaps without breaking existing workflows.

Key technical proposals:
- `.gitdeps` and `.gitdeps.lock` files for declarative dependency specification and locking
- `.gitorigin` for tracking repository provenance across moves/renames
- `.gitsecurity` for vulnerability reporting metadata
- `.gitproject` for multi-repo project configuration
- Repository UUIDs as stable identifiers independent of URLs
- All new features designed as optional additions to avoid breaking changes

Open questions:
- Technical feasibility and implementation complexity of each proposal
- Whether these features belong in core Git versus higher-level tooling
- Potential overlap/conflict with existing systems like submodules and worktrees
- Maintenance burden of new metadata formats and their evolution
- Performance implications for large repositories

Participant positions: Initial proposal from Skybuck Flying; no reviews or responses yet recorded. The comprehensive nature suggests this may generate significant discussion about Git's scope and role in the modern development ecosystem.

Related work: Implicitly compares to external systems like Go modules, Cargo, and other language-specific package managers that implement similar features outside Git. The proposal positions these additions as bringing such capabilities into Git itself.
