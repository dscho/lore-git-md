Thread identity: Bugfix for subprocess communication in Git's filter mechanism, addressing crashes when filter paths contain spaces. Originating author not specified in this summary.

Core problem: Git would crash with a "remote end hung up" error when a filter subprocess fails to start due to path containing spaces, because the subprocess handshake used `packet_read_line()` which calls `die()` on failure rather than the error-handling-capable `packet_read_line_gently()`.

Current status: Patch proposes changing all handshake packet reads in `sub-process.c` to use `packet_read_line_gently()`, allowing proper error propagation when filter processes fail to start.

Key technical details:
- Fix targets `sub-process.c` handshake logic
- Particularly affects Windows ("Program Files" paths) and POSIX systems with spaces in filter paths
- Includes new test case verifying behavior with non-existent spaced paths
- Changes error message from opaque "hung up" to clear initialization failure notice
