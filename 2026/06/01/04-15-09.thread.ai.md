Thread identity: Bugfix for subprocess communication in Git's filter mechanism, addressing crashes when filter paths contain spaces. Originating author is Michael Montalbo.

Core problem: Git would crash with a "remote end hung up" error when a filter subprocess fails to start due to path containing spaces, because the subprocess handshake used `packet_read_line()` which calls `die()` on failure rather than the error-handling-capable `packet_read_line_gently()`.

Current status: Patch v2 implements Junio C Hamano's review feedback with refined error handling in `sub-process.c` to:
1. Distinguish between true flush packets and error conditions during capabilities negotiation
2. Prevent misleading "<flush packet>" messages when subprocess fails entirely
3. Add explicit error returns when subprocess dies mid-handshake
4. Maintain improved error messages showing initialization failures
5. More precise error state tracking during negotiation phases
6. Better separation of error conditions from normal protocol flow

Key technical details:
- Fix targets `sub-process.c` handshake logic (version handshake, capabilities loop, flush checking)
- Particularly affects Windows ("Program Files" paths) and POSIX systems with spaces in filter paths
- Includes new test cases verifying behavior with non-existent spaced paths
- Original patch already switched from `packet_read_line()` to `packet_read_line_gently()`
- Clearer error messages identifying which handshake phase encountered problems
