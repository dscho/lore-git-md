Performance optimization for index-pack's delta resolution.

This v2 patch from Arijit Banerjee follows up on Derrick Stolee's review of the initial version, incorporating requested benchmark data directly into the commit message while maintaining the core 1-line change. The optimization prevents index-pack from prematurely freeing delta base objects that will be needed again for resolving child deltas, instead letting the existing delta base cache policy manage retention.

The patch now includes comprehensive benchmark results showing 13-16% speedups across multiple repositories (linux.git, git.git, libgit2, redis) with minimal memory overhead (1.9% RSS increase at worst). The commit message has been expanded to document these results and confirm passing tests, including SANITIZE=leak verification as requested in review.

The change remains simple and focused - still just removing one `free_base_data()` call - but now better documented. This appears ready for merging as it addresses all review feedback while demonstrating clear performance benefits for large repositories. The optimization is low-risk since it works within the existing cache infrastructure rather than introducing new mechanisms.
