This is a follow-up in the thread about deprecating the `git-init-db` command alias in favor of `git-init`. Phillip Wood suggests adding a runtime warning when `git-init-db` is used, noting that users with muscle memory for the old command name might not see the deprecation notice in the man pages.

The suggestion builds on the already-agreed technical approach of marking the command as deprecated in the code (via a `DEPRECATED` flag in the command table). Phillip's proposal would make the deprecation more visible to end users by printing a warning at runtime, similar to how other deprecated Git features behave. This would help transition users away from the old command name more effectively.

The thread shows consensus on deprecating `git-init-db`, with discussion now focusing on implementation details to ensure the deprecation is properly communicated. Patrick Steinhardt has already incorporated Kristoffer Haugsbakk's earlier suggestion about the `DEPRECATED` flag, and this new suggestion from Phillip represents a natural refinement of the deprecation strategy.
