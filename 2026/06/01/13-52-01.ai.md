Bugfix for HTTP pack index handling, removing redundant cleanup code. This is the first of two final patches in Lorenzo Pegorari's series addressing resource management in the HTTP transport layer's pack index fetching logic.

The patch removes an unnecessary `unlink()` call in `fetch_and_setup_pack_index()` that became redundant after commit 63aca3f7f1 made the tempfile subsystem handle cleanup automatically. The change is straightforward - just deleting two lines that manually removed the index file on error paths, since the tempfile API now guarantees this cleanup will happen at process exit.

This represents the simpler solution that emerged from Jeff King's review of earlier iterations, where he identified the tempfile inconsistency and evaluated alternative approaches. The patch maintains all the proper resource cleanup while eliminating redundant operations, following Git's best practices for error path management. With consensus achieved through multiple review rounds, this being the third iteration, the change appears ready for merging.
