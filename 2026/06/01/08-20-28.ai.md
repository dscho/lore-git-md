This is patch 5/18 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the ODB (object database) abstraction effort. The patch wires up a `close()` callback for the loose source, though it remains a no-op since the loose source currently has no resources requiring cleanup.

The change is straightforward - it adds the callback implementation in odb/source-loose.c and updates the files source to call it through the generic interface when closing. The diff shows the mechanical nature of this change, with the new callback simply returning immediately while maintaining the expected interface contract.

This continues the series' pattern of incrementally converting direct operations to callback-based ones through the odb_source interface. The patch doesn't modify behavior but moves the code closer to the goal of having all loose object operations go through the vtable. As with previous patches, this appears to be a well-contained, low-risk change that follows the established refactoring approach.
