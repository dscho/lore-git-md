This RFC thread from Skybuck Flying (Harald Houppermans) proposes major extensions to Git's capabilities for modern development workflows, now with a specific focus on repository provenance tracking. The original proposal introduced several new metadata files (.gitdeps, .gitsecurity, .gitproject) and a repository UUID system for stable identification. The latest follow-up adds detailed specifications for tracking fork lineage through a new `.gitorigin` file that would store parent repository UUIDs and synchronization points.

The expanded proposal aims to solve real-world problems like tracking multi-generation fork relationships, maintaining provenance across repository migrations, and calculating precise divergence between forks. Key technical elements include optional metadata files that would work together with repository UUIDs to construct a complete fork DAG while remaining backward compatible. The author provides concrete examples demonstrating how this system would improve upon current limitations in dependency management and security advisory handling.

While the proposal remains at the RFC stage without implementation patches, its comprehensive nature raises important questions about Git's role in modern development ecosystems. The thread has yet to receive reviews or responses from other contributors, but the depth of the proposal suggests it may spark significant discussion about whether such features belong in core Git versus higher-level tooling, and how they might interact with existing hosting provider systems. The author continues to develop the ideas systematically, with each follow-up adding more technical specification to address specific workflow pain points.
