This is a documentation clarification about Git hook behavior, continuing the thread about config-based hooks.

Junio C Hamano adds an important technical note to Jeff King's earlier response about hook argument handling. He points out that hooks must also properly handle their standard input, not just command-line arguments. Some hooks (like pre-push) expect to read specific data from stdin, and simply ignoring it could cause problems.

Unlike with arguments (where Jeff suggested using `#` to discard them), there's no simple syntax to ignore stdin - the best approach is to explicitly discard it with `cat >/dev/null` before running the actual hook command. This maintains the hook contract while allowing the desired command to run.

The exchange highlights that while the immediate issue had a workaround, there are broader considerations about how hooks interface with Git that could be better documented. Junio's comment suggests these stdin handling requirements should be another area for clarification in the hook documentation.
