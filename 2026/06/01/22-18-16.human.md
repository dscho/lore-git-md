This is a follow-up in the ongoing thread about deprecating the `git-init-db` command alias in favor of `git-init`. Junio C Hamano weighs in with a strong opinion against using `you_still_use_that()` for runtime deprecation warnings in this case.

Junio argues that while runtime warnings might have been justified for more commonly used command aliases (like the log-family commands), `git-init-db` is both less frequently used and has a straightforward replacement in `git-init`. He notes that runtime warnings wouldn't help scripted usage anyway, which is where most legacy usage would likely appear.

This marks a shift in the discussion - where previous emails had moved toward consensus on including both compile-time deprecation markers and runtime warnings, Junio's intervention suggests the runtime warning may be overkill for this particular case. As the maintainer, his opinion carries significant weight in settling this detail.

The thread remains technically settled on the core approach (deprecating `init-db` in favor of `init` with documentation updates and compile-time markers), but now questions whether to include the additional runtime warning mechanism. Patrick Steinhardt will need to decide whether to proceed with just the `DEPRECATED` flag or also include the warning in his next version.
