Performance optimization for index-pack's delta resolution.

This v2 patch from Arijit Banerjee follows up on Derrick Stolee's review of the initial version, incorporating requested improvements while maintaining the core optimization. The change remains a simple one-line removal of `free_base_data()` in index-pack's delta resolution path, but now includes more detailed benchmark data directly in the commit message rather than just the cover letter.

The key improvement is better reuse of delta base objects during pack indexing - instead of immediately freeing reconstructed bases that have child deltas, the patch lets the existing delta base cache policy decide when to evict them. This avoids redundant reconstruction work for descendant deltas. Performance gains remain strong: 15-16% faster wall times for large repositories like linux.git with minimal memory overhead (1.9% RSS increase in worst case).

The v2 changes address Stolee's review by:
1. Moving benchmark data from cover letter to commit message
2. Confirming SANITIZE=leak testing via CI
3. Adding more context about the cache accounting

The patch shows thorough testing across multiple repository types and configurations, with neutral results on the standard p5302 perf test (as expected for its smaller test case). This appears ready for merging as a well-validated optimization that improves a performance-critical path without introducing new complexity.
