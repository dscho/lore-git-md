This thread examined the long-term status of Git's `git-init-db` alias, which has existed alongside the primary `git init` command since 2007. The discussion began with Patrick Steinhardt proposing to align internal naming with the modern command, but maintainer Junio Hamano firmly established that the implementation would remain unchanged to preserve backward compatibility. The alias will stay supported indefinitely, though it's already hidden from help output in favor of documenting only `git init`.

In the final exchange, Junio considered Phillip Wood's suggestion for a deprecation warning but concluded it would be unnecessary since the alias isn't actually being deprecated - it will remain available permanently as a legacy feature. This maintains consistency with Git's conservative approach to historical commands, where truly deprecated features (like `git-whatchanged`) receive warnings before removal, while indefinitely supported aliases (like `git-stage`) remain quietly available. The thread demonstrates how the project balances modernization against stability, with the maintainer's guidance ensuring technical changes only occur when they provide clear user benefit without disrupting existing workflows. No further action is expected beyond potential minor documentation updates.
