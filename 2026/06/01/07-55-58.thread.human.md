Patrick Steinhardt has proposed deprecating the historical `git-init-db` command in favor of the now-standard `git-init`, sending an initial two-patch series that renames the implementation file while maintaining backward compatibility. The changes include documentation updates marking `init-db` as deprecated and build system modifications to optionally compile out the old command name.

Kristoffer Haugsbakk has provided the first substantive review, suggesting a refinement to how the deprecation is implemented. Rather than just conditionally compiling the old command name, he proposes adding a `DEPRECATED` flag to the command table to make the status more explicit in the code. This could enable future deprecation warnings or other behaviors, though the exact implications would need to be worked out. The core goal of standardizing on `git-init` isn't contested - the discussion is now focused on the best way to mark the transition in the codebase.

This continues Git's ongoing effort to clean up historical command aliases, with `git-init` having been the preferred form since 2007. The thread remains early in its lifecycle with only the initial version and one review so far.
