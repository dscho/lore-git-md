This thread discusses Patrick Steinhardt's effort to formally deprecate the `git-init-db` command alias in favor of the more modern `git-init`. The series consists of two patches so far - the first mechanically renames the implementation file from `builtin/init-db.c` to `builtin/init.c` while maintaining backward compatibility, and this second patch updates documentation and build systems to mark `git-init-db` as deprecated.

The changes are straightforward: documentation now clearly indicates `git-init-db` is deprecated (with a notice in BreakingChanges.adoc and a redirect man page), build systems have been updated to handle the deprecation, and tests now use git-init exclusively. Notably, the patch maintains backward compatibility - both command names will continue to work unless explicitly compiled with WITH_BREAKING_CHANGES. 

This is part of Git's ongoing effort to clean up historical command aliases, with git-init-db having been effectively replaced by git-init since 2007. The changes are low-risk since they don't break existing usage while steering users toward the preferred form. So far there hasn't been any review feedback on the series.
