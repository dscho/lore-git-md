This thread discusses Patrick Steinhardt's effort to formally deprecate the `git-init-db` command alias in favor of the canonical git-init. The initial proposal was to handle this through code and documentation changes, including renaming the implementation file and adding deprecation notices. Kristoffer Haugsbakk suggested improving the technical approach by adding a DEPRECATED flag in the command table, which Patrick has accepted but not yet implemented.

Phillip Wood has now expanded the discussion by proposing that the deprecation should also trigger a runtime warning when users execute git-init-db. His review notes that while documentation changes are important, many users with muscle memory for the old command name might never see man page warnings. A runtime message would make the deprecation more visible and help users transition. This suggestion follows Git's established patterns for other deprecated commands.

The technical approach is now well-defined, with consensus on both the code-level deprecation marking and the new user-facing warning. We're awaiting Patrick's updated patch series that will incorporate both Kristoffer's DEPRECATED flag suggestion and Phillip's runtime warning proposal. The thread demonstrates Git's careful approach to backward-compatible changes, where even straightforward deprecations receive thorough consideration of both implementation details and user impact.
