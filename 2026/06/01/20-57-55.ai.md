This is a feature proposal for Git to better support modern development workflows involving dependencies, multi-repo projects, and security metadata. The author, Skybuck Flying (Harald Houppermans), presents a comprehensive RFC outlining what they see as major gaps in Git's functionality.

The proposal identifies 10 key missing features Git "should have had", organized into three main sections:

1. A critique of Git's current limitations for modern development needs
2. Detailed technical proposals for new metadata files and systems
3. Concrete examples showing how these features would work

Key proposed additions include:
- `.gitdeps` and `.gitdeps.lock` for dependency management
- `.gitorigin` for provenance tracking
- `.gitsecurity` for vulnerability reporting
- `.gitproject` for multi-repo coordination
- Repository UUIDs for stable identity independent of URLs

The author argues these would address pain points around:
- Dependency hell and submodule workflows
- Lost provenance when repositories move/rename
- Lack of built-in security metadata
- Fragility of import paths tied to URLs
- Difficulty managing multi-repo projects

The proposal is ambitious in scope but emphasizes backward compatibility - all new features would be optional additions rather than breaking changes. The author presents this as filling gaps that currently force ecosystems to build parallel systems (like Go modules, Cargo) on top of Git.

This appears to be an initial RFC seeking discussion rather than a polished patch series. The tone mixes technical detail with strong opinions about Git's limitations. While passionate, the proposal does lay out concrete mechanisms for each suggested feature and provides example use cases showing the problems they would solve.
