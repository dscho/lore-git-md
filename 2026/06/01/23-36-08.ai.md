This is a bugfix patch for `git describe` that addresses an issue with the `--exclude` and `--match` options when used together with `--contains` and `--all`. The patch comes from Jacob Keller and is version 2 of the fix.

The core issue is that `git describe --contains` (which internally uses `git name-rev`) wasn't properly forwarding the `--match` and `--exclude` patterns to `name-rev` when operating in `--all` mode. This caused the filters to be silently ignored, contrary to what the documentation suggests should happen.

The fix modifies the pattern handling to:
1. Always pass tag patterns with the `refs/tags/` prefix
2. When `--all` is used, additionally pass the patterns with `refs/heads/` and `refs/remotes/` prefixes to match the documented behavior

The patch includes several new test cases that verify the corrected behavior works as expected, including cases with:
- Basic tag matching
- Branch name matching
- Remote branch matching
- Combinations of includes and excludes

The changes are straightforward and focused on the pattern forwarding logic in `builtin/describe.c`, with corresponding test additions in `t/t6120-describe.sh`. The v2 iteration includes some test improvements based on feedback, like using `check_describe` helper and adding more test coverage for remote branches.

This appears to be a well-contained fix for a clear documentation/implementation mismatch, with good test coverage to prevent regression. The patch follows Git's standard practices and the changes align with the documented behavior.
