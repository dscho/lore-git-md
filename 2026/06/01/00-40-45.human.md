Maintainer feedback on `git describe` pattern matching stability.

Junio C Hamano responds to Tuomas Ahola's proposed fix for unstable test output in the `git describe --contains --all` pattern matching behavior. While acknowledging that switching to `STABLE_QSORT` would make the test pass consistently, he argues this would actually make real-world usage worse by introducing an arbitrary ordering preference where multiple equally valid answers exist.

The maintainer suggests alternative approaches that would better preserve the command's flexibility:
1. Modifying the test to avoid having multiple equally valid answers
2. Updating the test to accept any of several possible outputs rather than requiring an exact match

This feedback indicates the sorting instability is a test design issue rather than a bug in the command's behavior. Junio's preference leans toward making the test more robust rather than constraining the implementation to produce deterministic but potentially suboptimal output ordering. The response leaves open how to properly handle the remote ref matching case that originally surfaced the issue.
