This is patch 7/18 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the ODB (object database) abstraction effort. The patch wires up the `read_object_stream()` callback for loose objects, moving the implementation from object-file.c to odb/source-loose.c.

The change is a mechanical relocation of code that handles streaming loose object contents, including:
- Moving the core `odb_source_loose_read_object_stream()` function
- Relocating helper functions like `open_loose_object()` and `odb_source_loose_map_object()`
- Exposing two previously static functions (`unpack_loose_header()` and `parse_loose_header()`) in object-file.h since they're now shared between subsystems

The patch follows the established pattern of the series - converting direct function calls into callback-based operations through the odb_source interface. No behavior changes are introduced; this is purely an internal reorganization to support the ODB abstraction work. The changes span multiple files but maintain the same functionality, with test coverage confirming everything continues to work as before.

This continues the methodical, incremental approach seen in previous patches of the series. With no substantive technical feedback on v1 and only minor doc fixes addressed in v2, this infrastructure work appears to be progressing smoothly toward the larger goal of making Git's object storage pluggable.
