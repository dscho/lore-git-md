This is the first patch in Patrick Steinhardt's 2-part series adding a "drop" subcommand to the experimental `git history` command. The patch refactors the reference update handling in builtin/history.c to split it into two distinct phases: computing pending updates and applying them.

The change is a preparatory refactoring that separates the logic for determining which refs need updating (now in `compute_pending_ref_updates`) from the actual transaction execution (in `apply_pending_ref_updates`). This split enables the upcoming "drop" functionality in patch 2, which will need to perform these operations separately.

The refactoring appears clean and mechanical, maintaining all existing behavior while making the code more flexible. The patch follows Git's style guidelines and includes updates to the existing test suite. Given Patrick's track record with the history command and the straightforward nature of this change, this seems like a solid foundation for the new functionality to come in patch 2.
