This is patch 13/18 in Patrick Steinhardt's ongoing series to refactor Git's loose object handling as part of the ODB (object database) abstraction effort. The patch focuses on cleaning up the loose object map implementation to operate directly on `struct odb_source_loose` rather than taking a detour through the files backend.

The key change removes an implicit assumption that loose object map functions were making - they accepted a generic `struct odb_source*` but always expected it to be the files backend. The patch makes this relationship explicit by having the functions take a `struct odb_source_loose*` directly. This eliminates unnecessary indirection and makes the code's intent clearer.

The changes are mechanical but meaningful - they touch core object handling code in loose.c and object-file.c, updating function signatures and call sites. The patch maintains all existing behavior while simplifying the implementation. It follows the established pattern in this series of making small, focused changes that incrementally improve the code structure.

This continues the careful, well-structured approach seen in previous patches of the series. With no substantive technical feedback on earlier versions, this appears to be progressing smoothly as part of the larger ODB abstraction effort. The changes are unlikely to be controversial as they don't modify behavior, just clean up internal interfaces.
