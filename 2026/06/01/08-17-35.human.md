This is a performance optimization patch for Git's priority queue implementation, following up on earlier discussion in the thread. Kristofer Karlsson from Spotify has revised his approach based on Junio C Hamano's feedback to preserve both the new `prio_queue_get()` optimizations and René Scharfe's existing `prio_queue_replace()` optimizations.

The patch introduces a new `sift_up_rebalance()` function that halves the number of comparisons needed for extract-min operations in the priority queue. The key improvement comes from promoting the smaller child at each level (one comparison + one copy) rather than the standard approach of placing the last element at root and sifting it down (two comparisons + swap). Benchmarks show:

- 15-23% faster for ascending keys (Git's common case)
- 1-4% improvement for descending keys
- ~2% speedup in real-world `rev-list` operations on wide DAGs
- No regressions in any scenario

Changes since v1:
- Preserved René's optimized `prio_queue_replace()` implementation
- Extracted the new logic into a separate `sift_up_rebalance()` function
- Added more benchmark data showing consistent improvements

The patch is well-motivated with clear performance data and maintains compatibility with existing behavior. It's a focused optimization that should benefit repositories with wide commit graphs while being essentially free for smaller ones. The technical approach appears sound and the implementation is clean.
