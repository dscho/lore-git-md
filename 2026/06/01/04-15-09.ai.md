Bugfix targeting subprocess communication in Git's filter mechanism. This patch addresses an issue where Git would crash with a "remote end hung up" error when a filter subprocess fails to start due to a path containing spaces. The root cause is that the subprocess handshake uses `packet_read_line()` which calls `die()` on failure, rather than the gentler `packet_read_line_gently()` that allows error handling.

The fix changes all handshake packet reads in `sub-process.c` to use the gentle variant, ensuring proper error propagation when a filter process fails to start. This particularly affects Windows users where "Program Files" paths are common, as well as any POSIX system where filter paths contain spaces. The patch includes a new test case that verifies the improved behavior when a non-existent filter path containing spaces is specified.

The commit message clearly demonstrates the before/after behavior with concrete examples, showing how the error message changes from an opaque "hung up" to a clear initialization failure notice. The change is well-contained, touching only the subprocess handshake logic while adding a targeted test. This appears to be a straightforward improvement to error handling that should be uncontroversial.
