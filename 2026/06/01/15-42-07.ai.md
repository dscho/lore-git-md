This is part 4 of an 8-patch series in the ongoing `the_repository` removal effort, focusing on migrating the `pack_compression_level` configuration from a global variable to `struct repo_config_values`. The patch maintains the existing eager parsing behavior for this performance-sensitive setting while preventing cross-repository state leakage.

The changes touch five files with mechanical updates to access the compression level through the repository's config structure rather than directly. Key modifications include:
- Moving the global `pack_compression_level` into `repo_config_values`
- Updating compression initialization in `fast-import`, `pack-objects`, and object-file operations to use the repository-specific value
- Preserving the same validation and default value logic (Z_DEFAULT_COMPRESSION)

The patch follows the established pattern seen in earlier parts of the series, with similar changes to how other settings like `zlib_compression_level` were migrated. Performance impact should be neutral since the configuration continues to be parsed eagerly, avoiding any runtime overhead in compression hot paths.

This continues the incremental but wide-reaching refactoring work to eliminate global state, with the series having already received positive reviews from multiple contributors. The changes are straightforward mechanical updates that don't introduce new behavior, making this a low-risk part of the larger effort.
