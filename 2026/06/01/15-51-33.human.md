Bugfix addressing subprocess handshake error handling in Git's filter mechanism. This is Michael Montalbo's response to Junio C Hamano's review of his earlier fix for crashes when filter paths contain spaces.

The patch series aims to make subprocess startup failures more graceful by switching from `packet_read_line()` (which crashes on error) to `packet_read_line_gently()` (which allows proper error handling). Junio identified two subtle issues in the initial implementation:

1. Error messages could misleadingly show "<flush packet>" when no flush actually occurred
2. The capabilities negotiation could incorrectly report success if the subprocess died mid-handshake

In this response, Michael acknowledges both issues and confirms he'll update the patch to:
- Fix the misleading error messages when reads fail
- Add explicit error checking in the capabilities negotiation loop to distinguish between expected flush termination and actual failures

The changes primarily affect `sub-process.c` and are particularly relevant for Windows systems (where "Program Files" paths commonly contain spaces) and any POSIX systems with spaced paths in filter configurations. The fix includes a new test case verifying behavior with non-existent spaced paths.

This demonstrates the careful attention to protocol edge cases that characterizes Git's subprocess communication code. Junio's review shows his characteristic focus on making error conditions both robust and clearly reported.
