This is a documentation-focused follow-up in the thread about Git hook argument handling, with Junio C Hamano adding an important clarification about stdin handling in hooks.

Junio builds on Jeff King's earlier confirmation about hook command argument handling by pointing out that hooks must also properly handle their stdin input, not just command-line arguments. He notes there's no simple way to ignore stdin (unlike arguments which can be discarded with shell tricks), except by explicitly redirecting it to /dev/null.

The exchange highlights two key aspects of hook behavior that need documentation:
1. Argument passing conventions (already discussed in the thread)
2. Stdin handling requirements (this new point)

This moves the documentation discussion beyond just argument passing to encompass the full hook interface contract. Junio's comment suggests the documentation should explicitly warn about both aspects, particularly noting that some hooks may fail if they don't properly consume their stdin input.

The thread continues to focus on improving documentation clarity around hook contracts while maintaining backward compatibility with existing implementation.
