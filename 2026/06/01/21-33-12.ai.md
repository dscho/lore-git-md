This is a performance optimization patch for `git stash -p` that has now received maintainer approval from Junio C Hamano. The patch is in its second iteration, with all previous review feedback addressed.

The key improvement replaces the external `git read-tree HEAD` call with an in-process `unpack_trees()` operation when creating the temporary index for interactive stash selection. This preserves cached stat data and fsmonitor-valid bits for unchanged files, allowing fsmonitor to skip unnecessary refreshes. Performance gains are substantial - in a 206k file repository with one change, time to first prompt drops from 34.774s to 0.659s when fsmonitor is enabled.

The v2 patch adds a new performance test showing similar improvements (6.90s->0.55s without fsmonitor, 6.83s->0.28s with fsmonitor). Junio notes the diff looks good and is comfortable with the changes, though he suggests an additional review from a regular `stash -p` user would provide extra confidence before merging.

The implementation is clean and focused, touching only `builtin/stash.c` and adding the new performance test. It builds on fsmonitor optimizations by Paul Tarjan and aligns with similar optimizations in `git restore -p`. With all review feedback addressed and maintainer approval, this appears ready for inclusion.
