This is the first patch in a GSoC participant's series to improve path handling in `git repo info`. The patch extracts path formatting logic from `rev-parse` into a new `strbuf_add_path()` helper function in `path.c`, making it reusable across Git commands.

The new function provides flexible path formatting options through two enums:
- `path_format_type` (default/relative/canonical)
- `path_default_type` (relative/relative_if_shared/canonical/unmodified)

The implementation cleanly handles four cases:
1. Unmodified paths (exactly as-is)
2. Explicit/implicit relative paths
3. Relative only if paths have common prefix
4. Forced absolute/canonical paths

The patch appears well-structured with clear documentation and proper memory management. It's part of a larger effort to improve path handling in repository information commands, building on prior discussions. The author has consulted with mentors Justin Tobler and Lucas Seiki Oshiro, suggesting good engagement with the community.

This foundational change will be used by subsequent patches in the series to add relative/absolute path variants to `git repo info` output. The technical implementation looks solid, though the broader series awaits community input on default behavior preferences.
