Feature addition to the experimental `git history` command, adding a "drop" subcommand to remove commits from history.

This is the second patch in Patrick Steinhardt's series introducing the `git history drop` command, which removes a specified commit and replays its descendants on top of its parent. The implementation builds on the refactoring from patch 1 that split ref updates into compute/apply phases.

Key aspects of this new subcommand:
- Removes a commit while preserving its descendants by replaying them
- Handles working tree and index updates when HEAD is affected
- Includes extensive test coverage (513 lines across 4 test scripts)
- Documents the new command and its limitations (no root or merge commits)
- Preserves unrelated local modifications during the operation

The implementation appears thorough, with careful attention to edge cases like empty descendants (controlled via --empty flag) and conflicts with local changes. This continues Patrick's pattern of well-structured additions to the history command, following the same high standard as previous subcommands like replay and fixup.

The patch touches builtin/history.c and adds new documentation and tests, maintaining consistency with the existing codebase. Given Patrick's track record with this command and the careful implementation shown here, this addition seems likely to be accepted with minimal controversy.
