This thread documents the behavior of Git's `@` prefix for raw Unix timestamps, clarifying that it forces interpretation as seconds-since-epoch rather than potentially ambiguous YYYYMMDD formats. The original patch from Luna Schwalbe, co-authored by Junio Hamano, added thorough documentation and test cases showing how the prefix affects parsing, particularly for timestamps under 100,000,000.

Junio has since reviewed the documentation, suggesting style adjustments to match the surrounding man page format and noting an edge case where unambiguous timestamps like '99999999' (which can't represent a valid date) still get rejected. While the style feedback will be incorporated, the parsing edge case remains unchanged for now as it falls outside this documentation-focused patch's scope. The thread demonstrates Git's attention to both clear documentation and precise timestamp handling, with the maintainer engaging on both presentation details and potential future improvements to the parsing logic.
