This thread documents a previously implicit behavior in Git's date parsing: the `@` prefix forces interpretation of a number as a raw Unix timestamp. The patch clarifies this in the documentation and adds test cases showing how `@2000` (a timestamp) differs from `2000` (which Git might try to parse as YYYYMMDD). 

Junio Hamano co-authored the patch, indicating maintainer approval of the clarification. The tests cover both exact parsing and the fallback to Git's fuzzy "approxidate" logic, making this a thorough documentation improvement. The change is cleanly focused, touching only the date format documentation and test files. This is a small but useful clarification of behavior that has existed in Git for years but wasn't properly documented until now.
