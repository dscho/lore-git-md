This is the second patch in a bugfix series addressing resource cleanup in HTTP pack index handling. The patch fixes a memory leak in `fetch_and_setup_pack_index()` where pack structures weren't being freed when index verification failed.

The change ensures proper cleanup by:
1. Always calling `close_pack_index()` to munmap the index file (which might have been mmapped during verification)
2. Freeing the pack structure itself when verification fails

This completes the series' goal of robust error handling in the HTTP transport layer's pack index fetching logic. The patch follows thorough review from Jeff King (Peff) across multiple iterations and represents the simpler solution that emerged from that discussion. With all identified issues now addressed and consensus achieved, this appears ready for merging.
