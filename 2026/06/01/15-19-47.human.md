This is the first patch in a GSoC participant's series to improve path handling in `git repo info`. It extracts path formatting logic from `rev-parse` into a new reusable `strbuf_add_path()` function in the path utilities.

The patch cleanly moves the existing path formatting code into `path.c` while:
- Adding proper enum types for path formatting options
- Preserving all the existing formatting behaviors (absolute, relative, canonical paths)
- Maintaining the same edge case handling (like shared prefixes)

The implementation looks solid - it's a straightforward refactoring that will enable consistent path handling across Git commands. The author has clearly studied the existing code and consulted with mentors (Justin Tobler and Lucas Seiki Oshiro are credited). 

This foundational change will be used by subsequent patches in the series to add relative/absolute variants to `git repo info` output. The patch itself is mechanical and low-risk, though reviewers may want to verify the enum naming and documentation since these will become a public API.
