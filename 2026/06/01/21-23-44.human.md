This is a follow-up discussion in the ongoing thread about deprecating the `git-init-db` command alias in favor of `git-init`. Kristoffer Haugsbakk provides additional context by searching the mailing list archives for real-world usage of `git-init-db`.

The key new information is that Kristoffer found only one recent mention of `git-init-db` in the archives - from last year - where it was used as a bug reproducer rather than in production scripts. This suggests the alias has largely fallen out of active use, though its presence in someone's muscle memory indicates some lingering familiarity.

Kristoffer weighs in on Phillip Wood's suggestion to add a runtime warning when the deprecated command is used. He notes that Git's standard `you_still_use_that()` function would be too aggressive (as it dies), but suggests a simple warning message would be helpful. His rationale is that any remaining uses are likely buried in old scripts where the failure might be confusing without clear messaging.

The discussion continues to converge on implementing both the `DEPRECATED` flag and a runtime warning, though Patrick Steinhardt had initially questioned whether the warning was necessary given how straightforward the replacement is. Kristoffer's input reinforces the case for including a warning to help users transition away from the deprecated alias.
