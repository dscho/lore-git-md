# Documentation patch suggesting a refinement to command deprecation

Kristoffer Haugsbakk responds to Patrick Steinhardt's patch deprecating `git-init-db` in favor of `git-init`. While agreeing with the overall direction, he suggests a small refinement: marking the deprecated alias with an explicit `DEPRECATED` flag in the command table rather than just conditionally compiling it out.

The suggestion is straightforward - adding this flag would make the deprecation status visible in the code even when the command remains available for backward compatibility. This follows the pattern used elsewhere in Git's codebase to clearly indicate deprecated functionality.

This is a surface-level review focused on a small implementation detail of an otherwise uncontroversial cleanup. The core proposal to deprecate `git-init-db` (which has been effectively replaced by `git-init` since 2007) remains sound, and Kristoffer's suggestion would simply make the deprecation more explicit in the code. The change would be trivial to incorporate if Patrick agrees with the approach.
