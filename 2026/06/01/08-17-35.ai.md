This is a performance optimization patch for Git's priority queue implementation, version 2 of Kristofer Karlsson's earlier proposal. The patch focuses on optimizing the `prio_queue_get()` operation while preserving René Scharfe's existing optimizations for `prio_queue_replace()`.

The key change replaces the standard sift-down algorithm in `prio_queue_get()` with a more efficient cascade-down approach. The new method:
1. Promotes the smaller child upward at each level (one comparison + one copy)
2. Lets the vacancy sink to a leaf
3. Places the last array element there with a potential sift-up

Benchmarks show significant improvements:
- 15-23% faster for ascending-key workloads (Git's common case)
- 1-4% faster for worst-case descending keys
- ~2% speedup in real-world `rev-list` operations on wide DAGs
- No regressions in any scenario

The v2 revision addresses Junio's feedback by:
1. Keeping `sift_down_root()` and `prio_queue_replace()` unchanged
2. Extracting the new logic into a separate `sift_up_rebalance()` function
3. Providing updated benchmark numbers across more scenarios

The optimization is particularly effective for wide commit graphs where priority queues grow deeper, as the per-level savings compound. The patch touches only 22 lines of code and is well-covered by existing tests, making it a low-risk performance win.
