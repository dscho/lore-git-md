This is a follow-up RFC proposal from Skybuck Flying (Harald Houppermans) expanding on their earlier ideas for modernizing Git's capabilities, now focusing specifically on repository provenance tracking through fork lineage metadata. The proposal introduces a `.gitorigin` file to complement the previously suggested `.git/identity` UUID system.

The technical core proposes storing parent repository UUIDs and last sync points to enable Git to:
- Reconstruct full fork ancestry chains
- Calculate divergence at each fork level
- Detect mirrors and migrated repositories
- Preserve lineage across host migrations and renames

Key implementation aspects include:
- Optional `.gitorigin` file containing `origin_uuid` and `last_synced` commit
- Works in conjunction with repository UUIDs for DAG construction
- Backward compatible as purely additive metadata
- Enables precise divergence calculations (e.g. "7 commits ahead of immediate parent, 8 behind origin")

The proposal provides concrete examples showing how this would solve current limitations in:
- Tracking multi-generation fork relationships
- Maintaining provenance when repositories move/rename
- Identifying mirror repositories
- Recovering lost fork history from clones

This builds on the thread's earlier discussion about Git's limitations for modern workflows, now drilling deeper into provenance tracking with more technical specification. The proposal remains at RFC stage with no implementation patches. The comprehensive nature suggests this could spark significant discussion about whether such metadata belongs in core Git versus higher-level tooling, and how it might interact with existing hosting provider fork systems.
