Patrick Steinhardt has completed his v4 series introducing `git history drop`, a new subcommand that removes a commit from history while replaying its descendants onto the commit's parent. This builds on the experimental `git history` command added earlier. The series went through significant preparatory refactoring of Git's reset machinery in earlier patches, modernizing the API and splitting reference updates into compute/apply phases.

The final patch adds the actual drop functionality with careful handling of edge cases: it prevents dropping root commits (which could leave references empty) and merge commits (not yet supported), while properly managing working tree and index updates when HEAD moves. The implementation includes extensive test coverage (537 lines across various scenarios) and documentation with usage examples. Key reviewers like Phillip Wood and Junio C Hamano have signed off on the technical approach, with all prior feedback addressed.

The changes not only add the new drop capability but also improve Git's reset infrastructure more broadly - the refactored reset API will benefit other commands like rebase and sequencer. The series appears ready for merging, though follow-up work is already identified for handling merge commits and consolidating test helpers. This represents another step in Patrick's ongoing effort to expand Git's history manipulation capabilities while modernizing underlying infrastructure.
