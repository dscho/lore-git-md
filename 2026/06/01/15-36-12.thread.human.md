Patrick Steinhardt’s `git history drop` series is now complete at version 7, with all review feedback addressed and the code ready for final consideration. The series introduces a new `git history drop` command that removes a commit from history and replays its descendants on its parent, while also modernizing Git’s reset API, advancing the removal of the `the_repository` global variable, and fixing a latent bug in the reset machinery.

The latest update exposes a shared helper function, `replay_result_queue_update()`, to eliminate code duplication between the replay and history code paths, as suggested by Christian Couder. This change is purely mechanical and doesn’t alter behavior. Earlier revisions addressed all substantive feedback: the reset API was fully modernized (renamed functions, converted flags to an enum, added an `oid_from` field for explicit reset origins, and introduced opt-in HEAD updates), dry-run support was added, and a bug that could corrupt the index when resetting with a dirty index was fixed. The series also refactored index helper functions to support arbitrary index operations and removed the `the_repository` macro from `reset.c`.

Key participants include Patrick Steinhardt, who implemented all changes; Junio C Hamano, who verified the dry-run fix; Phillip Wood, who reviewed the reset API modernization; Christian Couder, who approved the series after the code duplication was resolved; and René Scharfe, who reviewed the `the_repository` removal. The series is now fully reviewed and awaits final integration.
