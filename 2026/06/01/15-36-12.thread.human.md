Patrick Steinhardt's `git history drop` series, now at version 4, introduces a new subcommand that allows removing a commit from history while replaying its descendants—a powerful addition to the experimental `git history` command. The series builds on earlier work that added the `replay` subcommand, with this iteration focusing on reset API modernization, reference update splitting, and explicit HEAD update control. 

The implementation has received thorough review from multiple contributors. Phillip Wood verified the flag modernization changes and suggested an additional safety check, while Pablo Sabater and Kristoffer Haugsbakk contributed documentation and error message refinements. Junio C Hamano has now reviewed the reference update splitting that enables dry-run functionality, noting that while the NULL transaction approach for dry-run detection wasn't his first choice stylistically, he confirms it's a stable mechanism that's been in use since early 2026. His "Looking good" indicates this preparatory refactoring meets the project's standards.

With all core functionality implemented across ten patches and no outstanding technical concerns from reviewers, the series appears ready for merging. The remaining open questions—like future support for root/merge commit drops—are marked for follow-up work rather than blocking the current changes. This represents a significant step in evolving Git's history manipulation capabilities while maintaining the project's careful approach to introducing new features.
