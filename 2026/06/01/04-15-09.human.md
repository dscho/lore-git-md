This is a bugfix for subprocess handling in Git's filter mechanism. The patch addresses a case where Git would crash with a confusing "remote end hung up" error when a filter command containing spaces in its path fails to start. Instead, it now properly reports the initialization failure.

The issue occurs because Git's subprocess handshake was using `packet_read_line()` which calls `die()` on errors, rather than the gentler `packet_read_line_gently()` that returns an error code. This particularly affects Windows users where program paths often contain spaces (e.g., "C:/Program Files/..."), but can also trigger on POSIX systems with spaces in the path.

The fix changes the handshake protocol in `sub-process.c` to use the gentle version of packet reading throughout, and includes a new test case that verifies the improved error reporting when a filter command with spaces in its path is missing. The patch is well-contained with clear before/after examples showing the improved user experience.
