This is a bugfix series addressing resource cleanup in HTTP pack index handling, now in its third iteration. The two-patch series from Lorenzo Pegorari finalizes fixes for both a memory leak and tempfile management in `fetch_and_setup_pack_index()`, following thorough review from Jeff King (Peff).

The first patch removes redundant tempfile cleanup code that became unnecessary after commit 63aca3f7f1 made the tempfile subsystem handle process-exit cleanup. The second patch fixes the core memory leak by ensuring pack index resources are properly freed on verification failure paths. Both changes are narrowly focused on error handling in the HTTP transport layer's pack index fetching logic.

The series represents the culmination of multiple review iterations, with Jeff King having previously identified the tempfile inconsistency and evaluated alternative approaches. The current version adopts the simpler solution that properly separates three cleanup operations: closing the pack index (unmapping mmap'd regions), freeing the temporary filename, and releasing the pack structure. All technical concerns appear resolved, with consensus that this addresses the original issues without introducing new complexity.
