Bugfix for `git describe`'s `--exclude` and `--match` options when used with `--contains` and `--all`.

Jacob Keller fixes an issue where `git describe --contains --all` wasn't properly forwarding the `--match` and `--exclude` patterns to the underlying `git name-rev` command. The patterns were only being applied to tags, ignoring heads and remotes despite the documentation stating they should work in `--all` mode. The patch ensures the patterns are passed with the correct ref prefixes for all ref types when `--all` is used.

The fix is straightforward - it adds the missing pattern forwarding logic with appropriate ref prefixes. The patch includes new tests that verify the corrected behavior with various combinations of `--match` and `--exclude` patterns against tags, local branches, and remote branches. The tests demonstrate the patterns now properly filter refs as documented.

This appears to be a clean fix for a clear bug where the implementation didn't match the documented behavior. The test coverage is thorough, checking both positive and negative cases across different ref types. The patch maintains backward compatibility while fixing the inconsistency.
