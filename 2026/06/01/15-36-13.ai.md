This is the first patch in Patrick Steinhardt's 2-part series adding a `drop` subcommand to the experimental `git history` command. The patch refactors the reference update handling in builtin/history.c to split it into two distinct phases: computing pending updates and applying them.

The change is purely preparatory - it takes the existing `handle_reference_updates()` function and splits it into `compute_pending_ref_updates()` and `apply_pending_ref_updates()`, with the original function now just coordinating between them. This refactoring enables the upcoming `drop` subcommand (in patch 2) to perform these operations separately.

The patch touches only builtin/history.c and maintains all existing functionality while making the code more modular. The changes are mechanical and well-contained, with careful attention to error handling and memory management. This appears to be a straightforward refactoring with no behavioral changes, following the pattern of Patrick's work on the history command.
