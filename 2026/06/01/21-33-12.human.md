This is a performance optimization patch for `git stash -p` that has now received Junio Hamano's approval pending final review from stash users. The patch is version 2 and has addressed all previous feedback.

The optimization replaces an external `git read-tree HEAD` call with an in-process `unpack_trees()` operation when creating the temporary index for interactive stash selection. This preserves cached stat data and fsmonitor-valid bits for unchanged files, allowing fsmonitor to skip unnecessary refreshes. Performance improvements are dramatic - in a 206k file repository with one change, time to first prompt drops from 34.774s to 0.659s when fsmonitor is enabled.

The v2 patch adds a new performance test showing similar improvements (6.90s->0.55s without fsmonitor, 6.83s->0.28s with). It also maintains the original lenient error handling behavior via an unconditional `refresh_index()` call. The implementation is clean, touching only `builtin/stash.c` and adding the new test.

Junio notes the patch looks good but would like an additional review from someone who actively uses `stash -p` before merging. The change builds on fsmonitor optimizations by Paul Tarjan and aligns with similar optimizations in `git restore -p`. With all technical concerns addressed, this appears ready for inclusion pending that final review.
