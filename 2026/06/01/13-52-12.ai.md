This is the second patch in a bugfix series addressing resource cleanup in HTTP pack index handling, following thorough review from Jeff King (Peff). The patch specifically fixes a memory leak in `fetch_and_setup_pack_index()` where pack structures weren't being freed when index verification failed.

The change ensures proper cleanup by:
1. Always calling `close_pack_index()` to munmap the index file (which might have been mmapped during fetching or verification)
2. Freeing the temporary filename (`tmp_idx`)
3. Freeing the `new_pack` structure itself when verification fails

The patch represents the final piece of a multi-iteration effort to properly handle resource cleanup in HTTP pack index operations. It complements the first patch in the series (removing redundant tempfile cleanup) by addressing the remaining memory management issue. The solution cleanly separates the three cleanup operations while maintaining clear error paths.

Jeff King's earlier review identified both the tempfile inconsistency and this memory leak, and the current implementation reflects his feedback. With all technical concerns resolved and consensus achieved, this appears to be the final version ready for merging. The changes demonstrate Git's resource management best practices in the HTTP transport layer.
