[PATCH] Proposal: Mirror repositories as alternate submodule sources

Author: Benson Muite
Thread type: Feature proposal
Status: Initial proposal met with maintainer pushback on scope, now gaining real-world use case support
Core problem: Fetch operations can fail due to single-source timeouts/bandwidth limits, with Debian packaging identifying specific pain point for archived projects with submodules
Current direction: General repository-level mirror fallback functionality favored by Junio Hamano
New evidence: Simon Richter (Debian) confirms need for reliable mirroring of projects containing submodules, where current behavior breaks when external URLs or relative paths change
Subsystems affected: submodule.c, remote.c, fetch-pack.c (would expand to more if generalized)
Technical details: Original proposal suggested new submodule config syntax for alternate URLs; general solution might use existing alternates mechanism or new repository identity system
Open questions: Whether to pursue submodule-specific case (less likely given new input), exact configuration format for general solution, precedence rules, error handling, and how to maintain internal references when mirrored
Participant positions: Junio opposes submodule-specific implementation, favors repository-wide solution; Debian use case supports general approach while highlighting submodule-specific pain points
Key decision point: Author should now focus on general repository mirroring design, with submodule handling as a special case of the broader problem
Related work: Debian's current workaround using UUIDs and symlinks acknowledged as problematic but necessary interim solution
