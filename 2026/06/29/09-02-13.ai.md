This is a security-hardening patch series for Git’s reftable backend, now at v2 with 12 patches (up from 11 in v1). The series systematically addresses vulnerabilities in parsing corrupted reftable files, including out-of-bounds reads/writes, NULL pointer dereferences, and uninitialized memory usage. While these issues require local disk access to exploit (reftables are not transferred over the network), the fixes are comprehensive and proactive.

The v2 update introduces a new preparatory patch (patch 5/12) that adds a test helper function, `cl_reftable_write_block`, to reduce boilerplate in unit tests. This change responds to Christian Couder’s surface-level feedback on v1, which suggested improving test readability by encapsulating common setup logic. The helper is used in subsequent patches (6–10/12) to simplify test cases for block corruption scenarios.

Key technical details remain unchanged from v1: the series splits into two parts. The first two patches add fuzzing infrastructure (libFuzzer support in Meson and a new oss-fuzz target), while patches 3–12 implement fixes for specific vulnerabilities. Each fix is paired with a unit test in `t/unit-tests/`, and the fuzzer now runs for 2+ hours without surfacing new issues. The fixes touch internal reftable code (`reftable/basics.c`, `reftable/block.c`, `reftable/record.c`, `reftable/table.c`) and introduce no changes to public APIs or on-disk formats.

The series is part of the ongoing reftable backend effort led by Patrick Steinhardt and Karthik Nayak. The inclusion of fuzzing infrastructure suggests a long-term commitment to preventing regressions in this security-sensitive area. Given Patrick’s role as a primary reftable contributor and the thorough test coverage, this series appears well-prepared for review.
