This is the twelfth and final patch in Patrick Steinhardt’s v2 security-hardening series for Git’s reftable backend. It fixes a heap-buffer-overflow that occurs when a reftable file is truncated so that it contains a header but not a complete footer. The vulnerability allows an attacker with local disk access to trigger an out-of-bounds read when Git attempts to compute the table’s data section size by subtracting the footer size from the file size, potentially underflowing the result.

The fix adds a bounds check in `reftable_table_new()` to verify that the file is large enough to contain both the header and footer before performing the subtraction. If the check fails, the function returns `REFTABLE_FORMAT_ERROR` instead of proceeding. The patch includes a new unit test in `t/unit-tests/u-reftable-table.c` that constructs a truncated table (just large enough for the header but one byte short of the footer) and verifies that the error is correctly returned.

This patch completes the series’ goal of eliminating all known security issues in the reftable parser discovered by fuzzing. The fix is minimal, targeted, and follows the pattern established in earlier patches: replace a crash or undefined behavior with a graceful error return. The test coverage is thorough, leveraging the `cl_reftable_write_block` helper introduced in patch 5/12 to reduce boilerplate. No changes to public APIs or on-disk formats are introduced.

The series as a whole is now fully present and addresses all vulnerabilities identified by the fuzzer.
