This is the final patch in Patrick Steinhardt’s v2 security-hardening series for Git’s reftable backend. It fixes a heap-buffer-overflow that occurs when a reftable file is truncated so that it contains a header but not a complete footer. Without the fix, the code underflows when computing the table’s data section size, leading to an out-of-bounds read of the footer.

The patch adds a simple bounds check in `reftable_table_new()` to verify that the file is large enough to hold both header and footer before proceeding. If not, it returns `REFTABLE_FORMAT_ERROR`. The fix is paired with a new unit test in `t/unit-tests/u-reftable-table.c` that constructs a truncated table and verifies the error is caught.

This is a clean, well-contained fix for a real security issue discovered by fuzzing. The commit message includes a full ASan backtrace and explains the root cause clearly. The test is minimal but sufficient: it creates a buffer with a single ref record, truncates it to just below the footer size, and confirms the constructor fails with the expected error code. No changes to public APIs or on-disk formats are introduced.

The series as a whole is now complete and addresses all known vulnerabilities in the reftable parser. This patch is the last of the twelve and ties off the effort. Given Patrick’s role as the primary reftable contributor and the thorough fuzzing coverage, the series looks ready for serious review.
