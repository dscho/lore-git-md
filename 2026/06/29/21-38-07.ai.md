This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Junio C Hamano responds to Patrick Steinhardt’s proposal to convert `USE_NSEC` from a build-time option to a runtime-configurable setting (like `core.ignoreCase`). Junio acknowledges the mismatch between build-time granularity and runtime filesystem variability but pushes back on treating the two cases identically. While `core.ignoreCase` is mandatory for correctness on case-insensitive filesystems, `USE_NSEC` is optional even on capable systems—it improves performance but is not required for correctness. This distinction complicates Patrick’s proposal: if `USE_NSEC` is not strictly necessary, should it be auto-detected, user-configured, or left as a build-time knob for power users? The email does not resolve the debate but clarifies the trade-offs, leaving the thread open for further discussion about how (or whether) to implement runtime configuration.

Key technical details remain unchanged from earlier in the thread: the original patch adds a `nanosec` Meson option to mirror Autotools’ `USE_NSEC`, but the discussion now centers on whether the knob should exist at all. Junio’s response suggests that while runtime configuration is appealing, it may not be as clear-cut as Patrick’s analogy to `core.ignoreCase` implies. The thread still lacks consensus on whether to flip the default, deprecate the knob, or convert it to runtime control, and no new patches have been submitted to address these questions. The original patch remains queued for merging, but the broader debate about `USE_NSEC`’s future continues.
