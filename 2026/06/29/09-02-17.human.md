This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s ongoing effort to harden the code against corrupted files. Specifically, this is patch 4/12 in the v2 series, addressing a crash triggered by invalid ref value types.

The patch fixes a case where the reftable parser calls `abort()` when encountering an unrecognized ref value type. Since the data is untrusted (even though reftable files are local-only), treating this as a fatal programming error is overly aggressive. Instead, the patch makes the parser return a `REFTABLE_FORMAT_ERROR` and includes a new unit test in `t/unit-tests/u-reftable-record.c` to verify the behavior. The fix is minimal: it moves the assignment of `value_type` after the switch statement to avoid storing an invalid type, and replaces the `abort()` with an error return.
