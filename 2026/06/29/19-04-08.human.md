This is a short follow-up in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions. The series is part of Patrick Steinhardt’s broader ODB abstraction effort, and this specific patch (2/6) surfaces previously ignored errors in the "files" transaction backend—temporary directory creation, migration, and commit operations.

Justin clarifies a key point from Patrick’s review: the patch does *not* actually change behavior for existing callers, despite appearances. The old code silently ignored failures in temporary directory creation, and while the patch now propagates those errors, the callers (like `write_loose_object()`) still ignore them. This means the patch is a no-op for current users, preserving backward compatibility while laying groundwork for stricter error handling in the future. The v2 will keep this approach, avoiding a hard error for missing directories.

The exchange highlights a design tension: should the ODB transaction system enforce strict error handling (failing fast) or remain resilient to transient failures (silently falling back)? Justin’s response confirms the latter path for now, which aligns with the project’s conservative stance on behavioral changes. The patch itself is uncontroversial and well-motivated, but the discussion underscores a larger architectural question about error-handling philosophy in Git’s internals. No action is needed beyond the planned v2, which will focus on naming consistency and documentation tweaks.
