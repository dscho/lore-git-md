This is the sixth patch in Patrick Steinhardt’s v2 security-hardening series for Git’s reftable backend (12 patches total). It fixes a specific heap-buffer-overflow vulnerability in the log block parser that can be triggered by a maliciously corrupted reftable file.

The bug occurs when the inflated block size stored in the log block header is smaller than the header itself, causing an underflow when calculating the bytes to inflate. This leads zlib to write beyond the allocated buffer, as demonstrated by the AddressSanitizer trace included in the commit message. The fix adds a sanity check in `reftable/block.c` to ensure the block size covers at least the header and restart counter, returning `REFTABLE_FORMAT_ERROR` if not. The patch also introduces a new unit test in `t/unit-tests/u-reftable-block.c` that uses the `cl_reftable_write_block` helper (added in patch 5/12) to construct a corrupted log block and verify the error is caught.

This is a classic security hardening fix: it addresses a low-level parsing edge case with no user-visible behavior change, only preventing a crash. The commit message is thorough, including the ASan trace, reproduction steps, and a clear explanation of the underflow mechanism. The test coverage is strong, leveraging the helper function introduced earlier in the series to reduce boilerplate. Given the series’ overall goal of hardening the reftable backend against corrupted files, this patch fits neatly into the broader effort and appears well-prepared for review.
