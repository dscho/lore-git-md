This is Junio C Hamano’s **surface-level review** of the third patch in Harald Nordgren’s v6 `git history squash` series. The email focuses exclusively on **documentation and command-line interface (CLI) conventions**, not on the implementation or design.

Junio points out two violations of Git’s established CLI and documentation style:

1. **Option ordering in SYNOPSIS.** The existing `git history` subcommands incorrectly place dashed options (`--dry-run`, `--update-refs`, etc.) *after* the required argument (`<commit>`). The canonical Git style (documented in `gitcli(7)`) requires that all dashed options appear *before* any non-option arguments. Junio asks that the new `squash` subcommand not repeat this mistake and that the existing subcommands be corrected in a follow-up patch.

2. **Use of `@` shorthand in documentation.** The man page uses `@` (e.g., `@~3..`) instead of spelling out `HEAD`. Git’s documentation policy is to avoid cryptic shorthand in formal prose; `@` should only appear in the single place where it is explicitly introduced as a synonym for `HEAD`. Junio suggests rewriting the example as `HEAD~3..HEAD` and clarifying that this folds the three commits `HEAD~2`, `HEAD~1`, and `HEAD` into one commit on top of `HEAD~3`.

The review is **purely stylistic** and does not question the correctness or design of the patch. Junio’s tone is matter-of-fact and constructive; he even notes that the existing subcommands are already in violation, so the issue is not Harald’s fault. The requested changes are small, localized, and do not affect the code logic.
