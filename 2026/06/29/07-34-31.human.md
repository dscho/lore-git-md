This is part five of Patrick Steinhardt’s eleven-patch series implementing the `git history drop` subcommand. The patch introduces a dry-run mode to the `reset_working_tree()` function, allowing callers to check whether a reset would succeed without actually updating the index or working tree.

The change adds a new `RESET_WORKING_TREE_DRY_RUN` flag to the `reset_working_tree_flags` enum. When this flag is set, the function reads the index into a scratch copy, performs all the same validation and conflict checks as a real reset, but skips writing the index or updating any refs. The scratch index is discarded at the end, leaving the repository untouched. This is exactly what the upcoming `git history drop` command needs to verify that dropping a commit is safe before doing it for real.

The implementation is clean: it reuses the existing `unpack_trees()` machinery, setting the `dry_run` flag so that the merge logic runs but no files are written. The patch also handles the `refs_only` case correctly—when dry-run is active, it simply returns success without touching any refs. Error handling is preserved: if the index cannot be read, the function still reports the error.

This is a well-motivated, low-risk refactoring that directly supports the larger goal of the series. The commit message is clear, the code is straightforward, and the new flag is documented in the header. No controversy is expected.
