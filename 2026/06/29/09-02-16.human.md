This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s 12-patch v2 series addressing vulnerabilities in parsing corrupted reftable files. This specific patch (3/12) fixes an out-of-bounds read in the `binsearch()` function when called with an empty range (`sz == 0`).

The bug occurs because `binsearch()` attempts to call its comparison function with an index of 0 even when the search range is empty, leading to an invalid memory access. The fix is simple: return early if `sz` is zero. The patch includes a new unit test (`test_reftable_basics__binsearch_empty`) that verifies the function handles empty ranges correctly without invoking the comparison function.

Given the series’ broader goal of hardening the reftable backend against corrupted files, this patch fits neatly into the effort.
