This is the eighth patch in Patrick Steinhardt’s 11-patch `git history drop` series (v7). It fixes a latent bug in the reset machinery: the current `reset_working_tree()` function unconditionally skips updating the index’s cache tree, which is safe only when the incoming index is clean. The new `git history drop` command will call this function with a potentially dirty index, so the patch restricts the cache-tree skip to hard resets only. The change is minimal (5 insertions, 3 deletions in `reset.c`) and preserves the original performance optimization for the common case while fixing the edge case. The commit message clearly explains the motivation and the trade-off, and the patch itself is straightforward. This is a well-motivated bugfix that directly supports the larger series goal.
