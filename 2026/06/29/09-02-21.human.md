This is the eighth patch in Patrick Steinhardt’s v2 series hardening Git’s reftable backend against corrupted files. It fixes an out-of-bounds read vulnerability triggered by a maliciously crafted restart count in a reftable block.

The bug occurs when the restart count (stored in the last two bytes of a block) is large enough to cause an underflow when computing the restart table’s offset. This leads to reads outside the allocated memory, as demonstrated by the AddressSanitizer backtrace in the commit message. The fix adds a bounds check in `reftable_block_init()` to ensure the computed restart offset is valid before proceeding. If the offset is invalid, the function returns `REFTABLE_FORMAT_ERROR` instead of crashing.

The patch includes a new unit test in `t/unit-tests/u-reftable-block.c` that deliberately corrupts the restart count to verify the fix. The test uses the helper function `cl_reftable_write_block` introduced in patch 5/12 to reduce boilerplate. No changes to public APIs or on-disk formats are introduced.

This is a well-motivated security fix with clear test coverage. The commit message provides a detailed explanation of the vulnerability and the fix, including a reproduction case. Given the series’ focus on hardening the reftable backend and the proactive fuzzing infrastructure already in place, this patch looks like a straightforward improvement.
