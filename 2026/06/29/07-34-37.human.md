This is the final patch in Patrick Steinhardt’s 11-patch series implementing the `git history drop` subcommand. It adds the actual `drop` command to the experimental `git history` tool, allowing users to remove a commit from history and replay its descendants on top of its parent.

The patch is substantial: it introduces the new subcommand, updates the documentation with usage examples and limitations, and adds 537 lines of thorough test coverage. The implementation handles edge cases like bare repositories, detached HEAD, root commits (which are currently refused), merge commits (also refused), and conflicts during replay. It also respects the `--dry-run` flag, preserves unrelated staged and unstaged changes, and aborts cleanly if local modifications would be overwritten.

The command builds on the reset API modernization and ref-update phase separation introduced earlier in the series, so it benefits from the dry-run support, explicit HEAD-update control, and two-phase ref-update design. The test suite exercises all the documented behavior, including the `--empty` flag’s handling of descendants that become empty after the drop.

This is a well-crafted, complete feature addition with clear documentation and comprehensive tests. The series as a whole has addressed all substantive review feedback, and this final patch ties everything together.
