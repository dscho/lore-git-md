This is the seventh patch in Patrick Steinhardt’s 11-patch v7 series implementing the `git history drop` subcommand. The series is now complete and ready for final review, with all substantive feedback addressed.

This patch adds a new `oid_from` field to the `reset_working_tree_options` struct, allowing callers to specify the commit from which the reset should start. Previously, `reset_working_tree()` always derived this from HEAD, which was inflexible for callers like `git history drop` that already have the commit resolved or need to reset from a different commit. The change is minimal—just nine lines—and maintains backward compatibility by defaulting to HEAD when `oid_from` is not set.

The patch is well-motivated and directly supports the series’ goal of enabling `git history drop` to replay descendants after removing a commit. It also aligns with the broader reset API modernization effort in this series, which has already renamed the function, converted flags to an enum, and made HEAD updates opt-in. The implementation is clean and doesn’t introduce edge cases or behavioral changes for existing callers.

This is a small but necessary piece of the larger reset machinery refactoring. If the series as a whole is deemed ready, this patch should merge without controversy.
