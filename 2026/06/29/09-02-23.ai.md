This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s ongoing series to harden the code against maliciously corrupted files. This is the tenth patch in the v2 series (12 patches total), addressing an out-of-bounds read vulnerability triggered by a bogus restart offset in reftable blocks.

The issue occurs when a restart offset—stored in the restart table at the end of a block—points outside the valid record area, causing `get_var_int()` to read invalid memory during binary search. The fix adds a bounds check in `restart_needle_less()` (in `reftable/block.c`) to ensure the offset is within the record section, returning `REFTABLE_FORMAT_ERROR` if not. The patch includes a new unit test (`test_reftable_block__corrupt_restart_offset` in `t/unit-tests/u-reftable-block.c`) that corrupts the restart offset to trigger the error path, verifying graceful failure.

This patch builds on earlier fixes in the series (patches 6–9/12) that address related vulnerabilities in block parsing, such as heap-buffer-overflows and uninitialized memory usage. Like those, it uses the `cl_reftable_write_block` helper introduced in patch 5/12 to simplify test setup. The fix is minimal and targeted, touching only the validation logic without altering core parsing behavior or public APIs.

The vulnerability requires local disk access to exploit (reftable files are not transferred over the network), but the hardening is proactive and aligns with the series’ goal of comprehensive security coverage. The patch is well-motivated, with a clear commit message, ASan output, and test coverage. No objections or review feedback have been raised yet, and the series as a whole appears technically sound. This patch is unlikely to be controversial and should integrate smoothly into the ongoing reftable effort.
