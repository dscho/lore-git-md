This is a small but user-visible polish patch in the final `git history squash` series (v6). The series itself is complete, well-tested, and ready for merging; this email is about a cosmetic improvement to the `--reedit-message` feature.

Junio points out that the squash commit-message template currently omits the numbered markers (`# This is the 1st commit message`) that `git rebase -i` inserts between folded-in commit messages. Without these markers, the editor buffer is harder to read and edit. Harald agrees the markers would be a nice consistency improvement and is open to extracting the logic from `rebase -i`. Junio endorses the idea, suggesting that code sharing (even if cleaned up) would be beneficial.

The change is trivial and affects only the editor template’s appearance, not the resulting commit message or any other behavior. No design or technical work remains; this is purely a follow-up opportunity to improve usability. The series as a whole is code-complete and addresses all prior feedback, including input validation, merge commit handling, ref-handling, and CLI style.
