This is the third patch in Patrick Steinhardt’s six-part ODB refactoring series, which restructures `struct object_info` to better support multi-source object resolution. The patch adds a `source` field to the new `struct object_info_source`, allowing callers to identify which backend (loose, packed, or in-memory) an object came from. The change is mechanical—each backend now populates this field during object lookup—but does not yet change behavior, as the old `whence` enum remains in use until patch 5/6 removes it.

Justin Tobler’s review is substantive but narrowly scoped. He approves the implementation ("Looks good") and raises a thoughtful architectural question: since `struct packed_git` is always associated with an ODB source at initialization, could the source be recorded there instead of being passed as an optional parameter to `packed_object_info_with_index_pos()`? This echoes his earlier feedback on patch 1/6 about the design’s trade-offs, though he does not propose an alternative or object to the current approach. The question remains open for discussion but does not block progress.

The patch itself is small (13 lines added across four files) and uncontroversial. It prepares the groundwork for later patches that will eliminate the `whence` field entirely, a key step toward pluggable ODB backends. If the series continues to receive positive feedback, this patch is likely to merge as-is, with any architectural refinements deferred to follow-up work. For now, it’s a well-executed incremental change in a larger, well-motivated effort.
