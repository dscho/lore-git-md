This is a bug report with a reproduction script for a hang in `git receive-pack`. The issue occurs specifically when pushing a zero-object ref update into a repository configured as a promisor remote (with `.promisor` sidecar files present). The hang does not manifest in non-promisor repositories or if either the promisor remote configuration or the `.promisor` files are removed.

The report includes a clear reproduction script and details the environment (Git 2.54.0 on Ubuntu 24.04). The author notes the hang is reproducible and provides the minimal conditions to trigger it: a promisor-shaped repository receiving a zero-object push. No prior discussion or thread context is referenced, so this appears to be a new report.

The bug touches the promisor remote subsystem and the `receive-pack` command, which handles incoming pushes. The reproduction script is likely to be valuable for debugging, as it isolates the issue to a specific configuration. The report does not speculate on the root cause, but the hang suggests a potential infinite loop or deadlock in the promisor object resolution logic when no objects are actually being transferred.
