This is a security-hardening patch for Git’s reftable backend, part of Patrick Steinhardt’s v2 series (patch 4/12). It addresses a crash triggered by maliciously corrupted reftable files: when decoding a ref record with an invalid value type, the code previously called `abort()`, treating the issue as a programming error. The fix replaces the `abort()` with a graceful error return (`REFTABLE_FORMAT_ERROR`), ensuring the parser fails safely on untrusted input. The patch also defers setting the record’s `value_type` until after validation to avoid storing invalid values.

The change is minimal and targeted: it modifies `reftable/record.c` to handle invalid value types as format errors rather than fatal errors, and adds a new unit test in `t/unit-tests/u-reftable-record.c` to verify the behavior. The test constructs a corrupted ref record with an out-of-bounds value type (`REFTABLE_NR_REF_VALUETYPES`) and confirms the decoder returns `REFTABLE_FORMAT_ERROR`. No public APIs or on-disk formats are altered, and the fix aligns with the series’ broader goal of hardening the reftable parser against corrupted files.

This patch is one of several in the series that address vulnerabilities discovered via fuzzing (libFuzzer).
