This is a new bug report describing a hang in `git receive-pack` when pushing a zero-object ref update into a repository configured as a promisor remote. The issue is reproducible on Git 2.54.0 (Ubuntu 24.04) and occurs only when both the promisor remote configuration and `.promisor` sidecar files are present—removing either condition prevents the hang.

The report includes a clear reproduction script that isolates the problem to this specific edge case, making it easier for developers to debug. The hang likely stems from an infinite loop or deadlock in the promisor object resolution logic when no objects are being transferred, though the root cause isn’t yet identified. This affects the promisor remote subsystem and `receive-pack`, which handles incoming pushes.

No prior discussion or patches have been linked to this issue, so it appears to be a newly discovered problem. If you work on promisor remotes or `receive-pack`, this is worth investigating promptly.
