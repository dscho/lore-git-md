This is a **CI/build system** follow-up to the ongoing effort to stabilize macOS CI hangs in the `t5551` and `t5559` tests. Junio C Hamano responds to Patrick Steinhardt’s proposal to enable `GIT_TEST_LONG` for GitLab CI on pull-request events, endorsing the general goal of cross-platform test coverage but raising a strategic question: if CI resources are constrained, should GitLab prioritize running the same long tests as GitHub, or should it focus on *additional* tests or events not already covered by GitHub?

The email does not reject the patch or propose an alternative implementation. Instead, it invites discussion about how to best allocate CI resources across platforms. Junio notes that GitHub already enables `GIT_TEST_LONG` for pull requests to any branch and for pushes to integration branches (`next`, `master`, `main`, `maint`). If there are other branches or events (e.g., scheduled runs, tag pushes) that GitHub does not cover, GitLab could fill those gaps rather than duplicating GitHub’s coverage. This is a policy question, not a technical one: the patch itself is straightforward and correct, but its scope may need to be reconsidered in light of broader CI strategy.

The thread remains open. The next step is likely a reply from Patrick or another participant clarifying whether GitLab CI has capacity to run additional tests, or whether the current patch (which aligns GitLab with GitHub’s behavior) is the most practical way forward. Until that discussion concludes, the series is not yet ready to merge.
