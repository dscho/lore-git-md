This is a bugfix for a subtle regression in `git merge-base` that only affects repositories with v1 commit graphs (those without corrected commit dates). The issue was introduced in April 2025 and causes incorrect merge base results when clock skew exists in the commit history. The series adds a test case demonstrating the bug and fixes it by ensuring the early exit optimization only triggers when commits are processed in generation order. The fix is narrowly targeted and well-explained, with clear reproduction steps in the test. Given that v1 commit graphs are rare today (v2 has been default since 2021), this is a low-risk correction for an edge case that could otherwise produce confusing results. The patch looks ready for review.
