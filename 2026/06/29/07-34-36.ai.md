This is the tenth patch in Patrick Steinhardt’s 11-patch v7 series implementing the `git history drop` subcommand. It refactors the reference-update logic in `builtin/history.c` to separate the *analysis* phase (determining which refs need updating) from the *execution* phase (applying those updates). The original `handle_reference_updates()` function is split into two new functions: `compute_pending_ref_updates()` (which gathers refs to update) and `apply_pending_ref_updates()` (which commits the transaction). This two-phase design prepares the codebase for future changes—likely the next patch in the series—where the execution phase may need to be deferred or conditional.

The patch touches only `builtin/history.c` and is purely a refactoring: no behavior changes are introduced. The new `compute_pending_ref_updates()` function populates a `replay_result` struct with the refs that need updating, while `apply_pending_ref_updates()` takes that struct and applies the changes via a ref transaction. The original `handle_reference_updates()` is retained as a thin wrapper for backward compatibility. The split is clean and well-motivated by the series’ goal of enabling `git history drop` to handle ref updates in a more flexible way, such as supporting dry-run mode or deferring updates until conflicts are resolved.

This refactoring is a necessary step toward the final patch in the series, which implements the actual `drop` subcommand.
