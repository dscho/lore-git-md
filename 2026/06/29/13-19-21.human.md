This is the second patch in a two-patch bugfix series for the commit-reach subsystem. It addresses a clock-skew regression in `git merge-base` (without `--all`) introduced by commit 93e5b1680e (April 2025). The issue occurs when a repository uses a v1 commit-graph (no corrected commit dates), has clock skew in its topology, and the correct merge base has a lower committer date than one of its ancestors.

The fix is small and targeted: it adds a `gen_ordered` flag that tracks whether the queue is generation-ordered, and gates the early-exit optimization in `paint_down_to_common()` on this flag. When the code falls back to commit-date ordering (for v1 commit graphs), the flag is cleared, preventing the premature exit. The patch also updates the test added in the first patch to `test_expect_success` now that the fix is in place.

The change is well-motivated and clearly explained in the commit message, which explicitly lists the trigger conditions and scope of the problem. The fix itself is minimal (ten lines changed in `commit-reach.c`) and the test coverage is thorough. This looks like a clean, low-risk fix for a real bug, and the series appears ready for merging. No review feedback or objections have been raised so far.
