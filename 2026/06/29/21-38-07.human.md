This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Junio C Hamano responds to Patrick Steinhardt’s proposal to convert the `USE_NSEC` build-time option into a runtime-configurable setting (like `core.ignoreCase`). Junio acknowledges the appeal of runtime flexibility but highlights a key difference: `core.ignoreCase` is mandatory for correctness on case-insensitive filesystems, whereas `USE_NSEC` is purely an optimization that can be safely disabled even on capable systems. This distinction suggests that while runtime configuration is a reasonable direction, the urgency and trade-offs differ from `core.ignoreCase`.

The email does not resolve the debate but clarifies the technical constraints. Junio’s observation implies that a runtime knob (e.g., `core.useNsec`) could coexist with a build-time default, allowing distributors to ship Git with nanosecond resolution enabled by default while still permitting user overrides. This aligns with Brian M. Carlson’s earlier proposal to flip the default to `true` for most users, with a config knob for edge cases. The thread remains open, with no consensus yet on whether to proceed with runtime configuration, auto-detection, or a simpler default flip. The original Meson parity patch is still queued for merging, but the discussion now centers on the broader design question of how to handle filesystem-specific optimizations.
