This is the eighth patch in Patrick Steinhardt’s 11-patch v7 series implementing the `git history drop` subcommand. It fixes a long-standing assumption in the reset machinery that the index is clean before `reset_working_tree()` is called. The issue surfaced because `git history drop` can invoke the reset machinery with a dirty index, breaking the current optimization that skips cache-tree updates.

The patch restricts the `skip_cache_tree_update` optimization to hard resets only, where the index is guaranteed to be clean afterward. For non-hard resets, the cache tree is recomputed as needed. The commit message notes that the performance impact is negligible, so the change is straightforward and safe. This adjustment ensures that `git history drop` works correctly without introducing complex logic to track index dirtiness.

The change is minimal—just a few lines in `reset.c`—and well-motivated. It directly addresses a real problem that would otherwise break the new `drop` subcommand, and the reasoning is clear: the original optimization was always a micro-optimization, and restricting it to hard resets is a clean way to preserve correctness. No controversy is expected here.
