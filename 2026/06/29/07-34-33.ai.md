This is the seventh patch in Patrick Steinhardt’s 11-patch v7 series implementing `git history drop`. It modernizes the reset API by adding an `oid_from` field to `struct reset_working_tree_options`, allowing callers to explicitly specify the commit from which to reset rather than defaulting to HEAD. The change is small (9 lines) and touches only `reset.c` and `reset.h`.

The patch directly addresses a limitation in the reset machinery: previously, `reset_working_tree()` always derived the "from" commit by reading HEAD, which was inflexible for callers like `git history drop` that need to reset from a different commit (e.g., the parent of the dropped commit). The new `oid_from` field lets callers pass this commit explicitly, while maintaining backward compatibility—if `oid_from` is NULL, the function falls back to reading HEAD as before.

This is a refactoring patch that prepares the reset API for the `git history drop` command (introduced later in the series) but does not change behavior on its own.
