This thread is about a two-patch series that fixes a clock-skew regression in `git merge-base` (without `--all`), introduced in April 2025. The bug occurs when a repository uses a v1 commit-graph, has clock skew in its commit topology, and the correct merge base has a lower committer date than one of its ancestors. The fix gates an early-exit optimization in `paint_down_to_common()` on whether the queue is generation-ordered, ensuring correctness when commit-date ordering is used as a fallback.

The series has been agreed to address a real problem, and the maintainer, Junio C Hamano, has now accepted Kristoffer Karlsson’s proposal to merge the bugfix as-is for the upcoming 2.55 release. This decision resolves the earlier integration question about how to handle the in-flight `kk/merge-base-exhaustion` topic, which will now be rebased on top of the fix. The timing is tight, given the proximity to the release finalization, but the procedural path forward is now clear.

The patches touch `commit-reach.c` and add a regression test in `t6600-test-reach.sh`. The test, which was initially marked as `test_expect_failure`, now passes with the fix. While the integration question is settled, Junio has requested a second review of the patches, so the technical content remains open for scrutiny. No new arguments or code changes have been introduced at this stage.
