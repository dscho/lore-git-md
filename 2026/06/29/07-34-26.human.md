This is the seventh iteration of Patrick Steinhardt’s 11-patch series adding a `git history drop` subcommand to the experimental `git history` command. The series is now complete: it implements the core functionality, modernizes the reset API, removes reliance on `the_repository`, and—most importantly—eliminates the code duplication that was the last blocker in v6.

The new subcommand lets users remove a commit from history and replay its descendants on top of its parent. The implementation touches a dozen files, but the key changes are in `builtin/history.c` (the new drop logic), `reset.c` (API modernization), and `replay.c` (shared ref-update helper). The series also adds 537 lines of new tests covering edge cases like dry-run mode, bare repositories, and conflict detection.

All review feedback from v6 has been addressed. The most significant change is the extraction of `replay_result_queue_update()` into a shared helper, which resolves Christian Couder’s maintainability concern. The reset machinery has been modernized with clearer flag names (`RESET_WORKING_TREE_*`), a new `UPDATE_HEAD` flag, and a rename from `reset_head()` to `reset_working_tree()`. The series also fixes a subtle bug where `skip_cache_tree_update` was incorrectly applied during non-hard resets.

This looks like a solid, well-tested addition to the history command. The commit messages are detailed, the test coverage is thorough, and the API changes are forward-looking. Given Patrick’s track record and the careful iteration, this series is likely to be uncontroversial. The only remaining loose end is a low-weight forward-compatibility note about `is_bare_repository()`, but that’s not blocking.
