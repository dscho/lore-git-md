This is the sixth patch in Patrick Steinhardt’s 11-patch v7 series implementing the `git history drop` subcommand. The patch modernizes Git’s reset machinery by introducing explicit control over whether HEAD is updated during a working-tree reset.

The change adds a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to the `reset_working_tree_flags` enum, shifting from an implicit “always update HEAD” model to an opt-in approach. All existing callers in `builtin/rebase.c` and `sequencer.c` are updated to set the flag, preserving their current behavior. The patch also enforces a safety invariant: if `RESET_WORKING_TREE_UPDATE_ORIG_HEAD` is set, `RESET_WORKING_TREE_UPDATE_HEAD` must also be set, preventing nonsensical ORIG_HEAD updates without a corresponding HEAD update.

This is a refactoring patch that prepares the reset API for the upcoming `git history drop` command, which will need to update the index and working tree without touching any references.
