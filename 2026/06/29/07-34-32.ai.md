This is the sixth patch in Patrick Steinhardt’s 11-patch `git history drop` series (v7). It introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to the reset machinery, allowing callers to explicitly opt in to updating HEAD. The patch updates all existing callers in `builtin/rebase.c` and `sequencer.c` to set this flag, ensuring backward compatibility while enabling future use cases that only want to update the index and working tree.

The change is part of the broader reset-API modernization effort in this series, which includes renaming `reset_head()` to `reset_working_tree()`, converting flags to an enum, and adding a new `oid_from` field. This specific patch addresses Phillip Wood’s suggestion to make HEAD updates opt-in rather than opt-out, resolving an inconsistency with the existing `UPDATE_ORIG_HEAD` flag. The implementation adds a BUG() check to prevent updating ORIG_HEAD without also updating HEAD, and it updates the `refs_only` logic to respect the new flag.

The patch touches four files (`builtin/rebase.c`, `reset.c`, `reset.h`, and `sequencer.c`) and shifts the `RESET_WORKING_TREE_UPDATE_ORIG_HEAD` and `RESET_WORKING_TREE_DRY_RUN` flags to higher bit positions to accommodate the new flag. The commit message clearly explains the rationale and the awkwardness of the previous opt-out approach, making this a well-motivated and technically sound change. This is a refactoring patch that prepares the reset machinery for the upcoming `git history drop` command, which will need to update the index and working tree without touching HEAD.
