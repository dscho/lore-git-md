This is the maintainer’s review of the third patch in Harald Nordgren’s **v6 series** implementing `` `git history squash` ``, a new subcommand that folds a commit range into its oldest commit. The series is now feature-complete and ready for final assessment.

Junio’s feedback is **surface-level** but important: he points out two documentation style issues that should be fixed before the patch lands. First, the synopsis in the man page violates the project’s command-line argument ordering convention (dashed options should come before positional arguments). Second, the documentation uses the cryptic `@` shorthand for `HEAD` instead of spelling it out, which can confuse readers unfamiliar with Git’s reflog notation. Neither issue affects functionality, but both are easy to correct and align with long-standing project conventions.

The rest of the review is positive. Junio confirms that the range notation (`HEAD~3..HEAD`) is clear and correctly describes the behavior: the three commits `HEAD~2`, `HEAD~1`, and `HEAD` are squashed into a single commit on top of `HEAD~3`, preserving the tree of `HEAD`. This matches the design that has been stable since v4 and addresses all prior technical concerns about range resolution, merge commit handling, and ref safety.

No substantive objections or design questions remain. The series is on track for merging once the documentation nits are fixed.
