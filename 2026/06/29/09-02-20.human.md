This is the seventh patch in Patrick Steinhardt’s v2 twelve-patch series hardening Git’s reftable backend against maliciously corrupted files. It fixes an out-of-bounds read that occurs when a block header claims a size larger than the actual data available. The bug surfaces when computing the restart-table offset or reading the restart count, both of which are derived from the untrusted block size. The fix adds a simple bounds check in `reftable/block.c` that returns `REFTABLE_FORMAT_ERROR` if the claimed size exceeds the buffer length, and the patch includes a new unit test in `t/unit-tests/u-reftable-block.c` that deliberately corrupts the block-size field to verify the error is caught. The test uses the helper function `cl_reftable_write_block` introduced in patch 5/12, keeping the test code concise. No user-visible behavior changes; this is purely a hardening measure.
