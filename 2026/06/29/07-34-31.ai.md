This is the fifth patch in Patrick Steinhardt’s 11-patch v7 series implementing `git history drop`. It introduces a dry-run mode to the modernized `reset_working_tree()` function, enabling callers to check whether a reset would succeed without modifying the working tree or index.

The patch adds a new `RESET_WORKING_TREE_DRY_RUN` flag to the `reset_working_tree_flags` enum. When set, the function uses a scratch index instead of the repository’s real index, skips writing the lockfile, and configures `unpack_trees_options` to avoid updates (`update = 0`, `dry_run = 1`). This allows the caller to safely test whether a reset would succeed, including conflict detection and index state validation, without leaving any persistent changes.

The implementation is clean and well-contained: it adds a scratch index (`struct index_state scratch_index`), conditionally initializes it, and ensures proper cleanup with `release_index()`. The dry-run path reuses the same unpack-trees logic as the real reset, differing only in whether updates are applied. This consistency minimizes the risk of behavioral divergence between dry-run and actual operation.

This patch directly supports the upcoming `git history drop` command, which needs to verify whether dropping a commit would succeed before proceeding. The dry-run mode is also a general improvement to the reset API, making it more flexible for future callers.
