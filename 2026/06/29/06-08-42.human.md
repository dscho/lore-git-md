This is a **build system** and **platform compatibility** follow-up in the ongoing `USE_NSEC` discussion. Patrick Steinhardt responds to Jeff King’s testing results by questioning whether `USE_NSEC` should remain a build-time option at all. His argument is straightforward: if the knob works reliably on some filesystems but not others, a build-time setting is too blunt an instrument for distributions to use safely. Instead, he suggests treating it like `core.ignoreCase` — a runtime configuration that users (or `git init`) could enable when appropriate, ideally with auto-detection for filesystem compatibility.

The email advances the thread beyond the original Meson parity patch and Jeff’s testing: it shifts the focus from "does `USE_NSEC` still break?" to "how should we control it?" Patrick’s proposal — unconditional nanosecond support with a runtime override — is a middle ground between Brian M. Carlson’s default-flip idea and Patrick’s earlier skepticism about the knob’s value. It acknowledges Jeff’s findings (nanoseconds are safe on modern Linux) while addressing the interoperability and edge-case concerns that still linger. No patch has been submitted yet, but this sets the stage for a future design: runtime detection, auto-configuration, and possibly deprecating the build-time option entirely. For now, the original Meson patch remains queued, but the discussion has clearly moved on.
