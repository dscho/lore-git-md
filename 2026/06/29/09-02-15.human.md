This is the second patch in Patrick Steinhardt’s 12-patch v2 series hardening Git’s reftable backend against maliciously corrupted files. It adds a new fuzzer (`oss-fuzz/fuzz-reftable.c`) that exercises the reftable parser by feeding it arbitrary byte sequences, covering the three main entry points: ref, log, and raw block iterators.

The fuzzer is minimal but effective: it wraps the input data in a `reftable_block_source`, initializes a `reftable_table`, and then iterates over refs, logs, and raw blocks. This setup mirrors how Git would parse a reftable file in production, making it a realistic target for finding parsing vulnerabilities. The patch also updates the build system (Makefile, Meson) and CI configuration (`ci/run-build-and-minimal-fuzzers.sh`) to include the new fuzzer, ensuring it runs in every pipeline.

This is a foundational piece of the series. The fuzzer itself does not fix any bugs—those come in later patches—but it is the tool that uncovered the vulnerabilities being addressed.
