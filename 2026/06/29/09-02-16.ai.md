This is the third patch in Patrick Steinhardt’s v2 twelve-patch series hardening Git’s reftable backend against corrupted files. It fixes an out-of-bounds read in the generic `binsearch()` helper when called with an empty range (`sz == 0`). The patch adds a three-line guard clause in `reftable/basics.c` and a new unit test in `t/unit-tests/u-reftable-basics.c` that verifies the comparison function is never called for an empty range. The fix is minimal, targeted, and accompanied by a clear test case; no changes to public APIs or on-disk formats are introduced. Given the series’ overall goal of eliminating low-level vulnerabilities in reftable parsing, this patch is a straightforward and necessary part of the hardening effort.
