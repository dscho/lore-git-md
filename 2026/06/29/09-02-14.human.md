This is the first patch in Patrick Steinhardt’s v2 security-hardening series for Git’s reftable backend. It adds Meson build support for libFuzzer, enabling coverage-guided fuzzing of Git’s codebase.

The patch introduces a new Meson build option, `-Dfuzzers_link_args=`, which allows users to pass linker arguments (e.g., `-fsanitize=fuzzer`) specifically for fuzzing executables. This complements the existing `-Db_sanitize=` option, which already supports enabling sanitizers like "address" and "fuzzer-no-link" for coverage feedback. The documentation in `meson.build` now includes a clear example of how to set up libFuzzer, making it easier for contributors to start fuzzing Git’s code.

The change is minimal and focused: it modifies `meson.build` to add documentation, `meson_options.txt` to define the new option, and `oss-fuzz/meson.build` to apply the linker arguments to fuzzing targets. No existing functionality is altered, and the patch is purely additive. This infrastructure is a prerequisite for the reftable fuzzer introduced in the next patch, which will use libFuzzer to systematically test the reftable parser for security vulnerabilities.

Given Patrick’s track record and the straightforward nature of the change, this patch looks well-prepared. It’s part of a larger security effort, and the fuzzing infrastructure it enables will help prevent regressions in the reftable backend. No objections or concerns have been raised so far.
