This is a **CI/build system** follow-up to Jeff King’s patch series fixing macOS CI hangs in the `t5551` and `t5559` tests. Patrick Steinhardt notes that GitLab’s CI avoids these failures only because it disables `GIT_TEST_LONG` for all platforms except GitHub. He proposes a small patch to `ci/lib.sh` that would enable expensive tests on GitLab for the same integration branches (`next`, `master`, `main`, `maint`) and pull-request events that GitHub already covers.

The patch maps GitLab’s event types (`merge_request_event`, `push`) to a common `CI_EVENT` variable, then uses that variable in the existing logic that turns on `GIT_TEST_LONG`. This is a straightforward alignment of behavior between the two CI systems. The change is low-risk: it only affects test coverage, not production code, and the logic is already proven on GitHub. If merged, it would expose the same Apache timeout issue on GitLab’s macOS runners, but the root cause is already addressed by Peff’s timeout increase in the main series.

The proposal is well-timed: the main series is ready to merge, and this patch would ensure both CI systems benefit from the fix. There is no controversy here; it is a simple matter of consistency.
