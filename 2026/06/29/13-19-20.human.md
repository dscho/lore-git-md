This is the first patch in a two-patch bugfix series targeting a clock-skew regression in `git merge-base`. The series addresses a bug introduced in April 2025 where `git merge-base` (without `--all`) can return the wrong merge base under specific conditions: a v1 commit-graph (no corrected commit dates), clock skew in the commit topology, and the correct merge base having a lower committer date than one of its ancestors.

This patch adds a regression test in `t6600-test-reach.sh` that constructs a carefully designed commit topology to expose the bug. The test creates a scenario where the correct merge base (`M2`) is overlooked because its ancestor (`M1`) has a higher committer date due to clock skew. When the commit-graph lacks corrected commit dates, the algorithm falls back to commit-date ordering, causing `M1` to be processed first and triggering an early exit before `M2` is considered. The test is marked as `test_expect_failure` to document the bug, with the fix coming in the next patch.
