This is the second patch in Justin Tobler’s six-patch series converting `git receive-pack` to use ODB transactions instead of `tmp_objdir`. The series is part of Patrick Steinhardt’s broader ODB abstraction effort, and this patch specifically addresses error handling in the "files" transaction backend.

The patch changes the `odb_transaction_files_{prepare,begin,commit}()` functions to return error codes instead of silently ignoring failures. Previously, errors like temporary directory creation or migration failures were ignored, which could lead to silent corruption. The new behavior surfaces these errors to callers, making the transaction system more robust. Justin acknowledges that some existing callers may expect the old behavior (where a missing temp directory was handled transparently) and plans to restore that resilience in the next version.

Patrick Steinhardt’s review identified several cases where the old code "YOLOed" it—ignoring critical errors that could corrupt data. His feedback is substantive and constructive, focusing on correctness and long-term maintainability. The discussion also touches on architectural questions, such as why the transaction functions remain in `object-file.c` instead of `odb/source-files.c` (a cleanup planned for a future series) and the ODB transaction system’s single-transaction-per-ODB limitation, which differs from reference transactions’ multi-transaction design.

The patch is well-motivated and technically sound, but a v2 is needed to address the feedback. The changes are internal and won’t affect user-facing behavior, but they lay groundwork for backend-agnostic object writes. The series is now queued for `next` pending the update. If you’re following the ODB abstraction effort, this is a key step toward making Git’s object storage more modular.
