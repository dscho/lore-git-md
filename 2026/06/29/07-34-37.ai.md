This is the final patch in Patrick Steinhardt’s 11-patch v7 series implementing the `git history drop` subcommand. It adds the actual `drop` command to the experimental `git history` built-in, enabling users to remove a commit from history and replay its descendants on top of its parent.

The patch introduces the new subcommand with full functionality: it prevents dropping root or merge commits, handles conflicts, supports dry-run mode, preserves unrelated staged and unstaged changes, and updates the index and working tree when HEAD moves. The implementation reuses the ref-update and replay machinery introduced in earlier patches, including the two-phase reference update design (`compute_pending_ref_updates` / `apply_pending_ref_updates`) and the modernized reset API (`reset_working_tree`). A new helper, `update_worktree()`, encapsulates the dry-run and actual worktree updates, while `find_head_tree_change()` detects whether HEAD will move and triggers the necessary index/worktree synchronization.

The test coverage is thorough: 537 lines of shell tests verify edge cases such as bare repositories, detached HEAD, conflict detection, `--empty` flag behavior, and preservation of local modifications. The documentation update adds a clear explanation of the command’s behavior, limitations, and examples. With all prior feedback addressed—including code duplication, reset API modernization, and dry-run consistency—this patch completes the series and is ready for final review.
