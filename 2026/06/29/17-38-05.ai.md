This is a minor follow-up in the `git history squash` series (v6 4/4), now code-complete and awaiting Junio’s final review. The thread has already resolved all major design and implementation questions; this exchange focuses solely on a cosmetic polish to the `--reedit-message` feature’s commit-message template.

Junio observes that the squash commit-message template produced by `git history squash --reedit-message` currently omits the numbered markers (`# This is the 1st commit message`) that `git rebase -i` includes between folded-in commit messages. These markers serve as visual boundaries, making it easier to distinguish where one commit’s message ends and the next begins. Without them, the template becomes harder to read, especially when multiple commits are squashed. Junio initially doubted the practical impact but, after seeing Phillip Wood’s side-thread example, now agrees the markers are a meaningful usability improvement.

Harald Nordgren agrees the markers would be a nice consistency improvement and is open to extracting the marker logic from `rebase -i`. Junio endorses this approach, suggesting that code sharing (even if cleaned up) would be beneficial. The change is trivial: it affects only the editor template’s appearance, not the resulting commit message or any other behavior. The series itself remains ready for Junio’s final assessment; this is a follow-up opportunity rather than a blocker. No further design or technical work remains.
