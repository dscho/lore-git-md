This is Junio C Hamano’s review of the final patch in Patrick Steinhardt’s `git history drop` series. The patch implements the user-facing `drop` subcommand, completing the 11-patch v7 effort to add commit-dropping capability to the experimental `git history` command.

Junio’s feedback focuses on a subtle edge case in the `find_head_tree_change()` helper, which determines whether HEAD will move during the drop operation. The concern centers on how the function resolves HEAD’s target ref: when HEAD is detached, `refs_resolve_ref_unsafe()` returns `"HEAD"` as the refname, but the code manually overwrites this with `"HEAD"` again, obscuring what the original value was. More critically, Junio questions whether the ref-filtering logic in `compute_pending_ref_updates()` (which only includes `DECORATION_REF_HEAD` when `--update-refs=head` is specified) might cause the function to miss HEAD updates entirely, leaving `head_update` unset and preventing the index/worktree synchronization that should occur when HEAD moves.

The review is substantive, identifying a potential logic gap that could lead to incorrect behavior in detached-HEAD or branch-checkout scenarios. While the series as a whole is complete and addresses all prior feedback—including reset API modernization, dry-run support, and code duplication—this final observation suggests a last-minute correctness issue that may require a v8 iteration. The patch is otherwise well-crafted, with thorough test coverage and clear documentation, but this edge case could undermine its reliability in real-world use.
