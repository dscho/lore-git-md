This is a **build system** and **platform compatibility** follow-up in the `USE_NSEC` thread. Patrick Steinhardt responds to Jeff King’s testing results by questioning whether `USE_NSEC` should remain a build-time option at all. His argument centers on the mismatch between the option’s granularity (build-time) and the actual variability of filesystem behavior (runtime). Since `USE_NSEC` works on some filesystems but not others, a build-time knob forces distributors to choose a conservative default (`false`) to avoid breaking users on problematic filesystems—even if most users would benefit from the performance improvement. Instead, Patrick proposes treating `USE_NSEC` like `core.ignoreCase`: a runtime-configurable setting, ideally auto-detected during repository initialization. This would allow Git to enable nanosecond resolution by default on platforms where it is safe, while still providing a fallback for edge cases. The proposal suggests unconditionally enabling nanoseconds at build time (removing the Meson option entirely) and introducing a new config knob (e.g., `core.useNsec`) for runtime control. No patch has been submitted yet, but this shifts the discussion from "how to expose the option in Meson" to "should the option exist at all, and if so, at what level?" Key technical details: the proposal would touch `git-config` machinery, `git-init`, and potentially filesystem detection code (e.g., `statfs`), while removing the Meson option added in the original patch. The thread now hinges on whether the project prefers runtime flexibility over build-time simplicity.
