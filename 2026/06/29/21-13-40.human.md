This is the final patch iteration in Harald Nordgren’s `git history squash` series, now at **v6**. The feature adds a new subcommand to fold a commit range (including merge commits, if fully contained) into its oldest commit, preserving descendant history in a single three-way merge. The series is complete, addressing all prior feedback: input validation, merge commit handling, ref safety, `--reedit-message` usability, and CLI/documentation style.

The only remaining point of disagreement is cosmetic: Phillip Wood prefers a cleaner `--reedit-message` template that omits redundant `fixup!`/`amend!` messages and visual delimiters, while Harald retains numbered markers for clarity. Harald’s reply here asks Phillip for a concrete example of his proposed format, signaling willingness to adjust if the alternative is demonstrably better. This is a usability trade-off, not a design blocker—v6 is otherwise ready for Junio’s final review.

The implementation is robust: shape-based input validation (rejecting malformed histories), explicit rejection of merges with external parents, and detection of interior refs with advice to use `--update-refs=head`. Test coverage is thorough, and the plumbing changes (`commit_tree_ext()` with a `message_template` parameter) are minimal and backward-compatible. If you care about interactive history editing, this is worth skimming for the template discussion; otherwise, it’s a polished feature waiting for merge.
