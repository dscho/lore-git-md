This is a **CI/platform-compatibility** follow-up in the ongoing thread about macOS CI hangs in the `t5551` and `t5559` tests. Michael Montalbo responds to Patrick Steinhardt’s proposal to increase Apache’s timeout value as a workaround for the upstream `mod_http2` bug (70131) that causes HTTP/2 stalls or `curl 18` mid-transfer aborts during `ls-refs` advertisements.

Montalbo confirms that the Apache bug affects both HTTP/1.1 and HTTP/2, meaning an upstream fix alone would not fully resolve the flakiness. He endorses Patrick’s suggestion to increase the timeout, reporting successful experiments with an artificially slowed CI runner where jobs completed without stalling when given a longer timeout. While he notes that an hour is excessive, he suggests a 5–10 minute timeout as a reasonable starting point, though he hasn’t determined a precise value. The linked GitHub Actions run demonstrates the approach’s viability, showing that the tests can progress to completion under controlled conditions.

This email reinforces the emerging consensus to address the root cause by adjusting Apache’s timeout rather than relying on client-side mitigations or retry logic. The discussion is now shifting toward implementation details—specifically, what timeout value to use and how to test it. The patch itself is straightforward (modifying `t/lib-httpd.sh`), but the choice of timeout will require balancing reliability against practical CI runtime constraints. The tone remains pragmatic, with Montalbo deferring to the maintainers’ judgment on the final value.
