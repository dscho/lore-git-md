This is a **refactoring and performance instrumentation** patch in the commit-reach subsystem, part of the ongoing `paint_down_to_common()` optimization series. Patch 5/8 introduces `struct paint_state`, a new data structure that replaces the old `nonstale_queue` with per-side counters (`p1_count`, `p2_count`, `pending_merge_bases`) to track commits by their paint flags (PARENT1-only, PARENT2-only, or both). The counters are maintained by `paint_count_update()`, which adjusts the appropriate bucket based on a commit’s flags, and the queue is drained via `paint_queue_get()`, which returns NULL when all counters reach zero.

The patch is **mechanical and low-risk**, converting `paint_down_to_common()` to use `paint_state` while preserving equivalent behavior. The loop now terminates when the counters indicate no non-stale entries remain, replacing the old `max_nonstale` pointer-based check. The "pop first" form of `paint_queue_get()` (dequeue, then check counters) causes the loop to exit one iteration earlier in some topologies, reducing step counts by one in a few test cases (e.g., `pending-stale` drops from 6 to 5 steps). The existing `nonstale_queue` is left untouched for `ahead_behind()` to avoid coupling.

Key changes:
- **New symbols**: `struct paint_state`, `paint_count_update()`, `paint_queue_put()`, `paint_queue_get()`.
- **Files touched**: `commit-reach.c`, `Documentation/technical/paint-down-to-common.adoc` (updated to reflect the new termination logic), and `t/t6600-test-reach.sh` (adjusted step counts).
- **Behavior**: No functional change, but step counts drop slightly due to the "pop first" optimization.
- **Test impact**: Deterministic step-count assertions are updated to match the new behavior (e.g., `test_paint_down_steps 5 5 5 5` for `pending-stale`).

The patch is **well-motivated and cleanly implemented**, with clear commit messages and inline comments. The counters improve code clarity by making the termination condition explicit, and the exhaustive switch in `paint_count_update()` documents all valid flag combinations. The step-count changes are minor and well-tested, with no regressions expected. This is a **prerequisite for the early-termination optimization** in later patches, enabling precise tracking of side exhaustion. The series remains on track for merging.
