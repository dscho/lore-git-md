This thread is about a small but important bugfix for the `git history reword` subcommand. The patch, authored by Junio C Hamano, fixes two related issues in `fill_commit_message()`: an inefficient file-handling pattern that wrote to a buffer, flushed it to a file, then reopened the file in append mode, and a file stream leak that could cause problems on Windows by leaving open handles that block other processes.

The fix is straightforward: open the target file once in write mode upfront, write the initial message directly to the stream, and explicitly close the file before launching the external editor. Junio describes it as "tested and merge-ready," crediting Johannes Schindelin with diagnosing the problem, which was introduced in January 2026 (commit d2205234c). The change is minimal—just 8 insertions and 7 deletions—and focuses solely on `fill_commit_message()`. There’s no mention of test failures or edge cases, so this appears to be a clean, well-contained fix with clear urgency due to the Windows compatibility concern. Expect this to land in `next` soon unless someone spots an unexpected side effect.
