Junio sent a small bugfix patch to address two related issues in `git history --reword`: an inefficient file-handling pattern that wrote a buffer to disk, flushed it, then reopened the file in append mode, and a file stream leak that could cause problems on Windows by leaving the file handle open before launching the external editor. The fix is minimal—just eight lines changed in `fill_commit_message()`—and consolidates file operations by opening the target file once in write mode, writing the initial message directly, and closing the stream before the editor starts.

Patrick Steinhardt reviewed the patch and agreed it fixes the original problems but pointed out a potential regression: the patch removes error checking on the initial file write. Previously, `write_file_buf()` would fail loudly if the write failed, but the new version uses `fwrite()` without checking its return value. Since the rest of the commit message is written by `wt_status_print()`—which also lacks error checking—Patrick warned that a partially-written file could go unnoticed.
