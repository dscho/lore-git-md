This thread is about a patch series (v9) by Tian Yuchen that continues Git's libification effort by moving nine global configuration variables into a centralized `struct repo_config_values`. The goal is to eliminate globals, improve memory management, and prepare the codebase for further modularization. The series builds on the recently merged `excludes_file` migration and touches configuration handling, ignore-file logic, apply settings, branch/push defaults, and editor/pager/askpass programs.

The series was technically complete and CI-clean, but Junio C Hamano identified a memory leak regression in the `pager_program` migration (patch 4/9 of v8). The leak occurred in `core_pager_config()`, which directly overwrote the heap-allocated string without freeing the old value. Tian acknowledged the issue and confirmed the fix—adding `FREE_AND_NULL()` before re-assignment—will be included in v9. This resolves the last technical blocker, ensuring consistent memory management across all migrated fields, including `askpass_program` and apply whitespace settings.

The series remains under active review and is not yet in `next` or `master`. Two RFC questions remain open: whether migrating program paths (editor, pager, askpass) is worthwhile, and how this work relates to prior discussions about `git_branch_track`. Junio’s review was substantive, focusing on correctness and edge cases, while Tian’s follow-up ensures the series is now memory-safe. Expect v9 to land soon, pending no further objections.
