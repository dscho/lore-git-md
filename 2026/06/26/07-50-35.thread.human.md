This thread is a follow-up to the recently merged `excludes_file` migration, extending the libification effort by moving nine more global configuration variables into `struct repo_config_values`. The series, now at v8, is authored by Tian Yuchen and targets variables like editor/pager/askpass programs, apply whitespace settings, and several enums (`push_default`, `autorebase`, `object_creation_mode`, `attributes_file`). The goal is to eliminate globals, centralize memory management, and prepare the codebase for further modularization.

The series is technically complete and CI-clean, with Junio C Hamano’s memory leak concern from v7 fully addressed in v8. The fix ensures proper cleanup of heap-allocated strings during re-assignment, eliminating leaks in long-running processes. Patches 1-2 overlap with the prior `excludes_file` work but are re-split for clarity, while patches 3-9 migrate the remaining variables. The latest email (patch 5/9) moves `askpass_program` into `repo_config_values`, following the established pattern for program paths and reinforcing the memory management fix.

Two RFC questions remain open: whether migrating program paths (editor, pager, askpass) is worthwhile, given their rare per-repository use, and how this work relates to prior discussions about `git_branch_track`. The author argues for the value of per-repo configuration for developers with different toolchains but seeks feedback. A promised follow-up cleanup for comments and variable classification in `repo_config_values` is also noted, along with unresolved `NEEDSWORK` items like submodule support and enum placements. The series is under active review but not yet in `next`.
