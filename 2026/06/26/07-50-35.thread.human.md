This thread is a nine-patch series by Tian Yuchen that continues Git's libification effort by migrating more global configuration variables into `struct repo_config_values`. The series builds on the recently merged `excludes_file` migration and moves nine additional variables—editor, pager, and askpass programs; apply whitespace settings; and four enums (`push_default`, `autorebase`, `object_creation_mode`, and `attributes_file`)—into repository-specific storage. The goal is to eliminate globals, centralize memory management, and prepare the codebase for further modularization.

The series is now technically complete and under review. Tian addressed a memory leak regression Junio C Hamano identified in an earlier version, ensuring all heap-allocated fields are properly freed during re-assignment. The patches are CI-clean and introduce no user-visible behavior changes. Two RFC questions remain open: whether migrating program paths (like editor and pager) is worthwhile, given they’re rarely overridden per-repository, and how this work relates to prior discussions about `git_branch_track`. The author argues per-repo configuration is useful for developers with different toolchains, but no reviewer feedback has weighed in yet.

Key technical details include the introduction of `repo_config_values_clear()` to manage memory, getters for some variables (like `repo_askpass_program()`), and direct field access for others. The series touches multiple subsystems, including configuration handling, ignore-file logic, apply settings, and branch/push defaults. Some loose ends remain, such as a `NEEDSWORK` comment about submodule support and temporary placements of enums in `environment.h` to avoid circular dependencies, but these aren’t blockers. Junio’s memory leak concern has been resolved, removing the last major obstacle to merging. The series is not yet in `next` or `master`.
