This thread is about a refactoring patch series that moves the global `excludes_file` variable into Git's repository configuration structure (`struct repo_config_values`) as part of the ongoing libification effort. The series, originally split into two patches in v2, has now been squashed into a single patch (v4) at Junio Hamano's suggestion.

Tian Yuchen, the author, has addressed all substantive feedback from the previous round. The most significant change was replacing a temporary guard (`if (repo != the_repository)`) with a stricter `repo->initialized` check in both the new getter function (`repo_excludes_file()`) and the cleanup helper. This aligns with existing patterns and resolves Junio's concern about premature abstraction. The patch also properly manages heap memory for the migrated variable and abstracts XDG fallback lazy-loading into the getter. No user-visible behavior changes are introduced.

The series has been guided by Christian Couder and other mentors, and all technical objections from v2—including a build-breaking unused parameter issue raised by SZEDER Gábor—have been resolved. The patch touches core files (`dir.c`, `environment.c`, `environment.h`, `repository.c`) and is foundational for further modularization. With no open questions remaining, the series appears ready for inclusion in Junio's `next` branch.
