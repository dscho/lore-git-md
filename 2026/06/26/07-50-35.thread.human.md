This patch series from Tian Yuchen continues the libification effort by migrating nine more global configuration variables into `struct repo_config_values`, building on the recently merged `excludes_file` work. The series is now at v8 and under active review, with all patches technically complete and passing CI. The primary goal is to eliminate globals, centralize memory management, and prepare the codebase for further modularization.

Junio C Hamano has identified a memory leak regression in patch 4/9, which migrates `pager_program`. The issue arises in `core_pager_config()`, where the old heap-allocated string is not freed before re-assignment, reintroducing a leak Junio previously flagged in v7. This is a blocking concern, as it undermines the series' memory safety guarantees. The fix is straightforward—free the old value before calling `git_config_string()`—but the oversight highlights the need for consistent memory management across similar code paths. The rest of the patch appears uncontroversial, and the series is otherwise ready for integration once this is addressed.

The series also raises two open questions: whether migrating program paths (editor, pager, askpass) is worthwhile, given their rare per-repository use, and how this work relates to prior discussions about `git_branch_track`. Tian argues for the value of per-repo configuration, particularly for developers using different toolchains, and has promised a follow-up cleanup for comments and variable classification in `repo_config_values`. No other technical objections have been raised, and the series is expected to advance quickly once the memory leak is fixed.
