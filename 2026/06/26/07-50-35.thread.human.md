This thread is a follow-up to the recently merged `excludes_file` migration, where Tian Yuchen is extending the pattern to move nine more global configuration variables into `struct repo_config_values` as part of Git’s libification effort. The v9 series, now under review, migrates editor, pager, and askpass programs, apply whitespace settings, four enums (`push_default`, `autorebase`, `object_creation_mode`, `attributes_file`), and fixes a memory leak regression Junio C Hamano flagged in an earlier version.

The series is technically complete and CI-clean, with all heap-allocated strings now properly freed during re-assignment, including in `core_pager_config()`. Tian has addressed Pablo Sabater’s feedback on redundant function calls in `repo_excludes_file()` and `git_editor()`, though these remain as minor performance nits. The bigger unresolved discussion is Pablo’s concern about silent submodule leaks in `repo_config_values_clear()`—Tian prefers fail-fast behavior to catch misuse early, while Pablo advocates for robustness. No merge status has been reported; the series is still under review.

Tian has also raised two open questions: whether migrating program paths (like editor/pager) is worthwhile, given they’re rarely overridden per-repository, and how this work relates to the more complex `git_branch_track` migration. The series touches many subsystems but introduces no user-visible changes, focusing instead on foundational refactoring.
