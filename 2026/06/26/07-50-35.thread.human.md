This thread is about a final patch (v4) that moves the global `excludes_file` variable into Git’s repository configuration structure as part of the ongoing libification effort. Tian Yuchen, the author, has incorporated all prior feedback—squashing the series into a single patch, replacing a temporary guard with a stricter `repo->initialized` check, and marking an unused parameter to fix a build issue.

The only remaining point of contention is a defensive programming choice in the new `repo_excludes_file()` getter. Junio Hamano has suggested replacing the current silent early return for uninitialized repositories with a `BUG()` assertion, arguing that callers should never invoke the getter on an uninitialized repository and that silent failures could hide deeper problems. Tian has not yet responded to this suggestion, but the rest of the patch is otherwise ready for merging. The discussion reflects the project’s preference for fail-fast design in foundational refactoring, though the change itself is small and localized. No other objections or open questions remain.
