This thread is a follow-up to the recently merged `excludes_file` migration, extending the same libification pattern to nine more global configuration variables. Tian Yuchen’s v9 series moves these into `struct repo_config_values` to eliminate globals, centralize memory management, and prepare for further modularization. The series is now technically complete and CI-clean after fixing a memory leak Junio C Hamano flagged in v8.

The latest patch (4/9) migrates `pager_program`, following the same approach used for `editor_program` in patch 3/9. It adds the variable to `struct repo_config_values`, updates initialization and cleanup routines, and fixes the leak in `core_pager_config()` by ensuring old values are freed before re-assignment. Like the rest of the series, this patch makes no user-visible changes but lays groundwork for per-repository configuration. Tian argues in the commit message that migrating program paths (editor, pager, askpass) is worthwhile for developers who use different toolchains across projects, though no reviewers have weighed in on this yet.

The series is under active review, with no merge status reported. Junio’s memory-leak concern is now resolved, removing the last technical blocker. Open questions are design-oriented: whether migrating program paths is useful, and how this work might interact with future `git_branch_track` migration. The author has also flagged some cleanup tasks (comment organization, enum placement) and a `NEEDSWORK` limitation around submodule support, but none are blocking. The patches are ready for integration once review concludes.
