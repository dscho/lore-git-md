Core problem or goal
Continue the libification effort by migrating global configuration variables into `struct repo_config_values`. This series builds on the merged `excludes_file` migration and extends the pattern to eleven variables: editor/pager/askpass programs, apply whitespace settings, four enums (`push_default`, `autorebase`, `object_creation_mode`, `attributes_file`), and the recently added `askpass_program`. The goal is to eliminate globals, centralize memory management, and prepare the codebase for further modularization. The author’s RFC questions—(1) whether migrating program paths is worthwhile, and (2) how this work relates to prior discussions about `git_branch_track`—remain open but do not affect correctness.

Current status
The series is **technically complete** and **ready for `next`**, addressing all prior feedback. **Key changes in v11**:
- **Patch 1/9 (new in v11)**: Introduced `repo_config_values_clear(struct repo_config_values *)` in `environment.c`, declared in `environment.h`, and wired into `repo_clear()` in `repository.c`. The destructor frees heap-allocated fields (starting with `attributes_file`) and is designed to support submodule use cases and avoid initialization-order crashes. The signature takes a `struct repo_config_values*` rather than `struct repository*` for this purpose.
- **Patch 2/9 (new in v11)**: Migrates the `excludes_file` global variable into `struct repo_config_values` and introduces `repo_excludes_file()` as a getter. The getter encapsulates lazy-loading fallback logic (XDG default path assignment) and ensures backward compatibility. The destructor `repo_config_values_clear()` is extended to free the `excludes_file` field.
- **Patch 3/9 (new in v11)**: Migrates the `editor_program` global variable into `struct repo_config_values`. The field is initialized to `NULL` in `repo_config_values_init()`, freed in `repo_config_values_clear()`, and accessed directly via `repo_config_values(the_repository)->editor_program` in `git_editor()`. Memory management is handled via `FREE_AND_NULL()` before reassigning the field in `git_default_core_config()`.
- **Patch 4/9**: Migrates the `pager_program` global into `struct repo_config_values`. The field is added to `environment.h`, initialized to `NULL` in `repo_config_values_init()`, and freed in `repo_config_values_clear()`. In `pager.c`, the static global `pager_program` is removed, and configuration parsing is redirected to use the repository-specific field. The patch fixes memory leaks in `core_pager_config()` and `check_pager_config()` by properly freeing the old value before reassigning the field via `FREE_AND_NULL()`. The commit message documents the `BUG()` assertion in `repo_config_values()` (which enforces `repo == the_repository`) and notes that all current callers comply. The result of `repo_config_values()` is cached in local variables to avoid redundant calls.
- **Patch 5/9**: Removes the global variable `askpass_program` and its extern declaration from `environment.c` and `environment.h`, eliminating redundant state. The field is added to `struct repo_config_values`, initialized to `NULL` in `repo_config_values_init()`, and freed in `repo_config_values_clear()`. In `git_default_core_config()`, configuration parsing updates `cfg->askpass_program` instead of the global variable. The only caller in `prompt.c` accesses the field via `repo_config_values(the_repository)->askpass_program`.
- **Patch 6/9**: Migrates the `apply_default_whitespace` and `apply_default_ignorewhitespace` global variables into `struct repo_config_values`. The patch updates `git_apply_config()` to accept a `struct repository *` parameter, eliminating its reliance on the global `the_repository`. Memory management is improved by adding `FREE_AND_NULL()` calls before reassigning the fields in `git_apply_config()`, ensuring old values are properly freed. The fields are initialized to `NULL` in `repo_config_values_init()` and freed in `repo_config_values_clear()`. Callers in `apply.c` now access the values via `repo_config_values(repo)->apply_default_whitespace` and `repo_config_values(repo)->apply_default_ignorewhitespace`, with the result of `repo_config_values()` cached to avoid redundant calls.
- **Patch 7/9**: Extracted `cfg` from `repo_config_values(the_repository)` in `builtin/push.c` for readability, as suggested by Pablo Sabater.
- **Patch 9/9**: Adjusted a stale comment in `repository.h` to reflect the migration of `askpass_program` into `struct repo_config_values`.

The series is **CI-clean**, **memory-leak-free**, and **no longer has open technical feedback**. The base commit remains `ab776a62a7` (Git 2.55-rc2, 2026-06-22). **No merge status has been reported**; the series is not in `next` or `master`.
