Core problem or goal
Continue the libification effort by migrating additional global configuration variables into `struct repo_config_values`. This series builds directly on the recently merged `excludes_file` migration (v6, now in `next`) and extends the pattern to nine variables: editor/pager/askpass programs, apply whitespace settings, four enums (`push_default`, `autorebase`, `object_creation_mode`, `attributes_file`), and the recently added `askpass_program` (patch 5/9). The goal is to eliminate globals, centralize memory management, and prepare the codebase for further modularization. The author raises two RFC questions: (1) whether migrating program paths (editor, pager, askpass) is worthwhile, and (2) how this work relates to prior discussions about `git_branch_track`.

Current status
The series is **under review** as a follow-up to the merged `excludes_file` work. The first two patches overlap with the prior series (introducing `repo_config_values_clear()` and migrating `excludes_file`), but are re-split for clarity. Patches 3-9/9 migrate `editor_program`, `pager_program`, `askpass_program`, `attributes_file`, `push_default`, `autorebase`, **`apply_default_whitespace`**, **`apply_default_ignorewhitespace`**, and **`object_creation_mode`**. The series is **technically complete** and **CI-clean**, but **a new memory leak regression has been identified in patch 4/9** by Junio C Hamano. The leak occurs in `core_pager_config()` (used by `read_early_config()`), which directly overwrites `repo_config_values(r)->pager_program` via `git_config_string()` without freeing the previous heap-allocated string. This reintroduces the leak Junio flagged in v7, now in a different code path. The fix pattern established in earlier patches (3/9 for `editor_program`, and patch 4/9’s own `check_pager_config()`) is not consistently applied: `core_pager_config()` must free the old value before calling `git_config_string()`. The rest of the patch (field migration, lifecycle management, and caller updates) is uncontroversial. **No merge status has been reported; the series is not yet in `next`**.

Key technical details
- Files touched: `environment.c`/`environment.h` (primary), `editor.c`, `pager.c`, `apply.c`, `branch.c`, `builtin/push.c`, `remote.c`, `repository.c`, `dir.c`, `prompt.c`, `object-file.c`, and others for enum-specific logic.
- New symbols:
  - `repo_config_values_clear()` (destructor function for heap-allocated strings in `struct repo_config_values`, now handling `excludes_file`, `editor_program`, `pager_program`, `askpass_program`, `attributes_file`, **`apply_default_whitespace`**, **`apply_default_ignorewhitespace`**, **`autorebase`**, **`object_creation_mode`**, and **`push_default`**).
  - Getters for migrated variables: `repo_askpass_program()`, `repo_apply_whitespace()`, `repo_push_default()`, `repo_autorebase()`, `repo_object_creation_mode()`, and `repo_excludes_file()` (added in patch 2/9).
  - Direct field access for `editor_program`, `pager_program`, `askpass_program`, **`apply_default_whitespace`**, **`apply_default_ignorewhitespace`**, **`push_default`**, **`autorebase`**, and **`object_creation_mode`** (no getters introduced; callers use `repo_config_values(the_repository)-><field>`).
  - Migrated enums: `push_default`, `autorebase`, `object_creation_mode` (now stored in `struct repo_config_values`).
  - `attributes_file` migration (new in this series, following the same pattern as `excludes_file`).
  - Updated function signature: `git_apply_config(struct repository *)` (previously relied on `the_repository`).
- Memory management:
  - Heap allocation for all migrated strings, cleanup via `repo_config_values_clear()` (called during repository teardown in `repo_clear()`).
  - **Fixed in v8 for most code paths**: `repo_config_values_clear()` properly handles intermediate re-assignments of heap-allocated strings (e.g., `pager_program`, `editor_program`, `askpass_program`, `attributes_file`, **`apply_default_whitespace`**, **`apply_default_ignorewhitespace`**), freeing old values before re-assignment to prevent memory leaks. This is visible in patch 3/9 with `FREE_AND_NULL(cfg->editor_program)` in `git_default_core_config()`, reinforced in patch 4/9 with the same pattern for `pager_program` in `check_pager_config()`, extended in patch 5/9 to `askpass_program` in `git_default_core_config()`, and **further extended in patches 6-9/9 to `apply_default_whitespace`, `apply_default_ignorewhitespace`, `autorebase`, and `object_creation_mode` (though the latter two are enums and do not require heap allocation)**.
  - **New regression in v8 (patch 4/9)**: `core_pager_config()` (used by `read_early_config()`) directly overwrites `repo_config_values(r)->pager_program` via `git_config_string()` without freeing the previous heap-allocated string, reintroducing the leak Junio flagged in v7. The fix requires adding `free()` before `git_config_string()` in `core_pager_config()`.
  - Patch 9/9 specifically migrates `object_creation_mode` (an enum) into `struct repo_config_values`, relocating its definition in `environment.h` to resolve visibility and updating `finalize_object_file_flags()` in `object-file.c` to read from the repository-specific structure. No memory management concerns apply (enum, not heap-allocated).
- Submodule guardrail: `repo_config_values_clear()` silently returns if called on a submodule repository, avoiding a crash since `repo_config_values()` currently BUG()s out for non-`the_repository` instances. This limitation is marked as `NEEDSWORK` but is not a blocker.
- No user-visible behavior changes; foundational for libification.
- Subsystems: configuration handling, ignore-file logic (follow-up to `excludes_file`), apply settings, branch/push defaults, editor/pager/askpass programs, attributes file, object creation mode.
- **Overlap with prior work**: Patches 1-2 reimplement the `excludes_file` migration (already merged) but are re-split for clarity in this series. Patch 2/9 specifically moves `excludes_file` into `struct repo_config_values` and introduces `repo_excludes_file()` with lazy-loading fallback to the XDG default path.

  - **Patch 9/9**: Migrated `object_creation_mode` into `struct repo_config_values`, relocating `enum object_creation_mode` in `environment.h` to resolve visibility and updating `finalize_object_file_flags()` in `object-file.c` to read from the repository-specific structure. The default value `OBJECT_CREATION_MODE` is initialized in `repo_config_values_init()`. No memory management concerns apply (enum, not heap-allocated).
