This is the first patch in a two-part refactoring series targeting the ongoing libification effort. It introduces `repo_excludes_file()`, a getter function that encapsulates the lazy-loading logic for the global `excludes_file` variable. The goal is to prepare the codebase for moving this variable into `struct repo_config_values` in the next patch, eliminating another piece of global state.

The change is mechanical but important: it abstracts the XDG fallback logic (`xdg_config_home("ignore")`) out of `setup_standard_excludes()` in `dir.c` and into `environment.c`, where it can be managed more cleanly. The patch touches three files (`dir.c`, `environment.c`, `environment.h`) and adds a TODO comment acknowledging that the getter still relies on the global variable for now. This is a deliberate intermediate step before the variable is fully migrated in the next patch.

The implementation looks clean and well-scoped. The getter is simple and mirrors the existing lazy-loading pattern, and the commit message clearly explains the motivation. The patch does not change behavior—it just reorganizes the code to make the next step possible. Reviewers will likely focus on whether the abstraction is complete and whether the new function integrates smoothly with the rest of the codebase.

This is part of a mentored series (Christian Couder, Ayush Chandekar, and Olamide Caleb Bello are listed as mentors), which suggests it has guidance from experienced contributors. The patch is a small but necessary step toward making Git's internals more modular, and it fits neatly into the broader `the_repository` removal effort.
