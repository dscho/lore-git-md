This is the final patch in a **post-merge follow-up series** (v3) optimizing Git’s `paint_down_to_common()` function in the commit-reach subsystem. The patch **consolidates termination conditions** by moving the `min_generation` check into `paint_queue_get()`, alongside existing stale-entry and side-exhaustion checks. It also **widens the generation-monotonicity BUG assertion** to fire unconditionally, enforcing correct generation ordering for all callers—not just those using `min_generation`.

The key change is structural: `last_gen` is now stored in `struct paint_state`, ensuring `commit_graph_generation()` is called exactly once per dequeued commit. The loop in `paint_down_to_common()` now reads `state.last_gen` instead of recomputing the generation, and the `min_generation` check is performed immediately after dequeuing, before any other conditions. This simplifies the main loop and ensures the `last_gen` assertion is shared across all termination checks. The "pop first" form of `paint_queue_get()` (dequeue, then check) is preserved, keeping the optimization commit’s diff minimal.

The patch updates the new technical documentation (`paint-down-to-common.adoc`) to include the `min_generation` cutoff as a fourth termination condition, with a dedicated subsection explaining its role in `remove_redundant()`. The documentation now clearly distinguishes between the four halt conditions: stale entries, side exhaustion, generation cutoff, and the finite-generation guard.

This is a **cleanup and defensive hardening** rather than a new optimization. The changes are internal to `commit-reach.c` and have no on-disk format impact. The patch is **low-risk**: it consolidates existing logic, improves code clarity, and enforces invariants more strictly. The test suite (including deterministic step-count assertions for all commit-graph modes) already validates the behavior, and the benchmarks from earlier patches demonstrate the optimization’s impact. The series is **ready for review and merging**.
