This is the seventh patch in a v3 series (8/8 total) that optimizes Git’s `paint_down_to_common()` function—a key part of merge-base calculation. The series is a post-merge follow-up: all v2 patches are already merged, and this iteration adds cleanup, hardening, and documentation. This specific patch implements the core optimization: **early termination of the merge-base walk when one side’s commit queue is exhausted**, yielding **100-1000x speedups** for asymmetric queries (e.g., repositories with import grafts or shallow histories).

The patch adds an early-exit condition that triggers when either `p1_count` or `p2_count` (per-side counters introduced earlier in the series) drops to zero, no pending merge-base candidates remain, and the walk is in the finite-generation region (`generation < GENERATION_NUMBER_INFINITY`). This gate ensures correctness: commits without commit-graph entries (generation `INFINITY`) are ordered by commit date, which isn’t topologically reliable, so the optimization only activates where ordering guarantees hold.

However, **Derrick Stolee’s review confirms a regression** introduced by this patch: the widened generation-monotonicity BUG assertion now fires unconditionally, breaking correctness when `min_generation` isn’t set. The test suite catches this in some commit-graph modes (e.g., "none" or "no-gdat"). The author has acknowledged the issue and plans to rework the logic to preserve the original behavior while keeping the optimization. **This patch is not ready for merging in its current form**, but the rest of the series (patches 1–6 and 8) remains stable.

The performance gains are dramatic and well-instrumented. Trace2 step-counting (added in patch 4/8) shows reductions like `72,264 → 44,589 steps` for `merge-base --all v2.0.0 v2.55.0-rc1` and `110 → 7 steps` for `merge-base --all v2.55.0-rc1 v2.55.0-rc1~5`. The test suite updates reflect these improvements, with deterministic step-count assertions for all commit-graph modes. Stolee’s review notes the "satisfying" diffs in expected step counts, signaling the optimization works as intended—**when the regression is fixed**.

The patch touches `commit-reach.c` (adding the early-exit logic and adjusting the BUG assertion), `Documentation/technical/paint-down-to-common.adoc` (documenting the new termination condition), and `t/t6600-test-reach.sh` (updating step-count expectations). The documentation explains why the `INFINITY` gate is necessary and how the optimization preserves correctness.

**Key takeaway**: This is a high-impact performance win with a clear regression. The fix should be straightforward, and the rest of the series is ready to merge. The instrumentation and test coverage make this a low-risk change once the bug is addressed.
