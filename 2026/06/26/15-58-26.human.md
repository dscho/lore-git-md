This is a Rust-focused bugfix patch targeting the loose object map in Git's nascent Rust codebase.

The patch addresses a latent correctness issue in `ObjectMap::insert()`, which stores mappings between a repository's storage hash (e.g., SHA-256) and a compatible hash (e.g., SHA-1). The current implementation assumes that if the first object ID does not use the compatible algorithm, the second must be the compatible one—without validating the second ID's algorithm. This allows callers to pass two IDs with the same algorithm or an unknown algorithm, silently violating the map's invariant that each entry must contain exactly one storage and one compatible hash.

Feng Wu makes the invariant explicit by decoding both object ID algorithms upfront and rejecting unknown or mismatched pairs before any insertion occurs. The patch introduces a new `ObjectMapInsertError` enum with variants for invalid hash algorithms and mismatched algorithm pairs, providing clear error reporting. The existing tests are updated to unwrap successful insertions, and new tests verify that same-algorithm and unknown-algorithm inputs are properly rejected.

The change is narrowly scoped to `src/loose.rs` and is well-motivated: the commit message clearly explains the problem, the fix, and the testing strategy. The patch looks like a straightforward, low-risk correction to a subtle but real bug in the Rust object map logic. It is part of the ongoing Rustification effort, but this particular patch does not touch C code or interact with the rest of Git's internals—it is purely internal to the Rust loose object map implementation.
