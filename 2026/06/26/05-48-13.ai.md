This is the third and final patch in Toon Claes's v5 series introducing the `--linearize` option to `git replay`. The series is now technically complete, with all feedback from v4 addressed and Junio Hamano's "Will merge to 'next'" approval actionable.

This patch implements the core `--linearize` functionality, which flattens merge commits into linear history by walking only first parents. This provides server-side functionality equivalent to `git rebase --no-rebase-merges`. The implementation handles merge commits by mapping them to their first parent in the `replayed_commits` OID map, effectively dropping them from the replayed history while preserving the linear chain of regular commits. The option is documented as incompatible with `--revert`, and the code includes an explicit `BUG()` check to enforce this constraint.

The patch touches five files: `replay.c` (core logic), `replay.h` (option struct), `builtin/replay.c` (CLI integration), `Documentation/git-replay.adoc` (user documentation), and `t/t3650-replay-basics.sh` (test coverage). The test suite has been significantly expanded to verify root commit handling, `--advance` combinations, and complex rebase scenarios involving multiple divergent branches. A key test uses `git range-diff` to confirm that the replayed commits produce identical patches to the originals, ensuring functional equivalence.

The implementation builds on the preparatory work in patches 1/3 (helper functions) and 2/3 (base-selection logic fix and explanatory comments) from this v5 series. The merge commit handling is straightforward: when `--linearize` is active, merge commits are skipped during replay, leaving `last_commit` unchanged and mapping the merge commit's OID to the previous non-merge commit in `replayed_commits`. This approach cleanly addresses the architectural concerns raised in v4 by avoiding the controversial boolean refactoring while still delivering the promised functionality.

Key technical details for follow-up discussion include the `linearize` field in `struct replay_revisions_options`, the `pick_regular_commit()` helper's `replayed_base` parameter, and the test cases covering root commits and `--onto` edge cases.
