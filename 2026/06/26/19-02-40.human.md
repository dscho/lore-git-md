This is the ninth patch in Taylor Blau’s ten-patch RFC series to combine `git repack --geometric` and `--cruft`. It teaches `git pack-objects` to accept a `--refs-snapshot=<path>` option when used with `--stdin-packs=follow-reachable`, ensuring that the set of reachable objects seen by `pack-objects` matches the set seen by the MIDX bitmap writer.

The problem is a race: without a snapshot, `pack-objects` discovers refs by iterating live references, which may change between the time the geometric pack is written and the MIDX bitmap is generated. This can cause reachable objects to end up in the cruft pack instead of the geometric pack, preventing them from receiving bitmap coverage and forcing fetches to load the cruft pack (which may contain many unrelated unreachable objects).

The solution is straightforward: the snapshot file uses the same format as the MIDX bitmap writer (one hex OID per line, with an optional `+` prefix for preferred bitmap commits), and `pack-objects` ignores the `+` prefix for convenience. The patch adds the option, validates that it is only used with `--stdin-packs=follow-reachable`, and implements the snapshot reader in a new `read_refs_snapshot()` function that replaces the live ref iteration.

The change is small (52 lines added, 2 removed) and touches only `builtin/pack-objects.c` and the man page. It is a necessary plumbing piece for the final integration patch (10/10) and does not change behavior on its own. The patch is well-motivated and addresses a real correctness issue in the combined geometric/cruft repack workflow.
