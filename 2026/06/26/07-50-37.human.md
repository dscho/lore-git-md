This is the second patch in a two-part refactoring series that moves the global `excludes_file` variable into `struct repo_config_values` as part of the ongoing libification effort. The patch completes the work begun in the first patch by migrating the variable itself, introducing proper heap memory management, and adding a cleanup helper function.

The patch removes the global `excludes_file` declaration and adds it as a field in `struct repo_config_values`. The new `repo_config_values_clear()` function is introduced to free both `excludes_file` and `attributes_file` when a repository instance is destroyed. The getter function `repo_excludes_file()` is updated to access the variable through the repository struct, with a temporary guard to avoid BUG() assertions in uninitialized submodules.

The changes are mechanical but touch core files (`environment.c`, `environment.h`, `repository.c`) and involve memory management, so correctness is critical. The author has addressed feedback from v1 by ensuring proper initialization and cleanup.
