This is the v5 iteration of Toon Claes's feature series introducing a `--linearize` option to `git replay`. The series teaches `git replay` to flatten merge commits into linear history by walking only first parents, providing server-side functionality equivalent to `git rebase --no-rebase-merges`.

The most significant change in v5 is the **replacement of the controversial enum-to-boolean refactoring** (Patch 1/3 in v4) with a new preparatory patch that **adds detailed code comments explaining how `pick_regular_commit()` selects a base commit**. This addresses the callsite clarity concerns raised by Junio Hamano and Patrick Steinhardt in v4, while avoiding the extensibility debate entirely. The new patch also **fixes a logic error in `replayed_base` handling** when rebasing multiple divergent branches with `--onto`, a bug that became apparent during the refactoring work. A new test case verifies this edge case.

The series now consists of three patches:
1. A helper function (`put_mapped_commit()`) to encapsulate khash OID map updates (unchanged from v4).
2. The new explanatory patch with the base-selection fix.
3. The main `--linearize` implementation, which remains largely unchanged except for improved comments and the base-selection logic fix.

The `--linearize` option is documented as incompatible with `--revert`, and test coverage has been expanded to include root commit handling, `--advance` combinations, and patch preservation verification via `git range-diff`. The series continues to carry Johannes Schindelin's Signed-off-by, indicating his support.

This version appears to address all outstanding architectural concerns from v4. The boolean vs. enum debate is moot with the new approach, and the base-selection fix resolves Patrick Steinhardt's interface scope question by ensuring correct behavior for complex rebase scenarios. The series is now focused on its core goal: providing a `--linearize` option that mimics `git rebase --no-rebase-merges` for `git replay`.
