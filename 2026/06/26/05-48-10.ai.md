This is the v5 iteration of the `--linearize` option for `git replay`, a feature addition that flattens merge commits to match `git rebase --no-rebase-merges`. The series now consists of three patches: two refactoring patches (one new, one carried over from v4) and the core implementation patch. The most significant change in v5 is the **reversion of the controversial `enum replay_mode` refactoring** (previously patch 1 in v4) and its replacement with a new patch that **adds detailed code comments** explaining how `pick_regular_commit()` selects a base commit. This addresses the readability and extensibility concerns raised by Junio and Patrick Steinhardt in v4, who argued that converting the enum to a boolean `reverse` flag obscured intent and complicated future additions.

The new patch (2/3) is a pure refactoring with no behavior change: it expands comments in `pick_regular_commit()` to clarify the logic for selecting the base commit (e.g., why `last_commit` is used during reverts and `onto` for forward replays). This work uncovered a **bug in the `--linearize` implementation** when replaying multiple divergent branches with `--onto`: the `replayed_base` parameter was incorrectly handled, causing child commits to be replayed onto the wrong parent. The fix is included in the core patch (3/3), which now correctly maps merge commits to the previous non-merge commit in `replayed_commits`, ensuring proper reparenting. A new test case verifies this edge case, covering a scenario where two branches (one with a merge commit) are replayed onto a common base.

The core patch (3/3) remains largely unchanged from v4, with the exception of the bug fix and improved comments. It implements `--linearize` by skipping merge commits in the replay loop, leaving `last_commit` unchanged to reparent subsequent commits onto the previous non-merge commit. The option is mutually exclusive with `--revert` (enforced by `die_for_incompatible_opt2`) and documented in the man page. Test coverage is thorough, including cases for `--linearize` with `--advance`, `--revert`/`--linearize` incompatibility, and a `git range-diff` check for patch equivalence. The series is now **technically complete** and addresses all prior feedback, though the **interface design question** (whether to mirror `git rebase`'s three-mode design now or later) remains open. Toon has outlined a possible future evolution (default: preserve topology, `--linearize`: flatten, `--no-merges`: abort, `--replay-cousins`: rebase cousins) but prefers to implement `--linearize` incrementally.
