This is a **CI/platform-compatibility** follow-up in the macOS CI hang thread. Jeff King (Peff) responds to Michael Montalbo’s identification of the root cause as an upstream Apache `mod_http2` bug (70131). Peff acknowledges the diagnosis but expresses skepticism about the proposed client-side mitigation (enabling `http.lowSpeedLimit` and `http.lowSpeedTime` to convert hangs into fast failures). He argues that this approach merely "punts" on the problem by creating spurious failures, and notes that Git has historically resisted automatic retries for flaky tests, preferring to eliminate flakes at the source. Instead, Peff suggests two alternatives: either **wait for an upstream Apache fix** (given the bug’s external origin) or **increase Apache’s timeout value** to reduce the likelihood of hitting the problematic state. His response shifts the discussion toward evaluating the trade-offs between mitigation, upstream resolution, and test reliability, with no clear consensus yet on the best path forward. The thread remains focused on CI stability and test flakiness, with no new code changes proposed.
