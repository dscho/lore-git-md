This is the first patch in a two-part refactoring series targeting the libification effort. It introduces `repo_excludes_file()`, a getter function that encapsulates the lazy-loading logic for the global `excludes_file` variable, which tracks the path to the global ignore file (`core.excludesfile`). The change moves the XDG fallback path resolution (`xdg_config_home("ignore")`) from `setup_standard_excludes()` in `dir.c` into the new getter, preparing the ground for the next patch to migrate `excludes_file` into `struct repo_config_values`.

The patch touches three files: `dir.c` (replacing direct access to `excludes_file` with the getter), `environment.c` (implementing the getter), and `environment.h` (declaring the function). The implementation is straightforward, but the commit message notes a temporary reliance on global state, which the next patch will address. The change is mechanical and does not alter user-visible behavior, but it is a critical step toward eliminating global variables.

Reviewers are likely to focus on the correctness of the getter’s logic and its interaction with the existing lazy-loading pattern. The patch includes a TODO comment acknowledging the remaining global state dependency, which the series aims to resolve. The author is mentored by Christian Couder and two others, suggesting guidance from experienced contributors. This patch sets up the memory management and abstraction needed for the follow-up commit, which will handle the actual migration into `struct repo_config_values`.
