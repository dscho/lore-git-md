This is a **performance instrumentation patch** in the commit-reach subsystem, part of the ongoing `paint_down_to_common()` optimization series. The patch adds **trace2 step-counting** to `paint_down_to_common()` so that the number of commits visited during merge-base calculations becomes observable via `GIT_TRACE2_EVENT`. This is a **diagnostic enhancement** rather than a behavior change—it lets developers measure the impact of future optimizations without relying solely on wall-clock benchmarks.

The implementation is straightforward: a `steps` counter is incremented for each commit processed, and the final count is emitted via `trace2_data_intmax()`. The test suite (`t6600-test-reach.sh`) is updated to capture trace2 output per commit-graph mode (none, full, half, no-gdat) and assert deterministic step counts for existing test cases. A new helper, `test_paint_down_steps()`, verifies the step counts across all modes, and a new test (`merge-base --all commit-walk steps`) exercises the instrumentation with a large commit history (80-81 steps).

This patch is **well-motivated and uncontroversial**. The step-counting is lightweight (a single integer increment per commit) and the trace2 output is opt-in via environment variables. The test updates are thorough, covering edge cases (self, pending-stale, infinity-both-sides) and mixed finite/INFINITY generation numbers. The deterministic assertions provide strong regression protection for the optimization introduced earlier in the series.

The patch is **ready for merging**—it addresses a clear need (measurable performance tracking) with minimal overhead and no risk of regressions. The test coverage is comprehensive, and the instrumentation aligns with the series’ goal of self-verifying performance. No further changes are expected.
