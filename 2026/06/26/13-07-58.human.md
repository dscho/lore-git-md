This is a **documentation patch** that adds a new technical document explaining the `paint_down_to_common()` algorithm used in Git’s merge-base computation. It is the first patch in a **post-merge follow-up series (v3 1/8)** that builds on an already-merged optimization for the commit-reach subsystem.

The document provides a clear, high-level overview of how `paint_down_to_common()` works, covering its two primary use cases (finding all merge bases and ancestry checks), the paint-walk algorithm, generation number regions (finite vs. INFINITY), and termination conditions. It explains the role of generation numbers in ensuring topological traversal and how the walk handles commits not present in the commit-graph (the INFINITY region). The termination section clarifies why the walk can safely exit early once all queued commits are marked STALE, as no new merge-base candidates can emerge.

The patch adds the new document (`Documentation/technical/paint-down-to-common.adoc`) and updates the build system (`Makefile` and `meson.build`) to include it. It also tweaks the existing doc comment in `commit-reach.c` to reference the new document. The writing is concise and well-structured, making it accessible to contributors who need to understand or modify the merge-base logic. Junio C Hamano previously praised the documentation in v2 as "great," "very clear," and "concise," which suggests this patch is a polished and uncontroversial addition.

This patch is **purely additive** and does not change any code behavior. It is a **low-risk, high-value** contribution that will help future contributors navigate the commit-reach subsystem.
