This is a **substantive review** from Junio C Hamano on the eighth patch in Taylor Blau’s RFC series, which introduces `--stdin-packs=follow-reachable` to `git pack-objects`. The patch is part of the effort to combine `--geometric` and `--cruft` repack modes.

Junio identifies a **potential correctness issue** in the two-phase traversal logic. The current implementation marks *all* tag objects found in included packs (and loose objects, if `--unpacked` is given) with the `IN_INCLUDED_PACK` flag and adds them to the pending list for the second-phase traversal. This risks retaining unreachable tags and objects reachable only from those tags, which could incorrectly include unreachable objects in the output pack. The intended behavior is to include only objects that are both reachable from references *and* present in an included pack, so the pending list should be limited to tags that are themselves reachable from refs.

The review focuses on two helper functions—`mark_included_pack_tip()` and `mark_loose_object_tip()`—both of which follow the same pattern. Junio’s concern applies equally to both: the current logic may over-retain objects by not filtering out unreachable tags before adding them to the pending list. This could undermine the goal of separating reachable and unreachable objects when combining geometric and cruft repacks.

This is a **non-trivial correctness issue** that could affect the core functionality of the series. The fix would likely involve modifying the pre-walk phase to verify reachability from refs before adding tags to the pending list, rather than adding all tags found in included packs. The review does not suggest a specific implementation, but the implication is that the current approach may need rethinking to avoid including unreachable objects in the output pack.
