This is the second patch in the v5 series introducing `--linearize` to `git replay`. It is a **refactoring and documentation patch** with no behavior change, addressing readability concerns raised in prior reviews.

The patch improves clarity in `pick_regular_commit()` by renaming the `onto` parameter to `default_base` (a more accurate name) and reordering function parameters to group `struct commit` arguments together. More importantly, it **adds detailed code comments** explaining how the function selects a base commit: it looks up the parent of the commit being replayed (`pickme`) in `replayed_commits`, and falls back to `default_base` if no ancestor is found. The comments explicitly document the special case for `REPLAY_MODE_REVERT`, where commits are replayed in reverse order, so the lookup always fails and `last_commit` is used instead.

This patch directly responds to feedback from Junio and Patrick Steinhardt, who objected to the `enum replay_mode` refactoring in v4 on grounds of readability and future extensibility. Instead of changing the function signature, Toon now **clarifies the existing logic** with comments, making the code easier to understand without altering its behavior. The patch is uncontroversial and appears ready for integration. It also uncovered a bug in the `--linearize` implementation (fixed in patch 3/3), where `replayed_base` was incorrectly handled when replaying multiple divergent branches with `--onto`.
