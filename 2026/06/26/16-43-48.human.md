This is a minor but important utility patch in the ongoing `git cat-file --batch-command` security-hardened series. Karthik Nayak points out a small documentation nit in the commit message: the function `strtoul_szt()` returns a `size_t`, not an `unsigned long`, and the commit message should reflect that.

The patch itself adds a safe numeric conversion helper, `strtoul_szt()`, to Git’s compatibility layer. This function converts a string to a `size_t` with full error checking—rejecting negative values, validating that the entire string was consumed, and propagating `errno` from the underlying `strtoul` call. It follows the established pattern of similar helpers like `strtoul_ui()` and will be used in the upcoming `remote-object-info` command to handle object size fields, which were recently changed from `unsigned long` to `size_t` for better type safety.

The implementation is clean and uncontroversial. The only change needed is the commit message correction Karthik identified. The patch is part of a well-reviewed, fourteenth-iteration series that has addressed all prior feedback, including memory safety and protocol compatibility concerns.
