This is the ninth patch in Taylor Blau’s ten-patch RFC series combining `git repack --geometric` and `--cruft`. It teaches `git pack-objects` to accept a `--refs-snapshot=<path>` option when used with `--stdin-packs=follow-reachable`, ensuring that the set of reachable objects seen by `pack-objects` matches the set seen by the MIDX bitmap writer.

The patch is a small but critical correctness fix. Without it, a reference update between the time the geometric pack is written and the MIDX bitmap is generated can cause reachable objects to be incorrectly placed in the cruft pack, depriving them of bitmap coverage and forcing fetches to load the cruft pack. The snapshot file uses the same one-OID-per-line format as the MIDX bitmap writer, with an optional `+` prefix for preferred bitmap commits, allowing the same file to be shared between both tools.

The implementation adds a new `stdin_packs_refs_snapshot` global variable, a `read_refs_snapshot()` helper that parses the snapshot file and adds each OID as a pending object, and a conditional in `stdin_packs_add_reachable_pack_entries()` that uses the snapshot instead of iterating live references. The patch also updates the man page to document the new option and adds a safety check in `cmd_pack_objects()` to ensure `--refs-snapshot` is only used with `--stdin-packs=follow-reachable`.

Files touched: `Documentation/git-pack-objects.adoc` (man page update) and `builtin/pack-objects.c` (core logic). The change is confined to the pack-objects subsystem and has no on-disk format impact. It is a prerequisite for the final patch in the series, which will wire everything together in `git repack`.
