Originating author: Junio C Hamano

Core problem or goal
Fix two related issues in `git history --reword`: (1) an inefficient file-handling pattern in `fill_commit_message()` that writes a buffer to a file, flushes it, then reopens the file in append mode; (2) a file stream leak that can cause problems on Windows by leaving the file handle open before launching the external editor.

Current status
Patch is ready for merge; Junio describes it as "tested and merge-ready." The fix is minimal (8 insertions, 7 deletions) and targets only `fill_commit_message()` in `builtin/history.c`. It consolidates file handling by opening the target file (`path`) once in write mode upfront, writing the initial message buffer directly to the stream, and explicitly closing the stream before launching the editor. The issue was introduced in d205234c (January 2026) and the patch credits Johannes Schindelin with diagnosing the problem.

Key technical details
Files touched: `builtin/history.c`
Function modified: `fill_commit_message()`
New behavior: opens file once in write mode, writes buffer directly, closes stream before editor launch
Old behavior: wrote buffer to file, flushed, reopened in append mode, left stream open
Platform impact: fixes Windows compatibility issue (open file handles blocking other processes)
Test coverage: no test failures or edge cases mentioned; fix is well-contained
