This is the **eighth patch in Taylor Blau’s RFC series** to combine `git repack --geometric` and `--cruft` modes. It introduces the new `--stdin-packs=follow-reachable` mode to `git pack-objects`, a key technical piece of the integration.

The patch teaches `git pack-objects` to accept a new `--stdin-packs=follow-reachable` option. Unlike the existing `--stdin-packs=follow` (which includes all objects from listed packs and then rescues reachable ones), `follow-reachable` starts from reference tips and only includes objects that are both reachable *and* belong to an included pack (or are reachable from a commit or tag in one). Objects in excluded-open packs (`!`) are traversed but not included; objects in excluded-closed packs (`^`) halt the traversal entirely. The implementation uses a two-phase approach: first marking commits and tags in included packs (and loose objects, if `--unpacked` is given) with an `IN_INCLUDED_PACK` flag, then walking from reference tips to identify which marked objects are reachable, and finally using those reachable marked objects as tips for a full object traversal.

The patch touches `builtin/pack-objects.c` (adding the new mode, helper functions, and callbacks), updates the `git-pack-objects` man page, and adds four new tests in `t/t5331-pack-objects-stdin.sh` covering basic reachability filtering, open/closed pack boundaries, `--unpacked` with loose objects, and loose annotated tags. The new mode is designed specifically for geometric repacking with cruft packs, ensuring the output pack contains only reachable objects so that unreachable ones can be collected separately.

This is the **integration-phase patch** of the series, following six refactoring patches and one preparatory patch (extracted `stdin_packs_add_all_pack_entries`). The new mode is not yet wired into `git repack` (that happens in patch 9/10), but the plumbing is now in place. The implementation is careful to respect the existing pack exclusion semantics while adding the new reachability constraint, and the tests cover the key edge cases (unreachable objects, open/closed pack boundaries, loose objects, annotated tags). The patch is well-motivated and appears technically sound, though the complexity of the two-phase traversal and the interaction with `--unpacked` may attract scrutiny during review.
