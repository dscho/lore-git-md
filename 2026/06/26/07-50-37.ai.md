This is the second patch in a two-patch refactoring series targeting the libification effort. It completes the migration of the global `excludes_file` variable into `struct repo_config_values`, following the getter abstraction introduced in the first patch.

The patch adds proper heap memory management for `excludes_file` by extending `repo_config_values_clear()` to free both `excludes_file` and `attributes_file`. It also updates `git_default_core_config()` to store the excludes file path directly in the repository's config struct rather than the global variable. The temporary guard (`if (repo != the_repository)`) remains in both the getter and cleanup functions to avoid BUG() assertions in uninitialized submodules, a pattern reused from prior libification work.

Key technical details for follow-up discussion: the interaction between the new cleanup helper and existing lazy-loading logic in `repo_excludes_file()`, the correctness of the memory management (heap allocation/freeing), and the validity of the submodule guard pattern. The patch touches core files (`environment.c`, `environment.h`, `repository.c`) and is foundational for further libification, but does not change user-visible behavior.

The author has addressed feedback from v1: proper initialization of `excludes_file` to NULL, and ensuring `attributes_file` is also freed in the cleanup function. The series is mentored by Christian Couder and two other contributors, suggesting it has experienced oversight. Reviewers are likely to focus on the memory management and the submodule guard, as these are critical for correctness in a refactoring that touches repository initialization and cleanup paths.
