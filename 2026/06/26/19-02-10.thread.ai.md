Core problem or goal
Allow `git repack` to combine `--geometric` and `--cruft` modes, which are currently mutually exclusive. The goal is to let repositories maintain a geometric progression of reachable packs while simultaneously collecting unreachable objects into cruft packs, streamlining maintenance workflows. The series introduces `--stdin-packs=follow-reachable` to enable precise reachability filtering during pack generation, ensuring geometric repacks can coexist with cruft pack collection. A critical correctness fix in patch 9/10 ensures consistency between `git pack-objects` and the MIDX bitmap writer by introducing `--refs-snapshot=<path>`, preventing reference updates from causing reachable objects to be incorrectly placed in cruft packs.

Key technical details
- New CLI options:
  - `git pack-objects --stdin-packs=follow-reachable` (patch 8/10): Starts from reference tips and includes only objects that are both reachable *and* belong to an included pack (or are reachable from a commit/tag in one). Objects in excluded-open packs (`!`) are traversed but not included; objects in excluded-closed packs (`^`) halt traversal entirely.
  - `git pack-objects --refs-snapshot=<path>` (patch 9/10): Uses a snapshot file (same format as MIDX bitmap writer) to ensure reachability consistency between `pack-objects` and the MIDX bitmap writer. The snapshot file contains one OID per line, with an optional `+` prefix for preferred bitmap commits.
- Two-phase traversal implementation (patch 8/10):
  1. **Marking phase**: Commits and tags in included packs (and loose objects, if `--unpacked` is given) are marked with an `IN_INCLUDED_PACK` flag.
  2. **Reachability phase**: Walks from reference tips to identify which marked objects are reachable, then uses those as tips for a full object traversal.
- Implementation details (patch 9/10):
  - New global variable: `stdin_packs_refs_snapshot`.
  - New helper: `read_refs_snapshot()` parses the snapshot file and adds each OID as a pending object.
  - Conditional in `stdin_packs_add_reachable_pack_entries()` uses the snapshot instead of iterating live references.
  - Safety check in `cmd_pack_objects()` ensures `--refs-snapshot` is only used with `--stdin-packs=follow-reachable`.
- Files touched: `builtin/pack-objects.c` (core logic, helper functions, callbacks), `Documentation/git-pack-objects.txt` (man page updates), `t/t5331-pack-objects-stdin.sh` (new tests for `follow-reachable`).
