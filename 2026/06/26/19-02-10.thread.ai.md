Core problem or goal
Allow `git repack` to combine `--geometric` and `--cruft` modes, which are currently mutually exclusive. The goal is to let repositories maintain a geometric progression of reachable packs while simultaneously collecting unreachable objects into cruft packs, streamlining maintenance workflows. The series introduces `--stdin-packs=follow-reachable` to enable precise reachability filtering during pack generation, ensuring geometric repacks can coexist with cruft pack collection. A critical correctness fix ensures consistency between `git pack-objects` and the MIDX bitmap writer by introducing `--refs-snapshot=<path>`, preventing reference updates from causing reachable objects to be incorrectly placed in cruft packs.

Key technical details
- **New CLI behavior**: `--cruft` no longer implies `-a` when combined with `--geometric`.
- **Reachability filtering**: `--stdin-packs=follow-reachable` ensures only reachable objects from rolled-up packs are included in the geometric pack, leaving unreachable objects for the cruft writer. The implementation uses a two-phase traversal: first marking objects in included packs, then walking from reference tips. Junio's review and Taylor's reply highlight a critical flaw in this logic: *all* tag objects found in included packs (and loose objects, if `--unpacked` is given) are marked and added to the pending list, regardless of reachability from refs. Taylor proposes reordering the traversal to first walk from reference tips, then mark objects as starting points only if they appear in included packs and are reachable. This would require significant rework of the two-phase logic. The conditional `if (type != OBJ_COMMIT && type != OBJ_TAG)` in `mark_included_pack_tip()` was confirmed correct after a brief discussion; no changes were made.
- **Cruft pack generation**: The cruft writer (`write_cruft_pack()`) interprets the geometric split, treating packs above the split as reachable (excluded from cruft) and those below as candidates for cruft collection. Promisor packs are handled similarly, with their own split point.
- **Refs snapshot**: Used to ensure reachability consistency between `pack-objects` and the MIDX bitmap writer.
