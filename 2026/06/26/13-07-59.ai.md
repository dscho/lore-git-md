This is a **test patch** in the `commit-reach` performance optimization series. It adds **four new test cases** to `t6600-test-reach.sh` to exercise edge-case behavior in the `paint_down_to_common()` side-exhaustion optimization, ensuring the optimization works correctly in scenarios that the existing 10x10 grid topology does not cover.

The new tests target specific edge cases:
- **`in_merge_bases_many:self`**: A commit is both the query target (`A`) and one of the inputs (`X`), testing self-referential merge-base queries.
- **`get_merge_bases_many:duplicate-twos`**: Duplicate entries in the `X` list, verifying the function handles redundant inputs without incorrect deduplication or crashes.
- **`get_merge_bases_many:pending-stale`**: A diamond-shaped topology (`ps-*`) where a commit transitions from `(PARENT1|PARENT2)` to `(PARENT1|PARENT2|STALE)` during the walk, exercising the STALE propagation logic in `paint_down_to_common()`.
- **`get_merge_bases_many:infinity-both-sides`**: A topology (`pi-*`) where both query tips are outside the commit-graph (generation = `INFINITY`) and have non-monotonic commit dates, testing the fallback to commit-date ordering and the INFINITY-gate termination condition.

The patch extends the test setup to include the two new topologies (`ps-*` and `pi-*`), with detailed ASCII-art comments explaining their structure and purpose. The `ps-*` topology is designed to trigger the `(PARENT1|PARENT2) -> (PARENT1|PARENT2|STALE)` transition, while the `pi-*` topology ensures the walk correctly handles `INFINITY` generation numbers and non-monotonic dates. All tests use `test_all_modes` to validate behavior across commit-graph modes (none, full, half, no-gdat).

This is the **second patch in the v3 series** (2/8) and was originally authored by Elijah Newren (via GitGitGadget) as part of PR #2150. The test cases are **well-motivated** and directly address feedback from earlier iterations, particularly around edge-case coverage. The patch is **low-risk** (test-only) and **uncontroversial**, with no behavioral changes to Git itself. It complements the optimization in patch 1/8 by ensuring the side-exhaustion logic is robust across diverse topologies and commit-graph states. The test names and comments are **clear and descriptive**, making the intent and coverage obvious to future maintainers.
