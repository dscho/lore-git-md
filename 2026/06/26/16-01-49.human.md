This is a platform compatibility fix for Patrick Steinhardt’s RFC v2 patch series that moves Git’s `libgit.a` sources into a new `lib/` directory. Johannes Schindelin (Git for Windows maintainer) reports a missing path adjustment in the GitHub Actions workflow file (`.github/workflows/main.yml`) that breaks the `vs-build` job on Windows. The fix adds a single line to ensure the `compat` directory is correctly referenced under the new `lib/` structure.

The change is minimal and targeted: it updates the `get-azure-pipelines-artifact` step to point to `lib/compat` instead of the now-incorrect root-relative path. Johannes provides a link to a successful CI run demonstrating the fix works. This is a straightforward follow-up to the broader reorganization effort, addressing a Windows-specific build issue that surfaced during testing. No controversy or debate here—just a necessary tweak to keep the build functional across platforms. Downstream consumers should note this as a minor but essential correction to the series.
