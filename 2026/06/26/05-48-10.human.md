This is the v5 iteration of Toon Claes’s feature series adding a `--linearize` option to `git replay`. The series teaches `git replay` to flatten merge commits into linear history, mirroring `git rebase --no-rebase-merges`.

The biggest change in v5 is a **substantive fix** for a bug in how `pick_regular_commit()` handles the `replayed_base` parameter when rebasing multiple divergent branches with `--onto`. The bug caused incorrect base selection, leading to wrong commit ordering. Toon discovered this while refactoring to address earlier feedback about the enum-to-boolean conversion (which he ultimately dropped). The fix includes a new test case that verifies correct behavior when replaying two branches (`topic2` and `topic-with-merge`) onto `main`.

The series now consists of three patches: two refactors (adding a `put_mapped_commit()` helper and improving code comments to clarify base selection) and the main implementation. The `--linearize` option is documented as incompatible with `--revert`, and the man page now includes it in the SYNOPSIS. Test coverage has expanded to verify edge cases like root commits, `--advance` combinations, and patch preservation via `git range-diff`.

This version addresses all prior architectural concerns. The enum-to-boolean refactoring is gone, replaced with clearer code comments that explain the base-selection logic. The interface scope debate (whether `--linearize` should support all `git rebase` modes) remains unresolved but is now deferred to future work—Toon’s current implementation hardcodes the `--no-rebase-merges` behavior, which aligns with the series’ stated goal.
