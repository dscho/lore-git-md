This is the v5 revision of Toon Claes’s series introducing a `--linearize` option to `git replay`, a feature addition that flattens merge commits to match the default behavior of `git rebase --no-rebase-merges`. The series is now three patches: two refactoring patches (one new, one carried over) and the core implementation patch, which has been substantially revised to fix a logic error in `--onto` handling when rebasing multiple divergent branches.

The most significant change in v5 is the removal of the controversial `enum replay_mode` → boolean `reverse` refactoring (patch 1 in v4). Instead, Toon added a new patch (now patch 2) that extends code comments to clarify how `pick_regular_commit()` selects a base commit. While writing those comments, he discovered and fixed a bug in the `--onto` logic: when replaying multiple branches with `--linearize`, the `replayed_base` parameter was incorrectly reused across branches, causing commits to be replayed onto the wrong base. The fix is accompanied by a new test case that verifies correct behavior when rebasing two divergent branches (`topic2` and `topic-with-merge`) onto `main`.

The core `--linearize` implementation (patch 3) remains largely unchanged in functionality but has been reordered and re-commented for clarity. The commit message now explicitly documents the edge-case behavior: merge commits are dropped, root commits are replayed, and `last_commit` is left unchanged during merge linearization so that subsequent commits are reparented onto the previous non-merge commit. The test suite has been expanded to cover the new `--onto` scenario and continues to verify `--linearize` with `--advance`, `--revert`/`--linearize` mutual exclusivity, and patch equivalence via `git range-diff`.

All prior review feedback has been addressed: Junio’s surface-level comments, Elijah Newren’s requests for improved documentation and test coverage, and Patrick Steinhardt’s concerns about the enum-to-bool refactoring. The series is now positioned as a simpler alternative to Johannes Schindelin’s merge-replay work (pull.2106) and is ready for final review. The only remaining open question is whether the interface should be extended now to mirror `git rebase`’s three-mode design (`--no-rebase-merges`, `--rebase-merges`, `--rebase-merges=rebase-cousins`), but Toon has stated a preference for implementing only the default behavior now and extending later. No merge status is reported.
