This thread is about a documentation patch by Harald Nordgren that adds hints for `git rebase --abort` in two contexts: when an "exec" command fails during rebase, and in rebase status messages. The goal is to make the `--abort` option more discoverable for users interrupted during rebase operations.

The discussion has revealed that the exec-failure hint targets a niche workflow—using `git rebase` as a control structure to run checks on each commit, where a single exec failure should terminate the entire process. This framing has sparked debate about whether Git should accommodate this use case with built-in hints or expect users to handle it via external scripts. Junio Hamano and Phillip Wood argue that aborting after a single exec failure isn’t a "normal" rebase use case, and Junio suggests this might be better served by a dedicated command. Meanwhile, the status-message additions remain uncontroversial.

Phillip Wood’s latest reply challenges the patch’s core motivation, asking why a user would want to check commits but not fix the failing ones. This sharpens the thread’s central question: does the patch address a real user need, or is it optimizing for an edge case? The exec-failure hint’s design (a split message with conditional logic) is now agreed upon, but its necessity and the workflow it supports remain contested. No new technical changes have been proposed, but the author must now justify the workflow’s validity or reconsider the patch’s scope. The thread’s future direction hinges on this response.
