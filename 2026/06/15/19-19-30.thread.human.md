This thread is about a small but user-facing documentation patch from Harald Nordgren that adds `--abort` hints to Git rebase failure and status messages. The goal is to improve consistency: currently, `--abort` is only mentioned in conflict scenarios, but not when an "exec" command fails during rebase or in the status help text during interactive editing.

The series is still at its first version. The status-message changes (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial, but the exec-failure addition in `sequencer.c` has sparked debate. Phillip Wood argues that suggesting `--abort` for exec failures (like test failures) could mislead users into thinking it’s the recommended action, while Junio C Hamano sees it as a harmless "escape hatch" for new users. Harald’s latest email adds a personal anecdote—he once struggled with an ill-planned rebase and wished the hint had been there—reinforcing Junio’s framing. No alternative wording or code changes have been proposed yet, but the maintainer’s stance may shape the final version. The discussion remains open on whether the exec-failure hint stays, and if so, how it’s phrased.
