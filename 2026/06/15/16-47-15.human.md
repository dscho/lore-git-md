This is v15 of Harald Nordgren's series adding `git branch --delete-merged` for safe automated local branch cleanup, now renamed from `--prune-merged` based on feedback. The series has evolved through 15 iterations with all major technical concerns addressed.

The key changes in this version:
- Renamed the option from `--prune-merged` to `--delete-merged` throughout
- Now silently skips unmerged branches rather than warning about them
- Added support for bare remote names (e.g. "origin") as shorthand for the branch its origin/HEAD points to
- Improved initialization and documentation in the bulk deletion code
- Expanded test coverage with more realistic scenarios

The feature provides automated cleanup of local branches whose work has landed upstream, with several safety mechanisms:
- Never deletes checked-out branches
- Skips branches where the upstream no longer exists
- Preserves branches that push to the same place as their upstream
- Allows per-branch opt-out via `branch.<name>.deleteMerged` config
- Includes a `--dry-run` mode to preview deletions

The implementation builds on the existing `--forked` filter and handles edge cases like detached HEAD states and various push/upstream configurations. The test suite has been significantly expanded to cover these scenarios.

This appears to be the final iteration before potential merging, with all known issues addressed and thorough test coverage. The rename from `--prune-merged` to `--delete-merged` seems to better match Git's existing terminology for destructive operations.
