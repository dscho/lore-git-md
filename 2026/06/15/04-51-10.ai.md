This is part 2 of a 4-patch series from a GSoC participant that refactors path handling in Git. The patch focuses on `rev-parse`, eliminating its duplicate path formatting logic in favor of the new shared `append_formatted_path()` helper introduced earlier in the series.

The key changes in this patch:
- Removes local `format_type` and `default_type` enums from `rev-parse.c`
- Replaces custom path formatting code with calls to `append_formatted_path()`
- Introduces `PATH_FORMAT_DEFAULT` to handle per-path fallback behavior
- Maintains all existing functionality while reducing code duplication

The implementation has been thoroughly reviewed through multiple iterations, with substantive feedback from Justin Tobler and Lucas Seiki Oshiro. The changes align with Git's philosophy of explicit over implicit for plumbing commands, and the test coverage remains comprehensive.

This is a clean refactoring that removes 80 lines of redundant code while preserving all existing behavior. The patch appears ready for integration, having addressed all reviewer feedback in previous versions. The series as a whole represents a solid improvement to Git's path handling infrastructure.
