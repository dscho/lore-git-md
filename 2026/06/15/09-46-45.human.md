This is a review of patch 1/6 in Harald Nordgren's v14 series adding `git branch --delete-forked` functionality (previously called `--prune-merged`). The series aims to provide safe automated cleanup of local branches that have been merged upstream.

Phillip Wood provides substantive feedback on the implementation of the `--forked` filter, which is the foundational building block for the deletion functionality. His review focuses on several technical aspects:

1. Suggests restoring support for "origin" shorthand (matching origin/HEAD) to maintain consistency with `git checkout -b` behavior
2. Notes the test setup could be more realistic by including local commits on branches rather than just tracking upstreams
3. Points out missing test coverage for combining `--forked` with explicit branch name arguments
4. Observes the test uses "detached" in a potentially confusing way (as a branch name rather than detached HEAD state)
5. Recommends using `add -f` to simplify test setup by combining remote addition and fetch

The review acknowledges the code's overall quality and the significant reduction in lines from moving logic to ref-filter.c. Phillip's feedback is constructive and focused on making the implementation more robust and consistent with Git conventions, without requesting major changes to the core functionality.

This continues the pattern of thorough technical review for this long-running series, now in its 14th iteration. The feedback appears aimed at final polish rather than identifying fundamental issues.
