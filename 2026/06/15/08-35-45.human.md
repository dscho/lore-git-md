This is a platform compatibility discussion about testing large object handling on Windows (LLP64) systems. Patrick Steinhardt is reviewing Philip Oakley's patch series that enables Git to handle objects larger than 4GB on Windows, where `unsigned long` is 32-bit but `size_t` is 64-bit.

The current patch adds a test case verifying that `git hash-object --stdin` works correctly with 5GB files on such systems. Patrick suggests removing the `!LONG_IS_64BIT` test prerequisite, which would make the test run on all platforms where `size_t` is 64-bit, not just LLP64 systems like Windows. This follows his earlier suggestion in the thread to broaden the test coverage.

The series is already well-validated, having been used in Git for Windows for years, with Johannes Schindelin's sign-off. The only remaining questions are about test scope (Patrick's suggestion) and a potential `objsize_t` typedef for future consistency (raised earlier in the thread). The changes are mechanical and low-risk, addressing a long-standing platform limitation.
