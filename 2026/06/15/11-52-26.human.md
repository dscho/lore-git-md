This is the fourth patch in Johannes Schindelin's series addressing Windows-specific issues with handling objects larger than 4GB. The patch focuses on widening the `unpack_entry()` function's size parameter from `unsigned long` to `size_t` to properly handle large objects on Windows where `unsigned long` is only 32-bit.

The changes are primarily mechanical but require careful handling of compatibility layers:
- Updates `unpack_entry()` and related functions in packfile.c to use `size_t` for object sizes
- Maintains transitional compatibility with `fast-import` via temporary size casting
- Preserves existing behavior for `packed_object_info_with_index_pos()` until its interface can be updated in a future patch
- Affects delta base cache and compressed entry unpacking paths

The patch includes a temporary bridge for `fast-import` (which still uses `unsigned long` throughout) and notes this will be removed in a future commit. Patrick Steinhardt had previously suggested adding a `NEEDSWORK` comment about the transitional casting, but Dscho responded that the function name `cast_size_t_to_ulong()` serves as sufficient documentation of its temporary nature.

This is a well-contained change that builds on the previous patches in the series while maintaining compatibility with unconverted subsystems. The patch has already received substantive review from Patrick Steinhardt in v1, with no new technical concerns raised in v2.
