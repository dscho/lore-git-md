Windows platform patch updating MSVC's `ftruncate()` compatibility layer to properly handle large files (>4GB) where `size_t` is 64-bit but `unsigned long` is 32-bit. This is the first patch in a 7-part series addressing Windows-specific large object handling.

The change replaces the problematic `_chsize` shim (which silently caps files at 2GB) with `_chsize_s` (which supports 64-bit sizes), while carefully maintaining POSIX return conventions (-1 for errors). The new `msvc_ftruncate()` wrapper translates `_chsize_s`'s non-POSIX return values (0 for success, errno for failure) to match existing callers' expectations in `http.c`, `parallel-checkout.c`, and test code. The patch fixes test failures in t7508 where `git add` was failing with 4GB+ files due to silent truncation.

Key technical details:
- Preserves API compatibility for existing callers checking return values
- Places wrapper after `mingw-posix.h` include to ensure correct `off_t` resolution
- Leaves MinGW builds unaffected (they already use proper 64-bit `ftruncate64`)
- Includes detailed inline documentation of the compatibility considerations

This is a well-considered platform-specific fix that maintains backward compatibility needed by multiple subsystems while enabling proper large file support on Windows. The change is narrowly scoped to the MSVC compatibility layer and has clear motivation from test failures. As the first patch in a larger series, it sets up the foundation for subsequent 64-bit size handling improvements.
