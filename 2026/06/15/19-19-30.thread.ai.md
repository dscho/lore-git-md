Thread identity: Documentation patch adding `git rebase --abort` hints to failure and status messages, authored by Harald Nordgren. Series remains at v1.

Core problem or goal: Improve rebase user interface consistency by adding `--abort` advice in two scenarios where only `--continue` was previously mentioned: when an "exec" step fails during rebase, and in status help text during commit splitting/editing. The goal is to reduce user confusion by making the abort option more discoverable in all rebase interruption contexts.

Current status: Initial version (v1) of patch series. The status-message additions (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial. The exec-failure addition (in `sequencer.c`) remains contested, with both Phillip Wood and Junio C Hamano having weighed in with substantive positions. No code changes have been proposed yet, but the maintainer’s framing and user feedback may influence future wording.

Key technical details: Modifies three files: `sequencer.c` (exec-failure message), `wt-status.c` (rebase status help), and `t/t7512-status-help.sh` (tests). The exec-failure change parallels existing conflict-case advice; the status-message changes follow established patterns. The exec-failure message in `sequencer.c` is the sole point of contention, with no alternative implementations or wording proposed.

Open questions and loose ends: Whether the exec-failure case warrants `--abort` advice, and if so, whether the wording should be adjusted to avoid implying abort is the recommended action. Phillip Wood argues the hint could mislead users into thinking abort is preferable for minor exec failures (e.g., test failures), while Junio C Hamano views it as a harmless "escape hatch" for new users. Harald Nordgren’s follow-up provides anecdotal support for Junio’s framing, emphasizing real-world user confusion in ill-planned rebases. No alternative wording or behavior has been proposed, and the discussion remains focused on user experience rather than technical implementation.

Participant positions:
- Harald Nordgren (author): Proposes adding `--abort` advice to exec-failure messages for consistency with conflict cases. Provides anecdotal evidence of user confusion in ill-planned rebases, reinforcing the need for the hint as an "escape hatch." Position is substantive (engages with user experience and real-world pain points).
- Phillip Wood (reviewer): Objects to the exec-failure addition on workflow grounds, arguing it misleads users into thinking abort is the recommended action for minor exec failures (e.g., test failures). Position is substantive (engages with user behavior and edge cases).
- Junio C Hamano (maintainer): Supports the hint as a low-cost training aid for new users, framing it as an "escape hatch" rather than a workflow recommendation. Position is substantive (engages with user experience and learning curves). No review trailers yet.
