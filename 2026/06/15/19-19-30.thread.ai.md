Thread identity: Documentation patch adding `git rebase --abort` hints to failure and status messages, authored by Harald Nordgren. Series remains at v1.

Core problem or goal: Improve rebase user interface consistency by adding `--abort` advice in two scenarios where only `--continue` was previously mentioned: when an "exec" step fails during rebase, and in status help text during commit splitting/editing.

Current status: Initial version (v1) of patch series. The status-message additions (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial. The exec-failure addition (in `sequencer.c`) is now contested.

Key technical details: Modifies three files: `sequencer.c` (exec-failure message), `wt-status.c` (rebase status help), and `t/t7512-status-help.sh` (tests). The exec-failure change is a straightforward text addition that parallels existing conflict-case advice; the status-message changes follow established patterns.

Open questions and loose ends: Whether the exec-failure case is sufficiently analogous to conflict cases to warrant `--abort` advice. Phillip Wood argues that exec failures are typically minor (e.g., test failures) where continuing is usually preferable, making `--abort` advice potentially misleading. No alternative wording or behavior has been proposed yet.

Participant positions:
- Harald Nordgren (author): Proposes adding `--abort` advice to exec-failure messages for consistency with conflict cases.
- Phillip Wood (reviewer): Objects to the exec-failure addition on workflow grounds, arguing it misleads users into thinking abort is the recommended action. Position is substantive (engages with user behavior and edge cases). No review trailers yet.
