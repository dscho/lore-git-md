Thread identity: Documentation patch adding `git rebase --abort` hints to failure and status messages, authored by Harald Nordgren. Series remains at v1.

Core problem or goal: Improve rebase user interface consistency by adding `--abort` advice in two scenarios where only `--continue` was previously mentioned: when an "exec" step fails during rebase, and in status help text during commit splitting/editing. The goal is to reduce user confusion by making the abort option more discoverable in all rebase interruption contexts, framed as a low-cost "escape hatch" for new users rather than a workflow recommendation.

Current status: Initial version (v1) of patch series. The status-message additions (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial and unchanged. The exec-failure addition (in `sequencer.c`) has reached full consensus on design: print two separate messages (one explaining the failure and how to continue, followed by a generic `--abort` hint). The next patch revision is expected to implement this split-message structure. Junio has signaled openness to making the abort hint non-configurable, though this is not a blocker.

Key technical details: Modifies three files: `sequencer.c` (exec-failure message), `wt-status.c` (rebase status help), and `t/t7512-status-help.sh` (tests). The exec-failure change will now parallel the conflict-case advice by splitting the message into two parts, preserving the existing warning while appending a neutral `--abort` suggestion. The status-message changes follow established patterns and remain unchanged. The exec-failure message will explicitly avoid triggering the abort hint if the failure is due to a conflict, maintaining the distinction between exec failures (where continuing is more likely) and conflicts (where aborting might be more common).

Open questions and loose ends: Final implementation of the split exec-failure message in `sequencer.c` (wording and conditional logic to exclude conflict cases). No remaining objections or alternative approaches; the discussion is now purely about code.
