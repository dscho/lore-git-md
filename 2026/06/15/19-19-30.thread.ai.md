Thread identity: Documentation patch adding `git rebase --abort` hints to failure and status messages, authored by Harald Nordgren. Series remains at v1.

Core problem or goal: Improve rebase user interface consistency by adding `--abort` advice in two scenarios where only `--continue` was previously mentioned: when an "exec" step fails during rebase, and in status help text during commit splitting/editing. The goal is to reduce user confusion by making the abort option more discoverable in all rebase interruption contexts, framed as a low-cost "escape hatch" for new users rather than a workflow recommendation.

Current status: Initial version (v1) of patch series. The status-message additions (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial and unchanged. The exec-failure addition (in `sequencer.c`) has reached full consensus on design: print two separate messages (one explaining the failure and how to continue, followed by a generic `--abort` hint). The patch is now in implementation phase, with the next revision expected to include the split-message structure in `sequencer.c` and finalize the conditional logic to exclude conflict-induced exec failures.

Key technical details: Modifies three files: `sequencer.c` (exec-failure message), `wt-status.c` (rebase status help), and `t/t7512-status-help.sh` (tests). The exec-failure change will now parallel the conflict-case advice by splitting the message into two parts: a failure-specific warning (e.g., "exec command failed: <command>") followed by a neutral `--abort` suggestion ("You can also abort the rebase with `git rebase --abort`."). The abort hint will be suppressed if the exec failure is due to a conflict, maintaining the existing distinction between exec failures (where continuing is more likely) and conflicts (where aborting might be more common). The status-message changes follow established patterns and remain unchanged.

Open questions and loose ends: None remaining. The discussion is now purely about code implementation, with all design questions resolved.
