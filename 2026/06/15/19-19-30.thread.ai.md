Thread identity: Documentation patch adding `git rebase --abort` hints to failure and status messages, authored by Harald Nordgren. Series remains at v1.

Core problem or goal: Improve rebase user interface consistency by adding `--abort` advice in two scenarios where only `--continue` was previously mentioned: when an "exec" step fails during rebase, and in status help text during commit splitting/editing.

Current status: Initial version (v1) of patch series. The status-message additions (in `wt-status.c` and tested in `t/t7512-status-help.sh`) are uncontroversial. The exec-failure addition (in `sequencer.c`) remains contested, with Junio C Hamano now weighing in.

Key technical details: Modifies three files: `sequencer.c` (exec-failure message), `wt-status.c` (rebase status help), and `t/t7512-status-help.sh` (tests). The exec-failure change parallels existing conflict-case advice; the status-message changes follow established patterns. No code changes have been proposed yet, but the maintainer’s framing may influence future wording.

Open questions and loose ends: Whether the exec-failure case warrants `--abort` advice, and if so, whether the wording should be adjusted to avoid implying abort is the recommended action. Phillip Wood argues the hint could mislead users into thinking abort is preferable for minor exec failures (e.g., test failures), while Junio C Hamano views it as a harmless "escape hatch" for new users. No alternative wording or behavior has been proposed.

Participant positions:
- Harald Nordgren (author): Proposes adding `--abort` advice to exec-failure messages for consistency with conflict cases.
