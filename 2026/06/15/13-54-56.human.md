This is part 6/10 of Patrick Steinhardt's v6 series introducing the `git history drop` subcommand, focused on refactoring Git's reset machinery. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to control whether HEAD should be updated during reset operations, addressing an awkwardness in the previous approach where callers had to opt out of reference updates.

The change modernizes the reset API by making HEAD updates explicit rather than implicit, which better supports the upcoming `git history drop` functionality that needs to update just the working tree and index. The patch updates all existing callers in rebase.c and sequencer.c to maintain current behavior by explicitly setting the new flag.

This is a clean, focused change that follows Phillip Wood's suggestion to improve the API design. It's part of the broader reset machinery modernization that underpins the new history command while also advancing the codebase's architectural cleanliness. The patch shows typical Steinhardt quality - thorough, with all call sites updated and clear commit message explaining the rationale.
