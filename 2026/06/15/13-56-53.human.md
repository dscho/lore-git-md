This is patch 7/8 in Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure. The patch fixes a recursive initialization issue with the "onbranch" config conditional that was causing reference stores to be constructed twice and leaking memory.

The core problem stems from a chicken-and-egg situation where the reference database needs to read config (including "onbranch" conditionals) during initialization, but evaluating those conditionals requires an already-initialized reference database. The current check for whether the database is initialized (looking at `ref_storage_format`) wasn't working because the format gets set too early during repository discovery.

The fix temporarily unsets the storage format during initialization, which properly gates the "onbranch" evaluation and prevents the recursion. While this means "onbranch" conditions won't be evaluated during reference store initialization, that's actually the desired behavior since we can't properly check branches at that stage anyway.

This is a well-contained fix that:
- Resolves a subtle initialization ordering issue
- Prevents memory leaks from duplicate store creation
- Maintains existing behavior where "onbranch" isn't evaluated during init
- Fits cleanly into the larger series' goal of cleaning up reference backend infrastructure

The patch has been reviewed as part of the overall series, with Karthik Nayak providing substantive feedback on related patches. It represents another incremental improvement in Patrick's ongoing effort to modernize Git's reference handling code.
