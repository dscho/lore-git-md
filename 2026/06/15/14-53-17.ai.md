This is a bug report about Git Bash on Windows incorrectly handling the GNUPGHOME environment variable. The reporter, Will Flowers, describes how Git Bash appends the GNUPGHOME value to the existing path rather than replacing it, resulting in malformed paths like "/c/Users/wiflow/C:\Users\wiflow\.gnupg" when running `gpg --version`.

The issue occurs when:
1. Git for Windows is installed with default settings
2. GPG4Win is installed (a common Windows GPG implementation)
3. GNUPGHOME environment variable is set in Windows

The bug manifests as a difference in behavior between PowerShell (which shows the expected GNUPGHOME path) and Git Bash (which incorrectly concatenates paths). The report includes clear reproduction steps and version information (Git for Windows 2.54.0.windows.1 on Windows 11 Enterprise).

This appears to be a genuine platform compatibility issue in Git Bash's environment variable handling, specifically affecting Windows path conversion between native and Unix-style paths. The bug could impact users who need to configure custom GPG home directories while using Git Bash on Windows.
