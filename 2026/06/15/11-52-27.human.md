This is the fifth patch in Johannes Schindelin's 7-part series addressing Windows compatibility with large (>4GB) objects where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch focuses on `pack-objects`, converting its in-memory object size handling from `unsigned long` to `size_t`.

The change removes size limitations that previously caused `upload-pack` to fail when serving large objects in tests. It updates all size-related functions in `pack-objects` (`oe_size`, `oe_delta_size`, etc.) to use `size_t` and removes the `cast_size_t_to_ulong()` calls that were capping sizes at 4GB. The patch maintains compatibility with existing interfaces while allowing proper handling of larger objects.

This is a mechanical but important change that builds on previous work in the series. The patch has already been reviewed by Patrick Steinhardt in v1, with no new feedback needed for this revision. The changes are straightforward and well-contained within the pack-objects subsystem, completing the type conversion for in-memory object sizes while the series will later address the remaining ODB API updates.
