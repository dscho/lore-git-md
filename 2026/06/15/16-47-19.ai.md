This is part 4/7 of Harald Nordgren's v15 series introducing `git branch --delete-merged` for safe automated branch cleanup. The patch refactors the underlying `delete_branches()` function to support new bulk operation modes needed by the upcoming feature.

Key changes in this patch:
- Adds two new flag-based operation modes to `delete_branches()`:
  - `DELETE_BRANCH_NO_HEAD_FALLBACK`: Skips the HEAD fallback check when determining merge status (used when caller already knows the branch has an upstream)
  - `DELETE_BRANCH_DRY_RUN`: Performs a deletion preview without actually removing refs
- Modifies the merge-base check logic to respect the new `NO_HEAD_FALLBACK` flag
- Implements dry-run output formatting that matches the actual deletion messages
- Maintains backward compatibility for existing callers by preserving current behavior when flags aren't set

The changes enable the series' core functionality while keeping the implementation clean and extensible. The flag-based approach follows the pattern established earlier in the series for other behaviors like `SKIP_UNMERGED`. The dry-run support will be used by `--delete-merged --dry-run` to provide a safe preview of deletions.

This is a foundational patch that enables the bulk branch operations while maintaining all existing safety checks. The implementation appears solid, with clear attention to edge cases and backward compatibility. The changes are well-contained to `builtin/branch.c` and don't introduce any new dependencies.
