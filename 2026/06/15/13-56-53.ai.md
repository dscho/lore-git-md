This is patch 7/8 in Patrick Steinhardt's series refactoring Git's reference backend infrastructure. The patch fixes a recursive initialization issue when parsing "onbranch" config conditions during ref store setup.

The core problem involves a chicken-and-egg scenario where:
1. The ref store needs config to initialize itself
2. The config needs a ref store to evaluate "onbranch" conditions
3. This leads to infinite recursion as each tries to initialize the other

The current implementation fails to properly prevent this recursion because it checks for an unconfigured ref store format, but the format is already set during repository discovery. The patch solves this by temporarily unsetting the format during ref store initialization, which properly gates the "onbranch" evaluation.

Key technical details:
- Modifies `get_main_ref_store()` in refs.c
- Temporarily sets `ref_storage_format` to UNKNOWN during initialization
- Prevents recursive calls when evaluating config conditions
- Fixes a memory leak that was masked by the chdir-notify subsystem
- Maintains consistency with worktree/submodule ref store handling

This continues the series' pattern of careful, incremental improvements to the ref backend code while avoiding the performance regressions identified in earlier versions. The change is well-contained and unlikely to be controversial, though it does touch a sensitive area of repository initialization.

The patch has already received substantive review from Karthik Nayak and addresses feedback from the previous version. It represents another step toward the series' goal of cleaning up ref backend initialization while deferring the more complex path handling questions to future work.
