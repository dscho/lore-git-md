This is part of Patrick Steinhardt's v6 series introducing the `git history drop` subcommand, specifically patch 9/10. The patch refactors reference update handling in the history command by splitting it into two distinct phases: computing pending updates and applying them.

The change separates the logic that determines which refs need updating (now in `compute_pending_ref_updates()`) from the actual transaction execution (in `apply_pending_ref_updates()`). This prepares for future work where these phases may need to be handled independently, while maintaining the same functionality. The split makes the code more modular and easier to reason about, following the pattern seen elsewhere in Git's codebase.

The patch is a mechanical refactoring with no behavior changes - all existing tests continue to pass. It's part of the larger effort to modernize Git's reset machinery and reference handling while implementing the new history manipulation features. The changes are well-contained to builtin/history.c and build on the extensive review feedback the series has received through its six iterations.
