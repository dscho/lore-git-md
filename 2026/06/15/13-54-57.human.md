This is part of Patrick Steinhardt's v6 series introducing the `git history drop` command, specifically focusing on improvements to the reset machinery. The patch adds flexibility to `reset_working_tree()` by allowing callers to specify the "from" commit (previously always derived from HEAD) via a new `oid_from` option in `reset_working_tree_options`.

The change is a small but meaningful enhancement to the reset API, making it more versatile for operations that need to reset from a specific commit rather than always using HEAD. This is particularly useful for the history drop functionality where the reset operation may need to work from a commit other than HEAD. The implementation is clean and maintains backward compatibility by falling back to HEAD when `oid_from` isn't specified.

This patch continues the series' broader theme of modernizing Git's reset machinery while supporting the new history drop feature. It's a focused change that follows the established pattern of the series - careful API improvements that enable new functionality while maintaining clean interfaces.
