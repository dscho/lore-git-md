This is part 5/10 of Patrick Steinhardt's v6 series introducing a `git history drop` subcommand, focused on adding dry-run capability to the reset machinery. The patch introduces a new `RESET_WORKING_TREE_DRY_RUN` flag that allows callers to check whether a reset operation would succeed without actually modifying the working tree or index.

The implementation creates a scratch index for dry-run operations to avoid contaminating the real index state, while maintaining all the same validation checks. Key changes include:

- New dry-run flag added to `reset_working_tree_flags` enum
- Modified index handling to use a scratch index for dry runs
- Skip lock acquisition and reference updates in dry-run mode
- Early exit after unpack_trees() completes for dry runs
- Proper cleanup of scratch index resources

This foundational change enables the subsequent `git history drop` implementation to safely check for potential conflicts before performing destructive operations. The patch follows the established pattern of the series by modernizing reset infrastructure while maintaining backward compatibility. It touches core reset.c functionality but with careful attention to isolation of the dry-run path.
