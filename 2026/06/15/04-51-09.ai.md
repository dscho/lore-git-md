This is the first patch in a 4-part series introducing standardized path formatting for repository information, part of a GSoC project. The patch extracts path formatting logic from `rev-parse` into a new shared helper function `append_formatted_path()` in `path.c`.

The new function provides consistent path formatting with several strategies:
- UNMODIFIED (output path as-is)
- RELATIVE (make path relative to given prefix)
- RELATIVE_IF_SHARED (relative only if sharing common prefix)
- CANONICAL (fully resolved absolute path)

The implementation handles edge cases like NULL prefixes by falling back to current working directory, and includes proper memory management with strbuf usage. The enum and function are added to path.h with detailed documentation. The patch appears well-structured with clear commit message and proper sign-offs from mentors.

This foundational change enables consistent path handling across Git while eliminating duplicate logic. The implementation has been through multiple review iterations and shows careful attention to edge cases and memory safety. As the first in the series, it sets up the infrastructure that subsequent patches will build upon to refactor `rev-parse` and add new path variants.
