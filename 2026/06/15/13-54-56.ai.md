This is part of Patrick Steinhardt's v6 series introducing the `git history drop` subcommand, specifically focusing on reset machinery modernization. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to explicitly control HEAD updates during reset operations, addressing an inconsistency in the previous approach where callers had to opt out of reference updates.

Key changes:
- Adds `RESET_WORKING_TREE_UPDATE_HEAD` flag to make HEAD updates explicit
- Updates all existing callers in rebase.c and sequencer.c to set the new flag
- Adds BUG() check to prevent invalid combinations (updating ORIG_HEAD without HEAD)
- Maintains backward compatibility while making the API more intentional

The change was suggested by Phillip Wood during review process to improve the reset API's clarity. This is one of several preparatory changes needed for the `git history drop` functionality, which requires precise control over reference updates during its operations. The patch follows the series' pattern of modernizing reset machinery while maintaining careful backwards compatibility.
