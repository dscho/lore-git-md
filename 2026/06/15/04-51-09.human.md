This is the first patch in a GSoC participant's series to standardize path formatting across Git commands. It introduces a new `append_formatted_path()` helper function in `path.c` that provides consistent path formatting behavior (absolute, relative, canonical) through a well-defined enum interface.

The implementation cleanly extracts path-handling logic that was previously duplicated in `rev-parse.c`, making it available to other commands. The function handles several formatting modes:
- Unmodified output (PATH_FORMAT_UNMODIFIED)
- Relative paths (PATH_FORMAT_RELATIVE)
- Conditionally relative paths for shared repos (PATH_FORMAT_RELATIVE_IF_SHARED) 
- Canonical absolute paths (PATH_FORMAT_CANONICAL)

The patch has gone through multiple rounds of review with substantive feedback from Justin Tobler and Lucas Seiki Oshiro, addressing edge cases like NULL gitdir handling and shared repository detection. The v4 changes are minor style tweaks following final review comments.

This foundational change enables the subsequent patches in the series to standardize path output in `rev-parse` and other commands while eliminating duplicate logic. The implementation appears solid with comprehensive error handling and clear documentation of the new API.
