This is the final patch (7/7) in Harald Nordgren's v15 series adding `git branch --delete-merged`, introducing a `--dry-run` option for previewing deletions. The patch completes the series' safety mechanisms by allowing users to verify which branches would be deleted before actually removing them.

The implementation:
- Adds `--dry-run` as a companion to `--delete-merged` that prints "Would delete branch <name>" for each candidate
- Maintains all existing filtering logic (forked branches, merged status checks, etc.)
- Rejects `--dry-run` when used without `--delete-merged`
- Includes comprehensive tests verifying dry-run output matches actual deletion behavior
- Documents the new option with a clear use case for previewing pattern-based deletions

The patch follows the series' established safety-first approach, with dry-run output reflecting the same strict criteria as the live operation (skipping checked-out branches, preserving pushable branches, etc.). Test coverage includes both simple cases and mixed scenarios where some branches would be preserved.

This concludes the 15-iteration development of the `--delete-merged` feature, which now provides:
1) Precise branch selection via `--forked`
2) Multiple safety mechanisms (checked-out protection, push divergence checks)
3) Per-branch opt-out via `branch.<name>.deleteMerged`
4) Preview capability with `--dry-run`
