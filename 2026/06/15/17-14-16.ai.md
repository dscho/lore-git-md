This is a tangential discussion about timestamp handling in Git, sparked by a documentation typo fix thread.

Jeff King (Peff) provides a detailed technical explanation in response to D. Ben Knoble's offhand question about timestamp_t overflow behavior. The response clarifies that while standard 32-bit time_t (signed) overflows in 2038, Git's timestamp_t (unsigned) extends to 2106. Peff notes this is a Git-specific type created because the project can't control system time_t definitions.

The email also mentions Peff's own (currently shelved) work to support negative timestamps, which would enable storing historical dates before 1970. He identifies Windows' gmtime() incompatibility as the blocking issue, though notes this is a niche concern since most modern commits use positive timestamps.

This is purely an informational exchange - no patches are proposed or discussed. The content provides useful background for anyone working with Git's time handling, particularly around the 2038/2106 transition periods and historical date support. The discussion remains technically focused, with Peff sharing implementation details from his deep knowledge of Git's internals.
