This is the second version of a platform compatibility patch series from Johannes Schindelin (Dscho) addressing Windows-specific issues with handling objects larger than 4GB where `size_t` is 64-bit but `unsigned long` is 32-bit. The 7-patch series systematically converts `unsigned long` to `size_t` for object sizes across multiple subsystems.

Key changes in v2:
- Rebased onto master to resolve conflicts with the recently merged `ps/odb-source-loose` series
- Removed superfluous `size_t` variables in `cat-file.c` as suggested by Patrick Steinhardt's review of v1

The series touches 72 files across core functionality including object handling, packfiles, deltas, and the ODB layer. It builds on previous Windows compatibility work and interacts with Patrick Steinhardt's ODB abstraction effort. The changes are primarily mechanical type conversions but require careful attention to maintain consistency across the codebase.

Notable technical aspects:
- First patch updates MSVC compatibility layer to use `_chsize_s` for proper 64-bit size handling
- Subsequent patches systematically convert size handling in delta, packfile, and ODB subsystems
- Final patch updates `struct object_info` to use `size_t` for size parameters while maintaining backward compatibility
- Includes test coverage for t5608 and t7508 which verify large object handling

The series has received substantive reviews from Patrick Steinhardt across all patches, with all major technical feedback addressed in this revision. The changes appear well-considered and ready for integration, representing an important step in improving Git's handling of large objects on Windows platforms.
