This is a cleanup patch in Johannes Schindelin's series improving Windows support for large (>4GB) objects. It removes transitional scaffolding that was introduced earlier in the series to make the type conversion from `unsigned long` to `size_t` more reviewable.

The patch eliminates the `cast_size_t_to_ulong()` wrappers and renames the `_sz` variants back to their original names (e.g., `get_delta_hdr_size_sz()` becomes `get_delta_hdr_size()`). This simplification is now possible because all callers have been converted to handle `size_t` sizes directly. The changes touch delta handling and packfile operations, removing unnecessary indirection while maintaining functionality.

Patrick Steinhardt had previously noted the need for this cleanup in his review of earlier patches in the series. The patch satisfies that request, confirming the temporary scaffolding is no longer needed now that the type conversion is complete. The changes are mechanical but important for code clarity, and they represent the final step in normalizing the size handling for large objects.

This is part 6/7 of the series that has already received thorough review, with all major technical feedback addressed in this version. The patch appears straightforward and uncontroversial, cleaning up after the more substantive changes in earlier parts of the series.
