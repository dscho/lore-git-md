This is the second version of Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure, now reduced to 8 patches (down from 9 in v1). The series continues the effort to eliminate `chdir_notify_reparent()` usage but now takes a more incremental approach after performance concerns were identified.

Key changes in v2:
- Patch 9/9 (the absolute path transition) has been dropped due to performance regressions identified by Jeff King (10x slowdown in pathological cases with deep directory hierarchies)
- Patrick now suggests investigating an alternative approach using `openat(3p)` that could maintain performance while avoiding TOCTOU issues
- The remaining patches still provide value by:
  - Simplifying repository setup code (patches 1-3)
  - Cleaning up memory management (patches 4,6)
  - Removing dead code (patch 5)
  - Fixing initialization recursion with "onbranch" config (patch 7)
  - Optimizing path computation (patch 8)

The series remains well-reviewed, with Karthik Nayak, Junio Hamano, and Jeff King having provided substantive feedback on various patches. While the original goal of eliminating relative paths entirely is now on hold, these preparatory changes still represent meaningful improvements to the ref backend code.

Patrick indicates he may explore introducing a `struct fsroot` abstraction using platform-specific equivalents of `openat()` as a more robust long-term solution, though Windows compatibility remains a consideration. For now, this version focuses on the uncontroversial improvements while deferring the more complex path handling changes.
