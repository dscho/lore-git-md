Maintainer feedback on the `--fixup-all` rebase option proposal. Junio C Hamano responds to Harald Nordgren's patch series that would introduce a new `--fixup-all` option for `git rebase --autosquash` to fold a range of commits into their oldest ancestor.

Junio raises two key points:
1. He suggests the option might be clearer if named and modeled after `merge --squash` rather than using the `--fixup-all` name proposed in the patch.
2. He questions whether a new option is actually needed, proposing that `git reset --soft HEAD~3 && git commit --amend --no-edit` might achieve the same result through existing commands.

This feedback indicates the maintainer is open to the functionality but wants to explore simpler approaches before adding new options to the rebase machinery. The response suggests the proposal may need to either justify why the new option is necessary compared to existing commands, or consider alternative naming/implementation approaches.

The thread context shows this is a well-prepared proposal with thorough test coverage, but Junio's comments indicate the design may need refinement before proceeding.
