Bugfix follow-up discussing future date handling in Git tests.

Patrick Steinhardt responds to Elijah Newren's patch fixing commit-graph generation number calculation for future-dated commits (beyond 2106-02-07). He suggests expanding test coverage by creating a new test job that would use future dates (beyond UINT32_MAX) for all test operations, noting that while many tests would break, most failures would likely be benign. He includes a proof-of-concept patch modifying test-lib.sh to support this mode when GIT_TEST_FUTURE is enabled.

The response acknowledges the correctness of Elijah's specific fix (changing the generation number accumulator to timestamp_t) and its test case, while proposing a broader investigation into how other parts of Git might handle future dates. This is positioned as a separate effort from the immediate bugfix, which Patrick explicitly states looks correct as-is. The exchange shows technical alignment on the specific issue while opening a new discussion about more comprehensive future-date testing.
