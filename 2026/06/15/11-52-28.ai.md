This is a cleanup patch in Johannes Schindelin's (Dscho) series addressing Windows-specific handling of large (>4GB) objects where `size_t` is 64-bit but `unsigned long` is 32-bit. As the sixth patch in the v2 series, it removes transitional scaffolding that was introduced earlier to make the type conversion reviewable.

The patch eliminates the `cast_size_t_to_ulong()` wrappers and renames the `_sz` variants back to their original names (e.g. `get_delta_hdr_sz()` becomes `get_delta_hdr_size()`), since all callers have now been converted to use `size_t` directly. This simplification affects delta handling and packfile operations code, touching delta.h, packfile.c, packfile.h, and patch-delta.c.

Key technical points:
- Removes the temporary `get_delta_hdr_size()` wrapper that previously converted sizes back to `unsigned long`
- Renames `get_size_from_delta_sz()` to `get_size_from_delta()` and updates its return type to `size_t`
- Updates all callers to use the direct `size_t` versions
- Maintains functionality while reducing indirection

The patch addresses Patrick Steinhardt's earlier request to clean up the transitional scaffolding, completing the type conversion effort for these subsystems. With this change, the delta and packfile handling code now consistently uses `size_t` for object sizes throughout, properly supporting large objects on Windows platforms.
