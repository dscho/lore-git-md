This is part 8/10 of Patrick Steinhardt's v6 series introducing the `git history drop` command, focused on fixing an assumption in the reset machinery about index state. The patch removes an optimization that assumed callers would always pass a clean index to `reset_working_tree()`, since the new `git history drop` command will violate this assumption. 

The change modifies when the cache tree update is skipped - now only for hard resets rather than all cases. This maintains correctness while still keeping the performance optimization where safe. The patch notes this was a negligible optimization anyway, so the change has minimal impact.

This is a straightforward technical adjustment needed to support the new drop` functionality while maintaining existing behavior for other callers like rebase. It's a small but important piece of the larger series that has already undergone extensive review.
