This is the second patch in a two-part series introducing a new `--squash` option for `git rebase`. The feature allows folding a range of commits into their first commit while preserving the original message, providing a more convenient alternative to interactive rebase or manual `reset --soft` + `commit --amend` workflows.

The implementation modifies the sequencer to handle range folding and updates the rebase command to support the new option. Key aspects include:
- Default range of `@{upstream}..HEAD` when no upstream is specified
- Preserving commit order to maintain fixup!/squash! compatibility
- Prohibiting merge commits from being folded
- Adding 117 lines of test coverage for various edge cases

The patch builds on the test cleanup from part 1 and addresses Junio's naming feedback by using `--squash` (matching `merge --squash`) rather than the original `--fixup-all` proposal. The implementation appears solid with thorough test coverage of scenarios like:
- Handling fixup! commits within the range
- Skipping dropped commits
- Proper behavior with merge commits
- Interaction with autosquash configuration

This provides a more discoverable way to consolidate commit ranges while maintaining the original message structure.
