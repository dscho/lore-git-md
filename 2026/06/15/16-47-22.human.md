This is the final patch (7/7) in Harald Nordgren's v15 series adding `git branch --delete-merged`, introducing a `--dry-run` mode for previewing deletions. The series has evolved through 15 iterations with extensive review, now providing a robust solution for safe automated branch cleanup.

The new `--dry-run` option shows exactly which branches would be deleted by a real run, printing "Would delete branch <name>" for each candidate while leaving refs untouched. This helps users verify their branch selection before executing deletions, particularly useful when using broad patterns like `origin/*`. The implementation maintains all existing safety checks - it still skips checked-out branches, preserves pushable branches, and respects the new per-branch `deleteMerged` config opt-out.

The patch includes comprehensive tests verifying that:
1) Dry-run correctly identifies deletable branches without modifying refs
2) Output matches exactly what a real run would do
3) The option is properly rejected when used without `--delete-merged`

This completes the series' functionality after addressing all major technical concerns raised during review. The implementation appears solid, building on the well-tested core deletion logic from earlier patches while adding this final user-facing convenience feature. With dry-run capability in place, users can confidently adopt `--delete-merged` for branch maintenance workflows.
