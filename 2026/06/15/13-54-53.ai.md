This is a refactoring patch from Patrick Steinhardt's `git history drop` series (v6 03/10). It renames `reset_head()` to `reset_working_tree()` to better reflect the function's actual behavior, which is resetting the working tree to a specific commit rather than just updating HEAD. The change was suggested by Phillip Wood during review.

The patch updates all callers across builtin/rebase.c, reset.c, reset.h, and sequencer.c to use the new name. The corresponding struct `reset_head_opts` is also renamed to `reset_working_tree_options`. This is a preparatory change for making HEAD reference updates optional in a subsequent commit, as the current name would no longer accurate once that change lands.

This is part of the broader architectural work to modernize Git's reset machinery while adding the new `git history drop` functionality. The change is mechanical and straightforward, touching only function names and struct definitions while preserving all existing behavior. As part of a well-reviewed series that's now in its sixth iteration, this patch appears uncontroversial and ready for integration.
