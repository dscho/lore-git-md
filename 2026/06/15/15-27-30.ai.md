Performance optimization for `git ls-files` with pathspecs.

This is Junio Hamano's final approval of Tamir Duberstein's patch to optimize `git ls-files --deleted` and `--modified` by applying pathspec filtering before `lstat()` calls. While the original patch only applied the optimization for single pathspecs (to avoid potential regressions with multiple pathspecs), Junio agrees with Jeff King's earlier suggestion that the optimization should apply universally for consistency with Git's other similar optimizations. 

Junio notes that special-casing single pathspecs would create an arbitrary threshold that future contributors might question ("why one and not three?"). He prefers the simpler, more consistent approach of always applying the optimization, as long as the performance characteristics are clearly documented in the commit message. The patch demonstrates dramatic speedups (65.8s to 5.0s in tested cases) by avoiding unnecessary filesystem operations for non-matching entries.

With this approval, the patch is now queued for inclusion in the 'next' integration branch, marking the successful conclusion of this optimization effort. The thread shows how Git's performance-sensitive code evolves through maintainer feedback - starting with a cautious approach (single pathspec only) before converging on a more principled solution that maintains consistency with the codebase while delivering the same performance benefits.
