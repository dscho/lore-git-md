Performance regression fix for the ref-filter subsystem, addressing a 25x slowdown in ref listing commands (`git branch`, `git tag`) introduced in Git 2.51.0. This is the fourth iteration of the patch, now incorporating all requested changes and appearing ready for merging.

The issue stems from how ref iteration was changed to handle the `--start-after` option, causing unnecessary I/O by reading all loose refs before applying prefix filters. The fix restores prefix-scoped iteration behavior when `--start-after` isn't used, while maintaining the unscoped iteration path needed for that option. Benchmarks show dramatic improvements - commands now run in ~0.11s instead of ~2.8s when there are 10,000 unrelated loose refs.

This version includes better historical context in the commit message and makes the performance tests backend-agnostic, addressing feedback from previous reviews. The patch is targeted for the maint branch as it fixes a regression affecting released versions.
