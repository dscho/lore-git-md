This is the final patch in Johannes Schindelin's (Dscho) series to improve Windows support for objects larger than 4GB by converting `unsigned long` to `size_t` for object sizes. This patch updates the ODB (object database) API to use `size_t` for size parameters, completing the series-wide conversion.

Key changes in this patch:
- Updates `struct object_info` to use `size_t` for the `sizep` field
- Converts four main ODB wrapper functions (`odb_read_object`, `odb_read_object_peeled`, `odb_read_object_info`, `odb_pretend_object`) to use `size_t`
- Removes transitional scaffolding from earlier patches
- Maintains backward compatibility with unconverted subsystems (diff, blame, textconv, fast-import)
- Touches 65 files with mostly mechanical changes

The patch builds on previous conversions in the series and addresses Patrick Steinhardt's review feedback from v1 by removing superfluous `size_t` variables in `cat-file.c`. The changes are wide-ranging but mechanical, focusing on type consistency across the codebase.

This completes the series' goal of proper 64-bit size handling on Windows where `unsigned long` differs from `size_t`. The changes appear well-considered and ready for integration, representing an important step in improving Git's handling of large objects on Windows platforms.
