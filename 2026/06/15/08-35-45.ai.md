This is a platform compatibility patch discussion regarding large object handling on LLP64 systems. Patrick Steinhardt is reviewing Philip Oakley's test case for `git hash-object --stdin` with files over 4GB, which was previously validated in Git for Windows.

Patrick suggests removing the `!LONG_IS_64BIT` test prerequisite, which currently restricts the test to platforms where `size_t` is 64-bit but `long` is 32-bit (like Windows). His proposal would make the 5GB test run on all platforms that support large files, not just LLP64 systems. This follows his earlier architectural question about whether to use `size_t` or introduce a platform-independent `objsize_t` typedef.

The test itself verifies correct hashing of large inputs through stdin, complementing previous tests of direct file hashing. Johannes Schindelin has already signed-off on the Windows-specific validation. The change would broaden test coverage while maintaining the EXPENSIVE marker for the large file requirement.

This is a minor refinement to an otherwise complete series that has been production-proven in Git for Windows. The suggestion doesn't block merging but could improve cross-platform testing consistency. The core technical work remains sound, with Patrick's comment focusing on test strategy rather than the underlying implementation.
