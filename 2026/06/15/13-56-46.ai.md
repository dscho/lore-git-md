This is version 2 of Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure, now reduced to 8 patches from the original 9. The series continues the effort to eliminate `chdir_notify_reparent()` usage but now takes a more incremental approach after performance concerns were raised.

Key changes in v2:
- Patch 9/9 (the absolute path transition) has been dropped due to Jeff King's benchmarks showing 10x slowdowns in pathological cases with deep directory hierarchies
- The remaining patches still provide value by:
  - Simplifying repository initialization in setup.c
  - Fixing memory leaks
  - Cleaning up chdir_notify infrastructure
  - Resolving recursive initialization issues with "onbranch" config
- Patrick now exploring an alternative approach using `openat(3p)` that could maintain performance while avoiding TOCTOU issues, though Windows compatibility remains a challenge

The series remains well-reviewed with substantive feedback incorporated from Karthik Nayak, Junio Hamano, and Jeff King. While the original goal of eliminating relative paths entirely is now on hold, these preparatory changes still represent meaningful improvements to the ref backend code.

Technical details:
- Touches refs/, repository.c, and setup.c
- Affects all three ref backends (files, packed, reftable)
- Fixes subtle initialization ordering issues
- Cleans up memory management around ref stores
- Maintains test coverage throughout

This continues Patrick's pattern of careful, incremental refactoring in the refs subsystem. The changes are unlikely to be controversial but warrant attention from anyone working on repository initialization or ref storage code. The performance tradeoffs around path handling remain an open discussion point.
