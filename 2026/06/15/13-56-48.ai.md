This is patch 2/8 in Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure. The patch cleans up redundant repository format configuration during initialization.

The change addresses a subtle issue where repository format settings (hash algorithm and ref storage format) were being applied twice during repository setup - once via `repository_format_configure()` and again via `apply_repository_format()`. The patch reorders these operations so the format is configured first, then applied once to the repository.

Key technical changes:
- Removes the `struct repository*` parameter from `repository_format_configure()`
- Moves the format configuration call before `apply_repository_format()`
- Eliminates duplicate setting of hash algorithm and ref storage format
- Maintains all existing functionality while simplifying the initialization sequence

This is a preparatory change that improves the code structure without altering behavior, making it easier to reason about repository initialization. The patch has already received substantive review from Karthik Nayak in the thread context. It's part of the larger effort to clean up ref backend infrastructure and eliminate `chdir_notify_reparent()` usage.
