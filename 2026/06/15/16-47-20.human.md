**Feature: Safe branch cleanup with `git branch --delete-merged`**

This is patch 5/7 in Harald Nordgren's v15 series introducing a new `--delete-merged` option for `git branch`. The feature provides automated cleanup of local branches that have been merged into their upstreams, with careful safety mechanisms to avoid accidental data loss.

The new option builds on the `--forked` filter introduced earlier in the series, deleting only branches that both match the given upstream patterns *and* have all commits reachable from their configured upstream. The implementation includes several protective measures:
- Never deletes checked-out branches
- Skips branches whose upstream no longer exists
- Preserves branches that push back to their upstream (like `main` tracking `origin/main`)
- Silently skips unmerged branches rather than aborting the operation

The patch adds comprehensive tests covering edge cases like missing upstreams, checked-out branches, and complex push/upstream configurations. The implementation uses the new flag-based API from earlier patches, including `DELETE_BRANCH_SKIP_UNMERGED` and `DELETE_BRANCH_NO_HEAD_FALLBACK` flags for robust bulk operations.

This appears to be a well-considered addition to Git's branch management capabilities, with thorough test coverage and clear documentation. The 15-iteration evolution suggests the design has been carefully refined based on community feedback, particularly from Phillip Wood's detailed reviews. The feature should be particularly useful for developers working with topic branches in fork-based workflows.
