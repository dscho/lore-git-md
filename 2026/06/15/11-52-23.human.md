**Windows compatibility patch for large file handling**

This is the first patch in Johannes Schindelin's series addressing Windows-specific issues with files larger than 4GB. The problem stems from Windows' 32-bit `long` type even on 64-bit systems, which causes silent truncation when using the existing `_chsize` wrapper for `ftruncate`.

The patch introduces a careful solution that maintains POSIX compatibility while properly handling 64-bit file sizes:
1. Replaces the problematic `_chsize` with `_chsize_s` (which supports 64-bit sizes)
2. Wraps it to preserve the expected POSIX return convention (-1 on error)
3. Places the wrapper strategically to ensure correct type resolution
4. Maintains compatibility with existing callers in http.c, parallel-checkout.c, and test code

The change fixes test failures in t7508 where Git was unable to handle 4GB+ files properly on Windows. The implementation shows attention to detail in maintaining the expected POSIX semantics while working around Windows' quirks. This foundational change enables the rest of the series' large-object handling improvements.
