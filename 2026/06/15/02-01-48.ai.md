Feature proposal for `git rebase --autosquash --fixup-all` to fold commit ranges. This is Junio C Hamano's response to Harald Nordgren's patch series that would add a new `--fixup-all` option to `git rebase --autosquash`.

Junio raises two key points about the proposed feature:
1. Notes a naming inconsistency between the cover letter's description (`--fixup`) and the actual implementation (`--fixup-all`), suggesting that modeling the name after `merge --squash` might be clearer
2. Questions whether a new option is actually needed, proposing that existing commands (`git reset --soft` followed by `git commit --amend`) could achieve the same result without modifying rebase behavior

The response suggests Junio is skeptical about the need for this feature justifies adding new rebase machinery, given existing alternatives. This doesn't reject the proposal outright but indicates the maintainer would need stronger justification for the change. The thread context shows this is building on earlier GitHub discussion #1135 about improving fixup workflows.
