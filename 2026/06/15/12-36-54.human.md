Ref backend modernization follow-up: This is Patrick Steinhardt's response to Jeff King's performance benchmarks showing a 10x slowdown in edge cases when using absolute paths for ref handling (deep directory hierarchies with many loose refs). While acknowledging the regression, Patrick notes this is an artificial scenario mitigated by modern ref storage formats like packed-refs and reftable.

The email suggests proceeding with most of the series (which simplifies setup.c and fixes memory issues) while potentially deferring the final patch that removes chdir_notify entirely. Patrick also revives discussion of a filesystem abstraction using openat(3p) as a future direction that could provide both performance and security benefits, though notes Windows compatibility remains a hurdle.

The exchange provides important context about tradeoffs in the ref backend modernization - the current series represents a clear simplification but comes with measurable (if likely acceptable) performance costs in extreme cases. The thread shows both contributors thoughtfully weighing technical tradeoffs while keeping the broader architectural direction in view.
