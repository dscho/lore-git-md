This is the second patch in a two-part series introducing a new `--squash` option for `git rebase`. The feature allows folding a range of commits into their first commit while preserving the original message, providing a more discoverable alternative to `git reset --soft` + `git commit --amend`.

The implementation modifies `sequencer.c` to handle range folding and updates `builtin/rebase.c` for option handling. Key technical details:
- The option implies the merge backend and works independently of `--autosquash`
- Commits are folded in their original order, preserving any existing fixup!/squash! commits in the range
- Merge commits in the middle of the range are handled gracefully
- The option cannot be combined with `--rebase-merges`

The patch includes extensive test coverage (117 new test lines) verifying:
- Basic range folding functionality
- Interaction with fixup! commits
- Edge cases like single-commit ranges and empty ranges
- Behavior with merge commits in the range
- Precedence over `--autosquash`
- Incompatibility with `--rebase-merges`

The implementation appears technically solid, with thorough test coverage addressing the various edge cases. The thread has already resolved the naming question (settling on `--squash` to align with `merge --squash`) and now focuses on whether the convenience justifies a new rebase option versus composing existing commands.
