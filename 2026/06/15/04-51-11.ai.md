This is the third patch in a 4-part series introducing standardized path formatting for repository information, part of a GSoC project. The patch adds `path.commondir.absolute` and `path.commondir.relative` fields to `git repo info`, providing reliable access to the common directory path in both formats.

The implementation builds on the shared `append_formatted_path()` helper introduced earlier in the series, using it to handle both absolute and relative path formatting consistently. Key technical aspects include:

1. Integration with `repo_get_common_dir()` to properly handle worktree cases where the common dir differs from the gitdir
2. Comprehensive test coverage through a new `test_repo_info_path` helper that:
   - Creates isolated repositories per test case
   - Handles environment variable overrides (GIT_COMMON_DIR/GIT_DIR)
   - Verifies both absolute and relative path outputs
3. Explicit error handling for NULL common dir cases

The patch follows the design consensus from earlier reviews to provide explicit `.absolute` and `.relative` variants rather than a single key with default behavior. Test cases cover standard repositories, GIT_COMMON_DIR overrides, and GIT_DIR edge cases.

This continues the series' pattern of thorough, well-tested additions to Git's path handling infrastructure. The implementation appears clean and complete, with all substantive technical discussion having been resolved in prior iterations. The final v4 changes are minor style tweaks to the test helper based on Lucas Seiki Oshiro's feedback.
