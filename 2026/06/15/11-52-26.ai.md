This is the fourth patch in Johannes Schindelin's (Dscho) v2 series addressing Windows platform compatibility for handling objects larger than 4GB. The patch focuses on widening the `unpack_entry()` function's size parameter from `unsigned long` to `size_t` in the packfile subsystem.

The change is necessary because Windows uses 32-bit `unsigned long` while having 64-bit `size_t`, which would truncate object sizes over 4GB. The patch makes the conversion while maintaining transitional compatibility with unconverted subsystems like `fast-import` through temporary casting. It also preserves the existing behavior for `packed_object_info_with_index_pos()` until a future interface update.

Key technical aspects:
- Updates delta base cache to use `size_t` for stored sizes
- Modifies `unpack_compressed_entry()` and related functions to handle `size_t` sizes
- Adds temporary casting in `fast-import.c` to bridge the gap with its still-narrow interface
- Leaves `packed_object_info_with_index_pos()` using a temporary `size_t` variable until `struct object_info` is fully converted (handled in patch 7/7)

The patch received a surface-level review from Patrick Steinhardt in v1, who suggested adding a `NEEDSWORK` comment about the transitional casting in `fast-import.c`. Dscho responded that the `cast_size_t_to_ulong()` function name itself serves as sufficient documentation of the temporary nature, and indicated the casting will be removed when the full conversion completes. The discussion shows shared understanding of the transitional approach.

This is a mechanical but important change in the series' systematic conversion of object size handling across Git's codebase. It builds on previous patches while setting up for the final ODB API conversion in patch 7/7. The changes are localized to packfile handling while carefully maintaining compatibility with unconverted subsystems.
