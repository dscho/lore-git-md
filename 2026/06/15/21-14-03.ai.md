This is the fourth revision of an RFC series introducing `diff.<driver>.process`, a mechanism for external tools to inject diff hunks into Git's diff and blame pipelines. The series is technically complete with comprehensive test coverage, having addressed all substantive review feedback from previous iterations.

The latest email identifies a remaining gap: certain diff flags like `-L` (line ranges) and stat-related flags currently bypass the external diff process. The author notes these should ideally consult the external provider for consistency with how blame integration works. This suggests the need for additional documentation clarifying which flags interact with external process and which fall back to builtin behavior, along with the rationale for each case.

The series has already implemented core functionality including:
- Pkt-line protocol for tool communication
- Graceful fallback to builtin diff on errors
- Blame integration that can skip reformat-only commits
- Windows compatibility fixes
- Comprehensive test coverage (708+ lines)

With Windows path handling resolved and the test helper transitioned to C (as Junio Hamano recommended), the main remaining work appears to be finalizing the flag behavior documentation and potentially extending support for additional flags. The blame integration demonstrates the value proposition - skipping reformat-only commits in history analysis while preserving semantic change attribution. Performance remains a consideration (current blame overhead is ~17%), though an OID-based optimization is noted as future work.

The RFC appears ready for final review pending documentation refinements around flag behavior. Junio Hamano has previously endorsed the technical direction, suggesting this is likely to progress toward merging once these last details are addressed.
