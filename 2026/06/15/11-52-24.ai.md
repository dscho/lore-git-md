This is the second patch in Johannes Schindelin's 7-part series addressing Windows platform compatibility for handling objects larger than 4GB, where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch focuses on converting delta handling to use `size_t` for object sizes.

The change updates `patch_delta()` and related functions to use `size_t` instead of `unsigned long` for size parameters, allowing proper handling of large objects on Windows. Key aspects:

1. Introduces consistent `size_t` usage across delta subsystem while maintaining the same on-disk format
2. Switches internal calls from `get_delta_hdr_size()` to the `_sz` variant introduced in commit 17fa077596
3. Propagates the type change through callers in apply.c, index-pack.c, unpack-objects.c, and packfile.c
4. Updates test helper to match the interface change

The patch builds on previous work in the series and addresses Patrick Steinhardt's v1 review feedback about cleaning up temporary scaffolding. The changes are mechanical but wide-ranging, touching core delta handling code paths while carefully maintaining compatibility.

This is part of the broader Windows large object support effort, with all technical feedback from v1 now addressed. The patch appears well-considered and ready for integration, representing an important step in improving Git's handling of large objects on Windows platforms.
