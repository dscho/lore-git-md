This is a follow-up discussion about the proposed `--fixup-all` option for `git rebase --autosquash`. The author Harald Nordgren responds to Junio Hamano's concerns about the feature's naming and necessity.

Harald agrees with Junio's suggestion to model the option name after `merge --squash` rather than using `--fixup-all`. However, he pushes back on the alternative workflow Junio proposed (using `git reset --soft` and `git commit --amend`), arguing that it's both less intuitive and more cumbersome - requiring users to manually count commits (HEAD~N) and execute multiple commands.

The exchange highlights the tension between adding new convenience features versus encouraging users to compose existing commands. While Junio's suggested alternative technically works, Harald maintains that the proposed rebase option would offer a more streamlined workflow for squashing fixup commits. The discussion remains unresolved but civil, with both sides making reasonable cases.
