This is the final patch in Johannes Schindelin's (Dscho) series to improve Git's handling of large objects (>4GB) on Windows platforms where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch completes the conversion by updating the ODB (object database) API to use `size_t` for object sizes throughout the codebase.

The key changes:
- Updates `struct object_info` to use `size_t` for the `sizep` field
- Converts four main ODB wrapper functions (`odb_read_object`, `odb_read_object_peeled`, `odb_read_object_info`, `odb_pretend_object`) to use `size_t`
- Removes transitional scaffolding from earlier patches
- Maintains backward compatibility with unconverted subsystems (diff, blame, textconv, fast-import)
- Touches 65 files with mostly mechanical changes

The patch builds on the previous six patches in the series which already converted size handling in delta, packfile, and other subsystems. It addresses Patrick Steinhardt's review feedback from v1 by removing superfluous `size_t` variables in `cat-file.c` and passing sizes directly.

This is a significant but mechanical change that completes the Windows large object support work. The series has received thorough review and appears ready for integration. The changes are wide-ranging but focused on type consistency rather than functional changes.
