This is part of Patrick Steinhardt's v6 series introducing the `git history drop` subcommand, specifically patch 9/10 which refactors the reference update handling. The patch splits the monolithic `handle_reference_updates()` function into two distinct phases: `compute_pending_ref_updates()` for gathering references that need updating, and `apply_pending_ref_updates()` for executing the actual reference transaction.

The refactoring enables better separation of concerns and prepares for future functionality where these phases might need to be called independently. The changes are mechanical rather than behavioral - the same reference updates are performed, just via a more structured code path. The patch maintains all existing functionality including dry-run support and error handling.

This is a preparatory change for the final patch in the series that implements the actual `drop` subcommand. The clean separation of reference update phases will make it easier to implement the drop operation's logic while keeping the reference update code maintainable. The patch follows good refactoring practice by keeping the changes focused and testable.
