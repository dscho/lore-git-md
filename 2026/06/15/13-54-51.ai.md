This is the first patch in Patrick Steinhardt's v6 series introducing the `git history drop` command, focused on refactoring index handling. The patch extracts the unmerged-entry resolution logic from `repo_read_index_unmerged()` into a new standalone function `index_state_unmerged_to_stage0()` that can operate on any index state, not just the repository's main index. 

The change serves two purposes: it fixes a signedness mismatch in the index iteration (changing `int i` to `unsigned int i`), and prepares for future use cases where this operation needs to be performed on arbitrary index states rather than just the repository's main index. The new function is exposed in read-cache-ll.h alongside related index operations.

This is a mechanical refactoring that doesn't change behavior - it just makes the unmerged-entry resolution logic more reusable. The patch is straightforward and well-contained, touching only the index handling code that will be needed by the upcoming `git history drop` functionality. As the first in a series that has already gone through extensive review, this foundational change appears uncontroversial.
