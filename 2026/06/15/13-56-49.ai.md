This is patch 3/8 in Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure. The patch focuses on cleaning up how the GIT_REFERENCE_BACKEND environment variable is applied during repository setup.

The key change moves the environment variable handling to only when a repository is actually discovered, rather than applying it unconditionally. This eliminates a redundant call to `repo_set_ref_storage_format()` since the format can now be configured before being applied via `apply_repository_format()`. The patch also fixes a subtle issue where the ref storage format was being set after repository initialization, which could lead to inconsistencies.

The changes are contained to setup.c and maintain the same functionality while making the code more logical in its sequencing. This continues the series' theme of simplifying repository initialization while preparing for future refactoring of the reference backend code. Junio C Hamano provided substantive review of this patch in particular, indicating it's on the right track technically.

This is part of Patrick's ongoing effort to modernize Git's reference handling infrastructure, building on previous work with the reftable backend and ODB abstraction. The changes are preparatory but meaningful improvements to the setup code that should make future refactoring easier.
