This is the second patch in Johannes Schindelin's series improving Windows support for large (>4GB) Git objects by converting `unsigned long` size parameters to `size_t`. The patch focuses on the delta subsystem, updating `patch_delta()` and related functions to use `size_t` consistently.

The changes are mechanical but important for Windows compatibility where `unsigned long` is 32-bit while `size_t` is 64-bit. The patch builds on a previous change (17fa077596) that introduced `get_delta_hdr_size_sz()` specifically to enable this conversion without changing the on-disk format. It updates the delta handling code across multiple files while maintaining existing behavior.

Patrick Steinhardt reviewed v1 of this patch, questioning whether `get_delta_hdr_size()` would have any remaining callers after the conversion (it won't) and suggesting test coverage for the size conversion. Dscho responded that creating 4GB+ test objects is impractical but the conversion is sound. The patch appears ready for integration as part of the larger Windows compatibility effort.
