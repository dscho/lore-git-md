This is patch 4/8 in Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure. The patch focuses on fixing memory management issues in the reference store subsystem.

The key problem addressed is that reference stores were being registered with Git's "chdir_notify" subsystem (which handles working directory changes) but never unregistered. This led to two issues:
1. For the main repository's reference database, this caused a memory leak since the pointer remained registered indefinitely
2. For submodule/worktree reference databases, it could lead to dangling pointers after the stores were freed

The patch fixes this by:
- Adding proper unregistration when reference stores are released
- Switching from `chdir_notify_reparent()` to `chdir_notify_register()` to enable unregistration
- Implementing the change consistently across all three ref backends (files, packed, reftable)

This is a preparatory change in the larger effort to eliminate `chdir_notify_reparent()` usage. While the patch touches multiple backend implementations, the changes are mechanical and straightforward. The fix is well-established by the series' prior reviews from Karthik Nayak and Junio Hamano, and follows the incremental improvement approach the series has taken after performance concerns were raised about more sweeping changes.
