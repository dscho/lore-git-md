This is patch 6/7 in Harald Nordgren's v15 series adding `git branch --delete-merged`, introducing a per-branch opt-out mechanism via `branch.<name>.deleteMerged` configuration.

The patch adds a new safety feature that allows users to exempt specific branches from automatic deletion by `--delete-merged`. When set to false, this config prevents the branch from being deleted even if it meets all other criteria (merged status, push divergence checks, etc.). The branch will be skipped with an explanatory message unless `--quiet` is used. Importantly, this setting does not affect explicit deletions via `git branch -d`.

Key implementation details:
- Adds documentation for the new config option in both the branch config and command documentation
- Implements the check in `delete_merged_branches()` using `repo_config_get_bool()`
- Includes tests verifying both the opt-out behavior and that `branch -d` remains unaffected
- Maintains the series' focus on safety by making the skip behavior visible by default

This patch builds on the series' established safety architecture while giving users more fine-grained control over which branches are considered for automatic cleanup. The implementation appears straightforward and well-tested, with clear documentation of the new feature's behavior and limitations.
