This is patch 4/8 in Patrick Steinhardt's refactoring series to modernize Git's reference backend infrastructure. The patch focuses on fixing memory management issues in the chdir_notify subsystem used by reference stores.

The key change is properly unregistering reference stores from chdir_notify when they are released. Currently, reference stores register with chdir_notify to handle relative path reparenting when the working directory changes, but they never unregister. This leads to two problems:
1. For main reference databases, this creates a memory leak (though not detected by leak checkers since the pointer remains registered)
2. For submodule/worktree databases, it can leave dangling pointers after repo_clear()

The patch introduces proper unregistration by:
- Adding reparent callbacks for each backend (files, packed, reftable)
- Switching from chdir_notify_reparent() to chdir_notify_register() which supports unregistration
- Adding chdir_notify_unregister() calls in each backend's release function

This is part of the larger effort to eliminate chdir_notify_reparent() usage while maintaining correct behavior. The changes are mechanical but important for memory safety, touching all three ref backends (files, packed, reftable) with consistent patterns. The patch follows the series' pattern of careful, incremental improvements to the refs subsystem infrastructure.
