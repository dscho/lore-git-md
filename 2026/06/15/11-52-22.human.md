This is the second version of a platform compatibility patch series from Johannes Schindelin (Dscho) that continues work to properly support objects larger than 4GB on Windows systems where `size_t` is 64-bit but `unsigned long` is 32-bit. The 7-patch series systematically converts object size handling from `unsigned long` to `size_t` across multiple Git components.

The key changes in v2 are:
- Rebased onto master to resolve conflicts with the recently merged `ps/odb-source-loose` series
- Removed some unnecessary temporary `size_t` variables in `cat-file.c` as suggested by Patrick Steinhardt's review of v1

The series touches 72 files across core functionality including object handling, packfiles, deltas, and the ODB layer. It builds on previous Windows compatibility work and addresses test failures in t5608 and t7508 that verify large object handling. The changes are primarily mechanical type conversions but require careful attention to maintain consistency across the codebase.

Notable aspects:
- Patch 1 updates MSVC compatibility layer to use `_chsize_s` for proper 64-bit size handling
- Patch 2 converts delta handling to use `size_t` consistently
- Patch 3 improves pack-objects behavior for large objects despite zlib's 32-bit limitation
- Patch 7 finalizes the ODB API conversion while maintaining backward compatibility

The series has received substantive technical review from Patrick Steinhardt, with all major feedback addressed in this revision. The changes appear well-considered and focused on the specific Windows platform issue, making this a likely candidate for integration.
