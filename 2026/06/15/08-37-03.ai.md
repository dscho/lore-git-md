This is a feature proposal for a new `--squash` option in `git rebase` that folds a range of commits into their first commit while preserving the original message. The patch series has evolved from its initial `--fixup-all` naming to align with Junio's suggestion to follow the `merge --squash` pattern.

The implementation modifies `sequencer.c` to handle range folding and updates `builtin/rebase.c` for option handling. Key changes from v1 include:
- The renamed `--squash` option now implies the merge backend and works independently of `--autosquash`
- Improved documentation and test coverage (now 118 lines)
- Better integration with existing autosquash behavior

The feature provides a more discoverable alternative to `git reset --soft` + `git commit --amend` for consolidating commit ranges. The thread shows progress on naming consensus but continues to question whether the convenience justifies a new rebase option versus existing tools. The implementation appears solid with thorough test coverage of edge cases like merge commits and fixup! commits in the range.
