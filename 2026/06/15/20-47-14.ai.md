This is the final version of a performance bugfix for the ref-filter subsystem, addressing a regression in ref listing commands that was introduced in Git 2.51.0. The patch restores prefix-scoped iteration behavior while maintaining `--start-after` functionality, fixing a significant slowdown when many unrelated loose refs exist.

The key technical change modifies `refs_ref_iterator_begin()` to take the prefix directly during construction when `--start-after` isn't used, avoiding the performance penalty of reading all loose refs before applying the prefix filter. Benchmarks show dramatic improvements - commands now run ~25x faster (from ~2.8s to ~0.11s) when there are 10,000 unrelated loose refs.

This v4 patch incorporates all feedback from previous reviews, including better historical context in the commit message and making the performance tests backend-agnostic. The implementation maintains the existing control flow while solving the performance issue, keeping the unscoped iteration path for `--start-after` cases. The patch is targeted for the maint branch since the regression affects released versions.
