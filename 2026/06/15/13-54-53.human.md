This is a refactoring patch from Patrick Steinhardt's `git history drop` series, specifically renaming `reset_head()` to `reset_working_tree()` to better reflect its actual functionality. The change comes as part of preparing the reset machinery to support optional HEAD reference updates in future commits.

The patch updates all callers across builtin/rebase.c, reset.c, reset.h, and sequencer.c to use the new name. The corresponding struct `reset_head_opts` is also renamed to `reset_working_tree_options`. The change is mechanical but meaningful - the new name more accurately describes that the function's core purpose is resetting the working tree state rather than just manipulating HEAD.

This is patch 3/10 in the v6 series that introduces the `git history drop` subcommand. The rename was suggested by Phillip Wood during review and helps pave the way for subsequent changes that will make HEAD updates optional while maintaining the working tree reset behavior. The patch demonstrates careful attention to naming clarity in Git's core APIs.
