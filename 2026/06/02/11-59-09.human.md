This is the first patch in a two-part documentation series promoting the `b4` tool for Git's mailing list workflow. Patrick Steinhardt adds project-specific configuration files to standardize how contributors use b4 when submitting patches to the Git list.

The patch introduces two new files in the repository root:
- `.b4-config` sets default behaviors for b4, including keeping patch series versions connected by replying to the original cover letter
- `.b4-cover-template` provides a standardized cover letter format that automatically includes a range-diff showing changes between versions

This is a straightforward infrastructure change that formalizes existing community practices. The changes are well-contained and non-invasive, focused on improving the contributor experience without modifying any code. As part of a documented effort with maintainer buy-in (referencing prior discussion with Junio), this seems like a low-risk quality-of-life improvement for contributors working with the mailing list.
