This is the second patch in a two-part documentation series promoting the `b4` tool for Git mailing list workflows, following up on the first patch that added b4 configuration files.

The patch updates `MyFirstContribution.adoc` to explicitly recommend `b4` as the preferred way to submit patches via email, positioning it as the third option alongside GitGitGadget and raw `git send-email`. It adds a comprehensive new section explaining how to use b4 for:
- Initial patch preparation and cover letter editing
- Dry-run testing before sending
- Managing version updates and range-diffs for v2+ iterations
- Threading follow-up versions properly

The changes to `SubmittingPatches` are minimal, just adding b4 alongside the existing GitGitGadget mention with a note about its automation benefits. The implementation follows the pattern established in the first patch - this is purely documentation aimed at improving contributor experience by formalizing b4 usage.

As with the first patch, this appears non-controversial and well-executed, completing the series' goal of standardizing on b4 for mailing list workflows. The documentation is clear and thorough, walking new contributors through the key b4 workflows while maintaining compatibility with existing methods.
