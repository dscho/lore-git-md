This is a bug report about environment variable handling in Git's performance test infrastructure. Jeff King (Peff) identifies a subtle interaction where `GIT_PERF_*` variables set in the environment are lost when running performance tests with `--verbose-log` or `--tee` options.

The issue stems from how `test-lib.sh` and `perf-lib.sh` handle environment variables during test execution. Normally, `perf-lib.sh` saves and restores `GIT_PERF_*` variables, but this mechanism breaks when test execution involves re-execution (as happens with `--verbose-log`). The problem is compounded when `GIT_TEST_OPTS` includes these options, as they can be silently inherited from build configurations.

Peff notes this is particularly problematic for performance testing where environment variables like `GIT_PERF_LARGE_REPO` are crucial for test behavior. He describes the issue as "insidious" since it can lead to inconsistent test behavior depending on seemingly unrelated build configurations. While he doesn't provide a fix, the detailed analysis clearly outlines the problematic code paths and their interactions.

This appears to be a genuine bug that could affect anyone using Git's performance testing infrastructure with logging options. The report is thorough and well-explained, making it easy to understand both the symptoms and underlying cause.
