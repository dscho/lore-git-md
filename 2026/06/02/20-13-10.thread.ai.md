Thread identity: Bugfix for thread sanitizer (TSAN) race condition in transport helper code, specifically in the `transfer_debug()` function.

Core problem: A static variable `debug_enabled` was being lazily initialized based on `GIT_TRANSLOOP_DEBUG`, creating a race condition when called from multiple worker threads. The fix moves initialization to `bidirectional_transfer_loop()` before thread creation and renames the variable to `transfer_debug_enabled`.

Current status: v2 patch incorporates Junio's feedback to maintain exact behavioral equivalence with `if (transfer_debug_enabled <= 0)` handling. Jeff King (Peff) now suggests adding a `BUG()` check for negative values in `transfer_debug()` to catch missed initialization, and notes `git_env_bool()` would be more idiomatic but changes behavior.

Key technical details:
- Fix targets transport helper subsystem
- Debug flag now initialized in `bidirectional_transfer_loop()`
- Variable renamed to `transfer_debug_enabled`
- Condition check handles uninitialized state (-1)
- `.tsan-suppressions` entry removed
- Peff additions: proposed `BUG()` check for negative values
- Historical context: thread-based transport dates to 2010, modern `poll()` approach would be cleaner
