Thread identity: Bugfix for thread sanitizer (TSAN) race condition in transport helper code, specifically in the `transfer_debug()` function.

Core problem: A static variable `debug_enabled` was being lazily initialized based on the `GIT_TRANSLOOP_DEBUG` environment variable, creating a potential race condition when called from multiple worker threads. This could lead to undefined behavior in debug scenarios.

Current status: The race condition has been fixed by moving initialization of the debug flag (now renamed to `transfer_debug_enabled` for clarity) to `bidirectional_transfer_loop()` before worker threads are created. Junio C Hamano identified an edge case where the new implementation could proceed with debugging when the variable is still uninitialized (-1), unlike the original behavior. He suggests changing the condition check to `<= 0` to maintain exact behavioral equivalence while preserving thread safety.

Key technical details:
- Fix targets the transport helper subsystem
- Changes the debug flag initialization timing and location
- Renames variable from `debug_enabled` to `transfer_debug_enabled`
- Removes entry from `.tsan-suppressions` file
- Maintains identical debug functionality but in a thread-safe way
- Edge case identified where uninitialized state (-1) could incorrectly proceed with debugging
- Proposed solution changes condition check to `if (transfer_debug_enabled <= 0)`

Impact: The change is low-risk as it only affects debugging scenarios where `GIT_TRANSLOOP_DEBUG` is set, but demonstrates good attention to thread safety in concurrent code paths.
