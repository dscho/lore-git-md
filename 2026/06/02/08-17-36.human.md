This is a documentation patch that clarifies an existing but undocumented feature in Git's date parsing. The patch documents that prefixing a Unix timestamp with `@` (e.g. `@123456789`) forces Git to interpret the value as a raw timestamp rather than potentially confusing it with other date formats like `YYYYMMDD`. This is particularly important for small timestamps (under 100,000,000 seconds) that could be ambiguous.

The patch adds clear documentation in `date-formats.adoc` and includes test cases in `t0006-date.sh` that demonstrate the difference between prefixed and unprefixed timestamps. The tests show how `@2000` correctly parses as a Unix timestamp while `2000` gets interpreted as a date. The patch is co-authored by Junio Hamano, suggesting it has maintainer approval, and addresses a real gap in the documentation. The implementation looks straightforward and well-tested.
