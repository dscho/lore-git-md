This is a feature patch adding metadata capabilities to Git worktrees. The patch introduces two new pieces of metadata for linked worktrees:

1. Creation timestamps (automatically recorded when a worktree is created)
2. Free-form notes/descriptions (set via `--note` during creation or with a new `git worktree annotate` subcommand)

Key aspects:
- The main worktree cannot be annotated (as it has no administrative files)
- `git worktree list` gains new options: `--show-created`, `--show-note`, and `--sort` (by path or creation time)
- Porcelain output now includes `created` and `note` lines when available
- Legacy worktrees (created before this change) show as "created: unknown" and sort after timestamped ones
- The implementation is thorough with tests covering all new functionality
- Documentation is comprehensive, explaining the new features and options
- The patch maintains backwards compatibility with existing worktrees

The motivation appears to be helping users track when and why worktrees were created, addressing a common pain point of worktree sprawl. The implementation looks clean and well-tested, with careful attention to edge cases like legacy worktrees and the main worktree special case.
