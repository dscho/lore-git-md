This is the sixth iteration of a UX improvement patch series for the config subsystem, addressing user confusion when mistakenly using `=` syntax in `git config` commands. The series implements Junio's requested API redesign while maintaining the approved user-facing behavior.

The v6 changes focus on restructuring the internal API:
1. Introduces a new `git_config_key_is_valid()` function for callers that only need validation without parsing
2. Moves the core parsing logic into a static `do_parse_config_key()` helper that can operate quietly
3. Restores the original `git_config_parse_key()` signature as a thin wrapper
4. Adds more test coverage for edge cases like invalid keys with `=`

The user experience remains unchanged from v5 - it still provides helpful hints when users accidentally use `=` syntax while maintaining strict validation of key patterns. The implementation now cleanly separates the validation-only use case from full parsing, addressing Junio's architectural concerns.
