This is the first patch in the sixth version of a series improving `git config` command-line syntax error handling. The patch focuses on API restructuring as requested by Junio Hamano, splitting the key validation logic into internal and public-facing functions.

The key changes in this patch:
1. Extracts the core parsing logic into a new static `do_parse_config_key()` helper that takes a `quiet` flag and makes the `store_key` parameter optional
2. Maintains the existing `git_config_parse_key()` as a thin wrapper for backward compatibility
3. Adds a new public `git_config_key_is_valid()` function for validation-only use cases

The restructuring cleanly separates concerns while preserving all existing validation behavior. The new API allows callers to:
- Get full parsing with error reporting (via the original function)
- Perform silent validation checks (via the new function)
- Avoid unnecessary allocations when only validation is needed

This is a technical refactoring that enables the user-facing improvements (better error messages and hints) that will follow in patch 2/2. The changes appear well-contained and maintain backward compatibility while providing a cleaner internal structure.
