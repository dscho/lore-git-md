This thread addresses a bug in Git's HTTP authentication handling during redirects, where authentication headers (WWW-Authenticate) were being lost when following redirects - particularly problematic for OAuth flows. The issue occurs when Git clears credentials during redirect processing, causing the server's authentication headers to be discarded before credential helpers can inspect them.

The proposed fix modifies http.c to preserve these headers across the credential update that happens during redirects. The 14-line change has significant implications for authentication flows that rely on reading WWW-Authenticate headers. The patch includes thorough test coverage with a new Apache redirect rule and verification that credential helpers receive the expected headers after a redirect. This appears to be a well-scoped fix for a real-world authentication scenario, with clear reproduction steps in the commit message. The change touches the HTTP authentication subsystem and will be particularly relevant for maintainers of credential helpers and those working with OAuth integrations.
