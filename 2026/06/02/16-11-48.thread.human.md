This thread addressed a bug in Git’s HTTP authentication handling where WWW-Authenticate headers were lost during redirects, breaking OAuth flows. The issue was fixed with a 14-line patch in `http.c` that preserves these headers during credential updates triggered by redirects. The fix is confirmed safe, with test coverage added to verify correct behavior post-redirect, and has already been merged.

The discussion initially included a broader architectural question about whether to refactor the credential URL update logic (e.g., introducing a `credential_update_url()` helper in `credential.c`) or reconsider where WWW-Authenticate headers should be stored. However, Junio and Aaron agreed to decouple this from the immediate fix, treating it as a low-priority follow-on. Aaron noted that the fix isn’t urgent for his users due to an existing workaround (using the server’s FQDN), and he hasn’t revisited the refactoring since being sidetracked by other work. The thread now clearly separates the landed bugfix from the unresolved design discussion, with no remaining technical blockers.
