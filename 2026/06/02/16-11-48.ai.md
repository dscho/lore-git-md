Bugfix targeting HTTP authentication flow during redirects. This patch addresses an issue where authentication headers (WWW-Authenticate) were being lost when Git follows HTTP redirects, specifically breaking OAuth authentication flows.

The problem occurs when:
1. A server redirects (e.g. from HTTP to HTTPS)
2. Git clears all credentials while processing the redirect
3. The authentication headers from the redirect response are lost
4. Credential helpers can't see which authentication methods are supported

The fix preserves the WWW-Authenticate headers across the credential update that happens during redirect processing. The patch includes a new test case that verifies the headers are properly preserved when using bearer token authentication after a redirect.

The change is relatively small (14 lines added to http.c) but has significant implications for authentication flows that rely on reading the WWW-Authenticate headers, particularly OAuth. The test coverage is thorough, adding a new Apache redirect rule and a test case that verifies the credential helper receives the expected authentication headers.

This appears to be a well-motivated fix for a real-world authentication scenario, with clear reproduction steps provided in the commit message and comprehensive test coverage. The patch touches the HTTP authentication subsystem and may be of particular interest to maintainers of credential helpers and those working with OAuth authentication flows.
