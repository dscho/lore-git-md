The thread discusses adding metadata tracking to Git worktrees, with the proposal now gaining clearer justification from both practical and philosophical angles. The original design by Norbert Kiesel suggested storing metadata like creation timestamps and descriptions in existing worktree files, maintaining backward compatibility. Initial skepticism from reviewers like Phillip Wood questioned whether branch descriptions were sufficient, but Kristoffer Haugsbakk provided concrete use cases where worktree-specific metadata is needed - build environments, historical snapshots, testing contexts, and tooling integration.

Chris Torek's latest contribution strengthens the conceptual foundation, arguing that worktrees serve general-purpose work contexts that transcend branch associations. He notes that Git's current branch-centric constraints are implementation artifacts rather than fundamental limitations. This philosophical perspective complements Kristoffer's practical examples, together making a robust case for the feature.

Key open questions remain about implementation details: whether to track creation timestamps or last-used times (Phillip Wood favors the latter), whether to support multiple sort criteria, and whether to consider an alternative storage mechanism via per-worktree refs.
