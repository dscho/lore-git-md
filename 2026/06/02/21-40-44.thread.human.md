Norbert Kiesel's worktree metadata patch continues to face fundamental questions about its purpose and design. The patch would track worktree creation timestamps and descriptions, storing them in `.git/worktrees/<id>/created` and repurposing the existing description file mechanism. While the technical implementation is settled, reviewers are challenging whether this solves real user needs.

Phillip Wood raised two key concerns: that branch descriptions might already cover most use cases, and that last-updated timestamps (available from reflogs) would be more useful than creation times. In response, Norbert argues that worktrees sometimes serve as containers" for groups of changes where users switch branches within the same worktree, making worktree-specific notes valuable. He also suggests supporting multiple sort options (created, last-updated, name) similar to GNU ls.

The discussion now hinges on whether worktree context is meaningfully distinct from branch context for most workflows, and what timestamp information would actually help users manage worktrees. Junio Hamano has also questioned whether the feature's maintenance cost is warranted given the alternatives. While Norbert appears open to expand sorting options, the patch needs clearer use cases demonstrating why these metadata features are needed beyond what existing mechanisms provide.
