This is the second patch in a 2-part documentation series promoting the `b4` tool for Git mailing list workflows, following up on the first patch that introduced b4 configuration files. Patrick Steinhardt updates the contributor documentation to explicitly recommend b4 as the preferred way to handle patch submission and review.

The patch makes two main changes:
1. Adds a new section to `MyFirstContribution.adoc` explaining how to use b4 for preparing, sending, and revising patch series, including commands for enrolling branches, editing cover letters, and sending revisions with automatic versioning and range-diffs.
2. Updates `SubmittingPatches` to mention b4 alongside GitGitGadget as an alternative to raw email tools, with a specific recommendation for contributors to use b4 due to its automation benefits.

The documentation presents b4 as building on top of `git format-patch` and `git send-email` while automating much of the manual bookkeeping those tools require. The changes are purely additive and well-contained, continuing the series' goal of improving contributor experience by formalizing b4 usage as a community practice.

This completes the series started in patch 1/2, providing both the configuration foundation and the documentation guidance needed to encourage b4 adoption. The changes appear straightforward and non-controversial, aligning with Junio Hamano's previously expressed support for b4 tooling.
