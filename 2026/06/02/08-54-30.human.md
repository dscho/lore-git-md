This is the final patch in Patrick Steinhardt's series improving TAP output validation in Git's test infrastructure. The patch makes `prove` fail when encountering invalid TAP output, helping catch format violations earlier.

The change addresses a discrepancy where Meson would warn about invalid TAP output while `prove` silently accepted it. By adding a `pragma +strict` directive when running under `prove`, the test harness will now treat malformed output as a failure. This would have caught the fsmonitor test issues fixed earlier in the series, as shown in the example output where initialization messages were incorrectly mixed with TAP output.

The implementation is straightforward - it adds the pragma when the `HARNESS_ACTIVE` environment variable is set (indicating `prove` is running). The patch maintains backward compatibility while making the test infrastructure more strict about output format. This preventative measure should help avoid similar issues creeping back in, particularly benefiting developers using Meson who previously saw distracting warnings.

As with the rest of the series, this is a focused, mechanical improvement to test infrastructure rather than a behavioral change. It completes the set of fixes by adding enforcement to match the earlier corrections. The patch appears ready for merging as it cleanly solves a clear problem with minimal risk.
