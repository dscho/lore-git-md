Patrick Steinhardt has proposed a series of four patches to improve the reliability of Git's test infrastructure by addressing various TAP output validation issues. The series fixes specific problems that have slipped through in the past while adding stricter validation to prevent similar issues in the future.

The first three patches address concrete issues: fixing test number reuse in fsmonitor tests (t7527), silencing spurious EBUSY errors during Windows test cleanup (t921x Scalar tests), and improving process termination handling in git-p4 tests. The final patch, which just landed in the thread, makes the test harness more strict by configuring `prove` to fail on invalid TAP output. This change leverages a TAP extension (`pragma +strict`) to catch malformed output early, which would have prevented the fsmonitor test issues fixed earlier in the series.

The changes are mechanical improvements to test infrastructure rather than behavioral modifications, touching test scripts and harness configuration without affecting core Git functionality. The series appears well-considered and ready for review, though no reviewers have commented yet. These changes build on ongoing efforts to make Git's test output more reliable across different platforms and test environments, particularly for Windows and container-based testing scenarios.
