Patrick Steinhardt's series improving TAP output validation in Git's test infrastructure appears ready for merging. The four-patch v2 series addresses several long-standing issues where invalid test output could slip through unnoticed, particularly affecting fsmonitor tests, Windows cleanup, and git-p4 test termination.

The series fixes specific problems like test number reuse in fsmonitor tests (t7527) and Windows EBUSY errors during cleanup, while also adding broader protections. The final patch enforces strict TAP parsing by adding a `pragma +strict` directive when tests run under prove, ensuring future protocol violations will be caught. This leverages a TAP 14 feature that's been available in prove since 2008 but wasn't previously enabled in Git's test harness.

All review feedback from v1 iteration has been addressed, including Junio C Hamano's catch of a variable naming inconsistency in the git-p4 test cleanup improvements. The changes are mechanical infrastructure improvements that don't modify test behavior, just make the output validation more rigorous. The series builds on ongoing efforts to improve test reliability across platforms and would have caught the fsmonitor test issues through early validation. With no remaining open questions, this appears ready to be picked up for the next cycle.
