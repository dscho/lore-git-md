Thread identity: Feature patch adding metadata tracking to Git worktrees, including creation timestamps and user-provided descriptions.

Core problem/goal: Enable users to track when worktrees were created and add descriptive notes about their purpose, making it easier to manage multiple worktrees. The implementation maintains backward compatibility while adding new metadata capabilities.

Key technical details:
- New metadata stored in `.git/worktrees/<id>/`:
  - `created`: Unix timestamp (auto-recorded on creation)
  - `note`: free-form user description (implementation under discussion)
- New commands/options:
  - `git worktree add --note <text>`
  - `git worktree annotate` subcommand for modifying notes
  - Enhanced `git worktree list` with `--show-created`, `--show-note`, `--sort` options
- Main worktree cannot be annotated (no administrative files)
- Pre-existing worktrees show "created: unknown" and sort after timestamped ones

Current status: Initial version of patch submitted with comprehensive test coverage in t/t2410-worktree-metadata.sh and updates to t2402. Backward compatibility maintained. Junio C Hamano has suggested using the existing `description` file mechanism (via `$GIT_COMMON_DIR/worktrees/$worktree/description`) rather than introducing a new `note` file, noting this would maintain consistency with long-standing repository identification conventions.

Implementation notes:
- Self-contained feature addition
- Follows existing patterns except for the `note` vs `description` question
- No apparent conflicts with ongoing efforts
- Thorough documentation and test coverage

Open questions: Whether to use new `note` file or existing `description` mechanism for worktree notes. This remains the primary design question to resolve.

Participant positions:
