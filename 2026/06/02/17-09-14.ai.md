This is the first patch in the fifth version of an 8-part series completing the migration of configuration globals into `struct repo_config_values` as part of Git's ongoing `the_repository` removal effort. The patch moves the `core.trustctime` configuration from a global variable to repository-specific storage.

The change affects low-level stat-matching functions like `match_stat_data()` where `core.trustctime` is used to determine whether to check ctime changes. The patch maintains the existing eager parsing behavior to avoid performance regressions and potential fatal errors in these critical paths. The modification follows the established pattern for this refactoring effort, updating all references to use the new repository-specific storage location.

The diff shows changes across three files: removing the global `trust_ctime` variable from environment.h, adding it to `struct repo_config_values`, and updating the statinfo.c implementation to access the value through the repository config. The patch has already been reviewed and approved by Christian Couder, with no outstanding technical issues remaining from previous iterations.

This is a mechanical but important step in eliminating global state from Git's codebase, preventing cross-repository configuration leakage while maintaining performance in critical paths. The change is part of a larger, well-established effort that has been progressing through multiple review cycles.
