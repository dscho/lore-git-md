This is part 6/8 of a series completing the `the_repository` removal effort by migrating the `core.sparseCheckoutCone` configuration into `struct repo_config_values`. The patch moves this sparse-checkout-related setting from a global variable to repository-specific storage, preventing cross-repo state leakage while maintaining the existing eager parsing behavior needed for early repository setup.

The change affects several commands and subsystems that interact with sparse-checkout, including `git mv`, `git sparse-checkout`, and the index/sparse-index handling. The patch updates all call sites to access the configuration through the repository-specific `repo_config_values()` interface rather than the global variable. 

The implementation follows the established pattern seen in earlier patches of this series, with careful attention to preserving the existing behavior while eliminating global state. The sparse-checkout cone mode remains an integer (not converted to boolean) to maintain compatibility with the existing tristate handling. 

This appears to be a straightforward mechanical conversion that completes the migration of another configuration setting as part of the broader `the_repository` removal effort. The patch has already received positive reviews from multiple contributors and aligns with the maintainer-approved approach for this large-scale refactoring.
