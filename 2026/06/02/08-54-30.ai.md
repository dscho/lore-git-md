This is the final patch in Patrick Steinhardt's series to improve TAP output validation in Git's test infrastructure. The patch makes `prove` fail when encountering invalid TAP output, helping catch format violations earlier in the development process.

The change addresses a discrepancy between how different test harnesses handle malformed TAP output - while `prove` silently accepts invalid lines, Meson prints warnings. The patch leverages a long-standing but unofficial TAP extension (`pragma +strict`) that causes `prove` to treat invalid output as test failures, even though the formal TAP 14 specification standardizing this behavior is relatively new.

The implementation adds the pragma declaration to the test harness initialization in `t/test-lib.sh`, ensuring all tests will be validated strictly when run through `prove`. This would have caught the fsmonitor test issues fixed earlier in the series, as demonstrated by the example output showing `prove` detecting and reporting the "Initialized empty Git repository" message as an invalid TAP token.

The change is well-motivated and builds on previous work to improve TAP output reliability (referencing commits b1dc2e796e and 362f69547f). As with the rest of the series, this is a focused mechanical improvement rather than a behavioral change, and appears ready for merging. The patch maintains compatibility with existing test runs while making the harness more strict about output validation.
