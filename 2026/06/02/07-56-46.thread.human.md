This thread reports a subtle bug in Git's performance test infrastructure where `GIT_PERF_*` environment variables can be silently lost when running tests with `--verbose-log` or `--tee` options. Jeff King (Peff) identified that the issue stems from an interaction between `perf-lib.sh`'s variable preservation and `test-lib.sh`'s logging behavior, particularly when triggered indirectly via `GIT_TEST_OPTS` in the build configuration.

The problem appears to have been introduced by commit 32b74b9809 (which allowed `GIT_PERF_*` overrides) and made worse by build system changes in 4638e8806e. While this doesn't affect end users, it could lead to misleading performance test results if scripts unintentionally use different repository configurations than intended. Peff notes that a proper fix would require non-trivial changes to `test-lib.sh`'s environment handling, making this a potentially complex issue to resolve.
