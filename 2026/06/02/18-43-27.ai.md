This is the first patch in the v6 series improving `git config` command-line syntax errors. It refactors the config key parsing API as requested by Junio, separating validation from parsing while maintaining the same behavior.

The patch introduces a new internal `do_parse_config_key()` helper that handles the actual parsing logic with a `quiet` flag parameter. The existing `git_config_parse_key()` becomes a thin wrapper around this, maintaining backward compatibility. A new public `git_config_key_is_valid()` function is added for callers that only need validation without allocation.

Key technical changes:
- Splits parsing into three layers: internal helper, original API wrapper, and new validation-only API
- Makes the key storage parameter optional via NULL checks
- Preserves all error cases and messages from previous versions
- Adds the quiet flag to suppress errors for validation-only use

The implementation cleanly separates concerns while keeping the same validation rules. This prepares for the user-facing improvements in patch 2/2 while satisfying Junio's API design request. The changes are mechanical refactoring with no behavior change for existing callers.
