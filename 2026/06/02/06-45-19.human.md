This is a performance optimization discussion for index-pack's delta resolution cache behavior.

Jeff King (Peff) follows up on Arijit Banerjee's v2 patch with a thoughtful technical question about the cache eviction strategy. While agreeing with the core premise that the current "done" detection is too aggressive, Peff suggests an alternative approach: rather than always letting the cache manage retention (the patch's current approach), we could track when a base object is truly no longer needed by any remaining deltas and evict it precisely then.

The key insight is that with multiple delta chains sharing a common base (like A being used by both B->C and D->F chains), we currently free A after processing just one chain. Peff's proposal would keep A cached until all dependent deltas are resolved, potentially making better use of cache space under memory pressure. He acknowledges uncertainty about both implementation complexity and real-world impact, noting the existing cache behavior may already approximate LRU.

This moves the discussion beyond the original patch's scope into deeper cache management questions. Peff's tone is constructive - he's not blocking the current change but exploring whether we can do even smarter cache management. The thread shows experienced contributors collaborating to refine a performance optimization.
