This is the second patch in Junio C Hamano's documentation series updating the SubmittingPatches guide. It adds a new section on writing effective cover letters for patch series.

The patch introduces a `[[cover-letter]]` section with concrete advice for contributors, emphasizing that cover letters should make the series' purpose clear to both new readers and those familiar with prior iterations. Key points include:
- Cover letters should explain changes clearly without requiring prior context
- Later iterations should still introduce the topic for newcomers
- Summarizing changes from previous versions helps returning reviewers

The guidance reflects Junio's recent mailing list advice that cover letters should "sell the idea to the widest possible audience." As a maintainer-authored documentation change, this carries implicit approval of the described practices. The addition is well-structured and fits naturally with the existing document's style.

This completes the two-patch series that began with reorganizing typo-fix guidance. Both changes are straightforward documentation improvements that clarify contributor expectations without introducing controversy.
