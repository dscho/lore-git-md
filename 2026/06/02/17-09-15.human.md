This is part 2 of an 8-patch series completing the `the_repository` removal effort by migrating configuration globals into repository-specific storage. The series is now in its fifth iteration and appears merge-ready, with maintainer approval pending this final documentation fix.

The patch moves the `core.checkstat` configuration (which controls how Git checks file freshness via `match_stat_data()`) from a global variable into `struct repo_config_values`. This continues the project-wide effort to eliminate global state while maintaining the existing performance characteristics - the setting remains eagerly parsed since it affects critical filesystem operations. The change prevents cross-repository state leakage in multi-repo operations.

The mechanical changes touch several files that interact with stat checking, including `entry.c` (checkout handling) and `statinfo.c` (core freshness checking logic). The patch follows established patterns from prior migrations in this large-scale refactoring effort, with careful attention to preserving behavior while eliminating globals. Reviewers have already signed off on the technical approach, and this version addresses the last known documentation issue from previous iterations.
