This is the sixth version of a UX improvement patch series for the config subsystem, addressing user confusion when mistakenly using `=` syntax in `git config` commands. The series implements Junio's requested API redesign while maintaining the approved user-facing behavior.

The key changes in v6:
1. Restructures the key validation API as suggested, introducing:
   - A new static `do_parse_config_key()` helper that handles the quiet flag
   - A thin public `git_config_parse_key()` wrapper maintaining the original signature
   - A new public `git_config_key_is_valid()` for validation-only use cases
2. Preserves all the user-facing improvements from v5:
   - Clear error messages for missing values
   - Contextual hints for valid keys with wrong syntax
   - No hints for invalid keys
3. Adds more test coverage for edge cases like numeric-prefixed sections

The implementation now cleanly separates the internal parsing logic from the public API while maintaining all the validation cases. The user experience remains unchanged from the approved v5 version, with the same three-case error structure and hint behavior. This appears ready for merging once the final API structure is confirmed.
