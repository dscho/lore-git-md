This thread documents Patrick Steinhardt's effort to standardize Git contributor workflows around the `b4` tool for mailing list interactions. The three-part v2 series addresses both documentation and technical configuration to make b4` adoption smoother, particularly for new contributors.

The first two patches updated Git's `MyFirstContribution` tutorial to recommend b4's shallow threading model (--no-chain-reply-to) and added detailed b4 workflow instructions. The just-landed third patch completes the technical implementation by adding project-level configuration files: `.b4-config` sets defaults including the threading model, while `.b4-cover-template` provides a custom template with range-diff support. The implementation favors direct configuration files over sample files (Junio's earlier suggestion), but keeps them overrideable via git-config for flexibility.

The series has seen responsive iteration - Patrick incorporated feedback from v1, including documentation structure improvements from Ramsay Jones. While the pedagogical positioning of b4 (fundamental vs advanced tool) saw some early discussion, the current approach presents it as a recommended option with clear instructions. Junio hasn't commented on v2's configuration file approach yet, but the changes are straightforward and unlikely to face significant opposition given they preserve individual workflow flexibility. With this final patch, the series provides both the documentation and technical foundation for standardized b4 usage in Git development.
