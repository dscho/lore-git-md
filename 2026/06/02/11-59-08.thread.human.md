Patrick Steinhardt's patch series promoting the `b4` tool for Git mailing list workflows has received its first substantive review from maintainer Junio Hamano. The two-part series aims to improve contributor experience by standardizing on b4 for patch submission and review, with the first patch adding configuration files and the second updating documentation.

Junio raised a specific technical concern about the implementation approach, suggesting that the proposed `.b4-config` and `.b4-cover-template` files should instead be provided as `.sample` files that contributors can optionally copy and customize. This follows Git's established pattern for configuration files (like `.gitconfig.sample`) and would avoid making the working tree dirty when these files are modified locally. The feedback doesn't reject the functionality but guides it toward better alignment with Git's conventions.

The review focused narrowly on this implementation detail in patch 1/2, leaving the broader documentation changes in patch 2/2 untouched for now. Patrick will likely need to revise the first patch to use the `.sample` convention before the series can proceed. Given Junio's prior endorsement of b4 usage (referenced in the cover letter) and the focused nature of this feedback, the path forward appears clear once this technical adjustment is made.
