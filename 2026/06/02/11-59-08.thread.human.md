Patrick Steinhardt's documentation series promoting the `b4` tool for Git mailing list workflows has reached a mature state, with version 2 addressing all substantive technical concerns about threading models and tool behavior. The series now includes tutorial modifications, comprehensive workflow documentation, and configuration files to standardize on shallow threading (where all patches in a series reply to the cover letter rather than nesting deeply). Key contributors like SZEDER Gábor, Weijie Yuan, and Tuomas Ahola helped clarify terminology differences between Git's threading preferences and b4's implementation, while Toon Claes identified version compatibility considerations for b4 v0.15+.

Kristoffer Haugsbakk's recent feedback provides valuable real-world validation of the approach, describing how deep threading creates mobile reading difficulties (particularly in Safari where deeply nested replies become unclickable), while Patrick's own git-history series - which used shallow threading - remained easily navigable. This practical perspective reinforces the documentation update's value beyond technical correctness, showing it will improve the contributor experience for mobile readers.
