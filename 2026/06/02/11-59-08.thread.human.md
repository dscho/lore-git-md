Patrick Steinhardt's documentation series promoting the `b4` tool for Git mailing list workflows has sparked a multi-faceted discussion. The core goal is to standardize on b4` for patch submission while resolving inconsistencies with existing workflow guidance. The technical debate centers on two configuration approaches - direct `.b4-config` files versus maintainer-preferred sample variants - and has expanded to include a terminology discussion about what constitutes "shallow" versus "deep" threading models in patch series context.

Junio Hamano, the maintainer, recently weighed in to support Ramsay Jones' suggestion to include references to b4's website documentation, recognizing that not all contributors may be familiar with the tool. This maintainer acknowledgment carries weight and suggests the final patches should include such onboarding guidance. Meanwhile, reviewers Weijie Yuan and Tuomas Ahola continue discussing threading model terminology, with Yuan asserting that replying to a cover letter constitutes deep threading while Ahola relates it to GitGitGadget's established behavior. The thread remains open on several fronts: configuration approach, threading definitions, and how to best sequence the pedagogical aspects of introducing this tool to new contributors.
