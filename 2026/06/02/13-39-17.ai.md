This is the second patch in a two-part series improving the user experience around `git config` command-line syntax errors. The series addresses a common mistake where users incorrectly use `=` instead of a space when setting config values.

The patch focuses on providing better error messages when users forget to provide a value for `git config set`. It now detects when the argument has the form "key=value" and suggests the correct split syntax ("key value") when the key portion is valid. For invalid keys, it omits the hint to avoid confusion.

Key technical aspects:
- Introduces `die_missing_set_value()` helper to handle the error cases consistently
- Uses the enhanced `git_config_parse_key()` from patch 1/2 for robust validation
- Maintains clear error differentiation between:
  - Valid keys with missing values (shows hint)
  - Invalid keys (no hint)
  - Malformed syntax (original behavior)
- Adds comprehensive test coverage including:
  - Valid/invalid key patterns
  - Implicit vs explicit `set` forms
  - Edge cases like numeric-prefixed sections
  - Proper handling of `=` in subsections

The implementation builds on the core parser changes from 1/2 and appears ready for merging. This completes the series' goal of helping users recover from the common `=` syntax mistake while maintaining strict validation of config key patterns.
