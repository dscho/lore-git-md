This is part 2/8 of a series completing the `the_repository` removal effort by migrating configuration globals into `struct repo_config_values`. The patch moves the `core.checkstat` configuration (which controls file freshness checking behavior) from a global variable to repository-specific storage.

The change affects how Git determines whether files have changed by moving the `check_stat` flag into `repo_config_values`. This maintains the existing performance-sensitive eager parsing behavior while preventing cross-repository state leakage. The patch updates all call sites that check file status (primarily in `statinfo.c` and `entry.c`) to use the repository-specific value.

Key technical details:
- Preserves the existing eager parsing optimization for performance-critical file status checks
- Follows the established pattern for migrating configuration globals
- Touches core file status checking paths used by commands like `status`, `checkout`, and `diff`
- Maintains Windows/Cygwin special casing where inode trust is always disabled

The change is mechanical but important for the larger architectural goal of eliminating global state. It has already received positive reviews from Christian Couder and Usman Akinyemi, with no outstanding issues identified. This continues the series' progression toward being merge-ready.
