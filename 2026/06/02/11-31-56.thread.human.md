This thread reports a platform-specific bug in Git for Windows where clone operations fail with a pack file corruption error ("fatal: pack has bad object at offset 460179591: inflate returned 1"). The same repository clones successfully on Linux (Git 2.47.3), suggesting the issue lies in the Windows implementation's handling of pack file transfer or decompression rather than the remote repository itself. The reporter provided clear version details (Git for Windows 2.54.0.windows.1) which should help diagnose whether this is a network transfer, decompression, or index handling issue. As this affects a core operation on a major platform, it will need attention from the Git for Windows maintainers.
