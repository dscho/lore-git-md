This is a feature patch adding metadata tracking to Git worktrees. The patch introduces two new pieces of metadata for each worktree:

1. A creation timestamp (automatically recorded when the worktree is created)
2. A free-form note/description) that can be set by the user

Key changes include:
- New `--note` option for `git worktree add` to set an initial description
- New `git worktree annotate` subcommand to add/change/remove notes on existing worktrees
- Enhanced `git worktree list` with `--show-created`, `--show-note`, and `--sort` options to display and organize by the new metadata
- Porcelain output format extended to include the metadata when present
- The main worktree cannot be annotated (as it has no administrative files)
- Backward compatibility is maintained - worktrees created before this change will show "created: unknown" and sort after timestamped ones

The implementation stores the metadata in files under `.git/worktrees/<id>/`:
- `created` contains a Unix timestamp
- `note` contains the user-provided description

The patch includes comprehensive tests covering all new functionality in t/t2410-worktree-metadata.sh. The author has also updated existing tests in t2402 to handle the new metadata fields.

- Clear documentation of the new options and behaviors
- Careful handling of backward compatibility
- Thorough test coverage
- Clean implementation following existing patterns

The feature addresses a real use case (tracking worktree purposes and ages) without introducing significant complexity. The patch is self-contained and doesn't appear to conflict with any ongoing efforts.
