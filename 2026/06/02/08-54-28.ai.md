Test infrastructure patch addressing Windows-specific TAP output corruption during test cleanup. This is the second patch in Patrick Steinhardt's series to fix TAP validation issues.

The patch silences EBUSY errors from `rm -rf` during test directory cleanup on Windows, where lingering processes (like the fsmonitor daemon in t921x Scalar tests) can hold file handles open. While the proper fix would be to ensure all processes are terminated, this pragmatic workaround redirects error output to /dev/null during cleanup attempts to prevent the messages from breaking the TAP format. The change is minimal - just adding `2>/dev/null` to two `rm` calls in t/test-lib.sh - but addresses a real issue where test output was being corrupted. The patch maintains the existing retry behavior and final error reporting if cleanup ultimately fails.

This continues the series' theme of mechanical improvements to make test output more reliable, particularly for Windows environments where process management differs from Unix. The change is low-risk since it doesn't modify test behavior, only error message handling during cleanup.
