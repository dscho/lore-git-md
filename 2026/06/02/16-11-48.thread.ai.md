Thread identity: HTTP authentication bugfix addressing loss of WWW-Authenticate headers during redirects, particularly impacting OAuth flows. Authored by Aaron Plattner.

Core problem: When Git follows HTTP redirects (e.g. HTTP->HTTPS), it clears credentials but incorrectly discards WWW-Authenticate headers from the redirect response. This breaks authentication flows that rely on these headers to determine supported methods, particularly OAuth bearer token authentication.

Current status: The immediate 14-line fix in `http.c` (preserving WWW-Authenticate headers during redirects) has been confirmed correct, safe, and is now explicitly treated as a standalone fix. Architectural refactoring (e.g., introducing a `credential_update_url()` helper in `credential.c`) is acknowledged as a follow-on improvement but decoupled from the immediate fix. Junio has merged the bugfix to `master`; no further action is required for the core issue. The helper-function refactoring remains a low-priority, unaddressed follow-up.

Technical details: The fix preserves WWW-Authenticate headers during credential updates triggered by redirects. Test coverage includes new Apache redirect configuration (`t/lib-httpd/apache.conf`) and verification that credential helpers receive expected headers post-redirect. Both parties confirm the implementation is safe (no leaks or use-after-free) with negligible overhead. Key files: `http.c` (authentication handling), `t/t5551-http-fetch-smart.sh` (test case), `credential.c` (future refactoring target). The patch is now in `master` (merge date unknown).
