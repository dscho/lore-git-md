Thread identity: HTTP authentication bugfix addressing loss of WWW-Authenticate headers during redirects, particularly impacting OAuth flows. Authored by Aaron Plattner.

Core problem: When Git follows HTTP redirects (e.g. HTTP->HTTPS), it clears credentials but incorrectly discards WWW-Authenticate headers from the redirect response. This breaks authentication flows that rely on these headers to determine supported methods, particularly OAuth bearer token authentication.

Current status: Initial patch version works correctly for immediate WWW-Authenticate header preservation with comprehensive test coverage. Maintainer review confirms correctness but raises architectural concerns. Author agrees with technical assessment while considering broader design implications.

Technical details: The 14-line fix in http.c preserves WWW-Authenticate headers during credential updates triggered by redirects. Test coverage includes new Apache redirect configuration and verification that credential helpers receive expected headers post-redirect. Both parties acknowledge the implementation is safe (no leaks or use-after-free) though somewhat inefficient due to string copying. Author confirms the overhead is negligible compared to typical Git operations.

Key files: http.c (authentication handling), t/lib-httpd/apache.conf (test redirect setup), t/t5551-http-fetch-smart.sh (test case), credential.c (potential future refactoring target)

Open questions:
- Architectural concern: Whether other credential struct members might need similar preservation in future
- Design question: Whether manual save/restore creates brittle coupling between HTTP and credential layers
- Maintainer suggests alternative approach via new `credential_update_url()` function in credential.c for better encapsulation
- Author suggests WWW-Authenticate headers may belong in separate HTTP-specific structure rather than credential struct
- Reveals unsuccessful attempts to avoid clearing headers via credential_clear()

Participant positions:
- Maintainer (Junio C Hamano) confirms current patch works but proposes more maintainable long-term solution
- Author (Aaron Plattner) agrees with technical assessment while considering broader design implications
- Both acknowledge tension between immediate fix and long-term architectural health

Related work: Connects to broader HTTP authentication subsystem and credential helper implementations. May affect projects implementing OAuth-based Git authentication. Potential follow-on work to refactor credential URL update logic and reconsider header storage location.
