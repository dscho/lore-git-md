This is a bug report about Git for Windows failing to complete a clone operation. The user reports that while cloning works fine from Linux, on Windows it fails with an error about a corrupt pack object during the fetch phase. The error suggests an inflation failure when processing the packfile data.

The key details:
- Remote server runs Git 2.47.3
- Windows client is Git for Windows 2.54.0.windows.1
- Error occurs consistently with "fatal: pack has bad object at offset 460179591: inflate returned 1"
- Same clone operation succeeds on Linux

This appears to be a Windows-specific issue with packfile handling, possibly related to zlib inflation or network transport differences. The fact that it works on Linux but fails on Windows with the same repository suggests a platform-specific bug rather than a repository corruption issue. The report includes all the key troubleshooting details (versions, error message, reproduction steps) making it a well-formed bug report.
