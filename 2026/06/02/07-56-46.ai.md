This is a bug report about environment variable handling in Git's performance test infrastructure. Jeff King (Peff) identifies an issue where `GIT_PERF_*` variables set in the environment are lost when running performance test scripts with `--verbose-log` or `--tee` options.

The problem stems from an interaction between how `perf-lib.sh` tries to preserve these variables and how `test-lib.sh` re-executes scripts when logging is enabled. The issue is particularly subtle because it can be triggered indirectly via `GIT_TEST_OPTS` in `config.mak`, leading to confusing behavior where test scripts suddenly stop respecting explicitly set `GIT_PERF_*` variables.

The bug appears to be a consequence of commit 32b74b9809 (perf: do allow `GIT_PERF_*` to be overridden again) and is exacerbated by the build system changes in 4638e8806e (Makefile: use common template for GIT-BUILD-OPTIONS). Peff notes that fixing this would require deeper changes to `test-lib.sh`'s environment handling and expresses hesitation about the complexity of such a solution.

This is a technical deep-dive into Git's test infrastructure plumbing, affecting developers who run performance tests with custom repository configurations. The bug doesn't have immediate user-facing impact but could lead to misleading performance results if test scripts silently use different repositories than intended.
