This is the first patch in a 4-part series fixing TAP output validation issues in Git's test infrastructure, with a focus on the fsmonitor tests (t7527). The patch addresses a specific problem where the test's initial filesystem verification was printing output outside the TAP format, potentially corrupting the test results.

The change moves the filesystem verification check from a direct function call into a lazy prerequisite (`FSMONITOR_WORKS`). This ensures the verification output is properly captured within the TAP framework rather than leaking raw output that could break the test harness's parsing. The fix is mechanical and well-contained, touching only the fsmonitor test file.

The patch demonstrates good attention to test hygiene - it solves a real problem (TAP output corruption) that could mask test failures, while maintaining the same functional behavior. As the first in a series that already has a clear overall goal (improving TAP validation), this change sets up the subsequent preventative measures by first fixing existing issues.
