This is the first patch in Patrick Steinhardt's series to fix TAP output validation issues in test infrastructure, specifically targeting the fsmonitor tests (t7527). The patch addresses a problem where the test suite's TAP output was being corrupted by extraneous output from `git init` during fsmonitor capability verification.

The change moves the filesystem verification from a direct function call into a lazy prerequisite (`FSMONITOR_WORKS`). This ensures the verification output is properly captured and doesn't interfere with the TAP format. The fix is mechanical and well-contained, touching only the fsmonitor test file. It solves a real problem (TAP output corruption) that has caused issues in the past, particularly on container/overlayfs environments where fsmonitor may not work.

The patch demonstrates good attention to test infrastructure details - it maintains the same functionality while making the output more reliable. As the first in a series that aims to both fix existing issues and prevent future ones, this sets a solid foundation for the subsequent patches.
