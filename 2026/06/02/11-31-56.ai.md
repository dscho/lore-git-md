This is a bug report about Git for Windows failing to complete a clone operation. The user reports that while cloning a repository from a remote server (running Git 2.47.3) works fine on Linux, it fails on Windows (Git for Windows 2.54.0.windows.1) with an error about a corrupt pack file: "fatal: pack has bad object at offset 460179591: inflate returned 1". 

The error suggests either corruption in the pack file being transferred or an incompatibility in how Windows handles the compression/decompression of pack files compared to Linux. The fact that the same operation succeeds on Linux points to a platform-specific issue in the Windows implementation rather than a problem with the remote repository itself.

This appears to be a genuine bug in Git for Windows' pack file handling, though without more information it's unclear whether the issue lies in the network transfer, decompression, or index handling. The report includes all relevant version information which will help diagnose the issue. Since this is a core operation failing on a supported platform, this would likely warrant investigation by the Git for Windows maintainers.
