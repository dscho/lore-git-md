This thread fixes a segfault that occurs when Git encounters an invalid `.git` file path, a regression introduced in March 2026. The issue was traced to `read_gitfile_gently()` improperly handling error paths, leading to NULL pointer dereferences when reporting the target repository path. Jeff King (Peff) submitted a third version of the patch that simplifies error reporting to show only the problematic `.git` file path, removing the risky out-parameter approach entirely. The fix is now ready for merging after addressing all review feedback, including clarifying test expectations for parallel submodule cloning scenarios.

The solution prioritizes simplicity and robustness, replacing the original "not a git repository" error message with a clearer "gitfile does not point to a valid repository: %s". Key changes include updates to `setup.c`, `submodule.c`, and two test files (`t/t0002-gitfile.sh` and `t/t7450-bad-git-dotfiles.sh`), with particular attention to fixing a race condition in the latter. Junio C Hamano and Patrick Steinhardt reviewed the patch, with Junio initially flagging test ambiguity but later accepting Peff's explanation that the test matches any one of the listed patterns rather than all. The bare `grep` usage in tests remains as-is, with the understanding that any modernization conflicts will be resolved during integration.

All participants are aligned on the technical approach, and the patch maintains backward compatibility while improving debuggability. A separate but related discussion about worktree pruning was noted, though no action is required in this thread. The fix demonstrates effective collaboration, with clear resolution of all prior concerns.
