This thread addresses a segfault in repository setup when handling invalid .git file paths, introduced by a recent commit. Jeff King (Peff) initially proposed a solution that added path-returning infrastructure, which Junio Hamano accepted while calling the implementation "kind of gross." Peff then suggested a simpler alternative that changes the error message format instead of adding new infrastructure.

Patrick Steinhardt has now weighed in, agreeing with the simpler approach that just shows the original .git path in error messages. He sees no downside to this cleaner solution that maintains sufficient debuggability while reducing code complexity. The discussion also touched on a related worktree pruning issue Peff observed, though Patrick couldn't identify any recent changes that would explain more aggressive pruning behavior.

With Patrick's review and no objections raised, the thread appears to be converging on Peff's simpler error message approach. Patrick also noted a minor style issue (adding curly braces for consistency) that would need addressing in the final patch. The solution maintains backward compatibility while simplifying the code - a good example of Git's iterative refinement process where initial solutions evolve into cleaner implementations through review.
