This is a documentation patch series (2 parts) that formalizes Git's use of the `b4` tool for patch submission and review. Patrick Steinhardt proposes adding configuration files for b4 and updating the tooling recommendations in the contributor documentation.

The series:
1. Adds `.b4-config` and a cover letter template specifically for Git project contributions
2. Updates `MyFirstContribution.adoc` to recommend b4 over raw email tools, with detailed instructions on setup and workflow

The motivation comes from a prior discussion (referenced but not quoted here). The changes look well-considered - the b4 configuration is minimal but useful, and the documentation updates are thorough while maintaining the existing alternatives for those who prefer traditional email workflows. This aligns with the project's gradual modernization of contribution tooling while staying within the email-based workflow paradigm.
