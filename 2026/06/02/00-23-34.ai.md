Documentation patch follow-up addressing formatting and edge cases in timestamp parsing.

Junio Hamano provides review feedback on Luna Schwalbe's documentation patch about the `@` prefix for raw timestamps. He notes two technical points:

1. The documentation formatting may need adjustment to match the style used elsewhere in `date-formats.adoc`, suggesting removing the four-space indent and using a '+' list continuation operator instead, similar to the "ISO 8601" section.

2. Points out an edge case where the test rejects '99999999' as ambiguous when it technically couldn't be a valid YYYYMMDD date (since there's no 99th month or day). This suggests the parsing rules could potentially be made more precise to accept such clearly non-date values even without the `@` prefix.

The review maintains focus on the documentation and parsing behavior without requesting functional changes. Junio's comments indicate careful reading of both the documentation formatting and the test cases, though he acknowledges the second point is "totally outside the scope" of the current patch. The exchange shows the maintainer engaging with both presentation details and potential future improvements to the timestamp parsing logic.
