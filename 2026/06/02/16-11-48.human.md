This is a bugfix for HTTP authentication handling when following redirects. The patch addresses an issue where authentication headers (WWW-Authenticate) were being lost when cURL follows a redirect, breaking OAuth and other authentication flows that rely on these headers.

The problem occurs because credential_from_url() clears all credential information including the wwwauth_headers when processing a redirect, even when the new URL doesn't contain embedded credentials. The fix preserves these headers across the redirect, allowing credential helpers to see the server's supported authentication methods.

The patch includes a test case demonstrating the scenario where a server redirects from HTTP to HTTPS and provides OAuth authentication headers. Without the fix, the credential helper wouldn't receive these headers and couldn't properly authenticate. The change is small and focused, with clear test coverage showing both the problem and solution.

This appears to be a well-motivated fix for a real-world authentication scenario, particularly relevant for OAuth workflows. The patch maintains the existing behavior when credentials are embedded in URLs while fixing the case where they come from credential helpers.
