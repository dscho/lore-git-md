This is a platform compatibility test patch, the first in a series addressing Windows' LLP64 limitations with large (>4GB) objects. The patch adds a failing test case demonstrating the issue where Git's use of `unsigned long` (32-bit on Windows) prevents proper hashing of files over 4GB when using `git hash-object --literally`.

The test generates a 5GB file and attempts to hash it, expecting the operation to fail on LLP64 systems until subsequent patches convert the relevant code to use `size_t`. The test is marked expensive and platform-specific (only runs where `size_t` is 64-bit but `long` is not). Johannes Schindelin has signed off, indicating this has been validated in Git for Windows.

This is a well-scoped first step in a series that has already proven stable downstream. The test cleanly isolates the issue from other large-file code paths by using `--literally` to avoid zlib and packfile handling. The commit message clearly explains the technical context and how this test fits into the broader fix.
