This is a response to review feedback on the final patch in Patrick Steinhardt's `git history drop` series, which implements a new subcommand for removing commits from history while replaying their descendants. The exchange focuses on documentation and test style issues raised by Kristoffer Haugsbakk.

Patrick addresses several minor points from the review:

1. Defends the unquoted section name "LIMITATIONS" in documentation, noting this matches existing style in the same manpage.

2. Acknowledges the suggestion to demonstrate revision expressions (like `main^{/second}`) instead of raw hashes in examples, agreeing this could make the command more ergonomic compared to rebase's interactive editor. He hints at future plans for a TUI interface to further improve usability.

3. Explains the use of `test_grep` over `test_cmp` for error messages as an established (if not strictly consistent) pattern in the test suite.

4. Accepts the observation about inconsistent use of subshells versus `git -C` in tests, promising to standardize this in the next iteration.

The response maintains the technical focus of the series while engaging constructively with the stylistic feedback. Patrick demonstrates his characteristic attention to detail, noting where existing conventions justify current choices and where improvements can be made. The exchange doesn't touch on the core functionality changes from the patch, instead resolving peripheral documentation and testing questions in preparation for the v3 submission.
