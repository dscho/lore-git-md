This is the second patch in a platform compatibility effort to support large objects (>4GB) on Windows (LLP64) systems. The series converts object header length handling from `unsigned long` to `size_t` to properly handle large files where 32-bit `long` would be insufficient.

This patch specifically updates the `object-file.c` and `object-file.h` interfaces to use `size_t` for buffer lengths in key object hashing and writing functions. The changes are mechanical type signature updates affecting:
- `hash_object_body()`
- `write_object_file_prepare()`
- `hash_object_file()`
- `odb_source_loose_write_object()`

The patch notes this is part of a larger effort - the test still fails after these changes, indicating more work is needed in lower-level hash functions. The changes have been validated in Git for Windows for 4.5 years, suggesting they're production-ready despite being new to upstream.

This continues the systematic approach seen in patch 1, focusing on core object-file handling code with clear test coverage. The changes are well-contained and appear uncontroversial, being primarily type signature updates for a known platform limitation.
