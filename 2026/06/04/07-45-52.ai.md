This is a test infrastructure patch series introducing a new lint tool to convert bare 'grep' assertions to 'test_grep' in the test suite. The series is well-structured and appears carefully implemented.

The cover letter explains that many tests still use bare 'grep' for assertions, which silently swallows context on failure, while 'test_grep' provides better debugging output. The series adds a lint tool (lint-style.pl) that can detect and convert these cases, reusing the existing shell parser from chainlint.pl to properly handle shell syntax.

Key technical points:
- The tool distinguishes grep assertions (checking exit status) from grep used as filters
- It fixes three pre-existing bugs where grep assertions were missing file arguments
- The conversion handles ~2800 assertions across ~340 files
- Future rules could catch other test anti-patterns like 'test_must_fail grep'

The series is structured as:
1. Documentation of test_grep
2. Extraction of chainlint's parser into a shared module
3. Fix for line counting in the parser
4. Initial lint tool with negation rule
5. Fixes for missing file arguments
6. Bulk conversion of grep assertions

The implementation appears thorough, with attention to edge cases (several special cases are noted as '# lint-ok'). The cover letter provides clear verification instructions and discusses future directions. This looks like a well-prepared contribution to improve test suite maintainability.
