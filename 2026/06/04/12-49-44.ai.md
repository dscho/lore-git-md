This is a response to a bug report about `git gc` and `git fetch` not respecting the `commitGraph.changedPaths` configuration when generating commit-graphs. Patrick Steinhardt confirms this is indeed a bug, explaining that `write_commit_graph_reachable()` is called directly without checking the config, while the newer maintenance tasks handle it correctly by invoking `git-commit-graph` directly.

Patrick suggests the reporter switch to using `git-maintenance` instead of `git gc`, as the former is now Git's default maintenance strategy and properly handles the changedPaths configuration. He notes that while fixing `git gc` would be straightforward (either by using `run_write_commit_graph()` or respecting the config), he personally doesn't plan to work on it as he considers `git gc` a legacy tool being phased out.

The response provides clear technical context about the divergence between the old and new maintenance approaches, and leaves the door open for others to contribute a fix for `git gc` if desired. This positions the issue as a known inconsistency that could be addressed either through configuration updates (switching to maintenance) or code changes (fixing gc), with Patrick favoring the former path.
