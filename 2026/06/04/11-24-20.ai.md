This is a bug report about `git gc` and `git fetch` not respecting the `commitGraph.changedPaths` configuration when generating commit-graphs. The reporter, Tomasz Konojacki, demonstrates that while a direct `git commit-graph write` command honors the setting to generate changed-path Bloom filters, these filters are not created during `git gc` or fetch operations with `fetch.writeCommitGraph` enabled.

The behavior appears inconsistent - the commit-graph is written in both cases, but the additional Bloom filter data is only generated for the explicit `commit-graph write` command. The reporter asks whether this is intentional (it doesn't appear to be) and if there's a way to make the automatic operations generate the filters.

This touches the commit-graph and gc subsystems, specifically around how configuration is handled during automatic maintenance operations versus explicit commands. The issue seems straightforward to reproduce and would likely be of interest to contributors working on the commit-graph feature (like Derrick Stolee who has been involved in this area) or performance-related optimizations.
