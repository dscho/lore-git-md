This is a platform compatibility patch from Johannes Schindelin, part of a series improving Windows process termination behavior. The patch introduces a gentler approach to killing child processes on Windows by injecting threads to call ExitProcess() rather than using TerminateProcess(), allowing for proper cleanup via atexit handlers. 

The change addresses a long-standing issue where Windows' lack of Unix-style signals meant Git couldn't properly clean up (e.g., leaving behind .lock files). The solution has been battle-tested in Git for Windows for nearly a decade. The implementation carefully handles process architecture matching and falls back to forceful termination if the gentler approach fails.

The patch is well-documented with thorough technical explanations of the problem and solution. It touches only Windows-specific code in compat/mingw.c and adds a new compat/win32/exit-process.h header. While limited to same-architecture processes, this represents a significant improvement over the current brute-force approach.
