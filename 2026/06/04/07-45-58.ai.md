This is the final patch in a 6-part series introducing a lint tool to convert bare 'grep' assertions to 'test_grep' in Git's test suite. The series aims to improve test debugging by ensuring failed grep assertions show file contents.

The patch extends lint-style.pl with a rule that detects bare 'grep' used as test assertions and converts them to 'test_grep'. Key technical details:

- Uses the shared shell parser from chainlint.pl to properly handle shell syntax
- Distinguishes grep assertions (convertible) from grep used in pipes/control flow
- Handles various grep forms: negated (! grep), -q flags, pattern files (-f)
- Preserves formatting when fixing by modifying original text
- Adds tests covering edge cases and validation

The implementation:
- Adds is_filter_context() to identify non-assertion grep usage
- Classifies grep commands as assertions, filters, or bugs (missing files)
- Handles conversion of negated grep and -q flags
- Preserves line continuations and formatting
- Adds test cases for all conversion scenarios

The patch also fixes three pre-existing test bugs where grep assertions were missing file arguments. The changes touch ~350 test files, converting ~2800 grep assertions while preserving intentional grep usage via '# lint-ok' annotations.

This completes the series by providing both the detection logic and automated fixing capability, building on the earlier infrastructure patches. The implementation demonstrates careful attention to edge cases and shell syntax handling.
