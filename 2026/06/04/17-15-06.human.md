Windows platform compatibility patch series addressing large object handling limitations. This 6-part series from Philip Oakley (originally contributed 4.5 years ago and maintained in Git for Windows) tackles issues with hashing objects larger than 4GB on LLP64 systems like Windows where `unsigned long` is 32-bit.

The series:
1. Adds test cases demonstrating the >4GB object problem
2. Converts header length variables from `unsigned long` to `size_t` in object-file.c
3. Updates hash algorithm interfaces to use `size_t` for section lengths
4. Verifies `hash-object --stdin` works with >4GB input
5-6. Add additional test cases including filtered input scenarios

The changes are focused on the object-file and hash algorithm subsystems, with corresponding test additions in t1007. This appears to be part of broader efforts to improve Git's handling of large objects across different platforms. The patches have been battle-tested in Git for Windows and are now being proposed for upstream inclusion.
