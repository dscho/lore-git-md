This is the final test case in a platform compatibility series addressing large object handling on Windows (LLP64 systems). The patch adds a test verifying that Git's filter interface correctly processes files over 4GB when using `git hash-object` with a clean filter.

The test reuses the 5GB test file from previous patches (generating it if needed) and exercises the filter code path with a trivial `cat` filter. This specifically targets the clean/smudge filter subsystem to ensure it properly handles large files when `size_t` is 64-bit but `unsigned long` is 32-bit. The test is marked expensive and platform-specific, only running where relevant.

As with previous patches in the series, this has Johannes Schindelin's sign-off and builds on the established pattern of validating large-file handling across different code paths. The series has proven stable through years of use in Git for Windows, and this final test case provides additional coverage for the filtered input scenario. The change is minimal and focused, adding just the test case without modifying production code.
