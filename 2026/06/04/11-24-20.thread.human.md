Tomasz Konojacki reported that `git gc` and `git fetch` fail to generate commit-graph Bloom filters despite the `commitGraph.changedPaths` setting being enabled, while explicit `git commit-graph write` commands work correctly. Patrick Steinhardt has confirmed this is indeed a bug, explaining that the older `write_commit_graph_reachable()` path (used by gc/fetch) bypasses config checks that the maintenance tasks properly handle.

Patrick recommends switching to `git maintenance` instead of `git gc`, as Git's newer maintenance infrastructure correctly processes the changedPaths configuration. While fixing `git gc` would be straightforward (either by using the modern `run_write_commit_graph()` or properly checking the config), Patrick considers gc a legacy tool and doesn't plan to work on it himself. The issue remains open for others to address if they want to maintain compatibility with the older gc/fetch paths, but the recommended solution is to adopt the maintenance-based approach.
