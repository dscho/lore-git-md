This is a build system patch review from Junio C Hamano, the Git maintainer. He's responding to Harald Nordgren's proposed change that would eliminate duplicate library references in Makefile link recipes.

Junio identifies a potential issue with the patch's approach - the current explicit filtering of `.a` files ensures proper linker ordering (object files before libraries), while relying solely on `$(LIBS)` makes this ordering implicit and potentially fragile. He notes this concern applies to all three link rules modified in the original patch.

The review is substantive, engaging with the technical rationale behind the current implementation rather than just surface-level concerns. Junio suggests the change might introduce brittleness since it depends on an undocumented assumption about `$(LIBS)` contents. This signals the patch may need revision to either maintain the explicit ordering guarantee or better document the expectations around `$(LIBS)`.
