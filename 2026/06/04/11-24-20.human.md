This is a bug report about unexpected behavior in Git's commit-graph generation. The author, Tomasz Konojacki, observes that while the `commitGraph.changedPaths` setting is enabled in their config, `git gc` and fetch operations with `fetch.writeCommitGraph` don't honor this setting when generating commit-graph files - only an explicit `git commit-graph write` command creates the Bloom filters for changed paths.

The email includes clear reproduction steps showing that `git gc` runs without generating the Bloom filters, while a subsequent manual `commit-graph write` does produce them. The behavior is surprising since one would expect these operations to respect the same configuration.

The issue appears to be a gap in how the changed paths feature is integrated with automatic commit-graph generation paths. The report is well-formulated with version information and clear examples, making it easy to verify. This seems like a legitimate oversight rather than intentional behavior, though the email doesn't dig into the code to identify the exact point where the config is being ignored.
