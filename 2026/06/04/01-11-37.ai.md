This is a documentation thread clarification from Junio C Hamano regarding email threading models in Git's contribution workflow.

Junio confirms SZEDER Gábor's technical explanation of Git's threading terminology, emphasizing that:
- Shallow threading means all patches in a series reply to the current cover letter
- Deep threading means each email replies to the previous one in sequence
- Git's best practice is to use shallow threading within a series iteration

Junio adds nuance about how iterations relate across versions:
- The preferred practice is for cover letter N+1 to reply to cover letter N
- Some tools may create cover letters that reply to the initial iteration's cover letter instead
- While this works with current tooling (br and lore), cross-version threading behavior isn't formally standardized
