This is the fourth patch in Johannes Schindelin's series addressing Windows platform compatibility for handling objects larger than 4GB. The patch focuses on widening the `unpack_entry()` function's size parameter from `unsigned long` to `size_t` to properly handle large objects on Windows where `unsigned long` is only 32-bit.

The changes are systematic and careful:
- Updates the core `unpack_entry()` function and related helpers to use `size_t`
- Maintains compatibility with existing callers through temporary conversions where needed (notably in `fast-import` and `packed_object_info_with_index_pos()`)
- Touches delta base cache handling and compressed entry unpacking
- Includes a temporary bridge for `oi->sizep` which will be removed in a later patch

The patch demonstrates the author's deep Windows platform knowledge and attention to maintaining compatibility while making architectural improvements. It's part of a well-structured series that's clearly building toward comprehensive large object support on Windows. The changes are mechanical but wide-ranging, affecting packfile handling at multiple levels.
