This is the fourth patch in a platform compatibility series addressing Windows-specific limitations with large objects (>4GB) on LLP64 systems. The patch extends the test coverage to verify that `git hash-object --stdin` correctly handles large inputs when `size_t` is 64-bit but `long` is 32-bit (the LLP64 model used by Windows).

The test reuses the 5GB test file from previous patches (generating it if needed) and confirms the hash computation matches expectations when reading via stdin. Like earlier tests, it's marked EXPENSIVE due to the large file requirement and skipped on incompatible platforms. Johannes Schindelin's sign-off indicates this has been validated in Git for Windows.

This continues the mechanical but important work of ensuring Git's object handling works correctly on LLP64 platforms, building on the type conversion groundwork laid in earlier patches. The test follows the established pattern of the series while focusing specifically on the stdin code path.
