This is a bug report about Git's trailer parsing behavior, specifically how URLs in commit messages get incorrectly normalized when using `--only-trailers` or `%(trailers:only)`.

Kristoffer Haugsbakk reports that standalone URLs in commit messages (like `https://example.com`) are being incorrectly parsed as trailers with the key `https` and value `//example.com`. This happens even when the URLs are clearly not intended as trailers, such as when they appear in commit message bodies or as references.

The report provides several concrete examples where this causes problems:
1. URLs in non-trailer sections getting mangled (NTL)
2. Line-wrapped URLs accidentally creating `https` trailers (LW)
3. Normalization during patch application introducing malformed trailers (NL)

Analysis of Linux kernel commits shows 245 instances where `https: //` appears as a trailer, suggesting this is a real-world problem affecting projects that use Git's trailer functionality. The report argues this violates Git's design goal of avoiding false positives in trailer detection.

The author suggests special-casing URLs to prevent this unwanted normalization, though acknowledges the behavior is technically working as documented. The issue primarily affects users who process commit messages with trailer normalization, particularly in collaborative workflows where messages might be reformatted.

This appears to be a legitimate usability issue that could be addressed with targeted changes to Git's trailer parsing logic, though any solution would need to carefully consider backward compatibility.
