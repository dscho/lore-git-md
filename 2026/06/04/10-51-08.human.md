This is patch 3/7 in Johannes Schindelin's series to improve Git's handling of large (>4GB) objects on Windows. The patch focuses on the pack-objects subsystem, specifically updating the `check_pack_inflate()` function to use `size_t` instead of `unsigned long` for object sizes.

The change addresses a Windows-specific issue where the current implementation would die() when encountering large objects due to type mismatches. The patch removes a type-casting shim and lets the function fail gracefully when dealing with oversized objects, falling back to a safer code path that decompresses and recompresses the content.

This is a logical continuation of the series' goal to make Git's object handling work correctly with large files on Windows.
