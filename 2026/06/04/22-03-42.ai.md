This is a build system patch that redefines the $(LIBS) variable in the Makefile to eliminate duplicate library references in link recipes. The patch comes from Harald Nordgren as a follow-up to Junio Hamano's review of v1, which identified that simply removing duplicates would break linker symbol resolution.

The key change restructures $(LIBS) to:
1. Explicitly list prerequisite archive files first (from $^)
2. Follow with other libraries while filtering out those already listed
3. Maintain the critical left-to-right linker ordering where object files must precede archives

This addresses macOS linker warnings about duplicate libraries while preserving correct build behavior. The patch modifies three link recipes (test helpers, fuzz programs, unit tests) to rely on the new $(LIBS) definition rather than explicitly listing archives twice. The solution demonstrates careful attention to both the cosmetic warning issue and the underlying technical constraints of linker behavior.

The v2 iteration shows substantial improvement over v1 by tackling the root cause through $(LIBS) restructuring rather than just removing duplicates at individual call sites. This makes the solution more maintainable and less likely to regress. The commit message clearly explains the technical rationale and expected impact.
