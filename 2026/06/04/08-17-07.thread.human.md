Rasmus Villemoes provided feedback on the experimental `git history split` command, suggesting two workflow improvements: an iterative splitting mode (similar to `git add -p`) and an "atomize" feature to automatically split commits by hunk with descriptive prefixes. These stem from real-world use cases where such features would help reorganize changes more efficiently.

Patrick Steinhardt responded positively, agreeing these would be valuable additions. He proposed implementing them as `--iter` and `--explode` options, noting they align with the command's design direction and planned future features like `git history move`. Patrick also revealed he's exploring a TUI interface for more visual commit manipulation, though this is still early-stage. While bash completion support isn't yet implemented, he welcomes contributions for it. The exchange suggests these user-driven improvements are likely to be incorporated into the command's ongoing development.
