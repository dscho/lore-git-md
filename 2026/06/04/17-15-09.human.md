This is the third patch in a platform compatibility series addressing Windows' LLP64 limitations with large (>4GB) objects. The change focuses on the SHA-1 hashing path, converting function signatures from `unsigned long` to `size_t` to properly handle large object sizes on 32-bit systems.

The patch updates the SHA1DC implementation (Git's collision-detecting SHA-1 code) to accept `size_t` lengths, removing an implicit downcast that previously broke >4GB object handling. The commit message carefully explains the call chain through macros and wrapper functions, noting this change finally fixes the test case for 5GB file hashing that was added in earlier patches.

The modifications are mechanical but well-justified, touching core hashing infrastructure in `object-file.c` and the SHA1DC implementation.
