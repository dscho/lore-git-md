Patrick Steinhardt continues his multi-year effort to abstract Git's object storage with a 17-part series converting packed object storage to use the new `struct odb_source` interface. This represents the final major restructuring in the ODB abstraction work, which will enable pluggable storage backends.

The v2 series has incorporated all feedback from Karthik Nayak's architectural review of v1. The first three patches performed mechanical groundwork: renaming `struct packfile_store` to `struct odb_source_packed`, splitting packfile list management into separate files, and moving the packed source implementation to the odb/ directory. These changes affect 28 files with over 1,000 lines modified while preserving performance characteristics.

Patch 4/17, which just landed, makes the relationship between packed storage and its parent files source more explicit by replacing a generic pointer with a specific `struct odb_source_files *` type. This 11-line mechanical change improves code clarity during the transition period while maintaining existing behavior. The series remains on track to complete the ODB interface restructuring, with some path handling and chdir notification work planned for future follow-ups. Karthik Nayak has confirmed the architectural approach is sound, with only minor formatting nits needing attention in earlier rounds.
