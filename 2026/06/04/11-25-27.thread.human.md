Patrick Steinhardt’s ODB abstraction series continues to make progress on its goal of fully decoupling Git’s object database backends. The latest patch (9/17) wires up the `read_object_info()` callback for the packed object storage backend, moving its implementation into the new `odb/source-packed.c` unit and exposing the `find_pack_entry()` helper as a public symbol—for now. This is a mechanical step in aligning the packed source’s interface with the loose source’s precedent, though the symbol exposure is acknowledged as temporary until all remaining callers in `packfile.c` can be migrated.

The series as a whole has now completed all ODB abstraction changes in its v3 iteration, with patches 1–8/17 establishing the foundation and patches 11, 16, and 17 rounding out the interface alignment. Justin Tobler has reviewed the mechanical aspects of these changes, confirming consistency with the loose source’s patterns, but no deeper technical review has yet engaged with the callback logic’s correctness, edge cases (like `do_not_close` packs), or the broader implications for the MIDX and refdb subsystems. The type system is now fully consistent across sources, with both loose and packed backends using an embedded `struct odb_source` base and identical constructor signatures.

The series remains blocked, however, by critical refdb lifecycle management flaws—memory leaks, duplicate refdb creation, and initialization ordering issues—that Patrick discovered during implementation. These require an 11-patch fix series, which in turn depends on the "ps/setup-centralize-odb-creation" series being merged first. Until those issues are resolved, the ODB work cannot progress further. Patrick has also noted that this is the final large-scale restructuring he plans for the ODB; future changes should be incremental. Open questions include the permanence of exposed symbols like `find_pack_entry()`, the unresolved chdir notification redesign, and the timeline for loose source refactoring.
