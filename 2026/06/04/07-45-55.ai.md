This is a test infrastructure patch in a series introducing a new lint tool to convert bare 'grep' assertions to 'test_grep' in Git's test suite. The patch fixes a line counting issue in the shell parser that was extracted from chainlint.pl for reuse by the new lint tool.

The specific issue addressed is that the parser was double-counting newlines when processing multi-line `$()` command substitutions inside double-quoted strings. The fix modifies the scanner tracks newlines incrementally as they're encountered rather than in a post-processing step, ensuring each newline is counted exactly once.

Key technical details:
- Adds a new test script `check-shell-parser.pl` to verify line number reporting
- Modifies `scan_dqstring` in `t/lib-shell-parser.pl` to count newlines inline
- Handles three cases correctly: literal newlines, line splices (`\<newline>`), and newlines from `$()` substitutions
- The fix is important for tools like the upcoming `lint-style.pl` that need accurate line numbers to locate and fix specific lines

The patch demonstrates careful attention to edge cases in shell parsing logic and maintains compatibility with existing chainlint functionality while fixing the issue for new consumers of the shared parser. The new test cases verify the fix handles multiple multi-line substitutions without error accumulation.

This is patch 3/6 in a well-structured effort to improve test suite maintainability by standardizing on `test_grep` assertions and providing tooling to automate the conversion.
