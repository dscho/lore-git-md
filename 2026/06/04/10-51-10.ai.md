This is the fifth patch in Johannes Schindelin's series addressing Windows platform compatibility for handling objects larger than 4GB. The patch focuses on `pack-objects`, converting in-memory object size handling from `unsigned long` to `size_t` to properly support large objects on Windows where these types differ in size.

Key changes:
- Updates all size-related functions in `pack-objects` (`oe_size`, `oe_delta_size`, etc.) to use `size_t`
- Removes now-unnecessary `cast_size_t_to_ulong()` calls that were capping sizes at 4GB
- Maintains compatibility with existing `object_info::sizep` which still uses `unsigned long` (to be addressed in a later patch)
- Touches core packfile handling code but avoids changing on-disk formats

The patch continues the series' careful approach to type conversions while maintaining functionality. It specifically fixes test failures in `t5608` where `upload-pack` would fail on >4GB objects. The changes are mechanical but wide-ranging within `pack-objects`, showing the author's deep understanding of both the Windows platform constraints and Git's object handling internals.

This patch builds on the previous work in the series while preparing for the final ODB API conversion. The changes are part of a well-structured effort to systematically address Windows' 32-bit `unsigned long` limitation throughout Git's object handling stack.
