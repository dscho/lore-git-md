[PATCH] git history split: iterative mode and atomization suggestions

Rasmus Villemoes provided user feedback on the experimental `git history split` command, identifying two key workflow improvements: (1) an iterative splitting mode to continue working with remaining portions after each split (avoiding manual SHA-1 lookups), and (2) an `atomize` subcommand to split commits into one-per-hunk with descriptive prefixes. Patrick Steinhardt responded positively, agreeing these would be valuable additions. He suggested implementing them as `--iter`/`--explode` options, noting the iterative mode was discussed during initial implementation but deprioritized. The atomization functionality could use `--explode` to create hunk-based commits, aligning with planned future commands like `git history move` and `squash`. Patrick also revealed early work on a TUI interface for visual commit manipulation and confirmed bash completion is planned but not yet implemented. These enhancements fit the command's experimental phase and design direction, with Patrick welcoming contributions. The thread captures concrete user experience feedback and maintainer response indicating likely implementation of both suggested features, along with related in-progress UI work.
