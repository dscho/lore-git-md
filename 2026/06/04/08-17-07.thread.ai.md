[PATCH] git history split: iterative mode and atomization suggestions

Rasmus Villemoes provided user feedback on the experimental `git history split` command, identifying two key workflow improvements: (1) an iterative splitting mode to continue working with remaining portions after each split (avoiding manual SHA-1 lookups), and (2) an `atomize` subcommand to split commits into one-per-hunk with descriptive prefixes. Patrick Steinhardt responded positively, agreeing these would be valuable additions, suggesting `--iter`/`--explode` as option names and revealing early TUI interface work.

Kristoffer Haugsbakk reinforces the need for iterative mode with a concrete example: splitting a commit with subject "anchor" multiple times, demonstrating the manual SHA-1 lookup (`:/anchor`) and restart steps required in current workflow. This shows the tedium of multi-step splits without iteration support, particularly when maintaining the original commit subject across operations. The example provides empirical evidence supporting Rasmus' original request.

The thread captures user experience feedback from multiple contributors, with Patrick indicating likely implementation of both iterative mode (`--iter`) and hunk-based splitting (`--explode`), along with related in-progress UI work. All discussion remains focused on practical enhancements to the splitting functionality, with clear use cases establishing the value of proposed features. The command remains experimental, with bash completion still planned but unimplemented.
