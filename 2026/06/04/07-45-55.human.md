This is a test infrastructure patch fixing a line-counting issue in Git's shell parser. It's part of a series introducing a new lint tool to improve test assertions.

The patch fixes a subtle bug where the shell parser's line counter would double-count newlines when processing `$()` command substitutions inside double-quoted strings. The fix changes the counting mechanism to track newlines as they're encountered rather than in a post-processing step. This ensures accurate line numbers for tools that use the parser's output to locate issues in test files.

The change is carefully validated with:
1. A new test script (`check-shell-parser.pl`) that verifies line numbers in multi-line command substitutions
2. Updates to the parser's string scanning logic to count newlines incrementally
3. Integration into the test suite's lint checks

While this doesn't affect existing chainlint behavior (which uses byte offsets), it's important for the new lint-style.pl that will use line numbers to report and fix issues. The patch demonstrates good attention to edge cases and maintains backward compatibility needed by existing tools.
