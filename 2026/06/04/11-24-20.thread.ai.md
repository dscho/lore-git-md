Thread identity: Bug report about `git gc` and `git fetch` not respecting `commitGraph.changedPaths` configuration when generating commit-graphs, filed by Tomasz Konojacki.

Core problem: Automatic commit-graph generation during `git gc` and `git fetch` (with `fetch.writeCommitGraph`) fails to create changed-path Bloom filters despite `commitGraph.changedPaths` being enabled, while explicit `git commit-graph write` commands do generate them. This creates inconsistent behavior for a performance optimization feature.

Current status: Issue reported but not yet addressed. The behavior appears unintentional based on reporter's analysis.

Key technical details: 
- Affects commit-graph Bloom filter generation (changedPaths feature)
- Impacts `builtin/gc.c` (gc) and `fetch-pack.c` (fetch) paths
- Configuration handling differs between explicit vs automatic operations
- Bloom filters improve performance for path-specific queries

Open questions:
- Is this behavior actually intentional?
- Should automatic operations respect commitGraph.changedPaths?
- Need to verify if this affects other commit-graph generation paths
