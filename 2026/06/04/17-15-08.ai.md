This is the second patch in a platform compatibility series addressing Windows' LLP64 limitations with large (>4GB) objects. The patch continues the mechanical conversion from `unsigned long` to `size_t` for object header handling in `object-file.c`, specifically targeting the `hash_object_file()` and `write_object_file_prepare()` functions that are part of the `hash-object --literally` code path.

The changes are straightforward type signature updates, with header length parameters also converted to `size_t` for consistency. The patch notes this doesn't yet fix the test case - that requires further changes to lower-level hash functions in subsequent patches. The modifications have been validated through Git for Windows' production use, as indicated by Johannes Schindelin's sign-off.
