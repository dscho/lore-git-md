This is the first patch in Johannes Schindelen's 7-part series addressing Windows platform compatibility for handling objects larger than 4GB. The series converts `unsigned long` to `size_t` throughout Git's object handling code to properly support 64-bit sizes on Windows where `unsigned long` is only 32-bit.

This specific patch focuses on the `ftruncate()` function in MSVC compatibility layer. It replaces the problematic `_chsize` wrapper (which silently truncates to 32-bit) with a new wrapper around `_chsize_s` that properly handles 64-bit sizes while maintaining POSIX return value conventions. The change fixes test failures when dealing with 4GB+ files and maintains compatibility with existing callers that check for `-1` error returns.

Key technical details:
- Introduces `msvc_ftruncate()` wrapper that converts `_chsize_s`'s return convention to POSIX style
- Preserves 64-bit size handling while maintaining API compatibility
- Affects several callers including HTTP, parallel-checkout, and test code
- Builds on existing Windows compatibility infrastructure

The patch is narrowly focused on the MSVC compatibility layer while being part of the larger effort to enable proper large object support on Windows. Given the author's deep Windows expertise and the careful handling of both size and API compatibility, this appears to be a well-considered change.
