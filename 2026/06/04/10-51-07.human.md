This is the second patch in Johannes Schindelin's 7-part series to enable proper handling of objects larger than 4GB on Windows, where `size_t` is 64-bit but `unsigned long` is 32-bit. The series systematically converts object size handling from `unsigned long` to `size_t` across Git's codebase.

This particular patch focuses on the delta subsystem, updating `patch_delta()` and related functions to use `size_t` for all size parameters. The changes include:

1. Converting the `patch_delta()` function signature and its internal size variables to `size_t`
2. Updating callers in `apply.c`, `index-pack.c`, `unpack-objects.c`, and `packfile.c` to match
3. Switching to the `get_delta_hdr_size_sz()` helper introduced in a previous commit
4. Adjusting the test helper to handle the type change

The patch is mechanical but important - it ensures delta operations can properly handle large sizes on platforms where `unsigned long` is too small. The changes are straightforward and build on preparatory work (the `_sz` helper function) to maintain compatibility.

As with the rest of the series, this demonstrates careful attention to platform-specific details while maintaining cross-platform compatibility. The wide scope (7 files touched) reflects how deeply the delta subsystem is integrated into Git's object handling.
