This is a follow-up in the thread about `git gc` not respecting the `commitGraph.changedPaths` configuration. Theodore Tso responds to Patrick Steinhardt's suggestion that users should migrate from `git gc` to `git maintenance` by proposing a convenience feature: a config option that would make `git gc` automatically redirect to `git maintenance run`. 

Tso acknowledges the technical superiority of the maintenance command but argues for preserving the ergonomic benefits of the shorter `git gc` invocation, especially for manual use cases like pre-travel repository maintenance. He also suggests expanding the maintenance system's power management awareness, noting that Git already integrates with systemd and launchctl on Linux and macOS respectively.

The email doesn't directly address the original Bloom filter issue but explores the migration path from `git gc` to `git maintenance` that Patrick recommended. It represents a pragmatic user perspective on deprecating old commands while maintaining workflow convenience. The suggestion about power-aware maintenance hints at potential future directions for the maintenance subsystem.
