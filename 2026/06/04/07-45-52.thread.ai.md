Thread identity: Completed 6-patch series (v4) introducing `greplint.pl`, a test-suite linter converting bare `grep` assertions to `test_grep`. Originated as a test infrastructure improvement but evolved to address systemic risks in automated conversion masking pre-existing test bugs. Now **technically complete and approved for merging** by the maintainer, with only minor documentation refinements, bugfixes, and a latent lexer fix since v3.

Core problem or goal: Standardize test assertions by replacing bare `grep` with `test_grep` to improve debuggability (prints file contents on failure) while ensuring the conversion tool does not preserve or introduce bugs. The series demonstrated value through 10+ bugfixes but revealed critical flaws where the linter's `# lint-ok:` exemptions preserved incorrect test logic (e.g., grepping files that should not exist). All such cases have now been audited and addressed. The series also documents the previously undocumented `test_grep` helper in `t/README`, clarifying its purpose, usage guidelines, and edge cases where bare `grep` remains appropriate. Documentation now emphasizes explicit guards (e.g., `test_have_prereq REFFILES` or `test -f <path>`) for conditionally present files, replacing the prior reliance on `# lint-ok` annotations for missing-file cases.

- Detection logic: The linter tracks command position and pipeline state to distinguish assertion `grep` (at command position, after `&&`, `;`, or `then`) from filter `grep` (e.g., `grep | wc -l` or `x=$(grep ...)`). It skips `grep` in pipelines, redirects, command substitutions, heredocs, or quoted strings. For double-quoted test bodies with backslash-continuation lines, it adjusts reported line numbers to match the source file. The linter flags two anti-patterns: bare `grep` at command position and `! test_grep` (where `test_grep !` is preferred).
- Suppression mechanism: `# lint-ok` comments now **strictly document greps used as data filters** (e.g., `grep | wc -l`), not missing-file cases. The two remaining annotations (in `t5326` and `t5702`) are for this purpose.
- Edge-case handling: Bare `grep` retained only for platform-dependent paths (e.g., NTFS 8.3 short names) or cases where the file may not exist, now guarded by explicit prerequisites (e.g., `test_have_prereq REFFILES` or `test -f <path>`). The last missing-file-tolerant `! grep` (in `t7450-bad-git-dotfiles.sh`) was converted to a guarded `test_grep` using `test -f`.

The fix ensures each newline is counted exactly once, whether literal, spliced (backslash-newline), or inside `$()`. This bug was latent (no existing consumer used token line numbers) and does not affect `chainlint.pl` (which uses byte offsets). The fix is purely internal to the lexer and does not alter parser output or behavior for existing consumers.
