This is a follow-up in the thread about `git gc` not respecting the `commitGraph.changedPaths` configuration. Theodore Tso responds to Patrick Steinhardt's recommendation to switch from `git gc` to `git maintenance`, suggesting a convenience feature that would make `git gc` act as an alias for `git maintenance run` to ease the transition for users accustomed to the shorter command.

Tso also raises the practical consideration of maintenance tasks needing to respect power/battery status on laptops, noting that since `git-maintenance` already integrates with systemd and launchctl on Linux and macOS, similar power-aware behavior could be added. This reflects real-world usage patterns where users might manually trigger maintenance before going offline.

The email doesn't directly address the original Bloom filter issue but extends the discussion about the transition path from `git gc` to `git maintenance`. It suggests the project may want to consider both user experience (command aliasing) and system integration (power management) as part of the maintenance command's maturation. The tone is constructive, framing these as natural evolution points rather than criticisms of the current design.
