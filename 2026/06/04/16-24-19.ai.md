This is a platform compatibility patch from Johannes Schindelin, part of a series improving Windows process termination behavior. The patch introduces a gentler approach to killing child processes on Windows by injecting threads to call ExitProcess() rather than using TerminateProcess(), allowing for proper cleanup via atexit handlers.

The key technical changes:
- Adds new compat/win32/exit-process.h with two main functions:
  - `exit_process()`: Attempts graceful termination via thread injection
  - `terminate_process_tree()`: Fallback brute-force termination
- Modifies mingw.c to use these new methods when SIGTERM is received
- Handles architecture mismatches between processes
- Includes thorough documentation of the approach and limitations

The solution has been battle-tested in Git for Windows for nearly a decade. While it can't perfectly emulate Unix signal behavior, it's a significant improvement over the current TerminateProcess() approach that prevents any cleanup. The patch maintains backwards compatibility and carefully handles edge cases with a fallback to the old behavior when needed.

This appears to be a well-considered solution to a long-standing Windows-specific pain point, with production-proven code and clear technical documentation. The changes are appropriately scoped to Windows-specific code paths.
