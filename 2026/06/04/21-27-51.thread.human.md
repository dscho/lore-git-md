This thread fixes a bug in Git’s trailer parsing where URLs in commit messages (like `https://example.com`) were mistakenly treated as trailers, corrupting output from `--only-trailers` and `%(trailers:only)`. The issue affected 245 real commits in the Linux kernel alone. The solution, developed by Kristoffer Haugsbakk with review from Jeff King and Junio Hamano, modifies `trailer.c` to skip lines containing `://` during trailer detection. This simple but robust heuristic avoids false positives while preserving legitimate trailers.

The patch has been through two iterations: the first implemented the core fix, and the second adopted Peff’s readability improvement (replacing manual pointer checks with `starts_with()`). Junio’s recent query about remaining issues confirms the patch is now ready for integration, with no open technical objections. The only edge case—a theoretical false positive like `1://`—was discussed and deemed acceptable. Test coverage and documentation updates are included.

This is a straightforward, well-reviewed fix that addresses a real-world problem with minimal risk. It should land in `master` shortly.
