This thread addresses a bug where Git incorrectly interprets URLs in commit messages as trailers, affecting both `--only-trailers` output and `%(trailers:only)` formatting. Kristoffer Haugsbakk originally reported three problematic cases where URLs were being mangled or creating false trailers, with analysis showing this affected hundreds of real-world commits in the Linux kernel history.

Jeff King (Peff) provided the key technical insight, identifying that the issue stems from Git's loose trailer matching across all operations. He proposed modifying the trailer parsing logic to exclude any line containing `://` from being considered a trailer, which would handle all URL schemes uniformly while preserving legitimate trailer behavior. Kristoffer agreed this was the right approach, better than his earlier scheme-specific suggestion.

In the latest update, Kristoffer confirms he'll take over implementation of the solution, using Peff's draft patch as a starting point. He'll add comprehensive test cases covering the URL edge cases and update the relevant documentation. The technical direction is settled, with the work now moving to implementation. This represents a smooth handoff from problem analysis to solution, with both contributors aligned on the approach. We can expect Kristoffer's patch submission with tests and docs to follow.
