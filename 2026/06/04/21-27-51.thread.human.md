This thread is about fixing a bug in Git’s trailer parsing where URLs in commit messages are incorrectly treated as trailers, causing mangled output in `--only-trailers` and `%(trailers:only)` formatting. Kristoffer Haugsbakk initially reported the issue, and Jeff King (Peff) identified the root cause: Git’s loose trailer matching, which doesn’t account for URLs. The agreed-upon fix modifies `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing, a solution Junio C Hamano praised as robust.

The patch is effectively ready for integration, with only a minor readability tweak pending—replacing manual pointer arithmetic with `starts_with(c, "://")` as suggested by Peff. The implementation includes comprehensive tests for all reported bug scenarios and updates documentation. No technical objections remain, and the solution is a strict improvement over the status quo.

In this latest exchange, Kristoffer and Peff are informally exploring a potential future enhancement: treating bracketed text (e.g., `[peff: note]`) as non-trailer content, which would align with Linux kernel commit message conventions. While this isn’t part of the current patch, it reflects ongoing discussion about making trailer parsing more resilient to common edge cases. The immediate focus remains on landing the `://` exclusion fix.
