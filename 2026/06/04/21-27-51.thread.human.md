This thread fixes a bug in Git’s trailer parsing where URLs in commit messages were incorrectly treated as trailers, causing mangled output in `--only-trailers` and `%(trailers:only)` formatting. Kristoffer Haugsbakk initially reported three real-world cases—non-trailer URLs getting corrupted, line-wrapped URLs creating false trailers, and patch processing introducing bad trailers—with analysis showing 245 instances in the Linux kernel’s history.

Jeff King (Peff) identified the root cause as Git’s overly permissive trailer matching and proposed a targeted fix: modifying `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing. Junio C Hamano reviewed the approach, calling the `://` heuristic "much more robust" than a scheme whitelist, and confirmed the pointer arithmetic was safe, though he briefly questioned whether the token before `://` should be restricted further. Kristoffer implemented the fix with comprehensive tests and documentation updates, addressing all three bug scenarios.

The latest exchange clarifies two minor points: Kristoffer acknowledges the `://` heuristic could produce rare false positives (e.g., `1://`) but argues it’s a strict improvement over the current behavior, and he confirms the pointer arithmetic is safe due to C’s string handling. A small documentation tweak is needed to note that trailer keys can include hyphens. The patch is now effectively ready for integration, with no remaining technical objections. Files touched include `trailer.c`, `t/t7513-interpret-trailers.sh`, and `Documentation/git-interpret-trailers.txt`.
