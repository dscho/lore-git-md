This thread fixes a bug where Git incorrectly treats URLs in commit messages as trailers, mangling them in both `--only-trailers` output and `%(trailers:only)` formatting. Kristoffer Haugsbakk reported three real-world cases—non-trailer URLs getting corrupted, line-wrapped URLs creating false trailers, and patch processing introducing bad trailers—with 245 confirmed instances in Linux kernel history.

Jeff King (Peff) identified the root cause: Git’s overly permissive trailer matching. The agreed solution modifies `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing, a heuristic Junio C Hamano called "much more robust" than a scheme whitelist. Kristoffer implemented the fix with comprehensive tests covering all three bug scenarios, and the patch has received maintainer approval. The only remaining discussion is a minor readability tweak—replacing manual pointer arithmetic with `starts_with(c, "://")`—which Junio endorsed. The patch is effectively ready for integration, with no open technical objections.
