This thread addresses a bug where Git incorrectly interprets URLs in commit messages as trailers, affecting both `--only-trailers` output and `%(trailers:only)` formatting. Kristoffer Haugsbakk initially reported three concrete cases of this behavior, with analysis showing hundreds of real-world instances in the Linux kernel history. Jeff King (Peff) provided the key technical insight that the root cause is Git's overly permissive trailer matching across all operations, not just formatting. He proposed modifying `find_separator()` in trailer.c to exclude lines containing `://` from trailer parsing - a solution that would uniformly handle all URL schemes without special cases.

Kristoffer has now responded, agreeing with Peff's analysis and endorsing the `://` matching approach as superior to his earlier suggestion of special-casing only HTTPS URLs. He notes this solution is robust against false negatives, as it would only block trailers that both look exactly like URLs and have values starting with `//` - an extremely unlikely scenario. The discussion has reached consensus on the technical solution, with the next step being implementation and testing of the proposed change to `find_separator()`. The fix appears well-scoped to address the reported issues while maintaining Git's trailer functionality for legitimate use cases.
