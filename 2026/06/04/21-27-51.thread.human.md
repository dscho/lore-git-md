This thread fixed a bug in Git’s trailer parsing where URLs in commit messages were incorrectly treated as trailers, causing mangled output in `--only-trailers` and `%(trailers:only)` formatting. Kristoffer Haugsbakk reported three real-world cases—non-trailer URLs, line-wrapped URLs, and patch-processing artifacts—with analysis showing 245 affected commits in the Linux kernel history.

Jeff King (Peff) identified the root cause as Git’s overly permissive trailer matching and proposed a simple fix: exclude lines containing `://` from trailer parsing. Junio C Hamano reviewed the approach, calling the `://` heuristic "much more robust" than a scheme whitelist, and the patch was implemented with comprehensive test coverage for all three bug scenarios. After two iterations (v1 used manual pointer arithmetic, v2 adopted Peff’s more readable `starts_with()`), the fix was merged to `master` on 2024-07-12. The thread briefly explored a broader enhancement (ignoring bracketed text like `[...]` to match Linux kernel conventions) but took no action on it.

The latest email is just a trivial correction to the interdiff notes in the v3 submission—changing "Changes in v2" to "Changes in v3"—and doesn’t affect the merged code. The thread is now closed.
