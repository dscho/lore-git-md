This thread resolved a bug in Git’s trailer parsing where URLs in commit messages were incorrectly treated as trailers, affecting both `--only-trailers` and `%(trailers:only)` formatting. Kristoffer Haugsbakk initially reported three problematic cases—non-trailer URLs getting mangled, line-wrapped URLs creating false trailers, and patch processing introducing bad trailers—with real-world examples found in 245 Linux kernel commits.

Jeff King (Peff) identified the root cause as Git’s overly permissive trailer matching and proposed a fix in `trailer.c` to exclude lines containing `://` from trailer parsing. Junio C Hamano reviewed the approach, praising the `://` heuristic as robust and confirming its safety. Kristoffer implemented the fix in two versions: the first used manual pointer arithmetic, while the second adopted Peff’s more readable `starts_with(c, "://")` suggestion, which Junio also approved. The patch includes comprehensive test coverage and documentation updates.

The fix is now merged to `master` after Peff’s final sign-off in this email, confirming no technical objections remain. The solution is minimal, well-tested, and addresses a documented issue without disrupting legitimate trailer parsing. A broader enhancement (special-casing bracketed text like `[...]`) was discussed but remains exploratory.
