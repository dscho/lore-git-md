This thread fixes a bug in Git’s trailer parsing where URLs in commit messages (like `https://example.com`) were incorrectly treated as trailers, corrupting their formatting. Kristoffer Haugsbakk reported the issue after finding 245 real-world cases in the Linux kernel history, and Jeff King (Peff) designed the fix: exclude lines containing `://` from trailer parsing. The patch has been reviewed and approved by both Peff and Junio C Hamano, with only a minor readability tweak (using `starts_with()`) still pending.

The implementation is complete, with tests covering all three bug scenarios and updates to the documentation. Junio’s latest email confirms the patch’s base topic has now graduated to `master`, and he’s checking for any last-minute issues before merging. There are no open technical objections, and the fix is ready for integration. A separate discussion about handling bracketed text (like `[tag: message]`) in commit messages is ongoing but doesn’t block this patch.
