This thread is about fixing a bug in Git's trailer parsing where URLs in commit messages are mistakenly treated as trailers, causing issues with `--only-trailers` and `%(trailers:only)` formatting. Kristoffer Haugsbakk initially reported the problem with three specific cases, and after analysis by Jeff King (Peff), they agreed on a solution: modifying `find_separator()` in `trailer.c` to exclude lines containing `://` from trailer parsing.

Kristoffer has now submitted a complete patch implementing this fix. The patch includes the core logic change, comprehensive test coverage for all three problematic scenarios, and updated documentation. It follows Peff's proposed approach precisely and is ready for review. Given the prior discussion and alignment between the two, this patch is likely to be uncontroversial and should resolve the 245 documented instances of this issue in the Linux kernel history. The implementation is minimal, targeting only the trailer parsing logic without affecting other Git behaviors.
