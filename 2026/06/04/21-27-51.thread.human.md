This thread addresses a bug where Git's trailer parsing incorrectly interprets URLs in commit messages as trailers, affecting both `--only-trailers` output and `%(trailers:only)` formatting. Kristoffer Haugsbakk originally reported three concrete cases where this occurs, with analysis showing hundreds of real-world instances in the Linux kernel history.

Jeff King (Peff) provided the key technical insight that the root issue lies in Git's loose trailer matching logic rather than just the formatting output. He proposed modifying the trailer parsing code to exclude any line containing `://` from being considered a trailer, which would uniformly handle all URL schemes while being extremely unlikely to accidentally block legitimate trailers. Kristoffer agreed this approach is superior to his earlier suggestion of special-casing specific URL schemes.

The discussion has now reached clear consensus, with Peff jokingly noting his initial motivation was partly to defend his `--only-trailers` implementation. Both agree the solution is technically sound and maintainable, with Peff offering his draft patch as a starting point but encouraging Kristoffer to take over the implementation work, which will need proper tests and documentation updates. The change is now ready to be implemented in trailer.c, preserving Git's trailer functionality while fixing this edge case.
