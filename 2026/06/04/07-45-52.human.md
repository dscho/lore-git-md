This is a test infrastructure improvement series that introduces a new lint tool to convert bare 'grep' assertions to 'test_grep' in the test suite. The 'test_grep' wrapper provides better debugging output by showing file contents when assertions fail.

The series starts by documenting the existing 'test_grep' helper in t/README (patch 1), then extracts chainlint's shell parser into a shared module (patch 2) with a bugfix for line counting (patch 3). Patch 4 introduces the new lint-style.pl tool with an initial rule for handling negated greps. Patch 5 fixes three pre-existing bugs where grep assertions were missing file arguments. The bulk conversion of ~2800 grep assertions across ~340 files happens in patch 6.

The lint tool intelligently distinguishes grep assertions (which should be converted) from grep used as a filter (which should remain unchanged). It also flags likely bugs like grep assertions without file arguments. The implementation reuses chainlint's shell parser rather than implementing new parsing logic.

The series appears well-structured and carefully implemented, with clear documentation of known edge cases and limitations. The author has identified several special cases that need to remain as bare grep (like checking .git/packed-refs which may not exist in reftable backends) and marked them with '# lint-ok' comments.

This looks like a solid infrastructure improvement that will make test failures easier to debug while maintaining the exact same assertion behavior. The careful approach to parsing and the clear documentation of the tool's capabilities suggest this is production-ready.
