Documentation patch series follow-up: Toon Claes raises a practical consideration about CI testing in the context of the b4` tool recommendation. 

This is a brief but substantive review comment on Patrick Steinhardt's v2 patch that adds b4 documentation to the MyFirstContribution tutorial. Toon notes that while GitGitGadget includes CI testing as part of its workflow, neither b4 nor raw git-send-email provide this automation. He asks whether the documentation should explicitly call out that users are responsible for running the test suite themselves when using b4, or if this falls outside the scope of the current series.

The question touches on an important practical difference between the contribution methods being documented. While not a blocking issue, it's the kind of real-world consideration that could help new contributors understand the tradeoffs between tools. The thread context shows this is part of a well-discussed series that has already addressed threading models and version compatibility, now nearing completion with maintainer input.
