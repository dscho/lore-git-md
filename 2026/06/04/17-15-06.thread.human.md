This thread addresses a long-standing Windows-specific limitation with large objects (>4GB) on LLP64 systems, where Git previously failed due to 32-bit `unsigned long` usage for object header lengths. The series, originally developed by Philip Oakley and maintained in Git for Windows, has been production-validated for over four years and carries Johannes Schindelin's sign-off on all patches. The core fix—converting object header lengths from `unsigned long` to `size_t`—has already been merged in Git for Windows and is now awaiting final integration into upstream Git.

The discussion has now shifted to minor refinements, with the latest exchange focusing on test coverage. Patrick Steinhardt suggested removing the `!LONG_IS_64BIT` prerequisite from the 5GB test case, arguing that the fix should now work on all platforms that support large files. Johannes Schindelin agreed, calling it a "good point," and the change would make the test more broadly applicable while keeping its `EXPENSIVE` marker. This is a low-impact but meaningful improvement to test robustness. The only remaining work before merging is a rebase to resolve integration conflicts (requested by Junio Hamano) and this test adjustment.

The architectural discussion about whether to use `size_t` or introduce an `objsize_t` typedef has been resolved in favor of `size_t`, with Johannes firmly rejecting the latter as unnecessary for memory-addressable sizes. The series is effectively complete, with all technical concerns addressed and no outstanding objections. The changes are mechanical and well-contained, touching `object-file.c`, `sha1dc_git.c`, and `hash.h`, and the test infrastructure now covers all major code paths, including direct file hashing, `--stdin` input, and clean filter processing.
