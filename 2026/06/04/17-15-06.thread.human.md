This thread addresses Windows-specific limitations with handling large objects (>4GB) on LLP64 systems where `unsigned long` is 32-bit. The series, originally contributed by Philip Oakley and maintained in Git for Windows, converts object header length handling from `unsigned long` to `size_t` across key code paths. Johannes Schindelin has signed off on all patches, which have been proven stable through years of production use in Git for Windows.

The progression has systematically validated different code paths: direct file hashing, stdin processing (both standard and `--literally` modes), and now - with this final patch - the filter subsystem. Each test case reuses a generated 5GB test file and verifies correct behavior on relevant platforms. The latest addition specifically checks that clean filters properly handle large inputs when using `git hash-object`, completing the series' coverage of major object-handling scenarios.

While the core changes were mechanical conversions from `unsigned long` to `size_t` in `object-file.c` and SHA1DC, the test coverage has been thorough, addressing edge cases across different input methods. With this final test case confirming filter compatibility, the series appears ready for broader adoption beyond Git for Windows. The changes remain minimal and focused, with no production code modifications in this last patch - just an additional platform-specific test to lock in the behavior.
