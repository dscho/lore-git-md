This thread addresses a long-standing Windows compatibility issue with large files (>4GB) where Git's use of 32-bit `unsigned long` for object sizes causes problems on LLP64 systems. The patch set, originally developed by Philip Oakley and maintained in Git for Windows for over four years, systematically converts these size variables to `size_t` across key subsystems including object-file handling and hash computation.

The series has now been proposed for upstream inclusion by Johannes Schindelin (Dscho), who has signed off on all patches after extensive production validation in Git for Windows. The final patch adds test coverage for the clean/smudge filter interface, completing verification of all major code paths. The changes are focused and mechanical, primarily updating type signatures in `object-file.c` and the SHA-1 implementation while maintaining the existing abstractions.

With five test cases passing for 5GB files across various code paths (direct hashing, stdin input, and filtered processing) and years of real-world validation, this appears ready for merging. The work builds on Oakley's original LLP64 compatibility efforts and complements Git's broader large-file handling improvements. While other subsystems may eventually need similar conversions, this series addresses the core object handling paths that were blocking Windows users.
