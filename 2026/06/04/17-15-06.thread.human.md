This thread completes a long-running effort to fix Windows-specific LLP64 limitations that prevented Git from correctly handling objects larger than 4GB. The series, originally developed by Philip Oakley and maintained in Git for Windows for over four years, has now been merged by Junio C Hamano after its second iteration resolved all technical and integration concerns.

The core change replaces `unsigned long` with `size_t` for object header lengths across `object-file.c`, ODB source files, and the SHA1DC interface, ensuring 64-bit buffer handling on platforms where `size_t` is appropriately sized. Six new test cases in `t/t1007-hash-object.sh` verify the fix works across all major code paths—direct file hashing, `--stdin` input, and clean filter processing—using 5GB test files. These tests are now unconditional (beyond the `SIZE_T_IS_64BIT` prerequisite) and marked as `EXPENSIVE`, reflecting their universal applicability.

Johannes Schindelin, who signed off on all patches, confirmed the series has been production-validated in Git for Windows, while Patrick Steinhardt’s suggestion to remove the `!LONG_IS_64BIT` prerequisite was accepted to simplify testing. The architectural discussion about type consistency was resolved in favor of `size_t` for memory-addressable sizes, with Johannes clarifying that `off_t` remains appropriate only for streaming scenarios on 32-bit platforms. Junio’s merge notice marks the final step, noting only a minor procedural curiosity about GitGitGadget’s range-diff generation. The fix is now complete, addressing a long-standing platform limitation while maintaining backward compatibility.
