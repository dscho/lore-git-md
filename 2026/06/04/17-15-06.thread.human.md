This thread wrapped up the long-running effort to fix Windows-specific LLP64 limitations that prevented Git from correctly handling objects larger than 4GB. The series, originally developed by Philip Oakley and maintained in Git for Windows, was merged to `next` in its second iteration after converting object header lengths from `unsigned long` to `size_t` across the object-file and hash algorithm code paths. All production changes and test cases are now finalized, with no further updates expected.

The core issue was 32-bit truncation of object sizes on Windows, where `unsigned long` is 32 bits even on 64-bit systems. The fix systematically replaced `unsigned long` with `size_t` in key functions like `hash_object_file()` and `write_object_file_prepare()`, ensuring compatibility with large objects on all platforms where `size_t` is 64-bit. The series also added comprehensive test coverage, including a 5GB file-hashing test that now runs unconditionally on all platforms supporting large files.

Johannes Schindelin and Junio C Hamano were the key participants, with Schindelin confirming the production validation in Git for Windows and Junio merging the series. The thread also included a minor procedural follow-up explaining how GitGitGadget generates range-diff output, but this was purely informational and doesn’t affect the technical outcome. The effort complements other large-file handling improvements and leaves reusable test infrastructure for future platform validation work.
