This thread addresses Windows compatibility issues when handling large objects (>4GB) on LLP64 systems where `unsigned long` is 32-bit. The series, originally from Philip Oakley and maintained in Git for Windows, converts object header length handling from `unsigned long` to `size_t` across key code paths.

The work has progressed through several mechanical but important conversions in `object-file.c` and SHA1DC implementation, with Johannes Schindelin providing consistent review and sign-off. The latest patch adds coverage for basic `git hash-object` operation on large files, complementing existing tests for `--stdin` and `--literally` paths. The new test reuses file generation logic from previous tests and is marked EXPENSIVE to avoid unnecessary runtime on unsuitable platforms.

All changes have been proven in Git for Windows production use, with the test suite now verifying correct handling of 5GB files. While the series remains at version 1 on the main list, its real-world validation gives confidence in the approach. Remaining work may address similar conversions in other subsystems, but the core object handling appears solid.
