This thread is about fixing a long-standing Windows-specific limitation that prevented Git from correctly handling objects larger than 4GB due to 32-bit truncation in the LLP64 model. The series, originally developed by Philip Oakley and maintained in Git for Windows, is now in its second version (`v2`) with all production code changes validated in production.

The core issue was that object sizes were stored in `unsigned long` variables, which are 32-bit on Windows even in 64-bit builds. The solution systematically converts these to `size_t` across the object-file and hash algorithm code paths. The series is now complete with all technical discussions resolved. Junio C Hamano approved the approach, and Johannes Schindelin (Git for Windows maintainer) confirmed the changes work in production. Patrick Steinhardt contributed to the architectural discussion, which concluded that `size_t` is the correct type for memory-addressable sizes.

The thread includes six patches. The first added a test case demonstrating the 5GB file-hashing failure, now running unconditionally on all platforms. The second updated `object-file.c` and ODB source files to use `size_t` for memory buffer lengths. This third patch completes the type conversion for the SHA-1 implementation by updating the SHA1DC interface, removing an implicit downcast that could cause truncation. The test now passes for 5GB files on 64-bit platforms. The remaining patches will finish the call chain to lower-level hash functions.

The series is ready for merging, with no open questions or loose ends. All changes are backward-compatible and maintain support for 32-bit systems. The test infrastructure added here will be useful for future platform validation.
