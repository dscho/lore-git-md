Patrick Steinhardt responds to Rasmus Villemoes' feedback on the experimental `git history split` command. This is part of the ongoing development of the new `git history` feature, which aims to provide more intuitive tools for commit manipulation.

Steinhardt acknowledges both of Rasmus's key suggestions for improving the split workflow: an iterative mode to handle multi-step splits more smoothly, and an "atomize" option to automatically split commits into individual hunks. He indicates these would be reasonable additions, proposing `--iter` and `--explode` as potential flag names for the respective features.

The response also reveals that more functionality is in development, including a `git history move` command and potential future additions like a `git history squash` operation. Steinhardt even mentions experimenting with a TUI interface for commit manipulation, though he notes this is still early-stage work.

On the bash completion question, Steinhardt confirms this would be welcome but simply hasn't been implemented yet. The exchange shows active development of the `git history` feature with thoughtful consideration of real-world use cases, suggesting these experimental commands may mature into core functionality.
