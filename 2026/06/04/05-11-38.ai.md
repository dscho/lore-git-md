This is a response in the ongoing discussion about mirror repositories, specifically addressing the Debian packaging use case. Simon Richter from Debian weighs in with practical concerns about archiving projects that use submodules, where current Git behavior makes it difficult to maintain self-contained archives when submodules reference external URLs.

The email highlights two key pain points:
1. Debian's archive server cannot reliably mirror projects with submodules because the submodule URLs either point externally or use relative paths that break when mirrored
2. The proposed "repository identity" solution (using UUIDs and symlinks) is acknowledged as problematic but presented as the best current idea

Simon notes this isn't just a Debian-internal issue - they anticipate external users will rely on these mirrors once available, similar to how Debian's tarball mirrors are widely used. This reinforces the maintainer's position that any solution should be general rather than submodule-specific, since the mirroring need extends beyond submodules.

The response doesn't propose concrete code changes but provides important real-world context about why the mirror fallback functionality would be valuable. It suggests the discussion should consider how to make repositories reliably mirrorable while maintaining their internal references.
