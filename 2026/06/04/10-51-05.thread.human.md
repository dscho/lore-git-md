Johannes Schindelin (Dscho) is working to improve Git's handling of large objects (>4GB) on Windows, where `size_t` is 64-bit but `unsigned long` remains 32-bit. His 7-patch series systematically converts `unsigned long` to `size_t` for object sizes across multiple subsystems, addressing test failures and crashes when processing large files.

The third patch, just submitted, focuses on pack-objects, updating `check_pack_inflate()` to use `size_t` for object sizes. This removes a problematic type conversion that was causing immediate crashes on Windows when handling large objects. While the underlying zlib limitation (32-bit counters) remains, the change allows graceful fallback to alternative code paths rather than failing outright. The patch builds on previous work that made `write_reuse_object()` track sizes as `size_t`.

The series represents careful, platform-specific work from Dscho, who has deep Windows expertise. Changes are mechanical but wide-ranging, touching 71 files across core functionality including object handling, packfiles, deltas, and the ODB layer. The patches maintain compatibility while addressing Windows-specific limitations, building on both Dscho's previous Windows compatibility work and Patrick Steinhardt's ongoing ODB abstraction efforts.
