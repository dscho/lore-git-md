This thread is about Johannes Schindelin’s (Dscho) patch series enabling Git to handle objects larger than 4GB on Windows, where `size_t` is 64-bit but `unsigned long` is 32-bit. The series, now at version 2, systematically converts object size tracking from `unsigned long` to `size_t` across core subsystems like delta handling, packfiles, and the object database (ODB). It includes eight patches, with the first addressing MSVC compatibility for large file operations and the rest converting size-related functions and data structures.

Key progress includes Junio Hamano’s ack for the delta-handling patch ("Makes sense") and his indication that he plans to queue the series for potential inclusion, pending his final review before the next release candidate. Patrick Steinhardt provided thorough reviews across all patches in v1, raising questions about transitional scaffolding, zlib counter handling, and cleanup opportunities. Most of his feedback has been addressed in v2, including the removal of superfluous `size_t` variables in `cat-file.c`, which he confirmed in this latest email. The series has also been rebased onto `master` to resolve conflicts with Patrick’s recently merged ODB abstraction work.

The patches are mechanical but wide-ranging, touching 72 files and requiring careful review for platform-specific edge cases. While the series is now in good shape for integration, one design question remains unresolved: Steinhardt’s suggestion to track total object size in a local `size_t` variable while resetting zlib’s 32-bit counter each iteration (for better handling of very large objects) was not adopted, with Dscho maintaining the current approach is sufficient given prior workarounds. No other open technical concerns are blocking progress, and the series appears ready for Junio’s final review.
