Here's a human-readable summary of the thread so far:

Johannes Schindelin (Dscho) has proposed upstreaming two Windows-specific patches that have been part of Git for Windows for about ten years. The changes address how Git terminates child processes on Windows, where the current brute-force approach (TerminateProcess()) prevents proper cleanup since Windows lacks Unix-style signals. The solution introduces a more graceful shutdown mechanism by creating remote threads to call ExitProcess(), effectively emulating SIGTERM behavior, along with proper SIGINT handling in the MSYS2 runtime.

The changes are confined to Windows-specific code in compat/mingw.c and a new header file. While the approach has some limitations (it won't work across different CPU architectures), it's a significant improvement over the current behavior and has proven stable through years of real-world use in Git for Windows. The thorough commit message explains the technical challenges of Windows process management and justifies the design choices.
