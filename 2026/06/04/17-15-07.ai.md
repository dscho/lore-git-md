This is a platform compatibility test patch that demonstrates a Windows-specific limitation with large objects (>4GB) on LLP64 systems. It's the first in a series that has been maintained in Git for Windows for 4.5 years.

The patch adds a test case showing how Git currently fails to correctly hash files larger than 4GB on Windows (LLP64) systems where `unsigned long` is 32-bit. The test uses `git hash-object --literally` to avoid writing the object, isolating just the hashing behavior. The test is marked as expensive and conditional on 64-bit `size_t` but 32-bit `long` systems.

The test provides concrete validation for the subsequent patches that will convert object size handling from `unsigned long` to `size_t`. The test case includes expected SHA-1 and SHA-256 hashes for a 5GB file, showing the series considers both hash algorithms. The test is marked as expected to fail initially, which is proper for demonstrating the problem before fixing it.

This appears to be a well-constructed test that cleanly isolates the specific issue the series will address. The test's long tenure in Git for Windows suggests it has proven reliable in practice. The patch follows the common pattern of first demonstrating the problem before fixing it.
