This is a response to user feedback about the experimental `git history split` command. Patrick Steinhardt acknowledges Rasmus Villemoes' suggestions for improving the workflow:

1. **Iterative splitting mode** - Patrick agrees this would be useful and suggests implementing it as an option (like `--iter` or `--explode`). He notes this was discussed during the initial implementation but wasn't prioritized.

2. **Automatic hunk splitting** - The proposed "atomize" functionality could be implemented as `git history split --explode`, which would create one commit per hunk with descriptive prefixes. Patrick mentions this aligns with planned future commands like `git history move` and `git history squash`.

Patrick also reveals he's experimenting with a TUI interface for `git history` to make commit manipulation more visual, though this is still in early development. Regarding bash completion, he confirms it's on the roadmap but hasn't been implemented yet, and would welcome contributions.

The response indicates these are valid enhancements that fit within the command's design direction. Patrick's openness to the suggestions and disclosure of related in-progress work suggests the feedback is likely to influence the feature's evolution.
