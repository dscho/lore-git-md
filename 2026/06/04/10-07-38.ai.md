This is the final patch in Patrick Steinhardt's test infrastructure series, enforcing strict TAP output validation when running tests with `prove`. The patch addresses a long-standing issue where invalid TAP output from tests would be silently accepted by `prove` while generating warnings in Meson.

The change adds a TAP pragma (`pragma +strict`) to make `prove` treat invalid TAP lines as test failures, catching format violations that previously slipped through. This would have detected the fsmonitor test issues fixed earlier in the series. The implementation is minimal - just adding the pragma declaration when `HARNESS_ACTIVE` is set (indicating `prove` is running).

The patch builds on previous TAP validation work (b1dc2e796e, 362f69547f) and completes the series' goal of making test output more reliable. It's a straightforward improvement that closes a gap in the test infrastructure's ability to catch malformed output early. The change is well-motivated by real-world issues that have slipped through in the past, and the implementation is clean with no obvious downsides.
