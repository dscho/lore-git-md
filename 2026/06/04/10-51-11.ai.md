This is the sixth patch in Johannes Schindelin's series to enable proper handling of large (>4GB) objects on Windows systems where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch removes transitional wrapper functions that were introduced earlier in the series to maintain compatibility during the type conversion process.

The key changes in this patch:
- Removes the `cast_size_t_to_ulong()` wrappers that were temporarily used to safely transition from `unsigned long` to `size_t` for object sizes
- Renames the `_sz` variants of functions back to their original names (e.g. `get_delta_hdr_size_sz()` becomes `get_delta_hdr_size()`)
- Updates callers to use the direct `size_t` versions
- Maintains the same functionality while simplifying the code by eliminating the intermediate conversions

The patch affects delta handling and packfile operations, touching delta header parsing and size calculation functions. It builds on the previous patches in the series that systematically converted object size handling throughout the codebase to use `size_t` instead of `unsigned long`.

This is a cleanup patch that removes transitional scaffolding now that the type conversion work is complete. The changes are mechanical but important for maintaining clean, consistent interfaces. The series as a whole demonstrates careful attention to Windows platform specifics while maintaining cross-platform compatibility.
