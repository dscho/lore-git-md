This is patch 3/8 in Patrick Steinhardt's v3 series refactoring repository initialization and object database setup, part of the ongoing ODB abstraction effort.

The patch deduplicates repository format application logic that was previously spread across three call sites. It introduces a new `apply_repository_format()` function that centralizes the work of applying repository extensions and configuration to a repository instance. The function also handles format verification, making the previous verification in `read_and_verify_repository_format()` redundant (now renamed to `read_repository_format_from_commondir()`).

Key changes in this version (v3) include improved documentation of `apply_repository_format()`'s verification role and clearer function naming. The patch maintains the series' goal of separating repository format application from ODB creation while eliminating duplicate initialization paths. All review feedback from Karthik Nayak has been addressed, making this the final form of the technical changes.

The changes are internal plumbing improvements with no user-visible behavior changes, but they significantly improve maintainability by reducing duplication. This work lays important groundwork for future extensions to the object storage layer while making the codebase more robust against regressions.
