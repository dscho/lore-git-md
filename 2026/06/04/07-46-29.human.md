This is patch 5/8 in Patrick Steinhardt's series refactoring repository initialization and object database (ODB) setup, part of the larger ODB abstraction effort. The series has already gone through thorough review from Karthik Nayak and is in its final form.

The patch continues the work of centralizing ODB creation by removing conditional logic from `setup_git_env()` and making ODB initialization more consistent. It introduces temporary duplication of ODB creation calls (which will be resolved in patch 8/8) to ensure the object database is properly initialized in all repository setup paths.

Key changes:
- Eliminates the `skip_initializing_odb` parameter that was making the initialization flow harder to follow
- Adds ODB creation in several places where repository setup occurs
- Maintains all existing functionality while making the initialization sequence more explicit

The patch is a mechanical refactoring that prepares for the architectural change in patch 8/8 where ODB creation will be fully centralized in `apply_repository_format()`. As with the rest of the series, there are no user-visible behavior changes - this is purely internal plumbing work to enable future ODB backend improvements.

The series has completed its technical review cycle and appears ready for merging, with this patch representing one of the transitional steps in the refactoring.
