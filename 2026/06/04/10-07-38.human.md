This is the final patch in Patrick Steinhardt's test infrastructure series, enforcing strict TAP output validation in the test suite. The patch ensures that `prove` will fail when encountering invalid TAP output, rather than silently accepting it as it does by default. This matches the behavior already seen in Meson (which issues warnings) and helps catch malformed test output earlier.

The change is implemented by adding a TAP pragma (`+strict`) when running under `prove`, which treats invalid TAP lines as test failures. While this pragma was only standardized in TAP 14, Patrick notes that `prove` has supported it as an unofficial extension since 2008. The patch includes an example showing how this would have caught the fsmonitor test output issues fixed earlier in the series.

This is a straightforward and well-justified change that completes the series' goal of making test output more reliable. The series as a whole has been through multiple iterations with thorough review, particularly from Jeff King, and appears ready for merging. The changes are focused on test infrastructure quality rather than introducing new features, continuing Patrick's ongoing work to improve Git's testing framework.
