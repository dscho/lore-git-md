This is a platform compatibility patch series addressing Windows-specific limitations with large objects. The series, originally contributed by Philip Oakley 4.5 years ago and maintained in Git for Windows, tackles the issue of handling objects larger than 4GB on LLP64 systems (like Windows) where `unsigned long` is 32-bit.

The patches demonstrate the problem through new test cases and systematically convert relevant code to use `size_t` instead of `unsigned long` for object header lengths and hash algorithm sections. The changes touch core object-file handling code, SHA-1 implementation, and add several test cases to verify the fixes work with >4GB inputs, including through filtered input paths.

The series appears well-tested given its long tenure in Git for Windows, and addresses a real limitation that becomes more pressing as other >4GB object handling work progresses upstream. Johannes Schindelin's cover letter positions this as complementary to other ongoing large-object efforts, suggesting these changes have proven stable in production use. The modifications are focused and mechanical, primarily type signature updates with clear test coverage added.
