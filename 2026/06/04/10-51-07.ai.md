This is the second patch in Johannes Schindelin's 7-part series to enable Git to handle objects larger than 4GB on Windows systems where `size_t` is 64-bit but `unsigned long` is 32-bit. The series systematically converts object size handling from `unsigned long` to `size_t` across multiple subsystems.

This particular patch focuses on the delta subsystem, updating `patch_delta()` and related functions to use `size_t` for object sizes. The changes include:

1. Converting the `patch_delta()` function signature and all its callers to use `size_t` instead of `unsigned long` for size parameters
2. Switching internal delta header size parsing to use the `get_delta_hdr_size_sz()` helper introduced in a previous commit
3. Updating test helper code to maintain consistency

The patch affects several key areas: delta application (used in packfile handling), index-pack, unpack-objects, and the test infrastructure. While the changes are mechanical in nature (type conversions), they touch core functionality that needs to handle potentially large objects correctly.

This continues the series' pattern of careful, systematic conversion while maintaining compatibility with existing on-disk formats and APIs. The patch builds on previous work (referencing commit 17fa077596) and maintains the series' focus on Windows platform compatibility issues around large object handling.
