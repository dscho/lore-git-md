This is the fourth patch in Johannes Schindelin's series enabling Git to handle objects larger than 4GB on Windows, where `size_t` is 64-bit but `unsigned long` remains 32-bit. The patch focuses on widening the `unpack_entry()` function's size parameter from `unsigned long` to `size_t` throughout the packfile subsystem.

Key changes:
- Updates `unpack_entry()` and related functions in packfile.c to use `size_t` for object sizes
- Maintains compatibility with `fast-import` by adding temporary size conversion
- Preserves existing behavior for `packed_object_info_with_index_pos()` until a future patch can update its interface
- Touches core packfile handling including delta base cache and compressed entry unpacking

The patch demonstrates careful attention to transitional compatibility, particularly where subsystems like fast-import still use `unsigned long`. The changes are mechanical but wide-ranging, affecting how Git handles object sizes in memory across the packfile subsystem. This continues the series' systematic approach to eliminating 32-bit size limitations on Windows.
