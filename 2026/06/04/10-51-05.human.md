This is a patch series from Johannes Schindelin addressing Windows-specific issues with large objects (>4GB). The series is part of an ongoing effort to properly handle large objects on platforms where `size_t` is 64-bit but `unsigned long` is 32-bit (like Windows).

The 7-patch series makes widespread changes to use `size_t` instead of `unsigned long` for object sizes throughout the codebase. Key changes include:

1. Using Windows' `_chsize_s` for truncation
2. Converting delta handling to use `size_t`
3. Widening packfile object size parameters
4. Removing now-unnecessary size conversion wrappers
5. Updating the object database APIs to use `size_t`

The changes touch many files (71 modified) but are mostly mechanical type changes. The series conflicts with Patrick Steinhardt's `ps/odb-source-loose` work, and Johannes has provided a rebased version to help resolve these.

This appears to be a well-motivated series addressing real platform limitations, though the wide scope means it will need careful review for any unintended side effects. The changes are particularly relevant for Windows users working with very large repositories.
