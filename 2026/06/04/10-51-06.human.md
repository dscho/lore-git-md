This is the first patch in a 7-patch series addressing Windows platform compatibility for handling large objects (>4GB) where `size_t` is 64-bit but `unsigned long` remains 32-bit. The series comes from Johannes Schindelin, Git's Windows expert.

The patch focuses on fixing `ftruncate()` behavior in MSVC builds. Currently, Windows silently truncates files to 2GB due to using the 32-bit `_chsize()` function. The solution introduces a wrapper around the modern `_chsize_s()` (which supports 64-bit sizes) while maintaining POSIX return value conventions (-1/errno). This fixes test failures in t7508 with large files.

The change is surgical - adding a compatibility wrapper while preserving existing behavior for callers. It's a necessary foundation for the rest of the series which will convert object size handling throughout Git to use `size_t` consistently. Given Dscho's Windows expertise and the focused nature of the change, this appears to be a solid technical solution to a real platform limitation.
