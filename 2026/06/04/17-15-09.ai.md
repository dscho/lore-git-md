This is the third patch in a platform compatibility series addressing Windows' LLP64 limitations with large (>4GB) objects. The change focuses on the hash algorithm implementation, converting `unsigned long` to `size_t` in SHA-1 handling code to properly support large object sizes.

The patch updates the SHA1DC implementation (Git's collision-detecting SHA-1) to use `size_t` for length parameters, removing an implicit downcast that previously limited object sizes on 32-bit `long` systems. The author explains the somewhat indirect call path through `git_hash_sha1_update()` that makes this change safe despite no direct callers being modified. With this update, the test case for hashing 5GB files now passes on LLP64 systems.

The changes are mechanical but well-justified, touching core object-file handling and the SHA1DC interface while maintaining compatibility through the existing abstraction layers. Johannes Schindelin's sign-off indicates this code has been validated in Git for Windows' production use. The patch completes the hash-object path's conversion to large-file support, with subsequent patches likely addressing remaining subsystems.
