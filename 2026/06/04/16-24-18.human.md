This is a platform compatibility patch series from Johannes Schindelin, targeting Windows process management behavior. The two patches have been carried in Git for Windows for nearly a decade but are now being proposed for upstream inclusion.

The core issue addresses how Git terminates child processes on Windows. Unlike Unix systems where SIGTERM allows graceful shutdown, Windows lacks equivalent signaling. The current approach uses TerminateProcess() (similar to Unix's SIGKILL), which prevents proper cleanup like .lock file removal. The first patch introduces a gentler termination method by injecting a remote thread that calls ExitProcess(), allowing orderly shutdown. The second patch properly handles SIGINT signals from the MSYS2 runtime.

The changes touch Windows-specific compatibility code, adding a new header file for process termination logic. While the approach has some limitations (like not working across different CPU architectures), it represents a significant improvement over the current brute-force termination. Given this has been battle-tested in Git for Windows for years, it's likely ready for upstream consideration.
