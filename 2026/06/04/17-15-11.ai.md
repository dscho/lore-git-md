This is a test patch in the ongoing series addressing Windows compatibility with large (>4GB) objects on LLP64 systems. The patch adds a new test case for `git hash-object` without any special flags, complementing the existing tests for `--stdin` and `--literally` paths.

The test verifies basic file hashing of a 5GB file works correctly on LLP64-bit platforms (like Windows) where `unsigned long` is 32-bit. It reuses the test file generation logic from previous tests to avoid redundant setup. The test is marked EXPENSIVE due to the large file size and is skipped on platforms where `size_t` isn't 64-bit or where `long` already is.

This continues the mechanical but important work of ensuring Git handles large objects properly across all platforms. The patch follows the established pattern of the series and has Johannes Schindelin's sign-off, indicating it's been validated in Git for Windows. The test coverage expansion is straightforward and aligns with the series' goal of comprehensive validation.
