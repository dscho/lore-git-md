This is the final patch in a platform compatibility series addressing Windows' LLP64 limitations with large (>4GB) objects. The patch adds a test case verifying that Git's filter interface correctly handles large files when cleaning/smudging, specifically ensuring the code path uses `size_t` rather than 32-bit `unsigned long` on LLP64 systems.

The test reuses the 5GB test file from previous patches (generating it if needed) and exercises a trivial "null" filter (just `cat`) to validate the interface without actually storing the object. Johannes Schindelin has signed off, indicating this approach has proven reliable in Git for Windows.

This completes the test coverage for the series, having now verified:
1. Direct file hashing
2. `--stdin` input
3. Standard hashing path
4. Filtered input path

The changes are mechanical and well-contained, with clear real-world validation from their long tenure in Git for Windows. The series appears ready for merging as it addresses a concrete limitation while maintaining compatibility with existing behavior.
