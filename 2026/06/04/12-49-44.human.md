Bugfix targeting commit-graph Bloom filter generation in `git gc` and `git fetch`.

Patrick Steinhardt confirms this is indeed a bug where `git gc` and fetch operations with `fetch.writeCommitGraph` ignore the `commitGraph.changedPaths` setting for Bloom filter generation. He explains the technical root cause: these operations call `write_commit_graph_reachable()` directly without checking the config, unlike the explicit `git commit-graph write` command which handles the setting properly.

Steinhardt notes this has already been addressed indirectly in Git 2.54+ through the newer maintenance infrastructure, which executes `git commit-graph` directly rather than using the legacy `git gc` path. While he acknowledges the bug could be fixed in `git gc`, he suggests moving to the newer maintenance approach instead, calling `git gc` a "legacy tool" nearing end-of-life.

This response provides clear technical context about the divergence between code paths and offers both a workaround (using newer maintenance tools) and potential fix directions for anyone wanting to address the `git gc` case specifically. The tone suggests this isn't a high priority for the core team given the newer infrastructure already handles it correctly.
