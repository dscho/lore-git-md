This is the third patch in Johannes Schindelin's series to improve Git's handling of large objects (>4GB) on Windows systems where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch focuses on the pack-objects subsystem, specifically updating `check_pack_inflate()` to use `size_t` for object sizes rather than `unsigned long`.

The change removes a type conversion shim (`cast_size_t_to_ulong()`) that was causing Windows systems to die immediately when processing large objects. While the underlying zlib limitation (32-bit `uLong` counter) remains, this change allows the code to gracefully fall back to an alternative path (`write_no_reuse_object()`) rather than failing outright. The patch builds on previous work (commit 606c192380) that made `write_reuse_object()` track sizes as `size_t`.

This is a focused, mechanical change that maintains the existing behavior for small objects while improving handling of large ones. The patch touches only pack-objects.c and follows the series' pattern of systematically converting size types throughout the codebase. Given Dscho's Windows expertise and the careful handling of the zlib limitation, this appears to be a sound incremental improvement in the larger effort to support big objects on Windows.
