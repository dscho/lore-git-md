Feature enhancement discussion for `git history split`

This is a follow-up in the thread about improving the experimental `git history split` command. Kristoffer Haugsbakk responds to Rasmus Villemoes' earlier suggestions for an iterative splitting mode and automatic atomization feature.

Kristoffer provides a concrete workflow example showing how they currently handle multi-step splits by manually repeating the command with the new commit SHA. Their example demonstrates the exact pain point Rasmus identified - having to manually track the new commit ID after each split operation. The reply reinforces the need for the proposed `--iter` mode that Patrick Steinhardt had indicated would be valuable in his earlier response.

While brief, this email serves as additional real-world validation of the workflow improvements suggested in the thread. It shows another user encountering the same friction points with the current implementation, strengthening the case for adding these features. The discussion remains focused on practical usability concerns rather than technical implementation details.
