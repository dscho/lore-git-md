This is the final patch in Johannes Schindelin's series to enable proper handling of objects larger than 4GB on Windows, where `size_t` is 64-bit but `unsigned long` is 32-bit. The patch converts the object database (ODB) API to use `size_t` for size parameters, completing the series' goal of consistent large object handling.

The change widens `struct object_info::sizep` and related ODB interfaces (`odb_read_object`, `odb_read_object_peeled`, `odb_read_object_info`, `odb_pretend_object`) to use `size_t` instead of `unsigned long`. This fixes cases where operations like `cat-file -s` or `git add` would silently truncate sizes for blobs over 4GB on Windows.

The patch removes transitional scaffolding (like `cast_size_t_to_ulong()` calls) that was added in earlier patches, as the type conversion is now complete throughout the stack. It touches 64 files across core functionality, though some subsystems like diff/blame remain unchanged as they're outside this series' scope.

This builds on the previous 6 patches which systematically converted object size handling in delta, packfile, and pack-objects subsystems. The changes are mechanical but wide-ranging, requiring careful attention to maintain consistency. Given the author's Windows platform expertise and the focused nature of the changes, this appears technically sound though the wide impact warrants review from other experts.

The series is part of ongoing work to improve Git's handling of large objects on Windows and interacts with Patrick Steinhardt's ODB abstraction efforts.
