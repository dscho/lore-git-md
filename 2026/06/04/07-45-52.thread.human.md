This thread introduced `greplint.pl`, a linter that converts bare `grep` assertions in Git’s test suite to `test_grep` for better debuggability. The 6-patch series began as a test infrastructure improvement but evolved to address systemic risks in automated conversion, uncovering and fixing over 10 pre-existing test bugs where `grep` was misused (e.g., missing file arguments or incorrect patterns). The maintainer, Junio C Hamano, initially raised concerns about the `# lint-ok:` exemption mechanism potentially preserving bugs, but these were fully resolved in the final version (v4) by replacing exemptions with explicit guards for conditionally present files (e.g., `test_have_prereq REFFILES` or `test -f <path>`).

The series is now technically complete and approved for merging. Key changes since v3 include bugfixes for three latent test suite issues (e.g., `grep` assertions reading empty stdin), a latent lexer fix for line counting in multi-line command substitutions, and refined documentation in `t/README` clarifying `test_grep` usage. The linter itself, added in the final patch, reuses the shared shell parser from `chainlint.pl` to distinguish assertion `grep` from filter `grep` (e.g., `grep | wc -l`), ensuring only the former is flagged. It handles edge cases like negated forms (`test_grep !` instead of `! test_grep`) and respects `# lint-ok` annotations for legitimate filter uses. The bulk conversion replaced ~2800 `grep` assertions across 338 test scripts, with manual interventions for two edge cases involving conditionally present files.

Participants included the author (Michael Montalbo), who addressed all feedback, and SZEDER Gábor, whose 2021 fix for a similar issue was incorporated. The series is ready for integration, with no open questions or technical concerns. Expect it to graduate to `next` shortly.
