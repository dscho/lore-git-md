This thread discusses a proposed tool to standardize how Git's test suite uses grep for assertions. The author, Michael Montalbo, initially suggested automatically converting bare `grep` calls to the preferred `test_grep` helper across the entire test suite. While the technical implementation is solid - handling edge cases and fixing several pre-existing test bugs - maintainer Junio Hamano raised concerns about the approach. He prefers adding diagnostic checks to the existing test-lint framework rather than creating a new tool that modifies files automatically.

The v2 series responds to some feedback by dropping the automatic fixing mode and reusing chainlint's shell parser infrastructure. It now detects and converts about 2800 grep assertions across 340 test files while preserving formatting and handling complex cases like negations and pipe contexts. The tool also fixes 10 pre-existing test bugs it discovered during development.

Key outstanding questions center on whether to proceed with the conversion tool or shift to a diagnostic-only approach in test-lint, and how to reliably distinguish between grep used for assertions (which should use test_grep) versus grep used as implementation detail (which should remain). The test bug fixes and documentation improvements would be valuable regardless of which direction the series ultimately takes. The author now needs to address Junio's core concerns about the tool's fundamental approach before the series can move forward.
