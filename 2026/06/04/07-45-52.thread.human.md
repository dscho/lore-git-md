Junio Hamano, the Git maintainer, has weighed in on the series introducing a lint tool to convert bare 'grep' assertions to 'test_grep' in the test suite. While the technical implementation appears sound, Junio expresses reservations about the fundamental approach of automatically rewriting test files. He suggests instead adding diagnostic checks to the existing test-lint framework that would flag problematic grep usage without modifying files directly. 

Junio raises two key concerns: first, that automated rewriting may be too heavy-handed compared to simply detecting issues, and second, that the tool needs to better distinguish between grep uses that are actual test assertions (which should use test_grep) versus those that are implementation details (which may legitimately remain as bare grep). This feedback suggests the series may need significant restructuring to focus on detection rather than automatic fixes and to add logic for identifying assertion contexts.

The author, Michael Montalbo, has been responsive to feedback so far (having incorporated D. Ben Knoble's earlier suggestion about Makefile maintainability), but now faces a more fundamental design question. The path forward likely involves reworking the approach to align with the maintainer's vision for test linting, potentially splitting the effort into separate detection and conversion phases. The series' current test fixes (which addressed 10 pre-existing bugs) remain valuable regardless of the linting approach.
