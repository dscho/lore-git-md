This thread is about a now-complete six-patch series introducing `greplint.pl`, a test-suite linter that converts bare `grep` assertions to `test_grep` for better debuggability. The series, originally a test infrastructure improvement, evolved to address systemic risks in automated conversion that could mask pre-existing test bugs—over 10 such bugs were fixed during development. The maintainer, Junio C Hamano, has approved the series for merging after all concerns about edge cases, documentation, and the linter’s suppression mechanism were resolved.

The core change replaces ~2800 `grep` assertions with `test_grep`, which prints file contents on failure to aid debugging. The linter itself is careful to distinguish assertion `grep` from filter `grep` (e.g., `grep | wc -l`), skipping the latter. The series also documents the previously undocumented `test_grep` helper in `t/README`, clarifying its purpose and edge cases, such as when bare `grep` is still appropriate (e.g., for platform-dependent paths or data filters). The shared shell parser infrastructure (`lib-shell-parser.pl`), extracted from `chainlint.pl`, is now reused by `greplint.pl` and future linters.

The latest update is a minor bugfix to the shared shell parser, correcting a latent line-counting issue in the lexer that double-counted newlines inside multi-line command substitutions. This fix is internal to the lexer and does not affect existing functionality, as no current tool uses token line numbers. The series is technically complete, with no open questions or technical concerns, and is ready for integration. Expect it to graduate to Junio’s `next` branch shortly.
