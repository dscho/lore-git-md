This thread is about a six-patch series introducing `greplint.pl`, a tool to convert bare `grep` assertions in Git’s test suite to the safer `test_grep` helper. The series, now at v2, was motivated by test infrastructure improvements and has already uncovered over 10 bugs during conversion. However, its adoption is now in question after a review by SZEDER Gábor revealed that automated conversion can preserve pre-existing bugs—specifically, a latent issue in `t3420-rebase-autostash.sh` where a negated `grep` assertion (`! grep dirty file3`) incorrectly assumes the file exists after `git rebase --quit`. The correct fix would use `test_path_is_missing` instead.

The author, Michael Montalbo, has defended the tool’s value while engaging with maintainer concerns, but Junio C Hamano remains opposed to automated conversion on philosophical grounds, arguing it obscures the distinction between using `grep` as an assertion versus a filter. The latest development comes from Junio, who has proposed a technical solution: extend `test_grep` to detect when a negated pattern fails because the file is missing (not just because the pattern wasn’t found). This would mirror how `test_must_fail` flags unexpected command failures (e.g., segfaults) and could address both the immediate bug and future automation risks. The idea shifts the discussion toward tooling improvements rather than outright rejection, leaving the door open for a middle ground—though the broader methodological debate (automation vs. diagnostics) remains unresolved. The next steps will likely focus on whether this enhancement can satisfy both the demonstrated value of the tool and maintainers’ concerns about long-term maintenance.
