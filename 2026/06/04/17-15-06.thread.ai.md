This thread addresses Windows-specific LLP64 limitations for large objects (>4GB) by converting object header lengths from `unsigned long` to `size_t` across object-file and hash algorithm code paths. The series, originally authored by Philip Oakley 4.5 years ago and maintained in Git for Windows, is now in its second iteration (`v2`) with all production code changes merged and validated in Git for Windows.

**Core problem or goal**
The series resolves 32-bit truncation of object sizes on Windows (LLP64) by systematically replacing `unsigned long` with `size_t` in object-file handling code (`object-file.c`, `sha1dc_git.c`, `hash.h`, `odb/source-*`). The goal is to enable Git to correctly process objects larger than 4GB on all platforms where `size_t` is 64-bit, while maintaining backward compatibility and avoiding regressions on 32-bit systems.
