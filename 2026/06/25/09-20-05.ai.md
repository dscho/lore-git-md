This is **patch 7/11 in Patrick Steinhardt's v6 refactoring series** for Git's reference backend, targeting the **lazy-loading design** to resolve recursive initialization issues caused by "onbranch" configuration. The patch **moves parsing of `core.logAllRefUpdates` back into the ref backends** (files and reftable), reversing a previous refactoring (cc42c88945) that centralized this logic in the generic layer. This change is a **preparatory step** for the lazy-loading refactor, ensuring all backend configuration is parsed consistently and avoiding early config reads that could trigger recursion.

### Key changes
- **Moves `core.logAllRefUpdates` parsing** from `repo-settings.c` (generic layer) back into the **files backend** (`refs/files-backend.c`) and **reftable backend** (`refs/reftable-backend.c`). The backends now handle this setting via their own `*_ref_store_config()` callbacks.
- **Removes the `log_all_ref_updates` field** from `struct ref_store_init_options`, as this setting is no longer passed during ref store initialization.
- **Adds `refs_parse_log_all_ref_updates_config()`** to `refs.h` as a public helper for parsing the config value, replacing the now-removed `repo_settings_get_log_all_ref_updates()`.
- **Updates `builtin/checkout.c`** to use `repo_config_get_string_tmp()` and `refs_parse_log_all_ref_updates_config()` directly when checking reflog creation for orphan branches, avoiding reliance on the generic layer.
- **Simplifies `setup.c`** by removing the redundant `LOG_REFS_UNSET` check in `create_default_files()`, as `repo_config_get_string_tmp()` now handles the unset case.

### Why this matters
The patch **decouples ref backend initialization from early config parsing**, a critical step for the lazy-loading design. By moving `core.logAllRefUpdates` back into the backends, Patrick ensures that:
1. **All backend config is parsed the same way**, avoiding inconsistencies between settings handled generically (e.g., `core.prefersymlinkrefs`) and those handled in the backend (e.g., `core.logAllRefUpdates`).
2. **Write-critical config is deferred** until the first write operation, eliminating the recursive initialization issues that plagued earlier versions (e.g., "onbranch" conditions triggering ref store creation during config parsing).
3. **The reftable backend’s config parsing** is aligned with the files backend, paving the way for dynamic write option passing in later patches.

- **Edge cases**: The patch ensures `core.logAllRefUpdates` is parsed consistently across backends, even when "onbranch" conditions are present. The `LOG_REFS_UNSET` state is now handled explicitly in `builtin/checkout.c` and `setup.c`.
