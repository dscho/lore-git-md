This is the fourth patch in Patrick Steinhardt’s v2 series refactoring Git’s connectivity checks to support ODB backend independence. The patch replaces packfile-specific logic with a generic ODB iteration interface, but Junio C Hamano identified a **logical inversion** in the control flow: the patch currently causes the connectivity check to fall back to a full rev-list scan when a promisor object *is* found, instead of taking the fast path.

Patrick acknowledges the issue and proposes an alternative fix. Instead of reversing the return values in the error-handling branch (as Junio suggested), he suggests modifying the callback (`promised_object_cb`) to set a boolean flag via its `payload` parameter, then checking that flag in `check_connected_promisor()`. This approach makes the logic more explicit: the callback signals whether a promisor object was found, and the caller acts accordingly. The proposed change is small and self-contained, touching only the callback and its invocation.

The patch remains critical for Patrick’s ODB abstraction effort, but this inversion must be resolved before the series can proceed. Patrick also notes that the bug does not trigger any test failures, which is concerning—he plans to add a test to catch similar regressions. The fix itself looks straightforward, but reviewers may weigh in on whether the boolean-flag approach is clearer than simply reversing the return values. No other issues are raised in this reply.
