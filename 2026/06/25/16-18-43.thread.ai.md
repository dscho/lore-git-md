Subject: [PATCH 0/2] libify excludes_file handling
Series version: v1 (first iteration)
Originating author: Tian Yuchen
Thread type: patch series (refactoring / libification)

Core problem or goal
Eliminate the global `excludes_file` string variable by moving it into `struct repo_config_values` and introducing proper heap memory management. This is part of the ongoing libification effort to make Git's internals more modular and suitable for use as a library.

Current status
Series is at v1, under initial review by Junio C Hamano. Two patches:
1. Introduces `repo_excludes_file()`, a getter function that encapsulates the lazy-loading logic for the global `excludes_file` variable, moving it from `dir.c` to `environment.c`. This is a preparatory step that maintains existing behavior while making the global's usage more explicit.
2. Migrates the global to `struct repo_config_values`, adds `repo_config_values_clear()` for cleanup, and removes the global declaration. Junio's review identified two mechanical issues: missing explicit `NULL` initialization for `excludes_file` in `repo_config_values_init()`, and an incomplete cleanup function that does not account for the existing heap-allocated `attributes_file` field.

Key technical details
- Files touched: `dir.c`, `environment.c`, `environment.h`, `repository.c`
- New symbols: `repo_excludes_file()`, `repo_config_values_clear()`
- Memory management: heap-allocated string in `struct repo_config_values`, must be freed by `repo_config_values_clear()` alongside `attributes_file`
- Temporary guard: `if (repo != the_repository)` in both the getter and cleanup functions to avoid BUG() with uninitialized submodules
- Net change: +60 lines (36 from patch 1, 24 from patch 2)
- No behavioral changes expected
- The getter function in patch 1 includes a TODO comment in `environment.h` acknowledging the remaining global dependency, resolved in patch 2.

Open questions and loose ends
- The temporary submodule guard remains a stopgap until broader submodule initialization issues are addressed.
- Junio's review raises two actionable items: explicit `NULL` initialization for `excludes_file` in `repo_config_values_init()`, and updating `repo_config_values_clear()` to handle both `excludes_file` and `attributes_file`.

Participant positions
- **Junio C Hamano**: Substantive review of patch 2, identifying two mechanical issues (initialization and cleanup completeness). No objections to the series' direction or the temporary submodule guard.

Related work
