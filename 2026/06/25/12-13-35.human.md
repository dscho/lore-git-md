This is the final patch in the 14-part security-hardened `git cat-file --batch-command` series, now ready for merging. It replaces the hardcoded allow-list for remote object metadata queries with a dynamic system that respects what the server actually advertises.

The patch makes the placeholder validation in `expand_atom()` adapt to the server's capabilities rather than assuming every server supports the same set of fields. The client now maps requested placeholders (like `%(objectsize)`) to protocol options ("size"), asks the server which options it supports, and only allows placeholders that correspond to advertised capabilities. This future-proofs the feature for servers that may support additional metadata (like object type) in later Git versions.

Key changes include moving `object_info_options` out of `get_remote_info()` so callers can specify which metadata they want, introducing a mapping between protocol options and placeholder atoms, and ensuring `batch_object_write()` always produces output (even if empty) when placeholders are unsupported. The patch also adds "type" to the protocol options in preparation for future server support.

The implementation is careful about memory management (clearing string lists) and maintains backward compatibility by still allowing "objectname" unconditionally. The backward iteration during capability filtering ensures safe list modification. All prior review feedback has been addressed, and the series has passed CI testing.
