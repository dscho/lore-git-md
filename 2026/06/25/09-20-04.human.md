This is the sixth patch in Patrick Steinhardt’s 11-part v6 refactoring series modernizing Git’s reference backend infrastructure. The patch fixes a **memory leak** in `repository.c` where the main reference database (`repo->refs_private`) was never released during repository cleanup, despite worktree and submodule reference databases being properly freed.

The leak went unnoticed because the `chdir_notify` subsystem kept the pointer alive, masking the issue. The fix is straightforward: add a check in `repo_clear()` to call `ref_store_release()` on `repo->refs_private` and free the pointer. This aligns the main reference database’s lifecycle management with that of submodules and worktrees, which already receive this treatment.

The change is **low-risk and uncontroversial**—it’s a mechanical cleanup that doesn’t alter behavior, only plugs a leak. It’s also a **prerequisite** for the later patches in the series (notably patch 4/11, which fixed `chdir_notify` lifecycle management), ensuring the refactoring doesn’t introduce new leaks. The patch touches only one file (`repository.c`) and adds five lines of code, making it easy to review.

Given the series’ focus on resolving recursive initialization issues and improving ref backend modularity, this patch is a small but necessary step toward that goal. It’s unlikely to attract objections, as it addresses a clear oversight with minimal impact. Reviewers will likely approve it quickly as part of the broader series.
