This is a platform-compatibility bugfix for the new `git history` command. Johannes Schindelin identifies a file-descriptor leak in `git history reword` and `git history fixup`: the code writes the commit message to `COMMIT_EDITMSG`, appends status information via a second handle, and then launches the editor without closing that handle. On Unix-like systems this merely leaks a descriptor; on Windows it breaks outright because the editor cannot replace the file while Git still holds it open. The fix is a one-line addition that closes the handle before handing the file to the editor. The patch touches only `builtin/history.c` and includes a clear explanation of the problem and the rationale for the timing of the fix (sent during the -rc phase rather than waiting for the next cycle). The test failures that surfaced the issue (t3451-history-reword and t3453-history-fixup) are mentioned, giving readers a concrete way to verify the fix.
