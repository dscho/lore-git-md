This is the fifth patch in Patrick Steinhardt’s 11-part **v6 refactoring series** for Git’s reference backend. It is a **cleanup patch** that removes the now-unused `chdir_notify_reparent()` function from the `chdir_notify` subsystem.

The patch is **mechanical and uncontroversial**: earlier patches in the series (notably patch 4/11) eliminated all callers of `chdir_notify_reparent()`, so this patch simply deletes the dead code. The diff removes 26 lines from `chdir-notify.c` and updates the header file to remove the function’s declaration, while leaving the documentation comment to explain how callers should use `reparent_relative_path()` instead.

This is **not a functional change**—it is a follow-up to the lifecycle management fixes in patch 4/11, which added proper `chdir_notify_unregister()` calls to the ref backends. The removal of `chdir_notify_reparent()` is a natural consequence of that work, as the function’s sole purpose (reparenting relative paths during chdir events) is now handled directly by the backends.

The patch is **ready to merge** and unlikely to attract review comments, as it is purely a cleanup with no behavioral impact. It is part of the series’ broader effort to stabilize the `chdir_notify` subsystem before introducing the lazy-loading refactoring in later patches.
