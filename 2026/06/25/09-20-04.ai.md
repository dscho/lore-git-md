This is **patch 6/11 in Patrick Steinhardt's v6 refactoring series** for Git's reference backend infrastructure. The patch fixes a **memory leak** in `repository.c` where the main reference database (`repo->refs_private`) was never released during repository cleanup, despite being tracked by the `chdir_notify` subsystem.

### What the patch does
The change adds a **five-line block** to `repo_clear()` that explicitly releases the main reference database by calling `ref_store_release(repo->refs_private)` and then freeing the pointer. This mirrors the existing cleanup logic for submodule reference databases, which are already released via `strmap_for_each_entry()`.

### Why it matters
- **Lifecycle management**: The leak was latent because `chdir_notify` kept the pointer alive, but failing to release it could cause issues in long-running processes (e.g., daemons) or during repository reinitialization.
- **Preparatory work**: This is a **low-risk, uncontroversial cleanup** that paves the way for the lazy-loading refactor in later patches (7–11/11). The `chdir_notify` subsystem was already identified as a source of leaks in patch 4/11, and this patch completes the fix for the main ref store.
- **Consistency**: The change aligns the main ref store’s cleanup with submodule ref stores, eliminating a special case.

### Technical context
- **File touched**: `repository.c` (core repository management).
- **Key functions**: `repo_clear()`, `ref_store_release()`.
- **Risk level**: Minimal. The patch only adds cleanup code where it was clearly missing, with no behavior changes.
- **Test coverage**: No new tests are added here, but the leak would be caught by existing memory-leak detectors (e.g., `GIT_TEST_PASSING_SANITIZE_LEAK=1`).
