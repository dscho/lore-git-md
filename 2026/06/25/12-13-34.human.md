This is a security-focused patch in the fourteenth iteration of a series implementing `git cat-file --batch-command` support for remote object metadata queries. This specific patch addresses a critical validation gap in the format placeholder handling for remote queries.

The patch fixes two serious issues in the `expand_atom()` function: (1) uninitialized `data->type` could cause segmentation faults when processing recognized but unsupported atoms, and (2) the function would die on unknown atoms, breaking local queries that shared the same format string. The solution introduces an allow-list of supported remote atoms (`objectname` and `objectsize`) and modifies the behavior to return empty strings for unsupported atoms, matching how `for-each-ref` handles known-but-inapplicable placeholders.

Key changes include:
- Adding `remote_object_info_atoms[]` array to explicitly list supported remote atoms
- Initializing `data->type` to `OBJ_BAD` and adding NULL checks for `type_name()`
- Adding `is_remote` flag to `expand_data` struct to distinguish remote vs local queries
- Updating documentation to clarify that unsupported atoms return empty strings rather than failing
- Modifying tests to expect empty strings instead of die() for unsupported placeholders

The patch demonstrates careful attention to security and edge cases, with particular focus on preventing crashes from uninitialized data and maintaining consistent behavior across local and remote queries. The changes are well-tested, with updated and new test cases covering the modified behavior. This is a substantive fix that addresses real issues while maintaining the series' security posture.
