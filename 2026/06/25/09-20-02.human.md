This is the fourth patch in Patrick Steinhardt’s 11-part v6 series refactoring Git’s reference backend to implement lazy-loading of write configuration. This specific patch addresses a **lifecycle management bug** in the `chdir_notify` subsystem: reference stores register for directory-change notifications when created, but are never unregistered when released. The result is either a **memory leak** (for the main ref store) or a **dangling pointer** (for submodule/worktree stores), though neither symptom has been observed in practice because Git rarely changes directories mid-process.

The fix is straightforward: each backend (`files`, `packed`, `reftable`) now provides its own reparenting callback and uses `chdir_notify_register()` instead of `chdir_notify_reparent()`. The callbacks are then unregistered in the backend’s `release()` function. The patch touches three files (`refs/files-backend.c`, `refs/packed-backend.c`, `refs/reftable-backend.c`) and adds about 50 lines of code, mostly boilerplate for the new callbacks.

This is a **cleanup patch** that fixes a latent bug without changing user-visible behavior. It is uncontroversial and well-motivated: the commit message clearly explains the problem, the symptoms, and why they haven’t been noticed. The change is mechanical and low-risk, relying on existing `chdir_notify` infrastructure. Reviewers are unlikely to object, though they may check that the unregistration happens in all code paths (e.g., error cases). The patch is a prerequisite for the next one, which will fix the main ref store leak.
