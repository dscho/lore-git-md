This is the fourth and final patch in Patrick Steinhardt’s v3 series refactoring Git’s connectivity checks to use generic ODB iteration instead of packfile-specific logic. It directly addresses the core goal of the series: removing the hard dependency on packfile internals so that connectivity checks work with alternative ODB backends (e.g., reftable or custom storage).

The patch replaces the packfile-centric loop in `check_connected_promisor()` with `odb_for_each_object_ext()`, using the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag and a prefix filter to search for promisor objects. The new `promised_object_cb()` callback sets a `found` boolean flag when a promisor object is located, fixing the logical inversion from v2 where the check incorrectly fell back to a full rev-list scan when an object *was* found. The control flow is now clearer: if no promisor object is found (`!found`), the function returns `0` to trigger the fallback connectivity check; otherwise, it continues iterating.

The added test in `t/t5616-partial-clone.sh` is a key improvement, explicitly verifying that the optimized promisor check is used during partial fetches (when all tips are in promisor packs) and that the full rev-list connectivity check is triggered when any tip is not in a promisor pack. This closes the coverage gap Patrick noted in v2, where the logical inversion did not cause test failures.

The patch is technically sound and well-motivated. It touches only `connected.c` and the test suite, with no user-facing behavior changes or on-disk format modifications. The use of `odb_for_each_object_ext()` aligns with the ODB abstraction effort, and the `found` flag approach is a clean fix for the v2 regression. Reviewers may still scrutinize edge cases (e.g., error propagation from `odb_for_each_object_ext()`, interactions with future ODB backends), but the changes are uncontroversial and directly support the series’ goal. This patch is ready for final review and likely to be merged as part of the ODB abstraction work.
