This is the core client-side implementation patch in a security-hardened feature series that adds `git cat-file --batch-command` support for querying remote object metadata (initially just object sizes) without full downloads. It is patch 10/13 in v14 of the series, which is now ready for merging after addressing all prior review feedback.

The patch introduces `fetch-object-info.c`, a new file that implements the client logic for the `object-info` protocol v2 command. The key function, `fetch_object_info()`, sends a request to the server listing the desired object IDs and metadata fields (currently only "size" is supported), then parses the response into an array of `struct object_info` structures. The implementation strictly enforces protocol v2 and checks that the server advertises the `object-info` capability before proceeding. Input validation is thorough: the client verifies that requested fields match the server's advertised capabilities, and numeric conversions use the new `strtoul_szt()` helper for type safety.

The patch wires this functionality into the transport layer by extending `struct git_transport_options` with three new fields (`object_info`, `object_info_oids`, and `object_info_options`) and modifying `transport.c` to invoke `fetch_object_info()` when the feature is enabled. The fetch-pack state machine is updated to transition to `FETCH_SEND_REQUEST` when `args->object_info` is set, ensuring the object-info request is sent before any fetch operations. In `transport-helper.c`, the patch adds an explicit error for object-info requests on non-v2 protocols and ensures `get_refs_list_using_list()` is called even when no refs are being fetched, which is necessary for the object-info flow.

The implementation follows the established pattern of writing the entire request into a buffer before sending it to the remote, matching the approach used in `send_fetch_request()`. The patch includes comprehensive error handling: it dies on protocol mismatches, capability mismatches, and malformed server responses, and it properly cleans up allocated memory (including the `sizep` fields in `object_info_data`). The `Helped-by` trailers credit Jonathan Tan and Christian Couder for substantive review, indicating this patch has received attention from maintainers familiar with the protocol layer.

This is a well-crafted, security-conscious addition that fits cleanly into the existing transport infrastructure. The patch is narrowly focused on the client-side protocol logic and does not yet expose the functionality through user-facing commands (that comes in patch 11/13), but it provides all the necessary plumbing for `git cat-file --batch-command` to query remote object sizes. The series' earlier patches have already addressed memory safety, protocol compatibility, and test infrastructure, so this patch can focus on the core functionality.
