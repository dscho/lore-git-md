This is a refactoring patch in the ongoing `git cat-file --batch-command` security series (now at v14). It moves initialization code out of the `FETCH_CHECK_LOCAL` state in `do_fetch_pack_v2()` so that the same variables are set regardless of which state the function starts in. A later patch in the series will introduce a new initial state, making this change necessary.

The patch is mechanical: six lines of variable initialization are moved from inside the first state case to just before the state machine loop. The commit message explains that this is a pure refactoring with no behavior change, and the `Helped-by` trailers from Jonathan Tan and Christian Couder suggest the change was reviewed for correctness. The diff is small and focused, touching only `fetch-pack.c`.

This is part of the preparatory work for the new `remote-object-info` protocol command, though the connection is indirect. The patch itself does not introduce new functionality or user-visible changes, but it enables future protocol extensions by making the state machine more flexible. The series as a whole is now considered ready for merging, with all substantive review feedback addressed.
