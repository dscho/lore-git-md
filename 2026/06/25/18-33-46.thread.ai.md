Core problem or goal
Fix a file descriptor leak in `git history`'s `fill_commit_message` function that causes `git history reword` and `git history fixup` to fail on Windows when the editor attempts to overwrite the `COMMIT_EDITMSG` file. The leak also affects non-Windows platforms but is only symptomatic on Windows due to BusyBox `ash` shell limitations. Junio's review expands the scope to address redundant file operations, improve code quality, and correct a mechanical typo in the refactoring (`fwrite(out.buf, ...)` -> `fwrite(out->buf, ...)`).

Current status
Original patch sent by Toon Claes; Junio proposes a more thorough refactoring that eliminates the leak, removes redundant file operations, and improves maintainability, then corrects a trivial typo in his own refactoring. No new versions posted yet. No acks or reviews beyond Junio's critique and correction.

Key technical details
- File: `builtin/history.c`
- Function: `fill_commit_message`
- Symbols: `s.fp` (FILE pointer), `git_path_commit_editmsg()`, `write_file_buf()`, `strbuf *out` (pointer, not struct)
- On-disk file: `COMMIT_EDITMSG`
- Test coverage: `t3451-history-reword` and `t3453-history-fixup` (unchanged)
- Behavior change: none on non-Windows; Windows now succeeds instead of failing with "File exists" from `cp` in the test suite's fake editor
- New technical details: Junio's refactoring eliminates the redundant call to `git_path_commit_editmsg()` and consolidates file writes into a single stream opened in write mode, avoiding the append-mode reopen that caused the leak. The typo correction ensures the refactoring compiles.
