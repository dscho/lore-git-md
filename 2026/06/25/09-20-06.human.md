This is the **eighth patch in Patrick Steinhardt’s 11-part v6 series** refactoring Git’s reference backend to fix initialization-order issues. Specifically, this patch **implements lazy-loading of write-critical configuration** in the files backend, resolving a chicken-and-egg problem where parsing `core.preferSymlinkRefs` or `core.logAllRefUpdates` during backend initialization could trigger recursive access to the ref store via `includeif.onbranch` conditions.

The patch introduces a new `files_ref_store_write_options` struct inside `struct files_ref_store` to hold deferred write settings (`log_all_ref_updates` and `prefer_symlink_refs`). These settings are parsed only when first needed (e.g., during `ref_transaction_commit()`) via the new `files_ref_store_write_options()` accessor, which caches the parsed values in a `initialized` flag. The commit message and code comment clearly explain the lazy-loading rationale: avoiding early config reads that could require the ref store before it is fully initialized.

The test added in `t/t0600-reffiles-backend.sh` verifies that `core.preferSymlinkRefs` can now be set via an `onbranch` condition without causing recursion. This is a **real-world regression fix**—earlier versions of the series failed this test, as noted in the thread context.

This patch is **well-motivated and technically sound**. The lazy-loading design was endorsed by Jeff King (Peff) as the correct root-cause fix, and Justin Tobler’s review feedback (a suggested code comment) was incorporated in v6. The changes are confined to the files backend and its tests, with no cross-subsystem impact. The patch is **ready for final review**, though reviewers may scrutinize edge cases like concurrent write operations or config cache consistency. If merged, it will resolve a long-standing initialization bug while improving backend modularity.
