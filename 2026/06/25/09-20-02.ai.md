This is the **fourth patch in Patrick Steinhardt's v6 refactoring series** for Git's reference backend infrastructure. It addresses a **lifecycle management bug** in the `chdir_notify` subsystem by ensuring reference stores are properly unregistered when released.

### What the patch does
The patch fixes a long-standing issue where reference stores (files, packed, and reftable backends) register themselves with Git's `chdir_notify` subsystem to handle relative path updates when the working directory changes, but **never unregister** when the stores are freed. This creates two problems:
1. **Memory leaks**: The main repository's reference store is never freed, and the leak checker ignores it because it remains registered.
2. **Dangling pointers**: Submodule and worktree reference stores *are* freed (in `repo_clear()`), leaving the `chdir_notify` subsystem with pointers to freed memory. This hasn't caused visible issues because Git rarely changes directories mid-process, but it’s a latent bug.

The fix replaces `chdir_notify_reparent()` (which lacks unregistration support) with `chdir_notify_register()` and adds corresponding `chdir_notify_unregister()` calls in the `*_ref_store_release()` functions for all three backends. Each backend gets a new `*_ref_store_reparent()` callback to handle path updates.

### Technical details
- **Files backend**: Adds `files_ref_store_reparent()` to update both `gitdir` and `gitcommondir` paths. The release function now unregisters the callback.
- **Packed backend**: Adds `packed_ref_store_reparent()` to update the `path` field. The release function unregisters the callback.
- **Reftable backend**: Adds `reftable_be_reparent()` to update `gitdir`. The release function unregisters the callback.
- **No behavior change**: The patch only fixes lifecycle management; user-visible behavior remains unchanged.

### Context in the series
This is a **preparatory cleanup** for the larger lazy-loading refactor (patches 8–11/11). While not directly tied to the "onbranch" recursion fix, it eliminates a source of potential instability in the `chdir_notify` subsystem, which could interfere with the series' core changes. The leak in the main reference store is explicitly deferred to a later patch (likely 1/11, which fixes a memory leak in `chdir_notify_register()`).
