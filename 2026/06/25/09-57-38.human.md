This is the third iteration of a four-patch series from Patrick Steinhardt that refactors Git’s connectivity checks to work generically across different object database (ODB) backends, removing a hard dependency on packfile internals. The series is a key step in Patrick’s ongoing ODB abstraction effort, which aims to support alternative backends like reftable or pluggable storage.

The core goal is to make connectivity checks—used to verify that all objects reachable from a set of refs are present—work correctly in repositories that don’t use packfiles. Currently, these checks assume a packfile-based ODB, which blocks the ODB abstraction work. The series achieves this by extracting and generalizing the logic for searching promisor objects, replacing direct packfile access with a generic ODB iteration interface.

Version 3 addresses two issues raised in v2: a logical inversion in Patch 4 (where the connectivity check incorrectly fell back to a full rev-list scan when a promisor object *was* found) and a performance optimization in Patch 2 (reordering checks to avoid unnecessary work). Both fixes are mechanical and localized. The series also adds a new test in Patch 4 to verify that the optimized check is used when expected, filling a gap in promisor object coverage.

The patches touch two files: `connected.c` (connectivity logic) and `odb/source-packed.c` (packfile iteration). Key changes include:
- A new helper, `should_exclude_pack()`, to determine pack exclusion based on flags.
- Support for flags in `odb_for_each_object()` when iterating over an object prefix.
- Splitting promisor-specific logic into `check_connected_promisor()`.
- Replacing `find_pack_entry_one()` with `odb_for_each_object_ext()` and the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag.

The series is well-motivated and technically sound, with clear commit messages and a concise cover letter. It’s unlikely to be controversial, though reviewers may scrutinize edge cases in the new iteration logic or flag handling. The addition of a test in v3 is a welcome improvement, though the test’s reliance on `GIT_TRACE2_EVENT` to detect rev-list invocations might raise questions about robustness.

This is a focused, incremental step toward ODB abstraction, and it looks ready for review. If you care about Git’s storage layer or the ODB abstraction effort, this series is worth your time.
