This is **patch 9/11 in Patrick Steinhardt’s v6 refactoring series**, which restructures the reftable backend to separate stack-level and write-specific configuration. The patch splits the `reftable_write_options` struct into two distinct structs: `reftable_stack_options` (for stack-level settings like hash ID and reload callbacks) and `reftable_write_options` (for write-specific settings like block size and compression). This enables dynamic write option passing during write operations, a key requirement for the lazy-loading design introduced in earlier patches.

### Key changes
The patch touches **14 files**, primarily in the `reftable/` directory, and introduces the following structural changes:
- **New `reftable_stack_options` struct**: Contains stack-level settings (`hash_id`, `on_reload` callback and payload). This replaces the stack-level fields previously embedded in `reftable_write_options`.
- **Updated APIs**: Functions like `reftable_new_stack()`, `reftable_stack_new_addition()`, and `reftable_stack_add()` now accept separate stack and write options. For example, `reftable_stack_add()` gains a `const struct reftable_write_options *opts` parameter to pass write-specific settings.
- **Dynamic write option passing**: The reftable backend now passes write options explicitly to functions like `reftable_stack_add()` and `reftable_stack_compact_all()`, enabling deferred parsing of write-critical config (e.g., `reftable.blockSize`).
- **Hash ID handling**: The `hash_id` field moves from `reftable_write_options` to `reftable_stack_options`, and `reftable_writer_new()` now takes an explicit `enum reftable_hash` parameter. Defaults are set in `reftable_writer_new()` (SHA1) and `reftable_new_stack()` (SHA1 if unset).
- **Test updates**: Unit tests (`t/unit-tests/u-reftable-*.c`) and helpers (`t/helper/test-reftable.c`, `t/unit-tests/lib-reftable.*`) are updated to pass the new structs and explicit hash IDs. Tests now use `REFTABLE_HASH_SHA1` or `REFTABLE_HASH_SHA256` directly instead of relying on defaults.

### Why this matters
This patch is a **mechanical but critical refactor** that enables the lazy-loading design for write-critical configuration. By decoupling stack and write options, the reftable backend can defer parsing write settings (e.g., `reftable.blockSize`) until the first write operation, avoiding recursive initialization issues with `includeif.onbranch`. The changes are **backward-compatible** for callers (e.g., `reftable_stack_compact_all()` accepts a `NULL` write options pointer to use defaults) but require updates to all reftable-related code.
