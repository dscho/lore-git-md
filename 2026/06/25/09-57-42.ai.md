This is the fourth and final patch in Patrick Steinhardt’s v3 series refactoring Git’s connectivity checks to search for promisor objects generically, removing a hard dependency on packfile internals. The patch completes the series’ goal of making connectivity checks backend-agnostic, a critical step for the ODB abstraction effort.

The patch replaces the packfile-specific `find_pack_entry_one()` logic in `check_connected_promisor()` with a generic ODB iteration using `odb_for_each_object_ext()` and the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag. The new `promised_object_cb()` callback sets a `found` boolean flag when a promisor object is located, fixing the v2 logical inversion where the connectivity check incorrectly fell back to a full rev-list scan when a promisor object *was* found. The main function now checks `if (!found)` to determine whether to fall back to the rev-list-based connectivity check, ensuring correctness while preserving the optimization for partial clones.

The patch also adds a new test in `t/t5616-partial-clone.sh` that explicitly verifies the optimized promisor check is used during partial fetches (when all tips are in promisor packs) and that the full rev-list connectivity check is triggered when any tip is not in a promisor pack. This addresses the earlier coverage gap Patrick noted in v2, where the logical inversion did not cause test failures. The test uses `GIT_TRACE2_EVENT` to inspect the command invocation chain, ensuring the rev-list subcommand is absent or present as expected.

The changes are confined to `connected.c` and the test suite, with no user-facing behavior changes or on-disk format modifications. The patch is technically sound and directly supports the ODB abstraction effort, enabling connectivity checks to work with non-packfile backends (e.g., reftable, custom storage layers). The `found` flag approach is clearer than the v2 return-value inversion and addresses Junio’s feedback about maintainability.

Reviewers may focus on whether the generic iteration logic handles all edge cases (e.g., error propagation, partial matches) and whether the fallback behavior is correct in all scenarios. However, the patch is uncontroversial and ready for final review, with all substantive feedback from v2 addressed. ODB-focused contributors (e.g., Justin Tobler, Taylor Blau) are likely to provide the most relevant feedback.
