This is a maintainer's reply to the final iteration of a documentation patch series. Junio Hamano, the Git maintainer, approves the v4 patch from Tamir Duberstein that documents the `--no-follow` option for `git log` and its interaction with the `log.follow` configuration. The patch is now merged into the `next` branch, closing the thread.

The email clarifies a minor point about option ordering in the documentation: Junio initially misread the patch as combining the descriptions of `--follow` and `--no-follow`, but upon closer inspection, he acknowledges that the existing text already lists `--no-follow` before `--follow`. While he personally prefers `--follow` to come first (consistent with the pattern seen in other parts of Git's documentation), he accepts the current ordering as acceptable given the existing inconsistency across the codebase. This is not a blocker for merging.

The substantive feedback is that Junio would prefer the `--no-follow` entry in `git-log.adoc` to be a standalone one-liner (e.g., `--no-follow:: Overrides `--follow` and `log.follow`.") rather than embedding the override behavior in the `--follow` description. However, he does not insist on this change for this patch, implying the current version is acceptable. The update to `config/log.adoc` (noting that `--no-follow` overrides `log.follow`) is retained as correct.

The patch addresses a long-standing gap in the documentation: `--no-follow` has existed since 2012 but was never documented. The series has undergone four iterations, incorporating maintainer feedback and resolving integration conflicts with the `mv/log-follow-mergy` topic. The final version is uncontroversial, well-scoped, and aligns with Git's documentation style. The thread is now conclusively closed with Junio's approval.
