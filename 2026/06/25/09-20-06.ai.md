This is **patch 8/11 in Patrick Steinhardt’s v6 refactoring series** for Git’s reference backend, targeting the **files backend’s lazy-loading of write-critical configuration**. The patch resolves a **chicken-and-egg initialization problem** where parsing `core.preferSymlinkRefs` and `core.logAllRefUpdates` during ref store setup could trigger recursive access to the ref store itself (e.g., via `includeif.onbranch` conditions).

### What the patch does
The files backend now **defers parsing write-related config** until the first write operation. Key changes:
- Introduces a new `files_ref_store_write_options` struct to hold deferred config (`log_all_ref_updates`, `prefer_symlink_refs`), with an `initialized` flag to track lazy-loading state.
- Adds `files_ref_store_write_options()`, an accessor that parses and caches write options on first use.
- Updates `log_ref_setup()` and `files_transaction_finish()` to use the lazy-loaded options instead of reading them during initialization.
- The config parsing callback (`files_ref_store_config`) now operates on the deferred struct rather than the ref store itself.

### Why this matters
This is the **core fix** for the "onbranch" recursion issue flagged by Jeff King (Peff) in earlier iterations. By deferring write-config parsing, the ref store can initialize without accessing the config system, breaking the cycle. The change is **minimal and targeted**: read operations remain unaffected, and write operations transparently parse config when needed.

### Test coverage
The patch adds a new test (`core.preferSymlinkRefs can be set up via onbranch condition`) that verifies the fix works with `includeif.onbranch`. The test creates a symlink ref after setting `core.preferSymlinkRefs` via an "onbranch" include, confirming the deferred config is applied correctly.

### Technical context
This patch is **mechanically straightforward** but critical to the series’ goal. It complements:
- **Patch 7/11**: Moves `core.logAllRefUpdates` parsing back into the backend (reversing a prior refactoring).
- **Patches 9–10/11**: Apply the same lazy-loading pattern to the reftable backend.
- **Patch 11/11**: Adds a recursion guard to `get_main_ref_store()` as a safeguard.

The changes are **low-risk** for users (no behavior changes unless "onbranch" is used) but **high-impact** for developers working on ref backends or config system interactions. The patch touches only the files backend, leaving the packed backend and reftable backend changes to later patches.
