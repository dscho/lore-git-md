This thread is about a patch from Grayson Tinker that relaxes Git’s SSH signature verification to show basic signature details (key, fingerprint, validity) even when `gpg.ssh.allowedSignersFile` is not configured. The goal is to let users inspect signatures without setting up automated principal validation, which currently blocks any signature output.

Junio C Hamano has reviewed the patch and raised a usability concern: the patch emits an unconditional advice message ("Configure gpg.ssh.allowedSignersFile...") for every SSH-signed commit when the allowed signers file is unset. In commands like `git log --show-signature -100`, this would spam 100 identical messages, creating noise without value. The message also bypasses Git’s standard `advise_if_enabled()` mechanism, leaving users no way to suppress it. Junio questions whether users commonly inspect signatures without the allowed signers file configured, noting that while cryptographic verification alone (without principal validation) still has value, the repeated advice could be disruptive for those who rely on it. The review is substantive but leaves the trade-off open for the author to address.

The patch remains under review with no objections or requests for technical changes yet. The author has not responded to Junio’s feedback. Key details: the patch touches `gpg-interface.c`, adds a "novalidate" fallback mode, and changes output to show signature details, but lacks test coverage or documentation updates. The thread is now waiting for the author’s response on whether to adjust the advice mechanism.
