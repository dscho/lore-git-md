This is the first patch in Patrick Steinhardt’s v3 series refactoring Git’s connectivity checks to generalize promisor object handling. It is a preparatory refactoring that extracts pack-exclusion logic into a new helper function, `should_exclude_pack()`, without changing behavior. The patch touches only `odb/source-packed.c` and is a straightforward code reorganization to enable the next patch, which lifts the restriction on passing flags alongside object prefixes in `odb_for_each_object()`.

The new `should_exclude_pack()` function consolidates four separate flag checks (local-only, promisor-only, skip in-core kept packs, skip on-disk kept packs) into a single conditional block. This makes the logic more maintainable and reusable, particularly for the upcoming changes in Patch 2 that allow `odb_for_each_object()` to accept flags even when an object prefix is specified. The function is called in the main iteration loop, replacing the inline flag checks that previously skipped packs based on the caller’s flags.

No functional changes or new behavior are introduced; the patch is purely mechanical. Junio’s v1 review described it as "quite straight-forward," but did not engage with whether the extracted logic handles all flag combinations robustly or whether edge cases (e.g., interactions between flags) are covered. The patch remains unchanged in v3, suggesting the author and reviewers consider it uncontroversial.

This patch is a necessary building block for the series’ goal of making connectivity checks backend-agnostic. It does not yet enable any new functionality, but it sets the stage for the more substantive changes in Patch 2. Reviewers focused on the ODB abstraction effort (e.g., Justin Tobler, Taylor Blau) may still scrutinize whether `should_exclude_pack()` is future-proof as new flags or pack attributes are introduced, but the patch itself is unlikely to generate significant discussion. The real technical debate will center on the later patches, which introduce the generalized promisor object search.
