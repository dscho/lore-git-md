This is a bugfix patch targeting Git's GPG/SSH signature verification subsystem.

The patch addresses a user-facing annoyance: when `gpg.ssh.allowedSignersFile` is not configured, Git currently errors out during signature verification (e.g., when using `git show --show-signature` or `git log --show-signature`), preventing the user from seeing the SSH signature details at all. The error message forces users to create and configure the file even if they only want to inspect the signature's key and validity without automated principal matching.

The fix changes the logic in `gpg-interface.c` so that the allowed signers file is only required for *automatic principal validation*. If the file is missing, Git now falls back to a "novalidate" mode, showing the signature information (key type, fingerprint, and "Good" or "Bad" status) while printing a hint advising the user to configure the file for full validation. The patch touches only `gpg-interface.c` and adds a new include for `advice.h` to emit the hint.

The commit message includes clear before/after examples demonstrating the improved output. The change is minimal and focused, with no test updates or documentation changes. The motivation is straightforward: users should not be blocked from seeing signature details just because they haven't configured an optional validation file. This aligns with the principle of progressive enhancement—basic functionality remains available while advanced features require configuration.
