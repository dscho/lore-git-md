This is the first patch in a two-part refactoring series that advances Git's ongoing libification effort. The goal here is to encapsulate the lazy-loading logic for the global `excludes_file` variable, which tracks the path to the global ignore file (`core.excludesfile`), into a dedicated getter function.

The patch introduces `repo_excludes_file()` in `environment.c`, which checks if `excludes_file` is NULL and, if so, assigns it the XDG default path (`$XDG_CONFIG_HOME/git/ignore`). This logic was previously embedded directly in `setup_standard_excludes()` in `dir.c`, where it ran unconditionally. The new getter abstracts this behavior, making it reusable and preparing the ground for the next patch, which will move `excludes_file` into `struct repo_config_values`.

The changes are minimal and mechanical: the patch touches only three files (`dir.c`, `environment.c`, and `environment.h`), replacing two lines of direct logic with a function call. The commit message is clear and ties the work to the broader libification effort, which aims to eliminate globals and improve modularity. The mentorship by Christian Couder, Ayush Chandekar, and Olamide Caleb Bello suggests this is part of a structured onboarding effort, likely for a newer contributor.

This patch doesn’t change behavior or introduce new memory management responsibilities—that comes in the second patch—but it’s a necessary step to make the subsequent migration safe. The series as a whole looks uncontroversial and well-scoped, targeting a specific global variable with a pattern that’s been used before in similar libification work. If you’re following the libification effort, this is a small but meaningful step forward.
