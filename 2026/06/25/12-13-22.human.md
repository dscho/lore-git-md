This is the fourteenth and final iteration of a security-focused feature series that adds `git cat-file --batch-command` support for querying remote object metadata without full downloads. The series is now ready for merging, addressing all prior review feedback including the two confirmed issues from v13: the memory management concern in the client implementation and the protocol compatibility regression in the refactoring.

The core implementation introduces a new `remote-object-info` command that lets clients safely request object sizes (and eventually other metadata) from servers supporting the object-info capability in protocol v2. This version completes the hardening work by implementing dynamic capability-based validation: the client now validates requested format placeholders against the server's advertised capabilities, closing a potential information-leak vector. The series also includes strict protocol v2 enforcement, input size limits to prevent denial-of-service, and comprehensive test coverage.

Notable improvements in v14 include: converting the numeric conversion helper to use `size_t` instead of `unsigned long` to match recent upstream changes, splitting the function-move patch into two commits for better clarity, reverting the unintentional protocol compatibility regression by restoring `GIT_HASH_SHA1_LEGACY` usage, removing unnecessary `static` declarations that could cause thread-safety concerns, and adding explanatory comments for safety-critical code paths. The series maintains backward compatibility while being forward-compatible for future metadata types like %(objecttype).

The implementation currently supports only objectsize end-to-end, with other fields like objecttype returning empty strings (matching `for-each-ref` behavior). The author notes this as a deliberate design choice that will be unified in a follow-up series once server-side support is added. The default format for remote-object-info is set to %(objectname) %(objectsize), with clear error messages when unsupported fields are requested.

All prior substantive reviews from Junio Hamano, Patrick Steinhardt, Karthik Nayak, and others have been addressed, with no outstanding objections. The series demonstrates careful attention to security, memory safety, and cross-platform correctness, making it a well-crafted contribution that looks ready for integration.
