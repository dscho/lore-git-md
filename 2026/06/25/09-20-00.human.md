This is the second patch in Patrick Steinhardt’s 11-part v6 series refactoring Git’s reference backend to implement lazy-loading of write-critical configuration. This specific patch is a **cleanup refactor** that eliminates redundant application of repository format settings during repository initialization.

The patch addresses a minor inefficiency in `setup.c`: the repository format (hash algorithm and ref storage format) is currently applied twice—once via `repository_format_configure()` and again via `apply_repository_format()`. The redundancy exists because `repository_format_configure()` is called *after* `apply_repository_format()`, forcing it to update both the `repository_format` struct *and* the `repository` struct to ensure consistency. By reordering the calls—configuring the format first, then applying it—Patrick removes the need for the second update, simplifying the code.

The change is **mechanical and uncontroversial**: it touches only `setup.c`, removes seven lines, and has no user-visible behavior change. It’s a preparatory step for the later patches in the series, which introduce the lazy-loading design for write configuration. The patch is well-motivated in the commit message, and the diff is straightforward.
