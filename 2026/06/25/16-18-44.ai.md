This is the first patch in a two-part refactoring series targeting the libification effort. It introduces `repo_excludes_file()`, a getter function that encapsulates the lazy-loading logic for the global `excludes_file` variable. Currently, `setup_standard_excludes()` in `dir.c` checks if `excludes_file` is NULL and, if so, assigns it the XDG default path. This patch moves that logic into `environment.c`, making the global variable's behavior more explicit and preparing it for migration into `struct repo_config_values` in the next patch.

The change is mechanical: the getter function replicates the existing NULL-check and XDG fallback, and `dir.c` now calls this function instead of directly accessing the global. The patch adds a TODO comment in `environment.h` acknowledging that the getter still relies on global state, which is the problem the series aims to solve. No behavioral changes are introduced, and the patch is uncontroversial as a preparatory step.

Files touched are `dir.c`, `environment.c`, and `environment.h`, with a net addition of 12 lines. The commit message is clear and ties the change to the broader libification goal. This patch is a straightforward refactoring with no known edge cases or open questions, and it follows established patterns for eliminating globals in the codebase.
