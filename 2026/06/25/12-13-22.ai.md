This is the fourteenth iteration of a security-focused feature series that adds `git cat-file --batch-command` support for querying remote object metadata without full downloads. The series is now ready for merging, addressing all prior review feedback including the two confirmed issues from v13: the unnecessary `static` declarations in `parse_cmd_remote_object_info()` and the protocol compatibility regression in `connect.c`.

The core implementation introduces a new `remote-object-info` command that lets clients request object sizes (and eventually other metadata) from servers supporting the object-info capability in protocol v2. The key security improvement remains dynamic capability-based validation: the client validates requested format placeholders against the server's advertised capabilities, preventing information leaks. This version also fixes a memory leak in `transport-helper.c` and improves error handling in numeric conversions.

Notable changes since v13 include:
- Replaced `strtoul_ul()` with `strtoul_szt()` to match the recent change of `object_info.sizep` to `size_t`
- Split the function move patch into two commits (cleanup + pure move) for better clarity
- Reverted the unintended `GIT_HASH_SHA1_LEGACY` substitution to preserve protocol compatibility
- Removed unnecessary `static` declarations in `cmd_remote_object_info()`
- Added an explanatory comment for the backward iteration in capability validation
- Fixed various typos and style issues

The series maintains backward compatibility while being forward-compatible for future metadata types. Currently only objectsize is supported end-to-end, with other fields like objecttype returning empty strings. The implementation includes comprehensive test coverage (new `t1017-cat-file-remote-object-info.sh`) and shared test infrastructure (`t/lib-cat-file.sh`).

All prior substantive reviews from Junio Hamano, Patrick Steinhardt, Karthik Nayak, and others have been addressed. The series demonstrates careful attention to security, memory safety, and protocol design, with no outstanding objections. The GitHub CI run shows all tests passing.
