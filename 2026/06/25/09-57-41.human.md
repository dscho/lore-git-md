This is the third patch in Patrick Steinhardt’s four-part series refactoring Git’s connectivity checks to remove hard dependencies on packfile internals, a key step in the ODB abstraction effort. The patch extracts the promisor-based connectivity logic from `check_connected()` into a new helper function, `check_connected_promisor()`, improving readability and maintainability.

The change is purely refactoring: no behavior is altered, and the logic remains identical. The new function encapsulates the promisor pack check, returning `1` if all new tips are found in promisor packs (indicating full connectivity), `0` if any tip is missing (triggering a fallback to the rev-list-based check), or a negative value on error. The extraction simplifies the control flow in `check_connected()` by replacing nested loops and gotos with a single function call, making the code easier to reason about and paving the way for further generalization in the next patch.

The commit message credits Christian Couder for suggesting the refactoring, reflecting the collaborative nature of the series. The patch is uncontroversial and directly supports the ODB abstraction goal, though reviewers may scrutinize whether the split sufficiently improves maintainability or if edge cases (e.g., error propagation) are handled correctly. The change is confined to `connected.c` and is a straightforward, well-motivated step toward backend-agnostic connectivity checks.
