This is the final patch in the GSoC v14 series implementing `git cat-file --batch-command` support for remote object metadata queries. It makes the format placeholder allow-list dynamic, enabling the client to adapt to servers with varying capabilities rather than hardcoding support for only "objectname" and "objectsize".

The patch replaces the static `remote_object_info_atoms` array with a `remote_allowed_atoms` string list in the `expand_data` struct. The client now maps requested placeholders (like "%(objectsize)") to protocol options ("size"), filters them against the server's advertised capabilities, and populates the allow-list only with supported placeholders. This ensures future extensibility—new metadata types (e.g., "type") can be added to the `remote_atom_map` without breaking compatibility with older servers.

Key changes include:
- Moving `object_info_options` out of `get_remote_info()` so callers can specify which metadata to request
- Adding logic to skip unsupported placeholders rather than failing (matching `for-each-ref` behavior)
- Introducing a `protocol_placeholder_entry` struct to map protocol options to placeholders
- Updating `expand_atom()` to check the dynamic allow-list
- Ensuring `batch_object_write()` always produces output, even if all placeholders are unsupported

The patch maintains backward compatibility while enabling forward compatibility for future metadata types. It includes explanatory comments for the backward iteration during capability filtering (to avoid skipping elements when removing unsupported options) and documents the mapping between protocol options and placeholders. The implementation is security-conscious, dynamically validating placeholders against server capabilities to prevent information leaks.
