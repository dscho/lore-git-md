This is a bugfix patch that plugs a memory leak in the transport helper subsystem. It is the first patch in the fourteenth iteration of Pablo Sabater's GSoC series implementing `git cat-file --batch-command` support for remote object metadata queries.

The leak occurs in `disconnect_helper()`: when a transport is disconnected before its helper process is fully started, the `data->name` string allocated in `transport_helper_init()` is never freed. The fix moves the `FREE_AND_NULL(data->name)` call outside the conditional block so it runs unconditionally on disconnect. The change is minimal (one line moved) and clearly correct.

This patch is part of a larger security-hardened feature series, but it stands alone as a straightforward correctness fix. The commit message references the specific leak scenario and links to the original discussion, making the motivation clear. No test is added here, but the fix is simple enough that it does not need one. The patch is uncontroversial and ready to merge.
