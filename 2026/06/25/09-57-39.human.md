This is the first patch in Patrick Steinhardt’s four-part v3 series refactoring Git’s connectivity checks to generalize promisor object handling. It is a preparatory refactoring that extracts pack-exclusion logic into a new helper function, `should_exclude_pack()`, without changing any behavior. The patch is part of the broader ODB abstraction effort, which aims to make Git’s object storage backend-agnostic.

The change is confined to `odb/source-packed.c` and moves the existing conditional logic for skipping packs (based on flags like `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` or `ODB_FOR_EACH_OBJECT_LOCAL_ONLY`) into a standalone function. This prepares the codebase for the next patch, which will lift the current restriction that prevents `odb_for_each_object()` from accepting flags when an object prefix is specified. The extracted logic is straightforward and mirrors the existing checks, so there are no functional changes or edge cases introduced here.

Junio’s review of the v1 version was brief, calling the patch "quite straight-forward," but did not engage with potential subtleties like whether all relevant flags are covered or how the helper might interact with future ODB backends. The patch remains unchanged in v3, suggesting it is uncontroversial. However, reviewers may still scrutinize whether `should_exclude_pack()` robustly handles all flag combinations, especially as the ODB abstraction evolves.

This patch is a small but necessary step toward the series’ goal of making connectivity checks backend-agnostic. It is well-explained and aligns with the project’s preference for incremental refactoring. The lack of test changes or user-facing impact makes it low-risk, but its value lies in enabling the more substantive changes in later patches.
