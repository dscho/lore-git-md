This is a bugfix patch targeting Git's GPG/SSH signature verification. It addresses an annoying usability regression: when a user hasn't configured `gpg.ssh.allowedSignersFile`, `git show --show-signature` (and similar commands) would previously fail with an error and suppress the signature information entirely. The patch changes the logic so that the signature is always displayed, with a hint suggesting configuration for full verification.

The change is small and focused: it moves the allowed-signers check from an early error return to a conditional branch later in the function. When the file isn't configured, Git now falls back to unvalidated signature display and shows a non-blocking advisory message. The commit message includes clear before/after examples that demonstrate the improvement.

This looks like a well-motivated fix for a real pain point. The patch is clean, the test coverage (though not shown here) would be straightforward to add, and the behavior change aligns with user expectations—people want to see signatures even if they haven't set up full verification yet.
