This is a bugfix patch from Pablo Sabater’s GSoC series implementing `git cat-file --batch-command` for remote object metadata queries. It fixes a memory leak in `transport-helper.c` where `data->name` (allocated during `transport_helper_init()`) was not being freed when disconnecting a transport whose helper had not fully started. The fix moves `FREE_AND_NULL(data->name)` outside the conditional block so it is always freed on disconnect, regardless of the helper’s state.

The patch is small (one line moved) and self-contained, with a clear commit message referencing the specific leak scenario. It addresses a correctness issue that could accumulate over repeated transport operations, though the leak is unlikely to be severe in typical usage. The change is part of the v14 iteration of the series, which has otherwise reached readiness for merging after addressing all prior review feedback.

This is a minor but necessary cleanup for the larger feature effort, and the fix itself is uncontroversial. No further discussion is expected.
