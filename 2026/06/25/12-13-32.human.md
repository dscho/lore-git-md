This is the core feature patch in a security-hardened series that adds client-side support for querying remote object metadata without downloading full objects. It introduces the `fetch_object_info()` function and integrates it into the transport layer, enabling `` `git cat-file --batch-command` `` to request object sizes from servers that advertise the `object-info` capability in protocol v2.

The patch implements the client logic for the `object-info` command, which sends a list of object IDs to the server and parses the response. It strictly enforces protocol v2 (failing for v0/v1) and validates that the server supports the required capability. The implementation follows the established pattern of buffering the entire request before sending, matching the approach used in `send_fetch_request()`. Currently only the "size" feature is supported, with other fields like "objecttype" returning empty strings.

Key integration points include:
- A new `fetch-object-info.c` source file with the core logic
- Transport layer hooks in `transport.c` and `transport-helper.c` that trigger the object-info flow when `transport->smart_options->object_info` is set
- State machine updates in `fetch-pack.c` to handle the new `FETCH_SEND_REQUEST` state
- Build system updates (Makefile and meson.build) to include the new source file

The patch maintains backward compatibility by failing cleanly if the server does not support the capability, and it includes proper error handling for malformed responses.
