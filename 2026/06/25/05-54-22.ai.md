This is the **fourth patch in Patrick Steinhardt’s v2 series** refactoring Git’s connectivity checks to generalize promisor object handling as part of the ODB abstraction effort. The email is a **reply to Junio C Hamano’s substantive review**, which identified a **logical inversion** in the patch’s control flow that would cause the connectivity check to incorrectly fall back to a full rev-list scan when a promisor object *is* found.

Patrick **acknowledges the inversion** and proposes an alternative implementation that avoids the issue by introducing a `found` boolean flag passed as the callback’s payload. The callback (`promised_object_cb`) now sets this flag to `true` when a promisor object is found, and the main function checks `if (!found)` to determine whether to fall back. This approach is functionally equivalent to Junio’s suggested fix (reversing the return values) but may be clearer to follow, as it separates the iteration result (`err`) from the object-found state (`found`).

The email also expresses concern that the inversion did not cause any test failures, suggesting that existing tests may not adequately cover promisor object scenarios. Patrick plans to investigate adding a test to catch similar regressions in the future. The proposed change is **mechanical and localized**, touching only `connected.c` and introducing no new dependencies or behavior changes beyond fixing the inversion.

This reply **resolves the immediate blocker** for the series, but the fix must be incorporated into a v3 before the patch can proceed. The broader design (using `odb_for_each_object_ext()` for generic ODB iteration) remains uncontested. Reviewers may focus on whether the new `found` flag approach improves maintainability or whether it introduces unnecessary indirection, but the change is unlikely to be controversial. The next step is for Patrick to send a v3 addressing the inversion and, optionally, adding a test.
