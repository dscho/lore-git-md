This is the second patch in Patrick Steinhardt’s 11-part v6 series refactoring Git’s reference backend infrastructure. It is a **refactoring patch** that eliminates redundant application of repository format settings during repository initialization.

The patch addresses a minor inefficiency in `setup.c` where the repository format (hash algorithm and ref storage format) is applied twice: once via `repository_format_configure()` and again via `apply_repository_format()`. The current flow requires both calls because `repository_format_configure()` is invoked *after* `apply_repository_format()`, meaning any changes it makes to the format struct would not propagate to the repository. The fix reorders the calls so that `repository_format_configure()` runs first, allowing `apply_repository_format()` to handle the final application. This removes the need for `repository_format_configure()` to directly update the repository, simplifying the code and avoiding redundant work.

The change is **mechanical and uncontroversial**, touching only `setup.c` and removing seven lines of code. It is a preparatory step for the series’ larger goal of implementing lazy-loading for write-critical configuration, though it does not directly advance that goal. The patch is **low-risk** and does not alter behavior; it merely streamlines the initialization sequence. No test failures or edge cases are expected, as the logic remains functionally identical.

This patch is part of the early, non-core portion of the series (patches 1–7/11), which focuses on cleanups and preparatory refactoring. The substantive lazy-loading changes begin in patch 8/11. Reviewers are unlikely to raise objections here, as the change is straightforward and aligns with the series’ broader goal of simplifying ref backend initialization. The patch’s value lies in reducing technical debt rather than introducing new functionality.
