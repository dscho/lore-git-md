This is the core client-side implementation patch for the `remote-object-info` command in `git cat-file --batch-command`, completing the feature series. It adds the final piece that lets users query object metadata (currently just size) from a remote repository without downloading the full objects, using the new protocol v2 `object-info` capability.

The patch introduces the `remote-object-info` command to the `--batch-command` interface, allowing users to request metadata for multiple objects in a single command (e.g., `remote-object-info <remote> <oid1> <oid2> ...`). This batching is a key optimization, reducing network overhead compared to the existing `info` command which processes one object at a time. The implementation handles both buffered and unbuffered modes, with special logic to defer remote requests until flush time in buffered mode to avoid repeated network round trips.

Key technical details include:
- Input validation enforces full OIDs (rejecting short OIDs for safety) and limits requests to 10,000 objects per command
- The command fails cleanly if the server doesn't advertise the `object-info` capability or if protocol v2 isn't supported
- Currently only the "size" field is supported; requests for unsupported fields like `objecttype` or `objectsize:disk` trigger errors
- The default format for `remote-object-info` is `%(objectname) %(objectsize)`, differing from the standard `%(objectname) %(objecttype) %(objectsize)` to reflect current limitations
- Memory management is handled carefully, with `free_object_info_contents()` cleaning up allocated fields in `struct object_info`

The patch includes comprehensive test coverage (680 lines in `t1017-cat-file-remote-object-info.sh`) verifying behavior across git://, file://, and http:// transports, with tests for edge cases like malformed OIDs, missing objects, and protocol version mismatches. The tests also confirm that objects aren't downloaded from the remote, only their metadata.

This is a well-crafted implementation that addresses the security and performance goals of the series. The command structure, input validation, and error handling all demonstrate careful attention to edge cases. The only current limitation is the lack of support for object types, which is clearly documented and will be addressed in future work. The patch is ready for merging as part of the v14 series.
