This is a refactoring patch preparing for a function move in the ongoing `git cat-file --batch-command` security series (GSoC v14, patch 5/13). The patch modifies `fetch-pack.c` to eliminate a static variable (`advertise_sid`) so that `write_fetch_command_and_capabilities()` can later be relocated to `connect.c` without carrying platform-specific state.

The change replaces the static `advertise_sid` with a local variable initialized via `repo_config_get_bool()`, a function already available in `connect.c`. The commit message explains why the existing static assignment in `do_fetch_pack()` (protocol v1 only) is irrelevant for the v2-only `write_fetch_command_and_capabilities()`. A minor type adjustment (`int` → `const unsigned int`) for `hash_algo` is included for consistency.

This is a pure preparatory step with no behavior change; the function’s logic remains identical. The patch is well-motivated by the series’ goal of reusing this function for future protocol v2 commands. Helped-by trailers credit Jonathan Tan and Christian Couder, and the patch carries sign-offs from Calvin Wan and Eric Ju, indicating broad review support. The change is mechanical and low-risk, touching only the function’s internal variable handling.
