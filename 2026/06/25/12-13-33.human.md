This is the penultimate patch in a security-hardened feature series that adds `git cat-file --batch-command` support for querying remote object metadata. Specifically, this patch introduces the `remote-object-info` command, which lets users fetch object sizes (and eventually other metadata) from a remote repository without downloading the full objects.

The implementation is careful about security and performance. The command accepts multiple object IDs in a single request to minimize network overhead, enforces strict input validation (rejecting short OIDs and malformed inputs), and only works with servers that explicitly advertise the `object-info` capability. Currently, only object sizes are supported; attempts to request other fields like object type or disk size will fail with a clear error message. The patch also includes comprehensive test coverage across all supported transports (git://, file://, http://) and modes (buffered, unbuffered, null-delimited).

This patch is part of a mature 14-iteration series that has addressed all prior review feedback, including memory safety fixes, protocol compatibility restorations, and documentation improvements. The implementation is now ready for merging, with no outstanding objections from maintainers. The test suite (new file `t/t1017-cat-file-remote-object-info.sh`) is particularly thorough, covering edge cases like missing objects, malformed OIDs, and protocol version mismatches.
