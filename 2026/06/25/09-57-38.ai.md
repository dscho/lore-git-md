This is the v3 iteration of Patrick Steinhardt’s four-patch series that refactors Git’s connectivity checks to search for promisor objects generically, removing a hard dependency on packfile internals. The series is a critical step in the ODB abstraction effort, enabling connectivity checks to work in repositories that do not use packfiles (e.g., reftable or custom backends).

The v3 update addresses all feedback from v2: the logical inversion in Patch 4 (where the connectivity check incorrectly fell back to a full rev-list scan when a promisor object *was* found) is fixed by introducing a `found` boolean flag in the callback payload, and the performance optimization in Patch 2 (reordering the prefix-matching check to avoid unnecessary pack preparation) is implemented. Additionally, a new test in `t/t5616-partial-clone.sh` verifies that the optimized promisor check is used when expected, closing a coverage gap Patrick noted in v2.

The series remains well-scoped and technically sound. Patch 1 extracts pack-exclusion logic into `should_exclude_pack()` without functional changes. Patch 2 enables `odb_for_each_object()` to accept flags alongside prefixes, delegating pack exclusion to the new helper and propagating pack open errors via a `pack_errors` flag. Patch 3 splits promisor-specific logic into `check_connected_promisor()`, improving maintainability. Patch 4 replaces `find_pack_entry_one()` with `odb_for_each_object_ext()` and the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag, using the `found` flag to track whether a promisor object was located. The changes are confined to `connected.c` and `odb/source-packed.c`, with no user-facing behavior changes or on-disk format modifications.

The new test in Patch 4 is a notable improvement, explicitly verifying that the optimized promisor check is used during partial fetches (where all tips are in promisor packs) and that the full rev-list connectivity check is triggered when any tip is not in a promisor pack. This addresses the earlier observation that the logical inversion did not cause test failures, suggesting inadequate coverage for promisor object scenarios.

The series is now ready for final review. The remaining open questions from v2—whether `should_exclude_pack()` handles all flag combinations robustly, whether the generic iteration logic in Patch 4 handles edge cases (e.g., error propagation, partial matches), and whether the fallback behavior is correct—should be resolved by the fixes in v3. Reviewers may still scrutinize the interaction between the new flags and future ODB backends, but the changes are uncontroversial and directly support the ODB abstraction goal. ODB-focused contributors (e.g., Justin Tobler, Taylor Blau) are likely to provide substantive feedback, while low-weight reviews (e.g., style) are not expected to carry significant weight.
