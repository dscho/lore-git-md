This is the fourth patch in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It targets the ODB transaction subsystem itself, specifically the `odb_transaction_commit()` function.

The patch fixes a silent failure mode: previously, `odb_transaction_commit()` ignored the return value of the backend’s commit callback, so backends like the "files" backend had no way to signal that committing failed (e.g., when migrating a temporary object directory into the permanent ODB). The change is mechanical: the commit callback’s signature is updated to return an `int` error code, and `odb_transaction_commit()` now propagates that error to its caller. The function also gains a return value (`int`) to surface failures.

This is a straightforward infrastructure fix with no user-facing behavior change. It prepares the ground for patch 5, where `git-receive-pack` will start relying on transaction commit errors to handle push failures gracefully. The diff is small (13 lines added, 4 removed) and touches only `odb/transaction.c` and `odb/transaction.h`. The change is uncontroversial and aligns with the series’ goal of making error handling explicit throughout the transaction lifecycle.

Key symbols modified: `odb_transaction_commit()` (now returns `int`), and the `commit` callback in `struct odb_transaction`. No new interfaces are introduced, and the patch does not affect test coverage. It is part of the broader ODB abstraction effort led by Patrick Steinhardt.
