This is the cover letter for a six-patch series from Patrick Steinhardt refactoring the `struct object_info` in Git’s object database (ODB) subsystem. The goal is to replace the `whence` field—a coarse indicator of the object’s source type—with a new `struct object_info_source` that carries both the source type and backend-specific data. This change enables callers to re-query the same backend for an object and, eventually, uniquely identify objects even when they appear in multiple sources (e.g., different packfiles).

The series touches 14 files, primarily in the ODB and packfile subsystems (`odb.h`, `odb.c`, `packfile.c`, `odb/source-*.c`), plus scattered callers in `builtin/cat-file.c`, `commit-graph.c`, `reachable.c`, and test helpers. Each patch builds on the previous: the first threads the new source struct through `packed_object_info()`, the next two make backend fields optional and add the `source` field, the fourth converts all `whence` users to the new field, the fifth drops `whence`, and the sixth documents the updated struct.

The motivation is clear: `whence` was insufficient for identifying specific sources, and the new design aligns all fields in `struct object_info` to a request-response style. The series is part of Patrick’s ongoing ODB abstraction effort, which aims to make Git’s object storage layer pluggable. It’s based on `ps/odb-source-packed` and targets the `master` branch.

No prior discussion or review feedback is visible in this email, so the series is likely in its first iteration. The changes are mechanical but foundational, setting the stage for future work like multi-source object resolution. If the ODB abstraction is a priority for the reader, this series is worth tracking.
