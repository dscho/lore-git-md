Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). All blocking feedback from v1–v3 is now addressed, including the final conversion in patch 11/11. Follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, flag-based behavioral preservation for `receive-pack`, explicit transaction lifecycle management, merging `odb/transaction.h` and `odb/source.h`, refactoring call sites that create and immediately commit transactions, and the redundant `tmp_objdir_env()` call in `update_shallow_ref()`) remains explicitly deferred. Two design-level items remain deferred:
- Header dependency concern in patch 9/11: Patrick Steinhardt questioned whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by `enum odb_transaction_flags`. Justin Tobler agrees the separation may complicate future ODB abstraction work and plans to explore merging the headers in a future series. No code changes made; the discussion remains at the design level.
- Explicit `odb_transaction_abort()` calls in error paths: Junio C Hamano raised whether explicit abort calls are warranted for clarity, consistency, or to handle non-file-based backends. Justin agrees the change would improve clarity but defers it to follow-up work, noting the current behavior (relying on `atexit()` cleanup) is functionally correct and matches the old `tmp_objdir` behavior. The resolution is now documented: the deferral is pragmatic, as the series is otherwise ready for integration and the explicit abort is not a blocker.

- **Safety concern in patch 6/11 (resolved)**: `odb_transaction_begin()` now returns an `int` error code (instead of a transaction pointer) and uses an `out` parameter for the transaction. The function employs a conditional assignment pattern (`if (!(ret = odb_source_begin_transaction(...))) odb->transaction = *out;`) to ensure the ODB’s internal state is updated only when the backend call succeeds. A convenience wrapper, `odb_transaction_begin_or_die()`, is introduced for call sites that cannot handle errors. All existing callers (e.g., `cache_tree_update()`, `add_files_to_cache()`) are updated to handle the new error-returning interface, including checks for an inflight transaction before starting a new one.
- **Error-handling gap in patch 8/11 (resolved)**: `odb_transaction_env()` now propagates the return value of `odb_transaction_files_prepare()`; if preparation fails, the function returns the error and avoids pushing the transaction’s object directory into the child process’s environment. The "files" backend’s `env` callback (`odb_transaction_files_env()`) is introduced to handle backend-specific environment setup, and the generic `odb_transaction_env()` function calls this callback, propagating any errors. The patch touches `object-file.c`, `odb/transaction.c`, and `odb/transaction.h`.
- **Latent transaction-leak in patch 7/11 (resolved)**: `odb_transaction_commit()` now returns `int` (error code) and propagates the backend commit callback’s return value. The function clears the ODB’s internal transaction pointer even on failure, fixing the leak. The backend commit callback (`transaction->commit`) is updated to return `int` to match. The patch touches `odb/transaction.c` (10 lines) and `odb/transaction.h` (7 lines), with no behavior changes beyond surfacing previously ignored errors.
- **Redundant validation in patch 4/11 (resolved)**: The "files" backend’s `odb_transaction_files_begin()` no longer checks for an existing transaction, as the generic ODB transaction layer already enforces this invariant. The change removes four lines from `object-file.c` and updates the function’s docstring in `object-file.h` to remove the "already pending" caveat. No behavior changes; the patch is purely mechanical and carries Patrick Steinhardt’s Reviewed-by.
- **Error propagation in patch 5/11 (resolved)**: The "files" backend’s transaction lifecycle functions (`odb_transaction_files_prepare`, `odb_transaction_files_begin`, `odb_transaction_files_commit`) now return `int` instead of `void`, surfacing previously ignored errors (e.g., temporary directory creation failures) to callers. The patch touches `object-file.c`, `object-file.h`, `odb/source-files.c`, and `odb/transaction.h`; no behavior changes are introduced. Uncontroversial and carries Patrick Steinhardt’s Reviewed-by from v3.
- **Flags parameter and `ODB_TRANSACTION_RECEIVE` in patch 9/11 (resolved)**: Introduces `enum odb_transaction_flags` and the `ODB_TRANSACTION_RECEIVE` flag to preserve receive-pack’s quarantine semantics (eager directory creation and "incoming" prefix) while maintaining ODB abstraction. The `flags` parameter is added to `odb_transaction_begin()`, `odb_source_begin_transaction()`, and `odb_transaction_files_begin()`, with all call sites updated to pass `0` except where the new flag is needed. The change is mechanical (13 files touched) and carries Patrick Steinhardt’s Reviewed-by from v3. The function previously populated the child process environment with the temporary object directory’s variables, but the directory had already been migrated (via `tmp_objdir_migrate()`) by the time this function was called, rendering the environment variables inert. The change deletes a single line in `builtin/receive-pack.c` and has no behavioral impact.

- New/modified interfaces (updates since v3):
  - `odb_transaction_begin()`: now returns `int` (error code) and uses an `out` parameter for the transaction. Guards the assignment to `odb->transaction` with a conditional pattern to ensure state is updated only on success. Introduces `odb_transaction_begin_or_die()` as a convenience wrapper for call sites that cannot handle errors. Now accepts a `flags` parameter (patch 9/11) to control backend-specific behavior (e.g., `ODB_TRANSACTION_RECEIVE`).
  - `odb_transaction_commit()`: now returns `int` (0 on success, negative on error) and propagates the backend commit callback’s return value. Clears the ODB’s internal transaction pointer even on failure.
  - `odb_transaction_env()`: generic interface that calls the backend-specific `env` callback (e.g., `odb_transaction_files_env()`). Propagates the return value of `odb_transaction_files_prepare()`; skips environment setup on failure. Introduced in patch 8/11.
  - `odb_transaction_files_env()`: backend-specific callback for the "files" ODB that prepares the transaction and pushes the staging directory’s environment variables (e.g., `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`) into a `strvec`. Returns `int` to propagate errors from `odb_transaction_files_prepare()`. Introduced in patch 8/11.
  - `odb_transaction_files_prepare()`: renamed from `prepare_loose_object_transaction()` (patch 1/11); now returns `int` (patch 5/11) to propagate errors (e.g., `tmp_objdir_create` failures). No functional changes beyond error propagation.
  - `odb_transaction_files_begin()`: renamed from `begin_loose_object_transaction()` (implied by prior patches); now returns `int` (patch 5/11) to propagate errors (e.g., transaction setup failures). The redundant validation check was removed in patch 4/11. Now accepts a `flags` parameter (patch 9/11) to control backend-specific behavior (e.g., `ODB_TRANSACTION_RECEIVE` triggers eager directory creation and "incoming" prefix).
  - `odb_transaction_files_commit()`: inlined `flush_loose_object_transaction()` (patch 3/11); now returns `int` (patch 5/11) to propagate errors (e.g., `tmp_objdir_migrate` failures). No functional changes beyond error propagation.
  - `odb_transaction_files_fsync()`: renamed from `fsync_loose_object_transaction()` (patch 2/11); no functional change, but the new name aligns with the "files" ODB transaction helper convention. The function’s conditional logic is restructured for clarity (explicit null-check at the top), but fsync semantics remain identical.
  - `enum odb_transaction_flags`: introduced in patch 9/11 to control backend-specific behavior. Currently defines `ODB_TRANSACTION_RECEIVE` (triggers eager directory creation and "incoming" prefix in the "files" backend).
  - `odb_source_begin_transaction()`: backend-agnostic interface that now accepts a `flags` parameter (patch 9/11) to pass flags to the backend-specific implementation (e.g., `odb_transaction_files_begin()`).
  - `update_shallow_ref()`: no longer calls `tmp_objdir_env()` (patch 10/11), as the temporary object directory has already been migrated by the time this function is called. The change is purely mechanical and has no behavioral impact.
  - `git-receive-pack` functions (`unpack`, `unpack_with_sideband`, `execute_commands`, `set_connectivity_errors`, `run_receive_hook`): updated in patch 11/11 to accept a `struct odb_transaction *` parameter and use ODB transaction interfaces (`odb_transaction_begin`, `odb_transaction_env`, `odb_transaction_commit`) instead of `tmp_objdir`. The `ODB_TRANSACTION_RECEIVE` flag ensures quarantine semantics are preserved.
