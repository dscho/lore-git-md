Thread identity
Subject: [PATCH 0/6] receive-pack: use ODB transactions instead of tmp_objdir
Series version: v1 (initial submission, now complete)
Originating author: Justin Tobler
Thread type: patch series (infrastructure refactoring)

Core problem or goal
Replace direct use of `tmp_objdir` interfaces in `git-receive-pack` with the newer `odb_transaction` subsystem, moving the command toward ODB-backend agnosticism. The series stages incoming objects via transactions rather than temporary object directories, though actual object writes remain tied to the "files" backend (via `git-index-pack` and `git-unpack-objects`). A follow-up series is planned to make the object writes themselves backend-agnostic.

Current status
Complete v1 submission (all six patches posted). Patches 1–5 are uncontroversial infrastructure changes that surface previously silent failures in the ODB transaction layer and prepare for backend-agnostic object writes. Patch 6 (new) replaces `tmp_objdir` calls in `builtin/receive-pack.c` with `odb_transaction` interfaces, introducing the `ODB_TRANSACTION_RECEIVE` flag to preserve `receive-pack`'s eager directory creation and "incoming" prefix naming. No reviews yet.

Key technical details
- Files touched: 44 total across the series (30 previously + 14 in patch 6: `builtin/receive-pack.c`, `object-file.c`, `odb/transaction.c`, `odb/transaction.h`, and others).
- New/modified interfaces: `odb_transaction_begin()` now takes an `enum odb_transaction_flags` parameter; `odb_transaction_env()` replaces `tmp_objdir_env()`; `odb_transaction_files_prepare()` (renamed from `prepare_loose_object_transaction`); `odb_transaction_begin_or_die()` (convenience wrapper); `odb_transaction_commit()` (returns `int`). The `odb_transaction_files` backend gains a `prefix` field to support "incoming" vs. "bulk-fsync" distinction.
- Subsystems: `receive-pack`, ODB transaction layer, object-file management, and callers of the transaction API (`add`, `unpack-objects`, `update-index`, `cache-tree`, `read-cache`).
- Behavior: no user-facing changes; purely internal refactoring. Error handling is now explicit: previously silent failures in transaction setup, commit, abort, or environment access are propagated. The `ODB_TRANSACTION_RECEIVE` flag ensures `receive-pack`'s eager directory creation and "incoming" prefix are preserved.
- Symbols: `prepare_loose_object_transaction` -> `odb_transaction_files_prepare`; `odb_transaction_begin()` signature changed to `int odb_transaction_begin(struct odb_transaction **out, enum odb_transaction_flags flags)`; `odb_transaction_commit()` now returns `int`; `odb_transaction_begin_or_die()` added; `odb_transaction_env()` added; `ODB_TRANSACTION_RECEIVE` flag introduced.
- Test coverage: not mentioned; likely unchanged. Correctness depends on existing test suite exercising `receive-pack` and its child processes.
