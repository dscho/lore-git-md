Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). A follow-up series is planned to make object writes themselves backend-agnostic.

- New/modified interfaces:
  - `odb_transaction_begin()`: now takes an `enum odb_transaction_flags` parameter and returns `int`; disallows `NULL` output on success (callers must check for active transaction before calling).
  - `odb_transaction_env()`: redesigned to take a `struct strvec` as input and return `int` for error propagation.
  - `odb_transaction_files_prepare()`: renamed from `prepare_loose_object_transaction`; returns `int` but callers ignore it for backward compatibility.
  - `odb_transaction_begin_or_die()`: convenience wrapper for safe transaction initiation.
  - `odb_transaction_commit()`: returns `int`; `NULL` transaction is a no-op returning success (`0`).
  - `odb_transaction_files_flush()`: renamed from `flush_loose_object_transaction`; propagates migration failures.
  - `ODB_TRANSACTION_RECEIVE` flag: introduced to preserve `receive-pack`'s eager directory creation and "incoming" prefix naming; documented in `odb/transaction.h` in v2.
  - `odb_source_packed_begin_transaction()`: updated to accept `enum odb_transaction_flags` (merge fix).
- Subsystems: `receive-pack`, ODB transaction layer, object-file management, packed ODB backend, reftable unit tests, and callers of the transaction API (`add`, `unpack-objects`, `update-index`, `cache-tree`, `read-cache`).
- Behavior:
