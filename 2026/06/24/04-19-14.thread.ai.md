Thread type: patch series (infrastructure refactoring, ODB abstraction)

Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). **All blocking feedback from v1 is addressed**; follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, **redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, and flag-based behavioral preservation for `receive-pack`**) is explicitly deferred to maintain focus. **One open item remains**:
- **Header dependency concern in patch 9/11**: Patrick Steinhardt questions whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by `enum odb_transaction_flags`. The patch is correct but may complicate future ODB abstraction work.

Current status

All v1 feedback has been incorporated, including:
- **Patch 2/11**: renames `fsync_loose_object_transaction()` to `odb_transaction_files_fsync()` for naming consistency and reorders conditional logic for clarity. **No behavioral change**; purely mechanical refactoring. **Reviewed-by Patrick Steinhardt (subsystem owner)** with explicit acceptance of the minor duplication introduced by the conditional reordering.
- **Patch 3/11**: eliminates `flush_loose_object_transaction()` by inlining its hardware-flush (`fsync`) and directory-migration (`tmp_objdir_migrate`) logic directly into `odb_transaction_files_commit()`. **No behavioral change**; reduces indirection in the transaction lifecycle. **Motivation clarified**: the helper was eliminated because its name was misleading—it performs both hardware flushing *and* object migration, which conceptually belongs in the commit phase. The rename was initially planned for consistency, but embedding the logic directly into `odb_transaction_files_commit()` better reflects its role in the transaction lifecycle. **Commit message will be updated for clarity**; no code changes required.
- **Patch 4/11**: removes redundant validation in `odb_transaction_files_begin()` (the generic `odb_transaction_begin()` layer already enforces the "only one transaction per ODB" rule). **No behavioral change**; mechanical simplification. **Reviewed-by Patrick Steinhardt**, who explicitly endorses the change as fixing a layering violation: the "files" backend should not duplicate ODB-layer state management.
- **Patch 5/11**: converts `odb_transaction_files_prepare()`, `odb_transaction_files_begin()`, and `odb_transaction_files_commit()` from `void` to `int` return types, propagating previously ignored errors to callers. **Usability gap resolved**: Justin Tobler added error logging for `tmp_objdir_create()` and `tmp_objdir_migrate()` failures in response to Patrick Steinhardt’s feedback. **No behavioral change**; error-propagation improvement now includes actionable error messages. **Reviewed-by Patrick Steinhardt** (implied by resolution of feedback).
- **Patch 6/11**: refactors `odb_transaction_begin()` to return an error code and write the transaction into an out-parameter, replacing the old behavior of returning the transaction pointer directly. Adds a convenience wrapper `odb_transaction_begin_or_die()` for call sites that don’t need explicit error handling. **No behavioral change**; purely mechanical error-propagation improvement. **Reviewed-by Patrick Steinhardt**, who calls the change "very much welcome" and notes it results in "much saner behaviour with less surprises." Minor style nit (including `git-compat-util.h` in a header file) flagged but accepted as-is. Design observation: some call sites (e.g., `cache_tree_update`) create and immediately commit transactions, which may warrant future revisiting.
- **Patch 7/11**: modifies `odb_transaction_commit()` and its backend callback to return an `int` error code instead of `void`, enabling backends to signal commit failures. **Latent issue**: the function frees the transaction *before* returning any backend error, so a failing commit leaks the transaction object. The leak predates this series (it existed in the old `void` version) but becomes more visible with the error-return conversion. **Not a blocker**; Patrick explicitly says the issue can be deferred. **No behavioral change**; purely mechanical error-propagation improvement.
- **Patch 8/11**: introduces `odb_transaction_env()` and its "files" backend implementation, allowing child processes (e.g., `git-index-pack`, `git-unpack-objects`) to inherit the transaction’s staging area via environment variables. **No behavioral change**; purely plumbing. Touches `object-file.c`, `odb/transaction.c`, and `odb/transaction.h`.
- **Patch 9/11**: adds `enum odb_transaction_flags` and the `ODB_TRANSACTION_RECEIVE` flag to preserve `git-receive-pack`’s existing object-directory behavior (eager directory creation, "incoming" prefix) during the transition. The flag is documented as a temporary measure to maintain compatibility while the refactoring is in progress. **Header dependency concern**: Patrick Steinhardt questions whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by the enum. The patch is correct but may complicate future ODB abstraction work. **No behavioral change**; purely plumbing for future conversion.
- **Patch 10/11**: removes a redundant call to `tmp_objdir_env()` in `update_shallow_ref()` in `builtin/receive-pack.c`. The call is unnecessary because `tmp_objdir_migrate()` has already moved the temporary objects into the main object store by the time `update_shallow_ref()` runs, so there is no temporary directory left for child processes to see. **No behavioral change**; purely mechanical cleanup of dead code. **Reviewed-by Patrick Steinhardt**, who confirms the redundancy by tracing the call chain (`update_shallow_ref()` is only invoked after `tmp_objdir_migrate()`).
- **Patch 11/11**: replaces direct `tmp_objdir` usage in `builtin/receive-pack.c` with `odb_transaction` interfaces. The global `tmp_objdir` variable is removed, and a local `struct odb_transaction *` is created at the start of the unpack phase (`odb_transaction_begin` with the `ODB_TRANSACTION_RECEIVE` flag) and committed just before reference updates (`odb_transaction_commit`). The temporary directory is no longer added as an alternate; instead, the transaction’s object directory becomes the primary ODB in the main process, preserving quarantine semantics. **Behavioral change is non-regressive**: objects are staged in an "incoming" directory and migrated to the main object store only after pre-receive hooks and connectivity checks pass, matching the existing behavior. Error handling is consistent with the rest of the series: failures during transaction begin or commit are surfaced as command errors.
Retains all prior v2 changes (patches 1–2/11: naming consistency; error-handling semantics, file-local global, deferred improvements).
**Architectural limitation documented**: only one ODB transaction can exist per ODB (due to global `tmp_objdir` and `atexit()` cleanup); targeted for future refactoring.
**Queued for `next`** pending integration and resolution of the header dependency concern in patch 9/11. No objections to goals or approach.
