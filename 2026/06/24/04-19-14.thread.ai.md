Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). All blocking feedback from v1–v3 is now addressed, including the final conversion in patch 11/11. Follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, flag-based behavioral preservation for `receive-pack`, explicit transaction lifecycle management, merging `odb/transaction.h` and `odb/source.h`, refactoring call sites that create and immediately commit transactions, and the redundant `tmp_objdir_env()` call in `update_shallow_ref()`) remains explicitly deferred. - Header dependency concern in patch 9/11: Patrick Steinhardt questioned whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by `enum odb_transaction_flags`. No code changes made; the discussion remains at the design level.

- New/modified interfaces (updates since v3):
  - `odb_transaction_begin()`: Returns `int` (error code) and uses an `out` parameter for the transaction. Guards the assignment to `odb->transaction` with a conditional pattern to ensure state is updated only on success. Introduces `odb_transaction_begin_or_die()` as a convenience wrapper for call sites that cannot handle errors. Accepts a `flags` parameter (patch 9/11) to control backend-specific behavior (e.g., `ODB_TRANSACTION_RECEIVE`).
  - `odb_transaction_commit()`: Returns `int` (0 on success, negative on error) and propagates the backend commit callback’s return value. Clears the ODB’s internal transaction pointer even on failure.
  - `odb_transaction_env()`: Generic interface that calls the backend-specific `env` callback (e.g., `odb_transaction_files_env()`). Propagates the return value of `odb_transaction_files_prepare()`; skips environment setup on failure.
  - `odb_transaction_files_env()`: Backend-specific callback for the "files" ODB that prepares the transaction and pushes the staging directory’s environment variables into a `strvec`. Returns `int` to propagate errors from `odb_transaction_files_prepare()`.
  - `odb_transaction_files_prepare()`: Renamed from `prepare_loose_object_transaction()`; returns `int` to propagate errors (e.g., `tmp_objdir_create` failures).
  - `odb_transaction_files_begin()`: Renamed from `begin_loose_object_transaction()`; returns `int` to propagate errors. Removed redundant validation check (patch 4/11). Accepts a `flags` parameter (patch 9/11) to control backend-specific behavior (e.g., `ODB_TRANSACTION_RECEIVE` triggers eager directory creation and "incoming" prefix).
  - `odb_transaction_files_commit()`: Inlined `flush_loose_object_transaction()`; returns `int` to propagate errors (e.g., `tmp_objdir_migrate` failures).
  - `odb_transaction_files_fsync()`: Renamed from `fsync_loose_object_transaction()`; no functional change, but the new name aligns with the "files" ODB transaction helper convention.
  - `enum odb_transaction_flags`: Introduced in patch 9/11 to control backend-specific behavior. Currently defines `ODB_TRANSACTION_RECEIVE` (triggers eager directory creation and "incoming" prefix in the "files" backend).
  - `odb_source_begin_transaction()`: Backend-agnostic interface that accepts a `flags` parameter to pass flags to the backend-specific implementation.
  - `update_shallow_ref()`: No longer calls `tmp_objdir_env()` (patch 10/11), as the temporary object directory has already been migrated.
  - `git-receive-pack` functions (`unpack`, `unpack_with_sideband`, `execute_commands`, `set_connectivity_errors`, `run_receive_hook`): Updated in patch 11/11 to accept a `struct odb_transaction *` parameter and use ODB transaction interfaces.
