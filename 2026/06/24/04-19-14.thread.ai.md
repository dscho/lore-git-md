Thread identity
Subject: [PATCH 0/6] receive-pack: use ODB transactions instead of tmp_objdir
Series version: v1 (initial submission)
Originating author: Justin Tobler
Thread type: patch series (infrastructure refactoring)

Core problem or goal
Replace direct use of `tmp_objdir` interfaces in `git-receive-pack` with the newer `odb_transaction` subsystem, moving the command toward ODB-backend agnosticism. The series stages incoming objects via transactions rather than temporary object directories, though actual object writes remain tied to the "files" backend (via `git-index-pack` and `git-unpack-objects`). A follow-up series is planned to make the object writes themselves backend-agnostic.

Current status
Initial submission (v1). Patches 1–4 posted: patch 1 (mechanical rename of `prepare_loose_object_transaction` to `odb_transaction_files_prepare`), patch 2 (error propagation in the "files" transaction backend), patch 3 (error propagation in `odb_transaction_begin`), and patch 4 (error propagation in `odb_transaction_commit`). No reviews yet. All four patches are uncontroversial infrastructure changes that surface previously silent failures in the ODB transaction layer.

Key technical details
- Files touched: 27 total across the series so far (17 previously + 10 in patch 4: `odb/transaction.c`, `odb/transaction.h`).
- New/modified interfaces: `odb_transaction_begin()` (now returns `int` and writes the transaction pointer to an out-parameter), `odb_transaction_begin_or_die()` (convenience wrapper), `odb_transaction_files_prepare()` (renamed from `prepare_loose_object_transaction`), and `odb_transaction_commit()` (now returns `int`). All transaction callbacks (`prepare`, `commit`, `abort`) now return `int` to propagate errors.
- Subsystems: `receive-pack`, ODB transaction layer, object-file management, and callers of the transaction API (`add`, `unpack-objects`, `update-index`, `cache-tree`, `read-cache`).
- Behavior: no user-facing changes; purely internal refactoring. Error handling is now explicit: previously silent failures in transaction setup, commit, or abort are propagated.
- Symbols: `prepare_loose_object_transaction` -> `odb_transaction_files_prepare`; `odb_transaction_begin()` signature changed to `int odb_transaction_begin(struct odb_transaction **out)`; `odb_transaction_commit()` now returns `int`; `odb_transaction_begin_or_die()` added.
- Test coverage: not mentioned; likely unchanged.
