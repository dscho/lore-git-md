Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). All blocking feedback from v1–v3 is now addressed; follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, flag-based behavioral preservation for `receive-pack`, and the header dependency concern) remains explicitly deferred. Two design-level items remain deferred:
- Header dependency concern in patch 9/11: Patrick Steinhardt questioned whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by `enum odb_transaction_flags`. Justin Tobler agrees the separation may complicate future ODB abstraction work and plans to explore merging the headers in a future series. No code changes made; the discussion remains at the design level.
- Explicit `odb_transaction_abort()` calls in error paths: Junio C Hamano raised whether explicit abort calls are warranted for clarity, consistency, or to handle non-file-based backends. Justin agrees the change would improve clarity but defers it to follow-up work, noting the current behavior (relying on `atexit()` cleanup) is functionally correct and matches the old `tmp_objdir` behavior.

Current status
v4 posted (11 patches, 11/11 reviewed and integrated). All prior feedback addressed:
- **Safety concern in patch 6/11 (resolved)**: `odb_transaction_begin()` now returns an `int` error code (instead of a transaction pointer) and uses an `out` parameter for the transaction. The function employs a conditional assignment pattern (`if (!(ret = odb_source_begin_transaction(...))) odb->transaction = *out;`) to ensure the ODB’s internal state is updated only when the backend call succeeds. A convenience wrapper, `odb_transaction_begin_or_die()`, is introduced for call sites that cannot handle errors. All existing callers (e.g., `cache_tree_update()`, `add_files_to_cache()`) are updated to handle the new error-returning interface, including checks for an inflight transaction before starting a new one.
- **Error-handling gap in patch 8/11 (resolved)**: `odb_transaction_env()` now propagates the return value of `odb_transaction_files_prepare()`; if preparation fails, the function returns the error and avoids pushing the transaction’s object directory into the child process’s environment.
- **Latent transaction-leak in patch 7/11 (resolved)**: `odb_transaction_commit()` now clears the transaction even on failure, fixing the leak. The fix is uncontroversial and aligns with Patrick Steinhardt’s suggestion to introduce `odb_transaction_release()` in future work.
- **Redundant validation in patch 4/11 (resolved)**: The "files" backend’s `odb_transaction_files_begin()` no longer checks for an existing transaction, as the generic ODB transaction layer already enforces this invariant. The change removes four lines from `object-file.c` and updates the function’s docstring in `object-file.h` to remove the "already pending" caveat. No behavior changes; the patch is purely mechanical and carries Patrick Steinhardt’s Reviewed-by.
- **Error propagation in patch 5/11 (resolved)**: The "files" backend’s transaction lifecycle functions (`odb_transaction_files_prepare`, `odb_transaction_files_begin`, `odb_transaction_files_commit`) now return `int` instead of `void`, surfacing previously ignored errors (e.g., temporary directory creation failures) to callers. The patch touches `object-file.c`, `object-file.h`, `odb/source-files.c`, and `odb/transaction.h`; no behavior changes are introduced. Uncontroversial and carries Patrick Steinhardt’s Reviewed-by from v3.
- **Patch 1/11**: Pure refactoring that renames `prepare_loose_object_transaction()` to `odb_transaction_files_prepare()` to reflect its expanded role (supporting both loose objects and packfiles in future patches). Mechanical change (three call sites in `object-file.c`), no behavior change, uncontroversial, and carries Patrick Steinhardt’s Reviewed-by from v3.
- **Patch 2/11**: Mechanical refactoring that renames `fsync_loose_object_transaction()` to `odb_transaction_files_fsync()` to align with the naming convention of other "files" ODB transaction helpers. The patch restructures the conditional logic for clarity, moving the null-check for `transaction` and `transaction->objdir` to the top of the function. No behavior changes; fsync semantics (writeout-only vs full hardware flush) remain identical. Uncontroversial, carries Patrick Steinhardt’s Reviewed-by from v3, and touches only `object-file.c` (16 lines changed).
- **Patch 3/11**: Mechanical refactoring that inlines `flush_loose_object_transaction()` into `odb_transaction_files_commit()`. The same hardware-flush and object-directory-migration logic is preserved, but the standalone helper is eliminated to prepare for future patches that will extend transactions to handle packfiles (not just loose objects). The patch touches only `object-file.c` (64 lines changed) and carries Patrick Steinhardt’s Reviewed-by from v3. No behavior changes.
