Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). All blocking feedback from v1–v3 is now addressed; follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, flag-based behavioral preservation for `receive-pack`, and the header dependency concern) remains explicitly deferred. Two design-level items remain deferred:
- Header dependency concern in patch 9/11: Patrick Steinhardt questioned whether splitting `odb/transaction.h` from `odb/source.h` is worthwhile, given the tight coupling introduced by `enum odb_transaction_flags`. Justin Tobler agrees the separation may complicate future ODB abstraction work and plans to explore merging the headers in a future series. No code changes made; the discussion remains at the design level.
- Explicit `odb_transaction_abort()` calls in error paths: Junio C Hamano raised whether explicit abort calls are warranted for clarity, consistency, or to handle non-file-based backends. Justin agrees the change would improve clarity but defers it to follow-up work, noting the current behavior (relying on `atexit()` cleanup) is functionally correct and matches the old `tmp_objdir` behavior.
