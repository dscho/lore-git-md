Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). A follow-up series is planned to make object writes themselves backend-agnostic.

Current status
Complete v1 submission (all six patches posted and reviewed). **Patches 1–5/6** prepare the ODB transaction layer for backend-agnostic use by surfacing previously silent failures, introducing new interfaces, and addressing correctness issues. **Patch 6/6** replaces `tmp_objdir` calls in `builtin/receive-pack.c` with `odb_transaction` interfaces, introducing the `ODB_TRANSACTION_RECEIVE` flag to preserve `receive-pack`'s eager directory creation and "incoming" prefix naming. **All patches have received substantive technical review from Patrick Steinhardt**, identifying:

Patrick’s overall assessment is positive ("a pleasant read") and endorses the series’ direction, but a v2 is required to address the feedback. No objections to the series’ goals or approach.

Key technical details
- Files touched: 44 total across the series (`builtin/receive-pack.c`, `object-file.c`, `odb/transaction.c`, `odb/transaction.h`, and others).
- New/modified interfaces:
  - `odb_transaction_begin()`: now takes an `enum odb_transaction_flags` parameter and returns `int`; can return success (`0`) with `out` as `NULL` if a transaction is already active (correctness issue in patch 3/6).
  - `odb_transaction_env()`: replaces `tmp_objdir_env()` to expose transaction-specific environment variables to child processes.
  - `odb_transaction_files_prepare()`: renamed from `prepare_loose_object_transaction`.
  - `odb_transaction_begin_or_die()`: convenience wrapper that does not handle the `NULL`-transaction case (blocking issue in patch 3/6).
  - `odb_transaction_commit()`: now returns `int` to propagate backend commit errors.
  - `ODB_TRANSACTION_RECEIVE` flag: introduced to preserve `receive-pack`'s eager directory creation and "incoming" prefix naming; purpose undocumented in the header (issue in patch 6/6).
- Subsystems: `receive-pack`, ODB transaction layer, object-file management, and callers of the transaction API (`add`, `unpack-objects`, `update-index`, `cache-tree`, `read-cache`).
- Behavior:
  - Patches 1–5/6: no user-facing changes; purely internal refactoring with explicit error handling.
  - Patch 6/6: changes alternate handling by no longer adding the transaction’s object directory as an alternate (previously done via `tmp_objdir_add_as_alternate`), only propagating it via environment variables. This undocumented change could affect child processes (e.g., `git-index-pack`).
  - Error handling: previously silent failures in transaction setup, commit, abort, or environment access are now propagated.
- Symbols:
  - `prepare_loose_object_transaction` -> `odb_transaction_files_prepare`.
  - `odb_transaction_begin()` signature: `int odb_transaction_begin(struct odb_transaction **out, enum odb_transaction_flags flags)`.
  - `odb_transaction_commit()` now returns `int`.
  - `odb_transaction_begin_or_die()` added.
  - `odb_transaction_env()` added.
  - `ODB_TRANSACTION_RECEIVE` flag introduced.

Open questions and loose ends
- **Patch 2/6**:
  - Why transaction functions remain in `object-file.c` instead of `odb/source-files.c` (acknowledged as outside scope).
  - ODB transaction system’s single-transaction-per-ODB limitation, inconsistent with reference transactions’ multi-transaction design (noted for future work).
- **Patch 3/6**:
  - **Blocking issue**: `odb_transaction_begin()` can return success (`0`) with `out` as `NULL` if a transaction is already active. The convenience wrapper `odb_transaction_begin_or_die()` does not handle this case, risking crashes or silent failures. Requires follow-up to either treat an existing transaction as an error or ensure the wrapper dies if `out` is `NULL`.
- **Patch 4/6**:
  - Minor documentation nit: clarify that passing a `NULL` transaction to `odb_transaction_commit()` is a no-op returning success (`0`).
- **Patch 5/6**:
  - Minor documentation improvements (grammar, possessive form).
  - Design alternative for the `env` callback: instead of returning a `NULL`-terminated array owned by the backend, the callback could take a `struct strvec` as input and return an error code. Framed as a question; no immediate action required.
- **Patch 6/6**:
  - **Blocking issue**: behavioral change where the transaction’s object directory is no longer added as an alternate, only propagated via environment variables. This change is undocumented in the commit message and could affect child processes.
  - **Blocking issue**: `ODB_TRANSACTION_RECEIVE` flag’s purpose is undocumented in the header; name isn’t self-explanatory. Patrick questions whether the lazy vs. eager directory creation distinction is necessary long-term.
  - **User-facing terminology**: error message uses "ODB" acronym, which may confuse users.
  - **Code organization**: inconsistent use of transaction parameter vs. `the_repository` access.
  - **Future work**: investigate whether lazy directory creation is needed at all (possible `NEEDSWORK` comment); consider splitting the patch into two (flag introduction and application in `receive-pack`).
- Follow-up work explicitly noted: backend-agnostic object writes.
