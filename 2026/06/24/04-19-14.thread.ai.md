Core problem or goal
Replace `tmp_objdir` usage in `git-receive-pack` with the `odb_transaction` subsystem to advance ODB-backend agnosticism. The series stages incoming objects via transactions (replacing temporary object directories) while preserving existing object-write behavior (via `git-index-pack`/`git-unpack-objects` and the "files" backend). **All blocking feedback from v1 is addressed**; follow-up work (error-handling improvements, lazy directory creation, explicit abort interface, detangling object-write paths, **redundant validation removal, surfacing previously ignored errors, propagating backend errors to callers, environment-variable plumbing for child processes, and flag-based behavioral preservation for `receive-pack`**) is explicitly deferred to maintain focus. **Two open items remain**:
1. Patrick Steinhardt requests clarification on the motivation for eliminating `flush_loose_object_transaction()` in patch 3/11, specifically what future change this refactoring enables.
2. Patrick Steinhardt identifies a usability gap in patch 5/11: error-propagation improvements are mechanical but silent (no error messages logged when `tmp_objdir_create()` or `tmp_objdir_migrate()` fail), making debugging harder.

Current status
**v2 posted (11 patches, 11/11 reviewed and integrated, 2/11 pending clarification/improvement)**. The series is **functionally complete** with the final patch (11/11) converting `git-receive-pack` to use the new `odb_transaction` interfaces. All v1 feedback has been incorporated, including:
- **Patch 2/11**: renames `fsync_loose_object_transaction()` to `odb_transaction_files_fsync()` for naming consistency and reorders conditional logic for clarity. **No behavioral change**; purely mechanical refactoring. **Reviewed-by Patrick Steinhardt (subsystem owner)** with explicit acceptance of the minor duplication introduced by the conditional reordering.
- **Patch 3/11**: eliminates `flush_loose_object_transaction()` by inlining its hardware-flush (`fsync`) and directory-migration (`tmp_objdir_migrate`) logic directly into `odb_transaction_files_commit()`. **No behavioral change**; reduces indirection in the transaction lifecycle. **Open question**: Patrick Steinhardt asks why this helper is being eliminated now and what specific future change it enables. The commit message’s rationale ("subsequent commit") is deemed insufficient.
- **Patch 4/11**: removes redundant validation in `odb_transaction_files_begin()` (the generic `odb_transaction_begin()` layer already enforces the "only one transaction per ODB" rule). **No behavioral change**; mechanical simplification. **Reviewed-by Patrick Steinhardt**, who explicitly endorses the change as fixing a layering violation: the "files" backend should not duplicate ODB-layer state management.
- **Patch 5/11**: converts `odb_transaction_files_prepare()`, `odb_transaction_files_begin()`, and `odb_transaction_files_commit()` from `void` to `int` return types, propagating previously ignored errors to callers. **Usability gap**: Patrick Steinhardt notes that failures in `tmp_objdir_create()` and `tmp_objdir_migrate()` are propagated but not logged, making debugging harder. **No behavioral change**; purely mechanical error-propagation improvement with a pending usability enhancement.
- **Patch 6/11**: refactors `odb_transaction_begin()` to return an error code and write the transaction into an out-parameter, replacing the old behavior of returning the transaction pointer directly. Adds a convenience wrapper `odb_transaction_begin_or_die()` for call sites that don’t need explicit error handling. **No behavioral change**; purely mechanical error-propagation improvement. **Reviewed-by Patrick Steinhardt**, who calls the change "very much welcome" and notes it results in "much saner behaviour with less surprises." Minor style nit (including `git-compat-util.h` in a header file) flagged but accepted as-is. Design observation: some call sites (e.g., `cache_tree_update`) create and immediately commit transactions, which may warrant future revisiting.
- **Patch 7/11**: modifies `odb_transaction_commit()` and its backend callback to return an `int` error code instead of `void`, enabling backends to signal commit failures. **No behavioral change**; purely mechanical error-propagation improvement.
- **Patch 8/11**: introduces `odb_transaction_env()` and its "files" backend implementation, allowing child processes (e.g., `git-index-pack`, `git-unpack-objects`) to inherit the transaction’s staging area via environment variables. **No behavioral change**; purely plumbing. Touches `object-file.c`, `odb/transaction.c`, and `odb/transaction.h`.
- **Patch 9/11**: adds `enum odb_transaction_flags` and the `ODB_TRANSACTION_RECEIVE` flag to preserve `git-receive-pack`’s existing object-directory behavior (eager directory creation, "incoming" prefix) during the transition. The flag is documented as a temporary measure to maintain compatibility while the refactoring is in progress. **No behavioral change**; purely plumbing for future conversion.
- **Patch 10/11**: removes a redundant call to `tmp_objdir_env()` in `update_shallow_ref()` in `builtin/receive-pack.c`. The call is unnecessary because `tmp_objdir_migrate()` has already moved the temporary objects into the main object store by the time `update_shallow_ref()` runs, so there is no temporary directory left for child processes to see. **No behavioral change**; purely mechanical cleanup of dead code.
- **Patch 11/11**: replaces direct `tmp_objdir` usage in `builtin/receive-pack.c` with `odb_transaction` interfaces. The global `tmp_objdir` variable is removed, and a local `struct odb_transaction *` is created at the start of the unpack phase (`odb_transaction_begin` with the `ODB_TRANSACTION_RECEIVE` flag) and committed just before reference updates (`odb_transaction_commit`). The temporary directory is no longer added as an alternate; instead, the transaction’s object directory becomes the primary ODB in the main process, preserving quarantine semantics. **Behavioral change is non-regressive**: objects are staged in an "incoming" directory and migrated to the main object store only after pre-receive hooks and connectivity checks pass, matching the existing behavior. Error handling is consistent with the rest of the series: failures during transaction begin or commit are surfaced as command errors.
Retains all prior v2 changes (patches 1–2/11: naming consistency; error-handling semantics, file-local global, deferred improvements).
**Architectural limitation documented**: only one ODB transaction can exist per ODB (due to global `tmp_objdir` and `atexit()` cleanup); targeted for future refactoring.
**Queued for `next`** pending integration and resolution of the open items (patch 3/11’s motivation and patch 5/11’s usability gap). No objections to goals or approach.
