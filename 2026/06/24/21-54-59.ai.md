This is the first patch in Harald Nordgren’s **v5 series** implementing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now code-complete and ready for Junio’s final assessment, with all prior technical concerns resolved.

This patch is a **refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit’s first parent (or falling back to the empty tree for root commits). The helper replaces three nearly identical code blocks in `builtin/history.c`, reducing duplication and improving maintainability. The change is purely mechanical—no behavior is altered—and prepares the codebase for the subsequent patches in the series, which introduce the squash logic and its supporting infrastructure.

The helper takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`, returning 0 on success or -1 on error. It handles parsing the parent commit and copying its tree OID, or falling back to the empty tree if the commit has no parents. The three callers—`commit_tree_with_edited_message()`, `commit_became_empty()`, and `split_commit()`—are updated to use the new helper, eliminating redundant error handling and tree-resolution logic.

The patch touches only `builtin/history.c` (26 insertions, 32 deletions) and is a clean, focused refactoring. It is a prerequisite for the squash logic introduced in later patches, where `first_parent_tree_oid()` will be used to resolve the parent tree for the three-way merge that folds the commit range. The change aligns with Git’s coding style and is well-motivated by the need to avoid code duplication in a file that is already growing to accommodate the new subcommand.
