This is the fourth patch in Harald Nordgren’s **v18 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch prepares the `delete_branches()` function for bulk callers by adding a new flag, `DELETE_BRANCH_NO_HEAD_FALLBACK`, that prevents the function from falling back to `HEAD` when no upstream is configured for a branch.

The change is a small but necessary step toward the upcoming `--delete-merged` command (patch 5/7). Currently, `delete_branches()` falls back to checking whether a branch is merged into `HEAD` if it has no upstream. However, `--delete-merged` is specifically designed to operate on branches with upstreams, so this fallback would be misleading or incorrect in that context. The new flag allows callers to opt out of the `HEAD` fallback, ensuring the function only considers the branch’s upstream.

The patch is **well-motivated** and **minimal**, touching only the logic that determines whether to use `HEAD` as a fallback. It preserves the existing behavior for all current callers while enabling the new `--delete-merged` functionality. The commit message clearly explains the purpose of the change, and the code itself is straightforward: the flag is added to the `enum delete_branch_flags`, and the fallback logic is gated behind a check for `no_head_fallback`.

This patch is part of a **larger, carefully structured series** that introduces a safe, automated branch cleanup mechanism with multiple safety checks (e.g., stacked-branch protection, per-branch opt-out, `--dry-run` preview). The series has undergone extensive review, and this patch in particular has remained stable since v17, reflecting its maturity.
