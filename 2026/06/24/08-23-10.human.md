This is the seventh patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes an out-of-bounds read vulnerability triggered when a corrupted reftable block claims an implausibly large restart count.

The bug occurs in `reftable/block.c` during block initialization. The restart count is stored in the last two bytes of the block and is used to compute the offset of the restart table. If the count is too large, the offset underflows, causing subsequent reads to access memory outside the block. The fix adds a sanity check that verifies the computed restart offset lies within the block’s bounds; if not, it returns `REFTABLE_FORMAT_ERROR` instead of proceeding.

The patch includes a new unit test in `t/unit-tests/u-reftable-block.c` that deliberately corrupts the restart count to confirm the fix works. The test constructs a valid block, overwrites the restart count with an extreme value (0xffff), and verifies that `reftable_block_init()` now fails with the expected error.

This is a targeted security fix with no user-visible behavior change. It complements the earlier patches in the series by addressing another edge case discovered through fuzzing. The fix is straightforward and well-tested, making it a clear candidate for inclusion.
