This is the tenth patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes a NULL pointer dereference that occurs when seeking to a corrupted section or index offset that points beyond the end of the table.

The bug surfaces when `table_iter_seek_to()` treats an out-of-bounds offset as a normal end-of-iteration condition, leaving the block partially initialized. Later, when the code tries to read the block type, it dereferences a NULL pointer. The fix is simple: return `REFTABLE_FORMAT_ERROR` instead of a positive value when the offset is invalid. The patch also adds a new unit test in `t/unit-tests/u-reftable-table.c` that deliberately corrupts the log section offset in the footer, verifies the error is reported, and confirms no crash occurs.

This is a clear security fix with a narrow, well-defined scope. The commit message includes a full stack trace and a concise explanation of the root cause, making it easy to assess. The test coverage is thorough and directly exercises the edge case. Given the series’ overall goal of hardening the reftable parser against malicious corruption, this patch fits neatly into the broader effort.
