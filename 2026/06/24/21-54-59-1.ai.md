This is the v18 submission of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete** and addressing the last major design question around stacked-branch protection. The series adds a safe, automated local-branch cleanup command that deletes branches whose work has been merged into their upstream, while preserving branches that are checked out, missing their upstream, pushing back to their upstream (like `main` tracking `origin/main`), or opted out via `branch.<name>.deleteMerged` config.

The key change in v18 is a **refined stacked-branch protection mechanism**: instead of keeping the entire chain of upstream branches (as in v17), the command now **keeps only the branches that an unmerged branch still needs** and **clears the upstream config for any kept (merged) branch whose own upstream is being deleted**. For example, in a chain like `lower→mid→tip` where `tip` is unmerged, `lower` and `mid` are merged, and all three track their immediate upstream, deleting `lower` would now **clear `mid`’s upstream config** (since `lower` is gone) but **preserve `mid` itself** (because `tip` still needs it). This approach balances safety with cleanup, avoiding the "all-or-nothing" behavior of v17 while still preventing broken upstreams.

The series is structured as seven patches, all of which are now stable except for the core logic in patch 5/7 (which implements the new stacked-branch protection). The other patches are unchanged from v17:
1. Adds the `--forked` filter for `--list` mode (unchanged).
2. Converts `delete_branches()` to use an `unsigned int flags` argument (unchanged).
3. Adds `DELETE_BRANCH_SKIP_UNMERGED` to skip unmerged branches on bulk refusal (unchanged).
4. Prepares `delete_branches()` for bulk callers with `DELETE_BRANCH_NO_HEAD_FALLBACK` (unchanged).
5. Implements `--delete-merged` with all safety checks, including the new stacked-branch protection logic.
6. Adds the `branch.<name>.deleteMerged` opt-out mechanism (unchanged).
7. Adds `--dry-run` support for `--delete-merged` (unchanged).

The test suite has been expanded to cover the new stacked-branch protection behavior, including edge cases like clearing upstreams for kept branches and handling chains of dependencies. The implementation is now **ready for final review**, with no known blocking issues remaining. Phillip Wood’s proposed refinement to the stacked-branch protection design has been fully implemented, and the series aligns with the project’s API consistency expectations.

Key technical details:
- **Stacked-branch protection**: The command now **fails to delete a branch if it is used as an upstream for an unmerged branch**, but **clears the upstream config for kept (merged) branches whose own upstream is being deleted**. This avoids breaking dependency chains while still cleaning up stale configs.
- **Safety checks**: Branches are spared if they are checked out, missing their upstream, pushing to the same ref as their upstream, or opted out via `branch.<name>.deleteMerged=false`.
- **`--dry-run`**: Prints "Would delete branch <name>" or "Would skip branch <name> (used as upstream)" for each affected branch, reflecting the new stacked-branch protection logic.
- **`--forked` filter**: Composes with `--merged`/`--no-merged` to select branches whose upstream matches a given pattern (e.g., `origin/main` or `origin/*`).
