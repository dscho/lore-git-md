This is the final patch (6/6) in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It completes the transition by replacing the direct `tmp_objdir` calls in `builtin/receive-pack.c` with the new `odb_transaction` interfaces, and introduces a special `ODB_TRANSACTION_RECEIVE` flag to preserve the eager directory creation and "incoming" prefix naming that `receive-pack` requires.

The patch touches 14 files, with the bulk of the changes in `builtin/receive-pack.c` (46 lines) and `object-file.c` (22 lines). Key symbols modified or introduced include `odb_transaction_begin()`, which now takes an `enum odb_transaction_flags` parameter, and `odb_transaction_env()`, which replaces `tmp_objdir_env()`. The `odb_transaction_files` backend gains a `prefix` field to support the "incoming" vs. "bulk-fsync" distinction, and the `ODB_TRANSACTION_RECEIVE` flag triggers eager directory creation in the "files" backend.

This is a pure refactoring with no user-facing behavior changes. The series as a whole is part of Patrick Steinhardt’s ODB abstraction effort, and this patch specifically enables `receive-pack` to stage objects via transactions rather than temporary directories, while deferring backend-agnostic object writes to a follow-up series. The changes are mechanical but non-trivial, and the commit message clearly explains the motivation and special-casing for `receive-pack`. No review feedback has been posted yet, but the patch looks well-scoped and uncontroversial.
