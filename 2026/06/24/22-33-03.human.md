This is the first patch in Harald Nordgren’s v2 usability series, part of the `hn/branch-push-mistake-advise` topic. The patch refines error messages for a common user mistake: typing `git branch --set-upstream-to origin main` (missing slash) instead of `origin/main`. Junio C Hamano’s reply here is a light review of the updated patch, suggesting a small improvement to the commit message to cover the case where the local branch *does* exist but the upstream argument is still misformatted.

Junio’s feedback is minor and constructive. He proposes adding a sentence to the commit message to clarify that when the local branch exists, the error message is equally confusing—something like “when 'main' does exist, the command dies with 'fatal: the requested upstream branch 'origin' does not exist'.” This would make the motivation section more complete. He otherwise calls the updated description “much more nicely described” and sees “no room for confusion,” a clear signal that the patch’s premise is now sound.

The code itself is unchanged in this reply; Junio’s only technical comment is a question about whether the `advise_if_enabled()` call inside `die_if_upstream_looks_like_remote()` is redundant, since the caller already gates the helper on the same config option. This is a small implementation detail, not a blocker.

No new objections or open questions are raised. The patch is technically ready and the only remaining work is the trivial commit-message tweak. If Harald incorporates that, this patch should be in good shape for merging.
