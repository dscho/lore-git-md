This is a v2 resubmission of Harald Nordgren's usability improvement series that makes Git's error messages more helpful when users accidentally misformat remote/branch arguments. The series targets two common mistakes: `git branch --set-upstream-to=origin main` (missing slash) and `git push origin/main` (slash instead of space). Both patches now gate their advice on `advice_enabled()` and extract detection logic into helper functions, addressing Junio C Hamano's technical feedback from v1.

The cover letter and commit messages have been rewritten to clearly state the intended command, the common slip, and the resulting error, making the motivation more accessible. The first patch now only suggests the correct `<remote>/<branch>` form when the remote-tracking ref (`origin/main`) actually exists, reconstructing the user's likely intent as setting upstream for the current branch. This refinement responds directly to Junio's critique about the original patch's premise.

The implementation touches `builtin/branch.c` and `builtin/push.c`, adding two new config options (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) and corresponding tests in `t/t3200-branch.sh` and `t/t5529-push-errors.sh`. The changes are focused and non-disruptive, with clean separation of concerns. The v2 structure ensures users who disable advice pay no performance penalty, as the detection logic now runs only when advice is enabled.

The series appears well-crafted and addresses a real usability pain point. The v2 refinements resolve the technical concerns raised in v1 while preserving the original goal. The first patch's motivation remains the most debated aspect—Junio's proposed refinement narrows the advice to cases where it's most likely correct, but D. Ben Knoble's review suggests the current error message can still mislead users even with this adjustment. The second patch's implementation is now technically sound following Junio's feedback.
