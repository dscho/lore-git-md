This is the third patch in Justin Tobler’s six-part series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It addresses a latent error-handling gap in the ODB transaction subsystem: `odb_transaction_begin()` previously returned the transaction pointer directly, leaving no way for the backend to signal setup failures (e.g., when creating the temporary object directory). The patch refactors the function to return an `int` error code and write the transaction into an out-parameter, then adds `odb_transaction_begin_or_die()` as a convenience wrapper for callers that don’t need fine-grained error handling.

The changes are mechanical but widespread: eight files are touched, with the core logic in `odb/transaction.c` and `odb/transaction.h`. Every caller of `odb_transaction_begin()` is updated to use the new signature or the `_or_die` helper. The patch is clearly motivated by the upcoming `receive-pack` work (patch 4/6), where silent transaction failures would be especially problematic. No user-facing behavior changes, so this is pure infrastructure cleanup.

The diffstat is modest (33 insertions, 15 deletions) and the commit message is concise but complete. There’s no test coverage mentioned, but the existing test suite should suffice since the patch only adds error propagation without altering logic. This looks like a solid, uncontroversial step in the ODB abstraction effort.
