This is the fifth patch in the **v2 performance optimization series** for Git’s commit-reach subsystem, refactoring the `paint_down_to_common()` function to use a new `paint_state` struct with per-side counters. The patch is part of a larger effort to optimize merge-base calculations by terminating early when one side of the history is exhausted, yielding **100-1000x speedups** for asymmetric queries.

The patch introduces a `paint_state` struct that wraps a priority queue and tracks the number of commits from each side (PARENT1-only, PARENT2-only, or pending merge-base candidates). The counters are maintained by `paint_count_update()`, which adjusts the appropriate bucket based on the commit’s paint flags. The main loop now drains the queue via `paint_queue_get()`, which returns `NULL` when all counters reach zero, replacing the old `max_nonstale` termination condition. This refactoring is behaviorally equivalent—both conditions detect when no non-stale entries remain—but prepares the code for the upcoming early-exit optimization in patch 7/7.

The patch leaves the existing `nonstale_queue` in place for `ahead_behind()`, avoiding the structural dispute from v1. The documentation in `paint-down-to-common.adoc` is updated to reflect the new termination logic, and the commit message confirms that trace2 step counts remain identical before and after the refactoring, ensuring no behavioral regression.
