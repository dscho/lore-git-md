This thread is a focused bugfix for Git’s GPG and SSH signature handling, submitted by first-time contributor Antonio De Stefani. The patch corrects an overzealous line-ending normalization in `gpg-interface.c` that has been present since 2008 and was carried over into SSH signing support in 2021. Specifically, the current code strips *all* CR characters (`\r`) from signature output, but the fix ensures only `\r\n` sequences (Windows line endings) are normalized, preserving lone CRs. The change is confined to a single helper function and its two call sites, with no tests or documentation updates included yet.

The commit message provides clear historical context, tracing the issue through three prior commits and explaining why the original behavior was safe at the time but no longer appropriate. While the fix itself is unlikely to be controversial, reviewers may request a test case to verify that lone CRs are now preserved in signature output. The patch is standalone and not part of a larger series.
