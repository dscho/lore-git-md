This is the first patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It adds Meson build support for libFuzzer, the fuzzing engine that uncovered the vulnerabilities the rest of the series fixes.

The patch introduces a new Meson build option, `-Dfuzzers_link_args=`, which lets users pass linker flags specifically for fuzzing executables. This plugs a gap in the existing `-Db_sanitize=` mechanism, which can only set global sanitizer flags but cannot add the `-fsanitize=fuzzer` flag needed to link libFuzzer itself. The documentation update shows users exactly how to configure the build for fuzzing: enable the address and fuzzer-no-link sanitizers, turn on fuzzers, and supply the required linker argument.

The change is small and mechanical: 15 lines of documentation in `meson.build`, two lines in `meson_options.txt`, and a single line in `oss-fuzz/meson.build` that wires the new option into the fuzzer executables. No new fuzzing targets are added yet; those appear in later patches. This patch simply makes it possible to build the fuzzing infrastructure that the rest of the series relies on.

Because the patch is purely build-system plumbing, it is unlikely to be controversial. It is a necessary enabler for the security fixes that follow, and the documentation makes the setup process clear. If the series lands, this patch will be the first step users take to reproduce the fuzzing results that motivated the hardening.
