This is a bugfix patch targeting the GPG signature handling in Git. It corrects a long-standing issue in the `remove_cr_after()` helper function, which was originally written to normalize Windows-style line endings (`\r\n`) in GPG output but was incorrectly stripping *all* carriage return (`\r`) characters, even lone ones that might legitimately appear in the signature.

The patch renames the function to `strip_cr_before_lf()` to better reflect its new behavior and modifies the loop to skip `\r` only when it is immediately followed by `\n`. The commit message traces the history of the function back to 2008, noting that the original "simplification" was safe at the time but left a `NEEDSWORK` comment that this patch now addresses. Both GPG and SSH signing call sites are updated to use the corrected function.

The change is small (11 lines added, 14 removed) and well-motivated, with a clear explanation of why the old behavior was problematic. No tests are included, but the patch itself looks straightforward and unlikely to introduce regressions. This is a good example of a targeted cleanup that fixes a latent issue without changing the overall design.
