This is the fourth patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes a crash (`abort()`) that occurs when Git encounters a corrupted reftable file containing an invalid ref value type.

The patch replaces the `abort()` call with a graceful error return (`REFTABLE_FORMAT_ERROR`), ensuring Git fails safely rather than crashing when parsing malformed data. The fix is minimal: it moves the assignment of `r->value_type` after the switch statement to avoid storing an invalid type, and adds a new unit test (`test_reftable_record__ref_record_decode_invalid_value_type`) to verify the error is handled correctly. The test constructs a deliberately corrupted record and checks that the decoder returns the expected error code.

This is a clear security fix targeting a specific edge case in the reftable parser. The change is internal-only (no API or on-disk format changes) and strictly improves robustness. The accompanying test is thorough and follows the pattern established in earlier patches in the series. Given the series’ goal of hardening the reftable backend against corrupted files, this patch fits neatly into the broader effort and looks like a well-crafted, uncontroversial fix.
