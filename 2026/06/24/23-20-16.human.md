This is Junio C Hamano, the Git maintainer, responding to Harald Nordgren’s latest attempt to justify the `--track=fetch` feature for `git checkout`/`git switch`. The email pushes back firmly on the workflow argument, questioning whether automating the fetch step actually improves user behavior or instead encourages careless branching.

Junio’s core concern is that the feature might *discourage* users from inspecting recent upstream changes before starting work. He sketches a more thorough workflow (`git fetch`, review changes with `git log -p`, then branch) and suggests that folding fetch and checkout into one command could lead users to skip the review step entirely. His tone is skeptical: he frames the feature as potentially enabling a "bad workflow" where users blindly branch from the latest tip without understanding what they’re building on. The email also notes that well-run projects often encourage branching from stable release tags rather than the ever-changing tip of the main branch—a practice that conflicts with the feature’s premise of always fetching the latest remote state.

There’s no new technical feedback here; this is purely a philosophical objection. Junio acknowledges that these points may have been raised before but asks if Harald has any *new* arguments to counter them. The implication is clear: without fresh justification, the feature’s workflow risks remain unresolved, and the series is unlikely to be merged. The ball is back in Harald’s court to either refine the rationale or concede the point.
