This is the second patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It introduces a new fuzzer (`oss-fuzz/fuzz-reftable.c`) that exercises Git’s reftable parsing code by feeding it arbitrary byte sequences.

The fuzzer is minimal but thorough: it creates a block source from the fuzzer’s input, initializes a reftable table, and then iterates over ref records, log records, and raw blocks. This covers the three main data paths in the reftable reader. The patch also wires the fuzzer into the build system (Makefile and Meson) and CI, so it will run automatically in Git’s oss-fuzz integration.

No fixes are included here—this is pure infrastructure. The commit message explicitly states that fallout from the fuzzer will be addressed in subsequent patches. The patch is clean, well-scoped, and clearly part of the larger hardening effort. If you care about reftable robustness or fuzzing in Git, this is worth noting as the foundation for the rest of the series.
