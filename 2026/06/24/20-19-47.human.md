This is a **maintainer's clarification** in response to Karthik Nayak's review of patch 6/12 in the `git cat-file --batch-command` security-hardened series. Junio Hamano addresses the code organization question about the forward declaration of `struct string_list` in `connect.h`.

Junio explains that the forward declaration is intentional and preferable to including the full `string-list.h` header. The function only needs to know that `struct string_list` exists (to declare a pointer), not its internal structure. Including the full header would be unnecessary and could potentially introduce circular dependencies or slow down compilation. This is a common pattern in Git's codebase for minimizing header inclusion.

The response is brief and technical, focusing on a single point of code hygiene rather than the larger protocol compatibility concern Karthik raised. It does not engage with the `GIT_HASH_SHA1_LEGACY` vs `GIT_HASH_SHA1` issue, which remains the more significant open question in the patch. The clarification is useful for understanding Git's coding conventions but does not advance the substantive discussion about the patch's correctness.
