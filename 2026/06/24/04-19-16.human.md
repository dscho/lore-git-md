This is the second patch in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It focuses on error propagation in the "files" transaction backend: previously, errors in `odb_transaction_files_prepare()`, `begin()`, and `commit()` were silently ignored, but now they are surfaced to callers so failures can be handled explicitly.

The changes are mechanical but important: the three key functions (`prepare`, `begin`, `commit`) are converted from `void` to `int`, and their implementations now return error codes when `tmp_objdir` operations fail. The patch also updates the function signature in `object-file.h` to reflect the new error-returning behavior, and adjusts the wrapper in `odb/source-files.c` to match. No user-facing behavior changes, but the internal contract is now stricter and more predictable.

This is a clear, well-scoped refactoring that fits neatly into the larger ODB abstraction effort. The commit message is concise and the diff is clean, with no obvious oversights. If the series lands, this patch will make the transaction layer more robust by ensuring that staging failures are visible rather than hidden. It looks uncontroversial and ready for review.
