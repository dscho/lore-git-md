This is the second patch in the v8 series of a GSoC effort to standardize path formatting in Git. It adds two new `git repo info` fields—`path.commondir.absolute` and `path.commondir.relative`—so scripts can reliably discover the repository’s common directory (the shared `.git` directory that holds objects, refs, and global configuration) in both absolute and relative formats.

The patch builds on the shared `format_path()` helper introduced in the first patch, which already handles the formatting logic for `rev-parse`. Here, two new getter functions (`get_path_commondir_absolute()` and `get_path_commondir_relative()`) call that helper with the appropriate `path_format` enum value (`CANONICAL` or `RELATIVE`). The implementation is straightforward: each getter retrieves the common directory via `repo_get_common_dir()`, checks for errors, and delegates formatting to the shared helper. Documentation is updated to describe the new fields, and the new test script (`t/t1900-repo-info.sh`) verifies both absolute and relative output in standard and worktree setups, including edge cases like custom `GIT_COMMON_DIR` and `GIT_DIR` environment variables.

This patch is part of a three-patch series that has already resolved all substantive feedback from Junio C Hamano and Phillip Wood. The helper’s API and semantics are now stable, and the series is ready for maintainer pickup. The new fields are purely additive and do not change existing behavior, so there is no risk of breaking scripts that rely on current `git repo info` output. Test coverage is thorough, including worktree scenarios and error conditions. If you care about scriptability or worktree setups, this patch delivers a small but useful improvement.
