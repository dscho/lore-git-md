This is the third patch in Patrick Steinhardt’s four-patch v2 series refactoring Git’s connectivity checks to generalize promisor object handling. It is a pure refactoring that extracts the promisor-specific logic from `check_connected()` into a new helper function, `check_connected_promisor()`, without changing behavior. The patch directly addresses Christian Couder’s review feedback on v1, which criticized the original patch’s overly complex control flow.

The new function, `check_connected_promisor()`, encapsulates the logic that checks whether all new tips are present in promisor packs. This is the fast path for partial clones, where full connectivity checks are unnecessary because promisor objects are expected to be incomplete. The function returns 1 if all objects are found in promisor packs (indicating full connectivity), 0 if any object is found in a non-promisor pack (triggering a fallback to the slower rev-list-based check), and a negative value on error. The extraction simplifies `check_connected()` by removing nested loops and gotos, making the code easier to read and maintain.
