This is the third patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes an out-of-bounds read in the `binsearch()` helper when the search range is empty.

The bug is straightforward: when `sz` is zero, the function still calls the comparison callback with index 0, which is outside the valid range. The fix adds a one-line guard that returns early if the range is empty. A new unit test in `t/unit-tests/u-reftable-basics.c` verifies that the comparison function is never called in this case.

The patch is minimal, well-motivated, and comes with test coverage. It is part of the broader effort to harden reftable parsing against maliciously corrupted files, and the fuzzing infrastructure introduced earlier in the series already caught this issue. No controversy or open questions are apparent; this looks like a clear, uncontroversial fix.
