This is the sixth patch in Harald Nordgren’s **v18 `git branch --delete-merged` series**, which is now implementation-complete and ready for merging. This patch adds a **per-branch opt-out mechanism** via the `branch.<name>.deleteMerged` configuration key, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion via `git branch -d`.

The opt-out addresses a real workflow need: topic branches that are actively developed after an early round has been merged upstream. When `branch.<name>.deleteMerged` is set to `false`, the branch is skipped by `--delete-merged` (with a non-quiet message explaining why), but remains deletable via the traditional `git branch -d` command, which ignores the opt-out and uses the normal merge check. The implementation is clean and well-tested, with documentation updates for both `git-branch(1)` and `git-config(1)`.

The patch touches `builtin/branch.c` to add the config check during candidate filtering in `delete_merged_branches()`, and updates the test suite to verify both the opt-out behavior and the continued functionality of explicit deletion. The config key is checked using `repo_config_get_bool()`, and the opt-out is respected uniformly across all safety checks (checked-out branches, missing upstreams, push divergence, and stacked-branch protection).

This is a **thoughtful, user-centric feature** that complements the series’ broader goal of safe automated branch cleanup. The opt-out mechanism is simple, discoverable, and integrates naturally with Git’s existing config system. The patch is **ready for review**, with no known issues or design questions remaining.
