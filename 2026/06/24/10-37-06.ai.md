This is the final patch in Patrick Steinhardt’s four-part v2 series refactoring Git’s connectivity checks to generalize promisor object handling. It replaces the packfile-specific `find_pack_entry_one()` logic in `check_connected_promisor()` with a generic ODB iteration mechanism, using `odb_for_each_object_ext()` and the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag. The patch restores the `odb_reprepare()` call that was accidentally omitted in v1, addressing Junio C Hamano’s correctness concern, and introduces a minimal callback function (`promised_object_cb()`) that returns `1` when any promisor object is found.

The change is narrowly scoped to `connected.c` and preserves the existing behavior: the function still returns `1` if all new tips are in promisor packs (fast path), `0` if any object is in a non-promisor pack (fallback to rev-list), or a negative value on error. The new implementation is backend-agnostic, removing the hardcoded assumption that the ODB uses packfiles, which is critical for Patrick’s ongoing ODB abstraction effort. No on-disk format changes or new user-facing behavior are introduced.

The patch is well-motivated and directly addresses the feedback from v1. The use of `odb_for_each_object_ext()` with a prefix filter and promisor-only flag is a clean abstraction, and the error propagation from the ODB iteration is preserved. Reviewers will likely focus on whether the callback logic (`promised_object_cb()`) correctly handles all edge cases (e.g., partial matches, error conditions) and whether the restored `odb_reprepare()` call is sufficient to ensure the ODB’s view of packfiles is up-to-date before iteration begins. The patch is ready for substantive review, particularly from ODB-focused contributors like Justin Tobler or Taylor Blau.
