This is the first patch in a security-hardening series for the reftable backend, focusing on CI/build system infrastructure. It introduces Meson support for building Git's fuzzers with libFuzzer, a coverage-guided fuzzing engine.

The patch adds a new `-Dfuzzers_link_args=` build option to Meson, allowing users to specify linker arguments for fuzzing executables. This is necessary because libFuzzer requires the `-fsanitize=fuzzer` flag to be passed during linking, which cannot be configured through Meson's existing `-Db_sanitize=` option. The patch also updates documentation to guide users on setting up libFuzzer, recommending the use of address sanitizer (`-Db_sanitize=address,fuzzer-no-link`) alongside the new link arguments.

The changes are minimal and targeted: the patch modifies `meson.build` to add documentation, `meson_options.txt` to declare the new option, and `oss-fuzz/meson.build` to apply the link arguments to all fuzzing executables. This infrastructure is a prerequisite for the subsequent patches in the series, which fix vulnerabilities uncovered by the fuzzer. The patch itself does not address any security issues but enables the tooling that will help prevent regressions and discover new ones.

This is a build-system patch with clear motivation and scope. It is part of Patrick Steinhardt's broader effort to harden the reftable backend against corrupted files, and the fuzzing infrastructure introduced here will likely be reused for other subsystems in the future. The patch is well-documented and appears ready for review.
