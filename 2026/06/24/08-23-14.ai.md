This is the final patch in Patrick Steinhardt's 11-patch security-hardening series for the reftable backend, targeting an out-of-bounds read vulnerability when parsing truncated reftable files. The patch addresses a case where a maliciously truncated file could cause Git to read the footer from memory outside the allocated buffer, as demonstrated by the AddressSanitizer report in the commit message.

The fix is straightforward: before computing the table's data section size, the code now verifies that the file is large enough to contain both the header and footer. If not, it returns `REFTABLE_FORMAT_ERROR` instead of proceeding. The patch adds a corresponding unit test in `t/unit-tests/u-reftable-table.c` that constructs a valid reftable, truncates it to just below the footer size, and verifies that `reftable_table_new()` fails with the expected error code.

This completes the hardening effort initiated in the series. The vulnerability is not remotely exploitable (reftable files are local-only), but the fix is a necessary defense-in-depth measure. The patch is minimal, well-motivated, and includes test coverage, making it a clear candidate for merging. With this patch, the fuzzer now runs for 2+ hours without finding new issues, suggesting the series effectively addresses the discovered vulnerabilities.
