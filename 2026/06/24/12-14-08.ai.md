This is the second patch in the v2 series optimizing `paint_down_to_common()` for one-sided histories. It adds targeted test coverage for edge cases in the side-exhaustion optimization, authored by Elijah Newren and co-signed by Kristofer Karlsson.

The patch extends `t6600-test-reach.sh` with four new test cases that exercise scenarios where the optimization’s early-exit logic could misbehave. The first case (`in_merge_bases_many:self`) checks behavior when a commit is both the query subject and one of the merge-base candidates. The second (`get_merge_bases_many:duplicate-twos`) verifies correct handling of duplicate entries in the input list. The third (`get_merge_bases_many:pending-stale`) constructs a diamond topology where a commit transitions to `STALE` while still pending, testing the interaction between the `PARENT1|PARENT2` and `STALE` states. The fourth (`get_merge_bases_many:infinity-both-sides`) builds a history entirely outside the commit-graph with non-monotonic dates, exercising the generation-number `INFINITY` gate that prevents early exit when generation numbers cannot guarantee final paint states.

The test topologies are carefully documented in the setup section, with ASCII diagrams and commit-date annotations explaining the expected behavior. The `pending-stale` test, for example, creates a criss-cross merge where `ps-X` transitions to `STALE` via `ps-B` while still in the queue, ensuring the optimization does not terminate prematurely. The `infinity-both-sides` test forces the walk to fall back to commit-date ordering, verifying the optimization respects the finite-generation guard even when dates are non-monotonic.

This patch is uncontroversial and purely additive, providing the regression coverage needed before the optimization lands in patch 7/7. The test cases reuse edge-case scenarios from Elijah Newren’s prior work (PR #2150), signaling high confidence in their correctness. No new symbols or behavior changes are introduced; the patch exists solely to validate the optimization’s edge-case handling. The commit message clearly links each test to the specific logic it exercises, making the coverage intent transparent.
