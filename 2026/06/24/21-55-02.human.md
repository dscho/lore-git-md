This is the final patch in Harald Nordgren’s four-part series introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. This patch specifically implements the `--reedit-message` feature, allowing users to combine the messages of all folded commits in the editor, mirroring the behavior of `git rebase -i`.

The patch gathers the messages of every commit in the range (oldest first) and uses them as the editor template when `--reedit-message` is specified. Previously, only the oldest commit’s message was available for editing, which meant the messages of folded-in commits were effectively lost. The implementation builds the combined message *before* the descendant walk to avoid interference from the flags the walk leaves on commits. The plumbing for this was introduced in an earlier patch (2/4), which extended `commit_tree_ext()` to accept an optional `message_template` parameter.

The documentation is updated to clarify that `--reedit-message` now presents all folded commit messages, not just the oldest. The test coverage is thorough: it verifies that all folded-in messages appear in the editor template, that the combined message is correctly saved, and that the operation aborts if the user leaves the message empty. The implementation is clean, with a dedicated helper (`build_squash_message()`) that handles the message construction, and the code integrates seamlessly with the existing squash logic.

This patch completes the series, which is now code-complete and ready for Junio’s final assessment. All prior feedback—including the `--ancestry-path` requirement, ref-handling design, and range validation—has been addressed, and the implementation appears solid, with comprehensive test coverage and clear documentation. The series as a whole is a well-crafted addition to Git’s history-editing toolkit, offering a more efficient alternative to rebase-based squashing for complex commit ranges.
