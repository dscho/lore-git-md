This thread is about Justin Tobler’s six-patch series converting `git-receive-pack` to use ODB transactions instead of the older `tmp_objdir` mechanism. The goal is to advance Git’s object database abstraction, making it possible to plug in alternative backends in the future. All six patches have been posted, reviewed, and integrated via an evil merge by Junio, though a second version is needed to address feedback.

The series has received thorough technical review from Patrick Steinhardt and lighter but substantive feedback from Junio. The main sticking points were error-handling design, interface clarity, and a few behavioral changes—most notably, patch 6/6 no longer adds the transaction’s object directory as an alternate, which could affect child processes like `git-index-pack`. Justin has agreed to all requested changes for v2, including renaming functions for consistency, clarifying documentation, and tightening the semantics of `odb_transaction_begin()`.

The fifth patch, which this email addresses, is a straightforward infrastructure change that introduces `odb_transaction_env()` to expose transaction state to child processes. Patrick’s review was surface-level, focusing on documentation nits and a design improvement for the callback interface. Justin agreed to switch from a backend-owned array to a `struct strvec` input, making the interface more robust. This patch is uncontroversial and ready for v2. The series as a whole is now queued for `next` and remains on track for eventual merging.
