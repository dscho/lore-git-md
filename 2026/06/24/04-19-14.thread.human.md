This thread is about Justin Tobler’s patch series (now at v3) converting `git-receive-pack` to use ODB transactions instead of temporary object directories, advancing Git’s ODB-backend abstraction effort. The series is functionally complete, with all prior feedback addressed and strong approval from Patrick Steinhardt, the ODB subsystem owner. It’s now queued for Junio’s `next` branch pending integration.

The latest email covers patch 4/11, a small but important cleanup that removes redundant validation from the "files" backend. The generic ODB layer already enforces the "only one transaction per ODB" rule, so the duplicate check in the backend was unnecessary. Patrick endorsed this change earlier as fixing a layering violation. Like the rest of the series, this patch introduces no behavioral changes—it’s purely about code organization.

Two deferred issues remain open for future work: a latent transaction-leak in `odb_transaction_commit()` (where the transaction is freed before backend errors are returned) and a design-level question about whether `odb/transaction.h` and `odb/source.h` should be merged to reduce tight coupling. Neither blocks the current series, which is ready for integration. The conversion preserves all existing behavior, including quarantine semantics for incoming objects.
