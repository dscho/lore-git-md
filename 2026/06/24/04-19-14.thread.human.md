Justin Tobler’s six-patch series refactors `git-receive-pack` to use the ODB transaction subsystem instead of `tmp_objdir`, moving the command toward backend-agnostic object storage. The series is now complete at v1, with patches 1–5 preparing the transaction layer and patch 6 making the switch in `receive-pack`. Patrick Steinhardt has provided substantive review on two patches so far: patch 2, where he identified silent failures in the "files" backend that could lead to data corruption, and now patch 3, where he caught a correctness issue in the new `odb_transaction_begin()` interface.

The issue in patch 3 is a design flaw in error handling: the function can return success while leaving the output transaction pointer `NULL` if a transaction is already active on the ODB. The convenience wrapper `odb_transaction_begin_or_die()` doesn’t check for this case, so callers could proceed with a `NULL` pointer, risking crashes or silent failures. This is a narrow but important fix—Patrick’s feedback doesn’t challenge the series’ direction but highlights a semantic mismatch between the old and new interfaces. The rest of the series remains uncontested, and the broader ODB abstraction effort continues to progress. Justin is expected to send a follow-up patch to address the issue, likely by either treating an existing transaction as an error or ensuring the wrapper fails if the output pointer is `NULL`.
