This six-patch series from Justin Tobler completes the refactoring of `git-receive-pack` to use the ODB transaction subsystem instead of the older `tmp_objdir` mechanism. The goal is to move the command toward backend-agnostic object handling, though the actual object writes still rely on the "files" backend for now. The first five patches laid the groundwork by renaming interfaces, propagating errors, and exposing transaction environment variables for child processes—all uncontroversial plumbing changes. The just-arrived sixth patch finishes the job by replacing the remaining `tmp_objdir` calls in `receive-pack` with the new transaction interfaces, introducing a `ODB_TRANSACTION_RECEIVE` flag to preserve the command’s specific directory-creation and naming requirements.

No reviews have appeared yet, but the series looks like a clean, mechanical refactoring with no user-facing behavior changes. The changes are part of Patrick Steinhardt’s broader ODB abstraction effort, and Justin notes that a follow-up series will tackle making the object writes themselves backend-agnostic. The only open question is whether reviewers will spot any edge cases in the transaction flag or prefix handling, but so far the patches appear well-scoped and ready for feedback.
