This is a feature patch in an ongoing architectural debate about external notes commands. Siddh Raman Pant replies to Johannes Sixt’s critique of the v3 series, defending the design and expanding its use cases.

The email directly addresses Hannes’ two alternatives. First, Siddh argues that improving Git’s native notes backend would require “massive changes” because Git storage is inherently ref-based, and the core problem is that only the latest state matters—not historical notes. Second, he counters that tracking notes outside Git entirely (e.g., in a database) sacrifices the coherence of displaying notes alongside commits, which is the whole point of the feature. The external command approach, he claims, gives users the best of both worlds: external storage *and* seamless Git integration.

Siddh also broadens the motivation beyond the original TOCTOU concern. He links to a 2022 thread from a colleague at Oracle Linux who was trying to solve a similar problem (fetching notes from an external source), suggesting the feature has broader applicability. He further references a kernel-specific tool that annotates commits with external data, framing the patch as a general solution for that pattern.

No new technical details are introduced; the focus is purely on defending the architectural choice. The tone remains measured but firm, positioning the external command as a pragmatic middle ground rather than an over-engineered niche. This reply is likely to shift the discussion toward whether the use cases justify the complexity, rather than whether the implementation itself is sound.
