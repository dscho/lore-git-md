This is the third patch in Patrick Steinhardt’s six-part series refactoring `struct object_info` to support pluggable ODB backends. It adds a `source` field to the new `struct object_info_source` introduced in the previous patch, allowing callers to identify which backend (loose, packed, in-memory) an object came from.

The change is small (13 lines across four files) and mechanical: each backend now sets `oi->sourcep->source` to point back to itself during object lookup. The `whence` enum is still populated for now but will be removed in a later patch once `sourcep->source` is sufficient. The only behavioral difference is that callers can now opt into source tracking by passing a non-NULL `sourcep`; otherwise, the field remains unpopulated.

This patch is a straightforward plumbing step that doesn’t alter Git’s behavior but lays the groundwork for uniquely identifying object sources—a requirement for multi-source resolution and Patrick’s broader ODB abstraction effort. If you’re following that effort, this is a key piece of the puzzle. The series remains unreviewed at this stage.
