This is the eighth patch in Patrick Steinhardt's 11-patch security-hardening series for the reftable backend. It fixes a use of uninitialized memory in `reftable/block.c` when a binary search fails during key lookup.

The bug occurs in `block_iter_seek_key()`, which performs a binary search over a block's restart points to locate a record. If the helper function `restart_needle_less()` fails to decode a record at a given offset, the code correctly detects the error but then calls `reftable_record_release()` on a record that was never initialized. The fix moves the `reftable_record_init()` call to the start of the function, ensuring the record is always initialized before any error path can attempt to release it.

The patch is minimal: it rearranges four lines of code in `reftable/block.c` without changing behavior or introducing new APIs. The commit message clearly explains the issue and the fix. This is a classic "use before init" bug, and the fix is straightforward and safe.

This patch is part of the series' second half, which focuses on individual security fixes (patches 3–11). Like the others, it targets an edge case in parsing corrupted reftable files, ensuring graceful error handling rather than crashes or undefined behavior. The series as a whole is well-motivated, with each fix accompanied by unit tests and fuzzing coverage to prevent regressions.
