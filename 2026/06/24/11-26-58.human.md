This is the final patch in Justin Tobler’s six-patch series converting `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. Patrick Steinhardt’s review is substantive but narrowly focused: he raises a behavioral change (dropping the alternate object directory setup), questions the need for the new `ODB_TRANSACTION_RECEIVE` flag, and suggests minor improvements to error messages and documentation.

The patch itself is a clean, mechanical replacement of `tmp_objdir` calls with `odb_transaction` equivalents. It introduces the `ODB_TRANSACTION_RECEIVE` flag to preserve `receive-pack`’s eager directory creation and “incoming” prefix, but Patrick wonders whether this special-casing is necessary or whether the backend should simply create directories unconditionally. He also notes that the commit drops the `tmp_objdir_add_as_alternate()` call, which previously made the quarantine directory visible to the current process; this change is not mentioned in the commit message and may be unintentional.

No fundamental objections are raised, and the series as a whole remains on track for the ODB abstraction effort. The review is constructive and likely to result in a small follow-up patch to address the alternate-object-directory behavior and add documentation for the new flag.
