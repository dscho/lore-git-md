This is a **substantive review** of the test cases added in patch v2 2/7 of the `paint_down_to_common()` optimization series. Derrick Stolee engages with the test design, not just its surface presentation.

The review is positive ("I'm happy that these cases now exist") but proposes a **technical enhancement** to the test infrastructure. Stolee suggests extending `test_all_modes` to capture **trace2 step-count data** for each commit-graph state (full, half, none) so that the tests can validate the exact number of commits walked, not just the correctness of the output. The proposal is concrete: set `GIT_TRACE2_EVENT` for each mode, save the trace output to separate files, and then assert the expected step counts with `test_trace2_data`. This would make the tests **self-verifying for performance** and allow future regressions in the optimization to be caught early.

The context is that the series has already merged, so this is **post-merge feedback** aimed at improving test maintainability. Stolee’s tone is constructive and the suggestion is framed as a way to "check exact stats without too much extra work". The review is **not blocking** and does not question the correctness of the existing tests, but it does identify a gap in the test’s ability to validate the optimization’s core claim (reduced commit traversal).
