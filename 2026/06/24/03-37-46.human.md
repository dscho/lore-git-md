This is the first patch in the v8 iteration of a GSoC series that extracts path-formatting logic from `` `git rev-parse` `` into a new `` `format_path()` `` helper in `path.c`. The helper is immediately used to replace ~44 lines of duplicated logic in `builtin/rev-parse.c`, preserving exact backward compatibility while making the code reusable for other commands.

The patch introduces a `path_format` enum with four modes (`UNMODIFIED`, `RELATIVE`, `RELATIVE_IF_SHARED`, and `CANONICAL`) and implements the helper with "replace" semantics: the caller provides a `strbuf` that the helper clears and populates, eliminating temporary allocations. The `rev-parse` conversion refactors the existing `print_path()` function to map its legacy `format_type` and `default_type` enums to the new `path_format` enum, then delegates the actual formatting to the shared helper.

This version addresses all maintainer feedback from v7: the helper is renamed to `format_path()` (from `append_formatted_path()`), its semantics are changed to replace rather than append, and the control flow in `print_path()` is simplified to handle `FORMAT_DEFAULT` first before mapping to the new enum. The API has received explicit approval from Phillip Wood, and the series is now structurally complete. The patch is well-tested: all existing `rev-parse` tests continue to pass, validating the helper against edge cases and worktree scenarios.
