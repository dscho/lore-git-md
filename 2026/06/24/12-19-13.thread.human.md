Here’s the human-readable summary for a developer catching up on the thread:

This thread is the start of Patrick Steinhardt’s six-patch series refactoring Git’s `struct object_info` to better support pluggable object database (ODB) backends. The core issue is that the current `whence` field is too vague to uniquely identify an object’s source—such as which packfile it came from—blocking multi-source resolution. The series replaces `whence` with a new `struct object_info_source` that carries both the source type and backend-specific data.

The first two patches are now public. Patch 1 laid the groundwork by adding an optional `source` parameter to key ODB functions, though all callers currently pass `NULL`. Patch 2 (the latest update) splits backend-specific details into a new, opt-in `struct object_info_source`, making provenance information available only to callers that request it. The changes are mechanical and don’t alter behavior yet, but they’re a necessary step toward uniquely identifying objects across multiple sources. No substantive review feedback has arrived so far, but the patches are clean and align with Patrick’s broader ODB abstraction effort. If this work interests you, keep an eye on the remaining patches, which will likely introduce the multi-source logic.
