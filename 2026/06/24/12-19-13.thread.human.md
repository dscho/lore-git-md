Here’s the human-mode summary for a developer catching up on the thread:

This thread is the second iteration of Patrick Steinhardt’s patch series refactoring `struct object_info` to replace its `whence` field and `u` union with an opt-in `source_infop` field. The goal is to better track object provenance—like which packfile or ODB backend an object came from—without forcing all callers to pay the cost of populating that information. Junio C Hamano has already given the series conceptual approval, calling it "everything makes sense," and the design is now settled.

The series is complete at six patches. The first five refactor the code, replacing `whence` with `source_infop` and moving the `u` union into a new `struct odb_source_info`. These changes are mechanical and don’t alter behavior, though Junio flagged one pointer assignment in patch 3 as a potential readability wart. The final patch, just posted, adds documentation for previously undocumented fields in `struct object_info`. It’s a straightforward follow-up that closes the last loose end.

All patches have been reviewed, and the only remaining step is merging. The series is part of Patrick’s larger ODB abstraction effort, which aims to make Git’s object storage layer more modular. If you’re tracking that work, this is the last piece before this refactor lands.
