This is the third patch in Harald Nordgren’s **v5 series (4/4) introducing `git history squash`**, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The patch implements the core logic, range validation, ref safety checks, and merge commit handling.

The command takes a `<base>..<tip>` range, squashes all commits into the oldest one (keeping its message and authorship), and replays descendants on top. Key behaviors:
- **Strict range validation**: rejects single revisions (e.g., `HEAD`), empty ranges, or ranges with multiple bases.
- **Ref safety**: refuses to proceed if any ref (branch, tag) points to a commit inside the squashed range, unless `--update-refs=head` is used to rewrite only the current branch.
- **Merge handling**: supports merges inside the range (including nested/octopus merges) but rejects ranges with ambiguous ancestry (e.g., a side branch forked before the base).
- **Message editing**: `--reedit-message` seeds the editor with all folded-in commit messages (oldest first), mirroring `git rebase -i` behavior.

The implementation adds:
- `resolve_squash_range()`: parses and validates the range, enforcing `--ancestry-path` to ensure only commits descended from the base are folded.
- `find_interior_ref()`: detects refs pointing into the squashed range.
- `cmd_history_squash()`: orchestrates the squash (three-way merge of the range against the base, then replaying descendants).

Test coverage is extensive (460 lines), including edge cases like:
- Interior ranges (`@~5..@~2`), root commits, and ranges with merges at the tip/base.
- Ref-handling (rejection, `--update-refs=head`, advice messages).
- Complex merge topologies (nested, octopus, and merges with arms forked before the base).
- `--dry-run` prediction accuracy and authorship preservation.
