Thread identity: patch series, v1, "refactor `struct object_info` to use `source` field", Patrick Steinhardt, ODB subsystem refactoring.
Core problem: `struct object_info`'s `whence` field is too coarse to uniquely identify an object's source (e.g., which packfile), blocking multi-source object resolution and pluggable ODB backends. The series replaces `whence` with a new `struct object_info_source` that carries both source type and backend-specific data, making provenance information opt-in rather than unconditionally populated.
Current status: v1 complete (6/6 patches posted), conceptually approved by Junio C Hamano ("Great"), unmerged, **architectural design question remains unresolved**. Series is self-contained and targets `master`; based on `ps/odb-source-packed`. All patches now reviewed: 1-5/6 refactor the struct and callers (patches 1-3/6 received **substantive review** from Justin Tobler and Junio C Hamano; patches 4-5/6 received **surface-level approval** from Justin Tobler), 6/6 adds documentation. Behavior remains unchanged except callers can now opt out of source population.
Key technical details: 6 patches, 21 files touched (`odb.h`, `odb.c`, `packfile.c`, `odb/source-*.c`, `builtin/cat-file.c`, `commit-graph.c`, `reachable.c`, `builtin/pack-objects.c`, `pack-bitmap.c`, `t/helper/test-bitmap.c`, `builtin/index-pack.c`). New symbols: `struct object_info_source` (with `source` field), `oi->sourcep` (replaces `oi->whence` and `oi->u`). Patch 1/6 adds optional `struct odb_source_packed *source` parameter to `packed_object_info()` and `packed_object_info_with_index_pos()`; patch 2/6 introduces opt-in `sourcep` pointer and converts callers; **patch 3/6 populates the `source` field in backends (`odb/source-inmemory.c`, `odb/source-loose.c`, `packfile.c`), ensuring each backend records its ODB source type during object lookup (no behavior change, but enables future multi-source resolution)**; patch 4/6 replaces all `whence` usage with `sourcep->source->type` (touches `builtin/cat-file.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `reachable.c`); **patch 5/6 removes the `whence` field and its assignments (mechanical cleanup, no behavior change)**; patch 6/6 adds documentation for `struct object_info` fields (`typep`, `sizep`, `disk_sizep`, `delta_base_oid`, `contentp`) in `odb.h`. No on-disk format changes. Test coverage: existing ODB/packfile tests exercise the changes. **Patch 3/6 includes a BUG check in `packfile.c` to prevent callers from requesting source information without providing a valid `source` parameter.**
Open questions: **High-weight architectural design question remains unresolved**: whether the current opt-in `source` parameter design (threaded through `packed_object_info()`) is preferable to centralized source tracking at the `packed_git` level. Justin Tobler and Junio C Hamano favor the latter for simplicity, while Patrick Steinhardt defends the former as a pragmatic intermediate step toward eliminating direct use of `packed_object_info()` in favor of `odb_read_object_info()`. Patrick argues that:
- The `source` parameter is *not* "almost always NULL"—most callers use the higher-level `odb_read_object_info()` API, which already has access to the source and thus doesn’t appear in the diff. Only low-level `packed_object_info()` callers (e.g., `git-pack-objects`, `git-cat-file`) require adjustment.
- Centralized source tracking at the `packed_git` level would be a layering violation, as packfiles can exist independently of their source (e.g., during repacking or when accessed via `mmap`).
- The opt-in design aligns with the long-term goal of replacing direct `packed_object_info()` usage with `odb_read_object_info()`, which abstracts source tracking entirely.
Patrick acknowledges the design feels "iffy" but argues it is necessary for incremental progress. **Surface-level naming concern**: Justin Tobler pointed out that `oi->sourcep` could be misread as a pointer to `struct odb_source` (a later-introduced type) rather than `struct object_info_source`. Patrick Steinhardt acknowledged the ambiguity and explained the current implementation avoids casting by assigning the base struct (`source->base`), but did not propose a rename, leaving this as a non-blocking follow-up.
