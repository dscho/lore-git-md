This is Junio C Hamano’s review of the first patch in Harald Nordgren’s v2 usability series, which improves error messages for the common `git branch --set-upstream-to=origin main` mistake (missing slash). The patch is now technically sound and addresses all feedback from v1, but Junio raises a few minor points and one open question about edge cases.

The review is substantive but narrowly focused. Junio’s main suggestion is to expand the commit message to cover the case where the local branch *does* exist but the user still mistypes the upstream argument—this would make the motivation more complete without changing the code. He also questions whether the `advise_if_enabled()` wrapper is still needed inside `die_if_upstream_looks_like_remote()`, since the caller already gates the call on the same config option. These are both small, actionable items that do not challenge the patch’s core design.

The open question is whether the patch should also handle the case where the local branch exists, the remote portion is invalid as an upstream, but the remote-tracking ref (`<remote>/<branch>`) does exist. Junio does not demand this be addressed, but flags it as a potential gap in the current logic. This is the only point that could spark further discussion, though it is unlikely to derail the patch.

Junio’s tone is constructive and approving; he explicitly calls the commit message “much more nicely described” than v1. The patch is now ready for broader review, with the advice’s scope and wording as the most likely points of follow-up discussion. No performance or correctness concerns are raised.
