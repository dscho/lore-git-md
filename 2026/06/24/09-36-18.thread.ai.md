Core problem or goal
Correct an over-aggressive CR-stripping behavior in Git’s GPG/SSH signature handling. The current `remove_cr_after()` helper removes *all* CR characters (`\r`) from signature output, but only `\r\n` sequences (Windows line endings) should be normalized to `\n`. Lone CR characters should be preserved. The fix affects both GPG and SSH signing code paths.

Key technical details
- File touched: `gpg-interface.c`
- Helper renamed: `remove_cr_after()` -> `strip_cr_before_lf()`
- Logic change: skip CR only when immediately followed by LF (`\n`)
- Old behavior: strip every CR
- New behavior: strip CR only in `\r\n` sequences
