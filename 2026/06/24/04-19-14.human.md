This is the cover letter for a six-patch series from Justin Tobler that refactors `git receive-pack` to use ODB (object database) transactions instead of the `tmp_objdir` interface for staging object writes. The goal is to move Git closer to being ODB-backend-agnostic, though the actual object writes (handled by `git index-pack` and `git unpack-objects`) remain tied to the files backend for now. That limitation is explicitly deferred to a future series.

The series touches core object storage plumbing (`object-file.c`, `odb/transaction.c`) and the receive-pack built-in, with minor fallout in other commands (`add`, `update-index`, `unpack-objects`) that call into the same transaction APIs. The commit messages are clear and the changes appear mechanical: renaming a transaction-prepare function, propagating errors through the transaction stack, and adding a new environment-interface layer. No behavior change is claimed, so this is pure refactoring in service of the larger ODB abstraction effort led by Patrick Steinhardt. If that effort is on your radar, this series is worth tracking; otherwise it can safely be skimmed.
