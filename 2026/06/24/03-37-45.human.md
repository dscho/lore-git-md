This is the eighth iteration of a Google Summer of Code patch series that teaches `` `git repo info` `` to expose repository paths in both absolute and relative formats. The series extracts path-formatting logic from `` `git rev-parse` `` into a new ``format_path()`` helper in `path.c`, then uses it to add four new fields to `` `git repo info` ``: `path.commondir.absolute`, `path.commondir.relative`, `path.gitdir.absolute`, and `path.gitdir.relative`.

The v8 update addresses Junio’s feedback from v7 by renaming the helper from `append_formatted_path()` to `format_path()` and switching its semantics from “append” to “replace” (eliminating temporary allocations). The control flow in `rev-parse.c` has also been refactored to handle `FORMAT_DEFAULT` first, making the code more readable and future-proof. The author considered alternative names (`replace_formatted_path`, `strbuf_format_path`, `populate_formatted_path`) but settled on `format_path()` as the clearest choice.

The implementation is clean and well-tested: the new helper is exercised by existing `rev-parse` tests, and a dedicated test script (`t/t1900-repo-info.sh`) covers all four new fields. Phillip Wood’s substantive review in v7 confirmed the API design and conversion correctness, and the series now carries explicit approval from him. Junio’s remaining feedback is optional stylistic polish rather than a blocker, so the series looks ready for maintainer pickup and graduation to `next`.
