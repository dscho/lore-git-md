This is the third patch in Harald Nordgren’s **four-patch series v5** introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now code-complete and ready for Junio’s final assessment.

This patch implements the core squash logic. It adds the `squash` subcommand to `git history`, which takes a revision range in `<base>..<tip>` form, folds all commits in that range into the oldest one (keeping its message and authorship but using the newest commit’s tree), and replays any descendants on top. The range must have a single base, so ranges with multiple entry points (e.g., a side branch that forked before the range) are rejected. The command also enforces `--ancestry-path` to ensure only commits descended from the base are folded, and it rejects single revisions (e.g., `HEAD`) with a clear error message.

The ref-handling design is finalized: by default, the command refuses to proceed if any ref (branch, tag, or other) points to a commit inside the squashed range, with an advice message suggesting `--update-refs=head` to retarget only the current branch. This avoids silently orphaning refs like bisection markers. The implementation includes thorough input validation, strict range parsing, and helpers like `resolve_squash_range()` and `find_interior_ref()` to detect interior refs and enforce the single-base requirement.

The patch adds 208 lines to `builtin/history.c`, including the new `cmd_history_squash()` function and supporting helpers. It also updates `advice.c`/`advice.h` to add the `historyUpdateRefs` advice, and extends the `git history` subcommand dispatch to include `squash`.
