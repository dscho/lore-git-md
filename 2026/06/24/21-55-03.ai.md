This is the fourth patch in Harald Nordgren’s **implementation-complete v18 series** for `git branch --delete-merged`, which refactors the branch-deletion API to support bulk callers like the upcoming `--delete-merged` command. The patch introduces `DELETE_BRANCH_NO_HEAD_FALLBACK`, a flag that prevents `delete_branches()` from falling back to `HEAD` when checking whether a branch is merged, ensuring the function only considers the branch’s upstream. This change is purely preparatory: existing callers (like `git branch -d`) retain their current behavior, while the new `--delete-merged` command will use the flag to avoid treating `HEAD` as a fallback for branches with missing upstreams.

The patch modifies `delete_branches()` to respect the new flag by skipping the `HEAD` lookup when `no_head_fallback` is set. The logic in `branch_merged()` is also updated to suppress the "gentle reminder" about `HEAD` fallback when `head_rev` is `NULL`, since callers using `DELETE_BRANCH_NO_HEAD_FALLBACK` have already confirmed the branch has an upstream. The change is mechanical and does not alter behavior for existing callers, but it is critical for `--delete-merged`: without it, branches missing an upstream would silently fall back to `HEAD`, potentially deleting branches that are not actually merged into their intended target.

This patch is part of a **flags-based API refactoring** (patches 2–4/7) that replaces boolean arguments in `delete_branches()` with an `unsigned int flags` parameter. The refactoring is motivated by the need to support multiple orthogonal behaviors (force, quiet, skip-unmerged, no-head-fallback) without proliferating boolean parameters. Patch 2/7 introduced the initial flags (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`), patch 3/7 added `DELETE_BRANCH_SKIP_UNMERGED`, and this patch completes the foundation by adding `DELETE_BRANCH_NO_HEAD_FALLBACK`. The series’ core command (patch 5/7) will combine these flags to implement `--delete-merged`’s safety checks.
