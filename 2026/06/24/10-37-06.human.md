This is the final patch in Patrick Steinhardt’s four-part series refactoring Git’s connectivity checks to remove hardcoded packfile assumptions, a key step in the ODB abstraction effort. The patch replaces the packfile-specific `find_pack_entry_one()` logic in `check_connected_promisor()` with a generic ODB iteration mechanism (`odb_for_each_object_ext()`), using the `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag and an object prefix filter to search for promisor objects.

The change is narrowly scoped: it modifies only `connected.c`, replacing the loop over all packfiles with a single call to `odb_for_each_object_ext()`. The new callback `promised_object_cb()` is minimal—it returns `1` unconditionally when an object is found, mirroring the original behavior where `find_pack_entry_one()`’s success short-circuited the search. The `odb_reprepare()` call (restored in this version after being accidentally dropped in v1) ensures the ODB’s view of packfiles is refreshed before iteration begins.

This patch directly addresses the core goal of the series: making connectivity checks backend-agnostic. The use of `odb_for_each_object_ext()` with a prefix filter and promisor-only flag is a clean abstraction, allowing the same logic to work regardless of whether the ODB uses packfiles, reftable, or other backends. The commit message clearly explains the motivation and the technical shift, though it doesn’t discuss edge cases (e.g., error propagation from `odb_for_each_object_ext()` or performance implications).
