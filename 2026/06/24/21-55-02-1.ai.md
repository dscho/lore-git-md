This is the third patch in Harald Nordgren’s seven-patch v18 series implementing `git branch --delete-merged`. The series is now implementation-complete, with all design questions resolved, and ready for merging.

This patch adds a new `DELETE_BRANCH_SKIP_UNMERGED` flag to the `delete_branches()` and `check_branch_commit()` functions. When this flag is set, the functions silently skip unmerged branches instead of emitting an error and advice to use `git branch -D`. This change enables bulk callers (like the upcoming `--delete-merged` command) to continue processing other branches after encountering an unmerged one, rather than aborting the entire operation. Existing callers are unaffected, as the flag is not set by default.

The implementation is straightforward: the patch introduces the new flag, updates the functions to check for it, and modifies the error-handling logic to skip unmerged branches when the flag is set. The change is purely mechanical and does not alter behavior for existing callers. This preparatory work is necessary for the `--delete-merged` command (patch 5/7), which will use the flag to avoid aborting when it encounters an unmerged branch that is protected by the refined stacked-branch protection logic.

The patch touches only `builtin/branch.c` and is well-scoped, with no behavioral changes outside the new flag. The commit message clearly explains the motivation and the intended use case. This is a refactoring patch that enables future functionality without introducing risk to existing code paths. The change aligns with the series’ broader goal of providing safe, automated branch cleanup with precise control over deletion behavior.
