This is the ninth patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes an out-of-bounds read vulnerability triggered by a maliciously crafted restart offset in a reftable block.

The bug occurs when a restart offset—stored in the restart table and meant to point to a valid record—is corrupted to point beyond the records section. During key lookup, the code attempts to decode the record at that offset, reading from invalid memory. The patch adds a bounds check in `restart_needle_less()` to ensure the offset is within the records section; if not, it sets an error flag and aborts the search. The fix is accompanied by a new unit test in `t/unit-tests/u-reftable-block.c` that constructs a block with a deliberately corrupted restart offset and verifies the code fails gracefully with `REFTABLE_FORMAT_ERROR`.

This is a targeted security fix with no user-visible behavior change. The vulnerability requires local disk access to exploit (reftable files are not transferred over the network), but the hardening is part of a systematic effort to make the reftable parser robust against corrupted input. The patch is well-motivated, includes a clear test case, and fits cleanly into the larger series. Given Patrick’s role as the primary reftable contributor and the security-sensitive nature of the issue, this patch is likely to be uncontroversial.
