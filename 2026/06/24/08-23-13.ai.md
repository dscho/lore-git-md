This is the tenth patch in Patrick Steinhardt's eleven-patch security-hardening series for the reftable backend, targeting a NULL pointer dereference when seeking to corrupted offsets.

The patch fixes a case where `table_iter_seek_to()` treats an out-of-bounds offset as a normal end-of-iteration, leaving the block partially initialized. When the offset originates from a section or index (rather than a multi-block iteration), this indicates corruption, but the code silently returns success and later crashes when dereferencing the uninitialized block. The fix adds a check: if `table_init_block()` returns a positive value (indicating the offset is beyond the block), the function now returns `REFTABLE_FORMAT_ERROR` instead of proceeding.

The unit test (`test_reftable_table__seek_invalid_log_offset`) constructs a valid reftable, corrupts the log section offset in the footer to point past the end of the table, and verifies that seeking the log iterator returns a format error rather than crashing. The test includes recomputing the footer's CRC to maintain checksum validity, ensuring the corruption is limited to the offset field.

This is a clear security fix for a NULL pointer dereference, part of the broader reftable hardening effort. The patch is narrowly scoped, touching only `reftable/table.c` and adding a corresponding unit test. The fix is consistent with the series' pattern of converting silent failures into explicit error returns.
