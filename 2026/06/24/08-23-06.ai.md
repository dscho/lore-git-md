This is the third patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes an out-of-bounds read in the `binsearch()` helper when called with an empty range (`sz == 0`). The bug occurs because the function still invokes the comparison callback at index 0 even when no elements exist, leading to an invalid memory access. The fix is a simple early return that avoids the callback entirely for empty ranges, and the patch includes a new unit test (`test_reftable_basics__binsearch_empty`) that verifies the comparison function is never called in this case. The test uses a deliberately failing callback to ensure the code path is unreachable.

The change is internal to `reftable/basics.c` and does not affect any public APIs or on-disk formats. The fix is minimal and targeted, addressing a specific edge case uncovered by the fuzzer introduced in the earlier patches of the series. The unit test is written in the `clar`-style framework and lives in `t/unit-tests/u-reftable-basics.c`, consistent with the series’ pattern of pairing each fix with a corresponding test. This patch is part of the "fixes" portion of the series (patches 3–11) and follows the infrastructure patches that set up the fuzzing environment. The vulnerability is not remotely exploitable, as reftable files are local to the repository, but the hardening is still critical for robustness.
