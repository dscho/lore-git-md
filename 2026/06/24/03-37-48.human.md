This is the final patch in a three-part GSoC series that completes the exposure of repository paths in `git repo info`. The series has already extracted path-formatting logic into a shared `format_path()` helper (patch 1) and added `path.commondir.absolute` and `path.commondir.relative` fields (patch 2). This patch adds the corresponding `path.gitdir.absolute` and `path.gitdir.relative` fields, giving scripts a stable, machine-readable way to locate the `.git` directory without parsing `rev-parse` output or relying on its flag-driven formatting.

The implementation is straightforward: two new getter functions (`get_path_gitdir_absolute()` and `get_path_gitdir_relative()`) call the shared `format_path()` helper with the appropriate formatting mode (`CANONICAL` for absolute paths, `RELATIVE` for relative paths). The patch updates the `repo_info_field` array to expose the new fields, extends the documentation to describe them, and reuses the existing `test_repo_info_path` helper to validate both variants under standard and environment-override conditions. The test coverage is thorough, including edge cases like explicit `GIT_DIR` overrides.

This patch is the culmination of a well-structured series that has addressed all technical and stylistic feedback from Junio C Hamano, Phillip Wood, and other reviewers. The API design is now settled, the helper semantics are aligned with existing Git patterns, and the series is ready for maintainer pickup. The addition of these fields is purely additive and preserves backward compatibility, so there is no risk of breaking existing scripts. For anyone writing tooling that needs to locate the Git directory, this is a small but meaningful improvement.
