The patch extends `commit_tree_ext()`—a helper used by the history subsystem—to accept an optional `message_template` parameter, allowing callers to override the commit message rather than reusing the original commit’s message.

The change is straightforward: `commit_tree_ext()` now takes a `message_template` argument. When `NULL`, it behaves exactly as before (using the original commit’s message). When non-`NULL`, it uses the template instead. The patch updates the function’s signature and logic, then passes `NULL` from the existing `fixup` and `split` callers to preserve their current behavior. The only file touched is `builtin/history.c` (10 insertions, 6 deletions).

This refactoring is a prerequisite for the final patch in the series, which implements `git history squash --reedit-message`. That feature seeds the editor with all folded-in commit messages (oldest first), mirroring `git rebase -i`’s squash behavior. The template parameter introduced here will be populated by `build_squash_message()` in patch 4/4.
