Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, calls to `abort()`, and invalid memory access during block parsing. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

Current status
Series is at v1; no prior versions. All 11 patches are new and now complete. The series is split into two logical parts:
1. **Infrastructure** (patches 1–2): Meson build support for libFuzzer and CI integration for fuzzing. Patch 2 introduces the reftable fuzzer (`oss-fuzz/fuzz-reftable.c`), which exercises the reftable parser by feeding it arbitrary byte sequences. The fuzzer covers the three main entry points into the reftable parser (`reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`) and is integrated into both Makefile and Meson builds, running in every CI pipeline via `ci/run-build-and-minimal-fuzzers.sh`.
2. **Fixes** (patches 3–11): Individual security fixes for the vulnerabilities discovered by the fuzzer, each accompanied by unit tests in `t/unit-tests/`. Patch 3 addresses an out-of-bounds read in the `binsearch()` helper when called with an empty range (`sz == 0`), fixing it with an early return to avoid invoking the comparison callback on invalid memory. Patch 4 fixes a crash in `reftable/record.c` where an invalid ref value type (outside the valid range) triggered an `abort()` call; the patch replaces this with a `REFTABLE_FORMAT_ERROR` return and defers setting the record’s `value_type` field until after validation, preventing inconsistent state. Patch 5 fixes an out-of-bounds write in `reftable/block.c` during log block reconstruction: when the untrusted block size (read from the header) is smaller than the header size, subtracting the header size underflows, causing zlib to write beyond the allocated buffer. The patch adds a sanity check ensuring the block size is at least large enough to cover the header, a 4-byte block header, and a 2-byte restart counter, returning `REFTABLE_FORMAT_ERROR` if not. Patch 6 fixes an out-of-bounds read in `reftable/block.c` during block initialization: the block size is read from the untrusted header and used to compute the restart table offset and restart count without validation. If the claimed size exceeds the actual data length, the code attempts to read the restart count from memory beyond the allocated buffer. The fix adds a sanity check verifying the claimed block size fits within the available data, returning `REFTABLE_FORMAT_ERROR` if not. Patch 7 fixes an out-of-bounds read in `reftable/block.c` during block initialization: the restart count is stored in the last two bytes of the block and used to compute the restart table offset without validation. If the count is large enough, the offset calculation underflows, causing subsequent reads to access memory outside the allocated block. The patch adds a sanity check ensuring the computed restart offset is within bounds (at least `header_size + 4` and at most `block_size - 2`), returning `REFTABLE_FORMAT_ERROR` if not. Patch 8 fixes a use of uninitialized memory in `reftable/block.c` during key lookup: in `block_iter_seek_key()`, if `restart_needle_less()` fails to decode a record, the code calls `reftable_record_release()` on a record that was never initialized. The fix moves the `reftable_record_init()` call to the start of the function, ensuring the record is always initialized before any error path can attempt to release it. Patch 9 fixes an out-of-bounds read during key lookup in `block_iter_seek_key()` when a corrupted restart offset points beyond the records section. The patch adds a bounds check in `restart_needle_less()` to verify the restart offset is within the valid range (before the restart table), returning `REFTABLE_FORMAT_ERROR` if not. Patch 10 fixes a NULL pointer dereference in `table_iter_seek_to()` when seeking to a corrupted offset. The function previously treated out-of-bounds offsets as normal end-of-iteration, leaving the block partially initialized and later crashing when dereferencing the uninitialized block. The fix adds a check: if `table_init_block()` returns a positive value (indicating the offset is beyond the block), the function now returns `REFTABLE_FORMAT_ERROR` instead of proceeding. The unit test constructs a valid reftable, corrupts the log section offset in the footer to point past the end of the table, and verifies that seeking the log iterator returns a format error rather than crashing. Patch 11 (final patch) fixes an out-of-bounds read in `reftable/table.c` when parsing a truncated reftable file. The footer is read from the end of the file, but if the file is truncated, the footer may be read from memory outside the allocated buffer. The patch adds a sanity check ensuring the file is large enough to contain both the header and footer before computing the table's data section size, returning `REFTABLE_FORMAT_ERROR` if not. The unit test constructs a valid reftable, truncates it to just below the footer size, and verifies that `reftable_table_new()` fails with the expected error code.

Key technical details
- **Files touched**:
  - Build system: `meson.build`, `meson_options.txt`, `oss-fuzz/meson.build`
  - Reftable internals: `reftable/basics.c` (patch 3), `reftable/record.c` (patch 4), `reftable/block.c` (patches 5–9), `reftable/table.c` (patches 10–11)
  - Testing: `t/unit-tests/` (new unit tests for each fix, including `u-reftable-basics.c` for patch 3, `u-reftable-record.c` for patch 4, `u-reftable-block.c` for patches 5–9, and `u-reftable-table.c` for patches 10–11), `oss-fuzz/fuzz-reftable.c` (fuzzer target)
- **New symbols**: None (internal-only fixes; no changes to public APIs or on-disk format).
- **Behavior**: Old-vs-new is strictly safer; no user-visible changes. The fixes address edge cases in parsing corrupted files, ensuring graceful failure (e.g., returning errors instead of crashing). Patch 4’s fix ensures that invalid ref value types are handled as format errors rather than fatal programming errors. Patches 5–11 prevent heap-buffer-overflow, out-of-bounds reads, use of uninitialized memory, and NULL pointer dereferences by validating block sizes, restart counts, restart offsets, record initialization, section offsets, and file truncation before parsing.
- **Fuzzing infrastructure**: New Meson build option `-Dfuzzers_link_args=` to pass linker arguments (e.g., `-fsanitize=fuzzer`) for libFuzzer. Recommended setup uses `-Db_sanitize=address,fuzzer-no-link` alongside the new option. The fuzzer is integrated into Git’s CI via oss-fuzz and runs in every pipeline.
