Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, calls to `abort()`, and invalid memory access during block parsing. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

Current status
Series is at v2; all 12 patches are now present. The v2 update added one preparatory patch (patch 5/12) that introduces a test helper function, `cl_reftable_write_block`, to reduce boilerplate in unit tests, addressing Christian Couder’s surface-level feedback on v1. The series is split into three logical parts:
1. **Fuzzing infrastructure** (patches 1–2): Meson build support for libFuzzer and the reftable fuzzer target.
2. **Test helper** (patch 5): Adds `cl_reftable_write_block` to `t/unit-tests/lib-reftable.{c,h}` to reduce duplication in unit tests for block corruption scenarios. The helper is fully integrated into the test suite and used in patches 6–12.
3. **Fixes** (patches 3–4, 6–12): Individual security fixes for vulnerabilities discovered by the fuzzer, each accompanied by unit tests in `t/unit-tests/`. **All fixes are now accounted for and complete**:
   - **Patch 3/12**: Fixes a potential infinite loop in `binsearch()` when the range is empty, ensuring immediate return without calling the comparison function.
   - **Patch 4/12**: Fixes a call to `abort()` in `reftable_record_decode()` when encountering an invalid ref value type, replacing it with a `REFTABLE_FORMAT_ERROR` return.
   - **Patch 6/12**: Fixes a heap-buffer-overflow in the log block parser caused by an underflow when the inflated block size is smaller than the header, leading zlib to write beyond the allocated buffer.
   - **Patch 7/12**: Fixes an out-of-bounds read in `reftable_block_init()` when a block header claims a size larger than the actual data available.
   - **Patch 8/12**: Fixes an out-of-bounds read triggered by a bogus restart count in reftable blocks.
   - **Patch 9/12**: Fixes use of uninitialized memory in `block_iter_seek_key()` when an error occurs during binary search over restart offsets.
   - **Patch 10/12**: Fixes an out-of-bounds read triggered by a bogus restart offset in the restart table.
   - **Patch 11/12**: Fixes a NULL pointer dereference in `reftable_block_type()` when seeking to a bogus offset in a reftable table.
   - **Patch 12/12**: Fixes a heap-buffer-overflow in `reftable_table_read_block()` when the block size is corrupted to exceed the file size, and a new **heap-buffer-overflow in `reftable_table_new()`** when the file is truncated so that it contains a header but not a complete footer. The fix adds bounds checks to ensure the file size is sufficient for both header and footer before computing the data section size.
