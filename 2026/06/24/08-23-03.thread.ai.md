Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, calls to `abort()`, and invalid memory access during block parsing. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

Current status
Series is at v2; v1 was the initial submission. The v2 update adds one preparatory patch (patch 5/12) that introduces a test helper function, `cl_reftable_write_block`, to reduce boilerplate in unit tests. This change responds to Christian Couder’s surface-level feedback on v1, which suggested improving test readability by encapsulating common setup logic. The helper is used in subsequent patches (6–10/12) to simplify test cases for block corruption scenarios. The series is now split into three logical parts:
1. **Fuzzing infrastructure** (patches 1–2): Meson build support for libFuzzer (patch 1) and the reftable fuzzer target (patch 2). Patch 1 adds a new Meson build option `-Dfuzzers_link_args=` to pass linker arguments (e.g., `-fsanitize=fuzzer`) specifically for fuzzing executables, addressing a gap in Meson’s existing `-Db_sanitize=` option. The fuzzer (patch 2) exercises the reftable parser by feeding it arbitrary byte sequences, covering the three main entry points (`reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`). Both patches are integrated into Git’s CI via `ci/run-build-and-minimal-fuzzers.sh`.
2. **Test helper** (patch 5): Preparatory patch adding `cl_reftable_write_block` to `t/unit-tests/lib-reftable.{c,h}` to reduce duplication in unit tests for block corruption scenarios.
3. **Fixes** (patches 3–4, 6–12): Individual security fixes for vulnerabilities discovered by the fuzzer, each accompanied by unit tests in `t/unit-tests/`. The fixes address:
   - Patch 3: Out-of-bounds read in `binsearch()` when called with an empty range (`sz == 0`).
   - Patch 4: Crash in `reftable/record.c` due to invalid ref value type triggering `abort()`.
   - Patch 6: Out-of-bounds write in `reftable/block.c` during log block reconstruction (underflow in block size calculation).
   - Patch 7: Out-of-bounds read in `reftable/block.c` during block initialization (unvalidated block size).
   - Patch 8: Out-of-bounds read in `reftable/block.c` during block initialization (unvalidated restart count).
   - Patch 9: Use of uninitialized memory in `block_iter_seek_key()` during key lookup.
   - Patch 10: Out-of-bounds read during key lookup in `block_iter_seek_key()` (corrupted restart offset).
   - Patch 11: NULL pointer dereference in `table_iter_seek_to()` when seeking to a corrupted offset.
   - Patch 12: Out-of-bounds read in `reftable/table.c` when parsing a truncated reftable file.

- **Behavior**: Old-vs-new is strictly safer; no user-visible changes. The fixes address edge cases in parsing corrupted files, ensuring graceful failure (e.g., returning errors instead of crashing). Patch 4’s fix ensures that invalid ref value types are handled as format errors rather than fatal programming errors. Patches 6–12 prevent heap-buffer-overflow, out-of-bounds reads, use of uninitialized memory, and NULL pointer dereferences by validating block sizes, restart counts, restart offsets, record initialization, section offsets, and file truncation before parsing.
- **Fuzzing infrastructure**: New Meson build option `-Dfuzzers_link_args=` to pass linker arguments for libFuzzer. Recommended setup uses `-Db_sanitize=address,fuzzer-no-link` alongside the new option. The fuzzer is integrated into Git’s CI via oss-fuzz and runs in every pipeline.
