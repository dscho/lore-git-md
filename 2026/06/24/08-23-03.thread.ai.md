Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, calls to `abort()`, and invalid memory access during block parsing. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

- **Fuzzing infrastructure**: New Meson build option `-Dfuzzers_link_args=` to pass linker arguments for libFuzzer. The fuzzer target (`oss-fuzz/fuzz-reftable.c`) feeds arbitrary byte sequences to the reftable parser using `reftable_buf` and `reftable_block_source`. Integrated into Git’s CI via `ci/run-build-and-minimal-fuzzers.sh` and oss-fuzz.
- **Test helper details**: `cl_reftable_write_block` encapsulates the repetitive logic of writing records into a reftable block and appending it to a buffer. Used in patches 6–12 to simplify test cases for block corruption scenarios.
- **Patch 3/12 specifics**: Fixes an out-of-bounds read in `binsearch()` (`reftable/basics.c`) when called with an empty range (`sz == 0`). The fix adds an early return to avoid calling the comparison function with an invalid index. Unit test verifies the fix by passing an empty range and a comparison function that fails if called.
- **Patch 4/12 specifics**: Fixes a call to `abort()` in `reftable_ref_record_decode()` (`reftable/record.c`) when encountering an invalid ref value type. The fix validates the value type before storing it in the record and returns `REFTABLE_FORMAT_ERROR` instead of crashing. Unit test verifies the behavior by feeding an out-of-range value type.
- **Patch 6/12 specifics**: Fixes a heap-buffer-overflow in the log block parser (`reftable/block.c`). The vulnerability occurs when the inflated block size is smaller than the header size, leading to an out-of-bounds write during zlib decompression. The fix adds a sanity check to reject blocks where the size is insufficient to cover the header. Unit test reproduces the issue by corrupting the block size field to a value smaller than the header. **Approved by Junio.**
- **Patch 7/12 specifics**: Fixes an out-of-bounds read in `reftable_block_init()` (`reftable/block.c`). The vulnerability occurs when the block size exceeds the actual data available. The fix adds a bounds check to verify the claimed block size fits within the available data. Unit test now dynamically calculates the corruption value to ensure robustness. **Approved by Junio.**
- **Patch 8/12 specifics**: Fixes an out-of-bounds read in `reftable_block_init()` when a bogus restart count underflows the restart table offset calculation. The fix adds a bounds check to verify `restart_off` is within the valid range. Unit test reproduces the issue by corrupting the restart count to `0xffff`. **Approved by Junio.**
- **Patch 9/12 specifics**: Fixes a use of uninitialized memory in `block_iter_seek_key()` (`reftable/block.c`) when the binary search fails during record decoding. The fix moves the `reftable_record_init()` call to the start of the function, ensuring the record is always initialized. **Approved by Junio.**
- **Patch 10/12 specifics**: Fixes an out-of-bounds read in `restart_needle_less()` (`reftable/block.c`) when a bogus restart offset points past the end of the records section. The fix adds a bounds check to verify the offset is within the valid range. Unit test reproduces the issue by corrupting the restart offset to `0xffffff`. **Approved by Junio.**
- **Patch 11/12 specifics**: Fixes a NULL pointer dereference in `reftable_block_type()` (`reftable/table.c`) when `table_iter_seek_to()` encounters a bogus section or index offset. The vulnerability occurs because an out-of-bounds offset is treated as a normal end-of-iteration condition, leaving the block partially initialized. The fix ensures `table_iter_seek_to()` returns `REFTABLE_FORMAT_ERROR` when the offset exceeds the block size. The unit test (`test_reftable_table__seek_invalid_log_offset`) reproduces the issue by corrupting the log section offset to `UINT64_MAX` and verifies the function now returns the expected error code. The test uses the `cl_reftable_write_block` helper. **Approved by Junio.**
- **Patch 12/12 specifics**: Fixes a heap-buffer-overflow in `reftable_table_new()` (`reftable/table.c`) when a truncated reftable file is too small to contain both the header and footer. The vulnerability occurs because the code computes the table’s data section size by subtracting the footer size from the file size without first verifying that the file is large enough to hold both the header and footer. In a truncated file, this subtraction can underflow, leading to an invalid pointer calculation and an out-of-bounds read when the footer is accessed. The fix adds a bounds check to ensure the file size is at least the sum of the header and footer sizes before proceeding; if not, the function returns `REFTABLE_FORMAT_ERROR`. The unit test (`test_reftable_table__new_with_truncated_table`) reproduces the issue by writing a valid reftable block and then truncating it to one byte less than the footer size. The test verifies that `reftable_table_new()` correctly returns the expected error code. The test uses the `cl_reftable_write_to_buf` helper introduced earlier in the series.
