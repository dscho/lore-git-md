Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, calls to `abort()`, and invalid memory access during block parsing. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

- **New symbols**: `cl_reftable_write_block` (test helper, introduced in patch 5/12). No changes to public APIs or on-disk format.
- **Behavior**: Old-vs-new is strictly safer; no user-visible changes. The fixes address edge cases in parsing corrupted files, ensuring graceful failure (e.g., returning errors instead of crashing). Patch 3’s fix ensures that `binsearch()` handles empty ranges safely by returning immediately without calling the comparison function. Patch 4’s fix ensures that invalid ref value types are handled as format errors (`REFTABLE_FORMAT_ERROR`) rather than fatal programming errors (`abort()`). **Patch 6/12’s fix** prevents a heap-buffer-overflow in the log block parser by validating that the inflated block size covers at least the header and restart counter, returning `REFTABLE_FORMAT_ERROR` if not. Patches 7–12 (remaining) prevent additional heap-buffer-overflow, out-of-bounds reads, use of uninitialized memory, and NULL pointer dereferences by validating block sizes, restart counts, restart offsets, record initialization, section offsets, and file truncation before parsing.
- **Fuzzing infrastructure**: New Meson build option `-Dfuzzers_link_args=` to pass linker arguments for libFuzzer. The fuzzer target (`oss-fuzz/fuzz-reftable.c`) exercises the three main entry points into the reftable parser (`reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`) by feeding them arbitrary byte sequences. Recommended setup uses `-Db_sanitize=address,fuzzer-no-link` alongside the new option. The fuzzer is integrated into Git’s CI via `ci/run-build-and-minimal-fuzzers.sh` and oss-fuzz.
- **Test helper details**: `cl_reftable_write_block` encapsulates the repetitive logic of writing records into a reftable block and appending it to a buffer. It is defined in `t/unit-tests/lib-reftable.c` and declared in `t/unit-tests/lib-reftable.h`. The helper is used in patches 6–10/12 to simplify test cases for block corruption scenarios, replacing 19 lines of boilerplate with a single function call in `test_reftable_block__iterator` and similar tests.
