Subject: [PATCH 0/11] reftable: security hardening against corrupted files
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (security hardening)

Core problem or goal
The series systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted reftable files. The initial report identified an out-of-bounds write, but subsequent fuzzing with libFuzzer uncovered additional issues: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and calls to `abort()`. Although reftable files are not stored remotely (exploitation requires local disk access), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions and discover future issues.

Current status
Series is at v1; no prior versions. All 11 patches are new. The series is split into two logical parts:
1. **Infrastructure** (patches 1–2): Meson build support for libFuzzer and CI integration for fuzzing. Patch 2 introduces the reftable fuzzer (`oss-fuzz/fuzz-reftable.c`), which exercises the reftable parser by feeding it arbitrary byte sequences. The fuzzer covers the three main entry points into the reftable parser (`reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`) and is integrated into both Makefile and Meson builds, running in every CI pipeline via `ci/run-build-and-minimal-fuzzers.sh`.
2. **Fixes** (patches 3–11): Individual security fixes for the vulnerabilities discovered by the fuzzer, each accompanied by unit tests in `t/unit-tests/`.
The fuzzer now runs for 2+ hours without finding new problems, indicating the fixes are effective.

Key technical details
- **Files touched**:
  - Build system: `meson.build`, `meson_options.txt`, `oss-fuzz/meson.build`
  - Reftable internals: `reftable/basics.c`, `reftable/block.c`, `reftable/record.c`, `reftable/table.c`
  - Testing: `t/unit-tests/` (new unit tests for each fix), `oss-fuzz/fuzz-reftable.c` (fuzzer target)
- **New symbols**: None (internal-only fixes; no changes to public APIs or on-disk format).
- **Behavior**: Old-vs-new is strictly safer; no user-visible changes. The fixes address edge cases in parsing corrupted files, ensuring graceful failure (e.g., returning errors instead of crashing).
- **Fuzzing infrastructure**: New Meson build option `-Dfuzzers_link_args=` to pass linker arguments (e.g., `-fsanitize=fuzzer`) for libFuzzer. Recommended setup uses `-Db_sanitize=address,fuzzer-no-link` alongside the new option. The fuzzer is integrated into Git’s CI via oss-fuzz and runs in every pipeline.
