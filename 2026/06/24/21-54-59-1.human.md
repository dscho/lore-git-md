This is the v18 submission of Harald Nordgren’s `git branch --delete-merged` series, now **implementation-complete** and ready for final review. The series adds a safe, automated local-branch cleanup command that deletes branches merged into their upstream while preserving branches that are checked out, missing their upstream, pushing back to their upstream (like `main` tracking `origin/main`), or opted out via `branch.<name>.deleteMerged` config.

The **key change in v18** is a refinement to the stacked-branch protection logic. Instead of preserving the entire chain of upstream dependencies (e.g., `b1→b2→b3`), the command now **keeps only the branches that an unmerged branch still needs** and **clears the upstream config of any kept branch whose own upstream is being deleted**. This is a more nuanced approach than the previous "abort-and-notify" design, allowing some branches in a dependency chain to be deleted while still preserving safety. The implementation uses a two-pass algorithm: first, identify branches to spare; then, clear the upstream config of any spared branch whose upstream is being deleted. The change addresses Phillip Wood’s proposal for a more flexible stacked-branch protection mechanism.

The series is structured as seven patches:
1. Adds the `--forked` filter for `--list` mode (unchanged).
2. Converts `delete_branches()` to use an `unsigned int flags` argument (unchanged).
3. Adds `DELETE_BRANCH_SKIP_UNMERGED` to skip unmerged branches on bulk refusal (unchanged).
4. Prepares `delete_branches()` for bulk callers by adding `DELETE_BRANCH_NO_HEAD_FALLBACK` (unchanged).
5. Implements `--delete-merged` with all safety checks, including the refined stacked-branch protection logic.
6. Adds the `branch.<name>.deleteMerged` opt-out mechanism (unchanged).
7. Adds `--dry-run` support for `--delete-merged` (unchanged).

The test suite has been expanded to cover the new stacked-branch protection behavior, including cases where a kept branch’s upstream is cleared. The implementation is now **technically complete**, with all previously discussed safety mechanisms in place. The series aligns with the project’s API consistency expectations and addresses all high-weight feedback from Phillip Wood and Junio C Hamano. No blocking issues remain.
