This is the fifth patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It fixes an out-of-bounds write vulnerability in the reftable block parser when handling a maliciously corrupted log block.

The bug occurs when the block header claims an inflated log size smaller than the header itself. The code subtracts the trusted header size from the untrusted block size, underflows, and then tells zlib to write more data than the allocated buffer can hold. The patch adds a sanity check that rejects any block whose size is smaller than the minimum required for the header plus restart counter. A new unit test (`test_reftable_block__corrupt_log_block_size`) reproduces the issue and verifies the fix.

The commit message is exemplary: it explains the block layout, the compression flow, the underflow, and includes a full AddressSanitizer backtrace. The fix is minimal and targeted, touching only `reftable/block.c` and the corresponding unit test file. No public API or on-disk format changes; the hardening is purely defensive. Given the series’ overall goal and Patrick’s track record, this patch looks like a clear, well-motivated security fix.
