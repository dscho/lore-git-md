This is a security-hardening patch series for the reftable backend, authored by Patrick Steinhardt. The series addresses multiple potential issues in Git’s reftable parser that could be triggered by corrupted tables, including out-of-bounds reads and writes, uninitialized memory access, and calls to `abort(3p)`.

The motivation stems from a report on the security mailing list about an out-of-bounds write vulnerability. While reftables are not transmitted over the network (so exploitation would require local disk access), Patrick took the opportunity to systematically audit the code. He wrote a fuzzer for reftable parsing, which initially uncovered several bugs; after these fixes, the fuzzer ran for over two hours without finding new issues.

The series consists of eleven patches. The first two add fuzzing infrastructure: one enables libFuzzer support in the Meson build, and the other adds a dedicated reftable fuzzer to the oss-fuzz suite. The remaining nine patches fix specific bugs in the reftable codebase, each targeting a distinct issue (e.g., binary search on empty ranges, invalid ref value types, bogus block sizes, restart counts, and offsets). The fixes are accompanied by new unit tests that verify the hardened behavior.

This is clearly a well-crafted, thorough effort. The commit messages are detailed, the fixes are narrowly scoped, and the test coverage is comprehensive. If you care about the reftable backend or Git’s resilience to corrupted data, this series is worth reviewing.
