This is the final patch in a three-part GSoC series that completes the exposure of repository paths in `git repo info`. The series as a whole introduces a standardized `format_path()` helper and uses it to provide scriptable access to the repository's Git directory and common directory in both absolute and relative formats.

This patch adds the last two missing fields: `path.gitdir.absolute` and `path.gitdir.relative`. These fields mirror the `path.commondir` fields added in the previous patch, using the same shared helper and following the same design pattern. The implementation is straightforward: two new getter functions (`get_path_gitdir_absolute()` and `get_path_gitdir_relative()`) call `format_path()` with the appropriate mode (`PATH_FORMAT_CANONICAL` or `PATH_FORMAT_RELATIVE`), and the fields are registered in the `repo_info_field` array. The patch also extends the test suite to cover both variants, including edge cases where `GIT_DIR` is explicitly set.

The patch is minimal and focused, touching only three files: the documentation, the `repo.c` implementation, and the test script. It reuses the test helper (`test_repo_info_path`) introduced in the previous patch, ensuring consistent validation across all path fields. The commit message clearly states the motivation: scripts need a stable way to locate the Git directory without parsing `rev-parse` output or relying on its flag-driven formatting.

This patch is ready for merging. All technical feedback on the series has been addressed in earlier iterations, and the design has received explicit approval from Phillip Wood. The implementation is clean, well-tested, and maintains backward compatibility. The series as a whole is now structurally complete and awaits maintainer pickup for graduation to `next`.
