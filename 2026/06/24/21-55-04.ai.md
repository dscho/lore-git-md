This is the core implementation patch of Harald Nordgren’s **`git branch --delete-merged`** series, now in its final v18 form. It adds the new `--delete-merged` subcommand, which safely deletes local branches whose work has been merged into their upstream while preserving branches that are checked out, missing their upstream, pushing back to their upstream, or used as an upstream by another branch.

The patch is **implementation-complete** and addresses the last major design question: **refined stacked-branch protection**. Instead of keeping the entire chain of upstream branches (as in v17), the command now **keeps only the branches that an unmerged branch still needs** and **clears the upstream config for any kept (merged) branch whose own upstream is being deleted**. For example, in a chain like `lower→mid→tip` where `tip` is unmerged, deleting `lower` would **clear `mid`’s upstream config** (since `lower` is gone) but **preserve `mid` itself** (because `tip` still needs it). This approach avoids breaking dependency chains while still cleaning up stale configs.

Key technical details:
- **Safety checks**: The command skips branches that are checked out, missing their upstream, pushing to the same ref as their upstream, or opted out via `branch.<name>.deleteMerged=false`.
- **Stacked-branch protection**: The command **fails to delete a branch if it is used as an upstream for an unmerged branch**, but **clears the upstream config for kept (merged) branches whose own upstream is being deleted**. This logic is implemented in `spare_stacked_bases()` and `spare_stacked_base()`.
- **Filtering**: Uses the `--forked` filter (introduced in patch 1/7) to select branches whose upstream matches a given pattern (e.g., `origin/main` or `origin/*`).
- **Flags-based API**: Uses the refactored `delete_branches()` API (patches 2-4/7) with `DELETE_BRANCH_SKIP_UNMERGED` and `DELETE_BRANCH_NO_HEAD_FALLBACK` to skip unmerged branches silently and avoid falling back to `HEAD`.
- **Test coverage**: The test suite verifies the new stacked-branch protection logic, including edge cases like clearing upstreams for kept branches and handling chains of dependencies.
