This is the third patch in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. The patch propagates errors from `odb_transaction_begin()` by changing its return type from a direct `struct odb_transaction *` to an `int` error code, with the transaction pointer written to an out-parameter. A convenience wrapper, `odb_transaction_begin_or_die()`, is added for callers that do not need to handle errors explicitly.

The change touches eight files, all of which are mechanical call-site updates: `builtin/add.c`, `builtin/unpack-objects.c`, `builtin/update-index.c`, `cache-tree.c`, `object-file.c`, `odb/transaction.c`, `odb/transaction.h`, and `read-cache.c`. The core logic in `odb/transaction.c` is straightforward: `odb_source_begin_transaction()` is now checked for errors, and the transaction pointer is stored in the out-parameter. The header introduces the new signature and the die-on-failure wrapper.

This is a pure refactoring patch with no user-visible behavior change. The motivation is to surface transaction setup failures (e.g., temporary directory creation) that were previously silently ignored, which will be needed in the next patch when `git-receive-pack` starts using ODB transactions. The patch is uncontroversial and well-scoped, fitting cleanly into the ODB abstraction effort led by Patrick Steinhardt. Key symbols introduced or modified: `odb_transaction_begin()`, `odb_transaction_begin_or_die()`, and the `struct odb_transaction **out` parameter.
