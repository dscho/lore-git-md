This thread is about Patrick Steinhardt’s 12-patch series hardening Git’s reftable backend against security vulnerabilities in corrupted files. The series is now at v2, with all feedback addressed, and is technically complete. It introduces fuzzing infrastructure, a new test helper to reduce boilerplate, and fixes for nine distinct issues—including out-of-bounds reads/writes, NULL pointer dereferences, and uninitialized memory usage—discovered via libFuzzer.

The latest development is a substantive review from Toon Claes on the sixth patch, which fixes a heap-buffer-overflow in the log block parser. Toon’s feedback focuses on the test case, proposing two small but meaningful improvements to make it stricter: adding a sanity check for the expected block size before corruption and using a minimally invalid size (5 instead of 1) to reduce off-by-one risks. These suggestions don’t challenge the fix itself but aim to harden the test’s reliability. The review reflects careful attention to test mechanics and is likely to be adopted.

Junio C Hamano and Christian Couder have already acknowledged or approved the test helper (patch 5/12), with no outstanding objections to the series. The fuzzer now runs for hours without surfacing new issues, signaling the fixes are comprehensive. The next step is likely a final round of review on the security fixes and fuzzing infrastructure before Junio queues the series for merging.
