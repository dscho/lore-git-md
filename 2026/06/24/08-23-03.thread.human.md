This thread is a 12-patch series from Patrick Steinhardt hardening Git’s reftable backend against security vulnerabilities in corrupted files. The series is now at v3, with all patches present and technically complete. The initial report uncovered an out-of-bounds write, but fuzzing with libFuzzer revealed additional issues—out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory, and calls to `abort()`—prompting a comprehensive hardening effort.

The series is split into three parts: fuzzing infrastructure (patches 1–2), a test helper to reduce duplication (patch 5), and individual fixes for vulnerabilities (patches 3–4, 6–12). The v3 update is minimal, addressing only Toon Claes’s feedback on patch 7/12 by making its test case stricter with dynamic corruption value calculation. All other patches are unchanged from v2, and all prior feedback has been resolved. Junio C Hamano and Christian Couder have acknowledged or approved the test helper improvements, while Toon Claes’s substantive review feedback on patches 6/12 and 7/12 has been fully addressed. The fixes are defensive, replacing crashes or undefined behavior with error returns, and include new unit tests for each vulnerability.

The latest email covers patch 3/12, which fixes an out-of-bounds read in `binsearch()` when called with an empty range. The fix is minimal—adding an early return for `sz == 0`—and includes a unit test to verify the correction. Like the rest of the series, this patch is uncontroversial and ready for merging. No technical blockers remain, though Junio has not yet signaled readiness to merge the full series. The fuzzing infrastructure introduced here is now fully integrated into Git’s CI and may be reused for other subsystems.
