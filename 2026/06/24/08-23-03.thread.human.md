This thread is a security-hardening patch series for Git’s reftable backend, authored by Patrick Steinhardt. The series addresses a range of vulnerabilities—out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and calls to `abort()`—discovered through fuzzing with libFuzzer. While reftable files are not remotely accessible, the hardening is comprehensive, covering all parser entry points and introducing new fuzzing infrastructure to prevent regressions.

The series is now at v2, with all 12 patches technically complete and all prior feedback addressed. The latest update resolves the last open discussion: Patrick accepted Toon Claes’s suggestion to improve the test case for patch 7/12 by dynamically calculating the corrupted block size, ensuring the test reliably triggers the minimal invalid condition. Earlier feedback from Christian Couder (on test boilerplate) and Junio C Hamano (acknowledging the test helper) has also been incorporated. Toon’s review of patches 6/12 and 7/12 was substantive, focusing on test robustness, while other reviewers engaged primarily with code hygiene.

The series is split into three parts: fuzzing infrastructure (patches 1–2), a test helper to reduce duplication (patch 5), and individual security fixes (patches 3–4, 6–12). No user-visible changes or on-disk format modifications are introduced; the fixes replace crashes or undefined behavior with graceful error returns. The fuzzing infrastructure is now fully integrated into Git’s CI, and the test helper (`cl_reftable_write_block`) has been confirmed to reduce boilerplate as intended. With all feedback resolved, the series appears ready for integration, though Junio has not yet signaled a merge.
