This thread is a security-hardening effort for Git’s reftable backend, led by Patrick Steinhardt. The goal is to systematically eliminate vulnerabilities triggered by maliciously corrupted reftable files, which could lead to crashes, memory corruption, or other undefined behavior. The series is now at version 2, with 12 patches—one more than v1, due to the addition of a preparatory test helper to improve code readability.

The series is split into two parts. The first part, covered by the new email, introduces Meson build support for libFuzzer, enabling coverage-guided fuzzing of the reftable parser. This infrastructure patch adds a new build option, `-Dfuzzers_link_args=`, to handle libFuzzer’s linker requirements separately from compiler sanitizers. The second part, which remains unchanged from v1, includes the actual security fixes—11 patches addressing out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and other issues discovered through fuzzing. Each fix is accompanied by unit tests in `t/unit-tests/`, and the fuzzer itself is integrated into Git’s CI pipeline.

Christian Couder provided surface-level feedback on v1, suggesting a test helper to reduce boilerplate in unit tests. This was addressed in v2 with the addition of `cl_reftable_write_block`, a helper function used in subsequent patches to simplify test cases for block corruption scenarios. No other open questions or objections have been raised, and the fuzzer now runs for hours without surfacing new issues, indicating the fixes are comprehensive. The series is part of the broader reftable backend effort and introduces reusable fuzzing infrastructure that could benefit other Git subsystems in the future.
