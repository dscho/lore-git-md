Patrick Steinhardt has sent an 11-patch series hardening Git’s reftable backend against security vulnerabilities in maliciously corrupted files. The series began after an initial report of an out-of-bounds write, and subsequent fuzzing with libFuzzer uncovered additional issues—out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and crashes—all addressed in this series. While reftable files are stored locally (not remotely), the hardening is comprehensive and includes new fuzzing infrastructure to prevent regressions.

The series is split into two parts: infrastructure (patches 1–2) and fixes (patches 3–11). The infrastructure patches add Meson build support for libFuzzer and integrate a reftable fuzzer into Git’s CI, exercising the parser with arbitrary byte sequences. The fixes systematically address each vulnerability, replacing crashes with graceful error returns (e.g., `REFTABLE_FORMAT_ERROR`) and adding unit tests for each case. The final patch (11) fixes an out-of-bounds read when parsing truncated reftable files, ensuring the code verifies the file is large enough to contain both header and footer before proceeding. With this patch, the fuzzer now runs for over two hours without finding new issues, indicating the hardening is effective.

No objections or open questions have been raised yet. The series is self-contained, with no user-visible changes—only internal safety improvements—and appears ready for review. The fuzzing infrastructure introduced here may also be reused for other subsystems in the future.
