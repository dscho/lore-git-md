This thread is a 12-patch series from Patrick Steinhardt that systematically hardens Git’s reftable backend against security vulnerabilities triggered by maliciously corrupted files. The series began after an initial report of an out-of-bounds write, but fuzzing with libFuzzer uncovered additional issues—out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and calls to `abort()`—prompting a comprehensive fix. While reftable files aren’t stored remotely (exploitation requires local disk access), the hardening is thorough and includes new fuzzing infrastructure to prevent regressions.

The series is now at its third version, with all patches present and technically complete. The latest update, patch 12/12, fixes a heap-buffer-overflow in `reftable_table_new()` when a truncated reftable file is too small to contain both the header and footer, leading to an out-of-bounds read. The fix adds a bounds check to ensure the file size is sufficient before proceeding, returning `REFTABLE_FORMAT_ERROR` if not. Earlier patches in the series address similar issues, such as NULL pointer dereferences, uninitialized memory usage, and invalid memory access during block parsing. Junio C Hamano has already approved several of the fixes as "obviously correct," and all prior feedback—including from Christian Couder and Toon Claes—has been addressed.

The series is split into three parts: fuzzing infrastructure (patches 1–2), a test helper to reduce boilerplate (patch 5), and the security fixes themselves (patches 3–4, 6–12). The fuzzing infrastructure is now fully integrated into Git’s CI, and the test helper, `cl_reftable_write_block`, simplifies unit tests for corruption scenarios. Each fix replaces crashes or undefined behavior with safe error returns, and the series introduces no changes to public APIs or on-disk formats. With this final patch, the series is ready for merging, and the infrastructure it introduces will help prevent future vulnerabilities.
