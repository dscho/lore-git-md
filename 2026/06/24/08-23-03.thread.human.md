This thread is a security-hardening effort for Git’s reftable backend, led by Patrick Steinhardt. The series addresses vulnerabilities discovered through fuzzing, including out-of-bounds reads/writes, NULL pointer dereferences, and uninitialized memory usage in the reftable parser. While reftable files are local-only (not remotely accessible), the fixes are comprehensive, covering edge cases in corrupted file parsing to ensure graceful failure instead of crashes. The series also introduces new fuzzing infrastructure (libFuzzer + Meson support) to prevent regressions and catch future issues, integrated into Git’s CI pipeline.

The patches are split into two parts: infrastructure (fuzzing setup and CI integration) and fixes (11 individual security patches, each with unit tests). No prior versions exist; this is the initial submission. The fixes are internal-only, with no changes to public APIs or on-disk formats, and no user-visible behavior changes—just stricter validation to handle corrupted files safely. Christian Couder provided surface-level feedback on test code hygiene, suggesting a helper function to reduce duplication, which Patrick accepted.
