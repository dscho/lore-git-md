This thread is a security-hardening effort for Git’s reftable backend, led by Patrick Steinhardt. The series systematically addresses vulnerabilities in the reftable parser that could be triggered by maliciously corrupted files, such as out-of-bounds reads/writes, NULL pointer dereferences, and uninitialized memory usage. While reftable files are stored locally (not remotely), the fixes are comprehensive and include new fuzzing infrastructure to prevent regressions.

The series is split into two parts: infrastructure (patches 1–2) and fixes (patches 3–11). The infrastructure patches add Meson build support for libFuzzer and integrate a reftable fuzzer into Git’s CI, ensuring continuous testing. The fixes address specific vulnerabilities, each with accompanying unit tests. For example, the latest patch (7/11) fixes an out-of-bounds read in block initialization by validating the restart count before computing the restart table offset. The fuzzer now runs for hours without finding new issues, suggesting the fixes are effective.

No open questions or objections have been raised yet. The series is self-contained and appears ready for review. The fuzzing infrastructure is reusable for other subsystems, though no immediate follow-ups are tied to this effort. Given Patrick’s leadership on the reftable backend, these fixes are likely to be uncontroversial.
