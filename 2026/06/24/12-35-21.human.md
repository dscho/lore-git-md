This is a surface-level review from D. Ben Knoble on the first patch in Harald Nordgren’s usability-improvement series for Git’s error messages. Knoble chimes in on the ongoing discussion about whether the current error message for `git branch --set-upstream-to origin main` (when the local branch `main` does not exist) is misleading. He notes that if `origin/HEAD` is available locally, the command `git branch --set-upstream-to origin` (without a branch name) already works to set the upstream to whatever `origin/HEAD` refers to. This observation suggests that the user’s expectation—treating `origin main` as a remote-tracking branch—is not entirely unreasonable, as Git already handles similar cases where the remote portion alone is sufficient. Knoble’s comment is brief and does not engage with the patch’s implementation or test coverage, but it adds a small piece of context to the debate about whether the current error message is truly unhelpful. The review does not shift the discussion’s direction but reinforces the idea that the user’s mental model may not be entirely misaligned with Git’s design.
