This is the third patch in Harald Nordgren’s seven-part `git branch --delete-merged` series, which is now implementation-complete and ready for merging. The series introduces a safe, automated way to clean up local branches that have been merged into their upstream, with multiple safety mechanisms and filtering options.

This specific patch adds a new `DELETE_BRANCH_SKIP_UNMERGED` flag to the branch-deletion API. When this flag is set, `delete_branches()` and `check_branch_commit()` will silently skip any branch that isn’t fully merged, rather than stopping with an error and suggesting the user run `git branch -D`. This is a preparatory change for the `--delete-merged` command (introduced in patch 5/7), which needs to process many branches at once and shouldn’t fail on the first unmerged branch. Existing callers like `git branch -d` are unaffected.

The change is small and mechanical: the patch adds the new flag to the `enum delete_branch_flags`, splits the flags into named booleans at the start of each function, and wraps the existing error-and-advice block in a conditional so it only runs when `skip_unmerged` is false. The rest of the logic is unchanged.

This patch is part of a well-structured series that has already resolved all design questions, including the stacked-branch protection mechanism (which prevents deleting branches that are still needed as upstreams for unmerged branches). The series is thoroughly tested and addresses a real workflow pain point—safe automated branch cleanup—with careful attention to edge cases. The flags-based API refactoring (started in patch 2/7) makes the code more extensible and consistent, and this patch is a straightforward extension of that work.
