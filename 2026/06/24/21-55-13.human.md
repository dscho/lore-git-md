This is the first patch in Harald Nordgren’s v2 usability series, targeting a common mistake when setting upstream branches. The patch improves error messages for the case where a user runs `` `git branch --set-upstream-to=origin main` `` (missing slash) instead of `` `git branch --set-upstream-to=origin/main` ``. The v2 refinement now only suggests the correct `<remote>/<branch>` form when the remote-tracking ref (`origin/main`) actually exists, addressing Junio C Hamano’s critique that the original advice was too broad.

The implementation adds a helper function `die_if_upstream_looks_like_remote()` in `builtin/branch.c` that checks for a missing slash, verifies the remote is configured, and confirms the remote-tracking ref exists. The advice is gated on the new `advice.setUpstreamFailure` config option and only triggers when the remote-tracking ref is present, reconstructing the user’s likely intent as setting upstream for the current branch. Test coverage in `t/t3200-branch.sh` exercises the happy path, cases where the remote-tracking ref doesn’t exist, and edge cases like slashed branch names.

The patch is well-crafted, with clear separation of concerns and no performance penalty when advice is disabled. The narrowed scope—advice only when the remote-tracking ref exists—makes the suggestion more precise, though it remains the most debated aspect of the series. D. Ben Knoble’s earlier review suggested the current error message can still mislead users even when the remote-tracking branch exists, but this refinement limits advice to cases where it’s most likely correct. The patch is ready for broader review beyond the maintainer’s feedback.
