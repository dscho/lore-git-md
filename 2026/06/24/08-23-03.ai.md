This is a security-hardening patch series for the reftable backend, addressing multiple potential vulnerabilities in parsing corrupted reftable files. The series consists of 11 patches from Patrick Steinhardt, motivated by an initial report of an out-of-bounds write vulnerability (though not remotely exploitable, as reftables are not transferred over the network).

The patches fix a range of issues uncovered by a new fuzzer: out-of-bounds reads/writes, NULL pointer dereferences, uninitialized memory usage, and cases where the code would call `abort()`. Specific problems include binary search on empty ranges, invalid ref value types, bogus block sizes/restart counts, and truncated tables. The series also introduces the fuzzing infrastructure itself (libFuzzer support in Meson, an oss-fuzz target, and CI integration) alongside the fixes.

Key technical details: the fixes touch `reftable/basics.c`, `reftable/block.c`, `reftable/record.c`, and `reftable/table.c`, with corresponding unit tests added to `t/unit-tests/`. The fuzzer (`oss-fuzz/fuzz-reftable.c`) is now capable of running for 2+ hours without finding new issues. While the vulnerabilities require local disk access to exploit, the hardening is thorough and addresses edge cases systematically.

This is part of the reftable backend effort, which has been ongoing for several years. The series appears well-scoped and motivated, with clear test coverage for each fix. The inclusion of fuzzing infrastructure suggests a proactive approach to preventing regressions. Given Patrick's role as a primary reftable contributor and the security-sensitive nature of the fixes, this series is likely to receive close attention.
