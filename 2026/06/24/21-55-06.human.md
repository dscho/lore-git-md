This is the final patch in Harald Nordgren’s **`git branch --delete-merged`** series, now in its 18th iteration and ready for merging. The patch adds `--dry-run` support to the new `--delete-merged` subcommand, allowing users to preview which branches would be deleted before committing to the operation.

The implementation is straightforward: when `--dry-run` is combined with `--delete-merged`, Git prints a "Would delete branch <name>" message for each candidate branch and exits without modifying any refs. The output mirrors the real deletion output exactly, including the same filtering logic (merged status, stacked-branch protection, opt-out config, etc.), so users can trust the preview. The flag is rejected if used without `--delete-merged`, preventing accidental misuse.

The patch touches three files:
- **Documentation/git-branch.adoc**: Adds a brief description of `--dry-run` under the `--delete-merged` section.
- **builtin/branch.c**: Introduces the `DELETE_BRANCH_DRY_RUN` flag, extends `delete_branches()` to handle dry-run mode, and adds the command-line option. The dry-run logic is cleanly integrated into the existing flags-based API (introduced in earlier patches).
- **t/t3200-branch.sh**: Expands the test suite to verify dry-run output matches real deletion output and rejects `--dry-run` without `--delete-merged`.

This is a **well-crafted, low-risk addition** that addresses a common user need (previewing destructive operations). The implementation is consistent with Git’s existing `--dry-run` patterns (e.g., in `git clean` or `git rebase`), and the test coverage is thorough. The patch completes the series, which has already resolved all design questions—including the stacked-branch protection refinement—and is now **implementation-complete**. No further changes are expected.
