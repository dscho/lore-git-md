This is the fourth and final patch in Harald Nordgren’s `git history squash` series (v5), implementing the `--reedit-message` feature. The patch enables users to re-edit the squash commit message using *all* folded-in commit messages as a template, mirroring the behavior of `git rebase -i` when squashing commits.

The implementation adds a new helper function, `build_squash_message()`, which gathers the messages of every commit in the range (oldest first) and constructs a combined template for the editor. The messages are collected *before* the descendant walk to avoid interference from flags set during the walk. The patch also updates the documentation to clarify that `--reedit-message` now includes all folded-in messages, not just the oldest commit’s message.

The test coverage is thorough, verifying that:
- The editor template includes all folded-in commit messages (subjects and bodies).
- The combined message is correctly trimmed and formatted.
- The operation aborts if the user leaves the message empty (matching `git commit` behavior).

This patch builds on the plumbing added in patch 2/4 (`commit_tree_ext()` with a `message_template` parameter) and completes the `--reedit-message` feature. The series is now code-complete, with all prior feedback addressed, and ready for Junio’s final assessment. The implementation is clean, well-tested, and aligns with Git’s existing UX patterns.
