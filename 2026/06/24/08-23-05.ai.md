This is the second patch in Patrick Steinhardt’s 11-patch security-hardening series for the reftable backend. It introduces a new fuzzer (`oss-fuzz/fuzz-reftable.c`) that exercises the reftable parsing code by feeding it arbitrary byte sequences.

The fuzzer is minimal but thorough: it creates a block source from the fuzzer-provided data, initializes a reftable table, and then iterates over ref records, log records, and raw blocks. This covers the three main entry points into the reftable parser (`reftable_table_init_ref_iterator`, `reftable_table_init_log_iterator`, and `reftable_table_iterator_init`). The fuzzer is wired into both the Makefile (`FUZZ_OBJS`) and the Meson build (`oss-fuzz/meson.build`), and is added to the CI script (`ci/run-build-and-minimal-fuzzers.sh`) so that it runs in every pipeline.

No new symbols or public APIs are introduced; the fuzzer is purely an internal testing tool. The commit message is terse but sufficient: it states the purpose (exercising reftable parsing) and defers the fallout (the actual security fixes) to subsequent patches. The patch itself is mechanical and uncontroversial; its value lies in enabling the fixes that follow.
