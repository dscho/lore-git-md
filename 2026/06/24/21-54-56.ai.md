This is the v15 revision of Harald Nordgren’s `--track=fetch` feature series, which extends `` `git checkout` `` and `` `git switch` `` with a `--track=fetch` mode to automatically fetch the remote branch before creating a local tracking branch. The series remains split into two patches: the first exposes tracking remote lookup helpers from `branch.c`, and the second implements the feature using those helpers.

The v15 update is a direct response to Phillip Wood’s v14 review, addressing all requested code nits and test improvements. The commit message now leads with a clearer workflow motivation—framing the feature as a way to reduce merge conflicts and duplicated work by ensuring users start from the latest remote tip rather than a potentially stale local copy. The implementation drops `RESOLVE_REF_NO_RECURSE` to match `` `git checkout` ``’s behavior for the same ref, removes redundant `check_refname_format()` checks, switches to brace initialization (`= {0}`) instead of `memset()`, and uses `refs_ref_exists()` with `NULL` OID out-params. Error messages are split onto separate lines for better readability, and the test suite is significantly streamlined: six redundant tests are removed, `test_cmp_rev` replaces manual revision comparisons, and test titles are reworded to avoid confusing terminology (e.g., “namespace” → “remote-tracking prefix”).

The series is now technically complete, with all substantive feedback incorporated. Junio’s earlier technical approval still applies, but the maintainer’s final decision hinges on whether the workflow benefits—automating the fetch step to align with user expectations—justify the feature’s inclusion. The v15 changes do not alter the core design or address Junio’s fundamental concerns about network operations during checkout without user preview, but they do make the implementation cleaner and the test suite more maintainable. The author’s reworked commit message explicitly ties the feature to user expectations and existing Git behaviors (e.g., `` `git clone` `` and `` `git pull` ``), which may help build broader support. No new technical objections are expected, but the series remains in a holding pattern pending Junio’s assessment of the feature’s merit.
