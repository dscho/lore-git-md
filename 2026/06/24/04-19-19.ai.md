This is the fifth patch in Justin Tobler’s six-patch series refactoring `git-receive-pack` to use ODB transactions instead of `tmp_objdir`. It introduces the `odb_transaction_env()` interface, which provides the environment variables needed by child processes (like `git-index-pack` or `git-unpack-objects`) to access the transaction’s staging area. The patch adds a new `env` callback to the `odb_transaction` struct and implements it for the "files" backend by delegating to `tmp_objdir_env()`. No user-facing behavior changes; this is purely infrastructure plumbing for the ODB abstraction effort.

The patch touches three files: `object-file.c` (adding the `odb_transaction_files_env` callback), `odb/transaction.c` (implementing the public `odb_transaction_env()` function), and `odb/transaction.h` (declaring the new interface and documenting its contract). The changes are mechanical and follow the pattern established in earlier patches: the "files" backend’s callback ensures the transaction is prepared before returning the environment, and the public function safely handles NULL transactions. The commit message is concise but clear about the purpose: enabling child processes to participate in the transaction.

This patch is a logical continuation of the series’ goal to make `receive-pack` backend-agnostic. By exposing the transaction environment, it paves the way for the follow-up work mentioned in the cover letter—making object writes themselves backend-agnostic. The implementation is straightforward and aligns with the error-propagation changes in patches 2–4. No test coverage is mentioned, but the interface is simple enough that correctness likely depends on the existing test suite exercising `receive-pack` and its child processes.

The patch is uncontroversial and fits cleanly into the ODB abstraction effort led by Patrick Steinhardt. It introduces no new dependencies or edge cases, and the interface design (NULL-terminated array, owned by the backend) is consistent with Git’s conventions for environment handling. The only potential point of future discussion might be whether the `env` callback should be mandatory for all backends, but the current design (allowing NULL) is flexible enough for now. This is a small but necessary step toward the larger goal of pluggable ODB backends.
