This is the fifth patch in the v2 series optimizing `paint_down_to_common()` for one-sided histories. It introduces a `paint_state` struct to track per-side commit counters (PARENT1-only, PARENT2-only, and pending merge-base candidates) and replaces the old `nonstale_queue` termination logic with a counter-based approach.

The patch refactors `paint_down_to_common()` to use the new `paint_state` struct, which wraps a `prio_queue` and maintains three counters: `p1_count`, `p2_count`, and `pending_merge_bases`. These counters are updated by `paint_count_update()`, which adjusts the appropriate bucket based on a commit’s paint flags. The `paint_queue_put()` and `paint_queue_get()` helpers manage enqueueing and dequeueing commits while keeping the counters in sync. The loop now terminates when all counters reach zero, replacing the old `max_nonstale` pointer-based check with equivalent behavior.

The refactoring is purely structural and does not change the function’s behavior. The commit message confirms this by noting that trace2 step counts remain identical before and after the change. The existing `nonstale_queue` is preserved for `ahead_behind()` to avoid disrupting other callers. The documentation in `paint-down-to-common.adoc` is updated to reflect the new counter-based termination logic, replacing the old `max_nonstale` explanation.

Key technical details:
- **Files touched**: `commit-reach.c` and `Documentation/technical/paint-down-to-common.adoc`.
- **New symbols**: `paint_state` struct, `paint_count_update()`, `paint_queue_put()`, `paint_queue_get()`.
- **Behavior**: No functional change; the counter-based termination is equivalent to the old `max_nonstale` logic.
- **Test coverage**: Trace2 instrumentation from the previous patch validates that step counts remain unchanged.

This patch is a prerequisite for the final optimization (patch 7/7), which will use the per-side counters to implement the early-exit logic. The refactoring is clean and well-motivated, with clear commit message explanations and no regressions. Reviewers have already endorsed the approach, and the patch is ready for merging.
