This is the **v2 performance optimization series** for Git’s commit-reach subsystem, targeting the `paint_down_to_common()` function used in merge-base calculations. The series is **technically complete and ready to land**, with all design feedback incorporated and no remaining open questions.

The core optimization (patch 7/7) teaches `paint_down_to_common()` to terminate early when one side of the history is exhausted—no new merge-base candidates can emerge once one side’s queue is empty. This eliminates unnecessary traversal of large one-sided histories (e.g., repositories with import grafts or shallow histories), yielding **100-1000x speedups** for asymmetric queries. The optimization activates only after entering the finite-generation region, where generation numbers guarantee final paint states, ensuring correctness.

The series is **well-structured and thoroughly tested**. Patch 1/7 adds technical documentation for `paint_down_to_common()`, patches 2-3/7 introduce regression tests (including edge cases from Elijah Newren’s parallel work), and patch 4/7 adds trace2 instrumentation for deterministic step-count validation. Patches 5-6/7 refactor the code to introduce a `paint_state` struct with per-side counters, decoupling the ahead/behind logic from the non-stale queue. The final patch (7/7) implements the early-exit logic, gated by the finite-generation guard and pending merge-base check.

Key technical details:
- **Files touched**: `commit-reach.c`, `Documentation/technical/paint-down-to-common.adoc`, and test scripts (`t6099-merge-base-side-exhaustion.sh`, `t6600-test-reach.sh`).
- **New/renamed symbols**: `paint_state` struct (replaces `paint_queue` in v2), per-side counters (`p1_count`, `p2_count`, `pending_merge_bases`), `paint_count_update()`, `paint_queue_put()`, `paint_queue_get()`.
- **Behavior change**: The walk terminates early when `(!state->p1_count || !state->p2_count) && !state->pending_merge_bases` and the dequeued commit’s generation is finite. The check is encapsulated in `paint_queue_get()`.
- **Performance instrumentation**: Trace2 step counts (e.g., `paint_down_to_common steps 9` vs. `80` in git.git) and wall-clock benchmarks (e.g., `7.26s -> 88ms` for a 2.6M-commit monorepo) validate the optimization.

The series addresses all feedback from v1, including:
- **Structural dispute resolution**: The ahead/behind decoupling patch was dropped; `nonstale_queue` is preserved for `ahead_behind()`.
- **Termination condition**: Finalized as `(!p1_count || !p2_count) && !pending_merge_bases`, gated by `last_gen < GENERATION_NUMBER_INFINITY`.
- **State encapsulation**: `last_gen` is derived from the dequeued commit in `paint_queue_get()`, eliminating external parameters.
- **Patch ordering**: Documentation and tests appear before the optimization, demonstrating correctness with the old logic first.
