This is the first patch in the v8 iteration of a GSoC series that extracts path-formatting logic from `builtin/rev-parse.c` into a new `format_path()` helper in `path.c`. The patch refactors `rev-parse` to use the shared helper while preserving exact backward compatibility, replacing ~44 lines of duplicated logic with a single call to `format_path()`.

The core change introduces the `path_format` enum (`UNMODIFIED`, `RELATIVE`, `RELATIVE_IF_SHARED`, `CANONICAL`) and implements the helper with "replace" semantics: the caller provides an output buffer, and the function overwrites it rather than appending. This aligns with precedent in `ls-tree.c` and eliminates wasteful temporary allocations. The helper handles all edge cases—absolute/relative path conversion, canonicalization via `strbuf_realpath_forgiving()`, shared repository detection, and error conditions (via `BUG()` for invalid formats).

In `rev-parse.c`, the `print_path()` function is refactored to map the existing `format_type` and `default_type` enums to the new `path_format` enum in a single `switch` statement, improving readability and future-proofing. The patch maintains strict backward compatibility: all existing `rev-parse` output (e.g., `--git-dir`, `--show-toplevel`) remains unchanged, and the new helper is validated against the existing test suite.

Files touched: `path.c`/`path.h` (new helper and enum) and `builtin/rev-parse.c` (refactor). New symbols: `format_path()` and the `path_format` enum. The implementation addresses all prior feedback from Junio C Hamano and Phillip Wood, including API semantics and control flow refinements. This patch is the foundation for the series; the next two patches will use the helper to add new `git repo info` fields.
