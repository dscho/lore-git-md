This is a procedural update in the ongoing effort to silence translation-catalog build output during `make -s` for gitk and git-gui. Johannes Sixt (Hannes) responds to Harald Nordgren’s question about when the changes will land in `master`.

The gitk patch (1/2) is already merged into Sixt’s `j6t-testing` branch for gitk, and the git-gui patch (2/2) is effectively superseded by Sixt’s pre-existing `hn/silence-make-s` branch in git-gui. Sixt confirms that both sets of changes are now in his testing branches and will be proposed for inclusion in the upstream Git repository in the coming weeks, though not in time for the upcoming v2.55 release. The integration timing depends on the independent release cycles of gitk and git-gui, which are maintained separately from core Git.

No technical discussion remains; the thread is now focused solely on scheduling. The changes themselves are complete and align with core Git’s quiet build conventions (commit 2f12b31b746c). The key files involved are `gitk-git/Makefile` (gitk) and `git-gui/Makefile` (git-gui), with the gitk patch introducing a `QUIET_MSGFMT` helper for conditional message suppression. The behavior change—fully silent translation-catalog generation during `make -s`—is already implemented in Sixt’s branches and will propagate to upstream Git in due course.
