This is the sixth patch in Karthik Nayak’s seven-patch series extending `` `git log -L` `` to support range-scoped diff stat, whitespace checking, and the ``-G`` pickaxe. The series is now at v2, with only documentation tweaks since v1.

This patch adds support for ``--check`` (whitespace error detection) when ``-L`` is active, ensuring that only whitespace errors within the tracked line ranges are reported. The implementation reuses the existing ``line_range_filter`` infrastructure, routing ``checkdiff_consume()`` through it to forward only in-range lines for checking. A key challenge was preserving accurate file line numbers in error reports, which the patch solves by adding an optional hunk callback to the filter. This callback routes ``checkdiff_consume_hunk()`` through the filter, setting the post-image position before in-range lines are replayed. Without this, reported line numbers would count from the start of the range hunk rather than the start of the file.

The patch also gates the trailing blank-at-eof check (which scans the whole file) on the tracked ranges, ensuring that blank lines at the end of the file are only reported if they fall within the range. The ``DIFF_FORMAT_CHECKDIFF`` format is added to the ``-L`` output format allowlist in ``setup_revisions()``, and the documentation is updated to list ``--check`` among the supported formats. Test coverage in ``t/t4211-line-log.sh`` verifies that whitespace errors are correctly scoped to the tracked range, reported with accurate file line numbers, and that gaps within a single range (which would otherwise split into multiple xdiff hunks) are handled correctly.

The implementation is clean and well-motivated, addressing a real usability gap: users previously had to manually filter ``--check`` output to match their ``-L`` ranges. The patch integrates seamlessly with the rest of the series, reusing the same filter infrastructure introduced in earlier patches. The test coverage is thorough, including edge cases like multiple tracked ranges, gaps within a range, and blank-at-eof checks. This looks like a solid, uncontroversial addition that should be ready for merging once the rest of the series is reviewed.
