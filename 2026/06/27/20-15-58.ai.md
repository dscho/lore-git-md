This is a follow-up in a user support thread about a transient infinite-loop bug in `git ls-remote`.

Steffen Nurpmeso reports that the issue has disappeared: the command `` `git ls-remote https://gitlab.xiph.org/xiph/opus.git` `` now completes normally, consuming no more CPU than expected. He confirms the problem was not a network stall but a genuine busy-loop inside Git, and that it affected all repositories on the same host, not just the opus.git repository.

The email does not introduce any new technical details, patches, or configuration changes. It simply acknowledges Michael Montalbo’s earlier troubleshooting suggestions (``GIT_TRACE_CURL=1``, ``http.version=HTTP/1.1``, ``http.lowSpeedLimit``, ``http.lowSpeedTime``) and notes that Steffen will adopt those settings. The thread can now be considered resolved from the user’s perspective, although the root cause inside Git remains unidentified.
