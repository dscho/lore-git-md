This is patch 6/7 in the v2 series extending `` `git log -L` `` to support range-scoped diff stat, whitespace checking, and pickaxe operations. The patch enables ``--check`` to honor tracked line ranges, ensuring that only whitespace errors within the specified ranges are reported and that the reported file line numbers are accurate.

The implementation reuses the line-range filter infrastructure introduced in earlier patches, wrapping ``checkdiff_consume()`` to forward only in-range lines for whitespace checking. A key challenge is maintaining correct file line numbers: the filter synthesizes its own hunk headers, so the patch adds an optional hunk callback to ``line_range_filter`` to route ``checkdiff_consume_hunk()`` through it, setting the post-image position before replaying in-range lines. Without this, reported line numbers would count from the start of the range hunk rather than the start of the file. The patch also gates the trailing blank-at-eof check on the tracked ranges, preventing false positives when the blank line lies outside the range.

The patch updates ``setup_revisions()`` to allow ``DIFF_FORMAT_CHECKDIFF`` with ``-L`` and documents ``--check`` as a supported format. Test coverage in ``t/t4211-line-log.sh`` verifies that whitespace errors are reported only within the tracked range, that file line numbers are correct (including across gaps within a single range), and that the blank-at-eof check is properly scoped. The implementation is clean and aligns with the pattern established in patch 5 for stat formats, making it a natural extension of the series. No substantive review feedback has been addressed yet, but the patch looks technically sound and well-tested.
