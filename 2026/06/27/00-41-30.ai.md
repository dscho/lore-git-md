This is a **reply from Taylor Blau** addressing Junio C Hamano’s substantive review of patch 8/10 in the RFC series combining `--geometric` and `--cruft` repack modes. The patch introduces `--stdin-packs=follow-reachable` to `git pack-objects`, but Junio identified a correctness issue in the two-phase traversal logic that could retain unreachable tags and objects.

Taylor acknowledges the flaw: the current implementation marks *all* tag objects found in included packs (via `mark_included_pack_tip()`) and adds them to the pending list for the second-phase traversal, regardless of whether they are reachable from refs. This risks including unreachable objects in the output pack, undermining the goal of separating reachable and unreachable objects. He agrees the logic should be reordered to first traverse from reference tips, then mark objects as starting points only if they appear in included packs and are reachable.

The reply also corrects a minor logical error in the patch (changing `&&` to `||` for object type filtering) but focuses on the larger correctness issue. Taylor’s proposed fix—reversing the traversal order to prioritize reachability from refs—would likely require significant rework of the two-phase logic. This is a **non-trivial change** that could affect the series’ core functionality, and further iteration is expected before the patch is ready for merging. The discussion remains open, with no concrete implementation yet proposed.
