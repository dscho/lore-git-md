Core problem or goal
A regression in commit `663d7abe07ea` (http: reject unsupported proxy URL schemes, 2026-05-05) causes Git to incorrectly reject HTTPS proxy URLs (`https://...`) as unsupported, despite the code already being configured to handle them. The fix addresses a control-flow error in `set_curl_proxy_type()` where the HTTPS branch falls through to a `return -1` intended for unknown schemes.

Current status
Patch submitted; no prior versions. The fix is a minimal, self-contained change to `http.c` (two lines added) that mirrors the early returns used for HTTP and SOCKS proxies. No tests are included, as the change addresses a specific logic error rather than introducing new behavior. The regression was discovered while investigating a Coverity report about unchecked `curl_easy_setopt()` calls, which are noted as orthogonal to this fix.

- File touched: `http.c`
- Function modified: `set_curl_proxy_type()`
- New behavior: HTTPS proxy URLs are now correctly accepted and configured
- Old behavior: HTTPS proxy URLs were incorrectly rejected due to fall-through to `return -1`
- Subsystem: HTTP transport layer, specifically proxy URL validation in `get_curl_handle()`
