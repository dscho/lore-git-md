Core problem or goal
A regression in commit `663d7abe07ea` (http: reject unsupported proxy URL schemes, 2026-05-05) causes Git to incorrectly reject HTTPS proxy URLs (`https://...`) as unsupported, despite the code already being configured to handle them. The fix addresses a control-flow error in `set_curl_proxy_type()` where the HTTPS branch falls through to a `return -1` intended for unknown schemes. The function’s contract—returning an `int` to signal success or failure—is now confirmed as correct, and the original hardening intent (rejecting unsupported schemes) is preserved.

Current status
Patch submitted and settled; no prior versions. The fix is a minimal, self-contained change to `http.c` (two lines added) that mirrors the early returns used for HTTP and SOCKS proxies. Junio C Hamano’s initial suggestion to refactor `set_curl_proxy_type()` to return `void` was retracted after realizing the function must return an error code to reject unsupported proxy schemes. No tests are included, as the change addresses a specific logic error rather than introducing new behavior. The regression was discovered while investigating a Coverity report about unchecked `curl_easy_setopt()` calls, which remain orthogonal to this fix.

Key technical details
- File touched: `http.c`
- Function modified: `set_curl_proxy_type()`
- New behavior: HTTPS proxy URLs are now correctly accepted and configured
- Old behavior: HTTPS proxy URLs were incorrectly rejected due to fall-through to `return -1`
- Subsystem: HTTP transport layer, specifically proxy URL validation in `get_curl_handle()`
