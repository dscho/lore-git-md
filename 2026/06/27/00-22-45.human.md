This is the tenth patch in the v14 series implementing `git cat-file --batch-command` support for querying remote object metadata. Karthik Nayak’s review raises several concerns about the client-side implementation, focusing on documentation clarity, error handling, and architectural decisions.

The patch adds `fetch-object-info.c`, a new file that implements the client logic for the `object-info` protocol v2 command. Karthik questions the use of `git-cat-file` terminology in comments, suggesting the documentation should instead describe the function’s purpose generically to allow future users beyond `git cat-file`. He also flags missing error handling: the code does not `BUG()` if the server returns an unsupported feature (like anything other than "size"), and it silently continues when an object lacks a size value instead of failing. This design choice—intended to improve user experience by not aborting on missing data—leaves open questions about how missing values should be displayed and whether the command should report success or failure in such cases.

Architecturally, Karthik is uneasy about piggybacking on `fetch_refs_via_pack()` to send object-info requests, as it bypasses the intended contract of the transport vtable’s `fetch_refs` function. He suggests either adding a new vtable entry for object-info or at least updating the documentation to reflect this deviation. The patch also modifies `transport-helper.c` to ensure `get_refs_list_using_list()` is called even when no refs are fetched, which Karthik notes is redundant with existing code.

The review is substantive, engaging with the patch’s design and edge cases rather than just style or wording. While the series has addressed all prior feedback, these points—particularly the error-handling behavior and transport-layer integration—could spark further discussion before merging. The patch is otherwise well-structured, with clear separation of concerns and thorough input validation.
