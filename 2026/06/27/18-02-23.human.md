This is the v3 resubmission of Harald Nordgren’s usability improvement series, which makes Git’s error messages more helpful when users accidentally misformat remote/branch arguments. The series targets two common mistakes: `git branch --set-upstream-to=origin main` (missing slash) and `git push origin/main` (slash instead of space). The patches are now polished and ready for merging, with all prior feedback addressed.

The v3 changes are minor but important. The commit message for the first patch now explicitly describes the second confusing error case—when the operated-on branch *does* exist but the upstream argument is mistyped, Git reports that the requested upstream branch "origin" does not exist, leaving users just as puzzled. The test suite for the second patch has been updated to use `test_grep` instead of bare `grep`, fixing the test-lint failures Junio flagged in v2. Both patches now include brief comments at the call sites explaining why the up-front `advice_enabled()` check is redundant with the helper’s `advise_if_enabled()` call: it skips expensive ref lookups when the hint is disabled, while still ensuring the advice message includes the standard "disable this message" footer.

The implementation remains clean and focused. Each patch adds a new config option (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) and gates the advice on its value, so users who disable the hints pay no performance penalty. The detection logic is extracted into helper functions (`die_if_upstream_looks_like_remote` and `die_if_repo_looks_like_ref`), making the call sites read as single guarded lines. Test coverage in `t/t3200-branch.sh` and `t/t5529-push-errors.sh` is thorough, including edge cases like branches with slashes, unconfigured remotes, and existing paths.

The series looks well-crafted and addresses a real usability pain point. The v3 refinements resolve the last technical nits—test style and commit message clarity—while preserving the original goal. The only remaining open question is Junio’s edge case about the first patch: what happens when the local branch exists, the remote portion is invalid as an upstream, but the remote-tracking ref (`<remote>/<branch>`) exists. This is flagged as a non-blocking follow-up, but it could spark further discussion if others see it as a gap.

For a busy reader, this series is worth attention if you care about Git’s usability or error messaging. The changes are small, self-contained, and unlikely to be controversial. Junio has already queued the series in `seen`, signaling his intent to graduate it to `next` soon.
