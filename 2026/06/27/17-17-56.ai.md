This is a bugfix patch targeting the HTTP transport layer. Johannes Schindelin identifies and fixes a regression introduced in commit `663d7abe07ea` (http: reject unsupported proxy URL schemes, 2026-05-05). The regression causes Git to incorrectly reject HTTPS proxy URLs (`https://...`) as unsupported, even though the code is already configured to handle them.

The root cause is a control-flow error in `set_curl_proxy_type()`: the HTTPS branch configures the CURL handle for HTTPS proxying but then falls through to the trailing `return -1` intended for unknown schemes. The fix adds an explicit `return 0` after the HTTPS setup, mirroring the early returns used for HTTP and SOCKS proxies.

The patch touches only `http.c`, adding two lines. The commit message is clear and concise, naming the regressing commit, describing the symptom, and explaining the fix. No tests are included, but the change is small and self-contained, addressing a specific logic error rather than introducing new behavior. The regression was likely discovered while investigating a Coverity report about unchecked `curl_easy_setopt()` calls, though those are noted as orthogonal to this fix.

This is a straightforward correctness fix with no apparent controversy or edge cases. The patch is part of a GitGitGadget pull request (PR 2161), but it is a single-patch series and does not depend on other changes. The affected code path is the proxy URL validation in `get_curl_handle()`, which is used whenever Git makes HTTP/HTTPS requests through libcurl.
