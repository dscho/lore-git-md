This is the third patch in Karthik Nayak’s seven-patch v2 series extending `` `git log -L` `` to support range-scoped diff stat, whitespace checking, and the ``-G`` pickaxe. The patch fixes an off-by-one bug in the hunk headers that ``-L`` produces, making them match `` `git diff` ``’s output exactly.

The bug surfaces in two edge cases: pure insertions (old side count 0) and pure deletions (new side count 0). The hand-rolled hunk-header code was incorrectly starting the old side at line 25 in a 24-line file, whereas `` `git diff` `` would start at 24. The patch replaces the hand-rolled logic with a new helper, ``xdiff_emit_hunk_header()``, that wraps xdiff’s own hunk-header emitter. This ensures the count-0 begin is correct by construction and also drops the redundant “,1” when the count is exactly one, so ``@@ -22 +22 @@`` appears instead of ``@@ -22,1 +22,1 @@``.

The change is purely internal; no user-visible behavior changes except the bug fix. Two test fixtures (no-assertion-error and vanishes-early) are regenerated to reflect the corrected headers. The patch touches ``diff.c``, ``xdiff-interface.c``, and the test expectations, and is a prerequisite for the later stat and whitespace-checking patches in the series.
