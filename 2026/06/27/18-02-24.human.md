This is the first patch in Harald Nordgren’s v3 series improving Git’s error messages for common command-line slips. It targets the case where a user runs `` `git branch --set-upstream-to=origin main` `` (missing slash) instead of `` `git branch --set-upstream-to=origin/main` ``. The patch adds a new helper function, `die_if_upstream_looks_like_remote()`, that detects the likely mistake and suggests the correct `<remote>/<branch>` form—but only when the remote-tracking ref (`origin/main`) actually exists, ensuring the hint is relevant.

The implementation is clean and well-scoped. It introduces a new config option, `advice.setUpstreamFailure`, documented in `Documentation/config/advice.adoc`, and gates the advice on both the config setting and the existence of the remote-tracking ref. The callsite in `cmd_branch()` redundantly checks `advice_enabled()` up front to avoid unnecessary ref lookups when the hint is disabled, while still ensuring the advice message includes the standard "disable this message" footer via `advise_if_enabled()`. A comment now clarifies this redundancy as intentional, addressing Junio’s earlier readability concern.

Test coverage in `t/t3200-branch.sh` is thorough, verifying the hint appears only when the remote-tracking ref exists, doesn’t trigger for local branches, and handles slashed branch names correctly. The patch also documents a second confusing error case in the commit message: when the local branch exists but the upstream argument is mistyped, Git reports that the upstream branch "origin" does not exist, which is equally puzzling to users.

This patch is ready for merging. All feedback from v1 and v2 has been addressed, including test style fixes and commit message refinements. Junio has queued the series in `seen`, and it’s slated to graduate to `next`. The only open question is a non-blocking edge case Junio noted: what happens when the local branch exists, the remote portion is invalid as an upstream, but the remote-tracking ref (`<remote>/<branch>`) exists. That’s acknowledged as a follow-up and doesn’t affect the current implementation.
