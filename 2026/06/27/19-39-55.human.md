This is a bug report follow-up, not a patch. A user (Steffen Nurpmeso) reported that `git ls-remote` hangs indefinitely at 100% CPU when run against a specific GitLab-hosted repository (`https://gitlab.xiph.org/xiph/opus.git`). Michael Montalbo replies with troubleshooting suggestions rather than a fix.

Montalbo was able to reproduce a stall but not a full hang; he notes the repository is behind Anubis, a rate-limiting proxy, and suggests enabling `GIT_TRACE_CURL=1` to diagnose network-level issues. He also provides three configuration knobs (`http.version`, `http.lowSpeedLimit`, `http.lowSpeedTime`) that might help work around timeouts or protocol-level stalls. The tone is helpful but the email does not identify a root cause or propose a code change. If this thread continues, the next step is likely to be logs from the reporter showing where the curl trace gets stuck.
