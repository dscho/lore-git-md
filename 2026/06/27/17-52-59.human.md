This is the ninth patch in the v14 series implementing `git cat-file --batch-command` support for querying remote object metadata. The patch enables servers to advertise the `object-info` capability, currently supporting only the "size" feature, when `transfer.advertiseobjectinfo` is enabled.

Pablo Sabater responds to Karthik Nayak’s clarification question about the wire protocol format for future metadata features. The current implementation appends supported features (e.g., "size") as a space-separated list to the capability value (e.g., `object-info=size`). Pablo confirms this format will scale for additional features like "type" or "delta", which would be appended similarly (e.g., `object-info=size type`). He also proposes updating the protocol documentation in `gitprotocol-v2.adoc` to clarify that object IDs must be full (not abbreviated) and that responses omit attributes for unrecognized objects.

The exchange is purely informational and does not require code changes to this patch. The space-separated format is uncontroversial and aligns with existing Git protocol conventions. Pablo’s proposed documentation updates would improve clarity for future contributors but are not blocking for this series. The patch itself remains ready for merging, with no outstanding technical concerns.
