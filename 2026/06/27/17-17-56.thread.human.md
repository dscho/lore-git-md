This thread is about a regression in Git’s HTTP transport layer that incorrectly rejected HTTPS proxy URLs, despite the code already supporting them. The issue was introduced in commit `663d7abe07ea` (May 2026), which aimed to reject unsupported proxy schemes but inadvertently caused a control-flow error in `set_curl_proxy_type()`, making HTTPS proxies fall through to an error return.

Johannes Schindelin identified the bug and submitted a minimal two-line fix in `http.c` to correct the logic. Junio C Hamano initially suggested refactoring the function to return `void` to eliminate the error path entirely, but later retracted this idea, confirming that the function *must* return an error code to reject unsupported schemes—its original purpose. The discussion is now resolved: the original patch is correct, and no further changes are needed. The fix ensures HTTPS proxies are properly accepted while preserving the intended behavior of blocking unsupported schemes. No tests or follow-ups are required, as the change addresses a pure logic error.
