This thread is about a regression in Git's HTTP transport layer that incorrectly rejects HTTPS proxy URLs. Johannes Schindelin identified the issue—a control-flow error in `set_curl_proxy_type()` where the HTTPS branch fell through to an error return—and submitted a minimal two-line fix in `http.c`.

Junio C Hamano reviewed the patch and agreed it resolves the immediate problem but raised a broader design question: whether `set_curl_proxy_type()` should return an error at all. He noted that the pre-regression version of the function didn’t treat unsupported schemes as errors, and suggested refactoring it to return `void` instead, which would simplify the logic and prevent similar fall-through bugs. The patch itself remains uncontroversial and correct, but the discussion is now open to whether a more robust follow-up change should be made. No other participants have weighed in yet.
