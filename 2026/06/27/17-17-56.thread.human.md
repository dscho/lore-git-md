This thread is about a small but important fix to Git’s HTTP transport layer. Johannes Schindelin identified a regression in commit `663d7abe07ea` (from May 2026) that incorrectly rejected HTTPS proxy URLs, even though Git already supports them. The bug was a simple control-flow error in `set_curl_proxy_type()`: the HTTPS branch fell through to a `return -1` meant for unknown schemes. The fix—a two-line addition to `http.c`—mirrors the early returns used for HTTP and SOCKS proxies, restoring the correct behavior.

The discussion was brief but clarifying. Junio C Hamano initially suggested refactoring the function to return `void`, but after realizing the function *must* return an error code to reject unsupported schemes, he confirmed the original patch as correct. The fix was merged into `master` ahead of the Git 2.55 release, and the thread is now closed. No tests were needed, as the change addressed a specific logic error rather than introducing new behavior. The regression was discovered while investigating a Coverity report, though that issue remains separate.
