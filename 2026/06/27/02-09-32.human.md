This is a **substantive review follow-up** in the ongoing RFC series to combine `--geometric` and `--cruft` repack modes. Junio C Hamano replies to Taylor Blau’s correction of a logical error in patch 8/10, which introduces `--stdin-packs=follow-reachable` to `git pack-objects`.

The exchange clarifies a minor but important detail: Taylor initially misread Junio’s comment as a critique of the object-type filtering logic, proposing to change `&&` to `||` in the condition that skips non-commit, non-tag objects. Junio corrects this, explaining that the original `&&` is correct—blobs and trees are neither commits nor tags, so they should be skipped, while commits and tags should be processed. The `||` change would incorrectly skip *all* objects, breaking the intended behavior.

This back-and-forth does not alter the core correctness issue Junio identified earlier (the two-phase traversal logic retaining unreachable tags), but it underscores the patch’s complexity and the need for precision in low-level reachability filtering. The discussion remains focused on patch 8/10, with no new implementation yet proposed for the larger traversal-order flaw. Expect further iteration before this patch is ready.
