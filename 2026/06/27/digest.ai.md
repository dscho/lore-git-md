# The Git Mailing List Daily Digest for 2026/06/27

**The day in brief.** Saturday brought a moderate volume of traffic (50 emails across 15 threads) with a mix of long-running feature work, test fixes, and a handful of urgent bug reports. The standout developments: a critical correctness debate in Taylor Blau’s `--geometric`/`--cruft` repack series, Tian Yuchen’s libification refactoring reaching resolution, and a security inquiry about CVE-2026-34182 that turned out to be a false alarm for Git itself. Two test-suite fixes—one for `rebase --autostash` and another for `git log -L`—also advanced, while a user-reported `git ls-remote` hang mysteriously resolved itself.

## Notable threads

### `git repack --geometric --cruft`: Correctness debate stalls RFC
Taylor Blau’s 10-patch RFC to combine `--geometric` and `--cruft` repack modes hit a snag when Junio C Hamano identified a **non-trivial correctness issue** in the two-phase traversal logic of `--stdin-packs=follow-reachable`. The current implementation risks retaining unreachable tags and objects reachable only from those tags, undermining the series’ core goal of cleanly separating reachable and unreachable objects. Blau acknowledged the flaw and proposed reversing the traversal order (prioritizing reachability from refs before marking objects in included packs), but no concrete fix has been posted yet. The series remains in RFC limbo, with the integration patch (10/10) now contingent on resolving this issue. The stakes are high: this feature aims to streamline maintenance workflows, but the complexity of reachability filtering—especially around annotated tags—demands thorough review.

### Libification refactoring: `excludes_file` migration completes
Tian Yuchen’s effort to move the global `excludes_file` variable into `struct repo_config_values` reached a milestone with the submission of v4, a squashed patch addressing all prior feedback. The final version replaces the controversial `if (repo != the_repository)` guard with a stricter `repo->initialized` check, adds a destructor for heap-allocated memory, and consolidates two patches into one for clarity. Junio’s last-minute critique of the getter’s defensive programming style (silent early return vs. `BUG()`) remains unresolved, but the patch is otherwise ready for `next`. This is a foundational step in the ongoing `the_repository` removal effort, with mentorship from Christian Couder and others ensuring alignment with project conventions.

### `git replay --linearize`: Post-merge edge case surfaces
Phillip Wood and Junio C Hamano clarified a **behavioral edge case** in Toon Claes’s recently merged `git replay --linearize` feature. When replaying a merge commit that merges two divergent branches (e.g., `A->X` and `A->Y` merging at `Z`), the current implementation drops the merge and grafts only the first-parent branch (`A->X'`), leaving the other branch (`Y'`) dangling. This differs from `git rebase --no-rebase-merges`, which replays both branches to produce a fully linear history. Junio proposed a test to document this behavior, while Phillip confirmed the algorithmic difference. The discussion is now focused on whether users should have control over which branch survives, but no follow-up patch has been posted yet. The series itself is merged, so this is a post-stabilization clarification rather than a blocker.

### Usability improvements: Better error messages land
Harald Nordgren’s v3 series improving Git’s error messages for common command-line slips (`git branch --set-upstream-to=origin main` and `git push origin/main`) is now complete and queued in `seen`. The patches add config-based advice (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) that triggers only when the remote-tracking ref exists (branch case) or the remote is configured (push case). Junio’s earlier concerns about redundant advice checks and edge cases were addressed with comments and refined detection logic. The series is uncontroversial and ready for `next`, offering a clear usability win for new users.

### `git log -L`: Range-scoped diff stat and whitespace checking
Michael Montalbo (standing in for Karthik Nayak) posted v2 of a seven-patch series extending `git log -L` to support range-scoped diff stat formats (`--stat`, `--numstat`, `--shortstat`), whitespace checking (`--check`), and the `-G` pickaxe. The only change from v1 was rewording documentation to avoid the term "range-scoped" in favor of clearer phrasing like "count only lines within the tracked range." The series is technically complete, with thorough test coverage for edge cases (root commits, renames, multiple ranges) and no outstanding objections. The preparatory patches (1-3) fix bugs in the existing line-range filter, while patches 4-7 implement the new functionality by reusing the filter infrastructure. This is a natural extension of the recent `mm/line-log-cleanup` topic and should graduate to `next` soon.

## In brief

**Rebase autostash test fix** -- SZEDER Gábor and Phillip Wood endorsed a five-year-old patch to fix a fragile test in `t3420-rebase-autostash.sh`. The test incorrectly used `! grep dirty file3` to verify a file’s absence after `git rebase --quit`; the file should not exist at all. The fix replaces the `grep` check with `test_path_is_missing file3`, aligning with Git’s test suite conventions. Todd Zullinger caught a typo in the commit message ("Thighten" → "Tighten"), and the patch is now ready for merging.

**Git for Windows and Gitk build silencing** -- Johannes Sixt confirmed that Harald Nordgren’s patches to silence translation-catalog build output during `make -s` are already merged into the Git for Windows and gitk `master` branches. The changes adopt core Git’s quiet build pattern (commit 2f12b31b746c) and will land in the next release cycles for both projects.

**`greplint.pl` series: Pre-existing bug surfaces** -- SZEDER Gábor identified a pre-existing bug in `t/t3420-rebase-autostash.sh` that Michael Montalbo’s `greplint.pl` series inadvertently preserved. The test checks `file3`’s contents after `git rebase --quit`, but the file should not exist at all. Gábor referenced his 2021 patch to fix this, while Junio proposed extending `test_grep` to detect such cases. The discussion highlights a tension in automated refactoring: while `greplint.pl` improves test debuggability, it can also mask latent bugs. The series’ fate hinges on whether the tool should convert or merely diagnose.

**HTTP proxy regression fix** -- Johannes Schindelin fixed a regression in the HTTP transport layer where Git incorrectly rejected HTTPS proxy URLs (`https://...`) as unsupported. The bug was introduced in commit `663d7abe07ea` (http: reject unsupported proxy URL schemes) and stemmed from a control-flow error in `set_curl_proxy_type()`. The fix adds an explicit `return 0` after HTTPS proxy setup, mirroring the early returns for HTTP and SOCKS proxies. The patch is small, self-contained, and ready for `next`.

**CVE-2026-34182: False alarm for Git** -- A security inquiry about CVE-2026-34182 (a critical OpenSSL flaw) turned out to be a false alarm for Git. Todd Zullinger clarified that the vulnerability affects CMS (Cryptographic Message Syntax) functionality, which Git does not use directly. The only potential exposure would be if Git were configured to use `gpgsm` for x509 signatures, but `gpgsm` is not impacted. The inquiry also revealed that the Git project does not distribute binaries—the Windows installer is produced by the separate Git for Windows project.

**`git ls-remote` hang: Resolved without root cause** -- A user-reported infinite loop in `git ls-remote` against `https://gitlab.xiph.org/xiph/opus.git` mysteriously resolved itself. Steffen Nurpmeso confirmed the issue disappeared without configuration changes, ruling out network stalls or rate-limiting proxies. The root cause inside Git remains unidentified, but the thread is now closed from a user-support standpoint.

## On the radar

**`git cat-file --batch-command` remote object-info series** -- Pablo Sabater’s GSoC series to implement `git cat-file --batch-command` for querying object metadata from remotes is nearing completion, but Karthik Nayak’s review of patch 10/13 raised **architectural concerns** about error handling and transport-layer integration. The current implementation silently skips objects lacking size data (returning empty strings), which Karthik argues creates ambiguity about success/failure. Pablo defended the approach as consistent with local `git cat-file` behavior, but the discussion remains open. The series is otherwise technically complete, with all other feedback addressed.
