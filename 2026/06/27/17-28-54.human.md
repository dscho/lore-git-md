This is the second iteration of a seven-patch series that extends `` `git log -L` `` to support range-scoped diff stat formats, whitespace checking, and the `` `-G` `` pickaxe. The series builds on the recent `mm/line-log-cleanup` topic, which integrated `` `-L` `` with the standard log output pipeline and added support for non-patch formats like `` `--raw` `` and `` `--name-only` ``.

The key improvements in this version are documentation clarifications. The term "range-scoped" has been replaced with more explicit phrasing like "count only lines within the tracked range" or "scoped to the tracked range," addressing feedback from Junio C Hamano on the previous iteration. The commit messages and test descriptions have been updated accordingly, making the behavior clearer without changing the implementation. The series remains technically unchanged from v1, which was already approved in principle by Junio and Michael Montalbo (the author of the underlying cleanup work).

Patches 1-3 are preparatory: they rename and clarify the line-range filter internals, fix two bugs in the existing `` `-L` `` patch output (a leaked deletion and an off-by-one hunk header), and align hunk headers with `` `git diff` ``’s format. These changes are motivated by the observation that the current filter model is cryptic and error-prone, so the patches first document and simplify it before building on it. Patches 4-7 then extract a reusable helper for range-scoped diffs and implement the new formats: patch 4 introduces `line_range_filter_diff()`, patch 5 adds stat support, patch 6 adds `` `--check` ``, and patch 7 scopes `` `-G` `` to the tracked range.

The series touches `diff.c`, `diffcore-pickaxe.c`, `revision.c`, and `xdiff-interface.c`, along with updates to the line-range documentation and extensive test coverage in `t/t4211-line-log.sh`. The exclusion of `` `--dirstat` `` and `` `-S` `` is explicitly justified in the commit messages, and the documentation now clearly distinguishes between `` `-G` `` (scoped to the tracked range) and `` `-S` `` (whole-file). The series looks well-structured, with thorough test coverage and clear explanations of the changes. The only remaining work is the agreed-upon documentation tweaks, which are already reflected in this version.
