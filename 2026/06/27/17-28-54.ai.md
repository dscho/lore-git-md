This is the second iteration (v2) of a seven-patch series extending `` `git log -L` `` to support range-scoped diff stat formats (``--stat``, ``--numstat``, ``--shortstat``), whitespace checking (``--check``), and the ``-G`` pickaxe. The series builds on the recent ``mm/line-log-cleanup`` topic, which integrated ``-L`` with the standard log output pipeline and added support for non-patch formats like ``--raw`` and ``--name-only``.

The key change since v1 is the rewording of documentation and commit messages to avoid the term "range-scoped" in favor of clearer phrasing like "count only lines within the tracked range" or "scoped to the tracked range." This addresses feedback from Junio C Hamano on patch 5, which was the only substantive review comment on v1. The implementation itself remains unchanged: the series still reuses the line-range filter to scope stat counts, whitespace errors, and ``-G`` matches to the tracked range, while deliberately excluding ``--dirstat`` and leaving ``-S`` whole-file due to architectural constraints.

Patches 1-3 are preparatory and unchanged from v1: they rename and clarify the line-range filter internals, fix two bugs in the existing ``-L`` patch output (a leaked deletion and an off-by-one hunk header), and align hunk headers with `` `git diff` ``’s format. Patches 4-7 then extract a reusable helper for range-scoped diffs and implement the new formats: patch 4 introduces ``line_range_filter_diff()``, patch 5 adds stat support, patch 6 adds ``--check``, and patch 7 scopes ``-G`` to the tracked range. The series touches ``diff.c``, ``diffcore-pickaxe.c``, ``revision.c``, and ``xdiff-interface.c``, along with updates to the line-range documentation and extensive test coverage in ``t/t4211-line-log.sh``.

The range-diff shows only documentation and commit message tweaks, with no code changes. The updated phrasing is more precise and avoids jargon, which should make the behavior clearer to users. The series looks ready for further review, with the only prior feedback already addressed. The exclusion of ``--dirstat`` and ``-S`` is explicitly justified, and the documentation now clearly distinguishes between the scoped behavior of ``-G`` and the whole-file behavior of ``-S``. The test coverage is thorough, including edge cases at range boundaries, renames, and root commits.
