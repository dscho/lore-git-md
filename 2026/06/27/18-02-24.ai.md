This is the first patch in Harald Nordgren’s v3 series improving Git’s error messages for common command-line slips. It targets the `git branch --set-upstream-to` case where users accidentally omit the slash between remote and branch (e.g., `origin main` instead of `origin/main`). The patch adds a new helper function, `die_if_upstream_looks_like_remote()`, that detects this mistake and suggests the correct `<remote>/<branch>` form—but only when the remote-tracking ref (`refs/remotes/<remote>/<branch>`) exists, ensuring the advice is actionable.

The implementation is careful and well-scoped. The helper function checks for a missing slash, verifies the remote is configured, and confirms the remote-tracking ref exists before suggesting the correction. The advice is wrapped in `advise_if_enabled()` to respect the new `advice.setUpstreamFailure` config option, and the callsite in `cmd_branch()` redundantly checks `advice_enabled()` up front to avoid unnecessary ref lookups when the hint is disabled. This redundancy is now documented with a comment to clarify its purpose, addressing Junio’s earlier readability concern.

Test coverage in `t/t3200-branch.sh` is thorough, covering the happy path (advice triggers when the remote-tracking ref exists), the disabled-advice case, the no-matching-ref case (no advice), local branch operations (no false positives), and slashed branch names (correct reconstruction). The tests use `test_grep` consistently, complying with Git’s test-lint rules.

The patch is uncontroversial and ready for merging. The only open edge case—where the local branch exists but the remote-tracking ref also exists—is acknowledged as non-blocking.
