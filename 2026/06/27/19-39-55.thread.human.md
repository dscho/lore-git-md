The thread began when Steffen Nurpmeso reported that `git ls-remote` would hang with 100 % CPU when run against the Xiph.org Opus repository. Michael Montalbo replied with diagnostic steps and suggested work-arounds—setting `http.version=HTTP/1.1` and tuning `http.lowSpeedLimit`/`http.lowSpeedTime`—but could not reproduce the issue reliably.

Steffen has now followed up to say the problem has vanished: the same command completes normally and no longer spins the CPU. He confirms the hang was a genuine busy-loop inside Git, not a network stall, and that it affected all repositories on the same host. He plans to keep the suggested HTTP settings, but the thread is effectively closed from the user’s side. The root cause inside Git remains unknown.
