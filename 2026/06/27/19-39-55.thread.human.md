This thread began when Steffen Nurpmeso reported that `git ls-remote` on the Xiph Opus repository would hang indefinitely, consuming 100% CPU. The issue was transient and resolved on its own without any changes to Git, leaving the root cause—likely external factors like an Anubis proxy or network conditions—unidentified.

Since then, Steffen has observed a different but related symptom: under the same network constraints, `git ls-remote` now fails with a low-speed timeout instead of entering a busy-loop. Adjusting `http.lowSpeedLimit` and `http.lowSpeedTime` prevents the timeout, but the command still blocks without progress feedback. Michael Montalbo had previously suggested these settings as debugging aids, not as recommended configurations. The thread remains closed from a development standpoint, with no further investigation or patches planned. The original CPU-hogging behavior has not recurred, but the underlying issue—whatever caused the transient hang—remains unexplained.
