This is the second patch in Harald Nordgren’s two-part usability series, targeting a common command-line slip in `` `git push` ``. When users mistakenly write `` `git push origin/main` `` instead of `` `git push origin main` ``, Git currently fails with a generic "not a git repository" error. This patch improves the error message to suggest the correct syntax, making it clear that a space was intended instead of a slash.

The implementation is clean and well-scoped. It adds a new config option, `advice.pushRepoLooksLikeRef`, and a helper function, `die_if_repo_looks_like_ref()`, that checks whether the argument resembles a `<remote>/<branch>` ref. The advice triggers only when the prefix before the slash matches a configured remote and the argument is not an existing path. This avoids false positives and ensures no performance penalty when the advice is disabled. The patch also includes thorough test coverage in `t/t5529-push-errors.sh`, covering edge cases like branches with slashes, unconfigured remotes, trailing slashes, and existing paths.

The patch addresses all feedback from earlier versions, including the test style fix (replacing bare `grep` with `test_grep`) that Junio flagged in v2. The callsite in `cmd_push()` now includes a comment explaining the up-front `advice_enabled()` check, which skips the remote lookup when the hint is off while still ensuring the advice message includes the standard "disable this message" footer. This matches the pattern established in the first patch and resolves Junio’s readability concern.

This is a well-crafted usability improvement that fits neatly into Git’s existing advice framework. The series is now complete, with both patches queued in `seen` and slated for `next`. The only open question is whether this pattern should eventually be expanded to other commands (e.g., `` `git fetch` ``), but that’s a discussion for another day. For now, this patch delivers a clear, uncontroversial fix for a real user pain point.
