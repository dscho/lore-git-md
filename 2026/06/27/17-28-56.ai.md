This is patch 2/7 in the v2 series extending `` `git log -L` `` to support range-scoped diff stat, whitespace checking, and the ``-G`` pickaxe. The patch simplifies the line-range filter by immediately classifying removal lines instead of buffering them, which eliminates a bug where deletions just outside the tracked range could leak into the patch output.

The change removes the ``pending_rm`` buffer and related fields (``pending_rm_count``, ``pending_rm_pre_begin``) from ``struct line_range_filter``, replacing them with direct classification of each line as it arrives. This is possible because xdiff emits removals before additions within a change, so the post-image position of the following line is already known when a ``-`` line arrives. The patch also drops the per-line counting fields (``old_count``, ``new_count``, ``has_changes``) in favor of deriving the hunk geometry from the buffered lines when flushing, which avoids potential desynchronization between the buffer and the counters.

The new ``begin_range_hunk()`` helper initializes the hunk’s ``old_begin`` and ``new_begin`` from the live image cursors at the first in-range line, replacing the previous logic that had to account for pending removals. The coordinate model is now documented in a detailed block comment on ``struct line_range_filter``, including a worked example that clarifies how removals are classified by the post-image position of the following line.

The test coverage adds three new cases: the leaked trailing deletion bug this patch fixes, the symmetric leading-deletion case (where a removal just before the tracked range is correctly included because the following line is in-range), and edge cases at the range boundaries (a change at the first and last line of the range, and a pure in-range deletion). The tests verify that the filter’s behavior matches the documented model and that the synthetic hunk headers are accurate.
