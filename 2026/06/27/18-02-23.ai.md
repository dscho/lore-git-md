This is the v3 cover letter for Harald Nordgren’s usability improvement series, which refines Git’s error messages for two common command-line slips: `git branch --set-upstream-to=origin main` (missing slash) and `git push origin/main` (slash instead of space). The series is now complete and ready for merging, with all feedback from v1 and v2 addressed.

The v3 changes are minor but important. The branch commit message now explicitly documents the second confusing error case—when the operated-on branch exists but the upstream argument is mistyped, Git reports that the upstream branch "origin" does not exist, which is equally puzzling to users. The new tests in `t5529-push-errors.sh` have been converted from bare `grep` to `test_grep` to comply with Git’s test-lint rules, resolving the style issue Junio flagged in v2. Both patches now include brief comments at the callsite explaining the up-front `advice_enabled()` gate, which skips expensive ref lookups when the hint is disabled while still ensuring the advice message includes the standard "disable this message" footer via `advise_if_enabled()`.

The implementation remains clean and focused. Each patch introduces a new config option (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) and a helper function (`die_if_upstream_looks_like_remote()` and `die_if_repo_looks_like_ref()`) to encapsulate the detection logic. The advice triggers only when the remote-tracking ref exists (branch case) or the remote is configured (push case), reconstructing the user’s likely intent. The redundant advice check in the branch patch—critiqued by Junio as potentially confusing—is now documented as intentional, ensuring consistent advice-message formatting.

The series is queued in `seen` and slated for `next`, with no outstanding technical objections. The open edge case Junio noted (where the local branch exists but the remote-tracking ref also exists) remains unresolved but is acknowledged as non-blocking. The broader question of whether config-based advice is the right long-term approach may resurface, but the current implementation is uncontroversial and addresses a clear usability pain point. Test coverage in `t/t3200-branch.sh` and `t/t5529-push-errors.sh` confirms no false positives for local branch operations or existing paths.
