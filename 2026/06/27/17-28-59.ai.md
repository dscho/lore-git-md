This is patch 5/7 in the v2 series extending `` `git log -L` `` to support range-scoped diff stat formats (``--stat``, ``--numstat``, ``--shortstat``). The patch reuses the line-range filter infrastructure introduced in earlier patches to ensure stat counts reflect only the lines within the tracked range, not the whole file. It updates ``builtin_diffstat()`` to wrap ``diffstat_consume()`` with the filter when line ranges are present, and expands the allowed output format mask in ``setup_revisions()`` to accept the three stat formats with ``-L``. The documentation is updated to clarify that stat counts are scoped to the tracked range and to explain why ``--dirstat`` is deliberately excluded (its default mode measures whole-file churn, and accepting only the ``--dirstat=lines`` variant would be confusing). The test suite gains extensive coverage for range-scoped stat counts, including edge cases like root commits, renames, and multiple tracked ranges.

The implementation is straightforward and well-motivated: the line-range filter already exists, and this patch simply routes its output through the stat counters. The exclusion of ``--dirstat`` is clearly justified, and the documentation now avoids the ambiguous "range-scoped" phrasing that Junio flagged in v1. The test coverage is thorough, verifying that counts match the tracked range across commits, renames, and multiple ranges, and that untracked changes are excluded. No new helpers or data structures are introduced; the patch relies entirely on the infrastructure from patches 1-4. The series remains on track for review, with the only prior feedback already addressed.
