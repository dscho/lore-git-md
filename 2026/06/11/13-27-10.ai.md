This is patch 7/10 in Patrick Steinhardt's v5 series adding a `git history drop` subcommand. The patch modifies the reset machinery to allow callers to specify the "from" commit when performing a reset operation, rather than always deriving it from HEAD.

The change adds a new `oid_from` field to `reset_working_tree_options` that callers can populate with the commit they want to reset from. When set, this overrides the default behavior of reading HEAD. The implementation is straightforward - it checks for the new option before falling back to the existing HEAD resolution logic.

This flexibility is needed for the `history drop` command's implementation, which needs to reset from a specific commit (the one being dropped) rather than HEAD. The change maintains backwards compatibility by keeping the HEAD-based approach as the default when `oid_from` is NULL.

The patch is a small but meaningful piece of the larger series, enabling more precise control over reset operations. It follows the established pattern of the reset refactoring work, with clear documentation of the new field and careful handling of the object ID copying. As with the rest of the series, this appears well-considered and ready for inclusion.
