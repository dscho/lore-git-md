This is a performance discussion about timestamp precision in Git's worktree operations. brian m. carlson responds to Junio C Hamano's concerns about runtime detection of nanosecond timestamp support (USE_NSEC) by proposing explicit user control via `git update-index` options.

The email suggests adding `--use-nsec` and `--no-use-nsec` flags to `git update-index`, similar to the existing untracked-cache controls, allowing users to manually enable the feature when they know their filesystem supports it. As a fallback for auto-detection, they propose a `--test-use-nsec` option that would check system information (via `uname` and `statfs`) to determine safe configurations exist.

This builds on the ongoing thread where Jeff King identified timestamp precision as the root cause of worktree diff slowdowns, with Junio having expressed concerns about reliable auto-detection. The proposal offers a middle ground between fully automatic detection and build-time configuration, though it still leaves some implementation questions open about how exactly the safety checks would work.
