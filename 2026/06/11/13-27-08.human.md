This is patch 5/10 in Patrick Steinhardt's v5 series introducing a `git history drop` command. The patch adds a dry-run mode to the reset machinery, which will be used by the new drop command to check whether an operation would succeed before actually performing it.

The changes introduce a new `RESET_WORKING_TREE_DRY_RUN` flag that prevents updates to the working tree and index when set. The implementation carefully handles the index state - using a scratch index for dry runs to avoid modifying the real index, while still performing all the same validation checks. The patch touches core reset functionality in reset.c and adds the new flag definition to reset.h.

This appears to be a well-considered addition that follows established patterns in Git's codebase. The dry-run capability will be useful not just for the history command but potentially for other callers of the reset machinery in the future. The patch has already been reviewed positively in previous iterations of the series.
