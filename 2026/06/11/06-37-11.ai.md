Performance optimization discussion about benchmark reporting style. Jeff King (Peff) continues the conversation with D. Ben Knoble about how much detail to include in performance-related commit messages, specifically regarding Tamir Duberstein's `git describe` optimization patch.

Peff acknowledges the academic convention of detailed benchmark reporting but argues for a more concise approach in Git commit messages. He suggests the key is presenting the minimal set of details needed to understand the performance impact, noting that humans naturally filter irrelevant information while automated tools tend to include everything. The email references René Scharfe's commit messages as good examples of balanced performance reporting.

This is a stylistic follow-up to the now-completed `git describe` optimization series, which has already addressed all technical feedback. The discussion reflects broader project norms around commit message writing rather than any substantive issue with the patch itself. Peff's position suggests favoring readability and focus over exhaustive reproducibility details in this context.
