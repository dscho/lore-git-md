Documentation patch addressing AsciiDoc rendering of octothorpe (#) characters in Git's man pages. Jean-Noël Avila follows up on Jeff King's investigation of HTML rendering inconsistencies by proposing a fix to Git's AsciiDoc configuration files.

The patch modifies the `[literal-inlinemacro]` definitions in both `asciidoc.conf.in` and `asciidoctor-extensions.rb.in` to explicitly include the octothorpe character (#) as a valid keyword character. This ensures proper `<code>` markup for # symbols in documentation, particularly in command synopses where they appear (like in `git-config`'s `--comment` option).

The changes touch three key areas:
1. DocBook backend configuration for man pages
2. XHTML11 backend configuration for HTML output
3. Asciidoctor extension handling

This is part of the ongoing documentation synopsis-style conversion effort and specifically addresses the rendering issue identified during the git-config documentation fixes. The solution involves modifying the complex regular expressions that handle literal text formatting, adding # to the character classes that trigger code formatting.

The patch appears technically sound and builds on prior discussion where Jeff King identified the root cause in Git's custom asciidoc.conf file. It represents the final piece needed to properly handle octothorpes in documentation after the earlier decision to use backtick escaping.
