This is patch 9/10 in Patrick Steinhardt's v5 series introducing the `git history drop` subcommand. The patch refactors reference update logic in the history command by splitting it into two distinct phases: computing pending updates and applying them.

The change separates `handle_reference_updates()` into:
1. `compute_pending_ref_updates()` - Determines which refs need updating by analyzing the revision walk results
2. `apply_pending_ref_updates()` - Executes the actual ref transactions with the computed updates

This prepares for future work where these phases may need to be handled separately. The split maintains all existing functionality while making the control flow more explicit. The patch follows the series' pattern of careful refactoring with attention to edge cases and backwards compatibility.

Key technical details:
- Moves ref update computation into its own function that populates a `replay_result` struct
- Creates new function to handle the transaction creation and execution
- Preserves all existing error handling and dry-run support
- Maintains the same behavior for HEAD and branch updates
- Keeps the same memory management patterns (alloc/free of transaction and result)

The change is mechanical and well-contained, touching only builtin/history.c. It builds on the series' previous work modernizing the reset machinery and aligns with Git's ongoing architectural improvements around reference handling.
