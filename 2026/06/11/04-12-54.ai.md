This is a follow-up in the thread proposing a global `followRemoteHEAD` configuration option. Matt Hunter responds to Jeff King's review, confirming alignment on implementing the feature in the `fetch.*` namespace (matching the `fetch.prune` precedent) rather than `remote.*`.

Hunter makes two key technical decisions:
1. Prefers `fetch.followRemoteHEAD` over `remote.followRemoteHEAD` for consistency with existing configuration patterns
2. Proposes omitting support for the "warn-if-not-$branch" value in the global setting, arguing this per-branch warning is too remote-specific for a default configuration

The email reveals an interesting edge case about remote definition semantics - that any configured key (even without a URL) makes a remote "exist" in Git's model. While tangential to the main proposal, this detail could inform future discussions about remote configuration behavior.
