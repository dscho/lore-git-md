This is part 6 of Patrick Steinhardt's v5 series introducing the `git history drop` command, which focuses on refactoring Git's reset machinery. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to explicitly control whether HEAD should be updated during reset operations, rather than the previous approach of disabling all reference updates.

The change makes the API more consistent by pairing with the existing `UPDATE_ORIG_HEAD` flag, and includes a BUG() check to prevent invalid combinations where ORIG_HEAD would be updated without HEAD. The patch updates all existing callers in rebase.c and sequencer.c to use the new flag appropriately.

This is a mechanical but important change that improves the reset API's clarity and safety. The implementation looks solid, with thorough updates to all call sites and clear documentation of the new flag. The patch received positive feedback from Phillip Wood, who suggested this approach in an earlier iteration. As part of the larger series that's already received extensive review, this change appears ready for inclusion.
