This is patch 3/7 in Patrick Steinhardt's v2 series to eliminate global state in setup.c, continuing the `the_repository` removal effort. The patch removes the `git_work_tree_cfg` global variable, which was previously used to track worktree configuration across setup.c and builtin/init-db.c.

The key changes are:
1. The worktree configuration is now accessed directly from the repository format structure rather than through the global variable
2. Memory management is carefully handled - when the repository format check fails (`has_common` case), the candidate work tree path is explicitly freed to maintain the same behavior as when the global was implicitly set to NULL
3. All call sites are updated to reference `repo_fmt->work_tree` instead of the global

The patch demonstrates Patrick's characteristic thoroughness in maintaining identical behavior while removing global state. The commit message clearly explains the rationale for the memory management change, addressing Justin Tobler's earlier feedback about this edge case. This continues the series' pattern of mechanical but careful refactoring of core repository setup code.
