This is patch 6/10 in Patrick Steinhardt's v5 series introducing the `git history drop` subcommand, part of the broader `the_repository` removal effort. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to explicitly control whether HEAD should be performed during resets, rather than the previous approach of disabling all reference updates.

The change makes the reset API more precise by allowing callers to specify exactly which references should be updated (HEAD and/or ORIG_HEAD) rather than using a blanket "no ref updates" flag. The implementation includes a BUG() check to prevent invalid combinations (updating ORIG_HEAD without HEAD) as suggested by Phillip Wood. All existing callers in rebase.c and sequencer.c have been updated to explicitly request HEAD updates where needed.

The patch follows established patterns for reset machinery changes and maintains backwards compatibility while making the API more flexible for new use cases like the upcoming `git history drop` command. The changes are mechanical but important for the series' goal of enabling selective reference updates during history modifications.
