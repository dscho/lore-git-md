This is the fifth version of Patrick Steinhardt's patch series introducing a `git history drop` subcommand, building on the experimental `git history` command. The series now consists of 10 patches that have evolved through several rounds of review.

The `drop` subcommand removes a specified commit from history and replays descendant branches on top of its parent. The implementation required refactoring parts of Git's reset machinery to support this operation, including:

1. Modernizing the reset API (renaming `reset_head()` to `reset_working_tree()`)
2. Adding dry-run capability
3. Splitting reference updates into compute/apply phases
4. Adding explicit HEAD update control with a new RESET_WORKING_TREE_UPDATE_HEAD flag
5. Implementing proper handling of dirty indexes and cache tree updates

Version 5 specifically addresses Phillip Wood's feedback by adding a BUG() check when UPDATE_ORIG_HEAD is set without UPDATE_HEAD, preventing an invalid flag combination. The series has received positive feedback from reviewers, with Junio C Hamano approving the reference update splitting changes and Phillip Wood confirming the mechanical changes look good.

The implementation is thorough, with 537 lines of test coverage across 4 test scripts, and touches several core components including builtin/history.c, refs.c, reset.c, and read-cache.c. The changes follow established patterns from other refactoring efforts and align with ongoing work like `the_repository` removal.

This appears to be a well-considered addition to the history command, with careful attention to edge cases and backwards compatibility. Given Patrick's track record with this command and the positive review feedback, this version seems likely to be merged.
