This is patch 8/10 in Patrick Steinhardt's v5 series adding a `git history drop` subcommand. The patch fixes an assumption in the reset machinery that the index is always clean when `reset_working_tree()` is called.

The change modifies when the cache tree update is skipped during a reset operation. Previously, the code always skipped recomputing the cache tree based on an assumption that callers (rebase and sequencer) would only use it with a clean index. However, the new `history drop` command will call this with a potentially dirty index, so the patch now only skips the cache tree update for hard resets where we know the index will be clean afterward.

The change is straightforward - it moves the `skip_cache_tree_update` flag to only be set for hard resets, and similarly only calls `prime_cache_tree()` in that case. The commit message notes this was a negligible performance optimization anyway, so the change shouldn't impact performance meaningfully.

This is a necessary preparation for the `history drop` functionality while maintaining existing behavior for other callers. The patch follows the series' pattern of carefully updating reset machinery to support new use cases while preserving backwards compatibility.
