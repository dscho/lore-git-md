This is the third iteration of a feature patch from Junio C Hamano adding a `--rename` option to `git update-ref`. The patch continues the effort to provide low-level ref renaming capability while preserving reflogs, with Junio's integration workflow for managing "evil merges" as the primary use case.

The v3 changes focus on documentation improvements based on Patrick Steinhardt's feedback:
1. Simplified commit message to be more direct about redirecting users to `git branch -m` for branch renames
2. Removed mention of `--[no-]deref` from the synopsis since those flags don't apply to renames
3. Reworded the documentation to better distinguish between the plumbing behavior and higher-level branch operations

The core functionality remains unchanged - the command renames refs atomically with their reflogs, failing if the old ref doesn't exist or new ref already exists. The implementation still excludes batch/`--stdin` mode due to transaction API limitations, which Junio notes will require future refactoring.

Test coverage verifies the basic rename operation, error cases, and reflog preservation. The patch appears technically sound and well-tested, with the documentation now clearly framing this as a plumbing command not meant for casual branch renaming. The thread shows the patch converging toward acceptance after substantive review engagement in previous iterations.
