This is the final patch in Patrick Steinhardt's v5 series introducing the `git history drop` subcommand, completing the implementation of this new history-editing capability. The command allows removing a commit from history while replaying its descendants on top of its parent.

The implementation is thorough, with 537 lines of test coverage across various scenarios:
- Basic commit dropping functionality
- Handling of root and merge commits (currently rejected)
- Working tree and index updates when HEAD moves
- Dry-run mode and conflict detection
- Empty commit handling options (drop/keep/abort)
- Reference update control (branches vs HEAD only)

Notable technical aspects:
- First `git history` command modifying both index and working tree
- Builds on refactored reset machinery from earlier patches
- Integrates with the reference update phase separation
- Carefully handles edge cases like dirty working trees

The patch appears production-ready, with all prior review feedback addressed.
