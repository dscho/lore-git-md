This is patch 9/10 in Patrick Steinhardt's v5 series introducing the `git history drop` command, which removes commits from history while replaying their descendants. The series has already undergone extensive review and is now in its final form.

The current patch refactors the reference update handling in the history command by splitting it into two distinct phases: computing which refs need updates (gathering the data) and applying those updates (executing the transaction). This separation makes the code more modular and prepares for future enhancements where these operations might need to be handled separately.

The changes are mechanical but important for the command's architecture:
- Extracts the ref-gathering logic into `compute_pending_ref_updates()`
- Moves transaction handling to `apply_pending_ref_updates()`
- Keeps the original `handle_reference_updates()` as a wrapper for compatibility
- Maintains all existing functionality while making the control flow clearer

This follows the pattern seen elsewhere in the series of careful, incremental refactoring to support the new `drop` subcommand's needs while keeping the code maintainable. The patch has no user-visible changes but improves the internal structure in a way that will enable future work.
