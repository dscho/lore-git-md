This is patch 3/10 in Patrick Steinhardt's v5 series introducing the `git history drop` command, focused on refactoring Git's reset machinery. The patch renames `reset_head()` to `reset_working_tree()` to better reflect its actual functionality, as the function's purpose is to reset the working tree to a specific commit rather than just updating HEAD.

The change is mechanical but touches several key components: builtin/rebase.c, reset.c, reset.h, and sequencer.c. The rename was suggested by Phillip Wood in prior review feedback. The patch updates all callers to use the new function name and renames the associated `reset_head_opts` struct to `reset_working_tree_options`.

This is part of the broader preparation work needed for the `git history drop` functionality, which requires more flexible control over HEAD updates during reset operations. The change aligns with Git's ongoing codebase modernization efforts, though it doesn't yet implement the new flag behavior - that comes in subsequent patches.

The patch appears straightforward and well-contained, with no functional changes beyond the rename. Given that it addresses prior review feedback and comes from an established contributor, it seems likely to be accepted as part of the larger series.
