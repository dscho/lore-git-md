This is the final patch in Patrick Steinhardt's v5 series introducing the `git history drop` subcommand, completing the implementation of this new history-rewriting capability. The patch adds the core `drop` functionality to remove a commit from history while replaying its descendants on top of its parent. Key aspects:

- Implements the actual drop operation by building on the reset machinery refactoring from earlier patches in the series
- Handles working tree and index updates when HEAD moves as a result of the drop
- Prevents dropping root commits (which could leave refs empty) and merge commits (not yet supported)
- Includes extensive test coverage (537 lines) verifying edge cases like:
  - Conflict detection when local changes would be overwritten
  - Behavior with empty descendants (controlled by --empty flag)
  - Correct handling of staged/unstaged changes
  - Dry-run mode operation
  - Bare repository support

The implementation is thorough and builds on the preparatory work in the previous 9 patches, particularly the reset API modernization and reference update phase separation. The patch maintains consistency with the existing `git history` command's limitations (no merge commit support) while adding this new operation.
