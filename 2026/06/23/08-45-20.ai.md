This is a bugfix patch targeting the GPG signature interface. The patch corrects the behavior of a helper function that was incorrectly stripping *all* carriage return (`\r`) characters from GPG signature output, even when they were not part of a Windows-style `\r\n` line ending. The fix restricts the stripping to only those `\r` characters that immediately precede a line feed (`\n`), and renames the function from `remove_cr_after` to `strip_cr_before_lf` to better reflect its intended behavior.

The change is confined to `gpg-interface.c` and updates two call sites: one in `sign_buffer_gpg` and one in `sign_buffer_ssh`. The commit message is clear and the rationale is sound: the original implementation was over-aggressive and could corrupt signature data by removing `\r` characters that were not part of line endings. The patch is small (18 lines changed), well-scoped, and includes a NEEDSWORK comment that it directly addresses.

This is a correctness fix with no new features or configuration knobs. It affects users on Windows (and potentially other platforms where GPG output might contain stray `\r` characters) by ensuring that only `\r\n` sequences are normalized to `\n`, preserving any standalone `\r` characters in the signature payload. The patch looks ready for review and appears to address a real, if narrow, issue.
