Here’s a concise human-readable summary of the Git mailing list thread covering Junio’s "What’s cooking" report for June 2026 (#08):

The thread is Junio C Hamano’s latest integration report ahead of Git 2.55, summarizing the state of in-flight topics. The tree is now feature-frozen, with only regression fixes and a handful of late topics expected to graduate before the second release candidate (rc2) on June 24. Two topics have already merged to `master`: a Windows-specific fix for objects larger than 4 GiB (converting ODB size fields to `size_t`) and a minor `gitattributes` typo fix for Perl scripts.

Eight new topics are under consideration for post-freeze inclusion, though most are still in early review. The most technically significant is Patrick Steinhardt’s ODB abstraction stack—18 patches refactoring the packed object source into a proper `struct odb_source`, with follow-ups that generalize connectivity checks, move libgit.a sources into a `lib/` directory, and eliminate global state in `setup.c`. These changes lay groundwork for promisor object support in non-packfile repositories. Other notable new work includes Kristoffer Haugsbakk’s optimization to terminate merge-base walks early for one-sided histories, and Taylor Blau’s fix for `--incremental --base` in `git multi-pack-index write`.

The report also highlights two user-facing features cooking in `next`: `git branch --delete-merged` (Hannes Sixt) to clean up local branches already merged to their upstream, and `git cat-file --batch-command remote-object-info` (Patrick Steinhardt), which lets clients request object metadata (like size) from a remote server without downloading the object. The experimental `git history drop` subcommand (also from Patrick) is another addition, allowing users to remove a commit and replay its descendants onto its parent.

Three stalled topics remain unresolved after a month of silence, while the bulk of the report (25 topics) describes work still in progress. No security or data-corruption issues are flagged—this cycle’s focus is on performance, correctness, and foundational refactoring. The ODB abstraction stack is the most ambitious effort, with its packed-source conversion already merged and several dependent topics queued behind it.
