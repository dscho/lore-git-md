This GSoC thread continues Siddharth Shrimali’s work on improving disk space recovery for partial clones. The latest update (week 6) refines the proposed `git maintenance run --task=gc-promisor` subcommand, which would prune unreachable promisor objects while recording them in a `.keep` file to allow re-fetching if needed. The design still targets the promisor packfile machinery and `git maintenance` scheduler, with new config keys like `maintenance.gcPromisor.enabled` and a default 30-day grace period for pruning.

No formal patches have been posted yet, but the week 6 blog post likely addresses some earlier open questions, such as how the new task integrates with existing `git maintenance` scheduling or whether additional configurability (e.g., grace period tuning) is needed. Edge cases like shallow clones and alternate object directories remain unresolved, and the author is still seeking feedback before coding begins in earnest. Christian Couder, the GSoC mentor, hasn’t weighed in yet, but wider review is expected once patches are submitted.
