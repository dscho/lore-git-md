This Google Summer of Code thread follows Siddharth Shrimali’s work to improve disk space recovery for partial clones by safely pruning unneeded promisor objects. The project centers on a new `git maintenance run --task=gc-promisor` subcommand and corresponding `maintenance.gcPromisor.enabled` config key, with a default 30-day grace period before pruning. Recent progress has finalized the per-remote `.keep`-file safety mechanism, which now includes timestamps and remote-specific markers to prevent data loss, and added a `--dry-run` flag to preview prune operations. The task is now stably integrated into the `git maintenance` scheduler, running after `gc` to avoid interference.

Performance testing has expanded to repositories with up to 15 remotes and promisor packs over 1 GB, showing minimal fetch latency increases post-prune. Edge cases like shallow clones and grafted history are still under evaluation, and open questions remain about the sufficiency of the `.keep`-file mechanism for recovery and whether additional configurability (e.g., per-remote grace periods) is needed. The design remains backward-compatible, with no changes to existing pack or index formats. While no formal patch series has been posted yet, the work continues to invite feedback from the broader Git community, with Christian Couder (the GSoC mentor) and other contributors yet to engage.
