This is the second patch in Phillip Wood's now-merged two-patch bugfix series for `git status` display during interactive rebase. It directly addresses the two long-standing correctness issues described in the cover letter: unabbreviated commit object IDs in "fixup -C" and "merge -C" commands, and incorrect replacement of refnames (like "reset main") with their pointed-to object IDs.

The patch replaces the old line-parsing logic in `wt-status.c` with a new `format_todo_line()` function that uses the shared `sequencer_parse_todo_command()` infrastructure introduced in patch 1/2. The new function implements command-specific display logic: it only attempts to abbreviate object IDs for commands that actually take them, and it tries to resolve object names as labels first (via `refs/rewritten/` detection) before falling back to object ID resolution. This prevents collisions between object IDs and ref labels, and it leaves hex-digit-only tag or branch names unchanged.

Test coverage in `t/t7512-status-help.sh` is expanded to cover "fixup -C", "merge -C", "reset", and "update-ref" commands, with the updated tests verifying that refnames are preserved and object IDs are properly abbreviated. The implementation is careful about edge cases: it handles CR-only lines (now rejected), protects against invalid object names, and uses a scratch buffer for label resolution.

The patch is well-motivated and thoroughly reviewed, with all feedback from Junio C Hamano, Elijah Newren, and Tian Yuchen incorporated. The behavioral trade-offs (CR-only line rejection and comment-detection order changes) were explicitly accepted during review, and the implementation demonstrates careful attention to backward compatibility. This is a clear bugfix that improves the usability of interactive rebase workflows.
