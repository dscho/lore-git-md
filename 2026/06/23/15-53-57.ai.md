This is the second patch in Phillip Wood's now-merged two-patch bugfix series (v4) targeting `git status` display correctness during interactive rebase. It directly addresses the two long-standing usability bugs described in the cover letter: (1) commit object IDs in "fixup -C" and "merge -C" commands were left unabbreviated, and (2) refnames (e.g., "reset main") were incorrectly replaced with their pointed-to object IDs.

The patch replaces the old `abbrev_oid_in_line()` function with a new `format_todo_line()` that uses the shared parsing infrastructure introduced in patch 1/2. The new implementation is command-aware: it only attempts to abbreviate object IDs for commands that actually take them, and it resolves labels before attempting OID abbreviation to avoid collisions. The logic is careful to preserve refnames (e.g., "main" in "reset main") and to leave tag/branch names unchanged even if they consist entirely of hex digits. The patch also aligns comment handling with the sequencer's `parse_insn_line()` by stripping leading whitespace before processing.

Test coverage in `t/t7512-status-help.sh` is expanded to cover "fixup -C", "merge -C", "reset", and "update-ref" commands, with the updated tests demonstrating the corrected behavior. The implementation touches only `wt-status.c` and the test file, leaving the parsing refactor in `sequencer.c` (patch 1/2) untouched. The series is now merged to master, so this patch represents the final state of the fix.
