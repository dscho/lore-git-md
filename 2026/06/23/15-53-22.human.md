This is the first patch in Phillip Wood’s two-patch bugfix series (v3) that corrects `git status` display issues during interactive rebase. The patch refactors the todo-command parsing logic into a new shared function, `sequencer_parse_todo_command()`, to enable consistent handling between the sequencer and `git status`. The change is mechanical and preparatory for the second patch, which will fix the actual display bugs.

The refactoring tightens input validation slightly: lines starting with a lone CR (not followed by LF) are now treated as invalid rather than comments, a change Junio C Hamano reviewed and accepted as reasonable. The order of comment detection has also swapped (concrete commands first, then comment lines), but this is purely internal and has no user-visible impact. The patch is uncontroversial and ready for merging, with all feedback from the maintainer already addressed.

This is a well-crafted refactoring that lays the groundwork for the more visible fixes in the follow-up patch. The commit message clearly explains the motivation and behavioral differences, and the code itself is clean and focused. If you care about interactive rebase usability or sequencer internals, this series is worth tracking—though the real payoff comes in the second patch.
