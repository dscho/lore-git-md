This is the cover letter for the fourth iteration of Phillip Wood's two-patch bugfix series targeting `git status` display during interactive rebase. The series is now merged to master (as noted in the thread AI summary), but this v4 submission incorporates the final review feedback before integration.

The stated goal remains fixing two long-standing correctness issues in how `git status` displays the rebase todo list: (1) commit object IDs in "fixup -C" and "merge -C" commands are no longer left unabbreviated, and (2) refnames (e.g., "reset main") are preserved instead of being incorrectly replaced with their pointed-to object IDs. The preparatory patch (1/2) refactors todo command parsing into `sequencer_parse_todo_command()` to enable shared logic between parsing and display code, addressing maintainer feedback about input validation and comment detection order.

Changes since v3 are minimal and cosmetic: a single style fix for a cast in `wt-status.c` (adding a missing space in `(const char **)`). The series base is now current master (commit 8c9303b1ff), and CI failures on the earlier base have been resolved. Phillip Wood explicitly notes that the label-before-OID-abbreviation safety check (added in v2) remains in place, preventing potential collisions between object IDs and ref labels.

The patch touches four files: `sequencer.c` (parsing refactor), `sequencer.h` (new function declaration), `wt-status.c` (display logic), and `t/t7512-status-help.sh` (expanded test coverage for "fixup -C", "merge -C", "reset", and "update-ref" commands). The implementation demonstrates careful handling of edge cases, including CR-only line rejection, hex-digit tag/branch name protection, and invalid object name gracefulness. The behavioral trade-offs (CR-only line rejection and comment-detection order changes) were accepted during review.
