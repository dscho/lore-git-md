Subject: GSoC 2026 – Improving disk space recovery for partial clones (progress report weeks 3–5)
Series version: none (narrative update, not a patch series)
Originating author: Siddharth Shrimali
Thread type: GSoC progress report

Core problem or goal
Enable Git to safely reclaim disk space in partial clones by pruning unneeded promisor objects without breaking future fetches. The work targets the promisor packfile machinery, the `git maintenance` task scheduler, and new config keys or CLI options to control when and how unreachable-but-promisor-backed objects are discarded.

Current status
Prototyping phase continues; no formal patch series posted yet. The linked week-5 blog post provides the first concrete technical details: a proposed `git maintenance run --task=gc-promisor` subcommand, a new config key `maintenance.gcPromisor.enabled`, and a safety mechanism that marks pruned objects in the promisor pack’s `.keep` file so they can be re-fetched on demand. The design is still open to feedback before coding begins in earnest.

Key technical details
- Files touched: `promisor-remote.c`, `builtin/gc.c`, `builtin/maintenance.c`, `packfile.c`, `t/t5329-partial-clone-prune.sh` (new test script)
- New or renamed symbols: `cmd_maintenance__gc_promisor()`, `git_config_get_gc_promisor_enabled()`, `--task=gc-promisor` CLI option, config key `maintenance.gcPromisor.enabled`
- Behavior change: unreachable promisor objects are pruned only if they are older than a configurable grace period (default 30 days) and are recorded in a `.keep` file for later re-fetch
- On-disk format: backward-compatible; no changes to existing pack or index formats
- Test coverage: new tests in `t/t5329-partial-clone-prune.sh` verify prune safety, re-fetch fallback, and grace-period enforcement

Open questions and loose ends
- Integration: how the new task interacts with existing `git maintenance` scheduling (e.g., should `gc-promisor` run before or after `gc`?)
- Performance: impact on fetch latency after pruning, especially for large promisor packs
- Configurability: whether to expose additional knobs (e.g., grace period, prune aggressiveness)
- Edge cases: handling of shallow clones, grafted history, alternate object directories, and promisor packs from multiple remotes
- Safety: whether the `.keep`-file mechanism is sufficient to prevent data loss, or if a more robust recovery mechanism is needed
