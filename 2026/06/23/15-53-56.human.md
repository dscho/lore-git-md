This is the first patch in Phillip Wood’s now-merged two-patch bugfix series. It refactors the interactive-rebase todo-list command parser into a new helper, `sequencer_parse_todo_command()`, so that the same logic can be reused by `git status` in the next patch. The change is mechanical and preparatory: it moves the existing parsing loop into a standalone function, switches from `starts_with_mem()` to `starts_with()` (since the input is now NUL-terminated), and tweaks how blank lines and CR-only lines are handled. The only behavioral difference is that a lone CR at the start of a line is now treated as an invalid command rather than a comment, a trade-off accepted during review. The patch touches only `sequencer.c` and `sequencer.h` and is a clean, well-motivated refactoring that lays the groundwork for the display fixes that follow.
