Subject: `git fetch --recurse-submodules` fails on dangling submodule commits

Core problem or goal
When `git fetch --recurse-submodules` encounters a submodule commit that does not exist on the remote, the entire fetch fails with a hard error, even if the missing commit is not referenced by the current tracking branch. This disrupts CI workflows and user operations by requiring manual intervention (e.g., disabling recursion or retrying fetches) to proceed.

Current status
No prior discussion or patches in this thread. The issue is newly reported with a detailed reproduction script. No decisions or agreements yet; the thread is in the problem-statement phase.

Key technical details
- **Command affected**: `git fetch --recurse-submodules`
- **Subsystems touched**: submodule handling, recursive fetch logic
- **Behavior change**: Current behavior fails the entire fetch; proposed solutions would either (1) limit recursive fetches to commits referenced by the current tracking branch or (2) treat submodule fetch failures as non-fatal.
- **Test coverage**: Reproduction script provided, involving SSH-based remotes, a superproject, and a submodule with a dangling commit on a non-tracking branch.
- **Edge case**: Missing submodule commits on non-tracking branches (common in personal/WIP branches).
