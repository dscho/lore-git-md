This is the first patch in Phillip Wood's two-patch bugfix series (v4) that refactors the sequencer's todo command parsing logic. The patch extracts the parsing code from `parse_insn_line()` into a new shared function `sequencer_parse_todo_command()`, which will be used by both the sequencer and `git status` display logic in the next patch.

The refactoring introduces several behavioral changes: it replaces `starts_with_mem()` with `starts_with()` (since the input is now NUL-terminated), and changes how blank lines and CR-only lines are handled. Previously, a line starting with CR but not followed by LF was treated as a comment; now it is rejected as invalid. The new function also reverses the order of command vs. comment detection, checking for commands before comments, which was a specific review request from Junio C Hamano.

The patch touches only `sequencer.c` and `sequencer.h`, adding the new function and its declaration. The implementation uses enum-based dispatch for todo commands and explicitly handles blank lines (NUL, CR LF, or LF). While the changes are mechanical, they establish the infrastructure needed for the next patch's display fixes and future sequencer improvements. The commit message clearly documents the behavioral differences introduced by the refactoring.
