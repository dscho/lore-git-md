This thread is about a bugfix patch that corrects an overzealous carriage-return stripping function in Git’s GPG signature interface. The function in `gpg-interface.c` was removing *all* `\r` characters, even those not part of Windows-style `\r\n` line endings, which could corrupt signature data. The patch, originally sent by DSAntonio08, renames the function to `strip_cr_before_lf` and restricts stripping to `\r` characters that immediately precede a `\n`.

Junio C Hamano reviewed the patch and identified three key issues: the commit message lacks a sign-off, the author’s real name should be used instead of a handle, and the message needs deeper historical context to justify the change. His most significant technical feedback is that the patch’s logic for skipping `\r` characters is buggy—it fails to preserve a lone `\r` at the end of the buffer. He provided a corrected version of the loop to make the special case more explicit and readable. Junio also requested that the commit message explain why the original code was written the way it was (citing specific commits from 2008, 2011, and 2021) and why it is safe to change now. The patch is now blocked on addressing this feedback before it can proceed.

The patch itself is small and well-scoped, touching only `gpg-interface.c` and updating two call sites. While it addresses a NEEDSWORK comment in the code, Junio’s review makes it clear that the commit message must go further to justify the change. No reviews or tests have been submitted yet, but future iterations will likely need regression tests to ensure the new behavior doesn’t introduce edge-case regressions. The thread is currently focused on refining the patch and its justification before further review.
