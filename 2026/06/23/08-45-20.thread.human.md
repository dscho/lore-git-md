This thread is about a small but important bugfix to Git’s GPG signature handling. The patch, authored by an unnamed contributor, fixes an over-aggressive helper function that was stripping *all* carriage return (`\r`) characters from GPG signature output, even when they weren’t part of Windows-style `\r\n` line endings. The fix narrows the behavior to only remove `\r` characters that immediately precede a line feed (`\n`), and renames the function to `strip_cr_before_lf` for clarity.

The change is confined to `gpg-interface.c` and affects two call sites in the signing code. The issue is a correctness fix—no new features or configuration options are introduced—but it could prevent subtle corruption of signature data on Windows or other platforms where GPG output might include stray `\r` characters. The patch is small, well-scoped, and includes a clear commit message explaining the rationale. So far, there’s been no review feedback, but the fix looks ready for merging once it gets attention from maintainers or GPG subsystem experts.
