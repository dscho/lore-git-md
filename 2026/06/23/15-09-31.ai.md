This is a review reply from Junio C Hamano to a bugfix patch targeting the GPG signature interface. The patch aims to correct an over-aggressive carriage-return stripping function in `gpg-interface.c` that was removing *all* `\r` characters, even those not part of Windows-style `\r\n` line endings. Junio’s review is **substantive** and identifies three key issues: a missing sign-off in the commit message, a preference for real names over handles, and a need for deeper historical context in the commit message to justify the change.

Junio’s most significant technical feedback is that the patch’s logic for skipping `\r` characters is buggy—it fails to preserve a lone `\r` at the end of the buffer. He provides a corrected version of the loop that makes the special case (skipping `\r` only when followed by `\n`) more explicit and readable. The review also requests that the commit message explain why the original code was written the way it was (citing specific commits from 2008, 2011, and 2021) and why it is safe to change now. This historical context is critical for reviewers to assess whether the fix is correct and whether it might break existing assumptions elsewhere in the codebase.

The patch itself is small (18 lines changed) and well-scoped, touching only `gpg-interface.c` and updating two call sites. The original author (DSAntonio08) addressed a NEEDSWORK comment in the code, but Junio’s feedback makes it clear that the commit message must go further to justify the change. The review does not mention testing, but future iterations will likely need regression tests to ensure the new behavior does not introduce edge-case regressions. The patch is now blocked on addressing Junio’s feedback before it can proceed.
