This is a substantive review of the third patch in Patrick Steinhardt’s three-patch series refactoring Git’s connectivity checks to generalize promisor object handling. The series is part of the ODB abstraction effort, which aims to make Git’s object storage layer backend-agnostic.

Christian Couder echoes Junio C Hamano’s earlier concern about the removal of `odb_reprepare(the_repository->objects)` in this patch. He points out that the call was originally added in commit b739d971 to handle corner cases where new packfiles might be added after the initial ODB preparation. Christian questions whether `odb_for_each_object_ext()` performs an equivalent refresh internally, and suggests the commit message should explicitly address why the original rationale no longer applies. This is a correctness issue: without the refresh, the connectivity check might miss promisor objects in newly added packs, leading to false negatives.

Beyond the `odb_reprepare()` issue, Christian finds the control flow in the refactored `check_connected()` function difficult to follow, attributing this to the function’s broad responsibilities. He proposes a preparatory refactoring that would split the logic into two smaller, focused functions: `check_connected_promisor()` (which would handle the promisor object search and return a clear status) and `check_connected_rev_list()` (which would handle the fallback rev-list check). This would make the code easier to understand and review, and would likely surface edge cases more clearly.

The review is substantive and constructive, focusing on correctness and maintainability rather than style or surface-level issues. Christian’s feedback aligns with Junio’s earlier concern, reinforcing the need for a clear explanation or fix for the `odb_reprepare()` removal. The proposed refactoring would also make the patch easier to review and less prone to subtle bugs. This is a high-signal review that Patrick will need to address before the patch can move forward.
