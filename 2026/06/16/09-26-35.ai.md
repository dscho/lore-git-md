This is the first patch in Toon Claes's v3 series introducing `--linearize` to `git replay`. It refactors the `enum replay_mode` (which had two values: `REPLAY_MODE_PICK` and `REPLAY_MODE_REVERT`) into a simple boolean `reverse` flag. The change is purely internal and does not alter behavior; it simplifies control flow by eliminating redundant enum checks and BUG() assertions, making the code shorter and easier to maintain.

The patch touches only `replay.c`, replacing every occurrence of `enum replay_mode` with `bool reverse`. The logic remains identical: when `reverse` is true, the code behaves as it did under `REPLAY_MODE_REVERT` (reverting changes), and when false, it behaves as it did under `REPLAY_MODE_PICK` (cherry-picking). The refactoring is mechanical and well-contained, with no cross-file changes or new functionality introduced.

This preparatory step was motivated by the need to simplify the codebase before adding the `--linearize` option in patch 3/3. The boolean approach was debated in earlier rounds, with Justin Tobler questioning its long-term maintainability; the consensus was that it is sufficient for the current dual-mode needs (forward/reverse) and does not preclude future extensions. All review feedback on this patch has been addressed, and it carries Dscho's Signed-off-by, indicating support. The patch is ready for merging as part of the series.
