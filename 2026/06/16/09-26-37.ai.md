This is the final patch in Toon Claes's three-part series introducing the `--linearize` option to `git replay`. It implements the core functionality that flattens merge commits into linear history by walking only first parents, effectively replicating `git rebase --no-rebase-merges` behavior on the server side.

The patch adds the `--linearize` option to the command-line interface and configuration, documents it in the man page (including its incompatibility with `--revert`), and updates the help text. The implementation modifies `replay.c` to handle merge commits by dropping them (leaving `last_commit` unchanged so their children are reparented onto the previous non-merge commit) while cherry-picking regular commits using a unified `pick_regular_commit()` helper. The test suite (`t3650-replay-basics.sh`) has been expanded with comprehensive coverage: root commit handling, `--linearize`/`--advance` combination, mutual exclusion with `--revert`, and patch preservation verification via `git range-diff`.

Key technical details include the `replayed_base` parameter added to `pick_regular_commit()` to support linearization, the `linearize` field in `struct replay_revisions_options`, and the explicit BUG() check ensuring linearization isn't used with reverse replay. The patch maintains compatibility with Johannes Schindelin's earlier merge-replay work, though reconciliation may be needed later.
