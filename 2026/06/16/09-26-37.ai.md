This is the third and final patch in a v3 series introducing a `--linearize` option to `git replay`. The patch implements the core functionality: when `--linearize` is specified, `git replay` drops merge commits and replays only the non-merge commits in topological order, matching the default behavior of `git rebase --no-rebase-merges`. The implementation is mutually exclusive with `--revert` (enforced by a `die_for_incompatible_opt2` check) and is documented in the man page with a clear description and usage example.

The patch touches `replay.c`, `replay.h`, `builtin/replay.c`, the man page, and the test script. In `replay.c`, the main change is in `replay_revisions`, where the loop now skips merge commits when `--linearize` is active, leaving `last_commit` unchanged so that subsequent commits are reparented onto the previous non-merge commit. The `pick_regular_commit` helper is extended with an optional `replayed_base` parameter to support this reparenting. The test suite expands coverage to verify `--linearize` with `--advance`, test `--revert`/`--linearize` incompatibility, and use `git range-diff` to confirm that the replayed commits produce the same patches as the originals.

All prior review feedback has been addressed: the man page now includes `--linearize` in the SYNOPSIS and usage array, documents its mutual exclusivity with `--revert`, and improves the option description; the code adds a clarifying comment about `last_commit` handling during merge linearization; and the test suite includes all requested cases. The series is ready for final review, with no unresolved technical objections remaining.
