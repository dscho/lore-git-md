This is a proposal to standardize how Git handles an `Assisted-by:` trailer for AI-assisted commits, motivated by the Linux kernel's recent adoption of such a tag.

Marius Spix reports two inconsistencies in Git's current trailer handling: (1) `git commit --signoff` inserts a blank line before the `Signed-off-by:` trailer, but `--trailer "\nAssisted-by: ..."` does not convert the literal `\n` into a newline, and (2) `--signoff` silently skips the trailer if the commit message is otherwise empty, whereas `--trailer` does not. He suggests that Git should normalize the formatting and, when merging or squashing, automatically propagate any `Assisted-by:` trailers to the new commit message to preserve the AI-assistance record.

The email is short and does not include a patch or a concrete design; it is an RFC asking for opinions. The topic is timely—AI-assisted contributions are becoming more common—and the request is narrow: make trailers behave consistently and propagate them during history rewrites. Whether the project wants to bless `Assisted-by:` as a standard trailer is still an open question.
