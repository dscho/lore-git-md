This is the third patch in a six-part platform compatibility series addressing Windows LLP64 limitations for handling objects larger than 4GB. The series systematically converts object header lengths from `unsigned long` to `size_t` across Git’s object-file and hash algorithm code paths, with all production changes already validated in Git for Windows.

This patch updates the SHA1DC hash algorithm implementation to use `size_t` for section lengths, completing the type conversion chain for the `hash-object --literally` code path. The change is subtle but important: while the function signature of `git_SHA1DCUpdate()` is updated, no call sites are modified directly because the function is always invoked through macros (`platform_SHA1_Update` and `git_SHA1_Update`). The existing `git_hash_sha1_update()` wrapper already uses `size_t`, so this patch eliminates the implicit downcast from `size_t` to `unsigned long` that previously occurred. The patch also removes an unnecessary comment about the `unsigned long` expectation, as the type conversion now aligns with the rest of the codebase.

The test case in `t/t1007-hash-object.sh` that verifies 5GB file hashing is now unconditionally enabled (removing the `!LONG_IS_64BIT` prerequisite) and marked as a success, confirming the fix works on all platforms where `size_t` is 64-bit. The patch is mechanical and focused, touching only the SHA1DC interface and related headers without altering behavior.

This is a well-motivated and technically sound contribution. The series has been thoroughly reviewed and tested in production, and the type conversion approach has been agreed upon after architectural discussion. The patch itself is minimal and clearly explained, making it a straightforward addition to the broader effort. If you care about large-object support on Windows or platform compatibility in general, this patch is worth noting.
