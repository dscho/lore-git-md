The thread is about brian m. carlson’s ongoing work to make Git repositories interoperable between SHA-1 and SHA-256. The core functionality is now working, with the test suite passing and support for key features like shallow clones, submodules, and partial clones. However, the implementation still has significant limitations—particularly around filtered bundles, multi-pack index usage, and packfile URIs—and requires cleanup and performance optimizations. The 200+ patch series is not targeting Git 3.0, and brian has indicated openness to others upstreaming the work, though no clear path to integration exists yet.

Junio C Hamano, the maintainer, has now raised two specific technical concerns in response. First, he questions how packfile URIs will function under the new interoperability layer, given that Git currently recomputes object names from received pack streams as a security measure. Second, he flags a potential issue with large-object promisors, asking whether the client must blindly trust the server’s object mapping claims without verification. These questions focus on security and correctness implications, leaving the broader status of the work unaddressed for now. The thread remains in a technical clarification phase, with no substantive reviews or decisions yet.
