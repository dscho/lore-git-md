This thread is about brian m. carlson’s ongoing work to make Git repositories interoperable between SHA-1 and SHA-256 object formats. The core functionality—shallow clones, submodules, partial clones, and delta resolution—now works, and the test suite passes, but several limitations remain, including filtered bundles, multi-pack index usage, and packfile URIs.

Junio C Hamano recently raised two security-related concerns: how packfile URIs (which deliver packs out of order) interact with object-name recomputation, and whether promisor remotes (which offload objects) can safely provide object mappings. Brian has now clarified that packfile URIs currently break indexing in multi-algorithm repositories because each pack must connect to the local history, which isn’t guaranteed when packs arrive separately. For promisors, the server must have the full history to generate mappings, so submodule mappings are disabled by default and require an explicit security override. Regular fetches and clones work fine as long as no submodules are involved.

The branch is functional for repositories without submodules (Brian provided a working example), but the 200+ patch series is not targeted for Git 3.0 due to its scope and the need for further testing. No other contributors have reviewed the work yet, and the thread is now waiting for feedback on these clarifications.
