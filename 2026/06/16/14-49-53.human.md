This is the second patch in a six-part series addressing Windows LLP64 compatibility for handling objects larger than 4GB. The series systematically converts object header lengths from `unsigned long` to `size_t` across Git’s object-file handling code to prevent 32-bit truncation on Windows.

This patch updates `object-file.c` and related ODB (object database) source files, changing function signatures in `hash_object_file()`, `write_object_file_prepare()`, and their callers to use `size_t` instead of `unsigned long` for memory buffer lengths. The changes are mechanical and maintain interface compatibility while fixing the truncation issue. The patch also updates the header buffer length parameter in `write_object_file_prepare()` and related functions for consistency, though the test added in the first patch still fails—subsequent patches will complete the call chain fixes.

The patch touches core object storage code (`object-file.c`, `odb/source-*`) and is part of a well-validated effort that has been running in Git for Windows for years. Johannes Schindelin’s sign-off confirms production validation, and the series has no outstanding objections. This is a focused, low-risk change that directly addresses the LLP64 limitation without altering behavior on other platforms. If you care about large-object support on Windows, this series is worth tracking.
