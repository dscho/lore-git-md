This is the maintainer's merge notice for a platform compatibility series that enables Git to handle objects larger than 4GB on Windows (LLP64). Junio C Hamano has queued the v2 series after it resolved conflicts with `ps/odb-source-loose` and removed the `!LONG_IS_64BIT` test prerequisite. The patches, originally authored by Philip Oakley and maintained in Git for Windows for 4.5 years, are now production-validated and ready for upstream integration.

The series converts object header lengths from `unsigned long` to `size_t` across `object-file.c`, ODB source files, and the SHA1DC interface, fixing 32-bit truncation on Windows while maintaining compatibility on all platforms. Six test cases in `t/t1007-hash-object.sh` verify the fix for direct file hashing, `--stdin` input, and filtered input with 5GB test files. Junio notes the changes work correctly regardless of whether `long` is 32-bit or 64-bit.

This is a clean, focused fix with thorough test coverage and no remaining objections. The patches touch only the necessary interfaces and add reusable test infrastructure for future platform validation. The series is now queued for the next integration cycle.
