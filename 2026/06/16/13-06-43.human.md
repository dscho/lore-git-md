This is the second patch in Pablo Sabater's v5 series improving `git log --graph` rendering for commits with excluded parents. The patch implements the core visualization change: cascading indentation of visual roots (commits that appear as new branches in the graph) to clarify parent-child relationships when some parents are excluded.

The patch introduces a new `GRAPH_PRE_ROOT` state in the graph engine, tracks visual roots with an `is_visual_root` flag and `visual_root_depth` counter, and progressively indents each subsequent visual root while exempting merge parents. Pablo's response to Junio clarifies that this indentation works regardless of which column the visual root appears in - addressing a specific edge case where visual roots appear in non-first columns.

The discussion with Junio has shifted from the core functionality (which both agree appears correct) to test methodology. Pablo acknowledges the test's dependence on hardcoded graph outputs makes it sensitive to traversal order changes, but argues removing the commit-graph file is currently necessary to test specific visualization scenarios. He demonstrates how the same commit relationships can be rendered differently (with or without indentation) while remaining correct, suggesting the test expectations may need adjustment rather than the visualization logic.

This patch looks technically sound with good test coverage, though the test robustness question remains open. The implementation handles the documented edge case (visual roots in non-first columns) and maintains correct relationship representation across layout variations. The series appears ready for final review from Phillip Wood or Jeff King on the architectural approach.
