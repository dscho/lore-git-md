This is a platform compatibility discussion in the ongoing Windows LLP64 large-object series. Johannes Schindelin (Dscho) replies to Patrick Steinhardt’s architectural question about whether to use `size_t` or a platform-independent `objsize_t` typedef for object header lengths.

Dscho firmly rejects the idea of introducing a new typedef, arguing that `size_t` is the correct type because it represents what the current platform can handle in memory. He notes that on 32-bit platforms, streaming via `off_t` could theoretically handle objects larger than 4GB, but cautions that such setups would be inefficient and impractical for real-world Git operations like reconstructing large objects from delta chains.

The exchange is brief and technical, with no new code changes proposed. It clarifies the design intent behind the series’ use of `size_t` and effectively closes the architectural discussion Patrick raised. The series itself remains ready for rebase and merge, with all technical sign-offs in place.
