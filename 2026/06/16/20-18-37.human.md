This is the final patch in Kristoffer Haugsbakk’s six-part documentation series updating Git’s `SubmittingPatches` guidelines, specifically addressing trailer ordering conventions. The patch itself is minor but conceptually important: it adds a note that trailers like `Acked-by` and `Reviewed-by` should appear *before* the author’s `Signed-off-by`, with the rationale that the sign-off applies to both the patch and the preceding trailers.

Junio C Hamano’s review suggested a refinement to the explanation, pointing out that the current wording could be misread as implying trailer types determine order (e.g., "all `Acked-by` lines must come before `Signed-off-by`"). Instead, he recommended leading with the underlying principle: trailers should reflect the *chronological order of events*. Kristoffer agrees and plans to update the text to emphasize this, which will make the guideline more intuitive and harder to misapply. This is a substantive but non-controversial improvement—no disagreement on the rule itself, just on how best to explain it.

The series as a whole remains on track, with only this minor clarification pending. The broader debate about non-identity trailers (e.g., `Closes:`) is still unresolved, but that’s a separate issue from this patch. For readers following the thread, this is a clean example of how Git’s documentation evolves: small, precise updates driven by maintainer feedback to prevent future confusion. The patch is worth attention only if you care about commit message hygiene; otherwise, it’s a routine refinement.
