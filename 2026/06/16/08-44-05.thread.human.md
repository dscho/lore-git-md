This thread is about Patrick Steinhardt’s patch series adding four new subcommands—`delete`, `update`, `create`, and `rename`—to `git refs`, consolidating Git’s scattered reference manipulation functionality under a unified interface. The series is now fully merged into Junio C Hamano’s `next` branch and ready for the next release cycle. Version 4 is a post-merge reroll with no functional changes, focusing on test additions, stylistic tweaks, and mechanical refactoring (including removing `the_repository` usage in `builtin/refs.c`).

The central design question—how to balance atomicity, backwards compatibility, and ergonomics—was resolved by retaining `git refs update`’s implicit creation semantics (mirroring `git update-ref`) while adding `git refs create` for explicit atomic creation. Two usability concerns remain open but documented: the `--no-deref` option’s counterintuitive behavior in symref handling (it controls failure when the target exists as a symref, not symref creation), and the lack of symref renaming support in `git refs rename` (due to backend limitations). Both are now explicitly tested and clarified in error messages, though the man page still omits the symref renaming limitation.

Key participants include Patrick Steinhardt (author), who addressed all review feedback and added tests to document edge cases, and Junio C Hamano (maintainer), who approved the series after the typo fix in `git refs create`’s error message. Toon Claes provided surface-level reviews focusing on usability and test consistency, raising the `--no-deref` and symref renaming questions that are now documented. The series touches the `refs/` subsystem, adds new test scripts, and aligns with ongoing efforts like `the_repository` removal. No further changes are expected before release.
