Patrick Steinhardt’s four-patch series adding `git refs delete`, `update`, and `rename` subcommands is consolidating Git’s scattered reference manipulation commands under a single interface. The thread is in active design review, with Junio C Hamano raising high-weight concerns about atomicity, naming, and error handling in the initial submission.

Patrick’s latest reply addresses the most critical issue: the lack of atomic "create" semantics. He agrees that overloading `update` with NUL object IDs is cumbersome and proposes adding a dedicated `git refs create` subcommand to provide a race-free way to ensure a reference doesn’t already exist. This would resolve Junio’s safety critique while keeping the interface explicit. Patrick also clarifies that the `update` subcommand already supports atomic creation checks (via `$NULL_OID`), but the test suite fails to verify this—he’s committed to adding a test to confirm creation fails when the reference exists.

The series is now likely headed for a v2 iteration that will include the new `create` subcommand and expanded test coverage. Junio’s other concerns—naming inconsistencies, error message formatting, and return value conventions—remain unaddressed but may resurface in the next round. The thread is still in design-review phase, with no merge decision yet, but the exchange shows the interface evolving toward a safer, more explicit design.
