This thread covers Patrick Steinhardt’s five-patch series adding `git refs delete`, `update`, `create`, and `rename` subcommands to consolidate Git’s reference manipulation functionality. The series is now fully merged into Junio C Hamano’s `next` branch and ready for the next release.

The goal was to unify scattered reference-handling commands under a single `git refs` interface while balancing atomicity, backwards compatibility, and ergonomics. The design resolved a key question by retaining `git refs update`’s implicit creation behavior (matching `git update-ref`) while adding `git refs create` for explicit atomic creation. All subcommands are now integrated, with thorough test coverage for edge cases like symref handling, reflog updates, and atomic checks.

The final v3 reroll addressed a single typo in the `git refs create` error message ("null new object ID"), which Junio approved in this sign-off. No other changes were needed, as all prior feedback—including return value consistency, reflog edge cases, and test coverage—had been resolved in earlier versions. The series also included a mechanical patch removing `the_repository` from `builtin/refs.c`, aligning with the ongoing effort to eliminate global state. Future work may explore reflog handling in `rename` and alignment of `--create-reflog` options, but the current implementation is complete and uncontroversial.
