Patrick Steinhardt’s patch series adding `delete`, `update`, `create`, and `rename` subcommands to `git refs` has been merged into Junio C Hamano’s `next` branch and is slated for the next release. The series consolidates scattered reference-manipulation commands under a unified interface, improving discoverability while preserving backward compatibility.

The key design question—how to handle reference creation—was resolved by offering two paths: `git refs update` retains the implicit creation semantics of `git update-ref` (using `$NULL_OID` for atomic checks), while `git refs create` provides an explicit atomic alternative that enforces "must not exist" semantics. Junio’s final review of the `create` subcommand caught a single typo in an error message ("null old object ID" → "null new object ID"), which Patrick has since corrected. All other patches in the series were uncontroversial, with Junio approving the return value conventions, reflog edge cases, and expanded test coverage. The only deferred work is whether `git refs rename` should automatically create a reflog for the new reference if the source lacks one—currently, it does not, though a `--create-reflog` option remains possible for future enhancement.
