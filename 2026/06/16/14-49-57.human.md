This is the final patch in a six-part series addressing Windows LLP64 compatibility for handling objects larger than 4GB. The series converts object header lengths from `unsigned long` to `size_t` across core object-file code and adds comprehensive test coverage.

This patch adds a test case to `t/t1007-hash-object.sh` that verifies the `clean` filter code path correctly processes files larger than 4GB on platforms where `size_t` is 64-bit. The test uses a trivial `cat`-based filter (configured via `filter.null-filter.clean`) and a 5GB test file (`big`), reusing the file from earlier tests if available to avoid redundant generation. The test is marked `EXPENSIVE` and `SIZE_T_IS_64BIT`, ensuring it runs only on relevant platforms.

The patch is narrowly focused and well-motivated: it completes the test coverage for the series by exercising the filter interface, which was the last major code path not yet verified for large-file correctness. The commit message clearly explains the scope (filter code only, no object store writes) and ties it back to the series' goal of ensuring `size_t` is used consistently. The test itself is straightforward and reuses existing infrastructure, making it low-risk.

This series has been validated in production through Git for Windows and carries sign-offs from both the original author (Philip Oakley) and the Git for Windows maintainer (Johannes Schindelin). All prior patches in the series have been merged or approved, and the architectural discussion about type choices is settled. The test added here is the last piece needed to confirm the entire large-object handling stack works correctly on LLP64 platforms.
