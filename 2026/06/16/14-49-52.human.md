This is the first patch in a six-part platform compatibility series addressing Windows LLP64 limitations for large objects (>4GB). The patch adds a test case to `t/t1007-hash-object.sh` that demonstrates the current failure when hashing a 5GB file on systems where `unsigned long` is 32-bit (like Windows). The test uses `git hash-object --literally --stdin` to avoid writing the object, focusing specifically on the type truncation issue in the object header handling code.

The test is marked as `EXPENSIVE` and currently fails (`test_expect_failure`) on LLP64 systems where `SIZE_T_IS_64BIT` is true but `LONG_IS_64BIT` is false. This patch serves as both a regression test and a proof-of-problem for the subsequent type conversion patches. The test infrastructure is cleanly separated from the production code changes, following Johannes Schindelin's preference for clarity over consolidation.

This is a well-motivated test addition that clearly demonstrates the problem being solved. The commit message effectively explains the LLP64 context and why this specific code path was chosen for testing. The test itself is minimal but sufficient, using `test-tool genzeros` to create the large file and verifying the hash against precomputed values. The `EXPENSIVE` marker is appropriate given the 5GB file size.
