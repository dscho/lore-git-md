This is an update on the SHA-1/SHA-256 interoperability effort, specifically Junio C Hamano’s reply to brian m. carlson’s progress report.

Junio acknowledges the milestone—Git now passes the full test suite in interoperability mode—but homes in on two protocol-level concerns. First, he questions how packfile URIs can work if the receiver cannot map object names from the partial pack stream; his expectation is that the same “recompute object names from the data” security model that applies to regular fetch/push should extend to packfile URIs. Second, he worries that promisor objects might force the client to blindly trust the server’s object-name mapping, breaking the “don’t trust the sender” principle.

The email is short and focused: it neither reviews code nor suggests changes, but flags two specific security assumptions that will need to be addressed before the series can be considered for merging. Readers following the interoperability work will want to watch how these protocol constraints are resolved in future iterations.
