This is a platform compatibility patch series targeting Windows LLP64 systems to enable handling objects larger than 4GB. The series, originally authored by Philip Oakley 4.5 years ago and maintained in Git for Windows, is now being upstreamed with all production code changes already validated in production use. This v2 submission resolves the previous version's conflicts with `ps/odb-source-loose` and removes the `!LONG_IS_64BIT` test prerequisite, making the 5GB test cases run on all platforms that support large files.

The series systematically converts object header lengths from `unsigned long` to `size_t` across core object-file handling code (`object-file.c`, `odb/source-*`), the SHA1DC interface (`sha1dc_git.c`), and related headers. The changes are mechanical type signature updates that maintain interface compatibility while fixing the 32-bit truncation issue on Windows. Six test cases in `t/t1007-hash-object.sh` verify all major code paths, including direct file hashing, `--stdin` input, and filtered input processing with 5GB test files.

Johannes Schindelin's cover letter positions this as complementary to other ongoing large-object efforts, noting the patches have proven stable through years of production use in Git for Windows. The architectural discussion about using `size_t` versus introducing an `objsize_t` typedef was resolved in favor of `size_t` as the correct choice for memory-addressable sizes, with Johannes clarifying that `off_t` remains appropriate only for streaming scenarios on 32-bit platforms.

The series appears technically sound with thorough test coverage and no outstanding objections. Junio C Hamano has approved the approach but requested a rebase due to integration conflicts, which this v2 addresses. The changes are focused and minimal, touching only the necessary interfaces while maintaining backward compatibility. The test infrastructure added here will be reusable for other platform validation efforts.
