This is the final piece of a long-running platform compatibility series that fixes Windows' inability to handle objects larger than 4GB on LLP64 systems. Johannes Schindelin replies to Patrick Steinhardt's suggestion about test prerequisites in the last patch of the series.

The discussion centers on whether to keep the `!LONG_IS_64BIT` prerequisite for the 5GB file hashing test. Patrick proposed removing it entirely since the underlying bug is now fixed and the test should pass on all platforms, not just LLP64 systems. Johannes agrees with this refinement, calling it a "good point" and effectively endorsing the change.

This is a minor but sensible improvement to test coverage. The series as a whole has already been validated through years of production use in Git for Windows, with all technical objections resolved and sign-offs in place. The only remaining work is a rebase to resolve integration conflicts, as previously requested by Junio Hamano. The changes are well-contained to object-file and hash algorithm code paths, and the architectural approach of using `size_t` for memory-addressable sizes has been firmly established as correct.
