This is the v3 iteration of Toon Claes's feature patch series introducing a `--linearize` option to `git replay`. The series is now complete, with all substantive feedback from prior rounds incorporated. It consists of three patches: two preparatory refactors and the main implementation.

The `--linearize` option flattens merge commits into linear history by walking only first parents, effectively replicating `git rebase --no-rebase-merges` behavior on the server side. This v3 addresses all remaining review points: the documentation now includes `--linearize` in the SYNOPSIS and explicitly notes its incompatibility with `--revert`; the help text has been reworded for clarity ("drop merge commits" instead of "ignore"); and the test suite has been expanded to cover root commit handling, `--linearize`/`--advance` combination, mutual exclusion with `--revert`, and patch preservation verification via `git range-diff`.

The implementation touches `replay.c` (commit mapping logic and merge commit handling) and `replay.h` (option definition), with corresponding updates to the man page and test file `t3650-replay-basics.sh`. The series maintains compatibility with Johannes Schindelin's (Dscho) earlier merge-replay work, though some reconciliation may be needed; Toon has volunteered to help with that. Dscho's Signed-off-by remains on the final patch, indicating his support for the approach.

This version appears ready for merging. The collaborative review process—including substantive input from Junio Hamano, Elijah Newren, Justin Tobler, and Dscho—has produced a technically sound implementation with comprehensive test coverage and clear documentation. The only remaining work is mechanical polish (e.g., test description tweaks), not architectural changes. The series is part of the broader effort to enhance `git replay`'s capabilities, complementing Patrick Steinhardt's `git history drop` and Kristoffer Haugsbakk's documentation improvements.
