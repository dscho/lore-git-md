This is a bugfix patch for the sequencer that prevents Git from incorrectly copying notes when a commit "disappears" during rebase because its changes are already present upstream. The issue occurs when a commit is dropped not because it was explicitly skipped (e.g., via `git rebase --skip`), but because its patch content is already applied by a different commit. In such cases, the notes attached to the disappearing commit were mistakenly copied to the unrelated commit that happened to be HEAD at the time.

The patch modifies `sequencer.c` to track whether a commit was dropped during rebase and skips the notes-copying logic when that happens. It introduces a new output parameter, `dropped_commit`, to `do_pick_commit()` and propagates this information through the call chain to ensure the sequencer correctly identifies when a commit is dropped due to redundant content. The change is minimal and focused, touching only the logic around commit processing and notes handling.

A new test, `t3322-notes-rebase.sh`, verifies the fix by setting up a scenario where a commit (`B`) is rebased onto a branch where its changes are already present (via a different commit, `BD`). The test confirms that the notes attached to `B` are not incorrectly copied to `BD` after the rebase. The test is added to the Meson build configuration to ensure it runs as part of the test suite.

The author, Uwe Kleine-König, notes that this patch addresses a previously reported bug (linked in the email) and follows a suggestion from Phillip Wood. While Uwe describes the implementation as "not pretty," the fix appears technically sound and is accompanied by a clear test case.
