This is the first patch in the v3 series introducing `--linearize` to `git replay`. It refactors the `enum replay_mode` into a simple boolean `reverse` flag, eliminating the need for a two-valued enum and removing redundant BUG checks for invalid enum values. The change is purely internal and does not alter behavior; it prepares the codebase for the `--linearize` feature by simplifying the control flow around commit processing order.

The patch touches only `replay.c`, replacing every occurrence of `enum replay_mode` with a `bool reverse`. The `create_commit` and `pick_regular_commit` functions are updated to use the boolean flag, and the ternary logic that previously checked the enum is streamlined. All existing functionality—including the `--revert` mode introduced in 2760ee4983—remains intact, and the patch passes the existing test suite.

This refactoring was prompted by Justin Tobler’s review of v2, which raised a forward-looking concern about extensibility if additional replay modes were introduced later. Toon Claes addressed the concern by noting that the boolean flag is sufficient for the current feature set and that future modes can be added via a new flag (e.g., `linearize`) rather than expanding the enum. The response satisfied the reviewers, and no further objections remain.

The patch is clean, well-motivated, and ready for integration. It sets the stage for the subsequent patches in the series, which introduce the `--linearize` option and its associated test coverage.
