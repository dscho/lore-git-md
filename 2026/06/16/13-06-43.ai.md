This is the second patch in Pablo Sabater's v5 series improving `git log --graph` visualization for commits with excluded parents. The patch implements the core cascading indentation logic that was refined across multiple iterations, addressing the long-standing issue of misleading vertical alignment in complex merge scenarios.

The patch introduces several key technical components: a new `GRAPH_PRE_ROOT` state to handle connections to indented roots, an `is_visual_root` flag and `visual_root_depth` counter to track hierarchy levels, and cascading indentation where each subsequent visual root increases indentation while preserving parent-child relationships. Merge parents are explicitly exempted from indentation since they're already connected through existing graph logic. The implementation includes thorough test coverage through new test file `t4218-log-graph-indentation.sh`, though one edge case in revision.c's lookahead prediction remains documented as `NEEDSWORK`.

Pablo's response to Junio's concerns provides important technical clarification about the test environment requirements. The commit-graph file removal isn't just a workaround but a necessary condition for testing specific visualization scenarios involving multiple visual roots and active columns, as commit-graph alters graph topology in ways that would mask the very behavior being tested. This explains why simpler approaches like `git config core.commitGraph false` proved insufficient. The response also demonstrates how the current implementation correctly handles edge cases where visual roots appear in non-first columns, something v3 failed to address.

The ongoing discussion with Junio has shifted from technical correctness to test methodology robustness. While the core visualization logic appears sound (both rendering variants correctly show the same commit relationships), Junio raises valid concerns about whether exact output matching is too brittle given potential traversal order variations. Pablo's point about all graph tests depending on traversal order is technically accurate but doesn't fully address the maintainability concern. The test infrastructure refactoring in patch 1/2 (already reviewed by Karthik Nayak and Chandra Pratap) provides a cleaner foundation, but the test expectations may need adjustment to verify relationship correctness rather than exact layout.
