This is the maintainer's merge notice for a platform compatibility series that enables Git to handle objects larger than 4GB on Windows (LLP64) systems. Junio C Hamano has queued the v2 series after it resolved conflicts with `ps/odb-source-loose` and removed the `!LONG_IS_64BIT` test prerequisite. The patches convert object header lengths from `unsigned long` to `size_t` across `object-file.c`, ODB source files, and the SHA1DC interface, with six new test cases in `t/t1007-hash-object.sh` verifying all major code paths with 5GB test files.

The series is technically complete and production-validated through years of use in Git for Windows. Junio's only procedural note is curiosity about how GitGitGadget generates range-diffs (the `git range-diff v1...v2` comparison in the email), which required manual tuning to produce the shown output. This is a routine merge of a well-scoped, uncontroversial fix that addresses a long-standing platform limitation while maintaining backward compatibility. The test infrastructure added here will be reusable for other large-object validation efforts.
