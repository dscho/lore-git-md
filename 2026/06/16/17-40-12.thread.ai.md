Core problem or goal
When `git rebase` drops a commit (e.g., because its changes are already present in the target branch), the sequencer incorrectly copies that commit’s notes to the current HEAD commit, corrupting the repository’s note history. The discussion has expanded into a systemic audit and repair of how the rebase machinery handles dropped commits across all operations: empty-changes, fixup sequences, edit commands, skip operations, final fixup cleanup, **external merge strategy failures** (e.g., merge tool crashes, permission errors, untracked file overwrites), and **command execution failures** (e.g., `git commit` failing to run due to missing executable or permission error). A secondary discussion emerged about the **scope of refactoring** needed to support the core behavioral change, with Phillip Wood advocating for incremental, minimal-churn changes and Oswald Buddenhagen suggesting broader refactoring for stylistic consistency. Phillip’s follow-up replies clarify that **temporary redundancy in earlier patches was intentional** to preserve clarity during the phased introduction of `enum pick_result`, and that the series’ technical direction remains unchanged.
