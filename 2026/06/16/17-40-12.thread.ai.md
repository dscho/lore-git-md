Core problem or goal
When `git rebase` drops a commit (e.g., because its changes are already present in the target branch), the sequencer incorrectly copies that commit’s notes to the current HEAD commit, corrupting the repository’s note history. The discussion has expanded into a systemic audit and repair of how the rebase machinery handles dropped commits across all operations: empty-changes, fixup sequences, edit commands, skip operations, final fixup cleanup, **external merge strategy failures**, and **command execution failures** (e.g., `git commit` failing to run).

Current status
Two parallel efforts now exist:
1. **Uwe’s original patch**: adds a `dropped_commit` output parameter to `do_pick_commit()`, propagates it through the call chain, and skips note copying for dropped commits. This patch remains under review but is now **functionally superseded** by Phillip’s series. Key gaps (fixup-commit edge case, documentation, test location) are addressed by Phillip’s work.
2. **Phillip’s 11-patch series**: a complete systemic overhaul that:
   - **Patch 1/11**: Restores test coverage for the "apply" rebase backend (lost when the default switched from "apply" to "merge") by replacing `-m` with `--apply` in `t3400-rebase.sh`. No behavior change; only test suite adjustment.
   - **Patch 2/11**: Refactors `sequencer.c` by moving the `is_final_fixup()` helper function earlier in the file to eliminate a forward declaration needed by later patches. No behavior change; purely preparatory.
   - **Patch 3/11**: Fixes a bug in the external merge strategy logic where non-zero exit codes (other than 1) from merge tools were incorrectly treated as conflicts. The patch ensures that exit codes like 2 (indicating failure, not conflict) trigger rescheduling of the pick rather than proceeding as a conflict.
   - **Patch 4/11**: Fixes a command execution edge case where `git commit` failing to run (e.g., due to a missing or misconfigured Git installation) was incorrectly treated as a reschedule condition. The patch converts a `-1` return value from `run_git_commit()` (indicating failure to execute the command) into `1` (indicating success), ensuring the sequencer does not reschedule the command since the commit’s changes have already been applied and state files written.
   - Refactors `pick_one_commit()` and `do_pick_commit()` to simplify control flow (patches 5–9).
   - Introduces an enum for pick results, replacing a boolean return value (patch 10).
   - Adds a `PICK_DROPPED` enum member and modifies the sequencer to avoid recording dropped commits as rewritten (patch 11).
   - Fixes the fixup-commit edge case, final fixup cleanup, edit command handling, skip command handling, **external merge strategy failures**, and **command execution failures**.
   - Integrates the test into `t3400-rebase.sh` and provides clear documentation in commit messages.
   The series is **ready for review** and addresses all open blockers from Junio’s earlier feedback, including the newly identified edge cases.
