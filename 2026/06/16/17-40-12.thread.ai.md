Core problem or goal
When `git rebase` drops a commit (e.g., because its changes are already present in the target branch), the sequencer incorrectly copies that commit’s notes to the current HEAD commit, corrupting the repository’s note history. The discussion has expanded into a systemic audit and repair of how the rebase machinery handles dropped commits across all operations: empty-changes, fixup sequences, edit commands, skip operations, final fixup cleanup, **external merge strategy failures**, and **command execution failures** (e.g., `git commit` failing to run).

Current status
Phillip Wood’s 11-patch systemic overhaul is **complete, queued in Junio’s tree for final review, and now carries Uwe Kleine-König’s Tested-by**. The series is self-contained and addresses all known edge cases, including those identified by Junio’s earlier feedback. Key outcomes:
- **Patch 11/11 (final patch)**: introduces the core behavioral change by adding `PICK_RESULT_DROPPED` to `enum pick_result` and modifying `pick_one_commit()` to skip `record_in_rewritten()` for dropped commits. This ensures notes and post-rewrite hooks no longer receive information about commits dropped due to empty changes, fixup sequences, edit commands, skip operations, **external merge strategy failures**, or **command execution failures**. A known limitation is documented: the "edit" command still erroneously records dropped commits as rewritten when `rebase --continue` is run, requiring a separate fix.
- **Test coverage**: expanded in `t3400-rebase.sh` (notes from dropped commits) and `t5407-post-rewrite-hook.sh` (post-rewrite hook accuracy for fixups + empty changes). The series restores test coverage for the "apply" backend (patch 1/11) and adds tests for **external merge strategy failures** (patch 3/11) and **command execution failures** (patch 4/11).
