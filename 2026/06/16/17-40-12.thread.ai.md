Thread identity
Subject: [PATCH] sequencer: avoid copying notes from dropped commits during rebase
Series version: standalone patch
Originating author: Uwe Kleine-König
Thread type: bugfix patch

Core problem or goal
When `git rebase` drops a commit because its changes are already present in the target branch (via a different commit), the sequencer subsystem incorrectly copies that commit’s notes to the current HEAD commit. This results in notes being attached to the wrong commit, corrupting the repository’s note history.

Current status
The patch is under initial review. No prior versions exist. The implementation is functionally sound but described by the author as “not pretty.” It modifies `do_pick_commit()` to add a `dropped_commit` output parameter, propagates this flag through `pick_one_commit()` and `single_pick()`, and skips note copying when the commit is dropped. A new test script `t3322-notes-rebase.sh` verifies the fix.

Key technical details
Files touched: `sequencer.c` (core logic), `t/t3322-notes-rebase.sh` (new test)
New symbols: `dropped_commit` output parameter in `do_pick_commit()`
Behavior change: notes are no longer copied from commits that are dropped during rebase
Test coverage: exercises the edge case where a commit’s changes are already present in the target branch

Open questions and loose ends
None yet; the patch is self-contained and addresses the reported bug without introducing new design questions.
