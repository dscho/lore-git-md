Core problem or goal
When `git rebase` drops a commit (e.g., because its changes are already present in the target branch), the sequencer incorrectly copies that commit’s notes to the current HEAD commit, corrupting the repository’s note history. The discussion has expanded into a systemic audit and repair of how the rebase machinery handles dropped commits across all operations: empty-changes, fixup sequences, edit commands, skip operations, final fixup cleanup, **external merge strategy failures** (e.g., merge tool crashes, permission errors, untracked file overwrites), **command execution failures** (e.g., `git commit` failing to run due to missing executable or permission error), and **user-initiated drops** (e.g., `git rebase --skip` or `--continue` without committing in interactive rebase). A secondary discussion emerged about the **scope of refactoring** needed to support the core behavioral change, with Phillip Wood advocating for incremental, minimal-churn changes and Oswald Buddenhagen suggesting broader refactoring for stylistic consistency. Phillip’s follow-up replies clarify that **temporary redundancy in earlier patches was intentional** to preserve clarity during the phased introduction of `enum pick_result`, and that the series’ technical direction remains unchanged. **New regression**: Uwe Kleine-König reports that the fix works for non-interactive rebase but **fails for interactive rebase (`-i`)**, where notes from dropped commits are still incorrectly copied. This backend-specific discrepancy is now partially explained: the series only handles commits dropped by `--empty=drop` (non-interactive default), not user-initiated drops (e.g., `git rebase --skip` or `--continue` without committing in interactive rebase). The interactive rebase backend’s `--empty=ask` behavior (which drops commits on `--continue` but keeps them on `--skip`) further complicates the fix. **Meta-discussion**: Junio C Hamano and Oswald Buddenhagen engaged in a **procedural debate** about the expressiveness of review systems, with Junio validating the mailing list’s nuanced feedback culture and Oswald countering that Gerrit’s multi-level scoring system (e.g., -2 to +2) already encodes the distinctions Junio described.
