This is the v2 cover letter for Matt Hunter’s seven-patch series that adds a global `fetch.followRemoteHEAD` configuration variable. The feature lets users set a default behavior for updating the local `remotes/<name>/HEAD` symbolic-ref when fetching, eliminating the need to configure each remote individually. The series builds directly on the per-remote `remote.<name>.followRemoteHEAD` introduced in Git 2.48, following the same precedence pattern as `fetch.prune`/`remote.*.prune`.

The implementation is complete: it touches the fetch machinery, refactors the decision logic to handle both global and per-remote settings, adds thorough test coverage in `t5510-fetch.sh`, and updates documentation in `Documentation/config/fetch.adoc` and `advice.adoc`. The v2 iteration incorporates Junio’s feedback on case-sensitive value matching and non-fatal error handling for invalid configuration values, and it polishes the documentation to clarify the relationship between the global and per-remote settings.

This is a well-crafted, user-facing feature that addresses a real configuration pain point without breaking backward compatibility. The series looks ready for final review and merging.
