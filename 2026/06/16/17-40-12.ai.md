This is a bugfix patch targeting the sequencer subsystem, specifically addressing a misbehavior in `git rebase` when notes are involved.

The patch fixes a case where a commit disappears during rebase because its changes are already present in the target branch (but not via the same commit). Currently, Git incorrectly copies the notes from the disappearing commit to the unrelated commit that happens to be HEAD at that moment. The fix modifies `do_pick_commit()` to track whether a commit was dropped and skip note copying in that case.

The implementation adds a new output parameter `dropped_commit` to `do_pick_commit()` and propagates this information through the call chain (`pick_one_commit()`, `single_pick()`). The test coverage is thorough: a new test script `t3322-notes-rebase.sh` exercises the scenario and verifies that notes are not copied when they shouldn't be.

Uwe Kleine-König authored the patch after two previous bug reports failed to attract a fix. Phillip Wood had suggested the approach, and while Uwe calls the implementation "not pretty," it appears functionally sound. The patch touches only the sequencer code and adds appropriate test coverage, making it a focused, well-contained fix for a real (if edge-case) bug.
