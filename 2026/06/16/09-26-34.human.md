This is the third iteration of Toon Claes's feature patch series adding a `--linearize` option to `git replay`. The series is now complete, with all substantive feedback from previous rounds incorporated. It introduces the ability to flatten merge commits into linear history by walking only first parents, effectively providing server-side functionality equivalent to `git rebase --no-rebase-merges`.

The implementation is split into three patches: two preparatory refactors (converting `enum replay_mode` to a boolean and adding a helper for commit mapping) and the main feature patch. The `--linearize` option is documented as incompatible with `--revert`, and the test suite has been expanded to cover root commit handling, `--advance` combination scenarios, and patch preservation verification via `git range-diff`. The series touches `replay.c`, `replay.h`, and the test file `t3650-replay-basics.sh`.

This version resolves all outstanding review comments from Junio Hamano, Elijah Newren, and Justin Tobler, including documentation improvements, test coverage gaps, and terminology clarifications. The collaborative review process appears to have produced a technically sound implementation, with Dscho's Signed-off-by indicating support. The series is positioned as an alternative to Johannes Schindelin's separate merge-replay approach, though the author notes willingness to reconcile the two if needed.
