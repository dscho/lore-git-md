This is a platform compatibility patch series targeting Windows LLP64 systems, where `unsigned long` is 32-bit and cannot represent object sizes larger than 4GB. The series, originally authored by Philip Oakley 4.5 years ago and maintained in Git for Windows, systematically converts object header lengths from `unsigned long` to `size_t` across core object-file and hash algorithm code paths.

The patches are effectively complete, with all production code changes already merged and validated in Git for Windows. The series includes six patches: one to demonstrate the problem, three to convert the relevant code to use `size_t`, and two to add comprehensive test coverage for all major code paths, including a new test for basic file hashing verification. The test infrastructure now handles 5GB test files unconditionally (keeping the `EXPENSIVE` marker) after removing the `!LONG_IS_64BIT` prerequisite.

The changes touch `object-file.c`, `sha1dc_git.c`, `hash.h`, and related ODB source files, with corresponding updates to function signatures and internal logic. The SHA1DC interface is modified to use `size_t` while maintaining abstraction. Test coverage validates direct file hashing, `--stdin` input, standard hashing paths, and clean filter processing. Johannes Schindelin's sign-off confirms the patches have been production-tested in Git for Windows for years.

Junio C Hamano has approved the technical approach but requested a rebase due to conflicts with in-flight topics (notably `ps/odb-source-loose`). The rebase has been completed in this v2 submission. The architectural discussion about using `size_t` versus introducing an `objsize_t` typedef has been resolved in favor of `size_t`, with Johannes firmly rejecting the typedef approach and clarifying that `size_t` is the correct choice for memory-addressable sizes.

This series complements other ongoing large-object handling improvements and provides reusable test infrastructure for platform validation. The patches are focused, mechanical, and well-tested, addressing a real limitation that becomes increasingly relevant as Git's support for large objects matures.
