This is the fourth patch in a six-part platform compatibility series addressing Windows LLP64 limitations for large objects (>4GB). The series systematically converts object header lengths from `unsigned long` to `size_t` across core object-file handling code, with all production changes already validated in Git for Windows.

This specific patch adds a test case to verify that `` `git hash-object --stdin` `` correctly processes files larger than 4GB on platforms where `size_t` is 64-bit. The test reuses the 5GB file created in the first patch (patch 1/6) but regenerates it if missing to ensure independence when running individual test cases. The test explicitly avoids writing the object to the object store or applying filters, focusing solely on the hashing behavior. Like the earlier test cases, it is marked `EXPENSIVE` and `SIZE_T_IS_64BIT` to ensure it only runs on platforms where the fix is relevant.

The patch is minimal and focused, touching only the test script (`t/t1007-hash-object.sh`). It complements the type conversion work in patches 2/6 and 3/6 by verifying the `--stdin` code path, which was not covered by the earlier test cases. The test infrastructure is clean and self-contained, with no dependencies beyond the test helper (`test-tool genzeros`) and the expected hash values defined in the test library.

This is a well-motivated addition to the series, filling a clear coverage gap. The test case is straightforward and unlikely to be controversial, though its `EXPENSIVE` marker means it will only run in CI or when explicitly requested. The patch maintains the series' overall quality: thorough, focused, and backed by production validation.
