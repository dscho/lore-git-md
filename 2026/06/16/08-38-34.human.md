This is the final patch in Toon Claes' three-part series introducing a `--linearize` option for `git replay`. The feature flattens merge commits into linear history by following only first parents, providing server-side functionality similar to `git rebase --no-rebase-merges`.

The email responds to Junio C Hamano's review of the v2 patch, which raised two technical questions about commit handling. Toon confirms that the current implementation intentionally treats root commits (those with no parents) differently from merge commits (those with multiple parents) under `--linearize`, and acknowledges that a test case was incorrectly described as covering "down to root commit" when it actually excluded the root commit. Both issues are now resolved: the test description will be corrected and the command split for clarity.

The series has reached a mature state, with all substantive feedback from v1 and v2 incorporated. The remaining work consists of mechanical documentation and test updates rather than architectural changes. The collaborative review process—particularly Junio's careful technical scrutiny and Elijah Newren's documentation-focused feedback—has significantly strengthened the implementation.
