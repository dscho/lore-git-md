This is the fourth patch in a six-patch series addressing Windows LLP64 compatibility for large objects (>4GB). The series systematically converts object header lengths from `unsigned long` to `size_t` across the object-file and hash algorithm code paths, with all production code changes already validated in Git for Windows.

This patch adds a test case to `t/t1007-hash-object.sh` verifying that `` `git hash-object --stdin` `` correctly processes files larger than 4GB on platforms where `size_t` is 64-bit. The test reuses the 5GB file (`big`) created in the previous test case but regenerates it if missing to ensure independence when running specific test numbers. The test is marked `EXPENSIVE` and `SIZE_T_IS_64BIT`, reflecting its resource requirements and platform applicability.

The test scope is intentionally limited: it does not write the object to the object store or apply filters, focusing solely on the `--stdin` code path's ability to handle large memory buffers. This complements the earlier test for `` `git hash-object --literally` `` and completes the verification of the two primary large-object input methods. The patch is a straightforward test addition with no code changes, maintaining the series' focus on platform compatibility without introducing new functionality.
