This is the third patch in Patrick Steinhardt’s four-patch series introducing reference-writing subcommands to the `git refs` builtin. It adds the `git refs update` subcommand, which mirrors the functionality of `git update-ref <refname> <oldoid> <newoid>`. The implementation follows the same pattern as the `delete` subcommand introduced in the previous patch, offering a unified interface for reference manipulation under `git refs`.

The patch touches `builtin/refs.c`, adding a new `cmd_refs_update()` function that parses command-line arguments, validates object IDs, and delegates to `refs_update_ref()`. The new subcommand supports the same options as `git update-ref`: `--message` (for reflog entries), `--no-deref` (to update symbolic refs directly), and `--create-reflog` (to force reflog creation). The man page (`Documentation/git-refs.adoc`) is updated to document the new subcommand, and a new test script (`t/t1465-refs-update.sh`) verifies its behavior, including edge cases like stale old values, invalid object IDs, and argument validation.

The implementation is straightforward and well-tested, with 13 test cases covering creation, updates, symbolic ref handling, reflog behavior, and error conditions. The code aligns with the series’ goal of consolidating reference operations under a single command, and the commit message clearly states its equivalence to `git update-ref`.
