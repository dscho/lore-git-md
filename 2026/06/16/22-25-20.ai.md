This is the sixth patch in Matt Hunter's 7-patch series (v2) implementing the global `fetch.followRemoteHEAD` configuration option. It introduces the core configuration variable and integrates it into the fetch machinery, completing the feature's primary implementation.

The patch adds `fetch.followRemoteHEAD` as a global fallback setting that applies to all remotes lacking an explicit `remote.<name>.followRemoteHEAD` configuration. The implementation follows the established `fetch.prune`/`remote.*.prune` precedence pattern, using case-sensitive value matching (`strcmp`) and excluding the "warn-if-not-$branch" value at the global level (as it is inherently remote-specific). The configuration logic is integrated into `git_fetch_config()` with non-fatal error handling for invalid values, and the effective `followRemoteHEAD` mode is computed in `do_fetch()` with fallback to the built-in default when no configuration exists.

Key technical details include:
- A new `follow_remote_head` field in the `fetch_config` struct, initialized to `FOLLOW_REMOTE_UNCONFIGURED` to distinguish unset configuration from explicit defaults
- Refactored advice messages in `set_head_advice_msg()` to reference both global and per-remote configuration variables
- Updated documentation in `Documentation/config/fetch.adoc` and `Documentation/config/remote.adoc` to clarify the relationship between global and per-remote settings
- Comprehensive test coverage in `t5510-fetch.sh` verifying feature parity, precedence rules, and edge cases (e.g., dangling symrefs, `--quiet` interaction, refspec fetches)
