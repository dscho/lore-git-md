This is a platform compatibility discussion in the ongoing Windows LLP64 large-object series. Johannes Schindelin responds to Patrick Steinhardt's architectural question about using `size_t` versus a platform-independent typedef like `objsize_t`.

Johannes firmly rejects the idea of introducing a fixed-width type, reaffirming that `size_t` is the correct choice because it accurately represents what the current platform can handle in memory. He clarifies that for streaming scenarios on 32-bit platforms (where objects might exceed 4GB), `off_t` would be the appropriate type, but notes that such setups come with significant performance and practicality limitations—particularly for delta chain reconstruction.

The response effectively closes the design discussion Patrick raised, reinforcing the series' existing approach. No changes to the patches are implied; this is purely a clarification of the rationale behind the type choice.
