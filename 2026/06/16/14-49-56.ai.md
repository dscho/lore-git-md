This is the fifth patch in a six-patch series addressing Windows LLP64 compatibility for handling objects larger than 4GB. The series systematically converts object header lengths from `unsigned long` to `size_t` across core object-file code paths, with all production changes already validated in Git for Windows.

This patch adds a test case to `t/t1007-hash-object.sh` that verifies `git hash-object` (without any options) correctly processes files larger than 4GB on platforms where `size_t` is 64-bit. The test reuses the 5GB file (`big`) generated in earlier tests if it exists, or regenerates it using `test-tool genzeros` if missing. It compares the output of `git hash-object -- big` against precomputed expected hashes for both SHA-1 and SHA-256, ensuring the standard hashing code path handles large memory buffers without truncation. Like the other large-file tests in this series, it is marked `EXPENSIVE` and `SIZE_T_IS_64BIT`.

The patch completes the test coverage for the series by exercising the final major code path: standard file hashing without `--stdin` or `--literally`. Earlier patches in the series already verified `--stdin` input (patch 4/6), `--literally` processing (patch 1/6), and the SHA1DC interface (patch 3/6). The test infrastructure is consistent with the rest of the series, using the same 5GB file and expected hash values (`test_oid large5GB`).

This is a straightforward test addition with no code changes to production files. The patch follows the series' established pattern of minimal, focused test cases that validate specific code paths. The test is well-motivated by the series' goal of ensuring all object-hashing code paths work correctly with large files on LLP64 platforms. No open questions or objections remain for this patch or the series as a whole.
