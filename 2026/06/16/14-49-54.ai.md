This is the third patch in a six-part platform compatibility series addressing Windows LLP64 limitations for handling objects larger than 4GB. The series systematically converts object header lengths from `unsigned long` to `size_t` across the object-file and hash algorithm code paths, with all production changes already validated in Git for Windows.

This patch updates the SHA1DC interface (`sha1dc_git.c` and `sha1dc_git.h`) to use `size_t` for section lengths, completing the type conversion chain for the SHA-1 implementation. The change is subtle but critical: while the function signature of `git_SHA1DCUpdate()` is updated, no call sites are modified directly because the function is always invoked through the `git_SHA1_Update` macro, which internally downcasts from `size_t` to `unsigned long`. The patch removes this implicit downcast, ensuring consistency with the rest of the series. The commit message explains this indirection clearly, addressing potential reviewer confusion about the lack of call-site changes.

The patch also updates `object-file.c` to pass `size_t` through the `hash_object_body()` function, maintaining type consistency in the call chain. A minor cleanup removes an outdated "Sha1.." comment in favor of a more generic "Hash (function pointers) computation" note, reflecting the algorithm-agnostic nature of the code. The test in `t/t1007-hash-object.sh` is updated to reflect the fix, changing the `test_expect_failure` to `test_expect_success` for the 5GB file-hashing case now that the truncation issue is resolved.

The series is technically sound, with this patch representing the final link in the type conversion chain for the SHA-1 implementation. The changes are minimal and focused, touching only the necessary interfaces while maintaining backward compatibility. The test infrastructure added in earlier patches (including the 5GB file test) now passes unconditionally on platforms where `size_t` is 64-bit, confirming the fix works as intended. No open questions remain, and the architectural discussion about type consistency has been resolved in favor of `size_t` for memory-addressable sizes.
