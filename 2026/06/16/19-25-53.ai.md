This is a **contributor housekeeping** proposal about commit message trailers, specifically suggesting Git adopt an `Assisted-by:` tag for AI-assisted commits and adjust its trailer-handling behavior.

Marius Spix reports an inconsistency in how Git handles trailers: `git commit --signoff` adds an empty line before the `Signed-off-by:` trailer and skips the trailer if the commit message is otherwise empty, but `git commit --trailer "\nAssisted-by: OpenAI"` does not convert the `\n` to a newline and still includes the trailer even when the rest of the message is empty. He proposes that Git should normalize this behavior and automatically propagate `Assisted-by:` tags when merging or squashing commits, treating them as "taint" markers similar to `Co-authored-by:` or `Helped-by:`.

The email does not include a patch or implementation, only a behavioral observation and a request for discussion. It ties the proposal to the Linux kernel's recent adoption of an `Assisted-by:` requirement for AI-assisted commits, suggesting Git should align with that practice. No prior discussion in this thread is referenced, so this appears to be the thread root. The tone is exploratory rather than prescriptive, inviting opinions on whether Git should formalize support for AI attribution.
