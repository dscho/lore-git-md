This is the second patch in Toon Claes's three-part series introducing a `--linearize` option to `git replay`. It is a refactoring patch that extracts and renames helper functions in `replay.c` to improve code clarity and prepare for the main feature implementation in patch 3/3.

The patch splits the existing `mapped_commit()` function into two distinct helpers: `get_mapped_commit()` (retrieving a commit from the `replayed_commits` khash map) and `put_mapped_commit()` (inserting a new commit into the same map). This separation makes the code more readable and aligns with the "get/put" naming convention common in Git's codebase. The change is purely internal—no behavior is altered, and the khash OID map and its error-checking logic remain unchanged.

The patch touches only `replay.c`, moving 11 lines of logic into a new helper and renaming the original function. The diff is clean and focused, with no functional overlap with other subsystems. This refactoring is a prerequisite for the `--linearize` implementation in the next patch, where `put_mapped_commit()` will be used to handle merge commits by mapping them to their first parent.

All substantive feedback from prior rounds has been addressed in this version of the series, and this patch carries Johannes Schindelin's Signed-off-by, indicating his support. The refactoring is well-motivated and uncontroversial, serving as a straightforward preparation step for the feature work to come.
