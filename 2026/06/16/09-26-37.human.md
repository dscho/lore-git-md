This is the final patch in Toon Claes's three-part series introducing a `--linearize` option to `git replay`. The series is now complete and ready for merging, with all substantive feedback from prior rounds incorporated.

The patch implements the core `--linearize` functionality, which flattens merge commits into linear history by walking only first parents—effectively replicating `git rebase --no-rebase-merges` behavior on the server side. The implementation adds the CLI option (`--linearize`), documents it in the man page (including its incompatibility with `--revert`), and updates the test suite to cover edge cases like root commit handling, `--linearize`/`--advance` combinations, and patch preservation verification via `git range-diff`.

Key changes in this patch include:
- The `pick_regular_commit()` helper now accepts a `replayed_base` parameter to support linearization.
- Merge commits are explicitly dropped (not replayed) when `--linearize` is active, with their children reparented onto the previous non-merge commit.
- The test suite (`t3650-replay-basics.sh`) expands significantly, adding four new tests that verify linearization behavior, root commit handling, and patch equivalence.

The series has undergone thorough review from Junio Hamano, Elijah Newren, Justin Tobler, and Johannes Schindelin (who co-authored this patch and provided a Signed-off-by). All technical concerns—such as root commit handling, boolean vs. enum control flow, and documentation clarity—have been resolved. The implementation is clean, well-tested, and aligns with the project's goal of enabling server-side rebase functionality. No further architectural changes are expected.
