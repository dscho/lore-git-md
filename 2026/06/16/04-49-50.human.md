This is a refactoring patch from a GSoC participant that introduces a new `append_formatted_path()` helper function to centralize Git's path formatting logic. The path handling code was previously duplicated in `builtin/rev-parse.c` and wrote directly to stdout, making it difficult to reuse elsewhere.

The new function in `path.c` provides several standardized path formatting options through a `path_format` enum:
- UNMODIFIED (output path as-is)
- RELATIVE (make path relative to given prefix)
- RELATIVE_IF_SHARED (relative only if sharing common prefix)
- CANONICAL (fully resolved absolute path)
- DEFAULT (maps to UNMODIFIED)

The implementation handles edge cases like NULL prefixes, non-absolute paths, and shared repository detection. It uses Git's existing path utilities like `relative_path()` and `strbuf_realpath_forgiving()` under the hood. The patch includes comprehensive documentation of the API in `path.h`.

This is the first of a 4-part series that will later refactor `rev-parse` to use this shared implementation. The code shows careful attention to memory management with proper cleanup of temporary strbufs. The change is well-contained and focused on providing reusable path formatting infrastructure - a solid foundation for the rest of the series. The implementation looks clean and follows Git's coding style, with good test coverage coming in subsequent patches.
