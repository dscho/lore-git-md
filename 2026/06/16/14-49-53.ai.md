This is the second patch in a six-part platform compatibility series addressing Windows LLP64 limitations for handling objects larger than 4GB. The series systematically converts object header lengths from `unsigned long` to `size_t` across the object-file subsystem to prevent 32-bit truncation on Windows.

This patch updates `object-file.c` and related ODB source files to use `size_t` for memory buffer lengths in the object hashing and writing code paths. The changes touch `hash_object_file()`, `write_object_file_prepare()`, and their callers in `odb/source-files.c`, `odb/source-inmemory.c`, and `odb/source-loose.c`. The patch maintains interface compatibility while fixing the type mismatch that causes the 5GB test case (added in patch 1/6) to fail on Windows. The header buffer length parameter is also converted to `size_t` for consistency, though this is currently upcast to `uintmax_t` for printf formatting.

The patch is mechanical and focused, changing only type signatures without altering behavior. All production code changes have already been validated in Git for Windows, and the series has no outstanding technical objections. The type conversion continues the call chain walk begun in patch 1/6, with subsequent patches addressing lower-level hash functions. The changes are minimal and targeted, touching only the necessary interfaces while preserving backward compatibility.
