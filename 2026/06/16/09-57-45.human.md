This is a **substantive review** of patch 5/6 in Harald Nordgren’s `git branch --delete-merged` series (formerly `--prune-merged`). The patch adds a per-branch opt-out mechanism via `branch.<name>.pruneMerged=false`, allowing users to exempt specific branches from automated cleanup while still permitting explicit deletion.

Phillip Wood’s feedback focuses on two implementation details. First, he identifies a performance and correctness issue in the config-checking loop: the code currently releases and reallocates the `strbuf` on every iteration, which is inefficient and unnecessary. He suggests resetting the buffer instead and moving the release outside the loop. Second, he questions the test design, noting that the new test case duplicates setup logic from earlier tests and could be merged into an existing scenario rather than standing alone. Both points are technical rather than conceptual — the feature itself is sound, but the patch needs minor structural adjustments to align with Git’s coding and testing conventions.

The review is constructive and specific, targeting code hygiene rather than functionality. With these tweaks, the patch should be ready for final approval. The series as a whole remains on track for merging, now that all major design questions have been resolved in earlier iterations.
