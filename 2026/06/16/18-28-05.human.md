This is the final patch in Harald Nordgren’s 15-part series adding `git branch --delete-merged` (formerly `--prune-merged`), which now introduces a `--dry-run` option to preview deletions. The patch itself is small and focused: it prints the branches that would be deleted without actually removing them, using the same filtering logic as the real command.

Phillip Wood’s review is brief but substantive. He endorses the dry-run feature as useful but flags two technical concerns. First, he objects to the new boolean `dry_run` parameter in `prune_merged_branches()`, arguing that a flags-based API (like the existing `delete_branches()` function) would be more consistent and extensible. This is not just a nit—it affects the entire series, and Phillip notes that earlier feedback about parameter design should have been applied throughout. Second, he suggests integrating dry-run testing into the existing test cases rather than adding standalone scripts, which would make the tests more efficient and ensure the preview behavior matches live execution.

Harald’s reply is short and constructive: he acknowledges the oversight and thanks Phillip for catching it. The exchange confirms that the dry-run feature is well-received, but the patch needs minor structural adjustments to align with Git’s coding conventions. The test design issue is not addressed in this reply, but it remains an open concern—Phillip’s earlier reviews have elevated test efficiency and realism to blocking issues for the series. If Harald addresses both points, the patch should be ready for merging.
