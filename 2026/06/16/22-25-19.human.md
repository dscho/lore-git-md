This is the fifth patch in Matt Hunter’s seven-patch series implementing the global `fetch.followRemoteHEAD` configuration option. It refactors the fetch machinery to handle the new global setting while preserving the existing per-remote behavior.

The patch introduces `FOLLOW_REMOTE_UNCONFIGURED` as the new zero-initialized state for the `follow_remote_head_settings` enum, allowing the code to distinguish between an unset value and the explicit default (`FOLLOW_REMOTE_CREATE`). The `do_fetch()` function is updated to determine the effective `followRemoteHEAD` mode, falling back to the system default when no remote-specific setting exists. The `set_head()` function now accepts the mode as an argument rather than relying solely on the remote’s configuration, decoupling the decision logic from the configuration source.

This is a clean, mechanical refactoring that prepares the codebase for the next patch, which will introduce the user-configurable global default. The changes are minimal and focused, with no behavior changes—just the groundwork for the upcoming feature. The patch looks well-structured and aligns with the established configuration patterns in Git.
