This thread began with Uwe Kleine-König’s patch to fix a bug where `git rebase` incorrectly copies notes from dropped commits to the current HEAD, corrupting note history. The discussion quickly expanded into a systemic audit of how the rebase machinery handles dropped commits across all operations—empty changes, fixup sequences, edit commands, skip operations, external merge strategy failures, and command execution failures. Phillip Wood took the lead, producing an 11-patch series that addresses all known edge cases and is now queued in Junio’s tree for final review, carrying Uwe’s Tested-by.

The series is self-contained and ready to land. The core fix (patch 11/11) introduces `PICK_RESULT_DROPPED` to ensure notes and post-rewrite hooks no longer receive information about dropped commits. Earlier patches refactor the sequencer’s control flow to prepare for this change, with no behavior modifications. Test coverage has been expanded to include both "apply" and "merge" backends, fixup sequences, edit commands, and newly identified edge cases like external merge strategy failures and command execution failures. A minor tooling issue with `b4 am` was resolved manually, and typofixes for editorial corrections are already queued.

The only open technical question is a known limitation: the "edit" command still erroneously records dropped commits as rewritten when `rebase --continue` is run, which will require a separate fix. Oswald Buddenhagen raised surface-level concerns about patch organization and code aesthetics, but Phillip rejected these as unnecessary churn, and the series’ technical goals remain unaffected. No substantive objections have been raised, and the series is expected to merge soon. Uwe’s original patch is now redundant and will likely be dropped.
