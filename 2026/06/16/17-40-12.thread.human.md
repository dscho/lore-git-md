This thread is about a systemic fix to a bug in `git rebase` where notes from dropped commits were incorrectly copied to the current HEAD, corrupting note history. The issue expanded into a broader audit of how the rebase machinery handles dropped commits across various operations, including edge cases like external merge strategy failures and command execution failures.

Phillip Wood has sent a 10-patch v2 series that fully addresses the problem, including all known edge cases. The series is complete, carries Uwe Kleine-König’s Tested-by, and is queued in Junio’s tree for final review. Key changes include fixing how the sequencer handles merge tool crashes and permission errors (patch 3/10), ensuring consistency in command execution failures (patch 4/10), and introducing `enum pick_result` to simplify control flow (patches 8/10 and 9/10). The final patch (10/10) implements the core behavioral change, ensuring notes and post-rewrite hooks no longer receive information about dropped commits. Test coverage has been expanded to cover both "apply" and "merge" backends, fixup sequences, and the newly addressed edge cases.

The only remaining loose ends are minor: a known limitation with the "edit" command (documented and flagged for a separate fix), and typofixes for editorial corrections in commit messages. Oswald Buddenhagen provided surface-level feedback on punctuation and grammar in patch 3/10’s commit message, but this does not affect the series’ technical direction. Phillip has confirmed he will squash these typofixes locally and send a rerolled version once further substantive reviews are complete. Junio’s latest email clarifies that the series is ready for final review and no substantive changes are required. The series is expected to land soon.
