This thread is about a long-standing bug in `git rebase` where notes from dropped commits (such as those with empty changes or during fixup sequences) were incorrectly copied to the current HEAD, corrupting the repository’s note history. The issue expanded into a systemic audit of how the rebase machinery handles dropped commits across edge cases like external merge failures, command execution errors, and skipped operations.

Phillip Wood authored a 10-patch v2 series that fixes the core issue and addresses all known edge cases, including merge tool crashes, permission errors, and `git commit` failures. The series also simplifies control flow in `sequencer.c` through targeted refactorings, such as introducing `enum pick_result` and removing redundant checks. Uwe Kleine-König, who originally reported the bug, tested the series and confirmed the regression is resolved. Junio C Hamano, the maintainer, has now given final approval, marking the series ready for the `next` branch and the next Git release. The only remaining step is merging minor typofixes (addressing surface-level feedback from Oswald Buddenhagen) before the series lands.

The key technical change is in patch 10, which ensures dropped commits are no longer recorded as rewritten, preventing notes and post-rewrite hooks from receiving incorrect information. Test coverage has been expanded to include both the "apply" and "merge" backends, fixup sequences, and edge cases like merge tool failures. Oswald Buddenhagen’s feedback was exclusively surface-level and has no impact on the series’ technical direction. The series is now effectively complete and expected to land soon.
