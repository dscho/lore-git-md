This thread is about a systemic fix to prevent `git rebase` from incorrectly copying notes from dropped commits to the current HEAD, corrupting note history. The issue expanded into a broader audit of how the rebase machinery handles dropped commits across various operations, including edge cases like external merge strategy failures and command execution errors.

Phillip Wood’s 10-patch v2 series, which addresses all known edge cases, is complete and approved by Junio C Hamano. The series is ready for the `next` branch pending minor typofixes, including a correction to the commit message in patch 2/10 noted by Andrei Rybak. The fix is self-contained, well-tested, and carries Uwe Kleine-König’s Tested-by. Key changes include introducing `enum pick_result` to simplify control flow and ensuring notes and post-rewrite hooks no longer receive information about dropped commits. A known limitation with the "edit" command remains, flagged for a separate fix.

The discussion also touched on refactoring scope, with Phillip advocating for incremental changes to minimize disruption, while Oswald Buddenhagen suggested broader stylistic refactoring. Phillip’s approach prevailed, and the series is now poised to land in the next Git release. Uwe’s original patch is superseded, and no further action is expected from him. The thread is effectively resolved, with only minor editorial corrections remaining.
