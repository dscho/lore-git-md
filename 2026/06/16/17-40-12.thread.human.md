This thread is about a bug in `git rebase` where notes from dropped commits—those whose changes are already present in the target branch—are incorrectly copied to the current HEAD, corrupting the repository’s note history. Uwe Kleine-König sent a patch to fix this, but the discussion has expanded to address broader correctness issues in how the rebase machinery handles dropped commits, including fixup sequences, edit commands, and skip operations.

The original patch adds a `dropped_commit` flag to track when a commit is skipped and avoids copying its notes, but Junio C Hamano and Phillip Wood identified several unresolved issues. The most critical is a fixup-commit edge case where the patch might break `record_in_rewritten()` logic, potentially mapping notes to the wrong commit. Phillip also found three additional bugs in how rebase handles dropped commits: final fixup cleanup, edit command handling, and skip command handling. While Uwe addressed surface-level feedback (like test script style), he hasn’t resolved the fixup-commit edge case or added documentation to clarify when users can expect notes to be lost. Phillip has volunteered to tackle these systemic issues in follow-up patches within two weeks, and Uwe has agreed to monitor for them.

The patch is not yet ready for merging.
