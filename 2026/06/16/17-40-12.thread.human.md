This thread is about a 9-patch series from Phillip Wood that fixes a bug in `git rebase` where notes from dropped commits (e.g., those with empty changes or during fixup sequences) were incorrectly copied to the current HEAD, corrupting note history. The series has grown into a systemic audit of how the rebase machinery handles dropped commits across all operations, including edge cases like external merge strategy failures (e.g., merge tool crashes) and command execution failures (e.g., `git commit` failing to run).

The series is now complete and approved by Junio Hamano, who has proposed marking it ready for the `next` branch. Key changes include introducing `enum pick_result` to replace integer return codes in `do_pick_commit()`, adding `PICK_RESULT_DROPPED` to skip `record_in_rewritten()` for dropped commits, and expanding test coverage for both "apply" and "merge" backends, fixup sequences, and edge cases like merge tool failures. The series also addresses a known limitation with the "edit" command, which still erroneously records dropped commits as rewritten when `rebase --continue` is run—this is documented and flagged for a separate fix.

Phillip’s patches have received substantive review and testing from Uwe Kleine-König (the original patch author) and surface-level feedback from Oswald Buddenhagen and Andrei Rybak, focusing on grammar, punctuation, and commit message clarity. Oswald’s suggestions were low-weight and have been incorporated as typofixes by Junio, who will squash them before the series advances. Phillip rejected some of Oswald’s broader refactoring suggestions to avoid unnecessary churn, and the series’ technical direction remains unchanged. The only remaining loose ends are the "edit" command limitation and the pending typofixes, neither of which block the series’ progress. The series is expected to land in the next Git release.
