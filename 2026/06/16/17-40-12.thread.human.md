This thread began when Uwe Kleine-König reported a bug in `git rebase`: when a commit is dropped (e.g., because its changes are already present), its notes are incorrectly copied to the current HEAD, corrupting the repository’s note history. Phillip Wood responded with a 9-patch systemic overhaul (v3) that fixes the issue for non-interactive rebase and `--empty=drop` in interactive rebase, while also addressing edge cases like fixup sequences, edit commands, external merge strategy failures, and command execution failures. The series has been approved by Junio C Hamano and is ready for the `next` branch pending minor typofix squashing.

The core fix introduces `enum pick_result` to clarify the sequencer’s return values and ensures `record_in_rewritten()` skips dropped commits. Tests now cover both rebase backends ("apply" and "merge"), external merge tool failures, and post-rewrite hooks. However, Uwe later reported a regression: the fix doesn’t work for *user-initiated drops* in interactive rebase (e.g., `git rebase --skip` or `--continue` without committing), where notes are still copied. Phillip acknowledged this gap, noting the series only handles `--empty=drop` (non-interactive default), not `--empty=ask` (interactive default), which behaves inconsistently (drops on `--continue`, keeps on `--skip`). A follow-up series is expected to address this.

Reviews were mixed in depth. Phillip’s patches received substantive, tested-level feedback from Uwe and Junio, while Oswald Buddenhagen provided exclusively surface-level comments (punctuation, grammar) and a low-confidence acknowledgment ("it seems to make sense"). Junio’s latest email defends the value of such cursory replies, framing them as `Acked-by` signals that help gauge consensus, though they don’t alter the series’ technical status. The thread also touched on procedural meta-commentary (mailing-list vs. Gerrit workflows) and minor commit message tweaks, all of which have been queued as typofixes. The series is technically complete and will land in `next` shortly, with the interactive rebase regression to be resolved separately.
