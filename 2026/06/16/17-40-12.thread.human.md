This thread is about a bugfix for `git rebase` that prevents incorrect note copying when a commit disappears during rebase because its changes are already present in the target branch. The issue occurs when Git mistakenly attaches notes from the disappearing commit to the unrelated commit currently at HEAD. Uwe Kleine-König authored the patch, which modifies the sequencer subsystem to track dropped commits and skip note copying in those cases.

The fix is straightforward: it adds a `dropped_commit` output parameter to `do_pick_commit()` and propagates this information through the call chain. Phillip Wood had previously suggested this approach, and while Uwe describes the implementation as "not pretty," it addresses the bug effectively. The patch includes thorough test coverage with a new test script, `t3322-notes-rebase.sh`, ensuring the fix works as intended.

This is a well-contained, focused fix for a real (if edge-case) bug, touching only the sequencer code and adding appropriate tests. There are no open questions or objections in the thread so far, and the patch appears ready for review and potential merging.
