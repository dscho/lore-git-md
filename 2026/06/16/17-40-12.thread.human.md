This thread is about a systemic fix to a bug in `git rebase` where notes from dropped commits were incorrectly copied to the current HEAD, corrupting the repository’s note history. The issue was initially reported by Uwe Kleine-König, but the solution has since expanded into a 10-patch overhaul led by Phillip Wood, addressing not just the original bug but also edge cases like external merge strategy failures, command execution failures, and systemic refactoring of the sequencer’s control flow.

Phillip’s series is now complete and queued in Junio’s tree for final review. The core fix, introduced in the final patch, ensures that notes and post-rewrite hooks no longer receive misleading information about dropped commits—whether due to empty changes, fixup sequences, edit commands, or other edge cases. The series also restores test coverage for the "apply" backend, adds tests for merge tool failures and command execution failures, and simplifies the sequencer’s logic with targeted refactorings. A known limitation remains: the "edit" command still erroneously records dropped commits as rewritten when `rebase --continue` is run, but this is flagged for a separate fix.

Key participants include Uwe, who provided the original patch and later tested Phillip’s series, and Junio, who queued the series with minor typofixes. Oswald Buddenhagen raised surface-level concerns about patch organization, but these were rejected as unnecessary churn. The series is now ready to land, with no substantive changes expected beyond squashing the queued typofixes.
