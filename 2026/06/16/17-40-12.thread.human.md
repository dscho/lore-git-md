This thread is about a systemic fix to Git’s rebase machinery to prevent notes from being incorrectly copied from dropped commits. The issue was originally reported by Uwe Kleine-König, but Phillip Wood’s 9-patch series (v3) has now fully addressed it, along with a broader audit of how the sequencer handles dropped commits across various operations—empty changes, fixup sequences, edit commands, skip operations, external merge strategy failures, and command execution failures.

The series is complete and has been approved by Junio Hamano, who has proposed marking it ready for the `next` branch once minor typofixes are squashed. Key changes include fixing error handling for external merge strategies (e.g., merge tool crashes) and command execution failures (e.g., `git commit` failing to run), as well as ensuring post-rewrite hooks and notes no longer receive information about dropped commits. The series also includes test coverage expansions and refactoring to simplify control flow, though Phillip intentionally kept the refactoring incremental to avoid unnecessary churn.

The only remaining loose end is a known limitation with the "edit" command, which still incorrectly records dropped commits as rewritten when `rebase --continue` is run—this is documented and flagged for a separate fix. Uwe’s original patch is now superseded, and no further action is expected from him. Reviewers Oswald Buddenhagen and Andrei Rybak provided surface-level feedback (grammar, punctuation, commit message wording), which has been incorporated as typofixes. The series is expected to land in the next Git release.
