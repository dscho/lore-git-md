This thread began with Uwe Kleine-König’s patch to stop Git from incorrectly copying notes from dropped commits during rebase. Phillip Wood expanded it into a nine-patch systemic overhaul that fixes not just notes but the entire handling of dropped commits—whether from empty changes, fixup sequences, edit commands, skip operations, external merge strategy failures (e.g., merge tool crashes), or command execution failures (e.g., `git commit` failing to run). The series also restores test coverage for the "apply" backend, improves error handling for merge tools and commit commands, and refactors the sequencer’s control flow to make the behavioral change safer and clearer.

Phillip’s v3 series is now complete and approved by Junio C Hamano, who has proposed marking it ready for the `next` branch once minor typofixes are squashed. The core fix—preventing dropped commits from being recorded as "rewritten"—is implemented in the final patch, which adds a `PICK_RESULT_DROPPED` enum value and skips `record_in_rewritten()` for such commits. Tests confirm notes and post-rewrite hooks no longer receive misleading data. One known limitation remains: the "edit" command still records dropped commits as rewritten when `rebase --continue` is run, but this is documented and flagged for a separate fix.

Reviews were mostly surface-level, focusing on punctuation, grammar, and commit message wording. Oswald Buddenhagen and Andrei Rybak contributed exclusively low-weight feedback, while Phillip’s responses clarified the series’ technical direction and rejected suggestions that would have introduced unnecessary churn. Uwe’s original patch is now superseded, and no further action is expected from him. The series is a substantive, tested-level contribution that addresses a real bug without broader disruption.
