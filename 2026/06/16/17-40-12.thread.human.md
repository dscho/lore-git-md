This thread began with a bug report by Uwe Kleine-König: when `git rebase` drops a commit, it incorrectly copies that commit’s notes to the current HEAD, corrupting note history. Phillip Wood took this as the starting point for a 10-patch overhaul that now addresses how the rebase machinery handles *all* dropped commits—not just those with empty changes, but also fixup sequences, edit commands, skip operations, external merge strategy failures, and command execution failures (e.g., `git commit` failing to run).

Phillip’s v2 series is complete and queued in Junio’s tree, carrying Uwe’s Tested-by. The first patch restores test coverage for the “apply” backend; the second moves a helper function without changing behavior. The third patch—just summarized—fixes a long-standing gap in error handling: external merge strategies that fail for reasons other than conflicts (exit code ≠ 0 or 1) now trigger a reschedule rather than a silent drop. The final patch (10/10) introduces the core behavioral change, ensuring notes and post-rewrite hooks no longer receive information about any dropped commit. Test coverage has been expanded across three scripts, including new tests for merge-tool crashes and command failures.
