This thread began with Uwe Kleine-König’s patch to fix a bug where `git rebase` incorrectly copied notes from dropped commits to the current HEAD. The discussion quickly expanded into a broader audit of how the rebase machinery handles dropped commits across all operations—empty changes, fixup sequences, edit commands, skip operations, external merge strategy failures, and command execution failures.

Phillip Wood then sent an 11-patch series that systematically addresses all these edge cases. The series is now complete, queued in Junio’s tree, and carries Uwe’s Tested-by. The final patch (11/11) introduces the core fix by adding `PICK_RESULT_DROPPED` to the sequencer’s pick result enum, ensuring notes and post-rewrite hooks no longer receive information about dropped commits. The series also includes pure refactoring patches (2/11–10/11) to simplify control flow, expanded test coverage for both apply and merge backends, and fixes for external merge strategy failures and command execution failures. A minor tooling issue with `b4 am` was resolved manually, and Junio has queued typofix commits for minor editorial corrections, which Phillip will squash locally.

The only remaining loose end is a documented limitation: the "edit" command still incorrectly records dropped commits as rewritten when `rebase --continue` is run, but this is flagged for a separate fix. Uwe’s original patch is now functionally redundant, and no further action is expected unless Junio requests it. The series is ready for final review and is expected to land soon.
