This is the fifth patch in Matt Hunter’s 7-patch v2 series implementing the global `fetch.followRemoteHEAD` configuration.  It refactors the fetch machinery to support a fallback default value when no per-remote setting exists.

The patch introduces a new `FOLLOW_REMOTE_UNCONFIGURED` enum value (zero-initialized) so the code can distinguish between an unset configuration and the explicit system default (`FOLLOW_REMOTE_CREATE`).  The `do_fetch()` function is updated to compute the effective `followRemoteHEAD` mode itself, falling back to the built-in default when the remote-specific setting is missing.  The `set_head()` helper is modified to accept the mode as an explicit argument rather than reading it directly from the remote struct.  The “warn-if-not-$branch” value is deliberately excluded from the global fallback logic because it is inherently remote-specific; the patch preserves the existing per-remote handling of `no_warn_branch`.

The diff touches only `builtin/fetch.c` and `remote.h`, with no new tests or documentation in this patch.  The changes are mechanical and follow the established `fetch.prune`/`remote.*.prune` precedence pattern.  All review feedback from Junio on case sensitivity and error handling has already been incorporated in earlier patches.
