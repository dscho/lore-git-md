SHA-1/SHA-256 interoperability work update from brian m. carlson. The branch implements core functionality with a passing test suite, covering protocol extensions for shallow clones, submodule handling, partial clones, and recursive delta resolution in `git index-pack` (reworked iteratively). Current limitations include filtered bundles, multi-pack index usage, packfile URIs, and edge cases; unresolved technical challenges involve object map batching and performance optimization. The 200+ patch series is not targeted for Git 3.0 due to scope and testing requirements, with the author open to others upstreaming the work. The branch remains available for testing but unstable, with no `Reviewed-by` or `Acked-by` tags.

Junio C Hamano raised two high-weight security/correctness concerns about the implementation:
1. **Packfile URIs**: The interoperability layer requires each pack to connect to the repository history to resolve unmapped objects, but packfile URIs deliver multiple packs that are only complete in aggregate. The protocol pack (delivered first) is almost never connected to local history, preventing indexing in multi-algorithm repositories. While a theoretical fix exists (pause `git index-pack`, download all URIs, index them, then resume), no implementation currently addresses this.
2. **Large-object promisors**: The server must possess the *entire* history to generate object mappings, ruling out promisor remotes that offload objects to secondary storage. This limitation affects submodule mappings, shallow clones, and partial clones, but regular fetches/clones work against existing servers (unless submodules are involved). Submodule mappings require a security override because clients cannot verify that SHA-1 and SHA-256 object IDs correspond to the same commit, preventing malicious server spoofing.

Additional technical details:
- **Delta handling**: When objects are rewritten between hash algorithms, deltas are preserved by mapping base/target objects to their new names, avoiding redeltification costs.
- **Current usability**: The branch works today for repositories without submodules (example: `git clone --object-format=sha256:sha1 https://github.com/bk2204/lawn.git`).
- **Open questions**: No progress on packfile URI resolution or promisor remote support; these remain blockers for broader adoption. Participant positions unchanged; thread awaits further discussion or implementation updates.
