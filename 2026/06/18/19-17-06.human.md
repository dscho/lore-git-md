This is the final patch in Harald Nordgren’s four-part series introducing the new `` `git history squash` `` subcommand. It completes the user-experience story by making the `--reedit-message` option actually useful: instead of reopening only the oldest commit’s message, the editor now presents every folded-in message (oldest first), exactly mirroring the familiar `` `git rebase -i` `` squash workflow.

The patch adds a new helper, `build_squash_message()`, that walks the commit range in reverse topological order, extracts each message body, and concatenates them into a single template. The template is built before any descendant replay begins, so the walk’s internal flags do not corrupt the messages. The man page is updated to clarify that `--reedit-message` now offers all messages, not just the oldest, and the test script grows two new cases: one that verifies the combined template contains every folded message, and another that checks the command aborts cleanly if the user leaves the editor empty.

This is a small but important polish layer on top of the core squash logic. The implementation is clean, the tests are thorough, and the change directly addresses the only remaining UX gap Phillip Wood identified in the previous round. With this patch the series is now feature-complete and ready for Junio’s final assessment.
