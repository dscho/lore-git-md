This is the second patch in Harald Nordgren’s v14 `--track=fetch` series, implementing the user-facing feature for `git checkout` and `git switch`. It adds a `fetch` mode to the `--track` option that automatically fetches the remote branch before checking it out, addressing the workflow pain point where users must manually fetch before creating a tracking branch.

The patch extends the `--track` option syntax to accept a comma-separated list of modes: `direct` (default), `inherit`, and now `fetch`. When `fetch` is included, the command identifies the remote whose fetch refspec maps to the given `<start-point>`, runs `git fetch <remote> <src-ref>` for just that ref, and proceeds with the checkout. The implementation handles edge cases such as bare remote names (e.g., `origin`), hierarchical remote names (e.g., `nested/remote`), ambiguous refspecs, and offline failures. If the fetch fails but the remote-tracking ref already exists locally, the command warns and proceeds from the existing tip; otherwise, it aborts.

The patch touches `builtin/checkout.c`, updating the option parser (`parse_opt_checkout_track`) to recognize the new `fetch` mode and introducing `fetch_remote_for_start_point` to encapsulate the fetch logic. The documentation for both `git-checkout` and `git-switch` is updated to describe the new mode, including its behavior, error conditions, and interaction with other tracking modes. The test coverage is comprehensive (276 lines in `t/t7201-co.sh`), verifying all advertised behaviors: successful fetches, offline fallback, namespace resolution, ambiguous refspec handling, quiet mode, and invalid input rejection.

This patch depends on the first patch in the series, which refactored `branch.c` to expose tracking remote lookup functions. The implementation is technically complete and approved, with all requested changes (including the v14 header cleanup) addressed. The series now awaits Junio’s final decision on whether the feature’s workflow benefits justify its inclusion, as the maintainer has expressed sustained reservations about automatic network operations during checkout.
