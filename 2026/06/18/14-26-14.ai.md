This is a feature patch that enhances Git's command typo handling. When a user mistypes a Git command and there is exactly one close match, Git now prompts interactively (if running in a terminal) with "Did you mean 'git checkout neo'? [y/N]"—showing the full corrected invocation including original arguments. Answering 'y' re-executes Git with the corrected command; any other input exits as before. The original behavior (printing a suggestion list and exiting) is preserved for non-interactive sessions or when multiple matches exist.

The patch updates `help_unknown_cmd()` to accept the full argument vector so the prompt can reconstruct the intended command line. It touches `builtin/help.c`, `git.c`, `help.c`, and `help.h`, and adds comprehensive tests in `t/t9003-help-autocorrect.sh` covering interactive and non-interactive scenarios, including TTY prerequisites for the prompt logic.

The implementation is careful to preserve existing behavior for edge cases (multiple matches, scripts, pipes) and only activates the prompt when stdin and stderr are both terminals. The commit message is clear and the test coverage looks thorough, including a creative use of a wrapper script to simulate user input in a test-terminal environment. This appears to be a well-scoped, user-friendly improvement with no obvious downsides.
