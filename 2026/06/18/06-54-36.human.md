This is the seventh patch in Patrick Steinhardt’s eight-part refactoring series modernizing Git’s reference backend. It tackles a long-standing initialization quirk that causes the reference database to be constructed twice when "onbranch" configuration conditionals are present.

The problem is a classic chicken-and-egg scenario: the reference database needs configuration to set itself up, but the configuration parser needs a reference database to evaluate "onbranch" conditions. Git currently handles this by skipping "onbranch" checks when the refdb format is `REF_STORAGE_FORMAT_UNKNOWN`, but the check fails because the format is usually set during repository discovery. The result is a recursive call to `get_main_ref_store()`, constructing the same refdb twice and leaking one instance (though the leak was masked by the `chdir_notify` subsystem).

Patrick’s fix is pragmatic: before constructing the refdb, he temporarily sets the format to `UNKNOWN`, forcing the "onbranch" check to skip. After initialization, he restores the original format. This prevents the recursion and ensures "onbranch" conditions are consistently ignored during refdb setup. The change is confined to `refs.c` and adds 18 lines of straightforward logic.

The patch is well-motivated and addresses a real issue, but the solution—repurposing `UNKNOWN` as an initialization signal—is acknowledged as awkward. Earlier versions of the series explored alternatives (like eager refdb construction), but those broke `git config set` in misconfigured repositories. The current approach is a compromise, and Patrick’s commit message candidly explains the trade-offs.

Reviewers familiar with Git’s initialization sequence (like Junio C Hamano or Karthik Nayak) may weigh in on whether this is the least-bad option or if a cleaner signal (e.g., a dedicated flag) is worth adding. For now, the patch is a necessary step toward eliminating `chdir_notify_reparent()` and simplifying the ref backend. It’s unlikely to be controversial in principle, but the implementation may prompt further discussion.
