This is the sixth patch in Karthik Nayak’s seven-patch series extending `git log -L` (line-log) to support range-scoped diff stat formats, whitespace checking, and the `-G` pickaxe. This patch specifically adds support for `--check` when used with `-L`, ensuring that whitespace errors are reported only within the tracked line ranges and that the reported line numbers match the actual file positions rather than counting from the start of the range hunk.

The implementation reuses the `line_range_filter` infrastructure introduced in earlier patches, wrapping `checkdiff_consume()` to forward only in-range lines for whitespace checking. A key challenge was preserving the correct file line numbers in error reports, which the patch addresses by routing the synthetic hunk headers through an optional callback to `checkdiff_consume_hunk()`. The patch also gates the trailing blank-at-EOF check on the tracked ranges, preventing false positives when the blank line lies outside the range. The documentation and `setup_revisions()` are updated to list `--check` among the supported `-L` formats, and the test coverage in `t/t4211-line-log.sh` verifies that errors are correctly scoped, reported with accurate line numbers, and handle edge cases like gaps within a single range or multiple ranges.

The patch is well-motivated and technically sound, addressing a clear gap in `-L`’s functionality. The commit message and code comments explain the design choices clearly, and the test cases cover both basic and edge-case scenarios. This is a natural extension of the series’ goal to make `-L` work consistently with common diff options, and it looks ready for review.
