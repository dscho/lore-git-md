Core problem or goal
When a user mistypes a Git command, Git currently prints a list of close matches and exits. The patch proposes to change this so that, when there is exactly one close match and the session is interactive (stdin and stderr are terminals), Git prompts the user with the full corrected command line (including original arguments) and re-executes if the user answers 'y'.

Current status
Patch is under review; no prior versions. The patch's necessity is now contested because the proposed behavior already exists via the `help.autoCorrect=prompt` configuration option, which provides identical functionality (interactive prompt with argument preservation). The patch does not explain why the default behavior should change or why the existing config-based approach is insufficient.
