Thread identity
Subject: interactive typo correction for Git commands
Series version: standalone patch (no version trailer)
Originating author: Jishnu C K
Thread type: feature patch

Core problem or goal
When a user mistypes a Git command, Git currently prints a list of close matches and exits. The patch proposes to change the default behavior so that, when there is exactly one close match and the session is interactive (stdin and stderr are terminals), Git prompts the user with the full corrected command line (including original arguments) and re-executes if the user answers 'y'. The author argues this improves usability by eliminating the need for users to discover or configure `help.autoCorrect=prompt` and by providing more context in the prompt (preserving arguments).

Current status
Patch is under review; no prior versions. The patch’s technical implementation (TTY detection, argument preservation) is uncontested, but its necessity and design are now contested. The proposed behavior already exists via the `help.autoCorrect=prompt` configuration option, which provides identical functionality except for argument preservation in the prompt. The thread is now focused on whether the default behavior should change or if the patch should be refactored to enhance the existing config-based approach.

Key technical details
Files touched: `builtin/help.c`, `git.c`, `help.c`, `help.h`
New behavior: `help_unknown_cmd()` now takes the full argument vector to reconstruct the intended command line; prompt logic is gated on `isatty(0) && isatty(2)`. The prompt now shows the full corrected command (e.g., `Did you mean 'git checkout neo'? [y/N]`) instead of just the corrected command name (e.g., `Run 'checkout' instead [y/N]?`).
Test coverage: new tests in `t/t9003-help-autocorrect.sh` verify interactive prompt, non-interactive fallback, TTY detection, and argument preservation.
No on-disk format changes; no new symbols exposed outside the help subsystem.
The patch duplicates most functionality of `help.autoCorrect=prompt` but differs in two ways: (1) it changes the default behavior, and (2) it preserves arguments in the prompt.

Open questions and loose ends
