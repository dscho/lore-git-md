Subject: interactive typo correction for Git commands

Core problem or goal
When a user mistypes a Git command, the existing `help.autoCorrect=prompt` configuration option provides an interactive prompt to re-execute the corrected command, but it omits the user’s original arguments from the prompt. This leaves users uncertain whether their arguments will be preserved. The v2 patch addresses this by preserving the full command line (including arguments) in the prompt, improving usability without altering the default behavior.

Current status
The v2 patch abandons the v1 proposal to change the default behavior (making the interactive prompt the default) and instead focuses on a targeted enhancement: preserving arguments in the `help.autoCorrect=prompt` prompt. The patch is uncontested technically and directly addresses Junio C Hamano’s feedback by building on the existing `autocorrect=prompt` code path. The broader design debate—whether to change the default behavior—remains unresolved, but this version is a narrowly scoped, incremental improvement.

Key technical details
Files touched: `help.c`, `t/t9003-help-autocorrect.sh`
New behavior: `help_unknown_cmd()` now accepts the full argument vector, allowing the prompt to show the complete corrected command (e.g., `Run 'git checkout neo' instead [y/N]?`). Callers that cannot provide the argument vector (e.g., `builtin/help.c`) pass `NULL`, and the prompt falls back to the old format (showing only the command name).
Test coverage: verifies that the prompt includes arguments when `help.autocorrect=prompt` is set. No on-disk format changes; no new symbols exposed outside the help subsystem.
The patch is backward-compatible and does not deprecate or modify the existing `help.autoCorrect=prompt` option.
