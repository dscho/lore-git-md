Subject: interactive typo correction for Git commands
Series version: standalone patch (no version trailer)
Originating author: Jishnu C K
Thread type: feature patch

Core problem or goal
When a user mistypes a Git command, Git currently prints a list of close matches and exits. The patch proposes to change the default behavior so that, when there is exactly one close match and the session is interactive (stdin and stderr are terminals), Git prompts the user with the full corrected command line (including original arguments) and re-executes if the user answers 'y'. The author argues this improves usability by eliminating the need for users to discover or configure `help.autoCorrect=prompt` and by providing more context in the prompt (preserving arguments). The existing `help.autoCorrect=prompt` configuration option provides identical functionality except for argument preservation in the prompt.

Current status
Patch is under review; no prior versions. The technical implementation (TTY detection, argument preservation) is uncontested, but the necessity and design of the patch are contested. The thread has shifted from technical review to a design debate: whether to change the default behavior (as the patch proposes), enhance the existing `help.autoCorrect=prompt` option (e.g., adding argument preservation and improving documentation), or abandon the patch in favor of documentation improvements alone.

Key technical details
Files touched: `builtin/help.c`, `git.c`, `help.c`, `help.h`
New behavior: `help_unknown_cmd()` now takes the full argument vector to reconstruct the intended command line; prompt logic is gated on `isatty(0) && isatty(2)`. The prompt now shows the full corrected command (e.g., `Did you mean 'git checkout neo'? [y/N]`) instead of just the corrected command name (e.g., `Run 'checkout' instead [y/N]?`).
Test coverage: new tests in `t/t9003-help-autocorrect.sh` verify interactive prompt, non-interactive fallback, TTY detection, and argument preservation.
No on-disk format changes; no new symbols exposed outside the help subsystem.
The patch duplicates most functionality of `help.autoCorrect=prompt` but differs in two ways: (1) it changes the default behavior, and (2) it preserves arguments in the prompt.
