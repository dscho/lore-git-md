This is the third patch in Harald Nordgren's v16 series introducing `git branch --delete-merged`. It adds a `DELETE_BRANCH_SKIP_UNMERGED` flag to the `delete_branches()` API, allowing bulk callers to silently skip unmerged branches instead of erroring out. This is a refactoring patch that prepares the API for the upcoming `--delete-merged` functionality while preserving existing behavior for all current callers.

The change is mechanical: the new flag is added to the `delete_branch_flags` enum, passed through to `check_branch_commit()`, and checked before emitting the "not fully merged" error. When the flag is set, unmerged branches are skipped without error, and the function returns success. The patch touches only `builtin/branch.c` and is well-scoped, with no functional changes to existing commands.

This patch directly addresses Phillip Wood's earlier feedback about API consistency by extending the flags-based interface to handle unmerged branches gracefully. The implementation is clean and follows the established pattern of the existing `DELETE_BRANCH_FORCE` and `DELETE_BRANCH_QUIET` flags. The commit message clearly states that existing callers are unaffected, which should ease review.

The new flag will be used in the next patch (4/7) to implement the core `--delete-merged` logic, where skipping unmerged branches is the desired behavior. This patch is a necessary plumbing change that enables the higher-level functionality while keeping the API flexible for future callers.
