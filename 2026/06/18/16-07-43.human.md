This is a **substantive follow-up review** from Jeff King (Peff) in the ongoing thread about Pablo Sabater’s `git log --graph` visualization series. Peff clarifies a critical implementation detail for Pablo’s proposed workaround to the prio-queue interaction blocker.

The series aims to improve `git log --graph` rendering of commits with excluded parents by cascading indentation of visual roots, but it collides with Kristofer Haugsbakk’s prio-queue refactoring (commit `dd4bc01c0a`, now in `master`). Peff’s earlier review confirmed that the prio-queue only allows peeking at the first entry, making full lookahead impossible. Pablo proposed limiting lookahead to the next commit, and Peff now points out that even this requires iterating over *both* `revs->commits` and `revs->commit_queue`, since the prio-queue refactoring left both structures in place to avoid disrupting existing callers. He suggests pushing the loop body into a helper function to avoid code duplication.

This detail does not change the fundamental feasibility of Pablo’s workaround, but it adds a concrete implementation constraint: the lookahead logic must handle both queues, not just one. The series remains blocked until Pablo demonstrates whether the three key flags can be set correctly with only the next commit, and this new wrinkle makes that task slightly more involved. The discussion is now focused on the mechanics of the workaround rather than its conceptual soundness.
