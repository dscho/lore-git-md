This is v16 of Harald Nordgren's long-running series adding `git branch --delete-merged`, a safe automated local branch cleanup command. The series is now technically complete and addresses all prior blocking issues: the API consistency problem (converting `delete_merged_branches()` to use the flags-based interface) and the stacked-branch safety debate (omitted as unnecessary per Junio C Hamano's feedback). The implementation provides comprehensive safety mechanisms, filtering capabilities, and `--dry-run` preview functionality.

The core functionality allows users to delete local branches whose work has been merged into their upstream, with multiple safety checks: it never deletes checked-out branches, skips branches whose upstream no longer exists, preserves branches that push back to their upstream (like `main` tracking `origin/main`), and supports per-branch opt-out via `branch.<name>.deleteMerged` config. The `--forked` filter enables precise branch selection, and `--dry-run` provides a preview of deletions.

Key changes in v16 include:
- Converting `delete_merged_branches()` to use an unsigned int flags argument instead of separate boolean parameters, matching the `delete_branches()` interface
- Rewriting the tests as comprehensive integration tests that verify both deleted and preserved branches in a single run, with clearer repository naming and subshell usage for setup commands
- Memory management improvements (reusing a single `strbuf` across the config loop)
- The stacked-branch protection proposal was dropped after Junio argued it was unnecessary for typical rebase workflows

The test suite now uses a single reusable repository setup and verifies all safety cases together: checked-out branches, missing upstreams, push-equals-upstream protection, and unmerged branches. The series appears ready for final review, with no known blocking issues remaining. Phillip Wood's high-weight feedback has been addressed, and the implementation now matches the project's API consistency expectations.
