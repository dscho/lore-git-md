This is the first patch in Harald Nordgren’s four-part series introducing `git history squash`. It is a refactoring patch that extracts a small helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit’s first parent (or the empty tree for root commits).

The patch touches only `builtin/history.c`, replacing three nearly identical blocks of code—each handling the parse-and-copy dance—with calls to the new helper. The change is purely mechanical and does not alter behavior; it simply removes duplication and makes the code easier to read and maintain. The helper itself is straightforward: it checks for a parent, parses it if present, and copies either the parent’s tree OID or the empty tree OID into the output parameter.

This kind of preparatory cleanup is typical in well-structured series and signals that the author is thinking ahead about code organization. The patch is small (26 insertions, 32 deletions), clearly motivated, and unlikely to be controversial. It lays the groundwork for the more substantial changes that follow in the series.
