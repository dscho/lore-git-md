This is a cleanup patch in Patrick Steinhardt's 8-part refactoring series modernizing Git's reference backend infrastructure. It removes the now-unused `chdir_notify_reparent()` function from the `chdir-notify` subsystem after the previous patch (4/8) replaced all its callers with the two-way `chdir_notify_register()`/`chdir_notify_unregister()` API.

The change is mechanical and uncontroversial: the patch deletes 26 lines of code from `chdir-notify.c` (the entire `reparent_cb()` helper and its wrapper) and updates the header file to remove the function declaration and its documentation. The commit message is minimal but sufficient, explaining that the function is now unused. This aligns with the series' broader goal of eliminating `chdir_notify_reparent()` to simplify path handling in ref backends, though the larger architectural shift (absolute path usage) has been deferred to future work.

The patch touches only the `chdir-notify` infrastructure, with no impact on ref backends or repository initialization logic. It follows the pattern established in patch 4/8, which plugged memory leaks by replacing the one-way `chdir_notify_reparent()` with proper registration/unregistration. This cleanup is a natural follow-up and should integrate smoothly, as the function's removal was already prepared by earlier patches in the series.

Reviewers familiar with the `chdir-notify` subsystem (or those who reviewed patch 4/8) would recognize this as a straightforward deletion. The patch is ready for integration and unlikely to require further discussion, as it merely removes dead code. It contributes to the series' incremental improvements by tidying up the API after the more substantive changes in preceding patches.
