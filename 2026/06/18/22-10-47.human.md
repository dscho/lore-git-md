This is a **test suite cleanup** targeting a long-standing but recently surfaced platform-compatibility issue in `t4216-log-bloom.sh`. Junio C Hamano replies to Patrick Steinhardt’s proposed fix for TAP parse errors on non-x86 architectures, where the test’s assumption about `char` signedness causes unsuppressed diff output to break the test harness.

The issue stems from a 2024 addition that uses `test_cmp` to set the `SIGNED_CHAR_BY_DEFAULT` prerequisite, which is only used by a single test that does nothing (`true`). Junio questions why this hasn’t been caught in two years and leans toward simply removing the check entirely, as the prerequisite serves no functional purpose. Patrick had suggested either dropping the check or converting it to a `test_lazy_prereq` to suppress the diff output, but Junio’s preference is clear: the simpler solution is to eliminate the unused prerequisite.

The patch is uncontroversial and low-risk, touching only the test script. The underlying question—whether the Bloom filter logic should be architecture-dependent—remains unaddressed, but neither participant sees it as relevant to the immediate fix. This is a straightforward cleanup that should resolve the CI-breaking TAP errors without side effects.
