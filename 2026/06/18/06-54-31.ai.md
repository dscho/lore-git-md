This is a refactoring patch (part of Patrick Steinhardt's 8-patch series modernizing Git's reference backend) that eliminates redundant application of repository format settings during repository initialization. The patch targets `setup.c` and adjusts the order of operations so that `repository_format_configure()` runs *before* `apply_repository_format()`, allowing the latter to handle all format propagation to the repository in one step. This removes the need for `repository_format_configure()` to directly modify the repository's hash algorithm and ref storage format, simplifying the control flow.

The change is mechanical and well-motivated: the commit message clearly explains the current redundancy (applying the same settings twice) and how the new ordering resolves it. The diff itself is small and focused, touching only the initialization sequence in `init_db()`. This patch is a preparatory step for later changes in the series, though it stands alone as a minor cleanup. Reviewers (including Justin Tobler, per the thread context) have already approved similar initialization logic in other patches, so this one is unlikely to be controversial.

Key technical details: the patch removes direct calls to `repo_set_hash_algo()` and `repo_set_ref_storage_format()` from `repository_format_configure()`, instead letting `apply_repository_format()` handle these updates. The `GIT_DEFAULT_REF_FORMAT` environment variable handling remains unchanged. This affects all repository initialization paths but does not alter behavior—only the internal sequencing of steps. The patch is part of the broader effort to simplify ref backend path handling, though it doesn’t yet tackle the larger architectural changes deferred from earlier versions of the series.

The patch is ready for integration and fits cleanly into the series’ incremental approach. It doesn’t introduce new edge cases or dependencies, making it a low-risk improvement. Future patches in the series (particularly patch 7/8) will build on this cleanup to address more complex initialization issues.
