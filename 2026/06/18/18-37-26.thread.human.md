This thread explores a new Git concept called *pinned references*—a way to specify a reference (like a tag) alongside an expected object ID, ensuring the ref exists, resolves, and points to that exact OID. The goal is to combine the readability of refs with the immutability of object IDs, creating a stable reference for external tooling. Erik Östlund proposed the idea, initially suggesting a URL-style syntax like `refs/tags/v1.2.3?oid=a1b2c3d4`, but the discussion has since shifted to evaluating alternatives.

Patrick Steinhardt pointed out that Git already has a `<describeOutput>` syntax (e.g., `v2.54.0-0-g0b13e48a3`) that expresses a similar "ref plus OID" concept, though it doesn’t enforce the invariant. Junio C Hamano weighed in to clarify that modifying `<describeOutput>` to enforce this invariant is unlikely—its behavior is too entrenched to change without breaking existing scripts. Instead, he suggested that any enforcement would need to be introduced as a new mechanism, such as a command-line option or a dedicated command. The thread remains conceptual, with no code or patches yet, and the focus is on refining the design, use cases, and syntax.

Key questions still open include whether the feature is broadly useful or niche, how to implement it safely (without encouraging reliance on OIDs that might be garbage-collected), and whether it should be a CLI-level check or require deeper ref backend changes. The discussion is still early, but the consensus so far leans toward an additive solution rather than repurposing existing syntax.
