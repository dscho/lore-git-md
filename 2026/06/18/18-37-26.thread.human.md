Erik Östlund has proposed a new Git concept called "pinned references"—a way to specify a reference (like a tag) along with an expected object ID, ensuring the ref exists, resolves, and points to the exact OID. This would combine the readability of refs with the immutability of object IDs, useful for deployment or CI/CD workflows. The initial strawman syntax uses URL-style query parameters (`refs/tags/v1.2.3?oid=a1b2c3d4`), but no code or implementation exists yet.

Patrick Steinhardt responded by pointing out that Git already has a mechanism that *almost* does this: the `<describeOutput>` syntax from `gitrevisions(7)`. For example, `git rev-parse v2.54.0-0-g0b13e48a3` resolves to the commit ID `0b13e48a3...` if the tag `v2.54.0` points to it—but Git doesn’t verify that the tag and OID match. This means the functionality exists, but enforcement doesn’t. Patrick’s reply suggests that if pinned references move forward, the discussion may shift toward extending the existing syntax (e.g., adding a `--verify` flag to `git rev-parse`) rather than inventing something new.

The thread remains in the exploratory phase, with open questions about syntax, use cases, and whether this is a niche need or a broadly useful feature. No other participants have weighed in yet, and no code has been written. The key takeaway is that Git already has a way to express "tag plus OID," but it lacks the safety checks Erik envisions.
