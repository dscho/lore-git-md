This is the second patch in Karthik Nayak’s seven-patch series extending `` `git log -L` `` to support range-scoped diff stat formats, whitespace checking, and the `` `-G` `` pickaxe. This patch simplifies the line-range filter in `` `diff.c` `` by classifying removal lines immediately rather than buffering them, which eliminates a latent bug where deletions just outside the tracked range could leak into the patch output.

The core change is that the filter now classifies each `` `-` `` line as it arrives, using the post-image position of the following `` `+` `` or `` ` ` `` line (which xdiff emits immediately after the removals). This removes the need for the `` `pending_rm` `` buffer and its associated state (`` `pending_rm_count` ``, `` `pending_rm_pre_begin` ``, and the `` `discard_pending_rm()` `` helper), and also drops the per-hunk counters (`` `old_count` ``, `` `new_count` ``, `` `has_changes` ``) in favor of deriving them from the buffered lines when the hunk is flushed. The new `` `begin_range_hunk()` `` helper seeds the hunk’s begins from the live image cursors at the first in-range line, and `` `flush_range_hunk()` `` now walks the buffer to compute the counts and detect changes.

The patch fixes a real bug: the old code would flush pending removals into the range hunk whenever the hunk was active, even after the post-image cursor had advanced past the tracked range, leaking deletions just outside the range into the patch. The new model makes this impossible by construction. The commit message documents the coordinate model in detail and includes a worked example, and the test suite adds coverage for the leaked trailing deletion, the symmetric leading-deletion case, and edge cases at the range boundaries (changes at the first and last line of a range, and a pure in-range deletion).

The patch is a clean refactoring that reduces state and eliminates a bug, and it prepares the ground for the later patches that add stat, `` `--check` ``, and `` `-G` `` support. The commit message is thorough and the test coverage is extensive, which suggests the author has thought carefully about the edge cases. The changes are confined to `` `diff.c` `` and the test suite, with no on-disk format or user-visible behavior changes beyond the bug fix.
