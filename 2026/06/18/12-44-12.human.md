This is the second patch in Harald Nordgren’s 14th revision of the `--track=fetch` feature for `git checkout` and `git switch`. It implements the user-facing behavior: when you run `git checkout -b new_branch --track=fetch origin/some-branch`, Git now fetches the latest tip of `origin/some-branch` before creating the new local branch. The patch is technically complete, with all requested refinements from earlier rounds incorporated and comprehensive test coverage (276 lines) verifying edge cases like ambiguous remotes, offline failures, and hierarchical remote names.

The implementation is clean and conservative: it only fetches the specific branch you asked for, leaves other remote-tracking branches untouched, and falls back gracefully if the fetch fails but the remote-tracking ref already exists locally. The code reuses the tracking-remote lookup logic introduced in patch 1/2, so the behavior is consistent with `git branch --track`. Documentation updates are clear and cover all modes (`direct`, `inherit`, and `fetch`), including error conditions and quiet-mode operation.

This patch is ready to merge from a technical standpoint—Junio and Phillip Wood have already approved the design and implementation in earlier iterations, and the v14 update only addressed a minor header cleanup. The open question is whether the feature’s workflow benefits justify its inclusion; Junio has expressed sustained reservations about automatic network operations during checkout, and the series now awaits his final decision on that point. If the feature is accepted, this patch will be the one that delivers it to users.
