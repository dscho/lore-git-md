This is the fourth patch in Harald Nordgren's v16 series implementing `git branch --delete-merged`, a new command for safe automated local branch cleanup. The patch prepares the existing `delete_branches()` function for bulk use by the upcoming `--delete-merged` feature, adding two new modes: one that skips the HEAD fallback when checking merge status, and another that performs a dry run without actually deleting refs.

The changes are mechanical and focused: `delete_branches()` gains two new flags, `DELETE_BRANCH_NO_HEAD_FALLBACK` and `DELETE_BRANCH_DRY_RUN`, which modify its behavior without altering the function's core logic. The `NO_HEAD_FALLBACK` flag ensures the function only checks whether a branch is merged into its upstream, not HEAD, which is necessary for `--delete-merged` to avoid redundant merge-base checks. The `DRY_RUN` flag mirrors the actual deletion logic exactly but prints "Would delete" messages instead of removing refs, providing a preview of what would happen.

The patch maintains backward compatibility: existing callers (like `git branch -d`) continue to use the original behavior, falling back to HEAD when no upstream exists. The implementation is clean, with clear flag documentation and no behavioral changes for current users. The dry-run mode is particularly well-designed, reusing the same code path as real deletions to ensure accuracy.
