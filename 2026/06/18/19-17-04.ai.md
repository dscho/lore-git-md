This is the second patch in Harald Nordgren’s four-patch v3 series introducing `git history squash`. It adds an optional `message_template` parameter to the internal `commit_tree_ext()` helper in `builtin/history.c` so that callers can seed the commit message from something other than the single commit they are handed. The squash subcommand will use this in the next patch to populate the editor with every folded-in message, not just the oldest one.

The change is a straightforward plumbing tweak: when `message_template` is NULL, the function falls back to the original behavior (using the commit’s own message). The existing `fixup` and `split` callers pass NULL, so they are unaffected. The patch is 16 lines (10 insertions, 6 deletions) and touches only `builtin/history.c`. No tests or documentation are added here; those follow in patches 3/4 and 4/4.

This is a well-scoped refactoring that directly enables the user-experience improvement Phillip Wood requested in the previous round. The implementation is clean and backward-compatible, and the commit message clearly explains the motivation.
