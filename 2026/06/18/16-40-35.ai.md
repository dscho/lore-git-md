This is a **substantive review** from Jeff King (Peff) on **patch 7/8** of Patrick Steinhardt’s refactoring series for Git’s reference backend. The patch addresses a recursive initialization issue in `get_main_ref_store()` triggered by "onbranch" config conditions, but Peff challenges the fundamental design that creates the recursion in the first place.

Peff argues the recursion stems from an architectural misstep: `ref_store_init()` should not rely on the general config subsystem to read backend-critical settings like `logAllRefUpdates`. Instead, these settings should either be (1) deferred until after the ref store is initialized or (2) read alongside other repository-format settings (e.g., `core.repositoryFormatVersion`) via `read_repository_format()`, which intentionally ignores includes. He demonstrates this with a `BUG()` marker in `include_by_branch()` showing that the current recursion only occurs when the ref store is *partially* initialized, not when no repository exists at all.

The review suggests the patch’s workaround—temporarily unsetting `ref_storage_format`—is treating a symptom rather than the root cause. Peff’s alternative would require splitting config parsing into two passes: one for repository-format settings (ignoring includes) and another for user config (respecting includes). This aligns with the series’ broader goal of cleaning up ref backend initialization but would likely require a more invasive change than the current patch. The thread’s prior discussion (summarized in the parent email) had settled on the current approach as pragmatic, but Peff’s feedback reopens the design question.

Key technical details Peff highlights:
- The recursion is triggered by `repo_settings_get_log_all_ref_updates()` calling into the general config parser during `ref_store_init()`.
- `read_repository_format()` already avoids includes, suggesting a model for how ref backend config could be read safely.
- The current patch’s workaround may mask deeper issues in how config and ref store initialization interact.

This review is **tested** (Peff includes a reproduction case) and **substantive**, directly engaging with the patch’s core logic. It could shift the series’ direction if Patrick revisits the design, though the prior consensus may limit changes to follow-up work. The patch remains uncontroversial in its current form, but Peff’s critique flags a potential technical debt.
