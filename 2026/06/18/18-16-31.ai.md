This is the sixth patch in Karthik Nayak’s seven-patch series extending `git log -L` (line-log) to support range-scoped diff stat formats, whitespace checking, and the `-G` pickaxe. This patch implements `--check` support, ensuring that whitespace errors are reported only within the tracked line ranges and that the reported file line numbers are accurate.

The patch reuses the `line_range_filter` infrastructure introduced earlier in the series to wrap `checkdiff_consume()`, the same pattern already used for patch output and diffstat. A key challenge is that `checkdiff` reports file line numbers, which it normally learns from the hunk header via `checkdiff_consume_hunk()`. The filter synthesizes its own hunk headers, so the patch adds an optional hunk callback to `line_range_filter` and routes `checkdiff_consume_hunk()` through it, ensuring the post-image position is set before in-range lines are replayed. Without this, reported line numbers would count from the start of the range hunk rather than the start of the file.

The trailing blank-at-eof check, which scans the whole file via `check_blank_at_eof()`, is also gated on the tracked ranges. The patch adds a helper function, `idx_in_ranges()`, to check whether a given line falls within any of the tracked ranges, and uses it to suppress reports of blank lines at EOF that lie outside the range. The patch updates `setup_revisions()` to add `DIFF_FORMAT_CHECKDIFF` to the `-L` output format allowlist, ensuring `-L --check` is accepted, and updates the documentation to list `--check` among the supported formats.

Test coverage in `t/t4211-line-log.sh` is extensive, verifying that whitespace errors are reported only within the tracked range, that file line numbers are correct (including when two errors in one range are separated by a gap that would otherwise split into multiple xdiff hunks), and that blank-at-eof errors outside the range are suppressed. The patch touches `diff.c`, `revision.c`, and the line-range documentation, and is a natural extension of the infrastructure built in earlier patches. The commit message is detailed and includes worked examples, which suggests the author has put care into explaining the changes. The patch looks well-crafted and addresses a clear gap in `-L`’s functionality.
