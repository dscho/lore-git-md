This is the cover letter for the **v3 series introducing `git history squash`**, a new feature that folds a commit range into its oldest commit while preserving descendant history. The series is now **technically complete and approved by Junio C Hamano**, with only a trivial test script renumbering (from `t3454` to `t3455`) remaining before queuing.

The implementation pivots from the earlier `git rebase --squash` proposal to a standalone `git history squash` subcommand, addressing architectural and efficiency concerns raised in prior discussion. The core design performs a **single three-way merge** of the entire range against the oldest commit’s parent, avoiding the repeated conflict stops of a rebase-based approach. Descendants are replayed on top of the squashed result, and ranges with merge commits are handled gracefully (only multi-base ranges are rejected). The `--reedit-message` option seeds the editor with **all folded-in commit messages** (oldest first), matching `git rebase -i`’s squash behavior via a new `build_squash_message()` helper.

The series consists of four patches:
1. A refactoring patch extracting `first_parent_tree_oid()` (26 insertions, 32 deletions).
2. A plumbing patch adding a `message_template` parameter to `commit_tree_ext()` (16 insertions, 6 deletions).
3. The core squash implementation (154 insertions in `builtin/history.c`, a 20-line man page section, and a 213-line test script).
4. The `--reedit-message` implementation (17 insertions, 20-line test additions).

**Key files touched**: `builtin/history.c`, `Documentation/git-history.adoc`, and `t/t3455-history-squash.sh` (renamed from `t3454`). The test suite covers range parsing, merge commit handling, descendant replay, authorship preservation, and edge cases like `fixup!` commits and empty-message aborts.
