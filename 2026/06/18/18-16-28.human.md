This is the third patch in Karthik Nayak’s seven-patch series extending `` `git log -L` `` to support range-scoped diff stat, whitespace checking, and the `` `-G` `` pickaxe. This patch aligns the hunk headers produced by `` `-L` `` with those from `` `git diff` `` by delegating header formatting to xdiff’s own emitter instead of hand-rolling it.

The patch fixes a long-standing off-by-one bug in the hunk header’s “begin” field when one side of the diff has zero lines (e.g., a pure insertion). Previously, `` `-L` `` would emit `` @@ -25,0 +18,9 @@ `` for an insertion at line 18 in a 24-line file, whereas `` `git diff` `` would use 24. The fix is mechanical: the hand-rolled `` strbuf_addf() `` is replaced with a new `` xdiff_emit_hunk_header() `` helper that wraps xdiff’s `` xdl_emit_hunk_hdr() ``, so the headers now match exactly, including the omission of a count of 1 (`` @@ -22 +22 @@ `` instead of `` @@ -22,1 +22,1 @@ ``).

The change touches `` diff.c `` and adds the helper to `` xdiff-interface.c `` and its header. Two test fixtures in `` t/t4211-line-log.sh `` are regenerated to reflect the corrected headers. The commit message explains the bug’s origin (it predates the series) and how the two fixtures reached it from different directions, which gives confidence the fix is robust. This is a small but necessary cleanup that removes a visual inconsistency and prepares the code for the range-scoped diff features that follow.
