Patrick acknowledges the awkwardness of the current approach but explains why alternatives are unworkable. The core issue is a circular dependency: constructing the reference database requires parsing Git configuration, but parsing configuration (specifically "onbranch" conditions) may require constructing the reference database. His first attempt to resolve this by eagerly constructing the refdb failed because it broke `git config set` in misconfigured repositories, where users expect to be able to fix configuration issues without manual file editing. The current patch's workaround—temporarily setting `ref_storage_format` to `REF_STORAGE_FORMAT_UNKNOWN`—is presented as the least bad solution, ensuring "onbranch" conditionals are honored except during ref store construction.

The response reveals this as a fundamental design tension in Git's initialization sequence rather than a superficial implementation flaw.
