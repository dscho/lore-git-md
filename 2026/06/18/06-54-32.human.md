This is the third patch in Patrick Steinhardt’s 8-part refactoring series modernizing Git’s reference backend. It addresses a control-flow hygiene issue in repository discovery by moving the application of the `GIT_REFERENCE_BACKEND` environment variable so it only executes when a repository is actually found.

The patch eliminates redundant logic: previously, the environment variable was applied unconditionally, even when no repository existed, and required manually reapplying the repository format afterward. Now, the variable is only processed during repository discovery, allowing the format to be adjusted *before* `apply_repository_format()` is called. This removes the need for an explicit `repo_set_ref_storage_format()` call and makes the initialization sequence cleaner.

The change is small (39 lines modified in `setup.c`) and mechanical, with no behavior change—just a reordering of operations to improve clarity. It incorporates Justin Tobler’s suggestion from the previous iteration, which was accepted by Patrick. The patch is uncontroversial and ready for integration, fitting neatly into the series’ broader goal of simplifying reference backend initialization. Reviewers familiar with repository setup (like Junio C Hamano) would likely find this an obvious improvement.
