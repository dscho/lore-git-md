This thread is about a patch by Jishnu C K that proposes making Git’s interactive typo correction the default behavior when a user mistypes a command in an interactive terminal session. Currently, Git suggests close matches but requires users to manually enable interactive correction via the `help.autoCorrect=prompt` configuration option. The patch would prompt users automatically (e.g., `Did you mean 'git checkout neo'? [y/N]`) and re-execute the corrected command if confirmed, while preserving the original arguments for better usability.

The patch’s necessity is now the central debate. Justin Tobler pointed out that the proposed behavior already exists via the config option, shifting the discussion from technical implementation to design justification. Jishnu argues the patch improves usability by removing the need for configuration and providing more context in the prompt (e.g., including arguments), but the core question remains: should the default behavior change, or should the patch be refactored to enhance the existing `autocorrect=prompt` mode instead? The technical details—TTY detection, argument preservation, and test coverage—are uncontested, but the patch’s fate hinges on whether the usability gains outweigh the disruption of altering the default. No decisions have been made yet, and the thread is now focused on this trade-off.
