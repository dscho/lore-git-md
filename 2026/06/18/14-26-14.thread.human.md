This thread is about a proposed change to Git’s command typo correction: when a user mistypes a Git command in an interactive terminal session, the patch would prompt them with the corrected full command line (including arguments) and re-execute it if they confirm. The patch’s author, Jishnu C K, argues this improves usability by making the feature more discoverable and providing better context in the prompt.

The discussion has shifted from the patch’s technical implementation—which is uncontested—to whether the default behavior should change at all. Justin Tobler, a key reviewer, questions the need to alter defaults, noting that the same functionality already exists via the `help.autoCorrect=prompt` configuration option. He suggests the real issue is discoverability, proposing better documentation as a less disruptive alternative. While he’s indifferent to the patch’s argument-preservation improvement (showing the full corrected command in the prompt), this feature’s value remains unresolved pending broader feedback.

The thread is now focused on design trade-offs: whether changing the default is justified, if the prompt enhancement is worth modifying the existing config-based approach, or if documentation alone would suffice. No consensus has emerged yet, and the path forward hinges on whether others find the argument-preservation feature compelling enough to warrant inclusion. The patch’s technical details—like TTY detection and argument reconstruction—are not in dispute, but its necessity and scope are.
