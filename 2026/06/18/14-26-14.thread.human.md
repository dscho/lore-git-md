This thread proposes a small but useful enhancement to Git’s interactive typo correction. When a user mistypes a command and has `help.autoCorrect=prompt` set, Git currently asks whether to run the corrected command—but the prompt omits the user’s original arguments, leaving them unsure if their intended flags or paths will be preserved. Jishnu C K’s patch (now at v2) fixes this by showing the full corrected command in the prompt, like `Run 'git checkout neo' instead [y/N]?`.

The change is narrowly scoped and uncontroversial. It builds on the existing `autocorrect=prompt` code path, preserving backward compatibility: callers that can’t provide the full argument vector (like `git help`) fall back to the old behavior. Junio C Hamano’s feedback on the earlier version—preferring incremental improvements over changing defaults—is fully addressed here. The patch touches only `help.c` and its test file, with no broader impact on Git’s internals or on-disk formats.

The main open question isn’t technical but UX-related: whether this feature is discoverable enough. The patch doesn’t tackle that, leaving it for future discussion. For now, the argument-preservation addition seems ready to merge, as it’s a clear usability win without any downsides.
