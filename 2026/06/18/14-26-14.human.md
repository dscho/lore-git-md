This is a user-facing feature patch that improves Git's command typo handling. When a user mistypes a Git command and there is exactly one close match, Git now prompts interactively: "Did you mean 'git checkout neo'? [y/N]". Answering "y" re-executes Git with the corrected command and the original arguments; anything else exits as before. The feature only activates when stdin and stderr are both connected to a terminal, preserving the existing behavior (printing a suggestion list and exiting) for scripts, pipes, or ambiguous matches.

The patch updates `help_unknown_cmd()` to accept the full argument vector so the prompt can show the complete corrected invocation. It touches `builtin/help.c`, `git.c`, `help.c`, and `help.h`, and adds thorough tests in `t/t9003-help-autocorrect.sh` covering interactive and non-interactive cases, single and multiple matches, and both "y" and "n" responses.

The implementation is careful about edge cases: it checks for TTY presence, handles argument reconstruction cleanly, and maintains backward compatibility. The commit message is clear and the test coverage looks solid. This is a small but polished quality-of-life improvement that should reduce friction for new users without disrupting automation.
