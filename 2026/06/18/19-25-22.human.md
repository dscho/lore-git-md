This is the v16 cover letter for Harald Nordgren's long-running series adding `git branch --delete-merged`, a new command for safe automated cleanup of local branches whose work has already landed upstream. The series is now functionally complete and addresses all previously blocking issues.

The key change in v16 is the conversion of `delete_merged_branches()` to use a flags-based API, matching the style of `delete_branches()` and resolving the last major technical blocker identified in v15. The test suite has also been rewritten as proper integration tests: instead of many small, isolated test repositories, there is now a single reusable setup that exercises all safety mechanisms (checked-out branches, missing upstreams, push divergence, per-branch opt-out) in one realistic workflow, with output verified via `test_cmp`. This makes the tests both more maintainable and more convincing.

The implementation provides several layers of safety: branches are only deleted if their tip is reachable from their upstream, checked-out branches are never touched, branches whose upstream no longer exists are skipped, and branches that push back to their upstream (like a local `main` tracking `origin/main`) are preserved. Users can opt out per-branch via `branch.<name>.deleteMerged` config, and `--dry-run` lets them preview deletions before committing. The `--forked` filter (introduced earlier) lets users target only branches whose upstream lives on a specific remote or matches a glob pattern.

This version appears ready for serious review. The API is now consistent, the test coverage is thorough and realistic, and the safety mechanisms are well thought out. The only remaining work is likely to be minor documentation tweaks rather than functional changes. Phillip Wood, who provided detailed feedback on earlier versions, has not yet reviewed v16, but the changes here directly address his last round of concerns.
