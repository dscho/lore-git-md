This is the first patch in Harald Nordgren’s v16 series introducing `git branch --delete-merged`, adding the `--forked` filter to `git branch --list`. The filter lets users list only branches whose upstream matches a given ref, remote, or glob pattern (e.g., `origin/main`, `origin`, or `origin/*`). It’s a building block for the later `--delete-merged` command, which will use this filter to identify branches whose work has landed upstream and can be safely deleted.

The implementation is clean and well-tested: the patch adds the filter to the ref-filter machinery, documents it in the man page, and includes a thorough test suite covering literal refs, globs, remote shorthand, and composition with other filters like `--merged` and `--no-merged`. The tests use a reusable repository setup with clear naming (`forked-upstream`, `forked-other`, `forked`) and verify both positive and negative cases.

This patch is a refactoring that enables the later feature work; it doesn’t change behavior on its own but provides the foundation for the series’ core functionality. The series as a whole is now technically complete and addresses all prior blocking issues, so this patch is ready for final review alongside the rest of v16.
