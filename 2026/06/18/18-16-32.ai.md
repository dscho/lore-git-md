This is the final patch in Karthik Nayak’s seven-part series extending `git log -L` to support range-scoped diff stat formats, whitespace checking, and the `-G` pickaxe. Patch 7 teaches `-G` to honor the tracked line ranges, so commits are selected only if the pattern appears on an added or removed line within the range.

The implementation exposes the line-range filter as `diff_emit_line_ranges()`, a new helper in `diff.c` that wraps `xdi_diff_outf()` and forwards only the lines within the given ranges to the caller’s line callback. In `diffcore-pickaxe.c`, `diff_grep()` now calls this helper when ranges are set, routing the xdiff pass through the filter. The pickaxe callback (`pickaxe_match()`) threads the filepair’s `line_ranges` through to `diff_grep()`, but skips scoping under textconv because the driver’s output is not in the original file’s line coordinates. `-S` is left unchanged, as it counts needle occurrences per blob rather than grepping the diff; the commit message justifies this as requiring a different approach and notes it as a follow-up.

The documentation update in `line-range-options.adoc` clarifies that `-G` is range-scoped while `-S` still matches the whole file, and the test coverage in `t/t4211-line-log.sh` verifies that `-G` now correctly ignores changes outside the tracked range and falls back to whole-file search under textconv. The patch is cleanly integrated with the rest of the series, reusing the infrastructure introduced in patches 1-4, and the commit message explains the design choices and limitations clearly.
