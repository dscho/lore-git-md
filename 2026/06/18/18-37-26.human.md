This is a feature proposal from Erik Östlund asking whether Git has (or should have) a way to express a reference *and* an expected object ID together, so that both the ref’s existence *and* its current target can be checked atomically.

Erik’s strawman syntax is `refs/tags/v1.2.3?oid=a1b2c3d4`—the idea is that Git would fail if the ref exists but points to a different commit. He notes that tags are human-readable but mutable, while object IDs are immutable but opaque; he wants both properties at once, and currently has to track them separately in external tooling.

There is no mention of prior discussion or existing Git-native mechanism in the email, so this appears to be a fresh idea rather than a revival of an old thread. The tone is exploratory rather than a patch or RFC, so it is likely to spark discussion rather than land quickly.
