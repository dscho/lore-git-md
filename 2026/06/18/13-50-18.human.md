This is a bugfix patch targeting Git's zlib wrapper, authored by Johannes Schindelin.

The patch addresses a subtle but important issue in how Git clamps buffer sizes when interacting with zlib on platforms where `unsigned long` and `size_t` differ in bit size. The problem was introduced in a recent commit (d05d666977, "git-zlib: handle data streams larger than 4GB", 2026-05-08) that attempted to handle large data streams but incorrectly clamped values by masking bits rather than enforcing the maximum value of `unsigned long`. This could lead to zlib being passed a buffer size of 0 in edge cases, which would likely cause incorrect behavior or crashes.

The fix is straightforward: replace the bitwise masking with a proper clamping function (`zlib_uLong_cap`) that ensures values are capped at `ULONG_MAX_VALUE` when necessary. The change affects only the `git-zlib.c` file, modifying how `total_in` and `total_out` are handled before and after zlib calls.

This is a low-level plumbing fix with no user-visible impact, but it's clearly well-motivated and addresses a real correctness issue.
