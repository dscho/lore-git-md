This is the first patch in a two-part refactoring series (v2) that moves the global `ignore_case` variable into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. The patch introduces the new field and a getter function, `repo_ignore_case()`, which includes a `repo->initialized` check to ensure safe access during repository setup. This design aligns with the pattern used by other repository-specific configuration getters like `trust_executable_bit` and `protect_hfs`.

The change is mechanical and well-motivated, addressing the maintainer’s feedback from v1 by adopting a consistent getter pattern. The commit message clearly explains the rationale—reducing global state and tying the configuration value to its repository instance—while the code itself is straightforward, adding only 16 lines across two files. No behavior changes are introduced, and the patch retains the existing fallback logic (returning `0` when the repository isn’t initialized).

This patch sets the stage for the second patch, which will update all call sites to use the new getter. The series is part of a broader initiative to eliminate globals, and this patch follows the established pattern for migrating such variables. It looks ready for review, with no obvious red flags in the implementation. The only open question is whether the performance overhead of repeated getter calls (noted in the cover letter) will be acceptable, but that’s deferred to the second patch.
