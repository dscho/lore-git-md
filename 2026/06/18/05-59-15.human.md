This is a follow-up in the ongoing refactoring series by Patrick Steinhardt to modernize Git’s reference backend. The email is Patrick’s response to Justin Tobler’s substantive review of patch 7/8, which addresses a recursive initialization issue in `get_main_ref_store()` when evaluating "onbranch" config conditions.

Patrick acknowledges Justin’s critique—that temporarily setting `ref_storage_format` to `REF_STORAGE_FORMAT_UNKNOWN` as a signal to prevent recursion is awkward—but explains why no cleaner alternative exists. The core problem is a circular dependency: constructing the refdb requires parsing Git config, but config parsing (specifically "onbranch" conditions) may need to read refs, which requires the refdb. Patrick tried making the refdb non-lazy to use `r->refs_private` as a signal, but this broke `git config set` in misconfigured repositories, where users expect to fix config issues without manual file edits. He concludes that the current workaround, while hacky, is the least bad solution given Git’s design constraints.

The response is pragmatic and transparent about the trade-offs. Patrick doesn’t dismiss Justin’s concern but instead frames it as an inherent limitation of Git’s architecture. He emphasizes that the patch preserves the intended behavior—honoring "onbranch" conditionals everywhere except during refdb construction—while admitting the implementation is inelegant. This leaves the door open for future improvements but justifies the current approach as necessary for now.

For readers tracking the series, this exchange highlights a key tension in the refactoring effort: balancing incremental progress with long-term design cleanliness. The series is otherwise well-reviewed and close to integration, but this design choice in patch 7/8 remains a potential technical debt. If the discussion stalls here, the patch will likely proceed as-is, but Justin’s critique could inspire follow-up work to introduce a dedicated initialization flag. Either way, the outcome will shape how future ref backend changes interact with config parsing.
