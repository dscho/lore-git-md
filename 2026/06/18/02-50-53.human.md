This is a process discussion about the `--track=fetch` feature series, now at its thirteenth iteration. Junio C Hamano responds to Harald Nordgren’s reflection on the review process, clarifying the project’s expectations for feature proposals.

Junio acknowledges Harald’s frustration but pushes back on the idea that technical review should wait until the feature’s fundamental value is settled. He explains that contributors are expected to address *both* high-level design questions (why the feature is worthwhile) and mechanical implementation details (how it is built). The latter, he notes, is often easier to tackle first, especially when reviewers say, "I’m not sure this is a good idea, but if it is, here’s how the code could be improved." Junio emphasizes that the bar for inclusion is not universal enthusiasm—only enough support to justify an opt-in feature—and that he doesn’t need to personally agree with the feature as long as trusted contributors vouch for it.

The email doesn’t re-litigate the feature’s merits or suggest next steps for the series. Instead, it serves as a gentle corrective to Harald’s process critique, reinforcing that iterative technical refinement is a normal part of Git’s development workflow, even for features whose acceptance is uncertain. For readers, this exchange highlights the project’s balance between open-ended discussion and incremental progress, and underscores that even well-crafted patches can stall if they fail to build broader consensus.
