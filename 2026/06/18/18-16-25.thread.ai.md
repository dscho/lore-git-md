Subject: [PATCH 0/7] line-log: support range-scoped diff stat, whitespace check, and -G pickaxe
Series version: v2 (second iteration)
Originating author: Karthik Nayak
Thread type: patch series

Core problem or goal
Extend `git log -L` (line-log) to support range-scoped diff stat formats (`--stat`, `--numstat`, `--shortstat`), whitespace checking (`--check`), and the `-G` pickaxe. The goal is to make these common diff options work consistently with the line-range filter, so that only changes or errors within the tracked line ranges are reported.

Current status
Series is at v2. Patches 1 (refactoring), 2 (bug fix), and 3 (hunk header off-by-one fix) are now fully described. Patch 3 replaces hand-rolled hunk header logic with `xdiff_emit_hunk_header()`, ensuring `-L` output matches `git diff` exactly. The change fixes an off-by-one where headers for pure insertions/deletions incorrectly used the line number of the change itself instead of the line before it (e.g., `@@ -25,0 +18,9 @@` -> `@@ -24,0 +18,9 @@`). The patch also aligns the omission of a count of 1 (e.g., `@@ -22 +22 @@`). No user-visible behavior changes beyond the bug fix. The implementation remains approved in principle by Junio C Hamano (patch 5 feedback incorporated in v2). No additional reviews or maintainer decisions yet.

The filter-state pointer in callbacks is now called `filter` instead of `s`.
Behavior changes:
- Patch 2 fixes a bug where deletions just outside the tracked range could leak into patch output by removing the `pending_rm` buffer and classifying removal lines immediately based on the post-image position of the following line. The symmetric leading-deletion case (removals just before the tracked range) is now correctly included if the following line is in-range.
- Patch 3 fixes an off-by-one in hunk headers (count=0 now correctly shows the line before the change, and count=1 is omitted) and ensures `-L` headers match `git diff` exactly. The new `xdiff_emit_hunk_header()` helper wraps xdiff’s own `xdl_emit_hunk_hdr()` to guarantee consistency.
- `--stat`, `--numstat`, `--shortstat`, `--check`, and `-G` now honor tracked line ranges.
- `--dirstat` and `-S` are explicitly excluded (justified in commit messages).
- The line-range filter’s `flush_range_hunk()` replays buffered content through `diffstat_consume()` and `checkdiff_consume()`, ignoring synthetic hunk headers and processing only `+`/`-` lines within the range.
- Patch 6 adds an optional hunk callback to `line_range_filter` to route `checkdiff_consume_hunk()`, ensuring accurate file line numbers.
- Patch 7 exposes `diff_emit_line_ranges()` to wrap `xdi_diff_outf()`, forwarding only in-range lines to the caller’s callback. `-G` now scopes to ranges, but skips textconv (driver output lacks original line coordinates). `-S` remains whole-file due to counting logic.
