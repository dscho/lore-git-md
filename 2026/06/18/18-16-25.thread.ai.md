Core problem or goal

The goal is to make these common diff options work consistently with the line-range filter, so that only changes or errors within the tracked line ranges are reported.

Behavior changes:
- Patch 2 (new email) fixes a bug where deletions just outside the tracked range could leak into patch output by removing the `pending_rm` buffer and classifying removal lines immediately based on the post-image position of the following line. The symmetric leading-deletion case (removals just before the tracked range) is now correctly included if the following line is in-range. The fix defers calculation of old and new line counts for the hunk header until flush time, reducing state management complexity.
- Patch 3 fixes an off-by-one in hunk headers (count=0 now correctly shows the line before the change, and count=1 is omitted) and ensures `-L` headers match `git diff` exactly. The new `xdiff_emit_hunk_header()` helper wraps xdiff’s own `xdl_emit_hunk_hdr()` to guarantee consistency.
- Patch 4 centralizes line-range filter boilerplate without changing behavior. The helpers enforce invariants (one xdiff hunk per range, hunk headers always emitted) and handle `ctxlen` inflation, flag clearing, diff execution, and buffer cleanup.
- Patch 5 enables `--stat`, `--numstat`, and `--shortstat` to honor tracked line ranges by routing the line-range filter’s output through `diffstat_consume()`. The stat counters now reflect only in-range lines, and the documentation clarifies the exclusion of `--dirstat` (its default mode measures whole-file churn, and accepting only `--dirstat=lines` would be confusing).
- Patch 6 enables `--check` to honor tracked line ranges by wrapping `checkdiff_consume()` with the line-range filter. The implementation adds an optional hunk callback to `line_range_filter` to route `checkdiff_consume_hunk()`, ensuring accurate file line numbers (counting from the start of the file rather than the range hunk). The trailing blank-at-eof check is gated on the tracked ranges, preventing false positives when the blank line lies outside the range.
- Patch 7 enables `-G` to honor tracked line ranges by exposing `diff_emit_line_ranges()` to wrap `xdi_diff_outf()`, forwarding only in-range lines to the caller’s callback. `-G` now scopes to ranges, but skips textconv (driver output lacks original line coordinates). `-S` is explicitly excluded due to architectural constraints (whole-file search is inherent to its design).
- The line-range filter’s `flush_range_hunk()` replays buffered content through `diffstat_consume()` and `checkdiff_consume()`, ignoring synthetic hunk headers and processing only `+`/`-` lines within the range.
