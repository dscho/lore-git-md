The patch corrects logic introduced in commit `d05d666977` (2026-05-08), which aimed to handle data streams larger than 4GB but inadvertently clamped to the *bits* of `unsigned long` rather than its maximum value. This could lead to incorrect buffer sizes being passed to zlib, including edge cases where the size would be zero.

The fix introduces a helper function `zlib_uLong_cap()` that properly clamps `size_t` values to `ULONG_MAX` (the maximum value of `unsigned long`) before casting to `uLong` (zlib's type). The change updates the `zlib_pre_call()` and `zlib_post_call()` functions to use this helper, ensuring zlib receives valid buffer sizes. The patch touches only `git-zlib.c` and includes no tests or documentation changes.
