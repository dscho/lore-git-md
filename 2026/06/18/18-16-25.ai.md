This is a seven-patch series extending the line-log functionality (`` `git log -L` ``) to support range-scoped diff stat formats, whitespace checking, and the `` `-G` `` pickaxe. The series builds on the recent `mm/line-log-cleanup` topic, which integrated `` `-L` `` with the standard log output pipeline and added support for non-patch formats like `` `--raw` ``, `` `--name-only` ``, and `` `--summary` ``.

The key additions here are that `` `--stat` ``, `` `--numstat` ``, `` `--shortstat` ``, and `` `--check` `` now honor the tracked line ranges, reporting only changes or errors within those ranges. The `` `-G` `` pickaxe is also scoped to the tracked range, so commits are selected only if the pattern appears on an added or removed line within the range. The series deliberately excludes `` `--dirstat` ``, as its default mode cannot honor range scoping without a more invasive redesign, and `` `-S` `` is left unchanged since it operates on whole blobs rather than diffs.

Patches 1-3 are preparatory: they rename and clarify the line-range filter internals, fix two bugs in the existing `` `-L` `` patch output (a leaked deletion and an off-by-one hunk header), and align hunk headers with `` `git diff` ``’s format. These changes are motivated by the observation that the current filter model is cryptic and error-prone, so the patches first document and simplify it before building on it. Patches 4-7 then extract a reusable helper for range-scoped diffs and implement the new formats: patch 4 introduces `line_range_filter_diff()`, patch 5 adds stat support, patch 6 adds `` `--check` ``, and patch 7 scopes `` `-G` `` to the tracked range.

The series touches `diff.c`, `diffcore-pickaxe.c`, `revision.c`, and `xdiff-interface.c`, along with updates to the line-range documentation and extensive test coverage in `t/t4211-line-log.sh`. The commit messages are detailed and include worked examples, which suggests the author has put care into explaining the changes. The exclusion of `` `--dirstat` `` and `` `-S` `` is explicitly justified, and the documentation update in patch 7 clarifies the behavioral distinction between `` `-G` `` and `` `-S` ``, which is a nice touch for users. The series looks well-structured and addresses a clear gap in `` `-L` ``’s functionality.
