This is the sixth patch in Harald Nordgren's v16 series implementing `git branch --delete-merged`, introducing a per-branch opt-out mechanism via the `branch.<name>.deleteMerged` config key. The patch adds a safety valve that exempts specific branches from automated deletion while preserving the ability to delete them manually with `git branch -d`.

The implementation checks the config key for each candidate branch during the deletion loop. If `branch.<name>.deleteMerged` is set to `false`, the branch is skipped and a message is printed (unless `--quiet` is given). The config check is performed after the existing safety checks (checked-out branches, missing upstreams, push divergence) but before the branch is added to the deletion list. Memory management is handled by reusing a single `strbuf` across the config loop, matching the efficiency improvements introduced in earlier patches.

Documentation updates cover both the new config key (`Documentation/config/branch.adoc`) and the opt-out behavior (`Documentation/git-branch.adoc`). The test suite verifies two scenarios: that the opt-out is respected during `--delete-merged` operations, and that explicit deletion with `git branch -d` bypasses the config setting. The tests use the same reusable repository setup introduced in earlier patches, maintaining consistency across the series.

This patch completes the safety architecture for the series by providing fine-grained control over which branches are eligible for automated deletion. The opt-out mechanism addresses the use case of topic branches that receive iterative updates after an initial merge, allowing users to keep them around without disabling the feature entirely. The implementation is straightforward and integrates cleanly with the existing flags-based API.
