This is the core implementation patch in Harald Nordgren’s four-part series introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. This is the third patch in the series (3/4) and contains the actual squash logic, documentation, and test coverage.

The patch adds roughly 150 lines to `builtin/history.c`, including a new `cmd_history_squash()` function and a helper `resolve_squash_range()` that parses and validates the revision range. The implementation computes a single three-way merge of the entire range against the oldest commit’s parent, then replays any descendants on top of the result. This design avoids the repeated conflict stops that Phillip Wood criticized in the earlier rebase-based approach. The `--reedit-message` option seeds the editor with every folded-in message, addressing the user-experience gap Phillip noted.

Documentation is added to `git-history.adoc`, explaining the range syntax (`<base>..<tip>`), behavior with merge commits, and the `--reedit-message` flag. The 213-line test script `t/t3454-history-squash.sh` covers edge cases: empty ranges, root commits, interior ranges, fixup commits, authorship preservation, dry-run mode, and ref updates. The tests also verify that ranges with multiple bases are rejected, a key correctness constraint.

This patch directly addresses all substantive feedback from the previous round by moving the feature out of rebase and into the `git history` roadmap, eliminating the efficiency concerns, and providing a clean user interface. The implementation appears solid, with thorough test coverage and clear documentation, and should now be ready for Junio’s final assessment.
