This is the first patch in Harald Nordgren’s v14 `--track=fetch` series, part of the ongoing effort to extend `git checkout` and `git switch` with automatic fetching when creating tracking branches. The patch refactors `branch.c` to expose two helper functions—`find_tracking_remote_for_ref()` and `advise_ambiguous_fetch_refspec()`—and moves the `struct tracking` definition to `branch.h` for reuse by other commands. The v14 update is purely mechanical: it replaces an explicit `#include "string-list.h"` with a forward declaration (`struct string_list;`) in `branch.h`, addressing Junio’s minor header cleanup request from the v13 review.

The refactoring extracts the remote-lookup logic currently used by `setup_tracking()` into shared helpers, with no behavior changes. `find_tracking_remote_for_ref()` centralizes the existing `for_each_remote` walk that resolves which remote owns a given tracking ref, while `advise_ambiguous_fetch_refspec()` standardizes the advice message shown when multiple remotes map to the same tracking ref. The patch also moves the `struct tracking` definition to `branch.h`, making it available for cross-file use (e.g., by the upcoming `--track=fetch` implementation in patch 2/2).

The implementation is clean and well-scoped: it avoids functional changes, maintains backward compatibility, and includes no new dependencies beyond the existing `refspec.h` include. The header cleanup in v14 is a minor improvement that reduces compilation dependencies without altering the patch’s core purpose. The exposed helpers are already used by `setup_tracking()`, so their extraction is a natural refactoring step for the broader feature.

This patch is technically complete and approved, with all substantive feedback from earlier iterations addressed. Its merge depends entirely on the maintainer’s final decision about the feature’s workflow merit—specifically, whether the convenience of automatic fetching during checkout justifies the potential risks (e.g., network operations without user preview). The v14 update does not affect that decision, as it is purely a header hygiene improvement. The patch stands on its own as a useful refactoring, but its primary value is enabling the `--track=fetch` feature in the second patch.
