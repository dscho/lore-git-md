This is a seven-patch feature series extending ``git log -L`` (line-log) to make more diff output and commit selection respect the tracked line ranges. The series builds on earlier work that integrated ``-L`` with standard log output formats like ``--raw`` and ``--name-only``.

The key additions are range-scoped ``--stat``, ``--numstat``, ``--shortstat``, ``--check``, and ``-G`` pickaxe. Each now operates only on the lines inside the tracked range rather than the whole file. ``--dirstat`` is deliberately excluded because its default mode cannot honor the range; ``-S`` is also left whole-file for now, with the documentation updated to clarify the distinction.

Patches 1–3 are preparatory: they rename and group the internal line-range filter for clarity, fix two bugs in the existing patch output (a leaked deletion and an off-by-one hunk header), and align ``-L`` hunk headers with ``git diff``’s format. Patches 4–7 then reuse the filter to implement the new formats. The series is well-motivated, the commit messages are detailed, and the test coverage is thorough. It looks like a clean, incremental improvement that should be uncontroversial.
