This is the final patch in Harald Nordgren’s 7-part series adding `git branch --delete-merged`, and it implements the `--dry-run` option. The patch is small, focused, and completes the feature’s safety story: users can now preview which branches would be deleted before committing to the action.

The implementation is straightforward. The option is rejected unless `--delete-merged` is also given, ensuring it only applies to the new command. When used, it prints “Would delete branch <name>” for each branch that matches the deletion criteria, then exits without touching any refs. The same filtering logic applies—checked-out branches, missing upstreams, push-divergent branches, and per-branch opt-outs via `branch.<name>.deleteMerged` are all respected—so the output is exactly what the real run would delete.

The tests verify both the happy path (a merged branch is listed in dry-run mode and later deleted) and the error case (using `--dry-run` alone is rejected). The commit message and documentation are clear and concise, and the code itself is clean: a single flag (`DELETE_BRANCH_DRY_RUN`) is plumbed through the existing flags-based API introduced in earlier patches.

This patch looks ready. It addresses the last remaining user-facing piece of the feature, integrates naturally with the rest of the series, and maintains the safety guarantees that have been the focus of the entire effort.
