This is the fifth patch in Harald Nordgren's v16 series introducing `git branch --delete-merged`, a new command for safe automated local branch cleanup. The patch implements the core deletion logic, integrating the `--forked` filter, safety checks, and the flags-based API established in earlier patches.

The command deletes local branches that `--forked` would list for the given arguments, but only if their tip is reachable from their configured upstream. Three key safety mechanisms are enforced: branches checked out in any worktree are spared, branches whose upstream no longer exists are preserved, and branches whose push destination equals their upstream (like `main` tracking `origin/main`) are kept to avoid false positives after pulls. Unmerged branches are silently skipped rather than aborting the operation.

The implementation adds a new `delete_merged_branches()` function in `builtin/branch.c` that filters candidates using `ref_filter_forked_add()`, checks each branch's upstream and push configuration, and delegates the actual deletion to the existing `delete_branches()` function with the `DELETE_BRANCH_SKIP_UNMERGED` and `DELETE_BRANCH_NO_HEAD_FALLBACK` flags. The CLI plumbing is straightforward, adding `--delete-merged` as a new option that triggers the deletion logic.

The test suite verifies the safety mechanisms in two comprehensive integration tests: one checks that merged branches are deleted while unmerged, checked-out, and protected branches are spared; the other confirms that branches with missing upstreams or push-equals-upstream configurations are preserved. The tests use a reusable repository setup with clear naming (`upstream`, `fork`, `repo`) and subshells for branch creation.

This patch is the technical centerpiece of the series, tying together the `--forked` filter, flags-based API, and safety architecture. The implementation appears clean and well-tested, with no obvious gaps in the safety logic.
