This is a bugfix patch in Patrick Steinhardt's 8-part refactoring series modernizing Git's reference backend infrastructure. It plugs a memory leak in `repository.c` where the main reference database (`repo->refs_private`) was never freed during repository cleanup, despite worktree and submodule reference databases being properly released.

The leak was masked by the `chdir_notify` subsystem, which kept the pointer alive. The fix adds a missing `ref_store_release()` call and `FREE_AND_NULL` in `repo_clear()`, mirroring the existing cleanup logic for submodule reference stores. The change is confined to a single 5-line addition in `repository.c` and is uncontroversial—it aligns with the series' broader goal of improving memory hygiene in the ref backend.

This patch is part of the incremental improvements in v3 of the series, which shifted focus to preparatory cleanup after earlier versions revealed performance regressions. It directly follows the `chdir_notify` memory leak fixes in patch 4/8 and complements the initialization sequencing work in patch 7/8. Reviewers familiar with repository lifecycle management (e.g., Karthik Nayak, Junio C Hamano) would likely find this straightforward, as it addresses a clear omission in the existing cleanup logic.

The patch is ready for integration and doesn't appear to introduce new edge cases or dependencies. It’s a targeted fix that doesn’t alter behavior, only ensuring proper resource cleanup. Key technical details: the leak affected the main refdb (`repo->refs_private`), not submodule or worktree stores; the fix uses the same `ref_store_release()` pattern already established for submodules; and the `chdir_notify` subsystem’s role in masking the leak explains why it went unnoticed until now.
