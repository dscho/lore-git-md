This is the seventh patch in Patrick Steinhardt’s 8-part refactoring series targeting Git’s reference backend infrastructure. It addresses a long-standing initialization sequencing problem that causes recursive construction of the main reference store when "onbranch" configuration conditionals are present.

The patch fixes a chicken-and-egg scenario where the reference database needs configuration to initialize, but the configuration parser needs a reference database to evaluate "onbranch" conditions. The current mechanism—checking whether the ref storage format is `REF_STORAGE_FORMAT_UNKNOWN`—fails because the format is typically set during repository discovery, leading to unintended recursion. The fix temporarily sets the format to `UNKNOWN` before constructing the ref store, ensuring "onbranch" conditions are skipped during initialization. This prevents the redundant construction (and potential leak) of the reference store while maintaining the expected behavior of ignoring "onbranch" conditions during refdb setup.

The change is confined to `refs.c` and introduces a clear, 18-line addition that documents the rationale and explicitly manages the ref storage format state. The approach is pragmatic, acknowledging the awkwardness of repurposing `UNKNOWN` as an initialization signal but offering a working solution to a fundamental sequencing issue. This patch remains the most technically nuanced in the series, with its design still under discussion (as noted in the thread context), but the implementation itself is straightforward and unlikely to introduce regressions.

Reviewers familiar with Git’s initialization sequence (e.g., Junio C Hamano, Justin Tobler) or ref backend internals (Karthik Nayak) would be well-positioned to assess the trade-offs. The patch is ready for integration pending resolution of the broader design question about initialization state tracking, but it effectively resolves the immediate recursion problem without requiring changes to other subsystems.
