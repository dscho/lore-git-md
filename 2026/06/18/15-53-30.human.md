This is a brief follow-up in the ongoing refactoring series that modernizes Git’s reference backend. The series is now in its third iteration, and this email is part of the discussion around patch 7/8, which addresses a recursive initialization issue when the "onbranch" configuration is used.

Justin Tobler responds to Patrick Steinhardt’s skepticism about adding an `initialized` boolean to `struct ref_store` to track whether the ref store is fully set up. Justin concedes that the idea may not be worth pursuing: while it could provide a cleaner signal for `include_by_branch()`, the ref store isn’t actually fully initialized at the point where the check would be needed, so the benefit is limited. He acknowledges that the current workaround—temporarily setting the ref storage format to `REF_STORAGE_FORMAT_UNKNOWN`—is a pragmatic solution, even if it feels like a hack.

The exchange doesn’t resolve the design question, but it clarifies that Justin no longer sees his proposed alternative as a clear improvement. This leaves the current implementation of patch 7/8 as the likely path forward, though the door remains open for further discussion if someone else sees a better way. The rest of the series (patches 1–6 and 8) is uncontroversial and ready for integration.
