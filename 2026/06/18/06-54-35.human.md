This is a bugfix patch in Patrick Steinhardt’s 8-part refactoring series modernizing Git’s reference backend. It plugs a memory leak in `repo_clear()`: the main reference database (`repo->refs_private`) was never freed, even though worktree and submodule reference databases were. The leak persisted because the `chdir_notify` subsystem kept the pointer alive, masking the issue.

The fix is straightforward—five lines in `repository.c` that call `ref_store_release()` and `FREE_AND_NULL()` on `repo->refs_private`—and uncontroversial. The patch is part of a larger effort to clean up initialization sequencing and eliminate reliance on `chdir_notify_reparent()`, but this specific change is purely a correctness fix with no behavioral impact.

Reviewers familiar with repository teardown (e.g., Karthik Nayak, who reviewed earlier patches in the series) will recognize this as a necessary hygiene improvement. The patch is ready for integration and unlikely to draw further discussion. If you’re tracking the series for its architectural goals, this is a minor but solid step forward.
