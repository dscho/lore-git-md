This is the second patch in Harald Nordgren's v16 series for `git branch --delete-merged`, performing a refactoring to prepare for the new functionality. The patch converts `delete_branches()` and its helper `check_branch_commit()` from using separate boolean parameters (`force`, `quiet`) to a single `unsigned int flags` argument with an enum for bitmask values. This change is purely internal and does not alter behavior—it is a mechanical refactoring to make the API more extensible for the flags that will be introduced in later patches.

The conversion is straightforward: the patch defines an enum (`DELETE_BRANCH_FORCE`, `DELETE_BRANCH_QUIET`) and replaces the boolean parameters with a flags argument. Inside the functions, the flags are split back into named boolean locals so the existing logic remains unchanged. The call site in `cmd_branch()` is updated to construct the flags bitmask from the existing `delete` and `quiet` variables. The diff is clean and focused, touching only the function signatures, enum definition, and a few lines of bitmask construction.

This refactoring is a prerequisite for the series' core functionality: the flags-based API will later be extended with new options like `DRY_RUN` and `SKIP_UNMERGED` to support the `--delete-merged` and `--dry-run` behaviors. The change aligns with the project's preference for extensible APIs and was requested by Phillip Wood to ensure consistency with the `delete_merged_branches()` interface introduced in a later patch. The patch is well-motivated, minimal, and ready for review.
