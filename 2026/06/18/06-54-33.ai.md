This is a bugfix patch in Patrick Steinhardt’s 8-part refactoring series modernizing Git’s reference backend. It plugs a latent memory-management issue in the `chdir_notify` subsystem: reference stores (files, packed, reftable) register themselves to be notified when the working directory changes, but they never unregister. The patch adds the missing `chdir_notify_unregister()` calls in the release functions of each backend and switches from the one-way `chdir_notify_reparent()` API to the two-way `chdir_notify_register()`/`unregister()` pair. The change is confined to the three backend files (`refs/files-backend.c`, `refs/packed-backend.c`, `refs/reftable-backend.c`) and is uncontroversial—it fixes a clear leak and a potential dangling-pointer bug without altering any behavior. Reviewers familiar with the `chdir_notify` machinery or the ref backends will recognize this as a straightforward hygiene improvement that aligns with the series’ goal of making the ref subsystem more robust.
