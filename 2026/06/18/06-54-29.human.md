This is the cover letter for the third iteration of Patrick Steinhardt’s eight-patch refactoring series that removes Git’s dependency on `chdir_notify_reparent()` in the reference backends. The goal is to simplify the ref storage layer by making all backends use absolute paths internally, eliminating the need for chdir notifications that currently keep stale refdb pointers reachable.

The series has grown more complex than originally planned due to subtle initialization issues with the “onbranch” configuration, which causes the refdb to be constructed twice in some cases. The first two patches clean up repository setup code (inlining a function and avoiding duplicate format application), while the third patch tightens the scope of the `GIT_REFERENCE_BACKEND` environment variable to apply only during repository initialization. Patches 4–6 remove chdir notification callbacks, fix memory leaks, and ensure proper cleanup of the main refdb. The seventh patch addresses a circular dependency in refdb initialization, and the final patch optimizes path computation.

Version 3 incorporates Justin Tobler’s suggestion to further restrict when the `GIT_REFERENCE_BACKEND` environment variable is applied, improving control-flow hygiene. The series is built on Patrick’s recent ODB centralization work and is ready for integration, pending resolution of the design question in patch 7/8. The changes are well-motivated and unlikely to be controversial, though they touch core ref backend and repository initialization code, so they warrant attention from anyone working in those areas.
