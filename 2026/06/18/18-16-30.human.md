This is the fifth patch in Karthik Nayak’s seven-patch series extending `` `git log -L` `` to support range-scoped diff stat formats, whitespace checking, and the `` `-G` `` pickaxe. This patch specifically enables `` `--stat` ``, `` `--numstat` ``, and `` `--shortstat` `` to honor the tracked line ranges, so only changes within those ranges are counted.

The implementation reuses the line-range filter infrastructure introduced in earlier patches. When a filepair carries line ranges, the filter wraps `` diffstat_consume() ``, forwarding only in-range lines for counting. The patch also updates the output format allowlist in `` `setup_revisions()` `` to accept the new stat formats with `` `-L` ``, while deliberately excluding `` `--dirstat` `` because its default mode cannot honor range scoping without a more invasive redesign. The documentation is updated to clarify that stat formats now show range-scoped counts, and the generic `` `-L` `` rejection message is tweaked to remove the misleading “yet” (since some formats, like `` `--dirstat` ``, are fundamentally incompatible with line ranges).

Test coverage is extensive: new tests verify that `` `--numstat` ``, `` `--stat` ``, and `` `--shortstat` `` correctly scope counts to the tracked range, handle root commits, follow renames, and exclude untracked changes when multiple ranges are specified. The tests also confirm that `` `--dirstat` `` (including `` `--dirstat=lines` ``) is rejected as expected. The patch is well-motivated, clearly explains the design choices, and integrates cleanly with the preparatory work in patches 1-4. It looks like a solid, uncontroversial addition to the series.
