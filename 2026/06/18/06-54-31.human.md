This is a refactoring patch in Patrick Steinhardt’s 8-part series modernizing Git’s reference backend infrastructure. It targets `setup.c` and eliminates redundant application of repository format settings during repository initialization.

The patch addresses a minor inefficiency: Git currently applies the repository format (hash algorithm and ref storage format) twice—once via `repository_format_configure()` and again via `apply_repository_format()`. The redundancy exists because `repository_format_configure()` is called *after* `apply_repository_format()`, so any changes it makes to the format struct never propagate to the repository. Patrick’s fix reorders the calls so the format is configured first, then applied once, removing the need for the second pass.

The change is small (7 lines removed, 2 added) and purely mechanical. It doesn’t alter behavior but improves code clarity by making the initialization flow more straightforward. The patch is uncontroversial and aligns with the series’ goal of cleaning up ref backend internals. Reviewers like Justin Tobler have already approved similar initialization logic in other patches, so this one is likely to be accepted without pushback.

This is the second patch in the series, following a preparatory helper inlining. It sets the stage for later patches that fix memory leaks and initialization sequencing issues. While not flashy, it’s a solid incremental improvement—exactly the kind of cleanup that keeps Git’s internals maintainable. Busy readers can safely skim this one unless they’re specifically interested in repository setup mechanics.
