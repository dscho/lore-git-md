This is the maintainer’s review of the core patch in Harald Nordgren’s `git history squash` series. Junio C Hamano gives the implementation a clear thumbs-up: the single three-way merge that folds an entire commit range in one step is “very nice” and avoids the inefficiency of a rebase-style stepwise replay. He notes a minor limitation—the feature uses only the oldest commit’s message by default—but acknowledges that the existing `--reedit-message` option already addresses this by letting users edit a template containing all folded-in messages, matching `git rebase --squash` behavior. Junio also suggests a possible future enhancement (allowing users to pick which commit’s message to keep) but calls the current design a “good place to start.” The only mechanical change he made was renaming the test script from `t3454` to `t3455` to avoid a collision with another in-flight topic. The patch is now queued and ready for integration.
