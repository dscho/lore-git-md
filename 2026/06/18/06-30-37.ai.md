This is a brief follow-up in the thread about the macOS keychain credential helper build regression. Patrick Steinhardt confirms that the issue does not affect the Meson build system—only the Makefile-based build fails to link when Rust support is enabled. The root cause remains the same: the Makefile rule for `contrib/credential/osxkeychain` omits the Rust library (`RUST_LIB`), which is required to resolve varint symbols pulled in indirectly via `libgit.a`. The fix (already merged) replaces `$(LIB_FILE) $(EXTLIBS)` with `$(LIBS)` to ensure proper linking, but the underlying coarse-grained dependency issue persists.

The new detail here is the build system discrepancy: Meson handles the dependency correctly, while the Makefile does not. This explains why the regression went unnoticed in CI, which relies on Meson. Patrick’s reply adds no technical objections or alternatives; it simply clarifies the scope of the problem and implicitly endorses the merged fix. No further action is proposed, and the thread appears resolved. The key takeaway for future work is the need to audit other credential helpers or non-Rust components for similar build-time regressions as Rust code continues to integrate into `libgit.a`.
