This thread is about a seven-patch series (now at v3) that extends `git log -L`—which tracks changes to specific line ranges—to support range-scoped diff stat formats, whitespace checking, and the `-G` pickaxe. The series was originally implemented by Karthik Nayak and is now maintained by Michael Montalbo.

The goal is to make common diff options like `--stat`, `--check`, and `-G` work consistently with line-range filtering, so they only report changes or errors within the tracked ranges. The series is complete and under review, with no evidence of integration into Junio’s branches yet. The latest patches (5 and 6 in v3) enable `--stat` and `--check` to honor tracked ranges, while the final patch (7) adds support for `-G`, though it excludes `-S` due to architectural constraints and falls back to whole-file search when textconv is enabled.

Junio C Hamano reviewed the diff stat portion in an earlier version, approving the implementation and suggesting minor documentation tweaks, which were incorporated. The series builds on recent work (`mm/line-log-cleanup`) that integrated `-L` with the standard log output pipeline. Tests verify that stat counts, whitespace errors, and `-G` matches align with the tracked ranges, including edge cases like renames, multiple ranges, and textconv fallbacks. The only exclusions noted are `--dirstat` and `-S`, which would require more invasive redesigns.
