The first refactors the line-range filter, while the second fixes a bug where deletions just outside the tracked range could leak into patch output. Junio C Hamano approved the core approach in v1, and his feedback on documentation clarity has been incorporated.

The latest update, patch 3, fixes an off-by-one bug in hunk headers to match `git diff` exactly. The bug caused headers like `@@ -25,0 +18,9 @@` (incorrect) instead of `@@ -24,0 +18,9 @@` (correct) for pure insertions. The fix replaces hand-rolled header logic with a new `xdiff_emit_hunk_header()` helper, ensuring consistency with Git’s diff output. Tests have been updated to reflect the corrected behavior, including edge cases that had carried the bug since 2025. The patch is a prerequisite for later work but doesn’t change the filter’s core logic.

The series touches `diff.c`, `xdiff-interface.c`, and tests in `t/t4211-line-log.sh`, with no on-disk format changes. Open questions are minimal—`--dirstat` and `-S` are excluded due to design complexity, but no other objections or loose ends remain. The next patches will build on this foundation to enable range-scoped stat, whitespace checks, and `-G` pickaxe support.
