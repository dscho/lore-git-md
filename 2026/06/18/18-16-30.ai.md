This is the fifth patch in Karthik Nayak’s seven-patch series extending `git log -L` to support range-scoped diff stat formats, whitespace checking, and the `-G` pickaxe. It implements support for `--stat`, `--numstat`, and `--shortstat` by reusing the line-range filter infrastructure introduced in earlier patches.

The patch wraps `diffstat_consume()` with the line-range filter so that only lines within the tracked range are counted. The filter’s `flush_range_hunk()` replays buffered content through `diffstat_consume()`, which ignores synthetic hunk headers and counts only `+` and `-` lines. The `setup_revisions()` allowlist is expanded to accept the three stat formats with `-L`, while `--dirstat` remains explicitly excluded because its default mode cannot honor range scoping without a more invasive redesign. The commit message justifies this exclusion and notes that `--numstat` already provides the exact per-file counts that `--dirstat=lines` would, making the split behavior confusing for users.

The documentation in `line-range-options.adoc` is updated to reflect the new support and clarify that stat formats now show range-scoped counts. The test suite in `t/t4211-line-log.sh` is significantly expanded, covering edge cases such as root commits, renames, multiple ranges, and the exclusion of untracked changes. The tests also verify that the counts match the expected range-scoped values rather than whole-file statistics.

The patch is focused and well-justified, with clear explanations for the exclusion of `--dirstat` and thorough test coverage. It builds cleanly on the preparatory work in patches 1-4 and sets the stage for the remaining features in patches 6 and 7.
