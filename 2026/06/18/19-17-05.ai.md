This is the core feature patch in Harald Nordgren’s v3 series introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. It is the third patch in a four-patch series; the first two are preparatory refactorings.

The patch implements the actual squash logic in `builtin/history.c`: parsing a revision range (`<base>..<tip>`), resolving it to the base commit just outside the range, the oldest commit inside, and the tip, then performing a single three-way merge of the entire range against the base. The resulting commit keeps the oldest commit’s message and authorship, takes the tip’s tree, and replays any descendants on top. A merge commit inside the range is folded like any other, but ranges with multiple bases (e.g., a side branch that forked before the range) are rejected. The `--reedit-message` option seeds the editor with all folded-in messages, addressing the user-experience gap noted in earlier reviews.

The implementation touches only `builtin/history.c` (154 insertions), adds a 20-line man page section in `Documentation/git-history.adoc`, and introduces a 213-line test script `t/t3454-history-squash.sh` that covers range parsing, merge handling, descendant replay, authorship preservation, and edge cases like fixup! commits and dry-run mode. The patch is well-tested and directly addresses the efficiency and workflow concerns raised in the thread by moving the feature out of `git rebase` and into the `git history` roadmap. No unresolved objections remain; this is the final technical piece before Junio’s acceptance decision.
