This is a follow-up in the ongoing thread about the curl authentication regression affecting Git's HTTP test suite. Todd Zullinger reports that the recently released curl 8.21.0-rc3 (now available in Fedora) resolves the test failures in Git's t5563.18 without requiring any Git-side changes. The fix confirms that curl maintainers treated the behavior change as a regression rather than intended behavior, eliminating the need for Git to adapt either the test expectations or the `http.emptyAuth=auto` implementation.

The resolution is straightforward: the upstream curl issue (curl/curl#21943) has been addressed in time for distributions to pick up the fix before Git 2.55.0's final release. Todd's confirmation closes the loop on the thread's open question about whether Git would need to implement workarounds. The test suite's role in catching the regression is now fully validated, as the original test expectations (three HTTP 401 responses for Negotiate authentication) are once again correct.

No further action is expected on the Git mailing list unless distributions report new issues with the curl fix. The thread can now be considered resolved from Git's perspective, pending only the routine inclusion of curl 8.21.0 in production distributions. Key technical details to track in future discussion would include the specific curl commit that fixed the regression (not mentioned in this email but likely part of the rc3 changes) and any potential edge cases in other authentication schemes that might have been affected by the original regression.
