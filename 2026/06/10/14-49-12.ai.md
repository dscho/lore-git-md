This is a refactoring patch (1/3) from Toon Claes's series adding `--linearize` support to `git replay`. The patch simplifies the `enum replay_mode` into a boolean `reverse` flag since the enum only had two states (`REPLAY_MODE_PICK` and `REPLAY_MODE_REVERT`).

The change:
- Removes the enum definition and replaces all enum parameters/checks with boolean logic
- Maintains identical behavior while reducing code paths (removes BUG() checks for invalid enum values)
- Cleans up conditional logic in `pick_regular_commit()` by using if/else rather than switch-style enum checks
- Preserves all existing functionality for both pick and revert modes

The refactoring appears straightforward and mechanical, with no behavior changes. This prepares the codebase for the subsequent patches that will add the new `--linearize` option. The patch follows Git's preference for small, focused changes - this one purely deals with the enum-to-bool conversion without mixing in other modifications.

Technical details for future reference:
- Touches core replay logic in `replay.c`
- Affects commit creation and picking functions
- Part of broader effort to expand `git replay` capabilities
- Builds on earlier work by Johannes Schindelen (Dscho) who signed off on the approach

The patch has already been reviewed in v1 and the author has incorporated feedback, making this a low-risk change that improves code maintainability.
