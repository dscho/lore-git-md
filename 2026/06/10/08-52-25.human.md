This is part 5/10 of Patrick Steinhardt's v4 series introducing a `git history drop` subcommand, which builds on the experimental `git history` command. The patch adds a dry-run mode to the reset machinery, allowing callers to check if a reset operation would succeed without actually modifying the working tree or index.

The key changes in this specific patch:
- Introduces a new `RESET_WORKING_TREE_DRY_RUN` flag
- Modifies `reset_working_tree()` to use a scratch index when in dry-run mode
- Skips index locking and ref updates during dry runs
- Maintains all existing functionality while adding the new capability

The dry-run support will be used by the upcoming `git history drop` command to detect potential conflicts before performing the actual operation. The implementation is careful to avoid modifying any state when in dry-run mode, using a separate index instance to test the operation.

This continues the series' pattern of careful API design and thorough consideration of edge cases. The changes are well-contained to the reset machinery while providing functionality that will be useful for the broader codebase. The patch follows the series' ongoing modernization of the reset API, building on previous work to remove `the_repository` usage.
