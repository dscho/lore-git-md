This is a refactoring patch in the `the_repository` removal effort, moving the global `protect_hfs` and `protect_ntfs` configuration variables into repository-specific storage. Tian Yuchen's patch (v2) follows up on Christian Couder's substantive review of the first version, implementing helper functions for default value handling and type-safe getters.

The changes relocate these Windows filesystem protection variables from global scope to the `repo_config_values` struct while maintaining identical validation behavior. New getter functions `repo_protect_hfs()` and `repo_protect_ntfs()` handle the transition cleanly, falling back to default values when repository configuration isn't available. The patch touches several files to update access patterns, including `compat/mingw.c`, `read-cache.c`, and the test helper code.

Notable technical aspects include preserving the special case handling in `t/helper/test-path-utils.c` by introducing local variables, and maintaining all existing test coverage while restructuring the code. The implementation follows Glen Choo's preferred struct field approach rather than the rejected global lazy-loader alternative.

The patch mentors (Christian Couder, Ayush Chandekar, Olamide Caleb Bello) suggest this is part of a structured mentoring effort, and the changes appear well-considered with clear documentation of the design decisions. This continues the pattern established by prior work migrating `trust_executable_bit` to the same struct.
