This is part 3/10 of Patrick Steinhardt's v4 series introducing the `git history drop` subcommand, focused on refactoring the reset machinery. The patch renames `reset_head()` to `reset_working_tree()` to better reflect its actual functionality, as the function's purpose is to reset the working tree to a specific commit rather than just updating HEAD. The change was suggested by Phillip Wood in prior review discussion.

The rename affects several callers across builtin/rebase.c, reset implementation files, and sequencer.c, updating both the function name and the associated options struct name (`reset_head_opts` -> `reset_working_tree_options`). This is a mechanical change that doesn't yet modify the function's behavior - flag adjustments will come in subsequent patches.

The change is part of a broader effort to modernize and clarify the reset API in preparation for making HEAD updates optional, which will be particularly useful for the new drop` command's two-phase reference update approach. The patch maintains consistency with the series' goal of removing global state dependencies while improving API clarity.
