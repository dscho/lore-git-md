This is the third and final patch in a refactoring series that migrates the `trust_executable_bit` configuration from global scope to repository-specific storage as part of the ongoing `the_repository` removal effort. The patch introduces a new getter function `repo_trust_executable_bit()` while maintaining the existing behavior of falling back to `the_repository` for now.

The changes are mechanical but important for the long-term goal of eliminating global state:
1. Moves `trust_executable_bit` into `struct repo_config_values`
2. Adds the new getter function with proper documentation
3. Updates all call sites to use the repository-scoped accessor
4. Maintains the same default value (1) in the initialization function

The patch touches core index handling code in read-cache.c and configuration plumbing in environment.c/h, showing how filesystem capability flags are being migrated to the new storage pattern. The author has incorporated feedback from multiple mentors (Christian Couder, Ayush Chandekar, Olamide Caleb Bello) and maintained the series' focus on incremental, behavior-preserving changes.

This completes the immediate goal for `trust_executable_bit` migration while leaving the more complex `has_symlinks` case for future work, as previously agreed in the thread. The changes are well-contained and appear ready for inclusion, representing another step forward in the larger architectural effort to eliminate global state from Git's codebase.
