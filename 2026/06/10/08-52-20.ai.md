This is the v4 patch series introducing a `git history drop` subcommand, part of Patrick Steinhardt's ongoing work on the experimental history command. The series builds on previous work adding the replay subcommand (commit 1666c12652).

The key changes in v4:
- Renamed `reset_head()` to `reset_working_tree()` to better reflect its scope
- Replaced the `SKIP_REF_UPDATES` flag with a new `UPDATE_HEAD` flag per Phillip Wood's suggestion
- Incorporated all prior feedback from v3

The 10-patch series:
1. Refactors index handling to split out unmerged entry cleanup
2. Removes `USE_THE_REPOSITORY_VARIABLE` from reset.c
3-4. Modernizes and renames the reset machinery
5-7. Adds dry-run mode, HEAD update control, and caller-specified HEAD object
8. Removes assumption of clean index in reset operations
9-10. Implements the actual drop command with two-phase ref updates

The implementation provides thorough test coverage (537 lines across 4 test scripts) and documentation updates. The drop command prevents dropping root/merge commits and includes dry-run conflict detection.

This appears to be a well-structured addition to the history command, with careful attention to API design and edge cases. The reset machinery changes benefit the broader codebase beyond just the history command. The series touches multiple subsystems (builtin/history.c, refs.c, reset.c, read-cache.c) but maintains clear separation of concerns.

The discussion around reset API design appears to be converging, with agreement to resolve flag semantics now while deferring the final function rename. This seems likely to proceed smoothly given the careful iteration and responsiveness to review feedback.
