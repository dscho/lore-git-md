This is a follow-up to a refactoring patch that consolidates reachability functions in Git's commit-reach.c. Kristofer Karlsson responds to Junio C Hamano's review of his patch that removes the redundant `get_reachable_subset()` function in favor of `tips_reachable_from_bases()`.

Kristofer acknowledges Junio's point about the hand-wavy performance justification in the original patch and provides a more detailed analysis of the traversal strategies. He explains that while the two functions were optimized for different scenarios (DFS for deep ancestry checks, priority queue for shallow tag lookups), the difference becomes negligible when commit-graph is available. He also notes that the priority queue behavior can be preserved within the consolidated function by adding a mode parameter.

The response shows the author engaging substantively with the technical feedback while maintaining the original goal of code reduction. The analysis suggests the change is well-considered rather than purely mechanical, though the practical impact may be minor given commit-graph prevalence. Kristofer indicates a v2 patch is forthcoming that will incorporate both the priority queue support and the deeper analysis.
