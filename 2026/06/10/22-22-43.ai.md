This is a documentation patch series (6 parts) updating the SubmittingPatches guidelines, specifically focusing on trailer usage. Kristoffer Haugsbakk has collected several trailer-related discussion points from the mailing list into this coherent update.

The series aims to clarify and expand the documentation around Git's patch submission conventions. Key changes include encouraging trailers for substantial help (not just authorship), discussing non-identity trailers, discouraging Linux-specific trailers, documenting the less-common `Based-on-patch-by` convention, standardizing trailer markup, and noting that trailer order matters in commit messages.

The motivation comes from recurring questions and inconsistencies observed on the mailing list. The patches appear well-structured, with the cover letter providing clear rationale for each change. As documentation updates, these changes don't affect code but help standardize contributor expectations around commit message conventions.

This looks like a useful housekeeping series that codifies existing practices while cleaning up some inconsistencies in the contributor guidelines. The changes are focused and non-controversial, making them likely candidates for smooth merging.
