This is the final patch in Patrick Steinhardt's v4 series introducing the `git history drop` subcommand, which allows removing a commit from history while replaying its descendants onto its parent. The patch implements the actual drop command functionality after the preparatory refactoring in previous patches.

The implementation:
- Adds the `drop` subcommand with options matching other history commands (--dry-run, --update-refs, --empty)
- Prevents dropping root commits (which could leave refs empty) and merge commits (not yet supported)
- Handles working tree and index updates when HEAD moves due to the drop
- Includes extensive test coverage (537 lines across various scenarios)
- Documents the new command with examples

Key technical aspects:
- Uses the refactored reset API from earlier in the series
- Splits reference updates into compute/apply phases
- Handles dirty index cases properly
- Provides dry-run capability
- Integrates with the existing history command framework

- Basic drop operations

- Working tree/index handling
