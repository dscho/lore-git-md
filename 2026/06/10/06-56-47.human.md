This is the second patch in Patrick Steinhardt's 7-part series to eliminate global state in setup.c as part of the `the_repository` removal effort. The patch focuses on cleaning up worktree configuration logic in `builtin/init-db.c`.

The change simplifies how Git determines the worktree path during repository creation. Previously, the code would always compute a worktree path (stored in `git_work_tree_cfg`) even when not needed, particularly when an explicit `--work-tree` was provided. The patch refactors this to only compute the path when actually required, making the control flow clearer and avoiding unnecessary work.

Key changes include:
- Renaming `git_work_tree_cfg` to the more local-scoped `work_tree_cfg`
- Moving the worktree path computation inside the else branch where it's actually used
- Cleaning up the variable immediately after use rather than at function end

The patch is a straightforward refactoring that maintains existing behavior while making the code more efficient and readable. It builds on the first patch's work to stop modifying the global `git_work_tree_cfg` variable. As with the rest of the series, this appears to be a well-considered mechanical change that advances the broader architectural goal of removing global state.
