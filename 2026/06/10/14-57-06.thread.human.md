Patrick Steinhardt's ref backend modernization series, now at version 1, aims to simplify path handling by transitioning to absolute paths throughout the reference backend code. The 9-part series removes the complex chdir_notify_reparent() mechanism and addresses several related issues around repository setup, memory management, and initialization sequencing. Junio C Hamano has already reviewed patch 3, agreeing with the technical approach while suggesting a minor documentation clarification.

Jeff King (Peff) has now weighed in with substantive technical feedback, raising an important historical consideration. He notes that the move to absolute paths might affect a performance optimization from 2008 that used relative paths to speed up operations during directory changes. While acknowledging the original speed improvement wasn't dramatic and might be negligible today, Peff ensures this tradeoff is explicitly considered. His review references two key commits that introduced the chdir-notify mechanism, demonstrating deep familiarity with Git's internals.

The series remains in early review, with Junio's initial engagement validating the architectural direction and Peff adding valuable context about potential performance implications. The discussion now includes consideration of whether the absolute path transition's benefits outweigh any possible speed impact, particularly for repositories deep in the filesystem hierarchy. Patrick may need to address this in a future version or provide benchmarking data showing the current impact.
