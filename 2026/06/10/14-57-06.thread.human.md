Patrick Steinhardt's ref backend refactoring series has sparked a substantive technical discussion about path handling in Git. The initial series aims to modernize reference backend infrastructure by moving to absolute paths, eliminating complex relative path handling through chdir_notify_reparent() callbacks. 

Jeff King (Peff) raised important historical context about a 2008 optimization that used relative paths for performance, prompting Patrick to acknowledge the tradeoffs while noting the lack of reproducible benchmarks makes it hard to quantify the current impact. In response, Patrick has proposed an ambitious architectural direction: introducing a higher-level filesystem abstraction (`struct fsroot`) inspired by Go's interfaces. This would use `openat(3p)`-style operations to maintain both performance (avoiding path recomputation) and security (through mechanisms like `O_BENEATH`), while being more portable than direct `openat` emulation on Windows.

The discussion has expanded from the immediate ref backend changes to consider how Git might handle paths across multiple subsystems more securely and efficiently. Patrick specifically mentions applying this to repository working tree management to prevent security issues. While the Windows compatibility challenge remains, the proposed abstraction aims to make cross-platform implementation more tractable. Junio C Hamano had earlier provided review feedback on documentation clarity, which Patrick has incorporated while confirming the technical approach. The thread now contains both the concrete ref backend changes and this forward-looking filesystem abstraction proposal as parallel considerations.
