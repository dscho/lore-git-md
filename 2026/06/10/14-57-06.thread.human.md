This thread is the tail end of Patrick Steinhardt’s eight-part refactoring series modernizing Git’s reference backend. The series has already addressed initialization sequencing, memory leaks, and path handling, with all but one patch now settled. The remaining open question centers on patch 7/8, where Patrick’s design choice to temporarily override `ref_storage_format` as a signal to prevent recursive initialization during "onbranch" config evaluation drew substantive critique from Justin Tobler.

Patrick’s latest reply clarifies why this awkward workaround is necessary: Git’s initialization sequence has a circular dependency where constructing the reference database requires parsing configuration, but parsing "onbranch" conditions may itself require the reference database. Earlier attempts to break this cycle—like eagerly constructing the refdb—broke `git config set` in misconfigured repositories, where users expect to fix issues without manual file edits. The current approach, while clunky, ensures "onbranch" conditionals are honored except during ref store construction. Patrick frames it as a pragmatic compromise, though he’s open to cleaner alternatives if they emerge.

The series is otherwise ready for integration, with substantive reviews from Karthik Nayak, Junio Hamano, Jeff King, and Justin Tobler. The only unresolved design tension is this initialization state signaling, which may require further discussion or a targeted v3. If no better solution surfaces, the current approach will likely proceed as-is, given its role in enabling future architectural improvements like openat(3p) path handling.
