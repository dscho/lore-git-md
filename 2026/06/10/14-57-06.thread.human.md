This thread is the third iteration of Patrick Steinhardt’s eight-patch series refactoring Git’s reference backend to fix initialization issues, memory leaks, and path-handling quirks. The series had largely settled after earlier feedback, with all patches marked ready for integration—until Jeff King (Peff) reopened the design discussion on the most critical patch, 7/8.

Patch 7/8 addresses a recursive initialization problem in `get_main_ref_store()`: when Git parses config during ref store setup (e.g., for "onbranch" conditions), it can trigger another attempt to initialize the same ref store, leading to a loop. Patrick’s solution temporarily unsets `ref_storage_format` to break the cycle, a pragmatic fix that Justin Tobler and others accepted after alternative designs were explored. Peff, however, argues the recursion reveals a deeper architectural flaw. He proposes splitting config parsing into two phases—one for repository-format settings (ignoring includes) and another for user config (respecting includes)—to avoid the recursion entirely. His critique includes a reproduction case showing the issue only arises when the ref store is *partially* initialized, not when no repository exists.

The thread’s key participants—Patrick, Justin, Karthik Nayak, and Junio—had previously converged on the current approach, but Peff’s feedback may prompt a rethink. The series’ other patches (memory leak fixes, `chdir_notify` cleanup, and path optimizations) remain uncontroversial. If Patrick revisits the design, it would likely be as follow-up work, as the current patch is functional and the series is otherwise ready to merge. For now, the open question is whether the recursion workaround is sufficient or if a more invasive config-parsing overhaul is needed.
