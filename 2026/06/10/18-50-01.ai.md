Performance optimization for `git describe` that limits ref iteration to tags by default. This v3 patch from Tamir Duberstein implements the final refinements requested by Junio C Hamano, completing the optimization that was technically approved in v2.

The core change remains the same - modifying `builtin/describe.c` to pass a `refs/tags/` prefix filter to the ref iterator when `--all` isn't specified, avoiding wasted iteration over non-tag refs. The v3 changes focus on presentation and test improvements:
- Packed refs are now used in the performance test to better simulate real-world repositories
- The commit message is more concise while still reporting key benchmark results
- The synthetic ref generation uses `test_seq -f` for cleaner test setup

Performance impact remains significant - the test case shows a drop from 171.7ms to 9.9ms (17x faster) when describing an exactly-tagged commit in a repository with 120,532 refs (only 330 tags). The new perf test demonstrates this with 10,000 packed refs, showing timing improvements from 0.03s to 0.02s in the synthetic case.
