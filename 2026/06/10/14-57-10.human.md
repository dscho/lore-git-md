This is patch 4/9 in Patrick Steinhardt's series modernizing Git's reference backend infrastructure. The patch focuses on fixing memory management issues around the "chdir_notify" subsystem used by reference stores.

The key problem addressed is that reference stores register with chdir_notify to handle path reparenting when the working directory changes, but they never unregister. This leads to two issues: keeping the main reference database alive indefinitely (though not caught by leak checkers), and potentially holding onto freed memory for submodule/worktree reference databases after they're released.

The solution introduces proper unregistration when reference stores are released, requiring a switch from `chdir_notify_reparent()` to `chdir_notify_register()`/`unregister()` pairs. The changes touch all three ref backends (files, packed, and reftable) with consistent patterns. While this is an interim step before completely removing the chdir_notify infrastructure in later patches, it properly fixes the immediate memory management issues.

The patch demonstrates Patrick's characteristic thoroughness - it's a focused change with clear explanations of both the current problems and the solution approach. The changes are mechanical but important for correctness, and the commit message does a good job explaining why this intermediate step is necessary before the final removal of the chdir_notify usage.
