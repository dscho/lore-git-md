This is the sixth and final patch in Kristoffer Haugsbakk's documentation series updating the SubmittingPatches guidelines, focusing on trailer conventions in commit messages. The patch adds a new section clarifying that trailer order matters in commit messages, with specific emphasis on placing the `Signed-off-by` trailer last.

The patch explains two key points about trailer ordering: First, that the `Signed-off-by` trailer should come after other trailers since it represents signing off on both the patch content and all preceding message elements. Second, that this ordering helps track who added which trailers when multiple contributors are involved, as demonstrated by the example showing how to distinguish between reviewer and maintainer-added acknowledgments.

This completes the series' coverage of trailer usage, building on previous patches that established basic trailer principles, discussed non-identity trailers, discouraged Linux-specific conventions, documented the `Based-on-patch-by` trailer, and standardized trailer markup. The change is straightforward and aligns with existing Git project norms, though it formally documents a practice that was previously more implicit.

As with the rest of the series, this is a non-controversial documentation improvement that codifies established mailing list practices. The patch maintains the same clear, instructional tone seen throughout the series and follows the newly standardized trailer formatting (using backticks for trailer names) introduced in patch 5. This brings the SubmittingPatches documentation into better alignment with actual project conventions around commit message trailers.
