This is the fifth patch in Patrick Steinhardt's 7-part series refactoring global state in setup.c as part of the `the_repository` removal effort. The patch focuses on splitting the dual-purpose `is_bare_repository_cfg` global variable into two distinct concerns:

1. `startup_info.force_bare_repository` now tracks whether the user passed the `--bare` flag
2. `struct repository::bare_cfg` tracks the actual bare state of a repository

The change makes the logic clearer by separating the user's intent (via command line) from the repository's actual state. This is a preparatory step for making `is_bare_repository()` not depend on global state. The patch modifies 9 files with mechanical changes that preserve behavior while improving the architecture.

This continues Patrick's methodical approach to removing global state - first introducing the new structure for tracking bareness, then in future patches removing the old global. The changes are focused and well-contained, touching only the necessary call sites to maintain correctness. As with previous patches in the series, this appears to be a straightforward refactoring that moves Git's architecture in the right direction.
