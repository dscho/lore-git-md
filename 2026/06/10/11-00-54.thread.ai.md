Bug report: `git rebase --update-refs` incorrectly generates unqualified "update-ref HEAD" line in todo list when rebasing checked-out branch, causing sequencer to reject as invalid. Expected behavior is to either expand HEAD to target ref (e.g. refs/heads/feat) or omit it entirely since branch ref is already being updated. Issue occurs in minimal reproduction with empty commits on feature branch, not worktree-specific. Affects Git 2.54.0+, likely earlier versions with --update-refs feature. Workarounds: disable updateRefs or manually edit todo file. Clear reproduction steps and technical details provided.
