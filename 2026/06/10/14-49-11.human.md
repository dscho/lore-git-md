This is a feature patch series (v2) from Toon Claes that adds a `--linearize` option to `git replay`, allowing it to flatten merge commits into linear history similar to `git rebase --no-rebase-merges`. The series builds on collaboration with Johannes Schindelin (Dscho) and addresses feedback from Junio Hamano on the initial version.

The series consists of three patches:
1. A refactoring that simplifies control flow by converting an enum to a boolean
2. A helper function extraction for commit mapping
3. The core implementation of `--linearize` functionality

Key changes in v2 include:
- Restructured merge commit detection logic with added comments
- Expanded test coverage including root commit handling
- Documentation improvements
- Retained Dscho's sign-off after confirmation

The implementation handles merge commits by walking their first parent only when linearizing, explicitly disallowing combination with `--revert`. Test cases demonstrate the linearization behavior and verify it works with merge commits down to root commits.

The series remains positioned as an alternative to Dscho's separate merge-replay approach, with the author noting potential documentation conflicts with Kristoffer Haugsbakk's work and Patrick Steinhardt's `git history drop` series, though these are considered minor. The changes touch `replay.c`'s commit mapping logic and add the new flag through `replay.h`.

The patch quality appears solid with thorough test coverage and clear commit messages. The collaborative development with Dscho and responsiveness to Junio's review suggests this is on track for inclusion.
