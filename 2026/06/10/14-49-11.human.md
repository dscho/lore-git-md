This is a feature patch series introducing a `--linearize` option to `git replay` that flattens merge commits, matching the default behavior of `git rebase --no-rebase-merges`. The v2 update addresses feedback from Junio C Hamano on the initial version, improving logic clarity, test coverage, and commit message wording.

The series consists of three patches: two preparatory refactorings and the main implementation. The first patch replaces an `enum replay_mode` with a boolean `reverse` flag, simplifying the code. The second extracts a helper function (`put_mapped_commit`) and renames `mapped_commit` to `get_mapped_commit` for symmetry. The third patch adds the `--linearize` option, updates the documentation, and expands test coverage in `t3650-replay-basics.sh`.

Key improvements in v2 include a clearer distinction between merge commits and root commits in the logic, rewritten tests that reuse the existing history setup, and additional test cases (including replaying down to the root commit). The author also re-added Johannes Schindelin’s Signed-off-by trailer after confirming consent, addressing a procedural oversight from v1.

The series positions itself as a simpler alternative to Schindelin’s earlier merge-replay work (pull.2106), suggesting the two approaches could coexist. The `--linearize` option is intentionally omitted from `git history`, as the author sees no clear use case there. Potential conflicts with other in-flight series (Kristoffer’s documentation changes and Patrick Steinhardt’s `git history drop`) are noted but expected to be trivial.

The implementation looks well-structured and addresses the feedback from v1 directly. The test coverage is thorough, and the commit messages are clear. This appears to be a solid contribution that should interest anyone following the `git replay` command’s evolution.
