This is patch 7/9 in Patrick Steinhardt's series to modernize Git's reference backend infrastructure. The patch fixes a subtle recursion issue in the reference store setup when "onbranch" configuration is present.

The core problem involves a chicken-and-egg situation where:
1. The reference database needs configuration to initialize itself
2. The configuration needs the reference database to evaluate "onbranch" conditions

Currently, this can lead to recursively creating duplicate reference stores, with one instance being leaked (though the leak was previously masked by the chdir_notify subsystem being present). The patch solves this by temporarily unsetting the reference storage format during initialization, which prevents the recursion by making the "onbranch" check skip evaluation.

This is a technical but important fix that maintains the series' focus on cleaning up the ref backend code. The change is well-explained in the commit message and appears to be targeted at a real issue uncovered during the refactoring work. As with the rest of the series, this patch demonstrates Patrick's thorough approach to refactoring - not just making the immediate change but also fixing related issues that surface during the process.
