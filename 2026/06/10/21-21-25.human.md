This is patch 7/11 in Kristoffer Haugsbakk's documentation series for `git-interpret-trailers`, which has already been merged. The patch adds a concrete example demonstrating how invalid trailer keys (containing non-ASCII-alphanumeric characters like periods) cause the entire trailer block to be rejected, even when valid trailers are present.

The example shows three attempted trailers - one valid ("Reviewed-by") and two invalid ("Skapad-på" with an accented character and "Hash-in-v6.11" with a period). The patch explains why none are recognized: the invalid keys violate the strict format rules, and since no trailers are configured, the entire block fails the criteria for being processed.

This is purely a documentation improvement - no functionality changes. The patch serves to reinforce the key format rules established earlier in the series while also illustrating the trailer block validation rules. The example is well-chosen to show both the key format restrictions and their consequences in a real usage scenario.
