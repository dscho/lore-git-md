This is a follow-up to a refactoring patch that consolidates reachability functions in commit-reach.c. Kristofer Karlsson responds to Junio C Hamano's review of his patch that removed the redundant `get_reachable_subset()` function in favor of `tips_reachable_from_bases()`.

Kristofer acknowledges Junio's point about the hand-wavy performance justification in the original patch, and proposes a more thorough solution. He plans to modify `tips_reachable_from_bases()` to support both DFS and priority queue modes (using the existing prio_queue struct's LIFO/heap capabilities), which would preserve the optimal traversal strategy for each use case while still achieving the code consolidation.

The response includes a detailed analysis of the traversal characteristics: DFS being better for deep ancestry queries (like --merged) while priority queues work better for shallow targets (like add_missing_tags). Kristofer notes this difference mostly disappears with commit-graphs, but remains relevant for repositories without them. He concludes that while the performance impact is limited in practice (most large repos have commit-graphs), the dual-mode solution will maintain optimal behavior in all cases.

This follow-up shows the author taking the maintainer's feedback seriously and proposing a more robust solution that addresses the technical concerns while still achieving the original goal of code consolidation. The thread appears headed toward a technically sound resolution that satisfies both the simplification goal and performance considerations.
