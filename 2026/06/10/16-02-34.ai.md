This is a technical discussion about the behavior of `git history reword` (an experimental command in Patrick Steinhardt's `git history` feature), specifically focusing on how to handle cases where only the committer identity needs correction.

Junio C Hamano responds to Patrick Steinhardt's suggestion to model the behavior after `git commit --reset-author`. He notes that while this approach works for author identity, it doesn't fully address cases where only the committer identity is wrong (a common scenario when someone commits others' patches under the wrong identity). 

Junio proposes a two-phase solution:
1. Short-term: Default to creating a new commit even when only timestamps differ, but add an option to skip updates in such cases
2. Long-term: At a major version bump, flip this default to skip updates by default with an option to force creation

The discussion continues to refine the technical approach for handling identity corrections separately from message changes, building on earlier consensus about silent success for unchanged messages. Junio's response introduces new considerations about versioning behavior changes and the need for a distinct mechanism beyond `--reset-author` for committer-only corrections.
