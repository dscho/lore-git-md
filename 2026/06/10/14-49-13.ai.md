This is the second patch in the v2 series introducing `--linearize` to `git replay`. It is a pure refactoring patch that extracts the logic for storing a commit mapping into a new helper function `put_mapped_commit()` and renames the existing `mapped_commit()` to `get_mapped_commit()` for symmetry. The patch touches only `replay.c` and makes no behavior changes.

The extraction simplifies the lengthy `replay_revisions()` function by moving the khash map insertion logic into a dedicated helper. The new `put_mapped_commit()` function handles the duplicate-checking and insertion, while the renamed `get_mapped_commit()` (formerly `mapped_commit()`) remains responsible for retrieval. The patch is mechanical and self-contained, with no external callers or dependencies beyond the immediate file.

This refactoring is preparatory for the third patch, which implements the `--linearize` option and will use both `get_mapped_commit()` and `put_mapped_commit()`. The commit message is clear and the diff is straightforward, showing only the extracted logic and the corresponding call site updates. No test changes are needed since behavior is unchanged.
