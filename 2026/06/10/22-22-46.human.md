This is the third patch in Kristoffer Haugsbakk's documentation series updating the SubmittingPatches guidelines, focusing on discouraging Linux-specific commit message trailers like `Fixes:` and `Link:` in Git contributions.

The patch clearly explains why these trailers, while useful in the Linux kernel development workflow, don't serve the same purpose in Git's development model. For `Fixes:`, Git has fewer active trees and different cherry-picking practices, making the trailer less valuable. For `Link:`, Git already has alternative mechanisms like `refs/notes/amlog` for tracking patch discussions.

The change is well-motivated and non-controversial, simply documenting existing practice rather than introducing new rules. The patch follows the series' pattern of providing clear rationale for each guideline, helping contributors understand the conventions rather than just follow them blindly. As with the rest of the series, this appears to be a straightforward documentation improvement that codifies established norms.
