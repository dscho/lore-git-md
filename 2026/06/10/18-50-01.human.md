Performance optimization for `git describe` that limits ref iteration to tags by default, now in its third iteration. This patch from Tamir Duberstein builds on a 2008 optimization, further improving performance by having the ref backend skip non-tag refs entirely when `--all` isn't specified.

The key change remains adding a `refs/tags/` prefix filter to the ref iteration in `builtin/describe.c`. The v3 iteration incorporates feedback from Junio C Hamano to streamline the commit message, while maintaining the technical improvements from v2 that showed dramatic speedups - from ~172ms to ~10ms (17x faster) when describing an exactly-tagged commit in a repository with many refs.

New in v3:
- More realistic testing with packed refs
- Cleaner test setup using `test_seq`
- More concise performance reporting
- Maintains all the v2 improvements like testing with both ref backends

The patch is technically sound and has received positive reviews from Jeff King. The remaining discussion was purely about commit message presentation, which Tamir has now addressed. This optimization is particularly valuable for large repositories where `git describe` would previously waste time examining irrelevant refs.
