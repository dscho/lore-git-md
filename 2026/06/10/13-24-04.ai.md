This is a build system patch that refines the handling of library dependencies in Git's Makefile to eliminate duplicate archive references while maintaining correct linker behavior. The patch comes from Harald Nordgren as a follow-up to Junio Hamano's review of v1, which identified issues with simply removing duplicates.

The key technical change redefines the $(LIBS) variable to:
1. Explicitly list prerequisite archive files first (from $^)
2. Filter subsequent libraries to avoid duplicates
3. Preserve critical left-to-right linker ordering where object files must precede archives

The solution addresses macOS linker warnings about duplicate libraries while ensuring correct build behavior. The patch modifies three link recipes (test helpers, fuzz programs, unit tests) to use the new $(LIBS) definition rather than explicitly listing archives twice. The implementation demonstrates careful attention to both the cosmetic warning issue and the underlying technical constraints of linker behavior.

The v2 iteration shows substantial improvement over v1 by tackling the root cause through $(LIBS) restructuring rather than just removing duplicates at individual call sites. This makes the solution more maintainable and less likely to regress. The commit message clearly explains the technical rationale and expected impact.

The patch appears well-considered and addresses the issue at the right architectural level. It maintains backward compatibility requirements while cleaning up the build warnings, and the solution could serve as a pattern for similar situations elsewhere in the build system.
