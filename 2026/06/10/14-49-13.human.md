This is the second patch in Toon Claes' v2 series adding a `--linearize` option to `git replay`. It's a refactoring patch that extracts commit mapping logic into helper functions to improve code organization.

The patch introduces a new `put_mapped_commit()` helper function to handle storing rewritten commits in the `replayed_commits` hashmap, pairing with the existing lookup function (renamed from `mapped_commit()` to `get_mapped_commit()` for consistency). This change makes the main `replay_revisions()` function more readable by moving the hashmap manipulation details into dedicated functions.

The refactoring is mechanical and doesn't change behavior - it's preparation for the actual `--linearize` functionality that comes in patch 3/3. The implementation looks clean and follows Git's coding style, with the BUG() check preserved for duplicate commits. This is the kind of preparatory refactoring that makes subsequent feature additions easier to implement and review.

As part of a well-structured series, this patch has already incorporated feedback from Junio Hamano's review of v1 and carries Dscho's Signed-off-by, indicating technical alignment with his related merge-replay work. The changes are focused and unlikely to be controversial.
