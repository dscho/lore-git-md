This thread is about a five-part documentation patch series from Kristoffer Haugsbakk that updates Git’s `SubmittingPatches` guidelines to standardize how trailers (like `Signed-off-by:`) are used in commit messages. The series is now finalized and ready to be merged.

The goal is to clarify Git’s trailer conventions for legal compliance (DCO sign-off) and practical usability, while removing ambiguity about crediting contributions and formatting. Key updates include: a new section on basic trailer principles, explicit guidance to avoid Linux-specific trailers (like `Fixes:`), rules for the `Based-on-patch-by:` trailer (including DCO requirements), and standardized formatting. The series also establishes that trailers should be ordered chronologically, with `Signed-off-by:` last.

The latest patch (4/5) is a minor stylistic update to enforce consistent markup for trailers throughout the document, using backticks and colons (e.g., `` `Signed-off-by:` ``). This change is uncontroversial and aligns with the rest of the series. All feedback from Junio C Hamano and Patrick Steinhardt has been addressed, including clarifications on DCO compliance, trailer ordering, and rationale for omitting Linux-specific trailers. The series touches only the `Documentation/SubmittingPatches` file and is fully resolved.
