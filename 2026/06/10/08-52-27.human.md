This is part 7 of Patrick Steinhardt's v4 series adding a `git history drop` command, which builds on the experimental `git history` infrastructure. The series modernizes Git's reset machinery while implementing commit-dropping functionality.

This particular patch enhances the reset API by allowing callers to explicitly specify the "from" commit when performing a reset operation, rather than always deriving it from HEAD. This provides more flexibility for operations that need to reset from a different base (like the upcoming drop command). The change is straightforward - it adds an `oid_from` field to the reset options struct and uses it when present.

The patch continues the series' pattern of careful API design, with clear documentation of the new field's purpose. It touches the reset subsystem (reset.c/reset.h) but doesn't introduce any complex new behavior - just expands the existing reset capabilities in a way that will be useful for the drop command and potentially other callers. The implementation looks clean and maintains backward compatibility by falling back to HEAD when no explicit "from" commit is provided.
