This is part 9/10 of Patrick Steinhardt's v4 series introducing the `git history drop` subcommand, which refactors the reference update handling in preparation for the drop functionality.

The patch splits the existing `handle_reference_updates()` function into two distinct phases:
1. `compute_pending_ref_updates()` - Gathers all references that need updating by analyzing the revision walk results
2. `apply_pending_ref_updates()` - Executes the actual reference transaction with the collected updates

Key technical changes:
- Separates the computation of reference updates from their application
- Maintains the same behavior while making the code more modular
- Prepares for future changes where these phases may need to be called separately
- Continues the pattern of careful refactoring seen throughout this series

The changes are mechanical and well-contained, touching only builtin/history.c. The split follows good software engineering practices by separating concerns while maintaining the existing functionality. This appears to be a preparatory step for the actual drop command implementation that follows in patch 10/10.

The patch maintains all existing test coverage and doesn't introduce new functionality, focusing purely on internal API improvements. It's a typical example of Patrick's thorough, incremental approach to refactoring complex operations.
