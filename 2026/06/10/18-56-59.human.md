This is a review from Junio C Hamano on the v2 patch about hiding dotfiles in Git's path completion. The review focuses on implementation details and consistency across commands.

Junio notes that the current implementation requires duplicating the dotfile-hiding logic in the AWK script, suggesting a refactoring that would make the code cleaner and the new feature easier to maintain. He proposes restructuring the path processing loop to handle quoting and dotfile checks in a single place.

More significantly, Junio points out inconsistencies in which commands get the new dotfile-hiding behavior. While `git ls-files` and `git mv` hide dotfiles, other commands like `git add` and `git commit` don't, without clear rationale. He suggests several ways to make this more coherent:
- Making the dotfile parameter mandatory (with explicit "hide" or "include" values)
- Adding comments explaining the choices
- Standardizing on hiding dotfiles by default when no pattern is given

The review doesn't challenge the fundamental approach but highlights areas where the implementation could be more maintainable and consistent. This suggests the patch is conceptually sound but needs another iteration to address these technical concerns before merging.
