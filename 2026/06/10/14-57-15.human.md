This is the final patch in Patrick Steinhardt's 9-part refactoring series to modernize Git's reference backend infrastructure. The patch completes the transition to using absolute paths consistently across all ref backends by modifying `refs_compute_filesystem_location()` to always return absolute paths.

The key changes are:
- Makes `refs_compute_filesystem_location()` always resolve paths to absolute form
- Removes now-unnecessary `chdir_notify_reparent()` callbacks from files, packed, and reftable backends
- Updates several tests to expect absolute paths in error messages

This builds on the series' earlier work to eliminate relative path handling in ref backends. The change is mostly mechanical but does have a user-visible impact - error messages will now show absolute paths rather than relative ones. Patrick argues this is actually beneficial when working across multiple repositories.

The patch continues Patrick's pattern of thorough, incremental refactoring in the refs subsystem. With this change, the series achieves its goal of simplifying path handling in the reference backend code by removing the need for chdir notification callbacks entirely. The changes appear well-contained and unlikely to be controversial.
