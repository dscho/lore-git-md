This is a v2 of Junio C Hamano's feature patch adding a `--rename` option to `git update-ref`. The new version removes the runtime warning when renaming branch refs (under `refs/heads/`), keeping only the documentation note that users should prefer `git branch -m` for branches since it handles worktree HEAD updates and config tracking.

The core functionality remains the same: `git update-ref --rename <old> <new>` atomically moves a ref and its reflog, failing if the old ref doesn't exist or new ref already exists. The implementation still doesn't support renames in `--stdin` batch mode due to limitations in the ref transaction API.

Test coverage is expanded to verify reflog preservation and error conditions. The changes are focused and well-contained, touching documentation, command-line handling, and the core rename logic. This fills a gap in Git's low-level ref manipulation toolkit while deferring transactional batch support for future work. The patch appears ready for merging.
