This is patch 4/9 in Patrick Steinhardt's series refactoring Git's reference backend infrastructure. The patch focuses on fixing memory management issues related to the "chdir_notify" subsystem in reference stores.

The key changes in this patch:
1. Adds proper unregistration of reference stores from chdir_notify when they are released, preventing memory leaks and use-after-free scenarios
2. Replaces `chdir_notify_reparent()` calls with `chdir_notify_register()`/`unregister()` pairs to enable proper cleanup
3. Implements this for all three ref backends: files, packed, and reftable

The patch addresses two specific issues:
- For main reference databases, it prevents a memory leak (though the actual leak fix comes in a later commit)
- For submodule/worktree databases, it prevents potential use-after-free if chdir occurs after release

The changes are mechanical but important for correctness. Each backend gets a new reparent callback function and proper cleanup registration. This is part of the larger effort to eliminate chdir_notify usage entirely in favor of absolute paths, as noted in the commit message.

The patch maintains the series' focus on cleaning up ref backend infrastructure while being careful to note this is an intermediate step toward the ultimate goal of removing chdir_notify entirely. The changes appear straightforward and well-contained to the refs subsystem.
