This is the final patch in Patrick Steinhardt's v4 series introducing a `git history drop` subcommand, building on the experimental history command framework. The patch implements the actual drop functionality that removes a commit from history while replaying its descendants onto its parent.

The implementation:
- Prevents dropping root commits (to avoid empty history edge cases) and merge commits (due to existing limitations in the history command)
- Handles working tree and index updates when HEAD is affected by the drop
- Includes extensive test coverage (537 lines across various scenarios)
- Integrates with the reset API modernization from earlier in the series
- Provides dry-run capability and ref update control via flags

The command works by:
1. Verifying the commit can be dropped (not root/merge)
2. Computing the new history by replaying descendants onto the commit's parent
3. Checking for working tree conflicts in a dry-run phase
4. Updating references and working tree if successful

Notable limitations:
- Root and merge commits cannot be dropped (though root commit support may come later)
- The implementation inherits the history command's general limitation around merge commits

This appears to be a well-considered addition to the history command, with thorough test coverage and careful handling of edge cases. The reset API changes from earlier in the series pay off here by providing clean working tree integration. The patch builds on established patterns from the history command while introducing new functionality that should be useful and intuitive for users.
