This is the third and final patch in a v2 series adding a `--linearize` option to `git replay`. The feature lets `git replay` flatten merge commits, matching the default behavior of `git rebase --no-rebase-merges`. This patch implements the user-facing option, updates the internal replay machinery to skip merge commits when `--linearize` is active, and adds test coverage for the new mode.

The patch touches the man page (`Documentation/git-replay.adoc`), the command-line parser (`builtin/replay.c`), the core replay logic (`replay.c` and `replay.h`), and the test script (`t3650-replay-basics.sh`). It introduces a new boolean flag `linearize` in the `replay_revisions_options` struct, enforces mutual exclusivity with `--revert`, and modifies the commit-traversal loop to skip merge commits when the flag is set. The test cases verify that merge commits are dropped and that the resulting history is linear, including a case that replays all the way to the root commit.

The implementation is straightforward and follows the feedback from Junio’s v1 review: the logic for handling merge commits is now explicitly structured with a clarifying comment, and the test suite has been rewritten to reuse the existing history setup. The patch is part of a well-motivated series that positions `git replay` as a server-side building block for rebase-like operations. It looks ready for review and is unlikely to be controversial.
