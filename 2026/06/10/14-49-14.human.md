Feature patch completing the `git replay --linearize` series. This final patch in the v2 series implements the `--linearize` option for `git replay`, which flattens merge commits into linear history similar to `git rebase --no-rebase-merges`. The implementation now properly handles merge commits by walking their first parent only when linearizing, while maintaining the existing error for merge commits without `--linearize`.

Key technical details:
- Adds CLI/config option with standardized documentation
- Implements merge commit handling (maps to first parent)
- Uses unified `pick_regular_commit()` helper
- Explicitly disallows combining `--linearize` with `--revert`
- Includes expanded test coverage in t3650 for root commit handling

The patch builds on Johannes Schindelin's earlier merge-replay work and includes his Signed-off-by, indicating alignment between the approaches. The implementation appears clean and well-tested, with Junio Hamano's review feedback from v1 already incorporated. This provides a useful alternative to interactive rebase for server-side operations that need linear history.
