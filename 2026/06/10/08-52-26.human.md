This is part 6 of Patrick Steinhardt's v4 series introducing the `git history drop` subcommand, which builds on the experimental history command framework. The patch focuses on refining the reset machinery's behavior around HEAD updates.

The key change here is introducing a new `RESET_WORKING_TREE_UPDATE_HEAD` flag that makes HEAD updates opt-in rather than opt-out, addressing an inconsistency Phillip Wood identified in the previous approach. The patch updates all existing callers (in rebase.c and sequencer.c) to explicitly request HEAD updates where needed.

This is a well-contained change that follows naturally from the API design discussion in earlier iterations. The implementation is cleanly scoped - it touches only the reset machinery and its callers, with no behavioral changes beyond making the update control more explicit. The patch demonstrates good attention to detail by ensuring all existing call sites are properly updated to maintain current behavior.

As part of the larger series, this helps enable the drop command's two-phase reference updates while keeping the reset API clean and consistent. The change is unlikely to be controversial given it implements an agreed-upon design direction from prior review feedback.
