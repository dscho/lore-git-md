This is patch 6/9 in Patrick Steinhardt's series to modernize Git's reference backend infrastructure, focusing on memory management cleanup. The patch fixes a memory leak where the main reference database wasn't being freed when clearing a repository, while worktree and submodule reference databases were properly released.

The change adds cleanup code to `repo_clear()` that releases the `refs_private` field when destroying a repository. The leak had gone unnoticed because the chdir_notify subsystem was keeping the pointer alive. This is a logical next step after the previous patches removed chdir_notify dependencies from the ref backends.

The patch is small and focused, following the series' pattern of incremental improvements to reference storage cleanup. It demonstrates good code hygiene by plugging a leak that became visible as part of the broader refactoring effort. The change is straightforward and unlikely to be controversial, though reviewers may want to verify it doesn't interact unexpectedly with any edge cases in repository teardown.
