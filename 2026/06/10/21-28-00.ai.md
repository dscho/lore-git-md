This is a v2 of Junio C Hamano's patch adding a `--rename` option to `git update-ref`, following up on the initial proposal. The key change from v1 is removing the runtime warning when renaming branch refs (under `refs/heads/`) while keeping the documentation warning users to prefer `git branch --rename` for branches.

The patch adds low-level ref renaming capability with reflog preservation via `git update-ref --rename <old-ref> <new-ref>`. The operation fails if the old ref doesn't exist or new ref already exists. The implementation explicitly defers adding batch/transactional rename support via `--stdin` mode, as that would require deeper ref transaction API changes.

Changes from v1:
- Dropped the runtime warning for branch refs (now only documented)
- Improved test coverage with explicit reflog verification
- Clarified commit message about the plumbing nature of the command
- Simplified error messages and test assertions

The patch remains focused on the core rename functionality while leaving transactional support for future work. Documentation and tests have been updated to match the revised behavior. This appears to be a well-considered iteration addressing the initial feedback about warning verbosity while maintaining the safety guidance for branch renames.
