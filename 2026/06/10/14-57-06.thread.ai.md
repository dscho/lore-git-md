Thread identity: 11-part **v5 refactoring series** by Patrick Steinhardt modernizing Git's reference backend infrastructure. The series implements a **lazy-loading design** to resolve recursive initialization issues caused by "onbranch" configuration conditions, abandoning the v4 `ignore_refs` workaround. The rewrite targets the root cause by deferring write-config parsing until the first write operation, eliminating early config reads that could trigger recursive ref store access. The series is now **functionally complete**, with the final patch (11/11) adding a **recursion guard** to `get_main_ref_store()` as a safeguard against recursive initialization.

Core problem: The reference backend suffered from initialization sequencing issues, redundant repository format application, memory leaks, and incomplete lifecycle management in the `chdir_notify` subsystem. The v5 redesign **decouples read-critical and write-critical config parsing**: ref backends initialize with only minimal config (e.g., hash algorithm) and defer write-related settings (e.g., `core.logAllRefUpdates`, `core.sharedRepository`, `core.preferSymlinkRefs`, `reftable.blockSize`) until the first write. This eliminates the fragile dependency on early config reads that could trigger recursion via `includeif.onbranch`, addressing Jeff King's (Peff) concerns about config cache inconsistencies and user-facing regressions (e.g., `git commit` failing to respect `onbranch`-scoped `core.logAllRefUpdates`).
