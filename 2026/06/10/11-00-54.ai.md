Bugfix targeting the interactive rebase machinery with `--update-refs`.

This patch reports a bug where `git rebase --update-refs` incorrectly generates an unqualified "update-ref HEAD" line in the todo list when rebasing the currently checked-out branch. The sequencer then rejects this as invalid since it requires fully qualified refnames. The issue occurs in a minimal reproduction scenario with just a few empty commits on a feature branch.

The expected behavior would be to either expand HEAD to its target ref (refs/heads/feat in the example) or omit it entirely, since the branch ref itself is already being updated. The bug breaks the rebase workflow by producing an invalid todo file that must be manually edited to proceed.

The reporter notes this isn't worktree-specific and provides clear reproduction steps showing the malformed todo list and the resulting error. They also identify workarounds (disabling updateRefs or manually editing the todo file). The bug appears in Git 2.54.0 but likely affects earlier versions with the `--update-refs` feature.

This seems like a straightforward logic error in the ref-update generation code that needs to special-case HEAD handling. The report is well-written with all necessary technical details to diagnose and fix the issue.
