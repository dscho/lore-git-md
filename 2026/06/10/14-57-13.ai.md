This is patch 7/9 in Patrick Steinhardt's series refactoring Git's reference backend infrastructure. The patch addresses a subtle recursion issue in the reference store setup when "onbranch" configuration conditions are present.

The core problem is a chicken-and-egg scenario where:
1. The reference database needs configuration to initialize itself
2. The configuration needs a reference database to evaluate "onbranch" conditions
3. This leads to recursive calls to `get_main_ref_store()`

The patch fixes this by temporarily unsetting the reference storage format during initialization, which prevents the recursion by making the "onbranch" condition check fail as intended. This ensures we only construct the reference store once rather than leaking a duplicate instance.

The change is narrowly focused on the initialization sequence in `refs.c` and maintains the existing behavior of not evaluating "onbranch" conditions during refdb setup. The solution is a bit of a dance with the format flag, but effectively preserves the intended semantics while fixing the recursion and leak.

This continues the series' theme of cleaning up reference backend initialization and follows naturally from the earlier patches that removed chdir_notify infrastructure. The change appears well-contained and unlikely to introduce new issues, though reviewers may want to verify the exact sequencing of format flag manipulation.
