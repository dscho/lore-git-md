This is patch 6/10 in Patrick Steinhardt's v4 series introducing the `git history drop` subcommand, focusing on reset machinery improvements. The patch introduces a new `RESET_WORKING_TREE_UPDATE_HEAD` flag to control whether HEAD updates should occur during reset operations, addressing feedback from Phillip Wood about making the API more consistent.

The key change is flipping the previous approach - rather than having callers opt out of reference updates (via `SKIP_REF_UPDATES`), they now explicitly opt in to HEAD updates. This better aligns with the existing `UPDATE_ORIG_HEAD` flag pattern. The patch updates all existing callers in rebase.c and sequencer.c to maintain current behavior while enabling the new dry-run functionality needed for the history drop command.

The implementation is straightforward - the flag is checked in reset.c to conditionally skip the reference update logic. This maintains backward compatibility while providing the flexibility needed for the history command's dry-run mode. The changes are mechanical but important for the overall series' goal of robust reset behavior during commit dropping operations.

This continues the series' pattern of careful API design and thorough updates to all affected call sites. The change appears well-contained and unlikely to introduce regressions given the comprehensive updates to existing reset callers.
