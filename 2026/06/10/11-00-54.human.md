Bugfix for `git rebase --update-refs` with HEAD references.

This patch reports a bug where interactive rebase with `rebase.updateRefs=true` generates an invalid todo command when rebasing the currently checked-out branch. The sequencer incorrectly emits an unqualified "update-ref HEAD" line that it then rejects as not being a fully-qualified refname, requiring manual intervention to delete the line and continue the rebase.

The issue occurs in a minimal single-branch repository and appears to stem from the rebase machinery treating HEAD as a separate ref to update rather than recognizing it as a symbolic reference to the branch being rebased. The patch includes a clear reproduction recipe showing the problematic behavior and contrasts it with the expected output (where HEAD would either be expanded to its target ref or omitted entirely).

While the bug is not catastrophic - there's a straightforward workaround of either disabling updateRefs or manually editing the todo file - it does break the rebase workflow unexpectedly. The reporter notes the issue is not worktree-specific and persists across different repository configurations. The bug appears well-isolated and reproducible, making it a good candidate for fixing in a maintenance release.
