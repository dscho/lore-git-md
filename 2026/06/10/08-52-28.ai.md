This is part 8/10 of Patrick Steinhardt's v4 series adding a `git history drop` subcommand, focused on improving the reset machinery's handling of dirty indexes. The patch removes an optimization that assumed callers would always pass a clean index to `reset_working_tree()`, since the upcoming drop command will violate that assumption.

The change modifies when cache tree updates are skipped - now only during hard resets rather than unconditionally. This maintains correctness while still preserving the optimization where safe. The patch notes the original performance benefit was negligible anyway, making the tradeoff clearly worthwhile.

This is a straightforward technical adjustment that prepares the reset infrastructure for the drop command's needs while maintaining existing behavior for current callers (rebase and sequencer). The change is well-motivated and narrowly scoped, touching only the cache tree update logic in reset.c. It follows naturally from the series' earlier reset API modernization work.
