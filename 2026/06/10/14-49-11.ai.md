This is a feature patch series (v2) from Toon Claes that adds a `--linearize` option to `git replay`, building on Johannes Schindelin's (Dscho) earlier merge-replay work. The series refactors some replay internals first, then implements the new option which flattens merge commits into linear history similar to `git rebase --no-rebase-merges`.

Key changes in v2:
- Restructured merge commit detection logic with clearer comments
- Expanded test coverage to include root commit handling scenarios
- Added Dscho's Signed-off-by after confirming it was appropriate
- Fixed documentation verb tense and phrasing issues noted in review

The implementation now cleanly handles merge commits by walking their first parent only when linearizing, while maintaining the existing error for merge commits without `--linearize`. The test suite additions verify both the linearization behavior and proper error handling.

The series remains positioned as an alternative to Dscho's separate merge-replay approach, with the author noting they'll help reconcile the two if needed. Documentation conflicts with Kristoffer Haugsbakk's work and Patrick Steinhardt's `git history drop` series are mentioned as minor and resolvable.

Technical details for future reference:
- Touches `replay.c` commit mapping logic and `replay.h` option definition
- Adds new test cases in t3650 for linearization scenarios
- Explicitly disallows combining `--linearize` with `--revert`
- Does not extend the option to `git history` as the author feels it doesn't fit that command's use case

The series appears ready for inclusion pending final documentation polish, with Junio Hamano's substantive review feedback already incorporated. The collaborative development between Toon and Dscho suggests this approach has buy-in from key stakeholders in the replay functionality.
