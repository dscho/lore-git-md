This is the v2 cover letter for a three-patch feature series adding a `--linearize` option to `git replay`. The series teaches `git replay` to flatten merge commits, matching the default behavior of `git rebase --no-rebase-merges`. Toon Claes is the primary author, with Johannes Schindelin contributing the first patch and co-authoring the third.

The v2 iteration addresses Junio’s feedback from v1: the conditions for detecting merge commits are now explicitly structured with a clarifying comment, the test suite has been rewritten to reuse the existing history setup and now includes a case replaying all the way to the root commit, and Johannes’s Signed-off-by trailer has been re-added (with his consent). The series touches `replay.c`, `replay.h`, `builtin/replay.c`, the man page, and the test script `t3650-replay-basics.sh`.

Key technical details remain unchanged from v1: the new option is exposed as `--linearize`, the internal logic uses two boolean flags (`reverse` and `linearize`), and the implementation is mutually exclusive with `--revert`. The series is still positioned as a simpler alternative to Johannes’s earlier merge-replay work (pull.2106), and the author reiterates that `--linearize` is intentionally omitted from `git history` because no clear use case exists. Potential trivial conflicts with Kristoffer’s documentation changes and Patrick Steinhardt’s `git history drop` series are still noted but expected to be easy to resolve.
