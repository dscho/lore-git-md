Feature patch completing the `--linearize` option for `git replay`, building on Johannes Schindelin's earlier merge-replay work. This final patch in the series implements the actual linearization behavior that flattens merge commits by walking only their first parent, similar to `git rebase --no-rebase-merges`.

Key technical details:
- Adds `--linearize` CLI option and config support
- Modifies `pick_regular_commit()` to handle linearization case
- Explicitly disallows combining `--linearize` with `--revert`
- Includes test cases verifying:
  - Basic linearization behavior
  - Root commit handling
  - Proper error when attempting to replay merges without `--linearize`

The implementation cleanly separates the linearization logic from the existing replay infrastructure while maintaining the same error checking and commit mapping.
