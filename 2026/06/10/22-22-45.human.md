This is the second patch in Kristoffer Haugsbakk's documentation series updating the SubmittingPatches guidelines, focusing on trailer conventions in commit messages. The series aims to clarify and standardize how trailers (those metadata lines at the end of commit messages) should be used.

This particular patch addresses non-identity trailers - those that don't credit people, such as issue tracker references. The change encourages contributors to consider whether such trailers are truly useful before adding them, rather than treating the trailer section as a general metadata dumping ground. The patch maintains the existing guidance to prefer the common identity-related ones (Signed-off-by, Reviewed-by, etc.) while acknowledging there may be valid cases for other types.

The change is small but thoughtful, adding nuance to the documentation without being overly prescriptive. As with the rest of the series, this appears to be a non-controversial documentation improvement that codifies existing best practices. The patch follows the same clean style as the rest of the series, with a clear commit message explaining the rationale.
