This is a refactoring patch in the ongoing `the_repository` removal effort, specifically addressing the movement of `protect_hfs` and `protect_ntfs` configuration variables from global scope to repository-specific storage. Tian Yuchen sends this as the first version of what appears to be a mentored contribution (with three mentors listed).

The patch itself moves these filesystem protection variables into the `repo_config_values` struct and updates all access points accordingly. The changes are mechanical but touch sensitive areas of path validation code, particularly for Windows (HFS/HFS+ protections). The author maintains existing behavior while progressing the architectural goal of eliminating globals.

The email raises three specific design questions for discussion:
1. Whether default values should remain in `repo_config_values_init()` or be handled elsewhere
2. Whether to introduce a macro/getter for safer access to these values when repository context is unclear
3. Whether an alternative approach by Derrick Stolee (using `get_int_config_global`) might still have merit despite previous rejection

The patch appears well-contained with appropriate test coverage preserved, though the author notes some temporary fallbacks to `the_repository` remain that will need future cleanup. The multiple mentors suggest this may be part of an outreach program contribution. No reviews have been posted yet on this version.
