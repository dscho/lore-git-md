Optimization of Git's priority queue implementation with deferred removal tracking and operation fusion, **merged** after four iterations. The series generalizes the lazy_queue pattern from builtin/describe.c into core prio_queue functionality, eliminating duplicate optimizations while delivering measured 1.7-2.7% speedups on traversal-heavy operations (merge-base, revision walking).

**Core problem/goal**: Replace three independent lazy_queue implementations (describe.c, commit.c, show-branch.c) with a unified core optimization, reducing code duplication while maintaining or improving performance. The key technical change is the `get_pending` flag enabling deferred removals, which fuses get+put operations into single replaces to avoid full remove-rebalance-insert cycles.

**Technical details**:
- **Files touched**: 13 files across builtin commands and core subsystems (e.g., `prio-queue.c`, `commit.c`, `describe.c`, `show-branch.c`).
- **New/renamed symbols**: `.nr_` (renamed from `.nr`), `prio_queue_size()`, `prio_queue_for_each()`, `flush_get()` (restored helper).
- **Behavioral changes**: Deferred removal logic inlined into core prio_queue, empty-queue guard (`nr_ <= get_pending`), removal of `prio_queue_replace()`.
- **Performance**: Validated by René Scharfe; 30-run Xeon benchmarks show all variants within 1.3% envelope, with 1.7-2.7% speedups on merge-base/revision walking.
- **On-disk format**: No changes; this is a pure in-memory optimization.

**Evolution across versions**:
- **v1-v2**: Eliminated unsafe direct field accesses (e.g., `.nr`).
