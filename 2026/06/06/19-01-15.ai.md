This is a performance optimization patch for Git's priority queue implementation, now in its second iteration. The patch folds the "lazy_queue" pattern (which defers removals to allow subsequent puts to become simple replaces) into the core prio_queue functionality while addressing all correctness concerns from the v1 review.

The key optimization enables deferred removals via a new `get_pending` flag, fusing get+put operations to avoid full remove-rebalance-insert cycles. This matches Git's common commit traversal pattern of getting a commit then putting its parents. Benchmarks show 3-6% speedups on traversal-heavy operations like merge-base and revision walking.

The v2 changes significantly harden safety by renaming the internal `.nr` field to `.nr_internal` to surface direct accesses, converting all identified callers to use a new `prio_queue_size()` helper. It also adds a `prio_queue_for_each()` macro for safe element access. The patch eliminates duplicate lazy_queue implementations from builtin/describe.c, builtin/show-branch.c, and commit.c while maintaining the performance benefits.

Review feedback from v1 has been thoroughly addressed - all identified direct field accesses have been converted, edge cases are properly handled, and documentation reflects the new access patterns. The changes touch multiple subsystems (fetch-pack, path-walk, commit-reach) but maintain clean separation. The optimization is particularly impactful for operations that heavily use priority queues like merge-base calculations.

The series appears ready for integration, having preserved its performance gains while properly hardening the correctness concerns raised in v1. The cross-subsystem impact is now handled with consistent, safe access patterns.
