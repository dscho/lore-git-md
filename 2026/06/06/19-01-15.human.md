This is a performance optimization patch for Git's priority queue implementation, part of a v2 series that has already addressed correctness concerns from earlier review.

The patch folds the "lazy_queue" pattern (which defers removals to allow subsequent puts to become simple replaces) into the core prio_queue implementation. This eliminates duplicate implementations in several callers while maintaining 3-6% speedups on traversal-heavy operations like merge-base calculations and revision walking. The optimization is particularly effective for Git's common get+put pattern in commit traversals.

Key changes include:
- Deferred removal tracking via a new `get_pending` flag
- Fusion of get+put operations to avoid full remove-rebalance-insert cycles
- Removal of the now-unnecessary `prio_queue_replace()` function
- Addition of `prio_queue_size()` helper for callers needing element count

The patch shows thorough responsiveness to v1 review feedback, with all identified direct field accesses converted to use proper helpers. Benchmark results show consistent speedups without regressions, and the implementation now properly handles edge cases across multiple subsystems. The changes are well-scoped and the commit message clearly explains both the optimization and safety improvements.

This appears ready for integration, having addressed all substantive feedback while preserving its performance benefits. The cross-subsystem impact is now properly handled with consistent, safe access patterns.
