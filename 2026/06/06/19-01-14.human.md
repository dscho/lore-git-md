Performance optimization for Git's priority queue implementation, now in its second iteration. This patch series generalizes the common pattern of popping an item from the queue and immediately pushing new items (typically during commit traversals), avoiding expensive remove-rebalance-insert cycles.

The key changes in v2 address feedback from Junio C Hamano about direct field access safety:
- Renames the internal `.nr` field to `.nr_internal` to prevent unsafe direct access
- Adds a `prio_queue_for_each()` macro for safe element traversal
- Converts all remaining direct field accesses to use proper helper functions
- Fixes several missed callers from v1 across multiple subsystems

The optimization itself remains unchanged - it still provides 3-6% speedups on traversal-heavy operations by fusing get+put operations. The series now properly handles the cross-subsystem impact, touching priority queue usage in describe, show-branch, fetch-pack, path-walk, and other areas.

This is part of ongoing performance work building on prior commit-reach optimizations. The changes are independent of but complementary to other queue optimizations like cascade sift-down. The v2 hardening makes this ready for serious consideration while maintaining the original performance benefits.
