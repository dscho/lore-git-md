This is the second patch in a two-part series optimizing Git's priority queue implementation. It follows up on v1 feedback by hardening the API against unsafe direct field access.

The patch renames the internal `.nr` field to `.nr_internal` to prevent direct access from outside the prio-queue implementation, forcing callers to use the proper accessor functions. This catches both existing misuse and prevents future violations. It also adds a new `prio_queue_for_each()` macro for safe element iteration.

The changes touch multiple subsystems that use priority queues (describe.c, show-branch.c, fetch-pack.c, etc.), converting all external `.nr` accesses to use the new API. The patch demonstrates thorough responsiveness to v1 review feedback - all identified direct field accesses have been properly converted, and the implementation now properly handles edge cases across the codebase.

This hardening work complements the performance optimization from the first patch (which introduced deferred removal tracking) while maintaining the 3-6% speedups on traversal-heavy operations. The series appears ready for integration, having addressed all substantive feedback while preserving its benefits.
