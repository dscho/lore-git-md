This is the fifth version of Pablo Sabater's feature patch series improving `git log --graph` rendering of commits with excluded parents. The series introduces cascading indentation for visual root commits to make parent-child relationships clearer when history simplification filters out some parents.

The key change in v5 is fixing a test failure from v4 by unsetting COMMIT_GRAPH in the test environment. The series maintains the architectural redesign from v4 where visual roots (except the first) are progressively indented to create hierarchy, rather than indenting following commits as in earlier versions.

The implementation handles multiple visual roots with cascading indentation while exempting merge parents. There remains one known edge case where the lookahead mechanism can't perfectly predict when a commit will become a visual root after history simplification, documented with a NEEDSWORK comment. The author notes unfamiliarity with revision.c to fix this.

The series consists of two patches:
1. Moving a common test helper function to a shared location
2. The main implementation adding visual root indentation

Test coverage appears thorough with a new dedicated test file (t4218) plus updates to existing graph tests. The v5 iteration suggests the author is actively responding to feedback and test failures, with the current version appearing technically sound aside from the documented lookahead edge case. The series seems close to merge-ready pending any final review feedback on the visualization rules documentation question raised in earlier versions.
