This is the first patch in a 2-part series to improve `git commit --amend` behavior. It's a preparatory refactoring that extracts the index file committing logic into a new helper function `commit_index_files_or_die()`.

The change is purely mechanical - it moves the existing error handling code from `cmd_commit()` into a new function without altering any behavior. This sets up for the second patch which will use this helper when implementing the no-op amend optimization.

The patch touches only `builtin/commit.c`, converting the direct call to `commit_index_files()` with its error handling into a wrapped version. The error message remains identical, just moved to the new helper. This is a clean, focused change that follows Git's convention of extracting reusable functionality before adding new features that need it.

As noted in the commit message, there's no functional change here - it's groundwork for the actual behavior change coming in patch 2/2. The test coverage for this change will come with the follow-up patch that exercises the new helper.
