This is a feature proposal to add a `GIT_CLONE_DEPTH` environment variable as a fallback for the `--depth` option in `git clone`. The patch comes from Hadrien Loge, who argues this would be particularly useful for packaging workflows (like Arch Linux's PKGBUILD and Alpine's APKBUILD) where nested clone operations lose the depth setting when called from scripts.

The key motivation is that environment variables propagate naturally through nested script invocations, unlike command-line arguments. The example shows a scenario where an initial shallow clone calls a script that performs its own clones - currently there's no way to preserve the depth setting across this boundary. The author notes significant space savings (900KB vs 17MB for a 5k-commit history) when using shallow clones.

The patch has been revised to include tests and documentation, and the proposed variable name was changed from `DEPTH` to `GIT_CLONE_DEPTH` to follow Git's naming conventions. This appears to be a well-motivated change targeting a specific pain point in packaging workflows, with attention given to testing and naming consistency. The implementation seems straightforward but would need review for edge cases around environment variable precedence and interaction with other clone options.
