Thread identity: RFC documentation patch series (2 parts) from Weijie Yuan proposing updates to contributor guidelines in `MyFirstContribution.adoc` and `SubmittingPatches` regarding patch review etiquette.

Core problem/goal: Improve documentation around two key aspects of patch review workflow: (1) requiring substantive discussion of review feedback before rerolling patches, and (2) establishing appropriate reroll cadence based on series size and review depth. The goal is to make implicit review norms explicit for new contributors.

Current status: Initial RFC (v1) seeking feedback on content and phrasing. Junio C Hamano has reviewed the second patch (reroll timing guidance) and supports the general direction while adding philosophical rationale about review quality and global participation.

Key technical details: Modifies two core documentation files that shape new contributor expectations. Changes include:
1. Explicit guidance about discussing review feedback in-thread before sending new versions, including explaining reasoning about which suggestions to implement/reject
2. Concrete advice about reroll timing (default of no more than one per day) with flexibility for series size and review depth, now with additional rationale about review quality and timezone considerations
3. Clear demonstration of the proposed approach through well-motivated documentation changes
4. Attribution of Patrick Steinhardt's prior contributions to these guidelines

Open questions:
- Final phrasing of new guidelines in both documents
- Whether additional review etiquette aspects should be included
- Whether the balance between discussion and implementation is correctly framed
- If the reroll timing guidance adequately covers edge cases (e.g., trivial fixes, time-sensitive topics)
- How to incorporate Junio's perspective about review quality and global participation into the documentation

Participant positions:
- Weijie Yuan (author) proposing changes based on mailing list discussions and demonstrating the advocated approach
- Junio C Hamano supports the direction, adding rationale about review quality and timezone considerations
- Patrick Steinhardt's prior advice about reroll timing being incorporated and properly attributed (CC'd but not yet responded)
- The patch structure itself models the proposed review best practices

Related work: Builds on ongoing mailing list discussions about improving contributor experience and review workflow efficiency. The changes formalize observed patterns where new contributors sometimes send new versions without sufficient prior discussion or consideration of reviewer bandwidth.
