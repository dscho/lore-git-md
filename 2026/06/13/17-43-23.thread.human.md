Hadrien Loge proposed adding a `GIT_CLONE_DEPTH` environment variable as a fallback for `--depth` in `git clone`, aimed at packaging workflows where nested clones lose the depth setting. The initial patch added support in `builtin/clone.c` with tests, following Git's naming conventions.

brian m. carlson has raised substantive concerns about the design, questioning whether shallow clones are appropriate for reproducible packaging workflows. They argue that environment variables could break scripts relying on full history (like those using `git describe`) and that shallow fetches create unnecessary server load. While acknowledging the packaging use case, they suggest the change might introduce subtle failures elsewhere in the ecosystem. This moves the discussion from implementation details to broader design tradeoffs about whether environment variables should influence cloning behavior.
