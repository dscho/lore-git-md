Hadrien Loge has proposed adding a `GIT_CLONE_DEPTH` environment variable that would serve as a fallback for the `--depth` option in `git clone`. The main use case is for packaging workflows (like Arch Linux's PKGBUILD and Alpine's APKBUILD) where nested clone operations currently lose the depth setting when called from scripts. Environment variables naturally propagate through nested script invocations, solving this problem where command-line arguments fail.

The proposal demonstrates significant space savings - showing a 900KB shallow clone versus 17MB for a full 5k-commit history. The patch has gone through revisions to include proper tests and documentation, with the variable name carefully chosen as `GIT_CLONE_DEPTH` to follow Git's naming conventions. This appears to be a well-considered solution to a specific pain point in packaging workflows, though it would need review for edge cases around environment variable precedence and interaction with other clone options.
