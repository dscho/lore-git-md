This is a discussion thread about the proposed behavior change for `git commit --amend --no-op`. Ben Knoble weighs in on Johannes Sixt's review of Harald Nordgren's patch series.

Ben concisely notes that the current behavior of `git commit --amend --no-edit` (which always updates the committer timestamp) serves a practical purpose - it provides a way to force CI re-runs by creating a new commit hash even when no other changes are made. This observation supports Johannes' concern that removing this capability might break existing workflows.

The exchange highlights a tension between optimization (avoiding no-op commits) and preserving existing use cases. Ben's comment suggests the proposed change could unintentionally remove functionality that some users rely on for triggering rebuilds or other timestamp-dependent behaviors.

This moves the discussion forward by providing a concrete example of why the current behavior might be intentionally used, beyond just being an implementation artifact. The thread now has clear examples of both the problem the patch aims to solve (unnecessary commit creation) and the functionality it would remove (forced timestamp updates).
