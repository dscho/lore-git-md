**Test fix patch in greplint series**: This is the second patch in a 6-part series (v2) that fixes three test cases where `grep` assertions were missing file arguments, causing them to silently pass by reading empty stdin rather than checking the intended files. The fixes address:

1. A worktree listing test where a negated grep was missing its input file
2. A commit status test with a malformed grep pattern that accidentally omitted the file
3. A repack test checking for missing objects where the input file was omitted

The patch demonstrates the value of the broader greplint effort by catching these pre-existing bugs during the conversion process. Each fix is straightforward - adding the missing filename argument to make the assertions actually verify what they intended. The tests happened to pass before due to the empty stdin behavior, but now properly validate their conditions.

This patch stands on its own as a clear improvement to test correctness, independent of the larger debate about automated grep conversions. It shows the kind of subtle test issues that can be uncovered when systematically examining grep usage patterns across the test suite.
