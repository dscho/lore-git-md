This is the second patch in a 2-part series addressing a behavior change in `git commit --amend`. The patch implements the core functionality to avoid creating no-op commits when amending with no substantive changes.

The change makes `git commit --amend --no-edit` preserve the original commit hash when nothing has changed (tree, message, author, parents, and committer identity remain the same), rather than always creating a new commit with an updated timestamp. The implementation:

1. Adds a new `amend_is_noop()` function that checks if the amended commit would be identical to the original by reusing the existing committer date
2. Skips commit creation and reports "nothing to amend" when true
3. Explicitly excludes signed commits from this optimization (since signatures can't be reproduced)
4. Adds comprehensive test coverage for various edge cases:
   - Verifies behavior with unchanged content
   - Confirms reflog isn't updated for no-op amends
   - Tests interaction with signoff, GPG signing, --reset-author, and --date
   - Ensures post-commit hooks are skipped for no-op cases

The change is well-motivated and the implementation appears thorough, with careful attention to edge cases. The test coverage is particularly robust, verifying both the happy path and various scenarios where the optimization should not apply. This should make `--amend` more predictable in scripts and automated workflows while maintaining all existing behavior for substantive changes.
