Thread identity: Proposal to add `GIT_CLONE_DEPTH` environment variable as fallback for `--depth` in `git clone`, authored by Hadrien Loge. This is a feature patch targeting packaging workflows.

Core problem: When performing nested clone operations in packaging scripts (e.g. PKGBUILD, APKBUILD), the `--depth` setting from the outer clone is lost in inner clones called by scripts. Environment variables would propagate naturally through these nested invocations, enabling consistent shallow cloning.

Key technical details: The patch adds support for `GIT_CLONE_DEPTH` env var that mirrors the `--depth` option's behavior. The variable name follows Git convention (prefixing with `GIT_`). Implementation touches `builtin/clone.c` to check the env var when `--depth` is unspecified. Includes tests in `t/t5601-clone.sh` verifying the new behavior.

Current status: Initial version proposed with tests and documentation. Variable name was revised from `DEPTH` to `GIT_CLONE_DEPTH` based on naming conventions. brian m. carlson has raised substantive concerns about the design approach.

Open questions: Whether shallow clones are appropriate for packaging workflows given reproducibility concerns. Potential edge cases around variable precedence (env var vs command line) and interaction with other clone options. Broader ecosystem impacts including: (1) scripts breaking when assuming full history (e.g. `git describe`), (2) server load from shallow fetches leading to throttling. Philosophical question about whether environment variables should influence Git's cloning behavior.

Participant positions: Hadrien Loge as author proposing the change. brian m. carlson opposes the design direction, arguing it could introduce hard-to-diagnose failures and that packaging workflows should handle source acquisition explicitly rather than through implicit environment variables. The review engages with system-level impacts rather than implementation details.

Related work: The discussion touches on broader questions about shallow clone usage patterns and Git's behavior in automated build systems. No specific prior art or dependencies referenced yet.
