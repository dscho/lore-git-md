This thread discusses a proposed change to make `git commit --amend --no-edit` avoid creating new commit objects when nothing substantive changes (tree, message, author info). The original patch series from Harald Nordgren implemented this optimization with thorough test coverage, but raised concerns from reviewers.

Johannes Sixt questioned whether suppressing commit creation aligns with Git's conceptual model, noting edge cases around message editing and signature handling. Ben Knoble pointed out that the current behavior of always creating new commits serves legitimate workflow needs - particularly for forcing CI re-runs via timestamp changes.

The discussion took a decisive turn when maintainer Junio Hamano weighed in, rejecting the change outright. Junio explained that the current behavior is intentional, serving important merge/revert scenarios where forcing new commit objects is necessary. He suggested that if such an optimization were desired, it would need to be introduced gradually through an optional flag first, with potential default changes only at major version boundaries.

Given Junio's authoritative position as maintainer and the clear workflow impacts identified, this approach appears unlikely to proceed in its current form. The thread demonstrates how even well-intentioned optimizations must consider Git's established workflows and the maintainer's deep understanding of edge cases across the entire system.
