This is the first patch in a 2-part series to improve `git commit --amend` behavior. It's a preparatory refactoring that extracts a helper function `commit_index_files_or_die()` from existing code in `builtin/commit.c`.

The change is purely mechanical - it takes the error handling code for committing index files and wraps it in a reusable function. This sets up for the second patch which will use this helper when implementing the actual behavior change (preserving commit hashes in no-op amend cases).

The patch is straightforward and well-contained, with no functional changes. It follows Git's typical pattern of separating refactoring from behavior changes into distinct commits. The commit message clearly states this is preparatory work for the subsequent patch in the series.
