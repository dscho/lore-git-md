This is the second patch in a 2-part RFC documentation series from Weijie Yuan, proposing updates to contributor guidelines about patch review etiquette. The patch focuses on establishing best practices around reroll timing.

The changes add concrete advice to both `MyFirstContribution.adoc` and `SubmittingPatches` about when to send new patch versions. It suggests a default of no more than one reroll per day to allow for batching feedback and giving reviewers time to respond. The documentation acknowledges this is flexible based on factors like series size, review depth, and how close the topic is to being merged.

The patch demonstrates the approach it advocates by clearly explaining the motivation for each change. It builds on Patrick Steinhardt's prior advice about reroll cadence while making the guidance more accessible to new contributors. The changes appear well-considered and address a real-world pain point in the review process.

This RFC is still seeking feedback on the exact phrasing and whether additional factors should be considered in the reroll timing guidance. The patch maintains the thread's focus on improving documentation around review workflow efficiency.
