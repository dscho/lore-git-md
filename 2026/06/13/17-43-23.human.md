This is a feature proposal to add a `GIT_CLONE_DEPTH` environment variable as a fallback for the `--depth` option in `git clone`. The author, Hadrien Loge, argues this would be particularly useful for packaging workflows (like Arch's PKGBUILD or Alpine's APKBUILD) where nested clone operations lose the depth setting from the parent command.

The key motivation is that environment variables propagate naturally through nested scripts and CI environments, whereas command-line `--depth` does not. The author provides a concrete example where a shallow clone followed by a script that performs its own clones would lose the depth setting without this change. They note the space savings can be significant (900KB vs 17MB for a 5k-commit history).

The patch has been revised to include tests and documentation, and the proposed variable name was changed to `GIT_CLONE_DEPTH` (presumably from an earlier `DEPTH` based on the subject line). This appears to be a well-motivated change targeting a specific pain point in packaging workflows, with attention given to testing and naming consistency with Git's existing environment variables.
