This is a follow-up in the ongoing discussion about Rust compatibility in Git builds, specifically regarding NonStop platform support. Randall S. Becker confirms that using the `NO_RUST=yes` make flag successfully works around the build failure on NonStop systems where Rust tooling is unavailable. 

The exchange highlights the practical reality that while Rust components are currently optional (with this escape hatch), the project's stated direction is to make Rust mandatory in Git 3.0. Randall's successful workaround provides a temporary solution for NonStop users, but doesn't resolve the longer-term compatibility question - particularly given his previous indications that Rust may not be available on NonStop before 2027. 

The thread continues to show the tension between Git's Rust roadmap and platform support constraints, with this email demonstrating that the immediate technical solution works while leaving the strategic alignment question open. For NonStop users, this means they can build Git 2.55, but their ability to use future versions remains uncertain.
