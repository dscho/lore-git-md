Feature patch adding environment variable support for shallow clones.

This patch teaches `git clone` to accept a `DEPTH` environment variable as a fallback when the `--depth` option isn't specified on the command line. The motivation is to enable shallow clones in situations where users can't directly control the clone command (like CI runners or build scripts), since environment variables propagate to child processes.

The implementation is straightforward - it checks for the `DEPTH` env var only when `--depth` isn't provided, with command-line arguments taking precedence. The patch includes the same validation as the existing `--depth` option. This could be particularly useful for CI pipelines where you'd want all nested clones to be shallow by default.

The change is minimal (6 lines added) and focused on `builtin/clone.c`. The commit message clearly explains the use case and behavior, though it might benefit from mentioning any security considerations (environment variables are generally less secure than direct command-line arguments). This appears ready for review, with the main discussion point likely being whether this is the right approach versus other configuration mechanisms.
