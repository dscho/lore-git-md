**Test infrastructure fix**: This patch corrects a line-counting bug in the shared shell parser library (lib-shell-parser.pl) that affects multi-line command substitutions (`$()`) within double-quoted strings. The issue caused newlines to be double-counted when they appeared in command output, which could impact tools that rely on accurate line numbers for diagnostics.

The fix modifies the `scan_dqstring` function to count newlines incrementally as they're encountered in the input, rather than doing a final count at the end. This ensures each newline is counted exactly once, whether it appears literally in the string, as a line splice (backslash-newline), or within a command substitution. The change is subtle but important for maintaining parser accuracy - particularly relevant as this library is now shared between chainlint.pl and the new greplint.pl tool.

Notably, this was a latent bug that didn't affect chainlint's operation since it uses byte offsets rather than line numbers, but fixing it improves the robustness of the shared infrastructure. The patch demonstrates careful attention to edge cases in shell syntax parsing while maintaining the existing behavior for all valid inputs.
