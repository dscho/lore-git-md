This is a test infrastructure patch series that converts bare 'grep' assertions to 'test_grep' in Git's test suite. The series is now in its second version (v2) and has evolved based on maintainer feedback.

The key changes in v2:
- Dropped the original lint-style.pl approach in favor of a new greplint.pl tool that more closely follows chainlint's conventions
- Reused chainlint's shell parser via a shared module (lib-shell-parser.pl)
- Fixed a line-counting bug in the shell lexer that affected multi-line command substitutions
- Converted ~2800 grep assertions across ~340 test files
- Added annotations for intentional grep usage that can't be converted (e.g. when files may not exist)

The series addresses a real problem - bare grep assertions fail without showing the file contents, making test failures harder to debug. test_grep provides better diagnostics by showing the file contents on failure.

However, the approach has drawn substantive technical objections from maintainer Junio Hamano, who prefers:
- Adding checks to test-lint framework rather than a new tool
- Distinguishing assertion grep from implementation grep
- Avoiding automatic file modifications

The series appears well-implemented but may need restructuring to align with the maintainer's preferred approach. The test bug fixes (10 cases found during development) remain valuable regardless of the final linting mechanism.

This is part of ongoing test infrastructure improvements, building on chainlint.pl's shell parsing capabilities. The conversion was mechanical but careful, preserving test semantics while improving debuggability.
