This is a technical bugfix in the shell parser infrastructure that was extracted from chainlint.pl to support the greplint tool. The patch fixes a subtle line-counting issue in the parser's handling multi-line command substitutions (`$()`) inside double-quoted strings.

The core issue is that newlines were being double-counted when they appeared in command substitutions within quoted strings - once during the recursive parse of the `$()` body, and again when scanning the overall string. The fix changes the counting to happen inline as characters are consumed, ensuring each newline is counted exactly once.

While this is a standalone fix, it's part of the larger greplint effort to standardize test assertions. The parser infrastructure is being made more robust to support both chainlint and the new greplint tool. The author notes this was a latent bug that didn't affect chainlint's operation since it uses byte offsets rather than line numbers, but fixing it makes the parser more correct for other potential uses.

The change is small (6 lines added, 3 removed) and focused, with a clear explanation of both the problem and solution. It demonstrates the value of the parser refactoring work by catching and fixing an edge case that could affect future tooling.
