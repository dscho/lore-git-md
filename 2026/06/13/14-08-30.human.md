This is the first patch in a two-part RFC documentation series from Weijie Yuan, proposing updates to contributor guidelines around patch review etiquette. The patch focuses on improving guidance about responding to review feedback before sending new patch versions.

The changes emphasize that contributors should discuss review comments in the mailing list thread *before* preparing a new version, rather than using the rerolled patches as their only response. The updates appear in both `MyFirstContribution.adoc` (the new contributor guide) and `SubmittingPatches` (the canonical process document).

Key improvements include:
- Making explicit that reviewers should see the author's reasoning in-thread before a reroll
- Encouraging authors to state whether they'll accept, reject, or modify suggestions
- Adding rationale about saving time by getting alignment before preparing new versions

The patch appears well-motivated by common mailing list patterns where new contributors sometimes reroll without discussion. The changes are focused and clearly explained, though as an RFC, the exact phrasing may evolve based on feedback. This would be particularly useful guidance for new contributors learning the project's review culture.
