This is the fifth version of Pablo Sabater's feature patch series improving `git log --graph` visualization by indenting visual root commits. The series addresses the longstanding issue where commits with excluded parents could appear misleadingly aligned in the graph output.

The key change in v5 is fixing a test failure from v4 by unsetting COMMIT_GRAPH in the test setup. The core approach remains the same as v4: using cascading indentation for visual roots (starting from the second root) to create clearer hierarchy while maintaining parent-child relationships. The implementation handles multiple visual roots and includes extensive test coverage.

One known limitation remains regarding the lookahead mechanism in revision.c, which can't perfectly predict when a commit will become a visual root after history simplification. The author has documented this edge case with a NEEDSWORK comment but notes unfamiliarity with that part of the codebase.

The series consists of two cleanly separated patches:
1. Moving a test helper function to a shared location
2. Implementing the visual root indentation logic

The changes appear well-considered and the author has been responsive to feedback through multiple iterations. With the test fix in v5, this seems ready for final review, pending resolution of the lookahead edge case and any remaining documentation questions from Junio's earlier review. The visualization improvements should make complex commit graphs significantly more readable.
