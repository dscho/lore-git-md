This is a substantive review of Harald Nordgren's patch series about no-op commit amends. Johannes Sixt raises several thoughtful technical questions about the proposed behavior change:

1. He questions the special treatment of `--no-edit`, suggesting the same logic should apply if the message is manually edited but unchanged.

2. Challenges the fundamental premise, arguing that since `git commit` is explicitly a request to create a new commit, not doing so could be considered a failure case rather than a feature.

3. Asks about the ref update mechanics - whether the branch pointer is actually moved (creating a reflog entry) or left unchanged.

4. Questions the signature handling rationale, noting that if nothing changes, the existing signature should remain valid rather than being rewritten.

The review digs into edge cases the original series may not have fully considered, particularly around the interaction between the no-op optimization and Git's normal commit creation workflow. Johannes seems skeptical that suppressing commit creation is the right approach, suggesting it might violate user expectations about what `git commit` does.

This moves the discussion beyond implementation details to consider the conceptual model of what constitutes a "successful" commit operation. The signature question in particular highlights a potential inconsistency in the current patch's logic.
