This RFC thread documents an effort to improve Git's contributor guidelines around patch review etiquette, specifically addressing when to reroll patches and how to handle feedback. The series, proposed by Weijie Yuan, initially targeted two files (`SubmittingPatches` and `MyFirstContribution.adoc`) but has now narrowed focus to the core `SubmittingPatches` changes after Patrick Steinhardt identified redundancy in the other file.

Junio C Hamano provided philosophical grounding for the changes, emphasizing the importance of substantive discussion before rerolling and considering global timezone differences in review cycles. Patrick Steinhardt offered detailed technical review, approving the `SubmittingPatches` modifications while suggesting structural improvements. The thread has become a model of the practices it seeks to document, with Yuan demonstrating proper attribution by using "Helped-by" trailers (even joking about directly reusing Patrick's wording).

With strong consensus on the `SubmittingPatches` changes and the author responsive to feedback, this RFC appears ready to transition to a regular patch series. The exchange highlights Git's collaborative culture while providing concrete guidance for new contributors - exactly what the documentation updates aim to achieve.
