This is a bugfix patch series addressing an edge case in `git commit --amend`. Currently, even when no changes are made (using `--no-edit`), the command still creates a new commit with an updated timestamp, changing the commit hash unnecessarily. The series proposes preserving the original commit when nothing substantive changes.

The first patch is a refactoring that extracts a helper function for index file operations. The second implements the core change - when amending with no actual modifications (same tree, message, author, etc.), it reuses the original committer date to maintain the same commit hash. The series includes thorough test coverage in t7501.

The change seems well-motivated - it prevents unnecessary commit hash churn in a common workflow scenario while maintaining all existing behavior when actual changes are made. The implementation appears clean, splitting the refactoring from the functional change, and the tests verify both the new no-op case and all existing amend behaviors.
