**Feature patch adding GIT_CLONE_DEPTH environment variable for shallow clones**

This is a follow-up to the initial proposal for environment-based shallow clone configuration, now addressing naming and memory management concerns. The thread starter (Matt Hunter) suggests two improvements:

1. Renaming the variable from `DEPTH` to `GIT_CLONE_DEPTH` to match Git's convention of prefixing environment variables with `GIT_`. This would maintain consistency with existing variables like `GIT_TRACE` and `GIT_CONFIG`.

2. Fixing a memory leak where `xstrdup()` allocates a new string for the depth value but never frees it. While clone operations typically exit soon after completion, the oversight is notable given explicit cleanup elsewhere in `cmd_clone()`.

The review is substantive - it identifies both a design issue (naming convention) and a technical flaw (memory management), suggesting the reviewer examined the implementation details. No new functionality is proposed beyond fixing these issues in the original approach.

This continues the discussion of making shallow clones more flexible for automation scenarios where users can't directly control the clone command. The core use case remains valid, but the implementation needs refinement before merging. Documentation updates will still be needed to cover the final environment variable name.
