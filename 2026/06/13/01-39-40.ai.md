This is a feature patch proposing to add environment variable support for shallow clones. The patch teaches `git clone` to accept a `DEPTH` environment variable as a fallback when the `--depth` option isn't specified on the command line.

The motivation is to enable shallow clones in scenarios where users don't directly control the clone command, such as in CI runners or build scripts. Currently, shallow cloning can only be requested via the `--depth` command-line option, with no configuration or environment variable alternative. The change would allow setting `DEPTH=1` once to make all nested clones shallow.

The implementation is straightforward - it checks for the `DEPTH` environment variable if `--depth` wasn't provided, and applies the same validation. Command-line `--depth` still takes precedence. The patch touches only `builtin/clone.c`, adding 6 lines to read the environment variable.

This appears to be a well-motivated change that could be useful in automation scenarios. The patch is small and focused, though it might benefit from documentation updates (man pages) to advertise the new environment variable support. The commit message clearly explains the use case and implementation.
