This is a documentation patch series (2 parts) aimed at improving contributor guidelines around patch review etiquette. The RFC cover letter comes from Weijie Yuan, who is proposing updates to both `MyFirstContribution.adoc` and `SubmittingPatches` based on existing mailing list discussions.

The first patch addresses a common new contributor pitfall - sending new patch versions without first discussing review feedback in the thread. It emphasizes that substantive responses should happen in the email thread before rerolling patches, so reviewers can understand the author's reasoning.

The second patch incorporates advice from Patrick Steinhardt about reroll timing, suggesting contributors batch feedback rather than sending multiple versions in quick succession. It notes factors like series size and review depth that influence ideal reroll cadence.

The author acknowledges the wording may need refinement and seeks feedback on both content and attribution (particularly for Patrick's contribution). The patches touch core documentation files that shape contributor expectations, so getting the tone right matters. The changes appear well-motivated by actual mailing list discussions, though as an RFC, the exact phrasing may evolve based on review.
