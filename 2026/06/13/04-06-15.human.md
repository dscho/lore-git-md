**Test infrastructure improvement**: This is the final patch in a 6-part series introducing a new `greplint.pl` tool to detect and convert bare `grep` assertions to `test_grep` in Git's test suite. The series has evolved through maintainer feedback, with this version focusing on:

1. Adding the actual `greplint.pl` tool that detects bare `grep` assertions (where `test_grep` should be used) and incorrect negations (`! test_grep` vs `test_grep !`)
2. Wiring it into the test infrastructure via Makefile targets (`test-greplint`, `check-greplint`, `clean-greplint`)
3. Including comprehensive test fixtures demonstrating the linter's behavior across various shell constructs

The tool intelligently distinguishes between assertion greps (which should use `test_grep`) and filter greps (which can remain bare) by analyzing shell syntax via a shared parser library. It handles edge cases like command substitutions, pipelines, and heredocs, and allows intentional bare greps to be marked with `# lint-ok`.

While the series has demonstrated concrete value by finding 10 pre-existing test bugs, maintainer Junio Hamano has expressed reservations about automated conversion, preferring a diagnostic-only approach. The author has addressed feedback by:
- Dropping the original `--fix` mode concept
- Following `chainlint.pl` conventions more closely
- Better handling shell syntax edge cases

This represents a significant test infrastructure improvement that could prevent future test regressions, though its ultimate acceptance remains uncertain given the maintainer's position. The shared parser infrastructure also enables future lint rules beyond grep conversion.
