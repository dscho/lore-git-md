This is the final patch in Patrick Steinhardt's v2 series improving TAP output validation in Git's test infrastructure. The patch enforces strict TAP parsing when running tests with `prove`, which would have caught the invalid output issues fixed in earlier patches of the series.

The change adds a TAP pragma to make `prove` treat invalid TAP output as test failures, addressing a gap where such issues could slip through (as happened with the fsmonitor tests in t7527). While the TAP 14 standard formalized this behavior, the patch leverages an older unofficial extension that's been supported by `prove` since 2008, making it widely compatible.

The implementation is straightforward - adding two lines to `test-lib.sh` to emit the strict parsing pragma when tests run under `prove`. This provides immediate feedback when tests emit non-compliant output, preventing such issues from reaching CI systems (where they'd trigger Meson's ugly warnings) or being merged.

This patch completes the series' goal of both fixing existing TAP output problems and preventing future ones through stricter validation. All review feedback from v1 has been addressed, and the changes are well-contained to test infrastructure with no behavioral impact on Git itself. The series appears ready for merging.
