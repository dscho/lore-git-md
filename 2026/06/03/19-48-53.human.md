This is a naming suggestion for a new parse-options helper function in an ongoing thread. Jean-Noël Avila, the French translation maintainer and documentation contributor, provides feedback on the function name `die_for_required_opt()` introduced in the first patch of the series.

He argues the current name is misleading because:
1. It doesn't accurately reflect that the function dies when a *required* option is *missing* (not when it's present)
2. The parameter names don't clearly indicate the asymmetric nature of the check (it's not a mutual exclusion check)

Jean-Noël suggests renaming it to `die_for_missing_opt()` with more descriptive parameter names (`tested_opt` and `required_opt`) to better convey the function's behavior. His perspective as a documentation expert and translator makes this naming feedback particularly relevant, as unclear function names create challenges for both code maintainers and those localizing error messages.

The feedback is constructive and focused - it doesn't challenge the technical implementation but aims to improve the API's clarity before it becomes widely used. Given Jean-Noël's role in maintaining Git's documentation and translations, this input carries weight regarding naming consistency and localization considerations.
