This is a documentation patch series (v2) promoting the `b4` tool for Git mailing list workflows, now expanded to 3 parts. Patrick Steinhardt continues his effort to standardize on b4 for patch submission and review, with new focus on resolving the model threading conflict.

The series now leads with documentation changes before introducing configuration files. Key additions in v2:
1. A new patch recommending shallow threading (--no-chain-reply-to) in MyFirstContribution, aligning with b4's defaults
2. Explicit documentation about b4 configuration precedence (user Git config overrides project defaults)
3. Clarification that users can override .b4-config settings without dirtying their tree

The threading model change is framed as a discussion starter, recognizing this may be contentious since the current tutorial recommends deep threading (--chain-reply-to). The technical approach remains unchanged - adding .b4-config and .b4-cover-template files while updating contributor docs - but now better structured to introduce b4 basics first.

This iteration shows thoughtful response to prior feedback while advancing the core goal of making b4 the standard workflow tool. The shallow threading recommendation in particular represents a concrete step toward resolving the model threading conflict identified in earlier discussion. The changes appear well-considered and maintain the series' focus on improving contributor experience through documentation rather than code changes.
