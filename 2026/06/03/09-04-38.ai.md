This is patch 5/6 in Harald Nordgren's v12 series adding `git branch --prune-merged` functionality. The patch introduces a configurable opt-out mechanism for the new branch cleanup feature.

The key addition is a `branch.<name>.pruneMerged` configuration option that, when set to false, exempts the named branch from being deleted by `git branch --prune-merged`. This is designed for cases where a topic branch will see further development after an initial merge. The patch maintains all existing protections (checked-out branches, trunk branches, etc.) while adding this new opt-out capability.

Notable implementation details:
- The setting only affects `--prune-merged` - explicit `git branch -d` still performs the standard merge check
- When skipped due to the setting, branches are reported (unless `--quiet` is used)
- The change includes comprehensive documentation updates and tests verifying both the opt-out behavior and that `branch -d` remains unaffected
