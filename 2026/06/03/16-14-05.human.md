This is part 6 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch focuses on enhancing the `reset_head()` function to be more flexible for callers.

The change allows callers to explicitly specify the "from" commit when performing a reset operation, rather than always deriving it from HEAD. This is useful when the caller already has the commit OID or wants to reset from a different commit than HEAD. The patch adds a new `oid_from` field to `struct reset_head_opts` and updates the logic in `reset.c` to use it when provided.

This is a small but meaningful improvement to the reset machinery that enables more precise control over reset operations. The change is cleanly implemented with minimal code impact (just 5 lines added across two files). While motivated by the needs of the `git history drop` command, this enhancement could benefit other parts of Git that use `reset_head()`.

The patch follows Patrick's typical style - focused, well-explained, and with clear boundaries. It's part of the broader effort to modernize Git's reset machinery that we've seen across this series.
