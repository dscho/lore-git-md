This is a follow-up discussion in the b4 configuration thread, clarifying threading terminology for Git's mailing list workflow.

Tuomas Ahola confirms SZEDER Gábor's earlier clarification about Git's threading terminology, noting a terminology clash between Git's definitions and b4's implementation. The key points:

1. Git defines:
   - Shallow threading: all patches reply to the current cover letter
   - Deep threading: each email replies to the previous one
   This differs from b4's implementation where "shallow" refers to cover letter relationships.

2. The discussion reveals that Git's documentation (specifically MyFirstContribution.adoc) contains some potentially misleading references that could be interpreted as recommending deep threading, though the community agrees this is not the intended guidance.

3. There's consensus that Git's documentation should consistently recommend against deep threading due to its poor usability with nested discussions.

This email helps solidify the technical understanding that will inform the final documentation changes. The thread appears to be converging on standardizing around shallow threading as the recommended approach, with some minor documentation cleanups needed to remove any remaining deep-threading suggestions. The discussion remains technical and constructive, with participants working to align terminology across tools and documentation.
