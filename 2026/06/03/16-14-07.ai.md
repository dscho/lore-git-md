This is part 8 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch refactors reference update logic in preparation for future changes.

The change splits the existing `handle_reference_updates()` function into two distinct phases:
1. `compute_pending_ref_updates()` - Gathers all references that need updating based on the rewrite operation
2. `apply_pending_ref_updates()` - Actually performs the reference transaction updates

This separation enables future work where these operations may need to be performed independently. The patch maintains all existing functionality while making the code more modular. Key technical points:

- The split preserves the same error handling and memory management patterns
- Reference updates are now stored in the `replay_result` struct between phases
- The dry-run mode continues to work as before, skipping the transaction commit
- All callers continue using the original `handle_reference_updates()` interface

This appears to be a clean refactoring that doesn't change behavior but improves the architecture in preparation for subsequent patches. The changes are focused and well-contained to the history command's reference update logic.
