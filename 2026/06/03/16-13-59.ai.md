This is version 2 of Patrick Steinhardt's patch series introducing a "drop" subcommand to the experimental `git history` command. The series builds on previous work adding the "replay" subcommand (commit 1666c12652).

The key changes in v2 focus on refactoring the worktree update logic to reuse the existing `reset_head()` function rather than implementing custom unpack-trees logic. This required significant changes to `reset_head()` itself (patches 1-7), including:
- Adding dry-run mode support
- Allowing skipped ref updates
- Removing assumptions about index cleanliness
- Modernizing the flags interface

The actual "drop" functionality (patches 8-9) remains conceptually the same - it removes a commit from history and replays descendants on top of its parent. The implementation now splits ref updates into prepare/commit phases and uses the enhanced `reset_head()` for worktree updates.

The series includes thorough test coverage (513 lines across 4 new test scripts) and addresses all review feedback from v1, including:
- Consistent error message formatting
- Removal of redundant test helper flags
- Better commit context in error messages

This appears to be a well-executed iteration, with Patrick's characteristic attention to detail and incremental approach. The changes to `reset_head()` have broader implications beyond just the history command, potentially benefiting other parts of Git that need similar reset functionality. The series touches multiple subsystems (reset machinery, ref handling, worktree updates) while maintaining a clear focus on the history command's needs.
