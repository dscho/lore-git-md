This is part 4 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch introduces a dry-run mode to `reset_head()`, which will be used by the upcoming drop functionality to test whether a reset operation would succeed without actually modifying the working tree or index.

The implementation creates a scratch index for dry-run operations to avoid polluting the real index, and adds a new `RESET_HEAD_DRY_RUN` flag to control this behavior. The changes are focused on the patch follows Git's established patterns for similar dry-run functionality elsewhere in the codebase.

This is a well-contained preparatory change that cleanly extends the reset machinery while maintaining the existing behavior for normal operations. The patch touches core reset functionality but does so in a way that's clearly motivated by the needs of the history command series. The implementation appears robust, with proper cleanup of temporary state and clear separation between dry-run and actual execution paths.
