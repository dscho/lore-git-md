This is patch 5/6 in Harald Nordgren's final v12 adding `git branch --prune-merged` functionality, introducing a configurable opt-out mechanism for the new feature.

The patch adds `branch.<name>.pruneMerged` configuration to exempt specific branches from automatic pruning, addressing a use case where developers want to keep working on a topic branch after its initial changes have been merged upstream. The setting defaults to true (allowing pruning) but can be set to false to preserve branches. Importantly, this only affects the new `--prune-merged` operation - traditional `git branch -d` deletion still follows the standard merge check behavior.

The implementation includes:
- Documentation updates explaining the new config option
- Logic in the pruning function to check the setting and skip branches accordingly
- A non-quiet mode that reports skipped branches to inform users
- Tests verifying both the opt-out behavior and that `branch -d` remains unaffected

This comes as part of a mature series that has undergone 12 iterations with all major technical concerns addressed. The safety-focused design maintains all previous protections (checked-out branch detection, push/upstream comparison) while adding this new flexibility.
