This is the second patch in a 3-part documentation series promoting the `b4` tool for Git mailing list workflows (v2). Patrick Steinhardt continues his effort to standardize contributor workflow around b4, now focusing on updating the "MyFirstContribution" tutorial to explicitly recommend its use.

The patch adds a new section to the tutorial explaining b4's workflow in detail, positioned as the third recommended method alongside GitGitGadget and raw git-send-email. It covers:
- Initial setup with `b4 prep`
- Cover letter management
- Dry-run and actual sending with `b4 send`
- Version iteration workflow
- Configuration options via git-config and project-specific `.b4-config`

The documentation presents b4 as the recommended approach for mail-based contributions, emphasizing its automation of tedious bookkeeping tasks like recipient tracking and range-diff generation. A corresponding update to SubmittingPatches reinforces this recommendation.

This is a straightforward documentation improvement that formalizes an existing community practice. The patch is well-structured and clearly explains the tool's benefits without deprecating the other methods. As part of the larger threading model alignment effort (where v2's first patch proposed changing the tutorial to prefer b4's shallow threading), this provides the concrete how-to guidance that makes the recommendation actionable.
