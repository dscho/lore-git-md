This is the third and final patch in Patrick Steinhardt's v2 series standardizing Git contributor workflow around the `b4` tool. It introduces project-wide b4 configuration files to align with the documentation changes proposed in the first two patches.

The patch adds two new files:
1. `.b4-config` sets defaults for the mailing list workflow, specifically:
   - Using shallow threading (replies to cover letter rather than previous patch)
   - Specifying a custom cover letter template
2. `.b4-cover-template` provides that template, which adds a range-diff section to help reviewers track changes between versions

The configuration is designed to be overrideable via Git config without modifying these files, preserving flexibility for individual contributors. This addresses earlier discussion about whether to use direct config files (as implemented here) versus sample files (as Junio had suggested).

As the technical complement to the documentation updates in patches 1-2, this completes the series' goal of formalizing b4 usage while resolving the threading model discrepancy. The changes are straightforward and unlikely to be controversial, though the pedagogical positioning of b4 (basic vs advanced tool) may still need final discussion.
