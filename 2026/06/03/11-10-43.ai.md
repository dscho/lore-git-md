This is the first patch in a 2-part series introducing a new parse-options helper function for validating option dependencies. The patch adds `die_for_required_opt()` to handle cases where one option requires another (e.g. "option X requires option Y").

The implementation follows the pattern of existing mutual-exclusion helpers in parse-options.c, providing a simple API that checks if the first option is set without its required counterpart. When this occurs, it dies with a standardized error message showing both option names. The function signature matches the style of similar helpers like `die_for_incompatible_opt{2,3,4}()`.

The change is cleanly scoped - just 7 lines of implementation code plus 3 lines for the header declaration. The error message is marked for translation with `_()`, consistent with Git's localization approach. The patch comes with a Suggested-by credit to Christian Couder, indicating prior discussion of the concept.

This appears to be a well-formed utility function that could see use across multiple commands.
