This is part 7 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch modifies `reset_head()` to stop assuming the caller always provides a clean index, which is necessary for the new drop functionality.

The change removes an optimization from commit 652bd0211d that skipped cache tree updates during resets, since that optimization relied on the index being clean - an assumption that won't hold for the history command's use case. The patch now only skips cache tree updates for hard resets, where we know the index will be clean afterward.

This is a focused technical change that:
- Touches only `reset.c`
- Preserves existing behavior for current callers (rebase/sequencer)
- Enables the new history drop functionality to work with dirty indexes
- Maintains the performance optimization where safe (hard resets)

The change is well-motivated in the commit message, which explains both the original optimization and why it needs to be made conditional. The implementation is straightforward - just moving the skip flag inside the hard-reset conditional block. This appears to be a solid incremental improvement to the reset machinery that enables the broader history command work while maintaining existing behavior.
