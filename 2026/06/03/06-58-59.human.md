This is the first patch in a 3-part documentation series promoting the `b4` tool for Git mailing list workflows, now at version 2. The patch proposes changing Git's "MyFirstContribution" tutorial to recommend shallow threading (--no-chain-reply-to) when using b4, rather than the current deep threading recommendation.

The change addresses a practical issue where deep threading (each new version replying to the previous one) creates overly nested threads that become hard to follow. The new recommendation would have all versions of a patch series reply to the original cover letter (v1), keeping the thread flatter and more readable. This aligns with b4's default behavior while still maintaining thread continuity.

The patch is straightforward - it modifies two lines in the tutorial document to update the threading recommendation. As part of a larger effort to standardize on b4 workflows, this change helps resolve an inconsistency between the tool's defaults and Git's documentation. The modification is non-controversial but serves as a concrete starting point for discussion about threading model alignment.

This continues Patrick Steinhardt's effort to improve contributor experience by formalizing b4 usage while addressing feedback from the v1 review cycle. The change shows thoughtful iteration on the series while maintaining its core goal of making the patch submission process more accessible.
