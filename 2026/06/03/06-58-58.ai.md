This is a documentation patch series (v2) promoting the `b4` tool for Git mailing list workflows, now expanded to 3 parts. Patrick Steinhardt continues his effort to standardize on b4 for patch submission and review, addressing feedback from the v1 review.

The key change in v2 is the addition of a new first patch that proposes modifying `MyFirstContribution.adoc` to recommend shallow threading (--no-chain-reply-to) when using b4. This aims to resolve the threading model conflict between b4's default behavior (shallow) and Git's current tutorial recommendation (deep threading). The patch serves as a discussion starter for aligning the project's preferred threading style with b4's defaults.

The series maintains the original technical proposals while improving the pedagogical flow:
1. Documentation now introduces b4 basics first before covering advanced configuration
2. Explicitly notes that users can override defaults via git-config without modifying project files
3. Fixes a typo from v1 and improves the commit message to clarify configuration override mechanics

The configuration approach remains under discussion between direct `.b4-config` files (Patrick's preference) and sample variants (Junio's earlier suggestion). The threading terminology debate now has a concrete proposal via the tutorial modification, though community consensus is still needed.

As a documentation update that formalizes an existing community practice while improving new contributor guidance, this remains a non-controversial quality-of-life improvement. The v2 changes show thoughtful iteration based on-list feedback while keeping the core value proposition intact.
