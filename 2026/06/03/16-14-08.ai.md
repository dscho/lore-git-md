This is the final patch (9/9) in Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The series builds on previous work adding the "replay" subcommand (commit 1666c12652).

The patch implements the core "drop" functionality which removes a commit from history and replays its descendants on top of its parent. Key aspects include:
- Reuses the enhanced `reset_head()` function from earlier patches for worktree updates
- Adds thorough test coverage (513 lines across 4 new test scripts)
- Handles various edge cases like root/merge commits and empty descendants
- Preserves unrelated local changes while aborting if changes would be overwritten
- Supports dry-run mode and selective ref updates (branches/HEAD)

The implementation builds on the refactored reset machinery from earlier patches in the series, using the new `RESET_HEAD_DRY_RUN` and `RESET_HEAD_SKIP_REF_UPDATES` flags. It splits reference updates into prepare/commit phases and handles dirty indexes safely.

Notable limitations:
- Cannot drop root commits (may be relaxed later)
- Cannot drop merge commits (inherited from replay limitations)
- Requires clean worktree when HEAD would move

The patch appears well-constructed with comprehensive tests covering the main scenarios. It follows Patrick's characteristic thorough approach, with some technical debt noted (root/merge commit limitations) for future work. The changes to `reset_head()` have broader implications beyond just this command.
