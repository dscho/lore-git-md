This is a follow-up discussion in the ongoing thread about Windows path handling in `git ls-files` tests. Junio C Hamano responds to Kristofer Karlsson's explanation about the backslash pattern issue being a long-standing limitation (dating back to 2018) rather than a recent regression.

Junio acknowledges the practical need for skipping these tests on Windows to maintain clean CI results, though he expresses concern about effectively declaring backslash pattern matching as permanently broken on Windows. He notes this could make wildmatch functionality less useful on the platform. However, he recognizes that the BSLASHPSPEC prerequisite provides a clear marker for future contributors to address the underlying issue if they choose to.

The exchange highlights the balance between immediate CI stability and proper architectural solutions - while the test-skipping approach is being accepted as a pragmatic short-term fix, it leaves open the question of whether Windows pathspec handling needs deeper changes to properly support backslash patterns. Junio's response suggests he's willing to queue the patch while keeping the door open for future improvements to the core path handling behavior.
