This is the second patch in a two-part series introducing a new helper function for validating required dependencies between command-line options. The patch demonstrates the practical application of the new `die_for_required_opt()` function by converting manual option checks in `builtin/add.c`.

The changes replace explicit conditional blocks that checked for two option dependencies:
1. `--ignore-missing` requiring `--dry-run`
2. `--pathspec-file-nul` requiring `--pathspec-from-file`

The conversion removes 4 lines of manual checking while maintaining identical behavior, just with more standardized error messages. The patch shows the helper being used in two slightly different contexts - one where the check happens before other option processing, and another where it was previously embedded in an if-else chain.

This appears to be a clean, mechanical conversion that serves as a good proof-of-concept for the new helper function introduced in the first patch. The changes are minimal and focused, exactly matching the scope described in the cover letter. The patch demonstrates how the helper can simplify option validation logic while making error messages more consistent - one of the key motivations for this series.
