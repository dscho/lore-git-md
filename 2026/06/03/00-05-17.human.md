Performance optimization for index-pack's delta resolution.

This v3 patch from Arijit Banerjee refines the delta base caching strategy in index-pack based on Jeff King's review feedback. The core optimization remains the same - preventing premature freeing of delta base objects needed for child resolution - but now with more precise control over when cached data is released.

The key change from v2 is tracking whether a base object still has direct children pending resolution, only freeing the cached bytes when both conditions are met: no threads are actively using the base (retain_data=0) AND all direct children have been processed. This maintains the existing subtree bookkeeping while avoiding unnecessary reconstruction of bases that will be needed again.

Benchmark results show consistent 12-15% speedups across major repositories (linux.git, git.git, libgit2, redis) with minimal memory overhead (1.9% RSS increase at worst case). The patch includes comprehensive performance data from both isolated index-pack tests (p5302) and end-to-end clone operations.

The implementation remains focused and low-risk, working within the existing cache infrastructure. All tests pass, including leak checking under SANITIZE=leak. This appears ready for merging, having addressed all substantive review feedback while demonstrating clear performance benefits for large repositories.
