This is the second patch in a 4-part series addressing TAP output validation issues in Git's test infrastructure. The patch specifically targets Windows test cleanup where EBUSY errors from `rm -rf` can corrupt TAP output when processes (like the fsmonitor daemon in Scalar tests) aren't properly terminated.

The change is straightforward: it silences stderr from the cleanup commands by redirecting to /dev/null, while maintaining the existing retry behavior and final error reporting. This prevents EBUSY messages from breaking the TAP format while still failing the test if cleanup ultimately doesn't succeed.

The patch acknowledges the root cause (leaked processes) but takes a pragmatic approach of suppressing the symptoms rather than fixing all potential process leaks, which would be more invasive. This matches the series' theme of mechanical test infrastructure improvements rather than behavioral changes.

As part of the v2 series, this patch has already incorporated feedback from the initial review round and appears ready for merging. It cleanly solves a specific Windows test issue that was allowing invalid TAP output to slip through.
