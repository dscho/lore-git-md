HTTP authentication fix with architectural considerations. Aaron Plattner responds to Junio Hamano's review of the WWW-Authenticate header preservation patch, agreeing with the technical assessment while considering broader design implications.

The discussion centers on preserving authentication headers during HTTP redirects, where the current implementation safely but inefficiently copies header strings to maintain them across credential updates. Both parties acknowledge the patch works correctly for the immediate use case but recognize deeper structural questions about credential handling.

Key points in this response:
- Confirms the string copying overhead is negligible compared to typical Git operations
- Reveals unsuccessful attempts to avoid clearing headers via credential_clear()
- Suggests WWW-Authenticate headers may belong in a separate HTTP-specific structure rather than the credential struct
- Agrees to consider Junio's proposed credential_update_url() approach for better encapsulation

The exchange highlights an ongoing tension between immediate fixes and long-term architectural health, with both technical and maintainability concerns in play. While the current solution is functionally adequate, the thread suggests future work may restructure how authentication state flows through the HTTP and credential subsystems.
