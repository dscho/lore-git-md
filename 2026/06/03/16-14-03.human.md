This is part 4 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch introduces a dry-run mode to the `reset_head()` function, which will be used by the history command to check if a reset operation would succeed before actually performing it.

The changes:
- Adds a new `RESET_HEAD_DRY_RUN` flag to control dry-run behavior
- Modifies `reset_head()` to skip index updates and ref changes when in dry-run mode
- Uses a scratch index for dry-run operations to avoid modifying the real index
- Maintains all existing functionality while adding the new capability

This appears to be a well-considered change that cleanly extends the reset machinery's capabilities. The implementation carefully handles edge cases like unmerged states while keeping the dry-run operation isolated from actual repository modifications. The patch is focused and follows Git's established patterns for similar dry-run functionality elsewhere in the codebase.

As part of the larger series, this change helps enable safer history modification operations by allowing the `git history drop` command to validate operations before executing them. The patch touches core reset functionality but does so in a way that maintains backward compatibility while adding the new feature.
