This is a test fix targeting the fsmonitor test suite. The patch addresses an issue where the TAP output from t7527 (builtin-fsmonitor tests) could be corrupted when verifying fsmonitor functionality.

The problem occurs because the verification check runs outside normal test infrastructure, allowing git-init output to interleave with TAP protocol output. Patrick Steinhardt fixes this by converting the verification into a lazy prerequisite (`FSMONITOR_WORKS`), which properly contains the output within the test framework.

The change is mechanical but important for test reliability - it ensures clean TAP output while maintaining the same filesystem compatibility check. This is part of Patrick's ongoing work on fsmonitor and test infrastructure improvements. The patch is small (7 lines changed) and focused, with no apparent controversy or need for deeper review.
