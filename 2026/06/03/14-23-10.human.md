This is a follow-up discussion on a Windows platform compatibility issue in `git ls-files` tests, where backslash patterns in pathspecs are incorrectly converted to forward slashes during parsing.

Junio Hamano expresses lingering concerns about the test-skipping approach, noting it's "a little disturbing" to effectively declare backslash patterns unusable on Windows. While acknowledging the practical need for stable CI results, he questions whether this represents a fundamental limitation of wildmatch on Windows or just an implementation gap that could be fixed.

Kristofer Karlsson's earlier response had established the issue dates back to 2018 (commit de8bada2bf), suggesting it's a long-standing quirk rather than a recent regression. The exchange reveals the tension between immediate CI stability (achieved through test skipping) and proper architectural solutions - while the current patch provides a practical fix, it leaves open whether Windows pathspec handling needs deeper changes to properly support backslash patterns.

Junio ultimately concludes that Windows contributors could remove the BSLASHPSPEC prerequisite if they implement proper backslash handling, making the test-skipping approach an acceptable stopgap. The thread remains open to future discussion about whether this represents a test limitation or a core platform compatibility constraint.
