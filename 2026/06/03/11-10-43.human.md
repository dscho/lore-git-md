This is the first patch in a 2-part series introducing a new parse-options helper function. The patch adds `die_for_required_opt()` to handle simple cases where one option requires another (e.g. "--foo requires --bar"). The implementation follows the pattern of existing mutual-exclusion helpers in parse-options.c, providing a standardized way to validate option dependencies.

The new function takes two option-value pairs as parameters and dies with a consistent error message if the first option is set without the second. This centralizes what would otherwise be duplicated validation code across commands. The error message format is designed to be translation-friendly, addressing one of the motivations mentioned in the cover letter.

The implementation is clean and minimal - just 7 lines of code plus header declaration. It fits naturally alongside similar helpers in the parse-options API. The patch includes a Suggested-by credit to Christian Couder, indicating this may have emerged from prior discussions about option validation patterns.

This appears to be a well-scoped foundation for the series. The simple initial API focuses on the most common case (single-option dependencies) while leaving room for future extension to more complex scenarios if needed. The next patch will demonstrate practical use by converting option checks in `builtin/add.c`.
