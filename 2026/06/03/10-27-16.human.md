This is a bugfix for `git rebase --update-refs` behavior when dealing with branch symrefs, addressing an edge case where symbolic references to branches cause rebase failures. The patch comes from Son Luong Ngoc as version 2 of the series, incorporating feedback from Phillip Wood's substantive review.

The issue occurs when local branches are symbolic references (like `main` pointing to `master` during a branch rename migration). Previously, `git rebase --update-refs` would fail during ref updates even after successfully rebasing the primary branch, because it didn't properly handle these symref decorations.

The fix modifies the sequencer to:
1. Skip branch symrefs that resolve to other branches (since those targets are already updated)
2. Preserve special handling for checked-out branches
3. Maintain existing behavior for symrefs pointing outside refs/heads/

The patch combines the test case and fix into a single commit (per project preference) and expands test coverage to verify both HEAD aliases and other branch symrefs. Phillip Wood's review identified several technical improvements that have been incorporated, though some open questions remain about full symref chain resolution and broader ref filtering consistency.

This is a focused, well-tested fix for a real edge case that affects branch rename workflows. The implementation appears solid, with careful attention to maintaining existing behavior while adding the new symref handling.
