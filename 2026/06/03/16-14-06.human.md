This is part 7 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch focuses on modifying `reset_head()` to handle cases where the index may be dirty before the reset operation.

The change removes an optimization from commit 652bd0211d that assumed callers would always pass a clean index, which was true for `rebase` and `sequencer` but won't hold for the new `git history drop` use case. The patch now only skips the cache tree update for hard resets, where we know the index will be clean afterward.

This is a focused technical change that maintains correctness while removing an assumption that no longer holds. The commit message clearly explains the rationale and connects it to the broader series. The diff itself is small (8 lines changed) but touches core reset machinery that multiple commands rely on.
