This is a cover letter for a 2-patch series introducing a new helper function for option dependency checking in Git's parse-options machinery.

The series aims to address code duplication and localization concerns by centralizing the common pattern where commands need to verify that certain options are present when others are used. Currently, this is done with ad-hoc conditional checks and duplicated error messages across commands.

The first patch adds a new `die_for_required_opt()` helper to the parse-options API that provides a standardized way to enforce option prerequisites. The second patch demonstrates its use by converting the manual checks in `builtin/add.c` for the `--ignore-missing` and `--pathspec-file-nul` options.

The motivation comes from discussions with Christian Couder about improving localization support (since centralized error messages are easier to translate) and reducing code duplication. The author suggests this could be extended to handle more complex multi-option dependencies if the initial approach is well-received.

The changes are relatively small and focused - just 13 lines added and 4 removed across 3 files. The series appears to be a clean, incremental improvement to the parse-options infrastructure with a clear demonstration of its utility in a real command.
