This is a cover letter for a 2-patch series introducing a new parse-options helper function. The series aims to reduce code duplication in option prerequisite checking across Git commands.

The core contribution is a new `die_for_required_opt()` function in parse-options.c that provides a standardized way to validate option dependencies (e.g. "option X requires option Y"). The first patch implements this helper, while the second demonstrates its use by converting manual checks in `builtin/add.c` for the `--ignore-missing` and `--pathspec-file-nul` options.

The motivation comes from discussions about localization and avoiding duplicated error messages. The current approach of manual checks leads to inconsistent error reporting and makes translation maintenance harder. The proposed helper centralizes this logic while providing consistent error messages.

The series appears well-scoped, starting with a simple implementation focused on single-option cases. The cover letter explicitly notes this could be extended later for more complex multi-option dependencies if the initial approach proves useful. The changes to `builtin/add.c` serve as a clean proof-of-concept, removing 4 lines of manual checking while maintaining the same behavior.

This looks like a solid quality-of-life improvement for the parse-options API that could enable future cleanups across other commands. The implementation appears straightforward and the motivation is well-explained in terms of both code hygiene and i18n benefits.
