This is the second patch in a 3-part documentation series promoting the `b4` tool for Git mailing list workflows. Patrick Steinhardt continues his effort to standardize contributor workflow around b4, now focusing on updating the "MyFirstContribution" tutorial to explicitly recommend its use.

The patch adds a comprehensive new section to the tutorial explaining how to use b4 for patch preparation and submission. It covers:
- Initial setup with `b4 prep`
- Editing cover letters and managing recipients
- Dry-run and actual patch sending
- Handling v2+ iterations with rebasing and version comparison
- Configuration options via git-config and project defaults

The documentation presents b4 as the recommended method for mail-based contributions, positioned between GitGitGadget (simpler but less control) and raw git-send-email (more manual). The patch also updates SubmittingPatches to note b4's advantages for bookkeeping automation.

This is a well-structured documentation addition that fills a gap in the contributor guide. The b4 recommendation aligns with Junio Hamano's earlier endorsement of the tool, and the tutorial integration should help new contributors adopt the more automated workflow. The patch maintains the series' focus on improving contributor experience while addressing the threading model alignment from v1 feedback.
