This is part 8 of Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch refactors reference update handling in preparation for future changes.

The change splits the `handle_reference_updates()` function into two distinct phases:
1. `compute_pending_ref_updates()` - identifies which refs need updating
2. `apply_pending_ref_updates()` - executes the actual ref updates

This separation allows for more flexible handling of reference updates in subsequent patches, particularly for the new dry-run functionality. The patch maintains all existing behavior while making the code more modular. It's a clean refactoring that follows the series' pattern of careful, incremental improvements to the history command's infrastructure.

The changes are mechanical but well-justified, continuing the series' high standard of implementation. This patch doesn't introduce new functionality but lays groundwork for the final patch in the series that will implement the actual drop operation.
