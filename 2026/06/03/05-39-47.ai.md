This is the final patch in Patrick Steinhardt's v2 series improving TAP output validation in Git's test infrastructure. The patch enforces strict TAP parsing by adding a `pragma +strict` directive when tests are run under prove, which will cause invalid TAP output to be treated as test failures.

The change addresses a long-standing issue where invalid TAP output could slip through unnoticed, as prove by default accepts non-compliant output while Meson (Git's alternative test runner) produces ugly warnings. The patch leverages a TAP 14 feature (backported to prove since 2008) that makes the parser strict about protocol violations. This would have caught the fsmonitor test issues fixed earlier in the series, where test numbers were being reused and non-TAP output was being mixed in.

The implementation is straightforward - it inserts the pragma directive in test-lib.sh when running under harness (prove). The patch completes the series' goal of making test output validation more rigorous while maintaining compatibility with existing test runners. All review feedback from v1 has been addressed, and the series appears ready for merging as it provides clear improvements to test reliability.
