This is the third and final patch in Patrick Steinhardt's v2 series standardizing Git contributor workflow around the `b4` tool for mailing list interactions. The patch introduces project-level b4 configuration files to align with Git's preferred practices.

The patch adds two new files:
1. `.b4-config` sets defaults for the project - specifically configuring shallow threading (reply-to-cover-letter) and specifying a custom cover letter template
2. `.b4-cover-template` provides that template, which notably includes a range-diff section not present in b4's default

The configuration is designed to be overridable via git-config without modifying the in-tree files, preserving flexibility for individual contributors. This addresses earlier discussion about whether to use direct configuration files (as implemented here) versus sample files (as Junio had suggested).

The patch maintains the series' focus on lowering barriers for new contributors while respecting existing workflows. It builds on the previous patches' threading model alignment and documentation updates, completing the technical implementation side of the b4 integration. The changes are straightforward and unlikely to be controversial, though the configuration file approach may still see discussion given Junio's earlier preference for samples.
