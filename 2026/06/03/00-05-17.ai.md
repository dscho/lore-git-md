Performance optimization for index-pack's delta resolution.

This v3 patch from Arijit Banerjee refines the delta base caching strategy in response to Jeff King's review of v2. The core optimization remains - preventing premature freeing of delta base objects needed for child resolution - but now adds precise tracking of when cached base data can be safely released. The key addition is `base_data_has_remaining_direct_children()` which checks if any direct children still need a base object before allowing its data to be freed.

The patch maintains the same performance benefits shown in v2 (13-16% speedups across major repositories) while addressing Peff's concern about potentially holding memory longer than necessary. The implementation now releases cached bytes as soon as both conditions are met: no thread is actively using the base for delta application (`!parent->retain_data`), and no direct children need it (`!base_data_has_remaining_direct_children(parent)`).

The commit message has been updated with fresh benchmark data showing consistent improvements, including end-to-end clone timings. All tests pass, including leak checking under SANITIZE=leak. This appears ready for merging as it has addressed all substantive review feedback while demonstrating clear performance wins with careful memory management.
