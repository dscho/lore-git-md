This is a bugfix patch (part 6 of 10) in Patrick Steinhardt’s refactoring series modernizing Git’s reference backend. It plugs a memory leak in `repository.c` where the main reference database (`repo->refs_private`) was never freed when clearing a repository, despite worktree and submodule reference databases being properly released. The leak was masked by the `chdir_notify` subsystem keeping the pointer alive.

The fix is straightforward: add a conditional block in `repo_clear()` to call `ref_store_release()` and free the main ref database if it exists. The change is minimal (five lines added) and follows the same pattern already used for submodule ref stores. This aligns with the series’ broader goal of improving lifecycle management in the ref backend, particularly around `chdir_notify` cleanup (addressed in patches 4–5).

The patch is uncontroversial and likely to be merged as-is. It’s a clear, well-motivated fix with no behavior changes—just proper resource cleanup. While the leak itself is minor (the memory would be reclaimed on process exit), plugging it is good hygiene and removes a latent issue that could complicate future refactoring. No test failures or edge cases are expected, as the fix mirrors existing code for submodule ref stores.
