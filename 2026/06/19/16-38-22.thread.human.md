This thread is a small but important follow-up to a recently merged refactoring that moved the `protect_hfs` and `protect_ntfs` settings from global variables into Git’s per-repository configuration struct (`repo_config_values`). The change is part of the broader effort to remove implicit dependencies on `the_repository` and advance Git’s libification. The original patch series (v4) was authored by Tian Yuchen and queued in Junio’s `next` branch, but Junio immediately spotted a minor inconsistency in the accessor functions: they used `repo->gitdir` as a guard, while other repository-scoped config accessors (like `repo_ignorecase()`) used `repo->initialized`.

This follow-up patch, also authored by Tian and already queued in `next`, replaces the `gitdir` guard with `initialized` for the new `repo_protect_hfs()` and `repo_protect_ntfs()` functions. The change is purely defensive—it prevents the functions from being called on uninitialized repositories, which could happen if repository setup is incomplete or the object isn’t a Git repository. The patch is mechanical, touching only four lines across two files (`environment.c` and `environment.h`), and doesn’t alter behavior or configuration semantics. Junio’s quick merge suggests it’s uncontroversial, though a separate, deferred cleanup (consolidating comments for the accessor functions) will happen after Git 2.55 final. The thread reflects the project’s attention to consistency in low-level patterns, even for small follow-ups.
