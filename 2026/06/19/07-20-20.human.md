This is a test suite fix. Patrick Steinhardt removes a no-op test in `t4216-log-bloom.sh` that was causing TAP output parsing to fail on systems where the `char` type is unsigned by default. The test infrastructure set up a prerequisite (`SIGNED_CHAR_BY_DEFAULT`) that guarded a test which did nothing (`true`), but the prerequisite check itself used `test_cmp()` outside of a test body, producing invalid TAP output. Since the prerequisite was unused elsewhere and the test provided no value, the patch simply drops the entire block.

The issue was introduced by a recent change (389c83025d) that made the TAP parser stricter, causing `t4216` to fail on affected systems. The fix is straightforward and well-motivated, with a clear commit message and a Reported-by credit to Todd Zullinger. No controversy or follow-up discussion is evident from the patch itself. If you care about test suite robustness or TAP compliance, this is worth noting.
