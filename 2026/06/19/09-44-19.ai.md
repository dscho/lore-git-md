This is the v3 iteration of Matt Hunter's 8-patch series introducing the global `fetch.followRemoteHEAD` configuration variable. The series is now merged-ready after addressing all substantive review feedback, including the final design question around configuration value validation.

The core implementation remains unchanged: a new global `fetch.followRemoteHEAD` setting acts as a fallback for all remotes when no remote-specific `remote.<name>.followRemoteHEAD` exists, following the established `fetch.prune`/`remote.*.prune` precedence pattern. The v3 changes focus on two key improvements: (1) configuration value validation now produces a warning (rather than silently ignoring) for unrecognized values, matching the per-remote behavior, and (2) a `NEEDSWORK` comment documents the opportunity to defer warnings until the value is actually consulted (e.g., avoiding warnings when the global setting is overridden by a remote-specific one).

Patch 5/8 is new in this version, fixing control flow in `git_fetch_config` to return early for known keys rather than falling through to `git_default_config`. This avoids unnecessary config parsing and aligns with Git's config-handling conventions. The main implementation (patch 7/8) now includes the warning for invalid values and the `NEEDSWORK` comment, while patch 8/8 corrects a minor comment alignment issue.

The series touches the fetch machinery (`builtin/fetch.c`), remote configuration handling, advice messages, and documentation. Test coverage in `t5510-fetch.sh` verifies feature parity, precedence rules, and edge cases. Junio C Hamano's acceptance of the warning-based validation approach ("this looks excellent") signals the series is ready for integration. The implementation is conservative, maintaining backward compatibility and excluding the "warn-if-not-$branch" value at the global level (as it’s inherently remote-specific).
