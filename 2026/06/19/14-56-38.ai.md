This is the core client-side implementation patch in the GSoC RFC v13 series that enables `git cat-file --batch-command` to query remote object metadata without full downloads. It adds the `fetch_object_info()` function in a new `fetch-object-info.c` file, which sends object-info requests to protocol v2 servers and parses the responses.

The patch introduces the plumbing needed for the feature: a new `object_info_args` struct to hold request parameters (object IDs, requested metadata fields, server options), protocol handling logic that validates server capabilities, and integration points in `transport.c` and `fetch-pack.c`. The implementation strictly requires protocol v2 and fails fast if the server doesn't advertise the object-info capability, maintaining the series' security hardening goals.

Key technical details include the dynamic capability validation (checking requested fields against server-advertised features), memory management for object size data (using `xcalloc` and `FREE_AND_NULL`), and numeric parsing with the new `strtoul_ul()` helper. The patch also extends the transport layer to support object-info operations, adding new fields to `git_transport_options` and modifying the fetch flow to handle object-info requests before regular fetches.

This is patch 9/12 in the series, building on earlier preparatory work (protocol command refactoring, utility functions, test infrastructure) and enabling the server-side capability advertisement added in patch 8/12. The implementation follows established patterns like buffering the entire request before sending (matching `send_fetch_request()`) and uses the generalized `write_command_and_capabilities()` function introduced earlier in the series.

The patch touches multiple subsystems (transport, fetch-pack, protocol v2) and introduces new files (`fetch-object-info.c/h`) and build system entries. It maintains backward compatibility while being forward-compatible for additional metadata fields beyond the current "size" support. All prior review feedback on type safety, memory management, and protocol handling appears to be addressed in this version.
