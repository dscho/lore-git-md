This is a build system cleanup patch that eliminates duplicate library warnings on macOS while preserving correct linker behavior. Harald Nordgren’s v2 patch redefines the `$(LIBS)` variable in the Makefile to explicitly list archive prerequisites first, then filter out those archives from the rest of the library list. This systematic approach removes the macOS linker warnings shown in Harald’s terminal output (repeated during rebase operations) without breaking the critical left-to-right linker ordering where object files must precede archives.

The patch modifies three link recipes—test helpers, fuzz programs, and unit tests—to rely on the new `$(LIBS)` definition rather than explicitly listing archives twice. This makes the solution more maintainable and less brittle than the v1 approach, which only removed duplicates at individual call sites. The commit message clearly explains the technical rationale and demonstrates Harald’s responsiveness to Junio Hamano’s review feedback.

This is a well-crafted fix that addresses both the cosmetic warning issue and the underlying technical constraints of linker behavior. The solution appears robust and unlikely to regress, making it a good candidate for merging. While primarily benefiting macOS developers, the cleanup improves the build system for everyone.
