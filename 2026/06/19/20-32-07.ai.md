This is a CI/build system patch, the final piece of Harald Nordgren’s macOS linker warning cleanup series. It implements the consensus solution reached in the thread: suppressing the "ignoring duplicate libraries" warning at the linker level rather than restructuring the Makefile.

The patch adds `-Wl,-no_warn_duplicate_libraries` to `BASIC_LDFLAGS` in `config.mak.uname`, but only for Xcode 15+ linkers (ld64-907 or newer, dyld-1009.5 or newer). It reuses the existing `LD_MAJOR_VERSION` probe infrastructure introduced for the `-fno-common` alignment fix, broadening the regex to match all three forms (ld, ld64, dyld) that Xcode 15 reports. The version gate ensures the flag is only passed to linkers that understand it, avoiding errors on older macOS versions.

This approach preserves the existing Makefile logic that sometimes intentionally lists the same archive twice to handle circular dependencies (e.g., libA.a → libB.a → libA.a), while eliminating the cosmetic warning. The patch is minimal, touching only `config.mak.uname`, and includes a clear commit message explaining the version-gating rationale and the floor values (907/1009.5) sourced from Meson’s linker compatibility table.

The v3 iteration abandons the v2 Makefile restructuring approach in favor of Junio’s linker flag proposal, reflecting the thread’s convergence. The patch is well-motivated, platform-specific, and unlikely to cause regressions given the version gate and the harmless nature of the warning. It sets a precedent for handling other platform-specific linker behaviors in Git’s build system, though the commit message does not speculate on future applications. Test coverage is implicit in the repeated test executions (e.g., rebase workflows) where the warnings previously accumulated.
