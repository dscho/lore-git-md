This is a bugfix patch (part 6/10 in Patrick Steinhardt's v4 ref backend refactoring series) that plugs a memory leak in `repository.c`. The leak occurs because the main reference database (`repo->refs_private`) is never freed when clearing a repository, despite worktree and submodule reference databases being properly released. The leak was masked by the `chdir_notify` subsystem keeping the pointer alive.

The fix is straightforward: the patch adds a block in `repo_clear()` to call `ref_store_release()` on the main ref database and then free its pointer, mirroring the existing cleanup logic for submodule ref stores. The change is minimal (5 lines added) and touches only `repository.c`. This aligns with the series' broader goal of improving ref backend lifecycle management, particularly the `chdir_notify` subsystem cleanup in patches 4-5.

The patch is uncontroversial and likely to be merged as-is. It addresses a clear leak with no behavior changes, and the fix is consistent with the existing codebase patterns. This is a targeted cleanup that complements the series' architectural improvements, though it leaves one remaining leak in the main ref database (noted in patch 4/10) for future work. Reviewers familiar with the series (like Justin Tobler, who approved similar fixes in v3) will likely view this favorably.
