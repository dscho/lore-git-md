This is the second patch in Kristoffer Haugsbakk’s now-merged five-part documentation series that standardizes Git’s trailer conventions in `Documentation/SubmittingPatches`. It explicitly discourages the use of Linux Kernel–style trailers `Fixes:` and `Link:` in Git commit messages, providing a clear rationale grounded in Git’s distinct workflow.

The patch adds a concise four-line paragraph to the “Commit trailers” section, explaining that while other projects (notably Linux) rely on `Fixes:` and `Link:`, Git does not. The justification is practical: Git’s workflow involves fewer trees and less cherry-picking than Linux, so `Fixes:` is redundant with inline commit-message references; and Git already tracks patch submissions via `refs/notes/amlog`, making `Link:` unnecessary. The commit message cites a specific Linux kernel commit (linux/d5d6281a) to illustrate the contrast, reinforcing the data-driven approach.

This patch is uncontroversial and aligns with the series’ broader goal of codifying existing practice rather than inventing new rules. The change is minimal—just four lines of text—but it eliminates ambiguity for contributors accustomed to Linux conventions. The series as a whole (including this patch) is now fully merged to `master`, reflecting consensus on the trailer guidelines.
