This is a small refactoring patch that improves code hygiene in preparation for the larger `git cat-file --batch-command` security series. The patch moves loop counter declarations (`int i`) inside their respective `for()` statements and, where appropriate, changes the type from `int` to `size_t` to better match the loop bounds (array sizes, `nr` parameters, etc.).

The changes touch two files: `builtin/cat-file.c` (three loops in the batch-command handling code) and `fetch-pack.c` (one loop in the protocol-v2 capability advertisement helper). Each loop now declares its counter in the loop header, which is a minor readability win and brings the code in line with modern C style. The type changes to `size_t` are technically safer for array indexing, though the loops in question are all small and the risk of overflow is negligible.

The patch is part of the v13 iteration of the series and carries sign-offs from both Eric Ju (author) and Pablo Sabater (series maintainer). It addresses a surface-level review comment from earlier rounds and is uncontroversial. There is no behavior change, so no new tests are needed. This is purely a cleanup that makes the subsequent patches in the series slightly cleaner.
