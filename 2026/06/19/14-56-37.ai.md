This is patch 8/12 in the v13 series implementing `git cat-file --batch-command` for secure remote object metadata queries. The patch adds server-side capability advertisement for the object-info feature, enabling clients to discover what metadata a server supports before making queries.

The change is minimal and focused: it modifies `object_info_advertise()` in `serve.c` to populate the `value` strbuf with supported object-info components when the feature is enabled. Currently only "size" is advertised, matching the client-side implementation in earlier patches. The advertisement respects the `transfer.advertiseobjectinfo` configuration (disabled by default), maintaining backward compatibility.

This patch directly enables the dynamic capability validation introduced in v13. By advertising supported features, the server allows clients to validate requested format placeholders (like `%(objectsize)`) against what the server actually supports, closing a potential information-leak vector where clients might request unsupported metadata. The implementation is forward-compatible, as the strbuf can be extended with additional components (e.g., "objecttype") in future patches.

The patch is authored by Calvin Wan with help from Jonathan Tan and Christian Couder, and carries sign-offs from Eric Ju and Pablo Sabater, indicating broad review coverage. It builds on the protocol v2 refactoring in patches 5-7 and prepares for the client-side implementation in patch 9. The change is mechanical and behavior-preserving except for the new capability advertisement, which is gated by the existing configuration.

This is a key piece of the security hardening in the series, as it enables the client to make informed decisions about whether to query for object metadata or fall back to fetching objects. The patch is uncontroversial and ready for merging as part of the larger series.
