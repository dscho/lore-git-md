This is the seventh patch in Patrick Steinhardt’s 10-patch v4 series refactoring Git’s reference backend infrastructure. It moves the parsing of `core.logAllRefUpdates` back into the individual ref backends (files and reftable), reversing a previous refactoring that had centralized this logic in the generic layer.

The change is a preparatory step for the series’ main goal: fixing recursive initialization issues caused by "onbranch" config includes. By handling `core.logAllRefUpdates` in the backends themselves—alongside other backend-specific config—Patrick ensures all ref-store configuration is parsed consistently, avoiding the chicken-and-egg problem where config parsing could trigger ref-store initialization before the store was fully set up. The patch touches `refs/files-backend.c`, `refs/reftable-backend.c`, and related headers, and updates call sites like `builtin/checkout.c` to use the new `refs_parse_log_all_ref_updates_config()` helper.

This is a well-motivated refactoring that directly addresses the architectural concerns raised in earlier versions of the series.
