This is the eighth patch in Patrick Steinhardt’s ten-part refactoring series (v4) modernizing Git’s reference backend. It prepares for the upcoming `ignore_refdb` flag by moving the parsing of `core.sharedRepository` out of the generic config layer and into the reftable backend itself, mirroring the approach taken in the previous patch for `core.logAllRefUpdates`.

The change is straightforward: `reftable_be_config()` now directly handles `core.sharedRepository`, using `calc_shared_perm()` with a manually parsed permission value instead of relying on `repo_settings_get_shared_repository()`. This avoids the circular dependency that would otherwise occur when the config system tries to access the ref store during repository initialization. The patch also reorders the repository setup sequence in `setup.c` to ensure `core.sharedRepository` is written to the config *before* the ref database is created, so the backend can read it during its own initialization.

The diff is small and focused, touching only the reftable backend, `path.c` (to remove the `repository` parameter from `calc_shared_perm()`), and `setup.c`. The change is behavior-preserving and well-motivated by the series’ goal of eliminating recursive initialization issues. It directly addresses Jeff King’s critique of the v3 workaround by enabling a cleaner architectural solution in the final patch. This patch, along with the preceding one, lays the groundwork for the `ignore_refdb` flag without introducing new complexity.
