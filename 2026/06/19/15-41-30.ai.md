This is a build system discussion about the macOS linker warning for duplicate libraries. Junio C Hamano responds to Harald Nordgren's v2 patch with a fundamental architectural concern: rather than removing duplicate library references from the Makefile, the linker itself should be configured to suppress these warnings.

Junio argues that listing the same library multiple times on the linker command line is not just harmless but sometimes necessary for correct symbol resolution, particularly when dealing with circular dependencies between libraries. He provides a concrete example where a program depends on two mutually dependent libraries (libA.a and libB.a), requiring libA.a to be listed twice to ensure all symbols are resolved. This pattern is more portable than GNU ld's `--start-group`/`--end-group` syntax and should not trigger warnings.

The proposed alternative is to add `-Wl,-no_warn_duplicate_libraries` to the macOS linker flags in `config.mak.uname`, following the approach taken by other build systems like CMake. Junio's patch demonstrates this solution, though he notes it should ideally be version-gated for XCode 15 or later. This approach preserves the existing Makefile logic while addressing the cosmetic warning at the linker level.

The discussion reveals a tension between two valid perspectives: Harald's focus on developer experience (eliminating terminal noise during test runs) and Junio's emphasis on maintainability and correctness (preserving the ability to list libraries multiple times when needed). The thread now hinges on whether the linker-level suppression is an acceptable compromise or if the Makefile restructuring should proceed.

Key technical details for follow-up discussion: the circular dependency use case, the `-no_warn_duplicate_libraries` flag, and the version-gating question for macOS/XCode. The outcome may set a precedent for how Git handles platform-specific linker behaviors in the future.
