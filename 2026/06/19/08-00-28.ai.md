This is a build system cleanup patch (v2) that refines the Makefile's library linking logic to eliminate duplicate archive references while preserving correct linker symbol resolution. Harald Nordgren addresses macOS linker warnings (`ld: warning: ignoring duplicate libraries`) that appear during repeated test runs, demonstrating the issue with terminal output from a rebase operation.

The core change redefines the `$(LIBS)` variable to explicitly list archive prerequisites from `$^` first, then filter those same archives from the remaining library list. This systematic approach replaces the previous ad-hoc duplicate removal in individual link recipes, making the solution more maintainable and less prone to future regressions. The patch affects three key build targets: test helpers, fuzz programs, and unit tests.

The v2 iteration shows clear improvement over v1 by tackling the root cause through `$(LIBS)` restructuring rather than just removing duplicates at specific call sites. The commit message and code comments demonstrate careful attention to both the cosmetic warning issue and the underlying technical constraint of left-to-right linker ordering, where object files must precede archives.

Harald's terminal output illustrates the practical impact - these warnings appear repeatedly during development workflows like rebasing with test execution, making this a quality-of-life improvement for macOS developers. The solution maintains compatibility with other platforms while specifically addressing the macOS linker's warning behavior.
