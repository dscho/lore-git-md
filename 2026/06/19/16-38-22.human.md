This is a refactoring patch that moves the `protect_hfs` and `protect_ntfs` global variables into Git’s per-repository `repo_config_values` structure. It is part of the ongoing libification effort to eliminate global state and make Git’s internals more modular and thread-safe.

The patch touches five files: `compat/mingw.c`, `environment.c`, `environment.h`, `read-cache.c`, and a test helper. The core change is in `environment.c`, where the two boolean flags are now stored inside `struct repo_config_values` and accessed via new helper functions `repo_protect_hfs()` and `repo_protect_ntfs()`. The commit message explains that this approach was chosen over a previous lazy-loading proposal because it keeps the configuration warnings at the same time and avoids introducing new global state.

The update from v3 is minor: the helper functions now check `repo && repo->initialized` instead of just `repo->gitdir`, which is a defensive coding tweak rather than a functional change.

The patch is well-motivated, clearly documented, and fits cleanly into the larger libification roadmap. It should be uncontroversial for anyone following that effort.
