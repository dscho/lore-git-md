This is a **bug report** about data loss in sparse-checkout mode. The author, charmocc, demonstrates that `git checkout` behaves inconsistently when sparse mode is enabled: it correctly aborts in normal mode if an untracked file would be overwritten, but in sparse mode it silently overwrites the file and issues a misleading warning about paths "not updated despite sparse patterns." The report includes clear reproduction steps, expected vs. actual behavior, and system details.

The issue appears to be a logic flaw in how sparse-checkout interacts with the working directory state check. The warning message ("The following paths were already present...") is confusing because it suggests the file was preserved, when in fact it was overwritten. This could lead users to believe their uncommitted changes were retained when they were not.
