This is a **test suite bugfix** for platform compatibility, resolving TAP parse errors in `t4216-log-bloom.sh` on non-x86 architectures. Patrick Steinhardt submits the final patch (`[PATCH v1]`) to drop the redundant `SIGNED_CHAR_BY_DEFAULT` prerequisite and its associated `test_cmp` check, as previously agreed by Junio C Hamano, Jeff King, and Patrick himself. The patch touches only the test script (`t/t4216-log-bloom.sh`), leaving the Bloom filter logic and on-disk format unchanged.

The issue stems from a long-standing assumption in the test that `char` is signed by default (true on x86), which causes `test_cmp` diff output to leak into the TAP stream on architectures where `char` is unsigned (e.g., ARM, PowerPC). This leakage became visible only after the June 2026 commit `389c83025d` tightened TAP parsing strictness. The `highbit1` test case, which uses this prerequisite, runs `true` regardless of the outcome, making the check unnecessary. The patch removes it entirely, eliminating the parse errors without altering test behavior.

The thread has converged on this solution, with no objections raised. The unresolved question—whether the Bloom filter logic should vary by platform—remains orthogonal to the fix and is not addressed here. The patch is expected to be uncontroversial and ready for merging. Key symbols involved include `SIGNED_CHAR_BY_DEFAULT`, `test_cmp`, and the `highbit1` test case. The fix is isolated to the test suite and does not affect runtime functionality.
