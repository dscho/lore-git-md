This is the final patch in a security-hardened 12-part GSoC series that adds `git cat-file --batch-command` support for querying remote object metadata. The series is now complete and ready for merging, with this patch addressing the last major architectural concern: replacing the static allow-list for format placeholders with dynamic capability-based validation.

The patch makes the `remote-object-info` command future-proof by validating requested placeholders (like `%(objectsize)`) against the server's advertised capabilities rather than a hardcoded list. This closes a potential information-leak vector where clients could request metadata the server doesn't support. The implementation maps protocol options ("size", "type") to placeholders ("objectsize", "objecttype") and filters unsupported options before sending requests, while maintaining backward compatibility by returning empty strings for unsupported fields (matching `for-each-ref` behavior).

Key changes include:
- New `remote_allowed_atoms` string list in `expand_data` that tracks server-supported placeholders
- Backward iteration in the capability validation loop (necessary for safe list compaction)
- Explicit type initialization to `OBJ_BAD` with NULL checks for `type_name()`
- Comprehensive cleanup of string lists and object info contents
- Support for the "type" option in preparation for future server capabilities

The patch demonstrates careful attention to security and edge cases, with thorough memory management and input validation. All prior review feedback has been addressed, including Junio Hamano's concerns about type safety and protocol compliance. The series has received substantive review from core maintainers and is fully rebased on current master. This final piece completes the security hardening that was the series' primary goal.
