This is the second patch in Patrick Steinhardt's v4 refactoring series (10 patches total) modernizing Git's reference backend infrastructure. It is a targeted refactoring that eliminates redundant application of repository format settings during repository initialization.

The patch addresses a minor inefficiency in `setup.c` where the repository format (hash algorithm and ref storage format) was being applied twice: once via `repository_format_configure()` and again via `apply_repository_format()`. The fix reorders the calls so that `repository_format_configure()` runs first, allowing it to fully prepare the `struct repository_format` before `apply_repository_format()` propagates those settings to the repository. This removes the need for `repository_format_configure()` to directly modify the repository, simplifying its signature and logic.

The change is purely internal to the initialization sequence and does not affect user-visible behavior. It touches only `setup.c`, removing 7 lines and adding 2, with no test changes required. This patch is preparatory work for later architectural changes in the series, particularly the introduction of the `ignore_refdb` flag in patch 9/10, which will prevent recursive initialization during config parsing.

The patch appears well-motivated and uncontroversial. It was present in the previous v3 series (as patch 2/8) and received no negative feedback, suggesting it is a straightforward cleanup. The commit message clearly explains the redundancy and the solution. This is part of the broader effort to modernize Git's ref storage layer, which has seen active review from Jeff King, Justin Tobler, and Karthik Nayak.
