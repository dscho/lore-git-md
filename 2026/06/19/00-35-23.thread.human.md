The Git mailing list is tracking an intermittent but serious CI reliability issue on macOS runners in GitHub Actions. Junio C Hamano reported that the `osx-clang` and `osx-gcc` jobs now occasionally hit the 6-hour timeout and are killed, even though the same commit finishes in under 30 minutes when other jobs are removed. No root cause was initially known.

Patrick Steinhardt has now identified the likely culprit: orphaned `httpd` and `git-remote-http` processes left behind by the `t5551` and `t5559` test scripts, which share HTTPD-based test infrastructure. The GitHub Actions logs show these processes being forcibly terminated at the 6-hour mark, strongly suggesting the test suite is hanging rather than running slowly. The issue appears specific to GitHub’s macOS runners, as Patrick could not reproduce it locally or on GitLab CI. This narrows the investigation to either a macOS-specific bug in the HTTPD test harness or a resource contention issue unique to GitHub’s environment.

No patches have been proposed yet, but the next steps will likely focus on fixing the HTTPD test cleanup logic or diagnosing what in GitHub’s macOS environment triggers the hang. The thread remains open, with the root cause now localized to a specific subsystem.
