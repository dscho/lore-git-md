This is a **test suite bugfix** targeting platform compatibility. Patrick Steinhardt sends the actual patch that resolves the TAP parse errors in `t4216-log-bloom.sh` on non-x86 architectures. The issue, long-standing but only exposed by a June 2026 TAP harness tightening, stems from a redundant `SIGNED_CHAR_BY_DEFAULT` prerequisite that leaks diff output into the TAP stream when `char` is unsigned.

The patch itself is straightforward: it removes the unused prerequisite and its associated `test_cmp` check from the test script. The fix is uncontroversial, aligns with earlier discussion, and touches only the test file—no Bloom filter logic or on-disk formats are altered. The thread has already established consensus among Junio C Hamano, Jeff King, and Patrick Steinhardt, so this patch is essentially a formality. If you care about platform compatibility or test suite robustness, this is a small but necessary cleanup worth noting.
