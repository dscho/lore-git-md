This is the sixth patch in Matt Hunter’s now-merged 8-patch series that adds a global `fetch.followRemoteHEAD` configuration option. The patch refactors the fetch machinery to prepare for the global fallback setting introduced in the next patch.

The core change is mechanical: the `follow_remote_head_settings` enum gains a new `FOLLOW_REMOTE_UNCONFIGURED` sentinel value (zero-initialized) so the code can distinguish between an unset variable and the explicit default (`FOLLOW_REMOTE_CREATE`). The `do_fetch()` function is updated to compute the effective `followRemoteHEAD` mode itself, falling back to the built-in default when the remote-specific setting is missing. The `set_head()` helper is also refactored to accept the mode as an explicit argument rather than reading it directly from the remote struct.

The patch is clean and conservative: it does not change behavior, only restructures the control flow to make the global fallback possible in the next patch. The commit message clearly explains why the “warn-if-not-$branch” value is excluded from the global scheme (it is inherently remote-specific) and how the existing `no_warn_branch` logic remains untouched.
