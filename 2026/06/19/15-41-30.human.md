This is a build system discussion about a macOS linker warning that appears during repeated test runs. Junio C Hamano responds to Harald Nordgren's v2 patch that aimed to eliminate duplicate library references in the Makefile.

Junio acknowledges the annoyance of the warnings but raises a deeper technical concern: some linkers (not just macOS) may need to process the same library archive multiple times to resolve circular dependencies between libraries. He gives a concrete example where listing `libA.a` twice is necessary for correct linking when two libraries depend on each other. The current macOS linker's warning behavior could therefore break valid build scenarios.

Instead of restructuring the Makefile to avoid duplicates, Junio proposes a simpler solution: suppress the warnings at the linker level using `-Wl,-no_warn_duplicate_libraries`. He provides a patch that adds this flag to `config.mak.uname` for Darwin platforms, noting it should ideally be version-gated for XCode 15+. This approach maintains the existing build logic while eliminating the cosmetic issue.

The discussion reveals this is more than just a macOS-specific annoyance - it touches on fundamental linker behavior and portability concerns. Junio's counter-proposal suggests the original architectural change might be over-engineering for what could be a one-line configuration fix. The thread now pivots from "how to remove duplicates" to "should we remove duplicates at all, or just silence the warnings?"
