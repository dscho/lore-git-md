This is the eleventh patch in the GSoC v13 series implementing `git cat-file --batch-command` support for remote object metadata queries. The series as a whole is now complete and ready for merging, with this patch addressing a critical security and usability issue in the format placeholder validation.

The patch replaces the previous `strstr()`-based validation with a proper allow-list of supported atoms (`objectname` and `objectsize`). This fixes two serious problems: (1) unsupported atoms like `%(objecttype)` would cause segfaults due to uninitialized `data->type`, and (2) unknown atoms would trigger `die()` via `strbuf_expand_bad_format()`, breaking local queries if the same format string was reused. The new behavior matches `for-each-ref`'s handling of inapplicable atoms by returning empty strings for unsupported placeholders in remote mode.

Key changes include:
- A static `remote_object_info_atoms[]` array listing supported atoms
- Dynamic validation against the allow-list in `expand_atom()`
- Initialization of `data->type` to `OBJ_BAD` and a NULL check for `type_name()`
- Updated documentation to reflect the new "empty string" behavior
- Tests adjusted to expect empty strings instead of `die()` for unsupported atoms

The patch is well-motivated and clearly explains the security implications of the previous implementation. The allow-list approach is conservative and forward-compatible, though the commit message notes that future work may need to address how to distinguish "unsupported" vs "no data" responses (currently both return empty strings). All prior review feedback appears to be addressed, and the patch maintains the series' focus on security hardening.
