This is the core implementation patch in Matt Hunter’s now-merged 8-patch series introducing the global `fetch.followRemoteHEAD` configuration variable. It adds the new global setting, wires it into the fetch machinery, and documents its interaction with the existing per-remote `remote.<name>.followRemoteHEAD` option.

The patch teaches Git to consult `fetch.followRemoteHEAD` as a fallback whenever a remote lacks an explicit `remote.<name>.followRemoteHEAD` setting. The global option accepts the same values (`never`, `create`, `warn`, `always`) except `warn-if-not-$branch`, which remains remote-specific. A new `FOLLOW_REMOTE_UNCONFIGURED` enum state distinguishes unset from default (`create`), and the fetch machinery now computes an effective mode with a clear fallback chain: remote-specific → global → built-in default. The advice message and documentation are updated to reflect the two-tier configuration, and the code includes a `NEEDSWORK` comment about the opportunity to defer warnings until the value is actually consulted.

Test coverage in `t5510-fetch.sh` verifies feature parity, precedence rules (remote-specific overrides global), and edge cases such as dangling symrefs, `--quiet` interaction, and refspec fetches. The implementation is conservative, maintaining backward compatibility and excluding the inherently remote-specific `warn-if-not-$branch` value from the global fallback logic. This patch is the technical centerpiece of the series and was merged as-is into `master`.
