Subject: macOS CI jobs timing out in GitHub Actions
Series version: N/A (standalone bug report)
Originating author: Junio C Hamano
Thread type: bug report / CI reliability

Core problem or goal
Git’s GitHub Actions CI workflow has developed an intermittent reliability issue on macOS runners: jobs (`osx-clang` and `osx-gcc`) now occasionally hang, exhausting the 6-hour timeout and being killed by GitHub Actions. The same commit completes in under 30 minutes when all other jobs are removed from the workflow. The goal is to identify the environmental or code-level factor causing the hang, which Patrick Steinhardt has now traced to orphaned `httpd` and `git-remote-http` processes left behind by the `t555*` test scripts (`t5551` and `t5559`).

Current status
Root cause identified: orphaned HTTPD test processes (`httpd` and `git-remote-http`) are not being cleaned up by the test suite, causing the CI job to hang until forcibly terminated. The issue is specific to the `t5551` and `t5559` test scripts (which share `lib-httpd.sh` infrastructure) and appears to be triggered only in GitHub’s macOS runner environment. No patches have been proposed yet, but the scope of investigation is now narrowed to either the HTTPD test cleanup logic or GitHub’s macOS environment.

Key technical details
- **Platform**: GitHub Actions macOS runners (`osx-clang`, `osx-gcc`)
- **Timeout threshold**: 6 hours (GitHub Actions maximum)
- **Test suite**: full Git test suite (`make test` or equivalent)
- **Problematic tests**: `t5551` (smart HTTP tests) and `t5559` (HTTP/2 tests), both using `lib-httpd.sh`
- **Orphaned processes**: `httpd` and `git-remote-http` left running after test completion
- **Workflow file**: `.github/workflows/main.yml`
- **Commit under test**: `95e20213`
- **Environmental specificity**: Issue not reproducible locally or on GitLab CI, suggesting a GitHub macOS runner quirk
- **Minimal reproduction**: Remove all non-macOS jobs from the workflow; failing runs show missing logs for `t5551` and `t5559`

Open questions and loose ends
- **Why does the HTTPD test cleanup fail only on GitHub’s macOS runners?** Is this a macOS-specific bug in the test harness, or does GitHub’s environment introduce resource contention (e.g., process limits, signal handling differences) that prevents cleanup?
- **Are there recent changes to the `lib-httpd.sh` infrastructure or the `t555*` tests that could have introduced this regression?** If so, reverting or patching those changes may resolve the issue.
- **Could the issue be exacerbated by parallel test execution?** The full CI workflow runs multiple jobs concurrently; removing other jobs may reduce resource contention and allow the HTTPD tests to complete.
- **What is the safest fix?** Options include:
  - Patching the HTTPD test cleanup logic to ensure processes are terminated even in error cases.
  - Adding a pre-test or post-test hook in the CI workflow to forcibly kill orphaned `httpd` processes.
  - Disabling the `t555*` tests on macOS CI until the root cause is resolved (not ideal, as it reduces test coverage).
- **Is this issue affecting other projects using GitHub’s macOS runners?** If so, it may indicate a broader problem with GitHub’s infrastructure.
