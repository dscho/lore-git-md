This is the eighth patch in the GSoC RFC v13 series implementing `git cat-file --batch-command` support for secure remote object metadata queries. The patch enables servers to advertise which object-info features they support, currently just "size" but designed to be extensible.

Calvin Wan introduces a small but crucial change to `serve.c`: the `object_info_advertise()` function now populates a `strbuf` with the server's supported features when the `transfer.advertiseobjectinfo` configuration is enabled. This allows clients to dynamically validate their requested format placeholders against what the server actually supports, closing a potential information-leak vector that existed in earlier versions with static allow-lists.

The implementation is minimal and focused: it checks the existing `advertise_object_info` flag (which defaults to disabled), and if enabled, adds "size" to the capabilities string. This matches the series' security-hardened design where clients must explicitly opt-in to capability advertisement and only supported features are exposed. The patch preserves backward compatibility while laying groundwork for future metadata types like objecttype or objectmode.

This is a well-crafted, necessary piece of the larger protocol v2 object-info capability effort. The change is small but significant - it completes the server-side capability advertisement that enables the client's dynamic validation introduced in earlier patches. With all prior review feedback addressed and no outstanding objections, this patch appears ready for merging as part of the series.
