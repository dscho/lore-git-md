This is a **bug report** about data loss in Git's sparse-checkout mode. The author, a first-time contributor, demonstrates that `git checkout` behaves inconsistently when sparse mode is enabled: it correctly aborts when untracked files would be overwritten in normal mode, but silently overwrites those same files in sparse mode, accompanied by a misleading warning message.

The reproduction steps are clear and minimal: initialize a repository, clone it with `--no-checkout`, create an untracked file with conflicting content, then enable sparse mode and run `git checkout`. The expected behavior (checkout aborts) differs from the actual behavior (checkout succeeds, overwriting the untracked file). The report includes system details and Git version (2.53.0), but no patch or proposed fix.

This looks like a serious correctness issue—data loss is always worth attention. The report is well-structured and easy to follow, though the author does not appear to be a regular contributor. The bug affects the sparse-checkout subsystem, which has seen significant work in recent years (notably from Derrick Stolee and Elijah Newren). If this behavior is confirmed, it may require a targeted fix in the sparse-checkout logic.
