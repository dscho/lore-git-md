This is a refactoring patch (v4 4/10) in Patrick Steinhardt's series modernizing Git's reference backend infrastructure. It fixes a lifecycle management issue in the `chdir_notify` subsystem by ensuring reference stores are properly unregistered when released.

The patch addresses a latent bug where reference stores (files, packed, and reftable backends) were registered with `chdir_notify` to handle relative path reparenting during directory changes, but never unregistered. This created two problems: for the main repository's ref database, it masked memory leaks (since the store was never freed), while for submodule/worktree stores, it risked dangling pointers to freed memory. Though these issues were not observed in practice (Git rarely changes directories mid-process), they represent clear correctness violations.

The fix replaces the one-way `chdir_notify_reparent()` calls with the full registration/unregistration API (`chdir_notify_register()`/`chdir_notify_unregister()`), adding custom reparenting callbacks for each backend. The changes are mechanical but thorough, touching all three ref backends (`files-backend.c`, `packed-backend.c`, `reftable-backend.c`) and introducing no behavior changes. The patch is part of the series' broader effort to clean up initialization sequencing and memory management in the ref subsystem.

This is a well-motivated cleanup that plugs a subtle lifecycle gap. The implementation is straightforward and aligns with the series' goal of making ref backend behavior more predictable. The patch is uncontroversial and likely to be accepted as-is, though it depends on earlier patches in the series for context. The remaining leak in the main ref database is flagged for a follow-up commit.
