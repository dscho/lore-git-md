Subject: [PATCH v4] repo-settings: move `protect_hfs` and `protect_ntfs` into `repo_config_values`

Originating author: Tian Yuchen
Thread type: patch series (refactoring, libification)

Core problem or goal
Eliminate the global `protect_hfs` and `protect_ntfs` variables by moving them into the per-repository `struct repo_config_values`, removing implicit `the_repository` dependencies and advancing the project’s libification effort.

Current status
v4 is queued in Junio’s `next` branch. Junio has proposed a tiny follow-up patch (4 lines) that replaces the `repo->gitdir` guard in the new accessor functions (`repo_protect_hfs()` and `repo_protect_ntfs()`) with `repo->initialized` for consistency with other repository-scoped config topics. The follow-up is purely defensive and does not alter behavior; it is expected to graduate quickly.

Key technical details
- Files touched: `compat/mingw.c`, `environment.c`, `environment.h`, `read-cache.c`, `t/helper/test-path-utils.c` (v4); follow-up touches only `environment.c` and `environment.h`
- New fields in `struct repo_config_values`: `protect_hfs`, `protect_ntfs`
- Accessor functions: `repo_protect_hfs(struct repository *)`, `repo_protect_ntfs(struct repository *)`
- Initialization: values are set during `prepare_repo_settings()` via the existing config keys `core.protectHFS` and `core.protectNTFS`
- On-disk format: unchanged; config keys and semantics remain identical
- Test coverage: updated `test-path-utils.c` to use the new accessors; the helper now directly manipulates `repo_config_values` for benchmarking, replacing prior global-variable loop iterators
- Fallback: all callers explicitly fall back to `the_repository`, acknowledged as a temporary measure for future cleanup
- Follow-up change: replaces `repo->gitdir` with `repo->initialized` in accessor guards, aligning with existing patterns for similar config fields
