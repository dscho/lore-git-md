This is the sixth patch in Matt Hunter’s now-merged 8-patch series implementing the global `fetch.followRemoteHEAD` configuration. It refactors the fetch machinery to decouple the decision of *which* followRemoteHEAD mode to use from the act of *applying* that mode.

The patch introduces `FOLLOW_REMOTE_UNCONFIGURED` as the new zero-initialized value for the `followRemoteHEAD` variable, allowing the code to distinguish between “unset” and “explicitly set to the default (`create`)”. The `do_fetch()` function is updated to compute the effective mode itself, falling back to the built-in default (`FOLLOW_REMOTE_CREATE`) when no remote-specific setting exists. The `set_head()` helper is modified to accept the mode as an explicit argument rather than reading it from the remote struct, making its behavior independent of where the setting came from.

The change deliberately excludes the `warn-if-not-$branch` value from the global fallback logic, since that mode is inherently remote-specific. The patch also removes unnecessary indentation in the enum definition and updates the logic in `do_fetch()` to use the computed mode consistently. No behavior changes are introduced; this is purely a refactoring that prepares for the next patch, which will wire up the global configuration.
