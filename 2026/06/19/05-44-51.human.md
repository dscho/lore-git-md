This is the second patch in Kristoffer Haugsbakk’s now-merged five-part documentation series that standardizes Git’s trailer conventions in commit messages. The patch explicitly discourages the use of Linux Kernel trailers `` `Fixes:` `` and `` `Link:` `` in Git, explaining why they are unnecessary and how Git’s workflow differs.

The commit message provides clear, data-driven justification: Linux uses `` `Fixes:` `` to help cherry-picking across its many trees, whereas Git has few downstream trees and typically handles fixes inline in the commit message body. Similarly, `` `Link:` `` is redundant because Git already tracks patch submissions via `` refs/notes/amlog `` and reserves footnotes for the message body. The patch adds a concise four-line section to `Documentation/SubmittingPatches` that names the two trailers and states they are not used in Git.

The change is uncontroversial and aligns with the series’ goal of codifying existing practice. It complements the other patches by removing ambiguity about which trailers belong in Git commit messages. The patch is ready to merge and requires no further discussion.
