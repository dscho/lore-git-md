This is the seventh patch in Patrick Steinhardt’s v4 refactoring series (10 patches total) that modernizes Git’s reference backend infrastructure. The patch moves parsing of the `core.logAllRefUpdates` configuration setting back into the individual ref backends (files and reftable), reversing a previous refactoring (cc42c88945) that had centralized this logic in the generic layer.

The change is a preparatory step for patch 9/10, which introduces an `ignore_refdb` flag to prevent recursive initialization during ref store setup. By moving `core.logAllRefUpdates` parsing back into the backends, the series ensures all backend-specific configuration is handled consistently in one place, reducing reliance on the generic config subsystem during initialization. The patch touches `refs/files-backend.c`, `refs/reftable-backend.c`, `refs.c`, and related headers, while removing the now-unused generic parsing logic from `repo-settings.c`.

This is a targeted refactoring with no behavior change—test coverage confirms the setting’s effect remains identical. The patch is well-motivated by the series’ goal of resolving initialization-order issues, though it reverses a recent change, which may draw scrutiny. It directly addresses Jeff King’s critique of the v3 series by enabling a cleaner solution to the "onbranch" recursion problem. The diff is clean and focused, with no obvious oversights.
