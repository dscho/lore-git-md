Subject: `git log <file>` omits commits that modify the file
Series version: standalone bug report (no patch series)
Originating author: Vincent Lefevre
Thread type: bug report

Core problem or goal
`git log <file>` fails to show commits that modify the specified file in two distinct edge cases: (1) when the file history involves merges, commits are silently omitted unless `-m` is used; (2) when `--reverse` is used, commit selection logic is altered in a way that contradicts the man page, including commits that predate the file's creation.

Current status
Reported; no patches or fixes proposed yet. The issues are reproducible on Git 2.53.0 using the Git project's own repository and an external MPFR repository. No maintainer response or triage yet.

Key technical details
- Subsystem: revision walking (`git log`)
- Command: `git log <file>`
- Flags involved: `-m` (show merge commits), `--reverse` (reverse output order)
- Edge cases: merge commits, file creation history, commit ordering
- Test coverage: none yet; reporter provided exact reproduction steps and commit hashes
- Files: `git-gui/git-gui--askyesno.sh` (Git repo), `AUTHORS` (MPFR repo)
- Behavior: commits modifying the file are incorrectly filtered out in specific scenarios
