This is the pivotal patch in Patrick Steinhardt’s v4 refactoring series (9/10). It fixes the long-standing recursive initialization bug in `get_main_ref_store()` that occurs when an "onbranch" config include condition tries to resolve HEAD before the ref store is fully set up.

The patch introduces a new `ignore_refs` flag in `struct config_options` and uses it to skip "onbranch" condition evaluation during ref-store initialization. Both the files and reftable backends now parse their config with this flag set, breaking the chicken-and-egg cycle. A static `initializing` guard in `get_main_ref_store()` catches any remaining recursion and turns it into a BUG().

The change is minimal (25 lines), well-motivated, and directly addresses Jeff King’s critique of the v3 workaround. It should be uncontroversial now that the preparatory patches (7–8/10) have moved backend-critical config parsing into the ref stores themselves.
