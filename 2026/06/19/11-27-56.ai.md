This is the eighth patch in Patrick Steinhardt’s v4 refactoring series (10 patches total) modernizing Git’s reference backend infrastructure. It prepares for the upcoming `ignore_refdb` flag (patch 9/10) by moving the parsing of `core.sharedRepository` for the reftable backend out of the generic config layer and into `reftable_be_config()`, mirroring the approach taken for `core.logAllRefUpdates` in patch 7/10.

The change addresses the same recursive initialization problem as the rest of the series: `calc_shared_perm()` currently calls `repo_settings_get_shared_repository()`, which triggers config parsing that can re-enter the ref backend during repository setup. By handling `core.sharedRepository` directly in the backend, the patch avoids this circular dependency. The diff shows the backend now computes permissions using `git_config_perm()` and `calc_shared_perm()` with a raw config value instead of a repository reference. A small reordering in `setup.c` ensures the config is written *before* the ref database is created, since the backend now reads the value during initialization.

The patch touches `path.c`/`path.h` to remove the repository parameter from `calc_shared_perm()`, `refs/reftable-backend.c` to add the manual config parsing, and `setup.c` to adjust the initialization sequence. The change is behavior-preserving and covered by existing tests. This is a targeted, mechanical step toward the architectural fix in patch 9/10, and it directly responds to Jeff King’s critique of the v3 series by eliminating the need for the config layer to access the ref store during setup. The patch looks clean and well-motivated, though reviewers may want to verify the reordering in `setup.c` doesn’t introduce edge cases in other initialization paths.
