This thread is about a broken test in `t/t4216-log-bloom.sh` that checked whether the system’s `char` type is signed by default. The test was unused (guarding only a `true` statement) and caused TAP output parsing to fail on systems with unsigned `char` after a recent test harness change. The original patch simply deleted the test, but Taylor Blau suggested preserving it in a TAP-compliant form, arguing it might guard against future murmur3 hash regressions.

Junio C Hamano has now weighed in, shifting the discussion from the mechanical fix to the test’s *intent*. He questions whether the test was ever meaningful—was it just checking `char` signedness, or was it guarding against a real risk of murmur3 regressions? He also notes that the prerequisite’s name (`SIGNED_CHAR_BY_DEFAULT`) is misleading, since it could be set even on platforms where `char` isn’t signed by default. The thread now hinges on whether anyone can justify keeping the test; if not, deletion seems likely. No other contributors have weighed in yet, and the technical details (TAP compliance, `test_lazy_prereq`) are now secondary to the question of the test’s purpose.
