This is a bugfix patch from the final v13 iteration of Pablo Sabater's GSoC series implementing `git cat-file --batch-command` for remote object metadata queries. The series as a whole is security-hardened and ready for merging, and this specific patch addresses a memory leak in the transport-helper subsystem.

The leak occurs in `disconnect_helper()` when a transport is disconnected before its helper process is fully started. In that case, the `data->name` string allocated during `transport_helper_init()` is never freed because the cleanup code is guarded by an `if(data->helper)` check. The fix is simple and surgical: move the `FREE_AND_NULL(data->name)` call outside the conditional block so it always runs on disconnect, regardless of whether the helper was started.

This is a classic "small but important" patch that often surfaces late in a series' lifecycle. The change itself is trivial (one line moved), but it plugs a real leak that could accumulate in long-running Git processes or scripts that repeatedly connect and disconnect transports. The commit message clearly explains the scenario and references the problematic code path, making it easy for reviewers to verify the fix. No test is included, which is typical for memory-leak fixes in plumbing code where the leak is hard to trigger deterministically in the test suite.

The patch is part of a larger security-conscious effort, and its presence in the final v13 series signals the author's attention to detail. While not glamorous, this kind of housekeeping is exactly what separates a "works for me" patch from one that is truly production-ready. For a busy reader, this is a clear "merge as-is" candidate.
