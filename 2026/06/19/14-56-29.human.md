This is the thirteenth iteration of a Google Summer of Code feature that extends `` `git cat-file --batch-command` `` to query object metadata from remote repositories without downloading the full objects. The series is now complete and ready for merging, with all prior review feedback addressed.

The core functionality lets users request object sizes (and eventually other metadata) from a remote server using the new `remote-object-info` command. The implementation is hardened with dynamic capability-based validation: the client only asks for fields the server advertises support for, replacing the earlier static allow-list approach. This version also fixes a memory leak in the transport helper, improves error messages, and adds better handling for invalid or short object IDs.

Two design questions remain open. First, how to distinguish between "unsupported" and "no data" for future placeholders like `%(rest)` or `%(objectmode)`—the author suggests using a placeholder like "???" to signal unsupported fields. Second, whether to extend the protocol to support short object IDs, which would require either a `--pick-first` option or sending a list of possible matches back to the client.

The series touches transport protocols, the cat-file builtin, and test infrastructure, with thorough test coverage across git://, file://, and http:// transports. All substantive review comments from Junio Hamano, Patrick Steinhardt, and others have been resolved, including type-safety fixes and iteration-direction rationale for capability validation. The code is rebased on current master and carries Reviewed-by tags from key reviewers.
