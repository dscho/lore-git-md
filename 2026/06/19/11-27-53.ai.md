This is a cleanup patch (5/10) in Patrick Steinhardt’s 10-part refactoring series modernizing Git’s reference backend. It removes the now-unused `chdir_notify_reparent()` function from the `chdir_notify` subsystem after the previous patch (4/10) migrated all callers to the full registration/unregistration API. The change is mechanical and uncontroversial: the function was introduced as a convenience wrapper for reparenting relative paths during directory changes, but the series’ broader lifecycle management improvements made it redundant.

The patch deletes 26 lines from `chdir-notify.c` (the entire `reparent_cb` helper and the wrapper function) and updates the header file to remove the function declaration while preserving the documentation for the remaining `reparent_relative_path()` helper. No behavior changes are introduced; this is purely dead-code elimination following the architectural shift in patch 4/10. The diff is minimal and self-contained, touching only the `chdir-notify` files.

This patch is part of the series’ focus on fixing latent bugs in the `chdir_notify` subsystem, specifically ensuring reference stores are properly unregistered when released. The removal of `chdir_notify_reparent()` aligns with the goal of simplifying the API surface and enforcing explicit lifecycle management. As with the rest of the series, the changes are motivated by the need to stabilize ref backend initialization and avoid recursive issues, though this particular patch is a straightforward follow-up to earlier work.

The patch is unlikely to attract significant discussion, as it merely cleans up after the substantive changes in patch 4/10. It reflects the series’ incremental approach to refactoring, where each step builds on the previous one to avoid breaking existing functionality. The `chdir_notify` subsystem is a small but critical part of Git’s setup process, and this patch contributes to its long-term maintainability.
