This is a **feature enhancement** to the existing `help.autoCorrect=prompt` configuration option, part of the ongoing discussion about interactive typo correction for Git commands. The v2 patch abandons the earlier proposal to change the default behavior and instead focuses on a targeted improvement: preserving the user’s original arguments in the autocorrect prompt.

The patch updates `help_unknown_cmd()` in `help.c` to accept the full argument vector, allowing the prompt to show the complete corrected command (e.g., `Run 'git checkout neo' instead [y/N]?`) rather than just the command name. This addresses a usability gap in the current `autocorrect=prompt` implementation, where users are left uncertain whether their arguments will be preserved. The change is backward-compatible: callers that cannot provide the argument vector (like `builtin/help.c`) pass `NULL`, and the prompt falls back to the old format.

Test coverage is reduced in this version, as the patch no longer tests the default interactive behavior (which was the most controversial part of v1). The remaining test verifies that the prompt now includes arguments when `help.autocorrect=prompt` is set. The patch touches only `help.c` and its test file, with no new symbols exposed outside the help subsystem.
