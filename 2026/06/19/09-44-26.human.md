This is the core implementation patch in Matt Hunter’s now-merged 8-patch series introducing the global `fetch.followRemoteHEAD` configuration option. It adds the new `fetch.followRemoteHEAD` setting that acts as a fallback for all remotes lacking a `remote.<name>.followRemoteHEAD` value, following the established `fetch.prune`/`remote.*.prune` precedence pattern.

The patch wires the configuration variable into the fetch machinery: `git_fetch_config` parses the setting, storing it in the `fetch_config` struct, and `do_fetch` consults it only when no remote-specific value exists. The implementation excludes the “warn-if-not-$branch” value at the global level (it’s inherently remote-specific) and emits a warning for unrecognized values, matching per-remote behavior. A `NEEDSWORK` comment flags the opportunity to defer warnings until the value is actually consulted, avoiding noise when the global setting is overridden.

Documentation updates in `config/fetch.adoc` and `config/remote.adoc` clarify the relationship between the two variables, and the advice message in `builtin/fetch.c` now references both. The 105-line test suite in `t5510-fetch.sh` verifies feature parity, precedence rules, and edge cases (dangling symrefs, `--quiet` interaction, refspec fetches). The patch is conservative, maintaining backward compatibility and requiring no changes to existing user workflows.
