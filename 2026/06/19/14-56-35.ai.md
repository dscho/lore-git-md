This is a refactoring patch in the ongoing `git cat-file --batch-command` security-hardened series (v13/12). It generalizes the existing `write_fetch_command_and_capabilities()` function into a more reusable `write_command_and_capabilities()` that can handle arbitrary protocol v2 commands, not just "fetch". The change is mechanical: the function signature is updated to accept a `command` string parameter, and all internal references are adjusted accordingly.

The patch touches three files: `connect.c` (where the function is implemented), `connect.h` (where it is declared), and `fetch-pack.c` (where it is called). The only behavioral change is replacing the hardcoded "fetch" string with the passed-in command, and updating a legacy hash algorithm check from `GIT_HASH_SHA1_LEGACY` to `GIT_HASH_SHA1` for consistency. The commit message explains that this refactoring enables future protocol v2 commands (like the "object-info" capability introduced earlier in the series) to reuse the same capability-writing logic.

This is a clean, well-contained refactoring that follows the established pattern of making functions more generic when new use cases arise. The change is small (13 insertions, 9 deletions) and does not alter the function's core behavior. It is part of the series' broader effort to enable secure, capability-based object metadata queries without full downloads, and specifically supports the "object-info" command introduced in patch 5/12. The patch is ready for merging as part of the larger series.
