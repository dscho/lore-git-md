This is the second patch in the v3 series that libifies the `ignore_case` global variable into `struct repo_config_values`. It migrates all usage sites—14 files across core Git subsystems (index, filesystem operations, Windows compatibility, and built-in commands)—to use the new `repo_ignore_case(the_repository)` getter instead of the global `ignore_case`. The patch is mechanical and aligns with the established pattern from prior work on `protect_hfs` and `protect_ntfs`.

The migration touches critical paths in `dir.c` (e.g., `git_fspathcmp`, `fspatheq`, `directory_exists_in_index`), where repeated getter calls may introduce measurable overhead. The authors acknowledge this trade-off in the cover letter as a necessary cost for eliminating global state. The Windows compatibility layer (`compat/win32/path-utils.c`) now includes `repository.h` to access the getter, avoiding a larger refactoring of function signatures. This dependency is noted as an intentional design choice.

No new tests are added, but the patch retains existing coverage by preserving the fallback logic (e.g., `repo->initialized` checks in the getter). The commit message explicitly calls out the Windows layering decision and the performance implications, addressing maintainer feedback from earlier iterations. This patch is the final step in the series and appears ready for integration, with no unresolved technical concerns.
