This is the first patch in the v3 series that libifies the `ignore_case` global variable into `struct repo_config_values`. It introduces the getter function `repo_ignore_case()` and adds the `ignore_case` field to the repository configuration structure.

The patch touches two files: `environment.c` and `environment.h`. In `environment.h`, it extends `struct repo_config_values` with an `ignore_case` field (initialized to 0 in `repo_config_values_init()`). In `environment.c`, it implements the getter function `repo_ignore_case()`, which checks `repo->initialized` before accessing the repository's configuration values, returning 0 if the repository is not yet initialized. This matches the pattern established by prior migrations of `protect_hfs` and `protect_ntfs` into the same structure.

The commit message explains the motivation clearly: reducing global state and aligning with the ongoing `the_repository` removal effort. The getter is designed to maintain backward compatibility and readability, and the patch retains the existing fallback behavior for uninitialized repositories. No new tests are added, as the patch does not change behavior—only the location of the state.

This patch is well-structured and follows project conventions. The getter's design, including the `repo->initialized` check, addresses Junio C Hamano's earlier feedback from v1. The patch is ready for integration and is part of a broader, well-motivated refactoring effort. The next patch in the series will handle the actual migration of the global variable and its usage sites.
