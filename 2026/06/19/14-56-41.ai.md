This is the final patch in the GSoC v13 series implementing secure remote object metadata queries via `git cat-file --batch-command`. It replaces the static allow-list for format placeholders with dynamic capability-based validation, closing a potential security gap where clients could request metadata types the server does not support.

The patch introduces a mapping between protocol options ("size", "type") and their corresponding format atoms ("objectsize", "objecttype"), then populates the `remote_allowed_atoms` string list based on what the server actually advertises. This ensures clients only attempt to use placeholders the server supports, preventing information leaks or protocol violations. The implementation maintains backward compatibility while being forward-compatible for future metadata types.

Key technical details include: backward iteration during capability filtering (necessary for safe list compaction), explicit type casting to `int` for the loop counter, and proper cleanup of all string lists. The patch also moves test utility functions to lib-cat-file.sh for reuse and ensures empty output lines when no supported placeholders are present.

This completes the security hardening begun in earlier patches: the series now has dynamic capability validation, strict protocol enforcement, input size limits, and comprehensive error handling. All prior review feedback from Junio Hamano, Chandra Pratap, and others has been addressed, with no outstanding objections. The series is ready for merging.
