This is the fourth iteration of Patrick Steinhardt’s ten-patch refactoring series that removes Git’s dependency on `chdir_notify_reparent()` by making reference backends consistently use absolute paths. The series has grown in scope to address a subtle recursion issue during refdb initialization triggered by `includeif.onbranch` config conditions.

The key change in v4 is architectural: instead of the v3 workaround that temporarily set `ref_storage_format` to `UNKNOWN`, v4 introduces a new `ignore_refdb` flag in `struct config_options`. This flag selectively disables `onbranch` includes during ref store initialization, preventing the recursion while preserving other include conditions (e.g., `includeif.gitdir`). Two new patches (7/10 and 8/10) move the parsing of `core.logAllRefUpdates` and `core.sharedRepository` back into the ref backends, making the config parsing more modular and avoiding the need for lazy-loading these settings. The recursion fix is now patch 9/10.

The first six patches remain unchanged from v3 and are uncontroversial: they inline a helper function, stop applying repository format settings twice, restrict the `GIT_REFERENCE_BACKEND` environment variable to repository contexts, unregister ref stores from `chdir_notify`, remove an unused function, and fix a memory leak by freeing the main refdb. The final patch (10/10) is a small optimization to `refs_compute_filesystem_location()`.

The series is well-motivated and addresses a real technical debt in the ref backend infrastructure. The v4 design responds directly to Jeff King’s critique of v3 by tackling the root cause (recursive config parsing) rather than its symptom. The new approach looks clean and should satisfy reviewers who wanted a more principled solution. The patches are likely to be ready for merging once the new design is validated in review.
