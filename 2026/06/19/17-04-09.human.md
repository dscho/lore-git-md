This is a **feature patch** that refines Git’s typo-correction prompt. The v2 revision abandons the earlier proposal to change the default behavior and instead builds on the existing `help.autoCorrect=prompt` configuration option. When enabled, the prompt now shows the full corrected command line—including the user’s original arguments—rather than just the corrected command name. For example, if the user types `git comit --amend`, the prompt now asks “Run `git commit --amend` instead [y/N]?” instead of the current “Run `commit` instead [y/N]?”.

The patch touches only the help subsystem (`help.c` and its callers) and adds no new configuration knobs or on-disk formats. It is a pure usability tweak that makes the existing prompt more informative. The implementation is straightforward: `help_unknown_cmd()` now accepts the original argument vector so it can reconstruct the intended command line, and the TTY-detection logic remains unchanged.

Test coverage is minimal but sufficient: a single new test verifies that the prompt includes the arguments when `help.autoCorrect=prompt` is set. The patch removes several tests that were specific to the abandoned default-behavior change, so the net diff is actually smaller than v1.

Junio and Justin’s feedback on v1—questioning the necessity of changing the default and suggesting the patch should extend the existing config option rather than reimplement it—has been fully addressed. This version is uncontroversial on technical grounds and appears ready to merge if the maintainer agrees the argument-preservation feature is worth the small code churn. The only remaining open question is whether the improvement is significant enough to justify inclusion, but the patch itself is clean and well-scoped.
