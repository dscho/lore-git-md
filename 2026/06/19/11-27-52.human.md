This is a refactoring patch (4/10 in Patrick Steinhardt’s v4 series) that fixes a lifecycle issue in Git’s reference backends. The patch ensures reference stores properly unregister from the `chdir_notify` subsystem when released, preventing potential use-after-free bugs and memory leaks.

The problem is straightforward: when Git creates a reference store (for the main repository, submodules, or worktrees), it registers the store with `chdir_notify` to handle relative path updates if the working directory changes. However, it never unregisters these stores when they are freed, which could lead to dangling pointers—especially for submodule and worktree stores that *are* freed during `repo_clear()`. While this hasn’t caused visible issues (Git doesn’t often change directories mid-process), it’s clearly a latent bug.

The fix is mechanical but thorough: each backend (files, packed, reftable) now uses `chdir_notify_register()` instead of `chdir_notify_reparent()`, and adds a corresponding `chdir_notify_unregister()` call in its release function. The patch also introduces per-backend reparenting callbacks to replace the inline logic previously handled by `chdir_notify_reparent()`. This change is low-risk and aligns with the series’ broader goal of cleaning up ref backend initialization.

This patch is uncontroversial and well-motivated. It’s part of a larger effort to modernize Git’s ref storage layer, and the fix itself is a textbook example of proper resource management. The only follow-up mentioned is a later patch to address the leak of the main reference database, which remains registered (and thus hidden from leak checkers). For anyone tracking the ref backend work, this is a small but necessary step forward.
