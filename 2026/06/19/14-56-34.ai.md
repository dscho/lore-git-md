This is a refactoring patch in the GSoC RFC v13 series implementing `git cat-file --batch-command` for remote object metadata queries. Patch 5/12 moves `write_fetch_command_and_capabilities()` from `fetch-pack.c` to `connect.c` to make it reusable for future protocol v2 commands, particularly the upcoming `object-info` capability.

The patch addresses a subtle design constraint: the function depends on `advertise_sid`, which was originally a static variable in `fetch-pack.c`. Since `connect.c` cannot access that static, the patch replaces the dynamic modification in `do_fetch_pack()` (which only applies to protocol v1) with a direct `repo_config_get_bool()` call at initialization. This is safe because the function is only used in protocol v2, where the config-based value is authoritative.

The change is mechanical and well-justified: the commit message explains the static-variable limitation, the protocol v1/v2 distinction, and the config dependency. The diff is clean, moving 31 lines from `fetch-pack.c` to `connect.c` and adding the necessary declaration to `connect.h`. No behavior changes are introduced, and the patch prepares the ground for the next commit’s refactoring of this function into a more general-purpose capability writer.
