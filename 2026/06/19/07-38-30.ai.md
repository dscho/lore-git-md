This is a **design discussion reply** to Erik Östlund’s RFC on pinned references. Patrick Steinhardt responds by pointing out that Git already has a mechanism that *almost* does what Erik wants: the `<describeOutput>` syntax from `gitrevisions(7)`.

Patrick shows that `git rev-parse v2.54.0-0-g0b13e48a3` will resolve to the commit ID `0b13e48a3...` if the tag `v2.54.0` points to that commit, or to a different commit ID if it doesn’t. This gives users a way to combine a human-readable tag name with a specific object ID in a single string. However, as Patrick notes, Git does *not* verify that the tag and the object ID actually match—it just resolves the string to whatever commit the tag currently points to. If the tag has been moved, the result can be confusing or wrong.

The key takeaway is that Git already has a syntax for expressing "tag plus expected OID," but it lacks the enforcement Erik wants. Patrick doesn’t take a position on whether Erik’s proposal is worth pursuing, but he does highlight that the existing `<describeOutput>` syntax is under-documented and surprising to users. If Erik’s pinned references idea gains traction, the discussion will likely revolve around whether to extend the existing syntax (e.g., by adding a `--verify` flag to `git rev-parse`) or introduce a new mechanism altogether.

For now, this reply provides a concrete alternative to Erik’s strawman syntax and clarifies that the core functionality—combining a ref and an OID—is already possible, just not enforced. The thread is still in the exploratory phase, with no code or patches yet.
