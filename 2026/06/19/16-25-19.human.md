This is a **design discussion reply** in the ongoing thread about "pinned references" — a proposed Git feature that would combine a reference (like a tag) with an expected object ID, ensuring both exist and match. Junio C Hamano, the Git maintainer, responds to Patrick Steinhardt’s observation that Git already has a syntax (`<describeOutput>`) that expresses "tag plus OID" but does not enforce the invariant.

Junio treats the idea as a thought experiment rather than a serious proposal. He outlines how the existing `<describeOutput>` syntax (e.g., `v2.54.0-0-g0b13e48a3`) *could* be made to enforce the invariant: if the "hop count" is `-0-`, Git could verify that the hexadecimal part exactly matches the object ID the tag points to; if the hop count is non-zero, Git could verify that the hexadecimal part names a descendant of the tag’s commit. However, he immediately dismisses the idea of actually implementing this, calling it "very unlikely we would change this" — a clear signal that the existing behavior is not going to be altered.

This reply does not advance the pinned references proposal itself, but it does clarify the project’s stance on the existing `<describeOutput>` mechanism: it is intentionally loose, and that looseness is not up for reconsideration. For Erik Östlund’s pinned references idea to move forward, it will need to be implemented as a new feature — either a new syntax, a new command-line option, or a new command — rather than as a modification to the existing `<describeOutput>` behavior. The thread remains in the exploratory phase, with no code or patches yet.
