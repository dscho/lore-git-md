This is the first patch in a two-part refactoring series (v3) that moves Git’s global `ignore_case` variable into `struct repo_config_values`. The patch itself is small—just 16 lines across `environment.c` and `environment.h`—and introduces the `repo_ignore_case()` getter function. The getter follows the established pattern from earlier migrations (`protect_hfs`, `protect_ntfs`) by checking `repo->initialized` before accessing the repository’s config values, ensuring safe fallback behavior.

The motivation is clear: eliminating a global variable aligns with the ongoing `the_repository` removal effort, and the change is purely mechanical with no behavior differences. The patch is well-explained in the commit message, which explicitly ties it to prior work and mentorship. No tests are added, but the existing test suite should catch any regressions in case-insensitive filesystem operations.

This patch is ready for merging; the only remaining discussion in the series revolves around performance trade-offs in `dir.c` (addressed in patch 2/2), not this one.
