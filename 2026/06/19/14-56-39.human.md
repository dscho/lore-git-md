This is the tenth patch in the v13 series implementing `git cat-file --batch-command` support for querying remote object metadata. It adds the `remote-object-info` command, which lets users fetch object sizes (and eventually other metadata) from a remote repository without downloading the full objects.

The patch introduces a new command that works differently from existing `cat-file --batch-command` commands. While `info` processes one object at a time, `remote-object-info` accepts multiple object IDs in a single request to minimize network overhead. The implementation carefully avoids downloading objects by checking server capabilities first and only requesting supported metadata fields (currently just objectsize). The command works with both regular and `--buffer` modes, and includes thorough input validation - rejecting short OIDs, malformed inputs, and unsupported format placeholders.

The test coverage is extensive, with 680 lines of new tests verifying behavior across git://, file://, and http:// transports, including edge cases like protocol version mismatches, missing objects, and invalid inputs. The tests confirm the command works without downloading objects and properly handles server configuration (like transfer.advertiseobjectinfo). The implementation maintains security by strictly validating server capabilities and enforcing protocol v2 requirements.

This is a well-crafted feature addition that fits cleanly into the existing `cat-file` infrastructure while addressing a real use case - efficiently checking object sizes before deciding whether to fetch them. The thorough test coverage and careful attention to edge cases suggest it's ready for merging.
