This is a **reply in the refactoring series** for Git’s reference backend, specifically addressing Jeff King’s substantive critique of **patch 7/8**. Patrick Steinhardt acknowledges Peff’s architectural concern but pushes back on the proposed solution, proposing instead a narrower fix that disables only "onbranch" includes during ref store initialization.

Patrick argues that Peff’s suggestion—reading ref backend config via `read_repository_format()`—would be overly broad and cumbersome, requiring every backend to opt into the mechanism. He also notes that disabling *all* includes (as `read_repository_format()` does) is unnecessary; only "onbranch" conditions cause the recursion. His counterproposal is to extend Git’s config subsystem with a new `ignore_refdb` toggle in `struct config_options`, allowing ref backends to parse config while explicitly skipping "onbranch" includes. This would preserve other include conditions (e.g., `includeif.gitdir`) while avoiding the recursion.

The reply suggests the series may take a fourth iteration (`v4`) to implement this new approach. If adopted, it would replace the current workaround (temporarily unsetting `ref_storage_format`) with a more targeted solution, addressing Peff’s root-cause critique without requiring a full split of config parsing. The trade-off is added complexity in the config subsystem, but Patrick frames it as a pragmatic middle ground.

This exchange keeps the series’ focus on incremental improvements while deferring larger architectural changes. The outcome will likely hinge on whether Peff (or others) find the `ignore_refdb` toggle acceptable, or if they push for a more invasive refactoring. For now, the patch remains in flux, with no clear consensus yet.
