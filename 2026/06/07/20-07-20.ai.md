This is an RFC patch proposing a behavior change for the experimental `git history reword` command, part of Patrick Steinhardt's larger `git history` feature effort. The patch comes from a relatively new contributor to this subsystem.

The change makes `git history reword` abort when the new commit message matches the original, unlike `git commit --amend` and `git rebase -i` which proceed regardless. The rationale is that `git history` (1) operates purely in-memory without touching the worktree/index (so there are no side effects to preserve) and (2) updates all branches containing the original commit (a more expensive operation than rebase's single-branch updates). The patch includes a test verifying the new behavior.

The author acknowledges this diverges from established amend/rebase behavior but argues the different constraints justify it. The implementation adds a message comparison check in builtin/history.c and updates t/t3451-history-reword.sh with a test case. The patch is well-structured with clear commit message and references to prior discussions.

This appears to be a thoughtful, narrowly-scoped change to the experimental command, though its divergence from existing behavior may warrant discussion. The RFC flag suggests the author is particularly interested in feedback on this design choice. The patch builds on Patrick Steinhardt's v11 `git history` series from January 2026.
