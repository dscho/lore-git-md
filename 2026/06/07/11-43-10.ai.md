This is a performance optimization patch (part 1 of 2) finalizing the lazy_queue pattern generalization into Git's core priority queue implementation. The patch folds the deferred removal optimization from builtin/describe.c into prio_queue itself, enabling automatic get+put fusion for all users of the data structure.

The key change makes prio_queue_get() defer actual removal until the next operation, allowing subsequent puts to become simple replaces that avoid full remove-rebalance-insert cycles. This matches Git's common commit traversal pattern of getting a commit then putting its parents. The optimization shows measurable speedups (1.7-2.7%) on traversal-heavy operations like merge-base and rev-list.

The patch eliminates three duplicate implementations of this pattern (from builtin/describe.c, builtin/show-branch.c, and commit.c) while maintaining the performance benefits. It also removes the now-unused prio_queue_replace() function and adds prio_queue_size() to properly handle the logical element count when there's a pending removal.

Performance benchmarks on a large monorepo show consistent improvements without regressions, with the most significant gains (2.69%) in merge-base calculations. The changes affect multiple subsystems but maintain compatibility through careful conversion of all callers to use the new access patterns.

This v3 iteration incorporates René Scharfe's suggestion to inline the deferred removal logic directly into get()/peek() functions, eliminating helper function overhead while maintaining clarity. With all substantive feedback addressed and performance benefits validated, this optimization appears ready for merging.
