This is a performance optimization patch series for Git's priority queue implementation, now in its third iteration. The series builds on previous discussion about optimizing the common get+put pattern in commit traversals.

The main optimization folds the lazy_queue pattern (deferring removals to allow subsequent puts to become simple replaces) into the core prio_queue implementation. This eliminates duplicate implementations in several callers while maintaining 3-6% speedups on traversal-heavy operations. The v3 iteration incorporates René Scharfe's suggestion to inline the deferred removal logic directly into get() and peek() functions, eliminating a helper function and improving clarity.

The second patch renames the internal `.nr` field to `.nr_internal` to prevent unsafe direct access from outside the prio_queue implementation, addressing correctness concerns raised in earlier reviews. This hardening change ensures all callers use the proper accessor functions.

The series has seen thorough review and benchmarking, with all substantive feedback addressed. Performance validation shows consistent 1.7-2.7% improvements on traversal-heavy operations like merge-base and rev-list, while maintaining neutral performance for code paths that already had manual fusion. The changes affect multiple subsystems including commit-reach, fetch-pack, and revision walking, but the impact is well-contained through consistent use of the new access patterns.

With all correctness concerns resolved and performance benefits validated, this series appears ready for merging. The optimization is particularly impactful for operations that heavily use priority queues in commit traversal patterns.
