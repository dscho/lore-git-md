This is the second patch in a two-part series optimizing Git's priority queue implementation. The first patch introduced deferred removal tracking and operation fusion to improve performance in traversal-heavy operations. This follow-up patch hardens the implementation by preventing unsafe direct access to internal queue fields.

The key change renames the internal `.nr` field to `.nr_internal` to force callers to use the new `prio_queue_size()` helper or `prio_queue_for_each()` macro instead of accessing the field directly. This catches both existing misuse and prevents future direct access. The patch updates all callers across 13 files to use the proper access patterns.

The changes are mechanical but important for correctness - they ensure all queue operations go through the proper interfaces that handle the deferred removal tracking correctly. The patch maintains the 1.7-2.7% performance improvements measured in the first patch while making the implementation more robust against misuse.

This completes the optimization series, which has gone through three iterations with thorough review and benchmarking. The changes affect multiple subsystems that use priority queues (commit-reach, fetch-pack, revision walking) but the impact is well-contained through consistent use of the new access patterns. With all correctness concerns addressed, this appears ready for merging.
