This thread discusses proposed behavior changes for the experimental `git history reword` command, part of Patrick Steinhardt's broader `git history` feature. The key debate centers on whether the command should abort when the new commit message matches the original (unlike similar commands like `git commit --amend`), and if so, whether this should be the default behavior or require a `--force` flag. Junio Hamano has weighed in, favoring the `--force` approach for consistency with Git's existing commands.

The discussion has expanded to consider output consistency across all `git history` subcommands (reword, fixup, split, drop), balancing Git's traditional "rule of silence" against the usability needs of a porcelain command. Pablo Sabater, the patch author, has been responsive to review feedback, most recently confirming a minor test simplification suggested by D. Ben Knoble (replacing a custom editor script with `GIT_EDITOR=true`). However, the core design questions remain open, particularly around default behaviors and output verbosity, with Junio's input making alignment with Git conventions a key consideration for moving forward.
