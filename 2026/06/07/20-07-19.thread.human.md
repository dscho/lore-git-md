This RFC thread discusses Pablo Sabater's proposed changes to the experimental `git history reword` command, part of Patrick Steinhardt's broader `git history` feature. The discussion has evolved through two versions, with v2 showing significant refinement based on feedback.

The core issue is how to handle cases where `git history reword` is called but the commit message remains unchanged. Junio Hamano successfully argued against making this an automatic abort, instead advocating for a `--force` flag approach to maintain consistency with Git's existing conventions. Pablo has accepted this direction in v2, dropping his earlier proposal for comprehensive feedback output (which will be addressed separately) to focus narrowly on the abort behavior.

Technical implementation now modifies `commit_tree_ext()` to support abort-on-identical-message when requested via flag, while allowing subcommands like `fixup` to proceed regardless. The tests have been optimized using `GIT_EDITOR=true` per D. Ben Knoble's suggestion. An open question remains about whether similar behavior should apply to `git history fixup --reedit-message`.

The discussion has touched on several related considerations: the balance between Git's "rule of silence" and porcelain command usability, appropriate flag naming (`--force` vs `--force-rewrite`), and how this new command relates to existing functionality like `git commit --amend` and rebase operations. Pablo has demonstrated good responsiveness to feedback while maintaining focus on the core technical change needed for the new command.
