Pablo Sabater has proposed an RFC patch series to modify the behavior of the experimental `git history reword` command, which is part of Patrick Steinhardt's broader `git history` feature. The first patch would make the command abort if the new commit message matches the original, citing performance concerns since `history reword` updates all branches containing the original commit. Patrick noted this change would need refinement to avoid affecting the related `fixup --reedit-message` subcommand. The second patch adds success feedback showing the original and rewritten commit hashes.

In response to the success feedback proposal, Patrick has raised substantive concerns about whether this aligns with Git's "rule of silence" principle, suggesting commands should only output when they can't fulfill a request. He questions why the feedback would only show the rewritten commit rather than HEAD or other affected branches, and why `reword` should be treated differently from other `history` subcommands. Patrick proposes that if such feedback is valuable, it might belong in a verbose mode consistently applied across all subcommands. While not rejecting the idea outright, his review signals the patch needs stronger justification and possibly a different approach. The discussion remains open on both the no-op abort behavior and the feedback mechanism.
