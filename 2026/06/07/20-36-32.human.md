This is a follow-up in the `diff.<driver>.process` RFC thread, addressing test implementation concerns. Michael Montalbo responds to Johannes Schindelin's review about Python-based test issues by reconsidering the use of scripting languages in Git's test suite.

Key points from the email:

1. **Test Implementation Concerns**: Michael acknowledges Johannes' feedback about Python dependency issues in the test implementation, particularly on Windows CI where Python may not be available. The current approach would make this the first non-p4 test in 20 years to require Python.

2. **Project Direction Alignment**: Michael recognizes that introducing Python dependency goes against the project's trend of reducing scripting language dependencies, as seen in recent efforts to remove Perl dependencies (Patrick Steinhardt's work) and prior conversions like the rot13-filter test helper from Perl to C.

3. **Re-evaluation of Approach**: Michael considers whether his other patch series (using Perl for shell parsing logic) might also conflict with project direction, showing willingness to reconsider implementation strategies to align with Git's testing philosophy.

4. **Alternative Solution**: Johannes had suggested using a C-based test helper (similar to test-tool pkt-line and test-rot13-filter) instead of Python, providing a prototype implementation as reference.

The discussion highlights an important technical decision point for the RFC series - whether to maintain the Python-based approach or switch to a C-based test helper that better aligns with Git's testing conventions and platform-specific concerns. Michael appears open to making this change, which would address the final significant implementation concern for the feature.
