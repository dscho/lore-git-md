This is a performance optimization for `git describe` that limits ref iteration to tags by default, avoiding unnecessary work when scanning repositories with many non-tag refs.

The patch modifies `builtin/describe.c` to pass a "refs/tags/" prefix to the ref iterator when `--all` is not specified, since the command already ignores non-tag refs in this case. The change is significant: benchmarks show a 3.1x speedup (196ms -> 63ms) when describing HEAD in a repository with 124,357 refs (only 330 of which are tags). The improvement comes from avoiding iteration over irrelevant refs entirely rather than filtering them out after the fact.

The commit includes a thorough performance test case in `t/perf/p6100-describe.sh` that creates 10,000 unrelated refs to demonstrate the optimization's impact. The benchmark results show clear wall-time and system time reductions, with the system time dropping from 123ms to just 12ms as the ref backend no longer needs to stat all those extra refs.

This appears to be a well-motivated optimization that maintains the existing behavior while improving performance in large repositories. The patch is small and focused, with clear benchmark evidence to support the change. The test addition provides regression protection for the optimization going forward.
