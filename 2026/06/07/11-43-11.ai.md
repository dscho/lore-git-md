This is the second patch in a performance optimization series for Git's priority queue implementation, now in its third iteration. The patch focuses on hardening the API against unsafe direct field access by renaming the internal `.nr` field to `.nr_internal` and introducing a `prio_queue_for_each()` macro for safe iteration.

The change prevents callers from directly accessing the queue's internal size counter, forcing them to use the proper accessor functions (`prio_queue_size()`, `prio_queue_get()`, or `prio_queue_peek()`). This addresses correctness concerns raised in earlier reviews about potential misuse of the internal state. The patch converts all existing direct `.nr` accesses across 13 files to use the new patterns, including loop conditions in builtin commands (describe, show-branch, last-modified) and core subsystems (commit-reach, fetch-pack, revision walking).

The implementation maintains the performance benefits from prior iterations (1.7-2.7% speedups on traversal-heavy operations) while adding safety. The new `prio_queue_for_each()` macro provides a clean way to walk queue elements while accounting for the deferred removal optimization (get_pending offset) introduced earlier in the series. Benchmark results from René Scharfe confirm the changes don't regress performance.

This patch completes the hardening work started in v2, with all substantive feedback addressed. The series appears ready for merging, having demonstrated both performance improvements and correctness across multiple subsystems that use priority queues for commit traversal.
