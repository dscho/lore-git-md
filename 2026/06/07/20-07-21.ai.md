This is the second patch in Pablo Sabater's RFC series improving the experimental `git history reword` command. The patch adds user feedback to confirm when a reword operation succeeds, addressing a UX gap compared to similar commands like `git commit --amend` and `git rebase -i` which provide explicit success messages.

The change is straightforward: it adds a message to stderr showing the original and rewritten commit hashes when the reword completes successfully. The implementation uses the existing `repo_find_unique_abbrev()` function to display shortened commit IDs consistently with other Git commands. A new test case verifies the output appears as expected.

This patch builds cleanly on the first one in the series (which added early abort for no-op rewrites) and continues the theme of making `git history reword` behave more like a polished porcelain command. The changes are well-contained, touching only the command implementation and its test file. The test coverage is thorough, checking both the presence and format of the new output.

As with the first patch, this appears to be the author's first contribution to the `git history` subsystem, but the quality of the implementation suggests familiarity with Git's codebase and testing framework. The patch follows standard formatting and includes a clear commit message explaining the motivation.
