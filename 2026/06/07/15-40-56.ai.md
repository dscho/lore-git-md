Performance optimization for `git ls-files` that filters pathspecs before expensive lstat operations. The patch changes `show_files()` to apply pathspec matching early when checking for deleted or modified files, avoiding unnecessary filesystem checks for non-matching paths. 

The performance impact is dramatic - on a large repository with 859k index entries, the `--deleted` check with a pathspec drops from 60.7s to 1.06s. The change maintains existing behavior for `--error-unmatch` by keeping the secondary pathspec check in `show_ce()`. 

Includes both a performance test (`t/perf/p3010-ls-files.sh`) showing the speedup and a functional test (`t/t3010-ls-files-killed-modified.sh`) verifying pathspec handling with wildcards. The optimization is particularly impactful for top-level pathspecs or those with leading wildcards that previously couldn't be pruned by `prune_index()`.

This is a well-motivated change with clear performance measurements and thorough test coverage. The optimization appears safe since it preserves all existing behavior while avoiding redundant work. The patch touches only the performance-critical path in `builtin/ls-files.c` while adding appropriate test coverage.
