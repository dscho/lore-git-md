Thread identity: RFC patch series proposing behavior changes for `git history reword` (experimental command in Patrick Steinhardt's `git history` feature). Author Pablo Sabater is new to this subsystem. Current version is v1 with two patches.

Core problem/goal:
1. Modify `git history reword` to abort when new commit message matches original (unlike `git commit --amend`/`git rebase -i`), citing expensive branch updates and in-memory-only operation constraints. Implementation needs refinement to avoid impacting `git history fixup --reedit-message` which shares the same `commit_tree_ext()` function.
2. Add success feedback after reword operation showing original/rewritten commit hashes, though Patrick Steinhardt questions this aligns with Git's "rule of silence" principle. Pablo Sabater's follow-up argues for feedback necessity while engaging with philosophical concerns.

Current status: Both patches build on Patrick Steinhardt's v11 `git history` series (Jan 2026). Patch 1 needs scoping refinement per Patrick's feedback. Patch 2's design discussion has progressed with Pablo acknowledging some review points (HEAD/branch feedback value) while maintaining core position on feedback necessity. Verbose mode emerges as potential compromise.

Key technical details:
- Changes in builtin/history.c and tests in t/t3451-history-reword.sh
- `repo_find_unique_abbrev()` used for hash feedback
- Shared `commit_tree_ext()` function requires careful behavior scoping
- Feedback would show original and rewritten commit hashes (invalidated original being key motivation)

Open questions:
- Is no-op abort behavior justified given command constraints? (patch 1)
- Does success feedback violate Git's rule of silence? (patch 2)
  - Pablo argues porcelain commands may warrant different standards
  - Verbose mode emerging as likely solution
- Should feedback include HEAD/branch updates in addition to commit hashes?
- Should feedback mechanism be generalized across all history subcommands?

Participant positions:

  - Acknowledges HEAD/branch feedback value
  - Open to verbose mode but maintains basic output needed
  - Suggests porcelain commands may differ from plumbing standards

  - Position on current discussion not yet stated
