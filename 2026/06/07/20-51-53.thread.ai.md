Thread identity: Performance optimization for `git describe` to limit ref iteration to tags by default, avoiding unnecessary work when scanning repositories with many non-tag refs. Originating author not specified.

Core problem or goal: Improve `git describe` performance by avoiding iteration over non-tag refs when they will be ignored anyway (when `--all` is not specified). The command already filters out non-tag refs in this case, but was previously doing so after iterating over all refs.

Current status: Single patch proposing the optimization, with benchmark showing 3.1x speedup (196ms -> 63ms) in a repository with 124,357 refs (330 tags). System time reduced from 123ms to 12ms by avoiding stat operations on irrelevant refs. Patrick Steinhardt has reviewed the patch and identified several areas needing improvement.

Key technical details: Modifies `builtin/describe.c` to pass "refs/tags/" prefix to ref iterator when `--all` is not specified. Adds performance test case in `t/perf/p6100-describe.sh` that creates 10,000 unrelated refs to demonstrate optimization impact. Patrick notes the test currently only covers the "files" ref backend and suggests it should be expanded.

Open questions and loose ends:
