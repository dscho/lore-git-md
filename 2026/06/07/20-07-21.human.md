This is the second patch in an RFC series improving the experimental `git history reword` command. It adds user feedback to make the command feel more polished and confirm when a reword operation succeeds.

The patch makes `git history reword` print a success message showing the original and rewritten commit hashes, addressing a UX gap where the command previously gave no output. This brings it closer to the behavior of commands like `git commit --amend` that provide feedback. The change is straightforward - just adding a fprintf() call to builtin/history.c - and comes with a test verifying the output appears.

The implementation is clean and the motivation is well-explained: porcelain commands should provide clear feedback about what they did. Since this is part of an experimental feature (Patrick Steinhardt's `git history` work), the RFC tag suggests the author is open to feedback on the exact messaging format, though the basic idea seems uncontroversial.

This patch is less contentious than the first in the series (which changed behavior to abort on no-op rewrites) and appears ready to merge pending any minor wording tweaks to the success message. The test coverage is thorough for the new behavior.
