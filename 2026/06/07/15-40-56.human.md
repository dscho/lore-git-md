Performance optimization for `git ls-files` with pathspecs. This patch from Tamir Duberstein addresses a performance bottleneck in `ls-files` when checking deleted/modified files against pathspecs. Currently, the command lstat()s every index entry before applying the pathspec filter, which is inefficient for large repositories.

The change moves the pathspec matching earlier in the process, before the expensive lstat() calls. Benchmark results show dramatic improvements - from 60 seconds down to 1 second for a test case with 859k index entries. The patch includes both performance tests and functional tests to verify the behavior remains correct, particularly around the `--error-unmatch` flag.

This appears to be a well-constructed optimization with thorough testing. The performance impact is substantial enough that it would benefit any user working with large repositories and pathspec filtering. The commit message clearly explains the problem and solution, and the benchmark data provides concrete evidence of the improvement.
