This is a review of a patch in the `diff.<driver>.process` series, focusing on test implementation concerns. Johannes Schindelin identifies several issues with the Python-based test implementation and suggests moving to a C-based approach instead.

Key points from the review:

1. **Test Implementation Issues**:
   - The test script fails on Windows CI due to Python availability assumptions
   - The Python script uses Python3-specific syntax (f-strings) but tries to run with Python2
   - The heredoc approach makes static analysis difficult
   - The test would be the first non-p4 test in 20 years to require Python

2. **Suggested Improvements**:
   - Follows the project's direction of reducing scripting language dependencies
   - Points to prior art using C-based test helpers (test-tool pkt-line, test-rot13-filter)
   - Provides a prototype implementation using test-tool diff-process-backend
   - Notes the complexity of the test may require a C implementation anyway

3. **Project Context**:
   - References recent efforts to remove Perl dependencies (Patrick Steinhardt's work)
   - Notes established patterns for test fixtures (using t/NNNN directories rather than heredocs)
   - Highlights the project's preference for C-based test tools over scripting languages

The review is substantive, identifying real technical issues and providing concrete suggestions for improvement while situating the discussion within broader project trends. It represents a significant consideration for the patch series that will need to be addressed before merging.
