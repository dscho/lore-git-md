This is the final version of a performance optimization series for Git's priority queue implementation, now incorporating all feedback from previous iterations. The patch series:

1. Generalizes the lazy_queue optimization pattern (deferring removals to allow subsequent puts to become simple replaces) into the core prio_queue implementation, eliminating duplicate implementations in several callers while maintaining 3-6% speedups on traversal-heavy operations.

2. Hardens the implementation by renaming the internal `.nr` field to `.nr_internal` to prevent unsafe direct access from outside the prio_queue implementation, addressing correctness concerns raised in earlier reviews.

The v3 changes refine the implementation based on René Scharfe's suggestions, inlining the flush logic directly into get() and peek() functions and moving it below the LIFO early-return. Benchmark results show consistent 1.7-2.7% improvements on code paths that benefit from the new automatic fusion, while paths that already had manual fusion remain neutral.

The series has been thoroughly reviewed, with all identified direct field accesses converted to use proper accessors and edge cases properly handled across multiple subsystems. Junio C Hamano has indicated the correctness requirements are satisfied, and the performance improvements have been validated through rigorous benchmarking.

This optimization is particularly impactful for operations like merge-base calculations and revision walking that heavily use priority queues. The changes are well-scoped and the commit messages clearly explain both the optimization and safety improvements. The series appears ready for merging.
