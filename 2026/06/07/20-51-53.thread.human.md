The thread discusses a performance optimization for `git describe` that would limit ref iteration to tags by default, avoiding unnecessary work when scanning repositories with many non-tag refs. The original patch demonstrated a 3.1x speedup in a test repository with 124,357 refs (only 330 tags), showing particular improvement in system time by reducing stat operations on irrelevant refs.

Patrick Steinhardt has provided substantive technical feedback on the implementation. While agreeing with the optimization's premise, he identified several areas needing attention: benchmark presentation should use raw hyperfine format for clarity; the test script should avoid file-scoped variables; and the performance test should cover all ref backends, not just the files backend. He also noted the optimization's impact depends on repository structure (tag-to-ref ratio) and suggested a related but out-of-scope optimization possibility (wiring up exclude patterns). The patch author will need to address these points before the change can proceed.
