This is a technical review response to Jason Newton's worktree improvement proposal, focusing on edge cases and alternative approaches. The reviewer, brian m. carlson, raises several substantive questions about the proposed changes:

1. **Windows compatibility**: Notes that Windows ReFS supports copy-on-write and suggests looking at Git LFS's implementation. This expands the scope beyond just Linux/macOS filesystems.

2. **Dirty worktree handling**: Asks how the reflink approach handles cases where a worktree has unindexed changes when another worktree is created via reflink. This probes an important edge case that wasn't addressed in the original proposal.

3. **Branch contention**: Questions what happens when two worktrees sharing the same branch both try to commit changes, potentially leading to race conditions where one worktree's changes could be inadvertently reverted.

4. **Alternative approach**: Suggests using multiple refs pointing to the same commit as an alternative to shared-branch worktrees, noting this would work well with reftable backends. While not rejecting the proposal outright, this offers a different solution path.

The review is technically substantive, identifying real potential issues with the current implementation approach. The tone is constructive but probing - the reviewer clearly wants to ensure these edge cases are properly handled before the feature lands. The questions about dirty worktrees and branch contention in particular highlight scenarios that would need clear documentation if not code changes.
