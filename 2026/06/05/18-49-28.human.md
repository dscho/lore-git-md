This is the second patch in a two-part series introducing worktree improvements, focusing on allowing shared branch checkouts across worktrees.

The patch modifies `git worktree` to permit checking out the same branch in multiple worktrees, relaxing a longstanding restriction. The key change is replacing `die_if_checked_out()` with a more targeted `die_if_branch_busy()` that only prevents checkouts when a branch is actively being rebased or bisected in another worktree. This enables parallel work on the same branch across different worktrees while maintaining safety for operations that could be disrupted by concurrent branch modifications.

The implementation includes:
- Updated documentation explaining the new behavior
- A new helper function to detect "busy" branches (mid-rebase/bisect)
- Test updates showing successful shared branch checkouts
- Preservation of existing protections against force-updating busy branches

This change appears well-considered, addressing a real workflow limitation (parallel work on branches) while maintaining necessary safeguards. The patch follows naturally from the first in the series (which added copy-on-write worktree creation), together offering significant efficiency improvements for users managing multiple worktrees.
