This thread is about Matt Hunter’s 7-patch series introducing a global `fetch.followRemoteHEAD` configuration option, which builds on Git 2.48’s per-remote `remote.<name>.followRemoteHEAD` setting. The goal is to eliminate repetitive per-remote configuration while preserving override capability, following the established `fetch.prune`/`remote.*.prune` pattern.

The implementation is complete, with v2 addressing all substantive feedback. Key aspects include a new global setting that acts as a fallback when no remote-specific value exists, case-sensitive value matching, and exclusion of the "warn-if-not-$branch" value at the global level. The series touches configuration handling, fetch machinery, refactored `set_head()` behavior, advice system integration, and documentation, with thorough test coverage in `t5510-fetch.sh`. Junio Hamano and Jeff King reviewed the design and technical approach, and all concerns have been resolved.

The final patch in the series is a trivial whitespace fix in `builtin/fetch.c`, aligning a comment to match surrounding indentation. With this, the series is now fully ready for merging. The only remaining discussion points are edge cases around remote definition behavior (acknowledged as historical artifacts) and potential future work to unify clone behavior, though the latter is distinct from this effort.
