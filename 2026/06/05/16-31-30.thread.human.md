This thread implements a global `fetch.followRemoteHEAD` configuration option, allowing users to set a consistent default fetch behavior across all remotes while preserving per-remote override capability. The feature, proposed by Matt Hunter as a 7-patch series (v2), builds on Git 2.48’s per-remote `remote.<name>.followRemoteHEAD` and follows the established `fetch.prune`/`remote.*.prune` precedence pattern.

The implementation is now complete and ready for merging. Key aspects include a new global setting that acts as a fallback when no remote-specific configuration exists, explicit exclusion of the "warn-if-not-$branch" value at the global level (as it’s inherently remote-specific), and comprehensive updates to configuration handling, fetch machinery, and documentation. The series also includes thorough test coverage for edge cases and feature parity. The last design question—how to handle invalid configuration values—was resolved by adopting the same behavior as per-remote settings: warning users (with a `NEEDSWORK` comment for future improvement) and falling back to "never" for unrecognized values, which is more user-friendly than failing outright.

Junio C Hamano, the maintainer, provided critical review feedback and ultimately accepted the resolution, calling the work "excellent" and signaling merge-readiness. Jeff King and Bence Ferdinandy also contributed to validating the technical approach and clone behavior distinctions. The series is functionally complete, with all substantive feedback addressed, and connects to broader discussions about remote configuration consistency.
