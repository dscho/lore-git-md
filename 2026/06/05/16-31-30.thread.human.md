This thread implements a global `fetch.followRemoteHEAD` configuration option, extending Git 2.48's per-remote `remote.<name>.followRemoteHEAD` to eliminate repetitive configuration while maintaining override capability. The 7-patch series from Matt Hunter is now functionally complete and ready for merging, with all substantive review feedback addressed in v2.

The implementation follows the established `fetch.prune`/`remote.*.prune` precedence pattern, where the global setting acts as a fallback when no remote-specific setting exists. It includes comprehensive documentation updates (man pages, configuration references, and advice system integration) and thorough test coverage in `t5510-fetch.sh`. Key technical details include case-sensitive value matching, proper enum state management, and decoupled `set_head()` behavior.

The only remaining concern is a design shortcoming in configuration value validation: invalid values are silently ignored without distinguishing whether they're actually needed.
