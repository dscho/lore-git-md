This thread implements a global `fetch.followRemoteHEAD` configuration option (Matt Hunter’s 7-patch series, v2) to eliminate repetitive per-remote setup while maintaining override capability. The series builds on Git 2.48’s per-remote `remote.<name>.followRemoteHEAD` and follows the established `fetch.prune`/`remote.*.prune` precedence pattern.

All substantive feedback has been addressed in v2, including configuration integration, case-sensitive value matching, documentation, and test coverage. The implementation spans configuration handling, fetch machinery, refactored `set_head()` behavior, advice system integration, and comprehensive test cases. Junio C Hamano’s final review raises a technical concern about silent handling of invalid configuration values—specifically, that unrecognized values for `fetch.followRemoteHEAD` are ignored without warning or error, even when the value is used. While this mirrors the existing behavior of the per-remote setting (and thus isn’t a regression), Junio suggests a follow-up patch to improve error handling consistency. The series is otherwise complete and ready for merging, with no remaining open questions.
