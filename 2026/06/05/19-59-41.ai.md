This is a review of Jason Newton's worktree improvements proposal, focusing on technical concerns about the copy-on-write and shared-branch functionality. The review comes from brian m. carlson, who raises several substantive questions about edge cases and potential pitfalls in the proposed changes.

For the reflink functionality (Patch 1), they note that Windows does support CoW via ReFS and suggest looking at Git LFS's implementation. More critically, they question how the patch handles dirty worktrees when reflinking occurs - specifically whether stale files might appear in the new worktree if the index hasn't been updated. They suggest this scenario should be documented in the commit message.

Regarding the shared-branch worktrees (Patch 2), brian m. carlson asks about the behavior when two worktrees on the same branch both try to commit - whether one might inadvertently revert the other's changes. They propose an alternative approach using multiple refs pointing to the same commit, which they note would be efficient with reftable, while still acknowledging the utility of the reflink optimization.

The review is substantive, engaging with the technical details of the implementation rather than surface-level concerns. It identifies specific scenarios that need consideration (dirty worktrees during reflink, concurrent commits on shared branches) and suggests concrete documentation improvements. The tone is constructive while probing for potential issues the author may need to address in a revision.
