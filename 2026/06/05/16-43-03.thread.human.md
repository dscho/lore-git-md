This thread addresses a performance regression in Git's ref-filter subsystem that affected common commands like `git branch`, `git branch --remotes`, and `git tag`. The slowdown occurred in repositories with many unrelated loose refs, where operations that previously took milliseconds could take nearly 3 seconds with 10,000 loose refs. The regression was introduced by a change that added `--start-after` functionality to ref iteration.

The fix restores optimized prefix-scoped iteration for commands that don't use `--start-after`, while maintaining the new functionality for those that do. The patch includes thorough performance tests showing the improvement - reducing runtime from ~2.8 seconds back to ~0.1 seconds for basic operations. Both Patrick Steinhardt and Junio Hamano reviewed the change, with Steinhardt analyzing the iterator behavior and Hamano considering future compatibility implications. The fix has been carefully crafted to maintain existing semantics while solving the performance issue.
