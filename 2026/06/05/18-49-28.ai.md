This is the second patch in Jason Newton's series improving worktree functionality, focusing on allowing shared-branch worktrees. The patch modifies Git's behavior to permit checking out the same branch in multiple worktrees, which was previously prohibited.

The change relaxes the restriction that prevented multiple worktrees from having the same branch checked out, while still maintaining protection against truly dangerous operations. The key distinction is that parallel checkouts of the same branch are now allowed, but checking out a branch that's mid-rebase or mid-bisect in another worktree is still blocked (unless forced). This enables workflows where multiple agents need to work on the same branch simultaneously.

The implementation:
- Replaces `die_if_checked_out()` with a more targeted `die_if_branch_busy()` that only blocks when a branch is actively being rebased or bisected
- Updates documentation to clarify the new behavior
- Adds tests demonstrating the relaxed checking behavior
- Maintains existing force-update protections for branches in use elsewhere

This change appears well-considered, with clear documentation updates and thorough test coverage. It addresses a real limitation in Git's worktree functionality that users have likely worked around in ad-hoc ways. The patch maintains safety where needed while enabling new parallel workflows.

The patch follows logically from the first in the series (which added copy-on-write worktree creation) as both aim to improve worktree scalability for parallel workflows. Together they provide both space efficiency (via reflinks) and workflow flexibility (via shared branches).
