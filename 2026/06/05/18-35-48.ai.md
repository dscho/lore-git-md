This is the first patch in v13 of Harald Nordgren's series adding `git branch --delete-forked` (formerly `--prune-merged`), introducing the core `--forked` filter capability that will be used by the deletion command. The patch adds a new `--forked` option to `git branch --list` that shows only branches whose upstream matches given patterns, either as exact refs (like "origin/main") or globs (like "origin/*").

The implementation integrates cleanly with Git's existing ref-filter machinery, adding the new filter type alongside `--merged` and `--contains`. Key technical aspects include:
- Exact patterns match full refnames (avoiding ambiguity)
- Globs match abbreviated upstream names (so "origin/*" works as expected)
- The filter can be combined with other filters like `--merged`
- Comprehensive test coverage verifies the matching behavior

This foundational change enables the subsequent patches to implement safe branch deletion based on upstream tracking status. The implementation appears solid after 13 iterations of review, with the filter logic now properly integrated into `apply_ref_filter()` and using `strvec` for pattern storage. The documentation clearly explains the new option's behavior and interaction with other filters.
