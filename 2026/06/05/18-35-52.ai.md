This is patch 5/6 in Harald Nordgren's v13 series adding `git branch --prune-merged` functionality, which provides safe way to automatically delete local branches that have been merged upstream. The series is in its final polishing phase before merging.

The patch adds a configurable opt-out mechanism via `branch.<name>.pruneMerged=false` to exempt specific branches from automatic pruning. This is useful for topic branches that may have additional development planned even after an initial version has been merged upstream. The implementation:

1. Adds documentation for the new config option in both the config and command man pages
2. Modifies the pruning logic to check the config setting before deletion
3. Reports skipped branches (unless --quiet is given) so users understand why branches were retained
4. Explicitly maintains that `git branch -d` ignores this setting and uses the normal merge check
5. Includes comprehensive tests verifying both the opt-out behavior and that `branch -d` remains unaffected

The safety model remains robust - branches are still protected if checked out, have missing upstreams, or have matching push/upstream destinations. This patch completes the series' goal of providing flexible automation while preserving user control over branch lifecycle management.

The implementation is clean and well-tested, with clear documentation explaining both the feature and its relationship to existing deletion mechanisms. This appears to be the final piece needed before the series can be merged.
