This is a feature proposal introducing two worktree-related improvements: copy-on-write worktree creation and shared-branch worktrees. The series comes from Jason Newton via GitGitGadget.

The first patch adds `--reflink` support to `git worktree add`, enabling copy-on-write worktree creation on supported filesystems (btrfs on Linux, APFS on macOS). This avoids the disk and I/O cost of full checkouts when creating multiple worktrees from the same repository. The patch includes platform-specific implementations (FICLONE for Linux, clonefile() for macOS) and falls back to normal checkouts on unsupported systems. Benchmarks show significant disk savings - from ~5.3GB for 4 normal worktrees down to near-zero additional usage with reflink.

The second patch changes worktree behavior to allow checking out the same branch in multiple worktrees, enabling parallel work on a single branch. The restriction against checking out branches mid-rebase or mid-bisect remains. This required updating two test assertions in t2400.

The changes look well-motivated for workflows involving many worktrees (like CI agents), with clear performance benefits demonstrated. The implementation appears thorough, adding new config options (`worktree.reflink`) and platform-specific handling while maintaining backwards compatibility. The benchmark results are compelling, though Windows support would need to rely on the fallback path since it lacks native reflink support.
