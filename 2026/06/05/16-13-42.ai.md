This is a feature patch adding metadata tracking to Git worktrees, now facing substantive questions about its design rationale. The author Norbert Kiesel responds to Phillip Wood's review by:

1. Defending the need for worktree-specific notes (distinct from branch descriptions) by citing use cases where worktrees serve as "group changes" containers where users switch between branches within the same worktree.

2. Engaging with the suggestion to track last-updated timestamps (from reflogs) rather than creation timestamps, proposing to support multiple sort options (created, last-updated, name) and drawing a parallel to GNU ls's time sorting options.

The technical implementation remains unchanged from previous versions, storing metadata in `.git/worktrees/<id>/created` (timestamp) and repurposing the existing description file mechanism for notes. The patch includes full test coverage and documentation updates.

Key points for future discussion tracking:
- The worktree-vs-branch description debate centers on whether worktree context is meaningfully distinct from branch context
- Timestamp usefulness hinges on whether creation time or last activity is more actionable for workflow management
- The author appears open to expanding sorting options but needs to demonstrate concrete user needs for the metadata features
