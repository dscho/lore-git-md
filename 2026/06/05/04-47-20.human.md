This is a follow-up in the ongoing discussion about repository mirroring, particularly for submodules. Benson Muite responds to Simon Richter's concerns about Debian's archival needs by proposing a concrete technical approach: allowing multiple URLs to be specified in `.gitmodules` files, with Git trying them in order when fetching.

The key idea is to extend the submodule configuration syntax to support multiple `url` entries, which would provide built-in fallback behavior when the primary source is unavailable. This directly addresses Simon's concern about Debian's need to maintain self-contained archives while still allowing fallback to original sources when needed.

Benson provides a clear example showing how this might look in practice, modifying the `linphone-desktop` project's `.gitmodules` to include both the GitLab and GitHub URLs for its SDK submodule. The proposal suggests this could be enhanced with user-configurable ordering or network proximity detection.

This represents a practical middle ground between Junio's insistence on a general solution (not submodule-specific) and Simon's real-world archival requirements. The approach leverages existing Git concepts while solving the immediate mirroring problem. However, as Benson notes, there are still open questions about how to handle URL ordering preferences that would need to be addressed in any implementation.
