The first patch introduces copy-on-write worktree creation using reflinks (supported on btrfs/Linux and macOS), which dramatically reduces disk usage when creating multiple worktrees from the same repository. The second patch, which just arrived, addresses a long-standing limitation by allowing the same branch to be checked out in multiple worktrees simultaneously. While Git previously blocked this entirely, the new behavior carefully maintains safety by still preventing checkouts of branches that are mid-rebase or mid-bisect in another worktree. This enables parallel workflows where multiple developers need to work on the same branch at once, a common scenario in team environments.

Both changes are well-considered, with thorough test coverage and clear documentation updates. The first patch provides space efficiency through copy-on-write, while the second enables workflow flexibility through shared branches.
