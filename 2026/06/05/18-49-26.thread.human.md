Jason Newton has proposed two improvements to `git worktree`: adding copy-on-write support for faster worktree creation on compatible filesystems (btrfs, macOS, and potentially Windows via ReFS), and allowing multiple worktrees to share the same branch while still protecting branches mid-operation like rebase or bisect. The initial implementation includes configuration options, thorough test coverage, and careful handling of edge cases.

brian m. carlson has provided the first substantive review, raising important technical considerations. For the copy-on-write feature, they note the need to handle dirty worktrees properly to avoid stale files appearing in new worktrees, suggesting this edge case be documented. They also point out Windows' ReFS support as an additional platform to address. Regarding shared-branch worktrees, they question how concurrent commits would behave and propose an alternative approach using multiple refs, while acknowledging the value of the current implementation's reflink optimization. These points will likely need addressing in a revised version of the patches.
