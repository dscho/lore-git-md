This is a performance bugfix targeting the ref-filter subsystem, addressing a regression in `git branch`, `git branch --remotes`, and `git tag` commands. The issue was introduced in commit dabecb9db2 ("for-each-ref: introduce a '--start-after' option", 2025-07-15) which changed how ref iteration works, causing these commands to unnecessarily scan all loose refs even when only looking for specific types (branches, tags).

The patch restores the original behavior by passing the namespace prefix during iterator construction rather than applying it later with a prefix seek. This avoids the performance hit from reading irrelevant loose refs. The fix comes with new performance tests showing dramatic improvements - from ~2.7 seconds down to ~0.1 seconds for these commands when there are many unrelated loose refs.

The change maintains compatibility with the `--start-after` option while fixing the performance regression for the common case. The patch includes detailed benchmark results showing the improvement and has been reviewed by Patrick Steinhardt and Junio Hamano. The regression has been present since Git 2.51.0, making this a worthwhile fix for users with repositories containing many loose refs.
