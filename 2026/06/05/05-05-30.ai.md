This is a follow-up in the ongoing discussion about repository mirroring, particularly for submodules in archival contexts like Debian's package repositories. Benson Muite responds to Simon Richter's concerns about maintaining self-contained archives when submodules reference external URLs.

The key technical proposal is an extension to `.gitmodules` syntax that would allow specifying multiple fallback URLs for each submodule, with a suggested default behavior of trying them in order when the primary URL fails. The example shows how this could work for the linphone-sdk submodule, listing both its GitLab and GitHub mirrors.

Benson also suggests the system could be enhanced with user-configurable ordering preferences or network proximity detection, though these are presented as potential future directions rather than concrete implementation details. The proposal attempts to address Simon's concern about external URL dependencies while working within the submodule framework, though it notably doesn't yet engage with Junio's strong preference for a repository-level solution rather than submodule-specific changes.

The email maintains focus on the archival use case while introducing a more concrete technical mechanism than previous discussions. However, it doesn't yet resolve the tension between submodule-specific solutions and the repository-wide approach favored by the maintainer.
