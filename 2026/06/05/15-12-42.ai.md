This is a review of patch 5/9 in Patrick Steinhardt's v2 series adding a "drop" subcommand to the experimental `git history` command. The patch introduces a new `RESET_HEAD_SKIP_REF_UPDATES` flag for `reset_head()` to allow updating the index and working tree without modifying references.

Phillip Wood provides a substantive review suggesting an alternative API design where updating HEAD would be opt-in rather than opt-out. He questions whether the current flag name (`SKIP_REF_UPDATES`) is the clearest approach given the existing `RESET_HEAD_ORIG_HEAD` flag, noting the confusing combination of requesting both ORIG_HEAD updates while skipping ref updates. Phillip also raises a naming concern about `reset_head()` itself if HEAD updates become optional, proposing alternatives like `reset_worktree()` or `update_working_copy()`.

The review engages with the technical design at a deeper level than surface syntax, focusing on API clarity and future maintainability. Phillip's suggestions would require updating existing callers but could result in a more intuitive interface. This feedback comes from someone with extensive experience in Git's sequencer and worktree handling code, making his perspective particularly relevant to this change.

Patrick will need to consider whether to adjust the API design in v3 based on this feedback or justify keeping the current approach. The review doesn't identify any correctness issues with the implementation itself, focusing instead on the higher-level interface design.
