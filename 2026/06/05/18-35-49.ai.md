This is patch 2/6 in Harald Nordgren's v13 series adding `git branch --delete-forked` functionality, which implements safe automated local branch cleanup. The series is in its final polishing phase before merging.

The patch modifies `delete_branches()` to add a "warn-only" mode for bulk branch deletion operations, rather than erroring out when encountering unmerged branches. This allows commands like the upcoming `--delete-forked` to continue processing other branches after warning about unmerged ones, while preserving the existing error behavior for direct `git branch -d` usage.

Key changes:
- Introduces a `DELETE_BRANCH_WARN_ONLY` flag in a new bitfield enum for branch deletion flags
- Modifies `check_branch_commit()` to issue warnings instead of errors when the warn-only flag is set
- Updates `delete_branches()` to pass through the flags and only return failure for non-warn cases
- Maintains existing behavior for all current callers by not setting the new flag

The implementation cleanly separates the concern of reporting unmerged branches from the actual deletion logic, while keeping all safety checks intact. This prepares for the bulk deletion use case in the series' main feature without disrupting existing workflows. The changes are well-contained to `builtin/branch.c` with comprehensive error handling preserved.
