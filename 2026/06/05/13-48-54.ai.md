This is a review of the final v12 patch series adding `git branch --prune-merged` functionality, focusing on the `--forked` filter implementation. Phillip Wood provides substantive technical feedback on the first patch in the series, which introduces the `--forked` option for branch listing. The review identifies several areas for improvement while acknowledging the overall approach.

Key points from the review:

1. **Remote name handling**: Phillip questions whether the implementation should support remote names (like `origin`) as aliases for `$remote/HEAD` to match `git checkout -b` behavior.

2. **Option ordering**: Suggests moving the `--forked` documentation to be grouped with other filtering options like `--merged` and `--contains` for logical consistency.

3. **Implementation details**:
   - Recommends avoiding forward declarations by reorganizing function placement
   - Proposes moving the filtering logic into `apply_ref_filter()` to avoid unnecessary allocations
   - Notes potential ambiguity with abbreviated refnames and suggests using full refs instead
   - Points out the quadratic matching algorithm but considers it acceptable for now

4. **API preferences**: Suggests using `strvec` instead of `string_list` since the util member isn't needed.

5. **Positive aspects**:
   - Likes the idea of making this a standard `--list` filter
   - Finds the basic implementation approach reasonable
   - Notes it should be straightforward to match on full refs and move code to filter-refs.c

The review maintains the series' technical completeness while identifying specific implementation refinements that would improve code quality and maintainability. Phillip's feedback focuses on architectural consistency and future extensibility rather than fundamental flaws, suggesting the patch is nearing readiness for merging after addressing these points.
