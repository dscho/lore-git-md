This is part 2/6 of Harald Nordgren's v13 series adding `git branch --delete-forked` for safe automated branch cleanup. The patch modifies the branch deletion machinery to support warning rather than erroring when unmerged branches are encountered during bulk operations.

The key change introduces a `DELETE_BRANCH_WARN_ONLY` flag that makes `delete_branches()` and `check_branch_commit()` emit warnings instead of errors for unmerged branches, while preserving the existing error behavior for single-branch deletions. This prepares the plumbing for the upcoming `--delete-forked` command which will operate on multiple branches at once.

The implementation:
- Adds a flags bitfield to replace boolean parameters in the deletion functions
- Maintains all existing safety checks (merged status, broken refs, etc.)
- Only affects the error/warning behavior - no functional changes to actual deletion logic
- Keeps the same detailed advice message for interactive `git branch -d` usage

This is a well-contained refactoring that cleanly separates the warning behavior from the core deletion logic. The patch follows the series' pattern of careful, incremental changes to the branch machinery while maintaining all safety guarantees. It's a straightforward change that enables the bulk operation behavior needed for the full `--delete-forked` feature.
