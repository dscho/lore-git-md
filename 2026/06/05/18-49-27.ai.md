This is the first patch in a series introducing copy-on-write worktree creation, implementing the `--reflink` option for `git worktree add`. The patch adds support for creating new worktrees via copy-on-write (reflink) clones on supported filesystems (btrfs/Linux via FICLONE, macOS via clonefile()). This avoids the disk and I/O overhead of full checkouts when creating multiple worktrees from the same repository.

The implementation introduces a new `reflink_file()` helper in copy.c that handles the low-level reflink operations, with platform-specific implementations for Linux and macOS. The worktree creation logic detects reflink support and falls back gracefully to normal checkouts when unavailable. The patch includes configuration via `worktree.reflink` (true/false/auto) and command-line options `--reflink`/`--no-reflink`.

Key technical aspects include:
- Filesystem capability probing upfront to avoid expensive fallbacks
- Preserving symlinks, modes, and directory structure during reflink
- Cloning the index to minimize subsequent checkout work
- Careful handling of edge cases like nested worktrees
- Comprehensive test coverage in t2400-worktree-add.sh

The benchmark results mentioned in the cover letter show significant disk savings (from ~5.3GB for 4 normal worktrees to near-zero allocation with reflink). The implementation appears well-considered, with attention to platform compatibility and graceful degradation. The patch touches core worktree functionality in builtin/worktree.c while maintaining existing protections against checking out branches mid-operation.
