Bugfix targeting the ref-filter subsystem, addressing a performance regression in `git branch`, `git branch --remotes`, and `git tag` commands when many unrelated loose refs exist.

The regression was introduced in commit dabecb9db2 ("for-each-ref: introduce a '--start-after' option", 2025-07-15) which changed how ref iteration handles namespace prefixes. The patch restores prefix-scoped iteration for commands that don't use --start-after, avoiding unnecessary I/O when reading loose refs. Performance tests show dramatic improvements - from ~2.8 seconds to ~0.1 seconds for basic operations in repositories with 10,000 unrelated loose refs.

The fix maintains the existing --start-after behavior while optimizing the common case where no start-after is needed. The change was reviewed by Patrick Steinhardt and Junio C Hamano, with Steinhardt noting the semantic differences in iterator construction versus seeking, and Hamano pointing out future compatibility considerations.

The patch includes comprehensive performance tests that clearly demonstrate the impact, showing the commands now scale independently of unrelated loose refs. The implementation carefully preserves the existing ref-filter state semantics while fixing the performance issue.
