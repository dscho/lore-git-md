This is a platform compatibility concern regarding the Rust integration in Git v2.55.0-rc0. Randall S. Becker reports that the build fails on NonStop systems because the `cargo` command (Rust's build system) is not available. The error occurs when trying to build the Rust components that are now enabled by default in this release candidate.

The email asks if there's a workaround for systems where Rust tooling isn't installed. This continues Randall's longstanding concerns about Rust's platform support, particularly for NonStop systems where he maintains the Git port. The question implies that the current build system doesn't gracefully fall back to pure C when Rust isn't available, despite Rust being technically optional.

This is likely to prompt discussion about build system modifications to better handle missing Rust toolchains, or whether the Rust components should remain opt-in rather than default-on for this release. The issue touches on the broader tension between advancing Git's memory safety through Rust and maintaining compatibility with platforms that lack Rust support.
