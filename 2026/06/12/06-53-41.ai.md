This is a review comment in the ongoing thread about memoized commit traversal optimization. Kristofer Karlsson suggests simplifying the cycle detection approach in the first patch of the series.

The key points:
- Questions whether falling back to a second reachability walk when cycles are detected is necessary
- Proposes instead dying immediately when cycles are found, since:
  * Cycles indicate misconfigured replacement refs
  * Current behavior already loops forever on cycles
  * Other parts of Git (do_lookup_replace_object, parse_commit_or_die) treat similar cases as fatal errors
- Argues the fallback path adds complexity while masking what should be considered an invalid state

This is a substantive review that engages with the technical tradeoffs of the current implementation. The reviewer provides specific examples of similar error handling elsewhere in Git to support their position. The comment focuses on a single aspect of the patch (cycle handling strategy) rather than proposing broader changes.

The suggestion would affect the first patch's behavior but doesn't challenge the overall optimization approach. This feedback comes after the patch has already gone through multiple iterations with Jeff King's review, indicating continued scrutiny of edge cases even in well-reviewed code.
