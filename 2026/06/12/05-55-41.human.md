This is patch 5/7 in Matt Hunter's series introducing a global `fetch.followRemoteHEAD` configuration option, building on the per-remote version added in Git 2.48. The patch refactors the fetch machinery to prepare for the new global default behavior.

The key change is introducing a new `FOLLOW_REMOTE_UNCONFIGURED` enum value to distinguish between an unset configuration and an explicit 'create' setting. This allows the fetch logic to properly fall back to the system default when no configuration exists. The patch moves the followRemoteHEAD decision-making into `do_fetch()` rather than having it handled implicitly in `set_head()`, which will enable the next patch to introduce the global configuration fallback.

The implementation maintains the existing behavior where remote-specific settings take precedence, and explicitly excludes the "warn-if-not-$branch" value from the global configuration scheme since that behavior is inherently remote-specific. The changes are mechanical but important groundwork for the feature - they ensure the fetch machinery can properly evaluate configuration precedence when the global option is introduced in the next patch.

This appears to be a well-structured intermediate step in the series, cleanly separating the refactoring from the actual feature introduction while maintaining all existing behavior. The patch follows Git's typical patterns for configuration precedence handling.
