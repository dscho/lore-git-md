This is the second patch in Pablo Sabater's v4 series improving `git log --graph` rendering of commits with excluded parents. The patch implements cascading indentation for visual root commits to prevent misleading vertical alignment in the graph output.

The key change from v3 is a redesign to indent the visual roots themselves rather than the commits following them. This creates clearer hierarchy while maintaining parent-child relationships. The implementation handles multiple visual roots with cascading indentation (starting from the second root) and includes extensive test coverage in a new t4218 test file.

One known edge case remains where the lookahead mechanism can't perfectly predict when a commit will become a visual root after history simplification, leading to suboptimal indentation in rare cases. The author has documented this with a NEEDSWORK comment but notes they're not deeply familiar with revision.c to fix it.

The patch appears technically sound with thorough test coverage. It addresses all previous feedback and seems merge-ready pending resolution of:
1. Junio's outstanding question about documenting the visualization rules
2. Potential final review from Phillip Wood/Jeff King on the architectural change
3. The documented lookahead edge case

The test infrastructure change (moving a helper to lib-log-graph.sh) was already reviewed positively in patch 1/2. This main implementation patch represents a significant redesign from v3 that appears to solve the original problem more elegantly.
