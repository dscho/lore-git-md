Performance optimization for `git ls-files` with pathspecs.

This is the final version of Tamir Duberstein's patch to optimize `git ls-files --deleted` and `--modified` by applying pathspec filtering before expensive `lstat()` calls. The patch has been approved by both Jeff King and Junio Hamano after addressing all technical feedback.

The key change moves pathspec matching earlier in the process to avoid unnecessary filesystem operations for non-matching entries. While the original version only applied this optimization for single pathspecs (to avoid potential performance regressions with multiple pathspecs), the maintainers agreed the optimization should apply universally for consistency with similar optimizations elsewhere in Git. The commit message documents this decision rationale.

Performance improvements are substantial - in one test case with 881,290 index entries, runtime for `--deleted` with a single pathspec dropped from 65.8 seconds to 5.0 seconds. The patch includes new performance tests to validate these improvements and ensure no regressions in other cases. Test coverage has been expanded to verify correct handling of wildcard pathspecs and error conditions.
