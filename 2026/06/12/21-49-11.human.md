This is a performance optimization series that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`), building on the existing optimization that was previously only available for `git tag --contains`. The series has gone through multiple iterations with substantive review feedback incorporated.

The key change in v4 is treating cyclic ancestry as a hard error rather than falling back to another reachability walk, which simplifies the code and aligns with Git's existing error handling patterns. The series now consists of three well-separated patches: cycle detection in commit-reach.c, enabling memoized traversal for all ref-filter commands, and improving error reporting for reachability walks.

Performance impact is significant - benchmarks show a 100x speedup with generation numbers (104s -> 467ms for 62k refs) and 10x without. The implementation maintains safety through cycle detection and preserves existing behavior while providing these optimizations. The patches have been thoroughly reviewed by Jeff King (Peff) with all identified issues addressed, and now include comprehensive test coverage for both correctness and performance across all affected commands.

This appears ready for merging with its robust safety mechanisms, validated performance improvements, and clean separation of concerns. The changes are particularly valuable for repositories with many refs where repeated `--contains` queries are common.
