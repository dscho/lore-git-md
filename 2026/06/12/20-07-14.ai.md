This is the third and final patch in Taylor Blau's series fixing MIDX incremental writes with custom base layers. The patch corrects the pack inclusion logic when using `--base` options with `git multi-pack-index write`.

The core issue addressed here is that `should_include_pack()` was incorrectly skipping packs that appeared in the current MIDX (`ctx->m`), when it should have been skipping packs from the base MIDX (`ctx->base_midx`) during incremental writes. This caused reachability problems for bitmaps when using custom base layers.

The patch modifies `should_include_pack()` to:
1. Use `ctx->base_midx` as the exclusion boundary for incremental writes
2. Fall back to `ctx->m` for non-incremental cases
3. Maintain the existing behavior for `to_include` filtering

The test changes convert two previously failing cases (`--base=none` and `--base=<hash>`) to expected successes, now that the pack inclusion logic correctly handles custom base layers. This completes the series' goal of making incremental MIDX writes work properly with custom bases.
