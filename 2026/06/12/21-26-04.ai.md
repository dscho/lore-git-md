This is a follow-up in the thread about optimizing ref-filter commands with memoized commit traversal, specifically addressing cycle detection in commit ancestry graphs.

Tamir Duberstein responds to Kristofer Karlsson's review of the cycle detection patch, agreeing with the suggestion to simplify the handling of commit graph cycles. The current implementation fell back to a slower reachability walk when cycles were detected, but Karlsson had argued this masked what should be treated as an invalid state (since cycles indicate misconfigured replacement refs).

Duberstein confirms the change will be made in v4 of the patch series, noting that while the existing MAXREPLACEDEPTH check doesn't catch this particular type of cycle (created through replacement commit parents), the principle of treating cycles as fatal errors still applies. This aligns with similar error handling in `do_lookup_replace_object()` and `parse_commit_or_die()` elsewhere in Git.

The response indicates the series continues to evolve based on substantive technical feedback, with the author demonstrating responsiveness to review suggestions that improve code quality and maintain consistency with Git's existing error handling patterns.
