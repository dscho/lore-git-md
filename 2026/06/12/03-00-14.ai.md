This is the second patch in a three-part series extending Git's memoized commit traversal optimization from just `git tag --contains` to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The optimization significantly speeds up these operations by reusing commit traversal results across multiple `--contains` queries.

The key change in this patch enables the memoized depth-first walk for all ref-filter commands when generation numbers are available, while keeping `git tag` on its existing path without generation numbers (since caching still helps when many tags share deep history). The implementation builds on the cycle detection safety mechanisms added in patch 1/3.

Performance improvements are substantial - benchmarks show a 100x speedup with generation numbers (104s -> 468ms for 62k refs) and 10x without. The patch includes new performance tests covering all three frontends (tag, branch, for-each-ref) and a synthetic shared history case. The test infrastructure is enhanced to create a realistic scenario with many refs sharing history.

The patch maintains careful separation from the error handling improvements that were split out into patch 3/3. It preserves existing behavior while providing these optimizations, addressing all review feedback from Jeff King (Peff) in previous iterations. The implementation is now well-tested with both functional and performance tests across all affected commands.

This appears ready for merging as part of the complete series, offering significant performance benefits for repositories with many refs while maintaining safety and correctness through the cycle detection foundation established in the first patch.
