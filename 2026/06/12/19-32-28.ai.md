This is a discussion about the role of AI in Git's code review process, continuing from Christian Couder's proposal to formalize AI-assisted reviews. Junio Hamano responds to the project's stance on requiring AI review as a gate for patch acceptance.

Junio makes a clear distinction between encouraging tool use and mandating it. He acknowledges the value of AI tools (and other automation like CI runs) in catching issues pre-submission, comparing them to GitHub's PR-driven CI which is available but not required. However, he firmly states the project should not mandate contributors to "bring your own token budget" - a reference to the cost barriers of commercial AI services.

The response emphasizes Git's culture of individual developer choice in tooling while maintaining high standards for patch quality. Junio notes that what ultimately matters is the output quality, not the tools used to achieve it. He leaves the door open for optional AI review services that could help less experienced contributors, drawing a parallel to how GitHub CI is offered as an optional resource today.

Key technical context includes:
- Reference to Sashiko (Linux kernel's AI tool) as an existing model
- Mention of CodingGuidelines/SubmittingPatches as potential configuration targets
- Comparison to GitHub CI's optional-but-valuable status
- The discussion remains at the policy level, with no specific technical implementation proposed
- Junio's position reflects Git's historical approach to tooling - supportive of automation but resistant to mandatory requirements that might exclude contributors

This email solidifies the project's position that while AI tools can be valuable aids, they should remain optional developer aids rather than becoming a formal part of the contribution workflow. The response maintains Git's tradition of valuing human judgment and accessibility over process automation.
