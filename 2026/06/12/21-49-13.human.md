Performance optimization extending memoized commit traversal to all ref-filter commands. This is the second patch in a series that brings the performance benefits of memoized commit traversal (previously only available for `git tag --contains`) to all ref-filter commands like `git branch --contains` and `git for-each-ref --contains`. The key change enables the optimization when generation numbers are available, while keeping the existing behavior for `git tag` without generation numbers.

The performance improvements are substantial - benchmarks show a 100x speedup (104s to 468ms) when checking 62k refs with generation numbers. The patch includes new performance tests that demonstrate these gains across all affected commands. The implementation builds on the cycle detection added in the first patch of the series, ensuring safety when processing replacement refs.

Jeff King (Peff) suggested this approach and has reviewed multiple iterations of the series. The patch maintains clean separation from the cycle detection and error handling changes in the other patches, focusing specifically on enabling the optimization across ref-filter commands. Test coverage is comprehensive, including both synthetic and real-world repository scenarios.
