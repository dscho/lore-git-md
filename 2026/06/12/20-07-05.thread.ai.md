Thread identity: Patch series from Taylor Blau addressing MIDX incremental writes with custom base layers. Subject focuses on fixing MIDX write path issues when using --base option, specifically handling custom base layers (--base=none or --base=<hash>) during incremental writes.

Core problem: The MIDX write path was not properly handling custom base layers during incremental writes, leading to incorrect reachability closure for bitmaps. This caused test failures when a helper function from another test file was used.

Current status: Series remains at v1 with 3 patches: 1) Moves test helper (`nth_line()`) from t5335 to shared lib-midx.sh (test infrastructure cleanup), 2) Fixes MIDX base layer passthrough by threading the incremental_base parameter through the write path, 3) Corrects pack inclusion logic for custom bases by using base_midx as the exclusion boundary during incremental writes. All test cases now pass, including previously failing scenarios for --base=none and --base=<hash>. Patrick Steinhardt's review of the third patch confirmed the fix's correctness but requested a commit message clarification regarding the mutual exclusivity assumption between `m` and `ctx->to_include` when using `--stdin-packs --incremental --base=<foo>`. The first patch received low-weight feedback from Patrick noting the stylistic oddity of placing a generic helper in `lib-midx.sh` but no objection to the change itself; Taylor acknowledged this but defended the move as pragmatic. No evidence of merge to any integration branch; series is under review and appears ready to proceed pending the commit message update for patch 3.

Key technical details: First patch was test infrastructure refactoring, moving a generic helper function (`nth_line()`) to a shared location (lib-midx.sh) to avoid duplication, despite its non-MIDX-specific nature. Second patch modified the MIDX write path in builtin/multi-pack-index.c to properly plumb the base layer parameter, including the `incremental_base` field in the `write_midx_context` struct and updating the `write_midx_internal()` function signature. Final patch adjusted pack selection logic in `should_include_pack()` to use `ctx->base_midx` for exclusion during incremental writes while preserving existing behavior for non-incremental cases. The revised logic now correctly handles the edge case where both `ctx->base_midx` and `ctx->to_include` may be set simultaneously when using `--stdin-packs --incremental --base=<foo>`.
