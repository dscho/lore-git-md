This is the second patch in a three-part series extending Git's memoized commit traversal optimization from `git tag --contains` to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The key change enables the optimization whenever generation numbers are available, providing significant performance improvements - benchmarks show a 100x speedup (104s to 468ms) for repositories with many refs.

The patch modifies `commit-reach.c` to use the memoized depth-first walk for all ref-filter commands when generation numbers exist, while keeping `git tag` on its original path when they don't. It adds comprehensive performance tests covering all affected commands, including a synthetic shared history case that improves from 0.72 to 0.03 seconds. The implementation builds on the cycle detection safety mechanisms added in patch 1/3.

The changes are well-motivated by real-world performance data and maintain backward compatibility. Test coverage is thorough, with new benchmarks added to track the optimization's impact across different command variants. The patch cleanly separates the performance optimization from the safety mechanisms (handled in 1/3) and error reporting (handled in 3/3), following Git's incremental patch series best practices.

This appears ready for merging as part of the complete series, having addressed all prior review feedback and demonstrating clear performance benefits while maintaining safety and correctness. The optimization will be particularly valuable for repositories with many refs where repeated `--contains` queries are common.
