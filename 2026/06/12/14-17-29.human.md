This is a review from Junio C Hamano on Matt Hunter's patch adding a global `fetch.followRemoteHEAD` configuration option. Junio focuses on two technical implementation details rather than the feature itself (which he notes he hasn't been following closely).

First, he objects to the case-insensitive parsing of configuration values (using `strcasecmp`), arguing it creates unnecessary inconsistency since the per-remote version (`remote.<name>.followRemoteHEAD`) is case-sensitive. He advocates for strict case matching to avoid user confusion and align with Git's general direction toward more precise configuration parsing.

Second, he questions whether failing with `die()` when encountering an invalid value is appropriate, especially for one-off fetches where the setting wouldn't even be used. He suggests this could unnecessarily break workflows where users have newer configuration values that older Git versions don't understand yet.

The review is substantive - it engages with the code's behavior and its implications for users, though Junio explicitly avoids commenting on the feature's overall merit. His feedback suggests the patch may need adjustments to configuration parsing behavior before merging.
