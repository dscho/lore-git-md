Taylor Blau has sent a 3-patch series addressing issues with incremental MIDX writes when using custom base layers. The problem was discovered when a test case (t5334) failed because it was trying to use a helper function that only existed in a different test file. Fixing this exposed deeper issues in how the MIDX write path handles custom base layers specified via `--base`.

The series first moves the test helper to a shared location, then fixes the MIDX code to properly pass through base layer specifications, and finally corrects the pack inclusion logic to handle custom bases properly. This ensures that `--base=none` and `--base=<hash>` now correctly produce incremental MIDX layers that maintain reachability closure for bitmaps. The changes are part of Taylor's ongoing work on the MIDX and geometric repacking infrastructure.

The patches appear well-structured, with each commit addressing a distinct aspect of the problem. The cover letter references SZEDER Gabor's original report and clearly explains the motivation behind the changes. This looks like a focused improvement to the MIDX functionality that should help maintain bitmap consistency when using custom base layers.
