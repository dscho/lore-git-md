This thread is about a three-patch series from Taylor Blau that fixes a bug in Git’s MIDX (multi-pack index) incremental write path when using custom base layers. The issue specifically affects the `--stdin-packs` code path, where the MIDX write logic was incorrectly handling `--base=none` or `--base=<hash>` during incremental updates, leading to improper reachability closure for bitmaps.

The series is now at v1 and under review. The first patch moves a test helper function to a shared location to avoid duplication, while the second and third patches fix the core bug by threading the base layer parameter through the write path and adjusting pack inclusion logic. All tests pass, including previously failing scenarios, but two commit messages still need clarification: one to emphasize the bug’s scope is limited to `--stdin-packs`, and another to explain why the mutual exclusivity assumption between certain variables no longer holds in this context.

Taylor and Patrick Steinhardt have engaged in a brief but substantive discussion about test coverage. Patrick, while acknowledging the fix is correct, expressed a preference for more direct verification that `--base=none` includes objects from *all* MIDX layers, not just the newest one. Taylor pushed back, arguing the existing tests are sufficient. The exchange remains unresolved but doesn’t block the series, which is otherwise ready to proceed once the commit messages are updated.
