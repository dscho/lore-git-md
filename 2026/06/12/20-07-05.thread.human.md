This thread is about a three-patch series from Taylor Blau that fixes issues with MIDX incremental writes when using custom base layers (`--base=none` or `--base=<hash>`). The series is now at v1 and addresses a bug where the MIDX write path failed to properly handle custom base layers during incremental writes, leading to incorrect reachability closure for bitmaps. The bug was confirmed to affect only the `--stdin-packs` path, not the normal MIDX write path.

The first patch moved a test helper function (`nth_line()`) from `t5335` to a shared location (`lib-midx.sh`) to avoid duplication, despite its generic nature. The second patch fixed the MIDX base layer passthrough by threading the `incremental_base` parameter through the write path, and the third patch corrected the pack inclusion logic for custom bases by using `ctx->base_midx` as the exclusion boundary during incremental writes. All test cases now pass, including previously failing scenarios for `--base=none` and `--base=<hash>`.

Patrick Steinhardt reviewed the series and confirmed the fix's correctness but requested clarifications in the commit messages for the second and third patches. The second patch's message needs to clarify that the bug applies only to the `--stdin-packs` path, while the third patch's message needs to accurately describe the mutual exclusivity (or lack thereof) between `m` and `ctx->to_include` when using `--stdin-packs --incremental --base=<foo>`. Taylor acknowledged these points and agreed to update the messages. The series is now effectively ready to proceed, pending these trivial documentation updates. The only remaining mild disagreement is over whether the existing test coverage for `--base=none` is sufficient, but this does not dispute the core fix's correctness. The series remains under review and has not been merged to any integration branch.
