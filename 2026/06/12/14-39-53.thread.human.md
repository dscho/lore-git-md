This thread is about a bug in Git's notes handling during rebase operations, where notes from commits that disappear during rebase (because their changes are already present in the target branch) incorrectly persist. Uwe Kleine-König submitted a test patch demonstrating the issue, which has been a workflow problem since 2023 for users tracking patch Message-Ids with notes.

Phillip Wood reviewed the patch and raised a practical concern about test organization: he suggests the new test case should be added to an existing test file (like `t3400-rebase.sh`) rather than creating a new one (`t/t3322-notes-rebase.sh`). He also noted that a potential fix was discussed in 2023 but never implemented due to lack of contributor bandwidth. The review doesn't dispute the bug's existence or propose an alternative fix, but it does highlight that the test structure could be improved. The core issue—a bug in the interaction between `notes.c` and `rebase.c`—remains unresolved, and it's still unclear whether similar problems exist in other operations like cherry-pick.
