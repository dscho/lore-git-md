This is the fourth version of a performance optimization series that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`), building on the existing optimization previously available only for `git tag --contains`. The key change in v4 is treating cyclic ancestry as a fatal error rather than falling back to another reachability walk, simplifying the code while maintaining safety.

The series consists of three well-separated patches:
1. Adds cycle detection in commit-reach.c to safely handle replacement refs, now updated to treat cycles as fatal errors (per Kristofer Karlsson's suggestion)
2. Enables memoized traversal for all ref-filter commands when generation numbers are available
3. Improves error reporting for reachability walks to match the memoized path's behavior

Performance impact remains significant - benchmarks show 100x speedup with generation numbers (104s -> 467ms for 62k refs) and 10x without. The implementation maintains safety through robust cycle detection and preserves existing behavior while providing these optimizations.

The patches have been thoroughly reviewed by Jeff King (Peff) across multiple iterations, with all identified issues addressed. Test coverage is comprehensive, including both functional tests for correctness (cycles, edge cases) and performance tests across all affected commands. The separation of concerns is clean, with cycle handling, optimization, and error reporting each getting their own focused patch.

This version appears ready for merging with its robust safety mechanisms, validated performance improvements, and comprehensive test coverage. The changes are particularly valuable for repositories with many refs where repeated `--contains` queries are common. The switch to treating cycles as fatal errors (rather than falling back) aligns with Git's existing error handling patterns and simplifies the code while maintaining safety.
