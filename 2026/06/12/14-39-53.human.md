This is a test case submission that demonstrates a bug in Git's notes handling during rebase. The author, Uwe Kleine-König, reports that when a commit disappears during rebase (because its changes are already present in the target branch), the notes from that commit incorrectly persist and get attached to the rebased parent commit.

The test creates a scenario with this commit graph:
```
A -- B -- C
 \
  \- BD
```
where BD contains the same changes as B. When rebasing C onto BD, the note attached to B should disappear, but currently it gets incorrectly transferred to BD. The author notes this causes problems when using notes to track patch Message-IDs during rebases of large patch series.

The patch adds a new test file `t/t3322-notes-rebase.sh` that sets up this scenario and includes a failing assertion that the note should not appear on BD after rebase. The test is marked as `test_expect_failure`, indicating the current behavior is wrong.

This appears to be a legitimate bug report with a clear reproduction case. The author previously reported this issue in 2023 but is now following up with a concrete test to help drive a fix. The test is well-structured and the commit message clearly explains the problem and motivation.
