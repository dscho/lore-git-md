This is the first patch in a three-part series that improves Git's handling of cyclic commit histories when using memoized traversal for `--contains` operations. The patch specifically addresses a safety issue where replacement refs could create cycles in the commit ancestry, potentially causing infinite loops or memory exhaustion.

The key change is introducing a `CONTAINS_IN_PROGRESS` state to detect cycles during traversal, treating them as fatal errors rather than falling back to another reachability walk. This aligns with Git's existing error handling patterns in similar scenarios. The implementation marks commits as "in progress" when they enter the traversal stack and dies if it encounters a commit that's already being processed.

The patch includes a new test case that verifies the cycle detection works by creating a cyclic replacement ref history and confirming the appropriate error is raised. This builds on Kristofer Karlsson's suggestion to simplify the code by treating cycles as errors rather than implementing fallback behavior.

This change provides a robust foundation for the subsequent performance optimizations in the series while maintaining safety. The patch has already undergone multiple rounds of review, with all identified issues addressed in this v4 iteration. The implementation is cleanly separated from the optimization logic that follows in later patches.
