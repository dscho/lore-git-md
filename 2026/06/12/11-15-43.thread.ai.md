Thread identity: Performance optimization proposal for commit reachability algorithms in `paint_down_to_common` function, affecting merge-base calculations. Authored by Kristofer Karlsson as RFC, now with substantive review from Derrick Stolee.

Core problem: Current merge-base computations may perform unnecessary traversal after one side of the comparison is fully processed. The proposal introduces an early termination condition when one branch's commits are fully traversed, with ongoing refinement to handle complex DAG topologies where multiple paths exist between commits.

Current status: RFC stage with theoretical proposal showing promising speedups (300x-1000x) in simple cases. Derrick Stolee identified cases where the initial optimization would fail to find all merge bases, prompting Karlsson to refine the termination condition to handle these cases while preserving performance benefits.

Key technical details: Targets `paint_down_to_common` in commit-reach.c. The refined optimization now considers both commit exhaustion and STALE bit propagation through the intersection of commit histories. The new termination condition requires both: (1) all P1 or all P2 commits exhausted, and (2) no remaining non-stale P1|P2 candidates in the queue. Analysis shows this correctly handles Stolee's counterexample graph, producing the correct single merge base [B] rather than the incorrect [B, C].

Open questions: Need to verify behavior with octopus merges and other edge cases. Implementation and testing against complex repository topologies remains pending. The scope may still need adjustment for cases where the optimization cannot guarantee correctness.
