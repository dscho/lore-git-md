This is the fourth version of Pablo Sabater's feature patch series improving `git log --graph` rendering of commits with excluded parents. The series has evolved from its initial placeholder-based approach to now using cascading indentation for visual root commits.

The key change in v4 is a complete redesign from the v3 approach - instead of indenting commits *following* visual roots, it now indents the visual roots themselves. This creates clearer visual hierarchy while maintaining unambiguous parent-child relationships. The patch includes extensive test cases demonstrating the improved output format.

The implementation handles multiple visual roots with cascading indentation (starting from the second root to avoid redundant indentation of the first). There's one known edge case where the lookahead mechanism can't perfectly predict when a commit will become a visual root after history simplification, leading to suboptimal indentation in rare cases. The author has documented this with a NEEDSWORK comment but notes they're not deeply familiar with revision.c to fix it.

The series comes with two patches:
1. A cleanup moving a common test helper function to a shared location
2. The main implementation adding visual root indentation

Test coverage appears thorough with a new dedicated test file (t4218) plus updates to existing graph tests. The author has addressed all previous feedback and the approach seems technically sound, though Junio's question about documenting the visualization rules remains open.

This appears to be in its final form with just the lookahead edge case and potential documentation updates as loose ends. The redesign in v4 suggests the author is actively refining the solution based on feedback, and the patch seems merge-ready pending resolution of those final items.
