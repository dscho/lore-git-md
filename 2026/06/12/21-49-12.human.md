This is the first patch in a three-part performance optimization series that extends Git's memoized commit traversal to all ref-filter commands. The patch specifically addresses a safety issue where replacement refs could create cycles in commit ancestry, which the memoized traversal previously couldn't handle.

The key change in this v4 iteration is treating cyclic ancestry as a fatal error rather than falling back to another reachability walk, following Kristofer Karlsson's suggestion. The patch marks commits as "in progress" during traversal and dies if it encounters an already-marked commit, preventing infinite loops. This approach aligns with Git's existing error handling patterns in similar cases.

The implementation adds a new `CONTAINS_IN_PROGRESS` state to track active commits and includes a test case that verifies the cycle detection works by creating a cyclic replacement ref history. The change is focused and well-contained, touching only the commit-reach.c/h files and adding a single test case.

This foundational patch enables the subsequent performance optimizations by ensuring they can safely handle edge cases. The series has undergone thorough review from Jeff King across multiple iterations, with all identified issues addressed. The cycle detection provides robust safety for the memoized traversal that will be leveraged in the following patches.
