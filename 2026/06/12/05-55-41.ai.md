This is the fifth patch in Matt Hunter's 7-part series introducing a global `fetch.followRemoteHEAD` configuration option. The patch refactors the fetch machinery to prepare for the new global setting by:

1. Adding a new `FOLLOW_REMOTE_UNCONFIGURED` enum value to distinguish between unset and explicitly configured states, with `FOLLOW_REMOTE_CREATE` becoming the system default.

2. Moving the followRemoteHEAD decision logic into `do_fetch()` where it can consider both remote-specific and (in the next patch) global configuration, falling back to the system default when needed.

3. Modifying `set_head()` to accept the followRemoteHEAD mode as a parameter rather than reading it directly from the remote struct, decoupling the behavior from the configuration source.

The changes maintain the existing behavior while making the necessary plumbing adjustments to support the upcoming global configuration. The patch preserves the special handling of 'warn-if-not-$branch' values, which remain remote-specific only. The implementation appears clean and focused, with clear separation between the refactoring and the actual feature addition (which will come in patch 6).
