This is the first patch in a GSoC participant's series to refactor path formatting logic in Git. It introduces a new `append_formatted_path()` helper in `path.c` that centralizes path formatting behavior previously duplicated in `rev-parse.c`.

The helper supports several formatting modes through a new `path_format` enum:
- `UNMODIFIED` (output path as-is)
- `RELATIVE` (make path relative to a prefix)
- `RELATIVE_IF_SHARED` (relative only if sharing a common root)
- `CANONICAL` (fully resolved absolute path)
- `DEFAULT` (treated as `UNMODIFIED`)

The implementation handles edge cases like NULL prefixes by falling back to the current working directory, and includes proper memory management with strbufs. The patch comes after substantive review from Justin Tobler and Lucas Seiki Oshiro, with the helper's API and behavior now well-defined.

This foundational change enables subsequent patches to extend `git repo info` with consistent path formatting while eliminating duplicate logic. The code looks clean and well-structured, with comprehensive strbuf handling and clear documentation of the enum values.
