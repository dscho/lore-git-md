This is a feature patch series introducing a global `fetch.followRemoteHEAD` configuration option, building on the per-remote `remote.<name>.followRemoteHEAD` introduced in Git 2.48. The series comes from Matt Hunter, who has clearly incorporated feedback from earlier discussion into this implementation.

The core motivation remains the same: currently, users who want consistent remote HEAD tracking behavior across multiple repositories must configure each remote individually, which becomes cumbersome. The new `fetch.followRemoteHEAD` provides a global default that applies to all remotes unless overridden by a remote-specific setting, following the same precedence pattern as `fetch.prune`/`remote.*.prune`.

The series includes several preparatory cleanups and documentation improvements before introducing the new feature. Notably, it excludes support for the "warn-if-not-$branch" value at the global level (as this was deemed too remote-specific in prior discussion) and maintains backward compatibility with existing per-remote settings. The implementation appears well-considered, with test coverage expanded to verify the new behavior.

This is the culmination of a well-run discussion where key technical points (namespace choice, clone behavior, value support) were validated by experienced contributors like Jeff King. The patches look ready for review, with the design questions already settled, this should be a straightforward addition that solves a real configuration management pain point.
