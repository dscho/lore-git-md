This is the first patch in a performance optimization series that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The patch focuses on making the optimization safe against cycles that can occur with replacement refs.

The key technical contribution is adding cycle detection to the commit-reach.c contains walk. The patch introduces a new `CONTAINS_IN_PROGRESS` state to mark commits during traversal, allowing it to detect cycles. When a cycle is found, it falls back to a cycle-safe reachability walk while maintaining the cache for future queries. The implementation includes comprehensive tests that verify correct handling of cyclic replacement ref histories.

This is a well-crafted patch that addresses a real safety issue in the optimization. It has already gone through multiple rounds of review (notably from Jeff King) and appears ready for merging. The changes are particularly valuable for repositories with many refs where repeated `--contains` queries are common.
