This is the first patch in a 3-part series that adds cycle detection to Git's memoized commit traversal optimization, which is being extended to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The patch specifically addresses a safety issue where replacement refs could create cycles that would cause the memoized traversal to exhaust memory.

The key changes are:
1. Adds a new `CONTAINS_IN_PROGRESS` state to track active commits during traversal
2. Detects cycles by checking for commits marked as in-progress
3. Falls back to a cycle-safe reachability walk when cycles are detected
4. Adds test coverage for cyclic replacement ref histories

The implementation maintains the optimization's performance benefits while ensuring safety against cycles. The patch has already gone through substantive review from Jeff King (Peff) in previous iterations, with all identified issues addressed. The test case demonstrates correct handling of replacement ref cycles while preserving the expected output behavior.

This is a well-contained change that cleanly separates the cycle detection logic from the broader optimization work in subsequent patches. The commit message clearly explains the problem being solved and the solution approach. The patch appears ready for merging as part of the larger performance optimization series.
