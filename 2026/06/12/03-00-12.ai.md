This is a performance optimization series that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`), building on the existing optimization that was previously available only for `git tag --contains`. The series has gone through multiple iterations with substantive review feedback incorporated.

The key changes in v3:
- Split error handling for missing ancestors into a separate patch (patch 3)
- Improved test coverage with performance benchmarks for all three frontends (tag, branch, for-each-ref)
- Removed an unrelated behavior change regarding empty target lists
- Added explanations for why `git tag` retains memoization even without generation numbers
- Cleaned up error handling to use `die()` consistently

The series now consists of three well-separated patches:
1. Adds cycle detection to the commit-reach.c contains walk to safely support replacement refs
2. Enables memoized traversal for all ref-filter commands when generation numbers are available
3. Improves error reporting for reachability walks

Performance impact is significant - benchmarks show a 100x speedup with generation numbers (104s -> 467ms for 62k refs) and 10x without. The implementation maintains safety through cycle detection and preserves existing behavior while providing these optimizations.

The patches have been thoroughly reviewed by Jeff King (Peff) with all identified issues addressed. The test suite now includes both functional tests for correctness and performance tests across all affected commands. The separation of concerns is clean, with cycle handling, optimization, and error reporting each getting their own focused patch.

This appears ready for merging with its robust safety mechanisms, validated performance improvements, and comprehensive test coverage. The changes are particularly valuable for repositories with many refs where repeated `--contains` queries are common.
