Thread identity: Usability improvement series to make Git's error messages more helpful when users accidentally swap or misformat remote/branch arguments, consisting of two patches: (1) `git branch --set-upstream-to` missing slash case, (2) `git push` slash-as-space case. Originating author: Harald Nordgren.

Core problem: Addresses two common command-line mistakes that frustrate users: (1) `git branch --set-upstream-to=origin main` (missing slash between remote and branch name), where the user likely intended `origin/main` but the command fails because the local branch `main` does not exist, and (2) `git push origin/main` (using slash instead of space to separate remote and refspec). The series aims to improve error messages to guide users toward correct syntax. The first patch's premise is contested by Junio C Hamano, who argues the current error message is accurate and sufficient, as the command requires the local branch to exist and the user's expectation does not align with its design. The second patch's premise remains unchallenged, but its implementation has drawn technical feedback.

Current status: v1 series resubmitted after initial silence. The first patch (branch upstream case) is in question following Junio's critique of its motivation. The second patch (push case) has received substantive technical feedback from Junio, who suggests improvements to code organization but does not dispute the feature's value. No other reviewers have engaged with either patch.

Key technical details:
- Introduces two new config options: `advice.setUpstreamFailure` (branch upstream case) and `advice.pushRepoLooksLikeRef` (push case).
- Modifies `builtin/branch.c` to detect missing slash in upstream argument, verify remote existence, and confirm matching remote-tracking ref. Junio's review questions whether this detection logic is necessary or desirable, given the command's existing semantics.
- Modifies `builtin/push.c` to identify slash-separated argument, validate remote portion, and exclude existing paths/repos. Junio's review critiques the implementation for unnecessary computation when advice is disabled and premature exit that prevents fallback to URL/path handling, recommending a helper function that runs only when advice is enabled.
- Test coverage added in `t/t3200-branch.sh` (branch cases) and `t/t5529-push-errors.sh` (push cases).
- Implementation maintains strict separation of concerns; changes are non-disruptive and focused solely on error messaging.
