Thread identity: Usability improvement series to make Git's error messages more helpful when users accidentally misformat remote/branch arguments (e.g., `git branch --set-upstream-to=origin main` or `git push origin/main`). Originating author: Harald Nordgren. Series consists of two patches: (1) `git branch --set-upstream-to` missing-slash case, (2) `git push` slash-as-space case. Topic branch name `hn/branch-push-mistake-advise`.

Core problem: Addresses two common command-line mistakes: (1) `git branch --set-upstream-to=origin main` (missing slash between remote and branch name), where the user likely intended `origin/main` but the command fails because the local branch `main` does not exist, and (2) `git push origin/main` (using slash instead of space to separate remote and refspec). The series improves error messages to guide users toward correct syntax. The first patch's premise is refined to only suggest the correct `<remote>/<branch>` form when the remote-tracking ref (`origin/main`) exists, reconstructing the user's likely intent as setting upstream for the *current* branch. This refinement responds to Junio C Hamano's critique that the original patch's advice was too broad.

Current status: v2 series resubmitted, addressing all technical feedback from v1. Both patches are technically sound and ready for merging pending minor test style corrections. The first patch (branch upstream case) gates advice on the existence of the remote-tracking ref and has an open edge case question from Junio about scenarios where the local branch exists but the remote-tracking ref also exists. The second patch (push case) introduces a helper function to avoid performance penalties when advice is disabled and now requires a test style fix (replacing bare `grep` with `test_grep`). Junio's latest reviews approve the core design of both patches but flag the test style issue and the edge case as non-blocking follow-ups.

Key technical details:
- Introduces two new config options: `advice.setUpstreamFailure` (branch upstream case) and `advice.pushRepoLooksLikeRef` (push case), documented in `Documentation/config/advice.adoc`.
- **First patch (branch upstream case)**: Modifies `builtin/branch.c` to detect missing slash in upstream argument, verify remote existence, and confirm matching remote-tracking ref (`origin/main`). Advice triggers only when the remote-tracking ref exists, via the helper function `die_if_upstream_looks_like_remote()`, which runs only when advice is enabled. The commit message now needs to cover the case where the local branch exists but the upstream argument is still mistyped. Junio questions whether the `advise_if_enabled()` wrapper inside `die_if_upstream_looks_like_remote()` is redundant, as the caller already gates the call on the config option. An open edge case remains: the scenario where the local branch exists, the remote portion is invalid as an upstream, but the remote-tracking ref (`<remote>/<branch>`) exists.
- **Second patch (push case)**: Modifies `builtin/push.c` to identify slash-separated argument, validate remote portion, and exclude existing paths/repos. The helper function `die_if_repo_looks_like_ref()` ensures no performance penalty when advice is disabled. Test coverage in `t/t5529-push-errors.sh` now requires a style fix (replacing bare `grep` with `test_grep`) but otherwise covers edge cases (branches with slashes, unconfigured remotes, trailing slashes, existing paths).
- Test coverage added in `t/t3200-branch.sh` (branch cases) and `t/t5529-push-errors.sh` (push cases), confirming no false positives for local branch operations or existing paths. Implementation maintains strict separation of concerns; changes are non-disruptive and focused solely on error messaging. No regressions in existing functionality.
