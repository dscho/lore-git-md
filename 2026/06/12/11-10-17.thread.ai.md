Thread identity: Usability improvement series to make Git's error messages more helpful when users accidentally misformat remote/branch arguments (e.g., `git branch --set-upstream-to=origin main` or `git push origin/main`). Originating author: Harald Nordgren. Series consists of two patches: (1) `git branch --set-upstream-to` missing-slash case, (2) `git push` slash-as-space case. Topic branch name `hn/branch-push-mistake-advise`. Current version: v3.

Core problem: Addresses two common command-line mistakes: (1) `git branch --set-upstream-to=origin main` (missing slash between remote and branch name), where the user likely intended `origin/main` but the command fails because the local branch `main` does not exist, and (2) `git push origin/main` (using slash instead of space to separate remote and refspec). The series improves error messages to guide users toward correct syntax. The first patch's detection logic is refined to only suggest the correct `<remote>/<branch>` form when the remote-tracking ref (`origin/main`) exists, reconstructing the user's likely intent as setting upstream for the *current* branch. The second patch handles the push case by validating the remote portion and excluding existing paths/repos.

Key technical details:
- Introduces two new config options: `advice.setUpstreamFailure` (branch upstream case) and `advice.pushRepoLooksLikeRef` (push case), documented in `Documentation/config/advice.adoc`.
- **First patch (branch upstream case)**: Modifies `builtin/branch.c` to detect missing slash in upstream argument, verify remote existence, and confirm matching remote-tracking ref (`origin/main`). Advice triggers only when the remote-tracking ref exists, via the helper function `die_if_upstream_looks_like_remote()`. The function includes an `advise_if_enabled()` wrapper to ensure the advice message includes the standard "this can be disabled" footer. The callsite (`cmd_branch()`) redundantly checks `advice_enabled(ADVICE_SET_UPSTREAM_FAILURE)` for readability and to prevent future confusion; this is now documented with a comment. Test coverage in `t/t3200-branch.sh` covers the happy path (advice triggers when the remote-tracking ref exists), disabled-advice case, no-matching-ref case (no advice), local branch operations (no false positives), and slashed branch names (correct reconstruction).
- **Second patch (push case)**: Modifies `builtin/push.c` to identify slash-separated argument, validate remote portion, and exclude existing paths/repos. The helper function `die_if_repo_looks_like_ref()` ensures no performance penalty when advice is disabled by gating remote lookups on the advice config. The callsite (`cmd_push()`) includes a comment explaining the up-front `advice_enabled()` check, matching the pattern in the first patch. Test coverage in `t/t5529-push-errors.sh` covers edge cases (branches with slashes, unconfigured remotes, trailing slashes, existing paths).
- Files touched: `builtin/branch.c`, `builtin/push.c`, `advice.{c,h}`, `Documentation/config/advice.adoc`.
- Helper functions: `die_if_upstream_looks_like_remote()`, `die_if_repo_looks_like_ref()`.
- Test files: `t/t3200-branch.sh` (branch cases), `t/t5529-push-errors.sh` (push cases).
- Implementation maintains strict separation of concerns; changes are non-disruptive and focused solely on error messaging. No regressions in existing functionality.
