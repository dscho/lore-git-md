Thread identity: Usability improvement series to make Git's error messages more helpful when users accidentally swap or misformat remote/branch arguments, consisting of two patches: (1) `git branch --set-upstream-to` missing slash case, (2) `git push` slash-as-space case. Originating author: Harald Nordgren.

Core problem: Addresses two common command-line mistakes that frustrate users: (1) `git branch --set-upstream-to=origin main` (missing slash between remote and branch name), where the user likely intended `origin/main` but the command fails because the local branch `main` does not exist, and (2) `git push origin/main` (using slash instead of space to separate remote and refspec). The series aims to improve error messages to guide users toward correct syntax, but the fundamental premise is now contested: Junio C Hamano argues that the current error message for the first case is accurate and not misleading, as the command requires the local branch to exist, and the user's expectation (that `origin main` should be parsed as a remote-tracking branch) does not align with the command's design.

Current status: v1 series resubmitted after initial silence. The first patch (branch upstream case) is now in question following Junio's review, which challenges its motivation and suggests the existing error handling is sufficient. The second patch (push case) remains unreviewed. No substantive technical feedback has been provided on implementation, test coverage, or advice message wording for either patch.

Key technical details:
- Introduces two new config options: `advice.setUpstreamFailure` (branch upstream case) and `advice.pushRepoLooksLikeRef` (push case).
- Modifies `builtin/branch.c` to detect missing slash in upstream argument, verify remote existence, and confirm matching remote-tracking ref. Junio's review questions whether this detection logic is necessary or desirable, given the command's existing semantics.
- Modifies `builtin/push.c` to identify slash-separated argument, validate remote portion, and exclude existing paths/repos.
- Test coverage added in `t/t3200-branch.sh` (branch cases) and `t/t5529-push-errors.sh` (push cases).
- Implementation maintains strict separation of concerns; changes are non-disruptive and focused solely on error messaging.
