Thread identity: Usability improvement series to make Git's error messages more helpful when users accidentally swap or misformat remote/branch arguments, consisting of two patches: (1) `git branch --set-upstream-to` missing slash case, (2) `git push` slash-as-space case. Originating author: Harald Nordgren.

Core problem: Addresses two common command-line mistakes that frustrate new users: (1) `git branch --set-upstream-to=origin main` (missing slash between remote and branch name), and (2) `git push origin/main` (using slash instead of space to separate remote and refspec). Current error messages fail to guide users toward correct syntax.

Current status: v1 series complete and resubmitted after initial silence. Both patches now in play: first handles branch upstream detection, second handles push refspec parsing. No reviews yet; author has gently pinged the list.

Key technical details:
- Introduces two new config options: `advice.setUpstreamFailure` (branch upstream case) and `advice.pushRepoLooksLikeRef` (push case).
- Modifies `builtin/branch.c` to detect missing slash in upstream argument, verify remote existence, and confirm matching remote-tracking ref.
- Modifies `builtin/push.c` to identify slash-separated argument, validate remote portion, and exclude existing paths/repos.
- Test coverage added in `t/t3200-branch.sh` (branch cases) and `t/t5529-push-errors.sh` (push cases).
- Implementation maintains strict separation of concerns; changes are non-disruptive and focused solely on error messaging.
