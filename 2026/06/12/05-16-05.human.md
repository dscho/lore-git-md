This is a documentation patch addressing a subtle formatting issue in Git's man pages, part of the ongoing AsciiDoc synopsis-style conversion effort.

Jeff King responds to Jean-Noël Avila's patch that properly handles octothorpe (#) characters in documentation by modifying AsciiDoc configuration files. While the core solution works correctly - fixing the XML and HTML output - Jeff notices an unexpected side effect in the roff (man page) output where an extra space appears before the # character.

The issue appears to be a quirk in groff handles punctuation and spacing when the # appears on its own line, unrelated to the AsciiDoc changes. Jeff suggests this is a pre-existing formatting quirk that's only now visible due to the improved markup handling, and recommends proceeding with the patch while possibly addressing the spacing issue separately later.

This marks the final piece in solving the octothorpe rendering problems that have affected Git's documentation, building on previous work to standardize backtick-escaping for # symbols. The patch appears technically sound and ready for merging, with the minor spacing artifact being a known but acceptable side effect.
