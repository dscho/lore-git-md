This is a performance bugfix review for the ref-filter subsystem, addressing a regression in ref listing commands like `git branch` and `git tag`. The patch has already gone through several iterations and appears ready for merging, with Patrick Steinhardt providing final review comments.

The core issue was a 25x performance regression introduced in Git 2.51.0 when listing refs with prefixes (like `refs/heads/`), where the code was reading all loose refs before applying the prefix filter. The v3 patch implements Karthik Nayak's suggested approach to modify the ref iterator construction to take the prefix directly, avoiding unnecessary I/O. Benchmarks show dramatic improvements - commands now run in ~0.11s instead of ~2.8s when there are 10,000 unrelated loose refs.

Patrick's review notes two minor issues: the commit message includes raw links without proper context, and the performance test uses an unnecessary REFFILES prerequisite. However, he confirms the technical approach is sound. This appears to be the final polish before the patch can be merged to maint to fix the regression in released versions.
