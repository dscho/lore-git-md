This thread improves Git's error messages for two common command-line mistakes: `git branch --set-upstream-to=origin main` (missing slash) and `git push origin/main` (slash instead of space). The series, authored by Harald Nordgren, is now complete and ready for merging after addressing all feedback from two iterations.

The first patch refines error messages when users omit the slash between remote and branch names in `git branch --set-upstream-to`, while the second patch does the same for `git push` when users use a slash instead of a space. Both patches introduce configurable advice messages (via `advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) and include thorough test coverage. Junio has queued the series in `seen` and confirmed it will graduate to `next`.

The only remaining discussion is a minor readability concern about redundant advice-checking in the first patch. Junio noted that the callsite checks `advice_enabled()` while the helper function also wraps its advice in `advise_if_enabled()`, creating a redundant check. Harald clarified this is intentional to ensure consistent advice-message formatting, and the discussion is now about whether to add a comment to prevent future confusion—not about functionality. This doesn’t block merging. The series has broad support, with substantive reviews from D. Ben Knoble and Junio, and is expected to land soon.
