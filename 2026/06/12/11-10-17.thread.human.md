This thread is about a small but practical usability improvement to Git’s error messages when users accidentally misformat remote/branch arguments. Harald Nordgren sent a two-patch series (`hn/branch-push-mistake-advise`) that makes Git more helpful in two common slip-ups: `git branch --set-upstream-to=origin main` (missing slash between remote and branch) and `git push origin/main` (using a slash instead of a space). The first patch now only suggests the correct `<remote>/<branch>` form when the remote-tracking ref actually exists, addressing Junio’s earlier concern that the advice could be misleading.

The series is now technically complete. Junio reviewed both patches in v2, approving the design and implementation but flagging a minor test-style issue in the second patch—using bare `grep` instead of the project-standard `test_grep`. This latest email provides a squashable fix for that, touching seven lines in the test file. With that applied, the series is ready to be merged; Junio’s only remaining question is a non-blocking edge case in the first patch (what happens if the local branch exists but the remote-tracking ref also exists). D. Ben Knoble had earlier supported the usability argument with a concrete example, while Weijie Yuan’s feedback was more surface-level. The patches introduce two new config options (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) and add test coverage in `t/t3200-branch.sh` and `t/t5529-push-errors.sh`. No regressions or functional changes are involved.
