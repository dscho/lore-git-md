Harald Nordgren’s series to improve Git’s error messages for common command-line mistakes—like `git branch --set-upstream-to=origin main` (missing slash) or `git push origin/main` (slash instead of space)—is still shaping up after Junio C Hamano’s critique and a new review from D. Ben Knoble.

The first patch, which targets the `branch --set-upstream-to` case, remains the sticking point. Junio argues the current error message is accurate and sufficient, but now proposes a refinement: the advice should only appear when `origin/main` actually exists, reconstructing the user’s likely intent as setting the upstream for the *current* branch. Knoble’s recent reply bolsters Harald’s case by pointing out that `git branch --set-upstream-to origin` (without a branch) already succeeds when `origin/HEAD` exists, suggesting the command’s behavior isn’t always intuitive. This edge case supports the idea that users might reasonably expect `origin main` to work like `origin/main`, especially when the remote-tracking branch exists.

The second patch, which handles the `git push origin/main` case, is less controversial but still needs revision to address Junio’s technical feedback—specifically, moving the detection logic into a helper function that only runs when advice is enabled. No other reviewers have weighed in substantively beyond Weijie Yuan’s surface-level endorsement. Harald is expected to revise the first patch’s commit message and detection logic to align with Junio’s proposed refinement, while the second patch awaits a more targeted implementation. The thread is still open, with the core question unresolved: whether the advice should be config-based or unconditional, and whether the first patch’s premise holds up under scrutiny.
