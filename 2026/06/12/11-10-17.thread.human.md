Harald Nordgren’s series aims to make Git’s error messages more helpful for two common command-line mistakes: omitting the slash in `git branch --set-upstream-to=origin main` (where the user likely meant `origin/main`) and using a slash instead of a space in `git push origin/main`. The first patch in the series has faced pushback from Junio C Hamano, who argues that the current error message is accurate and that the real issue is a mismatch between user expectations and the command’s design—`--set-upstream-to` requires the local branch to exist, so the command fails as intended. The second patch, which addresses the `git push` case, remains unreviewed but has now received a technical critique from Junio.

Junio’s review of the second patch is constructive, focusing on implementation details rather than the feature’s premise. He points out that the detection logic runs even when the advice is disabled, creating unnecessary overhead, and that the patch exits prematurely, preventing fallback to URL or path handling. He suggests refactoring the logic into a helper function that only executes when the advice is enabled. While this feedback is substantive, it doesn’t challenge the patch’s core goal, unlike his critique of the first patch. No other reviewers have weighed in on either patch yet.

The series is at a crossroads: the first patch’s motivation is contested, while the second patch’s implementation needs refinement. Harald will need to address Junio’s technical feedback on the second patch and either revise the first patch’s approach or provide a stronger justification for its premise. The outcome of this discussion will determine whether the series can proceed—or whether it might serve as a template for similar usability improvements elsewhere in Git. For now, the push case remains the more viable of the two, but both patches need further review to clarify their direction.
