This thread is about a small but impactful usability improvement to Git’s error messages when users accidentally misformat remote/branch arguments. Harald Nordgren sent a two-patch series (`hn/branch-push-mistake-advise`) that addresses two common mistakes: `git branch --set-upstream-to=origin main` (missing slash between remote and branch) and `git push origin/main` (using slash instead of space). The patches improve error messages to guide users toward the correct syntax, with the first patch’s logic refined to only suggest the `<remote>/<branch>` form when the remote-tracking ref exists.

The series is now complete and ready for merging. Junio has queued both patches in `next` after addressing all feedback from earlier versions. The only minor quibble—Harald’s intentional use of a redundant advice check in the first patch—was documented and left unchanged. Both patches include thorough test coverage and introduce new config options (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`) to control the behavior. D. Ben Knoble supported the usability argument early on, while Junio’s reviews across v1–v3 were constructive and ultimately approving. No further changes are expected, and the thread is effectively closed.
