Harald Nordgren’s series proposes two small but thoughtful usability improvements to Git’s error messages, targeting common mistakes that trip up new users. The first patch helps when someone runs `git branch --set-upstream-to=origin main` (missing the slash between remote and branch), while the second catches `git push origin/main` (using a slash instead of a space). Both cases currently produce unhelpful errors; the patches add gentle advice that points users toward the correct syntax.

The series is now at v1, with both patches resubmitted after an initial silence. Weijie Yuan chimed in to agree that the inconsistent syntax between `branch --set-upstream-to` and `push` is confusing, but the message was purely supportive and didn’t dig into the code or tests. So far, no one has reviewed the implementation details—how the advice messages are worded, whether the detection logic is robust, or if the test coverage is sufficient. The patches touch `builtin/branch.c` and `builtin/push.c`, add two new config options (`advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`), and include tests in `t/t3200-branch.sh` and `t/t5529-push-errors.sh`. Everything is designed to be non-disruptive, so the series could land quickly once it gets a thorough look.
