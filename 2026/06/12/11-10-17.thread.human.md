This thread is about a two-patch series by Harald Nordgren aimed at improving Git's error messages for common command-line mistakes involving remote and branch arguments. The series targets two specific cases: `git branch --set-upstream-to=origin main` (missing slash between remote and branch) and `git push origin/main` (using slash instead of space to separate remote and refspec).

The first patch, which handles the `git branch` case, has been refined in its second version to only suggest the correct `<remote>/<branch>` form when the remote-tracking ref (like `origin/main`) exists, addressing feedback from Junio C Hamano that the original advice was too broad. The second patch, which is the focus of this latest email, improves error messages for the `git push` case by detecting when users accidentally use a slash instead of a space and suggesting the correct syntax. This patch is technically sound, with clean detection logic that ensures no performance penalty when advice is disabled, and includes comprehensive test coverage.

Key participants include Harald Nordgren (the author), Junio C Hamano (the maintainer, who provided constructive feedback on the first patch), D. Ben Knoble (who supported the usability argument with a concrete example), and Weijie Yuan (who endorsed the problem statement). The series is now complete and awaits broader review, though the first patch's narrowed scope remains a point of debate. The implementation introduces two new config options for enabling the advice and touches `builtin/branch.c`, `builtin/push.c`, and related documentation. The patches are non-disruptive and focus solely on improving error messages without regressing existing functionality.
