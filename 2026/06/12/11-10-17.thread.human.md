This thread is about a small but impactful usability improvement to Git’s error messages for two common command-line mistakes: `git branch --set-upstream-to=origin main` (missing slash between remote and branch) and `git push origin/main` (using a slash instead of a space). Harald Nordgren authored a two-patch series (`hn/branch-push-mistake-advise`) that refines the error messages to guide users toward the correct syntax, with configurable advice via `advice.setUpstreamFailure` and `advice.pushRepoLooksLikeRef`.

The series is now complete and ready for merging. The first patch, which handles the branch upstream case, was refined in response to Junio C Hamano’s feedback to only suggest the correct `<remote>/<branch>` form when the remote-tracking ref exists, reconstructing the user’s likely intent. The second patch, addressing the push case, introduces a helper function to avoid performance penalties when advice is disabled and now complies with test suite style requirements after a minor fix (replacing bare `grep` with `test_grep`). Harald accepted Junio’s squashable patch for this fix, and Junio has queued it for tonight’s `seen` integration.

Key participants include Harald, who addressed all feedback and resubmitted the series as v2, and Junio, who provided constructive critiques and approved the technical implementation. D. Ben Knoble supported the usability argument with a concrete example, while Weijie Yuan endorsed the problem statement without deeper engagement. The only open question is a non-blocking edge case Junio flagged—where a local branch exists, the upstream argument is invalid, but the remote-tracking ref exists—but this is expected to be addressed in follow-up work if needed. The series is uncontroversial and could serve as a template for similar usability improvements elsewhere.
