This thread is about a small but user-friendly improvement to Git’s error messages when users accidentally misformat remote and branch arguments. Harald Nordgren sent a two-patch series that adds helpful advice for two common mistakes: `git branch --set-upstream-to=origin main` (missing slash between remote and branch) and `git push origin/main` (using a slash instead of a space). The series is now called `hn/branch-push-mistake-advise` after Junio C Hamano suggested the clearer term “mistake” instead of “slip.”

The first patch has drawn the most discussion. Junio initially felt the current error message was accurate but later proposed a refinement: the advice should only appear when the intended remote-tracking branch (`origin/main`) actually exists, suggesting the user likely meant to set the upstream for the *current* branch. Harald is expected to adjust the detection logic and commit message accordingly. The second patch, which handles the `git push` case, has no objections to its premise but needs a small code refactor to address Junio’s feedback on efficiency and structure. No other reviewers have engaged beyond a brief endorsement, so the conversation remains between Harald and Junio. The series is still at v1, and once the first patch is revised, it should be ready for broader review.
