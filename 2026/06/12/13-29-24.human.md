This is a proposal about using AI for code reviews in the Git project, sparked by the ongoing discussion about review bandwidth challenges. Christian Couder suggests formalizing AI-assisted reviews as a way to catch common issues before human reviewers need to engage.

The email references Sashiko, an AI review tool used by Linux kernel developers, and notes that some GitLab engineers already use AI privately for pre-submission reviews. The core proposal is to potentially require AI review as a gate (similar to CI) to catch low-level issues like style violations, memory leaks, and basic correctness problems, while still requiring human review for architectural decisions and project alignment.

Several open questions are raised about implementation: whether to use existing corporate AI systems (with potential inconsistencies between providers), when in the process to apply AI review, and how to handle AI-generated suggestions that might conflict with project policies. The email also touches on potential abuse vectors that would need mitigation.
