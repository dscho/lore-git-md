This is a preparatory patch in Matt Hunter's 7-part series introducing a global `fetch.followRemoteHEAD` configuration option. The patch fixes a minor documentation inconsistency in the advice message shown when a remote's HEAD doesn't match expectations.

The change corrects the suggested command for configuring `followRemoteHEAD` - the advice previously included an incorrect "branch" in the configuration value ("warn-if-not-branch-%s") that didn't match either the actual implementation or the documented behavior. The fix aligns the advice with the proper syntax ("warn-if-not-%s").

As the first patch in the series, this serves as groundwork for the subsequent changes by ensuring consistent terminology before introducing the new global configuration option. The change is straightforward and uncontroversial, touching only a single line in `builtin/fetch.c`. The patch follows Git's standard practices with a clear commit message and proper sign-off.
