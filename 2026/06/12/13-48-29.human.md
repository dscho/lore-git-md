This is the fourth version of Pablo Sabater's feature patch series improving `git log --graph` rendering for commits with excluded parents. The series is in its final polishing phase with the cascading indentation design confirmed but implementation work still ongoing.

The core improvement addresses misleading vertical alignment in graph output when displaying commits with filtered-out parents (including root commits). The new approach indents visual root commits rather than the subsequent commits, creating clearer visual distinction between unrelated lineages. The patch demonstrates this with before/after ASCII examples showing how indentation prevents false visual connections.

Key technical changes in v4:
- Complete redesign from v3's approach (now indenting roots rather than subsequent commits)
- Added a new test file (t4218-log-graph-indentation.sh) with extensive test cases
- Documented a known edge case where lookahead fails to detect some visual roots
- Includes a preparatory commit moving shared test helper functions to a common location

The implementation appears solid but has one acknowledged limitation: the lookahead mechanism can't always detect when the next commit will become a visual root after history simplification, leading to occasional extra indentation. The author has marked this with a NEEDSWORK comment but notes unfamiliarity with revision.c's internals.

The series seems ready for merging pending resolution of:
1. Completion of test fixes (actively being worked)
2. Junio Hamano's open question about whether to document the visualization rules in man pages

This represents the final stretch of a well-executed effort to improve Git's graph visualization, with thorough test coverage and clear examples demonstrating the improvement. The remaining issues appear minor and unlikely to block merging.
