This is the third and final patch in a performance optimization effort that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The series has been through multiple rounds of review with substantive feedback from Jeff King (Peff).

The patch focuses on error handling, making the code die when `repo_is_descendant_of()` encounters an error (like being unable to read commit ancestry) rather than silently treating it as a match. This matches the behavior of the memoized walk path which already dies on parse errors. The change ensures consistent error reporting across both code paths.

The implementation adds a test case that verifies missing ancestors are properly reported for both `--contains` and `--no-contains` filters. The test creates a commit with a missing parent and confirms the command fails with an appropriate error message rather than silently including or excluding the ref.

This completes the series which now provides:
1. Cycle detection safety (patch 1)
2. Performance optimization for all ref-filter commands (patch 2)
3. Robust error handling (this patch)

The patches demonstrate careful attention to both performance and correctness, with comprehensive test coverage. The series appears ready for merging after thorough review.
