This is the final patch in a three-part performance optimization series that extends Git's memoized commit traversal to all ref-filter commands (`git branch --contains`, `git for-each-ref --contains`). The patch focused on error handling consistency.

The patch makes `commit_contains()` die when `repo_is_descendant_of()` encounters an error (like missing parent commits), matching the behavior of the memoized path. Previously, these errors were silently treated as matches, which could incorrectly include or exclude refs in `--contains`/`--no-contains` queries. The change ensures consistent behavior between optimized and non-optimized code paths.

A new test case verifies the behavior by creating a commit with a missing parent and checking that both `--contains` and `--no-contains` properly fail when encountering it. This completes the series' error handling story, which now has robust coverage for cycles (patch 1), performance optimization (patch 2), and error reporting (this patch).
