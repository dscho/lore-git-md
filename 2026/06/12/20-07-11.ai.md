This is the second patch in Taylor Blau's series fixing MIDX incremental writes with custom base layers. The patch addresses a bug where the `--base` option wasn't being properly passed through to the MIDX write path, causing incorrect behavior when writing incremental MIDX layers.

The key changes are:
1. Threading the `incremental_base` parameter through `write_midx_file()` and updating all callers
2. Marking two test cases as expected failures since they expose a deeper issue with pack inclusion during incremental writes with custom bases
3. Adding more thorough verification to those test cases to check object reachability

The patch reveals that when using `--base` with incremental writes, the MIDX writer was incorrectly skipping packs from the full existing MIDX chain, breaking reachability closure needed for bitmaps. This manifests in the test cases that try to use `--base=none` or `--base=<hash>`.

The changes are mechanical and focused - each commit in the series tackles a distinct aspect of the problem. This patch lays the groundwork for the final fix in the series by properly plumbing the base value through the write path while documenting the remaining issue. The test updates help verify the eventual fix while preventing false positives during bisect.

As part of Taylor's ongoing MIDX work, this continues his pattern of careful, incremental improvements to the pack and MIDX infrastructure. The changes are well-contained and the commit message clearly explains both the immediate fix and the remaining problem.
