This is the third and final patch in a performance optimization effort that extends Git's commit traversal optimization to all ref-filter commands. The patch focuses on error handling consistency between memoized and non-memoized paths.

The key change makes `commit_contains()` die on errors from `repo_is_descendant_of()` rather than silently treating them as matches. This matches the behavior of the memoized path (which already dies on parse errors) and prevents inconsistent results between the two code paths. The patch includes a new test case that verifies proper error reporting when commits reference missing parents.

This completes the series by ensuring robust error handling across all scenarios while maintaining the significant performance improvements (100x speedup with generation numbers, 10x without) demonstrated in earlier patches. The implementation now:
- Detects cycles as fatal errors (patch 1)
- Extends optimizations to all ref-filter commands (patch 2)
- Ensures consistent error reporting (this patch)
