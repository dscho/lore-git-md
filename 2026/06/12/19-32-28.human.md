This is a discussion about the role of AI in Git's code review process, continuing from earlier conversations about review bandwidth challenges. Junio Hamano responds to Christian Couder's suggestion that AI-assisted reviews could be made mandatory for patch submissions.

Junio acknowledges the potential benefits of AI tools (catching typos, memory issues, style violations) but draws a clear line: while contributors are welcome to use such tools to improve their patches, the project should not require them. He compares this to GitHub's CI system - useful for those who choose to use it, but not a formal requirement. The key metric remains the quality of the final output, not the tools used to achieve it.

The response reflects Git's long-standing philosophy of valuing results over process. Junio emphasizes that while automated review services could be helpful if made widely available (particularly for new contributors), mandating their use would create unnecessary barriers. The discussion remains open-ended, with Junio positioning this as a personal view rather than a project policy decision.
