This is a review from Junio C Hamano on Matt Hunter's patch adding the global `fetch.followRemoteHEAD` configuration option. Junio focuses on two technical implementation details rather than the feature itself, which he notes he hasn't been following closely.

First, he strongly objects to using case-insensitive comparison (`strcasecmp`) for the configuration values, arguing it creates unnecessary inconsistency with the case-sensitive per-remote version and complicates documentation. He advocates for using strict `strcmp` matching to lowercase values as documented, seeing case insensitivity as a historical mistake that shouldn't be perpetuated.

Second, he questions whether a `die()` is appropriate for invalid configuration values, particularly in single-shot fetch scenarios where the setting wouldn't even be used. He suggests this could unnecessarily break workflows where users have newer configuration values that older Git versions don't understand yet.

The review is substantive, engaging with real technical tradeoffs in the implementation rather than surface-level concerns. Junio doesn't challenge the overall design but identifies two specific points where the current approach might cause problems or inconsistencies. His feedback suggests the patch needs adjustments to configuration parsing behavior before merging.
