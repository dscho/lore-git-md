Performance optimization extending memoized commit traversal to all ref-filter commands. This is the second patch in a series that significantly speeds up `--contains` operations across `git branch`, `git for-each-ref`, and `git tag` when generation numbers are available. The change builds on Git's existing memoized depth-first walk optimization that was previously only used for `git tag --contains`.

The patch demonstrates impressive performance improvements - reducing a 104-second operation to under half a second when querying 62,000+ refs. It maintains the existing behavior for repositories without generation numbers while taking advantage of them when present. The implementation is clean, touching only two files with minimal changes to enable the optimization broadly.

Test coverage has been expanded to include performance benchmarks for all three frontend commands, showing the real-world impact. The patch follows good Git development practices by building on prior work (the tag optimization from 2011) and preserving backward compatibility. With substantive review feedback from Jeff King incorporated and comprehensive testing added, this appears ready to merge as a valuable performance win for repositories with many refs.
