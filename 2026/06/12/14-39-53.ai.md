This is a test patch that demonstrates a bug in Git's notes handling during rebase operations. The issue occurs when a commit disappears during rebase because its changes are already present in the target branch (but not from the same patch), yet the notes from that disappearing commit persist and get incorrectly attached to the rebased parent commit.

The patch adds a new test file `t/t3322-notes-rebase.sh` that:
1. Sets up a repository with commits A-B-C on master and A-BD on a branch
2. Rebases B+C onto BD
3. Expects (but currently fails) that the note from commit B doesn't appear on BD

The author reports this has been a persistent issue since at least 2023, affecting their workflow where they use notes to track Message-Ids of sent patches. When rebasing, these notes incorrectly transfer to unrelated commits, causing tracking confusion.

The test demonstrates a clear case where notes should not persist when commits disappear during rebase due to content being already present. This appears to be a legitimate bug in Git's notes handling logic during rebase operations.
