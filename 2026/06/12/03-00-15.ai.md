This is the third and final patch in a performance optimization series that improves `--contains` filtering across Git's ref-filter commands. The patch focuses on error handling, ensuring consistent behavior when commit ancestry cannot be determined.

The change makes `commit_contains()` die when `repo_is_descendant_of()` encounters an error (such as missing commit objects), rather than silently treating the error as a false positive. This matches the behavior of the memoized path which already dies on parse errors. The patch includes a new test case that verifies both `--contains` and `--no-contains` properly report errors when encountering commits with missing parents.

This completes the series by addressing the last remaining edge case identified in review, ensuring the performance optimizations from the first two patches don't introduce subtle behavioral differences in error scenarios.
