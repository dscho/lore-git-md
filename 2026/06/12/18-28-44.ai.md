This is a refactoring patch from a GSoC participant that introduces a shared path formatting utility (`append_formatted_path()`) in `path.c`. The patch is part of a series extending `git repo info`'s path handling capabilities.

The new helper function centralizes path formatting logic that was previously duplicated in `rev-parse.c`, supporting several formatting modes through a `path_format` enum:
- UNMODIFIED (raw path)
- RELATIVE (to given prefix)
- RELATIVE_IF_SHARED (relative only if sharing common prefix)
- CANONICAL (fully resolved absolute path)
- DEFAULT (maps to UNMODIFIED)

The implementation handles edge cases carefully:
- Proper memory management with strbufs
- Fallback to current working directory when prefix is NULL
- Correct relative path calculation
- Canonicalization with forgiving realpath
- BUG() on invalid format values

The patch includes thorough documentation of both the enum values and function parameters. This appears to be a well-structured utility that follows Git's established patterns for path handling, with clean separation between the formatting logic and output destination (writing to a strbuf rather than directly to stdout).

This foundational change enables subsequent patches in the series to reuse this logic consistently. The implementation has already undergone multiple rounds of review from experienced contributors (Justin Tobler, Lucas Seiki Oshiro) and incorporates their feedback.
