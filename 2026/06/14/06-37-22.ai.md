This is the first patch in Elijah Newren's merge-ort hardening series, which addresses error propagation issues in the merge machinery. The patch specifically fixes a case where traverse_trees_wrapper() was silently discarding callback return values, which could mask tree depth limit violations and other error conditions.

The key changes in this patch:
- Modifies traverse_trees_wrapper() to properly capture and propagate callback return values
- Stops processing on negative returns (errors)
- Normalizes successful positive returns to 0 for the caller
- Fixes a case where exceeding core.maxTreeDepth would silently prune subtrees rather than failing

The patch is part of a larger effort to harden merge-ort against corrupt trees and improve its directory/file conflict detection. This initial change lays groundwork for subsequent patches that will add more error detection cases (like duplicate entries in malformed trees).

The implementation is straightforward and focused - it preserves the existing behavior for successful cases while properly bubbling up errors that were previously being swallowed. The change is well-contained to merge-ort.c with minimal diff churn (14 lines changed).

This patch has already been through one revision cycle, incorporating maintainer feedback to expand the commit message explanation of the error propagation changes. The series as a whole is now maintainer-approved and ready for merging.
