Thread summary:

The thread discusses a proposal to make Git respect a `DEPTH` environment variable as a fallback for `git clone --depth`, similar to how other Git environment variables like `GIT_TRACE` work. The originating author is Hadrien Loge, who argues this would benefit packaging workflows where clean chroot builds need consistent shallow cloning behavior.

brian m. carlson has raised two main objections: 1) the risk of scripts unintentionally getting shallow clones when they expect full history due to the environment variable being set, and 2) potential server-side performance impacts since shallow fetches are more resource-intensive. Hadrien counters that other environment variables already follow this pattern, the change wouldn't affect existing flows unless explicitly opted into, and the packaging use case justifies the addition. The discussion remains open with no consensus yet reached, as the tradeoffs between packaging convenience and potential unintended consequences need further evaluation. Key technical considerations include the behavioral impact on existing scripts and the server load implications of more widespread shallow clone usage.
