This is a feature proposal for `git rebase` that would add a `--fixup-all` option to automatically fold a range of commits into their oldest ancestor commit while reusing that commit's message. The patch series comes from Harald Nordgren via GitGitGadget.

The main change would allow users to specify `git rebase --autosquash --fixup-all` to squash a sequence of commits into the oldest one in the range, similar to how `--fixup` works for individual commits. The implementation touches the rebase and sequencer code, with corresponding documentation updates.

The series includes two patches:
1. A test cleanup removing a prepare-commit-msg hook after use
2. The main implementation adding the `--fixup-all` functionality

The motivation appears to be streamlining workflows where developers want to combine a series of follow-up fixes into their original commit while preserving the original message. The test coverage looks thorough, adding over 100 lines of new test cases to verify the behavior.

This seems like a well-structured proposal that could be useful for interactive rebase workflows, though it would need review from rebase/sequencer experts (Phillip Wood, Elijah Newren, etc.) to assess the implementation details and edge cases. The patch builds on existing autosquash infrastructure rather than introducing entirely new mechanisms.
