This is a refactoring patch in the `diff.<driver>.process` series, which enables external tools to inject diff hunks into Git's diff and blame pipelines. The patch focuses on improving the subprocess management code.

The change separates the concerns of process lifecycle management from hashmap operations in the subprocess API. Previously, `subprocess_start()` and `subprocess_stop()` handled both starting/stopping processes and maintaining the hashmap. This patch introduces new functions `subprocess_start_command()` and `subprocess_stop_command()` that handle just the process management, while the original functions become thin wrappers that add hashmap operations.

This is a clean, focused refactoring that makes the code more flexible - callers that don't need the hashmap (like the diff-process implementation) can now use just the process management parts. The changes are mechanical and maintain all existing behavior while improving the API design.

The patch is part of a larger series that has already addressed key concerns around test implementation (moving from Python to C) and Windows compatibility. This particular change appears straightforward and well-contained, following the project's established patterns for subprocess handling.
