This is a follow-up discussion about a proposed feature patch that would make `git clone` accept a `DEPTH` environment variable as a fallback for the `--depth` option. The original motivation (from the thread context) was to help package builders who frequently need shallow clones in clean chroots.

The current discussion highlights two concerns raised by reviewers:
1. Potential for unexpected breakage if scripts assume full history but encounter a shallow clone due to the environment variable
2. The server-side cost of serving shallow fetches, which the author hadn't considered

The author (Hadrien Loge) defends the proposal by noting:
- Other Git environment variables already affect behavior
- Package builders would only use this when they specifically want shallow clones
- The change wouldn't impact existing workflows
- They see value in saving bandwidth and time for packagers

The tone remains constructive, with the author acknowledging the technical points while maintaining their position. The patch appears to be at an impasse between the convenience use case and concerns about unintended consequences and server load. The discussion suggests this may need more input from other contributors or the maintainer to reach consensus.
