This is the final patch in a series introducing `diff.<driver>.process`, a new configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines. The patch focuses on integrating this capability with `git blame`.

Key points:
- When a diff process is configured, blame will consult it during per-commit diffing
- If the process returns no hunks (indicating equivalent content), blame will skip that commit and attribute lines to earlier commits
- The implementation maintains a long-running subprocess (one startup cost per blame operation)
- Includes thorough test coverage showing:
  - Blame attribution respects tool-provided hunks
  - Reformatted files can be skipped when the tool reports no semantic changes
  - The `--no-ext-diff` flag properly bypasses the external process

The patch builds on previous work that established the core diff process infrastructure and protocol. Performance remains a consideration (17% overhead currently), though future OID-based optimizations are noted. With Windows compatibility addressed and all substantive review feedback incorporated, this appears technically ready pending final maintainer sign-off.
