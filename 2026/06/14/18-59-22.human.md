This is part 5 of a 6-patch series introducing the `diff.<driver>.process` feature, which allows external tools to inject diff hunks into Git's diff and blame pipelines. The series is in its fourth revision and has been through extensive review, with all major technical concerns addressed.

This specific patch focuses on bypass mechanisms for the new diff process feature. It makes two key changes:

1. **`--no-ext-diff` now disables both `diff.<driver>.command` and `diff.<driver>.process`** - The patch unifies the control of external diff tools under the existing `--no-ext-diff` flag, treating both command-based and process-based external diffs consistently as "external tools" that should be disabled.

2. **Format-patch always uses builtin diff** - The patch forces `format-patch` to use Git's builtin diff algorithm regardless of any `diff.<driver>.process` configuration, ensuring generated patches are reliable and reproducible even for recipients who don't have the external tool installed.

The implementation:
- Replaces the simple `OPT_BOOL` for `--ext-diff` with an `OPT_CALLBACK` that manages both flags
- Adds documentation clarifying that `--diff-algorithm` also bypasses the diff process
- Includes new test cases verifying the bypass behavior

This is a straightforward refinement that improves the user experience by making external diff control more consistent and ensuring patch portability. The changes align with the series' goal of integrating external diff tools while maintaining Git's core reliability. With Windows compatibility concerns now addressed and test coverage comprehensive, the series appears ready for final review.
