This is a bugfix patch addressing a memory leak in the `git history reword` command. The leak occurs when the command retrieves a commit message buffer but fails to properly release it afterwards.

The patch identifies that `commit_tree_ext()` calls `repo_logmsg_reencode()` to get the original commit message but doesn't pair it with the required `repo_unuse_commit_buffer()`. This oversight causes a 1813-byte memory leak that was detected under AddressSanitizer.

The fix is straightforward - adding the missing cleanup call. The author notes they're unsure why this was omitted originally, suggesting there might be some subtle reason, but the patch appears correct based on Git's buffer management conventions. This is a focused, well-explained fix for a clear issue, though it would benefit from a test case to prevent regression.

The patch touches the relatively new `git history` command (part of Patrick Steinhardt's ongoing work), so reviewers familiar with that subsystem would be best positioned to evaluate it. The change itself is mechanical and unlikely to be controversial.
