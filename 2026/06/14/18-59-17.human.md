This is the fourth revision of an RFC series introducing a new `diff.<driver>.process` configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines. The key changes since v3 include:

1. **Test backend transition** - Replaced the Python test backend with a C-based `test-tool` helper per Johannes Schindelin's recommendation, aligning with the project's direction of reducing scripting language dependencies.

2. **Enhanced validation** - Added specific warning messages for various hunk validation failures (out-of-bounds ranges, overlaps, sync mismatches) to help tool authors debug their implementations.

3. **Protocol refinement** - Now accepts start=0 with count=0 in the hunk protocol to match git diff's output for empty file sides, while normalizing to 1-based internally for validation.

4. **New test cases** - Added coverage for deleted files, malformed hunk lines, and missing capability scenarios.

The series remains focused on enabling specialized diff tools (like AST-based diffs) to participate in Git's diff processing while preserving downstream features like word-diff and color-moved. The protocol follows Git's established long-running process model from the filter subsystem.

Junio C Hamano has explicitly endorsed the C-based test helper approach, signaling the series is on the right track pending completion of the test implementation. All substantive review feedback from previous iterations has been addressed, with Michael Montalbo demonstrating consistent application of the project's scripting language reduction principle.

The blame integration in patch 6 shows how this could be used to skip reformat-only commits in history analysis. Performance remains a consideration - the current implementation adds ~17% overhead to blame operations due to per-commit roundtrips, though an OID-based optimization is noted as future work.

The series appears technically sound with comprehensive test coverage (now 708 lines). The main remaining items are final verification of the Windows path handling fix and completion of the C-based test helper implementation.
