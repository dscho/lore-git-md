This is a feature patch introducing a new `diff.<driver>.process` configuration that enables external tools to inject diff hunks into Git's diff and blame pipelines while preserving downstream features like word-diff and color-moved. The patch is part of a larger RFC series (now at v4) that has undergone significant refinement based on review feedback.

Key aspects of this specific patch:

1. **Core functionality**: Adds support for long-running diff processes that communicate via pkt-line protocol. The tool receives file pairs and returns custom line-matching hunks that Git then uses in its standard diff pipeline.

2. **Protocol details**: Documents the handshake and per-file request/response protocol in gitattributes.adoc. The tool can mark files as unchanged (no hunks) which affects both diff output and blame attribution.

3. **Error handling**: Includes robust fallback to builtin diff on errors (invalid hunks, tool crashes, protocol violations) with appropriate warnings. Tools can signal temporary errors or permanent withdrawal.

4. **Integration**: Works alongside existing features like textconv and respects bypass mechanisms (--no-ext-diff, --diff-algorithm). The subprocess is cached per-driver to avoid per-file startup costs.

5. **Testing**: Includes a comprehensive test suite (432 lines) covering success paths, error fallbacks, and integration with various Git commands and flags. The implementation follows patterns from Git's existing long-running process protocols (like convert.c) and has been updated to use a C-based test helper instead of Python per project standards.

This builds on previous iterations that addressed Windows compatibility concerns, subprocess API refinements, and expanded test coverage. The maintainer (Junio C Hamano) has signaled technical satisfaction with the approach, particularly after the test implementation transition. The series appears ready for merging pending final verification of Windows fixes and performance optimization in the blame integration.
