This is the final patch in Elijah Newren's merge-ort hardening series, completing the detection of directory/file conflicts in cache-tree verification. The patch addresses a subtle case where verify_cache() could miss D/F conflicts when non-adjacent entries in the index created the conflict (like "docs" and "docs/requirements.txt" with "docs-internal/README.md" in between).

The key technical change introduces a new `find_df_conflict()` helper that performs a binary search when adjacent entry comparison fails to detect a conflict. This maintains O(n log n) performance while expanding detection to catch all D/F conflicts, not just adjacent ones. The implementation handles cases where intervening entries sort between conflicting paths due to character ordering ('-' < '/').

The patch includes comprehensive test coverage with two new test scripts:
- t0093-direct-index-write.pl: A helper to construct corrupt index files by bypassing normal D/F checks
- t0093-verify-cache-df-gap.sh: Tests verifying both adjacent and non-adjacent D/F conflict detection

This completes the merge-ort hardening against corrupt trees that was started in the series. All maintainer feedback from earlier iterations has been addressed, and the extraction of the binary search logic into a separate function (as suggested by Junio Hamano) makes the implementation cleaner. The series is now ready for integration, having successfully closed the gap in verify_cache()'s safety net against tree corruption.
