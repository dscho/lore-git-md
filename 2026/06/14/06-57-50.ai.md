Bugfix for commit-graph generation number calculation with future-dated commits.

Elijah Newren identifies and fixes a subtle issue in the commit-graph generation number computation where parent commits with timestamps beyond 2106-02-07 (exceeding 32-bit unsigned integer range) would cause incorrect generation numbers to be calculated for their children. The problem stems from using a uint32_t accumulator when computing the maximum parent generation number, which silently truncates large timestamp values.

The fix changes the accumulator type to timestamp_t (which is 64-bit) while maintaining the existing on-disk format. This ensures correct generation number calculations for repositories containing commits with very future dates (like the amusing example of commits apparently made in 2120). A new test case verifies the fix by creating a repository with a future-dated parent and present-day child, checking that the commit-graph handles this case correctly.

This is a focused technical correction to an edge case that could affect repositories with extremely future-dated commits. The patch is small (just a type change) but important for correctness, with a clear test demonstrating the problem. The commit message provides thorough background on when and how the issue was introduced (in 80c928d947c2 and 368d19b0b7fa).
