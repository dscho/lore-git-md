Patch 2/5 in Elijah Newren's merge-ort hardening series removes an unnecessary error-handling flag that was originally copied from unpack-trees.c but serves no purpose in merge-ort. The `show_all_errors` setting caused traverse_trees() to continue processing after errors rather than stopping immediately, which wasn't actually needed since merge-ort doesn't batch error messages like unpack-trees does.

This change is a straightforward cleanup that paves the way for the series' later patches to properly handle early exits when detecting corrupt trees. The removal of this flag restores the default behavior where a negative callback return immediately breaks out of traversal, which will be used by subsequent patches in the series to abort processing when corruption is found.

The patch is well-justified with a commit message explaining the historical context and practical effect of the change. As part of this maintainer-approved series that has already addressed all technical feedback, this patch represents a small but meaningful step in hardening merge-ort's error handling.
