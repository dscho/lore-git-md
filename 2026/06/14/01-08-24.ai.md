This is a substantive review of the proposed `GIT_CLONE_DEPTH` environment variable feature, raising concerns about unintended consequences. brian m. carlson questions whether shallow clones are appropriate for packaging workflows that prioritize reproducibility, suggesting that source downloads should happen before building with full control over clone parameters. They identify two specific problems: (1) environment variables could break scripts that assume full history (like those using `git describe`), and (2) shallow fetches create significant server load, potentially leading to throttling.

The review acknowledges the packaging use case but argues the change could introduce hard-to-diagnose failures elsewhere in the ecosystem. The critique focuses on broader system impacts rather than implementation details, suggesting a philosophical difference about whether environment variables should influence Git's cloning behavior. This positions the discussion at the level of design tradeoffs rather than code correctness.
