The `git history squash` feature, now in its eighth iteration by Harald Nordgren, is functionally complete and ready for integration after addressing all prior feedback. The series introduces a new `git history squash` subcommand to efficiently collapse a commit range into its oldest commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach.

Key improvements in v8 include autosquash alignment (grouping `fixup!`/`squash!`/`amend!` commits under their targets in the `--reedit-message` template), stricter input validation (sanitizing all `rev-list` options to prevent silently incorrect results), and refined merge handling (allowing fully contained merges while rejecting those with external parents). The series also finalizes the ref-handling design, rejecting operations with interior refs by default while guiding users to `--update-refs=head` to explicitly retarget branches.

The only unresolved debate is whether `--reedit-message` (or `--edit`) should be the default to encourage commit hygiene, with Phillip Wood advocating for it and Harald preferring the current behavior. Now, Matt Hunter has raised a **substantive edge case**: when `--reedit-message` is omitted, the command ignores any `amend!` message targeting the first folded commit, even though it already processes `fixup!`/`squash!`/`amend!` semantics elsewhere (e.g., rejecting out-of-range targets). Hunter suggests incorporating the `amend!` message into the default squashed commit message for consistency and improved usability. This observation could prompt a small but meaningful tweak before the series is queued, though it doesn’t reopen the broader default-behavior debate. The series remains technically sound and likely to be merged soon.
