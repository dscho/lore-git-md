The `git history squash` command, proposed by Harald Nordgren, is nearly ready for integration after 14 iterations. The series implements a new standalone subcommand to collapse a commit range into a single commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach. All technical and procedural feedback has been addressed except for one final policy question: whether autosquash markers (`fixup!`, `squash!`, `amend!`) should enforce strict case-sensitive OID matching—rejecting all uppercase hexadecimal OIDs—or adopt a permissive approach that accepts all-uppercase or all-lowercase OIDs, matching `git rebase --autosquash`.

Junio C Hamano previously resolved this in favor of strict matching, citing Git’s historical convention of emitting only lowercase OIDs. However, Phillip Wood has now reopened the debate, arguing for consistency with `git rebase`, which accepts uppercase OIDs. The series is otherwise complete: input validation, merge commit handling, ref safety, and message editing are all finalized. The only remaining work is a mechanical update to Patch 7/8 to implement whichever policy is chosen, along with test coverage for uppercase OID rejection (or acceptance). Junio’s "Will replace" sign-off in v7 signals intent to merge once this is resolved, and the series is currently cooking in `seen`. The next step is a maintainer decision on the case-sensitivity policy, after which Harald will post v15 for final integration.
