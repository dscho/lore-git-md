Harald Nordgren’s `git history squash` series is now in its seventh iteration and was recently marked "Will replace" by Junio C Hamano, signaling it’s on track for the next Git release. The latest exchange with Phillip Wood, however, surfaces three unresolved design questions that could affect usability and correctness.

The core feature—collapsing a commit range into its oldest commit while preserving descendant history—is complete and addresses prior feedback: it rejects ranges with external merge parents, handles interior refs safely, and adopts `git rebase -i`’s squash-message template (though with some deviations). What’s still open is whether `--reedit-message` should be the default (Phillip argues yes for commit hygiene, Harald disagrees), whether the template should reorder `fixup!`/`squash!` commits to match their targets (currently it doesn’t, which could confuse users), and whether input validation should catch more edge cases, like marker targets outside the squashed range.

Harald has agreed to tighten input validation by checking `rev-list` options and expanding marker checks, but these changes may not land in time for the current cycle. The series is otherwise ready, with Junio’s sign-off, but these lingering questions suggest a v8 might be needed before it graduates to `next`. For now, the feature remains opt-in, and users will need to explicitly request message re-editing or ref updates.
