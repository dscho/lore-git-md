Harald Nordgren’s `git history squash` feature is now complete and ready for Junio’s final review. The series, now at v6, lets users collapse a range of commits—including those with merges—into a single commit while preserving descendant history, all without the repeated conflict stops of a rebase-based workflow.

The core design is settled: the command performs a single three-way merge of the entire range against the oldest commit’s parent, then replays descendants on top. By default, it rejects operations where any refs point to commits inside the squashed range, guiding users to `--update-refs=head` to explicitly retarget the current branch. Input syntax is flexible—multiple arguments are supported, and compound ranges like `@~3.. ^topic` work as expected. Merge commits with external parents are explicitly rejected to avoid ambiguity, and `fixup!`/`squash!`/`amend!` commits are folded like any other.

The latest patch adds the `--reedit-message` flag, which gathers all folded-in commit messages (oldest first) into an editor template, matching the behavior of `git rebase -i` when squashing. This was the last missing piece, and the implementation is clean, using Git’s existing revision-walking machinery. Phillip Wood’s thorough reviews shaped key improvements, from stricter input validation to better merge commit handling, while Junio and Patrick Steinhardt helped finalize the ref-handling design. All feedback has been addressed, and no further design changes are expected. The series is now waiting on Junio’s final assessment before merging.
