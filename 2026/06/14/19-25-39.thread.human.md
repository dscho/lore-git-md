The `git history squash` feature has reached its final form in version 11, posted by Harald Nordgren. This new subcommand lets you collapse a range of commits—including those with merge commits—into the oldest commit in that range, while preserving all descendant history. Unlike a rebase-based approach, it avoids repeated conflict resolution, making it a faster way to clean up a feature branch before merging.

The command now opens an editor by default with an autosquash-style template that groups `fixup!`, `squash!`, and `amend!` commits under their targets, matching the behavior of `git rebase -i --autosquash`. If you prefer to keep the oldest commit’s message unchanged, you can use `--no-edit`. The implementation also handles edge cases like interior merges, ref retargeting, and strict input validation—rejecting ranges that reach a root commit or have more than one tip, and protecting local branches that point into the squashed range unless explicitly overridden with `--update-refs=head`.

All prior feedback has been addressed, including Phillip Wood’s usability concerns and Junio’s requests for template consistency. The series is marked "Will replace" by Junio and is functionally complete, with Matt Hunter’s explicit sign-off on v10 confirming that the last technical questions have been resolved. The patches are now ready for integration, and the feature is positioned as a foundational piece of a larger effort to modernize Git’s history-editing infrastructure—particularly as a faster backend for `git rebase --autosquash` when combined with `git replay`.
