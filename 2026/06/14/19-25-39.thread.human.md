Harald Nordgren’s `git history squash` series is now at version 6, with all prior feedback addressed and the design finalized. The feature lets users collapse a range of commits—including merge commits—into a single commit at the oldest end of the range, while preserving descendant history. This avoids the repeated conflict stops that would come from a rebase-based approach.

The implementation is a new standalone subcommand, `git history squash`, with flags like `--reedit-message` (to edit the combined commit message) and `--update-refs=head` (to retarget the current branch to the squashed commit). By default, the command rejects operations where any refs point to commits inside the squashed range, guiding users to explicitly opt in with `--update-refs`. The input syntax is now flexible, supporting compound ranges like `@~3.. ^topic` to exclude commits already on another branch.

Key technical details include strict input validation (rejecting single-commit ranges, empty ranges, and ambiguous boundaries), explicit rejection of merge commits with external parents, and a three-way merge of the entire range against the oldest commit’s parent. The series touches `builtin/history.c`, adds new helpers like `resolve_squash_range()` and `build_squash_message()`, and includes extensive test coverage.

All prior design concerns—raised by Phillip Wood, Junio C Hamano, and Patrick Steinhardt—have been resolved. Phillip’s substantive reviews focused on usability gaps (e.g., input syntax, merge commit handling, and ref behavior), while Junio and Patrick helped finalize the ref-handling design.
