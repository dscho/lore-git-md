This thread is about the final version (v5) of Harald Nordgren’s patch series introducing `git history squash`, a new command that collapses a range of commits into a single commit while preserving descendant history. The series is now code-complete and awaiting Junio C Hamano’s final review before merging.

The command addresses a long-standing workflow gap: efficiently squashing a range of commits (including merge commits) without the repeated conflict stops of a rebase-based approach. The design has settled on a conservative default—rejecting the operation if any refs point to commits inside the squashed range—with an `advice()` message guiding users to `--update-refs=head` to explicitly retarget the current branch. This balances safety with flexibility, and the behavior has been endorsed by both Patrick Steinhardt and Junio.

The series has resolved all prior technical concerns, including strict range validation, merge commit handling, and the adoption of `--ancestry-path` to ensure predictable range resolution. The implementation is now well-tested, with coverage for edge cases like nested merges, ref-handling, and dry-run prediction. Phillip Wood’s efficiency and UX concerns have been addressed, and the code structure has been streamlined with focused helpers like `first_parent_tree_oid()` (introduced in this patch) and `build_squash_message()`.

The only remaining step is Junio’s final assessment. Unless he raises new concerns, the series is expected to merge as-is.
