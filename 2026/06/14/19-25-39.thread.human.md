The `git history squash` feature, now in its sixth iteration by Harald Nordgren, is nearing readiness for merging after addressing all prior technical feedback. The series introduces a new subcommand to collapse a range of commits into a single commit while preserving descendant history, offering a more efficient alternative to interactive rebase for this common workflow.

The core design is settled: the command performs a three-way merge of the entire range against the oldest commit’s parent, replays descendants on top, and rejects operations where refs point to commits inside the squashed range unless explicitly retargeted with `--update-refs`. Merge commits with external parents are rejected to avoid ambiguity, while fully contained merges are allowed. The `--reedit-message` flag provides a template for refining the squashed commit message, now streamlined to reduce noise by omitting `fixup!`/`amend!` subjects and using minimal visual separation.

Recent discussion has focused on usability refinements. Phillip Wood has proposed two key changes: making `--reedit-message` the default to encourage better commit hygiene, and adjusting the template to retain `squash!` commit bodies while still omitting `fixup!` content. These suggestions aim to align the command’s behavior with Git’s emphasis on meaningful commit messages. Meanwhile, Matt Hunter and Harald have highlighted a broader recoverability issue—Git’s reflog doesn’t clearly show which refs were affected by multi-ref operations like `--update-refs`, making undo operations difficult. Phillip expanded this into a systemic critique, noting that tools like Jujutsu solve this with transaction-aware reflogs, though such changes would require architectural work beyond this series.

The series is code-complete and ready for Junio’s final review. While no further design changes are expected, minor adjustments to the template or default behavior may still be considered. The recoverability discussion, though not blocking this feature, could influence future improvements to Git’s reflog design.
