The `git history squash` feature, proposed by Harald Nordgren, is now complete and ready for final review. This new subcommand allows users to collapse a range of commits—including those with merge commits—into a single commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach.

The series has evolved through six iterations, addressing all prior feedback. Key improvements include stricter input validation, support for multiple revision arguments (e.g., `HEAD~3.. ^topic`), explicit rejection of merges with external parents, and expanded test coverage. The `--reedit-message` flag lets users edit the squash commit message, seeding the editor with all folded-in commit messages (oldest first), mirroring `git rebase -i` behavior but omitting numbered markers—a minor cosmetic difference Junio noted but did not require changing. The implementation also detects and rejects operations where refs point to commits inside the squashed range by default, with an advice message guiding users to `--update-refs=head` to retarget the current branch.

Phillip Wood, Junio C Hamano, and Patrick Steinhardt provided substantive reviews, focusing on usability, input validation, and merge commit handling. All concerns have been addressed, and the series is now code-complete. The only remaining discussion is a follow-up opportunity to align the `--reedit-message` template’s appearance with `git rebase -i` by adding numbered markers, but this is purely cosmetic and does not affect functionality. Junio’s final assessment is the next step.
