**Thread identity**: Bugfix patch for memory leak in `git history reword` command, part of Patrick Steinhardt's ongoing `git history` work.

**Core problem or goal**: Fix and analyze a memory leak in `git history reword` when retrieving commit messages via `repo_logmsg_reencode()`. The leak stems from improper buffer management for re-encoded commit messages not cached in the commit slab, requiring explicit cleanup via `repo_unuse_commit_buffer`. The discussion has refined the root cause: the leak occurs when `repo_get_commit_buffer` returns a freshly allocated buffer (non-slab-cached) rather than when commits contain encoding headers, clarifying the buffer lifecycle distinction between slab-cached and dynamically allocated buffers.

**Current status**: Fix remains merged and correct. The thread now focuses on deeper analysis of *why* some commits bypass the slab cache, which could inform future optimizations or test coverage. No regression or design objections have emerged; the discussion is purely diagnostic.

**Key technical details**:
- Affects `builtin/history.c`, specifically `commit_tree_ext()`.
