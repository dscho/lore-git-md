This is the final patch in a series introducing `diff.<driver>.process` configuration for external diff tools, specifically focusing on blame integration. The patch enables blame to consult the configured diff process when determining whether a file changed in a given commit, allowing tools to indicate that certain changes (like reformatting) should not affect blame attribution.

Key technical aspects:
- Adds `diff_hunks_xpp()` variant to accept pre-populated hunks from external tools
- Modifies `pass_blame_to_parent()` to use `diff_process_fill_hunks()` and skip blame attribution when the tool reports no hunks (DIFF_PROCESS_EQUIVALENT)
- Maintains the long-running subprocess model from earlier patches
- Includes comprehensive tests showing:
  - Selective blame attribution when tools report partial changes
  - Skipping reformat-only commits when tools report no semantic changes
  - Proper bypass behavior with `--no-ext-diff`

The implementation adds about 17% overhead to blame operations due to per-commit roundtrips to the tool, though an OID-based optimization is noted as future work. The patch series as a whole has addressed all substantive review feedback, including transitioning to a C-based test helper and resolving Windows compatibility concerns.

This completes the technical implementation of the feature, with the remaining open questions being performance optimization and final maintainer sign-off. The blame integration demonstrates a key use case - skipping reformat-only commits in history analysis while preserving semantic change attribution.
