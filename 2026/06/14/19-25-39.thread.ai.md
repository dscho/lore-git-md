- **Fixup/squash/amend handling**: A marker is now **refused only when its target lies outside the range**, allowing multiple fixups for the same in-range commit to fold together. - **Rev-list option validation**: The command now **sanitizes all `rev-list` options** (including those after `--`) by forcing the walk order back to `--reverse --topo-order` and warning if the user’s options would have changed it. This fixes the v7 regression where `git history squash -- --reverse` could produce silently incorrect results.
- **Merge handling**: Interior merges are folded as long as the range has a single base, with `--ancestry-path` ensuring only commits descended from the base are included. A range reaching more than one base is rejected.

**Core problem**: Efficiently collapse a linear or merge-commit-containing range into its oldest commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach. **Finalized behavior**:
- Refs pointing to commits inside the squashed range are **detected and rejected by default**, with an `advice.historyUpdateRefs` message suggesting `--update-refs=head` to explicitly retarget the current branch to the squashed commit.
- Ranges whose **oldest commit is a `fixup!`/`squash!`/`amend!` are no longer rejected** unless the marker’s target lies outside the range. Instead, the command now **groups markers under their targets** in the `--reedit-message` template, matching `git rebase -i --autosquash`.
- **Rev-list options are now validated**: The command forces `--reverse --topo-order` and warns if user-provided options would alter the walk order, preventing silently incorrect results.
