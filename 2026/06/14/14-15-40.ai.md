This is a bugfix patch addressing a memory leak in the `git history reword` command. The leak occurs when the command retrieves a commit message buffer via `repo_logmsg_reencode()` but fails to release it with `repo_unuse_commit_buffer()`.

The patch is well-motivated, showing:
1. A clear leak report from ASAN
2. The exact call chain leading to the leak
3. The missing cleanup call
4. A straightforward one-line fix

The author notes they're unsure why the buffer wasn't being released originally, suggesting this might have been an oversight rather than an intentional omission. The change appears safe as it follows the standard pattern for managing commit buffers in Git's codebase.

This touches the relatively new `git history` command (part of Patrick Steinhardt's ongoing work) and specifically its reword functionality. The fix is narrow and focused, with no apparent wider implications beyond fixing the memory leak.
