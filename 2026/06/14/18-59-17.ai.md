This is the fourth revision of an RFC series introducing a new `diff.<driver>.process` configuration that enables external tools to inject diff hunks into Git's diff and blame pipelines while preserving downstream features like word-diff and color-moved. The key changes since v3 include:

1. **Test backend transition** - Replaced the Python test implementation with a C-based `test-tool` helper per Johannes Schindelin's recommendation, aligning with the project's direction of reducing scripting language dependencies. Junio C Hamano explicitly endorsed this approach.

2. **Enhanced validation** - Added specific warning messages for various hunk validation failures (out-of-bounds ranges, overlaps, sync mismatches) to help tool authors debug their implementations.

3. **Protocol refinement** - Now accepts start=0 with count=0 in the hunk protocol to match git diff's output for empty file sides, while normalizing to 1-based internally for validation.

4. **New test coverage** - Added cases for deleted files, malformed hunk lines, and missing capability negotiation, bringing total test coverage to 708 lines.

The series remains technically complete with comprehensive test coverage, now addressing the test implementation concern through transition to a C-based helper. The maintainer's recent stylistic guidance about email composition practices does not affect the technical direction but reinforces project communication norms. All substantive review feedback is being addressed, with Michael Montalbo demonstrating consistent application of the scripting language reduction principle across his contributions.

Key technical points:
- Uses pkt-line protocol for communication with external tools
- Tools can mark files as unchanged (no hunks) which affects both diff output and blame attribution
- Falls back gracefully to builtin diff on errors
- Includes thorough test coverage of success/error paths

The blame integration shows how this could be used to skip reformat-only commits in history analysis. Performance remains a consideration - the current implementation adds ~17% overhead to blame operations due to per-commit roundtrips, though an OID-based optimization is noted as future work.
