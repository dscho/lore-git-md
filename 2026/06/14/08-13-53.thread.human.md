The discussion centers on a proposal to add a `DEPTH` environment variable that would act as a fallback for `git clone --depth`, similar to how Git already handles other environment variables like `GIT_TRACE`. The goal is to make it easier for packaging systems to standardize on shallow clones during clean chroot builds.

brian m. carlson raised significant concerns about the change, warning it could unintentionally break scripts that assume full history but unexpectedly get shallow clones due to the environment variable. He also noted the potential server-side performance impact, as shallow fetches are more resource-intensive than regular ones.

Hadrien Loge, defending the proposal, points out that Git already has precedent for this pattern with other environment variables. He argues the change wouldn't affect existing workflows since users would only set `DEPTH` when explicitly wanting shallow clones. Loge expressed particular interest in understanding the server performance implications better.

The discussion highlights a tension between the convenience for packagers (who want consistent shallow cloning behavior) and the potential for unintended consequences. While the code change itself is small, the implications for both client-side scripting and server load make this a non-trivial decision. The thread remains active with no clear consensus yet reached.
