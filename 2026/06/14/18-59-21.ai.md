Feature: RFC for `diff.<driver>.process` to enable external diff hunk injection.

This is patch 4/6 in the series implementing a new `diff.<driver>.process` configuration that allows external tools to inject diff hunks into Git's diff and blame pipelines while preserving downstream features like word-diff and color-moved. The patch introduces the core infrastructure for the long-running process protocol.

Key technical aspects:
- Uses pkt-line protocol for communication with external tools (similar to filter processes)
- Tools can mark files as unchanged (no hunks) which affects both diff output and blame attribution
- Falls back gracefully to builtin diff on errors
- Includes thorough test coverage of success/error paths (708 lines of tests)
- Handles textconv integration and empty file cases
- Stores subprocess state on the userdiff_driver struct
- Validates hunk ranges and detects overlaps/sync violations

The implementation follows patterns from existing long-running processes (like convert.c) while adding specific validation for the hunk protocol. The test suite verifies various modes of operation including error handling and fallback scenarios.

This builds on previous discussion where Johannes Schindelin recommended moving from Python to a C-based test helper, which has now been implemented. Junio C Hamano has explicitly endorsed this direction, signaling the technical approach is sound. The patch appears well-structured with careful attention to edge cases and validation.
