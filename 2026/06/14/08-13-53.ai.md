This is a reply in an ongoing discussion about adding a `DEPTH` environment variable as a fallback for `git clone --depth`. The patch would make Git respect `DEPTH` similarly to how it handles other environment variables like `GIT_TRACE`.

The thread context reveals key concerns raised by brian m. carlson (the parent email's author): 
1. Unintended breakage risk if scripts assume full history but get shallow clones due to the environment variable
2. Server-side performance impact since shallow fetches are resource-intensive

Hadrien Loge defends the proposal by:
- Noting other existing env vars with similar behavior
- Explaining the packaging use case (clean chroot builds)
- Arguing it wouldn't affect existing flows since users would only set `DEPTH` when explicitly wanting shallow clones
- Expressing interest in understanding the server-side performance implications

The discussion highlights a tension between convenience for packagers (who want to standardize shallow clones) and potential unintended consequences. The technical merits appear debatable - while the change is small, the implications for both client-side scripting and server load warrant careful consideration. The patch remains under discussion with no clear consensus yet.
