This is the first patch in a series introducing external diff driver support via `diff.<driver>.process`, focusing on the xdiff infrastructure changes needed to accept pre-computed hunks.

The patch adds core xdiff support for external hunks by:
1. Defining a new `xdl_hunk` struct to represent hunk ranges (1-based line numbers)
2. Adding `external_hunks` and `external_hunks_nr` fields to `xpparam_t`
3. Implementing validation logic that checks for:
   - Negative counts or invalid line numbers
   - Out-of-bounds ranges
   - Overlapping/out-of-order hunks
   - Synchronization invariant violations (matching unchanged line counts)
4. Falling back to built-in diff on validation failures
5. Skipping `trim_common_tail()` when using external hunks since they reference original line numbers

The validation includes detailed warning messages to help tool authors debug issues. The implementation maintains xdiff's existing behavior while adding the new capability, with careful handling of edge cases like empty files (accepting start=0 when count=0 to match git diff output).

This foundational change enables the subsequent patches to implement the actual diff driver protocol while keeping the diff algorithm bypass logic contained within xdiff. The validation ensures external tools can't corrupt Git's diff processing even if they produce malformed output.
