This is the fourth patch in Elijah Newren's five-part series hardening merge-ort's error handling and duplicate entry detection. The patch specifically addresses cases where malformed trees containing duplicate entries could previously cause assertion failures in merge-ort.

The key change modifies `setup_path_info()` to return an error when duplicate paths are detected (rather than silently overwriting entries), causing the merge to abort with a clear message. The patch includes:

1. Conversion of `setup_path_info()` from void to int return type to propagate errors
2. Checks for duplicate entries via `strmap_put()` that will now fail the merge
3. Updated call sites to handle potential errors from `setup_path_info()`
4. A new test case that verifies the merge properly aborts when encountering a tree with both a gitlink and directory entry for the same path

The test simulates a scenario where a third-party tool creates a corrupted tree containing both a submodule gitlink and regular files under the same path. This would previously cause merge-ort's internal data structures to become inconsistent, but now cleanly aborts the merge with an error about duplicate entries.

This patch builds on the earlier error handling improvements in the series and maintains the same high standard of test coverage. It represents another step toward making merge-ort robust against malformed tree structures while providing clear feedback when corruption is detected.
