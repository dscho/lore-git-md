This is the fourth patch in Elijah Newren's merge-ort hardening series, focusing on handling corrupt trees. The patch addresses a specific case where trees contain duplicate entries - a malformed state that fsck would flag but that merge-ort previously assumed couldn't happen.

The key change makes `setup_path_info()` return an error when it detects duplicate paths, causing the merge to abort cleanly rather than silently corrupting internal data structures. The patch includes a test case that simulates this scenario by creating a tree with both a gitlink and a directory entry at the same path.

The change is well-motivated by real-world cases where such corrupt trees caused assertion failures. The implementation is straightforward - converting the void return to int and adding error handling at all call sites. The test demonstrates the new behavior by verifying the merge fails with an appropriate error message when encountering duplicates.

This continues the series' pattern of making merge-ort more robust against malformed input while maintaining clean error handling. With maintainer feedback already incorporated from earlier versions, this patch appears ready for integration.
