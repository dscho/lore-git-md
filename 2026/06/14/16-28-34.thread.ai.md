Performance optimization for `git cat-file`'s default batch format. René Scharfe updated the code to use more efficient string buffer operations (`strbuf_add_oid_hex()` and `strbuf_add_uint()`) instead of `strbuf_addf()` for the standard `%(objectname) %(objecttype) %(objectsize)` output pattern in `--batch-check` mode, showing 3-7% speed improvements in benchmarks (979ms vs 1.051s). The change affects `builtin/cat-file.c` with minimal code delta (6 added, 3 removed).

Jeff King (Peff) conducted substantive technical review, first exploring whether a more radical parser redesign using pre-parsed format strings with atom-specific callbacks could yield further gains (3% speedup for custom formats, 600ms vs 618ms). In follow-up testing, Peff determined that converting callbacks to a switch statement provided no additional benefit, confirming the callback design's adequacy. His analysis suggests deeper architectural changes would only be justified if Git unified its formatting systems (`ref-filter`, `cat-file`, `--pretty=format`), which remains an open question.
