The `git history reword` command had a memory leak that only surfaced when processing commits with encoding headers, which standard tests missed. Kaartic Sivaraam identified and fixed the issue by adding a missing `repo_unuse_commit_buffer` call in the commit-tree extension logic. The fix has been merged after review from Patrick Steinhardt and a deeper technical analysis from Jeff King, who clarified that the leak only occurs with re-encoded commit messages (those with encoding headers) due to how Git manages buffer caches.

The discussion confirmed the fix is correct but revealed two follow-up needs: better test coverage for encoded commit scenarios, and potential optimizations around bulk memory cleanup in the `git history` code path. The thread also highlighted how AddressSanitizer (ASAN) caught the leak where the test suite didn't, suggesting a gap in coverage for new commands. This is part of Patrick Steinhardt's broader `git history` work, and the fix aligns with Git's standard commit buffer management patterns.
