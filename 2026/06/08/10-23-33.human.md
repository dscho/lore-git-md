This is the final patch in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The new subcommand removes a specified commit from history while replaying its descendants on top of its parent.

The implementation builds on the infrastructure from previous patches in the series, particularly the refactored reset machinery. Key features include:
- Preventing drops of root and merge commits (with clear error messages)
- Handling working tree and index updates when HEAD moves
- Supporting dry-run mode to preview changes
- Extensive test coverage (537 lines across 4 test scripts) for various scenarios

The patch follows through on all the preparatory work from earlier in the series, cleanly integrating the new subcommand while maintaining consistency with the existing `git history` interface. The implementation appears solid, with careful attention to edge cases like dirty working trees and empty descendants.

This completes the series' goal of adding commit-dropping capability to `git history`, marking another step in the ongoing development of this experimental command. The changes are well-contained and unlikely to be controversial given the thorough review process the series has undergone.
