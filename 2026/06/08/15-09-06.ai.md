This is a review comment on the second patch of Patrick Steinhardt's 16-part series converting Git's packed object storage to use `struct odb_source` as part of the ODB abstraction effort. Karthik Nayak provides a substantive review noting that the patch exposes `struct packfile_list` and `struct packfile_list_entry` in the new `odb/source-packed.h` header, which may not be ideal since these structures are also used by the transport layer outside the ODB subsystem. He suggests these might better remain in `packfile.h` alongside `struct packed_git`.

The review acknowledges the rest of the patch looks good, focusing specifically on this architectural question about where certain data structures should live. This is a meaningful technical consideration about subsystem boundaries and header organization, not just surface-level feedback. The comment reflects an understanding of how the packed storage changes interact with other parts of Git's codebase, particularly the transport layer.

This feedback comes early in the series (patch 2/16) and raises a design question that could influence how subsequent patches handle the relationship between the ODB abstraction and other parts of the system that use packfiles. The thread context shows this is part of a larger, multi-patch effort to fully decouple packed object storage from the files backend.
