This is a memory leak fix for the transport-helper subsystem, part of a larger GSoC series (v12 patch 1/12) implementing remote object metadata queries. The patch addresses a case where `data->name` allocated during transport initialization wasn't being freed if the helper failed to start properly before disconnect.

The change moves the `FREE_AND_NULL(data->name)` call outside the conditional block in `disconnect_helper()`, ensuring cleanup happens regardless of whether the helper was fully initialized. This plugs a leak that could occur during error paths in transport setup. The fix is straightforward and uncontroversial, with clear motivation from the commit message referencing prior discussion.

As the first patch in a mature series that's gone through 12 iterations, this appears to be final cleanup work rather than substantive new functionality. The change demonstrates good attention to resource management in the transport layer, which is particularly important given the security focus of the overall series.
