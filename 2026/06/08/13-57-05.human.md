This is the second patch in Derrick Stolee's series to add ways to disable config includes. It implements the first of two proposed mechanisms - a `GIT_CONFIG_INCLUDES=0` environment variable that globally prevents Git from following include directives in config files.

The patch adds the environment variable handling in config.c, documents it in git-config.txt, and includes thorough test coverage showing it works for both `include.path` and conditional `includeIf` directives. The tests also verify it prevents alias overrides via included configs, which was a key motivating use case.

The implementation appears clean and focused, building on existing config include infrastructure. Stolee's commit message clearly explains the sandboxing use case where this would be valuable - particularly for build systems that need to run Git commands with predictable behavior and controlled filesystem access.

This looks like a well-constructed patch that solves a real problem while maintaining backwards compatibility (the default remains to respect config includes). The test coverage is comprehensive, checking both the basic functionality and edge cases like alias overrides. Given Stolee's track record with config system changes and the clear problem statement, this seems likely to be uncontroversial.
