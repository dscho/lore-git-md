This is a review comment from Patrick Steinhardt on Pablo Sabater's RFC patch about `git history reword` behavior. The patch proposed making the command abort when the new commit message matches the original, citing the command's in-memory nature and branch-update costs as rationale.

Patrick points out a technical consideration the original patch missed: the same message-comparison logic is also used by `git history fixup --reedit-message`, where aborting on unchanged messages wouldn't make sense. This suggests the proposed behavior change needs to be more narrowly scoped to just the `reword` operation rather than applying to all message-editing paths through the shared `commit_tree_ext()` function.

The review is substantive - it identifies a concrete technical interaction with another command's expected behavior, though it doesn't propose specific implementation alternatives.
