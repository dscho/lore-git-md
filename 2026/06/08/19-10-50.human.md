This is the first patch in the final version of a performance optimization series for Git's priority queue implementation. The patch renames the internal `.nr` field to `.nr_` to prevent direct access from outside the prio-queue module, and introduces helper functions `prio_queue_size()` and `prio_queue_for_each()` for safe access to queue properties and iteration.

The changes are mechanical but wide-ranging, touching 14 files across Git's codebase to convert all external users of the priority queue to use the new access patterns. The patch maintains the same performance characteristics while enforcing better encapsulation. Key aspects:

- The rename to `.nr_` follows Junio's naming convention suggestion from earlier reviews
- New helpers provide clean access patterns for common operations
- All conversions preserve existing behavior while using the safer interfaces
- The changes are part of a larger optimization effort that shows measurable speedups (1.7-2.7%) in traversal-heavy operations

This patch represents the final naming and encapsulation changes needed before the core optimization (deferred removal tracking) can be merged. With all prior review feedback addressed and comprehensive testing showing no regressions, this appears ready for inclusion.
