This is a feature patch adding metadata tracking to Git worktrees, now with updated implementation and test coverage based on previous discussion. The patch has evolved through the thread with both practical use cases (from Kristoffer Haugsbakk) and philosophical justification (from Chris Torek) supporting its inclusion.

The key additions are:
1. Creation timestamps for worktrees (stored in `.git/worktrees/<id>/created`)
2. Free-form descriptions (stored in `.git/worktrees/<id>/description`)
3. Last-updated timestamps (derived from `HEAD` file mtime)
4. New `git worktree describe` subcommand to manage descriptions
5. Enhanced `git worktree list` with sorting and display options

The implementation is thorough, with complete test coverage in `t2410-worktree-metadata.sh`. The design remains backward compatible - worktrees created before this feature will show "unknown" for creation time. The patch handles edge cases like legacy worktrees, main worktree exclusion, and timezone-aware display.

The discussion has shifted from whether to add the feature (now well-justified) to implementation details like timestamp strategy (creation vs last-updated). Phillip Wood still advocates for last-updated timestamps, but the current patch maintains both metrics. The documentation has been expanded to capture both practical scenarios and the conceptual framework that worktrees are general-purpose workspaces.

This appears ready for final review, with the main outstanding question being whether to keep both timestamp types or simplify to just one. The implementation quality is high, with careful attention to backward compatibility and edge cases.
