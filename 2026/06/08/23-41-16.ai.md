**Feature proposal** for submodule mirroring infrastructure, continuing the discussion about repository identity vs. location. Jeff King (Peff) responds to Simon Richter's concerns about using `url.*.insteadOf` for submodule mirroring, clarifying the decentralized use cases that motivate the current design.

Peff acknowledges Simon's Debian use case where submodules are hosted relative to the superproject, but emphasizes that Git must also support decentralized scenarios where submodules have no administrative relationship to their superproject. He explains that while Simon's relative URL approach works for coordinated mirroring setups, the current canonical URL system remains necessary for general cases where repositories are mirrored independently.

The email highlights two key tensions: between centralized mirroring needs and decentralized Git workflows, and between immediate practical solutions (like Debian's relative URLs) and generalizable infrastructure. Peff suggests that while the mirror mapping process could output `insteadOf` settings automatically, he leaves open how that mapping would be discovered or distributed - recognizing this as the core unsolved problem for institutional users like Debian.

This exchange moves the discussion forward by explicitly framing the tradeoffs between different mirroring approaches, while maintaining focus on Git's need to serve both coordinated mirroring scenarios and fully decentralized use cases. The technical direction appears to be converging toward enhancing URL rewriting capabilities while leaving the mapping distribution problem to higher-level tools.
