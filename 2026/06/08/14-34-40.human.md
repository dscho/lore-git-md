This is a review of the second patch in Derrick Stolee's series to disable config includes, focusing on the environment variable mechanism. Patrick Steinhardt raises thoughtful questions about the design's flexibility.

Patrick notes that while the patch's core use case (sandboxed builds) makes sense, he hadn't considered the scenario where users include config files from the working directory - a practice he finds "quite scary." His main concern is whether the binary on/off approach of `GIT_CONFIG_INCLUDES=0` might be too restrictive, suggesting an allow-list mechanism could provide more granular control over which includes are processed.

The review is substantive, engaging with the technical tradeoffs of the proposed solution rather than just surface-level issues. Patrick doesn't reject the approach outright but questions whether it fully addresses real-world needs, particularly for tools that might want to selectively honor some project-specific configs while blocking others. His comment about potentially "overthinking" this shows awareness that his suggestion might complicate the implementation.

This feedback indicates the patch may need to either justify its all-or-nothing design more clearly or consider extending the mechanism to support more nuanced control. The review doesn't identify any implementation flaws in the current code but prompts important design discussion about the feature's scope.
