This is a review from Junio C Hamano on Tamir Duberstein's performance optimization for `git ls-files`. The patch aims to speed up pathspec filtering by applying it before expensive `lstat` operations, showing dramatic improvements (60.7s->1.06s) in large repositories.

Junio raises two substantive technical points about the change:

1. **Performance tradeoff concern**: He notes that while the optimization helps when most entries don't match the pathspec, it could theoretically cause a regression when most entries do match (due to the extra `match_pathspec` call). He suggests adding a performance test case for this scenario.

2. **Behavioral change question**: He identifies a potential interaction with `--recurse-submodules`, where the early pathspec filtering might prevent submodule recursion that would normally occur. This suggests the optimization might unintentionally alter behavior for submodule cases.

The review is substantive, engaging with both the performance implications and correctness of the change. Junio doesn't reject the approach but identifies areas needing verification - a characteristic maintainer review that pushes for completeness while acknowledging the value of the optimization.
