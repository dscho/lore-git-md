This is a performance bug report from D. Ben Knoble about `git diff` being significantly slower in secondary worktrees compared to the main worktree. The email provides detailed benchmark data showing a 10x slowdown (3.4ms vs 223ms) when running `git diff` in a secondary worktree, with similar performance gaps observed in a large corporate repository.

The author has done preliminary investigation using `perf` and found key differences in where time is spent - the main worktree spends time in path-related functions while the worktree spends more time in file comparison and filtering operations. The email includes comprehensive `perf stat` output showing the worktree version executes ~150x more instructions and has twice as many page faults.

Knoble asks two key questions: whether this is a known issue being worked on, and how they can help identify problem areas. The email demonstrates solid technical investigation and offers to contribute to a fix, suggesting this is a serious and well-documented performance regression worth attention from the diff/worktree maintainers.
