This is a review response from the Git maintainer regarding the test infrastructure patch series introducing a lint tool for converting bare 'grep' assertions to 'test_grep'.

Junio Hamano expresses reservations about the automated rewriting approach, preferring instead to add diagnostic checks to the existing test-lint framework that would flag problematic grep usage without automatically modifying files. He also notes that some grep uses are implementation details rather than assertions and should remain unchanged.

The review raises two substantive concerns:
1. The tool's automated rewriting capability may be undesirable compared to a diagnostic-only approach
2. The conversion needs to be more selective about which grep uses are actually test assertions versus internal plumbing

This feedback suggests the series may need significant restructuring to align with the maintainer's vision for how test linting should work. The author will likely need to rework the approach to focus on detection rather than automatic fixes and add logic to distinguish assertion grep from other grep uses.

The review doesn't question the technical implementation of the fundamental design choice, indicating this may require revisiting the series' core premise rather than just making incremental adjustments.
