This is a review of the second patch in Derrick Stolee's series to disable config includes, focusing on the environment variable mechanism. Patrick Steinhardt raises thoughtful questions about the design approach.

Patrick acknowledges the validity of the use case (preventing config includes in sandboxed environments) but expresses two concerns:
1. Some tools might actually want to read project-relative configuration
2. A binary on/off switch may be too restrictive - an allow-list mechanism could provide more flexibility

The review doesn't identify any technical flaws in the implementation but questions whether the current design offers enough granularity. Patrick suggests considering an allow-list approach that would let users specify which include locations should be evaluated rather than a global disable.

This is a substantive review that engages with the design tradeoffs rather than just the code mechanics. While not rejecting the patch outright, it raises important questions about whether the current solution might be too blunt an instrument for real-world use cases. The feedback suggests the feature might benefit from more nuanced control over which includes get processed.

The review maintains a constructive tone while probing the design assumptions. It doesn't propose specific implementation changes but opens the door for discussion about whether the current approach should be modified before merging.
