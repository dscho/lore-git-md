This is a security hardening patch in the `remote-object-info` series, addressing validation of format placeholders when querying remote object metadata. The patch fixes two critical issues in the client-side implementation:

1. Previously, unsupported format placeholders could cause segfaults due to uninitialized `data->type` values when the remote didn't return type information. The patch initializes this to `OBJ_BAD` and adds NULL checks.

2. The validation was too permissive - using `strstr()` could incorrectly match partial atoms. The patch introduces an explicit allow-list of supported remote atoms (`objectname` and `objectsize`) and makes unsupported atoms return empty strings rather than failing, matching `for-each-ref`'s behavior for inapplicable placeholders.

The changes include:
- Adding an `is_remote` flag to track remote queries
- Implementing strict allow-list validation for remote atoms
- Initializing `data->type` safely
- Updating tests to expect empty strings rather than errors for unsupported placeholders
- Documenting the new behavior in the man page

This patch represents the final security hardening for the format validation in the remote object info feature, ensuring safe handling of all edge cases while maintaining compatibility with the established `for-each-ref` behavior pattern.
