Feature patch implementing `--linearize` option for `git replay`, completing the 3-patch series from Toon Claes and Johannes Schindelin (Dscho). This final patch adds the core functionality to flatten merge commits into linear history, mimicking `git rebase --no-rebase-merges` behavior.

The implementation:
- Adds `--linearize` option to CLI and config
- Modifies commit picking logic to skip merge commits when linearizing
- Maintains existing behavior for non-linear cases
- Includes test coverage in t3650
- Explicitly disallows combining with `--revert`

Key technical details:
- When linearizing, merge commits are mapped to their first parent
- New helper `pick_regular_commit()` handles the linear/non-linear cases
- Touches replay.c commit mapping logic and replay.h option definition
- Adds documentation for the new option

The patch builds on the preparatory refactors from patches 1-2 (enum-to-boolean conversion and commit mapping helpers). It represents a collaborative approach between Toon and Dscho, offering an alternative to Dscho's separate merge-replay series. The implementation appears clean and well-tested, with clear documentation of the new behavior.
