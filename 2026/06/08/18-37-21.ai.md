This is the third and final patch in Toon Claes’s three-patch series introducing a `--linearize` option to `git replay`. It implements the core feature: when `--linearize` is given, `git replay` flattens the commit topology by dropping merge commits and cherry-picking only the non-merge commits in order, matching the default behavior of `git rebase --no-rebase-merges`.

The patch adds the CLI option (`--linearize`) to `builtin/replay.c`, updates the man page (`Documentation/git-replay.adoc`) with a short description, and extends the internal `replay_revisions` logic in `replay.c` to skip merge commits when the `linearize` flag is set. A new test in `t3650-replay-basics.sh` verifies that the resulting history is linear and that the commit messages match the expected order.

Key technical details: the `linearize` boolean is added to `struct replay_revisions_options`, the `pick_regular_commit` helper is modified to accept an optional `replayed_base` parameter (used to chain cherry-picks in linear mode), and the main replay loop now conditionally skips merge commits. The patch also enforces mutual exclusivity between `--linearize` and `--revert` in the option parser.

The implementation is straightforward and the test coverage is minimal but sufficient for the basic case. The commit message positions this as a simpler alternative to Johannes Schindelin’s earlier merge-replay work, suggesting the two modes could coexist in the future. No review feedback has appeared yet, so the patch remains an initial proposal.
