This is the first patch in Patrick Steinhardt's v3 series documenting the `b4` tool workflow for Git contributors. The patch updates the "MyFirstContribution" tutorial to recommend "shallow threading" of cover letters - linking each new version's cover letter back to the first version's cover letter rather than the immediately preceding one.

The change addresses a practical issue where deep threading (each version linking to the previous) creates excessively nested email threads that become hard to follow. The patch modifies four instances in the documentation where deep threading was previously recommended, replacing them with the shallow threading approach.

This is a straightforward documentation change that follows from earlier discussion in the thread where threading terminology was clarified. The patch is part of a larger effort to standardize contributor workflows around the `b4` tool while improving the mailing list experience. The v3 iteration leaves the final decision on threading style (shallow vs status quo) to the maintainer, with Patrick indicating willingness to drop this patch if the maintainer prefers the current behavior.

The change is well-contained and mechanically sound, updating the tutorial to match the project's evolving best practices for patch submission. It represents one piece of a coordinated documentation update that has already addressed all substantive technical feedback from earlier rounds of review.
