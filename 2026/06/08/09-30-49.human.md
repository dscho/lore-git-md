This is a review response from Patrick Steinhardt on Pablo Sabater's RFC patch to add success feedback to `git history reword`. Patrick questions whether the change aligns with Unix philosophy (the "rule of silence") and raises several technical concerns about the implementation's scope.

Patrick's main critique is that commands should remain silent unless reporting an error, citing the Unix principle that "a program should not print unnecessary output." He suggests that if feedback is needed, it should be part of a verbose mode that could apply consistently across all `git history` subcommands, not just `reword`. The review identifies three specific issues with the current approach: it only shows the rewritten commit without indicating HEAD changes, omits other affected branches, and lacks justification for treating `reword` differently from similar subcommands like `fixup` or `split`.

The review is substantive, engaging with both design philosophy and implementation details. Patrick's position reflects his role as the primary maintainer of the `git history` feature - he's steering toward consistency across subcommands rather than piecemeal UX improvements. This suggests the patch will need to either broaden its scope to cover other subcommands or find stronger justification for `reword`-specific behavior. The author may also need to address whether silent operation is truly a UX gap given Git's existing conventions.
