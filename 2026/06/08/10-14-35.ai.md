This is the final patch in a 12-part security-hardening series that implements remote object metadata queries via `git cat-file --batch-command`. The patch makes the format placeholder validation dynamic based on server capabilities rather than using a static allow-list.

The key changes in this final version:
- Replaces the hardcoded allow-list for remote query placeholders with a dynamic one based on server-advertised capabilities
- Adds support for future expansion by mapping protocol options to format atoms (currently "size" -> "objectsize" and "type" -> "objecttype")
- Ensures proper cleanup of allocated memory for the dynamic allow-list
- Maintains backward compatibility by still allowing "objectname" for all remote queries
- Includes comprehensive error handling for unsupported server capabilities

The implementation now properly handles cases where servers may support different subsets of metadata (like only size but not type) by filtering requests based on advertised capabilities. This makes the feature more robust and future-proof while maintaining security by strictly validating all inputs.

With this final hardening, the series addresses all identified security concerns around remote object metadata queries and is ready for merging. The implementation has been thoroughly reviewed across 12 iterations with input from multiple core contributors.
