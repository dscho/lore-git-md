This is a review response to a feature proposal about remote HEAD tracking configuration. Jeff King (Peff) weighs in on Matt Hunter's suggestion to add a global `remote.followRemoteHEAD` setting as a default for all remotes.

Peff confirms that Hunter's use case (disabling remote HEAD tracking to reduce branch listing noise) is reasonable and validates the core problem: the current per-remote configuration requires repetitive setup across repositories. He identifies this as a gap in the recent `followRemoteHEAD` feature implementation, comparing it to how `fetch.prune` serves as a global fallback for per-remote prune settings.

The review notes the known issue with Git's remote-config namespace where defining any key (even without a URL) makes the remote "exist" in a half-baked state. Peff endorses Hunter's proposed solution direction while acknowledging the naming decision between `fetch.*` and `remote.*` namespaces remains open. His tone is supportive and constructive, treating this as a natural evolution of the feature rather than a fundamental redesign.

This is a substantive review that engages with both the technical merits and the configuration ergonomics, coming from one of Git's most experienced contributors. The interaction suggests the feature proposal is likely to move forward, though the exact configuration namespace choice may need discussion.
