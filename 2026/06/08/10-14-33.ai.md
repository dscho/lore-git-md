This is part 10/12 of a security-focused series adding remote object metadata queries to `git cat-file --batch-command`. The patch implements the client-side `remote-object-info` command that allows querying object sizes from remote servers without downloading the full objects.

Key technical aspects:
- Adds new `remote-object-info` command to `cat-file --batch-command` that takes a remote URL and one or more object IDs
- Currently only supports the `%(objectsize)` format specifier (other specifiers like `%(objecttype)` will be added later)
- Includes comprehensive tests across git://, file:// and http:// transports
- Verifies objects aren't downloaded locally by checking they remain "missing" after remote queries
- Handles batch mode and null-delimited input (-Z) correctly
- Validates inputs (malformed OIDs, missing objects, etc)
- Requires protocol v2 and server capability advertisement (transfer.advertiseobjectinfo)

The implementation follows the established pattern of buffering requests before sending to minimize round trips. The tests demonstrate the functionality works while maintaining security invariants - objects are queried but not downloaded unless explicitly requested.

This builds on the server-side capability advertisement added in earlier patches and represents the main user-facing functionality of the series. The careful input validation and transport integration suggest this is production-ready code.
