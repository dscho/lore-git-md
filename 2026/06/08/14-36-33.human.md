This is a maintainer response to a feature proposal for worktree improvements, specifically copy-on-write (CoW) worktree creation and shared-branch worktrees. Junio C Hamano raises thoughtful questions about the design approach.

Junio questions why CoW support should be opt-in rather than always-on when available, suggesting the implementation could transparently use CoW when possible without user configuration. He notes that if CoW behaves identically to regular copies (just more efficiently), there may be no need for a `--reflink` option at all. The probing mechanism could automatically use CoW when supported by the filesystem.

For the branch-sharing aspect, Junio clarifies that the current single-branch-per-worktree restriction is a safety feature unrelated to file sharing. He points out a potential confusion scenario where concurrent commits from different worktrees on the same branch could lead to unexpected `git diff` behavior, as each worktree would see the other's changes reverted in its diff.

The response indicates these are fundamental design questions that need addressing before the feature can proceed. Junio's tone suggests he's open to the improvements but wants to ensure the implementation approach aligns with Git's principles of safety and transparency. The questions imply the current proposal may need revision to either:
1) Make CoW fully transparent when safe, or
2) Better document why opt-in behavior is necessary
And to more carefully consider the implications of shared-branch worktrees.
