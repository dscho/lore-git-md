This is the third version of Patrick Steinhardt's patch series introducing a "drop" subcommand to the experimental `git history` command. The series builds on previous work to add commit-dropping capability that removes a specified commit and replays its descendants on top of its parent.

Key changes in v3:
- Fixed commit message typos
- Made `update_orig_head` and `skip_ref_updates` flags mutually exclusive
- Improved example syntax using fancy revisions
- Added detection of working tree conflicts in dry-run mode
- Consistently used subshells in tests
- Renamed `RESET_HEAD_ORIG_HEAD` to `RESET_HEAD_UPDATE_ORIG_HEAD` per Phillip Wood's suggestion

The series refactors the `reset_head()` API to support these operations, splitting the work into 9 patches that:
1. Extract helper functions for index handling
2. Modernize reset flags and add dry-run capability
3. Enable skipping ref updates and specifying HEAD objects
4. Remove assumptions about clean indexes
5. Finally implement the drop subcommand with extensive test coverage

The implementation now properly handles worktree conflicts during dry-run operations and has addressed several technical concerns raised in previous rounds. While some API design questions remain (notably around opt-in vs opt-out HEAD updates), Patrick proposes deferring those to a follow-up series to keep this focused.

The changes touch core reset machinery (reset.c, read-cache.c) and add 537 lines of new tests across 4 scripts. Given Patrick's careful approach and the thorough test coverage, this appears to be uncontroversial infrastructure work that enables useful functionality in the history command.
