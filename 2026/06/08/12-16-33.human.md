This is a review comment from Junio C Hamano on Pablo Sabater's RFC patch to add feedback output to `git history reword`. The patch is part of an ongoing discussion about making this experimental command more user-friendly while balancing Git's traditional "rule of silence."

Junio raises an important consistency question: should this feedback behavior align with other `git history` subcommands (split, drop, fixup) rather than just matching `git commit --amend`? This suggests the decision about output verbosity should be made holistically for the entire `history` command family.

The review is substantive - it doesn't just comment on style or formatting, but engages with the design principle of command consistency. Junio doesn't outright reject the idea of feedback, but implies the solution should consider the broader command set. This continues the thread's theme of weighing porcelain usability against Git's traditional output minimalism.

The patch itself is technically sound (as noted in the parent summary), but Junio's comment indicates the design discussion isn't settled. The next steps likely involve either:
1. Surveying other `history` subcommands' output behavior
2. Proposing a consistent output policy for all `history` commands
3. Possibly adding a `--verbose` flag as previously suggested by Patrick Steinhardt

This moves the conversation forward by framing the feedback question in terms of subsystem-wide consistency rather than just this one subcommand.
