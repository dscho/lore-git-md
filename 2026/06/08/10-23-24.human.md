This is the third version of Patrick Steinhardt's patch series adding a "drop" subcommand to the experimental `git history` command. The series now consists of 9 patches that refactor the reset machinery and implement the new functionality.

The `git history drop` command removes a specified commit from history and replays its descendants on top of its parent. The implementation builds on previous work in the history command and includes extensive test coverage (537 new test lines).

Key changes in v3:
- Fixed commit message typos
- Made `update_orig_head` and `skip_ref_updates` flags mutually exclusive
- Improved example documentation with fancy revision syntax
- Added detection of working tree conflicts in dry-run mode
- Consistently used subshells in tests
- Renamed `RESET_HEAD_ORIG_HEAD` to `RESET_HEAD_UPDATE_ORIG_HEAD` per review feedback

The series has seen substantive review from Phillip Wood, who raised important questions about the API design of `reset_head()`. Patrick has incorporated much of the feedback while proposing to address some larger design questions in a follow-up series. The patches touch several core components including the reset machinery, ref updates, and working tree handling.

This appears to be a well-considered addition to the history command, with careful attention to edge cases and thorough test coverage. The changes to `reset_head()` may have implications beyond this series, but the incremental approach and clear documentation should help minimize risk. Given Patrick's track record with this command and the careful evolution of the series, this seems likely to be uncontroversial.
