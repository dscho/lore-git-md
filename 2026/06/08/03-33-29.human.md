Performance optimization for ref-filter's --contains checks.

This patch unifies the traversal logic used by `git branch --contains` and `git for-each-ref --contains` with the more efficient memoized algorithm previously only by `git tag --contains`. The key improvement is caching traversal results across ref checks when they share common history, avoiding redundant graph walks.

The change shows dramatic speedups in benchmarks - from 104s to 0.47s (223x faster) when checking 62k remote-tracking refs. The implementation handles edge cases like cyclic replacement refs by falling back to a full reachability check when cycles are detected.

This completes work started in 2015 to unify the different --contains implementations. The patch includes thorough test coverage of both the performance gains and edge case handling.
