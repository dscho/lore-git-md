This is a technical discussion about performance tradeoffs in Tamir Duberstein's `git ls-files` optimization patch. Jeff King (Peff) provides concrete measurements showing the worst-case scenario where the optimization could degrade performance - when running `git ls-files` with all files as pathspecs (a rare operation). 

Peff demonstrates that with 10,000 files, the patched version takes ~800ms compared to ~15ms without the patch in this edge case. He explains this is because the current code can skip pathspec matching entirely when files are unmodified (via lstat first), while the patched version must always check pathspecs. However, he notes this is an unrealistic workload and that improving pathspec matching itself would be a better solution if this becomes problematic.

The discussion shows the patch has been thoroughly vetted, with all major concerns addressed. Peff's analysis confirms the optimization's benefits for the common case (selective pathspecs) outweigh this theoretical regression, and suggests pathspec matching improvements as a future direction rather than blocking the current change.
