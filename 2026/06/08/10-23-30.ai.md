This is patch 6/9 in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch modifies the `reset_head()` API to allow callers to specify the source commit for a reset operation, rather than always deriving it from HEAD.

The change introduces a new `oid_from` field in `struct reset_head_opts` that callers can use to pass in an arbitrary commit OID. When set, this overrides the default behavior of reading HEAD. The implementation maintains all existing error handling paths and fallbacks.

This is a focused infrastructure change that enables more flexible use of the reset machinery, particularly for the history command's drop operation which needs to reset from a specific point in the commit graph. The patch follows the series' pattern of incrementally modernizing the reset API while maintaining backward compatibility.

The change is small (9 lines net) and well-contained, touching only reset.c and reset.h. It builds on the previous patches' refactoring of the reset machinery and will be used by the upcoming drop subcommand implementation in later patches.
