This is the sixth patch in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch extends the `reset_head()` API to allow callers to specify which commit they want to reset from, rather than always using HEAD.

The change adds an `oid_from` field to `struct reset_head_opts` that callers can populate with the starting commit OID. This is useful when the caller already knows the commit they want to reset from (as the history drop command will) or wants to reset from a commit other than HEAD. The implementation maintains backward compatibility by falling back to reading HEAD when `oid_from` is NULL.

This appears to be a straightforward and well-contained change that enables more flexible use of the reset machinery. The patch is small (9 lines net change) and focused, with clear documentation of the new field. It builds on the reset API modernization work in earlier patches of the series.
