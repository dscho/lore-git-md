This is a review response in the thread about adding a global `remote.followRemoteHEAD` configuration option. Jeff King (Peff) provides substantive feedback on Matt Hunter's proposal to create a global default for the per-remote `followRemoteHEAD` setting introduced in Git 2.48.

Peff confirms that Hunter's use case (disabling remote HEAD tracking to reduce branch listing noise) is reasonable and validates the need for a global configuration option. He identifies this as a gap in the original feature implementation, drawing a parallel to how `remote.*.prune` falls back to `fetch.prune`. The review notes the long-standing issue with remote-config namespaces where defining any key makes a remote "exist" even without a URL, though acknowledges the ambiguity is unavoidable.

While supportive of the general approach, Peff leaves open the naming should follow `fetch.followRemoteHEAD` or `remote.followRemoteHEAD` patterns, recognizing both namespaces have merit. The review provides clear technical guidance while avoiding prescriptiveness, positioning this as a natural extension of existing configuration patterns rather than a controversial change.

This is a substantive review that engages with both the immediate proposal and broader configuration design considerations in Git, offering experienced perspective while leaving implementation decisions to the author. The tone is collaborative and constructive, typical of Peff's thorough but pragmatic review style.
