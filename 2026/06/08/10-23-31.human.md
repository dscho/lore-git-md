This is patch 7/9 in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch modifies the `reset_head()` function to stop assuming the index is clean before being called, which is necessary for the upcoming drop functionality.

The change removes an optimization from 2022 that skipped cache tree updates during resets, since the existing callers (rebase and sequencer) always started with a clean index. The new drop subcommand will need to handle dirty indexes, so the patch now only skips cache updates for hard resets where we know the index will be clean afterward.

Patrick notes the original performance optimization was negligible anyway. The change is small (5 lines modified) and focused, touching only reset.c. It maintains the existing behavior for hard resets while properly supporting the new use case. This appears to be a straightforward infrastructure change needed for the larger series.
