Ben Knoble suspected, but a counter-based mechanism that only triggers index refreshes when stat-dirty paths without content changes are detected. This guard, introduced in commit aecbf914, initializes `skip_stat_unmatch` to 1 when `diff_auto_refresh_index` is true and increments it for each "ghost change" (stat-dirty but content-unchanged path), ensuring refreshes only occur when such paths exist. This revelation reframes the problem: the guard is functionally correct but may represent an overly subtle design choice that prevents index persistence in `git diff` while allowing it in `git status` (which explicitly calls `repo_updated_index_if_able`).

Three solution paths remain under active consideration:
