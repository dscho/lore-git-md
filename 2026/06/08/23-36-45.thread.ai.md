Thread summary:

Performance investigation in worktree diff operations initiated by D. Ben Knoble, with key analysis from Jeff King. The thread began with Knoble reporting a 10x slowdown in `git diff` operations in secondary worktrees (223.3ms vs 3.4ms in main worktree), particularly affecting shell prompt responsiveness. Profiling showed secondary worktrees spending more time in `ie_match_stat` and `ce_modified_check_fs` with 150x more CPU instructions.

Jeff King's response recontextualized the issue as a racy-git problem rather than worktree-specific regression. His tests on the Linux kernel repo showed the worktree case running faster (20ms vs 189ms), demonstrating the slowdown occurs when files share modification times with index entries, forcing full content checks. King identified this as documented behavior in `racy-git.adoc` and suggested enabling USE_NSEC at build time for nanosecond-precision timestamps to reduce false positives triggering content checks.

The thread has shifted from investigating a potential worktree regression to understanding fundamental racy-git behavior affecting mtime-based comparisons. King's analysis points to build configuration (USE_NSEC) as a potential solution path rather than worktree-specific code changes. The discussion remains open regarding whether this fully explains the original observations or if additional worktree-specific factors may still be involved.
