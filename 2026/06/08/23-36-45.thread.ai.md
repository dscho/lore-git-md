Thread summary:

Performance regression in worktree diff operations reported by D. Ben Knoble. The issue manifests as 10x slower `git diff` execution in secondary worktrees (223.3ms) compared to the main worktree (3.4ms), particularly affecting shell prompt responsiveness when checking dirty status. Benchmark data shows the slowdown occurs in basic diff operations without `--cached`. Profiling indicates secondary worktrees spend more time in `ie_match_stat`, `ce_modified_check_fs`, and data conversion paths versus the main worktree's efficient `preload_thread` and symlink checking, with 150x more CPU instructions and double the page faults. The regression reproduces back to Git v2.50.0. Knoble seeks confirmation if this is a known issue and offers to investigate further, noting potential relevance to the worktree and object-file subsystems where Patrick Steinhardt and Jeff King have expertise. No responses or suggested solutions yet.
