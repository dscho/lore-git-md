Thread summary:

Performance investigation into worktree diff operations, initiated by D. Ben Knoble, identified timestamp precision as the root cause of `git diff` slowdowns in secondary worktrees (223.3ms vs 3.4ms in the main worktree). The thread established that racy-git scenarios—where second-granularity timestamps force full content checks via `ie_match_stat`/`ce_modified_check_fs`—are the primary culprit. Solutions explored include `git update-index --refresh`, nanosecond timestamp precision (`USE_NSEC`), and architectural refinements to track or eliminate racy entries.

Jeff King (Peff) proposed and now prefers a minimal patch that removes the `#ifdef USE_NSEC` guard in `read-cache.c:is_racy_stat()`, enabling nanosecond-aware timestamp comparisons unconditionally. This 8-line change eliminates racy entries at the source by leveraging existing nanosecond precision infrastructure, resolving the performance issue without architectural changes or tradeoffs. Testing confirms the problem "goes away" with this approach. Junio C Hamano acknowledged the patch with mild approval ("That's cute"), signaling recognition of its elegance and effectiveness while leaving room for further validation of edge cases (e.g., the original rationale for the `USE_NSEC` conditional).

An alternative proposal from Junio—adding a field to the `istate` structure to track racy entries for auto-refreshing—remains viable but is now secondary to Peff’s root-cause fix. Junio’s approach avoids propagating flags through the diff machinery and aims to sidestep the first-diff performance regression seen in Peff’s earlier `DIFF_RACY_IS_MODIFIED` patch (1800ms vs 500ms baseline). Peff’s latest patch, however, resolves the issue without such tradeoffs. Historical context revealed the counter-based guard (`1 < rev.diffopt.skip_stat_unmatch`), introduced in commit aecbf914 (2007), as a dual-purpose mechanism that has proven confusing; Peff’s patch sidesteps this complexity entirely.

Technical details:
- **Files touched**: `read-cache.c` (`is_racy_stat`, `ie_match_stat`), with potential future changes to `builtin/diff.c` (conditional guard logic) or diffcore subsystem.
- **Key symbols**: `is_racy_stat()` (now unconditionally nanosecond-aware), `ie_match_stat()`, `rev.diffopt.skip_stat_unmatch`, `USE_NSEC`, `st_size` field in index entries.
- **Behavior changes**: Racy entries are eliminated when nanosecond precision is available. No on-disk format changes.
- **Performance impact**: Resolves the worktree diff slowdown (223.3ms → 3.4ms) without regressions.
- **Test coverage**: Performance measurements in worktree scenarios (e.g., `t/perf/p7820-git-diff-worktree.sh`), racy-git test cases, and platform-specific timestamp precision validation.

Open questions:
- Whether Peff’s patch introduces hidden edge cases, given the original `USE_NSEC` conditional’s purpose (avoiding stat-matching failures when the kernel’s in-memory cache dropped nanosecond precision).
- Whether Junio’s `istate` field proposal remains relevant as a fallback or architectural refinement.
- Long-term direction for the counter-based guard in `builtin/diff.c`, given that timestamp precision now addresses the root cause.
