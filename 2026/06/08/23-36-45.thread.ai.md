Thread summary:

Performance investigation into worktree diff operations, initiated by D. Ben Knoble, identified timestamp precision as the root cause of `git diff` slowdowns in secondary worktrees (223.3ms vs 3.4ms in main worktree). The thread has established that racy-git scenarios—where second-granularity timestamps force full content checks via `ie_match_stat`/`ce_modified_check_fs`—are the primary culprit, with `git update-index --refresh` and `USE_NSEC` (nanosecond timestamp precision) both serving as effective but incomplete solutions.

The discussion has evolved through diagnosis (racy-git timestamp limitations), architectural analysis (index refresh/writeback behavior), and implementation tradeoffs (runtime vs build-time precision configuration). A key development is the historical context behind the counter-based guard in `builtin/diff.c` (`1 < rev.diffopt.skip_stat_unmatch`), introduced in commit aecbf914 (2007) to address real-world performance issues. The guard was designed as an optimization to avoid unnecessary index refreshes when no stat-dirty paths existed, acting as both a boolean flag and a counter for "ghost changes" (stat-dirty but content-unchanged paths). While functionally correct, its dual-purpose nature has proven confusing, and its role in preventing index persistence in `git diff` (while allowing it in `git status`) remains a focal point.

Three solution paths remain under active consideration:
1. **Index refresh fixes**: Modifying or replacing the counter-based guard with a more explicit refresh mechanism to ensure `git diff` persists its internal refreshes.
2. **Timestamp precision improvements**: Expanding `USE_NSEC` support (including Meson build system integration) or implementing runtime configuration (e.g., `--use-nsec` flag with platform-specific auto-detection via `uname`/`statfs`).
3. **Runtime configuration**: A hybrid approach combining user control (manual flags) with automated optimization (e.g., detecting btrfs on Linux), while addressing concerns about detection complexity.
