This is a review from Junio C Hamano on Tamir Duberstein's performance optimization for `git ls-files`. The patch had previously shown dramatic speed improvements (60.7s->1.06s) by filtering pathspecs before expensive lstat operations.

Junio raises two thoughtful technical questions about the change:

1. He notes that while the optimization helps when most paths don't match the pathspec, it could theoretically cause a performance regression when most paths *do* match, since we'd then be doing double pathspec matching. He suggests adding a performance test case for this scenario.

2. More significantly, he identifies a potential behavior change regarding submodules - the current code unconditionally recurses into submodules with `--recurse-submodules`, but the new pathspec filtering might prevent this for submodules whose paths don't match the pathspec.

The review is substantive, engaging with both the performance characteristics and correctness implications of the change. Junio isn't rejecting the patch, but is flagging areas that need either measurement (for the performance question) or behavioral verification (for the submodule case).
