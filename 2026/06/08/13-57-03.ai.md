This is a cover letter for a 3-patch series introducing new ways to disable Git config includes. The series comes from Derrick Stolee, known for his work on performance optimizations and large-repository features.

The core proposal adds two mechanisms to ignore config include directives:
1. A `GIT_CONFIG_INCLUDES=0` environment variable
2. A `--no-includes` command-line option at the Git top level

The use case stems from build systems where users include repo-tracked config files (for sharing aliases/etc) but then need to run Git commands in sandboxed environments where those includes would cause filesystem access violations. The author notes this builds on existing `--no-includes` logic in `git config` but extends it to all Git commands.

The series is organized as:
1. A documentation typo fix (prep for changes in patch 2)
2. Environment variable implementation with tests
3. Command-line option implementation

Stolee raises a valid concern about potential behavior breakage, suggesting this may need careful consideration regarding backwards compatibility. The patches appear focused and well-structured, with test coverage included. Given Stolee's track record and the clear problem statement, this seems like a well-motivated change, though the impact on existing workflows using includes would need evaluation.
