This is a maintainer response in the ongoing thread about extending `git repo info`'s path handling capabilities. Junio C Hamano weighs in on one of the open questions from the patch series regarding default path output formats.

Junio argues against introducing a default path format option (like a bare `path.gitdir` that would implicitly choose absolute or relative). His reasoning focuses on the plumbing interface's need for unambiguous, scriptable behavior - having a single explicit way to request each format (via `.absolute` or `.relative` suffixes) prevents future confusion and configuration drift.

The response aligns with Git's general philosophy for plumbing commands, where explicitness and stability for scripting take precedence over typing convenience. This guidance likely settles that particular design question for the series, allowing the author to proceed without implementing a default format option.

The thread appears to be in its final stages, with this being one of the last outstanding questions before the series can be integrated. Junio's input carries significant weight of maintainer approval on this interface design point.
