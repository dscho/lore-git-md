This is the final patch in Patrick Steinhardt's v3 series introducing a "drop" subcommand to the experimental `git history` command. The patch implements the actual drop functionality that removes a specified commit and replays its descendants on top of its parent.

Key technical details:
- Adds the `git history drop <commit>` command with options for dry-run, ref updates, and empty commit handling
- Prevents dropping root commits (may leave empty history) and merge commits (not yet implemented)
- Updates working tree and index when HEAD moves as a result of the drop
- Includes extensive test coverage (537 lines across 4 test scripts) for various scenarios:
  - Basic commit dropping
  - Branch updates
  - Working tree conflicts
  - Empty commit handling
  - Dry-run behavior
  - Edge cases (root commits, merge commits)

The implementation builds on the infrastructure changes from earlier patches in the series, particularly the reset machinery modernization and reference update refactoring. It handles dirty working trees by first performing a dry-run merge before updating refs, aborting if local changes would be overwritten.

This completes the series' goal of adding commit-dropping capability to the history command while addressing all substantive feedback from previous rounds. The only remaining open questions (API design direction and root/merge commit limitations) have been deferred to follow-up work as planned.
