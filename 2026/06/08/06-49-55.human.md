This is the final patch in Patrick Steinhardt's three-part series standardizing `b4` tool usage for Git's mailing list workflow. The patch adds project-level configuration files (`.b4-config` and `.b4-cover-template`) to establish default behaviors for contributors using b4 to send patches.

The configuration enforces two key preferences:
1. Shallow threading of patch series versions (replying to the original cover letter rather than the most recent version)
2. A custom cover letter template that includes a range-diff by default

The patch thoughtfully notes these are just starting points - users can override them via Git config without modifying the checked-in files. The implementation is clean and well-explained, with clear documentation of the override mechanism.

This completes the technical implementation portion of the series after previous discussion resolved all substantive questions. The only remaining open item is maintainer preference on threading style (shallow vs deep), which Patrick has indicated willingness to adjust if needed. The patch appears ready for merging once that final decision is made.
