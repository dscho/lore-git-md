This thread introduces a new `--linearize` option to `git replay` that flattens merge commits into linear history, similar to `git rebase --no-rebase-merges`. The series was developed by Toon Claes in coordination with Johannes Schindelin (Dscho), who has been working on a separate merge-replay approach. 

The three-patch series refactored the replay infrastructure (patches 1-2) before implementing the linearization behavior (patch 3). The final version incorporates Junio Hamano's feedback from the v1 review, including additional test cases for root commits and documentation improvements. Dscho has signed off on the approach, indicating alignment between the two solutions. 

The implementation cleanly separates the linearization logic while maintaining the existing error checking and commit mapping infrastructure. It explicitly prevents combining `--linearize` with `--revert` and includes comprehensive test coverage. With no new review comments on v2 and all preparatory refactoring complete, the series appears ready for merging. This provides users with a well-integrated alternative to Dscho's merge-replay approach while sharing underlying infrastructure.
