The `git replay --linearize` feature is now complete and ready for merging after three iterations. Toon Claes's series introduces a `--linearize` option that flattens merge commits into linear history by walking only first parents, providing server-side functionality equivalent to `git rebase --no-rebase-merges`.

The series consists of three patches. The first refactors the internal `enum replay_mode` into a simple boolean `reverse` flag, simplifying control flow without changing behavior. This preparatory step was debated but ultimately accepted as sufficient for the current dual-mode needs (forward/reverse). The second patch introduces helper functions for commit mapping, and the third implements the core `--linearize` functionality with comprehensive test coverage, including root commit handling, option combinations, and incompatibility testing.

All substantive feedback from Junio Hamano, Elijah Newren, Justin Tobler, and Johannes Schindelin has been incorporated. The implementation now includes full documentation, clear option incompatibility notes, and expanded test coverage for edge cases.
