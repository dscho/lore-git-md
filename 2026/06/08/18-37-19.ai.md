This is the first patch in Toon Claes's three-part series introducing a `--linearize` option to `git replay`. It refactors the internal `enum replay_mode` into a boolean flag (`reverse`), simplifying the code by removing redundant checks and eliminating the need for a default case.

The patch touches only `replay.c`, replacing all instances of `enum replay_mode` with a `bool reverse`. The change is mechanical: `REPLAY_MODE_REVERT` becomes `true`, and `REPLAY_MODE_PICK` becomes `false`. The commit message explains that this avoids unnecessary code paths for invalid enum values and shortens ternary operations. No behavior change is intended, and the patch is positioned as a preparatory step for the `--linearize` feature in patch 3.

The diff shows the removal of the `enum replay_mode` definition, the replacement of `mode` parameters with `reverse` in functions like `create_commit` and `pick_regular_commit`, and the elimination of `BUG()` checks for invalid enum values. The logic for reverting commits (swapping base and pickme) is preserved but now controlled by the boolean. The patch is clean and focused, with no test or documentation changes, as it is purely internal refactoring.
