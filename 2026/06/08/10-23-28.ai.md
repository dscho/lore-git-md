This is part 4 of Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch introduces a dry-run mode to the `reset_head()` function, which will be used by the drop command to check for potential conflicts before making changes.

The key technical changes are:
- Adds `RESET_HEAD_DRY_RUN` flag to `enum reset_head_flags`
- Implements dry-run behavior by:
  - Using a scratch index rather than modifying the real index
  - Skipping ref updates and working tree changes
  - Still performing all validation checks
- Maintains existing error handling and cleanup paths
- Adds proper cleanup of the scratch index

The implementation carefully preserves all existing reset functionality while adding the new mode. This is infrastructure work that enables the subsequent drop command implementation while also being generally useful for other callers that might want to test reset operations.

The patch follows the series' pattern of careful, incremental changes to core reset machinery. It builds on the index handling refactoring from earlier patches in the series and maintains the high standard of test coverage seen throughout.
