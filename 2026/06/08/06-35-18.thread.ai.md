Core issue: `git log --follow` fails to properly track file renames across merge commits due to using a single global variable to store the followed path, which gets overwritten during non-linear traversal. This particularly affects subtree merges where different parents may have different rename histories.

Solution: Introduces a commit slab (`follow_pathspec_slab`) to track the followed path per-commit, ensuring correct path tracking regardless of traversal order. For merges, runs rename detection between the merge and each parent to determine the correct path to follow. Removes the documentation note about --follow not working with non-linear history.

Technical details:
- Adds `struct follow_context` to store slab and related data
- Modifies `log_tree_diff()` to use per-commit paths
- Implements parent path calculation for merges via `diff_tree_oid()`
