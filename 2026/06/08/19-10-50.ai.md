This is the first patch in a two-part series finalizing the optimization of Git's priority queue implementation. The patch focuses on encapsulation and access patterns, renaming the internal `.nr` field to `.nr_` to prevent direct access and introducing helper functions `prio_queue_size()` and `prio_queue_for_each()` for safer iteration.

The changes enforce proper queue access patterns across 13 files that use the priority queue, converting all direct `.nr` accesses to use the new helpers. This includes loop conditions in traversal-heavy operations like merge-base calculations and revision walking. The patch maintains the performance improvements (1.7-2.7% speedups) validated in prior iterations while hardening the interface against misuse.

Key technical aspects:
- Renames `.nr` to `.nr_` per Junio's naming convention suggestion
- Adds `prio_queue_size()` for element count checks
- Introduces `prio_queue_for_each()` macro for safe iteration
- Updates all callers to use the new access patterns
- Maintains existing performance characteristics
- Part of the larger lazy_queue optimization effort

The patch represents the final step in generalizing the deferred removal tracking pattern from builtin/describe.c into core priority queue functionality. With all substantive feedback from prior reviews addressed, this change solidifies the interface before the performance optimizations in patch 2/2.
