This is the second part of a platform compatibility patch series modernizing compiler version checks in Git's codebase. First-time contributor Dominik Loidolt follows up his earlier Clang-specific improvement (v3 1/2) by updating the GCC version check macro `GIT_GNUC_PREREQ()` to use a more readable major/minor comparison style.

The patch replaces the historical bit-shift version comparison (inherited from glibc) with explicit `>` and `==` checks, matching the style already used for Clang and many BSD systems. This change:
- Improves code readability while maintaining identical functionality
- Removes the implicit assumption that GCC version components will never exceed 65536
- Keeps the same compile-time evaluation behavior
- Aligns with the Clang version check style introduced in the first patch

The implementation remains focused in `compat/posix.h` and includes improved documentation clarifying the macro's purpose and relationship to Clang checks. The patch has already addressed Patrick Steinhardt's feedback from earlier versions, with all technical questions resolved in the thread.

This completes the series' goal of establishing consistent, future-proof version checking across both major compilers. The changes are low-risk (affecting only compile-time evaluation) and demonstrate good attention to Git's compatibility standards. With both patches in v3 addressing all feedback, the series appears ready for maintainer consideration.
