This is the third and final patch in Derrick Stolee's series adding ways to disable config includes. It introduces a `--no-includes` command-line option that complements the environment variable mechanism added in patch 2/3.

The patch follows the same model as Git's existing `--no-advice` option, adding the new flag to the top-level Git options. When specified, it sets the `GIT_CONFIG_INCLUDES` environment variable to "0", which was implemented in the previous patch to skip all config include directives. The implementation is straightforward - just a few lines of code in `git.c` to handle the new option.

The documentation is updated in `git.adoc` to describe the new option alongside similar flags. The test suite is extended to verify the command-line option works equivalently to the environment variable, testing both direct config access and alias resolution behavior. The tests confirm that `--no-includes` can be overridden by `--includes` just like the environment variable can.

This completes the series' goal of providing both environment-based and command-line mechanisms to disable config includes, addressing the sandboxed build system use case. The implementation appears clean and well-tested, maintaining consistency with Git's existing option patterns. With this patch, users now have flexible control over config include behavior at both the environment and per-command level.
