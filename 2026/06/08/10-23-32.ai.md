This is patch 8/9 in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch refactors the reference update handling in preparation for future changes.

The key change splits the monolithic `handle_reference_updates()` function into two distinct phases:
1. `compute_pending_ref_updates()` - Gathers all references that need updating based on the rewrite operation
2. `apply_pending_ref_updates()` - Actually performs the reference transaction with the collected updates

The split enables future patches to inspect or modify the pending updates before they are applied. The implementation maintains all existing functionality while making the control flow clearer - the dry-run mode still works as before, and error handling remains robust.

This appears to be a straightforward refactoring with no behavior changes, following the pattern seen in other parts of Git where transaction preparation is separated from execution. The patch builds on the series' earlier infrastructure work and keeps the focus on enabling the drop subcommand's functionality.
