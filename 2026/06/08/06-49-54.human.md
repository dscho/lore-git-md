This is the second patch in Patrick Steinhardt's v3 series documenting the use of `b4` for Git's mailing list workflow. The patch updates the "MyFirstContribution" tutorial to recommend `b4` as the preferred tool for patch submission, alongside the existing coverage of GitGitGadget and raw `git send-email`.

The changes add a new section explaining `b4`'s workflow, including:
- Setting up a branch with `b4 prep`
- Editing cover letters and managing recipients
- Sending patches (with preview capability)
- Handling version iterations with automatic version bumping and range-diffs
- Configuration options via git-config and project defaults

The patch positions `b4` as building on top of `git format-patch` and `git send-email` while automating much of the manual bookkeeping. It also updates the SubmittingPatches document to encourage `b4` use. The changes are well-contained documentation updates that formalize existing community practices while improving the contributor experience. 

This patch follows the v3 series' resolution of all substantive technical discussion, with only minor threading style preferences remaining open for maintainer input. The documentation presents `b4` as an optimization layer after establishing manual workflow understanding, maintaining pedagogical clarity while promoting tool adoption.
