This is a review response from Patrick Steinhardt regarding Pablo Sabater's RFC patch to add success feedback to `git history reword`. Patrick questions whether the change aligns with Git's "rule of silence" principle, suggesting commands should only output when they can't fulfill a request. He raises several technical concerns about the implementation's scope (why only show the rewritten commit, not HEAD or other affected branches) and consistency (why treat `reword` differently from other `history` subcommands like `fixup` or `split`).

Patrick proposes that if such feedback is valuable, it might belong in a verbose mode that could be consistently applied across all subcommands. The review is substantive, engaging with both the philosophical design question (when should Git output to stderr) and practical implementation details (what information would actually help users). He stops short of outright rejecting the idea but clearly signals the patch needs stronger justification and possibly a different approach to be acceptable.
