Miklos Vajna has proposed a fix for `git log --follow` to properly track file renames across non-linear history, particularly addressing issues with subtree merges where different parents may have different rename histories. The initial patch introduces a commit slab to track followed paths per-commit rather than using a single global variable, removing the longstanding limitation documented in the manual.

Junio Hamano has reviewed the patch, offering both stylistic guidance (preferring present tense in commit messages) and raising an important technical question about merge handling. He presents a scenario where a merge commit's parents followed different rename paths from their common ancestor, questioning whether the current slab-based approach can correctly track multiple divergent paths. While not rejecting the solution outright, Junio's review identifies a potential edge case that may need addressing, either through implementation changes or additional test coverage.
