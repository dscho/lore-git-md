This is the first patch in Patrick Steinhardt's v3 series adding a "drop" subcommand to the experimental `git history` command. The patch refactors index handling code to prepare for upcoming changes.

The change splits out functionality from `repo_read_index_unmerged()` into a new `index_state_unmerged_to_stage0()` function that can operate on arbitrary index states rather than just the repository's main index. This is groundwork for later patches that will need to manipulate scratch indexes during dry-run operations. The patch also fixes a signedness mismatch in the index iteration.

The refactoring is straightforward and mechanical - it moves code without changing behavior. The new function is added to `read-cache-ll.h` for wider use, and the existing function becomes a simple wrapper. This follows the pattern seen elsewhere in Git's codebase where repository-specific operations are built atop more general ones.

As the first in a series, this patch sets up infrastructure that will be used by subsequent commits. The changes are limited to the index handling layer (read-cache.c) and don't yet touch the history command itself. Given Patrick's track record and the focused nature of the change, this appears to be solid preparatory work.
