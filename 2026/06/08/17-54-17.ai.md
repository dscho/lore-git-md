This is a substantive technical review from Justin Tobler on a patch that refactors `rev-parse` to use the new shared `format_path()` helper. The patch is part of a GSoC participant's series improving path handling in `git repo info`.

Justin raises a thoughtful point about the API design for handling default path formats. The current implementation uses `-1` as a sentinel value to indicate when no format was specified by the user, which Justin finds slightly awkward. He suggests an alternative approach using a `PATH_FORMAT_DEFAULT` enum value that could be mapped to the appropriate default format in `print_path()`.

The review doesn't identify any functional issues with the current implementation - it's more of a design discussion about which approach makes the API cleaner and more self-documenting. Justin acknowledges that his proposed alternative may not be significantly better, showing this is more about polish than correctness.
