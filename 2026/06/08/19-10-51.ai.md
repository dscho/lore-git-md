This is the second and final patch in a performance optimization series for Git's priority queue implementation, now incorporating all feedback from prior reviews. The patch generalizes the lazy_queue pattern (deferring removals to allow subsequent puts to become simple replaces) into the core prio_queue implementation, eliminating duplicate optimizations in several callers while maintaining measured speedups.

The key optimization fuses get+put operations in commit traversals (a dominant pattern) into single replace operations, avoiding full remove-rebalance-insert cycles. Benchmarks show 1.7-2.7% improvements on traversal-heavy operations like merge-base and rev-list, while maintaining neutral performance for code paths that already had manual fusion.

The patch removes three independent implementations of this optimization (from describe.c, commit.c, and show-branch.c) in favor of handling it automatically in the priority queue itself. It also removes the now-unused prio_queue_replace() function. The changes have been validated to preserve the performance gains across multiple benchmark runs.

This completes the generalization of the lazy_queue pattern from builtin/describe.c into core functionality, addressing all substantive feedback from prior iterations. The series is now ready for merging with no outstanding questions. The optimization affects multiple subsystems (commit-reach, fetch-pack, revision walking) but the impact is well-contained through consistent access patterns.
