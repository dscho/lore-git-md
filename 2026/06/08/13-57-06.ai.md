This is the final patch in Derrick Stolee's series adding ways to disable config includes, implementing the `--no-includes` command-line option as a complement to the environment variable mechanism added in patch 2/3.

The patch follows the same pattern as Git's existing `--no-advice` option, adding:
1. Documentation in git.adoc explaining the option
2. Command-line handling in git.c that sets the same environment variable used by the environment-based mechanism
3. Test updates in t1305-config-include.sh to verify the new option works equivalently to the environment variable

The implementation is straightforward and consistent with Git's existing patterns for similar features. The tests demonstrate that both the environment variable and command-line option:
- Successfully block include directives
- Can be overridden by `--includes`
- Affect alias resolution
- Work equivalently to each other

This completes the series' goal of providing both environment-based and command-line-based ways to disable config includes for sandboxed environments. The patch appears well-tested and follows established Git conventions, though as noted in the cover letter, the broader impact on workflows using includes may need consideration.
