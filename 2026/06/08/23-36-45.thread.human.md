This thread is about a performance regression in `git diff` operations within secondary worktrees, where the command can take over 200ms compared to just 3ms in the main worktree. D. Ben Knoble initially identified timestamp precision as the root cause, triggering a deeper investigation into "racy-git" scenarios—cases where Git must fall back to expensive full-content checks because file timestamps lack sufficient precision.

Jeff King (Peff) proposed a minimal fix: enabling nanosecond-precision timestamp comparisons unconditionally by removing a conditional guard in `read-cache.c`. This 8-line change resolves the performance issue by eliminating racy entries at their source, leveraging existing infrastructure. Testing confirms the slowdown disappears with this approach, but Junio C Hamano raised a correctness concern: if the kernel’s inode cache inconsistently preserves nanosecond precision (e.g., one file’s timestamp is truncated while another’s is not), Git might incorrectly treat files as modified. Peff acknowledged the theoretical risk but argued it’s unlikely in practice, especially on Linux.

Knoble’s latest email shifts the focus to user experience. He accepts Peff’s tradeoff—a slower first `git diff` (~1800ms vs ~500ms) in exchange for consistent subsequent performance (~30ms)—as reasonable for his use case (shell prompts), where predictability matters more than initial speed. He also highlights two open questions: why Peff’s patch introduces an unexplained 800ms overhead in the first diff, and whether racy entries could be reduced at index write time (e.g., via broader `USE_NSEC` adoption). While Knoble defers to Peff and Junio on technical details, his feedback underscores the need for a solution that balances performance, correctness, and usability.

The thread is now centered on Peff’s patch, with Junio’s edge case as the primary unresolved concern. The discussion has also linked to broader efforts, like enabling `USE_NSEC` in the Meson build system, which could further reduce raciness. Key participants—Peff, Junio, and Knoble—appear aligned on the goal but are still weighing tradeoffs between simplicity, performance, and correctness.
