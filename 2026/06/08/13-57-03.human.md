This is a feature proposal to allow disabling Git's include directives in config files, motivated by build system sandboxing needs. The 3-patch series from Derrick Stolee introduces two mechanisms:

1. A `GIT_CONFIG_INCLUDES=0` environment variable
2. A `--no-includes` command-line option

The use case comes from scenarios where users include repo-tracked configs (like shared aliases) but then need to run Git commands in sandboxed environments where the included paths would be inaccessible. The implementation builds on existing `--no-includes` logic in `git config`.

Patch 1 fixes a documentation formatting issue. Patch 2 adds the environment variable with tests. Patch 3 introduces the top-level command-line option. The changes are straightforward and well-tested, though Stolee notes some concern about potential behavior breakage - this seems unlikely given the opt-in nature of the feature.

The proposal appears well-considered and addresses a real pain point in controlled environments. As a feature that expands Git's flexibility without breaking existing workflows, it seems likely to be uncontroversial.
