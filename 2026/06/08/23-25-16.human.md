This is a technical follow-up in the ongoing discussion about optimizing `git ls-files` performance by filtering pathspecs early. Jeff King (Peff) provides concrete measurements showing the worst-case scenario where the optimization could degrade performance - when running `git ls-files` with all files as pathspecs (a rare operation).

The key findings:
- The patch introduces quadratic scaling when most paths match (demonstrated with 1000 vs 10000 file repos)
- However, this case is already slow by nature (800ms for 10k files) and uncommon in practice
- The optimization's benefits for selective pathspec cases (60x speedup shown earlier) outweigh this edge case

Peff suggests that if this becomes a real-world issue, the better solution would be improving pathspec matching itself rather than avoiding this optimization. The discussion appears to have reached consensus that the tradeoffs are reasonable, with all major technical concerns addressed through this iterative review process.
