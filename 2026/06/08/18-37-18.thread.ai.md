Git replay linearization series summary:

Subject: [PATCH 0/3] replay: introduce --linearize option
Author: Toon Claes
Status: v1 (3/3 patches complete) under review
Type: Feature patch series (3 patches)

Core goal: Add `--linearize` option to `git replay` that flattens merge commits into linear history, similar to `git rebase --no-rebase-merges`. This provides an alternative to Johannes Schindelin's (Dscho) separate merge-replay approach while sharing some infrastructure.

Technical details:
- Patch 1/3 refactored `replay.c` by converting `enum replay_mode` to boolean `reverse` flag and simplifying control flow
- Patch 2/3 introduced `put_mapped_commit()` helper for storing rewritten commits, creating symmetrical API with `get_mapped_commit()`
- Patch 3/3 implements `--linearize` core functionality:
  - Adds CLI/config option with documentation
  - Skips merge commits when linearizing (maps to first parent)
  - Uses `pick_regular_commit()` helper for linear/non-linear cases
  - Explicitly disallows combining with `--revert`
  - Test coverage in t3650
- Touches `replay.c` commit mapping logic and `replay.h` option definition
- Current implementation questions:
  - Root commit handling (treated same as merges - maps to previous commit)
  - Merge commit logic organization could be clearer
- Missing test case for replaying to root commit
