Core goal: Implement `--linearize` option for `git replay` to flatten merge commits into linear history by walking only first parents, providing server-side functionality equivalent to `git rebase --no-rebase-merges`.

Technical details:
- **Patch 1/3 (refactoring)**: Introduced `put_mapped_commit()`/`get_mapped_commit()` getter/setter pair for `replayed_commits` khash OID map. No behavior change.

  - Renamed `onto` to `default_base`, reordered parameters.
  - 10-line comment documenting base-selection logic.
  - Fixed `replayed_base` handling for `REPLAY_MODE_REVERT`.
- **Patch 3/3 (implementation)**: Core `--linearize` functionality:
  - CLI/config option documented, including `--linearize`/`--revert` mutual exclusion.
  - Merge commit handling (maps to first parent).
  - Unified `pick_regular_commit()` with `replayed_base` parameter.

**Critical issues (post-merge)**:
1. **Single-branch replay regression**:
   - v5's base-selection logic **inadvertently removed the `replayed_base` mechanism** that preserved linearized history for single branches.
   - **Silent commit dropping**: Only the tip commit is replayed, intermediate commits (including merges) are lost.
   - **Johannes Schindelin confirmed** with test case (`master~2..master`), showing v5 replays only tip commit directly onto `--onto`, dropping "Git 2.55-rc2" commit entirely.
   - **Root cause**: Removal of `replayed_base` logic in `pick_regular_commit()`.

2. **Merge commit divergence handling**:
   - Current implementation silently discards one side of divergent merges (confirmed by Junio Hamano and Phillip Wood).
   - **Design limitation**: Recognized as secondary to regression but requires clarification.

3. **CLI design inconsistency** (Patrick Steinhardt):
   - `--linearize` deviates from `git rebase`'s established syntax (`--rebase-merges`, `--no-rebase-merges`, `--rebase-merges=rebase-cousins`).
   - **Risk**: Inventing new flags (`--no-merges`, `--replay-cousins`) may confuse users and limit future compatibility.
   - **Principle**: Commands manipulating commit history should share CLI vocabulary for consistency.
