**Critical regression (post-merge)**:
- **Single-branch replay with merge commits**: v5's base-selection logic fix **inadvertently removed the `replayed_base` mechanism** that preserved linearized history for single branches. This causes **silent commit dropping** where only the tip commit is replayed, and intermediate commits (including merges) are lost. **Johannes Schindelin confirmed** with a real-world example (`master~2..master`), showing that v5 replays only the tip commit directly onto `--onto`, dropping the "Git 2.55-rc2" commit entirely. This differs from v4's correct behavior and represents a **regression with silent data loss**.
- **Merge commit divergence handling**: When replaying divergent branches, the current implementation silently discards one side of the merge (confirmed by Junio Hamano and Phillip Wood). This is now recognized as a **design limitation** rather than a bug, but the single-branch regression takes precedence.
