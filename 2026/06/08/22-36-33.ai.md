This is a maintainer response in the ongoing thread about extending `git repo info`'s path handling capabilities. Junio C Hamano weighs in on one of the open questions from the patch series regarding default path output formats.

Junio argues against introducing a default path format option (like a bare `path.gitdir`), stating that plumbing interfaces should prioritize unambiguous behavior over typing convenience. His rationale is that allowing defaults would invite configuration tweaks that undermine the reliability of scripts using this feature. He emphasizes that plumbing layer commands should have one clear way to do things rather than multiple options that could lead to ambiguity.

This feedback aligns with Git's design philosophy for low-level commands, where explicit behavior is valued over convenience shortcuts. The response suggests the current approach with explicit `.absolute` and `.relative` variants is the right direction for this plumbing command.

The comment doesn't require any code changes but provides important design guidance that likely settles one of the open questions from the original proposal. As maintainer feedback, this carries significant weight in determining how the feature will be implemented.
