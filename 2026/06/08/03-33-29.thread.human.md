The current implementation suffers from redundant graph traversals when checking commit ancestry across multiple references, leading to significant slowdowns in repositories with many refs.

The proposed patch unifies and optimizes this ancestry checking by:
1) Reusing the memoized traversal algorithm previously only available for `git tag --contains`
2) Properly handling commit graph cycles (which can occur with replacement refs)
3) Making failure cases consistent
4) Showing dramatic speedups - up to 223x faster in benchmarks with over 60,000 refs

The changes touch several parts of the codebase but maintain backward compatibility while providing substantial performance benefits. This optimization could noticeably improve workflows that frequently use containment filtering in large repositories. The patch builds on ideas discussed in the project as far back as 2011, finally delivering on the long-suggested unification of these implementations.
