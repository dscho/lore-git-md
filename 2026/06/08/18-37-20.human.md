This is the second patch in Toon Claes's three-patch series introducing a `--linearize` option to `git replay`. It is a refactoring patch that extracts a small piece of logic from the lengthy `replay_revisions()` function into a new helper, `put_mapped_commit()`.

The change is mechanical and self-contained: eleven lines of code that store a commit mapping are moved into a separate function, and the original site is replaced with a single call. The new helper is named `put_mapped_commit()` to complement the existing `get_mapped_commit()` (which is also renamed from `mapped_commit()` for consistency). No behavior is altered; the patch exists solely to make the code easier to read and to prepare for the `--linearize` implementation in patch 3.

The patch touches only `replay.c` and is small enough that it should be uncontroversial. It is a textbook example of a preparatory refactoring: the extracted logic is reused exactly once today, but the helper will be called again in the next patch when `--linearize` needs to record rewritten commits. The commit message is concise and accurately describes what the patch does.
