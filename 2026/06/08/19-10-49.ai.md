This is the fourth iteration of a performance optimization series for Git's priority queue implementation, now incorporating all feedback from prior reviews. The series generalizes the lazy_queue pattern (deferring removals to allow subsequent puts to become simple replaces) into the core prio_queue implementation, eliminating duplicate optimizations in several callers while maintaining measured speedups.

Key changes in v4:
- Renamed `.nr_internal` to `.nr_` per Junio's naming convention suggestion
- Restored `flush_get()` as a static inline helper rather than inlining logic into get()/peek()
- Added guard for empty-queue check with `nr_ <= get_pending`
- Flipped commit order to put the rename/accessor changes first

The optimization fuses get+put operations in commit traversals (a dominant pattern) into single replace operations, avoiding full remove-rebalance-insert cycles. Benchmarks show 1.7-2.7% improvements on traversal-heavy operations like merge-base and rev-list, while maintaining neutral performance for code paths that already had manual fusion.

The series has seen thorough review across three prior iterations, with all substantive feedback addressed. Performance validation confirms consistent speedups without regressions. With the final naming convention resolved and correctness hardening complete, this appears ready for merging. The changes affect multiple subsystems (commit-reach, fetch-pack, revision walking) but the impact is well-contained through consistent access patterns.
