This is the fourth iteration of a performance optimization series for Git's priority queue implementation, now incorporating all feedback from prior reviews. The series generalizes the "lazy queue" pattern (deferring removals to allow subsequent puts to become simple replaces) into the prio_queue data structure itself.

The key optimization fuses get+put operations that commonly occur in commit traversals, avoiding full remove-rebalance-insert cycles. Benchmarking shows 1.7-2.7% speedups on traversal-heavy operations like merge-base and rev-list, while maintaining neutral performance for code paths that already had manual fusion.

Changes in v4:
- Renamed internal field from `.nr_internal` to `.nr_` per Junio's suggestion
- Restored a static inline `flush_get()` helper instead of fully inlining the logic
- Added guard for empty-queue checks using `nr_ <= get_pending`
- Flipped commit order to do the field rename first

The series has seen thorough review and benchmarking across multiple subsystems. All substantive feedback has been addressed, and the optimization is particularly impactful for operations that heavily use priority queues in commit traversal patterns. With no remaining correctness concerns and validated benefits, this appears ready for merging.
