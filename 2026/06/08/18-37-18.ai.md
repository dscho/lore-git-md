This is a feature patch series introducing a new `--linearize` option to `git replay` that mimics `git rebase --no-rebase-merges` behavior by flattening merge commits. The series comes from Toon Claes with contributions from Johannes Schindelin (Dscho).

The 3-patch series starts with two preparatory refactorings: first converting an enum to a boolean for simpler control flow, then adding a helper function for commit mapping. The third patch implements the core functionality, adding the `--linearize` option that will rewrite merge commits as single-parent linear history. The implementation appears to be a collaborative effort with Dscho, suggesting it builds on prior work around merge replaying. 

The cover letter positions this as an alternative to Dscho's separate merge-replay series, noting the approaches may need coordination. It also mentions potential documentation conflicts with Kristoffer Haugsbakk's work and Patrick Steinhardt's `git history drop` series, though the author considers these trivial to resolve. Test coverage is included via new cases in t3650.

Key technical details for future reference: the change touches `replay.c`'s commit mapping logic and adds the new option through `replay.h`. The implementation appears to handle merge commits by walking their first parent only when linearizing. The option is deliberately not added to `git history` as the author feels it doesn't fit that command's use case.
