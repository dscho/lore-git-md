This is the final patch in a 12-part series implementing secure object metadata queries from remote repositories via `git cat-file --batch-command`. The patch focuses on security hardening by making the format placeholder validation dynamic based on server capabilities.

The key change replaces the static allow-list of supported placeholders ("objectname" and "objectsize") with a dynamic system that:
1. Checks which capabilities the server advertises
2. Filters requests to only include supported options
3. Builds an allow-list of placeholders the server actually supports
4. Validates placeholders against this dynamic list

The implementation includes several safety improvements:
- Proper initialization of type information (setting to OBJ_BAD with NULL checks)
- Clear separation of remote vs local query handling
- Future-proof architecture that can support additional metadata types
- Comprehensive test coverage across different transport protocols

The patch represents the culmination of extensive review and refinement over 12 iterations, with all core reviewers (including Junio Hamano, Patrick Steinhardt, and Karthik Nayak) having approved the approach. It addresses the last remaining security concerns around format placeholder validation while maintaining compatibility with existing behavior.

This completes a production-ready implementation of secure remote object metadata queries that can safely be used in scripts and automation without requiring full object downloads. The dynamic capability checking ensures forward compatibility as servers add support for additional metadata types in the future.
