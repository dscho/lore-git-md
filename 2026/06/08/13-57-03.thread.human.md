Derrick Stolee's series to add mechanisms for disabling Git config includes has received its first substantive review from Patrick Steinhardt. The series proposes two approaches - an environment variable (`GIT_CONFIG_INCLUDES=0`) and a command-line option (`--no-includes`) - to address sandboxed build system use cases where config includes could cause filesystem access violations.

Patrick's review acknowledges the validity of the use case but questions whether a binary on/off switch provides enough flexibility. He suggests considering an allow-list approach that would let users specify which include locations should be evaluated, rather than globally disabling all includes. This raises important design questions about whether the current implementation might be too restrictive for some real-world scenarios where selective inclusion would be preferable.

The review maintains a constructive tone while probing the design assumptions. While the implementation itself appears technically sound with comprehensive test coverage, Patrick's feedback suggests the feature might benefit from more nuanced control. This opens discussion about whether the current approach should be modified before merging, though no specific implementation changes are proposed yet. The series now awaits Derrick's response to these design considerations.
