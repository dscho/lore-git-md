Derrick Stolee's patch series proposing ways to disable Git config includes has progressed through thoughtful discussion. The initial patches introduced two mechanisms - an environment variable and command-line option - to completely disable config include processing, addressing sandboxed build system needs. While Patrick Steinhardt initially suggested a more granular allow-list approach, he now supports the current binary solution as a first step.

The most recent exchange with Jeff King (Peff) has deepened the conversation. Stolee acknowledges Peff's substantive concerns about the partial security coverage (since other config vectors remain open) and potential workflow breakage, particularly for common patterns like work/personal email separation via conditional includes. This has led Stolee to reconsider whether a more comprehensive sandboxing solution might be needed rather than just targeting includes. He's also exploring ways to mitigate impact, such as warning users about behavioral changes.

The thread has reached consensus that the current binary disable approach is appropriate for immediate needs while leaving room for future enhancements. The discussion remains productive, with Stolee showing willingness to iterate based on feedback - though the series appears ready to progress in its current form, with real-world usage expected to inform whether additional mechanisms become necessary.
