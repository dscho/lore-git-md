This is a review from Junio Hamano on Miklos Vajna's patch to improve `git log --follow` behavior with non-linear history and renames. The review focuses on two main points:

First, Junio provides stylistic feedback about using present tense when describing current behavior rather than past tense ("used to store"), noting this consistency helps readers follow the thought process across multiple commits.

Second and more substantively, Junio questions whether the proposed commit-to-path mapping solution (using a slab) can properly handle cases where merge commits require tracking multiple divergent rename paths. He presents a concrete scenario where a merge commit M has two parents (B and C) that each followed different paths (path1 and path2) from their common ancestor A, asking how the slab would determine which path to use when traversing past A.

The review doesn't reject the approach but probes a potential edge case in the implementation. Junio's example suggests the slab might need to store multiple paths per commit in some cases, though the current patch appears to assume a single path per commit. This is a substantive technical review that identifies a scenario the tests may not yet cover.
