This is a review comment on the second patch of Patrick Steinhardt's 16-part series converting Git's packed object storage to use `struct odb_source` as part of the ODB abstraction effort.

Karthik Nayak provides a substantive review, noting that the patch exposes `struct packfile_list` and `struct packfile_list_entry` in the new `odb/source-packed.h` header. He questions whether these structures should remain in `packfile.h` since they are also used by the transport layer outside the ODB subsystem. This suggests a potential architectural consideration about where these shared data structures should live.

The review acknowledges the rest of the patch looks good, indicating general approval of the code movement while raising this one thoughtful point about header organization. This feedback comes early in the series (patch 2/16) and may influence how subsequent patches handle the relationship between packed storage and other parts of the codebase that use packfiles.

The exchange shows the careful balancing act required in this large-scale refactoring - moving code to its logical subsystem while maintaining existing cross-component dependencies. Karthik's review demonstrates engagement with the architectural implications beyond just the mechanical changes.
