This is a review from Junio C Hamano on Jason Newton's worktree improvements series, focusing on the fundamental design choices rather than implementation details.

Junio questions why copy-on-write (CoW) worktree creation needs to be opt-in via `--reflink`, suggesting it should instead be the default behavior when the filesystem supports it. He argues that if CoW provides transparent space savings without functional differences (as with shell `cp`), there's no need to make it as a user-visible option - Git should just use the most efficient available method automatically. This challenges the current patch's approach of explicit `worktree.reflink` configuration.

On the shared-branch worktrees change, Junio identifies a key safety concern: concurrent commits from different worktrees on the same branch could create confusing `git diff` behavior where one worktree sees unexpected changes from another. This suggests the current protection against same-branch checkouts exists for good reason, and relaxing it may introduce subtle workflow hazards.

The review doesn't reject the changes outright but probes their underlying assumptions. Junio's questions imply the series may need stronger justification for its opt-in CoW design and more robust handling of the shared-branch edge cases before proceeding. His perspective as maintainer suggests these are fundamental design questions that should be resolved before implementation details.
