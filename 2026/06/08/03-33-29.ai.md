This is a performance optimization patch for the ref-filter subsystem, specifically targeting the `--contains` and `--no-contains` filtering operations in commands like `git branch` and `git for-each-ref`.

The patch unifies and optimizes the commit ancestry checking used by these commands. Previously, each reference being filtered would perform its own independent graph walk to check ancestry, leading to redundant traversals of the same commits. The new approach:

1. Reuses the memoized traversal algorithm that was previously only used by `git tag --contains`, caching positive/negative results across reference checks
2. Handles cycles in the commit graph (which can occur with replacement refs) by falling back to the slower but cycle-safe `repo_is_descendant_of()` when needed
3. Makes ancestry parsing failures consistently fail (rather than treating them as "contains" matches in some cases)
4. Shows dramatic performance improvements - up to 223x faster in the benchmark case with 62,174 remote-tracking refs

The changes touch several areas:
- Removes the separate tag-specific algorithm selection flag
- Modifies the commit-reach internals to handle cycles and caching
- Updates ref-filter to use the unified implementation
- Adds tests for cycle handling and error cases
- Includes performance test demonstrating the speedup

The patch builds on prior work from 2011, 2015 and 2018, finally unifying the implementations as suggested in earlier discussions. The performance impact is substantial enough that this could noticeably improve workflows that frequently use `--contains` filtering on repositories with many refs.
