This is the fourth iteration of Harald Nordgren’s `git history squash` feature, now fully addressing the last open design question—how to handle refs pointing into the squashed range. The series is a well-crafted, standalone subcommand that folds a commit range into its oldest commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach.

The key change in v4 is the ref-handling logic: by default, the command now **rejects the operation** if any ref (branch, tag, or other) points to a commit inside the range being folded. This conservative approach prevents surprising users by silently orphaning refs like bisection markers or topic branches. The error message includes an `advice()` hint suggesting `--update-refs=head` to rewrite only the current branch and leave other refs untouched. The implementation is thorough, with new test coverage for the rejection logic, the advice message, and the `--update-refs=head` behavior.

The series also resolves the remaining technical concerns Patrick Steinhardt raised about range resolution. The code now explicitly tracks commits inside the range, checks for interior refs, and handles edge cases like merge commits at the tip or base of the range. The test suite has grown to 340 lines, validating everything from range parsing to authorship preservation, merge commit handling, and the new ref-handling behavior.
