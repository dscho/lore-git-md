This is the **final patch (4/4)** in Taylor Blau’s **v3** series integrating `--delta-islands` with `--path-walk` in `git pack-objects`. The patch removes the long-standing incompatibility between the two options by ensuring path-walk traversal performs the same island-mark propagation as the regular traversal.

### Key implementation details
- **Island propagation during path-walk**: The `add_objects_by_path()` callback now calls `propagate_island_marks()` for commits (skipping excluded/boundary commits to match the regular traversal’s behavior) and `record_tree_depth()` for trees. This ensures `resolve_tree_islands()` receives identical island inputs regardless of traversal mode.
- **Order preservation**: Path-walk’s commit batch maintains the same descendant-first order as the regular traversal, guaranteeing correct island-mark propagation.
- **Documentation update**: The man page no longer lists `--delta-islands` as incompatible with `--path-walk`.
- **Test coverage**: New tests in `t5320-delta-islands.sh` verify that path-walk respects island boundaries (with and without bitmaps) and allows deltas within the same island.

### Technical context
- **Files touched**: `pack-objects.c` (core logic), `Documentation/git-pack-objects.adoc` (updated compatibility note), and `t5320-delta-islands.sh` (new tests).
- **No on-disk format changes**: The patch reuses existing island infrastructure without modifying how islands are stored.
- **Performance**: The implementation avoids a second tree walk by piggybacking on path-walk’s existing traversal, aligning with Jeff King’s original suggestion.

### Why this matters
This patch completes the series’ goal of enabling `--path-walk` to leverage delta-islands without regressing compression or performance. The solution is minimal and robust, relying on the same island-propagation logic as the regular traversal. The tests confirm that island boundaries are respected even when bitmaps are used, addressing Derrick Stolee’s earlier validation request.

The patch is **merge-ready**, with all prior feedback incorporated and no open technical concerns. It directly builds on the helper (`record_tree_depth()`) introduced in patch 3/4, and the series as a whole is now empirically validated for both speed and compression benefits.
