This is the second patch in the v7 series introducing standardized path formatting for Git repository information. It adds two new fields to `` `git repo info` ``: ``path.commondir.absolute`` and ``path.commondir.relative``, exposing the repository's common directory in both absolute and relative formats.

The patch is straightforward and well-executed. It builds on the ``append_formatted_path()`` helper introduced in the first (now squashed) patch, using it to provide consistent, scriptable access to the common directory path. The implementation handles worktree setups correctly, including edge cases where ``GIT_COMMON_DIR`` or ``GIT_DIR`` are explicitly set. The test coverage is thorough, exercising both standard and custom common directory configurations, and verifying both absolute and relative path outputs.

This is a clean plumbing improvement that addresses a real gap in scriptability. The new fields are additive and do not change existing behavior, so there is no risk of breaking existing workflows. The patch has already received substantive review from Phillip Wood, Justin Tobler, and Lucas Seiki Oshiro, and the series as a whole is ready for maintainer pickup. If you care about worktree setups or need reliable path discovery in scripts, this patch is worth noting.
