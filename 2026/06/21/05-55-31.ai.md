This is the v7 iteration of a GSoC feature series that teaches `` `git repo info` `` to expose repository paths in both absolute and relative formats. The series is now down to three patches after squashing the first two as requested by Junio C Hamano in v6, eliminating any dead code in the tree.

The core of the work is a new ``append_formatted_path()`` helper in ``path.c`` that consolidates the path-formatting logic previously duplicated in ``rev-parse``. This helper is then used to add four new fields to `` `git repo info` ``: ``path.commondir.absolute``, ``path.commondir.relative``, ``path.gitdir.absolute``, and ``path.gitdir.relative``. The implementation preserves exact backward compatibility for existing ``rev-parse`` output while making the new fields available for scripting.

All technical design concerns from previous rounds have been resolved, and the series has received substantive review from Phillip Wood, Justin Tobler, and Lucas Seiki Oshiro. Junio’s structural feedback about patch ordering has been addressed by squashing the first two patches, so the helper is now introduced and used immediately. The test coverage is thorough, exercising all path variants, worktree scenarios, and error conditions.

The files touched are ``path.c``/``path.h``, ``builtin/rev-parse.c``, ``builtin/repo.c``, ``Documentation/git-repo.adoc``, and the new test script ``t/t1900-repo-info.sh``. The new symbols are ``append_formatted_path()`` and the ``path_format`` enum. No behavior changes are introduced for existing commands; the new fields are purely additive.

This version is ready for maintainer pickup and should graduate to ``next`` once Junio confirms the squash satisfies his structural requirement. The series is a clean, well-tested plumbing improvement that addresses a real gap in scriptability without breaking any existing workflows.
