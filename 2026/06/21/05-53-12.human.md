This is the first patch in Harald Nordgren’s **four-part `git history squash` series (v4)**, which is now code-complete and ready for final review. This patch is a **refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit’s first parent (or the empty tree for root commits). The helper replaces three nearly identical code blocks in `builtin/history.c`, reducing duplication and making the code easier to maintain.

The change is purely mechanical and introduces no behavior changes. The new helper is straightforward: it takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`, then either copies the first parent’s tree OID or falls back to the empty tree. Error handling is preserved, with the helper returning a negative value on failure. The three call sites—`commit_tree_with_edited_message()`, `commit_became_empty()`, and `split_commit()`—are updated to use the helper, eliminating redundant parsing and OID-copying logic.

This patch is a small but necessary step toward the larger goal of the series: implementing the `git history squash` subcommand, which will allow users to collapse a commit range into its oldest commit while preserving descendant history. The refactoring here supports the core squash logic in later patches, where the first-parent tree is used to perform a three-way merge of the entire range.

The patch is well-scoped and uncontroversial. It follows Git’s coding conventions and includes a clear commit message. Since the series as a whole has already addressed all prior technical and design concerns (including the ref-handling behavior finalized in v4), this patch is unlikely to generate discussion on its own. It’s a solid, low-risk cleanup that sets the stage for the more substantive changes in the rest of the series.
