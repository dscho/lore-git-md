This is a **build system** discussion about the recently merged Meson `nanosec` option, which mirrors the Autotools `USE_NSEC` knob. Jeff King (Peff) replies to D. Ben Knoble’s patch, which was already accepted and queued by Junio, to raise a technical caveat about the `USE_NSEC` feature itself.

Peff’s email is a **substantive review** of the *implications* of enabling `USE_NSEC`, not a critique of the patch. He quotes `Documentation/technical/racy-git.adoc` to explain the long-standing concern: sub-second timestamps can cause Git to misdetect file changes when in-core timestamps (with nanosecond precision) differ from on-disk timestamps (which may have coarser resolution, especially on network filesystems like CEPH, CIFS, or NTFS). The issue was partially fixed in Linux 2.6.11 (2005), but Peff notes that some filesystems may still be affected. He concludes that while the patch is correct for parity, the default `USE_NSEC=false` remains prudent until someone investigates platform-specific behavior more thoroughly.

The email does not propose changes to the patch or suggest deprecating the option. It is a heads-up for anyone considering `-Dnanosec=true`: the feature is not universally safe, and the documentation already warns about it. This is unlikely to derail the patch’s integration, but it may prompt future discussion about whether `USE_NSEC` should be platform-gated or deprecated entirely. For now, the patch stands as a straightforward parity fix.
