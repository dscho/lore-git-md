This is a **substantive review** of patch 10/12 in the `git cat-file --batch-command` remote-object-info series, focusing on a memory management concern in the client-side implementation. Chandra Pratap questions the use of `static` variables for `remote_object_info` and `object_info_oids` in `parse_cmd_remote_object_info()`, noting that these variables are allocated, used, and freed within a single command cycle and do not need to persist between calls. The static declaration misleadingly suggests state persistence where none is required, and the current implementation already properly cleans up all resources in the `cleanup` block. This is a valid correctness observation that could affect thread-safety and clarity, though it does not change the feature's core functionality. The review is narrowly scoped to this single issue in an otherwise mature, security-hardened patch series that has reached v13 with all prior technical and design feedback resolved.
