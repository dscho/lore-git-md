This is a documentation patch (part 1 of 2 in v3) that updates contributor guidelines in `MyFirstContribution.adoc` and `SubmittingPatches` to explicitly encourage new contributors to reply to review feedback in the mailing-list thread before sending a rerolled patch series. The goal is to make the author’s reasoning visible upfront rather than forcing reviewers to infer it from code changes, and to foster more direct interaction between contributors.

The patch adds a paragraph to `MyFirstContribution.adoc` that tells newcomers to explain their planned response—whether they will adopt a suggestion, keep the original, or try a different approach—so reviewers can engage with the reasoning before the author spends time implementing a version that may not be acceptable. A similar but shorter addition appears in `SubmittingPatches`, reinforcing the same principle for all contributors.

Thread context shows this patch has been effectively dropped from the series due to redundancy concerns raised by Patrick Steinhardt: the new text largely restates existing advice in more words. The author has not revised this patch since v1 despite feedback, and discussion has converged on removing it. The second patch in the series, which documents reroll cadence expectations, has clear consensus and is ready to move forward. This first patch is now a candidate for omission unless new objections arise.
