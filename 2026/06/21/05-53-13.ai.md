This is the second patch in Harald Nordgren’s **code-complete** `git history squash` series (v4, 2/4). It introduces a `message_template` parameter to `commit_tree_ext()` in `builtin/history.c`, allowing callers to override the commit message that would otherwise be reused from the input commit. The change is minimal (10 insertions, 6 deletions) and purely preparatory: it enables the next patch in the series to construct a squash message from multiple commits rather than just one.

The patch adds the optional `message_template` argument to `commit_tree_ext()`. When `NULL`, the function behaves exactly as before, using the original commit’s message. When non-NULL, it uses the provided template instead. The existing `fixup` and `split` callers pass `NULL`, so their behavior is unchanged. The implementation is straightforward: the template is passed through to `fill_commit_message()` or `strbuf_addstr()` depending on whether the commit message is being edited.

This is a refactoring patch with no user-visible behavior change. Its sole purpose is to enable the squash logic in patch 3/4 to seed the editor with a message constructed from all commits in the folded range. The patch is clean, well-scoped, and does not introduce any new complexity or edge cases. The commit message clearly states the motivation and the unchanged behavior for existing callers. No test coverage is added here because the patch does not alter any observable behavior; testing will be handled in the subsequent patch that uses the new parameter.
