This is Junio Hamano's review of the second patch in Pablo Sabater's v6 series, which introduces abstraction functions in `revision.c` for `git log --graph`'s lookahead logic. The patch is part of the cascading indentation feature for visual roots in graph rendering.

Junio identifies a technical debt issue in the implementation: the loop in `revision_has_commits_after()` directly accesses `info->topo_queue.nr` and iterates over `info->topo_queue.array`, which assumes the priority queue is stored as a dense array. This is fragile because it relies on internal details of the `prio_queue` structure. He suggests using `prio_queue_for_each()` instead, which would make the code more robust against future changes to the priority queue implementation.

The review references Kristofer Haugsbakk's ongoing `kk/prio-queue-get-put-fusion` topic, which is refactoring the priority queue API. Junio notes that the two topics will need to be reconciled—either by rebasing this series on top of the prio-queue changes or by merging this series first and then updating the prio-queue topic. The decision will depend on the readiness of both topics.

This is a substantive review comment, but it does not block the current patch. The issue is a forward-compatibility concern rather than a correctness problem, and Junio does not request an immediate rewrite. The patch remains conditionally approved pending the defensive `BUG()` check discussed earlier in the thread, and this new comment adds another item to the follow-up work list. The interaction with the prio-queue topic will need to be resolved before either series graduates to `master`.
