This is a follow-up in the ongoing worktree diff performance thread, where Jeff King (Peff) responds to Junio C Hamano’s design suggestion for tracking racy entries in the index state (`istate`).

Peff acknowledges Junio’s proposal to add a new field to `istate` to track racy entries that would benefit from auto-refreshing, calling it "fairly clean." However, he reiterates his preference for addressing the root cause by enabling nanosecond-aware timestamp comparisons unconditionally, as his latest patch does. He argues that if nanosecond precision works as intended—making racy entries extremely rare—it would be a more fundamental and simpler solution than architectural changes to the diff machinery.

On a tangential note, Peff questions the necessity of the `refresh_index_quietly()` call in `cmd_diff()` for tree-to-tree comparisons, suggesting it could be moved into `builtin_diff_files()` or removed entirely. He also notes that `--no-optional-locks` (a flag to avoid optional file locks) is not currently respected by `git diff`, but this is likely not a practical issue since users rarely run `git diff` in the background. This observation aligns with the project’s historical approach of adding such flags only when users encounter real-world conflicts.

The email advances the thread by weighing Junio’s `istate` proposal against Peff’s timestamp-precision approach, with Peff leaning toward the latter for its simplicity. No new patches or performance data are introduced, but the discussion clarifies the tradeoffs between architectural refinement and addressing the root cause. The thread remains focused on validating Peff’s latest patch while keeping Junio’s proposal as a fallback if unforeseen issues arise.
