This is a technical discussion in the ongoing worktree diff performance thread, focusing on the root cause of slow `git diff` operations in secondary worktrees. Jeff King (Peff) weighs in on the counter-based guard in `builtin/diff.c` that controls index refresh behavior, which was previously clarified by Junio C Hamano.

Peff identifies the core issue: "racy git dirty" entries (files with timestamps matching the index mtime) force expensive content checks, but `diffcore_skip_stat_unmatch()` doesn’t count them as dirty. This means the counter never increments, so `git diff` never writes out the refreshed index, causing repeated expensive checks in subsequent diffs. He presents two potential fixes: either modify `diffcore_skip_stat_unmatch()` to count these entries as dirty, or change how the index marks them (though the latter risks user-visible side effects in plumbing commands).
