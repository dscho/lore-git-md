### **`git pack-objects` gains full `--delta-islands`/`--path-walk` compatibility**
Taylor Blau's four-patch v3 series, posted late in the day, resolves the long-standing limitation where `--path-walk` could not leverage bitmaps or delta-islands. The implementation enables sequential compatibility: bitmaps accelerate object counting (with path-walk as a one-way fallback), while delta-islands are respected during path-walk traversal via tree-depth recording. Empirical validation in the updated `p5311` perf test confirms that path-walk's compression benefits persist when bitmaps are enabled (e.g., 558.4M → 164.4M in the fluentui repository). Derrick Stolee's earlier request for performance documentation is now satisfied, and Junio's test robustness concerns are addressed by forcing fresh repacks (`-F`). The series touches `pack-objects.c`, test scripts, and adds the new `p5311-repack.sh` perf test, with no on-disk format changes. All prior review feedback is incorporated, and the patches are now merge-ready.

### **`git history squash` clears final design hurdle**
Harald Nordgren's four-patch v4 series implementing `git history squash <range>` is now code-complete and ready for Junio's final assessment. The command folds a commit range into its oldest commit while preserving descendant history, avoiding the repeated conflict stops of a rebase-based approach. The key design resolution—rejecting operations with refs pointing inside the squashed range by default, with an `advice.historyUpdateRefs` hint to use `--update-refs=head`—addresses Patrick Steinhardt's earlier concerns about surprising users. The implementation handles merge commits, authorship preservation, and `--reedit-message` template construction (mirroring `git rebase -i` squash behavior). Test coverage (340 lines in `t/t3455-history-squash.sh`) validates range parsing, ref-handling, and `--dry-run` prediction accuracy. The series touches `builtin/history.c`, `advice.c`/`advice.h`, and documentation, with no behavioral regressions. All prior technical and design objections are resolved, and the patches are queued in `next`.

### **Worktree diff performance investigation yields minimal root-cause fix**
A performance investigation into `git diff` slowdowns in secondary worktrees (223.3ms vs 3.4ms in the main worktree) culminated in Jeff King's minimal patch to remove the `#ifdef USE_NSEC` guard in `read-cache.c:is_racy_stat()`. The change enables nanosecond-aware timestamp comparisons unconditionally, eliminating racy entries at the source by leveraging existing nanosecond precision infrastructure. Testing confirms the problem "goes away" with this approach, which Junio Hamano acknowledged as "cute" (mild approval). The patch is small (8 lines removed, 1 line added) and directly addresses the root cause—racy-git scenarios forcing full content checks via `ie_match_stat`/`ce_modified_check_fs`—without architectural changes or performance tradeoffs. The original `USE_NSEC` conditional was introduced to avoid stat-matching failures when the kernel's in-memory cache dropped nanosecond precision, but this concern does not apply to simple timestamp comparisons. The patch touches core index refresh logic (`is_racy_stat`, `ie_match_stat`) and is motivated by the observation that the existing nanosecond comparison code is well-tested. No on-disk format changes are required.
