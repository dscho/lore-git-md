This is the first patch in the v7 iteration of a GSoC feature series that standardizes path formatting across Git commands. The patch extracts the path-formatting logic from `builtin/rev-parse.c` into a new `append_formatted_path()` helper in `path.c` and immediately converts `rev-parse` to use it. This is a refactoring patch that consolidates duplicated code without changing any behavior.

The helper supports four formatting modes: unmodified, relative, relative-if-shared, and canonical. The implementation preserves exact backward compatibility for `rev-parse` output, which is validated by existing tests. The patch also introduces a `path_format` enum in `path.h` to make the API self-documenting.

This version addresses Junio C Hamano's feedback from v6 by squashing the first two patches, so the helper is introduced and used in the same commit. The change is mechanical and well-tested, with no dead code introduced. The patch is part of a three-patch series that adds new `git repo info` fields in later commits, but this patch stands alone as a clean plumbing improvement.

The files touched are `path.c`, `path.h`, and `builtin/rev-parse.c`. The new symbols are `append_formatted_path()` and the `path_format` enum. The patch is ready for maintainer pickup and should graduate to `next` once Junio confirms the squash satisfies his structural requirement.
