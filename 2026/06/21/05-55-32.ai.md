This is the first patch in the v7 iteration of a GSoC feature series that consolidates Git’s path-formatting logic into a reusable helper. The patch extracts the duplicated code from `builtin/rev-parse.c` into a new `append_formatted_path()` function in `path.c`, exposing it via a `path_format` enum in `path.h`. The `rev-parse` command is immediately converted to use the helper, ensuring the API is validated against existing tests and avoiding any dead code in the tree.

The implementation is mechanical and preserves exact backward compatibility: all existing `rev-parse` output formats (unmodified, relative, relative-if-shared, and canonical) are handled by the new helper, and the patch passes the full test suite. The helper’s design was refined through earlier review feedback to align with the existing `rev_parse_format` enum, and the squash of the first two patches in v7 satisfies Junio C Hamano’s structural requirement to show the helper replacing existing logic before adding new features.

Files touched are `path.c`, `path.h`, and `builtin/rev-parse.c`. The new symbols are `append_formatted_path()` and the `path_format` enum. No behavior changes are introduced; this is purely a refactoring step that sets the stage for the next two patches, which will add new path fields to `git repo info`. The patch is well-tested, with the existing `rev-parse` tests serving as implicit validation of the helper’s correctness.
