This is a review comment on the client-side implementation of the `remote-object-info` command in the `git cat-file --batch-command` feature. The reviewer, Chandra Pratap, raises a **substantive technical concern** about the use of `static` variables in the `parse_cmd_remote_object_info()` function.

The issue is straightforward: the variables `remote_object_info` and `object_info_oids` are declared `static`, which suggests they might retain state between function calls. However, the code allocates, uses, and frees them entirely within a single command cycle, making the `static` qualifier unnecessary and misleading. This could confuse future maintainers into thinking the function is designed to preserve state across invocations, when in fact it is not. The reviewer points out that the current implementation gives a "false impression" of persistence.

The patch is part of the **security-hardened `git cat-file --batch-command` integration series**, now in its 13th iteration and considered ready for merging. This is the first time this specific issue has been raised, and it is a **clear technical oversight** rather than a stylistic nit. The fix would be mechanical (removing the `static` keyword), but the observation is valid and worth addressing before the series lands. No other concerns are raised in this email.
