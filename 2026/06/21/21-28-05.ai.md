This is a performance-focused patch proposal in the ongoing worktree diff performance thread. Jeff King (Peff) responds to Junio C Hamano’s suggestion to leverage nanosecond timestamp precision (`USE_NSEC`) by implementing and testing a minimal change to `read-cache.c` that enables nanosecond-aware timestamp comparisons unconditionally. The patch removes the `#ifdef USE_NSEC` guard in `is_racy_stat()`, allowing Git to compare timestamps with full nanosecond precision when available, and adds a debug warning to track racy entries.

Peff’s patch demonstrates that enabling nanosecond comparisons effectively eliminates racy entries in practice, even without Junio’s proposed 50-millisecond delay. He argues that the delay is unnecessary because the probability of a nanosecond-level collision is astronomically low (on the order of one in a billion for a typical repository), and even a single collision would not meaningfully impact performance. The patch touches the core index refresh logic (`is_racy_stat`, `ie_match_stat`) and is motivated by the observation that the existing `USE_NSEC` conditional was introduced to avoid stat-matching failures when the kernel’s in-memory cache dropped nanosecond precision, but this concern does not apply to simple timestamp comparisons.

The patch is small (8 lines removed, 1 line added) and directly addresses the root cause of the worktree diff slowdown by eliminating racy entries at the source. Peff notes that the nanosecond comparison code already exists and is well-tested, but he remains cautious about potential edge cases that might have led to the original `USE_NSEC` conditional. His testing shows the problem "goes away" with this change, though he does not provide specific performance measurements in this email. The patch does not modify on-disk formats or require build-time configuration, making it a runtime-only fix.

This proposal shifts the solution space toward a simpler, more fundamental fix than Peff’s earlier `DIFF_RACY_IS_MODIFIED` patch, which required architectural changes to the diff machinery. It aligns with Junio’s preference for addressing raciness at the source rather than working around it in the diff subsystem. The key technical detail is the removal of the `USE_NSEC` guard, which allows Git to use nanosecond precision when comparing index and file timestamps, effectively eliminating the racy-git scenario that forces full content checks. The patch is likely to be uncontroversial if no hidden edge cases emerge, as it leverages existing infrastructure and avoids the performance tradeoffs of Peff’s earlier approach.
