This patch implements the core logic of `git history squash <revision-range>`, which folds a commit range into its oldest commit while preserving descendant history. The command performs a single three-way merge of the entire range against the oldest commit’s parent, then replays any descendants on top of the result. The range must have a single base (rejecting ambiguous ancestry), and merge commits inside the range are handled like any other commit.

Key implementation details in this patch:
- The new `resolve_squash_range()` helper parses the `<base>..<tip>` range, validates it has a single base, and identifies the oldest commit (whose message and authorship are preserved) and the tip commit (whose tree becomes the result).
- The `find_interior_ref()` callback checks for refs (branches, tags) pointing into the squashed range, triggering the default rejection with an `advice.historyUpdateRefs` hint to use `--update-refs=head`.
- The `cmd_history_squash()` entry point orchestrates the squash: resolving the range, validating refs, performing the three-way merge, and replaying descendants using the existing `handle_reference_updates()` machinery.
