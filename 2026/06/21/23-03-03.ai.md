This is the second patch in Taylor Blau’s **v3** 4-patch series integrating `--delta-islands` and reachability bitmaps with `--path-walk` in `git pack-objects`. It specifically enables **bitmap support during path-walk traversal**, resolving a long-standing limitation where `--path-walk` could not leverage existing bitmaps.

The patch teaches `add_objects_by_path()` to call `index_commit_for_bitmap()` for commits it adds, ensuring the bitmap selector sees the same commit candidates it would during a regular traversal. It also stops clearing `use_bitmap_index` when `--path-walk` is specified, allowing Git to attempt a bitmap traversal first and fall back to path-walk only if bitmaps are unavailable. Performance measurements in the commit message show dramatic speedups (up to 99.3% reduction in server time) while preserving path-walk’s compression benefits, as validated by the updated `p5311` perf test.

A key edge case is handled: `--boundary` is set *after* any bitmap attempt, since bitmap traversal does not understand boundary commits. The patch touches `pack-objects.c`, updates the `git-pack-objects` documentation to clarify the sequential interaction model, and adds a new test in `t5310` verifying that path-walk repacks can both write and use bitmap indexes.

This is a **performance-focused refactoring** with no on-disk format changes. The implementation is well-tested, with empirical validation across multiple repository types (including the fluentui repository) demonstrating that bitmap acceleration does not regress path-walk’s compression improvements. All prior review feedback has been addressed, and the series is now merge-ready.
