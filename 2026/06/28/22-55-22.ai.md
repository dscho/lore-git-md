This is a protocol-design clarification in the GSoC v14 series that adds remote object metadata queries via `git cat-file --batch-command`. The email is the ninth patch in a thirteen-patch series; the thread AI summary above gives the full context.

Karthik Nayak asks how future metadata features (e.g., object type) will be advertised by the server. Pablo Sabater replies that they will be appended to the same space-separated list in the `object-info` capability value—so the current `"size"` will become `"size type"` when object type support is added. He also proposes a small documentation update to `gitprotocol-v2.adoc` that tightens the spec: full object IDs will be required, and servers will respond with just the object ID (no attributes) if the object is unknown. The names (`size`, `type`) are arbitrary and chosen for simplicity.

No code changes are needed; the discussion establishes consensus on the wire protocol’s extensibility mechanism. The response is narrowly focused on the advertisement format and does not revisit the larger architectural questions (error handling, transport-layer cleanliness) that remain open elsewhere in the series.
