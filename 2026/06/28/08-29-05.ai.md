This is the sixth iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete and addresses all prior feedback, including major design changes in v6.

The headline change in v6 is the shift from a single `<base>..<tip>` argument to supporting multiple revision arguments, read like `git rev-list`. This allows compound ranges such as `@~3.. ^topic` to exclude commits already on another branch, directly addressing Junio C Hamano’s usability concern about the earlier single-argument limitation. The range resolution logic has been rewritten: the base is now always the oldest in-range commit’s parent, and any boundary commit other than that base is treated as evidence of multiple bases and rejected. This replaces the earlier `--ancestry-path` enforcement with a more flexible and intuitive rule that still prevents ambiguous ranges.

Input validation is now stricter: single-commit ranges (e.g., `@^!`) are explicitly rejected with “nothing to squash,” and the code checks for empty ranges, non-range arguments, and multiple bases. The commit messages have been reworded to clarify behavior around `fixup!`/`squash!`/`amend!` commits (which are folded like any other, not interpreted), merge-parent handling, and ref safety. The test suite has grown to 550+ lines, covering compound ranges, merge topologies (including merges with external parents, which are now rejected), and interior ref detection.

The implementation remains a single three-way merge of the entire range against the oldest commit’s parent, followed by replaying descendants. The `--reedit-message` flag continues to seed the editor with every folded-in commit message, oldest first, mirroring `git rebase -i` behavior. The ref-handling logic introduced in v4 is unchanged: the command rejects operations where any ref points to a commit inside the squashed range, with an advice message suggesting `--update-refs=head` to retarget only the current branch.

Files touched are `builtin/history.c` (357 insertions, 76 deletions across the series), `advice.c`/`advice.h`, `Documentation/git-history.adoc`, and a new test script `t/t3455-history-squash.sh`. The series is ready for Junio’s final assessment; no further design changes are expected.
