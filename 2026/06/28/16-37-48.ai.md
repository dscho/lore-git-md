This is a user-support follow-up in the resolved `git ls-remote` infinite-loop thread. Steffen Nurpmeso reports that the original hang has not recurred, but now observes that `git ls-remote` fails with a low-speed timeout instead of entering a busy-loop. He confirms that adjusting `http.lowSpeedLimit` and `http.lowSpeedTime` prevents the timeout, but notes that the process still blocks indefinitely without progress feedback. The root cause of the original busy-loop remains unidentified; this email merely documents a different symptom on the same repository under constrained network conditions. No code changes or further investigation are proposed.
