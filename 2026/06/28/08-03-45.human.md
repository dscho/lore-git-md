This is the second patch in Jeff King’s three-patch series fixing macOS CI hangs in the `t5551` and `t5559` test scripts. It isolates the expensive "many tags" test cases into their own repository, cutting the runtime of the full test script from ~2.7 seconds to ~1.9 seconds in normal runs and from ~95 seconds to ~37 seconds when the `--long` (EXPENSIVE) flag is used.

The change is simple: the 2,000-tag and 100,000-tag tests now run in a separate `$HTTPD_DOCUMENT_ROOT_PATH/many-tags.git` instead of sharing the main `repo.git`. This avoids forcing every subsequent test to process the large ref advertisement, which was the main source of the slowdown. Peff notes that the gain is modest in normal runs but becomes dramatic under `--long`, where the 100,000-tag case was the real performance culprit. The patch touches only `t/t5551-http-fetch-smart.sh` and is a straightforward refactoring with no behavior change.

The motivation is purely performance: the existing coverage was already redundant, and the isolated repository still exercises the same code paths. The patch is uncontroversial and complements the series’ other optimizations (ref-packing in patch 3/3 and the Apache timeout increase in patch 1/3). It’s a clean, low-risk improvement that directly addresses the CI flake root cause.
