This is the ninth patch in the GSoC v14 series implementing `git cat-file --batch-command` support for remote object metadata queries. The patch adds server-side capability advertisement for the `object-info` feature, allowing clients to discover whether a server supports querying object metadata (initially just object size) without downloading the full object.

The email is a clarification exchange between Karthik Nayak and Pablo Sabater about the wire protocol format for future extensibility. Karthik asks how additional metadata attributes (like object type) will be advertised, and Pablo confirms they will be appended as space-separated strings in the same `value` buffer (e.g., `"size type"`). Pablo also proposes tightening the protocol documentation in `gitprotocol-v2.adoc` to specify that full object IDs are required and that unrecognized objects will return an empty attribute list.

The discussion is purely about protocol design and does not introduce code changes. It resolves the forward-looking question raised in the thread summary, establishing consensus on how the protocol will handle future metadata features. The proposed documentation update would make the protocol spec more precise without requiring changes to the current implementation. This patch remains uncontroversial and ready for merging.
