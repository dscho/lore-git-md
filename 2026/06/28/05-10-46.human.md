This is a brief follow-up in the HTTPS proxy regression thread. Junio C Hamano retracts his earlier suggestion to refactor `set_curl_proxy_type()` to return `void`. He clarifies that the original intent of the regressing commit (`663d7abe07ea`) was to actively reject unsupported proxy schemes, so the function must retain its error-return path. The bug was simply a logic error where HTTPS proxies—already supported—were incorrectly rejected due to a missing `return 0`. The patch under discussion (adding the missing return) remains the correct fix. No further changes are proposed; the thread is now settled on the original patch as the solution.
