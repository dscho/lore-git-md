This is a follow-up to Jeff King’s memory-leak fix in the reftable backend. The patch itself is already merged (via `pu`), but Peff notes a minor textual conflict with a recent commit (`44f46f2be5`, "reftable: split up write options", 2026-06-25) that added a line near the leak fix. He provides the resolution: the new `hash_id` initialization should stay grouped with the other `opts` setup, while the allocation (`reftable_calloc`) moves after the block-size check. The resolution is mechanical and uncontroversial—just a three-line reordering in `reftable/writer.c`—and Peff’s diff shows exactly how the conflict should be handled. No functional changes are involved; this is purely about keeping the code tidy during integration. The reftable backend remains an ongoing effort led by Patrick Steinhardt and Karthik Nayak.
