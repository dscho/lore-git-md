This is the sixth iteration of Harald Nordgren’s `git history squash` feature, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The series is now functionally complete, addressing all prior feedback from Phillip Wood, Junio C Hamano, and Patrick Steinhardt.

The headline change in v6 is the shift from a single `<base>..<tip>` argument to accepting multiple revision arguments, parsed like `git rev-list`. This resolves Junio’s usability concern about excluding branches (e.g., `git history squash @~3.. ^topic` now works). The range resolution logic has been rewritten: the base is now the oldest in-range commit’s parent, and any boundary commit other than that parent is treated as a multi-base error. Single-commit ranges (e.g., `@^!`) are now explicitly rejected with a clear error message.

The commit messages have been reworded to clarify edge cases: `fixup!`/`squash!`/`amend!` commits are folded like any other (not interpreted), merge commits are accepted only if their other parent is reachable from the base, and the default behavior of rejecting operations with interior refs is now documented. The test suite has grown to 550+ lines, covering multi-argument ranges, merge-parent validation, and interior ref detection.

The implementation remains a single three-way merge of the range against the oldest commit’s parent, followed by replaying descendants. The `--reedit-message` flag continues to seed the editor with all folded-in commit messages (oldest first), mirroring `git rebase -i`. The series touches `builtin/history.c` (357 insertions), `advice.c`/`advice.h`, and adds a new test script. The range-diff shows the multi-argument support, stricter validation, and expanded test coverage.

This iteration looks solid: the core functionality is well-tested, the input syntax is more flexible, and the edge cases are clearly documented. The series is ready for Junio’s final assessment.
