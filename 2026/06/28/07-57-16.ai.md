This is a **CI/platform-compatibility** patch series that implements the consensus solution for macOS CI hangs in `t5551` and `t5559`. Jeff King (Peff) sends three patches to address Apache bug 70131, which causes HTTP/2 stalls or `curl 18` mid-transfer aborts during `ls-refs` advertisements of 100,000 loose refs. The series directly targets the root cause by increasing Apache’s `Timeout` directive from 300 to 600 seconds (10 minutes) and includes complementary optimizations to reduce timeout risk.

The first patch (`t/lib-httpd: bump apache timeout`) is the core fix, raising the timeout to 600 seconds in `t/lib-httpd/apache.conf`. This aligns with Peff’s earlier proposal and the thread’s consensus, addressing the immediate CI failures without client-side workarounds. The second and third patches are optimizations: `t5551: put many-tags case into its own repo` isolates the expensive test case to avoid interference, and `t5551: pack refs after creating many tags` reduces the `ls-refs` advertisement time from ~1.2 seconds to 24 ms by packing refs. Peff expresses mild skepticism about the third patch’s necessity but includes it as a belt-and-braces measure.

The series touches `t/lib-httpd/apache.conf`, `t/t5551-http-fetch-smart.sh`, and implicitly the GitHub Actions CI configuration (though no changes are made there). It affects the test suite’s HTTP/2 and HTTP/1.1 transport layers, Apache’s `mod_http2`/`mod_cgi`, and timeout handling. The new behavior is straightforward: Apache will wait longer for slow `upload-pack` responses, and the expensive test case will run faster. No on-disk format changes or user-visible features are introduced.

This is a well-motivated, low-risk fix for a persistent CI flake. The timeout increase is conservative (600 seconds is double the default but far below Michael Montalbo’s tested 3600-second value), and the optimizations are non-controversial. The series is likely to be merged quickly, as the technical direction has already been agreed upon in the thread. The only open question is whether the third patch (ref-packing) is worth its marginal complexity, but even if dropped, the first patch alone resolves the issue.
