This is the third patch in Harald Nordgren’s **v6 series** implementing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. The patch introduces the core logic for range resolution, input validation, and ref safety checks.

The key technical work happens in `resolve_squash_range()`, which parses and validates the revision range. It now supports **multiple arguments** (e.g., `@~3.. ^topic`) to exclude commits already on another branch, addressing Junio C Hamano’s usability concern from earlier iterations. The function rejects single-commit ranges, empty ranges, and ranges with multiple bases (e.g., a side branch forked before the range). It also detects refs pointing to commits inside the squashed range and refuses the operation by default, advising users to use `--update-refs=head` to retarget only the current branch.

The patch adds `find_interior_ref()`, a helper that scans all refs to detect those pointing into the squashed range. This powers the safety check that prevents accidental ref loss. The test suite (`t/t3455-history-squash.sh`) is comprehensive, covering range parsing (including compound ranges), merge commit handling (nested, octopus, and external-parent rejection), descendant replay, authorship preservation, and ref-handling behavior (rejection logic, `--update-refs=head`, and advice messages).
