This is a small but well-crafted bugfix targeting the reftable backend. Jeff King (Peff) fixes a memory leak in `reftable_writer_new()` that occurs when the function returns early due to an invalid block size. The leak was introduced over a year ago when a `BUG()` call was converted to a regular error return, but only recently flagged by Coverity.

The patch is minimal and surgical: it moves the allocation of the `reftable_writer` struct *after* input validation, ensuring no resources are leaked if the function exits early. The commit message is clear and traces the leak's origin, and the code change itself is straightforward and logical. This is the kind of low-risk, high-value cleanup that the project welcomes.

No controversy here—just a quiet, correct fix for a latent issue. If you care about reftable internals or memory safety, it’s worth a quick look; otherwise, it’s safe to skip.
