This is the third patch in the v4 series optimizing `paint_down_to_common()` for one-sided histories. It adds **regression tests** for the side-exhaustion optimization, ensuring the code correctly handles cases where one merge-base candidate is an ancestor of another and exercises the optimization across generation-number regions.

The patch introduces a new test script, `t6099-merge-base-side-exhaustion.sh`, which verifies that `git merge-base --all` correctly excludes redundant merge-base candidates (e.g., when one candidate is an ancestor of another). The test constructs a diamond-shaped commit graph where two merge-base candidates exist, but only one should appear in the output. It also confirms that the optimization behaves correctly both with and without a commit-graph present.

Additionally, the patch extends `t6600-test-reach.sh` with a test for **mixed finite/INFINITY generation numbers**, where one commit is outside the commit-graph (INFINITY generation) and the other is inside (finite generation). This exercises the region transition logic: the walk starts in the INFINITY region (where side-exhaustion is disabled) and crosses into the finite region (where it can fire). The test ensures the optimization works correctly when traversing these boundaries.

The tests are **deterministic, self-contained, and cover edge cases** that were not previously exercised. They complement the broader test coverage added in other patches (e.g., the four new edge-case tests in patch 2/8). The patch is **stable since v3** and has no known issues. If the series lands, these tests will help prevent regressions in the side-exhaustion logic.
