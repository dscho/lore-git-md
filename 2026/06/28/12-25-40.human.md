This is the second patch in Tian Yuchen’s eight-part series optimizing `paint_down_to_common()` for one-sided histories. The patch adds four edge-case test scenarios to `t6600-test-reach.sh`, all authored by Elijah Newren and co-signed by Kristofer Karlsson.

The new tests exercise the side-exhaustion optimization in `paint_down_to_common()` by covering four distinct edge cases: a commit that is both the query tip and one of the inputs (`self`), duplicate entries in the input list (`duplicate-twos`), a STALE transition on an already-painted commit (`pending-stale`), and a scenario where both query tips lie outside the commit-graph and have non-monotonic commit dates (`infinity-both-sides`). Each test builds a small, targeted commit topology (e.g., a diamond-shaped graph for `pending-stale` and a linear history with non-monotonic dates for `infinity-both-sides`) and verifies that the merge-base calculation returns the expected result across all commit-graph modes (none, full, half, no-gdat).

The patch is purely additive—111 lines of new test code—and does not touch production code. It is stable, uncontroversial, and ready to merge. The test coverage it provides was instrumental in catching the regression in v3 of the series, and the topologies it introduces (particularly `ps-*` and `pi-*`) are now referenced in the new technical document (`paint-down-to-common.adoc`) added in patch 1/8. If you care about the correctness of merge-base calculations or the performance of asymmetric queries, these tests are worth reviewing as a reference for the kinds of edge cases the optimization must handle.
