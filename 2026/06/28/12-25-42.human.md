This is a **performance instrumentation patch** in the ongoing `paint_down_to_common()` optimization series. It adds **trace2 step-counting** to the `paint_down_to_common()` function in Git’s commit-reach subsystem, allowing developers to measure the number of commits visited during merge-base calculations via `GIT_TRACE2_EVENT`. The patch also **refactors the test harness** to capture trace2 output per commit-graph mode (none, full, half, no-gdat) and introduces a new helper, `test_paint_down_steps()`, to assert deterministic step counts across all modes.

The change is **minimal and focused**: it increments a counter for each commit processed and emits the total via `trace2_data_intmax()` at the end of the walk. The test suite is updated to verify step counts for existing edge-case topologies (self, pending-stale, infinity-both-sides, mixed-finite-infinity) and adds a new test for `git merge-base --all` that confirms the step count for a 10×10 grid topology (80–81 steps, depending on commit-graph mode). The refactored `run_all_modes()` helper now writes trace2 logs to `trace-mode-*.txt` files, enabling self-verifying performance assertions.

This patch is **ready to merge** and received **unqualified approval** from Derrick Stolee, who praised the implementation as "clean" and noted it "over-achieve[d]" by capturing step counts for all commit-graph modes. The instrumentation is **low-risk**, with no behavior changes—it merely exposes internal metrics for future optimization work. The test updates are **deterministic and self-contained**, ensuring the optimization’s correctness across all commit-graph configurations. This is the **fourth patch in the eight-patch v4 series**, which has already addressed a critical regression in patch 7/8 and consolidated termination conditions in patch 8/8.
