This is the first patch in Harald Nordgren’s **v6 `git history squash` series** (4/4). It is a **refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit’s first parent (or the empty tree for root commits). The helper replaces three nearly identical code blocks in `builtin/history.c`, reducing duplication and making future changes easier.

The patch touches only `builtin/history.c` (26 insertions, 32 deletions) and introduces no behavior changes. The new helper is straightforward: it takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`; parses the first parent if it exists; and copies either the parent’s tree OID or the empty tree OID into the output. Error handling is preserved: if parsing the parent fails, the helper returns an error, and callers propagate it upward.

This refactoring is a direct response to earlier review feedback that noted the repeated code paths. The helper will be used in the subsequent patches (notably patch 3/4, which implements the core squash logic) to resolve the base tree for the three-way merge. The patch is uncontroversial and appears ready for integration.
