This is the **second patch in Jeff King’s 3-patch series** addressing macOS CI hangs in `t5551` and `t5559`. It **isolates the expensive "many-tags" test cases into a dedicated repository**, reducing the runtime of the entire `t5551` script from ~2.7 seconds to ~1.9 seconds in normal runs and from ~95 seconds to ~37 seconds when the `--long` (EXPENSIVE) flag is used.

The patch modifies `t/t5551-http-fetch-smart.sh` to create a new repository (`many-tags.git`) for the 2,000- and 100,000-tag test cases, instead of reusing the main `repo.git`. This avoids forcing all subsequent tests to process the large ref advertisement, which was previously a hidden cost. The change is a straightforward refactoring: the `create_tags` helper is now called in the new repository, and the clone/fetch commands are updated to point to `many-tags.git`. The CMDLINE_LIMIT prereq test (which checks for OS command-line overflow) is also redirected to the new repository.

Peff’s commit message explains the motivation clearly: the performance gain is modest for the 2,000-tag case but substantial for the 100,000-tag EXPENSIVE test, which was the primary culprit behind the CI hangs. He acknowledges a minor trade-off—reduced incidental test coverage—but dismisses it as unlikely to matter, given that the large-ref tests are already focused on similar scenarios. The patch is uncontroversial and aligns with the series’ goal of reducing timeout risks in CI. It complements the first patch (Apache `Timeout` increase) and the third patch (ref-packing optimization), though Peff has expressed mild skepticism about the latter’s necessity.

No new behavior or user-visible changes are introduced; this is purely a test-suite optimization. The patch is well-justified and likely to be merged as part of the series.
