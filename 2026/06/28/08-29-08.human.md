This is the third patch in Harald Nordgren’s v6 series introducing `git history squash`, a new subcommand that folds a commit range into its oldest commit while preserving descendant history. This patch implements the core logic and is the centerpiece of the series.

The patch adds the `squash` subcommand to `git history`, allowing users to collapse a range of commits (e.g., `git history squash @~3..`) into a single commit whose tree is the newest in the range and whose message and authorship come from the oldest. The implementation handles complex cases: it accepts multiple revision arguments (like `git rev-list`), rejects ambiguous ranges (those with more than one base or external merge parents), and replays descendants verbatim. By default, it refuses to run if any ref points to a commit inside the squashed range, offering an advice message that guides users to `--update-refs=head` to rewrite only the current branch.

The code is well-structured: `resolve_squash_range()` parses and validates the revision range, `find_interior_ref()` detects problematic refs, and the main `cmd_history_squash()` orchestrates the three-way merge and replay. The test suite (`t/t3455-history-squash.sh`) is thorough, covering range parsing, merge topologies (nested, octopus, and external-parent rejection), interior ref detection, and edge cases like single-commit ranges and empty ranges. The documentation update is clear and includes examples.

This patch directly addresses all prior feedback: it supports compound ranges (e.g., `@~3.. ^topic`), enforces strict input validation, and maintains the ref-handling design agreed in earlier rounds. The series is now code-complete and ready for Junio’s final review.
