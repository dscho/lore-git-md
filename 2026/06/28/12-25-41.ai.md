This is the third patch in the v4 series optimizing `paint_down_to_common()` for one-sided histories. It adds **regression tests** for the side-exhaustion optimization, ensuring the fix for the v3 regression (patch 7/8) is robust and that the optimization behaves correctly in edge cases.

The patch introduces a new test script, `t6099-merge-base-side-exhaustion.sh`, which verifies that `merge-base --all` correctly handles cases where multiple merge-base candidates exist and one is an ancestor of another. The test exercises the interaction between the side-exhaustion optimization (which may exit early before STALE propagation) and the `remove_redundant` safety net in `get_merge_bases_many_0`. The test topology is a diamond-shaped graph where `B` and `C` are both reachable from tips `A` and `X`, but `B` is an ancestor of `C` via `d1`. The test confirms that only `B` appears in the output, demonstrating that the optimization does not break correctness.

Additionally, the patch extends `t6600-test-reach.sh` with a test for **mixed finite/INFINITY generation numbers**, where one tip is outside the commit-graph (INFINITY generation) and the other is inside (finite generation). This exercises the region transition: the walk starts in the INFINITY region (where side-exhaustion is disabled) and crosses into the finite region (where it can fire). The test ensures the optimization works correctly when generation numbers are not uniform.

The tests are **deterministic and self-contained**, running in `test_all_modes` to verify all commit-graph modes (none, full, half, no-gdat). The new test script (`t6099`) is added to `t/meson.build` for Meson compatibility. No code changes are made to the core logic; this is **pure test coverage** to harden the optimization against regressions.

The patch is **stable and uncontroversial**, with no open questions or follow-up work. It directly addresses the regression risk identified in v3 and provides confidence that the optimization is safe. The test topologies are minimal and focused, avoiding overlap with existing test coverage while exercising the critical edge cases.
