This is the fifth patch in the v4 series optimizing `paint_down_to_common()` for one-sided histories. It introduces `struct paint_state` to track per-side commit counters (PARENT1-only, PARENT2-only, and pending merge-base candidates) and replaces the old `nonstale_queue` termination logic with a cleaner, counter-based approach.

The patch defines `paint_state`, a struct wrapping a `prio_queue` with three counters: `parent1_count`, `parent2_count`, and `mb_candidate_count`. The `paint_count_update()` helper adjusts these counters based on a commit’s paint flags, and `paint_queue_get()` now returns NULL when all counters reach zero, signaling that only stale entries remain. This change is behaviorally equivalent to the old `max_nonstale` pointer but more explicit and easier to reason about.

The "pop first" form of `paint_queue_get()` (dequeue, then check counters) reduces step counts by one in some topologies, as seen in the updated test expectations: the `pending-stale` test now expects 5 steps instead of 6, and the `infinity-both-sides` test drops from 5 to 4 steps in half-graph mode. The documentation in `paint-down-to-common.adoc` is updated to reflect the new termination condition ("the queue contains only stale entries").

This is a refactoring patch that prepares for the core optimization in patch 7/8. The changes are internal to `commit-reach.c` and do not affect the on-disk format or user-visible behavior. The patch fully addresses René Scharfe’s feedback from v3 by renaming counters for clarity and switching their types to `size_t`. The test updates are minimal and deterministic, and the new struct improves code clarity by centralizing the state tracking logic. Ready to merge.
