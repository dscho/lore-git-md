This is a **build system** and **platform compatibility** follow-up in the `USE_NSEC` Meson parity thread. Jeff King (Peff) expands on his earlier testing of the `USE_NSEC` knob’s reliability, now confirming that even vfat and CIFS filesystems on modern Linux preserve timestamp behavior correctly. He also surfaces an old 2015 thread that documents kernel fixes for coarse-grained filesystems (CEPH, CIFS, NTFS, UDF, and eventually FAT), suggesting the original "racy Git" concerns are obsolete on Linux.

The email introduces a new dimension: **interoperability risks** when different Git implementations (or versions) mix nanosecond and millisecond timestamps. Peff notes that while correctness is preserved if each implementation consistently uses its own resolution, performance could degrade if a non-`USE_NSEC` Git (or JGit) writes an index with millisecond timestamps and an `USE_NSEC`-enabled Git reads it—everything would appear stat-dirty, forcing unnecessary re-reads. This is a theoretical issue, but one that may go unnoticed since `USE_NSEC` is rarely enabled today.

Key technical details for future discussion:
- **Filesystems tested**: ext4, ext2, vfat, CIFS (all behave correctly on modern Linux).
- **Kernel fixes**: Timestamp rounding issues were resolved for most filesystems by kernel 4.3 (2015), with FAT support added later.
- **Interoperability**: The risk is performance (not correctness) when mixing `USE_NSEC` and non-`USE_NSEC` implementations.
- **JGit compatibility**: JGit’s millisecond-resolution APIs could trigger stat-dirty re-reads if used with `USE_NSEC`-enabled Git.
- **Test coverage gap**: No formal tests exist for these edge cases, and the knob’s real-world usage is likely minimal.

The thread’s focus has shifted from "should Meson expose this option?" to "is `USE_NSEC` still relevant, and should its default change?" Peff’s findings weaken the case for keeping the knob as a safety measure, but the interoperability caveats add complexity. No patch changes are proposed yet, but the discussion now centers on whether the knob should be deprecated, flipped to `true` by default, or left as-is. The original patch (adding the Meson option) remains technically valid, but its justification is now in question.
