This is the third and final patch in Elijah Newren's series refining the new `git backfill` command, which optimizes partial clone operations by pre-fetching objects. The patch focuses on blob handling behavior.

The change introduces a new `--[no-]include-edges` flag that controls whether blobs from boundary commits (like the 'A' in 'A..B' ranges) should be included in the backfill. The flag defaults to `--include-edges` because these blobs are often needed for common operations like `git log -p` and `git replay` that diff against boundary commits. The patch includes thorough test coverage demonstrating how this prevents on-demand blob fetching in various commands.

The implementation adds the flag to both documentation and the command-line interface, with the default behavior triggering the `revs.edge_hint` flag internally. Test cases verify the behavior with `git log`, `git replay`, and `git merge` operations, showing how edge inclusion affects subsequent command performance in partial clones.

This completes the series that began with safety checks for `rev-list` arguments and documentation improvements. The change is well-motivated by real-world partial clone usage patterns and comes with comprehensive test coverage.
