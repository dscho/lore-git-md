This is the final patch in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite. The patch implements the core change that makes the test suite abort immediately when any command outside a test case fails unexpectedly. The change is carefully scoped to only activate for Bash 5+ due to inconsistent behavior in older shells, particularly macOS's Bash 3.2.57.

The patch adds the `set -e` directive at the start of `t/test-lib.sh`, guarded by a version check. This follows from the extensive preparatory work in earlier patches that hardened test infrastructure components to work correctly with errexit enabled. The commit message cites a concrete motivation - a recent case where a misspelled `test_expect_success` went undetected because failures outside test cases were silently ignored.

This change represents the culmination of the series' goal to make the test suite more robust by catching errors that would otherwise be missed. The version restriction reflects the pragmatic approach taken throughout - prioritizing reliability in modern CI environments (which typically use Bash 5+) while avoiding brittle behavior on platforms with problematic shell implementations. The door is left open to expand support to other shells in the future if their behavior can be verified as compatible.
