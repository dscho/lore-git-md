This is the final patch in a merged feature series implementing autostash behavior for `git checkout -m`. The series has already been merged to the `next` branch and is now in its polishing phase.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches if there are conflicts, then reapply them after the switch. If the reapplication causes conflicts, the stash is preserved and the user is given instructions for resolving the situation. The behavior mirrors existing autostash functionality in other commands like `git rebase`.

Key technical changes include:
- New autostash creation and application logic in `builtin/checkout.c`
- Integration with the existing merge conflict resolution machinery
- Comprehensive test coverage in `t/t7201-co.sh` for various edge cases
- Documentation updates explaining the new behavior in `git-checkout.adoc` and `git-switch.adoc`

The implementation builds on prior work in the sequencer's autostash handling, extending it to support branch switching scenarios. The patch includes fixes for resource management (ensuring proper lock rollback) and maintains backward compatibility with existing conflict resolution workflows.

This represents the culmination of a 13-iteration series that has undergone extensive review from Phillip Wood and Junio Hamano. The changes are well-tested and the documentation clearly explains both the happy path and conflict scenarios.
