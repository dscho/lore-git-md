This is part 6/7 of Derrick Stolee's series introducing negotiation controls for fetch/push operations, focusing on monorepo scaling. The patch adds config-based defaults for the `--negotiation-require` option introduced earlier in the series.

The key addition is `remote.<name>.negotiationRequire`, a multi-valued config option that specifies ref patterns (exact names or globs) whose tips should always be included in negotiation. This mirrors the existing `remote.<name>.negotiationRestrict` config for the restrict option. The config values are resolved through the same `resolve_negotiation_require()` codepath as CLI options.

The implementation spans `remote.c` (config handling), `builtin/fetch.c` (transport preparation), and includes comprehensive tests in `t/t5510-fetch.sh` verifying:
- Basic config functionality
- Glob pattern support
- CLI option overriding config
- Interaction with restrict options

The changes maintain the additive nature of negotiation - config-specified refs are sent unconditionally alongside algorithm-selected commits. The patch follows the established pattern from earlier in the series, with clean separation between transport layer changes and user-facing configuration.
