This is the first patch in a 3-patch series refining the new `git backfill` command, which helps pre-fetch objects in partial clone scenarios. The patch comes from Elijah Newren, a Git merge machinery expert.

The patch adds explicit rejection of several `rev-list` options that don't make sense for `backfill` but would otherwise be silently ignored or counterproductive. These include diff-related options like `-S/-G`, `--diff-filter`, `-L`, and `--follow`, which could cause the command to skip blobs when its whole purpose is to fetch them. The patch adds clear error messages rather than letting these options fail silently.

The change is straightforward and well-justified in the commit message, which explains why each rejected option would be problematic. The implementation adds a new helper function that checks for these cases early in the command's execution. This is a sensible safety measure for a new command that will likely see experimentation from users.
