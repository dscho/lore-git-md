This is a test infrastructure patch series that continues Patrick Steinhardt's effort to make Git's test suite more robust by enabling `set -e` (errexit) to catch errors outside of test cases. The series has evolved based on feedback and testing, with v2 introducing several important refinements.

The key changes in this version include:
- Restricting `set -e` to Bash 5+ only, after discovering inconsistent behavior in older shells (particularly macOS's Bash 3.2.57)
- Using a more reliable `ret=0; command || ret=$?` pattern for error handling
- Fixing platform-specific issues on FreeBSD 15
- Improving handling of SVN module detection in test prerequisites
- Standardizing on `|| :` instead of `|| true` for no-op commands

The series carefully prepares various test helper functions and existing tests to work correctly with `set -e` enabled, addressing edge cases in signal handling, daemon management, conditional test execution, and cleanup routines. Specific test scripts (t0008, t1301, t6002, t9902) receive targeted fixes for their unique requirements.

This represents a pragmatic approach to test hardening, prioritizing reliability in modern CI systems (which use Bash 5+) while avoiding brittle behavior on platforms with problematic shell implementations. The changes are mechanical but important for catching more test failures early. Reviewers will want to verify the error handling changes don't introduce false positives, though Patrick's testing across multiple shells and platforms gives confidence in the implementation.

The series exemplifies Git's iterative development process, where technical constraints (shell behavior inconsistencies) have shaped a more targeted solution that still achieves the core goal of improved error detection. The narrowed scope to Bash 5+ reflects the project's willingness to adapt when universal adoption proves infeasible.
