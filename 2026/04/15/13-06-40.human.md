This is part 7 of Patrick Steinhardt's ongoing test infrastructure series to enable `set -e` (errexit) in Git's test suite. The patch focuses on making the `test_when_finished()` and `test_atexit()` cleanup handlers work correctly when `set -e` is active.

The change modifies how these functions preserve the test's exit code during cleanup operations. The previous implementation could fail with `set -e` when the test body had failed (non-zero exit), as the subshell would exit early. The new version uses a simpler `|| eval_ret=$?` pattern that maintains the same behavior while being compatible with `set -e`.

The patch includes clear truth tables showing the behavior before and after the change, demonstrating that the exit code handling remains equivalent while becoming more robust. This is a well-motivated change that addresses a concrete issue in the test infrastructure, continuing the series' systematic approach to hardening Git's test suite.
