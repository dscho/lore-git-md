This is part 3 of Patrick Steinhardt's test infrastructure series to enable `set -e` in Git's test suite. The patch focuses on making the `stop_git_daemon()` helper function work correctly under strict error checking.

The function currently has two issues that would cause failures with `set -e` enabled: an unconditional `wait` call that's expected to fail, and a second `kill` call that often fails harmlessly when the daemon is already stopped. The patch fixes these by:

1. Wrapping the `wait` in a `ret=0; ... || ret=$?` pattern to capture the exit code without triggering `set -e`
2. Silencing the second `kill` with `|| :` since its failure is expected and harmless

These changes maintain the function's error checking (it still verifies the daemon exited with SIGTERM) while making it robust under `set -e`. The patch is mechanical but important - daemon management appears in many tests, so getting this right is foundational for the broader `set -e` effort.

The changes align with the series' overall approach of carefully auditing test infrastructure for `set -e` compatibility. This particular helper needed attention because it's called outside test cases (where errors would be fatal) and has expected-but-handled failures in its normal operation. The implementation follows patterns established earlier in the series for reliable error handling.
