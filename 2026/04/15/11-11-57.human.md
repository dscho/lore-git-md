Feature patch implementing autostash behavior for `git checkout -m` during branch switching conflicts. This is the final patch in a merged series that has been through 13 iterations of review and refinement.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches would cause conflicts, then reapply them after the switch. If the changes apply cleanly, the stash is silently dropped. If conflicts occur during reapplication, the stash is preserved and the user is given clear instructions for recovery. The behavior matches existing autostash functionality in `git rebase` and `git pull`.

Key improvements in this version:
- Proper lockfile management in `merge_working_tree()` to prevent resource leaks
- Clearer user messaging about conflict resolution options
- Comprehensive test coverage of edge cases (non-conflicting changes, staged+unstaged mixes, etc.)
- Integration with existing merge conflict style configurations

The implementation touches core checkout machinery (`builtin/checkout.c`), sequencer autostash handling (`sequencer.c`), and adds extensive tests. Documentation updates explain the new behavior for both `git checkout` and `git switch`.

This represents the culmination of a long review process with input from Phillip Wood and Junio Hamano, now merged to `next` with all major technical issues resolved. The patch is well-tested and appears ready for final inclusion.
