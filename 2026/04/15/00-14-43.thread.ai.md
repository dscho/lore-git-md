[RFC PATCH] git worktree add --recurse-submodules proposal from JAM, extending worktree object store sharing to submodules via hardlinking modules directories and config adjustments. Prototype shell script demonstrates approach but faces fundamental technical hurdle identified by Phillip Wood and confirmed by Junio C Hamano: shared submodule directories prevent different worktrees from having independent submodule checkouts (different HEADs), which conflicts with Git's worktree model where working state must be isolated while object storage is shared. 

The maintainer consensus solidifies that any viable solution must properly isolate submodule working state across worktrees, not just share object storage. This requires revisiting per-worktree submodule configuration questions avoided in initial proposal. Original motivation was multi-agent development workflows where current submodule support is pain point. References prior discussions with Glen Choo. Open questions now include handling uninitialized submodules, community appetite for feature, and the core design challenge of worktree-specific submodule state isolation. Phillip Wood's expertise in worktree/submodule behavior and Junio's maintainer perspective establish this as the key technical barrier needing resolution in any revision.
