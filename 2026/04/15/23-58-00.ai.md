This is the first patch in a 3-part series refining the new `git backfill` command, which handles object pre-fetching in partial clone scenarios. The patch comes from Elijah Newren, known for his deep Git expertise.

The patch adds explicit rejection of several `rev-list` options that would be silently ignored or counterproductive when used with `git backfill`. These include diff-filtering options (-S/-G, --diff-filter), file-following (--follow), line-log (-L), diff-merge controls, and object filtering (--filter). The command's path-walk approach bypasses the mechanisms these options rely on, so accepting them could mislead users into thinking their filtering is being honored when it isn't.

The implementation adds a new `reject_unsupported_rev_list_options()` function that checks for these cases and dies with clear error messages. The changes are focused on the command's safety and correctness rather than adding new functionality. The patch includes straightforward C code changes in builtin/backfill.c with no test additions (likely covered by the existing t5620-backfill.sh tests mentioned in the cover letter).

This appears to be a well-justified safety measure for the new command, preventing subtle misuse cases that could lead to incomplete backfilling. The error messages will help users understand why certain options they might expect to work are actually incompatible with the command's design.
