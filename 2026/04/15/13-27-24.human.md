This is the final version (v15) of a feature patch series implementing Linux filesystem monitoring (fsmonitor) support via inotify, now approved for integration by Junio Hamano. The series brings comprehensive cross-platform fsmonitor support to Git, completing the implementation with Linux alongside existing macOS and Windows backends.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The series has undergone extensive testing across 15 iterations.

Changes in v15 focus on test suite fixes:
- Replaces problematic `test_might_fail maybe_timeout` wrapper with `{ ... || :; }` pattern to maintain proper &&-chain behavior while preserving the 30s timeout
- Follows suggestions from SZEDER Gábor and Jeff King to harden test infrastructure

The series demonstrates thorough engineering with attention to edge cases (stale renames, watch limits, remote filesystems) and platform compatibility (Windows pthread emulation). It builds on prior work from Eric DeCosta and Marziyeh Esipreh, now addressing all substantive review feedback. The implementation appears production-ready, having been tested for months in various environments.

This represents the completion of a major cross-platform feature, with Linux being the last major platform to gain native fsmonitor support. The careful handling of technical constraints and thorough test coverage make this a high-quality contribution ready for inclusion in Git.
