This is a test infrastructure patch in Patrick Steinhardt's ongoing series to enable `set -e` (errexit) in Git's test suite. The patch modifies several test scripts to handle cases where `git config --unset` fails because the configuration being unset doesn't exist - a common cleanup pattern that would cause tests to fail under `set -e`.

The changes are mechanical but important: each `git config --unset` call that might fail is followed by `|| :` to ensure the test continues even if the unset operation fails. This affects three test scripts that deal with diff context configuration, status output coloring, and SVN author mapping. The changes follow the pattern established earlier in the series for robust error handling.

This patch is part of a well-motivated effort to make the test suite more reliable by catching errors that would otherwise be silently ignored. The changes are straightforward and unlikely to be controversial, though reviewers will want to verify they don't mask any real problems in the tests. The patch fits cleanly into the series' goal of preparing the test suite for stricter error checking.
