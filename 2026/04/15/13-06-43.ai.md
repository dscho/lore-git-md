This is a test infrastructure fix in Patrick Steinhardt's ongoing series to enable `set -e` in Git's test suite. The patch specifically addresses t6002-rev-list-bisect.sh, where the test helper `test_bisection_diff()` uses `expr` for arithmetic operations that can fail when the result is zero - a behavior that would break under `set -e`.

The change replaces `expr` with shell arithmetic (`$(( ))`), which doesn't have the same failure modes. The patch also modernizes the test formatting by moving the test expectation to a multi-line format. This is part of the broader effort to make test infrastructure robust under `set -e` by eliminating commands that could fail for expected conditions.

The change is mechanical and low-risk, following the established pattern of the series. It touches only test code and doesn't affect production behavior. Reviewers will want to verify the arithmetic logic remains correct, though the transformation is straightforward. This continues the careful, systematic approach seen in earlier patches of the series.
