This is a feature patch in the ongoing autostash series, adding customization options for conflict markers during autostash application. It's part 3 of a 5-patch post-merge refinement series following the main autostash functionality that was already merged.

The patch extends `apply_autostash_ref()` to accept optional parameters for customizing conflict marker labels (`label_ours`, `label_theirs`, `label_base`) and stash messages. These parameters propagate through to the underlying `git stash apply` command, allowing users to specify more descriptive labels when conflicts occur during branch switching operations. The changes maintain backward compatibility by making all new parameters optional (defaulting to NULL).

The implementation touches several key files - `sequencer.c` gets the main logic changes, while `builtin/commit.c` and `builtin/merge.c` are updated to pass NULL for the new parameters to maintain existing behavior. This is a well-contained change that builds on the established autostash infrastructure, showing the iterative refinement process where core functionality merges first and customization options follow.
