This is a memory leak fix in the fsmonitor daemon implementation, part of the larger cross-platform filesystem monitoring series that has been through 15 iterations. The patch addresses a resource management issue where the `state.cookies` hashmap and its allocated strings were not being freed during daemon shutdown.

The fix adds cleanup code to the `done:` label in `fsmonitor_run_daemon()`, iterating through the hashmap to free each cookie name string before clearing the hashmap itself. This completes the resource management for the daemon's cookie tracking system, which is used for rename operation tracking.

The change is straightforward and mechanical - it follows the established pattern for hashmap cleanup in Git's codebase. Since this is part of a well-tested series that has already received maintainer approval, the fix can be considered low-risk and necessary for proper daemon operation. The patch maintains the series' high standard of resource management, addressing one of the final edge cases in the implementation.
