This is a test infrastructure patch in Patrick Steinhardt's ongoing series to enable `set -e` (errexit) in Git's test suite. The patch focuses on fixing conditional execution patterns that would fail under `set -e` by converting them to proper `if` conditionals.

The changes systematically update test scripts and library functions that check for command availability (like `svn`, `cvs`, and `git` itself) or handle expected failures. Key technical changes include:
- Replacing direct command execution with `if ! cmd` patterns in prerequisite checks
- Using the established `ret=0; cmd || ret=$?` pattern for error handling
- Updating test helper functions like `test_might_fail()` and `test_expect_code()`
- Fixing test cases that verify exit codes (t7422, t5000)

The patch continues the series' careful approach to error handling, building on prior work that addressed daemon management, config cleanup, and test assertions. It demonstrates consistent application of the `set -e` preparation patterns across multiple test components. The changes are mechanical but important for the eventual goal of enabling strict error checking in the test suite.

This iteration shows the series maturing as it addresses more subtle cases where tests intentionally execute commands that may fail. The changes maintain compatibility while preparing for stricter error handling, particularly in modern CI environments that use Bash 5+.
