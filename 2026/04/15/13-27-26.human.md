This is a bugfix patch in the fsmonitor series, addressing a memory leak in the daemon's client handling code. The patch fixes a case where a khash table used for tracking shown paths wasn't being freed when the client received a trivial response, due to the cleanup code being placed after an early return path.

The change is straightforward: it initializes the hash table pointer to NULL and moves the cleanup to a shared exit path that's always reached. This ensures the hash table is properly freed regardless of which code path is taken. The fix demonstrates good attention to resource management in the fsmonitor daemon, which is particularly critical for long-running processes.

This patch is part of the larger fsmonitor implementation that has already gone through extensive review (15 iterations) and received maintainer approval. The memory leak being fixed here was likely caught during final testing of the series.
