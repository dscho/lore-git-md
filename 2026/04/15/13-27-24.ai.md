This is the final version (v15) of a feature patch series implementing Linux filesystem monitoring (fsmonitor) support via inotify, now approved for integration by Junio Hamano. The series brings comprehensive cross-platform fsmonitor support to completion, adding Linux alongside existing Windows and macOS implementations.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The series has undergone extensive testing across 15 iterations.

Changes in v14->v15 focus on test suite robustness:
- Fixed a test_might_fail/maybe_timeout interaction that broke &&-chains in t7527
- Applied Jeff King's suggestion to add curly braces around the timeout helper for defensive programming
- Maintains all core functionality from previous versions:
  - Process isolation with FD cleanup and session detachment
  - Daemon shutdown timeout (30s) with 50ms polling
  - Windows compatibility via pthread emulation
  - Linux inotify implementation with edge case handling
  - Path deduplication using strset (replacing khash)
  - Comprehensive test coverage

The series represents production-ready fsmonitor support across all major platforms, having addressed all substantive review feedback and test suite issues identified during its 15-iteration development. With maintainer approval and all test validations passing, this is now ready for integration.
