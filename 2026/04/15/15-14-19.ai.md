This is a feature proposal for Git's fetch/push negotiation system, part of a 7-patch series from Derrick Stolee that introduces new options to control which refs are prioritized during negotiation. The series addresses a real-world monorepo scaling issue where important long-lived branches were being truncated from negotiation due to protocol limits.

The key changes in this cover letter (v2) include:
- Renaming the main option from `--must-have` to `--negotiation-require` for better alignment with existing terminology
- Adding a new `--negotiation-restrict` option as a synonym for `--negotiation-tip` to clarify its restrictive behavior
- Introducing corresponding config options (`remote.*.negotiationRequire` and `remote.*.negotiationRestrict`)
- Supporting these options in both fetch and push operations (when `push.negotiate` is enabled)

The implementation spans multiple files including `builtin/fetch.c`, `fetch-pack.c`, and the transport layer, with thorough test coverage. The changes allow users to specify critical refs that should always be included in negotiation while still allowing the algorithm to opportunistically include other refs - solving the monorepo problem where certain branches (like 'main' and 'release') need guaranteed inclusion but shouldn't completely dominate negotiation.

The series appears well-motivated and carefully implemented, with Stolee responding to earlier feedback by adjusting terminology and interface design. The core functionality remains uncontested, with discussion now focused on naming and configuration details rather than technical approach.
