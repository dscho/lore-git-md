This is part 10/13 of the fsmonitor feature series, focusing on process isolation improvements for the filesystem monitoring daemon. The patch enhances daemon startup by addressing two key issues: inherited file descriptors and process group management.

The changes ensure the daemon properly cleans up when spawned either explicitly via `fsmonitor--daemon start` or implicitly when clients detect no running daemon. The implementation now closes all inherited file descriptors above stderr (FD 2) via a new `close_fd_above_stderr` flag in `struct child_process`, preventing hangs when parent processes wait on inherited pipe endpoints. The patch also adds `setsid()` calls on Unix systems when detaching, preventing the daemon from blocking shell job control.

The solution handles both Windows (via `FreeConsole()`) and Unix platforms, with careful attention to maintaining existing functionality while adding these isolation guarantees. The changes are minimal but important for robust daemon operation, particularly in CI/test environments where inherited file descriptors are common. This builds on the series' cross-platform approach, complementing earlier work on Linux inotify support and Windows compatibility.
