This is a feature patch in the fsmonitor series, specifically addressing timeout handling for cookie waits in the filesystem monitoring daemon. It's part of the larger cross-platform fsmonitor implementation that has undergone extensive review over 15 iterations.

The patch replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()` in the cookie wait mechanism. This prevents indefinite hangs when filesystem events aren't delivered (a known issue on some container/overlay filesystems). On timeout, it logs the event and falls back to a full scan rather than blocking forever.

Key technical details:
- Uses `gettimeofday()` and `timespec` to implement the timeout
- Preserves the existing cookie tracking infrastructure while adding timeout logic
- Maintains the same error reporting through the `FCIR_ERROR` result code
- Adds trace logging for timeout events
- The change is part of making fsmonitor robust across different filesystem types
- Follows the pattern of defensive programming seen throughout the series
- Builds on the existing pthread-based synchronization in the daemon

The patch represents a focused improvement to the Linux inotify implementation, addressing a specific edge case while maintaining the core functionality that has already been extensively reviewed. It's one of the final pieces in the comprehensive fsmonitor support that has now received maintainer approval.
