This is part 4/7 of Derrick Stolee's series introducing negotiation controls for fetch/push operations, focusing on monorepo scaling. The patch adds a new `remote.<name>.negotiationRestrict` config option that serves as the configuration counterpart to the `--negotiation-restrict` command-line flag introduced earlier in the series.

The config option allows users to persistently specify which refs should restrict the negotiation scope for a given remote, with the same as the CLI flag (exact refs or glob patterns). The implementation spans `remote.c` (for config handling), `builtin/fetch.c` (for applying the config defaults), and includes new test cases in `t/t5510-fetch.sh` verifying both the config behavior and its interaction with command-line overrides.

Key technical details:
- The config is multi-valued and stored in a new `negotiation_restrict` string list in the `remote` struct
- Config values are ignored if any `--negotiation-restrict` arguments are provided on the command line
- Includes proper warning when the transport protocol doesn't support negotiation restrictions
- Moves the `--negotiate-only` validation to after config processing
- Adds test cases for both basic config usage and CLI override behavior

The patch maintains the series' focus on providing dual control points (required refs via `negotiationRequire` and restricted scope via `negotiationRestrict`) while keeping the implementation clean and well-tested. It follows naturally from the earlier CLI work and shows good attention to edge cases like protocol support and config/CLI precedence.
