This thread focuses on modernizing Git's test suite to work correctly when `set -e` is enabled, part of a larger effort by Patrick Steinhardt (v2 01/12). The current patch specifically addresses signal-handling tests that verify Git's behavior when receiving SIGPIPE. It updates three test cases across `t/t0005-signals.sh` and `t/t3600-rm.sh` to use a more robust pattern for capturing exit codes when commands terminate due to signals. The changes are mechanical infrastructure improvements that don't modify Git's functionality but make the tests more reliable under stricter shell conditions. This work appears to enable broader use of `set -e` in the test suite in subsequent patches of the series.
