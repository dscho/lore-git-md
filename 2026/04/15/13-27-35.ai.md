This is part of the fsmonitor feature series (patch 11/13) implementing cross-platform filesystem monitoring support. The patch adds a timeout mechanism to the daemon stop command to prevent indefinite hangs if the fsmonitor daemon fails to shut down properly.

The change introduces a 30-second timeout (30000ms) with 50ms polling intervals when waiting for the daemon to exit after sending a quit command. If the daemon remains in the LISTENING state beyond the timeout, the command will error out rather than blocking forever. The implementation tracks elapsed time and includes trace2 regions to monitor the shutdown process.

This builds on the series' existing IPC and process management infrastructure, using the same 50ms polling interval seen elsewhere in the fsmonitor implementation. The timeout value appears consistent with other timing parameters in the series (like the 1-second cookie wait timeout added in earlier patches). The change addresses a real-world reliability concern while maintaining the careful resource management seen throughout this well-tested series.
