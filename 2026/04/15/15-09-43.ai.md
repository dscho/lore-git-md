Feature addition to `git cat-file`'s batch mode, now finalized for merging.

This patch from Siddharth Asthana adds dynamic mailmap toggling to `git cat-file --batch-command`, allowing mailmap behavior to be changed mid-operation without restarting the process. The implementation introduces a `mailmap <bool>` subcommand that accepts standard Git boolean values (yes/no, true/false, on/off) and is primarily motivated by GitLab Gitaly's need to reuse long-running processes.

The technical implementation handles mailmap data with lazy loading - data is loaded on first use and kept in memory, with subsequent toggles to "true" reusing the cached data. The changes are well-contained to `builtin/cat-file.c` and include comprehensive test coverage in `t/t4203-mailmap.sh` that verifies:
- Runtime toggling between enabled/disabled states
- Interaction with startup options (`--mailmap`/`--no-mailmap`)
- Support for all boolean value formats
- Proper error handling for invalid inputs
- Correct behavior in buffered mode

The patch has gone through multiple review iterations with feedback incorporated from Junio Hamano (documentation and code clarity), Patrick Steinhardt (boolean parsing), Karthik Nayak (documentation simplification), and Jean-Noël Avila (AsciiDoc formatting). The documentation clearly explains the interface behavior, including the subtle difference from Git config syntax where the argument cannot be omitted to mean "true".

With all review feedback addressed and consensus established, this well-tested and clearly documented feature is ready for merging into Git's mainline. The implementation solves the original use case while maintaining clean code organization and performance through in-memory caching.
