This is a documentation patch in Elijah Newren's 3-part series refining the new `git backfill` command. The series follows up on the initial introduction of `backfill` in the current development cycle.

The patch standardizes how revision range arguments are documented for `git backfill` to match Git's conventions. Currently, the man page uses informal prose to mention rev-list options, unlike other commands that formally declare `<revision-range>` in the synopsis and options sections. The change makes the documentation more consistent with commands like `git log` and `git replay`.

The patch updates both the synopsis and OPTIONS section to properly document the revision range parameter, including a reference to gitrevisions(7) for range syntax details. It also clarifies that rev-list options like `--first-parent` and `--since` are accepted. The builtin's usage message is updated to match.

This is a straightforward documentation improvement that brings the new command in line with established patterns. The change is mechanical but important for consistency. As the second patch in the series, it follows the safety checks added in patch 1 and precedes the behavior tweak for blob downloading coming in patch 3.
