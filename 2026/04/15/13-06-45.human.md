This is the final patch in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite, specifically targeting Bash 5+ environments. The change modifies `t/test-lib.sh` to automatically enable `set -e` when running under modern Bash versions, causing the test suite to abort immediately if any command outside a test case fails unexpectedly.

The motivation comes from a real incident where a typo in `test_expect_success` went undetected because failures outside test cases were silently ignored. The patch takes a conservative approach by only enabling this for Bash 5+, acknowledging that shell behavior varies too much across platforms (especially older Bash versions like macOS's 3.2.57) to make this universally applicable.

This change builds on the extensive preparatory work in the previous 11 patches, which systematically hardened test infrastructure components to work correctly with `set -e`. The series represents a pragmatic compromise between improved error detection and platform compatibility, focusing first on modern CI environments while leaving the door open to expand support to other shells in the future.
