This is a feature patch implementing Linux filesystem monitoring (fsmonitor) support via inotify, part of a 15-patch series that has now been approved for integration by Junio Hamano. The patch brings comprehensive cross-platform fsmonitor support to completion, adding Linux alongside existing Windows and macOS implementations.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The patch adds three new files under compat/fsmonitor/ for Linux-specific implementations of the health monitoring, event listening, and path utilities.

The implementation includes several notable features:
- Uses inotify_init1(O_NONBLOCK) with 50ms poll timeout
- Bidirectional hashmaps between watch descriptors and directory paths
- Cookie-based rename tracking with timeout handling
- Recursive watch registration for new directories
- Remote filesystem detection via statfs() and /proc/mounts
- Comprehensive error handling and resource cleanup

Documentation is included explaining Linux-specific caveats around inotify watch limits and how to increase them. The patch also updates existing documentation to reflect that socket directory handling applies to Linux as well as macOS.

This represents the production-ready Linux component of fsmonitor, completing the cross-platform support after extensive testing and review across 15 iterations. The implementation is careful to handle edge cases like stale renames, watch limits, and remote filesystems while maintaining compatibility with the existing fsmonitor architecture.
