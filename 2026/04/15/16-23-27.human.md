Maintainer perspective on worktree submodule challenges. Junio C Hamano weighs in on JAM's RFC for `git worktree add --recurse-submodules`, agreeing with Phillip Wood's critique about the fundamental limitation of sharing submodule state across worktrees. While acknowledging he's not a submodule user himself, Junio concurs that submodules would need independent worktree state (like separate HEADs) when their superproject uses multiple worktrees, since each superproject worktree may need different submodule checkouts. 

This reinforces Phillip's earlier technical objection that the current proposal's approach of sharing the modules directory prevents this necessary isolation. Junio's brief but authoritative comment suggests the RFC will need to address this core design challenge before moving forward - any solution must allow submodules to maintain per-worktree state while still leveraging shared object storage where possible. The maintainer's agreement with the critique signals this is a substantive blocker that the proposal's next iteration will need to resolve.
