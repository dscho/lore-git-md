This is the thirteenth iteration of a feature patch series that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The series has already been merged to the `next` branch and is now in its final polishing phase, addressing both process improvements and technical refinements.

The main change in v13 is a restructuring of the autostash functionality to better integrate with the existing merge machinery. The series now:
1. Adds `--label-ours`, `--label-theirs`, and `--label-base` options to `git stash apply` for custom conflict markers
2. Allows silent autostash creation during operations with branch-specific messages
3. Improves error handling in `merge_working_tree()` with proper lock rollback
4. Implements the core autostash behavior for `checkout -m` that stashes changes before attempting a merge and reapplies them afterward

The implementation spans multiple components (`builtin/checkout.c`, `builtin/stash.c`, `sequencer.c`) and includes comprehensive test coverage. Key technical details include:
- New `create_autostash_ref()` and `apply_autostash_ref()` functions that handle both silent operation and conflict marker labels
- Proper lockfile management in `merge_working_tree()` to prevent resource leaks
- Conditional autostash application based on whether a stash was actually created
- Integration with the existing merge conflict resolution machinery

The series builds on prior work merged in v12, with this version focusing on final refinements suggested by reviewers Phillip Wood and Junio Hamano. The changes demonstrate Git's culture of post-merge refinement, with careful attention to error handling patterns and test infrastructure improvements.
