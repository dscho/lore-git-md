This is a feature patch adding customizable conflict marker labels to `git stash apply`, part of a larger series that was recently merged implementing autostash behavior for conflicted checkouts. The patch allows users to specify custom labels (via `--label-ours`, `--label-theirs`, and `--label-base`) for the conflict markers that appear when applying a stash with conflicts, rather than the default "Updated upstream"/"Stashed changes" text.

The implementation touches the stash command's documentation, core application logic in `builtin/stash.c`, and the xdiff merge machinery, with new tests verifying the behavior. The changes are cleanly scoped and well-tested, building on the existing conflict marker infrastructure. This appears to be a polished addition that follows the pattern established in other merge operations while giving users more control over their conflict resolution workflow.

The patch comes from Harald Nordgren, who has been working on this autostash series with extensive review from Phillip Wood. It's now in the post-merge refinement phase where test improvements are being added after the core functionality was accepted. The changes look solid and address a specific user-facing need in a way that's consistent with Git's existing conflict resolution tools.
