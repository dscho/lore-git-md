This is a test infrastructure patch series from Patrick Steinhardt that aims to make Git's test suite more robust by enabling `set -e` (errexit) to catch errors outside of test cases. The series has evolved based on feedback and testing, with v2 narrowing the scope to only enable `set -e` for Bash 5+ in modern CI environments after discovering platform-specific quirks, particularly with macOS's outdated Bash 3.2.57.

The 12 patches systematically prepare various test helper functions and existing tests to work correctly with `set -e` enabled. Changes include fixing signal handling in test helpers, adjusting test cleanup routines, and addressing specific test cases that would fail with strict error checking. The series demonstrates careful attention to cross-platform compatibility, with fixes for FreeBSD and explicit handling of shell behavior differences.

The approach is pragmatic - rather than forcing universal adoption of `set -e` across all platforms, it focuses on reliable environments where the benefits can be realized without brittleness. The changes are mechanical but important for test reliability, continuing Git's ongoing effort to improve test robustness. Reviewers will want to verify the error handling changes don't introduce false positives, though the author has already validated the changes against both Bash and Dash.

This represents a significant step forward in making the test suite more reliable by catching errors that would otherwise be silently ignored, while thoughtfully navigating the realities of cross-platform shell behavior.
