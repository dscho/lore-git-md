This is a feature patch in the fsmonitor series, adding process isolation improvements by closing inherited file descriptors in child processes. The patch introduces a new `close_fd_above_stderr` flag in `struct child_process` that, when set, causes the child to close all file descriptors above stderr (FD 2) between fork and exec, while preserving the child-notifier pipe. The implementation caps the scan at the minimum of `sysconf(_SC_OPEN_MAX)` or 4096 for efficiency.

The change is part of the broader fsmonitor effort to ensure clean process isolation, particularly important for the filesystem monitoring daemon that runs as a long-lived background process. The patch follows standard Git conventions for child process handling and includes documentation of the new field in the header file. This is a low-level plumbing change that enables the fsmonitor daemon to avoid inheriting potentially problematic file descriptors from its parent process (such as test harness pipes), while maintaining the existing child notification mechanism.
