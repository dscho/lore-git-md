This is part 6/7 of Derrick Stolee's series introducing negotiation controls for fetch/push operations, focused on adding config option support. The patch adds `remote.<name>.negotiationRequire` as a configuration counterpart to the `--negotiation-require` command-line option introduced earlier in the series.

The config option works exactly like its CLI counterpart - specifying refs (either exact names or glob patterns) that should always be included in negotiation - but provides a persistent default. The implementation mirrors the existing `negotiationRestrict` config handling, with CLI flags taking precedence over config values. The patch includes thorough documentation updates and tests verifying the config works with glob patterns and respects the CLI override behavior.

This completes the configuration story for the negotiation control system, complementing the CLI interface work from earlier patches. The implementation is clean and consistent with existing patterns, with careful attention to edge cases like protocol support warnings. As with the rest of the series, this appears well-considered and addresses a clear need for monorepo workflows where certain branches need guaranteed inclusion in negotiation.
