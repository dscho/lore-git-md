This is a bugfix and feature enhancement patch that completes the implementation of autostash behavior for `git checkout -m`. The patch is part of a long-running effort (16 iterations) to improve conflict handling during branch switching, with extensive review input from Phillip Wood and Junio C Hamano.

The core change makes `checkout -m` automatically stash local changes when switching branches with conflicts, then reapply them after the switch. If the reapplication fails due to conflicts, the stash is preserved with clear instructions for recovery. This matches the behavior already present in `git rebase --autostash` and `git merge --autostash`.

Key improvements in this version:
- Proper handling of lockfiles during merge failures
- Clearer user messaging about conflict resolution options
- More robust test coverage for edge cases
- Integration with existing conflict style configurations
- Preservation of the stash when conflicts occur during reapplication

The patch touches several areas:
- Documentation updates for `git-checkout` and `git-switch` man pages
- Core checkout logic in `builtin/checkout.c`
- Stash application handling in `sequencer.c`
- New test cases in `t7201-co.sh` covering various conflict scenarios
- Conflict style infrastructure in `xdiff-interface`

This represents the final piece of a well-tested feature that makes conflicted branch switching more user-friendly while maintaining safety. The implementation looks solid, with thorough test coverage and careful attention to edge cases. The patch series has gone through extensive review and iteration, with this version addressing all outstanding feedback.
