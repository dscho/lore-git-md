This is a test fix for the fsmonitor series, specifically addressing an incompatibility between Scalar's default `index.skipHash` setting and split-index mode. The patch is part of the now-approved v15 series implementing comprehensive filesystem monitoring support.

The issue arises because Scalar's use of `index.skipHash` (which avoids computing index checksums) interacts poorly with split-index mode - the shared index ends up with a null OID and fails to reload properly, triggering a BUG in fsmonitor when the dirty bitmap references more entries than the index contains. 

The fix disables `GIT_TEST_SPLIT_INDEX` in the affected Scalar clone tests (tests 12, 13, and 22 in t9210, plus all of t9211) to prevent this interaction. This matches an existing workaround already present in test 16 of t9210. The changes are straightforward - just adding `sane_unset GIT_TEST_SPLIT_INDEX` at the appropriate points in the test scripts.

As part of the final fsmonitor series that has already received maintainer approval, this patch represents a minor but necessary test adjustment to ensure compatibility between these features. The core fsmonitor functionality remains unchanged.
