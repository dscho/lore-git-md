This is a feature proposal to add `--recurse-submodules` support to `git worktree add`, reviving a discussion from 2022. The patch would enable creating worktrees that properly handle submodules by hardlinking the object store and updating configuration, without tackling the thornier issues of per-worktree submodule configuration.

The author identifies a concrete use case in multi-agent development workflows where current worktree behavior breaks down with submodules. The proposed implementation would share submodule objects via hardlinks (like the main worktree already does) while ensuring each worktree gets its own working directory state. Some edge cases around uninitialized submodules and worktreeConfig extension handling remain to be decided.

The email references prior discussions from Glen Choo and others about the complexities of submodule/worktree interaction, positioning this as a pragmatic solution that avoids the hardest configuration questions. An attached shell script demonstrates the approach works in practice. The author is gauging interest before investing in a proper patch series.
