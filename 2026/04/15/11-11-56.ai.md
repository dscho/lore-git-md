This is a bugfix patch in the final polishing phase of a merged series that enhances `git checkout -m` with autostash behavior. The patch addresses a resource leak in `merge_working_tree()` where early returns would leave the index lock held. While currently harmless since the process exits soon after, this could cause problems if the function were called multiple times in the same process.

The change adds `rollback_lock_file()` calls to all early return paths in `merge_working_tree()`, ensuring proper lock cleanup. The patch touches `builtin/checkout.c` with 22 lines added and 7 removed across several conditional blocks. Each error path now properly releases the lock before returning.

This is a straightforward cleanup that improves the robustness of the already-merged autostash functionality. The change follows Phillip Wood's earlier review feedback about proper error handling and resource management. The patch maintains the existing behavior while fixing the lock management, demonstrating Git's culture of post-merge refinement.
