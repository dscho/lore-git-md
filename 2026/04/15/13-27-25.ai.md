This is a test patch in the fsmonitor series, specifically addressing an incompatibility between Scalar's default `index.skipHash` setting and split-index functionality. The patch disables `GIT_TEST_SPLIT_INDEX` in Scalar clone tests to prevent a BUG assertion in fsmonitor when the shared index gets a null OID.

The issue occurs because Scalar clone's `index.skipHash` skips computing the hash, resulting in a null OID for the shared index. When this empty index is re-read, it fails to load while fsmonitor's dirty bitmap still references entries, triggering an assertion. The fix unset `GIT_TEST_SPLIT_INDEX` in affected tests (t9210 tests 12, 13, 22 and all of t9211) to avoid this conflict.

This is a straightforward test adjustment that follows the pattern already established in t9210 test 16. The change is minimal and focused, with clear commit message explaining the incompatibility and rationale for the fix. As part of the larger fsmonitor series that has already received maintainer approval, this patch appears ready for integration.
