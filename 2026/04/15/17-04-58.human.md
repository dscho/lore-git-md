Feature patch refining progress reporting tests for `git backfill`.

Tian Yuchen provides review feedback on Trieu Huynh's v2 patch adding progress reporting to the experimental `git backfill` command. The comments focus on test improvements, suggesting two key changes: reducing redundant repository cloning in the test cases, and clarifying what output should be suppressed by `--no-progress`.

The review notes that each test currently clones a fresh repository unnecessarily, when reusing a single clone would suffice. More importantly, it questions whether `--no-progress` should suppress just the backfill progress meter or all output (including fetch output), pointing out that the current test only checks for the progress message while potentially missing other output that should also be suppressed.

This appears to be thoughtful feedback from an engaged reviewer, identifying concrete ways to improve the test coverage. The suggestions would make the tests both more efficient (avoiding redundant setup) and more thorough (better verifying the intended suppression behavior). The patch author will need to decide whether to address these in v3, particularly the question of what exactly `--no-progress` should cover in this context.
