This is the third and final patch in Elijah Newren's series refining the new `git backfill` command, which optimizes partial clone operations by pre-fetching objects. The patch focuses on blob handling behavior.

The change introduces a new `--[no-]include-edges` flag that controls whether blobs from boundary commits (like the 'A' in 'A..B' ranges) should be included in the backfill. The flag defaults to `--include-edges` because several common commands (`git log -p`, `git replay`, and `git merge`) need these edge blobs to avoid on-demand fetching later. The patch includes thorough test coverage in t/t5620-backfill.sh demonstrating how the flag affects blob fetching behavior across these use cases.

The implementation adds a new `include_edges` field to `struct backfill_context` that sets `revs.edge_hint` when true, and updates both documentation and the command's usage message. The tests verify that with edge inclusion enabled, operations like `git log -p` can run without triggering additional fetches, while disabling it (with `--no-include-edges`) causes the expected on-demand fetches when those operations need the missing edge blobs.

This completes the series that began with safety checks for `rev-list` arguments and documentation improvements. The change is well-motivated by real-world partial clone scenarios and maintains the command's focus on preventing disruptive on-demand fetching. The test coverage is particularly thorough, exercising the new behavior through multiple realistic workflows.
