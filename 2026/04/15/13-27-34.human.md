This is a process isolation patch in the fsmonitor series, focusing on cleaning up inherited file descriptors and detaching the daemon process properly. It's part of the larger cross-platform filesystem monitoring implementation that has gone through 15 iterations and received maintainer approval.

The patch addresses two specific issues that can occur when the fsmonitor daemon is spawned:
1. It closes all file descriptors above stderr (FD 2) that might have been inherited from the parent process, preventing hangs when test harnesses or CI systems use pipes to capture output.
2. It properly detaches the daemon process on both Windows (via `FreeConsole()`) and Unix (via `setsid()`) to prevent the spawning shell from waiting indefinitely for the daemon to exit.

The changeset is straightforward - it adds the `close_fd_above_stderr` flag to both explicit and implicit daemon startup paths, and ensures proper session detachment. The implementation is careful to maintain compatibility across platforms while solving real-world issues seen in testing environments.

This patch represents the final polish on the fsmonitor daemon's process management, complementing the core monitoring functionality that was stabilized in earlier iterations. The changes are well-considered and unlikely to be controversial given the extensive review history of the overall series.
