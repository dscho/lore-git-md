This is part of the fsmonitor feature series, specifically addressing daemon shutdown behavior. Patch 11/13 in the v15 series adds a 30-second timeout to the `fsmonitor--daemon stop` command, preventing indefinite hangs if the daemon fails to shut down properly.

The change modifies the polling loop that waits for daemon termination after sending a quit command. Previously this could spin forever if the daemon was stuck. The new version tracks elapsed time and returns an error if the 30-second limit is reached, while still preserving the existing IPC state checking and trace2 instrumentation.

This is one of the final pieces in a long-running effort to implement robust cross-platform filesystem monitoring support. The timeout mechanism works consistently across platforms, building on earlier work that added Windows-compatible pthread emulation. The patch follows the series' established pattern of defensive programming while maintaining the existing error reporting structure.
