Junio Hamano raises an important configuration design question in response to Derrick Stolee's patch adding `remote.*.negotiationRestrict` config. While the patch itself is sound, Junio points out a potential issue with multi-valued config inheritance across different config files (system, global, local).

The core concern is that there's no clear way to "reset" a multi-valued config when it's set in a higher-priority file (like system config) but needs to be overridden in a lower-priority file (like repo config). Junio suggests two possible solutions: either restrict the config to local-only use (simpler but less flexible), or introduce a syntax to explicitly clear inherited values (more powerful but requires framework changes).

This isn't a blocking concern for the patch - the implementation works as designed - but Junio is flagging a broader configuration system limitation that affects how this feature (and similar multi-valued configs) will behave in practice. The discussion may lead to follow-up work on Git's config handling infrastructure.
