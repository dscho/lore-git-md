This is a test patch in the fsmonitor series, adding Linux-specific test coverage for the new inotify-based filesystem monitoring implementation. It's part of a larger 15-patch series that has already been approved for integration by Junio Hamano.

The patch adds several test scenarios:
- A smoke test that verifies the filesystem actually delivers inotify events (skipping all tests if not)
- A stress test for rapid nested directory creation to catch EEXIST race conditions
- Process group handling improvements for submodule tests
- Timeout reductions from 60 to 10 seconds for faster test feedback
- Robustness improvements for environments without procps (falling back to /proc/$pid/stat)
- Error redirection cleanup to avoid noise from already-exited processes

The changes focus on hardening the test infrastructure while maintaining all the core functionality from previous versions. The test additions complement the Linux implementation's technical components (inotify with recursive watches, cookie wait timeouts, and mount point detection) that were established in earlier patches of the series.

This represents the final test coverage needed for the production-ready fsmonitor support across all major platforms, with all substantive review feedback addressed over the 15-iteration development cycle. The patch maintains consistency with the series' focus on robust cross-platform support and comprehensive edge case handling.
