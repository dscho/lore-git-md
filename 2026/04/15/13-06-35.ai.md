This is a test infrastructure change, part of Patrick Steinhardt's ongoing series to enable `set -e` (errexit) in Git's test suite. The patch modifies the `test_must_fail()` helper function to work correctly when the test suite runs with `set -e` enabled.

The key change replaces direct command execution with a pattern that captures the exit code without triggering `set -e` termination: `exit_code=0; "$@" 2>&7 || exit_code=$?`. This ensures the function can properly test commands that are expected to fail, even when the overall test script is running with strict error checking enabled.

The modification is mechanical but important for maintaining test reliability as the suite transitions to stricter error handling. Reviewers should verify the change doesn't introduce false positives in failure detection, though the pattern is well-established in shell scripting for this purpose. This patch exemplifies the careful, incremental approach needed when modifying core test infrastructure that hundreds of tests depend on.
