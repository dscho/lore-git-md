This is a post-merge refinement patch in the ongoing autostash feature series for `git checkout -m`. The patch finalizes the implementation of automatic stashing during conflicted branch switches, addressing resource management and improving user messaging.

The key changes in this version are:

1. Complete lockfile handling in `merge_working_tree()` to ensure proper cleanup on all early return paths
2. Enhanced conflict messaging that clearly explains recovery options when autostash application fails
3. Documentation updates in `git-checkout.adoc` and `git-switch.adoc` to better explain the autostash behavior
4. New test cases in `t7201-co.sh` covering:
   - Various conflict scenarios (staged/unstaged changes, overlapping/non-overlapping modifications)
   - Conflict style handling (diff3/zdiff3)
   - Stash message contents and branch references
   - Clean application when changes don't conflict

The implementation now properly handles the full lifecycle of autostash operations during branch switching, including silent creation, application, and conflict recovery. The user experience is improved with clearer error messages that guide users through resolving conflicts or recovering their stashed changes.

This represents the final technical refinement of functionality that was already merged to `next`, showing Git's iterative development process where core functionality lands first and optimizations follow. The patch demonstrates responsiveness to review feedback while maintaining stability of the existing implementation.
