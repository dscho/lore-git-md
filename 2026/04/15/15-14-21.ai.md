This is a refactoring patch in Derrick Stolee's series on fetch/push negotiation controls, introducing a new `--negotiation-restrict` option as a synonym for the existing `--negotiation-tip`. The change clarifies the option's restrictive behavior while maintaining backward compatibility.

The patch makes several key changes:
1. Adds `--negotiation-restrict` as the preferred name for what was previously called `--negotiation-tip`, with identical functionality
2. Updates documentation to indicate the new name is preferred while keeping the old name for compatibility
3. Modifies warning and error messages to use the new terminology and makes them translatable
4. Adds tests verifying the new option works equivalently to the old one, including with glob patterns and when mixed with the legacy option

The implementation touches `builtin/fetch.c`, `builtin/pull.c`, and related test files, with careful attention to maintaining existing behavior while improving clarity. The changes are mechanical but important for setting up the subsequent patches in the series that will introduce complementary `--negotiation-require` functionality.

This patch demonstrates Stolee's characteristic attention to detail in interface design and test coverage, responding to earlier feedback about terminology while keeping the technical solution intact. The changes are straightforward and unlikely to be controversial, serving as an important stepping stone for the more substantive negotiation control features that follow in the series.
