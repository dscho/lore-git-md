Bugfix for `git send-email` hanging when `sendemail.suppresscc` is set without `sendemail.confirm`. 

Siwei Zhang reports that when `sendemail.suppresscc` is configured (e.g., to "bodycc") but `sendemail.confirm` is unset, `git send-email` hangs indefinitely after processing patch headers. The expected behavior would be to either send the email directly or show a confirmation prompt. A simple workaround is to explicitly set `sendemail.confirm` to "always".

The bug appears in Git 2.53.0 and likely affects other recent versions. This looks like a straightforward interaction issue between two configuration options where the code fails to handle the case where one is set and the other isn't. The report includes clear reproduction steps and a workaround, making it easy to verify and fix. Given that `git send-email` is a critical tool for Git contributors, this bug could be quite disruptive for anyone using the suppresscc feature.
