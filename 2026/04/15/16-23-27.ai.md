Maintainer response on worktree submodule proposal. Junio C Hamano weighs in on Phillip Wood's technical critique of JAM's RFC for `git worktree add --recurse-submodules`, agreeing with the key limitation identified. While not a submodule user himself, Junio concurs that shared submodule directories would prevent different worktrees from having independent submodule checkouts - a fundamental requirement for the feature to be useful. 

The response reinforces Phillip's point that submodules bound to a superproject with multiple worktrees would themselves need corresponding worktree-specific state to allow independent checkouts, even while sharing object storage. This aligns with Git's existing worktree model where per-worktree data (like HEAD) is isolated while repository data is shared. 

The exchange solidifies the technical hurdle the proposal must overcome: any solution will need to provide proper isolation of submodule working state across worktrees, not just object sharing. As maintainer, Junio's agreement with Phillip's analysis suggests this concern will need to be addressed before the feature could be considered for merging. The thread now has clear maintainer feedback that the current approach of sidestepping submodule configuration questions may not be viable.
