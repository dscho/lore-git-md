This is a documentation patch in Elijah Newren's 3-part series refining the new `git backfill` command. The patch focuses on standardizing how revision range arguments are documented for the command.

The change aligns `git backfill`'s documentation with Git's conventional style for commands that accept revision ranges. It replaces a prose description of rev-list options with:
1. A formal `<revision-range>` entry in the SYNOPSIS
2. A dedicated OPTIONS section explaining the range syntax
3. A reference to gitrevisions(7) for range specification details
4. A clearer mention of rev-list options like `--first-parent`

The patch also updates the command's usage message in builtin/backfill.c to match. This is a straightforward improvement that brings consistency with how other Git commands document revision arguments, making the behavior more discoverable for users familiar with Git's standard patterns.

As the second patch in the series, it follows the safety check from patch 1 and precedes the blob downloading behavior change in patch 3. The changes are mechanical and unlikely to be controversial, focused purely on documentation clarity rather than functional changes.
