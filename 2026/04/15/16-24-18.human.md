This is a bugfix patch in the ongoing autostash feature series for `git checkout -m`. It addresses a resource management issue where early returns in `merge_working_tree()` could leave the index lock held, which could cause problems if the function is called multiple times in the same process.

The patch adds proper lock rollback calls to all early return paths in `merge_working_tree()`, ensuring the index lock is always released before exiting. While currently harmless since the process exits soon after, this becomes important for future use cases where the function might be called repeatedly.

The changes are mechanical but important for correctness - each early return now properly cleans up the lockfile. This follows up on earlier feedback from Phillip Wood about resource management in this code path. The patch is part of a well-tested series that has already gone through extensive review, with this being a final cleanup item.
