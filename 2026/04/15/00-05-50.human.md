Bugfix addressing inconsistent argument parsing in `git fetch`. 

Alix Brunet reports that `git fetch <url>` silently fails while `git fetch <url> ""` correctly fetches the default branch, noting this behavior is undocumented. The patch appears to identify a genuine inconsistency in argument handling that could confuse users, though it doesn't yet propose a specific fix - it's more of a bug report at this stage. 

This seems like a straightforward usability issue that should be addressed either through documentation (clarifying the expected behavior) or code changes (making the empty-string case work consistently with the no-argument case). The silent failure is particularly problematic as it gives users no indication why their fetch didn't work as expected. Given the simplicity of the reported issue and its potential to trip up users, this seems worth fixing in either the next release's documentation or codebase.
