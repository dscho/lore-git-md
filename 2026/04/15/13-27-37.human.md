This is a refactoring patch in the final version (v15) of the fsmonitor daemon series, converting pathname deduplication from a khash implementation to Git's strset interface. The change was suggested by Patrick Steinhardt in earlier review feedback.

The patch simplifies the code in `do_handle_client()` by replacing the manual khash string set with the higher-level strset API. Since the paths are already interned strings from the batch data, it sets `strdup_strings=0` to avoid unnecessary copies. The functionality remains identical - it still tracks seen paths to eliminate duplicates when sending notifications to clients.

This is a straightforward cleanup that follows the project's preference for using standard Git data structures where possible. The change reduces code complexity while maintaining the same behavior, and comes after extensive testing in previous iterations of the series. With the maintainer's approval already given for the full series, this final technical improvement is ready for integration.
