This is a bugfix patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch is part of a larger 15-iteration effort to implement comprehensive cross-platform fsmonitor support, now approved for integration.

The change replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()` in the cookie wait mechanism. This prevents indefinite hangs when filesystem events fail to be delivered (a known issue on certain container/overlay filesystems). If the timeout fires, the daemon will report an error and allow the client to proceed with a full scan rather than blocking forever.

The implementation carefully handles the timeout calculation and error conditions while maintaining thread safety. The patch includes trace logging for timeout events to aid debugging. This change completes the Windows compatibility work by ensuring robust behavior across all platforms, addressing one of the last remaining edge cases in the fsmonitor implementation.

The patch is well-contained and follows the established pattern of the series, with clear commit message explaining both the problem and solution. It represents a production-ready fix for a real-world issue that could affect users on certain filesystems.
