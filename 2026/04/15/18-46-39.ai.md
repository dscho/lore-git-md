This is a bug report about `git send-email` hanging when certain configuration options are set. The issue occurs when `sendemail.suppresscc` is configured (in this case to "bodycc") but `sendemail.confirm` is not explicitly set. The reporter, Siwei Zhang, provides clear reproduction steps showing the command hangs indefinitely after processing patch headers, with a workaround of explicitly setting `sendemail.confirm`.

The bug appears to be an interaction between these two email-sending configuration options where the lack of explicit confirmation setting causes the process to stall rather than proceeding with sending or prompting for confirmation. The report is well-structured with version information (tested on Git 2.53.0) and demonstrates the problem can be worked around, though the underlying issue remains unresolved.

This looks like a legitimate bug in the email-sending workflow that could affect users relying on the suppresscc feature. The clear reproduction case makes it straightforward to verify, and the workaround provides immediate relief while the root cause is investigated.
