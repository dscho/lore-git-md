Test modernization patch that prepares signal-handling tests for `set -e` compatibility. This is part of a larger series (v2 01/12) from Patrick Steinhardt to make Git's test suite work correctly when `set -e` is enabled.

The patch modifies three test cases that verify Git dies with SIGPIPE (signal 13) under certain conditions. The original tests used `foo; echo $?` syntax which would fail under `set -e` when `foo` terminates with a signal. The new version uses `foo && echo 0 || echo $?` which properly captures the exit code regardless of whether `set -e` is active.

Changes affect:
- Two tests in `t/t0005-signals.sh` that check SIGPIPE behavior
- One test in `t/t3600-rm.sh` that verifies `git rm` handles SIGPIPE correctly

The modifications are mechanical and focused on test infrastructure rather than changing any Git behavior. This appears to be a straightforward improvement to make the test suite more robust when run with stricter shell options. As part of a larger series, it likely enables subsequent patches to safely use `set -e` in more test scripts.
