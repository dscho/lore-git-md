Subject: git send-email hangs with suppresscc=bodycc when confirm is unset
Author: Siwei Zhang
Type: Bug report
Status: Unresolved, workaround available (set sendemail.confirm explicitly)

Core issue: git send-email command hangs indefinitely when sendemail.suppresscc is configured (specifically to "bodycc") while sendemail.confirm is not explicitly set. The process stalls after processing patch headers without proceeding to send or prompt for confirmation. Verified on Git 2.53.0.

Technical details: The bug manifests in the interaction between sendemail.suppresscc and sendemail.confirm configuration options. The suppresscc feature (which controls CC header handling) appears to trigger an unexpected state when the confirmation prompt behavior is left at its default/unset value. The workaround confirms the issue stems from implicit vs explicit configuration states.

Open questions: The root cause of the hang condition needs investigation - whether it's a missing prompt, infinite loop, or blocked I/O state. The email-sending workflow's state machine may need examination where these two options intersect. No patches or proposed fixes have been submitted yet.

Related: This touches the same configuration space as other send-email features like chain reply-to and smtp server selection, though the direct interaction appears limited to suppresscc and confirm options. The bug report stands alone with no prior discussion referenced.
