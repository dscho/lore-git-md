Test modernization patch from Patrick Steinhardt, part of a larger series preparing test scripts for `set -e` compatibility. This specific patch fixes signal-handling tests that would break under `set -e` by changing how exit codes are captured from expected-to-fail commands.

The patch updates three test cases that verify Git dies with SIGPIPE (signal 13) under certain conditions. The original tests used `cmd; echo $?` to capture the exit code, which would cause the subshell to exit immediately under `set -e` when the command fails. The new version uses `cmd && echo 0 || echo $?` to ensure the subshell completes normally while still capturing the expected failure code.

Changes are limited to test scripts `t/t0005-signals.sh` and `t/t3600-rm.sh`, with straightforward mechanical replacements. The commit message clearly explains the motivation and the solution. This appears to be a well-justified change that maintains test behavior while making it compatible with stricter shell error handling.
