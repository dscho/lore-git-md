This is the final patch in Derrick Stolee's 7-part series introducing negotiation controls for fetch/push operations, specifically focusing on push negotiation support. The patch extends the `--negotiation-require` and `--negotiation-restrict` functionality to `git push` when `push.negotiate` is enabled.

The key changes in this patch:
1. Modifies `send-pack.c` to pass the negotiation requirements and restrictions from config (`remote.*.negotiationRequire` and `remote.*.negotiationRestrict`) to the child `git fetch --negotiate-only` process spawned during push negotiation
2. Updates the transport layer to propagate these settings from the remote configuration to the send-pack arguments
3. Adds tests verifying both require and restrict functionality work correctly with push negotiation
4. Maintains backward compatibility by falling back to the old `--negotiation-tip` behavior when no restrictions are configured

The implementation carefully handles the interaction between:
- The existing push negotiation infrastructure that spawns a fetch process
- The new config-based negotiation controls
- The CLI flag precedence established earlier in the series

Test coverage includes verification that:
- Required refs are properly included in push negotiation
- Restricted refs properly limit the negotiation scope
- The negotiation rounds complete successfully (verified via trace2 events)
- The correct number of objects are transferred

This completes the series' goal of providing comprehensive negotiation control for both fetch and push operations, solving the original monorepo scaling problem where critical branches needed guaranteed inclusion in negotiation. The implementation appears solid with thorough test coverage and maintains backward compatibility with existing behavior.
