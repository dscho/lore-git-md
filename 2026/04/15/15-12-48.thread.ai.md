Thread identity: Discussion about implementing `--recurse-submodules` support for `git worktree add`, focusing on how submodule worktrees would share immutable state while maintaining independent working state.

Core problem: Currently `git worktree add` does not support recursive submodule worktree creation. The challenge is to maintain proper isolation between worktrees while efficiently sharing immutable objects.

Current status: Prototype implementation exists using hardlinks for immutable objects (packs/loose objects) and atomic rename(2) for mutable state (HEAD/index/refs), following the same pattern as main worktrees. Discussion suggests the final implementation should use proper `git worktree add` machinery per submodule rather than relying directly on hardlink+rename behavior.

Key technical details:
- Submodule worktrees would share pack files and loose objects via hardlinks
- Each worktree gets independent mutable state through atomic rename operations
- Implementation touches worktree and submodule subsystems
- Filesystem-level considerations (inodes, atomic operations) are critical

Open questions:
- Whether to use direct hardlink+rename approach vs proper `git worktree add` machinery for submodules
- Ensuring correct behavior across all supported filesystems
- Potential edge cases in state isolation

Participant positions:
- Phillip Wood raised concerns about state management
- Jimmy Aguilar Mena responded with technical details of the prototype and suggested proper worktree machinery as the likely final approach

Related work: Builds on existing worktree implementation which already uses similar sharing/isolation patterns for the main repository.
