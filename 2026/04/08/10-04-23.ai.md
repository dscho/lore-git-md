This is a follow-up discussion in the bundle-URI bugfix thread, focusing on error handling behavior for misconfigured bundle URIs. Patrick Steinhardt raises two key points about the proposed fix from Toon Claes.

First, he suggests clarifying the patch's behavior when bundle URIs are explicitly requested (via `--bundle-uri` flag) versus when they're optional (via config). The current implementation continues gracefully for optional cases but should potentially fail hard for explicit requests - a distinction that should be documented and tested.

Second, Patrick notes the new test cases verify clone success with misconfigured URIs but don't confirm the expected error messages are shown. This is important for maintaining user awareness of server misconfigurations while still allowing the operation to complete.

The discussion continues the thread's theme of balancing error reporting with usability - preserving the optional nature of bundle URIs while ensuring administrators are informed of problems. Patrick's feedback suggests the patch is conceptually sound but could be strengthened with additional documentation and test coverage around the explicit/optional behavior boundary.
