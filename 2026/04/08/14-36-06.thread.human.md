This series adds fetch/push negotiation controls for monorepo scenarios. Derrick Stolee is
on v4 (8 patches) of a series that provides two complementary options:
`--negotiation-include`, which guarantees specific refs are always advertised during
common-object search, and `--negotiation-restrict`, which limits negotiation to a subset
of remote refs. The existing single-valued `--negotiation-tip` is renamed to
`--negotiation-restrict` (kept as an alias) because its old name gave users the wrong
mental model -- it restricts, not expands, the set of refs considered. The key structural
fix in v4 is a new `have_sent()` callback interface on the negotiator struct that replaces
the previous COMMON-flag hack, addressing an abstraction breakage that Matthew Cheetham
identified in v3 review.

Each of the 8 patches has now been posted. Beyond the naming fix and CLI plumbing, the
series includes config options for both include and restrict behavior (`remote.<name>.negotiationRestrict` and `remote.<name>.negotiationInclude`), and wires push negotiation through `send-pack.c`. All of Cheetham's v3 concerns have been addressed. No new
issues have been raised against v4; the cover letter suggests readiness for `next`. Patch
1 includes a one-line test fix for a sort-key regression in t5516.
