Derrick Stolee's patch series on fetch/push negotiation controls has progressed to version 2, with Junio C Hamano providing detailed review feedback. The series introduces two key mechanisms for monorepo scaling: `--negotiation-require` to guarantee inclusion of specific refs and `--negotiation-restrict` (a renamed version of `--negotiation-tip`) to limit negotiation scope. The implementation spans multiple files including `fetch-pack.c` and `transport.c`, with comprehensive test coverage.

Junio's latest review focuses on polishing the `--negotiation-restrict` option. He approves of using `%s` placeholders in warning messages (helping translators) and suggests using `OPT_ALIAS()` to avoid code duplication since both old and new options share the same underlying variable. He also notes one remaining inconsistency where `--negotiate-only` still references the old `--negotiation-tip` name. These are relatively minor refinements that don't affect the core functionality but improve the patch's quality.

The series has largely converged on the interface design, with Junio's reviews surfacing implementation details that could be tightened. Open questions remain around config inheritance edge cases and behavior with missing refs/objects, but these don't appear to block progress. The changes address important monorepo scaling needs while maintaining backward compatibility.
