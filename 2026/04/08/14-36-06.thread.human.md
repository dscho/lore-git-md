The thread is Derrick Stolee's v4 series adding `--negotiation-include` and `--negotiation-restrict` fetch/push negotiation controls for monorepo scenarios — specifically, avoiding huge object transfers when a negotiator skips a long-lived release branch. Seven patches address the fetch side; the eighth and final patch wires the same config options into `git push`'s child process when `push.negotiate` is enabled.

All eight patches have now been posted. The core innovation is a `have_sent()` negotiator callback (patch 5) that cleanly replaces a v3 approach that conflated the COMMON flag with "we decided to include this commit anyway." The config options for both restrict and include follow a consistent pattern: CLI flags in patches 2 and 6, config counterparts in patches 4 and 7, and the push wiring in patch 8. The final patch is a straightforward mechanical extension that passes `remote.<name>.negotiationInclude` and `remote.<name>.negotiationRestrict` into `send-pack.c`, with appropriate tests.

No reviews have been received for any v4 patch. Matthew Cheetham reviewed v3 and raised the issue that patch 5 addresses, but has not yet engaged with v4. The series is complete and ready for review; patch 1 includes a small test-order flakiness fix that fixes a regression from a November 2024 commit.
