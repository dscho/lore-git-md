Here is the updated thread summary:

Derrick Stolee's patch series adds two new negotiation controls for `git fetch` (and push): `--negotiation-include` guarantees specified refs are always advertised, while `--negotiation-restrict` limits negotiation to a subset of remote refs. The series is at v4, with Stolee having addressed all issues from the earlier review of patches 2/7 and 4/7.

Matthew Cheetham has now reviewed patch 6/7, which adds the config option `remote.<name>.negotiationInclude`. This was a light review with two small observations: the documentation for the config value's type should point to `--negotiation-include` rather than `--negotiation-restrict`, and one of the new tests for empty-value reset is not robust enough to detect if the reset were broken. Neither is a structural concern.

The main open item remains Cheetham's review of patch 5/7, which includes a potentially critical bug: the COMMON flag used to deduplicate "have" lines for `--negotiation-include` OIDs uses a different flag bit in `fetch-pack.c` (bit 6) than in the default negotiator (bit 2), which could produce duplicate "have" lines on protocol v0/v1. Stolee has not yet responded to this review or to Cheetham's design-layer consistency questions about where refs are resolved. Once patch 5/7's issues are resolved, the series appears ready for integration.
