This thread covers Derrick Stolee's v6 patch series introducing new negotiation controls for fetch and push operations in Git. The goal is to improve efficiency in monorepos by allowing bidirectional control over object transfer: `--negotiation-include` ensures certain refs are always advertised, while `--negotiation-restrict` (formerly `--negotiation-tip`) limits negotiation to specific refs. This solves cases where dropped refs could trigger full-history transfers of 60+ GB.

The series is now in its final form after thorough review, with all 8 patches carrying Reviewed-by tags from Matthew Cheetham (email corrected to mjcheetham@outlook.com in v6). The latest patch adds config support for `--negotiation-include` via `remote.<name>.negotiationInclude`, mirroring the restrict config pattern. This completes the feature set, allowing both include and restrict options to be specified either via command line or configuration. The implementation handles glob patterns, CLI overrides, and empty-value resets consistently across both features.

With all technical concerns addressed and no open questions remaining, the series is ready for maintainer consideration. The changes touch the transport layer, negotiator interface, and both fetch/push operations while maintaining backward compatibility. This represents a significant improvement for large repository workflows where selective negotiation can dramatically reduce transfer sizes.
