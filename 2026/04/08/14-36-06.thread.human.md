This thread is Derrick Stolee's seven-patch series adding `--negotiation-include` and `--negotiation-restrict` options to `git fetch` and `git push`, giving users finer control over which refs participate in pack negotiation for monorepo environments. The series replaces the existing single-valued `--negotiation-tip` with a two-direction mechanism.

Matthew Cheetham has now completed a full review of all seven patches, concluding with a brief, positive assessment of the final patch (push negotiation wiring) that found no issues. Across the series, Cheetham identified real bugs in patches 2, 3, and 4 -- control-flow errors in config parsing and a rename/alias issue -- which Stolee acknowledged and planned to fix in a v4 that has not yet been posted. The remaining open substantive question is Cheetham's finding in patch 5 that the `--negotiation-include` implementation may produce duplicate "have" lines over the Git v0/v1 protocol because it reuses a bit flag (`COMMON`, bit 6 in `fetch-pack.c`) that conflicts with the negotiator's own use of a different `COMMON` flag (bit 2). The v2 protocol path is correct via `oidset_contains()`. Stolee has not yet responded to this concern. The rest of patches 5 through 7 raised only surface-level issues: documentation wordings, a test that would not catch a regression, and a typo -- all easy fixes.

The series is conceptually ready for integration once the v4 fixes are posted and the v0/v1 duplicate-haves question is resolved. No other reviewers have weighed in on the v3 iteration.
