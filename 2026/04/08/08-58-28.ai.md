This is a bugfix targeting the bundle-URI protocol implementation. The patch addresses an issue where a misconfigured server advertising invalid bundle-URI data (empty URIs) would leave stale packet data in the read buffer, causing confusing "expected 'packfile'" errors during clone operations.

The key changes are:
1. Modifies `get_remote_bundle_uri()` to continue reading (but not processing) remaining packets after encountering an error, ensuring the protocol stream is properly drained
2. Adds test cases verifying the behavior with both missing and empty bundle URIs
3. Maintains error reporting while allowing the operation to continue, since bundle-URIs are designed to be optional

The patch is well-motivated with clear reproduction steps and discussion of design tradeoffs. It follows up on previous feedback from Junio Hamano and Justin Tobler about how to handle misconfigurations while maintaining user awareness. The implementation is clean and focused, with appropriate test coverage.

This fixes a real usability issue where server misconfigurations would produce misleading error messages, while preserving the optional nature of bundle-URIs as designed. The changes are unlikely to be controversial as they don't change the fundamental behavior - just make error handling more robust.
