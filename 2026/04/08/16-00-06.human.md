This is a documentation patch following up on an RFC discussion about `git archive --prefix` behavior. Pushkar Singh has submitted a patch to clarify that `--prefix` passes paths verbatim without normalization, including absolute paths ("/") and parent references ("../"), and notes that some archive tools may treat these as potentially unsafe paths.

The patch directly addresses the open question from the RFC thread about improving documentation, as suggested by Junio Hamano. It adds clear wording to the man page explaining the current behavior while noting that downstream tools may handle these paths differently. The change is minimal and focused, adding just a few lines of explanatory text.

This appears to be a well-executed response to the earlier discussion, providing the documentation clarification that participants agreed would be useful. The patch maintains Git's philosophy of letting archive tools handle path policy while making the current behavior more transparent to users. Since this was the expected outcome of the RFC thread, the patch seems likely to be accepted without further discussion.
