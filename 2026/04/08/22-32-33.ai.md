This is a platform compatibility discussion about `writev()` optimizations in Git's network code, continuing from test failures in Git 2.54.0-rc1 on NonStop systems. Jeff King (Peff) responds to Junio Hamano's skepticism about the value of `writev()` optimizations given platform limitations.

Jeff acknowledges the complexity of handling platform-specific `writev()` constraints, particularly NonStop's SSIZE_MAX=53248 byte limit in 32-bit environments. He outlines two potential approaches: either declare `writev()` unsupported on problematic platforms (via `NO_WRITEV`), or implement runtime fallback logic in `git_writev()` that checks total size against `MAX_IO_SIZE`. He provides a sample implementation of the latter approach but questions whether the complexity is worthwhile given that platforms with small `MAX_IO_SIZE` are already doing many small `write()` calls.

The discussion reveals deeper implications for Git's network protocol design. While `writev()` currently only handles sideband packets, future use cases (like streaming blob data) could face similar platform limitations. Jeff notes this may become a recurring issue if `writev()` usage expands, suggesting the current debate has broader architectural significance beyond just NonStop compatibility.

Junio's position favoring reliability over performance gains appears to be gaining traction, with Jeff acknowledging the tradeoffs and questioning whether the optimization is worth maintaining. The exchange highlights how platform constraints can force reevaluation of performance optimizations that initially seemed straightforward.
