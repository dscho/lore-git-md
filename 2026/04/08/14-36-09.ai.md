This is the third patch in Derrick Stolee's series introducing the `--must-have` feature for fetch negotiation. The patch adds config support via `remote.<name>.mustHave` to specify default ref patterns that should always be included in negotiation, mirroring the command-line `--must-have` behavior from patch 2.

The implementation follows Git's standard config precedence rules - command-line arguments override config values. The config is stored in a `string_list` in `struct remote` and parsed similarly to other remote-specific options like `serverOption`. The patch includes thorough documentation updates and tests covering:
1. Basic config usage as default when no CLI --must-have is given
2. Support for glob patterns in config values
3. CLI --must-have taking precedence over config values

The tests verify the negotiation packets contain the expected commits through packet tracing. This maintains consistency with the test approach from patch 2 while exercising the new config pathway. The change is additive to the negotiation algorithm - config-specified refs are sent unconditionally alongside heuristically selected commits.

This patch completes the core functionality for fetch-side negotiation, with patch 4 expected to add push negotiation support. The implementation appears clean and well-tested, following established patterns for remote config handling. The design addresses the monorepo use case where certain branches should be prioritized in negotiation by default without requiring per-fetch command-line options.
