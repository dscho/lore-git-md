Bugfix discussion regarding `writev()` failures on NonStop platform in Git 2.54.0-rc1.

Jeff King (Peff) responds to Randall S. Becker's confirmation that the test failures in t5310.25 (and other tests) stem from `writev()` issues rather than `--git-dir` problems as initially suspected. The error occurs during network operations when cloning a bitmapped repository, with NonStop reporting "Invalid function argument" for the `writev()` system call on what should be a standard pipe descriptor.

Peff notes the behavior is puzzling since `writev()` should work on pipes, and the failure's consistency at this specific point suggests a platform-specific limitation in how NonStop handles vectorized writes. While debugging the exact cause might be informative, he suggests the more practical solution may be to simply disable `writev()` support via the `NO_WRITEV=Nope` build flag, asking Randall to verify if this workaround resolves the issue.

This exchange confirms the regression affects multiple test suites in the release candidate and narrows the solution space to either platform-specific code or disabling the optimization entirely for NonStop. The discussion highlights the ongoing challenge of balancing performance optimizations with cross-platform compatibility, particularly for less common systems like NonStop.
