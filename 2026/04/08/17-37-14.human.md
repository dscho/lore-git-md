Bugfix discussion for NonStop platform's `writev()` limitations in Git 2.54.0-rc1.

Jeff King follows up on Randall S. Becker's report of test failures in multiple test suites (t5310, t5326, t5327, t5608, t7700) when using Git 2.54.0-rc1 on NonStop systems. The core issue stems from NonStop's `writev()` implementation rejecting vectorized writes on network sockets, causing operations like cloning bitmapped repositories to fail with "Invalid function argument" errors.

Peff confirms this is a platform-specific limitation rather than a problem with the `--git-dir` option as initially suspected. The failures occur during network operations that use `writev()` for performance optimizations recently introduced in Git. While the exact nature of NonStop's `writev()` constraints remains unclear, Peff suggests the immediate workaround of building with `NO_WRITEV=Nope` to disable the vectorized writes entirely.

This exchange highlights the ongoing challenge of balancing performance optimizations with platform compatibility, particularly for less common systems like NonStop. The discussion remains technical and solution-oriented, with Peff focusing on practical next steps rather than deep debugging of the platform-specific behavior. The thread shows Git maintainers' responsiveness to platform-specific issues even when they affect niche environments.
