This is a review comment on patch 5/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ODB abstraction effort. Justin Tobler acknowledges the technical correctness of the implementation but questions the practical need for streaming access when the entire object is already in memory.

The patch implements a streaming interface for reading objects from the in-memory backend, which Justin notes seems somewhat redundant since the data is already fully available in memory. While he confirms the code itself is well-written and follows the established pattern, his comment suggests this might be an interface requirement rather than an optimization opportunity. This raises an interesting design consideration about whether streaming semantics are truly necessary for purely in-memory operations.

The exchange highlights the careful balance between interface consistency (providing all expected ODB methods) and implementation efficiency when adding new backend types. Justin's feedback doesn't request changes to this patch but plants a flag about potential future optimization opportunities once the core abstraction is in place.
