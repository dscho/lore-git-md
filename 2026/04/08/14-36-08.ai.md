This is the second patch in a 4-part series introducing a new `--must-have` option for Git's fetch negotiation system, part of Derrick Stolee's effort to improve monorepo performance. The patch implements the core functionality after the preparatory test fix in patch 1.

The change adds a `--must-have` flag that ensures specified refs are always included in fetch negotiation, even if they would otherwise be excluded by `--negotiation-tip` or skipped by the negotiation algorithm. This addresses cases where important long-lived branches (like main/release) get truncated from negotiation in large repos. The implementation:
- Adds option parsing in `builtin/fetch.c`
- Implements ref resolution in `fetch-pack.c` (handling both exact refs and glob patterns)
- Integrates with both protocol v0 and v2
- Includes comprehensive tests verifying:
  - Basic functionality with exact refs
  - Glob pattern support
  - Interaction with `--negotiation-tip` 
Key technical details:
- Uses same pattern syntax as `--negotiation-tip`
- Maintains existing negotiation behavior while adding the extra "must have" commits
- Deduplicates commits that would be sent by both mechanisms
- Silently ignores non-existent refs rather than erroring
- Adds transport layer plumbing to pass the option through

The implementation looks thorough with good test coverage. This appears well-designed to solve the real-world monorepo scaling issue described in the cover letter, where critical branches were being excluded from negotiation. The patch maintains backward compatibility while adding the new capability.
