Bugfix investigation update for NonStop platform's `writev()` compatibility issues in Git 2.54.0-rc1.

Randall S. Becker confirms that the `writev()` failures on NonStop are more widespread than initially thought, now affecting additional tests (t5608 and t7700) beyond the original bitmap-related test failures. The error occurs consistently when Git attempts vectorized writes on network sockets, with the platform reporting "Invalid function argument" - suggesting fundamental incompatibility with this operation type on NonStop systems.

The issue traces back to a recent optimization that introduced `writev()` usage in `sideband_send()` for more efficient network transfers. Randall notes this isn't the first time the platform has had system call compatibility challenges, recalling past issues with `MAX_IO_SIZE` handling. The failures appear systemic wherever `writev()` is used, not limited to bitmap operations.

While Jeff King previously suggested building with `NO_WRITEV=Nope` as a workaround, Randall's findings indicate this may be the only viable path forward for NonStop users, as the platform's `writev()` implementation seems fundamentally incompatible with Git's network operations. The situation presents a clear regression in 2.54.0-rc1 that will need addressing before the final release - either through platform-specific code paths or broader reconsideration of the `writev()` optimization's portability impact.
