This is a bugfix for the bundle-URI feature, addressing an issue where invalid bundle-URI configurations on the server could leave stale data in the protocol stream, causing confusing error messages during clone operations.

The patch fixes a case where servers advertise bundle-URIs with empty or missing URIs, which currently causes clone to fail with a misleading "fatal: expected 'packfile'" error. The root issue is that the bundle-URI parsing code exits early when encountering invalid lines, leaving unprocessed packet data in the read buffer.

The solution modifies `get_remote_bundle_uri()` to continue reading (but not processing) remaining lines when an error is encountered, ensuring the protocol stream is properly drained. This maintains the error reporting while allowing clone to continue, since bundle-URIs are designed to be optional. The commit includes tests verifying the fix handles both missing and empty URI cases.

The patch is a revised version of earlier work, now addressing maintainer feedback by keeping error reporting while improving the protocol handling. It follows the principle that bundle-URIs should be gracefully degraded when misconfigured rather than failing the entire clone operation.
