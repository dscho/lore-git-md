This is a bugfix patch addressing SIGPIPE handling in parallel process execution, specifically affecting hook behavior. Jeff King (Peff) submits the final version of a fix that was previously discussed and verified by multiple contributors.

The patch corrects a subtle race condition in `run_processes_parallel()` where SIGPIPE signal handling was incorrectly ordered. The original implementation could cause premature child process cleanup when hooks exited without reading all input, particularly visible in the t5401.13 test case on NonStop platforms. The fix reorders signal handler installation to ensure SIGPIPE is properly ignored during child process execution.

Key technical details include:
- Moves SIG_IGN for SIGPIPE after pp_init() to prevent interference with child cleanup handlers
- Maintains correct signal handler stack ordering for both setup and teardown
- Preserves behavior for current sequential hook execution while preparing for future parallel hook support
- Specifically addresses Randall Becker's NonStop platform verification failure
