This is a refactoring patch in the xdiff subsystem, part of Ezekiel Newren's series to improve type safety and code clarity in `xdl_cleanup_records()`. The patch converts nested ternary operators into explicit if/else ladders for setting the `action1` and `action2` arrays, making the logic more readable while maintaining identical behavior.

The changes are purely stylistic - replacing `(nm == 0) ? DISCARD: nm >= mlim1 ? INVESTIGATE: KEEP` with a three-branch if/else structure. This affects both file processing loops in `xdl_cleanup_records()`, with identical transformations for `action1` (xdf1 processing) and `action2` (xdf2 processing). The patch builds on previous work in the series that introduced the `mlim1` and `mlim2` variables and converted various types to `ptrdiff_t` and `uint64_t` for better type safety.

This is the fifth patch in a six-part series that has already been through extensive review, including regression identification and resolution in earlier versions. The current iteration preserves all the type safety improvements while avoiding the behavioral regression that occurred in v4. The change is low-risk as it only affects code flow readability without altering the underlying logic or performance characteristics.
