Feature proposal for fetch negotiation improvements. This is a cover letter for a 4-patch series from Derrick Stolee that introduces a new `--must-have` option and corresponding `remote.*.mustHave` config to improve fetch negotiation in large repositories.

The series addresses a real-world problem in monorepos where fetch negotiation can fail to properly advertise important reference states (like a long-lived 'release' branch) when there are many other references. The current `--negotiation-tip` option is too restrictive, forcing an all-or-nothing approach. The new `--must-have` provides a middle ground - ensuring certain references are always included in negotiation while still allowing opportunistic inclusion of others.

The implementation follows the existing `--negotiation-tip` pattern but with more flexible semantics. Patch 1 fixes a flaky test, patch 2 adds the CLI option, patch 3 adds config support, and patch 4 extends it to push negotiation. The changes touch fetch-pack, transport, and remote configuration code.

This looks like a well-motivated change from an experienced contributor who has clearly thought through the real-world implications. The proposal raises good questions about naming, interaction with existing features, and whether similar config should be added for `--negotiation-tip`. The implementation appears clean and follows established patterns while solving a demonstrable pain point in large-scale deployments.
