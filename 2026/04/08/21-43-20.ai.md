This is a platform compatibility discussion about `writev()` limitations on NonStop systems, continuing from test failures in Git 2.54.0-rc1. Junio C Hamano responds to Randall S. Becker's confirmation that the `NO_WRITEV=Nope` workaround successfully resolves the test failures on NonStop systems.

Junio expresses skepticism about modifying callers to handle NonStop's `writev()` limitations, suggesting the platform is better served by using the compatibility implementation in `compat/writev`. He questions whether the `writev()` optimization is worth keeping at all if it requires handling partial writes, noting that the previous approach using two `write(2)` calls might be preferable if the current code is broken by short writes.

The discussion highlights a tension between performance optimizations (vectorized writes) and platform compatibility, with Junio leaning toward favoring reliability over the potential performance benefits of `writev()`. His response suggests the possibility of reverting the `writev()` changes entirely if they prove problematic across platforms, not just on NonStop. This would represent a significant shift from the current direction, indicating the issue may have broader implications beyond just NonStop compatibility.
