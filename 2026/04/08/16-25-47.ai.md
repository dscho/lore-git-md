Bugfix investigation update for NonStop platform issues with `writev()` in Git 2.54.0-rc1.

Randall S. Becker provides additional details confirming the scope of the `writev()` issue on NonStop systems. The problem now appears to affect not just the bitmap-related tests (t5310, t5326, t5327) but also t5608 and t7700 - essentially any test that uses `writev()`. The error "Invalid function argument" suggests NonStop's implementation rejects vectorized writes in contexts where the code expects them to work.

The email notes this isn't the first time Git has encountered I/O size limitations on NonStop, recalling past issues with `MAX_IO_SIZE` that required platform-specific handling. The current `writev()` failures appear to be a regression from recent optimizations that introduced vectorized writes in more code paths, particularly in network operations like cloning.

Jeff King's suggested workaround of building with `NO_WRITEV=Nope` (which falls back to individual `write()` calls) remains untested in this exchange but seems increasingly relevant as the primary mitigation path. The breadth of affected tests suggests this isn't just a bitmap-specific issue but rather a fundamental platform compatibility problem with the `writev()` optimization.

This update strengthens the case that the `writev()` changes in 2.54.0-rc1 may need to be reverted or made conditional for NonStop builds, as the thread continues to explore solutions for this performance-critical but platform-sensitive optimization.
