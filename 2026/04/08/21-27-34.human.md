This is a platform compatibility discussion about `writev()` limitations on NonStop systems, continuing from test failures in Git 2.54.0-rc1. Randall S. Becker confirms that using `NO_WRITEV=Nope` (which falls back to non-vectorized writes) successfully compiles and runs on NonStop systems, and asks whether this can be adopted as a permanent solution. 

The thread has established that NonStop's `writev()` implementation has stricter limits than POSIX requires - failing with EINVAL when the total size exceeds 53248 bytes (SSIZE_MAX) rather than handling partial writes. While the `NO_WRITEV` workaround resolves the immediate issue, the discussion remains open about whether Git should modify its packet-line protocol assumptions to better accommodate platforms with small SSIZE_MAX values. Randall's confirmation that the workaround functions provides a viable path forward while longer-term solutions are considered.
