This is the third patch in Derrick Stolee's series adding `--must-have` support to Git's fetch negotiation system. The patch introduces config support via `remote.<name>.mustHave` as a default for the command-line `--must-have` option.

The change allows users to configure which refs should always be included in fetch negotiation on a per-remote basis, similar to how `remote.<name>.serverOption` works. The config values are stored in a new `must_have` string_list in the remote struct. When no `--must-have` is specified on the command line, these config values are used automatically. The implementation maintains CLI precedence - explicitly provided `--must-have` options override the config settings.

The patch includes thorough documentation updates explaining the new config option and its interaction with the command-line flag. Test cases verify the basic functionality, glob pattern support, and the CLI-over-config behavior. This continues the series' high-quality approach with clear documentation and comprehensive test coverage.

As with previous patches, this addresses real-world monorepo scaling issues where important branches might get excluded from negotiation. The config support makes the feature more convenient for regular workflows where certain branches (like main/release) should always be prioritized.
