**Thread identity**: "negotiator: implement new negotiation and restrict options" series (v4), by Derrick Stolee. Type: patch series (8 patches). v4 cover letter posted; this is the 7th of 8 patches.

**Core problem/goal**: Provide fetch/push negotiation controls for monorepo scenarios: (1) `--negotiation-include` guarantees specified refs are always advertised during common-object search, and (2) `--negotiation-restrict` limits negotiation to a subset of remote refs. Replaces the existing single-valued `--negotiation-tip` with a two-direction mechanism. The motivating case is monorepos with long-lived release branches -- if the negotiator skips that branch, the server may assume no shared history and send the entire parallel commit tree (60+ GB in a real case Stolee cites).

**Current status**: v4 posted with 8 patches. Patches 1-7 received. Patch 7/8 (`remote.<name>.negotiationInclude` config) is the config counterpart to patch 6/8's `--negotiation-include` CLI option. Patch 8/8 (push negotiation wiring) remains pending. Patches 1-7 have received no review yet.

(6/8) `--negotiation-include` implementation: In `builtin/fetch.c`, `add_negotiation_restrict_tips()` generalized to `add_negotiation_tips()` handling both restrict and include lists, stored separately in `transport->smart_options`. In `fetch-pack.c`, include OIDs are sent as haves *before* the negotiator's `next()` iterator, with `have_sent()` tracking to avoid duplicates. Both v0/v1 (`find_common`) and v2 (`send_fetch_request`) codepaths are wired. `negotiate_using_fetch()` also gets the include-tips parameter. Behavioral change: restrict-tip matching now silently ignores non-existent refs (previously would die), matching include behavior. Test coverage: basic include with restrict, glob patterns, additive behavior without restrict, silent missing-refs, duplicate avoidance (v0 and v2), updated existing tests for silent-ignore.
7. (7/8) `remote.<name>.negotiationInclude` config -- a multi-valued key in `remote.c` stored on the `remote` struct's new `negotiation_include` string list. `handle_config()` calls `parse_transport_option()`. `prepare_transport()` in `builtin/fetch.c` feeds it into the same `add_negotiation_tips()` codepath. Empty value resets the list. Config is ignored when `--negotiation-include` is given on CLI. Documentation added to `remote.adoc` and `fetch-options.adoc` including the push-negotiation note. Tests added to `t5510-fetch.sh`: basic usage with empty-value reset, glob patterns against `refs/tags/beta_*`, CLI override showing config is dropped with explicit CLI flag. Follows the exact pattern of patch 4/8's `negotiationRestrict` config.
