**Thread identity**: "negotiator: implement new negotiation and restrict options" series (v3-v4), by Derrick Stolee. Type: patch series (7 patches).

**Core problem/goal**: Provide fetch/push negotiation controls for monorepo scenarios: (1) `--negotiation-include` guarantees that specified refs are always advertised even when not part of the common-object search, and (2) `--negotiation-restrict` limits negotiation to a subset of remote refs. Replaces the existing single-valued `--negotiation-tip` with a more general two-direction mechanism.

**Key technical details**:
- Files touched: `builtin/fetch.c`, `fetch-pack.c`, `transport.c`, `transport-helper.c`, `remote.c`, `send-pack.c`, `builtin/pull.c`, plus documentation (`Documentation/fetch-options.adoc`, `Documentation/config/fetch.adoc`, `Documentation/config/remote.adoc`).
- New/renamed symbols: internal rename of `negotiation_tips` field to `negotiation_restrict_tips` (transport layer). New `negotiation_include` and `negotiation_restrict` fields in `git_transport_options` and `send_pack_args`. Config keys `remote.<name>.negotiationInclude` and `remote.<name>.negotiationRestrict` (multi-valued, glob patterns). Backward-compatible `--negotiation-tip` retained via `OPT_ALIAS`.
- Behavior: `--negotiation-include` causes included commits to be unconditionally advertised as COMMON. `--negotiation-restrict` narrows the set of refs considered during negotiation to those matching given patterns. When no restrict patterns are given, falls back to all remote refs. Push negotiation works by `send-pack.c` shelling out to `git fetch --negotiate-only` with explicit `--negotiation-restrict=<oid>` args. Missing refs are silently ignored (best-effort); missing objects are fatal.
- Edge cases: early server stop, duplicate OID prevention, protocol capability warnings for negotiation restrictions, empty-value reset behavior for config, CLI-priority-over-config, non-smart-transport handling.

   - (a) **Potential bug (duplicate "have" lines on protocol v0/v1)**: The patch marks `--negotiation-include` OIDs with COMMON flag (bit 6, defined in `fetch-pack.c`) to suppress them from the negotiator's output. However, the negotiator's internal `get_rev()` checks a *different* flag -- bit 2, defined in `negotiator/default.c`. Deduplication works correctly on protocol v2 (which uses an `oidset_contains()` check) but may produce duplicate "have" lines on protocol v0/v1. Cheetham presents this as an open question with appropriate humility, but the analysis of the two distinct COMMON bits is precise and well-grounded.
   - (b) Design consistency question: `--negotiation-restrict` resolves refs to OIDs in the builtin layer, but `--negotiation-include` resolves in the transport layer. Cheetham asks whether future readers would benefit from resolving at the same layer -- a design-preference question, not a bug.
   - (c) Documentation mismatch: `--negotiation-include` uses `<revision>` placeholder but the description talks about ref names and globs; `--negotiation-restrict` uses `(<commit>|<glob>)`. The syntax descriptions should align.
   - (d) Minor typo: `s/brances/branches/`.
   - (e) Missing test coverage for silent-ignore of missing refs.
5. **Patch 1/7 (test flakiness fix)**: Root cause identified as off-by-one column error (`sort -k 3` -> `sort -k 4`) introduced in commit 3f763ddf28. Settled.
