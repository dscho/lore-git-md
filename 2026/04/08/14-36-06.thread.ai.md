**Thread identity**: "negotiator: implement new negotiation and restrict options" series (v4), by Derrick Stolee. Type: patch series (8 patches). v4 cover letter posted.

**Core problem/goal**: Provide fetch/push negotiation controls for monorepo scenarios: (1) `--negotiation-include` guarantees specified refs are always advertised during common-object search, and (2) `--negotiation-restrict` limits negotiation to a subset of remote refs. Replaces the existing single-valued `--negotiation-tip` with a two-direction mechanism.

**Current status**: v4 posted with 8 patches. All issues from Cheetham's v3 review addressed. Key structural change: patch 5/8 introduces a `have_sent()` callback interface on the negotiator struct, replacing the COMMON-flag hack that Stolee called a broken abstraction in the v3 review.

**Key technical details**: Eight patches:
1. Test-order flakiness fix (`sort -k 4` -> `sort -k 3` in t5516, regression from 3f763ddf28). The sort-key mismatch is a copy-paste mistake -- `git for-each-ref` output has only three columns, so sorting by column 4 relies on undefined locale-dependent sort behavior. The fix is a one-line change. The commit message does not explain whether the original author used `-k 4` intentionally with a different sort implementation or if it was simply a bug.
2. `--negotiation-restrict` CLI option (alias for `--negotiation-tip`, preserved as alias). Renames the primary option name in `builtin/fetch.c` and `builtin/pull.c` using `OPT_STRING_LIST` for the new name, `OPT_ALIAS` for the old. Motivation: the old name `--negotiation-tip` sounded like it added tips to negotiate with, when it actually _restricts_ the set of refs considered -- it sets an upper bound, not a lower bound. The rename clarifies the semantics and sets up a complementary `--negotiation-include` option later. Also makes several warning messages translatable (`_()`), updates die messages for `--negotiate-only`, and changes option names in warning strings across `builtin/fetch.c`, `transport-helper.c`, and `send-pack.c`. Three new tests in `t5510-fetch.sh` (basic restrict, glob pattern, both option names mixed). Two test names updated in `t5702-protocol-v2.sh`. No behavioral change.
3. Rename internal field `negotiation_tips` to `negotiation_restrict_tips` across transport, fetch-pack, and headers.
4. `remote.<name>.negotiationRestrict` config (multi-valued, empty-value reset, uses `parse_transport_option()`).
5. **`have_sent()` negotiator interface** (new patch): three strategy implementations (default, noop, skipping). Fetch-pack calls `have_sent()` for each unconditional include-have before the negotiator's `next()` iterator. This is the abstraction fix Cheetham identified as needed.
6. `--negotiation-include` CLI option: ref-pattern resolution moved into `builtin/fetch.c`, fetch-pack receives pre-resolved `oid_array` objects.
7. `remote.<name>.negotiationInclude` config (same pattern as patch 4, empty-value reset).
8. Push negotiation wiring: `send-pack.c` passes config values to `git fetch --negotiate-only` child process.
