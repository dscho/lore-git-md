This is a documentation patch following up on the RFC discussion about `git archive --prefix` path handling. Pushkar Singh has submitted a patch to clarify that `--prefix` passes paths verbatim without normalization, including absolute paths ("/") and parent references ("../"), and notes that some archive tools may treat these as potentially unsafe.

The patch adds a clear warning to the `git-archive` man page that the prefix is used exactly as provided, with no path normalization performed by Git. It also notes that downstream archive tools (like tar or zip) may handle these paths differently, possibly warning about or adjusting them during extraction. This matches the consensus from the RFC discussion where Jeff King, brian m. carlson, and Junio C Hamano agreed the current implementation is intentional but could benefit from clearer documentation.

The patch is straightforward and well-targeted, addressing exactly the documentation gap identified in the thread. It doesn't change any behavior - just makes the existing behavior more transparent to users. The wording is clear and technical without being alarmist about the security implications, which aligns with Git's philosophy of letting archive tools handle their own path policies.

This appears to be the expected outcome from the RFC discussion - a documentation improvement rather than a behavior change. The patch is small, focused, and uncontroversial, making it likely to be accepted as-is.
