This thread is about a two-patch bugfix series (v2) that makes Git clients more resilient when servers advertise malformed bundle-URI data—specifically, empty URIs that previously caused confusing "expected 'packfile'" errors during clone operations. The solution combines client-side stream draining to prevent protocol errors with server-side silent filtering of invalid URIs.

The series is now complete, with both patches posted and technical consensus reached on the combined approach. Key changes include draining the protocol stream after invalid bundle-URI lines (client-side) and silently omitting empty URIs from server responses while logging warnings. Tests cover both client and server behavior, and the implementation touches `connect.c`, `bundle-uri.c`, and related test files.

Junio Hamano’s recent review raises a philosophical question about whether the client should *continue* after encountering unparseable bundle-URI data (as the patch does) or terminate the connection immediately. While he’s "on the fence," he accepts the current approach as reasonable for optional features like bundles, though he notes future protocol extensions might require stricter handling. His feedback doesn’t block the patch—he calls it "good"—but flags the design choice as something to revisit if the protocol evolves. The series remains ready for integration, with no unresolved technical objections.
