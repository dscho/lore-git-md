This is a platform compatibility discussion about `writev()` system call limitations on NonStop systems, continuing the thread about test failures in Git 2.54.0-rc1.

Jeff King confirms Randall S. Becker's analysis that the root cause is NonStop's `SSIZE_MAX` being 53248 bytes - smaller than Git's packet-line protocol maximum of 64k. This explains why `writev()` calls are failing across multiple test suites (t5310, t5326, t5327, t5608, t7700) where network operations use vectorized writes. The issue isn't just about descriptor types as initially hypothesized, but about violating platform-specific size constraints.

The discussion has progressed from diagnosis to considering solutions. The `NO_WRITEV=Nope` workaround has been validated in production CI for both 32-bit and 64-bit NonStop environments. Junio Hamano has suggested using the compat/writev implementation as a preferred solution and questioned whether keeping the `writev()` optimization is worthwhile if it requires complex partial write handling. There's now consideration of reverting to simpler `write(2)` calls if vectorized writes prove too problematic across platforms.

This remains a release-blocking issue for 2.54.0, though the immediate problem can be addressed with the workaround. The deeper tension between Git's network protocol assumptions and platform constraints like `SSIZE_MAX` remains unresolved, with implications for future performance optimizations versus cross-platform compatibility.
