This is a technical review follow-up in the Rust enablement series, where Patrick Steinhardt provides minor suggestions to brian m. carlson's final patch that flips the default Rust build flag. The review focuses on three small improvements to the CI and build system changes:

1. Suggests removing an obsolete `WITH_RUST` export from the CI script now that Rust is enabled by default, noting it appears redundant.

2. Asks whether a Meson-based CI job should also be adjusted to test without Rust, similar to the existing `NO_RUST` case for the `linux-clang` job. This would maintain consistency in testing both build paths.

3. Recommends moving the `cargo` program detection logic from the top-level `meson.build` to `src/meson.build` where it's actually used, as a small code organization improvement.

The tone is constructive and technical, focused on polishing the implementation details rather than reopening any substantive discussion about Rust enablement itself. This follows the maintainer's prior ack of the series and Patrick's earlier confirmation that the core approach (including the unconditional `-ldl` linker flag) is sound. The suggestions are all minor and uncontroversial - typical of final polish before a series gets merged.
