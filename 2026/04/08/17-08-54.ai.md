This is a feature patch (v2) adding structured repository metadata access via `git repo info`, specifically introducing a `paths.toplevel` field that mirrors `git rev-parse --show-toplevel` functionality. The patch comes from Jayesh Daga and addresses maintainer feedback from Junio C Hamano on the initial version.

The key changes in v2 are:
1. Added documentation mapping `rev-parse` options to `repo info` fields, making the API design more transparent
2. Fixed the indentation in `get_paths_toplevel()` to use tabs instead of spaces
3. Improved the commit message to better explain the motivation and relationship to existing commands

The implementation remains technically sound, exposing the worktree root via `repo_get_work_tree()` and handling bare repositories by returning an empty string (consistent with other fields). Test coverage verifies behavior matches `rev-parse` in both regular and bare repositories. The change is self-contained in `builtin/repo.c` with corresponding test additions in `t/t1900-repo-info.sh`.

This version appears ready for inclusion, having incorporated the maintainer's style and documentation suggestions while maintaining the original functionality. The patch provides a structured alternative to `rev-parse` for scripts needing repository root information, following established patterns in the repo info subsystem.
