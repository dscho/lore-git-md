Patrick Steinhardt weighs in on the config file locking patch, expressing cautious support while raising deeper concerns about concurrent config writes. He notes that while the 100ms timeout (already approved by Junio) will help with lock contention, it doesn't address the fundamental issue that concurrent config writers can still overwrite each other's changes without detection - unlike reference updates which have conflict checking.

Steinhardt acknowledges this is an improvement over the current immediate-failure behavior, but points out the architectural limitation that config writes lack atomic verification of unchanged state. He considers but dismisses the idea of adding validation as impractical due to the extensive changes required across callers. His final position is that while not ideal, the patch is a net positive since it maintains the current behavior's safety while reducing spurious failures.
