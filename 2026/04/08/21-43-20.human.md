This is a platform compatibility discussion about `writev()` limitations on NonStop systems, continuing from test failures in Git 2.54.0-rc1. Junio C Hamano responds to Randall S. Becker's confirmation that the `NO_WRITEV=Nope` workaround successfully resolves the test failures on NonStop systems.

Junio expresses skepticism about modifying Git's code to accommodate NonStop's restrictive `writev()` implementation, which fails with EINVAL when writes exceed platform-specific size limits. He suggests that platforms with such constraints should simply use the compatibility layer (`compat/writev`) that falls back to non-vectorized writes. More significantly, Junio questions whether the `writev()` optimization is worth keeping at all if it requires complex workarounds for partial writes, proposing instead to revert to the previous approach of using separate `write()` calls.

The discussion highlights a tension between performance optimizations and platform compatibility, with Junio leaning toward favoring broader compatibility over marginal performance gains from vectorized writes. His response indicates this may not remain a NonStop-specific issue but could lead to reconsidering the optimization more broadly. The immediate path forward appears to be maintaining the `NO_WRITEV` workaround while the project evaluates whether to keep the `writev()` changes in the codebase.
