This is a technical analysis from Jeff King (Peff) diagnosing the pre-receive hook test failure reported by Randall Becker. The issue occurs when a pre-receive hook exits successfully without reading its input, causing all refs to be incorrectly rejected on NonStop systems.

Peff traces the problem to a subtle interaction in signal handling within Git's parallel process execution code. The root cause is a race condition in SIGPIPE handling where:
1. The hook API uses `run_processes_parallel()` which initially ignores SIGPIPE
2. But then installs a cleanup handler that propagates signals to children
3. On some platforms (like NonStop), this can cause the hook to appear to fail when it actually succeeded

The proposed fix reorders signal handler installation in `run-command.c` to ensure SIGPIPE is properly ignored even when child processes are involved. The patch moves the SIG_IGN handler after `pp_init()` to take precedence over the child cleanup handler.

Key technical details for future reference:
- File: run-command.c
- Function: run_processes_parallel()
- Signal handling sequence issue between SIG_IGN and child cleanup
- Potential race condition when multiple hooks run in parallel
- NonStop appears more sensitive to this timing than Linux

This appears to be a genuine bug in the hook execution infrastructure rather than a NonStop-specific issue. Peff's analysis suggests the problem could theoretically manifest on any platform, though it was only observed on NonStop in testing. The proposed solution would make the behavior consistent across all platforms.
