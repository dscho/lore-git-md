This is a bugfix patch addressing SIGPIPE handling in parallel process execution, specifically affecting hook behavior. Jeff King (Peff) submits the final version of a fix that was previously discussed and verified by multiple contributors.

The patch corrects a subtle race condition in `run_processes_parallel()` where SIGPIPE signal handling could incorrectly trigger child process termination when hooks exit without reading all input. The core issue stems from signal handler installation order - the cleanup handlers were being installed before the SIGPIPE ignore, causing premature process termination on some platforms (notably NonStop, as reported by Randall Becker).

The solution reorders signal handling to ensure SIGPIPE is properly ignored during child process execution. While the immediate motivation was fixing test t5401.13's pre-receive hook behavior, the change also future-proofs the code for Adrian Ratiu's upcoming parallel hooks work. The patch includes a thorough commit message explaining both the technical details and platform-specific implications.

This appears ready for immediate inclusion, having been vetted by multiple contributors across different platforms and use cases. The fix is small (11 lines changed) but impactful, resolving a cross-platform compatibility issue while maintaining correct behavior for existing hook implementations.
