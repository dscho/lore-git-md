This is a platform compatibility issue affecting Git 2.54.0-rc1 on NonStop systems, continuing the discussion about `writev()` failures. Randall S. Becker confirms that the problem extends beyond the initially reported bitmap tests (t5310, t5326, t5327) to also impact t5608 and t7700 - essentially anywhere `writev()` is used in network operations. He notes that NonStop's `SSIZE_MAX` limit of 53248 bytes is being violated by Git's packet-line protocol which assumes 64k maximums.

The exchange reveals a deeper platform constraint: NonStop fundamentally rejects vectorized writes on certain descriptor types regardless of size, not just having size limitations. This affects recent optimizations that expanded `writev()` usage in network code paths. While Jeff King had initially thought the 64k packet limit would avoid `MAX_IO_SIZE` issues, Randall's response shows the platform's actual limit is lower, making this a clear regression.

The thread continues to explore solutions, with the `NO_WRITEV=Nope` build flag still under consideration as a workaround. However, this response highlights that the issue may require more fundamental changes to respect platform-specific constraints in the network code. The widespread test failures make this a release-blocking issue for 2.54.0.
