This is patch 4/6 in a refactoring series targeting the xdiff subsystem's record cleanup logic. The patch focuses on making the per-file limit calculations in `xdl_cleanup_records()` clearer and more maintainable.

The key changes in this patch are:
1. Introduces explicit per-file limit variables (`mlim1`, `mlim2`) initialized at the processing loops
2. Removes redundant `need_min` condition that was previously part of the INVESTIGATE logic
3. Moves the limit calculation logic before the processing loops for better code flow
4. Maintains the same behavior while making the logic more straightforward

The changes are purely internal refactoring with no functional impact - the same limits are calculated, just in a more readable way. The patch builds on previous work in the series that converted types to `ptrdiff_t` and `uint64_t` where appropriate.

This continues the series' theme of improving type safety and code clarity in xdiff's record processing. The changes are well-contained to xdiff/xprepare.c and follow the established pattern of the earlier patches in the series. Given that the regression from v4 has already been addressed by reverting the problematic INVESTIGATE handling changes, this patch represents a safe improvement that maintains all the type safety gains while making the code more maintainable.
