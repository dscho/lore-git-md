This is the second patch in a 4-part series introducing a new `--must-have` option for Git's fetch negotiation, from Derrick Stolee who specializes in large-repository performance optimizations.

The patch implements the core functionality of `--must-have`, which ensures specified refs are always included in fetch negotiation as "have" lines, even if they would otherwise be excluded by `--negotiation-tip` or the negotiation algorithm. This is particularly useful in monorepos where certain long-lived branches (like main/release) are critical but might get truncated from negotiation due to protocol limits.

Key aspects of this implementation:
- Supports both exact ref names and glob patterns (matching `--negotiation-tip` syntax)
- Works additively with normal negotiation - the algorithm still runs but the specified refs are guaranteed inclusion
- Handles duplicates gracefully (won't send the same "have" line twice)
- Includes comprehensive tests verifying the behavior with globs, negotiation tips, and edge cases
- Updates documentation with clear usage examples

The change touches several layers of the fetch/negotiation stack, requiring updates to transport.c, fetch-pack.c, and related headers. The implementation looks thorough and well-tested, with packet tracing used to verify the negotiation protocol behavior.

This appears to be a well-motivated change that cleanly solves a real pain point in large repositories while maintaining backward compatibility. The patch follows the established pattern of `--negotiation-tip` while addressing its limitations for certain workflows.
