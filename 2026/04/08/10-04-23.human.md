This is a follow-up discussion in the bundle-URI bugfix thread, where Patrick Steinhardt provides review feedback on Toon Claes' patch to handle misconfigured bundle-URI servers. The patch previously addressed an issue where invalid bundle-URI data would leave stale packets in the read buffer during clones, causing confusing error messages.

Patrick agrees with the general approach but raises two key points for clarification: First, he suggests explicitly documenting in the commit message why the code continues reading packets after encountering an error (rather than bailing immediately). Second, he questions whether the new test cases should verify that the expected error messages appear, since the patch maintains error reporting while allowing the clone to continue.

The discussion also revisits the broader design philosophy around bundle-URIs being optional by default. Patrick notes that while continuing silently makes sense for optional bundle-URIs, explicit requests (like via `--bundle-uri`) should still fail hard on errors. He believes this distinction is already handled correctly but suggests making it clearer in the documentation and tests.

This is a focused technical review that maintains the patch's core improvements while suggesting minor documentation and testing enhancements. The exchange shows careful consideration of both user experience (avoiding misleading errors) and maintainability (clear documentation of design decisions).
