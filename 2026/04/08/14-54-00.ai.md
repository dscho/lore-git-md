Bugfix investigation update for NonStop platform issues with `writev()` in Git 2.54.0-rc1.

Randall S. Becker follows up on Jeff King's analysis of the first failing test (t5310.25) where cloning a bitmapped repository fails with a `writev()` error. The error occurs during the sideband transfer when attempting to clone a repository, with the system reporting "Invalid function argument" - likely indicating an unsupported operation on the socket or file descriptor type.

This confirms Peff's suspicion that the root issue lies in NonStop's `writev()` implementation rather than a problem with the `--git-dir` option itself. The failure mode suggests a platform-specific limitation in how NonStop handles vectorized writes on network sockets during the clone operation. The error appears consistently at the same point where sideband data transfer would occur.

The technical details point to a compatibility gap between Git's recent optimization (using `writev()` for more efficient network transfers) and NonStop's system call implementation. This raises questions about whether the optimization should be conditionally disabled on NonStop or if a deeper investigation into the platform's `writev()` constraints is needed. The workaround of building with `NO_WRITEV=Nope` remains untested in this follow-up but appears increasingly relevant as the primary path forward for NonStop users.
