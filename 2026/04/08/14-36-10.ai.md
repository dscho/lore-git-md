This is the final patch in Derrick Stolee's series adding `--must-have` negotiation support, now extending the feature to push operations. The patch completes the feature by integrating the must-have refs into push negotiation subprocess when `push.negotiate` is enabled.

The implementation adds a `must_have` field to `send_pack_args` and passes it through from the transport layer where the remote config is available. This ensures push negotiation respects any `remote.*.mustHave` config settings while avoiding config re-parsing in the subprocess. The approach is robust against URL-only remote specifications.

Test coverage demonstrates the feature working with `remote.*.mustHave` config, verifying through packet tracing that the negotiation succeeds with the expected number of rounds. The implementation follows the same patterns established in the fetch-side patches, maintaining consistency across both operations.

With this patch, the series now provides complete must-have negotiation support for both fetch and push operations, addressing the original monorepo scaling issue where important branches were being excluded from negotiation. The solution remains backward compatible while giving large repositories better control over their negotiation priorities.
