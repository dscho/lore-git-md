This is a platform compatibility patch series targeting Windows-specific issues with large objects (>4GB) during cloning. The series comes from Johannes Schindelin (Git for Windows maintainer) and addresses a fundamental limitation where 32-bit `unsigned long` on Windows causes truncation of large object sizes.

The series focuses on the most critical paths that prevent large objects from surviving a clone at all:
1. Fixes zlib wrapper to handle streams >4GB
2. Updates object size handling in pack streaming, delta headers, and index-pack/unpack-objects
3. Prevents pack-objects from corrupting reused pack entries with truncated sizes

The last two commits add test infrastructure - a helper to synthesize large packfiles and regression tests for cloning them via both unpack-objects and index-pack paths. The author notes this is just the first step - many other code paths still need similar fixes (cat-file, object_info, delta machinery).

The changes are mechanical but wide-ranging, touching core object handling code in packfile.c, odb/streaming.c, and related subsystems. The test coverage appears thorough for the targeted scenarios. Given Schindelin's Windows expertise and the clear focus on a real platform limitation, this seems like a well-motivated series that addresses a concrete pain point for Windows users working with large repositories.
