This is the first patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The change is a platform compatibility fix that prevents object size corruption during cloning on Windows.

The patch changes the type used for object sizes from `unsigned long` to `size_t` in `index-pack` and `unpack-objects`, ensuring 64-bit arithmetic when decoding packfile entries. On Windows (even 64-bit builds), `unsigned long` is only 32-bit, causing truncation when handling objects larger than 4GB. The fix ensures the shift operations during size decoding happen in 64-bit space by casting the byte being shifted to `size_t`.

The change is mechanical but important - it prevents corruption of large objects during cloning operations. The patch was originally authored by an anonymous contributor (LordKiRon) who transferred authorship to Schindelin for submission. As the first in a series targeting Windows large object support, this lays groundwork for subsequent patches that will address other affected code paths.
