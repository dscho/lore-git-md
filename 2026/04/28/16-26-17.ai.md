This is the third patch in Johannes Schindelin's series addressing Windows platform compatibility issues with large objects (>4GB). The patch focuses on streaming object sizes in the ODB and packfile subsystems, converting `unsigned long` to `size_t` to prevent truncation on Windows where `unsigned long` is 32-bit.

The changes are mechanical but wide-ranging, touching core object handling code across multiple files. Key aspects:
- Updates the `odb_read_stream` struct to use `size_t` for object sizes
- Introduces temporary variables to handle API compatibility where `object_info.sizep` remains `unsigned long*`
- Adds comments documenting the remaining truncation limitations for loose objects
- Modifies packfile handling to properly process large objects during streaming

The patch maintains careful backwards compatibility while fixing the critical paths for large object handling. It builds on work originally done by an anonymous contributor ("LordKiRon") that Schindelin has taken over authorship of. The changes are well-commented and appear to maintain all existing functionality while adding 64-bit size support where needed.

This continues the series' systematic approach to fixing Windows' 32-bit size limitations, following the earlier patches that addressed index-pack/unpack-objects and zlib wrapper issues. The thoroughness of the changes and test coverage in subsequent patches suggests this is a well-considered solution to a real platform limitation.
