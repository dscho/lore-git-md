Performance optimization patch for `index-pack` and `unpack-objects` I/O efficiency, version 4.

Scott Bauersfeld's fourth iteration of this patch series provides improved measurement methodology while maintaining the core optimization - increasing the input buffer size from 4KB to 128KB to reduce system call overhead. The key change in this version is replacing strace-based measurements with direct FUSE daemon logging, revealing the true write reduction is 94% (74,958 to 4,687 writes) rather than the previously reported 65% from strace. The patch explains this discrepancy as being due to strace's measurement overhead distorting the results.

The performance improvements remain consistent with previous versions: 10-11% faster clones on FUSE filesystems (75.7s vs 84.5s for vscode repo, 20.0s vs 22.6s for git/git). The implementation continues to use the `DEFAULT_IO_BUFFER_SIZE` constant introduced in v3, properly centralized in `git-compat-util.h`. The commit message now includes additional technical insight about Linux pipe buffer sizes affecting the exact write count.

This version appears to be the final refinement of this optimization, having addressed all substantive feedback across four iterations. The changes are well-validated by improved measurement techniques and maintain the performance benefits while being technically sound.
