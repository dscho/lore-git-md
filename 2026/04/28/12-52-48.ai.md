This is the second patch in a two-part bugfix series addressing a Windows-specific deadlock in `git maintenance`'s geometric repacking. The issue occurs when mmap'd pack index files prevent deletion of old packfiles on certain Windows versions.

The patch fixes the root cause by properly setting `child.odb_to_close` in `maintenance_task_geometric_repack()`, ensuring the object database is released before spawning `git repack`. This matches the pattern used by other maintenance tasks and prevents the mmap'd files from being locked during deletion.

The change is well-validated with:
1. A new test case that detects orphaned .idx files after repacking
2. A Windows-specific test that verifies the fix works even with legacy delete semantics (using the `GIT_TEST_LEGACY_DELETE` helper from patch 1/2)
3. Clear documentation of the Windows version behavior changes that made this issue surface

The patch references prior related work (df76ee7b77f0) and connects to an open Git for Windows issue (#6210). The fix is straightforward and follows established patterns, with comprehensive testing that should prevent regression. Johannes Schindelin's implementation demonstrates deep understanding of both the Windows platform specifics and Git's maintenance machinery.
