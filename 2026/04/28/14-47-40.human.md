Performance optimization for `index-pack` and `unpack-objects` I/O efficiency, version 4.

Scott Bauersfeld's final iteration of this patch series increases the input buffer size from 4KB to 128KB to reduce system call overhead, particularly benefiting FUSE filesystems where small writes incur significant latency. The change introduces a shared `DEFAULT_IO_BUFFER_SIZE` constant in `git-compat-util.h` (addressing Derrick Stolee's naming feedback from v2) and uses it consistently across `index-pack`, `unpack-objects`, and the hashfile` layer in `csum-file`.

This version improves upon previous measurements by using FUSE daemon write logging instead of strace, revealing the true impact: a 94% reduction in pack file writes (74,958 to 4,687) during HTTPS clones of git/git. Wall-clock time improvements remain strong at 10-11% faster clones on FUSE filesystems. The commit message now includes a detailed explanation of why the write count doesn't reach the theoretical minimum (due to Linux's default 64KB pipe buffer size) and documents all changes since v1.

The patch has received thorough review from Junio Hamano and Derrick Stolee, with Jeff King providing additional network protocol context. All technical concerns have been addressed, and the series appears ready for merging with consensus from maintainers. The optimization is straightforward, well-tested, and provides measurable benefits for FUSE users while maintaining compatibility with existing code.
