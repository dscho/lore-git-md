This is the final documentation and test refinement patch series for the long-running `checkout -m` autostash feature, now fully complete after 20 iterations (14 pre-merge + 6 post-merge). The series represents the last polish on a feature that enables automatic stashing of local changes during conflicted branch switches.

The v16 series makes several final improvements based on Phillip Wood's review:

1. Documentation updates to show actual command output (rather than hypothetical examples) and clarify that local changes "will" (not "would") be carried during branch switches. The conflict resolution instructions are now more concise.

2. Parameter simplification in the merge logic - replacing the `show_unpack_errors` flag and `old_commit` parameter with a direct `quiet` boolean for clearer control flow.

3. Test suite enhancements including:
   - Verifying the stash reflog message format
   - Using heredoc for more robust test assertions
   - Consolidating duplicate test assertions
   - Ensuring error messages appear exactly once

The implementation has comprehensive test coverage for all edge cases including untracked file handling, conflict scenarios, and quiet mode behavior. All technical work is now complete, with only non-blocking architectural considerations about stash message handling deferred to potential future work.

This represents the conclusion of a major feature development cycle in Git, demonstrating the project's thorough review culture from initial implementation through final documentation and test refinements. The feature is now stable and production-ready.
