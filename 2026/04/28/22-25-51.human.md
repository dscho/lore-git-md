This is a feature patch series (v3) from Kristoffer Haugsbakk that introduces a new experimental `git format-rev` command for on-demand pretty formatting of revisions. The series represents a significant pivot from v2, where the functionality was implemented as an option to `git name-rev`.

The new command provides two modes:
1. `--stdin-mode=revs`: Processes one revision per line from stdin
2. `--stdin-mode=text`: Formats commit object names found in freeform text (similar to `git name-rev --annotate-stdin`)

Key motivations include:
- Formatting arbitrary commits in any particular order (unlike `git log` which sorts)
- Handling duplicate commits in input (which `git log` would deduplicate)
- Processing commits mixed with arbitrary text (like commit messages containing hashes)

The implementation shares infrastructure with `git name-rev` but is now a separate command, avoiding feature creep in the existing command. The patch series:
1. Prepares the codebase with style fixes and refactoring
2. Adds comprehensive tests
3. Introduces the new command with full documentation

The command is marked as EXPERIMENTAL to allow for future changes or removal if needed. The implementation appears thorough, with careful attention to edge cases and memory management. The documentation includes practical examples showing integration with commands like `git last-modified` and potential use in commit-msg hooks.

This represents a well-considered solution to a real workflow gap in Git's tooling, particularly for processing commit lists that don't fit the `git log` model. The separation into a new command rather than extending `name-rev` seems justified given the different use cases.
