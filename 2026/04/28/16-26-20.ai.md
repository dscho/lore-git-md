This is the final patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The patch adds regression tests for cloning repositories containing objects larger than 4GB, verifying the fixes from previous patches in the series.

The test creates a synthetic repository with a >4GB blob using the new `test-tool synthesize pack` helper introduced in patch 5/6. It then verifies successful cloning through both unpack-objects and index-pack paths by checking that the large blob's OID remains intact. The tests are gated behind `SIZE_T_IS_64BIT` to ensure they only execute on platforms where size_t can handle the test case.

Notable technical details:
- Tests both unpack-objects and index-pack code paths by manipulating fetch.unpackLimit
- Uses OID comparison rather than size checks due to remaining unsigned long limitations in object_info.sizep
- Demonstrates the series' effectiveness at preventing corruption during clone operations
- Completes the test coverage for the core cloning scenarios addressed by the previous patches

This concludes the initial phase of fixes for Windows large object handling, though the commit message notes that additional work remains (particularly around object_info.sizep and other code paths like cat-file). The test infrastructure now exists to validate future improvements in this area.
