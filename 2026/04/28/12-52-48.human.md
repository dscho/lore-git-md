This is the second patch in a two-part bugfix series addressing a Windows-specific deadlock in `git maintenance`'s geometric repacking. The issue occurs when mmap'd pack index files prevent deletion of old packfiles on certain Windows versions.

The patch fixes the root cause by properly setting `child.odb_to_close` in `maintenance_task_geometric_repack()`, ensuring the object database is released before spawning `git repack`. This matches the behavior of other maintenance tasks and prevents the file-locking issue on Windows.

Johannes Schindelin adds a robust regression test that:
1. Verifies no orphaned .idx files remain after repacking
2. Specifically tests the fix under legacy Windows delete semantics (using the `GIT_TEST_LEGACY_DELETE` helper from patch 1/2)
3. Preserves the test environment to verify both modern and legacy behaviors

The commit message provides thorough context, tracing the regression's introduction and explaining Windows' file deletion semantics changes. The fix is straightforward - a one-line change with comprehensive testing - and clearly addresses a real-world issue reported in the Git for Windows tracker (#6210).

This is a well-constructed patch from the Git for Windows maintainer that demonstrates deep understanding of both the platform-specific behavior and Git's maintenance internals. The separation of test infrastructure (1/2) from the actual fix (2/2) follows good patch series hygiene.
