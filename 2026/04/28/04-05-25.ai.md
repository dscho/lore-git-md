This is the second patch in a 3-part series refactoring `git log -L` (line-log) to integrate with Git's standard diff output pipeline. The core change moves line-log processing through the normal `log_tree_diff()` -> `log_tree_diff_flush()` path rather than taking a separate shortcut.

Key technical changes in this patch:
- Renames `line_log_print()` to `line_log_queue_pairs()` and simplifies it to just queue pre-computed filepairs
- Makes line-log flow through the standard diff pipeline, fixing issues where pickaxe (`-S`, `-G`) and `--diff-filter` weren't properly suppressing commits when all line-log pairs were filtered out
- Aligns commit/diff separator behavior with regular log output (only showing for verbose headers)
- Explicitly rejects `--full-diff` as incompatible with `-L`

The patch includes test updates showing the fixed behaviors and new capabilities. The changes are well-motivated and the commit message clearly explains both the current limitations and the solution. This appears to be a solid technical improvement making line-log behave more consistently with Git's other diff operations.
