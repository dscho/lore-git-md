This is the first patch in a two-part series addressing a Windows-specific deadlock in `git maintenance`'s geometric repacking. The patch comes from Johannes Schindelin, the Git for Windows maintainer, and focuses on test infrastructure.

The core of the patch adds a new `GIT_TEST_LEGACY_DELETE` environment variable that forces Windows to use pre-POSIX delete semantics, where files cannot be deleted if another process has them memory-mapped. This simulates behavior from older Windows 10 builds (pre-18363) where the deadlock occurs, allowing the regression test in the second patch to verify the fix works even on modern Windows systems.

The implementation is clean and well-documented, using `SetFileInformationByHandle()` with `FileDispositionInfo` to force the legacy behavior. The change is scoped to `mingw_unlink()` in `compat/mingw.c` and includes clear comments explaining the Windows version differences and testing rationale.

This is a thoughtful approach to testing platform-specific edge case - rather than requiring actual old Windows versions, the patch provides a way to simulate the problematic environment. The separation of test infrastructure from the actual bugfix in the series follows good patch organization practices.
