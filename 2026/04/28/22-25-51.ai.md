This is a feature patch series (v3) from Kristoffer Haugsbakk that introduces a new experimental `git format-rev` command for on-demand pretty formatting of revisions. The series represents a significant pivot from v2, where the functionality was implemented as an option to `git name-rev`.

Key changes in v3:
- Splits the formatting functionality into a new standalone command rather than extending `git name-rev`
- Adds two input modes: `--stdin-mode=revs` (one revision per line) and `--stdin-mode=text` (find commits in freeform text)
- Maintains all the formatting capabilities from v2 including notes support
- Marks the command as EXPERIMENTAL to allow for potential future changes

The new command addresses the same core use cases as v2:
- Formatting output from commands like `git last-modified`
- Processing commit hashes in commit messages
- Handling duplicate/mixed input that `git log`/`git show` can't process efficiently

Technical implementation notes:
- Shares infrastructure with `name-rev.c` through refactored common code
- Uses the same pretty formatting machinery as other Git commands
- Includes comprehensive tests covering both input modes and edge cases
- Handles annotated tags by peeling them to commits

The series appears well-structured, with preparatory commits cleaning up and factoring code before introducing the new command. The documentation is thorough, including examples and discussion of why existing commands don't suffice for these use cases.

This represents a more architecturally sound approach than v2's `name-rev` extension, though the experimental flag suggests the interface may still evolve based on feedback. The implementation looks solid and the tests provide good coverage of the functionality.
