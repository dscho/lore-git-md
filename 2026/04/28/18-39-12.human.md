This is the final patch in a long-running series (21 iterations) implementing autostash behavior for `git checkout -m` when switching branches with local changes. The feature is now complete and merged.

The patch adds automatic stashing of local changes during conflicted switches, with several key behaviors:
- If the local changes don't conflict with the branch differences, they are silently reapplied after the switch
- If conflicts occur during reapplication, the stash is preserved and the user gets clear recovery instructions
- The implementation handles both staged and unstaged changes properly
- New test cases verify the behavior with mixed changes and untracked files

The documentation has been updated to show the new behavior with concrete examples, replacing the old merge-focused wording. The implementation includes proper lockfile cleanup and handles all edge cases identified during the extensive review process.

This concludes a major feature development that demonstrates Git's thorough review culture - from initial implementation through final documentation and test refinements. The result provides a more robust workflow for users switching branches with uncommitted changes.
