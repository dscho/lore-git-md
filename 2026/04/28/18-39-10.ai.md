This patch is part of the final refinements for the long-running `checkout -m` autostash feature, now in its 16th iteration. It extends the autostash application machinery to support customizable conflict marker labels and stash messages, completing the implementation's flexibility.

The key technical change adds four new parameters to `apply_autostash_ref()` and related functions:
- `label_ours`, `label_theirs`, `label_base` for conflict marker customization
- `stash_msg` for customizing the stored message

The patch updates callers in `builtin/commit.c` and `builtin/merge.c` to pass NULL for these new parameters, maintaining backward compatibility while exposing the new functionality. The implementation passes these options through to `git stash apply` and `git stash store` commands when non-NULL.

This represents the last major functional addition to the autostash feature before its completion. The changes are well-contained, touching only the sequencer subsystem and its callers, with comprehensive parameter handling that maintains existing behavior while enabling new use cases. The patch follows Git's established patterns for command-line option plumbing through the sequencer internals.

With this change, the autostash feature now supports the full range of conflict resolution customization that direct `git stash` operations provide, while maintaining its automatic behavior during branch operations. The implementation demonstrates careful attention to backward compatibility and clean integration with existing stash plumbing.
