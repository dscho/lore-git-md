This is a follow-up discussion on the HTTP authentication bugfix series, specifically addressing documentation improvements for the `http.emptyAuth` configuration option. Matthew John Cheetham responds to Junio C Hamano's observation that the current documentation is unclear about the allowed values for `http.emptyAuth`.

Matthew proposes adding a documentation patch to explicitly list the three possible values (`auto`, `true`, `false`) with clear descriptions of each behavior. The suggested documentation would explain:
- `auto` (default) sends empty credentials only when the server requests them via specific auth mechanisms like GSS-Negotiate
- `true` always sends empty credentials on the first request
- `false` never sends empty credentials, disabling mechanisms like GSS-Negotiate

This clarification would complement the technical fixes in the series (which Junio has already reviewed positively) by making the configuration's behavior more transparent to users.
