This is a 3-patch series refactoring how `git log -L` (line-log) integrates with Git's diff output pipeline. The main goal is to make line-log processing flow through the standard `log_tree_diff()` -> `log_tree_diff_flush()` path used by other diff operations, rather than taking a separate shortcut.

The series enables several improvements:
1. Fixes issues where pickaxe (`-S`, `-G`) and `--diff-filter` weren't properly suppressing commits when all line-log pairs were filtered out
2. Aligns commit/diff separator behavior with regular log output
3. Adds support for non-patch diff formats (`--raw`, `--name-only`, etc.) with `-L`, while still blocking stat formats that would show whole-file stats

Patch 1 is a preparatory reordering of revision setup code. Patch 2 does the core refactoring to use the standard diff pipeline. Patch 3 expands the allowed diff formats. The changes are well-motivated and the series includes test coverage showing the fixed and new behaviors.

This appears to be a solid technical improvement to the line-log machinery, making it behave more consistently with Git's other diff operations while enabling new use cases. The changes are focused and the commit messages clearly explain both the current limitations and the solutions.
