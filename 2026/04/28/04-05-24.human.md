This is the first patch in a 3-part series refactoring `git log -L` (line-log) to integrate with Git's standard diff output path. The current implementation is a preparatory change that reorders revision setup code to ensure the line-log default output format (DIFF_FORMAT_PATCH) is properly registered before the diff pipeline checks revs->diff.

The patch moves the line-level traversal block before the "Did the user ask for any diff output?" check in setup_revisions(). This ensures that when no explicit output format is given, the default patch format is visible to the diff pipeline. While this change alone doesn't modify behavior, it's necessary groundwork for the subsequent patches that will route line-log through the standard diff path.

The change is mechanical and well-explained in the commit message, which clearly states why the reordering matters for the upcoming refactoring. The patch appears focused and uncontroversial, with no functional changes yet - just setting up the plumbing for the more substantial changes to come in patches 2 and 3.
