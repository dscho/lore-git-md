This is the third patch in the final v16 series concluding the long-running `checkout -m` autostash feature. The patch extends the autostash machinery to support customizable conflict marker labels when applying stashes, matching functionality recently added to `git stash apply`.

The key change adds parameters to `apply_autostash_ref()` and related functions to pass through `--label-ours`, `--label-theirs`, and `--label-base` options to the underlying stash application. It also allows customizing the stash message when storing the autostash. The implementation maintains backward compatibility by making all new parameters optional (NULL by default).

The patch updates callers in `builtin/commit.c` and `builtin/merge.c` to pass NULL for the new parameters, preserving existing behavior. This is part of the final polish for a feature that has undergone extensive review over 20 iterations (14 pre-merge and 6 post-merge).

The changes demonstrate careful attention to interface design - the new functionality is opt-in and doesn't disrupt existing uses, while providing the full flexibility of the underlying stash machinery. This represents the last major technical piece before the series concludes with documentation and test refinements in the remaining patches.
