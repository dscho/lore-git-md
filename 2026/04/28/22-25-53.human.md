This is a preparatory style cleanup patch in Kristoffer Haugsbakk's series introducing the new `git format-rev` command. It's part 2/5 of v3, following the architectural pivot from extending `git name-rev` to creating a new command.

The patch applies clang-format to `builtin/name-rev.c` to standardize whitespace and alignment before the subsequent refactoring that will share code between `name-rev` and the new `format-rev`. Changes are purely mechanical:
- Adjusts spacing around operators (e.g., `p+1` becomes `p + 1`)
- Aligns continuation lines in option definitions
- Normalizes indentation in conditional blocks

No behavior changes are introduced - this is housekeeping to make the actual refactoring in later patches cleaner. The changes follow Git's coding guidelines and match the project's typical style patterns.

This is a straightforward preparatory step in a well-structured series that has already undergone significant review. The careful separation of style changes from logic changes demonstrates good patch hygiene.
