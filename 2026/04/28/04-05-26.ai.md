This is the final patch in a 3-part series refactoring `git log -L` (line-log) to integrate with Git's standard diff pipeline. The series makes line-log processing flow through the same `log_tree_diff()` -> `log_tree_diff_flush()` path used by other diff operations, rather than taking a separate shortcut.

Patch 3/3 expands the allowed diff formats when using `-L`, now permitting metadata-only formats like `--raw`, `--name-only`, `--name-status`, and `--summary`. The patch maintains the existing restriction on stat formats (`--stat`, `--numstat`, etc.) since they would show whole-file statistics rather than range-scoped ones. The implementation works because these metadata formats only need the filepair fields (status, mode, path) that are already set during line-log processing.

The changes are well-tested with new test cases verifying the supported formats and confirming the continued rejection of stat formats. Documentation is updated to reflect the new capabilities. This completes the series' goal of making line-log behave more consistently with Git's other diff operations while enabling new use cases.

The series appears technically sound, with each patch building logically on the last. The commit messages clearly explain the changes and limitations, and the test coverage is thorough. This looks like a solid improvement to the line-log machinery.
