This is the first patch in the final documentation and test refinement series for the long-running `checkout -m` autostash feature. The patch adds customizable conflict marker labels to `git stash apply`, allowing users to specify their own labels instead of the standard "Updated upstream", "Stashed changes", and "Stash base".

The key changes include:
1. New `--label-ours`, `--label-theirs`, and `--label-base` options for `git stash apply`
2. Updated documentation explaining the new options
3. Tests verifying the custom labels work with both normal and empty labels
4. Fixes to `xdiff/xmerge.c` to properly handle empty labels

The implementation is clean and well-tested, with clear documentation. This represents the final polish on a feature that has undergone extensive review (20 iterations total). The patch maintains consistency with Git's existing conflict marker handling while providing more flexibility for users.

This is part of a larger effort to improve conflict resolution during branch switching operations, now concluding with these final documentation and test refinements. The changes are focused and well-contained, with all edge cases (like empty labels) properly handled.
