This is the final patch (5/5) in Kristoffer Haugsbakk's v3 series introducing the new experimental `git format-rev` command. The command provides on-demand pretty formatting of revisions, addressing use cases where existing commands like `git log` and `git show` fall short.

The new command offers two input modes:
- `--stdin-mode=revs`: Processes one revision per line
- `--stdin-mode=text`: Finds and formats commit hashes in freeform text

Key features demonstrated in the patch:
- Shares infrastructure with `git name-rev` through refactored common code
- Supports all standard pretty formats and notes display (%N)
- Handles annotated tags by peeling them to commits
- Includes comprehensive tests covering both input modes and edge cases
- Marked as EXPERIMENTAL to allow for interface refinement

The implementation builds on the preparatory work in earlier patches, which refactored `name-rev.c` to support this new command. The documentation provides clear examples of practical use cases like processing `git last-modified` output and formatting commit references in messages.

The patch appears well-structured and maintains Git's quality standards with thorough test coverage. The experimental flag suggests the interface may still evolve based on feedback, but the core functionality looks solid. This represents a useful addition for workflows that need to format commits on demand rather than walking commit graphs.
