This is the third patch in Johannes Schindelin's series addressing Windows platform compatibility issues with large objects (>4GB). The patch focuses on streaming object sizes in the object database (odb) and packfile subsystems.

The core change converts `unsigned long` to `size_t` for object size tracking in the streaming interfaces, fixing truncation issues on Windows where `unsigned long` is 32-bit even in 64-bit builds. The patch carefully maintains API compatibility where needed (like with `object_info.sizep`) by using temporary variables and adding explanatory comments about the remaining truncation limitations.

Key technical changes include:
- Updating the `odb_read_stream` struct to use `size_t` for object sizes
- Introducing `unpack_object_header_sz()` for size_t-based size returns
- Adding temporary variables and comments where API compatibility requires unsigned long
- Touching multiple subsystems (pack-objects, object-file, odb streaming) to ensure consistent size handling

The patch continues the series' pattern of mechanical but important type changes, with thorough updates across related code paths. It builds on work originally done by an anonymous contributor ("LordKiRon") that Schindelin is now shepherding through the process. The changes appear well-contained and focused on the specific Windows limitation, with clear comments explaining the remaining edge cases (like loose objects >4GB still being truncated in some paths).

This is a solid incremental step in the larger effort to properly support large objects on Windows, following the earlier patches that addressed index-pack/unpack-objects and zlib wrapper issues. The changes are low-risk but important for Windows users working with large repositories.
