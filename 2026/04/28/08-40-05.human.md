This is a platform compatibility and tooling proposal regarding Git-generated tarballs for Debian packaging. Simon Richter from the Debian project explains their need for verifiable source tarballs that can be bitwise compared to ensure no modifications were made during packaging.

The current approach using `git archive` is only accidentally reproducible and doesn't handle submodules well. Simon has created a tool that extracts tree checksums from tarballs, but it has limitations: it requires access to the original commit for verification, and doesn't work with submodules. He suggests several potential solutions, including embedding commit objects in tarcalls or extending git-archive format to better handle submodules.

The proposal is well-motivated by Debian's packaging requirements and identifies clear technical challenges. The suggested solutions seem practical, though they would require changes to Git's archive functionality. This appears to be a legitimate use case that could benefit other distributions as well, though the implementation details would need careful consideration regarding backward compatibility and security implications of embedding commit objects in tarballs.
