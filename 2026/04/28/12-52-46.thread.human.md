Johannes Schindelin (Git for Windows maintainer) reported and fixed a Windows-specific deadlock that could occur during geometric repacking in `git maintenance`. The issue affected pre-POSIX-delete Windows 10, where mmap'd pack index files would prevent child processes from deleting old packfiles. 

The fix comes in two parts: first, a test infrastructure patch that simulates legacy Windows delete behavior on modern systems using `GIT_TEST_LEGACY_DELETE`; second, the actual fix that properly sets `child.odb_to_close` in `maintenance_task_geometric_repack()` to release the object database before spawning `git repack`. This matches the pattern used by other maintenance tasks and prevents file locking issues during deletion.

The solution includes comprehensive testing - both a general test for orphaned .idx files and a Windows-specific test using the new legacy delete simulation. Johannes' implementation demonstrates deep understanding of both Windows platform specifics and Git's maintenance machinery, with clear documentation of the version-specific behavior changes that triggered this issue. The fix is straightforward and follows established patterns, addressing Git for Windows issue #6210 while maintaining compatibility with the broader geometric repacking work by Taylor Blau and Patrick Steinhardt.
