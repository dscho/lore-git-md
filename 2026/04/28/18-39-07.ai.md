This is the final documentation and test refinement patch series for the long-running `checkout -m` autostash feature, now concluding after 20 iterations (14 pre-merge + 6 post-merge). The series represents the last polish on a feature that enables automatic stashing of local changes during conflicted branch switches.

The key improvements in this v16 version focus on documentation clarity and test robustness:
1. Updated man pages for both `git-checkout` and `git-switch` to show actual output examples and use more precise wording (changing "would carry" to "will carry" for definitive behavior)
2. Simplified the merge conflict example documentation to match the new concise autostash conflict message format
3. Replaced the `show_unpack_errors` flag with a direct `quiet` boolean parameter in the merge logic, giving callers control over error suppression
4. Enhanced test coverage by:
   - Verifying stash reflog message format
   - Using heredoc for clearer test expectations
   - Consolidating duplicate test assertions
   - Adding explicit checks for untracked file safety

The implementation now cleanly handles all edge cases identified during the extensive review process, with comprehensive test coverage of:
- Conflict marker customization
- Silent operation modes
- Lockfile cleanup
- Error message suppression
- Untracked file protection
- Reflog entry formatting

This series marks the conclusion of a major feature development cycle that demonstrates Git's thorough review culture, from initial implementation through final documentation and test refinements. All technical objectives have been achieved, with any remaining architectural considerations (notably around stash message handling interfaces) explicitly deferred to potential future work.
