This is a proposal about improving tarball reproducibility and verification for Debian packaging. Simon Richter from the Debian project explains their current workflow and challenges with Git-generated tarballs.

The key issue is that while Debian needs verifiable "original" tarballs for packages, Git-generated tarballs (via `git archive`) are only reproducible by accident. Simon has created a tool that generates tree checksums for verification, but it has limitations: it requires access to the original commit object (not included in tarballs) and doesn't handle submodules well.

Two main solutions are proposed:
1. Adding commit objects and signed tags as ancillary files to the tarball
2. Extending `git archive` to include this information in pax headers

For submodules, the current workaround of concatenating multiple archives loses metadata. Simon suggests Git could be extended to create archives that properly include submodule information while maintaining verifiability.

The email asks whether these changes should be implemented in Git itself or handled within Debian's tooling. This touches on packaging workflows, cryptographic verification, and Git's archive functionality - areas where Debian's needs for deterministic builds intersect with Git's capabilities.
