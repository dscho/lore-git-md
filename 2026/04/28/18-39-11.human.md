This is a lockfile cleanup patch in the final series for the `checkout -m` autostash feature. The patch fixes several early return paths in `merge_working_tree()` that were failing to release the index lock, which could cause problems if the function were called multiple times in the same process.

The changes add `rollback_lock_file()` calls to all error paths where the function exits early, ensuring proper cleanup. While not currently causing issues (the process exits soon after these returns), this is good defensive programming that makes the code more robust for potential future use cases.

This patch represents one of the final polish items in a 21-iteration effort to implement autostash behavior for conflicted branch switches. The series has already been through extensive review and testing, with this being a straightforward cleanup of a minor oversight in the error handling paths.
