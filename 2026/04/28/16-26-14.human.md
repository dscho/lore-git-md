This is a platform compatibility patch series targeting Windows support for large objects (>4GB). The series comes from Johannes Schindelin (Git for Windows maintainer) and addresses a fundamental limitation where 32-bit `unsigned long` on Windows causes truncation of large object sizes during cloning operations.

The series makes targeted changes to handle large objects in several key areas:
- Fixes zlib wrapper to avoid BUG() assertions with >4GB streams
- Updates object size handling in pack streaming, delta headers, and index-pack/unpack-objects
- Prevents pack-objects from corrupting packs when reusing entries with truncated sizes

The last two patches add test infrastructure - a helper to generate test packs with >4GB blobs and regression tests for cloning these via both unpack-objects and index-pack paths. The commit messages note this is just the first step - many other code paths still need similar fixes for full >4GB object support.

This appears to be a well-scoped series addressing a clear Windows-specific limitation, with thorough test coverage added. The changes are focused on the most critical paths needed to make cloning work, while explicitly deferring other size-related fixes to future work. Given Schindelin's expertise in Windows compatibility and the careful approach taken, this seems like an important foundation for large object support on Windows.
