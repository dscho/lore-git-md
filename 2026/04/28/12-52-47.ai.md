This is the first patch in a two-part series addressing a Windows-specific deadlock in geometric repacking during `git maintenance`. The patch introduces test infrastructure to simulate legacy Windows file deletion behavior.

The core change adds a `GIT_TEST_LEGACY_DELETE` environment variable that forces Windows compatibility layer to use pre-POSIX delete semantics, where files cannot be deleted while memory-mapped. This allows testing the deadlock scenario on modern Windows systems that default to POSIX semantics (where mapped files can be deleted).

The implementation adds a new `legacy_delete_file()` helper that uses `SetFileInformationByHandle()` with `FileDispositionInfo` instead of `DeleteFileW()`, replicating the older Windows 10 behavior. The change is well-contained to `compat/mingw.c` and includes clear documentation of the different delete semantics.

This test infrastructure will be used in the second patch to verify the geometric repack deadlock fix works correctly. The patch comes from Johannes Schindelin (Git for Windows maintainer) and demonstrates thoughtful cross-platform testing design - the ability to simulate legacy behavior on modern systems makes the test more robust and maintainable.
