This is the final patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB) during cloning. The patch adds regression tests for the fixes implemented in previous patches.

The test creates a repository with a synthetic >4GB blob using the new test helper from patch 5, then verifies the object can be correctly cloned via both unpack-objects and index-pack paths. The test is careful to work around remaining Windows limitations (like object_info.sizep still being 32-bit) by comparing OIDs rather than sizes.

This completes the test coverage for the core cloning paths that were fixed to handle large objects on Windows. The test is skipped on 32-bit systems (SIZE_T_IS_64BIT prerequisite) and demonstrates the series' key achievement: Git can now clone repositories containing objects larger than 4GB on Windows.

The patch comes from the Git for Windows maintainer and builds on work from an anonymous contributor ("LordKiRon"). It's a well-constructed test that exercises the critical paths while acknowledging remaining limitations in other parts of the codebase.
