This is the final patch in a 3-part series refactoring `git log -L` (line-log) to integrate with Git's standard diff pipeline. The series makes line-log behavior more consistent with other diff operations and enables new capabilities.

Patch 3 expands the supported diff formats when using `-L`, allowing metadata-only formats like `--raw`, `--name-only`, `--name-status`, and `--summary`. These work because they only need the filepair information already computed for line-log ranges. The patch maintains the restriction on stat formats (`--stat`, `--numstat`, etc.) since they would show whole-file statistics rather than range-specific ones.

The changes include:
- Documentation updates explaining the newly supported formats
- Revision setup code to allow the additional formats
- Comprehensive test coverage showing the new capabilities work while stat formats remain blocked

This completes the series' goal of making line-log flow through the standard diff pipeline while maintaining all existing functionality. The implementation appears clean and well-tested, with clear commit messages explaining both the changes and remaining limitations. The series as a whole looks like a solid technical improvement to the line-log machinery.
