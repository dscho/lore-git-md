This is a feature patch that extends the `--track` option in `git checkout` and `git switch` to include a "fetch" mode that updates remote-tracking branches before creating new local branches.

The patch represents a significant redesign from previous versions, folding the standalone `--fetch` flag into the existing `--track` option as a comma-separated mode (`--track=fetch`). This addresses the maintainer's philosophical concerns by tying the fetch behavior explicitly to branch tracking setup rather than making it a general checkout feature.

Key technical changes:
- Replaces the previous `--fetch` flag with `--track=fetch` syntax
- Removes the `checkout.fetch` config option
- Adds a new parser callback to handle the comma-separated track modes
- Maintains the same underlying fetch behavior (single-branch fetch when possible, full remote fetch otherwise)
- Includes comprehensive tests for the new syntax and combinations with other track modes

The implementation remains technically solid, with careful attention to edge cases and thorough test coverage. However, the fundamental philosophical disagreement about whether this behavior belongs in Git's workflow model persists. The maintainer had previously rejected the concept as workflow-inappropriate despite the technical completeness, and this redesign doesn't fundamentally alter those objections.

The patch shows responsiveness to feedback by restructuring the feature to align with Git's tracking concepts, but the core debate about remote-tracking branch stability versus convenience remains unresolved. The thread appears to be at an impasse unless new arguments emerge that satisfy the workflow concerns.
