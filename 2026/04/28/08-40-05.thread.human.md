Simon Richter from the Debian project has raised an important issue about the reproducibility and verification of Git-generated tarballs used in Debian packaging. Currently, Debian requires verifiable original tarballs for packages, but `git archive` produces tarballs that are only reproducible by coincidence. Simon has developed a tool that generates tree checksums for verification, though it has limitations - it needs access to the original commit object (which isn't included in tarballs) and doesn't properly handle submodules.

Two potential solutions are on the table: either including commit objects and signed tags as additional files in the tarball, or extending `git archive` to embed this information in pax headers. The submodule case presents additional challenges, as the current practice of concatenating archives loses important metadata. Simon is seeking input on whether these changes should be implemented within Git itself or handled through Debian-specific tooling, highlighting the intersection between Git's capabilities and Debian's needs for deterministic, verifiable builds.
