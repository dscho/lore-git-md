This thread explores the challenges of creating reproducible tarballs with `git archive`, particularly for packaging workflows. Simon Richter from Debian kicked off the discussion by highlighting issues with commit objects and submodules in verifiable tarballs. Theodore Tso then contributed practical insights from e2fsprogs packaging, noting compression parameter variations and timestamp inconsistencies.

brian m. carlson has now responded with a broader architectural analysis, identifying three main reproducibility obstacles: the variable nature of `export-subst` (which embeds short object IDs), compression inconsistencies (since Git doesn't control external compressors), and timestamp handling in zip files. They propose a versioned approach where Git could offer explicitly reproducible formats that disable non-deterministic features, suggesting this would be easier to implement in Rust due to better data structures.

The discussion now spans both high-level design questions (like whether to modify `git archive` or packaging tooling) and implementation details (compression parameters, timestamp handling).
