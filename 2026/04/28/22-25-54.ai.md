This is a refactoring patch (part 3/5) in Kristoffer Haugsbakk's series introducing the new `git format-rev` command. The patch factors out common code from `name-rev.c` to prepare for sharing with the upcoming command.

Key changes:
- Introduces a `command` struct with tagged union to handle command-specific payloads (currently just NAME_REV with name_only flag)
- Extracts `name_rev_line()` functionality to work with the new command abstraction
- Maintains identical behavior while restructuring the code to be more generic
- Prepares the ground for the subsequent introduction of FORMAT_REV command type

The refactoring is mechanical and well-contained, with no functional changes. It follows the pattern seen in earlier preparatory patches in this series - cleaning up and modularizing the code before introducing new functionality. The patch continues the architectural shift from v2's approach of extending `git name-rev` to v3's cleaner separation of concerns via a new command.

This intermediate step demonstrates careful attention to code structure, ensuring the shared functionality will work cleanly for both commands. The BUG() case for uncovered command types suggests the author is thinking defensively about future maintenance.
