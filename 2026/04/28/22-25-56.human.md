This is the final patch in Kristoffer Haugsbakk's series introducing the new experimental `git format-rev` command, a feature that provides on-demand formatting of revision expressions. The command fills a gap where users need to format individual commits outside of graph-walking commands like `git log`.

The new `git format-rev` offers two input modes:
- `--stdin-mode=revs` for processing one revision per line
- `--stdin-mode=text` for finding and formatting commit hashes in freeform text

The implementation shares infrastructure with `git name-rev` (refactored in earlier patches) while adding support for Git's full pretty formatting capabilities, including notes display via `%N`. The patch includes comprehensive documentation with practical examples showing how to:
- Format output from `git last-modified`
- Process commit hashes in commit messages
- Handle custom and multiple notes references

The command is marked EXPERIMENTAL to allow for interface refinement, though the implementation appears solid with thorough test coverage. This addresses real workflow needs that were awkward with existing commands, particularly cases requiring processing of duplicate or mixed input that `git log`/`git show` handle poorly.

The series has evolved thoughtfully through three versions, moving from extending `git name-rev` to this cleaner standalone command approach. While still experimental, it represents a well-considered addition to Git's revision formatting toolkit.
