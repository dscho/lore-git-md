This is the final implementation patch in the long-running series to add autostash behavior to `git checkout -m`. The feature enables automatic stashing of local changes during conflicted branch switches, providing a safer alternative to the previous behavior which could lose work.

The patch implements the core autostash functionality for `git checkout -m` by:

1. Creating a temporary stash when branch switching would cause conflicts with local changes
2. Attempting to reapply the stash after switching branches
3. Preserving the stash if conflicts occur during reapplication, with clear user instructions for recovery
4. Showing which files were modified after successful application
5. Handling edge cases like untracked files and mixed staged/unstaged changes

Key technical changes include:
- New `MERGE_WORKING_TREE_UNPACK_FAILED` constant to signal merge conflicts
- Modified `merge_working_tree()` to attempt stash creation and reapplication
- Updated documentation for both `git-checkout` and `git-switch` to explain the new behavior
- Comprehensive test coverage including conflict scenarios, reflog verification, and untracked file handling

The implementation builds on the earlier groundwork from the series, now providing full feature parity between manual stash operations and the new autostash behavior during branch switching. All edge cases identified during the extensive review process have been addressed, making this a robust addition to Git's branch switching capabilities.

This marks the conclusion of a 21-iteration development effort (14 pre-merge and 7 post-merge patches) that demonstrates Git's thorough review culture. The feature is stable and ready for inclusion, with all technical objectives achieved and comprehensive test coverage in place.
