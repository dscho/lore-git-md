This is a continuation of the discussion about making Git-generated tarballs verifiable for Debian packaging workflows. Simon Richter responds to brian m. carlson's points about Git's lack of reproducibility guarantees for `git archive` output.

Simon clarifies that Debian's approach already accounts for some of the variation sources mentioned - they calculate checksums of the corresponding tree objects rather than the tarball contents directly, avoiding issues with compression differences. However, he notes that `export-subst` remains problematic since it can embed short object IDs that change when repository contents change, breaking verification.

The exchange highlights the technical constraints of the current system while maintaining focus on the core need - reliably verifying tarball contents for Debian's packaging system. Simon's response suggests the discussion is narrowing to the remaining challenges (like `export-subst` handling) rather than the broader reproducibility questions that carlson raised. The thread continues to explore where additional verification information should be stored - within the archive or in separate files.
