Johannes Schindelin's series addressing Windows' 4GB+ object handling limitations has progressed to its second iteration, with 11 patches now covering the core fixes, test infrastructure, and CI integration. The series systematically replaces 32-bit types with 64-bit size_t across critical paths (index-pack, zlib wrappers, ODB streaming) while maintaining compatibility. Notable test optimizations include unsafe SHA-1 hashing (3-5x speedup) and precomputed packfiles (reducing test generation from minutes to seconds), now extended to support both SHA-1 and SHA-256 repositories. The tests are properly gated as EXPENSIVE and only run in CI on push builds to avoid resource issues.

Derrick Stolee, who previously raised concerns about test execution time (leading to the CI gating in patch 11/11), has now reviewed patch 8/11's test optimizations. His latest review asks for clarification on whether the performance numbers account for both the unsafe SHA-1 optimization from earlier patches and the new precomputed pack approach. This demonstrates careful attention to how the optimizations compound across the series. While not requiring code changes, the question ensures accurate performance claims for this sensitive area affecting large repository operations on Windows. The series appears technically sound and nearing readiness, with Schindelen showing good responsiveness to reviewer feedback throughout.
