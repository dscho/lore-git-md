This thread addresses Windows-specific issues with handling large Git objects (>4GB) during cloning, where 32-bit types cause truncation problems. Johannes Schindelin (Git for Windows maintainer) has sent an 11-patch series (now at v3) that systematically replaces these with 64-bit types while maintaining compatibility. The changes span index-pack/unpack-objects, zlib wrappers, ODB streaming, and delta handling, with extensive test infrastructure work to verify the fixes.

The latest patches focus on optimizing the test suite to make large-object testing practical. Patch 8/11 introduced precomputed pack structures for 4GB+1 NUL-filled blobs, reducing test runtime from 75-80 seconds to under 21 seconds. The new patch (9/11) extends this optimization to SHA-256 repositories by adding SHA-256 variants to the precomputed test packs, maintaining the same performance benefits while ensuring coverage across hash algorithms.

Key reviewers including Jeff King and Torsten Bögershausen have had their performance and type-safety concerns addressed in this iteration. The series now handles all critical paths for >4GB objects during cloning, though some follow-up work remains for cat-file and loose object handling. The changes demonstrate careful attention to both platform compatibility and test suite practicality, with the SHA-256 support showing forward-looking consideration for users of alternative hash algorithms.
