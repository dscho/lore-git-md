Johannes Schindelin has been leading a series to fix Windows platform limitations when handling large objects (>4GB) during cloning, addressing truncation issues caused by 32-bit types. The six-part series systematically converts problematic unsigned long types to 64-bit size_t across index-pack, unpack-objects, zlib wrappers, ODB streaming, and delta handling, while adding test infrastructure and regression tests. The changes are mechanical but important for correct large-object support on Windows.

The technical work appears sound, with Derrick Stolee having approved the core approach earlier in the thread. The current discussion has shifted to test suite ergonomics, where both Stolee and Jeff King (Peff) have raised concerns about the regression tests' resource demands - particularly their long runtime (160 seconds for t5608 alone) and significant disk space requirements (4-8GB). Peff notes the tests are already gated behind GIT_TEST_CLONE_2GB but suggests better integration with Git's existing EXPENSIVE test infrastructure. This practical discussion about test management, while not directly about the patches' technical content, will need resolution before the series can be finalized. The core fixes themselves seem ready, with follow-up work identified for other code paths like pack-objects reuse and cat-file handling.
