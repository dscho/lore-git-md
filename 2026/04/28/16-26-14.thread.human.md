This thread addresses Windows platform limitations when handling large objects (>4GB) during cloning, where 32-bit types cause truncation issues. Johannes Schindelin (Git for Windows maintainer) has submitted a six-patch series that systematically replaces problematic unsigned long types with 64-bit size_t in critical paths (index-pack, unpack-objects, zlib wrapper, ODB streaming, and delta headers), while maintaining compatibility. The series includes both mechanical fixes and new test infrastructure to verify the changes.

Derrick Stolee has reviewed the series twice - first approving the transitional strategy in patch 4/6, and now raising practical concerns about the test execution time impact of the new regression tests in patches 5-6. While supporting the technical approach, he questions whether creating and cloning 4GB+ test repositories should be marked as "expensive" by default, suggesting this might be better enabled specifically for Git for Windows where the platform issue is most relevant. The discussion remains constructive, with agreement that additional work remains (particularly for pack-objects reuse, cat-file, and delta machinery), but differing perspectives on how heavily to test these fixes in the core suite versus platform-specific builds.
