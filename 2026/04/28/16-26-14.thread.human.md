Johannes Schindelin's series addressing Windows' handling of large objects (>4GB) continues with a regression test patch (6/11) that validates the core fixes. The test uses the new `test-tool synthesize pack` infrastructure from earlier in the series to create a repository with a 4GB+1 byte blob, then verifies successful cloning through both unpack-objects and index-pack paths by comparing object IDs. 

The series has evolved through constructive feedback, with Schindelin adapting to concerns about test resource usage by marking these as EXPENSIVE tests (160s runtime, 4-8GB disk space). While the core object handling issues are now addressed, some limitations remain - particularly around size reporting on Windows where 32-bit types persist in certain paths. The test deliberately compares OIDs rather than sizes to work around this known constraint. 

Key participants have weighed in on tradeoffs: Derrick Stolee raised runtime concerns, Jeff King noted disk space implications, and Schindelen has shown willingness to compromise on test infrastructure while maintaining the essential Windows fixes. The series represents significant progress on a longstanding platform limitation, with the current iteration systematically addressing components from zlib wrappers to delta handling while laying groundwork for future work on loose object paths.
