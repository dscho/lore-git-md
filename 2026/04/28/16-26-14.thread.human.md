Johannes Schindelin (Git for Windows maintainer) is leading a series to fix Windows-specific issues with handling large objects (>4GB) during cloning operations. The core problem stems from 32-bit types (unsigned long) causing truncation in critical paths. The six-part series systematically replaces these with 64-bit size_t while maintaining compatibility, covering index-pack/unpack-objects, zlib wrapper, ODB/packfile streaming, delta headers, and adding test infrastructure and regression tests.

The patches have seen positive technical engagement, with Derrick Stolee approving the approach while suggesting test suite optimizations to handle the resource-intensive 4GB+ tests. Torsten Bögershausen recently noted this work supersedes a related GitHub pull request (#2179), connecting the mailing list discussion with prior efforts. The series appears technically sound but still needs follow-up work on pack-objects reuse logic and other code paths like cat-file. Testing remains a focus area, with discussions ongoing about how to balance comprehensive coverage with practical CI constraints.
