This thread addresses Windows platform limitations when handling large objects (>4GB) during cloning, where 32-bit types cause truncation issues. Johannes Schindelin (Git for Windows maintainer) has submitted a six-patch series that systematically replaces problematic unsigned long types with 64-bit size_t across index-pack, unpack-objects, zlib wrappers, ODB streaming, and delta header handling, while maintaining API compatibility. The final patch adds regression tests for >4GB object cloning, though these are gated behind size and resource constraints.

The series builds on work by an anonymous contributor ("LordKiRon") and supersedes a prior GitHub PR (#2179). While the technical approach has been validated—including the transitional strategy of implementing 64-bit versions first then down-casting—several open questions remain. These include long-term API improvements for object size handling, test execution time/resource optimization (raised by Derrick Stolee and Jeff King), and broader challenges around upstreaming Windows-specific fixes via the mailing list workflow. The latest interaction confirms the methodology is sound but doesn't resolve the thread's outstanding issues around test infrastructure and remaining code paths needing similar fixes.
