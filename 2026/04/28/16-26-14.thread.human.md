Johannes Schindelin's patch series addressing Windows' 4GB object size limitations has progressed to its second version, with 11 patches covering index-pack, zlib wrappers, and test infrastructure. The core issue involves replacing 32-bit types with 64-bit size_t to properly handle large objects during cloning. While most technical aspects have been addressed, two patches (1/11 and 3/11) remain under review for type safety concerns raised by Torsten Bögershausen.

The series has uncovered an unexpected CI issue where glibc's use of C11 features conflicts with clang's strict C99 checking on older Ubuntu runners. Junio Hamano provided historical context about similar system header/compiler interactions, while Patrick Steinhardt diagnosed the specific problem (glibc's use of `_Generic` instead of `_has_feature`) but doesn't propose further fixes, accepting it as a known limitation. The team has worked around this by marking the large-object tests as EXPENSIVE and only running them on push builds.

Performance optimizations have been a notable subplot, with Johannes demonstrating both platform-specific (3-5x speedup using unsafe SHA-1 on Linux) and cross-platform (5-10x speedup using precomputed packs) approaches. The discussion shows effective collaboration between Windows specialists (Johannes), infrastructure experts (Patrick), and the maintainer (Junio) to navigate both the core Windows limitations and the emergent CI challenges.
