This is the first patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The change focuses on fixing object size truncation in index-pack and unpack-objects by switching from `unsigned long` to `size_t` for object size handling.

The key technical change ensures object sizes are processed in 64-bit space even on Windows (where `unsigned long` is 32-bit), preventing corruption when unpacking large objects from packfiles. The patch modifies both the data structures and the variable-length encoding logic that reads packfile entries.

The change is mechanical but critical - it fixes a real data corruption issue for Windows users working with large repositories. The patch credits an anonymous contributor ("LordKiRon") who preferred not to reveal their identity, with Schindelen taking over authorship for mailing list submission.

This is a foundational change for the series, addressing one of the core issues that prevents correct handling of large objects during cloning operations on Windows. The subsequent patches in the series will build on this to fix related issues in other subsystems.
