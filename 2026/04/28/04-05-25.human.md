This is the second patch in a 3-part series refactoring `git log -L` (line-log) to integrate with Git's standard diff output pipeline. The current implementation takes a separate shortcut path, causing inconsistencies with other diff operations.

The key change in this patch moves line-log processing through the standard `log_tree_diff()` -> `log_tree_diff_flush()` path used by regular diffs. This fixes several long-standing issues:
- Pickaxe (`-S`, `-G`) and `--diff-filter` now properly suppress commits when all line-log pairs are filtered out
- Commit/diff separator behavior now matches regular log output
- The patch explicitly blocks `--full-diff` which doesn't make sense with `-L`

The implementation renames `line_log_print()` to `line_log_queue_pairs()` and restructures the flow to queue filepairs first, then let the standard diff pipeline handle the rest. This is a clean technical improvement that makes line-log behave more consistently while enabling new test cases to verify the fixed behaviors.

The patch includes thorough test updates showing the corrected output formats and new capabilities. It builds on the preparatory changes in patch 1/3 and sets up for the expanded diff format support coming in patch 3/3. The changes are well-contained and the commit message clearly explains both the technical problem and solution.
