Feature patch extending `--track` with a "fetch" mode to automatically fetch remote refs before branch creation.

This is the fifth iteration of Harald Nordgren's proposal to streamline the common workflow of fetching before creating a tracking branch. The patch has undergone significant redesign since v4, folding the functionality into the existing `--track` option rather than adding a separate `--fetch` flag. The key changes are:

1. The standalone `--fetch` flag and `checkout.fetch` config are removed entirely
2. Fetch behavior is now triggered via `--track=fetch` (combinable with other modes like `--track=fetch,inherit`)
3. New parser logic in `parse_opt_checkout_track()` handles the comma-separated tracking modes
4. Tests have been updated to use the new syntax and verify mode combinations

The implementation remains technically solid, with careful attention to edge cases and thorough test coverage. The patch demonstrates responsiveness to prior feedback by integrating with Git's existing tracking infrastructure rather than adding parallel mechanisms. However, the fundamental philosophical disagreement with the maintainer about whether this behavior belongs in Git's workflow model remains unresolved. While the technical execution has improved, the higher-level design objections about remote-tracking branch invariants and workflow implications persist unchanged from earlier iterations.
