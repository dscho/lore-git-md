This is a response in the thread about Git-generated tarballs for Debian packaging. brian m. carlson provides important technical context about `git archive`'s behavior that affects reproducibility.

Key points from this reply:
- `git archive` output is not guaranteed to be identical across Git versions (a past format change broke kernel.org)
- Several factors can cause variation: `export-subst` producing different-length object IDs, different compression tools (zlib vs pigz vs gzip)
- The author mentions having previously intended to create a reproducible format for `git archive` and suggests it might be easier now with Rust support
- References their experience with Git LFS producing bit-for-bit identical source tarballs

The response serves as a caution against assuming `git archive` output will be stable, while also indicating there may be interest in standardizing a reproducible format. This provides important constraints for any solution to Debian's packaging needs. The mention of Rust suggests one possible implementation path, though no concrete proposal is made here.
