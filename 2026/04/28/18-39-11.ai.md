This is a lockfile cleanup patch in the final series for the `checkout -m` autostash feature. The patch addresses a subtle resource management issue in `merge_working_tree()` where early returns could leave the index lock held. While currently harmless since the process exits soon after, this could cause problems if the function were called multiple times in the same process.

The changes add `rollback_lock_file()` calls to all early return paths in the function, ensuring proper cleanup. The patch demonstrates the thoroughness of the review process - even after 20 iterations, edge cases like this were identified and fixed before finalizing the feature. The implementation is straightforward and mechanical, wrapping each early return with the necessary cleanup while maintaining the existing behavior.

This represents one of the final polish items for the long-running autostash effort, showing the project's attention to detail in resource management even for cases that don't currently manifest as bugs. The patch has Harald Nordgren's sign-off and builds on Phillip Wood's earlier review feedback about lockfile handling.
