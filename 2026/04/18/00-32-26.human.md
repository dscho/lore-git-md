This is the second patch in Elijah Newren's performance optimization series for partial clone behavior, focusing on `git cherry`. The patch implements batch prefetching of blobs to avoid the performance penalty of individual on-demand fetches in partial clones.

The key technical contribution is a clever hashmap comparison function swap trick in `prefetch_cherry_blobs()` that allows identifying which blobs would be needed for collision resolution without actually fetching them. The function:

1. Temporarily replaces the hashmap's comparison function with an always-match function
2. Enumerates all potential collisions that would trigger blob fetches
3. Collects the blob OIDs from these potential collisions
4. Restores the original comparison function
5. Performs a single batch fetch of all needed blobs

The implementation handles edge cases like binary files (skipped since patch-ids don't examine their content) and includes tests verifying the prefetch behavior in a partial clone scenario. The test confirms that multiple blobs are fetched in a single batch operation rather than individually.

This follows the established pattern of batch prefetching seen in other Git commands and completes the optimization for `git cherry` in partial clone workflows. The patch is well-contained, touching only `builtin/log.c` and adding a test case, while building on existing partial clone infrastructure.
