This thread documents the implementation of `--max-count-oldest`, a new revision walk feature that shows the oldest N commits in a history (complementing the existing `--max-count` for newest commits). After eight iterations of review and refinement, the feature is now merge-ready.

The implementation uses Jeff King's efficient sliding window algorithm while maintaining compatibility with other revision walk features like `--boundary` and `--graph`. Key technical work included extending `struct rev_info` with new flags, placing the counting logic in `get_revision_internal()`, and fixing subtle edge cases in graph output handling. Johannes Sixt provided crucial guidance on architectural integration points.

Mirko Faina drove the implementation through multiple rounds of review, addressing feedback from Junio C Hamano (who approved the interface naming and final polish), Tian Yuchen (edge case analysis), and Jean-Noël Avila (documentation standards). The test suite was made fully portable across platforms, resolving all CI issues. With all technical and documentation requirements now satisfied, this provides a robust solution for viewing early commit history while maintaining Git's performance characteristics.
