This thread discusses Mirko Faina's proposal to add a `--reverse=before` option to control when commit reversal happens during revision walks. The implementation is technically complete in v4, featuring a memory-efficient sliding window approach (based on Jeff King and Tian Yuchen's input) and thorough documentation. While the core functionality has consensus, the interface design is now being debated at a philosophical level.

Junio C Hamano has stepped in to strongly advocate for Johannes Sixt's alternative `--max-count-oldest` naming, arguing it better reflects the conceptual model of controlling when limits are applied rather than when reversal occurs. This creates a tension between technical precision (Mirko's current implementation accurately describes what happens internally) and usability (Junio's preference for terminology that matches user expectations). The underlying technical work - including the sliding window optimization and state machine changes - would likely remain valid regardless of which naming approach is chosen.

With the implementation polished and only minor test/style nits remaining, the thread has reached a decision point: proceed with the current technically-accurate interface or redesign the user-facing options to better match mental models. Junio's position as maintainer gives his preference significant weight, though the technical contributors have invested considerable effort in the current approach. The next steps will likely involve either Mirko adapting the interface or the group reaching consensus on why the technical names are worth preserving despite being less intuitive.
