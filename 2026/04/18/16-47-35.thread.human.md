This thread discusses Mirko Faina's proposal to add a `--reverse=before` option to Git's revision walk, which would reverse commits before applying limits (as opposed to the current `--reverse` which reverses after). The technical implementation has been worked out with input from Jeff King (Peff) and Ben Knoble, using an enum-based state machine that maintains backward compatibility while adding the new syntax.

Junio Hamano, the Git maintainer, has raised conceptual questions about whether framing this as a `--reverse` variant is the most intuitive approach, suggesting it might be better understood as "applying count limits later." Tian Yuchen has now weighed in on potential performance optimizations, noting that while a sliding window approach could reduce memory usage for small commit counts, it would be complicated to maintain when combined with other filters like `--author` or `--min-parents`. Yuchen agrees with Junio that the feature's mental model may need refinement.

The implementation itself is technically sound, with all parsing behavior and edge cases addressed. The discussion has now shifted to higher-level design questions about how users will understand and interact with the feature. Mirko is expected to address these concerns in an upcoming v2 submission. The key files involved remain `revision.c`, `list-objects.c`, and the rev-list documentation.
