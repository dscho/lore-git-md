The `--max-count-oldest` feature for revision walks has completed its development cycle and is now being merged into Git. After eight iterations of the patch series, with thorough technical review from Jeff King, Johannes Sixt, Tian Yuchen, and others, Junio C Hamano has confirmed the implementation meets all requirements and is ready to graduate to the 'next' integration branch.

The feature provides an optimized way to view the earliest commits in a history while maintaining Git's architectural constraints, using Jeff King's efficient sliding window algorithm. The final version handles all edge cases, maintains compatibility with other revision walk features like `--graph` and `--boundary`, and includes comprehensive test coverage. Documentation has been polished to clearly contrast the new `--max-count-oldest` option with the existing `--max-count`.

Mirko Faina, the patch author, has incorporated all feedback through multiple rounds of review, addressing everything from core algorithm concerns to final CI portability fixes. With no outstanding objections and all technical requirements satisfied, this marks the successful conclusion of the development effort. The feature will now proceed through Git's standard integration process before appearing in a future release.
