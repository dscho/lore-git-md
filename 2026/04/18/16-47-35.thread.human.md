This thread introduces a new `--reverse=before` option for Git's revision walk, allowing commits to be reversed before applying count limits (unlike the existing `--reverse=after` behavior). The feature has gone through four iterations, with the first patch establishing the core functionality and this second patch adding memory optimizations.

The implementation follows Jeff King's suggested state machine approach, with the memory optimization using a sliding window technique to reduce memory usage from O(N) to O(K) when using `--reverse=before` with `--max-count`. Tian Yuchen's performance analysis helped refine this approach. The patches touch `revision.c`, `list-objects.c`, and include comprehensive documentation and test coverage.

All technical feedback from reviewers (Jeff King, Tian Yuchen, D. Ben Knoble) has been addressed across the four versions. The only remaining open item is Junio C Hamano's conceptual review of the high-level design. The patches appear functionally complete and ready for maintainer consideration, with both the core behavior and memory optimizations now stable.
