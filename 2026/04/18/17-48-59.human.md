This is a follow-up to the gitk race condition bugfix discussion. Johannes Sixt (gitk maintainer) responds to Michael Warmuth-Uhl's patch that addressed a long-standing issue where view changes could crash gitk when background diff operations were still running.

Johannes acknowledges the problem and Michael's solution (waiting for pending operations to complete), but notes that simply clearing the run queue as Michael proposed introduces a different error ("can't unset 'currunq'") due to recursive execution of the task processor. He provides an alternative patch attempt that forcibly closes file descriptors and clears the queue, though it doesn't fully resolve the issue either.

The exchange highlights the tricky nature of fixing this race condition - the straightforward approaches either block too aggressively (waiting for all operations) or fail to properly clean up in-progress work. Johannes indicates he'll investigate further when time permits, but makes no promises about an immediate resolution. This leaves the thread in a state where the problem is well-understood but a fully satisfactory solution remains elusive.
