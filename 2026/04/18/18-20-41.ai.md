This is a review response to a feature patch adding `--reverse=before` functionality to revision walks. Tian Yuchen provides substantive feedback on Mirko Faina's proposed implementation.

The review focuses on two main aspects: user experience and implementation efficiency. Yuchen suggests the naming (`before`/`after`) might not be intuitive for users who simply want "oldest commits" rather than thinking about the internal ordering mechanics. They propose considering more user-centric terminology that better matches the mental model of wanting "first N commits versus last N commits."

On the implementation side, Yuchen notes the current approach loads the entire reversed commit history into memory when using `--reverse=before`, which could be inefficient for large repositories when only a few commits are needed. They suggest exploring alternatives like maintaining a finite window or max heap to reduce memory usage.

The review is technically detailed, referencing specific code sections and proposing concrete improvements while acknowledging the soundness of the overall approach. Yuchen's comments demonstrate familiarity with Git's revision walking machinery and consideration for both user experience and performance implications.
