This is a documentation patch from Lorenzo Pegorari's GSoC project on promisor file handling during repacks (v6 series). It adds explanatory comments to clarify the purpose of ref names and hashes stored in `.promisor` files.

The patch explains that while these ref names and hashes (written during packfile creation) aren't used in normal operations, they serve an important debugging role for partial clones. The information allows developers to see what refs were fetched when the packfile was downloaded, enabling comparison with current remote states if issues arise.

The comment follows the style established in commit 5374a290 (which introduced this functionality) and has been reviewed by Junio Hamano. This is a straightforward documentation improvement that provides useful context for future maintainers working with promisor files. The patch is part of a larger series that has already addressed all substantive technical concerns through five previous iterations.
