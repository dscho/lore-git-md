This is a follow-up to the gitk race condition bugfix thread. Johannes Sixt (gitk maintainer) responds to Michael Warmuth-Uhl's patch that addressed the "can't read 'treediffs'" error by waiting for pending diff operations to complete before view changes.

Johannes acknowledges the issue and Michael's solution, but notes that simply waiting for completion isn't ideal. He shares an alternative approach that attempts to actively clear the run queue instead of waiting, but reports this still triggers an error ('can't unset "currunq"') due to recursive execution of the dorunq procedure. The patch he provides shows the queue-clearing attempt, which involves:
- Iterating through pending runq operations
- Closing any open file descriptors
- Unsetting script tracking variables
- Clearing the runq list entirely

The maintainer indicates he'll investigate further when time permits, but doesn't expect an immediate solution. This keeps the thread open for potential alternative approaches to solve the race condition without the performance penalty of waiting for all operations. The exchange demonstrates the complexity of gitk's asynchronous task handling and the challenge of cleanly canceling in-progress operations.
