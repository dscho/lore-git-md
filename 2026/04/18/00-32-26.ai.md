This is the second patch in Elijah Newren's performance optimization series for partial clone behavior, specifically targeting `git cherry`. The patch implements batch prefetching of blobs to avoid the performance penalty of individual on-demand fetches in partial clones.

The key technical contribution is the new `prefetch_cherry_blobs()` function, which:
1. Temporarily replaces the hashmap comparison function with a no-op to identify potential blob collisions without triggering fetches
2. Collects all blob OIDs that would be needed for patch ID computation
3. Performs a single batch fetch of these blobs before restoring the original comparison function
4. Includes logic to skip binary files (which don't need blob content for patch IDs)

The implementation follows established patterns from other commands that support batch prefetching, using `oidset` and `promisor_remote_get_direct()` for efficient blob fetching. The patch includes tests verifying the prefetch behavior in a partial clone scenario, confirming that blob fetches are batched rather than performed individually.

This is a well-contained change focused specifically on the `git cherry` command's performance characteristics in partial clones. The implementation appears robust, with careful handling of edge cases (binary files, merge commits) and clear separation from the core patch ID computation logic. The accompanying test provides concrete validation of the optimization's effectiveness.
