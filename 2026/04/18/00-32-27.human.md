This is the final patch in Elijah Newren's performance optimization series for partial clone behavior, focusing on `git grep`. The patch adds batch prefetching of blobs to avoid the slow one-at-a-time fetching that currently happens in partial clones.

The implementation:
- Adds a new `prefetch_grep_blobs()` function that first walks the tree to collect all blob OIDs that match the pathspec
- Uses an oidset to track blobs and converts it to an oidarray for batch fetching via `promisor_remote_get_direct()`
- Explicitly skips submodules since they have their own promisor configuration
- Includes a new test case that verifies the bulk prefetch behavior in a partial clone scenario

The changes are well-established patterns seen in other commands that already support batch prefetching (like checkout/diff/merge). The patch is cleanly focused, touching only `builtin/grep.c` and adding a test case. With this addition, both `git cherry` (from earlier patches) and `git grep` now benefit from the same performance improvements in partial clone scenarios.

This completes the optimization effort with no outstanding issues - the series appears ready for merging after addressing the maintainer's earlier feedback about documentation formatting. The changes should provide measurable speedups for partial clone users of these commands.
