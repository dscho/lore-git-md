This is the final patch in Elijah Newren's performance optimization series for partial clone behavior, focusing on `git grep`. The patch 3/3 adds batch prefetching to `git grep` to avoid the performance penalty of individual blob fetches in partial clones.

The implementation introduces:
1. A tree-walking mechanism (`collect_blob_oids_for_tree`) that gathers all blob OIDs matching the search pathspec
2. A prefetch helper (`prefetch_grep_blobs`) that batches the blob requests using the promisor-remote interface
3. Careful handling of submodules (explicitly excluded since they have their own fetch configuration)
4. A new test case verifying the bulk prefetch behavior in blobless clones

The changes are well-contained, touching only `builtin/grep.c` and adding a test to `t/t7810-grep.sh`. The implementation follows the same pattern established in earlier patches for `git cherry`, using `oidset` for blob collection and `promisor_remote_get_direct()` for batch fetching. The test demonstrates the optimization by showing all 3 blobs being fetched in a single operation when searching a partial clone.

This completes the series' goal of extending batch prefetching to commands that previously suffered from poor partial clone performance. With all three patches now addressing `git cherry` and `git grep`, the maintainer's feedback has been incorporated and the series appears ready for merging.
