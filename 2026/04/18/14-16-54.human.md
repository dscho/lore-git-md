This is a documentation patch from Lorenzo Pegorari's GSoC project on promisor file handling during repacks (now at v6). The patch adds a clarifying comment to `pack-write.c` explaining the purpose of ref names and hashes stored in `.promisor` files.

The comment explains that while these ref details aren't used in normal operations, they serve a debugging purpose - allowing developers to identify which refs were fetched when a packfile was downloaded and compare them against current remote state if needed. This addresses a gap where the rationale wasn't previously documented in the code, though it was mentioned in commit 5374a290's message.

The patch is straightforward and well-motivated, with Junio Hamano providing guidance (as noted in the Helped-by trailer). As part of a larger series that has already undergone extensive review, this documentation improvement helps future maintainers understand the context of this debugging feature. The change is purely additive and uncontroversial, aligning with the project's emphasis on clear code documentation.
