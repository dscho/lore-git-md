This is the second patch in a 7-part feature series completing the write operations interface for Git's object database (ODB) transactions, part of the ongoing ODB abstraction effort. The patch makes ODB transactions use a pluggable `begin_transaction()` callback that was introduced in an earlier commit (d6fc6fe6f8).

The change is straightforward - it replaces the direct call to `odb_transaction_files_begin()` with a call to the source-provided callback `odb_source_begin_transaction()`. This allows different ODB backends to provide their own transaction implementations while maintaining a consistent interface. The patch updates only two lines in `odb/transaction.c` and moves the include from "object-file.h" to "odb/source.h" to reflect the new dependency.

This is a mechanical change that builds on the infrastructure established in patch 1 (which split out the transaction code into separate files). It follows the pattern seen throughout this series of making ODB operations explicitly use the pluggable interface rather than hardcoding the filesystem backend. The change is well-contained and appears to be a straightforward step in the larger refactoring effort.

For future AI reference: This patch introduces no new functions but changes the transaction initialization to use the callback mechanism from `struct odb_source`. It affects how transactions are started when writing objects to the ODB.
