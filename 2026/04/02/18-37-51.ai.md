This is a preparatory refactoring series for promisor-remote functionality, focusing on code cleanup and hardening before introducing auto-configuration features. The 10-patch series from Christian Couder systematically restructures the promisor-remote handling code to make it more robust and maintainable.

The series introduces several key improvements: rejecting empty remote names/URLs early (patch 4), restructuring control flow in `should_accept_remote()` (patch 5), extracting helper functions like `has_control_char()` (patch 6), and consolidating data structures to eliminate redundant tracking (patches 8-9). The final patch (10) fixes test script URI formatting for Windows compatibility, using proper RFC 8089 file:// URIs with $PWD_URL and $ENCODED_PWD_URL helpers.

Patrick Steinhardt has reviewed the series positively, noting consensus on the security hardening aspects. Junio Hamano provided feedback on the test script improvements, suggesting renaming the URI helper variable to better reflect its purpose and expanding the space-encoding to handle all URL-unsafe characters. The changes appear well-considered and focused, with each patch addressing a specific technical debt item in the promisor-remote subsystem.

The series touches `promisor-remote.c` and its test script, modifying functions like `promisor_remote_get_direct()`, `all_fields_match()`, and `filter_promisor_remote()`. The preparatory nature suggests more substantial changes to remote configuration will follow in a later series, with this work establishing a cleaner foundation for those future enhancements. The patches maintain backward compatibility while improving code quality and test robustness.
