This is the first patch in a feature series introducing new `includeIf` conditions for worktree path matching in Git configs. Chen Linxuan proposes adding `worktree:<pattern>` and `worktree/i:<pattern>` conditions to complement the existing `gitdir` and `onbranch` options.

The change refactors the existing path matching logic in `config.c` to handle both gitdir and worktree paths through a shared `include_by_path()` helper. The new conditions match against the actual worktree path (from `repo_get_work_tree()`) rather than the `.git` directory location, which is particularly useful in multi-worktree setups where gitdirs all point to the main repository's `.git/worktrees/` directory.

The implementation is cleanly separated from the existing logic and maintains all current behavior while adding the new functionality. The patch includes careful handling of path resolution, case sensitivity, and edge cases like bare repositories. This appears to be a well-considered addition that solves a real configuration management pain point for users with multiple worktrees.
