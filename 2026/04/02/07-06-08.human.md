This is part 5 of Christian Couder's 10-patch series refactoring promisor-remote handling. The series is preparing for future auto-configuration features while cleaning up the existing code.

This patch focuses on control flow restructuring in `should_accept_remote()`, which determines whether to accept a promisor remote from a server. The key changes are:

1. Replaces a warning about empty URLs with a BUG() assertion, since empty URLs are now caught earlier in the parsing phase (as established in patch 4). This makes the code more defensive by treating such cases as programming errors rather than runtime conditions.

2. Reorganizes the function to have a single exit path at the bottom, making it easier to extend with new acceptance logic in future patches. The URL comparison is inverted to return early on mismatches rather than matches.

The changes are mechanical refactoring with no behavior change - the same remote acceptance decisions are made, just with different internal flow. This continues the series' pattern of cleaning up the promisor-remote subsystem before introducing new functionality. The patch touches only `promisor-remote.c` and maintains all existing functionality while making the code more maintainable.
