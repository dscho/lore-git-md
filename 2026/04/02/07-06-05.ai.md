This is a refactoring patch in Christian Couder's series to improve promisor-remote handling. The change focuses on optimizing the `all_fields_match()` function in `promisor-remote.c` by eliminating redundant lookups when checking remote configurations.

The key change replaces the `in_list` boolean parameter with a direct `config_entry` pointer, which allows the function to either:
1. Check all remotes (when NULL, equivalent to previous `in_list=1` behavior)
2. Check just one specific remote (when non-NULL, avoiding the previous redundant lookup by name)

The patch also adds clarifying comments to both `all_fields_match()` and `match_field_against_config()` to document their behavior and prevent future misuse. This is particularly important as the code prepares for future auto-configuration features where remote names might differ between server advertisements and local config.

The changes are mechanical and focused - updating the function signature, call sites, and internal logic while maintaining the same behavior. The patch follows the series' pattern of cleaning up the promisor-remote subsystem before introducing new functionality, with this change specifically addressing an efficiency concern in the configuration matching logic.
