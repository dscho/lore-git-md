This is patch 7/12 in Jeff King's series addressing C23 const-correctness warnings, specifically targeting the pseudo-merge bitmap subsystem. The patch fixes a const-correctness issue in `find_pseudo_merge()` while uncovering a deeper architectural problem with how pseudo-merges handle on-disk data.

The immediate issue is that `find_pseudo_merge()` returns a non-const pointer to memory-mapped disk data (which should be treated as read-only), triggering new glibc warnings about const-correctness. However, Jeff discovers the function also fails to properly byte-swap the on-disk values, which the comparator function does correctly. 

The solution changes `find_pseudo_merge()` to take an output parameter and properly byte-swap the values before returning, rather than returning a direct pointer to mmap'd data. This makes the const handling proper while also fixing the missing byte-swapping. The change propagates through `apply_pseudo_merges_for_commit()`, which now works with a stack-allocated `merge_commit` struct rather than a pointer.

Notably, Jeff observes this code path doesn't appear to be exercised by the test suite, suggesting a test coverage gap for pseudo-merges. While the patch makes clear technical improvements, he notes further investigation is needed to verify the functionality works as intended. The change follows the series' pattern of careful, technically sound fixes while surfacing deeper questions about the codebase's architecture.
