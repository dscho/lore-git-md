Jeff acknowledges that while const is sometimes used as a hint about memory ownership (where const might indicate the caller shouldn't free the buffer), it's always been an inconsistent and weak signal in the codebase. He notes this pattern appears more reliably in function return values than in struct fields. The discussion doesn't propose immediate changes to this convention, but suggests the series might prompt future reconsideration of how const is used throughout Git's codebase.

This email doesn't introduce new technical changes - it's more of a philosophical follow-up to the already-approved patch.
