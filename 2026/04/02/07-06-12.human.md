This is a refactoring patch in Christian Couder's series to improve promisor-remote handling. It continues the work of simplifying the data structures used to track accepted promisor remotes.

The patch removes the redundant 'accepted' strvec from filter_promisor_remote(), consolidating all tracking into the 'accepted_remotes' string list that was introduced in the previous patch. This eliminates parallel data structures and makes the code more straightforward - the string list now serves as the single source of truth for accepted remotes.

Key changes:
- Replaces strvec parameter with string_list in filter_promisor_remote()
- Updates promisor_remote_reply() to use the string_list directly
- Removes now-unnecessary strvec_push() calls
- Maintains identical behavior while simplifying the implementation

This is a clean, focused change that builds on the previous structural improvements in the series. The patch follows the established pattern of methodical, behavior-preserving refactoring to prepare for future promisor-remote enhancements.
