This is the final patch in Patrick Steinhardt's 5-part series to improve reftable portability for libgit2 integration. The patch introduces memory mapping abstractions (`reftable_mmap` struct and related functions) to allow platform-specific mmap implementations while maintaining a consistent interface.

The change replaces direct mmap/munmap calls in the reftable block source code with new wrapper functions `reftable_mmap()` and `reftable_munmap()`. The implementation uses Git's existing `xmmap_gently()` internally but provides a clean interface that libgit2 can implement differently if needed. The patch follows the established pattern of the series by introducing minimal, focused abstractions only where necessary for cross-platform compatibility.

Key technical details:
- Adds `struct reftable_mmap` to system.h to hold mapping state
- Implements platform-agnostic mmap/munmap wrappers in system.c
- Updates `file_block_source` in blocksource.c to use the new interface
- Maintains error handling semantics (returns REFTABLE_IO_ERROR on failure)
- Preserves existing behavior while making the implementation replaceable

This completes the portability layer needed for libgit2 to share Git's reftable implementation. The change is well-contained to the reftable subsystem and maintains the series' high standard of test coverage. With this final abstraction in place, the path is clear for libgit2 adoption of the shared code.
