This is a documentation patch in the ongoing `git replay` root commit handling discussion. Toon Claes responds to Junio Hamano and Christian Couder's debate about how to document the behavior of replaying from root commits, proposing specific documentation changes while expressing reservations about their necessity.

The patch clarifies that:
1. Each ref in the range is replayed separately down to root by default
2. Empty commits are dropped (correcting previous phrasing about "changes being present")
3. Only one positive ref is allowed in advance/revert modes
4. References the existing "Specifying Ranges" documentation for more details

Toon acknowledges Junio's position that documentation changes belong with the feature implementation but questions whether repeating range syntax basics is necessary given existing docs. He also agrees with Junio that special error messages for root commits would be overkill, seeing them as part of general boundary case handling.

The discussion exemplifies Git's documentation philosophy in action - balancing completeness against redundancy, with Junio advocating for clear explanations of behavior while Toon leans on existing documentation where possible. The proposed doc update attempts to clarify the actual behavior changes introduced by the root commit support while avoiding unnecessary duplication of range syntax details.
