This is the second patch in Patrick Steinhardt's 5-part series to improve reftable portability for libgit2 integration. The patch simplifies the fsync handling by removing the callback-based approach from v1 and instead requiring projects to provide their own fsync implementation via the reftable-system.h header.

The key change is replacing the optional fsync callback in reftable_write_options with a direct fsync implementation that projects must provide. For Git, this is implemented using the existing fsync_component() function. The patch removes the callback plumbing from the reftable backend while maintaining the same safety guarantees - if a project forgets to implement fsync, it will fail to compile rather than silently risking data loss.

This continues the series' theme of reducing abstraction surface area while maintaining the portability layer libgit2 needs. The change is straightforward and well-contained, touching only reftable internals and the Git backend integration. With the fsync approach now settled (after being a point of discussion in v1), this patch appears ready for merging as part of the overall portability effort.
