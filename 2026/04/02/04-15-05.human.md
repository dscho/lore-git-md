This is a bugfix patch in Jeff King's ongoing series addressing C23 compatibility warnings, specifically targeting the pseudo-merge bitmap functionality. The patch fixes both a const-correctness warning and a deeper issue with disk reads in the pseudo-merge code.

The core problem involves `find_pseudo_merge()` returning a pointer to mmap'd on-disk data without proper byte-swapping, while also triggering new glibc warnings about const-correctness. Jeff's solution changes the function to fill in a caller-provided struct instead of returning a direct pointer, ensuring proper byte-swapping occurs.

Interestingly, the bug appears to be latent - the affected code path doesn't seem to be exercised by the test suite. Jeff notes this warrants further investigation but focuses here on fixing the immediate issues. The changes are technically sound, converting the direct pointer return to a safer fill-in pattern while maintaining all existing functionality.

This patch continues the series' pattern of thorough, careful fixes to subtle issues. While part of a larger const-correctness effort, it stands out for uncovering a more significant underlying problem in the pseudo-merge code. The changes are well-contained and unlikely to be controversial, though the discovery of untested functionality may prompt follow-up work.
