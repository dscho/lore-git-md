This is a test infrastructure patch in Christian Couder's ongoing series to add URL-based allowlisting for promisor remotes. The discussion focuses on how to properly format `file://` URIs in test cases, particularly for Windows paths.

Christian responds to Patrick Steinhardt's suggestion about simplifying the test helper by unconditionally prepending slashes to paths. He cites RFC 8089 (the standard for file URIs) to explain that the current platform-specific handling is actually more correct - the standard specifies exactly three slashes for local paths (`file:///path`) and specifically addresses Windows drive letters (`file:///c:/path`).

The exchange shows Christian's attention to standards compliance and future-proofing, preferring the technically correct approach over a simpler but potentially non-standard implementation. This is a minor but thoughtful refinement to the test infrastructure that supports the larger promisor remote functionality.

The patch itself is part of the preparatory work (patches 1-12) that's been separated from the new functionality (13-15) based on earlier review feedback. This test helper change doesn't affect the core functionality but ensures the test suite properly exercises the URI handling that will be important for the URL-based allowlisting feature.
