This is the second patch in Phillip Wood's performance optimization series for xdiff, continuing the work to reduce memory usage in Git's diff implementation. The patch focuses on cleaning up the `xdl_clean_mmatch()` function after the array size reductions made in patch 1/4.

The key changes are:
1. Removing the now-unused `s` parameter since the function is always called with `s == 0`
2. Changing the `e` parameter to accept a length rather than an end index, which simplifies the calling code
3. Moving the calculation of the actual end index (`e = len - 1`) into the function itself

The changes are mechanical and focused, touching only `xdiff/xprepare.c`. The commit message clearly explains the rationale - these are follow-on simplifications enabled by the previous patch's changes. This continues the series' pattern of focused, low-risk optimizations to xdiff's memory usage. The changes maintain the same behavior while making the code slightly cleaner and more maintainable.
