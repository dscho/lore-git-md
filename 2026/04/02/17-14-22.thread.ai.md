Git thread summary:

This thread introduces a new `git repo info` feature to expose repository metadata in a structured format, starting with `paths.toplevel` to show the working tree root (matching `git rev-parse --show-toplevel` behavior). The initial patch from [author] adds a `get_paths_toplevel()` function in `builtin/repo.c` that uses `repo_get_work_tree()`, returning empty string for bare repos. The implementation includes tests verifying behavior against `rev-parse` in both regular and bare repositories.

Maintainer Junio C Hamano reviewed the patch and noted two improvements needed: (1) fixing indentation from spaces to tabs in `get_paths_toplevel()` to match Git's coding style, and (2) suggesting a comprehensive mapping between `rev-parse` options and `repo info` fields be documented as a comment above the `repo_info_field` array. This would clarify existing mappings (like `layout.bare` for `--is-bare-repository`) and highlight gaps (like `--show-cdup`).

- New field: `paths.toplevel` in `git repo info` JSON output
- Implementation reuses `repo_get_work_tree()` infrastructure
- Bare repo case explicitly handled (empty string)

- Follows established repo info conventions for errors and output format
- Requires style fix (tabs vs spaces) and suggested API mapping documentation

The patch remains technically sound with no functional objections. The maintainer's feedback focuses on code style and long-term API design considerations rather than core functionality. The change is still self-contained in `builtin/repo.c` with tests, but the next version should address both the indentation fix and the suggested documentation of the rev-parse to repo-info field mapping.
