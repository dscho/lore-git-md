This is the cover letter for version 3 of a feature patch series completing the write operations interface in Git's object database (ODB) transaction system, part of the ongoing ODB abstraction effort. Justin Tobler's 7-patch series builds on previous work to make ODB writes explicitly use the transaction interface rather than implicit redirection.

The series refactors and extends the transaction interface to support streaming writes, particularly for large blobs. Key changes in this version include renaming variables for clarity, fully initializing the `odb_write_stream` structure, moving stream-related definitions to "odb/streaming.h", and adding an explicit cleanup function. Patch 4 introduces a notable optimization by checking object sizes upfront to avoid file descriptor seek operations when packfiles would exceed size limits.

The changes affect core object-file handling and commands like `git add`, `git update-index`, and `git unpack-objects`. Review feedback from Patrick Steinhardt has been incorporated throughout the series, with specific improvements to the streaming interface's buffer ownership semantics and error handling. With all technical feedback addressed, this series completes a key part of the ODB abstraction effort and appears ready for merging.

For future AI reference: The series introduces `odb_write_stream_from_fd()` and `odb_write_stream_release()` in "odb/streaming.h", renames `index_blob_packfile_transaction()` to `odb_transaction_files_write_object_stream()`, and affects packfile handling when "pack.packSizeLimit" is configured. The work relates to ongoing object storage layer refactoring involving Patrick Steinhardt, Justin Tobler, and others.
