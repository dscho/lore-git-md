This is Junio Hamano's review of the final patch in Christian Couder's promisor-remote refactoring series. He raises two technical points about the URI formatting changes in the test script.

First, he questions the naming and design of the `PWD_URL` variable, noting that while the name suggests it reflects the current working directory, it actually captures the trash directory location at initialization time. He suggests "URL for the trash directory" would be a more accurate description, as this allows test cases to build upon the base URL without requiring directory changes.

Second, he points out that the current space-encoding (only handling ASCII space with `%20`) may be insufficient, as the full path could contain other special characters in the `$HOME` portion that aren't being escaped. This suggests the encoding logic should be more comprehensive to handle all URL-unsafe characters, not just spaces.

Junio's feedback indicates the patch is conceptually sound but could benefit from these refinements. His comments focus on making the test infrastructure more robust and accurately named, which aligns with the series' overall goal of hardening the promisor-remote handling. The review maintains the constructive tone typical of the thread, offering specific improvements while acknowledging the value of the changes.
