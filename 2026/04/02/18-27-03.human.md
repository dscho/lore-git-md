This is a review comment from Junio C Hamano on Patrick Steinhardt's reftable portability series, specifically addressing the time measurement abstraction introduced in patch 4/5. Junio notes that while the `reftable_time_ms()` function provides a clean way to get millisecond timestamps, the documentation should clarify that the epoch (reference point) is implementation-defined but must remain consistent within a given implementation. This is a minor documentation nit on an otherwise straightforward patch that replaces direct `gettimeofday()` calls with a portable abstraction. The change is part of a larger effort to make Git's reftable code shareable with libgit2, and Junio's comment suggests adding a brief note about epoch consistency to the function's documentation. The series as a whole has already addressed more substantive feedback from v1 and appears ready for merging.
