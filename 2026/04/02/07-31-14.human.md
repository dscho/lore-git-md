Refactoring patch for reftable portability, part of Patrick Steinhardt's series to enable shared reftable implementation between Git and libgit2. This first of five patches introduces a new "reftable-system.h" header to better organize platform-specific code.

The change establishes a three-layer system for handling platform dependencies in the reftable code:
1) "reftable-system.h" - project-specific POSIX environment setup (each project provides its own)
2) "system.h" - project-independent interface declarations (shared)
3) "system.c" - project-specific implementations (each project provides its own)

The patch updates numerous reftable headers to include "reftable-system.h" instead of directly including system headers like <stdint.h>. This is a mechanical but important change that enables the abstraction needed for libgit2 integration while maintaining Git's existing compatibility layer ("compat/posix.h").

The approach follows the consensus reached in earlier discussion, with all controversial elements from v1 (inline macros, fsync callbacks) now resolved or removed. This foundational change paves the way for the remaining portability fixes in the series.
