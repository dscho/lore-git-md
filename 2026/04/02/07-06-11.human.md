This is patch 8/10 in Christian Couder's series refactoring promisor-remote handling. The patch focuses on memory management improvements in the promisor-remote subsystem.

The change modifies how accepted promisor information is handled in `filter_promisor_remote()`. Instead of immediately dismantling and freeing `struct promisor_info` instances for accepted remotes (storing their data in separate parallel structures), the patch keeps these instances alive in a new `accepted_remotes` list. This simplifies the code by:
- Reducing the need for multiple parallel data structures
- Allowing a single iteration over the list to handle protocol replies, filter application, and remote marking
- Preparing for future additions (like a planned 'local_name' member) by keeping the structs intact

The patch maintains all existing functionality while making the code more maintainable. It's part of the larger effort to clean up and prepare the promisor-remote subsystem for upcoming auto-configuration features. The changes are focused and well-contained, touching only `promisor-remote.c` with straightforward modifications that preserve behavior while improving the code structure.
