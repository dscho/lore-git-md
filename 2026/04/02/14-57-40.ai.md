This is a performance optimization series targeting xdiff, Git's diff algorithm implementation. Phillip Wood addresses memory usage in the Myers diff algorithm by reducing the size of arrays allocated during diff calculation.

The key insight is that after removing common prefix/suffix lines during preprocessing, the algorithm only needs arrays sized for the remaining lines, not the entire file. The series makes four changes:

1. Shrinks action arrays in `xdl_do_diff()` to match the actual post-processing line count rather than the full file size.
2. Cleans up `xdl_clean_mmatch()` by removing redundant parameters and simplifying the logic.
3. Streamlines error handling in the preparation phase.
4. Further reduces array sizes in the preparation stage.

The changes are focused and mechanical, touching only `xdiff/xprepare.c`. The commit messages are clear about the motivation (memory savings) and approach. This appears to be a straightforward optimization that shouldn't affect diff results, only memory usage during calculation.

The series builds on previous xdiff cleanup work (en/xdiff-cleanup-3) and follows Git's pattern of incremental improvements to core algorithms. Given Phillip Wood's track record with diff-related changes and the focused nature of these patches, they seem likely to be uncontroversial.
