This is the fourth patch in Patrick Steinhardt's 5-part series to improve reftable portability for libgit2 integration. The patch introduces a time measurement abstraction (`reftable_time_ms()`) to replace direct calls to `gettimeofday()` in the reftable stack code.

The change simplifies the existing time comparison logic in `reftable_stack_reload_maybe_reuse()` by:
1. Replacing `struct timeval` with a simple `uint64_t` millisecond timestamp
2. Using Git's getnanotime()/1000000 for the platform-specific implementation
3. Removing the manual `tv_cmp()` helper function in favor of direct integer comparison

The abstraction follows the pattern established earlier in the series - providing a clean interface that libgit2 can implement differently while keeping Git's implementation simple. The change is mechanical and well-contained, touching only reftable stack operations that need timeout handling. Test coverage remains comprehensive as this doesn't introduce new behavior, just a more portable way to express existing timing logic.

This continues the series' steady progress toward making Git's reftable code fully shareable with libgit2 while maintaining clean separation between platform-specific and portable concerns.
