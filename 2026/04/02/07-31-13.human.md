This is a revised patch series from Patrick Steinhardt continuing the reftable portability work, now reduced to 5 patches from the original 6. The series represents the final steps to enable libgit2 to fully adopt Git's reftable implementation by completing the system abstraction layer.

Key changes in v2:
- Drops the controversial `REFTABLE_INLINE` macro patch entirely, with Patrick opting to handle this in libgit2 instead
- Reorganizes the header structure more cleanly with a three-layer model (system.h interface, project-specific implementation, and system-specific shims)
- Makes fsync behavior fail explicitly when no callback is provided, addressing Junio's earlier concern
- Adds clearer documentation about the header organization strategy

The series now focuses on:
1. Introducing the new "reftable-system.h" header with clear separation of concerns
2. Providing fsync functionality through the system header
3. Standardizing unused parameter annotations
4. Adding time measurement abstraction
5. Introducing memory-mapping wrappers

Patrick confirms successful test runs with both Git and libgit2, noting that only a few test fixes remain before libgit2 can fully review the reftable backend. The changes are well-contained to the reftable subsystem and represent the culmination of a long effort to make this code portable between projects. With the architectural questions now resolved and the most contentious parts removed, this series appears ready for final review.
