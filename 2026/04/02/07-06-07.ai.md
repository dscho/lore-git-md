This is the fourth patch in Christian Couder's 10-part series refactoring promisor-remote handling. It's a security hardening patch that rejects empty names or URLs in advertised promisor remotes at parse time rather than later in the process.

The change modifies `parse_one_advertised_remote()` in `promisor-remote.c` to check for both NULL and empty strings (via `!*info->name` and `!*info->url`). While Git servers shouldn't advertise such remotes (as they're already ignored in `promisor_config_info_list()`), this adds an explicit early rejection to protect against buggy or malicious servers. The warning message is also updated to be more explicit that such remotes will be ignored.

The patch is small but important for robustness - it ensures invalid remote configurations fail fast with clear warnings rather than potentially causing issues later. This aligns with the series' goal of cleaning up and hardening the promisor-remote subsystem before introducing new auto-configuration features. The change maintains backward compatible behavior while making the code more defensive.
