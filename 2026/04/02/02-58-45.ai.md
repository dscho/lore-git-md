This is the first patch in a feature series introducing new `includeIf` conditions for worktree path matching in Git configs. Chen Linxuan's patch adds two new condition types to the config include mechanism: `worktree:<pattern>` for case-sensitive matching of worktree paths and `worktree/i:<pattern>` for case-insensitive matching.

The implementation refactors the existing `include_by_gitdir()` function into a more generic `include_by_path()` that can handle both gitdir and worktree path matching. The new conditions use `repo_get_work_tree()` to get the worktree path, which properly handles linked worktrees where the gitdir points to the main repository's `.git/worktrees/` directory. The patch maintains all existing behavior around path resolution, including handling of symlinks, relative paths, and glob patterns.

The change is focused in `config.c` and builds on the same pattern matching infrastructure used for gitdir conditions. The implementation is careful to not match in bare repositories or during early config reading when repository information isn't available yet. This is a well-contained change that solves a real usability issue for multi-worktree setups while maintaining consistency with Git's existing config system behavior.
