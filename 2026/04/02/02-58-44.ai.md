This is a feature patch series introducing new `includeIf` conditions for matching worktree paths in Git configs. The series comes from Chen Linxuan and is currently at version 2.

The core proposal adds two new `includeIf` condition types to handle worktree paths in multi-worktree setups:
- `worktree:<pattern>` for case-sensitive matching of worktree paths
- `worktree/i:<pattern>` for case-insensitive matching

The motivation stems from limitations in the existing `gitdir` condition when dealing with linked worktrees, since their gitdirs point to the main repository's `.git/worktrees/` directory rather than the actual worktree location. The new conditions provide a more intuitive way to match configs based on where the worktree is checked out rather than where its metadata lives.

The implementation handles various path matching features including glob patterns, `~` expansion, relative paths, and trailing slash matching. The series includes thorough documentation updates and test coverage in `t1305-config-include.sh`. The changes are focused in `config.c` where the condition matching logic lives.

This appears to be a well-constructed series addressing a real usability pain point in multi-worktree setups. The commit messages are clear, the tests comprehensive, and the implementation builds on existing patterns in the config system. The feature should be particularly useful for developers who maintain multiple worktrees with different configuration needs.
