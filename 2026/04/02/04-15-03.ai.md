This is patch 6/12 in Jeff King's series addressing C23 const-correctness warnings, specifically focusing on the `find_last_dir_sep()` function. The patch converts an inline function to a macro to maintain const-correctness while avoiding C23 generics.

The issue stems from `find_last_dir_sep()` being an inline function that calls `strrchr()`, which in C23 more strictly enforces const-correctness. The function's current implementation silently drops const qualifiers, which newer compilers now warn about. The patch solves this by converting the function to a macro, letting `strrchr()` handle the const checking directly.

This change follows the series' pattern of addressing const-correctness systematically while minimizing disruption. The patch notes there's a Windows-specific implementation in `compat/win32/path-utils.h` that isn't changed here, as it already handles const explicitly (though less ideally). The solution is clean and maintains compatibility with both const and non-const callers.

The change is small but thoughtful, typical of Jeff King's careful approach to compatibility issues. It fits well with the series' goal of addressing C23 warnings without requiring broader const-correctness changes across the codebase.
