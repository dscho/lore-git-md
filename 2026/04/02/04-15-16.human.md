This is the final patch in Jeff King's 12-part series addressing C23 const-correctness warnings in string function usage across Git. The patch focuses on the refs backend, specifically fixing a const mismatch in `show_one_reflog_ent()` where a writable strbuf buffer needs non-const access for parsing reflog entries.

The key change removes a const qualifier from the buffer pointer in the reflog parsing function, since it needs to modify the buffer (writing a NUL terminator). To maintain type safety with the `parse_oid_hex_algop()` helper, the patch extends the CONST_OUTPARAM pattern introduced earlier in the series to this function, converting it to a macro wrapper that handles the const/non-const conversion safely.

The change follows the series' established pattern of matching constness to actual buffer usage while maintaining type safety. It touches three files - hex.c, hex.h, and refs/files-backend.c - with minimal but precise modifications.
