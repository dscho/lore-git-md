This is part 9 of Christian Couder's 10-part series refactoring promisor-remote handling. The patch continues the series' methodical cleanup by eliminating the redundant 'accepted' strvec in favor of the more comprehensive 'accepted_remotes' string list that was introduced in the previous patch. 

The change simplifies the data flow in `filter_promisor_remote()` by removing parallel tracking of accepted remote information - now all processing uses the single string list that already contained the necessary `promisor_info` structs. The modification affects several key functions: `filter_promisor_remote()` loses its strvec parameter, `promisor_remote_reply()` switches to building its output directly from the string list, and the intermediate conversion step is eliminated.

The patch maintains the same external behavior while reducing code complexity - a net deletion of 3 lines despite adding URL encoding safety checks. This continues the series' pattern of internal improvements that pave the way for future promisor-remote enhancements, particularly around auto-configuration via URL allowlists. The changes are focused and well-contained, touching only `promisor-remote.c` with no user-facing impact.
