This is the final patch in Jeff King's 12-part series addressing C23 const-correctness warnings, specifically targeting the refs backend. The patch fixes a strchr() warning in show_one_reflog_ent() where a writable strbuf buffer was being parsed with const/non-const pointer mismatches.

The key change removes const from the buffer pointer 'p' since the function writes a NUL terminator into the buffer. This requires modifying parse_oid_hex_algop() to use the CONST_OUTPARAM pattern introduced earlier in the series, similar to how skip_prefix() was handled. The implementation follows the established pattern of wrapping the original function with an _impl suffix and providing a macro interface for type safety.

This is a clean mechanical change that completes the series' systematic approach to C23 compatibility.
