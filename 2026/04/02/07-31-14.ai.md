This is the first patch in Patrick Steinhardt's v2 series for reftable portability improvements, focusing on header organization. The patch introduces a new three-layer system for handling platform-specific code in the reftable implementation:

1. A new `reftable-system.h` header that projects must provide, containing their platform-specific POSIX environment setup (here using Git's existing `compat/posix.h` and `compat/zlib-compat.h`). This is the only file projects need to modify.

2. The existing `system.h` is repurposed to contain only the platform-agnostic interface definitions that projects must implement.

3. `system.c` (not shown in this patch) will contain the project-specific implementations of those interfaces.

The change replaces direct includes of standard headers like `<stdint.h>` with the new `reftable-system.h` throughout the reftable codebase. This creates a clean separation between the reftable library's needs and how those needs are satisfied on different platforms, which is crucial for sharing the code with libgit2.

The patch is mechanical but important groundwork - it doesn't change behavior, just reorganizes how platform dependencies are expressed. This was agreed upon in previous discussion as the right approach after dropping more controversial elements from v1. The change is well-contained to the reftable subsystem and follows the pattern established in other cross-project shared code.
