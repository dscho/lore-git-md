This is patch 11/12 in Jeff King's series addressing C23 const-correctness warnings, specifically targeting the HTTP subsystem's header redaction logic. The patch fixes a warning where `strstr()` assigns a const pointer to a non-const variable when processing sensitive headers like Authorization and Cookie.

The change removes const qualifiers from `sensitive_header` and `cookie` variables in `redact_sensitive_header()`, since they point to writable memory within a strbuf. To maintain type safety with `skip_iprefix()`, the patch applies the same CONST_OUTPARAM pattern introduced earlier in the series, converting `skip_iprefix()` to a macro wrapper around a new `skip_iprefix_impl()` function.

This follows the series' established approach of matching constness to actual memory usage while preserving type safety through macro patterns. The change is straightforward and consistent with the series' technical direction, which has already received maintainer approval for similar patterns in earlier patches. As with the rest of the series, this is a mechanical but carefully considered change that addresses a real compatibility issue before it becomes problematic.
