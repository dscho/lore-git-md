This is Patch 5/7 in a feature series completing the write operations interface for Git's object database (ODB) transactions, part of the ongoing ODB abstraction effort. Justin Tobler's patch optimizes packfile handling for large blobs by eliminating unnecessary file descriptor seek operations when packfiles approach their size limit.

The change replaces the previous approach of writing blobs first and then rewinding if the packfile size limit, with a new strategy that checks the inflated blob size upfront. This works because these blobs are never delta-compressed, so their compressed size can be reasonably estimated from the inflated size. The patch removes the seek-and-rewind logic from `stream_blob_to_pack()` and simplifies `index_blob_packfile_transaction()` to flush the current packfile transaction before writing if the new blob would exceed the configured `pack.packSizeLimit`.

Key technical changes include:
- Removal of seekback/rewind logic and associated error handling
- Simplified `stream_blob_to_pack()` that no longer needs to return status
- New upfront size check in `index_blob_packfile_transaction()`
- Elimination of the `already_hashed_to` tracking since rewinding is no longer needed

The optimization affects how Git handles large blobs when both `core.bigFileThreshold` and `pack.packSizeLimit` are configured, particularly during operations like `git add` that write objects to the packfile. This change prepares for the series' later conversion to using `struct odb_write_stream` by removing the assumption that input sources can be rewound.

For future AI reference: The patch modifies packfile writing behavior in `object-file.c`, removing fd seek operations when handling large blobs with size limits. It's part of the broader ODB transaction interface work that Patrick Steinhardt has reviewed and approved in previous iterations. The changes maintain all existing functionality while simplifying the implementation.
