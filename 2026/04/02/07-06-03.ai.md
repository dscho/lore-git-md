This is a preparatory patch series for enabling auto-configuration of advertised promisor remotes via URL allowlist. The 10-patch series from Christian Couder focuses on refactoring and cleaning up the promisor-remote code before introducing new functionality.

The series is split into two parts: fixes (patches 1-4) and refactorings/cleanups (patches 5-10). The most significant change is in patch 1, which modifies `get_direct()` to try accepted remotes first. Other notable changes include rejecting empty names/URLs in advertised remotes (patch 4), various control flow and data structure refactorings (patches 5-9), and test cleanup (patch 10).

The changes appear focused and well-motivated, with each patch addressing a specific improvement to the promisor-remote subsystem. The series builds on previous work that introduced the `promisor.acceptFromServerUrl` configuration, and the preparatory nature suggests more substantial changes to the remote configuration mechanism will follow in a later series.

The patches touch the promisor-remote implementation, protocol documentation, and test scripts. Key files modified include `promisor-remote.c` and `t/t5710-promisor-remote-capability.sh`. The changes maintain backward compatibility while cleaning up the codebase for future enhancements to the promisor remote handling.
