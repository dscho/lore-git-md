This is the fourth patch in Patrick Steinhardt's 5-part series to improve reftable portability for libgit2 integration. The patch introduces a time measurement abstraction (`reftable_time_ms()`) to replace direct calls to `gettimeofday()` in the reftable stack implementation.

The change standardizes time handling by:
1. Adding `reftable_time_ms()` that returns milliseconds using Git's getnanotime()/1000000
2. Replacing the manual `tv_cmp()` and `gettimeofday()` logic in `reftable_stack_reload_maybe_reuse()` with simpler millisecond comparisons
3. Maintaining the same 3-second timeout behavior but with cleaner arithmetic

The implementation leverages Git's existing high-precision timer while providing a portable interface that libgit2 can implement differently if needed. This follows the series' pattern of introducing minimal, focused abstractions where platform differences exist. The change is well-contained to the reftable stack's retry logic and maintains the same timeout semantics with less platform-specific code.

This patch continues the series' progress toward making Git's reftable implementation fully portable for libgit2 adoption, with all tests passing in both codebases. The abstraction is straightforward and unlikely to be controversial given the prior discussion about platform abstraction needs.
