This is a documentation patch adding support for new `worktree` and `worktree/i` conditional include keywords in Git config files. The patch thoroughly explains how these new conditions differ from the existing `gitdir` option - they match against the working tree checkout path rather than the `.git` directory path.

The documentation covers all the pattern matching features (glob wildcards, `**/` and `/**` patterns, `~` expansion, relative paths) and explicitly notes these conditions will never match in bare repositories. The author provides clear examples showing practical use cases, particularly for managing different user identities or GPG keys across worktrees of the same repository.
