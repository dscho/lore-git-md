This is the first patch in Christian Couder's 10-part series refactoring promisor-remote handling. The patch changes the promisor remote lookup order to prioritize remotes that were explicitly accepted by the client (via server advertisement) over other configured promisor remotes.

The key change modifies `promisor_remote_get_direct()` to first try only accepted remotes before falling back to other configured remotes. This better reflects the intended agreement between client and server about preferred object sources. The patch includes a new helper function `try_promisor_remotes()` to implement this two-phase lookup.

Two new test cases verify the behavior works as expected in both clone and fetch scenarios, showing that accepted remotes are contacted before non-accepted ones even when they appear later in the config file. The tests use GIT_TRACE output to confirm the remote access order.

The change is well-motivated as preparation for future work on auto-configuring promisor remotes, where this ordering will become even more important. The patch maintains backward compatibility while improving the logical flow of remote selection. Documentation is updated to clarify the new behavior.
