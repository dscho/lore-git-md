This is part of Patrick Steinhardt's reftable portability series, specifically patch 3/5 in v2. The series aims to make Git's reftable implementation fully portable for shared use with libgit2.

The patch fixes a minor inconsistency where the reftable code was using Git's `UNUSED` macro instead of the reftable-specific `REFTABLE_UNUSED` macro for marking unused function parameters. This is a straightforward cleanup that maintains the separation between Git-specific and portable reftable code.

The change is mechanical and low-risk, affecting only one line in the reftable fsck code. The commit message explains why a more comprehensive solution (moving `UNUSED` to git-compat-util.h) isn't feasible due to header dependencies. This patch continues the series' theme of clean boundaries between Git and reftable code, which is important for the libgit2 integration effort.

As with the rest of the series, this change has been tested against both Git and libgit2 test suites. It's a small but necessary piece of the larger portability work.
