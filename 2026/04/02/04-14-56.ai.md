This is patch 3/12 in Jeff King's series addressing C23 const-correctness warnings in string function usage. The patch focuses on the transport-helper subsystem, specifically the `push_update_ref_status()` function.

The issue arises when `strchr()` is called on a const `key` parameter, with the result assigned to a non-const pointer `p`. C23's stricter const-correctness rules in libc implementations (notably recent glibc) trigger warnings about this implicit const dropping. The solution is straightforward: since the string ultimately comes from a writable strbuf, we can safely make `key` non-const while keeping `val` const. This matches the actual usage pattern where `p` needs to be writable to NUL-terminate at the found space.

The change is minimal and mechanical - just adjusting the type declarations of `key` and `val` variables. This follows the series' pattern of making the minimum viable change to satisfy C23 requirements while maintaining existing functionality.
