This is the second patch in Patrick Steinhardt's 5-part series to improve reftable portability for libgit2 integration. The patch focuses on standardizing fsync behavior across platforms by removing the callback-based approach from v1 in favor of a direct fsync abstraction.

The key change replaces the optional fsync callback in `reftable_write_options` with a mandatory `reftable_fsync()` function that projects must implement via the reftable-system.h interface. For Git, this is implemented using the existing `fsync_component()` infrastructure. The patch:

1. Removes the fsync callback field from `reftable_write_options`
2. Adds `reftable_fsync()` declaration in reftable-system.h
3. Implements Git's version in system.c using `fsync_component()`
4. Updates all fsync call sites to use the new direct approach

This simplifies the interface while maintaining safety - projects can't accidentally omit fsync behavior, and Git gets to keep its component-aware flushing. The change aligns with the v2 series' goal of reducing abstraction surface area while providing the portability libgit2 needs. Test coverage remains comprehensive across both codebases.
