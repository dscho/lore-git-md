This is a refactoring patch in Christian Couder's series to improve promisor-remote handling. It focuses on optimizing the `all_fields_match()` function in `promisor-remote.c` to avoid redundant lookups when checking if advertised remote fields match local configuration.

The key change replaces an `in_list` boolean parameter with a direct `config_entry` pointer, eliminating repeated lookups of the same remote configuration. When checking against a specific remote (rather than all remotes), the function now uses the pre-looked-up config entry directly. The patch also adds clarifying comments to document the function's behavior and purpose.

This change appears well-contained and motivated - it removes unnecessary work while making the code more straightforward. The modification helps prepare for future work on auto-configured remotes by removing an implicit dependency on remote names. The patch maintains existing behavior while cleaning up the implementation, following the series' theme of preparatory refactoring before introducing new functionality.
