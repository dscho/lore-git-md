This is a review comment from Junio C Hamano on Patrick Steinhardt's reftable portability series, specifically addressing the time measurement abstraction introduced in patch 4/5. Junio notes that while the `reftable_time_ms()` function implementation (using Git's `getnanotime()/1000000`) is correct, the interface documentation should clarify that callers only rely on relative time comparisons, not absolute epoch values. 

The maintainer suggests adding wording to the function's header comment to explicitly state that implementations must be consistent in their epoch choice but that the actual epoch value is unspecified. This is a minor documentation improvement to the otherwise complete and well-received patch. The comment does not indicate any functional concerns with the implementation itself, which has already been tested across both Git and libgit2 codebases. 

This feedback represents the final polish on a series that has already achieved consensus between Git and libgit2 maintainers, with all major technical questions resolved in previous iterations. The change aligns with the series' goal of providing minimal, well-defined abstractions for platform-specific functionality.
