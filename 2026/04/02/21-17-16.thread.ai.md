Thread identity: RFC patch series from Pablo Sabater proposing improvements to Git's graph rendering engine for multiple root commits in `git log --graph` output.

Core problem: Current graph rendering vertically aligns multiple root commits, creating misleading visual implications of parent-child relationships between unrelated commit lineages. The proposal aims to properly indent subsequent commits by keeping root commits "alive" for an extra row via a placeholder mechanism.

Technical details: Introduces `is_placeholder` flag to graph columns and modifies graph.c rendering logic. Test cases in t4202-log.sh cover multiple root scenarios and complex merges. Files touched: graph.c, graph.h, t/t4202-log.sh. The change preserves existing ASCII-art constraints while fixing the root commit alignment issue.

Current status: Initial RFC version seeking feedback on both technical implementation and visual design choices. Author acknowledges remaining visual quirks with long diagonal lines between distant columns as potential follow-up work.

Open questions: Whether the placeholder approach is the optimal solution, correctness of new indentation logic, and whether to address the noted diagonal line artifacts in this series or separately.

Participant positions: Only author (Pablo Sabater) so far, presenting the RFC for review. The graph rendering subsystem is historically finicky, so reviewers will likely scrutinize edge cases around merge display and ASCII-art constraints.

Related work: Graph rendering has seen periodic improvements over the years, particularly around merge commit display and edge cases in the ASCII output. This appears to be the first focused effort to address multiple root commit visualization.
