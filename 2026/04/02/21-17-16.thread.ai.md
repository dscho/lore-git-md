Thread identity: RFC patch series from Pablo Sabater proposing improvements to Git's graph rendering engine for multiple root commits and commits with excluded parents in `git log --graph` output.

Core problem: Current graph rendering vertically aligns commits whose parents are excluded from display (including root commits and commits with parents outside the displayed range), creating misleading visual implications of parent-child relationships between unrelated commit lineages. The proposal aims to properly indent subsequent commits by keeping such commits "alive" via a placeholder mechanism that handles both true root commits and commits with excluded parents uniformly.

Technical details: Introduces `is_placeholder` flag to graph columns and modifies graph.c rendering logic, with test cases in t4202-log.sh covering multiple root scenarios and complex merges. Files touched: graph.c, graph.h, t/t4202-log.sh. The solution must handle both true root commits and commits with parents outside the displayed range (C..Z) through a unified "seems_root" concept rather than checking actual root status. Test case portability issue now being addressed - filenames differing only by case (`8_a` vs `8_A`) will be revised in v2 to use case-unique names while preserving test intent, resolving the Windows/macOS CI blocker.
