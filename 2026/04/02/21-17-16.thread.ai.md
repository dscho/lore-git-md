Thread identity: RFC patch series from Pablo Sabater proposing improvements to Git's graph rendering engine for multiple root commits and commits with excluded parents in `git log --graph` output.

Core problem: Current graph rendering vertically aligns commits whose parents are excluded from display (including but not limited to root commits), creating misleading visual implications of parent-child relationships between unrelated commit lineages. The proposal aims to properly indent subsequent commits by keeping such commits "alive" via a placeholder mechanism.

Technical details: Introduces `is_placeholder` flag to graph columns and modifies graph.c rendering logic. Test cases in t4202-log.sh cover multiple root scenarios and complex merges. Files touched: graph.c, graph.h, t/t4202-log.sh. The change must handle both true root commits and commits with parents outside the displayed range (C..Z) consistently.

Current status: Initial RFC version seeking feedback. Junio C Hamano clarified the problem scope extends beyond root commits to any commit with excluded parents, suggesting the solution needs unified handling of both cases. Author acknowledges remaining visual quirks with long diagonal lines between distant columns.

Open questions: Whether the placeholder approach optimally handles both root commits and commits with parents excluded, correctness of indentation logic for both cases, and whether to address diagonal line artifacts in this series. Historical context suggests previous attempts at this fix may have encountered subtle edge cases in graph rendering logic.

Participant positions: Pablo Sabater proposed the RFC. Junio C Hamano provided essential clarification about problem scope (root commits vs excluded parents) and noted prior awareness of this long-standing issue. The graph rendering subsystem's complexity means reviewers will scrutinize edge cases around merge display and ASCII-art constraints.

Related work: Graph rendering has seen periodic improvements around merge commit display. This appears to be the first focused effort to address visualization of both root commits and commits with excluded parents. Junio's reference to "gotchas" hints at previous unsuccessful attempts to solve this issue.
