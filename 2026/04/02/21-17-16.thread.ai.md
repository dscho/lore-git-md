Thread identity: Feature patch series implementing visual root indentation for `git log --graph`, now at **v10**. Originating author: Pablo Sabater. Thread type: patch series (RFC -> v1-v10).

Core problem: The series introduces indentation in `git log --graph` to clearly represent commits with excluded parents by progressively indenting visual roots (except the first) while preserving parent-child relationships. The architectural challenge was safely accessing future commits in the revision walk to determine visual root status, resolved via a **lookahead buffer** in `struct git_graph` populated by a unified helper function, ensuring commits are fully simplified before inspection.

Resets indentation after four levels, eliminating symmetry-induced ambiguity in edge cases (e.g., when the number of visual roots is a multiple of 3 or 4). The patch modifies `graph_update()` to stop cascading when the visual root depth reaches a multiple of four, forcing the next commit to indent normally if it is not itself a visual root. The indentation calculation in `graph_output_commit_line()` uses `(depth - cascade) % 4` to ensure consistent wrapping. **Test coverage** in `t4218-log-graph-indentation.sh` verifies the wrap with a ten-commit sequence of orphaned roots, including the ambiguous case where a non-root commit would otherwise align with the wrapped root.

This change is **purely internal** and prepares for future graph-related configuration options (e.g., `log.graphIndent` in patch 7/7). The patch touches only `graph.c` (9 lines added, 4 removed) and is **mechanically straightforward**, with no new edge cases or dependencies.

Allows users to disable indentation entirely via a command-line flag (`--[no-]graph-indent`) or configuration variable (`log.graphIndent`). The default remains **indented** (`log.graphIndent=true`).
