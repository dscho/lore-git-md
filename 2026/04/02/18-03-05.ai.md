This is Junio C Hamano's review of Patrick Steinhardt's patch standardizing fsync behavior in the reftable stack. The patch is part of a completed 5-part series establishing portability abstractions for libgit2 integration.

Junio notes that the change from a per-write-options fsync callback to a single mandatory `reftable_fsync()` implementation in system.c means projects can no longer customize fsync behavior per-operation. He observes this is acceptable because the reftable library itself manages all file operations internally - projects using the library don't directly control which files get written, so having one consistent implementation is sufficient.

The review confirms the architectural approach taken in the patch, where Git implements `reftable_fsync()` using its existing `fsync_component()` infrastructure. This maintains data safety while simplifying the interface, which was a key goal of the v2 series. Junio's "OK" indicates he finds the patch ready for inclusion, completing the review cycle for this part of the reftable portability work.
