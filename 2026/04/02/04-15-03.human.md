This is patch 6/12 in Jeff King's series addressing C23 compatibility warnings about const-correctness in string function usage. The patch converts the `find_last_dir_sep()` inline function to a macro to avoid const-casting warnings from newer C23 compilers.

The issue stems from how C23's stricter `strrchr()` annotations would flag the inline function's implicit const removal. Rather than complicate the code with C23 generics (which Git doesn't otherwise require), Jeff takes the pragmatic approach of converting the wrapper to a simple macro that passes through the type information directly to `strrchr()`. This maintains the existing behavior while silencing the warning.

The change is small but thoughtful - it preserves the ability for callers to get either const or non-const results as needed, while making the type handling more transparent. The patch notes there's a Windows-specific implementation that isn't affected by this warning but could potentially be updated similarly in the future.

This continues the series' pattern of making const-correctness tradeoffs explicit while minimizing disruption. The change is straightforward and unlikely to be controversial, following the established approach from earlier patches in the series.
