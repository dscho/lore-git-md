This thread documents a straightforward but important documentation update regarding the reftable storage format. brian m. carlson has submitted a patch correcting two inaccuracies in the ref-storage-format documentation. First, it removes outdated language labeling reftable as "experimental" - the format has since stabilized. Second, it clarifies the default behavior: while the traditional filesystem-based format remains the default for now, reftable will become the default when the `with-breaking-changes` mode is enabled, which is part of the Git 3.0 transition. The changes are minimal but meaningful, ensuring the documentation as Git prepares for its major version update.
