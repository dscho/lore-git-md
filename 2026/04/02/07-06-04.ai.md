This is the first patch in Christian Couder's 10-part series refactoring promisor-remote handling, focusing on improving the order in which promisor remotes are tried when fetching missing objects. The patch modifies `promisor_remote_get_direct()` to prioritize remotes that were explicitly accepted by the client (via server advertisement) over other configured promisor remotes.

The key change extracts the remote-trying logic into a new `try_promisor_remotes()` helper function and calls it twice - first with `accepted_only=true` to try only accepted remotes, then with `false` to fall back to others. This ensures the client honors the server's preference for where to fetch missing objects from, rather than just trying remotes in config file order.

The patch includes documentation updates clarifying this behavior in `gitprotocol-v2.adoc` and adds two new test cases in `t5710-promisor-remote-capability.sh` that verify accepted remotes are tried first. The tests create scenarios with multiple promisor remotes where only some are advertised/accepted, then confirm via trace logs that the accepted remote is contacted before others.

This change appears well-contained and motivated, with clear test coverage. It serves as groundwork for future auto-configuration of promisor remotes while maintaining backward compatibility. The patch touches core promisor-remote functionality but doesn't introduce new user-facing behavior - it just changes the internal priority of existing functionality.
