This is Patch 5/7 in a performance-focused series completing the object database (ODB) transaction write operations interface. The patch optimizes packfile handling for large blobs by eliminating unnecessary file descriptor seek operations when packfiles approach their size limit.

The key change replaces the previous approach (which would write an object, check if it exceeded the size limit, then seek back and retry if needed) with a more efficient upfront check using the object's inflated size as an approximation. While this means packfiles may not be filled to their absolute maximum capacity (since zlib compression could make the actual on-disk size smaller), it avoids the costly seek operations while still respecting pack size limits.

The patch simplifies the blob streaming logic by removing the retry mechanism and associated checkpointing code. It affects the packfile writing path used by commands like `git add` and `git update-index` when handling large files. Patrick Steinhardt has reviewed and approved the series, with this version incorporating feedback from earlier iterations.

This change is part of the broader ODB abstraction effort led by Patrick Steinhardt and Justin Tobler to make Git's object storage layer more flexible and pluggable. The series appears technically sound and ready for merging after thorough review.
