This is part 3 of Christian Couder's 10-patch series refactoring promisor-remote handling. The patch improves warning messages when Git ignores an advertised promisor remote, making it clearer to users that the remote is being skipped (not just that there was a problem with it).

The changes are straightforward: three warning messages in `promisor-remote.c` now explicitly state "ignoring this remote" when a promisor remote is rejected due to missing/empty URLs or name/URL mismatches. This makes the user experience more transparent when Git encounters malformed or mismatched promisor remote advertisements from servers.

While small, this is a meaningful quality-of-life improvement that helps users understand the system's behavior better. The patch fits cleanly into the larger effort to prepare the promisor-remote subsystem for upcoming auto-configuration features. No functional changes are introduced - just clearer messaging about existing behavior.
