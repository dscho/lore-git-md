Feature patch adding repository root path to `git repo info` output.

This patch introduces a new `paths.toplevel` field to `git repo info` that exposes the working tree root path, matching the behavior of `git rev-parse --show-toplevel`. For bare repositories, it returns an empty string, consistent with other non-applicable fields in the command's output.

The change provides a more structured way for scripts to access the repository root without needing to parse `rev-parse` output. The implementation is straightforward - it uses the existing `repo_get_work_tree()` function and follows the same pattern as other fields in the repo info command. The patch includes tests verifying the behavior in both regular and bare repositories.

This appears to be a well-contained, focused addition to the repo info command. The commit message clearly explains the motivation and the implementation approach. The patch includes appropriate test coverage and maintains consistency with existing behavior for bare repositories.
