This is the first patch in Jeff King's 12-part series addressing C23 compatibility warnings about const-correctness in string function usage. The patch focuses on the convert.c file, where it adds const qualifiers to two pointer variables (`dollar` and `spc`) that don't need to be modified. This silences compiler warnings that would appear with C23's stricter const-correctness rules for string functions like `strchr()`.

The change is straightforward and well-justified - these pointers are only used to scan through the input string and never modified, so marking them const is both correct and helps future compatibility. This is typical of Jeff King's work: small, precise fixes that address real issues before they become problems. The patch is part of a larger effort that touches multiple subsystems, but this particular change is self-contained and low-risk.
