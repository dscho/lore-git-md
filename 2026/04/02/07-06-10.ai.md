This is patch 7/10 in Christian Couder's series refactoring promisor-remote handling. The patch extracts the configuration parsing logic for `promisor.acceptfromserver` into a new `accept_from_server()` helper function, moving it out of the more complex `filter_promisor_remote()` function.

The change is purely structural - the behavior remains identical, just organized more cleanly. The new helper function handles all the string-to-enum conversion for the configuration value, returning one of the `ACCEPT_*` constants (NONE, KnownUrl, All). This prepares for future patches that will add more filtering logic to `filter_promisor_remote()`.

Key technical details:
- The new `accept_from_server()` takes a `struct repository*` parameter (consistent with the `the_repository` removal effort)
- It maintains all existing validation and warning behavior for invalid config values
- The extracted code handles the same three valid values (None, KnownUrl, All) case-insensitively
- Error messages about invalid config values remain unchanged

This continues the series' pattern of methodical, behavior-preserving refactoring to make the promisor-remote code more maintainable before introducing new functionality. The patch touches only `promisor-remote.c`, modifying control flow but not adding or changing any user-visible behavior.
