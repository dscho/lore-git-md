This is a feature patch adding a new structured way to query repository information through `git repo info`. The patch introduces a `paths.toplevel` field that exposes the working tree root, matching the behavior of `git rev-parse --show-toplevel`.

The implementation adds a new `get_paths_toplevel()` function to `builtin/repo.c` that retrieves the worktree path via `repo_get_work_tree()`, returning an empty string for bare repositories. The change includes tests verifying the behavior in both regular and bare repositories.

The motivation is to provide a more structured alternative to `rev-parse` for scripts that need to determine the repository root. The patch follows existing patterns in the repo info subsystem, maintaining consistency with how other repository properties are exposed. The implementation looks straightforward and well-tested, with clear handling of both regular and bare repository cases.

Key technical details:
- Adds new field `paths.toplevel` to `git repo info` output
- Uses existing `repo_get_work_tree()` internally
- Returns empty string for bare repos (consistent with other fields)
- Includes tests comparing against `rev-parse --show-toplevel`
- Follows same error style as other repo info fields (-1 for errors)
