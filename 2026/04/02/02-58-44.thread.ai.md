Thread summary:

Feature patch series from Chen Linxuan introducing new `includeIf` conditions for worktree path matching in Git configs (v2). The core change adds two condition types to `includeIf`: `worktree:<pattern>` for case-sensitive and `worktree/i:<pattern>` for case-insensitive matching of worktree paths in multi-worktree setups. This addresses limitations of the existing `gitdir` condition which points to the main repository's `.git/worktrees/` directory rather than the actual worktree location.

Implementation in `config.c` refactors `include_by_gitdir()` into a more generic `include_by_path()` to handle both gitdir and worktree path matching. The new conditions use `repo_get_work_tree()` to properly handle linked worktrees. The changes maintain all existing behavior around path resolution including symlinks, relative paths, and glob patterns, while being careful to not match in bare repositories or during early config reading when repository information is unavailable.

Junio C Hamano has reviewed the series and suggested splitting the first patch into two parts: one for the refactoring of gitdir matching into a generic path-based helper (changing the parameter from `struct config_options *` to `const char *path`), and another for adding the new worktree conditions using that helper. This organizational change would make the series easier to review while maintaining the same functionality. Documentation and test updates would move to the second patch introducing the new feature.

The series includes comprehensive test coverage in `t1305-config-include.sh` and thorough documentation updates. Changes are focused on the condition matching logic while maintaining consistency with existing config system behavior. The feature solves a real usability issue for developers managing multiple worktrees with different configuration needs. The maintainer's feedback suggests the technical approach is sound but needs restructuring for clarity. The author will likely send a v3 incorporating this suggestion.
