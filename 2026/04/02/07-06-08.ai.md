This is the fifth patch in Christian Couder's 10-part series refactoring promisor-remote handling. The patch focuses on control flow restructuring in `should_accept_remote()` to prepare for future URL-based acceptance logic.

The key changes convert what was previously a warning about empty URLs into a BUG() assertion, since patch 4 already ensures empty URLs are rejected during parsing. The control flow is inverted to check for URL mismatches first and return early, leaving a single exit path at the bottom for successful matches. This makes the function more linear and easier to extend with new acceptance criteria in future patches.

The patch touches only `promisor-remote.c`, modifying the logic that determines whether to accept an advertised promisor remote. It maintains the existing behavior while cleaning up the implementation - the BUG() is effectively dead code given the earlier validation, but serves as a safeguard against regressions. The changes are part of the series' broader effort to harden and refactor the promisor-remote subsystem before introducing auto-configuration features.
