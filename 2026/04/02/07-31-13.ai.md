This is a revised version of Patrick Steinhardt's reftable portability series, now reduced to 5 patches from the original 6. The series continues the effort to make Git's reftable implementation fully portable for use in libgit2, with these being the final platform abstraction changes needed before libgit2 can adopt the shared code.

The v2 series drops two previously controversial elements: the `REFTABLE_INLINE` macro (now handled in libgit2 itself) and the fsync callback approach (replaced with direct use of Git's `fsync_component()`). The remaining changes focus on:

1. Introducing a clearer three-layer system header architecture (`reftable-system.h` for project-specific POSIX environment, `system.h` for interface definitions, and `system.c` for implementations)
2. Adding time measurement (`reftable_time_ms()`) and memory mapping (`reftable_mmap`) abstractions
3. Standardizing unused parameter annotations with `REFTABLE_UNUSED`

The series shows good test coverage against both Git and libgit2 test suites. With the architectural questions from v1 now resolved (header organization and fsync behavior), this version appears ready for merging. The only remaining open item from the original discussion - the `inline` abstraction debate - has been sidestepped by handling it in libgit2 rather than Git.

This represents the final step before libgit2 can fully adopt Git's reftable implementation, marking an important milestone in the reftable backend's cross-project compatibility. The changes are well-contained to the reftable subsystem and maintain clean separation between platform-specific and portable code.
