This thread is about Pablo Sabater’s patch series implementing cascading indentation for visual roots in `git log --graph`, now at version 7. The series aims to improve the clarity of commit graphs by progressively indenting visual roots (except the first) while preserving parent-child relationships, addressing a long-standing challenge in safely accessing future commits during revision walks.

The architectural core of the series—a lookahead buffer in `struct git_graph`—has been finalized and approved by Junio Hamano, replacing the fragile peek-based approach from earlier versions. The v7 series is complete, with the test infrastructure refactoring (patch 1/3) already merged. The remaining patches—the lookahead buffer implementation (patch 2/3) and the visualization logic (patch 3/3)—are ready for final review. All failing test cases from v6 now pass, and the redesign is compatible with planned changes like Jeff King’s removal of `revs->commits`.

The latest feedback from Chandra Pratap is purely cosmetic, suggesting minor readability improvements to the lookahead buffer code (e.g., comment clarity, `memset` vs. explicit initialization, and `ARRAY_SIZE()` usage). While constructive, this review does not engage with the series’ technical substance or open questions, such as the pending documentation of visualization rules or Junio’s lingering concerns about test brittleness. The series remains on track for inclusion, with only final sign-offs from Junio and Phillip Wood outstanding.
