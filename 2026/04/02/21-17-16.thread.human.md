This thread is about Pablo Sabater’s patch series implementing cascading indentation for visual roots in `git log --graph`, now at its eighth iteration (v8). The goal is to improve the clarity of commit graphs by progressively indenting visual roots—commits with excluded parents—while preserving parent-child relationships. The series has evolved through several design iterations, with the latest version introducing a lookahead buffer to address fragility in earlier approaches.

The core architecture is now settled, with Junio Hamano approving the lookahead buffer design, and patches 1/4 (test infrastructure cleanup) already merged. Patches 2/4 and 3/4, which implement the unified lookahead population and buffer logic, are ready for final review. However, the fourth and final patch, which introduces the visualization logic, has hit a snag. Mirko Faina identified a critical design oversight: the current implementation fails to indent visual roots when using filters like `--author` or `--grep`, because these filters exclude commits *after* they are enqueued, leaving parent pointers intact. This breaks the lookahead buffer’s ability to detect visual roots until the next commit is processed—too late to apply indentation. Pablo has proposed a fix by iterating over parents and using `graph_is_interesting()` to detect exclusions, but this remains untested.

The series is otherwise technically sound, with robust test coverage for edge cases like `--max-count`, `--first-parent`, and octopus merges. However, the lack of tests for `--author` and similar filters is now a glaring gap. Junio and Phillip Wood’s final reviews of patches 2/4 and 3/4 are still pending, but the primary blocker is the edge case in patch 4/4. A v9 is likely needed to address Mirko’s feedback, validate the proposed fix, and expand the test suite. The series remains under active review and is not yet ready for `next`.
