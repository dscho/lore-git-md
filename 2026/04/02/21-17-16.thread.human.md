This thread is about Pablo Sabater’s v6 patch series implementing cascading indentation for visual roots in `git log --graph`. The series has resolved its main architectural blocker by introducing an abstraction layer in `revision.c` that insulates `graph.c` from the commit walker’s internals, and now includes the full visualization implementation.

The core goal is to improve the clarity of `git log --graph` output when commits have excluded parents by progressively indenting visual roots (except the first) while preserving parent-child relationships. The v6 series is complete, with three patches covering test infrastructure cleanup, the abstraction layer, and the main visualization logic. Junio Hamano and Phillip Wood have conditionally approved the abstraction layer (patch 2/3), pending a follow-up patch to add a defensive `BUG()` check in `revision_has_more_commits()`. The visualization logic (patch 3/3) is pending final review, and Taylor Blau’s input on commit-graph interactions remains outstanding.

Junio’s latest review raises a forward-compatibility concern about the abstraction layer’s reliance on internal details of the `prio_queue` structure, suggesting the use of `prio_queue_for_each()` to make the code more robust against future changes. This is not a blocker but adds another item to the follow-up work list, and the series will need to be reconciled with Kristofer Haugsbakk’s ongoing `prio-queue` refactoring before either can graduate to `master`. The series is technically complete but requires minor defensive hardening and coordination with related work before it can be merged.
