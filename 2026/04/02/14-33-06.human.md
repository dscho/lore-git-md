This is a test modernization series preparing for a potential future change where Git may require explicit specification of bare repositories. Johannes Schindelin sends 17 patches updating test scripts to explicitly handle bare repositories rather than relying on implicit discovery.

The series addresses tests that currently assume Git will automatically recognize bare repos through directory structure. Each commit focuses on one test file, using techniques like:
- Replacing `git -C <bare-repo>` with `git --git-dir=<bare-repo>`
- Exporting GIT_DIR after entering a bare repo directory
- Wrapping commands in GIT_DIR subshells
- Explicitly allowing implicit discovery where it's part of the test's purpose

The changes are mechanical but important - they future-proof the test suite against a possible default change in Git's safe.bareRepository setting. The work appears thorough, touching 16 test scripts and git-p4.py across various test scenarios. The patches follow Git's convention of small, focused changes with clear commit messages explaining each adjustment.

This is part of a larger effort (PR #2072) to make Git's behavior around bare repositories more explicit and configurable. The series looks well-structured and uncontroversial - it's the kind of preparatory work that typically gets merged after straightforward review.
