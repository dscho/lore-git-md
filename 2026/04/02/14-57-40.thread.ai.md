Performance optimization series by Phillip Wood targeting xdiff's Myers diff algorithm implementation to reduce memory usage. The changes focus on shrinking dynamically allocated arrays in `xdiff/xprepare.c` to match only the post-prefix/suffix line counts rather than full file sizes. Current version includes all four parts:

1/4 adjusts action arrays in `xdl_cleanup_records()`: introduces `len1`/`len2` variables for reduced sizes, maintains correct indexing into xdfile_t via offset, and updates bounds passed to `xdl_clean_mmatch()`. Junio C Hamano reviewed this patch, confirming its technical correctness while noting a minor commit message typo ("As as") that needs fixing. His detailed analysis validated the offset-based indexing approach and showed the changes don't require awareness in `xdl_clean_mmatch()`.

2/4 follows up with simplifications to `xdl_clean_mmatch()` enabled by the first patch: removes unused `s` parameter (always 0), changes `e` parameter to accept length rather than end index, and moves end index calculation into the function.

3/4 consolidates error handling in the same file by combining two separate allocation failure checks (`action1` and `action2` arrays) into a single conditional with logical OR. The behavior remains identical (returning -1 on failure after cleanup) but the implementation is more compact, preparing for future additions.

4/4 completes the series by moving allocation of `reference_index` arrays to `xdl_cleanup_records()`, where the actual needed size (post prefix/suffix removal) is known. This shrinks these arrays from full-file size to just the count of lines that will be processed by the Myers diff algorithm, following the same pattern as earlier patches.

All changes are strictly mechanical improvements to xdiff's memory handling with no impact on diff results, continuing Phillip Wood's established pattern of xdiff optimizations. Builds on prior xdiff cleanup work (en/xdiff-cleanup-3). The series demonstrates a clean, focused approach to reducing memory usage in the diff preparation phase, particularly beneficial for large files.
