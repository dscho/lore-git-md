Performance optimization series by Phillip Wood targeting xdiff's Myers diff algorithm implementation to reduce memory usage. The four-part series focuses on shrinking dynamically allocated arrays in `xdiff/xprepare.c` to match only the post-prefix/suffix line counts rather than full file sizes. All changes are mechanical improvements to xdiff's memory handling with no impact on diff results, continuing Phillip Wood's established pattern of xdiff optimizations.

1/4 adjusts action arrays in `xdl_cleanup_records()`: introduces `off`, `len1`, and `len2` variables for reduced sizes and offset tracking, maintains correct indexing via offset calculation, and updates bounds passed to `xdl_clean_mmatch()`. Junio C Hamano reviewed this with technical validation while noting a commit message typo.

2/4 simplifies `xdl_clean_mmatch()` by the first patch's changes: removes unused `s` parameter (always 0 after previous changes), changes `e` parameter to accept length rather than end index, and moves end index calculation into the function. Junio approved the approach in v1 with "Makes sense"; v2 maintains these changes with only a rebase.

3/4 consolidates error handling by combining two separate allocation failure checks into a single conditional with logical OR, reducing code duplication while maintaining the same cleanup path. Junio confirmed this approach as safe in v1 review, and v2 maintains the change with only a rebase.

4/4 moves allocation of `reference_index` arrays to `xdl_cleanup_records()` where the actual needed size is known, shrinking these arrays from full-file size to just the count of processed lines. Junio gave explicit "Looking good" approval, confirming correct array access and appropriate allocation.
