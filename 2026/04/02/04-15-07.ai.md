This is part 8 of Jeff King's 12-patch series addressing C23 compatibility warnings, specifically around const-correctness in string function usage. The patch introduces a new CONST_OUTPARAM macro pattern to safely handle const/non-const parameter matching in the `skip_prefix()` function.

The core issue is that `skip_prefix()` takes a const input string but returns a pointer into that string via a const out-parameter, which prevents some valid use cases while allowing potentially dangerous ones. The patch introduces a macro-based solution that:
1. Allows non-const out-parameters when the input is non-const (safe case)
2. Maintains existing const out-parameter behavior
3. Generates compile-time warnings when trying to drop constness (dangerous case)

The implementation uses a clever ternary expression that fails compilation when constness would be incorrectly dropped, while allowing safe cases through. The patch renames the underlying function to `skip_prefix_impl()` to avoid macro recursion and keeps all related definitions together in git-compat-util.h.

This is a technically sophisticated solution to a subtle type safety issue, characteristic of Jeff King's careful attention to both correctness and usability. The change is well-explained in the commit message with clear examples of both valid and invalid cases. As with other patches in this series, it demonstrates thoughtful consideration of C23 compatibility while maintaining backward compatibility.
