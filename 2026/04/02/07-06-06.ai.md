This is part 3 of Christian Couder's 10-patch series refactoring promisor-remote handling. The patch improves warning messages when Git ignores advertised promisor remotes due to configuration mismatches or missing fields.

The changes make it explicit in the warning text that the remote is being ignored, not just why. Previously, messages like "no or empty URL advertised" or "known remote but with different URL" didn't state the consequence (ignoring the remote). Now each warning clearly indicates the remote will be ignored, helping users understand the actual system behavior rather than just seeing a diagnostic.

The patch touches three warning cases in `promisor-remote.c`:
1. When a remote has no URL or an empty URL
2. When a remote's URL doesn't match the locally configured one
3. When a server-advertised remote lacks either a name or URL

This is a small but user-facing improvement to the series' preparatory work for auto-configuring promisor remotes. The changes don't affect functionality - they make the existing behavior more transparent. The patch follows the series' pattern of cleaning up the subsystem before introducing new features, with this change focused on clarifying user feedback rather than modifying core logic.
