This thread introduces new `worktree` and `worktree/i` conditional include keywords for Git config files, allowing configuration to vary based on which worktree is active. The feature differs from existing `gitdir` matching by operating on the worktree path rather than the `.git` directory location.

The current patch (v2 2/3) provides thorough documentation of the new functionality, explaining pattern matching rules (including globbing support), clarifying that the condition never applies in bare repositories, and showing practical examples like per-worktree user identity configuration. The documentation is well-structured and clearly written, suggesting this will be a useful addition for users managing multiple worktrees with different configuration needs.
