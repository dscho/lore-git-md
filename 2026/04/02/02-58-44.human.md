This is a feature patch series introducing new `includeIf` conditions for matching worktree paths in Git configs. The series comes from Chen Linxuan and is in its second iteration.

The core addition is two new `includeIf` condition keywords: `worktree:<pattern>` and its case-insensitive variant `worktree/i:<pattern>`. These allow including config sections based on the real path of the current worktree's working directory, which is particularly useful in multi-worktree setups where the `.git` directory paths don't directly reflect the worktree locations. The patterns support glob matching with features like `**/` recursion and `~` expansion.

The implementation appears thorough, with clear documentation additions and comprehensive test coverage in t1305. The commit messages explain the motivation well - this solves a real pain point in multi-worktree configurations where current `gitdir`-based conditions are awkward to use. The v2 changes are minor (just adding missing sign-offs), suggesting the technical approach was sound in v1.
