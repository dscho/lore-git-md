This is a test infrastructure patch in a series about filtering `.gitconfig` from test output. The patch addresses an issue where `git ls-files --others` shows the global `.gitconfig` file in test output because the test suite writes to `$HOME/.gitconfig` for `safe.bareRepository` settings.

The patch:
1. Adds a new `test_filter_gitconfig` helper function to strip `.gitconfig` entries from test output
2. Updates multiple `ls-files` test scripts to use this filter when checking output
3. In one test (`t7104`), switches from bare `ls-files -o` to `ls-files -o --exclude-standard` to respect the exclude rules

The changes are mechanical but necessary to make the tests reliable when the test suite's own configuration file appears in the working directory. The patch is part of a larger series (6/8) but stands alone as a focused test fix. Johannes Schindelin (Git for Windows maintainer) is the author, with assistance from Claude Opus 4.6 (likely an AI assistant).
