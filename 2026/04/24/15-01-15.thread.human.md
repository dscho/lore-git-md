This thread addresses test infrastructure improvements to handle `.gitconfig` files appearing in test output. The core issue stems from test-lib.sh creating a global `safe.bareRepository=all` setting, which generates a `$HOME/.gitconfig` that unexpectedly shows up in `git ls-files --others` output since that command doesn't consult `.git/info/exclude` by default.

Johannes Schindelin (Git for Windows maintainer) has proposed a solution in patch 6/8 of his series: a new `test_filter_gitconfig` helper function that strips `.gitconfig` entries from test output. The patch also updates several test files to use this filter or switch to `--exclude-standard` (which properly respects exclude files) where applicable. The changes are focused and mechanical, specifically targeting test reliability when global configs are present - a scenario particularly relevant for Windows environments. Given the narrow scope and clear problem/solution pairing, this appears to be a straightforward improvement to the test infrastructure.
