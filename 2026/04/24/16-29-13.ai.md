This is a follow-up in the thread about `git send-email` reply-to configuration. Tian Yuchen suggests an alternative workaround to Christian König's original issue where the `sendemail.reply-to` config setting wasn't working.

The key technical point is that while `git send-email` doesn't support `reply-to` as a config option, the `format.headers` setting can achieve the same effect by directly injecting a Reply-To header. This is a known pattern used for other custom headers but wasn't mentioned in the earlier discussion.

The suggestion is pragmatic - it leverages existing functionality rather than requiring new code. However, as Ramsay Jones noted earlier, the lack of a dedicated `sendemail.reply-to` option appears to be design rather than an oversight. The thread remains open on whether to add proper config support or document the workaround as the preferred approach.

This moves the discussion forward by providing a functional solution while the broader question of config file support remains unresolved. The workaround is simple and likely sufficient for most users' needs, though it may not satisfy those wanting full parity between command-line flags and config options.
