This is a bugfix patch in the final iteration of a long-running series implementing autostash behavior for conflicted branch switching. The patch addresses a lockfile cleanup issue in `merge_working_tree()` within `builtin/checkout.c`.

The core issue is that several early return paths in `merge_working_tree()` were exiting without releasing the index lock acquired via `repo_hold_locked_index()`. While currently harmless since the process exits soon after, this could cause problems if the function were called multiple times in the same process. The patch systematically adds `rollback_lock_file()` calls to all early return paths.

Key technical details:
- Adds lockfile rollback in error cases like corrupt index, missing tree, unmerged index, and failed merge operations
- Maintains the existing behavior while ensuring proper cleanup
- Part of a comprehensive series that has already been merged, with this being one of the final refinements
- Follows Git's pattern of careful resource cleanup even in error paths

The change is straightforward and clearly motivated, with the patch author (Harald Nordgren) having already addressed extensive review feedback from Phillip Wood and Junio C Hamano in previous iterations. This represents the final polish on a well-tested feature.
