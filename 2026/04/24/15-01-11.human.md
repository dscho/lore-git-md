This is a test fix patch from Johannes Schindelin, part of a larger series (position 2/8). The patch addresses an interaction between test setup and XDG config file handling in Git's maintenance command tests.

The issue occurs when test-lib.sh creates a global `$HOME/.gitconfig` file (for settings like `safe.bareRepository`), which then causes Git to prefer that location over the XDG config location (`$XDG_CONFIG_HOME/git/config`) that the tests explicitly set up. This interferes with the test's expectations about where configuration should be written.

The fix is straightforward: in the subshells testing XDG behaviors, override `$HOME` to point to a non-existent directory, ensuring Git won't find or create a `.gitconfig` file there. This maintains test isolation while preserving the original behavior outside these test cases.

The patch is well-motivated and clearly explains both the problem and solution. It's a focused change that improves test reliability without introducing new complexity. As part of a larger series about maintenance command behavior, this appears to be solid groundwork for whatever broader changes are coming in subsequent patches.
