Thread subject: [PATCH v8] checkout/switch: extend --track with fetch mode for remote ref updates

Core problem/goal: Extend `git checkout`/`git switch` with `--track=fetch` to automatically fetch from the remote when creating a tracking branch, so that users do not need a separate `git fetch` step. A parallel but still-unsubmitted `--autostash` option was also discussed but has not progressed.

Current status:
- v8 patch has been sent by Harald Nordgren, addressing all previous technical feedback including Phillip Wood's final ref resolution simplification.
- Junio C Hamano posted a review focused on code details rather than his earlier philosophical objection. He did not state that he tested the patch, nor did he engage with the broader design question.

Key technical details:
- `--track=fetch`: v8 implements the following:
  - `resolve_fetch_target()` helper to translate a remote-ref specification into a refspec for fetching.
  - `fetch_remote_for_start_point()` performs the actual fetch, with error handling (converts offline failures to warnings when the target ref already exists locally).
  - Mode validation: rejects invalid combinations (e.g., `inherit,direct`), "last one wins" for multiple `--track` flags.
  - Narrow fetch scoping: bare remote names (e.g., `origin`) fetch only the default branch, which Junio confirmed as correct.
  - 12 comprehensive test cases.
  - Updated documentation.
- Junio raised a substantive concern about the `resolve_fetch_target()` logic: because Git does not forbid hierarchical remote names (e.g., `a/b`), the code's heuristic of splitting on the first `/` to separate remote name from branch name is fragile. This could silently misbehave for users with slashes in remote names -- a genuine edge case.
- Junio also questioned whether the pre-fetch existence check in `fetch_remote_for_start_point()` is necessary, suggesting that `resolve_fetch_target()` could be made solely responsible for that determination, potentially simplifying the code.
- A minor issue: an unrelated whitespace change (stray blank line removal) was flagged as patch noise.

Open questions:
- The hierarchical remote name ambiguity (slash in remote name) is an unaddressed technical bug in the v8 logic.
- Whether the pre-fetch existence check logic should be folded into `resolve_fetch_target()`.
- Junio's earlier philosophical objection to the feature remains unstated in this v8 review; it is unclear if his technical engagement signals openness or is simply a maintenance review of the code on its technical merits without endorsing the feature.
