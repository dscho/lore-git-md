Thread subject: [PATCH v9] checkout/switch: extend --track with fetch mode for remote ref updates

Core problem/goal: Extend `git checkout`/`git switch` with `--track=fetch` to automatically fetch from the remote when creating a tracking branch, eliminating the need for a separate `git fetch` step before checkout.

Current status:
- v9 resolves both issues from Junio's v8 review: the hierarchical remote name parsing bug and the control flow simplification suggestion.
- No response from Junio C Hamano on v9 yet. His earlier philosophical objection remains unaddressed in this round.

Key technical details:
- `resolve_fetch_target()` in v9 is rewritten to be correct for hierarchical remote names (e.g., `nested/remote`). Instead of splitting on the first `/`, it walks backwards from the end of the start-point string, trying the longest prefix as a remote name first and falling back to shorter prefixes if the initial guess is not a configured remote. This is a robust fix for the slash ambiguity edge case.
- The pre-fetch existence check logic is folded into `resolve_fetch_target()` via an `existing_ref` output parameter, simplifying `fetch_remote_for_start_point()` by removing a separate ref-lookup block.
- 16 test cases (up from 12 in v8), including a dedicated test for hierarchical remote name handling: `test_expect_success 'checkout --track=fetch handles hierarchical remote name' ...`.
- Range-diff provided for easy v8-to-v9 inspection.
- Removed stray whitespace change that Junio flagged as noise in v8.
