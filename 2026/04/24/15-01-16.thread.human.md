This thread addresses test failures that occur when `.gitconfig` files appear unexpectedly in `git status` output during test runs. The issue stems from test infrastructure (test-lib.sh) creating `$HOME/.gitconfig` in certain configurations, causing these files to show up as either untracked or ignored files in test assertions.

The current patch (7/8 in the series) introduces a solution through a new `filter_gitconfig` helper that strips these entries from status output before comparison. The changes are focused and mechanical, targeting specific test files (t7060, t7061, t7064, t7508, and t7521) where this issue manifests. The patch maintains all existing test expectations while eliminating the `.gitconfig` noise.

Johannes Schindelin (Git for Windows maintainer) is leading this effort to improve test reliability. The series appears to be nearing completion, with this patch handling the remaining test cases affected by the `.gitconfig` visibility issue. The changes are strictly limited to test infrastructure and don't modify core Git behavior.
