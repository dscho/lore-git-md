Performance optimization patch targeting `index-pack` and `unpack-objects` I/O efficiency.

Scott Bauersfeld proposes increasing the input buffer size from 4KB to 128KB in both `index-pack` and `unpack-objects` to reduce system call overhead, particularly on FUSE filesystems where small writes incur significant latency. The change matches the buffer size already employed by Git's hashfile layer.

The patch includes detailed benchmarking showing a 66% reduction in pack file writes and elimination of all 4KB writes during HTTPS clones of the git/git repository (~296MB pack). All clones passed consistency checks (fsck, HEAD verification, file counts). The implementation is straightforward - replacing hardcoded buffer sizes with a shared `INPUT_BUFFER_SIZE` constant.

This appears to be a well-motivated change with clear performance data showing benefits, particularly for FUSE scenarios. The patch maintains compatibility (verified by fsck) while reducing syscall overhead. The 128KB size aligns with existing Git conventions, suggesting it's a reasonable default that won't introduce memory pressure issues.
