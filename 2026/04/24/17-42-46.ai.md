Feature patch discussion about `--fetch` option for `git checkout`/`git switch`.

Marc Branchaud raises a design concern about the proposed `--fetch` option that would automatically fetch remote refs before branch creation. While the original patch ties the fetch behavior specifically to remote-tracking refs (like `origin/foo`), Marc suggests this is overly restrictive and could confuse users who might expect `--fetch` to work with any checkout operation (tags, detached HEADs, local branches).

The key argument is that the current design's remote-specific behavior seems unnecessarily complex compared to simply doing a plain fetch before proceeding with the checkout. Marc notes this would be easier to implement, maintain, and explain to users. While not personally needing the feature, they suggest the simpler approach would have broader utility.

This feedback introduces a new design consideration beyond the implementation details discussed in previous reviews (test coverage, config naming, documentation). The thread now has two distinct perspectives on the feature's scope: the original remote-specific behavior versus a more general pre-checkout fetch. This will likely require the author to revisit the design before sending a v2.
