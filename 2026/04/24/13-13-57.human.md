This is a bug report about `git send-email` configuration. Christian König reports that while the `--reply-to` command line option works as expected, setting the same value in `.gitconfig` under `[sendemail] reply-to` has no effect. The issue appears when trying to ensure replies go to an AMD email address rather than a personal Gmail account used for sending.

The report is clear and provides the relevant configuration snippet showing both the working command-line approach and the non-working config file approach. This looks like a legitimate configuration parsing issue that would affect anyone trying to set a default reply-to address in their Git config rather than specifying it per-invocation. The problem appears straightforward to reproduce given the provided details.
