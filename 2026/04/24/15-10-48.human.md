This is a bugfix patch for a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. The patch comes from Jonatan Holmgren, the original author of the change that introduced the regression.

The fix restores backward compatibility for dotted aliases while preserving the new subsection syntax introduced in commit ac1f12a9de. The key change makes Git fall back to treating the full name as an alias when it encounters an unknown subsection key (anything other than "command"). This maintains both the new functionality for non-ASCII aliases and the old behavior for simple dotted aliases.

The patch includes tests verifying that:
1. Simple dotted aliases work again (e.g. `git simple.dotted`)
2. These aliases appear in `git help -a` output
3. The subsection syntax continues to work as before

The solution aligns with the analysis from Jeff King and René Scharfe in the thread, and addresses the use case reported by Michael Grossfeld where `pull.sub` aliases broke for submodule workflows. The only remaining edge case is aliases ending in ".command" which will stay broken for backward compatibility reasons.

This appears to be a well-considered fix that balances compatibility with the new features, and includes appropriate test coverage. Given the regression affects a documented feature, this would likely be a candidate for inclusion in a 2.54.x maintenance release.
