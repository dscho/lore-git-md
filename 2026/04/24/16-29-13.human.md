This is a follow-up in the thread about `git send-email` reply-to configuration. Tian Yuchen suggests an alternative workaround to Christian König's issue where the `sendemail.reply-to` config setting doesn't work (as Ramsay Jones clarified this option isn't actually implemented).

Yuchen proposes using the more general `format.headers` configuration to manually inject a Reply-To" header, which would achieve the same end result. This is a pragmatic solution that bypasses the missing `sendemail.reply-to` option entirely by using Git's existing email header manipulation capabilities.

The suggestion appears technically sound and provides a functional workaround while the discussion about whether to properly implement `sendemail.reply-to` continues. It's a typical Git contributor approach - when faced with a missing feature in one subsystem, leverage existing functionality from another part of Git to accomplish the same goal.
