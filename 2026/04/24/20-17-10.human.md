This is a follow-up in the thread fixing a commit signing regression for non-UTF-8 messages. The regression caused signatures to become invalid when commit messages contained non-UTF-8 characters, affecting Git versions 2.45.0 through at least 2.53.0.

brian m. carlson responds to Elijah Newren's review of their patch, agreeing with two issues Elijah identified. First, they acknowledge that users might see duplicate UTF-8 warning messages (once for the main buffer and once for the compatibility buffer) and commit to fixing this in v2 of the patch. Second, they confirm that the patch did indeed correct a logical short-circuiting issue where invalid UTF-8 in both buffers would previously only trigger validation on the first one.

The exchange shows productive collaboration on finalizing the fix, with brian accepting the feedback and planning to address it in the next iteration. The core solution - moving UTF-8 validation before signing to ensure signature validity - remains sound, with these being refinements to the implementation details.
