Johannes Schindelin has proposed a security-focused patch series that changes the default behavior for bare repository access when Git is built with WITH_BREAKING_CHANGES. The series makes safe.bareRepository default to "explicit" in such builds, requiring explicit permission to access bare repos as a security hardening measure against potential vulnerabilities. The 8-patch set carefully handles test compatibility by modifying the test infrastructure to globally set safe.bareRepository=all when WITH_BREAKING_CHANGES is enabled, rather than requiring per-test modifications.

Junio Hamano has reviewed patch 6/8, which adds a test helper to filter .gitconfig from ls-files output - a side effect of the test infrastructure writing to $HOME/.gitconfig. While acknowledging the technical merit of the solution, Junio reflects on how test infrastructure might have been designed differently to avoid such edge cases. He also reports integration issues when this series merges with other in-flight topics, noting test failures when WITH_BREAKING_CHANGES is enabled that may need investigation before final merging. The series remains in active discussion, with the maintainer validating the technical approach while surfacing important integration concerns that may require attention in later iterations.
