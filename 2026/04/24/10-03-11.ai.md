Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This patch introduces a new `--fetch` flag for `git checkout` and `git switch` that fetches from the remote when the start-point is a remote-tracking ref. The motivation comes from a common workflow where users first fetch and then checkout a branch, which can lead to stale checkouts if the fetch step is forgotten. The implementation adds a new `fetch_remote_for_start_point()` function that handles the remote fetching logic, plus a `checkout.autoFetch` config option to enable this behavior by default.

The changes touch the checkout machinery in `builtin/checkout.c`, adding the new option and config, plus tests in `t7201-co.sh` that verify:
- Basic `--fetch` functionality with remote branch names
- Behavior with bare remote names (fetches default branch)
- Failure cases where fetch fails
- Config-driven auto-fetch behavior
- Compatibility with `git switch`

The implementation appears clean and well-tested, with clear commit messages explaining the motivation and behavior. This seems like a useful quality-of-life improvement for users who frequently create branches from remote refs. The patch follows Git's standard patterns for adding new command-line options and config settings.
