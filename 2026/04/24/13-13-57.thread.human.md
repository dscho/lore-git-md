This thread started with Christian König reporting that while `git send-email --reply-to` works as expected, setting the same value in `.gitconfig` under `[sendemail] reply-to` had no effect. He wanted replies to go to his AMD email rather than his Gmail sending address.

Ramsay Jones clarified the situation: the `reply-to` config setting isn't actually a supported configuration variable - it's undocumented in the man pages and appears to be treated as an internal variable in the code. This explains why Christian's attempt to configure it didn't work. The behavior he observed is expected since the config option he tried doesn't exist as user-configurable.

The thread has now established that this is a documentation/expectation issue rather than a bug. The `--reply-to` command line option works as designed, but there's no equivalent config file setting. The next steps would be either to document that reply-to addresses must be specified via command line, or to propose adding proper config file support for this functionality.
