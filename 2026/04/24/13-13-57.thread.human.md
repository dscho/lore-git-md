Christian König has reported an issue with `git send-email` where the `reply-to` configuration in `.gitconfig` doesn't work as expected. While the `--reply-to` command line option correctly sets the reply address, the equivalent config setting under `[sendemail] reply-to` appears to have no effect. This creates a workflow problem for Christian, as he needs replies to go to his AMD email address rather than his Gmail sending address.

The report is clear and includes the relevant configuration details, making it straightforward to reproduce. The core question is whether this is a documentation issue (if the config option name has changed) or an actual bug in the config parsing logic. Given that `git send-email` is a critical tool for the Git project's mailing list workflow, this issue could affect many contributors who rely on similar reply-to configurations. The next steps will likely involve verification from other contributors to determine if this is a known issue or regression.
