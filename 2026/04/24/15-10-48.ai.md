This is a bugfix patch addressing a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in previous versions. The patch comes from Jonatan Holmgren, the original author of the change that introduced the regression.

The fix restores backward compatibility for dotted aliases while preserving the new subsection syntax introduced in commit ac1f12a9de. The key change makes Git fall back to treating the full name as an alias when the final key isn't "command", which maintains both the old behavior (dotted aliases) and new behavior (subsection syntax).

The patch includes test cases verifying both execution and help output for simple dotted aliases, showing careful attention to the user experience. It's worth noting this addresses the core issue reported by Michael Grossfeld while maintaining the new functionality for non-ASCII aliases that was the original goal of the subsection syntax change.

The fix has already been vetted by Jeff King and René Scharfe in the thread discussion, suggesting it's technically sound. The only remaining limitation is that aliases ending in ".command" will stay broken for backward compatibility reasons, but this appears to be an edge case that wasn't in common use.
