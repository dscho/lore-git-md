Ben Knoble initially proposed adding per-worktree ignore patterns via a new `extensions.worktreeIgnore` config option, but after substantive feedback from reviewers, has scaled back to just fixing documentation. The original proposal would have allowed different ignore patterns per worktree, but Phillip Wood raised concerns about path collisions and design scalability, while Junio C Hamano questioned whether the feature was truly needed given that shared patterns cover most use cases. brian m. carlson suggested a more general approach for worktree-specific files.

The current patch (v2) simply updates the gitignore(5) man page to correctly state that per-repository ignore patterns are stored in `$GIT_COMMON_DIR/info/exclude` rather than `$GIT_DIR/info/exclude`. The commit message explains this change while acknowledging the original motivation (managing different LLM tool skill files across worktrees) and the community's preference against implementing the feature. This appears to be the conclusion of the thread, with the documentation fix being the uncontroversial resolution.
