This thread discusses D. Ben Knoble's proposal to add per-worktree ignore patterns via a new `extensions.worktreeIgnore` config option. The initial implementation provides three modes for handling exclude files while maintaining backward compatibility, with thorough documentation and tests.

The discussion has evolved into a broader design debate. brian m. carlson suggested generalizing the approach to handle multiple worktree-specific files (like `info/attributes` and `info/sparse-checkout`) through a unified `extensions.worktreeInfoFiles` mechanism rather than focusing solely on ignore patterns. Phillip Wood's recent review raises substantive concerns about the current implementation's file location strategy, noting that reusing `info/exclude` prevents simultaneous use of shared and worktree-specific patterns. He proposes using a distinct path like `info.worktree/exclude` and hints this could prevent future proliferation of worktree-specific file variants.

Key open questions include whether to:
1. Proceed with the ignore-specific solution as-is
2. Build a general framework now
3. Structure the current work to ease future generalization

The thread currently features three distinct technical perspectives: D. Ben Knoble's working implementation, brian m. carlson's architectural suggestion, and Phillip Wood's concrete design concerns about file locations and future extensibility. All participants agree the functionality is valuable but differ on the best path to implement it robustly.
