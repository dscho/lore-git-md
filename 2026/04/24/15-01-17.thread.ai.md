Subject: security hardening of safe.bareRepository default for Git 3.0. Core problem: preventing malicious hook execution in implicitly discovered bare repositories. Originating author: Johannes Schindelin. Thread type: security patch for breaking changes in Git 3.0.

Changes default value of safe.bareRepository from "all" (allow all bare repos) to "explicit" (only allow explicitly specified bare repos via --git-dir or GIT_DIR) when built with WITH_BREAKING_CHANGES. Motivation is security hardening against attacks where users could be tricked into cloning repositories containing malicious bare repos that execute hooks when discovered. Particularly important for shell prompts that automatically run Git commands.

Implementation in setup.c uses #ifdef WITH_BREAKING_CHANGES to toggle the default. Documentation thoroughly updated to explain change and migration path (users can set safe.bareRepository=all to restore old behavior). Test cases carefully updated to handle both old and new default behaviors, avoiding repository discovery during cleanup when new default would prevent it.

This is part of series preparing breaking changes for Git 3.0. Maintains backward compatibility through configuration while making safer behavior the default. No open questions or objections raised in this initial patch - appears to be well-considered security hardening change.
