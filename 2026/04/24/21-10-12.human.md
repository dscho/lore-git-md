This is the final patch in a long-running series (20 iterations) implementing autostash behavior for `git checkout -m` with conflict resolution customization. The feature is now fully merged and stable.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches, then reapply them after the switch. If the changes apply cleanly, the stash is silent. If conflicts occur, the stash is preserved and the user is given clear instructions for resolution (either resolve now and drop the stash, or reset hard and pop later). The implementation includes:

- New documentation explaining the behavior in both `git-checkout` and `git-switch` man pages
- Core logic in `builtin/checkout.c` to handle the stash creation and application
- Comprehensive test coverage for various scenarios including:
  - Mixed staged/unstaged changes
  - Conflict cases with recoverable stashes
  - Untracked file protection
  - Proper messaging and error handling

The patch represents the culmination of a well-executed feature development process with thorough review from Phillip Wood and Junio Hamano. It provides a more robust alternative to the previous behavior where `checkout -m` would fail outright on conflicts, leaving users in a difficult recovery state. The implementation is careful about edge cases and maintains backward compatibility while adding this safety net for branch switching with local modifications.
