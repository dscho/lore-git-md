This is a test patch in a series (7/8) that fixes test failures caused by `.gitconfig` appearing in `git status` output. The issue arises because test-lib.sh creates `$HOME/.gitconfig` when `WITH_BREAKING_CHANGES` is set, making it show up as either untracked or ignored in status output.

The patch introduces a `filter_gitconfig` helper to strip `.gitconfig` entries from status output before comparison in affected tests (t7061 and t7521). It also makes targeted adjustments in t7060, t7064, and t7508 by either adding the filter or excluding `.gitconfig` directly.

Key technical details:
- Adds `/ .gitconfig` to `.git/info/exclude` in t7060
- Introduces `test_filter_gitconfig` helper in t7061 and t7521
- Applies the filter to various status output checks
- Maintains existing test expectations while removing the `.gitconfig` noise

This is part of a larger series addressing test stability issues, with Johannes Schindelin (Git for Windows maintainer) as the primary author. The changes are mechanical and focused on test reliability rather than modifying core behavior.
