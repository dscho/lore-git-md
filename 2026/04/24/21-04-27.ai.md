This is a bugfix for `git grep`'s column number reporting when using `--only-matching`. The patch addresses an inconsistency where subsequent matches on the same line showed incorrect column positions compared to GNU grep's behavior.

René Scharfe's fix modifies the column calculation in `grep.c` to track positions from the line start rather than relative to previous match ends. The change makes Git's output match GNU grep's behavior, showing absolute column numbers for each match. For example, searching for digits in "1234567890" now correctly reports columns 1, 11, 21 rather than the previous incorrect 1, 2, 12.

The patch includes updates to the test suite (`t7810-grep.sh`) to verify the corrected behavior, particularly for the "mmap" test case where the second match should start at column 14. The fix has consensus from multiple reviewers (including Phillip Wood) who confirmed the current behavior was likely unintentional and that matching GNU grep's output is the right approach.

This affects tools that parse `git grep --column` output for precise match locations, such as editor integrations. The change is straightforward with minimal risk, touching only the column calculation logic while preserving all other grep functionality.
