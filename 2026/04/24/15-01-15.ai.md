This is a test infrastructure patch in a series about handling `.gitconfig` in test output. The patch addresses an issue where the global `safe.bareRepository=all` setting in test-lib.sh creates a `$HOME/.gitconfig` file that appears in `git ls-files --others` output, since that command doesn't consult `.git/info/exclude` by default.

The solution adds a `test_filter_gitconfig` helper function to strip `.gitconfig` entries from test output, and applies it to several test files that check `ls-files --others` output. For t7104, it switches to using `--exclude-standard` which already respects the exclude file. The changes are mechanical but necessary to make the tests pass reliably when the global config is present.

The patch is part of a larger series (position 6/8) but stands alone well - it solves a concrete testing problem with minimal changes. Johannes Schindelin (the Git for Windows maintainer) is the author, suggesting this may be particularly relevant for Windows testing scenarios. The changes are focused and unlikely to be controversial.
