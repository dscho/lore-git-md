This is a feature patch introducing per-worktree ignore patterns in Git. D. Ben Knoble proposes a new configuration option `extensions.worktreeIgnore` that allows controlling how ignore patterns are loaded for worktrees.

Currently, all worktrees share the same ignore patterns from `$GIT_COMMON_DIR/info/exclude`. The patch adds flexibility by letting users:
1. Keep current behavior (default)
2. Use only worktree-specific patterns (`worktree` mode)
3. Merge both common and worktree patterns (`merge` mode)

The implementation adds a new test file `t2408-worktree-ignore.sh` that verifies all three modes work as expected. Documentation updates explain the new option in config, worktree, and gitignore man pages.

The patch appears well-crafted with clear motivation (some users want per-worktree ignores), thorough test coverage, and comprehensive documentation updates. It builds on existing worktree infrastructure and follows Git's pattern of using `extensions.*` namespace for experimental features. The change is backward compatible since it defaults to current behavior when unset.
