This is a security-related patch series that changes the default behavior for bare repository access when Git is built with `WITH_BREAKING_CHANGES`. The series comes from Johannes Schindelin (Git for Windows maintainer) and follows up on earlier discussion with Junio Hamano.

The main change (patch 8) makes `safe.bareRepository` default to "explicit" (requiring explicit permission) rather than "all" when `WITH_BREAKING_CHANGES` is enabled. This is a security hardening measure to prevent accidental access to bare repositories.

The first 7 patches are preparatory test fixes needed because the test suite assumes the current permissive behavior. The approach taken (as suggested by Junio) is to set `safe.bareRepository=all` in the test environment's global config when `WITH_BREAKING_CHANGES` is active, rather than modifying individual tests. The test fixes address various interactions where writing to `$HOME/.gitconfig` affects test behavior (e.g., showing up in `ls-files` or `status` output, or conflicting with tests that manipulate config files).

The series appears carefully constructed to maintain test suite functionality while introducing the security change. The commit messages clearly explain each adjustment's purpose, and the changes are focused on test infrastructure rather than core functionality. This looks like a well-considered incremental improvement to Git's security defaults.
