Johannes Schindelin has proposed a security hardening change for Git 3.0 that modifies how bare repositories are handled by default. When built with the new `WITH_BREAKING_CHANGES` flag (targeting Git 3.0), the `safe.bareRepository` configuration will default to "explicit" rather than "all". This means Git will only recognize bare repositories that are explicitly specified via `--git-dir` or `GIT_DIR`, preventing accidental execution of malicious hooks in implicitly discovered bare repos.

The change specifically addresses security concerns around shell prompts and other automated tools that run Git commands, where users could unknowingly trigger hooks from a malicious repository. The implementation is straightforward, toggling the default via `#ifdef` in setup.c while maintaining all existing logic. Documentation has been carefully updated to explain both the new default and how to revert to the old behavior by setting `safe.bareRepository=all`.

This appears to be a well-considered security improvement that maintains backward compatibility while making the safer behavior the default for Git 3.0. The patch includes thorough test updates that account for both old and new behaviors, demonstrating careful attention to edge cases. As part of the Git 3.0 breaking changes, this aligns with the project's ongoing effort to improve security defaults.
