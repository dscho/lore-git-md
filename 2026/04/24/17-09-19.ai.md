This is a feature patch introducing per-worktree ignore patterns via a new `extensions.worktreeIgnore` config option. The patch comes from D. Ben Knoble, who has previously contributed to Git's build system and infrastructure.

Currently, all worktrees share the same ignore patterns from `$GIT_COMMON_DIR/info/exclude`. The patch adds flexibility by allowing worktrees to optionally use their own ignore files (located in `$GIT_DIR/info/exclude` for each worktree) or combine both sets of patterns. The new config accepts three values:
- Unset/`no`: maintain current behavior (only common-dir exclude)
- `worktree`: use worktree-specific excludes
- `merge`: combine both common-dir and worktree excludes

The implementation touches the directory handling code in `dir.c` to check the config and select the right exclude files. It includes thorough documentation updates across three man pages and adds a new test file `t2408-worktree-ignore.sh` that verifies all three modes work as expected. The test creates a main worktree and secondary worktree with different exclude patterns, then checks which files are ignored under each configuration.

This appears to be a well-constructed patch with clear motivation (discussed in a prior thread), complete documentation, and comprehensive test coverage. The change is backward-compatible since the default behavior matches current Git. The implementation handles edge cases like invalid config values and properly integrates with the existing exclude-file loading infrastructure.
