This is a test infrastructure patch that's part of a larger series (1/8) preparing for a breaking change to Git's default behavior around bare repository access. The patch comes from Johannes Schindelin (Git for Windows maintainer) with input from Junio Hamano.

The core change modifies the test suite to maintain backward compatibility when `WITH_BREAKING_CHANGES` is enabled. A future change will make Git default to requiring explicit access to bare repositories (rather than allowing implicit discovery), which would break many existing tests that assume the old behavior. This patch ensures tests continue working by globally configuring `safe.bareRepository=all` in the breaking-changes test environment, while adding the config file to `.git/info/exclude` to avoid polluting test results.

The approach was suggested by Junio as preferable to modifying hundreds of individual tests to use explicit bare repo access. The patch notes this is just the first step - follow-up commits will address specific test cases that use commands like `git ls-files` or `git status` that might still be affected.

This is a mechanical but important change to maintain test suite stability during a significant behavior change. The patch is well-motivated and follows the maintainer's guidance, though its effectiveness will depend on the subsequent patches in the series addressing edge cases.
