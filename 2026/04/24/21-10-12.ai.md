This is the final patch in a long-running series implementing autostash behavior for `git checkout -m` with conflict resolution customization. The series has already been merged and this version represents the post-merge refinements.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches, then reapply them after the switch. If the changes can be cleanly applied, the stash is silently dropped. If conflicts occur during reapplication, the stash is preserved and the user is given clear recovery instructions.

Key technical aspects:
- Introduces silent autostash creation capability
- Adds comprehensive error handling for unpack_trees() failures
- Implements proper lockfile cleanup in merge_working_tree()
- Extends test coverage for edge cases including:
  - Mixed staged/unstaged changes
  - Untracked file safety checks
  - Conflict scenarios
  - Stash recovery workflows

The implementation spans multiple subsystems:
- `builtin/checkout.c` for the core branch switching logic
- `sequencer.c` for autostash handling
- `xdiff-interface.c` for conflict style configuration
- Extensive test updates in t7201-co.sh and related suites

This represents the culmination of 20 iterations (14 pre-merge + 6 post-merge) with all technical objectives achieved. The feature provides a safer workflow for conflicted branch switches while maintaining backward compatibility. The test coverage is thorough, verifying all error paths and edge cases.
