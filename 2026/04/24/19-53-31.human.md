This is a review of D. Ben Knoble's patch introducing per-worktree ignore patterns via `extensions.worktreeIgnore`. Phillip Wood raises substantive concerns about both the design and implementation approach.

Phillip questions the need for per-worktree ignore patterns, noting the current shared-excludes behavior seems reasonable and asking for concrete use cases. He suggests the proposed solution (`$GIT_DIR/info/exclude`) would prevent a worktree from having both shared and private excludes, proposing alternative paths like `info.worktree/exclude` instead.

The review engages with the technical merits, pointing out that `git rev-parse --git-path` already handles path resolution correctly and should be preferred over manual path construction. Phillip's suggestion to use a different path structure shows consideration for future extensibility, aligning with brian m. carlson's earlier proposal for a general worktree-info-files mechanism.

This is a substantive review that identifies potential design limitations and suggests alternatives while acknowledging the technical correctness of the current implementation. The feedback moves the discussion forward by focusing on architectural considerations rather than surface-level issues.
