This is a security-related patch series that changes the default behavior of `safe.bareRepository` to "explicit" when Git is built with `WITH_BREAKING_CHANGES`. The change aims to improve security by requiring explicit permission to access bare repositories, addressing a potential security vector where Git could inadvertently operate on bare repos in untrusted directories.

The series comes from Johannes Schindelin (Git for Windows maintainer) and represents a follow-up to earlier discussions about how to handle this breaking change in the test suite. The key insight here is to modify the test infrastructure to set `safe.bareRepository=all` in the global config when `WITH_BREAKING_CHANGES` is enabled, rather than modifying individual tests. This approach maintains test compatibility while allowing the security change to proceed.

The series includes 8 patches:
1. Core test infrastructure change to allow bare repo access in tests
2-7. Various test fixes to handle side effects of writing to `$HOME/.gitconfig`
8. The actual behavior change making "explicit" the default when `WITH_BREAKING_CHANGES` is set

The changes touch multiple test scripts across different areas of Git's functionality, showing the wide impact of this security change. The documentation updates explain both the new default behavior and the rationale behind it in `BreakingChanges.adoc`.

This appears to be a well-considered approach to introducing a security-hardening change while minimizing test suite disruption. The series carefully handles edge cases where tests might interfere with the global config setting or where the config file might appear in test output. The change aligns with Git's increasing focus on security defaults, though the use of `WITH_BREAKING_CHANGES` suggests this may be staged for a future major version where breaking changes are expected.
