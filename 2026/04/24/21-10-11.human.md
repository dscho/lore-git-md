This is a bugfix patch in the final iteration of a long-running series that implemented autostash behavior for `git checkout -m`. The series has already been merged, and this patch addresses a cleanup issue found during post-merge review.

The patch fixes a resource leak in `merge_working_tree()` where several early return paths were exiting without releasing the index lock file. While currently harmless since the process exits soon after, this could cause problems if the function were ever used multiple times in the same process. The change adds proper lock cleanup to all early return paths in the function.

This is a straightforward mechanical fix that:
1. Adds `rollback_lock_file()` calls to 7 different error/early return paths
2. Maintains the existing behavior while making it more robust
3. Follows the pattern established in the rest of the codebase

The patch is part of a well-tested series that has gone through extensive review (19 iterations total) and represents the final cleanup of a now-stable feature. The change is small, focused, and clearly motivated by the review feedback from Phillip Wood.
