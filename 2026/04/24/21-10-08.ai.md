This is a feature patch adding customizable conflict marker labels to `git stash apply`, part of the concluded autostash implementation effort. The patch allows users to specify custom labels for the "ours", "theirs", and "base" sides of merge conflicts when applying stashes, rather than using the default "Updated upstream"/"Stashed changes"/"Stash base" labels.

The implementation:
- Adds new `--label-ours`, `--label-theirs`, and `--label-base` options to `git stash apply`
- Updates documentation to describe the new options
- Modifies the conflict marker generation in xdiff/xmerge.c to handle empty labels
- Adds test cases verifying:
  - Custom labels work with diff3 conflict style
  - Empty labels produce minimal markers
  - The feature integrates properly with the existing stash workflow

This was the first patch in the final v15 series that completed all post-merge refinements for the autostash feature. The implementation is clean and focused, with thorough test coverage for both the happy path and edge cases. The changes touch only the expected subsystems (stash command plumbing, and xdiff internals) without introducing any broader architectural impacts.

The patch represents a polished final state after extensive review, with all technical considerations around error handling, edge cases, and user experience having been addressed across 18 iterations of development. The test cases in particular demonstrate careful attention to real-world usage scenarios while avoiding redundancy.
