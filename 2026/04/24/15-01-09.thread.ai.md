Thread summary:

Security-focused patch set from Johannes Schindelin changing default bare repository access behavior when built with WITH_BREAKING_CHANGES. The series makes safe.bareRepository default to "explicit" in such builds, requiring explicit permission to access bare repos as a security hardening measure. This addresses potential vulnerabilities where Git might operate on bare repos in untrusted directories.

The 8-patch series takes a careful approach to test compatibility by modifying the test infrastructure to globally set safe.bareRepository=all when WITH_BREAKING_CHANGES is enabled, rather than requiring per-test modifications. Patches 2-7 handle various test fallout from writing to $HOME/.gitconfig, while patch 8 implements the core behavior change. Documentation updates in BreakingChanges.adoc explain the new default and its security rationale.

The changes span multiple test areas demonstrating the wide impact of this security change. The approach shows thoughtful consideration of both security goals and practical test maintenance, with particular attention to edge cases involving global state and config file visibility in test output. This appears positioned as a breaking change for a future major version, using the WITH_BREAKING_CHANGES flag as a staging mechanism while maintaining current behavior in standard builds.
