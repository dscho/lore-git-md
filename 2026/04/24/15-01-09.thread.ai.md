Security-focused patch set from Johannes Schindelen changing default bare repository access behavior when built with WITH_BREAKING_CHANGES. The 8-patch series makes safe.bareRepository default to "explicit" in such builds, requiring explicit permission to access bare repos as a security hardening measure. Version 2 incorporates Junio Hamano's feedback to modify test infrastructure globally rather than individual tests, and ensures compatibility with Patrick Steinhardt's set -e work by being more careful about .git/info/exclude creation.

The series begins with a test infrastructure patch that globally configures safe.bareRepository=all when WITH_BREAKING_CHANGES is enabled, ensuring existing tests continue working after the default behavior becomes more restrictive. Patch 2/8 addresses an interaction between the test infrastructure's global config settings and XDG config file precedence in `git maintenance` tests. Patch 3/8 handles test fallout in t1300-config.sh where the safe.bareRepository setting leaks into git config --list output. Patch 4/8 (this update) fixes t1305-config-include.sh by explicitly using `--git-dir=.` when accessing a bare repo in tests, removing dependency on global config for repository discovery. Patches 5-7 will address additional test fallout from writing to $HOME/.gitconfig, with patch 6 adding a test helper to filter .gitconfig from ls-files output. Patch 8 implements the core behavior change, while documentation updates in BreakingChanges.adoc explain the new default and its security rationale.

Junio Hamano has reviewed patch 6/8, acknowledging its technical merit while reflecting on how test infrastructure design might have avoided such edge cases if started fresh. He reports integration issues when this series interacts with other in-flight topics, particularly test failures when WITH_BREAKING_CHANGES is enabled. The v2 changes address some concerns by better aligning with ongoing test infrastructure work, including Patrick Steinhardt's set -e changes.

The approach shows thoughtful consideration of both security goals and practical test maintenance, with particular attention to edge cases involving global state (XDG config precedence in patch 2/8, config output visibility in patch 3/8, bare repo access in patch 4/8) and config file visibility in test output. This remains positioned as a breaking change for a future major version, using the WITH_BREAKING_CHANGES flag as a staging mechanism while maintaining current behavior in standard builds. Open questions persist about integration with other in-flight topics when the breaking changes flag is enabled, particularly around test interactions that may need resolution before merging. The series continues its careful progression from test preparation (patch 1) through specific test fixes (patches 2-7) to the core behavior change (patch 8).
