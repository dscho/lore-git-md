Thread type: patch series (4 versions, 4 emails in thread)

Core problem or goal: Reduce the system call overhead in `index-pack` and `unpack-objects` by increasing the input buffer size from 4 KiB to 128 KiB. This is especially beneficial on FUSE filesystems, where writes are amplified.

Current status: Merged to `next` by Junio C Hamano. The v4 version was accepted; v3 already had consensus approval, and v4's improvements (replacing strace-based measurements with direct FUSE daemon logging) were final polish. No open questions remain.

Key technical details:
- Files touched: `builtin/index-pack.c`, `builtin/unpack-objects.c`, `git-compat-util.h`, `csum-file.c`.
- New symbol: `DEFAULT_IO_BUFFER_SIZE` constant in `git-compat-util.h`, set to 128 KiB. Naming feedback from Derrick Stolee (v2) reflected the constant's broader usage.
- Performance: 94% write reduction on FUSE (74,958 to 4,687 writes, measured via FUSE daemon logging, not strace). 10-11% faster clones: vscode repo (75.7s vs 84.5s), git/git (20.0s vs 22.6s).
- The commit message includes analysis of why the theoretical 97% write reduction isn't achieved: small application-level flushes and Linux pipe buffer sizes. Junio analyzed the flush behavior; Jeff King (Peff) noted that `git fetch`'s 64 KiB sideband demuxer packets constrain the optimization impact.
