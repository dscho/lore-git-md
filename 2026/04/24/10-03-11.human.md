Feature proposal adding automatic remote fetching to `git checkout` and `git switch`.

Harald Nordgren proposes a new `--fetch` option for `git checkout` and `git switch` that automatically fetches from the remote when the start-point argument references a remote branch. The patch also introduces a `checkout.autoFetch` config option to enable this behavior by default.

The motivation comes from a common workflow where developers first fetch from a remote before creating a new branch from an up-to-date remote reference. The new option combines these steps while ensuring the remote reference is fresh. If the fetch fails, the checkout operation aborts to prevent creating a branch from stale data.

The implementation adds:
- A `--fetch` flag to both commands
- A new `fetch_remote_for_start_point()` helper function
- Configuration option `checkout.autoFetch`
- Comprehensive tests covering various usage scenarios
- Bash completion support

The patch appears well-structured with clear commit messages and thorough test coverage. This could be a useful quality-of-life improvement for developers who frequently create branches from remote references. The opt-in nature (via both CLI flag and config) makes it non-disruptive while providing the convenience when wanted.
