Feature patch discussion about `--fetch` option for `git checkout`/`git switch`.

Marc Branchaud raises concerns about the design of the proposed `--fetch` option that automatically fetches from a remote when checking out a branch. While the original patch ties the fetch behavior specifically to remote-tracking refs (like `origin/foo`), Marc suggests this is overly restrictive and could confuse users who might expect `--fetch` to work for any checkout operation (like tags or local branches).

The key critique is that the current implementation's remote-specific behavior seems unnecessarily complex compared to a simpler "just fetch everything" approach. Marc notes this could particularly trip up users with multiple remotes who might want to fetch all remotes before checking out any reference. The feedback suggests reconsidering the scope of the fetch operation to be more general rather than tied to the start-point's remote association.

This is a substantive design-level review that questions the fundamental approach rather than just implementation details. The discussion now centers on whether the convenience of the remote-specific fetch justifies the potential confusion, or if a more straightforward fetch-all behavior would be simpler to understand and maintain. The thread appears to need input from other contributors to help weigh these tradeoffs.
