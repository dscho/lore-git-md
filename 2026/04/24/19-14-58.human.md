Performance optimization for `index-pack` and `unpack-objects` when working with FUSE filesystems.

Scott Bauersfeld proposes increasing the input buffer size from 4KB to 128KB in both `index-pack` and `unpack-objects` to reduce the buffer size already used by the hashfile layer. The current small buffer causes many small writes that are particularly inefficient on FUSE filesystems where each write becomes a synchronous round trip.

The patch includes benchmark results showing a 66% reduction in pack file writes and elimination of all 4KB writes when cloning a ~296MB repository. The change maintains correctness while improving performance, particularly for FUSE-backed storage. The new 128KB size matches Git's existing default buffer size in `csum-file.c`.

The change is straightforward - just increasing a buffer size constant in two files - and comes with clear performance measurements showing the benefit. The patch appears well-motivated and low-risk since it doesn't change any logic, just the I/O chunk size.
