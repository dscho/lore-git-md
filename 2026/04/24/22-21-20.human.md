Maintainer feedback on the `--fetch` checkout/switch feature proposal.

Junio C Hamano, the Git maintainer, expresses strong reservations about the proposed `--fetch` option and `checkout.autoFetch` configuration for `git checkout` and `git switch`. While acknowledging that checkout has special handling for remote-tracking branches, he argues this particular change goes too far in altering fundamental assumptions about remote-tracking ref stability.

The core concern is that remote-tracking branches are widely used throughout Git commands (like `git log`, `git grep`, and `git rev-list`) as stable references to specific commits. Automatically fetching before resolving these refs would break the expectation that they remain constant during a command sequence. Junio questions whether such auto-fetch behavior should then apply consistently across all commands using remote-tracking refs, implying this would be an impractical scope expansion.

This feedback from the maintainer suggests the current proposal is unlikely to be accepted in its present form, as it challenges a basic assumption about how remote-tracking refs behave. The discussion now pivots to whether the feature can be redesigned to avoid this fundamental issue, or if the convenience benefit justifies changing Git's reference model. The thread's future direction will likely focus on reconciling the workflow improvement with Git's core behavior expectations.
