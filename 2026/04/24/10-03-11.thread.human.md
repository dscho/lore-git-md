Junio Hamano has firmly closed the door on the proposed `--fetch` option for `git checkout` and `git switch`, rejecting it on workflow philosophy grounds despite the technical completeness of Harald Nordgren's implementation. The maintainer argues that automatically fetching remote refs when creating branches encourages poor practices by removing the explicit verification step developers should perform before branching. Junio suggests that if such a feature were to be reconsidered, it should integrate with `--track` rather than introducing a new flag, but makes clear his fundamental objection remains - Git workflows should maintain remote-tracking branch stability as an invariant.

Harald's v4 patch had addressed all technical feedback, adding comprehensive test coverage for `--no-fetch` override cases and refining the single-branch fetch behavior. Reviewers like D. Ben Knoble and Ramsay Jones had contributed to improving the implementation, though some (like Ramsay) personally preferred separate fetch/checkout operations. The discussion now appears concluded unless other contributors can present new arguments that satisfy Junio's workflow concerns, which seems unlikely given the maintainer's strong stance on preserving Git's explicit verification model. The thread may see final acknowledgments when Junio returns from vacation, but the feature's rejection appears definitive.
