Harald Nordgren has submitted version 11 of his patch series adding a `--track=fetch` mode to `git checkout` and `git switch`, which automatically fetches from the remote when creating a tracking branch. This version directly addresses Junio C Hamano's technical concerns from the v10 review by completely rewriting the remote resolution logic.

The key improvement in v11 is proper handling of custom refspec mappings (like fetching into `refs/remotes/upstream/*` from `origin`) by querying all remotes' fetch refspecs rather than making assumptions about remote naming. It also adds support for bare namespace names by first looking at `<namespace>/HEAD`. The implementation in `resolve_fetch_target()` now uses a callback to match against all remotes and properly follows symbolic refs.

With 18 test cases covering hierarchical remotes, custom refspecs, and error conditions, the feature appears technically sound. Junio's earlier feedback about edge cases has been fully incorporated, and the implementation now handles the scenarios that were problematic in previous versions. Unless new issues surface, this looks ready for final maintainer approval and potential inclusion in an upcoming release. The series has progressed through multiple rounds of review, with each iteration addressing substantive feedback from Junio and others, suggesting the feature has reached maturity.
