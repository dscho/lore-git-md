This thread is about a patch series by Harald Nordgren that adds a `--track=fetch` option to `git checkout` and `git switch`. The feature automatically fetches the remote branch when creating a local tracking branch, aiming to reduce merge conflicts and duplicated work by ensuring users start from the latest remote tip rather than a stale local copy. The series is now in its 15th iteration, split into two patches: the first refactors existing code to expose tracking remote lookup functions, and the second implements the feature.

The technical work is complete and approved by Junio C Hamano, but the maintainer has expressed sustained reservations about the feature's workflow value, particularly concerning network operations during checkout without user preview. Harald has addressed all code nits from Phillip Wood's review, including dropping `RESOLVE_REF_NO_RECURSE`, removing redundant checks, improving initialization style, and streamlining the test suite. The commit message now more clearly articulates the workflow benefits, framing the feature as a pragmatic alignment with user expectations rather than a novel convenience.

The series is ready for a final decision from Junio on whether the workflow benefits justify its inclusion. While the implementation is clean and well-tested, the core question remains whether automating the fetch step during checkout is a net improvement for users. Phillip Wood and D. Ben Knoble have both expressed hesitation about bundling fetch and checkout into a single step, though Phillip's technical concerns have been fully addressed. No new objections are expected, but the feature's future depends on Junio's assessment of its merit.
