This thread proposes adding a `--fetch` option to `git checkout` and `git switch` that would automatically fetch remote refs before creating a new branch. The fourth version of the patch now includes tests verifying that `--no-fetch` correctly overrides both config settings and earlier `--fetch` flags on the command line, addressing a gap identified in Ramsay Jones' review of v3.

Technically, the implementation has matured through four iterations, with v4 demonstrating robust handling of edge cases: it fetches only the specific remote-tracking branch when given as a start point, performs full remote fetches for bare remote names, and properly respects the `--no-fetch` override. The tests now comprehensively cover the expected behavior.

However, the fundamental design question remains unresolved. Maintainer Junio Hamano has previously expressed concerns about whether automatic fetching aligns with Git's workflow principles and the expected stability of remote-tracking branches. These philosophical objections haven't been addressed in the patch series, which has focused instead on refining the technical implementation. The discussion is effectively on hold until the maintainer returns from vacation to weigh in on the higher-level design questions. While the code appears technically sound, its future depends on resolving these workflow philosophy questions.
