Maintainer feedback on the `--fetch` checkout/switch feature proposal.

Junio C Hamano, the Git maintainer, raises a fundamental concern about the proposed `--fetch` option and `checkout.autoFetch` configuration. While acknowledging that checkout has special handling for remote-tracking branches, he questions whether automatically fetching before operations that reference remote-tracking branches is the right approach. He points out that many common Git operations (like `git log`, `git grep`, and `git rev-list`) rely on the stability of remote-tracking refs, and suggests that if we add auto-fetch behavior for checkout, we might need to extend it to all commands that use remote-tracking refs for consistency.

This feedback from the maintainer represents a significant design challenge for the proposal. Junio is not just reviewing the implementation details but questioning the fundamental premise of when and where automatic fetching should occur. His comment suggests that either:
1) The feature should be reconsidered entirely, or
2) The scope needs to be significantly expanded to cover all remote-tracking ref usage, which would be a much larger change to Git's behavior.

The maintainer's position contrasts with the earlier reviews which focused on implementation details and test coverage. This raises the bar for the feature's acceptance, as it now needs to address these broader design concerns about Git's behavior with remote-tracking refs. The patch author will need to either justify why checkout/switch should be special cases for auto-fetching, or reconsider the approach entirely.
