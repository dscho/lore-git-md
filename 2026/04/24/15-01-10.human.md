This is a test infrastructure patch preparing for a future breaking change in Git's default behavior regarding bare repository access. It's part of a larger 8-patch series (this being the first), though we haven't seen the cover letter yet.

The patch addresses an upcoming change where `safe.bareRepository` will default to `explicit` (rather than `all`) when Git is built with `WITH_BREAKING_CHANGES`. This would break many tests that implicitly access bare repositories. Rather than modifying hundreds of tests, Johannes Schindelin (with input from Junio) proposes setting `safe.bareRepository=all` in the test environment's global config when `WITH_BREAKING_CHANGES` is enabled.

The solution is pragmatic but comes with some caveats - the global config file gets created in the test's working tree and could interfere with tests checking untracked files. The patch handles this by excluding `.gitconfig` via `.git/info/exclude`, though follow-up patches will address remaining edge cases.

This appears to be a well-considered preparatory change that maintains test coverage while allowing the default behavior to evolve. The commit message clearly explains the rationale and acknowledges limitations that will be addressed later in the series.
