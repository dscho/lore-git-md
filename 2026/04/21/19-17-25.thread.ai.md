Subject: Ninja build system compatibility fix for config-list.h generation
Thread type: build system patch
Author: Toon Claes
Core problem: Resolved build failures on older Ninja versions (pre-1.10.0) due to multi-line dependency parsing bug in config-list.h generation, particularly affecting AlmaLinux 8 (Ninja 1.8.2).

Technical details:
- Final implementation uses `tr` to unconditionally collapse dependencies onto single line (Patrick Steinhardt's suggestion)
- Phillip Wood identified portability issue with `\n` in sed replacement strings
- Two proposed alternatives for more portable implementation:
  1. Actual newline in sed script
  2. printf-based line construction
- Works around Ninja parser bug while maintaining compatibility with both Make and all Ninja versions
- Preserves no-op targets in config-list.h.d for Make compatibility
- Changes isolated to meson.build and generate-configlist.sh
- No runtime behavior changes
- Verified working on Ninja 1.8.2 through real-world testing
- GCC-generated depfiles already use single-line format, supporting solution's general applicability

Status: Ready for merging with consensus achieved, pending portability refinement
Participant positions:
- Toon Claes: Implemented and tested final solution
- Patrick Steinhardt: Proposed unconditional approach (substantive technical review), confirmed solution works
- Phillip Wood: Identified sed portability issue (substantive technical review), suggested portable alternatives
