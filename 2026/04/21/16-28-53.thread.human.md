This thread addresses a bug in git-gui where it fails with cryptic errors when launched from bare repositories or locations without accessible worktrees. The discussion has evolved through several proposed solutions, now centering on a fundamental tradeoff between correctness and backward compatibility.

Shroom Moo's latest patch (v4) takes a strict approach, preventing git-gui from running in any gitdir context. Johannes Sixt (Hannes) countered with a more permissive alternative that would maintain compatibility with launching from .git directories - a longstanding behavior dating back to pre-worktree support. However, Mark Levedahl has now identified a concerning edge case where Hannes' approach could allow accidental file operations directly in the gitdir when core.bare=false but no valid worktree exists, potentially leading to data corruption.

Mark strongly advocates for either failing fast with a clear error or presenting an interactive worktree selection dialog, arguing that silent directory switching could mask user errors. His analysis lends significant technical weight to the correctness-focused side of the debate. The thread now presents maintainers with a clear choice: preserve historical behavior at the risk of edge case problems, or enforce stricter boundaries at the cost of breaking some existing workflows. Johannes Schindelin (git-gui maintainer) or Junio Hamano's input will likely be needed to resolve this policy question.
