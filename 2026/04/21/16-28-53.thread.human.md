This thread addresses a bug in git-gui where it fails with cryptic errors when launched from bare repositories or locations without accessible worktrees. The original patch author, Shroom Moo, has gone through several iterations, with v4 representing a major shift by adopting Mark Levedahl's suggestion to use `git rev-parse --is-inside-git-dir` as the primary detection mechanism. This simpler approach explicitly blocks all gitdir launches (including .git subdirectories) while maintaining bare repository detection and providing clearer error messages.

Johannes Sixt (Hannes) has now entered the discussion with historical context, noting that git-gui's current behavior predates worktree support. He proposes a middle-ground solution that would preserve compatibility with launching from .git directories while still addressing the core safety issues. His approach would first check for bare repositories, then attempt to find the worktree, falling back to the parent directory if in a .git directory.

The thread now presents three distinct technical approaches: Shroom Moo's original v3 attempt to preserve .git directory launching, Mark Levedahl's stricter v4 solution that blocks all gitdir launches, and Hannes' compromise that maintains more backward compatibility. While the v4 patch appears technically sound, Hannes' historical perspective and alternative proposal may influence the final decision, particularly regarding whether to break backward compatibility with existing workflows that launch from .git directories. The git-gui maintainer will likely need to weigh in on which approach best balances safety and compatibility.
