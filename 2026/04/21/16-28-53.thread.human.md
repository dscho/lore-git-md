This thread documents a completed bugfix series for git-gui that has now been merged. The series, authored by Shroom Moo and implemented by Mark Levedahl, addresses long-standing issues with repository and worktree detection that could cause cryptic errors in edge cases. The 12-patch v3 series standardizes git-gui's behavior to match core Git's repository discovery logic, particularly for bare repos, missing worktrees, and .git directory launches.

The latest patch (9/12) specifically improves worktree detection when git-gui is launched from within a repository directory. It introduces robust validation to ensure discovered worktrees correctly point back to their gitdirs, handling three key scenarios: when core.worktree is set, when the gitdir is a .git subdirectory, and when it's a worktree-specific directory. The changes maintain backward compatibility while fixing edge cases broken since Git 2.19.

Maintainer Johannes Sixt contributed two patches to the series and approved the final version, which has addressed all substantive feedback across three iterations. The changes complete an architectural shift to use git rev-parse --absolute-git-dir for repository discovery and --show-toplevel/--show-prefix for worktree detection, making git-gui's behavior consistent with core Git's CLI. The series also includes fixes for browser and blame subcommands, environment variable handling, and repository picker behavior.
