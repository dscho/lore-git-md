This thread documents a completed 12-patch series that fixed several long-standing edge cases in git-gui's repository and worktree detection. The core issue was that git-gui would produce cryptic errors when dealing with bare repositories, missing worktrees, or when launched from a .git directory. 

Shroom Moo and Mark Levedahl led the effort across three iterations, with maintainer Johannes Sixt contributing cleanup patches and approving the final version. The series standardized repository discovery using `git rev-parse --absolute-git-dir`, improved worktree validation, removed problematic heuristics, and aligned git-gui's behavior with core Git's expectations. A key improvement was eliminating the path-before-rev argument ordering that could silently fail.

The final patch, which just landed, adds explicit `gui` and `pick` subcommands to give users more control over when the repository picker appears. The `gui` subcommand fails with an error if repository discovery fails (rather than automatically showing the picker), while `pick` always shows the picker first. This maintains backward compatibility while making the behavior more predictable. The series has now fully addressed all the original issues, with Johannes Sixt merging the complete set of improvements.
