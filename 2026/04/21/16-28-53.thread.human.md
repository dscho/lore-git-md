This thread covers a series of bugfixes for git-gui that address long-standing issues with repository and worktree detection. The patches, authored by Shroom Moo and implemented by Mark Levedahl, fix edge cases involving bare repositories, missing worktrees, and .git directory launches that previously caused cryptic errors. The 11-patch v2 series has received thorough review and final technical approval from git-gui maintainer Johannes Sixt.

The fixes comprehensively address repository discovery, worktree validation, and path resolution by using core Git's `git rev-parse` infrastructure consistently. Specific improvements include proper handling of bare repository contexts in blame/browser subcommands, detached HEAD state display, root directory path resolution, and early failure for configuration errors. The final patch just added introduces explicit `gui` and `pick` subcommands that give users more control over when the repository picker appears, completing the series' goal of making startup behavior more predictable.

With all technical concerns addressed and maintainer approval secured, this series is now ready to be merged. It resolves issues dating back to 2014/2019 regressions while aligning git-gui's behavior with core Git's conventions, particularly around worktree handling and bare repository contexts. The detached HEAD fix also addresses a regression from 2024's reftable changes.
