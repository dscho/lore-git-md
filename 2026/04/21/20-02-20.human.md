This is the final patch in Taylor Blau's bugfix series for pseudo-merge bitmaps, addressing a memory leak in the pattern handling code. The patch fixes an issue where redefining a pseudo-merge group's pattern would leak the internal state of the previously compiled regular expression.

The key changes are:
1. Adds proper cleanup of the old regex_t state via regfree() before freeing the memory when a pattern is reassigned
2. Includes a new test case that verifies the fix by setting the same group's pattern twice and confirming no leaks occur

This completes the series that has systematically addressed various issues in the pseudo-merge bitmap implementation, from lookup table sorting to date parsing and now memory management. The patch shows careful attention to resource cleanup and includes thorough test coverage, maintaining the high standard set by the rest of the series.

The changes are straightforward and well-contained, focusing specifically on the leak scenario without introducing any new functionality. With this patch, the pseudo-merge bitmap implementation appears to be in good shape, with comprehensive test coverage validating both the fixes and expected behavior.
