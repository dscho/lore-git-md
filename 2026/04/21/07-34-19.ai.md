This is part 6 of Patrick Steinhardt's 12-part series to make Git's test suite compatible with `set -e` (errexit), now in its final form ready for merging. The patch focuses on adapting tests that execute potentially failing commands outside conditionals, which would cause immediate test failure under `set -e`.

The changes convert several test patterns to be `set -e` safe:
- Replaces direct command execution with conditional checks for binary availability (svn, cvs, git)
- Modifies test helpers like `test_might_fail()` to properly capture exit codes
- Updates test framework plumbing to handle exit codes safely
- Adjusts signal handling tests to work with strict error checking

The patch touches core test infrastructure files (test-lib.sh, test-lib-functions.sh) along with several test scripts that verify external tool integration (git-svn, git-cvsserver) and special cases like large file handling. Each change maintains the original test semantics while ensuring compatibility with `set -e`.

This represents the mechanical completion of the test suite adaptations needed for the broader `set -e` effort, following thorough review and iteration. The changes are focused and well-contained, with all technical questions resolved in previous rounds.
