This is a feature patch in Taylor Blau's ongoing series to improve Git's repacking strategy for large repositories. It implements the core incremental MIDX repacking functionality that maintains a geometric MIDX chain structure to avoid periodic full repacks.

The patch introduces `write_midx_incremental()` which constructs and maintains an incremental MIDX chain during geometric repacking. Key aspects:

1. The strategy writes a new MIDX layer containing newly created packs plus any surviving packs from the previous tip layer if it was rewritten.

2. Adjacent MIDX layers are merged when the accumulated object count exceeds half the next deeper layer's count (controlled by `repack.midxSplitFactor`).

3. The implementation uses atomic operations with a lockfile to safely update the MIDX chain, executing each compaction step with `--no-write-chain-file` before atomically updating the chain file.

4. The patch includes extensive trace2 instrumentation to help diagnose compaction decisions and performance characteristics.

This builds on previous preparatory work in the series and will be exposed to users via `git repack --write-midx=incremental` in a subsequent patch. The implementation shows careful attention to edge cases and resource management, with clear commit message documentation of the strategy.

The patch is part of a larger effort to improve Git's scalability for large repositories by avoiding expensive periodic full repacks while still maintaining good object locality. It represents a significant architectural improvement to Git's object storage layer.
