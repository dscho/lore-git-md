This is the final patch in Patrick Steinhardt's series to make Git's test suite compatible with `set -e` (errexit), now ready for merging. The patch enables strict error checking by default for Bash 5+ (with opt-in via `GIT_TEST_USE_SET_E` for other shells), ensuring that failures outside test cases will abort immediately rather than being silently ignored.

The change addresses a real reliability issue - the test suite previously missed failures in setup/teardown code and helper functions. The implementation activates `set -e` in CI for Linux jobs while carefully handling shell compatibility concerns. This completes a six-iteration effort that has undergone thorough review from Jeff King, Junio Hamano, and others, with all technical questions now resolved.

The patch itself adds the core enabling mechanism in `t/test-lib.sh` and configures CI to use `set -e` for Linux jobs. It includes robust boolean parsing of the environment variable and version checking to avoid problematic shells. This represents a significant improvement to test suite reliability by catching previously silent failures, while maintaining compatibility across all supported platforms.
