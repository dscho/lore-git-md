Bugfix for `git grep` column output with `--only-matching`.

Brandon Chinn reports an inconsistency in `git grep` output when using both `--column` and `--only-matching` flags. The issue manifests when searching for multiple matches on a single line - while GNU grep correctly reports each match's byte offset, Git's output shows incorrect column numbers for subsequent matches.

The test case demonstrates the problem clearly: searching for 'x' in "x   x   x" should show matches at columns 1, 5, and 9 (0-based), but Git reports 1, 2, and 6 instead. This suggests the column counting logic isn't properly resetting between matches when `--only-matching` is active.

The bug appears in Git 2.51.1 on macOS/arm64, though it's likely not platform-specific. The report doesn't include a patch but provides a clean reproduction case that would make this straightforward to debug. This seems like a genuine bug in the column calculation logic rather than a documentation or edge case issue.
