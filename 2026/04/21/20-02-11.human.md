This is patch 6/9 in Taylor Blau's bugfix series for pseudo-merge bitmaps, addressing a critical to the feature's correct operation. The patch fixes a date classification bug where unparsed commits were being incorrectly categorized as "stable" due to their default zero timestamp.

The key fix is adding `repo_parse_commit()` after `lookup_commit()` in `find_pseudo_merge_group_for_ref()`, ensuring commit dates are properly read before classification. Without this, the stable/unstable partitioning was effectively broken, causing pseudo-merges to be formed based on size alone rather than the intended date-based decay pattern.

The included test demonstrates the fix by configuring two pseudo-merge groups - one targeting stable commits (older than 1 month) and one targeting all commits. With the fix, only the "all" group matches the test commits (which are all recent), while previously both groups would match due to the zero-date issue. The test uses GIT_TEST_DATE_NOW to precisely control the time context.

This patch reveals another issue (sampleRate=0 causing division by zero) which will be addressed in a subsequent patch, as noted by the test being marked as failing. The changes show careful attention to review feedback and maintain the series' high standard of test coverage.
