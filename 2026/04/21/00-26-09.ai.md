This is the third patch in Elijah Newren's series fixing merge-ort issues with duplicate tree entries and D/F conflicts. The patch addresses a memory leak in the merge machinery's cleanup path.

The change fixes a case where diff pairs could be leaked if collect_merge_info() encountered an error before resolve_and_process_renames() had a chance to free them. The patch adds proper cleanup of renames->pairs[].queue in clear_or_reinit_internal_opts(), which handles cleanup of merge_options_internal structures. The fix is straightforward - freeing the queue and reinitializing it - and safe since the normal path already NULLs the pointer first.

This is a technical cleanup that plugs a resource leak in the error path, maintaining the series' focus on hardening merge-ort's handling of edge cases. The change is small (just 2 lines) but important for correctness, coming from the merge subsystem maintainer who knows this code intimately. No new tests are needed here since the leak would only manifest in error cases that the series' other tests already cover.
