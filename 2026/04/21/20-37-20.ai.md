This is a refactoring patch in Taylor Blau's incremental MIDX/bitmap-based repacking series. It improves the code structure for tracking MIDX file checksums during repacking operations.

The patch simplifies the logic for building the `keep_hashes` array by:
1. Collecting MIDX layers into a temporary array while traversing forward
2. Then filling `keep_hashes` sequentially by processing the temporary array in reverse
3. Adding an assertion to verify the final count matches expectations

This replaces the previous approach that used reverse indexing (`keep_hashes[count - i - 1]`) during forward traversal, which was harder to follow. The change is purely internal - no user-visible behavior is modified. It prepares for a future switch to using `strvec` for the checksum storage.

The patch demonstrates careful attention to code quality in a performance-sensitive area of Git's multi-pack-index handling. It's part of the larger effort to improve repacking for large repositories, though this particular change focuses on maintainability rather than functionality.
