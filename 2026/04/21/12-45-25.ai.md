This is a bugfix for the files ref backend's consistency checking, addressing an issue where lock files (`.lock`) were being processed during verification. The patch is part of an ongoing thread where Karthik Nayak is responding to Junio C Hamano's review.

Karthik clarifies the reasoning behind moving the lock file check from `files_fsck_refs_name()` to `files_fsck_refs_dir()`. He explains there are two callers of `files_fsck_ref()` - one that handles root refs (which won't encounter lock files) and one that manually iterates the refs directory (where lock files need skipping). This makes `files_fsck_refs_dir()` the appropriate place for the check, as any future checks would be added via the `fsck_refs_fn[]` array and thus automatically inherit the lock file skipping behavior.
