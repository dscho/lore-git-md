This is a bug report about `git grep`'s column output when using `--only-matching`. The reporter, Brandon Chinn, demonstrates a discrepancy between GNU grep and Git's grep behavior when searching for the same pattern in a simple test file.

The key finding is that with `--only-matching` and `--column` options together, `git grep` shows incorrect column numbers for matches. The first match is reported at column 1 (correct), but subsequent matches on the same line show incorrect positions (2 and 6) when they should be at 4 and 8 like GNU grep shows. The test case uses a file containing "x   x   x" to clearly demonstrate the issue.

The bug appears in Git version 2.51.1 on macOS/arm64). The reporter asks if this is a known limitation, suggesting they haven't found prior reports of this specific issue. The problem appears to be in how Git calculates column positions for multiple matches on a single line when using `--only-matching`.

This would affect anyone using `git grep` with these options for precise match location reporting, particularly in contexts like editor integrations or scripts that parse the column output. The bug report provides a clear minimal reproduction case that should make it straightforward to investigate and fix the column calculation logic.
