Subject: git grep --only-matching shows incorrect column numbers for multiple matches on same line

Brandon Chinn reported a bug where `git grep --only-matching --column` produces incorrect column positions for multiple matches on a single line, showing positions 1, 2, 6 for "x   x   x" instead of the expected 1, 4, 8 (matching GNU grep). The issue affects Git 2.51.1 and appears to stem from incorrect column calculation logic when processing multiple matches per line with `--only-matching`.

René Scharfe confirmed this as a bug, tracing it to Taylor Blau's 2018 implementation which calculated positions relative to previous match ends rather than line start. Scharfe provided a detailed analysis with visual examples and a proposed fix modifying `grep.c` to track line start positions, updating test expectations in `t7810-grep.sh`. The change would align Git's behavior with GNU grep's absolute column positioning, affecting editor integrations and scripted parsing use cases. The patch represents a behavior change from the current implementation but matches user expectations for column reporting.
