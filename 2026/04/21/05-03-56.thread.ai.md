Thread summary:

Subject: git grep --only-matching shows incorrect column numbers for multiple matches on same line

Brandon Chinn reported a bug where `git grep --only-matching --column` produces incorrect column positions for multiple matches on a single line, showing positions 1, 2, 6 for "x   x   x" instead of the expected 1, 4, 8 (matching GNU grep). The issue affects Git 2.51.1 and stems from Taylor Blau's 2018 implementation calculating positions relative to previous match ends rather than line start.

René Scharfe confirmed the bug and proposed a fix modifying `grep.c` to track line start positions, with test updates in `t7810-grep.sh`. Phillip Wood joined the discussion, validating René's analysis and noting the current behavior appears unintentional based on the original review focus. Phillip agrees absolute column positions (GNU grep style) would better match user expectations for the `--column` option.

The thread shows consensus forming around fixing this as a bug rather than maintaining the current behavior, with two independent reviewers (Scharfe and Wood) confirming the column numbering is counterintuitive and should align with GNU grep. The proposed change would affect editor integrations and scripted parsing that rely on accurate column positions. Open questions remain about whether the original implementation's behavior was deliberately chosen or an oversight, but technical agreement exists on the correct fix direction.
