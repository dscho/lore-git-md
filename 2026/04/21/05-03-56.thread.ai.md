Subject: git grep --only-matching shows incorrect column numbers for multiple matches on same line

Brandon Chinn reports a bug in `git grep` where combining `--only-matching` with `--column` produces incorrect column positions for multiple matches on a single line. Using a test file containing "x   x   x", the first match shows correctly at column 1, but subsequent matches report positions 2 and 6 instead of the expected 4 and 8 (matching GNU grep's output). The issue is reproducible on Git 2.51.1 (macOS/arm64) and appears to stem from incorrect column calculation logic when processing multiple matches per line with `--only-matching` enabled. No prior reports of this specific behavior were found. The bug impacts use cases relying on precise column positioning, such as editor integrations or scripted parsing of grep output. A minimal reproduction case is provided for investigation.
