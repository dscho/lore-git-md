This is the third patch in Elijah Newren's series fixing merge-ort issues with duplicate tree entries and D/F conflicts. It's a bugfix addressing a memory leak in the merge machinery's error handling path.

The patch fixes a case where `collect_merge_info()` could return early due to an error before `resolve_and_process_renames()` had a chance to clean up queued diff pairs. The diff pairs queue would then leak. The solution adds proper cleanup of `renames->pairs[].queue` in `clear_or_reinit_internal_opts()`, which is merge-ort's general cleanup function.

The change is straightforward and low-risk - it just ensures resources are freed in an error path that was previously missed. Since the queue is already NULL in the normal success case (due to being initialized earlier), this is effectively a no-op for happy paths while preventing leaks in error cases. The patch demonstrates Elijah's characteristic attention to detail in the merge subsystem, catching a subtle resource management issue that could only surface in error conditions.
