This is a test infrastructure patch from Patrick Steinhardt's series to make Git's test suite compatible with `set -e` (errexit). It's patch 3/12 in the sixth iteration of this effort, which is now complete and ready for merging.

The patch specifically addresses the `stop_git_daemon()` helper function in the test suite. Currently, this function has two issues that would cause problems under `set -e`:
1. The `wait` command is expected to fail (since it's waiting for a process we just killed), but without `||` handling, `set -e` would cause the test to abort immediately.
2. The second `kill` call (via PID file) is likely to fail since we already killed the process, and this failure would also trigger `set -e`.

The changes are mechanical but important for reliability - they ensure the test suite can properly handle daemon shutdown under strict error checking. The patch follows the established pattern in this series of using `||` for expected failures and `|| :` to silence non-critical ones.

This is part of the broader effort to harden Git's test infrastructure by enabling `set -e` by default in Bash 5+, catching silent failures that might otherwise go unnoticed. The series has undergone thorough review across six iterations and is now in its final form.
