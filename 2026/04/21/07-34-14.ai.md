This is the first patch in Patrick Steinhardt's final v6 series to make Git's test suite compatible with `set -e` (errexit). The patch focuses on adapting signal-handling test cases to work under strict error checking.

The changes modify three test cases that verify Git dies with SIGPIPE (signal 13) under certain conditions. The original tests used a pattern of `command; echo $?` which would fail under `set -e` when the command terminates with a signal. The patch replaces this with `command && echo 0 || echo $?` to properly capture the exit code while remaining `set -e` safe.

The modifications affect:
1. Two tests in t0005-signals.sh that verify Git dies with SIGPIPE when output is blocked
2. One test in t3600-rm.sh that checks SIGPIPE handling during `git rm`

This is a mechanical change that maintains the exact same test semantics while making the tests compatible with the upcoming `set -e` requirement. The patch follows the established pattern seen throughout the series for handling expected failures under strict error checking.
