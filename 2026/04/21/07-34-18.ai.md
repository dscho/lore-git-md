This is part 5 of Patrick Steinhardt's 12-patch series to make Git's test suite compatible with `set -e` (errexit), now in its sixth iteration and ready for merging. The series has undergone thorough review and addresses a long-standing reliability issue in Git's test infrastructure.

The patch specifically converts conditional test execution patterns from using `&&` chains to proper `if` statements. This change is necessary because under `set -e`, a failed condition in an `&&` chain would cause the entire test script to exit early rather than gracefully skipping the test. The patch updates two test files:

1. `t4032-diff-inter-hunk-context.sh`: Changes file-existence checks before running diff output verification tests
2. `t7450-bad-git-dotfiles.sh`: Modifies conditional tests for symlink handling in the index

The changes are mechanical but important for ensuring test reliability under strict error checking. The patch maintains all existing test semantics while making the code more robust and slightly more readable. This work builds on previous patches in the series that adapted other test patterns (like shell arithmetic and cleanup handlers) for `set -e` compatibility.

The series as a whole represents a significant improvement to Git's test infrastructure by ensuring failures are caught immediately rather than silently ignored. This particular patch is one of several foundational changes needed to enable that behavior safely across the entire test suite.
