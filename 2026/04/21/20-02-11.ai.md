Bugfix for pseudo-merge bitmap date classification. This is patch 6/9 in Taylor Blau's series addressing issues in the pseudo-merge bitmap implementation.

The patch fixes a critical issue where commit dates weren't being properly parsed in `find_pseudo_merge_group_for_ref()`, causing all commits to be incorrectly classified as "stable" (older than threshold) due to their unparsed dates defaulting to zero. This meant the stable/unstable partitioning and sampleRate configuration weren't functioning as intended.

Key changes:
- Adds `repo_parse_commit()` call after `lookup_commit()` to properly load commit dates
- Updates the corresponding test case to expect success now that date classification works
- Reveals a related division-by-zero issue with sampleRate=0 that will be fixed in a subsequent patch

The fix ensures pseudo-merge groups are now correctly partitioned based on actual commit timestamps rather than always using the stable path. This is part of the core bitmap lookup functionality that affects performance optimizations for large repositories.

The patch shows careful attention to the test case, using GIT_TEST_DATE_NOW to align test timestamps with the "1.month.ago" threshold being tested. This demonstrates the bug was well-understood and the fix properly validated.
