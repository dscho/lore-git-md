This is the fourth patch in Elijah Newren's bugfix series addressing issues with duplicate tree entries and directory/file conflict detection in merge-ort. As the recognized expert on Git's merge machinery, his changes carry significant technical weight.

The patch modifies merge-ort to properly abort when encountering trees with duplicate entries, rather than silently overwriting paths and potentially corrupting internal data structures. The core change converts `setup_path_info()` from returning void to returning an int, allowing it to detect and report duplicate paths via `strmap_put()`. When duplicates are found, the merge now fail with a clear error message.

The change is well-motivated by real-world cases where corrupt trees caused assertion failures. The patch includes a new test case that creates a repository with both a gitlink and tree entry for the same path, demonstrating the merge properly aborts rather than proceeding with potentially corrupt state. This builds on the earlier preparatory patches in the series that improved error handling and resource management.

For context, this is part of Elijah's ongoing work to harden merge-ort against edge cases and malformed inputs. The changes are focused and surgical, touching only the necessary parts of merge-ort.c while adding comprehensive test coverage. Given Elijah's deep expertise in this area and the clear demonstration of real-world impact, this appears to be a straightforward improvement to merge safety.
