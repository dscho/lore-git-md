This is the fourth patch in Elijah Newren's bugfix series addressing issues with duplicate tree entries and directory/file (D/F) conflict detection in merge-ort. The patch specifically handles malformed trees containing duplicate entries, which fsck would normally flag as invalid.

The change modifies merge-ort to properly abort when encountering duplicate tree entries rather than silently overwriting paths and potentially triggering assertions. The key technical change is converting setup_path_info() from void to int return to allow error detection, then having it return an error when strmap_put() detects a duplicate path. This bubbles up through collect_merge_info_callback() to abort the merge with a clear error message.

The patch includes a new test case that creates a pathological repository where one side has both a gitlink (submodule) and a tree entry for the same path, then verifies the merge correctly fails with a "duplicate entries" error rather than proceeding with corrupted state. This demonstrates the fix handles a real-world corruption scenario that could previously cause assertion failures.
