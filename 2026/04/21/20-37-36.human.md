This is a refactoring patch in Taylor Blau's ongoing series to improve Git's repacking strategy for large repositories using MIDX (multi-pack-index) and bitmaps. The series is now at version 2 with 16 patches, and this is patch 8/16.

The change is straightforward: it renames an internal helper function `midx_contains_pack_1()` to the more descriptive `midx_layer_contains_pack()` and makes it publicly available via the midx.h header. The key difference from the existing `midx_contains_pack()` is that this new function checks only a single MIDX layer rather than recursing through the entire chain. 

This is a preparatory change that will be used in a subsequent commit to specifically check whether a pack belongs to the tip MIDX layer. The patch maintains all existing functionality while making this capability available to other parts of the code. The implementation is clean and well-contained, with no functional changes - just renaming and exposing the function.

As part of a larger architectural effort to improve Git's scalability for large repositories, this small but meaningful refactoring continues the series' pattern of careful, incremental changes with clear explanations. The patch follows the project's coding style and includes appropriate documentation in the header file.
