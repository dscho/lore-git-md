This is a follow-up in the ongoing discussion about Patrick Steinhardt's proposal to reorganize Git's source tree by moving libgit.a components into a "lib/" directory. The thread has moved from technical design to practical implementation concerns.

Patrick responds to Derrick Stolee's concerns about the impact on in-flight patches and downstream forks. He expresses willingness to help minimize merge conflicts and notes Johannes Schindelin (Git for Windows maintainer) has given preliminary approval. On the timing suggestion to align with a major release (v2.54.0), Patrick agrees but wants to consider other forks beyond Git for Windows.

Regarding Stolee's suggestion to also move command implementations (git.c, git-*.c) into a "cmd/" directory now to avoid future disruption, Patrick reveals he had prototyped this in an earlier version (using "bin/") but chose to focus on the "lib/" move first as it provides the most benefit. While open to doing both, he leans toward incremental changes to keep discussions focused, noting the command move would significantly expand the patch series.

The exchange shows the proposal has technical consensus but is now navigating the practicalities of a large-scale change. Patrick remains flexible on implementation approach while maintaining the core goal of reducing root directory complexity. The next steps will likely involve coordinating timing with downstream maintainers and finalizing whether to include command file relocation in this effort.
