This thread addressed a build system compatibility issue where older versions of Ninja (particularly 1.8.2 on AlmaLinux 8) failed to properly parse multi-line dependencies in config-list.h generation. Toon Claes initially implemented a fix using `tr` to unconditionally collapse dependencies to a single line, following Patrick Steinhardt's suggestion. The core solution was validated through testing and maintains compatibility with both Make and all Ninja versions without runtime impact.

Phillip Wood provided substantive technical review, first identifying a portability issue with using `\n` in sed replacement strings, then offering two portable alternatives: using an actual newline in the sed script or a printf-based line construction. These refinements address edge cases while preserving the solution's effectiveness. The approach aligns with GCC's depfile format, further supporting its general applicability.

The thread demonstrates the project's careful attention to cross-platform compatibility details, with consensus reached on the main approach and only minor implementation refinements remaining. All participants - Toon Claes as implementer, Patrick Steinhardt as solution proposer, and Phillip Wood as portability expert - contributed substantively to reaching a robust solution. The changes are isolated to build system files (meson.build and generate-configlist.sh) with no runtime behavior impact.
