This thread addresses a build system issue affecting Git compilation with older versions of Ninja (pre-1.10.0). The problem manifests when generating config-list.h dependencies, where Ninja's depfile parser incorrectly creates circular dependencies when entries are listed on separate lines.

The proposed solution modifies the generate-configlist.sh script to optionally collapse all dependencies onto a single line when building with affected Ninja versions, while preserving the original multi-line format for Make and newer Ninja builds. The patch includes meson.build updates to detect the Ninja version and pass the appropriate flag automatically. The change was prompted by real-world build problems encountered on AlmaLinux 8, which ships with Ninja 1.8.2.

The implementation appears well-considered, maintaining backwards compatibility and limiting changes to build system components without impacting runtime behavior. The commit provides thorough technical background about the underlying Ninja parser issue and clear reproduction steps, suggesting the author has done careful research into the root cause.
