Brandon Chinn reported a bug where `git grep --only-matching --column` shows incorrect positions for multiple hits on the same line - subsequent matches get offset by the length of previous matches rather than showing their true column positions. This affects tools that rely on precise match locations.

René Scharfe has confirmed the discrepancy with GNU grep's behavior and traced the issue to the original 2018 implementation. He provided a detailed analysis showing how Git currently calculates positions relative to previous match ends instead of line start. His proposed fix would align Git's output with GNU grep by tracking absolute column positions, along with updated tests to verify the corrected behavior.

The thread now has both a clear reproduction case and a technically sound solution from an experienced contributor. Unless there are objections about backwards compatibility or edge cases, this fix will likely be merged in the next release.
