The thread addresses a bug in `git grep --only-matching --column` where multiple matches on the same line show incorrect column positions (e.g., reporting 1, 2, 6 for "x   x   x" instead of the expected 1, 4, 8). Brandon Chinn originally reported the issue, which stems from Taylor Blau's 2018 implementation calculating positions relative to previous match ends rather than line starts.

René Scharfe proposed a fix that modifies `grep.c` to track line start positions, making Git's output match GNU grep's absolute column numbering. Phillip Wood provided a thorough technical review, confirming the approach of maintaining a line start pointer (`bol`) to compute correct absolute columns. He approved the fix with "That looks good, thanks for fixing it," noting the current behavior was likely unintentional. 

The patch includes test updates in `t7810-grep.sh` to verify correct behavior, particularly for edge cases like the "mmap" test where the second match should start at column 14. There's clear consensus that matching GNU grep's output is the right approach, and the change is low-risk since it only affects column calculation logic. With Phillip's approval following earlier validation from other reviewers, the fix appears ready for merging. This will benefit tools that parse `git grep --column` output for precise match locations, such as editor integrations.
