This is patch 3/9 in Taylor Blau's series fixing bugs in the pseudo-merge bitmap implementation. The patch addresses a critical issue where the commit lookup table was being sorted lexically (by OID) rather than by pack position, causing the binary search during fill-in traversal to fail.

The key technical change introduces a custom sort comparator (`pseudo_merge_commit_pos_cmp`) that sorts commits by their position in the pack order rather than by OID. This matches what the reader's binary search expects, fixing the broken fill-in traversal path. The patch also updates a test case that was previously expected to fail (due to this bug) to now expect success.

While this changes the on-disk format to match what was already documented, the author notes this is safe since the previous behavior was effectively broken anyway. The patch maintains compatibility with any out-of-tree implementations that correctly followed the documented format.

This is a substantive fix for a core functionality issue in the pseudo-merge bitmap system, which is an important performance optimization. The change shows careful attention to both the implementation details and backward compatibility considerations.
