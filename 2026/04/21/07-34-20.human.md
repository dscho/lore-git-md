This is patch 7/12 in Patrick Steinhardt's series to make Git's test suite compatible with `set -e` (errexit). The series is now in its sixth iteration and ready for merging, having addressed all review feedback.

The patch focuses on the test cleanup handlers `test_when_finished()` and `test_atexit()`, which run commands after test completion. The current implementation uses `&&` chaining that would break under `set -e` when the test fails. The change replaces this with `||` chaining that properly preserves the test's exit code while being `set -e` safe.

The commit message provides clear truth tables showing the behavior before and after the change, demonstrating how the new version maintains the same semantics while working correctly with strict error checking. This is a mechanical but important change that's part of the broader effort to harden Git's test infrastructure by enabling `set -e` by default in Bash 5+ environments.

The series has been thoroughly reviewed, with Jeff King and others confirming the approach, and all tests pass across supported shells and platforms. This patch represents one of several foundational changes needed to enable reliable error detection in the test suite.
