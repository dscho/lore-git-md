Thread identity: Security bug report for `git-credential-libsecret` helper leaking credentials to stdout during store operations, affecting Git 2.53.0 and master branch.

Core problem: The helper incorrectly writes stored credentials to stdout during `store` operations when invoked directly, potentially exposing secrets in terminal scrollback/logs/CI artifacts. Discussion has clarified this may be the documented storage pattern (high severity) versus an internal implementation detail of `git credential approve` (lower severity if undocumented). Only `get` operations should output credentials in any case.

Current status: Unfixed security vulnerability in current releases. Original reporter provided analysis and fix proposal. Mantas Mikulėnas has raised important questions about interface boundaries that may affect severity assessment and solution approach.

Key technical details:
- Bug location: `git-credential-libsecret` helper
- Affected operations: `store` when using direct helper invocation pattern
- Security impact: Credentials exposed in stdout streams if using direct helper calls
- Interface ambiguity: Whether direct helper invocation for storage is supported public API
- Files involved: `credential-libsecret.c` and credential helper protocol documentation

Open questions:
- Whether direct helper `store` invocation is supported public interface or internal detail
- Whether to accept minimal fix or do broader operation interface refactoring
- Need to audit other credential helpers for similar issues
- Potential documentation updates to clarify proper credential storage patterns

Participant positions:
- Original reporter identified issue and proposed solution
- Mantas Mikulėnas questioning interface boundaries and documented workflows
