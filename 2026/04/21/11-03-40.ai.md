This is a security bug report for the `git-credential-libsecret` helper, which is leaking credentials to stdout during store operations. The issue affects the current stable release (2.53.0) and master branch.

The bug occurs when using the documented non-interactive credential storage pattern - the helper unconditionally writes the username and password back to stdout after storing them in the keyring, exposing secrets in terminal scrollback, log files, or CI artifacts. This is incorrect behavior since only `get` operation should output credentials. The reporter provides a clear reproduction case showing the leak and notes that similar credential helpers may need auditing for the same pattern.

The proposed fix is straightforward - condition the credential write on the operation being `get`. While a more thorough refactoring of the operation interface would be cleaner, the minimal change addresses the immediate security issue. The reporter offers to submit a proper patch if desired.

This is a moderate severity issue since it affects the documented workflow, though it requires the user to run legitimate commands rather than being exploitable by attackers directly. The workaround of redirecting stdout is simple but shouldn't be necessary. The report is well-researched, with clear analysis of the code path and security implications.
