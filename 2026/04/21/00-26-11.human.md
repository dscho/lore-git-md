This is the fifth and final patch in Elijah Newren's series addressing duplicate tree entries and directory/file (D/F) conflict detection in merge-ort. The patch fixes a gap in verify_cache()'s ability to catch non-adjacent D/F conflicts in the index.

The issue occurs when a submodule entry (like "docs") is separated from its conflicting tree entry ("docs/file") by another entry (like "docs-internal/README"). The current verify_cache() only checks adjacent entries, missing this case. The patch modifies verify_cache() to perform a binary search for potential conflicts when it finds a non-adjacent path that shares a prefix.

The change comes with two new test scripts: t0093-direct-index-write.pl (a helper to construct corrupt indices) and t0093-verify-cache-df-gap.sh (which verifies the fix). The tests demonstrate both adjacent and non-adjacent D/F conflict cases, showing write-tree now properly rejects them.

As the merge subsystem maintainer, Elijah's changes carry significant technical weight. This patch completes the series by hardening verify_cache() against a subtle corruption vector, with comprehensive test coverage. The implementation is careful to maintain backward compatibility while fixing the edge case.
