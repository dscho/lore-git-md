This is a bugfix discussion for `git grep`'s column number reporting when using `--only-matching`. René Scharfe confirms Brandon Chinn's report that `git grep --column --only-matching` shows incorrect column positions for multiple matches on the same line, where subsequent matches incorrectly accumulate positions from previous matches rather than showing their absolute position in the line.

René provides historical context, noting this behavior dates back to the feature's original implementation by Taylor Blau in 2018, where the output was presented as expected without challenge. However, René agrees the current behavior is counterintuitive compared to GNU grep's output and proposes a fix that would make column number reporting consistent for all matches.

The proposed patch modifies the column calculation to track each match's position from the start of the line rather than accumulating from previous matches. This would align Git's behavior with GNU grep's output for the test case (showing matches at columns 1, 4, and 8 rather than 1, 2, and 6). The patch includes test updates to verify the new behavior.

This appears to be a straightforward correction of a long-standing but likely low-impact bug in a specialized grep output mode. The fix is well-contained and comes from a trusted contributor, suggesting it should be uncontroversial.
