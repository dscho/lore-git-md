This is a performance patch in Taylor Blau's ongoing series to improve Git's repacking strategy for large repositories. It implements the core incremental MIDX repacking functionality, which avoids expensive full repacks by maintaining a geometric progression of MIDX layers.

The patch introduces `write_midx_incremental()`, which constructs and maintains an optimized MIDX chain during geometric repacking. The strategy:
- Always writes a new MIDX layer containing freshly created packs
- Merges adjacent layers when their combined size exceeds half the next layer's size (controlled by `repack.midxSplitFactor`)
- Atomically updates the MIDX chain file after all steps complete
- Deletes unused MIDX layers

The implementation handles edge cases like:
- Rewritten vs unmodified MIDX tip layers
- Preferred pack selection
- Object count overflow checks
- Atomic updates via lockfiles

This is patch 14/16 in the series, building on previous infrastructure changes. The code is well-structured with extensive trace2 instrumentation and error handling. The commit message clearly explains the strategy and implementation choices. This represents a significant step toward the series' goal of reducing repacking overhead in large repositories.
