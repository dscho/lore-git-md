This is a refactoring patch (11/16) in Taylor Blau's series on incremental MIDX/bitmap-based repacking. The patch prepares the pack geometry subsystem for incremental MIDX repacking by adding logic to selectively include packs from the most recent MIDX layer when certain conditions are met.

The key changes are:
1. Adds new fields to `struct pack_geometry` to track MIDX layer thresholds and whether the tip layer was rewritten
2. Modifies `pack_geometry_init()` to optionally restrict repacking candidates to packs in the tip MIDX layer only when a threshold is configured
3. Updates `pack_geometry_split()` to track whether any MIDX'd packs were included in the repack (indicating the tip layer will need updating)

The patch maintains the series' pattern of careful, incremental changes that build toward the final functionality. It follows the necessary preparatory work done in previous patches (like the `midx_layer_contains_pack()` helper added in 8/16) and sets up infrastructure that will be used in subsequent patches to handle MIDX chain updates after repacking. The changes are well-contained and clearly explained in the commit message.
