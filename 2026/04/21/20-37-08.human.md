This is a feature patch series introducing incremental MIDX/bitmap-based repacking, the third and final major component of Taylor Blau's multi-part effort to improve Git's repacking strategy for large repositories. The series builds on previous work that refactored repack.c and implemented MIDX layer compaction.

The core innovation is a new repacking strategy that avoids periodic all-into-one repacks by maintaining an incrementally growing and shrinking MIDX chain. The approach:
1. Repacks non-MIDX'd packs geometrically
2. Prepares new MIDX layers with fresh packs
3. Compacts adjacent MIDX layers to maintain geometric progression
4. Writes a new optimized MIDX chain

This creates a structure where older layers contain fewer, larger packs while newer layers contain many smaller packs - significantly reducing repacking overhead in large monorepos that repack frequently. The series includes preparatory refactors, new MIDX write options needed for the strategy, and the core implementation.

Key changes in this version:
- Replaced string_list with strset for tracking retained MIDX files
- Improved keep_hashes array building logic
- Renamed --checksum-only to --no-write-chain-file
- Added --base option to specify MIDX layer base
- Added configuration parameters (midxSplitFactor, midxNewLayerThreshold)
- Added validation for configuration values
- Improved safety when deleting redundant packs during incremental repacking

The patches show careful attention to edge cases and include new test coverage. This represents a major architectural improvement to Git's scalability for large repositories, completing a multi-year effort. The series is rebased on current master and ready for final review.
