Karthik Nayak continues his series to consolidate ref backend logic, with this third patch focusing on error handling infrastructure. The thread began by identifying inconsistencies in how different backends handle object validation and peeling, proposing to move this logic into the shared refs layer for uniformity.

The latest patch makes a preparatory change to `ref_transaction_update()`, switching its error return from a simple `int` to a dedicated `enum ref_transaction_error`. While currently only implementing a generic error case (matching the old `-1` behavior), this sets up the type system to support more specific error reporting in future patches. The change is mechanical and behavior-preserving - all existing callers continue working as before since they were already treating any non-zero return as a failure.

This follows the series' incremental approach: each patch makes one focused infrastructure improvement while keeping the overall system functional. Previous patches removed unused typedefs and introduced standardized backend initialization via a new options struct. The work builds on Patrick Steinhardt and Karthik's broader effort to unify ref backend behavior, particularly following the reftable integration.
