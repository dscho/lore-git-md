This is the second patch in Phillip Wood's bugfix series addressing `git status` display issues during interactive rebase. Building on the first patch's refactoring of sequencer todo parsing, this change fixes two specific problems in how `git status` shows the rebase todo list:

1. It now correctly abbreviates commit object IDs for "fixup -C" and "merge -C" commands, which were previously displayed in full
2. It preserves refnames (like "reset main") rather than incorrectly replacing them with the object IDs they point to

The implementation uses the new `sequencer_parse_todo_command()` function from patch 1 to properly identify command types should have their arguments abbreviated. The changes affect both the core logic in wt-status.c and the test cases in t7512, which are expanded to cover more command variants.

The patch demonstrates careful handling of edge cases - for example, it only abbreviates object IDs when they start with the abbreviated form, avoiding false matches with branch names that happen to be all hex digits. The test updates maintain existing coverage while adding new cases for the fixed scenarios.

As with the first patch, this comes from Phillip Wood who is a recognized expert in Git's rebase/sequencer subsystems. The changes are well-motivated and technically sound, completing the series' goal of improving rebase status display accuracy.
