This is a brief follow-up in the ongoing discussion about adding a new mode to `git rev-list` for partial clone workflows. The thread has been exploring two alternative approaches for the interface design:

1. Extending the existing `--missing` enum with a new `MA_PRINT_ONLY` value (the original proposal)
2. Introducing a separate `--missing-only` flag (Phillip Wood's suggestion)

Patrick Steinhardt concurs with Phillip's assessment that a standalone `--missing-only` flag would be more self-documenting than extending the enum with `--missing=print-only`. This agreement from Patrick, who had previously raised concerns about potential enum bloat, suggests growing consensus around the flag-based approach.

The exchange is brief but significant as it represents alignment between two key reviewers (Patrick and Phillip) on the preferred direction for the feature's interface. This likely means the patch author will need to rework their implementation to use the `--missing-only` flag rather than extending the enum when submitting a v2.

The technical merits remain unchanged from previous discussion - the feature aims to support GitLab's Gitaly service by providing cleaner output of missing object IDs without prefixes. The current focus is purely on interface design rather than the underlying functionality.
