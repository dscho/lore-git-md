This is part 6 of Patrick Steinhardt's 12-patch series to enable `set -e` (errexit) in Git's test suite, building on the foundation established in earlier merged patches. The series is now in its fifth iteration with refinements based on feedback.

The patch focuses on adapting test patterns that execute potentially failing commands outside of conditionals, which would cause the test to abort when `set -e` is enabled. Changes include:

1. Converting direct command execution followed by `$?` checks into proper `if` statements or `||` chains
2. Updating test helper functions like `test_must_fail()` to handle exit codes safely
3. Modifying test scripts that check binary availability (svn, cvs) to use conditional execution
4. Adjusting output checking patterns to avoid failing the test prematurely

The changes are mechanical but important for maintaining test behavior under stricter error checking. The patch touches multiple test scripts and infrastructure files, with careful attention to preserving existing semantics while making them `set -e` compatible.

This continues the established pattern of the series - methodically updating test infrastructure to work with `set -e` without introducing functional changes.
