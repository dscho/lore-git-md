This is a bugfix patch for Git's merge-ort engine, addressing an interaction between cached renames and trivial resolutions. The patch comes from Elijah Newren, the primary expert on Git's merge machinery.

The issue occurs when a rename is cached from a previous merge operation, but the target path either doesn't exist in the current merge (due to trivial directory resolution) or has already been cleanly resolved with all sides agreeing on its content. The current code could hit an assertion in these cases. The patch moves the handling of these cases earlier in the process and adds more direct checks to avoid the problematic scenarios.

The change is accompanied by a new test case that demonstrates a scenario where:
1. A file is renamed in the upstream branch
2. The topic branch modifies the original file
3. Later copies it to the new name
4. Finally deletes the original file
The test verifies the merge can complete without hitting assertions about cached renames.
