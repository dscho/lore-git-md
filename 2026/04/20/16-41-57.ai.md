Bugfix addressing UTF-8 truncation vulnerabilities in diffstat display. Junio C Hamano has reviewed and approved Elijah Newren's v3 patch fixing NULL dereference and out-of-bounds read issues in the diffstat filename truncation logic.

The patch introduces a regression from Git 2.54's UTF-8 handling improvements (f85b49f3d4a) where malformed UTF-8 sequences or control characters could crash Git when core.quotePath=false. The solution centers around a new utf8_ish_width() wrapper that guarantees safe string advancement and non-negative width returns, with comprehensive test coverage including:
- Invalid UTF-8 (0xC0) triggering NULL dereference
- C1 control characters (0xC2 0x9F) causing out-of-bounds reads
- Verification under forced truncation via --stat-name-width

Junio's review confirms the approach is sound, noting the additional NUL termination check provides robust protection even for truncated multi-byte sequences. The patch appears ready for integration with its thorough test cases and clear handling of edge cases while maintaining correct display behavior for valid UTF-8. This concludes the multi-iteration review process that began with Lorenzo Pegorari's test coverage feedback in v2.
