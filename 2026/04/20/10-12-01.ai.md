This is the third patch in Karthik Nayak's refactoring series to consolidate ref backend logic. The patch changes the return type of `ref_transaction_update()` from `int` to `enum ref_transaction_error`, replacing the previous `-1` error returns with `REF_TRANSACTION_ERROR_GENERIC`.

The change is infrastructure work preparing for future validation improvements - the commit message notes this will allow callers to distinguish between different error types when more validations are added later. The patch maintains the same behavior while setting up the type system for more granular error reporting.

This is a mechanical change that:
1. Updates the function signature in both refs.c and refs.h
2. Converts error returns to use the new enum value
3. Leaves all callers unchanged since they were already treating -1 as a generic error

The patch follows the series' incremental approach, making one focused change that enables future work (in this case, more detailed error reporting) without yet implementing that functionality. It touches core refs infrastructure but should not affect behavior, as evidenced by the lack of caller updates needed.
