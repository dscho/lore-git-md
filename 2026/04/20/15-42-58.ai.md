The patch introduces a new utf8_ish_width() wrapper function that guarantees safe string advancement and non-negative width returns, building on the v2 approach with improved test coverage. Key changes in v3:
- The control character test case now uses repeated 0xC2 0x9F sequences (C1 control characters) instead of 0x01, which more reliably triggers the out-of-bounds read under ASan
- Commit message updated to clarify that ASan is needed to detect the out-of-bounds read
- Maintains the unified handling of invalid UTF-8 and control characters from v2

The implementation cleanly handles both edge cases while maintaining correct truncation behavior for valid UTF-8. The test cases now includes:
- Invalid UTF-8 (bare 0xC0 byte) to test NULL dereference
- Multiple C1 control characters (0xC2 0x9F) to test out-of-bounds reads
- Verification under core.quotePath=false with forced truncation via --stat-name-width
