This is a test modernization patch discussion in Siddharth Shrimali's series for t7004-tag.sh. Patrick Steinhardt weighs in on Junio Hamano's earlier review of the first patch, which removed brittle tag count checks from the test.

Patrick expresses reservations about relying solely on exit codes (via `test_must_fail`) without verifying the repository state remains unchanged after failed tag creation attempts. He explicitly endorses Junio's suggested alternative approach that would compare tag lists before and after the test operations, noting this would provide stronger validation that the failed commands didn't modify repository state.

The exchange highlights a tension in test design philosophy - between minimal assertions that verify just the immediate behavior being tested versus more comprehensive checks that validate broader invariants. While Junio had accepted the simpler approach as an improvement, Patrick's comment suggests some maintainers may prefer the more thorough verification method. This could influence future test modernization efforts, though the current series appears likely to proceed as-is given Junio's earlier approval.
