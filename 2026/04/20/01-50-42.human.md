This is a maintainer response in the ongoing `contrib/subtree` discussion, where Junio Hamano weighs in on Ian Jackson's Rust/libgit2 prototype for `git subtree split`. Junio makes his position clear: he prefers to see the subtree functionality moved out of the Git repository entirely rather than maintaining it as an in-tree component, especially if it depends on libgit2.

Junio's stance reflects his long-standing philosophy about the `contrib/` directory - he views it as a temporary home for tools that should eventually graduate to standalone projects. He explicitly states this isn't specific to subtree but applies broadly to components without strong dependencies on Git's core. His reasoning is both technical (libgit2 isn't a Git dependency) and historical (Git has outgrown the need to bundle auxiliary tools for visibility).

The email suggests a concrete path forward: replacing the current subtree implementation with a simple README pointing to the new external location. This would effectively deprecate the in-tree version in favor of Ian's Rust rewrite, but as a separate project rather than as part of git.git. The response is characteristically pragmatic and consistent with Junio's maintenance approach, though it leaves open how to handle the immediate recursion limit problem in the existing shell implementation while the Rust version matures.
