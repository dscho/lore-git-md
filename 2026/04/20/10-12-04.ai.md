This is patch 6/8 in Karthik Nayak's series refactoring Git's reference backend system, continuing the effort to consolidate object validation logic into the generic refs layer.

The patch moves object existence checking from individual backends (files and reftable) into the shared `ref_transaction_update()` function in refs.c. Key changes:

1. Object validation now happens immediately when an update is queued, rather than during transaction preparation. This means invalid objects will be caught earlier in the process.

2. The `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type is removed since validation failures now occur during update queuing rather than preparation.

3. `receive-pack` is updated to properly propagate the specific error type to clients, maintaining the same user-facing error messages despite the internal changes.

4. The files and reftable backends are simplified by removing their duplicate validation code, now that the generic layer handles it.

The change affects how invalid object errors are reported in batched updates - they can no longer be ignored since validation happens during update queuing. However, callers can still choose to continue adding other valid updates to the transaction after seeing an error.

This is a mechanical but important step in the larger ref backend consolidation effort, removing backend-specific validation logic in favor of a single implementation in the shared layer. The patch maintains backward compatibility while paving the way for future standardization of reference handling.
