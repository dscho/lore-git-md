This is the final patch in Patrick Steinhardt's series to make Git's test suite compatible with `set -e` (errexit). The patch enables strict error checking for test failures that occur outside of individual test cases, which previously could be silently ignored.

The key changes are:
1. Enables `set -e` by default for Bash 5+ in the test suite
2. Adds a `GIT_TEST_USE_SET_E` flag that can override this behavior
3. Configures Linux CI jobs to use the new error checking

The motivation comes from a real case where a typo in `test_expect_success` went undetected because the error occurred outside a test case. The implementation is careful about shell compatibility, only enabling this by default for Bash 5+ where the behavior is well-defined, while still allowing other shells to opt-in.

This represents the culmination of a 12-patch series that has already addressed various edge cases in test infrastructure to work with `set -e`. The changes have been thoroughly reviewed and tested across platforms, with input from Jeff King and others. The patch appears ready for merging as the final piece of this test reliability improvement effort.
