This is a review response from Junio C Hamano on Patrick Steinhardt's series to remove `the_repository` usage from the setup subsystem. The review focuses on patch 9/18 which converts `setup_work_tree()` to take an explicit repository parameter.

Junio notes two key concerns:
1. The removal of the `work_tree_config_is_bogus` global variable is correct since it can't be shared across repositories, though he humorously warns about potential breakage if core.bare/core.worktree are set in non-local configs.
2. More seriously, he questions the removal of the "initialized" check without replacement, worrying this could cause performance regressions if callers rely on `setup_work_tree()` being cheap for idempotent checks. He wonders if the current code avoids multiple calls precisely because it only works with `the_repository`.

The review confirms the patch is otherwise sensible while highlighting these architectural considerations. This continues the pattern of substantive but focused feedback on the series - Junio is engaging with the deeper implications of removing globals rather than just the mechanical changes. The thread shows steady progress on this major refactoring effort, now nearing completion.
