This is a bugfix patch targeting the files ref backend's consistency checking mechanism. Karthik Nayak addresses an issue where lock files (`.lock`) were being incorrectly processed during ref verification, despite some checks attempting to skip them.

The patch moves the lock file detection logic higher up in the call stack to `files_fsck_refs_dir()`, ensuring all validation checks skip lock files consistently. Previously, only the name validation check (`files_fsck_refs_name()`) skipped them, while other checks still processed these temporary files. The change is accompanied by a new test case that verifies lock files are properly ignored while malformed refs are still caught.

The modification is straightforward - it relocates the lock file check from the per-ref validation function to the directory iteration level, making the behavior more consistent. The accompanying test demonstrates both the desired skipping of lock files and continued validation of actual refs. This appears to be a clean, focused fix for a clear inconsistency in the refs files backend's validation behavior.
