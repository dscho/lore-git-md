This is a platform compatibility patch addressing filesystem ownership checks on network filesystems.

David Howells points out that Git's is_path_owned_by_current_uid() function currently makes strict UID comparisons that may not be meaningful on network filesystems like NFS, AFS, or CIFS where UIDs may be mapped differently or fabricated entirely. He suggests two potential solutions:

1. Checking the filesystem type via statfs() to identify network filesystems where UID comparisons should be relaxed
2. Adding a new statx() attribute flag in the kernel to explicitly mark filesystems where UID/GID values shouldn't be directly compared

The issue appears well-motivated for environments where Git repositories are stored on network filesystems, though the patch doesn't yet include implementation details or demonstrate the problem with concrete examples. The proposal would need coordination with both Git and kernel developers to determine the best approach.
