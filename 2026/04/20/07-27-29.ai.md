This is a test infrastructure patch from Patrick Steinhardt, part of the ongoing effort to make Git's test suite more robust by enabling `set -e` (errexit) behavior. This specific patch (10/12 in the v5 series) addresses a subtle issue in the bisection test script.

The patch replaces uses of the `expr` command with shell arithmetic (`$(( ))`) in `t/t6002-rev-list-bisect.sh`. The key problem being solved is that `expr` fails when its result is zero, which would cause the test to fail when `set -e` is enabled. The shell arithmetic approach doesn't have this limitation.

The changes are mechanical but important for the broader `set -e` compatibility work:
1. Converts three `expr` calls to arithmetic expressions
2. Wraps the negative check in an explicit `if` statement
3. Modernizes the test expectation syntax to use single quotes and split the command across lines

This follows the established pattern of the series - making minimal changes to ensure tests remain correct under `set -e` while preserving their original behavior. The patch builds on the foundation of previous work in the series and doesn't introduce new concepts or complications. All tests continue to pass with these changes.
