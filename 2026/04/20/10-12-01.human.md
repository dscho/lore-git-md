This is the third patch of an 8-part refactoring series that aims to consolidate object validation and peeling logic across Git's reference backends. The series is part of the broader effort to standardize behavior between the files, packed, and reftable backends.

The current patch makes a preparatory change to `ref_transaction_update()`, converting its return type from a simple `int` to the more descriptive `enum ref_transaction_error`. This sets up infrastructure for future patches that will add more validation to this function, allowing callers to distinguish between different types of errors. The change is mechanical - existing error cases still return the generic error code, preserving current behavior.

The patch follows the series' incremental approach, making one focused change that enables later work while keeping the code functional. It touches both the implementation in refs.c and the public interface in refs.h, but doesn't yet modify any callers. This is a typical pattern in Karthik's series - each patch introduces infrastructure needed for subsequent behavioral changes while remaining reviewable on its own.

The change is low-risk but meaningful - it will allow future patches to add more specific error reporting when validating ref updates, which could help debugging and error handling in commands like `update-ref` and `receive-pack`.
