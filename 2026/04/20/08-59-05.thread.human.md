brian m. carlson fixed a high-impact commit-signing regression that has affected all Git releases from v2.45.0 through v2.53.0. The bug caused signatures to be computed before commit messages were validated and transcoded to UTF-8, making signed commits with non-ASCII messages unverifiable when no explicit encoding was configured.

The fix reorders operations in `commit_tree_extended()` so that `ensure_utf8()` runs *before* signing. It also corrects a logical short-circuit bug in the original code that caused the compatibility buffer's UTF-8 check to be skipped when the main buffer was invalid. Elijah Newren's substantive review caught edge cases that were addressed in the v2 iteration, and D. Ben Knoble identified the exact commit (6206089cbd) that introduced the regression. A test using bytes 0xfe and 0xff provides regression protection.

Junio C Hamano has queued the two-patch series for `next`, effectively closing the thread. The fix is backend-agnostic (GnuPG, SSH, X.509) and eliminates the workaround of manually setting `i18n.commitEncoding`. No open questions remain.
