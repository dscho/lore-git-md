This is a bugfix patch addressing UTF-8 filename truncation vulnerabilities in diffstat display, now ready for integration after multiple rounds of review. The patch from Elijah Newren fixes NULL dereference and out-of-bounds read issues that could occur when displaying filenames containing malformed UTF-8 sequences or control characters with core.quotePath=false.

The solution introduces a utf8_ish_width() wrapper that guarantees safe string advancement and non-negative width returns, handling both invalid UTF-8 (advancing 1 byte, returning width 1) and control characters (returning width 0). The patch includes comprehensive test coverage with two key test cases: one with a bare 0xC0 byte to verify NULL dereference protection, and another with repeated C1 control characters (0xC2 0x9F) to validate bounds checking.

Junio C Hamano's review confirms the technical approach is sound, noting the additional safety provided by the new NUL-termination check in the loop condition. The patch appears well-vetted through multiple iterations, with all reviewer feedback addressed and ASan-validated test cases demonstrating the memory safety fixes. This represents a robust solution to a potentially serious security issue in filename display handling.
