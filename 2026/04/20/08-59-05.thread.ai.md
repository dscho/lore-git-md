Commit signing regression for non-UTF-8 messages since v2.45.0, caused by commit 6206089cbd changing operation order in `commit_tree_extended`. Signatures were generated before UTF-8 validation/transcoding, causing mismatch between signed content (raw bytes) and stored content (UTF-8 transcoded). Affects all signature types across Git 2.45.0 through at least 2.53.0. High impact on signed commits with non-ASCII messages.

brian m. carlson addressed the issue with a two-patch series. First patch renamed `verify_utf8()` to `ensure_utf8()` to accurately reflect its behavior (validation plus possible transcoding), touching only the function name and call sites in `commit.c`. Second patch (now landed) fixes the core issue by moving `ensure_utf8()` before signing operations in `commit_tree_extended()`, ensuring signed content matches stored content. Added test case using invalid UTF-8 bytes (0xfe and 0xff) provides regression protection.

Kushal Das confirmed the fix works for real-world use with non-UTF-8 messages while suggesting expanded test coverage for non-GnuPG signing tools. brian m. carlson responded that the fix's abstraction means it should work identically across all signing backends (SSH/X.509), making separate tests unnecessary. This indicates the technical solution is considered complete.

The solution restores pre-2.45.0 behavior where signatures remain valid for non-UTF-8 messages. While the technical fix is implemented, open questions remain about whether unconfigured non-UTF-8 messages should be supported at all. Current workaround (setting `i18n.commitEncoding`) is no longer needed once this fix lands in a release.

Key technical details: Issue manifested when commit messages contained non-UTF-8 bytes without explicit encoding configuration. Signature was affected at the abstract signing interface level, making the fix backend-agnostic (GnuPG/SSH/X.509). Affected files: `commit.c` (signing and UTF-8 handling), `gpg-interface.c` (signature verification). Test coverage includes invalid UTF-8 byte sequences but broader signing backend tests were deemed unnecessary.
