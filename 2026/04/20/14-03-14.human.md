This is a bugfix patch targeting the files ref backend's consistency checking. Karthik Nayak addresses an issue where `git refs verify` was unnecessarily checking lock files (`.lock`) during its scan of the refs directory. 

The patch moves the lock file check from `files_fsck_refs_name()` up to `files_fsck_refs_dir()`, skipping all validation for lock files rather than just the name check. This makes the behavior more consistent and avoids wasted effort. The change comes with a new test case that verifies lock files are ignored while malformed refs are still caught.

The change is straightforward and well-motivated - lock files are temporary artifacts that shouldn't be validated as refs. The patch maintains all existing functionality while making the code more efficient. The test coverage is thorough, checking both that lock files are skipped and that real ref validation still works. This looks like a clean, focused improvement to the refs verification code.
