This is the first of two patches addressing a regression in commit signing for non-UTF-8 messages. The patch renames `verify_utf8()` to `ensure_utf8()` to better reflect its actual behavior - the function doesn't just validate UTF-8 but also transcodes non-UTF-8 text to UTF-8 when needed. 

The change is part of fixing a deeper issue where commit signatures were being generated before UTF-8 validation/transcoding in Git 2.45.0+, causing mismatches between signed content and stored content. The rename clarifies the function's purpose ahead of the actual fix in the second patch. 

The patch is straightforward and mechanical, updating both the function name and its documentation comment. It maintains the same behavior while making the code's intent clearer. This is a typical preparatory refactoring before addressing the core issue, making the subsequent fix easier to understand.
