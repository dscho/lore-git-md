This is part 5 of Patrick Steinhardt's 12-patch series to enable `set -e` (errexit) in Git's test suite, building on the foundation established in previous iterations. The series has already addressed shell compatibility and CI integration in earlier patches.

This patch focuses on fixing conditional test execution patterns that would break under `set -e`. It converts problematic `test ... && test_expect_success` constructs into proper `if` statements in two test scripts:

1. `t/t4032-diff-inter-hunk-context.sh`: Changes file existence checks before running diff output verification tests
2. `t/t7450-bad-git-dotfiles.sh`: Modifies symlink-related tests to properly handle conditional execution based on the `$refuse_index` variable

The changes are mechanical but important - they maintain the same test behavior while making it compatible with the stricter error checking that `set -e` will introduce. This continues the series' pattern of methodically updating test infrastructure to work with the new error handling regime.

The patch follows the established approach from earlier in the series and doesn't introduce new concepts. All tests pass in CI, indicating these changes successfully adapt the test suite without introducing regressions. This represents another incremental step toward the test suite's eventual full `set -e` compatibility.
