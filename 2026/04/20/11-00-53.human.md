This is a discussion about improving `git rev-list`'s partial clone support, specifically for GitLab's Gitaly service which needs to filter output to only missing object IDs. The thread has evolved from an initial `--missing=print-only` enum proposal to considering simpler flag-based approaches.

Kristoffer Haugsbakk weighs in on the interface design, arguing that the current proposal conflates two concerns: handling missing objects (the original purpose of `--missing`) and filtering present objects. They find both `--missing=print-only` and `--missing-only` unintuitive since they mix these concerns, and suggest a more orthogonal approach like `--present=no-print` that would explicitly control present-object output separately from missing-object handling.

The discussion reflects Git's careful attention to CLI design principles, with multiple contributors (including Phillip Wood and Patrick Steinhardt) offering perspectives on how to best serve the use case while maintaining clear, composable options. The GitLab Gitaly workflow remains the driving motivation, needing to efficiently identify missing objects without post-processing currently required.
