This is Junio Hamano's "What's cooking in git.git" status report for April 2026, marking the start of a new development cycle after Git 2.54's release. The report provides a comprehensive overview of in-progress topics across Git's integration branches (maint, master, next, seen), noting which patches are stable enough for next inclusion and which need more work.

Several significant technical efforts are highlighted:

1. The ODB (object database) abstraction work by Patrick Steinhardt continues with an in-memory object source implementation (ps/odb-in-memory), building on Justin Tobler's transaction interface changes (jt/odb-transaction-write). This is part of the larger effort to make Git's storage layer more pluggable.

2. Multiple `the_repository` removal efforts are progressing, with Shreyansh Paliwal's refs backend changes already merged to 'next' and Patrick Steinhardt's setup.c conversions still under review. These continue the project-wide effort to eliminate global state.

3. The fsmonitor daemon implementation for Linux by Paul Tarjan (pt/fsmonitor-linux) appears ready for merging after extensive development, bringing Linux to parity with existing Windows/macOS support.

4. Performance improvements include Derrick Stolee's incremental MIDX repacking (tb/incremental-midx-part-3.3) and Elijah Newren's blob prefetching for grep/cherry (en/batch-prefetch).

5. Adrian Ratiu's parallel hooks implementation (ar/parallel-hooks) has merged to 'next', enabling concurrent hook execution where safe.

The report also notes several documentation efforts, test suite improvements, and smaller fixes across various subsystems. Junio mentions he will be offline for a few weeks but expects the community to self-organize during this period, with no designated interim maintainer named this time.

Key points for future AI summarization context:
- The ODB abstraction work introduces new concepts like `odb_source_inmemory` and builds on transaction interfaces
- Multiple parallel efforts continue removing `the_repository` global from different subsystems

- Hook execution can now parallelize where marked safe
- Several test suite improvements make tests more robust with `set -e`
