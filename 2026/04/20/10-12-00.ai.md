This is the second patch in Karthik Nayak's refactoring series to consolidate ref backend logic. It moves reflog configuration handling from individual backends to the generic refs layer.

The patch introduces a new `ref_store_init_options` struct to pass initialization parameters to ref backends, including both the existing access flags and the new `log_all_ref_updates` setting. This replaces the previous approach where each backend would call `repo_settings_get_log_all_ref_updates()` independently.

Key changes:
- Adds `ref_store_init_options` struct in refs-internal.h to hold backend-agnostic initialization parameters
- Modifies the backend initialization signature to accept this struct instead of raw flags
- Updates all three backends (files, packed, reftable) to use the new initialization pattern
- Centralizes reflog configuration lookup in the generic refs.c layer

The change is mechanical but touches all ref backends, ensuring consistent handling of reflog configuration across implementations. This continues the series' theme of moving shared logic out of backend-specific code. The patch builds on the first patch's removal of unused typedefs, progressing from cleanup to substantive refactoring.
