This is a test infrastructure patch from Patrick Steinhardt, part of his ongoing v5 series to enable `set -e` (errexit) in Git's test suite. The patch fixes signal handling tests that would fail when `set -e` is active by changing how exit codes are captured from commands expected to die with signals.

The change modifies three test cases that verify Git dies with SIGPIPE (signal 13) under certain conditions. The original tests used `command; echo $?` which would cause the subshell to exit immediately when `set -e` is enabled, since the command fails. The new version uses `command && echo 0 || echo $?` which properly captures the exit code regardless of whether `set -e` is active.

The patch touches two test scripts:
- `t/t0005-signals.sh` (two test cases)
- `t/t3600-rm.sh` (one test case)

This is a mechanical change that maintains the exact same test semantics while making the tests compatible with the stricter error checking that `set -e` provides. The changes are straightforward and focused, with no apparent edge cases or controversy - they simply adapt existing tests to work with the new error handling regime being introduced in the larger series.
