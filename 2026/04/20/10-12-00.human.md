This is the second patch in Karthik Nayak's refactoring series, focusing on reflog configuration handling. The patch moves the logic for determining when to create reflog entries from individual backends to the generic refs layer, standardizing behavior across all reference storage implementations.

The key changes introduce a new `ref_store_init_options` struct that centralizes backend initialization parameters, including both the existing access flags` and the new `log_all_ref_updates` setting. This eliminates duplicate calls to `repo_settings_get_log_all_ref_updates()` in each backend and ensures consistent reflog behavior.

The patch touches all three ref backends (files, packed, reftable) with mechanical changes to adopt the new initialization pattern. The changes are straightforward and maintain the existing functionality while improving code organization. This continues the series' theme of consolidating common ref handling logic in the generic layer rather than having each backend implement it separately.

As with the rest of the series, this appears to be a well-motivated cleanup that emerged from practical ref backend work rather than being purely theoretical. The patch maintains backward compatibility while paving the way for more consistent behavior across storage implementations.
