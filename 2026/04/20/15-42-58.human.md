Bugfix addressing UTF-8 truncation vulnerabilities in diffstat display. This v3 patch from Elijah Newren finalizes the solution to NULL dereference and out-of-bounds read issues in the diffstat filename truncation logic that were introduced in Git 2.54.

The patch introduces a robust utf8_ish_width() wrapper that safely handles both invalid UTF-8 sequences and control characters during filename truncation. Key improvements in this version include:

1. A properly constructed test case for control characters (using \302\237 sequences) that reliably triggers the out-of-bounds read under AddressSanitizer, addressing the coverage gap identified in v2.
2. Clarification in the commit message about how core.quotePath=false interacts with the bug (most but not all control characters are escaped).
3. Minor documentation fixes in the commit message.

The solution maintains the unified approach from v2 that treats both invalid UTF-8 and control characters consistently while being simpler than the initial proposal. The comprehensive test coverage now includes both malformed UTF-8 (0xC0 byte) and control character cases, with ASan validation for the latter.

This appears ready for integration with all review feedback addressed and no outstanding questions. The patch demonstrates careful attention to edge cases and memory safety, particularly for the relatively rare but important scenario where core.quotePath=false allows raw bytes to reach the diffstat display logic.
