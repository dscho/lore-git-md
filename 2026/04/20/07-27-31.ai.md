Test infrastructure patch completing the `set -e` (errexit) adoption in Git's test suite. This final patch in Patrick Steinhardt's 12-part series enables strict error checking for commands outside test cases, catching previously silent failures like the recent `test_expect_success` typo that went undetected.

The change activates `set -e` by default for Bash 5+ (the most reliable implementation) while making it opt-in via `GIT_TEST_USE_SET_E` for other shells. The CI configuration now enables this for Linux jobs (AlmaLinux, Debian, Fedora). The implementation includes careful boolean parsing to avoid surprises from environment variables.

This builds on the merged foundation from earlier patches that adapted test helpers and individual test scripts. The series has undergone extensive review, with Jeff King (Peff) providing input and all tests passing across supported shells. The change represents a significant reliability improvement for Git's test infrastructure, ensuring failures outside test cases - whether from typos or genuine bugs - will now surface immediately rather than being silently ignored.
