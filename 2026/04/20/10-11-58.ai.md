This is a refactoring series targeting Git's reference backend system, part of the ongoing effort to consolidate common logic from the individual backends (files, packed, reftable) into the generic layer. The series comes from Karthik Nayak, a frequent contributor working on ref-related subsystems.

The main goal is to move object parsing and peeling logic out of the individual backends and into the shared refs layer. Currently, different backends handle these operations in slightly different ways, which could lead to inconsistencies. The key changes involve:

1. Moving commit object validation from transaction preparation to `ref_transaction_update()`, making it happen earlier in the process
2. Standardizing how peeled tag values are handled across backends by adding a `peeled` field to the `ref_update` struct
3. Extracting reflog configuration handling to the generic layer

The series touches several components including `update-ref`, `receive-pack`, and all three ref backends. The changes are mechanical but wide-ranging, affecting how ref updates are validated and processed throughout the system. Karthik notes this work emerged naturally while working on other ref-related code, suggesting these are genuine pain points rather than theoretical cleanups.
