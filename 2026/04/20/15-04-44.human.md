This is the second patch in Phillip Wood's bugfix series addressing issues in `git status`'s display of the rebase todo list during interactive rebase. Building on the first patch's refactoring of sequencer todo parsing, this change fixes two specific problems:

1. The status display now properly abbreviates commit object IDs for "fixup -C" and "merge -C" commands, matching the behavior for other rebase commands. Previously these special cases were missed.

2. It stops incorrectly replacing refnames (like "reset main") with their object IDs in the status output. The patch ensures branch names and labels containing only hex digits remain unchanged.

The implementation uses the new `sequencer_parse_todo_command()` function from the first patch to properly identify command types before processing. The test suite (t7512) is expanded to cover these edge cases with new scenarios testing merge, reset, and update-ref commands in the rebase todo list.

Phillip Wood's expertise in the sequencer/rebase code shows in the careful handling of command parsing and the comprehensive test coverage. The changes are focused and well-motivated, addressing clear correctness issues without introducing new complexity. This appears ready for merging as part of the series.
