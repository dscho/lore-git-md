This is a security-related proposal about filesystem ownership checks in Git. David Howells suggests modifying Git's `is_path_owned_by_current_uid()` function to handle network filesystems (9p, AFS, Ceph, CIFS, NFS) differently, since their UID/GID handling differs from local filesystems.

The core issue is that Git currently assumes UID/GID comparisons are meaningful for all filesystems, but on network filesystems these IDs may come from separate namespaces or be fabricated entirely. David proposes two solutions:
1. Checking the filesystem type via `statfs()` to identify network filesystems
2. Adding a new `statx()` attribute flag in the kernel to explicitly mark filesystems where UID/GID comparisons are unreliable

This touches Git's security model for repository access control and would require coordination with kernel developers for the second approach. The change would affect operations that check repository ownership, particularly in shared environments using network-mounted repositories. The proposal doesn't include a patch yet, but raises an architectural question that would need input from both Git and kernel maintainers.
