This is patch 5/8 in Karthik Nayak's series to consolidate ref backend validation logic, part of the ongoing ref backend refactoring effort. The patch modifies `builtin/update-ref.c` to handle reference update rejections that occur during transaction preparation phase, not just during commit. 

Key changes:
- Introduces a `command_options` struct to track whether individual update failures should be allowed (controlled by `--batch-updates` flag)
- Modifies all command handlers to accept this options struct and properly handle non-generic rejection errors from `ref_transaction_update()`
- Uses the previously moved `print_rejected_refs()` function to show rejection details when updates fail during preparation
- Maintains existing behavior where generic errors still cause immediate termination
- The changes are preparatory for later patches that will move validation logic into `ref_transaction_update()`

The patch follows the series' pattern of small, focused changes that enable future work while keeping the code functional. It touches a wide surface area of `update-ref` command parsing but the changes are mechanical - mostly adding the options parameter and error handling branches. 

This continues the incremental approach to moving validation logic upward from the backends while maintaining compatibility. The next patches will introduce the actual validation changes that will trigger these new error paths.
