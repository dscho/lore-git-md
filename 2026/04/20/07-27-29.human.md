This is part 10 of Patrick Steinhardt's ongoing series to make Git's test suite compatible with `set -e` (errexit) mode, which helps catch errors earlier. The series has already gone through several rounds of review and testing.

The patch fixes a specific issue in the bisection test script where `expr` was being used for arithmetic that could return zero - which `expr` treats as a failure when `set -e` is enabled. The solution replaces `expr` with the more reliable `$(( ))` arithmetic syntax and modernizes the test function's style slightly.

This is a mechanical but careful change that:
1. Preserves the same arithmetic logic while avoiding `expr`'s zero-exit behavior
2. Improves readability by using `if` rather than chained `&&` operations
3. Maintains the exact same test expectations

The change is part of the broader effort to make Git's test suite more robust by enabling strict error checking. Since this builds on already-reviewed infrastructure work and follows established patterns from earlier patches in the series, it's likely to be uncontroversial.
