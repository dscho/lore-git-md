This is a test infrastructure patch from Patrick Steinhardt, part of his ongoing series to enable `set -e` (errexit) in Git's test suite. The patch specifically addresses signal handling tests that would fail under `set -e` due to their current implementation.

The change modifies three test cases that verify Git dies with SIGPIPE (signal 13) when its output pipe is closed. The current tests use a pattern of `command; echo $?` which would cause the subshell to exit immediately under `set -e` when the command fails. The patch replaces this with `command && echo 0 || echo $?` to properly capture the exit code while remaining `set -e` safe.

This is a mechanical but necessary change as part of the larger effort to make the test suite more robust by enabling strict error checking. The patch follows the established pattern from previous iterations of the series and maintains the exact same test behavior while being compatible with `set -e`.

The changes are limited to test scripts (t/t0005-signals.sh and t/t3600-rm.sh) and don't affect production code. This patch represents one of the final preparatory steps before the `set -e` functionality can be fully enabled in CI.
