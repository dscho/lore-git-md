This thread wraps up a two-patch bugfix series from Phillip Wood that corrects `git status` display issues during interactive rebase. The series addresses two specific problems: commit object IDs in "fixup -C" and "merge -C" commands weren't being abbreviated, and refnames (like "reset main") were incorrectly replaced with their target object IDs.

The fixes are now ready for merging after Phillip incorporated all review feedback from Junio C Hamano, Elijah Newren, and Tian Yuchen. The most recent discussion focused on a theoretical risk where a label might collide with an object ID - Junio initially raised this as a concern, but Phillip addressed it by modifying the code to check for labels (via `refs/rewritten/`) before attempting OID abbreviation. This change eliminates the collision risk entirely while maintaining the human-readable status output that was the original goal.

The implementation touches the sequencer and status display code, with a preparatory refactor that enables shared parsing logic between the two components. The series includes expanded test coverage for various rebase commands and maintains backward compatibility. All technical concerns have been resolved, and the patches are now awaiting Junio's merge.
