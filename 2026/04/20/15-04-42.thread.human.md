This thread is about a small but important bugfix series from Phillip Wood that was recently merged to Git's master branch. The series fixes two usability issues in `git status` during interactive rebase: commit object IDs in commands like "fixup -C" and "merge -C" were showing up unabbreviated, and refnames (like "reset main") were incorrectly being replaced with their target object IDs.

The solution involved a careful refactoring of the rebase todo list parsing code to properly distinguish between labels and object IDs, with special handling to prevent collisions between the two. Junio C Hamano and others reviewed the series across four iterations, validating both the technical approach and edge cases like label/OID collisions. The final version (v4) included some last-minute style fixes and expanded test coverage before being merged.

This was a well-contained fix that improves the interactive rebase experience without changing any fundamental behaviors. The parsing infrastructure it establishes might be useful for future sequencer improvements, but for now it simply resolves some long-standing display quirks that could confuse users.
