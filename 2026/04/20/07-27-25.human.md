This is part 6 of Patrick Steinhardt's ongoing test infrastructure series to enable `set -e` (errexit) in Git's test suite. The patch focuses on updating test patterns that execute potentially failing commands outside of conditionals, which would cause the test to abort when `set -e` is enabled.

The changes are mechanical but important - they wrap command executions that could fail (like checking for binary availability or running git commands) in proper conditionals or error handling. Key updates include:

1. Converting direct command execution followed by `$?` checks into `if ! cmd` patterns
2. Adding explicit error handling for git commands that might fail during tests
3. Updating test helper functions like `test_might_fail` to properly capture exit codes

The patch touches multiple test scripts and infrastructure files, including CVS-related tests, submodule tests, and core test helpers. All changes maintain the existing test behavior while making them compatible with strict error checking.

This continues the established pattern from previous iterations of the series - methodically updating test patterns to work with `set -e` without introducing new functionality or test cases. The changes are straightforward adaptations that have already passed CI testing across shell implementations.
