This is a refactoring series targeting Git's reference backend system, part of the ongoing effort to consolidate common logic from the individual ref backends (files, packed, reftable) into a shared generic layer. Karthik Nayak, a frequent contributor to ref-related code, proposes moving object validation and tag-peeling logic out of the backend implementations.

The key changes involve:
1. Moving object parsing (to verify commit OIDs) from transaction preparation into `ref_transaction_update()`
2. Centralizing peeled tag handling in the generic layer rather than having each backend implement it separately
3. Cleaning up related infrastructure like reflog configuration and error handling

The series touches core ref operations in `update-ref` and `receive-pack`, requiring adjustments to their update handling. The changes appear well-motivated to reduce backend divergence and simplify future maintenance, though they do involve non-trivial plumbing changes across multiple subsystems.

This looks like a technically sound contribution from an experienced refs contributor, though reviewers will likely want to scrutinize the transaction flow changes carefully given their potential impact on reference updates. The patch organization follows Git's convention of starting with preparatory cleanups before the substantive changes.
