This is the first patch in a two-part series addressing a commit signing regression for non-UTF-8 messages. The patch renames `verify_utf8()` to `ensure_utf8()` to more accurately reflect its behavior - the function doesn't just validate UTF-8 but also transcodes non-UTF-8 input to UTF-8 when needed.

The change is straightforward but important for code clarity, as the original name misleadingly suggested pure validation. This renaming sets up for the second patch which will address the core issue where commit signing happens before UTF-8 processing, causing signature mismatches. The patch touches only the function name and its call sites in `commit.c`, maintaining all existing behavior.

This is part of brian m. carlson's response to a reported regression where commit signatures became invalid for non-UTF-8 messages starting in Git 2.45.0. The series appears to be taking a two-pronged approach: first clarifying the API (this patch), then fixing the signing order issue (upcoming patch). The change is uncontroversial and unlikely to generate discussion on its own, but provides necessary groundwork for the more substantive follow-up.
