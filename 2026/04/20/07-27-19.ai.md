This is a test infrastructure patch series from Patrick Steinhardt that builds on previous discussions about making Git's test suite more robust by enabling `set -e` (errexit) to catch errors outside of test cases. The series has gone through five iterations with refinements based on feedback and testing.

The key changes in v5 include:
- Adding a `GIT_TEST_USE_SET_E=yes` opt-in flag and enabling it in Linux CI jobs
- Additional fixes for potentially failing commands
- Continued work to ensure compatibility across shells (Bash and Dash)

The series prepares various test helper functions and existing tests to work correctly with `set -e` enabled, addressing edge cases in signal handling, test cleanup, and command execution patterns. Changes span across multiple test scripts and infrastructure files, with careful attention to maintaining existing behavior while adding stricter error checking.

The discussion thread has already resolved key technical questions around shell compatibility, settling on a version-based allowlist approach for Bash 5+ rather than capability testing. This version appears ready for final review, with all tests passing in CI and on the author's local machine across multiple shell implementations.

This represents a significant step forward in Git's ongoing effort to improve test reliability, building on previous modernization work. The changes are focused on the test framework itself rather than any particular Git feature, with the goal of catching more test failures early in the development process.
