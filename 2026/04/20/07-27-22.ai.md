This is part 3 of Patrick Steinhardt's v5 series to enable `set -e` (errexit) in Git's test suite, building on the already-merged foundation patches. The series aims to make test failures more visible by causing scripts to exit immediately on unhandled errors.

The current patch focuses on adapting the `stop_git_daemon()` helper function in `t/lib-git-daemon.sh` to work correctly under `set -e`. The function kills a background git-daemon process and checks its exit status, but contains two patterns that would fail with `set -e` enabled:

1. The `wait` command is expected to fail (since we just killed the process) but would cause immediate exit under `set -e`. The patch changes this to use the `||` pattern to capture the exit code.

2. A second `kill` call attempts to terminate the daemon via its pidfile, which often fails harmlessly (since the process is already dead). The patch silences this expected failure with `|| :`.

These changes maintain the existing behavior while making the function robust under stricter error checking. The patch is a mechanical adaptation following the established pattern from earlier parts of the series, with all tests passing in CI. This continues the careful, incremental approach to test infrastructure modernization that has characterized the entire effort.
