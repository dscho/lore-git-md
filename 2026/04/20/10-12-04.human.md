This is patch 6/8 in Karthik Nayak's series to consolidate object validation logic across Git's reference backends. The patch moves object existence checking from the individual backends (files and reftable) into the generic refs layer.

Key changes:
- Object validation now happens in `ref_transaction_update()` rather than during transaction preparation, meaning invalid objects are caught immediately when updates are queued
- Removes redundant validation code from both the files and reftable backends
- Updates `receive-pack` to properly handle the new error reporting flow
- Eliminates the `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type since validation is now handled earlier

The change affects how invalid objects are reported - they can no longer be ignored in batched updates since validation happens immediately. However, callers can still choose to continue adding other updates to the transaction after seeing an error.

This is a well-structured patch that follows the series' incremental approach. The changes are mechanical but important for consistency across backends. The patch maintains existing behavior while cleaning up redundant code - a solid step toward the series' goal of unifying backend logic.
