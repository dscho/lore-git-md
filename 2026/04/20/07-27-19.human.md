This is the fifth iteration of Patrick Steinhardt's test infrastructure series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The series aims to make tests more robust by detecting errors that would otherwise be silently ignored. 

The key change in v5 is the ability to opt-in via `GIT_TEST_USE_SET_E=yes`, which is now enabled for Linux CI jobs. This follows extensive discussion about shell compatibility, particularly around mksh edge cases that have been documented and will be reported upstream by brian m. carlson. The version-based allowlist approach (only enabling for Bash 5+) has been adopted as the most maintainable solution.

The 12 patches systematically prepare test infrastructure to work with `set -e`:
- Adjust test helper functions like `test_match_signal()` and `test_must_fail()`
- Fix potential failure points in test cleanup (`stop_git_daemon`, config unset)
- Address specific test cases that would break with strict error checking
- Add CI integration to verify the changes

The series appears well-tested, with Patrick confirming it passes with both Bash and Dash, and CI results looking good. While some edge case fallout is expected given the scope, the changes are mechanical and focused on test reliability rather than core Git functionality. This continues Git's ongoing effort to modernize and harden its test infrastructure.

The discussion has reached consensus on the technical approach, and this version incorporates all feedback from previous rounds. Reviewers should focus on verifying the error handling changes don't introduce false positives in existing tests.
