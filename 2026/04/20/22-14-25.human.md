This is the second patch in brian m. carlson's series fixing a commit signing regression for non-UTF-8 messages. The patch addresses the core issue where signatures were being generated before UTF-8 validation/transcoding, causing verification failures when commit messages contained non-UTF-8 bytes.

The fix moves the UTF-8 processing (`ensure_utf8()`) before the signing operation in `commit_tree_extended()`, ensuring the signed content matches what gets stored. This resolves the regression introduced in Git 2.45.0 where the thread summary identified signature mismatches for non-ASCII messages. The patch includes a test case using invalid UTF-8 bytes (0xfe and 0xff) to verify the fix.

The change is straightforward but important - it maintains the same UTF-8 validation behavior while ensuring signatures remain valid. The patch follows naturally from the preparatory rename in part 1/2 and appears to be the complete solution to the reported issue. Given brian m. carlson's expertise in this area (they implemented Git's hash-algorithm-agnostic internals) and the clear regression test, this fix seems likely to be accepted without controversy.
