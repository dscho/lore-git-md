This is a design discussion about the `git rev-list --missing` interface for partial clone workflows, specifically focused on how to best implement a mode that outputs only missing object IDs without present objects.

Kristoffer Haugsbakk weighs in on Phillip Wood's suggestion to use a `--missing-only` flag rather than extending the `--missing` enum with `print-only`. While agreeing that `--missing-only` is better than `--missing=print-only`, Kristoffer argues that both approaches still mix concerns of handling missing objects with controlling output of present objects. 

The key points raised:
- The current `--missing` option describes what to do about missing objects, so adding behavior that also affects present objects (`print-only`) feels conceptually inconsistent
- For GitLab's Gitaly use case (the motivating example), the requirements are actually two separate concerns: (1) include missing objects and (2) exclude present objects
- Suggests an alternative approach with orthogonal options like `--present=no-print` to better separate these concerns

This continues the thread's substantive discussion about API design clarity, with Kristoffer offering a fresh perspective on separating the concerns of object presence handling versus output filtering. The suggestion aligns with Git's general preference for orthogonal, single-purpose options over multi-faceted enums.

The thread shows consensus forming around avoiding the enum extension approach, but now considering whether `--missing-only` fully captures the intended semantics or if a more explicit separation of concerns would be better. This will likely influence Siddharth Asthana's v2 implementation as they incorporate the feedback.
