This is a bugfix series targeting the rebase status display in `git status`. Phillip Wood addresses two specific issues in how `git status` parses and displays the rebase todo list during an interactive rebase:

1. Currently fails to abbreviate commit object IDs when lines start with "fixup -C" or "merge -C"
2. Incorrectly replaces refnames (like "reset main") with the object IDs they point to

The series takes a two-patch approach: first factoring out the sequencer's todo command parsing logic into a reusable function, then using that shared parsing in `wt-status.c` to properly handle these edge cases. The changes touch core rebase machinery (sequencer.c) and status display code, with accompanying test updates in t7512.

The motivation is clear - these are straightforward correctness issues in status display during rebase. Phillip Wood is a known expert in the sequencer and rebase subsystems, so this fix comes from a domain authority. The patch structure shows good separation of concerns, and the test updates demonstrate the fixed behavior. This appears ready for review with no obvious red flags.
