This is the final patch (8/8) in Karthik Nayak's refactoring series to consolidate object validation and peeling logic across Git's backend implementations. The series is part of the ongoing effort to standardize reference backend behavior.

The patch completes the work started in previous patches by modifying the packed and reftable backends to use the pre-peeled tag values that are now provided through the generic refs layer, rather than performing their own peeling operations. This eliminates duplicate peeling work and ensures consistent behavior across backends.

Key changes in this patch:
- Updates the packed and reftable backends to check the new `REF_HAVE_PEELED` flag
- Uses the `peeled` field from the `ref_update` struct that was added in patch 7/8
- Removes now-redundant calls to `peel_object()` in both backends
- Simplifies the code by removing object.h inclusion where no longer needed

The changes are mechanical and focused, following the incremental approach seen throughout the series. With this patch, the backends now rely entirely on the generic layer for tag peeling, completing the standardization effort. The series appears well-structured and addresses a clear technical debt in the backend implementations.
