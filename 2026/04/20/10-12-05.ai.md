This is patch 7/8 in Karthik Nayak's series to consolidate ref backend validation logic, continuing the broader ref backend refactoring effort. The patch introduces a `peeled` field to the `ref_update` struct to standardize how tag object peeling is handled across reference backends.

Key changes:
- Adds `peeled` field to `ref_update` to store peeled OIDs, avoiding repeated ODB lookups
- Modifies `ref_transaction_add_update()` to accept and store peeled OIDs
- Updates `ref_transaction_update()` to automatically peel tag objects and pass the result
- Adjusts all callers (including files and reftable backends) to handle the new parameter
- Introduces `REF_HAVE_PEELED` flag to indicate when a peeled OID is available

The change moves peeling logic from individual backends to the shared refs layer, eliminating duplicate code and ensuring consistent behavior. The implementation maintains backward compatibility while preparing for future backend simplifications where they can rely on the generic layer rather than implementing their own peeling.

This is a mechanical but important step in the series, touching core ref transaction handling. The changes are wide-ranging but follow a clear pattern established in earlier patches. The next (final) patch will presumably update the backends to use this new peeling infrastructure.
