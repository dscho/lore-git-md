This is patch 7/8 in Karthik Nayak's series refactoring Git's reference backend system to consolidate object validation and peeling logic. The series is part of the ongoing effort to standardize behavior across different ref backends (files, packed, reftable).

The current patch introduces infrastructure for handling peeled object IDs in the generic refs layer. It adds a `peeled` field to the `ref_update` struct and modifies related functions to pass this information through the transaction system. The key changes are:

1. Adding a `REF_HAVE_PEELED` flag and `peeled` OID field to track tag object peeling
2. Updating `ref_transaction_add_update()` to accept and store peeled OIDs
3. Modifying `ref_transaction_update()` to automatically peel tag objects when needed
4. Adjusting all callers to pass NULL for the peeled parameter where appropriate (reflogs, deletions)

The patch follows the series' incremental approach - it lays groundwork for the next patch which will modify backends to use this centralized peeling rather than doing it themselves. The changes are mechanical but touch several files including the core refs.c and all three backend implementations.

This continues the series' pattern of moving backend-specific logic into the shared layer while maintaining existing behavior. The changes appear well-contained and focused scope, with clear documentation of the new fields and flags. The patch maintains backward compatibility while enabling future backend simplification.
