This is the final patch (4/4) in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has undergone extensive review over 7 iterations and is now in its polished state with maintainer approval.

The patch implements unified conflict resolution in `git checkout -m` by:
1. Automatically stashing local changes before attempting the branch switch
2. Reapplying the stash after the switch, with clear messaging when conflicts occur
3. Adding comprehensive test coverage (19 test cases in t7201-co.sh)
4. Preserving backward compatibility while improving the merge workflow

Key technical changes include:
- New silent autostash creation via `create_autostash_ref_silent()`
- Enhanced stash application with custom labels through `apply_autostash_ref_with_labels()`
- Modified conflict resolution flow in `builtin/checkout.c`
- Updated documentation in `git-checkout.adoc` and `git-switch.adoc` to reflect the new behavior

The implementation handles edge cases like:
- Non-conflicting changes (skips stashing when possible)
- Mixed staged/unstaged changes
- Non-overlapping changes in the same file
- Various conflict styles (diff3, zdiff3)

The patch series has been validated through real-world testing and maintainer review. Junio Hamano has approved the approach, praising the dry-run optimization and unified behavior. All test cases pass outside sub-shell environments, and the new test in v7 specifically verifies clean stash application with non-overlapping changes.

This represents a significant quality-of-life improvement for branch switching workflows, particularly in environments where developers frequently context switch between branches with uncommitted changes. The implementation is production-ready with all edge cases addressed.
