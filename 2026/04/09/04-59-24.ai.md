This is a bugfix patch in the fsmonitor daemon series, addressing a memory leak in the client handling code. The patch fixes a case where a khash table (`shown`) would not be freed when the daemon sends a trivial response to the client, skipping the cleanup path.

The fix initializes the hash table pointer to NULL and moves its cleanup to the shared `cleanup` label using `kh_destroy_str()` which safely handles NULL pointers. This ensures the hash table is properly freed regardless of whether the response is trivial or non-trivial.

The change is small (5 lines modified) but important for correct memory management in the fsmonitor daemon. It's part of the larger fsmonitor implementation that has been through 14 iterations of review and testing. The patch demonstrates attention to detail in resource cleanup paths, a common source of leaks in long-running daemon processes.
