This is a follow-up discussion in the `git stash` argument parsing thread, focusing on documentation clarity. Mirko Faina points out that the current documentation phrasing ("push-specific options") could be misleading, since the implementation actually accepts any option that `stash push` understands - even if those same options are technically valid for other subcommands too (like `-m` for `create`).

The concern is that users reading "push-specific" might incorrectly assume the feature only works with options *unique* to `push`, when in fact it works with all `push`-compatible options regardless of whether other subcommands also accept them. This is a documentation precision issue rather than a technical one, since the implementation already behaves as intended (assuming "push" when no subcommand is given and the options are valid for push).

This email doesn't propose specific wording changes but flags an area where the documentation could be clearer about the actual behavior. The thread has otherwise reached consensus on the technical approach, with v4 of the patch series incorporating all prior feedback about edge cases and limitations.
