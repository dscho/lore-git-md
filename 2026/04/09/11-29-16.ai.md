This is a platform compatibility patch addressing the `writev()` optimization issues in Git 2.54.0-rc1 on NonStop systems. Patrick Steinhardt presents an updated implementation of his proposed `xwritev()` solution, incorporating Phillip Wood's clarification that the platform limitation applies to the total size of iovec arrays rather than individual entries.

The patch introduces a new `xwritev()` function that handles large vectorized writes by:
1. Calculating the total size of iovec entries while respecting platform-specific `MAX_IO_SIZE` limits
2. Falling back to `xwrite()` when the first entry exceeds the limit
3. Splitting the iovec array when the total would exceed the limit
4. Maintaining the existing error handling for interrupted/blocked writes

The implementation has been tested with an artificially small `MAX_IO_SIZE` (100 bytes) to verify the fallback behavior. This solution aims to preserve the performance benefits of `writev()` on capable platforms while gracefully handling constraints on systems like NonStop where the total iovec size must stay below platform-specific limits (52KB for 32-bit, 868KB for 64-bit).

The patch appears technically sound, building on the thread's earlier analysis from Jeff King, Junio Hamano, and brian m. carlson. It addresses the core issue where Git's 64k packet-line protocol assumptions conflict with platforms having smaller SSIZE_MAX values. Patrick indicates he will soon send a polished version to the mailing list, suggesting this may become the preferred solution over the current `NO_WRITEV=Nope` workaround.
