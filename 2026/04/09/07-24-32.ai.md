This is a refactoring patch in Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically part 11 of a 17-patch series introducing an in-memory ODB source. The patch converts the in-memory storage backend from using a simple growable array to using an oidtree data structure.

The key changes are:
1. Replaces the array-based storage (`struct cached_object_entry`) with an oidtree that stores `struct inmemory_object` entries
2. Implements proper cleanup of the oidtree in the free function
3. Maintains the same external interface while improving internal efficiency

The motivation is threefold: better lookup performance (O(1) vs O(n)), easier iteration in sorted order, and support for unique prefix lookups - all of which come "for free" by using the same data structure as the loose object backend. The implementation appears clean and maintains the existing functionality while setting up for future needs.

This is a straightforward technical improvement that fits naturally into the larger ODB abstraction series. The change is well-contained and doesn't introduce new concepts - it just swaps one well-understood data structure for another that better matches the use case. Given Patrick's track record with this kind of architectural work and the clear benefits, this seems like a solid step forward in the series.
