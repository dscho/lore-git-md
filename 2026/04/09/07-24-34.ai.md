This is patch 13/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ODB abstraction effort. The patch adds the `find_abbrev_len()` callback to the in-memory ODB backend, completing another piece of the ODB source interface.

The implementation determines the shortest unambiguous prefix length for a given object ID by:
1. Using the existing `for_each_object()` infrastructure to iterate objects matching the prefix
2. Calculating the common hex prefix length between each candidate and the target OID
3. Tracking the minimal length that uniquely identifies the object

The callback follows the same pattern as other implementations in the codebase, using a helper struct to pass state between the iteration callback and the main function. The implementation is straightforward since the in-memory backend already stores objects in an oidtree, making prefix searches efficient.

This continues the series' pattern of methodically implementing each required ODB source callback. The change is well-contained and builds on infrastructure established in earlier patches. With this addition, the in-memory backend now handles all major object lookup operations, bringing it closer to feature parity with persistent backends.
