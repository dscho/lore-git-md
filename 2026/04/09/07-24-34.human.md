Feature patch implementing the `find_abbrev_len()` callback for the in-memory ODB backend as part of Patrick Steinhardt's ODB abstraction effort. This is the 13th patch in a 17-part series.

The patch adds support for finding the minimal unique abbreviation length for object IDs in the in-memory object database. It builds on the iteration infrastructure from patch 12, using the oidtree-based storage to efficiently check for hash collisions when determining the shortest unambiguous prefix length.

The implementation follows the same pattern as other callbacks in the series, with a helper struct (`find_abbrev_len_data`) to track state during iteration and a callback function that compares each object's OID against the target. The code handles the case where multiple objects share the same prefix by incrementing the required length until uniqueness is achieved.

This completes another piece of the in-memory ODB backend's required functionality, bringing it closer to feature parity with persistent backends. The change is straightforward and follows the established patterns from earlier patches in the series. As with the rest of the work, this appears to be a solid technical foundation for the broader ODB abstraction effort.
