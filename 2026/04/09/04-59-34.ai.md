This is a test patch in the ongoing fsmonitor daemon series, adding Linux-specific test coverage for the inotify-based filesystem monitoring implementation. The patch focuses on verifying event delivery reliability while hardening the test scenarios.

The key additions are:
1. A smoke test that verifies the filesystem actually delivers inotify events, skipping the entire test suite if event delivery fails (common in container/overlayfs environments)
2. A stress test for rapid nested directory creation to catch EEXIST race conditions during recursive watch registration
3. Reduced daemon start timeout from 60 to 10 seconds for faster test feedback
4. Improved test helper robustness in environments without procps (Fedora CI)
5. Process group handling fixes for submodule pull tests

The patch demonstrates thorough testing of edge cases that emerged during development, particularly around inotify event delivery reliability and race conditions during recursive directory watch setup. The test hardening changes make the suite more portable across different CI environments while maintaining the ability to detect filesystem monitoring failures early.

This appears to be the final test coverage patch in the series that has undergone extensive review over 14 iterations, with all major technical concerns addressed. The tests complement the detailed Linux inotify implementation from earlier patches while ensuring the daemon behaves correctly under stress conditions.
