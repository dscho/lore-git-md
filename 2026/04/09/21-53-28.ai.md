This is a platform compatibility fix reverting the `writev()` implementation due to NonStop system limitations. Junio C Hamano responds to Jeff King's analysis by completely removing the `writev()` emulation layer that was causing test failures on NonStop platforms.

The patch reverts four commits (89152af176 through 3b9b2c2a29) that introduced `writev()` support, removing all related code from the Makefile, CMake/meson build systems, and wrapper functions. The immediate motivation is NonStop's inability to handle the 64k buffer sizes Git assumes, where the emulation layer's strict `EINVAL` checks made the situation worse rather than better.

The revert affects multiple subsystems: the sideband code falls back to simpler `write()` calls, and all platform-specific `writev()` handling is removed from Windows and MINGW configurations. Junio frames this as a temporary measure ("retract the topic until we have a better emulation"), acknowledging the performance tradeoff of losing `writev()`'s scatter/gather I/O benefits.

This is a significant but surgical change, touching 11 files while maintaining backward compatibility. The patch demonstrates Git's pragmatic approach to platform support - when a compatibility issue proves too complex to fix immediately, reverting problematic functionality takes precedence over keeping broken optimizations. The change is well-contained and clearly documented, with Junio's commit message directly addressing the technical constraints Jeff King identified.
