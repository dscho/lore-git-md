This is patch 12/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch adds the `for_each_object()` callback implementation to the in-memory ODB backend.

The implementation:
- Introduces a new `populate_object_info()` helper to centralize object info population logic shared between read and iteration operations
- Adds a `odb_source_inmemory_for_each_object_data` struct to pass iteration state through the oidtree traversal
- Implements the callback to properly handle both bare object ID iteration and full object info requests
- Respects iteration flags like `PROMISOR_ONLY` and `LOCAL_ONLY`
- Leverages the oidtree structure (converted in patch 11) for efficient prefix-based iteration

The changes are cleanly separated from the existing read/write operations and maintain consistency with the broader ODB source interface. This completes another key piece of the in-memory backend's functionality, bringing it closer to feature parity with persistent backends.

The implementation appears solid and follows the established patterns seen in other parts of the series. As with previous patches, this continues the careful architectural work needed for the ODB abstraction while providing direct utility for the in-memory use case. The patch is well-contained and builds logically on the oidtree conversion from the previous patch.
