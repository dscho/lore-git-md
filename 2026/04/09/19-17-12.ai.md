This is the first patch in a feature series (v8) that adds customizable conflict marker labels to `git stash apply`. The patch introduces three new options: `--ours-label`, `--theirs-label`, and `--base-label` to override the default conflict marker text when applying stashes.

The implementation modifies several components:
- Adds documentation for the new options in `Documentation/git-stash.adoc`
- Updates the usage string in `builtin/stash.c`
- Adds two new test cases in `t/t3903-stash.sh` verifying both custom labels and empty label handling
- Fixes `xdiff/xmerge.c` to properly handle empty label strings

The changes allow users to specify alternative labels for the "ours" (current branch) and "theirs" (stashed changes) sides of conflicts, with an additional option for the base label when using diff3-style conflict markers. The xdiff changes ensure empty strings are handled correctly when labels are explicitly set to empty.

This is part of a larger effort to unify conflict resolution behavior across Git commands, with this patch specifically enabling the same label customization for stash apply that exists in other merge operations. The implementation has been thoroughly reviewed through multiple iterations (now at v8) and includes comprehensive test coverage for both the new functionality and edge cases.
