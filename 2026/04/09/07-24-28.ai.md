This is patch 7/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ODB abstraction effort. The patch implements the `write_object()` callback for the in-memory backend, which is responsible for storing objects in the transient in-memory storage.

The implementation:
- Adds a call to `hash_object_file()` to properly compute the object ID from the provided content, type, and repository's hash algorithm
- Continues using the existing array-based storage (later patches will convert this to an oidtree)
- Maintains type safety through the `odb_source_inmemory_downcast` helper
- Follows the pattern of growing the objects array as needed

This is a straightforward implementation that builds on the infrastructure established in earlier patches. The change is technically sound and aligns with the series' goal of providing a complete callback suite for the in-memory ODB source. The patch is small and focused, exactly what we'd expect at this stage of the series.
