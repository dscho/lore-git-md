This is a test patch in the fsmonitor Linux implementation series, specifically addressing test suite compatibility between split-index and scalar clone operations. The patch disables GIT_TEST_SPLIT_INDEX in scalar clone tests (t9210 and t9211) to avoid a known incompatibility where index.skipHash (enabled by default in scalar) causes shared indexes to get null OIDs and fail to load properly, triggering fsmonitor assertion failures.

The change follows the same pattern already established in t9210 test 16, now extending it to tests 12, 13, and 22 in t9210 and all of t9211. The technical explanation in the commit message is clear - when skipHash skips computing the hash, the shared index gets a null OID which prevents proper loading on re-read, causing fsmonitor's dirty bitmap to reference non-existent index entries.

This appears to be a straightforward test adjustment that maintains consistency with the project's established approach to handling this particular test environment constraint. The patch is narrowly focused and well-explained, with no functional changes to the core fsmonitor implementation itself. It represents a minor but necessary test suite adjustment in the larger fsmonitor series that has already undergone extensive review.
