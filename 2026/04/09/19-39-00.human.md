This is the naming discussion phase of Patrick Steinhardt's 17-part feature series introducing an in-memory object database backend as part of the ODB abstraction effort. The series is now complete with all technical feedback addressed, and Junio C Hamano is raising a final naming consistency issue before integration.

Junio notes that while the patch uses "inmemory" in identifiers and error messages, Git's existing terminology uses "in-core" (as seen in the `--no-kept-objects=in-core` option). He suggests aligning with this established pattern for consistency across the codebase. This is the last remaining question before the series can be merged.

The technical implementation has been thoroughly reviewed by Karthik Nayak and Justin Tobler, with all earlier feedback incorporated in v2. The in-memory ODB backend provides transient storage for objects, implementing all required callbacks (some as no-ops where functionality isn't needed). This work enables git-blame worktree commits and represents a significant milestone in the ongoing ODB abstraction effort led by Patrick Steinhardt.

The discussion now hinges on whether to use "in-memory" (as in the current patch) or "in-core" (following existing Git conventions) for the final naming. This decision may influence terminology for future storage backends.
