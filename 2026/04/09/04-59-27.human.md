This is a feature patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch replaces an infinite wait for cookie file events with a one-second timeout, preventing indefinite blocking when filesystem events fail to arrive (a known issue on some container/overlay filesystems).

The change modifies `with_lock__wait_for_cookie()` to use `pthread_cond_timedwait()` instead of `pthread_cond_wait()`, implementing proper timeout handling. If the timeout fires without receiving the expected event, the daemon will report an error and allow the client to proceed with a full scan rather than hanging forever. The implementation includes careful time conversion from `gettimeofday()` to the timespec format required by pthreads.

This is part of the larger cross-platform fsmonitor effort that has gone through 14 iterations of review. The patch demonstrates attention to edge cases and platform-specific behavior, particularly for containerized environments where filesystem event delivery can be unreliable. The change maintains the existing behavior in normal cases while adding robustness against hangs.
