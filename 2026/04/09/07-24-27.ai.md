This is patch 6/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `write_object()` callback for the in-memory backend, completing the write path.

The implementation moves the existing `odb_pretend_object()` logic from `odb.c` into the new callback, converting it to use the standard ODB source interface. Key changes include:
- The write operation now uses `xmemdupz()` instead of separate allocation and copy steps
- The callback signature includes compatibility OID and flags parameters (currently unused)
- The storage remains an array of `cached_object_entry` structs (though later patches will convert this to an oidtree)

The patch continues the series' pattern of methodically implementing each required callback while maintaining type safety through the `odb_source_inmemory_downcast()` helper. The changes are straightforward and well-contained, with the bulk of the diff being the movement of existing functionality into the new callback structure.

This is a solid incremental step in the series, implementing a core piece of functionality while cleaning up some technical debt by moving object writing into the proper abstraction layer. The implementation appears correct and maintains consistency with the broader ODB source interface design.
