This is a refactoring patch in Patrick Steinhardt's ongoing ODB abstraction series, specifically modifying the cbtree data structure to support embedded wrapper nodes. The change allows callers to embed `struct cb_node` within their own data structures while maintaining proper key access.

The patch removes the flex array from `struct cb_node` and replaces it with an explicit key offset stored in the containing `struct cb_tree`. This enables wrapper structures (like the new `struct oidtree_node`) to contain both the tree node and their own data while ensuring proper key alignment. The tradeoff is 4 bytes of padding per node (growing from 60 to 64 bytes on 64-bit systems) in exchange for eliminating memory copies needed for alignment.

Key technical changes:
- Adds `key_offset` field to `struct cb_tree`
- Introduces `cb_node_key()` helper to locate keys using the offset
- Updates all cbtree operations to use the new key access pattern
- Modifies oidtree to use a wrapper `struct oidtree_node` containing both the base node and object ID
- Removes manual memory copying of object IDs in oidtree

The change appears well-motivated as part of the broader ODB abstraction effort, where flexible node embedding will be useful. The implementation is thorough, touching cbtree.c, cbtree.h, and oidtree.c to maintain consistency. While this is a foundational change rather than user-visible, it demonstrates Patrick's characteristic attention to clean abstractions in the ODB work.
