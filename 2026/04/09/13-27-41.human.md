This is version 7 of a feature patch series that enhances `git checkout -m` to automatically stash local changes when switching branches with conflicts. The series has been through multiple rounds of review and refinement, with Junio Hamano and Phillip Wood providing input.

The main changes in v7 are:
1. Added a new test case verifying clean stash application when changes don't overlap in the same file
2. Kept all previous improvements from v6 including proper lock file cleanup and optimized dry-run checks
3. Maintained the new stash labeling options (`--ours-label`, `--theirs-label`, `--base-label`)

The implementation remains focused on making `git checkout -m` behave more intuitively by:
- Silently stashing local changes when conflicts would prevent branch switching
- Applying the stash back after successful merge
- Providing better conflict marker context through customizable labels

The series appears production-ready with:
- Comprehensive test coverage (18 cases in t7201-co.sh plus new tests)
- Clean integration with existing autostash behavior from rebase/merge
- Maintainer approval from Junio Hamano
- All edge cases addressed through previous iterations

This represents the final polish before merging, with only minor documentation tweaks remaining from earlier reviews. The changes are well-contained and maintain backward compatibility while improving the branch switching experience.
