This is the final patch (4/4) in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch implements the core functionality after extensive review and testing across multiple iterations (now at v8).

The key changes in this patch:
1. Modifies `git checkout -m` to automatically stash local changes before switching branches and reapply them afterward, similar to existing autostash behavior in `git rebase`/`git merge`
2. Adds comprehensive test coverage (19 new test cases in t7201-co.sh) verifying:
   - Conflict resolution with different styles (diff3, zdiff3)
   - Proper handling of non-conflicting changes
   - Stash behavior with staged vs unstaged changes
   - Recovery paths when conflicts occur
3. Updates documentation to reflect the new behavior and user messaging
4. Integrates with the sequencer's autostash infrastructure while adding new capabilities like silent stash creation

The implementation touches several core components:
- `builtin/checkout.c` - main logic for merge/checkout with autostash
- `builtin/stash.c` - extended to support custom conflict marker labels
- `sequencer.c` - enhanced autostash handling
- `xdiff-interface` - conflict style utilities
- Multiple test files with expanded coverage

This represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes. The series has received maintainer approval through multiple iterations and addresses all feedback. The additional test cases in v8 specifically verify edge case behavior around empty labels and proper stash list handling, further strengthening the implementation.
