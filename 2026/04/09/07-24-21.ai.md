This is a feature patchset introducing an in-memory object database source as part of the ongoing ODB (object database) abstraction effort led by Patrick Steinhardt. The v2 series expands on the initial version with 17 patches that implement a complete in-memory ODB backend for transient objects.

The in-memory ODB source serves as a non-persistent storage layer that discards all objects when the process exits. While this may seem unusual, the cover letter explains several use cases including git-blame's temporary worktree commits and potential future applications like re-merging diffs. The implementation also helps clean up technical debt by eliminating the `struct object_info::whence` field in favor of richer backend-specific metadata.

Key technical changes in v2 include:
- Fixed handling of object IDs when writing objects
- Rebased onto Justin Tobler's ODB write stream refactoring work
- Renamed from "inmemory" to "in-memory" for consistency
- Added proper streaming interface implementation
- Converted storage from an array to an oidtree for better performance
- Implemented all required ODB source callbacks (read/write operations, iteration, etc.)

The series touches core object storage code across multiple files including `odb/source-inmemory.[ch]`, `cbtree.[ch]`, and `oidtree.[ch]`. It appears carefully structured with each commit focused on implementing a specific piece of functionality. Given Patrick's track record with architectural changes and the clear motivation provided, this seems like a solid technical foundation for future work in the ODB abstraction effort.

The changes are well-motivated and the implementation appears thorough, though some reviewers may question the immediate practical need for certain features like the streaming interface in an in-memory context. The series is ready for consideration but may need to wait for Justin Tobler's related ODB changes to land first.
