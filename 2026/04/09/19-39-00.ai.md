This is a maintainer comment on naming consistency in Patrick Steinhardt's feature series implementing an in-memory object database source (part of the ODB abstraction effort). Junio C Hamano notes that while the technical implementation appears complete and correct, the terminology used in error messages and user-facing text should align with Git's existing conventions.

The specific issue is the use of "inmemory" versus "in-core" - Junio points out that Git already has a `--no-kept-objects=in-core` option, suggesting the latter term may be more consistent with established patterns. This is not a technical blocker but rather a request to ensure naming aligns with the project's existing vocabulary.

The comment comes after the series has already addressed all substantive technical feedback and received positive reviews from Karthik Nayak and Justin Tobler. The naming question appears to be the final issue before the series can be considered ready for integration. This type of terminology discussion is typical in the final stages of review for large architectural changes, where consistency with the broader codebase becomes important.
