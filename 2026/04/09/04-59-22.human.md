This is a feature patch series implementing Linux filesystem monitoring (fsmonitor) support via inotify, now at version 14. The series brings Linux to parity with existing Windows and macOS implementations while also fixing memory leaks and deduplicating shared IPC/settings logic.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The series has undergone extensive testing across 14 iterations.

Changes in v14 focus on test coverage, specifically ensuring consistent handling of the split-index incompatibility across all relevant test files (t9210 and t9211). The series now disables GIT_TEST_SPLIT_INDEX in all scalar clone tests, matching the maintainer-approved approach from earlier iterations. This follows Junio Hamano's feedback to apply the same workaround consistently.

The implementation appears production-ready, having been tested for months in various environments. It demonstrates thorough engineering with attention to edge cases (stale renames, watch limits, remote filesystems) and platform compatibility (Windows pthread emulation). The careful handling of technical constraints and thorough test coverage suggest this is a high-quality contribution likely to be well-received.

This represents the final major piece in completing cross-platform fsmonitor support, with Linux being the last platform to gain native implementation. The series builds on prior work from Eric DeCosta and Marziyeh Esipreh while addressing all substantive review feedback across its many iterations.
