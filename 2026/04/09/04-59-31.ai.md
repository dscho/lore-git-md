This is a feature patch in the fsmonitor series, adding process isolation improvements to `run-command`. The patch introduces a `close_fd_above_stderr` flag in `struct child_process` that, when enabled, makes child processes close all file descriptors above stderr (FD 2) before exec, while preserving the child-notifier pipe. The implementation caps the scan at the minimum of `sysconf(_SC_OPEN_MAX)` and 4096 for efficiency.

The change prevents child processes from inheriting unintended file descriptors from the parent environment, which is particularly useful for test harnesses and the fsmonitor daemon implementation. The patch maintains careful exception handling for the child-notifier pipe and includes system-aware bounds checking. This builds on the series' broader process isolation work, complementing earlier additions like session detachment and proper FD cleanup.

Technical details include the use of `sysconf(_SC_OPEN_MAX)` with a fallback to 4096, explicit skipping of the child-notifier pipe, and the addition to `struct child_process`'s documentation. The change is narrowly scoped but provides important isolation guarantees for the fsmonitor daemon and other child processes.
