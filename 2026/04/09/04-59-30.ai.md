This is a feature patch implementing Linux filesystem monitoring (fsmonitor) support via inotify, part of a larger series bringing fsmonitor to parity across platforms. The patch adds the core Linux listener implementation that watches directories for changes using inotify, with careful handling of edge cases like directory moves, remote filesystems, and system limits.

The implementation uses inotify rather than fanotify due to privilege requirements, with recursive watch registration for directories and rename tracking via inotify cookies. It includes remote filesystem detection via statfs() and /proc/mounts, falling back to socket relocation when .git is on a network mount. The code handles system limits gracefully, warning when they may need adjustment (max_user_watches).

Key technical components include:
- Non-blocking inotify_init1(O_NONBLOCK) with 50ms poll timeout
- Bidirectional watch descriptor <-> path hash maps
- Cookie-based rename tracking with stale detection
- Recursive watch registration for new directories
- Remote filesystem detection via statfs() and /proc/mounts
- Edge case handling in fsm-listen-linux.c, fsm-health-linux.c, fsm-path-utils-linux.c

The patch appears production-ready, with thorough attention to resource management and platform compatibility. It builds on prior work from Eric DeCosta and Marziyeh Esipreh, completing the Linux fsmonitor implementation after 14 iterations of review. The code is well-structured with clear separation between platform-specific and shared components via the FSMONITOR_OS_SETTINGS build variable.

Documentation updates note Linux-specific caveats around inotify watch limits and clarify that socketDir now applies to Linux as well as macOS. The implementation matches the existing Windows and macOS fsmonitor daemons in functionality while accounting for Linux-specific constraints.
