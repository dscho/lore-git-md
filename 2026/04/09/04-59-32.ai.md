This is a feature patch in the fsmonitor series, focusing on process isolation improvements for the filesystem monitoring daemon. It addresses two key issues in the daemon's startup behavior:

First, it ensures the daemon closes inherited file descriptors above stderr (FD 2) when spawned, both for explicit "fsmonitor--daemon start" commands and implicit spawns when no running daemon is found. This prevents hangs in parent processes (like test harnesses or CI systems) that might be waiting on pipe endpoints the daemon unintentionally inherited.

Second, it properly detaches the daemon process on Unix systems by calling `setsid()` when started with `--detach`, creating a new session and process group. This prevents shells with job control from waiting indefinitely on the daemon when it was implicitly spawned by a foreground command.

The changes are minimal but important for robustness:
- Adding `close_fd_above_stderr = 1` to both spawn paths
- Implementing proper session detachment via `setsid()` on Unix
- Suppressing stdout/stderr in implicit spawns to avoid terminal pollution
- Maintaining Windows compatibility with `FreeConsole()`

This patch builds on the extensive fsmonitor work already done in the series, now ensuring clean process isolation while preserving all existing functionality. The changes are well-contained and appear to address real-world issues observed in test environments.
