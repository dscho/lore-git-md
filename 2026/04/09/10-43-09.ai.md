This is the first patch in a two-part series introducing branch name prefixing functionality to `git branch`. The patch adds a `--name-prefix` option that can prepend either a static string or the current branch name (via `@{current}` token) to new branch names.

The implementation includes:
- A new `get_current_branch_name()` helper that properly resolves HEAD to get the current branch name
- An `add_branch_prefix()` function that handles both static strings and the `@{current}` token
- Error handling and warning/advise messages for failed cases
- Documentation updates explaining the new option
- Test coverage in t3200-branch.sh verifying the prefixing behavior

Key technical details:
- The prefix is applied before the branch name validation checks
- Supports `--name-prefix` from both CLI and config (handled in patch 2/2)
- Includes `--no-name-prefix` override capability
- Current branch resolution happens internally rather than requiring caller input (fixing a v3 issue)

The patch appears well-structured with thorough test coverage, though the fundamental motivation for this feature remains under discussion from previous rounds. The implementation quality has improved significantly since v3, addressing earlier technical concerns about current branch resolution and error handling.
