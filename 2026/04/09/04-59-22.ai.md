This is a feature patch series implementing Linux filesystem monitoring (fsmonitor) support via inotify, now at v14. The series brings Linux to parity with existing Windows and macOS implementations while addressing memory leaks and improving test coverage.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The series has undergone extensive testing across 14 iterations.

Changes in v14 focus on test suite improvements:
- Extends the GIT_TEST_SPLIT_INDEX workaround to t9211 scalar clone tests (matching the pattern already in t9210)
- Maintains the fundamental design decision that split-index and index.skipHash are incompatible
- Follows maintainer guidance to handle the test environment consistently across all affected tests

The series demonstrates thorough engineering with attention to edge cases (stale renames, watch limits, remote filesystems) and platform compatibility (Windows pthread emulation). It builds on prior work from Eric DeCosta and Marziyeh Esipreh, now addressing all substantive review feedback. The implementation appears production-ready, having been tested for months in various environments.

Notable technical components include:
- Process isolation enhancements with new close_fd_above_stderr option
- System-aware FD scanning capped at min(sysconf(_SC_OPEN_MAX), 4096)
- Preserved child-notifier pipe during FD cleanup
- Suppressed stdout/stderr in implicit spawns
- Proper session detachment via setsid() on Unix
- New daemon shutdown timeout (30000ms) with 50ms polling intervals
- Complete Windows compatibility via pthread emulation
- pthread_cond_timedwait() implementation using SleepConditionVariableCS()
- Careful time conversion (gettimeofday() to milliseconds)
- Proper ETIMEDOUT handling
- Windows-to-POSIX error code translation
- One-second timeout for container/overlayfs hang prevention

The Linux inotify implementation includes:
- inotify_init1(O_NONBLOCK) with 50ms poll timeout
- Bidirectional hash maps for watch descriptors <-> paths
- Cookie-based rename tracking with stale detection
- Recursive watch registration for new directories
- Remote filesystem detection via statfs() and /proc/mounts
- Edge case handling (watch limits, unmounts, queue overflows) in new files fsm-listen-linux.c, fsm-health-linux.c, fsm-path-utils-linux.c

The series represents a significant completion of cross-platform fsmonitor support, with Linux being the last major platform to gain native implementation. The careful handling of technical constraints and thorough test coverage suggest this is a high-quality contribution ready for inclusion.
