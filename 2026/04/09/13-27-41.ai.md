This is version 7 of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through multiple iterations with maintainer review and is now in its final polishing stage.

The main changes in v7 are:
1. Added a new test case for non-overlapping changes in the same file
2. Fixed a minor documentation formatting issue in the first patch
3. Kept all other functionality from v6 intact

The series implements:
- New stash apply labeling options (`--ours-label`, `--theirs-label`, `--base-label`)
- Silent autostash creation during checkout operations
- Unified conflict resolution behavior in `git checkout -m` through autostash
- Comprehensive test coverage (now 19 test cases in t7201-co.sh)

Key technical components touched:
- `builtin/checkout.c` - main merge/checkout logic
- `builtin/stash.c` - new labeling options
- `sequencer.c` - autostash handling
- Extensive test updates across multiple test files

The implementation appears production-ready with all edge cases addressed. Junio Hamano has expressed approval of the approach in previous iterations. The new test case in v7 specifically verifies clean stash application when changes don't overlap in the same file, further strengthening the implementation.

This series represents a significant quality-of-life improvement for branch switching workflows, particularly in environments where developers frequently need to context switch between branches with uncommitted changes. The maintainer feedback suggests this is likely to be merged soon.
