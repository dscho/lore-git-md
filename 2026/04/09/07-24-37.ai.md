This is patch 16/17 in Patrick Steinhardt's feature series introducing an in-memory object database source as part of the ODB abstraction effort. The patch stubs out remaining ODB source callbacks that aren't needed for the in-memory backend.

The changes implement no-op or error-returning versions of several functions:
- `begin_transaction()` returns an error since transactions aren't supported
- `read_alternates()` is a no-op (returns success)
- `write_alternate()` errors out as alternates aren't supported
- `close()` and `reprepare()` are empty stubs
- The functions are wired up in the source initialization

This completes the callback implementation for the in-memory ODB source by covering the remaining operations that either don't make sense for transient storage (transactions, alternates) or require no special handling (close/reprepare). The patch is straightforward and follows the pattern established in earlier parts of the series.

With this change, the in-memory source now implements all required ODB source callbacks, though several are intentionally minimal since the backend's transient nature makes full implementations unnecessary. The series appears to make steady progress toward its goal of providing a complete in-memory object storage solution.
