Jeff King (Peff) identified a critical platform compatibility issue where Git's `writev()` emulation layer was causing test failures on NonStop systems due to overly strict buffer size limits. Randall S. Becker originally reported the problem when clone operations failed with "Invalid function argument" errors on NonStop's constrained `ssize_t` implementation.

Junio C Hamano has now taken decisive step to address this by completely reverting the `writev()` support that was introduced in four prior commits. This surgical change removes the problematic emulation layer from Git's codebase, build systems, and platform-specific configurations. While this means temporarily losing the I/O efficiency benefits of scatter/gather operations, Junio frames it as a necessary stopgap until a more robust solution can be developed. The revert cleanly falls back to using simpler `write()` calls, particularly in the sideband code where the issues were most apparent.

This demonstrates Git's pragmatic approach to platform support - when a compatibility issue proves too complex to resolve immediately, reverting problematic functionality takes precedence over keeping broken optimizations. The change is well-contained, touching 11 files while maintaining backward compatibility, and Junio's commit message directly addresses the technical constraints Peff's analysis identified. No further discussion has occurred since the revert was proposed, suggesting consensus around this temporary solution.
