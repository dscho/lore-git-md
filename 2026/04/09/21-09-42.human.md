This is a platform compatibility patch addressing edge cases in the `writev()` implementation for NonStop systems. The discussion between Junio C Hamano and Jeff King confirms the final correctness of Patrick Steinhardt's proposed `xwritev()` wrapper, which handles platform-specific I/O size limits.

The key verification here is that the overflow protection properly handles all cases where iovec entries might exceed `MAX_IO_SIZE`, including when the first entry is too large (falling back to `xwrite()`) or when subsequent entries would cause overflow (properly checking before proceeding). Both reviewers are now satisfied with the implementation's safety properties after working through these edge cases.

The patch represents a robust solution to the NonStop compatibility issue, following the pattern of Git's existing `xwrite()` wrapper. It will be included after the Git 2.54 release, with NonStop users advised to use the `NO_WRITEV` workaround in the interim.
