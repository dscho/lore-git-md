This is patch 6/17 in Patrick Steinhardt's series implementing an in-memory object database (ODB) source as part of the broader ODB abstraction effort. The patch implements the `write_object()` callback for the in-memory backend, completing a key piece of functionality.

The change moves the object writing logic from `odb.c` into the new `odb_source_inmemory_write_object()` function, which follows the same pattern as the existing implementation but now properly integrates with the ODB source abstraction. The function allocates memory for the object, stores its contents, and tracks it in the in-memory storage (now using an oidtree rather than a simple array, as established in earlier patches).

This is a straightforward refactoring that maintains the same behavior while fitting into the new architecture. The patch appears well-contained and follows the established pattern of the series. Given Patrick's track record with architectural changes and the clear motivation for the overall effort, this seems like a solid incremental step in the ODB abstraction work.
