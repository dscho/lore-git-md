This is a platform compatibility discussion about NonStop system limitations with `writev()`. Jeff King (Peff) responds to Randall S. Becker's report that `NO_WRITEV=Nope` isn't preventing `writev()` usage, causing test failures.

Peff identifies the root cause: Git's fallback `writev()` wrapper is too strict in its emulation, rejecting valid operations due to NonStop's smaller `ssize_t` type. The wrapper enforces size limits that trigger `EINVAL` errors, even though the underlying issue is the platform's inability to handle the buffer sizes Git assumes (64k chunks).

The response suggests two paths forward for Git 2.54: either properly implement `MAX_IO_SIZE` support to respect platform limits, or temporarily revert `writev()` usage in `send_sideband()` until a complete fix is ready. Peff notes the complexity of a proper fix would require careful handling of partial writes to avoid overflow while still reporting progress to callers.

This exchange highlights the tension between Git's performance optimizations (using `writev()` for efficient I/O) and platform compatibility, particularly on NonStop systems with unusual constraints. The technical analysis is thorough, identifying both the immediate symptom and the deeper architectural consideration needed for a robust solution.
