This is a follow-up from the maintainer on the branch name prefixing feature proposal, now in its fourth iteration. Junio Hamano raises additional concerns about the design's usability, specifically questioning why users must manually include a hyphen in their branch names when using the prefix feature.

The email focuses on a test case where the config sets `branch.namePrefix=blob` and creates a branch with `-- -with-prefix`, resulting in `blob-with-prefix`. Junio argues this design is awkward - if the goal is to create consistently prefixed branches (like `blob-master`, `blob-feature`), the hyphen should either be part of the prefix itself (`blob-`) or automatically inserted by the prefixing mechanism, rather than requiring users to type it as part of the branch name.

This critique goes beyond the earlier fundamental objections about whether the feature belongs in core Git, now focusing on ergonomic issues in the current implementation. While the technical aspects of config integration and prefix handling were addressed in v4, this highlights another layer of design consideration needed if the feature were to proceed. The maintainer's continued skepticism suggests the series faces significant hurdles despite its technical improvements.
