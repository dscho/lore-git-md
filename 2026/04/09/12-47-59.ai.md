This is a platform compatibility patch addressing an issue with `MAX_IO_SIZE` handling in NonStop systems. Patrick Steinhardt introduces a new `xwritev()` wrapper function that properly handles platform-specific I/O size limits when using `writev()`, similar to how `xwrite()` already does for regular writes.

The patch was prompted by a report from Randall Becker about NonStop systems having a small `MAX_IO_SIZE` limit that wasn't being respected in the `writev()` path. The new function coalesces iovec entries to stay under the limit, falling back to `xwrite()` if the first entry is too large. Jeff King (Peff) provided input on the solution.

The change affects the low-level I/O wrapper layer, modifying `wrapper.c` to add the new function and updating `writev_in_full()` to use it. The implementation carefully handles edge cases like integer overflow and partial writes. While Patrick mentions the alternative of just disabling `writev` on NonStop for now, he suggests this more complete solution is preferable long-term.
