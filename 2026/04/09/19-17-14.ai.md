This is part 3/4 of a feature patch series that enhances conflict resolution in `git checkout -m` by integrating autostash behavior. The series is now in its final v8 iteration with all edge cases resolved and ready for merge.

The current patch specifically extends the sequencer's autostash machinery to support customizable conflict marker labels when applying stashes. It adds new parameters to several internal functions to pass through label strings (ours/theirs/base) to the underlying `git stash apply` command. A new public function `apply_autostash_ref_with_labels()` is exposed in sequencer.h for callers that want to specify labels.

Key technical details:
- Modifies `apply_save_autostash_oid()` to accept optional label parameters
- Adds label support to the ref-based autostash application functions
- Introduces `apply_autostash_ref_with_labels()` API for external callers
- Maintains backward compatibility by making all label parameters optional
- Follows the established pattern of the existing autostash infrastructure

The changes are focused on the sequencer component (`sequencer.c` and `sequencer.h`), building on the previous patches in the series that implemented the core autostash behavior for checkout. This patch completes the plumbing needed to support customized conflict markers throughout the autostash workflow.

The implementation has been thoroughly reviewed and tested across multiple iterations, with v8 specifically adding test coverage for edge cases like empty label strings. The patch maintains clean separation of concerns while extending the existing autostash machinery in a natural way.
