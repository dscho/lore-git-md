This is a feature patch in the final iteration of a series enhancing Git's autostash functionality with custom conflict marker labels. The patch adds label support to the sequencer's autostash application code, allowing callers to specify custom labels for the "ours", "theirs", and "base" sides of merge conflicts.

The implementation introduces `apply_autostash_ref_with_labels()` as a new public API that accepts three label parameters, which get passed through to `git stash apply` via the corresponding `--ours-label`, `--theirs-label`, and `--base-label` options. The patch maintains backward compatibility by keeping the existing label-less functions while adding this new variant.

Junio Hamano provides final review feedback suggesting two possible naming improvements for the parameters: either using the more descriptive "ours/theirs/base" terminology consistently, or adopting the conventional stage numbering (1=base, 2=ours, 3=theirs) if numbered parameters are preferred. This is the only remaining issue in an otherwise complete and well-structured patch that has already addressed all technical requirements through previous iterations.

The change is part of the series' broader goal to unify conflict resolution behavior between `git checkout -m` and other commands that use autostash, while giving users more control over conflict presentation. With maintainer approval already confirmed pending these final naming tweaks, the patch appears ready for merging once the parameter naming is finalized.
