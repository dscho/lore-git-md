This is patch 15/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ODB abstraction effort. The patch adds the `freshen_object()` callback to the in-memory ODB backend.

The implementation is straightforward - it checks if an object exists in the in-memory storage (using the existing `find_cached_object()` helper) and returns 1 if found, 0 otherwise. This matches the behavior of other ODB backends where `freshen_object()` is used to update timestamps or otherwise mark objects as recently used, though in the in-memory case it's just an existence check since there's no persistence.

This completes another piece of the ODB source interface, bringing the in-memory backend closer to feature parity with the persistent backends. The change is small and mechanical, following the same pattern as the other callback implementations in this series. It touches only `odb/source-inmemory.c`, adding the callback function and wiring it into the source operations structure.

As with previous patches in the series, this appears to be a well-contained and properly motivated change that moves the overall ODB abstraction effort forward. The implementation is simple and correct, though reviewers may want to confirm that the behavior aligns with expectations for how `freshen_object()` should work across all ODB backends.
