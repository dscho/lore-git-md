This is a technical discussion about patch 5 in Patrick Steinhardt's 16-part series introducing an in-memory object database backend, part of the ongoing ODB abstraction effort. 

Justin Tobler had questioned whether implementing a `read_object_stream()` callback for the in-memory backend was actually useful, since the whole point of an in-memory backend is that objects are already fully available. Patrick Steinhardt replies that while he can't think of a practical use case for streaming in this context, he included the implementation anyway to make the backend interface complete.

The exchange highlights a thoughtful review pattern where Justin surfaces architectural considerations (in this case, questioning whether the streaming abstraction adds unnecessary overhead) while acknowledging the technical correctness of the implementation. Patrick's response indicates this was a completeness consideration rather than a hard requirement. This kind of discussion is typical for the ODB abstraction work, where interface design decisions often have long-term implications.
