This is patch 16/17 in Patrick Steinhardt's series implementing an in-memory object database (ODB) backend as part of the broader ODB abstraction effort. The patch stubs out remaining ODB source callbacks that aren't needed for the in-memory implementation.

The changes:
- Adds no-op implementations for `close()` and `reprepare()` since the in-memory backend doesn't need cleanup or refresh logic
- Returns errors for transaction and alternates operations which don't make sense for transient storage
- Keeps `read_alternates()` as a no-op since alternates aren't supported
- The implementation is straightforward - either returning errors for unsupported operations or doing nothing where appropriate
- This completes the pattern seen throughout the series of carefully considering each ODB interface method and implementing only what's meaningful for an in-memory store

As the second-to-last patch in the series, this is tying up loose ends after the core functionality was implemented in previous patches. The changes are mechanical but necessary for the backend to fully implement the ODB source interface. The series appears to be in its final polishing stages before potential merging.
