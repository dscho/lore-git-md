This is a bugfix patch in the fsmonitor daemon series, addressing a khash memory leak in the client handling code. The patch is part of a larger v14 series implementing Linux filesystem monitoring via inotify.

The issue occurs when the fsmonitor daemon sends a trivial response to a client - the code was skipping cleanup of a string hash table (`shown`) that tracks which paths have already been reported. The fix initializes the hash table pointer to NULL and moves the cleanup to a shared exit path that runs in all cases, using `kh_destroy_str()` which safely handles NULL pointers.

This appears to be a straightforward and well-contained fix to a memory leak that was likely found during testing of the larger fsmonitor implementation. The change is small (5 lines modified) and follows the pattern of the surrounding code. Given the extensive review and testing of the overall series (now at v14), this patch seems like a low-risk improvement to an otherwise stable feature.
