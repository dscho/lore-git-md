This is a test patch in the fsmonitor series, adding Linux-specific test coverage for the filesystem monitoring daemon. It's part of a larger effort (v14 of the series) to bring Linux support to parity with Windows and macOS implementations.

The patch adds several key test scenarios:
1. A smoke test that verifies the filesystem actually delivers inotify events (some configurations like older overlayfs kernels accept watches but never deliver events)
2. A stress test for rapid nested directory creation to catch EEXIST race conditions during recursive scanning
3. Reduced start-timeout from 60 to 10 seconds for faster test feedback
4. Improved test robustness in environments without procps (like Fedora CI) by falling back to /proc/$pid/stat
5. Job control fixes for submodule pull tests to prevent shell wait blocking

The tests demonstrate thoughtful consideration of edge cases and real-world environments, with particular attention to container/overlayfs scenarios that have caused problems in the past. The implementation appears well-tested and production-ready, with this patch rounding out the test coverage for the Linux implementation.

This is the 12th of 13 patches in v14 of the series, which has undergone extensive review and iteration. The tests complement the core implementation work in previous patches, providing confidence in the daemon's behavior under various filesystem conditions.
