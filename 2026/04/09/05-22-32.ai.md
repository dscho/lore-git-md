This is a naming discussion in Patrick Steinhardt's feature patch series introducing an in-memory object database source as part of the ODB abstraction effort. The thread has progressed from technical implementation details to a more conceptual discussion about terminology consistency in the codebase.

Junio C Hamano raised a question about whether the new "in-memory" backend represents the same concept as the existing "in-core" terminology used elsewhere in Git. Patrick responds that while the concepts are fundamentally similar, he chose "in-memory" for several reasons: it will eventually be exposed to power users through a planned "objectStorage" extension (similar to the existing "refStorage" extension), and he believes "inmemory://" is more intuitive than "incore://" for configuration purposes. He acknowledges the counterargument that power users might understand "in-core" but maintains his preference for the clearer "in-memory" terminology.

The discussion reflects the project's attention to precise naming, especially for concepts that may become user-facing. While this doesn't block the technical implementation (which has already been reviewed and confirmed by Justin Tobler), it shows the maintainer's focus on long-term conceptual clarity. The exchange also hints at future directions for the ODB abstraction work, particularly around configurable storage backends.
