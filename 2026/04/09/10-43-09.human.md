This is the first patch in a two-part series introducing branch name prefixing functionality to `git branch`. The feature allows users to automatically prefix new branch names with either a static string or the current branch name (via `@{current}` token).

The implementation adds a `--name-prefix` option to `git branch` and includes:
- A new `get_current_branch_name()` helper to properly resolve HEAD
- The core `add_branch_prefix()` function that handles both static strings and the `@{current}` token
- Error handling and warning messages for failed prefix resolution
- Documentation updates explaining the new option
- Comprehensive tests in t3200-branch.sh covering various prefixing cases

The patch represents significant improvement over previous iterations, fixing issues with current branch resolution and adding proper error handling. However, as noted in the thread context, fundamental questions about the feature's value remain unresolved from earlier review rounds. The implementation itself looks technically sound, with good test coverage and clear documentation.

This is part of an ongoing effort to simplify hierarchical branch naming workflows, particularly for backport scenarios in large projects like Ocean HPC (as mentioned in the cover letter). While the technical execution has improved, the series still needs to address the maintainer's concerns about whether this specific approach is the right solution to the problem.
