This is a platform compatibility patch addressing feedback from Junio Hamano on Patrick Steinhardt's proposed `xwritev()` implementation for handling `MAX_IO_SIZE` limits in `writev()` calls. The discussion focuses on refining the solution for NonStop systems where `MAX_IO_SIZE` is particularly small.

Junio acknowledges the general approach of mirroring `xwrite()`'s pattern for handling platform-specific I/O limits but raises several technical points about the implementation. He questions whether `unsigned_add_overflows()` is the right check for preventing `ssize_t` overflow in `writev()`, suggests improving comment clarity around the first-buffer special case, and notes that the error handling for EINTR/EAGAIN should be consistent with `xwrite()`'s behavior.

The maintainer also points out that this change comes too late for Git 2.54 and recommends NonStop users set `NO_WRITEV` as a temporary workaround. However, he engages with the technical merits to prepare for a post-release solution, emphasizing the importance of earlier testing from minority platforms.

The patch remains technically sound but will need adjustments to address:
1) The `ssize_t` overflow detection logic
2) More precise error handling alignment with `xwrite()`
3) Improved comment wording
4) Consideration of chunking behavior for very large requests

Given Junio's detailed review and Patrick's track record with low-level improvements, this discussion appears to be moving toward a refined solution rather than encountering fundamental objections. The exchange highlights Git's careful approach to platform compatibility, even for less common systems.
