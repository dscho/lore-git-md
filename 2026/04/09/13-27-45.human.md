This is the final patch in a feature series (v7) that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch implements the core functionality where `checkout -m` will now automatically stash local changes before switching branches and reapply them afterward, with clear messaging when conflicts occur.

The key improvements in this patch:
- Unified conflict resolution behavior in `git checkout -m` through autostash
- Silent autostash creation during checkout operations
- Comprehensive documentation updates explaining the new behavior
- Extensive test coverage (19 test cases in t7201-co.sh)
- Backward compatibility maintained
- When switching branches with local changes that don't conflict, the changes are cleanly carried over
- When conflicts occur, the stash is preserved and the UI clearly explains next steps
- New test case specifically verifies clean stash application with non-overlapping changes

The implementation appears production-ready with all edge cases addressed. Junio Hamano has expressed approval of the approach in previous iterations. This represents a significant quality-of-life improvement for branch switching workflows, particularly when developers need to context switch between branches with uncommitted changes. The maintainer feedback suggests this is likely to be merged soon.
