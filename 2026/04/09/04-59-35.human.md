This is a refactoring patch in the fsmonitor daemon series, converting from a khash implementation to a strset for pathname deduplication. It's the final patch (13/13) in v14 of the cross-platform filesystem monitoring implementation.

The change replaces the manual khash string set management with Git's higher-level strset API, which provides a cleaner interface for the same deduplication functionality. Since the paths are already interned strings from the batch data, the patch sets strdup_strings=0 to avoid unnecessary string copies.

The conversion was suggested by Patrick Steinhardt and maintains all the existing functionality while simplifying the code. This is a straightforward improvement that follows the pattern of other recent string handling conversions in the codebase. The patch is small (17 lines changed) and focused, touching only the path deduplication logic in the daemon's client handling code.

This change comes after extensive testing and review across 14 iterations of the fsmonitor series, indicating it's a low-risk final polish to an otherwise mature implementation. The series as a whole has already addressed memory management, platform compatibility, and test coverage, with this patch representing a last bit of code hygiene.
