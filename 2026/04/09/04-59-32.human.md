This is a feature patch in the fsmonitor series, specifically addressing process isolation improvements for the filesystem monitoring daemon. It's part of a larger effort (v14) to bring comprehensive cross-platform fsmonitor support, with Linux implementation via inotify being the focus.

The patch solves two key issues in the daemon's process management:
1. It prevents the daemon from inheriting unnecessary file descriptors when spawned, which could cause parent processes (like test harnesses) to hang waiting for EOF on pipes. This is done by setting `close_fd_above_stderr` in the child process configuration.
2. It properly detaches the daemon process on Unix systems using `setsid()` when started with `--detach`, preventing shell job control from keeping the spawning shell waiting for the daemon to exit.

The changes affect both explicit daemon startup (`fsmonitor--daemon start`) and the implicit spawn path when a client finds no running daemon. The implementation is careful platform-specific handling, with Windows using `FreeConsole()` while Unix systems use `setsid()`.

This appears to be a well-considered addition to the fsmonitor implementation, addressing real-world issues seen in CI/test environments while maintaining the daemon's functionality. The patch builds on the extensive work already done in previous iterations of the series, now focusing on cleaning up edge cases in process management.
