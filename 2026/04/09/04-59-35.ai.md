This is a refactoring patch in the fsmonitor daemon series, converting from a khash implementation to using Git's strset for pathname deduplication in the client handling code. The change follows Patrick Steinhardt's suggestion to use the higher-level strset interface rather than direct khash manipulation.

The patch replaces the khash initialization and operations with equivalent strset calls, maintaining the same deduplication behavior while simplifying the code. Since the paths are already interned strings from the batch data, it sets strdup_strings=0 to avoid unnecessary string copying. The memory management remains correct with strset_clear() handling cleanup.

This appears to be a straightforward quality-of-life improvement late in the fsmonitor series, building on the extensive platform support and testing work already established in previous patches. The change is mechanical and well-contained, touching only the client response path deduplication logic while preserving all existing functionality.
