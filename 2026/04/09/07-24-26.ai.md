This is patch 5/17 in Patrick Steinhardt's v2 series implementing an in-memory object database source as part of the ODB abstraction effort. The patch adds streaming read capability to the in-memory ODB backend.

The implementation introduces a new `odb_read_stream_inmemory` struct that wraps the base streaming interface with in-memory specific state (buffer pointer and offset). It provides the required callbacks for reading chunks of data (`odb_read_stream_inmemory_read`) and closing the stream (`odb_read_stream_inmemory_close`), though the close operation is a no-op since there are no resources to release for in-memory objects.

The core function `odb_source_inmemory_read_object_stream` locates the requested object via the existing `find_cached_object` helper, then constructs and returns a properly initialized stream object. The implementation follows the pattern seen elsewhere in the series, using type-safe downcasting via `odb_source_inmemory_downcast` and maintaining consistency with the broader ODB source interface.

This is a straightforward implementation of a required callback that completes the read-side functionality for the in-memory source. While streaming reads may seem like overkill for in-memory objects (since the full content is already available), the uniform interface allows the in-memory source to be used interchangeably with other ODB backends. The patch appears well-structured and maintains the series' focus on clean, incremental changes.
