This is a bugfix patch in the fsmonitor series, adding a timeout to prevent indefinite hangs when stopping the daemon. It's part of a larger effort to implement cross-platform filesystem monitoring (v14 of the series).

The patch addresses a specific issue where the `fsmonitor--daemon stop` command could hang forever if the daemon fails to shut down properly. It introduces a 30-second timeout (polling every 50ms) after which the command will error out rather than blocking indefinitely. The implementation is straightforward - it tracks elapsed time during the polling loop and returns an error if the timeout is exceeded.

This is a sensible safety measure that follows the pattern established in other parts of the fsmonitor implementation where timeouts are used to prevent hangs. The 30-second duration seems reasonable for normal operation while still catching stuck cases. The patch maintains the existing trace2 instrumentation and error reporting patterns used elsewhere in the codebase.

As part of the mature v14 series that has already addressed numerous edge cases across platforms, this appears to be a well-considered final polish to the shutdown behavior. The change is small and focused, with clear motivation explained in the commit message.
