Thread subject: "compat: add xwritev() to handle platform-specific I/O size limits" - patch series root from Patrick Steinhardt addressing NonStop platform compatibility issue with `writev()`.

Core problem: NonStop systems have small `MAX_IO_SIZE` limit (reported by Randall S. Becker) not respected in `writev()` path, unlike regular writes which use `xwrite()`'s size-limiting wrapper. Current implementation risks failing on NonStop when large iovec entries exceed platform limits.

Solution: Introduces new `xwritev()` wrapper in `wrapper.c` that coalesces iovec entries under `MAX_IO_SIZE`, falls back to `xwrite()` for oversized first element, and maintains careful error handling. Updates `writev_in_full()` to use new wrapper.

Technical details:
- Modifies `wrapper.c` with new function and updates callers
- Handles EINTR, partial writes like `xwrite()`
- Preserves behavior on platforms without `MAX_IO_SIZE` limits
- Alternative considered: disable `writev` on NonStop temporarily
