This is part 3 of a 4-patch feature series enhancing `git checkout -m` with autostash behavior and conflict marker labeling. The series has been through multiple rounds of review and is now in its final polishing stage with maintainer approval.

The current patch extends the autostash machinery in `sequencer.c` to support custom conflict marker labels when applying stashes. It adds new parameters to internal functions for passing label strings through to `git stash apply`'s `--ours-label`, `--theirs-label`, and `--base-label` options. A new public function `apply_autostash_ref_with_labels()` is exposed for callers that want to specify labels.

The changes are straightforward plumbing to connect the existing stash label functionality (added in patch 1 of the series) with the autostash machinery. The implementation maintains backward compatibility by keeping the original functions that don't take labels, and all existing callers continue using those. The patch includes comprehensive updates to both the implementation and header file.

This is a well-contained change that completes the series' goal of unifying conflict resolution behavior between `git checkout -m` and other commands while adding the ability to customize conflict markers. The series as a whole appears production-ready, with Junio Hamano having expressed approval in previous iterations. The changes here are the final plumbing needed to support the new functionality.
