Bugfix addressing platform-specific I/O constraints on NonStop systems. Patrick Steinhardt proposes a solution for handling `MAX_IO_SIZE` limits in `writev()` operations, following a report from Randall Becker.

The patch introduces a new `xwritev()` wrapper that properly handles systems (like NonStop) with small `MAX_IO_SIZE` limits by either:
1. Coalescing iovec entries that stay under the limit
2. Falling back to `xwrite()` when the first entry exceeds the limit

The change adapts `writev_in_full()` to use this new wrapper, maintaining the existing retry-on-interrupt behavior while adding proper size limit handling. Jeff King (Peff) provided input on the solution.

The patch appears well-considered, with clear commit message explaining both the problem and solution. Patrick notes this could be a starting point for discussion, alternatively suggesting `NO_WRITEV` as a temporary workaround for NonStop. The implementation looks solid, handling edge cases like integer overflow and maintaining the existing error reporting behavior.
