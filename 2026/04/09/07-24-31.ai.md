This is a refactoring patch in Patrick Steinhardt's ongoing ODB abstraction series, specifically enhancing the oidtree data structure to support arbitrary payload storage alongside object IDs. The patch modifies the oidtree implementation to allow associating arbitrary data pointers with stored object IDs, while maintaining the existing prefix-based lookup functionality. Key changes include:

- Adding a `data` field to `struct oidtree_node` to store payloads
- Modifying `oidtree_insert()` to accept and store a data pointer
- Introducing `oidtree_get()` to retrieve stored data
- Updating the iteration callback signature to include node data
- Adding unit tests for the new data-storage behavior

The changes are cleanly implemented with thorough test coverage. This refactoring enables the next patch in the series to use oidtree for storing object metadata in the in-memory ODB backend. The patch maintains backward compatibility by making the data parameter optional (NULL by default in existing call sites).

This is a well-contained change that follows the series' architectural direction while providing a useful enhancement to the oidtree abstraction. The implementation is careful to handle edge cases like duplicate insertion (overwriting existing data) and maintains all existing functionality. The unit test additions verify both the new data storage capability and backward compatibility with NULL payloads.
