This is patch 8/17 in Patrick Steinhardt's feature series implementing an in-memory object database source as part of the broader ODB abstraction effort. The patch adds streaming write capability to the in-memory ODB backend.

The implementation follows the pattern established in previous patches, providing a `write_object_stream()` callback that reads data in chunks (using a 16KB buffer) and accumulates it into a single allocation before passing it to the existing `write_object()` function. The code includes error handling for cases where the stream yields more or fewer bytes than expected, maintaining the safety guarantees expected from the ODB interface.

Technically, this completes another piece of the callback suite needed for a fully functional ODB source. The implementation is straightforward - it reads the stream to completion before writing the object - which makes sense for an in-memory backend where performance overhead is less critical than for persistent storage. The patch maintains type safety through the existing `odb_source_inmemory_downcast` helper and follows the series' established patterns for memory management.

This continues the series' consistent approach of implementing one well-defined piece of functionality per commit. While the streaming interface may see limited use in an in-memory context (as noted in previous summaries), its inclusion ensures the backend meets all interface requirements for potential future uses. The patch appears ready for review alongside the rest of the series.
