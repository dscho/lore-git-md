This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The patch has gone through extensive review (now at v8) and is ready for merging.

The change makes `git checkout -m` automatically stash local changes when they conflict with the target branch, then reapply them after switching. If the changes can be cleanly applied, it shows "Applied autostash"; if conflicts occur, it keeps the stash entry and provides guidance for resolving them. The implementation includes:

- New silent stash creation and labeled application functions
- Support for custom conflict marker labels (including empty strings)
- Comprehensive test coverage (19 cases in t7201-co.sh)
- Documentation updates explaining the new behavior
- Modified components in `builtin/checkout.c`, `builtin/stash.c`, `sequencer.c`, and xdiff handling

The patch builds on previous work in the series that added label support to stash application and fixed xdiff handling of empty labels. It's been validated in production environments and has maintainer approval from Junio Hamano with technical review from Phillip Wood. The implementation matches existing autostash behavior in `git rebase`/`git merge` while preserving backward compatibility.

This represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes. The thorough test coverage and documentation updates make this a production-ready change that's been carefully vetted through multiple iterations.
