This is a memory leak fix in the fsmonitor daemon implementation, part of a larger series adding Linux filesystem monitoring support. The patch addresses a resource management issue where cookie tracking data structures weren't being properly cleaned up when the daemon shuts down.

The fix adds cleanup code to free both the individual cookie names (allocated via strbuf_detach) and the hashmap itself during daemon shutdown. This plugs a leak that would accumulate memory over time for long-running daemon processes. The change is straightforward and follows the project's patterns for hashmap cleanup.

This is the third patch in the 14th iteration of a well-tested series that has already addressed numerous edge cases and platform-specific concerns. The fix demonstrates continued attention to detail in resource management for this production-ready feature.
