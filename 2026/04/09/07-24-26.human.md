This is part 5 of Patrick Steinhardt's 17-patch series introducing an in-memory object database (ODB) backend, a key piece of the ongoing ODB abstraction effort. The patch implements the `read_object_stream()` callback for the in-memory source, completing the streaming interface started in earlier patches.

The implementation follows the established pattern for ODB source callbacks, with a dedicated `odb_read_stream_inmemory` struct that wraps the in-memory buffer and tracks read position. The code handles bounds checking during reads and maintains proper type safety through the container_of pattern seen elsewhere in the series. 

This is a straightforward but necessary piece of the puzzle - while an in-memory backend might not seem like an obvious candidate for streaming reads (since the data is already fully in memory), implementing the full callback suite ensures consistency with the ODB abstraction interface. The patch appears cleanly implemented with no obvious issues, though some reviewers might question the streaming interface's utility in this context.

The changes are focused entirely on `odb/source-inmemory.c`, adding 50 lines to implement the new callback while maintaining the series' clean separation of concerns. This continues the series' pattern of methodically building up the in-memory backend's capabilities one well-contained piece at a time.
