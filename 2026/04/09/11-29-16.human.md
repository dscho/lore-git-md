This is a platform compatibility patch addressing `writev()` limitations on NonStop systems, part of the ongoing thread about Git 2.54.0-rc1 test failures. Patrick Steinhardt shares an updated version of his proposed `xwritev()` solution after Phillip Wood confirmed the technical limitation applies to the total size of iovec arrays rather than individual entries.

The patch introduces a new `xwritev()` function that handles platforms with small SSIZE_MAX limits by splitting large writes while maintaining the optimization benefits of vectorized I/O where possible. The implementation carefully handles edge cases where the first iovec entry exceeds MAX_IO_SIZE by falling back to `xwrite()`, and includes proper error handling for partial writes and system call interruptions.

This appears to be a well-considered technical solution to the platform compatibility issue, building on the earlier discussion where Jeff King, Junio Hamano, and others analyzed the root cause. Patrick has tested the patch with an artificially low MAX_IO_SIZE to verify its behavior. The implementation seems robust, addressing both the immediate NonStop issue while preserving performance on platforms without such limitations.

The patch moves the discussion forward from the temporary NO_WRITEV workaround toward a more architectural solution. Given Phillip Wood's confirmation about the nature of the limitation and Patrick's thorough handling of edge cases, this seems likely to be accepted as the long-term fix unless new technical concerns emerge during review.
