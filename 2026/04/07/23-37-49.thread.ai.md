Thread identity: Test failure report for t5401.13 ("pre-receive hook that forgets to read its input") in Git 2.54.0-rc0, reported by Randall Becker (NonStop port maintainer).

Core problem: A regression in pre-receive hook behavior where hooks that exit successfully (status 0) without reading their input are incorrectly rejecting all pushed references, contrary to the expected behavior where such hooks should allow the push to succeed. The test creates 900 branches and pushes them to a repository with such a hook.

Current status: The issue was observed during 2.54.0-rc0 testing on NonStop systems, but may not be platform-specific. The test expects the push to succeed when the pre-receive hook exits 0 without reading input, but instead sees all branch pushes (branch_100 through branch_999) rejected with "remote rejected" messages.

Key technical details: Test file is t/t5401-update-hooks.sh test 13. The test verifies behavior of pre-receive hooks that exit early without processing reference updates. The hook in question exits successfully (status 0) without reading stdin, which should allow the push to proceed but is instead causing all ref updates to be rejected.

Open questions: Whether this is a NonStop-specific issue or a general regression in hook handling. The root cause of why the hook's early exit is being interpreted as rejection of all refs.

Participant positions: Randall Becker reported the issue during rc testing, noting it may affect hook behavior generally rather than being NonStop-specific.

Related work: This touches the hook subsystem which is currently undergoing changes via Adrian Ratiu's configuration-based hooks work, though that effort is likely unrelated to this specific issue.
