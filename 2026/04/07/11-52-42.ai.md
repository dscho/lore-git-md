This is a refactoring patch in Christian Couder's series on promisor-remote handling, specifically addressing memory management. The patch eliminates the redundant 'accepted' strvec in favor of using the existing 'accepted_remotes' string list throughout the promisor-remote filtering process.

The change simplifies the data flow by removing parallel structures - previously there were three separate collections (server names in a strvec, filters in a string list, and promisor_info structs) that now consolidate into a single string list retaining the full promisor_info structs. This makes the code more maintainable and prepares for future extensions (like adding a 'local_name' field to promisor_info) while maintaining all existing behavior.

The patch touches key promisor-remote functions including `filter_promisor_remote()` and `promisor_remote_reply()`, removing 15 lines while adding 12. The changes are mechanical but meaningful - instead of pushing names to a separate strvec, the code now directly uses the string list that was already tracking the accepted remotes. The reply generation is updated to iterate this list rather than the now-removed strvec.

This continues the series' pattern of preparatory cleanups before introducing new URL-based auto-configuration functionality. The changes are well-contained to promisor-remote.c and maintain backward compatibility while making the internal structure more coherent.
