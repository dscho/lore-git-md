This is a follow-up in the `git fast-export` bugfix thread, addressing path ordering issues when deletions are prefixes of added paths. Raymond E. Pasco responds to Elijah Newren's technical points about the current behavior of `fast-export` and `fast-import`.

The key new information is that `fast-export` already handles renames by forcing them to appear after other operations on the same path (commit 4ce6fb80). Pasco confirms that prioritizing deletions first (the current proposed solution) would work with the patterns `fast-export` actually generates, and notes that the existing depth-based sorting was already addressing a subset of this problem (ensuring directory deletions appear before modifications to symlinks).

Pasco is now focusing on writing comprehensive round-trip tests to verify the fix, mentioning this is particularly relevant as users might start using `fast-export | fast-import` for hash function migration once commit/tag signing support is complete in `fast-import`. This suggests the fix has implications beyond just correctness - it affects a potential future workflow.
