This is a maintainer review response in Lorenzo Pegorari's promisor repack series, focusing on portability and design concerns. Junio Hamano points out two key issues with the current approach to timestamp handling in the promisor file helper:

1. The `localtime_r()` usage is not just a typo (using comma instead of semicolon) but actually breaks the macOS build due to platform differences in how file timestamps are accessed. The CI failure shows this is a concrete portability problem, not just theoretical.

2. More fundamentally, Junio questions the design choice to store timestamps in human-readable format ("%Y/%m/%d-%H:%M:%S") rather than as raw epoch seconds. He suggests this would be both simpler to implement and less prone to timezone-related issues, while still serving the debugging purpose.

The exchange continues the thread's pattern of thorough review catching subtle issues - first memory leaks and syntax errors identified by Tian Yuchen, now platform compatibility and design questions from the maintainer. These are the kinds of implementation details that often surface in later review rounds for complex changes like geometric repacking with promisor files. The author will need to address both the immediate macOS build failure and consider whether to redesign the timestamp storage approach.
