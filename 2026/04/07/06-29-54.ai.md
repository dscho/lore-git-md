This is a review response in Taylor Blau's ongoing series on incremental MIDX/bitmap-based repacking, specifically addressing patch 13/16 which fixes a memory leak in packfile revindex handling. Jeff King (Peff) confirms the technical correctness of the fix while providing additional context about why the leak wasn't previously noticed in practice.

Peff notes that while the leak exists, it's rarely triggered in current usage because the main repository's object database isn't frequently freed (only submodules' are), and submodules typically don't need revindexes. He confirms that the patch's approach of adding `FREE_AND_NULL(p->revindex)` in `close_pack_revindex()` is appropriate, as this function is meant to fully reset the packed_git struct's state rather than just releasing on-disk resources.

The review highlights how the series' new test cases are uncovering subtle resource management issues that predate the current work. Peff's analysis provides valuable historical perspective on why this particular leak went unnoticed, while agreeing the fix is correct and necessary for the new functionality. This continues the pattern of thorough subsystem review from Peff, who consistently examines both the immediate change and its broader architectural context.
