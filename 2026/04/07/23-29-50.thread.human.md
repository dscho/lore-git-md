This thread reports a regression in Git 2.54.0-rc1 affecting the NonStop platform, where network operations using the `writev()` system call fail with "Invalid function argument" errors. The issue was initially reported by Randall S. Becker (NonStop maintainer) and analyzed by Jeff King (Peff), who determined it affects multiple test suites (t5310, t5326, t5327, t5608, t7700) and general network operations like cloning and push/pull.

The core problem is that NonStop's `writev()` implementation rejects vectorized writes on certain descriptor types, despite Git's expectation that it should work on pipes. This became apparent after recent optimizations expanded `writev()` usage in network code paths. While the issue was initially thought to be bitmap-specific, it's now clear it impacts any network operation using vectorized I/O.

Jeff King has proposed using the `NO_WRITEV=Nope` build flag as an immediate workaround, though this needs verification. The discussion continues about whether this is sufficient for the 2.54.0 release or if the optimization should be reverted. The case highlights the ongoing challenge of balancing performance improvements with support for less common platforms that may have system call limitations. With multiple test failures and potential user impact, this is a release-blocking issue that will need resolution before 2.54.0 final.
