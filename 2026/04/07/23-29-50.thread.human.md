This thread reports a regression in Git 2.54.0-rc1 affecting the NonStop platform, where recent optimizations using `writev()` for network operations are failing with "Invalid function argument" errors. The issue was initially observed in bitmap-related tests (t5310, t5326, t5327) but Randall S. Becker now confirms it affects any test using `writev()`, including t5608 and t7700.

Jeff King correctly identified the root cause - NonStop's `writev()` implementation rejects vectorized writes on network sockets. While the `--git-dir` confusion in t5310 was initially thought to be a separate issue, it's now clear this was just a symptom of the underlying `writev()` problem. The thread has discussed using `NO_WRITEV=Nope` as a workaround (falling back to individual `write()` calls), though this hasn't been tested yet.

Given the broad impact across multiple tests and the regression's severity on NonStop systems, the discussion is leaning toward either reverting the `writev()` optimization for the 2.54.0 release or making it conditional for NonStop builds. This follows a pattern of past I/O size limitations on NonStop that required platform-specific handling. The thread awaits maintainer input on the best path forward for this performance optimization that's proving problematic on this niche but supported platform.
