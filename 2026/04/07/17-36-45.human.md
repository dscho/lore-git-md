Junio Hamano pushes back on Christian Couder's security hardening patch for promisor-remote handling, questioning the value of explicitly rejecting empty remote names and URLs. While the patch aims to add defense-in-depth against buggy/malicious servers by tightening validation in `parse_one_advertised_remote()`, Junio argues this creates an arbitrary distinction - if empty strings are invalid, why not single-character strings? He suggests the existing usage-side validation in `promisor_config_info_list()` is sufficient protection.

This is a philosophical disagreement about where to draw input validation boundaries, not a technical flaw in the patch. Junio's position reflects Git's general preference for minimal upfront validation, trusting downstream code to handle edge cases. The exchange shows how even small security-minded changes can prompt discussion about the right balance between robustness and simplicity in Git's codebase.

The patch remains part of Christian's larger promisor-remote refactoring series, which has otherwise received positive feedback.
