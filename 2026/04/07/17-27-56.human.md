This is a follow-up discussion in Christian Couder's promisor-remote refactoring series, specifically about improving warning message clarity in patch 03/10. Junio Hamano agrees with the goal of making it clearer that invalid promisor remotes are being ignored, but suggests reordering the warning messages to put the action ("ignoring") before the reason.

The maintainer proposes more direct phrasing like "ignoring remote X that advertises no usable URL" rather than the current "no URL advertised for X, ignoring this remote". This follows the principle of leading with the most important information - what Git is doing - before explaining why. The change would apply to all three warning messages in the patch.

While this is a small stylistic tweak, it's a meaningful user experience improvement that makes Git's behavior more transparent. The discussion shows Junio's attention to detail in ensuring error messages are optimally structured, even in a series that's otherwise technically sound and ready to merge. No code changes are needed beyond what Christian already proposed - this is just a suggested refinement of the message wording.
