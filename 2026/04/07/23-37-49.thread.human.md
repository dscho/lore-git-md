This thread concerns a regression in Git 2.54.0-rc0 where pre-receive hooks that exit successfully without reading their input incorrectly reject all pushed references. Randall Becker, the NonStop port maintainer, first reported the issue when testing the release candidate. Jeff King (Peff) diagnosed the root cause as a race condition in signal handling within `run_processes_parallel()`, where SIGPIPE handling gets overridden by child cleanup handlers, particularly visible on NonStop systems.

Peff has now extended his analysis with a new test case showing the issue also affects parallel hook execution scenarios, demonstrating that a fast-exiting hook can incorrectly terminate a slower one due to the same signal propagation race. His proposed fix - reordering signal handler installation to ensure SIG_IGN takes precedence - resolves both the original NonStop case and this newly identified parallel execution scenario. While parallel hooks aren't in 2.54.0, the analysis confirms the fix addresses a general signal handling issue rather than being platform-specific. Peff is still awaiting confirmation that the fix resolves Randall's original test case on NonStop systems, but the technical case for the change appears solid.
