This thread began with Randall Becker reporting a race condition in pre-receive hook execution that caused incorrect reference rejection when hooks exited without reading input, particularly affecting the NonStop port. Jeff King diagnosed the issue as a SIGPIPE handling problem in `run_processes_parallel()` and proposed a fix that reordered signal handler installation. The solution was confirmed to work on NonStop and addressed parallel execution scenarios, leading Junio to queue it for 2.54.0-rc2 with Adrian Ratiu handling the final patch submission.

However, Randall has now discovered that this fix introduces a regression in pre-push hooks, causing t5571.11 to hang indefinitely when a pre-push hook exits successfully without reading input. This suggests the signal handling changes may have broader implications across hook types than initially tested. The test hangs after the pack-reused line with no further output, indicating either a deadlock or infinite loop in push/hook interaction under these conditions.

With this regression affecting core push functionality, the previously agreed integration path for 2.54.0-rc2 is now in question. The thread awaits analysis from Jeff King and Adrian Ratiu to determine whether this is a fundamental limitation of the approach or an additional edge case that can be addressed within the current framework. The severity of the regression means the fix may need to be held from rc2 until the pre-push interaction is fully understood and resolved.
