This thread reports a test failure in Git 2.54.0-rc0 involving pre-receive hook behavior. Randall Becker, the NonStop port maintainer, found that test t5401.13 ("pre-receive hook that forgets to read its input") fails unexpectedly. The test creates 900 branches and pushes them to a repository with a pre-receive hook that exits successfully without reading input. While the test expects the push to succeed (since the hook exits with status 0), it instead fails with hundreds of "remote rejected" messages for each branch reference.

The failure suggests either a regression in how Git handles pre-receive hooks that don't consume their input, or possibly a platform-specific issue on NonStop systems. Since pre-receive hooks are a core Git feature, this could affect any workflow relying on hooks that exit early without processing all reference updates. The test in question (t/t5401-update-hooks.sh test 13) is designed to verify this specific edge case behavior.
