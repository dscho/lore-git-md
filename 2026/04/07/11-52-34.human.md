This is the first patch in Christian Couder's 10-part series refactoring promisor-remote handling, focusing on improving the order in which promisor remotes are tried when fetching missing objects. The patch introduces a behavioral change where remotes explicitly accepted from the server (via the promisor-remote capability) are now tried before other configured promisor remotes.

The key change extracts a new `try_promisor_remotes()` helper function and modifies `promisor_remote_get_direct()` to first try accepted remotes (those the server advertised and client accepted) before falling back to other configured remotes. This better reflects the intended agreement between client and server about preferred fetch sources.

The patch includes thorough test coverage with two new test cases that verify the new priority ordering works correctly preferring an accepted "lop" remote over a non-accepted "unused_lop" remote, both in clone and init+fetch scenarios. The tests use GIT_TRACE to verify the actual fetch order.

This is a well-structured patch that clearly documents the behavior change in gitprotocol-v2.adoc while maintaining backward compatibility. The changes are focused and the commit message provides good context about why this ordering matters, especially for future auto-configuration work. The test additions are comprehensive and follow existing patterns in the test suite.
