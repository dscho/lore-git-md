This is a refactoring patch in Christian Couder's series on promisor-remote handling. The patch restructures the control flow in `should_accept_remote()` to be more robust and prepare for future URL-based acceptance logic.

The key changes are:
1. Replaces a warning about empty URLs with a BUG() assertion, since empty URLs are now rejected earlier in parsing (as established by previous patches in the series)
2. Moves the URL validation check to the top of the function to cover all acceptance modes
3. Inverts the URL comparison logic to return early on mismatches and have a single exit path for matches

The changes are mechanical and don't introduce new functionality, but they make the code more maintainable and prepare for upcoming work. The patch follows the series' pattern of systematic improvements to promisor-remote handling, with this particular change focused on cleaning up the control flow before more substantial URL-based configuration features are added.

The patch is well-contained, touching only `promisor-remote.c`, and builds on the security hardening from earlier in the series. It maintains backward compatibility while making the code more robust for future extensions.
