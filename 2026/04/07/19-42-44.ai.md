This is a brief follow-up in the `git backfill` progress reporting thread, where Junio C Hamano clarifies a minor stylistic point about increment operators. The email corrects a misunderstanding in Trieu Huynh's response regarding Git's coding conventions for increment operators in void contexts.

Junio notes that while Huynh correctly acknowledged the need to change from pre-increment to post-increment style, the example given ("++counter; foo(counter)") actually demonstrates the wrong pattern - it still shows pre-increment. The correct form should be "counter++; foo(counter)" to match Git's convention of using post-increment in void contexts.

This is purely a coding style clarification that doesn't affect the functionality of the `--[no-]progress` option being added to `git backfill`. The thread shows the maintainer paying close attention to detail even in small stylistic matters, and the author appears receptive to these corrections. This level of attention to coding conventions is typical for the project, especially when a new contributor is being onboarded.
