This is a documentation and user experience improvement patch in Christian Couder's promisor-remote refactoring series. The patch clarifies warning messages when Git ignores invalid promisor remote configurations by explicitly stating that the remote is being ignored, rather than just describing why it's problematic.

The changes modify three warning messages in `promisor-remote.c` to be more explicit about the consequence (ignoring the remote) when:
1. A remote has no URL or an empty URL
2. A known remote's URL doesn't match the advertised URL
3. A server advertises a promisor remote without a name or URL

The patch maintains all existing functionality while making the user feedback more transparent. This is a small but meaningful quality-of-life improvement that helps users better understand Git's behavior when dealing with promisor remotes. The changes are straightforward and focused, touching only the warning message strings in the promisor-remote subsystem.
