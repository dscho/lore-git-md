This is a refactoring patch in Christian Couder's series to improve promisor-remote handling. The patch optimizes the `all_fields_match()` function by eliminating redundant lookups when checking remote configurations.

The key change replaces the `in_list` boolean parameter with a direct `config_entry` pointer, which allows the function to either:
1. Check all remotes (when NULL, maintaining the `ACCEPT_ALL` behavior)
2. Check just one specific remote (when non-NULL, avoiding repeated lookups)

The patch also adds clarifying comments to both `all_fields_match()` and `match_field_against_config()` to document their behavior and prevent future misuse. The changes are focused on `promisor-remote.c` and maintain the existing functionality while making the code more efficient and better documented.

This is a clean, focused change that removes unnecessary work while preparing for future auto-configuration features. The patch follows the series' pattern of structural improvements before adding new functionality, and the added comments will be valuable for future maintainers working with this code.
