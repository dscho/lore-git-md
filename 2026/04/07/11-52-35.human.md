This is a refactoring patch in Christian Couder's series to improve promisor-remote handling. The patch simplifies the `all_fields_match()` function by removing redundant lookups when checking remote configurations.

The key change replaces an `in_list` boolean with a direct `config_entry` pointer parameter, eliminating repeated lookups of the same remote configuration. When checking against a specific remote (rather than all remotes), the caller now passes the already-looked-up config entry directly rather than having the function look it up again by name. This makes the code more efficient and removes a hidden dependency on the remote name that could cause issues with future auto-configuration features.

The patch also adds clarifying comments to explain the behavior of `all_fields_match()` and its helper function `match_field_against_config()`. These help document the expected usage patterns and constraints.

This is a clean, focused change that improves the code structure without altering behavior. It's part of a larger effort to prepare the promisor-remote subsystem for future enhancements, particularly around auto-configuration capabilities. The patch has already been reviewed and incorporated into the final version of the series.
