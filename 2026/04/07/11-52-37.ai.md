Security hardening patch in Christian Couder's promisor-remote refactoring series. This patch tightens validation of advertised promisor remotes by rejecting empty names and URLs at parse time, rather than later in the configuration handling.

The change modifies `parse_one_advertised_remote()` in `promisor-remote.c` to check for both NULL and empty strings (via `!*info->name` and `!*info->url`). While Git already ignores such remotes during configuration, this early rejection provides defense-in-depth against buggy or malicious servers advertising invalid remotes. The warning message is updated to clarify that the invalid remote is being ignored.

This is a focused security improvement that maintains all existing functionality while making the code more robust. The patch is part of a larger effort to prepare the promisor-remote subsystem for future auto-configuration features, with this change specifically addressing edge cases in remote advertisement parsing. The change is small (2-line diff) but meaningful, and fits well with the series' overall goal of hardening the remote handling code.
