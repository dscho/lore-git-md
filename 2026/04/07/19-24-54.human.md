This is a discussion about `git archive --prefix` path handling, continuing an RFC thread. Jeff King (Peff) responds to Pushkar Singh's questions about whether Git should validate or normalize paths passed to `--prefix`, which currently accepts absolute paths ("/") and parent references ("../") verbatim.

Peff notes that while tar normally warns about these paths, they can be useful in some cases (with tar's `-P` flag). He observes that the behavior appears intentional but undocumented, and that while some normalization (like collapsing multiple slashes) might be harmless, completely disallowing parent references could break existing use cases. The discussion remains exploratory, with Peff leaning toward documenting the current approach rather than changing behavior.

The exchange highlights Git's general philosophy of deferring to tools for path handling while acknowledging that clearer documentation could help users understand the current behavior. No concrete changes are proposed yet, but the thread suggests documentation improvements may be warranted for this edge case.
