This is a follow-up in the `git fast-export` output ordering bugfix thread. Raymond E. Pasco responds to Junio C Hamano's question about why this issue wasn't caught earlier, clarifying that while the original case involved a directory symlink being converted to a real directory, the core problem is actually about path prefixes and doesn't depend on symlinks.

The key technical point is that `fast-import` processes commands strictly in the order they're received, without any special handling for path prefixes - it's the exporter's responsibility to ensure deletions come first when needed. This confirms the earlier patch's approach of fixing the ordering in `fast-export` is correct. The symlink case was a red herring; the fundamental issue is about path prefix relationships between deletions and additions.

The response strengthens the case for the proposed fix by showing `fast-import` has no compensating logic that might have masked the issue, addressing one of Junio's concerns from the previous email. This leaves the thread waiting primarily for resolution of the architectural question about whether `depth_first()` is the right place for the fix.
