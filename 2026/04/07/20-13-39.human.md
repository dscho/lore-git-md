Feature patch proposing a policy-based approach for preserving change-IDs during commit operations. Nico Williams builds on Junio Hamano's acknowledgment that project-enforced metadata policies (like Signed-off-by) could extend to change-IDs, suggesting a concrete framework where upstream projects define policies for handling these identifiers during splits, squashes, cherry-picks and rebases. The proposal involves named hooks for metadata transformation, keeping execution safe by requiring local installation.

Nico agrees with Junio that commit message trailers (visible in `git log`) may be preferable to headers for this metadata, suggesting hooks could extract change-IDs from messages. The email advances the discussion by moving from philosophical debate to a workable mechanism, though it still doesn't address Phillip Wood's three test scenarios. The tone suggests potential consensus forming around project-configurable policies rather than core Git changes, with implementation details now the main open question. This represents progress from the earlier stalemate between header versus trailer approaches.
