Security hardening patch in Christian Couder's promisor-remote refactoring series. This is patch 4/10 in a well-structured set of changes preparing for future auto-configuration of promisor remotes via URL allowlist.

The patch tightens validation in `parse_one_advertised_remote()` to reject empty names and URLs in advertised promisor remotes, not just NULL values. This guards against buggy or malicious servers that might send malformed remote advertisements. The change is minimal (just two additional checks) but important for security hardening, as empty strings could potentially bypass existing NULL checks while still being invalid configurations.

The patch maintains consistency with the project's existing behavior - `promisor_config_info_list()` already ignores remotes with empty URLs, so this just moves the validation earlier in the parsing process. The warning message (which was improved in a later patch in the series) clearly indicates when such invalid remotes are ignored.

This is a straightforward, focused improvement that fits well with the series' broader goals of making promisor remote handling more robust. The change has already been reviewed and iterated on, with Patrick Steinhardt and Junio Hamano having signed off on the approach.
