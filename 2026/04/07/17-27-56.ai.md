This is a follow-up discussion about a documentation improvement in Christian Couder's promisor-remote refactoring series. The patch (03/10) aims to make warning messages clearer when Git ignores invalid promisor remote configurations by explicitly stating that the remote is being ignored.

Junio Hamano suggests improving the message formatting to put the most important information (the action being taken) first, followed by the reason. He provides a concrete example showing how to rephrase one of the messages from "no or empty URL advertised for remote, ignoring this remote" to "ignoring remote that advertises no usable URL". This follows the principle of leading with the consequence rather than burying it after technical details.

The discussion focuses purely on message wording and doesn't raise any technical concerns about the underlying functionality. Junio's feedback is about optimizing the user experience by making the messages more immediately understandable, particularly for cases where a promisor remote is being ignored due to configuration issues. The suggested change maintains all existing behavior while improving clarity.

This exchange shows the maintainer's attention to detail in user-facing messaging, even in what might seem like minor warning text. The feedback is constructive and specific, offering a clear alternative formulation that follows Git's general principle of putting the most important information first in error and warning messages.
