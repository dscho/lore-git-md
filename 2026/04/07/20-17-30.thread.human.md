This thread addressed a segfault in Git's object database (ODB) transaction interface that occurred when running `git diff` outside a repository on large files (exceeding core.bigFileThreshold). The bug was introduced by commit ce1661f9da, which caused `index_fd()` to incorrectly attempt ODB transactions in non-repository contexts where only object hashing should occur.

Justin Tobler identified the issue and proposed a fix that cleanly separates the hashing-only and object-writing paths in `index_fd()`, introducing a new `hash_blob_stream()` helper for non-repository cases. Jeff King (Peff) reviewed the solution, suggesting test improvements that Junio Hamano incorporated while confirming the core fix was sound. The fix has been verified across multiple Git versions, with backports to maintenance branches (2.52, 2.53) alongside the master branch update.

Junio has coordinated with Justin to handle integration with Justin's larger `jt/odb-transaction-write` topic (currently in `seen`). The plan is to first apply this standalone fix to `next` and `master` as an immediate solution, then let the full topic supersede it while preserving the regression test. With all technical aspects resolved and the final merge pending, this thread demonstrates effective collaboration between contributor, reviewer, and maintainer to address a subtle but important edge case in Git's object handling.
