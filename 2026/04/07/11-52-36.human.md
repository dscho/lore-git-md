This is part of Christian Couder's 10-patch series refactoring promisor-remote handling, specifically focusing on improving warning messages when invalid remotes are encountered. Patch 3/10 makes the warning messages more explicit by clearly stating when a remote is being ignored due to invalid configuration.

The changes modify `promisor-remote.c` to append "ignoring this remote" to warning messages in two scenarios: when a remote has no URL or an empty URL, and when a remote's advertised URL doesn't match its configured URL. A third case is added for when the server advertises a promisor remote without a name or URL. The patch maintains all existing functionality while making the system's behavior more transparent to users.

This is a straightforward documentation improvement within a larger technical series. The changes are clean and focused, with clear commit messages explaining the modifications. As part of the broader promisor-remote refactoring effort, this patch helps set the stage for future auto-configuration features by ensuring users understand when and why remotes are being ignored.
