This is a follow-up to the fsmonitor Linux implementation patch series, specifically addressing test coverage for the known incompatibility between split-index and index.skipHash. Junio Hamano notes that the current patch (which disables GIT_TEST_SPLIT_INDEX in t9210 scalar clone tests) should likely be extended to t9211 as well, since the same conflict exists there.

The issue stems from how index.skipHash (a Scalar default) leaves the shared index with a null OID, which then triggers a BUG() in fsmonitor when re-reading the index. The proposed solution follows an existing pattern seen in test 16 of the same file. Junio provides a test script snippet showing the various GIT_TEST_* variables that would need similar handling in t9211.

This is a straightforward test adjustment that maintains consistency with the maintainer-approved approach for handling this known limitation. The exchange demonstrates careful attention to test coverage across the entire test suite as part of the broader fsmonitor implementation effort.
