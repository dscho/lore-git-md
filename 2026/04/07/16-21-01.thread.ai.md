RFC discussion about `git archive --prefix` path handling behavior, initiated by Pushkar Singh. Core question is whether Git should normalize absolute paths ("/"), parent references ("../"), and multiple slashes ("////") in archive output paths or pass them verbatim to underlying tools. Jeff King (Peff) provided technical context: tar/zip tools typically warn about or strip such paths by default but can allow them (e.g., tar's `-P` flag), noting these patterns have legitimate uses despite security risks with untrusted input. brian m. carlson adds that POSIX technically allows `//` to differ from `/` (relevant only for Windows/Interix) and confirms multiple slashes are usually typos, while absolute paths have valid deployment use cases like `/etc`. Junio C Hamano (maintainer) concurs with these assessments, confirming the current behavior is likely intentional given lack of prior discussion and that multiple slashes are effectively harmless. All agree documentation could be improved to clarify this behavior while maintaining readability. Junio explicitly invites documentation patches ("Patches welcome") while indicating the behavior itself won't change, upholding Git's philosophy of deferring path policy to archive tools. No technical changes proposed; thread appears headed toward documentation update as sole outcome.
