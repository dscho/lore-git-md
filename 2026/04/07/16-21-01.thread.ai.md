RFC discussion about `git archive --prefix` path handling behavior, initiated by Pushkar Singh. Core question was whether Git should normalize paths ("/", "../", "////") in archive output or pass them verbatim. Consensus from Jeff King (Peff), brian m. carlson, and Junio C Hamano confirmed current behavior is intentional: Git passes paths unmodified while archive tools (tar/zip) may warn or adjust them. Peff noted legitimate uses for absolute paths despite security risks with untrusted input, while brian m. carlson clarified POSIX edge cases around `//`. Junio indicated behavior won't change but invited documentation improvements.

Pushkar Singh has now submitted a documentation patch implementing the agreed clarification. The patch updates the `git-archive` man page to explicitly state that `--prefix` uses paths verbatim without normalization, noting downstream tools may handle special paths differently. The wording matches the technical consensus while maintaining Git's philosophy of deferring path policy to archive tools. Patch is small, focused, and uncontroversial - exactly the outcome anticipated from the RFC discussion. All open questions from the thread are now addressed by this documentation update. Key participants aligned: Pushkar (question and patch), Peff and brian m. carlson (technical context), Junio (maintainer confirmation). No further action expected unless documentation feedback arises during review.
