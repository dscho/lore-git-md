Thread identity: UX proposal regarding "up to date" message in `git checkout`, originating from Jesko Schwarzer as a first contribution.

Core problem: The current "Your branch is up to date with 'origin/master'" message compares against the local remote-tracking ref rather than the actual remote state, which can mislead users into thinking their branch matches the true upstream when it may be stale.

Key technical details: Message originates in `builtin/checkout.c`, compares local branch HEAD against remote-tracking ref (e.g. refs/remotes/origin/master) without network access. Current behavior is by design to avoid implicit fetches. Maintainer Junio C Hamano has confirmed openness to clarifying the message wording while respecting this constraint.

Proposed solutions:
1. Clarify wording to indicate comparison is against locally cached ref (explicitly endorsed by Junio)
2. Optionally include context about ref staleness (last fetch time) - noted as potentially acceptable if metadata is available

Current status: Maintainer has greenlit the general approach. Ben Knoble has surfaced relevant context about prior discussions on recording fetch-time metadata that could inform implementation of option #2, though the specific thread reference remains to be located. The path remains clear for immediate work on the simpler message clarification (option #1) while the metadata questions are explored separately.

Open questions: Specific wording choices for the core message clarification. Technical feasibility of incorporating staleness indicators given the need to either (a) locate existing fetch-time recording mechanism or (b) propose new metadata storage. No technical objections raised yet to either approach.
