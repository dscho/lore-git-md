This is a documentation RFC about the `git archive --prefix` behavior with unusual path inputs.

Pushkar Singh observes that `git archive` passes through absolute paths and parent directory references (`/`, `////`, `../../`) in the `--prefix` option exactly as given, which can trigger warnings from `tar` about removing leading slashes or `../` components. The email asks whether this behavior is intentional, whether it should be documented more clearly, and whether Git should normalize these paths itself rather than relying on the archive tool to handle them.

The question touches on Git's general philosophy of avoiding policy decisions where possible, leaving interpretation to downstream tools. The email is framed as seeking clarification rather than proposing a specific change, suggesting the author is still exploring whether this warrants any action. This appears to be a genuine inquiry from someone who noticed potentially surprising behavior while working with the command. The thread may attract input from archive and filesystem experts about whether the current behavior is correct or could be improved.
