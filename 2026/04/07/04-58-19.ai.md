Nico Williams responds to Junio Hamano's skepticism about the claimed consensus around change-id headers by proposing a more configurable approach.

Nico acknowledges Junio's concerns about semantic consistency, particularly around operations like commit splitting and differences between rebase/cherry-pick behaviors. He suggests making header preservation behavior configurable per operation type (rebase, cherry-pick, etc.) with different defaults for each, while still keeping the header format itself opaque to Git. The proposal introduces hooks that would allow custom transformation logic when headers need to be modified during complex operations.

The email also floats the idea of an `original-change-id` header to track commit lineage, though the interaction with existing change-id headers isn't fully specified. Nico recognizes the risk of over-complicating the configuration but believes the flexibility would prove useful in practice. The discussion remains in the design phase, with core questions about Git's role in supporting external tool workflows still unresolved.
