This is a feature patch that preserves the 'change-id' header during rebase, cherry-pick, and amend operations. The change addresses a common need among tools like Gerrit, GitButler, and Jujutsu that use change IDs to track commits across rewrites.

The patch modifies the sequencer code to detect and carry forward any existing 'change-id' header when performing operations that rewrite commits. It adds tests verifying the header preservation in three scenarios: rebase, cherry-pick, and amend. The implementation is intentionally format-agnostic, preserving whatever change-id format was originally present rather than enforcing a standard.

The change is well-motivated by real-world tooling needs and appears carefully implemented with thorough test coverage. The author notes there's prior discussion about standardizing the format but deliberately avoids that larger question, focusing instead on the narrower compatibility improvement. This seems like a pragmatic approach that solves an immediate pain point without precluding future standardization.
