This is a user experience (UX) proposal regarding the "up to date" message shown during `git checkout`. The author, Jesko Schwarzer, points out that the current message "Your branch is up to date with 'origin/master'" can be misleading because it compares against the local remote-tracking ref (origin/master) rather than the actual remote state. The message remains "up to date" even if the remote has new commits that haven't been fetched yet.

The proposal suggests either clarifying the wording to explicitly mention the comparison is against the local cached ref, or optionally including context about how stale the remote-tracking ref might be (e.g. last fetch time). The author acknowledges Git's design of avoiding implicit network access but argues the current phrasing could be clearer about what "up to date" actually means.

This appears to be a well-articulated first contribution from a user perspective, highlighting a potential point of confusion that many users likely encounter. The proposal is focused and offers concrete suggestions while respecting Git's existing design constraints. The change would affect the user-facing output in `builtin/checkout.c` and related documentation.
