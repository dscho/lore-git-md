This is a test failure report from Randall Becker about a pre-receive hook test case that's unexpectedly failing in Git 2.54.0-rc0. The test in question is t5401.13 ("pre-receive hook that forgets to read its input"), which creates 900 branches and attempts to push them to a repository with a pre-receive hook that exits successfully without reading its input.

The test expects the push to succeed since the hook exits with status 0, but instead gets hundreds of "remote rejected" messages for each branch reference. The output shows the hook is declining every single branch push (from branch_100 through branch_999), which suggests either a regression in how Git handles pre-receive hooks that don't consume their input, or possibly a platform-specific issue on NonStop systems.

Randall Becker, who maintains the NonStop port of Git, is reporting this as he encounters it during testing of the 2.54.0 release candidate. The test failure appears to be related to hook behavior rather than NonStop-specific code, making it potentially relevant to all platforms. The issue could affect any workflow relying on pre-receive hooks that exit early without processing all reference updates.

- Test file: t/t5401-update-hooks.sh

- Hook type: pre-receive

- Actual behavior: push fails with all refs rejected
- Platform where observed: NonStop (though may not be platform-specific)
