This thread explores how `git archive --prefix` handles special path components like absolute paths ("/"), parent references ("../"), and multiple slashes ("////"). Pushkar Singh initiated the discussion by questioning whether Git should normalize these paths. Jeff King (Peff) provided key technical context, explaining that while tar/zip tools typically warn about or strip such paths by default, they can be allowed (e.g., with tar's `-P` flag), and there are legitimate use cases for them. Junio Hamano confirmed this behavior is likely intentional, aligning with Git's philosophy of deferring path policy to archive tools, and invited documentation improvements.

brian m. carlson has now added further context, noting that absolute paths have valid uses (like deploying to `/etc`) and that some users want repository support for multiple roots. They also clarified that while POSIX technically treats `//` differently from `/`, this mainly matters on Windows and Interix systems. The thread has converged on keeping the current permissive behavior while potentially improving documentation to clarify it. No technical changes are proposed, and the discussion appears settled, with Junio's earlier "patches welcome" for documentation being the likely next step if anyone chooses to take it.
