This thread discusses the behavior of `git archive --prefix` when given unusual path inputs like absolute paths ("/") or parent directory references ("../../"). Pushkar Singh initiated the discussion with an RFC, noting that Git currently passes these paths through verbatim to the archive tool (like tar) without any normalization.

The key questions raised are whether this behavior is intentional, whether it should be better explained in the documentation, and whether Git should perform any path validation itself. The discussion touches on Git's general philosophy of avoiding policy decisions where possible, while considering whether basic path sanitization might be warranted in this case. So far the thread is exploratory, seeking to understand the current design rather than proposing specific changes.
