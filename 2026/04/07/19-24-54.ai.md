This is a discussion about path handling in `git archive --prefix`, continuing an RFC thread started by Pushkar Singh. Jeff King (Peff) responds to questions about whether Git should validate or normalize paths containing absolute references ("/") or parent directory components ("../").

Peff notes that while tar and zip tools typically warn about or strip such paths by default, they can be explicitly allowed (with tar's `-P` flag). He observes that absolute paths and parent references can be useful in some cases, though potentially dangerous with untrusted input. Multiple slashes ("////") are mostly harmless but could theoretically be normalized.

The response suggests documenting the current behavior more clearly while expressing hesitance to change the implementation, since: (1) the behavior hasn't been problematic enough to generate prior discussion, and (2) some users may rely on the current permissive handling. Peff leaves the door open for documentation improvements that don't make the existing docs harder to read.

The exchange highlights Git's general philosophy of deferring to tools for policy decisions while maintaining awareness of potential security implications. The thread remains exploratory rather than prescriptive, with no immediate changes proposed beyond possible documentation clarifications.
