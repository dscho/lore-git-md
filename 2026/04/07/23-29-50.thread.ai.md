Thread identity: Test failure report for Git 2.54.0-rc1 regarding `--git-dir` option issues and `writev()` problems in bitmap-related operations, reported by Randall S. Becker (NonStop platform maintainer) with analysis from Jeff King.

Core problem: Two distinct issues causing test failures in bitmap-related operations (t5310, t5326, t5327) on NonStop platform:
1. Initial confusion around "not a git repository" errors when using `git --git-dir=clone.git` in test t5310 (now confirmed as secondary to the main issue)
2. Primary issue: Network protocol errors during cloning from bitmapped repositories in tests t5326/t5327, traced to `writev()` implementation in `sideband_send()`, with NonStop reporting "Invalid function argument" for socket operations

Current status: Regression in release candidate 2.54.0-rc1 affecting bitmap functionality. Jeff King's analysis and Randall's follow-up confirm:
- The `--git-dir` issue was a red herring caused by earlier `writev()` failures
- The network errors stem from NonStop's `writev()` implementation rejecting vectorized writes on network sockets
- Workaround available via `NO_WRITEV=Nope` build flag (not yet tested in this thread)

Key technical details: Failures involve:
- `writev()` failures in `sideband_send()` during network operations (t5326/t5327)
- Specific error "Invalid function argument" on NonStop platform
- Test files t5310, t5326, t5327 (bitmap-related functionality)
- Recent introduction of `writev()` optimization in sideband code
- Socket/file descriptor type handling differences on NonStop

Open questions:

Participant positions:
