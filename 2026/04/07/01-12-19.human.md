This is a bugfix for `git fast-export` that addresses a long-standing issue with path ordering in the export stream. Raymond E. Pasco follows up on Junio C Hamano's questions about why this problem wasn't caught earlier, confirming that the issue stems purely from path prefixes rather than symlink handling as initially suspected.

The key insight is that `fast-import` processes commands in strict order without any hidden logic to reorder operations, placing the responsibility on `fast-export` to emit deletions before additions when paths have prefix relationships. This matches the behavior seen in similar fixes for `git checkout` and `git am`.

The patch appears well-motivated and technically sound, with consensus forming around the deletion-first approach. While Junio raised valid architectural questions about function placement, the core solution seems uncontroversial. This fix closes a subtle but important gap in `fast-export`'s output correctness that has persisted through multiple prior discussions over nearly a decade.
