This is the first patch in Christian Couder's 10-part series refactoring promisor-remote handling, focusing on changing the priority order for fetching from promisor remotes. The patch introduces a behavioral change where accepted promisor remotes (those advertised by the server and accepted by the client) are now tried before other configured promisor remotes when fetching missing objects.

The key technical change is the extraction of a new `try_promisor_remotes()` helper function that implements the fetching logic with an `accepted_only` parameter. `promisor_remote_get_direct()` now calls this helper twice - first with `accepted_only=true` to try only accepted remotes, then with `false` to fall back to others. This ensures server-advertised remotes are prioritized as intended by the protocol.

The patch includes comprehensive tests in `t5710-promisor-remote-capability.sh` that verify the new priority ordering works correctly in both clone and fetch scenarios. The tests specifically check that accepted remotes are contacted before non-accepted ones, regardless of their order in the config file. Documentation is also updated to clarify this behavior in `gitprotocol-v2.adoc`.

This change lays groundwork for future auto-configuration of promisor remotes by ensuring server-suggested remotes will be tried first. The implementation is clean and well-tested, with clear separation of concerns between the new helper function and the modified main logic. The patch touches core promisor-remote functionality in `promisor-remote.c` while maintaining backward compatibility.
