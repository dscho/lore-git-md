This is a refactoring patch in Christian Couder's series on promisor-remote handling. It extracts control character checking logic into a new `has_control_char()` helper function, which will be reused in future changes. The patch maintains the same behavior while making the code more modular and readable.

The existing `valid_token()` function, which warns about control characters in remote tokens, now delegates to the new helper. This is a straightforward cleanup with no functional changes - the warning messages and validation logic remain identical. The patch is part of a larger effort to prepare the promisor-remote subsystem for URL-based auto-configuration.

The change is well-contained, touching only `promisor-remote.c`, and follows the series' pattern of incremental improvements. Given the positive feedback on earlier patches and the mechanical nature of this refactoring, it appears uncontroversial and ready for merging.
