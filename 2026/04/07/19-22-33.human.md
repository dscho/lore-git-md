Progress reporting refinement for `git backfill`.

This is a follow-up in the thread about adding progress reporting to the experimental `git backfill` command. Trieu Huynh responds to Junio C Hamano and Derrick Stolee's feedback on the initial patch, confirming plans to address their concerns in v2.

The key changes coming in the next version will switch from tracking batch counts to tracking individual objects in the progress meter, which provides more meaningful feedback during long operations. Huynh also acknowledges the need to adjust the increment operator style, moving from pre-increment to post-increment for struct member updates to match Git's coding conventions.

The tone is cooperative and responsive - Huynh clearly understands the feedback and is implementing the requested changes. This thread shows the typical Git patch refinement process in action, where maintainers and contributors work through implementation details to reach a solution that meets the project's standards. With these changes, the progress reporting feature appears on track for inclusion.
