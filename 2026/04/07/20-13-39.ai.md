Feature patch discussion about preserving change-ids during commit operations, with evolving consensus around policy-based approaches.

Nico Williams responds to Junio C Hamano's latest position on handling change-ids during rebase, cherry-pick, and amend operations. The exchange shows movement toward potential agreement on a policy-based approach where upstream projects could define rules for change-id handling, similar to how some projects enforce Signed-off-by trailers. Nico proposes a concrete strawman design involving project-defined policies and hooks that would handle change-id transformations during various operations (splits, squashes, cherry-picks, rebases).

The key technical elements in Nico's proposal include: project-published policies for change-id handling, named hooks for safe local execution, and new options for providing context during cherry-picks and rebases. He suggests pushing all semantic decisions to hooks and policies, leaving only generic operation-to-hook mappings to be standardized in Git itself. While Junio continues to prefer keeping this metadata in commit message trailers rather than headers, Nico acknowledges this could work if accompanied by hooks for extracting change-ids from messages.

This email advances the discussion by offering a specific implementation path that addresses both technical needs and security concerns (via the named hooks approach). The proposal attempts to bridge the gap between Junio's preference for trailer-based metadata and the workflow requirements of tools like Gerrit and GitButler. However, it still leaves open how exactly the hooks would handle Phillip Wood's three key scenarios, and whether the community will converge on this policy-based direction versus more direct core integration.
