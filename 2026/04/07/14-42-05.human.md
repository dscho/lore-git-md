This is a design discussion about preserving 'change-id' headers during commit rewriting operations, continuing a thread about supporting tools like Gerrit and Jujutsu. Junio Hamano responds to Nico Williams' proposal for configurable header preservation by suggesting Git notes/trailers as an alternative approach that would keep metadata separate from commit messages.

Junio acknowledges Nico's point about cherry-pick and rebase potentially having different default behaviors for header propagation, noting that this makes sense given their distinct purposes - rebase as a rewriting operation versus cherry-pick as a duplicating one. However, he argues that Git's existing notes/trailers mechanism could handle all the proposed use cases without needing to modify core commit-rewriting logic.

The email highlights the philosophical divide in the thread: whether Git should natively support external tool metadata (Nico's position) or maintain workflow neutrality by keeping such metadata in separate systems like notes/trailers (Junio's position). Junio suggests the trailers framework, while perhaps currently limited, provides enough infrastructure to build custom solutions without special-casing change-ids in Git's core.

This response represents a significant counterproposal to the earlier configurable approach, shifting the discussion toward whether notes/trailers can satisfy the requirements while maintaining Git's traditional separation of concerns. The thread remains in design phase with no clear resolution yet on which direction will better handle Phillip Wood's identified test cases (cherry-picks, commit splitting, and squashing).
