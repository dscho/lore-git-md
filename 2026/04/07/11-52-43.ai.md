This is the final patch in Christian Couder's 10/10 series refactoring promisor-remote handling, focusing on test improvements for cross-platform URI compatibility. The patch addresses Windows-specific URI formatting issues in the test suite while maintaining existing test coverage.

The key change ensures test scripts generate RFC 8089-compliant `file://` URIs by properly handling absolute paths across platforms. On Windows, paths like `D:/foo` are converted to `/D:/foo` to form valid 3-slash URIs. The patch introduces `$TRASH_DIRECTORY_URL` and `$ENCODED_TRASH_DIRECTORY_URL` helper variables to consistently handle path encoding throughout the test script.

The changes include safety checks to skip tests if the path contains unsupported special characters, and updates all test cases to use the new URI helpers instead of raw `file://$(pwd)` constructs. This affects multiple test scenarios including clone operations with various promisor configurations (`acceptfromserver=All/None/KnownName/KnownUrl`), fetch operations, and field verification tests.

The patch demonstrates careful attention to cross-platform compatibility and future-proofing, particularly for upcoming changes that will pass these URIs through normalization functions. It maintains all existing test assertions while making the test infrastructure more robust. The changes are well-contained to the test script (`t/t5710-promisor-remote-capability.sh`) with no impact on production code.
