This is a feature patch that preserves the 'change-id' header during rebase, cherry-pick, and amend operations. The change addresses a common need among tools like Gerrit, GitButler, and Jujutsu that use this header to track commits across rewrites.

The patch modifies the sequencer to detect and carry forward any existing 'change-id' header when performing operations that rewrite commits. It includes tests verifying the header preservation in rebase, cherry-pick, and amend scenarios. The implementation is intentionally format-agnostic - it preserves whatever change-id format was originally present rather than enforcing a specific standard.

This seems like a pragmatic solution that provides immediate value without precluding future standardization efforts.
