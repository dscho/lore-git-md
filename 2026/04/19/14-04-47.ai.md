Performance optimization review for `git cherry` prefetching in partial clones.

Phillip Wood raises a substantive review point about potential code sharing between the new `prefetch_cherry_blobs()` function and the cherry-pick detection logic in `revision.c`. He notes that `git rebase` without `--reapply-cherry-picks` performs similar cherry-pick detection and could benefit from the same prefetch optimization.

The review identifies a clear opportunity to generalize the prefetch logic beyond just the `git cherry` command. Phillip's observation suggests the current implementation might be too command-specific when the underlying issue (inefficient blob fetching during cherry-pick detection) affects multiple code paths. This is the kind of architectural consideration that often surfaces during review but might be missed in initial implementation.

The review doesn't propose specific changes but raises an important design question about where this functionality should live - whether it should remain in `builtin/log.c` or be moved/shared with `revision.c`. This could impact how the optimization gets applied to other commands like `git rebase`.

No technical flaws are identified in the current implementation - the review focuses purely on the broader applicability of the optimization. The author will need to decide whether to address this in the current series or follow up separately.
