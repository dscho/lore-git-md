This is a review response in the ongoing thread about Patrick Steinhardt's proposal to move libgit.a sources into a dedicated "lib/" directory. Phillip Wood offers a substantive review that engages with the technical merits while questioning some of the claimed benefits.

Phillip supports the reorganization conceptually, agreeing it makes sense to group library code together, particularly for enforcing coding conventions like avoiding `the_repository` and preferring `error()` over `die()`. However, he pushes back on the discoverability argument, noting that moving files into a subdirectory doesn't inherently make them easier to find - developers will still need to use tools like `git grep` or ctags regardless of the directory structure.

The review highlights an important distinction between the mechanical benefits (clearer separation of library vs non-library code) and the human factors (whether the change actually improves code navigation). Phillip's perspective as an experienced contributor carries weight here, suggesting the discoverability claims may be oversold even if the structural change is worthwhile.

This feedback doesn't raise any blocking concerns but does provide useful reality check on one of the proposal's key motivations. The review is substantive but not tested - Phillip is evaluating the concept rather than reporting on having built or used the modified layout. His comments align with the thread's generally positive reception while adding thoughtful nuance about the claimed benefits.
