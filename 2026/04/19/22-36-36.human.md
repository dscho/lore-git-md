This is a review of a feature addition to `git rev-list` that introduces a `--missing=print-only` mode for partial clone workflows. Derrick Stolee provides feedback on Siddharth Asthana's patch, which aims to simplify output processing by emitting only missing object IDs without the '?' prefix.

Stolee expresses general support for the feature ("I'm a fan of this mode") as it reduces I/O processing overhead, but raises several technical concerns:

1. **Code style**: Questions the spacing adjustments in the enum comments, noting the existing inconsistency with MA_ALLOW_PROMISOR but suggesting the new MA_PRINT_ONLY could maintain the original alignment.

2. **Implementation details**: Suggests combining the OID and line terminator output into a single printf() call for efficiency.

3. **Option interactions**: Expresses concern about the multiple special cases needed to handle the new mode's interaction with other rev-list options (count, disk-usage). Proposes either documenting these interactions clearly or adding warnings about incompatible combinations.

4. **Documentation**: Notes the patch is missing updates to the command documentation to explain the new mode's behavior and limitations.

The review is substantive, engaging with both the technical implementation details and broader design considerations. Stolee identifies real potential issues (particularly around option interactions) while remaining constructive. His feedback suggests the patch needs refinement before merging, particularly around documenting the new behavior and its constraints.
