The thread has reached consensus on adding a `--missing-only` flag to `git rev-list` to support partial clone workflows, particularly for GitLab's Gitaly service. After substantive technical reviews from Derrick Stolee, Patrick Steinhardt, and Phillip Wood, the author Siddharth Asthana has settled on a clean flag-based design rather than extending the existing `--missing` enum.

In the latest update, Siddharth confirms he will implement Phillip Wood's suggestions to use direct OID file comparison in tests (replacing multiple `grep` calls with `test_cmp` for better efficiency and diagnostics) and is considering whether to require explicit `--missing=print` alongside `--missing-only` for clarity. All reviewers agree the flag-based approach is more orthogonal and self-documenting.

The implementation details are now finalized: the flag will be incompatible with `--count` and `--disk-usage` (with clear error messages), helper functions will be renamed, and documentation will cover the new semantics. With the design settled and all substantive feedback addressed, the thread awaits the revised v2 patch series to complete this useful addition for partial clone workflows.
