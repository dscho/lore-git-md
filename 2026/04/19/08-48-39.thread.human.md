This thread implements a new `--missing-only` option for `git rev-list`, designed to streamline GitLab's Gitaly workflow for partial clones. The feature allows users to list only missing object IDs in a single command, eliminating the need for post-processing to strip prefixes or filter out present objects. This is particularly useful for GitLab's transaction packing process, where missing objects are recorded as dependencies rather than fetched immediately.

The implementation is complete and approved, with Junio C Hamano providing final sign-off after the commit message was updated to clarify the Gitaly workflow. The patch introduces the `--missing-only` flag, which works alongside existing `--missing=print` and `--missing=print-info` options to filter output while preserving their formatting. Key technical details include a new helper function `should_collect_missing()`, comprehensive test coverage, and clear error messages for incompatible options like `--count` and `--disk-usage`.

Reviewers including Derrick Stolee, Patrick Steinhardt, Phillip Wood, and Kristoffer Haugsbakk endorsed the design, which cleanly separates filtering (`--missing-only`) from formatting (`--missing=`). The feature is now queued for the `next` branch, with no further code changes expected. All open questions about workflow and design have been resolved, and the implementation is ready for integration.
