This thread centers on adding a `--missing-only` flag to `git rev-list` to better support partial clone workflows, particularly for GitLab's Gitaly service. The discussion has evolved through several design iterations, with initial proposals using an enum extension (`--missing=print-only`) giving way to the current consensus around a simpler flag-based approach.

Key participants include Siddharth Asthana (the patch author), Derrick Stolee, Patrick Steinhardt, Phillip Wood, and Kristoffer Haugsbakk. The technical debate has largely settled on making `--missing-only` a separate flag that filters output to show only missing objects, distinct from the existing `--missing=` enum that controls how missing objects are formatted. This separation of concerns addresses earlier objections about mixing output formatting and filtering logic.

Derrick Stolee's latest review reinforces this direction, dropping his earlier suggestion about printf/putchar consolidation and strongly endorsing Phillip Wood's simpler design. The thread has also clarified documentation needs, with agreement that v2 should explicitly document option interactions and incompatibilities (like `--count` and `--disk-usage`).

With no outstanding technical objections, the path forward is clear: Siddharth will send a v2 implementing `--missing-only` as a standalone flag, with improved tests using direct OID comparison and comprehensive documentation. The feature's utility for GitLab's needs remains uncontested, and the refined design better accommodates potential future extensions while keeping the current change focused.
