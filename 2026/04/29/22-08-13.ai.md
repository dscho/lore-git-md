This is the fourth patch in a six-part refactoring series improving type safety and clarity in xdiff's record cleanup logic. The series has gone through multiple iterations incorporating feedback, with this version implementing final suggestions from Phillip Wood.

The patch focuses on making the per-file limit calculations in `xdl_cleanup_records()` more explicit and easier to follow. Key changes include:

1. Introducing separate limit variables (`mlim1` and `mlim2`) for each file being processed, rather than reusing a single `mlim` variable. This makes the code's intent clearer when processing each file's records.

2. Removing a redundant `!need_min` condition that was made unnecessary by earlier changes in the series. The logic now cleanly separates the minimal case (where limits are effectively infinite) from the non-minimal case (where limits are calculated based on record counts).

3. The limit initialization is now more clearly structured with explicit conditionals for the minimal vs. non-minimal cases, improving readability.

The changes are purely internal refactoring with no behavioral impact, continuing the series' focus on code quality improvements. The patch maintains all the type safety improvements from previous versions while making the limit handling logic more transparent. Phillip Wood's review feedback has been fully incorporated, and the changes align with the overall goal of making the xdiff codebase more maintainable.
