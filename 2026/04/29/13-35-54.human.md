This is a review comment on Johannes Schindelin's Windows platform compatibility patch series addressing 4GB+ object handling limitations. The series systematically replaces 32-bit `unsigned long` with 64-bit `size_t` in critical paths to prevent truncation during cloning operations.

Derrick Stolee expresses general approval for the approach, noting it avoids the brute-force "replace all unsigned longs" strategy in favor of more targeted changes. His primary concern is about the performance impact of the new regression tests that verify large object handling - specifically whether generating and testing with 4GB+ blobs should be marked as an expensive test in the main Git project while remaining enabled by default in Git for Windows.

The review is substantive but focused on a single practical consideration (test execution time) rather than engaging with the technical implementation details. Stolee's position as a Microsoft/GitHub engineer with Windows experience lends weight to his platform-specific testing concerns. The exchange reflects the ongoing balancing act between comprehensive platform testing and CI resource constraints in the Git project.
