This is part 2 of a 6-patch refactoring series in the xdiff subsystem, focusing on type safety improvements. The series has gone through multiple iterations with careful review, particularly from Phillip Wood, and appears ready for merging.

This specific patch changes the `xdl_bogosqrt()` function to use `uint64_t` instead of `long` for two reasons: negative numbers don't have real square roots (making the unsigned type more semantically appropriate), and `size_t` may not be large enough for some use cases. The change is mechanical but meaningful - it updates the function signature and all call sites to use the new type, with appropriate casts where needed.

The patch is part of a larger effort to improve type safety in xdiff's record cleanup logic, building on previous work that was merged but then found to cause a regression (now fixed). The changes are purely internal with no behavioral impact, just clearer and more robust type usage. Given the careful review history and the straightforward nature of this change, it appears uncontroversial and ready for inclusion.
