This is a review comment from Derrick Stolee on the final patch in Johannes Schindelin's series addressing Windows platform limitations with large objects (>4GB). The review focuses on test execution time rather than the technical content of the patch itself.

Stolee raises two main points about the regression test added in this patch:

1. **CI Pipeline Impact**: He notes the test takes approximately 4 minutes to run in CI pipelines, which is significant overhead for every test run. He suggests this might warrant marking the test as "expensive" (using Git test infrastructure's EXPENSIVE flag) since the code paths being tested are unlikely to change frequently.

2. **Platform Considerations**: While acknowledging the SIZE_T_IS_64BIT prerequisite properly excludes 32-bit builds, Stolee suggests different handling might be appropriate between the main Git project and Git for Windows - keeping the test always-enabled in Git for Windows where the fix matters most, while making it optional in upstream Git.

The review doesn't engage with the technical correctness of the patch (which had already been established in previous iterations) but rather focuses on practical considerations around test execution. Stolee also raises a broader question about Git's release validation process regarding when expensive tests should be run.

This is a surface-level review that doesn't address the patch's technical content but provides useful feedback about test suite ergonomics.
