This is a bug report about `git maintenance`'s error handling when dealing with unavailable remotes. The issue occurs when running maintenance tasks on repositories where one of the remotes is no longer accessible - the prefetch task fails with a generic error message that doesn't identify which remote caused the problem, and the entire maintenance run aborts rather than continuing with other remotes.

The reporter, Anselm Schüler, suggests two improvements: (1) making the error message identify the problematic remote, and (2) having the prefetch task continue with other remotes even if one fails. They also note that when using `git-for-each-repo` (as their systemd timers do), it would be helpful to identify which repository encountered the error.

The report is clear and well-motivated, describing a real usability pain point for users with multiple remotes. The proposed changes seem reasonable and focused. The reporter indicates they might be willing to contribute a patch if the suggestions are accepted. This looks like a straightforward quality-of-life improvement that shouldn't be controversial.
