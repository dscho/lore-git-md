This thread addresses a regression in `git fetch --deepen` that was introduced in Git 2.54.0, where the command would incorrectly convert full clones into shallow ones, losing commit history. The issue was originally reported by Owen Stephens and affects ARM64 Darwin systems.

After technical review, consensus settled on a fix that modifies `shallow.c` to properly handle non-shallow repositories. René Scharfe reviewed and approved the approach, and Samo Pogačnik has now submitted the final patch implementing this solution. The key change makes `get_shallow_commits()` return NULL for non-shallow repositories, preventing the unwanted shallow conversion. The patch includes a test case that verifies full clones remain unchanged after `fetch --deepen` operations.

With the technical approach validated and the patch now properly formatted with sign-off and test coverage, this longstanding issue appears ready for merging in the next release cycle. The fix maintains the expected behavior where `--deepen` only affects already-shallow repositories while preserving the commit history in full clones.
