This thread addresses a regression in `git fetch --deepen` that caused full clones to incorrectly revert to shallow state when the option was used repeatedly. The core technical fix, implemented by Samo Pogačnik in `shallow.c`, has been reviewed and approved by René Scharfe, resolving the underlying issue where commits were being lost in shallow clones. 

Junio C Hamano raised two final points about the patch's presentation (suggesting `git show` format for references) and whether to warn users when `--deepen` is used on non-shallow repositories. René Scharfe has now responded to the latter, noting that `--deepen` has silently been a no-op on full clones since 2016. He suggests that if a warning were to be implemented, it should be done in the `fetch` command itself rather than in the shallow-handling code, and that this would be a separate change from the current bugfix. 

With the technical solution settled and only minor user experience questions remaining, this patch appears ready for finalization. The discussion has progressed from initial bug report through implementation to these final polish considerations, suggesting it will likely be included in an upcoming release.
