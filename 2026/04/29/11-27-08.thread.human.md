This thread addresses a regression in `git fetch --deepen` introduced in Git 2.54.0, where repeated fetches on a shallow clone (depth=2) would revert the repository to a shallow state, losing previously visible commits. The bug was reported by Owen Stephens and traced to commit 3ef68ff40e, which incorrectly toggled the `is-shallow-repository` flag on ARM64 Darwin systems.

After technical discussion, Samo Pogačnik proposed moving the fix to `shallow.c` to properly handle non-shallow repositories. René Scharfe reviewed the solution, and Samo has now acknowledged the feedback, confirming he will prepare a formal patch submission including commit message and sign-off. While this may take some time, the thread indicates consensus on the fix approach and suggests the issue is nearing resolution after this longstanding bug.
