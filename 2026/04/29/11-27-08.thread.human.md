A bug in Git 2.54.0's `git fetch --deepen` command was causing shallow clones to incorrectly lose previously visible commits when the command was repeated. After initial reports from Owen Stephens and two competing fixes proposed by René Scharfe and Samo Pogačnik, the thread has now reached consensus on the solution.

René has reviewed Samo's approach and endorsed moving the fix from `builtin/fetch.c` to `shallow.c` as architecturally cleaner. The fix ensures `--deepen` properly becomes a no-op in non-shallow repositories by having `get_shallow_commits()` return NULL when there's no existing shallow depth. Some minor formatting cleanup remains before final submission, but the technical approach is now agreed upon.

The regression test added earlier will prevent future occurrences, and while documentation clarifications were discussed, the focus remains on getting the core fix merged. With René's approval of Samo's solution, the maintainer now has clear technical consensus to base the final decision on.
