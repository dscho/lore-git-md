This is a bugfix patch for the `git subtree` contrib script, addressing an issue where re-adding a previously removed subtree at the same path would fail. The problem occurs because the split cache mechanism was too strict about duplicate entries, even when they represented the same mapping.

The patch modifies `cache_set()` to silently succeed when encountering an existing cache entry that already contains the same value being written, rather than treating it as a fatal error. This matches the logical expectation that writing the same mapping twice should be a no-op. The change is accompanied by a new test case that exercises the scenario of adding, removing, and re-adding a subtree at the same path.

The fix is straightforward and well-motivated, with clear commit message explaining both the problem and solution. The test case provides good coverage of the specific failure scenario. This appears to be a solid quality-of-life improvement for users of the subtree script.
