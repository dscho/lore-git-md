This is the third patch in a six-part refactoring series targeting the xdiff subsystem, specifically improving type safety in the record cleanup logic. The series has gone through multiple iterations with careful review, particularly from Phillip Wood, and is now in its final form.

The current patch focuses on making type usage unambiguous in `xdl_cleanup_records()` and its helper function `xdl_clean_mmatch()`. It changes the parameters and local variables from `long` to `ptrdiff_t`, which is the more appropriate type for array indexing and pointer arithmetic operations. The changes are mechanical type safety improvements with no behavioral impact.

Key technical aspects:
- Converts `long` parameters in `xdl_clean_mmatch()` to `ptrdiff_t`
- Changes local variables i, nm, mlim in `xdl_cleanup_records()` to `ptrdiff_t`
- Maintains all existing functionality while improving type safety
- Part of a larger effort to modernize xdiff's internal type usage
- Builds on previous work that addressed a regression in this area

The patch is small and focused, touching only xdiff/xprepare.c. It follows the series' overall goal of making the code more robust while preserving all the non-regressing improvements from earlier versions. The changes align with the project's ongoing efforts to improve code quality and maintainability through careful refactoring.
