**Thread identity** -- Subject: `[PATCH v2] shallow: fix --deepen for non shallow repositories`. Series version: v2 (v1 had a commit reference format issue). Originating author: Samo Pogačnik. Thread type: bugfix patch series.

**Core problem or goal** -- Regression introduced in Git 2.54.0 by commit 3ef68ff40e. On a non-shallow repository, running `git fetch --deepen=<n>` (e.g., `fetch --deepen 2` twice on a shallow clone with depth=2) incorrectly toggles `is-shallow-repository`, truncating history and reverting the repository to a shallow state that loses previously visible commits. Bug originally reported by Owen Stephens. Manifests on ARM64 Darwin systems.

**Current status** -- v2 submitted, pending Junio C Hamano's application. The core fix is settled; v2 is a presentation cleanup (fixing commit reference format per Junio's request from v1 review). No outstanding technical objections.

**Key technical details** -- File modified: `shallow.c`. Function modified: `get_shallow_commits()`. The change: when a relative deepen (`--deepen`) is requested, current code unconditionally adds `cur_shallow_depth` to the requested depth. The fix guards this by checking whether the repository actually has a shallow depth (i.e., whether it is a shallow repo). If the repo is non-shallow (no `cur_shallow_depth`), the function returns NULL, making `--deepen` a no-op on non-shallow repos -- restoring pre-regression behavior. Test file: covers cloning a full repo, capturing shallow status and commit list, running `fetch --deepen=1`, then asserting no changes.

**Open questions and loose ends** -- Junio C Hamano raised the question of whether to warn when `--deepen` is used on non-shallow repos. Junio and Rene Scharfe subsequently agreed: (1) `--deepen` has silently been a no-op on non-shallow repos since its introduction in commit cccf74e2da (2016), (2) any warning implementation belongs in `fetch`, not in shallow-handling code, and (3) warnings are explicitly deferred to a separate, future patch. No action pending on this thread.
