This is a review comment from Derrick Stolee on the final patch in Johannes Schindelin's series addressing Windows platform limitations with large (>4GB) objects. The patch adds regression tests for cloning repositories with large objects, verifying the fixes from previous patches.

Stolee raises a practical concern about the test's runtime impact in CI pipelines, noting that generating the 4GB+ test packfile takes about 4 minutes per run. He suggests marking these tests as "expensive" (which would exclude them from default test runs) since the affected code paths are unlikely to change frequently. He acknowledges these tests are more critical for Git for Windows specifically, where the fixes matter most.

The review is surface-level, focusing on test infrastructure considerations rather than the technical correctness of the large object handling itself. Stolee doesn't engage with the core functionality but does ask an important process question about when expensive tests should run during release validation. This reflects the patch's position as the final piece in an otherwise technically solid series that has already addressed the main implementation challenges.
