This is the second patch in a 6-part refactoring series for the xdiff subsystem, focusing on type safety improvements. The patch changes the `xdl_bogosqrt()` function to use `uint64_t` instead of `long` for better clarity and to avoid potential issues with negative numbers (which don't have real square roots) and size limitations.

The changes are straightforward but important:
1. The function signature and implementation now use `uint64_t` consistently
2. All call sites explicitly cast their arguments to `uint64_t` when calling the function
3. The return value is cast back to `long` where needed (in `xdiffi.c` and `xprepare.c`)

This is a clean, mechanical change that improves type safety without altering behavior. The patch fits well with the series' overall goal of making the xdiff code more robust and maintainable. The changes touch several xdiff files but are limited to the square root calculation logic, keeping the scope focused.

The patch follows the project's coding style and appears to be merged as part of the larger series that has already been reviewed and approved by key contributors like Phillip Wood. This particular change addresses a specific technical concern about type safety of mathematical operations in the diff algorithm.
