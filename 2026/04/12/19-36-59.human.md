Feature addition to the `git backfill` command, adding progress reporting functionality.

This patch from Trieu Huynh introduces a `--[no-]progress` option to `git backfill`, bringing it in line with similar commands like `git fetch` and `git gc`. The new option shows a progress meter when downloading missing blobs across batches, addressing the lack of feedback during potentially long operations on large repositories.

The implementation follows Git's standard progress reporting conventions:
- Progress is shown by default when stderr is a terminal
- Can be forced with `--progress` or suppressed with `--no-progress`
- Tracks total downloaded objects across all batches

The patch includes thorough test coverage verifying the different progress reporting scenarios. The changes are cleanly implemented, adding the new option to the command's usage string and maintaining consistency with existing progress reporting patterns in other Git commands.

This appears to be a well-considered addition that improves the user experience of the backfill command without introducing complexity. The patch is part of Trieu Huynh's GSoC project, as indicated by the subject line prefix.
