This is the tenth iteration of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through extensive review and is now fully polished, with all technical concerns resolved.

The key change in v10 is the renaming of the autostash ref from `CHECKOUT_AUTOSTASH` to `CHECKOUT_AUTOSTASH_HEAD` to follow Git's documented rules for root-level refs (which must end with `_HEAD`). This change was prompted by Jeff King's analysis and represents the final naming refinement before merging. The functionality remains identical - it's purely a naming convention update.

The series provides several user-visible improvements:
1. `git checkout -m` now automatically stashes uncommitted changes when encountering conflicts during branch switching, similar to existing rebase/merge behavior
2. New `--label-ours`, `--label-theirs`, and `--label-base` options for `git stash apply` to customize conflict markers
3. Silent autostash creation during branch switching operations

The implementation touches multiple components including `builtin/checkout.c`, `builtin/stash.c`, and `sequencer.c`, with comprehensive test coverage in t7201-co.sh (19 test cases). Documentation has been made consistent across git-checkout, git-stash, and git-switch man pages.

With this final naming convention update, the series has addressed all feedback from reviewers (including Junio Hamano, Phillip Wood, and Jeff King) and is ready for merging. The changes represent a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes.
