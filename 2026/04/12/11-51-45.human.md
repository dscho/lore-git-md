This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has gone through extensive review and is now fully polished, with all technical concerns resolved.

The patch implements the core functionality where `git checkout -m` will now automatically stash uncommitted changes when encountering conflicts during branch switching, similar to existing rebase/merge behavior. When conflicts occur, the changes are stashed and reapplied after the switch. If reapplying causes conflicts, the stash is preserved and the user is given clear instructions on how to resolve the situation.

Key aspects of this implementation:
- Uses the newly introduced `CHECKOUT_AUTOSTASH_HEAD` refname (finalized in earlier patches)
- Provides clear user guidance when conflicts occur during stash application
- Includes comprehensive test coverage in t7201-co.sh (19 new test cases)
- Updates documentation for both `git-checkout` and `git-switch` to explain the new behavior
- Handles edge cases like non-conflicting changes, staged changes, and mixed staged/unstaged changes

The patch touches multiple components including `builtin/checkout.c`, documentation, and test files. It represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes. With this final patch, the series is complete and ready for merging after receiving approval from Junio Hamano and positive reviews from Phillip Wood and Jeff King.
