Feature patch adding customizable conflict marker labels to `git stash apply`. This is the first of four patches in the v10 series that enhances conflict resolution during branch switching with autostash behavior.

The patch introduces three new options to `git stash apply`:
- `--label-ours=<label>` - Custom label for the upstream side of conflicts
- `--label-theirs=<label>` - Custom label for the stashed side of conflicts  
- `--label-base=<label>` - Custom label for the base in diff3-style conflicts

The implementation modifies `builtin/stash.c` to pass these labels through to the merge machinery, with empty strings allowed to produce unlabeled conflict sections. Documentation is updated in `git-stash.adoc` and comprehensive tests are added in `t3903-stash.sh` covering both custom labels and empty labels.

This builds on existing merge conflict marker functionality while maintaining backward compatibility - when no labels are specified, it falls back to the default "Updated upstream"/"Stashed changes"/"Stash base" text. The changes touch the stash command plumbing but don't affect other commands' behavior.

The patch is well-tested (29 new test lines across two scenarios) and follows Git's established patterns for merge conflict handling. It's part of a larger effort to improve conflict resolution during branch switching operations, with subsequent patches in the series building on this foundation.
