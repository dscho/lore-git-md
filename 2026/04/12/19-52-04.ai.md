This is the final version of a bugfix patch series improving `git stash`'s argument parsing behavior. The patch makes `git stash` automatically assume the "push" subcommand when the command line starts with any option flag (like `-m`, `--staged`, etc.), rather than requiring explicit "push" or `--` before pathspecs.

The implementation is simpler and more robust than previous versions - it now unconditionally assumes "push" when seeing any leading option, rather than checking a list of push-specific options. This handles all current and future push-compatible options correctly. The change maintains backward compatibility while making common `git stash` usage more intuitive.

The patch includes thorough test coverage verifying the new behavior with various push-compatible options (`-m`, `--staged`, `--keep-index`, `--include-untracked`). Documentation is updated to clarify the new inference rules. Junio C Hamano has reviewed and approved the design direction, noting it better matches user expectations and future-proofs against new options.
