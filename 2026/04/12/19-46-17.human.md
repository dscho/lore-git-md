Progress reporting refinement for `git backfill`.

Derrick Stolee responds to Trieu Huynh's patch adding progress reporting to the experimental `git backfill` command, raising important considerations about how it interacts with the underlying `git fetch` progress indicators. While the initial implementation follows Git's standard progress reporting patterns, Stolee points out that it doesn't account for the fetch operation's own progress output.

The key concern is that `--no-progress` currently only suppresses backfill's own progress meter while still allowing fetch's progress to show, which may not match user expectations. Stolee suggests two potential solutions: either unconditionally suppress fetch output (which might be too restrictive) or introduce a separate `--[no-]verbose` flag to control fetch output independently of the backfill progress meter.

This moves the discussion from implementation details to a design question about how multiple progress indicators should coexist in a command that wraps other Git operations. The patch appears technically sound but may need adjustments to properly handle these interaction cases before being ready for merging.
