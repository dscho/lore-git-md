This is the third patch in a four-part series that enhances Git's autostash functionality during conflicted branch switches. The series has already gone through extensive review and is now in its final polished form.

The current patch adds support for customizable conflict marker labels when applying autostashes. It introduces new parameters to the sequencer's autostash machinery to pass through label options to `git stash apply`. The key changes are:

1. A new `apply_autostash_ref_with_labels()` function that accepts `label_ours`, `label_theirs`, and `label_base` parameters
2. Modifications to the internal `apply_save_autostash_oid()` to handle these new label options
3. Updated function signatures throughout the sequencer autostash code to maintain consistency

The patch maintains backward compatibility by keeping the existing functions that don't take labels, while adding the new labeled variant. This builds on the previous patches in the series that introduced the core autostash behavior for `git checkout -m` and the silent autostash creation.

With this change, callers (like the checkout machinery) can now specify custom labels for the conflict markers when automatically applying stashed changes during branch switches. The implementation is clean and follows the established patterns in the sequencer code.

Since this is part of a well-reviewed series that has already received maintainer approval (with only naming refinements in v10), this patch appears ready for merging as part of the complete feature set.
