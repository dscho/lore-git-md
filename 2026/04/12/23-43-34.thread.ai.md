Proposed new `git recall` command for formatted commit activity summaries. RFC from Ammaar Bakshi with working C implementation. Command would show commits grouped by date with --day/--week/--month/--year time windows, aiming to simplify standup/review workflows currently requiring complex `git log` invocations. Parallels `git switch`/`git restore` simplification of `git checkout`. 

Tian Yuchen raises concerns about scope and naming, questioning whether the functionality warrants a new built-in command versus Git aliases, and noting potential confusion from the `recall` name's multiple meanings (including revocation/amendment side effects). Suggests `git activity` as a clearer alternative. Distinguishes this case from the `git checkout` split, arguing `git log` is already clear as a read-only operation.

Open questions: core Git scope appropriateness (built-in vs. alias), command naming (`recall` vs `activity`), prior art discussion, and whether similar output can be achieved through existing mechanisms like `.gitconfig` aliases. Implementation exists as standalone tool, ready for potential integration. Key technical elements remain date-grouped output format (hashes, messages, authors, times) and time window flags. Thread appears to be moving toward a debate about Git's philosophy around adding porcelain commands versus improving documentation of existing tools.
