This is the third patch in a four-part series implementing unified conflict resolution in `git checkout -m` through autostash behavior. The series has already received maintainer approval and is in its final polishing stage.

The patch extends the sequencer's autostash machinery to support customizable conflict marker labels when applying stashes. It adds new parameters (`label_ours`, `label_theirs`, `label_base`) to several internal functions and introduces a new public API `apply_autostash_ref_with_labels()` that callers to pass these labels through to `git stash apply`. The implementation maintains backward compatibility by keeping the existing functions that don't take labels, which simply pass NULL for all label parameters.

The changes are mechanical but important for the label customization feature - they allow the higher-level `git checkout -m` command (modified in other patches in the series) to pass through user-specified labels when it automatically handles stashing during conflicted branch switches. The patch follows the established pattern of the series by keeping the new functionality opt-in while preserving the existing behavior for all current callers.

With this change, the sequencer can now fully support the label customization feature that was added to `git stash apply` earlier in the series. The implementation is clean and maintains the separation of concerns - the sequencer handles the autostash application while delegating the actual label handling to the stash machinery.
