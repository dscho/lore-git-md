This is the 10th and final version of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through extensive review and is now fully polished, with all technical concerns resolved.

The key change in v10 is the renaming of the autostash ref from `CHECKOUT_AUTOSTASH` to `CHECKOUT_AUTOSTASH_HEAD` to follow Git's documented rules for root-level refs (which must end with `_HEAD`). This naming change was suggested by Jeff King and confirmed as the correct convention. The change is purely naming-related with no functional impact.

The series provides several user-visible improvements:
1. `git checkout -m` now automatically stashes uncommitted changes when encountering conflicts during branch switching, similar to existing behavior in `git rebase` and `git merge`
2. New `--label-ours`, `--label-theirs`, and `--label-base` options for `git stash apply` allow customizing conflict markers
3. Silent autostash creation during branch switching operations

The implementation touches multiple components including `builtin/checkout.c`, `builtin/stash.c`, and `sequencer.c`, with comprehensive test coverage (19 new test cases in t7201-co.sh). Documentation has been updated in git-checkout.adoc, git-stash.adoc, and git-switch.adoc.

The series has received maintainer approval from Junio C Hamano and thorough technical review from Phillip Wood. With the final refname convention resolved, this version is ready for merging. This represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes.
