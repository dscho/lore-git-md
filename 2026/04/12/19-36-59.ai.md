Feature patch adding progress reporting to `git backfill`.

This patch from Trieu Huynh adds a `--[no-]progress` option to `git backfill`, bringing its behavior in line with other Git commands like `git fetch` and `git gc`. The implementation tracks downloaded blobs across batches and shows a standard Git progress meter, defaulting to on when stderr is a terminal.

The changes are straightforward: a new `show_progress` flag in the context struct, counters to track downloads, and the standard progress API calls. The patch includes three new tests verifying the default TTY behavior and explicit `--progress`/`--no-progress` overrides. The implementation matches Git's conventions for progress reporting and integrates cleanly with the existing batch download logic.

This appears to be a well-scoped quality-of-life improvement for the experimental `backfill` command, which currently provides no feedback during potentially long operations. The patch follows Git's standard patterns for both the user interface (matching `fetch`'s behavior) and implementation (using the progress API correctly). The tests cover the expected cases and the commit message clearly explains the motivation.
