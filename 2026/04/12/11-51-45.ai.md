This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through extensive review and is now fully polished, with all technical concerns resolved.

The patch implements the core functionality where `git checkout -m` will now automatically stash uncommitted changes when encountering conflicts during branch switching, similar to existing rebase/merge behavior. On success, only "Applied autostash" is shown. If reapplying the stash causes conflicts, the stash is preserved and the user is given clear instructions on how to resolve the situation.

Key technical aspects:
- Adds silent autostash creation via `create_autostash_ref_silent()`
- Uses `apply_autostash_ref_with_labels()` to reapply stashed changes with proper conflict marker labels
- Handles both staged and unstaged changes appropriately
- Includes comprehensive test coverage in t7201-co.sh (19 new test cases)
- Updates documentation in git-checkout.adoc and git-switch.adoc to explain the new behavior

The implementation touches multiple components including `builtin/checkout.c`, `sequencer.c`, and the xdiff interface, with careful attention to error handling and edge cases. The test suite verifies various scenarios including non-conflicting changes, truly conflicting changes, mixed changes, and proper handling of the stash in all cases.

With this final patch, the series completes its goal of providing a more user-friendly branch switching experience when working with uncommitted changes, while maintaining backward compatibility. The changes have been reviewed by Junio Hamano, Phillip Wood, and Jeff King, with all feedback addressed across 10 iterations of the series.
