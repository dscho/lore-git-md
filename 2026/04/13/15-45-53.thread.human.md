The thread discusses a question about configuring different SSH commands for submodules during initial setup. Shibo Xia raised the issue that there's currently no Git-native way to specify per-submodule SSH settings during `git submodule update --init`, since submodules lack local configuration at this early stage. The existing options - repository-wide `core.sshCommand` or environment variables - affect all submodules uniformly, which may not be desired.

Git maintainer Junio C Hamano responded with a practical solution: separating the `submodule init` and `submodule update` steps. By running these commands separately, users can modify submodule URLs in the superproject's configuration before the actual clone occurs. This approach leverages Git's existing configuration mechanisms rather than requiring new functionality. Junio's response suggests the project views this as a workflow sequencing issue solvable with current features, maintaining the boundary between Git's configuration system and SSH tooling.

The discussion now centers on this existing-methods approach rather than proposing API changes, indicating the maintainer sees proper command sequencing as the solution to per-submodule SSH customization during initialization.
