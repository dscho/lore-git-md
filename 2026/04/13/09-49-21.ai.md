This is a test infrastructure patch series aimed at making Git's test suite more robust by detecting errors outside of test cases. Patrick Steinhardt follows up on Junio Hamano's earlier discussion about using `set -e` (errexit) in tests to catch failures that would otherwise be silently ignored.

The 12-patch series prepares various test helper functions and existing tests to work correctly with `set -e` enabled. Changes include:
- Modifying `test_match_signal()` and `test_must_fail()` to handle signals properly
- Adjusting `stop_git_daemon()` and config unset operations to not fail the test
- Fixing conditional test execution patterns that would break with `set -e`
- Addressing specific test cases that would fail with strict error checking (t0008, t1301, t6002, t9902)

The series is well-motivated by the goal of catching more test failures early, and appears carefully tested with both Bash and Dash. The changes are mechanical but important for test reliability. Since this touches many test scripts, some fallout in edge cases is expected despite the author's testing. The patches follow the common pattern of preparing the infrastructure first before flipping the switch to enable `set -e` in the final patch.

This continues Git's ongoing effort to improve test robustness, building on previous work to modernize test patterns. The changes are focused on the test framework itself rather than any particular Git feature or bug. Reviewers will want to verify the error handling changes don't introduce false positives in existing tests.
