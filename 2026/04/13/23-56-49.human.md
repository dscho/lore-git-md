This is the fourth patch in a bugfix series addressing issues in Git's pseudo-merge bitmap implementation. The patch fixes an inverted binary search in the `pseudo_merge_at()` function that was causing lookups to search in the wrong direction when multiple pseudo-merge groups existed.

The bug manifested when searching for pseudo-merges - the binary search would incorrectly update its bounds, potentially missing valid entries unless they happened to be near the midpoint. Taylor Blau's fix swaps the "lo" and "hi" assignments to correct the search direction. The impact is most noticeable with multiple pseudo-merge groups, where the incorrect search could fail to find valid entries during bitmap fill-in traversal.

The patch includes a test update that changes an expected failure (`test_expect_failure`) to an expected success (`test_expect_success`), demonstrating the fix allows pseudo-merges to be properly applied from multiple groups. This continues the series' pattern of thorough test coverage - each fix is accompanied by test verification.

Given Taylor's deep expertise in the bitmap subsystem and the clear, focused nature of this correction, the patch appears well-constructed. It's part of a larger effort to stabilize pseudo-merge bitmaps, an important performance optimization for large repositories.
