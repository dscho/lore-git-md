This is a test infrastructure follow-up addressing fallout from Patrick Steinhardt's `set -e` series. Junio Hamano reports that git-svn tests now fail hard when run without the required Perl modules (SVN::Core etc.), whereas previously they would gracefully skip with exit code 0. The change reveals a tension between strict error checking and legitimate test skips for optional dependencies.

The breakage affects all git-svn tests (t91xx and t915x series) when Perl modules are missing. The tests now abort immediately with a non-zero exit code when `git svn` commands fail due to missing dependencies, rather than marking the test as skipped. This wasn't caught in CI because those environments have the Perl modules installed.

Junio demonstrates the behavior difference by showing the test script exiting with status 1 (failure) after the merge versus the previous behavior of exiting 0 (success) with a skip message. The core issue is that the test suite's new strict error handling doesn't yet account for the pattern used by git-svn tests to handle optional dependencies.

This case highlights a real-world consequence of the `set -e` change - it surfaces previously hidden failures but requires adjustments to how optional-dependency tests are structured. The fix will need to preserve the ability to gracefully skip tests while still catching genuine errors, likely by making the prerequisite checks more robust in the git-svn test scripts themselves.
