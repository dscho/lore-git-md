This is a test infrastructure patch from Patrick Steinhardt, part of his ongoing series to improve test suite robustness by enabling `set -e` (errexit) in test scripts. The series aims to catch more test failures early by preventing silent error ignoring.

This specific patch (2/12) modifies the `test_must_fail()` helper function to work correctly under `set -e`. The function is used throughout the test suite to verify that Git commands fail in expected ways. The current implementation would cause the test to abort early when `set -e` is enabled, even for expected failures. The change wraps the command execution in a conditional to properly handle both success and failure cases while maintaining the same validation logic.

The patch is a mechanical but important preparation step in the larger effort to make the test suite more reliable. It follows the pattern seen in other parts of the series - modifying test infrastructure first before enabling `set -e` globally. The change is well-contained and unlikely to introduce new issues, though reviewers will want to verify it doesn't affect existing test behavior.
