This is a bugfix patch in Taylor Blau's series addressing issues in pseudo-merge bitmaps. The patch fixes a critical issue where commit dates weren't being properly parsed during pseudo-merge group classification.

The core problem is that `find_pseudo_merge_group_for_ref()` was using `lookup_commit()` without parsing the commit, resulting in all commits having a zero timestamp. This caused the date-based classification (stable vs unstable) to fail completely, making the `threshold` and `stableThreshold` config options ineffective. The fix adds `repo_parse_commit()` to properly read the commit timestamps.

The patch includes a test that demonstrates the fix by configuring two pseudo-merge groups - one for "stable" commits (older than 1 month) and one for all commits. With the fix, only the "all" group matches the test commits (which are all recent), while without the fix both groups would incorrectly match due to the zero timestamps. The test uses `GIT_TEST_DATE_NOW` to align Git's timestamp calculations with the test environment.

This patch is part of a larger effort to fix multiple compounding bugs in the pseudo-merge bitmap implementation that were uncovered by Jeff King's discovery of missing test coverage. The changes are focused on the bitmap writing and pseudo-merge handling code, with this particular fix addressing the date classification logic that affects how commits are assigned to pseudo-merge groups.
