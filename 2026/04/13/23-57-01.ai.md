This is the final patch in Taylor Blau's series fixing bugs in the pseudo-merge bitmap implementation. It addresses a memory leak in the pattern handling code when the same pseudo-merge group's pattern is reconfigured.

The patch fixes a case where redefining a `bitmapPseudoMerge.*.pattern` configuration would free the old regex pointer without first calling `regfree()`, leaking the compiled regex state. The fix properly cleans up by:
1. Adding a NULL check before freeing
2. Calling `regfree()` on the existing pattern before freeing it
3. Adding a test case that verifies the fix by setting the same pattern twice

The test creates a repository, configures the same pattern twice for a pseudo-merge group, then verifies the bitmap generation still works correctly. This demonstrates the leak is fixed while maintaining functionality.

This is a straightforward memory leak fix that completes the series' thorough approach to addressing pseudo-merge bitmap issues. The change is small but important for correctness, and follows the pattern established in earlier patches of adding targeted test coverage. As with the rest of the series, it touches core bitmap writing code but is well-contained and clearly motivated.
