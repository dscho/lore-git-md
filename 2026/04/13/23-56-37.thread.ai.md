

**Thread identity**: Subject: Pseudo-merge bitmap bugfix series -- v3, nine patches. Originating author: Taylor Blau. Thread type: Patch series (bugfix). Conclusion: Merged.

**Core problem**: Multiple compounding issues in the pseudo-merge bitmap implementation: binary-search sort order, swapped comparator, extended-table offset/parsing errors, group selection logic that rendered `stableThreshold` and `sampleRate` configuration inert, a latent division-by-zero crash when `sampleRate` is set to exactly 0, stale documentation showing `sampleRate = 100` when the valid range is `(0,1]`, and a memory leak when a `bitmapPseudoMerge.*.pattern` config key appears more than once for the same group. The existing test suite never exercised `apply_pseudo_merges_for_commit()` before this series.

- **Patch 1**: Adds `test-tool bitmap write` subcommand for fine-grained bitmap control.
- **Patch 2**: Adds 198 lines of test code with five new scenarios, all initially marked as expected failures.
- **Patch 3**: Fixes binary-search sort order in `pack-bitmap-write.c`. Corresponding test promoted.
- **Patch 4**: Fixes swapped `lo`/`hi` comparator in `pseudo_merge_at()` in `pseudo-merge.c`. Corresponding test promoted.
- **Patch 5**: Fixes three compounding bugs in the extended pseudo-merge lookup table: (a) write-side extended-table offset undercounted entries as 8 bytes instead of 12; (b) read-side `nth_pseudo_merge_ext()` parsed a stored offset through a 12-byte struct accessor; (c) latent off-by-one in `apply_pseudo_merges_for_commit()` tested `< -1` instead of `< 0`. Four lines of functional code across two files. Corresponding test promoted.
- **Patch 6**: Fixes silent classification bug in `find_pseudo_merge_group_for_ref()` in `pseudo-merge.c`: `lookup_commit()` returns an unparsed commit with `date` field set to zero, causing every commit to be classified as "stable" and making `bitmapPseudoMerge.*.threshold`, `stableThreshold`, and `sampleRate` completely inert. Fix is `repo_parse_commit()` after `lookup_commit()` with early return on parse failure. Corresponding date-classification test promoted; sample-rate division-by-zero test demoted to `test_expect_failure`.
- **Patch 7**: Prevents division-by-zero crash when `bitmapPseudoMerge.*.sampleRate` is exactly 0. Tightens config validation from `0 <= rate <= 1` to `0 < rate <= 1`, updates documentation, and promotes corresponding test. Touches `Documentation/config/bitmap-pseudo-merge.adoc`, `pseudo-merge.c`, and `t/t5333-pseudo-merge-bitmaps.sh`.
- **Patch 8**: Two-line documentation fix in `Documentation/gitpacking.adoc`. Two example configurations showed `sampleRate = 100`, but the valid range for `bitmapPseudoMerge.*.sampleRate` is `(0,1]`. The value `100` was correct when the config was in the range `(0,100]` but became invalid when the representation changed to a decimal fraction. Both instances changed to `sampleRate = 1`. Catch credited to Elijah Newren. Originating commit: faf558b23ef (2024-05-23).
- **Patch 9**: Fixes memory leak in `pseudo_merge_config()` when a `bitmapPseudoMerge.*.pattern` config key appears more than once for the same group. When a duplicate pattern is encountered, the old pointer is freed but `regfree()` is never called first, leaking `regcomp()`-allocated state. The fix is a NULL-checked guard in `pseudo-merge.c` that calls `regfree()` before `free()` when the pointer is non-NULL. The test in `t/t5333-pseudo-merge-bitmaps.sh` creates a repository with 64 commits, configures the same pattern twice, builds a pseudo-merge bitmap, and asserts exactly one pseudo-merge is produced. Runs under `test_when_finished` cleanup.
