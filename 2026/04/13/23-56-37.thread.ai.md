**Thread identity**: Subject: Pseudo-merge bitmap bugfix series -- v3 submitted. Originating author: Taylor Blau. Thread type: Patch series (nine patches, bugfix).

**Core problem**: Multiple compounding issues in the pseudo-merge bitmap implementation affecting lookup paths (binary-search sort order, swapped comparator, extended-table offset/parsing), group selection logic, and memory management. The existing test suite never exercised `apply_pseudo_merges_for_commit()` at all (noted in prior fix f16eb1c091, March 2026). The series establishes test infrastructure then systematically fixes all identified issues.

**Current status**: v3 submitted. Junio C Hamano has indicated the series is "so close to the finish line" and is awaiting this final update. Changes from v2 were purely test-hygiene: `test_when_finished` ordering (per Elijah Newren), avoiding piping `git rev-parse` into a test helper for the "duplicate pattern does not leak" test, and rebase onto current master. Patch 4 and patch 5 have now both been submitted as the latest arrivals.

- **Patch 4** (previously recorded): Fixed a swapped comparator in `pseudo_merge_at()` (`pseudo-merge.c`). When more than one pseudo-merge group existed, inverted `lo`/`hi` assignments caused searches to go the wrong direction and silently fall back. Two-line fix; corresponding test promoted from `test_expect_failure` to `test_expect_success`.
- **Patch 5** (newly arrived): Fixes three compounding bugs in the extended pseudo-merge lookup table (used when a commit belongs to multiple groups):
  1. On the write side in `write_pseudo_merges()`: the extended-table offset undercounted each commit lookup entry as 8 bytes instead of 12, so the extended table was written on top of the normal lookup table.
  2. On the read side in `nth_pseudo_merge_ext()`: parsed a stored offset through `read_pseudo_merge_commit_at()`, treating it as a 12-byte struct when it only needed to store the offset directly.
  3. A latent off-by-one in `apply_pseudo_merges_for_commit()`: error check tested `< -1` instead of `< 0`, which would silently swallow an `error()` return on corrupt data.
  Fix is four lines of functional code across two files plus moving one test marker. The corresponding test is promoted from `test_expect_failure` to `test_expect_success`.

The maintainer's What's cooking draft explicitly notes the series is nearly ready.
