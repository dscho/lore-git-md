Final review of `git stash` push inference improvements

This email from Phillip Wood provides the final review of Deveshi Dwivedi's patch to improve `git stash`'s argument parsing. The change makes `git stash` automatically assume the "push" subcommand when the command starts with any option flag (like `-m` or `--staged`), rather than requiring explicit "push" or `--` before pathspecs.

Phillip confirms the implementation correctly handles all cases, including negated options like `--no-staged` (which the v3 approach missed). He suggests minor wording improvements - using "assumed" instead of "inferred" in documentation and standardizing test quote syntax. The test coverage is thorough, verifying behavior with various push-compatible options.

This represents the culmination of four iterations incorporating feedback from Phillip Wood, Junio Hamano, and others. The final version is simpler and more robust than earlier attempts, using a universal "-" check rather than maintaining a list of push-specific options. The change improves usability while maintaining backward compatibility.

With Phillip's approval and Junio's earlier endorsement, this appears ready for merging. The patch cleanly addresses a long-standing usability pain point in a maintainable way, demonstrating Git's review process at its best - multiple rounds of feedback leading to a polished final result.
