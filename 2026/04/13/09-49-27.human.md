This is part of Patrick Steinhardt's ongoing test infrastructure series to make Git's test suite more robust by enabling `set -e` (errexit) behavior. Patch 6/12 focuses on fixing test patterns that check for executable availability, which would fail under `set -e` if the binary isn't found.

The patch modifies several test scripts to wrap executable checks in proper conditionals rather than relying on implicit exit code checking. Changes include:
- Converting `svn`/`cvs`/`git` availability checks to use `if ! command` patterns
- Fixing the HTTP server startup check in `t/lib-httpd.sh`
- Updating Perl module checks for the CVS server tests

These are mechanical but important changes that maintain the same skip behavior while making the tests compatible with strict error checking. The modifications follow the series' pattern of preparing the test infrastructure before enabling `set -e` in the final patch. The changes are focused and well-contained, touching only the specific patterns that would break under `set -e`.

This continues the project's broader effort to modernize and harden the test suite. The patch appears straightforward and unlikely to introduce regressions, though reviewers will want to verify the modified skip conditions work as intended across different test environments.
