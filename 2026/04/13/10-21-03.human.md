Documentation patch clarifying that `git interpret-trailers` works beyond commit messages. This is part 4/9 of Kristoffer Haugsbakk's series to improve the command's documentation, following discussion about trailer key format restrictions.

The patch updates the DESCRIPTION section to note that trailers can be added to any text, not just commit messages, while keeping the example focused on commits since that's the primary use case. This aligns with Git's broader support for trailers in other commands like `git tag --trailer`. The change is straightforward and uncontroversial, maintaining the series' goal of making the documentation more accurate and complete.

The series as a whole has already received maintainer approval, with this patch being one of several mechanical updates to terminology and scope. It helps set up the context for later patches that will define the trailer format rules more precisely.
