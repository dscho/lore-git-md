This is the third patch in Taylor Blau's series addressing bugs in the pseudo-merge bitmap implementation. The patch fixes a critical issue where the commit lookup table was being sorted lexically (by OID) rather than by pack position, causing the binary search during fill-in traversal to fail.

The change introduces a new comparison function `pseudo_merge_commit_pos_cmp` that sorts commits by their position in the pack order, matching what the bitmap reader expects. While this technically changes the on-disk format, the author notes this is actually making the implementation comply with the documented format - the previous behavior was effectively broken since the binary search wouldn't work correctly.

The patch includes a test update marking the previously failing fill-in traversal test as now passing. The commit message provides important context about the limited impact of this bug - while fill-in traversal was broken, initial traversal phases using `cascade_pseudo_merges_1()` worked correctly, and the failure mode was safe (missing optimizations rather than incorrect results).

This appears to be a well-justified fix from the primary contributor to this subsystem, with clear explanation of both the problem and solution. The change is focused and comes with test verification, addressing one of the core issues identified in the series.
