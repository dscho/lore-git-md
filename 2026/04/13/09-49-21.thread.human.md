Patrick Steinhardt's completed 12-patch series to enable `set -e` (errexit) in Git's test suite for Bash 5+ has addressed all prior review feedback, systematically preparing the test framework for stricter error checking. The series now catches previously silent issues like test_expect_success typos by failing immediately on command errors outside test cases. Jeff King (Peff) had previously suggested extending this functionality via a `GIT_TEST_USE_SET_E` environment variable to make the feature opt-in for other shells like dash.

In a new development, Peff responds to Junio Hamano's request for alternative approaches to catch unexpected test failures without strictly enforcing `set -e`. He explores two technical solutions for selectively monitoring stderr output - first attempting a separate "lint" mode (which proved too slow), then developing a more practical approach that redirects stderr to a file during normal test execution while preserving the original stderr for intentional error output. This catches typos while allowing expected diagnostic messages through, though Peff notes challenges around test framework diagnostics that intentionally write to stderr. His prototype suggests there may be viable alternatives to the `set -e` approach that could address Junio's maintainability concerns while still improving error detection.

The thread has seen thorough review from Jeff King, SZEDER Gabor, and Junio Hamano, with all identified edge cases in the original series now resolved. The remaining open question is whether to adopt Peff's stderr-monitoring alternative or proceed with the completed `set -e` implementation - a decision that hinges on balancing strict error checking against test suite usability and maintainer workflow.
