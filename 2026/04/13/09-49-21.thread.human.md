Patrick Steinhardt's series to make Git's test suite compatible with `set -e` (errexit) is now complete and ready for merging after six iterations. The work establishes `set -e` as the default for Bash 5+ while maintaining opt-in via `GIT_TEST_USE_SET_E` for other shells, with CI now enabling this for Linux jobs.

The latest patch (4/12) makes three test scripts robust against `git config --unset` failures when variables don't exist, adding `|| :` to suppress harmless errors. This affects tests dealing with diff context, status colors, and SVN author handling. These changes are mechanical but necessary for the suite to work reliably under strict error checking.

The series has seen thorough review from Jeff King (who confirmed some defensive coding was unnecessary), SZEDER Gábor (who provided input on completion tests), and others including brian m. carlson and D. Ben Knoble. Junio C Hamano had previously approved the approach. All technical questions have been resolved through careful iteration, with the changes now preserving original test semantics while enabling immediate failure detection. The work includes foundational improvements to test helpers like `test_must_fail()` and `stop_git_daemon()` to work correctly under `set -e`.
