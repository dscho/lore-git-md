Patrick Steinhardt continues his work to make Git's test suite more robust by preparing it for `set -e` (errexit) behavior. The series, which has grown to 14 patches, systematically updates test helper functions and individual tests to work correctly under strict error checking.

The latest patch focuses on `stop_git_daemon()`, a helper function used to terminate test Git daemon processes. It fixes two issues that would cause tests to fail prematurely when `set -e` is enabled: making the `wait` command conditional to properly handle its expected failure, and suppressing harmless failures from a secondary `kill` attempt. These changes maintain the function's error checking while making it safe for the stricter environment.

This follows earlier changes to core test helpers like `test_must_fail()` and addresses specific test cases across multiple files. The approach shows careful attention to backward compatibility - each change preserves existing behavior while enabling the stricter checking that will help catch errors earlier in test runs. The series is part of Git's ongoing test modernization efforts that Junio Hamano has previously discussed.
