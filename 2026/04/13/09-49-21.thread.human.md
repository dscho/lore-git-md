Patrick Steinhardt's series to enable `set -e` in Git's test suite has been approved and merged after thorough review, marking a significant reliability improvement. The change makes test failures immediately apparent rather than allowing them to silently pass. However, it has surfaced an issue with git-svn tests (t91xx and t915x series) when run without the required Perl modules (SVN::Core etc.). Where these tests previously skip gracefully when dependencies are missing, they now fail hard due to the new error checking.

Junio Hamano confirmed the behavior difference, showing the tests now exit with status 1 (failure) rather than 0 (success with a skip message) when modules are absent. This wasn't caught in CI since those environments have the Perl modules installed. The core tension is between strict error checking and legitimate test skips for optional dependencies. A fix will need to restructure the git-svn tests to maintain their ability to skip gracefully while still catching genuine errors under the new `set -e` regime. The underlying infrastructure improvement remains sound - it's just revealing a case where test patterns need updating to match the stricter standards.
