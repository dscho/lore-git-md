Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite has reached its final form after extensive review. The work makes Bash 5+ use strict error checking by default while maintaining compatibility with other shells via the `GIT_TEST_USE_SET_E` environment variable. The changes touch nearly every part of the test suite, converting shell arithmetic, conditional execution patterns, and cleanup handlers to work safely with error checking enabled.

The last remaining question - whether to keep defensive `|| true` coding in the `check_fsck()` helper - has been resolved. Patrick agreed with Jeff King's assessment that this was unnecessary over-engineering, since the test framework already handles `set -e` suppression within test snippets. With this settled, the series is now ready for merging.

Junio C Hamano, Jeff King, and several other reviewers have signed off on the approach after multiple iterations. The changes will make the test suite more reliable by surfacing failures immediately while maintaining backward compatibility. This concludes a significant infrastructure improvement that has been in development for several months.
