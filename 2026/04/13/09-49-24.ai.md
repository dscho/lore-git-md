This is a test infrastructure change in Patrick Steinhardt's series to prepare Git's test suite for `set -e` (Patch 3/12). The patch modifies the `stop_git_daemon()` helper function to work correctly when `set -e` (errexit) is enabled in test scripts.

The function currently has two issues that would cause tests to fail with `set -e`:
1. The `wait` command is expected to fail (since we're killing the daemon) but isn't in a conditional, which would trigger an immediate exit
2. The second `kill` call (via PID file) often fails harmlessly since the process was already killed, but this failure would also abort the test

The changes wrap the `wait` in a conditional to properly capture its exit status and add `|| :` to suppress the second `kill`'s failure. This maintains the function's error checking behavior (verifying the daemon was killed with SIGTERM) while making it `set -e` safe. The modification is mechanical but important for the series' goal of enabling stricter error checking across the test suite.
