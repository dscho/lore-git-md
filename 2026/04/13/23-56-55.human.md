This is a bugfix patch in Taylor Blau's series addressing issues with pseudo-merge bitmaps. The patch fixes a date classification problem where unparsed commits were being treated as stable (date=0) regardless of their actual timestamp.

The core issue is that `find_pseudo_merge_group_for_ref()` was using `lookup_commit()` without parsing the commit, causing all commits to appear infinitely old. This meant the stable/unstable classification was broken, making the `threshold` and `stableThreshold` config options ineffective. The fix adds `repo_parse_commit()` to properly read commit dates.

The patch includes a test that demonstrates the fix by creating two pseudo-merge groups - one for "stable" commits (older than 1 month) and one for all commits. With the fix, only the "all" group matches the test commits (which are all recent), while previously both groups would match due to the date=0 bug. The test also exposes a related division-by-zero issue with sampleRate=0 that will be fixed in a subsequent patch.

This is a well-constructed fix that addresses a clear functional gap in the pseudo-merge bitmap implementation. The test case provides good coverage of the fixed behavior and helps prevent regressions. As part of an important performance optimization feature, this fix helps ensure pseudo-merge bitmaps work as intended for large repositories.
