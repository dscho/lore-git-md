This is a test infrastructure patch (part 5/12 in a series) that prepares conditional test execution patterns to work with `set -e`. Patrick Steinhardt addresses a specific issue where tests using `test ... && test_expect_success` would fail the overall statement when skipping a test, which would cause problems when `set -e` is enabled.

The patch converts two patterns in test scripts:
1. In t4032-diff-inter-hunk-context.sh, changes file existence checks to use proper `if` conditionals before running test_expect_success
2. In t7450-bad-git-dotfiles.sh, similarly converts variable presence tests to use `if` blocks

These changes maintain the same test behavior while making the scripts compatible with strict error checking. The modifications are mechanical but important for the series' goal of enabling `set -e` across the test suite. The changes follow the established pattern of preparing infrastructure first, with the actual `set -e` enablement presumably coming in a later patch.

This continues the ongoing effort to improve test robustness, specifically targeting conditional test execution patterns that would break under strict error checking. The changes are focused and well-contained, touching only the necessary test scripts while maintaining their existing functionality. Reviewers will want to verify the conditionals still correctly skip tests when intended.
