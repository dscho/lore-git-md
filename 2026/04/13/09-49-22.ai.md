Test infrastructure patch from Patrick Steinhardt, part of a series to enable `set -e` in Git's test suite. This first patch modifies signal-handling test cases to work correctly with strict error checking.

The change updates three test cases that verify Git dies with SIGPIPE (signal 13) when its output pipe is closed. The original tests used `foo; echo $?` patterns that would fail under `set -e` since the Git command is expected to terminate abnormally. The patch changes these to `foo || echo $?` to properly capture the exit status while allowing the command to fail.

The affected tests are in t/t0005-signals.sh (two cases) and t/t3600-rm.sh (one case). All modify the same pattern of capturing and verifying signal exit codes. The changes are mechanical but important for the overall goal of enabling `set -e` across the test suite to catch more silent failures.

This is a straightforward preparation patch that doesn't yet enable `set -e` - it just makes existing tests work correctly with the stricter error checking that will come later in the series. The changes are limited to signal-related tests and follow the established pattern of using `test_match_signal()` to verify expected signal termination.
