Documentation patch clarifying git-interpret-trailers' broader applicability beyond commit messages. This is part 4/9 of Kristoffer Haugsbakk's v2 series that systematically improves the command's documentation.

The patch makes two small but meaningful changes to the DESCRIPTION section:
1. Explicitly states that trailers can be used with "any other kind of text" (not just commit messages)
2. Maintains the commit message example as the primary use case while broadening the context

This aligns with the series' goal of making the documentation more accurate and complete, particularly following git-tag's addition of trailer support. The change is straightforward and uncontroversial, building on the terminology standardization from earlier patches in the series. 

The patch maintains the command's focus on commit messages as the primary use case while properly acknowledging its general text-processing capabilities. This helps users understand they can apply the same trailer manipulation to other contexts like tag messages or arbitrary text files. The change is consistent with the series' overall direction and has already been reviewed as part of the v2 submission.
