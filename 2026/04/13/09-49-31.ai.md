This is part 10 of Patrick Steinhardt's 12-part test infrastructure series preparing Git's test suite for `set -e` (errexit) mode. The patch focuses on t6002-rev-list-bisect.sh, which tests Git's bisection functionality.

The change replaces `expr` with `$(( ))` arithmetic expansion in the `test_bisection_diff()` helper function. The key issue is that `expr` fails when its result is zero, which would cause test failures under `set -e`. The patch also modernizes the test syntax by:
- Using shell arithmetic instead of `expr`
- Converting the multi-line test_expect_success to a single quoted block
- Adding explicit if/else for negative value handling

This continues the series' pattern of mechanical but important changes to make tests robust under strict error checking. The modification preserves the bisection test's mathematical logic while making it compatible with `set -e`. Reviewers should verify the arithmetic transformations maintain the original test's intent, particularly around floor division and error tolerance calculations.
