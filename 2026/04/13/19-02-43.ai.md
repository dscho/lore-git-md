Feature patch addressing progress reporting interactions in `git backfill`.

Trieu Huynh responds to Derrick Stolee's feedback about coordinating progress reporting between `git backfill` and its underlying `git fetch` operations. The current implementation shows both backfill's "Downloading missing blobs" progress and fetch's standard output (object counting/compressing) when both are enabled, which Huynh demonstrates doesn't actually interleave badly in practice - the fetch output completes before the progress bar updates.

Huynh agrees with Stolee's suggestion to add a `--[no-]verbose` flag to control fetch output independently from backfill's progress, and plans to implement this in v3. The key insight is that the two outputs don't need special coordination logic since they naturally sequence well - fetch's per-batch output appears first, followed by backfill's cumulative counter. This avoids the need to suppress fetch output when showing progress or vice versa.

The patch remains focused on the experimental backfill command but now considers its output behavior more holistically. The proposed solution maintains backward compatibility while giving users control over both levels of verbosity. Implementation appears straightforward with no obvious technical hurdles, though the v3 patch will need to demonstrate the new `--verbose` option's interaction with progress reporting.
