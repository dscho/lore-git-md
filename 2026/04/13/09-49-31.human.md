This is part 10 of Patrick Steinhardt's 12-part series preparing Git's test suite for `set -e` (errexit) mode. The patch focuses on fixing a specific issue in `t6002-rev-list-bisect.sh` where the test script uses `expr` for arithmetic operations that could fail when `set -e` is enabled.

The change replaces `expr` with shell arithmetic (`$(( ))`) in the `test_bisection_diff()` function, which calculates and verifies bisection results. The key motivation is that `expr` fails when the result is zero, while shell arithmetic does not have this limitation. The patch also modernizes the test formatting slightly by moving the test expectation to a multi-line format.

This is a straightforward mechanical change that follows the series' pattern of addressing one specific test pattern at a time. The modification is low-risk since it maintains the same arithmetic logic while making it compatible with strict error checking. Reviewers will want to verify that the bisection calculations still work as intended, though the change is simple enough that problems are unlikely.

The patch continues the series' steady progress toward enabling `set -e` across the test suite, which will help catch more test failures early. It's a small but important piece of the larger test modernization effort.
