This is the 7th patch in a 9-part documentation series clarifying `git-interpret-trailers` behavior, specifically around trailer key formatting rules. The patch adds a concrete example showing what happens when invalid keys (containing non-alphanumeric characters like periods) are used - the entire trailer block is rejected, even if some keys are valid.

The example demonstrates that:
1. Keys must be ASCII alphanumeric + hyphens only (rejecting "Hash-in-v6.11" due to the period)
2. One invalid key causes the whole block to fail (even though "Reviewed-by" would normally be valid)
3. The behavior matches the strict parsing rules established in earlier patches

This continues the series' pattern of making the documentation more example-driven while maintaining technical accuracy. The patch is merge-ready, having incorporated all maintainer feedback from previous iterations. It directly addresses the original bug report that prompted this documentation overhaul by showing the failure case that confused the reporter.
