Patrick Steinhardt's 12-part series to enable `set -e` (errexit) in Git's test suite has been approved by Junio Hamano, with the final 4-line patch adding `set -e` to test-lib.sh after 11-patch preparation addressing edge cases. Junio's "Yay. Very nice." approval confirmed the changes meet reliability standards after thorough review of signal handling, test helpers, cleanup handlers, and cross-shell compatibility (Bash/Dash). 

A significant issue emerged post-merge when Junio reported git-svn tests (t91xx and t915x series) failing hard when run without required Perl modules (SVN::Core etc.), where they previously skipped gracefully. The strict `set -e` behavior now aborts with non-zero status on missing dependencies, revealing a tension between strict error checking and legitimate test skips. This wasn't caught in CI as those environments have the Perl modules installed.

Key technical details:
- New `stop_git_daemon()` helper with `|| :` fail-safe
- `git config --unset` made resilient with `|| :` in multiple tests
- Cleanup handlers updated with `|| eval_ret=$?` preserving FreeBSD compatibility
- Conditional tests converted to explicit `if/then/else` in t4032 and t7450
- Prerequisite checks using `git version` for reliable exit codes
- Signal handling in t0005 adjusted for SIGPIPE edge cases

Open issue: git-svn tests need restructuring to handle missing Perl modules gracefully under `set -e` while maintaining error detection. The tests currently abort immediately with status 1 when `git svn` commands fail due to missing dependencies, rather than marking as skipped. Junio demonstrated this behavior difference by showing test script exit with status 1 versus the previous exit 0 with skip message. The solution will require making git-svn prerequisite checks more robust to distinguish between skippable and genuine failures.

The core infrastructure improvement remains sound but requires this final adjustment for optional-dependency scenarios. The case highlights how `set -e` surfaces previously hidden failures that may require test restructuring, particularly for tests dealing with optional components like git-svn's Perl dependencies.
