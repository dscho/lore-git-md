Patrick Steinhardt's 12-patch series to enable `set -e` (errexit) in Git's test suite (Bash 5+ only) is now complete. The series systematically prepared the test infrastructure for strict error checking through incremental, backward-compatible changes before activating `set -e` in the final patch. Jeff King (Peff) provided thorough review throughout.

Parts 1-11 addressed signal handling (t0005, t3600), `test_must_fail()` behavior, daemon management, config cleanup, conditional test patterns across 11 test files (t4032, t7450, git-svn, HTTPD, CVS, submodules), core test infrastructure fixes (`test_when_finished()`, `test_atexit()`), and specific test file adaptations (t0008-ignores.sh, t1301-shared-repo.sh, t6002-rev-list-bisect.sh, t9902-completion.sh). Each patch carefully examined edge cases like heredoc behavior and command substitution patterns.

The final patch activates `set -e` in `test-lib.sh` for Bash 5+, ensuring command failures outside test cases cause immediate failure rather than being silently ignored. It includes a CI update to validate the behavior via the `linux-TEST-vars` job. This completes the test modernization effort while maintaining compatibility, representing a significant reliability improvement for Git's test infrastructure. The series is merge-ready with successful CI validation and addresses the original motivation (catching undetected test failures like `test_expect_success` typos).
