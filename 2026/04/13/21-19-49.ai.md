This is a feature proposal from Junio C Hamano exploring a gap in Git's content search capabilities. The email identifies a specific use case where neither `git log -S` (which shows changes) nor `git grep` (which requires guessing a revision range) adequately answers the question "when did this string appear in these versions of a file?"

The core problem is tracking the presence (not just changes) of a topic name across multiple "what's cooking" report versions. Junio demonstrates that `git log -S` only shows transitions (when the string appeared/disappeared) while `git grep` requires manual revision range specification. The email stops short of proposing a solution, instead framing this as an RFC to surface the limitation.

The discussion would likely interest contributors who work with Git's revision walking and content search tools, particularly those involved in `git log` and `git grep` implementations. As an RFC from the maintainer, this signals a real pain point in Git's current tooling that may inspire follow-up patches.
