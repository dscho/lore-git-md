This is a follow-up to Patrick Steinhardt's test infrastructure series that enabled `set -e` in Git's test suite. Junio Hamano reports significant breakage in the git-svn tests when running without the required Perl modules installed. The error occurs because the test suite now fails immediately when `git svn` commands exit with an error due to missing dependencies, whereas previously these failures were silently ignored.

The breakage affects all 50+ git-svn test scripts (t91xx and t915x series) when run without SVN::Core and related Perl modules. This reveals a tension between the new strict error checking and tests that may legitimately skip due to missing dependencies. The issue wasn't caught in CI because those environments presumably have the Perl modules installed.

This demonstrates a real-world consequence of the `set -e` change - it surfaces previously hidden failures but may require adjustments to how optional-dependency tests are structured. The fix will need to preserve the ability to gracefully skip tests while still catching genuine errors. Junio's report provides valuable feedback needed to make the error checking robust across all test scenarios.
