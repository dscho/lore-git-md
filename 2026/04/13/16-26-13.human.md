This is a review response from Junio C Hamano on Patrick Steinhardt's patch series to prepare Git's test suite for `set -e` mode. The patch in question modifies signal-handling tests to work correctly with strict error checking.

Junio raises a subtle concern about the change from `foo; echo $?` to `foo || echo $?` - while both forms correctly catch the expected signal termination (SIGPIPE/13), the new version would silently miss cases where the command unexpectedly succeeds (returning 0). He suggests several alternative approaches that would explicitly handle both success and failure cases, though acknowledges they may be overkill for the specific tests being modified.

The discussion highlights the careful balance required when modifying test infrastructure - even mechanical changes need to preserve the original test intent while adapting to new constraints. Junio's review shows his characteristic attention to edge cases and potential pitfalls, though he doesn't insist on changes to this particular patch.

This exchange is part of a larger, well-structured effort to make Git's test suite more robust by enabling `set -e` to catch silent failures.
