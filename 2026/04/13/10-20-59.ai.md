This v2 series from Kristoffer Haugsbakk builds on the earlier discussion about trailer key restrictions (particularly the rejection of periods in keys) by comprehensively updating the man page to explicitly document current behavior and improve pedagogical structure.

The 9-patch series systematically refactors the documentation to:

3. Clarify that trailers work beyond commit messages
4. Define key-value pair structure upfront with explicit character restrictions (ASCII alphanumeric + hyphens only)
5. Add concrete examples showing valid/invalid keys
6. Document comment line handling
7. Standardize on "trailer block" terminology

The changes directly address all feedback from v1, including removing unclear phrasing, adding the default separator mention, and improving flow. A new example demonstrates how invalid keys can cause entire blocks to be rejected - the exact scenario that prompted the original bug report. The patches maintain technical accuracy while making the rules more discoverable and the documentation more self-contained.
