Feature patch addressing progress reporting interactions in `git backfill`.

Trieu Huynh responds to Derrick Stolee's feedback about coordinating progress reporting between `git backfill` and its underlying `git fetch` operations. The current implementation shows both backfill's "Downloading missing blobs" progress and fetch's standard output, which could potentially interleave confusingly. Huynh clarifies that in practice the outputs don't actually overlap - the fetch output for each batch completes before the backfill progress updates.

The email proposes keeping both progress indicators active by default, noting that the backfill progress updates cleanly via carriage returns between fetch outputs. This suggests the initial concern about interleaving may be less severe than anticipated. Huynh plans to implement Stolee's suggestion of adding a `--[no-]verbose` flag in v3 to give users control over fetch output, while maintaining the existing `--[no-]progress` option for backfill's own reporting.

The discussion reveals thoughtful consideration of user experience tradeoffs - whether to suppress fetch output by default versus allowing both progress meters to coexist. The proposed solution aims to preserve information while avoiding visual clutter, though the actual implementation in v3 will show whether this balance works in practice.
