The pseudo-merge bitmap bugfix v3 series by Taylor Blau is nearly ready for merge per Junio C Hamano. Patch 5/9 arrived, fixing three bugs in the extended pseudo-merge lookup table used when a commit belongs to multiple groups: an off-by-eight offset calculation on the write side (undercounted entries as 8 bytes instead of 12, causing the extended table to overwrite the normal lookup table), a read-side bug where `nth_pseudo_merge_ext()` parsed a stored offset through a 12-byte struct when only the raw offset was needed, and a latent off-by-one in `apply_pseudo_merges_for_commit()` where `< -1` instead of `< 0` would silently swallow error returns on corrupt data. The fixes are four lines of functional code across two files. The corresponding test ("overlapping pseudo-merge groups during fill-in") is promoted from expected failure to passing. Three remaining expected failures (date classification, `sampleRate=0` division-by-zero, and one other) await their fix patches (6-9). Junio has signaled readiness to merge once the series is complete.
