This is the final patch in Patrick Steinhardt's 12-part series to prepare Git's test suite for `set -e` (errexit) mode. The series has systematically updated test patterns that would fail under strict error checking, with each prior patch addressing specific test categories.

The patch enables `set -e` in `t/test-lib.sh`, causing the test suite to abort immediately if any command outside a test case fails unexpectedly. This addresses a real problem where typos in test setup (like misspelled `test_expect_success`) could go undetected. The change builds on the careful groundwork laid in the previous 11 patches, which updated signal handling, test helpers, conditional tests, and prerequisite checks to work correctly with strict error checking.

The series represents a significant improvement in test reliability, following Junio Hamano's earlier discussion about adopting `set -e`. While the change itself is simple (just adding `set -e`), its effectiveness depends on the thorough preparation in the preceding patches. Reviewers can be confident the series has been carefully tested with both Bash and Dash, though some edge cases may still need attention as the change rolls out more widely.
