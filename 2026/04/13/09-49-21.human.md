This is a test infrastructure patch series from Patrick Steinhardt that aims to make Git's test suite more robust by detecting errors that occur outside of test cases. The series follows up on a previous discussion about using `set -e` (exit immediately on error) in tests.

The 12 patches systematically prepare various test components to work correctly with `set -e` by:
1. Fixing signal handling in `test_match_signal()`
2. Adjusting `test_must_fail()` helper
3. Making `stop_git_daemon()` more robust
4. Handling `git config --unset` failures
5. Improving conditional test execution
6. Safely running potentially failing commands
7. Making cleanup handlers (`test_when_finished`/`test_atexit`) error-safe
8-12. Fixing specific test cases that would break under `set -e`

The changes touch a wide range of test scripts and infrastructure files, with careful attention to maintaining backward compatibility. Patrick reports the series passes tests with both Bash and Dash and in CI, though he expects some fallout may still appear.

This appears to be a well-motivated quality improvement to the test suite that follows established patterns. The changes are focused and mechanical, with each patch addressing a specific category of potential issues. The series builds on Junio's earlier work in this area and seems ready for review.
