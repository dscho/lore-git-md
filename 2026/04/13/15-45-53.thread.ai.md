Thread summary:

Subject: Question about submodule initialization and SSH authentication configuration
Thread type: Technical question about submodule behavior
Key participants: Shibo Xia (question author), Junio C Hamano (maintainer response)

Core issue: During initial `git submodule update --init`, there is currently no Git-native way to specify different `sshCommand` settings per submodule. The problem stems from submodules lacking local configuration during initial setup, making repository-level `core.sshCommand` and environment variables like `GIT_SSH_COMMAND` unable to provide per-submodule customization at this stage.

Maintainer response: Junio C Hamano suggests separating `submodule init` from `submodule update` as a solution. This allows modifying submodule URLs in the superproject's configuration before cloning occurs, leveraging existing configuration mechanisms rather than requiring new per-submodule SSH command support. The approach maintains Git's boundary with SSH tooling by treating URL modification as the appropriate configuration point.

Current understanding: The project views this as a configuration sequencing issue solvable with current features, not requiring new functionality. The suggested workflow involves:
1. Running `submodule init` first to populate configuration
2. Modifying submodule URLs as needed (potentially embedding SSH command information)
3. Running `submodule update` to perform the actual operations

Open questions resolved:
- The maintainer acknowledges the use case but suggests it can be addressed without API changes
- The project maintains its stance on keeping SSH authentication configuration separate from core Git functionality

The thread now provides a clear path forward using existing Git features while preserving the project's design boundaries between Git configuration and SSH tooling responsibilities.
