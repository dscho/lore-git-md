This is a follow-up to Patrick Steinhardt's test infrastructure series that enabled strict error checking (`set -e`) in Git's test suite. Junio Hamano reports a significant regression: the git-svn tests now fail hard when run without the required Perl modules (SVN::Core etc.), whereas previously they would gracefully skip with exit code 0.

The issue affects all git-svn tests (t91xx and t915x series) when the Perl dependencies are missing. The new behavior immediately fails the test script when `git svn` commands error out, while the old behavior would recognize this as a legitimate skip condition. This wasn't caught in CI because those environments have the Perl modules installed.

Junio demonstrates the difference by showing the test output before and after the change - previously it would print a skip message and exit successfully (0), now it fails with a non-zero exit code. This reveals a tension between the new strict error checking and legitimate test skips for optional dependencies.

The core infrastructure improvement (enabling `set -e`) remains sound, but this case shows we need to adjust how optional-dependency tests handle their prerequisites under the new stricter regime. The fix will need to preserve the ability to skip tests gracefully while still catching genuine errors. This is the final edge case that needs addressing before the change can be considered complete.
