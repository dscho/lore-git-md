Junio C Hamano's RFC explores a gap in Git's content search capabilities for tracking string presence (not just changes) across file versions, particularly for "what's cooking" reports. Current tools like `git log -S` only show transitions while `git grep` requires manual range specification, making it hard to answer "when did this string appear in these file versions?" without guessing ranges or missing transitions.

Mirko Faina proposes a workaround using existing `git log -S` functionality with revision range specification to avoid guessing ranges. The approach involves identifying introduction/removal commits of a string (using `git log -S` with `--reverse` and `--max-count`) then using those ranges to show relevant history. Mirko notes an apparent bug where `--reverse` interacts unexpectedly with `-S` and `--max-count`. This provides a practical solution to Junio's use case for tracking topic names in "what's cooking" reports, though somewhat verbose. The technical details about commit ranges and flag interaction bugs would interest contributors working on revision walking or content search features. The discussion remains open for alternative approaches or fixes to the observed flag interaction issue.
