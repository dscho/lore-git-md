Junio Hamano has raised an interesting limitation in Git's content search capabilities. The current tools don't quite solve the specific problem of tracking when a particular string first appeared across multiple versions of a file. While `git log -S` shows when the string was added or removed, and `git grep` can find the string at specific points, neither cleanly answers the question "when did this text first appear in these file versions?" 

This came up when Junio wanted to trace when certain topic names first appeared in his "what's cooking" reports. The thread is currently an RFC (request for comments) rather than a concrete proposal, inviting discussion about how Git might better support this use case. As the maintainer has identified this as a real pain point, we can expect follow-up from contributors who specialize in Git's revision walking and content search subsystems. The discussion may lead to new functionality in `git log` or related tools.
