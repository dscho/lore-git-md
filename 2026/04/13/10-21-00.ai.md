Documentation patch clarifying git-interpret-trailers' format by removing RFC 822 references. This is the first of a 9-patch series from Kristoffer Haugsbakk that systematically updates the man page to better document trailer behavior, particularly around key format restrictions.

The patch removes comparisons to RFC 822 email headers, which were causing confusion about the expected format. The commit message explains that while trailers use a similar colon-separated key-value format, they are fundamentally metadata rather than email headers, and the RFC comparison was unnecessarily technical for most users. The diff shows the practical changes - removing the opening RFC 822 reference and a disclaimer about not following email header rules, while keeping the example-driven explanation of how trailers work.

This change sets up the documentation for subsequent patches that will more clearly define the actual trailer format rules. The series has already gone through review, with Junio Hamano approving this approach of focusing on the metadata aspect rather than email headers. The patch maintains all the technical content while making the documentation more accessible.
