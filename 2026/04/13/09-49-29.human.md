This is part 8 in Patrick Steinhardt's 12-patch series to prepare Git's test suite for `set -e` (errexit) mode. The series aims to make tests more robust by detecting errors that would otherwise be silently ignored.

The current patch fixes a specific case in t0008-ignores.sh where `grep -v` in a subshell would fail when no matches are found - an expected case that shouldn't fail the test. The change adds `|| true` to suppress the non-zero exit code from grep when it finds no matches, which will be needed once `set -e` is enabled.

This is a straightforward mechanical change that follows the pattern seen in earlier patches of the series - identifying cases where test scripts intentionally expect commands to fail, and modifying them to handle those cases gracefully under `set -e`. The patch is small and focused, touching only the specific test lines that need adjustment.

As with the rest of the series, this change maintains the existing test behavior while making it compatible with stricter error checking. The modification is low-risk since it only affects test infrastructure, not Git's core functionality.
