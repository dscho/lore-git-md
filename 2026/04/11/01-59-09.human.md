This is a technical follow-up in Lorenzo Pegorari's v5 patch series on promisor file handling during repacks, addressing the memory leak and API usage concerns raised by Junio C Hamano. The discussion focuses on the proper way to handle packfile index parsing in the `copy_promisor_content()` helper function.

Lorenzo confirms the memory leak was due to a missing `free()` call after `close_pack_index()` and has fixed it, making CI tests pass. He explains the function needs to create a temporary `packed_git` struct to check if specific objects exist in newly created packs, since these packs aren't yet in the repository's packfile list. The current approach using `parse_pack_index()` appears to be the only way to accomplish this, despite its low-level nature.

The exchange reveals this is a rare case where bypassing normal packfile APIs is necessary, and Lorenzo has identified a similar potential leak in another part of the codebase (http.c) that uses the same pattern. The discussion remains technical but productive, with the memory leak now resolved and the API usage justified, this appears to be the last remaining issue before the series can be merged.
