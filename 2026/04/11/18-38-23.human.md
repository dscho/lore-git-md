This is a technical review comment from Jeff King (Peff) on the final patch in Harald Nordgren's series implementing autostash behavior for `git checkout -m`. The series has already received maintainer approval and is now in the merge queue.

Peff points out a naming issue with the implementation's use of `CHECKOUT_AUTOSTASH` as a root-level ref. This violates Git's documented ref naming conventions, which require root-level refs to either end with `_HEAD` or be one of a few explicitly listed exceptions. He notes that while Git's enforcement of these rules currently has some holes, he's working on a series to tighten this up.

The comment suggests two possible paths forward: either add `CHECKOUT_AUTOSTASH` to the list of allowed exceptions (which the documentation states should not be extended), or choose a different name that conforms to the standard rules. Given that `MERGE_AUTOSTASH` is already an exception, following that pattern with `CHECKOUT_AUTOSTASH` might be the most straightforward solution, though Peff seems to prefer exploring a standards-compliant alternative if possible.

This is a relatively minor technical point that shouldn't block the series' merge, but does need resolution. The patch author will likely need to either adjust the ref name or coordinate with Peff on updating the documentation's list of exceptions.
