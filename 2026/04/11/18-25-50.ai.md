This is a review comment on patch 3/6 of Lorenzo Pegorari's v5 series about preserving promisor file contents during repacks. Tian Yuchen raises two technical points about the implementation details.

First, they question whether opening an empty promisor file just to immediately fill it is necessary, suggesting the helper function could be simplified since it's now static and only used in this specific context. Second, they point out a potential memory inefficiency in how the function processes file contents - the current implementation builds up a strbuf of all lines before writing, which could waste heap space for large files. They propose an alternative approach that writes lines directly to the destination file while tracking seen lines with a strset.

The review also hints at a broader architectural question about the helper function's design, noting it currently feels "a bit disjointed" and may warrant further discussion about its ultimate form. This comes after earlier versions had already seen the function's scope reduced from generic to static.

The feedback is constructive and focused on implementation details rather than the patch's core functionality, which remains sound. The memory usage concern is particularly relevant given the series' recent history with memory leak fixes. Yuchen's suggestions appear to be aimed at tightening up the code quality before final acceptance.
