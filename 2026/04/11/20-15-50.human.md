This is a documentation patch correcting an inaccuracy about `git am --message-id` behavior. Kristoffer Haugsbakk reverts part of their earlier commit that claimed the Message-ID header was added as a proper Git trailer (which would follow trailer block conventions). 

The patch explains that the Message-ID is actually appended directly after the commit message body in most cases, only behaving like a trailer when the message is subject-only or already has trailers. While this inconsistency could be considered a bug, the author opts for a documentation fix now since we're near the end of a release cycle.

The change removes the reference to git-interpret-trailers and rewords the description to be more accurate about the actual behavior. This is a straightforward correction to the man page that aligns documentation with reality, though it hints at a potential future cleanup of the underlying behavior.
