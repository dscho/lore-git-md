This is a test infrastructure patch that prepares some signal-handling tests to work correctly when `set -e` (exit immediately on error) is enabled. 

The patch modifies three test cases that verify Git dies with SIGPIPE (signal 13) under certain conditions. The original tests used a pattern of `command; echo $?` to capture the exit code, which would fail the whole test under `set -e` since the command is expected to fail. The new version uses `command && echo 0 || echo $?` to properly handle the expected failure case.

The changes affect two test files:
- `t/t0005-signals.sh` (two cases testing SIGPIPE behavior)
- `t/t3600-rm.sh` (one case testing `git rm` with SIGPIPE)

This is part of a larger 12-patch series (position 1/12) preparing the test suite for `set -e` usage, though the cover letter wasn't provided in this input. The changes are mechanical but important for making the tests robust when error handling is stricter.
