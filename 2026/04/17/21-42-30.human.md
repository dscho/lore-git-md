This is a review comment from Junio C Hamano (the Git maintainer) on Elijah Newren's performance optimization patch for `git cherry` in partial clones. The patch implements batch prefetching of blobs to avoid the performance penalty of individual on-demand fetches.

Junio questions whether the included design specification document (`investigations/cherry-prefetch-design-spec.md`) should be added to the project. He notes that while detailed, it may not be the right place for this level of implementation detail, which is typically either condensed into commit messages or omitted entirely. The document provides an extremely thorough explanation of the prefetching algorithm, edge cases, and testing approach - more than would normally be included in the project repository.

The patch itself (not shown in detail here) introduces a `prefetch_cherry_blobs()` function that temporarily swaps the hashmap comparison function to identify needed blobs without triggering fetches, then performs a single batch fetch. It includes careful handling of edge cases like merge commits, root commits, and binary files, along with new tests verifying the prefetch behavior.

This appears to be a minor point in an otherwise well-received patch from a trusted contributor (Elijah Newren) that follows established patterns for partial clone optimizations. The core technical approach seems sound and uncontroversial, with Junio's comment focusing only on documentation location rather than the implementation itself.
