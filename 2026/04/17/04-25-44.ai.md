This is a documentation patch from Junio Hamano that adds timestamp handling guidelines to Git's coding standards, specifically addressing platform differences in timestamp resolution. The patch was prompted by real-world issues encountered in Lorenzo Pegorari's promisor file repacking series, where macOS's lack of POSIX-compliant nanosecond-resolution timestamps caused problems.

Elijah Newren provided a surface-level review, pointing out only a minor grammatical nit ("need timestamp" -> "need a timestamp") which Junio has acknowledged and will incorporate. The review confirms the technical content is correct and uncontroversial, with no substantive feedback needed beyond the wording tweak.

The patch serves as preventative documentation to help future contributors avoid similar platform-specific timestamp handling issues. It explicitly states that macOS lacks the POSIX `st_mtim` field and recommends using the more portable `st_mtime` when second-level precision is sufficient. This guidance emerged from practical experience with the promisor repack series, showing how documentation improvements often follow from real-world implementation challenges.
