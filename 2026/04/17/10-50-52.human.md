This is patch 6/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch focuses on making test execution more robust by ensuring commands that might fail (like checking for program availability) are properly handled in conditionals rather than letting them trigger premature exit under `set -e`.

The changes touch various test scripts and library files, converting patterns like:
- Direct program execution checks (`svn >/dev/null 2>&1; if test $? -ne 1`) to conditional forms (`if ! svn help >/dev/null 2>&1`)
- Command execution with status capture to more robust forms using temporary variables
- Multi-line conditionals to properly handle error cases

The patch continues the series' careful, systematic approach to preparing the test suite for stricter error handling. It follows the same high standard as previous patches in the series, with clean, focused changes that maintain compatibility while improving robustness. The changes are mechanical but important for the overall goal of making test failures more reliable.

This patch has already benefited from thorough review in previous iterations and appears ready for merging as part of the complete series.
