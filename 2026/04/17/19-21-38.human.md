Bugfix for UTF-8 filename truncation in diffstat display. This is Junio C Hamano's review of Elijah Newren's patch addressing NULL dereference and out-of-bounds read vulnerabilities in the diffstat display code.

Junio notes a discrepancy in the commit date reference for f85b49f3d4a (the commit introducing the bug) between Elijah's message and his own records, though this appears to be a minor metadata issue rather than a substantive concern.

The review focuses on the technical approach to handling invalid UTF-8 sequences and control characters during filename truncation. Junio questions whether the patch's fallback behavior (showing the full untruncated name when invalid UTF-8 is detected) could be improved by instead truncating at the invalid byte and showing "..." rather than abandoning truncation entirely. He also suggests the control character handling could be made more consistent with this approach.

The tone is constructive and technical, typical of Junio's thorough style. While not blocking the patch, the review raises valid considerations about edge case handling that could potentially be addressed in a follow-up revision. The core fix for the security vulnerabilities remains sound.
