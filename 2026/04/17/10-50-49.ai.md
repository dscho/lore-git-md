This is patch 3/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch prepares the `stop_git_daemon()` helper function to work correctly with strict error checking enabled.

The changes address two specific issues that would cause the function to fail when `set -e` is active:
1. The `wait` command is expected to fail (since we're waiting for a killed process), but without error handling this would cause immediate exit under `set -e`. The patch adds `||` to capture the exit code.
2. The second `kill` call (via PID file) is likely redundant since we already killed the process, so the patch silences its failure with `|| :`.

The modifications maintain the existing behavior while making it compatible with strict error checking. The function still verifies the daemon exited with SIGTERM (15) and cleans up PID files, just with more robust error handling.

This is a straightforward mechanical change that's part of the larger, well-reviewed effort to improve test robustness by catching non-assertion errors. The patch follows the series' pattern of incrementally adapting test infrastructure components to work with `set -e`.
