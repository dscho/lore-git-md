This is the second patch in Patrick Steinhardt's 12-part series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch focuses on adapting the `test_must_fail()` helper function to work correctly with strict error checking.

The change modifies `test_must_fail()` to handle command failures gracefully when `set -e` is active. Previously, if the command failed, the shell would exit immediately due to `set -e` before the function could check the exit code. The new version captures the exit code explicitly with `|| exit_code=$?`, allowing the function to properly evaluate whether the failure was expected.

This is a mechanical but important preparation step in the larger effort to make the test suite more robust by ensuring errors are caught rather than silently ignored. The patch follows the careful, incremental approach seen throughout the series, with each component being adapted systematically before `set -e` is enabled globally in the final patch.

The change has already undergone thorough review from multiple contributors (Jeff King, SZEDER Gábor, and Junio Hamano) in previous iterations of the series, and this version appears to be the final polished form.
