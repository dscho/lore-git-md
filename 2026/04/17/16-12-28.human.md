This is a small bugfix patch for tig project (a text-mode interface for Git) that addresses a compiler warning. The patch changes a variable declaration to maintain const-correctness when calling strchr() on a const string.

The warning occurs because the code was assigning the result of strchr() (which returns a const char* when given a const char* input) to a non-const char* variable. The fix is straightforward - just make the pipe variable const to match. This doesn't change any behavior, it silences the compiler warning while being more type-correct.

The patch is clean and focused - it touches only the necessary line to fix the issue. While minor, these kinds of fixes help keep the project warning-free, which makes it easier to spot more serious warnings when they appear. The commit message could perhaps explain the change slightly more clearly, but the diff itself is self-explanatory for anyone familiar with C's const semantics.
