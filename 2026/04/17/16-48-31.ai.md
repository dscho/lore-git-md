This is a bugfix patch addressing an issue with `git rev-parse --bisect` when alternate bisect terms are used. The patch is part of a series (v3 2/2) but no cover letter was provided for context.

The core problem is that `rev-parse --bisect` currently hardcodes "good" and "bad" when looking up bisect refs, which fails when users specify alternate terms like "old" and "new". The fix reads the current bisect terms via `read_bisect_terms()` and uses them to construct the proper ref paths.

The patch includes:
1. Modifications to `builtin/rev-parse.c` to dynamically determine bisect ref paths
2. A new test case in `t/t1500-rev-parse.sh` that verifies the fix works with custom terms while ignoring the standard "good"/"bad" refs

The implementation appears clean and well-tested, with proper memory management (freeing allocated strings) and clear test coverage of the edge case. This is a real usability issue for anyone using alternate bisect terms, making the patch a straightforward improvement.
