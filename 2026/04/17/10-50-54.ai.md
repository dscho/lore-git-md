This is patch 8/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch fixes a specific test case in t0008-ignores.sh that would fail under strict error checking.

The issue occurs when `grep -v` runs in a subshell and finds no matches - normally this would exit with an error code, but the test suite currently relies on swallowing such errors. The patch modifies the grep call to use `|| :` (a no-op) to explicitly ignore any error, making the behavior compatible with `set -e` while maintaining the test's expectations.

This is a mechanical change that follows the pattern established in earlier patches of the series: identifying specific test patterns that would break under `set -e` and making minimal, behavior-preserving fixes. The change is straightforward and unlikely to be controversial, as it clearly documents the intent to ignore grep's exit code in this case.

The patch has already been reviewed as part of the larger series, with Jeff King, SZEDER Gábor, and Junio Hamano providing feedback on earlier versions. This iteration appears to be a final refinement addressing all previous concerns.
