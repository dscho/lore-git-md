This is the final patch in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch activates strict error checking that will cause tests to fail immediately if any command outside a test case fails, rather than silently continuing. This addresses a real problem where test suite typos (like misspelling `test_expect_success`) could go undetected.

The change is carefully scoped to only affect Bash 5+ due to inconsistent behavior in other shells and older Bash versions, particularly on macOS. The CI system is updated to ensure at least one job runs with Bash 5+ to validate the change. The series has undergone extensive review from key contributors (Jeff King, SZEDER Gabor, Junio Hamano) across multiple iterations, with all identified edge cases addressed in prior patches.

This represents a significant improvement in test robustness by catching errors that would previously be ignored. The conservative shell versioning approach and thorough preparatory work suggest this change is well-vetted and ready for merging. The patch maintains compatibility with other shells while providing stricter error checking where supported.
