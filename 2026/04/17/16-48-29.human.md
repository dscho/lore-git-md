This is a bugfix patch series addressing inconsistencies in Git's bisect functionality when using alternate terms (like "old"/"new" instead of "good"/"bad"). 

The series consists of two patches that work together to ensure all parts of the bisect machinery respect the configured terms:

1. The first patch fixes the `git bisect status` output to use the configured terms rather than hardcoded "good"/bad" references. This was the original motivation for the series.

2. The second patch addresses a related issue where `git rev-parse --bisect` was still using hardcoded "good"/bad" terms when looking up refs, which could cause problems when alternate terms were in use.

The patches have gone through three iterations with feedback from Phillip Wood and Junio Hamano, addressing memory leaks, improving test coverage, and refining commit messages. The changes look well-considered and the test additions demonstrate the fixes work as intended.

This appears to be a straightforward improvement to make the bisect feature more consistent when using alternate terminology. The changes are focused and the series seems ready for inclusion.
