Bugfix for UTF-8 filename truncation in diffstat display, addressing NULL dereference and out-of-bounds read vulnerabilities. This is the second iteration of Elijah Newren's fix for issues introduced in f85b49f3d4a (2026-01-16).

The patch introduces a safer utf8_ish_width() wrapper around utf8_width() that guarantees pointer advancement and non-negative return values. Key improvements from v1:
- Simplified approach using a wrapper function rather than separate checks
- Consistent handling of invalid UTF-8 and control characters
- Maintains the same behavior as utf8_strwidth() for invalid sequences
- The fix addresses two crash scenarios when core.quotePath=false:
  1. NULL dereference from invalid UTF-8 sequences (like bare 0xC0 byte)
  2. Out-of-bounds reads from control characters (like 0x01)

The patch includes two new test cases that demonstrate the failure modes by forcing truncation of problematic filenames with --stat-name-width. The solution appears well-considered, with the v2 iteration incorporating Junio's feedback to simplify the approach while maintaining safety. This looks ready for integration as an important stability fix for the diffstat display code.
