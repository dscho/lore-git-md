This is a follow-up in the ongoing discussion about fixing recursion limits in `contrib/subtree`, now touching on implementation language choices.

Colin Stagner responds to Ian Jackson's suggestion of using bash instead of POSIX sh for the `git-subtree` script. He notes that Debian's dash (the shell causing the recursion issues) is POSIX-compliant, and points out that Git's coding guidelines prefer POSIX constructs for portability. Colin argues that introducing bash would likely create more implementation inconsistencies rather than solving the root problem.

The exchange highlights the tension between quick fixes (switching shells) and sustainable solutions (algorithmic changes or rewrites). Colin's response maintains focus on his proposed algorithmic fix while acknowledging that a Rust/libgit2 implementation would be preferable from a readability and performance standpoint - though he jokingly notes Rust didn't exist when subtree was first written.

The discussion remains unresolved, with Junio Hamano's earlier comments about the component's maintenance status still looming over the technical debate. Colin's reply keeps the door open for both approaches - his shell fixes as an immediate solution and a potential Rust rewrite as a longer-term direction.
