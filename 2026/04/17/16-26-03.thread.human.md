This thread addresses a critical bug in Git's diffstat filename display logic that can cause crashes when processing malformed UTF-8 input with core.quotePath=false. The issue stems from a 2024 change (f85b49f3d4a) that added UTF-8-aware truncation but didn't properly handle edge cases. The current patch fixes two serious problems: a NULL pointer dereference when encountering invalid UTF-8 sequences and an out-of-bounds read with control characters. Elijah Newren contributed test cases demonstrating these failure modes by forcing truncation of problematic filenames. The solution adds proper bounds checking and falls back to showing untruncated names when invalid input is detected, providing a robust fix for this regression introduced in Git 2.54. The patch appears well-tested and clearly explained, addressing an important stability issue.
