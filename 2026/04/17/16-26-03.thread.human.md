This thread addresses a critical bug in Git's diffstat display that could cause crashes when processing filenames containing malformed UTF-8 sequences or control characters, particularly when core.quotePath is disabled. The issue stemmed from insufficient bounds checking in UTF-8-aware truncation logic introduced in Git 2.54.

Elijah Newren led the fix through three iterations, culminating in a v3 patch that introduces a utf8_ish_width() wrapper to safely handle both invalid UTF-8 and control characters while maintaining correct display width calculations. The solution includes comprehensive test coverage verifying protection against NULL dereferences (via malformed 0xC0 byte) and out-of-bounds reads (via C1 control characters 0xC2 0x9F).

Junio C Hamano has now reviewed and approved the final version, confirming the patch's robustness - particularly noting its careful handling of NUL termination for truncated multi-byte sequences. The fix addresses all concerns raised during review, including Lorenzo Pegorari's earlier feedback about test coverage. With this approval, the patch is ready for integration, resolving a potentially dangerous regression from Git 2.54's UTF-8 handling improvements.
