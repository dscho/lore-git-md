This thread addresses a critical security fix for UTF-8 filename handling in Git's diffstat display. The issue, introduced in Git 2.54, could cause crashes when processing malformed UTF-8 sequences or control characters in filenames with core.quotePath disabled.

Elijah Newren has led the fix through three iterations, with v3 now finalizing the solution. The patch introduces a new utf8_ish_width() wrapper that safely handles both invalid UTF-8 (advancing 1 byte) and control characters (returning width 0) while maintaining correct behavior for valid UTF-8. The implementation has been thoroughly tested, including edge cases that trigger the original vulnerabilities - malformed UTF-8 sequences for NULL dereference and C1 control characters for out-of-bounds reads.

Lorenzo Pegorari provided key review feedback that improved the test coverage, particularly around control character handling. Junio C Hamano's technical requirements were satisfied in v2, and v3 further refined the test cases to use more reliable C1 control character sequences (0xC2 0x9F) that better expose the memory safety issues under ASan. The patch appears ready for integration with its comprehensive test coverage and clear documentation of changes from previous versions.
