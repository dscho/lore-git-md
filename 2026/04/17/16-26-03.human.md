Bugfix for diffstat UTF-8 handling that could cause crashes or out-of-bounds reads. This patch from Elijah Newren addresses two dangerous edge cases in the diffstat display code introduced by a recent UTF-8 scaling improvement (f85b49f3d4a).

The issue occurs when:
1. Invalid UTF-8 sequences cause a NULL pointer dereference in the truncation logic
2. Control characters cause the code to read past the end of the string

The fix adds proper bounds checking and NULL pointer handling while maintaining the intended truncation behavior. New tests verify both failure modes by forcing truncation of filenames containing invalid UTF-8 (0xC0 byte) and control characters (0x01 byte) with core.quotePath=false.

This is a relatively small but important fix for a crash that could be triggered by specially crafted filenames. The patch demonstrates good defensive programming with clear test coverage of the edge cases. Given Elijah's expertise in the diff/merge area and the straightforward nature of the fix, this seems likely to be merged quickly.
