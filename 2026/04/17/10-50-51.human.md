This is patch 5/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch focuses on fixing conditional test execution patterns that would break under strict error checking.

The change converts problematic `test ... && test_expect_success` patterns into proper `if test ...` conditionals in two test scripts (t4032-diff-inter-hunk-context.sh and t7450-bad-git-dotfiles.sh). The original pattern would cause the overall statement to fail when skipping the test, which would trigger `set -e` to exit. The new version properly handles skipped tests while also improving readability.

This is a mechanical but important preparation step for the larger `set -e` effort, ensuring tests will continue to work as intended when error checking is enabled. The changes are straightforward and well-contained, modifying only the conditional logic while preserving the actual test content.

The patch follows the series' pattern of careful, incremental changes to make the test suite robust under stricter error handling. It has already been reviewed as part of the complete series, with Jeff King, SZEDER Gábor, and Junio Hamano providing feedback on earlier versions.
