This is a bugfix follow-up addressing edge cases in UTF-8 filename truncation for diffstat display. Elijah Newren responds to Junio C Hamano's review of his patch fixing NULL dereference and out-of-bounds read vulnerabilities in the diffstat display code.

1. The current patch falls back to showing the full untruncated filename when encountering invalid UTF-8 sequences, which Junio suggests could be improved by truncating at the invalid segment while preserving valid portions
2. The control character handling strategy (immediate truncation before the problematic byte) might serve as a better model for invalid UTF-8 cases as well

Elijah acknowledges the feedback and indicates he'll send a revised version that either:
- Implements Junio's suggestion of partial truncation with "..." markers
- Or introduces a safer utf8_width() wrapper that avoids NULL returns entirely

The exchange remains technical and constructive, with both parties focused on finding the most robust solution. The original bug was introduced in f85b49f3d4a (2026-01-16) when UTF-8-aware truncation was added to diffstat display. The fix is particularly important when core.quotePath=false, as this bypasses Git's normal filename sanitization.
