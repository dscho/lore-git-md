This is a bugfix patch for Git's bisect functionality, specifically addressing inconsistent terminology in status messages when using alternate bisect terms.

The patch fixes an issue where hardcoded "good"/"bad" terms would still appear in some bisect output messages even when users had specified alternate terms (like "new"/"old"). This could create confusing situations where the status message would say "waiting for bad commit" while the actual command needed was "bisect old".

Key changes:
- Updates status messages in builtin/bisect.c to use the selected terms consistently
- Adds corresponding test cases in t6030-bisect-porcelain.sh to verify the new behavior
- Maintains backward compatibility with existing bisect workflows

The patch is well-structured with:
- Clear commit message explaining the problem and solution
- Focused changes limited to the bisect output messages
- Comprehensive test coverage for the new behavior
- No behavioral changes beyond the message wording

This is part of a 2-patch series (1/2) and follows up on previous discussion about bisect terminology. The changes appear straightforward and uncontroversial, addressing a clear inconsistency in the user interface.
