This is a small bugfix patch addressing a compiler warning in Tig (a Git repository browser that's a separate project from Git itself). The patch fixes a const-correctness issue in Tig's diff.c file where a `const char*` was being assigned to a non-const `char*` variable when calling `strchr()`.

The warning occurs because `strchr()` returns a pointer into the original const string, but the code was storing it in a non-const pointer. The fix is straightforward - just declare the `pipe` variable as `const char*` to match the input string's constness. This maintains the const-correctness chain from the input parameter through to the pointer variable.

The patch is minimal (just one line changed) and clearly correct - it's the kind of mechanical fix that would typically be merged without much discussion. Since this is for Tig rather than Git core, it would be up to the Tig maintainers to pick it up, though Git contributors might review it if they also work on Tig.
