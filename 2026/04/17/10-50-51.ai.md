This is patch 5/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch focuses on fixing conditional test execution patterns that would cause problems when strict error checking is enabled.

The change converts two problematic test constructs that used `test ... && test_expect_success` into proper `if` conditionals. The issue with the original pattern is that when the first test fails (causing the condition to be false), the overall statement would still exit with a failure status - which would trigger `set -e` to abort execution. The new version properly handles these cases by making the conditional execution explicit.

The patch modifies two test scripts:
- t4032-diff-inter-hunk-context.sh: Changes file existence checks before test execution
- t7450-bad-git-dotfiles.sh: Updates conditional tests for symlink handling

This is a mechanical but important change that ensures the test suite will continue working correctly once `set -e` is enabled. The patch follows the series' pattern of careful, incremental preparation of the test infrastructure. It has already been reviewed by Jeff King and others in previous iterations of the series.
