Bugfix addressing UTF-8 truncation vulnerabilities in diffstat display. This v2 patch from Elijah Newren refines the solution to the NULL dereference and out-of-bounds read issues in the diffstat filename truncation logic.

The patch introduces a new utf8_ish_width() wrapper function that guarantees safe string advancement and non-negative width returns, addressing both failure modes in one unified approach. This replaces v1's more complex solution that handled invalid UTF-8 and control characters separately. The wrapper:
- Advances by one byte and returns width 1 for invalid UTF-8 (matching utf8_strwidth()'s fallback)
- Returns 0 for control characters (matching utf8_strnwidth() behavior)
- Always keeps the string pointer valid

The implementation now cleanly handles both edge cases while maintaining the original truncation behavior for valid UTF-8. The test cases (one for invalid UTF-8, one for control characters) remain unchanged from v1, demonstrating the fixes under core.quotePath=false with forced truncation via --stat-name-width.

This version incorporates Junio C Hamano's feedback from the v1 discussion, converging on a solution that treats both invalid UTF-8 and control characters consistently while being simpler than the initial approach. The patch appears ready for integration with its comprehensive test coverage and clear commit message documenting the changes from v1.
