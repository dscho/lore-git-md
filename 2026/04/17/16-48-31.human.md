Bugfix for `git rev-parse --bisect` with custom bisect terms.

This patch fixes an issue where `git rev-parse --bisect` fails to work when alternate bisect terms (like "old/new" instead of "good/bad") are used. The command was hardcoded to look for "refs/bisect/bad" and "refs/bisect/good", ignoring any custom terms specified in the bisect session.

The fix modifies `builtin/rev-parse.c` to read the current bisect terms and use them when constructing ref paths. A new test case verifies the behavior with custom terms, showing that it now correctly lists refs using the alternate terms while ignoring any standard "good/bad" refs that might exist.

The patch is straightforward and well-tested, with clean memory management (freeing allocated strings) and clear test coverage of the fixed behavior. This is part of a series (v3 2/2) but stands alone as a complete fix.
