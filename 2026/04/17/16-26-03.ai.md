Bugfix targeting the diffstat UTF-8 truncation logic. This patch addresses two serious issues in the diffstat filename display code that can lead to crashes when processing malformed input with core.quotePath=false.

The problem stems from f85b49f3d4a (2024-10-27) which added UTF-8-aware filename truncation but didn't properly handle edge cases. The patch fixes:
1. A NULL pointer dereference when encountering invalid UTF-8 sequences (like a bare 0xC0 byte)
2. An out-of-bounds read when processing control characters (like 0x01) that could cause the code to read past string boundaries

Elijah Newren provides two new test cases that demonstrate the failure modes by forcing truncation of problematic filenames with --stat-name-width. The fix adds proper bounds checking and fallback behavior when invalid UTF-8 is detected, falling back to showing the full untruncated name rather than crashing.

The patch is well-motivated with clear commit message explanations of both the problem and solution. The test coverage appears thorough, exercising both failure modes with core.quotePath=false to bypass Git's normal quoting protections. This looks like an important stability fix for a regression introduced in the v2.54 cycle.
