This is patch 4/12 in Patrick Steinhardt's series to enable `set -e` (errexit) in Git's test suite for Bash 5+. The patch focuses on making `git config --unset` calls resilient to failures when the configuration variables being unset don't exist.

The changes modify three test scripts where `git config --unset` was used to clean up test state, adding `|| :` to suppress errors when the config keys are already unset. This prevents the test suite from failing under `set -e` when these cleanup operations encounter missing keys. The modifications are straightforward mechanical changes that maintain the original cleanup intent while accommodating the new strict error checking.

The patch is part of the broader effort to make the test suite more robust by ensuring errors are caught rather than silently ignored. It follows the incremental approach seen throughout the series, addressing one specific category of potential failures before enabling `set -e` in later patches. The changes are minimal and focused, with each modified line clearly serving the goal of making the tests work correctly under stricter error handling.
