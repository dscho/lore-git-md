This is a review comment from Junio C Hamano (the Git maintainer) on Elijah Newren's performance optimization patch for `git cherry` in partial clones. The patch is part of a 3-part series to improve performance by batch-prefetching blobs rather than fetching them individually.

Junio questions whether the included design specification document (`investigations/cherry-prefetch-design-spec.md`) should be added to the project. He notes that while detailed, it doesn't serve as general documentation about how `git cherry` works, and much of its content would typically belong in the commit message rather than a separate file. He's unsure of the document's long-term value to the project.

The patch itself implements batch prefetching for `git cherry` in partial clones by:
1. Temporarily swapping the hashmap comparison function to identify blob OIDs needed for patch ID computation
2. Collecting these OIDs from both upstream and head-side commits
3. Performing a single batch fetch of all required blobs
4. Restoring the original comparison function

The implementation includes careful handling of edge cases and comes with new tests verifying the behavior in partial clones. Junio doesn't raise any technical concerns about the implementation itself - his comment is solely about whether the design spec document belongs in the project.

This appears to be a minor documentation-related nit on an otherwise well-received performance optimization patch from a trusted contributor. The core technical approach seems sound and follows established patterns from similar optimizations in other Git commands.
