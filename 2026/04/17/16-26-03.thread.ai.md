Thread identity: Bugfix for UTF-8 filename truncation in diffstat display, addressing NULL dereference and out-of-bounds read vulnerabilities introduced in f85b49f3d4a (2024-10-27).

Core problem: When core.quotePath=false, malformed UTF-8 sequences (like bare 0xC0 byte) or control characters (like 0x01) in filenames could cause crashes during diffstat truncation due to insufficient bounds checking in the UTF-8-aware truncation logic added in Git 2.54.

Current status: Patch v1 proposed with fix and test coverage. Not yet picked up by maintainer.

Key technical details: Fix modifies diff.c's filename display logic to:
1. Add bounds checking when processing UTF-8 sequences
2. Fall back to full untruncated name display when invalid UTF-8 detected
3. Handle control characters safely during truncation
Test cases added in t4014-diff-rename.sh demonstrate both crash scenarios using --stat-name-width with problematic filenames.

Open questions: None raised yet - appears to be a straightforward bugfix for a clear regression.

Participant positions: Elijah Newren authored the patch with comprehensive test coverage demonstrating both failure modes and the fix's effectiveness.
