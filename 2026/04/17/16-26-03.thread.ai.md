Thread identity: Bugfix for UTF-8 filename truncation in diffstat display, addressing NULL dereference and out-of-bounds read vulnerabilities introduced in f85b49f3d4a (2026-01-16, corrected from initial 2024-10-27 reference).

Core problem: When core.quotePath=false, malformed UTF-8 sequences (like bare 0xC0 byte) or control characters (like 0x01) in filenames could cause crashes during diffstat truncation due to insufficient bounds checking in the UTF-8-aware truncation logic added in Git 2.54.

Current status: Patch v1 under review by Junio C Hamano, who has engaged with edge case handling strategies. Not yet picked up for integration.

Key technical details: Fix modifies diff.c's filename display logic to:
1. Add bounds checking when processing UTF-8 sequences
2. Currently falls back to full untruncated name display when invalid UTF-8 detected (Junio suggests alternative approach)
3. Handles control characters safely during truncation (immediate truncation before problematic byte)
Test cases in t4014-diff-rename.sh demonstrate crash scenarios using --stat-name-width with problematic filenames.

Open questions: Junio proposes considering whether invalid UTF-8 sequences should trigger partial truncation (showing valid prefix + "...") rather than full fallback, and whether the control character handling strategy could be extended to the UTF-8 case. No resolution yet on these suggestions.

Participant positions: Elijah Newren authored the patch with comprehensive test coverage. Junio C Hamano provided substantive technical review focusing on edge case handling strategies, suggesting potential improvements while acknowledging the core fix's correctness.

Related work: Builds on f85b49f3d4a (UTF-8 truncation for diffstat) from 2.54 cycle. Fixes a regression that bypassed Git's normal core.quotePath protections.
