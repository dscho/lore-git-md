This is a bugfix series addressing inconsistencies in Git's bisect functionality when using alternate terms (like "old"/"new" instead of the default "good"/"bad"). The two patches work together to ensure all parts of the bisect machinery respect the configured terms.

The first patch updates the bisect status output to use the configured terms rather than hardcoded "good"/"bad" strings. The second patch makes `git rev-parse --bisect` similarly respect the alternate terms when looking up refs. Both patches include new tests to verify the behavior.

The series has gone through three iterations with feedback from Phillip Wood and Junio Hamano, addressing memory leaks, improving test coverage, and refining commit messages. The changes appear well-considered and the test coverage is thorough, exercising both the status output and ref lookup cases.

This is part of ongoing work to make the bisect subsystem more flexible with its terminology. The patches are relatively small and focused, touching only the specific areas where hardcoded terms were found. The changes maintain backward compatibility while fixing the inconsistency for users who configure alternate terms.
