This is a discussion about test infrastructure modernization in preparation for a potential future change to Git's bare repository discovery behavior. Johannes Schindelin responds to Junio C Hamano's feedback on his 17-patch series that updates Git's test suite to explicitly handle bare repositories rather than relying on implicit discovery.

Johannes clarifies that his commit message's "may well" phrasing was intentional - no formal decision has been made about changing the default `safe.bareRepository` behavior, though he sees Git 3.0 as a natural inflection point for such a change. He pushes back slightly on Junio's suggestion to document the behavior change first, explaining that a proper proposal would require more than just documentation updates - it would need code changes guarded by `WITH_BREAKING_CHANGES` and full test suite validation.

The email references Johannes' GitHub pull request #2072 which contains the complete set of changes needed to actually implement the behavior change, including the breaking changes documentation Junio requested. Johannes indicates he plans to propose this larger change later to formally start the discussion about whether to change the default behavior in Git 3.0.

Key technical points: the test modernization work has standalone value as "spring cleaning" regardless of the eventual policy decision, and the implementation approach (using `--git-dir`, `GIT_DIR` exports, and config overrides) has been validated across shell, Perl and Python test components. The thread shows the project's careful approach to behavior changes - even preparatory test updates receive scrutiny for both technical correctness and broader project implications.
