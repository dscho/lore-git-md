This is the final patch in a feature series introducing parallel hook execution, adding support for using all available CPU cores when configured with `-1`. The patch allows `hook.jobs`, `hook.<event>.jobs`, and the `-j` CLI flag to accept `-1` as a value, which resolves to the number of online CPUs (matching conventions used elsewhere in Git like `fetch.parallel`). Negative values other than `-1` are rejected with warnings for config settings or fatal errors for CLI usage.

The implementation adds proper validation and resolution of the `-1` value at parse time, ensuring the rest of the code always works with positive counts. The patch includes thorough test coverage verifying the behavior works correctly across all configuration layers (global, per-event, and CLI) and properly warns about invalid values. Documentation is updated to reflect the new `-1` option.

This completes the parallel hooks functionality that has been through multiple review iterations, with all core technical issues resolved and maintainer approval. The series represents a significant enhancement to Git's hook system, providing flexible parallel execution while maintaining backwards compatibility through careful design.
