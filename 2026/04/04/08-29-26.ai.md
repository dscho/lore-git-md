This is patch 4/12 in a feature series introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The patch implements the core parallel execution logic while maintaining backwards compatibility.

The patch adds parallel execution support by removing the hardcoded jobs=1 limit in run_process_parallel(). Hooks now run in parallel when:
1. The hook.jobs config is >1
2. Each hook explicitly opts in via hook.<name>.parallel=true
3. No hooks in the event are marked as non-parallelizable (handled in a follow-up patch)

The implementation includes comprehensive configuration handling with multiple layers of control:
- Global hook.jobs default (defaulting to serial execution)
- Per-hook parallel flags (opt-in)
- CLI -j/--jobs override (takes precedence)
- Special handling for hooks requiring separate output streams (still serial-only in this patch)

Test coverage verifies the parallel/serial behavior under various configurations, including cases where one non-parallel hook forces serial execution for the entire event. The tests use a clever sentinel/detector pattern to observe execution timing.

This is a well-structured patch that clearly builds on prior work in the series (referencing the upcoming RUN_HOOKS_OPT_INIT_FORCE_SERIAL marking) while leaving room for future improvements (output stream handling).
