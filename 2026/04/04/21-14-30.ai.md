This is a feature proposal (v2) to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash. The patch introduces a new config option `checkout.switchDetach` that, when enabled, makes `git switch` automatically detach HEAD when given a commit ID or tilde reference (like `branch~2`), just like `git checkout` does by default.

The v2 patch addresses review feedback from Pablo and D. Ben Knoble in several ways: it clarifies the commit message to better explain the motivation (some users stick with `checkout` due to this behavioral difference), improves documentation wording to focus on effect rather than implementation, fixes style nits in comments and whitespace, and uses `git config --unset` in tests rather than setting to false. Most significantly, it provides technical justification for why a new `switch_detach` flag is needed rather than reusing `force_detach` - attempting to reuse the existing flag caused test failures and broke branch switching functionality.

The implementation remains straightforward, adding the config check in `cmd_switch()` and modifying the relevant conditionals in `update_refs_for_switch()`, `die_expecting_a_branch()`, and `checkout_branch()`. The tests verify both enabled and disabled config states, checking HEAD detachment status after various switch operations. The patch also updates the advice message to mention the new config option when suggesting `--detach`.

While the technical implementation appears sound, the core design question remains open: whether configuration is the right approach versus changing the default behavior, and how to balance user preference with scripting needs. The v2 patch strengthens the case for the config approach by demonstrating the behavioral nuances that make a simple flag reuse impractical.
