This is part 2 of a 3-patch series continuing the `the_repository` removal effort in the refs subsystem. The patch removes usage of the global `the_hash_algo` variable in `refs.c`, replacing it with repository-specific hash algorithms obtained from either the transaction's ref_store or the repository parameter.

The changes are mechanical but important for eliminating global state. The patch updates several key functions to use repository-specific hash algorithms:
- `ref_transaction_create()` and `ref_transaction_delete()` now use the hash algo from `transaction->ref_store->repo`
- `repo_get_submodule_ref_store()` uses the passed repository's hash algo
- `transaction_hook_feed_stdin()` and `migrate_one_ref()` also switch to the transaction's repository hash algo

The diff shows straightforward replacements of `the_hash_algo` with the appropriate repository-specific versions. This follows the established pattern in the ongoing effort to remove global state, maintaining existing behavior while making the code more explicit about its dependencies. The patch appears well-contained and focused, touching only the necessary changes to eliminate the hash algorithm global in the refs subsystem.
