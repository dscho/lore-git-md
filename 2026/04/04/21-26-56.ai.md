This is a discussion response in the thread about making `git switch`'s commit hash behavior configurable to match `git checkout`'s detach behavior. Thibaud CANALE replies to D. Ben Knoble's concerns about script reliability with the proposed `checkout.switchDetach` config option.

The response clarifies that the change is narrowly scoped to match `git checkout`'s behavior for non-branch references, with test cases verifying this. CANALE notes the feature is primarily for easing transition for users still on `git checkout`, not something they personally need. They also mention the Windows environment motivation, though clarify they can't test Windows builds themselves.

The exchange highlights the tension between configurability (helping users transition) and script reliability (where predictable behavior matters). CANALE's position is that the impact on scripts would be minimal since the narrow scope matches existing `git checkout` behavior, and the feature serves a specific user transition need. The technical implementation details (new flag vs reuse, test coverage) were addressed in the v2 patch, leaving the higher-level question of whether configurability is the right approach versus a behavior change.
