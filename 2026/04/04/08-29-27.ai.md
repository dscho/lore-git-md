This is a feature patch (5/12) in Adrian Ratiu's parallel hook execution series, specifically addressing the pre-push hook's special output handling. The patch is part of the larger effort to enable parallel hook execution while maintaining backwards compatibility.

The pre-push hook has historically kept stdout and stderr separate (unlike other hooks) to support tools like git-lfs. This patch allows parallel execution of pre-push hooks by automatically merging stdout into stderr when parallelism is requested (hook.jobs > 1 or -jN flag), while maintaining the old behavior when running serially. The implementation adds a new `merge_output_if_parallel()` helper that sets stdout_to_stderr=1 when jobs > 1, removing the need for special extension infrastructure.

Key technical points:
- Documents the behavior change in config/hook.adoc
- Adds comprehensive tests verifying both serial (backwards-compatible) and parallel modes
- Confirms parallel execution works by checking hook ordering in tests
- Maintains the transport.c default of separate streams unless explicitly overridden

The patch builds on prior work in the series and has been reviewed, with all technical concerns addressed. It represents a careful balance between introducing new functionality while preserving compatibility with existing hook implementations. The test coverage is thorough, including both output stream behavior and parallel execution verification.
