This is a discussion response in the ongoing thread about making `git switch`'s behavior configurable to match `git checkout` when given a commit hash. The patch author, Thibaud CANALE, is responding to concerns raised by D. Ben Knoble about potential impacts on scripting use cases.

The core proposal would add a `checkout.switchDetach` config option to make `git switch` behave like `git checkout` by default when given a commit hash (detaching HEAD rather than requiring `--detach`). In this response, Thibaud acknowledges the scripting concerns but argues the impact would be minimal since the behavior only affects non-branch references and matches existing `git checkout` behavior. They note the change is primarily aimed at easing transition for users still accustomed to `git checkout`'s behavior, particularly in Windows environments where they cannot test the changes themselves. 

The discussion highlights the tension between configurability for interactive use and predictable behavior for scripting. While the technical implementation appears sound (with tests verifying both config states), the thread remains open questions about whether configuration is the right approach versus changing defaults, and how to balance different use cases. The author maintains this is a feature for interactive users rather than script authors, suggesting scripts relying on the current behavior could explicitly disable the config if needed.
