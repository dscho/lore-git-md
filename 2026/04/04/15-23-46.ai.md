This is a follow-up review of an RFC patch proposing to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash. Pablo provides detailed feedback on Thibaud CANALE's initial proposal to add a `checkout.switchDetach` config option.

Pablo identifies several issues with the patch submission:
1. Commit message style needs work - should use imperative mood and better explain the motivation
2. Documentation wording could be clearer about the effect rather than the implementation
3. Code style nits around comments and whitespace
4. Questions whether the new `switch_detach` flag is truly needed versus reusing `force_detach`
5. Test improvements around cleanup and description clarity

The review is thorough but raises an important design question about whether introducing a new config option is the right approach versus potentially reusing existing flags. Pablo suggests the author revisit the Documentation guidelines and resubmit with these fixes.

This continues the discussion from the initial RFC, focusing on implementation details rather than the high-level concept. The core proposal remains to make `git switch`'s commit hash behavior configurable to match `git checkout`'s default detach behavior.
