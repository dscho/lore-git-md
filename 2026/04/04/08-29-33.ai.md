This is a feature patch (11/12) in Adrian Ratiu's parallel hook execution series, introducing a high-level `hook.<event>.enabled` configuration switch to disable all hooks for a given event. The patch builds on the series' comprehensive hook control system, adding another layer of configuration precedence.

The new switch acts as a master kill-switch for entire hook events, overriding individual `hook.<friendly-name>.enabled` settings when set to false. Disabled hooks are clearly marked in `git hook list` output with an "event-disabled" prefix, shown before the hook name (and before any scope indicator when using `--show-scope`). The implementation carefully handles naming collisions between event names and friendly-names, with fatal errors for known event name conflicts and warnings for potential unknown event ambiguities.

The patch includes extensive test coverage in t/t1800-hook.sh, verifying behavior for both known and unknown event names, interaction with per-hook disabled states, and correct display in the listing command. The implementation stores disabled events in a new `disabled_events` string list in the repository struct, with proper cleanup in `repo_clear()`.

This represents the penultimate patch in the series, with all core technical issues resolved and maintainer acks secured. The careful attention to backwards compatibility and clear user feedback (through warnings and listing output) suggests this will integrate smoothly while providing administrators with robust control over hook execution. The only remaining patch (12/12) adds `-1` support for CPU core count detection to complete the parallelization feature set.
