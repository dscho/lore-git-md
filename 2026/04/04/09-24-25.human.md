This is a feature patch (v2) from Pablo Sabater improving Git's commit graph visualization in `git log --graph` output. The change addresses how commits with excluded parents (including root commits) are displayed, preventing misleading vertical alignment of unrelated commit lineages.

The core issue is that current graph output can make unrelated commits appear connected when their parents aren't shown. The solution introduces a placeholder mechanism that keeps parentless commits "alive" for an extra row via an `is_placeholder` flag in graph columns, forcing proper indentation of subsequent commits. This handles both true root commits and commits with parents outside the displayed range through a unified "seems_root" concept.

The patch includes comprehensive test cases demonstrating improved output for:
- Simple root commits
- Multiple parentless commits
- Complex merge scenarios (2-4 parent merges)
- Cascading indentation of disconnected roots
- Commits with excluded parents (not roots)

This v2 iteration expands the scope from just root commits to all parentless cases per Junio's feedback, fixes test portability issues from v1, and adds thorough test coverage. The implementation touches the finicky graph rendering subsystem but appears well-considered, with clear before/after examples showing the visual improvements. Some minor diagonal line rendering artifacts remain but could be addressed in follow-up work.

The change looks like a solid improvement to graph visualization that should make complex histories clearer, especially when viewing partial commit ranges. Reviewers will likely scrutinize edge cases around merge display and ASCII-art constraints, but the approach seems sound.
