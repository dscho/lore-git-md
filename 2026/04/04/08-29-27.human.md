This is a feature patch (5/12 in the series) enabling parallel execution for the pre-push hook while maintaining backwards compatibility. The pre-push hook has historically kept stdout and stderr separate (unlike other hooks), which prevented parallelization since run-command needs merged streams to properly buffer and de-interleave output.

The patch introduces a key compromise: when running serially (jobs=1), pre-push maintains its original behavior with separate streams, but when parallel execution is requested (via hook.jobs, hook.<event>.jobs, or -jN), stdout is automatically merged into stderr. This change is documented in the config/hook.adoc man page and implemented via a new merge_output_if_parallel() helper.

The implementation includes thorough test coverage in t/t1800-hook.sh, including cases verifying the parallel/serial behavior switch and output stream handling. The patch builds on prior work in the series (particularly the jobs configuration system) and has received maintainer acks, with all technical concerns addressed in previous iterations. This represents a careful balance between modernization and backwards compatibility for a widely-used hook.
