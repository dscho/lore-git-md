This thread addresses a segmentation fault in `git diff --no-index` when comparing large files outside a repository. The crash occurs when accessing the object database's transaction system, which isn't initialized in repository-less mode. Initially, Luca Stefani proposed a targeted solution to gate object storage operations, which Tian Yuchen confirmed as correct. Jeff King (Peff) then suggested a more comprehensive fix at the transaction layer to handle NULL sources gracefully, potentially preventing similar issues elsewhere.

The discussion has now taken a turn toward architectural considerations. Yuchen responded to Peff's proposal with concerns about silent data loss if NULL sources were handled silently, suggesting instead that such cases should trigger a `BUG()` to fail explicitly. This reflects a tension between robustness (Peff's preference for handling edge cases) and explicit failure modes (Yuchen's conservative approach). The thread awaits input from Justin Tobler, the original author of the transaction interface, to help resolve whether the fix should be narrow (focused on `diff --no-index`) or broad (changing transaction behavior). The outcome may influence how Git handles repository-less operations more generally, particularly for commands like `git hash-object` and `git mktag` that also operate outside repository contexts.
