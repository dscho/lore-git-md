This is the third patch in a 12-part series introducing parallel hook execution, building on Adrian Ratiu's earlier work on configurable hooks. The patch adds the foundational plumbing for a global `hook.jobs` configuration that sets the default parallelism level for all hooks, with finer-grained per-hook and per-event controls to be added in later patches.

The implementation introduces a `hook.jobs` config key that accepts positive integers (with warnings for invalid values) and stores the parsed value in the repository's `hook_jobs` field. The documentation is updated to describe this new configuration option, though it will be expanded in subsequent patches. The patch includes careful handling of edge cases like zero values and invalid inputs, with appropriate warning messages.

This is primarily infrastructure work - the cached `hook_jobs` value isn't yet used in this patch, but will be referenced by later patches in the series. The change follows Git's standard config parsing patterns and includes the necessary updates to repository.h to store the new configuration value. The patch maintains backwards compatibility by defaulting to serial execution (value of 1) when the config is unset.
