Thread identity: Bug report about segmentation fault in `git diff --no-index` when comparing large files outside repository context.

Core problem: When comparing files directly with `git diff --no-index`, if either file exceeds `repo_settings_get_big_file_threshold()`, Git crashes with NULL pointer dereference in object database handling due to `the_repository->objects` being NULL in this mode. Expected behavior would detect binary files and show "binary files differ" message instead.

Technical details: Crash occurs in `index_fd()` when attempting to access `the_repository->objects->transaction`. Tian Yuchen's initial analysis identified the issue stems from unconditional access to repository object store in `object-file.c`'s `index_fd()` function during large file handling. Luca Stefani followed up with a concrete fix proposal that checks `INDEX_WRITE_OBJECT` flag before object database operations, since `--no-index` diffs only need hash computation, not object storage. This solution would maintain existing behavior while preventing the NULL dereference.

Current status: Bug is confirmed with technical analysis and now a proposed fix. The solution modifies `index_fd()` to properly handle NULL repository context when operating in `--no-index` mode by gating object storage operations behind `INDEX_WRITE_OBJECT` check. No maintainer response yet, but the technically sound analysis and focused fix make this likely to attract attention from diff or object-database experts.

Key files/subsystems: diff machinery (`diff.c`), object database handling (`object-file.c`), `--no-index` mode implementation. The fix specifically targets `object-file.c` to properly handle repository-less operations.

Open questions: Whether maintainers will accept this focused fix or request a different architectural approach. Also whether this bug indicates similar NULL-dereference risks elsewhere in the codebase when operating without a repository.

Participant positions: Tian Yuchen provided the initial technical breakdown of the issue. Luca Stefani built on this with a concrete implementation proposal that aligns with the analysis. Both demonstrate clear understanding of the object database interaction requirements in repository-less operations.
