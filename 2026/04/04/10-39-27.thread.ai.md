Thread identity: Bug report about segmentation fault in `git diff --no-index` when comparing large files outside repository context.

Core problem: When comparing files directly with `git diff --no-index`, if either file exceeds `repo_settings_get_big_file_threshold()`, Git crashes with NULL pointer dereference in object database handling due to `the_repository->objects` being NULL in this mode. The discussion has evolved from a simple fix to considering architectural implications for repository-less operations.

Technical details: The crash occurs in `index_fd()` when accessing `the_repository->objects->transaction`. Two solution approaches are now on the table: 1) Luca Stefani's targeted fix modifying `object-file.c` to gate object storage operations behind `INDEX_WRITE_OBJECT` check, and 2) Jeff King's proposed broader fix at the transaction layer (tracing to commit ce1661f9da) to make the transaction system handle NULL sources gracefully, potentially preventing similar bugs elsewhere. The latter would involve establishing a "noop" transaction state or adding NULL checks at transaction begin.
