This is a feature patch (8/12 in the series) adding per-event job count configuration to Git's hook system. The patch introduces `hook.<event>.jobs` settings that override the global `hook.jobs` value for specific hook events, allowing finer-grained control over parallel execution. For example, users can now configure `post-receive` hooks to run with 4 parallel jobs while keeping other events at the global default.

The implementation adds a new `event_jobs` strmap to the repository struct to cache per-event job counts, with careful handling of config parsing and validation. The documentation clearly explains the precedence rules and warns about the common pitfall of confusing hook friendly-names with event names in the key. Three new test cases verify the behavior: overriding global jobs, forcing serial execution per-event, and ensuring parallel flags are still required even with per-event job counts.

This patch builds on the series' established parallel execution infrastructure while maintaining backwards compatibility. The changes integrate cleanly with the existing hook configuration system and follow the same pattern of thorough test coverage seen throughout the series. With maintainer acks already in place and all technical issues resolved in previous iterations, this appears ready for merging as part of the overall parallel hooks feature.
