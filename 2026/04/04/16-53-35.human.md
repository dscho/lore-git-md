Bugfix for NULL pointer dereference in `git diff --no-index` with large files.

Luca Stefani follows up on Tian Yuchen's analysis of a segmentation fault that occurs when using `git diff --no-index` to compare large files outside a repository context. The crash happens when the diff machinery attempts to access `the_repository->objects` while processing files larger than the big-file threshold, but this pointer is NULL in repository-less mode.

Stefani shares a simple local fix that adds a check for the `INDEX_WRITE_OBJECT` flag in `object-file.c`'s `index_fd()` function, which would prevent the NULL dereference by avoiding object database operations when only hash computation is needed (as in `--no-index` mode). The proposed change is minimal and appears to work in testing, though it hasn't been formally submitted as a patch yet.

This continues the thread's technical discussion with a concrete implementation suggestion that aligns with Yuchen's earlier analysis.
