This is a feature patch in a series introducing parallel hook execution, specifically marking certain hooks as non-parallelizable. The patch identifies seven hooks that must always run sequentially due to their access to shared resources like commit message files, working tree, or repository state. These include commit-related hooks (`applypatch-msg`, `prepare-commit-msg`, `commit-msg`, `pre-commit`, `post-commit`), checkout-related hooks (`post-checkout`), and `push-to-checkout`.

The implementation uses `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` to enforce serial execution regardless of global `hook.jobs` settings or runtime `-j` flags. The patch updates documentation to clearly list these non-parallelizable hooks and modifies the hook calls in various builtins (`am.c`, `checkout.c`, `clone.c`, `receive-pack.c`, `worktree.c`, `commit.c`) to use the serial option. A new test case in `t/t1800-hook.sh` verifies that `hook.jobs=2` is properly ignored for force-serial hooks like `pre-commit`.

The changes are straightforward mechanical conversions to use the new serial option, with careful attention to maintaining existing behavior. The patch has sign-off from both the author (Adrian Ratiu) and Emily Shaffer, who identified the non-parallelizable hooks. This is part of the larger parallel hooks series that has already received maintainer approval, with this patch solidifying an important safety constraint in the parallel execution system.
