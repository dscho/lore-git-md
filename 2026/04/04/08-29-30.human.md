This is a feature patch (8/12) in Adrian Ratiu's series adding parallel hook execution support. The patch introduces per-event job count configuration via `hook.<event>.jobs`, allowing users to override the global `hook.jobs` setting for specific hook events. For example, you could configure `post-receive` hooks to run with 4 parallel jobs while keeping other hooks at the global default.

The implementation adds a new `event_jobs` strmap to the repository struct to cache these per-event settings, with careful handling of the config lookup order. The documentation clearly explains the precedence rules and warns about the common pitfall of confusing hook friendly-names with event names in the key.

The patch includes comprehensive tests verifying that per-event job counts properly override global settings while still requiring individual hooks to be marked as parallelizable. This maintains the safety checks from earlier patches in the series. The implementation appears clean and well-tested, with all the technical issues from earlier iterations now resolved.

This is part of a mature series that has already received maintainer approval, with this patch representing one of the final configuration layers in the parallel hooks system. The careful attention to backwards compatibility and clear documentation suggests it will integrate smoothly.
