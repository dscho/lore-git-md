This is a proposal to extend the `git repo info` command with additional path-related metadata, submitted as part of a Google Summer of Code (GSOC) project. The author, Arsh Srivastava, notes that while `git repo info` provides structured repository metadata, users still need to fall back to `git rev-parse` for certain path-related information like the Git directory, working tree root, and object directory.

The proposal suggests adding these path-related fields to `repo.c` using the existing getter pattern, maintaining consistency with the current design. The author is seeking feedback on whether this extension aligns with the intended scope of `git repo info` before proceeding further.

This appears to be a well-motivated extension to a relatively new command, focusing on consolidating repository metadata access patterns. The proposal is appropriately framed as a question about design direction rather than a fully formed patch, which is sensible for an early-stage GSOC project. The implementation approach seems technically sound, building on existing patterns in the codebase.
