This is a feature proposal (v2) from Pablo Sabater improving Git's graph rendering in `git log --graph` output, specifically addressing how commits with no visible parents (either true root commits or those with parents outside the displayed range) are displayed. The patch builds on previous discussion that identified the need to handle these "parentless" commits uniformly.

The current behavior misleadingly aligns unrelated commit lineages vertically, implying connections that don't exist. The solution introduces a placeholder mechanism that keeps parentless commits "alive" for an extra row, forcing proper indentation of subsequent commits. This creates clearer visual separation between independent lineages, though some edge cases in the ASCII-art rendering (like long diagonal lines between distant columns) remain.

The implementation adds an `is_placeholder` flag to graph columns and modifies the rendering logic in graph.c, with comprehensive test cases added to t4215-log-skewed-merges.sh. The v2 changes expand the scope from just true root commits to all parentless commits (including those with excluded parents) and fix test portability issues that blocked CI on case-sensitive filesystems.

This appears to be a well-motivated change with clear before/after examples and test coverage. The patch touches the finicky graph rendering subsystem, so reviewers will likely scrutinize edge cases around merge display and ASCII-art constraints. The author acknowledges some remaining visual quirks and invites feedback on whether to address them in this series or follow-ups.
