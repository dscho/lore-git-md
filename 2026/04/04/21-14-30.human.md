This is a feature proposal to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash. The v2 patch from Thibaud CANALE introduces a new config option `checkout.switchDetach` that makes `git switch` automatically detach HEAD when given a commit ID, just like `git checkout` does by default.

The patch has been updated based on review feedback, with improvements to the commit message, documentation wording, and test cleanup. The author provides technical justification for keeping the separate `switch_detach` flag rather than reusing `force_detach`, explaining that the latter caused test failures and broke branch switching functionality. Tests now properly clean up config changes and have clearer descriptions.

Key changes in v2:
- More detailed commit message explaining the motivation and behavior
- Improved documentation formatting and clarity
- Better test cleanup using `git config --unset` instead of resetting to false
- More precise advice message wording
- Justification for the design choice of a new flag

The core proposal remains to address the inconsistency between `git switch` and `git checkout` behavior through configuration rather than changing defaults. The discussion thread shows this approach has tradeoffs around scripting predictability versus user preference flexibility. The patch appears well-constructed with thorough test coverage of both enabled and disabled config states.
