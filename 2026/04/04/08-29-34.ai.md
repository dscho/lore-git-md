This is the final patch in a feature series introducing parallel hook execution, adding support for `-1` to mean "use all available CPU cores" in hook job settings. The patch follows Git's established convention seen in `fetch.parallel` and other subsystems.

The change allows `-1` for three configuration points: the global `hook.jobs` setting, per-event `hook.<event>.jobs` overrides, and the `-j/--jobs` CLI flag. The value resolves to `online_cpus()` at parse time, ensuring consistent behavior throughout execution. Negative values below `-1` are rejected with warnings (for config) or fatal errors (for CLI). The implementation includes:

- Documentation updates clarifying the new `-1` behavior
- Modified config parsing to handle signed integers rather than unsigned
- A new `resolve_hook_config_jobs()` helper to centralize the `-1` handling
- Test coverage verifying core count resolution and invalid value rejection

This completes the parallel hook execution feature set, which now offers comprehensive configuration options while maintaining backwards compatibility. The series has received maintainer approval and appears ready for merging.
