This is a feature proposal to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash. The patch introduces a new config option `checkout.switchDetach` that, when enabled, makes `git switch` automatically detach HEAD when given a commit ID, just like `git checkout` does by default.

The change affects three areas:
1. Adds documentation for the new config option in `Documentation/config/checkout.adoc`
2. Modifies `builtin/checkout.c` to check the config and adjust behavior accordingly
3. Adds tests in `t/t2060-switch.sh` to verify both enabled and disabled states

The implementation appears straightforward, adding a new `switch_detach` flag to `struct checkout_opts` that gets set from config. The tests cover the basic cases of switching between branches and commits with the config both on and off. The patch includes appropriate advice messages suggesting the config option when users might want detach behavior.

This addresses a subtle but potentially confusing inconsistency between `git switch` and `git checkout`. The change is well-contained and comes with tests, though as an RFC it may need discussion about whether this is the right approach versus other solutions like making the behavior consistent by default. The author is proposing configuration rather than behavior change to maintain backward compatibility.
