This is a feature proposal to make `git switch`'s behavior configurable when given a commit hash rather than a branch name. Currently, `git switch` requires an explicit `--detach` flag to check out a commit directly, while `git checkout` does this automatically. The patch introduces a `checkout.switchDetach` config option to make `git switch` behave like `git checkout` when set to true.

The change touches documentation, the checkout implementation, and adds tests. The implementation adds a new config flag that gets checked in several places where detachment behavior is determined. The tests verify that the config option works as expected in both enabled and disabled states.

The patch appears well-structured with clear commit message and test coverage. The motivation is reasonable - providing consistency between the two commands' behaviors - though some might argue the current distinction between `switch` and `checkout` is intentional. The implementation looks straightforward, adding a new config option while maintaining backward compatibility. This seems likely to generate discussion about whether the behavioral difference should be preserved or unified.
