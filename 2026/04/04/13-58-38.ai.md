This is part 1 of a 3-patch series continuing the `the_repository` removal effort in the refs subsystem. Shreyansh Paliwal's patch converts `get_files_ref_lock_timeout_ms()` to take an explicit `struct repository*` parameter instead of implicitly using `the_repository`.

The change removes one more instance of global state usage while maintaining the existing static caching behavior. The patch updates all callers to pass the repository context through, including adding a small wrapper struct to pass both lock_file and repository through a callback in `create_reflock()`. The commit notes this doesn't fully repository-scope the functionality yet (static variables remain) but is an incremental step in that direction.

The changeset touches core refs functionality in `refs.c`, the files backend implementation, and the internal refs API header. It follows established patterns from René Scharfe's long-running effort to eliminate global state, with the author incorporating previous review feedback to improve the commit message's clarity about remaining work. The mechanical nature of the change and limited scope make it a straightforward step toward the larger goal.
