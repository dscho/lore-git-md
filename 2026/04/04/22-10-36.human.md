This is a technical discussion about a bug in Git's fsmonitor implementation when used with split-index mode, specifically around the interaction with `index.skipHash`. Johannes Schindelin provides a detailed analysis showing that Paul Tarjan's proposed fix addresses a symptom rather than the root cause.

The core issue stems from how `index.skipHash=true` (set by Scalar) interacts with split-index mode, leading to a corrupted index state where the shared index isn't properly loaded. This manifests when fsmonitor tries to validate its bitmap against the index entries. Johannes identifies three potential fixes:

1. Fix `write_shared_index()` to properly handle `index.skipHash` cases
2. Modify the `hn/git-checkout-m-with-stash` topic to avoid unnecessary index reloads
3. Continue using the existing workaround of disabling split-index in tests

Johannes argues that Paul's patch (which adds guards in fsmonitor code) is dangerous because it could silently ignore legitimate file changes reported by fsmonitor. He recommends dropping the patch from the series in favor of addressing the root cause in the split-index or checkout code paths.

The discussion demonstrates the complexity of interactions between Git's various subsystems (fsmonitor, split-index, checkout) and the importance of proper index handling. Johannes's analysis is thorough, drawing on historical context and bisection results to identify the true source of the bug.
