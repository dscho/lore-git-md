This is a review response to an RFC patch proposing to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash. The original patch introduced a `checkout.switchDetach` config option to control whether `git switch` automatically detaches HEAD for commit IDs.

Pablo provides detailed technical feedback on the submission, noting several areas needing improvement:
1. The commit message should use imperative mood and better explain the motivation
2. Documentation wording could be clearer about the effect rather than the implementation
3. Questions whether the new `switch_detach` flag is truly needed versus reusing `force_detach`
4. Points out minor style issues (comment format, test descriptions, redundant config resets)
5. Suggests consulting Git's contribution guidelines for proper patch formatting

The review is constructive but non-committal on whether the config approach is preferable to changing default behavior. Pablo focuses on helping the author improve the patch quality rather than evaluating the design choice itself. The feedback indicates the concept seems reasonable but needs polishing before being ready for serious consideration.
