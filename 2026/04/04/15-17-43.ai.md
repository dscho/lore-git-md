This is a bugfix proposal for the `--simplify-by-decoration` behavior in `git log` when dealing with empty root commits. The issue occurs when an empty root commit is incorrectly marked as TREESAME and thus omitted from the graph output, leading to a misleading visualization where branches appear disconnected when they actually share a common empty root.

Fernando Ramos identifies two specific problems:
1. Empty root commits being dropped from the graph when using `--simplify-by-decoration`, making the history appear disconnected
2. The graph visualization using the same "*" character for root commits as for regular commits, which can imply incorrect parent-child relationships

The proposed solutions are:
1. A patch that prevents empty root commits from being marked TREESAME when `--simplify-by-decoration` is active
2. An optional second patch that changes the graph marker for root commits from "*" to "I" to make their status clearer

The changes touch revision.c, specifically the commit simplification logic and graph mark generation. The first patch references Taylor Blau's prior work in commit 1343c893138 (Bloom filter handling for empty trees) but maintains that behavior when not using `--simplify-by-decoration`.

The email includes a test script that demonstrates both the current behavior and the desired output, showing how empty root commits currently disappear from the graph visualization. The proposed changes would make the output consistent regardless of whether the root commit is empty or not.
