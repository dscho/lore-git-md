This thread discusses a proposed extension to the `git repo info` command to include path-related metadata like the Git directory, working tree root, and object directory paths. The proposal comes from Arsh Srivastava as part of a Google Summer of Code project.

Currently, users need to use `git repo info` for some repository metadata but still fall back to `git rev-parse` for path information. The proposal suggests adding these path-related fields to `repo.c` while maintaining consistency with the command's existing design patterns. The author is specifically seeking feedback on whether this extension fits within the intended scope of `git repo info` before proceeding with implementation.

The suggestion appears well-motivated, as it would consolidate repository metadata access into a single command. The approach builds on existing patterns in the codebase, and the author has appropriately framed this as a design question rather than submitting a premature patch - a sensible approach for an early-stage GSOC project.
