This is a refactoring patch that adds unsigned integer parsing support to Git's config system, part of Adrian Ratiu's parallel hook execution series. The patch introduces a new `repo_config_get_uint()` helper and supporting functions to properly handle unsigned integer config values, which will be used for the upcoming `hook.jobs` configuration option.

The implementation follows the existing pattern for other numeric types in the config system, adding parallel functions for unsigned int at each layer: low-level parsing (`git_parse_uint`), config value conversion (`git_config_uint`), configset lookup (`git_configset_get_uint`), and repository-level access (`repo_config_get_uint`). The author considered alternatives like using signed int or unsigned long but chose unsigned int as the most appropriate type for the job count use case.

This is a straightforward plumbing change that fills a gap in the config API, enabling cleaner handling of unsigned values without casting or type mismatches. The patch is well-contained and follows established patterns, with clear documentation added for the new functions. As part of the larger parallel hooks series that has already received maintainer approval, this infrastructure piece appears uncontroversial and ready for merging.
