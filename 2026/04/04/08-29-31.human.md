This is part 9/12 of a feature series introducing parallel hook execution, now in its 6th iteration. The patch adds a warning when users mistakenly configure `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` format.

The warning detects when a configured job count appears to be targeting a hook's friendly name (like `pre-commit`) rather than its event name (like `post-rewrite`). It checks for other hook-specific configurations (`.command`, `.event`, or `.parallel`) as indicators of a friendly name. The implementation includes a new `is_friendly_name()` helper function and four test cases verifying the warning behavior.

This addresses a usability concern raised by Junio C Hamano about potential confusion between the two configuration namespaces. The warning helps users correct misconfigurations while maintaining backward compatibility. The patch fits into the larger parallel hooks framework by ensuring job count settings are properly targeted at event names rather than hook names.

The change is well-contained, with clear test coverage showing both the warning cases and the silent success case for proper event names. As with the rest of the series, this appears ready for merging with no outstanding technical issues.
