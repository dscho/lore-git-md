This is a feature patch in Adrian Ratiu's parallel hook execution series (v6 09/12). It adds a warning when users mistakenly configure `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` setting.

The patch introduces an `is_friendly_name()` helper that detects when a name is being used as a hook friendly-name (by checking for associated .command, .event, or .parallel configurations) rather than as an event name. When such a misconfiguration is found, it warns the user that their jobs setting will be ignored since it's in the wrong namespace. The warning explains that job counts should use event names (e.g. `hook.post-receive.jobs`).

Four new test cases verify the warning behavior: three checking that warnings appear when .jobs is set alongside other friendly-name indicators (.command, .event, .parallel), and one confirming no warning appears for proper event-name usage. The implementation builds on the existing hook configuration infrastructure, adding the warning check during the config parsing phase.

This addresses feedback from Junio Hamano about making the namespace distinction clearer to users. The warning helps prevent confusion between the two configuration namespaces (hook friendly-names vs. event names) that was identified as a potential pitfall in earlier discussion. The patch fits cleanly into the series' overall goal of providing comprehensive parallel execution configuration while maintaining clear user feedback.
