This thread explored a proposal to make `git switch`'s behavior configurable to match `git checkout` when given a commit hash, via a new `checkout.switchDetach` option. The initial patch from Thibaud CANALE aimed to ease the transition from `checkout` to `switch` by addressing a key behavioral difference. Reviewers Pablo and D. Ben Knoble provided detailed feedback on implementation and scripting concerns, which were addressed in v2. However, Junio Hamano firmly rejected the proposal, arguing that keeping `switch` strictly branch-focused serves Git's usability goals better than configurability, and that `checkout` remains available for detachment needs.

In a follow-up, Kristoffer Haugsbakk shared a thoughtful user perspective, noting their personal preference for `checkout`'s detachment behavior while acknowledging Git's official stance that `checkout` is superseded by `switch`/`restore`. This commentary highlights the tension between documentation guidance and real-world usage patterns, but doesn't challenge Junio's decision. The thread remains closed with the proposal rejected on design principle grounds, leaving `git switch`'s behavior unchanged. The discussion surfaces an ongoing philosophical divide between those who value strict command separation and those who prioritize backward compatibility and user transition paths.
