Feature patch adding CLI parallel execution control to `git hook run`. This is patch 7/12 in a series introducing parallel hook execution, now ready for merging with maintainer acks. The patch adds a `-j/--jobs` option to override the `hook.jobs` config, allowing callers to explicitly request parallel execution. 

Key aspects:
- The CLI flag takes precedence over all other parallelization settings (global config, per-hook flags)
- Includes warnings when forcing parallel execution for hooks not marked as parallel-safe
- Adds comprehensive tests verifying TTY behavior (parallel hooks lose direct TTY access), output grouping, and serial/parallel execution modes
- Documents the new option alongside the existing configuration hierarchy

The implementation builds on earlier patches in the series that established the parallel execution infrastructure and configuration system. This appears to be a well-tested addition that provides direct control over parallel execution while maintaining safety through warnings about potentially unsafe parallelization.
