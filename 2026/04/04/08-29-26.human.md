This is a feature patch (4/12 in the series) that implements parallel hook execution, building on Adrian Ratiu's earlier configurable hooks work. The patch has received maintainer acks from Junio C Hamano and appears ready for merging.

The core change removes Git's hardcoded sequential hook execution by introducing parallel processing when configured. Hooks remain serial by default for safety, but users can opt into parallelism by setting `hook.<name>.parallel = true` in config. The implementation carefully maintains backwards compatibility while adding:

- A new `hook.jobs` config to control default parallelism (defaults to 1)
- Per-hook `hook.<name>.parallel` flags to mark hooks as parallel-safe
- Logic to fall back to serial execution if any hook in an event isn't marked parallel
- Special handling for hooks that need separate output streams (currently forced to serial)

The patch includes comprehensive tests verifying the parallel/serial behavior under different config combinations. It also introduces helper functions like `get_hook_jobs()` to centralize the job-count determination logic. The implementation follows Git's standard patterns for numeric config parsing and hooks infrastructure.

This is a well-tested, carefully implemented change that provides meaningful performance improvements for hook-heavy workflows while maintaining safety through explicit opt-in. The series as a whole represents a significant enhancement to Git's hook system with clear attention to backwards compatibility.
