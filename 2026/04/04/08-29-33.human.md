This is a feature patch (11/12 in the series) introducing a high-level switch to disable all hooks for a given event via `hook.<event>.enabled` configuration. The patch builds on Adrian Ratiu's parallel hook execution work and has received suggestions from both Patrick Steinhardt and Junio C Hamano.

The new configuration acts as a master switch that takes precedence over individual hook enable/disable settings. When an event is disabled, all associated hooks are skipped regardless of their per-hook enabled status. The `git hook list` command now shows event-disabled hooks with an "event-disabled" prefix, making the state clearly visible to users.

The implementation includes careful handling of naming collisions between event names and friendly names, with fatal errors for known conflicts and warnings for potential ones. The patch adds comprehensive test coverage in t/t1800-hook.sh, verifying the interaction between event-level and per-hook disable states, CLI output formatting, and error cases around naming.

This appears to be a well-considered addition to the hook configuration system, with clear documentation and thorough test coverage. The patch maintains backwards compatibility while providing administrators more control over hook execution. As the penultimate patch in a well-reviewed series with maintainer acks, it looks ready for merging.
