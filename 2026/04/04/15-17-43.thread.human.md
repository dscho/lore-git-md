Fernando Ramos has identified an issue with `git log --simplify-by-decoration` where empty root commits are incorrectly omitted from the graph output, making branches appear disconnected when they actually share a common empty root. The problem affects both the commit filtering logic (causing the commits to disappear) and the visualization (using ambiguous markers).

The proposed solution comes in two parts: first, a core fix to prevent empty root commits from being marked as TREESAME when using `--simplify-by-decoration`, ensuring they remain visible in the graph. Second, an optional visualization improvement that changes the graph marker for root commits from "*" to "I" to make their special status clearer. The changes focus on revision.c and include test cases demonstrating both the current problematic behavior and the desired output.

The patch builds on prior work by Taylor Blau regarding Bloom filter handling for empty trees, maintaining that behavior when not using the decoration-simplification option. The test script included with the patch clearly illustrates how empty root commits currently vanish from view and how the fix would preserve them in the history visualization.
