This is a feature patch series (v6) introducing parallel hook execution, now ready for merging with all core technical issues resolved. The series builds on Adrian Ratiu's prior configurable hooks work and has received maintainer acks from Junio C Hamano. The v6 iteration includes only minor build system fixes from Patrick Steinhardt, addressing a meson.build dependency issue where hook-list.h needed to be moved from builtin_sources to libgit_sources to match the relocation of is_known_hook().

The series establishes a comprehensive parallel execution system with multiple configuration options: a global `hook.jobs` default (now supporting `-1` for CPU core count), per-hook `hook.<name>.parallel` flags, CLI `-j/--jobs` override (confirmed to override all other settings), per-event `hook.<event>.jobs` settings, and per-event `hook.<event>.enabled` master switches. Special handling is implemented for the pre-push hook to maintain backwards compatibility in serial mode while merging stdout into stderr when parallel.

Seven hooks are marked as non-parallelizable by default due to shared resources, with Emily Shaffer's signoff. The implementation includes thorough test coverage in t/t1800-hook.sh and resolves all technical concerns raised during review, including memory leaks, NULL dereferences, and documentation clarifications about precedence rules. The only remaining open question is a philosophical one from Patrick Steinhardt about namespace separation between hook friendly-names and event names, but this is explicitly not blocking the current approach.

With the meson.build fix now incorporated and all core components approved, this series appears ready for merging as a significant enhancement to Git's hook system. The careful attention to backwards compatibility and comprehensive configuration options suggest it will provide flexibility while maintaining stability.
