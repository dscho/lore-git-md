This is a follow-up in the fsmonitor thread addressing the split-index/index.skipHash interaction. Paul Tarjan responds to Johannes Schindelin's design concerns by implementing the simpler solution of unsetting GIT_TEST_SPLIT_INDEX in affected scalar clone tests rather than modifying core index behavior.

The patch removes both the fsmonitor.c bounds-check workaround and the read-cache.c skipHash fix that were previously proposed. Instead, it adds `sane_unset GIT_TEST_SPLIT_INDEX` to three specific test cases in t9210-scalar.sh where the incompatibility surfaces. This matches an existing workaround already present in test 16 of the same file.

Paul confirms the solution works by testing on Fedora with fsmonitor-linux and GIT_TEST_SPLIT_INDEX=yes, with all 22 tests now passing. The commit message notes the fundamental incompatibility between index.skipHash (a Scalar default) and split-index mode, where the shared index would get a null OID and fail to load.

This represents a pragmatic resolution to the debate - rather than forcing hashing during shared index writes or declaring the features broadly incompatible, the solution simply avoids the problematic combination in the specific test cases where it occurs. The approach maintains the existing behavior while preventing test failures, deferring any deeper architectural questions about feature interaction design.
