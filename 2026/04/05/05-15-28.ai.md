This is a follow-up in the fsmonitor thread, now addressing the root cause of the split-index/index.skipHash interaction that was causing index corruption. Paul Tarjan confirms Johannes Schindelin's analysis from the previous email and provides a concrete fix that addresses the underlying issue rather than just the symptom.

The key technical insight is that `write_shared_index()` needs to generate a real OID for the shared index even when `index.skipHash` is true, since this OID is used to identify and load the shared index later. Paul's patch temporarily forces hashing during the shared index write while preserving the original `index.skipHash` setting. He reports this fix passes all tests in t9210 with split-index enabled, making his previous fsmonitor-specific bounds check patch unnecessary.
