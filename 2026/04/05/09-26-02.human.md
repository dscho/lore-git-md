This is a follow-up in the fsmonitor thread discussing the interaction between split-index and index.skipHash. Johannes Schindelin responds to Paul Tarjan's proposed fix for the issue where index.skipHash was causing shared index corruption by preventing OID generation.

Johannes argues that Paul's solution - temporarily forcing hash generation in write_shared_index() - is not ideal long-term because it creates an inconsistency in how index.skipHash is handled. He points out the fundamental incompatibility between split-index (which requires OIDs) and index.skipHash (which skips them), suggesting these features may need to be mutually exclusive.

The email explores alternative approaches but finds problems with each: faking OIDs could cause compatibility issues, while adding index format flags would break interoperability. Johannes ultimately recommends his original suggestion to unset GIT_TEST_SPLIT_INDEX in t9210's test environment as the safest path forward, though he acknowledges this isn't a complete solution.

This represents a shift from the previous consensus - where Paul's fix appeared satisfactory - to a more cautious position that questions whether these features should work together at all. The discussion now centers on whether to treat this as a bug to fix or a fundamental design limitation.
