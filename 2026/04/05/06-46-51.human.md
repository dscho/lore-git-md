This is a technical discussion about a bugfix in Git's object-file handling during non-repository operations, specifically addressing edge cases with large file diffs.

Jeff King (Peff) responds to Luca Stefani's patch that fixed incorrect object database usage in `git diff` outside repositories. While agreeing with the core issue, Peff identifies a new problem: the proposed solution would cause `index_core()` to attempt mmap'ing very large files on 32-bit systems, which would fail. He provides a test case demonstrating this (though notes it's too resource-intensive for the regular test suite) and suggests the streaming code path would be more appropriate.

Peff also uncovers a related limitation - Git's diff and hash-object operations currently can't handle files over 4GB on 32-bit systems due to `size_t` vs `off_t` issues. While acknowledging this might not be a priority, he argues the code should still avoid problematic mmap operations.
