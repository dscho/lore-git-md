This is a follow-up in the fsmonitor thread discussing the root cause fix for the split-index/index.skipHash interaction. Johannes Schindelin responds to Paul Tarjan's confirmation that the proposed fix works, but raises concerns about the long-term implications of temporarily overriding index.skipHash during shared index writes.

The key technical disagreement centers on whether to:
1. Accept Paul's working fix that temporarily forces hashing for shared index writes while preserving skipHash
2. Treat split-index and skipHash as fundamentally incompatible features
3. Work around the issue in tests by unsetting GIT_TEST_SPLIT_INDEX

Johannes argues that the features are inherently incompatible since split-index requires OID generation while skipHash explicitly avoids it. He suggests alternative approaches like faking OIDs (with noted challenges) or simply avoiding the combination in tests. The tone remains technical but highlights deeper design considerations beyond the immediate fix.

This moves the discussion from implementation to design philosophy - whether to paper over the incompatibility or acknowledge it explicitly. The fsmonitor functionality itself remains unaffected, but the thread now surfaces a more fundamental question about feature interactions in Git's index handling. Johannes' response suggests he may prefer a more conservative approach that maintains clear feature boundaries rather than adding special cases.
