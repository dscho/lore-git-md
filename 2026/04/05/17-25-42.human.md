This is a follow-up in the fsmonitor thread addressing the split-index/index.skipHash interaction. Paul Tarjan responds to Johannes Schindelin's concerns by implementing Johannes' suggested approach - explicitly avoiding the problematic feature combination in tests rather than trying to make them work together.

The patch modifies `t/t9210-scalar.sh` to unset `GIT_TEST_SPLIT_INDEX` in three tests where scalar clone operations were failing due to the incompatibility between split-index and index.skipHash. This matches an existing workaround already present in test 16. Paul confirms this change allows all 22 tests to pass when running with fsmonitor enabled on Fedora.

The change represents a pragmatic resolution to the design debate - rather than trying to force the features to work together through temporary hashing overrides (Paul's original approach) or more invasive OID faking solutions, the project is opting to simply avoid combining these features in the test suite. This aligns with Johannes' preference for clear feature boundaries over special-case fixes.

The fsmonitor functionality itself remains unchanged and production-stable. This patch concludes the immediate issue while leaving open the broader question of how Git should handle similar feature interactions in the future. The solution is minimal and focused, affecting only the test suite rather than core functionality.
