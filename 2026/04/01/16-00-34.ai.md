This is a follow-up discussion about a recently merged xdiff refactoring series. Phillip Wood has identified a regression in the final patch (v4 6/6) that changes diff output behavior when using certain git log options. The issue stems from the patch modifying the action arrays during INVESTIGATE handling, which affects subsequent calls to xdl_clean_mmatch() that depend on those arrays.

The regression manifests in git log output, showing changes in diff formatting for commits related to pack handling, trailer processing, and object database operations. Phillip suggests using a local variable instead of modifying actionX[i] to preserve the original behavior while maintaining the clarity improvements.

This comes after the series was already merged to 'next' with Junio C Hamano's approval, following multiple review iterations that addressed test failures and build warnings. The regression wasn't caught during earlier testing, indicating the test coverage may need expansion for these edge cases.

The thread shows the typical post-merge review process where subtle issues can still surface, even after thorough pre-merge review. Phillip's analysis provides a clear path forward - either reverting the problematic part of the patch or adjusting it to use local variables while preserving the intended readability improvements.
