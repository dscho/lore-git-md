This is a feature patch series introducing new `includeIf` conditions for matching worktree paths in Git configs. The series comes from Chen Linxuan and consists of 3 patches: core implementation, documentation, and tests.

The main addition is two new `includeIf` condition keywords:
- `worktree:<pattern>` - matches the worktree's working directory path against a glob pattern
- `worktree/i:<pattern>` - case-insensitive variant

The motivation is that in multi-worktree setups, the `.git` directory (used by existing `gitdir` conditions) points to the main repository's `.git/worktrees/` rather than the worktree's actual location, making path-based config includes cumbersome. The new conditions directly match against the worktree path with full glob support including `**/`, `~` expansion, and relative paths.

The implementation touches the config parsing logic in `config.c` and adds comprehensive tests covering various path matching scenarios. The documentation patch thoroughly explains the new syntax and behavior. The changes look well-considered with clear motivation and thorough test coverage - exactly the sort of focused improvement that tends to get positive review on the list.

This appears to be a clean, well-motivated addition to Git's config inclusion system that solves a real pain point in multi-worktree setups. The patch structure follows Git conventions with implementation, tests, and docs all properly separated. The feature is backward compatible and introduces no breaking changes.
