Feature patch adding new `includeIf` conditions for worktree paths. This is the first in a 3-part series (no cover letter seen yet) that aims to make config inclusion more flexible in multi-worktree setups.

Currently, `includeIf` can match on gitdir paths or branches, but gitdir paths in linked worktrees point to the main repo's `.git/worktrees/` directory, which isn't always convenient. The patch introduces two new conditions: `worktree:<pattern>` matches the worktree's top-level directory path (what `git rev-parse --show-toplevel` returns), and `worktree/i:<pattern>` does case-insensitive matching. The implementation reuses the existing path-matching infrastructure, just applying it to the worktree path instead of the gitdir path.

The change is cleanly implemented by factoring out the path matching logic into a new `include_by_path()` helper that both gitdir and worktree conditions can use. The patch handles edge cases like bare repos (no worktree) and early config reading (no repo available) by returning no match in those cases. This looks like a well-motivated addition that should make worktree-specific configs easier to manage.
