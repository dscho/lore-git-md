This is a bug report about hash algorithm mismatch when cloning empty repositories. The reporter, Miljan Mitrovic, describes cloning an empty SHA256 remote repository but getting a local SHA1 repository instead, which then causes problems when trying to push commits back to the remote.

The key issue is that Git doesn't properly propagate the hash algorithm setting when cloning empty repositories. While the user receives a warning about cloning an empty repo, the more serious problem is the silent creation of a mismatched local repository that will be incompatible with the remote. The reporter notes this is particularly problematic since there's no way to convert between hash algorithms after creation.

The bug appears on Windows (Git version 2.39.1.windows.1) but likely affects other platforms as well. This touches on the ongoing work around SHA-256 support and interoperability, though the specific case of empty repository cloning seems to have been overlooked. The report suggests that critical initialization settings like the hash algorithm should be preserved during clone operations.

This appears to be a genuine bug rather than a configuration issue, and it affects the core clone functionality in a way that could lead to repository corruption (by creating incompatible local/remote pairs). The problem is well-described with clear reproduction steps and expected/actual behavior.
