This is a performance optimization patch in Justin Tobler's series to complete the object database (ODB) write interface, part of the ongoing ODB abstraction effort. The patch improves packfile writes for large blobs by eliminating unnecessary seek operations when packfiles approach their size limit.

Currently, when writing blobs that exceed core.bigFileThreshold, Git streams them directly to packfiles. If adding another object would exceed pack.packSizeLimit, Git must seek back in the file descriptor and restart the write in a new packfile. This patch replaces that seek-heavy approach with an upfront size check using the inflated blob size as an approximation, since these blobs aren't delta-compressed (only zlib-compressed).

The change simplifies the retry logic in index_blob_packfile_transaction() by moving the size check before writing begins. The stream_blob_to_pack() helper is simplified to a void function since it no longer needs to handle mid-stream failures. While this may leave some unused space in packfiles when zlib compression is more effective than expected, it's a worthwhile tradeoff to avoid the seek operations.

This appears to be a well-motivated optimization that fits cleanly into the larger ODB transaction interface work. The patch maintains all existing functionality while making the code both simpler and more efficient - exactly the kind of change that tends to get quick approval in the Git project.
