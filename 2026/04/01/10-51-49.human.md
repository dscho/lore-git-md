This is a bug report about hash algorithm mismatch when cloning empty repositories. When cloning an empty SHA-256 repository, Git currently creates a local repository with SHA-1 hashing instead, which then causes problems when trying to push commits back to the remote.

The reporter (Miljan Mitrovic) encountered this on Windows using Git 2.39.1. The core issue is that Git doesn't properly propagate the hash algorithm setting from the remote when cloning an empty repository, even though this is a fundamental property that should be preserved. The bug creates a workflow roadblock since there's no way to convert an existing repository between hash algorithms.

While the scenario is somewhat edge-case (cloning empty repositories), it highlights a real inconsistency in how Git handles hash algorithm settings during clone operations. The reporter reasonably expects the local clone to match the remote's hash algorithm by default, especially since hash algorithm is now treated as an immutable repository property.
