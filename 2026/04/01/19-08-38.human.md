This is a bugfix follow-up addressing a crash in `git commit -a` during unresolved merges when rename detection is active. Nick Golden confirms they've incorporated all of Junio C Hamano's review feedback from v1, including test improvements (replacing Perl with sed, simplifying assertions) and adding proper sign-off. 

The author notes they audited similar index refresh paths and found no other instances of this particular issue. The core fix remains unchanged - disabling rename detection in `add_files_to_cache()` since staging worktree changes doesn't need rename tracking. The regression test verifies the fix by creating a scenario with two identical files, generating a merge conflict on one while deleting the other, then confirming `git add -u` handles it correctly.

With the maintainer's requested changes addressed and no outstanding issues, this appears ready for inclusion. The patch is narrowly focused on the specific crash scenario without broader changes to merge/rename detection machinery. The test provides clear coverage while following Git's standards for maintainable test cases.
