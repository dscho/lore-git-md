This is the final patch in Patrick Steinhardt's reftable portability series, addressing header organization for the shared between Git and libgit2. The discussion focuses on architectural boundaries between platform-specific and platform-neutral code in the reftable implementation.

Patrick responds to Junio C Hamano's concerns about the somewhat confusing split between `reftable-system.h` (intended to be project-specific) and `system.h` (meant to be platform-neutral but containing some Git-specific elements). He explains the intended separation between internal and external API surfaces, acknowledging the current organization isn't ideal.

The key tension is whether to:
1) Keep the current split with clearer separation of concerns
2) Push more responsibility onto callers to satisfy dependencies
3) Find another organizational approach

Patrick remains open to alternatives, showing willingness to refine the design. This exchange exemplifies the careful attention to architectural boundaries required when creating shared infrastructure between projects with different constraints (Git's modern C expectations vs libgit2's broader platform support needs). The patch appears technically sound but the discussion suggests the header organization may see further iteration before finalization.
