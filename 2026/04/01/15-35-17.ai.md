This is a follow-up in a bug report thread about hash algorithm mismatches during repository cloning. Miljan Mitrovic confirms that upgrading their Git client to version 2.53 resolved the issue they were experiencing, where cloning an empty SHA256 repository would incorrectly create a local SHA1 repository. 

The thread had previously established that this was a known bug fixed in Git v2.41 through the introduction of an "object-format" capability in the clone protocol. Patrick Steinhardt had explained that this capability ensures proper hash algorithm propagation even for empty repositories, requiring both client and server to be at least v2.41 for the fix to work.

Miljan's latest message serves as a confirmation that the solution worked as intended when they updated their client, closing the loop on this issue. The exchange provides a clear case study of how protocol-level fixes in Git require coordinated client/server updates to take effect, and demonstrates the value of proper version checking when troubleshooting compatibility issues. The thread now appears fully resolved with no remaining open questions.
