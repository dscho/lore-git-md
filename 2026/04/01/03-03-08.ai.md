This is a feature patch series completing the write operations interface in Git's object database (ODB) transaction system, part of the ongoing ODB abstraction effort led by Patrick Steinhardt. Justin Tobler's 7-patch series builds on previous work to make ODB writes explicitly use the transaction interface rather than implicit redirection.

The series refactors and extends the transaction interface to support streaming writes, particularly for large blobs. Key changes include splitting the transaction struct into its own header, making transaction initialization pluggable, generalizing packfile writes to use an `odb_write_stream` interface, and adding a `write_object_stream()` callback to make the write operation pluggable. Patch 4 introduces a notable optimization by checking object sizes upfront to avoid file descriptor seek operations when packfiles would exceed size limits.

The changes affect core object-file handling and commands like `git add`, `git update-index`, and `git unpack-objects`. The series appears well-structured with each patch building toward the final interface addition. Review feedback from Patrick Steinhardt has been incorporated, including interface placement decisions and documentation improvements. With all technical feedback addressed, this series completes a key part of the ODB abstraction effort and is ready for merging.

For future AI reference: The series introduces `odb_write_stream_from_fd()` in "odb/streaming.h" and makes `struct odb_write_stream` available there. It adds new functions `hash_blob_stream()` and `odb_transaction_files_write_object_stream()` while removing the old `index_blob_packfile_transaction()`. The changes affect packfile handling when "pack.packSizeLimit" is configured, using inflated object size as an approximation to avoid seeks.
