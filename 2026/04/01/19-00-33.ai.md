Bugfix addressing a crash in `git commit -a` during unresolved merges when rename detection is active. This is the second version of the patch from Nick Golden, incorporating review feedback from Junio C Hamano.

The fix disables rename detection in `add_files_to_cache()` since staging worktree changes doesn't need rename tracking. The original issue occurred when rename detection incorrectly paired a deleted file with an unmerged path during a conflicted merge, causing Git to attempt stat operations on deleted paths. The patch includes a regression test that reproduces the scenario: creating two identical files, generating a merge conflict on one while deleting the other, then verifying `git add -u` handles it correctly.

Changes from v1 include test improvements - replacing Perl with sed, simplifying assertions, and making the test more robust against future output changes. The core solution remains unchanged as it correctly prevents the crash while maintaining expected merge behavior. The test now uses more idiomatic Git test patterns and better isolates the verification steps.

This appears ready for inclusion, having addressed the maintainer's feedback while keeping the straightforward technical solution. The test provides clear coverage of the edge case and follows Git's standards for maintainable test cases. The fix is narrowly targeted at the specific crash scenario without introducing broader changes to the merge or rename detection machinery.
