Feature patch for the `git replay` plumbing command, adding a `--ref` option to control which reference gets updated. This is part 3/3 of Toon Claes' v3 series that builds on previous work to stabilize and document the command.

The patch introduces a new `--ref` option that lets users specify exactly which reference should be updated with the replay result, rather than having the command infer it from other options. When used with `--onto`, it updates only the specified ref instead of all refs in the revision range. With `--advance` or `--revert`, it updates the given ref instead of the branch passed to those options. The ref must be fully qualified (starting with `refs/`).

Key technical changes include:
- Zero-initializing the `merge_opt` struct to prevent crashes when early exits occur
- Adding validation that rejects unqualified refs and multiple revision ranges with `--ref`
- Updating documentation to explain the new option and its interactions
- Adding comprehensive tests in t3650-replay-basics.sh covering various `--ref` scenarios

The implementation appears solid, with thorough test coverage and clear documentation. This builds on the previous patches in the series that fixed crashes and hardened option parsing. The changes maintain backward compatibility while adding the new functionality in a way that follows Git's standard practices.
