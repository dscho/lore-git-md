This is the final discussion in the RFC series adding remote group support to `git push`. Junio Hamano is responding to Usman Akinyemi's question about implementation strategy for failure handling in group pushes.

The maintainer confirms the design decision to continue pushing to remaining remotes after a failure (like shell `;` semantics) rather than stopping at first failure (`&&` semantics). Junio provides implementation guidance, suggesting that spawning child processes via `run_command` would be necessary only if there's a post-push summary phase. For the last remote in the group, the push could run in the primary process to maintain compatibility with single-remote behavior.
