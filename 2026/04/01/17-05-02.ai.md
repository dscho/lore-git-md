Bugfix addressing a crash in `git commit -a` during unresolved merges when rename detection is involved.

This patch from blindmansion fixes the crash reported earlier where `git commit -a` would fail with "unable to stat" when encountering both unresolved merge conflicts and deleted tracked files. The root cause was that rename detection in `add_files_to_cache()` could incorrectly pair a deleted file with an unmerged path, leading to an attempt to stat the deleted path.

The solution is straightforward: disable rename detection in `add_files_to_cache()` since staging worktree changes doesn't need rename detection anyway. The patch includes a thorough test case that reproduces the original crash scenario - creating two identical files, generating a merge conflict on one, deleting the other, then verifying `git add -u` handles it correctly without crashing.

The test covers both the crash scenario and verifies the correct post-conditions: the unmerged state remains, the deleted file is properly staged as deleted, and no spurious errors occur. This appears to be a clean, focused fix for a real edge case in the merge machinery. The change is minimal (just one line disabling rename detection) and well-justified by the commit message. The test case will help prevent regression of this behavior in the future.
