This is a feature patch introducing new `includeIf` conditions for Git config files, specifically targeting multi-worktree setups. It's the first in a 3-patch series from Chen Linxuan.

The patch adds two new condition keywords to `includeIf` directives:
- `worktree:<pattern>` matches the realpath of the current worktree's working directory against a glob pattern
- `worktree/i:<pattern>` provides a case-insensitive variant

The motivation is that in multi-worktree setups, the `.git` directory of linked worktrees points to the main repository's `.git/worktrees/`, making existing `gitdir` patterns cumbersome when trying to match based on the working tree path. The implementation refactors the existing `include_by_gitdir()` into a more generic `include_by_path()` that can work with either gitdir or worktree paths.

Key technical details:
- Uses `repo_get_work_tree()` to get the worktree path
- Follows same pattern matching logic as `gitdir` conditions (realpath resolution, glob patterns, symlink handling)
- Returns false for bare repos or during early config reading
- Touches only `config.c`, modifying the include condition handling logic

The patch appears well-structured with a focused scope. The commit message clearly explains the problem being solved and the solution approach. The implementation builds on existing patterns in the codebase rather than introducing new ones.
