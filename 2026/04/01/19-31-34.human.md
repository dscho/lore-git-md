This is a bugfix for the `git backfill` command's interaction with sparse-checkout configurations. Trieu Huynh (a GSoC contributor) explains that `git backfill` was ignoring repository sparse-checkout settings due to initializing the `sparse` field to 0 (forcing full backfills). The patch changes this to -1, allowing the command to respect `core.sparseCheckout` when no explicit `--sparse/--no-sparse` flags are given.

Junio Hamano questioned whether -1 truly represents "auto-detection" since the code defaults to sparse mode rather than actively detecting sparse status. In response, Trieu clarifies the current behavior: with sparse=0, the config check is skipped entirely, while sparse=-1 allows falling back to the config value. The test case verifies the new behavior by checking trace2 data in a sparse clone scenario.

The discussion now awaits input from Derrick Stolee (original author of the sparse backfill code) to clarify the intended design. The patch appears well-motivated and correctly implements the described behavior, though the conceptual framing of the -1 sentinel may need refinement based on Derrick's feedback.
