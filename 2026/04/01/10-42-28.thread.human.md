This is clearly an April Fools' joke from Patrick Steinhardt, proposing to add MD5 as a new hash algorithm option for Git repositories. The well-crafted patch satirizes the ongoing SHA-256 migration effort by suggesting MD5 would be better space efficiency while still meeting Git's needs, despite MD5 being cryptographically broken for years.

The patch includes all the technical changes needed to properly support a new hash algorithm - infrastructure updates, format handling, and OpenSSL integration - making it a humorous demonstration of Git's hash algorithm extensibility. The timing (April 1) and choice of MD5 make it clear this is tongue-in-cheek commentary on the SHA-256 transition, while also showing how far Git's hash abstraction has come since the early days when SHA-1 was hardcoded throughout the codebase.
