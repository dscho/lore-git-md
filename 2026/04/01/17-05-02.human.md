Bugfix for `git commit -a` crash during unresolved merges with rename detection.

This patch addresses a crash reported by Nick Golden where `git commit -a` would fail with an "unable to stat" error when two conditions occur simultaneously - an unresolved merge conflict and a deleted tracked file. The root cause was rename detection incorrectly pairing the deleted file with the unmerged path during index updates.

The fix from blindmansion (no full name provided) is straightforward: disable rename detection in `add_files_to_cache()` since this staging operation doesn't need it. The patch includes a thorough test case that reproduces the original crash scenario - creating two identical files, generating a merge conflict on one, deleting the other, then verifying `git add -u` handles it correctly without crashing.

This appears to be a well-considered solution to a real edge case. The test covers the problematic scenario and the change is minimal - just one line to disable rename detection. Given the clear reproduction case and non-controversial nature of the fix, this seems likely to be accepted without much discussion. The patch follows Git's conventions by including both the code change and regression test in a single commit.
