This is a bugfix for the `git backfill` command's interaction with sparse-checkout configurations. Trieu Huynh (a GSoC contributor) responds to Junio C Hamano's feedback about their patch that aimed to make `git backfill` respect repository sparse-checkout settings.

The key clarification in this response is that the current behavior was forcing a full backfill (sparse=0) regardless of the repository's core.sparseCheckout configuration, since the initialization value of 0 would bypass the config check entirely. The -1 sentinel allows falling back to the config value when no explicit --sparse/--no-sparse flag is given. Trieu explains the control flow more clearly: with sparse=0, the config check is skipped entirely, while sparse=-1 enables reading core.sparseCheckout.

The test case remains uncontested and demonstrates the desired behavior - when sparse-checkout is configured, backfill should automatically operate in sparse mode without requiring --sparse. The discussion now centers on whether this should be framed as "auto-detection" (as in the commit message) or simply as respecting the config (as Junio suggested). Derrick Stolee's input is still awaited on the original design intent for sparse handling in backfill.

This is part of Trieu's GSoC work improving the backfill command, touching the sparse-checkout subsystem originally developed by Derrick Stolee and Elijah Newren. The changes are minimal (just the initialization value flip) but important for correct behavior in sparse repositories.
