This is a response to a bug report about hash algorithm mismatches when cloning empty repositories. Patrick Steinhardt confirms that the issue Miljan Mitrovic reported was indeed a known bug that has since been fixed in Git v2.41 through the introduction of an "object-format" capability. This capability ensures the hash algorithm is properly communicated from server to client even for empty repositories.

The key technical detail here is that the fix involves protocol-level changes - the new capability allows the server to announce its object format during the clone handshake, preventing the client from defaulting to SHA1 when the remote is SHA256. This addresses the core issue where empty repository clones would silently create incompatible local repositories.

Patrick notes that users need both client and server to be running Git v2.41 or later for the fix to take effect. The response suggests this was a deliberate protocol enhancement rather than a quick fix, indicating the problem required proper infrastructure changes to solve correctly.

This exchange provides closure to the reported issue while also serving as documentation point for others encountering similar behavior - the solution is to upgrade to a recent Git version where the proper capability negotiation is implemented. The response is technically precise while remaining helpful to the original reporter.
