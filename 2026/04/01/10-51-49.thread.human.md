This thread reports a bug where cloning an empty SHA-256 repository incorrectly creates a local SHA-1 repository instead, leading to incompatibility when pushing changes back. Miljan Mitrovic discovered the issue on Windows (Git 2.39.1) but it likely affects all platforms. The problem occurs because Git fails to properly propagate the hash algorithm setting during empty repository clones, despite showing a warning about the empty clone. This creates a serious mismatch since hash algorithms can't be converted after repository creation.

The bug touches on core clone functionality and SHA-256 interoperability work, representing a potential source of repository corruption when users unknowingly create incompatible local/remote pairs. The report includes clear reproduction steps and demonstrates this is a genuine bug rather than a configuration issue. No solutions or workarounds have been proposed yet in the thread.
