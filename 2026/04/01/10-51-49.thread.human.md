This thread began with a bug report from Miljan Mitrovic about Git incorrectly creating SHA1 repositories when cloning empty SHA256 remotes, silently producing incompatible local/remote pairs. The core issue was that the hash algorithm setting wasn't properly propagated during empty repository initialization, which could cause problems when pushing commits back to the remote.

Patrick Steinhardt has now confirmed this was a known bug that was fixed in Git v2.41 through a protocol-level solution. The fix introduced an "object-format" capability that ensures the hash algorithm is properly communicated from server to client during the clone handshake, even for empty repositories. This prevents the client from defaulting to SHA1 when the remote uses SHA256.

The solution requires both client and server to be running Git v2.41 or later for the fix to take effect. Patrick's response provides clear technical details about the underlying protocol changes while also serving as useful documentation for others who might encounter this behavior. The thread now has a complete resolution - users experiencing this issue should upgrade to Git v2.41 or later where the proper capability negotiation is implemented.
