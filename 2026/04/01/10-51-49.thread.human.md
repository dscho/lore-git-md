Miljan Mitrovic reported a bug where cloning an empty SHA256 repository would incorrectly create a local SHA1 repository, causing compatibility issues when pushing changes. Patrick Steinhardt confirmed this was a known issue fixed in Git v2.41 through the introduction of an "object-format" capability in the clone protocol, which ensures proper hash algorithm propagation for empty repositories.

The fix requires both client and server to be running Git v2.41 or later. Miljan has now confirmed that upgrading their client to version 2.53 resolved the issue completely, validating that the protocol-level solution works as intended. This case demonstrates how protocol changes in Git often require coordinated updates on both ends to take effect, and serves as useful documentation for others encountering similar version-dependent behavior. The thread is now fully resolved with no remaining open questions.
