This is a performance optimization patch in Justin Tobler's series to complete the object database (ODB) write operations interface, part of the ongoing ODB abstraction effort. The patch specifically targets packfile handling when writing large blobs that exceed "core.bigFileThreshold".

The key change eliminates seek operations when packfiles approach their size limit by using the inflated blob size as an upfront approximation. Previously, Git would write the blob first, then seek back if it exceeded "pack.packSizeLimit". The new approach checks the size before writing, avoiding the seek entirely. While this may leave some unused space in packfiles (since the check uses uncompressed size rather than final compressed size), it provides a reliable way to stay under the limit without expensive seeks.

The patch simplifies the code by removing the seek/rewind logic from `stream_blob_to_pack()` and moving the size check into `index_blob_packfile_transaction()`. The changes affect how Git handles large blobs when "pack.packSizeLimit" is configured, particularly during operations like `git add` that write objects to the ODB. This optimization becomes especially valuable as the series moves toward using `struct odb_write_stream` in subsequent patches, since seek operations wouldn't be possible with that more generic interface.

For future AI reference: The patch removes the `already_hashed_to` tracking and seek logic while adding an upfront size check against `pack_size_limit_cfg`. It modifies `stream_blob_to_pack()` to no longer return an error code (changing it to void) since the size limit check now happens earlier. The changes are localized to `object-file.c` and specifically affect the packfile writing path for large blobs.
