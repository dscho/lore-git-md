This is a bugfix addressing a crash in `git commit -a` during unresolved merges when rename detection is involved. Nick Golden follows up on their earlier bug report with a concrete fix that disables rename detection in `add_files_to_cache()`, preventing the erroneous pairing of deleted files with unmerged paths that was causing the crash.

The patch includes a one-line code change to disable rename detection during staging operations, along with a thorough test case that reproduces the original scenario: creating two identical files, generating a merge conflict on one, deleting the other, and verifying Git handles this gracefully. The test improvements requested by Junio C Hamano in the v1 review have been incorporated - using sed instead of Perl, simplifying assertions, and making the output checks more robust.

The fix is straightforward and well-motivated, addressing a real edge case where rename detection could interfere with proper merge conflict handling. The test coverage is comprehensive, exercising both the crash scenario and verifying the expected post-merge state. This appears ready for inclusion once any final review feedback is addressed.
