This is a bugfix response regarding hash algorithm propagation during empty repository cloning. Patrick Steinhardt confirms that the reported issue - where cloning an empty SHA256 repository incorrectly created a local SHA1 repository - was indeed a known bug that has since been fixed in Git v2.41.

The fix introduced an "object-format" capability that properly communicates the hash algorithm between client and server, even for empty repositories. This ensures the local repository matches the remote's hash algorithm from creation. The reporter was using Git 2.39.1 on Windows, which predates this fix.

The response is straightforward and helpful - it acknowledges the problem, confirms it's been addressed, and tells the reporter exactly which version contains the fix. No further action is needed beyond upgrading to Git 2.41 or later. This closes the loop on what appeared to be a genuine bug in the SHA-256 support infrastructure.
