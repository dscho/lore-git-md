This is a documentation patch adding new config options to support conditional includes based on worktree paths. It's part of a 3-patch series (this being the second patch) introducing `worktree` and `worktree/i` conditions for config includes, analogous to the existing `gitdir` functionality but matching the working directory path instead of the `.git` directory location.

The patch thoroughly documents the new features, explaining how they differ from `gitdir` (matching the checked-out files rather than the repository metadata), supported pattern matching rules (including special cases for `~/`, `./`, and trailing `/`), and noting they don't apply to bare repositories. It includes practical examples showing how this could be used for per-worktree user.email or GPG key configurations without requiring repository-local changes like `extensions.worktreeConfig` does.

The documentation follows Git's standard format and appears complete, with clear explanations of the behavior and motivation. The patch is well-structured and maintains consistency with existing config documentation patterns.
