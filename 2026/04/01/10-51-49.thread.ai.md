Thread identity: Bug report about hash algorithm mismatch when cloning empty repositories, originally reported by Miljan Mitrovic, with follow-up from Patrick Steinhardt.

Core problem: When cloning an empty SHA256 remote repository, Git would incorrectly create a local SHA1 repository, silently creating an incompatible local/remote pair. This became problematic when pushing commits back to the remote. The root cause was missing hash algorithm propagation during empty repository cloning, despite it being a fundamental repository property that cannot be changed after creation.

Current status: The issue is confirmed resolved when using Git v2.53 (client) with the protocol fix introduced in v2.41. Miljan Mitrovic has successfully verified the solution works as intended in production use. The fix requires both client and server to run Git v2.41 or later for proper capability negotiation during clone operations.

Key technical details: The solution involved protocol-level changes - the new "object-format" capability allows the server to announce its object format during the clone handshake, preventing the client from defaulting to SHA1 when the remote is SHA256. This specifically addresses the empty repository case where the hash algorithm wasn't properly propagated before. The successful resolution with v2.53 confirms backward compatibility works as designed - newer clients properly negotiate with v2.41+ servers.
