Thread identity: Bug report about hash algorithm mismatch when cloning empty repositories, reported by Miljan Mitrovic.

Core problem: When cloning an empty SHA256 remote repository, Git incorrectly creates a local SHA1 repository instead, silently creating an incompatible local/remote pair. This becomes problematic when pushing commits back to the remote. The hash algorithm setting is not properly propagated during empty repository cloning, despite being a fundamental repository property that cannot be changed after creation.

Current status: Bug reported with clear reproduction steps on Windows (2.39.1.windows.1), likely affecting other platforms. No known fix yet. The issue touches on SHA-256 support and repository initialization.

Key technical details: Affects `git clone` operation when remote repository is empty. The warning about cloning an empty repository is shown, but the more serious hash algorithm mismatch is not indicated. The problem occurs during repository initialization where hash algorithm selection should be preserved from remote to local.

Open questions: How to properly propagate hash algorithm during empty repository initialization. Whether this affects other repository initialization settings beyond hash algorithm. Platform-specific considerations (originally reported on Windows but likely cross-platform).

Participant positions: Miljan Mitrovic reported the issue with clear reproduction steps and analysis of the implications. No other participants have responded yet.

Related work: Connects to broader SHA-256 support and repository initialization work, though this specific empty-repo case appears to have been overlooked in those efforts.
