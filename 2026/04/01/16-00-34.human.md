This is a follow-up discussion about a recently merged refactoring series in the xdiff subsystem. Phillip Wood has identified a regression in the final patch (v4 6/6) that changes diff output when using the myers algorithm. The issue stems from the patch modifying the action arrays during INVESTIGATE record handling, which affects subsequent calls to xdl_clean_mmatch(). Phillip suggests using a local variable instead of modifying actionX[i] directly to preserve the original behavior.

This comes after the series was already merged to 'next' with Junio C Hamano's approval, having gone through multiple review iterations where test failures and build warnings were addressed. The regression wasn't caught earlier because it only manifests in specific diff output cases not covered by the existing test suite (t4071, t8015).

The patch in question aimed to improve code clarity by converting nested ternaries to explicit if/else statements for INVESTIGATE record handling, adding BUG() checks for invalid states. While the refactoring achieved its readability goals, it inadvertently introduced this behavioral change. Phillip provides a concrete diff showing the output differences when running `git log` with certain options.

This appears to be a case where a well-intentioned refactoring had subtle side effects that only became apparent in real-world usage. The discussion will likely continue about whether to revert, amend, or add tests for this case.
