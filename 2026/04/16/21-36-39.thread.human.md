This thread addresses a long-standing race condition in gitk (the Git repository browser) where switching views while background diffs are still processing can trigger errors like "can't read 'treediffs(...)'". The original patch from Paul Mackerras introduced a solution that waits for all pending diff operations to complete before allowing view changes, using a runq_active counter and wait_runq_empty procedure. While functional, this approach has a performance tradeoff as it blocks on all operations, even those that may become irrelevant after the view change.

Gitk maintainer Johannes Sixt has now responded to Michael Warmuth-Uhl's follow-up, acknowledging the issue but noting that simply waiting for completion isn't ideal. He shared an alternative approach that attempts to actively clear the run queue instead, but encountered a new error ('can't unset "currunq"') due to recursive execution issues. Johannes has provided a patch showing his queue-clearing attempt and indicated he'll investigate further when time permits. The thread remains open for discussion of alternative solutions that could address the race condition without the full performance penalty of the current approach. The exchange highlights the complexity of gitk's asynchronous task handling and the challenges in cleanly canceling in-progress operations.
