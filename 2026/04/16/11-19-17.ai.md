This is a test infrastructure patch series from Patrick Steinhardt that aims to make Git's test suite more robust by enabling `set -e` (errexit) in test scripts when running under Bash 5+. The series has progressed through several iterations addressing feedback, with v3 focusing on CI validation.

The key changes in this version include:
- Explicitly configuring the `linux-TEST-vars` CI job to use Bash instead of Dash, ensuring at least one CI environment tests with Bash 5+ requirement
- Maintaining the restriction to Bash 5+ to avoid platform-specific shell quirks
- Confirming the changes work in GitLab and GitHub CI environments

The series shows careful attention to deployment safety, with Patrick acknowledging potential fallout while maintaining the position that catching silent test failures justifies proceeding. The discussion with Jeff King (Peff) has shifted from technical validation to operational verification, with consensus on the core design but continued focus on platform compatibility.

This continues Git's ongoing effort to improve test reliability, building on previous work to modernize test patterns. The changes are mechanical infrastructure improvements rather than feature work, touching many test scripts but with careful attention to backward compatibility. The series appears ready for merging as a reversible experiment, with the CI changes in v3 addressing the last remaining operational concerns.
