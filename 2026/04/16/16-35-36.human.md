This is a performance optimization patch for submodule handling in worktrees, part of a 3-patch series (position 2/3). The patch addresses a wasteful behavior where `git worktree add` with submodules would re-fetch submodule contents from remote even when they already exist in the main worktree.

The key improvement detects when a submodule exists in the main worktree but not yet in a linked worktree, and uses `git clone --local` to create hardlinks to the existing objects rather than downloading duplicates. This saves both bandwidth and disk space while maintaining proper isolation of per-worktree submodule state (HEAD, index, config).

The implementation is clean and well-explained in the commit message, with clear rationale for the approach. The patch touches only `builtin/submodule--helper.c`, adding logic to check for the common-dir case and falling back to the existing behavior when needed. The change looks straightforward and maintains backward compatibility.

This appears to be a thoughtful optimization that solves a real pain point for users who work with submodules across multiple worktrees. The patch is likely to be well-received, though reviewers may want to verify the edge cases around permission handling and error conditions.
