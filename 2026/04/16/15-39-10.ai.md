This is a bug report about unexpected behavior in `git checkout-index` and `git archive` when working with tree objects directly. Runxi Yu demonstrates that while `git cat-file -p` shows a tree object contains multiple files, both commands fail to actually extract those files when given a tree hash directly.

The key observations are:
1. `git checkout 43aa0d7...` (a tree hash) fails with "Cannot switch branch to a non-commit"
2. `git archive 43aa0d7...` produces an empty tarball
3. After using `git read-tree` to load the tree into the index, `git checkout-index -a` still doesn't extract any files despite the index clearly containing entries (verified via `xxd` dump)

The behavior is particularly surprising for `checkout-index` since its documentation states it should check out "all files in the index" with `-a` flag. The author suggests either documenting this as intentional behavior (limiting to current directory) or providing a proper way to check out trees.

This appears to be a genuine inconsistency in Git's handling of tree objects versus commits. The report is thorough, including verification that the objects exist (`git fsck`) and examination of the index contents. The issue affects both SHA-1 and SHA-256 repos. The author is not currently on the mailing list and requests replies be CC'd to them.
