This is a feature patch adding submodule support to `git worktree add`. The patch introduces a new `--recurse-submodules` flag that automatically initializes and updates submodules in the new worktree, saving users from having to run `git submodule update --init` manually afterwards.

The implementation runs a child `git submodule update --init --recursive` process after the main checkout completes, with the working directory set appropriately. The flag is incompatible with `--no-checkout` (since there would be no working tree to populate) and `--orphan` (since orphan branches have no submodule configuration).

The patch appears well-constructed with clear error handling for the incompatible flag combinations. It follows the existing pattern of worktree command implementation and includes appropriate documentation in the option help text. This seems like a useful quality-of-life improvement for users who work with submodules across multiple worktrees.
