This is a follow-up to the MIDX version compatibility fix for Git 2.54.0-rc2. Junio C Hamano is now preparing to push the MIDX version reversion (from v2 back to v1 as default) down to the 'master' branch, having already applied it in rc2. The email includes a squashable test adjustment that explicitly sets `midx.version=2` for tests requiring V2 features, since the default will now be V1.

The context here is that Johannes Schindeler (Dscho) reported repositories becoming unusable with Git 2.53 after being touched by 2.54-rc2 due to MIDX V2 incompatibility. Jeff King's solution - making V1 the default while keeping V2 opt-in - has been implemented and is now being propagated through the integration branches. Junio notes this needs to be coordinated with Taylor Blau's incremental MIDX work (the 'tb/incremental-midx-part-3.3' branch).

The patch demonstrates Git's careful handling of file format changes, where new versions are introduced as opt-in features until the ecosystem (including reimplementations like libgit2 and JGit) has time to catch up. The test adjustment shows how features requiring V2 will need to explicitly request it going forward, while most operations will continue working with the more widely compatible V1 format by default.
