This is a follow-up discussion on the `--recurse-submodules` support for `git worktree add` series. Junio C Hamano raises concerns about the implementation's reliance on hardlinks for sharing submodule objects between worktrees, noting that Git's native worktree support was specifically designed to work well on platforms where hardlinks are problematic.

Junio suggests an alternative approach leveraging `absorbgitdirs` - the existing mechanism for moving submodule repositories into the superproject's `$GIT_DIR/modules/`. This would create a single bare repository for the submodule that could then be shared across worktrees, with each worktree having its own working tree while sharing the underlying repository data. This matches the original motivation for `absorbgitdirs` - preserving submodule repositories when switching to commits that don't reference them.

The comment indicates the current patch series may need reconsideration of its object-sharing strategy, particularly regarding platform compatibility. Junio's suggestion points toward using Git's existing worktree infrastructure more directly rather than implementing a separate hardlink-based sharing mechanism. This feedback will likely require revisions to the implementation to better align with Git's cross-platform design principles.
