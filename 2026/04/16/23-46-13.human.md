This is a documentation patch adding platform compatibility guidance for timestamp handling in Git's codebase. Elijah Newren provides a review of Junio Hamano's patch that clarifies macOS's lack of POSIX-compliant nanosecond-resolution timestamp fields (`st_mtim`).

The review is surface-level, focusing only on a minor grammatical nit ("need timestamp" -> "need a timestamp"). Elijah agrees with the substance of the change, which documents that `st_mtime` should be used when second-level precision suffices, as macOS doesn't support the POSIX `st_mtim` field. The patch emerged from real-world issues encountered in Lorenzo Pegorari's promisor file repacking series.

This is a straightforward documentation improvement that will help prevent platform-specific timestamp handling issues in future code. The review confirms the technical accuracy of the change while suggesting a small wording tweak.
