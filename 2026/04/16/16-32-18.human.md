This is a feature patch series introducing `--recurse-submodules` support for `git worktree add`. The series follows up on earlier RFC discussion with a native C implementation that properly isolates submodule state per worktree while sharing object storage.

The key innovation is treating submodules in linked worktrees similarly to how the superproject already handles them - each gets its own gitdir under `$GIT_COMMON_DIR/worktrees/<id>/modules/` while sharing pack files via hardlinks. This maintains the worktree model's isolation guarantees while avoiding redundant network fetches when the submodule is already cloned in the main worktree.

The implementation comes in three parts: adding the flag and basic plumbing in the worktree command, optimizing submodule initialization to reuse existing clones, and comprehensive test coverage. The approach appears well-considered, building on existing patterns and addressing prior feedback about implementation strategy.

The series looks production-ready with thorough test coverage of both happy paths and edge cases. It touches core worktree and submodule integration points, so careful review of the isolation semantics would be warranted, but the design follows established conventions and the commit messages clearly explain the approach.
