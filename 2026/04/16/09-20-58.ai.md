This is the second patch in a three-part bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when `http.emptyAuth=auto` is configured. The patch modifies the authentication flow to properly handle Negotiate authentication in auto mode.

The core change delays stripping the Negotiate authentication method on the first 401 response when in auto mode, allowing the empty-auth mechanism to attempt using the system Kerberos ticket cache. If that attempt fails (no valid ticket), Negotiate is then stripped on the second 401 response. The patch introduces a new `empty_auth_try_negotiate` flag to track this state and modifies `http_reauth_prepare()` to skip credential filling when an empty auth attempt is pending.

The change is well-contained to HTTP authentication logic in `http.c`, touching only the retry path and auth method management. It preserves the existing behavior of `http.emptyAuth=true` (always send empty credentials) and `false` (never send empty credentials), while fixing the auto mode's interaction with Negotiate auth. The commit message clearly explains the problematic interaction between two historical changes (2015's Negotiate stripping and 2017's auto mode) and how this patch resolves it.

This appears to be a straightforward fix for a real-world authentication issue affecting Kerberos users. The change is logically sound and maintains backward compatibility while restoring the intended auto mode functionality. The patch builds on the preparatory refactoring from patch 1/3 and will be followed by test coverage in patch 3/3.
