This is the first patch in a bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) and the `http.emptyAuth=auto` configuration. The patch is a pure refactoring that extracts common credential-filling code from three HTTP retry paths into a new `http_reauth_prepare()` helper function.

The change is straightforward and mechanical - it moves the `credential_fill()` call that happens during HTTP reauthentication into a shared function, without altering any behavior. This sets up the next patch to modify the reauthentication logic in one place rather than three.

The patch touches `http.c`, `http.h`, and `remote-curl.c`, adding the new helper and updating the call sites. The commit message clearly states this is a preparatory change with no functional impact, making it easy to review. As the first step in fixing a real authentication issue, this looks like a clean, well-contained refactoring that will make the actual behavior change simpler to implement and verify.
