Patrick Steinhardt's RFC patch series (v3) to reorganize Git's source tree by moving all `libgit.a` components into a new `lib/` directory continues as a **refactoring-only** effort to reduce root-directory clutter (from ~550 to ~80 files) and establish a clearer boundary for Git's core library code. This iteration explicitly acknowledges the downsides of the mass rename—disrupted `git log --follow` history, rebasing/backporting challenges for in-flight topics, and merge conflicts for downstream forks (e.g., GitHub, Microsoft Git)—but frames these as one-time costs justified by permanent improvements in code discoverability and onboarding. The commit message now includes this trade-off rationale, addressing SZEDER Gábor's earlier objection about historical tracking by positioning it as a tooling deficiency the project should address. Johannes Schindelin's Windows CI fix (adjusting `.github/workflows/main.yml` to reference `lib/compat`) is incorporated, resolving the Visual Studio build regression from v2.

The series remains two patches: (1) a preparatory change to `t/helper/test-example-tap.c` to ensure build integrity, and (2) the main patch moving ~700 files (core subsystems like object handling, refs, diff, merge, and platform compatibility shims) into `lib/` while preserving internal structure. Changes are dominated by path updates in build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, `config.mak.uname`) and CI workflows.

**Core debate status**: The discussion remains polarized between structural benefits and logistical disruption. Proponents (Patrick, Oswald Buddenhagen, Johannes Schindelin) argue the reorganization improves discoverability and could incentivize tooling improvements (e.g., better rename tracking in `git log`). Opponents (Junio C Hamano, SZEDER Gábor, Derrick Stolee) emphasize the disruption to ongoing work, backporting, and historical tracking, viewing the change as cosmetic and risky during the prerelease freeze. Junio's skepticism persists despite the explicit trade-off framing in v3, while SZEDER's objection about `git log --follow` is now countered by Patrick's tooling-incentive argument.
