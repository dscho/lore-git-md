RFC proposal from Patrick Steinhardt to reorganize Git's source tree by moving all libgit.a components into a new "lib/" directory, with implementation now provided in the second patch. The change relocates ~700 files from Git's root directory (including core subsystems like object handling, refs, diff, merge, and utilities) while preserving their internal structure. Build system files (Makefile, CMakeLists.txt, meson.build) are updated to reflect new paths, along with CI workflows and documentation references. Minimal code changes beyond location updates.

Motivation remains improved code discoverability by reducing root directory file count from ~550 to ~80, making libgit.a boundary more visible in directory structure. Follows 2024 Contributor's Summit discussions. Elijah Newren has reviewed the proposal and generally supports the reorganization, agreeing it improves discoverability. His only reservation concerns moving the sha1collisiondetection submodule into lib/, noting submodule renames can sometimes be problematic, though he qualifies this as a minor practical issue given the submodule's infrequent updates. 

brian m. carlson has added surface-level support for the general direction, endorsing the improved organization and incremental approach while speculating about Rust code potentially influencing future layout decisions. This review does not examine implementation specifics but provides a +1 from an established contributor.

Implementation appears mechanically sound with comprehensive path updates across all three build systems (Make, CMake, Meson). RFC status indicates openness to feedback, though patch completeness suggests readiness to proceed if consensus forms. Timing targets next release cycle if accepted, allowing maximum time to address fallout. Tested against GitLab and GitHub builds.
