Patrick Steinhardt's RFC patch series (v2) to reorganize Git's source tree by moving all `libgit.a` components into a new `lib/` directory is now complete. The series aims to reduce root directory clutter (from ~550 to ~80 files) to improve shell tab completion and establish a clear boundary for `libgit.a`. Version 2 addresses all prior feedback, including Meson build logic, ODB source handling, fsmonitor backend paths, Rust build requirements, and submodule complications, with no outstanding technical objections from reviewers.

The first patch (1/2) was a preparatory adjustment to `t/helper/test-example-tap.c`, changing an include path to ensure build integrity after relocation. The second and final patch (2/2) performs the bulk relocation of ~700 files—including core subsystems (object handling, refs, diff, merge) and platform compatibility shims—into `lib/` while preserving internal structure. Changes are dominated by path updates in build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, `config.mak.uname`), CI workflows (GitHub Actions), and platform-specific logic. No functional changes or new symbols are introduced; this is purely a structural reorganization.

The series has been tested across GitLab and GitHub CI pipelines, with preliminary approval from Johannes Schindelin (Git for Windows) for the transition. Derrick Stolee's earlier concerns about merge conflicts and rebase challenges for long-lived forks (GitHub, Microsoft Git) are being addressed through incrementalism and Patrick's willingness to assist. However, Junio C Hamano has now expressed skepticism about the reorganization's practical benefits, framing it as a cosmetic change that may not justify the disruption to in-flight and upcoming patches, particularly during the prerelease freeze period. While Junio has not outright rejected the idea, his tone suggests reluctance, emphasizing the logistical burden of updating topics and complicating backporting fixes to older versions. The discussion now centers on whether the structural improvement outweighs the maintenance overhead, with no technical objections raised but timing and coordination emerging as key concerns. Downstream consumers should anticipate further debate about transition timing and its impact on long-lived forks. Key files introduced/modified remain `lib/` directory paths, build system files, and CI workflows.
