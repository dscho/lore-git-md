RFC proposal from Patrick Steinhardt to reorganize Git's source tree by moving all libgit.a components into a new "lib/" directory, with implementation now provided in the second patch. The change relocates ~700 files from Git's root directory (including core subsystems like object handling, refs, diff, merge, and utilities) while preserving their internal structure. Build system files (Makefile, CMakeLists.txt, meson.build) are updated to reflect new paths, along with CI workflows and documentation references. Minimal code changes beyond location updates.

Motivation remains improved code discoverability by reducing root directory file count from ~550 to ~80, making libgit.a boundary more visible in directory structure. Follows 2024 Contributor's Summit discussions. Elijah Newren has reviewed the proposal and generally supports the reorganization, agreeing it improves discoverability. His only reservation concerns moving the sha1collisiondetection submodule into lib/, noting submodule renames can sometimes be problematic, though he qualifies this as a minor practical issue given the submodule's infrequent updates.

brian m. carlson has added substantive technical input regarding Rust build requirements: the `build.rs` file must remain at the repository root for proper `cargo` invocation, but suggests Patrick's proposed "rust/" subdirectory for source files would address Junio's tab completion concern while maintaining build functionality. This clarifies an important platform-specific constraint that wasn't fully addressed in the original RFC. brian m. carlson also previously expressed surface-level support for the general direction, endorsing the improved organization and incremental approach while speculating about Rust code potentially influencing future layout decisions.

Junio C Hamano (the maintainer) expresses general support, citing a concrete usability motivation: the current file density interferes with shell tab completion (specifically `built<TAB>` not completing cleanly to `builtin` due to competing files like `build.rs`). His comment suggests he would welcome either renaming `build.rs` or moving the `builtin` directory/files to resolve this shell usability issue. The maintainer's lack of objections signals the change is unlikely to face high-level resistance.

Implementation appears mechanically sound with comprehensive path updates across all three build systems (Make, CMake, Meson). RFC status indicates openness to feedback, though patch completeness suggests readiness to proceed if consensus forms. Timing targets next release cycle if accepted, allowing maximum time to address fallout. Tested against GitLab and GitHub builds. Would be significant structural change affecting all build configurations and downstream consumers relying on current header locations. Elijah's substantive review combined with endorsements from brian m. carlson and Junio suggest the proposal is fundamentally sound and likely to proceed with minor adjustments, now incorporating Rust build system requirements.
