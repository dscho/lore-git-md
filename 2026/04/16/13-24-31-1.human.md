This is the second patch in Patrick Steinhardt's RFC series proposing a major refactoring of Git's source tree structure. The patch moves nearly 700 files that make up libgit.a into a new "lib/" directory, reducing the root directory from ~550 files to ~80 files.

The change is purely organizational - it relocates files but makes no functional modifications. Core subsystems like object handling, refs, diff, merge are moved while maintaining their internal structure. The extensive diff shows updates to build system files (Makefile, CMakeLists.txt, meson.build) to handle the new paths.

Patrick's motivation, explained in the commit message, focuses on improving code discoverability - both for newcomers who currently face an overwhelming root directory, and for experienced contributors who struggle to navigate the flat structure. He notes this follows up on discussions from the 2024 Git Contributor's Summit.

The RFC status signals this is a proposal open to discussion, not a final decision. The patch has been tested against GitLab and GitHub builds, suggesting Patrick has done due diligence on compatibility. However, the scale means it would impact nearly every build configuration and downstream consumers relying on current header locations.

This structural change would be one of the most significant reorganizations in Git's history if accepted. While mechanically straightforward, the community will need to weigh the benefits of better organization against the churn of updating build systems and documentation references. The timing right before a new release cycle suggests Patrick wants to land this early if accepted, giving maximum time to address any fallout.
