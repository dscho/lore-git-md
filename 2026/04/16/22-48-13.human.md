This is the second patch in a 3-part performance optimization series for partial clone behavior, focusing on `git cherry`. The patch implements batch prefetching of blobs needed for patch-ID comparisons in partial clones, addressing a performance bottleneck where hundreds of single-blob fetches could take 3 seconds each.

The core change is a new `prefetch_cherry_blobs()` function that:
1. Temporarily swaps the hashmap comparison function to identify which commits will need blob content
2. Collects all required blob OIDs without triggering individual fetches
3. Performs a single batch fetch of all needed blobs
4. Restores the original comparison function before proceeding

The implementation includes careful handling of edge cases like binary files (which don't need blob fetches) and merge commits (which are skipped). A detailed design spec document is included explaining the algorithm and rationale. New tests verify the prefetch behavior in partial clone scenarios.

The changes are focused and unlikely to be controversial, with clear test coverage demonstrating the improvement from hundreds of fetches to just one.
