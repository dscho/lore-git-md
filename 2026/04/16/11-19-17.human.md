This is a test infrastructure patch series from Patrick Steinhardt that aims to make Git's test suite more robust by enabling `set -e` (errexit) to catch errors outside of test cases. The series has progressed through three iterations, with v3 focusing on CI validation and platform-specific adjustments.

The key changes in this version include configuring an explicit Ubuntu-based CI job to use Bash (not Dash) for verification, though Patrick notes package mirror issues prevented full validation. The series remains limited to Bash 5+ to avoid shell quirks, and maintains the "merge and see" approach as a reversible experiment.

Jeff King (Peff) had raised concerns about CI platform compatibility, which Patrick addresses by confirming their Fedora CI already uses Bash 5.3.0 and adding the Ubuntu/Bash job. The discussion shows consensus on the core design but careful attention to deployment safety, with Patrick acknowledging potential future maintenance costs while emphasizing the benefits of catching silent test failures.

The 12 patches prepare various test helper functions and existing tests to work correctly with `set -e` enabled, touching areas like signal handling, daemon management, and conditional test execution. While mechanical in nature, these changes are important for test reliability and continue Git's ongoing effort to improve test robustness. Reviewers will want to verify the error handling changes don't introduce false positives in existing tests.
