This is the second patch in a three-part bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch modifies the authentication flow to properly handle Negotiate authentication in auto mode.

The core change delays stripping the Negotiate authentication method on the first 401 response when in auto mode, allowing the empty-auth mechanism to attempt using the system Kerberos ticket. If that attempt fails (no valid ticket), Negotiate is then stripped on the second 401 response. The patch introduces a new `empty_auth_try_negotiate` flag to track this state and modifies `http_reauth_prepare()` to skip credential filling when an empty auth attempt is pending.

The change is well-contained to the HTTP authentication logic and maintains backward compatibility with existing behavior for `http.emptyAuth=true` and `false` modes. The commit message clearly explains the interaction between the two historical features (2015's Negotiate stripping and 2017's auto mode) that led to the current bug. The solution aligns with the documented behavior of auto mode while adding just one additional round-trip when no valid Kerberos ticket exists.

This appears to be a straightforward fix for a real-world authentication issue affecting Kerberos users, building on the preparatory refactoring from patch 1/3. The changes are focused and the explanation is thorough, making this easy to review. The test coverage in patch 3/3 will verify the new behavior.
