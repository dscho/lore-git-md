[PATCH v2 2/3] submodule: optimize clone in linked worktrees by reusing main worktree objects

This patch series addresses performance when cloning submodules in linked worktrees. The core optimization detects when a submodule already exists in the main worktree's commondir and performs a local clone with hardlinks instead of a full remote fetch, saving bandwidth and disk space while maintaining worktree isolation.

The current patch modifies clone_submodule() in builtin/submodule--helper.c to first check for an existing submodule in the main worktree via the_repository->commondir. If found, it uses git clone --local to create hardlinks to the existing objects while keeping worktree-specific metadata (HEAD, config) separate. The change handles edge cases like non-empty target directories and maintains clear error reporting.

Technical details: The implementation adds about 50 lines focused on the new local-clone path, leaving the remote clone fallback unchanged. It builds on existing submodule and worktree infrastructure without introducing new user-facing options. The optimization specifically targets the common case where multiple worktrees need the same submodule checked out at similar revisions.
