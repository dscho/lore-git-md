This is a test infrastructure change from Patrick Steinhardt, part of his ongoing series to enable `set -e` in Git's test suite when running under Bash 5+. The patch modifies the `test_must_fail()` helper function to work correctly with `set -e` by changing how it captures exit codes from failing commands.

The key change replaces direct command execution with a pattern that captures the exit code even when the command fails (`exit_code=0; "$@" || exit_code=$?`). This prevents `set -e` from causing the test to abort early when a command fails - which is exactly the expected behavior for `test_must_fail()`. The change is mechanical but important for maintaining test suite behavior when `set -e` is enabled.

This patch follows established patterns seen elsewhere in the series, showing careful attention to backward compatibility. It's a small but necessary piece of the larger effort to make the test suite more robust by catching silent failures. The change is well-contained and unlikely to be controversial, as it maintains the existing behavior while preparing for the `set -e` transition.
