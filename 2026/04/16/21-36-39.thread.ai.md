gitk bugfix addressing race condition in view changes during diff processing. Patch from Paul Mackerras fixes "can't read 'treediffs(...)'" error that occurs when switching views while background diffs are still running for large commits. Introduces runq_active counter and wait_runq_empty procedure to ensure view changes wait for pending diff operations to complete before clearing treediffs data structure. Acknowledged performance tradeoff - view changes now block for all pending operations, even those that may become irrelevant after view change. Root cause analysis identifies background task queue (runq) continuing to process diffs after dependent data is cleared. Fix modifies gitk's core task scheduling by:
- Tracking in-progress operations with runq_active counter
- Adding wait_runq_empty to block until queue drains
- Calling wait_runq_empty before view changes and treediffs clears
Known issue since 2013 (StackOverflow report) but previously unfixed. Solution functional but may need future optimization to selectively cancel unnecessary operations during view changes. Patch demonstrates deep understanding of gitk's Tcl/Tk codebase and includes reproducible test case with many-file repository.
