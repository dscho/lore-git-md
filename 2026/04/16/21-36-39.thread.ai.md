gitk race condition bugfix thread addressing "can't read 'treediffs'" error during view changes while background diffs process. Original patch from Paul Mackerras introduced runq_active counter and wait_runq_empty procedure to ensure view changes wait for pending diff operations, with acknowledged performance tradeoff. Root cause was background task queue (runq) processing diffs after dependent data cleared, a known issue since 2013.

Johannes Sixt (gitk maintainer) responds to Michael Warmuth-Uhl's follow-up, acknowledging the waiting solution but proposing alternative approach to actively clear run queue instead. His attempt involves iterating pending operations, closing file descriptors, unsetting tracking variables, and clearing runq list, but hits 'can't unset "currunq"' error due to recursive dorunq execution. Maintainer indicates further investigation needed for solution that avoids full wait penalty while cleanly canceling operations. Thread remains open with two approaches now documented:
1. Original blocking wait (functional but suboptimal performance)
2. Attempted queue clearing (fails on recursive execution edge case)

Technical details remain: runq task scheduling, treediffs data structure lifecycle, and asynchronous diff processing in Tcl/Tk context. Core challenge is coordinating view changes with background operations that may become irrelevant mid-execution. Both solutions demonstrate deep gitk internals knowledge but highlight complexity of asynchronous task cancellation in the codebase.
