This is the third and final patch in Elijah Newren's series optimizing partial clone behavior, focusing on `git grep`. The patch adds batch prefetching of blobs to avoid the performance penalty of on-demand single-blob fetches in partial clones.

The implementation introduces several key components:
- `collect_blob_oids_for_tree()` and `collect_blob_oids_for_treeish()` walk trees to identify all blobs that will be needed for the grep operation
- `prefetch_grep_blobs()` collects these OIDs and performs a single batch fetch via `promisor_remote_get_direct()`
- The prefetch runs before the main grep operation begins
- Submodules are explicitly excluded since they have their own promisor configuration
- New tests verify the behavior in a blobless clone scenario

The changes follow the same pattern as the earlier `git cherry` optimization in the series, demonstrating careful attention to edge cases and maintaining the existing grep behavior while adding the prefetch optimization. The test shows the expected batch prefetch of all 3 blobs in one operation.

This completes the series' goal of extending batch prefetching to more commands, addressing a real performance pain point for partial clone users. The implementation appears solid and consistent with Git's existing prefetch patterns.
