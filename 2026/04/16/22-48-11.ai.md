This is a performance optimization series focused on improving partial clone behavior for `git` commands. The cover letter explains the motivation well - partial clones trade upfront blob downloads for on-demand fetching, but some commands can suffer severe performance penalties when they fetch blobs one at a time.

The series extends batch prefetching (already implemented for checkout/diff/merge) to two additional commands:
1. `git cherry` - fixes a reported case where hundreds of single-blob fetches were taking 3s each
2. `git grep` - added opportunistically while working on the cherry improvements

The implementation includes:
- A preparatory doc fix for patch-ids.h
- Core changes to add prefetching logic to both commands
- New tests verifying the behavior
- A detailed design spec document explaining the cherry prefetch implementation

The changes look well-motivated and carefully considered, coming from Elijah Newren who has deep expertise in Git's merge machinery and performance optimizations. The inclusion of a design spec document suggests thorough planning went into the cherry prefetch implementation.

This appears to be a solid performance improvement for partial clone users, particularly benefiting workflows that use `git cherry` heavily. The changes are focused and unlikely to be controversial.
