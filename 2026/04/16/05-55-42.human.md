This is a documentation patch that adds a detailed technical specification for the LMAP (Loose Object Map) binary format. The format is used by the experimental Rust implementation in `loose.rs` to map between different object ID formats (e.g., SHA-1 and SHA-256), but until now, its design was undocumented, making it difficult for C developers to understand or work with.

The patch creates a new file, `Documentation/technical/loose-object-map.adoc`, which provides a bit-by-bit breakdown of the LMAP format, including its header, object format table, data sections, and trailer. It also updates the build system (`Makefile` and `meson.build`) to include the new documentation in the generated output. The specification is thorough, covering alignment requirements, byte order, and the purpose of each field, which should make it easier for developers to implement or debug code that interacts with LMAP files.

The motivation is clear: without this documentation, C developers would have to reverse-engineer the format from the Rust implementation, which is inefficient and error-prone. The patch addresses a real gap in the project’s technical documentation. The commit message is concise and explains the purpose well, though it doesn’t mention whether this format is intended for broader adoption or remains experimental.

This patch is standalone and doesn’t appear to be part of a larger series. It’s a well-scoped contribution that should be uncontroversial, assuming the LMAP format is here to stay. If you’re interested in object ID interoperability or the Rustification effort, this is worth reviewing. Otherwise, it’s a niche addition that won’t affect most users.
