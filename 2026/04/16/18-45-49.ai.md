This is a MIDX (multi-pack-index) compatibility fix for the upcoming Git 2.54.0 release. The patch reverts the default MIDX version from v2 back to v1 to maintain backward compatibility with Git 2.53.0, addressing a regression where repositories touched by v2.54.0-rc2 became unusable with the stable release.

Jeff King (Peff) identified the issue where older Git versions would `die()` when encountering unknown MIDX versions rather than gracefully falling back to pack files. The solution implemented here makes v1 the default again while keeping v2 available via explicit configuration (`midx.version=2`). This maintains compatibility while allowing users who need v2 features (like compaction) to opt in.

The patch updates the MIDX writer to use v1 by default and modifies tests that exercise v2-specific features to explicitly request v2. Junio C Hamano has reworded the commit message to better explain the context - that this is a temporary measure until the ecosystem (including libgit2 and JGit) catches up with MIDX v2 support.

This change demonstrates Git's conservative approach to file format changes, prioritizing stability over new features by default. The solution has already been applied in rc2 and appears to be the consensus approach for resolving this compatibility issue, with broader error handling improvements (changing `die()` to `error()` for unknown versions) potentially coming in a future release.
