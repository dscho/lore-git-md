Bugfix for gitk's Tcl/Tk GUI, addressing a race condition when changing views. 

Michael Warmuth-Uhl reports that gitk can crash with a "no such variable" error when displaying a large commit and then quickly changing the view (e.g., switching to "All Files"). The error occurs because the view-changing code clears the `treediffs` variable while background tasks still need it. The provided patch works around this by making view changes wait for pending background operations to complete, though the author notes this is a slow solution that feels suboptimal.

The issue is reproducible with a test repository containing many large files. While this fixes the immediate crash, the author acknowledges it's not the cleanest solution - a proper fix would involve properly flushing the background task queue rather than just waiting for it to drain. This appears to be a long-standing issue, with reports dating back to at least 2013 on Stack Overflow.

The patch affects gitk's task scheduling system, adding synchronization around view changes to prevent the race condition. While functional, the solution may impact responsiveness when switching views on large repositories. The core issue stems from gitk's Tcl/Tk event loop architecture where background tasks can outlive the UI operations that spawned them.
