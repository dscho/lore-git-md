This thread discusses the planned deprecation of `git whatchanged`, a legacy command whose functionality is fully covered by `git log --raw --no-merges`. The original proposal to remove it came from core contributors citing maintenance burden, with technical analysis showing how `git log` can serve as a complete replacement. Several regulars supported deprecation as part of Git's broader effort to simplify its command set.

The maintainer, Junio C Hamano, has now weighed in on user feedback message expressing attachment to the command. While acknowledging the sentiment, Junio points out that the existing deprecation warning already provides clear migration paths - either using `git log` directly or creating an alias. His response suggests skepticism that this represents a genuine obstacle, given how straightforward the alternatives are. The exchange confirms the deprecation process is working as intended: surfacing real usage while providing transition guidance. The project's position remains firm that this redundant functionality should be removed, with `git log` offering equivalent capabilities through its flags.
