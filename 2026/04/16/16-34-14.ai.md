Feature patch adding submodule support to worktree creation. This is the first of a 3-patch series (no cover letter provided yet).

The patch adds a `--recurse-submodules` flag to `git worktree add` that automatically initializes and updates submodules in the new worktree, rather than leaving them empty as happens currently. The implementation runs `git submodule update --init --recursive` after the main checkout completes, with the working directory set appropriately.

The flag is incompatible with `--no-checkout` (since there would be no working tree to initialize submodules in) and `--orphan` (since orphan branches have no submodule configuration). The patch includes appropriate error handling for these cases.

The change is straightforward - it adds the new flag to the option parsing and implements the submodule initialization in `add_worktree()`. The implementation respects the `--quiet` flag for suppressing submodule output. This looks like a well-motivated quality-of-life improvement for users who work with submodules across multiple worktrees.
