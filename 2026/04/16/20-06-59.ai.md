This is a follow-up to the MIDX version compatibility fix for Git 2.54.0-rc2. Jeff King (Peff) proposes a refinement to Junio's earlier patch that reverted the default MIDX version from v2 to v1.

The key improvement is making the version selection smarter - rather than always using v1, it now defaults to v1 unless a feature requiring v2 (like compaction) is requested. This reduces test churn while still maintaining compatibility with Git 2.53.0. The patch updates the MIDX writer to check for the `MIDX_WRITE_COMPACT` flag when choosing the version, and adds documentation noting that compaction requires v2.

Peff acknowledges this means users experimenting with compaction will create repositories incompatible with older Git versions, but considers this acceptable since compaction isn't enabled by default. The test changes are minimal - just updating one test expectation in t5319 since it will now generate v1 files by default. The more comprehensive v2 testing in t5335 remains valid as it explicitly tests compaction scenarios.

This approach demonstrates Git's careful balance between introducing new features and maintaining backward compatibility. The solution provides a smooth path forward where:
1. Most operations stay compatible by using v1
2. New features can explicitly opt into v2 when needed
3. The ecosystem (including libgit2/JGit) has time to catch up with v2 support

The patch is well-considered and addresses the immediate compatibility issue while setting up a sustainable model for future MIDX version transitions. It's a good example of Git's stability-first approach to file format changes.
