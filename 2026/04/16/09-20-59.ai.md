This is the test coverage patch (3/3) for the HTTP authentication bugfix series addressing Kerberos (SPNEGO) behavior with `http.emptyAuth=auto`. The patch adds two new test cases to verify the corrected interaction between Negotiate authentication and the emptyAuth configuration.

The tests validate that:
1. With `http.emptyAuth=auto`, Git now properly attempts Negotiate authentication (resulting in three 401 responses before falling back to Basic auth) when the server advertises both Negotiate and Basic auth methods. This matches the intended behavior where auto mode allows one empty auth attempt for exotic methods like Kerberos.

2. With `http.emptyAuth=false`, Git immediately strips the Negotiate header (resulting in just one 401 response) and proceeds directly to credential filling with Basic auth, maintaining backward compatibility with the existing behavior.

The test setup includes:
- Credential helper configuration to simulate credential storage
- Custom HTTP server responses that advertise both Negotiate and Basic auth
- Verification of the number of 401 responses in the curl trace output
- Checks for proper credential helper interactions

The tests are guarded by a `SPNEGO` prerequisite that checks for curl's Negotiate support, ensuring they only run when the test environment has the necessary capabilities. This completes the test coverage for the earlier refactoring and behavior changes in patches 1/3 and 2/3, providing confidence in the fix's correctness.
