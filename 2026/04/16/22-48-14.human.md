This is the third and final patch in Elijah Newren's performance optimization series for partial clone behavior, focusing on `git grep`. The patch 2/3 (already summarized) addressed `git cherry`, while this one tackles another command that suffers from slow on-demand blob fetching in partial clones.

The patch adds batch prefetching to `git grep` by:
1. Introducing a new `collect_blob_oids_for_tree()` helper that recursively walks trees to identify all blobs that would be searched
2. Adding prefetch logic that gathers these OIDs before the actual grep operation begins
3. Including a test that verifies the prefetch happens in a single batch operation

The implementation follows the same pattern as the earlier `git cherry` optimization, maintaining careful handling of edge cases (like submodules which have their own promisor configuration). The test demonstrates a 3x reduction in fetch operations by batching them together.

This completes the series' goal of improving partial clone performance for both `git cherry` and `git grep`. The changes are well-contained and unlikely to be controversial, coming from a contributor with deep expertise in Git's internals. The series appears ready for merging pending any final review feedback.
