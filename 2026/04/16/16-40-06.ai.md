This is the second patch in a three-part bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when `http.emptyAuth=auto` is configured. Junio C Hamano provides review feedback, expressing appreciation for the clear explanation of the interaction between two historical changes (2015's Negotiate stripping and 2017's auto mode) that caused the current issue.

The patch modifies the authentication flow to properly handle Negotiate authentication in auto mode by introducing a new `empty_auth_try_negotiate` flag. This delays stripping the Negotiate authentication method on the first 401 response, allowing the empty-auth mechanism to attempt using the system Kerberos ticket cache. If that attempt fails, Negotiate is then stripped on the second 401 response.

Junio notes that while the global variable approach aligns with the current single-session design, a future refactor might move this state into a struct for multi-session support. He also points out that the documentation for `http.emptyAuth` could be clearer about its possible values. The review concludes with positive feedback on the solution's design, particularly how it maintains existing behaviors while fixing the auto mode's interaction with Negotiate auth.

The patch builds on the preparatory refactoring from patch 1/3 (which Junio has already acked) and will be followed by test coverage in patch 3/3. With Junio's approval of the approach, this appears merge-ready pending review of the remaining patches.
