This is a test infrastructure change from Patrick Steinhardt, part of his ongoing series to enable `set -e` (errexit) in Git's test suite when running under Bash 5+. The patch focuses on making `git config --unset` calls resilient to failures when the configuration being unset doesn't exist.

The change modifies three test scripts where `git config --unset` was used without checking the exit code. These calls were previously safe because the test suite didn't use `set -e`, but would fail under the stricter error checking Patrick is introducing. Each call is updated to append `|| :` to silently ignore failures when the config key isn't present.

This is a mechanical but necessary change that follows the pattern established in earlier patches of the series - making test infrastructure robust to `set -e` while maintaining backward compatibility. The changes are straightforward and well-contained, touching only the specific test files where unconditional unset operations occurred. As with the rest of the series, this appears ready for merging as part of the broader effort to improve test reliability.
