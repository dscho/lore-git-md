This is a test infrastructure patch from Patrick Steinhardt, part of his ongoing series to enable `set -e` in Git's test suite when running under Bash 5+. The patch modifies the `test_must_fail()` helper function to work correctly with `set -e` by changing how it captures exit codes from failing commands.

The key change replaces direct command execution with a pattern that explicitly captures the exit code (`exit_code=0; "$@" 2>&7 || exit_code=$?`), preventing `set -e` from causing early termination when the command fails (as expected). This maintains the function's ability to verify that commands fail in specific ways while being compatible with the stricter error handling that `set -e` provides.

The patch is a mechanical but important adjustment to core test infrastructure, ensuring one of Git's most frequently used test helpers (`test_must_fail`) continues working as intended under the new `set` regime. It follows the series' established pattern of making targeted, backward-compatible changes to individual test components. The change is straightforward and unlikely to be controversial, as it preserves existing behavior while enabling the broader `set -e` improvement.
