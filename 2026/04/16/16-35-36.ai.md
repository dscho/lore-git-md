This is a performance optimization patch (part 2 of 3) that improves how submodules are cloned in linked worktrees. The patch detects when a submodule already exists in the main worktree and reuses its objects via a local clone with hardlinks, avoiding redundant network fetches and disk usage.

The key change is in `clone_submodule()` where it now checks if the submodule exists in the main worktree's common directory before attempting a remote clone. If found, it uses `git clone --local` to create hardlinks to the existing objects while maintaining separate per-worktree metadata (HEAD, config, etc). This maintains worktree isolation while saving bandwidth and disk space.

The implementation handles edge cases like non-empty target directories and ensures proper error messages. The change is contained to `builtin/submodule--helper.c` and adds about 50 lines of focused logic. This appears to be a well-motivated optimization for a real-world pain point when working with submodules across multiple worktrees.

For future reference in this thread: The patch modifies submodule cloning behavior specifically for linked worktrees, introducing a new code path that checks `the_repository->commondir` for existing submodules before falling back to remote cloning. It uses Git's existing `--local` clone capability but applies it in a new context (worktree submodules). The change is performance-focused and doesn't introduce new user-facing options, building on existing submodule and worktree infrastructure.
