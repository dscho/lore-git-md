This thread centers on adding `--recurse-submodules` support to `git worktree add`, allowing new worktrees to initialize their submodules while maintaining proper isolation. The original 3-part series proposed using hardlinks to share submodule object data between worktrees, with each worktree getting its own gitdir under `$GIT_COMMON_DIR/worktrees/`. The implementation included optimizations to reuse existing submodule clones and thorough test coverage.

Junio C Hamano has now raised concerns about the hardlink approach, noting it could cause problems on platforms where Git's worktree support was specifically designed to avoid hardlink dependencies. He suggests an alternative leveraging `absorbgitdirs`—Git's existing mechanism for consolidating submodule repositories—which would create a single bare repository per submodule shared across worktrees, with each worktree maintaining only its working tree. This approach would better align with Git's cross-platform design. The feedback indicates the series will likely need revisions to its object-sharing strategy before proceeding.
