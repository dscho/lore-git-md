This thread explores how to implement `--recurse-submodules` support for `git worktree add`, focusing on how submodule objects should be shared between worktrees while maintaining isolation. The original proposal used hardlinks for object sharing, but Junio C Hamano raised cross-platform compatibility concerns, suggesting instead a single bare submodule repository. Phillip Wood then proposed an alternative using `commondir` files to leverage Git's existing worktree infrastructure.

Phillip has now identified a significant issue with his `commondir` approach: it could cause `git gc` in submodules to miss per-worktree refs and index files, potentially leading to premature object deletion. This discovery strengthens the case for Junio's single-repository approach, which would handle garbage collection more robustly. The discussion remains technical and nuanced, with tradeoffs between platform support, implementation complexity, and proper integration with Git's object lifecycle. While no final decision has been made, the thread is converging toward recognizing that Junio's simpler design may be the most reliable path forward, despite initially seeming less aligned with the original isolation goals.
