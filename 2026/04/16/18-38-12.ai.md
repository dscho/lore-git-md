This is a technical discussion about implementing `--recurse-submodules` support for `git worktree add`, focusing on the object-sharing mechanism between worktrees. Phillip Wood responds to Junio C Hamano's concerns about the current hardlink-based approach by proposing an alternative using `commondir` files, similar to how Git's native worktree support avoids hardlinks.

Phillip suggests creating a `commondir` file in each submodule's gitdir (under `$GIT_COMMON_DIR/worktrees/<id>/modules/<name>/`) that would point back to the main submodule repository in `$GIT_DIR/modules/`. This would maintain the desired isolation of per-worktree state (HEAD, refs, index) while sharing repository data through Git's existing worktree infrastructure rather than hardlinks. A key advantage is that removing a worktree would automatically clean up its submodules' worktrees without additional logic.

The email continues the thread's central debate about how to best share submodule repositories across worktrees while maintaining platform compatibility. Phillip's proposal attempts to address Junio's concerns by leveraging more of Git's built-in worktree mechanisms rather than introducing new hardlink-based sharing. This suggests the implementation may be moving toward a solution that better aligns with Git's cross-platform design principles, though the discussion of tradeoffs between approaches remains open.
