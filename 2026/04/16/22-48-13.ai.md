This is the second patch in a 3-part performance optimization series for partial clone behavior, focusing on `git cherry`. The patch implements batch prefetching to avoid the performance penalty of individual on-demand blob fetches when computing patch IDs in partial clones.

The core change introduces a `prefetch_cherry_blobs()` function that:
1. Temporarily swaps the hashmap comparison function to identify blob OIDs that would be needed for patch ID computation
2. Collects these OIDs from both upstream and head-side commits
3. Performs a single batch fetch of all required blobs
4. Restores the original comparison function before proceeding with normal operation

The implementation includes careful handling of edge cases:
- Early exit when not in a partial clone
- Special handling for root commits and merge commits
- Skipping binary files (which don't require blob content for patch IDs)
- Maintaining the existing patch ID computation logic exactly

The patch comes with:
- A detailed design specification document explaining the algorithm
- New tests verifying the prefetch behavior in partial clones
- Performance validation showing reduction from multiple individual fetches to a single batch operation

This appears to be a well-considered optimization that follows the established pattern of batch prefetching in other Git commands. The design spec demonstrates thorough analysis of the problem space and edge cases.
