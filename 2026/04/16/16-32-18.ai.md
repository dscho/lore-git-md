This is a feature patch series introducing `--recurse-submodules` support for `git worktree add`. The 3-part series follows up on earlier RFC discussion and implements a solution for efficiently creating worktrees that include initialized submodules.

The core idea is to maintain submodule isolation per worktree while sharing object data. Each linked worktree gets its own submodule gitdir under `$GIT_COMMON_DIR/worktrees/<id>/modules/<name>/`, keeping HEAD, refs and index separate while hardlinking pack files and objects from the main repository. This matches Git's existing worktree model for the superproject.

Patch 1 adds the flag and basic plumbing, calling `git submodule update --init --recursive` after checkout. Patch 2 optimizes by reusing existing submodule clones via local clones rather than refetching. Patch 3 adds test coverage verifying both behavior and gitdir isolation.

The implementation appears well-considered, building on existing patterns and infrastructure. The reuse of `submodule_name_to_gitdir()` for isolation and automatic cleanup via `remove_dir_recursively()` suggests careful attention to integration with Git's existing worktree model. The test coverage in t2405 looks thorough, checking both happy paths and invariants.

This addresses a real workflow need - creating worktrees with initialized submodules - in a way that should be efficient (avoiding redundant network/disk usage) and maintainable (following established worktree patterns).
