This is a bug report highlighting inconsistent behavior in `git checkout-index` and `git archive` when working with tree objects. Runxi Yu demonstrates that while `git checkout-index -a` claims to check out "all files in the index", it fails to do so when the index contains a tree object (as populated by `git read-tree`). Similarly, `git archive` produces an empty tarball when given a tree object directly.

The report includes detailed reproduction steps showing that:
1. The tree object exists and contains valid blobs (verified by `git cat-file`)
2. The index is correctly populated (verified by examining the index file)
3. The checkout operation silently fails rather than checking out the tree contents

The author suggests this may be a documentation issue (clarifying that "all files" only applies to the current directory) or potentially a bug in the implementation. They ask whether there's a better way to check out a tree object's contents without using `-C` to change directories.

This appears to be a legitimate edge case in Git's object handling that could affect users trying to programmatically work with tree objects. The behavior difference between `read-tree` populating the index and `checkout-index` failing to act on that index is particularly surprising.
