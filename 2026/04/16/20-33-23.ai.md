This is a bugfix patch from Junio C Hamano targeting the multi-pack-index (MIDX) subsystem. The patch improves error reporting when loading MIDX files, distinguishing between expected and unexpected failures.

The core issue is that the helper function `load_multi_pack_index_one()` silently ignores ENOENT (file not found) errors, which is correct when checking for an optional standalone MIDX file but wrong when verifying required files in a MIDX chain. The patch adds a `missing_ok` parameter to control this behavior and updates all callers appropriately.

Key technical changes:
- Adds new parameter to control ENOENT handling
- Improves error message for fstat() from "failed to read" to "failed to learn the size of"
- Converts die() calls for signature/version mismatches to error() + goto cleanup
- Updates two call sites with appropriate missing_ok values (0 for chain files, true for standalone)

The patch is clean and focused, with a clear commit message explaining both the problem and solution. It touches only the MIDX loading logic and doesn't introduce any new concepts or dependencies. The changes are straightforward improvements to error handling that should make debugging MIDX issues easier while maintaining backward compatibility.
