This is a bugfix series targeting the HTTP authentication subsystem, specifically addressing an interaction between Kerberos (SPNEGO) authentication and the `http.emptyAuth=auto` configuration. The issue prevents automatic Kerberos ticket use when servers advertise Negotiate authentication alongside Basic.

The core problem stems from two older features conflicting: a 2015 change that strips Negotiate auth on first 401 response (to fall back to Basic), and a 2017 "auto" mode that should allow empty auth attempts for exotic methods like Kerberos. Currently the stripping happens too early, making `auto` mode behave like `false` for Negotiate-only servers.

The series restores the intended behavior by:
1. Refactoring retry path code into a helper function (pure refactor)
2. Delaying Negotiate stripping in auto mode to allow one empty auth attempt
3. Adding tests to verify the new behavior

The trade-off is one extra round-trip when no valid Kerberos ticket exists, matching the documented behavior of `auto` mode. The fix has already been adopted in Git for Windows 2.54.0-rc2.

The changes are well-contained to HTTP auth logic, with clear commit messages explaining both the problem and solution. The test additions in patch 3 provide good coverage of the new behavior. This appears to be a straightforward fix for a real-world authentication issue affecting Kerberos users.
