This is a documentation patch introducing a technical specification for the LMAP (Loose Object Map) binary format. The patch adds a new file, `Documentation/technical/loose-object-map.adoc`, which provides a detailed, bit-level description of the LMAP format used by the experimental Rust implementation (`loose.rs`) to map between different object ID formats (e.g., SHA-1 and SHA-256). The patch also updates the build system files (`Makefile` and `meson.build`) to include the new documentation.

The LMAP format is designed for efficient storage and lookup of object ID mappings, with a structured layout that includes a header, object format table, data sections, and a trailer. The specification defines how multi-byte integers are stored (big-endian), the purpose of each section (e.g., shortened indices for binary search, full OID tables, and metadata tables), and the alignment requirements. The commit message notes that this documentation was missing, making it difficult for C developers to understand the format's logic and layout.

This patch is purely additive and does not modify any existing code or behavior. It is well-motivated, as the lack of documentation for the LMAP format was a clear gap, and the specification itself appears thorough and precise. The patch is likely uncontroversial, as it only adds documentation for an existing experimental feature. Future discussion may focus on whether the format itself is sufficient or needs adjustments, but this patch does not propose any such changes.
