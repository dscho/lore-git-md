Patrick Steinhardt has proposed reorganizing Git's source tree by moving all libgit.a components into a new "lib/" directory, a significant change affecting ~700 files while preserving their internal structure. The RFC has received generally positive feedback, with Elijah Newren supporting the improved discoverability (though noting a minor concern about moving the sha1collisiondetection submodule) and brian m. carlson providing important technical input about Rust build requirements. Maintainer Junio C Hamano has signaled approval, citing concrete usability improvements for shell tab completion.

Phillip Wood's recent review adds thoughtful nuance to the discussion. While supporting the structural benefits of clearer library/non-library separation, he questions whether the change will actually improve code discoverability as claimed - developers will still rely on tools like `git grep` regardless of directory structure. His perspective as an experienced contributor provides a reality check on the proposal's human factors, though he raises no blocking technical concerns. The thread now has both broad conceptual approval and substantive technical review, suggesting the reorganization is likely to proceed with minor adjustments to address the various perspectives shared.
