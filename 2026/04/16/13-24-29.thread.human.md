Patrick Steinhardt’s RFC to reorganize Git’s source tree by moving core library files into a new `lib/` directory continues to spark debate over its trade-offs. The latest exchange refines the discussion but leaves the central tension unresolved: whether the long-term structural benefits outweigh the immediate disruption to workflows and ongoing work.

The thread began with Patrick arguing that the reorganization would reduce root-directory clutter (from ~550 to ~80 files) and establish a clearer boundary for Git’s core library code, despite one-time costs like disrupted `git log --follow` history and rebasing challenges. Opponents, including Junio C Hamano and Phillip Wood, countered that the change was cosmetic, risked merge conflicts for downstream forks, and introduced recurring friction—such as remembering file moves (e.g., `wt-status.c` → `lib/wt-status.c`). Phillip’s substantive review also dismantled the discoverability rationale, noting that the number of files remains the same, just nested under an extra directory.

In the latest reply, Patrick clarifies that the primary goal was never to make *library* files easier to find but to improve discoverability of *non-library* files in the root directory by reducing clutter. He concedes Phillip’s point about library files but doubles down on the structural benefit of grouping library code, arguing that the current layout—where library and non-library files are mixed—makes it harder to enforce coding conventions (e.g., avoiding `the_repository` or `die()` in library code). However, he offers no concrete solutions for the recurring workflow pain, leaving the debate’s core trade-off unresolved. Junio’s earlier suggestion of a documentation-based "map" of the codebase remains unaddressed, and the series is still a pure refactoring effort with no functional changes.

The discussion now hinges on whether the structural benefits—such as enforcing coding conventions and reducing root-directory clutter—justify the ongoing friction for contributors. Proponents (Patrick, Johannes Schindelin, Oswald Buddenhagen) see the change as a necessary cleanup, while skeptics (Junio, Phillip, Derrick Stolee) view it as a risky disruption during the prerelease freeze. The thread remains open, with no clear path toward consensus.
