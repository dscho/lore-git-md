Patrick Steinhardt’s RFC patch series (v3) to reorganize Git’s source tree by moving all `libgit.a` components into a new `lib/` directory is now in its third iteration, still framed as a **refactoring-only** effort to reduce root-directory clutter and establish a clearer boundary for Git’s core library code. The latest patch—the second in the series—focuses on the mechanical relocation of roughly 700 files (including core subsystems like object handling, refs, diff, merge, and platform compatibility shims) into `lib/`, while preserving their internal structure. The commit message explicitly acknowledges the downsides of this mass rename: disrupted `git log --follow` history, rebasing and backporting challenges for in-flight topics, and merge conflicts for downstream forks like GitHub and Microsoft Git. Patrick positions these as one-time costs justified by long-term improvements in code discoverability and onboarding, and suggests the change could even drive tooling improvements (e.g., better rename tracking in Git). Johannes Schindelin’s Windows CI fix (adjusting `.github/workflows/main.yml` to reference `lib/compat`) is now incorporated, resolving the Visual Studio build regression from v2.

The discussion remains polarized. Proponents—Patrick, Oswald Buddenhagen, and Johannes Schindelin—argue the reorganization improves discoverability and could spur tooling improvements, while opponents—Junio C Hamano, SZEDER Gábor, and Derrick Stolee—emphasize the disruption to ongoing work, backporting, and historical tracking. Junio’s skepticism persists despite the explicit trade-off framing in v3, and SZEDER’s objection about `git log --follow` is now countered by Patrick’s argument that the change could incentivize tooling improvements. The series itself is technically straightforward: it updates build system files (`Makefile`, `meson.build`, `CMakeLists.txt`, `config.mak.uname`) and CI workflows to reference the new `lib/` directory, with no changes to symbols, APIs, or on-disk formats. Open questions include whether the tooling-incentive argument gains traction, how to mitigate rebasing and backporting pain for downstream consumers, and whether the logistical disruption outweighs the structural benefits—particularly during the prerelease freeze.
