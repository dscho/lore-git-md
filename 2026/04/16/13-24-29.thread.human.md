Patrick Steinhardt’s RFC patch series (v2) to reorganize Git’s source tree by moving all `libgit.a` components into a new `lib/` directory is nearing completion, with all technical feedback addressed. The latest update confirms that Johannes Schindelin’s one-line fix for a Windows CI regression—adding `path: lib/compat` to the GitHub Actions workflow—has been integrated by Junio C Hamano. This resolves the last known platform-specific issue, leaving no outstanding technical objections.

The series remains a two-patch effort: the first ensures build integrity for a test helper, while the second relocates ~700 files into `lib/` without introducing functional changes. The reorganization aims to reduce root directory clutter (from ~550 to ~80 files) and establish a clearer boundary for `libgit.a`, but Junio remains skeptical about its practical benefits, particularly during the prerelease freeze. He highlights the disruption to in-flight patches and backporting as key concerns, though he hasn’t rejected the idea outright. Patrick counters that Git’s poor handling of file moves is itself a usability issue, arguing the pain of this change could drive tooling improvements (e.g., better `git diff`/`rebase` support for moves).

The debate now centers on timing and logistics. Oswald Buddenhagen supports merging the change before Git 2.55, noting it’s a low-risk build system tweak, but this won’t ease rebasing challenges for long-lived forks (e.g., GitHub’s). Downstream consumers should watch whether the tooling argument gains traction or if the focus stays on minimizing disruption. The series is technically ready, but the broader discussion about trade-offs continues.
