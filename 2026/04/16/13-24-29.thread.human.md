Here's a human-readable summary of the thread so far:

Patrick Stehinardt has proposed a significant reorganization of Git's source tree through an RFC patch series. The goal is to move nearly 700 files that make up libgit.a components from the root directory into a new "lib/" subdirectory. This would leave only about 80 files in the root, dramatically improving code discoverability while maintaining all internal file relationships.

The second patch provides the actual implementation, showing thorough updates across all build systems (Make, CMake, Meson), CI workflows, and documentation. Core subsystems like object handling, refs, diff, and merge would move while keeping their internal structures intact. Patrick has clearly put substantial effort into ensuring the mechanical aspects work correctly, though he's marked this as an RFC to gather community feedback before proceeding.

The timing suggests Patrick would like to land this early in the next release cycle if accepted, allowing maximum time to address any issues. While the implementation appears technically sound, the proposal acknowledges this would be a major structural change affecting all build configurations and downstream consumers. The discussion is just beginning, with no clear consensus yet formed on whether to proceed with this reorganization.
