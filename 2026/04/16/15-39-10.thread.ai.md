Thread identity: Bug report about `git checkout-index` and `git archive` failing to properly extract files when given tree objects directly, submitted by Runxi Yu.

Core problem: When working with tree objects (not commits), `git checkout-index -a` and `git archive` fail to extract files despite the tree containing valid file entries. This contradicts expectations set by `git cat-file -p` showing the tree contents and `checkout-index` documentation stating `-a` should check out "all files in the index".

Key technical details:
- Reproducible with both SHA-1 and SHA-256 repositories
- `git checkout <tree>` fails with "Cannot switch branch to a non-commit"
- `git archive <tree>` produces empty tarballs
- `git read-tree <tree>` populates index (verified via `xxd`), but subsequent `checkout-index -a` still extracts nothing
- Tested with tree hash 43aa0d7... containing multiple files

Current status: Bug report freshly submitted, no responses yet. Author requests replies be CC'd as they are not on mailing list.

Open questions:
- Is this intentional behavior (limiting to current directory) that needs documentation?
- Should there be a proper way to check out trees directly?
- Why does `checkout-index -a` ignore index entries populated by `read-tree`?

Participant positions: Only Runxi Yu so far, with thorough investigation showing the inconsistency between object contents and command behavior.
