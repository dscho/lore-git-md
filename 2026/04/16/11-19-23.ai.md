This is part 6 of Patrick Steinhardt's 12-patch series to enable `set -e` in Git's test suite (Bash 5+ only), focusing on test infrastructure modernization. The patch updates test patterns that would fail under `set -e` by converting direct command execution followed by exit code checks into proper conditional statements.

The changes are mechanical but important for reliability, touching 11 files across the test suite. Key updates include:
- Converting `command && test_expect_success` patterns to `if` statements in various test scripts (t4032, t7450)
- Fixing command execution patterns in t/lib-git-svn.sh, t/lib-httpd.sh, and several CVS-related tests to properly handle failures under `set -e`
- Updating test-lib.sh and test-lib-functions.sh helpers to capture exit codes safely
- Adding explicit error handling for git-cvsserver and submodule tests

The patch follows the series' consistent approach of making minimal, backward-compatible changes to prepare for `set -e` while maintaining existing behavior. It continues the careful progression through test components, with each change narrowly scoped and explained. The work builds on previous patches addressing signal handling, test_must_fail behavior, and daemon management, now tackling command execution patterns that would silently fail under stricter error checking.
