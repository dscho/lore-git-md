This thread addresses a bug in Git's HTTP authentication where Kerberos (SPNEGO) fails when using `http.emptyAuth=auto`. The issue stems from a conflict between a 2015 change that strips Negotiate auth on the first 401 response and the 2017 "auto" mode that should allow empty auth for Kerberos. The complete solution involves three technical changes and a documentation update, all now reviewed and ready for merging.

The series refactors the HTTP retry path, modifies Negotiate stripping behavior via a new flag, adds comprehensive test coverage, and documents the `http.emptyAuth` configuration options. Junio has acked the technical approach, and the fix is already incorporated into Git for Windows 2.54.0-rc2. The latest patch adds two test cases verifying the interaction between `http.emptyAuth` and Negotiate authentication, using curl tracing to confirm the expected authentication flow. With this addition, the series now has complete test coverage for the Negotiate auth edge case that motivated the changes. All patches have received positive review and are ready for merging with no outstanding questions.
