This is a bugfix series addressing an interaction between HTTP authentication features, specifically targeting the `http.emptyAuth=auto` mode when Kerberos/Negotiate authentication is involved.

The core issue stems from two older features conflicting: a 2015 change that strips Negotiate auth on first failure (to fall back to Basic), and a 2017 "auto" mode that's supposed to try system credentials first. Currently the stripping happens too early, preventing the auto mode from working with Kerberos unless manually overridden.

The series restructures the authentication flow to:
1. First refactor the retry paths into a helper function (patch 1)
2. Modify the logic to delay Negotiate stripping in auto mode (patch 2)
3. Add tests verifying the new behavior (patch 3)

The change comes with a documented trade-off: when no valid Kerberos ticket exists, there will be one extra round-trip compared to the current behavior. The patch has already been picked up by Git for Windows in their 2.54.0-rc2 release, suggesting it's seen as a real-world improvement for Windows users relying on Kerberos authentication.
