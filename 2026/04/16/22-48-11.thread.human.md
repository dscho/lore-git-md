This series from Elijah Newren optimizes `git cherry` and `git grep` for partial clones, where commands that fetch blobs one-by-one can take 3+ seconds per fetch because partial clones defer downloads. The series adds batch prefetching (already used by checkout, diff, and merge) to these commands.

The v3 series was merged to `next` with three patches: `git cherry` prefetch via `prefetch_cherry_blobs()` and a hashmap swap, `git grep` prefetch via tree walkers that collect blob OIDs, and documentation/test fixes. The series touches `builtin/cherry.c`, `builtin/grep.c`, and `builtin/log.c`, using `oidset` and `promisor_remote_get_direct()`.

In his latest reply, Elijah responds to Derrick Stolee's earlier review. He confirms Stolee's pathspec-filtering test suggestion is sound and that the code already handles it correctly. More importantly, Elijah reveals he independently found and fixed a real efficiency bug during testing: the prefetch was unconditionally requesting downloads of all matching blobs, even ones already present locally. Fixing this unnecessary re-download should improve performance meaningfully.

The maintainer set the topic to "Expecting a re-roll" for the pathspec test addition. Elijah's reply makes clear the next iteration will include both that test and the redundant-prefetch fix. Broader architectural questions about whether to centralize the prefetch mechanism (in `diff.c` or elsewhere) remain deferred, as does the longer-term goal of extending this optimization to `git rebase` -- which faces additional barriers from apply-backend limitations and missing configuration options.
