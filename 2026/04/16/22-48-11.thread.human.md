This thread explores performance optimizations for partial clone operations, specifically targeting `git cherry` and `git grep` commands. Elijah Newren has completed a series that implements batch prefetching for these commands, following established patterns used in checkout/diff/merge operations. The implementation handles edge cases like root/merge commits and binary files while maintaining exact patch ID computation. Junio Hamano has approved the series for merging after removal of a design document.

Phillip Wood raised an important consideration about generalizing the cherry-pick prefetch logic to `revision.c` for broader use in commands like `git rebase`. While Elijah agrees this is technically feasible, he questions its practical value given alternative workflows in large repositories. In a follow-up, Phillip notes two specific pain points: the lack of path-based filtering in rebase's patch ID computation and the absence of a config setting for `--reapply-cherry-picks`. He finds it surprising that more users haven't complained about these performance bottlenecks.

The discussion remains constructive, with all parties technically aligned but differing on implementation priorities. The current series stands ready for merging as-is, providing immediate benefits to `git cherry` and `git grep` users, while leaving the broader architectural question of generalization open for future consideration by other contributors.
