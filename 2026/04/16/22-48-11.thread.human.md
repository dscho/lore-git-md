Elijah Newren has sent a detailed technical reply to Derrick Stolee's earlier architectural suggestion about centralizing batch-prefetch logic in `diff.c`. Elijah politely but firmly explains why the prefetch code for `git cherry` has two cherry-specific constraints that wouldn't generalize: it skips commits whose file list doesn't match, and it avoids binary files because patch-ID hashes use OID strings directly. He also notes the per-commit accumulation is fundamentally different from the existing pattern in `diffcore_std()`. He's open to extracting a shared helper if a second caller like `git archive` appears, but not before. Stolee's review of patches 2 and 3 was broader than the patch header suggested, which Elijah acknowledges. The architectural question remains an open, friendly technical disagreement, not a blocker. The re-roll remains on track for the two accepted fixups: a pathspec filtering test and Elijah's own fix for redundant re-downloads of already-local blobs.
