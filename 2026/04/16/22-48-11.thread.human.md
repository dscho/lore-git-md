Elijah Newren has completed a performance optimization series that improves partial clone behavior for `git cherry` and `git grep`. The changes address a key pain point where these commands would trigger hundreds of individual slow blob downloads. 

The solution introduces batch prefetching - already used in checkout/diff/merge - to these commands. For `git cherry`, it implements blob collection during patch ID computation with special handling for merge commits and binary files. The `git grep` patch adds tree walking to gather blob OIDs before searching, carefully excluding submodules which have separate fetch logic. Both use the promisor-remote interface for efficient batch fetching.

Junio Hamano reviewed the series and requested only one change - removing a standalone design document in favor of incorporating the details into commit messages. Elijah addressed this along with fixing a minor documentation syntax error. The implementations are cleanly contained to the relevant builtin commands with new tests verifying the optimizations. 

With all feedback incorporated and no outstanding issues, this series is now ready to merge. It will provide measurable performance gains for users working with partial clones, completing the extension of batch prefetching to these previously problematic commands. The changes follow established patterns while carefully maintaining existing behavior where needed.
