This is patch 6/8 in Johannes Schindelin's security-focused series changing the default bare repository access behavior when Git is built with WITH_BREAKING_CHANGES. The patch addresses test fallout from writing the global `safe.bareRepository=all` setting to `$HOME/.gitconfig` during tests.

The core issue is that `git ls-files --others` without `--exclude-standard` doesn't respect `.git/info/exclude`, causing the `.gitconfig` file to appear in test output where it shouldn't. The patch introduces a `test_filter_gitconfig` helper function to strip these entries from test output and applies it to several test files (t3000, t3001, t3002, t3009, t3011). For t7104 which already uses `--exclude-standard`, it simply makes that explicit.

The change demonstrates careful attention to test behavior while maintaining the security goals of the overall series. The approach preserves test intent while working around the global config side effects, with clear documentation of why each adjustment is needed. This continues the series' pattern of methodically addressing test interactions before implementing the core behavior change in patch 8/8.
