Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This third version of the patch refines the implementation to address concerns about remote-tracking branch stability by narrowing fetches to only the requested branch when possible. Key changes from v2 include:
- Explicitly fetches only the specific branch when given `<remote>/<branch>` form (previously fetched entire remote)
- Added test verifying other remote-tracking branches remain unchanged
- Improved documentation clarity around fetch scope
- Maintained all prior test coverage and config support

The patch remains well-constructed with thorough tests demonstrating:
- Basic remote branch fetching
- Bare remote name handling (fetches default branch)
- Single-branch fetch isolation
- Failure cases
- Config-driven behavior
- `git switch` compatibility

While the technical implementation has improved, the fundamental philosophical disagreement noted in previous reviews remains unresolved - whether automatic fetching belongs in Git's workflow model. The maintainer's vacation status is noted, with discussion likely to resume upon return. This version makes the implementation more precise but doesn't yet address the higher-level design concerns previously raised.
