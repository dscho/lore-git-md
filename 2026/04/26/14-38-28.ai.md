This is a security-focused cover letter for a patch series from Johannes Schindelin that changes the default behavior of `safe.bareRepository` to "explicit" when Git is built with `WITH_BREAKING_CHANGES`. The series represents version 2 of the effort, incorporating feedback from Junio Hamano to modify the test infrastructure rather than individual tests.

The key change makes Git require explicit permission to access bare repositories when built with breaking changes enabled, addressing a security vector where Git could inadvertently operate on bare repos in untrusted directories. The series takes a careful approach to test compatibility by globally setting `safe.bareRepository=all` in the test environment when `WITH_BREAKING_CHANGES` is enabled.

The 8-patch series includes:
1. Core test infrastructure change to allow bare repo access in tests
2-7. Various test fixes to handle side effects of writing to `$HOME/.gitconfig`
8. The actual behavior change making "explicit" the default when `WITH_BREAKING_CHANGES` is set

Notable changes since v1 include making the series compatible with Patrick Steinhardt's `set -e` work by being more careful about when to create `.git/info/exclude`. The changes span multiple test areas demonstrating the wide impact of this security change, with particular attention to edge cases involving global state and config file visibility in test output.

The approach shows thoughtful consideration of both security goals and practical test maintenance, positioning this as a breaking change for a future major version while maintaining current behavior in standard builds. The documentation updates in `BreakingChanges.adoc` explain the new default behavior and its security rationale.
