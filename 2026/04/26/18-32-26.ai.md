Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This is the fourth version of the patch, now addressing the test coverage gap for `--no-fetch` override behavior that Ramsay Jones identified in his review of v3. The new tests verify that:
- `--no-fetch` correctly overrides a `checkout.fetch=true` config setting
- `--no-fetch` overrides an earlier `--fetch` on the same command line

The core functionality remains unchanged from v3 - when `--fetch` is given and the start point is a remote-tracking branch, Git will fetch just that branch to update it before creating the new branch. For bare remote names (like "origin"), it performs a full remote fetch. The implementation continues to demonstrate careful attention to edge cases and thorough test coverage.

While the technical implementation appears solid with these latest test additions, the fundamental philosophical disagreement about whether this behavior belongs in Git's workflow model remains unresolved. The maintainer's prior objections about remote-tracking branch invariants and workflow implications have not been directly addressed, and the thread remains paused during the maintainer's vacation. The patch shows responsiveness to technical feedback but still awaits resolution of the higher-level design questions.
