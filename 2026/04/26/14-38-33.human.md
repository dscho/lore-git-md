This is a test fix patch in Johannes Schindelin's security-focused series changing default bare repository access behavior. It's part of an 8-patch set that makes `safe.bareRepository` default to "explicit" when Git is built with `WITH_BREAKING_CHANGES` enabled.

The patch fixes a specific test in t5601-clone.sh that was interfering with the test infrastructure's global configuration. The test overwrites `$HOME/.gitconfig` for an `includeIf` test but wasn't properly preserving the `safe.bareRepository=all` setting that the test infrastructure adds when `WITH_BREAKING_CHANGES` is active. This caused subsequent tests to fail when trying to access bare repositories.

The solution is straightforward: the patch adds code to back up `.gitconfig` before the test modifies it and restore it afterward. This maintains the test's original purpose while ensuring the security-related global configuration persists for later tests. The change shows careful attention to test isolation while accommodating the broader security hardening effort.

This is part of the middle section of the series (patch 5/8) that handles various test fallout from the security changes.
