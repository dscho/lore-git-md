Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This is the third version of a patch that aims to simplify the workflow of creating branches from remote-tracking refs by automatically updating them first. The key changes from v2 include:
- Clarified that `--fetch` performs a single-branch fetch when given a `<remote>/<branch>` start point (addressing concerns about remote-tracking branch stability)
- Added a test verifying other remote-tracking branches remain untouched when fetching a specific branch
- Improved documentation wording to be more precise about the fetch behavior
- Maintained all other functionality from v2 including config support and `git switch` integration

The implementation now explicitly fetches only the requested ref when given in remote/branch form, while still doing a full remote fetch for bare remote names. This addresses the core technical concern raised in the thread about preserving remote-tracking branch stability. The test suite has been expanded to verify this behavior.

While the technical implementation appears solid, the fundamental philosophical disagreement about whether this behavior belongs in Git's workflow model remains unresolved. The maintainer's prior objections about remote-tracking branch invariants and workflow implications have not been directly addressed in this revision. The thread remains paused during the maintainer's vacation.

The patch continues to show careful attention to detail with thorough test coverage and clear documentation. However, its ultimate acceptance likely hinges on resolving the higher-level design questions about remote ref handling consistency rather than technical implementation details.
