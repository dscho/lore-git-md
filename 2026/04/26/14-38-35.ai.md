This is patch 7/8 in Johannes Schindelin's security-focused series changing the `safe.bareRepository` default behavior when built with `WITH_BREAKING_CHANGES`. The patch addresses test fallout in status-related tests where the test infrastructure's creation of `$HOME/.gitconfig` causes unexpected output in `git status` results.

The patch introduces a `test_filter_gitconfig` helper to strip `.gitconfig` entries from status output in affected tests (t7061 and t7521), while making targeted adjustments in other status tests (t7060, t7064, t7508). The changes ensure test expectations remain valid despite the global config file appearing as either untracked or ignored in status output.

This continues the series' careful approach to maintaining test compatibility while preparing for the security change that will make bare repository access require explicit permission. The patch demonstrates the wide impact of the security change, requiring adjustments across multiple test scripts to handle the side effects of writing to `$HOME/.gitconfig`.

The changes are mechanical but necessary to keep tests passing when the breaking changes flag is enabled, showing the thoroughness of the series in addressing edge cases. The patch maintains the series' focus on both security goals and practical test maintenance.
