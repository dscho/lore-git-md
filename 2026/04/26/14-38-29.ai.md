Security patch modifying test infrastructure for upcoming bare repository access changes. This is the first of an 8-part series from Johannes Schindelin that prepares the test suite for a future security hardening change - making `safe.bareRepository` default to "explicit" when Git is built with `WITH_BREAKING_CHANGES` enabled.

The patch globally configures `safe.bareRepository=all` in the test environment when breaking changes are enabled, ensuring existing tests continue working even after the default behavior becomes more restrictive. It carefully writes to `.git/info/exclude` to hide the test's global config changes from `ls-files` output, with special handling for tests that create their own `.git/info` directory and tests that don't create repositories at all.

The approach follows Junio Hamano's suggestion to modify test infrastructure rather than individual tests, and shows awareness of integration concerns with Patrick Steinhardt's `set -e` work. The patch demonstrates thoughtful consideration of edge cases in test behavior while maintaining the security goal of eventually requiring explicit permission to access bare repositories. Subsequent patches in the series will address specific test fallout from this change.
