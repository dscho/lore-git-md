Security patch changing default bare repository access behavior when built with WITH_BREAKING_CHANGES. This final patch in the 8-part series implements the core behavior change, making `safe.bareRepository` default to "explicit" in such builds to prevent automatic discovery of potentially malicious bare repositories.

The change addresses a security vulnerability where attackers could trick users into cloning repositories containing embedded bare repos with malicious hooks. The new default requires explicit specification via `--git-dir` or `GIT_DIR` for bare repo access, while maintaining compatibility with `.git` directories, worktrees and submodules. Users can revert to the old behavior by setting `safe.bareRepository=all` globally.

The patch updates documentation in BreakingChanges.adoc and config/safe.adoc to explain the security rationale and migration path. Test changes include:
- Handling the new default behavior in t0035-safe-bare-repository.sh
- Switching from `test_config -C` to direct config file access to avoid discovery issues during cleanup
- Adding a WITH_BREAKING_CHANGES-specific test case

This represents the culmination of a carefully staged series that first prepared the test infrastructure (patches 1-7) before implementing the behavior change. The approach demonstrates thorough consideration of both security impact and backward compatibility, with clear documentation of the breaking change for Git 3.0.
