This is a test infrastructure patch in Johannes Schindelin's security-focused series changing default bare repository access behavior. The patch addresses an edge case where the test suite's global `safe.bareRepository=all` setting (written to `$HOME/.gitconfig`) appears in `git ls-files --others` output since that command doesn't respect `.git/info/exclude`.

The solution introduces a `test_filter_gitconfig` helper to strip `.gitconfig` entries from test output, applying it to several `ls-files` tests that deliberately avoid `--exclude-standard`. For `t7104-reset-hard.sh`, which already uses `--exclude-standard`, the patch simply makes that explicit. The approach maintains test correctness while accommodating the security changes' side effects.

This is patch 6/8 in the series, continuing the careful preparation of test infrastructure before the actual behavior change in patch 8. The changes demonstrate the wide impact of modifying global config defaults, even in test scenarios designed to examine unfiltered output.
