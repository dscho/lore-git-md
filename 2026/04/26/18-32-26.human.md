Feature patch adding `--fetch` to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This is the fourth version of a patch that aims to simplify the common workflow of creating branches from remote-tracking refs by automatically fetching them first. The key addition in v4 is test coverage for the `--no-fetch` override case, addressing a gap identified in Ramsay Jones' review of v3.

The implementation remains focused on:
- Adding `--fetch`/`--no-fetch` flags to both commands
- Supporting config option `checkout.fetch` to enable by default
- Performing targeted single-branch fetches when given `<remote>/<branch>` form
- Falling back to full remote fetch for bare remote names
- Aborting checkout if fetch fails

The new tests verify that `--no-fetch` can override both the config setting and an earlier `--fetch` on the command line. This completes the test coverage while maintaining all the technical refinements from v3 that addressed remote-tracking branch stability concerns.

While the technical implementation appears solid, the fundamental philosophical disagreement about whether this behavior belongs in Git's workflow model remains unresolved. The maintainer's prior objections about remote-tracking branch invariants and workflow implications have not been directly addressed, and the thread remains paused during the maintainer's vacation.

The patch continues to demonstrate careful attention to detail with thorough test coverage and clear documentation. However, its ultimate acceptance likely hinges on resolving the higher-level design questions about remote ref handling consistency rather than technical implementation details.
