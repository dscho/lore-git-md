This is patch 7/8 in Johannes Schindelin's security-focused series changing the default behavior of `safe.bareRepository` when built with `WITH_BREAKING_CHANGES`. The patch addresses test fallout from the global `.gitconfig` file that appears in `git status` output when the breaking changes flag is enabled.

The core issue is that the test infrastructure creates `$HOME/.gitconfig` when `WITH_BREAKING_CHANGES` is set, causing it to show up in status output as either untracked or ignored. This patch introduces a `test_filter_gitconfig` helper to strip these entries from test output before comparison, applying it to affected tests in t7061 and t7521. For other tests (t7060, t7064, t7508), it makes targeted adjustments like adding `.gitconfig` to `.git/info/exclude`.

The changes are mechanical but necessary to maintain test reliability as part of the larger security hardening effort. This continues the series' careful approach of preparing the test suite before making the actual behavior change in patch 8. The patch shows good attention to detail in handling different status output formats and edge cases across multiple test scripts.
