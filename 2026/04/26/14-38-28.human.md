This is a security-focused patch series from Johannes Schindelin (Git for Windows maintainer) that changes the default behavior of `safe.bareRepository` to "explicit" when Git is built with `WITH_BREAKING_CHANGES`. The change requires explicit permission to access bare repositories as a security hardening measure.

The v2 series takes a different approach from v1 based on Junio Hamano's suggestion - rather than modifying individual tests, it sets `safe.bareRepository=all` in the test environment's global config when `WITH_BREAKING_CHANGES` is enabled. This maintains test compatibility while allowing the security change to proceed.

The 8-patch series includes:
1. Core test infrastructure change to allow bare repo access in tests
2-7. Various test fixes to handle side effects of writing to `$HOME/.gitconfig`
8. The actual behavior change making "explicit" the default when `WITH_BREAKING_CHANGES` is set

Key changes in v2 include making the series compatible with Patrick Steinhardt's `set -e` work by being more careful about when to write to `.git/info/exclude`. The changes span multiple test areas showing the wide impact of this security change, with particular attention to edge cases involving global state and config file visibility in test output.

This appears to be a well-considered approach to introducing a security-hardening change while minimizing test suite disruption, positioned as a breaking change for a future major version using `WITH_BREAKING_CHANGES` as a staging mechanism. The documentation updates in `BreakingChanges.adoc` explain both the new default behavior and its security rationale.
