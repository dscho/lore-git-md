Documentation bug report for `git check-ignore`'s inconsistent behavior between -z/--stdin flags.

David Le reports that `git check-ignore -z` fails with "fatal: -z only makes sense with --stdin" despite the documentation suggesting -z should work independently. The man page currently states "-z modifies output format" with an additional note about --stdin behavior, implying these are separate concerns.

This appears to be a straightforward documentation mismatch where either the implementation should be updated to match the docs (allowing -z standalone) or the docs should be corrected to reflect the current behavior (requiring --stdin with -z). The bug report includes clear reproduction steps and version information showing this occurs in Git 2.54.0.

The issue seems minor but worth addressing for consistency - either making the behavior match the documentation or vice versa would resolve the confusion. No patch is provided in this initial report, just clear identification of the discrepancy.
