This is a documentation bug report for `git check-ignore`'s behavior with the `-z` option. The issue stems from a mismatch between the command's actual behavior and its documentation.

The reporter, David Le, found that `git check-ignore -z` fails with "fatal: -z only makes sense with --stdin" when used with path arguments, while the documentation suggests `-z` can work independently of `--stdin`. The help text currently implies `-z` modifies output format generally, with an additional effect on input parsing when combined with `--stdin`.

The bug appears straightforward - either the implementation should be changed to match the documentation (allowing `-z` without `--stdin`), or more likely, the documentation should be corrected to accurately reflect that `-z` requires `--stdin`. The reporter notes this is a minor issue but one that could confuse users trying to parse `check-ignore` output programmatically.

The email includes full system information showing this was tested with Git 2.54.0 on an Arch Linux system. No patch is provided - this is purely a bug report that would need follow-up from a documentation maintainer or someone familiar with the `check-ignore` command.
