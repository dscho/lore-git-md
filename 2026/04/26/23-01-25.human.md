This is a continuation of the discussion about fixing the regression in Git's alias handling where hierarchical aliases (like `pull.sub`) stopped working in Git 2.54.0. Jeff King (Peff) responds to Jonatan Holmgren's concerns about the two competing approaches to fix the issue.

Peff agrees with Holmgren's preference for the simpler "reserved prefixes" approach over the more complex "dual interpretation" method, acknowledging it provides clearer semantics. He suggests treating dotted aliases as a historical feature that could eventually be phased out, but without an active deprecation timeline. Peff notes this would need to wait until either (1) pre-2.54 Git versions are considered ancient, or (2) a major version like Git 3.0 that accepts breaking changes.

The email also raises the question of whether simple non-dotted aliases (`alias.foo`) might eventually be deprecated, though Peff sees little reason to do so given their minimal maintenance cost. This exchange shows the discussion converging toward Holmgren's simpler solution while acknowledging the need to maintain backward compatibility for existing workflows.
