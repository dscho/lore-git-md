This is a refactoring patch in Taylor Blau's 16-part series implementing incremental MIDX/bitmap-based repacking for large repositories. The series is now in its final form with all technical concerns addressed and ready for maintainer integration.

This particular patch (2/16) replaces a hand-rolled array of MIDX filenames with a `strset` data structure for cleaner code and slightly better lookup performance when pruning stale MIDX files. The change:

1. Simplifies the `clear_midx_data` struct by replacing `keep` array and `keep_nr` count with a single `strset`
2. Updates both `clear_midx_files_ext()` and `clear_incremental_midx_files_ext()` to use the new structure
3. Adds proper string buffer cleanup via `strbuf_release()`

While the performance impact is negligible (as noted in the commit message), the change makes the code more maintainable by using Git's standard string set abstraction rather than manual array management. This is a typical preparatory refactoring in a larger series - cleaning up infrastructure to support the more substantial changes coming in later patches.

The patch has already been reviewed as part of the complete series, with Jeff King (Peff) verifying the safety aspects and Elijah Newren confirming the object storage implications. No further discussion is expected on this standalone change.
