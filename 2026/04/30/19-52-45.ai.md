This is a feature patch implementing `--max-count-oldest` for revision walks, representing a significant pivot from the previous `--reverse=before` approach based on maintainer feedback. The patch comes from Mirko Faina in response to Junio C Hamano's strong preference for Johannes Sixt's suggested interface design that frames the feature as a limiting operation rather than a reversal timing control.

The key changes in v5:
1. Completely replaces the `--reverse=before` implementation with `--max-count-oldest` as the primary interface
2. Maintains the same underlying functionality (showing oldest commits) but with different command-line semantics
3. Adds mutual exclusion checks with `--max-count` and `--skip` options
4. Preserves the optimized sliding window implementation (now in `retrieve_oldest_commits()`) from previous versions
5. Includes new test cases demonstrating basic and reversed output behavior

The implementation introduces a new `max_count_type` flag in `struct rev_info` to track whether we're using the traditional `--max-count` or new `--max-count-oldest` behavior, along with a `max_count_stage` flag to manage the two-phase commit collection process. The core algorithm remains similar to v4's optimization, using two queues to maintain the K most recent commits in O(K) space.

Notable technical points:
- The patch touches critical revision walking code in `revision.c`
- Maintains backward compatibility with existing `--reverse` behavior
- Adds comprehensive error checking for invalid option combinations
- Includes tests verifying both direct and reversed output modes

This represents a major interface redesign while preserving the technical solution developed through four previous iterations. The change addresses Junio's concern that the original `--reverse=before` framing was conceptually misaligned with user expectations about limiting behavior.
