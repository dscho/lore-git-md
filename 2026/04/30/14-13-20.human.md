This is a review comment on Johannes Schindelin's patch series addressing Windows platform limitations with large objects (>4GB). The series fixes truncation issue caused by 32-bit types on Windows, with this first patch specifically targeting index-pack and unpack-objects.

Torsten Bögershausen notes that the patch looks good and mentions a related GitHub pull request (#2179) that will likely become obsolete once this series is merged. The review is brief and surface-level, simply acknowledging the progress without any technical feedback or suggestions.

The patch itself (which was summarized in the parent email) converts object size handling from `unsigned long` to `size_t` to properly handle objects larger than 4GB on Windows. The change is mechanical but important for correctness when working with large repositories. The series has already received substantive reviews from Derrick Stolee on later patches regarding test execution time concerns.
