This is the second patch in a bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch modifies the Negotiate stripping behavior to properly support empty auth attempts in auto mode.

The core change introduces an `empty_auth_try_negotiate` flag that delays stripping the Negotiate auth method on the first 401 response when in auto mode. This allows the empty auth mechanism to detect and attempt Negotiate authentication using the system's Kerberos ticket cache. If that attempt fails (no valid ticket), Negotiate is stripped on the second 401 and the code falls back to credential filling as usual.

The patch also teaches `http_reauth_prepare()` to skip credential filling when an empty auth attempt is about to be made, ensuring the empty auth mechanism isn't bypassed. The changes are well-contained to HTTP auth logic in `http.c` and maintain backward compatibility of the `true` and `false` modes.

This builds on the refactoring from patch 1/3 (which extracted retry path code into `http_reauth_prepare()`) and will be followed by test coverage in patch 3/3 and documentation updates in patch 4/4. The approach has already been acked by Junio and incorporated into Git for Windows 2.54.0-rc2.
