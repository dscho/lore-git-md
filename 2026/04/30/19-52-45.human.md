This is a feature patch that pivots from the previous `--reverse=before` approach to implement Junio C Hamano's suggested `--max-count-oldest` interface for revision walks. The patch provides a more intuitive way to show the oldest N commits without requiring `--skip`.

The key changes in v5:
- Completely reworked to introduce `--max-count-oldest` instead of `--reverse=before`
- Maintains the same sliding window optimization (O(K) space) from previous versions
- Adds mutual exclusion checks with `--max-count` and `--skip`
- Includes tests showing the new option works with both forward and reversed output

The implementation uses a new `max_count_type` flag in `struct rev_info` to track whether we're doing normal or "oldest" limiting, plus a `max_count_stage` to manage the two-phase commit collection process. The core logic in `retrieve_oldest_commits()` efficiently maintains the sliding window of commits.

This version addresses Junio's interface concerns while preserving the technical benefits of the earlier approach. The patch appears ready for final review, having incorporated all substantive feedback through five iterations. The main files touched are `revision.[ch]` for the core logic and `t/t4202-log.sh` for the new test cases.
