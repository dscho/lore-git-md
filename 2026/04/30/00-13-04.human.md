This is the final version of Taylor Blau's feature patch series implementing incremental MIDX/bitmap-based repacking for large repositories. The series introduces a new repacking strategy that maintains an incrementally growing and shrinking MIDX chain, avoiding periodic all-into-one repacks.

The key changes in this version are:
1. Fixed stale references to "--checksum-only" in commit messages
2. Replaced custom pipe handling with `pipe_command()` to eliminate deadlock potential
3. Added proper cleanup in error paths for `write_midx_included_packs()`
4. Moved an errant test to its correct location in the series

The implementation provides two operational modes:
- Geometric mode (recommended) creates a layered structure with older layers containing fewer, larger packs
- Append-only mode preserves all prior layers unchanged when geometric repacking isn't needed

The series has received thorough review from both object storage (Elijah Newren) and process management (Jeff King/Peff) experts, with all technical and documentation concerns addressed. It's now ready for maintainer integration with no outstanding items.

This completes a multi-year effort to improve Git's scalability for large repositories, building on previous work that refactored repack.c and implemented MIDX layer compaction. The incremental MIDX repacking strategy represents a major architectural improvement for large monorepos that repack frequently.
