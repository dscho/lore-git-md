This is the third patch in a bugfix series addressing HTTP authentication behavior with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch adds test coverage to verify the fixed behavior.

The tests specifically check that:
- With `http.emptyAuth=auto`, Git properly attempts Negotiate authentication first (resulting in two 401 responses) before falling back to Basic auth credentials
- With `http.emptyAuth=false`, Git immediately strips the Negotiate header and only gets one 401 response before using Basic auth

The test setup uses a custom HTTP server configuration to simulate a server that advertises both Negotiate and Basic authentication. The tests verify the expected behavior by counting 401 responses in curl traces and checking credential helper interactions.

This patch completes the technical implementation from the previous patches in the series, which refactored the HTTP auth retry logic and fixed the Negotiate stripping behavior. The tests demonstrate the fix works as intended for both auto and false modes of `http.emptyAuth`.

The patch follows Git's standard test patterns and includes clear explanations of what each test case verifies. With this test coverage added, the series appears ready for merging as it now has both the code changes and verification of the fixed behavior.
