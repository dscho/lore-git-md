This is patch 14/16 in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking for large repositories. The series introduces a new repacking strategy that maintains an incrementally growing and shrinking MIDX chain to avoid periodic all-into-one repacks.

The patch implements the core `write_midx_incremental()` function which builds and maintains the incremental chain during geometric repacking. Key aspects:

- Uses a lockfile to safely update the multi-pack-index-chain file
- Constructs a compaction plan determining which MIDX layers to write, compact, or copy
- Executes each step using `git multi-pack-index` subcommands with `--no-write-chain-file`
- Follows a merging condition where adjacent layers are combined if the accumulated object count exceeds half the next deeper layer's count (controlled by `repack.midxSplitFactor`)
- Atomically moves the new chain into place after all steps complete

The implementation handles several cases:
- Always writes a new layer containing fresh packs and optionally surviving packs from rewritten layers
- Compacts adjacent layers when the merging condition is met
- Preserves unmodified layers when compaction would violate the condition
- Maintains preferred pack selection across compaction steps

The patch includes extensive trace2 instrumentation for debugging and performance analysis. It builds on previous infrastructure patches in the series while introducing the core incremental compaction logic that will be exposed via `git repack --write-midx=incremental` in a later commit.

This represents a significant step in the multi-year effort to improve Git's scalability for large repositories, building on previous work refactoring repack.c and implementing MIDX layer compaction. The implementation has received thorough review from both object storage (Elijah Newren) and process management (Jeff King) experts.
