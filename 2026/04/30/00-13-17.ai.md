This is a refactoring patch in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking. The patch converts the `keep_hashes` array in `write_midx_internal()` from a manually managed array to using Git's `strvec` utility, which provides a more ergonomic interface for string array management.

Key changes:
- Replaces manual array allocation/counting with `strvec` operations
- Simplifies cleanup by using `strvec_clear()`
- Maintains the same ordering of MIDX file checksums which is critical for the `multi-pack-index-chain` file
- Updates related functions to accept a `strvec` instead of raw array+length parameters
- Includes corresponding changes to `clear_incremental_midx_files_ext()` to handle the new type

The refactoring builds on previous work in the series to modernize the codebase's string handling while preserving all functionality. This is part of the larger effort to improve Git's scalability for large repositories through more efficient repacking strategies. The patch has already been reviewed by both object storage (Elijah Newren) and process management (Jeff King) experts as part of the complete series.
