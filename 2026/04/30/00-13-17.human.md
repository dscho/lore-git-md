This is a refactoring patch in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking for large repositories. The patch converts the `keep_hashes` array in `write_midx_internal()` from a manually managed array to a `strvec`, which provides better memory management and a cleaner interface.

The change simplifies the code by:
1. Eliminating manual memory allocation and cleanup of the hash array
2. Using `strvec_push()` instead of indexed assignments
3. Removing the need to pre-count array elements
4. Leveraging `strvec_clear()` for automatic cleanup

This is part of the larger effort to improve Git's scalability for large repositories by implementing more efficient repacking strategies. The patch builds on previous work that introduced geometric and append-only MIDX chain repacking. The change is purely internal - it doesn't affect user-facing behavior but makes the code more maintainable.

The patch has already been reviewed by Jeff King (Peff) and addresses all prior feedback. It's one of the final refinements in this multi-patch series that's now ready for integration.
