This is a technical discussion about the behavior of `git fetch --deepen` in non-shallow repositories, following up on a reported regression in Git 2.54.0 that causes history truncation.

Mikael Magnusson responds to D. Ben Knoble's earlier analysis of the documentation ambiguity, arguing strongly that `--deepen` should be a no-op in non-shallow repositories. He provides a concrete example showing how the shallow boundary should logically move through commit history (A-B-C-D-E), and contends that resetting to a shallow state after a full fetch is clearly incorrect behavior. Magnusson points out that the original report already confirmed the behavior change between 2.53 and 2.54, making this a clear regression.

The exchange highlights two perspectives: Knoble's documentation-focused questioning of whether the behavior is truly specified versus Magnusson's practical argument about logical expectations. The discussion and demonstrated data loss suggest this will likely be treated as a bug to fix rather than a behavior to document. No proposed patch has emerged yet, but the technical case for treating this as a regression is strengthening.
