This is patch 15/16 in Taylor Blau's series implementing incremental MIDX/bitmap-based repacking for large repositories. The patch introduces a new `--write-midx=incremental` option for `git repack` that enables the incremental repacking mode implemented in earlier patches.

Key aspects of this patch:
- Adds the new `--write-midx=incremental` mode which requires `--geometric` to be specified
- Introduces two new config options to control compaction behavior:
  - `repack.midxSplitFactor` (default 2) - geometric merging factor for MIDX layers
  - `repack.midxNewLayerThreshold` (default 8) - minimum packs in tip layer before considering for repacking
- Includes extensive test coverage in t/t7705-repack-incremental-midx.sh that verifies:
  - Layer threshold behavior (when packs are/aren't repacked)
  - Geometric compaction of older layers
  - Handling of kept packs
  - Edge cases and invalid configurations

The implementation builds on the infrastructure from previous patches in the series, particularly the MIDX layer compaction logic. The tests demonstrate how the incremental mode maintains a chain of MIDX layers that are compacted over time using a merging strategy, with newer layers containing smaller packs that are rewritten more frequently than older layers.

This represents a significant user-facing piece of the incremental repacking functionality, providing the command-line interface and configuration options that will allow users to take advantage of the performance benefits for large repositories. The patch has received thorough review from object storage and process management experts earlier in the thread.
