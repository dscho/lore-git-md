This is the final patch in Taylor Blau's performance-focused series implementing incremental MIDX/bitmap-based repacking for large repositories. The patch relaxes a previous restriction that required `--write-midx=incremental` to be used with `--geometric`, allowing the incremental MIDX strategy to be used in an append-only mode.

The key change enables a simpler operational mode where each repack appends a new MIDX layer containing just the newly written packs, without any geometric merging of existing layers. This is implemented via a new `repack_make_midx_append_plan()` function that builds a plan consisting of a WRITE step for fresh packs followed by COPY steps for existing layers.

The patch updates documentation to clearly describe both modes (append-only vs geometric compaction) and replaces the test that enforced the old restriction with new tests exercising append-only behavior. Additional test cases verify safety properties when combining `--write-midx=incremental` with `-ad` repacks that delete old packs.

This completes the series' goal of providing flexible MIDX-based repacking strategies for large repositories, building on years of prior work refactoring Git's repack machinery. The implementation has received thorough review from both object storage (Elijah Newren) and process management (Jeff King) experts, with all technical concerns addressed in previous iterations. The series is now ready for integration.
