This is the final patch in Taylor Blau's series implementing incremental MIDX repacking, a performance optimization for large repositories. The patch relaxes a previous restriction that required `--write-midx=incremental` to be used with `--geometric`, now allowing it to operate in an append-only mode.

Without `--geometric`, the command simply adds a new MIDX layer containing the newly written packs while preserving all existing layers unchanged. This provides a simpler alternative to the geometric compaction strategy, which merges layers based on object count thresholds. The implementation introduces a new `repack_make_midx_append_plan()` function to handle this case separately from the geometric compaction logic.

The patch updates documentation to clearly explain both modes and replaces the test that enforced the old restriction with one verifying the new append-only behavior. It also adds a safety test confirming that `repack -ad --write-midx=incremental` correctly handles stale packs.

This completes a multi-year effort to improve Git's scalability for large repositories, building on previous work refactoring repack.c and implementing MIDX layer compaction. The series has received thorough review from both object storage (Elijah Newren) and process management (Jeff King) experts, with all technical concerns addressed. The implementation meets reliability standards for process safety and resource cleanup.
