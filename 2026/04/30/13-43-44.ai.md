This is a response from Phillip Wood clarifying the behavior of `git rebase -i` with multiple reword operations. He confirms that the sequential processing of reworded commits is the intended and longstanding behavior, not a regression. The response explains that this design allows inspecting changes for each commit being edited (particularly when `commit.verbose` is enabled) and suggests an alternative tool (`git-revise`) for batch editing commit messages.

Key technical points:
- The behavior described by the original reporter is working as designed
- Each reword operation opens the editor separately to maintain context about the specific commit being edited
- The `commit.verbose` configuration shows diffs during reword operations
- Alternative tools exist for batch editing workflows

The response effectively closes the issue by confirming this is not a bug but rather the expected behavior of the interactive rebase machinery. Phillip Wood's expertise in the sequencer subsystem lends authority to this clarification. The mention of `git-revise` provides a practical solution for users who prefer batch editing workflow while maintaining Git's default behavior for individual commit inspection.
