This is a bug report about changed behavior in `git rebase -i` on Windows. The reporter (David Jordanes) notes that when editing multiple commits in an interactive rebase (changing "pick" to "reword" for several commits), Git now processes them one at a time rather than applying all edits at once as it did previously.

The reporter provides clear reproduction steps using Git 2.53.0 on Windows 11, showing that after editing the rebase todo list to reword multiple commits, Git processes them sequentially rather than batching the changes. They question whether this is intentional behavior and express frustration at the workflow impact when rebasing many commits.

This appears to be a regression in behavior, though the reporter doesn't specify which version introduced the change. The issue specifically affects the Windows platform (as indicated by the Git version string and OS), suggesting it may be related to platform-specific changes in the interactive rebase machinery or editor handling. The report raises valid usability concerns but does not yet include any analysis of why the behavior changed or whether it affects other platforms.
