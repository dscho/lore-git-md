This is a refactoring patch from Taylor Blau's 16-part series implementing incremental MIDX/bitmap-based repacking. The patch simplifies the logic for building the `keep_hashes` array in `midx-write.c` by eliminating reverse indexing in favor of collecting MIDX layers into a temporary array first.

The key change replaces the previous approach of filling `keep_hashes` using `count - i - 1` indexing with a two-step process: first collecting all layers into a `layers` array while traversing forward, then iterating backward through that array to populate `keep_hashes` sequentially. This makes the control flow more straightforward and prepares for a future change to use `strvec` instead of manual array management.

The patch maintains all existing functionality while improving code clarity. It's part of the larger effort to enable geometric and append-only MIDX chain repacking strategies for large repositories. The change has already been reviewed as part of the complete series, with Jeff King (Peff) verifying the safety improvements and Elijah Newren confirming the object storage logic remains correct.
