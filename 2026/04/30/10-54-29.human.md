This is the first patch in a 4-part bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch refactors common retry path code into a new `http_reauth_prepare()` helper function.

The change is purely mechanical - it extracts the credential-filling logic that was duplicated across three HTTP retry paths into a single shared function. This prepares for subsequent patches that will modify the authentication behavior, particularly around empty auth attempts for Negotiate/Kerberos. The patch intentionally makes no functional changes.

The refactoring touches `http.c`, `http.h`, and `remote-curl.c`, moving the credential handling while maintaining the same behavior. Junio has already acked this change with a "Neat." comment, indicating it's a straightforward improvement. As the first step in the series, this lays groundwork for the more substantive authentication fixes to follow.
