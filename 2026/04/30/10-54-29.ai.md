This is a refactoring patch that's part of a series fixing HTTP authentication issues with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch extracts credential-filling logic into a new `http_reauth_prepare()` helper function that's called from three HTTP retry paths.

The change is purely structural - it moves the existing `credential_fill()` calls into a shared function without altering behavior. This prepares for a subsequent patch that will modify the authentication flow to properly handle empty auth attempts for Negotiate (Kerberos) authentication. The patch has already been reviewed and acked by Junio with a "Neat" comment, indicating it's a straightforward improvement.

The refactoring touches `http.c`, `http.h`, and `remote-curl.c`, centralizing the credential-filling logic that was previously duplicated in three places. The new function is documented with a clear header comment explaining its purpose. This is a typical preparatory patch that makes the actual behavior change (coming in patch 2/4) cleaner to implement.
