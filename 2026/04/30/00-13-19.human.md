This is part 5/16 of Taylor Blau's series implementing incremental MIDX/bitmap-based repacking for large repositories. The patch introduces a new `--no-write-chain-file` option for `git multi-pack-index` that allows writing new MIDX layers without immediately updating the chain file.

The key change is that when this flag is used with `--incremental`, Git will:
1. Write the new MIDX layer to the multi-pack-index.d directory
2. Print its checksum to stdout
3. Leave the chain file unchanged

This gives callers (like the new repacking strategy) the flexibility to assemble multiple layers themselves before atomically updating the chain file. The patch includes thorough documentation updates and tests verifying both the new option and its validation (it must be used with `--incremental`).

The implementation carefully handles lockfile management to ensure safety when skipping the chain file update. This is a well-contained change that fits cleanly into the larger series, maintaining the same attention to atomic operations and error handling seen in previous patches. The tests cover both happy paths and error cases, including verifying the chain file remains untouched when requested.
