Bug report regarding interactive rebase behavior change on Windows.

David Jordanes reports that `git rebase -i` on Windows (using Git 2.53.0.windows.2) now requires editing commits one at a time, rather than applying all changes at once. When attempting to reword multiple commits in a single interactive rebase session, Git processes them sequentially with separate edit prompts rather than applying the changes in bulk as expected.

The reporter questions whether this is intentional behavior, noting the workflow impact when rebasing many commits. They seek clarification on:
1. Whether this is a deliberate design choice
2. Who made this change
3. The rationale behind it
4. The problem it solves

This appears to be a regression report rather than a feature request, as the behavior differs from what the reporter expects based on prior experience. The issue is specific to the Windows build (the reporter notes their OS and Git for Windows version), suggesting it may be platform-specific behavior rather than a core Git change. No workaround is provided in the report.
