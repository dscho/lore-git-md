This is the second patch in a bugfix series addressing HTTP authentication issues with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The patch modifies the authentication flow to properly handle Negotiate authentication in auto mode.

The core change delays stripping the Negotiate authentication method on the first 401 response when in auto mode, allowing the empty-auth mechanism to attempt Kerberos authentication first. If that fails (due to no valid Kerberos ticket), it falls back to the original behavior of stripping Negotiate and proceeding with credential filling. The patch introduces an `empty_auth_try_negotiate` flag to control this behavior and modifies `http_reauth_prepare()` to skip credential filling when attempting empty auth.

This builds on the refactoring from patch 1/3 (which extracted retry path code into a helper function) and will be followed by test coverage in patch 3/3 and documentation updates in patch 4/4. The changes are well-contained to HTTP authentication logic in `http.c` and maintain backward compatibility with existing configurations.
