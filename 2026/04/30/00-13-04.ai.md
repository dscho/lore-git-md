This is the final version of Taylor Blau's feature patch series implementing incremental MIDX/bitmap-based repacking for large repositories. The series introduces a new repacking strategy that maintains an incrementally growing and shrinking MIDX chain to avoid periodic all-into-one repacks.

Key changes in this version:
1. Fixed stale references to "--checksum-only" in commit messages
2. Replaced custom pipe handling with `pipe_command()` to eliminate deadlock potential
3. Added proper cleanup in `write_midx_included_packs()` error paths
4. Moved an errant test to its correct location
5. Added new MIDX `--base` option for custom base layer specification

The implementation provides two operational modes:
- Geometric mode creates a layered structure with older layers containing fewer, larger packs
- Append-only mode preserves all prior layers unchanged

The series has received thorough review from both object storage (Elijah Newren) and process management (Jeff King) experts, with all technical concerns addressed. The documentation has been polished for consistency, and the implementation meets reliability standards for process safety and resource cleanup.

This represents the completion of a multi-year effort to improve Git's scalability for large repositories, building on previous work refactoring repack.c and implementing MIDX layer compaction. The series is now ready for maintainer integration with no outstanding items.
