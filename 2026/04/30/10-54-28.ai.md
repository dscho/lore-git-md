This is a bugfix and documentation series addressing an HTTP authentication issue with Kerberos (SPNEGO) when using `http.emptyAuth=auto`. The series builds on previous patches that were already reviewed and acked by Junio, now adding a documentation update to complete the solution.

The core issue involves a conflict between two older features: a 2015 change that strips Negotiate auth on first 401 response (to fall back to Basic), and a 2017 "auto" mode that should allow empty auth attempts for exotic methods like Kerberos. Currently the stripping happens too early, making `auto` mode behave like `false` for Negotiate-only servers.

The v2 series adds a new documentation patch (patch 4) that explicitly lists the allowed values for `http.emptyAuth` (auto/true/false) and clarifies their behaviors. This matches the technical implementation from the earlier patches, which:
1. Refactor retry path code into a helper function
2. Delay Negotiate stripping in auto mode to allow one empty auth attempt
3. Add tests verifying the new behavior

The changes are well-contained to HTTP auth logic and have already been adopted in Git for Windows 2.54.0-rc2. With the documentation now added, the series appears complete and ready for merging. The thread shows consensus on both the technical solution and documentation approach, with no outstanding questions remaining.
