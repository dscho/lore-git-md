This is a refactoring patch from Taylor Blau's 16-part series implementing incremental MIDX/bitmap-based repacking for large repositories. The patch converts the MIDX file cleanup code from using hand-rolled arrays to the `strset` data structure for tracking which MIDX files to retain during pruning operations.

The change affects two functions that clear stale MIDX files:
- `clear_midx_files_ext()` now uses a `strset` instead of an allocated array for the single keep_hash case
- `clear_incremental_midx_files_ext()` similarly replaces its array with a `strset` for multiple keep_hashes

The refactoring simplifies memory management by leveraging the `strset`'s built-in string storage and lookup capabilities, though the performance impact is noted as likely negligible given the small typical size of the keep lists. The patch maintains all existing functionality while reducing code complexity - the need to manually track array lengths and free individual strings is eliminated.

This is a straightforward improvement that builds on the series' earlier architectural work. As part of the larger incremental MIDX effort, it helps ensure reliable cleanup of temporary files while keeping the required MIDX layers intact. The change has already been reviewed as part of the complete series, with Jeff King (Peff) having verified the process safety aspects.
