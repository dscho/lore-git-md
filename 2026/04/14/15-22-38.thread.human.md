This thread discusses a critical compatibility issue in Git 2.54.0-rc2 involving the MIDX (multi-pack-index) format. The second release candidate unintentionally broke backward compatibility by defaulting to MIDX version 2, making repositories touched by rc2 unusable with stable Git 2.53.0 installations. Jeff King (Peff) diagnosed the problem - older versions would crash rather than gracefully falling back to pack files when encountering unknown MIDX versions.

The solution emerged quickly through consensus: revert the default MIDX version to v1 while keeping v2 available via explicit configuration (`midx.version=2`). This balances compatibility with forward progress, as users needing v2 features (like compaction) can opt in. Junio Hamano approved and applied this fix in rc2, with an improved commit message explaining this as a temporary measure until ecosystem tools (libgit2, JGit) support MIDX v2.

While this immediate issue is resolved, the thread reveals a deeper consideration about MIDX error handling - whether encountering unknown versions should trigger fatal errors (current behavior) or warnings with graceful degradation. Junio suggests this broader change warrants separate discussion, likely post-2.54.0. The thread demonstrates Git's careful approach to file format changes, where stability consistently outweighs new features by default, even when that means temporarily rolling back improvements.
