This is a test fix patch in the fsmonitor daemon series, addressing issues found in the Linux-specific test coverage added in v14. SZEDER Gábor points out two problems with the test infrastructure:

1. The `test_might_fail` helper doesn't properly handle the new `maybe_timeout` wrapper, causing daemon processes to be left running after tests complete. This was masked by a broken &&-chain and stderr redirection.

2. The process group handling in the submodule pull test needs adjustment to properly clean up background processes.

The patch had introduced thorough testing for Linux inotify edge cases (event delivery verification and EEXIST race conditions) but these test infrastructure issues slipped through. The problems are in the test plumbing rather than the core fsmonitor functionality, which has already been approved by Junio after 14 iterations of review.

This appears to be a final polish before integration, fixing test reliability issues that could cause false negatives or leave processes running. The core fsmonitor implementation remains solid, with these being test-suite specific fixes.
