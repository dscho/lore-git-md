This is the third patch in a 4-part feature series enhancing `git checkout -m` with autostash behavior during branch switching conflicts. The series has already undergone extensive review and is in its final polishing stages.

The patch adds support for customizable conflict marker labels when applying autostashes. It introduces new parameters (`label_ours`, `label_theirs`, `label_base`) to the autostash machinery and exposes them through a new public API function `apply_autostash_ref_with_labels()`. This allows callers to pass custom labels through to `git stash apply`'s new `--label-*` options (added in patch 1/4).

Key technical changes:
- Adds label parameters to internal functions `apply_save_autostash_oid()` and `apply_save_autostash_ref()`
- Introduces new public API apply_autostash_ref_with_labels()` in sequencer.h
- Maintains backward compatibility by keeping existing functions that pass NULL labels
- Updates the stash message handling to use the provided message or fall back to "autostash"

The implementation is clean and follows the established pattern of the series. The changes are focused and well-contained, touching only the sequencer.c and sequencer.h files. The patch builds on the solid foundation established in previous iterations, with all major design questions already resolved in earlier reviews.

This represents the final technical piece needed to fully integrate the label customization feature with the autostash machinery. With this patch, the series now provides complete support for both silent stash creation (from patch 2/4) and labeled conflict resolution when applying those stashes.
