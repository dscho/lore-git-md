This is a technical refinement discussion in the final stages of a feature series implementing autostash behavior for `git checkout -m`. Phillip Wood raises two specific implementation questions about the patch that adds conflict marker label support to the autostash machinery.

First, he questions why the patch requires passing a stash message parameter when applying an existing stash that already contains its own message. This appears to be an unnecessary parameter that could be simplified. Second, he suggests that rather than introducing a new `apply_autostash_ref_with_labels()` function, the existing callers could be updated to pass NULL labels, which would make future enhancements easier.

These are minor implementation details in an otherwise complete and approved series. The questions don't challenge the core functionality but aim to refine the API design before merging. The patch author Harald Nordgren will need to address whether these changes can be incorporated without disrupting the carefully reviewed series that has already gone through 12 iterations.
