This is the first patch in the v12 series implementing unified conflict resolution in `git checkout -m` with autostash behavior. The patch adds new `--label-ours`, `--label-theirs`, and `--label-base` options to `git stash apply` to customize conflict marker labels, which will be used by the autostash functionality in later patches.

The changes introduce a new `do_apply_stash_with_labels()` wrapper function that accepts custom labels for conflict markers, falling back to the default "Updated upstream"/"Stashed changes"/"Stash base" when none are provided. The implementation handles both regular labels and empty strings (which produce unlabeled conflict markers). The patch includes documentation updates and two new test cases in t3903-stash.sh verifying the label customization and empty label behavior.

The modifications touch several components:
- Documentation/git-stash.adoc for the new options
- builtin/stash.c for the core implementation
- xdiff/xmerge.c to properly handle empty labels
- t/t3903-stash.sh for test coverage

This is a well-contained change that builds on Git's existing conflict marker infrastructure while providing the foundation for the autostash behavior in subsequent patches. The implementation is clean and maintains backward compatibility with existing `git stash apply` usage. The test coverage is thorough, verifying both the happy path and edge cases like empty labels.
