This thread focuses on Siddharth Shrimali's series modernizing tests in t7004-tag.sh, part of Git's ongoing effort to replace brittle test patterns with more robust alternatives. The three-patch series removes hardcoded tag counts, eliminates subshell usage that could mask failures, and makes tests more isolated. Junio Hamano reviewed the first two patches, approving the second with an "Excellent" comment while suggesting (but not requiring) enhanced state verification for the first.

Patrick Steinhardt has now joined the discussion, reinforcing Junio's earlier suggestion that comparing tag lists before and after invalid tag attempts would provide stronger validation than just checking exit codes. While acknowledging the current patches improve test isolation, Patrick notes they could miss cases where a command fails but still modifies repository state. This exchange highlights the project's emphasis on thorough testing - even when modernizing tests, maintainers prefer verification that catches both command failures and unintended state changes.

The series appears headed for acceptance, as Junio already approved the second patch's approach and Patrick's feedback aligns with (rather than contradicts) that direction. Siddharth may choose to implement the suggested enhancement in a follow-up series, but the core improvements seem likely to merge as-is given their alignment with established test modernization patterns.
