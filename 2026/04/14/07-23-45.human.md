This is a follow-up in Patrick Steinhardt's series to enable `set -e` in Git's test suite, specifically addressing a macOS CI failure that surfaced after the preparatory patches were merged to the 'seen' branch. The issue appears in t9501-gitweb-standalone-http-status.sh where Perl module detection for the DATE_PARSER prerequisite fails under `set -e`.

Patrick identifies the problem as stemming from how the test checks for Perl modules - the current direct `perl -M...` calls would cause the test to exit immediately under `set -e` if the module isn't found. His proposed fix converts this to use `test_lazy_prereq`, which properly handles command failures. This matches the pattern seen throughout the series where `set -e` exposes previously hidden failure cases in test infrastructure.

The change is narrowly focused on making the gitweb test compatible with strict error handling while maintaining the same prerequisite checking behavior. This continues the series' theme of methodically addressing edge cases revealed by `set -e`, now catching a macOS-specific interaction that wasn't visible in earlier testing. The fix demonstrates how enabling `set -e` systematically improves test robustness by forcing explicit handling of failure cases.
