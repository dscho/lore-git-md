This is the eleventh iteration of a feature patch series that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The series has already received extensive review and maintainer approval, with this version making minor refinements to the autostash message format.

The key change in v11 is the addition of branch context to autostash messages - now showing "autostash while switching to 'branch'" when conflicts occur during checkout. This addresses the final UX polish point from previous discussions, implementing Junio Hamano's suggested message format rather than the source-branch alternative proposed by Harald Nordgren in v10.

The series remains technically complete with all prior feedback addressed, including Jeff King's validation of the `CHECKOUT_AUTOSTASH_HEAD` refname convention. The implementation spans multiple components (`builtin/checkout.c`, `builtin/stash.c`, `sequencer.c`) and includes comprehensive test coverage (19 new test cases in t7201-co.sh).

Changes from v10 are minimal:
1. Added branch context to autostash messages
2. Introduced new `create_autostash_ref_silent_with_msg()` function
3. Updated tests to verify message format

The series provides several user-facing improvements:
- `git checkout -m` now automatically stashes uncommitted changes during conflicting branch switches
- New `--label-*` options for `git stash apply` to customize conflict markers
- Silent autostash creation during operations

With this final message format settled, the series is fully polished and ready for merging, representing a significant quality-of-life improvement for branch switching workflows with uncommitted changes. The changes maintain backward compatibility while making conflict resolution more consistent with Git's existing autostash behavior in rebase/merge.
