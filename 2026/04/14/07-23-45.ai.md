This is a follow-up in Patrick Steinhardt's series to enable `set -e` in Git's test suite, now addressing a macOS-specific CI failure that surfaced after merging the changes to the 'seen' branch. The issue appears in t9501-gitweb-standalone-http-status.sh where Perl module detection for the DATE_PARSER prerequisite fails under `set -e` on macOS.

Patrick identifies that the current implementation directly runs Perl checks in the test file's main body, which now fails the test script when the modules are missing (due to `set -e` making the script exit immediately). His proposed fix converts the prerequisite check to use `test_lazy_prereq`, which properly handles command failures by design. This matches the pattern used elsewhere in the test suite for similar module checks.

The change is narrowly focused on making the gitweb test compatible with `set -e` while maintaining the same functionality - it still checks for either HTTP::Date or Time::ParseDate Perl modules, just in a way that won't abort the test script if neither is available. This continues the series' theme of systematically finding and fixing edge cases where `set -e` would expose previously silent failures, now surfacing a platform-specific interaction in Perl module detection.

Key technical details:
- Changes t9501's DATE_PARSER check from direct Perl commands to `test_lazy_prereq`
- Maintains same module check logic (HTTP::Date or Time::ParseDate)
- Follows established test suite patterns for module detection
- Fixes macOS CI failure while keeping behavior equivalent
- Demonstrates how `set -e` continues to reveal hidden assumptions in test infrastructure

The patch shows the series is now in its final refinement phase, addressing the last platform-specific edge cases before the `set -e` changes can graduate to more stable branches.
