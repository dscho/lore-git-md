Feature patch implementing autostash behavior for `git checkout -m` with conflict resolution. This is the final patch in a v11 series that has already received extensive review and maintainer approval.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches would cause conflicts, then reapply them after the switch. If the stash application results in new conflicts, the stash is preserved and the user is given instructions for resolving the situation. The implementation builds on Git's existing autostash infrastructure used by `git rebase` and `git merge`, with several key changes:

1. The autostash refname is now `CHECKOUT_AUTOSTASH_HEAD` (validated by Jeff King)
2. Autostash messages include the target branch name ("autostash while switching to 'branch'")
3. Conflict resolution uses the same labeling system as `git stash apply --label-*`
4. The implementation handles both staged and unstaged changes appropriately

The patch includes comprehensive test coverage (19 new tests in t7201-co.sh) verifying:
- Basic autostash behavior during branch switching
- Handling of both overlapping and non-overlapping changes
- Interaction with merge.conflictStyle configuration
- Proper behavior with staged vs unstaged changes
- Preservation and usability of the autostash when conflicts occur

Documentation for both `git checkout` and `git switch` is updated to reflect the new behavior. The changes maintain backward compatibility while making conflict resolution more consistent with Git's existing autostash workflows.

With all technical concerns addressed and maintainer approval from Junio Hamano, this patch represents a significant quality-of-life improvement for branch switching workflows with uncommitted changes. The implementation is polished and ready for merging.
