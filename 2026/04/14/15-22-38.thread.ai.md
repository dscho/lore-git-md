Git v2.54.0-rc2 release candidate announcement, second preview of upcoming Git 2.54.0 version. Contains 744 non-merge commits from 127 contributors (64 new). Notable changes since rc1 include reverting writev() series due to portability issues and now a MIDX version 2 compatibility problem reported by Johannes Schindelin. The MIDX version bump (commit b2ec8e90) breaks backward compatibility with Git v2.53.0, making repositories touched by v2.54.0-rc2 unusable with the stable version - contrary to the commit's claim that older versions would "gracefully degrade". This affects downgrade scenarios, mixed-version environments (including GitHub Desktop), and interoperability with libgit2/JGit.

Jeff King (Peff) provides technical analysis of the MIDX compatibility issue, noting that while MIDX should be optional, older Git versions call `die()` when encountering unknown versions rather than falling back to regular pack files. He provides a patch making v2.53.0 properly degrade by converting `die()` calls to non-fatal errors (though this can't be retroactively applied). Other implementations handle this better: JGit throws but catches exceptions, libgit2 falls back gracefully. Peff suggests deleting `.midx` files as a workaround but questions whether reverting to generating v1 MIDX files by default might be preferable until ecosystem catches up, since v2 currently represents a regression for users not yet needing its features.

Peff now proposes a concrete solution: temporarily revert the default MIDX version from v2 back to v1 via a one-line code change, while keeping the config option `midx.version=2` for users needing v2 features (like compaction). He includes accompanying test fixes that maintain expectations for the v1 format. The change would prevent compatibility breaks while allowing explicit opt-in to v2 functionality. Peff frames this as an interim measure pending ecosystem readiness, deferring to Taylor Blau (MIDX expert) for final guidance.

Derrick Stolee strongly supports Peff's proposal to temporarily revert the default MIDX version back to v1 while allowing explicit opt-in to v2 via configuration. He emphasizes this aligns with Git's standard approach of avoiding breaking file format changes by default. The key insight is that the problem manifests during normal maintenance operations (like fetch) where MIDX files get automatically regenerated, making manual workarounds impractical for users. While agreeing with the immediate fix, Stolee also notes the broader architectural point that Git should handle unknown MIDX versions more gracefully - falling back to packfiles with clear warnings rather than failing hard. However, he rightly separates this from the urgent rc2 fix, suggesting it as future work.

Junio Hamano concurs with Stolee's assessment that reverting the default MIDX version back to v1 (while allowing explicit v2 opt-in) aligns with Git's standard approach to file format changes. He seeks a volunteer to implement the patches for this change. The discussion clarifies that the problem is particularly acute because MIDX files get automatically regenerated during normal operations like fetch, making manual workarounds ineffective. Junio questions Stolee's phrasing about deleting MIDX files not keeping repositories in a good state, noting that MIDX indexes are technically optional, but agrees with the broader point about needing better handling of unknown MIDX versions - suggesting such improvements could be done separately from the urgent rc2 fix. The exchange demonstrates the maintainer's careful consideration of both immediate compatibility concerns and longer-term architectural improvements.

Key areas in this release remain: new experimental `git history` command for history rewriting, `git replay` improvements (empty commit handling), enhanced hook/alias configuration, pack handling optimizations (with MIDX compatibility concern now having a proposed solution), continued `the_repository` removal progress, Rust infrastructure work for object handling. Fixes address HTTP auth, diff stat with non-ASCII paths, submodule edge cases, ref transactions. Release notes organized into UI/workflow, performance/internal, fixes since v2.53.0 sections. The MIDX compatibility issue remains a critical blocker but now has clear consensus around Peff's proposed solution with Stolee's endorsement and Junio's approval, pending implementation and Taylor Blau's final decision.
