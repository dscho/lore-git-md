Feature patch adding customizable conflict marker options to `git stash apply`. This is the first patch in the v11 series that enhances `git checkout -m` with autostash behavior, now fully approved for merging.

The patch introduces three new options to `git stash apply`:
- `--label-ours=<label>` - Custom label for the upstream side in conflict markers
- `--label-theirs=<label>` - Custom label for the stashed side
- `--label-base=<label>` - Custom base label (only affects diff3-style conflicts)

The implementation modifies `builtin/stash.c` to pass these labels through to the merge machinery, with empty strings allowed to produce blank labels. The changes include thorough documentation updates and new test cases verifying both custom labels and empty label handling. The xdiff/xmerge.c modifications ensure proper handling of empty labels in the conflict marker generation.

This builds on Git's existing conflict marker infrastructure while providing more control over the presentation of stashed changes during conflicts. The patch maintains backward compatibility by defaulting to the traditional "Updated upstream"/"Stashed changes"/"Stash base" labels when no custom labels are specified.

Technical details include:
- New `do_apply_stash_with_labels()` function that wraps the existing apply logic
- Updates to the merge options structure to handle custom labels
- 2 new test cases in t3903-stash.sh covering both custom and empty labels
- Careful handling of NULL vs empty string cases in xdiff conflict marker generation

The patch has already undergone extensive review across 11 iterations, with this version representing the final polished implementation ready for merging. It provides a useful quality-of-life improvement for users who want more control over conflict resolution when applying stashes.
