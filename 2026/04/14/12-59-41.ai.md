This is the twelfth iteration of a feature patch series that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The series has already received extensive review and maintainer approval, with this version making minor refinements to function naming and message handling.

The key change in v12 is renaming `create_autostash_ref_silent()` to `create_autostash_ref_with_msg_silent()` to better reflect its functionality, following feedback from Junio Hamano. The implementation remains technically complete with all prior feedback addressed, including Jeff King's validation of the `CHECKOUT_AUTOSTASH_HEAD` refname convention.

The series spans multiple components (`builtin/checkout.c`, `builtin/stash.c`, `sequencer.c`) and includes comprehensive test coverage (19 new test cases in t7201-co.sh). It provides several user-facing improvements:
- `git checkout -m` now automatically stashes uncommitted changes during conflicting branch switches
- New `--label-ours`, `--label-theirs`, and `--label-base` options for `git stash apply` to customize conflict markers
- Silent autostash creation during operations with branch-specific messages

Changes from v11 are minimal:
1. Renamed `create_autostash_ref_silent()` to `create_autostash_ref_with_msg_silent()`
2. Consolidated message handling in the internal autostash functions
3. Updated tests to verify the new function naming

The series maintains backward compatibility while making conflict resolution more consistent with Git's existing autostash behavior in rebase/merge. With this final naming refinement, the series is fully polished and ready for merging, representing a significant quality-of-life improvement for branch switching workflows with uncommitted changes.
