This is the final patch in a feature series that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The series has already received extensive review and maintainer approval, with this version implementing the core functionality.

The patch teaches `git checkout -m` to automatically stash local changes when switching branches would cause conflicts, then reapply them after the switch. If the changes apply cleanly, it shows "Applied autostash"; if conflicts occur, it keeps the stash entry and provides clear instructions for resolution. The implementation spans multiple components (`builtin/checkout.c`, `sequencer.c`) and includes comprehensive test coverage (19 new test cases in t7201-co.sh).

Key improvements include:
- Automatic stashing of conflicting changes during branch switches
- Clear user messaging about conflict resolution options
- Support for various conflict styles (diff3, zdiff3)
- Careful handling of both staged and unstaged changes
- Preservation of the stash entry when conflicts occur

The changes maintain backward compatibility while making conflict resolution more consistent with Git's existing autostash behavior in rebase/merge. With all technical concerns resolved and maintainer approval, this represents a significant quality-of-life improvement for branch switching workflows with uncommitted changes.
