This is the final patch in a 12-part series implementing autostash behavior for `git checkout -m`, now ready for merging after extensive review. The patch teaches `git checkout -m` to automatically stash local changes when switching branches with conflicts, then reapply them after the switch. If reapplying causes conflicts, the stash is preserved with clear instructions for resolution.

The implementation handles both staged and unstaged changes, skips stashing when changes don't conflict, and provides consistent messaging about the stash state. It builds on earlier patches that added label support to `git stash apply` and silent autostash creation. The refname `CHECKOUT_AUTOSTASH_HEAD` was validated by Jeff King as compliant with Git's refname rules.

Documentation is updated for both `git checkout` and `git switch` to explain the new behavior. The patch includes 19 new test cases in t7201-co.sh covering all scenarios, from simple non-conflicting changes to complex staged/unstaged combinations. The implementation maintains backward compatibility while making conflict resolution workflow more consistent with Git's existing autostash behavior in rebase/merge.

With this final naming refinement (renaming `create_autostash_ref_silent()` to `create_autostash_ref_with_msg_silent()` per Junio's request), the series is fully polished and represents a significant quality-of-life improvement for branch switching workflows with uncommitted changes.
