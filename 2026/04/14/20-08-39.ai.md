This is a maintainer review comment from Junio C Hamano on the first patch in Taylor Blau's pseudo-merge bitmap bugfix series. The email focuses on a potential memory safety issue in the new `test-tool bitmap write` helper's object packing implementation.

Junio identifies a subtle reallocation hazard in the `add_packed_object()` callback function. The function stores pointers to `object_entry` structures that may become invalid if the underlying `packed.objects` array is reallocated during growth. This is a serious concern since the pointers are stored in `data->index` for later use, and any invalidation would lead to use-after-free bugs.

The review doesn't reject the patch but presents the issue as an open question ("I must be missing something?"), inviting the author to either explain why the current approach is safe or to propose a solution. Given Junio's deep familiarity with Git's memory management patterns, this is likely a genuine concern rather than a misunderstanding.

This interaction is foundational for the rest of the series since the test helper needs to be robust before it can be used to verify the subsequent pseudo-merge bitmap fixes. The issue touches core Git concepts like the packing data structure lifecycle and object entry management, areas where both Junio and Taylor have substantial expertise.
