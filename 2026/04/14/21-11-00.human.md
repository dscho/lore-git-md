This is a test infrastructure discussion about the `test_must_fail` and `test_might_fail` helpers, part of an ongoing effort to modernize error handling in Git's test framework. The thread originated in 2021 with SZEDER Gábor's patch to use BUG() for parameter validation in `test_must_fail`, which has gained new relevance as it would have caught a real test failure scenario that occurred in the interim.

Junio C Hamano now raises a broader question about whether `test_might_fail` should be deprecated, arguing its use cases are narrow and often better expressed with `|| :`. He notes that while these helpers can detect crashes (a nice-to-have feature), their primary value is limited since they're used for setup/teardown operations rather than the actual tests themselves. The discussion builds on prior consensus about standardizing on BUG() for test helper validation and using file descriptor 6 for stderr in test output.

This continues a well-established technical direction with no new implementation work proposed - just a maintainer's perspective on potentially simplifying the test helper API. The thread shows how long-running infrastructure improvements can have concrete payoff years later when they help catch real issues.
