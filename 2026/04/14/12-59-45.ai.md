This is the fourth and final patch in a feature series that enhances `git checkout -m` with autostash behavior during branch switching conflicts. The series has undergone extensive review and is now ready for merging after 12 iterations.

The patch implements the core functionality where `git checkout -m` will now automatically stash uncommitted changes when encountering conflicts during branch switches, then reapply them after the switch. If the stash application results in conflicts, the stash is preserved with clear instructions for the user on how to proceed. The implementation handles both staged and unstaged changes, and includes comprehensive test coverage (19 new test cases in t7201-co.sh).

Key technical details:
- Uses the `CHECKOUT_AUTOSTASH_HEAD` refname (validated by Jeff King)
- Adds silent autostash creation via `create_autostash_ref_with_msg_silent()`
- Applies stashes with proper conflict marker labels via `apply_autostash_ref_with_labels()`
- Maintains backward compatibility
- Integrates with merge.conflictStyle configuration
- Includes detailed documentation updates for both `git checkout` and `git switch`

The patch builds on the infrastructure from earlier patches in the series (label support in `git stash apply`, silent autostash creation in the sequencer) to provide a complete solution. It represents a significant quality-of-life improvement for branch switching workflows with uncommitted changes, making the behavior consistent with Git's existing autostash functionality in rebase/merge.

With all technical concerns resolved and maintainer approval from Junio Hamano, this final version is polished and ready for merging. The series as a whole demonstrates careful attention to edge cases, thorough test coverage, and clear documentation - making it a high-quality contribution to Git's branch switching capabilities.
