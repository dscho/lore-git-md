This is a technical follow-up in Patrick Steinhardt's series to enable `set -e` in Git's test suite. Jeff King identifies a subtle bash shell behavior difference that affects how `set -e` interacts with the `command` built-in on different bash versions, particularly on macOS where an older bash version is used.

The key finding is that when `command` is used (as happens when `perl` is a shell function calling `command $PERL_PATH`), bash 3.2.57 (used on macOS) will still trigger `set -e` failures even when the command is on the left side of `&&` - contrary to normal shell behavior. This explains why Patrick's original change to `test_lazy_prereq` was needed for macOS compatibility, despite the code being technically correct under standard shell semantics.

Jeff notes this appears to be a long-standing bash bug that won't be fixed in macOS's shell due to licensing constraints. The only workaround would be to temporarily disable `set -e` around such commands, though this would be cumbersome. The discussion provides important context about platform-specific shell behavior that the test suite needs to account for, particularly as the project moves toward stricter error handling with `set -e`.
