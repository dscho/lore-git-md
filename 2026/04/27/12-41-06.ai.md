This is a feature patch in Christian Couder's URL-based promisor remote configuration series (v2 6/8). It implements the core security mechanism for trusting known remotes when their URLs match patterns in `promisor.acceptFromServerUrl`.

The patch introduces a URL matching system that:
- Uses strict component-wise comparison (scheme/port must match exactly)
- Applies wildcard matching to host/path with security boundaries (host matching prevents crossing `/` boundaries)
- Normalizes URLs before comparison to prevent encoding/decoding tricks
- Only activates when `promisor.acceptFromServer` is set to "None" (the secure default)

Key technical additions:
- New `url_matches_accept_list()` helper that implements the pattern matching logic
- Enhanced `should_accept_remote()` to check URL patterns as an allowlist
- Comprehensive documentation of security considerations and matching rules
- New test cases covering various URL matching scenarios

The implementation carefully balances security and usability - organizations can now configure broad URL patterns (like `https://my-org.com/*`) while maintaining protection against malicious URL variations. The documentation provides clear guidance on safe pattern usage, particularly warning against overly broad patterns on shared hosting platforms.

This patch builds on the preparatory work in earlier patches of the series and appears well-integrated with the existing promisor-remote infrastructure. The security-conscious design and thorough test coverage suggest it's ready for merging after the positive reviews from Patrick Steinhardt and Junio C Hamano.
