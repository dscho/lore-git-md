This is part 3 of a 9-patch series refactoring Git's reference backend code to consolidate common logic. The patch moves reflog configuration handling from individual backends into the shared refs layer.

The change standardizes how backends determine when to create reflog entries by:
1. Adding a `log_all_ref_updates` field to `struct ref_store_init_options`
2. Setting this value once in `ref_store_init()` using the existing `repo_settings_get_log_all_ref_updates()` function
3. Having backends (files and reftable) use the passed value rather than querying config themselves

This is a mechanical refactoring that doesn't change behavior - it eliminates duplicate config lookups and makes the reflog policy consistent across backends. The patch follows the series' architectural approach of moving backend-specific logic into the generic layer where possible.

The change is well-contained, touching only initialization paths, and builds on prior review consensus about the refactoring direction. As with the rest of the series, this appears ready for integration.
