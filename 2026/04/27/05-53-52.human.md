This is the second patch in Patrick Steinhardt's v3 series introducing the `git history fixup` subcommand, which builds on the experimental `git history` command infrastructure. The patch refactors internal tree-commit functionality to support the new subcommand's needs.

The change generalizes `commit_tree_with_edited_message_ext()` into a more flexible `commit_tree_ext()` function that accepts a flags parameter. The key addition is `COMMIT_TREE_EDIT_MESSAGE`, which makes message editing optional while preserving all other functionality (parent handling, header stripping). This prepares for the `fixup` subcommand in the next patch, which needs to commit trees while retaining original commit messages.

The refactoring is mechanical and well-contained, touching only `builtin/history.c`. It maintains all existing behavior when the edit flag is set, while providing the new capability needed for the upcoming feature. The patch follows Git's style guidelines and includes updates to all callers of the original function.
