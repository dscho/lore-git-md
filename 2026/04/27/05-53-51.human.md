This is the first patch in a 3-part series introducing a `git history fixup` subcommand, part of Patrick Steinhardt's ongoing work on the experimental `git history` command. The series builds on earlier infrastructure from April 2026.

The patch generalizes empty commit handling in Git's replay infrastructure. Currently, when replaying commits that become empty (having identical tree content to their parent), they are automatically dropped with no user control. This change introduces a new enum `replay_empty_commit_action` that lets callers choose whether to drop empty commits (current behavior), keep them, or abort the operation entirely.

The implementation adds the enum to `replay.h` and modifies `pick_regular_commit()` to respect the chosen behavior. The default remains dropping empty commits to maintain backward compatibility. The change is cleanly implemented with thorough documentation of the new options.

This foundational work supports the upcoming `fixup` subcommand by providing more flexible control over empty commit handling during rebase-like operations. The patch follows Git's coding style and includes appropriate error handling when abort option is selected. As the first in a series from a trusted contributor, it appears well-structured and focused on its specific task.
