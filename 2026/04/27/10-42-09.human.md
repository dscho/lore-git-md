This is patch 8/9 in Karthik Nayak's v3 series refactoring Git's reference backend code. The patch adds support for storing peeled object IDs in the `ref_update` structure, moving tag-peeling logic from individual backends to the shared refs layer.

The change introduces a new `peeled` field to `ref_update` and modifies related functions to handle peeled OIDs. This allows backends like packed and reftable to store the peeled value of tag references without each having to implement their own peeling logic. The patch updates all callers to pass NULL for cases where peeling isn't needed (like reflog updates or deletions).

This is a mechanical but important change in the broader effort to consolidate backend-specific logic. The implementation looks clean and well-tested, with thorough updates to all affected call sites. The series has already received substantive review from Patrick Steinhardt and Toon Claes, with all prior feedback incorporated. This patch in particular builds on the validation changes from patch 7/9 to complete the peeling consolidation.

The series appears ready for merging, representing another step in the ongoing ref backend unification work that Karthik and Patrick have been driving.
