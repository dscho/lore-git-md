Performance optimization patch for `index-pack` and `unpack-objects` I/O efficiency, version 3.

Scott Bauersfeld's patch series continues to refine the buffer size optimization for pack file operations, now addressing feedback from Derrick Stolee about naming the shared constant. The key change in v3 is renaming `DEFAULT_PACKFILE_BUFFER_SIZE` to the more general `DEFAULT_IO_BUFFER_SIZE` to better reflect its use across multiple I/O operations, not just packfiles.

The patch maintains the core performance improvement - increasing the input buffer from 4KB to 128KB to reduce system call overhead, particularly beneficial for FUSE filesystems. Measurements show 10-11% faster clones on FUSE (75.7s vs 84.5s for vscode repo, 20.0s vs 22.6s for git/git) and a 65% reduction in pack file writes.

The implementation now properly centralizes the buffer size definition in `git-compat-util.h` while preserving the measured performance gains. The commit message has been further refined to explain the naming change and confirm there are no remaining hardcoded values to consolidate. This appears merge-ready pending any final review comments.
