This is the third version of a patch series introducing a `git history fixup` subcommand, part of Patrick Steinhardt's ongoing work on the experimental `git history` command. The series builds on commit 94f057755b from April 2026.

The new subcommand` allows amending staged changes to an existing commit (similar to `git commit --fixup`) while automatically rebasing dependent branches - a workflow the author reports using frequently. The implementation currently aborts on merge conflicts, with plans to improve conflict handling when Git gains first-class conflict resolution capabilities.

Key changes in v3:
- Further polishing of the command's documentation to better explain the behavior by comparing it to the familiar `git commit --fixup` + `git rebase --autosquash` workflow
- Maintains all technical details about the three-way merge implementation but presents them in a supporting role after the practical description

The series consists of 3 well-structured patches:
1. Generalizes empty commit handling in the replay infrastructure
2. Refactors internal tree-commit functionality into a more flexible `commit_tree_ext()` with flags parameter
3. Implements the `fixup` subcommand with automatic rebasing of dependent branches

The implementation includes thorough test coverage (680+ lines in t3453-history-fixup.sh) and appears production-ready aside from the noted conflict resolution limitation. The documentation improvements in v3 address previous review feedback by D. Ben Knoble to focus more on practical effects rather than implementation details.

Given Patrick's track record with the history command and the clear motivation, this seems likely to progress smoothly through review. The automatic rebasing of dependent branches remains the most notable aspect that may warrant discussion about edge cases and user expectations.
