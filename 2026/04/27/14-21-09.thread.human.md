This thread addresses a test failure in t5564-http-proxy.sh where Unix domain socket paths exceed Linux's 108-character limit when tests run in deeply nested worktrees. Johannes Schindelin (Dscho) originally proposed moving the SOCKS proxy socket to $TMPDIR (like similar fixes for SSH sockets), which solves the length issue. 

Peff has reviewed the solution and agrees with the general approach but raises important security concerns about using a static /tmp path - specifically race conditions between test runs and symlink attacks. He suggests instead using `mktemp -d` to create unique temporary directories, maintaining the short path requirement while being more secure. The discussion remains technical and constructive, with Peff building on Dscho's work by referencing Git's usual socket-handling patterns. 

The fix appears straightforward and the security improvements seem uncontroversial, so this will likely proceed with Peff's suggested modifications. Both contributors demonstrate deep knowledge of both test infrastructure and Unix domain socket constraints.
