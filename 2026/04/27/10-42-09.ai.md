This is patch 8/9 in Karthik Nayak's series refactoring Git's reference backend code to consolidate object validation and peeling logic. The patch adds support for passing peeled object IDs through the ref transaction layer.

The change introduces a new `peeled` field to the `ref_update` struct and modifies `ref_transaction_add_update()` to accept a peeled OID parameter. When a reference update points to a tag object, `ref_transaction_update()` now peels the tag and stores the result in the transaction. This prepares for future patches that will have backends use this pre-peeled OID rather than each performing their own peeling.

The patch updates all callers to pass NULL for the peeled parameter where appropriate (reflog updates, deletions) and modifies the files and reftable backends to handle the new field. A new `REF_HAVE_PEELED` flag indicates when the peeled field contains valid data.

This is a mechanical but important step in the series' goal of moving common ref operations into the shared layer. The change maintains existing behavior while setting up infrastructure for backend simplification in subsequent patches. Review discussion from prior iterations has been incorporated, and the technical approach appears sound based on the thread's established consensus.
