Ref backend consolidation: peeled OID support

This is the 8th patch in Karthik Nayak's v3 series refactoring Git's reference backend infrastructure. The patch adds support for storing peeled object IDs in the `ref_update` struct, moving this functionality from individual backends (packed, reftable) to the shared refs layer.

The change introduces a new `REF_HAVE_PEELED` flag (1 << 15) and modifies `ref_transaction_add_update()` to handle peeled OIDs. Toon Claes confirmed through systematic analysis that the chosen bit value doesn't conflict with existing flags, though Karthik notes the flag space could use cleanup in future work.

The patch follows the series' pattern of careful technical work with thorough review - Toon caught a minor commit message grammar issue ("backend" -> "backends") which Karthik acknowledges. The implementation appears sound and ready for integration after this documentation fix, continuing the series' steady progress toward consolidating backend logic.
