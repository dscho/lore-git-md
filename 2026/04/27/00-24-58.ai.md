This is the second part of a two-patch series introducing memory optimizations for the new `--reverse=before` revision walk behavior. The patch implements a sliding window approach to reduce memory usage from O(N) to O(K) when using `--reverse=before` with `--max-count`, where K is the count limit.

The optimization works by maintaining two queues (`into_queue` and `outo_queue`) that act as a sliding window over the commit history. As commits are processed, older ones beyond the count limit are discarded, keeping only the most recent K commits. The implementation maintains the same O(N) time complexity while significantly reducing memory usage for large histories.

Key technical points:
- The new `retrieve_with_window()` function implements the sliding window logic
- When `--reverse=before` and `--max-count` are both active, this function is used instead of storing all commits
- The optimization preserves all existing behavior while being more memory efficient
- The patch builds on the state machine approach from part 1 of the series

This completes the technical implementation of the feature, with both the core functionality (part 1) and memory optimization (part 2) now stable after four iterations.
