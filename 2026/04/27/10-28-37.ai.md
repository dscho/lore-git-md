This is a feature patch (v3) from Pablo Sabater that fixes misleading graph rendering in `git log --graph` when displaying commits with excluded parents (including root commits). The patch builds on previous RFC and v2 discussions, now awaiting final review.

The core issue is that Git's current graph output vertically aligns unrelated commit lineages when parent commits are excluded from display, creating false visual connections. The solution introduces a placeholder mechanism that keeps parentless commits "alive" for an extra row via an `is_placeholder` flag in graph columns, forcing proper indentation of subsequent commits. This handles both true root commits and commits with parents outside the displayed range uniformly through a "seems_root" concept.

The implementation modifies graph.c (rendering logic) and graph.h (new flag), with comprehensive test cases added to t4215-log-skewed-merges.sh demonstrating improved output for multiple scenarios. V3 maintains all improvements from v2 while adding minor documentation clarifications about the placeholder mechanism's behavior. The author notes some remaining visual quirks in diagonal line rendering between distant columns but suggests addressing those in follow-up work.

Changes from v2 include removing trailing whitespace, adding more explanatory comments, renaming `is_root` to `is_parentless` for consistency, and simplifying the cover letter's ASCII graphs. The test coverage remains thorough, now with additional comments explaining edge cases.
