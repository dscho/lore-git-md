This is the third and final patch in a series introducing the `git history fixup` subcommand, part of Patrick Steinhardt's ongoing work on the experimental `git history` command. The subcommand allows amending staged changes to an existing commit while automatically rebasing dependent branches - similar to `git commit --fixup` followed by `git rebase --autosquash`, but in a single operation.

The implementation performs a three-way merge between HEAD's tree (as base), the target commit's tree (as "ours"), and the staged changes (as "theirs"). It preserves the original commit message and authorship by default, though `--reedit-message` allows modifying the message. The command includes extensive test coverage (680+ lines) and handles edge cases like empty commits via `--empty=(drop|keep|abort)` options.

Key limitations noted:
- Doesn't work in bare repositories (requires index)
- Aborts on merge conflicts rather than resolving them
- Cannot drop root commits when they become empty

The patch builds on infrastructure from the first two patches in the series (generalized empty commit handling and refactored tree-commit functionality). Documentation has been refined through three versions to better explain the behavior by comparing it to familiar rebase workflows while maintaining technical accuracy about the three-way merge implementation.

Given Patrick's track record with the history command and the clear motivation, this appears production-ready aside from the noted conflict resolution limitation. The automatic rebasing of dependent branches is the most notable aspect that may warrant discussion about edge cases and user expectations.
