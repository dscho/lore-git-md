This is a feature patch in Christian Couder's series enhancing Git's promisor remote functionality with URL-based auto-configuration. It builds on the previous LOP (Large Object Promisors) work and is now at version 2 (6/8 in the series).

The patch introduces URL pattern matching to allow trusted updates to known remotes even when the default secure setting (`promisor.acceptFromServer=none`) would normally reject them. This enables scenarios like authentication token refreshes for pre-configured remotes while maintaining security.

Key technical aspects:
- Adds `url_matches_accept_list()` helper for component-wise URL matching (exact scheme/port, wildmatch for host/path)
- Modifies `should_accept_remote()` to check URL patterns when `accept==ACCEPT_NONE`
- Includes comprehensive tests showing allowlist behavior with various URL patterns
- Documents security considerations and matching rules in detail

The implementation is careful about security - URL normalization prevents bypass attempts, and host matching uses WM_PATHNAME to prevent wildcards crossing boundaries. The documentation provides clear warnings about dangerous patterns.

This patch appears well-structured and builds logically on the series' foundation. It has received positive reviews from Patrick Steinhardt and Junio. The security-conscious design and thorough testing suggest it's ready for merging after any final minor refinements.
