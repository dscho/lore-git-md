This is the final implementation of a feature adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The patch from Usman Akinyemi has gone through multiple review rounds with maintainer Junio Hamano and appears ready for merging.

The key behavior enables pushing to all remotes in a configured group (via `remotes.<name>`) with a single command like `git push all-remotes`. Each remote is pushed to in sequence via separate `git push` subprocesses, ensuring failures in one push don't affect others. The implementation carefully handles per-remote configurations and mirror settings while maintaining the same semantics as individual pushes.

Notable aspects:
- Explicitly does not support `--atomic` for group pushes (since atomicity can't be guaranteed across remotes)
- Preserves all existing push behaviors and configurations when used with single remotes
- Includes comprehensive test coverage verifying error handling, mirror detection, and push continuation after failures
- Documents the feature thoroughly in git-push.txt with clear examples and limitations

The implementation follows Junio's guidance to use process isolation for failure handling and shares group resolution logic between fetch and push commands. This appears to be a well-considered addition that provides useful symmetry with existing fetch capabilities while maintaining Git's push semantics.
