This is the second patch in Patrick Steinhardt's v3 series introducing the `git history fixup` subcommand, focused on refactoring internal commit functionality. The patch generalizes `commit_tree_with_edited_message_ext()` into a more flexible `commit_tree_ext()` function that accepts a flags parameter. The key change is making message editing optional via a new `COMMIT_TREE_EDIT_MESSAGE` flag, while preserving all other functionality like parent handling and header stripping. This refactoring supports the upcoming `fixup` subcommand implementation in patch 3, which will need to commit trees without modifying messages. The changes are mechanical and well-contained, touching only `builtin/history.c` with straightforward logic for the flag handling. The patch maintains existing behavior when the edit flag is set, ensuring no regression for current callers. As part of a larger series with thorough test coverage (680+ lines in t3453-history-fixup.sh), this infrastructure change appears solid and purpose-built for its role in enabling the automatic rebasing functionality of the new subcommand.
