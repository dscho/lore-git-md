This is the second part of a two-patch series introducing memory optimizations for the new `--reverse=before` revision walk behavior. The patch implements a sliding window approach to reduce memory usage when using `--reverse=before` with `--max-count`.

The optimization changes the space complexity from O(N) (storing all commits) to O(K) (storing only the K most recent commits needed for the final output), where K is the `--max-count` value. The implementation uses two queues (`into_queue` and `outo_queue`) to manage the sliding window while maintaining the same O(N) time complexity through amortized O(1) queue operations.

The patch builds on the core functionality introduced in part 1/2, which added the `--reverse=before` option itself. This optimization was previewed in earlier versions of the series and has now been cleaned up and finalized based on review feedback. The implementation appears technically sound and addresses the memory usage concerns raised during earlier discussion rounds.

With both parts of the series now stable after four iterations and all substantive feedback addressed, this appears ready for maintainer consideration. The only remaining open item is Junio C Hamano's conceptual review of the high-level approach.
