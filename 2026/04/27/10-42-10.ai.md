This is the final patch in Karthik Nayak's v3 series refactoring Git's reference backend code. The patch builds on the previous changes that moved object validation and peeling logic into the shared refs layer.

The key change here is modifying the packed and reftable backends to use the pre-peeled tag values that are now provided through the `ref_update` structure (added in patch 8/9) rather than performing their own peeling operations. This eliminates duplicate peeling work and ensures consistent behavior across backends.

The patch removes the direct calls to `peel_object()` in both backends, instead checking the `REF_HAVE_PEELED` flag and using the `peeled` field from the update structure when available. This is a mechanical change that follows through on the architectural direction established earlier in the series.

The changes are straightforward:
- In packed-backend.c, replaces local peeling with use of the pre-peeled value
- In reftable-backend.c, similarly uses the pre-peeled value and removes the now-unneeded object.h include
- Maintains all existing behavior while simplifying the backend implementations

This completes the series' goal of centralizing object validation and peeling logic. The patch has already received architectural approval from Patrick Steinhardt and implementation review from Toon Claes in earlier iterations, with no new technical concerns raised. The series appears ready for final maintainer review.
