This is part 2/9 of Karthik Nayak's refactoring series to standardize ref backend initialization. The patch introduces a new `ref_store_init_options` struct to consolidate backend configuration parameters, starting with the access flags.

The change is mechanical but foundational - it creates a structure that will allow future extension of backend configuration without changing function signatures repeatedly. The patch updates all three ref implementations (files, packed, reftable) to use the new options struct while maintaining identical behavior.

Key technical details:
- New `struct ref_store_init_options` in refs-internal.h holds backend-agnostic config
- Currently only contains `access_flags` but designed for future expansion
- All backend `init()` functions updated to take options pointer rather than raw flags
- Follow-up patch will add reflog configuration to this structure

The change is part of the broader effort to reduce backend-specific code by moving common functionality into the shared refs layer. Review discussion on prior versions (notably with Patrick Steinhardt and Toon Claes) has already validated the architectural approach, leaving this as a straightforward implementation of the agreed design.
