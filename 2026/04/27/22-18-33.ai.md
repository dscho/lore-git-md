This is the first patch in a two-part bugfix series addressing a regression in commit signing for non-UTF-8 messages. The patch renames `verify_utf8()` to `ensure_utf8()` in commit.c to better reflect its actual behavior - the function doesn't just validate UTF-8 but also transcodes non-UTF-8 text to UTF-8 when needed. 

The change is part of fixing a regression introduced in Git 2.45.0 where commit signatures were generated before UTF-8 validation/transcoding, causing mismatches between signed content and stored content. The renaming clarifies the function's purpose while maintaining identical behavior, setting up for the actual fix in patch 2/2 which will reorder operations to match pre-2.45.0 behavior.

The patch is straightforward with minimal risk, touching only the function name and its call sites. It follows the thread's established context where Elijah Newren identified issues with duplicate warning messages that will be addressed in the second patch. The series has already received substantive review and appears to be converging toward a solution.
