This is patch 4/9 in Karthik Nayak's v3 series refactoring Git's reference backend validation logic. The patch modifies `ref_transaction_update()` to return an `enum ref_transaction_error` instead of a simple `-1` for errors, preparing the ground for more specific error reporting in subsequent patches.

The change is mechanical - existing error cases now return `REF_TRANSACTION_ERROR_GENERIC` rather than `-1`, maintaining identical behavior while establishing the infrastructure for future error classification. The patch affects both the implementation in `refs.c` and the function declaration in `refs.h`.

This continues the series' goal of standardizing error handling across ref backends, with Patrick Steinhardt and Toon Claes having already reviewed and approved the technical approach in earlier iterations. The change is straightforward and uncontroversial, representing an incremental step toward the series' goal of moving validation logic into the shared refs layer.
