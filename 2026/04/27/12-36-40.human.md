Performance optimization discussion for `index-pack` buffer sizing.

Derrick Stolee joins the thread about increasing I/O sizes in `index-pack` and `unpack-objects`, building on Junio's earlier review. He agrees with the idea of centralizing the 128KB buffer constant but raises a more fundamental question about the performance measurement approach.

Stolee suggests reframing the analysis to focus on "number of writes not using the whole buffer" (essentially flush events) rather than just counting system calls. He notes this metric would better isolate the true source of improvement - reduced flush frequency due to larger buffers. More importantly, he asks for end-to-end timing measurements to validate whether the reduced system calls actually translate to observable speedups in real-world scenarios, proposing to use the existing `t/perf/` framework across multiple repository sizes.

This moves the discussion from implementation details to practical impact, suggesting the next step should be empirical performance testing rather than further buffer size adjustments. The exchange remains technical and constructive, with Stolee's perspective complementing Junio's earlier review by focusing on measurable outcomes.
