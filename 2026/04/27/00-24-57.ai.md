This is the first patch in a two-part series implementing a new `--reverse=before` option for revision walks, allowing commits to be reversed before applying limiting operations like `--max-count`. The patch introduces the core functionality while maintaining backward compatibility with existing `--reverse=after` behavior.

Key technical changes:
- Adds `enum rev_reverse` to `revision.h` with states: `NO_REVERSE`, `REVERSE_AFTER`, and `REVERSE_BEFORE`
- Modifies `get_revision()` to handle the new reversal timing via a two-stage output process
- Updates documentation to explain the new toggle behavior and historical quirks
- Adds comprehensive tests covering all combinations of reversal modes and toggling

The implementation follows Jeff King's suggested state machine approach from earlier discussion rounds. The patch appears well-tested with clear edge case coverage (negative numbers, multiple toggles) and maintains the existing behavior where expected. The documentation cleanly explains both the new functionality and historical behavior of `--reverse --reverse` cancellation.

This represents the stable core of the feature after four iterations of review, with all substantive technical feedback addressed. The companion patch (2/2) provides the memory efficiency optimization for this feature.
