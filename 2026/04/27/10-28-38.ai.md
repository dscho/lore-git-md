This is the implementation patch (v3) from Pablo Sabater that improves `git log --graph` rendering for commits with excluded parents, including root commits. The patch builds on previous RFC and v2 discussions, now awaiting final review before potential merging.

The core issue addresses misleading vertical alignment in graph output when displaying commits whose parents aren't shown (either true root commits or commits with parents outside the displayed range). The current behavior creates false visual connections between unrelated commit lineages. The solution introduces a placeholder mechanism via an `is_placeholder` flag in graph columns, keeping parentless commits "alive" for an extra row to force proper indentation of subsequent commits.

Key technical changes:
- Adds `is_placeholder` flag to struct column in graph.h
- Modifies graph.c rendering logic to handle placeholders
- Distinguishes between true root commits and boundary commits
- Includes comprehensive test cases in t4215-log-skewed-merges.sh covering:
  - Simple root commits
  - Multiple root commits
  - Merges with 2-4 parents
  - Cascading indentation
  - Excluded non-root parents

The v3 iteration incorporates all prior feedback, including:
- Renamed `is_root` to `is_parentless` for clarity
- Added detailed comments explaining the placeholder mechanism
- Removed trailing whitespace
- Simplified ASCII graphs in the cover letter
- Maintained thorough test coverage with added edge case explanations
