This is version 3 of a patch series introducing a `git history fixup` subcommand, part of Patrick Steinhardt's ongoing work on the experimental `git history` command. The series builds on commit 94f057755b from April 2026.

The new subcommand allows amending staged changes to an existing commit (similar to `git commit --fixup`) while automatically rebasing dependent branches - a workflow Patrick reports using frequently. The implementation currently aborts on merge conflicts, with plans to improve conflict handling when Git gains first-class conflict resolution capabilities.

Key changes in v3 focus on documentation improvements, particularly the description of how changes are applied. The new text now compares the behavior to the familiar `git commit --fixup` + `git rebase --autosquash` workflow while still explaining the underlying three-way merge mechanism. The series remains well-structured with thorough test coverage (680+ lines of tests).

The implementation handles empty commits through new infrastructure (patch 1) and refactors internal tree-commit functionality (patch 2) before introducing the actual `fixup` subcommand (patch 3). While the automatic rebasing of dependent branches is a useful feature, reviewers may want to examine edge cases around branch dependency tracking.
