This is the first patch in a two-part bugfix series addressing a commit signing regression for non-UTF-8 messages introduced in Git 2.45.0. The regression caused signatures to be generated before UTF-8 validation/transcoding, leading to mismatches between signed content and stored content.

The patch renames `verify_utf8()` to `ensure_utf8()` in commit.c` to more accurately reflect the function's behavior - it doesn't just validate UTF-8, but also modifies the buffer by transcoding non-UTF-8 characters to UTF-8. This is a preparatory change for the actual fix in the second patch, which will restore the pre-2.45.0 where signatures remain valid for non-UTF-8 messages.

The change is straightforward and uncontroversial, just updating the function name and its documentation to better describe what it actually does. The patch is part of a well-motivated series addressing a real regression that affects all signature types (GnuPG/SSH/X.509) when dealing with non-ASCII commit messages.
