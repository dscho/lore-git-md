This is patch 3/9 in a refactoring series that standardizes reflog configuration handling in Git's reference backends. The patch moves the logic for determining when to create reflog entries (controlled by `core.logallrefupdates`) from the shared refs layer down into the individual backend implementations.

The key change is adding a `log_all_ref_updates` field to the new `ref_store_init_options` struct introduced in patch 2/9. This allows the generic refs layer to handle the configuration lookup once and pass the value down to all backends (files, packed, and reftable) rather than having each backend query it separately.

The implementation is clean and mechanical - it removes duplicate configuration lookups while maintaining identical behavior. This continues the series' broader goal of consolidating backend-specific logic into shared infrastructure, following the architectural direction established in earlier review rounds with Patrick Steinhardt and Toon Claes.

As with the rest of the series, this change is well-motivated and appears ready for integration, having addressed all substantive feedback from prior versions. The patch touches multiple backend implementations but makes only straightforward, focused changes to each.
