This is the first patch in a 3-part series introducing the `git history fixup` subcommand, focusing on infrastructure changes needed to support the new command. The patch generalizes empty commit handling in Git's replay subsystem, which will be used by the upcoming `fixup` subcommand.

The change introduces a new `enum replay_empty_commit_action` with three options for handling commits that become empty during replay operations:
- `REPLAY_EMPTY_COMMIT_DROP` (default): Silently discard empty commits
- `REPLAY_EMPTY_COMMIT_KEEP`: Preserve empty commits
- `REPLAY_EMPTY_COMMIT_ABORT`: Treat empty commits as errors

The implementation modifies `pick_regular_commit()` to respect this new option and updates the `replay_revisions_options` struct to include it. The patch appears well-structured with clear documentation of the new enum and its usage. This foundational change enables more flexible handling of empty commits, which will be important for the `fixup` functionality where users may want different behaviors when their changes result in empty commits.

The patch follows Git's coding style and includes appropriate error handling. As the first in a series, it sets up infrastructure that the subsequent patches will build upon, particularly for the automatic rebasing behavior of `git history fixup`.
