This is the cover letter for v3 of a refactoring series that moves object validation and peeling logic from individual ref backends into Git's shared refs layer. The series comes from Karthik Nayak, who has been actively working on ref-related subsystems.

The key changes in this version address feedback from Patrick Steinhardt and Toon Claes on the error handling approach and implementation details. Notable updates include:

1. Simplified error classification in update-ref (Patch 6) by adopting Toon's suggestion to handle generic errors first with an explanatory comment
2. Clarified the NULL pointer safety requirements in object validation (Patch 7)
3. Confirmed availability of the peeled OID flag bit (Patch 8) through systematic analysis by Toon
4. Added commit message notes about error message ordering changes
5. Fixed various typos and grammar issues

The series continues the broader effort to consolidate backend-specific logic into the generic layer, specifically targeting:
- Moving object validation earlier in the transaction flow
- Standardizing peeled tag handling across backends
- Extracting reflog configuration to shared code

Review discussion has been substantive, with Patrick providing architectural oversight and Toon engaging deeply on implementation details. The technical questions raised in v2 have largely been resolved, leaving only minor documentation fixes outstanding. The changes are mechanical but wide-ranging, affecting how ref updates are validated throughout the system.

For future thread context: this series standardizes object validation and peeling across ref backends by moving logic from files-backend.c, packed-backend.c, and reftable-backend.c into refs.c. Key structures modified include `ref_update` (new `peeled` field) and `ref_transaction`. The changes affect how update-ref and receive-pack validate ref updates before passing them to the backends.
