This is a refactoring series (v3, 9 patches) from Karthik Nayak that continues the ongoing effort to consolidate reference backend logic in Git. The key goal is to move object validation and peeling operations from individual backends (files, packed, reftable) into the shared refs layer, ensuring consistent behavior across implementations.

The series builds on prior work standardizing ref backend interfaces, with notable changes including:
- Moving commit object validation earlier in the ref update process via `ref_transaction_update()`
- Adding peeled OID support to the `ref_update` struct to optimize tag handling
- Extracting reflog configuration to the generic layer
- Improving error handling in `update-ref` to better distinguish between recoverable and fatal errors

Review discussion has been substantive, with Patrick Steinhardt providing architectural oversight and Toon Claes contributing detailed implementation feedback. Key technical points resolved in v3 include:
- Confirmation that the new `REF_HAVE_PEELED` flag (1 << 15) is safely available
- Clarification around NULL pointer safety in object validation
- Adoption of a simpler error classification approach for `update-ref`

The changes are mechanical but wide-ranging, touching `update-ref`, `receive-pack`, and all three ref backends. While the series doesn't introduce user-visible changes, it significantly cleans up the backend implementation landscape and paves the way for future ref-related work. The patches appear well-tested and the discussion shows careful consideration of edge cases.
