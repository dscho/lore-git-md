This is a feature patch in Christian Couder's series adding URL-based auto-configuration for promisor remotes. It introduces the core `promisor.acceptFromServerUrl` config option that will allow clients to automatically configure promisor remotes based on URL patterns.

The patch adds infrastructure to:
- Parse and validate URL patterns from the new config option
- Handle optional remote name prefixes (e.g. "cdn=https://example.com/*")
- Store the parsed patterns for later matching against advertised remotes
- Reject invalid patterns with clear warning messages

Key technical details:
- Uses a new `allowed_url` struct to store parsed patterns and optional remote names
- Adds validation for remote names and URL patterns (rejecting control characters)
- Introduces test cases for invalid configurations
- Builds on existing URL matching infrastructure from `urlmatch.[ch]`

The implementation appears thorough, with careful attention to security (rejecting invalid patterns) and clear error messaging. This is part of a larger effort to make promisor remotes more flexible while maintaining security - the actual URL matching logic will come in a follow-up patch.

The patch has already received positive feedback from Patrick Steinhardt and Junio Hamano in previous iterations, suggesting it's on track for merging. The test case demonstrates the validation working as expected by rejecting a remote name with spaces.
