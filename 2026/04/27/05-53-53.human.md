This is the third and final patch in Patrick Steinhardt's series introducing a `git history fixup` subcommand, part of the experimental `git history` command effort. The subcommand allows amending staged changes to an existing commit (similar to `git commit --fixup`) while automatically rebasing dependent branches - a workflow improvement that addresses a common pain point.

The implementation performs a three-way merge using HEAD's tree as the base, preserving the original commit message and authorship by default. It includes comprehensive test coverage (680+ lines) and handles several edge cases:

- Empty commits can be configured to drop, keep, or abort via `--empty` flag
- Updates all descendant branches by default (configurable with `--update-refs`)
- Preserves unstaged working tree changes
- Aborts cleanly on merge conflicts (a current limitation)

The documentation has been refined through three versions to better explain the behavior by comparing it to the familiar `git commit --fixup` + `git rebase --autosquash` workflow, while maintaining technical accuracy about the three-way merge implementation.

This appears production-ready aside from the noted conflict resolution limitation, which the commit message indicates will be addressed when Git gains first-class conflict handling. Given Patrick's track record with the history command and the clear motivation, this seems likely to progress smoothly through review.
