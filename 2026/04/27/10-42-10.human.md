This is the final patch in Karthik Nayak's v3 series refactoring Git's reference backend code. The series standardizes object validation and peeling logic across different ref backends (files, packed, reftable) by moving these operations into the shared refs layer.

The current patch modifies the packed and reftable backends to use the peeled tag values that are now provided by the generic layer (introduced in patch 8/9) rather than performing their own peeling operations. This eliminates duplicate peeling work and ensures consistent behavior across backends.

Key technical changes:
- Removes direct calls to `peel_object()` from both backends
- Uses the new `peeled` field in `ref_update` (set by the generic layer) when available
- Simplifies both backend implementations by removing redundant code
- Maintains the same optimized behavior where peeled values avoid ODB lookups

The patch builds on the architectural work approved in earlier iterations, with Patrick Steinhardt providing oversight and Toon Claes verifying implementation details. All substantive feedback from previous versions has been addressed, leaving this as a clean mechanical change that completes the series' goal of consolidating backend logic.

This represents the culmination of a well-structured effort to standardize ref handling across Git's storage backends, with the series now ready for final maintainer review.
