Performance optimization patch for `index-pack` and `unpack-objects` I/O efficiency, version 3.

Scott Bauersfeld's third iteration of this patch series addresses Derrick Stolee's naming feedback from v2 by renaming the shared constant from `DEFAULT_PACKFILE_BUFFER_SIZE` to `DEFAULT_IO_BUFFER_SIZE`, better reflecting its broader usage beyond just packfile operations. The change maintains the core performance improvement - increasing the input buffer size from 4KB to 128KB to reduce system call overhead, particularly beneficial for FUSE filesystems where small writes incur significant latency.

The patch includes detailed performance measurements showing 10-11% faster clones on FUSE (75.7s vs 84.5s for vscode repo, 20.0s vs 22.6s for git/git) and 65% fewer pack file writes. The implementation now properly centralizes the buffer size definition in `git-compat-util.h` while preserving the measured performance gains. The commit message has been further refined to document the constant rename and clarify that the previously suggested `WRITE_BUFFER_SIZE` consolidation is no longer relevant since that constant was removed in a 2021 commit.

This appears to be the final iteration of this optimization, having addressed all substantive feedback from Junio Hamano and Derrick Stolee. The changes are straightforward and well-validated by performance testing, making this patch series likely ready for merging.
