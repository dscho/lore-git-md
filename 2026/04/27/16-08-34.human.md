Performance optimization for `index-pack` and `unpack-objects` I/O efficiency. This v2 patch from Scott Bauersfeld follows up on earlier discussion with Junio C Hamano and Derrick Stolee about buffer size handling.

The key change increases the input buffer size from 4KB to 128KB in both commands to reduce system call overhead, particularly beneficial for FUSE filesystems where small writes incur significant latency. The implementation now centralizes the buffer size as `DEFAULT_PACKFILE_BUFFER_SIZE` in git-compat-util.h, matching the existing 128KB size used by Git's hashfile layer.

New in v2 are wall-clock timing measurements showing 10-11% faster clones on FUSE filesystems, along with the buffer size standardization. The patch maintains all the performance benefits shown in v1 - 65% fewer pack file writes and elimination of all 4KB writes during HTTPS clones of the git/git repository (~296MB pack).

The changes appear well-considered, addressing Junio's suggestion to centralize the buffer size constant while adding the requested real-world timing data. The performance impact is clearly demonstrated across both micro (syscall counts) and macro (clone times) metrics. This looks ready for inclusion pending any final review comments.
