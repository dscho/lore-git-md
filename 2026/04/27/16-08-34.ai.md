Performance optimization patch for `index-pack` and `unpack-objects` I/O efficiency, version 2.

Scott Bauersfeld's updated patch addresses feedback from Junio Hamano and Derrick Stolee on the initial version. The key change is introducing a shared `DEFAULT_PACKFILE_BUFFER_SIZE` constant (128KB) in `git-compat-util.h` rather than using file-local defines, making the buffer size consistent across `index-pack`, `unpack-objects`, and the hashfile layer in `csum-file.c`.

The patch maintains the core performance improvement - reducing system call overhead by increasing the input buffer from 4KB to 128KB, particularly beneficial for FUSE filesystems where small writes incur significant latency. New in v2 are wall-clock timing measurements showing 10-11% faster clones on FUSE (75.7s vs 84.5s for vscode repo, 20.0s vs 22.6s for git/git).

The implementation now properly centralizes the buffer size definition while preserving the measured performance gains. The commit message has been refined to better explain the changes and include the new timing data. This appears ready for merging pending any final review comments about the centralized constant placement.
