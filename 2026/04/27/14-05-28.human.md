This is the fourth version of a feature patch series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The series from Usman Akinyemi has progressed through multiple review rounds with maintainer Junio Hamano and appears functionally complete.

The key change in v4 is switching to using child processes for each remote push in a group, ensuring failures in one push don't affect others. This addresses earlier concerns about failure isolation. The implementation now spawns separate `git push` subprocesses for each remote in the group, with the parent process aggregating results.

The documentation has been updated to clarify that:
- Each remote in the group gets its own subprocess with identical flags/refspecs
- `--atomic` is explicitly rejected for group pushes (since atomicity can't be guaranteed across remotes)
- All failures (both push rejections and connection errors) are reported but don't stop subsequent pushes

Test coverage has been expanded to verify the new behavior, including:
- Explicit rejection of `--atomic` with groups
- Confirmation that connection errors don't stop remaining pushes
- Verification that per-remote configurations (like mirror settings) are properly isolated

The series appears ready for merging with all architectural decisions settled and comprehensive test coverage. The implementation cleanly handles both single-remote and group cases while maintaining identical behavior to sequential individual pushes. Parallel push support remains a potential future enhancement.
