This is a refactoring patch in Christian Couder's URL-based promisor remote auto-configuration series. It introduces a new helper function `url_normalize_pattern()` that extends the existing URL normalization logic to handle glob patterns (`*`) in hostnames, which will be used for matching promisor remote URLs.

The patch adds the new function to both `urlmatch.c` and `urlmatch.h`, with thorough documentation explaining its purpose and behavior. The key differences from `url_normalize()` are:
- Explicitly allows `*` characters in host portions (while still maintaining other URL validation rules)
- Maintains the same interface and memory ownership semantics as the original function
- Includes detailed header comments about RFC 3986 compliance for path handling

This is a preparatory change for the series' core functionality that will use URL patterns to auto-configure promisor remotes. The implementation is clean and focused, with the boolean `allow_globs` parameter (recently refactored from `char` to `bool` in a previous patch) being passed through to the internal normalization logic.

The patch fits well within the series' progression and maintains the security-conscious approach seen in other parts of the work, particularly around URL handling and pattern matching.
