Performance optimization for `index-pack` and `unpack-objects` I/O efficiency.

Derrick Stolee provides a substantive review of Scott Bauersfeld's v2 patch that increases input buffer sizes from 4KB to 128KB. While approving the core changes, Stolee raises an interesting historical point about the 128KB value - it matches an existing buffer size constant (`WRITE_BUFFER_SIZE` in read-cache.c) used for index files. This prompts him to question whether the new `DEFAULT_PACKFILE_BUFFER_SIZE` name is too narrow, suggesting alternatives like `DEFAULT_HASHFILE_BUFFER_SIZE` that would better reflect its broader potential usage.

Stolee confirms the patch's technical correctness and notes the impressive 10-11% performance improvements on FUSE filesystems shown in the benchmarks. His review digs into Git's history to trace the origin of the 128KB value, revealing it was originally introduced in his own 2021 commit for index file writing. This historical context adds weight to his naming suggestion while not blocking the current changes.

The review maintains a positive tone about the patch's merits while thoughtfully considering how the naming choice might affect future code maintenance. Stolee's deep familiarity with Git's I/O subsystems allows him to spot this subtle naming opportunity that wasn't apparent in earlier reviews. His feedback suggests the patch is technically sound but could benefit from considering the constant's name in relation to other similar buffer sizes in the codebase.
