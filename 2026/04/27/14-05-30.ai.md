This is the second patch in a feature series adding remote group support to `git push`, mirroring the existing `git fetch` functionality. The patch implements the core group push behavior by spawning separate `git push` subprocesses for each remote in the configured group.

The key technical aspects are:
- Uses `run_command()` to isolate each remote's push operation
- Rebuilds refspec lists per-remote to handle `remote.<name>.push` configs
- Preserves mirror flag isolation (mirror remotes don't affect others in group)
- Explicitly rejects `--atomic` for group pushes
- Accumulates failures via bitwise OR of exit codes
- Includes comprehensive tests covering success/failure cases

- Each remote is pushed independently with its own config
- Failures don't stop subsequent pushes
- `--atomic` is incompatible with groups
- Mirror flags don't "bleed" between remotes
