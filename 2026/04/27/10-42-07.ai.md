This is patch 6/9 in Karthik Nayak's v3 series refactoring Git's reference backend validation logic. The patch modifies `builtin/update-ref.c` to handle reference update rejections that occur during the transaction preparation phase, not just during commit.

The key changes:
- Introduces a `command_options` struct to track whether individual update failures should be allowed (controlled by `--batch-updates` flag)
- Modifies all command parsers to accept this options struct
- Changes error handling works in `parse_cmd_update()` and `parse_cmd_symref_update()` to distinguish between generic errors (which abort the transaction) and specific rejections (which can be skipped in batch mode)
- Preserves the existing behavior where rejected updates are shown to users immediately rather than waiting for transaction commit

The patch maintains backward compatibility while preparing for future changes that will move more validation into `ref_transaction_update()`. The error message ordering will change slightly (validation errors will appear earlier), but the functionality remains equivalent.

This is a well-contained change that follows the series' architectural direction. The implementation is cleanly separated from the validation logic changes coming in subsequent patches, and the diff shows careful attention to error handling edge cases.
