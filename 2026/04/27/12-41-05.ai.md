This is a feature patch in Christian Couder's URL-based promisor remote auto-configuration series (v2 5/8). It introduces the core `promisor.acceptFromServerUrl` config option that allows clients to automatically configure promisor remotes based on URL patterns.

The patch adds infrastructure to:
1. Parse and validate URL patterns with optional remote name prefixes (e.g. "cdn=https://example.com/*")
2. Store validated patterns in a new `struct allowed_url` containing both the pattern and parsed URL components
3. Load these patterns from config into a string list for later matching
4. Include basic test coverage showing invalid patterns are rejected

Key technical details:
- Uses `urlmatch.[ch]` infrastructure for URL parsing/validation
- Implements strict validation for remote names and URL patterns
- Stores original advertised names separately from auto-generated names
- Adds test case verifying invalid patterns trigger warnings without creating remotes

The implementation is security-conscious, rejecting patterns with control characters and validating remote names before the equals sign. This is a foundational patch for the series' main functionality - the actual URL matching and remote creation will come in subsequent patches.

The patch builds on the existing promisor-remote infrastructure and aligns with the series' goal of reducing manual remote configuration while maintaining security. It has received positive reviews from Patrick Steinhardt and Junio Hamano in previous iterations.
