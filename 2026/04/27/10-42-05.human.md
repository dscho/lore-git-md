This is patch 4/9 in a series refactoring Git's reference backend validation logic. The patch changes `ref_transaction_update()` to return an explicit error enum (`ref_transaction_error`) rather than just -1, preparing for more detailed error handling in future changes.

The change is mechanical - existing error cases now return `REF_TRANSACTION_ERROR_GENERIC` instead of -1, maintaining the same behavior while setting up the infrastructure for more specific error reporting later. The patch affects both the implementation in refs.c and the function declaration in refs.h.

This is part of Karthik Nayak's ongoing effort to standardize ref backend behavior by moving validation logic into the generic refs layer. The series has already received substantive review from Patrick Steinhardt and Toon Claes, with all major technical points resolved in prior iterations. This particular patch appears straightforward and uncontroversial, just laying groundwork for the more significant validation changes coming in later patches.
