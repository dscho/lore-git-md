This is patch 7/9 in Karthik Nayak's v3 series refactoring Git's reference backend validation logic. The patch moves object ID validation from individual backends (files and reftable) into the generic refs layer, specifically into `ref_transaction_update()`.

Key changes:
1. Object existence checking via `parse_object()` is now performed when updates are queued rather than during transaction preparation
2. The `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type is removed as validation now happens earlier
3. `receive-pack` is updated to properly propagate the specific error type to clients
4. Backend-specific validation code is removed from both files and reftable implementations

The change makes validation behavior more consistent across backends and moves it earlier in the process. The patch maintains backward compatibility while eliminating duplicate validation logic. It builds on the error handling standardization introduced in patch 4/9 of the series.

Technical details:
- Validation now checks for both object existence and branch ref type constraints
- The `REF_SKIP_OID_VERIFICATION` flag is still respected
- Error messages remain consistent with previous behavior
- Test changes reflect the earlier validation timing

This continues the series' goal of consolidating backend logic while maintaining the same external behavior. The changes are mechanical but touch core ref transaction handling.
