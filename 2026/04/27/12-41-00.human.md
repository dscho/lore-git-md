This is a feature patch series that enhances Git's promisor remote functionality by introducing URL-based allowlisting for auto-configuring remotes. The series builds on the previous LOP (Large Object Promisors) work and is now at version 2 (down from 16 patches in v1 after some preparatory work was merged separately).

The key addition is a new `promisor.acceptFromServerUrl` config option that allows organizations to specify URL patterns (like "https://my-org.com/*") from which Git can automatically configure promisor remotes. This reduces the manual configuration burden while maintaining security through careful URL matching and name sanitization.

The implementation includes:
- URL pattern validation and normalization
- Component-wise matching (scheme/port must match exactly, host/path use wildcards)
- Auto-generated remote names with collision handling
- Documentation of security considerations
- Comprehensive test coverage

Security is a major focus, with protections against:
- URL normalization bypass attempts
- Remote name collisions/hijacking
- Overly broad patterns that could match malicious servers

The series has been reviewed by Patrick Steinhardt and Junio Hamano, with all feedback from v1 addressed. The changes are well-motivated and carefully implemented, with particular attention to security implications. The documentation clearly explains both the feature and its safe usage.

This appears ready for merging as it:
1) Solves a real configuration pain point
2) Maintains backward compatibility
3) Includes thorough security protections
4) Has been vetted through multiple iterations
5) Comes with comprehensive tests

The feature will be particularly useful for organizations using promisor remotes at scale, allowing them to centralize configuration while keeping tight control over which servers can auto-configure clients.
