This is a feature patch in Christian Couder's URL-based promisor remote auto-configuration series (v2 7/8). It implements automatic creation of remote configurations when a server advertises a promisor remote URL that matches an allowlist pattern.

The patch adds four key components:
1. `sanitize_remote_name()` - Converts URL-derived strings into valid remote names by replacing special chars with '-', collapsing runs, and prepending "promisor-auto-"
2. `promisor_remote_name_from_url()` - Normalizes URLs and extracts host+port+path to generate human-readable base names
3. `configure_auto_promisor_remote()` - Writes the remote.* settings to config
4. `handle_matching_allowed_url()` - Handles name collisions by appending numeric suffixes

The core logic in `should_accept_new_remote_url()` uses the existing `url_matches_accept_list()` helper to match patterns, then creates the remote configuration. The implementation includes comprehensive tests covering:
- Basic auto-creation
- Named pattern matching ("cdn=URL")
- Collision handling (appending "-1", "-2")
- Reuse of existing remotes with matching URLs

Security considerations are maintained through:
- URL pattern matching rules (exact scheme/port, host boundary constraints)
- Name sanitization
- Collision limits (MAX_REMOTES_WITH_SIMILAR_NAMES=20)
- Traceability via remote.<name>.advertisedAs

The documentation is updated to explain:
-creation rules
- Name prefix syntax
- Collision handling
- advertisedAs field purpose

This completes the core functionality of the URL-based auto-configuration system, building on the security foundations from earlier patches.
