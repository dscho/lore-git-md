This is a discussion thread about the proposed `--fetch` option for `git checkout`/`git switch`, with D. Ben Knoble chiming in to clarify a technical point about fetching specific branches.

Knoble points out that `git fetch origin main` can indeed fetch just a single branch (with the right refspec), addressing Harald Nordgren's uncertainty about whether partial fetching is possible. This directly relates to Junio Hamano's earlier concern about whether the feature should update unrelated remote-tracking branches from the same remote.

The exchange highlights the ongoing tension in the proposal between:
1. The convenience of automatically fetching the latest upstream state when creating a branch
2. The stability expectations around remote-tracking branches that many Git tools rely on

While Nordgren maintains that developers must eventually deal with upstream changes, Knoble's observation suggests there may be technical solutions to limit the scope of fetching - though it's unclear if this would satisfy the maintainer's broader workflow concerns.
