Maintainer pushes back on `--fetch` feature with design concerns.

Junio C Hamano, Git's maintainer, expresses strong reservations about the proposed `--fetch` option for `git checkout` and `git switch`. While acknowledging the workflow motivation, he fundamentally questions whether automatic fetching belongs in these commands at all. His core objection is that remote-tracking refs are used consistently across Git (in commands like `log`, `grep`, and `rev-list`), so special-casing checkout/switch would create an inconsistent model.

Junio suggests that if the feature were to proceed, it might need to be tied more closely to the `--track` functionality rather than being a standalone option, perhaps as a variant like `--track=fetch`. However, he makes clear his personal preference is to reject the change entirely, citing unaddressed usability questions - particularly around whether fetching should update all branches from a remote or just the one being checked out.

This feedback represents a veto threat from the maintainer, putting the feature's future in serious doubt. The author will need to either substantially rework the proposal to address these systemic concerns or abandon the approach. Junio's comments suggest the latter is more likely, as he views automatic fetching as potentially introducing more problems than it solves.
