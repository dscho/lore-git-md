This is a feature patch adding a `--set-head` option to `git remote add` that mirrors the behavior of `git clone` by automatically setting the remote's HEAD reference to point to its default branch. The change is motivated by improving integration with GitHub's `gh` tool, where fork remotes currently don't have their default branch recorded.

The patch:
1. Adds the new `--set-head` option that implies `--fetch` and runs `git remote set-head --auto` internally
2. Includes documentation updates explaining the new option
3. Adds test coverage verifying the behavior
4. Handles edge cases by making the option mutually exclusive with `-m` and push mirrors

The implementation is clean and follows existing patterns, with appropriate error handling and test coverage. The commit message clearly explains both the technical change and its practical motivation. This appears to be a well-scoped quality-of-life improvement that aligns with existing Git conventions.
