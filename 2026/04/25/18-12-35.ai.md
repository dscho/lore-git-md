Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This is the second version of a patch that aims to simplify the common workflow of fetching remote changes before creating a new branch. The key changes from v1 include:
- Renamed config from `checkout.autoFetch` to `checkout.fetch` to match the option name
- Updated commit message to better explain the problem (stale branch creation) before presenting the solution
- Added comprehensive documentation for both commands and config option
- Expanded test coverage to verify config-driven behavior and `git switch` integration

The implementation adds a new `fetch_remote_for_start_point()` function that handles the remote fetching logic when the start point references a remote branch. Tests demonstrate:
- Basic `--fetch` functionality with remote branch names
- Behavior with bare remote names (fetches default branch)
- Failure cases where fetch fails
- Config-driven auto-fetch behavior
- `git switch` compatibility

The patch appears well-constructed with clear commit messages and thorough test coverage. However, as noted in the thread context, there remains philosophical disagreement about whether this behavior belongs in Git's workflow model, particularly around whether automatic fetching violates the stability of remote-tracking branches. The maintainer has previously raised concerns about this approach, suggesting integration with `--track` behavior if implemented.

This version addresses the technical feedback from v1 but doesn't yet resolve the deeper design questions about remote ref handling consistency. The thread appears paused during the maintainer's vacation, with fundamental disagreements about workflow philosophy still outstanding.
