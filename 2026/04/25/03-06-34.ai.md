This is a response from Junio C Hamano (the Git maintainer) to Phillip Wood's review of the per-worktree ignore patterns proposal. Junio weighs in on the technical discussion with his perspective as maintainer.

Junio agrees with Phillip's skepticism about the need for per-worktree ignore patterns, noting that shared patterns across worktrees are generally more useful to avoid repetitive configuration. He endorses Phillip's point about using `git rev-parse --git-path` for correct path resolution rather than manual path construction.

While acknowledging there might be niche cases where per-worktree ignores could be useful (like his own atypical setup of storing unrelated histories in a single repository), Junio clearly states this isn't a recommended practice and shouldn't drive general-purpose functionality. His position suggests the feature may not be worth the complexity unless stronger use cases emerge.

The exchange highlights the maintainer's role in evaluating whether proposed features align with Git's design philosophy - here questioning whether the use case justifies the added complexity. Junio's response leans toward rejecting the current approach unless more compelling real-world needs are demonstrated.
