This is a follow-up discussion in the hierarchical aliases regression thread, where Jonatan Holmgren responds to Junio Hamano's design concerns about the alias system's future extensibility. The patch had already addressed the immediate regression where dotted aliases (like `pull.sub`) stopped working in Git 2.54.0.

Holmgren acknowledges the challenge of balancing backward compatibility with future extensibility. He suggests a compromise approach where only `command` and `alias-*` prefixes would be reserved for future alias attributes, as these are unlikely to conflict with existing user aliases. While he recognizes that a separate namespace (like `nalias`) would be cleaner from a technical perspective, he argues it from a user experience standpoint, noting that simple subsection aliases with just `command` will likely be more common than any future metadata attributes.

The discussion has shifted from the technical fix (which was already vetted by Jeff King and René Scharfe) to broader design considerations about how the alias system should evolve. Holmgren's response indicates he's weighing the tradeoffs between maintaining compatibility, keeping the UX clean, and leaving room for future features like alias help text or visibility attributes. This suggests the patch may need minor adjustments to its approach before final acceptance, though the core solution remains technically sound.
