This is the fourth patch in Johannes Schindelin's CI/build system update series, bumping the `actions/checkout` dependency from v5 to v6 across all GitHub Actions workflows. The change is mechanical but comes with a detailed analysis of the security and compatibility implications.

The key behavioral change in v6 moves credential storage from `.git/config` to `$RUNNER_TEMP`, which improves security by preventing accidental credential leakage through artifacts while requiring newer runner versions (v2.329.0+) for Docker container actions. Schindelin confirms this doesn't affect Git's CI since they use GitHub-hosted runners that already meet the version requirement, and their workflows don't rely on the credential storage mechanism.

The patch follows the series' pattern of thorough impact analysis, noting that Git's workflows either check out the default repository (no special credentials needed) or explicitly specify a repository path (vcpkg) that interacts with the API via `GITHUB_TOKEN` directly. The diff shows purely version number updates across all workflow files with no functional changes to the workflow logic.

This appears to be a low-risk maintenance update keeping CI infrastructure on supported versions while improving security posture. The analysis suggests downstream self-hosted runner users may need to update their runners before adopting this change.
