Feature patch adding a `--fetch` option to `git checkout` and `git switch` to automatically fetch remote refs before branch creation.

This is the second version of Harald Nordgren's patch to add a `--fetch` flag that fetches from the remote when creating a branch from a remote-tracking ref. The key changes from v1 are renaming the config from `checkout.autoFetch` to `checkout.fetch` for consistency with the flag name, improved commit message structure, and added documentation.

The implementation remains clean and well-tested, with new tests verifying:
- Basic `--fetch` functionality with remote branch names
- Behavior with bare remote names (fetches default branch)
- Failure cases where fetch fails
- Config-driven auto-fetch behavior
- Compatibility with both `git checkout` and `git switch`

However, this patch is part of an ongoing philosophical debate about whether automatic fetching violates Git's workflow principles. Maintainer Junio Hamano has previously raised objections about whether this behavior should be command-specific or apply more broadly across Git, suggesting integration with `--track` if implemented. The thread appears paused during Junio's vacation, so this v2 may not see immediate movement despite being technically sound.

For users who frequently create branches from remote refs, this would be a useful quality-of-life improvement to avoid stale checkouts. But its path forward depends on resolving the deeper design questions raised in the thread.
