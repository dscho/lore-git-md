Performance optimization follow-up from the maintainer. Junio C Hamano responds to Scott Bauersfeld's patch that increases the input buffer size in `index-pack` and `unpack-objects` from 4KB to 128KB to reduce I/O overhead, particularly on FUSE filesystems.

Junio acknowledges the sensible reasoning behind the change but points out a minor documentation nit - `unpack-objects` doesn't write to a pack file as the commit message suggests. He also suggests introducing a shared constant for the 128KB buffer size rather than hardcoding it in multiple places, noting this would be particularly useful for `csum-file.c` which currently lacks such a constant.

The maintainer expresses some surprise that the observed 66% reduction in pack file writes is lower than the theoretical maximum (~97% reduction), speculating this might be due to inherently short writes that don't utilize the full buffer. He suggests it would be useful to track writes smaller than 4KB to better understand the performance characteristics.

This is a constructive review that validates the core approach while identifying opportunities for improvement in both documentation and implementation details. The technical discussion remains focused on measurable performance impacts rather than subjective preferences.
