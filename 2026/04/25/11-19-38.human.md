Feature: New `--set-head` option for `git remote add` to automatically set remote HEAD.

Harald Nordgren proposes adding a `--set-head` flag to `git remote add` that mirrors `git clone`'s behavior of setting the remote's HEAD reference after fetching. The motivation comes from GitHub's `gh` tool not setting this reference when creating fork remotes, which breaks commands like `git log fork` that rely on the default branch being recorded.

The implementation:
- Adds the new option to both documentation and command-line parsing
- Automatically implies `--fetch` since it needs refs to determine the default branch
- Includes validation to prevent incompatible combinations with `-m` and push mirrors
- Adds a test verifying the new behavior

The patch appears well-constructed with:
- Clear commit message explaining the use case
- Documentation updates matching existing style
- Thoughtful error handling for edge cases
- A new test case covering the functionality

This would be particularly helpful for tooling that programmatically creates remotes (like `gh`) where users expect the same behavior as cloning. The implementation is straightforward and follows existing patterns in the remote-handling code.
