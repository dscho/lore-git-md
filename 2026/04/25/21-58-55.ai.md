2. This would make `git remote add --fetch` match `git clone` behavior without requiring new options
3. The change could be justified as fixing an inconsistency rather than adding new functionality

This shifts the discussion from whether to add a new option to whether the existing behavior should be changed to be more consistent. Junio's suggestion implies the original motivation (GitHub `gh` tool integration) could be addressed without expanding the command-line interface, though it would require modifying the default behavior of `remote add --fetch`.

The technical implementation would need to:
- Make `remote add --fetch` respect `followRemoteHEAD`
- Potentially change the default behavior when the config is unset
- Maintain backward compatibility with existing configurations
