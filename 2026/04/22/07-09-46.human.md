This is a build system patch addressing Ninja compatibility for config-list.h generation. The thread has identified a specific issue where older Ninja versions (pre-1.10.0) incorrectly handle dependencies listed on separate lines, causing build failures on systems like AlmaLinux 8.

Toon Claes initially proposed a conditional solution that would handle both old and new Ninja versions differently. Patrick Steinhardt suggested a simpler, unconditional approach that collapses all dependencies onto a single line using `tr`, which works for both Make and all Ninja versions. In this follow-up, Toon confirms Patrick's approach is indeed better - while the no-op targets in the depfile aren't strictly needed for Ninja, keeping them is harmless and the simpler solution works well.

The discussion shows technical alignment on both the problem and solution, with the only remaining work being Toon's promised v2 patch implementing Patrick's suggested simplification. This appears to be a straightforward build system improvement that will help users on older Ninja versions without introducing new complexity.
