This is a feature patch (v2) that implements a new `--reverse=before` option for revision walks, allowing commits to be reversed before applying commit limiting options like `--max-count`. The patch builds on previous discussion and incorporates feedback from Jeff King and others.

The key changes in v2 include:
- Simplified interface by removing the non-stuck form of `--reverse`
- Implemented cyclic toggle behavior for the reverse state (no-reverse → reverse-after → no-reverse → reverse-before → no-reverse)
- Added memory optimization when combining `--reverse=before` with `--max-count`
- Expanded documentation to clarify the toggle behavior and edge cases

The implementation adds a new `enum rev_reverse` in `revision.h` with states for `NO_REVERSE`, `REVERSE_AFTER` (current behavior), and `REVERSE_BEFORE` (new behavior). The core logic in `revision.c` handles the different ordering scenarios while maintaining backward compatibility.

The patch includes comprehensive tests in `t/t4202-log.sh` that verify:
- The new `--reverse=before` behavior shows earliest commits first when combined with `--max-count`
- The existing `--reverse=after` behavior remains unchanged
- Toggle behavior works correctly with multiple `--reverse` and `--no-reverse` options

All technical concerns raised in the v1 discussion appear to have been addressed, including Jeff King's state machine proposal and Tian Yuchen's performance considerations. The patch is well-structured with clear documentation and thorough test coverage. The only remaining open question is Junio C Hamano's conceptual framing about applying count limits later, which this version doesn't directly address.
