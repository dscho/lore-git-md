This is the final patch in Derrick Stolee's feature series introducing negotiation control options for fetch/push operations. The patch extends the push negotiation support to honor the new `remote.<name>.negotiationInclude` and `remote.<name>.negotiationRestrict` config options when `push.negotiate` is enabled.

Key changes in this patch:
- Passes negotiation config from `transport.c` through to the `send-pack` child process
- Updates the negotiation logic to use the new `--negotiation-restrict` option instead of the deprecated `--negotiation-tip`
- Adds comprehensive tests verifying both include and restrict behaviors during push negotiation
- Maintains backward compatibility with existing push negotiation behavior when no config is set

The implementation is clean and consistent with the rest of the series, with thorough test coverage demonstrating the new functionality works as expected. This completes the integration of the negotiation control features across both fetch and push operations.

The series has been through multiple rounds of review and appears technically sound, with all substantive feedback from Junio and Patrick Steinhardt addressed in previous iterations. This final patch ties up the loose ends for push negotiation support, making the feature complete and ready for integration.
