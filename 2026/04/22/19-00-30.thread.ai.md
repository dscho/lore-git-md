Thread identity: Bug report and fix for test suite hanging with mksh shell in Git 2.54.0, bisected to commit dd3693eb08 (transport-helper/connect child process cleanup).

Core problem: Regression where test suite hangs indefinitely when run with mksh due to shell behavior differences in SIGTERM handling. The problematic commit dd3693eb08 attempted zombie prevention via process cleanup but failed its primary goal while introducing new hangs, particularly in t5702-protocol-v2.sh.

Current status: Jeff King (Peff) has reverted dd3693eb08 in a new patch, removing the `clean_on_exit` and `wait_after_clean` flags from three process-spawning locations: `git_proxy_connect()` and `git_connect()` in connect.c, and `get_helper()` in transport-helper.c. The revert accepts that some processes may be reparented to pid1 as a temporary measure until a robust solution exists.

Key technical details: The original change's cleanup mechanism interacted poorly with shell process handling - while bash/dash terminate immediately on SIGTERM, mksh waits for child completion, creating deadlocks when children wait on Git. Peff's analysis shows the mechanism failed to prevent zombies when shells (which would reparent children anyway) while introducing new hangs. The current behavior is mostly acceptable for non-interactive cases as mksh optimizes away for trivial commands.

Open questions: Long-term solution for process tracking remains open - whether to implement more sophisticated tracking or recommend proper init systems for containerized environments. The immediate revert unblocks mksh users while maintaining the status quo for other shells.
