This is patch 5/7 in Derrick Stolee's feature series introducing negotiation control options for fetch operations. The patch adds the `--negotiation-include` option to complement the existing `--negotiation-restrict` option, allowing users to specify refs that should always be included in fetch negotiation regardless of the negotiation algorithm's selection.

The key addition is a mechanism to guarantee certain ref tips (like important release branches) are always advertised as "have" lines during fetch negotiation, preventing unnecessary large downloads when these refs would otherwise be truncated from the negotiation set. The implementation:

- Adds new CLI and config options (`--negotiation-include` and `remote.*.negotiationInclude`)
- Handles both exact ref names and glob patterns
- Silently ignores non-existent refs but fails on missing objects
- Marks included commits as COMMON to avoid duplicate negotiation
- Integrates with the existing negotiation protocol flow
- Includes comprehensive tests in t/t5510-fetch.sh

The patch appears technically sound with thorough test coverage and careful attention to edge cases. It completes the negotiation control feature set by providing both restrictive and inclusive controls, addressing real-world monorepo scaling issues where important branches were being truncated from negotiation. The series has already incorporated extensive review feedback and appears ready for integration.
