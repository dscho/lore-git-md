This is a bugfix patch from Jeff King (Peff) reverting commit dd3693eb08, which attempted to prevent zombie processes but instead caused test suite hangs with the mksh shell. The patch follows up on Jan Palus's report and Peff's earlier technical analysis.

The reverted commit had tried to clean up child processes by killing them when Git exits abnormally, but it fails in two key ways: it doesn't actually prevent zombies when shells are involved (since the shell process dies but its children live on), and it causes deadlocks with mksh which waits for child processes to complete before exiting. The deadlock manifests clearly in the test suite, particularly in t5702-protocol-v2.sh.

Peff's analysis shows the current approach is fundamentally flawed when dealing with shell-spawned processes, and since the original zombie prevention goal wasn't being met anyway, reverting is the cleanest solution. The patch removes the problematic clean_on_exit and wait_after_clean flags from three process-spawning locations in connect.c and transport-helper.c.

This is a straightforward, well-justified revert that addresses a clear regression while acknowledging the deeper process management issues that may need a more sophisticated solution in the future. The patch is minimal and focused, exactly matching the scope of the problem.
