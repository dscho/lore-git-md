This is a bugfix revert patch from Jeff King (Peff) addressing a regression in process cleanup behavior that causes the test suite to hang when run with the mksh shell. The patch reverts commit dd3693eb08 which attempted to prevent zombie processes by cleaning up child processes on abnormal exit.

The key issues identified:
1. The original change fails its primary goal - when using shells (like bash/dash/mksh), child processes still become zombies since only the shell itself is cleaned up
2. With mksh specifically, the cleanup causes deadlocks as mksh waits for children to complete before exiting on SIGTERM, while those children may be waiting on Git

The patch removes the `clean_on_exit` and `wait_after_clean` flags from three process-spawning locations:
- `git_proxy_connect()` in connect.c
- `git_connect()` in connect.c
- `get_helper()` in transport-helper.c

Peff's analysis suggests accepting that some processes may be reparented to pid1 is preferable to the current broken behavior, at least until a more robust solution can be developed. The revert is justified as an immediate fix since the current behavior both fails to prevent zombies and introduces new hangs, particularly affecting mksh users running the test suite.
