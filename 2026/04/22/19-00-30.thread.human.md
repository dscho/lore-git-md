Here's the human-readable thread summary:

This thread addresses a regression in Git 2.54.0 where the test suite hangs indefinitely when run with the mksh shell. The issue was bisected to commit dd3693eb08, which attempted to prevent zombie processes by cleaning up child processes on abnormal exit. Jan Palus originally reported and diagnosed the problem.

Jeff King (Peff) provided a thorough analysis showing the change fails its primary goal - when using any shell (bash, dash, or mksh), child processes still become zombies since only the shell itself gets cleaned up. Worse, with mksh specifically, the cleanup causes deadlocks because mksh waits for children to complete before exiting on SIGTERM, while those children may be waiting on Git. This particularly affects the t5702-protocol-v2.sh test.

Peff has now sent a revert patch that removes the problematic cleanup flags from three key process-spawning locations in connect.c and transport-helper.c. He argues this is the right immediate fix since the current behavior both fails to prevent zombies and introduces new hangs. The revert means we'll temporarily accept that some processes may be reparented to pid1, which Peff suggests is preferable until a more robust solution can be developed for handling process cleanup with shell intermediaries.

The discussion highlights broader challenges in Git's process handling, particularly when shells are involved, and suggests the run-command.c cleanup mechanisms may need rethinking for these cases. For now though, the revert provides a clear path forward to unblock mksh users while avoiding the regression's worst effects.
