This is a refactoring patch in Jiamu Sun's series to add subcommand autocorrection to Git's parse-options API. The patch moves TTY checking logic from help.c to autocorrect.c, consolidating all autocorrection configuration handling in one place.

The change makes sense architecturally - the autocorrect_resolve_config() function is now fully responsible for validating and resolving autocorrection settings, including the interactive session check. This follows the principle that configuration parsing should ensure the parsed value is correct and reliable before being used elsewhere.

The implementation:
- Moves the isatty() check into autocorrect_resolve_config()
- Maintains the same behavior (disabling prompt in non-interactive sessions)
- Simplifies help.c by removing its direct TTY awareness
- Keeps all error cases and fallback behaviors intact

This is a clean, focused change that improves code organization without altering functionality. The patch fits well with the series' goal of creating reusable autocorrection infrastructure. With the major technical questions already settled in previous iterations, this appears to be a straightforward improvement that's ready for merging.
