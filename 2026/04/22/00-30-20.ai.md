This is the second version of a feature patch series introducing a `--reverse=before` option for revision walks. The series builds on previous discussion and implements a toggle behavior for `--reverse` that cycles through states (no-reverse → reverse-after → no-reverse → reverse-before → no-reverse) while adding memory optimizations for the new `--reverse=before` mode.

The implementation now includes a sliding window optimization when combining `--reverse=before` with `--max-count`, addressing performance concerns raised in the thread. The changes touch key revision walking machinery in `revision.[ch]` and `list-objects.c`, with thorough test coverage added in `t4202-log.sh`. Documentation has been expanded to clarify the toggle behavior and edge cases.

All technical feedback from v1 appears addressed, including Jeff King's state machine suggestions and Tian Yuchen's performance analysis. The patch remains conceptually sound for its primary use case of showing earliest commits with `--reverse --max-count`, now with more robust handling of multiple specifications.
