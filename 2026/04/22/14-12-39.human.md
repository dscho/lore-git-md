This is a follow-up discussion in the Ninja build system compatibility thread, where Phillip Wood provides additional technical clarification about sed behavior. The core issue involves generating config-list.h dependencies in a way that works across different build systems and sed implementations.

Phillip points out that using `\n` in sed's replacement string doesn't actually insert a newline character as intended - it literally inserts the characters backslash-n. He references the FreeBSD sed manpage to confirm this behavior isn't portable. This builds on his earlier review where he suggested two more portable alternatives: using an actual newline in the sed script or constructing the output line-by-line with printf.

The email serves as a technical correction to the previous discussion, ensuring the final solution will work correctly across all platforms.
