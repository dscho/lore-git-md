This is the final patch (7/7) in Derrick Stolee's v3 series introducing negotiation control for fetch/push operations. The patch extends the push negotiation support to honor the new `remote.<name>.negotiationInclude` and `remote.<name>.negotiationRestrict` config options when `push.negotiate` is enabled.

The implementation modifies `send-pack.c` to pass these config values to the child `git fetch --negotiate-only` process that handles push negotiation. Key technical changes include:
- Adding `negotiation_include` and `negotiation_restrict` fields to `struct send_pack_args`
- Updating `get_commons_through_negotiation()` to handle both include and restrict lists
- Replacing the legacy `--negotiation-tip` usage with `--negotiation-restrict`
- Adding comprehensive tests in `t/t5516-fetch-push.sh` for both config options

The patch maintains backward compatibility while enabling the same negotiation control for push operations that was previously added for fetch. When no restrict patterns are specified, it falls back to using all remote refs as negotiation tips, matching the original behavior.

This completes the series' goal of providing fine-grained control over negotiation behavior in both fetch and push operations, particularly useful for monorepo scenarios where certain branches should be prioritized or excluded from negotiation. The implementation has been thoroughly reviewed and appears ready for integration.
