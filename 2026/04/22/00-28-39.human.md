This is the second version of a feature patch series introducing a `--reverse=before` option for revision walks, allowing commits to be reversed before applying constraints like `--max-count`. The key changes from v1 are:

1. Simplified the interface by removing the non-sticky form of `--reverse` (now it always toggles between states)
2. Implemented a memory optimization window when using `--reverse=before` with `--max-count` to reduce overhead
3. Updated documentation to clarify the toggle behavior when `--reverse` is specified multiple times

The first patch implements the core functionality, while the second adds the memory optimization. The series addresses Jeff King's feedback from v1 about state machine behavior, now ensuring that repeated `--reverse` toggles cycle cleanly between no-reverse, reverse-after, and reverse-before states.

The implementation touches revision walking internals in `revision.c` and adds comprehensive tests showing the new behavior. The memory optimization in patch 2 is particularly notable - it limits how much history needs to be buffered when using `--reverse=before` with a count limit, addressing a potential performance concern raised in earlier discussion.

The documentation updates clarify some subtle points about the toggle behavior that weren't obvious in v1. This looks like a well-considered revision that incorporates feedback while maintaining the original goal of making early-history queries more efficient. The series appears ready for review, though Junio's earlier conceptual questions about whether this is best framed as "applying limits later" remain unaddressed.
