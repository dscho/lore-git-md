This is a follow-up in the thread about Ninja build system compatibility for config-list.h generation. Patrick Steinhardt responds to Toon Claes's initial patch that addressed a circular dependency issue in older Ninja versions (pre-1.10.0) by optionally collapsing dependency lines.

Patrick suggests simplifying the approach - rather than having two modes (multi-line for newer Ninja/Make and collapsed for older Ninja), he proposes always using the single-line format. His reasoning is that this simpler approach should work universally across all build systems, eliminating the need for version detection and conditional logic.

The proposed change modifies the generate-configlist.sh script to always concatenate dependencies on a single line using `tr` and additional `sed` commands. This appears to be a clean simplification that maintains the fix's effectiveness while reducing maintenance overhead. The response is technical but constructive, focusing on the build system behavior rather than questioning the underlying issue's validity.
