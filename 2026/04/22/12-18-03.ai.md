This is a refactoring patch in Jiamu Sun's series to add subcommand autocorrection support to Git's parse-options API. The patch moves TTY checking logic from help.c to autocorrect.c as part of consolidating autocorrection behavior.

The key change relocates the interactive session check (verifying stdin/stdout are TTYs) from the command help handler to the autocorrect configuration resolver. This makes the TTY validation happen earlier in the flow and centralizes all autocorrection configuration logic in the new autocorrect.c file.

The patch maintains identical behavior while improving code organization - the same check that previously happened in help.c's `help_unknown_cmd()` now occurs in `autocorrect_resolve_config()`. This is part of the broader effort to extract and reuse autocorrection logic across both main commands and subcommands.

The change is straightforward and mechanical, with no functional impact beyond the code structure. It follows the pattern established in earlier patches of this series to create clean separation between the autocorrection subsystem and its callers. The patch has already received maintainer approval and is part of a series that's ready for merging.
