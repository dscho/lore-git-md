This is a feature patch (v2) that adds a `--reverse=before` option to revision walks, allowing commits to be reversed before applying commit limits rather than after. The change addresses a common confusion where `git log --reverse --max-count=3` currently shows the last 3 commits in reverse order, when many users expect it to show the first 3 commits in order.

The patch builds on previous discussion and incorporates feedback from Jeff King and others. Key improvements in v2 include:
- Simplified interface by removing the non-stuck form of `--reverse`
- Added cyclic toggle behavior for the reverse state
- Implemented a memory optimization when combining `--reverse=before` with `--max-count`
- Expanded documentation to clearly explain the toggle behavior and edge cases

The implementation adds a new `enum rev_reverse` in `revision.h` with states for no-reverse, reverse-after (default), and reverse-before. The core changes are in `revision.c`'s `get_revision()` function to handle the different ordering modes. The patch includes thorough test coverage in `t4202-log.sh` demonstrating the new behavior and backwards compatibility.

This appears to be a well-constructed patch that addresses all technical feedback while maintaining backward compatibility. The documentation clearly explains the new behavior and edge cases. The change is focused on the revision walking machinery without broader architectural impacts.
