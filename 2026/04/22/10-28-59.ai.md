Feature: This is the second patch in Patrick Steinhardt's series introducing a new `git history fixup` subcommand, building on the preparatory refactoring from patch 1/2. The command allows amending staged changes to an existing commit while automatically rebasing dependent branches.

The new subcommand works similarly to `git commit --fixup` but with the key addition of automatically rebasing dependent branches. It performs a three-way merge using HEAD's tree as the base, applying staged changes to the target commit. The implementation currently aborts on merge conflicts, with plans to improve this when Git gains better conflict resolution capabilities.

Key technical details:
- Adds `git history fixup <commit>` command with options for dry-run, ref updates control, and message editing
- Uses the new `commit_tree_ext()` function from patch 1/2
- Handles index interaction and tree merging via merge-ort
- Includes extensive test coverage (500+ lines in t3453-history-fixup.sh)
- Updates documentation in Documentation/git-history.adoc

Notable limitations:
- Doesn't work in bare repositories (requires index)
- Aborts on merge conflicts rather than resolving them
- Preserves original commit message by default unless --reedit-message is used

The patch follows Patrick's typical thorough style with comprehensive tests and documentation. The automatic rebasing of dependent branches is a notable workflow improvement, though the conflict handling limitation may be a practical concern until Git's conflict resolution capabilities improve. This continues the experimental `git history` command's expansion of Git's history editing capabilities.
