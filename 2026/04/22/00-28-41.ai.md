This is a performance optimization patch for the `--reverse=before` revision walk feature introduced earlier in the series. The patch addresses memory usage concerns raised during review by implementing a sliding window approach when `--max-count` is specified.

The key technical contribution is a new `retrieve_with_window()` function that maintains only the most recent `max_count` commits in memory during traversal, rather than storing the entire history. This reduces space complexity from O(N) to O(K) where K is the max count, while maintaining O(N) time complexity through efficient queue operations.

The implementation uses two queues (`into_queue` and `outo_queue`) to manage the sliding window, carefully transferring commits between them to maintain the correct order while discarding older commits once the window is exceeded. The patch preserves all existing behavior when `--max-count` isn't specified or when using the default `--reverse=after` mode.
