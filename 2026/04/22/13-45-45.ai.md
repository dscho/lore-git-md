This is a build system patch thread discussing portability concerns in the Ninja compatibility fix for config-list.h generation. Phillip Wood provides a substantive review of Toon Claes' v2 patch, pointing out that the use of `\n` in sed's replacement string may not be portable across all sed implementations.

The review identifies that while the current approach works for inserting literal backslash-n sequences, it doesn't actually insert a newline character as intended. Phillip suggests two alternative approaches that would be more portable:
1. Using an actual newline in the sed script with `s/ $/\` followed by newline`/`
2. Using printf to construct the output line-by-line

The review maintains support for the unconditional single-line approach (as previously agreed in the thread) while improving the implementation's portability. Phillip notes that GCC-generated depfiles already use single-line format, reinforcing the solution's general applicability.

This is a technical refinement to an already-solid solution, addressing a subtle portability concern that could affect builds on systems with non-GNU sed implementations. The review demonstrates Phillip's characteristic attention to cross-platform compatibility and standards compliance.
