This is a refactoring patch in Jiamu Sun's subcommand autocorrection series, now in its fifth iteration. The patch replaces magic number constants for autocorrection configuration with a proper `autocorrect_mode` enum and `autocorrect` struct containing both mode and delay values.

Key changes:
- Introduces `enum autocorrect_mode` with explicit values for different behaviors (PROMPT, NEVER, IMMEDIATELY, SHOW, DELAY)
- Defines `struct autocorrect` to bundle mode and delay configuration together
- Updates all related functions to use the new types instead of raw integers
- Maintains identical behavior while improving type safety and readability

The refactoring:
- Moves configuration parsing into `parse_autocorrect()` which now returns the enum
- Updates `autocorrect_resolve_config()` to populate the struct fields
- Modifies `autocorrect_confirm()` to take the struct instead of raw values
- Adjusts `help.c` to use the new types while keeping the same logic

This is a clean internal improvement that doesn't change user-visible behavior but makes the code more maintainable. The patch fits well into the larger series by providing better structure for the autocorrection subsystem that was introduced in earlier patches. With all major technical questions resolved in previous iterations, this appears to be final polishing change before the series is ready for merging.
