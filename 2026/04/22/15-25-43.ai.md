This is patch 4/7 in Derrick Stolee's v3 series introducing fetch/push negotiation controls, focusing on adding config support for the negotiation restriction feature.

The patch adds `remote.<name>.negotiationRestrict` as a multi-valued config option that serves as the default for `--negotiation-restrict` when fetching from a specific remote. Key aspects:

- The config accepts exact ref names or glob patterns, matching the CLI option's syntax
- Empty values reset the list, allowing override of inherited configs
- Command-line `--negotiation-restrict` takes precedence over config values
- Includes warning when protocol doesn't support negotiation restrictions
- Adds comprehensive tests verifying config behavior and CLI override

The implementation touches:
- `remote.c` for config parsing and storage in `struct remote`
- `builtin/fetch.c` for applying config defaults when no CLI option given
- Documentation updates in `remote.adoc`
- New test cases in `t/t5510-fetch.sh`

This completes the configuration interface for the negotiation restriction feature, complementing the earlier CLI option work. The patch maintains consistency with the series' goal of optimizing fetch/push negotiation in monorepos by allowing focused advertisement of "have" lines.
