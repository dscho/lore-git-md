Feature addition to the experimental `git history` command. This is a cover letter for a 2-patch series from Patrick Steinhardt introducing a "fixup" subcommand to the still-in-development `git history` tool.

The proposed `git history fixup` command allows amending staged changes to an existing commit (similar to `git commit --fixup`), with the added benefit of automatically rebasing dependent branches - a key feature of the `git history` command family. The implementation currently aborts on merge conflicts, with plans to improve conflict handling once Git gains better conflict resolution capabilities.

The series comes from a trusted contributor (Patrick Steinhardt) who has been driving the `git history` effort. The patches appear well-structured with comprehensive tests (500 lines of new test coverage for the feature). The cover letter clearly explains the motivation and current limitations, suggesting this is a polished proposal rather than an early RFC.

This builds on the ongoing `git history` work, which aims to provide higher-level version control operations with automatic branch dependency tracking. The feature seems immediately useful for the stated workflow of frequently creating fixup commits, though adoption will naturally be limited until `git history` itself becomes more established.
