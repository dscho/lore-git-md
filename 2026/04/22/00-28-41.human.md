This is a performance optimization patch for the `--reverse=before` revision walk feature introduced earlier in the series. The patch addresses memory usage concerns when combining `--reverse=before` with `--max-count`.

The key improvement is a sliding window algorithm that reduces memory usage from O(N) to O(K) (where K is the max count) by only keeping the most recent K commits in memory during the walk. The implementation uses two queues (`into_queue` and `outo_queue`) to efficiently manage the window of commits being retained. The change is focused in `revision.c` with a new `retrieve_with_window()` helper function.

This appears to be a well-considered optimization that directly addresses the performance concerns raised in earlier discussion. The implementation maintains the same output while being more memory-efficient for large histories. The patch includes clear comments explaining the queue management logic and complexity characteristics.
