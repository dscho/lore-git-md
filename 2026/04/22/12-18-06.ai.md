This is part 6/10 of Jiamu Sun's feature series adding subcommand autocorrection to Git's parse-options API, now in final polishing stage. The patch refactors the autocorrection configuration handling to provide a cleaner public API.

Key changes in this specific patch:
- Introduces `autocorrect_resolve()` as the public API for retrieving autocorrect config, hiding the internal config callback
- Makes the config callback `resolve_autocorrect()` internal to autocorrect.c
- Updates help.c to use the new API while maintaining the same behavior
- Keeps the same config resolution logic but presents it through a cleaner interface

The change improves encapsulation by preventing direct access to the config callback from outside autocorrect.c. While this means some config iterations can't be merged (potentially impacting performance), the code path is considered cold enough that this tradeoff is acceptable.

The patch maintains all existing functionality while cleaning up the interface, following the pattern seen elsewhere in the series of refining the implementation details while keeping the user-visible behavior consistent. This aligns with the overall series goal of providing subcommand autocorrection that matches Git's existing command autocorrection behavior.
