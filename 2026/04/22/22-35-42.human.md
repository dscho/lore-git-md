This is a bugfix discussion about a regression in Git 2.54.0 where the test suite hangs when run with mksh as the system shell. Jeff King (Peff) confirms Jan Palus's findings that commit dd3693eb08, which introduced child process cleanup in transport-helper and connect code, interacts poorly with mksh's process handling.

Peff's analysis shows that while bash terminates and reparents children on SIGTERM, mksh waits for child completion - causing the observed hangs. He demonstrates this with a simple test case showing the behavioral difference between shells. The immediate solution proposed is to revert dd3693eb08 since the current approach doesn't reliably solve the original problem (preventing zombie processes) and creates this new issue.

The discussion reveals deeper challenges with Git's run-command system when shells are involved - it can't reliably kill intended child processes when they're spawned via shell commands. Peff suggests this might require more fundamental changes to signal handling, possibly by closing pipes to signal children rather than relying on process termination. For now, reverting seems the safest path while the team considers more robust solutions.

This appears to be a legitimate regression that needs addressing before the next release, with Peff's technical analysis lending weight to the proposed revert. The thread shows careful consideration of both the symptom and underlying architectural questions about process management in Git.
