This is the first patch in Jiamu Sun's v5 series adding subcommand autocorrection support to Git's parse-options API. The patch refactors the subcommand handling logic in parse-options.c to prepare for the autocorrection feature.

The key changes are:
- Extracts subcommand parsing into a new `handle_subcommand()` helper function
- Simplifies `parse_subcommand()` to return a simple success/failure status rather than an enum
- Removes the switch statement over impossible parse_opt_result values
- Makes the non-option path clearer by separating subcommand handling from regular option parsing

This is a clean refactoring that maintains all existing behavior while making the code more maintainable. The changes are well-contained to parse-options.c and don't introduce any new functionality yet - that comes in later patches in the series. The patch has already been reviewed and approved in previous iterations, with Junio C Hamano specifically requesting the threshold unification that was implemented in v5.

The refactoring provides a solid foundation for the autocorrection feature that follows in subsequent patches, while improving the code structure independently of that new functionality.
