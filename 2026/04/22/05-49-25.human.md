This is a security discussion thread about credential handling in Git's libsecret helper. Mantas Mikulėnas responds to Lutz-Christian Quander's analysis of the credential leak issue, agreeing that the helper's unconditional credential_write() is unnecessary but questioning whether direct helper invocation should be considered a supported interface.

Key points from this exchange:
- The immediate security risk (credentials leaking to stdout during direct helper invocation) is confirmed, but there's debate about whether this usage pattern is officially supported or an implementation detail
- Mikulėnas argues the current behavior doesn't technically violate the credential helper protocol since stdout is documented as being ignored during store operations
- Both agree the helper should be fixed to avoid the unnecessary output, though Mikulėnas considers this more of a cleanup than a critical security fix
- The discussion highlights a documentation gap around proper credential storage patterns, with direct helper invocation being widely used despite potentially being an internal implementation detail

The thread is converging toward a fix for the libsecret helper while raising broader questions about credential helper interface boundaries that may warrant documentation updates. The security impact appears limited to non-standard usage patterns, but the prevalence of those patterns in the wild makes the fix worthwhile.
