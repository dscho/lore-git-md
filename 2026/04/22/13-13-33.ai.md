This is a security discussion follow-up about the `git-credential-libsecret` helper's credential leakage behavior. Phillip Wood weighs in to clarify that credential helpers are intentionally not in `$PATH` and that users should always use `git credential` rather than invoking helpers directly. He notes that `gitcredentials(7)` already documents the proper configuration approach without encouraging direct helper invocation.

The exchange reinforces the emerging consensus that while the helper's stdout output during store operations is technically allowed by the protocol (when properly used via `git credential`), the real issue is misuse of the helper interface. Wood's perspective as a core contributor with deep knowledge of Git's plumbing adds weight to the position that direct helper invocation is not a supported pattern, even if it appears in some documentation and scripts.

The thread now has clear agreement on two fronts: (1) the helper should be fixed to suppress unnecessary output (a simple change), and (2) the broader solution involves reinforcing the proper `git credential` interface rather than treating direct helper invocation as legitimate usage. This positions the discussion for a straightforward resolution combining a code fix with potential documentation clarifications about the intended credential storage workflow.
