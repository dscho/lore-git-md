This is the second patch in Patrick Steinhardt's series introducing a `git history fixup` subcommand, building on his ongoing work with the experimental `git history` command. The patch implements a new subcommand that allows amending staged changes to an existing commit while automatically rebasing dependent branches - similar to `git commit --fixup` but with automatic branch updates.

Key technical details:
- Adds `git history fixup <commit>` that performs a three-way merge of staged changes into the target commit's tree
- Uses HEAD's tree as the merge base (similar to cherry-pick logic)
- Preserves original commit message and authorship by default (can override with --reedit-message)
- Automatically rebases all descendant branches by default (configurable with --update-refs)
- Currently aborts on merge conflicts (a noted limitation)
- Includes extensive test coverage (500+ lines in t3453-history-fixup.sh)

The implementation appears thorough and well-tested, with clear documentation of both functionality and current limitations. The automatic rebasing of dependent branches is particularly notable workflow improvement, though the conflict handling limitation means it's not yet a complete solution. Given Patrick's track record with the history command and the clear motivation, this seems likely to progress smoothly through review.
