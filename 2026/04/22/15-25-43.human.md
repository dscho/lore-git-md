This is part 4/7 in Derrick Stolee's feature series introducing configurable fetch/push negotiation controls, specifically adding the `remote.*.negotiationRestrict` configuration option.

The patch adds persistent configuration support for the `--negotiation-restrict` command-line option introduced earlier in the series. Key aspects:

- Adds `remote.<name>.negotiationRestrict` as a multi-valued config option that sets default negotiation restrictions for fetches from that remote
- Behaves like the CLI option - accepts exact refs or glob patterns to restrict negotiation
- Empty values reset the list (useful for overriding system/global configs)
- Command-line arguments override any config values
- Includes comprehensive tests verifying config behavior and CLI override precedence

The implementation adds the new config handling in `remote.c` while modifying `builtin/fetch.c` to apply these defaults when no CLI options are provided. Documentation updates explain the new config option's behavior and interaction with CLI flags.

This is a straightforward addition to the negotiation control series that follows naturally from the CLI options introduced earlier. The patch maintains consistency of the feature's design while making it more convenient for regular use through configuration.
