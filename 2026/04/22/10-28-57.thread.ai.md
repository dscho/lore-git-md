Thread identity: Patch series introducing `git history fixup` subcommand, authored by Patrick Steinhardt, building on commit 94f057755b from April 2026. This is part of the experimental `git history` command effort.

Core problem/goal: Enable amending staged changes to an existing commit (like `git commit --fixup`) while automatically rebasing dependent branches, addressing a workflow pain point. The implementation handles simple cases but aborts on merge conflicts, with plans to improve conflict resolution pending future Git capabilities.

Current status: Complete 2-patch series posted (v1). First patch refactored internal tree-commit functionality; second patch implements the `fixup` subcommand with automatic rebasing of dependent branches. Tian Yuchen has reported a bug where file deletions aren't properly incorporated into fixup commits, causing target commits to appear empty in log output.

Key technical details:
- Refactored `commit_tree_with_edited_message_ext()` into generic `commit_tree_ext()` with flags parameter (patch 1)
- New `git history fixup <commit>` command performs three-way merge using HEAD's tree as base (patch 2)
- Uses merge-ort for tree merging and new `commit_tree_ext()` infrastructure
- Includes 500+ lines of tests in t3453-history-fixup.sh
- Documents command in Documentation/git-history.adoc
- Current limitations: no bare repo support, aborts on merge conflicts, preserves original message by default
- Bug report shows file deletions not properly handled in fixup operations

Open questions/loose ends:
- Handling merge conflicts before proper resolution support lands
- Edge cases around branch dependency tracking
- User expectations for automatic rebasing behavior
- Bare repository support considerations
- Fixing the file deletion handling bug reported by Tian Yuchen
- Documentation improvements to better explain command behavior to end users (raised by D. Ben Knoble)
