This is a preparatory refactoring patch for the new `git history fixup` feature, part of Patrick Steinhardt's ongoing work on the experimental `git history` command. The patch generalizes an internal function `commit_tree_with_edited_message_ext()` to make it more flexible for reuse.

The key change is converting the function to take a flags parameter that controls whether the commit message should be edited (the original behavior) or kept as-is. This prepares for the same plumbing to be used by the upcoming `fixup` subcommand, which needs to create commits without modifying their messages.

The patch touches only `builtin/history.c`, with straightforward mechanical changes to:
1. Add a new `enum commit_tree_flags`
2. Rename and modify the function to respect the flags
3. Update all existing callers to pass the new flag

This appears to be a clean, focused refactoring with no behavior changes - all existing functionality continues to work the same way, just through a more flexible interface. The changes are well-contained and the commit message clearly explains the motivation. This is typical of Patrick's careful, incremental approach to feature development.
