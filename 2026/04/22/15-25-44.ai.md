This is patch 5/7 in Derrick Stolee's v3 series introducing fetch/push negotiation controls, focusing on the new `--negotiation-include` option. The series addresses monorepo scenarios where important branches might be excluded from fetch negotiation, causing unnecessary large downloads.

The patch implements `--negotiation-include` to ensure specified ref tips are always sent as "have" lines during negotiation, regardless of what the algorithm selects. This complements the existing `--negotiation-restrict` option by allowing certain refs (like release branches) to be guaranteed in the have set while still allowing opportunistic inclusion of others.

Key technical aspects:
- Adds new `negotiation_include` field to `git_transport_options`
- Implements ref resolution for exact refs and glob patterns in `fetch-pack.c`
- Marks included commits as COMMON to avoid duplicate negotiation
- Updates protocol handling to properly count required haves
- Adds comprehensive tests in `t/t5510-fetch.sh` covering basic functionality, glob patterns, and edge cases
- Includes `git pull` passthrough support

The implementation ensures missing refs are silently ignored while missing objects are treated as fatal errors (indicating corruption). The patch maintains consistency with the series' overall approach while adding this complementary negotiation control mechanism.
