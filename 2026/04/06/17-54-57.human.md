This is a test patch in the fsmonitor Linux implementation effort, adding new test cases and hardening existing ones. It's part of a 13-patch series that brings Linux fsmonitor support to parity with Windows/macOS implementations.

The patch adds two key test scenarios:
1. A smoke test that verifies the filesystem actually delivers inotify events (important for overlayfs and older kernels where watches might succeed but events get lost)
2. A stress test for rapid nested directory creation to catch EEXIST race conditions during recursive watch registration

It also includes several test infrastructure changes:
- Reduces daemon start timeout from 60 to 10 seconds for faster test feedback
- Adds robustness for environments without procps (like Fedora CI) by falling back to /proc/$pid/stat
- Improves process group handling in submodule tests with set -m
- Adds better cleanup for test processes

The changes demonstrate careful attention to real-world edge cases and CI environments, continuing the high-quality engineering seen throughout this series. The tests specifically target scenarios that caused crashes in earlier versions, showing thorough validation of the implementation.

This patch appears ready for inclusion, completing the test coverage for the Linux fsmonitor work. It follows the pattern of earlier patches in the series by focusing on robustness and real-world compatibility while maintaining the clean separation between test workarounds and core behavior.
