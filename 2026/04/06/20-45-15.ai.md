Maintainer response on NULL ODB transaction handling in `git diff --no-index`.

Junio C Hamano weighs in on the discussion about fixing the NULL object database segfault in `git diff --no-index`, clearly siding with Justin Tobler's proposed solution over Jeff King's alternative. The maintainer agrees with Tobler's assessment that starting an ODB transaction makes no sense when there is no object database to write to, and explicitly rejects the idea of making the transaction system handle NULL sources gracefully.

This email effectively resolves the architectural debate by endorsing Tobler's approach of avoiding transactions entirely for hashing-only operations. Junio's brief but decisive response suggests the fix will likely take the form of Tobler's experimental `hash_blob_stream()` helper rather than modifying transaction handling to accommodate NULL cases. The decision aligns with Tobler's ongoing work on ODB abstraction and maintains cleaner invariants in the transaction system.

The key technical implication is that the fix will focus narrowly on the `git diff --no-index` streaming path rather than introducing broader changes to transaction semantics. This keeps the scope minimal while still addressing the immediate segfault when comparing large files outside a repository. The resolution leaves open the question of whether other commands might benefit from NULL-handling transaction infrastructure, but Junio's stance suggests such cases would need strong justification.
