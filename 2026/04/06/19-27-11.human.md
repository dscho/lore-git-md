Bugfix addressing incorrect cache-tree validation that could cause `write-tree` to use stale cached trees. This v2 patch from David Lin follows up on feedback from Derrick Stolee and Junio C Hamano, restoring a missing negation operator in `cache_tree_fully_valid()` that was accidentally dropped during a refactor in commit 062b914c84. The bug caused the function to incorrectly mark cache tree nodes as valid when their objects were missing from the object database, potentially leading to `write-tree` using outdated cached trees rather than rebuilding them.

The patch includes a test verifying that `write-tree` properly uses the cache-tree optimization when valid, though as noted in earlier discussion, this serves more as a demonstration than direct validation of the bug's full impact. The commit message has been updated with the requested historical context about the regression's origin. While narrowly scoped, this fix is important for maintaining index-to-tree consistency, particularly in partial clone scenarios where missing objects are common. The change should reduce unnecessary object database checks when the cache tree is actually valid.
