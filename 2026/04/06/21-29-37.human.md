This is a follow-up discussion in the `git fast-export` output ordering bugfix thread. Jeff King (Peff) weighs in with historical context and additional considerations for the proposed fix.

Peff confirms this is a long-standing issue, citing three previous reports from 2015, 2017, and 2023 that never reached resolution. The core problem - that deletions should come first when paths are prefixes - remains valid, though past discussions got sidetracked by more complex cases like rename cycles. He suggests the pragmatic approach is to implement the straightforward deletion-first ordering, noting that users needing complex renames could simply avoid them.

The response also raises an interesting architectural question: whether the sorting responsibility should lie with the exporter (`fast-export`) or importer (`fast-import`). Peff floats the idea that both tools might benefit from handling this - `fast-export` to help all consumers, and `fast-import` to be robust against malformed input from other sources.

This moves the discussion forward by providing historical context that validates the need for a fix while expanding the scope to consider where the fix should live in the architecture. Peff's perspective as a long-time contributor lends weight to the view that the deletion-first approach is sound, though the thread remains open for further discussion about implementation details.
