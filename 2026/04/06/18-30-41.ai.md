This is a bugfix targeting the promisor-remote subsystem, specifically addressing incorrect repository context when reading the `promisor.quiet` config. The patch is part of the ongoing `the_repository` removal effort.

The issue occurs when Git performs lazy fetches in submodules context - the code was reading the superproject's `promisor.quiet` setting instead of the submodule's own configuration. Trieu Huynh identifies this as affecting commands like `git grep --recurse-submodules` when operating on a superproject where the submodule is a partial clone.

The fix is straightforward: replace `the_repository` with the passed `repo` parameter in `fetch_objects()`. The patch includes a thorough test case that verifies the submodule's `promisor.quiet` setting is properly respected during a recursive grep operation. The test creates a superproject with a partial-clone submodule, sets `promisor.quiet` only in the submodule, then verifies the fetch operation uses the `--quiet` flag as expected.

The commit message clearly explains both the problem and solution, and the test case provides concrete validation of the fix. The change is small and focused, touching only the necessary lines while adding comprehensive test coverage.
