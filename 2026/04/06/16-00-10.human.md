This is a test modernization patch in Johannes Schindelin's series preparing for a potential future change to make bare repository access explicit by default. The thread has progressed with Junio Hamano weighing in on the approach.

Junio agrees with the overall direction but suggests a different implementation strategy. Rather than sprinkling `test_config_global safe.bareRepository all` throughout individual tests (as shown in this first patch), he proposes setting it globally in `test-lib.sh` when `WITH_BREAKING_CHANGES` is enabled. This would make most existing bare repository tests "just work" while allowing new tests to explicitly opt out when testing the restricted behavior.

The maintainer's input signals this preparatory work is on the right path technically, though the implementation approach may shift. The series remains focused on ensuring tests continue validating command behavior in bare repositories regardless of future default changes to repository safety policies. Junio emphasizes that the eventual behavior change would need separate documentation and careful consideration before landing.
