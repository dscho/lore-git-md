This is patch 2/5 in Lorenzo Pegorari's v3 series addressing promisor file handling during repacks, part of his GSoC work under Eric Sunshine's mentorship. The patch introduces a new helper function `copy_promisor_content()` that preserves debugging information in `.promisor` files when repacking promisor packfiles.

The function handles several key requirements:
- Maintains the original timestamp> <oid> <ref> format for debugging partial clones
- Uses an ignorelist (`not_repacked_basenames`) to skip packs not being repacked
- Only copies objects that exist in the new pack (verified via `find_pack_entry_one()`)
- Preserves existing timestamped entries while adding timestamps to new ones
- The implementation checks each object's presence in the new pack before copying its metadata, ensuring accurate mapping even when some packs remain untouched during partial repacks. Timestamps are taken from the source file's modification time rather than creation time for practicality.

Key technical details:
- New helper in `repack-promisor.c` with comprehensive error handling
- Uses `strset` to track already-copied content and avoid duplicates
- Handles both timestamped and non-timestamped input formats
- Integrates with the existing pack infrastructure via `parse_pack_index` and `find_pack_entry_one`

The patch demonstrates good attention to edge cases and error conditions, with proper cleanup of allocated resources. It forms the core of the series' functionality, with subsequent patches integrating it into the repack logic and adding tests. The implementation appears well-considered and addresses the core concerns raised in previous rounds about timestamp preservation and geometric repack handling.
