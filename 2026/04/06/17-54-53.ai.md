This is a feature patch implementing Linux filesystem monitoring (fsmonitor) support via inotify, part of a larger series bringing fsmonitor to parity across platforms. The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection.

The patch adds three new files implementing the Linux-specific components:
- `fsm-listen-linux.c` - Core inotify event handling with non-blocking polling, recursive watch registration, and rename tracking
- `fsm-health-linux.c` - Stub health monitoring (Linux doesn't need separate thread)
- `fsm-path-utils-linux.c` - Filesystem type detection and mount point handling

Key technical aspects include:
- Uses `inotify_init1(O_NONBLOCK)` with 50ms poll timeout
- Bidirectional hash maps for watch descriptors <-> paths
- Cookie-based rename tracking with stale detection
- Recursive watch registration for new directories
- Remote filesystem detection via `statfs()` and `/proc/mounts`
- Careful handling of edge cases (watch limits, unmounts, queue overflows)

The implementation appears production-ready, having been tested across 13 iterations. It builds on prior work from Eric DeCosta and Marziyeh Esipreh, now addressing all substantive review feedback. Documentation is updated to cover Linux-specific caveats around inotify watch limits.

This represents the final major platform for native fsmonitor support, completing a long-running cross-platform effort. The careful handling of technical constraints (privileges, performance, edge cases) and thorough test coverage suggest this is a high-quality contribution likely to be merged.
