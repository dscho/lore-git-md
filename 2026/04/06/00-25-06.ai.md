This is the third patch in Lorenzo Pegorari's v3 series addressing promisor file handling during repacks, part of his GSoC work under Eric Sunshine's mentorship. The patch focuses on preserving the contents of `.promisor` files after repacking operations, particularly addressing geometric repacking scenarios.

The key change modifies `finish_repacking_promisor_objects()` to use the new `copy_promisor_content()` helper (introduced in patch 2/5) to preserve debugging information from original `.promisor` files rather than creating empty ones. For geometric repacking, it introduces a `strset` to track excluded packs that shouldn't have their promisor content copied. The patch also updates documentation to clarify that `.promisor` files will now contain arbitrary contents rather than being empty.

Technical details worth noting for future reference:
- The geometric repack case now uses `strset` to track `not_repacked_basenames`
- Both regular and geometric repack paths flow through `finish_repacking_promisor_objects()` with different parameters
- Documentation update clarifies the `.promisor` file behavior in `git-repack.adoc`
- The implementation maintains backward compatibility while adding the new functionality
