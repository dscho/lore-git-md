Performance optimization for `git rev-list --maximal-only`. This is the third and final patch in Derrick Stolee's series that makes `rev-list --maximal-only` use the faster `merge-base --independent` algorithm when possible. The patch implements the actual optimization after the previous patches established test coverage and benchmarks.

The key change is a new `prepare_maximal_independent()` function that checks if the rev-list command can safely use the faster `reduce_heads()` algorithm (which powers `merge-base --independent`). This fast path is only taken when no other walk modifiers or output formatting options are present that would require a full revision walk. The patch includes extensive condition checking to ensure correctness and preserves all existing output formatting capabilities.

Performance improvements are significant - the Linux kernel repository sees `rev-list --maximal-only` go from 0.70s to effectively instant (matching `merge-base --independent`), while git.git sees a 50% reduction. The patch includes tests verifying the optimization works with `--pretty` formatting and maintains all expected behavior.

This is a well-executed optimization from a known performance expert, building carefully on the test infrastructure established in the previous patches. The implementation is thorough in its safety checks and maintains all existing functionality while providing substantial speedups, particularly for large repositories.
