This is a feature patch implementing Linux filesystem monitoring (fsmonitor) support via inotify, part of a larger series bringing fsmonitor to parity across platforms. The implementation is now at v13, having undergone extensive review and testing.

The patch adds Linux-specific monitoring code that uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The implementation appears production-ready, having been tested for months in various environments.

Notable characteristics:
- Uses inotify_init1(O_NONBLOCK) with a poll loop and 50ms timeout
- Maintains bidirectional hashmaps between watch descriptors and paths
- Handles directory renames via inotify's cookie mechanism
- Detects remote filesystems via statfs() magic numbers
- Includes documentation updates about Linux-specific caveats (inotify watch limits)

This represents the core Linux implementation piece of the cross-platform fsmonitor support, with Windows and macOS implementations already in place. The code is well-structured and appears to handle edge cases thoroughly. As part of the v13 series, it has addressed all substantive review feedback and is likely nearing readiness for inclusion.
