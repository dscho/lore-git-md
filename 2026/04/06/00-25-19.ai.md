This is a test patch (4/5) in Lorenzo Pegorari's v3 series on promisor file handling during repacks, part of his GSoC work under Eric Sunshine. The patch adds test coverage for verifying `.promisor` file contents are correctly preserved during repacking operations.

The tests focus on two scenarios: single and multiple promisor pack cases. Each test creates synthetic `.promisor` files (simulating partial clone state), performs repacks, and verifies the metadata is correctly preserved in the new pack's `.promisor` file. The tests check both the preservation of original content (object IDs and refs) and the addition of timestamps in the format `<time> <oid> <ref>`. The multiple-pack test specifically verifies that metadata from all source packs is correctly merged into the new promisor file.

Key technical details for future reference:
- Tests use `test_commit_bulk` to create test packs
- Manually create `.promisor` files with `echo "$oid ref" >$prom`
- Verify content with `test_grep` and `test_cmp`
- Test paths: `t/t7700-repack.sh`
- Covers both single and multiple pack scenarios
- Verifies timestamp preservation behavior

This test patch complements the core functionality added in patches 2-3 of the series, providing concrete verification of the promisor metadata preservation behavior that was a key requirement from Junio Hamano. The tests appear thorough, covering both basic and edge cases for the new functionality.
