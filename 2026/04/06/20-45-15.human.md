This is a bugfix discussion about NULL object database handling in `git diff --no-index` with large files.

Junio C Hamano weighs in on the ongoing discussion about how to fix the segfault that occurs when running `git diff --no-index` on large files outside a repository context. He strongly agrees with Justin Tobler's position that object database (ODB) transactions should not be initiated when there is no ODB present, calling the idea of transactions without an ODB "nonsensical". 

This aligns with Tobler's earlier argument that the current code path unnecessarily starts transactions even when only streaming objects for hashing (without writing them). Junio's intervention effectively endorses Tobler's proposed solution path - modifying the hashing operation to bypass transaction overhead - over Jeff King's alternative suggestion of making the transaction system handle NULL sources gracefully.

The maintainer's position gives clear direction to the thread, favoring the more surgical approach that avoids transactions entirely for hashing operations rather than expanding transaction system capabilities. This decision will likely shape the final fix, which may draw from Tobler's existing experimental work on `hash_blob_stream()` in his `seen` branch series. The resolution now appears to be converging on removing transaction overhead from pure hashing paths while maintaining the invariant that transactions require a valid ODB.
