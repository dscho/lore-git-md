This is a bugfix patch in the fsmonitor Linux implementation series, addressing a memory leak in the daemon's client handling code. The patch fixes a case where a hash table tracking shown paths wasn't being freed when the client received a trivial response, due to the cleanup code being placed after an early return path.

The change is straightforward and well-explained: initialize the hash table pointer to NULL and move its cleanup to a shared exit path that runs in all cases. This ensures proper resource management regardless of which response path is taken. The fix demonstrates attention to detail in the fsmonitor implementation, catching a subtle resource leak that could accumulate over time in long-running daemon processes.

As part of the mature v13 series that has already addressed more complex architectural issues, this patch represents final polish on the Linux fsmonitor support. The change is small but important for production reliability, and follows the pattern of thorough edge-case handling seen throughout the series.
