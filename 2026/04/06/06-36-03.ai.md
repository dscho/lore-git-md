Bugfix for `git fast-export` output ordering. Raymond E. Pasco identifies a case where the current pathname-based output order can produce invalid fast-export streams - specifically when a deleted path is a prefix of an added path (like deleting 'a' while adding 'a/b'). The current code emits the addition before the deletion, which violates fast-import's requirement that deletions come first when they are prefixes of other paths.

The proposed fix modifies the sorting comparator to always prioritize deletions before other change types, regardless of path length. The patch is marked as WIP because the author wants to investigate whether a more targeted fix (only reordering when there's an actual prefix relationship) would be better, and plans to add tests. The change is small (6 lines) and focused on the sorting logic in `builtin/fast-export.c`.

This appears to be a legitimate bug with a straightforward fix, though the author's note about potential refinement suggests the current solution might be broader than strictly necessary. The patch touches a sensitive area (export/import streaming) where ordering matters, so test coverage will be important to verify the fix doesn't introduce new edge cases. The change is mechanical enough that it's unlikely to be controversial, but reviewers may want to see the promised tests before merging.
