This is a feature patch adding file descriptor cleanup support to Git's run-command infrastructure, part of the larger fsmonitor Linux implementation series. The patch introduces a new `close_fd_above_stderr` flag in `struct child_process` that, when enabled, automatically closes all file descriptors above stderr (FD 2) in child processes before exec.

The implementation carefully preserves the child-notifier pipe (used for process monitoring) while closing other inherited FDs, with a sensible upper bound of 4096 descriptors (or the system's `_SC_OPEN_MAX` if lower). This prevents child processes from accidentally inheriting open file handles from their parent, which could cause issues like test harness interference or resource exhaustion.

As part of the fsmonitor series, this change helps ensure clean process isolation for the filesystem monitoring daemon. The patch is straightforward and focused, with clear documentation of the new field's purpose. Given the thorough review history of the overall fsmonitor series and the careful handling of edge cases here (like the child-notifier exception), this appears to be a well-considered addition to Git's process management capabilities.
