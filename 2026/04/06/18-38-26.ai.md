This is a bugfix for the parse-options subsystem, specifically addressing how subcommand typos are reported. The patch corrects the error message shown when a user mistypes a subcommand with a single dash (like `git stash -list`).

Currently, the code always suggests adding two dashes for any mistyped option, which is incorrect for subcommands that should have no dashes. The change makes `check_typos()` check the option type and provide appropriate advice: suggesting no dashes for subcommands (OPTION_SUBCOMMAND) while keeping the two-dash suggestion for regular options.

The fix is small (4 lines changed) and well-contained to parse-options.c. It clearly addresses a real usability issue where the current behavior gives misleading advice.
