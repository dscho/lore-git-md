Performance optimization patch completing Derrick Stolee's series to make `git rev-list --maximal-only` faster by leveraging the existing `reduce_heads()` algorithm from `git merge-base --independent`. This third patch implements the actual optimization after the first two established test coverage and benchmarks.

The change adds a new `prepare_maximal_independent()` function that checks if `--maximal-only` is the only active option (no other walk modifiers or output formatting) and all input commits are positive. When these conditions are met, it replaces the full revision walk with a direct call to `reduce_heads()`, which uses the more efficient `remove_redundant()` algorithm. The function carefully preserves all other output filtering by setting `revs->no_walk` to prevent subsequent walking while still allowing the existing output machinery to handle formatting.

The patch includes a 50% speedup in git.git (0.06s to 0.03s) and a complete elimination of the overhead in the kernel repo (0.70s to 0.00s) when no other options are present. A new test case verifies that pretty-printed output continues to work correctly with the optimization. The implementation maintains all existing behavior while providing significant performance gains in the targeted case, following Stolee's characteristic thorough approach of first proving equivalence, then measuring, and finally optimizing.
