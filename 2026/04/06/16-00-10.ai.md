Junio C Hamano responds to Johannes Schindelin's test modernization patch with an alternative approach for handling bare repository access in tests. This is part of the ongoing effort to prepare for a potential future `safe.bareRepository=explicit` default.

Junio suggests a more comprehensive solution than the per-test modifications in Johannes's series. Instead of sprinkling `test_config_global safe.bareRepository all` throughout individual tests, he proposes setting this globally in `t/test-lib.sh` when `WITH_BREAKING_CHANGES` is enabled. This would allow most existing tests to continue working as-is when bare repository access becomes opt-in, since they would automatically get the permissive setting. Only new tests specifically validating the opt-in behavior would need to explicitly remove this configuration.

The maintainer emphasizes that most tests checking command behavior in bare repositories aren't actually testing the discovery mechanism itself - they're verifying how commands operate in that context. His approach would preserve this testing while making it robust against future policy changes. He draws a parallel to how tests handle the default branch name, where global configuration is often set upfront rather than modified per-test.

This response indicates Junio's preference for a more systematic solution that minimizes test churn while still supporting the eventual behavior change. His suggestion implies that Johannes's patch-by-patch approach, while technically correct, might be more granular than necessary for the preparatory work. The proposed `WITH_BREAKING_CHANGES` guard also provides a clear mechanism to enable the new behavior when the project is ready for that transition.
