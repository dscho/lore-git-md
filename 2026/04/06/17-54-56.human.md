This is a feature patch in the fsmonitor series, adding a timeout to the daemon stop command to prevent indefinite hangs. The patch is part of the larger effort to bring Linux fsmonitor support to parity with Windows and macOS implementations.

The change addresses a specific edge case where the `fsmonitor--daemon stop` command could hang forever if the daemon fails to shut down properly. The patch introduces a 30-second timeout (configurable via `max_wait_ms`) with 50ms polling intervals, after which it will return an error if the daemon is still running. This matches the robust error handling seen throughout the rest of the fsmonitor implementation.

The implementation is straightforward - tracking elapsed time during the polling loop and bailing out if the timeout is exceeded. It maintains the existing tracing and error reporting patterns used elsewhere in the codebase. This appears to be a well-contained, focused improvement to an already mature feature set.

As part of the v13 series that has undergone extensive review, this patch represents one of the final refinements to the fsmonitor implementation. The series as a whole has demonstrated careful attention to edge cases and platform compatibility, and this change continues that pattern by addressing a potential hang scenario.
