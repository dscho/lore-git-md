This is a feature patch series implementing Linux filesystem monitoring (fsmonitor) support via inotify, bringing it to parity with existing Windows and macOS implementations. The series also includes memory leak fixes and IPC/settings deduplication.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. Key technical aspects include non-blocking event polling, recursive watch registration, and mount point detection via /proc/mounts. The series has undergone extensive testing across 13 iterations, with v13 specifically resolving the split-index interaction by disabling GIT_TEST_SPLIT_INDEX in scalar clone tests rather than modifying core behavior.

The patch set demonstrates thorough engineering with attention to edge cases (stale renames, watch limits, remote filesystems) and platform compatibility (Windows pthread emulation). It builds on prior work from Eric DeCosta and Marziyeh Esipreh, now addressing all substantive review feedback. The implementation appears production-ready, having been tested for months in various environments.

Notable changes in v13:
- Drops earlier split-index workarounds in favor of test-only solution
- Maintains the fundamental design decision that split-index and index.skipHash are incompatible
- Matches existing test 16 workaround pattern in t9210

The series represents a significant step in completing cross-platform fsmonitor support, with Linux being the last major platform to gain native implementation. The careful handling of technical constraints (privileges, performance, edge cases) and thorough test coverage suggest this is a high-quality contribution likely to be well-received.
