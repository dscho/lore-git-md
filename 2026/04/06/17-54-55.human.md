This is a process isolation patch in the fsmonitor series, addressing file descriptor handling and daemon detachment. It's part of the v13 series bringing Linux fsmonitor support to parity with Windows/macOS implementations.

The patch ensures the fsmonitor daemon properly cleans up inherited file descriptors when spawned, preventing hangs in parent processes (particularly in test harnesses and CI systems) that might be waiting on pipes the daemon doesn't need. It also adds proper session detachment on Unix systems to prevent shell job control from blocking on the daemon.

Key changes:
- Sets `close_fd_above_stderr` in both explicit (`fsmonitor--daemon start`) and implicit (client-triggered) spawn paths
- Silences stdout/stderr on implicit spawn to avoid terminal pollution
- Adds `setsid()` call for proper Unix process group detachment
- Maintains Windows console detachment behavior

The changes are focused and well-explained, with clear rationale for each modification. This appears to be a final polish on the fsmonitor daemon's process isolation, building on the extensive work already done in previous patches of the series. The implementation looks solid and addresses real-world issues seen in testing environments.
