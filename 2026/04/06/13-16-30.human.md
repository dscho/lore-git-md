Feature addition to `git backfill` with progress reporting, now with feedback from Derrick Stolee.

This is a follow-up to Trieu Huynh's initial patch adding `--[no-]progress` support to `git backfill`. Derrick Stolee provides detailed feedback suggesting the current implementation may not fully address the command's output behavior. He notes that `git backfill` is already quite verbose by default (showing batch fetch details from the server), and suggests the progress meter should track objects rather than batches. 

Stolee requests seeing the actual output with/without the changes before proceeding, and raises concerns about:
1. The progress meter showing batch counts rather than object counts
2. Potential interaction issues with recent rev-list option changes
3. Missing test coverage for TTY progress behavior (pointing to existing test patterns in t9211-scalar-clone.sh)

The patch appears well-intentioned but may need reworking to better match the command's actual output characteristics and user expectations. Stolee's feedback suggests the progress reporting should either replace or meaningfully augment the existing verbose output rather than just adding another layer. This will likely require a revised approach in the next iteration.
