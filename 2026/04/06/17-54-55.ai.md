This is a process isolation patch in the fsmonitor series, specifically addressing file descriptor handling in the fsmonitor daemon. The patch ensures proper cleanup of inherited file descriptors when the daemon starts, both in explicit "start" commands and implicit spawns when no daemon is running.

Key changes:
- Adds `close_fd_above_stderr` to child processes in both startup paths (explicit and implicit)
- Suppresses stdout/stderr in implicit spawns to prevent background output
- Implements proper session detachment via `setsid()` on Unix systems when running with `--detach`
- Maintains Windows console detachment behavior

The changes address potential hangs when the daemon inherits pipe FDs from test harnesses/CI systems, and prevent shells from waiting on implicitly spawned daemons. This is part of the broader fsmonitor effort to bring Linux support to parity with Windows/macOS, now in its 13th iteration with all major technical issues resolved.

The patch demonstrates careful attention to cross-platform process management and edge cases in daemon startup. It complements the series' existing focus on robustness and resource cleanup, with the implementation appearing well-considered and production-ready.
