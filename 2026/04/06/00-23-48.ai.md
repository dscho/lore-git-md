This is a v3 patch series addressing promisor file handling during repacks, part of Lorenzo Pegorari's GSoC work under Eric Sunshine. The series has been significantly reworked from v2 to address Junio Hamano's concerns about geometric repacking interactions and timestamp preservation.

The core change preserves debugging information in `.promisor` files when repacking promisor packfiles, solving the `NEEDSWORK` from commit 5374a290. The v3 redesign introduces several key improvements: timestamp preservation for debugging, proper handling of partial repacks (particularly in geometric repacking scenarios), and an ignorelist for excluded packs. The implementation now checks if each object appears in the new pack before copying its promisor metadata, ensuring accurate mapping even when some packs remain untouched.

The series consists of 5 patches (up from 4 in v2):
1. Documentation explaining `.promisor` file contents (unchanged from v2)
2. New helper function `copy_promisor_content()` that handles the metadata copying with timestamp preservation
3. Integration of the helper into the repack logic with geometric repack awareness
4-5. Expanded test coverage in both regular and geometric repack scenarios

The author notes the implementation adds minimal overhead (~0.5% in testing with large repos) while providing proper debugging information preservation. The series demonstrates good responsiveness to prior feedback, particularly around geometric repack edge cases and timestamp preservation that Junio highlighted. The test expansion to cover geometric repacks (t7703) is particularly important given the context of Taylor Blau's ongoing geometric repacking work.

Key technical details for future reference:
- New `copy_promisor_content()` helper in `repack-promisor.c`
- Timestamp format: `<time> <oid> <ref>` lines in `.promisor` files
- `promisor_ignorelist` for handling excluded packs
- Modified files: `pack-write.c`, `repack-promisor.c`, test scripts
- Performance impact measured at ~0.5% overhead for large repos

The series appears well-considered and addresses the core concerns raised in previous rounds. The geometric repack testing suggests it should integrate cleanly with that ongoing work, making this likely to progress toward merging once any final review feedback is addressed.
