Bugfix for cache-tree validation logic.

This patch corrects an inverted condition in `cache_tree_fully_valid()` that was causing the function to return incorrect results when checking tree object existence. The function is meant to mark cache tree nodes as invalid when their corresponding objects are missing from the object database, but the current implementation does the opposite - it considers them valid when missing.

The fix simply adds a negation to the `odb_has_object()` check. The patch includes a new test case that verifies `write-tree` properly uses a valid cache-tree (though the test appears to be more about demonstrating correct behavior than directly testing the bugfix). The change is small but important for maintaining cache consistency when objects are missing.

The patch touches core functionality (cache-tree validation) but is narrowly scoped to fix a clear logic error. The test addition provides some coverage, though it might be worth considering a more direct test of the fixed condition in future iterations.
