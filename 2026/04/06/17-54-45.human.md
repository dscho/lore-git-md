This is a feature patch series implementing Linux filesystem monitoring (fsmonitor) support, now at version 13. The series brings Linux fsmonitor to parity with existing Windows and macOS implementations using inotify, while also fixing memory leaks and deduplicating shared IPC/settings code.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename tracking, and remote filesystem detection. The series has undergone extensive testing and iteration, with v13 specifically resolving the split-index/index.skipHash interaction by adopting a test-only solution (disabling GIT_TEST_SPLIT_INDEX in scalar clone tests) that maintains both features' functionality while avoiding their problematic combination.

Key technical aspects include:
- Recursive directory watching with IN_MASK_CREATE
- Rename tracking via inotify cookies
- Remote filesystem detection using statfs()
- Poll loop with 50ms timeout to minimize CPU usage
- Memory leak fixes in khash and hashmap usage
- Windows compatibility via pthread emulation
- Test hardening against hangs and edge cases

The series appears mature and well-tested, having addressed all substantive technical feedback over 12 previous iterations. With maintainer approval of the split-index resolution approach, this looks ready for final consideration. The implementation brings a long-awaited feature to Linux users while maintaining Git's cross-platform consistency.
