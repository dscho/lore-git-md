Bugfix discussion for `git diff --no-index` segfault with large files outside a Git repository.

Justin Tobler responds to Jeff King's proposal about handling NULL object databases in the transaction system, providing additional context from his ongoing work. The segfault occurs when comparing large files with `--no-index` because the code attempts to start an object database transaction even when only streaming/hashing is needed (no actual object storage).

Tobler identifies two potential solutions: 1) his in-progress patch series introduces a dedicated `hash_blob_stream()` helper that bypasses transactions entirely for pure hashing operations, which already fixes this issue in his local testing, or 2) Jeff King's suggestion to make the transaction system handle NULL sources gracefully. Tobler expresses preference for the first approach, arguing there's no good reason to support transactions without an actual object database.

The discussion remains technical but has narrowed to these two approaches, with Tobler offering to extract his fix from his larger series if the community prefers that direction. His response provides important context about the original design intent of the transaction system and suggests the current bug stems from an unconsidered edge case in repository-less operations.

This moves the thread closer to resolution, with clear technical alternatives now on the table. The decision point appears to be whether to implement a targeted fix (Tobler's approach) or a more systemic change to transaction handling (King's approach). Both solutions would prevent the segfault while taking different architectural paths.
