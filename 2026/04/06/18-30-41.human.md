Bugfix targeting the promisor-remote subsystem, part of the ongoing `the_repository` removal effort.

This patch fixes a case where `fetch_objects()` incorrectly reads the `promisor.quiet` config from `the_repository` global instead of the passed-in `repo` parameter. The issue manifests when performing operations (like `git grep --recurse-submodules`) on a superproject where a submodule is a partial clone - the submodule's own `promisor.quiet` setting would be ignored in favor of the superproject's setting.

The fix is straightforward - just pass the correct repository parameter to `repo_config_get_bool()`. The patch includes a thorough test case that verifies the fix by:
1. Setting up a superproject with a partial-clone submodule
2. Configuring `promisor.quiet` only in the submodule
3. Verifying that a lazy fetch triggered by grep respects the submodule's setting

This appears to be a clean, well-motivated fix that addresses a specific gap in the earlier `the_repository` removal work (as noted in the referenced 5d215a7b3e commit). The test coverage is comprehensive and the change itself is minimal and focused.
