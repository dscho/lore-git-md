This is the fourth patch in Lorenzo Pegorari's v3 series about promisor file handling during repacks, part of his GSoC project mentored by Eric Sunshine. The patch adds test coverage for the `.promisor` file content copying behavior introduced in earlier patches.

The tests verify two scenarios:
1. Single pack case: Checks that repacking preserves the original `.promisor` content (with timestamps) when converting from one pack to another
2. Multiple packs case: Verifies the same behavior when merging multiple packs, ensuring all original promisor metadata is preserved in the combined output

The test setup manually creates `.promisor` files to simulate partial clone state, then verifies the repack operation maintains the expected content format (`<oid> <ref> <timestamp>`). The tests use `test_grep` and `test_cmp` to validate both the content and exact preservation across multiple repacks.

This is a straightforward test addition that complements the functionality implemented in patches 2-3. The tests appear well-constructed, covering both basic and multi-pack scenarios, and follow Git's test script conventions. As the final patch in the series approaches, this test coverage helps ensure the geometric repack integration works as intended.
