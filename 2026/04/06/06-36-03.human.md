This is a bugfix patch targeting `git fast-export`'s output ordering. The author, Raymond E. Pasco, identifies a case where the current pathname sorting can produce invalid output: when deleting a file that's a prefix of a newly created file (like deleting 'a' while creating 'a/b'), the commands are emitted in the wrong order.

The patch proposes a simple solution - always sorting deletions before other changes in the output. The change is minimal (6 lines added to the depth-first comparison function) but the author notes this might be too broad and plans to refine it further, possibly by only reordering when there's an actual prefix conflict, along with adding tests.

The patch is marked as WIP (Work In Progress), indicating the author expects to send follow-up revisions. While the current solution appears correct for the described case, the author's planned refinements suggest this initial version may not be the final approach. The change touches a sensitive area (export format compatibility) but is narrowly scoped to fix a clear edge case.
