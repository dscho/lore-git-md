Performance optimization patch from Derrick Stolee, part 2/3 in a series to make `git rev-list --maximal-only` faster by leveraging the algorithm from `git merge-base --independent`. This patch adds a performance test to measure the current difference between these commands.

The new test script `t/perf/p6011-rev-list-maximal.sh` demonstrates that `merge-base --independent` is significantly faster than `rev-list --maximal-only` in both git.git (0.03s vs 0.06s) and the Linux kernel repository (0.00s vs 0.70s). The test also includes a case with `--since` to ensure the generic walk logic remains measurable after the optimization.

The test setup creates a list of 50 commits from refs and writes a commit-graph before running the three timing cases. This follows Stolee's typical thorough benchmarking approach for performance-sensitive changes. The results clearly show the performance gap the series aims to close, with the Linux kernel case showing particularly dramatic differences due to its reference topology.
