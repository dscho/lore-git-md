This is a platform compatibility patch in the fsmonitor series, specifically addressing Windows pthread emulation. It modifies the fsmonitor daemon's cookie wait mechanism to use `pthread_cond_timedwait()` with a one-second timeout instead of an infinite wait, preventing hangs on container/overlay filesystems where inotify events may not be delivered.

The change replaces the previous `pthread_cond_wait()` loop with a timeout-based version that:
- Uses `gettimeofday()` to calculate a one-second timeout
- Properly handles `ETIMEDOUT` by setting an error result
- Includes Windows compatibility via `SleepConditionVariableCS()` emulation
- Maintains the same locking semantics while adding timeout safety

The patch demonstrates careful cross-platform consideration, with attention to edge cases like filesystems that accept inotify watches but fail to deliver events. It builds on the established fsmonitor IPC protocol where timeout cases fall back to a full scan rather than blocking indefinitely. The implementation matches the series' overall quality, with clear error handling and trace logging for debugging.
