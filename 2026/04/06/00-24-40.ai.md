This is a documentation patch from Lorenzo Pegorari, part of his GSoC work on promisor file handling during repacks (v3 patch 1/5). The patch adds a clarifying comment to `pack-write.c` explaining the purpose of ref names and hashes stored in `.promisor` files.

The comment documents that these ref names and hashes (written by `fetch-pack`) serve only for debugging partial clone issues, allowing comparison between what was fetched originally and what the promisor remote currently reports. This matches the original motivation from commit 5374a290 but was previously undocumented in the code itself. The patch is straightforward and uncontroversial, simply adding explanatory text without changing any behavior.
