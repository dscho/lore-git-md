This is a maintainer response rejecting a proposed configurable detach behavior for `git switch`. Junio C Hamano expresses strong opposition to the RFC patch that would add a `checkout.switchDetach` option to make `git switch` behave like `git checkout` when given commit hashes.

Junio argues that `git switch` was intentionally designed without implicit detach behavior as an improvement over `git checkout`, specifically to provide a simpler, more focused command that only switches branches. He views adding configurability to reintroduce detach behavior as counterproductive to this design goal, undermining the command's pedagogical value. 

The response makes clear that `git checkout` remains available for users who want the detach-on-hash behavior, and that this functionality isn't going away. This effectively closes the discussion by rejecting the premise of the patch rather than engaging with its technical implementation details. The position is that the current behavior is by design and shouldn't be made configurable.
