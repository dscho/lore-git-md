This thread addresses a bug in how Git reads the `promisor.quiet` configuration during submodule operations in partial clone scenarios. The core issue - where Git was incorrectly using the superproject's config instead of the submodule's - was fixed by Trieu Huynh in a patch that replaces `the_repository` with the proper repository parameter in `fetch_objects()`. This is part of the ongoing effort to eliminate the `the_repository` global variable.

While the technical fix works correctly, verifying it has proven tricky. The test case, which checks trace output for the "--quiet" string, passes in some environments (including Junio's and GitHub CI) but fails in Tian Yuchen's Ubuntu 24.04 setup. Trieu confirmed the grep pattern syntax is correct, suggesting the issue lies in environment-specific trace output formatting rather than the test itself. 

Junio has now checked in to nudge the discussion toward resolution. The core fix remains valid - the only open item is whether to adjust the test pattern for cross-platform robustness or accept the environment-specific behavior. This case highlights the challenges of testing configuration-dependent behavior, particularly when relying on trace output patterns that may vary across systems.
