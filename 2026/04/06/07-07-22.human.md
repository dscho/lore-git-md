Platform compatibility follow-up questioning OpenSSL version diagnosis. René Scharfe responds to Randall S. Becker's report of OpenSSL 3.0 build failures in Git 2.54.0-rc0, casting doubt on whether the reported errors actually come from OpenSSL 3.0.

Scharfe points to OpenSSL commit history showing that both the const-correctness issue (X509_NAME_ENTRY_get_data) and the missing function (ASN1_STRING_get0_data) were addressed in OpenSSL 1.1.0 and 1.1.1 respectively - long before OpenSSL 3.0. The errors Becker describes would only occur with pre-1.1.0 OpenSSL versions, suggesting either a version misidentification or an unusually configured OpenSSL 3.0 build.

This is a technically precise response from a frequent contributor known for careful code analysis. Scharfe doesn't propose a fix but provides clear evidence that the root cause may differ from Becker's initial assessment. The exchange highlights Git's ongoing challenges with OpenSSL version compatibility, particularly for enterprise environments running older but still-supported versions.
