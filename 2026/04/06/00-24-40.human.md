This is a documentation patch from Lorenzo Pegorari's GSoC work on promisor file handling during repacks. It's the first of five patches in the v3 iteration, unchanged from previous versions.

The patch adds a clear explanatory comment to `pack-write.c` about the purpose of ref names and hashes stored in `.promisor` files. These debugging aids were introduced in commit 5374a290 but lacked documentation until now. The comment explains that while this metadata isn't used in normal operations, it helps diagnose partial clone issues by recording what refs were fetched when each packfile was downloaded.

As part of a larger series addressing promisor pack repacking, this foundational documentation patch provides important context for the subsequent implementation changes. The comment is well-written and directly addresses a gap noted in the original implementation. Since this is documentation-only and uncontroversial, it's likely to be accepted as-is.
