Bugfix discussion about NULL object database handling in `git diff --no-index` with large files.

Justin Tobler responds to Jeff King's proposal about handling NULL object databases in the transaction system, providing additional context about the root cause and suggesting an alternative solution path. The issue occurs when `git diff --no-index` processes files larger than `core.bigFileThreshold` outside a repository context, triggering a NULL dereference in the object-file.c` transaction handling code.

Tobler identifies that the current code path unnecessarily starts an ODB transaction even when only streaming objects for hashing (without writing them), which he considers questionable design. He references an in-progress patch series that introduces a separate `hash_blob_stream()` helper to bypass transaction overhead for pure hashing operations, noting this approach would also fix the immediate segfault. While this series is currently only in the experimental `seen` branch, Tobler offers to extract the relevant patch as a standalone fix if preferred.

The email presents two potential solutions: 1) Tobler's preferred approach of avoiding transactions entirely for hashing-only operations (which aligns with his ongoing work), or 2) Jeff King's suggestion to make the transaction system handle NULL sources gracefully. Tobler expresses skepticism about the second approach, questioning whether there's any valid use case for transactions without an object database. He notes his patch series demonstrates the hashing operation can work safely without transaction infrastructure.

Key technical details include the reproduction case (using `core.bigFileThreshold=1` to force the streaming path), the problematic call chain through `index_fd()` and `index_blob_packfile_transaction()`, and the distinction between hashing and writing operations. The discussion now hinges on whether to adopt a surgical fix that changes the hashing path's behavior or a more systemic change to transaction handling that might affect other code paths.
