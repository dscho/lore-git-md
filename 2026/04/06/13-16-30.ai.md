Feature addition to `git backfill` with progress reporting discussion.

Derrick Stolee responds to Trieu Huynh's patch adding `--[no-]progress` to `git backfill`, pointing out that the current behavior isn't actually silent - it shows verbose output from the remote for each batch fetch. He suggests demonstrating the full output with and without the change to better understand the impact.

Key technical points raised:
1. The patch currently tracks batches rather than objects in the progress meter, which may not be the most useful metric
2. There's potential value in replacing the verbose remote output with a progress indicator instead
3. The tests should verify TTY behavior using the `TTY` prerequisite like other Git tests
4. The progress implementation should be checked for compatibility with recent rev-list option changes

Stolee provides example output showing the current verbose batch-by-batch progress from the remote, suggesting this context is important for evaluating the patch's value. The discussion is moving toward clarifying whether progress reporting should supplement or replace the existing output, and what metrics would be most useful to track.
