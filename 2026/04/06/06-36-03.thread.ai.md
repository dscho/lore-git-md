Thread identity: Bugfix for `git fast-export` output ordering affecting path deletions that are prefixes of added paths.

Core problem: Current pathname-based output ordering in `git fast-export` can produce invalid streams when a deleted path is a prefix of an added path (e.g. deleting 'a' while adding 'a/b'), violating fast-import's requirement that prefix deletions come first. The issue is in the sorting comparator in `builtin/fast-export.c`, independent of symlinks which were initially thought to be involved.

Current status: Raymond E. Pasco has proposed a WIP patch modifying the sorting to prioritize deletions before other changes. Jeff King (Peff) has provided historical context showing this issue has surfaced at least three times before (2015, 2017, 2023) and confirmed the technical direction. Elijah Newren has strengthened the case for exporter-side ordering with insights about `fast-import` behavior. The discussion has established clear technical consensus that the exporter-side ordering change is correct.

Key technical details: The change affects `compare_paths` in `builtin/fast-export.c`. `fast-import` processes commands strictly in the order received without special handling for path prefixes, placing full responsibility on the exporter for correct ordering. The symlink case that originally surfaced the issue was a red herring - the fundamental problem is path prefix relationships between deletions and additions. Peff notes a test case exists from prior discussions that could help validate the fix, though writing a new test would also be straightforward.

Open questions: Whether to keep the broad deletion-first approach or implement precise prefix detection. Tests still need to be added to verify the fix. Junio C Hamano's earlier question about whether `depth_first()` is the right place for this logic remains to be addressed in the final patch.

Participant positions: Raymond E. Pasco identified the bug and proposed the initial fix. Jeff King provided crucial historical context and confirmed the technical direction, noting this matches prior cases where directory symlinks were converted to real directories. Elijah Newren contributed key insights about `fast-import` behavior and documentation. Junio C Hamano raised architectural questions about function placement that need resolution.

Related work: Similar directory/file conflict fixes exist in `git checkout` and `git am`. The change touches the git-fast-import/export streaming which has strict ordering constraints. This is part of a long-standing pattern of path ordering issues, with prior discussions in 2015, 2017, and 2023 that didn't reach resolution due to edge case concerns. The current discussion appears headed toward a resolution with exporter-side ordering.
