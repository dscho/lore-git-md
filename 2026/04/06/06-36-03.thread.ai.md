Thread identity: Bugfix for `git fast-export` output ordering affecting path deletions that are prefixes of added paths.

Core problem: Current pathname-based output ordering in `git fast-export` can produce invalid streams when a deleted path is a prefix of an added path (e.g. deleting 'a' while adding 'a/b'), violating fast-import's requirement that prefix deletions come first. The issue is in the sorting comparator in `builtin/fast-export.c`, independent of symlinks which were initially thought to be involved.

Current status: Raymond E. Pasco has proposed a WIP patch modifying the sorting to prioritize deletions before other changes, with follow-up clarification that the core issue is about path prefixes rather than symlinks. Jeff King (Peff) provided historical context showing this issue has surfaced at least three times before (2015, 2017, 2023). Elijah Newren confirmed `fast-import` uses last-entry-wins semantics and its documentation recommends `filedeleteall` come first, strengthening the case for exporter-side ordering. The latest email confirms `fast-import` has no compensating logic for path prefixes, making exporter-side ordering mandatory.

Key technical details: The change affects `compare_paths` in `builtin/fast-export.c`. `fast-import` processes commands strictly in the order received without special handling for path prefixes, placing full responsibility on the exporter for correct ordering. The symlink case that originally surfaced the issue was a red herring - the fundamental problem is path prefix relationships between deletions and additions. Consensus is forming that prioritizing deletions first is correct despite edge cases with renames.

Open questions: Whether to keep the broad deletion-first approach or implement precise prefix detection. Tests still need to be added to verify the fix. The remaining architectural question about whether `depth_first()` is the right place for this logic needs resolution from Junio C Hamano.

Participant positions: Raymond E. Pasco identified the bug, proposed the initial fix, and clarified the symlink confusion. Junio C Hamano raised architectural questions about function placement. Jeff King provided crucial historical context and favored the fix while acknowledging design questions. Elijah Newren strengthened the technical case for exporter-side ordering with insights about `fast-import` behavior and documentation. No objections to the deletion-first approach have been raised.

Related work: Similar directory/file conflict fixes exist in `git checkout` and `git am`. The change touches the git-fast-import/export streaming which has strict ordering constraints. This is part of a long-standing pattern of path ordering issues, with prior discussions in 2015, 2017, and 2023 that didn't reach resolution due to edge case concerns.
