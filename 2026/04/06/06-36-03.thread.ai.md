Thread identity: Bugfix for `git fast-export` output ordering affecting path deletions that are prefixes of added paths.

Core problem: Current pathname-based output ordering in `git fast-export` can produce invalid streams when a deleted path is a prefix of an added path (e.g. deleting 'a' while adding 'a/b'), violating fast-import's requirement that prefix deletions come first. The issue is in the sorting comparator in `builtin/fast-export.c`, independent of symlinks which were initially thought to be involved.

Current status: Raymond E. Pasco has proposed a WIP patch modifying the sorting to prioritize deletions before other changes, with follow-up confirming this approach works with existing rename handling (commit 4ce6fb80). Jeff King (Peff) provided historical context showing this issue has surfaced at least three times before (2015, 2017, 2023). Elijah Newren strengthened the case for exporter-side ordering with insights about `fast-import` behavior. Technical consensus is established that exporter-side ordering is correct. Pasco is now focusing on comprehensive round-trip tests to verify the fix.

Key technical details: The change affects `compare_paths` in `builtin/fast-export.c`. `fast-import` processes commands strictly in order without special handling for path prefixes. The solution builds on existing depth-based sorting that already handles directory/symlink cases. The fix has implications for hash function migration workflows once `fast-import` gains commit/tag signing support, as users may use `fast-export | fast-import` for repository conversion.

Open questions: Tests still need to be added to verify the fix. Junio C Hamano's earlier question about whether `depth_first()` is the right place for this logic remains to be addressed in the final patch. The reference to hash function migration raises the question of whether additional test cases should cover that future use scenario.
