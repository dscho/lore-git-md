This is the second patch in Patrick Steinhardt's v2 series introducing the `git history fixup` subcommand, focusing on refactoring internal infrastructure to support the new functionality.

The patch generalizes the existing `commit_tree_with_edited_message_ext()` function into a more flexible `commit_tree_ext()` that accepts a flags parameter. The key change is making message editing optional via a new `COMMIT_TREE_EDIT_MESSAGE` flag, while maintaining all other functionality (parent handling, header stripping, etc.). This prepares the codebase for the fixup command's needs where message editing isn't always required.

The refactoring is mechanical and well-contained:
- Introduces the new flags enum
- Splits message editing into a conditional block
- Updates all callers to pass the new flag
- Maintains identical behavior when the edit flag is set

This change directly supports the series' goal by providing the plumbing needed for the fixup operation's tree commits. The implementation appears solid with thorough updates to all existing call sites. As an infrastructure patch in a well-tested series, it's unlikely to be controversial.
