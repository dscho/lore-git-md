Michael verifies that the suggested workaround using `alias.pull.sub.command` syntax does function, but notes this doesn't help users who already have the old aliases configured. His confirmation that the proposed solution would work for his use case helps validate René's technical approach. The email also provides useful context about how hierarchical aliases were discovered and adopted in practice, despite not being formally documented.

The thread appears to be converging on a solution that would restore most broken aliases while maintaining the new functionality, with the edge case of `.command` suffixes being the only remaining backward compatibility casualty. Michael's input as the original reporter helps confirm this resolution path would address real-world usage.
