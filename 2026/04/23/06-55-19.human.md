This is a follow-up discussion about a bug in the new `git history fixup` command where file deletions aren't being properly incorporated into the target commit. Patrick Steinhardt acknowledges Tian Yuchen's report showing that when deleting a file and using `fixup` to amend the change to an earlier commit, the target commit appears empty in the log output.

Patrick suggests this behavior might be acceptable with the right controls, proposing an approach similar to `git rebase`'s `--empty` option that lets users choose how to handle empty commits (drop, keep, or stop). This indicates the current behavior may be intentional rather than a bug, though the discussion is still open-ended.

The exchange shows active engagement with user feedback on this experimental feature, with the author considering how to best handle edge cases in the command's behavior. The thread remains unresolved regarding whether to treat this as a bug to fix or as expected behavior that needs better user control.
