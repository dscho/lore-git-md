Feature: Subcommand autocorrection for git-remote and git-notes

This patch enables autocorrection for mistyped subcommands in `git-remote` and `git-notes` by adding the `PARSE_OPT_SUBCOMMAND_AUTOCORRECT` flag to their parse-options setup. The change builds on the core autocorrection infrastructure introduced earlier in the series, which has already been approved by Junio Hamano.

The implementation removes manual error handling for unknown subcommands from both commands, letting the parse-options machinery handle this case uniformly. The patch demonstrates the safety of this change - both commands either resolve to a single subcommand or take no subcommand at all, so any unknown argument must be a mistyped subcommand.

This is the final implementation step in a well-reviewed series that has progressed through six iterations. The autocorrection behavior matches Git's existing command autocorrection system, providing a consistent user experience whether the typo is in a main command or subcommand. With all tests passing and maintainer approval received, this appears ready for merging.
