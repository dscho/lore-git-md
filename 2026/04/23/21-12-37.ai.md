Bugfix for hierarchical alias regression in Git 2.54.0. Jeff King (Peff) confirms the reported issue where dot-separated aliases like `pull.sub` stopped working after working in 2.53.0, identifying it as an unintended side effect of the new three-level alias syntax introduced in commit ac1f12a9de.

The regression occurs because Git now interprets `alias.pull.sub` as trying to set a "sub" key under the "pull" alias rather than treating it as a single command name. Peff provides both a short-term workaround (using the new `[alias "pull.sub"]` syntax) and proposes a fix that would restore backward compatibility while maintaining the new functionality.

The proposed patch modifies the alias parsing logic to fall back to the old behavior when encountering an unknown subsection key, though it notes this would still break any historical aliases that happened to be named `foo.command`. The fix demonstrates careful consideration of backward compatibility while addressing the core issue.

This is a clear regression affecting a documented feature, and Peff's response suggests it will likely be fixed in a maintenance release. The analysis is thorough, identifying both the root cause and edge cases while providing immediate relief for affected users.
