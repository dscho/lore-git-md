This is a refactoring series (v2) from Karthik Nayak that continues the ongoing effort to consolidate logic from Git's reference backends into the generic layer. The 9-patch series builds on previous work to standardize behavior across the files, packed, and reftable backends.

The key changes in this iteration:
- Introduces a `ref_store_init_options` struct to standardize backend initialization (split from v1's combined patch)
- Moves object validation and peeling logic out of individual backends into the generic refs layer
- Adds a `peeled` field to `ref_update` to handle tag peeling consistently
- Improves error handling in `update-ref` to catch validation failures earlier

The series has received thorough review from Patrick Steinhardt, with Karthik accepting all technical feedback. The only remaining discussion point is a stylistic preference around typedef usage (Karthik prefers keeping them while Patrick suggested removal), which doesn't block the technical changes.

This is a well-structured series that continues the project's architectural work to reduce backend-specific behavior. The changes are mechanical but important for consistency, particularly around object validation which could previously differ subtly between backends. The v2 iteration shows good responsiveness to review feedback, making this likely ready for merging once the final wording tweaks are incorporated.
