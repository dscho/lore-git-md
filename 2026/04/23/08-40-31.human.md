This is part 2 of Karthik Nayak's refactoring series to consolidate reference backend logic, now in its third iteration (v3). The patch introduces a new `ref_store_init_options` struct to standardize how reference backends are initialized, moving the direct `flags` parameter into this structure. This change affects all three backend implementations (files, packed, and reftable) and sets up the infrastructure for future backend configuration options.

The patch is a mechanical change that:
1. Defines the new struct ref_store_init_options in refs-internal.h
2. Updates all backend init functions to accept the options struct instead of raw flags
3. Modifies the core ref_store_init() function to construct and pass the options

This work continues the multi-year effort to reduce backend-specific behavior, with Patrick Steinhardt providing thorough review feedback that has been incorporated across the series. The changes here are uncontroversial plumbing work that paves the way for more substantial backend unification in later patches. The series as a whole is part of Git's ongoing ref storage modernization, building on previous reftable integration work.
