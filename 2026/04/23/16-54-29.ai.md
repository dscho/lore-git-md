This is part of the ongoing `the_repository` removal effort, specifically migrating the `core.precomposeunicode` configuration from a global variable to repository-specific storage in `struct repo_config_values`. The patch continues Olamide Caleb Bello's v3 configuration migration series, now handling Unicode path normalization settings that are particularly relevant for macOS compatibility.

The change moves the `precomposed_unicode` setting into per-repository configuration while maintaining its eager parsing behavior, which is critical for consistent filesystem operations on macOS. The patch updates four files - primarily the precompose_utf8 compatibility layer - to reference the new location of this setting. A notable improvement is changing the variable type from `int` to `bool` to better match its actual usage as a boolean value.

The modifications follow the established pattern seen in previous configuration migrations in this series, with mechanical updates to access the configuration through `repo_config_values(the_repository)` rather than directly via the global variable. The changes are straightforward and well-contained, touching only the necessary call sites while preserving all existing behavior.

This continues the incremental progress on eliminating global configuration variables, with particular attention to maintaining the special macOS filesystem handling that depends on this setting. The patch appears technically sound and properly documented, following positive feedback from mentors Christian Couder and Usman Akinyemi on earlier versions of the series.
