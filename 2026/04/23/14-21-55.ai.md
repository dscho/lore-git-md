This is version 2 of Patrick Steinhardt's patch series introducing a `git history fixup` subcommand, building on his ongoing work with the experimental `git history` command. The series now consists of 3 patches (up from 2 in v1) and addresses empty commit handling - a key issue raised in review of the initial version.

The new subcommand allows amending staged changes to an existing commit (similar to `git commit --fixup`) while automatically rebasing dependent branches. The main changes in v2:

1. Added a new first patch that generalizes empty commit handling in the underlying replay infrastructure
2. Introduced `--empty=(keep|drop|abort)` option to control behavior when commits become empty during fixup operations
3. Improved documentation to clarify the three-way merge behavior and empty commit scenarios

Key technical details:
- Uses merge-ort for tree merging
- Handles two empty commit cases: when the target becomes empty, and when descendants become empty during replay
- Includes extensive test coverage (680+ lines in t3453-history-fixup.sh)
- Documents limitations (no bare repo support, aborts on merge conflicts)

The implementation appears robust with thorough test coverage. The empty commit handling addresses Tian Yuchen's earlier feedback about file deletion edge cases. The documentation improvements respond to D. Ben Knoble's review requesting clearer explanations of user-visible behavior.

This version maintains the same core functionality while adding configurability around empty commits - a thoughtful response to review feedback. The series continues Patrick's pattern of careful, well-tested additions to the history command.
