This is part 6 of Karthik Nayak's refactoring series to consolidate reference backend logic, specifically focusing on error handling in `git update-ref`. The patch modifies how `update-ref` processes rejected updates when using `--batch-updates`, preparing for future validation improvements in the ref transaction system.

The key change is introducing a `command_options` struct to track whether individual update failures should be fatal (controlled by `--batch-updates`), and modifying the various command parsers (`parse_cmd_update`, `parse_cmd_symref_update`, etc.) to handle non-generic rejection errors appropriately. When updates are allowed to fail, the patch ensures rejected refs are properly reported to the user without terminating the entire operation.

This continues the series' pattern of moving backend-specific behavior into shared infrastructure while maintaining existing user-facing behavior. The changes are mechanical but important for the larger goal of standardizing ref transaction error handling across all backends. As with previous patches in the series, this has received thorough review from Patrick Steinhardt and fits cleanly into the ongoing ref backend consolidation effort.
