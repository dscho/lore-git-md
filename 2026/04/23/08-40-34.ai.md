This is a refactoring patch (part 5/9 in v2) from Karthik Nayak that moves the `print_rejected_refs()` function earlier in `builtin/update-ref.c` to avoid needing a forward declaration in a subsequent patch. The change is purely mechanical - the function's implementation remains identical, just relocated to appear before its future callers.

The patch is part of a larger series standardizing reference backend behavior by moving common functionality like object validation and error handling into the shared refs layer. This particular change prepares for upcoming modifications to the error reporting infrastructure in `update-ref`.

The relocation follows standard C practice of declaring functions before use, and the patch maintains all existing behavior. Since this is a straightforward code movement with no functional changes, it's unlikely to generate much discussion beyond the ongoing review of the series as a whole.
