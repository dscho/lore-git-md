This is a feature patch adding a new configuration option to control progress reporting during `git push`.

Harald Nordgren proposes adding a `push.showProgress` config option that lets users control whether progress output (the "Enumerating/Counting/Compressing/Writing objects" messages) is shown by default during push operations. The motivation is that some users find the default output excessive, and while `--no-progress` exists as a command-line option, there's currently no way to make this the default behavior. The new config option provides that control while still allowing command-line overrides with `--progress` or `--no-progress`.

The implementation is straightforward:
- Adds documentation for the new option
- Modifies `builtin/push.c` to read the config
- Includes new test cases verifying the behavior in both TTY and non-TTY contexts, including command-line override behavior

The patch appears well-constructed with clear motivation, proper documentation, and thorough test coverage. This seems like a reasonable quality-of-life improvement for users who prefer less verbose output by default. The change is small and focused, touching only the push command's progress reporting behavior without broader implications.
