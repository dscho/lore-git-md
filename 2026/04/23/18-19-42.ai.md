This is a bug report about a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. The reporter, Michael Grossfeld, provides a clear reproduction case showing that an alias defined as `pull.sub` in the gitconfig file now fails with "not a git command" error, though it worked previously.

The alias in question combines a `git pull` with subsequent submodule updates, suggesting this is a workflow convenience for repositories using submodules. The reporter includes both the gitconfig syntax that worked in 2.53.0 and the attempted workaround using `.command` suffix that produces different (but still non-working) config syntax.

Notably this is on Windows (git version 2.54.0.windows.1), though the reporter doesn't indicate whether they've tested on other platforms. The bug appears to be in the core alias handling rather than Windows-specific code, given the nature of the regression. This would affect any user relying on hierarchical aliases, which are a documented feature for organizing related commands.

The report is well-structured with clear before/after behavior and includes all relevant version information, making it easy to investigate. Since hierarchical aliases are a legitimate feature, this regression would likely be high priority to fix in a maintenance release.
