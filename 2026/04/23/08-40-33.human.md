This is part 4 of Karthik Nayak's refactoring series to consolidate reference backend logic (v2, now expanded to 9 patches). The series is part of the ongoing effort to standardize behavior across Git's reference backends (files, packed, reftable).

This particular patch changes the return type of `ref_transaction_update()` from `int` to `enum ref_transaction_error`, replacing the generic `-1` error returns with specific error codes. The change is purely preparatory - it maintains the same behavior (still returning a generic error for now) but sets up the infrastructure for future patches to introduce more specific error types. 

The patch is mechanical and straightforward, touching only the function signature and two error return sites. It's been reviewed by Patrick Steinhardt as part of the broader series, with all feedback addressed in previous iterations. The change aligns with the series' goal of making reference handling more robust by enabling better error differentiation in future validation work.
