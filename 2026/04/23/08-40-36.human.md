This is part 7 of Karthik Nayak's refactoring series to consolidate reference backend logic. The patch moves object validation (checking that referenced objects exist) from individual backends to the shared refs layer, eliminating duplicate code.

Key changes:
- Object existence checks now happen immediately when updates are queued via `ref_transaction_update()`, rather than during transaction preparation
- Removes the now-unused `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type
- Updates `builtin/receive-pack.c` to properly handle the new error reporting
- Removes validation logic from both files and reftable backends

The change affects how invalid object references are reported - errors now surface immediately rather than being batched. The author notes this is actually preferable since validation doesn't depend on transaction preparation. The patch maintains backward compatibility in error reporting while cleaning up the backend implementations.

This continues the series' pattern of moving common functionality out of backend-specific code. The changes are well-contained and build on prior infrastructure work in the series. With Patrick Steinhardt's thorough review of earlier versions, this appears to be a solid step in the backend consolidation effort.
