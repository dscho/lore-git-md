This is part 8 of a 9-patch refactoring series (v2) that continues consolidating reference backend logic into Git's shared layer. The series is led by Karthik Nayak as part of the ongoing effort to standardize behavior across Git's reference backends (files, packed, reftable).

This particular patch introduces infrastructure to handle peeled object IDs (the dereferenced OID when a tag points to another object) in the generic refs layer. The key changes are:

1. Adds a `peeled` field to the `ref_update` struct to store peeled OIDs
2. Modifies `ref_transaction_add_update()` to accept and store peeled OIDs
3. Updates `ref_transaction_update()` to automatically peel tag objects and pass the result downstream
4. Adjusts all callers to pass NULL for cases where peeling isn't needed (reflogs, deletions)

The change allows backends that support storing peeled OIDs (like packed and reftable) to access this information without hitting the object database repeatedly. This is a preparatory step - the next patch will modify the backends to actually use this new field.

The patch follows the established pattern of the series by moving backend-specific logic into the shared layer while maintaining existing behavior. It has already received thorough review from Patrick Steinhardt, with all technical concerns addressed in this version. The changes are mechanical but important for the overall backend consolidation effort.
