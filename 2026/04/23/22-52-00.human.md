This is the second patch in a two-part series introducing a memory optimization for the new `--reverse=before` revision walk option. The optimization reduces memory usage when combining `--reverse=before` with `--max-count` by maintaining a sliding window of commits rather than storing the entire history.

The patch implements a new `retrieve_with_window()` function that manages two queues to keep only the most recent `max_count` commits during traversal. This changes the space complexity from O(N) to O(K) where K is the max count, while maintaining O(N) time complexity. The implementation follows the sliding window approach suggested in earlier discussion, now cleaned up queue handling code as requested in reviews.

The optimization is particularly valuable for large repositories where walking the full history with `--reverse=before` could otherwise consume significant memory. The patch maintains all existing behavior while adding this efficiency improvement for the common case where users want only a limited number of commits in reverse order.

This version incorporates stylistic feedback on the queue management code while preserving the core optimization approach. With the documentation finalized in patch 1/2 and this memory optimization now cleaned up, the series appears ready for maintainer consideration.
