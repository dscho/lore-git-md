This is a refactoring patch from Jiamu Sun's series adding subcommand autocorrection to Git's parse-options API. The patch focuses on improving the autocorrect configuration handling by:

1. Introducing a new `autocorrect_resolve()` API that provides a cleaner way to retrieve autocorrect configuration values, hiding the internal config callback implementation details.

2. Moving the config resolution logic entirely into autocorrect.c, making the interface more self-contained. The previous version exposed the config callback publicly, which could lead to misuse.

3. Splitting the alias resolution from autocorrect config resolution in help.c, since they serve different purposes. This makes the code's intent clearer even though it means an extra config iteration.

The changes maintain all existing functionality while improving the API design. The patch is part of a well-reviewed series that has already received maintainer approval, with this iteration focusing on final polish before merging. The refactoring follows Git's typical patterns for configuration handling while keeping the autocorrect feature properly encapsulated.
