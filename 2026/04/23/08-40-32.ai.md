This is part 3 of a 9-patch refactoring series (v2) from Karthik Nayak that continues consolidating reference backend logic into the generic layer. The patch moves reflog configuration handling from individual backends to the shared refs layer.

The change standardizes how reference backends determine when to create reflog entries by:
1. Adding a `log_all_ref_updates` field to the `ref_store_init_options` struct
2. Setting this value in the generic `ref_store_init()` function using `repo_settings_get_log_all_ref_updates()`
3. Having backends (files and reftable) use the passed value rather than querying config themselves

This is a mechanical change that follows the series' architectural direction of moving common functionality out of backend-specific implementations. The patch affects core ref handling but doesn't change user-visible behavior - it just centralizes where the reflog configuration is obtained.

The diff shows straightforward updates to the files, reftable, and packed ref backends to use the new centralized configuration. This continues the broader effort to reduce backend-specific behavior and make the ref storage layer more consistent across implementations.
