This is a feature patch adding a new configuration option to control progress reporting during `git push`. The patch introduces `push.showProgress`, which allows users to configure whether progress output (the "Enumerating/Counting/Compressing/Writing objects" messages) should be shown by default.

The key aspects are:
1. The config option works similarly to the existing `--progress`/`--no-progress` command-line flags, but persists across invocations
2. It maintains the same behavior hierarchy where explicit command-line flags override the config
3. The default behavior (when unset) remains unchanged - progress shows on terminals and hides otherwise
4. The implementation includes tests verifying the config interacts correctly with TTY detection and command-line overrides

The motivation is to allow suppressing verbose progress output while still seeing the final push summary, something not possible with `-q/--quiet` which silences everything. The patch appears well-structured with documentation, implementation, and test coverage all included.
