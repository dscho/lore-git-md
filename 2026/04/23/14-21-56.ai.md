This is a feature patch from Patrick Steinhardt that adds control over how empty commits are handled in the `git replay` command. It's part of a 3-patch series (v2) focused on the replay subsystem.

The patch introduces a new `enum replay_empty_commit_action` with three options for handling commits that become empty during replay (where the commit's tree matches its parent's tree after replay):
- DROP (current default behavior)
- KEEP (preserve empty commits)
- ABORT (fail with error message)

The change threads this new option through the replay machinery, modifying the core `pick_regular_commit()` function to respect the caller's preference. The error handling is also updated to properly propagate abort conditions back to the caller.

This appears to be a well-constructed patch with clear documentation of the new enum and option. The implementation maintains the existing behavior by default while providing flexibility for callers who need different empty-commit handling. The change is focused and touches only the necessary parts of the replay subsystem.
