This is a refactoring patch from Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch moves TTY checking logic from help.c to autocorrect.c as part of consolidating the autocorrection functionality.

The change makes sense architecturally - since the autocorrect configuration parsing is handled in autocorrect.c, the TTY check (which determines whether to show an interactive prompt) belongs there too. The patch is straightforward, just relocating the check while maintaining the same behavior: if we're in a non-interactive session (no TTY), autocorrection prompts are disabled.

This is part of the final polish for the series, which has already received maintainer approval. The implementation looks clean and the test coverage remains comprehensive. With this change, the autocorrection logic is more self-contained in its own module rather than spread across files.
