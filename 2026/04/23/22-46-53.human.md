This is a follow-up in the hierarchical aliases regression thread, where Michael Grossfeld confirms René Scharfe's analysis of the issue and proposed solution. The regression, introduced in Git 2.54.0, broke dot-separated alias syntax (like `pull.sub`) that was previously working, though undocumented.

Michael confirms that the suggested workaround using `[alias "pull.sub"]` syntax does work, but notes this doesn't help users who already have the old-style aliases configured. His response validates René's technical assessment that the regression can be fixed while preserving most functionality, with the exception of aliases ending in ".command" which would remain broken for backward compatibility reasons.

The exchange moves the discussion toward resolution by confirming the workaround is viable for new configurations while acknowledging the migration pain for existing users. Michael's practical perspective as someone managing team configurations adds weight to the need for a fix that minimizes disruption.
