This is part of Karthik Nayak's ongoing refactoring series to consolidate reference backend logic (v3, patch 2/9). The patch introduces a new `ref_store_init_options` struct to standardize how reference backends are initialized, moving the access flags parameter into this structure. This prepares for future extensions where additional initialization options (like reflog configuration) can be passed to backends consistently.

The change affects all three ref storage backends (files, packed, and reftable), modifying their initialization signatures to accept the new options struct instead of raw flags. The implementation is mechanical but important infrastructure for the series' broader aim of standardizing backend behavior. Patrick Steinhardt has already reviewed and approved the technical approach in previous iterations, with only minor wording tweaks requested and addressed.

For future thread context: This patch establishes the `ref_store_init_options` structure in `refs-internal.h` and updates all backend initialization functions to use it. The `access_flags` field carries forward the existing permission controls while providing a framework for additional options. Subsequent patches in the series will build on this to move validation and peeling logic into the shared layer.
