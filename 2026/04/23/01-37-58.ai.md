This is the 8th patch in Jiamu Sun's 10-part series adding subcommand autocorrection to Git's parse-options API. The series has already received maintainer approval and is in its final polishing stage.

The patch enables autocorrection for optional subcommands in `git-remote` and `git-notes` by adding the new `PARSE_OPT_SUBCOMMAND_AUTOCORRECT` flag. This allows the parse-options machinery to handle mistyped subcommands automatically rather than requiring each builtin to implement its own error handling. The change is safe because both commands either resolve to a single subcommand or take no subcommand at all - any unknown argument must be a mistyped subcommand.

Key technical changes:
- Adds the new flag to both commands' parse_options() calls
- Removes now-redundant error handling code from both builtins
- Updates the parse-options.c logic to only bypass autocorrection when explicitly disabled
- Documents the new flag in parse-options.h

This represents the final integration step for the autocorrection feature, building on the earlier infrastructure patches that implemented the core functionality. With this change, users will get consistent autocorrection behavior whether they mistype a main command or a subcommand. The series has been thoroughly reviewed and tested across multiple iterations, with all feedback addressed.
