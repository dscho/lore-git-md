This is a documentation patch correcting an inaccurate description of `git am --message-id` behavior in the man page. The patch reverts part of a previous change that incorrectly claimed the option adds a Message-ID header as a Git trailer (using trailer block formatting rules). In reality, it simply appends the header line after the message body without regard for trailer block conventions.

The correction notes this is arguably a bug in the implementation, but since we're near the release cycle, the safer path is to revert the documentation to match current behavior rather than changing the code. The patch retains one useful change from the original commit - using inline-verbatim formatting for `Message-ID`.

Junio has already signed off on this change, suggesting it's uncontroversial and likely to be merged. The patch is narrowly focused and doesn't appear to be part of any larger ongoing effort - it's simply fixing an incorrect documentation claim.
