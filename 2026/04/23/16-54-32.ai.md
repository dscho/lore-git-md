This is part of the ongoing `the_repository` removal effort, specifically migrating the `core.warnAmbiguousRefs` configuration from a global variable to repository-specific storage in `struct repo_config_values`. The patch continues the pattern seen in previous configuration migrations in this series.

The change moves the `warn_on_object_refname_ambiguity` flag that controls whether Git warns about ambiguous object references into per-repository storage. The commit message explains this needs to remain eagerly parsed since ambiguity warnings affect user interpretation of commands across the codebase. The patch updates seven files that reference this flag, mostly following the same pattern of temporarily disabling the warning during operations where it would be noisy (like batch operations or revision walking).

The changes are mechanical and consistent with the established approach in this series - replacing direct global variable access with repository-specific lookups through `repo_config_values()`. The diff shows the typical small changes across multiple files rather than deep modifications to any single component. This represents another incremental but important step in eliminating global state from Git's codebase.
