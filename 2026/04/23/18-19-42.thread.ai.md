Thread identity: Bug report and fix discussion for regression in Git 2.54.0 where hierarchical aliases (e.g. `pull.sub`) stopped working after working in 2.53.0. Originally reported by Michael Grossfeld, with analysis from Jeff King and René Scharfe, now in active design discussion between Jonatan Holmgren (original change author), Jeff King, and Junio C Hamano.

Core problem: Regression in alias handling where dot-separated hierarchical aliases (documented feature) broke in 2.54.0 due to new three-level alias syntax (commit ac1f12a9de). The system misinterprets `alias.pull.sub` as a subsection rather than command name, affecting workflows like the reported `pull.sub` alias for pull+submodule operations.

Current status: Two competing technical solutions under active debate:
1. Holmgren's original: Restore backward compatibility while reserving `command` and `alias-*` prefixes for future attributes
2. King's alternative: Implement dual interpretation where `alias.foo.bar` is checked as both single alias "foo.bar" and "bar" key of alias "foo"

Key technical details:
- Both approaches would:
  - Restore backward compatibility for dotted aliases
  - Preserve new subsection syntax functionality
  - Add comprehensive test coverage in t0014-alias.sh
- King's proposal adds:
  - No special-casing of key names
  - More complex lookup logic in alias.c
  - Smoother transition path for future attributes
  - Potential edge cases with ambiguous interpretations
- Holmgren's concerns about King's approach:
  - Creates ambiguous configuration interpretation
  - Makes system behavior harder to document
  - May complicate future extensions
- Original regression stemmed from alias.c changes in ac1f12a9de
- Minimal changes to alias.c and help.c required

Open questions:

  - Holmgren's reserved prefixes (simpler, clearer semantics)

- Are there additional test cases needed to validate edge cases in King's approach?
