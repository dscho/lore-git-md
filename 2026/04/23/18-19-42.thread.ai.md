Thread identity: Bug report and fix for regression in Git 2.54.0 where hierarchical aliases (e.g. `pull.sub`) stopped working after working correctly in 2.53.0. Originally reported by Michael Grossfeld, with analysis from Jeff King and René Scharfe, now fixed by original change author Jonatan Holmgren via patch v1, with ongoing design discussion involving Junio C Hamano and Jeff King.

Core problem: Regression in alias handling where dot-separated hierarchical aliases (documented feature) broke in 2.54.0 due to new three-level alias syntax (commit ac1f12a9de). The system misinterprets `alias.pull.sub` as a subsection rather than command name, affecting workflows like the reported `pull.sub` alias for combined pull+submodule operations.

Current status: Fix submitted in v1 patch by Holmgren, implementing the solution approach previously vetted by King and Scharfe, now with expanded design discussion about long-term implications. The patch:
- Restores backward compatibility for dotted aliases
- Preserves new subsection syntax functionality
- Adds comprehensive test coverage
- Maintains documented edge case where aliases ending in ".command" remain broken
- Includes proper attribution via Reported-by and Helped-by trailers
- Missing Signed-off-by trailer (to be added)
- Now includes design discussion about future extensibility tradeoffs with two competing proposals:
  - Holmgren's original: reserve only `command` and `alias-*` prefixes
  - King's alternative: interpret keys both ways without special-casing

Technical details:
- Fix makes Git fall back to treating full name as alias when final key isn't "command"
- Test cases in t0014-alias.sh verify:
  - Simple dotted alias execution (`pull.sub = !git pull && git submodule update`)
  - Help output behavior
- Original regression stemmed from alias.c changes in ac1f12a9de
- New explicit syntax was intended to support non-ASCII characters in aliases
- Minimal changes to alias.c and help.c
- Workarounds remain available:
  - Temporary: `[alias "pull.sub"]` syntax
  - Future-compatible: `alias.pull.sub.command` syntax
- Design considerations:
  - Only `command` and `alias-*` prefixes would be reserved for future attributes (Holmgren)
  - Alternative: interpret keys both ways without special-casing (King)
  - Simple subsection aliases likely more common than future metadata attributes
  - Separate namespace (`nalias`) would be cleaner technically but worse UX
