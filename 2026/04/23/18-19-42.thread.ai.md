Thread identity: Bug report about regression in Git 2.54.0 where hierarchical aliases (e.g. `pull.sub`) stopped working after working correctly in 2.53.0, reported by Michael Grossfeld, now with analysis and proposed fix from Jeff King.

Core problem: Regression in alias handling where dot-separated hierarchical aliases (documented feature) broke in 2.54.0 due to new three-level alias syntax (commit ac1f12a9de). The system now misinterprets `alias.pull.sub` as a subsection rather than command name, affecting workflows like the reported `pull.sub` alias for combined pull+submodule operations.

Current status: Root cause identified - unintended interaction between new alias syntax and existing hierarchical aliases. Jeff King proposes fix to restore backward compatibility while preserving new functionality. Short-term workaround available using `[alias "pull.sub"]` syntax.

Technical details:
- Regression stems from alias.c changes for three-level syntax
- Fix would modify parsing to fall back to old behavior for unknown subsection keys
- Edge case: would still break historical aliases named `foo.command`
- Affects all platforms (originally reported on Windows but not Windows-specific)

Open questions:
- Will the proposed patch be accepted as-is or modified?
- Should the fix go into maint for a 2.54.x release?
- Are there other edge cases beyond `foo.command` that need consideration?

- Jeff King: Confirmed regression, identified root cause, proposed fix with workaround
