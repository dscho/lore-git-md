This is a bug report about a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. The reporter, Michael Grossfeld, provides a clear reproduction case showing how their submodule update alias no longer functions, instead producing an "unknown command" error.

The issue appears specific to the Windows build (git version 2.54.0.windows.1) and affects the alias subsystem's handling of nested commands. The reporter has tried alternative syntax variations (adding `.command`) but found they produce a different but still non-functional config structure.

This looks like a legitimate regression that broke existing workflows. The clear reproduction steps and version comparison make it easy to verify. Since hierarchical aliases are a documented feature, this warrants investigation - likely a parsing change in 2.54.0 inadvertently affected the alias expansion logic. Windows users relying on this feature would be most impacted.
