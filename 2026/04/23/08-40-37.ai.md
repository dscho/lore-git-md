This is part 8 of Karthik Nayak's refactoring series to consolidate reference backend logic into the generic layer, specifically focusing on adding peeled object ID support to the `ref_update` struct.

The patch adds a `peeled` field to `ref_update` and modifies `ref_transaction_add_update()` to accept a peeled OID parameter. When updating a tag reference, the transaction layer now automatically peel the tag and store the result in the update struct. This prepares for future changes where backends can use this pre-peeled OID rather than doing their own peeling.

Key technical changes:
- New `REF_HAVE_PEELED` flag indicates when a peeled OID is available
- `ref_transaction_update()` now peels tags and passes the result to `ref_transaction_add_update()`
- All callers updated to pass NULL for peeled OID where not applicable (reflogs, deletions)
- Backends will later be modified to use this centralized peeling (coming in follow-up patches)

The change maintains backward compatibility while enabling future optimization - backends can skip their own peeling steps once they're updated to use the pre-peeled OID. This continues the series' pattern of moving backend-specific logic into the shared refs layer.

The patch has mechanical updates across multiple files but the core logic change is straightforward. As with previous patches in the series, this appears well-considered and follows the established refactoring approach.
