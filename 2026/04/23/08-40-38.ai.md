This is the final patch in Karthik Nayak's v2 series refactoring Git's reference backends. The patch builds on the previous changes that centralized tag peeling logic in the generic refs layer (introducing the `peeled` field in `ref_update` and `REF_HAVE_PEELED` flag).

The change modifies both the packed and reftable backends to use the pre-peeled values from the transaction layer rather than performing their own peeling operations. This eliminates redundant work and ensures consistent behavior across backends. The packed-backend and reftable-backend changes are straightforward removals of now-unnecessary peeling calls, replacing them with checks of the `REF_HAVE_PEELED` flag and use of the stored `peeled` value.

The patch follows the series' established pattern of moving backend-specific logic into the shared layer while maintaining backward compatibility. With this change, the backends no longer need direct access to the object database for peeling operations, further decoupling them from Git's object storage implementation. The changes are mechanical and unlikely to be controversial given the thorough review of the foundational patches in the series.
