This is part 4 of a 9-patch refactoring series (v2) from Karthik Nayak that continues consolidating reference backend logic into the generic layer. The patch focuses on error handling improvements in the ref transaction machinery.

The change modifies `ref_transaction_update()` to return an `enum ref_transaction_error` instead of a simple `-1` for failures. This prepares for future validation enhancements by allowing callers to distinguish between different error types. Currently, all error cases still return the generic `REF_TRANSACTION_ERROR_GENERIC` value, maintaining existing behavior while setting up the infrastructure for more specific error reporting.

The patch touches core refs functionality in `refs.c` and `refs.h`, changing the function signature and updating two error return sites. This is a mechanical change that doesn't yet introduce new validation logic - that will come in subsequent patches. The modification follows the series' pattern of moving common ref handling out of backend-specific code and into the shared layer.

As part of the broader ref backend consolidation effort led by Patrick Steinhardt and Karthik Nayak, this change helps standardize error reporting across all ref backends (files, packed, reftable). The series has already received thorough review, with this particular patch being a straightforward infrastructure preparation step.
