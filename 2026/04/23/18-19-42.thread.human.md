This thread documents a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. The issue was reported by Michael Grossfeld, with technical analysis from Jeff King and René Scharfe identifying the root cause in alias.c changes for three-level syntax. Two solutions emerged: a temporary workaround using `[alias "pull.sub"]` syntax and a future-compatible `alias.pull.sub.command` format.

The original reporter has now confirmed the workaround would work for his team's workflow, validating the technical solution. While a minor edge case remains (historical aliases ending in ".command"), Grossfeld agrees this is rare enough to not block the fix. The thread shows consensus forming around the proposed approach, with the main remaining questions being whether the fix will be backported to the 2.54.x series and if any other edge cases might surface. Jeff King and René Scharfe's substantive technical reviews have established confidence in the solution's correctness.
