This thread reports a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. Michael Grossfeld originally reported the issue, demonstrating how a `pull.sub` alias that combines `git pull` with submodule updates now fails with a "not a git command" error.

Jeff King (Peff) has identified the root cause - the regression was an unintended side effect of the new three-level alias syntax introduced in commit ac1f12a9de. The change made Git interpret `alias.pull.sub` as trying to set a "sub" key under the "pull" alias rather than treating it as a single command name. Peff provided both an immediate workaround (using the new `[alias "pull.sub"]` syntax) and proposed a fix that would restore backward compatibility while maintaining the new functionality.

The proposed solution would modify the alias parsing logic to fall back to the old behavior when encountering an unknown subsection key, though it notes this would still break any historical aliases that happened to be named `foo.command`. Given this is a clear regression affecting a documented feature and Peff's thorough analysis, this will likely be fixed in an upcoming maintenance release.
