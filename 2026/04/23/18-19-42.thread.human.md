# Git Alias Regression Thread -- Resolved

This thread began when Michael Grossfeld reported that hierarchical aliases (like `pull.sub`) worked in Git 2.53.0 but broke in 2.54.0. The regression was caused by commit ac1f12a9de, which introduced a new three-level alias syntax that inadvertently treated dotted aliases as subsections rather than command names.

After technical analysis from Jeff King and René Scharfe, a fix was implemented by Jonatan Holmgren (the original change author) that restores backward compatibility while preserving the new structured syntax. The solution reserves certain keys for structured data and recognizes dotted aliases as historical behavior that may be deprecated in Git 3.0+. Minimal changes to `alias.c` and `help.c` were required, with comprehensive test coverage in `t0014-alias.sh`.

The thread has now concluded. Junio C Hamano confirmed that after discussion settled, the current patch represents a workable approach -- it restores compatibility without painting the project into a corner. He has marked the topic for inclusion in `next`, signaling the issue is resolved and ready for merge. The main open question (whether to backport to a 2.54.x maint release) was not addressed in Junio's closing note, which focused solely on the forward path through the integration branches.
