A regression in Git 2.54.0 has been reported where hierarchical command aliases (like `pull.sub`) stopped working after functioning correctly in 2.53.0. Michael Grossfeld provided a clear reproduction case showing that an alias combining `git pull` with submodule updates now fails with a "not a git command" error. The issue appears on Windows (Git for Windows 2.54.0) but likely affects all platforms since it involves core alias handling rather than Windows-specific code.

This regression impacts users who rely on hierarchical aliases - a documented feature for organizing related commands. The report includes both the previously working gitconfig syntax and attempted workarounds, making it straightforward to investigate. Given that this breaks existing functionality, it would likely warrant a fix in a maintenance release. No responses or suggested fixes have been posted yet.
