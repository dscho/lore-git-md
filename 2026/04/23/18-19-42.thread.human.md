This thread addresses a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. The issue was reported by Michael Grossfeld, with technical analysis from Jeff King and René Scharfe confirming the root cause. Jonatan Holmgren, the author of the original change that introduced the regression, submitted a v1 patch that restores backward compatibility while preserving the new subsection syntax functionality. The fix includes comprehensive test coverage and addresses the immediate issue, though it maintains a documented edge case where aliases ending in ".command" remain broken.

Junio Hamano raised design-level concerns about whether this approach might limit future extensions to the alias system, suggesting an alternative "nalias" configuration might have been better for long-term flexibility. In response, Holmgren acknowledged the tradeoffs but proposed a compromise where only certain prefixes (`command` and `alias-*`) would be reserved for future attributes, balancing backward compatibility with extensibility. He emphasized user experience considerations, noting that simple subsection aliases will likely be more common than future metadata needs.

The technical solution itself has already been vetted by King and Scharfe, so the remaining discussion centers on design philosophy rather than implementation correctness. The patch may need minor adjustments to address Junio's concerns before final acceptance, but the core fix for the regression appears sound. Kristoffer Haugsbakk also noted the missing Signed-off-by trailer, which Holmgren will need to add. The question of whether this fix will be backported to maint for a 2.54.x release remains open.
