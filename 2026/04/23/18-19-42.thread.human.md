This thread addressed a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working in 2.53.0. The issue stemmed from changes to alias handling that misinterpreted dotted aliases as configuration subsections rather than command names. After analysis from Jeff King and Rene Scharfe, Jonatan Holmgren (who originally introduced the regression) proposed a fix that restores backward compatibility while preserving the new structured alias syntax.

The solution has been accepted by maintainer Junio Hamano, who has queued the patch for inclusion in the `next` integration branch. Jeff King confirmed in the final email that the technical solution is sound, noting that any documentation updates to guide users toward the newer alias syntax can be handled separately. All participants agree the issue is resolved, with no remaining open questions. The fix maintains compatibility for existing workflows while keeping the door open for future syntax improvements.
