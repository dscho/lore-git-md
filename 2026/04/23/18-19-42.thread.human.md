The thread reports a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working correctly in 2.53.0. Michael Grossfeld originally reported the issue, which affects workflows using dot-separated aliases for combined operations. Jeff King and René Scharfe analyzed the problem, tracing it to changes in alias.c that introduced three-level alias syntax (commit ac1f12a9de). They proposed solutions to restore backward compatibility while preserving the new functionality, which Grossfeld confirmed would work for his use case.

Jonatan Holmgren, the original author of the three-level alias changes, has acknowledged the regression. He clarified that while the hierarchical aliases were working before, this was accidental rather than by design - the new syntax was actually intended to support non-ASCII characters in aliases. Holmgren has committed to sending a fix, though notes it will take time to go through the release cycle.

The thread now has consensus that:
1. The regression is real and affects legitimate workflows
