This thread addresses a regression in Git 2.54.0 where hierarchical aliases (like `pull.sub`) stopped working after working in 2.53.0. The discussion has evolved from identifying the bug to debating two technical solutions: Jonatan Holmgren's approach using reserved prefixes for future attributes, and Jeff King's more complex dual interpretation method that checks aliases both as single names and subsection keys.

In the latest exchange, King has shifted toward Holmgren's position, agreeing that dotted aliases were likely an accidental feature rather than an intentional design, but one that users now rely on. Both now favor restoring compatibility while reserving certain keys (like `command`) for structured data, acknowledging these dotted aliases as a "historical curiosity" that might eventually be deprecated—perhaps in Git 3.0—with proper notice. 

The technical debate appears to be converging, with the main open questions now focused on documentation and long-term planning rather than the immediate fix. Junio Hamano continues to monitor the discussion but hasn't indicated a final preference between the approaches. The solution will likely restore backward compatibility while setting up clearer rules for future alias handling.
