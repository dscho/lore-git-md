This is the third and final patch in Patrick Steinhardt's v2 series introducing a `git history fixup` subcommand, building on his experimental `git history` command work. The subcommand allows amending staged changes to an existing commit while automatically rebasing dependent branches, similar to `git commit --fixup` but with automatic branch updates.

Key features of the `fixup` subcommand:
- Performs a three-way merge using HEAD's tree as the base
- Preserves commit message and authorship by default (with `--reedit-message` option to modify)
- Handles empty commits via new `--empty=(drop|keep|abort)` option
- Includes extensive test coverage (680+ lines)
- Documents limitations (no bare repo support, aborts on merge conflicts)

The implementation appears robust, with thorough test coverage addressing edge cases like empty commits and file deletions. The patch builds on earlier infrastructure patches in the series that generalized empty commit handling and refactored commit tree creation.

This version incorporates feedback from v1 reviews, particularly around empty commit handling and documentation clarity. The command fills a clear workflow gap for amending changes while maintaining branch relationships, though it currently aborts on merge conflicts pending future Git conflict resolution support.
