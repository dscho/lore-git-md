This is the first patch in a two-part series implementing `--reverse=before` for revision walks, allowing commit reversal to happen before limiting rather than after. The patch introduces the core functionality while the second patch (not shown here) adds memory optimizations.

The key changes in this version:
1. Documentation has been updated to clarify the toggle behavior and historical edge cases, incorporating Jeff King's suggested wording
2. The implementation now uses an explicit `rev_reverse` enum in `struct rev_info` rather than a boolean flag
3. Test cases verify the new behavior, including combinations with `--max-count` and multiple `--reverse` toggles

The patch enables use cases like `git log --reverse=before --max-count=3` to show the first commits rather than the last. It maintains backward compatibility with existing `--reverse` behavior (which remains the default when no argument is provided). The implementation handles edge cases like multiple `--reverse` specifications and properly integrates with other revision walk options.

The changes touch core revision walking logic in `revision.c` and `list-objects.c`, with corresponding updates to documentation and test coverage. The patch appears functionally complete with all technical feedback from previous iterations addressed, though Junio C Hamano's high-level questions about the conceptual framing remain open.
