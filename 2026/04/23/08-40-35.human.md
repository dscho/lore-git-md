This is part 6 of a 9-patch series refactoring Git's reference backend to consolidate object validation and error handling logic. The series is now in its third iteration (v3) with all substantive feedback addressed.

The current patch modifies `git update-ref` to properly handle reference update rejections that occur during the preparation phase (not just during commit). It introduces a `command_options` struct to track whether individual failures should be fatal (default) or allowed (with `--batch-updates`), and propagates this through all command parsing functions. The changes are mechanical but important for the series' goal of standardizing error handling across reference backends.

Key technical points:
- Adds `enum ref_transaction_error` handling to distinguish between generic and specific failures
- Modifies all command parsers to accept the new options struct
- Maintains existing behavior where non-batch mode dies on any failure
- Prepares for future patches that will move more validation into the transaction layer

The patch is well-structured and follows the series' incremental approach. It has already received thorough review from Patrick Steinhardt, the primary driver of the ref backend consolidation effort. The changes appear technically sound and properly integrated with the broader series goals.
