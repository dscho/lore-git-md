This is a refactoring patch (7/9 in v2 series) from Karthik Nayak that moves object validation logic from individual ref backends to the generic refs layer. The change is part of the ongoing effort to standardize behavior across Git's reference backends (files, packed, reftable).

The patch centralizes the validation of object IDs during ref updates by moving the `parse_object()` check from backend-specific implementations into `ref_transaction_update()`. This eliminates duplicate validation code and ensures consistent behavior across all backends. The validation now happens immediately when an update is queued, rather than during transaction preparation.

Key technical changes:
- Removes object validation from files-backend.c and reftable-backend.c
- Adds validation to refs.c's `ref_transaction_update()`
- Updates receive-pack to handle the new error reporting flow
- Removes the now-unused `REF_TRANSACTION_ERROR_INVALID_NEW_VALUE` error type
- Preserves existing error messages and behavior for client-facing output

The change affects how invalid object IDs are reported in batch operations - they now fail immediately when added to the transaction rather than during preparation. The patch includes adjustments to maintain backward compatibility in receive-pack's error reporting.

This continues the architectural direction established in earlier patches of the series, with all substantive feedback from Patrick Steinhardt already addressed. The change is well-contained and follows the pattern of moving backend-specific logic into the shared layer while maintaining the same external behavior.
