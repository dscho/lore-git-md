This is a refactoring patch from Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch moves TTY checking logic from help.c to autocorrect.c as part of consolidating the autocorrection functionality.

The key change relocates the interactive session check (verifying stdin/stdout are TTYs) from the command error handler in help.c to the config resolution function in autocorrect.c. This makes the TTY verification happen earlier during config parsing rather than at runtime, which is more appropriate since the autocorrect behavior depends on whether the session is interactive.

The implementation maintains the same behavior - if autocorrection is set to prompt (AUTOCORRECT_PROMPT) but the session is non-interactive, it falls back to AUTOCORRECT_NEVER. The diff shows the straightforward movement of this check while keeping all other autocorrection logic intact.

This is a clean-up patch in the final stages of a well-reviewed series that has already received maintainer approval. The change follows the principle of keeping TTY verification with the config parsing code that determines autocorrection behavior.
