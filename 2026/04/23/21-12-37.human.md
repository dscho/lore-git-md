Bugfix for hierarchical alias regression in Git 2.54.0. Jeff King (Peff) confirms the reported issue where dot-separated aliases like `pull.sub` stopped working after the introduction of three-level alias syntax in commit ac1f12a9de. He provides a clear minimal reproduction case and explains the root cause: the new config parser now interprets the dot as indicating a subsection rather than part of the alias name.

Peff proposes both a short-term workaround (using the new `[alias "pull.sub"]` syntax) and a proper fix that would maintain backward compatibility with the old behavior while still supporting the new three-level syntax. The proposed patch modifies `alias.c` to fall back to the old two-level interpretation when the subsection key isn't recognized as "command".

The fix would preserve most existing behavior, though Peff notes it might still break the hypothetical case where someone had an alias literally named "foo.command". He leaves open whether to handle that edge case, suggesting it may be too obscure to worry about. This appears to be a well-analyzed response from a core contributor that directly addresses the regression while considering backward compatibility implications.
