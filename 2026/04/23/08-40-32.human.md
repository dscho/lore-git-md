This is part 3 of Karthik Nayak's refactoring series to consolidate reference backend logic (v2, now 9/8 patches). The patch moves reflog configuration handling from individual backends to the generic refs layer.

The change standardizes how backends determine when to create reflog entries by having the generic `refs.c` layer check the `core.logallrefupdates` config once during initialization, then pass the value down to all backends (files, packed, reftable) via the new `ref_store_init_options` struct. This eliminates duplicate config lookups and ensures consistent behavior across backends.

The implementation is straightforward - it adds the config value to the initialization options struct and updates the three backend implementations to use the passed value rather than querying the config themselves. The change is part of the broader effort to reduce backend-specific behavior and centralize common functionality in the shared refs layer.

This patch follows the structural foundation established in patch 2 of the series and has already been reviewed and approved by Patrick Steinhardt in previous iterations. The changes are mechanical and uncontroversial, continuing the series' pattern of cleanly separating concerns between the generic and backend-specific layers.
