This is part of Jiamu Sun's feature series adding subcommand autocorrection support to Git's parse-options API, which has now reached its sixth iteration with maintainer approval. This particular patch (02/10) extracts the autocorrection logic from help.c into new standalone autocorrect.{c,h} files to make the functionality reusable across different commands.

The patch moves:
- The config parsing logic (handling help.autocorrect values like "prompt", "never", etc.)
- The confirmation prompt/delay handling
- The autocorrect constants/enums

This refactoring enables the autocorrection system to be used not just for main commands (as it was in help.c) but also for subcommands in other parts of Git. The following patches in the series will use this to add autocorrection for subcommands in `git remote` and `git notes`.

The implementation looks clean and well-factored, maintaining all existing behavior while making the code more modular. The patch has already gone through multiple rounds of review and refinement, and with Junio's approval, this appears ready for merging as part of the larger subcommand autocorrection feature.
