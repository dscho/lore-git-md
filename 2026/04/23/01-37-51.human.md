This is the first patch in Jiamu Sun's now-approved series adding subcommand autocorrection to Git's parse-options API. The patch refactors the subcommand handling logic in parse-options.c to make it more maintainable and prepare for the autocorrection feature.

The key changes:
- Extracts subcommand parsing into a new `handle_subcommand()` helper function
- Simplifies `parse_subcommand()` to return a basic success/failure status rather than an `enum parse_opt_result`
- Removes the switch statement over impossible parse_opt values
- Makes the non-option path clearer by separating subcommand handling from regular option parsing

This is a clean refactoring that doesn't change behavior - it just reorganizes the code to be more maintainable and prepare for the autocorrection functionality that will be added in later patches. The series has already gone through multiple rounds of review and received maintainer approval from Junio Hamano, so this foundational change is well-vetted.
