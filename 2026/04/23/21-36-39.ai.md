This is a follow-up in the hierarchical aliases regression thread, with René Scharfe confirming the root cause and proposing a solution. The regression was introduced in commit ac1f12a9de ("alias: support non-alphanumeric names via subsection syntax") which changed how Git interprets dot-separated alias names, breaking existing hierarchical aliases like `pull.sub`.

René notes that while the new subsection syntax is useful, it unintentionally broke undocumented but legitimate usage of dot-separated aliases. He suggests the previous behavior could be restored while maintaining the new functionality, with the exception of aliases ending in ".command" which would remain broken for backward compatibility reasons.

The email also confirms that the workaround using `[alias "pull.sub"]` syntax (with the `.command` suffix) does work, providing users a migration path. René's analysis is characteristically precise - he identifies the exact commit that introduced the regression and outlines the technical tradeoffs in fixing it. This moves the discussion forward by confirming the problem is understood and suggesting a path to resolution that balances backward compatibility with new features.
