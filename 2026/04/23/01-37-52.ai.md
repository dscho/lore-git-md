This is a refactoring patch from Jiamu Sun's series adding subcommand autocorrection support to Git's parse-options API. The patch moves the core autocorrection logic (configuration parsing and user prompt handling) from help.c into new standalone files autocorrect.{c,h}, making the functionality reusable across different commands.

The key changes are:
- Creates new autocorrect.c with the config parsing and confirmation logic previously in help.c
- Defines a clean public API in autocorrect.h with constants and function declarations
- Updates help.c to use the new API instead of its internal implementation
- Adds the new files to both Makefile and meson.build build systems

The refactoring maintains all existing behavior while making the autocorrection system available to other parts of Git that need similar functionality. This is a foundational piece for the larger subcommand autocorrection feature, allowing the same autocorrection behavior to be used consistently whether users mistype a main command or a subcommand.

The implementation follows Git's coding standards and includes proper error handling and internationalization support. The patch is well-structured with clear separation of concerns between the core autocorrection logic and its integration points.
