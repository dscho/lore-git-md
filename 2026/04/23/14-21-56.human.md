This is a feature patch for Git's replay subsystem, part of a 3-patch series from Patrick Steinhardt. The patch gives callers more control over how to handle commits that become empty during replay operations (where a commit's tree matches its parent's tree after replaying).

Currently, such empty commits are automatically dropped. The patch introduces a new `replay_empty_commit_action` enum with three options:
- `DROP` (current behavior)
- `KEEP` (preserve empty commits)
- `ABORT` (fail with an error)

The change is cleanly implemented with minimal disruption to existing code paths. The enum is documented in `replay.h` and the behavior is wired through the replay machinery. This looks like a well-motivated addition that provides needed flexibility for callers who may want to preserve empty commits (perhaps for history tracking) or strictly forbid them.

As the first patch in a series, it sets up the infrastructure that subsequent patches will presumably build upon. The commit message could benefit from a concrete example of when a caller might want to use each option, but the technical implementation appears sound.
