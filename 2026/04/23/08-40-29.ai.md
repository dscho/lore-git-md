This is a refactoring series (v2) from Karthik Nayak that continues the ongoing effort to consolidate reference backend logic into the generic layer. The series builds on previous work to standardize behavior across Git's reference backends (files, packed, reftable).

The main technical changes in this iteration:

1. Introduces a new `ref_store_init_options` struct to standardize backend initialization (split from the previous single patch into two commits for clarity)
2. Moves object validation and peeling logic from individual backends to the shared refs layer
3. Adds a `peeled` field to the `ref_update` struct to handle tag peeling consistently
4. Improves error handling in `git update-ref` to properly surface validation failures

The series has received thorough review from Patrick Steinhardt, with all feedback on implementation details addressed in this version. The only remaining open discussion point is around typedef usage (Karthik prefers keeping them while Patrick suggested removal), but this doesn't block the technical changes.

For future thread context: this series standardizes how reference backends handle object validation and peeling by moving logic from files-backend.c, packed-backend.c, and reftable-backend.c into refs.c. Key structures modified include `ref_update` (new `peeled` field) and the introduction of `ref_store_init_options`. The changes affect validation behavior in update-ref and receive-pack when processing ref updates.
