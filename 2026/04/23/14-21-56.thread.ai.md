Thread identity: Feature patch series from Patrick Steinhardt adding empty commit handling control to `git replay`, currently at v2.

Core problem/goal: Provide configurable behavior for how `git replay` handles commits that become empty (no diff from parent) during replay. Current behavior silently drops such commits; this series adds options to keep them or abort the operation.

Current status: Second version of a 3-patch series. Default behavior remains DROP (silently remove empty commits). New enum `replay_empty_commit_action` defines three policies: DROP, KEEP, ABORT. Core change modifies `pick_regular_commit()` to respect the selected policy.

Key technical details:
- New enum in replay.h: `enum replay_empty_commit_action` (DROP, KEEP, ABORT)
- Modified function: `pick_regular_commit()` now takes empty_commit_action parameter
- Error handling updated to properly propagate ABORT conditions
- Existing callers continue using DROP behavior by default
