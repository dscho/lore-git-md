This is a refactoring patch in Patrick Steinhardt's ongoing ODB (object database) abstraction series. It modifies the cbtree data structure to support arbitrary wrapper structures around tree nodes, which is needed for the in-memory ODB backend being introduced in this series.

The patch changes how cbtree handles node keys by:
1. Removing the flex array from `struct cb_node` and replacing it with a key offset parameter in `struct cb_tree`
2. Adding helper functions to locate keys based on the offset
3. Updating all cbtree operations to use the new key access pattern
4. Modifying oidtree (which uses cbtree) to wrap nodes in a new `struct oidtree_node` containing both the base node and object ID

The changes enable cleaner integration with the in-memory ODB backend by allowing proper embedding of node data while maintaining the alignment requirements of object IDs. There's a small memory tradeoff (4 bytes of padding per node) but it eliminates the need for memory copies to ensure alignment.

This is a technical foundation patch that doesn't introduce user-visible changes but enables the subsequent patches in the series to implement the in-memory storage functionality more cleanly. The implementation appears carefully considered, with attention paid to alignment requirements and memory management.
