This is the first patch in a two-part series that improves submodule fetch error handling. It fixes a premature error reporting issue in recursive submodule fetches where failures in the initial ref-fetching phase (phase 1) were being recorded before the OID-based retry (phase 2) had a chance to complete. The patch restructures the error handling to only report failures if both phases fail, or if there's no phase 2 retry possible (like with `--recurse-submodules=on`).

The changes are focused on `submodule.c`, introducing a new `record_fetch_error()` helper and adjusting the logic in `fetch_finish()` to properly handle the two-phase fetch scenario. The patch removes a NEEDSWORK comment from 2019 that had identified this issue, showing the problem was long-standing. The implementation looks clean and well-tested, with clear commit message explaining the behavioral changes.

This is a refactoring that enables the second patch's new configurable error handling by first fixing the underlying error reporting mechanism. The changes maintain backward compatibility while setting up for the new features to come.
