This is part 4 of Shreyansh Paliwal's series to remove `the_repository` global state from the refs subsystem, focusing now on lock timeouts and hash algorithm usage. The series has been refined based on previous feedback, with some more complex branch helper conversions deferred for later.

Patch 1 updates file ref lock timeouts to use an explicit repository parameter, propagating it through the files backend and callback paths. This removes one of the remaining implicit dependencies on global state in the refs locking mechanism.

Patch 2 systematically replaces uses of `the_hash_algo` in refs.c with repository-specific hash algorithms, either from the transaction's ref_store or directly from the repository parameter. This affects transaction creation, deletion, and migration operations.

Patch 3 cleans up the reftable backend by removing remaining `the_repository` uses where a repository instance is already available through function parameters or the ref_store structure.

The series shows good progress on the long-running `the_repository` removal effort, with each patch focused and mechanical in nature. The changes maintain existing behavior while making repository dependencies explicit. The deferred branch helper conversions (from earlier versions) appear to be the more complex remaining piece, likely requiring deeper architectural consideration around repository validity checking.
