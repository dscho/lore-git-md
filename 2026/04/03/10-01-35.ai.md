This is a bugfix patch addressing concurrent config file locking issues. The change makes Git retry acquiring the config.lock file for 100ms when encountering contention, similar to the existing behavior for reference locks.

The patch identifies a real-world problem where concurrent `git worktree add -b` operations can fail to write branch tracking information due to lock contention, despite the operations being semantically independent. The current behavior fails immediately on lock conflict, while the proposed change introduces a brief retry period that should handle normal contention while still failing fast on stale locks.

The implementation adds a 100ms timeout constant and updates two functions in config.c to use `hold_lock_file_for_update_timeout()` instead of the immediate-failure variant. The commit message clearly explains the motivation and parallels the solution with existing reference lock behavior (commit 4ff0f01cb7).
