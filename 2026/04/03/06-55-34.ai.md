This is the second patch in a two-part series introducing configurable submodule fetch error handling. The feature allows users to control whether submodule fetch failures should be fatal (current behavior) or just produce warnings.

The patch adds a new `fetch.submoduleErrors` config option (with values "fail" or "warn") and a `--submodule-errors` command-line flag. When set to "warn", submodule fetch failures will be reported on stderr but won't cause the overall fetch operation to fail. This is particularly useful when working with upstream branches that reference submodule commits not yet pushed to the submodule's remote.

The implementation touches several areas:
- Adds config parsing in `builtin/fetch.c`
- Introduces a new CLI option with proper validation
- Modifies the submodule fetch machinery to respect the error mode
- Adds comprehensive tests verifying both config and CLI behavior
- Documents the new options in both config and command reference docs

The changes build on the first patch's refactoring of submodule error handling, now allowing the caller to control the failure mode. Test coverage is thorough, including scenarios with both reachable and unreachable submodule commits. The documentation clearly explains the motivation and usage.

This appears to be a well-considered feature addition addressing a real-world pain point when working with in-progress branches that reference unpublished submodule commits. The implementation is clean and maintains backward compatibility while providing the new flexibility.
