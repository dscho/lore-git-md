This is the 10th patch in Patrick Steinhardt's 16-part series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch refactors the in-memory storage backend to use an oidtree instead of a simple growable array.

The key changes are:
1. Replaces the linear array storage with an oidtree (the same data structure used by the loose object backend)
2. Introduces a new `inmemory_object` struct to hold object data
3. Updates all lookup and iteration code to use oidtree operations
4. Simplifies memory management by leveraging oidtree's built-in iteration and cleanup

The motivation is to gain better performance characteristics (O(1) lookups instead of O(n)) and enable lexicographic iteration of objects - functionality that will be useful for future features. The implementation appears clean and builds on existing infrastructure, continuing the series' pattern of careful, incremental changes to the ODB layer.

This patch follows logically from the previous ones in the series, building on the foundation established in earlier patches while making the storage backend more robust and feature-complete. Given Patrick's track record with this kind of architectural work and the clear technical rationale, this seems like a solid step forward in the ODB abstraction effort.
