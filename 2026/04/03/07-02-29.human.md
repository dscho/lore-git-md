This is the second patch in a v3 series introducing new `includeIf` config conditions for matching worktree paths. The patch adds `worktree` and `worktree/i` pattern matching to complement Git's existing `gitdir` and `onbranch` conditions.

The key addition here is the ability to include configs based on the actual working tree path (what `git rev-parse --show-toplevel` returns) rather than the `.git` directory location. This is particularly useful for multi-worktree setups where linked worktrees store their gitdirs in the main repo's `.git/worktrees/`, making `gitdir` patterns awkward to use. The implementation reuses path-matching infrastructure from the first patch in the series.

The documentation thoroughly explains the new conditions' behavior, including glob pattern support (with wildcards, `**/` recursive matching), home directory expansion, and case sensitivity. Test coverage is comprehensive, verifying behavior with bare repos, multiple worktrees, and symlinked paths. The patch appears well-considered and addresses a clear gap in Git's config inclusion system.
