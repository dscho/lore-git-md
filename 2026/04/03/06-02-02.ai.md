This is patch 15/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ODB abstraction effort. The patch stubs out remaining callback functions that aren't needed for the in-memory backend's intended use cases.

The new stubs include:
- `begin_transaction()` which explicitly errors out since transactions aren't supported
- `read_alternates()` as a no-op (in-memory DB has no alternates)
- `write_alternate()` which errors out
- `close()` and `reprepare()` as no-op functions
- Registration of these callbacks in the source initialization

The implementation follows the pattern seen throughout this series - focused, minimal changes that implement just what's needed for the in-memory use case while cleanly handling unsupported operations. The patch maintains the series' careful attention to detail, with each callback getting appropriate treatment based on whether the operation makes sense for ephemeral storage.

With this patch, the ODB source interface appears nearly complete - only one callback remains to be implemented in the final patch of the series. The changes are straightforward and unlikely to be controversial given they're just filling in the remaining pieces of the interface with appropriate behavior for an in-memory backend.
