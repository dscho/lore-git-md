This is a feature patch series that makes submodule fetch errors configurable. The series consists of two patches that work together to provide more flexible handling of submodule fetch failures.

The first patch fixes a pre-existing issue where submodule fetch errors were being recorded too early in the process, before the retry mechanism had a chance to complete. This is a refactoring that preserves existing behavior but cleans up the logic flow.

The second patch introduces new configuration options - both a config setting (`fetch.submoduleErrors`) and a command-line option (`--submodule-errors`) - that allow users to choose between the default "fail" behavior (current behavior where any submodule fetch error causes the whole fetch to fail) and a new "warn" mode where such errors only produce warnings. This is particularly useful when working with upstream branches that are still in flux, where missing commits in submodules don't necessarily indicate a real problem.

The series touches several files including the submodule handling code, fetch implementation, documentation, and adds new test coverage. The v2 iteration includes documentation fixes and expanded option documentation. The changes look well-structured and motivated by a real-world use case where the current behavior is too strict.
