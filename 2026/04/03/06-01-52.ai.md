This is patch 5/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `read_object_stream()` callback for the new in-memory backend, allowing objects to be read from memory-based storage.

The implementation introduces a new `odb_read_stream_inmemory` struct that wraps the streaming interface, with methods for reading chunks of data and closing the stream. The key aspects are:

1. The stream reads directly from the in-memory buffer stored in the `cached_object` structure, copying data into the caller's buffer in chunks.
2. It properly handles partial reads when the requested buffer size exceeds remaining data.
3. The stream maintains an offset to track read position across multiple calls.
4. The close operation is a no-op since there are no resources to clean up (the memory is managed by the parent source).

The patch follows the pattern established in previous patches, keeping the implementation focused on the in-memory backend while integrating with the broader ODB streaming interface. It builds on the infrastructure from patch 4 which implemented object metadata lookup.

This continues the series' trend of carefully implementing one ODB interface method per patch, with each change being relatively self-contained. The implementation appears straightforward and maintains the series' goal of providing temporary, non-persistent object storage. Given Patrick's track record with this kind of architectural work and the clear progression of the series, this seems like solid technical groundwork for the remaining callbacks to follow.
