Patrick Steinhardt continues his work on introducing an in-memory object database backend with patch 6/16 in the series. This patch implements the core write functionality, moving the object writing logic from the old `odb_pretend_object()` into a new `odb_source_inmemory_write_object()` callback. The implementation cleanly handles memory allocation, object storage, and cache growth while maintaining the same behavior as before.

The series is progressing methodically, with each patch implementing a specific ODB source operation. So far, Patrick has established the foundation (patch 1), implemented the free callback (patch 2), optimized object existence checking (patch 3), added read support (patches 4-5), and now completed the write path (patch 6). The changes are focused and maintain the separation of concerns that has characterized this ODB abstraction effort. No review feedback has been posted yet, but given Patrick's track record with architectural changes and the clean implementation approach, this appears to be solid progress toward enabling pluggable ODB backends.
