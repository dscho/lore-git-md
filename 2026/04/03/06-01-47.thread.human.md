Patrick Steinhardt has proposed a 16-patch series introducing an in-memory object database backend as part of his ongoing ODB abstraction effort. This would enable temporary object storage for operations like git-blame worktree commits and future re-merge scenarios, while cleaning up technical debt in the ODB interface.

Junio Hamano, the Git maintainer, has now weighed in with the first substantive review. He suggested a documentation tweak (changing "inmemory" to "in-memory") and provided important conceptual clarification about the feature's scope. Junio emphasized this backend is specifically for truly transient objects that should never persist beyond process lifetime, distinguishing it from ephemeral on-disk storage scenarios. He also speculated about potential applications beyond those mentioned, like octopus merges, while playfully acknowledging the care needed if this were used for non-persistent primary ODB writes.

The series appears technically sound and thorough, with all necessary callbacks implemented and the final patch making the source type generic. Junio's engagement suggests the work is on the right track for eventual inclusion, with his feedback focusing more on conceptual boundaries than implementation concerns at this stage.
