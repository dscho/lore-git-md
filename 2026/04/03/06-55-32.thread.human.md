This thread introduces a two-patch series that makes submodule fetch errors configurable, addressing a common pain point when working with branches that reference unpublished submodule commits. The first patch refactored the error handling in `submodule.c` to fix a pre-existing issue where failures were recorded too early, before the retry mechanism could complete. This was a clean internal change with no user-visible effects.

The second patch, now being discussed, adds the user-facing feature: a new `fetch.submoduleErrors` config option (with "fail" or "warn" modes) and corresponding `--submodule-errors` CLI flag. When set to "warn", submodule fetch errors will be reported but won't fail the overall operation - particularly useful when working with upstream branches in flux. The implementation is thorough, touching config parsing, CLI handling, submodule machinery, and adding comprehensive tests. Documentation clearly explains the motivation and usage.
