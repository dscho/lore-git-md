This is patch 4/16 in Patrick Steinhardt's series introducing an in-memory object database (ODB) backend, part of the ongoing ODB abstraction effort. The patch implements the `read_object_info()` callback for the in-memory source, moving functionality from `odb.c` to the new abstraction layer.

The key changes are:
1. Moves the `find_cached_object()` helper from `odb.c` to `odb/source-inmemory.c` where it logically belongs
2. Implements `odb_source_inmemory_read_object_info()` to handle object metadata queries for in-memory objects
3. Removes the now-redundant in-memory object handling from `do_oid_object_info_extended()`
4. Updates the in-memory source initialization to register the new callback

The implementation preserves all existing behavior while better encapsulating the in-memory object handling. Objects are still found via linear scan of the `objects` array, with special handling for the empty tree object. The callback fills in all standard `object_info` fields when requested (type, size, content, etc.), setting disk size and mtime to zero since these don't apply to in-memory objects.

This continues the pattern of moving ODB functionality into clearly defined callbacks while simplifying the core object database code. The patch appears to be a straightforward mechanical conversion of existing logic to the new abstraction, with no behavior changes beyond the internal reorganization. Given Patrick's track record with this kind of architectural work and the careful separation of concerns shown here, this seems like solid progress on the ODB abstraction effort.
