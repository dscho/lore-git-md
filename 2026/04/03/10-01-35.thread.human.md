This thread introduced a patch by Jörg Thalheim to add a 100ms timeout to config file locking, addressing cases where concurrent Git operations (particularly `git worktree add -b`) could silently fail due to immediate lock contention. The implementation follows the pattern used for reference locking, adding the timeout to two key config.c functions.

Junio Hamano reviewed and accepted the patch, noting that while different subsystems use varying timeout values (from 100ms for references up to 1000ms for credential-store), the chosen 100ms default is reasonable. He humorously dismissed making it configurable due to the circular dependency that would create. With no outstanding issues raised, Junio has queued the patch for inclusion, marking this straightforward bugfix as ready to merge.
