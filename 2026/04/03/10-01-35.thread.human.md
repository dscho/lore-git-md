The thread revisits a previously abandoned proposal to add timeout behavior to config file locking, which had been rejected due to fundamental design concerns despite Johannes Schindelin demonstrating a working implementation in Microsoft's fork. Original author Jörg Thalheim has returned with a revised version that addresses the maintainers' earlier objections.

The new patch introduces a configurable `core.configLockTimeout` option (defaulting to 1000ms) following the same pattern as packed-refs timeout handling. It includes thorough documentation of the behavior and comprehensive test coverage for both success and failure cases. The implementation builds on Microsoft's Scalar-specific solution while adapting it for core Git, maintaining backward compatibility with existing tests.

While the patch doesn't solve all possible race conditions (simultaneous writes to the same key remain problematic), it significantly improves the common case of transient lock contention that particularly affected `git worktree add -b` operations. The thorough test coverage and clear documentation of limitations make this a more mature proposal than the original attempt, though it remains to be seen whether the maintainers will reconsider their position given the earlier consensus to drop the approach.
