This is patch 7/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `write_object_stream()` callback for the new in-memory backend, completing the streaming write capability.

The implementation handles streaming writes by:
1. Allocating a buffer for the full object content
2. Reading chunks from the stream until completion
3. Verifying the total length matches expectations
4. Writing the final object using the existing `write_object()` callback
5. Cleaning up temporary buffers

The code includes error handling for both over- and under-sized streams, maintaining data integrity. This builds on the previous patches that implemented core write support (patch 6) and streaming reads (patch 5).

The patch appears technically sound, following the established pattern of moving functionality into the new backend while maintaining the expected ODB interface. As with the rest of the series, this is a well-contained change that advances the overall goal of a fully functional in-memory ODB source.
