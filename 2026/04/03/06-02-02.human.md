This is patch 15/16 in Patrick Steinhardt's series introducing an in-memory object database backend as part of the ongoing ODB abstraction effort. The patch stubs out the remaining unimplemented ODB source callbacks that aren't needed for the in-memory backend's functionality.

The patch adds no-op implementations for several operations that don't apply to ephemeral in-memory storage:
- Transactions and alternates are explicitly unsupported (returning errors)
- `close()` and `reprepare()` are empty since no cleanup is needed
- These stubs are wired into the source initialization function

The implementation follows the same careful pattern as previous patches in the series, maintaining consistency with the ODB interface while recognizing that some operations simply don't make sense for temporary storage. The changes are straightforward and well-contained, completing the callback suite needed for the in-memory backend to fully implement the ODB source interface.
