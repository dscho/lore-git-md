This is patch 7/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `write_object_stream()` callback for the new in-memory backend, completing the streaming write capability.

The implementation handles writing objects via a streaming interface rather than a single buffer. It:
1. Allocates a buffer for the full object content
2. Reads chunks from the stream until completion
3. Verifies the total length matches expectations
4. Delegates to the existing `write_object()` implementation
5. Cleans up temporary buffers

The code includes error handling for both over- and under-length streams. This matches the pattern seen in other ODB backends while keeping the in-memory implementation simple. The streaming capability will be important for future use cases where objects are generated incrementally rather than all at once.

This continues the series' pattern of methodically implementing each ODB callback while maintaining clean separation between the in-memory backend and core ODB logic. The patch appears straightforward and well-contained, building naturally on the previous infrastructure.
