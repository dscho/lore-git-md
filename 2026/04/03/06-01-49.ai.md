This is the second patch in Patrick Steinhardt's 16-part series introducing an in-memory object database backend as part of the ongoing ODB abstraction effort. The patch implements the `free()` callback for the new in-memory source, moving cleanup logic from `odb.c` into the new backend-specific implementation.

The changes relocate the definition of `struct cached_object_entry` to `odb/source-inmemory.h` since it's now shared between files, and consolidate the memory cleanup code into a new `odb_source_inmemory_free()` function. This follows the series' pattern of moving backend-specific logic out of the generic ODB code.

The patch removes duplicate cleanup code from `odb.c` and replaces it with a call to the new backend's free function, continuing the architectural cleanup started in the series. While this is a mechanical change, it's an important step in properly abstracting the ODB interface - each backend now handles its own resource management.

This appears to be a straightforward implementation building on the foundation established in patch 1. The changes are focused and well-contained, with the commit message noting that the temporary exposure of `struct cached_object_entry` will be addressed in later patches.
