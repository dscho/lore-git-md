This is a feature patchset introducing an in-memory object database source as part of Patrick Steinhardt's ongoing ODB abstraction effort. The 16-part series adds a new backend that stores objects purely in memory without persistence, serving as a building block for future features while cleaning up technical debt in the ODB interface.

Junio C Hamano provides a brief review comment, noting the proper hyphenation should be "in-memory" rather than "inmemory". He also suggests an additional use case for temporary merge objects that could benefit from this feature, while clarifying this isn't meant for cases where objects might later be shared with other processes.

The implementation is thorough, introducing new files `odb/source-inmemory.[ch]` and modifying core data structures like cbtree and oidtree to support arbitrary data storage. Each patch focuses on implementing specific ODB source callbacks, with the final patch making the source type generic. The changes appear carefully scoped to avoid disrupting existing behavior while providing new capabilities for temporary object handling.

Given Patrick's track record with architectural changes and the clear motivation provided, this seems like a solid technical foundation for future work in the ODB abstraction space. The series is now complete and awaiting further review feedback.
