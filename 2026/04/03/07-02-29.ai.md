This is the second patch in a v3 series introducing new `includeIf` config conditions for matching worktree paths. The patch adds `worktree` and `worktree/i` pattern matching to complement Git's existing config inclusion conditions (`gitdir` and `onbranch`).

The implementation builds on the refactored path-matching logic from the first patch, using the new `include_by_path()` helper to match against the worktree path (from `repo_get_worktree()`) rather than the gitdir. The conditions support the same glob pattern features as `gitdir`: wildcards, `**/` recursive matching, home directory expansion, and case-insensitive variants via `worktree/i`. The documentation clearly explains the difference between `gitdir` (matching the .git directory) and `worktree` (matching the checkout path), which is particularly relevant for linked worktrees where gitdirs live in the main repo's `.git/worktrees/`.

Test coverage is thorough, verifying behavior with bare repos, multiple worktrees, symlinked paths, and various pattern matching scenarios. The commit message and documentation provide clear examples of the feature's use cases, such as applying different user.email or GPG keys per worktree without requiring repository-local config changes.
