This is a brief follow-up from the maintainer (Junio C Hamano) on the config file locking timeout patch. He notes that the proposed 100ms timeout is consistent with the default used in the refs backend, though he points out that other subsystems use different values (credential-store uses 1000ms, gc uses 150ms). 

Junio jokingly mentions the chicken-and-egg problem that would arise if this timeout were made configurable (since the config system itself would need to read the configuration), but clarifies he's not seriously suggesting that. He indicates the patch looks good and will be queued for inclusion.

The original patch from Jörg Thalheim addressed a real-world issue where concurrent `git worktree add -b` operations could fail to write branch tracking info due to immediate lock contention. The solution mirrors the reference locking behavior with a 100ms retry period. Junio's response confirms this is reasonable and moves the patch forward without requiring changes.
