This is patch 6/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `write_object()` callback for the in-memory backend, completing the core write path functionality.

The implementation moves the object writing logic from `odb.c`'s `odb_pretend_object()` into a new `odb_source_inmemory_write_object()` function. The new callback handles:
- Memory allocation for the object buffer using `xmemdupz()`
- Storing the object's size, type, and content in the in-memory cache
- Tracking the object ID
- Growing the objects array as needed with `ALLOC_GROW()`

The patch simplifies `odb_pretend_object()` to just delegate to the new callback, removing 14 lines of direct memory management code. The implementation appears straightforward and maintains the same behavior while fitting into the new ODB source abstraction.

This continues the series' approach of methodically implementing each ODB source operation as a separate callback. Given Patrick's track record with architectural changes and the clean separation of concerns shown here, this seems like solid progress on the in-memory ODB backend implementation. The changes are focused and don't appear to introduce any new complexity beyond what's needed for the abstraction.
