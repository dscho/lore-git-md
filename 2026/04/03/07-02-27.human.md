This is a feature patch series introducing new `includeIf` conditions for matching worktree paths in Git configs. The 2-patch series (now in its third iteration) adds `worktree:<pattern>` and `worktree/i:<pattern>` conditions to complement the existing `gitdir` and `onbranch` options.

The motivation is clear: in multi-worktree setups, the `.git` directory always points to the main repository's worktrees directory, making `gitdir` patterns awkward when you want configs to apply based on the working tree's actual path. The new conditions support glob patterns with features like `**/` for recursive matching and case-insensitive variants.

The implementation looks solid - it refactors some existing path-matching code and adds thorough tests. Junio has already reviewed and suggested improvements that were incorporated in v3. This appears ready for inclusion, solving a real pain point for users managing configs across multiple worktrees.

The changes are well-contained to config handling, touching `config.c` and its tests, plus documentation. Given the clear use case and careful implementation, this seems like a worthwhile quality-of-life improvement likely to be picked up in the next cycle.
