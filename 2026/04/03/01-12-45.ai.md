This is a cover letter for a 4-patch series enabling Rust support by default in Git, part of the ongoing Rustification effort. The series comes from brian m. carlson, a long-time contributor who previously led the SHA-256 hash algorithm work.

The cover letter explains that Rust support was meant to be enabled by default in Git 2.53 but was missed, so this series makes the change for Git 2.54. The changes include documentation updates, CI fixes (adding cargo support for Alpine Linux and ensuring proper linking against libdl), and finally flipping the default to enable Rust. The author notes they're keeping two CI jobs that build without Rust to ensure that remains possible.

The series appears technically straightforward - it's implementing a previously agreed-upon change rather than proposing new functionality. The patches focus on build system and CI configuration, with one documentation update. Given this is part of the contentious Rustification effort, the series may attract discussion despite its mechanical nature, particularly around the platform compatibility implications (the libdl and Alpine changes suggest some platform-specific work was needed). The cover letter's lighthearted reference to a broken time machine suggests the author expects this to be non-controversial.
