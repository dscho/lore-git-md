This is patch 12/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `find_abbrev_len()` callback for the in-memory backend, which determines the minimum unambiguous abbreviation length for a given object ID.

The implementation uses the oidtree infrastructure added in earlier patches to efficiently find all objects matching a given prefix. It calculates the longest common hex prefix between the target OID and any matching objects, then returns the length needed to uniquely identify the object (or the next longer length if there are collisions at the current length).

Key technical details:
- Introduces `struct find_abbrev_len_data` to track iteration state
- Uses `oid_common_prefix_hexlen()` to compare prefixes
- Leverages the existing `for_each_object` infrastructure with prefix filtering
- Maintains consistency with Git's existing abbreviation behavior
- Handles the case where multiple objects share the same prefix

This continues the pattern seen in previous patches of implementing one ODB interface callback per commit. The change is focused and builds cleanly on the infrastructure established earlier in the series. The implementation appears straightforward and follows the same general approach used elsewhere in Git for abbreviation length calculation.
