This is a feature patchset introducing an in-memory object database source as part of the ongoing ODB (object database) abstraction effort led by Patrick Steinhardt. The series adds a new backend that stores objects purely in memory without persistence, serving as a building block for future features while also helping to clean up some technical debt.

The in-memory ODB source starts empty and discards all objects when the process exits. While this may seem odd at first, the cover letter explains several use cases: git-blame's temporary worktree commits, potential future re-merge operations, and eventually allowing callers to opt into non-persistent writes. The series also aims to eliminate the `struct object_info::whence` field by providing richer backend-specific metadata.

Technically, the implementation builds on Patrick's previous ODB refactoring work. It introduces a new `odb/source-inmemory.[ch]` pair implementing all required ODB source callbacks (read/write operations, iteration, etc.). The series modifies the cbtree and oidtree data structures to support storing arbitrary data, which the in-memory backend uses to track objects. Several existing ODB functions are simplified as the new abstraction makes some legacy code paths unnecessary.

The patchset appears well-structured with each commit focused on implementing a specific callback or piece of functionality. Given Patrick's track record with large architectural changes and the clear motivation provided, this seems like a solid technical foundation for future work. The changes touch core object storage code but appear carefully scoped to avoid disrupting existing behavior while providing new capabilities.
