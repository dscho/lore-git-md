This thread is about adding `includeIf worktree:` and `includeIf worktree/i:` conditions to Git's config system, so that users can automatically include config files based on which worktree checkout path they are in. The motivating use case is a Linux kernel contributor who wants Git to automatically set a company email address when working in worktrees under a specific directory prefix, without having to manually run `git config --worktree` for each new worktree.

Patch 1/2 refactors the existing `includeByGitdir()` into a generic `include_by_path()` helper, and patch 2/2 implements the new conditions. The feature has broad support from reviewers. Junio C Hamano called it "worthwhile," Patrick Steinhardt said it "seems sensible," and the author has provided the concrete use case the maintainer requested.

The only remaining work is for Chen Linxuan to send a v4 addressing three action items from Patrick: deduplicate documentation for pattern-matching rules (currently copied from `gitdir`), add a test for early-config parsing, and add a test for nongit environments. Junio also wants documentation that helps users choose between `includeIf worktree:` and the existing `extensions.worktreeConfig` based on their use case. Patrick has since clarified that even if the early-config limitation is intentional rather than a bug, it should still be captured as a test -- using `test_expect_failure` to document the expected future state if the behavior is known to be broken.

No new technical issues or objections have been raised. The path to landing this feature is clear once Chen produces v4 with the requested tests and documentation.
