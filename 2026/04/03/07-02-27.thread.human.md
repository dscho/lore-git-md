This thread introduces a new feature for more flexible config file inclusion in multi-worktree setups. The patch series adds `worktree` and `worktree/i` conditions to Git's `includeIf` syntax, allowing configs to be included based on the path to a worktree rather than just the gitdir. This solves a practical pain point since linked worktrees store their gitdirs in the main repo's `.git/worktrees/` directory, making `gitdir` patterns awkward to use.

The implementation builds on existing path-matching logic but generalizes it to handle both gitdir and worktree cases. It supports the same pattern matching features as other Git pathspecs, including wildcards, recursive matching with `**/`, and case-insensitive variants. The patches include comprehensive tests covering various path matching scenarios.
