This is patch 14/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `freshen_object()` callback for the in-memory backend, which checks whether a given object exists in the in-memory store.

The implementation is straightforward - it simply checks for the object's presence via the existing `find_cached_object()` helper function, returning 1 if found and 0 otherwise. This matches the behavior of other ODB backends where freshening an object updates its timestamp to prevent garbage collection, though in this is a no-op for the in-memory case since objects are never persisted.

The change follows the series' pattern of methodically adding each required ODB source callback. The implementation is clean and minimal, leveraging existing infrastructure. With this addition, the in-memory backend now handles all core object operations except for the remaining callbacks to be implemented in subsequent patches.

This continues the series' steady progress toward a complete in-memory ODB implementation that can serve as a building block for features needing temporary object storage while helping clean up technical debt in Git's object storage layer.
