This is a feature patchset introducing an in-memory object database source as part of Patrick Steinhardt's ongoing ODB abstraction effort. The series has now received feedback from Junio C Hamano, the Git maintainer, marking the first review interaction in this thread.

Junio's response focuses on two main points. First, he suggests a minor hyphenation correction for "inmemory" to "in-memory" for better readability. More substantively, he clarifies the intended use case for this feature, distinguishing it from ephemeral on-disk storage scenarios where objects might later be promoted to the main object store. His comment indicates this in-memory backend is specifically for truly transient objects that should never persist beyond the process lifetime.

The maintainer also speculates about potential applications beyond those mentioned in the cover letter, suggesting octopus merge operations could benefit from temporary in-memory objects. His ";-)" response to Patrick's vision of using this for non-persistent primary ODB writes hints at both the possibilities and the care needed with such applications.

This exchange confirms the technical direction while subtly reinforcing the feature's scope boundaries. Junio's engagement suggests the series is on track for consideration, with his feedback focusing more on conceptual clarity than implementation concerns at this stage. The thoroughness of the 16-part implementation appears to have met the maintainer's expectations for such a foundational change.
