This is a feature patch introducing an "inmemory" object database source as part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort. The series adds a new backend that stores objects purely in memory, never persisting them to disk.

The in-memory ODB serves several purposes: it provides a clean way to handle temporary objects (like those used by `git blame` for worktree commits), enables future use cases like re-merging diffs without persistence, and helps eliminate the `whence` field from `struct object_info` by tracking object origins through the ODB source instead.

The 16-patch series builds out the implementation methodically, starting with basic infrastructure and adding callbacks for all required operations (reading/writing objects, enumeration, etc.). It modifies the cbtree and oidtree data structures to support this use case and integrates the new source type into Git's ODB framework.

This appears to be a well-structured series from a trusted contributor working on a major architectural effort. The commit messages are thorough and the changes focused. While the immediate use cases are limited, the infrastructure could enable interesting future capabilities for temporary object storage. Reviewers will likely want to examine the memory management implications and verify the abstraction boundaries remain clean.
