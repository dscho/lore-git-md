This is a refactoring patch (9/16) in Patrick Steinhardt's series introducing an in-memory object database backend, part of the ongoing ODB abstraction effort. The patch extends the oidtree data structure to store arbitrary payload data alongside object IDs, rather than just tracking OID existence.

The change allows callers to associate custom data with each stored OID while maintaining the tree's efficient prefix operations. The implementation introduces a new `data` field in `struct oidtree_node` and adds an `oidtree_get()` function to retrieve stored values. Existing callers are updated to pass NULL where they previously didn't need payload data.

The patch includes a new unit test verifying that inserting with different data pointers correctly overwrites previous values. This functionality will be used in the next patch to store object metadata in the in-memory ODB backend. The changes are cleanly scoped and maintain backward compatibility while adding the new capability.
