Thread subject: [PATCH v2] config: add timeout to config file locking. Thread type: bugfix patch. Originating author: Jörg Thalheim. Core problem: concurrent Git operations fail when writing to config files due to immediate lock contention failures, particularly affecting `git worktree add -b` operations writing branch tracking information. Current status: v2 patch proposing configurable timeout after previous rejection, now with maintainer engagement; implementation details under active discussion between Junio C Hamano and Patrick Steinhardt. Key technical details: introduces `core.configLockTimeout` (default 1000ms) following `core.packedRefsTimeout` pattern; documents read-after-lock semantics; adds comprehensive test coverage. Junio identified caching behavior makes timeout effectively process-wide despite repository parameter, suggesting either making it explicitly process-wide (preferred) or removing caching for true per-repo behavior. Patrick Steinhardt counters that caching may be unnecessary overhead and proposes removing it while keeping repository parameter, creating de facto per-repo timeout that would typically use uniform values. Open questions: whether to adopt process-wide simplification (Junio's position) or remove caching while retaining repository parameter (Patrick's position). Participant positions: Jörg Thalheim driving implementation; Junio and Patrick engaged in substantive technical review of implementation tradeoffs; Johannes Schindelen now accepts the unit-less timeout naming convention despite personal preference for explicit units, noting he'll handle any Windows-specific adjustments. New development: Junio concurs with Johannes' philosophical position that numeric configuration values should include units, though considers this a separate code quality issue not requiring immediate resolution in this patch series. Related work: builds on Microsoft's Scalar-specific solution and packed-refs timeout precedent. Outcome: implementation refinement continues with two viable approaches under discussion (process-wide vs per-repo), while stylistic discussion about configuration value units remains acknowledged but deferred.
