This is part 2 of a 3-patch series continuing the `the_repository` removal effort in the refs subsystem. The patch focuses on eliminating usage of the global `the_hash_algo` variable in refs.c, replacing it with repository-specific hash algorithm access.

The changes are mechanical but important - they modify transaction handling and submodule ref storage to use the hash algorithm from either the transaction's ref_store->repo or the passed repository parameter rather than the global state. Key functions affected include ref_transaction_create/delete, migrate_one_ref, and transaction_hook_feed_stdin.

This follows the established pattern of the larger `the_repository` removal effort by René Scharfe, making repository dependencies explicit rather than implicit. The patch appears straightforward and well-contained, touching only the necessary call sites while maintaining existing behavior. It's a clear incremental step in the multi-year effort to eliminate global state from Git's codebase.

The changes are focused on refs.c only, with no behavioral changes intended. The patch builds on the previous work in the series (which handled file ref lock timeouts) and sets up for the final patch addressing the reftable backend.
