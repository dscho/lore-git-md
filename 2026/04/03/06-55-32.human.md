This is a feature patch series that makes submodule fetch errors configurable, allowing users to choose between fatal errors (current behavior) or warnings when submodule fetches fail.

The series addresses a common pain point when working with submodules during active development - currently Git fails hard if any submodule references an unreachable OID, even when the local branch doesn't actually depend on that commit. This is particularly disruptive during merge windows when upstream branches are still being prepared.

The first patch fixes a pre-existing issue where fetch failures were recorded too early in the submodule fetch process. The second patch introduces new configuration options (`fetch.submoduleErrors`) and a command-line flag (`--submodule-errors`) to let users opt into non-fatal behavior while maintaining backward compatibility (default remains fatal errors).

The series comes with thorough documentation updates and extensive test coverage (96 lines of new tests). The v2 iteration addresses minor documentation formatting issues from the initial submission. The changes are well-motivated and the implementation appears clean, touching only the relevant subsystems (submodule handling and fetch machinery). This looks like a useful quality-of-life improvement for submodule workflows.
