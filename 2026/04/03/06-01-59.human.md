This is patch 12/16 in Patrick Steinhardt's series introducing an in-memory object database (ODB) backend, part of the ongoing ODB abstraction effort. The patch implements the `find_abbrev_len()` callback for the in-memory source, which determines the shortest unambiguous prefix length for a given object ID.

The implementation uses the minimum length needed to uniquely identify an object in the in-memory store, building on the oidtree-based storage introduced in earlier patches. It leverages the existing `for_each_object` infrastructure with prefix filtering to efficiently find all objects that share the initial prefix bytes, then calculates the minimal distinguishing length.

The patch follows the established pattern of the series - cleanly implementing one ODB source callback at a time while maintaining the separation between interface and implementation. The changes are well-contained to the in-memory backend code and don't affect other parts of the system. As with previous patches in the series, this appears to be a solid technical contribution that moves the abstraction effort forward.
