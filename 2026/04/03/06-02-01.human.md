This is patch 14/16 in Patrick Steinhardt's series introducing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch implements the `freshen_object()` callback for the in-memory backend, which checks whether a given object exists in the in-memory store.

The implementation is straightforward - it simply looks up the object in the in-memory storage (using the existing `find_cached_object()` helper) and returns 1 if found, 0 otherwise. This matches the behavior of other ODB backends where freshening an object updates its timestamp to prevent pruning, though for the in-memory case it's just an existence check since the objects are transient anyway.

The patch follows the series' pattern of methodically implementing each required ODB callback in turn. With this addition, the in-memory backend now handles all the core object operations needed for basic functionality. The change is small and focused, touching only the in-memory source implementation file with no impact on other code paths.
