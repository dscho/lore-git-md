This is the second patch in a two-part series introducing configurable handling of submodule fetch errors. The first patch was a refactoring to clean up error handling; this one adds the new user-facing options.

The patch adds a `fetch.submoduleErrors` config setting (with values "fail" or "warn") and a corresponding `--submodule-errors` command-line option. When set to "warn", submodule fetch failures will be reported but won't cause the overall fetch to fail - useful when working with upstreams that reference submodule commits not yet pushed. The default remains "fail" (current behavior).

The implementation touches the fetch command, submodule handling code, and documentation, with thorough test coverage showing both config and CLI usage.
