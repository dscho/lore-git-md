This is a feature patch (10/16) in Patrick Steinhardt's series introducing an in-memory object database source as part of the ODB abstraction effort. The patch refactors the in-memory storage backend to use an oidtree instead of a simple growable buffer.

The key changes are:
- Replaces the array-based storage (`struct cached_object_entry`) with an oidtree that maps OIDs to `struct inmemory_object` entries
- Gains O(log n) lookups instead of O(n) scans
- Enables lexicographic iteration and unique prefix matching
- Updates all related functions to work with the new data structure
- Adds proper cleanup via `oidtree_each()` callback when freeing objects

The patch maintains the same external interface while improving internal efficiency. It builds on the oidtree modifications from patch 9/16, showing the series' careful progression from foundational changes to higher-level functionality. The implementation appears clean and well-contained, with no obvious impact on other subsystems beyond the in-memory ODB backend itself.
