This is part 1 of a 3-patch series continuing the `the_repository` removal effort in the refs subsystem. The patch focuses specifically on ref lock timeouts, converting the `get_files_ref_lock_timeout_ms()` function to take an explicit `struct repository*` parameter instead of relying on the global `the_repository`.

The key changes are:
1. Adding repository parameter to `get_files_ref_lock_timeout_ms()` and updating its call to `repo_config_get_int()`
2. Passing the repository through call chains - from `lock_raw_ref()` (which gets it from the transaction's ref_store) and via a new `create_reflock_cb` wrapper struct for the `create_reflock()` callback case
3. Updating the function declaration in `refs-internal.h`

The changes are mechanical but important for eliminating global state dependencies. The patch follows established patterns seen in other parts of the `the_repository` removal effort. While the timeout value itself remains cached statically (preserving existing behavior), the configuration lookup now uses the proper repository context.

This is a focused, well-contained change that makes incremental progress on the larger effort while avoiding more complex cases (like branch helpers) that were deferred from this series. The patch appears straightforward with no obvious issues - it maintains existing behavior while making repository dependencies explicit.
