This is a refactoring patch in Patrick Steinhardt's ongoing ODB (object database) abstraction series (9/16). It extends the oidtree data structure to store arbitrary payload data alongside object IDs, rather than just tracking OID existence.

The patch modifies the oidtree implementation to:
- Add a `data` pointer field to `struct oidtree_node`
- Introduce a new `oidtree_get()` function to retrieve stored data
- Update the callback signature for iteration to include the node data
- Handle data overwrites when inserting duplicate OIDs
- Add a unit test verifying data storage behavior

The changes are mechanical but carefully implemented, with all existing callers updated to pass NULL for the new data parameter. The patch maintains backward compatibility while enabling new functionality needed for the in-memory ODB backend, where objects themselves will be stored as the payload data.

This continues the series' pattern of methodically building infrastructure for the ODB abstraction. The changes are well-contained to the oidtree subsystem and include test coverage for the new behavior. As with previous patches in the series, this appears to be a solid technical foundation for the upcoming in-memory ODB implementation.
