This is a 2-patch series (v3) introducing new `includeIf` config conditions `worktree` and `worktree/i` for matching against worktree checkout paths, complementing existing `gitdir` and `onbranch` conditions. The originating author is not the thread root, but the series has gone through three iterations incorporating feedback from Junio C Hamano. The motivation is improving config inclusion in multi-worktree setups where `gitdir` patterns are awkward since linked worktrees store their gitdirs in the main repo's `.git/worktrees/`.

**Current status**: v3 has been posted. Junio has publicly stated the feature is "a worthwhile thing to have" and gave a preliminary "OK-ish" assessment, but explicitly declined to perform a full review himself as he is "not fully back up to speed." He is directly soliciting one or two volunteer reviewers before he will take the series into `seen`. The series is directionally approved but not yet ready for merge -- it needs an extra set of eyeballs from the community.

**Key technical details**: The first patch refactors path-matching logic from `include_by_gitdir()` into a generic `include_by_path()` to handle both gitdir and worktree cases. The second patch implements the new `worktree` condition (with `worktree/i` for case-insensitive matching) using this helper, matching against the worktree path from `repo_get_worktree()` rather than the gitdir. Both conditions support glob patterns (wildcards, `**/` recursive matching) and home directory expansion. Core files touched: `config.c`, `path.c`, new tests in `t/t1300-config.sh`.
