**Thread identity:** `[PATCH v3 0/2]` from Chen Linxuan, adding `includeIf` config conditions `worktree` and `worktree/i` that match a worktree's checkout path.

**Core problem and goal:** Enable config inclusion based on which worktree checkout path the user is in -- simplifies multi-worktree setups where `gitdir`-based patterns are awkward (linked worktree gitdirs live under the main repo's `.git/worktrees/`, not alongside the checkout).

**Current status:** v3 posted. The author has replied to Junio C Hamano and Phillip Wood with the concrete use case (contributing to Linux kernel as both employee and individual; `includeIf worktree:` automatically sets company email when worktree is under a specific directory prefix, avoiding manual `git config --worktree` per new worktree). This satisfies the maintainer's requirement for an articulated, real-world motivation.

**Key technical details:**

- **Patch 1/2:** Refactors `include_by_gitdir()` into a generic `include_by_path()` helper in `config.c`.
- **Patch 2/2:** Implements `worktree` and `worktree/i` conditions in `include_condition_is_true()` via `skip_prefix_mem`, calling `include_by_path()` with `repo_get_work_tree(inc->repo)` (NULL outside a repo). The matched path is the worktree checkout root (`git rev-parse --show-toplevel`), not the `.git` directory. Supports glob patterns and `~` expansion. Files: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh`.
