Thread identity: `[PATCH v3 0/2]` from Chen Linxuan, adding `includeIf` config conditions `worktree` and `worktree/i` to complement `gitdir` and `onbranch`.

Core problem and goal: Enable config inclusion based on a worktree's checkout path, simplifying multi-worktree setups where `gitdir` patterns are awkward because linked worktrees store their gitdirs in the main repo's `.git/worktrees/`.

Current status: v3 posted. Patrick Steinhardt provided a full substantive review endorsing the series with three actionable requests (documentation dedup, two additional tests). Phillip Wood then raised a design-level question challenging whether the feature is needed at all given that per-worktree config already exists via `extensions.worktreeConfig` and `git config --worktree`. This is the first substantive challenge to the feature's premise. The author has not yet replied. Expected next step is v4 that must address both Patrick's implementation requests AND Phillip's motivation question.

Key technical details:
- **Patch 1/2**: Refactors `include_by_gitdir()` into a generic `include_by_path()` helper in `config.c`.
- **Patch 2/2**: Implements `worktree` and `worktree/i` conditions in `include_condition_is_true()` using `skip_prefix_mem`, calling `include_by_path()` with `repo_get_work_tree(inc->repo)` (NULL outside a repo). Supports glob patterns and `~` expansion. The path matched is the worktree checkout root (`git rev-parse --show-toplevel`), not the `.git` directory. Files: `config.c`, `Documentation/config.adoc`, `t/t1305-config-include.sh`.

Open questions and loose ends:

Phillip asked for a concrete use case where `worktree:` patterns are meaningfully better than the existing mechanism. The author must reply.
