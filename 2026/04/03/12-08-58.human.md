This is part 1 of a 3-patch series in the ongoing `the_repository` removal effort, focusing specifically on refs subsystem cleanup. The patch converts `get_files_ref_lock_timeout_ms()` to take an explicit `struct repository` parameter instead of relying on the global `the_repository`.

The change is mechanical but important - it updates the lock timeout function to use repository context passed through call chains rather than the global variable. The patch handles two call sites: `lock_raw_ref()` which can get the repository from the transaction->ref_store, and `create_reflock()` which requires a new wrapper struct to pass both the lock_file and repository through callback data.

This continues René Scharfe's long-running effort to eliminate global state in Git. The change follows established patterns seen in similar conversions, maintaining existing behavior while making repository dependencies explicit. The patch appears well-contained and properly handles both direct calls and callback cases, suggesting careful consideration of the refs backend's locking mechanisms.

As part of a narrowed-down series (from 5 to 3 patches based on review feedback), this represents incremental but meaningful progress on the broader `the_repository` removal goal. The remaining patches in the series will tackle hash algorithm usage and reftable backend conversions.
