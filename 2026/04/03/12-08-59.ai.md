This is part 2/3 in Shreyansh Paliwal's refactoring series to remove `the_repository` usage from the refs subsystem, specifically targeting the `the_hash_algo` global variable. The patch mechanically converts all uses of `the_hash_algo` in refs.c to use repository-specific hash algorithms instead.

The changes propagate through several key ref transaction functions:
- `ref_transaction_create()` and `ref_transaction_delete()` now use the hash algorithm from the transaction's ref_store->repo
- `repo_get_submodule_ref_store()` uses the parent repository's hash_algo
- Hook and migration functions similarly access the hash algorithm through available repository context

The patch follows the established pattern of the `the_repository` removal effort by making repository dependencies explicit while maintaining identical behavior. It touches core ref transaction operations but avoids more complex cases (like the deferred branch helper conversions from earlier versions of this series). The changes are straightforward replacements with no functional impact, though they do highlight how deeply the hash algorithm was previously embedded as global state.

This continues René Scharfe's long-running effort to eliminate global variables from Git's codebase. The patch is well-contained and appears ready for merging, though it depends on the repository context being properly propagated through all call chains - something the series' other patches help ensure.
