Thread identity: Rust support enablement series for Git 2.54, authored by brian m. carlson, continuing the Rustification effort.

Core problem: Enabling Rust support by default in Git builds, which was intended for Git 2.53 but missed. This is an implementation of prior consensus rather than new functionality.

Current status: Series v1 with 4 patches - documentation updates, CI fixes for Alpine Linux (cargo support) and linking against libdl, followed by the default enablement. Maintains two CI jobs building without Rust to preserve that option. The latest patch specifically addresses a build requirement for older Rust versions on Linux systems by adding `-ldl` to the linker flags when building on Linux, ensuring compatibility with Debian 11's older Rust toolchain in CI.

Key technical details:
- Build system changes to flip default Rust support
- CI configuration updates for Alpine Linux compatibility
- Linking fixes for libdl (explicit `-ldl` for Linux builds)
- Documentation updates reflecting the new default
- Modifies `config.mak.uname` to add linker flag for Linux builds
- Ensures compatibility with older Rust toolchains that don't automatically link libdl

Open questions: None explicitly raised in cover letter, but platform compatibility implications may surface in discussion given Rustification's contentious history. The libdl change is noted as safe since libdl is part of libc and available on both glibc and musl systems.

Participant positions: Only author brian m. carlson so far, presenting as straightforward implementation of prior agreement. The latest change is presented as a necessary but uncontroversial platform compatibility fix.
