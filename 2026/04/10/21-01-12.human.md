This is the third patch in a four-part series that enhances `git checkout -m` with autostash behavior and adds customizable conflict marker labels. The series has gone through nine iterations and is now fully polished, with all technical concerns addressed.

The current patch extends the sequencer's autostash machinery to support optional conflict marker labels when applying stashes. It introduces a new `apply_autostash_ref_with_labels()` function that allows callers to specify custom labels for "ours", "theirs", and "base" sides of conflicts. The implementation builds on the existing autostash infrastructure while maintaining backward compatibility - all existing callers continue to work as before by passing NULL for the label parameters.

The changes are cleanly implemented with proper parameter passing through the call chain from the new public API down to the internal `apply_save_autostash_oid()` function that actually invokes `git stash apply` with the appropriate label options. The patch follows the project's established patterns for adding new functionality while preserving existing behavior.

This is part of the series' broader goal to unify conflict resolution behavior across Git commands by bringing autostash capabilities to `git checkout -m` while also providing more control over conflict marker labeling. The implementation looks solid and well-tested, with the surrounding series having already received thorough review from both Phillip Wood and Junio Hamano.
