This is the ninth iteration of a feature patch series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through extensive review and is now fully polished, with all technical concerns resolved.

The key changes in v9 include:
1. Renamed the stash apply label options from `--ours-label`/`--theirs-label`/`--base-label` to `--label-ours`/`--label-theirs`/`--label-base` for consistency with other Git commands
2. Fixed the boolean parameter type for silent autostash creation from `int` to `bool`
3. Maintained the original stdout message output behavior rather than switching to stderr
4. Improved test cases to use `test_commit` for better isolation and clarity

The implementation provides:
- Customizable conflict markers via new label options in `git stash apply`
- Silent autostash creation during branch switching
- Unified conflict resolution behavior matching existing rebase/merge workflows
- Comprehensive test coverage (19 cases in t7201-co.sh) including tests for:
  - Non-overlapping changes
  - Empty label handling
  - Stash list verification

Technical components modified include `builtin/checkout.c`, `builtin/stash.c`, `sequencer.c`, and related test files. The series has received maintainer approval through multiple iterations and addresses all feedback, making it production-ready with comprehensive documentation. This represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes.
