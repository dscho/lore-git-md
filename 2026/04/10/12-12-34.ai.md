This is patch 4/17 in Patrick Steinhardt's feature series implementing an in-memory object database source as part of the ongoing ODB abstraction effort. The patch moves the `read_object_info()` functionality from `odb.c` into the new in-memory backend implementation.

The key changes are:
1. Moves the `find_cached_object()` helper from `odb.c` to `source-inmemory.c` since it's now backend-specific
2. Implements the `read_object_info` callback for the in-memory source, handling all the same cases as the original code (type, size, content, etc.)
3. Updates the main ODB code to use the new callback instead of its direct implementation
4. Maintains identical behavior including special handling of the empty tree object

The implementation is clean and straightforward, following the pattern established in earlier patches of the series. It demonstrates good separation of concerns by moving backend-specific logic out of the core ODB code. The callback faithfully reproduces all the original functionality including the somewhat obscure empty tree special case.

This patch is part of the series' steady progress toward fully abstracting the ODB interface. With this change, another core operation (object info lookup) is properly delegated to the backend implementation rather than being handled directly by the ODB layer. The series as a whole is well-reviewed and appears ready for integration pending final terminology tweaks.
