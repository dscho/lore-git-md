This is a bugfix patch in the parallel hook execution series, addressing a memory leak in `repo_init()`. The patch fixes a pre-existing issue where `clear_repository_format()` wasn't called in the error path when initializing a repository with v1 extension on v0 format - an edge case that only occurs in development environments.

The change is minimal but important, adding a single line to ensure proper cleanup. While the memory leak wasn't affecting normal usage, the fix demonstrates good hygiene in the codebase. The patch has been reviewed as part of the larger parallel hooks series which has already received maintainer approval, suggesting this fix is uncontroversial.

Technical details: The patch adds `clear_repository_format(&format)` in the error path of `repo_init()` to match the cleanup that happens in the success path. This ensures symmetry in resource management and prevents a potential memory leak when repository initialization fails under specific conditions. The change touches the core repository initialization code but doesn't affect any user-visible behavior.
