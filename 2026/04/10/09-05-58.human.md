This is part 3 of a 13-patch series introducing parallel hook execution, now in its final version with maintainer approval. The series builds on Adrian Ratiu's earlier configurable hooks work to enable concurrent execution of hooks with extensive configuration options.

This particular patch adds the foundational `hook.jobs` configuration option - a global setting that determines how many hooks can run simultaneously. It defaults to 1 (serial execution) when unspecified. The implementation parses the config value and stores it in the repository struct, though the value isn't yet used (that comes in later patches). The patch includes basic validation to ensure the value is a positive integer.

The series as a whole provides a comprehensive configuration system with multiple layers of control (global, per-hook, per-event, and CLI overrides), with this patch establishing the base global setting. The implementation is clean and well-documented, with appropriate warnings for invalid values. As part of an already-approved series, this patch appears ready for merging.
