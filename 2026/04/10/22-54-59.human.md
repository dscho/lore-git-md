This is a documentation patch from Lorenzo Pegorari's v5 series on promisor file handling during repacks, part of his GSoC work mentored by Eric Sunshine. The patch adds a clarifying comment to `pack-write.c` explaining the purpose of storing ref names and hashes in `.promisor` files.

The comment documents that this information is not used in production but serves a debugging purpose - it helps identify which refs were fetched when the packfile was downloaded, allowing comparison with the promisor remote's current state if needed. This explanation was previously only in the commit message for 5374a290 ("fetch-pack: write fetched refs to .promisor").

The patch is straightforward and well-motivated, addressing a gap in the code's documentation. It's part of a larger series that has already addressed all technical and style feedback in previous iterations, including timestamp formatting and header inclusion compliance. This particular patch appears uncontroversial and ready for inclusion.
