This is a v4 patch series addressing promisor file handling during repacks, part of Lorenzo Pegorari's GSoC work under Eric Sunshine's mentorship. The series builds on the previous v3 iteration with several key improvements.

The core change preserves debugging information in `.promisor` files when repacking promisor packfiles, solving the `NEEDSWORK` from commit 5374a290. The v4 version makes several notable improvements: switching to Unix time format for timestamps, replacing the `strbuf` list with a more lightweight `string_list`, and fixing test flakiness by using `repack -a -f` for deterministic behavior. The tests have been significantly improved with better shell variable quoting, direct file operations, and simplified test setup.

The series consists of 5 patches:
1. Documentation explaining `.promisor` file contents
2. New helper function `copy_promisor_content()` that handles metadata copying with timestamp preservation
3. Integration of the helper into repack logic with geometric repack awareness
4-5. Expanded test coverage in both regular and geometric repack scenarios

A key technical discussion point is raised about header inclusion policy - the author questions whether `strmap.h` and other headers should be explicitly included per the CodingGuidelines, suggesting this may need clarification. The implementation appears solid, with all prior feedback addressed, including Junio's detailed test hygiene suggestions. The geometric repack testing in particular shows careful attention to integration with Taylor Blau's ongoing geometric repacking work.

For future reference, key technical details include:
- Unix epoch time format for timestamps in `.promisor` files
- `string_list` usage replacing `strbuf_split_max()`
- `repack -a -f` for deterministic test results
- Modified files: `pack-write.c`, `repack-promisor.c`, test scripts
- Open question about header inclusion requirements
