This is a feature patchset introducing an in-memory object database source as part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort. The series is now in its third iteration and appears ready for integration pending final terminology alignment in error messages.

The implementation provides a complete non-persistent ODB backend that stores objects purely in memory, discarding them when the process exits. While this may seem unusual at first, the cover letter explains several use cases including git-blame's temporary worktree commits and potential future re-merge operations. The backend also helps eliminate technical debt by providing richer metadata than the current `struct object_info::whence` field.

Technically, the series builds on previous ODB refactoring work and introduces a new `odb/source-inmemory.[ch]` implementation. Key aspects include:
- Full callback coverage (read/write operations, iteration, counting, etc.)
- Oidtree-based storage with O(1) lookups and sorted iteration
- Streaming read/write support
- Unit tests verifying all functionality
- The implementation has been reviewed and approved by Karthik Nayak and Justin Tobler
- Junio Hamano confirms the technical implementation is complete and correct
- Final discussion focuses on consistently using "in-memory" vs "in-core" terminology in error messages
- The series is ready for integration after this last terminology change

This represents a significant milestone in the ODB abstraction effort and provides infrastructure that will be immediately useful for git-blame while enabling future features requiring transient object storage. The careful review process and thorough test coverage suggest this is a well-vetted addition to Git's object storage layer.
