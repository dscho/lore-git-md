This is a refactoring patch from Adrian Ratiu as part of the parallel hook execution feature series. The change moves the `is_known_hook()` function from being a static helper in builtin/hook.c to a public function in hook.c/hook.h, making it available for wider use across the codebase. 

The patch converts the function to return a bool (rather than int) and renames the iterator variable for clarity. It also updates both the Makefile and meson.build to reflect that hook-list.h is now used by libgit rather than just the builtin sources. The change is co-authored by Patrick Steinhardt, indicating collaboration on the build system aspects.

This is a preparatory change for the next patch in the series which will use this function to detect when users accidentally configure hooks using friendly names rather than event names. The implementation is straightforward - it maintains the same functionality while making it more accessible to other parts of the hook system. The build system changes show careful attention to dependencies and proper header usage.

As part of the larger parallel hooks series that has already received maintainer approval, this patch represents a small but meaningful step in organizing the hook infrastructure code for better reuse. The change demonstrates good code hygiene by centralizing hook-related functionality while maintaining clean separation between the builtin command and core hook logic.
