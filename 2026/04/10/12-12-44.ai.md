This is part 14/17 of Patrick Steinhardt's feature patch series implementing an in-memory object database source, part of the ongoing ODB abstraction effort. The series is now reached its third iteration and is nearly ready for integration, with all technical review addressed.

This particular patch implements the `freshen_object()` callback for the in-memory ODB backend. The callback checks whether a given object exists in the in-memory store, returning 1 if found and 0 otherwise. The implementation is straightforward - it reuses the existing `find_cached_object()` helper function that was introduced in earlier patches of the series.

The patch is small and focused, touching only the `odb/source-inmemory.c` file to add the callback implementation and register it in the source vtable. This follows the pattern established by previous patches in the series for implementing individual ODB callbacks. The implementation appears correct and consistent with the rest of the series.

As with the other callback implementations in this series, this completes another piece of the puzzle for a fully functional in-memory ODB backend. The series as a whole has been thoroughly reviewed and is now in its final stages, with only some minor terminology alignment in error messages remaining before integration.
