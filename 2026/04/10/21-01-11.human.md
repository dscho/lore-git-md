This is part 2 of a 4-part feature series that enhances `git checkout -m` with autostash behavior and adds customizable conflict markers. The series is now in its 9th iteration and has been thoroughly reviewed, with all technical concerns resolved.

The current patch adds silent autostash creation capability to the sequencer, which will be used by the `git checkout -m` implementation in later patches. It introduces a new `create_autostash_ref_silent()` function that suppresses the "Created autostash" message output, while maintaining the existing verbose behavior for other callers. The implementation is clean and straightforward, adding a `bool silent` parameter to the internal helper function.

This change supports the series' goal of making branch switching with conflicts (`git checkout -m`) behave more like rebase/merge workflows that use autostash. The silent option will be particularly useful for scripted/non-interactive use cases where stable output is important. The patch follows Git's coding conventions and includes the necessary header updates to expose the new function.

As part of the now-complete series, this patch has been reviewed by Phillip Wood and has maintainer approval from Junio C Hamano. The series as a whole represents a significant quality-of-life improvement for branch switching workflows with uncommitted changes.
