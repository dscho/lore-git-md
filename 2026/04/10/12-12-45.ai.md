This is part 15/17 of Patrick Steinhardt's feature patch series implementing an in-memory object database (ODB) backend, now in its third iteration. The series is nearly complete, with all technical aspects reviewed and approved - this patch handles the final stubs for unimplemented ODB operations.

The patch adds no-op implementations for several ODB callbacks that don't make sense for an in-memory backend:
- Transactions (explicitly unsupported with an error)
- Alternate object databases (read as no-op, write as error)
- Close and reprepare hooks (no-ops)
These are wired into the backend's callback table alongside the previously implemented operations.

The implementation follows the established pattern of the series - clean, minimal code with clear error messages when operations aren't supported. The patch completes the callback coverage for the in-memory backend, leaving only the final terminology alignment (in-memory vs in-core) as the last remaining issue before integration.

As with the rest of the series, this shows careful attention to the ODB abstraction interface while making appropriate tradeoffs for the in-memory use case. The patch is straightforward and uncontroversial, representing the final technical pieces needed before this backend can be merged.
