This is the first patch in the v9 series implementing customizable conflict marker labels for `git stash apply`. The patch adds three new options to `git stash apply`: `--label-ours`, `--label-theirs`, and `--label-base` (the latter only effective with merge.conflictStyle=diff3). These allow users to specify custom labels for conflict markers instead of the default "Updated upstream"/"Stashed changes"/"Stash base".

The implementation:
- Adds documentation for the new options in Documentation/git-stash.adoc
- Introduces a new `do_apply_stash_with_labels()` function that wraps the existing apply logic while accepting the new label parameters
- Modifies xdiff/xmerge.c to properly handle empty labels (a key requirement for scripted workflows)
- Adds comprehensive tests in t/t3903-stash.sh covering both custom labels and empty labels

The changes are well-contained, touching only the stash command and its underlying merge machinery. The patch maintains backward compatibility by defaulting to the original labels when none are specified. The test coverage is thorough, verifying both the happy path and edge cases like empty labels.

This represents the final polished version of this functionality after nine iterations of review, with all technical concerns (option naming, parameter types, test structure) now resolved. The implementation is clean and follows Git's established patterns for similar features.
