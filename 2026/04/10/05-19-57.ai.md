Platform compatibility patch addressing NonStop I/O limits, now deferred to next release cycle. This is the final message in a thread where Patrick Steinhardt proposed a solution for NonStop systems' small `MAX_IO_SIZE` limit in the `writev()` path. The implementation introduces `xwritev()` to properly handle platform-specific I/O size limits by coalescing iovec entries and falling back to `xwrite()` when needed.

After thorough review by Jeff King and Junio C Hamano, all edge cases have been verified - including handling of oversized first entries and overflow protection. The counting-down approach to overflow checking (suggested by Jeff King) and restructuring of first-buffer handling were key improvements during review. While the technical solution is now confirmed correct, Patrick has decided to defer the patch until after the Git 2.54 release cycle, with NonStop users advised to use the `NO_WRITEV` workaround in the interim.

This exchange demonstrates the project's meticulous attention to platform-specific edge cases, particularly around I/O safety. The careful review process involving both Jeff King (for technical correctness) and Junio (as maintainer) ensures robust solutions even for less common platforms. The patch will be reintroduced in the next development cycle.
