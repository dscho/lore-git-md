This is a feature patch in Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically part 10/17 of the in-memory ODB backend series. The patch refactors the in-memory object storage from a simple growable array to using Git's existing oidtree data structure.

The key technical improvements in this patch are:
- Replaces the linear array storage with oidtree for O(1) lookups instead of O(n)
- Enables lexicographic iteration and unique prefix computation
- Introduces a new `inmemory_object` struct to hold type/size/buf data
- Maintains the same external interface while changing the storage backend
- Adds proper cleanup of the oidtree in the free function
- Keeps the special handling for empty tree objects

The change builds on Git's existing oidtree infrastructure (also used by the loose object backend) to provide better performance characteristics while maintaining the same functionality. The patch includes thorough memory management for both the oidtree nodes and the stored object data.

This is a well-contained refactoring that demonstrates careful attention to memory management and maintains all existing behavior while improving the underlying implementation. As part of the larger ODB abstraction series that has already undergone extensive review, this patch appears technically sound and ready for integration.
