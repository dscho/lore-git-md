This is a feature patch in the final version (v7) of Adrian Ratiu's parallel hook execution series, which has maintainer approval. The patch adds support for `hook.jobs=-1` to automatically use all available CPU cores, matching the convention used elsewhere in Git (like `fetch.parallel`).

The change allows `-1` to be specified in three places: the global `hook.jobs` config, per-event `hook.<event>.jobs` config, and the `-j/--jobs` CLI option. Negative values other than `-1` are rejected with warnings (for config) or fatal errors (for CLI). The implementation resolves `-1` to `online_cpus()` at parse time so the rest of the code always works with positive counts.

The patch includes documentation updates and new tests verifying the behavior, including trace2 event logging to confirm the core count is properly detected. This completes the parallelization configuration system by adding the standard "use all cores" option alongside the existing explicit job count controls.

As part of the already-approved series, this is a straightforward addition that follows established Git conventions. The implementation is clean integration with the existing parallel hooks infrastructure and maintains all the safety mechanisms from earlier patches.
