This is a follow-up in the ongoing discussion about enabling Rust support by default in Git builds, specifically addressing version numbering expectations for Git 3.0. The email comes from brian m. carlson in response to Junio C Hamano's surprise at the compressed timeline for Git 3.0.

brian m. carlson acknowledges that while they had been operating under the assumption that one of the 2.5x releases would be the last before 3.0 (based on discussions at the 2024 Berlin Contributor Summit), they recognize Junio's more gradual approach of reaching 2.95 first makes more sense. They note this would be clearer for downstream users, as 2.95 more obviously signals an impending major version change than 2.55 would.

The email suggests spinning off the version numbering discussion into a separate thread for better visibility, rather than continuing it buried in the Rust build changes thread. This shows the author recognizing the importance of community consensus on release planning, separate from the technical merits of the Rust changes themselves.

The exchange reveals an important disconnect in expectations - while brian m. carlson had been preparing for a potentially imminent 3.0 release (as soon as September 2026), the maintainer clearly expects a more gradual path with several more 2.x releases first. This clarification from the maintainer effectively removes one of the urgency arguments for including the Rust build changes in the upcoming 2.54 release.
