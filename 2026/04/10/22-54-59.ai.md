Performance patch (part of a series) adding documentation about promisor packfile debugging information.

This is the first patch in Lorenzo Pegorari's v5 series addressing promisor file handling during repacks. It adds a comment to `pack-write.c` explaining the purpose of storing ref names and hashes in `.promisor` files - they exist solely for debugging partial clone issues, allowing comparison between what was fetched originally versus current remote state. The explanation matches the rationale from commit 5374a290 which introduced this behavior.

The patch is straightforward and uncontroversial, simply documenting existing behavior that was previously implicit. The comment is clear and matches the technical details from the commit message it references. As part of a larger series that has already addressed all technical feedback in previous iterations, this patch serves as useful context for the subsequent changes that will modify how these debugging entries are handled during repacks.

For future reference, this patch touches `pack-write.c` and documents the debugging use case for the ref/hash pairs stored in `.promisor` files. The information is written by `write_promisor_file()` and used to help diagnose partial clone issues by comparing historical fetch states with current remote states. The series as a whole builds on Taylor Blau's geometric repacking work while addressing a `NEEDSWORK` from 5374a290.
