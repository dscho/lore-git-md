This is part of the parallel hook execution feature series (7/13), adding a CLI `-j/--jobs` option to override the parallelization configuration. The patch enables direct control over hook concurrency from the command line while maintaining all existing safety mechanisms.

The change introduces a new `--jobs` flag to `git hook run` that takes precedence over all other parallelization settings (config files, per-hook flags). When specified, it forces parallel execution even for hooks not marked as parallel-safe, though with appropriate warnings. The implementation includes comprehensive tests verifying serial vs parallel behavior, TTY handling differences between `-j1` and `-jN`, and output grouping guarantees.

Key technical details include the new `warn_non_parallel_hooks_override()` function that emits warnings when forcing parallel execution of non-parallel hooks, and updates to the TTY handling logic to ensure proper behavior in both serial and parallel modes. The tests demonstrate that parallel execution preserves output grouping (no interleaving) and properly handles the CLI override case.

This patch builds on the series' existing parallel execution infrastructure while providing users more direct control. The warning system helps surface potential safety issues when overriding the per-hook parallel flags, maintaining the careful balance between performance and safety that characterizes the overall feature.
