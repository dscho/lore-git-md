This is a feature patch implementing the streaming read interface for Patrick Steinhardt's in-memory object database backend, part of the ongoing ODB abstraction effort (patch 5/17 in v3 of the series). The patch adds support for streaming reads from the in-memory storage, complementing the direct read functionality already implemented.

The implementation introduces a new `odb_read_stream_inmemory` struct that tracks the current read position and provides callbacks for reading chunks of data (`odb_read_stream_inmemory_read`) and closing the stream (`odb_read_stream_inmemory_close`). The main entry point `odb_source_inmemory_read_object_stream` locates the requested object in the oidtree and initializes a stream structure pointing to its in-memory buffer.

Key technical details:
- Uses the same underlying oidtree storage as direct reads
- Implements proper bounds checking during reads
- Maintains position state between read operations
- Follows the established streaming interface pattern
- Will be used by callers that prefer streaming access over full-object reads

This patch completes another piece of the in-memory ODB backend's functionality, bringing it closer to feature parity with persistent backends. The implementation appears straightforward and well-contained, with no obvious technical concerns. As with the rest of the series, this has been thoroughly reviewed and is ready for integration pending the final terminology alignment discussed in the thread.
