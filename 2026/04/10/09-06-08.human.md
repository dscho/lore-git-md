This is the final test case for the parallel hook execution feature, addressing SIGPIPE handling. The patch adds a test scenario where one hook exits quickly (potentially causing SIGPIPE) while another runs slowly, verifying that the parallel execution system correctly handles this case without prematurely terminating the slow hook.

The test creates two hooks - one that exits immediately and another that sleeps for 1 second - and configures them to run in parallel during a push operation. This validates that the SIGPIPE fix from commit 2226ffaacd works correctly in the parallel case, where one hook's early exit shouldn't affect other concurrently running hooks.

This patch comes from Jeff King (with Adrian Ratiu's sign-off) and represents the last piece of the parallel hooks series, which has already received maintainer approval from both Junio Hamano and Patrick Steinhardt. The test provides important validation of the system's robustness, particularly for the pre-receive hook case where multiple hooks may run simultaneously. With this addition, the series appears complete and well-tested, ready for merging into the main branch.
