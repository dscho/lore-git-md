This is the first patch in Patrick Steinhardt's 17-part series introducing an in-memory object database source as part of the ongoing ODB (object database) abstraction effort. The patch lays the groundwork by:

1. Introducing new `odb/source-inmemory.[ch]` files that define the basic structure for the in-memory backend
2. Moving the existing cached objects functionality into this new framework
3. Maintaining all current behavior while preparing for future extensions

The implementation replaces the direct `cached_objects` array in `struct object_database` with a proper `struct odb_source_inmemory` that will eventually implement the full ODB source interface. Key technical aspects include:

- New `ODB_SOURCE_INMEMORY` type added to the source enumeration
- Basic initialization via `odb_source_inmemory_new()`
- Type-safe downcasting with `odb_source_inmemory_downcast()`
- Maintains existing cached object storage using the same allocation patterns

The patch is primarily structural - it doesn't yet implement the full source interface (that comes in later patches), but establishes the foundation while preserving all current functionality. The careful separation of concerns and type safety mechanisms suggest this is a well-considered start to the series.

As part of a mature patchset that has already undergone extensive review, this initial patch appears solid and uncontroversial, focused purely on the mechanical work of establishing the new infrastructure without yet changing behavior.
