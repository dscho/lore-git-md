This is the final naming discussion in Patrick Steinhardt's feature patchset introducing an in-memory object database source as part of the ODB abstraction effort. The technical implementation has been reviewed and approved, with all feedback addressed in v2 of the series. The remaining question is whether to use "in-memory" or "in-core" terminology for the new backend.

Patrick makes the case for "in-memory" as the more user-friendly and technically accurate term, noting that "in-core" is mostly an internal Git concept while "in-memory" better describes the transient nature of these objects. He also observes that existing user-facing documentation rarely uses "in-core", and that the concepts differ slightly - "in-core" refers to parsed objects while "in-memory" objects may never be parsed.

The discussion represents the final step before this significant ODB abstraction milestone can be integrated. The series is otherwise complete, having implemented all necessary callbacks and infrastructure for a non-persistent object storage backend that will enable features like git-blame worktree commits. The naming choice here may set a precedent for future storage backends.
