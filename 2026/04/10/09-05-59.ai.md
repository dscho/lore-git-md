This is part 4/13 of the parallel hook execution feature series, introducing the core parallel execution capability. The patch removes the hardcoded serial execution of hooks, allowing them to run in parallel when explicitly configured.

The implementation adds a new `hook.<name>.parallel` config option that must be set to `true` for each hook that can safely run concurrently. A global `hook.jobs` setting controls the default parallelism level, defaulting to 1 (serial) when unset. The patch includes logic to determine effective job counts, respecting both config settings and runtime overrides.

Key technical aspects:
- New `parallel` field in `struct hook` tracks per-hook parallel capability
- `get_hook_jobs()` function implements the job count resolution logic
- Special handling maintains serial execution for hooks requiring separate output streams
- Comprehensive test coverage verifies serial/parallel behavior under various config combinations

The patch builds on Adrian Ratiu's earlier configurable hooks work and has received maintainer approval from both Junio Hamano and Patrick Steinhardt. It represents a significant performance optimization for hook-heavy workflows while maintaining safety through explicit opt-in requirements.
