This thread reports a concerning bug in Git for Windows where `git fsck` runs indefinitely on a large repository, checking far more objects than actually exist (190% of expected objects). The issue occurs in a 70GB repository dating back to 2012, primarily containing media files, running on Windows 11 with Git for Windows 2.53.0. 

The problem persists even after aggressive garbage collection, ruling out simple unreachable object scenarios. The core symptom is a progress counter that continues incrementing well beyond the repository's actual object count (54,090 objects checked vs 28,351 expected), suggesting either a counting error in the Windows port's fsck implementation or a deeper object traversal issue specific to Windows environments. The reporter has provided detailed system specs including OpenSSL 3.5.5 and SHA-1 as the hash algorithm, giving maintainers a clear reproduction case to investigate.
