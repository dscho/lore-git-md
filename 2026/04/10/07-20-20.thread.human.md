This thread reports a concerning issue where `git fsck` on Windows appears to check nearly twice as many objects as exist in a large repository (70GB with media files), showing 54,090 objects checked when only 28,351 are expected. The original reporter provided detailed system information using Git for Windows 2.53.0.

Patrick Steinhardt has now responded, suggesting this might relate to a recently fixed bug in pack verification (commit 13eb65d366) that will be included in Git 2.54. The fixed issue involved incorrect verification counts with large objects, which could explain the behavior seen here. While the problem manifested on Windows, Patrick's response implies it may actually be a cross-platform issue in how Git handles large binary objects during verification, potentially just more visible in Windows environments. He's asked the reporter to test whether the upcoming 2.54 release resolves their problem.

The thread remains open pending verification of whether the fix addresses this specific case. If it doesn't, further investigation will be needed to determine if this is a distinct Windows-specific filesystem handling issue or another variant of the pack verification problem. Johannes Schindelin (Git for Windows maintainer) may need to weigh in if the issue persists after 2.54.
