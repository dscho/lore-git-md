This is a feature patch in the parallel hook execution series, adding a command-line `-j/--jobs` option to `git hook run`. The patch introduces the ability to override all other parallelization settings (including per-hook and per-event configurations) via a direct jobs count specification.

The implementation includes comprehensive test coverage of the new CLI option's behavior:
- Verifies TTY handling differs between serial (-j1) and parallel (-jN) execution
- Confirms parallel execution preserves output grouping (no interleaving)
- Demonstrates the CLI option overrides config settings (with warnings for non-parallel hooks)
- Tests both serial and parallel execution paths

The patch builds on the series' existing parallel execution infrastructure while maintaining safety for hooks that must run serially (like commit-related hooks). Emily Shaffer is listed as the primary author, with contributions from Ævar Arnfjörð Bjarmason and Adrian Ratiu.

This represents a key user-facing component of the parallel hooks feature, giving users direct control over parallelization when running hooks manually via `git hook run`.
