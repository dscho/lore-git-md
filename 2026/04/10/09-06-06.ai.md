Feature patch adding a master switch for hook events, part of Adrian Ratiu's parallel hook execution series. This introduces `hook.<event>.enabled` configuration to disable all hooks for a given event, complementing the per-hook `hook.<friendly-name>.enabled` setting.

The patch establishes clear precedence rules - when an event is disabled, it overrides any per-hook settings. Disabled hooks appear in `git hook list` with an "event-disabled" prefix, while per-hook disabled status only shows when the event is enabled. The implementation includes safeguards against naming collisions between event names and friendly names, with fatal errors for known conflicts and warnings for potential ones.

Key technical changes include adding a `disabled_events` string list to `struct repository`, updating the hook config parsing to distinguish between event-level and per-hook disables, and modifying the hook selection logic to respect both disable levels. The patch includes extensive test coverage verifying the precedence rules, display behavior, and naming conflict detection.

This builds on the series' existing parallel execution infrastructure while maintaining backward compatibility. The change is well-integrated with the parallel hooks work, as evidenced by its handling of the new `event_disabled` flag in the hook struct and updates to the config cache system. The implementation carefully considers edge cases like repository initialization and cleanup paths.
