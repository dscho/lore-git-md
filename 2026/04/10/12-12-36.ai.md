This is patch 6/17 in Patrick Steinhardt's feature series implementing an in-memory object database (ODB) backend, part of the ongoing ODB abstraction effort. The patch implements the `write_object()` callback for the in-memory source, completing the core write functionality.

The implementation moves the existing `odb_pretend_object()` logic into the new callback structure while maintaining identical behavior. Key changes:
- The old implementation in `odb.c` is reduced to a thin wrapper that delegates to the new callback
- The new `odb_source_inmemory_write_object()` function handles:
  - Object hashing (using the repository's hash algorithm)
  - Memory allocation and growth of the object storage array
  - Copying the object data into the in-memory store
  - Storing the object's metadata (size, type, OID)

The patch demonstrates good separation of concerns by keeping the in-memory storage details encapsulated within the backend implementation while providing a clean interface through the ODB abstraction layer. The change is mechanical but important for completing the backend's functionality.

This continues the series' pattern of thorough implementation with clear commit messages and careful attention to maintaining existing behavior while fitting into the new abstraction. With this patch, the in-memory backend now has complete write support to complement the previously implemented read operations.
