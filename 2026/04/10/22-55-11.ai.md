This is patch 2/6 in Lorenzo Pegorari's v5 series on promisor file handling during repacks, part of his GSoC work mentored by Eric Sunshine. The patch introduces a helper function `copy_promisor_content()` that preserves debugging information in `.promisor` files when repacking promisor packfiles.

The function handles several key scenarios:
- Copies content from existing `.promisor` files to new ones after repacking
- Maintains ref-to-packfile mapping information in the format "<oid> <ref>"
- Adds timestamps (using `PRItime` and `timestamp_t`) for never-repacked files
- Skips files listed in `not_repacked_basenames` ignore list
- Only includes objects present in the new packfile index

The implementation shows careful attention to platform compatibility (using `st_mtime` for timestamp handling) and follows Git's coding conventions. The function integrates with geometric repacking via the `not_repacked_basenames` parameter and includes comprehensive error handling.

This patch builds on the previous v4 iteration with improved timestamp formatting and header inclusion compliance. The helper function's behavior is well-documented in both the commit message and in-code comments, explaining the debugging rationale for preserving this information (originally introduced in commit 5374a290).
