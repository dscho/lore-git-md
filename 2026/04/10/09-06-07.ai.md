This is a feature patch in the parallel hook execution series, adding support for `-1` as a special value to automatically use all available CPU cores. The change affects three configuration points: `hook.jobs`, `hook.<event>.jobs`, and the `-j/--jobs` CLI flag.

The patch follows Git's established convention where `-1` means "use all cores" (as seen in `fetch.parallel` and other subsystems). When `-1` is specified, the value is resolved to `online_cpus()` at parse time, ensuring the rest of the code always works with positive counts. Invalid values (0, -2, etc.) are rejected with warnings for config settings or fatal errors for CLI usage.

Implementation-wise, the change replaces `git_parse_uint()` with `git_parse_int()` in config parsing to handle negative values, adds a `resolve_hook_config_jobs()` helper to centralize the `-1` handling logic, and updates the CLI option in `builtin/hook.c` to use `OPT_INTEGER` instead of `OPT_UNSIGNED`. The patch includes comprehensive tests verifying the behavior for all three configuration points, including validation of the core count resolution via `test-tool online-cpus` and rejection of invalid values.

This is a well-contained addition to the parallel hooks feature that maintains consistency with Git's existing conventions while providing a convenient way to maximize parallelization without hardcoding core counts.
