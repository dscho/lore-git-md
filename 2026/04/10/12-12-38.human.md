This is a refactoring patch in Patrick Steinhardt's ongoing ODB (object database) abstraction series. The patch modifies the cbtree data structure to allow embedding nodes in wrapper structures, which is needed for the in-memory ODB backend implementation.

The cbtree subsystem currently has limitations when trying to store arbitrary data with tree nodes due to alignment and memory management issues. This patch removes the flex array in `struct cb_node` and replaces it with an explicit key offset` parameter, letting callers specify where the key is located in their wrapper structure. While this adds some padding (growing the structure from 60 to 64 bytes), it eliminates memory copies needed for alignment and enables proper leak checking.

The changes affect three files:
- `cbtree.c`/`cb_node_key()` helper and updates to use the offset
- `cbtree.h` adds the`key_offset` field and removes`FLEX_ARRAY`
- `oidtree.c` adapts to use a new`oidtree_node` wrapper struct

This appears to be a well-considered change that improves flexibility while maintaining performance. The patch is in its third iteration and has been reviewed by Karthik Nayak and Justin Tobler, suggesting it's technically sound. As part of a larger series that's nearly ready for integration, this refactoring enables cleaner implementation of the in-memory ODB backend while preserving the cbtree's existing functionality.
