This is part 3/13 in the v7 series introducing parallel hook execution, now with maintainer approval. The patch adds the foundational `hook.jobs` configuration option that will control global parallelization of hooks across all hook events.

The change introduces a new `hook.jobs` config key that specifies how many hooks can run simultaneously, defaulting to 1 (serial execution) when unset. The value is parsed during config loading and stored in the repository's `hook_jobs` field. The implementation includes validation to ensure the value is a positive integer, with warnings for invalid inputs.

This is plumbing work that sets up the configuration infrastructure - the actual parallel execution logic comes in later patches. The documentation is updated to describe the new config option, though it notes that finer-grained per-hook and per-event controls will be added in subsequent commits.

The patch follows the series' established pattern of careful validation and clear documentation, maintaining backward compatibility by defaulting to serial execution. It's a straightforward addition that provides the base configuration layer for the parallelization system.
