Performance bugfix addressing memory leaks in promisor file handling during repacks, part of Lorenzo Pegorari's completed v5 GSoC series. This email from Junio C Hamano reports CI failures in the linux-leaks and linux-reftable-leaks jobs when testing the v4 patches, specifically in tests t0410, t5616, and t5710.

The issue manifests as a 285-byte memory leak in `copy_promisor_content()` when parsing pack indexes during promisor file content copying. Junio has reproduced the failure locally and provides the exact leak trace showing the allocation path: `xmalloc` -> `alloc_packed_git` -> `parse_pack_index` within the promisor file handling code. The leak occurs when the test script `t5710` runs with leak checking enabled.

This represents the final technical issue to be resolved in the series before merging. The problem appears isolated to the pack index parsing logic in the promisor file preservation code, which was introduced to maintain debugging information during repacks (addressing the `NEEDSWORK` from commit 5374a290). Junio's message indicates he has already identified a platform-specific consideration regarding timestamp precision (using `st_mtime` instead of `st_mtim`) that will need to be incorporated into the fix.

For future reference, key technical details include:
- Leak occurs in `repack-promisor.c` during pack index parsing
- Affected tests: t0410, t5616, t5710
- Allocation path: `xmalloc` -> `alloc_packed_git` -> `parse_pack_index`
- Platform consideration around timestamp precision (`st_mtime` vs `st_mtim`)

The series is otherwise complete with all prior feedback addressed, making this memory leak the last remaining issue before the promisor file preservation functionality can be merged. The responsiveness to Junio's feedback throughout the series suggests this will likely be resolved promptly.
