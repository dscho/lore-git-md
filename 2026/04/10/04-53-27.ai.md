This is the final naming discussion in Patrick Steinhardt's feature patch series introducing an in-memory object database source as part of the ODB abstraction effort. The technical implementation has already been reviewed and approved, with the thread now focused on terminology consistency between "in-memory" (used in the new backend) and Git's existing "in-core" terminology.

Patrick responds to Junio C Hamano's concern about potential inconsistency by analyzing the existing uses of "in-core" in the codebase. He notes that most occurrences are internal, with only a few documentation references that end users might see. He also identifies a subtle technical distinction: "in-core" refers to objects that have been parsed into memory (regardless of their storage backend), while "in-memory" describes objects that exist solely in memory without disk backing.

The discussion highlights Git's attention to precise naming, especially for concepts that may become user-facing. Patrick makes the case that "in-memory" is more intuitive for end users and better captures the technical reality of this backend, while acknowledging the maintainer's concern about consistency with existing terminology.
