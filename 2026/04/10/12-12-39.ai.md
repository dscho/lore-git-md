This is a refactoring patch in Patrick Steinhardt's ongoing ODB (object database) abstraction series, specifically modifying the oidtree data structure to support storing arbitrary data alongside object IDs. The change enables more flexible use of oidtree in the in-memory ODB backend being introduced in this series.

The patch extends oidtree's functionality beyond just tracking object IDs by:
- Adding a `data` field to `struct oidtree_node` to store arbitrary payloads
- Introducing new `oidtree_get()` function to retrieve stored data
- Modifying the iteration callback signature to include the node data
- Updating all existing callers to pass NULL for the data parameter
- Adding a unit test verifying data storage behavior

The changes are mechanical but important infrastructure for the in-memory ODB backend which will use this to associate metadata with stored objects. The implementation maintains all existing behavior while adding the new capability, with thorough test coverage including a new test case for the data storage functionality.

This is part of the larger ODB abstraction effort that aims to make Git's object storage backend pluggable. The patch has been reviewed by Karthik Nayak and Justin Tobler, and Junio Hamano has indicated the technical implementation is sound. It represents a building block for the in-memory ODB source that will follow in subsequent patches.
