This is a feature patchset introducing an in-memory object database source as part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort. The series is now in its third iteration and appears ready for integration pending final terminology alignment in error messages.

The patchset adds a new backend that stores objects purely in memory without persistence, serving as a building block for features like git-blame's temporary worktree commits and potential future re-merge operations. The implementation provides all required ODB source callbacks (read/write operations, iteration, etc.) and uses oidtree for O(1) lookups with sorted iteration.

Key technical changes in v3 include fixes to the streaming read interface, additional unit tests to verify functionality not yet exercised in production code, and consistency updates to use "in-memory" terminology throughout. The series builds on Justin Tobler's ODB write stream refactorings and represents a significant milestone in the ODB abstraction roadmap.

Reviewers Karthik Nayak and Justin Tobler have provided positive feedback, and maintainer Junio Hamano has confirmed the technical implementation is sound. The only remaining discussion point is ensuring consistent terminology in error messages before integration. Given Patrick's track record with architectural changes and the thorough review process, this appears to be a well-vetted addition to Git's object storage capabilities.
