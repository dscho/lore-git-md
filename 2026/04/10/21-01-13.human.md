This is the final patch in a feature series that enhances `git checkout -m` to use autostash behavior when switching branches with conflicts. The series has been through nine iterations of review and is now fully polished.

The patch implements the core functionality where `checkout -m` will now automatically stash local changes before attempting a branch switch, then reapply them afterward. If the changes don't conflict with the branch switch, they're cleanly applied with just an "Applied autostash" message. If conflicts occur, the stash is preserved and the user gets clear instructions on how to either resolve the conflicts or recover their changes.

Key technical changes include:
- New silent`create_autostash_ref_silent()` API for stash creation without output
- Modified conflict resolution flow in `merge_working_tree()`
- Updated documentation for both `git-checkout` and `git-switch` man pages
- Comprehensive test coverage in t7201-co.sh (19 new test cases) verifying:
  - Different conflict styles (diff3, zdiff3)
  - Config-driven conflict style
  - Various change scenarios (staged, unstaged, mixed)
  - Non-overlapping changes
  - New branch creation

The implementation builds on existing autostash infrastructure used by `git rebase` and `git merge`, providing consistent user experience across commands. The patch has received thorough review from Phillip Wood and maintainer approval from Junio Hamano, with all feedback addressed across the nine iterations. This represents a significant quality-of-life improvement for branch switching workflows when working with uncommitted changes.
