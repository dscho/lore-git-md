This is part of the parallel hook execution feature series (v7 9/13), adding a warning system to prevent configuration confusion between hook event names and friendly names. The patch addresses a potential user error where someone might mistakenly set `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs`.

The change introduces an `is_friendly_name()` helper that detects when a configured name appears to be a hook's friendly name (by checking for associated `.command`, `.event`, or `.parallel` settings) rather than an event name. When such a misconfiguration is found, Git now emits a warning explaining the correct format (`hook.<event>.jobs`). The implementation includes four new test cases verifying the warning appears in the expected cases and doesn't trigger for proper event name configurations.

This is a refinement to the parallel hooks configuration system, ensuring users don't accidentally set parallelization limits that will be silently ignored. The warning helps guide users toward the correct configuration syntax while maintaining backward compatibility. The patch builds on Junio Hamano's suggestion and fits into the larger series' careful approach to configuration hierarchy and user experience.
