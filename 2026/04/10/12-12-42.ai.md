This is a feature patch implementing the `find_abbrev_len()` callback for the in-memory ODB backend, part of Patrick Steinhardt's ongoing ODB abstraction effort (patch 12/17 in v3 of the series). The patch completes another piece of the in-memory object storage implementation by adding support for finding the minimal unique abbreviation length for object IDs.

The implementation follows the established pattern of the series, using a callback adapter structure (`find_abbrev_len_data`) to collect results during iteration. It leverages the existing `for_each_object()` infrastructure with prefix filtering to efficiently scan for objects that share the given prefix. The actual length calculation uses `oid_common_prefix_hexlen()` to determine how many hex digits are needed to uniquely identify the object.

Key technical details:
- New `find_abbrev_len_cb()` callback that compares each object's OID against the target
- Wrapper function `odb_source_inmemory_find_abbrev_len()` that sets up the iteration
- Integration into the source vtable alongside other callbacks
- Follows the same pattern as other callbacks in the series
- Builds on the oidtree-based storage from earlier patches
