This is part of the parallel hook execution feature series (patch 6/13), which has already received maintainer approval. The patch marks several Git hooks as non-parallelizable by forcing them to run serially regardless of configuration settings.

The patch identifies seven hooks that must always run sequentially because they operate on shared state: `applypatch-msg`, `pre-commit`, `prepare-commit-msg`, `commit-msg`, `post-commit`, `post-checkout`, and `push-to-checkout`. These hooks either modify commit messages in-place or interact with the working tree/repository state in ways that aren't thread-safe.

The changes update hook calls throughout the codebase to use `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` for these specific hooks, overriding any parallel execution settings. The documentation is also updated to clearly list these exceptions and explain why they can't be parallelized.

A new test case verifies that `hook.jobs=2` is properly ignored for force-serial hooks like `pre-commit`, ensuring they don't run concurrently even when configured to do so. The patch maintains backward compatibility while enforcing safety constraints for these special cases.

This is a well-contained part of the larger parallel hooks effort, with clear technical justification for the serial-only requirement. The changes are straightforward mechanical updates to hook calls, with good test coverage added.
