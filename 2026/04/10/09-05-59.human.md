Feature patch enabling parallel hook execution, part of Adrian Ratiu's configurable hooks series that has already received maintainer approval. This is patch 4/13 in the v7 series, introducing the core parallel execution capability while maintaining safety through opt-in configuration.

The patch removes Git's hardcoded serial execution of hooks, allowing users to run hooks concurrently when explicitly configured. It introduces a `hook.<name>.parallel` config option that must be set to `true` for each hook that can safely run in parallel (defaulting to false for safety). The number of parallel processes is controlled by `hook.jobs`, with careful handling of output streams to prevent interleaving.

The implementation includes extensive test coverage verifying serial vs parallel behavior under different configurations. Notably, any single non-parallel hook forces the entire event to run serially, providing a safety mechanism. The patch builds on previous work to make hooks configurable and represents a significant performance improvement for hook-heavy workflows while maintaining backward compatibility.

This is a well-tested, carefully designed change that has gone through multiple iterations and review cycles. The core functionality is already approved by both Junio and Patrick Steinhardt, with this version adding Jeff King's SIGPIPE test to complete the safety validation. The series is now ready for merging.
