This is part of the parallel hook execution feature series (v7 5/13), focusing specifically on enabling parallel execution for pre-push hooks. The patch addresses a key compatibility challenge - pre-push hooks traditionally keep stdout and stderr separate (important for tools like git-lfs), which conflicts with parallel execution's need to merge streams for output handling.

The solution maintains backward compatibility by default (jobs=1 keeps separate streams) while allowing merged output when users explicitly opt into parallelism via hook.jobs > 1, hook.<event>.jobs > 1, or -jN. The implementation automatically sets stdout_to_stderr=1 when parallel execution is requested, documented clearly in both code and config documentation.

The patch includes comprehensive tests verifying both the parallel execution capability and the stream merging behavior for pre-push hooks. This represents a careful balance between performance optimization and backward compatibility, completing an important piece of the parallel hooks puzzle. With maintainer approval already secured for the overall series, this refinement demonstrates thoughtful handling of a tricky edge case in the hook system.
