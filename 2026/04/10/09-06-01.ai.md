This is part of the parallel hook execution feature series (v7 6/13), marking certain hooks as non-parallelizable for safety. The patch identifies seven hooks that must always run sequentially due to their access to shared state: applypatch-msg, pre-commit, prepare-commit-msg, commit-msg, post-commit, post-checkout, and push-to-checkout. These hooks either modify commit messages in-place or interact with the working tree/index in ways that can't safely parallelize.

The changes update each hook's call site to use RUN_HOOKS_OPT_INIT_FORCE_SERIAL, which overrides any parallelization settings. Documentation is added explaining why these hooks require serial execution. A new test verifies that hook.jobs=2 is properly ignored for force-serial hooks like pre-commit, ensuring the safety mechanism works as intended.

The implementation touches multiple builtin commands (am, checkout, clone, receive-pack, worktree) and the core commit.c logic, with corresponding test coverage in t1800-hook.sh. This patch represents a key safety component of the larger parallel hooks feature, ensuring critical operations remain atomic while allowing parallel execution where safe.
