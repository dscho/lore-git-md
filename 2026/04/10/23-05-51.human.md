This is a bugfix patch addressing memory leaks in the promisor file repack handling series. Junio C Hamano reports that the v4 patches introduced memory leaks that cause test failures in the CI's leak-checking jobs (specifically t0410, t5616, and t5710). The leaks occur when parsing pack indexes during the `copy_promisor_content()` operation, where allocated memory is not being freed.

The issue was discovered when the series was merged into the 'seen' branch and showed up in GitHub Actions CI runs. Junio was able to reproduce the failure locally, confirming it's a genuine leak rather than a CI-specific issue. The stack trace points to `alloc_packed_git()` allocations in `parse_pack_index()` that aren't being cleaned up during the promisor file copying process.

This appears to be the final technical hurdle for the series, which has otherwise addressed all prior feedback about timestamp formatting, test improvements, and geometric repack integration. The patch author (Lorenzo Pegorari) will need to add proper cleanup of these pack index allocations to resolve the leaks before the series can proceed. Given the thoroughness of the prior iterations, this final fix should be straightforward to implement.
