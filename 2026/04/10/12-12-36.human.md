This is part 6 of Patrick Steinhardt's 17-part series implementing an in-memory object database backend, a key piece of the ongoing ODB abstraction effort. The series is now in its third iteration and has received thorough technical review.

This particular patch implements the `write_object()` callback for the in-memory backend, moving the object writing logic from `odb.c` into the new backend implementation. The change is straightforward - it takes the existing object writing code from `odb_pretend_object()` and moves it into a proper callback function in `source-inmemory.c`, while maintaining the same behavior. The patch also cleans up the now-redundant code in `odb.c`.

The implementation handles all the expected cases for writing objects to memory storage: allocating space, copying the object data, and tracking the object metadata. This is one of the final core operations needed for a complete ODB backend implementation.

With this patch, the in-memory backend now has both read and write capabilities, bringing it closer to being a fully functional alternative ODB source. The series as a whole appears well-vetted and ready for integration after some final terminology tweaks in error messages.
