This is the final patch in a feature series (v9) that implements autostash behavior for `git checkout -m` when switching branches with conflicts. The patch has been through extensive review and is now fully polished, addressing all technical feedback from previous iterations.

The key changes in this patch include:
1. Modifying `git checkout -m` to automatically stash local changes when switching branches would cause conflicts, then reapply them after the switch
2. Adding comprehensive test coverage in t7201-co.sh (19 new test cases) for various scenarios including:
   - Non-conflicting changes that don't need stashing
   - Truly conflicting changes that require stash preservation
   - Mixed staged/unstaged changes
   - Different conflict styles (diff3, zdiff3)
3. Updating documentation in git-checkout.adoc and git-switch.adoc to explain the new behavior
4. Implementing proper error handling and user messaging when conflicts occur during stash application

The implementation builds on existing autostash infrastructure from rebase/merge, adding new functions like `create_autostash_ref_silent()` and modifying the sequencer to support silent stash operations. When conflicts occur, users are given clear instructions on how to resolve them or recover their changes later.

This represents a significant quality-of-life improvement for branch switching workflows, particularly when working with uncommitted changes. The series has received maintainer approval through multiple iterations and addresses all feedback, making it production-ready with comprehensive documentation.
