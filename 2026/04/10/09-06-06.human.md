This is a feature patch in the parallel hook execution series, adding a new `hook.<event>.enabled` configuration switch to disable all hooks for a given event. The patch builds on Adrian Ratiu's configurable hooks work and has already received maintainer approval from both Junio C Hamano and Patrick Steinhardt.

The patch introduces a high-level event disable switch that takes precedence over individual hook settings. When an event is disabled via `hook.<event>.enabled=false`, all hooks for that event are skipped regardless of their per-hook enabled status. The `git hook list` command now shows event-disabled hooks with an "event-disabled" prefix, prioritizing this status over per-hook disabled states in the display.

The implementation includes safeguards against naming collisions between event names and friendly names, with fatal errors for known event names used as friendly names and warnings for potential unknown collisions. The change touches multiple subsystems including the hook configuration cache, repository state tracking, and the hook listing display logic.

Test coverage is comprehensive, verifying the new configuration hierarchy (event-level disable overrides per-hook settings), proper display in `git hook list`, and the naming collision protections. The patch maintains backward compatibility while adding this new control mechanism as part of the larger parallel hooks feature set.

This represents a well-integrated addition to the parallel hooks system, providing users with both fine-grained per-hook control and broad event-level management capabilities. The careful handling of naming conflicts and clear precedence rules demonstrate the series' attention to configuration safety and user experience.
