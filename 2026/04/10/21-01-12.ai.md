This is the third patch in a four-part feature series that enhances Git's autostash functionality with customizable conflict marker labels. The series is now in its ninth iteration and has been thoroughly reviewed, with all technical concerns addressed.

The patch extends the sequencer's autostash machinery to support optional conflict marker labels when applying stashes. It introduces a new `apply_autostash_ref_with_labels()` function that allows callers to specify custom labels for the "ours", "theirs", and "base" sides of conflicts. The implementation builds on the existing autostash infrastructure while maintaining backward compatibility - when no labels are provided, the behavior remains unchanged.

Key technical changes include:
- New parameters added to internal functions to propagate label specifications
- A new public API function `apply_autostash_ref_with_labels()` exposed in sequencer.h
- Modified calls to `git stash apply` that now pass through any provided labels
- Preservation of existing behavior when labels are NULL

The patch follows the series' established pattern of cleanly separating concerns while maintaining the existing autostash workflow. It represents the core plumbing needed to support the user-facing label customization features introduced in the other patches of the series. With all review feedback addressed across nine iterations, this implementation is now production-ready and maintains Git's high standards for backward compatibility and clean API design.
