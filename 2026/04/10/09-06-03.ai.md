This is part of the parallel hook execution feature series (v7 08/13), adding per-event job count configuration. The patch introduces `hook.<event>.jobs` settings that override the global `hook.jobs` value for specific hook events, allowing finer-grained control over parallelism.

The implementation adds a new `event_jobs` strmap to `struct repository` to cache per-event job counts, with corresponding updates to the config parsing and cleanup logic. The key technical challenge is integrating this with the existing parallelization rules - per-event job counts still require individual hooks to be marked as parallel-safe via `hook.<name>.parallel=true`. The patch includes comprehensive tests verifying that per-event settings properly override global values while maintaining all safety checks.

Documentation explains the distinction between event names and hook friendly names, clarifying that `hook.my-hook.jobs` (using a hook name) won't work - the key must use the event name like `hook.post-receive.jobs`. The tests demonstrate three key scenarios: per-event override enabling parallel execution despite a global serial setting, per-event override forcing serial despite a parallel global setting, and the continued requirement for individual hooks to opt into parallel execution regardless of event-level settings.

This patch builds on the series' existing infrastructure while introducing another layer to the configuration hierarchy that now spans global, per-event, per-hook, and CLI settings. The implementation is cleanly integrated with the core parallel execution logic in `get_hook_jobs()`, maintaining the series' careful approach to backward compatibility and safety.
