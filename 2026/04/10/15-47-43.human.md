This is a clarification from Junio Hamano on header inclusion policy in Git's C code, part of the final review for Lorenzo Pegorari's promisor file handling patch series.

Junio confirms that the CodingGuidelines do indeed require direct inclusion of any header files declaring functions and types used in a C file, even if those headers might be indirectly included through other headers. He explains this is important for future-proofing - a header might stop including another header it doesn't strictly need, which would break code that relied on the indirect inclusion.

However, he notes that in practice some headers like `strbuf.h` are so widely used that they often get pulled in indirectly, making builds work even when not explicitly included. This is not something to rely on though. The guidance is clear: if your code uses something, include its header directly.

This response resolves the last open question in Lorenzo's series about whether headers like `strmap.h`, `strbuf.h` and others needed explicit inclusion. Junio's answer indicates they should be added where used, aligning with the project's coding standards.
