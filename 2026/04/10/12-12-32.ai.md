This is part 2 of Patrick Steinhardt's 17-patch series introducing an in-memory object database source, a feature that's part of the ongoing ODB abstraction effort. The series is now in its third iteration and has received thorough technical review.

This specific patch implements the `free()` callback for the in-memory ODB source, moving the cleanup logic from `odb.c` into the new `odb_source_inmemory_free()` function. The change:
- Defines `struct cached_object_entry` in the header file since it's now shared between multiple source files
- Properly frees all allocated memory when the in-memory source is destroyed
- Maintains the same behavior as before but within the new callback-based architecture

The implementation is straightforward and follows the pattern established in the ODB abstraction work. The patch appears to be a mechanical refactoring that's part of the larger series' goal to properly encapsulate the in-memory object storage functionality. Given the series' advanced state of review and the maintainer's indication that it's technically sound, this patch seems ready for integration along with the rest of the series.
