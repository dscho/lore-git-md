This is a documentation update from Junio Hamano clarifying platform compatibility guidelines for file timestamp handling in Git's codebase. The patch adds a new section to `Documentation/CodingGuidelines` noting that macOS lacks POSIX-compliant nanosecond-resolution timestamp fields (`st_mtim`), and recommends using the more portable `st_mtime` when second-level precision suffices.

The change directly addresses a real-world issue encountered in Lorenzo Pegorari's promisor file repacking series, where timestamp handling needed adjustment for macOS compatibility. The documentation now explicitly warns against unconditional use of st_mtim` and points developers to the existing `USE_ST_TIMESPEC` compile-time check for cases requiring higher precision.

This is a straightforward but important addition to the project's style guide, ensuring future contributors handle timestamps portably from the start. The patch follows Git's typical documentation style and will help prevent similar platform-specific issues in future code.
