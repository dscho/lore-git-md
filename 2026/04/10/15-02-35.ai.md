This is a documentation patch from Lorenzo Pegorari, part of his GSoC work under Eric Sunshine's mentorship. It's the first patch in a v4 series addressing promisor file handling during repacks.

The patch adds a clarifying comment to `pack-write.c` explaining the purpose of the ref names and hashes stored in `.promisor` files. These debugging aids were introduced in commit 5374a290 but lacked documentation about their non-production debugging purpose. The new comment makes it clear this information helps diagnose partial clone issues by preserving the refs and hashes fetched when the packfile was downloaded.

This is a straightforward documentation improvement that follows the project's coding style. The patch is well-contained and uncontroversial, addressing a clear gap in the codebase's documentation. It sets up the context for the subsequent patches in the series that will modify how this debugging information is preserved during repacks.

Key technical details for future reference:
- Adds comment in `pack-write.c` explaining `.promisor` file contents
- Documents debugging-only nature of stored ref names/hashes
- References original commit 5374a290
- Part of larger promisor file handling series (5 patches total)
