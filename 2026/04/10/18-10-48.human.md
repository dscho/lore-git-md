This is a documentation update from Junio Hamano clarifying platform compatibility guidelines for file timestamps in Git's codebase. The patch adds a note to `Documentation/CodingGuidelines` warning against unconditionally using POSIX's `st_mtim` (and related timestamp fields) since macOS doesn't support nanosecond-resolution timestamps. Instead, it recommends using `st_mtime` when whole-second resolution is sufficient.

The change formalizes a practice that was already being followed in the codebase (as seen in the recent promisor` file repacking work by Lorenzo Pegorari) and makes it explicit for future contributors. This is a small but important clarification that helps maintain cross-platform compatibility, particularly for macOS users.

The patch is straightforward and uncontroversial - it documents existing practice rather than introducing new requirements. As the maintainer's direct contribution, it carries implicit approval and will likely be merged without further discussion. This fits into Git's ongoing efforts to maintain clear coding standards while supporting diverse platforms.
