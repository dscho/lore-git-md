This is a bugfix patch that addresses a memory leak in `repo_init()`, part of the larger parallel hook execution series. The leak occurs when enabling a v1 extension in a v0 repository format - an edge case that wouldn't surface in normal usage but represents a real memory management issue.

The fix is straightforward: adding a call to `clear_repository_format()` in the error path before calling `repo_clear()`. This ensures proper cleanup when initialization fails. While the scenario is rare, the patch is a clean, focused fix that demonstrates good attention to resource management details.

As the first patch in a series that has already received maintainer approval, this serves as groundwork for the more substantial parallel hook execution changes that follow. The small size and clear explanation make it an easy inclusion, though it's worth noting the issue was pre-existing rather than introduced by the series itself.
