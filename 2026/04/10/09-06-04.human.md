This is part of the parallel hook execution feature series (v7 09/13), which has already received maintainer approval. The patch adds a warning when someone mistakenly sets `hook.<friendly-name>.jobs` instead of the intended `hook.<event>.jobs` configuration.

The change introduces a new `is_friendly_name()` helper that detects when a name is being used as a hook friendly-name (by checking for associated `.command`, `.event`, or `.parallel` configurations) rather than as an event name. When such a misconfiguration is found, Git will now warn that the setting will be ignored, helping users understand why their parallelization settings might not be taking effect.

The patch includes four new test cases in t1800-hook.sh that verify the warning appears in the expected cases (when the name has `.command`, `.event`, or `.parallel` configured) and does not appear for proper event names. This is a user-facing quality-of-life improvement that helps prevent confusion between the two configuration namespaces while maintaining all existing functionality.
