Feature patch implementing object iteration for the in-memory ODB backend, part of Patrick Steinhardt's ongoing ODB abstraction series. This is patch 11/17 in the v3 series, which has already received thorough technical review and is nearly ready for integration.

The patch adds the `for_each_object()` callback to the in-memory object database implementation, completing another piece of the ODB interface. Key changes include:
- Extracts common object info population into a new `populate_object_info()` helper
- Implements the iteration callback with support for both bare OID iteration and full object info requests
- Handles filtering options like PROMISOR_ONLY and LOCAL_ONLY
- Uses the oidtree structure for efficient prefix-based iteration

This continues the pattern seen throughout the series of careful, well-structured implementations that match the existing ODB interface while leveraging the in-memory backend's capabilities. The patch builds on previous infrastructure changes (like the oidtree extensions) and maintains consistent error handling patterns.

With this addition, the in-memory ODB now supports all major object database operations, bringing it closer to production readiness. The series as a whole represents a significant step forward in Git's object storage architecture, with immediate applications for git-blame and potential future uses in re-merge operations.
