This is part 2/8 of a v2 series enhancing Git's promisor remote functionality, focusing on secure client-side storage of server-advertised fields. The patch introduces a new `promisor.storeFields` configuration that allows clients to automatically store certain fields (currently "partialCloneFilter" and "token") from server advertisements into their local config.

The implementation includes validation checks - filters are parsed to ensure they're valid, and tokens are checked for control characters. Changes are only made when the remote is already configured on the client side (a security measure), and users are notified via stderr when config values change. The patch includes comprehensive tests verifying the storage behaviors and edge cases.

This builds on previous work that allowed servers to advertise additional fields and clients to check them. The storage capability is particularly useful for tokens that may need frequent updates, allowing centralized server-side management rather than manual client updates. The implementation appears thorough, with attention to security considerations and backward compatibility.
