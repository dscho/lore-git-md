Thread identity: RFC discussion about reorganizing Git's experimental Rust infrastructure from `src/` to a dedicated `rust/` subdirectory, initiated by Mike Hommey (git-cinnabar maintainer), with ongoing debate involving brian m. carlson regarding mrustc compatibility and project structure conventions.

Core problem/goal: Evaluating whether to relocate Rust files to address three concerns: (1) project structure clarity in mixed C/Rust codebase, (2) git-cinnabar build issues with `cargo package`, and (3) mrustc compatibility for platforms lacking standard Rust toolchains. The discussion has evolved to challenge assumptions about mrustc's layout requirements, with new evidence showing it supports non-standard directory structures.

Current status: Active design discussion with no patches yet proposed. Key development is Mike Hommey's demonstration that mrustc's minicargo can handle non-standard layouts, weakening one technical justification for strict directory conventions. The git-cinnabar build issue remains unresolved but may now be considered separately from directory structure questions.

Technical details: Proposal would move Rust files (Cargo.toml, lib.rs, varint.rs) from `src/` to `rust/`. New technical findings: mrustc's minicargo implementation does parse non-standard layouts (contrary to earlier claims), and Rust's own compiler historically used non-standard structures before adopting conventions. Both Makefile and meson.build would require updates regardless of chosen structure. The git-cinnabar issue (Cargo skipping directories with Cargo.toml when Git is submodule) remains a separate concern.

Open questions: Discussion now focuses on: (1) whether mrustc compatibility truly requires standard layouts (evidence suggests no), (2) if moving files is still preferred for project hygiene independent of mrustc concerns, and (3) how to resolve git-cinnabar build issues regardless of directory structure decisions. The mrustc revelation may decouple platform support concerns from directory layout choices.

Participant positions: Mike Hommey maintains original proposal benefits but now questions necessity of strict conventions, provides evidence against mrustc layout constraints. brian m. carlson's position on standard layouts now lacks mrustc justification but may shift to emphasize other benefits. Both must reconcile git-cinnabar needs with clarified technical realities about cross-compilation.

Related work: git-cinnabar's build constraints remain primary driver. mrustc compatibility concerns now appear resolvable without directory structure changes. Historical Rust compiler layouts and Servo project examples regain relevance as precedents for non-standard structures in mature projects.
