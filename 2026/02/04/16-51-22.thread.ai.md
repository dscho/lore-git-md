Adrian Ratiu's config-based hooks series (v3, 8 patches) implements `hook.<name>.command`, `hook.<name>.event`, and `hook.<name>.enabled` configuration options while maintaining filesystem hook compatibility. The series introduces `struct hook` infrastructure supporting multiple hooks per event, a `git hook list` subcommand with `-z` output, and repository-level strmap caching. Junio Hamano has approved the architectural approach while noting documentation updates needed in API comments, and the prerequisite hooks-conversion series (v8) is marked for 'next' branch inclusion.

Key technical developments:
- Refactored hook callback data management from stack allocation to dynamic allocation via new `feed_pipe_cb_data_alloc`/`free` in `run_hooks_opt`, with Junio suggesting more concise validation checks using boolean negation/XOR operators (`(!A != !B)` instead of explicit conditionals)
- Updated reference transaction, pre-push, and receive-pack hooks to use new allocation pattern with `xcalloc` and designated initializers
- `git hook list` subcommand implementation with proper error handling and defensive `BUG()` checks for unknown hook types
- Two-phase config parsing with intermediate strmaps to collect hook configurations before final cache assembly, avoiding repeated config parsing while allowing per-invocation state initialization
- Clear separation between cached config data (strmaps) and runtime hook state (`struct hook` instances cannot be cached due to containing pipe callback data and other execution state)
- New `hook.<name>.enabled` config option (default true) for disabling hooks without removing configuration, implemented via `git_parse_maybe_bool()`
