Adrian Ratiu's v2 series implements config-based Git hooks through `hook.<name>.command`, `hook.<name>.event`, and `hook.<name>.enabled` configuration options, representing a major step in hook flexibility while maintaining filesystem hook compatibility. The series has evolved through multiple versions with key developments:

Core implementation:
- New `struct hook` with typed fields replaces temporary string-based identification
- Config caching implemented in `struct repository` via strmap, addressing Patrick Steinhardt's performance analysis showing critical cases like `reference-transaction` hook (called 3x per ref update)
- Supports config resets through `event = ""` syntax
- Maintains backward compatibility running filesystem hooks last
- New alloc/free callback infrastructure added for upcoming parallel execution support:
  - `cb_data_alloc_fn` and `cb_data_free_fn` typedefs in hook.h
  - Extended `struct run_hooks_opt` with alloc/free function pointers
  - BUG() check enforces alloc/free pairing
  - State now heap-allocated per hook run via xmalloc/xcalloc
  - Initialization context passable through `feed_pipe_ctx`

`git hook list` subcommand:
- Added NUL-delimited output mode (`-z` option)
- Incorporates prior feedback on scope and error messages
- Technical refinements:
  - Single-pass config parsing with cached repository object
  - Modern `git config set` examples in documentation
  - Security-conscious execution order between sources
  - Memory management via indices rather than pointer arithmetic

Documentation:
- New `Documentation/config/hook.adoc` covers:
  - Multi-event syntax
  - Reset behavior
  - Enabled/disabled toggles
  - Execution precedence rules
