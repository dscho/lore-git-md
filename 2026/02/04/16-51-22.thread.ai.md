Adrian Ratiu's config-based hooks series (v4, 12 patches) implements `hook.<friendly-name>.command`, `hook.<friendly-name>.event`, `hook.<friendly-name>.enabled` configuration options while maintaining filesystem hook compatibility. The series introduces disabled hook visibility in the final patch (12/12), building on prior work including out-of-repo execution support (patch 8/12), core config parsing (patch 5/12), and scope display (patch 11/12).

Key technical developments:
- Patch 1-7/12: Introduced alloc/free helpers, `struct hook`, `git hook list`, config parsing with strmap cache, enabled/disabled control, and event clearing via empty values
- Patch 8/12: Enables out-of-repo execution for config-based hooks using `RUN_SETUP_GENTLY`, with temporary config caches for nongit contexts while maintaining filesystem hook restrictions
- Patch 9/12: Adds `-z` option to `git hook list` for NUL-terminated output
- Patch 10/12: Refactors cache storage into typed `struct hook_config_cache` and `struct hook_config_cache_entry`, replacing raw strmap/string_list usage
- Patch 11/12: Implements `--show-scope` for `git hook list` to display hook definition source (local/global/system config)
- Patch 12/12: Completes functionality by showing disabled hooks in `git hook list` output with "(disabled)" annotation while maintaining execution-time skipping
- Core architecture maintains strict separation: config hooks work anywhere, filesystem hooks require repository
- Disabled state now preserved in cache with warnings for invalid configurations
- Test coverage in t1800-hook.sh verifies all new behaviors including disabled hook visibility
- Filesystem hook behavior remains unchanged - still requires repository context
- Defensive checks prevent mixed cache usage between repository and nongit cases
