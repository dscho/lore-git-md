This is a review response in the ongoing Meson build system integration effort, specifically addressing the wiring of gitk and git-gui components. Karthik Nayak provides feedback on Patrick Steinhardt's v2 patch, which switched from moving the GUI projects into a subprojects/ directory to using symlinks instead.

The key points are:
- Karthik notes the symlink approach is an improvement over the v1 patch's directory relocation
- He asks whether Meson might eventually allow configurable subproject paths, which could eliminate the need for symlinks
- The review confirms the toolchain requirements (gitk needs wish, git-gui needs both tclsh and wish) are correctly implemented
- The response is generally positive, with no major issues identified in the technical implementation

This continues the thread's progression toward full Meson compatibility while maintaining the GUI tools' build behavior. The symlink solution appears to be an acceptable compromise between Meson's requirements and Git's source layout preferences.
