This is part 2/8 of a v2 series enhancing Git's promisor remote functionality, focusing on secure client-side storage of server-advertised remote fields. The patch implements the `promisor.storeFields` configuration option, allowing clients to automatically store certain fields (currently "partialCloneFilter" and "token") from server advertisements into their local config.

The implementation includes several security-conscious design choices:
- Only stores fields for already-configured remotes (no new remotes are created)
- Validates filters by parsing them before storage
- Checks tokens for control characters before storage
- Emits warnings when invalid values are rejected
- Notifies users via stderr when config changes occur

The patch builds on previous work that allowed servers to advertise additional fields and clients to check them. It's particularly useful for tokens that need frequent server-side updates, avoiding manual client updates. The documentation explains the security model clearly, noting that stored values only come from pre-configured remotes.

Test coverage is thorough, verifying:
- Filter storage behavior and notifications
- Token non-storage when not requested
- Validation of stored values
- Edge cases around unknown remotes

The implementation follows Git's configuration patterns and includes appropriate memory management. Patrick Steinhardt reviewed the v1 version, and this revision incorporates his feedback on naming, worktree config handling, and test coverage. The patch is well-motivated as part of the larger LOP (Large Object Promisors) effort to improve partial clone workflows.
