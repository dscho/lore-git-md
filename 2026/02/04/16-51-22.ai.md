This is a feature patch series introducing configurable hooks, part of Adrian Ratiu's ongoing work to modernize Git's hook subsystem. The series builds on previous hook API cleanup work and allows specifying hook commands via Git config (in addition to the traditional filesystem-based hooks).

The key changes include:
1. Adding a new `hook.<event>.command` config option to specify hook commands
2. Introducing a `git hook list` subcommand to inspect configured hooks
3. Supporting hook commands both from config and filesystem, with config hooks running first
4. Allowing `git hook` commands to work outside repository contexts

The implementation maintains backward compatibility by keeping sequential execution (no parallel hooks yet) and preserving the existing hookdir behavior. The series is based on Adrian's earlier v8 hooks-conversion work that hasn't been merged yet, so it will need to be rebased once that lands.

The changes touch core hook handling code, several commands that use hooks (receive-pack, transport), and add substantial test coverage. The approach appears well-considered, with clear commit messages referencing prior art (Emily Shaffer and Ævar Arnfjörð Bjarmason's earlier configurable hooks proposal) while implementing a cleaner version based on modernized internals.

This represents a significant step toward more flexible hook configuration, though the series notes that parallel execution support will come in a follow-up. The changes are substantial but focused, with good test coverage and documentation updates. Reviewers will likely want to verify the interaction between config and filesystem hooks, as well as the security implications of config-based hook definitions.
