Junio C Hamano has finalized a fix for incorrect whitespace handling when dealing with symbolic links in Git's diff and apply machinery. The issue stemmed from recent improvements to whitespace checking that mistakenly applied incomplete-line validations (WS_INCOMPLITE_LINE) to symlinks, where such checks don't make sense since symlinks don't require newline termination.

The solution carefully modifies both `apply.c` and `diff.c` to skip these checks when the post-image side (accounting for `--reverse` operations) is a symlink. This properly handles cases like text-to-symlink transitions while maintaining strict validation for regular files. Patrick Steinhardt provided key technical review that helped refine the approach - particularly around mode-change edge cases - leading to the current implementation that considers only the post-image side for symlink checks.

New test cases in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh` verify the behavior works correctly in both forward and reverse operations. The patch has gone through multiple iterations and is now considered ready for integration, with all substantive questions resolved between the maintainer and reviewer. Theoretical edge cases like newline-terminated symlink targets were explicitly deferred as not worth the implementation complexity.
