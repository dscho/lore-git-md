This thread addresses a bug in Git's whitespace handling where symbolic links were incorrectly being checked for incomplete-line endings (WS_INCOMPLETE_LINE), which don't apply to symlinks. The original patch from maintainer Junio C Hamano modified both `apply.c` and `diff.c` to skip these checks for symlinks, with test cases added to verify the fix.

In the latest exchange, Junio and reviewer Patrick Steinhardt are refining the conditions under which whitespace checks should be skipped. While Patrick suggested only disabling checks when one side is missing and the other is a symlink, or when both sides are symlinks, Junio notes this may need adjustment for text-to-symlink transitions where we wouldn't want to flag missing newlines in the result. They agree that explicitly supporting newline-terminated symlinks isn't a priority, and Junio raises the question of how Git handles symrefs like .git/HEAD in this context.

The discussion has revealed that what initially seemed like a simple fix requires more careful handling of mode-change edge cases. Junio appears likely to send an updated version of the patch incorporating this refined logic, though the core approach of special-casing symlinks remains sound. The collaborative back-and-forth between maintainer and reviewer is working through the remaining subtleties to ensure the fix is complete.
