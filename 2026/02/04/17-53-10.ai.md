Build system patch addressing Windows symlink concerns in Meson integration. This is a follow-up to Patrick Steinhardt's v2 patch that wired up gitk and git-gui as Meson subprojects using symlinks.

Junio Hamano raises two key points in his review. First, he questions whether the symlink approach will work reliably on Windows, which has historically had poor symlink support. This is a practical concern since Git for Windows is a major distribution target. Second, he notes an unrelated but interesting edge case regarding `.gitattributes` handling of symlinks - suggesting either a new pattern syntax to exempt symlinks from line-ending checks or a blanket exemption for symlinks from the `whitespace=incomplete-lines` rule.

The thread context shows this patch has already gone through significant architectural discussion, with v2's symlink approach having received positive review from Karthik Nayak. Junio's Windows concern appears to be the last remaining technical hurdle before this can be merged. The symlink implementation is clean and minimal, creating two symlinks in the `subprojects/` directory pointing to the original git-gui and gitk-git directories.

This patch represents the final piece needed for Meson build system feature completeness relative to the Makefile, marking an important milestone in Git's build system modernization. The Windows symlink question is the only outstanding issue that needs resolution before this can proceed.
