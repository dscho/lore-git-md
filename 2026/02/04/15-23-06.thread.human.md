This thread addresses a discrepancy in how Git and GnuPG handle signatures from keys that were valid when created but later expired. While GnuPG marks these as "Good" (with an expiration note), Git currently rejects them as "BAD", causing problems for projects like the Linux kernel that rely on signed commits.

Uwe Kleine-König proposed modifying `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, recognizing 'Y' (expired key) result codes alongside 'G' (good signature). The change received support from Neal Walfield, who agreed it better matches the principle that signatures should be judged based on key validity at signing time, though he noted GnuPG's interface doesn't provide the exact signing timestamp needed for perfect enforcement.

Junio Hamano has now picked up the patch for inclusion, making minor formatting adjustments. The change resolves a practical pain point while aligning Git's behavior with GnuPG's, and appears likely to land in an upcoming release given the maintainer's involvement and the lack of opposition from security-conscious contributors.
