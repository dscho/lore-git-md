This thread discusses a proposed change to how GPG signature verification handles keys that were valid when a signature was created but have since expired. Currently, Git marks these signatures as "BAD" while GnuPG itself considers them "Good" (with an expiration note), creating a discrepancy that can reject commits that GnuPG would accept.

The patch modifies `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, and to recognize the 'Y' (expired key) result code alongside 'G' (good signature). The author cites real-world motivation from Linux kernel commit signing practices and references prior discussion with Linus Torvalds about this behavior.

Neal Walfield has expressed initial agreement that this change better aligns with the principle that signatures should be judged based on the key's validity at signing time, though notes GnuPG's interface doesn't provide the exact signing timestamp needed for perfect enforcement. The security implications of relaxing signature verification standards may warrant further discussion, but the patch appears well-motivated to resolve the current discrepancy with GnuPG's behavior. The thread is still early in the review cycle with no substantial objections raised yet.
