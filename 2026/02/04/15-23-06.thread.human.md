This thread addresses a discrepancy in how Git handles GPG signatures from keys that were valid when the signature was created but later expired. Currently, Git marks these as "BAD" while GnuPG considers them "Good" (with an expiration note), causing problems for projects like the Linux kernel that rely on signed commits.

The proposed solution modifies `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, and recognize the 'Y' (expired key) result code alongside 'G' (good signature). The changes are minimal but touch security-sensitive code. After discussion, there was consensus that this better matches ideal behavior, with no opposition raised. Neal Walfield supported the change, agreeing it aligns with expected behavior.

Junio Hamano is now handling final formatting adjustments (wrapping an overlong line) and confirms the patch will be queued for inclusion in an upcoming release. The author, Uwe Kleine-König, sought confirmation that no resend was needed, which Junio provided. This resolves a known discrepancy between Git and GnuPG's behavior that had been previously discussed, including with Linus Torvalds regarding Linux kernel commit signing practices.
