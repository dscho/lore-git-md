This is a bugfix patch finalizing a change to GPG signature verification behavior, now being queued by Junio Hamano. The patch aligns Git's handling of signatures from expired keys with GnuPG's more permissive stance: when a key was valid at signing time but later expired, Git will now accept the signature as "good" (with a note about expiration) rather than marking it "BAD". This resolves a practical issue for projects like the Linux kernel that rely on commit signing.

The change modifies two checks in `gpg-interface.c` to recognize both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, and to accept the 'Y' (expired key) result code alongside 'G' (good signature). The thread discussion indicates consensus that this better matches ideal behavior, with no security concerns raised. Junio confirms the patch is ready for integration after minor formatting adjustments, meaning it should appear in an upcoming release.
