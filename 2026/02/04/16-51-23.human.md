This is part 1 of Adrian Ratiu's series to enable configurable Git hooks, building on prior work by Emily Shaffer. The patch refactors Git's hook execution machinery to support running multiple hooks per event, preparing for future patches that will allow hooks to be defined via Git configuration.

The key change is replacing the single `hook_path` in the hook callback data with a `hook_command_list` that can contain multiple hook definitions. The patch maintains backward compatibility by initially populating this list with just the traditional filesystem hook (if present). It adds infrastructure to copy and free per-hook state when running multiple hooks, though the actual parallel execution is deferred to a future series.

The implementation touches core hook handling in `hook.c` and updates three hook callers (`receive-pack.c`, `refs.c`, and `transport.c`) to use the new state management APIs. The changes are mechanical but thorough, with clear documentation of the new data structures and careful handling of memory management. Test coverage appears comprehensive though no new tests are added in this patch - they'll come with the configurable hooks functionality.

This is a well-structured foundation for the series, cleanly separating the list-of-hooks infrastructure from the config parsing that will build on it. The patch carries Emily Shaffer's original sign-off from when this work began, suggesting it's changes align with the initial design.
