This is part of Adrian Ratiu's ongoing series to make Git hooks configurable via Git configuration. Patch 2/4 introduces a new `git hook list` subcommand that shows which hooks would run for a given event, in execution order.

The new command provides visibility tooling for the multi-hook system being built in this series. It lists hooks from both traditional filesystem locations and (in future patches) config-based hooks, with config hooks running first. The implementation exposes the existing `list_hooks()` function that was previously static, moving it to hook.h for broader use.

The patch comes with basic documentation and tests for the new subcommand. It builds on Emily Shaffer's original work from earlier iterations of the hooks configuration effort. The implementation is straightforward - it collects hooks via `list_hooks()` and prints them one per line, returning 1 if no hooks are found.

This is a useful debugging and inspection tool that will become more valuable as the series progresses to support config-defined hooks. The patch appears well-contained and properly integrated with the existing hook infrastructure.
