Git thread summary: Feature patch series introducing parallel hook execution (v4 0/9), building on Adrian Ratiu's prior configurable hooks work. This version updates the command-line `-j/--jobs` option (v4 6/9) while maintaining the series structure from v3 (9/9). The series implements parallel hook execution with multiple opt-in control points: `hook.jobs` config (3/9), `hook.<name>.parallel` markers (4/9), `-rewritten -j/--jobs` command-line option (6/9), per-event `hook.<event>.jobs` overrides (7/9), and output stream handling via `extensions.hookStdoutToStderr` (8-9/9).

Patch 1/9 fixes a memory leak in `repo_init()`. Patch 2/9 adds unsigned integer config infrastructure (`git_config_uint()`). Patch 3/9 implements global `hook.jobs` config. Patch 4/9 implements core parallel execution with `hook.<name>.parallel` markers and job count determination in `get_hook_jobs()`, introducing `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` for mandatory serial hooks. Emily Shaffer's contribution identifies seven hooks that must always run sequentially (`applypatch-msg`, `pre-commit`, `prepare-commit-msg`, `commit-msg`, `post-commit`, `post-checkout`, `push-to-checkout`), enforced via `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` across all relevant builtins (`am`, `checkout`, `clone`, `receive-pack`, `worktree`, commit handling). The updated patch 6/9 adds command-line `-j/--jobs` option with TTY behavior differentiation between serial (-j1) and parallel (-jN) execution, maintaining backward compatibility through serial default when neither config nor command-line specifies jobs.

Patch 7/9 introduces per-event job count configuration via `hook.<event>.jobs`, adding a new `event_jobs` strmap to the hook config cache with the same validation rules as the global setting. The job count resolution in `get_hook_jobs()` now checks for event-specific overrides before falling back to global setting. Documentation clarifies the distinction between event names and hook friendly names in config keys. Test cases verify: per-event jobs override global jobs, jobs=1 forces serial execution even with global jobs>1, and parallel execution still requires individual hooks marked parallel=true.

Implementation supports:
- Parallel execution with configurable job counts at multiple levels (global, per-event, per-hook, command-line)
- Critical hook serialization via force-serial flag or non-parallel hooks (explicit list of mandatory serial hooks)
- Output stream consistency enforcement
- Global override for stdout-to-stderr merging
- Backward compatibility throughout with serial default
- Thorough test coverage using sentinel/detector pattern, now including command-line job count verification and per-event override validation

The series builds on Adrian's configurable hooks work, providing comprehensive control over parallelization while maintaining safety through explicit opt-in requirements and mandatory serialization for critical hooks. The design accommodates existing tools like git-lfs while enabling performance improvements through parallel execution where explicitly configured. Follow-up patches will implement additional control points and output stream handling.
