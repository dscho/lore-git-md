Technical implementation spans: new repo_config_get_uint() helper (added in preparatory patch to support unsigned int configuration values), strmap cache for event jobs (v7 8/13), public is_known_hook() function (with meson.build fix co-authored by Patrick Steinhardt), transport.c integration preserving stream separation (modified to document automatic stdout/stderr merging when parallel), and updates to builtins requiring serial execution. This establishes the complete configuration system with CLI override capability while maintaining backward compatibility and safety through explicit opt-in requirements and warnings.

Patch 6/13 marks seven hooks as non-parallelizable for safety: applypatch-msg, pre-commit, prepare-commit-msg, commit-msg, post-commit, post-checkout, and push-to-checkout. These hooks either modify commit messages in-place or interact with the working tree/index in ways that can't safely parallelize. The changes update each hook's call site to use RUN_HOOKS_OPT_INIT_FORCE_SERIAL, which overrides any parallelization settings. Documentation is added explaining why these hooks require serial execution. A new test verifies that hook.jobs=2 is properly ignored for force-serial hooks like pre-commit, ensuring the safety mechanism works as intended. Implementation touches multiple builtin commands (am, checkout, clone, receive-pack, worktree) and the core commit.c logic, with corresponding test coverage in t1800-hook.sh.
