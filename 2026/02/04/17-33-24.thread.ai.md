Git thread summary: Feature patch series (v6 0/9) introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. Patch 1/9 (acked by maintainer Junio C Hamano) introduces new `repo_config_get_uint()` helper function for unsigned integer config values, used for `hook.jobs` setting. Patch 2/9 introduces `hook.jobs` configuration option controlling simultaneous hook execution, defaulting to 1 (serial). Patch 3/9 implements core parallel execution logic with `hook.<name>.parallel` config, output stream handling (stdout redirected to stderr except for pre-push hook), and comprehensive tests.

Implementation establishes clear precedence: CLI `-j/--jobs` override takes highest precedence, followed by per-hook `hook.<name>.parallel` flags, then global `hook.jobs`, with fallback to serial execution if safety checks fail. Patch 4/9 enables parallel execution for pre-push hook with automatic stdout-to-stderr merging when jobs > 1. Patch 5/9 marks several hooks as non-parallelizable (commit message hooks, working tree/index hooks) using RUN_HOOKS_OPT_INIT_FORCE_SERIAL. Patch 6/9 adds CLI job control to `git hook run` via `-j/--jobs` with warning messages for unsafe parallel execution.

Patch 7/9 introduces per-event job control via `hook.<event>.jobs` configuration, stored in new `event_jobs` strmap. Patch 8/9 adds warnings for misconfigured `hook.<friendly-name>.jobs` settings. Final patch (9/9) adds high-level `hook.<event>.enabled` master switch to disable all hooks for an event, completing the layered configuration approach. Implementation reuses `is_friendly_name()` helper, updates `git hook list` to show "event-disabled" status, and adds new `event_disabled` string list for tracking.

Series now provides comprehensive controls:
1. Global `hook.jobs` default
2. Per-hook `hook.<name>.parallel` flags
3. CLI `-j/--jobs` override
4. Per-event `hook.<event>.jobs` settings
5. Per-hook `hook.<name>.enabled` switches
6. Per-event `hook.<event>.enabled` master switch

All foundational patches have maintainer acks. Careful attention to backward compatibility and user feedback demonstrated throughout, with output stream handling simplified per Junio's feedback (dropping `extensions.hookStdoutToStderr` in favor of implicit parallel-mode behavior). Extensive test coverage in t/t1800-hook.sh verifies all behaviors including TTY handling, output ordering, precedence rules, and warning messages.
