Git thread summary: Feature patch series introducing parallel hook execution (v4 0/9), building on Adrian Ratiu's prior configurable hooks work. This version updates the command-line `-j/--jobs` option (v4 6/9) while maintaining the series structure from v3 (9/9). The series implements parallel hook execution with multiple opt-in control points: `hook.jobs` config (3/9), `hook.<name>.parallel` markers (4/9), `-rewritten -j/--jobs` command-line option (6/9), per-event `hook.<event>.jobs` overrides (7/9), and output stream handling via both repository-specific `extensions.hookStdoutToStderr` (8/9) and global `hook.forceStdoutToStderr` (9/9).

Patch 1/9 fixes a memory leak in `repo_init()`. Patch 2/9 adds unsigned integer config infrastructure (`git_config_uint()`). Patch 3/9 implements global `hook.jobs` config. Patch 4/9 implements core parallel execution with `hook.<name>.parallel` markers and job count determination in `get_hook_jobs()`, introducing `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` for mandatory serial hooks. Emily Shaffer's contribution identifies seven hooks that must always run sequentially (`applypatch-msg`, `pre-commit`, `prepare-commit-msg`, `commit-msg`, `post-commit`, `post-checkout`, `push-to-checkout`), enforced via `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` across all relevant builtins (`am`, `checkout`, `clone`, `receive-pack`, `worktree`, commit handling). The updated patch 6/9 adds command-line `-j/--jobs` option with TTY behavior differentiation between serial (-j1) and parallel (-jN) execution, maintaining backward compatibility through serial default when neither config nor command-line specifies jobs.

Patch 7/9 introduces per-event job count configuration via `hook.<event>.jobs`, adding a new `event_jobs` strmap to the hook config cache with the same validation rules as the global setting. The job count resolution in `get_hook_jobs()` now checks for event-specific overrides before falling back to global setting. Documentation clarifies the distinction between event names and hook friendly names in config keys. Test cases verify: per-event jobs override global jobs, jobs=1 forces serial execution even with global jobs>1, and parallel execution still requires individual hooks marked parallel=true.

Patch 8/9 introduces repository-level `extensions.hookStdoutToStderr` configuration to handle output stream consistency for parallel hooks, addressing compatibility with `pre-push` hooks (notably git-lfs) that expect separate stdout/stderr streams. The change adds a `hook_stdout_to_stderr` flag in repository format and modifies `transport.c` to respect the setting. Without this extension, `pre-push` hooks will always run sequentially to maintain backward compatibility.

Patch 9/9 completes the output stream handling by adding global `hook.forceStdoutToStderr` config that enables merged stdout/stderr streams for all hooks, required for parallel execution of hooks like `pre-push`. The implementation adds the config to the hook config cache and modifies `get_hook_jobs()` to check this setting first. `setup.c` changes ensure the extension is automatically enabled during repository initialization when the config is set globally. Test cases verify behavior during `git init` and `git clone`, plus validation that existing repositories respect the global setting.

Implementation supports:
- Parallel execution with configurable job counts at multiple levels (global, per-event, per-hook, command-line)
- Critical hook serialization via force-serial flag or non-parallel hooks (explicit list of mandatory serial hooks)
- Output stream consistency enforcement through both repository extension and global config
- Global override for stdout-to-stderr merging
- Backward compatibility throughout with serial default
- Thorough test coverage using sentinel/detector pattern, now extended to command-line job count verification, per-event override validation, and output stream behavior

The series builds on Adrian's configurable hooks work, providing comprehensive control over parallelization while maintaining safety through explicit opt-in requirements and mandatory serialization for critical hooks. The design accommodates existing tools like git-lfs while enabling performance improvements through parallel execution where explicitly configured. The final patch adds the last control point for output stream handling, completing the series' runtime configuration options.
