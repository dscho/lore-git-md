This is the 9th patch in Derrick Stolee's series introducing a new `git config-batch` command, focused on adding the `set` operation to the batch protocol. The series aims to optimize configuration operations by batching multiple queries/modifications in a single process, with particular attention to improving performance for credential management workflows on Windows.

The patch adds version 1 of the `set` command, which allows writing single key-value pairs to config files with explicit scope control (system/global/local/worktree). The implementation matches the behavior of `git config --set` while avoiding more complex operations like multi-value replacement. Responses indicate success/failure and echo back the scope/key/value for verification.

Key aspects of this patch:
- Adds core `set` command implementation in `builtin/config-batch.c`
- Introduces `location_options_set_scope()` helper in config.c to handle scope validation
- Extends test coverage in t1312-config-batch.sh with both regular and NUL-terminated format tests
- Documents the new command in git-config-batch.adoc
- Maintains consistency with the existing protocol design and error handling patterns

The implementation looks thorough, with careful attention to edge cases and comprehensive test coverage. This continues the series' pattern of well-structured, incremental additions to the config-batch functionality. The focus on Windows credential manager performance needs remains evident, particularly in the NUL-terminated format support.
