This is part 5/11 of Derrick Stolee's series introducing a new `git config-batch` builtin to optimize configuration operations. The series aims to improve performance for credential managers by batching multiple config queries/modifications in a single process.

This patch adds NUL-terminated I/O format capability to handle special characters in config values. Key changes:

- Introduces `-z` option for NUL-terminated format
- Uses double NUL bytes to terminate commands
- Implements length-prefixed tokens (`<length>:<value>`) to handle empty strings
- Adds helper methods to parse/print in both formats
- Extends test coverage for the new format

The implementation maintains backward compatibility while adding the more robust format needed for values containing spaces/newlines. The patch follows the series' careful incremental approach with thorough test coverage.

Technical details:
- New `parse_ztoken()` helper handles NUL-delimited input
- `print_word()` helper supports both formats
- Tests verify edge cases like empty strings and special characters
- Documentation updated with protocol details and examples

This continues the series' focus on performance-sensitive credential management workflows while maintaining Git's protocol conventions. The NUL-terminated format will be particularly useful for Windows credential managers dealing with paths containing spaces.
