This is part of the ongoing LOP (Large Object Promisors) effort, specifically patch 2/9 in the series. Christian Couder is implementing a new `promisor.storeFields` configuration option that allows clients to securely store additional fields (like tokens and filters) from server-advertised promisor remotes. The patch enables dynamic configuration updates without requiring new remote definitions.

Patrick Steinhardt has provided thorough review feedback, leading to several improvements in v2: using `repo_config_set_gently()` instead of worktree config, following naming conventions with `store_info_new()`, and adding a fetch test case. The discussion also touches on security considerations - the implementation deliberately prevents automatic addition of new remotes while allowing updates to existing ones. This careful approach balances convenience with security, particularly around token management.

The patch represents a building block for the larger `--filter=auto` functionality coming later in the series, while being useful for organizations that need to manage promisor remote credentials centrally. The implementation includes comprehensive tests and follows Git's pattern for similar configuration options like `promisor.checkFields`.
