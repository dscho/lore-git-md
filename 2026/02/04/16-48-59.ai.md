This is a follow-up discussion on a bugfix patch addressing pathspec handling for excluded patterns in `git add` and `git stash`. The original patch modified `dir.c` to skip ignored-file checks for `PATHSPEC_EXCLUDE` pathspecs, fixing cases where `:!ignored` would incorrectly fail when the ignored file existed.

Junio C Hamano raises a thoughtful question about whether the current behavior (where excluded pathspecs are simply ignored in the matching logic) is truly the desired semantics. He suggests the interaction between positive and negative pathspecs may need more nuanced handling - perhaps requiring a path to match at least one positive pattern *and* no negative patterns to be included.

The core issue revolves around the expected behavior of commands like `git add "x" ":!y"` - should this act identically to `git add "x"` (current patch behavior), or should it additionally require that matched paths do *not* match the excluded pattern "y"? This touches on fundamental pathspec semantics that have been ambiguous for a decade.

The discussion highlights that while the patch fixes a clear inconsistency with documented behavior, it may not fully resolve the underlying design question about how positive and negative pathspecs should interact. This could become a point requiring broader consensus among contributors familiar with pathspec internals.
