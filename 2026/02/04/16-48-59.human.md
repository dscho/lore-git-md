Junio C Hamano raises an important design question about the behavior of negated pathspecs in Git commands. This is a follow-up to Remy D. Farley's patch that fixed `git add :!x` failing when x is in `.gitignore`.

The core issue revolves around whether negated pathspecs (like `:!y`) should be completely ignored during matching (as the patch currently does) or if they should actively exclude matching paths. Junio points out there are four possible combinations to consider when a path matches/doesn't match both a positive pathspec (`x`) and a negated pathspec (`:!y`).

The current patch's approach makes `git add "$x" ":!$y"` behave identically to `git add "$x"`, effectively ignoring the negated pathspec. Junio questions whether this is the desired behavior, suggesting the logic might need to be more nuanced - perhaps requiring paths to match at least one positive pathspec AND zero negated pathspecs to be included.

This is a thoughtful critique that goes beyond the immediate bugfix to examine the underlying design principles of pathspec handling. The discussion will likely need input from other pathspec experts to determine the correct semantic behavior before finalizing the fix.
