Hook infrastructure refactoring to support multiple hooks per event.

This is the first patch in Adrian Ratiu's series to make Git hooks configurable via Git configuration. It refactors the hook execution infrastructure to handle lists of hooks rather than single hooks, preparing for future patches that will add config-based hooks alongside traditional filesystem hooks.

The key changes:
- Introduces `list_hooks()` to collect hooks from multiple sources (currently just filesystem hooks, but structured for future config hooks)
- Modifies `run_hooks_opt` to track and iterate through a list of hooks
- Adds callbacks for copying and freeing per-hook state data
- Updates hook callers (receive-pack, transport, refs) to use the new state management

The patch maintains backward compatibility while laying groundwork for the configurable hooks feature. It touches core hook handling code and several hook callers, with comprehensive test coverage. The implementation ensures each hook gets its own state copy when needed, though hooks still run sequentially (parallel execution is noted as future work).

This builds on Emily Shaffer's earlier hooks work and is part of Adrian's ongoing effort to make hooks more flexible and configurable. The changes are mechanical refactoring with no user-visible behavior changes yet - those will come in follow-up patches that add the actual config hook support.
