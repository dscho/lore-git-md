Feature patch enabling parallel hook execution, part of Adrian Ratiu's configurable hooks series. This patch removes the hardcoded job limit of 1 in hook.c, allowing multiple hooks for a single event to run concurrently by default. The implementation provides a priority system for determining job counts: compile-time settings (via RUN_HOOKS_OPT_INIT_SERIAL) take precedence, followed by the new `hook.jobs` config, with the system's CPU count as fallback. The pre-push hook requires special handling - it must opt into parallel execution via `extensions.hookStdoutToStderr` config due to output collation concerns.

The changes touch multiple builtin commands (am, checkout, clone, etc.) to update their hook calls, with extensive test coverage in t/t1800-hook.sh verifying parallel behavior, TTY handling, and job count precedence. The patch maintains backward compatibility by defaulting to serial execution when safety is uncertain (like for commit-msg hooks that modify content). Emily Shaffer and Ævar Arnfjörð Bjarmason contributed to the implementation.

Key technical details for future reference: new `RUN_HOOKS_OPT_INIT_PARALLEL` macro, `get_hook_jobs()` helper function, modified `run_processes_parallel` integration in hook.c, and the special case for `stdout_to_stderr=0` hooks. The tests demonstrate parallel execution timing differences and verify output grouping to prevent interleaving. This builds on unmerged configurable hooks work, so may need rebasing.
