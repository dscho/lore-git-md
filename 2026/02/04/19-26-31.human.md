This is Junio Hamano's review of Johannes Schindelin's v4 patch series addressing ANSI escape sequence injection vulnerabilities in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). While the series is already in 'seen', Junio raises three substantive concerns about the design.

First, he criticizes the "default" configuration value that changes behavior across Git 3.0 as a poor design choice, arguing that explicit configuration should remain stable across versions. He suggests simply removing this option since users can already choose specific behaviors that won't change.

Second, Junio expresses a preference for an incremental approach where the opt-in mechanisms could be merged earlier, allowing real-world testing before the security-sensitive default flip. This reflects his typical maintainer philosophy of gradual, well-validated changes.

Most significantly, Junio questions the fundamental allowlist approach, suggesting it may force users into insecure configurations. He proposes inverting the model to block only known-dangerous sequences rather than allowing only known-safe ones, particularly noting that the current design might not handle legitimate uses of encoding sequences like ISO/IEC 2022. This technical concern about encoding collisions adds weight to security considerations beyond what was previously discussed.

The review maintains Junio's characteristic thoughtful skepticism - acknowledging the work while probing fundamental assumptions. His comments suggest the series may need redesign before graduating from 'seen', particularly around how configuration interacts with version changes and whether the security model should be allowlist- or blocklist-based.
