Thread identity: Patch addressing GPG signature verification behavior for signatures from keys that later expired, modifying `gpg-interface.c`.

Core problem: Currently Git marks signatures from keys that were valid when created but later expired as "BAD" signatures, while GnuPG itself treats them as "Good" (with an expiration note). This discrepancy causes Git to reject commits that GnuPG considers valid.

Key technical details: Modifies two checks in `gpg-interface.c` to:
1. Accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG
2. Recognize 'Y' (expired key) result code alongside 'G' (good signature)

Current status: Initial patch proposing this behavior change, citing Linux kernel commit history as real-world motivation. References prior discussion with Linus Torvalds about this behavior.

Open questions: Whether Git should maintain stricter standards than GnuPG for expired keys, given the security implications. No review feedback yet on this initial version.

Participant positions: Only the author's position presented so far, arguing for alignment with GnuPG's behavior based on practical use cases.

Related work: References Linux kernel commit signing practices and prior mailing list discussion with Linus Torvalds about GPG behavior.
