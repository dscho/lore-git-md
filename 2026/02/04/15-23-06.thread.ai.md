Thread identity: Patch addressing GPG signature verification behavior for signatures from keys that later expired, modifying `gpg-interface.c`.

Core problem: Git currently marks signatures from keys that were valid when created but later expired as "BAD", while GnuPG treats them as "Good" (with an expiration note). This discrepancy causes Git to reject commits that GnuPG considers valid, creating practical problems for projects like the Linux kernel that rely on commit signing.

Key technical details: Modifies two checks in `gpg-interface.c` to:
1. Accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG
2. Recognize 'Y' (expired key) result code alongside 'G' (good signature)
The changes are minimal but touch security-sensitive signature verification code.

Current status: Initial patch has received positive feedback from Neal Walfield who agrees this better matches the ideal behavior where signatures should be judged based on key validity at signing time. However, Walfield notes GnuPG's interface doesn't provide the exact signing timestamp needed for perfect enforcement.

Open questions: Whether the security implications of relaxing signature verification standards warrant maintaining Git's stricter behavior despite the practical problems. The patch needs broader review from security-conscious contributors.

Participant positions: Author argues for alignment with GnuPG's behavior based on real-world use cases. Neal Walfield supports the change in principle but notes technical limitations in GnuPG's interface. No opposing views expressed yet.

Related work: References Linux kernel commit signing practices and prior mailing list discussion with Linus Torvalds about GPG behavior. The patch aims to resolve a known discrepancy between Git and GnuPG's handling of expired keys.
