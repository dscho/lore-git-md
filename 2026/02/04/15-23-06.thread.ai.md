Thread identity: Patch addressing GPG signature verification behavior for signatures from keys that later expired, modifying `gpg-interface.c`, now being queued by Junio Hamano.

Core problem: Git currently marks signatures from keys that were valid when created but later expired as "BAD", while GnuPG treats them as "Good" (with an expiration note). This discrepancy causes Git to reject commits that GnuPG considers valid, creating practical problems for projects like the Linux kernel that rely on commit signing.

Current status: Junio Hamano is queuing the patch with minor formatting adjustments (wrapping an overlong line), indicating it will likely be included in an upcoming release. The change has evolved from initial proposal to imminent inclusion.

Key technical details: Modifies two checks in `gpg-interface.c` to:
1. Accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG
2. Recognize 'Y' (expired key) result code alongside 'G' (good signature)
The modifications remain minimal but touch security-sensitive signature verification code.
