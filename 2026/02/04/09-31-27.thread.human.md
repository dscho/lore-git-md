This RFC thread explores the controversial proposal to introduce AI-assisted workflows for Git's localization (l10n) process, specifically for handling .po file translations. Jiang Xin (Chinese translation maintainer) initiated the discussion with an experimental implementation in the git-po repository's next branch, proposing standard prompts for AI-assisted translation updates and reviews.

The debate has drawn strong opposition from Peter Krefting (Swedish translation maintainer), who rejects AI tools outright for Swedish translations, calling current output low-quality. Michal Suchanek offered more nuanced concerns, particularly about AI handling technical terminology accurately, citing problems in Mozilla's Japanese SUMO community. The latest contribution from Lilydjwg (Chinese translator) adds concrete examples of AI translation failures in fish shell's Chinese translations and Python documentation, reinforcing concerns about accuracy and the burden of cleaning up poor-quality AI output.

While Jiang Xin's initial implementation remains available for testing, the discussion has shifted toward fundamental questions about whether and how AI should be used at all. Key unresolved issues include how to ensure terminology accuracy, whether to implement opt-out mechanisms for individual languages, and how to prevent increased review burdens on human maintainers. The thread currently reflects a divide between those seeing AI as helpful automation and others viewing it as a threat to translation quality, with no clear consensus emerging yet.
