This is a documentation clarification thread about rename detection behavior in `git format-patch`. Jeff King confirms that `git format-patch` indeed uses the same `diff.renames` configuration as `git diff` for controlling rename detection, though this relationship isn't explicitly documented in the man page. 

The thread was initiated by Chris Packham who wants to maintain rename detection for interactive diffs while disabling it for patch generation (to ensure compatibility with basic `patch` utility). Jeff notes there's currently no way to configure this divergence in behavior - users must explicitly pass `--no-renames` or override the config at runtime.

Jeff suggests that if someone wanted to implement separate configuration, the pattern would be to add a `format.renames` option that falls back to `diff.renames` when unset, similar to how `merge.renames` and `status.renames` work. However, this remains a hypothetical suggestion rather than a concrete proposal at this stage.

The key technical detail is the confirmation that `git format-patch` shares rename detection behavior with `git diff` via the `diff.renames` config, despite this not being documented. The thread may lead to either a documentation patch clarifying this relationship or potentially a feature patch adding format-specific rename configuration, though the latter seems less likely given Jeff's phrasing.
