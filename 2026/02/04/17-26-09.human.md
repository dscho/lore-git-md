This is a bugfix patch addressing GPG signature verification behavior for signatures from keys that later expired. The patch modifies `gpg-interface.c` to align Git's behavior with GnuPG's handling of such signatures.

Currently, Git marks signatures from keys that were valid when created but later expired as "BAD", while GnuPG treats them as "Good" (with an expiration note). This discrepancy causes Git to reject commits that GnuPG considers valid, creating practical problems for projects like the Linux kernel that rely on commit signing.

The changes are minimal but security-sensitive, modifying two key checks in the signature verification code to:
1. Accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG
2. Recognize 'Y' (expired key) result code alongside 'G' (good signature)

Junio Hamano has reviewed the patch and indicates he will queue it with minor formatting adjustments. The change has received positive feedback from Neal Walfield who agrees it better matches the ideal behavior where signatures should be judged based on key validity at signing time. However, Walfield notes GnuPG's interface doesn't provide the exact signing timestamp needed for perfect enforcement.

The patch appears well-justified and addresses a real-world pain point, particularly for projects with long-lived signed commits. While touching security-sensitive code always warrants careful review, the change seems uncontroversial and aligns Git's behavior with GnuPG's more practical approach to expired keys.
