Maintainer feedback on sideband control sequence security patch series

Junio Hamano, the Git maintainer, provides additional context about why the current approach to sanitizing control sequences in the sideband channel may be too restrictive. He shares a personal use case where he relies on terminal title updates (using ESC ] 0; <string> BEL sequences) to monitor long-running processes across multiple terminal tabs.

This feedback builds on his earlier concerns about the whitelist model being too inflexible for legitimate uses of non-color control sequences. The example demonstrates how some users may need to pass through sequences that would be blocked by the current security implementation, particularly in controlled environments where both server and client are trusted.

Junio suggests the current approach would force users to either accept broken functionality or enable full passthrough (ALLOW_ALL_CONTROL_CHARACTERS), which he considers suboptimal. His comment implies the security model may need to be rethought to better accommodate such valid use cases while still protecting against actual vulnerabilities.

The feedback comes as part of Junio's review of the test suite changes in patch 4/4 of the series, where he notices the test assumes color sequences are the only permitted control characters. His real-world example provides concrete justification for why the maintainer has been pushing back on the whitelist approach throughout the thread.
