This is a feature patch series implementing two enhancements to Git's promisor remote functionality as part of the LOP (Large Object Promisors) effort. The series adds:

1) A `promisor.storeFields` config option that securely stores remote fields (like tokens and filters) on the client side when they are advertised by the server. This enables workflows where clients can automatically update credentials from the server.

2) A `--filter=auto` mode for clone/fetch that dynamically combines filters from accepted promisor remotes, allowing clients to suggest optimal filters without breaking existing partial clone configurations.

The series builds on previous work to advertise promisor remote capabilities and refactors several components to support these features. Key changes include:

- New configuration handling in `promisor-remote.c` for storing fields
- Refactoring of filter options in clone/fetch commands to be local
- Documentation updates for the new `--filter` option in fetch
- Infrastructure for `auto` filter mode in `list-objects-filter-options`
- Logic to construct combined filters from accepted promisor remotes
- Wiring up the auto filter resolution in fetch-pack

The implementation has gone through multiple rounds of review from Patrick Steinhardt and others, with v2 incorporating feedback on naming, error handling, and simplification of the filter combination logic. The series maintains comprehensive test coverage and follows Git's security model by requiring pre-configured remotes for any stored fields.

This represents a significant enhancement to Git's promisor remote capabilities, enabling more dynamic and secure workflows for partial clones and large object handling. The changes are well-motivated in the context of the LOP effort and appear carefully implemented with attention to backward compatibility and error cases.
