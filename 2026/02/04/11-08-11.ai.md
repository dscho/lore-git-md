This patch is part of the ongoing LOP (Large Object Promisors) effort to enhance Git's promisor remote functionality. It introduces infrastructure for a new `--filter=auto` mode that will allow dynamic filter combination in subsequent patches.

The key changes in this patch:
- Adds a new `LOFC_AUTO` filter choice and `allow_auto_filter` flag to `struct list_objects_filter_options` to control which commands can accept "auto" filters
- Modifies `gently_parse_list_objects_filter()` to handle "auto" filters when allowed
- Prevents combining "auto" with other filters (though notes this could be relaxed in future)
- Adds a BUG() check to catch attempts to initialize an unresolved "auto" filter
- Includes new unit tests in `u-list-objects-filter-options.c` to verify the parsing behavior

The implementation is careful to maintain existing behavior while adding the new capability, with explicit error handling and documentation of current limitations. Patrick Steinhardt has reviewed earlier versions of this patch, and this revision addresses his feedback about error message formatting and `allow_auto_filter` handling.

This is a foundational change that enables the dynamic filter combination functionality that will be wired up in subsequent patches in the series (particularly patch 8/8). The changes touch core filtering infrastructure in `list-objects-filter-options.[ch]` and `list-objects-filter.c`, with corresponding test coverage added through the new unit test file.
