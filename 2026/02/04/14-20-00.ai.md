This is part 8/11 of Derrick Stolee's `git config-batch` series, which aims to optimize configuration operations by batching them in a single process. The series primarily targets performance improvements for credential management workflows on Windows.

This patch prepares for future commands that will need the `prefix` parameter by passing it through the command processing infrastructure. The changes are mechanical but important plumbing work:

- Adds `prefix` to the `command_fn` function pointer type and all command implementations
- Updates both NUL-terminated and whitespace-based command processors to pass through the prefix
- Maintains existing behavior where current commands ignore the prefix (marked with `UNUSED`)
- Keeps the same error handling and response emission patterns

The patch is straightforward and well-contained, touching only `builtin/config-batch.c`. It follows the incremental approach seen throughout the series, where each patch adds clearly scoped functionality while maintaining protocol consistency. The changes are clearly motivated by upcoming commands that will need the prefix parameter, though those commands aren't shown in this patch.

This continues the series' pattern of building infrastructure in preparation for future commands while keeping each change small and reviewable. The patch maintains all existing test coverage and doesn't introduce new functionality, so it's unlikely to be controversial.
