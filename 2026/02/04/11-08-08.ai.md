This is part 3/8 of a series enhancing Git's promisor remote functionality, specifically a refactoring patch for the clone command. The change makes the `filter_options` variable local to `cmd_clone()` rather than being a static file-level variable, passing it explicitly to the `checkout()` function. This is a straightforward cleanup that improves code clarity by making the ownership and lifetime of the filter options more explicit.

The patch is a mechanical refactoring with no behavior change, preparing for subsequent work in the series that will use these filter options more extensively. It follows the pattern seen in patch 4/8 (which similarly refactors fetch.c) and has already been approved by Patrick Steinhardt in the v1 review. The change is small and focused - just moving the variable declaration and adding a parameter to one function call.

This continues the series' theme of improving filter handling infrastructure while maintaining backward compatibility. The patch demonstrates good hygiene by properly releasing the filter resources at the end of `cmd_clone()`. As with the rest of the series, the change is well-covered by existing tests.
