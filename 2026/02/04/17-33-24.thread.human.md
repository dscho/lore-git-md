This thread introduces a major new feature enabling parallel execution of Git hooks, building on Adrian Ratiu's earlier configurable hooks work. The v6 series (now 12 patches) establishes a comprehensive system for controlling hook parallelism through multiple configuration layers: a global `hook.jobs` default (with new support for `-1` to auto-detect CPU cores), per-hook `hook.<name>.parallel` flags, CLI `-j/--jobs` override, and per-event `hook.<event>.jobs` settings. The final patch adds the `-1` convention for automatic core detection, matching behavior in other Git commands like `fetch`.

Key technical details include special handling for the pre-push hook's output streams (parallel mode merges stdout into stderr while maintaining backwards compatibility in serial mode), marking seven hooks as non-parallelizable by default due to shared resources, and adding an `hook.<event>.enabled` master switch to disable all hooks for specific events. The implementation includes thorough test coverage of TTY behavior, output ordering, and precedence rules.

The series has received extensive review, with all core components receiving maintainer approval from Junio C Hamano. Notable contributions came from Patrick Steinhardt (suggesting type improvements and config warnings) and Emily Shaffer (signing off on the non-parallelizable hooks list). The v6 iteration fixed memory leaks, NULL dereferences, and documentation issues while rebasing on config-cleanups-v3. With this final patch adding core auto-detection, the series appears ready for merging.
