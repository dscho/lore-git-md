This is the final patch in a 9/9 series implementing promisor remote enhancements, specifically wiring up the `--filter=auto` functionality for dynamic filter combination. The patch follows up on Patrick Steinhardt's review feedback about two key design points.

First, Christian Couder clarifies that `--filter=auto` currently only considers server-advertised filters (for accepted promisor remotes) and does not incorporate locally configured filters, though he suggests this could be a future enhancement. Second, he notes that the `list_objects_filter_resolve_auto()` function Patrick questioned has already been removed in v2 of the series, addressing the error handling concern by using existing filter parsing infrastructure instead.

The patch builds on earlier work in the series that:
- Added `promisor.storeFields` config for secure remote field storage
- Refactored filter options handling in clone/fetch
- Implemented core auto-filter infrastructure with `LOFC_AUTO`
- Added server filter advertisement capture

Key files touched include `fetch-pack.c` and documentation. The implementation maintains security considerations around promisor remote configuration while enabling dynamic filter combination based on server capabilities. Patrick Steinhardt has provided thorough technical review throughout the series, with this final exchange resolving remaining questions about filter precedence and error handling approaches.
