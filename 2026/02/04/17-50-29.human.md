This is a technical clarification in the ongoing ODB abstraction effort, specifically addressing transaction handling in pluggable object database backends. Justin Tobler responds to Karthik Nayak's question about whether the single-transaction limitation is inherent or just an implementation detail of the current files backend.

Justin explains that the restriction exists at the Git process level for now, justified by two factors: current architecture only supports writing to one ODB source, and the files backend's reliance on the `tmp_objdir` subsystem which itself enforces single-writer semantics. This maintains the status quo while leaving room for future parallel transaction support if needed.

The exchange shows careful consideration of both current constraints and future extensibility, typical of the ODB abstraction work. Justin's response confirms the team is making deliberate choices about what to lock down now versus leave flexible for later, with clear technical rationale.
