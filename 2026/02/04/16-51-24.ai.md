This is the second patch in Adrian Ratiu's series to make Git hooks configurable, introducing a `git hook list` subcommand. The patch builds on the infrastructure from the first patch (which refactored hook execution to handle multiple hooks) by adding a way to inspect which hooks would run for a given event.

The new `git hook list <hook-name>` command outputs the paths of configured hooks in execution order, with special handling for hooks from the traditional hookdir (marked as "hook from hookdir"). The implementation exposes the previously internal `list_hooks()` function and adds corresponding documentation and tests. The command exits with status 1 if no hooks are configured.

This is a straightforward addition that serves both debugging purposes (verifying hook configuration) and user visibility (showing what will run). The patch carries Emily Shaffer's original sign-off from when this was part of her earlier hooks work, now rebased onto Adrian's modernized hook infrastructure. The implementation is cleanly separated from the not-yet-implemented config-based hooks, which will be added in later patches.
