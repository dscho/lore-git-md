This is patch 7/8 in a series enhancing Git's promisor remote functionality, focusing on storing advertised filters in memory to support the upcoming `--filter=auto` feature. The patch adds infrastructure to:

1. Store server-advertised filters in a new `advertised_filter` field in `struct promisor_remote`, persisting them beyond initial parsing (previously they were only kept temporarily or stored to disk with `promisor.storeFields`).

2. Introduce `promisor_remote_construct_filter()` which combines filters from all accepted promisor remotes into a single filter spec. This will be used by `--filter=auto` to dynamically construct filters based on server suggestions.

The implementation carefully handles memory management (freeing old filters, properly releasing resources) and includes validation to skip invalid filters with appropriate warnings. The patch builds on Patrick Steinhardt's prior review of the series and maintains the security-conscious approach established earlier patches.

Key files modified are `promisor-remote.[ch]`, adding 58 lines of new functionality. The changes are preparatory work for the final patch (8/8) that will wire up `--filter=auto` in clone/fetch operations.
