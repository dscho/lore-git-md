This is the third patch in Adrian Ratiu's series to make Git hooks configurable via Git configuration, building on prior work by Emily Shaffer. The patch introduces config-based hooks that can be specified alongside traditional filesystem hooks.

The key changes are:
- Adds `hook.<name>.command` and `hook.<name>.event` config options to define hooks in Git's config files
- Config hooks execute before traditional hookdir hooks, in the order they appear in config
- Supports both executable paths and inline shell one-liners for hook commands
- Maintains backward compatibility with existing hookdir hooks
- Includes extensive documentation and test coverage

The implementation parses config entries during hook execution, with config hooks taking precedence over hookdir hooks. The patch handles edge cases like:
- Multiple events per hook command
- Path resolution for configured hooks
- Input handling when multiple hooks consume stdin
- Error cases like missing command configurations

This builds on the infrastructure from earlier patches in the series (hook list management, execution ordering) while adding the config parsing layer. The tests verify both the new config-based hooks and their interaction with traditional hooks. Security implications around config parsing and execution order are noted as areas for review.

The patch carries Emily Shaffer's sign-off from prior related work and maintains her original design for config-based hooks while integrating it with Adrian's hook execution infrastructure.
