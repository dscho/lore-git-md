This is a feature patch enabling parallel execution of Git hooks, part of Adrian Ratiu's ongoing configurable hooks work. The patch allows multiple hooks for a single event to run concurrently by default, removing the hardcoded job limit of 1 in hook.c. The implementation provides several ways to control parallelism: compile-time serial execution (via RUN_HOOKS_OPT_INIT_SERIAL), runtime configuration (hook.jobs), or automatic CPU-based scaling.

The patch carefully handles output collation for parallel hooks to prevent interleaving, though it makes an exception for the pre-push hook which requires opt-in via extensions.hookStdoutToStderr due to its output sensitivity. The changes touch multiple builtin commands (am, checkout, clone, etc.) to update their hook calls, with thorough test coverage in t/t1800-hook.sh demonstrating both serial and parallel behavior.

The implementation appears well-considered, with clear priority rules for job count determination and proper TTY handling differences between serial and parallel modes. The patch builds on Emily Shaffer's earlier work and includes sign-offs from both Shaffer and Ævar Arnfjörð Bjarmason, suggesting it has already undergone some review. As part of a larger series introducing configurable hooks (not yet in master), this represents a significant step toward more flexible hook execution in Git.
