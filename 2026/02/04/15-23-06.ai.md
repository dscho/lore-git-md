Bugfix targeting GPG signature verification, specifically handling signatures from expired keys.

This patch changes Git's behavior to treat signatures made with valid keys that later expired as valid, rather than marking them as bad. The author argues this matches GnuPG's own behavior, which considers such signatures "Good" (with a note about the expiration) rather than warning about them like it does for untrusted signatures. The change involves modifying two checks in `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, and to recognize the 'Y' (expired key) result code alongside 'G' (good signature).

The patch cites a real-world example from the Linux kernel commit history and references a mail thread with Linus Torvalds discussing this behavior. The implementation is straightforward - just two small condition changes - but touches security-sensitive signature verification code. The change appears well-motivated by GnuPG's actual behavior and has a clear real-world use case, though it might warrant discussion about whether Git should be more strict than GnuPG about expired keys.
