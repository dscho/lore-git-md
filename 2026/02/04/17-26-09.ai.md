Security patch modifying GPG signature verification to better align with GnuPG's behavior regarding expired keys. This is a follow-up to Uwe Kleine-König's initial proposal, now being queued by Junio Hamano with minor formatting adjustments.

The change makes Git accept signatures from keys that were valid when created but later expired, matching GnuPG's behavior where such signatures are marked "Good" with an expiration note rather than "BAD". The patch modifies two key checks in `gpg-interface.c` to recognize both `GOODSIG` and `EXPKEYSIG` status lines from GnuPG, and to accept 'Y' (expired key) result codes alongside 'G' (good signature).

Junio indicates he will wrap an overlong line while applying the patch, suggesting this is likely to be included in an upcoming release. The change addresses a real-world pain point for projects like the Linux kernel that rely on commit signing, where Git's stricter behavior was causing valid signatures to be rejected. While the security implications of relaxing signature verification standards might normally warrant careful consideration, the alignment with GnuPG's behavior and support from Neal Walfield in the thread suggest this is a well-justified change.
