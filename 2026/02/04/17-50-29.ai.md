This is a technical clarification in the ongoing ODB transaction infrastructure thread, where Justin Tobler responds to Karthik Nayak's question about transaction concurrency limits. The exchange focuses on the current single-transaction-per-process constraint in the object database backend work.

Justin explains that the single-transaction limitation is currently tied to two factors: (1) Git's present architecture only supports writing objects to one ODB source at a time, making single transactions sufficient for now, and (2) the files backend's reliance on the `tmp_objdir` subsystem inherently restricts each process to one active transaction directory. This maintains consistency with the existing implementation while leaving room for future expansion if either of these constraints changes.

The response confirms the team's incremental approach - establishing working core infrastructure first while explicitly noting current limitations that may be addressed later.
