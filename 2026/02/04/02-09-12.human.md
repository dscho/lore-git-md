This is a documentation clarification thread about rename detection in `git format-patch`. Jeff King (Peff) confirms that `git format-patch` shares the `diff.renames` configuration with `git diff`, though this relationship isn't explicitly documented in the man page.

The thread was initiated by Chris Packham, who wants to disable rename detection specifically for patch generation (to ensure compatibility with basic `patch` utility) while keeping it enabled for interactive diff viewing. Peff explains there's currently no way to configure this behavior differently per-command - users must explicitly pass `--no-renames` or override the config at runtime.

Peff suggests that if someone wanted to implement per-command rename configuration, they could follow the pattern seen in other commands (like `merge.renames` and `status.renames`) by adding a `format.renames` option that falls back to `diff.renames`. However, this is presented as a hypothetical rather than a concrete proposal.

The exchange highlights a small but real documentation gap - the man page could be more explicit about which configuration option controls rename detection for `format-patch`. The discussion remains at an early stage with no patches proposed yet.
