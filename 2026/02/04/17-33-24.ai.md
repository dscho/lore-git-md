This is a feature patch series introducing parallel hook execution, building on Adrian Ratiu's earlier work to enable configurable hooks. The 4-patch series allows multiple hooks for a single event to run concurrently rather than sequentially, with special handling for the pre-push hook which requires opt-in due to output collation concerns.

The core change removes the hardcoded job limit of 1 in hook.c, enabling parallel execution by default for hooks known to be safe. The pre-push hook gets special treatment via a new `extensions.hookStdoutToStderr` config option that must be explicitly enabled to maintain backward compatibility guarantees when running in parallel. The series includes a new `repo_config_get_uint()` helper to support the configuration changes.

The implementation touches several builtin commands (am, checkout, clone, etc.) to update their hook calls, along with extensive test coverage in t/t1800-hook.sh. The changes are based on Adrian's prior configurable hooks work which hasn't yet landed in master, as noted in the cover letter. The series appears well-structured with clear commit messages and motivation, though the pre-push hook's special casing suggests this area may need further refinement based on list feedback.
