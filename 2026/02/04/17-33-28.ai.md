This is the final patch in Adrian Ratiu's series introducing parallel hook execution, building on his prior configurable hooks work. The patch adds runtime control over the `extensions.hookStdoutToStderr` behavior via a new `hook.forceStdoutToStderr` config option.

The key addition is a global configuration toggle that enables the stdout-to-stderr merging behavior for all hooks, including pre-push hooks that would otherwise require serial execution. This provides a migration path for users who want parallel execution without requiring repository format version bumps. The implementation handles both new repositories (via `git init`/`git clone`) and existing ones, with comprehensive test coverage verifying the behavior across initialization, cloning, and push operations.

The patch touches core repository setup code in `setup.c` to handle the version bump when enabling the extension, and modifies the hook execution logic in `hook.c` to respect the runtime override. Test cases demonstrate that parallel execution of pre-push hooks works as expected when the config is enabled, with proper output stream handling.

This completes the parallel hooks feature by addressing the last major usability hurdle - allowing administrators to opt into parallel execution globally while maintaining backward compatibility. The implementation carefully preserves the safety defaults (serial execution when output streams must remain separate) while providing an escape hatch for those who need the performance benefits.
