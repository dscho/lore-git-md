This is a preparatory patch for the parallel hook execution series, adding infrastructure to handle unsigned integer config values. Adrian Ratiu introduces a new `repo_config_get_uint()` helper and supporting functions to properly handle the upcoming `hook.jobs` configuration option, which will control how many hooks can run in parallel.

The patch adds the full stack of functions needed to parse and retrieve unsigned int values from Git config, mirroring the existing infrastructure for signed ints and unsigned longs. The implementation is straightforward and well-contained, touching config parsing and access layers while maintaining consistency with existing patterns. The commit message clearly explains why this helper is needed rather than reusing existing int/ulong variants.

This is a typical plumbing patch - not user-visible on its own, but providing necessary foundations for the feature work to follow. The changes are mechanical and unlikely to be controversial, though reviewers may scrutinize whether unsigned int is indeed the right choice over other numeric types.
