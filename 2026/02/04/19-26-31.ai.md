This is Junio Hamano's review of Johannes Schindelin's v4 patch series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). The series introduces configurable sanitization of control characters, with plans to make stricter defaults in Git 3.0.

Junio raises three key concerns: First, he criticizes the "default" configuration value that changes behavior across Git versions as poor design, suggesting users should explicitly choose their preferred mode. Second, he advocates for an incremental approach where the opt-in mechanism could be tested in production before flipping defaults. Most significantly, he questions the fundamental security model - rather than whitelisting "safe" sequences (like ANSI colors), he suggests blacklisting known-dangerous sequences while allowing others by default, arguing Git cannot anticipate all legitimate uses of control sequences.

The review highlights a tension between security and flexibility, with Junio emphasizing that some users may need non-color control characters (like ISO/IEC 2022 encoding sequences) for legitimate purposes. His comments suggest the current approach might force users into an all-or-nothing choice between security and functionality. The footnote about ISO/IEC 2022 underscores that encoding-related sequences - which the current implementation might block - are actually important in multilingual environments.

This review will likely require Schindelin to reconsider either the configuration design or the fundamental security model before the series can proceed. Junio's position as maintainer gives his concerns particular weight, especially regarding the version-crossing behavior and handling of legitimate non-color control sequences.
