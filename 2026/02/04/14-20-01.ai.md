Feature addition to the `git config-batch` builtin, adding a `set` command for batched configuration writes. This is patch 9/11 in Derrick Stolee's series to optimize credential manager operations by reducing process overhead.

The new `set` command allows writing single key-value pairs to specified config scopes (system/global/local/worktree), matching the behavior of `git config --set --<scope>`. It returns "success" or "failed" responses and supports both regular line-based and NUL-terminated formats. The implementation shares config location handling infrastructure with the existing `get` command and includes comprehensive tests covering:
- Basic set operations across all valid scopes
- Error cases for invalid scopes (submodule/command)
- Both regular and NUL-terminated formats
- Verification of actual config changes

Key technical details:
- Uses `repo_config_set_in_file_gently()` for the actual writes
- Adds `location_options_set_scope()` helper to config.c
- Extends protocol documentation with `set` command specs
- Updates help command to advertise the new capability
- Maintains consistency with the series' existing error handling and response formats

This continues the series' incremental approach, adding a core write operation while leaving more complex config modifications (multi-value sets, pattern matching) for future commands. The implementation appears thorough, with careful attention to edge cases and clear documentation.
