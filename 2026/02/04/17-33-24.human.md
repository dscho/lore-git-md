This is a feature patch series introducing parallel hook execution, building on Adrian Ratiu's ongoing work to make hooks configurable. The 4-patch series enables running multiple hook commands simultaneously for a single event (like pre-push), while maintaining backward compatibility for hooks that expect sequential execution.

The key changes allow:
1. Running multiple commands in parallel for a hook event (e.g. running linters and tests simultaneously on pre-push)
2. A new `extensions.hookStdoutToStderr` config to handle the pre-push hook's special output collation needs
3. A `repo_config_get_uint()` helper to read unsigned integer configs

The implementation is careful about backward compatibility - the pre-push hook gets special treatment since its output handling would break if run in parallel by default. The series includes thorough test coverage in t/t1800-hook.sh with 270 lines of new tests.

This appears to be a well-considered extension of the hook system, with clear motivation (performance for multi-hook workflows) and attention to edge cases. The patches build on Adrian's prior configurable hooks work that hasn't landed yet, so reviewers will want to consider both series together. The pre-push hook special case seems likely to generate discussion about whether the config knob is the right approach versus finding a more automatic solution.
