This is a feature patch series implementing two enhancements to Git's promisor remote functionality as part of the LOP (Large Object Promisors) effort. The series comes from Christian Couder and has undergone review from Patrick Steinhardt and Jean-Noël Avila.

The first part (patches 1-2) adds a `promisor.storeFields` config option that allows clients to securely store certain fields (like tokens) from server-advertised promisor remotes in their local config. This enables workflows where servers can rotate tokens and clients can automatically update them by fetching.

The second part (patches 3-8) introduces a `--filter=auto` mode for clone/fetch that dynamically combines filter specs from accepted promisor remotes. This allows clients to automatically use server-suggested filters while maintaining backward compatibility with existing partial clone behavior. The implementation includes refactoring filter handling in clone/fetch commands, adding auto-filter support to the filter options infrastructure, and wiring everything together.

The series shows careful attention to security constraints, backward compatibility, and robust error handling. Review feedback has been incorporated, including simplifying the filter combination logic and improving documentation. Test coverage appears thorough, with new unit tests for the filter options code and integration tests for the promisor remote functionality.

This represents a significant enhancement to Git's partial clone and promisor remote capabilities, enabling more dynamic and maintainable large-object workflows. The changes are well-considered and the implementation appears solid based on the review history.
