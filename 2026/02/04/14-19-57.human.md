Feature addition to the `git config-batch` RFC series, focused on NUL-terminated I/O support.

This fifth patch in Derrick Stolee's 11-part series adds a `-z` option to enable NUL-terminated input/output for the new `git config-batch` command. The primary motivation is handling configuration values containing spaces or newlines, which the current line-based protocol can't represent cleanly.

The implementation introduces:
- A new `-z` flag that switches between line-based and NUL-terminated modes
- Length-prefixed tokens in NUL mode (`<length>:<value>`) to support empty strings
- Double-NUL termination for clear command boundaries
- Comprehensive test coverage showing both simple and complex cases
- Helper methods to handle both formats without duplicating core logic

The patch maintains backward compatibility while adding the more robust format needed for credential manager use cases. It follows the series' pattern of careful, well-tested incremental additions - each commit builds on the last while keeping the protocol extensible. The documentation updates clearly explain both formats with examples.

This continues the series' focus on performance-sensitive credential management workflows, where reducing process overhead is critical. The implementation looks solid, with attention to edge cases and clear separation between format handling and command logic.
