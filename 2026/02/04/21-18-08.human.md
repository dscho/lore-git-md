Security patch addressing GPG signature verification behavior for expired keys, now being finalized for inclusion. This resolves a discrepancy where Git was marking signatures from keys that were valid when created but later expired as "BAD", while GnuPG considers them "Good" with an expiration note. The change aligns Git's behavior with GnuPG's, which is particularly important for projects like the Linux kernel that rely on commit signing.

The patch modifies `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` statuses from GnuPG, ensuring signatures remain valid even if the signing key later expires.
