This is the third patch in Adrian Ratiu's series to make Git hooks configurable via Git configuration. The patch introduces support for defining hooks through config entries like `hook.<name>.command` and `hook.<name>.event`, which can specify executable commands to run for given hook events.

The implementation allows multiple hooks to be configured per event, with execution order following config file parsing order. Config-based hooks run before traditional hookdir hooks, maintaining backward compatibility. The patch includes extensive documentation explaining the new config syntax and provides test coverage for various hook configuration scenarios.

Key technical aspects:
- Config hooks are discovered via a new `hook_config_lookup()` callback
- Hooks can be shared across multiple events by listing multiple `hook.<name>.event` values
- The implementation handles both filesystem paths and inline shell commands
- Test cases verify config ordering, multi-event hooks, stdin handling, and error cases

The patch builds on the infrastructure from earlier patches in the series (hook list management and the `git hook list` command) while introducing the config parsing logic. It carries Emily Shaffer's sign-off from prior related work, indicating this is a continuation of her original hooks configuration effort.

This represents a significant step toward the series' goal of making hooks more flexible and shareable across repositories while maintaining compatibility with existing hookdir-based setups. The implementation appears thorough, with careful attention to edge cases and user experience.
