This is the first patch in an 11-part series introducing a new `git config-batch` builtin, part of a feature proposal to optimize configuration operations by batching multiple queries/modifications in a single process. The series is an RFC from Derrick Stolee, primarily motivated by performance improvements for `git-credential-manager` on Windows where individual `git config` calls (150-200ms each) accumulate significant overhead.

This initial commit establishes the basic boilerplate for the new builtin, following Git's standard patterns for adding new commands. It includes:
- The minimal C implementation in `builtin/config-batch.c` with placeholder command handling
- Documentation stub in `Documentation/git-config-batch.adoc`
- Test scaffolding in `t/t1312-config-batch.sh` with a basic help text check
- Build system integrations (Makefile, meson.build)
- Command registration in `command-list.txt` and `git.c`

The patch also fixes an oversight in `builtin.h`'s instructions for adding new builtins by documenting the need to update meson.build files. This is purely mechanical infrastructure work - the actual functionality will be added in subsequent patches. The implementation shows careful attention to Git's contribution conventions, suggesting the author is familiar with the project's standards.

As the first in a series, this patch doesn't yet reveal the full design, but establishes the foundation for a new plumbing command focused on machine-parseable configuration access. The thread context indicates this will eventually support batching get/set/unset operations via stdin/stdout with versioned protocol support, addressing a specific performance pain point in credential management workflows.
