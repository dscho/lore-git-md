This is a build system patch completing Meson integration for Git's GUI components (gitk and git-gui). Patrick Steinhardt's v2 submission addresses feedback from the previous round by using symlinks rather than moving the projects into the subprojects/ directory, maintaining the original source layout while satisfying Meson's requirements.

The patch adds Meson build rules for both gitk and git-gui, introducing new options in meson_options.txt to control their compilation. It handles Tcl/Tk tool detection (tclsh and wish) with careful auto-disable behavior that matches the existing Makefile's logic - automatically skipping builds when dependencies are missing in "auto" mode while allowing explicit builds to fail if requirements aren't met. The implementation uses Meson's subproject() mechanism with symlinks to reference the GUI projects from their original locations.

Key technical aspects include the conditional build logic (disable_auto_if), the symlink-based subproject integration, and the build summary reporting. The patch follows the pattern established in earlier Meson integration work while resolving the directory structure concerns raised in v1. This represents the final major component needed for feature parity between Meson and Makefile builds, though as noted in the thread, some practical issues like libexecdir handling and shell quoting remain to be addressed before full production readiness.

The architectural discussion about whether Git should adapt its source structure to Meson's requirements continues in parallel, with Junio Hamano expressing reservations about build systems dictating source organization. However, this patch takes a pragmatic approach that preserves both the original source layout and Meson compatibility through symlinks.
