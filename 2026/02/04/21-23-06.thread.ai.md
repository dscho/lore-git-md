Thread identity: Bugfix for whitespace handling of symbolic links in diff/apply machinery, addressing incorrect triggering of incomplete-line checks (WS_INCOMPLETE_LINE) on symlinks where such endings are normal. Patch from maintainer Junio C Hamano, with technical review from Patrick Steinhardt.

Core problem: Recent whitespace checking improvements introduced incorrect behavior for symbolic links by applying WS_INCOMPLETE_LINE checks (which verify files end with newlines) to symlinks, where such endings are not required. Needs special-casing in diff/apply code paths, with additional consideration for mode-change cases.

Current status: Single patch version addressing the core issue by modifying both `apply.c` and `diff.c` to disable WS_INCOMPLETE_LINE checks for symbolic links. Patrick Steinhardt has identified an edge case where the current implementation would incorrectly skip checks during file-to-symlink mode changes.

Key technical details:
- Changes in `apply.c` and `diff.c` to skip WS_INCOMPLETE_LINE checks for symlinks
- Current implementation would disable checks if either side of diff is symlink
- Review suggests more precise conditions needed: only disable when one side missing and other is symlink, or both sides are symlinks
- New test cases in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh`
- Theoretical question raised (but not emphasized) about newline-terminated symlink targets

Open questions:
- Need to refine symlink detection logic to properly handle mode-change cases
- Whether to explicitly support newline-terminated symlinks (low priority)

Participant positions:
