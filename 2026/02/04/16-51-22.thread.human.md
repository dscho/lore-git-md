Adrian Ratiu's config-based hooks series (v3) continues to refine the implementation of configuration-based Git hooks, with the latest discussion focusing on how disabled hooks should be handled. The series introduces `hook.<name>.command`, `hook.<name>.event`, and `hook.<name>.enabled` configuration options while maintaining backward compatibility with filesystem hooks, along with a new `git hook list` subcommand.

Junio Hamano and Patrick Steinhardt have been actively reviewing the series, with both agreeing that the current focus should be on storing enabled state directly in the `struct hook` while deferring UI features like a `--disabled` flag for `git hook list`. Junio noted that showing disabled hooks in the listing would be useful for discoverability, though this would require changes to the current early-filtering approach. The exchange confirms the technical direction is settled, with the remaining work being final polishing of the implementation.

The series has maintainer approval for both its architecture and specific implementation choices, including the refactored hook callback data management and two-phase config parsing. All patches are complete at v3, with Adrian incorporating reviewer feedback on API documentation, error handling, and code organization. The prerequisite hooks-conversion series is expected to land in 'next' soon, positioning this work for integration after final reviews.
