Adrian Ratiu's config-based hooks series continues to progress, now at version 4 with 12 patches. The series introduces configuration-based hooks that can be defined in git config files while maintaining compatibility with traditional filesystem hooks. 

The latest patch (11/12) adds a `--show-scope` option to `git hook list`, showing whether each hook was defined in the local repository config, global config, or system config. This builds on the series' existing config parsing infrastructure and maintains backward compatibility - filesystem hooks remain unchanged and don't show scope information since they don't come from config files.

Key reviewers Junio Hamano and Patrick Steinhardt have been actively engaged. Junio suggested the scope visibility feature and has approved the core approach, while Patrick has provided detailed technical reviews throughout. The series has addressed all major technical concerns and is now in its final polishing phase, with just one patch remaining after this one.

The implementation carefully maintains the separation between config-based hooks (which can run outside repositories) and filesystem hooks (which still require a repository context). Test coverage in t1800-hook.sh has been expanded to verify the new scope display functionality while ensuring existing behavior remains unchanged when the flag isn't used.

With the core functionality complete and review feedback incorporated, the series appears ready for merging once the final documentation updates and API consolidation are completed in the remaining patch.
