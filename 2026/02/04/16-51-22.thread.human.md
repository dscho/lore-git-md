Adrian Ratiu's config-based hooks series has reached completion with the 12th and final patch. The series implements configuration-based hooks through `hook.<name>.*` settings while maintaining compatibility with traditional filesystem hooks. The key innovation is that config-based hooks can now run outside repository contexts, unlike filesystem hooks which remain repository-bound.

The final patch adds visibility for disabled hooks in `git hook list` output, showing them with a "(disabled)" annotation while still skipping them during execution. This builds on the series' earlier work that introduced config parsing, out-of-repo execution support, NUL-terminated output options, and scope tracking for hook definitions. Throughout the series, careful attention was paid to cache management and maintaining clean separation between config-based and filesystem hooks.

Junio Hamano has approved the approach, with Patrick Steinhardt providing detailed technical feedback that shaped several features including the event clearing behavior and `-z` output option. The series is now rebased on 'next' and ready for merging, having addressed all major technical concerns. While some documentation polish remains, the core functionality is complete - giving users flexible hook configuration while preserving backward compatibility with existing setups.
