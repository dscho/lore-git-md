Adrian Ratiu continues to refine his series making Git hooks configurable via Git configuration, building on Emily Shaffer's earlier work. The latest addition enables hooks to run outside a repository when defined in global/system configs, while still requiring a repository for traditional filesystem-based hooks. This addresses use cases like `sendemail-validate` hooks when emailing from arbitrary directories.

The series now includes:
1. Core infrastructure for config-based hooks
2. A `git hook list` subcommand showing configured execution order
3. Support for multiple config-based hooks per event
4. This new out-of-repo execution capability

The implementation remains focused and backward-compatible, with comprehensive test coverage. Reviewers have been examining security implications, particularly around config parsing and execution order. The changes appear well-contained, with the latest patch requiring just a single-line modification to enable the new behavior while maintaining safety. The series continues to carry Emily Shaffer's sign-off from the foundational work it builds upon.
