This is a bugfix patch finalizing changes to GPG signature verification behavior, now being integrated by Junio Hamano. The patch aligns Git's handling of signatures from expired keys with GnuPG's more permissive approach, where signatures created while a key was valid remain valid even after key expiration.

The technical changes modify two checks in `gpg-interface.c`: first accepting both `GOODSIG` and `EXPKEYSIG` status lines from GnuPG output, then recognizing the 'Y' (expired key) result code alongside 'G' (good signature). This resolves a practical issue affecting projects like the Linux kernel that rely on commit signing, where Git previously rejected signatures that GnuPG considered valid.

Junio confirms the patch is ready for integration with only formatting adjustments needed (wrapping an overlong line), indicating no need for the author to resend. The thread shows consensus that this change better matches ideal behavior, with no opposition raised during discussion. The security implications were deemed acceptable during initial review since the modification brings Git's behavior in line with GnuPG's established practice.
