This is a bugfix discussion about pathspec handling in `git add` and `git stash` when using excluded pathspecs (`:!path`). The thread has evolved from fixing a specific inconsistency to debating deeper pathspec semantics.

Tian Yuchen responds to Junio C Hamano's question about whether negated pathspecs should be passive (just skipping matches) or active (requiring paths to match no excluded patterns). The current patch makes excluded pathspecs passive, but Junio suggests this might not be the right approach for cases like `git add x :!x` where the behavior should likely be a silent no-op.

Yuchen provides a clear example showing how the current patch would incorrectly complain about ignored files in some cases, and proposes a two-step solution that would first check for positive matches and then verify no negative matches. They also suggest adding test cases for edge conditions.

The discussion reveals this touches fundamental pathspec behavior that has been ambiguous for years. While the original patch fixed a clear documentation inconsistency, the thread now faces a more complex design question about how positive and negative pathspecs should interact - a question that may require broader consensus among pathspec experts.
