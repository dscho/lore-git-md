Feature patch introducing a new extension for hook output handling, part of Adrian Ratiu's parallel hooks series. This third patch in the 4-part series adds `extensions.hookStdoutToStderr` to standardize hook output behavior, particularly addressing the special case of `pre-push` hooks which currently maintain separate stdout/stderr streams (used by git-lfs). The change allows parallel execution of hooks while preserving output integrity by either merging streams (when enabled) or falling back to serial execution (when disabled).

The implementation adds repository format fields and config options, with test coverage verifying the new behavior. The patch maintains backward compatibility by defaulting to serial execution for `pre-push` when the extension is disabled, preventing output interleaving. The documentation explains the interaction with `hook.jobs` configuration and the safety implications.

Technical changes include new fields in `struct repository_format`, config parsing updates, and modifications to `transport.c`'s hook handling. The test suite gains new cases verifying the extension's effect on output streams and parallel execution behavior. This builds on the parallel hooks infrastructure from earlier in the series while addressing a real-world compatibility concern with git-lfs.
