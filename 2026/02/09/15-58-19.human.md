This is part of a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories, primarily for GitLab's use case. The series is in its final polishing phase with only minor documentation tweaks remaining.

Patch 2/4 introduces the plumbing to handle reference storage payloads, which will be used to specify alternate reference locations via a URI format. The key changes are:

1. Adds a new `refs_compute_filesystem_location()` function that calculates reference directory paths based on the gitdir and an optional payload (future URI). This handles both main and worktree cases.

2. Modifies the files and reftable backends to accept and use the payload parameter in their initialization, though the packed backend ignores it for now.

3. Updates path resolution to properly handle relative and absolute paths in the payload, with realpath() normalization.

The patch is well-structured and clearly part of a larger, carefully planned effort. It has already gone through multiple rounds of review, with all substantive feedback addressed. The changes are focused and maintain backward compatibility while laying groundwork for the URI-based configuration coming in later patches.
