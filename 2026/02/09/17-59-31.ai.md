This is a maintainer response in the ongoing discussion about supporting UTF-8 characters in Git alias names. Junio C Hamano weighs in on the technical approach, expressing clear preference for Jeff King's proposed subsection-based solution (`alias.*.{keyname}`) over direct UTF-8 handling in the config parser.

The key points are:
1. Junio confirms that macOS's existing `precompose_argv_prefix()` would handle Unicode normalization automatically if the subsection approach is used, avoiding the need for Git to implement its own Unicode handling
2. He sees the subsection syntax as "independently a good thing to do" beyond just solving the UTF-8 problem
3. This approach would completely sidestep the normalization complexities that Theodore Tso and others raised security concerns about

The email suggests the maintainer is leaning toward accepting the subsection solution, which aligns with Jonatan Holmgren's growing preference for this more maintainable path. This moves the thread closer to resolution, with the main outstanding question being whether to formally deprecate the old alias syntax or maintain both forms indefinitely. The response also implicitly validates Jeff King's original proposal as architecturally sound from the maintainer's perspective.
