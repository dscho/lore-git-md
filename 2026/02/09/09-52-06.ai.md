This is a status update on Adrian Ratiu's hook API refactoring series, which aims to standardize how Git invokes hooks by replacing ad-hoc `run_command()` calls with a dedicated hook API. The 12-patch series (currently on Junio's 'seen' branch) converts several hook types including receive-pack`, `update`, `pre-push`, and `post-rewrite` to use the new API, while adding parallel execution capabilities and improved stream handling.

The email notes this work is foundational for two other in-progress series from Adrian: `ar/config-hooks` (allowing hooks to be specified via config) and `ar/parallel-hooks` (enabling concurrent hook execution). With no objections raised since the initial submission in January 2026, Adrian suggests merging the base series to unblock dependent work. The changes appear well-tested, with explicit test coverage added in `t1800` for hook output streams.

This represents a significant step in modernizing Git's hook infrastructure, moving away from direct shell command execution toward a more structured API that supports future features like configurable hooks and parallel processing. The lack of discussion since v2 submission suggests the technical approach has stabilized, though Junio may want explicit acks from affected subsystem maintainers before promoting to 'next'.
