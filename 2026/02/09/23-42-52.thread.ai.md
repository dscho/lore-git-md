Thread summary:

Bug report and documentation clarification regarding `git send-email` recipient suppression options. Jim Cromie initially reported confusion around `--suppress-to`, `--suppress-cc`, `--no-to`, and `--no-cc` options, believing they should suppress all recipient sources including patch file headers. Junio C Hamano clarified the actual behavior: `--suppress-to` is invalid (despite appearing in some documentation), while `--no-to`/`--no-cc` only suppress addresses from command-line arguments and configuration, not patch files.

Jim Cromie followed up confirming Junio's explanation and identifying a documentation issue - the man page's description of `--no-to`/`--no-cc` as clearing addresses "previously set via config" is ambiguous. He suggests "options" would be clearer than "config" to properly indicate these flags affect both command-line and configured addresses. 

Key technical details established:
- `send-email` has no `--suppress-to` flag (documentation error)
- `--no-to`/`--no-cc` only suppress command-line/configuration addresses
- Patch file recipients are always included unless manually edited

Open documentation issue:
- Man page should clarify `--no-to`/`--no-cc` scope using "options" instead of "config"

The thread has clarified the current behavior is intentional but identified a documentation improvement opportunity. No code changes are proposed - the remaining action would be a documentation patch to improve clarity around the suppression options' limited scope.
