This is part of Adrian Ratiu's ongoing series to make Git hooks configurable via Git configuration, now at v4. The patch focuses on implementing config-based hooks through new `hook.<name>.command` and `hook.<name>.event` configuration options.

Key technical changes in this iteration:
- Introduces config parsing for hook commands and events, with the config format documented in a new `Documentation/config/hook.adoc`
- Maintains backward compatibility by combining config-based hooks with traditional filesystem hooks in execution order
- Uses a two-pass approach (currently) where event names are gathered first, then commands are looked up during execution

Patrick Steinhardt's review highlights several areas for improvement in the next version:
1. Config parsing efficiency - suggests caching hook config in the repository object to avoid repeated parsing
2. Documentation clarity - needs to explain multi-event syntax and reset behavior for multivalue keys
3. Additional features - proposes adding `hook.<name>.enabled` to globally disable hooks
4. Implementation details - notes the current separation between event lookup and command execution is suboptimal

Adrian confirms he will address these in v2, including:
- Support for resetting multivalue event keys with "event = "
- Modern `git config set` syntax in examples
- Consolidating config parsing into a single pass
- Considering (but questioning the value of) repository-level caching

The patch touches core hook infrastructure in `hook.c` while maintaining the existing filesystem hook compatibility. Test coverage appears thorough but will expand further in v2 to cover the new config behaviors. The discussion remains focused on implementation quality rather than fundamental design disagreements.
