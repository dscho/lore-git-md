Maintainer response to branch listing inconsistency discussion.

Junio C Hamano weighs in on the thread about inconsistent branch listing behavior in new repositories, agreeing with Ben Knoble's suggestion to use `init.defaultBranch` configuration as a solution. He frames this as a way to "live in the future" ahead of Git 3.0's planned change to default to "main" instead of "master". 

The response doesn't directly address the core UX issue raised in the original report - the mismatch between `git status` showing the unborn branch name while `git branch` shows nothing. Instead, Junio focuses on the configuration workaround, suggesting users set `init.defaultBranch` globally to avoid the "master" naming entirely. 

This maintains the status quo behavior where unborn branches remain invisible in `git branch` output, while implicitly acknowledging the broader context of moving away from "master" as the default branch name. The tone suggests Junio considers this sufficient resolution rather than requiring deeper changes to branch listing behavior. No indication is given whether the underlying inconsistency might be addressed in future versions beyond the default name change.
