This is a discussion about Git's branch listing behavior in new repositories, following up on a bug report about inconsistent UX around default branch naming.

Ben Knoble responds to Ryan Johnson's report about `git branch` showing no output in a newly initialized repository, while `git status` correctly shows "On branch master". Ben notes this is technically an "unborn" or "orphan" branch state (referencing `git switch` documentation) but doesn't directly address the UX inconsistency. He points Ryan toward `init.defaultBranch` configuration and mentions the planned breaking change in Git 3.0 that will make "main" the default branch name.

The technical impact would involve modifying `builtin/branch.c` to show the promised default branch name consistently with `git status`. The discussion highlights a real usability issue for users trying to follow modern branch naming conventions, where the current behavior makes it unnecessarily difficult to see and rename the default branch before first commit. No patches have been proposed yet - this remains at the discussion stage.
