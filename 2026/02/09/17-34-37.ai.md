Documentation patch completing a series about `git am` hooks and option documentation. This is the fourth and final patch in Kristoffer Haugsbakk's series improving `git-am` documentation, following three earlier patches that standardized command references, clarified trailer behavior, and documented the `am.messageId` config option.

The patch makes two main changes to the `git-am` man page. First, it adds the positive `--verify` option to the synopsis (previously only `--no-verify` was shown) and rewords the option description to lead with the default behavior rather than the negation. This brings consistency with other command documentation and accounts for use cases where someone might want to explicitly enable hooks after they've been disabled (e.g., in a Git alias). Second, it adds a cross-reference to these options in the "Hooks" section and notes that `post-applypatch` cannot be skipped, which was previously undocumented.

The changes follow established documentation patterns, referencing prior work on synopsis style (acffc5e9) and linking to `githooks(5)` for context. The author notes this doesn't require updating `builtin/am.c` because the help text mismatch is already excluded in the test suite.
