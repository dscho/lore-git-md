This is a technical discussion about extending Git's alias system to support non-ASCII characters, building on Jonatan Holmgren's RFC proposal. Jeff King (Peff) responds with a more comprehensive approach than the original UTF-8-specific suggestion.

Peff identifies the root issue as Git's config key syntax being poorly matched to command naming needs, noting this affects both aliases and pager configurations. Rather than special-casing UTF-8 in alias keys, he proposes a structural change: using the config file's subsection syntax (like `[alias "foo"] command = bar`) to handle arbitrary command names verbatim, avoiding normalization and case-folding complexities. This approach would:
- Support any command name as a byte stream
- Maintain backward compatibility with existing `alias.foo` syntax
- Potentially enable future extensions like help text for aliases
- Apply similarly to pager configurations

The response includes a proof-of-concept patch showing how the alias lookup could be modified to handle both old and new syntax. Peff notes this would resolve not just the immediate UTF-8 request but also longstanding issues with characters like underscores in aliases. The proposal represents a more fundamental solution than the original RFC, though it would require more extensive changes to Git's config handling.
