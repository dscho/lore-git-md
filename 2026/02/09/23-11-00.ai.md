Documentation patch addressing `git am` security vulnerability in patch parsing. This is Kristoffer Haugsbakk's updated version of the warning text for `format-patch-caveats.adoc`, incorporating feedback from Junio Hamano and Phillip Wood. The patch has been queued by Junio after review.

The documentation now clearly warns about the risks when roundtripping patches through `git format-patch` and `git am`, particularly when commit messages contain unindented diffs or separator lines that the parser may misinterpret. The text avoids the potentially confusing "inline" adjective (per Junio's suggestion) and focuses on the concrete hazards: commit message alteration, incorrect patch application, and outright failure. It references the specific termination patterns (three-dash lines, "diff -" lines, "Index:" lines) that can trigger these issues.

The patch is part of a layered solution to the long-standing security vulnerability where tools like `git am` and `patch(1)` can misinterpret embedded diffs in commit messages. This issue particularly affects distribution workflows that apply patches in bulk. The documentation complements Phillip Wood's security-focused `commit-msg` hook enhancements and Patrick Steinhardt's proposed `--accept-ambiguous-patch` flag for `git am`.

The warning will appear in multiple man pages (`git-am`, `git-format-patch`, and `git-send-email`) via a shared include file, ensuring consistent messaging across the documentation. The text maintains technical precision while improving clarity, as evidenced by Junio's approval of the queued version. This represents the documentation component of the broader effort to address patch parsing ambiguities that have caused real-world incidents like the Debian `sleep(1)` vulnerability.
