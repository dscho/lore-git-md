Karthik explains that the current implementation accounts for cases where the worktree might be NULL, which complicates the parameter passing.

This exchange highlights a deeper architectural question about how worktrees and repositories interact in Git's codebase. The discussion suggests that a more fundamental redesign of the worktree API might be needed to properly handle NULL worktrees and repository associations, rather than just mechanically adding repository parameters everywhere.

The thread shows how what started as a straightforward global variable removal has uncovered a design issue that affects multiple subsystems. The resolution will likely require careful consideration of backward compatibility and the broader implications for Git's worktree handling.
