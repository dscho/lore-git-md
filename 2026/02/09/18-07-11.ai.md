CI/build system patch in an ongoing series about test execution consistency.

Justin Tobler replies to Patrick Steinhardt's second patch in a 5-part series improving CI test slicing behavior. The patch reframes test slicing parameters from "offset/stride" to "slice number/total slices" with one-based indexing, fixing an issue where GitLab CI was skipping the smallest test due to parameter confusion. The changes include:

- Converting GitHub Actions to use one-based indexing (matching GitLab CI)
- Adding validation that slice numbers are within bounds (1 <= slice <= total)
- Maintaining the same test distribution logic but with clearer parameter semantics

Justin confirms the changes look correct, noting the surprising behavior of the original offset/stride approach where invalid inputs were silently accepted. The patch touches both CI configuration (.github/workflows/main.yml) and test infrastructure (t/helper/test-path-utils.c), continuing the series' methodical approach to standardizing test execution across platforms.
