This is the final patch in a series implementing reference backend selection for zero-downtime migrations between files and reftable backends. The patch adds environment variable support to complement the existing config-based approach.

The key addition is the `GIT_REFERENCE_BACKEND` environment variable, which follows the same URI format (`<backend>://<path>`) as the `extensions.refStorage` config option but takes precedence when both are set. This allows temporary backend overrides for individual commands without modifying repository configuration. The implementation hooks into repository setup to parse the environment variable early, validating the backend format and path before initializing the repository.

The patch includes comprehensive test updates in t1423-ref-backend.sh that verify:
- Environment variable precedence over config
- Consistent behavior with config-based backend selection
- Proper error handling for invalid URIs
- Worktree integration
- Cross-backend migration scenarios

This completes the series' goal of enabling runtime reference backend switching, with both persistent (config) and ephemeral (environment) control methods. The implementation maintains backward compatibility while providing the flexibility needed for large-scale repository migrations. With Junio Hamano's earlier approval signaling the design is sound, this final patch addresses the last documentation and testing requirements before potential integration.
