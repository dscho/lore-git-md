Here's the updated human-readable thread summary:

Ryan Johnson reported a confusing inconsistency in Git's branch listing behavior. When creating a new repository, `git status` shows "On branch master" while `git branch` displays nothing until the first commit is made. This makes it difficult for users to rename the default branch from "master" to "main" before their first commit, as they can't see what branch they're on through the branch listing command.

Ben Knoble responded by explaining the technical background - this is an "unborn" or "orphan" branch state - but didn't directly address the UX inconsistency Ryan highlighted. Ben did point to the `init.defaultBranch` configuration and noted that Git 3.0 will change the default branch name to "main", though this doesn't solve the immediate visibility issue.

The core problem remains: there's a mismatch between how Git shows the promised default branch name in different commands, creating confusion for users trying to follow current best practices around branch naming. The discussion suggests modifying `builtin/branch.c` to make the default branch visible consistently, but no concrete patches have been proposed yet. This appears to be a genuine usability issue that could be addressed with relatively straightforward changes to the branch listing behavior in new repositories.
