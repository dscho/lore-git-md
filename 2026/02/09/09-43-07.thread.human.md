The thread discusses a user experience issue where new Git repositories show inconsistent behavior in branch listing. Ryan Johnson created a new repository and found that while `git status` correctly shows "On branch master" (or whatever default branch name is configured), `git branch` shows no output until the first commit is made. This creates confusion for users trying to rename their default branch before making any commits.

Ben Knoble initially responded by pointing to the `init.defaultBranch` configuration and noting Git 3.0's planned change to default to "main" instead of "master". Now maintainer Junio C Hamano has weighed in, agreeing with Ben's suggestion to use `init.defaultBranch` as a solution. Junio frames this as a way to "live in the future" ahead of Git 3.0's changes.

While this provides a workaround, it doesn't directly address the core inconsistency between `git status` and `git branch` behavior that Ryan originally reported. The discussion currently suggests configuring the desired default branch name rather than changing how Git plumbing commands display unborn branches. There's no indication yet whether the underlying behavior might be changed in future versions, though the maintainer's response implies this may be considered sufficient resolution for now.
