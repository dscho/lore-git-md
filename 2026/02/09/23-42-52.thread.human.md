This thread clarified a point of confusion around `git send-email`'s recipient suppression options. Jim Cromie initially reported unexpected behavior with flags like `--suppress-to` (which doesn't actually exist) and `--no-to`/`--no-cc` (which don't affect recipients listed in patch files). Maintainer Junio C Hamano confirmed the current implementation intentionally only suppresses addresses from command-line arguments and configuration, not those parsed from patches.

In a follow-up, Jim acknowledged the explanation and identified a documentation improvement opportunity - suggesting the man page should clarify that `--no-to`/`--no-cc` affect "options" rather than just "config" to better reflect their scope. While the thread hasn't produced code changes, it has resolved the original confusion and identified a small but useful documentation tweak to prevent similar misunderstandings. The behavior remains unchanged - patch file recipients must still be manually edited if suppression is desired.
