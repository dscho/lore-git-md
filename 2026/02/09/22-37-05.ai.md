This is a documentation patch adding warnings about patch roundtrip hazards in `git format-patch` and `git am`. The patch has been queued by Junio after incorporating feedback from Phillip Wood.

The documentation now clearly explains how certain delimiters in commit messages (three-dash lines, "diff -" lines, and "Index:" lines) can prematurely terminate the commit message when roundtripping through `format-patch` and `am`. It specifically highlights the danger of unindented diffs in commit messages, which may get incorrectly applied along with the intended patch. The warnings appear in multiple man pages (`git-am`, `git-format-patch`, and `git-send-email`) via a shared include file.

Key technical details include the three trigger patterns that terminate commit message parsing, the particular risk to distribution workflows that apply patches in bulk, and the limitations of using `patch(1)` as an alternative. The documentation maintains backward compatibility while making the hazards explicit, addressing concerns raised in prior discussions about legitimate uses of separator lines.

The patch represents one layer of the multi-pronged approach to this security issue, complementing Phillip Wood's proposed commit-msg hook changes and Patrick Steinhardt's work on an `--accept-ambiguous-patch` flag. The documentation improvements are particularly important given that even experienced users (like distribution maintainers) may not recognize these parsing hazards.
