This is a patch in Adrian Ratiu's ongoing series to make Git hooks configurable via Git configuration. The current patch refactors hook execution infrastructure to support multiple hook sources, preparing for config-based hooks while maintaining backward compatibility with filesystem hooks.

The patch introduces a `list_hooks()` function that will eventually consolidate hooks from both config and filesystem sources, though currently only handles filesystem hooks (identified by empty strings as a temporary convention). It modifies the hook execution flow to iterate through a list of hooks rather than running a single hook. The changes span `hook.[ch]`, `receive-pack.c`, and `transport.c`, with comprehensive tests in `t/t1800-hook-config.sh`.

Patrick Steinhardt's review identifies several areas for improvement in the next version: better commit message structure, replacing string-based hook identification with explicit types (as Junio Hamano suggested), optimizing memory management by using indices instead of direct pointer arithmetic, and reconsidering the error message differentiation between hook types. He also questions whether the `r->gitdir` check is necessary and suggests splitting the patch into two for clearer review: one for the copy/free callback infrastructure and another for the hook list changes.

The discussion remains technical and constructive, with Adrian acknowledging the feedback and planning to address it in v2. The patch represents incremental progress toward the larger goal of configurable hooks while maintaining the existing hook execution behavior. Reviewers are focusing on implementation quality through better typing, memory management, and test coverage.
