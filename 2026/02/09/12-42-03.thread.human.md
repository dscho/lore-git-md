This thread addresses test failures that occur on Windows/MSVC platforms when Git is built with ICONV support (using libiconv) but the `iconv(1)` executable isn't available. Patrick Steinhardt has led the effort through three versions of a five-patch series that carefully distinguishes between libiconv (a runtime dependency) and the `iconv(1)` executable (used in test scripts).

The series modifies several test files (t6006, t4205, t4041, t4059, t4060, and t5550) to conditionally use `iconv(1)` only when available, with UTF-8 encoding as a fallback. Key improvements include prerequisite check refinements, test_grep usage, and preserving encoding-specific tests where possible. Torsten Bögershausen provided important Windows-specific details about MinGW no longer shipping `iconv(1)`, while Junio Hamano initially suggested skipping tests but ultimately agreed with the implemented solution.

After thorough review, Christian Couder has given final approval to the series, noting the improved organization in v3 where ICONV prerequisite changes were separated into their own commit. While there's a remaining NEEDSWORK note about potentially splitting ICONV prerequisite checks, the immediate issue is fully resolved. The series now appears ready for maintainer pickup, marking a significant improvement in test reliability for Windows/MSVC environments and closing GitHub issue #6083.
