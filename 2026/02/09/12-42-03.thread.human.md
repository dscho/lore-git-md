This thread addresses test failures on Windows/MSVC platforms when Git is built with ICONV support but the `iconv(1)` executable isn't available. Patrick Steinhardt has led the effort to modify test scripts to properly handle this scenario, distinguishing between libiconv (linked into Git) and the `iconv(1)` executable (used in scripts).

The discussion has clarified several technical points, including Windows-specific behavior where MinGW no longer ships the `iconv(1)` binary, and the test strategy of falling back to default UTF-8 encoding when ICONV isn't available. All review feedback from Junio Hamano, Torsten Bögershausen, and Christian Couder has been incorporated, including adding a reference to GitHub issue #6083 about `iconv(1)` in Git for Windows.

The only remaining loose end is documenting the relationship between the build-time `NO_ICONV` flag and test-time `ICONV` prerequisite, which Patrick plans to address separately. The series now in its final form and ready for merging, marking another step in improving CI/test infrastructure for Windows/MSVC platforms. Torsten Bögershausen raised the question of whether Git for Windows should restore the `iconv(1)` binary, but this isn't blocking the current changes.
