This thread covers Patrick Steinhardt's series addressing test failures that occur on Windows/MSVC platforms when Git is built with ICONV support but the `iconv(1)` executable isn't available. The core issue stems from the distinction between libiconv (linked into Git) and the `iconv(1)` executable (used in test scripts), particularly relevant since MinGW no longer ships the `iconv(1)` executable.

The five-patch series has gone through three iterations, with the final version receiving approval from Christian Couder. The patches systematically update affected test scripts (t6006, t4205, t4041, t4059, t4060, and t5550) to conditionally use `iconv(1)` only when available, falling back to UTF-8 encoding otherwise. The v3 improvements included better separation of ICONV prerequisite changes into their own commit.

Junio Hamano reviewed the final patch focusing on t6006-rev-list-format.sh, noting the clever handling of encoding fallbacks while maintaining test validity. Though he observed a minor oddity in still labeling files as ISO8859-1 when they might contain UTF-8, he confirmed this doesn't affect the tests' correctness. With all feedback addressed through three versions and Christian Couder's approval, the series is now ready for merging, providing a complete solution for Windows/MSVC test environments while preserving test coverage. The thread leaves open some future considerations about splitting ICONV prerequisite checks and behavior of `i18n.commitEncoding` without full ICONV support.
