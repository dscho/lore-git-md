This thread continues the discussion about how to handle encoding-related test failures on Windows when Git is built with ICONV support but the `iconv(1)` executable is unavailable. The core disagreement remains between two approaches: Junio Hamano advocates skipping encoding tests entirely when ICONV support is missing, while Patrick Steinhardt's patch series modifies test expectations to work around the missing binary while maintaining test coverage.

Patrick's latest response clarifies that his approach defaults tests to UTF-8 encoding (which should be a no-op without ICONV) while still allowing the ICONV-specific cases to be tested when available. He acknowledges Torsten Bögershausen's point about the platform-specific situation where Windows systems may have libiconv linked into Git but lack the separate `iconv(1)` executable that test scripts rely on. While Patrick agrees the current solution involves some duplicated logic across test files, he prioritizes fixing the immediate CI failures over architectural cleanup.

The discussion has expanded to consider whether Git for Windows should simply restore the `iconv(1)` binary (as suggested in GitHub issue #6083) rather than modifying test expectations. This would be a more direct solution but involves platform-specific packaging decisions. For now, the thread remains unresolved, with the test strategy debate continuing alongside these platform considerations. The key participants remain Patrick (driving the patches), Junio (maintainer perspective), and Torsten (Windows-specific expertise).
