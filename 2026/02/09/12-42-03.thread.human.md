This thread addresses test failures that occur on Windows/MSVC platforms when Git is built with ICONV support (using libiconv) but the `iconv(1)` executable isn't available. Patrick Steinhardt has led the effort to properly distinguish between libiconv (a runtime dependency linked into Git) and the `iconv(1)` executable (a test tool dependency), particularly important since Git for Windows no longer ships the binary.

The patch series, now in its second version, has evolved through review to handle this distinction across multiple test scripts. The latest addition modifies t5550-http-fetch-dumb.sh to properly guard tests that depend on `iconv(1)` for HTTP error message reencoding, while keeping non-encoding tests unchanged. This follows the established pattern of using ICONV prerequisites where needed and converting raw `grep` calls to `test_grep` for consistency.

All feedback from reviewers has been addressed, including extended prerequisite checks in test-lib.sh, proper documentation of the build-time vs test-time ICONV requirements, and references to the relevant Git for Windows issue (#6083). The changes affect several test files (t4205, t4041, t4059, t4060, and now t5550) but maintain core functionality while making the tests more portable.

Junio Hamano and other reviewers have approved the approach, though there's an open question about whether Git for Windows should restore the `iconv(1)` binary to simplify test assumptions. The series is now complete and ready for merging, representing an important step in improving Windows/MSVC CI reliability.
