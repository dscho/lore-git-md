This is the first patch in a 4-part series fixing test failures on Windows/MSVC platforms related to iconv handling. The patch addresses an inconsistency where tests would attempt to use the `iconv(1)` executable even when the ICONV prerequisite (indicating Git was built with ICONV support) wasn't met.

The changes modify three test scripts in the t4xxx range that deal with submodule diff output. These tests previously assumed the `iconv(1)` executable would be available whenever ICONV support was enabled in Git, which isn't true on some Windows/MSVC setups. The patch restructures the test code to only call `iconv(1)` when the ICONV prerequisite is actually set, falling back to UTF-8 otherwise.

Patrick notes this could be made more robust by splitting the ICONV prerequisite into separate checks for library support versus executable availability, but considers that overkill for the current issue. The changes are straightforward and focused, touching only test infrastructure with no impact on production code. This looks like a solid fix for a real-world CI problem that affects Windows testing.
