This is a bug report targeting the branch listing behavior after `git init`. Ryan Johnson points out that while `git status` shows "On branch master" in a newly initialized repository, `git branch` shows no output at all. This inconsistency creates confusion, particularly for users who want to rename the default branch from "master" to "main" but can't see what branch they're on.

The report argues this is poor UX design that hides important information - the promised default branch name that will be created on first commit. It suggests `git branch` should display this pending branch name to match what `git status` shows, regardless of internal implementation details about when the branch is actually created.

The issue touches core branch listing behavior and user expectations around default branch naming. While the technical distinction between a "promised" and actually created branch may be subtle, the current behavior creates a real usability problem for new users following modern branch naming conventions. The patch would need to modify `builtin/branch.c` to surface this information consistently.
