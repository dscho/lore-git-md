Documentation patch adding warnings about patch roundtrip hazards in `git am` workflows. This is part of an ongoing thread about security vulnerabilities in patch parsing, where embedded diffs in commit messages can be accidentally applied.

Kristoffer Haugsbakk's patch updates `format-patch-caveats.adoc` to explicitly warn about three parsing hazards when roundtripping patches through email: truncation at "---" lines, misparsing of "Index:" lines, and unintended application of unindented diffs. The warnings will appear in the man pages for `git-am`, `git-format-patch`, and `git-send-email`.

Phillip Wood provided review feedback that has been incorporated: removing an unnecessary reference to `git-send-email`, improving the explanation about trusting `git-format-patch` output, rewording the comparison with `patch(1)`, and clarifying that the issue affects the patch application rather than correctness. The documentation maintains its core warnings while becoming more precise.

This patch is now queued by Junio after the review process. It represents the documentation component of a layered solution that also includes Phillip Wood's security-focused commit-msg hook (now reconsidering "---" detection) and Patrick Steinhardt's proposed `--accept-ambiguous-patch` flag for `git am`. The changes aim to protect users - particularly distribution maintainers who apply many patches - while preserving legitimate workflows that use separator lines in commit messages.
