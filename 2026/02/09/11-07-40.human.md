This is a security discussion thread about `git am`'s vulnerability to embedded diffs in commit messages. Matthias Beyer responds to Phillip Wood's concerns about the scope of the issue, providing real-world context from distribution workflows.

Matthias confirms that distributions like NixOS frequently apply upstream patches (citing ~2800 instances in nixpkgs) and notes that even experienced Git users may not realize commit message diffs can be accidentally applied. While distributions typically use `patch` rather than `git am`, the same vulnerability exists in both tools. He supports Phillip's approach of focusing on documentation improvements rather than adding potentially confusing warnings to `git commit`.

The exchange highlights the tension between security hardening and practical workflow considerations, with Matthias providing concrete evidence that this is not just a theoretical issue but affects real-world package maintenance. His 15 years of Git experience lends weight to the observation that this vulnerability is non-obvious even to seasoned users. The thread continues to refine the layered approach combining documentation warnings and defensive hooks while acknowledging the limitations of any single mitigation.
