This is a documentation patch from Kristoffer Haugsbakk addressing the security implications of patch roundtripping in Git's email workflow. The patch adds warnings to `format-patch-caveats.adoc` about how inline patches can be misinterpreted when applied with `git am`, potentially leading to incorrect commit messages or misapplied diffs.

The email shows Haugsbakk incorporating feedback from Phillip Wood on the documentation wording. Key changes include removing an unnecessary reference to `git-send-email` (since it just calls `git-format-patch`), improving the explanation about trusting formatted patches, and rewording the comparison with `patch(1)`. The documentation maintains three core warnings: about "---" truncation, "Index:" line issues, and problems with unindented diffs.

This patch is part of a broader security discussion about `git am`'s vulnerability to embedded diffs in commit messages, particularly affecting distribution workflows. While the documentation is being queued, other solutions are still under discussion - including Phillip Wood's security-focused commit-msg hook (now reconsidering "---" detection) and Patrick Steinhardt's proposed `--accept-ambiguous-patch` flag for `git am`. The patch represents the documentation component of a layered approach to addressing this long-standing security issue.
