This is a follow-up in the RFC discussion about a proposed `--untangle` option for `git log --graph`, which aims to simplify complex history visualizations by suppressing some ancestry lines. Toon Claes responds to Johannes Sixt's technical concerns about edge cases in the visualization approach.

The email focuses on three key areas: visualization alternatives for truncated history links, handling of criss-cross merges and backward merges, and interaction with `--boundary`. Toon acknowledges the current implementation shows technically "wrong" history by omitting merge bases, proposing two alternative display approaches - using `/` markers or `+` symbols to indicate truncated ancestry. For backward merges, he demonstrates how the simplified view would look but notes the complexity when merge bases aren't first parents.

The thread remains in RFC stage with several open technical questions. Toon invites others to test the feature on real repositories, as small examples don't fully demonstrate its value. The implementation still needs work on edge cases (criss-cross merges, boundary handling) and visualization clarity before it could be considered for merging. The discussion shows progress in addressing maintainer concerns but confirms the feature needs more development to handle Git's full complexity.
