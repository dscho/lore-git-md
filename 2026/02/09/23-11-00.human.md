This is a documentation patch addressing security concerns around patch roundtripping in Git. Kristoffer Haugsbakk updates the caveats documentation to more clearly warn about how `git format-patch` output can be misinterpreted when applied with `git am`, particularly when commit messages contain certain patterns that get mistaken for patch delimiters.

The patch simplifies the warning text by removing the potentially confusing "inline" adjective, as suggested by Junio Hamano, making the risk more directly stated. The documentation now focuses on the core issue: that unindented diffs or separator lines in commit messages can cause the patch application to fail or apply incorrectly. This is part of a broader effort to address a long-standing security vulnerability where malformed patches could execute unintended code.

The change has been reviewed by Phillip Wood and Junio, with Junio queuing the patch after Haugsbakk incorporated the wording improvements. This documentation update complements other security measures being discussed, including Phillip Wood's proposed commit-msg hook enhancements and Patrick Steinhardt's work on an `--accept-ambiguous-patch` flag for `git am`.
