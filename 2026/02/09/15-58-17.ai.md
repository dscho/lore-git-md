This is a feature patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories. The series is now in its fifth iteration and appears technically complete, with only minor documentation refinements remaining.

The key additions are:
1. A URI format (`<format>://<payload>`) for the `extensions.refStorage` config to specify both backend and storage location
2. A new `GIT_REFERENCE_BACKEND` environment variable that overrides the config
3. Support for worktree references in alternate storage locations
4. Comprehensive test coverage in t1423-ref-backend.sh

The primary use case enables GitLab's migration strategy between reference backends with minimal downtime. The implementation handles both persistent (config) and ephemeral (environment variable) specifications, with the environment variable taking precedence. Worktree references are stored in `$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>` when using alternate storage.

The series has undergone extensive review from Patrick Steinhardt, Karthik Nayak, and others, addressing all substantive feedback. Junio Hamano has signaled approval of the core design. The current changes focus on final documentation wording refinements ("git"->"Git", "description"->"details"), allocation optimizations using `strbuf_detach()`, and commit message clarifications.

The implementation touches core repository initialization, URI parsing, worktree integration, and path computation while maintaining backward compatibility. The careful attention to detail in these late-stage reviews ensures both correctness and clear documentation for the new reference backend selection mechanism.
