This is part of the ongoing ref backend abstraction effort, specifically implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch is now in its fifth iteration with all substantive feedback addressed, awaiting final documentation polish before potential integration.

The patch extends the `extensions.refStorage` config to support URI syntax (`<format>://<payload>`) for specifying both the backend format and storage location. For files/reftable backends, the payload is a filesystem path where references will be stored (defaulting to commondir if unspecified). The implementation handles worktree references by storing them in `$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>` while maintaining stubs in the original `$GIT_DIR` path for compatibility.

Key technical changes include:
- New `parse_reference_uri()` function in setup.c` to handle URI parsing
- `ref_storage_payload` field added to `struct repository` and `struct repository_format`
- Worktree reference handling via `setup_alternate_ref_dir()` in `builtin/worktree.c`
- Comprehensive test coverage in new `t1423-ref-backend.sh` including:
  - URI validation tests
  - Cross-backend migration scenarios
  - Worktree integration testing
  - Path resolution cases (absolute/relative)

The patch maintains backward compatibility while enabling the primary use case of GitLab's migration strategy. A TODO notes the future goal of passing `struct worktree *` to backends instead of just gitdir, once worktree code is decoupled from `the_repository` global. The implementation has been thoroughly reviewed by Patrick Steinhardt and others, with only minor documentation wording refinements remaining before this stabilized design can be integrated.
