This is a security-focused documentation patch in the ongoing thread about `git am` vulnerability to embedded diffs in commit messages. Junio Hamano responds to Kristoffer Haugsbakk's suggestion of adding an environment variable escape hatch for the commit-msg hook that detects problematic separator lines ("---") in commit messages.

Junio acknowledges the concern but argues the sample hook should remain simple and understandable, noting that projects can always replace it with more sophisticated versions. He expresses particular concern about false positives - cases where legitimate uses of three-dash lines (like email workflow conventions) might be blocked by the security check.

The exchange shows the maintainer's balancing act between security hardening and workflow flexibility. While Haugsbakk's documentation patch (already queued) warns about the risks, Junio resists adding complexity to the sample hook, preferring to leave customization to individual projects. This reflects Git's philosophy of providing basic tools that users can adapt rather than trying to anticipate every use case.
