CI/build system patch fixing test slicing logic in GitLab CI. This is the second in Patrick Steinhardt's 5-part series improving test execution reliability across CI platforms.

The patch addresses a subtle issue where GitLab CI was unintentionally skipping the smallest test in each test slice due to an off-by-one error in the test slicing logic. The root cause was a mismatch in index handling - the `test-tool path-utils slice-tests` command expected zero-based indices while GitLab CI provided one-based indices (`$CI_NODE_INDEX`). This caused the first test in each slice to be skipped, which due to test sorting by size meant the smallest test was missed.

Patrick reframes the interface to use clearer "slice number" and "total slices" terminology (both one-based) rather than the ambiguous "offset" and "stride" terms. The changes include input validation to ensure slice numbers are within bounds and updates both the GitHub workflow (`.github/workflows/main.yml`) and the test helper (`t/helper/test-path-utils.c`) to use the new semantics. The fix ensures consistent test coverage across both GitLab and GitHub CI environments while making the slicing behavior more robust and self-documenting.
