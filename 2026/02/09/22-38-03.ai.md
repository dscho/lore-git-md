This is a maintainer response in an ongoing thread about default branch naming behavior. Junio C Hamano weighs in on the discussion about the inconsistency between `git status` showing "On branch master" while `git branch` shows no output in a new repository before the first commit.

Junio endorses Ben Knoble's suggestion to use `init.defaultBranch` configuration as the solution, demonstrating how Git already provides clear guidance about changing the default branch name through both warnings and configuration options. He shows the exact output users see when initializing a new repository, which includes instructions for setting a different default branch name globally and renaming the branch after creation.

The response suggests the maintainer position is that the current behavior with configuration is sufficient, implying the UX inconsistency between `git status` and `git branch` is not considered a bug worth fixing at the code level. Junio frames this as part of the broader transition away from "master" that will be completed in Git 3.0, treating the configuration workaround as the intended solution for users who want to avoid the "master" naming before then.

Key technical details for future reference: the `init.defaultBranch` config controls the initial branch name, while `advice.defaultBranchName` controls whether the warning message is shown. The thread shows no indication that changes to `builtin/branch.c` to make unborn branch visibility consistent are being considered - the focus remains on configuration rather than core behavior changes.
