This is part of the ref backend abstraction effort, specifically the fifth iteration of a series enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch extracts common stub creation code into a new `refs_create_refdir_stubs()` function to avoid duplication.

The function creates minimal directory structures (`HEAD` and `refs/`) that Git requires to recognize a directory as a repository, which is necessary even when using alternative backends like reftable. The patch consolidates this logic from two existing locations (clone.c and reftable-backend.c) into a single reusable implementation in refs.c, with an optional parameter to write a message in `refs/heads`.

The changes are straightforward mechanical refactoring with no behavior change. The new function handles both the basic stub case (used in clone.c) and the reftable-specific case where an explanatory message is written to `refs/heads`. This prepares for future use in additional contexts while cleaning up existing code. The implementation includes proper permission handling via `adjust_shared_perm()` and uses strbuf for path construction.

This is a well-contained preparatory change in a larger series that has already addressed all substantive feedback. The patch follows Git's coding style and includes a clear commit message explaining the motivation and changes. As part of the final polishing phase, it demonstrates the careful attention to detail seen throughout this backend selection work.
