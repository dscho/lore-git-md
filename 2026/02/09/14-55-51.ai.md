This is a discussion about extending Git's alias system to support UTF-8 characters in alias names, currently restricted to ASCII. The thread has evolved from Jonatan Holmgren's original RFC to consider broader config key design and security implications, with Junio now weighing in.

Junio expresses cautious openness to the idea of UTF-8 aliases but emphasizes the implementation must be robust. He notes that Unicode normalization (NFC/NFD) is currently only handled for macOS command-line arguments via `precompose_argv_prefix()`, suggesting this might be sufficient rather than needing comprehensive Unicode support. His primary concern is avoiding bug-prone implementations that would generate ongoing maintenance burden.

The discussion now centers on whether to:
1. Extend the current ASCII-only alias system with UTF-8 support (requiring Unicode handling)
2. Adopt Jeff King's alternative three-level config key proposal (`alias.foo.command`) that avoids Unicode complexities
3. Find some middle ground that addresses internationalization needs without introducing security risks from Unicode normalization

Junio's position appears pragmatic - not opposed to the feature in principle but wary of implementation quality and long-term maintenance impact. His comments suggest he would prefer a solution that either leverages existing macOS normalization or avoids Unicode handling altogether if possible. The security concerns raised by Theodore Tso about Unicode normalization vulnerabilities (citing ext4 case folding CVE) add weight to this cautious approach.
