This is a refactoring patch from Karthik Nayak, part of the v5 series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series is in its final polishing phase with only minor documentation tweaks remaining.

The patch extracts duplicate stub-creation code into a new `refs_create_refdir_stubs()` function, used when initializing Git directories. This ensures Git recognizes directories as valid repositories by creating required files/structures (HEAD and refs/) even when using alternate reference backends like reftable. The function centralizes logic previously duplicated in clone.c and reftable-backend.c, with an optional parameter to customize the refs/heads content.

The change is straightforward and well-contained, touching only the stub creation mechanism while maintaining existing behavior. It's a clean preparatory step for the series' subsequent patches that will introduce additional stub creation sites. The patch has already been reviewed by Patrick Steinhardt and others, with all substantive feedback addressed in earlier iterations.
