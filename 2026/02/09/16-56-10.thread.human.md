Patrick Steinhardt's series to improve CI test slicing consistency has hit a platform-specific snag in GitHub Actions. The first four patches established one-based indexing for test slices across both GitHub Actions and GitLab CI, with Justin Tobler reviewing and suggesting tighter patch grouping. However, Junio Hamano had to revert patch 3 when it became clear GitHub Actions doesn't support arithmetic operations in YAML expressions - a limitation that had existed for six years but wasn't caught in initial reviews.

Jeff King (Peff) has now weighed in with a precise solution, pointing to two historical commits that previously handled this arithmetic. One used PowerShell syntax (d3d6493dcf) while another moved the calculation into the test script itself (17bd1108ea). Peff suggests reverting to the PowerShell approach as the most straightforward fix given the platform constraints. This exchange highlights how even carefully reviewed infrastructure changes can uncover hidden platform quirks.

The fifth patch - which improves MSVC+Meson test handling in GitLab CI with better failure reporting and artifact collection - remains valid but can't proceed until the GitHub Actions issue is resolved. The core improvements for test consistency are sound, but Patrick will need to respin the series with either a script-based or PowerShell-based arithmetic workaround to maintain the one-based indexing while working within GitHub Actions' limitations.
