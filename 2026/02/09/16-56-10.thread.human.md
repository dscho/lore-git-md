This thread is a 5-patch series from Patrick Steinhardt improving CI/build system reliability, particularly for GitLab CI testing on Windows/MSVC platforms. The focus is on making test execution more robust and failures more debuggable across all CI environments.

The first patch fixed a subtle issue where test failures were being masked in `ci/run-test-slice.sh` due to shell pipe behavior, ensuring proper failure detection especially important for Windows testing. The second patch, just received, addresses an off-by-one error in test slicing that was skipping the smallest test in each slice. This occurred because GitLab CI's one-based `$CI_NODE_INDEX` clashed with the test tool's zero-based expectations. Patrick reframed the interface to use clearer "slice number" terminology and added input validation.

The series demonstrates Patrick's characteristic attention to cross-platform consistency, with changes spanning CI config files, test helper scripts, and infrastructure code. While motivated by Windows/MSVC debugging, the improvements benefit the entire CI pipeline by making test execution more reliable and failures more actionable. The remaining patches in the series will likely continue this theme of standardizing behavior between GitLab and GitHub CI environments.
