This is a maintainer response in an ongoing thread about branch listing behavior in new repositories. Junio C Hamano weighs in on Ben Knoble's suggestion to use `init.defaultBranch` configuration to address the reported inconsistency between `git status` and `git branch` output in fresh repositories.

Junio endorses Ben's recommendation to set `init.defaultBranch` globally as a practical workaround, noting it aligns with Git 3.0's planned change to default to "main" instead of "master". His brief reply signals agreement with the configuration-based approach rather than proposing code changes to make the commands behave consistently.

The response maintains the thread's focus on user-facing configuration while avoiding deeper technical discussion about the underlying branch plumbing behavior. As maintainer, Junio's approval of this direction suggests the issue may be considered resolved through documentation and upcoming defaults rather than requiring core behavior changes.
