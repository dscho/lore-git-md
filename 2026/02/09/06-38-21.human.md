This is a follow-up discussion in the RFC thread for a proposed `git log --graph --untangle` feature, which aims to simplify complex history visualization by suppressing some ancestry lines. Toon Claes responds to Johannes Sixt's technical concerns about edge cases and visualization accuracy.

The exchange focuses on three key challenges: how to visually represent truncated history links (with Toon proposing alternative glyphs like '.' or '+' to indicate missing connections), handling criss-cross merges and backward merges (where the current implementation struggles), and interaction with `--boundary` (which remains untested). Toon acknowledges these are real limitations but argues some inaccuracy is an acceptable tradeoff for cleaner visualization.

The thread shows the proposal is making progress on demonstrating concrete benefits (Toon invites others to test it on real repositories), but significant technical questions remain before it could be considered for merging. The discussion remains constructive, with Toon engaging substantively with the feedback while being transparent about current limitations.
