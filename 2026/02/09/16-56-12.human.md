This is a CI/build system patch from Patrick Steinhardt that fixes a test-slicing issue in Git's CI infrastructure. The patch corrects how test cases are distributed across parallel CI jobs by addressing an inconsistency between GitHub and GitLab CI configurations.

The core issue stems from how test slicing parameters are interpreted. The test-slicing helper expected a zero-based index (GitHub's approach) but GitLab CI provides a one-based index, causing the smallest test to be consistently skipped. Patrick reframes the parameter naming from "offset/stride" to "slice number/total slices" to make the semantics clearer and adds validation to catch invalid inputs.

The change ensures test distribution works correctly across both CI systems while making the code more robust against invalid inputs. This is part of a larger series improving CI reliability, particularly for Windows/MSVC testing where parallel test execution is most critical for performance. The patch demonstrates Patrick's characteristic attention to cross-platform consistency and infrastructure robustness.
