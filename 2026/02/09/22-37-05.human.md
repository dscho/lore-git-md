Documentation patch addressing security concerns around `git am` parsing of commit messages with embedded diffs. This is part of an ongoing thread about vulnerabilities in patch/commit message parsing that can cause unintended diff application.

Kristoffer Haugsbakk adds explicit warnings about how `git format-patch` and `git am` handle delimiters in commit messages, particularly focusing on three cases where commit message content can be misinterpreted as patch content: lines starting with "---", "diff -", or "Index:". The patch documents how unindented diffs in commit messages may get incorrectly applied, with special attention to distribution workflows that apply patches.

The documentation now appears in multiple man pages (`git-am`, `git-format-patch`, `git-send-email`) via a shared include file. The warnings emphasize that this isn't just an email workflow issue - bulk patch application (like Linux distributions use) is particularly vulnerable since problems may go unnoticed. The patch also notes that while `patch(1)` might seem like an alternative, it has even more aggressive diff detection behavior.

This v2 iteration incorporates feedback from Phillip Wood, removing redundant examples and focusing the explanation. The patch has been queued by Junio after review, indicating it addresses an important documentation gap in the ongoing security discussion. The warnings complement other proposed solutions in the thread like Phillip Wood's sample hook and Patrick Steinhardt's `--accept-ambiguous-patch` flag.
