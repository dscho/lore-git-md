This is the third patch in a 4-part test infrastructure series addressing CI failures on Windows/MSVC related to `iconv(1)` availability. The patch focuses on HTTP fetch tests in t5550 that interact with error message handling.

The key change adds ICONV prerequisites to several tests that use "$HTTPD_URL/error" endpoints, since these endpoints rely on the `iconv(1)` executable to reencode error messages. The tests verify that Git properly handles different error message formats (plain text, HTML, various character encodings), but were failing on platforms where `iconv(1)` isn't available despite Git having ICONV support compiled in.

Patrick Steinhardt's changes:
- Add ICONV prerequisite to 5 tests that depend on error message reencoding
- Convert remaining `grep` calls to `test_grep` for consistency
- Keep non-encoding-related tests (like Accept-Language header checks) unchanged

The patch maintains all test coverage while making the suite more robust on platforms where the test environment differs from development environments. This continues the series' pattern of carefully distinguishing between needing ICONV support in Git versus needing the `iconv(1) executable in the test environment.
