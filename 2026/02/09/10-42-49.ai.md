This is a security-focused patch in the ongoing thread about `git am`'s vulnerability to embedded diffs in commit messages. Phillip Wood responds to concerns raised by Junio Hamano and Jeff King about legitimate uses of "---" separator lines in commit messages, which his proposed hook would block.

The patch in question would detect and reject commit messages containing separator lines ("---") that could confuse `git am`'s parser. However, both Junio and Peff note they occasionally use this pattern intentionally as a workflow where notes after "---" are preserved through format-patch/am cycles. Phillip acknowledges this could be problematic for their workflows, though he initially suggested using `--no-verify` to bypass the hook, he now considers dropping the patch entirely.

Key technical points:
- The security issue stems from `git am` treating "---" as a patch separator, which can cause it to misparse commit messages containing that marker
- Phillip's solution would block this at commit-time via a hook, but this would break legitimate workflows
- Alternative solutions discussed include making the check configurable or adding special comments to bypass it
- Phillip leans toward dropping this particular check while keeping other security measures from the series

The exchange highlights the tension between security hardening and preserving established workflows, with Phillip showing willingness to compromise on this specific check given the legitimate counterexamples. This leaves the thread's broader security improvements intact while avoiding disruption to maintainers' email-based workflows.
