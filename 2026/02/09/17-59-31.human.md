Maintainer feedback on UTF-8 alias names proposal. Junio C Hamano responds to Jonatan Holmgren's RFC about supporting non-ASCII characters in Git aliases, which has evolved into a discussion of two implementation approaches: extending the current syntax to handle UTF-8 versus using a new subsection-based syntax (`alias.*.{keyname}`).

Junio clearly favors the subsection approach proposed by Jeff King, noting it would avoid the need for Git to handle Unicode normalization internally. He confirms that on macOS, the command-line arguments would already be normalized by `precompose_argv_prefix()` before reaching the alias matching code. This aligns with his stated preference for solutions that minimize new Unicode handling infrastructure in Git.

The response indicates the maintainer's position that the subsection method is the more maintainable path forward, as it leverages existing platform handling of Unicode normalization rather than requiring new Git-specific Unicode support. This appears to resolve the open question about which implementation approach would be acceptable.
