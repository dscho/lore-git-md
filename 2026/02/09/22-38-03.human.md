This is a maintainer response to a thread about default branch naming behavior in new repositories. Junio C Hamano confirms Ben Knoble's suggestion that users can configure `init.defaultBranch` globally to set their preferred default branch name (like "main") rather than waiting for Git 3.0's planned change. 

Junio demonstrates the current Git behavior when no default is set - it still uses "master" but shows a prominent warning about the upcoming change in Git 3.0, along with clear instructions for configuring an alternative name. The response implies this configuration approach is the intended solution rather than changing the core behavior where `git branch` doesn't show unborn branches.

The maintainer's position suggests this thread may conclude with the configuration workaround being the recommended approach, leaving the underlying UX inconsistency between `git status` and `git branch` unchanged. The response doesn't invite further technical solutions, focusing instead on the existing migration path via configuration.
