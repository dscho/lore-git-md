This is part of the ref backend abstraction effort, specifically patch 2/4 in the v5 series enabling reference storage backend selection via both config and environment variables. The patch focuses on plumbing the reference storage payload through the initialization chain.

The key change introduces `refs_compute_filesystem_location()`, a helper that calculates reference directory paths based on the gitdir and an optional payload. This handles both absolute and relative payload paths while maintaining worktree awareness. The files and reftable backends are modified to accept and process these payloads during initialization.

Patrick Steinhardt's review identifies several opportunities for refinement: clarifying why worktree paths don't need modification when no payload exists, optimizing the strbuf reset sequence, and better documenting the packed backend's payload handling. He suggests either passing NULL to `packed_ref_store_init()` or having it compute paths itself, and requests clearer comments about the packed backend's payload indifference.

The changes are preparatory - since no callers yet pass payloads, this remains a no-op for existing behavior. The patch demonstrates careful attention to path resolution and string handling, using `strbuf_detach()` for allocations. This foundational work enables the subsequent patches that will introduce actual payload usage via config and environment variables.
