Thread summary:

Bug report from Ryan Johnson about inconsistent branch listing behavior in new repositories, where `git status` shows "On branch master" but `git branch` shows no output until first commit. This creates confusion for users trying to rename the default branch from "master" to "main" before their first commit.

Core issue remains the UX mismatch between showing the promised default branch name in `git status` versus hiding it in `git branch`. Ben Knoble initially pointed to `init.defaultBranch` configuration and Git 3.0's planned default branch name change. Junio C Hamano has now responded, endorsing the configuration workaround but not addressing the behavioral inconsistency directly. His response frames `init.defaultBranch` as the solution, suggesting users set it globally to avoid "master" naming entirely, while implicitly maintaining the current behavior where unborn branches remain invisible in `git branch` output.

Technical impact would still involve modifying `builtin/branch.c` to display default branch names consistently, but Junio's response suggests the maintainer position is to consider configuration sufficient rather than changing core behavior. The thread now has input from both the original reporter and the maintainer, with Junio's stance indicating this may be closed as "works as designed" with configuration guidance. No patches have been proposed and no further technical discussion has been invited about modifying branch listing behavior for unborn branches. The Git 3.0 default branch name change remains the only planned resolution to the broader naming concern.
