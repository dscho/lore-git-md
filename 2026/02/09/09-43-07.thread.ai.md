Thread summary:

Bug report from Ryan Johnson about inconsistent branch listing behavior in new repositories, where `git status` shows "On branch master" but `git branch` shows no output until first commit. This creates confusion for users trying to rename the default branch from "master" to "main" before their first commit.

Core issue is the UX mismatch between showing the promised default branch name in `git status` versus hiding it in `git branch`. The behavior stems from the "unborn branch" state (referenced in `git switch` documentation) where the branch exists conceptually but not yet as a ref. Ben Knoble responded by pointing to `init.defaultBranch` configuration and noting Git 3.0's planned change to default to "main", but didn't directly address the inconsistency.

Technical impact would involve modifying `builtin/branch.c` to display the default branch name consistently with `git status`, regardless of internal implementation details about when the branch ref is created. The discussion highlights a real usability problem for new users following modern branch naming conventions, where current behavior obscures the pending branch name. No patches have been proposed yet - this remains at the discussion stage with Ryan's original report and Ben's response about configuration and future defaults. The thread may need input from branch plumbing experts to resolve whether showing unborn branches in `git branch` would be technically feasible and desirable.
