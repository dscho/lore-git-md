Thread summary:

Bug report from Ryan Johnson about inconsistent branch listing behavior after `git init`. While `git status` shows "On branch master" in a new repository, `git branch` shows no output until the first commit is made. This creates confusion for users trying to rename the default branch from "master" to "main" since they can't see what branch they're on.

Core issue is the mismatch between showing the promised default branch name in `git status` versus hiding it in `git branch`. The report argues this is poor UX that obscures important information about the pending branch name that will be created on first commit. Suggests modifying `builtin/branch.c` to display the default branch name consistently with `git status`, regardless of internal implementation details about when the branch is actually created.

Technical impact would involve changes to branch listing behavior in new repositories, touching core branch plumbing. The issue highlights a real usability problem for new users following modern branch naming conventions, where the current behavior makes it unnecessarily difficult to see and rename the default branch before first commit. No patches proposed yet - this is the initial bug report.
