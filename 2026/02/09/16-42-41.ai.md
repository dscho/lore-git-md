This is a documentation patch in an ongoing thread about security around `git am`'s patch parsing behavior. Kristoffer Haugsbakk has proposed adding explicit warnings about how diffs in commit messages can be misinterpreted during the format-patch/am roundtrip, particularly focusing on unindented diffs and separator lines ("---") that can truncate commit messages or cause unintended patch application.

Phillip Wood provides review feedback, suggesting some clarifications to the proposed documentation. He questions whether mentioning `git-send-email` is necessary since it doesn't do formatting itself, notes some formatting inconsistencies, and suggests the GitHub Markdown example might not add value. Phillip also points out that the explanation about trusting `git-format-patch` for Git origin changes could be clearer, and proposes rewording the section about using `patch(1)` instead.

The patch adds a new `format-patch-caveats.adoc` file and includes it in the man pages for `git-am`, `git-format-patch`, and `git-send-email`. The documentation warns about three specific hazards: commit message truncation at "---" lines, empty patch errors from "Index:" lines, and unintended application of unindented diffs in commit messages. It suggests indenting diffs as a workaround while noting that `patch(1)` has even broader matching behavior.

This is part of a layered security approach that also includes Phillip Wood's proposed commit-msg hook changes and Patrick Steinhardt's work on an `--accept-ambiguous-patch` flag for `git am`. Junio has already queued Kristoffer's documentation patch, indicating it is likely to be merged. The documentation improvements complement the technical changes by making the risks more visible to users who might encounter these edge cases.
