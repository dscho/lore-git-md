This is part of a feature series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable), primarily for GitLab's use case. This specific patch (v5 2/4) introduces the plumbing to forward and use reference storage payloads when initializing ref backends.

The patch adds a new `refs_compute_filesystem_location()` function that calculates reference directory paths based on the gitdir and an optional payload (which will later contain URI information). It modifies both the files and reftable backends to accept and process this payload during initialization. The changes include:

1. Adding payload parameters to backend init functions
2. Path resolution logic that handles both absolute and relative payload paths
3. Worktree reference location computation
4. String handling optimizations using strbuf_detach()

Key technical points:
- The payload will eventually come from `extensions.refStorage` config or `GIT_REFERENCE_BACKEND` env var
- Paths are properly realpath'd and worktree-aware
- Maintains backward compatibility when no alternate location is specified
- Includes allocation optimizations noted in previous reviews

The implementation shows careful attention to edge cases like worktree handling and path resolution. This is a foundational piece for the larger reference backend selection feature, with all substantive architectural feedback from previous rounds addressed. The patch is well-structured and follows Git's established patterns for ref backend modifications.
