This is a test infrastructure patch in a series addressing CI failures on Windows/MSVC platforms related to `iconv(1)` availability. The patch modifies three submodule test scripts to properly handle cases where Git is built with ICONV support but the `iconv(1)` executable isn't available in the test environment.

Junio Hamano raises a thoughtful concern about the approach - he questions whether we should be making the tests work without ICONV by skipping just the executable call, rather than skipping the entire test. His comment suggests the current solution might be masking a deeper issue about what behavior we can expect from Git when ICONV support is compiled in but the executable is missing.

The patch itself is mechanically sound, making the same careful change across three similar test files to wrap the `iconv` call in an ICONV prerequisite check. This maintains test coverage while fixing the Windows/MSCI failures, but Junio's comment hints we may need to reconsider the broader assumptions about ICONV behavior in Git's test suite.
