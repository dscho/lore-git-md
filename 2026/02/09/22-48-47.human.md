This is a patch in the Rustification effort, proposing to reorganize Git's experimental Rust infrastructure by moving files from `src/` to a dedicated `rust/` subdirectory. The patch follows up on an RFC discussion about project structure for mixed C/Rust codebases.

Mike Hommey's v2 patch moves all Rust-related files (Cargo.toml, lib.rs, varint.rs) into a new `rust/` directory, updating build system references in Makefile and meson.build. The motivation is to clarify project structure in a multi-language codebase and prevent confusion from having a top-level Cargo.toml that doesn't produce useful standalone builds. The changes are mechanical - file moves with corresponding path updates in build systems and .gitignore.

The patch appears well-constructed with clean diffs and comprehensive updates to all affected build systems. It addresses one of the original concerns from the RFC thread (project clarity) while new information in the thread has weakened the mrustc compatibility justification that was part of earlier discussion. This change now stands primarily on its merits for code organization rather than being tied to cross-compilation requirements.
