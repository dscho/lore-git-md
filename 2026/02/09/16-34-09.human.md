This is a refactoring patch in the ongoing ref backend abstraction effort, specifically preparing for runtime selection between files and reftable backends. The patch modifies the files and reftable backends to accept a "payload" parameter that will eventually contain alternate reference storage locations specified via configuration.

Patrick Steinhardt provides detailed review feedback on Karthik Nayak's implementation, focusing on several technical points. He suggests improving the documentation of `refs_compute_filesystem_location()` to clarify worktree path handling, proposes moving some path resolution logic into a conditional block, and questions whether the packed ref backend should receive the payload parameter when it doesn't use it.

The review also notes that while this change is currently a no-op (since no callers exist yet), it lays important groundwork for the upcoming URI-based backend selection. The discussion shows careful attention to edge cases in path handling and worktree integration, with Patrick providing specific suggestions for code organization and documentation clarity.

This is part of a mature patch series that has already addressed most substantive feedback, with Junio Hamano having signaled approval of the overall approach. The review focuses on final polishing touches before the feature can be merged.
