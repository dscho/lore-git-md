Feature proposal for `git log --graph --untangle` to simplify visualization of complex merge histories. This follow-up email from Toon Claes responds to Junio Hamano's request for concrete examples by showing before/after output from git.git's own history. The key change is suppressing ancestry lines to display merged branches as originating from merge commits rather than their original branch points, reducing visual clutter in octopus merges.

The example demonstrates the effect on git.git's l10n merge history - the untangled version collapses multiple parallel merge chains into cleaner vertical lines while preserving the merge structure. The implementation introduces `only_first_merge_base` and `ignored_merge_bases` in graph.c, though the author notes remaining memory leaks and naming concerns (`--ignore-merge-base` is floated as an alternative).

Technical open questions include edge cases with criss-cross merges and `--boundary` interactions, plus the need for more complex test cases. The maintainer has expressed general interest in graph visualization improvements while hinting at other potential directions. This remains an RFC stage with clear next steps: fixing memory issues, expanding test coverage, and demonstrating value on more complex histories before considering final naming and implementation details.
