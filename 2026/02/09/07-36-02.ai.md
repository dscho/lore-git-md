This is a technical discussion about extending Git's alias system to support non-ASCII characters, building on Jonatan Holmgren's RFC proposal. Jeff King (Peff) responds with a more comprehensive approach than the original UTF-8-specific suggestion.

Peff identifies the root issue as Git's config key syntax being poorly matched to command naming needs, noting this affects both aliases and pager configurations. He proposes a new schema using three-level config keys (e.g., `alias.foo.command`) that would allow arbitrary command names while maintaining backward compatibility with existing `alias.foo` syntax. The approach would treat command names as verbatim byte streams, avoiding Unicode normalization complexities by matching exactly what users configure.

Key technical points raised:
- Current implementation uses `strcasecmp()` for case-insensitive matching, which would need consideration in the new schema
- The patch demonstrates how `parse_config_key()` could be used to handle both old and new alias formats
- Suggests potential future extensions like `alias.foo.help` text while designing the new schema
- References a 2015 discussion about similar limitations with underscore-containing commands

The response shifts the conversation from a narrow UTF-8 allowance to a broader config schema redesign that would solve multiple related issues. Peff's approach would provide more flexibility while avoiding platform-specific Unicode handling complexities, though it requires more extensive changes to the alias implementation. The thread now faces a design decision between targeted UTF-8 support versus a more comprehensive config schema overhaul.
