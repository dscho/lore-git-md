This is a bugfix proposal targeting the branch listing behavior after `git init`. Ryan Johnson points out that while `git status` shows "On branch master" in a newly initialized repository, `git branch` shows no output at all. This inconsistency creates confusion, particularly for users who want to rename the default branch from "master" to "main" but can't see what to rename.

The patch argues this is a UX issue that should be fixed regardless of Git's internal distinction between a "promise" to create a branch and an actually created branch. The current behavior makes it needlessly difficult for users to discover and rename their default branch, which is a common workflow given modern naming conventions.

The proposed change would make `git branch` show the default branch name immediately after initialization, aligning it with what `git status` reports. This appears to be a straightforward quality-of-life improvement with no obvious downsides, though it might require touching some subtle branch-handling internals. The motivation is clearly explained and addresses a real pain point in the user experience.
