Security-focused documentation update for patch parsing hazards. This is a follow-up to the ongoing discussion about `git am`'s vulnerability to misinterpreting diffs embedded in commit messages, which recently caused a real-world incident in Debian.

Jeff King (Peff) expresses skepticism about relying solely on commit-msg hooks to address the issue, noting that few projects use these hooks and many developers no longer work with email-based patches. He suggests documentation warnings would reach more users, particularly in `git am` and `git format-patch` man pages, where the parsing behavior and its risks could be clearly explained.

The thread has already seen progress on this front - Kristoffer Haugsbakk's documentation patch adding explicit warnings about patch roundtrip hazards has been queued by Junio. Peff references prior discussions from 2015, 2022, and 2024 that established this as a long-standing issue, now recognized as a security risk affecting multiple tools in the Unix toolchain.

The core tension remains between security needs and backward compatibility, with the layered solution now including detection mechanisms, configurable comment characters, multiple bypass options, and now documentation warnings. Peff's comments reinforce that while Phillip Wood's commit-msg hook improvements are useful, they should be complemented by broader educational efforts given the limited adoption of such hooks.
