This is the third patch of a four-part series implementing reference backend selection for zero-downtime migrations between files and reftable backends in large repositories. The series is now in its final polishing stage with only minor documentation tweaks remaining.

The patch extends the `extensions.refStorage` configuration to support URI syntax for specifying both the backend type and location (e.g., `reftable://path/to/refs`). Key changes include:
- URI parsing and validation via `parse_reference_uri()`
- Worktree reference path resolution in `builtin/worktree.c`
- Comprehensive test coverage in new `t1423-ref-backend.sh` for:
  - Invalid URI formats
  - Unknown backends
  - Cross-backend operations between files and reftable
  - Relative and absolute path handling

Patrick Steinhardt's review identifies several small improvements needed:
- Typo fix for "worktress" -> "worktrees"
- Clarification around relative path resolution
- Suggestion to add tests for ref directories outside the repository
- Questions about dry-run migration behavior with payloads
- Request for more direct tests of specific format behaviors

The implementation builds on earlier work to make reference backends pluggable, with this patch specifically enabling runtime location control. All architectural concerns appear resolved at this point, with the discussion now focused on test coverage edge cases and documentation wording. The series is nearing final approval, having addressed substantive feedback from multiple reviewers including Patrick Steinhardt, Eric Sunshine, and Junio Hamano.
