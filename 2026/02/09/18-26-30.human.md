This is part of Adrian Ratiu's ongoing series to make Git hooks configurable via Git configuration, now focusing on the new `git hook list` subcommand. The patch introduces a way to view which hooks would run for a given event, currently showing only filesystem hooks (with plans to include config-based hooks in future patches).

Patrick Steinhardt's review suggests several improvements for the next iteration: using the passed `repo` parameter instead of `the_repository`, adding a `-z` mode for NUL-terminated output to handle paths with newlines, and improving test coverage with actual `.git/hooks` contents. Adrian acknowledges all points and indicates they'll be addressed in v2.

The discussion remains technical and constructive, with Patrick providing detailed feedback on implementation quality while Adrian demonstrates responsiveness to review comments. This patch appears to be a straightforward addition that will become more useful once config-based hooks are implemented in later series patches.
