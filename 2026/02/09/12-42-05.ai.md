Test infrastructure improvement in Patrick Steinhardt's series addressing CI failures on Windows/MSVC platforms related to ICONV support. This patch focuses on t4205 (log pretty formats tests) by restructuring how the tests handle character encoding.

The patch identifies two classes of tests in t4205 that were incorrectly marked with the ICONV prerequisite: those that output data as-is without reencoding, and those that use i18n.logOutputEncoding to reencode. Both were marked with ICONV because the test setup unconditionally used ISO-8859-1 encoding for initial commit messages, requiring UTF-8 conversion.

Key changes include:
1. Making the test encoding conditional on ICONV availability (using ISO-8859-1 when available, UTF-8 otherwise)
2. Removing the ICONV prerequisite from tests that don't actually need character conversion
3. Keeping ICONV only for tests that specifically exercise i18n.logOutputEncoding behavior

The changes maintain test coverage while making the tests more robust on platforms without the iconv(1) executable. This continues Patrick's broader effort to improve test reliability across different build configurations, particularly for Windows/MSVC environments where toolchain differences often expose test assumptions.
