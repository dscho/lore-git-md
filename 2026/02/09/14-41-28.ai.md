This is a refactoring patch in a series that unifies process ancestry tracing across platforms. The patch splits the Windows implementation into two phases: first collecting process names into a `strvec`, then formatting them as JSON. This prepares for patch 4/4 which will add the new `trace2_cmd_ancestry()` interface while maintaining backward compatibility with the existing JSON output.

Key changes:
- Replaces direct JSON writing with `strvec` collection in `get_processes()`
- Moves JSON formatting to the caller (`trace2_collect_process_info()`)
- Simplifies `get_ancestry()` to just handle process name collection
- Keeps the same cycle detection and depth limit (10 levels) as before

Derrick Stolee's review notes the JSON formatting could eventually be removed once tools migrate to the new ancestry interface, but agrees the transitional dual-emission approach is reasonable. The patch appears well-structured and maintains existing behavior while enabling the series' goal of cross-platform consistency.
