This is part of a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable), now in its final polishing phase with maintainer approval signaled. The series is technically complete with only minor documentation refinements remaining.

Patch 3/4 extends the `extensions.refStorage` config to support URI syntax (`<format>://<payload>`) for specifying both backend type and storage location. Key changes:

- Adds URI parsing to handle both format name alone (e.g. `reftable`) and full URI (e.g. `reftable:///path/to/refs`)
- Modifies worktree reference storage to use alternate paths when specified (`$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>`)
- Introduces `ref_storage_payload` field in `struct repository` to store the URI payload
- Adds comprehensive tests in t1423-ref-backend.sh covering URI validation and backend switching
- Documents the new URI format in config/extensions.adoc

The patch maintains backward compatibility while enabling future backends to support different payload schemes. Worktree integration required careful handling to ensure proper stub creation and Git directory detection.
