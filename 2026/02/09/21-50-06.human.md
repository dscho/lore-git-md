This is a build system patch addressing an issue with Meson's handling of documentation-generated headers. D. Ben Knoble follows up on Patrick Steinhardt's suggestion to improve how the build tracks dependencies for `config-list.h`.

The core problem is that the Meson build doesn't properly regenerate `config-list.h` when documentation files change, which can lead to stale configurations and test failures. The original patch attempted to solve this by explicitly listing dependencies, but Patrick pointed out this approach wouldn't catch newly added files.

The revised solution modifies `generate-configlist.sh` to output a dependency file listing all relevant `.adoc` files, similar to how compilers generate `.d` files. However, Knoble reports unexpected behavior where the dependency tracking doesn't work as intended - the `.d` file isn't created during normal builds, and the build sometimes gets stuck. The patch appears technically sound but seems to hit some Meson/ninja integration quirks that need debugging.

This is a focused build system improvement that would benefit anyone using Meson to build Git, particularly developers working on configuration documentation. The discussion shows careful attention to build correctness, though the current implementation may need more work to handle edge cases properly.
