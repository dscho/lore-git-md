This is a follow-up in the ongoing discussion about removing `the_repository` and `the_hash_algo` globals from `wt-status.c`, which has expanded into a broader conversation about worktree API design. Shreyansh Paliwal responds to Karthik Nayak's technical feedback about how main worktrees are currently identified (via NULL `worktree->id`) and stored in repositories.

The exchange confirms that while the current system uses NULL to mark main worktrees (with supporting functions like `get_main_worktree()`), this leads to complex NULL-handling throughout the code. Karthik points out additional complexity in the ref storage system where main worktrees are marked with a backslash. Shreyansh acknowledges needing deeper study of the worktree API before proposing changes, and plans to send a separate RFC for the cleanup once better prepared.

The thread shows the challenge of balancing immediate technical debt reduction (removing globals) with longer-term API improvements. Shreyansh's measured response suggests this may become a multi-phase effort, with the current patch series potentially proceeding while the worktree API redesign is explored separately. The discussion remains technical and collaborative, with participants working to understand the full implications before committing to a solution path.
