This is a feature patch series that enables flexible reference storage locations in Git, allowing users to specify alternate paths for storing references via both configuration and environment variables. The primary motivation is to support zero-downtime migrations between reference storage backends (files <-> reftable) in large repositories, particularly for GitLab's use case.

The series introduces two ways to specify reference storage:
1. Persistent configuration via `extensions.refStorage` which can now take a URI format (`<format>://<path>`)
2. Ephemeral override via the new `GIT_REFERENCE_BACKEND` environment variable

Key technical changes include:
- New `ref_storage_payload` field in `struct repository` to store the reference location
- Worktree reference handling that maintains stubs for compatibility
- URI parsing with strict validation
- Comprehensive test coverage in t1423-ref-backend.sh

The implementation has gone through multiple rounds of review from Patrick Steinhardt, Karthik Nayak, and others, with all substantive feedback addressed. Junio Hamano has signaled approval of the core design. The series is now in its final polishing phase with only minor documentation wording refinements remaining.

This represents a significant enhancement to Git's reference storage flexibility, particularly useful for large-scale deployments needing to minimize downtime during backend migrations. The careful attention to worktree handling and backward compatibility makes this a robust solution.
