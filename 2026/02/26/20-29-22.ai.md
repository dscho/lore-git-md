This is a refactoring patch from Junio C Hamano in response to Taylor Blau's RFC series on incremental MIDX/bitmap-based repacking. The patch is part of the larger geometric repacking effort but focuses on a small internal cleanup.

The change replaces hand-rolled string arrays in MIDX file handling with `string_list` structures, simplifying the code by:
- Eliminating manual memory management of string arrays
- Using standard string list operations instead of linear searches
- Reducing parameter passing since the list can be passed as a single struct

The patch touches two functions in midx.c that handle cleanup of MIDX files (`clear_midx_files_ext` and `clear_incremental_midx_files_ext`), converting their internal string storage to use Git's `string_list` API. While the commit message notes this could improve lookup performance, the main benefit is code simplification and maintainability.

This appears to be a straightforward improvement that aligns with the project's preference for using standard Git data structures where appropriate. The change is mechanical and unlikely to be controversial, though it may prompt discussion about whether similar cleanups should be made elsewhere in the MIDX code.
