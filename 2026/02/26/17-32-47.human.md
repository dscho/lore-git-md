This is the third iteration of a feature improvement to `git send-email`'s character encoding validation, from first-time contributor Shreyansh Paliwal. The patch series aims to replace the current length-based charset validation with proper semantic checking using Perl's `Encode::find_encoding()`, while also improving the prompt wording to avoid confusion.

The current version addresses feedback from Ben Knoble about code organization by extracting confirmation logic into a `confirm_ask()` helper function. Shreyansh is now seeking input on whether to further separate the encoding validation logic from the core prompting code. The patch has already incorporated several rounds of review feedback, including style fixes requested by maintainer Junio Hamano.

The changes improve robustness by validating charset names semantically rather than just checking their length, while maintaining backward compatibility. The prompt wording has been clarified to avoid misinterpretation as a yes/no question. This appears to be a well-considered improvement to a subtle but important edge case in email handling.
