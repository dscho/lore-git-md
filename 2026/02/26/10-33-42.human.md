Feature implementation for configurable branch comparisons in `git status`. This is the second and final patch in Harald Nordgren's series, adding the `status.compareBranches` configuration option after the preparatory refactoring in patch 1/2.

The new config allows users to specify multiple branch comparisons in `git status` output, supporting both `@{upstream}` (the default) and `@{push}` tracking branches. This is particularly useful for triangular workflows where the upstream and pull branches differ. The implementation includes:

- A new `status.compareBranches` config accepting space-separated values (`@{upstream}` and/or `@{push}`)
- Context-aware advice messages (pull advice for upstream, push advice for push branch)
- Duplicate detection to avoid showing the same comparison twice
- Extensive test coverage (310 new test lines) for various workflow scenarios
- Backward compatibility with the default `@{upstream}` behavior

The patch has undergone 28-iteration review process and received final approval from Junio Hamano after addressing style and organization feedback. It represents a successful first contribution from Harald Nordgren, demonstrating persistence through the mailing list workflow. The comprehensive test suite ensures robust handling of edge cases while maintaining backward compatibility.
