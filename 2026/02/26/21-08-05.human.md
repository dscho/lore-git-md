This is a final memory leak fix for the UTF-8 alias subsection feature, now queued for the `next` integration branch. The patch series addresses two memory leaks in the alias listing functionality that were introduced by earlier changes in the feature's development. The leaks occurred when callers cleared string lists without properly freeing the allocated `util` pointers.

Junio Hamano confirms the fixes look correct and marks the topic ready for `next`, indicating this is likely the last round of changes before final merging. The only remaining open issue is a regression affecting dot-prefixed aliases (like `.foobar`), which impacts Johannes Schindelin's workflow but is not addressed in this series.

The changes are straightforward: patch 3 updates `string_list_clear()` calls to free the `util` pointers in both `git.c` and `help.c` paths, while patches 1-2 contain minor whitespace and documentation fixes from the earlier version. With these memory issues resolved and Junio's approval, the UTF-8 alias support appears nearly complete after multiple iterations of review and refinement.
