This is a bugfix patch addressing a memory leak in Git's filesystem monitoring (fsmonitor) daemon. The patch is part of a larger series (v7 02/10) introducing Linux support for fsmonitor using inotify, bringing it to parity with existing Windows and macOS implementations.

The specific issue fixed here is that the `state.cookies` hashmap, used to track filesystem events, was being initialized during daemon startup but never properly cleaned up when the daemon shuts down. Paul Tarjan adds the missing `hashmap_clear()` call in the cleanup path to prevent memory leaks.

This is a straightforward fix that follows the pattern of the surrounding code, which already includes similar cleanup for other resources like mutexes and condition variables. The patch is small (just one line added) and focused, with a clear commit message explaining both the problem was and how it's being fixed.

As part of the larger fsmonitor series, this contributes to the stability and reliability of the new Linux implementation. The series has undergone extensive review over multiple iterations, with this particular issue being caught during later testing rounds.
