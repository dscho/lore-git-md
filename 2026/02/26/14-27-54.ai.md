This is a refactoring patch in the ongoing `git replay` revert capability series. Phillip Wood proposes an alternative implementation for the shared revert message formatting functionality that Siddharth Asthana introduced in v3 of the series.

Phillip suggests moving *all* revert message formatting into the new `sequencer_format_revert_message()` helper function, rather than splitting it between the helper and caller as in Siddharth's version. His approach:
- Takes a `repository` parameter (consistent with Git's move away from `the_repository` global)
- Uses a simple `bool` for the commit reference flag (can be expanded later if needed)
- Fully encapsulates the "Revert"/"Reapply" logic and reference formatting
- Updates `do_pick_commit()` to use the consolidated helper

The change would make the calling code cleaner while maintaining the same behavior. Phillip notes this could be split into two commits - one for the repository parameter addition, one for the full message formatting consolidation.

This is a refinement to the technical implementation that emerged from earlier discussion with Junio Hamano and others about API boundaries and configuration handling. The patch doesn't address the higher-level interface design questions (subcommands vs flags) that are still being debated in parallel.
