Refactoring patch preparing for configurable branch comparisons in `git status`. This is the first of two patches in Harald Nordgren's series that will allow users to configure which branches `git status` compares against (defaulting to just @{upstream} for backward compatibility). The patch extracts the branch comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` function, making the code more modular in preparation for the feature implementation in the next patch.

The changes:
- Moves the core comparison message generation into a standalone function
- Renames variables for clarity (e.g., `sti` -> `cmp_fetch`)
- Simplifies the control flow in `format_tracking_info()`
- Keeps all existing behavior exactly the same, just better organized

This is a clean, mechanical refactoring with no behavior changes - exactly what you'd want in a preparation patch. The diff shows careful attention to preserving all the existing message formats and advice hints while making the code more maintainable.
