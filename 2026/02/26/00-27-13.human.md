This is a feature patch series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS backends. The series represents the 7th iteration of this work, now ready for final submission after addressing extensive review feedback.

The implementation uses inotify rather than fanotify since it doesn't require elevated privileges, though it needs separate watches per directory. Key technical aspects include:
- Recursive directory watching via inotify_init1(O_NONBLOCK)
- Rename tracking through IN_MOVED_FROM/TO event cookies
- Remote filesystem detection via statfs() (excluding NFS/SMB by default)
- Fallback to $HOME/.git-fsmonitor-* when .git is remote
- Timeout handling for event delivery using pthread_cond_timedwait

The series also fixes memory leaks in the daemon code and significantly refactors the implementation to deduplicate Unix platform logic between macOS and Linux. New test coverage verifies event delivery and handles edge cases like rapid directory creation.

Changes since v6 focus on build system improvements:
- Introduced FSMONITOR_OS_SETTINGS variable to unify Unix platform handling
- Moved path utilities to FSMONITOR_DAEMON_BACKEND since they're platform-specific
- Removed redundant includes and improved commit messages
- Fixed minor comment wording per Junio's review

The implementation appears stable in Junio's 'seen' branch with production testing reported by Paul Tarjan. The series represents a major step forward in cross-platform fsmonitor support, with careful attention to edge cases and performance considerations.
