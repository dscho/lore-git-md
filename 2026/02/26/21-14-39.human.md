This is part of a feature series enhancing `git repo info` with structured path reporting. Patch 2/10 in v4 adds 13 new path-related fields that expose repository locations like the git directory, worktree, and object storage paths through a clean programmatic interface.

The patch introduces dedicated helper functions for each path type, using `repo_get_*` and `repo_git_path_replace` APIs to avoid global state. Paths are added under the `path.*` namespace, including both core locations (git-dir, toplevel) and specialized paths (hooks, grafts, shallow file). The implementation handles edge cases like superprojects and uses `strbuf` for memory safety.

This provides a more direct alternative to shelling out to `git rev-parse` for common path queries, with the added benefit of consistent output formatting. The changes align with the series' goal of making repository metadata more scriptable while following modern Git practices around repository context passing.
