This is a performance and reliability patch for the fsmonitor thread, specifically addressing file descriptor inheritance in long-running processes. It adds a new `close_fd_above_stderr` flag to `struct child_process` that automatically closes file descriptors 3 and above in child processes after forking but before exec. This prevents long-running daemons (like the fsmonitor daemon) from inheriting potentially problematic file descriptors from their parent processes.

The implementation uses `sysconf(_SC_OPEN_MAX)` to determine the maximum file descriptor number, with a safety cap at 4096 to avoid excessive iteration on systems with very high limits. It preserves the child notifier file descriptor (used for process communication) while closing all others above stderr.

This change helps prevent resource leaks and interference between processes, particularly important for the fsmonitor daemon which runs persistently. The patch is well-contained, touching only the run-command infrastructure with clear documentation of the new field. As part of the larger fsmonitor effort, this addresses one of the final technical concerns raised in earlier reviews.
