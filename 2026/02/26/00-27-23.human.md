This is the final patch in a series adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify. The patch focuses on process management improvements for the fsmonitor daemon.

The key changes address two issues that can cause hangs in CI/test environments:
1. The daemon now closes inherited file descriptors above stderr (using a new `close_fd_above_stderr` flag) to prevent holding open pipes from parent processes
2. When running detached, the daemon creates a new session via `setsid()` to avoid being tied to the parent's process group, which could cause shells with job control to wait indefinitely

Additionally, the patch adds a 30-second timeout to the daemon stop command and makes related test improvements. These changes complete the Linux fsmonitor implementation by ensuring reliable process management, particularly in automated testing scenarios.

The patch represents the culmination of a long series (now at v7) that has addressed numerous technical challenges around filesystem watching, event handling, and cross-platform compatibility. This final piece focuses on robustness in process management, particularly important for CI systems and test environments.
