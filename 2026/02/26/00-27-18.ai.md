This is part of the ongoing fsmonitor series adding Linux support via inotify, now in its seventh iteration. The patch focuses on code deduplication between Unix platforms (macOS and Linux) for the fsmonitor IPC path logic.

The key change is renaming `fsm-ipc-darwin.c` to `fsm-ipc-unix.c` since the IPC path handling is shared between macOS and Linux. It introduces a new `FSMONITOR_OS_SETTINGS` build variable set to "unix" for both platforms, while keeping `FSMONITOR_DAEMON_BACKEND` platform-specific. The patch also adds a missing BUG guard for NULL worktree that was absent in the macOS version.

Build system changes propagate this unification across Makefile, CMake, and meson configurations. The path utilities remain platform-specific (now tied to `FSMONITOR_DAEMON_BACKEND` rather than `FSMONITOR_OS_SETTINGS`), while the IPC logic becomes shared Unix code. This is a clean refactoring that reduces duplication while maintaining the existing functionality.

The change is part of a larger effort to bring Linux fsmonitor support to parity with existing macOS and Windows implementations, with careful attention to platform differences and shared infrastructure. The patch follows earlier feedback about code organization and represents a logical step in the Unix-side implementation.
