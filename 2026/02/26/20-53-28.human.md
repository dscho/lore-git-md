This is a bugfix patch addressing memory leaks in the UTF-8 alias subsection implementation, which is currently in the `next` branch. The patch fixes two memory leak paths in the alias listing functionality that were identified by Jacob Keller.

The leaks occur when:
1. `git.c` lists commands with `string_list_clear(&list, 0)` which didn't free util pointers
2. `help.c` deduplicates entries with `string_list_sort_u(list, 0)` which leaked util pointers of discarded duplicates

The fix is straightforward - changing the `free_util` parameter from 0 to 1 in both cases. This is the final patch in a series that has already addressed other issues like empty subsection handling and documentation formatting. Junio Hamano has confirmed the memory leak fixes, indicating this series is nearing completion.

The only remaining issue before full merge is a regression affecting dot-prefixed aliases (like `.foobar`), which impacts Johannes Schindelin's workflow. That will need to be resolved separately. This patch represents solid progress in cleaning up the implementation before the feature graduates to `master`.
