This thread discusses a small but useful improvement to gitk, Git's graphical repository browser, allowing users to customize link colors in the Preferences dialog. The change was proposed by Wang Zichong to address readability issues in dark themes where default link colors might not provide sufficient contrast.

The patch adds a "Link color" option following gitk's existing color configuration pattern, modifying Tcl/Tk code in the `prefspage_colors` and `prefspage_set_colorswatches` procedures. Johannes Sixt, gitk's maintainer, has reviewed the change and generally approved it while suggesting minor improvements: shortening the button label from "Link color" to just "Links" for better dialog layout, and adjusting the commit message to use imperative mood.

With these small wording tweaks, the patch appears ready for inclusion. The discussion shows typical maintainer guidance on style points while accepting the technical approach, and since the change is well-contained to gitk's UI code with no impact on core Git functionality, it should proceed smoothly once the suggested edits are made.
