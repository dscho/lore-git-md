Feature patch for gitk's color customization. This change adds a new "Link color" option to gitk's Preferences dialog, allowing users to configure the foreground color of links in the interface. The motivation comes from dark-theme users who find the default link color hard to read against dark backgrounds.

The patch modifies the Tcl/Tk code that handles gitk's color preferences, adding UI elements for the link color alongside existing color controls. It touches two key procedures: `prefspage_colors` (which builds the color preferences page) and `prefspage_set_colorswatches` (which updates the color swatches). The implementation follows gitk's existing pattern for color configuration, adding a new label and button pair that lets users pick and preview the link color.

This appears to be a straightforward usability improvement with no obvious technical drawbacks. The change is small (10 lines net) and well-contained to gitk's UI code. The commit message clearly explains the motivation and benefit to users. Since gitk is maintained separately from core Git (by Johannes Sixt), this patch would likely be routed to him for review and potential inclusion.
