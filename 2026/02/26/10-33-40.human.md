Feature patch series for configurable branch comparisons in `git status`, now ready for merging after extensive review.

This is the final version of Harald Nordgren's patch series adding a `status.compareBranches` configuration option that lets users specify which branches to compare in `git status` output. The implementation focuses on supporting `@{upstream}` and `@{push}` comparisons while deferring more complex branch matching scenarios. After 28 iterations and two months of review, the patches have been polished to address all feedback and are now cleared for merging by Junio Hamano.

The first patch refactors the existing `format_branch_comparison()` function in remote.c to prepare for the new functionality. The second patch implements the core feature, adding the new config option that accepts a space-separated list of branch specifications. The default behavior remains unchanged (comparing only `@{upstream}`) for backward compatibility. The implementation includes a warning system for unsupported values and handles triangular workflows with appropriate advice messages.

The test coverage is extensive (337 new test lines in t6040-tracking-info.sh) and verifies various scenarios including: duplicate branch handling, different remote configurations, remapped refspecs, and combinations of ahead/behind/diverged states. The final version incorporates Junio's style fixes (brace usage, line length), renamed flags (`ENABLE_ADVICE_*` to `USE_ADVICE_*`), and improved test organization.

This represents a successful first-time contribution from Harald Nordgren, who navigated Git's mailing list workflow through the extended review process. The feature is technically sound with comprehensive test coverage and maintains backward compatibility while providing useful new functionality for users who want to see both upstream and push branch comparisons in their status output.
