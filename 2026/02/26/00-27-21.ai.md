This is a test patch for the Linux fsmonitor implementation, part of the ongoing effort to bring Linux support to parity with existing Windows and macOS backends. The patch adds two key tests to verify the inotify-based filesystem monitoring works correctly.

The first test (`verify_fsmonitor_works`) is a smoke test that checks whether the filesystem actually delivers inotify events to the daemon. This catches cases where watches succeed but events aren't delivered (e.g., on overlayfs with older kernels). The test uses timeouts to prevent hangs and skips the entire test file if event delivery fails.

The second test (`rapid nested directory creation`) exercises a race condition where directory watches may be added concurrently during event processing and recursive scanning. This verifies the daemon correctly handles EEXIST errors that can occur when IN_MASK_CREATE is available and queued events arrive during watch registration.

The patch also includes several reliability improvements:
- Adds a 30-minute timeout for fsmonitor tests in meson builds to prevent CI hangs
- Improves process cleanup with better timeout handling and process group management
- Fixes potential fd leaks in test helper processes
- Adds platform-specific handling for process group IDs

This is patch 8/10 in the v7 series implementing Linux fsmonitor support. The tests complement the core implementation by verifying edge cases that were problematic in earlier versions, particularly around event delivery reliability and race conditions during rapid directory operations. The test infrastructure changes (timeouts, process management) address issues found during CI testing of previous versions.
