This is a follow-up discussion in the ongoing thread about configurable cover letter formatting for `git format-patch`. The specific focus here is on when to validate the format string - early in `cmd_format_patch()` or later in `make_cover_letter()`.

Junio C Hamano responds to Mirko Faina's question about whether to keep the early format validation check. He suggests that while early validation could theoretically prevent wasted work, the validation should fundamentally live in `make_cover_letter()` since it's the function that actually uses the format. Duplicating the check isn't necessary unless it provides clear user benefit by failing faster.

The exchange reveals an implementation detail that `make_cover_letter()` is called after the cover letter file creation has already begun, which explains Mirko's original motivation for the early check. However, Junio's position is that unless the early check significantly improves the user experience by failing before any visible action is taken, the validation should remain in the function that actually processes the format.

This continues the thread's theme of balancing implementation cleanliness with practical considerations. The discussion remains technical and constructive, with Junio providing clear guidance while leaving room for the author to make the final call based on actual user impact. No new functionality is being proposed here - it's purely about refining the existing approach to validation timing.
