This is a feature/bugfix patch for `git send-email` that improves the handling of character encoding prompts when non-ASCII content is detected. The patch comes from first-time contributor Shreyansh Paliwal and has gone through several iterations with review feedback from Ben Knoble and Junio C Hamano.

The core issue addresses a confusing user experience where the current prompt for 8-bit encoding could be misinterpreted as a yes/no question, leading to malformed email headers. The patch makes several key improvements:

1. Replaces the simple length-based validation with proper charset verification using Perl's `Encode::find_encoding()`
2. Introduces a new helper function `confirm_ask()` to handle confirmation prompts consistently
3. Clarifies the prompt wording to explicitly request an encoding name rather than risk yes/no confusion
4. Maintains backward compatibility while improving error handling

The new flow clearly indicates when an invalid charset is entered while still allowing users to proceed if they choose. The implementation uses core Perl modules to avoid new dependencies and follows Git's portability constraints.

This appears to be a well-considered solution to a real usability issue, with thorough test updates and careful attention to code organization. The patch has evolved through review feedback and now addresses all technical concerns raised, with only minor style refinements remaining. It builds on prior work from 2015 while significantly improving the robustness of the validation.
