This is a refactoring patch from Junio C Hamano that improves the `strvec` initialization infrastructure, building on Taylor Blau's earlier patch in the MIDX/bitmap repacking series. The change makes `strvec_init()` a wrapper around the new `strvec_init_alloc()` function while preserving the existing optimization for empty strvecs.

Junio points out that the original implementation didn't share the empty-strvec optimization between the two initialization functions, which could lead to inconsistencies. His version ensures both initialization paths properly handle the zero-allocation case by centralizing the logic in `strvec_init_alloc()`. The change is small (15 lines) but improves maintainability of the strvec API by eliminating duplicate initialization logic.

This patch is part of the infrastructure work supporting Taylor Blau's larger geometric repacking series, specifically preparing the string handling code to be used by the MIDX repacking machinery. The change is straightforward and unlikely to be controversial, though it may prompt discussion about whether similar cleanups should be applied elsewhere in the codebase.
