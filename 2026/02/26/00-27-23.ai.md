This is the final patch in a 10-part series adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify. The patch focuses on process management improvements for the fsmonitor daemon.

The key changes address two issues that can cause hangs in CI/test environments:
1. The daemon now closes inherited file descriptors above stderr (via a new `close_fd_above_stderr` flag in `struct child_process`) to prevent holding open pipes from the parent process
2. When running detached, the daemon creates a new session via `setsid()` to avoid being tied to the parent's process group, which some shells (like bash) wait on indefinitely

The patch also adds a 30-second timeout to the daemon stop command and makes related test improvements. These changes complete the Linux fsmonitor implementation by ensuring reliable process management, particularly in automated test environments where inherited FDs and shell job control can cause issues.

The implementation builds on the extensive fsmonitor infrastructure added in previous patches, including the inotify-based monitoring, Unix domain socket IPC, and platform-specific settings handling. This final piece addresses the last remaining edge cases for production readiness.
