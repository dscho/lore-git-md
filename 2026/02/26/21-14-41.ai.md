Feature patch adding object size metrics to the repository structure reporting series.

This is patch 4/10 in Eslam Reda Ragheb's v4 series enhancing `git repo info` with structured repository reporting. While earlier patches focused on path reporting, this one introduces metrics for maximum object sizes - both inflated (in-memory) and on-disk representations - tracked per object type (commits, trees, blobs, tags) and overall maximums. The implementation extends the existing object counting infrastructure to track these maxima during reachability walks.

The patch adds two new `object_values` structs to track maximum sizes (`max_inflated_sizes` and `max_disk_sizes`), with helper functions to compute the overall maximum across types. These metrics are exposed in both the structured table output (with descriptive labels) and the key-value format (for scripting). The counting logic handles negative disk sizes by skipping those objects, though this edge case isn't explicitly documented.

The changes integrate cleanly with the series' existing reporting framework, maintaining the same output formats and memory management patterns. The metrics complement Justin Tobler's parallel structural metrics work, though this patch focuses specifically on size outliers rather than aggregate statistics. The implementation appears solid, with proper type handling and BUG() assertions for invalid object types, though test coverage for the new metrics isn't visible in this patch (likely coming in a later series installment).
