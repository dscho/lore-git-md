This is a patch in the fsmonitor thread that adds a new feature to the run-command infrastructure. It introduces a `close_fd_above_stderr` option to `struct child_process` that automatically closes file descriptors 3 and above in child processes after forking but before exec.

The change is motivated by the fsmonitor daemon's need to prevent inheriting unwanted file descriptors from parent processes, particularly in test environments. The implementation uses `sysconf(_SC_OPEN_MAX)` to determine the maximum file descriptor number, with a safety cap at 4096 to avoid excessive iteration. It preserves the child notifier fd (used for process communication) while closing all others above stderr.

This is a supporting change for the larger fsmonitor effort, specifically addressing file descriptor inheritance issues that could affect the long-running fsmonitor daemon process. The patch is well-contained and follows Git's established patterns for process handling, with clear documentation of the new field in `run-command.h`.

Key technical details:
- Adds new `close_fd_above_stderr` bitfield to `struct child_process`
- Implements fd closing loop in `run_command.c` with sysconf-based upper bound
- Preserves child_notifier fd (used for inter-process communication)
- Caps iteration at 4096 fds for safety
- Documents the purpose and behavior of the new option
