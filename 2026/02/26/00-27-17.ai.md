This is a bugfix patch in the fsmonitor series, specifically addressing a potential hang condition in the filesystem monitoring daemon. The patch introduces a timeout mechanism for cookie file synchronization between the fsmonitor client and daemon.

The change replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()`. This prevents indefinite hangs when filesystem events fail to be delivered (a known issue on certain container/overlay filesystems where inotify watches succeed but events never arrive). If the timeout fires, the daemon will report an error and allow the client to proceed with a full scan rather than blocking forever.

Key technical details:
- Uses `gettimeofday()` and `timespec` to set a 1-second timeout
- Preserves existing locking semantics while adding timeout handling
- Maintains the same error reporting through `FCIR_ERROR` result code
- Adds trace logging for timeout events
- Keeps the same cleanup path via `done` label

This patch builds on the extensive fsmonitor work that has been through multiple review iterations, with Patrick Steinhardt and others providing detailed feedback on earlier versions. The change addresses a real-world reliability issue while maintaining the existing behavior in normal cases. The implementation is straightforward and follows the pattern of defensive programming seen elsewhere in the fsmonitor code.
