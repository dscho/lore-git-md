This is a bugfix patch in the fsmonitor series, addressing a potential hang when waiting for filesystem events on certain container/overlay filesystems. The patch introduces a timeout mechanism for the cookie wait in Git's filesystem monitoring daemon.

The change replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()`. This prevents indefinite hangs when filesystem events aren't delivered (which can happen on some container/overlay filesystems where inotify watches succeed but events never arrive). If the timeout fires, the daemon will report an error and allow the client to proceed with a full scan rather than blocking forever.

The implementation carefully handles timing calculations and error conditions, including proper conversion between time formats (timeval to timespec). The patch maintains all existing functionality while adding the new safety mechanism, and includes trace logging for debugging timeout cases.

This is the fourth patch in the seventh iteration of the fsmonitor Linux support work, showing the series is quite mature with multiple rounds of review. The change addresses a real-world reliability issue that could affect users on certain filesystems, making the fsmonitor feature more robust.
