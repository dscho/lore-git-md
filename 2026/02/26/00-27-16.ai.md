This is a platform compatibility patch adding Windows support for timed condition variable waits, part of the larger fsmonitor effort to bring Linux support to parity with existing Windows and macOS backends.

The patch implements `pthread_cond_timedwait()` in Git's Windows pthread compatibility layer by wrapping Windows' `SleepConditionVariableCS()` API. It converts the absolute timeout from `timespec` to milliseconds relative to the current time, handling the case where the deadline has already passed. The implementation properly maps Windows error codes to POSIX equivalents, including `ERROR_TIMEOUT` to `ETIMEDOUT`.

This enables bounded waits on condition variables in the fsmonitor IPC synchronization code, preventing hangs that could occur with indefinite waits. The change is straightforward and follows the pattern of Git's existing Windows pthread emulation layer. It's a focused addition that fills a gap in the compatibility layer rather than modifying core functionality.

The patch is part of the v7 series addressing fsmonitor Linux support, specifically enabling timeout handling that was identified as needed during testing. It builds on previous work to unify Unix platform implementations while maintaining Windows-specific behavior. The implementation appears correct and well-contained, with no obvious issues in the conversion between time formats or error handling.
