This is a feature improvement for `git send-email` that addresses usability and validation of character encoding prompts. The patch comes from first-time contributor Shreyansh Paliwal and has gone through several iterations with feedback from Ben Knoble and Junio Hamano.

The core issue is that `git send-email` currently uses a length-based heuristic (minimum 4 characters) to validate charset names when non-ASCII content is detected, which can allow invalid encodings through. The patch replaces this with proper semantic validation using Perl's `Encode::find_encoding()` while maintaining user control through confirmation prompts.

Key changes in v3:
- Extracts confirmation logic into a new `confirm_ask()` helper
- Implements proper charset validation while relaxing input rules (accepts any non-blank string)
- Improves prompt wording to avoid yes/no confusion ("Declare which 8bit encoding to use [default: UTF-8]?")
- Shows warnings for invalid charsets but still allows override
- Updates tests to match new prompt text
- Follows Git style conventions with explicit braces

The implementation builds on a 2015 fix that first addressed this issue, while significantly improving both the technical validation and user experience. The patch appears well-considered, with thorough commit message documentation and test coverage. It addresses all previous review feedback while maintaining backward compatibility and following project conventions.

This represents the third iteration of a focused improvement that has been carefully refined through mailing list discussion. The remaining open question from Ben Knoble about separating charset validation from core prompting logic appears to be the last design consideration before potential merging.
