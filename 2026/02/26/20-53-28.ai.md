This is a bugfix patch addressing memory leaks in the UTF-8 alias subsection implementation, which is currently in the `next` branch as part of a larger series. The patch fixes two memory leak paths in the alias listing functionality that were identified by Jacob Keller.

The leaks occur when:
1. `git.c` clears its string list without freeing the util pointers (fixed by changing `string_list_clear(&list, 0)` to `string_list_clear(&list, 1)`)
2. `help.c` deduplicates alias entries without freeing the util pointers of discarded duplicates (fixed by changing `string_list_sort_u(list, 0)` to `string_list_sort_u(list, 1)`)

This is the third patch in a v2 series that appears to be final cleanup before the UTF-8 alias subsection feature can be fully merged. The thread context shows this series is nearly complete, having addressed all identified issues except for one remaining regression with dot-prefixed aliases that affects Johannes Schindelin's workflow. Junio Hamano has already confirmed the memory leak fixes in this patch look correct.

The changes are minimal but important for correctness - each just changes a single parameter to ensure proper cleanup of heap-allocated alias command strings stored in the util pointers. The patch maintains all existing functionality while plugging the leaks. With this fix, the series appears ready for final merge once the dot-prefixed alias regression is resolved.
