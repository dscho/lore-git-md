This is a feature patch series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The series represents the 7th iteration of this work, now ready for final submission after addressing extensive review feedback.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches, rename detection via event cookies, and remote filesystem detection. Key technical aspects include:
- Recursive directory watching with inotify_init1(O_NONBLOCK)
- Bidirectional watch descriptor <-> path mappings using hashmap
- Statfs()-based remote filesystem detection (NFS/SMB)
- Fallback to $HOME/.git-fsmonitor-* for IPC sockets when .git is remote
- Timeout handling for cookie waits using pthread_cond_timedwait()
- Consolidated Unix domain socket path handling between macOS and Linux

The series also fixes memory leaks in the platform-independent daemon code and deduplication of IPC/settings logic shared between macOS and Linux. Changes since v6 include:
- Introduced FSMONITOR_OS_SETTINGS build variable for Unix platforms
- Removed V9FS_MAGIC from remote filesystem detection
- Fixed cookie wait comment wording
- Rewrote commit messages for IPC/settings dedup patches

The implementation has been thoroughly tested, including stress tests for rapid directory creation and event delivery verification. It builds on prior work from PRs #1352 and #1667, now addressing all review feedback and showing production stability in large deployments. The series is well-structured into 10 focused patches with clear commit messages and comprehensive test coverage.
