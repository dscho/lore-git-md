This is a refactoring patch in the ongoing `git replay` revert capability series. Phillip Wood proposes an alternative implementation for the shared revert message formatting function that Siddharth Asthana introduced in v3 of the series.

Phillip suggests moving all revert message formatting into the new `sequencer_format_revert_message()` helper, including the logic that handles both regular reverts and revert-of-revert cases. His version differs from Siddharth's by:
- Taking a `repository` parameter for the commit reference formatting
- Using a simple boolean for the reference flag rather than the full options struct
- Consolidating all message generation in one function rather than splitting it between helper and caller

The patch maintains the same functionality while potentially making the interface cleaner and more self-contained. Phillip notes this could be split into two commits - one for the repository parameter addition and one for the message formatting consolidation.

This is a refinement of the technical implementation that emerged from earlier discussion, showing the careful attention being paid to API boundaries and function responsibilities in this feature. The change doesn't affect the user-facing behavior but improves the internal code structure.
