Feature implementation for configurable branch comparisons in `git status`. This is the second and final patch in Harald Nordgren's series, implementing the `status.compareBranches` configuration option after the preparatory refactoring in patch 1/2.

The patch adds a new config option that allows users to specify multiple branch comparisons in `git status` output, supporting `@{upstream}` and `@{push}` as values. The implementation handles various workflow scenarios including triangular workflows where upstream and push branches differ, with appropriate context-aware messages (showing pull advice only for upstream comparisons, push advice for push comparisons, etc.).

Key technical aspects:
- New `resolve_compare_branch()` helper resolves branch names to full refs
- Enhanced `format_branch_comparison()` now takes flags to control which advice messages to show
- Uses string lists to process multiple branch comparisons while deduplicating with a strset
- Maintains backward compatibility by defaulting to `@{upstream}` behavior when unconfigured
- Includes extensive test coverage (310 lines in t6040-tracking-info.sh) for various scenarios:
  * Duplicate branch handling
  * Different remote configurations
  * Remapped refspecs
  * Combinations of ahead/behind/diverged states
  * Triangular workflows
  * --no-ahead-behind output

The implementation follows Jeff King's proposed middle path from earlier discussion, focusing exclusively on `@{upstream}` and `@{push}` comparisons while deferring more complex branch matching scenarios.
