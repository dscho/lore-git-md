This is part of the ongoing fsmonitor series adding Linux support for filesystem monitoring. Patch 6/10 focuses on build system consolidation, renaming the macOS-specific settings file to a more generic Unix version and unifying the build configuration.

The patch renames `fsm-settings-darwin.c` to `fsm-settings-unix.c` since the logic applies to all Unix platforms, not just macOS. It improves path handling by using `xstrdup()` and `dirname()` for safer string manipulation, and adds "vfat" to the list of incompatible filesystems that can't support Unix domain sockets. The build system changes propagate this unification, setting `FSMONITOR_OS_SETTINGS=unix` for macOS in `config.mak.uname` and simplifying the conditional logic in Makefile, CMake, and meson build files.

This is a straightforward refactoring that follows from earlier patches in the series that unified the IPC handling between macOS and Linux. The changes are mechanical but important for maintainability, reducing duplication between the Unix platforms. The patch appears well-tested as part of the larger fsmonitor series, which has undergone multiple iterations of review.
