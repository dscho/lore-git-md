This is a feature improvement for `git send-email`'s character encoding validation, now in its third iteration with maintainer feedback. The patch focuses on properly validating charset names when users input non-ASCII content in email subjects, replacing the previous length-based heuristic with semantic validation using Perl's `Encode::find_encoding()`.

Junio confirms that the Encode module dependency is acceptable since it's already used elsewhere in Git (gitweb and git-svn) and comes with standard Perl installations. This addresses one of the key open questions from previous reviews. The validation now properly checks if a charset name is actually supported rather than just verifying its length.

The patch maintains backward compatibility while improving the interactive prompt flow. It preserves the non-interactive path unchanged and follows Git's style guidelines with explicit braces. The discussion has evolved through multiple rounds of review regarding prompt wording, code organization, and validation strictness, with Shreyansh Paliwal iterating based on feedback from Ben Knoble, Philip Oakley, and Junio.

Remaining considerations include whether to keep the extracted `confirm_ask()` helper function or refactor to use the existing `ask()` function, and finalizing the exact prompt wording. The implementation builds on Git's email standards support (RFC 2047) while improving usability and maintaining portability.
