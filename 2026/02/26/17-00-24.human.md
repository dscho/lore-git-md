This is a follow-up to the UTF-8 alias subsection series, addressing memory leaks in the alias listing functionality. Junio C Hamano points out two locations where string lists containing alias names were not properly freed - in `git.c` and `help.c`. The proposed fix changes the `string_list_clear()` calls to free the string contents (setting the free_util parameter to 1).

The patches are part of a larger effort to support UTF-8 in Git config subsections (like `[alias "förgrena"]`) while maintaining backward compatibility. This particular email focuses on cleaning up memory management in the alias listing code paths that were modified as part of that feature. The changes look straightforward and address a real issue, though as Junio notes, the original author should verify the solution before resubmitting.

The thread indicates this is one of the final issues being resolved before the series can be fully merged, with only a documentation formatting issue and a regression with dot-prefixed aliases remaining as open items. The memory leak fixes appear uncontroversial and well-contained.
