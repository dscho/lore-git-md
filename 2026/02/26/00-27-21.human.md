This is a test patch for the Linux fsmonitor implementation, part of the ongoing effort to bring filesystem monitoring support to Linux (matching existing Windows and macOS capabilities). 

The patch adds two key tests for the Linux fsmonitor daemon. First, a smoke test verifies that the filesystem actually delivers inotify events - some configurations (like older overlayfs) accept watches but never deliver events. The test detects this early to skip the entire test file if needed. Second, a stress test exercises rapid nested directory creation to catch race conditions where directory watch registration might conflict with queued events.

The tests include platform-specific handling - generous timeouts for CI environments, process group cleanup for background daemons, and proper watchdog for hanging processes. The implementation builds on previous iterations that fixed memory leaks, crash bugs, and platform unification between macOS and Linux backends.

This appears to be a well-considered addition to the test suite, addressing real-world edge cases that could affect reliability. The patch follows the project's testing conventions while adding necessary Linux-specific validation for the new fsmonitor backend.
