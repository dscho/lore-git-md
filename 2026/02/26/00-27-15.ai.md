This is a bugfix patch addressing a memory leak in Git's filesystem monitoring (fsmonitor) daemon implementation. The patch is part of a larger series (v7 02/10) introducing Linux support for fsmonitor using inotify.

The specific issue fixed here involves the `state.cookies` hashmap in the fsmonitor daemon, which tracks filesystem event cookies for rename synchronization. While the hashmap was properly initialized during daemon startup, it wasn't being cleared during shutdown, leading to a memory leak. Paul Tarjan's patch adds the missing `hashmap_clear()` call in the cleanup path.

This is a straightforward fix that follows the pattern already established in the code for proper resource cleanup. The patch is minimal (just one line added) and clearly targeted at a specific issue identified during the development of the Linux fsmonitor backend. It demonstrates good attention to detail in resource management for this long-running daemon process.

The change is part of a well-tested series that has gone through multiple iterations (now at v7) with thorough review from Patrick Steinhardt and others. The memory leak being fixed here was likely caught during that rigorous review and testing process.
