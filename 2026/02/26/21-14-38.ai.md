This is the first patch in a 10-part series introducing enhanced repository path reporting functionality to `git repo info`. The series is part of a larger effort to improve repository introspection capabilities, coordinated with Justin Tobler's parallel work on structural metrics.

The patch introduces a `struct repo_info` to encapsulate repository state (repository pointer and prefix) and threads this context through value lookups and field printing functions. This removes direct coupling to global repository state, aligning with the ongoing `the_repository` removal effort. The key technical changes include:

1. Adding category key support that expands requests like "layout" to all matching "layout.*" fields while maintaining backward compatibility with explicit key requests
2. Refactoring value lookup functions to use the new context structure
3. Implementing proper error handling for unknown keys/categories

The implementation shows careful attention to memory management through `strbuf` usage and maintains the existing output formats (key-value pairs). Test coverage in t1900-repo.sh verifies the new category expansion behavior alongside existing functionality.

This foundational change enables the subsequent patches in the series to build out comprehensive path reporting features while keeping the codebase maintainable. The patch appears production-ready with thorough consideration of edge cases and clear documentation of the new category expansion rules.
