Feature patch series adding path reporting capabilities to `git repo info`. This is the fourth iteration of Eslam Reda Ragheb's work, now focused solely on path reporting after splitting out structural metrics into a separate series.

The series introduces several key improvements to `git repo info`:
- Category-aware key expansion (e.g. "layout" expands to "layout.*")
- New path-oriented keys (path.*) for common repository locations
- A `--path-format` option to control absolute vs relative path output
- Comprehensive test coverage in t1900-repo.sh (196 lines)
- Detailed documentation of all path fields and format behavior

The implementation avoids global state, aligning with the `the_repository` removal effort. Path resolution uses proper `strbuf` memory management and provides 13 path fields covering core repository locations. The `--path-format` option leverages Git's existing `relative_path()` utility.

This version drops all structural metric changes from previous iterations to keep the scope focused. The documentation patch provides complete specifications for the new functionality, including field references and output format details. Testing verifies key expansion behavior, path equivalence with `git rev-parse`, and submodule handling.
