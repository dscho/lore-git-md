This is a bugfix patch in the ongoing UTF-8 alias subsection series, addressing how empty subsections are handled in Git's alias configuration. The patch normalizes empty subsections (`[alias ""]`) to NULL to maintain backward compatibility with existing configurations that use `alias..name` syntax.

The change ensures that aliases written as `alias..name` in the config (which Git internally stores with an empty subsection) continue to work as plain case-insensitive aliases rather than being silently ignored. The patch also adds tests verifying both the empty-subsection compatibility case and the new recommended way to write aliases with leading dots using proper subsection syntax.

This appears to be one of the final fixes needed before the UTF-8 alias subsection feature can be merged, with Junio Hamano having confirmed the memory leak fixes in previous iterations. The only remaining known issue is a regression with dot-prefixed aliases that affects Johannes Schindelin's workflow, which will need to be addressed separately.

The patch itself is straightforward - it adds a simple normalization check in `alias.c` and includes comprehensive test coverage. The commit message clearly explains the behavior change and provides migration guidance for users who might have relied on the old syntax to create aliases with literal leading dots.
