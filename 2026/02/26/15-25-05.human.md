This is a feature patch for gitk, Git's graphical repository browser, adding a configurable link color option to improve readability in dark themes. The patch comes from Wang Zichong, who notes that while gitk's Preferences dialog allows customizing most colors, the link foreground color was previously hardcoded - problematic for dark theme users where the default link color can be unreadable.

The change is small and focused, adding just 10 lines to modify two Tcl/Tk procedures (`prefspage_colors` and `prefspage_set_colorswatches`) to expose the link color setting in the UI alongside other color options. The implementation follows gitk's existing color configuration pattern, making it a straightforward addition.

Since gitk is maintained separately from core Git by Johannes Sixt, Junio has forwarded the patch to him for review. The patch appears well-motivated and cleanly implemented, addressing a real usability issue for dark theme users without introducing complexity. Given gitk's nature as a Tcl/Tk application, this UI tweak is unlikely to have wider implications for Git's core functionality.
