This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with the existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The patch introduces inotify-based monitoring with recursive directory watching, handling directory renames through IN_MOVED_FROM/TO event cookies, and maintaining bidirectional watch descriptor <-> path mappings. It detects and rejects remote filesystems (NFS/SMB/vfat) via statfs() unless explicitly allowed, and falls back to $HOME/.git-fsmonitor-* for IPC sockets when .git is remote. The implementation includes comprehensive error handling, including detection of stale directory renames and queue overflows.

Key technical components include:
- New files `fsm-listen-linux.c`, `fsm-health-linux.c`, and `fsm-path-utils-linux.c` implementing the Linux-specific backend
- Documentation updates explaining Linux-specific caveats about inotify watch limits
- Build system integration via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=unix
- Support for meson, CMake, and traditional Makefile builds
- Extensive trace logging for debugging

The patch represents the seventh iteration of this work, having addressed feedback from previous versions including memory leaks, race conditions, and portability issues. It's now stable in Junio's 'seen' branch with all known issues resolved. The implementation is well-considered, with thorough test coverage and attention to edge cases like rapid directory creation and filesystem unmount scenarios.
