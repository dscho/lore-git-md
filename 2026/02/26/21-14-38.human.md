This is the first patch in a 10-part series introducing enhanced repository path reporting to `git repo info`. The series is part of a larger effort to provide structured programmatic access to repository metadata while removing reliance on global state.

The patch introduces a `struct repo_info` to encapsulate repository context (pointer and prefix) that gets threaded through the path resolution functions. This replaces direct access to repository globals, aligning with the ongoing `the_repository` removal effort. It also adds category key expansion, allowing scripts to request groups of related fields (like "layout.*") with a single category name.

Key technical changes:
- New `repo_info` struct to carry repository context
- All value-getter functions updated to take `repo_info` instead of raw `repository*`
- Category expansion logic that matches partial keys (e.g. "layout" expands to all "layout.*" fields)
- Maintains backward compatibility with explicit key requests

The implementation looks clean and well-contained, with the category expansion providing a useful ergonomic improvement for scripting use cases. The patch builds on prior work in the series while keeping the scope focused - it doesn't yet implement the actual path reporting that comes in later patches.
