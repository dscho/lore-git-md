This is a follow-up review note from Junio Hamano on the now-merged `.git` directory validation patch series. The thread has concluded with the patches merged, but Junio is pointing out a potential oversight in how the error code changes might affect other parts of the codebase.

The core observation is that the patch series changed the semantics of `READ_GITFILE_ERR_STAT_FAILED` and introduced `READ_GITFILE_ERR_STAT_ENOENT`, but there may be callers outside the main focus area (like in `submodule.c`) that still rely on the old error code meanings. Specifically, the submodule handling code currently treats `READ_GITFILE_ERR_STAT_FAILED` as indicating an unpopulated submodule, but with the new semantics, it should likely be checking for `READ_GITFILE_ERR_STAT_ENOENT` instead.

Junio notes this isn't necessarily a blocking issue (the series is already merged), but suggests auditing all uses of these error codes across the codebase to ensure consistent behavior. The affected functions are `read_gitfile_error_die()` and related error handling paths. The change could impact submodule handling, worktree code, and any other places that interact with `.git` file/directory validation.

This is typical post-merge feedback where the maintainer identifies follow-up work that wasn't caught during review. The original patch author (Tian Yuchen) or other contributors may want to address this in a future patch, though it's not urgent since the main series achieved its goals. The thread shows the careful attention to detail required when changing error handling paths that may have subtle dependencies.
