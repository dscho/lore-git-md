This is a refactoring patch in Adrian Ratiu's parallel hook execution series (3/10). It restructures the hook configuration cache from a raw `strmap` to a named `struct hook_config_cache`, which wraps the map and provides room for future expansion. The patch also replaces direct string storage with a proper `struct hook_config_cache_entry` to hold hook commands.

The changes are purely structural with no behavior modifications, preparing the infrastructure for upcoming patches that will add parallel execution metadata to hooks. The refactoring:
- Introduces the new struct types
- Updates all cache access patterns to use the new types
- Maintains the same memory ownership model (cache owns all strings and structs)
- Preserves existing hook lookup and initialization behavior
