This is a follow-up discussion in the thread about Jayatheerth Kulkarni's GSoC proposal to enhance the experimental `git repo info` command. The proposal aims to modernize parts of `git rev-parse` by removing `the_repository` global variable, implementing category-based queries, and improving path resolution.

In this email, Jayatheerth responds to feedback from Lucas Oshiro (the command's original implementer) about the proposal's scope. Lucas had cautioned that the review process might be too slow for the 12-week GSoC timeframe, citing his own experience requiring 11 iterations for acceptance. Jayatheerth asks for guidance on prioritizing the work, specifically which parts Lucas considers highest impact.

The exchange highlights the practical challenges of contributing to Git within a time-bound program like GSoC, where mailing list review cycles can be unpredictable. Lucas's perspective as the original implementer carries weight in assessing feasibility. The thread remains focused on scoping the work appropriately while maintaining the technical direction (global variable removal, path features) that both agree is valuable.
