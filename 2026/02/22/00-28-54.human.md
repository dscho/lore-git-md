This is a feature patch series introducing parallel hook execution, building on Adrian Ratiu's prior configurable hooks work. The 10-patch v2 series represents a significant redesign from v1 based on mailing list feedback, now making parallel execution opt-in rather than default.

The key changes include:
- Defaulting to serial execution (jobs=1) to maintain backward compatibility
- Requiring explicit opt-in via `hook.jobs` config or `-j/--jobs` CLI option
- Adding per-hook parallelization control with `hook.<name>.parallel`
- Introducing repository format extensions for output handling (`extensions.hookStdoutToStderr`)
- Adding runtime override via `hook.forceStdoutToStderr` config
- The implementation touches multiple builtins (am, checkout, clone) with extensive test coverage in t/t1800-hook.sh
- The series depends on Adrian's unmerged configurable hooks work and includes contributions from Emily Shaffer, Ævar Arnfjörð Bjarmason, and others

The v2 changes address safety concerns raised in v1 review, particularly around terminal access preservation and shared state modification in hooks like pre-commit. The implementation now carefully considered defaults while providing flexibility for performance optimization where safe. The test suite has been expanded to verify the new parallel behavior and configuration precedence rules.
