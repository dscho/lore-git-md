This is the fourth patch in a 10-part series introducing parallel hook execution, building on Adrian Ratiu's prior work on configurable hooks. The patch adds parsing for a new `hook.jobs` configuration that will control how many hooks can run simultaneously.

The patch introduces the global `hook.jobs` setting which serves as a default for all hooks, with later patches planned to add per-hook overrides. The value is parsed during configuration and stored in the hook cache, though not yet used. The implementation includes validation to ensure the value is a positive integer, with warnings for invalid inputs. Documentation is added to `Documentation/config/hook.adoc` explaining the new setting defaults to serial execution (jobs=1).

The change maintains the series' careful approach to configuration handling, with the jobs value flowing through the existing hook config cache infrastructure that was refactored in the previous patch. The patch shows attention to edge cases (zero values, invalid numbers) while keeping the door open for the more granular controls coming in subsequent patches. This is foundational work for the parallel execution feature, establishing the configuration plumbing before the runtime behavior is added.
