Parallel hooks series (part 6/10): Marking non-parallelizable hooks.

This patch in Adrian Ratiu and Emily Shaffer's parallel hooks series identifies several Git hooks that cannot safely run concurrently and forces them to execute serially regardless of the `hook.jobs` configuration. The affected hooks are those involved in commit workflows (`applypatch-msg`, `pre-commit`, `prepare-commit-msg`, `commit-msg`, `post-commit`) and checkout operations (`post-checkout`, `push-to-checkout`).

The implementation uses the new `RUN_HOOKS_OPT_INIT_FORCE_SERIAL` macro introduced earlier in the series, which overrides any parallel execution settings. The patch updates hook calls in several builtin commands (`am`, `checkout`, `clone`, `receive-pack`, `worktree`, and `commit`) to use this serial-only initialization. Documentation is added to `hook.adoc` explaining that these hooks always run sequentially.

A new test case in `t1800-hook.sh` verifies that `pre-commit` hooks ignore `hook.jobs=2` and run serially, demonstrating the force-serial behavior. The test uses the same sentinel file timing technique established in previous patches to reliably detect parallel execution attempts.

This patch builds on the series' foundation of configurable hook execution while ensuring critical workflow hooks maintain their sequential guarantees. The changes are mechanical but important for safety, touching core commands where these hooks are invoked. The series continues to maintain backward compatibility while introducing parallel execution capabilities for appropriate hooks.
