This is part 8/10 of Adrian Ratiu's series introducing parallel hook execution, building on his prior work for configurable hooks. The patch adds per-event job count configuration via `hook.<event>.jobs`, allowing users to override the global `hook.jobs` setting for specific hook events while maintaining the parallel-safety constraints established earlier in the series.

The key technical additions include:
- New `hook.<event>.jobs` config that takes precedence over `hook.jobs` for the specified event
- Storage of per-event job counts in the hook config cache (as heap-allocated unsigned ints)
- Updated job count resolution logic that checks for event-specific overrides before falling back to global config
- Comprehensive test coverage verifying precedence rules and interaction with parallel-safety constraints

The implementation maintains the series' safety invariants - parallel execution with `hook.<event>.jobs` still requires all hooks for that event to be marked parallel-safe via `hook.<name>.parallel`. The documentation clearly explains the distinction between event names and hook friendly names in the config keys.

This patch follows the series' incremental approach, adding another control point for parallel execution while preserving the safety mechanisms from earlier patches. The tests demonstrate realistic scenarios like overriding global serial execution for specific events and ensuring parallel-safety constraints still apply. The changes integrate cleanly with the existing hook config cache infrastructure.
