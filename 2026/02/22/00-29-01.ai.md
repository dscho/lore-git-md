This is part 7/10 in Adrian Ratiu's series adding parallel hook execution support, building on his earlier configurable hooks work. The patch adds a `-j/--jobs` command-line option to `git hook run` to control parallel execution, complementing the existing `hook.jobs` config.

The implementation makes several key design choices:
1. Explicit `-jN` overrides any config value (but critical hooks still force serial execution as established in patch 6/10)
2. TTY handling differs between serial (-j1) and parallel (-jN) modes - parallel hooks output to pipes rather than directly to the terminal
3. Output from parallel hooks is collected and de-interleaved to maintain coherent output streams

The patch includes extensive test coverage:
- Verifies TTY behavior in both serial and parallel modes
- Confirms output grouping for parallel hooks
- Tests interaction between -j flag and parallel=false hooks
- Validates serial execution ordering with -j1

This continues the series' careful approach to parallel execution safety while providing flexibility for callers. The next patches will likely address remaining questions about output stream handling and mark additional hooks as parallel-safe.
