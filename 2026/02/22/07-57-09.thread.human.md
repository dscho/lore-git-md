Jayatheerth Kulkarni has proposed expanding the experimental `git repo info` command as a GSoC project, building on Lucas Oshiro's initial implementation from GSoC 2025. The proposal aims to modernize the command by removing `the_repository` global variable dependencies (part of Git's ongoing libification effort), adding category-based queries for repository information, improving path resolution features, and potentially integrating repository analysis capabilities inspired by git-sizer.

Lucas Oshiro, the original implementer, has responded with cautious support. While agreeing the technical direction is sound, he warns that the scope may be too ambitious given Git's mailing list review cycles - noting his own experience where a single patch series required 11 iterations before acceptance. He suggests prioritizing work given the 12-week GSoC timeframe, particularly around the global variable removal and core query functionality.

The discussion highlights both the technical promise of the proposal and the practical realities of contributing to Git. Key files that would be modified include builtin/repo.c (for global state refactoring), path.c and setup.c (for path resolution), with corresponding test updates. The thread remains open as Kulkarni considers how to refine the project scope based on this feedback.
