This is a follow-up email in Adrian Ratiu's config-based hooks series, specifically addressing brian m. carlson's concerns about parallel hook execution. The email announces the release of v2 of the parallel hooks series, which is separate from the main config-based hooks work.

Adrian confirms that the parallel execution implementation preserves TTY handling (as Phillip Wood previously raised) by using run-command's muxer to combine stdout/stderr output while detached from the terminal. The design maintains sequential execution by default for compatibility, with opt-in parallelization for known-safe hooks under user control. Some hooks will always enforce serial execution when unsafe.
