Thread summary:

GSoC proposal from Jayatheerth Kulkarni to enhance the experimental `git repo info` command as a modern replacement for parts of `git rev-parse`. Focus areas include: removing `the_repository` global variable usage in builtin/repo.c (part of Git's libification effort), implementing category-based queries (e.g. "paths", "core") to group repository information, expanding path resolution functionality (git-dir, common-dir, toplevel), and potentially integrating repository analysis features from git-sizer. The proposal builds on prior work by Lucas Oshiro (GSoC 2025) and demonstrates familiarity with the codebase through previous micro-patches to repo.c and test modernization contributions. Technical challenges include maintaining compatibility across repository types (bare, worktree, submodules) and designing output formats supporting both human-readable and machine-parsable modes. The 12-week timeline is structured into core implementation (weeks 2-6), global state refactoring (weeks 4-6), category queries (weeks 7-9), and optional git-sizer integration (weeks 10-12), with buffer time for mailing list review cycles. Files impacted include builtin/repo.c, path.c, setup.c, with test coverage in t/. The author plans continued post-GSoC involvement and has engaged with the community through prior contributions.
