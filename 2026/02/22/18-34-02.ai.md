This is a discussion about GSoC proposal submission format, specifically regarding Tian Yuchen's draft proposal to work on reducing Git's global state (particularly `the_repository`). The email comes from Usman Akinyemi responding to Tian's initial proposal submission.

Usman strongly recommends against using a Google Doc link for the proposal, arguing that the traditional "giant wall of text" email format is more appropriate for the Git community's workflow. He notes that requiring reviewers to visit an external document and then copy content back to email creates unnecessary friction, and that inline email discussion is more accessible both for current reviewers and future GSoC applicants who might reference the thread.

The exchange highlights a cultural norm in the Git project - proposals and patches are expected to be self-contained in the email body rather than linked externally. This format enables the mailing list's archival nature and threaded discussion model. The technical content of Tian's actual proposal (about `the_repository` removal) isn't discussed here - the focus is purely on submission mechanics.

This is likely to be an important procedural note for Tian and other new contributors, as the project's email-based workflow has specific expectations that differ from many modern open source projects that use GitHub or other web-based collaboration tools. The response suggests that proposals following the traditional format may receive more engagement from established contributors.
