This is a security-related follow-up in the thread about receive-pack's handling of cross-namespace symbolic refs. The original patch fixed a crash when processing such symrefs, but maintainer Junio C Hamano now argues the behavior itself is a security risk that should be rejected by default.

Junio responds to Troels Thomsen's suggestion of documenting the current permissive behavior in gitnamespaces(7), firmly rejecting this approach. He asserts that security-sensitive defaults should err on the side of strictness, with any relaxation being an explicit opt-in. His "nobody reads documentation" comment reflects a long-standing Git philosophy that dangerous behaviors should be technically prevented rather than merely documented.

The exchange highlights a fundamental disagreement about namespace boundaries - whether they should be strict security barriers (Junio's view) or permeable links when explicitly configured (Troels' position). While both acknowledge hooks could enforce either policy, the core debate remains unresolved: should Git's default behavior change to block these cross-namespace symrefs entirely? Junio's position suggests he may push for such a change, though no concrete proposal has emerged yet.
