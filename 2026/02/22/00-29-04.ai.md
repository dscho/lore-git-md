This is the final patch in Adrian Ratiu's 10-part series introducing parallel hook execution, building on his prior configurable hooks work. The patch adds a runtime configuration option `hook.forceStdoutToStderr` that enables the `extensions.hookStdoutToStderr` behavior globally, making it easier to adopt parallel execution for hooks like pre-push that normally require separate output streams.

The key technical addition is a new boolean config that forces stdout-to-stderr merging for all hooks, allowing parallel execution even for hooks that would normally require sequential operation due to output stream requirements. The implementation ensures this works for both new repositories (via `git init` and `git clone`) and existing ones. The patch includes comprehensive tests verifying the behavior across repository creation, cloning, and push operations.

This completes the series' output stream handling strategy, complementing the earlier parallel execution controls (global `hook.jobs` config, per-hook `hook.<name>.parallel` markers, command-line `-j` option, and per-event `hook.<event>.jobs` overrides). The design maintains strict safety by requiring explicit opt-in at all levels while providing migration paths for tools like git-lfs that rely on pre-push hook stdout.

The series represents a significant expansion of Git's hook subsystem, adding five distinct control points for parallel execution while maintaining backward compatibility. This final piece ensures output behavior consistency is properly integrated into the overall parallelization strategy.
