This is an infrastructure patch in Adrian Ratiu's parallel hook execution series. It introduces a new helper function `repo_config_get_uint()` to properly handle unsigned integer configuration values, specifically for the upcoming `hook.jobs` setting that will control parallel hook execution.

The patch adds the full stack of functions needed to parse and retrieve unsigned int config values: `git_config_uint()`, `git_configset_get_uint()`, and `repo_config_get_uint()`, along with the underlying `git_parse_uint()` parser. This matches the existing pattern for other numeric types in the config subsystem.

The implementation is straightforward and follows the same error handling patterns as other config value parsers. The commit message explains the design choice to use unsigned int rather than int or ulong for the job count, noting it's the most appropriate type for this use case. The patch is well-contained, touching only config and parse infrastructure without introducing any behavior changes yet.

This is a preparatory patch that will be used by subsequent patches in the series to read the `hook.jobs` configuration. The careful attention to type safety here reflects the series' overall focus on robust parallel execution infrastructure.
