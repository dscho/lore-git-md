This is a bugfix patch that addresses a memory leak in Git's repository initialization code. It's the first patch in a 10-part series introducing parallel hook execution, but this particular change stands alone as a general infrastructure fix.

The patch fixes a pre-existing memory leak in `repo_init()` that occurs when repository initialization fails. The leak happens when a v1 extension is incorrectly enabled in a v0 format repository - an edge case that would only occur in development environments, not normal usage. The fix is straightforward: add a missing call to `clear_repository_format()` in the error path to properly clean up allocated memory.

While small, this change demonstrates good hygiene - the author found and fixed a real (if obscure) memory leak while working on the parallel hooks infrastructure. The commit message clearly explains both the problem and why it wasn't caught earlier. This kind of preparatory cleanup is typical for larger feature series, ensuring the foundation is solid before building new functionality on top.
