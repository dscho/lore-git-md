This is patch 8/10 in Adrian Ratiu's series adding parallel hook execution to Git. The patch introduces per-event job configuration, allowing users to override the global `hook.jobs` setting for specific hook events.

The key addition is a new `hook.<event>.jobs` config that takes precedence over the global `hook.jobs` when running hooks for that specific event. For example, you could configure `post-receive` hooks to run with 4 parallel jobs while keeping other hooks at their global default. The implementation carefully maintains all existing safety constraints - hooks still require explicit `hook.<name>.parallel=true` markings to run in parallel, and critical hooks (like `pre-commit`) always run serially regardless of configuration.

The patch includes thorough documentation explaining the precedence rules and naming conventions (noting that `<event>` must be the event name, not a hook's friendly name). It also adds comprehensive test coverage verifying that per-event jobs settings properly override global config while respecting parallel-safety constraints.

This continues the series' pattern of making parallel execution strictly opt-in with multiple layers of control (global config, per-event config, command-line flags, and per-hook markings). The implementation is careful about memory management and includes clear warning messages for invalid configurations.
