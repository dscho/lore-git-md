This is a refactoring patch in Adrian Ratiu's parallel hook execution series (v2 3/10). It restructures the hook configuration cache from a raw strmap to a named `struct hook_config_cache`, replacing direct string pointers with a proper `struct hook_config_cache_entry` to hold hook commands. 

The change prepares for upcoming additions to the hook metadata by introducing proper types rather than ad-hoc string storage. The patch:
- Defines new `hook_config_cache` and `hook_config_cache_entry` structs
- Updates all cache accessors to use the new types
- Maintains identical behavior while improving type safety
- Keeps the same memory ownership model (cache owns all allocations)

This is infrastructure work supporting later patches that will add parallel execution controls. The careful separation of concerns and type safety improvements suggest this is a solid preparatory step in the series.
