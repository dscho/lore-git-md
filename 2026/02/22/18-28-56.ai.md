This is a test modernization patch in the "[PATCH 0/4] repo: enhance repository info and structure reporting" series. The patch fixes portability issues in the test suite for the new `git repo` command by replacing dynamic reference and object counting with hardcoded expected counts.

The changes make the test more reliable by:
1. Replacing `git for-each-ref` pipe chains with static counts (1 branch, 1 tag, 0 remotes)
2. Using fixed object counts (42 commits/trees/blobs, 1 tag) instead of dynamic queries
3. Hardcoding inflated size values that match the test repository's expected state

This follows established patterns for making tests portable across platforms and hash algorithms. The patch maintains the same test coverage while removing dependencies on shell pipe behavior and dynamic repository inspection that could vary between test runs.

The changes align with the series' goal of providing reliable repository metrics by ensuring the tests themselves produce consistent results. As this is a test-only patch in an early series iteration, it hasn't attracted review feedback yet but follows conventional test modernization approaches seen in other parts of the codebase.
