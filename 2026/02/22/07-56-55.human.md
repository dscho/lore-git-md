This is a follow-up discussion in the ongoing thread about receive-pack's handling of symbolic refs that cross namespace boundaries. The original patch fixed a crash when processing such symrefs, but Junio raised security concerns about whether allowing cross-namespace symrefs could undermine namespace isolation.

Troels Thomsen responds to Junio's suggestion that the fix should reject such updates entirely. He argues that since symrefs must be explicitly created server-side, cross-namespace links are likely intentional configurations rather than accidents. He notes the lack of bug reports about this behavior suggests it's a rarely used feature combination. 

The exchange highlights a fundamental tension - Junio prioritizes strict namespace boundaries by default for security, while Troels values preserving flexibility for intentional configurations. Troels suggests documenting the behavior in gitnamespaces(7) as an alternative to changing the implementation, but acknowledges he'd need to propose a different solution if the stricter behavior were adopted.

The thread remains unresolved, with Troels seeking guidance on how to proceed given his original use case would be blocked by Junio's proposed security hardening. The discussion touches on Git's broader philosophy around security defaults versus configuration flexibility.
