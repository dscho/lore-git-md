This is a follow-up discussion in the ongoing thread about receive-pack's handling of symbolic refs that cross namespace boundaries. The original patch fixed a crash but raised security policy questions.

Troels Thomsen responds to Junio Hamano's suggestion that receive-pack should actively reject cross-namespace symref updates as a security measure. Troels argues that since symrefs require explicit server-side creation, they're unlikely to be accidental, and points to the lack of bug reports as evidence this is a niche use case. He suggests documenting the behavior in gitnamespaces(7) rather than changing the implementation.

The exchange highlights a fundamental disagreement about Git's security model for namespaces: Junio favors strict boundaries by default to prevent accidents, while Troels values flexibility for intentional configurations. Troels notes that rejecting updates would prevent his original use case (the reason for the patch) while acknowledging Junio's security concerns are valid.

The thread remains unresolved - Troels seems open to document the behavior but reluctant to implement Junio's proposed rejection policy, as it would negate his original fix's purpose. No concrete proposals emerge for how to reconcile these positions, leaving the design question open. The discussion has shifted from the technical crash fix to broader questions about namespace security defaults.
