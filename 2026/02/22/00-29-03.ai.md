This is part 9/10 of Adrian Ratiu's parallel hook execution series, focusing on output stream handling for parallel hooks. The patch introduces a new repository configuration extension `extensions.hookStdoutToStderr` to standardize hook output behavior across all hook types.

The key change forces all hooks to merge stdout to stderr when the extension is enabled, which is required for proper output de-interleaving in parallel execution. The pre-push hook is currently the only known exception to Git's typical stdout-to-stderr behavior, with git-lfs depending on separate streams. The patch makes this behavior configurable while maintaining backward compatibility - when disabled, pre-push hooks will always run sequentially to avoid interleaved output.

The implementation adds repository format tracking for the new extension, updates transport.c to respect the setting for pre-push hooks, and includes comprehensive tests verifying the behavior. The design provides a clean migration path where users can opt into the more consistent (and parallelizable) output behavior while not breaking existing hook implementations that rely on the current pre-push behavior.

It represents a compromise position between full backward compatibility and the requirements for parallel execution, giving users control over which behavior they want while clearly documenting the tradeoffs.
