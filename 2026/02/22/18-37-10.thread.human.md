The thread addresses a bug in `git fsck` where packfile verification could enter an infinite loop due to how the MRU (most recently used) list was updated during traversal. brian m. carlson's initial patch fixed this by adding a `skip_mru_updates` flag, which Junio Hamano reviewed and approved for merging. The discussion then turned to whether this fix should be backported to the stable branch, given the bug has existed since Git 2.53 but only affects explicit `git fsck` runs.

Jeff King (Peff) has now weighed in with deeper architectural concerns about the MRU implementation. While agreeing the immediate fix works, he points out the current design forces callers to manually opt out of MRU updates, which is both fragile and inefficient. Peff suggests either maintaining separate lists for stable iteration versus MRU optimization, or creating a dedicated interface for stable traversal. His comments highlight a tension in the design between iteration stability and cache efficiency that may warrant future attention, though no immediate code changes are proposed.

The core fix remains on track for merging, while Peff's observations about the MRU implementation have opened a broader design discussion that may influence how this part of Git's object storage layer evolves.
