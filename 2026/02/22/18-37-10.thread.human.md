This thread began as a bug report about `git fsck` entering an infinite loop when verifying multiple packfiles, caused by updates to the MRU (Most Recently Used) list during iteration. brian m. carlson provided an initial fix (v1 patch) that adds a `skip_mru_updates` flag, which Junio C Hamano has approved for merging. 

The discussion has since expanded to reveal deeper architectural concerns. Jeff King pointed out fragility in the MRU list design, while Patrick Steinhardt identified additional verification correctness issues - including potential problems with duplicate object verification and edge cases where the MRU flag might remain incorrectly set. Patrick is preparing follow-up patches to address these, separate from the already-approved immediate fix.

In the latest exchange, Patrick and Jeff discuss whether the MRU-based approach should be reconsidered entirely, given the tension between iteration stability and performance optimizations. While the immediate fix stands, Patrick indicates this may lead to more substantial changes as part of his ongoing object database (ODB) abstraction work. The thread now encompasses both the urgent bugfix and longer-term design questions about packfile verification architecture.
