The thread began with brian m. carlson reporting an infinite loop in `git fsck` when verifying multiple packfiles containing large objects, caused by MRU list updates during iteration. His initial patch added a `skip_mru_updates` flag as a targeted fix, which Junio approved for merging. However, deeper investigation by Jeff King and Patrick Steinhardt revealed this was symptomatic of broader architectural issues in pack verification.

Patrick's latest email confirms the root cause analysis and adds critical new details. The infinite loop only occurs with large objects (exceeding core.bigFileThreshold) because their verification path uses `find_pack_entry()`, which modifies the MRU list. More alarmingly, he discovered the verification could be checking the wrong instance of duplicate objects across packs - a fundamental correctness issue. Patrick is now preparing a patch series to address both the iteration safety and verification accuracy problems.

The discussion has evolved from a simple bugfix to a comprehensive examination of pack verification. Jeff King advocates for a more robust MRU redesign, preferring a separate iteration list approach over the current skip flag. Patrick connects these issues to his ongoing object database abstraction work, which aims to eventually eliminate `repo_for_each_pack()`. While the immediate fix is queued, the thread now focuses on ensuring verification correctness and planning the MRU's long-term design within Git's evolving object storage architecture.
