This is a security policy discussion in the ongoing thread about receive-pack's handling of cross-namespace symbolic references. His position reflects a security-first philosophy where potential vulnerabilities should be closed proactively rather than documented as accepted risks. The exchange highlights a fundamental disagreement about Git's namespace model - whether symrefs should be allowed to intentionally bridge namespaces (Troels' view) or whether namespaces should form strict security boundaries (Junio's preference).

The technical context remains the same: the original patch fixed a NULL dereference when processing symrefs pointing outside their namespace, but Junio now wants to repurpose that fix as a policy enforcement point. No new code is proposed implementation for Junio's stricter approach yet, leaving the thread at an impasse between security philosophy and backward compatibility concerns.
