This is part 7/10 in Adrian Ratiu's series adding parallel hook execution to Git, building on his earlier configurable hooks work. The patch adds a `-j/--jobs` command-line option to `git hook run` to control parallel execution, complementing the existing `hook.jobs` config setting.

The key changes are:
- Adds `-j/--jobs` option to specify parallel job count at runtime
- Documents the new option and its interaction with config settings
- Adds tests verifying TTY behavior differs between serial (-j1) and parallel (-jN) modes
- Includes tests for output grouping and ordering in parallel execution
- Maintains backward compatibility by defaulting to serial execution

The patch follows the series' safety-first approach by keeping critical hooks serial-only and making parallel execution opt-in. It addresses feedback from v1 by clarifying the interaction between CLI flags and config settings. The test coverage is thorough, verifying both expected behaviors and edge cases around output handling.

This continues the series' pattern of careful, incremental changes with strong test coverage. The parallel execution infrastructure appears well-considered, though the final patches will need to address remaining questions about output stream handling.
