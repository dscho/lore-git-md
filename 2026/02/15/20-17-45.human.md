This is the third and final patch in Colin Stagner's series addressing recursion limits in `git subtree split` on Debian/Ubuntu systems. The patch focuses on reducing recursion depth in the split operation's rejoin-deepening algorithm.

The core issue stems from Debian/Ubuntu's POSIX shell having a hardcoded 1000-call recursion limit, which `git subtree split` can hit when processing deep history graphs. The patch restructures the commit traversal logic to process entire ranges of commits at once rather than recursively handling each commit individually. This is particularly important for the `--rejoin` mode, which maps mainline commits to split commits but sometimes needs to process pre-rejoin history.

The change modifies `check_parents()` in `contrib/subtree/git-subtree.sh` to discover and process all commits back to the next available rejoin point in one operation, rather than recursing per commit. The commit message includes a clear example history graph showing cases where pre-rejoin history is needed. The patch adds 54 lines while removing 2, with the bulk being explanatory comments and the new traversal logic.

This completes the series' approach of first reducing function side effects (patch 1), then restructuring the traversal (this patch). While the cover letter mentioned testing on a large repository, we still lack specific performance measurements showing the improvement on affected systems. The changes appear well-contained to the subtree` implementation and don't interact with other in-flight topics.
