This is the first patch in a performance and compatibility series for `contrib/subtree`, addressing recursion limits in `git subtree split` on Debian/Ubuntu systems. The patch focuses on reducing function side effects in the shell script implementation.

Colin Stagner's change modifies `process_subtree_split_trailer()` to return its value via stdout rather than setting a variable in the caller's scope. The function now echoes its result, which callers capture via command substitution. This makes the data flow more explicit and eliminates a subtle side effect where the function was modifying a variable (`sub`) that belonged to its caller.

The patch also adds documentation clarifying what the function does - it parses commit hashes, fetches from a repository if needed, and either outputs the full commit hash or dies on failure. The changes are mechanical and focused on code clarity rather than behavior modification, though they set up for subsequent recursion-reduction changes in the series.

This appears to be a well-scoped preparatory change for the larger recursion limit fix. The commit message clearly explains the motivation (eliminating unclear side effects) and the implementation is straightforward shell scripting patterns. As the first in a series, it doesn't yet address the core recursion problem but lays groundwork for the subsequent patches.
