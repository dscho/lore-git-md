This is a security-focused patch series hardening Git's repository discovery by validating `.git` file types. The current patch (v3) follows up on Junio Hamano's review of error handling taxonomy in response to earlier versions.

The author acknowledges significant implementation flaws in their current approach, particularly notes confusion around error state categorization. They outline four distinct cases that need separate handling: ENOENT (non-existent paths should be ignored), IS_A_DIR (directory cases should check git dir), NOT_A_FILE (FIFOs etc. should trigger fatal error), and REAL errors (stat failures/invalid formats should die). The current code incorrectly conflates some of these cases.
