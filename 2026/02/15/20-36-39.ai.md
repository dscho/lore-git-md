Bugfix for `git subtree` regression with performance improvements. This is a follow-up to Colin Stagner's earlier attempt to fix a regression in subtree operations (introduced in Git 2.52.0) that broke handling of squashed subtree commits. The new approach completely removes the problematic "ignore other splits" optimization in `should_ignore_subtree_split_commit()` rather than trying to fix it, as analysis showed the heuristic was both incorrect and a performance bottleneck.

The patch series addresses two issues: the original regression affecting squashed commits (which caused subtree push operations to fail) and a separate "recursion depth exceeded" bug on Debian/Ubuntu systems. Testing on real-world repositories (including the Athena Framework monorepo that originally surfaced the issue) shows the solution works correctly while also providing significant performance benefits - the fixed version runs 3x faster than the original working version (10.8s vs 33.0s) and nearly 2x faster than the broken version (10.8s vs 18.7s).

Colin is seeking verification from George Dietrich on whether the patches correctly preserve history across all normal split operations in their workflow. The solution represents a significant simplification by removing a problematic optimization that was causing both functional and performance issues, though it may need additional test coverage to prevent regression recurrence. The thread has progressed from initial bug report through technical analysis to this implementation, which appears to resolve both the functional regression and uncover an unexpected performance win.
