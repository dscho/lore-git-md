This is Junio Hamano's review response to Tian Yuchen's v3 patch hardening Git's repository discovery by validating `.git` file types. The patch aims to fail explicitly when encountering non-file/non-directory `.git` entries (like FIFOs) rather than silently continuing, while preserving symlink support.

Junio identifies several issues with the current implementation:

1. The error handling in `read_gitfile_error_die()` appears backwards - it now dies on cases (STAT_ENOENT and IS_A_DIR) that should be treated as non-fatal, requiring callers to explicitly exclude these cases.

2. The caller in `setup_git_directory_gently_1()` incorrectly checks for a git directory when STAT_ENOENT occurs (which means the path doesn't exist).

3. The condition checking for STAT_FAILED seems inverted (using `!=` when `==` was likely intended).

Junio suggests the proper design should:
- Treat only ENOENT and IS_A_DIR as non-error cases
- Have `read_gitfile_error_die()` handle only actual error conditions
- Let callers naturally fall through for non-error cases without special exclusion logic

The review maintains the security focus of the original patch while pointing out implementation flaws in the error handling taxonomy. Junio's comments indicate the approach is conceptually sound but needs refinement in how the error cases are structured and propagated.
