This thread addresses a discrepancy between the documented and actual behavior of `git fetch --prune-tags`. Orgad Shaneh initially proposed a patch series to align the implementation with the documentation, which states that `--prune-tags` should both remove local tags and force-update changed ones. The current implementation only handles tag removal.

Junio C Hamano, the maintainer, has raised important questions about whether this discrepancy is actually a bug or a deliberate design choice. He notes that Ævar Arnfjörð Bjarmason's original implementation may have intended the current behavior, suggesting the documentation might need updating instead of the code. Junio also pointed out that the test coverage should be expanded to verify both aspects of the documented behavior - not just tag updates, but also the pruning of missing tags.

The discussion now hinges on determining the historical intent behind the current behavior. The next steps will likely involve either:
- Justifying why the code should change (if the behavior was unintentionally wrong)
- Updating the documentation (if the behavior was deliberate)
- Expanding test coverage to fully verify both pruning and force-update functionality

This has become more than a simple bugfix - it's now a question of design intent that needs resolution before proceeding.
