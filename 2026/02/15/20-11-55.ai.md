This is a straightforward memory leak fix in the shallow repository handling code, part of Samo Pogačnik's 2-patch series addressing fetch operations. The patch fixes a memory leak in `get_shallow_commits()` where the `stack` object_array was not being properly cleared before function return, leaving allocated elements unreferenced. The fix is simple - adding a single `object_array_clear(&stack)` call before returning.

The patch has already gone through multiple rounds of review (now at v5) with sign-off from Patrick Steinhardt, Junio C Hamano, and Kristoffer Haugsbakk. The leak was discovered through test failures in the linux-leaks and linux-reftable-leaks CI runs when testing the companion patch in this series. This appears to be a clean, well-justified fix that has cleared all technical review hurdles.

The change is minimal (just one line added) and focused specifically on the memory management issue. The thread context shows this is the simpler of the two patches in the series, with the more complex relative-depth fetching logic coming in patch 2. This fix stands on its own merits and would be beneficial even without the subsequent changes.
