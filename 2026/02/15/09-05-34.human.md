This is the third patch in Jeff King's refactoring series for the ref-filter component-stripping functions. It simplifies memory handling in `rstrip_ref_components()` by removing a redundant `to_free` variable that was causing unnecessary complexity and triggering a glibc warning about const qualifiers.

The patch eliminates the separate `to_free` pointer that was previously used alongside `start`, since both always pointed to the same allocated buffer. This makes the memory management more straightforward - now there's just one pointer to track and free. The change also resolves a compiler warning from glibc-2.43 about const-correctness in the process.

This continues the series' pattern of methodically improving the ref-filter internals, building on the earlier introduction of `normalize_component_count()` in patch 1 and the `lstrip_ref_components()` simplification in patch 2. The changes are small but meaningful, showing Peff's characteristic attention to clean, maintainable code. The commit message clearly explains both the technical improvement and the rationale behind it.
