Security patch refining Git's repository discovery error handling. This is the third iteration of Tian Yuchen's series hardening `.git` file validation, addressing Junio Hamano's feedback from previous rounds.

The patch introduces finer-grained error classification in `read_gitfile_gently()` by adding `READ_GITFILE_ERR_STAT_ENOENT` and `READ_GITFILE_ERR_IS_A_DIR` to distinguish between missing paths and directory cases. It maintains symlink support via `stat()` while rejecting non-file/non-directory entries (like FIFOs) with `READ_GITFILE_ERR_NOT_A_FILE`. The changes focus on `setup.c` and `setup.h`, modifying how `setup_git_directory_gently_1()` processes these error conditions.

Key technical points:
- Error taxonomy now separates ENOENT (non-existent paths) from other stat failures
- Directory cases (`IS_A_DIR`) trigger gitdir checks rather than failing
- Non-file entities (FIFOs etc.) now trigger fatal errors when `die_on_error` is set
- `read_gitfile_error_die()` skips non-fatal conditions (ENOENT, IS_A_DIR)

The author acknowledges remaining issues with error handling boundaries, particularly questions whether the `cleanup_return` logic should filter non-fatal cases before calling `read_gitfile_error_die()`. Junio's prior review suggested this separation but the current implementation maintains the filtering inline for readability. The thread appears to be converging toward a solution that will properly distinguish fatal errors from benign conditions in the discovery process.
