Performance and compatibility patch for `contrib/subtree`, part 1 of a series addressing recursion limits in `git subtree split`.

This first patch in Colin Stagner's series focuses on reducing function side effects in the `git-subtree.sh` script. The change modifies how `process_subtree_split_trailer()` communicates its return value - instead of setting a variable that's also in the caller's scope, it now uses a subshell to echo the result. This makes the data flow clearer and eliminates a subtle side effect.

The patch touches two call sites in `find_latest_squash()` and `find_existing_splits()`, adding proper error handling via `|| exit 1`. The function's behavior remains the same - it still parses commit hashes and fetches from repositories when needed - but the implementation is now more robust against recursion depth issues that can occur on Debian/Ubuntu systems with default POSIX shell limits.

The changes are contained to shell script modifications in `git-subtree.sh`, with 7 lines added and 2 removed. The commit message clearly explains the motivation (removing unclear side effects) and the solution (using subshell invocation). This appears to be a well-contained preparatory change for the deeper recursion-related fixes coming in later patches of the series.
