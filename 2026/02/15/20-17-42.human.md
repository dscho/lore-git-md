This is a bugfix patch series targeting the `contrib/subtree` script, addressing a recursion depth limitation in POSIX shells (particularly on Debian/Ubuntu) that can cause `git subtree split` to fail on large history graphs.

The cover letter explains that some shells artificially limit recursion to 1000 calls, which `git subtree` can hit when processing complex histories. The series restructures the split operation to reduce recursive calls through three changes: reducing function side effects, functionalizing the split algorithm, and ultimately lowering recursion depth.

The changes are focused on `git-subtree.sh` in the contrib directory, with 88 lines added and 7 removed across the three patches. The motivation is clear and well-explained - this is fixing a real limitation that affects users on common platforms. The patches appear to be a focused technical solution to a specific problem, though we'd need to see the actual code changes to assess their quality.

This seems like a worthwhile improvement for users of the subtree script, particularly those working with large repositories on Debian/Ubuntu systems. The changes are contained to the subtree implementation and shouldn't affect other parts of the system.
