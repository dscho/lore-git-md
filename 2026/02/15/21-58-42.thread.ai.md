Thread summary:

Feature proposal to address privacy leaks in Git's push certificate mechanism. The thread originates from Lorenz Leutgeb identifying that local filesystem paths appear in push certificates during local-to-local repository pushes, potentially exposing sensitive paths in application logs. Current behavior (from 2013 implementation) sanitizes URLs but preserves local paths in the "pushee" header.

Proposed solution adds `--signed-pushee` and `--no-signed-pushee` options to `git send-pack` (and possibly `git push`) to control the pushee header - either specifying an alternative value or omitting it entirely for privacy. Technical considerations include empty string handling and impact on `pre-receive` hooks that inspect certificates. The change would primarily modify push certificate generation in `send-pack.c`.

Use case stems from a Git-based application with an unconventional architecture splitting push operations between local and network phases. Open questions include whether to extend the option to `git push` and how existing hook implementations might be affected. No reviews or alternative approaches have been proposed yet.
