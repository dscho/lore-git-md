This RFC patch continues the `the_repository` removal effort by migrating the `core.trustctime` configuration from a global variable to repository-specific storage in `struct repo_settings`. The change follows established patterns from prior config migrations in this effort but has sparked discussion about validation timing.

- Removes global `trust_ctime` variable from environment.c
- Adds `trust_ctime` field to `struct repo_settings` with default -1 (unset)
- Introduces accessor that would lazily read config (original approach) or parse eagerly in `prepare_repo_settings()` (proposed alternative)
- Updates statinfo.c to use new accessor
- Follows same pattern as previous config migrations in this effort
- Junio C Hamano raised concern about delayed error detection with lazy loading approach
