This is a bugfix patch series addressing an inconsistency in `git fetch --prune-tags` behavior. The cover letter explains that while the documentation states this flag should both prune local tags not on the remote AND force-update tags that differ, the implementation currently does the former but not the latter.

The two-patch series first adds a test case demonstrating the missing force-update behavior, then implements the clobbering of changed tags to match the documented behavior. The changes are minimal - just a one-line modification in `builtin/fetch.c` to pass the correct flag to the tag-fetching logic, plus test updates.

The patch appears well-scoped and clearly motivated by bringing behavior in line with documentation. The test-first approach is good practice, and the test case will help prevent regression. This seems like a straightforward improvement that closes a small but real gap between what's promised and what's delivered in the fetch machinery.
