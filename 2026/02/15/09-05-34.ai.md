Refactoring patch in Jeff King's ref-filter cleanup series. This is the third of four patches improving the component-stripping functions in ref-filter.c, building on the earlier introduction of `normalize_component_count()`.

The patch simplifies memory handling in `rstrip_ref_components()` by eliminating a redundant `to_free` variable that was previously used alongside the `start` buffer. The old pattern was unnecessarily complex - maintaining two pointers to the same allocation while marking one as const` - and triggered a glibc-2.43 warning about const-correctness in the `strrchr()` call. The new version directly uses a non-const `start` pointer throughout, making the ownership flow clearer while maintaining identical behavior.

This continues the series' pattern of methodically improving the ref-filter subsystem's internals, with each patch building on the last. The changes are surgical - just 3 lines modified - but meaningfully clarify the code's memory management. The commit message thoroughly explains both the problem and solution, characteristic of Peff's patches.
