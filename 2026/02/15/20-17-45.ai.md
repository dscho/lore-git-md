Performance optimization for `contrib/subtree` to handle deep history graphs. This is the third and final patch in Colin Stagner's series addressing recursion limits in `git subtree split` on Debian/Ubuntu systems with default POSIX shell.

The patch modifies the `check_parents()` function in `git-subtree.sh` to reduce recursion depth when processing commits during a split operation. The key change is replacing recursive processing of each commit with a bulk processing approach that discovers and handles entire ranges of commits at once, stopping at the next available rejoin point. This addresses the problem where deep histories would hit shell's 1000-call recursion limit on Debian-alike systems.

The commit message provides a clear example of the problematic history graph and explains two common cases where pre-rejoin history is needed. The implementation adds 54 lines while removing only 2, with the bulk being new explanatory comments and the actual logic change in `check_parents()`. The patch maintains the same error handling via `|| exit 1` seen in earlier patches of the series.

This completes the series' approach of first reducing function side effects (patch 1), then functionalizing traversal logic (patch 2), and finally implementing this recursion reduction (patch 3). The changes remain focused on the shell script implementation without touching core Git functionality. While the cover letter mentioned testing on a large repository, this patch still lacks specific performance measurements showing the improvement on affected systems.
