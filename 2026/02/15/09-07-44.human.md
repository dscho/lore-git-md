This is the final patch in Jeff King's four-part refactoring series cleaning up the ref-filter` component-stripping functions. The series began with a simple const-correctness fix and has evolved into a systematic improvement of the code.

The patch optimizes `rstrip_ref_components()` by replacing a quadratic `strrchr()` loop with a linear scan from the end of the string. While the performance improvement is dramatic in pathological cases (500,000-component refs go from 5.5s to 11ms), Peff notes this is mostly theoretical since such refs can't exist in practice due to protocol limits. The real benefit is cleaner code - the new version eliminates a temporary buffer and makes memory ownership clearer by using `xmemdupz()` for the final copy.

This completes the series' transformation of the original one-line warning fix into a comprehensive cleanup. Each patch has built carefully on the last, demonstrating Peff's characteristic thoroughness. The changes are small but meaningful, improving both performance and maintainability in a subsystem that handles ref formatting for commands like `for-each-ref`.
