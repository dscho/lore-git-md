This is a refactoring patch for the `git subtree` contrib script, part of a series to improve its split functionality. The patch extracts the commit traversal logic used by `git subtree split` into a new function `find_commits_to_split`, which handles the ancestor-first history traversal required for subtree operations.

The changes include:
1. Moving the `git rev-list` command into a dedicated function with clear documentation
2. Passing unrevs via stdin rather than command line to avoid argument length limits
3. Removing an unnecessary `eval` that was previously used
4. Adding a `--count` option when getting the total commit count

The patch appears well-contained and focused - it doesn't change behavior but makes the code more maintainable by encapsulating the traversal logic. The commit message clearly explains the motivation and changes. This looks like a straightforward improvement to the script's internals.
