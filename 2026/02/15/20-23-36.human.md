This is the second patch in a two-part bugfix series addressing a discrepancy between `git fetch --prune-tags` documentation and implementation. The series comes from Orgad Shaneh.

The patch makes `--prune-tags` behave as documented by forcing tag updates when local and remote tags differ, in addition to pruning missing tags. The change is minimal - just a one-line modification in `builtin/fetch.c` to pass the force flag when `prune_tags` is true. 

The accompanying test updates verify the new behavior by:
1. Confirming tags aren't clobbered without `--force` or `--prune-tags`
2. Showing tags are updated with either `--force` or `--prune-tags`
3. Demonstrating the same behavior works via `fetch.prunetags` config

This appears to be a straightforward, well-contained fix. The test coverage is thorough, following existing patterns in the test suite. The change aligns the implementation with long-standing documentation, suggesting this was an oversight rather than a deliberate design choice.
