This is the second patch in Samo Pogačnik's v5 series addressing relative-depth fetching in shallow repositories. The patch implements correct handling of `--deepen` operations when fetching into a shallow repository with merged branches, fixing a case where some shallow commits could become unreachable.

The key technical changes are:
- Introduces a new unified internal function `get_shallows_or_depth()` that can either calculate current shallow depth or return a list of shallow commits
- Adds `get_shallows_depth()` to measure equivalent depth of local shallow commits in the remote repo
- Modifies `get_shallow_commits()` to handle both absolute and relative depth calculations
- Removes the now-redundant `get_reachable_list()` function from upload-pack.c
- Adds a test case demonstrating the fixed behavior when fetching beyond a merged branch

The patch builds on the memory leak fix from part 1/2 and represents the substantive behavioral change in the series. It has undergone thorough review from Patrick Steinhardt, Junio Hamano, and Kristoffer Haugsbakk across five iterations, with all identified issues addressed. The implementation now properly handles the edge case where relative deepening could leave some shallow commits unreachable behind merged branches.

The changes maintain component reusability while providing a cleaner interface, and the test coverage verifies the correct shallow commit behavior. This appears ready for integration after the extensive review process.
