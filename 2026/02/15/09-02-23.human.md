This is the second patch in Jeff King's refactoring series to clean up the ref-filter component stripping functions. The patch simplifies memory handling in `lstrip_ref_components()` by eliminating an unnecessary string allocation.

The key insight is that since we're stripping components from the left (start) of the string, we don't need to make a temporary copy of the pointer we're advancing through the string already points to a valid NUL-terminated substring once we've skipped the desired number of components. The patch removes the intermediate allocation and freeing of `to_free`, making the code both more efficient and easier to understand.

This continues the series' theme of carefully cleaning up the ref-filter internals while maintaining the same behavior. Peff's reputation for precise, well-explained refactoring is evident here - the commit message clearly explains both the change and its rationale, including historical context about why the extra allocation was originally present.
