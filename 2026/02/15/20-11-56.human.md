This is the second patch in Samo Pogačnik's series to improve shallow repository handling during fetch operations. The patch focuses on fixing relative-depth fetching (`--deepen`) by restructuring how shallow commit calculations work.

The key change unifies the logic for absolute and relative depth calculations by introducing a new internal function `get_shallows_or_depth()` that can either return a list of shallow commits or calculate current depth, depending on parameters. This replaces the previous approach that used separate functions and had issues with duplicate calculations. The patch:

1. Adds a new `get_shallows_depth()` function to calculate current depth of shallow commits
2. Modifies `get_shallow_commits()` to handle both absolute and relative depth cases
3. Removes the now-redundant `get_reachable_list()` function
4. Includes a new test case that demonstrates the fix for fetching beyond merged branches

The implementation properly handles cases where deepening would previously leave unreachable shallow commits, as shown in the test scenario where fetching with `--deepen=1` now correctly maintains all shallow points. The patch has gone through five iterations with thorough review from Patrick Steinhardt, Junio Hamano, and Kristoffer Haugsbakk, addressing all feedback about efficiency and interface design.

This is a well-tested improvement to shallow repository handling that completes the series started with the memory leak fix in patch 1/2. Both patches appear ready for integration after this extensive review process.
