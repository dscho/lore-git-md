This is a refactoring patch from Jeff King (Peff) that improves the ref-filter subsystem's handling of refname component stripping. It's the first in a four-part series that evolved from Collin Funk's original single-line fix for a compiler warning.

The patch factors out common logic between `lstrip_ref_components()` and `rstrip_ref_components()` into a new `normalize_component_count()` helper function. This eliminates duplicated code that handles negative length parameters (which ask to keep rather than strip components) and makes both functions more readable by focusing on their core stripping logic. Peff also takes the opportunity to standardize on using `int` rather than `long` for component counts, noting this is more consistent with current usage and poses no practical risk of overflow.

The change is a clean, mechanical refactoring that preserves existing behavior while improving maintainability.
