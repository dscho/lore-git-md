Thread identity: Bugfix patch series (2 patches) addressing `git fetch --prune-tags` behavior inconsistency between documentation and implementation. Originating author is Orgad Shaneh.

Core problem: The `--prune-tags` flag is documented to perform both (1) pruning local tags not present on remote and (2) force-updating tags that differ between local and remote, but current implementation only does (1). Historical analysis shows this may stem from timing - the flag was added (commit 97716d21) before tag clobbering protection (commit 0bc8d71b), suggesting an oversight rather than intentional design. This creates practical issues where tag conflicts cause fetch failures.

Current status: Initial version (v1) of series pinged by author. First patch adds test coverage for `git fetch --force` behavior with tags. Second patch modifies `builtin/fetch.c` to pass `--force` flag to tag-fetching logic when `--prune-tags` is active. Junio C Hamano has raised concerns about historical intent while Orgad Shaneh provides context suggesting the behavior was likely unintentional.

Key technical details:
- First patch adds test in `t5516-fetch-push.sh` verifying `--force` behavior with tags
- Second patch changes `builtin/fetch.c` to pass `TAG_FETCH_FORCE` flag in prune-tags case
- Changes are minimal - four new test lines and one-line code change
- Existing pruning tests in `t/t5510-fetch.sh` cover tag deletion
- Original implementation was by Ævar Arnfjörð Bjarmason in 2018
- Tag clobbering protection was added later the same year

Open questions:

- Need for additional test coverage of both pruning and force-update behaviors
- Potential addition of `fetch.force` config option as alternative solution
