This is a refactoring patch for the `contrib/subtree` script, part of a series to improve the subtree functionality. The patch extracts the commit traversal logic used by `git subtree split` into a dedicated function `find_commits_to_split`.

The key changes are:
1. Moving the `git rev-list` invocation that finds commits needing splitting into a new function with proper documentation
2. Passing the `unrevs` parameter via stdin rather than command line to avoid argument length limits
3. Removing an unnecessary `eval` of the git command
4. Using `--count` flag directly rather than piping to `wc -l`

The patch appears well-motivated - the functional decomposition makes the code more maintainable and the stdin change addresses a potential edge case. The commit message clearly explains the purpose and the new function has thorough documentation. This is a straightforward improvement to the subtree implementation with no obvious downsides.
