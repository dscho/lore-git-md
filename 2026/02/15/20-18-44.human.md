This is a bugfix series for `git subtree`, focusing on correcting an optimization that was incorrectly excluding commits from split operations. The series comes from Colin Stagner and addresses issues introduced in two previous commits (98ba49ccc2 and 83f9dad7d6) that caused regressions in subtree splitting behavior.

The core problem involves commits being wrongly excluded from split history when they should be included, particularly affecting cases with multiple subtrees or squashed subtrees. The series removes the problematic optimization entirely and adds substantial new test coverage to prevent future regressions.

The three patches work together to:
1. Add new test cases to capture the problematic scenarios
2. Specifically test history depth handling
3. Remove the faulty optimization and ensure all necessary commits are processed

The changes are focused in the `contrib/subtree/` directory, primarily touching the shell script implementation and its test suite. The test additions (+198 lines) far outweigh the code removal (-58 lines), suggesting a careful approach to fixing the issue while preventing recurrence.

This appears to be a well-motivated fix addressing clear regressions, with thorough test coverage added to validate the correction. The changes are appropriately scoped to the subtree contrib command and don't affect core Git functionality.
