This is a refactoring patch that's part of the ongoing `the_repository` removal effort. It moves the `core.trustctime` configuration variable from being a global in environment.c to being stored in `struct repo_settings`, making it repository-specific rather than process-wide. The change follows a pattern seen in previous work to eliminate globals.

The patch removes the global `trust_ctime` variable and adds it to `repo_settings` with a default value of -1 (unset). It introduces `repo_settings_get_trust_ctime()` to lazily read the config value (defaulting to true if unset) and updates statinfo.c to use this new accessor. The change is mechanical and focused - it doesn't modify behavior, just moves where the setting is stored.

The commit message references a previous discussion thread (from the same author) about moving global configuration into repo_settings, suggesting this is part of a larger effort. The implementation follows established patterns seen in similar migrations of other config variables. The patch appears to be well-scoped and correctly implemented, though as an RFC it may be seeking feedback on the design before finalizing.
