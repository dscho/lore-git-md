This is the fourth and final patch in Jeff King's ref-filter cleanup series, addressing performance and code clarity in the refname component stripping functions. The patch focuses on `rstrip_ref_components()`, which removes trailing path components from refnames.

The key change replaces a quadratic `strrchr()` loop with a linear scan from the end of the string, eliminating both the performance overhead and the need for a temporary buffer. While the performance impact is negligible in practice (since refnames are typically short), the new implementation is simpler and more robust, directly manipulating string pointers rather than modifying a copy. The patch also uses the new `xmemdupz()` helper for safer string duplication.
