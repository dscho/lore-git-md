Performance optimization discussion for file copying with `sendfile()`. Jeff King (Peff) weighs in on George Hu's proposal to use Linux's `sendfile()` system call for more efficient file copying in Git. While acknowledging the potential efficiency gains, Peff questions whether this optimization would meaningfully impact Git's performance in practice, since most current uses of `copy_file()` handle small files. He identifies two possible exceptions where large files might be copied (bundle-uri with file:// URIs and local clones without hardlinks), but notes the implementation complexity introduced by platform differences (as previously discussed by Chris Torek regarding FreeBSD's socket-only `sendfile()`).

Peff suggests that while the optimization might be worth pursuing if it's straightforward, the case would be stronger with benchmark data showing measurable speed improvements for real-world operations. His comment keeps the discussion grounded in practical impact rather than theoretical optimization, maintaining the thread's technical focus while raising the bar for what would make this change compelling to merge. The exchange remains constructive, with Peff's perspective as a seasoned contributor adding weight to the need for performance data before committing to the added code complexity.
