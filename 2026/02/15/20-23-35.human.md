Bugfix patch series (2 patches) addressing `git fetch --prune-tags` behavior inconsistency. This is the first patch in the series, adding a test case to demonstrate the current behavior mismatch.

The patch from Orgad Shaneh adds a test case showing that while `git fetch` can force-update tags either via explicit refspec (`+refs/tags/*`) or the `--force` flag, the documentation claims `--prune-tags` should also force-update tags - which it currently doesn't. The test verifies the expected behavior by:
1. Creating a tag in the parent repo
2. Showing the tag can't be fetched normally if it exists locally
3. Showing it can be force-updated via refspec
4. Showing the same via `--force` flag

This is groundwork for the second patch which will modify the `--prune-tags` implementation to match the documented behavior. The test change is minimal and focused, just adding the missing verification case for `--force`. The patch appears well-structured and clearly motivated by the documentation/implementation discrepancy.
