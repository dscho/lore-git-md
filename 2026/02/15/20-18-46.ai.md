This is the second patch in a three-part bugfix series for the `contrib/subtree` component, specifically targeting the subtree split operation's history handling. The series addresses a problematic optimization that was incorrectly excluding commits from split history.

Patch 2/3 focuses on expanding test coverage in `t7900-subtree.sh` to verify history depth during subtree operations. Author Colin Stagner adds explicit commit count checks to several existing test cases, ensuring the split operation maintains correct history depth. The changes verify that:
- Split operations produce the expected number of commits (e.g., checking `rev-list --count` equals 5 for one test case)
- Branch comparisons show correct commit differentials (e.g., verifying exactly 1 new commit between splits)
- The tests now track split history more precisely by naming branches explicitly (`-b spl`, `-b a1`, etc.)

The patch builds on prior work that was reverted (28a7e27cff) and prepares the ground for patch 3/3 which will remove the problematic optimization entirely. The test additions are mechanical but thorough, covering both simple and complex cases (multiple subtrees, nested subtrees). This intermediate step ensures the behavioral change in the final patch will be properly validated.
