Bugfix for `git blame` coloring when using `--ignore-rev` with `--color-lines`. This addresses an issue reported by Seth McDonald where adjacent lines that should be colored the same (after ignoring a specified revision) were not being colored consistently. The problem occurred because the coloring logic wasn't properly accounting for the post-ignored revision state when determining line colors.

René Scharfe's patch modifies the blame output logic to check both the current and previous blame entries when deciding whether to apply the repeated-line coloring. The fix ensures that lines that become contiguous due to ignoring a revision (and thus should share the same color) are properly highlighted. The patch includes a new test case that verifies the corrected behavior by creating a situation where lines become contiguous after ignoring a formatting-only change.

This is a focused, well-constructed fix that addresses a clear edge case in the blame coloring logic. The patch follows Git's standard practices with a clean implementation and thorough test coverage. The change is unlikely to be controversial and should cleanly apply to the maintenance branch if needed.
