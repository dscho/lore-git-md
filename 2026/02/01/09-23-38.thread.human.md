This thread addresses a bug in `git clone` where using `--revision` with protocol versions 0 or 1 could cause a segmentation fault when the revision argument doesn't specify the full ref path (like `master` instead of `refs/heads/master`). The issue occurs because these older protocols fetch all references without filtering, potentially leaving a NULL pointer when updating HEAD.

The proposed fix adds a simple NULL check in `builtin/clone.c` to prevent the crash. While the patch correctly solves the immediate problem, it would be strengthened by including a regression test that demonstrates the crash scenario. This appears to be a real bug rather than an obscure edge case, as using shorthand revision names with older protocols is a reasonable use case that should work safely.
