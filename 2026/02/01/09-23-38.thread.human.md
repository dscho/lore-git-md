This thread addresses a segmentation fault in `git clone --revision` when using older protocols (v0/v1) with shorthand revision names like "master". The original patch proposed a straightforward NULL check to prevent the crash, which fixed the immediate issue but left deeper architectural questions unaddressed.

Junio Hamano, the maintainer, has now weighed in with substantive concerns. While acknowledging the crash needs fixing, he argues that simply adding a NULL check might mask underlying problems where the `peer_ref` should have been properly set. Instead, he suggests restructuring `update_remote_refs()` to cleanly separate connectivity checking from reference updates - a more principled solution that would properly implement the expected `--revision` behavior (creating a repository with just the requested revision, not all refs).

The discussion and patch now need to address two key gaps: the architectural approach to handling `--revision` clones in older protocols, and the lack of test coverage verifying both the crash fix and the expected repository state. The author will need to rework the patch to satisfy these concerns before it can move forward.
