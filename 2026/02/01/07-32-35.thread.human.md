The thread reports a bug in `git blame` where using both `--color-lines` and `--ignore-rev` together produces incorrect coloring. The issue occurs when multiple consecutive lines should show the same commit (after ignoring a specified revision) but instead display different colors based on their pre-ignored history. Seth McDonald originally reported this with clear reproduction steps across multiple Git versions.

René Scharfe has now provided a fix that addresses the problem. His patch modifies the coloring logic in `builtin/blame.c` to properly check the previous line's commit when determining coloring, ensuring consistent colors for lines that blame the same commit after ignoring a revision. The change includes a new test case that verifies the corrected behavior by creating a commit that changes whitespace and checking the coloring output. The fix is small and focused, specifically targeting the interaction between these two blame features without affecting other functionality.
