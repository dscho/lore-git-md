The issue occurred when lines that should have been colored the same (after ignoring a specified revision) instead followed the pre-ignored revision history. 

René Scharfe quickly provided a fix that modifies the coloring logic in `builtin/blame.c` to properly handle the `--ignore-rev` case while maintaining existing behavior. Junio Hamano acknowledged the fix while noting this might point to a more general pattern in the blame machinery worth addressing in future refactoring.
