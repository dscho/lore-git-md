This thread reports and fixes a bug in `git blame` where the `--color-lines` and `--ignore-rev` options interacted incorrectly. Seth McDonald originally reported that consecutive lines from the same commit (after ignoring a specified revision) were showing incorrect coloring. René Scharfe diagnosed the issue and provided a fix that modifies the coloring logic in `builtin/blame.c` while preserving the distinction needed for `blame.markignoredlines` to function properly.

The solution involves special handling for the `--ignore-rev` case rather than using the existing `blame_coalesce()` function, revealing an architectural nuance in how the blame machinery treats merge traversal versus explicit revision ignoring. Junio C Hamano reviewed and approved the patch, noting it correctly addresses the immediate issue while suggesting there may be broader refactoring opportunities in how the blame subsystem handles similar cases. The fix includes a test case in `t/t8012-blame-colors.sh` that verifies the behavior with whitespace-changing commits.

With the maintainer's approval and confirmation from the original reporter that the fix works across multiple Git versions, this thread is now resolved. The discussion provided useful insights into the blame subsystem's design while delivering a focused fix for the specific coloring issue.
