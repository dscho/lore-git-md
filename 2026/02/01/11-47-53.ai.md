Bugfix for `git blame` coloring with `--ignore-rev`. This patch addresses an issue where `--color-lines` doesn't properly color adjacent lines that blame the same commit after applying `--ignore-rev`. The current implementation only checks the current line's commit when determining line coloring, causing incorrect coloring when multiple consecutive lines are assigned to the same commit due to an ignored revision.

René Scharfe's fix modifies the coloring logic in `builtin/blame.c` to also check the previous line's commit when determining whether to apply the repeated-line color. The patch adds a new test case in `t/t8012-blame-colors.sh` that verifies the corrected behavior by creating a commit that changes whitespace (tabs to spaces) and then checking that the pre-whitespace-change lines are properly colored when using both `--color-lines` and `--ignore-rev`.

The change is relatively small but targeted, touching only the line coloring logic while maintaining all other blame functionality. The test case follows the existing pattern in the test file and provides clear verification of the fix. This appears to be a straightforward correction of the interaction between two specific blame features that wasn't properly handled in the original implementation.
