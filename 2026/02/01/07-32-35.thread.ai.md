Git thread summary:

Subject: git blame --color-lines with --ignore-rev shows incorrect coloring
Author: Seth McDonald
Type: bug report
Status: fixed by René Scharfe
Key details: When both --color-lines and --ignore-rev are used together, the coloring of consecutive lines with the same blame (after ignoring a specified revision) incorrectly followed pre-ignored revision history rather than reflecting the post-ignored state where lines should show the same commit.

Fix: René Scharfe submitted a patch modifying the coloring logic in builtin/blame.c to properly check the previous line's commit when determining repeated-line coloring. The fix adds a test case in t/t8012-blame-colors.sh that verifies correct behavior when ignoring a whitespace-changing revision. The change is minimal and focused specifically on the interaction between these two features.

Technical impact: The fix ensures that when multiple consecutive lines are assigned to the same commit due to an ignored revision, they will be properly colored cyan to indicate repetition, matching the behavior when --ignore-rev is not used. The patch corrects the logic while maintaining all other blame functionality.

Testing: The new test case creates a commit that changes whitespace (tabs to spaces) and verifies proper coloring when using both options. This follows existing test patterns and provides clear verification of the fix. The bug was reproducible across Git versions 2.47.3 and 2.53.0.rc2.
