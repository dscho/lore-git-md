Git thread summary:

Subject: git blame --color-lines with --ignore-rev shows incorrect coloring
Author: Seth McDonald
Type: bug report
Status: fixed by René Scharfe, confirmed working by original reporter
Key details: When both --color-lines and --ignore-rev are used together, the coloring of consecutive lines with the same blame (after ignoring a specified revision) incorrectly followed pre-ignored revision history rather than reflecting the post-ignored state where lines should show the same commit.

Fix: René Scharfe submitted a patch modifying the coloring logic in builtin/blame.c to properly check the previous line's commit when determining repeated-line coloring. The fix adds a test case in t/t8012-blame-colors.sh that verifies correct behavior when ignoring a whitespace-changing revision. Seth McDonald has confirmed the fix resolves the incorrect coloring behavior, with lines now properly colored cyan to indicate repetition when they share the same commit after ignoring a revision.

Technical impact: The correction ensures consistent coloring between cases where --ignore-rev is and isn't used, maintaining the expected behavior where consecutive lines from the same commit are colored cyan. The change is minimal and doesn't affect other blame functionality.

Testing: The new test case creates a commit that changes whitespace (tabs to spaces) and verifies proper coloring when using these options together. The fix has been verified across Git versions 2.47.3 and 2.53.0.rc2. The thread is now complete with the original reporter confirming resolution and no outstanding issues.
