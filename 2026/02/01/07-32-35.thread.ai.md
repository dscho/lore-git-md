Git thread summary:

Subject: git blame --color-lines with --ignore-rev shows incorrect coloring
Author: Seth McDonald
Type: bug report
Status: open
Key details: Demonstrates that when both --color-lines and --ignore-rev are used together, the coloring of consecutive lines with the same blame (after ignoring a specified revision) does not work as expected. The coloring follows the pre-ignored revision history rather than reflecting the post-ignored state where all lines should show the same commit (the one before the ignored revision) and thus be colored cyan.

Reproduction: The bug is reproducible across Git versions 2.47.3 and 2.53.0.rc2. The report includes clear steps to reproduce and environment details. The issue appears to be in the interaction between the two features in the coloring logic.

Open questions: Needs investigation into the blame coloring logic to properly account for the post-ignored revision state when determining line coloring. No maintainer response or proposed fixes yet.
