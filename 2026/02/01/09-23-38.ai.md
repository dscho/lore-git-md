Bugfix targeting the clone command's handling of --revision with older protocols.

This patch fixes a segmentation fault that occurs when cloning with `--revision` using protocol v0 or v1. The issue arises when the revision argument doesn't specify the full ref path (e.g. using `--revision master` instead of `--revision refs/heads/master:master`). 

The root cause is that with protocol v0/v1, Git fetches all references without filtering, which can leave `remote_head_points_at->peer_ref` NULL when updating references. The fix adds a check for this NULL case before attempting to update HEAD. The change is minimal - just one additional condition in the if statement in `builtin/clone.c`.

The commit message clearly explains the conditions that trigger the bug and the difference in behavior between v0/v1 and v2 protocols. While the fix is straightforward, the patch would benefit from including a test case that demonstrates the crash scenario to prevent regression. The issue appears to be a genuine bug rather than an edge case, as using shorthand revision names with older protocols is a reasonable thing to do.
