This is a bug report for `git blame`'s interaction between the `--color-lines` and `--ignore-rev` options. Seth McDonald demonstrates that when both options are used together, the coloring of consecutive lines with the same blame (after ignoring a specified revision) does not work as expected.

The report includes a detailed reproduction case showing that when a revision is ignored, all lines should show the same commit (the one before the ignored revision), and thus consecutive lines should be colored cyan. However, the coloring only follows the pre-ignored revision history rather than reflecting the post-ignored state.

The bug appears consistent across Git versions 2.47.3 and 2.53.0.rc2. The report is thorough, including environment details and clear steps to reproduce. This looks like a legitimate bug in the blame coloring logic that doesn't properly account for the post-ignored revision state when determining line coloring. The issue appears to be in the interaction between two features that both modify how blame information is displayed.
