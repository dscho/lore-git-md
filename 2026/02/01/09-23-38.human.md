Bugfix targeting the clone command's handling of --revision with older protocols.

This patch fixes a segmentation fault that occurs when cloning with `--revision` using Git protocol v0 or v1. The issue arises when the revision argument uses a short name (like `master`) rather than a full refspec (like `refs/heads/master:master`). In protocol v2, Git can filter references using the `ref-prefix` parameter, but v0/v1 fetches all references unconditionally, leading to a NULL pointer dereference when updating remote refs.

The fix is straightforward - it adds a check for `remote_head_points_at->peer_ref` before proceeding with the update. The commit message clearly explains the conditions that trigger the bug and why the fix works. This appears to be a well-motivated change addressing a real crash scenario, though it would be good to see a test case demonstrating the fix. The patch is small and focused, touching only the necessary lines in `builtin/clone.c`.
