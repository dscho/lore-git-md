This is a follow-up discussion in the `git replay --revert` feature series, specifically about how to handle commit reference formatting in revert messages. The patch in question extracted revert message formatting into a shared function between `sequencer.c` and the new `replay.c` code.

The key points:
- The discussion confirms that `git replay` as a plumbing command will ignore user configurations like `revert.reference`, maintaining consistency with Git's plumbing philosophy (as established by Junio Hamano)
- Siddharth Asthana explains the technical rationale for not sharing the `refer_to_commit()` logic between sequencer and replay - the sequencer needs to handle interactive cases with abbreviated references while replay uses full OIDs
- For v3, Siddharth implemented a compromise where `sequencer_format_revert_header()` takes an optional OID parameter, letting the sequencer handle its special cases while keeping the core formatting shared
- The thread shows good technical discussion about API design boundaries between plumbing and porcelain commands
- The implementation appears to be converging toward a clean separation of concerns while avoiding unnecessary code duplication

This email doesn't introduce new functionality but rather confirms design decisions and implementation details for the shared revert message formatting that will be part of the upcoming v3 series.
