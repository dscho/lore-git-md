This is a test infrastructure patch from Patrick Steinhardt, part of a series addressing CI failures on Windows/MSVC platforms related to `iconv` support. The patch modifies how the test suite checks for iconv capability, distinguishing between Git being built with libiconv support (a compile-time feature) and the availability of the `iconv(1)` executable (a runtime dependency).

The change moves the ICONV prerequisite check from a simple compile-time flag to a lazy evaluation that verifies both the build configuration and executable availability. This fixes test failures that occurred when Git was built with iconv support but the `iconv(1)` binary was missing - a situation that recently arose in Git for Windows. The patch includes a NEEDSWORK comment suggesting this check might later be split into separate prerequisites for the library and executable.

This is a well-motivated change that cleanly handles a real-world testing gap while maintaining backward compatibility. The patch is straightforward and follows the established pattern for prerequisite checks in the test suite. As the first in a series that already has passing CI and addressed review feedback, it appears ready for inclusion.
