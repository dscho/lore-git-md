This is the final patch in Patrick Steinhardt's series addressing test failures related to `iconv(1)` availability on Windows/MSVC platforms. The patch focuses on `t6006-rev-list-format.sh`, making two tests properly conditional on the ICONV prerequisite.

The change ensures tests that previously depended on the `iconv(1)` executable will now fall back to UTF-8 encoding when ICONV support isn't available, while maintaining the same test coverage. Junio Hamano reviews the patch and notes the clever handling of the encoding fallback - where `$test_encoding` is set to UTF-8 when ICONV isn't available, allowing the same test assertions to work in both cases.

The patch completes the series that has already received approval from Christian Couder, with all feedback from three iterations incorporated. It demonstrates a consistent approach to handling the distinction between libiconv (used by Git itself) and the `iconv(1)` executable (used in tests) across multiple test scripts. The solution is particularly important for Windows/MSVC environments where MinGW no longer ships the `iconv(1)` executable.
