Bugfix for `git apply --directory` path normalization.

Joaquim Rocha's v2 patch addresses the issue where `git apply --directory=./some/sub` fails due to literal interpretation of the "./" prefix. The patch now takes Patrick Steinhardt's suggestion to use `strbuf_normalize_path()` for comprehensive path normalization rather than just stripping "./" prefixes. This version handles multiple edge cases: "./" prefixes, double slashes, "./" in the middle of paths, and "../" traversal (while rejecting leading "../"). The implementation adds just 4-line change to `apply.c` but comes with extensive test coverage in `t4128-apply-root.sh` that verifies all these scenarios.

The patch appears well-constructed with clear commit message explaining the broader normalization approach. However, Junio Hamano's earlier skepticism about whether this level of generalization is needed remains an open question - the thread may see discussion about whether this exceeds the scope of fixing the original "./" issue. The tests suggest real-world cases exist where users might pass these varied path forms, but the performance impact of `strbuf_normalize_path()` versus a targeted fix hasn't been measured.
