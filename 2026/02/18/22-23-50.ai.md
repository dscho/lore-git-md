This patch is part of Adrian Ratiu's ongoing series to implement config-based Git hooks. It adds the ability to reset previously configured hook events by setting an empty value (`hook.<name>.event = ""`), bringing the behavior in line with other multi-valued Git config keys.

The change allows users to clear all previously defined events for a hook by specifying an empty event value, which is particularly useful when reconfiguring hooks. The implementation:
- Adds documentation explaining this reset behavior
- Modifies the config parsing logic in `hook.c` to handle empty values by clearing any existing event associations
- Includes a new test case verifying the reset functionality works as expected

This builds on the infrastructure from previous patches in the series, maintaining the same approach of incremental feature additions with corresponding test coverage. The change was suggested by Patrick Steinhardt during review of earlier versions.

The patch follows the series' pattern of careful backward compatibility while expanding hook configuration capabilities. It touches the same core files (hook.[ch] and t/t1800-hook.sh) that have been the focus throughout the development of config-based hooks.
