Bugfix patch refining `.git` directory validation in the setup code. This is the first of two patches in a series addressing symlinked `.git` directory handling with security implications.

The patch improves error handling in `read_gitfile_gently()` by distinguishing between different types of `stat()` failures. Currently, all stat failures are treated the same way, which prevents proper handling of legitimate cases like missing files versus actual errors. The changes introduce three new error codes: `READ_GITFILE_ERR_STAT_ENOENT` for missing files, `READ_GITFILE_ERR_IS_A_DIR` for directory paths, and keeps `READ_GITFILE_ERR_STAT_FAILED` for other stat errors. The `read_gitfile_error_die()` function is updated to handle these cases appropriately - allowing non-fatal paths (ENOENT, IS_A_DIR) to continue while maintaining fatal errors for other cases.

This is a preparatory change for the next patch in the series which will handle symlinked `.git` directories. The changes touch core repository setup code in `setup.c` and modify the error code definitions in `setup.h`. The patch appears well-contained with clear commit message explaining the motivation and changes. This is the sixth iteration of the series, having incorporated feedback from Junio Hamano and Karthik Nayak, suggesting the approach has been vetted by key maintainers.
