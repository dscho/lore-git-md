This is the third patch in Patrick Steinhardt's five-part series fixing test failures related to `iconv` handling on Windows/MSVC platforms. The patch focuses on t4205-log-pretty-formats.sh, which tests Git's pretty formatting capabilities.

The key change is making the test encoding behavior conditional on whether ICONV support is available. Previously, the test unconditionally used ISO-8859-1 encoding which would fail if the `iconv(1)` executable wasn't present, even when the ICONV prerequisite wasn't set. Now it falls back to UTF-8 when ICONV isn't available. This allows removing the ICONV prerequisite from many test cases that don't actually need encoding conversion.

The patch demonstrates careful attention to maintaining test correctness while improving portability. It keeps ICONV prerequisites only for tests that specifically exercise encoding conversion behavior via `i18n.logOutputEncoding`. The changes follow the pattern established in earlier patches of the series, showing consistent application of the solution across different test files.

This continues the series' goal of making Git's test suite more robust on Windows platforms where the `iconv(1)` executable may not be available, while preserving all test functionality when full ICONV support is present. The changes are well-contained and the commit message clearly explains both the problem and solution.
