This is part 3/8 of Adrian Ratiu's series implementing config-based Git hooks, introducing a new `git hook list` subcommand to inspect configured hooks. The patch builds on the infrastructure from part 2/8 that enabled multiple hooks per event.

The new `git hook list <hook-name>` command displays all hooks that would run for a given event, currently only showing traditional filesystem hooks (from `.git/hooks/`) with a simple "hook from hookdir" label. The implementation:
- Exposes the previously internal `list_hooks()` and `hook_list_clear()` functions
- Returns exit code 1 with a warning if no hooks exist for the event
- Includes basic tests verifying the command's behavior with missing and present hooks

The commit message notes this is groundwork for future additions like `-z` output mode and config-based hooks, which will be added in subsequent patches. The implementation maintains Emily Shaffer's original sign-off while being rebased onto the current series.

This patch is a straightforward addition that provides visibility into the hook system, which will become more important as config-based hooks are introduced. The tests cover the basic functionality but will need expansion when config hooks are added. The code follows Git's established patterns for subcommand implementations.
