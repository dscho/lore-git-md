This is the second patch in a 5-part series fixing test failures related to iconv usage on Windows/MSVC platforms. The patch addresses three test scripts in the t40xx range that deal with submodule diff behavior.

The issue stems from tests unconditionally calling the `iconv(1)` executable even when the ICONV prerequisite isn't met. While the tests are designed to fall back to UTF-8 when iconv isn't available, they were still attempting to use the executable first. This caused failures on systems where Git is built with ICONV support (using libiconv) but the `iconv(1)` executable isn't present - a common scenario on Windows/MSVC.

The patch modifies each test to first check the ICONV prerequisite before attempting to use iconv. When the prerequisite isn't met, it skips the iconv conversion entirely since converting UTF-8 to UTF-8 would be a no-op anyway. The changes follow a consistent pattern across all three test files, making the tests more robust while maintaining their existing behavior.

This is part of Patrick Steinhardt's ongoing work to improve test reliability on Windows platforms. The changes are straightforward and well-contained, addressing a clear issue that was causing CI failures. The patch series has already gone through multiple iterations incorporating review feedback, and this particular change looks ready for inclusion.
