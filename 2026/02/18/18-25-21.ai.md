This is a security-focused patch discussion about hardening Git's repository discovery against malicious `.git` entries. The email from Junio Hamano provides detailed review feedback on Tian Yuchen's v5 patch series, specifically addressing the second patch which deals with symlink handling.

Junio points out several issues with the current implementation. The core concern is that the patch unconditionally calls `read_gitfile_error_die()` without respecting the `die_on_error` flag, which changes the control flow from the original behavior where non-fatal errors would return `GIT_DIR_INVALID_GITFILE`. He notes the original intent was to specifically handle directory cases with `is_git_directory()` when `.git` is actually a directory, and to properly propagate error conditions when callers don't want immediate termination.

The review highlights that the patch needs to maintain the existing error handling contract where:
1. Directory cases should trigger `is_git_directory()` checks
2. Non-fatal errors should return `GIT_DIR_INVALID_GITFILE` when `die_on_error` is false
3. The security hardening against FIFOs/sockets should be preserved

This discussion follows up on earlier feedback from Karthik Nayak about preserving control flow in error cases. The thread shows the careful balance required between security hardening (rejecting dangerous `.git` entry types) and maintaining backward compatibility with legitimate use cases (like symlinks to directories). Junio's comments suggest the patch needs restructuring to properly handle these edge cases while keeping each patch in the series in a working state.
