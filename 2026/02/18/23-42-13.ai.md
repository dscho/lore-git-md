This is a feature addition to the `git replay` command, introducing a `--revert` mode for server-side history rewriting. The patch series is now at v3, with Siddharth Asthana addressing feedback from previous rounds of review.

The changes enable `git replay` to reverse commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service where server-side operations on bare repos are common. The implementation follows the same approach as `sequencer.c`, treating reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to effectively reverse the diff direction.

Key technical aspects of v3 include:
- Rebased on top of recent upstream changes that refactored replay into a library (replay.c/replay.h)
- Shared revert message formatting via `sequencer_format_revert_header()` with optional OID parameter
- Improved option validation using `die_for_incompatible_opt3()`
- Consolidated ref update logic between modes
- NULL author handling for revert commits to pick up current user
- Test improvements including bare repo cases and error scenarios

The series maintains the architectural principle that `git replay` as plumbing should ignore user configurations by default, following Junio Hamano's guidance. The implementation has been reviewed by Phillip Wood, Patrick Steinhardt, and others, with all technical points from prior discussion addressed.
