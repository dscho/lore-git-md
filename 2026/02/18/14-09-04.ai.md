This is a bugfix patch targeting the strbuf subsystem, specifically the string reencoding functionality. The patch corrects an off-by-one error in memory allocation when attaching a reencoded string buffer.

The issue occurs in `strbuf_reencode()` where the function was passing an allocation size that was one byte too small when attaching the reencoded output buffer. This caused unnecessary reallocations even when the buffer size was sufficient. The fix changes the allocation parameter from `len` to `len + 1` to properly account for the NUL terminator that `reencode_string_len()` includes in its allocation.

The patch is straightforward - a single line change with a clear commit message explaining both the problem and solution. It's part of a 5-patch series (this being the first), though the other patches in the series weren't provided in this digest.
