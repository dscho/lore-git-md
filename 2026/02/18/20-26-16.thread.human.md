This thread focuses on correcting and standardizing the behavior of `format.noprefix` in Git's format-patch functionality. Kristoffer Haugsbakk's initial patch series makes `format.noprefix` behave as a proper boolean value (rejecting non-boolean configurations), bringing it in line with how `diff.noprefix` already works. The implementation adds proper config validation in `builtin/log.c` with clear error messages, following Jeff King's established patterns for similar config validation.

A follow-up documentation patch fixes an inconsistency in the `git-format-patch` man page, which incorrectly referenced `diff.noprefix` instead of `format.noprefix`. The correction uses AsciiDoc conditionals to show the right config variable depending on which command's documentation is being built. This change makes the docs accurately reflect that `git-format-patch` only respects `format.noprefix`, not `diff.noprefix` as previously documented.

The changes are technically breaking for any users who had non-boolean values set for `format.noprefix`, but this is justified since the documentation always described it as boolean and such configurations are rare. Error messages include transition hints to help affected users. The series includes new tests verifying both the boolean behavior and error messaging.
