This thread documents and fixes an inconsistency in how Git handles the `format.noprefix` configuration. Kristoffer Haugsbakk's series aligns the implementation with the documented behavior by making `format.noprefix` properly validate as a boolean (rejecting non-boolean values like "yes" or "on"), while improving related documentation.

The behavioral change, which technically breaks configurations using non-boolean values, is justified as a bug fix since the documentation has always specified boolean values. Jeff King (Peff) confirmed this view, noting the only affected cases would be users with non-boolean values (unlikely) or those setting `false` expecting it to enable the feature (unreasonable). Junio Hamano reviewed the changes and suggested strengthening the error messages to explicitly explain the transition from the old "accept any value" behavior, recommending direct `advise()` calls for configuration corrections.

The documentation portion fixes two issues: correcting the `git-format-patch` man page to reference `format.noprefix` instead of the incorrect `diff.noprefix`, and clarifying how `--default-prefix` interacts with `format.noprefix`. Junio has reviewed and queued these documentation patches, noting the use of AsciiDoc conditionals is appropriate despite being a new approach for this case.

With all feedback incorporated, the series is now complete. The changes bring the implementation in line with longstanding documentation while providing clear guidance for any users who might need to update their configurations.
