Test infrastructure patch series from Patrick Steinhardt addressing CI failures on Windows/MSVC platforms where tests were failing due to missing `iconv(1)` executable when Git was built with ICONV support. This is the third iteration of the series, now restructured to make the scope clearer while maintaining all technical improvements from previous rounds.

The core issue stems from Git for Windows no longer including the `iconv(1)` executable by default, though the libiconv library is still available. The series modifies several test scripts (t40xx, t4205, t5550, t6006) to properly handle cases where the ICONV prerequisite is set (indicating libiconv is available) but the `iconv(1)` executable is missing. The tests now skip iconv usage in such cases, falling back to UTF-8 encoding.

Key changes in v3 include splitting out the ICONV prerequisite modifications into a standalone commit and maintaining all the test fixes from v2. The series follows the established pattern of conditionally using iconv only when both the library and executable are available, while cleanly handling cases where they are not. This resolves the MSVC+Meson CI failures while keeping the tests functional across different platform configurations.

The patch series appears well-considered, with all previous review feedback addressed. The changes are focused and maintain test reliability without making assumptions about tool availability. This is part of ongoing work to improve Git's test infrastructure, particularly for Windows/MSVC environments.
