This is a technical discussion about the implementation details of the `git replay --revert` feature, specifically focusing on how commit references should be formatted in revert messages. The conversation follows up on earlier reviews of Siddharth Asthana's patch series that extracted revert message formatting into a shared function.

The key points center around whether `git replay` should respect the `revert.reference` configuration like `git revert` does. Junio Hamano has established that as a plumbing command, `git replay` should ignore user configurations by default for consistency. Siddharth confirms this principle will be followed in the upcoming v3 of the patch series.

The discussion also covers implementation approaches for sharing the revert message formatting logic between `sequencer.c` and `replay.c`. Siddharth has settled on passing an optional OID parameter to the shared `sequencer_format_revert_header()` function - when NULL, the sequencer handles the reference formatting itself (respecting interactive settings), while `replay` always passes the OID for consistent plumbing behavior.

Toon Claes and Patrick Steinhardt had suggested alternative approaches using flags or bool parameters, but Siddharth found the OID parameter approach simpler for current needs while leaving room for future refinement. The v3 series will incorporate this along with other review feedback, though the core architecture question about configuration handling is now settled per Junio's guidance.

This email represents the final coordination before v3 is sent, with Siddharth noting the series has been rebased on recent upstream changes that moved replay logic into a separate library (replay.c/replay.h).
