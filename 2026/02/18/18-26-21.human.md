Performance optimization in the shallow push handling series. This is a review response from Justin Tobler on Patrick Steinhardt's patch that optimizes `lookup_commit_reference_gently()` to avoid parsing non-commit objects during shallow pushes.

The patch changes the function to first check object types via `peel_object_ext()` before parsing, which yields significant improvements when dealing with repositories containing many non-commit refs: 1.63x speedup and a dramatic memory reduction (from 352MB to 17MB in use at exit). The optimization is particularly wasteful cases where many refs point to blobs or trees.

Justin's review confirms the technical approach, noting how the change avoids unnecessary object parsing while maintaining the same behavior for commit objects. The implementation appears sound, carefully preserving error handling while eliminating the performance bottleneck. This is the first of three patches in a series targeting shallow push performance, with the subsequent patches addressing commit-graph integration and further optimizations.
