This is a feature patch series (v2) from Adrian Ratiu that enables configuring Git hooks via Git configuration, building on earlier work by Emily Shaffer. The series introduces config-based hooks through `hook.<name>.command` and `hook.<name>.event` options while maintaining compatibility with filesystem hooks.

The key improvements in v2 include:
- Introducing a proper `struct hook` with typing information to replace the temporary string-based identification
- Adding config caching in the repository object to optimize performance, particularly for frequently-called hooks like `reference-transaction`
- Implementing a `hook.<name>.enabled` toggle to disable hooks
- Supporting `event = ""` config entries to reset previous values
- Adding a `-z` option to `git hook list` for script-friendly output
- The series now properly handles out-of-repo hook invocations
- Documentation has been improved with modern `git config set` examples
- Memory management has been optimized with better allocation/free callbacks

The implementation touches core hook infrastructure in `hook.[ch]`, modifies several commands (`receive-pack`, `transport`), and adds extensive tests in `t/t1800-hook.sh`. The changes enable users to define hooks in config files rather than requiring filesystem scripts, making it easier to share hooks across repositories.

The series shows steady progress from v1, with v2 incorporating feedback from Patrick Steinhardt and Junio Hamano. The performance optimizations in particular address real-world concerns about hook execution overhead. The implementation looks thorough and well-tested, with parallel execution planned as a follow-up series.
