This is a bug report describing issues with `git rebase --abort` failing to properly clean up after a segmentation fault. The reporter experienced a crash during a rebase (at commit 7 of 18) that left their repository in a stuck state where:

1. Both `--continue` and `--abort` initially failed
2. The repository showed rebase status messages across all branches
3. A lock file (`MERGE_RR.lock`) remained despite no other Git process running
4. After removing the lock file manually, operations still failed with a segmentation fault

The repository eventually appeared to "self-heal" after checking out the original branch and retrying `--abort`, though the reporter notes this wasn't a controlled resolution. The report lacks precise reproduction steps but provides clear symptoms of a rebase cleanup failure following a crash. This suggests a potential issue in how Git handles error recovery during interrupted rebase operations, particularly around lock file management and state cleanup.
