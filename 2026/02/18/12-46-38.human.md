This is the second patch in a two-part bugfix series addressing security and usability around symlinked `.git` directories. The patch refines Git's handling of `.git` symlinks to allow legitimate cases while maintaining security protections.

The change modifies `setup.c` to use `stat()` rather than `lstat()` when checking `.git` entries, allowing symlinks that point to valid Git repositories while still rejecting dangerous cases like FIFOs and invalid files. The patch introduces comprehensive tests in a new `t0009-git-dir-validation.sh` that verify:
- Valid symlinks to Git directories work
- FIFOs and symlinks to FIFOs are rejected
- Garbage content in `.git` files is caught
- Empty `.git` directories are handled properly

This is the sixth iteration of the series, having incorporated feedback from Junio Hamano and Karthik Nayak. The implementation appears thorough, with careful attention to maintaining security boundaries while relaxing overly strict checks. The test coverage is extensive, including platform-specific cases (SYMLINKS and PIPE prerequisites). The patch looks ready for final review, with no outstanding issues noted in the thread.
