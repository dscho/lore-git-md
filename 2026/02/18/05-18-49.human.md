This is the first patch in a two-part security series hardening Git's repository discovery by validating `.git` file types. The patch refactors error handling in `read_gitfile_gently()` to distinguish between different types of `stat()` failures, separating "path doesn't exist" (non-fatal, continue searching) from invalid paths (fatal error).

The changes introduce two new error codes (`READ_GITFILE_ERR_STAT_ENOENT` and `READ_GITFILE_ERR_IS_A_DIR`) and update the error handling logic in `setup.c` to treat them appropriately. This prepares for the security checks in the next patch that will reject dangerous `.git` entries like FIFOs and sockets while maintaining support for legitimate symlinks.

The patch is part of a well-reviewed series that has gone through five iterations, with all feedback from maintainers addressed. The implementation is clean and focused, touching only the necessary parts of `setup.c` and `setup.h` with clear error handling paths. This foundational work enables the security hardening in the follow-up patch while maintaining Git's existing behavior for valid repository discovery cases.
