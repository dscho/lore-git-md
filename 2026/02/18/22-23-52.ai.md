This is the final patch in Adrian Ratiu's v2 series implementing config-based Git hooks. The patch adds a `-z` option to `git hook list` that outputs NUL-terminated lines instead of newlines, making the output more robust for hooks with unusual characters in their names.

The implementation:
- Adds the `-z` flag to the `list` subcommand documentation
- Modifies the output formatting in `builtin/hook.c` to use the specified terminator (newline by default, NUL with `-z`)
- Includes a new test case verifying NUL-terminated output works correctly

The change is straightforward and follows Git's convention for machine-readable output options (similar to `-z` in other commands like `ls-files`). Patrick Steinhardt suggested this addition, likely anticipating edge cases where hook names might contain newlines or other special characters.

This completes the series' core functionality, which now provides:
- Config-based hooks alongside traditional filesystem hooks
- Multiple hooks per event with configurable execution order
- Enable/disable toggles and event reset capability
- Out-of-repo operation for config hooks
- Machine-readable listing of active hooks

The patch maintains backward compatibility while adding this final piece of functionality for robust hook management. The implementation is cleanly scoped to the hook listing feature without introducing broader architectural changes.
