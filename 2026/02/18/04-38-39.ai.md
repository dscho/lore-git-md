This is the second patch in a 5-part series addressing test failures on Windows/MSVC platforms related to `iconv(1)` availability when Git has ICONV support enabled. The patch focuses on three submodule-related test files in the t40xx range (t4041, t4059, t4060).

The core issue is that these tests were unconditionally calling the `iconv(1)` executable even when the ICONV prerequisite wasn't met, which happens when either the library or executable isn't available. The tests were prepared to handle this case (falling back to UTF-8), but still attempted the `iconv` call first. The patch makes the iconv usage properly conditional on the ICONV prerequisite.

Each test file follows the same pattern - they generate commit messages that need encoding conversion. The changes introduce a conditional block that only performs the iconv conversion when ICONV is available, otherwise using the UTF-8 message directly. This maintains the existing fallback behavior while making it more correct by avoiding attempts to call a potentially missing executable.

The changes are mechanical and consistent across all three files, showing this was a systematic issue in the test suite. This patch builds on the first in the series which modified the ICONV prerequisite check itself, and is part of Patrick Steinhardt's ongoing work to improve test reliability on Windows/MSVC platforms where the `iconv(1)` executable may not be available even when libiconv is present.
