This is a performance optimization patch in Patrick Steinhardt's series improving shallow push handling in `git receive-pack`. Justin Tobler provides a review of the first patch, which optimizes `lookup_commit_reference_gently()` to avoid parsing non-commit objects unnecessarily.

The key change modifies `lookup_commit_reference_gently()` to first use `peel_object_ext()` to determine an object's type before parsing it, rather than unconditionally parsing all objects. This provides significant performance gains when processing repositories with many non-commit refs, as shown in Patrick's benchmarks: a 1.63x speedup (62.571s -> 38.339s) and dramatic memory reduction (407MB -> 15.5MB allocations) when pushing to repos with 100k refs. The optimization has no impact when all refs point to commits, as expected.

Justin's review confirms the technical approach, noting how the patch avoids wasteful parsing by first peeling objects to check their type. He points out one minor typo in the commit message but otherwise finds the implementation sound. The changes touch core object handling code in commit.c and object.c, introducing a new `peel_object_ext()` variant that returns type information.

This is the first of three patches in the series, establishing the foundation by optimizing non-commit handling before subsequent commits address commit-graph integration. The review interaction shows the careful, incremental approach being taken to improve shallow push performance through targeted object lookup optimizations.
