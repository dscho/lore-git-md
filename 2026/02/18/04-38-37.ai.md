This is a test infrastructure patch series from Patrick Steinhardt addressing CI failures on Windows/MSVC platforms related to `iconv(1)` executable availability. The series is now in its third iteration (v3) and has incorporated all previous review feedback.

The core issue stems from Git for Windows no longer including the `iconv(1)` executable by default, causing test failures in MSVC-based CI jobs. The series modifies several test scripts (t40xx, t4205, t5550, t6006) to properly handle cases where the ICONV prerequisite isn't met, either because Git wasn't built with ICONV support or because the `iconv(1)` executable is missing.

Key technical changes in v3 include:
1. Splitting out the ICONV prerequisite changes into a standalone commit
2. Extending the ICONV prerequisite in test-lib.sh to check for both library support and the executable
3. Adding a NEEDSWORK comment about potentially splitting these checks in the future
4. Modifying test scripts to skip iconv(1) usage when the prerequisite isn't met
5. Maintaining UTF-8 fallback behavior where appropriate

The series follows a consistent pattern across all affected tests - they now properly respect the ICONV prerequisite rather than assuming the executable exists. This makes the tests more robust on systems without iconv(1) while maintaining existing functionality where available.

Patrick has addressed all feedback from previous rounds, including:
- Clarifying the scope in commit messages
- Referencing the Git for Windows issue (#6083)
- Converting raw grep calls to test_grep
- Fixing grammatical issues
- Including t6006 in the solution

The changes are now ready for final review, with the MSVC CI jobs passing again. The series demonstrates careful attention to test portability while avoiding unnecessary complexity (like introducing a separate ICONV_EXECUTABLE prerequisite). The clean separation between build-time ICONV support and test-time iconv(1) availability is particularly well-handled.
