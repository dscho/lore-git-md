This is a feature proposal for the `git repo info` command, part of the ongoing effort to rationalize repository introspection functionality currently scattered across `git rev-parse` and other commands. Pushkar Singh builds on Patrick Steinhardt's earlier endorsement of moving repository metadata out of `git rev-parse`, proposing to add stable path outputs (`path.git-dir`, `path.common-dir`, `path.objects-dir`) to the structured output format of `git repo info`.

The patch suggests reusing the existing `repo_info_fields[]` mechanism that Lucas Skeggs recently enhanced with `--format` and `--keys` support. Pushkar focuses on repository-derived paths (like those from `repo_get_git_dir()`) while deliberately avoiding invocation-dependent values for now. The path formatting behavior (absolute vs relative) would align with whatever consensus emerges from the parallel `--path-format` discussion.

This continues the thread's technical trajectory of making `git repo` the canonical home for repository introspection, with Patrick having previously noted `git rev-parse` has outgrown its original purpose. The proposal is narrowly scoped to avoid reopening broader design questions, instead focusing on mechanically exposing existing repository state through the new structured output interface. The thread shows alignment on direction but leaves path formatting semantics to be resolved separately.
