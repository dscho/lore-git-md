This is a documentation patch that adds a new style guideline to Git's CodingGuidelines. It's the first of an 8-part series focused on naming consistency and code organization following recent `git-repo-info` and `git-repo-structure` work.

The patch proposes that array variables should be named in singular form (e.g. `dog[]` rather than `dogs[]`), with the rationale that this makes array element access (like `dog[0]`) read more naturally as referring to a single element rather than a collection. The change is purely stylistic - it doesn't affect functionality - and follows the pattern of other naming conventions in the CodingGuidelines document.

The patch is small and focused, cleanly implementing a single guideline with clear before/after examples. As the first in a series that appears to incorporate prior feedback (referencing message IDs from earlier discussion), it sets a pattern of small, incremental improvements to naming and documentation consistency. The change is uncontroversial and aligns with Git's general preference for clear, consistent naming.
