Test patch for contrib/subtree history depth verification. This is the second patch in a 3-part series (v2) that adds commit history depth checks to subtree tests. The tests verify that split operations maintain expected commit counts in various scenarios, including:

- Basic subtree splits with --rejoin
- Multiple simultaneous subtree operations
- Nested subtree cases

The patch modifies t7900-subtree.sh to add `rev-list --count` assertions that were originally introduced in commit 28a7e27cff but were lost when that commit was reverted. The tests now explicitly verify commit counts for split branches and their relationships to main branches.

Key technical details:
- Adds branch names (-b spl/a1/b1/etc) to make rev-list targets explicit
- Verifies expected commit depth after splits (e.g. main..a1 should have 1 commit)
- Checks incremental depth between split operations (a1..a2 should add 1 commit)
- Maintains all existing test logic while adding the new assertions

The changes are focused on test coverage rather than modifying subtree functionality itself. The patch appears to be part of an ongoing effort to improve subtree test robustness.
