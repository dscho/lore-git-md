This is part of Adrian Ratiu's ongoing series to implement config-based Git hooks, now at version 2. The patch introduces internal state management for hook callbacks, preparing for future parallel hook execution.

The change adds alloc/free helpers for hook callback data structures, replacing stack-allocated state that worked when hooks ran sequentially. The new approach:
- Provides typed alloc/free functions for each hook's internal state
- Ensures proper cleanup with BUG() checks if callbacks are mismatched
- Maintains backward compatibility while enabling future parallel execution

The implementation touches several hook-related files (hook.[ch], receive-pack.c, refs.c, transport.c) and handles cases like:
- Reference transaction hooks that track state across multiple callbacks
- Pre-push hooks that need to maintain buffer state
- Receive-pack hooks that feed data incrementally

This foundational change enables the rest of the series to safely manage hook state when running multiple commands per hook event. The patch shows careful attention to memory management and lays groundwork for future parallelization while maintaining existing behavior.
