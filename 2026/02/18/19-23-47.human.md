This is the second patch in Patrick Steinhardt's three-part series optimizing shallow push performance in `git receive-pack`. The patch focuses on hardening `repo_parse_commit_no_graph()` to handle edge cases when commits were previously parsed via the commit-graph.

The issue arises when writing a new commit-graph while commits are still in memory from a previous commit-graph lookup. These commits have their `maybe_tree` field unpopulated, leading to segfaults when code tries to access the tree. The patch makes the function more robust by first unparsing such commits, forcing a fresh parse that properly populates all fields.

Justin Tobler's review confirms the technical approach but raises a philosophical question about whether `repo_get_commit_tree()` should handle this case instead. The patch includes a Coccinelle rule update to allow direct `maybe_tree` access, as the change requires bypassing the usual accessor.

This is a defensive change that prepares for the series' final optimization (using commit-graph for faster parsing) while fixing a subtle edge case that could surface during commit-graph writing. The fix is narrowly scoped to maintain performance, with no expected impact on normal operations.
