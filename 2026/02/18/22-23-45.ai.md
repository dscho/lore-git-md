This is part of Adrian Ratiu's ongoing series to implement config-based Git hooks, now at version 2. The patch adds internal state management infrastructure needed for upcoming parallel hook execution support.

The change introduces alloc/free callbacks for hook state management, replacing stack-allocated state that worked when hooks ran sequentially. The new mechanism:
- Adds `cb_data_alloc_fn` and `cb_data_free_fn` typedefs in hook.h
- Extends `struct run_hooks_opt` with alloc/free function pointers
- Enforces that alloc and free are provided together via BUG() check
- Updates three hook implementations (receive-pack, refs, transport) to use the new pattern
- Maintains existing behavior while preparing for parallel execution

Key technical details:
- State is now heap-allocated per hook run via xmalloc/xcalloc
- Initialization context can be passed through `feed_pipe_ctx`
- Memory management follows strict ownership rules (alloc must have matching free)
- Backward compatible with existing hook implementations

The change touches core hook execution paths but doesn't yet enable parallel processing - that comes in later patches. This foundational work addresses a prerequisite identified during review of the series, ensuring proper state isolation when multiple hook instances run concurrently.
