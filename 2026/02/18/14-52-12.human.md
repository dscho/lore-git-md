This is the second patch in a 4-part series implementing UTF-8 support for Git configuration subsections, specifically for aliases like `[alias "förgrena"]`. The series has gone through six iterations with all technical issues resolved, including final fixes for zsh completion.

The current change refactors the alias parsing logic in `help.c` to use `parse_config_key()` instead of `skip_prefix()`, properly handling the three-level config key structure needed for subsection support. This is a preparatory step for the actual UTF-8 alias support coming in the next patch.

Notably, this introduces a compatibility break: previously, Git would accept malformed alias definitions like `alias.foo.bar` and treat them as an alias named "foo.bar". Now such entries will be silently ignored unless the key is "command" (which gets special handling in the next patch). The commit message argues this was effectively a bug since dotted aliases were never intentionally supported.

The change is small (10 lines modified) and focused, with the diff showing the switch from `skip_prefix()` to `parse_config_key()` while maintaining the same basic alias registration behavior for non-subsection cases. The patch has already been reviewed and approved by Jeff King and Junio Hamano in previous iterations.
