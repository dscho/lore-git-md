This is part 5/8 of Adrian Ratiu's series implementing config-based Git hooks, adding the ability to disable configured hooks without removing them from config files. The patch introduces a new `hook.<name>.enabled` configuration option that defaults to true but can be set to false to skip execution while preserving the hook definition.

The implementation adds a `disabled_hooks` string list to track disabled hooks during config lookup, filtering them out before execution. The patch includes comprehensive tests verifying that disabled hooks are skipped (both in execution and `git hook list` output), that the setting can override global configurations, and that invalid boolean values are ignored.

This builds on the config hook infrastructure from previous patches, maintaining the series' pattern of incremental functionality with thorough test coverage. The change is focused in hook.c with corresponding documentation updates, following the broader effort to make hooks more flexible while maintaining backward compatibility. Patrick Steinhardt suggested this feature, which addresses a real workflow need for temporarily disabling hooks defined in shared configs.
