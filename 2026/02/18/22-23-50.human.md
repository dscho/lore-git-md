This is part 6/8 of Adrian Ratiu's series implementing config-based Git hooks. The patch adds the ability to reset previously configured hook events by setting an empty value (`hook.<name>.event = ""`), bringing the behavior in line with Git's standard handling of multi-valued config keys.

The change allows administrators to clear all previously defined events for a hook while keeping its command configuration intact. This is particularly useful when reconfiguring hooks across multiple events, as it provides a clean way to remove old event bindings before adding new ones. The implementation carefully handles the string list manipulation to maintain proper ordering while clearing entries.

The patch includes:
- Documentation updates explaining the reset behavior
- Core logic in hook.c to clear event mappings when encountering empty values
- A new test case verifying the reset functionality works as expected

This continues the series' pattern of incremental improvements to the hook configuration system while maintaining backward compatibility. The change was suggested by Patrick Steinhardt during review of earlier versions. With this addition, the config-based hook system gains more flexible management capabilities while keeping the interface consistent with Git's existing config semantics.
