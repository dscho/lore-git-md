This is the final patch in Adrian Ratiu's series implementing config-based Git hooks, adding a `-z` option to `git hook list` for NUL-terminated output.

The patch adds support for NUL-terminated output in the `git hook list` subcommand, which displays configured hooks for a given event. This is useful when hook names contain unusual characters like newlines, as NUL termination provides unambiguous parsing. The change follows Git's convention for machine-readable output (similar to `-z` options in other commands like `git ls-files`).

Implementation adds:
- A new `-z` flag to `git hook list`
- Documentation updates explaining the option
- A test case verifying NUL-terminated output works correctly
- Internal changes to use the specified terminator (newline or NUL) when printing hook information

The patch maintains consistency with the rest of the series by:
- Keeping the same hook execution order (config hooks first, filesystem hooks last)
- Preserving the existing behavior for disabled hooks (they remain filtered from output)
- Following the established pattern of incremental test expansion

This completes the v2 series which has introduced config-based hooks as a flexible alternative to filesystem hooks while maintaining backward compatibility. The series has evolved through multiple rounds of review, with this final patch addressing a suggestion from Patrick Steinhardt to support machine-parsable output.
