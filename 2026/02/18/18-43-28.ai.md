Security hardening patch series discussion. Junio Hamano provides additional review feedback on Tian Yuchen's v5 patch series that strengthens Git's repository discovery security by validating `.git` file types. The current exchange focuses on ensuring the error handling changes don't break existing callers outside the immediate security context.

Junio notes that while the core approach of distinguishing different stat() error types (ENOENT vs other failures) is sound, the changes to `read_gitfile_gently()` and `read_gitfile_error_die()` must maintain compatibility with all existing callers, including those in submodule.c and other parts of the codebase. He emphasizes the need to audit these external call sites to ensure they properly handle the refined error taxonomy being introduced.

The review highlights a key tension in security hardening work: balancing the need for stricter validation with maintaining backward compatibility across Git's codebase. Junio's comments suggest the series is conceptually approved but requires careful attention to integration points before merging. The author will need to verify that submodule handling and other edge cases continue working as expected with the new error classification system.
