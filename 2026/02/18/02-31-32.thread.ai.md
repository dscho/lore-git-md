Thread identity: Bugfix patch series (v2 3/3) for `git subtree` contrib command, addressing commit exclusion issues during subtree splits. Originating author not specified in this patch (but appears to be part of a series from a known contributor based on the referenced commit hashes).

Core problem: The `git subtree` split operation was incorrectly excluding commits based on trailer-based heuristics in `should_ignore_subtree_split_commit`, violating the API contract that commit hashes should remain stable across splits. This particularly affected merge commits and rebased/cherry-picked subtree commits.

Current status: Third version of fix in this series (v2 3/3), following prior attempts (98ba49c, 83f9dad, 28a7e27). The solution removes the problematic optimization entirely rather than attempting to fix it, as the current implementation both slowed operations and produced incorrect results.

Key technical details:
- Removed `should_ignore_subtree_split_commit` function that checked commit trailers to identify "foreign" subtree commits
- Fixed behavior where merge commit ancestry checks depended on complete split history
- Ensured consistent history maintenance across rebased/cherry-picked subtree commits
- Added test cases covering multiple subtrees and rebased commits with trailers

Open questions: None raised in this patch - appears to be the culmination of prior discussion with George and Christian Heusel who reported the regressions.
