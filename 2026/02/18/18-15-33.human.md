This is a review comment from Git maintainer Junio Hamano on Tian Yuchen's security hardening patch series. The series aims to improve Git's handling of `.git` directory discovery by properly validating file types (rejecting FIFOs/sockets while allowing symlinks).

Junio is questioning the patch organization in v5, noting that the first patch introduces new error types but doesn't fully update all callers to handle them correctly. He observes that after applying patch 1/2 but before patch 2/2, Git would lose the ability to handle plain `.git` directories properly. This violates Junio's principle that each patch should leave the code in a working state.

The core issue is about patch sequencing and completeness - Junio prefers each patch in a series to be self-contained rather than having intermediate states where behavior is broken. He suggests either combining the error type changes with their corresponding caller updates in each patch, or making sure each patch fully transitions the code to handle all new error cases properly.

This is a maintainer-level review focusing on patch organization rather than the technical merits of the security hardening itself (which appears sound). The author will need to restructure the series to address these concerns before it can be merged.
