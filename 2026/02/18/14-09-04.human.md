This is a bugfix patch for the strbuf subsystem, correcting an off-by-one allocation issue in `strbuf_reencode()`. The patch fixes a case where the function was passing an allocation size that was one byte too small when attaching a re-encoded string buffer, causing unnecessary reallocations.

The commit explains that `reencode_string_len()` allocates len+1 bytes (including the NUL terminator) but returns just len, and the original code was passing len as both the length and allocation size to `strbuf_attach()`. This meant the strbuf would always trigger a reallocation even when the buffer was the correct size. The fix is straightforward - passing len+1 as the allocation size - and comes with a clear explanation of both the problem and solution.

The patch appears well-contained and correct, touching only the strbuf.c file with a simple one-line change. It's part of a 5-patch series (this being the first), though the other patches aren't shown here. The author, Vaidas Pilkauskas from Shopify, provides a proper Signed-off-by line.
