This is a final polishing patch in a series enabling reference storage backend selection, adding environment variable support for specifying the backend. The patch introduces `GIT_REFERENCE_BACKEND` as an environment variable counterpart to the existing `extensions.refStorage` config, allowing runtime backend selection for commands like `git clone` and `git init`.

The implementation handles stub directory creation in the repository's `$GIT_DIR` when using alternate reference storage, with special consideration for worktree cases. The files backend remains exempt from some stub management due to its worktree requirements. Toon Claes suggests a clearer comment about stub requirements in the only remaining open discussion point.

With maintainer approval already secured and all substantive feedback addressed, this represents the last piece of a multi-version effort primarily serving GitLab's migration needs between files and reftable backends. The series is now complete with comprehensive test coverage and all configuration mechanisms (config, URI, environment variable) implemented.
