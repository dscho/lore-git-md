Security hardening patch series review from Junio Hamano, the Git maintainer, regarding Tian Yuchen's v5 series that strengthens repository discovery security by validating `.git` file types. This email focuses on patch 1/2 which distinguishes `ENOENT` from other `stat()` errors during repository setup.

Junio questions the patch organization, noting that while the commit message describes handling both missing files (`ERR_STAT_NOENT`) and directories (`ERR_IS_A_DIR`), the implementation appears incomplete without the corresponding caller changes from patch 2/2. He points out that the current split leaves the code in an inconsistent intermediate state where plain `.git` directories would stop working between applying patch 1/2 and patch 2/2.

The maintainer prefers each patch to be self-contained rather than relying on follow-up patches to complete the functionality. He suggests either combining the error type additions with their corresponding caller handling in a single patch, or making sure each incremental change maintains working behavior.

This feedback indicates the series needs restructuring before merging, with Junio emphasizing the importance of maintaining bisectability and logical patch boundaries. The security hardening itself isn't in question - the discussion focuses on implementation approach and patch organization.
