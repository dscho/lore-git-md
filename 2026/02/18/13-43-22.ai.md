This is a bugfix for the `strbuf_reencode()` function in the strbuf subsystem. The patch corrects an off-by-one error in memory allocation tracking where the function was passing the string length rather than length+1 to `strbuf_attach()`, failing to account for the null byte.

The issue was identified by Vaidas Pilkauskas, with Junio Hamano providing additional analysis in review. While the incorrect alloc size didn't cause memory corruption (since `strbuf_attach()` internally calls `strbuf_grow()` which corrects the size), it did trigger unnecessary reallocations. The fix ensures the strbuf's alloc field accurately reflects the buffer size from the start.

Junio suggests this may indicate a broader issue with `strbuf_attach()`'s parameter validation and proposes adding a BUG() check to enforce that alloc must exceed len. Vaidas indicates plans to follow up with additional patches to clean up other call sites and add this validation.

The patch itself is straightforward - a one-line change to pass len+1 instead of len. This is part of a 3-patch series, with the other patches presumably addressing related strbuf_attach() improvements. The discussion shows careful attention to edge cases in memory management while maintaining the strbuf invariants.
