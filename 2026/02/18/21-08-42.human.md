This is a test modernization patch in an ongoing series about improving naming consistency and code organization in the `repo-info` subsystem. 

Patch 6/8 refactors a test in `t1901-repo-structure.sh` to simplify how it verifies output formats. The test checks both key-value and NUL-formatted output from `git repo structure`, which differ only in their separators. Rather than maintaining separate expected output files, the patch uses `tr` to transform the NUL output to match the key-value format, then compares against the same expected output. This makes the test more maintainable by eliminating duplicate expected output while still verifying both formats work correctly.

The change is mechanical and follows the series' pattern of small, focused improvements. It builds on prior work in the test infrastructure (patch 5 renamed test files) and maintains the thread's theme of consistency - here by unifying test verification logic. The approach is clean and the commit message clearly explains the motivation.
