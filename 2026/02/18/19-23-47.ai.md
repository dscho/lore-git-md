This is a technical fix in the commit-graph subsystem, part of Patrick Steinhardt's three-patch series optimizing shallow push performance. The second patch addresses a subtle edge case where commit-graph writing could segfault when accessing tree information from commits that were previously parsed via the commit-graph.

The core issue occurs when:
1. A commit is parsed via commit-graph (leaving `maybe_tree` unpopulated)
2. The commit-graph is closed (making the tree inaccessible)
3. The same process tries to write a new commit-graph and needs the tree

Justin Tobler's review confirms the technical approach - using `unparse_commit()` to force re-reading commits without the graph when needed. He raises a thoughtful question about whether `repo_get_commit_tree()` should handle this case directly, but acknowledges the current solution works. The patch introduces careful unparsing logic while maintaining performance, as these re-parses only happen during commit-graph writing.

This is a robust fix for a rare but serious edge case, completing the groundwork before the final patch can safely optimize `lookup_commit_reference_gently()` to use the commit-graph. The interaction between commit parsing, graph usage, and graph writing is subtle, and this patch demonstrates careful attention to the lifecycle of parsed commit objects.
