This is a bugfix series for the `contrib/subtree` component, specifically addressing issues with the subtree split operation's history handling. The series removes a problematic optimization that was incorrectly excluding commits from split history, following two previous attempts to fix the issue that introduced their own regressions.

The 3-patch series comes from Colin Stagner and represents a complete solution after review feedback. Patch 1 adds test infrastructure, Patch 2 expands test coverage with explicit commit count verification, and Patch 3 removes the `should_ignore_subtree_split_commit` optimization function entirely. The tests now verify history integrity by tracking split results across explicitly named branches and using `rev-list --count` for precise commit counting.

Maintainer D. Ben Knoble has reviewed the series with only minor formatting feedback remaining on trailer formatting, which the author plans to address in v2. The changes focus on `git-subtree.sh` and significantly expand test coverage in `t7900-subtree.sh` (+268 lines total). The series builds on prior work in commits 98ba49ccc2 (original optimization) and 83f9dad7d6 (previous fix attempt), and addresses issues originally reported by George and Christian Heusel.

The key technical change is removing the optimization that skipped processing commits from other subtrees, which violated API contracts around commit hashes. The new test coverage includes simple and complex cases (multiple/nested subtrees, rebased commits) and documents merge commit handling requirements. While the test coverage provides confidence, extremely complex histories may need additional verification.
