This is part 5/8 of Adrian Ratiu's series implementing config-based Git hooks. The patch adds the ability to disable configured hooks via a new `hook.<name>.enabled` setting, which defaults to true but can be set to false to temporarily disable a hook without removing its configuration.

The implementation introduces a string list to track disabled hooks during config parsing, skipping any hook commands marked as disabled when building the execution list. The patch includes comprehensive tests verifying that disabled hooks are not run, do not appear in `git hook list` output, and can be re-enabled at a more local config level when globally disabled.

This continues the series' pattern of careful, incremental development with thorough test coverage. The change addresses a real-world use case where users might want to temporarily disable system-wide hooks without modifying the global configuration files. The implementation builds cleanly on the infrastructure established in earlier patches while maintaining backward compatibility.
