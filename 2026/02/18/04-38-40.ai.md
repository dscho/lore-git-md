This is the third patch in Patrick Steinhardt's v3 series addressing test failures on Windows/MSVC platforms related to `iconv(1)` availability when Git's ICONV support is enabled. The patch focuses on t4205-log-pretty-formats.sh, which tests pretty-format output with various encodings.

The key change is making the test encoding conditional on the ICONV prerequisite: when ICONV is available, tests use ISO-8859-1 encoding as before, but fall back to UTF-8 when it's not. This fixes test setup failures on platforms without the `iconv(1)` executable while maintaining test coverage. The patch removes the ICONV prerequisite from many tests that don't actually need encoding conversion, only keeping it where `i18n.logOutputEncoding` is explicitly tested.

The changes follow the pattern established in earlier patches of the series, cleanly separating the concerns of libiconv (a runtime dependency) from the `iconv(1)` executable (a test tool). The commit message clearly explains the two classes of tests in t4205 and why some ICONV prerequisites were unnecessary. The diff shows 50 lines changed, mostly removing ICONV markers from tests that don't need them while preserving encoding-specific tests where appropriate.

This continues the series' consistent approach to handling platform differences in iconv availability, with each patch methodically updating test files to the new pattern. The changes are well-contained and maintain existing test coverage while improving portability.
