This is a feature patch series (v2) from Adrian Ratiu that implements config-based Git hooks, allowing hooks to be defined via Git configuration rather than just filesystem scripts. The series builds on previous work to support multiple hooks per event and adds:

1. A new `hook.<name>.command` config option to specify hook commands (executables or shell oneliners)
2. A new `hook.<name>.event` option to specify which events trigger the command
3. A `hook.<name>.enabled` toggle to disable hooks
4. A `git hook list` subcommand to inspect configured hooks
5. A config cache in `struct repository` to avoid re-parsing hook configs on each invocation (critical for performance with hooks like `reference-transaction`)

Key technical changes:
- Introduces a `struct hook` with typed fields replacing the previous string-based identification
- Adds a strmap cache in `struct repository` for hook configs
- Supports config value resets via `event = ""` syntax
- Adds NUL-delimited output mode to `git hook list -z
- Maintains backward compatibility with filesystem hooks (run last)

The series has been through multiple rounds of review with significant input from Patrick Steinhardt (performance analysis, caching design) and Junio Hamano (API design, typing). It shows careful attention to both implementation quality and practical performance needs, particularly around the high-frequency `reference-transaction` hook case.

This represents a major step forward in hook flexibility, enabling global hooks, easier sharing between repos, and programmatic hook management while maintaining the existing filesystem hook workflow. The caching design addresses real-world performance concerns raised during review.
