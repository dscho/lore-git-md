This is a feature addition to the `git replay` command, introducing a `--revert` capability primarily for GitLab's Gitaly service use case. The patch extends `git replay` to support reversing commits directly on bare repositories, now in its third iteration.

The implementation adds a new `--revert <branch>` mode that creates commits undoing changes from a specified range, similar to `git revert` but without requiring a working tree. The revert commits follow standard conventions with "Revert" prefixes and original commit hashes in messages, and use the current user as author. The technical approach swaps merge arguments to reverse the diff direction, reusing much of the existing merge infrastructure.

The patch has undergone thorough review from key contributors including Patrick Steinhardt, Elijah Newren, and Phillip Wood, with v3 incorporating feedback around test organization, memory management, and architectural consistency. It maintains clear separation from existing `--onto` and `--advance` modes while sharing common infrastructure where possible. The implementation appears well-considered with comprehensive test coverage for both basic functionality and edge cases like reverting reverts and bare repository operations.

This represents a significant enhancement to Git's server-side history rewriting capabilities, particularly useful for services like GitLab that need to manipulate repository history without working trees. The careful attention to interface design and backwards compatibility suggests it should integrate smoothly with existing workflows.
