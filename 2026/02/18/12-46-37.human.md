This is the first patch in a two-part bugfix series addressing security-related handling of symlinked `.git` directories. The patch refines error handling in `read_gitfile_gently()` to better distinguish between different types of filesystem errors.

The change introduces three specific error cases that were previously lumped together: missing files (ENOENT), directory paths (IS_A_DIR), and other stat failures. This allows the function to handle benign cases (like a missing file) without fatal errors while still catching actual problems like permission issues. The patch updates both the error reporting in `setup.c` and adds new error codes in `setup.h`.

This is part of a larger effort to make Git's symlink handling more precise while maintaining security boundaries. The next patch in the series will build on these error codes to implement the actual symlink policy changes. The changes appear well-contained and focused, with clear commit message explaining the motivation and implementation.
