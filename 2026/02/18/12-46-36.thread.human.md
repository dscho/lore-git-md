This thread presents a two-patch series from Tian Yuchen addressing Git's handling of symlinked `.git` directories. The current overly strict security policy rejects all symlinked `.git` directories, even when they point to valid directories. The series carefully relaxes this restriction while maintaining security against malicious repository setups.

The first patch (already reviewed) refined error handling in `setup.c`, introducing new error codes to distinguish between different failure modes when checking `.git`. The second patch, now under discussion, implements the actual symlink handling changes - allowing `.git` to be a symlink when it points to a directory, while still rejecting dangerous cases like FIFOs and invalid gitfiles. Both patches include comprehensive tests in a new `t0009-git-dir-validation.sh` file that verify the security boundaries remain intact.

Junio Hamano and Karthik Nayak have reviewed prior versions, and their feedback has been incorporated into this sixth version. The current iteration appears to address all previous concerns, with no outstanding objections raised. The changes are focused and well-tested, carefully balancing usability improvements against security requirements. The series looks ready for final approval pending any last security review considerations.
