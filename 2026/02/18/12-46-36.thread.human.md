This thread began with Tian Yuchen's patch series (v9) improving error diagnostics for `.git` directory validation while maintaining security boundaries. After nine iterations and thorough review from Junio Hamano and Karthik Nayak, the series was merged with refinements focused on clearer error reporting rather than the initial symlink support motivation. The changes introduced new error codes (`READ_GITFILE_ERR_STAT_ENOENT`, `READ_GITFILE_ERR_IS_A_DIR`, `READ_GITFILE_ERR_STAT_FAILED`) and improved `setup_git_directory_gently_1()`'s handling while maintaining all security protections.

Now that the series is merged, Junio has followed up with an observation about potential ripple effects in other parts of the codebase. He notes that while the main changes are sound, some callers (particularly in `submodule.c`) may still rely on the old error code semantics. Specifically, submodule handling currently interprets `READ_GITFILE_ERR_STAT_FAILED` to mean an unpopulated submodule, but with the new changes, it should likely check for `READ_GITFILE_ERR_STAT_ENOENT` instead. This isn't urgent - the core functionality works as intended - but Junio suggests auditing all uses of these error codes for consistency, particularly in submodule and worktree code paths. The thread demonstrates how even after careful review and merging, maintainers continue to identify subtle integration points that may need follow-up attention.
