Bugfix for `git apply --directory` path handling. This second version from Joaquim Rocha addresses the issue where paths starting with `./` would cause `git apply` to fail, while also expanding the solution to handle other path normalization cases like double slashes (`some//sub`), mid-path `./` segments, and `../` traversal (while rejecting leading `../` for security).

The patch now uses Git's existing `strbuf_normalize_path()` function to handle all these cases in one go, rather than just stripping `./` prefixes as in v1. This responds to Patrick Steinhardt's suggestion in the thread, though Junio C Hamano had expressed some skepticism about whether such comprehensive normalization was necessary. The implementation adds several test cases to verify the behavior with different path formats.

The change is small (4 lines in `apply.c`) but touches a potentially sensitive area of path handling. The tests provide good coverage of edge cases, including verifying the error message when invalid paths are provided. This looks like a well-considered iteration that addresses the original bug while making the behavior more robust.
