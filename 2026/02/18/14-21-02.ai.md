This is part of the ongoing ref backend abstraction effort, specifically focusing on stub management for reference directories. The patch moves stub creation/deletion logic from backend-specific code to the generic refs layer, with special handling for the files backend which has different requirements.

The change enables future work with alternate reference directories while maintaining backward compatibility. Toon Claes provides review feedback, agreeing with Karthik Nayak's approach to keep stub creation logic in the generic layer while preserving files backend behavior. They discuss some nuances around worktree handling and HEAD creation timing that justify keeping the files backend's special treatment.

Key technical points:
- `refs_create_refdir_stubs()` is now called from the generic `ref_store_create_on_disk()`
- Files backend remains exempt from this generic handling due to its different requirements for worktree refs and lazy HEAD creation
- The patch maintains symmetry in condition formatting as suggested by Patrick Steinhardt
- Follow-up work will extend this to support alternate reference directories

The discussion shows consensus on the approach, with only minor formatting and ordering adjustments needed before this can proceed. This represents another step in the larger goal of making reference storage backends pluggable and configurable.
