Refactoring patch in the remote-curl HTTP error handling code. This is the fourth in a five-part series that started with strbuf fixes and has moved into HTTP protocol improvements.

Vaidas Pilkauskas introduces a new helper function `show_http_message_fatal()` that combines the common pattern of displaying HTTP error messages followed by terminating with `die()`. The patch refactors several error cases in remote-curl.c to use this helper, reducing code duplication. The changes are straightforward - each case now calls the helper rather than manually calling `show_http_message()` and `die()` separately.

The helper function handles three key tasks: displaying text/plain error messages from the server (with proper encoding conversion), cleaning up allocated resources, and terminating the program with the provided error message. Taylor Blau suggested this refactoring, which also sets up infrastructure for upcoming HTTP 429 rate limiting support.

This appears to be a clean, focused improvement to error handling in the HTTP transport code. The changes are mechanical but meaningful, and the patch follows Git's coding style well. Since this is part of a larger series, we can expect one more patch to follow.
