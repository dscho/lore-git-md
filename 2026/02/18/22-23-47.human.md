This is the third patch in Adrian Ratiu's v2 series implementing config-based Git hooks. It introduces a new `git hook list` subcommand to inspect which hooks would run for a given event, building on the hook listing infrastructure added in the previous patch.

The new subcommand currently only shows traditional filesystem hooks (from `.git/hooks/`), but the implementation is designed to later include config-based hooks that will be added in subsequent patches. The command warns and exits with status 1 if no hooks are found for the given event name.

The patch includes basic usage tests verifying:
- The command's help text and error handling
- Behavior when no hooks exist
- Output format for traditional hooks

This is a straightforward addition that provides visibility into the hook system's state, which will become more important as the series adds config-based hooks. The implementation follows Git's typical subcommand structure and includes appropriate documentation updates. The patch maintains Emily Shaffer's original sign-off while being rebased onto the current series.
