Feature patch adding HTTP 429 rate limit retry support. This is the final patch in a series that introduces graceful handling of HTTP 429 "Too Many Requests" responses from servers.

The patch adds three new configuration options to control retry behavior when rate limited:
- `http.maxRetries` (default 0) - maximum retry attempts
- `http.retryAfter` (default 0) - default wait time when no header is provided
- `http.maxRetryTime` (default 300s) - maximum allowed delay before failing

The implementation supports RFC-compliant Retry-After headers in both delay-seconds and HTTP-date formats. It takes a fail-fast approach - if any delay exceeds maxRetryTime, Git fails immediately with a clear error rather than capping the delay. The change includes extensive test coverage for various header formats, configuration combinations, and edge cases.

The patch appears well-constructed with thorough test coverage and clear documentation. It builds on earlier refactoring in the series (like the `show_http_message_fatal()` helper) and handles both modern curl versions (using CURLINFO_RETRY_AFTER) and older ones (with custom parsing). The implementation respects environment variable overrides for all three config options.

This completes the HTTP rate limiting feature set, providing Git users with configurable retry behavior when interacting with rate-limited HTTP servers. The extensive test suite suggests this is production-ready code that has been carefully validated.
