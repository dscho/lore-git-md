This is a feature addition to the `git replay` command, introducing `--revert` capability as part of a v3 patch series. The patch adds server-side revert functionality for bare repositories, primarily targeting GitLab's Gitaly service use case.

The implementation treats reverts as merges with swapped arguments (base=commit, ours=current, theirs=parent) to reverse the diff direction. It creates new commits that undo changes from the revision range, with commit messages following `git revert` conventions ("Revert" prefix and "This reverts commit <hash>"). The author is set to the current user rather than preserving the original author, matching `git revert` behavior.

Key technical changes include:
- New `REPLAY_MODE_REVERT` enum and mode handling
- Shared `sequencer_format_revert_header()` helper for message generation
- Swapped tree arguments in merge operation for revert vs pick
- Consolidated ref update logic between modes
- Comprehensive test coverage including bare repo cases and conflict handling

The patch builds on prior discussion with Elijah Newren, Phillip Wood, and others, establishing that revert is a distinct operation mode (not combinable with `--onto` or `--advance`). It handles edge cases like reverting reverts (using "Reapply" prefix) and maintains consistency with existing replay behavior while adding the new functionality.

The implementation is thorough, with attention to code quality concerns raised in prior reviews (enum naming, memory management, test organization). The changes touch builtin/replay.c, replay.{c,h}, sequencer.{c,h}, documentation, and test scripts, with careful consideration given to maintainability and architectural consistency.
