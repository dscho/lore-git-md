This thread has thoroughly documented and resolved a long-standing gap in Git's fetch behavior documentation. The discussion established that when `git fetch --jobs=0` or `fetch.parallel=0` are set, Git has consistently used the available CPU count (`online_cpus()`) as the fallback value since 2019's d54dea77dba commit. While this behavior was noted in Git 2.40.0's release notes, it was missing from the main documentation until now.

Johannes Schindelin's historical investigation confirmed there was no hidden rationale for the documentation omission - it appears to have been an oversight rather than a deliberate choice. The thread saw productive contributions from multiple core developers: Patrick Steinhardt helped expand the scope to cover both CLI and config cases while investigating the implementation history, and Junio C Hamano suggested that future versions might benefit from renaming the option to something like `--jobs=auto` for clearer intent.

With all historical questions resolved and consensus reached, this straightforward documentation update is ready for merging. The patches modify both fetch-options.adoc and config.txt to accurately reflect the long-standing behavior. While the immediate issue is closed, the discussion has planted seeds for potential future interface improvements regarding option naming clarity.
