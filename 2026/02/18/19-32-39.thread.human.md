This thread has been working to clarify the documentation around `git fetch --jobs=0` and `fetch.parallel=0` behavior. The implementation since 2023 has used the available CPU count (`online_cpus()`) as the fallback when these values are set to 0, but this wasn't clearly documented. 

The original patch proposed documenting this behavior, which Patrick Steinhardt expanded to cover both the command-line and configuration cases. Junio C Hamano accepted the change while noting the original vague documentation might have been deliberate and suggesting `--jobs=auto` could be a clearer name for future consideration. 

In the latest email, Patrick follows up on Junio's comment, checking with Johannes Schindelin whether there was specific historical reason for not documenting the fallback behavior. The technical consensus remains unchanged - both options will now explicitly document their fallback to `online_cpus()` in fetch-options.adoc and config.txt. 

This appears to be the final discussion point before finalizing the documentation updates, with Patrick ensuring there are no unrecorded reasons against being more specific. The thread demonstrates Git's careful approach to documentation - even straightforward clarifications undergo thorough review to understand historical context before changing.
