[PATCH 0/5] Remove `the_repository` from merge-ort and replay
Author: Elijah Newren
Thread type: Patch series (v2)
Subsystems: merge-ort, replay, promisor-remote, diff
Related effort: `the_repository` removal (ongoing project)

This series systematically eliminates direct uses of `the_repository` global variable and `the_hash_algo` from merge-ort.c and replay.c, replacing them with repository-specific parameters available via `opt->repo`. The v2 iteration adds a new first patch addressing prefetch checks and incorporates all feedback from the v1 review, with one remaining issue identified by Patrick Steinhardt where `the_repository` is still passed to `repo_has_promisor_remote()` rather than using `options->repo`. Elijah Newren has acknowledged this as a bug and committed to fixing it in the next version.

Patch 1 removes obsolete `the_repository` checks from `prefetch_for_content_merges()` in merge-ort.c and corresponding logic in diff.c, diffcore-break.c, and diffcore-rename.c. While it correctly eliminates unnecessary checks from 2021 promisor-remote changes (commit ef830cc434), Patrick Steinhardt noted the prefetch logic should fully respect repository context by using `options->repo` with `repo_has_promisor_remote()`. Elijah agrees this is necessary to maintain consistent repository handling and will update the call sites to properly propagate the repository context.

Patches 2-5 remain unchanged from previous summary, converting repository access throughout merge-ort.c to use `opt->repo` instead of `the_repository` for tree parsing, blob operations, merge base calculations, configuration handling, and hash algorithm access. These changes have been reviewed positively by Patrick Steinhardt as "welcome cleanup" with no substantive concerns.

Patch 6 introduces compile-time enforcement against `the_repository` usage in merge-ort.c and replay.c via `DO_NOT_USE_THE_REPOSITORY` macro, with all temporary exceptions now removed except for `DEFAULT_ABBREV` which still needs `USE_THE_REPOSITORY_VARIABLE`. The enforcement mechanism follows established patterns from other subsystems.

The series demonstrates responsiveness to review feedback through:
1. Acknowledgment and planned fix for repository context issue in prefetch logic
2. Macro casing fixes
3. Added explanatory comments
4. Maintained tight focus on merge-ort and replay subsystems
5. Final compile-time enforcement

Elijah's merge-ort expertise ensures the changes are technically sound. With Patrick Steinhardt's identified prefetch issue being addressed and all other review feedback incorporated, the series is nearing readiness for merging as part of the broader `the_repository` removal project.
