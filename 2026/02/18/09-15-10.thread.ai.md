[PATCH 0/5] Remove `the_repository` from merge-ort and replay
Author: Elijah Newren
Thread type: Patch series (v3)
Subsystems: merge-ort, replay, promisor-remote, diff
Related effort: `the_repository` removal (ongoing project)

This series systematically eliminates direct uses of `the_repository` global variable and `the_hash_algo` from merge-ort.c and replay.c, replacing them with repository-specific parameters via `opt->repo`. The v3 iteration completes the conversion by addressing Patrick Steinhardt's v2 feedback regarding repository context propagation in prefetch logic, ensuring `repo_has_promisor_remote()` uses `opt->repo` rather than falling back to `the_repository`.

Patch 1 removes obsolete `the_repository` checks from prefetch logic across four files (merge-ort.c, diff.c, diffcore-break.c, diffcore-rename.c). Patch 2 modifies `write_tree()` in merge-ort.c to take a `struct repository*` parameter. Patch 3 replaces all remaining direct uses of `the_repository` in merge-ort.c with repository-specific parameters from `opt->repo`, covering tree parsing, blob operations, merge base calculations, and configuration handling. Patch 4 updates 13 instances where null object IDs were being created using the global hash algorithm, replacing them with explicit `opt->repo->hash_algo` access for submodule handling, content merging, directory rename tracking, and conflict resolution.

The final patch (5/5) enforces compile-time prevention of future `the_repository` usage in merge-ort.c via `DO_NOT_USE_THE_REPOSITORY` macro, with the sole exception of `DEFAULT_ABBREV` which still uses `USE_THE_REPOSITORY_VARIABLE`. This completes the series' goal of eliminating implicit repository dependencies from merge-ort and replay, with all operations now properly scoped to the repository context via `opt->repo`. Patrick Steinhardt has reviewed and approved the approach in previous iterations, with no outstanding concerns remaining. As the maintainer of merge-ort, Elijah's authoritative handling ensures the changes maintain correct behavior while advancing the broader `the_repository` removal effort. The series is now complete and ready for merging.
