[PATCH 0/5] Remove `the_repository` from merge-ort and replay
Author: Elijah Newren
Thread type: Patch series (v2)
Subsystems: merge-ort, replay, promisor-remote, diff
Related effort: `the_repository` removal (ongoing project)

This series systematically eliminates direct uses of `the_repository` global variable and `the_hash_algo` from merge-ort.c and replay.c, replacing them with repository-specific parameters available via `opt->repo`. The v2 iteration adds a new first patch addressing prefetch checks and incorporates all feedback from the v1 review, though Patrick Steinhardt has identified one remaining inconsistency in patch 1 where `the_repository` is still passed to `repo_has_promisor_remote()` rather than using `options->repo`.

Patch 1 removes obsolete `the_repository` checks from `prefetch_for_content_merges()` in merge-ort.c and corresponding logic in diff.c, diffcore-break.c, and diffcore-rename.c. While it correctly eliminates unnecessary checks from 2021 promisor-remote changes (commit ef830cc434), Patrick Steinhardt notes the prefetch logic should fully respect repository context by using `options->repo` with `repo_has_promisor_remote()` rather than mixing repository contexts via `the_repository`. This suggests one additional change may be needed to maintain consistent repository handling.

Patch 2 converts repository access in `collect_merge_info()`, `merge_3way()`, `handle_content_merge()` and related merge-ort.c functions to use `opt->repo` instead of `the_repository`. Updates include tree parsing, blob operations, merge base calculations, and configuration handling. The prefetch check for promisor remotes is properly contextualized. Patrick Steinhardt reviewed this as "welcome cleanup" with no substantive concerns.

Patch 3 replaces all remaining `the_hash_algo` usage in merge-ort.c with direct access via `opt->repo->hash_algo`. The mechanical changes update null object ID initialization and comparisons across key functions: `merge_submodule`, `handle_content_merge`, `process_renames`, and `process_entry`. This builds on earlier infrastructure work threading the repository parameter through merge-ort. Patrick Steinhardt's v1 review approved the approach.

Patches 4-5 convert `write_tree()` and other functions in merge-ort.c to take explicit `struct repository *` parameters, replacing `the_repository` and `the_hash_algo` with `opt->repo` equivalents. The `write_tree()` conversion removes redundant hash algorithm size passing since the function can now look it up directly from the repository parameter. All call sites are updated to pass the repository pointer through from `opt->repo`. The commit message improvements suggested by Patrick Steinhardt (documenting hash-algo changes) and Kristoffer Haugsbakk (macro casing consistency) have been incorporated.

Patch 6 introduces compile-time enforcement against `the_repository` usage in merge-ort.c and replay.c via `DO_NOT_USE_THE_REPOSITORY` macro, with Patrick Steinhardt's requested explanatory comments added. The temporary exceptions for `prefetch_for_content_merges()` are now unnecessary and removed. One unavoidable exception remains for `DEFAULT_ABBREV` which still requires `USE_THE_REPOSITORY_VARIABLE`. The enforcement mechanism follows established pattern seen in other subsystems that have completed their `the_repository` removal.

All changes remain mechanical, behavior-preserving replacements that maintain correct merge-ort functionality while advancing the subsystem's alignment with the project's parameterization goals. The series demonstrates responsiveness to review feedback through:
1. Proactive prefetch check cleanup
2. Macro casing fixes
3. Added explanatory comments
4. Maintained tight focus on merge-ort and replay subsystems
5. Final compile-time enforcement

Elijah's merge-ort expertise ensures the changes are technically sound. Patrick Steinhardt's latest observation about repository context consistency in patch 1 suggests one remaining refinement may be needed, but the core approach remains valid. With all other review feedback incorporated, the prefetch checks properly removed, and compile-time enforcement added, the series appears nearly ready for merging as part of the broader `the_repository` removal project. Patrick Steinhardt's positive review of both the hash-algo conversion and compile-time enforcement suggests no other outstanding technical concerns beyond the noted repository context issue. The series follows established patterns for global variable elimination and represents a complete subsystem conversion when the final prefetch adjustment is made.
