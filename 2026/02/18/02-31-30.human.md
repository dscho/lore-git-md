This is the first patch in a 3-part bugfix series for `contrib/subtree`, specifically addressing issues with the subtree split operation's history handling. The series removes a problematic optimization that was incorrectly excluding commits from split history.

Patch 1/3 adds comprehensive test coverage for the subtree split functionality, converting a real-world example that exposed the bug into formal test cases. The new cases verify:
- How `--ignore-joins` handles subtree adds
- Correct processing of commits before/after rejoins
- Proper preservation of merges with unrelated histories

The tests use precise commit counting via `rev-list --count` and explicit branch comparisons to validate history integrity. This establishes a safety net for the subsequent patches that will remove the faulty optimization.
