This is the second patch in a four-part series implementing UTF-8 support for Git configuration subsections, specifically focused on alias definitions like `[alias "förgrena"]`. The series has gone through six iterations with all technical issues resolved, including final fixes for zsh completion.

The current patch prepares the ground for subsection aliases by switching from `skip_prefix()` to `parse_config_key()` for alias parsing in `help.c`. This properly handles the config key structure and paves the way for the new subsection syntax in the next commit. The change introduces a compatibility break: previously, dotted alias names (like "alias.foo.bar") were accepted as defining an alias "foo.bar", but now such entries will be silently ignored unless the final component is "command" (The next patch will give meaning to "alias.<subsection>.command".)

The implementation is clean and focused - just 10 lines changed in `help.c` to use the more robust parsing function while maintaining the same basic behavior for simple aliases. The commit message clearly explains both the technical change and its implications, noting that the old dotted-name behavior was arguably a bug since it was never documented or intentionally supported.

This patch follows the first one in the series (which consolidated alias listing logic) and precedes the main implementation of subsection support. With all review feedback addressed across the six iterations and maintainer approval from Junio Hamano, the series appears ready for merging.
