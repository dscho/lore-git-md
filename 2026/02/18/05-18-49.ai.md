This is the first of two security hardening patches in Tian Yuchen's v5 series that improves Git's repository discovery safety by validating `.git` file types. The patch refactors error handling in `read_gitfile_gently()` to distinguish between different types of `stat()` failures, a prerequisite for the security checks in the follow-up patch.

The key changes introduce two new error codes in `setup.h` (`READ_GITFILE_ERR_STAT_ENOENT` and `ENOENT` cases) and restructures `read_gitfile_error_die()` to handle them appropriately. Missing files (`ENOENT`) and directories are now non-fatal (allowing Git to continue searching parent directories), while other stat failures and non-regular files trigger fatal errors. The implementation uses `stat()` rather than `lstat()` to maintain support for legitimate symlinks to directories.

This preparatory patch has already addressed Junio Hamano's feedback from earlier versions, particularly around the error handling taxonomy. The changes are focused entirely on `setup.c` and `setup.h`, with no behavioral changes yet - those come in patch 2/2 which implements the actual security checks. The series appears well-structured with clear commit separation as requested by the maintainer.
