This is patch 3/5 in Justin Tobler's series adding repository statistics to `git repo`, focusing on technical refinements to the table output format. The patch adds OID annotations to identify the largest objects of each type, with numbered references linking table entries to their corresponding object IDs shown at the bottom.

Key technical changes:
- Implements `stats_table_object_size_addf()` to handle OID annotations when reporting maximum object sizes
- Uses `string_list_append()` to track annotations, with Patrick Steinhardt suggesting a `strbuf_detach()` optimization that Justin agrees to implement
- Handles NULL OIDs for empty object types (like in an empty repository)
- Updates test expectations to show the new annotation format with numbered references ([1], [2], etc.) and corresponding OIDs

The discussion reveals design decisions:
- Rejected more descriptive labels (like "[commits]") due to column width concerns, especially as future patches will add more annotation types
- Maintained numeric references as the simplest solution when multiple annotations per object type may exist (e.g., max size and max parents being different commits)
- Confirmed empty repository edge case handling

This patch shows the series maturing through review feedback, with Justin incorporating Patrick's suggestions while maintaining consistency with planned future additions. The technical implementation remains focused on the immediate need while leaving room for the additional statistics coming in later patches.
