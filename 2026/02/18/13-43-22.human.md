This is a bugfix for the `strbuf_reencode()` function in the strbuf subsystem. Vaidas Pilkauskas identifies and fixes an off-by-one error where the function was passing an incorrect allocation size to `strbuf_attach()`. While the original commit message overstated the potential memory management issues, Junio Hamano confirms the fix is worthwhile as it prevents unnecessary reallocations when the strbuf isn't extended further.

The discussion reveals a deeper issue with `strbuf_attach()`'s parameter validation - it currently relies on `strbuf_grow()` to paper over incorrect alloc/len relationships. Junio suggests adding a BUG()` check to enforce the contract that alloc must be larger than len, and Vaidas plans follow-up patches to clean up other call sites and add this validation.

The patch itself is straightforward - a one-line change to pass `len + 1` instead of `len` as the alloc parameter. This is part of a 3-patch series, with the remaining patches likely addressing the broader `strbuf_attach()` validation issues mentioned in the discussion.
