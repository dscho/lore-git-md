This is part 7/8 of Adrian Ratiu's series implementing config-based Git hooks, building on the infrastructure established in previous patches. The key change here is enabling `git hook` commands to work outside a Git repository when hooks are defined in global/system configs.

The patch modifies the hook subsystem to handle repository-less cases by:
1. Changing `git hook` to use `RUN_SETUP_GENTLY` instead of `RUN_SETUP`, allowing it to proceed without a repository
2. Making `find_hook()` return NULL when no repository is present (skipping filesystem hooks)
3. Adding temporary config cache handling for out-of-repo operations that gets cleaned up after use
4. Updating tests to verify global hooks work in nongit contexts while filesystem hooks remain repo-bound

The implementation maintains the existing behavior where filesystem hooks require a repository (since they need a `.git/hooks` directory), while config-based hooks can now run anywhere Git configs apply. This enables use cases like running `sendemail-validate` hooks from non-repository directories.

The changes are focused and well-contained, touching only the necessary parts of hook.[ch] while expanding test coverage. The patch carries Emily Shaffer's original sign-off, indicating this was part of her initial vision for config-based hooks that Adrian is now implementing.
