Hook infrastructure patch adding config-based hook support.

This is the 4th patch in Adrian Ratiu's 8-part series implementing config-based Git hooks. It builds on the infrastructure from earlier patches to now parse and execute hooks defined in Git config via `hook.<name>.command` and `hook.<name>.event` settings.

The key additions in this patch:
- New config parsing that collects all hook.* settings in one pass
- A strmap cache in struct repository to avoid re-reading config
- Support for multiple commands per hook event, executed in config order
- Documentation explaining the new config syntax and execution model
- Tests verifying config ordering, multi-event hooks, and stdin handling

The implementation maintains backward compatibility by still running traditional filesystem hooks last. The config format allows hooks to be shared across repositories and associated with multiple events. Performance is addressed via the config cache, though parallel execution is left for a future patch.

This represents a major step toward the series' goal of making hooks more flexible while preserving existing behavior. The patch is well-structured with thorough documentation and test coverage. Reviewers will likely focus on the config parsing approach and cache implementation details.
