This is a refactoring patch that extracts revert message formatting logic into a shared helper function, part of the `git replay --revert` feature effort. The patch moves the logic for generating "Revert" and "Reapply" commit messages from `do_pick_commit()` in sequencer.c into a new `sequencer_format_revert_header()` function in sequencer.h. This prepares for reuse by the upcoming `--revert` mode in `git replay`.

Key technical details:
- The new helper handles both regular reverts (prepending "Revert") and reverts-of-reverts (changing to "Reapply")
- It optionally appends the full commit hash when an OID is provided
- The implementation preserves the existing behavior of not nesting revert messages beyond one level
- The change maintains compatibility with `commit_use_reference` mode which generates different message formats

The patch shows clean separation of concerns and follows the project's pattern of factoring out reusable components. It's a straightforward extraction with no behavior changes, just moving code to eliminate duplication before the `git replay` series needs to use the same logic. The function signature and behavior are well-documented in the header file.
