This is the second patch in a 4-part series implementing UTF-8 support for Git configuration subsections, specifically for aliases. The series has gone through seven iterations with input from multiple reviewers including Jeff King and Junio Hamano.

The patch refactors the alias parsing logic in `help.c` to use `parse_config_key()` instead of `skip_prefix()`, properly handling the three-level config key structure needed for upcoming UTF-8 subsection support. This change makes the parser stricter - it will now silently ignore malformed "alias.subsection.key" entries unless the key is "command" (which will be used in the next patch). The commit message notes this is technically a compatibility break, but argues the old behavior was effectively a bug since dotted aliases were never intentionally supported.

The implementation touches just one file (`help.c`) with a small, focused change that replaces the simple prefix check with proper config key parsing. Reviewers have approved the approach through multiple iterations, and this version includes all requested changes including proper documentation of the compatibility implications. The patch is now in its final form and ready for merging as part of the complete UTF-8 alias support feature.
