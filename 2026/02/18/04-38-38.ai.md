This is a test infrastructure patch that fixes CI failures on Windows/MSVC platforms where tests were incorrectly assuming the `iconv(1)` executable would be available whenever Git was built with ICONV support. The patch is the first in a 5-part series from Patrick Steinhardt addressing this mismatch between libiconv (linked into Git) and the `iconv(1)` executable (used in test scripts).

The key change moves the ICONV prerequisite check in `t/test-lib.sh` from a simple build-time check (`NO_ICONV`) to a lazy prerequisite that also verifies the `iconv(1)` executable exists and works. This ensures tests will be skipped when either the library or executable is missing. The patch includes a NEEDSWORK comment suggesting this could eventually be split into two separate prerequisites for finer-grained control.

The motivation comes from Git for Windows no longer shipping the `iconv(1)` executable (issue #6083), which broke MSVC CI jobs. While that packaging issue will be fixed, this change makes the test suite more robust by properly distinguishing between Git's internal iconv support and the external tool. Subsequent patches in the series will update individual tests to respect this new behavior.

The patch is well-motivated and addresses a real testing gap, with all review feedback from previous versions incorporated. It maintains backward compatibility while fixing the Windows-specific issue and improving test reliability. The NEEDSWORK note provides a clear path for future refinement of the prerequisite system.
