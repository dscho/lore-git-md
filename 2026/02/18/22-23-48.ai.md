This is part 4/8 of Adrian Ratiu's series implementing config-based Git hooks, building on the infrastructure introduced in parts 2/8 and 3/8. The patch adds support for defining hooks via Git configuration (hook.<name>.command and hook.<name>.event) while maintaining backward compatibility with traditional filesystem hooks.

The implementation introduces a strmap cache in struct repository to store parsed hook configurations, avoiding repeated config parsing. Hooks are executed in config order, with traditional filesystem hooks running last. The patch includes comprehensive documentation explaining the new configuration syntax and execution order, plus tests verifying the behavior.

Key technical details:
- New hook.[hc] functions to parse and cache hook configurations
- Repository-level strmap cache for hook configurations
- Support for multi-event hooks (same command triggered by different events)
- Shell execution of configured commands (enabling one-liners)
- Validation requiring both .command and .event for configured hooks
- 149 lines of new test coverage in t/t1800-hook.sh

The patch maintains Emily Shaffer's sign-off from earlier iterations while adding Adrian's own. It represents a significant step toward the series' goal of making hooks more flexible and shareable across repositories while preserving the existing filesystem hook compatibility.
