This is part 2/8 of Adrian Ratiu's v2 series implementing config-based Git hooks. The patch refactors the hook execution infrastructure to support running multiple hooks per event, laying groundwork for the config-based hooks that will be added in later patches.

The key change is replacing the single-hook-path model with a list-based approach. A new `struct hook` represents each hook command (currently only traditional filesystem hooks, but config hooks will be added later). The `run_hooks_opt()` function now builds and manages a list of hooks to execute, while maintaining backward compatibility with the existing single-hook behavior.

Notable technical details:
- Introduces `hook_clear()` and `hook_list_clear()` for memory management
- Adds `list_hooks()` to collect hooks from all sources (currently just filesystem)
- Moves per-hook state into the new `struct hook` rather than `run_hooks_opt`
- Maintains the same execution order and behavior for existing hooks

The patch is well-structured with clear commit message and thorough documentation of the new data structures. It's part of a larger effort that has already incorporated feedback from Patrick Steinhardt and Junio Hamano on performance and API design. While this particular patch doesn't introduce user-visible changes, it's a necessary foundation for the config-based hooks coming next in the series.
