This is part 2/8 of Adrian Ratiu's v2 series implementing config-based Git hooks, building on Emily Shaffer's earlier work. The patch refactors the hook execution infrastructure to support multiple hooks per event while maintaining backward compatibility with traditional filesystem hooks.

The key changes introduce:
- A new `struct hook` to represent individual hook commands, currently supporting only traditional filesystem hooks (with config-based hooks to come in later patches)
- A `list_hooks()` function that builds an ordered list of hooks to execute, currently just finding the single filesystem hook
- Memory management helpers (`hook_clear()`, `hook_list_clear()`) to handle the new data structures
- Updated `run_hooks_opt()` to process the hook list instead of a single hook path
- Per-hook state allocation via the new `feed_pipe_cb_data` field in `struct hook`

The changes are preparatory - there's no user-visible behavior change yet since only traditional hooks directory hooks are supported. However, the infrastructure now supports:
- Future addition of config-based hooks (coming in later patches)
- Parallel hook execution (planned for a follow-up series)
- Proper cleanup of allocated resources through the new memory management callbacks

The patch maintains all existing hook functionality while laying groundwork for the more flexible hook system described in the series' cover letter. It touches core hook execution code in hook.[ch] but doesn't yet modify any hook callers.
