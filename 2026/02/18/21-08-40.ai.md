This is the fourth patch in an 8-part refactoring series focused on naming consistency in the `repo-info` subsystem. The patch renames the `struct field` to `struct repo_info_field` throughout `builtin/repo.c`, making the type's purpose more explicit as an internal data structure for `git-repo-info`.

The changes are mechanical and consistent with the series' pattern of improving code organization through systematic naming conventions. All references to the struct type and its instances are updated, including:
- The struct declaration itself
- The static array of fields
- The comparison function parameters
- The bsearch helper function
- All field access points in the printing functions

The patch follows logically from the previous changes in the series (which established singular naming conventions and renamed the array variable) and maintains the same careful, incremental approach. No behavior changes are introduced - this is purely a code organization improvement that makes the relationship between these components more obvious to readers.
