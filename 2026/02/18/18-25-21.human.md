Security hardening patch series (v5) addressing repository discovery vulnerabilities, now in review with Junio Hamano.

This is the second patch in a two-part series that tightens Git's handling of `.git` directory discovery, specifically addressing cases where `.git` could be a malicious FIFO or socket. The patch focuses on allowing legitimate symlinks to directories while rejecting dangerous file types.

Junio's review identifies two key concerns with the current implementation:
1. The error handling appears to unconditionally call `read_gitfile_error_die()` without respecting the `die_on_error` parameter from callers
2. The `is_git_directory()` check may be running in cases where it shouldn't, diverging from the original intent to only check when we know we have a directory

The thread shows the author (Tian Yuchen) and reviewers working through subtle edge cases in the control flow, particularly around when to die versus return errors to callers. Junio emphasizes preserving the original code's intent while adding the new security checks. The discussion is highly technical, focusing on the precise behavior when encountering different `.git` file types during repository discovery.

This patch series represents important security hardening that will likely land once these final edge cases are resolved. The changes touch core repository setup code in `setup.c`, so careful review is warranted. The thorough test coverage in `t0009-git-dir-validation.sh` gives confidence in the correctness of the approach.
