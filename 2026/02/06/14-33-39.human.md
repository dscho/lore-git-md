This is part of the ongoing ref storage backend abstraction effort, specifically addressing how reference storage locations are specified and handled for both main and worktree references. The patch focuses on parsing and utilizing the reference storage payload that was introduced in a previous commit to enable backend-specific reference locations.

The key changes include:
1) Extending the `extensions.refStorage` documentation to clarify URI format vs simple backend name specification
2) Modifying worktree reference storage to use alternate reference directories when configured, while maintaining stub directories for compatibility
3) Refactoring the files backend initialization to properly handle payload-specified reference locations
4) Adding a new `refs_compute_filesystem_location()` helper to centralize path resolution logic

Patrick Steinhardt's review points out several minor improvements needed:
- Documentation should use "payload" rather than "location" for consistency
- Some comments could be tightened up now that stub creation is handled by a helper function
- The commit message should explain why worktree handling isn't fully abstracted yet
- Memory handling in the files backend could be optimized further

This patch represents a significant step in enabling zero-downtime migrations between ref backends (files<->reftable) by properly handling reference location specification. The changes are well-motivated and carefully considered, with only minor documentation and implementation nits remaining to address.
