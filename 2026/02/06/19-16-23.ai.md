This is the second patch in a two-part series adding sparse-index support to the `merge-ours` strategy, part of the ongoing sparse-checkout/sparse-index optimization effort. The patch follows the first one which removed `the_repository` global usage.

The change enables `git merge-ours` to work efficiently with sparse-index by initializing repository configuration (via `repo_config()`) and explicitly marking the command as sparse-index compatible (`command_requires_full_index = 0`). Without this, the command would unnecessarily expand the full index before comparing it with HEAD. The patch includes new tests in t1092 that verify identical behavior between full and sparse modes while confirming no index expansion occurs.

The implementation follows established patterns from prior sparse-index integrations in other commands like `git merge` and `git rebase`. It builds on work by Derrick Stolee and Elijah Newren on sparse-index optimizations, while also aligning with René Scharfe's `the_repository` removal effort. The v2 iteration addresses all maintainer feedback from Junio C Hamano and Patrick Steinhardt, particularly around commit message clarity and safety guarantees of the repository parameter usage.

Key technical details include modifications to `builtin/merge-ours.c` for configuration handling and sparse-index enablement, plus 14 lines of new test coverage in t1092. The changes are minimal (6 lines of code) but complete the sparse-index integration started in the first patch. With all feedback addressed and tests passing, this appears ready for inclusion in the next integration cycle.
