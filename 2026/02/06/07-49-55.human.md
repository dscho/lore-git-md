This is a bugfix series addressing issues with exact refname matching in bitmap and bisect functionality. Patrick Steinhardt's third iteration consolidates fixes for two cases where `refs_for_each_ref_in()` was misused, causing Git to hit a BUG() when processing exact branch names.

The series now aligns with recent changes to ref exclusion patterns (10e8a9352b) by using hierarchy matching (with trailing slashes) rather than prefix matching for `pack.preferBitmapTips`. This resolves the key design question from earlier iterations, settling on glob-style pattern matching for consistency with `git for-each-ref` behavior. The changes include:

1. Deduplication of bitmap tip iteration logic between pack-objects and midx
2. Fix for exact ref matches in bitmap configuration
3. Correction of similar misuse in bisect code
4. Simplified string_list memory handling in bisect cleanup (from Jeff King)

The technical approach has been approved by Karthik Nayak and Junio C Hamano, with only minor string_list management details remaining under discussion. The series includes comprehensive tests in t5310 and t5319 to verify the fixes. This represents the final polishing of a well-motivated fix that addresses a real edge case while maintaining consistency with Git's ref matching conventions.
