The thread explores a proposed `git log --graph --untangle` option to simplify visualizing complex merge histories by displaying merged branches as originating from merge commits rather than their original branch points. The original RFC introduced core changes in graph.c with test coverage, drawing positive initial feedback from maintainer Junio Hamano, who requested concrete examples on complex histories like git.git's own graph.

Johannes Sixt (Hannes) raised substantive technical concerns about edge cases, questioning whether truncated links accurately represent history and highlighting potential ambiguity in criss-cross merges and interactions with `--boundary`. The latest contribution from Toon Claes addresses Junio's request by demonstrating the visualization improvement on git.git's l10n merge history, showing how the untangled version collapses parallel merge chains into cleaner vertical lines while preserving merge structure.

Key open questions remain around edge cases (particularly criss-cross merges), memory leaks in the implementation, and behavior with `--boundary`. The maintainer has signaled general interest in graph visualization improvements but wants to see more complex test cases and resolution of the technical concerns before finalizing the approach. The thread remains in exploratory phase, with the next steps being to address the memory issues, expand test coverage, and demonstrate the value on more substantial histories.
