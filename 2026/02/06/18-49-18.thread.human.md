This RFC thread explores a proposed `git log --graph --untangle` option to simplify visualizing complex histories by suppressing some ancestry lines, showing merged branches as originating from merge commits rather than their original branch points. The initial proposal from the author showed promise, with maintainer Junio C Hamano expressing interest while requesting concrete examples from Git's own complex history. Johannes Sixt raised important technical concerns about edge cases - questioning historical accuracy when links are truncated, and highlighting potential ambiguities with criss-cross merges, backward merges, and interactions with `--boundary`.

Toon Claes responded by demonstrating the visualization on Git's l10n merge history, showing how it can collapse parallel merge chains into cleaner vertical lines while preserving merge structure. In his latest follow-up, Toon addresses Johannes' concerns more deeply, proposing alternative visualization markers (`/` or `+` symbols) to indicate truncated ancestry and examining how backward merges would appear. He acknowledges the current implementation shows technically inaccurate history in some cases, particularly when merge bases aren't first parents.

The discussion remains in RFC stage with several open questions: the best way to visualize truncated links, handling of edge cases like criss-cross merges, memory leaks in the current implementation, and whether to rename the option to `--ignore-merge-base`. Toon encourages testing on real repositories, as small examples don't fully demonstrate the feature's value. While maintainer interest persists, the proposal needs more work to handle Git's full complexity before it could be considered for merging.
