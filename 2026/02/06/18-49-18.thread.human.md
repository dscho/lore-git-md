Here's a human-readable summary of the thread so far:

Toon Claes has proposed a new `--untangle` option for `git log --graph` that aims to simplify the visualization of complex merge histories. The key idea is to reduce visual clutter by displaying merged branches as if they originate directly from the merge commit, rather than showing their full ancestry lines back to the original branch point. This is particularly helpful for octopus merges and repositories with long-running topic branches that create excessively wide graphs.

The proposal includes core changes to Git's graph drawing logic in graph.c, new test cases demonstrating the simplified output, and acknowledges some current implementation limitations like memory leaks. The RFC nature of the patch indicates the author is open to feedback on both the approach and naming (with `--untangle` being one possible name among alternatives like `--ignore-merge-base`).

This appears to address a genuine usability pain point in visualizing complex repository histories, though the changes touch sensitive graph drawing code that would need careful review for edge cases. The thread is just starting, so we can expect discussion about whether this functionality belongs in core Git versus a porcelain command, and how to handle various merge scenarios cleanly.
