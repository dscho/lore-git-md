2. The `--force` flag correctly overrides this behavior to allow staging submodule changes
3. The behavior is consistent across different path specifications (`sub` vs `./sub/`)
4. Status and log commands respect the ignore setting as expected

The test file `t2206-add-submodule-ignored.sh` contains 8 test cases that:
- Set up a main repo with a submodule
- Verify default behavior with and without ignore settings
- Test both direct and relative path specifications
- Check interaction with `--ignore-submodules=none`
- Validate trace output and status reporting

This is part of the larger effort to align `git add` behavior with `git status` and `git diff` when dealing with ignored submodules.
