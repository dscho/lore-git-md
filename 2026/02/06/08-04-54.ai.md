This is a security-related discussion about `git am`'s handling of diffs in commit messages. Jacob Keller responds to Matthias Beyer's report about a real-world incident where a `sleep(1)` call was accidentally introduced into a Debian package via a diff in a commit message that `git am` applied.

Keller acknowledges the surprising behavior but questions whether it constitutes an attack vector, suggesting that users should review commit messages before applying. He notes that proper use of scissors markers ("-- >8 --") or indenting diffs could prevent accidental application. The email explores potential solutions but highlights the challenge of maintaining backward compatibility while fixing the issue.

The discussion indicates this is a real but nuanced security concern that would need careful handling to avoid breaking existing workflows.
