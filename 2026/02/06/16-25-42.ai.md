This is a bugfix addressing incorrect whitespace handling for symbolic links in Git's diff and apply machinery. The patch from maintainer Junio C Hamano, with review from Patrick Steinhardt, corrects a recent regression where whitespace checks (specifically WS_INCOMPLITE_LINE for missing newlines) were being incorrectly applied to symlinks.

The core fix modifies both `apply.c` and `diff.c` to skip these checks when dealing with symbolic links, where trailing newlines are not required. The implementation now uses a refined rule: disable the check when the post-image side (accounting for `--reverse`) is a symlink. This handles text-to-symlink transitions properly while maintaining whitespace validation for regular files.

The patch acknowledges but defers handling of theoretical edge cases like newline-terminated symlink targets, considering them not worth the complexity. Test coverage is added in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh`. The changes are focused and well-justified, with clear agreement between maintainer and reviewer on both the approach and what to defer.

This represents the final iteration of a focused fix for a clear regression, with all substantive technical questions resolved between the participants. The patch is ready for integration with no outstanding concerns.
