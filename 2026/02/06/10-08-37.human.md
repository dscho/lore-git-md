This is a security discussion thread about `git am`'s patch parsing vulnerability, where diffs embedded in commit messages can be applied unintentionally. Jeff King (Peff) responds to Florian Weimer's concerns about `git am`'s real-world usability by demonstrating that it can indeed handle both traditional GNU diff output and MIME-attached patches, though he acknowledges corner cases exist.

Peff provides concrete examples showing `git am` successfully processing both inline diffs (in the style of early Linux kernel patches) and modern MIME-attached patches. This illustrates the parser's flexibility but also highlights the security risk - the same parser that handles legacy formats is vulnerable to misinterpreting commit message content as patch content. The examples serve to ground the discussion in actual behavior rather than theoretical concerns.

The exchange reveals tension between maintaining backward compatibility (supporting decades of patch formats) and fixing a security issue that could allow malicious diffs to be hidden in commit messages. Peff's examples suggest any solution will need to carefully preserve this compatibility while closing the security hole. The thread continues to explore solutions that balance these concerns.
