Security issue in `git am` where it applies diffs from commit messages, with real-world impact (Debian package incident).

Matthias Beyer responds to Jacob Keller's initial assessment, emphasizing that the current behavior is clearly unintentional and could have serious security consequences beyond the benign `sleep(1)` example that made it into Debian's i3 package. He argues this could be exploited to sneak malicious changes into codebases by hiding them in commit message diffs that reviewers might not expect to be applied.

The email proposes a technical solution: modifying `git am` to search for the patch delimiter ("---\n") from the end of the email rather than the beginning, which would prevent it from applying diffs embedded in commit messages. This suggestion comes from Matthias' reading of the `git am` code, though he notes he's not deeply familiar with the codebase.

The discussion highlights a tension between backward compatibility (existing workflows that might rely on this behavior) and security (preventing potentially dangerous unintended patch application). The real-world impact gives this issue practical urgency, though the technical solution proposed may need careful evaluation for edge cases and compatibility implications.
