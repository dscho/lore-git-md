Security vulnerability follow-up regarding `git am` patch parsing. Jakob Haufe (sur5r) responds to Kristoffer Haugsbakk's suggestion about using indentation for code blocks in commit messages to prevent accidental patch application. The email points out that this approach wouldn't fully solve the problem, as the `patch` command itself has intentional behavior to handle indented diffs and encapsulated lines (per RFC 934). Even if `git am` were fixed, the underlying issue would persist when piping Git output directly to `patch`.

The message serves as a reality check about the scope of any potential fix - while `git am` improvements could help, the problem is more systemic due to how Unix patch tools fundamentally work. This adds complexity to the ongoing discussion about balancing security with backward compatibility in patch handling. The thread continues to explore solutions that would work across both Git's tools and the broader Unix patch ecosystem.
