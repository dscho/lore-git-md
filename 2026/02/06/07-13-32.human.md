This is a follow-up discussion in a bugfix thread about `pack.preferBitmapTips` configuration behavior. The patch series aims to fix issues with exact ref matching in bitmap and bisect functionality, but this email focuses specifically on the semantic question of how ref patterns should be interpreted.

Patrick Steinhardt responds to Taylor Blau's concerns about consistency between `pack.preferBitmapTips` and other Git commands' pattern matching behavior. While Patrick initially proposed making the configuration more flexible by allowing both prefix and exact matches, Taylor argues for aligning with `git for-each-ref`'s pattern matching semantics (using `*` wildcards) for consistency across Git commands.

The key points in this exchange:
- Patrick acknowledges the current behavior is already somewhat inconsistent
- Taylor highlights that `git for-each-ref` uses explicit wildcards (`refs/heads/ma*`) rather than implicit prefix matching
- While Patrick sees value in more flexible configuration, he ultimately defers to Taylor's preference for consistency with existing Git conventions
- Both agree the impact is limited since this is primarily used by hosting providers

The discussion shows the patch will likely be revised to use pattern matching semantics rather than prefix matching, though Patrick notes he's not strongly opinionated about the choice. This email represents a design decision point in an otherwise technically-approved series, with the authors converging on an approach that prioritizes consistency with other Git commands over configuration flexibility.
