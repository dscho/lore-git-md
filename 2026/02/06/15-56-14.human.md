This is the second patch in a three-part series introducing a `--rework-with-file` option for Git's interactive patch commands (`add -p`, `checkout -p`, `reset -p`, `stash -p`). The feature enables non-linear navigation between files during interactive hunk selection.

The patch implements the core navigation behavior, allowing users to move between files with '>' (next file) and '<' (previous file) keys when `--rework-with-file` is active. The changes modify the hunk selection state machine in `add-patch.c` to track decisions across files while preserving existing code paths. Key additions include new prompt options, file navigation logic, and handling for the "all hunks decided" state where users can continue editing or move to another file.

The implementation appears thorough, with proper guards to ensure the new behavior only activates with the flag. The patch maintains backward compatibility while adding ~80 lines of new logic. This middle patch builds on the flag plumbing from patch 1 and sets up for patch 3's timing fixes. The changes are well-contained to the interactive selection flow without affecting core Git functionality.
