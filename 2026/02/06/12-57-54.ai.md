This is part 2 of a 3-patch series refactoring `wt-status.c` to remove dependencies on the `the_repository` global variable, as part of the broader `the_repository` removal effort. The patch focuses on propagating repository context through function parameters rather than relying on worktree structures.

The key change in this version is modifying the rebase and bisect status checking functions (`wt_status_check_rebase()` and `wt_status_check_bisect()`) to take an explicit `struct repository *` parameter. This addresses the NULL worktree handling issue that was causing test failures in previous versions. The patch also updates all callers to pass the repository parameter appropriately.

The changes span multiple files (`wt-status.c`, `branch.c`, `worktree.c`, and `wt-status.h`) and touch several subsystems including stash counting, rebase state reading, and porcelain v2 output handling. The author reports that the changes pass all tests, indicating the NULL safety issues have been resolved.

This represents a significant step forward in the refactoring effort, with only two remaining global dependencies (`comment_line_str` and `DEFAULT_ABBREV`) explicitly scoped for future work. The architectural discussion appears to be converging toward direct repository parameter passing rather than worktree-based access patterns.
