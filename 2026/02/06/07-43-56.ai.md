This is a security-related bug report about an unexpected behavior in `git am`. The issue describes how `git am` will apply not just the patch content but also any diff that appears in the commit message itself, which could lead to unintended code changes being applied. The reporter, Matthias Beyer, found this through a Mastodon post showing how a `sleep(1)` call was accidentally introduced into a Debian package this way.

The behavior is clearly unintended and could be exploited maliciously - an attacker could hide harmful changes in what appears to be an innocent commit message. The report doesn't include a patch but raises an important security concern that would need to be addressed, likely by modifying `git am` to ignore diffs in commit messages or at least warn about them.

This seems like a legitimate security issue that would warrant attention from the security-conscious contributors like Jeff King (Peff) who often work on hardening Git's behavior. The fact that it was discovered through an actual incident (the i3 window manager package in Debian) gives it concrete urgency.
