Bugfix for whitespace handling in diff/apply when dealing with symbolic links. This patch from maintainer Junio C Hamano addresses an issue where recent whitespace checking improvements were incorrectly flagging symlinks for missing newlines at end of file - a condition that's actually normal for symlinks.

The fix modifies both `apply.c` and `diff.c` to skip the WS_INCOMPLETE_LINE check when the post-image (or pre-image when applying in reverse) is a symbolic link. This properly handles cases like text-to-symlink transitions where we shouldn't complain about missing newlines in the symlink content. The implementation is careful about mode changes and reverse application scenarios.

New test cases in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh` verify the behavior, including colorized output checks and mode transition cases. The v2 iteration refined the approach based on Patrick Steinhardt's review, focusing the check only on the post-image side rather than both sides of the diff. This is a clean, focused fix for a real issue that was introduced by recent whitespace checking improvements.
