This is the documentation patch (5/5) in a series that aligns `git add` behavior with `git status` and `git diff` for submodules with `ignore=all` configuration. The patch updates three documentation files to reflect the new requirement that `--force` must be used to stage updates to ignored submodules.

The changes clarify that while `ignore=all` prevents submodules from being considered modified by default, they can still be explicitly staged using `git add --force <submodule.path>`. The documentation now explains this behavior consistently across the `git-add`, `gitmodules`, and submodule config man pages.

Key updates include:
- Explicit mention of `--force` requirement in all three documents
- Improved phrasing of `ignore=all` behavior descriptions
- Clearer distinction between default behavior and `--force` override
- Added context about which commands are affected by the setting (status, update-index, diff, log)

The patch follows through on the implementation changes from earlier in the series, providing users with accurate guidance about the new stricter behavior while maintaining backward compatibility. Documentation changes were reviewed and improved by Ben Knoble in earlier iterations.

This completes the documentation side of the effort to make submodule handling more consistent across Git commands while preserving the ability to explicitly override the ignore behavior when needed.
