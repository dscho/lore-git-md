Thread identity: RFC patch series on refactoring `get_layout_bare()` in `builtin/repo.c` to remove dependency on `the_repository` global state, part of the ongoing repository independence effort.

Core problem: The function currently ignores its `struct repository*` parameter and uses the global `is_bare_repository()` instead, violating repository isolation principles. The patch aims to make it properly repository-aware by checking the repository's config and worktree status directly.

Current status: First version sent as RFC by a GSoC 2026 student contributor, seeking feedback on the approach to determining bare repository status in a repository-aware way. No reviews or acks yet.

Key technical details: Changes `get_layout_bare()` to examine the passed repository's `core.bare` config and worktree state rather than using the global `is_bare_repository()`. Maintains same external behavior while properly isolating repository state. Touches only `builtin/repo.c`.

Open questions: Whether this is the correct approach for determining bare repository status in a repository-aware context. The RFC nature suggests the author is specifically seeking input on this design decision.
