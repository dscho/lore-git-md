This is a const-correctness patch series addressing compiler warnings from glibc 2.43 in C23 mode. The first patch (v2 1/2) mechanically adds const qualifiers to pointers that receive results from string search functions where the pointed-to data isn't modified.

The changes are widespread but straightforward - 28 files touched with small, consistent modifications to pointer declarations. Each change follows the same pattern: adding const to pointers that store results from functions like strrchr() and memchr() when the input was const-qualified. This matches the new C23 standard behavior where these functions return const-qualified pointers when given const inputs.

The patch is well-motivated by concrete compiler warnings that would appear with GCC 15's default -std=gnu23 mode. Jeff King has already reviewed and approved the technical approach, and Junio Hamano has approved the series pending this organizational split (moving an unrelated NULL initialization removal to a separate patch, which Collin has now done in v2).

This is part of Git's ongoing effort to maintain compatibility with modern C standards and compiler versions. The changes are purely type-system improvements with no behavior modifications - a safe, mechanical update that improves code quality. With the requested split now made, this series appears ready for merging.
