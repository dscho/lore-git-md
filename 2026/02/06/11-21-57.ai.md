This is a patch in Adrian Ratiu's series to make Git hooks configurable via Git configuration, specifically addressing infrastructure changes for running a list of hooks. The patch refactors the hook execution machinery to support multiple hook sources (eventually including config-based hooks) while maintaining the existing filesystem hook behavior.

The key changes introduce a `list_hooks()` function that consolidates hooks from different sources (currently just filesystem hooks) into a string list for execution. Junio Hamano's review suggests several improvements to make the implementation more robust and self-documenting, particularly around hook identification and memory management. He proposes replacing the current string-based differentiation of hook types with explicit enum/struct types and avoiding redundant `find_hook()` calls.

The discussion reveals some implementation details that will likely change in v2: the current approach uses empty strings to identify filesystem hooks (a temporary convention), and there's room to optimize memory management by having callers pass in string lists rather than allocating new ones. The changes touch core hook execution code but maintain backward compatibility with existing hook behavior.

This patch represents foundational work needed before introducing config-based hooks in later patches. Junio's feedback focuses on making the infrastructure more maintainable before building on it, but raises no fundamental concerns about the series' direction. The tone remains constructive, with Adrian indicating he'll incorporate the suggestions in the next iteration.
