Bugfix for whitespace handling in diff/apply machinery when dealing with symbolic links. This final version from maintainer Junio C Hamano addresses incorrect triggering of incomplete-line checks (WS_INCOMPLITE_LINE) on symlinks where such endings are normal.

The patch modifies both `apply.c` and `diff.c` to skip WS_INCOMPLITE_LINE checks when the post-image side (accounting for `--reverse`) is a symlink. This properly handles text-to-symlink transitions where we shouldn't complain about missing newlines in the post-image, while still maintaining whitespace validation for regular files. The implementation includes careful mode-change handling in `apply.c` to determine whether we're looking at the pre- or post-image based on patch direction.

New test cases in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh` verify the behavior for both forward and reverse operations. The tests specifically check that:
- Symlink diffs don't trigger incomplete-line warnings
- Text-to-symlink transitions are handled correctly
- Reverse operations still validate text files appropriately

The v2 iteration refined the approach from v1 by only considering the post-image side (rather than either side) for symlink checks, as we still want to validate incomplete lines when converting symlinks to text files. Patrick Steinhardt provided technical review that helped shape this refinement. The patch is now considered ready for integration with no outstanding concerns.
