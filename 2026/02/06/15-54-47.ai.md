Feature patch introducing a new `--rework-with-file` option for interactive hunk selection. This is the first of three patches in Abraham Samuel Adekunle's series to modify Git's interactive patch selection workflow.

The patch adds a new flag that prevents automatic advancement to the next file during interactive hunk selection (in `git add -p`, `git checkout -p`, `git reset -p`, and `git stash -p`). Currently, Git moves to the next file immediately after completing hunk selection for a file. The new option lets users stay on the current file to rework their selections.

Implementation adds a `no_auto_advance` field to the `add_p_opt` and `add_i_state` structs, with corresponding command-line options for each affected command. The option is properly guarded to only work with `-p/--patch` mode, following the pattern of existing interactive options like `--unified`. The patch includes shell completion updates but doesn't yet modify the actual interactive behavior - that comes in subsequent patches.

The changes are mechanical plumbing additions that don't yet affect runtime behavior. The patch follows Git's standard patterns for adding new options, with appropriate error handling when used without `-p`. The series appears well-structured, with this first patch cleanly laying the groundwork for the interactive changes to follow.
