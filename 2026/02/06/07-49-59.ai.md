This is a memory management cleanup patch in the bisect subsystem, part of Patrick Steinhardt's series fixing ref iteration bugs. The patch simplifies string_list handling in `bisect_clean_state()` by using STRING_LIST_INIT_DUP instead of manual memory management.

The change switches from a NODUP string_list (where strings were manually allocated with xstrdup) to a DUP string_list (which handles its own duplication). This eliminates the need for explicit string duplication and the awkward pattern of toggling strdup_strings just before cleanup. The simplification was enabled by a previous commit that changed one callsite from xstrfmt() to xstrdup().

The patch maintains the same functionality while making the code more straightforward. It's authorship is credited to Jeff King (peff), with Patrick Steinhardt carrying it in his series. This appears to be a straightforward improvement that builds on the ref iteration fixes in the earlier patches.
