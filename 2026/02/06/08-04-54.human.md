Security issue in `git am` where it applies diffs from commit messages. This is a follow-up discussion in the thread about the unexpected behavior where `git am` applies diffs embedded in commit messages, which recently caused a real-world issue in a Debian package.

Jacob Keller responds to Matthias Beyer's initial report, agreeing the behavior is surprising but questioning whether it constitutes an attack vector since users should review commit messages before applying. He notes that while the current behavior is unintentional, it's not clear how to safely fix it without breaking backward compatibility. 

Keller suggests two workarounds: using scissors markers (`-- >8 --`) to separate commit messages from patches, or indenting diff text to prevent parsing. He also explores potential solutions like improving `format-patch` output to better delineate commit messages, but acknowledges the challenge of doing this in a backward-compatible way.
