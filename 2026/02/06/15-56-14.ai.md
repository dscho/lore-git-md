This is the second patch in a three-part series introducing inter-file navigation to Git's interactive hunk selection interface. The patch implements the core functionality for moving between files using '>' and '<' keys when the new `--rework-with-file` flag is active.

The changes modify `add-patch.c` to:
1. Add new navigation options to the help text
2. Introduce an enum to track file navigation responses
3. Update the hunk selection state machine to handle inter-file movement
4. Show a new prompt when all hunks in a file are decided
5. Implement circular navigation through files (wrapping from first to last and vice versa)

The patch touches 95 lines with 80 additions and 15 deletions, primarily focused on the `patch_update_file()` function. It builds on the first patch's plumbing changes by actually implementing the non-sequential workflow. The implementation appears careful to maintain existing behavior when the new flag isn't used, and includes error handling for invalid navigation attempts (like trying to go previous when on the first file).

This middle patch represents the bulk of the series' functional changes. The third patch will presumably handle proper timing of patch application. The changes are well-contained to the interactive selection flow and don't affect core Git operations.
