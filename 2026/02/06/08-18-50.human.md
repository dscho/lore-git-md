Security issue in `git am` where it applies unintended diffs from commit messages. Matthias Beyer follows up on Jacob Keller's response to highlight the real-world impact of this behavior, where a `sleep(1)` call accidentally made it into a Debian package (i3 window manager) via a diff in a commit message. He emphasizes that this could have been much worse if malicious code had been hidden in the commit message diff.

Beyer suggests a potential fix: having `git am` search for the patch delimiter ("---\n") from the end of the email rather than from the beginning, which would prevent it from applying diffs embedded in commit messages. While not a Git expert, he's done enough code reading to identify where the patch detection logic lives.
