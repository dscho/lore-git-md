This is a bugfix addressing incorrect whitespace handling for symbolic links in Git's diff and apply machinery. The patch follows up on Junio C Hamano's initial fix for WS_INCOMPLETE_LINE checks being incorrectly applied to symlinks, where trailing newlines aren't meaningful.

Patrick Steinhardt's review identified an edge case where the fix needs refinement: during text-to-symlink transitions, we shouldn't complain about missing newlines in the post-image symlink. The current discussion focuses on precisely defining when to skip these checks, with both parties agreeing that theoretical edge cases (like newline-terminated symlink targets) can be safely ignored.

The patch touches core diff/apply code paths in `apply.c` and `diff.c`, with accompanying test updates. This is a focused technical fix that should stabilize behavior without introducing new features. Given the maintainer's involvement and the clear problem statement, this fix is likely to land soon after the remaining edge cases are addressed.
