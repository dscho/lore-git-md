This is a bugfix patch in Patrick Steinhardt's series addressing issues with exact ref matching in bitmap generation. The patch specifically fixes a case where specifying an exact reference in `pack.preferBitmapTips` would trigger a BUG() due to incorrect refname trimming.

The fix ensures that ref patterns are always treated as hierarchies by appending a trailing slash when needed, matching Git's established convention from previous ref matching fixes. The change makes the behavior consistent with how ref exclusions work (as established in commit 10e8a9352b) and prevents the BUG() condition while maintaining expected functionality.

The patch includes thorough test coverage in both t5310-pack-bitmaps.sh and t5319-multi-pack-index.sh, verifying that:
- Exact ref matches are properly interpreted as hierarchy matches
- The fix works for both regular pack bitmaps and multi-pack-index bitmaps
- The behavior aligns with documentation updates that clarify the hierarchy matching semantics

This is the second patch in a 4-part series that has already gone through multiple iterations with positive feedback from reviewers including Taylor Blau and Junio Hamano.
