This is a patch in Adrian Ratiu's series to make Git hooks configurable via Git configuration. The current iteration addresses Junio Hamano's feedback on the infrastructure changes, particularly around how hook lists are managed.

The patch refactors the hook execution infrastructure to support running multiple hooks in sequence, consolidating hooks from both config-based sources (not yet implemented in this patch) and traditional hookdir locations. The key change is introducing `list_hooks()` which collects all hooks for a given event, though currently it only handles the traditional hookdir case.

Junio's review suggests several improvements to make the implementation more robust and self-documenting:
- Passing in an existing string_list rather than allocating a new one each time
- Using explicit enum/struct types to identify hook sources rather than relying on empty strings
- Avoiding redundant `find_hook()` calls by caching results
- Making the hook source identification more type-safe

Adrian acknowledges the feedback positively and indicates he'll explore these suggestions for v2. The discussion remains focused on refining the infrastructure before expanding functionality further in subsequent patches. This is part of a larger effort to enable config-based hooks that can execute both inside and outside repository contexts.
