Feature proposal for a new `git log --graph --untangle` option to simplify complex merge visualization.

This RFC patch from Toon Claes introduces a new `--untangle` flag for `git log --graph` that aims to simplify the display of complex merge histories, particularly octopus merges. The key idea is to stop drawing lines back to merge bases for merged branches, making the graph appear cleaner by showing merged branches as if they originate from the merge commit rather than their original branch point.

The patch demonstrates the effect with test cases showing before-and-after graphs. For example, an octopus merge that would normally show multiple crossing lines back to a common ancestor instead appears as a cleaner "hub and spokes" pattern. The author acknowledges some implementation issues remain (memory leaks, naming concerns) and seeks feedback on whether this direction is worth pursuing.

This appears to be a well-motivated quality-of-life improvement for users who work with complex merge histories. The implementation touches core graph drawing logic in `graph.c` and adds new test coverage. The author is open to alternative naming suggestions (`--ignore-merge-base` was considered) and wants to know if this approach aligns with the project's vision before investing more time in polishing it.

The patch would be particularly useful for repositories with many long-running branches or frequent octopus merges (like git.git itself), where the standard graph output can become unwieldy. The concept seems sound, though the implementation will need cleanup before being merge-ready.
