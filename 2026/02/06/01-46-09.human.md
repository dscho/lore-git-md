This is a const-correctness patch series addressing compiler warnings from glibc 2.43 in C23 mode. The first patch (v2) mechanically adds const qualifiers to pointers that receive results from string search functions (strrchr, memchr, etc.) where the pointed-to data isn't modified.

The changes are widespread but straightforward - 28 files touched with small, consistent modifications to pointer declarations. The motivation comes from glibc 2.43's change to make string functions return const-qualified pointers when given const inputs, which triggers warnings under GCC 15's default -std=gnu23 mode.

Jeff King reviewed and approved the technical approach, and Junio Hamano has given final approval pending one organizational change - splitting out an unrelated NULL initialization removal into a separate patch (which Collin Funk has done in this v2). The series is now in its final form and ready for merging.

This is part of Git's ongoing effort to maintain compatibility with modern C standards and compiler versions. The changes are purely type-system improvements with no behavior modifications.
