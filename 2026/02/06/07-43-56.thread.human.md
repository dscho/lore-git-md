This thread addresses a security vulnerability in `git am` where patches can be misparsed when commit messages contain content that resembles patch syntax (like diff output). The issue was highlighted by a Debian incident where a `sleep(1)` command was accidentally introduced from a commit message diff.

The discussion has produced a multi-layered solution approach. Kristoffer Haugsbakk's documentation patch (v3) has now been finalized and queued by Junio after review from Phillip Wood. It adds explicit warnings in multiple man pages about the parsing hazards when roundtripping patches via email. This serves as an immediate mitigation while technical solutions are developed.

Several technical approaches are under consideration:
- Jacob Keller proposed backwards-compatible boundary markers
- Jeff King (Peff) suggested both a sender-side reversible quoting mechanism and a new `--strict` mode for `git am` (now endorsed by Junio)
- Patrick Steinhardt is exploring an `--accept-ambiguous-patch` flag

Peff has raised concerns about Keller's boundary marker approach regarding visual clutter and potential false positives, while his `--strict` mode offers a cleaner solution for Git-generated patches by enforcing clear `---` separators. The documentation changes represent the first concrete outcome from this discussion, with technical implementations still being refined. Junio has indicated support for Peff's strict mode approach while the community works through the remaining open questions about edge cases and compatibility.
