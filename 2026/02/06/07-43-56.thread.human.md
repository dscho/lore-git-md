This thread examines a security vulnerability in `git am` where the tool can mistakenly apply diffs embedded in commit messages as actual patches, rather than treating them as documentation. The issue originally surfaced in a Debian incident where a `sleep(1)` command was accidentally introduced from a commit message's example diff. 

The discussion has revealed this is a systemic problem affecting not just Git but Unix tools more broadly - both `git am` and traditional `patch(1)` will apply any diff they find, even those meant as examples, if the diffs aren't properly distinguished. Kristoffer Haugsbakk initially thought avoiding certain markers like `From` and `---` would prevent misapplication, but Jakob Haufe's input showed the issue is more complex due to how tools handle indentation stripping during parsing.

Multiple solutions have been proposed but all face challenges: reverse parsing fails with certain diff contents, indentation conventions aren't universally followed, delimiter tracking requires format changes, and separating attachments breaks workflows. The thread has established this as a long-standing issue that now requires balancing security needs with backward compatibility across the Unix toolchain. While Git could modify its handling of indented diffs, any fix must consider how it interacts with other tools' behaviors and existing practices around embedding example diffs in commit messages.
