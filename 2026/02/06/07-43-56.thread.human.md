This thread addresses a security vulnerability in `git am` where patches can be misparsed when commit messages contain diff-like content, as demonstrated by a Debian incident where `sleep(1)` was accidentally introduced from a commit message. The discussion has evolved through multiple proposals to address this long-standing issue while maintaining backward compatibility.

Kristoffer Haugsbakk's documentation patch warning about this hazard has been finalized and queued by Junio. Jacob Keller now proposes a backwards-compatible solution introducing an explicit boundary marker (`--- git-patch-boundary ---`) after the traditional `---` separator. This would let older clients definitively identify patch starts while maintaining compatibility with existing workflows that tolerate text between separators. The proposal builds on prior work including Phillip Wood's security-enhanced commit-msg hook and Patrick Steinhardt's `--accept-ambiguous-patch` flag.

Junio remains open to solutions that don't break old clients, though skeptical about perfect compatibility. The layered approach under discussion combines documentation warnings, defensive hooks, explicit confirmation flags, and boundary markers. Key open questions remain about edge case handling and cross-tool compatibility, with Junio also suggesting signed patches as an alternative security boundary. The thread reflects Git's careful balancing of security needs with preservation of existing workflows.
