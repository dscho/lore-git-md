This thread addresses a security vulnerability in `git am` where patch parsing can accidentally apply embedded diffs from commit messages, as seen in a Debian incident that introduced unintended `sleep(1)` calls. The discussion has produced a layered solution combining documentation warnings, commit-msg hooks, and new parsing modes.

Kristoffer Haugsbakk's documentation patches warning about patch roundtrip hazards have been merged to `next`. Phillip Wood has developed a security-focused commit-msg hook (now at v3) that handles email headers, separator lines, and scissors markers, with Junio and Haugsbakk confirming its behavior in `--cleanup=scissors --verbose` mode. The hook's regex pattern for comment detection was recently clarified to properly handle edge cases like `$` as a comment character.

Other proposals under consideration: Jeff King's reversible quoting mechanism and `--strict` mode (endorsed by Junio), Patrick Steinhardt's `--accept-ambiguous-patch` flag, and Jacob Keller's boundary marker approach. The documentation component is complete, while the hook implementation appears technically sound pending minor documentation corrections. The thread shows careful attention to security-sensitive code review, with the maintainer scrutinizing even subtle implementation details.
