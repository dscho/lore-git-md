Here's the updated human-readable thread summary:

This thread addresses a security vulnerability in `git am` where it can mistakenly apply diffs embedded in commit messages, as demonstrated by a real-world incident in a Debian package (i3 window manager) where a `sleep(1)` call was accidentally introduced this way. Matthias Beyer reported the issue, arguing this clearly unintentional behavior could have serious security consequences.

The discussion has established consensus that this is a real vulnerability, not just a nuisance. Jeff King (Peff) provided historical context, explaining this is a long-standing issue with three prior discussions (2015, 2022, 2024). He detailed why neither top-down nor bottom-up parsing can reliably distinguish intended patches from embedded diffs, noting the irony that while `git format-patch --attach` produces unambiguous MIME parts, the current processing still combines them into vulnerable streams.

Several solutions have been proposed but all face backward compatibility challenges: Florian Weimer suggested reverse parsing, Jacob Keller and Kristoffer Haugsbakk discussed indentation conventions, and Beyer proposed delimiter position awareness. Peff noted the only robust solution might require manual separation of attachments, though this would break existing workflows. The discussion has now shifted from establishing the problem exists (which all agree on) to finding a solution that balances security with compatibility, with the Debian incident providing concrete motivation for action.
