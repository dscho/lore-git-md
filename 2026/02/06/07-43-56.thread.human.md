This thread addresses a security vulnerability in `git am` where embedded diffs in commit messages can be accidentally applied as patches, stemming from how email tools strip indentation before parsing. The issue came to light through a Debian incident where a `sleep(1)` command was unintentionally introduced from a commit message diff.

The discussion has progressed along two parallel tracks: technical solutions and documentation. On the documentation front, Kristoffer Haugsbakk's patch adding explicit warnings about patch round-tripping hazards has been finalized after review by Phillip Wood and is now queued by Junio. The documentation explains how unindented diffs in commit messages can be misinterpreted and provides workarounds like indenting problematic content.

For technical solutions, several approaches are under consideration:
1. Jacob Keller proposed backwards-compatible boundary markers
2. Jeff King (Peff) suggested both sender-side reversible quoting and a new `--strict` mode for `git am`
3. Patrick Steinhardt explored an `--accept-ambiguous-patch` flag

Peff's `--strict` mode, which enforces clean `---` separators for Git-generated patches, has gained Junio's endorsement as it maintains backward compatibility while reducing risk. The discussion has also touched on Phillip Wood's security-focused commit-msg hook enhancements and Junio's suggestion of signed patches as an alternative security boundary.

The thread reflects a growing consensus for a layered approach combining documentation warnings, technical safeguards, and parser improvements. With the documentation patch now finalized and queued, attention is shifting toward implementing the technical solutions, particularly Peff's `--strict` mode which appears to be emerging as the preferred path forward for Git-generated patches.
