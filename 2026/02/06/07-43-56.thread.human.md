This thread addresses a security vulnerability in `git am` where patch/commit message parsing can misinterpret embedded diffs, particularly affecting distribution workflows. The issue stems from ambiguity between intended patches (after "---") and diffs in commit messages, with three specific termination patterns causing problems: three-dash lines, "diff -" lines, and "Index:" lines.

Kristoffer Haugsbakk's documentation patch has been queued by Junio after incorporating feedback from Phillip Wood and Junio himself. The updated warnings in `format-patch-caveats.adoc` now clearly explain the risks of commit message alteration and incorrect patch application, avoiding potentially confusing language. These warnings will appear across multiple man pages via a shared include file.

The solution involves multiple layers: Wood's security-focused `commit-msg` hook (though detection of "---" lines may be removed after Junio demonstrated legitimate uses), Steinhardt's proposed `--accept-ambiguous-patch` flag for explicit confirmation when ambiguity is detected, and these documentation improvements. The issue is particularly acute for distributions like NixOS that apply thousands of patches, as confirmed by Beyer's input.

While the documentation component is now settled, open questions remain about the final form of Wood's hook and implementation details of Steinhardt's flag. The discussion has revealed tensions between security needs and backward compatibility, with Peff noting legitimate (though rare) uses of separator lines in workflows. The layered approach aims to preserve maintainer workflows while addressing the security risks that have caused real-world incidents like the Debian `sleep(1)` vulnerability.
