This thread addresses a security vulnerability in `git am` where commit messages containing unindented diffs can be misinterpreted as patch data - a problem that famously caused Debian to accidentally introduce a `sleep(1)` command via a misparsed commit message. The community has developed a multi-pronged solution.

The documentation component is now complete, with Kristoffer Haugsbakk's warnings about patch roundtrip hazards merged into the `next` branch after three iterations and review from Phillip Wood. These warnings appear in multiple man pages to alert users about the risks.

Phillip Wood has contributed the key technical piece - a v3 version of a security-focused commit-msg hook that detects and blocks dangerous patterns. It intelligently handles edge cases like email headers, separator lines, scissors markers, and comment characters while avoiding false positives. This hook has been thoroughly tested and complements the documentation updates.

The broader solution includes several other elements still in progress: Jeff King's proposed `--strict` mode for `git am` (endorsed by Junio), boundary marker proposals from Jacob Keller, and Patrick Steinhardt's work on an `--accept-ambiguous-patch` flag. Junio has suggested signed patches as another potential security boundary.

While the immediate documentation and hook components are now settled, discussions continue about the best way to handle ambiguous patches, with various technical tradeoffs being weighed. The thread reflects Git's careful approach to security issues that must balance protection with backward compatibility.
