This thread addresses a security vulnerability in `git am` where the tool can misinterpret embedded diffs in commit messages as intended patches, a problem highlighted by a Debian incident where `sleep(1)` was accidentally introduced from a commit message diff. The discussion has produced a multi-faceted solution combining documentation warnings, commit-msg hooks, strict modes, and boundary markers.

Kristoffer Haugsbakk's documentation patch, now finalized and queued for the `next` branch, adds explicit warnings about these hazards in `format-patch-caveats.adoc`. Phillip Wood and Junio Hamano have reviewed and approved the wording, marking the first completed component of the solution. Wood has also contributed a security-focused commit-msg hook (now in its third version) that handles email headers, separator lines, and other edge cases to prevent problematic diffs from being committed.

Technical discussions continue around Jeff King's proposed `--strict` mode for `git am` (endorsed by Junio), Patrick Steinhardt's `--accept-ambiguous-patch` flag, and Jacob Keller's boundary marker proposal. The documentation component is now settled, while the implementation details of the technical solutions are being refined. The thread reflects broad agreement that a layered approach is needed to address this long-standing issue that affects not just Git but other Unix tools in the patch-processing chain.
