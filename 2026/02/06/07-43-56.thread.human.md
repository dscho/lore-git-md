Here's a human-readable thread summary:

This thread reports a security vulnerability in `git am` where the command will apply not only the intended patch but also any diff that appears in the commit message itself. Matthias Beyer discovered this through a real-world incident where a `sleep(1)` call was accidentally introduced into a Debian package's i3 window manager via this mechanism.

The behavior is clearly unintended and could be exploited maliciously - an attacker could hide harmful code changes in what appears to be an innocent commit message. While no patch has been proposed yet, this represents a serious security concern that would need to be addressed, likely by modifying `git am` to either ignore diffs in commit messages or at least warn about them.

Given the security implications and the concrete real-world impact demonstrated, this issue warrants attention from security-focused contributors like Jeff King (Peff) who specialize in hardening Git's behavior. The fact that this was discovered through an actual incident affecting a Debian package adds urgency to addressing the vulnerability.
