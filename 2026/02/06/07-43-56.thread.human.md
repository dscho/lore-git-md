This thread addresses a security vulnerability in `git am` where the tool can inadvertently apply diffs embedded in commit messages, as demonstrated by a real-world Debian incident where a `sleep(1)` command was accidentally introduced. The core issue stems from `git am`'s difficulty in reliably distinguishing intended patches (after the "---" separator) from embedded diffs in commit messages when processing email streams.

Phillip Wood has implemented a security-focused enhancement to the sample `commit-msg` hook that detects problematic patterns like unindented diffs and ambiguous separator lines, while providing configurable bypass mechanisms. The solution includes detection of diffs only above the scissors line, support for configurable comment characters, and clear error messages. Kristoffer Haugsbakk has proposed adding an environment variable escape hatch to accommodate legitimate uses of separator lines, as highlighted by Junio Hamano's workflow example.

The latest contribution comes from Haugsbakk, who is proposing to add documentation warnings about this behavior. While the actual documentation changes aren't included yet, this represents an important layer of defense alongside the technical solutions. The thread has established that indentation-based approaches alone are insufficient due to parsing pipeline behaviors, and that a multi-layered approach combining hooks, parser improvements, and documentation is needed. Open questions remain about how to document bypass mechanisms without undermining security and whether to implement Haugsbakk's proposed environment variable escape hatch. The discussion continues to balance security needs with backward compatibility and workflow considerations.
