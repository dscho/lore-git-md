This thread addresses a security vulnerability in `git am` where patch/commit message parsing can be confused by embedded diffs or separator lines ("---") in commit messages. The issue came to light after a real-world incident in Debian where a `sleep(1)` command was accidentally introduced from a commit message diff. 

Phillip Wood has implemented a security-focused enhancement to the `commit-msg` hook that detects problematic patterns while maintaining backward compatibility. The solution includes multiple safeguards: detection of diffs only above the scissors line, configurable comment characters, and clear error messages. Kristoffer Haugsbakk has now contributed documentation patches (queued by Junio) that explicitly warn about these hazards in the `git-format-patch`, `git-send-email`, and `git-am` man pages. The documentation provides concrete examples of dangerous patterns and workarounds, though there was minor disagreement about how much attribution context to include in the commit message.

The layered approach combines technical detection (Wood's hook) with user education (Haugsbakk's docs) while preserving workflow flexibility through escape hatches like `--no-verify`. Some open questions remain about whether to add an environment variable bypass and how to coordinate with the broader Unix toolchain (like `patch(1)`), but the queued documentation represents significant progress in addressing this long-standing security concern.
