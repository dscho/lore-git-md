Thread summary:

RFC proposal for a new `git log --graph --untangle` option to simplify visualization of complex histories by suppressing ancestry lines, displaying merged branches as originating from merge commits rather than original branch points. Core changes in graph.c introduce `only_first_merge_base` flag and `ignored_merge_bases` list, with test coverage in t4214-log-graph-octopus.sh. Maintainer Junio C Hamano initially responded positively to the concept while requesting concrete visualization examples on complex histories like git.git's own graph. Johannes Sixt (Hannes) raised substantive technical concerns about edge cases - questioning truncated links' historical accuracy, highlighting ambiguity in criss-cross merges and backward merges, and noting interaction issues with `--boundary`.

Toon Claes has now responded to Junio's request by demonstrating before/after output from git.git's l10n merge history, where the untangled version collapses multiple parallel merge chains into cleaner vertical lines while preserving merge structure. The implementation still has memory leaks in `ignored_merge_bases` and naming concerns (`--ignore-merge-base` is proposed as an alternative). Open items now include: resolving Hannes' edge cases (criss-cross/backward merges, `--boundary` interactions), fixing memory leaks, expanding test coverage with more complex histories, and finalizing the option name. Maintainer interest persists but implementation must address these technical concerns while proving visualization benefits on substantial examples. The thread shows progress toward Junio's request for concrete demonstrations but remains in RFC stage with clear technical hurdles before consideration for merging.
