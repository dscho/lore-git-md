Thread summary:

RFC proposal for a new `git log --graph --untangle` option to simplify visualization of complex histories by suppressing ancestry lines for merged branches. Toon Claes suggests displaying merged branches as originating from the merge commit rather than their original branch point, reducing visual noise especially in octopus merges. Core changes in graph.c introduce a new `only_first_merge_base` flag and `ignored_merge_bases` list to modify column tracking and merge base calculation. New test file t4214-log-graph-octopus.sh demonstrates the behavior. Open questions include naming (`--untangle` vs alternatives like `--ignore-merge-base`), memory management of the ignored_merge_bases list, and edge case handling for complex merge scenarios. The motivation cites real-world readability issues in git.git's own history. This touches core graph drawing logic and would need careful review of corner cases before merging.
