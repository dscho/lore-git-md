Thread summary:

RFC proposal for a new `git log --graph --untangle` option (alternate name `--ignore-merge-base` under consideration) to simplify visualization of complex histories by suppressing ancestry lines, displaying merged branches as originating from merge commits rather than original branch points. Core changes in graph.c introduce `only_first_merge_base` flag and `ignored_merge_bases` list, with test coverage in t4214-log-graph-octopus.sh. Maintainer Junio C Hamano initially responded positively to the concept while requesting concrete visualization examples on complex histories like git.git's own graph.

Johannes Sixt (Hannes) raised substantive technical concerns about edge cases - questioning truncated links' historical accuracy, highlighting ambiguity in criss-cross merges and backward merges, and noting interaction issues with `--boundary`. Toon Claes has demonstrated before/after output from git.git's l10n merge history and now responds to Hannes' concerns with visualization alternatives for truncated history (proposing `/` markers or `+` symbols) and analysis of backward merge display challenges when merge bases aren't first parents.

The latest discussion focuses on visualization challenges for complex merge histories, particularly backward merges where the merge base isn't the first parent. Hannes argues the current approach leads to inconsistent visual representations when viewing subgraphs in isolation versus full history, creating potential confusion. He favors Toon's proposed '.' marker for truncated history but suggests adding commit references for context. The discussion identifies key unresolved issues: accurate representation of backward merges, subgraph consistency, and visual indication of truncated history.

Current implementation issues include memory leaks in `ignored_merge_bases`, incomplete handling of criss-cross merges and `--boundary` interactions, naming concerns, and now the newly highlighted backward merge visualization challenges. Open items include: finalizing visualization approach (markers vs symbols with possible commit references), resolving backward merge display logic, ensuring subgraph consistency, expanding test coverage with more complex histories, fixing memory leaks, and determining the final option name (`--untangle` vs `--ignore-merge-base`). The thread remains in RFC stage, needing more development to handle Git's full complexity before consideration for merging, with Toon inviting broader testing on real repositories.
