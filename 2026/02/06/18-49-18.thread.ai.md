Thread summary:

RFC proposal for a new `git log --graph --untangle` option (alternate name `--ignore-merge-base` under consideration) to simplify visualization of complex histories by suppressing ancestry lines, displaying merged branches as originating from merge commits rather than original branch points. Core changes in graph.c introduce `only_first_merge_base` flag and `ignored_merge_bases` list, with test coverage in t4214-log-graph-octopus.sh. Maintainer Junio C Hamano initially responded positively to the concept while requesting concrete visualization examples on complex histories like git.git's own graph.

Johannes Sixt (Hannes) raised substantive technical concerns about edge cases - questioning truncated links' historical accuracy, highlighting ambiguity in criss-cross merges and backward merges, and noting interaction issues with `--boundary`. Toon Claes has demonstrated before/after output from git.git's l10n merge history and now responds to Hannes' concerns with visualization alternatives for truncated history (proposing `/` markers or `+` symbols) and analysis of backward merge display challenges when merge bases aren't first parents.

Junio C Hamano now weighs in on the truncated history visualization debate, suggesting gitk's approach of using matching arrow markers and sequential identifiers (a-z, aa-az) to correlate disconnected graph segments. While acknowledging this may be more challenging in CLI output than gitk's GUI, his input moves the discussion toward more explicit labeling systems over Toon's simpler '.' marker proposal. The maintainer's feedback indicates visualization needs further refinement to balance historical accuracy with readability.

Current implementation issues include memory leaks in `ignored_merge_bases`, incomplete handling of criss-cross merges and `--boundary` interactions, naming concerns, and the backward merge challenges. Open items now include: finalizing visualization approach (with Junio's sequential identifiers proposal as a new option), resolving backward merge display logic, ensuring subgraph consistency, expanding test coverage with more complex histories, fixing memory leaks, and determining the final option name (`--untangle` vs `--ignore-merge-base`). The thread remains in RFC stage, with visualization design being the current focus before addressing remaining technical issues. Toon's invitation for broader testing on real repositories stands, now with Junio's specific visualization suggestions to consider in future iterations.
