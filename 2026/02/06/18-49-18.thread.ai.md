Thread summary:

RFC proposal for a new `git log --graph --untangle` option to simplify visualization of complex histories by suppressing ancestry lines, displaying merged branches as originating from merge commits rather than original branch points. Core changes in graph.c introduce `only_first_merge_base` flag and `ignored_merge_bases` list, with test coverage in t4214-log-graph-octopus.sh. Maintainer Junio C Hamano responds positively to the concept, requesting concrete visualization examples of the improvement on complex histories like git.git's own commit graph. He acknowledges the contributor's willingness to tackle graph drawing code and notes this aligns with his own long-standing interest in improving this area, though remains neutral on naming (`--untangle` vs `--ignore-merge-base`) and implementation specifics at this RFC stage. Open items include: demonstrating the visual benefit via requested example output, addressing known memory leaks in the `ignored_merge_bases` handling, and resolving edge cases in complex merge scenarios. The thread remains in discussion phase with maintainer encouragement for continued iteration, particularly around proving the visualization value proposition through concrete before/after comparisons.
