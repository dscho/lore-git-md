This is a bugfix for whitespace handling in Git's diff/apply machinery, specifically addressing incorrect behavior when checking symbolic links for incomplete-line endings (WS_INCOMPLETE_LINE). The patch comes from maintainer Junio C Hamano with technical review from Patrick Steinhardt.

The discussion has reached consensus on the implementation approach - the fix will disable WS_INCOMPLETE_LINE checks when the post-image side (accounting for `--reverse`) is a symlink. This properly handles text-to-symlink transitions where missing newlines in the post-image are expected behavior. The patch explicitly defers handling of theoretical edge cases like newline-terminated symlink targets, considering them not worth the implementation complexity.

Patrick Steinhardt confirms the approach is sensible in this follow-up email, though he raises a minor observation about whether readers could distinguish between symlinks with and without trailing newlines. This doesn't appear to be a blocking concern, just a clarification point about the theoretical limits of the solution. The core technical questions about mode-change handling and whitespace checking rules have been resolved between the participants.

The patch touches both `apply.c` and `diff.c` to implement these rules, with accompanying test cases in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh`. This represents the final refinement of a fix for behavior introduced by recent whitespace checking improvements, now ready for integration with no outstanding technical concerns.
