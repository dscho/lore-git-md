This is a bugfix addressing incorrect whitespace handling for symbolic links in Git's diff and apply machinery. The patch from maintainer Junio C Hamano, with review from Patrick Steinhardt, corrects a recent regression where whitespace checks (specifically the WS_INCOMPLITE_LINE check for missing newlines) were being applied to symlinks where such checks don't make sense.

The core issue stems from symlinks not requiring newline termination like regular text files do. The patch modifies both `apply.c` and `diff.c` to skip these checks when dealing with symlinks, with careful consideration for edge cases like text-to-symlink transitions. The implementation now disables checks when the post-image side (accounting for --reverse) is a symlink, though there's acknowledgment this may not cover all possible diff.wsErrorHighlight configurations.

The discussion reveals some interesting edge cases - like the theoretical possibility of newline-terminated symlink targets - but these are deliberately being left unaddressed as low priority. Test coverage has been added in `t4015-diff-whitespace.sh` and `t4124-apply-ws-rule.sh`.

This appears to be a well-considered fix from the maintainer for a clear regression, with appropriate attention to edge cases and test coverage. The change is focused and unlikely to be controversial, though it does touch core diff/apply machinery so careful review is warranted.
