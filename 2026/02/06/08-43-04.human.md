This is a security-related follow-up in the ongoing discussion about `git am` applying diffs embedded in commit messages. Kristoffer Haugsbakk points to prior related discussions about how `git am` identifies patch content, noting that proper indentation of code blocks (a stylistic choice) can prevent accidental patch application. 

The thread has established that the current behavior is unintentional and potentially dangerous, as demonstrated by a real-world case where a `sleep(1)` call was accidentally introduced into a Debian package via a commit message diff. While some initially questioned whether this constitutes a true security risk, consensus is building that it could be exploited maliciously.

Haugsbakk's contribution connects this issue to existing documentation about patch delimiters and code block formatting, suggesting that proper indentation (already a stylistic recommendation) could serve as a workaround. The discussion remains active, with security-conscious contributors like Jeff King likely to weigh in on any proposed fixes. The tension between backward compatibility and security remains unresolved, but the real-world impact gives this issue urgency.
