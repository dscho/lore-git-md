HTTP authentication testing clarification from Jeff King

This is a follow-up discussion about the HTTP authentication test series, specifically addressing Junio Hamano's questions about how .netrc credential handling interacts with HTTP status codes.

Jeff King explains that the tests are actually verifying curl's built-in .netrc behavior rather than Git's credential helper system. He walks through each test case to show how curl handles the authentication internally:

1. For successful clones, curl silently uses .netrc credentials and Git only gets a 200 response
2. For 401 responses with invalid .netrc credentials, Git still prompts for credentials normally
3. For 403 responses, curl handles the rejection internally and Git sees only the final error

The key insight is that these tests primarily verify that Git properly enables curl's .netrc support, not any novel Git behavior. While useful for coverage, they don't test Git's credential helper system at all. Jeff notes this differs from real-world services like GitHub, which use 401+404 rather than 403 for access control.
