Security issue in `git am` where it applies diffs from commit messages. Reporter Matthias Beyer found this through a real-world incident where a `sleep(1)` call was accidentally introduced into a Debian package (i3 window manager) via a diff in a commit message. The current behavior is dangerous as it could be exploited to hide malicious changes in what appears to be an innocent commit message. No patch provided yet, but this needs addressing - likely by modifying `git am` to ignore or warn about diffs in commit messages. Security-conscious contributors like Jeff King (Peff) would be key reviewers for any fix. The real-world impact (Debian package incident) gives this issue urgency.
