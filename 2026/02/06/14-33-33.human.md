This is a refactoring patch in the ongoing ref backend selection series, which enables switching between files and reftable backends for reference storage. The patch extracts the logic for creating stub reference directories into a helper function, `refs_create_refdir_stubs()`, to maintain compatibility when using non-files backends.

Patrick Steinhardt points out three minor issues in Karthik Nayak's patch: a typo ("object/" should be "objects/"), inconsistent capitalization ("git" should be "Git"), and an unclear variable name ("refs_heads_msg" should more accurately reflect that it contains the content for the HEAD file rather than being a message). These are straightforward fixes that don't affect the core functionality.

The patch is part of a mature series that has already addressed more substantive technical challenges around reference backend selection and migration. This particular change is a clean refactoring that improves code organization while supporting the larger goal of making reference storage backends configurable. The review feedback is focused on polishing details rather than raising architectural concerns.
