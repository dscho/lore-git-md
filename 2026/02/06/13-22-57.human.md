This is the second patch in a 5-part series that aligns `git add`'s behavior with `git status` and `git diff` when handling submodules configured with `ignore=all`. The patch introduces the core logic to skip such submodules during `git add` operations unless explicitly forced with `--force`.

The change makes `git add` skip submodules marked with `ignore=all` by default, printing an advice message suggesting `--force` if the user really wants to add them. This matches the existing behavior for ignored files and provides consistency across Git commands. The implementation carefully preserves backward compatibility while adding the new behavior.

The patch adds a comprehensive `skip_submodule()` helper function that:
- Verifies path and submodule configuration
- Checks pathspec matching
- Handles the `--force` flag
- Provides appropriate user feedback

The motivation is to better support workflows where submodules are used as loosely-coupled dependencies (like Google's repo tool), where users want to track branches rather than specific commits. The change reduces friction when working with such submodules while still allowing explicit SHA-1 tracking when desired.
