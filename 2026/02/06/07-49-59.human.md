This is a memory management cleanup patch in the bisect subsystem, part of Patrick Steinhardt's series fixing ref iteration bugs. The patch simplifies how string allocations are handled when cleaning up bisect state.

Jeff King noticed that the code was using an unnecessarily convoluted pattern for managing string memory - initializing the string_list with NODUP but then manually allocating strings and later enabling strdup_strings just for cleanup. Since a previous commit simplified the string generation to use plain xstrdup(), the patch now initializes the string_list with DUP from the start, letting the string_list handle all memory management automatically.

The change is straightforward and improves code clarity while maintaining identical functionality. It's a small but thoughtful improvement that follows naturally from the earlier refactoring in this series. The patch has already been reviewed by Jeff King (who originally wrote the improvement) and Patrick Steinhardt (who incorporated it into his series), suggesting it's ready for inclusion.
