This is the second patch in a two-part series adding sparse-index support to the `merge-ours` strategy, part of the ongoing sparse-checkout/sparse-index optimization effort. The patch follows a refactoring in patch 1 that removed `the_repository` global usage.

The change makes `merge-ours` properly respect sparse-checkout settings by initializing the sparse-checkout globals via `repo_config()`. Previously these remained unset when invoked as a subprocess by `git merge -s ours`, causing unnecessary expansion of the sparse index. The patch also explicitly opts out of full index requirements by setting `command_requires_full_index = 0`.

The 14-line test addition in t1092 verifies that `merge -s ours` behaves identically across full-checkout, sparse-checkout, and sparse-index modes, and confirms the sparse index isn't expanded during the operation. The test checks both the resulting merge commit structure and tree state.

The changes are straightforward - 6 lines modifying `builtin/merge-ours.c` to add config reading and index settings, following established patterns seen in other commands' sparse-index integrations. The patch appears well-contained and properly motivated, with clear test coverage for the new behavior. This continues the broader effort to make Git operations more efficient in sparse-checkout contexts.
