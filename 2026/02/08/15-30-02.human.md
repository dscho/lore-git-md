This is a feature proposal to allow UTF-8 characters in Git alias names, currently restricted to ASCII alphanumerics and hyphens. Jonatan Holmgren suggests modifying `git_config_parse_key()` to specifically permit UTF-8 in `alias.*` keys while keeping other config validation strict, with case-sensitivity for non-ASCII aliases to avoid locale-dependent case folding complexities.

The proposal is well-framed with clear examples (Swedish "förgrena", Chinese "分支") and identifies the technical constraints (current `iskeychar()` validation, platform Unicode normalization differences). It directly asks for feedback on desirability, approach, and potential pitfalls before implementation.

The change would primarily benefit non-English users wanting more natural alias names. The technical impact appears contained to config parsing, but platform Unicode handling (particularly macOS's NFD normalization) could introduce subtle compatibility issues. The RFC format suggests the author is seeking design consensus before coding, a good practice for a change touching core config parsing.
