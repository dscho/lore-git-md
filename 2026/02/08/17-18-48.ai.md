This is a documentation patch adding warnings about patch roundtrip hazards, now queued by Junio Hamano as part of the ongoing security-focused improvements to `git am` parsing behavior. Kristoffer Haugsbakk's patch supplements Phillip Wood's earlier technical solution by explicitly documenting the risks of embedded diffs and separator lines in commit messages when using `git format-patch` and `git am`.

The documentation warns about specific hazardous patterns (unindented diffs, three-dash separator lines) and provides real-world examples of incidents where these caused problems (notably the Debian i3 window manager case where a `sleep(1)` was accidentally introduced). The warnings appear in multiple man pages (`git-format-patch`, `git-send-email`, and `git-am`) to ensure visibility across the patch workflow.

Haugsbakk's email also reveals some tension in the documentation approach - Junio pushed back on the verbose attribution notes in the commit message, seeing them as unnecessary for readers, while Haugsbakk defends them as important context for those being credited. This minor stylistic disagreement doesn't affect the technical content of the queued documentation patch itself.

The patch represents the documentation component of a layered security solution that also includes Wood's enhanced commit-msg hook detection and multiple bypass mechanisms. Together these address the long-standing issue of reliably distinguishing intended patches from embedded diffs in commit messages when processing email streams.
