This is a documentation patch that adds warnings about potential pitfalls when roundtripping patches through `git format-patch` and `git am`. The patch, submitted by Kristoffer Haugsbakk, addresses a known security vulnerability where unindented diffs or separator lines ("---") in commit messages can cause `git am` to incorrectly parse and apply unintended changes.

The patch updates the man pages for `git-format-patch`, `git-send-email`, and `git-am` to explicitly warn users that these delimiters in commit messages can lead to unexpected behavior. It notes that while the commands will accept any commit message without warning, the presence of unindented diffs can cause `git am` to apply both the intended patch and the diff from the commit message itself.

Junio Hamano has queued the patch, noting that the current behavior (where lines matching "^diff " mark the end of the log message) can lead to unhappy outcomes when multiple diffs are present. The documentation serves as an important warning while the technical solutions (like Phillip Wood's enhanced commit-msg hook) continue to be developed.

This is part of an ongoing thread about patch parsing security vulnerabilities, with multiple real-world incidents reported (including one affecting the i3 window manager project). The documentation patch complements technical mitigations by making the risks more visible to users.
