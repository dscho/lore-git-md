This is a technical follow-up in the ongoing `the_repository` removal effort, specifically regarding performance considerations for attribute reading.

Tian Yuchen asks Junio C Hamano to elaborate on the performance characteristics of `read_attr()`, which was mentioned as "not that hot but not cheap" in the context of modifying it to use per-repository state instead of the global `the_repository`. The question comes after Junio suggested caching bareness state in the repository object to optimize the change.

The exchange shows the careful consideration being given to performance implications even for non-critical paths, as part of the broader architectural effort to eliminate global state. This follows earlier benchmarking by Tian showing no measurable impact from the initial changes, suggesting the discussion is now focusing on longer-term design decisions rather than immediate performance concerns.

The thread remains in RFC state while these architectural questions are resolved, with Junio's guidance pointing toward a more systematic solution that would involve caching repository state and potentially refactoring `is_bare_repository()` itself.
