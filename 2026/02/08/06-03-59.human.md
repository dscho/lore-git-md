Bugfix for the fsmonitor-watchman hook addressing error handling and protocol compliance issues. This is a straightforward fix for two specific problems in the watchman integration:

1. The hook was incorrectly checking `$o->{error}` instead of `$output->{error}` in watchman_clock(), causing error conditions to be silently swallowed rather than properly reported. This could mask real problems in the watchman integration.

2. The hook was violating Git's fsmonitor v2 protocol by outputting two clock tokens when falling back to a full scan (due to a recursive call to launch_watchman()). The protocol requires exactly one token in this case.

The patch modifies both the sample hook implementation and test helper scripts in t/t7519/. The changes maintain backward compatibility while fixing these issues.
