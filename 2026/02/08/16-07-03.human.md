This is a reply in an RFC thread about allowing UTF-8 characters in Git alias names. D. Ben Knoble responds to Jonatan Holmgren's initial proposal with technical context about Git's ASCII-only config key parsing.

Knoble notes that Git's ctype handling is intentionally ASCII-specific (dating back to a 2005 change) and would require more complex logic to properly handle UTF-8. He points to historical discussion suggesting UTF-8 config parsing would need careful implementation. While expressing personal support for internationalization in user-facing features, he distinguishes this from cases like git-apply's diff headers which must remain ASCII.

The reply provides useful historical context about Git's character handling but doesn't take a strong position on the proposal itself. It surfaces implementation challenges (locale handling, UTF-8 parsing) that would need to be addressed if the feature moves forward. The tone is constructive, focusing on technical constraints rather than outright opposition.
