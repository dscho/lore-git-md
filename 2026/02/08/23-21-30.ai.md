This is a response in an ongoing discussion about allowing UTF-8 characters in Git alias names, which currently only support ASCII. The thread has established that the technical implementation would require careful handling of Unicode normalization and case sensitivity.

brian m. carlson responds to Jonatan Holmgren's RFC, generally supporting the internationalization goal while flagging technical considerations. They agree that case folding should be avoided for non-ASCII aliases, noting this aligns with Git's existing mailmap behavior. The response highlights that command-line arguments would pass UTF-8 bytes unnormalized, but points out Git currently lacks Unicode normalization infrastructure - suggesting this might need to be added for a robust implementation.

Key technical points raised:
- Platform-specific Unicode normalization (macOS NFD vs others' NFC) could cause subtle issues
- Case sensitivity should be preserved for non-ASCII aliases to avoid locale-dependent folding
- The implementation would need to handle raw UTF-8 bytes without normalization unless new normalization code is added

The response doesn't take a position on whether the alias-specific approach is ideal, but does express general support for better i18n/l10n features while noting they wouldn't personally use this capability. The reply leaves open whether Unicode normalization should be considered a prerequisite or nice-to-have for the feature.
