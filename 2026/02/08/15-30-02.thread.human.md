This RFC thread explores allowing non-ASCII characters in Git alias names, which currently only support ASCII alphanumerics and hyphens. Jonatan Holmgren initiated the discussion with examples of Swedish and Chinese aliases that would improve accessibility for non-English speakers. Initial responses from D. Ben Knoble and brian m. carlson highlighted technical constraints around Git's ASCII-centric config parsing and Unicode normalization challenges.

Jeff King (Peff) has now shifted the conversation with a more comprehensive proposal. Rather than just enabling UTF-8 in aliases, he suggests redesigning the alias config schema to use three-level keys (e.g., `alias.foo.command`), which would solve multiple issues at once. This approach would handle arbitrary command names verbatim, avoiding Unicode normalization complexities while maintaining backward compatibility. Peff's solution also opens doors for future features like help text for aliases.

The thread now faces a key design decision: whether to pursue targeted UTF-8 support (simpler but limited) or Peff's more ambitious config schema overhaul (broader impact but more implementation work). Technical considerations around case sensitivity, platform-specific Unicode handling, and Git's existing config parsing infrastructure remain central to the discussion. While participants agree on the internationalization goals, the path forward depends on whether the project wants to tackle Unicode normalization or work around it through schema design.
