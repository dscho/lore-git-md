This thread explores whether to allow UTF-8 characters in Git alias names, which currently only accept ASCII. Jonatan Holmgren originally proposed the change to better support non-English users, but the discussion has broadened to consider both technical implementation and security implications.

Key participants have offered different approaches: Jeff King (Peff) suggested a three-level config syntax (like `alias.förgrena.command`) that would avoid Unicode handling by treating commands as literal byte streams, while Theodore Tso raised security concerns based on ext4's experience with Unicode normalization vulnerabilities. Maintainer Junio Hamano has expressed cautious openness to UTF-8 aliases but emphasized preferring robust solutions that minimize new code paths.

In the latest email, Jonatan responds to Junio's concerns by suggesting Peff's subsection approach could leverage Git's existing macOS normalization handling through `precompose_argv_prefix()`, potentially providing UTF-8 support without introducing new Unicode infrastructure. This appears to align with Junio's preference for solutions that build on existing, well-tested components rather than adding complex new Unicode handling.

The thread now seems to be converging toward either extending the current syntax with careful Unicode handling (following macOS's lead) or adopting Peff's more structural change to the config format. Junio's maintainer perspective and Tso's security input weigh heavily against solutions that would require Git to implement its own Unicode normalization, making the subsection approach increasingly attractive as it sidesteps those concerns while still addressing the original internationalization need.
