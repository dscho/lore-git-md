Jonatan Holmgren proposed allowing UTF-8 characters in Git alias names (currently restricted to ASCII), motivated by making Git more accessible to non-English speakers. The initial RFC suggested modifying config.c to relax restrictions specifically for alias.* keys while maintaining ASCII requirements elsewhere, with careful handling of Unicode normalization differences across platforms.

D. Ben Knoble responded with technical context about Git's current ASCII-only validation, noting it uses Git's own ctype implementation rather than locale-aware functions. He pointed to historical discussions about UTF-8 parsing complexity while expressing general support for internationalizing user-facing features. The reply highlighted two implementation challenges: adapting Git's character classification and handling platform-specific Unicode normalization. The core questions remain open - whether this feature is desirable, if the alias-specific approach is right, and how to address the technical constraints. The discussion is still in early stages with no clear consensus yet formed.
