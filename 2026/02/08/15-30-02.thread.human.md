This thread concerns the implementation of UTF-8 support for Git configuration subsections (like `[alias "förgrena"]`), now in the `next` branch as version 7. The core functionality is working well, with Jonatan Holmgren as the primary author and reviews from Jeff King, Junio Hamano, and Torsten Bögershausen. 

The latest patch addresses a documentation formatting issue where list continuation markers were missing in the alias configuration examples, causing rendering problems. Kristoffer Haugsbakk confirmed this fix should replace an earlier attempt (0ed2275f), and Junio Hamano has indicated he will apply this version instead. This leaves just one remaining documentation issue - visible `+` markers in HTML output - from the original set of follow-up polish items.

However, there remains one serious regression affecting real-world usage: aliases with leading dots (like `.foobar`) currently fail. Patrick Steinhardt identified this issue and provided a test case, noting it impacts Johannes Schindelin's workflow. The team needs to decide whether to fix this regression or document it as a behavior change. Other resolved issues include empty subsection compatibility and most documentation clarity items, with space handling in alias names now confirmed to work as designed.
