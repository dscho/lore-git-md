[PATCH] git clone --revision segfault with v0/v1 protocols

Thread discusses a segfault when using `git clone --revision` with older protocol versions (v0/v1). Core issue is that `.peer_ref` remains unset in this case, causing the crash. Original fix attempt would mask the underlying problem.

Junio identifies the root cause: `update_remote_refs()` assumes `.peer_ref` is set but this isn't true for `--revision` clones with older protocols. Suggests restructuring to split out needed functionality and make the call conditional. Author Jayce Cao agrees and seeks clarification on whether `find_ref_by_name()` should also be conditional since `--revision` detaches HEAD.

Key technical details:
- Bug manifests in protocol versions prior to v2
- `update_remote_refs()` makes invalid assumption about `.peer_ref` initialization
- `--revision` clones inherently detach HEAD after checkout

Open questions:
- Should `find_ref_by_name()` be made conditional as well?
- Need to add regression tests once fix approach finalized

- Jayce Cao (author): implementing fix, seeking clarification

Related: Protocol v2 handles this case correctly; issue is specific to v0/v1 implementations.
