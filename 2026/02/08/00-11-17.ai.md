Documentation patch adding warnings about patch roundtrip hazards in the email workflow. Kristoffer Haugsbakk follows up on the ongoing security discussion about `git am`'s vulnerability to embedded diffs in commit messages by adding explicit documentation warnings.

The patch creates a new `format-patch-caveats.adoc` file and includes it in the man pages for `git-format-patch`, `git-send-email`, and `git-am`. The warnings explain how certain commit message patterns (three-dash lines, unindented diffs) can cause `git am` to misinterpret the message or incorrectly apply embedded diffs. It provides concrete examples of problematic patterns and suggests workarounds (indenting diffs), while noting that even indented diffs may still cause issues with `patch(1)`.

This is part of the layered defense strategy emerging from the thread, complementing Phillip Wood's security-focused commit-msg hook by adding user education. The documentation maintains a neutral tone, presenting the limitations as inherent to the email patch format rather than as bugs, while still making the risks clear. The patch references multiple real-world reports of the issue affecting projects.
