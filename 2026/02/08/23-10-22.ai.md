This is an update in the ongoing SHA-1/SHA-256 interoperability effort, part of the Rustification work in Git. Brian m. carlson responds to Junio C Hamano's query about CI breakages in their patch series that introduces Rust-based object mapping between different hash algorithms. The series (previously at v2) adds infrastructure for maintaining object name mappings across hash functions, with components like a Rust wrapper for hashfile code, new binary object map format, and hash algorithm abstractions.

The key development here is that carlson has sent v3 of the series which resolves the CI failures mentioned in Junio's "What's cooking" report. This continues the multi-year effort to enable repositories using different hash algorithms (SHA-1 and SHA-256) to interoperate, with Rust playing an increasing role in Git's object storage layer. The work touches core areas like object-file conversion, hash computation, and repository initialization while introducing new components like a Rust-based object ID abstraction.

This thread shows the practical challenges of integrating Rust into Git's CI pipeline, a recurring theme in the Rustification effort. The series remains active in Junio's integration branches, indicating it's on track for eventual merging despite the platform compatibility concerns that have characterized this long-running interoperability work.
