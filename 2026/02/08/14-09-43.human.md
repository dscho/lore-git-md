This is a bugfix patch addressing a segfault in `git clone` when using the `--revision` option with the older v0/v1 protocol versions. The issue arises when the code tries to access `.peer_ref` without proper null checks during reference updates.

The patch follows up on Junio Hamano's feedback from the initial version, where he suggested a more robust fix than simply avoiding the segfault. The proposed solution involves restructuring the code to properly handle the `--revision` case by splitting out necessary functionality from `update_remote_refs()` and making the call conditional.

The author acknowledges Junio's points about wanting the code to fail visibly when invariants are violated, rather than silently working around issues. They also note the need to add tests to verify both the crash fix and the expected repository state (detached HEAD at specified revision with no other refs).

This appears to be a well-motivated fix for a real issue, though the implementation details are still being worked out based on maintainer feedback. The discussion shows good engagement with the technical concerns raised.
