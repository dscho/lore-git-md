Thread identity: RFC proposal to allow UTF-8 characters in Git alias names (currently restricted to ASCII alphanumerics and hyphens), authored by Jonatan Holmgren, with initial technical response from D. Ben Knoble.

Core problem: Git's config key parsing (git_config_parse_key() in config.c) enforces ASCII-only names for all config keys, including aliases, preventing non-English speakers from creating aliases in their native scripts. The discussion now includes technical constraints around modifying Git's character classification system.

Technical details: The change would modify config.c to allow UTF-8 in alias.* keys while maintaining ASCII restrictions for other config keys. Key implementation challenges identified:
- Git's custom ASCII-specific ctype handling (iskeychar() using sane-ctype.h) would need UTF-8 awareness
- Case-sensitivity handling for non-ASCII aliases must avoid locale-dependent folding
- Platform-specific Unicode normalization differences (macOS NFD vs NFC) require consideration
- Historical context (2005 discussion) suggests UTF-8 parsing would need careful implementation

Open questions:
- Is the feature desirable given the implementation complexity?
- Is the alias-specific approach the right scope, or should other config keys be considered?
- How to handle platform Unicode normalization differences in practice?
- What modifications to Git's ctype handling would be required?

Participant positions:
- Jonatan Holmgren: Original proposal with examples (Swedish "förgrena", Chinese "分支")
- D. Ben Knoble: Supportive of internationalization goals but flags technical constraints with Git's ctype implementation and platform normalization differences. Does not take position on alias-specific scope.

Related work: Builds on existing config parsing infrastructure. Historical 2005 discussion about UTF-8 config parsing noted as relevant context. No direct connection to other current efforts like ODB abstraction or reftable work.
