This is a documentation patch adding warnings about potential pitfalls when roundtripping commits through `git format-patch`/`git send-email`/`git am`. The patch follows up on recent security discussions about how these commands handle delimiters and embedded diffs in commit messages.

Kristoffer Haugsbakk proposes adding a new `format-patch-caveats.adoc` file that documents several issues: three-dash lines (`---`) in commit messages being misinterpreted as patch separators, unindented diffs in commit messages being accidentally applied, and the general loss of fidelity when roundtripping patches. The documentation explains these edge cases with examples and suggests workarounds like indenting problematic content. The patch links this new documentation from the man pages of all three commands (`git-am`, `git-format-patch`, and `git-send-email`).

This builds on prior discussions about security vulnerabilities in patch parsing, particularly the recent Debian incident where an unindented diff in a commit message was accidentally applied. While Phillip Wood's earlier security-focused commit-msg hook addressed runtime detection of these issues, this patch provides the complementary documentation to help users understand and avoid the pitfalls proactively.

The documentation is thorough and well-structured, with clear examples and cross-references. It strikes a good balance between warning about the risks while acknowledging legitimate uses of these patterns (like Junio Hamano's workflow that relies on three-dash lines). The patch has already collected Reported-by tags from several people who encountered these issues, indicating it addresses real-world pain points.
