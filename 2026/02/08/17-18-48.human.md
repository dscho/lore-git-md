This is a documentation patch adding warnings about patch roundtrip hazards in Git's email-based workflow. Kristoffer Haugsbakk follows up on Junio Hamano's feedback about the formatting of historical context notes in the commit message.

The patch is part of an ongoing thread addressing a security vulnerability where `git am` can misinterpret diffs embedded in commit messages as actual patches to apply. The documentation changes (already queued by Junio) explicitly warn users about dangerous patterns like unindented diffs and separator lines ("---") that could trigger parser confusion, with examples from real-world incidents.

Haugsbakk defends his inclusion of detailed historical context (listing past reporters of related issues) as necessary attribution, though acknowledges the formatting could be more concise. The exchange shows the project's careful balance between thorough documentation and keeping commit messages focused - a tension common when addressing security issues with long histories.

This is the documentation component of a multi-pronged solution that also includes Phillip Wood's enhanced commit-msg hook for detecting dangerous patterns. The layered approach combines technical prevention with user education about the email format's constraints.
