Maintainer feedback on `the_repository` removal in worktree status functions.

Junio Hamano responds to Shreyansh Paliwal's v3 patch converting `wt-status.c` functions to take explicit `struct repository *` parameters instead of using `the_repository`. While the mechanical conversion is correct, Junio questions the design approach for worktree-related functions in particular.

The key concern is that functions like `wt_status_check_rebase()` and `wt_status_check_bisect()` are being modified to take both a worktree and repository parameter, when the worktree structure already contains its owning repository (`wt->repo`). Junio suggests this may create API confusion by allowing potentially mismatched repository/worktree pairs when the worktree's own repository could be used directly.

Junio also notes formatting issues in the patch (inconsistent indentation in the function declarations). His feedback indicates that while the global variable removal is conceptually sound, the worktree-related changes in this series need reconsideration of parameter passing design before proceeding. The core `the_repository` elimination in non-worktree contexts remains uncontested.

This maintains the thread's focus on API design philosophy rather than implementation correctness - the question is whether passing both parameters is actually an improvement over using `wt->repo`, not whether the technical conversion works. The response suggests v4 should either justify the dual parameters or restructure to use the worktree's embedded repository.
