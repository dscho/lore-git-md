This thread discusses a code cleanup patch from René Scharfe that modernizes part of Git's commit-graph traversal code. The patch replaces manual array management in the `rev_collect` struct with the existing `commit_stack` utility structure, making the code more maintainable while preserving identical behavior. The changes are focused on `commit.c`, specifically touching the fork-point calculation used by commands like `git rebase --fork-point`.

René's patch follows his characteristic style - a precise, no-nonsense improvement to code hygiene that doesn't change functionality. The modification replaces direct array manipulation with the `commit_stack` API's push/init/access methods, updates the loop counter type to match, and lets `commit_stack_clear` handle memory management. This is part of Git's ongoing effort to eliminate manual memory management patterns in favor of reusable utility structures.
