Documentation patch adding warnings about patch roundtrip hazards in `git format-patch`/`git am` workflows.

Kristoffer Haugsbakk's patch adds explicit documentation warnings about the `git format-patch`/`git am` roundtrip hazards where delimiters (like "---" lines or unindented diffs) in commit messages can cause unexpected behavior. The patch updates `format-patch-caveats.adoc` to be included in the `git-format-patch`, `git-send-email`, and `git-am` man pages, explaining that these delimiters can truncate commit messages or cause unintended patch applications.

The documentation notes that while `git-format-patch` and `git-send-email` will silently accept these problematic patterns, `git-am` may misinterpret them, applying diffs from the commit message body along with the intended patch. It references real-world incidents (including a Debian i3 window manager case) where this caused issues, while acknowledging some workflows legitimately use separator lines for metadata below the scissors line.

Junio Hamano points out that the patch could be more precise about the exact parsing behavior (multiple diffs may be applied or rejected), but queues it as a useful warning. The documentation serves as an important user education component alongside Phillip Wood's technical mitigations (commit-msg hook enhancements) in addressing this long-standing security/parsing issue.
