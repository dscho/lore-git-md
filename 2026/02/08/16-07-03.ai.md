Feature proposal discussion about UTF-8 in Git alias names, with technical constraints noted.

D. Ben Knoble responds to Jonatan Holmgren's RFC about allowing UTF-8 characters in Git alias names, providing additional technical context about the current ASCII-only restrictions. The reply digs into Git's ctype handling, noting that the iskeychar() validation in config.c uses Git's own ASCII-specific character classification (from sane-ctype.h) rather than locale-aware system functions. Knoble points to historical discussion (2005 thread) suggesting UTF-8 config parsing would require more complex logic, and shares a personal opinion that user-facing parts of Git should support internationalization while acknowledging some technical constraints may remain for internal parsing.

The email highlights two key technical constraints: Git's custom ctype implementation that would need modification, and the potential need to handle UTF-8 normalization differences across platforms (particularly macOS's NFD vs NFC). Knoble's response is supportive of the general direction while flagging these implementation challenges, but does not take a position on whether the alias-specific approach proposed in the RFC is the right scope. The thread remains open for further discussion about both the desirability of the feature and the technical approach.
