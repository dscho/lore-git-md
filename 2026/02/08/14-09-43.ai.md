This is a bugfix discussion thread about a segfault in `git clone` when using the `--revision` flag with the older v0/v1 protocols. The thread follows up on an earlier patch attempt to fix the issue.

The maintainer (Junio) points out that the original fix would mask a deeper issue where `.peer_ref` should be set but isn't. He suggests restructuring the code to properly handle the `--revision` case by splitting out necessary functionality from `update_remote_refs()` and making its call conditional. The author (Jayce Cao) agrees with this approach and asks for clarification on whether they should also make `find_ref_by_name()` conditional, since `--revision` detaches HEAD anyway.

The discussion reveals this is a protocol version-specific edge case where the older protocols don't properly initialize refs when cloning with `--revision`. The author plans to add tests once the correct fix approach is settled. This appears to be a genuine bug that needs careful handling to avoid masking other potential issues while fixing the immediate segfault.
