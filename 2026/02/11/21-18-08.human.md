This is the first of three patches in a series implementing UTF-8 support for Git configuration subsections, specifically for aliases. The series has gone through several iterations with input from key contributors like Jeff King and Junio Hamano.

The current patch is a refactoring step that consolidates alias listing logic between `alias.c` and `help.c`. It moves the responsibility for handling alias values into `alias.c` by extending `list_aliases()` to store values via the string_list util field, rather than having `help.c` implement its own callback. The change preserves existing error checking for value-less aliases but moves it to `alias.c`.

The patch includes a new test case verifying that aliases without values are properly reported as errors. This is part of addressing feedback from earlier versions of the series. The changes are cleanly separated from the main UTF-8 functionality that will come in later patches, following Git's convention of separating refactoring from feature work.

The implementation looks solid, with thorough test coverage and careful attention to maintaining backward compatibility. The patch has already received positive feedback from Jeff King and Junio Hamano in previous iterations, suggesting it's ready for merging.
