This is the first patch in the final v4 series implementing UTF-8 support for Git configuration subsections, specifically focusing on alias definitions. The patch refactors the alias listing logic to consolidate duplicate code between `alias.c` and `help.c`.

The key change moves the alias value parsing fully into `alias.c` by having `list_aliases()` store the alias values via the string_list util field, replacing the separate `get_alias()` callback in `help.c`. This maintains the existing error checking for value-less alias definitions but now does it in `alias.c` rather than `help.c`. Junio Hamano notes this actually fixes a subtle bug where "git --list-cmds=alias" previously included broken (value-less) aliases but now properly rejects them.

The patch includes test coverage for the error case and preserves all existing functionality while cleaning up the implementation. This is a preparatory refactoring that enables the subsequent patches in the series to add UTF-8 subsection support more cleanly. The changes have been reviewed by both Jonatan Holmgren (the author) and Junio Hamano, with Junio explicitly approving the approach and calling the bugfix intentional.

Technical details include:
- New NULL value handling via `config_error_nonbool()`
- Consolidated alias listing between `alias.c` and `help.c`
- Uses string_list` util field for alias values
- Preserves error checking while eliminating duplicate logic
- Adds test case for value-less alias error case
- Part of larger UTF-8 subsection support effort but focused on internal refactoring

The patch is now merge-ready as part of the v4 series that has received maintainer approval, with all feedback from previous iterations addressed.
