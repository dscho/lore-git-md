This thread addresses a bug in Git's diffcore-break machinery that causes segmentation faults in partially cloned repositories (specifically blobless clones using `--filter=blob:none`). First-time contributor Han Young from Bytedance identified that `diffcore_break()` was freeing a file pair without NULLing the queue pointer, which could crash during operations like `git reset` when working with prefetched blobs, particularly large YAML files.

The initial version of the patch was reviewed by Junio C Hamano, who requested two additions: a Signed-off-by line (to satisfy the Developer Certificate of Origin requirement) and a test case demonstrating the fault. The v2 patch submitted includes both - the one-line fix to properly NULL the pointer in diffcore-break.c, plus a test that reproduces the crash scenario in a blobless clone context.

This appears to be the second such issue found in the diff machinery since December 2025 (similar to commit 56d388e6), suggesting there may be more patterns like this to audit.
