Performance improvement for `git config list --type` filtering. This is the final patch in Derrick Stolee's series to optimize type-based filtering in `git config list`, addressing a bottleneck found in git-credential-manager. The patch makes `--type=<X>` actually filter config values by type during parsing rather than ignoring the option.

Patrick Steinhardt reviews the change and generally agrees with the approach, though he raises a minor consideration about whether to preserve the old output format when no type is specified. The key behavior change is that invalid values for the requested type will now be silently skipped rather than shown as strings - a design decision that has been debated in the thread but which both Patrick and Derrick find reasonable.

The patch touches the same files as previous iterations (`builtin/config.c`, `config.c`, documentation) and adds test coverage. Patrick's feedback suggests the implementation is nearly ready, with only minor formatting questions remaining before the series could progress. This continues the productive discussion between Derrick, Patrick, and Junio about how to balance performance with Git's string-based config philosophy.
