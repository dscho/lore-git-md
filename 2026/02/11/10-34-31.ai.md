This is part 5 of Patrick Steinhardt's 7-patch series improving CI test infrastructure reliability, specifically addressing test slicing behavior in Meson builds. The patch standardizes test slicing to use one-based numbering consistently between Make and Meson builds, fixing an inconsistency where the Meson test runner was using zero-based indexing while the Make version used one-based. 

The change modifies both the GitHub workflow configuration (`.github/workflows/main.yml`) to adjust the slice number calculation and the Meson test slicing script (`ci/run-test-slice-meson.sh`) to remove the previous `+1` offset. This ensures test execution behaves the same way regardless of which build system is used. The patch notes that GitLab CI doesn't yet use this script but will be updated in a subsequent commit.

This is a straightforward mechanical change that completes the test slicing standardization work started in previous patches. The implementation is clean and focused, with corresponding updates to both the workflow definition and execution script. As part of the broader CI reliability effort, this helps eliminate a subtle source of potential confusion when comparing test results across different build systems.
