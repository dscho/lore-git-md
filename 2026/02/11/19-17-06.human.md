This is a documentation patch from Git maintainer Junio Hamano that formalizes the use of "NEEDSWORK" comments in the Git codebase. The patch adds a new section to the CodingGuidelines document explaining that these comments serve as placeholders for potential future work, emphasizing that the first step in addressing them is evaluating whether the proposed change actually makes sense.

The patch clarifies that NEEDSWORK comments are intentionally non-binding - they may be resolved either by implementing the suggested work or by removing the comment with justification for why the work isn't needed. This codifies existing informal practice in the project, where such comments are commonly used to mark areas that might benefit from future attention without committing to any particular solution.

As a documentation update from the maintainer, this patch carries clear authority and will likely be merged without controversy. It provides useful guidance for both new contributors (who may encounter these comments) and experienced developers (who add them). The change is small, focused, and well-explained in the commit message.
