This is the final patch in a performance-focused refactoring series that makes `git config list --type=<X>` actually filter values by type, rather than just parsing them after collecting all results. The change fixes what the author frames as broken behavior where the --type flag was previously ignored during listing.

The patch implements the core functionality after the preparatory refactoring in earlier patches. It modifies the config listing to filter values during parsing rather than after, which provides a performance boost by avoiding full parsing of non-matching values - particularly beneficial for path-type values. The implementation reuses the existing type-parsing infrastructure and maintains consistency with `git config get` behavior.

Patrick Steinhardt has reviewed the implementation and suggested only minor documentation tweaks remain, like updating the synopsis to better reflect the new behavior. The author confirms the implementation already handles the unfiltered case correctly. Test changes demonstrate how bool and path values are now properly normalized during filtered listing.

This appears to be a well-considered change that addresses a real performance bottleneck while maintaining backward compatibility. With the documentation polish Patrick suggested, it looks ready for inclusion. The series shows careful attention to both correctness and efficiency in a core command.
