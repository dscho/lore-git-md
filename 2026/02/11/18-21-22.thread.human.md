Tian Yuchen's security patch series to harden Git's repository discovery against malicious `.git` entries (like FIFOs and sockets) has reached v5, with Junio Hamano and Karthik Nayak providing detailed review feedback. The series refactors error handling in `setup.c` to validate `.git` file types while maintaining legitimate symlink support.

The current discussion focuses on Junio's latest review of patch 2/2, which handles symlink validation. Junio points out that the patch currently doesn't respect the `die_on_error` flag in all cases, changing the control flow from the original behavior where non-fatal errors would return `GIT_DIR_INVALID_GITFILE`. He emphasizes the need to maintain the existing contract where directory cases should trigger `is_git_directory()` checks and non-fatal errors should properly propagate when callers don't want immediate termination.

For v6, Tian plans to restructure the patches to:
1. Keep each patch in a working state (addressing Junio's concern about bisectability)
2. Only die in three specific cases (happy paths, security failures, explicit `die_on_error`)
3. Preserve backward-compatible behavior for other error cases
4. Maintain expected control flow in non-fatal scenarios (addressing Karthik's earlier concern)

The security hardening itself - rejecting dangerous `.git` entry types while allowing valid symlinks - remains uncontested. The discussion now centers on implementation details to ensure robust error handling that maintains compatibility with existing behavior. Once these edge cases are addressed, the series appears ready for merging.
