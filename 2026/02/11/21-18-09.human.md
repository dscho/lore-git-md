This is the second patch in a three-part series implementing UTF-8 support for Git configuration subsections, specifically focusing on aliases. The patch prepares for the new subsection syntax by tightening the alias parsing logic in `help.c`.

The key change replaces the permissive `skip_prefix()` approach with `parse_config_key()`, which properly handles the three-level config key structure needed for subsection support. This intentionally breaks backward compatibility with the undocumented behavior that previously allowed dotted alias names (like `alias.foo.bar`), as these were never officially supported.

The patch maintains the existing functionality for simple aliases while silently ignoring malformed dotted aliases (unless they use the new `command` key, which will be implemented in the next patch). This change is framed as fixing what was effectively a bug in the original implementation, since dotted aliases were never part of Git's documented behavior.

The implementation is clean and focused, touching only the alias parsing logic in `help.c` while preserving all other functionality. This is part of a well-structured series that has already gone through several rounds of review, with the current version addressing all previous feedback. The change appears ready for merging as part of the broader UTF-8 alias support effort.
