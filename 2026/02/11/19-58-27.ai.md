This is a CI/build system patch discussion about Meson dependency tracking for `config-list.h`.

D. Ben Knoble follows up on Patrick Steinhardt's earlier proposal for handling documentation changes in the Meson build system, specifically around regenerating `config-list.h` when config documentation files change. The core issue is that the current approach doesn't properly trigger rebuilds when documentation files are added or removed, only when existing files are modified.

Knoble reports some confusing build behavior where the dependency file (`config-list.h.d`) disappears after the initial build, making it hard to verify whether the system is correctly tracking changes. He observes that touching an existing config file does trigger a rebuild (executing 7 build steps), but adding a new file doesn't until after the first rebuild occurs. This matches Steinhardt's earlier explanation about depfiles only tracking existing files.

The discussion reveals subtle edge cases in Meson/Ninja's dependency handling - particularly around detecting new files and the ephemeral nature of depfiles. Knoble notes this caused practical issues during bisection where stale builds led to test failures. The thread demonstrates the careful attention the Git project gives to build system reliability, even for infrastructure components like generated headers. All participants (Knoble, Steinhardt, and Phillip Wood in earlier messages) are contributing specialized knowledge about Meson and Ninja's behavior to arrive at a robust solution.
