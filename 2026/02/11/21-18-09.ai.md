This is the second patch in a 3-part series implementing UTF-8 support for Git configuration subsections, specifically for aliases. The patch refactors the alias parsing logic in preparation for the new subsection syntax.

The key technical change replaces `skip_prefix()` with `parse_config_key()` in `help.c` to properly handle three-level config keys. This introduces a compatibility break by no longer accepting malformed "alias.<subsection>.<key>" entries unless the key is "command" (which will be used in the next patch). The change makes the parser stricter and more correct, treating dotted alias names as invalid rather than silently accepting them.

The patch maintains all existing functionality for traditional single-level aliases while laying groundwork for the UTF-8 subsection support coming in patch 3/3. It's part of a well-structured series that has already gone through multiple rounds of review, with this particular change having been validated by Jeff King and approved by Junio Hamano.

The implementation is cleanly split from the actual feature addition, showing good patch discipline. The change is focused (only touching `help.c`) and comes with a clear explanation of the compatibility implications in the commit message. This appears ready for merging as part of the complete series.
