This is a review response in the ongoing HTTP 429 rate limiting thread. Taylor Blau provides detailed feedback on Vaidas Pilkauskas's v2 patch series implementing retry support for rate-limited HTTP requests. The review focuses on several key areas:

1. Configuration defaults - Taylor questions whether http.retryAfter should default to 0 (immediate retry) rather than -1 (fail immediately), given that http.maxRetries defaults to 0 (no retries).

2. Code organization - Suggests consolidating duplicate HTTP_RATE_LIMITED error handling into a shared function, possibly in a preparatory commit.

3. Header parsing - Notes potential issues with Retry-After header handling, including whether to accept "Retry-After: 0" and questions about header continuation support.

4. Control flow - Raises concerns about whether run_active_slot() is the right place to implement retry delays, suggesting the behavior might be surprising.

5. Style and documentation - Points out several minor style issues (unnecessary braces, comparison to 0) and suggests shortening error messages while moving configuration advice to advise() calls.

6. Test infrastructure - Defers to Jeff King (Peff) for review of the lib-httpd test changes.

The review is thorough and constructive, identifying both high-level design questions and implementation details while acknowledging areas where Taylor feels less confident in the codebase. The feedback suggests the series is nearing readiness but could benefit from some reorganization and refinement of the error handling paths before final merging.
