This is a brief reply in an ongoing discussion about performance improvements to `git config list --type=<X>` filtering. Patrick Steinhardt weighs in on Derrick Stolee's RFC patch series, specifically addressing the concern about behavior changes for existing tools using `--type` with `git config list`.

Steinhardt downplays the compatibility concern, stating that the current behavior (where `--type` is accepted but ignored) seems more like a bug than a feature worth preserving. He argues that the proposed change -- making `--type` actually filter the output -- is reasonable even if it affects existing tools, as those tools are likely expecting the filtering behavior that the flag implies.

The comment is supportive of Stolee's direction but doesn't engage with the deeper design questions about type interpretation that Junio raised earlier in the thread. It focuses narrowly on the backward compatibility aspect, suggesting the behavior change is justified.
