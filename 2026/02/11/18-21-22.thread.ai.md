Security patch series from Tian Yuchen hardening Git's repository discovery by validating `.git` file types, now in v5 with two focused patches. The series addresses security issues where Git could attach to parent repositories through malformed `.git` entries (FIFOs/sockets) while maintaining legitimate symlink support. Core changes focus on `setup.c` and `setup.h`, introducing refined error taxonomy in `read_gitfile_gently()` with distinct cases: missing paths (continue searching), directories (check validity), non-files (reject FIFOs/sockets), and other errors (fatal).

Key technical implementation:
- Patch 1/2 refactors error handling in `read_gitfile_gently()` to distinguish between `stat()` failures:
  - Introduces `READ_GITFILE_ERR_STAT_ENOENT` and `READ_GITFILE_ERR_STAT_FAILED` in `setup.h`
  - Restructures `read_gitfile_error_die()` to handle new error cases
  - Maintains support for legitimate symlinks via `stat()` rather than `lstat()`
  - Non-fatal handling of `ENOENT` and directories (continue searching)
  - Fatal errors for other stat failures and non-regular files
- Patch 2/2 implements security checks in `setup_git_directory_gently_1()`:
  - Uses `stat()` instead of `lstat()` to properly resolve symlinks to directories
  - Explicitly rejects dangerous `.git` entry types (FIFOs/sockets) with clear errors
  - Handles empty directories appropriately
- Comprehensive test coverage in `t/t0009-git-dir-validation.sh` verifies:
  - Valid symlinked directories
  - Rejection of FIFOs/sockets (both direct and symlinked)
  - Edge cases (garbage content, empty dirs)
  - Build system integration via meson
