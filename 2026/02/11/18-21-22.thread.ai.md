Security patch series from Tian Yuchen hardening Git's repository discovery by validating `.git` file types, currently at v4. The series addresses potential security issues where Git could silently attach to parent repositories through malformed `.git` entries (like FIFOs). Core changes focus on `setup.c` and `setup.h`, introducing refined error taxonomy in `read_gitfile_gently()` to distinguish between different failure modes when checking `.git` entries.

Key technical implementation in v4:
- Switched from `lstat()` to `stat()` for `.git` checks, allowing symlinks to directories while still rejecting FIFOs/sockets
- Maintains security by explicitly rejecting non-file `.git` entries (FIFOs, sockets) with clear error messages
- Finalized error taxonomy with four distinct cases: 
  - `READ_GITFILE_ERR_STAT_ENOENT` (missing paths - continue searching)
  - `READ_GITFILE_ERR_IS_A_DIR` (directory cases - check if valid repo)
  - `READ_GITFILE_ERR_NOT_A_FILE` (FIFOs/special files - reject)
  - Other errors (die)
- Added comprehensive test coverage in new `t/t0009-setup-security.sh` verifying:
  - Valid symlinked `.git` directories
  - Rejection of FIFO `.git` files
  - Rejection of symlinks to FIFOs
  - Rejection of garbage `.git` content
  - Proper handling of empty `.git` directories
