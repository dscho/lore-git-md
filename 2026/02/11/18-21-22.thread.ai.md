Security-focused patch series from Tian Yuchen hardening Git's repository discovery by validating `.git` file types. Current behavior silently ignored malformed `.git` entries (like FIFOs), potentially causing unsafe attachment to parent repositories. Patch v3 implements Junio Hamano's suggested error taxonomy from v2 discussion, distinguishing failure modes when checking `.git` entries.

Key changes in v3:
- `read_gitfile_gently()` now explicitly handles ENOENT separately from other stat failures
- New `READ_GITFILE_ERR_IS_A_DIR` for directory cases
- Rejects non-file/non-directory entries (FIFOs etc.) with `READ_GITFILE_ERR_NOT_A_FILE`
- Preserves symlink support by using `stat()` rather than `lstat()`
- Updated `setup_git_directory_gently_1()` to handle refined error taxonomy
- Added test coverage for various `.git` file types

Junio Hamano's review of v3 identifies implementation issues in error handling:
1. `read_gitfile_error_die()` incorrectly treats STAT_ENOENT and IS_A_DIR as fatal when they should be non-fatal
2. `setup_git_directory_gently_1()` incorrectly checks for git dir on STAT_ENOENT (nonexistent path)
3. STAT_FAILED condition appears inverted (`!=` vs `==`)

Junio's suggested refinements:
- Restrict `read_gitfile_error_die()` to handle only true error conditions
- Let callers naturally handle non-error cases (ENOENT, IS_A_DIR) without special exclusion logic
- Correct condition checking for STAT_FAILED

Core resolved points from earlier discussion:
1) Error taxonomy distinguishes fatal vs non-fatal conditions
2) Backward compatibility maintained for symlinks
3) Security benefit balanced with practical considerations
4) Implementation reuses existing `stat()` call
5) Test coverage added for validation behavior

Technical changes remain focused in `setup.c` but touch sensitive repository setup path.
