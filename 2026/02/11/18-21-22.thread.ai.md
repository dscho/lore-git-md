Thread summary:

Security-focused RFC patch proposing to harden Git's repository discovery by validating `.git` file types. Currently Git silently ignores malformed `.git` entries (like FIFOs), potentially causing unsafe attachment to parent repositories. Patch replaces NEEDSWORK with explicit validation - when `.git` exists but isn't regular file/dir, now either dies (die_on_error=true) or returns GIT_DIR_INVALID_GITFILE (false). Uses lstat() for direct mode checking. Open questions: 1) Is die() too aggressive? 2) Should callers handle errors? Touches sensitive setup.c path. Small (12-line) focused change with clear security motivation, seeking design feedback before finalizing.
