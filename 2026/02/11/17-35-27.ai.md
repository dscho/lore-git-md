This is a follow-up in the ongoing discussion about the ODB (object database) API cleanup series, specifically addressing whether to convert flag parameters to enum types for type safety.

Junio Hamano responds to Patrick Steinhardt's question about whether to re-roll the series to use enums instead of unsigned integers for flag parameters. Junio expresses skepticism about the enum approach proposed in Patrick's earlier email, noting that while converting `#define` constants to enums would logically imply changing function parameters to take enum types, this would create a situation where a cleanup series itself needs further cleanup. He leaves the decision to Patrick but makes clear he doesn't see strong value in the enum conversion for this particular series.

The exchange highlights a common tension in API design between type safety (enums) and simplicity (plain integers). Junio's position suggests he views this as a case where the benefits of stricter typing don't outweigh the additional churn it would create, especially for a series whose primary purpose is already cleanup rather than introducing new functionality.

This moves the ODB abstraction effort forward by resolving the open question about parameter types, though it leaves the door open for enum conversions in future work if they come as part of more substantial changes rather than as standalone cleanups. The thread remains focused on the technical merits of API design choices while maintaining the project's characteristic pragmatic approach to such decisions.
