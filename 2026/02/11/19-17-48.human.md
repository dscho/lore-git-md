This is a documentation patch from Git maintainer Junio C Hamano that clarifies the project's coding guidelines around comment style. The patch is small but meaningful as it makes explicit a previously implicit rule.

The Git project exclusively uses `/* */` style comments in C code rather than `//` single-line comments. While this was already implied by the existing multi-line comment examples in the guidelines, it wasn't explicitly stated until now. The patch adds a simple one-line clarification to the Documentation/CodingGuidelines file.

As a maintainer-driven documentation clarification, this patch doesn't require debate - it's effectively codifying existing practice. The change is straightforward and uncontroversial, coming from the person ultimately responsible for enforcing these guidelines. The patch follows all the project's own style rules (including the use of hard tabs for indentation in the diff).
