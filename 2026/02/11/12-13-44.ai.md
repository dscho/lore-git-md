This is a performance optimization patch in an ongoing series about improving `git config list --type filtering`. The patch implements type-aware filtering for `git config list`, which previously ignored the `--type` parameter entirely.

The key change makes `git config list --type=<X>` actually filter out values that don't match the specified type, similar to how `git config get` already works. This is framed as fixing broken behavior rather than introducing new functionality, since the option was silently ignored before. The implementation reuses the existing `format_config()` infrastructure from earlier patches in the series.

Patrick Steinhardt's review generally approves of the direction but raises two considerations: whether to keep the old unfiltered output path when no type is specified (avoiding some code changes), and whether the documentation's synopsis should be updated to reflect the new behavior. He acknowledges these are minor points and seems inclined to accept the current approach.

The patch touches `builtin/config.c` to modify the output logic and updates tests in `t/t1300-config.sh` to verify the new filtering behavior works for boolean, integer, and path types. This builds on the series' earlier refactoring of config value parsing into reusable components.

This appears to be the final patch in the series that delivers the promised performance improvement by avoiding full parsing of non-matching config values. The discussion suggests the design questions have largely been resolved, with only minor implementation details remaining before potential merge.
