Security-focused documentation update for `git am` patch parsing risks.

Kristoffer Haugsbakk responds to Jeff King's analysis of Jacob Keller's proposal for unambiguous boundary markers in `git am` patch processing. The discussion centers on how to safely distinguish between intended patch content and embedded diffs in commit messages, a known security vulnerability vector (as seen in the Debian incident where `sleep(1)` was accidentally introduced from a commit message diff).

Jeff King had raised concerns about the visual impact of requiring a new marker in every email and suggested an alternative approach of reversible quoting for problematic content, similar to the existing `>From` convention. Haugsbakk agrees this sounds preferable, noting that trailing whitespace could serve as a less intrusive marker if needed.

This exchange is part of a broader effort to address patch parsing ambiguities that includes multiple complementary approaches: documentation warnings (already queued by Junio), boundary markers, strict modes, and quoting mechanisms. The discussion remains technical and collaborative, with participants weighing tradeoffs between security, backward compatibility, and usability.
