This is a CI/build system patch continuing the discussion about tracking dependencies for `config-list.h` generation in the Meson build. Patrick Steinhardt proposes an alternative approach to D. Ben Knoble's earlier solution for ensuring the header gets rebuilt when documentation changes affect it.

The key change is splitting `generate-configlist.sh` into two modes: one that generates the actual header file (with dependency tracking via a depfile), and another that maintains a list of all documentation files that could influence the output. The latter runs with `build_always_stale: true` to catch file additions/removals, while the former handles content changes through normal depfile tracking. This combines the benefits of Knoble's explicit dependency listing with more precise rebuild triggering.

Steinhardt's implementation demonstrates the approach works for all cases - file modifications, additions, and deletions - while keeping the build system maintainable. The patch shows active collaboration between two build system experts refining the solution, with no technical objections raised yet. The changes remain focused on build infrastructure without affecting core Git functionality.
