This is a performance optimization patch for `git pack-objects` in partial clone scenarios, addressing unnecessary object fetches during geometric repacking of promisor packs. The patch builds on Patrick Steinhardt's earlier work and has now been reviewed and accepted by Junio Hamano for inclusion.

The core issue is that when merging packs with `--stdin-packs`, Git performs a localized rev walk to gather name hashes for delta selection heuristics. This walk could trigger backfill fetches for missing promisor objects, even though these fetches weren't actually needed for the pack merging operation. The patch disables fetching during this walk while maintaining the delta selection benefits.

Junio notes the patch is well-described and the implementation is surprisingly simple, leveraging a global variable safely since only one packing operation runs at a time. He's queuing the patch after fixing a minor typo ("passe" -> "pass"). This optimization will be particularly valuable for large repositories using partial clones where unnecessary fetches impact performance.

The patch has already received positive feedback from Jeff King (Peff) and Taylor Blau in earlier rounds, with Jeff suggesting test improvements that were presumably incorporated. This represents a focused, well-reasoned optimization that builds on Git's ongoing work around geometric repacking and partial clone performance.
