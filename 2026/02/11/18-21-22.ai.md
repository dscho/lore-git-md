This is a security-oriented bugfix proposal targeting Git's repository discovery mechanism. The patch addresses a potentially dangerous edge case where Git would silently ignore malformed `.git` entries (like FIFOs) during repository discovery, potentially causing it to attach to a parent repository and execute commands there unintentionally.

The core change replaces a NEEDSWORK comment with explicit validation - if `.git` exists but isn't a regular file or directory, Git will now either die() (when `die_on_error` is true) or return `GIT_DIR_INVALID_GITFILE` (when false). The author raises two open questions about whether failing hard is the right approach and whether the error handling should be pushed to callers.

The patch is small (12 lines changed) and focused, with a clear security motivation. The implementation uses `lstat()` to check file modes directly rather than relying on the existing error codes. This touches the sensitive repository setup path in `setup.c`, so reviewers will likely scrutinize the error handling implications carefully. The RFC tag suggests the author is seeking design feedback before finalizing the approach.
