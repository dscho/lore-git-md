This is a CI/build system patch that standardizes test execution between GitLab and GitHub CI systems for Meson builds. It's the sixth in a seven-part series from Patrick Steinhardt improving test infrastructure reliability, particularly for Windows/MSVC builds.

The patch makes GitLab CI use the same `run-test-slice-meson.sh` script that GitHub CI already employs, rather than open-coding the Meson test parameters directly in the GitLab config. This ensures consistent test execution behavior across both CI providers. The change specifically affects Windows/MSVC builds in GitLab CI, where the direct Meson test command is replaced with a bash invocation of the shared slicing script.

Key technical details include:
- Updates `.gitlab-ci.yml` to call the shared script via bash
- Maintains the same parallel test slicing approach (10-way parallelization)
- Preserves the same artifact reporting configuration
- The script path is explicitly referenced via Git for Windows' bash installation

This change completes the standardization of test slicing behavior that was started in earlier patches of the series, ensuring both CI systems use identical logic for dividing up the test suite across parallel jobs. The patch is small and focused, representing the natural conclusion of the test slicing standardization effort that has been building through the series.
