This is the fourth iteration of a feature to support UTF-8 characters in Git alias names via config subsection syntax (`[alias "förgrena"]`). The series has progressed through multiple rounds of review, with all technical issues addressed in v3 except for the handling of NULL values in alias listings - which is now resolved in v4.

The patch series consists of three logical commits: first moving alias listing logic to a shared function, then preparing the alias subsystem for subsection support, and finally implementing the UTF-8 alias feature itself. The v4 changes specifically address Junio Hamano's feedback about NULL value handling by:

1. Removing redundant NULL checks since `git_config_string()` already handles this
2. Adding immediate error reporting for misconfigured aliases via `config_error_nonbool()`
3. Simplifying the code by consolidating error checking
4. Adding test coverage for value-less alias error cases

The implementation now properly handles edge cases while maintaining backward compatibility with traditional alias syntax. Test coverage has been expanded to verify both the new UTF-8 functionality and error conditions, using more robust test patterns that avoid piping to grep. Documentation has been refined to clearly explain the two syntax forms and their case sensitivity differences.

With these final changes, the series appears ready for merging. It has received thorough review from Jeff King (technical validation), Torsten Bögershausen (platform considerations), and Junio Hamano (documentation and edge case handling). The only remaining open question is Windows support, which is deferred to future work.
