This is a bug report about `git cat-file --batch` behavior when given an out-of-bounds reflog reference (like `branch@{20}` when the branch only has 5 entries). The reporter, Kristoffer Haugsbakk, notes that while most invalid object names result in a "missing" error message, reflog entries beyond the available history cause the command to die with a fatal error.

The behavior changed recently with commit 393bbb21, which introduced a `GET_OID_GENTLY` flag to handle such cases more gracefully in other parts of Git (notably `git stash`). The reporter observes that `cat-file` doesn't use this flag in batch mode, leading to the inconsistent behavior where malformed revs get nice errors but out-of-bounds reflog entries trigger a fatal exit.

The patch doesn't propose a solution but thoroughly documents the current behavior and its inconsistency with how `cat-file` handles other invalid inputs. The reporter is new to this area of the code but has done solid homework tracing the relevant flags and commits. This looks like a legitimate bug that could be fixed by applying the `GET_OID_GENTLY` flag to batch mode lookups.
