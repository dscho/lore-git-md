This is a review response in the ongoing shallow repository patch series by Samo Pogačnik, now at version 4. Patrick Steinhardt provides detailed technical feedback on the second patch, which implements correct relative-depth fetching (`--deepen`).

Patrick identifies several areas for improvement in the implementation:

1. **Code organization**: He suggests declaring the loop variable `j` inline where it's used rather than at function scope, and removing unnecessary braces around simple conditions in `shallow.c`.

2. **Behavioral concerns**: He questions why certain operations (updating `result`, setting `shallow_flag`, checking depth) are omitted when the `shallows` parameter is provided, noting this makes the function behave very differently based on its inputs. He suspects this relates to tracking `cur_depth_shallow` but finds the divergence confusing.

3. **Function structure**: He recommends inlining `get_shallows_depth()` in `upload-pack.c` since it only forwards to `get_shallow_commits()` and has a single caller.

4. **Redundant calls**: He points out the current flow calls `get_shallow_commits()` twice - first to compute `deepen_relative` then again with that value - and suggests consolidating this into a single call.

The review maintains the thread's productive tone while identifying substantive technical issues that would benefit from clarification or refactoring. These are focused on implementation details rather than the core algorithm, which had already been vetted in earlier rounds. The feedback suggests the patch is conceptually sound but could be cleaner in its execution.
