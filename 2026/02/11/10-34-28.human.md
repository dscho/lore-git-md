This is a CI/build system patch from Patrick Steinhardt that fixes an issue with test slicing in Git's CI infrastructure. The patch corrects a subtle but important bug where GitLab CI was unintentionally skipping the smallest test when running parallel test jobs.

The core issue stems from a mismatch in how test slicing parameters are interpreted. The test-slicing helper tool expected zero-based indexing (like GitHub CI provides), but GitLab CI uses one-based indexing (`$CI_NODE_INDEX`). This caused the first test slice to be skipped entirely. Since tests are sorted by size before slicing, this meant the smallest test was being missed rather than the lexicographically first one.

The solution reframes the slicing parameters to explicitly use one-based "slice number" terminology instead of the ambiguous "offset" concept. This makes the interface more intuitive and adds validation to catch invalid parameters. The patch updates both the test helper tool and GitHub's workflow file to use the new scheme consistently.

This is part of Patrick's larger v2 series improving CI reliability, particularly for Windows/MSVC builds using Meson. The change is straightforward and well-explained, with clear motivation and proper updates to both the implementation and its callers. The fix will ensure all tests actually run in CI rather than silently skipping some.
