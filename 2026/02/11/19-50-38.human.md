Maintainer feedback on the pre-add hook proposal. Junio Hamano responds to Chandra Kethi-Reddy's v2 patch implementing a `pre-add` hook that validates staged changes before they enter the index. While generally approving the architectural approach (which follows his earlier suggestions), he raises several documentation and implementation questions that need clarification.

The key points from Junio's review:
1. Documentation needs work - the hook name "pre-add" appears unmarked in the text, and the `--no-verify` option description should clarify whether it's hook-specific or general
2. Questions whether environment variables (like `GIT_INDEX_FILE`) should be explicitly mentioned as being passed through or cleared
3. Suggests the index copy might be unnecessary since Git's standard write pattern keeps the original untouched until commit
4. Notes the implementation follows the safe tempfile/lockfile pattern used elsewhere but leaves final wording of error messages open

This represents the maintainer's technical review pass - the core design is sound but needs polish on documentation details and some implementation questions answered. The patch appears to be on track for inclusion once these points are addressed.
