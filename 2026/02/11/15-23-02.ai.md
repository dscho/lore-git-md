This is a security-focused discussion about improving `git am`'s patch parsing safety, building on the earlier documentation patch that has now been queued by Junio. The thread explores technical solutions to prevent `git am` from misinterpreting diffs embedded in commit messages as actual patches to apply.

Jeff King (Peff) analyzes Jacob Keller's proposal for a new unambiguous boundary marker after the `---` separator, noting concerns about visual clutter and the challenge of making such a marker reliably distinct from legitimate commit message content. He suggests two alternative approaches: a sender-side reversible quoting mechanism (similar to the existing `>From` convention for email) that would escape problematic content, and a receiver-side `--strict` mode for `git am` that would enforce cleaner patch boundaries.

Kristoffer Haugsbakk, whose documentation warning patch is now finalized, agrees that Peff's reversible quoting approach seems preferable to adding new markers. The discussion reveals the tension between maintaining backward compatibility with existing workflows while addressing the security risk where tools might misinterpret commit message content as patch content. This builds on prior work including Phillip Wood's enhanced `commit-msg` hook and Patrick Steinhardt's proposed `--accept-ambiguous-patch` flag, forming a layered approach to the problem.
