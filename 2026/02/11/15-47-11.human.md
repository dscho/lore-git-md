This is a security-focused discussion about improving `git am`'s patch parsing safety. The thread has been exploring ways to prevent accidental application of diffs embedded in commit messages, a problem that recently caused a real-world issue in Debian's packaging workflow.

Junio C Hamano responds favorably to Jeff King's suggestion of a `--strict` mode for `git am` that would enforce stricter parsing rules when processing Git-generated patches. The key idea is that since Git's own `format-patch` always includes a clear `---` separator between commit message and patch, the receiver can safely ignore any diff-like content before that marker when in strict mode.

Junio notes this approach makes more sense today than it would have when `git am` was first written, since Git-generated patches are now the norm. The discussion reflects a growing consensus around layered solutions combining documentation warnings, stricter parsing options, and other defenses against this class of security issues.
