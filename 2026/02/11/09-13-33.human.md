This is a review response from Jeff King (Peff) regarding Vaidas Pilkauskas's HTTP 429 rate limiting patch series. The discussion focuses on implementation details and test infrastructure for handling HTTP 429 (Too Many Requests) responses with Retry-After headers.

Peff raises several technical concerns about the current approach:
1. Questions whether the retry delay logic belongs in run_active_slot(), suggesting it might be better handled at a higher level like http_request_reauth()
2. Notes that curl provides built-in Retry-After header handling via CURLINFO_RETRY_AFTER (since curl 7.66.0) that could simplify parsing
3. Suggests the dumb-http push/webdav code (http-push.c) may not need updating since it's effectively deprecated
4. Points out potential portability issues with date handling in the test scripts

The review indicates the patch is moving in the right direction but needs refinement in how retries are coordinated with Git's HTTP request lifecycle. Peff's comments suggest focusing the retry logic on smart HTTP cases first and potentially leveraging more curl features to reduce manual header parsing.
