Feature implementation for UTF-8 alias support via config subsections, completing the v4 series. This final patch adds the core functionality to allow non-ASCII alias names through the subsection syntax (`[alias "förgrena"]`), while maintaining backward compatibility with the traditional case-insensitive ASCII-only format.

The implementation handles several key aspects:
- Case-sensitive matching for subsection aliases vs case-insensitive for traditional ones
- UTF-8 display support in help output using `utf8_strwidth()`
- Strict validation of subsection keys (only `command` is accepted)
- Comprehensive test coverage including Swedish, CJK, and space-containing aliases
- Proper error handling for NULL values and malformed configurations

The patch builds on preparatory refactoring from earlier in the series, now using `parse_config_key()` consistently and consolidating alias listing logic between `alias.c` and `help.c`. Documentation has been updated to clearly explain the two syntax forms and their differing character set and case sensitivity rules.

All technical feedback from previous iterations has been addressed, including:
- Jeff King's validation of the core approach
- Junio Hamano's documentation wording suggestions
- Resolution of NULL value handling via `config_error_nonbool()`
- Strict key validation replacing previous `skip_prefix()` usage

The implementation appears ready for merging, with the known limitation that Windows support remains future work. The series represents a clean solution to enable non-English alias names while maintaining backward compatibility and clear documentation.
