CI/build system patch fixing test-slicing logic in Git's CI infrastructure. This is the second patch in Patrick Steinhardt's 7-part series improving test reliability across GitLab and GitHub CI, particularly for Windows/MSVC builds using Meson.

The patch addresses a subtle bug where GitLab CI was unintentionally skipping test cases due to an off-by-one error in the test-slicing logic. The `test-tool path-utils slice-tests` helper was designed to take a zero-based offset and total slice count, but GitLab CI was passing a one-based index (`$CI_NODE_INDEX`). This caused the smallest test (when sorted by size) to be skipped rather than the first test lexicographically.

The fix reframes the parameters as "slice number" (one-based) and "total slices" instead of "offset" and "stride", adding validation that the slice number is within bounds. This makes the interface more intuitive while fixing the GitLab case. The GitHub workflow is updated to match by adjusting its zero-based index to one-based.

The changes touch both the test helper implementation in `t/helper/test-path-utils.c` and the GitHub workflow configuration. The patch demonstrates Patrick's attention to cross-platform consistency in CI behavior, a recurring theme in his infrastructure improvements. The fix is part of broader work to make test execution more reliable across different CI providers and build systems.
