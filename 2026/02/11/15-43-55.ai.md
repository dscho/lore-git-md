This is a documentation and implementation discussion regarding the `format.noprefix` configuration option, part of an ongoing thread about patch prefix handling in Git.

Jeff King (Peff) identifies an implementation bug where `format.noprefix` incorrectly accepts any value rather than properly interpreting boolean values like most Git config options. The current code simply checks for the variable's existence rather than evaluating its value, which contradicts Git's standard configuration handling patterns. Peff notes this appears to be an unintentional bug rather than a deliberate design choice, as there's no reason users would set it to false if they didn't want the behavior.

The thread has progressed from initial version/documentation clarification to now addressing this implementation issue. Kristoffer Haugsbakk is taking ownership of both the documentation (which currently correctly describes boolean behavior) and the implementation fix, with Peff providing technical guidance. The fix will use `git_config_bool()` to standardize the behavior with Git's config conventions.

While technically not backwards-compatible, the consensus is this should be fixed as the current behavior is clearly incorrect. The discussion also touches on related configuration (`diff.noprefix`) and the implications for patch generation and application workflows. The man page patch for `futex_waitv.2` serves as a test case demonstrating the version-dependent behavior.
