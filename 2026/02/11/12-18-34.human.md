This is a feature proposal discussion about exposing repository paths through a new `git repo info` interface, positioned as a more discoverable alternative to `git rev-parse` for repository metadata.

Patrick Steinhardt responds positively to Pushkar Singh's RFC about adding path information (starting with `--git-dir` equivalent) to `git repo info`. He agrees that `git rev-parse` has accumulated functionality beyond its original scope and sees this as aligning with the original vision for `git repo`. The thread explores whether paths should be reported as absolute or relative, with Patrick noting that Lucas (CC'd) had previously considered making this configurable.

The exchange suggests this could be the start of a broader effort to migrate repository metadata access from `git rev-parse` to a more purpose-built interface, though the initial focus is deliberately narrow to gather feedback. Patrick's involvement signals this may gain traction, given his role in architectural efforts. The discussion remains open-ended on path resolution specifics, with future expansion to other paths (common dir, hooks) hinted at but not yet proposed.
