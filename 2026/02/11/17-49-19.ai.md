Performance improvement to `git config list --type filtering`. This is the final patch in Derrick Stolee's series that makes `git config list --type=<X>` actually filter values by type during parsing rather than after, addressing a performance bottleneck found in git-credential-manager.

The patch implements the core behavior change, making `--type` filter non-matching values during config parsing rather than after. It reuses the parsing infrastructure from earlier patches in the series (relocated `show_all_config()`, new `git_parse_maybe_pathname()`, modified `format_config()` with `gently` parameter) to enable type-aware filtering. The implementation matches `git config get` behavior where non-matching types are simply omitted rather than shown as strings.

Patrick Steinhardt has reviewed the implementation and suggested minor documentation updates - specifically to amend the synopsis of `git config list` to better reflect the new behavior. Derrick confirms the changes don't affect the output format when no `--type` is specified, and explains that test file modifications demonstrate type conversion behaviors (like case modification for bools) rather than being functional changes.

The series appears ready for merging with only these final documentation tweaks remaining. The performance improvement comes from skipping full parsing of values that won't match the requested type, particularly beneficial for path-type values. The change is framed as fixing broken behavior since `--type` was previously ignored in `list` mode.
