Documentation clarification and potential bugfix for `format.noprefix` behavior.

Jeff King (Peff) responds to Kristoffer Haugsbakk's observation that `format.noprefix` behaves differently from `diff.noprefix` - it accepts any value rather than being a proper boolean. Peff confirms this is unusual in Git's configuration system and likely a bug, proposing to change it to use `git_config_bool()` for consistency. 

The current implementation simply checks if the variable exists (setting `format_no_prefix = 1` regardless of value), which contradicts Git's standard pattern where boolean configs explicitly check for true/false values. While technically a behavior change, Peff argues this should be considered a bugfix since the current behavior was presumably unintentional.

The discussion also touches on documentation wording - the existing "If set" phrasing would remain appropriate after the fix since it aligns with how Git documents other boolean options. Peff suggests Kristoffer could submit the code fix, noting that identifying the issue was the hard part.

This follows up on an ongoing thread about version-specific behavior of patch prefix handling, where `format.noprefix` was introduced in v2.41.0 to complement the existing `diff.noprefix`. The exchange highlights both a documentation clarification and a potential code improvement opportunity in how the configuration is processed.
