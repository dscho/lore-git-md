Junio C Hamano has documented the meaning and handling of `NEEDSWORK` comments in Git's codebase, adding a new section to the CodingGuidelines. These comments, long used informally, are now formally defined as suggestions for potential future work that require evaluation rather than direct implementation. The documentation emphasizes that assessing whether the suggested work still makes sense - especially as the code evolves - is often more important than the implementation itself, and that removing such comments without action is valid if the idea is rejected.

Patrick Steinhardt initially suggested that `NEEDSTHOUGHTS` might better convey the intent, but Junio successfully argued that thinking is inherent in the work implied by `NEEDSWORK`. The second iteration of the patch incorporated minor but meaningful wording changes to clarify the temporal aspect of these comments, noting they may become obsolete over time. With Patrick's agreement, the documentation now stands as a reference point for contributors who might otherwise misinterpret these comments as mandatory todos. This patch closes a small but important gap in the project's documented conventions without introducing new requirements.
