This is a security-focused discussion about making `git am` safer when parsing patches with embedded diffs in commit messages. Jacob Keller proposes a technical solution to the long-standing issue where `git am` can misinterpret diffs in commit messages as actual patches to apply.

The thread has already seen significant discussion, with Kristoffer Haugsbakk's documentation warnings now queued by Junio, and Patrick Steinhardt proposing a `--accept-ambiguous-patch` flag. Keller suggests adding an unambiguous marker after the traditional `---` separator that new Git versions would recognize, while remaining backwards-compatible with older versions that would simply ignore it.

The key insight is that since all versions already ignore content between `---` and the diff start, adding a new marker there wouldn't break existing workflows. This builds on the layered approach emerging from the thread: documentation warnings, defensive hooks, and now potential parser improvements. The proposal appears technically sound but would need validation from the security-conscious contributors like Jeff King who have been involved in the discussion.
