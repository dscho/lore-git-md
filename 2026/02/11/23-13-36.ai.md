Bugfix for `git cat-file --batch` behavior with out-of-bounds reflog entries.

Kristoffer Haugsbakk reports that `git cat-file --batch` dies with a fatal error when given a reflog entry that is out of bounds (e.g., `branch@{20}` when the branch only has 5 entries). This behavior changed in commit 393bbb21 ("object-name: make get_oid quietly return an error", 2025-06-12), which introduced the `GET_OID_GENTLY` flag to allow callers to handle errors gracefully rather than dying.

The patch examines how `git cat-file` handles various invalid inputs, noting that it typically returns "missing" for nonexistent objects and malformed rev expressions, making the fatal error for out-of-bounds reflog entries inconsistent. The current behavior stems from `GET_OID_ONLY_TO_DIE` not being set for batch modes, while the new `GET_OID_GENTLY` flag (added primarily for `builtin/stash.c`) could provide a more graceful error handling path.

This appears to be a focused fix addressing a specific edge case in the batch processing mode. The analysis is thorough, referencing relevant commits and flag usage patterns. The change would make behavior more consistent by treating invalid reflog entries similarly to other invalid object references rather than terminating the batch process.
