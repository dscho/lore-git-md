Performance optimization patch in the `git config` series, with review feedback from Patrick Steinhardt.

This is the second patch in Derrick Stolee's series to improve `git config list --type=<X>` performance by enabling type filtering during config parsing rather than after. The patch extracts pathname parsing logic from `config.c` into a new `git_parse_maybe_pathname()` helper in `parse.c` that avoids dying on missing paths when they're marked as optional.

Patrick Steinhardt provides a thorough review, noting the initial commit message was hard to parse (pun intended) and suggesting improvements to document the function's behavior more clearly. He highlights three key aspects that need documentation: the `:(optional)` prefix handling, path expansion behavior (including `~` and `%(prefix)`), and the fact paths remain relative rather than becoming absolute.

The review is constructive and technical, focusing on making the helper's contract explicit. Patrick seems generally supportive of the direction while ensuring the details are properly specified. This fits with the thread's broader discussion about carefully evolving Git's config handling while maintaining backward compatibility.
