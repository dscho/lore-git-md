Bugfix for `git cat-file --batch` handling of out-of-bounds reflog entries. Junio C Hamano confirms that the current behavior where `git cat-file --batch` fatally errors on invalid reflog references (like `branch@{20}` when only 5 entries exist) should be considered a bug, not just a limitation. This follows Kristoffer Haugsbakk's report showing the inconsistency - while `cat-file` gracefully handles other invalid inputs by returning "missing", it dies on reflog bounds checks. 

The issue stems from commit 393bbb21 which introduced `GET_OID_GENTLY` for graceful error reporting but didn't apply it consistently to reflog cases in batch mode. Junio's response indicates this will likely be fixed to align with Git's general principle of diagnosing rather than dying on invalid references. The patch appears straightforward since the necessary error handling mechanism (`GET_OID_GENTLY`) already exists and just needs to be properly utilized for reflog cases in batch processing.
