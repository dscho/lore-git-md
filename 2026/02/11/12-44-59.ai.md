This is a performance optimization patch for `git pack-objects` that prevents unnecessary object fetches when merging packs in partial clones. The patch comes from Patrick Steinhardt, who has been actively working on Git's pack and repack machinery.

The issue arises when using `--stdin-packs` to merge multiple packfiles (including promisor packs) during geometric repacking. Previously, the command would perform a best-effort rev walk to gather object names for better delta selection, and this walk could trigger backfill fetches for missing promisor objects - even though these fetches aren't actually required for the pack merging operation.

The patch modifies the behavior to temporarily disable fetching during this rev walk, since the walk is only being used to gather name hashes as a delta selection heuristic. A new test case verifies that no fetches occur during this operation. The change is particularly relevant for large repositories using partial clones, where unnecessary fetches could significantly impact performance.

This appears to be a well-motivated change with clear test coverage. It builds on recent work (commit dcc9c7ef47) that enabled geometric repacking of promisor packs, and addresses a real-world performance issue reported by a GitLab user. The patch is focused and follows Git's established patterns for handling fetch_if_missing state.
