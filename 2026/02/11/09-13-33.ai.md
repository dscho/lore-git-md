This is a review response from Jeff King (Peff) regarding the HTTP 429 rate limit retry support patch series. The review focuses on several key technical concerns and suggests alternative approaches.

Peff raises significant architectural questions about the retry implementation, particularly questioning whether run_active_s() is the right layer for handling retry delays. He suggests the logic might better belong in http_request_reauth() or run_one_slot() instead. The review notes the complexity of the HTTP code, especially around handling both single and multiple simultaneous requests.

A notable technical proposal is to use curl's built-in CURLINFO_RETRY_AFTER functionality (available since curl 7.66.0) rather than manual header parsing, though this would require conditional compilation. Peff also identifies potential portability issues with date handling in the test suite and suggests using Git's test-tool date instead of system date commands.

Regarding scope, Peff recommends not touching the legacy http-push.c and http-walker.c code paths since they're used for deprecated protocols (WebDAV push and dumb HTTP). He suggests these could be left to return generic errors rather than implementing specialized 429 handling.

The review maintains a constructive tone while expressing deep technical concerns about the current approach. Peff acknowledges the complexity of the HTTP code and his own partial recollection of its details, but provides clear alternative directions for consideration. His feedback suggests the series may need significant restructuring before being ready for inclusion.
