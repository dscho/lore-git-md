This thread discusses a performance optimization for `git pack-objects` in partial clone scenarios, proposed by Patrick Steinhardt. The patch addresses an issue where geometric repacking of promisor packs could trigger unnecessary object fetches during what should be a local-only operation.

The core issue stems from how `--stdin-packs` performs a best-effort revision walk to gather object names for delta selection. While this walk is just a heuristic optimization, it was inadvertently causing missing promisor objects to be fetched from the server - even though these objects aren't actually needed to complete the pack merging operation. Patrick's solution temporarily disables fetching during this walk, since the name hashes are only being collected as a delta selection aid.

The change is particularly impactful for large repositories using partial clones, where such unnecessary fetches could create significant performance overhead. The patch includes a test case verifying that no fetches occur during the operation, building on previous work (dcc9c7ef47) that enabled geometric repacking of promisor packs. This appears to be a focused, well-tested optimization that follows Git's established patterns for managing fetch state.
