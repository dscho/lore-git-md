Security-focused discussion about hardening repository discovery by validating `.git` file types. Junio C Hamano responds to Tian Yuchen's RFC patch that would make Git fail when encountering malformed `.git` entries (like FIFOs) rather than silently continuing up the directory tree.

Junio questions whether this scenario is truly "very dangerous" as claimed, noting that if an attacker can replace `.git` with a FIFO, they likely have broader write access already. However, he acknowledges that failing explicitly could help users notice filesystem corruption sooner. The main open questions are whether to die() immediately or return an error code for callers to handle, and whether to maintain backward compatibility with systems that might intentionally have non-standard `.git` entries.

The technical discussion focuses on optimizing the lstat() check placement - Junio suggests moving it after the happy-path directory check to avoid unnecessary stats in normal cases. This remains an RFC while the security impact and error handling approach are debated.
