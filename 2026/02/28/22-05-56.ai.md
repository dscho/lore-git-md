This is a refactoring patch that extracts path formatting logic from `git rev-parse` into a reusable helper function. It's part of a 4-patch series preparing to share path handling between `rev-parse` and the new `git repo-info` command.

The patch moves the path formatting implementation from `builtin/rev-parse.c` to a new `strbuf_add_path()` function in `path.c`, along with the supporting enums`path_format_type` and `path_default_type`. The enums are renamed with `PATH_` prefixes for clarity (e.g., `FORMAT_RELATIVE` becomes `PATH_FORMAT_RELATIVE`). The `rev-parse` command is updated to use this shared implementation.

The changes are mechanical and preserve all existing behavior - this is pure code movement with no functional changes. The implementation handles various path formatting cases including relative vs absolute paths, shared roots, and unmodified output. The patch appears cleanly implemented with thorough test coverage, though as a new contributor's work it hasn't yet received review feedback.

Key technical details for future reference: the new `strbuf_add_path()` function encapsulates path formatting logic that was previously inline in `rev-parse`, using the same enum types (now publicly exposed in path.h) to control formatting behavior. This lays groundwork for `repo-info` to reuse this functionality in later patches.
