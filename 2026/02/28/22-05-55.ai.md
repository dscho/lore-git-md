This is a refactoring patch that's part of a series to add path-related functionality to `git repo-info`. The patch focuses on renaming enums in `builtin/rev-parse.c` to make their purpose clearer.

The changes rename two enums and their values by adding a `path_` prefix: `format_type` becomes `path_format_type` and `default_type` becomes `path_default_type`. Their values are similarly renamed (e.g., `FORMAT_RELATIVE` -> `PATH_FORMAT_RELATIVE`). This makes the code more self-documenting by clarifying these types are specifically for path formatting decisions.

The patch is mechanical and straightforward, touching only `builtin/rev-parse.c` with no behavior changes. It's part of a larger effort to extract and share path formatting logic between `rev-parse` and the new `repo-info` command. The implementation appears clean with all references to the old enum names updated consistently.

Key symbols introduced are the `path_format_type` and `path_default_type` enums, which will be used in subsequent patches to implement shared path handling infrastructure. The changes maintain compatibility with existing `rev-parse` behavior while setting up clearer code organization for the path-related functionality being added to `repo-info`.
