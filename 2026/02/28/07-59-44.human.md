This is a feature patch for gitk, adding a configurable link color option to the Preferences dialog. The change addresses a readability issue in dark themes where the default link color was hard to see against dark backgrounds.

The patch adds a "Link" color picker to gitk's color preferences tab, exposing the previously hardcoded `linkfgcolor` variable through the UI. This is a straightforward 10-line change following gitk's existing color configuration pattern, modifying the `prefspage_colors` and `prefspage_set_colorswatches` procedures in the Tcl/Tk code.

The patch has gone through three iterations, with maintainer Johannes Sixt providing feedback on both the technical implementation (simplifying the UI label from "Link color" to "Link") and process aspects (removing CC trailers from the commit message). The discussion also surfaced some useful documentation points about Git contribution conventions that will help future contributors.

This appears ready for inclusion - it's a small, well-motivated change that improves gitk user experience for dark theme users without introducing complexity. The maintainer has already approved the technical approach, and all process feedback has been addressed in v3.
