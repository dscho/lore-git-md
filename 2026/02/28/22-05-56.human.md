This is a refactoring patch that extracts path formatting logic from `git rev-parse` into a reusable helper function. It's part of a 4-patch series adding path-related functionality to the new `git repo-info` command.

The patch moves the path formatting implementation from `builtin/rev-parse.c` to a new `strbuf_add_path()` function in `path.c`, making it available for other commands. It also relocates two enums (`path_format_type` and `path_default_type`) that control path formatting behavior, giving them more descriptive names with `PATH_` prefixes.

The implementation appears clean and maintains all existing functionality while making it reusable. The changes are mechanical - the core logic remains the same, just moved to a shared location. This sets up infrastructure for the subsequent patches that will add path formatting to `repo-info`.

The patch builds on brian m. carlson's 2020 work on `rev-parse` path formatting and is part of groundwork for future contributors (several GSoC applicants are CC'd) to add more path functionality. While the implementation looks solid, the thread hasn't yet received any review feedback.
