GSoC proposal for prioritized fetching from multiple promisor remotes by Abraham Samuel Adekunle, building on Christian Couder's promisor-remote capability work. The proposal aims to add priority-based fetch ordering through protocol extension (v2 promisor-remote capability with priority field) and configuration (server-side priority settings, client-side controls). Christian Couder's review suggests starting with local `remote.<name>.priority` config before protocol changes, and questions the need for new `promisor.honorServerFetchOrder` config when existing `promisor.storeFields` could suffice. He emphasizes the solution should work for all partial clone objects, not just blobs, and points to undefined current behavior in partial-clone.adoc when using multiple promisor remites. Abraham has prior Git contribution experience with merged `git add -p` patch and another in `next`. Christian's feedback indicates this is well-scoped project addressing real need for partial clone users, though implementation will need to carefully handle fetch ordering edge cases and server-client negotiation. Key open questions include whether to use new vs existing config mechanisms and exact protocol negotiation flow for priority advertisement.
