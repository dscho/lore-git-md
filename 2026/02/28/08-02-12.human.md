This is a UI improvement patch for gitk, the Git repository browser, now in its third iteration. The change adds a "Links" color option to gitk's Preferences dialog, allowing users to customize the color of hyperlinks in the interface - particularly useful for improving readability in dark themes. The patch modifies Tcl/Tk code in gitk's color preference handling, following the existing pattern for other color configuration options.

The technical implementation was approved in v2 by gitk maintainer Johannes Sixt, who suggested simplifying the UI label from "Link color" to "Links" for better dialog phrasing. The v3 iteration addresses process feedback about proper CC trailer usage (moving them from commit messages to GitHub PR descriptions when using GitGitGadget) while keeping the technical change unchanged. The patch appears ready for inclusion, having navigated both technical review and contribution process clarifications.

This is a small but thoughtful quality-of-life improvement that follows gitk's existing patterns while making the previously hardcoded link color configurable. The change is well-contained (about 10 lines of UI code) and has maintained its focus through three iterations, suggesting the author has been responsive to feedback.
