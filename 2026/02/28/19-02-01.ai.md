This is a refactoring patch as part of the ongoing `the_repository` removal effort, specifically targeting the pretty-printing functionality in Git's commit formatting system. It's the third patch in Tian Yuchen's series to migrate encoding-related globals to repository-specific storage.

The patch updates `pretty_print_commit()` and `pp_commit_easy()` to take a `struct repository*` parameter, allowing them to access encoding settings via the repository context rather than the global `the_repository`. This affects 15 files across various builtin commands and core components, with call sites updated to pass either an explicit repository pointer or falling back to `the_repository` where context isn't yet available (like in `bundle.c`).

Key technical changes include modifying the pretty-printing functions to use `repo_get_log_output_encoding()` instead of the global access, and propagating repository context through commit formatting chains. The patch maintains backward compatibility by falling back to `the_repository` for unconverted callers, ensuring no behavior changes during the transition.

The changes are mechanical but widespread, touching commit display paths in commands like `log`, `show-branch`, `stash`, and the sequencer. Test suite passes indicate the refactoring maintains existing behavior while moving toward the architectural goal of eliminating global state. This follows the established pattern for `the_repository` migrations seen in other subsystems.
