Feature improvement for `git send-email`'s character encoding validation. This is the fourth iteration of a patch from first-time contributor Shreyansh Paliwal that improves how `git send-email` handles non-ASCII content in email subjects and bodies.

The patch replaces the current length-based heuristic (which only checks that charset names are at least 4 characters) with proper semantic validation using Perl's `Encode::find_encoding()`. The new flow first prompts for an encoding (defaulting to UTF-8 with clearer wording), then validates the input against known encodings before proceeding. If the encoding is invalid, it asks for explicit confirmation before using it.

Key technical changes:
- Removes the `confirm_ask()` helper from v3 in favor of direct validation
- Updates prompt wording to "Declare which 8bit encoding to use [default: UTF-8]?"
- Adds specific confirmation prompt for invalid encodings
- Relaxes input validation from 4+ chars to any non-blank string
- Maintains backward compatibility while improving safety
- Updates tests to match new prompt wording

The patch has undergone extensive review from Ben Knoble and Junio Hamano, with v4 addressing Junio's feedback about code organization and style. The implementation now uses core Perl functionality (already employed in gitweb and git-svn) for robust encoding validation while maintaining the project's interactive prompt conventions. This represents the final polishing phase of a well-considered improvement to email handling.
