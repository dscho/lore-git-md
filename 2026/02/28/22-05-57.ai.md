This is the third patch in a 4-part series adding path formatting capabilities to the new `git repo-info` command, building on existing path handling code from `git rev-parse`. The patch introduces a `--path-format` flag to control whether paths are displayed in absolute or relative form, matching the behavior of the same flag in `rev-parse`.

The implementation adds the new flag to both documentation and command-line options, with validation for invalid format values. The flag accepts "absolute" or "relative" values, stored in a new `path_format` enum (renamed from the original `format_type` in the refactored code). A test case verifies error handling for invalid format strings.

This continues the mechanical refactoring from previous patches, now exposing the shared path formatting through the `repo-info` interface. The changes are straightforward and maintain consistency with `rev-parse`'s behavior, though the thread context notes this design choice remains open for discussion. The patch includes appropriate documentation updates and test coverage for the new flag.

Key technical details for future reference: the `--path-format` flag values map to `PATH_FORMAT_CANONICAL` (absolute) and `PATH_FORMAT_RELATIVE` constants, with validation in `cmd_repo_info()`. The flag is passed through to `print_fields()` though not yet used there - that appears reserved for future patches to implement actual path formatting.
