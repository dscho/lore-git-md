This is the second patch in a two-part series addressing silent acceptance of duplicate long options in Git's option parsing. The patch adds runtime validation to detect duplicate long names and numerical options in command option tables, complementing the existing check for duplicate short names.

The implementation introduces `parse_options_check_harder()` which uses a `strset` to track long option names and report duplicates. To minimize performance impact, this check only runs when showing command usage (e.g. `--help`), not during normal operation. The patch also adds detection of multiple `OPTION_NUMBER` entries. Jeff King provided optimization suggestion (removing redundant `strset_contains()` call) which was incorporated.

The validation prevents issues like the duplicate `--batch-check` in `cat-file` and redundant `--stdin-packs` in `pack-objects` that Junio Hamano originally reported. Performance analysis shows the check adds negligible overhead (~10ms for 100,000 options) while providing systematic protection against option table mistakes. The series appears ready for merging with consensus that the benefits outweigh the minimal runtime cost.
