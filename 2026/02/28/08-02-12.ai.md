This is the third iteration of a feature patch for gitk's color customization, now ready for inclusion after addressing process feedback. The change adds a "Links" color option to gitk's Preferences dialog, allowing users to configure the color of hyperlinks in the interface - particularly useful for improving readability in dark themes.

The technical change remains unchanged from the v2 version that gitk maintainer Johannes Sixt approved, consisting of a 10-line addition to expose the previously hardcoded `linkfgcolor` variable through gitk's existing color configuration UI. The patch follows gitk's established patterns for color preferences, modifying `prefspage_colors` and `prefspage_set_colorswatches` procedures in the Tcl/Tk code.

The v3 iteration addresses process feedback about proper CC trailer usage in GitGitGadget workflows, removing the CC lines from the commit message while keeping them in the GitHub PR description. This clarification came from Johannes Sixt (Hannes), who also suggested simplifying the UI label from "Link color" to "Links" for better dialog phrasing. The patch has now navigated both technical review and contribution process requirements, appearing ready for merging with all feedback addressed.
