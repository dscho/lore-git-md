This thread follows Tian Yuchen's work to migrate Git's encoding-related functionality from global variables to repository-specific storage, part of the broader `the_repository` removal effort. The series has evolved through multiple versions, with v3 currently under discussion.

The changes focus on moving encoding settings (`git_commit_encoding` and `git_log_output_encoding`) into `struct repository`, affecting commit creation and display paths across 40+ files. Phillip Wood suggested a key architectural change - storing encodings directly in `struct repository` rather than `repo_settings` - which the author implemented in v3.

The latest patch (part 2 of 3) updates pretty-printing functions like `pretty_print_commit()` to take a repository parameter, modifying 14 files including core commands (`log`, `merge`, `stash`) and lower-level components. The changes maintain backward compatibility by falling back to `the_repository` where needed, following established migration patterns. While the test suite passes, reviewers will want to verify edge cases, particularly around NULL repository handling during the transition period.

This work builds on René Scharfe's patterns for global state removal and forms part of Tian's GSoC 2026 proposal. Remaining work includes migrating config parsing and eventually eliminating fallback paths once all callers are converted. The changes are mechanical but widespread, touching many commit formatting paths while preserving behavior during the transition.
