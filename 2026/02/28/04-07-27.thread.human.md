Tian Yuchen is working on migrating Git's encoding-related functionality from global variables to repository-specific storage as part of the broader effort to remove reliance on `the_repository` global. This is part of their Google Summer of Code 2026 project.

The series has gone through three versions, with the latest incorporating feedback from Phillip Wood to store the encoding configurations (`git_commit_encoding` and `git_log_output_encoding`) directly in `struct repository` rather than in the `repo_settings` structure. The changes affect commit creation and display paths across many files, with updates to functions like `commit_tree()` and `pretty_print_commit()` to take a `struct repository*` parameter.

The work is mechanically sound and follows established patterns for this type of migration, maintaining behavior during transition through fallbacks to `the_repository` where needed. While the core functionality is working and the test suite passes, some open questions remain about handling edge cases and eventually plumbing the repository pointer through the config callback machinery. The changes are widespread but focused, touching about 20 files across commit, log, rebase and merge subsystems.

This represents solid progress on the ongoing effort to eliminate global state from Git's codebase. The next steps will likely involve addressing any review feedback on the pretty-printing changes and working towards removing the remaining fallback paths once all callers are converted.
