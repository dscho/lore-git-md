This thread follows Tian Yuchen's work to migrate Git's encoding-related functionality from global variables to repository-specific storage, part of the broader `the_repository` removal effort. The series now stands at four patches, with the latest focusing on commit creation paths and pretty-printing functionality.

The core change moves encoding settings like commit and log output encodings from global variables into `struct repo_settings`, introducing new repository-aware APIs while maintaining backward compatibility. The most recent patch updates `pretty_print_commit()` and related functions to use repository context, affecting 15 files across various commands including `log`, `show-branch`, and the sequencer. The changes follow established patterns for global variable migration, with fallbacks to `the_repository` where context isn't yet available to ensure no behavior changes during transition.

While no reviews have been posted yet, the work aligns with René Scharfe's ongoing effort to eliminate `the_repository` global. The series appears technically sound based on test suite results, though some open questions remain about handling NULL repository pointers in all commit creation paths and final integration with other parts of the `the_repository` removal work. This is part of Tian's GSoC 2026 proposal to libify Git's global state.
