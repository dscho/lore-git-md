Martin Stensgård started this thread by requesting that Git preserve the deprecated `git whatchanged` command, which has been marked for deprecation since 2007 in favor of `git log --raw`. While acknowledging his personal usage of the command, he didn't provide technical arguments for keeping it beyond preference.

Kristoffer Haugsbakk responded with helpful documentation, clearly showing how to replace `whatchanged` with equivalent `git log` flags (--raw --no-merges -p) and suggesting alternative output formats like --stat that some users might prefer. He also noted that while Git 2.51.0 prevents aliasing built-in commands, version 2.52.0 will allow aliasing deprecated commands like whatchanged, giving users a migration path.

The discussion so far confirms that whatchanged remains a trivial wrapper in the codebase with negligible maintenance cost, though its functionality is fully covered by git log options. There hasn't yet been any maintainer input on whether the longstanding deprecation policy might be reconsidered, or if this will remain primarily a documentation and user education matter. The thread currently focuses on helping users transition rather than debating the deprecation itself.
