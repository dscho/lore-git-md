This is a performance optimization discussion in the ongoing thread about duplicate option validation in Git's option parser.

Jeff King (Peff) responds to René Scharfe's patch that adds runtime validation for duplicate long option names, suggesting a small but measurable optimization. The validation currently uses a `strset` to detect duplicates when showing command help (e.g. `--help`), adding about 10ms overhead for commands with many options. Peff proposes replacing the `strset` with a sorted array and binary search, which reduces the overhead by 2ms (20%) in his pathological test.

The thread has already converged on the approach of only performing validation during help display, so this is a minor tuning of an otherwise settled solution. Peff acknowledges the optimization may not be worth the added code complexity given the small absolute improvement (2ms is negligible for help output that already takes 5-10ms). The discussion shows the project's characteristic attention to performance details even for non-critical paths.
