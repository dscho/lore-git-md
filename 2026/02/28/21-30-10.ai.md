This is a documentation clarification in response to a user request about the deprecated `git whatchanged` command. Kristoffer Haugsbakk provides a more detailed explanation than the original deprecation warning, showing exactly how to replace `whatchanged` with equivalent `git log` flags and suggesting alternative output formats (`--stat`, `--name-only`) that may be more readable than the default `--raw` output.

The email notes that while Git 2.51.0 doesn't allow aliasing built-in commands, the upcoming 2.52.0 will permit aliasing deprecated commands like `whatchanged`. This provides a migration path for users who want to keep the command name while using the modern implementation.

The response is technically accurate but doesn't engage with the preservation request directly - it simply restates the deprecation rationale and offers workarounds. The thread remains at an early stage with no maintainer input yet on whether the deprecation policy might be reconsidered. The trivial implementation cost of keeping `whatchanged` (a small wrapper in builtin/whatchanged.c) means this is more a documentation and user-education issue than a technical burden.
