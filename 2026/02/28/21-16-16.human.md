Feature improvement for `git send-email` character encoding validation. 

Shreyansh Paliwal's v4 patch completes the refinement of `git send-email`'s handling of 8-bit character encodings, addressing all feedback from reviewers including maintainer Junio Hamano. The change replaces a simplistic length-based validation of charset names with proper semantic validation using Perl's `Encode::find_encoding()`, while maintaining backward compatibility.

The new flow is more robust and user-friendly: when non-ASCII content is detected, users are clearly prompted to "Declare which 8bit encoding to use [default: UTF-8]?" rather than the potentially confusing old prompt. Invalid encodings now trigger a specific warning and confirmation step. The implementation avoids introducing helper functions after Junio noted duplicate terminal-checking logic in v3, instead handling validation directly in the 8-bit encoding flow.

Ben Knoble gives final approval to this version, which has evolved through four iterations with input from multiple reviewers. The patch demonstrates good attention to detail - updating tests, maintaining style, and carefully considering the user interaction flow. This appears ready for merging as a clear improvement to `git send-email`'s handling of character encodings.
