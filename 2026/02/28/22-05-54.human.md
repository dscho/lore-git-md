This is a feature patch series introducing path-related fields to the new `git repo-info` command, building on existing path formatting functionality from `git rev-parse`.

The series (4 patches) starts by refactoring path-handling code from rev-parse into shared path.c functions, then adds a `--path-format` flag to repo-info similar to rev-parse's existing flag, and finally introduces `path.toplevel` as the first path-related field. The author notes this is just a starting point, leaving room for others to add more path fields later.

The motivation comes from uncertainty about how repo-info should handle path formatting by default. The approach taken here mirrors rev-parse's explicit `--path-format` option rather than baking in a default behavior. The author acknowledges this means repo-info can't return both relative and absolute paths in a single call, but considers this an acceptable tradeoff.

The patches look well-structured, with the first two doing necessary refactoring before adding new functionality. The series is based on recent master and appears ready for review, though the author explicitly invites discussion about the path formatting approach. Several GSoC contributors are CC'd as potential future contributors for additional path fields.
