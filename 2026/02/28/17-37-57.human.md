Bugfix for fsmonitor-watchman hook addressing error handling and protocol compliance issues. This is the second version of the patch, now with clarified authorship and incorporating feedback from the previous review.

Paul Tarjan fixes two issues in the fsmonitor-watchman sample hook and related test scripts:

1. The hook was checking the wrong variable (`$output->{error}`) after calling `watchman_clock()`, causing it to ignore errors from the watchman command. This is corrected to check `$o->{error}`.

2. The retry path was violating Git's fsmonitor protocol by outputting two clock tokens when it should only output one. The fix removes the recursive call to `launch_watchman()` that caused this, since the "/" flag already tells Git to do a full scan.

The patch also removes the now-unused `$retry` variable and associated logic that was only needed to prevent infinite recursion from the recursive call. These changes are applied consistently across the sample hook script and two test helper scripts in t/t7519/.

The changes appear straightforward and well-justified, with the second version incorporating Koji Nakamaru's suggestion to remove the unused retry logic. The fixes maintain backward compatibility while properly handling error cases and protocol requirements. This looks ready for maintainer approval.
