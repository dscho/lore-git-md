Feature improvement for `git send-email` character encoding validation. This patch from first-time contributor Shreyansh Paliwal addresses a usability issue in the email subject line encoding prompt, now in its fourth iteration with feedback from Ben Knoble and Junio Hamano.

The change replaces `git send-email`'s current length-based charset validation (which only checked for 4+ characters) with proper semantic validation using Perl's `Encode::find_encoding()`. The new flow first prompts for an encoding (defaulting to UTF-8 with clearer wording), then validates the input against known encodings before proceeding. Invalid encodings trigger a confirmation prompt rather than being silently accepted.

Key improvements in v4:
- Removed the `confirm_ask()` helper that was introduced in v3 after Junio noted duplicate terminal-checking logic
- Simplified the confirmation flow while maintaining the semantic validation
- Updated test expectations for the new prompt wording
- Keeps backward compatibility while improving the user experience

The patch appears well-tested and addresses all previous review feedback. Junio's latest comments suggest this is nearing final form, with just some minor style and wording refinements possibly remaining before merging.
