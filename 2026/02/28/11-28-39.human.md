This is a performance optimization discussion in the ongoing thread about detecting duplicate long options in Git's option parser. René Scharfe responds to Jeff King's proposed sorted-array approach with benchmark results showing that the current `strset` implementation performs better than sorting on René's M1 Mac (77.5ms vs 85.6ms for the sorted version). The difference is small enough that it likely doesn't justify the added complexity of maintaining a sorted-array solution.

The exchange demonstrates the careful attention to performance characteristics that Git contributors give even to infrastructure code that only runs during help display. Both approaches had already been shown to have negligible impact on normal command execution, with the validation overhead only appearing during `--help` output. The thread appears to be converging on the simpler `strset` approach as the final solution.
