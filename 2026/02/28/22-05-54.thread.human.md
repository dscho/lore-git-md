This thread centers on adding path-related fields to the new `git repo-info` command, with the initial implementation focusing on `path.toplevel`. The work builds on existing path handling from `git rev-parse` through shared infrastructure in `path.c`, including a new `strbuf_add_path()` function and standardized path format enums.

The discussion has largely settled on using a global `--path-format` flag (Option 1) rather than per-field naming variants (Option 3), as this keeps the API clean and predictable for scripting. Lucas Seiki Oshiro, the original implementer, reinforces this choice in his latest email, noting that most future path-related fields would live under the `path.*` namespace, making per-field variants unnecessarily verbose. Phillip Wood and others have helped clarify the historical context around naming choices ("working-tree" vs "toplevel") while supporting the current approach.

While the core design direction is now clear, some open questions remain about handling mixed-format output scenarios (which would require multiple command calls) and optimizing performance in submodule contexts. The thread has been careful to document the project's lineage and design constraints, with input from GSoC mentors and other contributors helping shape a solution that balances consistency with existing commands against `repo-info`'s specific needs. The implementation is well-tested and positioned for planned GSoC 2026 extensions to add more path-related fields.
