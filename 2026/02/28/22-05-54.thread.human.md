This thread discusses a 4-patch series adding path-related fields to `git repo-info`, building on existing path formatting infrastructure from `git rev-parse`. The core design has solidified around using a global `--path-format` flag, with consensus that this provides the cleanest approach while avoiding namespace bloat from per-field variants.

The implementation introduces new path handling utilities in `path.c`, including a `strbuf_add_path()` function and standardized format enums, with `path.toplevel` as the first supported field. While the high-level approach is settled, recent discussion has turned to optimization and architectural details. Tian Yuchen raised concerns about the efficiency of repeatedly calling `xgetcwd()` in scripts and whether `strbuf_add_path()` is properly abstracted. This follows earlier technical considerations from brian m. carlson about Windows path handling challenges.

Key participants including Lucas Seiki Oshiro (the original designer), Jayatheerth K, and Phillip Wood have converged on the global flag approach while working through implementation tradeoffs. The thread remains active on performance optimization strategies and proper code organization, particularly around shared path utilities, with Windows-specific considerations adding complexity. Planned GSoC 2026 work will extend this with additional path fields once these foundational questions are resolved.
