This thread discusses the implementation of path-related fields in `git repo-info`, focusing on how to best handle path formatting. The original proposal by Lucas Seiki Oshiro introduced a global `--path-format` flag, while subsequent discussions explored alternative approaches including Tian Yuchen's format modifiers and Ayush Jha's virtual fields proposal.

The core debate centers around balancing plumbing command simplicity with output flexibility. Junio Hamano has consistently advocated for keeping the design simple and plumbing-oriented, while contributors have proposed various ways to make the output more flexible without compromising maintainability. The latest discussion from Tian Yuchen suggests leveraging `ref-filter.c`'s existing format modifier infrastructure, arguing this provides a cleaner implementation path than creating new syntax while still allowing for future extensibility.

Key technical considerations include Windows path handling, performance of directory lookups, and how different approaches affect the `--all` output. While there's consensus on core functionality like the `PATH_FORMAT_*` enums and test infrastructure, the final decision on the formatting mechanism remains open. The discussion has evolved from initial implementation details to deeper architectural questions about how Git's plumbing commands should expose formatting options.
