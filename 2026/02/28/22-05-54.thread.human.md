This thread continues the discussion about implementing path format variants in `git repo-info`, with three distinct approaches now being compared in depth. The core question is how to best handle path formatting (absolute vs relative) in a maintainable way while meeting user needs.

Jayatheerth K recently provided a technical analysis showing that Tian Yuchen's `ref-filter.c` integration and Ayush Jha's virtual fields approach share the same underlying architecture - both separate field identity from presentation. However, Tian has now pointed out a key functional difference: Jayatheerth's virtual fields sketch uses global state for path format, which would prevent mixed-format outputs (like showing both absolute and relative paths in the same command). Supporting this would require per-field tracking similar to what `ref-filter.c` already provides.

Junio Hamano continues to advocate for plumbing simplicity, while the other contributors are working through the tradeoffs between the more flexible approaches. The discussion remains highly technical and constructive, with participants clearly understanding each other's positions. The key open question is whether the additional flexibility of per-field formatting (via either approach) justifies the added complexity over Lucas Seiki Oshiro's original global flag proposal. Performance measurements and Windows path handling considerations from brian m. carlson remain outstanding factors that may influence the final decision.
