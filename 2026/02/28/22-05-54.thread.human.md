This thread discusses a 4-patch series adding path-related functionality to `git repo-info`, part of Git's ongoing effort to migrate features from `git rev-parse` to dedicated commands. The work introduces a new path handling infrastructure with a `path.toplevel` field as the first implementation, building on shared `path.c` utilities.

The core design decisions are now settled, with consensus favoring a global `--path-format` flag (mirroring `rev-parse` behavior) rather than per-field variants. This keeps the interface clean while accepting that users needing different formats for different fields must make multiple calls. The implementation includes standardized enums for path formats and comprehensive test coverage.

Lucas Seiki Oshiro (the original author) and other participants (Jayatheerth K, Tian Yuchen, Ayush Jha, and Phillip Wood) have worked through several technical considerations: the scope of the new `strbuf_add_path()` helper function, performance of directory lookups in submodules, and how to handle format specifications in the API. The latest email from Lucas addresses Tian Yuchen's concerns about function abstraction levels while reinforcing the architectural approach.

The work originated from GSoC 2025 under Patrick Steinhardt's mentorship and is planned to expand with additional `path.*` fields in GSoC 2026. While some open questions remain about mixed-format output and performance optimizations, the core design is stable and ready for further implementation.
