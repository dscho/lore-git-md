Bugfix for the fsmonitor-watchman hook addressing two issues in the watchman integration. This is a follow-up to Paul Tarjan's initial patch that hasn't yet received review feedback.

The patch fixes:
1. A variable reference error where `$output->{error}` was checked instead of `$o->{error}` after calling `watchman_clock()`, which could silently swallow errors
2. A protocol violation where the hook would output two clock tokens during fallback to full scan instead of the single token specified by Git's fsmonitor v2 protocol

Koji Nakamaru, while noting limited experience with the Watchman backend, confirms the technical correctness of the fixes and suggests the `$retry` variable could potentially be removed as well since it may no longer be needed after these changes. The changes are contained to the sample hook script and related test infrastructure, making them low-risk.

The thread shows this straightforward bugfix is still awaiting review from fsmonitor maintainers despite being technically sound and ready for consideration. The fixes would be good candidates for the next release cycle as they address clear bugs in watchman integration without affecting core Git functionality.
