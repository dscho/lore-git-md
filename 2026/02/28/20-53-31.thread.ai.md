New thread summary:

This thread examines configuration behavior around submodule recursion settings, focusing on the interaction between `submodule.recurse` and the more specific `fetch.recurseSubmodules`/`push.recurseSubmodules` options. D. Ben Knoble identifies that these configs all write to the same internal variable, with parse order determining the final value rather than specificity. This leads to potentially surprising behavior where a later `submodule.recurse=true` can override an earlier `fetch.recurseSubmodules=on-demand`, contrary to user expectations that more specific settings should take precedence.

The discussion questions whether this behavior was intentional, noting limited discussion in the original patch series that introduced `submodule.recurse`. Key open questions include whether changing this to let more specific options win would be considered a breaking change, and if not, whether the current order-dependent behavior should at least be documented. The issue affects both fetch and push operations similarly, touching on Git's config precedence rules and the tension between backward compatibility and intuitive behavior. This appears to be starting a fresh discussion about whether the current implementation matches user expectations and potential paths forward.
