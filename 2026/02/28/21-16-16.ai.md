This is a feature improvement for `git send-email`'s character encoding handling, now in its fourth iteration. The patch comes from first-time contributor Shreyansh Paliwal and has undergone thorough review from Ben Knoble and Junio Hamano.

The change replaces `git send-email`'s current length-based validation of charset names (which only checked for 4+ characters) with proper semantic validation using Perl's `Encode::find_encoding()`. The new flow first prompts "Declare which 8bit encoding to use [default: UTF-8]?", then if an invalid encoding is entered, follows up with "'<encoding>' does not appear to be a valid charset name. Use it anyway [y/N]?".

Key technical improvements in v4 include removing a helper function that duplicated terminal-checking logic, making the confirmation prompt specific to the 8bit encoding flow, and maintaining backward compatibility while relaxing input rules (now accepting any non-blank string). The patch updates tests to match the new prompt wording and maintains all prior fixes from earlier versions.

The implementation uses Perl's core Encode module (already used elsewhere in Git) and preserves the non-interactive path unchanged. Junio has confirmed the approach is acceptable, and all prior review feedback has been addressed. This appears ready for merging as it improves both correctness (proper charset validation) and usability (clearer prompts).
