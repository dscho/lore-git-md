This is a review response from Junio C Hamano regarding a bugfix for `git clone`'s handling of `--revision` with protocol v0/v1. The original patch attempted to fix a segfault that occurs when using shorthand revision names (like `--revision master`) by adding a NULL check, but Junio suggests this may mask a deeper issue.

Junio points out that the `--revision` option is meant to create a repository with no branches and a HEAD detached at the specified commit. He questions whether the current fix is too narrow, as it might hide cases where `.peer_ref` should be set but isn't. Instead, he proposes a more comprehensive solution: splitting the connectivity check from the ref-writing logic in `update_remote_refs()`, and skipping the ref-writing entirely when `--revision` is used.

The review also notes the lack of test coverage for this behavior - we should verify not just that it doesn't segfault, but that the resulting repository has the expected state (no refs, detached HEAD at the correct revision). This suggests the patch needs significant reworking to properly implement the intended behavior of `--revision` rather than just papering over the immediate crash.
