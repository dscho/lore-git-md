This is a security-related patch in the ongoing thread about ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). Junio C Hamano is overriding the security team's position by proposing to disable the sideband filtering by default, despite production validation in Git for Windows and Red Hat.

The patch changes the default behavior to pass through all control characters (the historical behavior) rather than filtering potentially dangerous sequences. It modifies the documentation to reflect this opt-in approach and updates tests to explicitly enable filtering where needed. The implementation still allows granular control via `sideband.allowControlCharacters` configuration, but now requires explicit opt-in rather than being secure by default.

This represents a significant policy decision where maintainer preference for backward compatibility is overriding security hardening recommendations. The technical implementation remains sound, but the debate has shifted to whether security features should be opt-in or opt-out. Junio cites concerns about breaking existing deployments (particularly GitHub and Red Hat) and legacy character encodings as justification for this change.

The patch is part of a mature series that has undergone extensive review, but this final change effectively rolls back the security team's recommended defaults while preserving the underlying filtering capability for those who choose to enable it.
