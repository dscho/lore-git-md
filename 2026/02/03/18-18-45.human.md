This is a bugfix for `git stash`'s handling of ignored files when using the `--all` option. Pushkar Singh is responding to Elijah Newren's review feedback on a previous version of the patch.

The core issue is that `git stash push -a` currently removes ignored files even when `--no-overwrite-ignore` is specified, which contradicts the expected preservation of ignored files. The patch aims to make this behavior consistent with other parts of Git that respect `--no-overwrite-ignore`.

In this revision, Pushkar acknowledges two key points from Elijah's review: the patch doesn't actually remove a FIXME comment as originally claimed (now corrected in the commit message), and there's an open question about whether `--all` and `--no-overwrite-ignore` should be explicitly marked as incompatible rather than silently downgrading the behavior.

The technical implementation involves modifying how `stash` handles the interaction between include-untracked modes and the overwrite behavior in `builtin/stash.c`, with new regression tests added. While the patch has addressed some implementation details and test coverage based on earlier feedback, Elijah's more fundamental design questions about flag interaction remain outstanding.

This appears to be a well-motivated fix for a concrete issue, though the discussion suggests the solution may need another iteration to resolve the philosophical question about how to handle flags that appear to conflict in their intent.
