Bugfix for `git clone` addressing a segmentation fault when using `--revision` with protocol v0/v1. The issue occurs when cloning with a shorthand revision name (like `--revision master`) rather than a full refspec (like `--revision refs/heads/master:master`) while using the older protocol versions.

The root cause is that protocol v0/v1 fetches all references without filtering, which can leave `remote_head_points_at->peer_ref` NULL during reference updates. The patch adds a NULL check before dereferencing this pointer in `builtin/clone.c`. The commit message clearly explains the protocol version behavior differences and why this causes the segfault.

This is a straightforward fix for a real-world issue where shorthand revision names are commonly used with older protocols. The patch is well-explained but notably lacks a regression test case, which would help prevent future regressions. The v2 revision improves the commit message formatting while keeping the technical content unchanged.
