This is the fourth patch in Justin Tobler's series adding repository statistics to `git repo`. The patch focuses on identifying the commit with the most parents in the repository, which helps surface complex merge histories (like octopus merges).

The implementation:
- Adds tracking of parent counts when processing commits
- Extends the statistics table output to show the maximum parent count alongside the commit's OID
- Maintains the existing annotation system from previous patches to reference OIDs in the footer
- Includes thorough test updates to verify the new output format

The changes build cleanly on the infrastructure from earlier patches, keeping the same table-based presentation while adding the new metric. The test suite is updated to check both the human-readable table output and machine-readable key-value format.

This continues the series' pattern of incrementally adding useful repository metrics while maintaining backward compatibility. The implementation looks solid, with careful attention to memory management (freeing parsed objects when needed) and consistent formatting. The next patch in the series will presumably add tree entry count extremes to complete the statistics picture.
