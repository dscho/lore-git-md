This is a security patch introducing an escape hatch for the ANSI escape sequence sanitization in Git's sideband channel. It's part of a series addressing CVE-2024-32002 and CVE-2024-52005/GHSA-7jjc-gg6m-3329, which could allow malicious servers to inject terminal control sequences.

The patch adds a new configuration option `sideband.allowControlCharacters` that lets users opt out of the security protections when they specifically want to allow colored output from trusted remote servers. The default behavior (with the option unset) remains secure, sanitizing control characters to prevent terminal state corruption and input buffer injection attacks.

The implementation includes documentation, a simple boolean flag in the sideband code, and an extended test case verifying that the escape hatch works as intended. The test shows that without the config, color sequences are blocked, but with `sideband.allowControlCharacters` set, they pass through.

This is a carefully considered middle ground in an ongoing debate about security defaults versus backward compatibility. While Johannes Schindelin (the author) would prefer secure-by-default behavior, this patch provides flexibility for users who need it while maintaining protection for those who don't explicitly opt in. The implementation is clean and well-tested, with clear documentation of the tradeoffs.
