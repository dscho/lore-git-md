Maintainer override of security defaults for sideband control sequences. Junio C Hamano's patch changes the default behavior of Git's sideband channel sanitization, reverting to passing all control characters through by default rather than filtering potentially dangerous ANSI escape sequences. This overrides Johannes Schindelin's security-hardening approach that had been production-validated in Git for Windows and Red Hat for over a year.

The patch modifies the `sideband.allowControlCharacters` configuration to be entirely opt-in rather than having secure defaults, removing the `default` keyword that previously enabled basic ANSI color sequence filtering. Documentation is updated to reflect that no filtering occurs by default, with users needing to explicitly enable protections via `color`, `cursor`, or `erase` keywords. Test cases are adjusted to explicitly set `sideband.allowControlCharacters=color` to maintain their assertions about filtered behavior.

This change represents a maintainer decision prioritizing backward compatibility over security hardening, despite the security team's recommendations and production validation of the safer defaults. The implementation still supports URL-specific overrides via `sideband.<url>.allowControlCharacters`, though Junio has rejected middle-ground positions like allowing colors while blocking other sequences. The technical implementation remains sound, but the policy default shifts responsibility for security to end users.
