Thread identity: Platform compatibility discussion addressing const-correctness changes needed for glibc 2.43 and C23 standards compliance, focusing on string-handling patterns throughout Git's codebase. Originated with Collin Funk's patch for `git_find_last_dir_sep()` but expanded to broader architectural concerns.

Core problem: glibc 2.43 enforces C23 const-correctness for string functions, causing compilation warnings with GCC 15's default `-std=gnu23`. Approximately 65 problematic cases identified across the codebase, with two main categories: functions incorrectly modifying const parameters (notably in rev-parse internals) and incorrect constness propagation through string helpers like `skip_prefix()`. A critical case in `revision.c`'s `handle_revision_arg()` could segfault when modifying string literals containing "..".

Current status: Jeff King (Peff) has provided detailed analysis of scope and tradeoffs, proposing making copies of strings before modification in performance-non-critical paths like `handle_revision_arg()`. Toon Claes now proposes a C11 generic selection macro approach for `git_find_last_dir_sep()`, identifying 28 remaining const-correctness warnings. The Windows implementation (`win32_find_last_dir_sep()`) demonstrates one working approach using explicit casting. Discussion is converging toward recognizing this as a systemic issue requiring coordinated changes rather than piecemeal fixes.

Key technical details: Changes affect multiple subsystems including config.c, remote.c, scalar.c, strbuf.c, and revision.c. Peff identified three solution paths: (1) comprehensive const propagation, (2) selective casting (Windows-style), or (3) C11 generic selection macros. Toon's macro implementation provides a concrete example of approach (3), though he hasn't yet analyzed all 28 remaining warnings. The `revision.c` case shows a clear pattern where string copying is the safest approach. Peff also found and fixed a potential infinite loop in `http.c`'s cookie handling that these changes would expose.

Open questions: Whether to pursue a unified approach across all cases (macro-based vs. string copying vs. casting) or handle subsystems differently. The rev-parse modifications may need special handling strategy. Toon's macro approach needs evaluation against the remaining 28 cases, particularly in `builtin/rev-parse.c` and network-related files. No consensus yet on const propagation versus casting, though Peff's examples demonstrate a preference for clarity and safety over cleverness.
