This is part of the ongoing `the_repository` removal effort, specifically targeting the migration of the `core.sparseCheckout` configuration from a global variable to repository-specific storage. The patch is the second in a 3-part series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) that introduces `struct repo_config_values` to store repository-specific values.

The change moves the `core.sparseCheckout` config value into the new struct while maintaining the same behavior. This prevents potential issues where different repositories running in the same process could overwrite each other's settings. The patch updates 12 files across various commands (clone, grep, mv, sparse-checkout, worktree, etc.) to use the new repository-specific storage location.

The implementation follows the pattern established in previous patches of the series, using a `repo_config_values()` accessor with repository validity checking. The test suite passes with the new safety checks, confirming no existing double-initialization cases. Phillip Wood contributed naming improvements and commit message refinements.

This is a well-executed technical migration that demonstrates the viability of the approach for individual config variables, though broader architectural questions about initialization patterns remain open in the ongoing discussion.
