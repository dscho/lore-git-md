Bugfix for `git clone` addressing a segmentation fault when using `--revision` with older protocol versions (v0/v1). The issue occurs when cloning with a shorthand revision name (like `--revision master`) rather than a full refspec (like `--revision refs/heads/master:master`), causing a NULL pointer dereference during reference updates.

The patch adds a NULL check for `remote_head_points_at->peer_ref` in `builtin/clone.c` to prevent the crash. The problem stems from protocol v0/v1 fetching all references without filtering (unlike v2 which can filter based on the revision), leaving `peer_ref` NULL when a shorthand revision is used. While the fix is straightforward, the commit message could be clearer about the specific crash scenario and why it only affects older protocols. No test is included, which would help verify the fix and prevent regression.
