[Security] Final patch in the sideband sanitization series delays secure-by-default behavior to Git 3.0.

This sixth patch in Johannes Schindelin's v4 series modifies the previously proposed behavior to maintain backward compatibility in current Git versions while committing to stricter sanitization in Git 3.0. The change addresses concerns about breaking existing workflows that rely on unfiltered sideband output, particularly for colored pre-receive hooks.

The implementation introduces conditional compilation via `WITH_BREAKING_CHANGES` to toggle between permissive (current) and secure (future) defaults. Documentation now clearly warns about the impending behavior change in Git 3.0, where only ANSI color sequences will be allowed by default. Test updates verify both current and future behaviors through a new `TURN_ON_SANITIZING` test prerequisite.

Key technical details:
- Current versions maintain unfiltered output (`ALLOW_ALL_CONTROL_CHARACTERS`)
- Git 3.0 will default to allowing only color sequences (`ALLOW_ANSI_COLOR_SEQUENCES`)
- URL-specific overrides (`sideband.<url>.allowControlCharacters`) remain functional
- Test suite validates both modes through conditional assertions

This patch represents a compromise between security and compatibility, with the series having already undergone extensive production validation in Git for Windows and Red Hat systems. The architecture remains prepared for the Git 3.0 transition while minimizing disruption to existing deployments.
