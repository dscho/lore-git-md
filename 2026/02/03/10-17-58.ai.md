This is part of a security-focused patch series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). The patch introduces an escape hatch configuration option `sideband.allowControlCharacters` that lets users opt out of the security protections against malicious terminal sequences.

The change adds documentation for the new config option and implements the logic in `sideband.c` to bypass the sanitization when enabled. A test case verifies that with the option set, color control sequences from a remote server are passed through to the terminal, while they remain blocked by default. The implementation follows brian m. carlson's suggestion for an opt-out mechanism.

This patch represents a compromise position in the ongoing debate about security defaults versus backward compatibility. While the previous patches in the series implement strict sanitization by default, this one acknowledges some legitimate use cases for remote-controlled coloring (like highlighting urgent messages) by providing a way to disable the protections. The test demonstrates both the default secure behavior and the opt-in permissive mode.

The series has seen extensive real-world validation in Git for Windows and Red Hat deployments, with this particular patch balancing security concerns against practical needs for remote message formatting. The implementation leaves room for future policy adjustments while establishing the technical foundation for both secure and permissive operation modes.
