Bugfix for `git stash`'s handling of ignored files, addressing an inconsistency where `--no-overwrite-ignore` was not respected with `--all`. This is Pushkar Singh's third iteration of the patch, responding to Elijah Newren's technical concerns from v2.

The core issue is that `git stash push -a` would remove ignored files even when `--no-overwrite-ignore` was specified. The current implementation silently downgrades `INCLUDE_ALL_FILES` to just include-untracked in this case, preserving ignored files as requested. Elijah Newren had questioned whether this silent downgrade is the right approach or if the options should be explicitly marked incompatible.

Pushkar acknowledges this response doesn't yet address Newren's deeper concerns about the design implications of the silent downgrade behavior, though it does correct the commit message's mistaken claim about removing a FIXME comment. The v3 patch focuses on test improvements (using proper test helpers and covering both overwrite and preserve cases) while leaving the larger design questions open.

The implementation in `builtin/stash.c handles the interaction between include-untracked modes and the new overwrite behavior, with regression tests in t/t3905-stash-include-untracked.sh. Review feedback from Patrick Steinhardt, Karthik Nayak, and Kristoffer Haugsbakk on earlier versions has been incorporated, but Newren's substantive questions about option semantics remain outstanding. The patch appears technically sound but may need another revision to resolve the design questions before being ready for merging.
