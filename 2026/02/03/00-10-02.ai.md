This is the final patch in Justin Tobler's series to refactor object database (ODB) transaction handling as part of the ongoing ODB abstraction effort. The patch moves common transaction management logic - specifically the single-transaction-at-a-time enforcement and cleanup - from the files backend into the generic ODB layer.

The changes remove transaction state management from `object-file.c` (the files backend implementation) and consolidate it in `odb.c` (the generic ODB interface). Key modifications include:
- Moving the NULL check for existing transactions from files backend to `odb_transaction_begin()`
- Moving transaction pointer cleanup from files backend to `odb_transaction_commit()`
- Adding an assertion in the generic commit path to verify transaction matches the pending one
- Keeping the files-specific flush operations in the files backend while making them rely on the generic layer for state management

This completes the architectural shift where transaction handling is now properly abstracted - the ODB layer manages the transaction lifecycle while individual backends implement their specific commit behaviors through the callback mechanism introduced in patch 3/4. The changes maintain all existing behavior while making the codebase more maintainable for future pluggable backends.

The patch follows through on the direction agreed in earlier discussion, with Junio C Hamano and Patrick Steinhardt having reviewed and approved the approach. It builds cleanly on the prior work in the series and appears ready for merging as part of the broader ODB abstraction effort.
