CI infrastructure improvement to test contrib/ components during CI runs. This is a follow-up to the recent regression in the `git subtree` contrib script that was only caught after merging to the 'next' branch.

Junio C Hamano proposes adding a new `TEST_CONTRIB_TOO` flag that, when set, will run tests for contrib/ components during the standard test phase. The patch creates a new `contrib/Makefile` to coordinate testing across contrib/ subdirectories, initially targeting diff-highlight and subtree tests. The CI configuration is updated to enable this testing by default.

The change has already revealed several existing test failures in different configurations (breaking changes, SHA-256, leaks, reftable, ASAN) that were previously unnoticed because these tests weren't being run in CI. While some failures may be due to in-flight topics in the 'seen' branch, others likely represent long-standing issues in 'master'.

The patch is motivated by wanting to catch contrib/ regressions earlier in the development process, before they reach integration branches. This would prevent issues like the recent subtree regression from requiring reverts after merging. The implementation leaves room for future expansion to include more contrib/ components in the CI test coverage.
