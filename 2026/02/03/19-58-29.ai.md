This is a documentation clarification patch regarding `git format-patch`'s `--no-renames` option. Chris Packham notes that while the man page mentions this option can override configuration settings, it's unclear which specific configuration option controls rename detection for `format-patch`. The author wonders whether it shares the same configuration as `git diff` (diff.renames) and expresses a personal use case where they want different rename behavior between interactive diff viewing and patch generation.

The patch highlights a documentation gap - while the man page correctly states the option's effect, it doesn't specify what configuration it interacts with. This could be confusing for users who want to control rename detection differently across Git commands. The author's practical motivation is generating patches compatible with basic `patch` utility versions that don't handle renames.

For future reference in this thread, the key technical detail is that `git format-patch` does indeed use the same diff.renames configuration as `git diff`, but this isn't explicitly documented. The patch doesn't propose any code changes, just identifies an area where the documentation could be clearer about configuration interactions.
