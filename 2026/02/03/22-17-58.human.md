This is the final patch in Justin Tobler's 5-part series enhancing `git repo` with repository statistics. The patch adds tracking of the tree with the most entries, completing the set of metrics for identifying storage outliers.

The implementation introduces a new `tree_entries` field to the `largest_objects` struct and adds tree entry counting via a new `count_tree_entries()` helper that walks each tree object. The metric is integrated into all output formats (table, keyvalue, and nul) alongside the existing statistics for largest objects and most parents. Test coverage in t1901 verifies the new metric works across formats and maintains backward compatibility.

The series as a whole provides a comprehensive set of repository statistics that can help identify unusually large objects, complex commit histories, and now trees with many entries - all useful for repository maintenance and optimization. Each patch has built incrementally on shared infrastructure while maintaining clean separation of concerns. The changes are well-tested and maintain compatibility with both SHA-1 and SHA-256 repositories.
