This is part of the ongoing `the_repository` removal effort, specifically targeting the migration of the `core.sparseCheckout` configuration from a global variable to repository-specific storage in `struct repo_config_values`. The patch is the second in a 3-part series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder and Usman Akinyemi).

The change moves the `core_apply_sparse_checkout` global variable into the new `repo_config_values` struct embedded in `the_repository`, maintaining the same behavior while making it repository-specific. This prevents potential overwrites when multiple repositories operate in the same process. The patch updates 12 files across various commands (sparse-checkout, clone, worktree, grep, etc.) to use the new location via the `repo_config_values()` accessor.

The implementation follows the pattern established in previous patches of the series, with safety mechanisms including repository validity assertions and initialization tracking. Phillip Wood contributed naming improvements and commit message refinements. The change is mechanical but touches several key areas of Git's sparse-checkout functionality, demonstrating the migration pattern for repository-specific configurations.

This continues the broader architectural work to eliminate global variables as part of making Git's codebase more lib-ifiable, though as noted in the thread summary, questions remain about the necessity of runtime checking and proper initialization patterns across multiple repositories.
