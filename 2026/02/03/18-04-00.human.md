This is a bugfix patch for `git stash`'s handling of ignored files, addressing a long-standing issue where it would unconditionally overwrite ignored files during index updates. Pushkar Singh's v3 patch builds on previous feedback to improve the interaction between the `-a/--all` and `--no-overwrite-ignore` options.

The key change in this version is properly downgrading `INCLUDE_ALL_FILES` to just include-untracked when `--no-overwrite-ignore` is specified, preventing ignored files from being incorrectly removed. The patch also adds regression tests using `test_grep` and `test_path_is_missing` to verify both overwrite and no-overwrite behaviors.

This revision addresses several issues raised in previous rounds: fixing parse-options API misuse by consolidating to a single `OPT_BOOL`, improving test coverage, and incorporating documentation feedback. However, as noted in the thread summary, Elijah Newren has raised substantive questions about whether silently downgrading the include mode is the right design approach versus making the option incompatibility explicit.

The patch modifies `builtin/stash.c` to handle the include-untracked modes and new overwrite behavior, with corresponding test updates in `t/t3905-stash-include-untracked.sh`. While this version makes clear improvements, the discussion suggests it may need another iteration to resolve the design questions around option interactions before being ready for merging.
