This is a security patch addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin introduces a sanitization mechanism that replaces control characters in sideband messages with caret notation (e.g., `^[` for escape sequences) to prevent terminal state corruption and input buffer injection attacks.

The core change adds a `strbuf_add_sanitized()` function that filters control characters while preserving tabs and newlines. This affects all sideband output, including error messages from remote operations like `git clone`. The patch includes a test verifying that color control sequences from a pack-objects hook are properly sanitized.

This is part of a larger v4 series that evolved from production-tested implementations in Git for Windows and Red Hat. The current approach represents a compromise - while Schindelin advocates for secure-by-default behavior, maintainer decisions have shifted this to an opt-in model where users must explicitly enable control character filtering via `sideband.allowControlCharacters`. The debate continues about whether this security measure should be default in Git 3.0 versus remaining opt-in for backward compatibility.

The implementation is technically sound with thorough test coverage, though the policy decision around defaults remains contentious. The patch lays groundwork for future granular controls while providing immediate protection against the most severe injection risks. Security-conscious users should review their `sideband.allowControlCharacters` configuration regardless of which version they run.
