This is part of the ongoing ODB (object database) abstraction effort, specifically focusing on transaction handling for pluggable backends. The 4-patch series from Justin Tobler prepares the infrastructure for different ODB sources to implement custom transaction handling while keeping common logic shared.

The series makes several key changes: it adds ODB source awareness to transaction structures, introduces a base transaction structure with common fields and commit callback, moves files-backend-specific functionality into a new `struct odb_transaction_files`, updates all transaction-related code paths to use the new indirection patterns, and relocates common transaction management logic into the generic ODB layer. The implementation maintains existing files backend behavior while making the architecture more flexible for future backends.

Notable changes in this version include renaming the transaction type from `odb_transaction_loose` to `odb_transaction_files` (reflecting that it handles both loose objects and packfiles), and deferring `tmp_objdir` integration to a future series. The changes build cleanly on prior ODB abstraction work and have received positive feedback from both Junio C Hamano and Patrick Steinhardt, suggesting the series is in its final polishing phase before potential merging.

The patches touch core object storage code in `object-file.c`, `object-file.h`, `odb.c`, and `odb.h`, with careful attention to maintaining existing behavior while enabling future extensibility. This represents another step in the long-term effort to make Git's object storage layer properly abstract while keeping the files backend working as before. Future work will address unifying `tmp_objdir` usage under the ODB transaction API.
