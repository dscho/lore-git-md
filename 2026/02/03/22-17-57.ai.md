This is the fourth patch in Justin Tobler's 5-patch series enhancing `git repo` with repository statistics. The series focuses on identifying storage outliers by tracking various repository metrics.

This patch adds tracking of the commit with the most parents, useful for identifying complex merge histories (like octopus merges). The implementation:

1. Adds a new `parent_count` field to track maximum parent count in the `largest_objects` struct
2. Introduces `stats_table_object_count_addf()` helper for count-based metrics with OID annotations
3. Updates the commit processing in `count_objects()` to track parent counts
4. Extends both table and key-value output to show the commit with most parents
5. Updates tests to verify the new metric appears correctly in all output formats

The changes build cleanly on the object tracking infrastructure from earlier patches, maintaining the series' pattern of incremental improvements. The implementation carefully handles object parsing and memory management while preserving backward compatibility of existing output formats.

The patch includes thorough test coverage in t1901-repo-structure.sh, with updates to both the table format tests and key-value output verification. The remaining work in the series will add tree entry count extremes (patch 5/5).

Technical details to note for future reference:
- New struct field: `largest_objects.parent_count`
- New helper function: `stats_table_object_count_addf()`
- Modified parsing in `count_objects()` to track commit parents
- Output format changes in both table and key-value modes
- Test updates covering empty repo, populated repo, and format variations
