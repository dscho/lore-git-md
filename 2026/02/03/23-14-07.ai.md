This is a discussion about repository statistics in the `git repo` command, specifically regarding tracking commits with the most parents (octopus merges). Kristoffer Haugsbakk weighs in on Junio Hamano's skepticism about the operational value of this metric, noting that git-sizer (which inspired the feature) treats octopus merges as a low-priority concern. He points out that while the Linux kernel has a 66-parent commit (marked as significant in git-sizer), the project's own 10-parent merges are considered trivial.

The email highlights an open question about whether tracking "most children" would be more useful than "most parents" -- a suggestion Junio previously made. Kristoffer also raises an interesting historical question about why the project stopped doing 3+ parent merges, though this appears tangential to the current discussion. The exchange continues to shape the feature's direction, with maintainer feedback pushing toward more actionable metrics while acknowledging the current implementation's technical soundness.
