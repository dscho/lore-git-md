CI infrastructure improvement proposal from Junio C Hamano to catch contrib/ regressions earlier. This is a follow-up to the recent `git subtree` regression that slipped into the 'next' branch.

The patch adds a new TEST_CONTRIB_TOO flag that, when enabled, runs tests for contrib/ scripts (currently targeting diff-highlight and subtree) as part of the main test suite. The change includes modifications to the top-level Makefile, CI script, and a new contrib/Makefile to coordinate testing.

Initial CI runs with this change have already revealed existing test failures in both subtree (t7900) and diff-highlight (t9400) tests across various configurations (breaking changes, SHA-256, leaks, reftable, ASAN). While some failures may be due to in-flight topics in 'seen', others appear to be long-standing issues that went unnoticed because these tests weren't regularly run in CI.

Junio notes this is a first pass - a more sophisticated mechanism to automatically discover testable contrib/ components would be preferable, but this provides immediate value. The change demonstrates Git's CI infrastructure evolving in response to real-world issues, with the maintainer proactively addressing gaps in test coverage.
