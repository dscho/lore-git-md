Security patch adding granular control over ANSI escape sequence filtering in Git's sideband channel. This is part of an ongoing series addressing CVE-2024-32002 and CVE-2024-52005/GHSA-7jjc-gg6m-3329, which malicious ANSI sequences could corrupt terminal state or hide attack traces.

Johannes Schindelin's patch expands the `sideband.allowControlCharacters` configuration to support comma-separated values, adding `cursor` and `erase` options alongside the existing `color` and `default` settings. This allows selective whitelisting of cursor movement and character-erasure sequences that some legitimate `pre-receive` hooks may use, while maintaining security by default. The implementation carefully validates sequences against the configured permissions, replacing blocked control characters with caret notation (e.g., `^[`).

The change comes after production validation in Git for Windows and Red Hat environments, and includes thorough test coverage verifying that color sequences pass through by default while other control characters remain sanitized. The debate around default behavior continues, with Schindelin advocating secure-by-default while others prefer opt-in models, but this patch provides the technical foundation to support either approach.
