This is a follow-up discussion in the ongoing thread about adding repository statistics to `git repo`. Junio C Hamano responds to Kristoffer Haugsbakk's question about why the Git project stopped using octopus merges (merges with 3+ parents).

Junio explains that octopus merges lost their appeal because they make bisection more difficult, and while they were initially interesting to visualize in tools like gitk, the novelty quickly wore off. This reinforces the earlier skepticism in the thread about tracking "commits with most parents" as a useful statistic, as it aligns with Junio's view that such merges are more of a curiosity than a meaningful metric.

The exchange further solidifies the emerging consensus that the patch series should likely drop the octopus merge tracking in favor of more operationally relevant statistics like "most children" commits. Junio's response provides historical context about why the Git project itself moved away from this practice, adding weight to the argument against including it in the new `git repo` feature.
