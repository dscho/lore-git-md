This is a security-related patch in Johannes Schindelin's series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). The patch implements per-URL configuration for control character sanitization, allowing different security policies for trusted vs untrusted remotes.

The key addition is URL-scoped configuration via `sideband.<url>.allowControlCharacters`, mirroring Git's existing `http.<url>.*` pattern. This lets users maintain strict sanitization for public repositories while allowing control sequences (like ANSI colors) for trusted internal servers. The implementation introduces `sideband_apply_url_config()` which is called when transports are initialized, applying URL-specific settings.

The patch maintains backward compatibility with existing boolean/string configurations while adding granular control. Test coverage verifies URL-specific overrides work as expected, showing how a repository can be configured to allow all control sequences for a specific URL while maintaining stricter defaults elsewhere.

This represents a compromise position in the ongoing security debate - it preserves the secure-by-default approach while addressing the practical need for some servers to send formatted error messages. The implementation is production-tested, having been deployed in Git for Windows and Red Hat systems for months.
