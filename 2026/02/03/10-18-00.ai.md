This patch expands the control sequence handling in Git's sideband communication channel, part of the ongoing security hardening against ANSI escape sequence injection (CVE-2024-32002, CVE-2024-52005). Johannes Schindelin's implementation now allows finer-grained control over which ANSI sequences pass through, adding support for cursor movement and character erasure sequences via a new comma-separated configuration syntax for `sideband.allowControlCharacters`.

The patch introduces three new bitmask flags (`ALLOW_ANSI_CURSOR_MOVEMENTS`, `ALLOW_ANSI_ERASE`, and `ALLOW_ALL_CONTROL_CHARACTERS`) alongside the existing color sequence handling. The configuration parser accepts combinations like `cursor,erase` to selectively permit these potentially dangerous sequences that could otherwise be used to hide malicious activity in terminal output. The implementation carefully validates sequences against the allowed set, with comprehensive documentation of supported ANSI codes in the source comments.

New test cases verify the default behavior continues to block non-color sequences while demonstrating how to enable the additional sequence types. The test harness includes a CSI (Control Sequence Introducer) decoder to validate terminal output behavior. This maintains security while accommodating legitimate use cases like server-side hooks that may use cursor positioning for progress displays.

The changes build on the production-validated v5 series that has been running in Git for Windows and Red Hat environments. This iteration represents a middle ground in the ongoing debate between strict security (Schindelin's position) and usability (brian m. carlson's preference for opt-in), with the architecture now supporting both immediate needs and potential future policy shifts for Git 3.0.
