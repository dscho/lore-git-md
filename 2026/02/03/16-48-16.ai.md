Bugfix for the `git subtree` contrib script, addressing validation of `--prefix` argument during split operations. This is the fourth iteration of a patch that was previously reverted from the 'next' branch due to a regression.

The patch fixes an inconsistency where `git subtree split` validated the prefix path against the working tree rather than the specified commit. The new version uses `git cat-file -e` to check path existence in the target commit, which allows splitting subtrees that exist in historical commits but have since been removed from the working tree. The fix preserves the original error message format to maintain compatibility with existing tests.

Key changes in v4:
- Switches from `git ls-tree -d` (used in v3) to `git cat-file -e` for commit-based validation
- Maintains the exact error message text that test case 17 expects
- Adds a new test case that splits a subtree which exists in the target commit but not in the working tree

The patch touches:
- `contrib/subtree/git-subtree.sh` - adds commit-based validation for split operations
- `contrib/subtree/t/t7900-subtree.sh` - adds test coverage for the fixed behavior

This version appears to address the regression reported by Josh Steadmon while maintaining the original fix's intent. The use of `cat-file` rather than `ls-tree` suggests the validation is now more robust against edge cases in the repository state. The patch is part of a broader effort to improve testing of contrib/ components in CI, which has already uncovered several previously unknown issues.
