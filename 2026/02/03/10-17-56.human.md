Security patch series introducing ANSI escape sequence sanitization for Git's sideband channel, delayed until Git 3.0.

Johannes Schindelin proposes a 6-patch series to address CVE-2024-32002 and CVE-2024-52005/GHSA-7jjc-gg6m-3329, which involve ANSI escape sequence injection vulnerabilities in Git's sideband channel. The patches would sanitize control characters by default while allowing configurable exceptions, but Schindelin now proposes delaying the security-hardened defaults until Git 3.0 to avoid breaking existing workflows that rely on the current behavior.

The implementation introduces several configuration options:
- `sideband.allowControlCharacters` (boolean/string values)
- Per-URL overrides via `sideband.<url>.allowControlCharacters`
- Granular control over specific ANSI sequence types (color, cursor movement, erase)

The series has seen significant iteration (now at v4) with input from multiple contributors. While the technical implementation appears sound, there's ongoing debate about the security philosophy - Schindelin advocates for secure-by-default behavior while others prefer maintaining backward compatibility. The current proposal phases the change to give users time to adapt, with the stricter defaults planned for Git 3.0.

The patches include comprehensive tests (`t/t5409-colorize-remote-messages.sh`) and documentation updates. The implementation has already seen production validation in Git for Windows and Red Hat environments. This represents a mature security fix that's being carefully staged to balance protection with compatibility concerns.
