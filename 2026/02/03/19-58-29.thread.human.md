This thread discusses a documentation clarification for `git format-patch`'s `--no-renames` option. Chris Packham noticed that while the man page explains this option can override configuration settings, it doesn't specify which configuration option actually controls rename detection for `format-patch`. 

The key insight is that `git format-patch` shares the `diff.renames` configuration with `git diff`, though this relationship isn't explicitly documented. Chris points out a practical use case where someone might want different rename behavior when interactively viewing diffs versus generating patches - particularly when creating patches that need to work with older versions of the `patch` utility that don't handle renames well. 

The thread so far identifies this documentation gap but doesn't propose any code changes. The discussion focuses on making the configuration interaction clearer in the man pages to help users understand and control rename detection behavior across different Git commands.
