This is a security patch addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). Johannes Schindelin introduces basic sanitization of control characters in remote output, replacing them with caret notation (e.g., `^[` for escape sequences). The change prevents malicious servers from corrupting terminal state or hiding information via crafted sideband messages.

The patch adds a new `strbuf_add_sanitized()` function that filters control characters while preserving tabs and newlines, and updates the sideband coloring logic to use it. A new test verifies that color sequences from a remote hook are properly sanitized. This is the first in a series that will later introduce more granular controls via configuration.

Notably, this implementation represents a security hardening that has already seen production validation in Git for Windows and Red Hat deployments. While the current version makes sanitization opt-in (via `sideband.allowControlCharacters`), Schindelin argues this should eventually become the default behavior in Git 3.0. The patch is well-tested and addresses a real vulnerability, though the thread reveals ongoing debate about the right balance between security and backward compatibility.
