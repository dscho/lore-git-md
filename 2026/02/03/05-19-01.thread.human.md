This thread addresses const-correctness changes required for Git to compile cleanly with glibc 2.43 and C23 standards, particularly around string-handling functions. The discussion began with Collin Funk's patch for `git_find_last_dir_sep()` but has revealed broader architectural considerations affecting about 65 cases across the codebase.

Jeff King (Peff) has been instrumental in analyzing the scope, identifying three potential solution paths: comprehensive const propagation, selective casting (as used in Windows implementations), or C11 generic selection macros. A particularly concerning case in `revision.c` could potentially segfault when modifying string literals containing "..", leading Peff to recommend string copying in performance-non-critical paths. Toon Claes later contributed a C11 generic macro approach for `git_find_last_dir_sep()`, which Peff found acceptable for supporting compilers though cautioned against over-engineering.

Collin Funk's latest email provides important technical context about glibc's `__GLIBC_USE(ISOC23)` macro behavior, explaining it evaluates true under C23 standards flags or when `_GNU_SOURCE` is defined. He demonstrates a workaround involving undefining `__glibc_const_generic` after including system headers, noting this issue has affected multiple GNU projects. Collin confirms two simple fixes are already in Junio's "next" branch with another pending review, and he's open to others contributing solutions for the remaining cases.

The discussion continues to balance standards compliance with practical considerations, now also accounting for compiler-specific behaviors and backward compatibility. While no final decision has been reached on a unified approach, the conversation has produced concrete technical insights and several patches are already making progress through the integration branches.
