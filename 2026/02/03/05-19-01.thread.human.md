This thread addresses compiler compatibility changes needed for glibc 2.43's stricter C23 const-correctness enforcement. Collin Funk started with a patch modifying `git_find_last_dir_sep()` to return `const char*` to match `strrchr()`'s behavior, updating several callers. The change is straightforward but hints at a larger effort needed across the codebase.

Jeff King (Peff) has now responded with deeper analysis, estimating about 65 similar fixes may be required. He identifies two particularly tricky patterns: functions that modify const parameters internally (like some rev-parse code) and constness propagation issues through helper functions. For the specific case, Peff questions whether adding const only to cast it away later is ideal, suggesting alternatives like macro implementations or type-generic declarations similar to what Windows already does. His response indicates this will be a non-trivial effort requiring careful judgment about where to enforce constness versus using targeted casts, with implications across multiple subsystems handling string manipulation. The discussion is just beginning, with more patches and review likely needed to fully address the compatibility issues.
