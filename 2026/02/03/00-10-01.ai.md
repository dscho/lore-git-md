This patch is part of the ongoing ODB (object database) abstraction effort, specifically focusing on making transaction handling generic across different storage backends. It's the third in a 4-patch series from Justin Tobler that builds on prior work by Patrick Steinhardt.

The key change in this version is restructuring `struct odb_transaction` to use a callback-based approach, where each backend can provide its own commit implementation. The files backend's specific transaction handling moves into a new `struct odb_transaction_files` that inherits from the base transaction structure. The commit operation is now invoked through the callback rather than directly calling files-backend functions.

The implementation maintains all existing behavior while making the architecture more flexible for future pluggable backends. Changes touch `object-file.c`, `object-file.h`, `odb.c`, and `odb.h`, with careful attention to maintaining the single-transaction-at-a-time invariant. The patch follows through on earlier discussion about making `tmp_objdir` an implementation detail of the files backend rather than exposing it in the generic API.

This continues the series' progression toward properly abstracting Git's object storage layer while preserving current functionality. The changes are well-contained and build cleanly on prior work, with Junio C Hamano and Patrick Steinhardt having provided detailed review feedback that's been incorporated. The patch appears ready for merging as part of this architectural improvement effort.
