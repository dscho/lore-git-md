This is a security-related follow-up in the ongoing discussion about ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). Johannes Schindelin strongly disagrees with Junio Hamano's decision to make the security sanitization opt-in rather than enabled by default.

Schindelin argues that terminal emulators cannot distinguish between legitimate and malicious control sequences, making sanitization at the Git level essential. He notes his implementation already allows color sequences by default while blocking more dangerous ones (window title changes, cursor movement). The concern about Japanese ISO encodings is dismissed as theoretical since sideband messages are prefixed with ASCII.

The core contention is over security philosophy: Schindelin advocates for secure-by-default principles, warning that opt-in configurations leave most users unprotected. He proposes a compromise where sanitization remains off in Git 2.x but becomes the default in Git 3.0, giving users time to adapt while committing to stronger security long-term.

The technical implementation itself is not in dispute - the debate centers on policy defaults. Schindelin's position reflects a security-first mindset, while Junio's decision prioritizes backward compatibility. The email invites security experts to weigh in on the principle of sanitizing untrusted input before interpreter exposure.
