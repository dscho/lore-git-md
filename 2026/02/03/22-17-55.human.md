Feature addition to `git repo` for tracking largest repository objects.

This is the second patch in Justin Tobler's series to enhance `git repo` with repository statistics. Building on the refactoring from patch 1, it adds tracking of the largest objects in the repository by type (blob, trees, commits, and tags), showing both their sizes and OIDs. The implementation:

1. Introduces new data structures to track maximum sizes per object type
2. Updates the counting logic to compare each object's size against current maximums
3. Adds the new statistics to all output formats (table, key-value, and nul-delimited)
4. Includes comprehensive test coverage in t1901 that verifies the output matches expected values

The change is purely additive - existing statistics remain unchanged while the new largest-object tracking is layered on top. The table output shows sizes only (for space reasons), while the machine-readable formats include both sizes and OIDs. The implementation looks clean and well-tested, with clear progression from the series' stated goal of helping users spot storage outliers.

This continues the series' focus on repository introspection, complementing existing size reporting in `git repo`. The changes are logically contained and the patch follows Git's incremental development style well. Reviewers will want to verify the object size calculations match expectations, particularly for edge cases around very large objects.
