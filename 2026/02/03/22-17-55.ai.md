Feature addition to `git repo` command for repository statistics.

This is the second patch in Justin Tobler's series to enhance `git repo` with repository statistics. Building on the refactoring from patch 1, this change adds tracking of the largest objects in the repository by type (blob, trees, commits, and tags). The implementation records both the size and OID of the largest object found for each type during iteration.

The patch modifies `builtin/repo.c` to introduce a new `largest_objects` struct that tracks maximum sizes and their corresponding OIDs. It updates the statistics output formats (table, keyvalue, and nul) to include this new information. The table format shows just the sizes while the keyvalue/nul formats include both sizes and OIDs. Test coverage in t1901 verifies the output matches expectations for both empty and populated repositories.

The change is purely additive and maintains backward compatibility with existing output formats. The implementation follows the pattern established in the first patch, keeping the statistics gathering within the object iteration loop. The tests demonstrate the new functionality works correctly with SHA-1 hashes (a follow-up will likely address SHA-256 compatibility).

This continues the series' focus on helping users identify storage outliers in their repositories. The next patches will add commit parent count and tree entry count statistics, building on this same infrastructure. The careful separation of concerns and incremental approach makes the series easy to review.
