Git apply --directory path handling fix

Thread identity: Bugfix for `git apply --directory` option when given paths starting with `./`. Originating author not yet identified from this first email.

Core problem: When `git apply --directory=./some/sub` is used, the `./` prefix causes the command to fail with an invalid path error, despite this being a common and valid path notation. The behavior differs from non-prefixed paths.

Solution: Strip `./` prefix from directory paths before processing. Changes are minimal (4 lines in `apply.c`) and focused specifically on this edge case.

Technical details: Modifies path handling in `apply.c`. Adds test case in `t4128-apply-root.sh` to verify fixed behavior matches non-prefixed paths. Test is placed alongside existing `--directory` option tests.
