Git apply --directory path handling fix

Core problem: When `git apply --directory=./some/sub` is used, the `./` prefix causes the command to fail with an invalid path error, despite this being common notation. The behavior differs from non-prefixed paths.

Current status: Joaquim Rocha's v2 patch implements Patrick Steinhardt's suggestion to use `strbuf_normalize_path()` for comprehensive path normalization rather than just stripping "./" prefixes. This handles multiple edge cases while remaining minimal (4 lines in `apply.c`). Discussion now focuses on whether this generalization is justified versus a narrower fix.

Tests in `t4128-apply-root.sh` verify all cases. Performance impact remains unmeasured but likely negligible given the function's existing use elsewhere.
