This is a bug report about potentially surprising behavior in Git's date parsing for `--since` arguments. Gregor notes that when given a date without an explicit time (like "2026-02-09"), Git uses the current local time rather than defaulting to 00:00:00 as users might expect. This causes the same command to return different results depending on when it's run.

The email includes a technical analysis tracing the behavior to `approxidate_careful()` in date.c, where the fallback path inherits the current time when parsing incomplete dates. Gregor asks whether this is intentional (given Git's "human-friendly" parsing goals) or a bug that should be fixed, suggesting either documenting the behavior or changing it to use midnight by default.

The issue appears genuine and well-analyzed, though the impact is limited to cases where users rely on date-only `--since` arguments without realizing the time component matters. The proposed workaround (explicitly specifying midnight) is correct. This seems like a reasonable candidate for either a documentation patch or a behavioral change, depending on maintainer preference.
