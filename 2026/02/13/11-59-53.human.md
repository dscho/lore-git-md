This is the first patch in a 2-part RFC series refactoring how Git represents the primary worktree in the worktree API. The patch changes the primary worktree's internal identifier from NULL to "/" to eliminate ambiguity in how callers reference it.

Currently, the primary worktree can be represented in three ways: NULL pointers, worktree structs with NULL id fields, and "/" keys in ref-store maps. This leads to scattered NULL checks and implicit global access patterns. The patch modifies `get_main_worktree()` to explicitly set `wt->id = "/"` and updates related functions to check for this identifier rather than NULL.

Key changes include:
- Adding "/" as the primary worktree's ID in `get_main_worktree()`
- Updating `is_main_worktree()` to check for "/" instead of NULL id
- Removing NULL checks in favor of `is_main_worktree()` calls
- Adding validation to prevent "/" from being used as a linked worktree name

The changes are mechanical but touch core worktree handling code. As an RFC, the author is seeking feedback on whether this standardization approach is the right direction before proceeding. The patch appears well-structured and focused on its goal of eliminating NULL-based primary worktree representations.
