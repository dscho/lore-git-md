This is a feature patch in Patrick Stehtardt's ongoing series improving the `git history` command's UI. The patch replaces the technical `--ref-action=print` option with a more user-friendly `--dry-run` flag while maintaining the same functionality.

The key change is making the dry-run behavior more discoverable and flexible. The new `--dry-run` works with both `--ref-action=head` and `--ref-action=branches`, allowing users to test either mode. Junio C Hamano confirmed the implementation correctly creates commit objects in the ODB during dry-run while skipping reference updates, ensuring repository integrity if users later point refs to those objects.

The patch maintains the command's safety by keeping the object creation behavior unchanged - it just exposes the functionality through a clearer interface. Patrick acknowledges Junio's suggestion to document that objects are still created during dry-run, indicating he'll update the documentation accordingly. The change aligns with the series' goal of making `git history` more approachable while preserving its technical correctness.
