This is the final patch in Abraham Samuel Adekunle's series adding `--no-auto-advance` functionality to Git's interactive patch commands (`add -p`, `checkout -p`, `reset -p`, `stash -p`). The patch implements inter-file navigation when auto-advance is disabled, allowing users to move between files with '>' and '<' keys after deciding all hunks in a file.

The key changes include:
1. Adding navigation commands to the help text and permitting them when `--no-auto-advance` is active
2. Modifying `patch_update_file()` to handle the navigation keys and prevent auto-advance when the flag is set
3. Adding a hunk summary display when all hunks in a file are decided and the user requests help
4. Ensuring patches are applied to all files at the end when using `--no-auto-advance`

The implementation includes extensive test coverage verifying:
- Basic navigation between files
- Changing hunk decisions after navigating away and returning
- Hunk summary display behavior
- Selective staging across multiple files
- Proper rejection of invalid flag combinations

The patch builds on the refactoring work from earlier in the series, particularly the `apply_patch()` extraction in patch 3/4. It maintains backward compatibility by defaulting to auto-advance behavior when the new flag isn't used. The changes are focused in `add-patch.c` with corresponding test additions in `t3701-add-interactive.sh`.

This completes the series' goal of giving users finer control during multi-file interactive sessions while preserving the familiar default behavior. The implementation appears thorough, with careful attention to edge cases and clear test coverage of the new functionality.
