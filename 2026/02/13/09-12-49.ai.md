This is the third patch in Patrick Steinhardt's v2 series improving the `git history` command's interface. The patch focuses on making the dry-run functionality more user-friendly by replacing the technical `--ref-action=print` option with a clearer `--dry-run` flag.

The key changes are:
1. The old `--ref-action=print` mode is removed entirely
2. A new `--dry-run` option is added that works with both `--ref-action=head` and `--ref-action=branches`
3. The implementation consolidates ref update handling into a new `handle_ref_update()` helper that either prints updates or executes them via a transaction
4. Documentation is updated to explain the new `--dry-run` behavior and remove references to the old print mode
5. Tests are updated to verify the new dry-run behavior works correctly with both ref-action modes

The patch maintains all the existing functionality while making it more discoverable and intuitive for users. The implementation is clean, with proper error handling and resource cleanup. The test coverage verifies both the printing behavior and that no actual refs are modified during dry-run.

This change aligns with the series' goal of improving the user experience of `git history` by replacing technical plumbing-style options with more intuitive porcelain commands. The patch builds on the architectural improvements from earlier in the series while keeping the clean separation between validation and execution phases.
