This is part 5 of Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering, now at version 2. The series aims to make type-based filtering more efficient by avoiding full parsing of non-matching values.

This specific patch introduces gentle parsing for boolean config values when using `--type=bool`. Previously, encountering a non-boolean value would cause the command to fail. Now it quietly skips such values while still showing properly formatted boolean values ("true"/"false") for valid entries. The change moves boolean formatting into a dedicated `format_config_bool()` helper function that handles both strict and gentle parsing modes.

The patch includes test updates showing the new behavior - where previously `git config list --type=bool` would fail on non-boolean values, it now succeeds while only outputting the valid boolean values. This maintains consistency with the series' goal of making type filtering more efficient while preserving the expected output format.

The change follows the pattern established in earlier patches for other config value types, continuing the incremental refactoring approach that has been well-received in the thread.
