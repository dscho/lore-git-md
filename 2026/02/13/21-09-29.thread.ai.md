Subject: Bug report - Git's `--since` option uses current time instead of midnight for date-only inputs  
Core problem: Inconsistent date parsing behavior where date-only strings (without explicit time) default to current local time rather than midnight (00:00:00) in `--since` operations.  

Technical details:  
- Root cause traced to `date.c` functions `approxidate_careful()` and `approxidate_str()`  
- Current implementation initializes time fields from local time when parsing date-only strings  
- Creates non-deterministic behavior as results vary based on command execution time  

Proposed resolutions:  
1. Document current behavior as intentional  
2. Patch to standardize on midnight default

Impact: Affects scripts/automation relying on date-only `--since` specifications
