Subject: Bug report - Git's `--since` option uses current time instead of midnight for date-only inputs  
Core problem: Date-only strings in `--since` operations default to current local time rather than midnight (00:00:00), confirmed as intentional design from Git's early history.  

Technical details:  
- Behavior implemented in `date.c` functions `approxidate_careful()` and `approxidate_str()`  
- Time fields initialized from local time when parsing date-only strings  
- Design established in 2005 by Linus Torvalds (reference: Pine.LNX.4.64.0511171505080.13959@g5.osdl.org)  

Resolution:  
- Maintainer Junio C Hamano confirmed current behavior is working as designed  
- Design rationale: using current time makes common queries like "what happened in last 24 hours" more convenient  
- Explicit 00:00:00 specification required for midnight behavior  
- Not a bug but a longstanding practical default for human use cases  

Impact:  
- Scripts/automation using date-only `--since` must account for time-of-execution variance  
- Documentation could be updated to clarify this edge case  

Status: Closed - design confirmed, no code changes planned  
Key participants:  
- Gregor (original reporter with technical analysis)  
- Junio C Hamano (maintainer confirming historical intent and rationale)  

Related context:  
- Original 2005 design discussion establishes this as longstanding behavior  
- Current implementation matches historical precedent in `date.c` internals  
- Both conventions (current time vs midnight) considered technically sound, with current time chosen as more practical default
