This is the first patch in Patrick Steinhardt's v2 series improving the `git history` command's validation flow. The patch refactors the command to perform revwalk validation checks before* prompting the user for input, preventing wasted effort when the operation would fail anyway.

The key change splits the existing `handle_reference_updates()` function into two parts: `setup_revwalk()` for validation and `handle_reference_updates()` for the actual reference updates. This ensures checks like verifying the rewritten commit is an ancestor of HEAD happen before the user writes a commit message. The patch updates one test to use `-c core.editor=false` to avoid actually launching an editor when testing the failure case.

This is a clean refactoring that maintains all existing functionality while improving the user experience. The change aligns with the series' goal of making `git history` more robust and user-friendly. The patch builds on the architectural improvements from v1 series while incorporating Junio Hamano's feedback about string array management.
