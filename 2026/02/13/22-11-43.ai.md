This is the third patch in a four-part series introducing `--auto-advance` functionality for interactive patch selection commands (`git add -p`, `checkout -p`, `reset -p`, `stash -p`). The patch refactors the patch application logic into a new `apply_patch()` function to enable consistent behavior when users change their minds about hunks during interactive sessions.

The core change moves the patch application code from `patch_update_file()` into a reusable function, preparing for the all-or-none application behavior that will be implemented in the next patch. The refactoring maintains identical behavior - when hunks are marked for use, they get applied via either direct checkout logic or by piping to `git apply`, followed by index refresh. The key motivation is fixing an edge case where changing a hunk decision from USE to SKIP after visiting another file wasn't properly registered.

The patch touches only `add-patch.c`, extracting 27 lines into the new `apply_patch()` function while keeping the same control flow. This is a mechanical refactoring with no behavior change yet - the actual all-or-none functionality comes in patch 4/4. The series has evolved through multiple iterations (now at v4) with careful attention to backward compatibility and user experience in interactive sessions.
