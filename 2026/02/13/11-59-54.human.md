This is the second patch in Shreyansh Paliwal's RFC series to standardize how Git represents the primary worktree in the worktree API. The series aims to eliminate inconsistent representations (NULL pointers, NULL id fields, and "/" keys) by consistently using worktree structs with wt->id set to "/".

The patch updates various functions that currently accept NULL as a worktree parameter to instead use the new `get_worktrees_repo()` helper to access the primary worktree. Key changes include:

- Introducing `get_worktrees_repo()` to get worktrees for a specific repository rather than relying on `the_repository` global
- Modifying `worktree_git_path()` to use `wt->repo` instead of taking a separate repository parameter
- Updating callers across builtins (fsck, worktree), refs handling, and revision walking to use the new helper
- Replacing NULL checks with `is_main_worktree()` where appropriate

The changes are mechanical but touch core worktree code paths. As an RFC, the author is soliciting feedback on whether this standardization approach is the right direction before proceeding. The patch appears well-structured with clear commit message and focused changes, though as an RFC it hasn't yet received review feedback on the design.

This continues the effort from the first patch (which modified worktree.c internals) by updating the API callers. Together, these changes would eliminate the three inconsistent representations of the primary worktree in favor of a single standardized approach.
