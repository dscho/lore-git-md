This is the first patch in Patrick Steinhardt's v2 series improving the `git history` command's validation flow. The patch addresses a UX issue where validation checks were happening after user input, potentially causing users' work to be lost when checks failed.

The key change splits the revision walk setup into two phases: `setup_revwalk()` now performs all validation checks before any user input is collected, while `handle_reference_updates()` handles the actual reference updates afterward. This ensures users don't lose their commit message edits if the operation turns out to be invalid.

The patch includes a test adjustment to use `false(1)` as the editor, which cleanly aborts the operation rather than failing with an editor launch error. This builds on Junio Hamano's v1 feedback about test behavior.

This refinement maintains the series' core architectural improvements while fixing a real user-facing pain point. The change is cleanly scoped and well-explained, continuing the series' pattern of thoughtful iteration based on reviewer feedback.
