Performance improvement series for `git config list --type` filtering (part 7/13)

This patch is part of Derrick Stolee's series to optimize `git config list --type=<X>` by avoiding full parsing of non-matching values. The series addresses a performance bottleneck encountered by git-credential-manager when dealing with path-type config values.

Patch 7/13 introduces a new helper function `format_config_bool_or_str()` to handle boolean-or-string type configurations. The change is purely a refactoring - it moves existing logic into a dedicated function to maintain consistency with how other config types are handled in the series. The behavior remains identical to before, as this case was already doing "lazy" parsing (not failing on invalid values).

The patch follows the established pattern of the series by extracting type-specific formatting into separate functions. This prepares the codebase for the later patches that will implement the actual performance optimization by skipping full parsing of non-matching values. The change is small and focused, touching only `builtin/config.c` with straightforward test coverage already provided by earlier patches in the series.

This continues the incremental, well-structured approach seen throughout the series, with each patch making a clear, contained improvement. The overall goal remains to make `git config list --type` operations faster by avoiding unnecessary parsing work.
