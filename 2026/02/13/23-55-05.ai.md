Performance improvement to `git config list --type=<X>` filtering, now with final implementation.

This is the second version of Derrick Stolee's series to make `git config list --type=<X>` actually filter config values by type during parsing rather than after. The key motivation comes from git-credential-manager's performance bottleneck when processing path-type config values.

The series has evolved from RFC to full implementation, with all major design questions resolved. The 13 patches now:
1. Refactor config display infrastructure (patches 1-4)
2. Add gentle parsing variants for all config types (patches 5-12)
3. Restructure the core formatting logic (patch 13)

The final patch implements the actual type filtering by skipping full parsing of non-matching values, particularly benefiting path-type configs. The solution maintains consistency with `git config get` behavior while fixing what was effectively broken functionality in `list`.

Performance testing in git-credential-manager shows the expected improvements. Only minor documentation polish remains before merging. The series touches `builtin/config.c`, `config.c`, `parse.c` and adds comprehensive tests in `t/t1300-config.sh`.

Key reviewers Patrick Steinhardt and Junio Hamano have engaged throughout, with Patrick approving the final direction. The change is framed as fixing broken behavior rather than introducing new functionality, making it a strong candidate for merging once the last documentation tweaks are addressed.
