This is the first patch in a 4-part series introducing new interactive patch selection behavior for `git add -p`, `checkout -p`, `reset -p`, and `stash -p`. The series adds a `--auto-advance` flag (on by default) that controls whether these commands automatically move to the next file after processing all hunks in the current file.

The patch adds the core infrastructure for the new flag, modifying `add-interactive.[ch]` to store the auto-advance setting in the `add_i_state` and `add_p_opt` structs. It exposes the option through new command-line flags for all four interactive commands, with appropriate validation to ensure the flag is used with `-p/--patch`. The implementation maintains backward compatibility by defaulting to auto-advance behavior matching current Git.

Key technical details for future reference: the flag is stored in `add_p_opt.auto_advance` (default 1) and propagated to `add_i_state`, with validation ensuring it's only used with `-p`. The patch touches command implementations in `builtin/add.c`, `checkout.c`, `reset.c`, and `stash.c`, plus shell completion in `t9902-completion.sh`. The series appears well-structured, with this foundational patch cleanly introducing the infrastructure that subsequent patches will build upon.
