Security-focused commit-msg hook enhancement to prevent confusing `git am`. This is Phillip Wood's second version of a patch series that modifies the sample commit-msg hook to detect and reject commit messages containing unindented diffs that could confuse `git am`'s patch parsing.

The key changes in v2 refine the detection logic to:
1. Allow subjects starting with "diff -" since they appear in email headers and don't affect `git am`
2. Permit "---" separator lines which are commonly used in patch workflows
3. Improve the parsing logic to properly handle scissors lines and comment characters

The hook now specifically looks for unindented "diff -" and "Index: " lines in the commit message body while ignoring content below scissors lines. This addresses a known security vulnerability where `git am` can misinterpret embedded diffs in commit messages as part of the patch to apply.

The implementation handles edge cases like:
- Different comment character configurations
- Scissors line formatting
- Blank lines and message structure
- The distinction between subject (email header) and body content

This patch series is part of a broader layered solution to the patch parsing security issue, complementing Jeff King's proposed `--strict` mode for `git am` and the recently merged documentation warnings from Kristoffer Haugsbakk. The changes maintain backward compatibility while helping prevent accidental creation of problematic commit messages.
