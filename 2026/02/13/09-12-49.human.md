This is the third patch in Patrick Steinhardt's v2 series improving the UI of the new `git history` command. The patch focuses on making the dry-run functionality more user-friendly.

The change replaces the technical `--ref-action=print` option with a clearer `--dry-run` flag that works with both `--ref-action=head` and `--ref-action=branches`. The new flag maintains the same functionality (printing ref updates in `git-update-ref` format without actually modifying refs) but is more discoverable and intuitive for end users.

Key implementation details:
- The patch refactors the reference update handling to support both direct updates (via ref transaction) and dry-run printing through a new `handle_ref_update()` helper
- Documentation is updated to explain the new `--dry-run` behavior
- Tests verify that dry-run works correctly with both ref-action modes

The change addresses usability concerns from the v1 review while maintaining all existing functionality. This continues the series' trend of improving the command's UI while keeping its core behavior intact. The patch builds cleanly on the previous validation improvements while setting up for future work in the series.
