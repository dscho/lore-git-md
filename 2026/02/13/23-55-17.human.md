Performance improvement for `git config list --type=color` filtering.

This is patch 12/13 in Derrick Stolee's series to optimize `git config list` with type filtering. The series addresses a performance bottleneck in git-credential-manager by enabling type filtering during initial config parsing rather than after full parsing.

This specific patch introduces gentle parsing for color-type config values, following the same pattern established in earlier patches for other types (bool, int, path, expiry date). The change moves color value formatting into a new `format_config_color()` helper that uses the new `color_parse_gently()` function (added in patch 11) to silently ignore invalid color values when filtering. This matches the behavior of other type filters in the series.

The implementation maintains the existing public API while adding the gentle parsing capability needed for efficient filtering. Test coverage confirms that invalid color values are now silently skipped rather than producing error messages, consistent with the handling of other filtered types. The change removes four error message checks from the test suite since those cases now pass silently.

This continues the series' consistent approach to type-specific formatters while completing coverage for all major config value types. With this patch, the performance improvements for path-type values (the original motivation) are complemented by similar efficiency gains when filtering other types including colors.
