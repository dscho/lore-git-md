This is a bugfix patch for `git apply`'s `--directory` option. The patch addresses an issue where passing a relative path with a `./` prefix (like `--directory=./some/sub`) would cause the path to be prepended literally to patch filenames, resulting in an invalid path error.

The fix is straightforward: when the argument starts with `./`, the code now strips those two characters before processing. This makes `--directory=./some/sub` behave the same as `--directory=some/sub`, which is more intuitive since `./` is commonly used out of habit when specifying relative paths.

The patch includes a new test case that verifies the corrected behavior. The change is small and focused, touching only 4 lines in `apply.c` while adding a clear test. This appears to be a well-justified quality-of-life improvement that makes the command more forgiving of common input patterns.
