This is part 4 of Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering, now at version 2. The series aims to optimize config value parsing by skipping full parsing of values that don't match the requested type.

Patch 4/13 introduces gentle parsing for int64 config values, moving the formatting logic into a new helper function `format_config_int64()`. The key change is that when gentle parsing is requested (via the `gently` parameter), the function will return an error rather than dying if the value cannot be parsed as an int64. This matches the behavior pattern established in earlier patches for other config types.

The implementation maintains consistency with existing behavior - when not in gentle mode, it still uses `git_config_int64()` which may die on invalid values. The patch is a straightforward refactoring that builds on the infrastructure from patch 2 (which introduced the 'gently' parameter) while preparing for the type filtering functionality in patch 3.

This continues the series' incremental approach, with each patch focusing on one config type at a time. The changes are mechanical and well-contained, touching only `builtin/config.c` with no behavioral changes beyond the gentle parsing addition. The series appears to be progressing smoothly toward its goal of efficient type-based filtering.
