This is a feature patch series for the new `git history` command, focusing on UI improvements. Patrick Steinhardt sends version 2 of his 5-patch series that makes several usability enhancements to the experimental command.

The series splits into three logical parts:
1. Patches 1-2 move validation checks earlier in execution, ensuring problems are caught before user input is requested
2. Patch 3 replaces the technical `--ref-action=print` option with a more intuitive `--dry-run` flag
3. Patches 4-5 rename `--ref-action` to clearer `--update-refs` and document its default value

Key changes in v2 address feedback from Junio Hamano and D. Ben Knoble:
- Using `strvec_pushv()` for cleaner string array handling
- Documenting that `--dry-run` still writes objects for later use
- Clarifying test behavior around `core.editor=false`
- Adding documentation for the default `--update-refs` value

The series appears technically sound with all prior review feedback addressed. The changes improve the command's usability while maintaining safety - particularly the early validation checks that prevent wasted user effort. The documentation updates make the behavior more transparent to users. This looks ready for inclusion pending final maintainer review.
