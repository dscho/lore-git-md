This is part 2 of a 13-patch performance improvement series by Derrick Stolee, focused on making `git config list --type=<X>` filtering more efficient. The series addresses a performance bottleneck in git-credential-manager when dealing with path-type config values.

The current patch is a preparatory change that adds a new 'gently' parameter to the `format_config()` function, though it's not yet used. This groundwork will enable future patches to implement "gentle parsing" - parsing config entries without dying on errors when they don't match the requested type. The change is purely mechanical at this stage, just adding the parameter while maintaining all existing behavior.

This is part of a larger refactoring that will eventually allow `git config list` to skip full parsing of values that don't match the requested type, significantly improving performance. The series has already addressed major design questions in previous iterations and is now focused on implementation details.
