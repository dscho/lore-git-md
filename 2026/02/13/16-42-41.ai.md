Security-focused commit-msg hook enhancement. Phillip Wood's v3 patch adds a check to the sample commit-msg hook to detect and reject commit messages containing unindented diffs that could confuse `git am`. The hook now handles several edge cases:

1. Email headers (subjects starting with "diff -")
2. The "---" separator line used by `git format-patch`
3. Scissors lines (commit message truncation markers)
4. Comment characters in the message
5. Blank lines in the message body

The implementation carefully avoids false positives by skipping diffs that appear after scissors lines and accounting for various comment character configurations. This complements Kristoffer Haugsbakk's recently merged documentation warnings about patch roundtrip hazards, forming part of a layered security solution for the long-standing issue where `git am` can misinterpret commit message content as patch data.

The patch has been tested with `git commit --cleanup=scissors --verbose` and appears ready for inclusion. This represents the hook component of the broader security response, which also includes documentation updates, boundary marker proposals, and Jeff King's `--strict` mode for `git am`.
