Final patch in a performance improvement series for `git config list --type=<X>` filtering. This patch restructures the `format_config()` function to use a switch statement instead of nested if/else conditions, making the code more readable while maintaining all the type-specific parsing behaviors introduced earlier in the series.

The change reduces nesting depth by using a goto label for the common case of skipping values when `omit_values` is true. Each config type now has its own case in the switch, with the default case handling untyped string values. The restructuring doesn't change functionality but improves code organization after the series introduced several new type-specific formatters.

This completes the 13-part series that originally aimed to optimize config value filtering by type, particularly benefiting git-credential-manager's use of path-type config values. The series has addressed all major design questions and received positive feedback from reviewers including Patrick Steinhardt and Junio Hamano.
