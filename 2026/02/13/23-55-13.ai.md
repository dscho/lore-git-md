Patch 8/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. This patch introduces a gentle pathname parser to support the type-filtering infrastructure.

The change moves the pathname parsing logic from `git_config_pathname()` (which dies on error) to a new `git_parse_maybe_pathname()` function that returns an error code instead. This follows the pattern established in earlier patches of the series to enable type filtering during initial parsing rather than after full parsing. The new function handles both regular pathnames and optional paths (prefixed with ":(optional)"), maintaining the existing behavior where optional paths that don't exist are treated as NULL rather than errors.

The patch touches three files:
- `config.c` - removes the direct implementation in favor of calling the new parser
- `parse.c` - adds the new implementation with identical logic to the old version
- `parse.h` - exposes the new public function

This is a straightforward refactoring that follows the series' established approach of extracting parsing logic to support gentle type checking. The change is mechanical and maintains all existing behavior while enabling the performance improvements that come with early type filtering.
