This is the second patch in a two-part series standardizing string list sorting behavior across Git commands, focusing on the help command's configuration output. The patch comes from Amisha Chhajed with mentorship from Elijah Newren, building on their earlier work to ensure consistent `sort -u` style behavior.

The change refactors `builtin/help.c` to use the new `string_list_sort_u()` function (which combines sorting and deduplication) for the `keys_uniq` list that drives configuration output. The key insight is that the current implementation's uniqueness guarantee depends on the processing order of keys, which could break if the documentation structure changes. The patch demonstrates this with a test case showing how current documentation coincidentally avoids issues that the new approach would prevent.

The refactoring also simplifies the code by separating the human-readable output case from the machine-readable cases, addressing a suggestion from Junio Hamano. Performance impact is negligible since this isn't a hot path. The patch has reached consensus, with Junio accepting it after seeing the demonstrated need, though he noted an opportunity for further refactoring in help.c's output handling that Amisha has committed to address separately.
