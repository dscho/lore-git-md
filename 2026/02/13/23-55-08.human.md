This is patch 3/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series addresses a performance bottleneck in git-credential-manager by making type filtering happen during initial config parsing rather than after.

This patch implements the core behavior change - making `--type` actually filter values during listing. It introduces a breaking change by now omitting values that fail type parsing, where previously they were shown regardless. The commit justifies this as fixing previously ignored behavior, though notes it could surprise users who expected the option to do nothing.

Key changes:
- Modifies `show_all_config()` to use `format_config()` with gentle parsing
- Adds new `display_options_init_list()` helper to properly initialize output formatting
- Updates tests to verify the new filtering behavior for bool, path, date, and color types
- Documents that `--type` now filters listed values in the man page

The patch maintains the series' incremental approach, building on the groundwork from earlier patches while setting up for further refactoring. Test coverage is thorough, showing both successful filtering and proper error handling. The implementation appears clean and focused, with clear commit message explaining the behavior change.
