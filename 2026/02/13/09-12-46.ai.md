This is a feature patch series improving the new `git history` command's UI. Patrick Steinhardt's 5-patch v2 series refines the command's behavior and documentation based on feedback from v1. The changes focus on three areas: moving validation checks earlier in execution, replacing the technical `--ref-action` flag with clearer alternatives (`--dry-run` and `--update-refs`), and improving documentation.

Key technical changes in v2:
- Uses `strvec_pushv()` instead of manual string array handling (addressing Junio's feedback)
- Documents that `--dry-run` still writes objects to the ODB for later use
- Specifies the default value for `--update-refs` (branches)
- Adds commit message notes about the `false(1)` editor behavior in tests

The series maintains the core architectural improvements from v1:
- Early validation of revision walks and merge commits before user interaction
- Clearer flag semantics separating dry-run behavior from ref update control
- Transaction safety in reference handling

Reviewers (Junio Hamano and D. Ben Knoble) have already vetted the technical approach in v1, with all open questions resolved. The v2 changes are primarily documentation and minor implementation refinements. The series appears ready for inclusion pending final maintainer review, with no outstanding technical concerns. This work serves as groundwork for the upcoming `git history split` feature while avoiding conflicts with another in-flight topic.
