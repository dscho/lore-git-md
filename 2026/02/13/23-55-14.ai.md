Performance improvement series for `git config list --type` filtering (patch 9/13). This patch continues Derrick Stolee's work to optimize config value parsing by moving path-specific formatting into a dedicated helper function.

The change extracts path value handling from the main `format_config()` function into a new `format_config_path()` helper, following the pattern established in earlier patches for boolean and integer values. The new function uses the recently introduced `git_parse_maybe_pathname()` (from patch 8) when gentle parsing is requested, while maintaining the existing error handling behavior through `git_config_pathname()` for non-gentle cases. 

This is part of the larger effort to enable type filtering during initial config parsing rather than after full parsing, which provides performance benefits particularly for path-type values. The patch maintains all existing functionality including special handling of optional paths (marked with `:(optional)` prefix) while restructuring the code to support the series' goal of early filtering.

The change is mechanical and focused - it touches only `builtin/config.c` with 25 lines added and 10 removed. As with previous patches in the series, this appears to be a straightforward refactoring that preserves behavior while enabling the performance improvements to come in the final patches. The series has already addressed its major design questions and received positive feedback from reviewers.
