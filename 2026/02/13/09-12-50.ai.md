This is the fourth patch in Patrick Steinhardt's v2 series improving the `git history` command's interface. The patch focuses on renaming the `--ref-action` option to `--update-refs` to better reflect its current functionality.

The change follows from the previous patch's modification where `--ref-action` was simplified to only control which references would be updated (branches or just HEAD), rather than also controlling the action taken. The new `--update-refs` name more accurately describes this narrowed scope.

The patch updates:
1. Documentation in `git-history.adoc` to use the new flag name
2. The command's usage string and option parsing in `builtin/history.c`
3. Test cases in `t/t3451-history-reword.sh` to use the new flag name

This is a straightforward mechanical change that maintains all existing behavior while improving the command's interface clarity. The patch aligns with the series' goal of making the command's options more intuitive, following the earlier introduction of `--dry-run` to replace the technical `--ref-action=print` option.

The change is well-contained and consistent with the thread's progression, where all prior feedback on the naming and behavior of reference handling has already been addressed in previous patches. This appears to be the final piece of the UI refinement before the series moves on to other functionality.
