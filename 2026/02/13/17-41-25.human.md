This is a security-focused commit-msg hook enhancement from Phillip Wood, now in its third iteration. The patch adds checks to the sample commit-msg hook to prevent commit messages that could confuse `git am`'s patch parser, specifically targeting unindented "diff -" and "Index: " lines in message bodies while allowing them in email headers (subjects) and preserving the useful "---" separator lines.

The changes since v2 include handling of scissors lines (commit message truncation markers) and comment characters, addressing edge cases that came up in review. This is part of a layered security response to a long-standing issue where embedded diffs in commit messages can be misinterpreted as patches during email-based workflows, particularly affecting distribution maintainers.

The patch is now been reviewed and refined through multiple iterations, with Junio indicating satisfaction with the current state. It complements Kristoffer Haugsbakk's recently merged documentation warnings about patch roundtrip hazards, forming part of a broader solution that also includes Jeff King's proposed `--strict` mode for `git am` and Patrick Steinhardt's work on an `--accept-ambiguous-patch` flag.
