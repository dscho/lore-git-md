This is patch 11/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series refactors config parsing to enable type filtering during initial parsing rather than after, with particular focus on path-type values that were causing performance issues for git-credential-manager.

This specific change introduces `color_parse_gently()`, a variant of the existing color parsing function that returns an error code rather than printing an error message when parsing fails. The implementation factors out the core parsing logic into a new static helper `color_parse_mem_1()` that takes a 'gently' parameter, then wraps this for the existing public functions. The change follows the pattern established earlier in the series for gentle parsing of other config types.

The patch maintains all existing behavior while adding the new capability needed for the config filtering work. It moves the `color_parse()` function down in the file to keep related functions together, and adds the new function to color.h. The implementation is straightforward and follows the same approach used for other type parsers in the series, suggesting it should integrate cleanly with the rest of the work.
