This is a security-focused enhancement to the sample `commit-msg` hook, part of the ongoing effort to prevent `git am` misparsing of commit messages containing unindented diffs. Phillip Wood's patch adds detection for problematic patterns that could cause `git am` to incorrectly interpret message content as patch content.

The hook now checks for two specific cases that commonly trip up `git am`:
1. Unindented lines starting with "diff -" or "Index: " in the message body
2. The presence of "---" separator lines (though these are allowed since they're commonly used for patch commentary)

Junio raises several technical questions about the implementation, particularly around handling of scissors lines (used to mark where patch content begins in emails) and comment characters. He notes some confusion about whether the hook should detect diffs appearing before versus after scissors lines, and points out that scissors lines don't necessarily need to be comments.

The patch represents a practical mitigation while broader solutions (Jeff King's `--strict` mode, boundary markers) are still under discussion. It's a defensive measure that projects can adopt now to prevent common cases where commit messages might be misinterpreted during patch application. The implementation is careful to avoid false positives by respecting Git's comment character configuration and properly handling message structure.
