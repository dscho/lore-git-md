This is the third patch in Abraham Samuel Adekunle's series adding `--auto-advance` and related features to Git's interactive patch commands (`add -p`, `checkout -p`, etc.). The patch focuses on fixing an edge case where changing a hunk decision from USE to SKIP after moving between files wasn't properly registered, leaving the hunk applied when it should have been skipped.

The solution extracts the patch application logic into a new `apply_patch()` function that can be reused for consistent all-or-none application of patches. This refactoring prepares for the series' goal of giving users more control during interactive sessions while maintaining backward compatibility. The changes are mechanical - moving code rather than altering behavior - and maintain the existing test coverage from earlier in the series.

The patch continues the series' pattern of incremental, focused changes that build toward the larger interactive workflow improvements while keeping each step reviewable. The author has clearly incorporated feedback from previous iterations, as seen in the careful handling of edge cases and the clean separation of concerns in the refactoring.
