Performance improvement patch for config pathname parsing, part of a larger series optimizing `git config list --type=<X>` filtering.

This is patch 8/13 in Derrick Stolee's series to make config value filtering more efficient by avoiding full parsing of non-matching values. The current patch extracts pathname parsing logic from `config.c` into a new `git_parse_maybe_pathname()` function in `parse.c`, making it available for reuse while maintaining the same behavior - just without the `die()` calls. 

The change moves the path expansion and optional-file checking logic into a gentler parser that returns errors rather than terminating. This fits the series' pattern of refactoring config parsing to support type-aware filtering during initial parsing rather than after. The patch is straightforward - it splits existing code with minimal changes beyond the function extraction.

As with earlier patches in the series, this continues the incremental refactoring approach that has already addressed major design questions. The change is well-contained (touching only 3 files) and follows the established pattern of creating gentle parsing variants. Performance testing in earlier patches shows measurable improvements when filtering path-type config values, which was the original motivation from git-credential-manager's use case.
