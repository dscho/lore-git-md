Performance improvement patch in Derrick Stolee's config type-filtering series (9/13). This patch extracts path-value formatting into a dedicated helper function (`format_config_path()`) as part of the effort to enable early type filtering in `git config list --type=<X>`. 

The change moves path-specific logic out of the main `format_config()` function, using the new `git_parse_maybe_pathname()` helper introduced in patch 8/13. This maintains the existing behavior (including special handling of optional paths marked with `:(optional)`) while making the code more modular. The patch follows the established pattern of the series by separating parsing logic from display formatting.

This is a straightforward refactoring with no behavior changes, building on the infrastructure established in earlier patches. The series as a whole is addressing a performance bottleneck in git-credential-manager when dealing with path-type config values, and this patch continues that work by making the type-specific path handling more maintainable. The change is well-contained and follows the incremental approach that has been working well throughout the series.
