This is a follow-up clarification in the `git history` UI improvement series. Patrick Stehtardt responds to Junio Hamano's question about why using `-c core.editor=false` in the test prevents the editor from being invoked.

The exchange confirms that setting `core.editor=false` causes Git to abort with an editor launch failure message rather than proceeding with the commit rewrite. This ensures the test reliably checks for the expected "rewritten commit must be an ancestor of HEAD" error rather than potentially seeing an editor-related error.

The response is brief but resolves the open question from Junio about the test mechanism. This small clarification helps ensure the test suite properly validates the early validation checks introduced in patch 1 of the series.
