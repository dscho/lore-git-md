This is part 8 of a 9-patch series enhancing Git's promisor remote functionality, specifically focusing on the `--filter=auto` feature. The patch refactors the `promisor_remote_reply()` function to take an output parameter rather than returning a string, addressing feedback from Patrick Steinhardt on the previous version.

The change makes the API more explicit about ownership and memory management - callers now pass in a pointer to store the result rather than receiving a newly allocated string they must free. This matches the pattern seen elsewhere in Git's codebase and prevents potential memory leaks from callers forgetting to free the returned string.

The implementation remains functionally equivalent, just restructuring how the accepted filters are returned to the caller. This is a clean refactoring that improves the code's maintainability without changing behavior. As part of a larger series that has already received extensive review, this patch appears ready for inclusion.
