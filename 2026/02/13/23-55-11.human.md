Performance improvement patch in Derrick Stolee's config filtering series. This is patch 6/13 in v2 of the effort to optimize `git config list --type=<X>` by avoiding full parsing of non-matching values.

The patch introduces a new helper function `format_config_bool_or_int()` that handles boolean-or-integer config values with the same gentle parsing approach used earlier in the series. When in gentle mode (used during type filtering), it first tries to parse the value as a boolean, falling back to integer parsing if that fails. This matches the behavior of the existing non-gentle path while skipping full validation for values that won't be included in the output.

The change is mechanical and follows the pattern established by earlier patches in the series. It touches only `builtin/config.c`, extracting logic that was previously inline in `format_config()`. Test coverage for this behavior was already added in patch 3/13, so no new tests are needed here.

This continues the series' incremental refactoring approach, with each patch building on the infrastructure established by prior ones. The implementation looks straightforward and maintains consistency with Git's existing config value handling.
