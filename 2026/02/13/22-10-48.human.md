This is part 2 of Abraham Samuel Adekunle's series adding `--auto-advance` and inter-file navigation to interactive patch commands (`git add -p` and friends). The patch refactors the core `patch_update_file()` function to enable moving between files during an interactive session.

The key change modifies `patch_update_file()` to track and return the current file index rather than operating directly on a `file_diff` pointer. This allows the caller to control file navigation when `--no-auto-advance` is used. The function now returns either the next file index to process, -1 to quit, or the current index if more hunks remain. The changes are mechanical but touch several parts of the interactive loop logic to maintain the same behavior while enabling the new navigation features. 

This is a foundational change for the series' goal of letting users move between files with '>'/'<' keys while keeping backward compatibility with the default auto-advance behavior. The patch appears well-contained, with clear commit message explaining the motivation and straightforward implementation that doesn't introduce new behavior yet.
