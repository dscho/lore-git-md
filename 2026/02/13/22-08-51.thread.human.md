This thread introduces a new `--auto-advance` option for Git's interactive patch selection commands (`add -p`, `checkout -p`, etc.), proposed by Abraham Samuel Adekunle in a v4 patch series. The feature gives users more control during interactive sessions by preventing automatic file advancement after processing all hunks (with `--no-auto-advance`) and adding navigation commands ('>'/'<') to move between files manually.

The implementation touches several interactive commands and includes comprehensive test coverage in t3701. Through four iterations, the series has evolved its option naming (settling on `--auto-advance`/`--no-auto-advance`), refined function signatures, and removed the whatnow prompt in favor of persistent hunk display. The changes appear well-considered and would particularly benefit users who frequently work with multi-file interactive patches.

The technical work involves modifications to add-interactive.[ch], extraction of reusable git apply logic, and new interfile navigation commands. The series seems ready for maintainer consideration, with no outstanding objections or requested changes evident in the thread so far.
