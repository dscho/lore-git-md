This is the first patch in a 2-part RFC series refactoring how Git represents the primary worktree in the worktree API. The goal is to eliminate inconsistent representations (NULL pointers, NULL id fields, and "/" keys) by standardizing on worktree structs with wt->id set to "/" as the sole representation.

The patch modifies worktree.c internals to use "/" instead of NULL for primary worktree identification. Key changes include:
- Setting wt->id to "/" in get_main_worktree()
- Updating is_main_worktree() to check for "/" instead of NULL id
- Replacing NULL checks with is_main_worktree() calls
- Adding validation to prevent "/" being used for linked worktrees

The changes are mechanical but touch core worktree handling code. The RFC status indicates the author is seeking feedback on whether this standardization approach is the right direction before proceeding. The patch appears well-structured with clear commit message and focused changes, though as an RFC it hasn't yet received review feedback on the design.
