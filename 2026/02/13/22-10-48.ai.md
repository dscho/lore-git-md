This is part 2 of Abraham Samuel Adekunle's series adding `--auto-advance` functionality to interactive patch commands (`git add -p` and related). The patch refactors the core `patch_update_file()` function to enable inter-file navigation when using the new `--no-auto-advance` flag.

The key change modifies `patch_update_file()` to take a file index rather than a direct `file_diff` pointer, allowing the function to return either the next file index to process or -1 to quit. This enables the infrastructure for the subsequent patch's navigation features ('>'/'<' keys to move between files). The function now returns an ssize_t instead of an int to properly handle these cases.

The implementation maintains all existing behavior when `--no-auto-advance` isn't used, defaulting to sequential file processing. The changes are mechanical - updating call sites, adjusting control flow, and ensuring proper index handling - with no functional changes yet to the user experience. This is a preparatory patch that enables the actual navigation features coming in later parts of the series.

The patch touches core interactive patch machinery in `add-patch.c`, modifying how files are processed while preserving the existing hunk-level interaction model. The changes are focused and well-contained, with clear mechanical transformations that don't introduce new behavior yet. This continues the series' pattern of careful, incremental refactoring to support the new features.
