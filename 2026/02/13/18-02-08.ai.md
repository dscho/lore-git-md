Junio C Hamano has merged Kristoffer Haugsbakk's documentation patch that adds explicit warnings about the security risks of patch round-tripping in `git format-patch`. The patch, which was already technically complete, now been approved for inclusion in the `next` integration branch after review by both Junio and Phillip Wood. This marks the first completed component of the multi-layered solution to the `git am` patch parsing vulnerability.

The documentation update serves as an important first step in addressing the long-standing issue where embedded diffs in commit messages can be misinterpreted as patches during email processing. While the patch itself is straightforward, its inclusion in the official documentation helps raise awareness of the risks, particularly for distribution maintainers who frequently process patches via email workflows.

This email thread shows the final approval step before merging, with Phillip Wood confirming his satisfaction with the patch and Junio formally queuing it. The documentation component is now complete, with other technical solutions (commit-msg hooks, boundary markers, strict modes) still under active development and review in parallel threads.
