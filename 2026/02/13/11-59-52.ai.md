This is a refactoring patch series that aims to clean up how the primary worktree is represented in Git's worktree API. The series comes from Shreyansh Paliwal as part of their ongoing effort to reduce global state in the wt-status subsystem.

Currently, the primary worktree has three different representations: NULL pointers, worktree structs with NULL id fields, and the "/" key in ref-store maps. This inconsistency leads to ambiguity and requires extra NULL checks throughout the code. The series proposes standardizing on using worktree structs with wt->id set to "/" as the sole representation.

The first patch changes the internal representation in worktree.c to use "/" instead of NULL. The second updates API callers to use a new get_primary_worktree() helper rather than passing NULL. The changes touch several key files including builtins (fsck, worktree), refs handling, and the revision walker.

The motivation appears sound - eliminating NULL checks and implicit global state access is generally good for code clarity and maintainability. However, as an RFC, the author is specifically asking whether this is the right approach before proceeding further. The changes are fairly mechanical but do touch core worktree handling code, so careful review of the approach would be valuable before this moves forward.
