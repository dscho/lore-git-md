This is a bugfix patch for `git apply`'s `--directory` option. The patch addresses an issue where paths starting with `./` (like `--directory=./some/sub`) would be treated literally, causing the command to fail with an invalid path error. The fix strips the `./` prefix before processing the directory path, making it behave consistently with paths that don't use the `./` prefix.

The change is minimal and focused - just 4 lines added to `apply.c` to handle the prefix stripping, plus a new test case in `t4128-apply-root.sh` to verify the behavior. The test shows the command now works correctly with `./`-prefixed paths, matching the behavior of non-prefixed paths.

The patch appears well-crafted for its purpose - it solves a clear usability issue (where a common path notation fails) without introducing complexity. The test case is appropriately placed alongside similar existing tests for the `--directory` option. The commit message clearly explains both the problem and solution.
