This thread explores whether Git should adopt platform-specific optimizations for file copying operations, specifically Linux's `sendfile()` system call. The original proposal by George Hu suggested modifying `copy.c` to use this faster method where available, with Phillip Wood advising a Linux-specific implementation in `compat/linux/` and proper error handling.

Key concerns have centered around whether the optimization provides meaningful benefits for Git's typical workloads. Jeff King (Peff) noted that most Git operations involve small files where read/write overhead is negligible, with few exceptions like bundle operations. FreeBSD maintainer Ed Maste and Chris Torek highlighted platform constraints—FreeBSD's `sendfile()` only works on sockets—while Collin Funk added that the alternative `copy_file_range(2)` has its own issues, including problems with large files.

The discussion remains technically thorough but increasingly skeptical. Participants agree that without benchmark data showing clear performance gains for Git's real-world use cases, the complexity of platform-specific optimizations may not be justified. The thread is effectively on hold pending such measurements. Key participants include George Hu, Phillip Wood, Jeff King, Ed Maste, Chris Torek, and Collin Funk.
