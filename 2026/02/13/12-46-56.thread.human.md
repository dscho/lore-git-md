This thread explores a proposed optimization to use Linux's `sendfile()` system call for faster file copying in Git. The original patch from George Hu targets the `copy.c` infrastructure, which handles file operations across Git. Initial discussion established significant platform differences—Linux supports general file-to-file `sendfile()`, while FreeBSD restricts it to sockets—making a portable solution challenging. Phillip Wood provided detailed maintainer feedback, leading George to refine the Linux-specific approach with proper error handling and code organization (moving the implementation to `compat/linux/`).

Jeff King (Peff) has now joined the conversation, shifting the focus to whether this optimization is worthwhile in practice. While acknowledging the theoretical benefits of `sendfile()`, Peff questions whether it would meaningfully improve Git's performance, noting that most `copy_file()` operations involve small files where the current read/write loop overhead is negligible. He highlights the lack of benchmark data showing real-world speedups for large-file cases like bundle operations or local clones without hardlinks. This raises a key question: does the complexity of platform-specific code justify the potential gains?

The thread remains technically focused, with George Hu, Phillip Wood, and Chris Torek having established the implementation constraints, and Peff now evaluating the optimization's practical value. The open questions now span both technical details (error handling, fallback conditions) and broader project considerations (whether to proceed given the cross-platform tradeoffs). Benchmark data would help resolve the latter.
