This is patch 6/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series aims to optimize config value parsing by skipping full parsing of non-matching values.

The current patch introduces a new helper function `format_config_bool_or_int()` that centralizes the logic for handling boolean-or-integer config values. It follows the pattern established in earlier patches by supporting both gentle parsing (for type filtering) and strict parsing (for direct value display). The gentle parsing path uses `git_parse_maybe_bool_text()` and `git_parse_int()` to validate values without erroring, while the strict path maintains the existing `git_config_bool_or_int()` behavior.

The change is mechanical and focused - it moves existing logic into the new helper while maintaining identical behavior. This continues the series' incremental refactoring approach, building on the infrastructure from patches 1-5 (which introduced gentle parsing for other config value types). The patch touches only `builtin/config.c` and follows the established pattern of the series.

This is part of the broader effort to improve performance when filtering config lists by type, particularly benefiting git-credential-manager's use case with path-type values. The series has addressed all major design questions and is now in the polishing phase before merging.
