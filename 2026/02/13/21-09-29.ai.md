This is a bug report about date parsing behavior in Git's `--since` option. The issue concerns how Git handles dates without explicit times - instead of defaulting to midnight (00:00:00) as might be expected, it uses the current local time when the command is executed.

The reporter, Gregor, provides a clear technical explanation of the root cause in `date.c`, tracing it through `approxidate_careful()` and `approxidate_str()`. The current implementation initializes time fields from the current local time when parsing a date-only string, which leads to inconsistent results depending on when the command is run.

Gregor suggests two possible resolutions: either documenting this behavior as intentional, or submitting a patch to change it to default to midnight. The report is well-structured with clear examples and technical details, making it easy to understand the issue and its implications. This appears to be a legitimate inconsistency in Git's date handling that could affect scripts or any usage relying on date-only `--since` specifications.
