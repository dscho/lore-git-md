This is part 4 of Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series aims to speed up config value filtering by avoiding full parsing of non-matching values.

The current patch moves the int64 formatting logic into a dedicated helper function `format_config_int64()` and implements gentle parsing when requested. This continues the refactoring work from earlier patches to enable type-aware parsing during the initial config scan rather than after collecting all values. The change is mechanical but important for the series' goal of skipping unnecessary parsing.

The patch maintains the same behavior as before - formatting int64 values correctly - but now does so in a way that can fail gracefully when gentle parsing is enabled. This prepares the ground for the performance optimization where non-matching values can be quickly skipped without full parsing.

As with the rest of the series, the implementation is clean and well-contained, building incrementally on the infrastructure established in previous patches. The change is straightforward and unlikely to be controversial at this point in the review cycle.
