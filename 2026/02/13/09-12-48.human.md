This is part 2 of Patrick Steinhardt's v2 series improving the `git history` command's validation and UI. The patch moves merge commit detection earlier in the execution flow to fail fast before any user input is collected.

The change introduces a new helper function `revwalk_contains_merges()` that checks for merge commits (using `--min-parents=2`) during the revision walk setup. This prevents users from writing commit messages that would later be discarded when the unsupported merge commit case is detected. The test is updated to use `false(1)` as an editor to verify the early failure path.

This refinement addresses a specific UX pain point from the initial implementation while maintaining the series' overall goal of robust validation. The implementation looks clean, with proper error handling and resource cleanup. The test change demonstrates thoughtful consideration of the user experience - failing before editor invocation rather than after.
