This is a feature patch series introducing a new `--auto-advance` option for interactive patch selection commands like `git add -p`. The series comes from Abraham Samuel Adekunle and is at version 4.

The main goal is to give users more control during interactive patch selection by:
1. Adding a `--no-auto-advance` flag that prevents automatically moving to the next file after processing all hunks in the current file (the default `--auto-advance` maintains current behavior)
2. Enabling navigation between files using '>' and '<' commands when there are multiple files
3. Allowing all-or-none application of patches

The implementation touches several interactive commands (`add`, `checkout`, `reset`, `stash`) and includes tests in t3701. The series has evolved through 4 versions with changes to the option naming (now `--auto-advance`/`--no-auto-advance`), function signatures, and removal of the whatnow prompt in favor of persistent hunk display.

Key technical details:
- Adds new flag handling in add-interactive.[ch]
- Modifies `patch_update_file()` to take file index rather than file_diff
- Extracts git apply logic into reusable function
- Implements interfile navigation commands ('>'/'<')
- Updates test coverage in t3701-add-interactive.sh

The changes appear focused and well-motivated, with thorough test coverage. The evolution through multiple versions suggests careful consideration of feedback. This would be particularly useful for users who frequently work with multi-file interactive patches and want more control over the workflow.
