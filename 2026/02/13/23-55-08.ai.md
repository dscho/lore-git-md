This is the third patch in a 13-part performance improvement series by Derrick Stolee, focusing on making `git config list --type=<X>` filtering actually work as intended. The series addresses a performance bottleneck in git-credential-manager when dealing with path-type config values.

The patch implements the core functionality for type filtering in `git config list`, which previously ignored the `--type` parameter entirely. Now it properly filters config values during parsing, skipping values that don't match the requested type. This represents a behavior change - previously all values were shown regardless of type, while now non-matching values are omitted.

Key technical changes include:
- Adding type-aware parsing to `show_all_config()` via `format_config()`
- Introducing a new `display_options_init_list()` helper to properly initialize formatting options
- Comprehensive test coverage in t1300-config.sh showing the new filtering behavior for bool, path, expiry-date, and color types
- Documentation updates clarifying the new `--type` behavior in list mode

The implementation maintains consistency with `git config get` behavior while improving performance by avoiding full parsing of non-matching values. The patch builds on the infrastructure refactoring from earlier in the series (particularly the 'gently' parameter added in patch 2) to enable this type-aware filtering.

This represents a significant step in the series' goal of optimizing config value processing, with all major design questions now resolved according to the thread discussion. The remaining patches will continue refining the implementation and adding support for additional config types.
