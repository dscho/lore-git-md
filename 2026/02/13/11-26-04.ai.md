This is the final patch in a 9-part series implementing auto-filter logic for promisor remotes, reviewed by Patrick Steinhardt and Christian Couder. The patch wires up the `--filter=auto` functionality in `fetch-pack.c`, completing the LOP (Large Object Promisors) effort.

The key technical change here is the handling of the `promisor-remote` server feature in the V2 protocol. When the server advertises this feature, the client now processes the configuration through `promisor_remote_reply()` but passes NULL for the output parameter, avoiding unnecessary string allocations when the response isn't needed - an optimization suggested in earlier review rounds.

The implementation builds on previous patches that:
1) Added secure storage for remote fields via `promisor.storeFields`
2) Introduced the `LOFC_AUTO` filter type infrastructure
3) Refactored the `promisor_remote_reply()` API to use output parameters

This final patch demonstrates the series' careful attention to both functionality and performance, with Patrick noting approval of the NULL pointer handling that avoids allocations. The change is small but completes the integration of auto-filter logic while maintaining the security-conscious design established earlier in the series.
