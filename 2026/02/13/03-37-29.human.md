This is the second patch in a two-part series standardizing string list sorting behavior across Git commands, with a focus on `git help` output. The patch comes from Amisha Chhajed with mentorship from Elijah Newren.

The change refactors how `git help -c` processes configuration keys to ensure consistent sorted-and-deduplicated output matching `sort -u` behavior. The key improvement replaces separate sort+dedupe operations with a unified `string_list_sort_u()` call, similar to the first patch in the series for `git sparse-checkout list`. The patch includes a test demonstrating how the current documentation structure could potentially break without this change.

The refactoring also simplifies the code by separating the human-readable output case from other formats, making the logic clearer. Junio Hamano has already acked the approach after seeing concrete examples of potential issues, though he noted an opportunity for further cleanup in how `SHOW_CONFIG_HUMAN` is handled (which Amisha has committed to address in follow-up work).

This is a well-justified change that follows the pattern established in the first patch of the series, with clear test coverage showing the edge cases it prevents. The impact is limited to non-critical paths (help output formatting) and maintains backward compatibility while making the behavior more robust against future documentation changes.
