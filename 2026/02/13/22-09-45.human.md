Feature patch introducing `--auto-advance` for interactive patch commands.

This is the first patch in Abraham Samuel Adekunle's v4 series adding navigation controls to Git's interactive patch selection commands (`git add -p`, `checkout -p`, `reset -p`, `stash -p`). The patch introduces a new `--auto-advance` flag (enabled by default) that controls whether these commands automatically move to the next file after processing all hunks in the current file. The complementary `--no-auto-advance` option allows users to stay on the current file for further editing.

The implementation adds the interactive machinery in `add-interactive.[ch]` to track this setting through the `add_p_opt` and `add_i_state` structs. All four interactive commands are updated to accept the new flag, with appropriate validation to ensure it's only used with `-p/--patch`. The patch includes completion script updates and maintains backward compatibility by defaulting to auto-advance behavior.

This looks like a well-structured change that cleanly extends the existing interactive patch interface. The series has evolved through several iterations (now at v4) with clear attention to detail in the implementation and test coverage. The feature addresses a real workflow need - giving users more control during multi-file interactive sessions - without disrupting existing behavior.
