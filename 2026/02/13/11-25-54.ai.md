This is a technical refinement in the LOP (Large Object Promisors) series, specifically addressing the promisor remote reply handling. The patch modifies the `promisor_remote_reply()` function signature to make its behavior more explicit and efficient.

The key change converts the function from returning an allocated string (which was sometimes discarded) to using an output parameter (`accepted_out`). This better matches the actual usage patterns where callers may not always need the formatted reply string. The implementation now only constructs the reply string when the caller provides a non-NULL output pointer, avoiding unnecessary allocations.

The change comes in response to Patrick Steinhardt's review feedback on v2, where he noted the inefficiency of generating a reply string that would immediately be discarded. Christian Couder's implementation cleanly separates the filtering logic from the reply formatting, making the caller's intent more explicit while maintaining the same functionality.

This is part of the larger effort to enhance promisor remote capabilities with secure storage of remote fields and dynamic filter combination. The modification touches core promisor-remote functionality but doesn't introduce new behavior - it's purely an internal API improvement that makes the code more efficient and clearer in its intent.
