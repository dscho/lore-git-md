Here's a human-readable summary of the thread so far:

Shreyansh Paliwal has proposed an RFC patch series to clean up how Git represents the primary worktree in its worktree API. Currently, there are three inconsistent ways the primary worktree is handled: NULL pointers, worktree structs with NULL id fields, and the "/" key in ref-store maps. This leads to ambiguity and requires extra NULL checks throughout the code.

The series aims to standardize on using worktree structs with wt->id set to "/" as the sole representation. The first patch changes worktree.c's internal representation, while the second introduces a get_primary_worktree() helper and updates API callers across builtins (fsck, worktree), refs handling, and the revision walker.

As an RFC, Shreyansh is specifically seeking feedback on whether this is the right approach before proceeding further. The changes are mechanical but touch core worktree handling code, so careful review of the design would be valuable. The motivation - eliminating NULL checks and implicit global state - aligns with Git's ongoing efforts to reduce global state and improve code clarity.
