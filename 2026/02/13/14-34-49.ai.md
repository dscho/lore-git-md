Security-focused commit-msg hook enhancement to prevent `git am` confusion. This is Phillip Wood's second version of a sample hook that detects commit messages containing unindented diffs, which can cause `git am` to incorrectly parse them as part of the patch rather than the commit message.

The hook now includes refined detection logic that:
1. Skips email headers (subjects starting with "diff -")
2. Allows "---" separator lines (common in patches)
3. Handles scissors lines and comment characters properly
4. Specifically targets unindented "diff -" and "Index: " lines in the message body

The implementation carefully navigates edge cases like commented lines and blank lines while maintaining backward compatibility. The hook warns users when their commit messages contain patterns that would confuse `git am`, suggesting they indent any embedded diffs. This complements the documentation warnings added in Kristoffer Haugsbakk's earlier patch and is part of a layered security approach that also includes Jeff King's proposed `--strict` mode and Patrick Steinhardt's `--accept-ambiguous-patch` flag.

The patch shows attention to detail in handling the various ways commit messages can be formatted while still catching the problematic cases. It's particularly relevant for projects where patches might be shared via email or where users might copy-paste diffs into commit messages. The changes are confined to the sample hook template, making it easy for projects to adopt if desired.
