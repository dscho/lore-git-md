This is the second patch in Patrick Steinhardt's v2 series improving the `git history` command's UI. The patch focuses on moving merge commit validation earlier in the execution flow to avoid wasting user effort when merges are present.

The key change introduces a new `revwalk_contains_merges()` function that checks for merge commits (using `--min-parents=2`) before any user interaction occurs. This prevents the frustrating scenario where a user writes a message only to have the operation fail later due to unsupported merge commits. The function integrates with the existing `setup_revwalk()` infrastructure while maintaining clean error handling and resource cleanup.

A test is updated to use `-c core.editor=false` to verify the editor isn't launched when merge detection fails, demonstrating the early validation working as intended. The implementation follows the series' architectural pattern of separating validation (`setup_revwalk()`) from action (`handle_reference_updates()`).

This change directly addresses one of the series' stated goals - moving validation earlier - while maintaining compatibility with the transaction-safe reference handling and other improvements from v1. The patch shows careful attention to resource management (revwalk cleanup) and error messaging that clearly explains the limitation to users.
