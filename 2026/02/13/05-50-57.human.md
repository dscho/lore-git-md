This is a UI improvement patch for the new `git history` command, part of Patrick Steinhardt's ongoing series to refine its interface. The patch replaces the technical `--ref-action=print` option with a more user-friendly `--dry-run` flag that better matches Git's conventional terminology.

The change makes the dry-run functionality more discoverable while also fixing a limitation where the original implementation only simulated rewriting all branches, not allowing HEAD-only dry runs. The new `--dry-run` works with both `--ref-action=head` and `--ref-action=branches` modes.

Junio C Hamano's review confirmed the implementation correctly creates commit objects in the object database during dry runs (preventing future corruption if references are later updated manually), while only skipping the reference updates themselves. Patrick acknowledges this point and will update the documentation accordingly.

The patch appears well-considered, addressing both usability and technical correctness. It follows the series' pattern of making `git history` more polished and intuitive while maintaining robust behavior under the hood.
