This is a security-focused patch series addressing repository discovery hardening. Tian Yuchen is working on improving Git's handling of malformed `.git` entries (like FIFOs) that currently get silently ignored, which could lead to unsafe attachment to parent repositories.

In this follow-up email, Tian responds to Junio Hamano's review comments on v2 of the patch. Junio had suggested a more comprehensive approach - refining the error taxonomy in `read_gitfile_gently()` with new error codes (`STAT_ENOENT`, `IS_A_DIR`) to better distinguish non-error conditions while making other cases (`STAT_FAILED`, `NOT_A_FILE`) consistently fatal when `die_on_error` is true.

Tian acknowledges this is a better architectural approach and commits to working on a v3 patch that will:
1. Introduce the new error codes
2. Make certain errors fatal by default
3. Audit and adjust all callers to handle the new codes

The discussion has evolved from just hardening `.git` validation to a broader refactoring of the error handling system in this sensitive repository setup path. While the technical change remains small (15 lines in `setup.c`), it touches core functionality and requires careful consideration of backward compatibility, particularly around symlink support which brian m. carlson raised concerns about preserving.

The thread appears to be converging toward a solution that maintains historical symlink behavior while improving validation for other special file types. Tian's response shows they understand the architectural implications and are taking time to implement the changes properly rather than rushing another version.
