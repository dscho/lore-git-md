Performance improvement for `git config list --type=<X>` filtering (12/13). This patch continues Derrick Stolee's series to optimize config value filtering by moving color parsing into a dedicated `format_config_color()` helper that supports gentle parsing.

The change factors out color handling from the main `format_config()` function, following the same pattern established in previous patches for other config value types. The new helper uses `color_parse_gently()` (introduced in patch 11) to silently skip invalid color values when filtering, rather than emitting error messages. This matches the behavior seen with other type filters in the series.

Test updates confirm the new silent behavior for non-color values while maintaining correct output for valid color specifications. The patch maintains the existing public `git_config_color()` API while adding the new gentle parsing capability internally.

This is part of the larger effort to make `git config list --type=<X>` more efficient by filtering during parsing rather than after. The series has addressed all major design questions and is now in its final polishing stages, with documentation updates expected in the final patch.
