This is a UI improvement patch for `git send-email`'s character encoding handling, following up on a thread started by first-time contributor Shreyansh Paliwal. The patch addresses a confusing prompt that appears when non-ASCII characters are detected in email subject lines.

Currently, when `git send-email` encounters 8-bit content, it asks "Which 8bit encoding should I declare [UTF-8]?" - which users sometimes misinterpret as a yes/no question, answering "y" and producing malformed email headers. The patch changes the prompt to explicitly say "[default: UTF-8]" to make clear that the expected response is an encoding name.

The change is minimal and focused - just a one-line modification to the prompt text in `git-send-email.perl`. Shreyansh also raises the question of whether to add validation for invalid charset names or fall back to UTF-8, but this initial patch sticks to the simpler prompt wording improvement suggested by Ben Knoble in the thread.

This appears to be a well-scoped quality-of-life improvement for a real usability issue. The patch is clean and follows the existing pattern in the code. Since `git send-email` is a critical tool for Git contributors, even small usability fixes like this can have an outsized impact on the contributor experience.
