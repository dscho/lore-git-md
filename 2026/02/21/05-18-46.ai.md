This is a follow-up in the RFC discussion about improving `git format-patch`'s cover letter commit list format. The author Mirko Faina responds to Junio C Hamano's feedback about two key design questions from the initial proposal.

On the question of whether to include abbreviated commit hashes (which Junio suggested might be "useless garbage" since they won't match the final repository state), Mirko proposes possibly showing author identifiers instead, arguing this could help reviewers quickly see who worked on what before diving into the patches.

Regarding making the new format optional versus replacing the current shortlog-style output, Mirko suggests adding a `--cover-letter=<shortlog|commitlist>` parameter but expresses skepticism that many actually prefer the current author-grouped shortlog format, speculating most just accept it as the default. The response maintains the original motivation - that the current format obscures patch series flow - while engaging with the maintainer's concerns about backward compatibility.

The exchange remains focused on design validation rather than the known implementation issues (reverse order, memory leaks) from the initial patch. This follow-up doesn't introduce new code changes, instead probing the maintainer's position on these two specific aspects that would shape any future implementation. The thread continues to center on whether the proposed chronological numbered list provides enough value to justify changing (or adding an alternative to) the current behavior.
