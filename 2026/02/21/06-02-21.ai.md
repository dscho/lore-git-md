This is a follow-up in the ongoing discussion about improving `git format-patch`'s cover letter commit list format. Maintainer Junio C Hamano proposes a more flexible configuration-based approach than the original numbered-list proposal, suggesting a `format.commitListFormat` setting that would allow users to customize how commits appear in the cover letter using printf-style format strings.

The key new idea is making the output format configurable via a format string that gets passed to the underlying log machinery, with `[N/M]` prepended automatically. This would support use cases like including author names via `%a` while keeping the numbering that helps visualize patch series flow. The default would show just the subject (`[N/M] subject`), while unsetting the config would fall back to the current shortlog-style output.

Junio also sketches how this could map to a command-line option syntax (`--cover-letter=log:"%s (%an)"`) for per-invocation overrides. The proposal maintains the original goal of better showing series flow while addressing earlier concerns about rigid output formats by introducing user customization.

This moves the discussion from choosing between two fixed formats to designing an extensible system. The thread appears to be converging on this approach, with the remaining work being to finalize the format string specification and placeholder support before addressing the known implementation issues in the prototype. The maintainer's engagement suggests this feature is likely to proceed once those details are settled.
