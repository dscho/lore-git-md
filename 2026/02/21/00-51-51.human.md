This is a follow-up to an RFC patch proposing changes to `git format-patch`'s cover letter commit list format. The author is responding to feedback about their proof-of-concept implementation.

The original patch suggested replacing the current author-grouped shortlog in cover letters with a numbered chronological list showing each commit as "[N/M] abcd: summary". In this reply, the author acknowledges two implementation issues in their prototype: the list is generated in reverse order, and there appears to be a memory leak. However, they emphasize they're primarily seeking feedback on the format change itself rather than the implementation details at this stage.

The proposed change aims to make commit order and content more immediately apparent in patch series cover letters, addressing developer feedback that the current author-grouped presentation is less useful for understanding the flow of changes. The discussion is still in the RFC (Request For Comments) phase, with the author looking for consensus on the design approach before finalizing the implementation.

The patch touches `builtin/log.c` and would require accompanying documentation updates if accepted. The change is well-contained and focused on improving a specific pain point in the patch submission workflow. While the implementation needs polishing (as expected for an RFC), the core idea appears straightforward and potentially useful.
