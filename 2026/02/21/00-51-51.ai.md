This is a follow-up to an RFC patch proposing changes to `git format-patch`'s cover letter commit list format. The original patch suggested replacing the current author-grouped shortlog with a numbered chronological list showing each commit as "[N/M] abcd123: summary".

In this reply, the author Mirko Faina acknowledges two implementation issues in their proof-of-concept code: the list is generated in reverse order and there appears to be a memory leak. However, they emphasize this was just a prototype and are primarily seeking feedback on whether the proposed output format would be useful to users.

The technical details show the patch modifies `builtin/log.c` to generate sequential numbered output using `pp_commit_easy()` for one-line summaries, with careful hash formatting. The core idea remains making commit order and content more immediately apparent in cover letters, addressing developer feedback that the current author-grouped shortlog obscures series flow.

The discussion continues to focus on design feedback rather than implementation details at this stage. Key open questions from the original RFC remain relevant: whether the format should be configurable, how to document it, and what test coverage would be needed. The memory management and ordering issues noted here would need to be addressed in any future version, but the author is appropriately treating them as secondary to validating the concept first.
