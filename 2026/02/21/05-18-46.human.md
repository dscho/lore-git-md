This is a follow-up discussion in the RFC thread about improving `git format-patch`'s cover letter commit list format. The original proposal suggested replacing the current author-grouped shortlog with a numbered chronological list showing each commit as "[N/M] abcd123: summary" to better illustrate patch series flow.

In this response, Mirko Faina addresses two key points raised by Junio C Hamano:

1. **Commit hash usefulness**: Junio questioned whether abbreviated commit hashes in the cover letter add value since they won't match the final repository state. Mirko suggests possibly replacing them with author identifiers instead, arguing this might help reviewers quickly see who worked on what.

2. **Configurability**: Junio wondered if the format should be optional to preserve the shortlog style. Mirko proposes making `--cover-letter` accept an argument to choose between styles (`shortlog` or `commitlist`), though he personally doubts many prefer the current shortlog format, suggesting it may be used more by default than by preference.

The exchange shows the RFC moving from initial implementation concerns to deeper design questions about what information belongs in cover letters and how much flexibility users need. Mirko maintains the core motivation - that the current format obscures patch series flow - while engaging with the maintainer's feedback about hash usefulness and optionality.
