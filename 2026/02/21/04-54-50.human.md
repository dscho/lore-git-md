Junio C Hamano responds to Mirko Faina's RFC proposing a new cover letter format for `git format-patch`. The current format groups commits by author in a shortlog style, which Mirko argues obscures the chronological flow of a patch series. Junio acknowledges this point but raises two key considerations.

First, he questions whether including abbreviated commit hashes in the new format is useful, since these hashes won't match the final commits after the patches are applied. The hashes would become meaningless for future reference. Second, he wonders if the new format should be optional to accommodate users who prefer the current author-grouped style.

The response suggests Junio is open to the idea of improving cover letter presentation but wants to carefully consider these design questions before committing to a change. His tone is constructive while flagging practical concerns that would need resolution in any future version of the patch. The exchange represents typical early-stage design discussion on the list, where the maintainer helps shape a proposal before implementation details are finalized.
