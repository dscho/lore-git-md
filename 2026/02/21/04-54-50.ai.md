Summary from the Git project maintainer on cover letter format proposal.

Junio C Hamano responds to Mirko Faina's RFC proposing a new cover letter format for `git format-patch`. The current implementation generates a shortlog grouped by author, which Mirko argues obscures the chronological flow of a patch series. The proposed change would list commits sequentially with "[N/M] abcd123: summary" format.

Junio acknowledges the validity of the motivation but raises two key design considerations: First, he questions whether including abbreviated commit hashes adds value, since these hashes won't match the final repository state after patching. Second, he wonders if the new format should be optional to preserve the shortlog style for users who prefer author grouping.

The response indicates openness to the concept but suggests the proposal needs refinement before moving from RFC to implementation. Junio's feedback focuses on practical usability concerns rather than technical implementation issues (which the author had already acknowledged need work). This positions the thread at a design discussion stage, with the next steps likely involving either a revised proposal addressing these questions or broader community input on the format preferences.
