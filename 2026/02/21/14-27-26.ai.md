This is a follow-up discussion in Adrian Ratiu's config-based hooks series, specifically addressing brian m. carlson's concerns about parallel hook execution. The exchange clarifies that parallel execution is being handled in a separate patch series (v2 coming soon) that will maintain backward compatibility while introducing optional parallelization.

Adrian confirms that Phillip Wood previously identified the TTY preservation issue, and the upcoming parallel hooks series will address it by:
- Keeping sequential execution as the default to maintain compatibility
- Introducing an opt-in extension for parallel execution when hooks are known to be safe
- Using run-command's muxer to handle combined stdout/stderr output
- Allowing users to control parallelization since they know their hooks' requirements
- Enforcing serial execution for inherently unsafe hooks

The response emphasizes that this is a separate effort from the current config-based hooks series (which remains focused on core functionality) and invites brian m. carlson to review the parallel execution changes when v2 of that series is posted. The tone is collaborative, acknowledging prior feedback while positioning the parallel work as an optional extension building on the current foundation.
