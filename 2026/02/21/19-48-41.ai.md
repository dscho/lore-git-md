This is a documentation patch updating the Git HTTP protocol specification to define the error response when a client fails to provide any "want" lines during upload-pack negotiation.

The patch adds explicit error handling for the case where a client initiates an upload-pack request without specifying any objects to fetch. It states that the server must treat this as an invalid request and terminate the negotiation, responding with "ERR no wants received" to indicate the client failed to specify any objects. The server behavior is now clearly documented where previously there was only a TODO placeholder.

The change is straightforward and uncontroversial, properly documenting expected protocol behavior. The patch follows standard documentation formatting and makes a useful clarification to the protocol specification. As a documentation-only change, it doesn't affect runtime behavior but helps implementers understand the correct server response should be in this edge case.
