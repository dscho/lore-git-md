This is a security-adjacent bugfix discussion regarding symbolic refs and namespace isolation in `receive-pack`.

The thread centers around a patch from Troels Thomsen that fixes a crash when handling symbolic refs that point outside their designated namespace. While the technical fix itself is straightforward (preventing NULL dereferences by properly handling fully-qualified ref names), the discussion has evolved into a policy debate about namespace security.

Junio Hamano, while acknowledging the crash fix, raises concerns about whether allowing cross-namespace symref updates might inadvertently bypass namespace protections. He suggests the fix could be modified to explicitly reject such updates rather than permitting them. Troels counters that symrefs require explicit creation on the receiving side, implying intentional use, and notes that update hooks could enforce stricter policies if needed.

In this final email, Junio summarizes the tradeoff: cross-namespace symrefs could be useful for intentional cases but dangerous if created accidentally. He drops the topic from his tree but leaves the door open for a future patch that would convert the crash into an explicit error message about cross-namespace links. The discussion remains unresolved, with valid arguments on both sides about the right balance between flexibility and safety in namespace isolation.
