This is a security-sensitive bugfix discussion regarding symbolic refs crossing namespace boundaries in `receive-pack`. The thread has reached an impasse between two perspectives on namespace isolation policy.

The original patch from Troels Thomsen fixed a NULL dereference crash when processing symbolic refs pointing outside their namespace by properly handling fully-qualified ref names in `check_aliased_update_internal()`. While Junio Hamano acknowledges the crash fix, he raises deeper concerns about whether allowing such cross-namespace symrefs violates the intended security model of namespaces.

The key technical points at issue are:
- The crash occurs in `builtin/receive-pack.c` when checking symref updates
- The test case in `t5509-fetch-push-namespaces.sh` verifies the fixed behavior
- Underlying commits ded8393610 (namespaces) and da3efdb17b (symref checks) provide context

Junio now suggests dropping the current approach in favor of making `receive-pack` explicitly reject cross-namespace symref updates with an error message, treating them as potential security violations rather than valid configurations. This would represent a policy shift from the permissive approach in Troels' patch.

The discussion highlights a fundamental tension in Git's namespace design - whether symrefs should be allowed to intentionally bridge namespaces (as Troels argues, since they require explicit server-side configuration) or whether the namespace boundary should be strictly enforced (as Junio suggests, to prevent accidental security holes). Neither side has proposed concrete implementation changes yet, but the thread remains open for further design discussion.
