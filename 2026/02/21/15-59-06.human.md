This is a feature proposal for `git format-patch`'s cover letter generation, evolving from an earlier RFC. The thread has converged on a flexible approach where users can configure the commit list format via `format.commitListFormat` (defaulting to "[N/M] subject") with printf-style placeholders. The current email focuses on whether to expose this as a command-line option (`--cover-letter=log:"%s (%an)"`) or just a config setting.

Mirko Faina (the original proposer) agrees with Junio Hamano's configurable format approach but questions the need for a command-line override, arguing the main value is in having a sensible default. He suggests aligning this change with the upcoming 3.0 release if it involves behavior changes.

The patch appears well-motivated (improving cover letter readability) and follows the maintainer's guidance, though the exact interface details remain open. This is a small but thoughtful quality-of-life improvement for patch series authors.
