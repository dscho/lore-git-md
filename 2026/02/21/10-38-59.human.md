This is a bugfix patch addressing a memory leak in the `pack-redundant` command. The patch is straightforward and well-contained.

Sahitya Chandra identifies a case where `llist_init()` allocates memory for `l.remaining_objects` but if `open_pack_index()` fails, the function returns without freeing that memory. The fix adds the missing cleanup by calling `llist_free()` on the error path.

The change is small (just 3 lines added) and clearly correct - it plugs a leak that would occur when processing pack files with invalid indexes. This is the kind of maintenance fix that typically gets merged quickly with little discussion, as it doesn't change any behavior other than fixing the leak. The patch follows Git's coding style and includes a clear commit message explaining both the problem and solution.
