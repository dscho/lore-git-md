This is a follow-up in the ongoing discussion about configurable commit list formatting for `git format-patch` cover letters. The thread has evolved from Mirko Faina's initial proposal for numbered commit lists to Junio Hamano's suggestion of a flexible `format.commitListFormat` configuration using printf-style format strings.

Mirko agrees with Junio's core proposal for a configurable format string that would automatically prepend the `[N/M]` series position marker. However, he expresses reservations about the command-line override syntax (`--cover-letter=log:"%s (%an)"`), arguing that requiring users to specify formats manually might undermine the goal of providing useful defaults. He suggests aligning any default behavior change with the upcoming Git 3.0 release.

The technical discussion remains focused on the configuration mechanism rather than implementation details, with the maintainer's flexible format-string approach now clearly favored over the original numbered-list proposal. Mirko's response indicates general agreement with the direction but raises practical concerns about the user experience of the command-line interface. The thread shows consensus forming around the configurable approach while leaving some interface details open for refinement.
