This is part 1 of a 6-patch series removing `the_repository` usage from merge-ort and replay, part of the ongoing `the_repository` removal effort. The patch removes obsolete checks that restricted blob prefetching to only work with `the_repository`, a limitation that was lifted in 2021 but left behind these now-unnecessary guard conditions.

The changes touch four files (diff.c, diffcore-break.c, diffcore-rename.c, and merge-ort.c), simplifying the prefetch logic by directly checking for promisor remotes using the repository parameter already available in each context. This version (v3) specifically addresses Patrick Steinhardt's feedback from v2 by ensuring the repository context is properly propagated to `repo_has_promisor_remote()` calls.

The patch demonstrates careful attention to historical context, explaining how these checks originated from when lazy fetching only worked with `the_repository`, and why they can now be safely removed. The changes are mechanical but well-justified, with Elijah Newren's merge-ort expertise ensuring the modifications are technically sound. This appears ready for integration as part of the broader repository abstraction effort.
