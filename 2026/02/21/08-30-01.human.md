Bugfix improving error handling for invalid `.git` files and directories. This final version (v9) of Tian Yuchen's patch series refines error diagnostics while maintaining Git's security boundaries around repository setup.

The patch introduces new error codes to better distinguish between different failure modes when checking `.git` paths: `READ_GITFILE_ERR_STAT_ENOENT` for missing files and `READ_GITFILE_ERR_IS_A_DIR` for directories. This replaces the previous catch-all approach that treated all non-regular files the same way. The changes ensure Git properly handles symlinks to directories (which already worked in practice) while still rejecting dangerous cases like FIFOs and sockets.

Key improvements include:
- More precise error classification in `read_gitfile_gently()`
- Optimized filesystem access patterns by only checking directory status when needed
- Clearer error messages through a restructured switch statement
- New test suite (`t0009-git-dir-validation.sh`) covering symlinks, FIFOs, garbage content, and empty directories

The thread discussion revealed that the original motivation (symlink support) was somewhat misplaced since symlinks to directories already worked. The real value lies in the improved error handling and diagnostics. Junio Hamano suggested refining the commit message to reflect this, which the author has incorporated in this final version.

This represents a careful balance between security (maintaining protections against malicious `.git` files) and usability (better error messages). After eight iterations and thorough review from Junio and Karthik Nayak, the patch is ready for merging.
