This is part 2 of a 6-patch series in the ongoing `the_repository` removal effort, specifically targeting the merge-ort and replay subsystems. The patch comes from Elijah Newren, the foremost expert on Git's merge machinery.

The change modifies `write_tree()` in merge-ort.c to take a `struct repository*` parameter instead of relying on the global `the_repository`. This allows the function to operate on any repository instance rather than being tied to the singleton. As part of this change, the function now looks up the hash algorithm size directly from the passed repository rather than taking it as a parameter, simplifying the call sites.

The patch demonstrates careful attention to repository context propagation, with all callers updated to pass `opt->repo` to `write_tree()`. This is a straightforward but important step in the larger effort to make merge-ort fully repository-agnostic. The changes are mechanical but well-justified, with no behavioral impact beyond removing the global dependency.

This version (v3) comes after positive review feedback on earlier iterations, with no outstanding technical concerns. The patch fits cleanly into the series' overall goal of eliminating `the_repository` usage while maintaining Elijah's authoritative handling of merge-ort internals.
