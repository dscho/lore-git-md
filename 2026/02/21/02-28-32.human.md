This is a UX improvement suggestion for `git send-email` regarding character encoding prompts. Ben Knoble responds to Shreyansh Paliwal's report about confusing behavior when `git send-email` encounters non-ASCII characters in subject lines.

The current interface presents an ambiguous prompt ("Which 8bit encoding should I declare [UTF-8]?") that users can misinterpret as a yes/no confirmation, leading to malformed email headers when they answer "y" (which gets incorrectly used as the charset name). Ben suggests a small but clear improvement: changing the prompt to explicitly say "[default: UTF-8]" to make the expected input more obvious.

The issue is real but relatively minor - while some mail clients like Gmail handle the malformed headers gracefully, the raw encoding appears incorrectly in mailing list archives. This appears to be Ben's first contribution to this particular discussion, offering a straightforward suggestion while acknowledging the validity of the reported confusion. The thread remains open for further UX refinement ideas.
