This is a follow-up in the ongoing discussion about configurable cover letter formatting in `git format-patch`. The thread has evolved from Mirko Faina's initial proposal for numbered commit lists to a more flexible configuration-based approach suggested by maintainer Junio C Hamano.

Junio responds to Mirko's concern about the proposed command-line override syntax (`--cover-letter=log:"%s (%an)"`). He emphasizes that any configuration option must include a command-line override mechanism, since user preferences may vary by situation. Junio argues that even if a default works well most of the time, users still need the ability to temporarily override it - making the command-line option essential rather than defeating the purpose.

The exchange shows the thread converging on the core design (a printf-style `format.commitListFormat` configuration) while still working through interface details. Junio's position reflects Git's general philosophy that configurations should be overrideable, while Mirko's original concern highlights the tension between convenience and flexibility in CLI design.

Key technical points:
- The configuration direction is now agreed (printf-style format strings)
- Command-line override remains a requirement from the maintainer's perspective
- Exact syntax for the override (`--cover-letter=log:"..."`) may still need refinement
- Discussion has shifted from whether to implement to how best to expose the feature

This moves the RFC closer to implementation, with only the command-line interface details remaining as open questions. The maintainer's guidance suggests the feature will likely land with both config and CLI options, following Git's established patterns for similar customizable outputs.
