This is a follow-up in the ongoing discussion about improving `git format-patch`'s cover letter commit list format. Maintainer Junio C Hamano proposes a more flexible configuration-based approach than the original RFC's numbered list suggestion.

Junio suggests making the format configurable via `format.commitListFormat`, with the value acting as a printf-style format string (similar to `git log --format`). The format would automatically be prefixed with "[N/M]" numbering. Examples show how this could include just subjects ("[1/1] subject") or subjects with authors ("[1/1] subject (Author)"). The traditional shortlog format would remain the default when unconfigured.

The email also proposes a corresponding command-line option `--cover-letter=log:"format"` to override the config per-invocation. This builds on the original goal of better showing patch series flow while allowing customization beyond just numbered lists.

The thread has evolved from Mirko Faina's initial RFC proposing a specific numbered format to a more general solution that maintains the visibility improvement while accommodating different workflow preferences. Junio's response indicates conceptual approval of the feature's direction, with implementation details still to be worked out. The configurable approach addresses earlier concerns about rigid formatting while preserving the core benefit of clearer series navigation.
