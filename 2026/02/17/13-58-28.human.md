This is the second patch in a 4-part series addressing test failures on Windows/MSVC platforms related to `iconv(1)` availability when Git has ICONV support enabled. The patch focuses on improving test handling in t4205-log-pretty-formats.sh.

The key change makes the test encoding conditional on ICONV availability - using ISO-8859-1 when iconv is available and falling back to UTF-8 otherwise. This fixes test setup failures on platforms without the iconv(1) executable while maintaining test coverage. The patch also removes the ICONV prerequisite from many tests that don't actually need it, since they either don't reencode or can work with UTF-8 fallback.

Patrick Steinhardt has addressed all previous feedback in this v2 version, including proper handling of the encoding fallback and documenting the relationship between build-time NO_ICONV and test-time ICONV prerequisites. The changes are well-contained to the test script and maintain existing test coverage while making the tests more robust across platforms.

This is part of ongoing work to improve CI reliability on Windows/MSVC, particularly around encoding handling where Git for Windows no longer ships the iconv(1) executable. The patch series appears ready for merging after thorough review.
