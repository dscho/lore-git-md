This is part 2 of Shreyansh Paliwal's v4 series to remove `the_repository` and `the_hash_algo` globals from `wt-status.c`. The patch mechanically converts several functions in `wt-status.c` to use locally available repository instances (`s->repo` or `r`) instead of the global `the_repository`.

The changes are straightforward replacements where the repository parameter is already being passed or available through the `wt_status` struct. Key conversions include:
- Status initialization functions now use the passed repository rather than the global
- Diff and revision setup code uses the repository's hash algorithm
- Ref operations use the repository's ref store
- Path operations use the repository-relative path helpers

The patch maintains existing behavior while reducing reliance on global state. It follows the pattern established in part 1 of the series, focusing on mechanical conversions where the local repository is clearly available. The changes are limited to `wt-status.c` and don't yet address the broader worktree API standardization being discussed in parallel.

This continues the incremental progress on the `the_repository` removal effort while leaving architectural questions about worktree handling for future patches. The changes look well-contained and follow the established approach for these types of mechanical conversions.
