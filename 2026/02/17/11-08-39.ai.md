HTTP client refactoring for error handling. This is the second patch in Vaidas Pilkauskas's v3 series implementing HTTP 429 rate limiting support. It introduces a helper function to consolidate error message display and process termination in the remote-curl backend.

The patch adds `show_http_message_fatal()`, which combines the existing `show_http_message()` display logic and subsequent `die()` calls into a single NORETURN function. This refactoring eliminates repetitive error handling patterns across multiple HTTP status code cases (404, 401, etc.) in remote-curl.c. The new helper properly handles strbuf cleanup and uses the configured die message routine, while maintaining the same text/plain filtering behavior for server messages.

Key technical details:
- Preserves existing behavior for non-text/plain content and empty messages
- Properly releases strbuf resources before termination
- Uses va_list for formatted error messages
- Will be used by upcoming HTTP 429 handling code
- Follows Taylor Blau's suggestion for consolidation

The change touches only remote-curl.c, converting five existing error paths to use the new helper. This is a clean refactoring with no functional changes, preparing the codebase for the HTTP 429 retry logic in subsequent patches. The implementation appears solid, with careful attention to resource cleanup and control flow.
