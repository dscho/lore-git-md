This is a feature patch in the final polishing phase of a series enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch adds environment variable support (`GIT_REFERENCE_BACKEND`) to specify reference backends, complementing the existing config-based approach.

The implementation allows specifying alternate reference storage locations via URI format (`files` or `reftable:///path/to/refs`) through both config and environment variables. This is particularly useful for `git-clone` and `git-init` operations where the environment variable can dynamically set up the storage location. The patch handles stub creation in the repository's `$GIT_DIR` when using alternate reference folders, with careful consideration to maintain usability during migrations.

Patrick Steinhardt's review confirms the architectural approach makes sense but requests additional test verification that the alternate ref directory contains the actual data while the repository only contains stubs. The series has already received maintainer approval from Junio Hamano and addresses feedback from multiple reviewers, indicating it's nearing readiness for merging. This capability is critical for GitLab's large repository migration needs.
