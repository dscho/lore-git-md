Bugfix for strbuf memory allocation accounting. This patch corrects an off-by-one error in `strbuf_reencode()` where the allocated buffer size was incorrectly reported as the string length rather than length+1 (to account for the null terminator). The fix ensures proper memory management when the strbuf is later modified or freed.

The change is straightforward - passing `len + 1` instead of `len` as the allocation size parameter to `strbuf_attach()`. This matches the actual allocation done by `reencode_string_len()` which includes space for the null terminator. The patch touches only strbuf.c with a one-line change.

While this is a bugfix, it's worth noting this appears to be a theoretical rather than observed issue - there's no reports of actual problems caused by this in the commit message. The patch is part of a larger series about HTTP 429 retry support, but this particular fix is an independent strbuf correction that was presumably discovered during that work.
