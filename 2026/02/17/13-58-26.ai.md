Test infrastructure patch series addressing CI failures on Windows/MSVC platforms when the `iconv(1)` executable is unavailable despite Git being built with ICONV support. This is the second version of the series, now incorporating all feedback from reviewers.

Patrick Steinhardt explains that GitLab CI tests were failing because Git for Windows environments no longer include the `iconv(1)` binary, though the libiconv library (used by Git itself) remains available. The series modifies several test scripts to properly respect the ICONV prerequisite, which now checks for both the build-time ICONV support and the presence of the `iconv(1)` executable.

Key changes in v2 include:
- Extending the ICONV prerequisite definition in test-lib.sh to explicitly check for both the library and executable
- Adding a NEEDSWORK comment about potentially splitting these checks in the future
- Referencing the Git for Windows issue (#6083) about the missing `iconv(1)` binary
- Improved handling of the ICONV prerequisite in t4205-log-pretty-formats.sh

The series touches multiple test files (t4xxx, t4205, t5550, t6006) to ensure tests either skip when ICONV isn't fully available or use UTF-8 as a no-op fallback. The changes are mechanical but important for maintaining test reliability across platforms, particularly for Windows/MSVC CI environments. All outstanding feedback has been addressed and the series appears ready for merging.
