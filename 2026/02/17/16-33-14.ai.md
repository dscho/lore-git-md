This is a status update on Derrick Stolee's `--maximal-only` feature for `git rev-list`, which identifies commits that are not reachable by other commits (effectively finding "maximal" elements in the commit graph). The patch had been proposed for merging into the 'next' integration branch, and Stolee confirms it has been stable in testing for several weeks. Junio Hamano agrees to merge it, though he mildly questions whether "stable" is the most precise term, suggesting "dormant" might better reflect that there simply hasn't been further discussion rather than active validation. The feature represents a useful optimization for commit graph analysis, particularly in large repositories where identifying these maximal commits can simplify certain queries. The exchange is brief and procedural, with no technical concerns raised about the implementation at this stage.
