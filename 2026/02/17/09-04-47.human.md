Performance optimization series for `git config list --type=<X>` filtering, now in its final form. This is part 3 of a 13-patch series by Derrick Stolee that improves the efficiency of type-filtered config listing, originally motivated by performance issues in git-credential-manager when handling path-type config values.

The patch makes `--type=<X>` actually work for `git config list` by using the new `format_config()` infrastructure to parse and filter values during the initial pass, rather than parsing everything and then filtering. When type parsing fails for a value, that key-value pair is silently skipped (Patrick Steinhardt suggests documenting this design choice in the commit message). The implementation uses `fwrite()` for output since the formatted string may contain NUL bytes.

This is a key piece of the performance optimization, as it enables early filtering during parsing rather than post-processing. The thread shows consensus on the approach, with Patrick noting minor implementation details (like the choice of `fwrite` vs `puts`) but no substantive objections. The series appears ready for merging, having addressed all earlier feedback.
