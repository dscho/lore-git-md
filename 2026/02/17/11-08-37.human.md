This is the third version of a feature patch series adding HTTP 429 (rate limiting) retry support to Git's HTTP client. The series implements RFC-compliant handling of Retry-After headers with both delay-seconds and HTTP-date formats, introducing three config options: http.maxRetries (default 0), http.retryAfter (default 0), and http.maxRetryTime (300s delay ceiling).

Key changes in v3:
- Added a new helper function show_http_message_fatal() to reduce code duplication
- Simplified the retry architecture by replacing complex non-blocking delays with simple blocking sleep()
- Added support for curl's native CURLINFO_RETRY_AFTER parsing (for curl >= 7.66.0)
- Improved test portability by replacing GNU date commands with test-tool date
- Changed http.retryAfter default from -1 to 0 to allow immediate retries when no Retry-After header is present
- Squashed trace2 logging into the main commit

The implementation now cleanly handles both delay-seconds and HTTP-date formats for Retry-After headers, with configurable limits on retry attempts and maximum delay times. The tests demonstrate proper behavior across various scenarios including header parsing, delay enforcement, and configuration overrides.

The patch series has evolved based on feedback from Jeff King and Taylor Blau, with v3 addressing architectural concerns and improving portability. The changes appear well-considered and the test coverage is thorough, suggesting this is a robust implementation of HTTP rate limiting support.
