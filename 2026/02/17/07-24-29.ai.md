This is a feature patch in the final polishing phase of a series enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch adds `GIT_REFERENCE_BACKEND` environment variable support, complementing the existing `extensions.refStorage` config option, to allow runtime specification of reference storage location and format.

The implementation handles stub creation/removal in the generic refs layer rather than backend-specific code, with special consideration for worktree cases. The environment variable supports the same format as the config option (`files` or `reftable:///path/to/refs`), enabling consistent behavior across configuration methods. The patch includes tests for both `git init` and `git clone` scenarios.

Patrick Steinhardt's review confirms the architectural approach but requests additional test verification that the alternate ref directory contains the actual references while the repository only contains stubs. The series has already addressed extensive feedback from multiple reviewers and has maintainer approval from Junio Hamano, with only minor documentation and test improvements remaining before merging.

Key technical aspects include URI parsing in `parse_reference_uri()`, environment variable handling in `setup_ref_storage()`, and comprehensive path management through the new `refs_compute_filesystem_location()` infrastructure. The changes maintain compatibility with worktree reference locations while adding the new environment-based configuration capability.
