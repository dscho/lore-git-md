This is a test infrastructure patch series from Patrick Steinhardt addressing CI failures on Windows/MSVC platforms related to the `iconv(1)` executable availability. The series builds on previous discussion that clarified the distinction between libiconv (linked into Git) and the `iconv(1)` executable (used in test scripts).

The core issue is that tests were failing when Git was built with ICONV support but the `iconv(1)` executable wasn't available - a situation that occurred in GitLab CI's MSVC jobs where Git for Windows no longer ships the `iconv(1)` binary. The patches modify several test scripts to properly respect the ICONV prerequisite, which now checks for both the build-time ICONV support and the presence of the `iconv(1)` executable.

The series has gone through review with feedback incorporated from Junio Hamano, Torsten Bögershausen, and Christian Couder. All outstanding issues have been addressed, including documenting the relationship between build-time NO_ICONV and test-time ICONV prerequisites and referencing the relevant Git for Windows issue (#6083). The changes are focused and well-justified, with each patch modifying specific test files to handle the ICONV prerequisite properly.

This appears ready for merging and will help stabilize the MSVC CI jobs while maintaining proper test coverage. The approach is pragmatic - rather than introducing a separate ICONV_EXECUTABLE prerequisite, it extends the existing ICONV prerequisite to cover both requirements, with a NEEDSWORK comment noting this could potentially be split in the future.
