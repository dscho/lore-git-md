Test infrastructure patch from Patrick Steinhardt fixing CI failures related to `iconv(1)` availability on Windows/MSVC platforms, now in its second version. This is part of a series addressing test failures that occur when Git is built with ICONV support (using libiconv) but the `iconv(1)` executable isn't available, which no longer ships the `iconv(1)` binary by default.

The patch modifies several test scripts (`t4041`, `t4059`, `t4060`) that use `iconv(1)` to convert commit message encodings. Previously these tests would attempt to use `iconv(1)` even when the ICONV prerequisite wasn't met, which could fail if the binary was missing. The new version properly skips the `iconv(1)` call when the prerequisite isn't set, falling back to UTF-8 encoding (effectively a no-op conversion).

The test-lib.sh changes extend the ICONV prerequisite definition to explicitly check for both the library support (via `NO_ICONV`) and the executable availability. A NEEDSWORK comment notes this might be worth splitting into separate prerequisites in the future. The patch references Git for Windows issue #6083 about the missing `iconv(1)` binary.

This version incorporates all feedback from the initial submission, including documentation improvements and clearer prerequisite handling. The changes are straightforward and focused on making the tests more robust across platforms while maintaining their existing functionality when full ICONV support is available.
