This is a test infrastructure patch from Patrick Steinhardt, part of a series addressing CI failures on Windows/MSVC platforms related to `iconv(1)` availability. The patch fixes several tests that were incorrectly trying to use the `iconv(1)` executable even when the ICONV prerequisite wasn't met.

The issue stems from Git for Windows no longer shipping the `iconv(1)` binary, though the underlying libiconv support remains available. The tests were prepared to handle missing iconv support by falling back to UTF-8, but still attempted to call the executable. This caused failures in CI where the binary was unavailable.

The patch makes three key changes:
1. Modifies multiple test scripts to properly skip `iconv(1)` calls when the ICONV prerequisite isn't met
2. Updates the ICONV prerequisite definition in test-lib.sh to check for both the library and executable
3. Adds a NEEDSWORK comment about potentially splitting these checks in the future

This is the second version of the patch, incorporating all feedback from the initial submission. The changes are straightforward and focused on test reliability, particularly for Windows/MSVC environments. The patch references Git for Windows issue #6083 for context but doesn't depend on its resolution.
