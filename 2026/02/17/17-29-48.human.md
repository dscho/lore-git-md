This is the third and final patch in Shreyansh Paliwal's v4 series removing `the_repository` and `the_hash_algo` globals from `wt-status.c`. It completes the mechanical conversion work by replacing remaining uses of `the_hash_algo` with the hash algorithm from the local repository instance (`r->hash_algo` or `s->repo->hash_algo`).

The patch makes three straightforward changes:
1. Updates `null_oid()` calls in cherry-pick/revert state tracking to use the repository's hash algorithm
2. Changes the empty tree lookup to use the repository's hash algorithm
3. Maintains all existing behavior while removing global state dependencies

This follows the same incremental pattern as the first two patches in the series, focusing narrowly on mechanical conversions while deferring broader architectural questions about worktree handling to ongoing parallel discussions. The changes are small but meaningful - each eliminated global reference makes the code more self-contained and easier to reason about in multi-repository contexts.

With this patch, the wt-status.c conversions are complete, demonstrating a viable pattern for `the_repository` removal that other subsystems can follow. The series appears ready for review, with the broader worktree API standardization discussions continuing separately.
