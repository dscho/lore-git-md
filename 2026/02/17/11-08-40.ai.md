This is the final patch in a 3/3 series implementing HTTP 429 (rate limiting) retry support for Git's HTTP client. The series has evolved through multiple iterations addressing feedback from Jeff King and Taylor Blau.

The patch adds comprehensive retry-After header handling for HTTP 429 responses, supporting both delay-seconds and HTTP-date formats. It introduces three new options:
- `http.maxRetries` (default 0)
- `http.retryAfter` (default 0)
- `http.maxRetryTime` (300s ceiling)

Key technical details:
- Uses curl's native CURLINFO_RETRY_AFTER parsing when available (curl >= 7.66.0)
- Falls back to manual header parsing for older curl versions
- Implements blocking sleep() for retry delays (simpler than v2's non-blocking approach)
- Adds extensive test coverage including edge cases
- Includes trace2 instrumentation for monitoring retries
- Properly handles HTTP-date parsing and time comparisons
- The implementation fails fast when delays exceed maxRetryTime rather than capping
- Environment variables can override all three config options
- Test suite uses test-tool date for portability

The patch touches http.c, http.h, remote-curl.c, and adds new test scripts. It builds on preparatory refactoring from patch 2/3 which consolidated error handling paths. All major feedback from v2 has been addressed, making this a mature implementation ready for consideration.

The series represents a significant improvement in Git's ability to handle rate-limited HTTP responses gracefully, particularly useful for services like GitHub and GitLab that implement API rate limits. The comprehensive test coverage and careful handling of edge cases suggest this is production-ready code.
