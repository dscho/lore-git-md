Refactoring patch in the HTTP 429 rate limiting series. This is the second of three patches implementing RFC-compliant HTTP 429 (rate limiting) retry support in Git's HTTP client.

Vaidas Pilkauskas introduces a new helper function `show_http_message_fatal()` in remote-curl.c that combines the common pattern of showing an HTTP error message followed by terminating with die(). The helper handles displaying server error messages (filtering for text/plain content) and then exits with a configurable error message, reducing code duplication at several call sites. The change was suggested by Taylor Blau during review of the series.

The patch is straightforward - it consolidates error handling that previously repeated the show+die pattern in multiple places. The new helper will also be used by the upcoming HTTP 429 support. Test coverage appears to be handled by the existing HTTP tests rather than requiring new ones for this refactoring.

This is a clean, focused change that improves maintainability without altering behavior. The series has already addressed significant review feedback from Jeff King and Taylor Blau in prior iterations, and this patch represents a logical step in preparing the codebase for the rate limiting functionality.
