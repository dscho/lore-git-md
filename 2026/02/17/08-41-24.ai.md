Security patch refining Git's repository discovery to properly handle `.git` symlinks while maintaining security against malformed repository attachments. This is v4 of a series addressing cases where Git could incorrectly attach to parent repositories through unsafe `.git` entries.

The patch makes several key changes to `setup.c`:
- Switches from `lstat()` to `stat()` for `.git` checks, allowing symlinks to directories while still rejecting FIFOs/sockets
- Introduces refined error handling with new `READ_GITFILE_ERR_STAT_ENOENT` and `READ_GITFILE_ERR_IS_A_DIR` codes
- Maintains security by explicitly rejecting non-file `.git` entries (FIFOs, sockets) with clear error messages
- Adds comprehensive test coverage in new `t/t0009-setup-security.sh` verifying:
  - Valid symlinked `.git` directories
  - Rejection of FIFO `.git` files
  - Rejection of symlinks to FIFOs
  - Rejection of garbage `.git` content
  - Proper handling of empty `.git` directories

The implementation now cleanly separates four cases: missing files (continue searching), directories (check if valid repo), non-files (reject), and other errors (die). This addresses Junio Hamano's concerns from v3 about incorrect error handling while maintaining the security properties of rejecting potentially dangerous repository attachments. The test coverage appears thorough, exercising both the happy path and various edge cases.
