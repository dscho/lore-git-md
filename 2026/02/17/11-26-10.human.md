This is a review comment on a security patch series about Git repository discovery hardening. Karthik Nayak provides feedback on Tian Yuchen's v4 patch that allows `.git` to be a symlink while maintaining security against malicious repository attachments.

The review focuses on two main suggestions: (1) splitting the changes into smaller, test-accompanied commits for better reviewability, and (2) improving the error handling logic to be less convoluted. Karthik questions whether the error code exclusions should be moved into `read_gitfile_error_die()` rather than being handled at the call site, and notes some potential confusion around the `die_on_error` flag behavior.

The review is constructive and technical, coming after Junio Hamano's earlier concerns have been addressed in v4. Karthik suggests renaming the test script to better reflect its purpose (`t0009-git-dir-validation.sh` rather than `t0009-setup-security.sh`). The feedback indicates the series is nearing readiness but could benefit from some structural cleanups before final acceptance.
