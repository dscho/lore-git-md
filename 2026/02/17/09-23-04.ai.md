This is a worktree API refactoring patch that follows up on the ongoing effort to standardize worktree handling in Git. Phillip Wood corrects a typo in his previous patch (s/commondir/gitdir/) and mentions plans to add a test for `git status` behavior during rebases in linked worktrees.

The changes focus on eliminating NULL worktree parameters in wt-status.c by introducing `get_worktree_from_repository()` to construct worktree structs from repository data. Key technical points:

1. The patch adds BUG() assertions when NULL worktrees are passed to `wt_status_check_rebase()` and `wt_status_check_bisect()`, enforcing explicit worktree handling.

2. `wt_status_get_state()` now constructs a temporary worktree struct via `get_worktree_from_repository()` rather than passing NULL, maintaining the same behavior while being more explicit.

3. The worktree struct construction follows Junio Hamano's guidance on comparing gitdir and commondir paths to determine worktree relationships.

This continues the incremental approach to worktree API cleanup while preserving backward compatibility. The changes touch core status-checking functions and path handling, with Phillip indicating he'll wait for additional feedback before sending a revised version with tests. The patch aligns with the broader effort to make worktree handling more robust and explicit throughout the codebase.
