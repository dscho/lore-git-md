This is the second patch in a 4-part series addressing test failures on Windows/MSVC platforms related to ICONV support. The patch focuses on improving test handling in t4205-log-pretty-formats.sh.

The key change makes the test encoding conditional on ICONV availability - using ISO-8859-1 when ICONV is available and falling back to UTF-8 otherwise. This fixes test setup failures that occurred when the iconv(1) executable was missing, even when the ICONV prerequisite wasn't set. The patch also removes the ICONV prerequisite from many tests that don't actually need it, since they either don't do encoding conversion or handle it through the new conditional logic.

The changes are mechanical but well-considered, with the patch:
1. Adding proper fallback behavior for platforms without iconv(1)
2. Cleaning up unnecessary ICONV prerequisites
3. Maintaining all existing test coverage
4. Preserving the distinction between tests that do/don't need encoding conversion

This builds on the thread's established understanding of the libiconv vs iconv(1) distinction and addresses all prior feedback. The changes are focused specifically on t4205 while the series handles similar issues across multiple test files. The patch is ready for merging as part of the complete series.
