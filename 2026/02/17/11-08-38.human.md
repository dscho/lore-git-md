Bugfix for strbuf memory allocation accounting. This patch corrects an off-by-one error in `strbuf_reencode()` where the allocated buffer size wasn't properly accounting for the null terminator. The fix ensures `strbuf_attach()` receives the correct allocation size (len + 1) to match what `reencode_string_len()` actually allocated. 

This appears to be a straightforward correction to a subtle memory accounting issue. The impact is likely limited to edge cases where code relies on the strbuf's alloc field being accurate, but the fix is clearly correct and aligns with how the string allocation works internally. The patch is small, focused, and comes with a clear explanation of both the problem and solution.

While this patch is part of a larger series about HTTP 429 retry support, it stands alone as an independent strbuf fix. The change is simple enough that it could potentially be picked up by Junio for the maint branch if deemed important enough, though it doesn't appear to be fixing any actively reported bug.
