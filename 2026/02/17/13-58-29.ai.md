Test infrastructure patch from Patrick Steinhardt addressing CI failures related to HTTP error message encoding tests when the `iconv(1)` executable is unavailable. This is part of a series fixing test failures on Windows/MSVC platforms where Git is built with ICONV support (using libiconv) but lacks the `iconv(1)` executable.

The patch modifies t5550-http-fetch-dumb.sh to properly guard tests that depend on the `iconv(1)` executable with the ICONV prerequisite. These tests verify that HTTP error messages are correctly reencoded, which requires both the libiconv library (linked into Git) and the `iconv(1)` executable (used by test scripts). The changes include:

1. Adding ICONV prerequisite to tests that hit "$HTTPD_URL/error" endpoints, which use error.sh script requiring iconv(1)
2. Converting plain `grep` calls to `test_grep` for consistency
3. Keeping non-encoding-related tests (like Accept-Language header checks) unchanged

This follows the pattern established in earlier patches of the series, maintaining the distinction between libiconv (runtime dependency) and iconv(1) (test tool dependency). The changes are straightforward and align with the thread's consensus that tests requiring iconv(1) should be properly guarded while still verifying core functionality where possible.

Key technical details:
- Tests affected involve HTTP error message handling via error.sh script
- Uses test_grep instead of raw grep for better test output
- Preserves existing behavior for non-encoding tests
- Part of broader Windows/MSVC CI fixes addressing iconv(1) availability

The patch has already incorporated all feedback from previous rounds and is ready for merging as part of the complete series.
