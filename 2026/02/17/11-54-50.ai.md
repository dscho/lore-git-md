This is a test infrastructure patch series addressing CI failures on Windows/MSVC platforms related to `iconv(1)` executable availability. The series is now in its final form after incorporating all review feedback.

Patrick Steinhardt has addressed Christian Couder's final comments about documenting the relationship between the build-time `NO_ICONV` flag and test-time `ICONV` prerequisite. The series modifies several test scripts to properly conditionally use `iconv(1)` only when the prerequisite is met, fixing test failures that occurred when Git was built with ICONV support but the `iconv(1)` executable wasn't available (a common scenario on Windows/MSVC).

Key technical points include: the distinction between libiconv (linked into Git) versus the `iconv(1)` executable (used in scripts), Windows-specific behavior where MinGW no longer ships the `iconv(1)` binary, and the test strategy of falling back to default UTF-8 encoding when ICONV isn't available. The series also references GitHub issue #6083 about `iconv(1)` in Git for Windows.

All outstanding issues have been resolved except for documenting the `NO_ICONV`/`ICONV` relationship, which Patrick plans to address in the test library. The discussion has converged with agreement from Junio Hamano, Torsten Bögershausen, and Christian Couder, and the series is now considered ready for merging. This work is part of ongoing CI/test infrastructure improvements for Windows/MSVC platforms.
