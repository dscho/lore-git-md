Bugfix for `git format-patch` cover letter generation regarding `--from` option handling.

This is a follow-up discussion on a bugfix that ensures the `--from` option is properly respected in cover letters when generating patch series with `git format-patch`. The original issue was that while individual patches in a series correctly used the specified sender identity, cover letters ignored this setting and defaulted to the committer's identity.

Patrick Steinhardt reviews Mirko Faina's proposed fix, agreeing with the technical approach but suggesting two improvements. First, he notes that the documentation currently implies `--from` only applies to commit emails, not cover letters, and suggests updating this wording to match the intended behavior. Second, he proposes a more focused test case that specifically verifies the cover letter behavior rather than checking both cover letter and patches in one test.

The changes themselves are straightforward - a 6-line modification to `builtin/log.c` that properly checks the configured `from` value before falling back to default committer info. The patch appears technically sound and ready for merging, having already incorporated all previous maintainer requests in its second version. This is a clear inconsistency fix that makes the tool behave more predictably when generating complete patch series.
