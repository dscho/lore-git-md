This is a follow-up discussion about documentation clarification for a bugfix patch addressing `git format-patch`'s `--from` option behavior in cover letters. The thread has already established the technical correctness of the fix (which ensures cover letters respect the `--from` sender identity like individual patches do), and now focuses on updating the documentation to explicitly include cover letters in the `--from` option's scope.

D. Ben Knoble points out an interesting inconsistency in the documentation ecosystem: while `git format-patch`'s man page currently describes `--from` as applying to "each commit email" (implying it excludes cover letters), the `git send-email` documentation's main example shows cover letters being generated by `format-patch` before being sent. This real-world usage pattern suggests the documentation should be updated to match actual practice.

The exchange reveals some historical context from Jeff King (original author of the `--from` implementation) that the cover letter case was simply overlooked in 2013 rather than intentionally excluded. Patrick Steinhardt had earlier flagged this documentation ambiguity, and the consensus is forming that the man page should be clarified to explicitly state that `--from` applies to both individual patches and cover letters.

This is a minor but important polish item before the patch can be merged - the actual code behavior is correct and tested, but the documentation needs to catch up to reflect the intended (and now properly implemented) behavior. The discussion shows how even small fixes can surface interesting documentation inconsistencies that span multiple commands.
