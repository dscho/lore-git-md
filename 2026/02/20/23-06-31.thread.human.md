This thread has progressed from an RFC to a nearly finalized design for configurable cover letter formatting in `git format-patch`. The original proposal by Mirko Faina sought to improve the commit list presentation in cover letters, initially suggesting a numbered chronological format. Through discussion, maintainer Junio C Hamano guided the solution toward a more flexible approach using printf-style format strings via a new `format.commitListFormat` configuration, while insisting on preserving the ability to override defaults via command-line.

The key technical decision establishes that cover letters will show commits in "[N/M] subject" format by default, with options to customize the display (including author names via "%a" specifier). Junio has made clear that command-line override capability is non-negotiable, and Mirko has accepted this requirement, committing to implement it in the coming week. While some implementation issues remain (like output ordering and memory handling), the design itself has reached consensus.

With the architectural questions settled and only implementation work remaining, this feature appears on track for inclusion in an upcoming release. The discussion demonstrates Git's characteristic evolution of proposals through maintainer guidance - preserving the original goal of better cover letter customization while ensuring the solution fits Git's configuration philosophy. The thread has effectively moved from design to execution phase, with the remaining work focused on polishing the command-line interface syntax before final submission.
