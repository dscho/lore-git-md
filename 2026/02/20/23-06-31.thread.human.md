This RFC thread explores making `git format-patch` cover letters more informative by allowing customization of how commit lists are displayed. The discussion began with Mirko Faina's proposal for numbered commit lists, but maintainer Junio Hamano steered the conversation toward a more flexible solution using printf-style format strings via a new `format.commitListFormat` configuration. The default would show "[N/M] subject" to maintain series flow visibility while allowing customization to include author names or other details.

The thread has reached broad agreement on the configurable approach, with Junio's direction now clearly favored. Mirko supports the core idea but raises concerns about the proposed command-line syntax (`--cover-letter=log:"%s (%an)"`), worrying that requiring manual format strings might make the feature less accessible. He suggests timing any default behavior changes with Git 3.0. While some implementation issues remain (like output ordering and memory handling), the discussion is currently focused on finalizing the user interface - particularly the format string syntax and command-line options - before addressing those lower-level concerns. The thread demonstrates how an initial concrete proposal can evolve through maintainer feedback into a more general solution while preserving its original goal of improving patch series readability.
