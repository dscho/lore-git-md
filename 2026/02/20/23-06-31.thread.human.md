This thread discusses an RFC proposal to change how `git format-patch` displays commit lists in cover letters. The current author-grouped shortlog format would be replaced with a numbered chronological list showing each commit as "[N/M] abcd123: summary" to make the patch series flow more apparent. The original patch from Mirko Faina modifies `builtin/log.c` to generate this sequential output while maintaining existing line wrapping and proper memory handling.

In a follow-up, Mirko acknowledges two prototype issues - reverse ordering and a memory leak - but emphasizes these are implementation details to be fixed later. The primary focus remains gathering feedback on whether the new format would be more useful than the current author-grouped presentation. Key open questions include whether to make the format configurable rather than hardcoded, how to document the change, and what test coverage would be needed.
