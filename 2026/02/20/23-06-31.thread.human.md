This RFC patch series introduces configurable formatting for the commit list in `git format-patch` cover letters, allowing users to customize the output via both command-line (`--cover-letter-format`) and configuration (`format.commitListFormat`) options. The implementation builds on Git's existing formatting infrastructure while maintaining backward compatibility.

The series has seen thorough review from Jeff King (Peff) on architectural soundness and active maintainer involvement from Junio C Hamano, who has squashed several critical improvements into the 'seen' branch. These include const-correctness fixes, validation timing adjustments, and expanded test coverage. Author Mirko Faina has been responsive to feedback, addressing style issues, simplifying logic, and improving test coverage - now extending beyond direct format-patch tests to broader integration cases.

The most recent discussion focused on a subtle implementation choice regarding newline handling in format strings. While Junio suggested preprocessing the format string to include newlines, Mirko maintained that preserving user control over newlines was preferable. Junio accepted this rationale, demonstrating the collaborative refinement process typical of Git development.
