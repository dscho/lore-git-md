Mirko Faina's RFC series to make `git format-patch` cover letter commit lists configurable has progressed to version 2, now reduced to two patches from the original. The series introduces both command-line (`--cover-letter-format`) and config-based (`format.commitListFormat`) options to control how commits are listed in cover letters, with format strings following the same "shortlog" or "log:<format>" syntax as other Git commands.

Jeff King (Peff) provided key architectural guidance that shaped the implementation, particularly around proper use of `repo_format_commit_message()` and NULL handling. The current version addresses these concerns while maintaining backward compatibility - when unconfigured, it falls back to the traditional shortlog format. The implementation is focused in `builtin/log.c` with careful memory management via `format_config_release()`.

With the command-line interface solidified in patch 1/2 and the config option now added in patch 2/2, the series has cleared its major technical hurdles. Remaining work includes finalizing test coverage for format combinations and documentation updates. The feature will be particularly useful for regular patch submitters who want more control over their cover letter presentation. The series appears ready for final review, with Junio likely to queue it once the remaining polish is addressed.
