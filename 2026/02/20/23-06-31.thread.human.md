This RFC thread explores adding configurable commit list formatting for `git format-patch` cover letters, allowing both command-line (`--cover-letter-format`) and config-based (`format.commitListFormat`) control. The discussion has centered around proper integration with Git's pretty-printing subsystem.

Jeff King (Peff) provided crucial architectural guidance, identifying that the initial approach incorrectly used `get_commit_format()`/`pp_commit_easy()` with global state. He recommended instead using `repo_format_commit_message()` for one-off formatting, supplying a concrete diff showing the proper implementation. This resolved both the technical approach and validated Junio C Hamano's earlier position that NULL format handling should be treated as a programming error.

Author Mirko Faina has now acknowledged this feedback, confirming they will:
1) Drop the first patch (which addressed NULL handling separately)
2) Reimplement patch 2/3 using the recommended API
3) Maintain the existing memory management and backward compatibility

The series is now unblocked with a clear technical path forward. Remaining work includes implementing these changes, adding test coverage for format combinations, and finalizing documentation. Peff's review has effectively resolved the major questions about subsystem integration while preserving the feature's core value of flexible cover letter presentation.
