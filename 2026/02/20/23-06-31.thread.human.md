This thread documents the development of a feature to add configurable cover letter formatting to `git format-patch`, now in its final form after seven iterations. The series introduces both command-line (`--cover-letter-format`) and configuration (`format.commitListFormat`) options while maintaining backward compatibility with the traditional shortlog-based output. Key technical components include new functions in `builtin/log.c`, special placeholder support in `pretty.c`, and comprehensive test coverage.

The most recent patch (v7) addresses a minor test suite typo where `test_expected_success` was incorrectly used instead of the standard `test_expect_success` macro. Junio C Hamano caught this during final review. While the fix itself is trivial, it represents the final polish on a series that has already addressed all major technical and documentation requirements. The test in question verifies the new formatting options, including the `%(count)` and `%(total)` placeholders that provide patch numbering functionality.

The series has received thorough review from multiple contributors. Junio has approved the architecture and confirmed the documentation is complete, while Jeff King (Peff) designed the numbering approach. Author Mirko Faina has incorporated all feedback and considers this version final, though minor discussions continue about the "log:" prefix requirement and config value typing (boolean vs string). With these last polish items addressed, the feature appears ready for merging, offering flexible cover letter formatting while preserving backward compatibility.
