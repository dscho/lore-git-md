This RFC patch series introduces configurable formatting for commit lists in `git format-patch` cover letters, now at version 2. The implementation provides both command-line (`--cover-letter-format`) and config-based (`format.commitListFormat`) control over how commits are presented, while maintaining backward compatibility with the traditional shortlog format.

The architectural approach has been validated by Jeff King (Peff), with the implementation correctly using Git's `repo_format_commit_message()` API. Junio C Hamano has been reviewing the details, initially raising concerns about NULL handling (now resolved) and more recently focusing on style and implementation polish in the second patch. His latest review notes several areas needing attention: consistent asterisk placement in variable declarations, proper memory management when the config option is set multiple times, and questions about validation timing and control flow. He also provides guidance on the standard pattern for handling configuration precedence.

With the major technical questions settled, the series is now in its final polishing phase. The author, Mirko Faina, needs to address Junio's style and implementation feedback before resubmitting. Once these final tweaks are made, this feature - which will be particularly useful for frequent patch submitters - appears ready for inclusion.
