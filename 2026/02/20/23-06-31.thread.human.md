This thread discusses an RFC patch proposing to change how `git format-patch` generates the commit list in cover letters. The current author-grouped shortlog format would be replaced with a numbered chronological list showing each commit as "[N/M] abcd123: summary" to make the patch flow more immediately apparent.

The patch modifies `builtin/log.c` to implement this change while maintaining existing line wrapping and hash formatting. The implementation appears clean and focused, removing the shortlog dependency while preserving all information in a more useful order. The author has marked this as RFC to gather feedback on the design before finalizing.

Open questions remain about whether the format should be configurable (currently hardcoded) and what test coverage/documentation updates would be needed. The change is well-contained, only affecting cover letter generation without modifying patch email subjects. The thread appears to be in early discussion stages, with the author seeking input on whether this approach addresses a genuine pain point in the patch submission workflow.
