This thread discusses Mirko Faina's RFC patch series adding configurable cover letter formatting to `git format-patch`, allowing customization of how commit lists appear in cover letters via command-line (`--cover-letter-format`) and config (`format.commitListFormat`) options. The series has evolved through several versions with substantial input from Jeff King (Peff), who provided detailed technical reviews on format string processing and proposed an extension for customizable patch numbering formats.

The current version (v3) has incorporated all major feedback, including deferred default value assignment, robust format validation, and special-case handling for "shortlog" output. Peff's new proposal for patch numbering customization (using `%(count)` and `%(total)` placeholders) remains under discussion, with questions about its utility versus complexity still open. Maintainer Junio C Hamano has squashed several fixes into the series, which currently resides in the 'seen' integration branch.

In the latest exchange, Junio pointed out a minor code style issue - suggesting use of the `starts_with()` helper function instead of manual string length checks when validating format prefixes. While acknowledging this is a small nit (the prefixes are unlikely to change), his comment exemplifies Git's attention to implementation quality even in mature patches. The series appears technically sound and is now in the final polishing phase before potential promotion to 'next', pending resolution of the numbering format question and completion of any additional test coverage.
