RFC-to-feature patch series implementing comprehensive cover letter formatting for `git format-patch`, now in final form ready for merging. The series provides:

1. Core formatting system with:
   - Unified processing of CLI (`--cover-letter-format`) and config (`format.commitListFormat`) formats
   - Special "shortlog" handling for backward compatibility (now refactored into dedicated `generate_shortlog_cover_letter()` function)
   - New `generate_commit_list_cover()` and `generate_shortlog_cover_letter()` functions
   - Config behavior matrix (unset->shortlog, empty->default format, custom formats)
   - Proper memory management for config option
   - Consistent "log:" prefix requirement for all non-shortlog formats

2. Patch numbering in `pretty.c`:
   - Zero-padded `%(count)` matching total width (Peff's design)
   - Strict context validation limiting placeholders to cover letters
   - Width calculation based on total patch count
   - New `%(total)` placeholder for series size
   - Context enforcement via `rev_info` requirement
   - Clear error messages for invalid usage contexts

3. Documentation complete with:
   - Explanation of `--cover-letter-format` CLI option
   - `format.commitListFormat` config variable details
   - Examples of format strings with placeholders (`%s` for subject, `%an` for author name)
   - Demonstration of numbering scheme (`%(count)`/`%(total)`) usage
   - Clear specification of "log:" prefix requirement
