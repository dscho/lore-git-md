This is a follow-up discussion about potential improvements to `git format-patch`'s cover letter generation, building on the recently approved fix for the `--from` option handling.

The conversation between Junio Hamano and Jeff King focuses on enhancing how patch series are listed in cover letters. Jeff confirms Junio's suggestion to replace the current shortlog-based listing with a more readable `log --oneline --reverse` format, noting he's personally used this format in his scripts since 2009 without issues. He explains this would be straightforward to implement since `format-patch` already has access to the complete patch list and subjects.

The exchange positions this as a good "leftoverbits" project - a small, self-contained improvement that could be tackled by a newer contributor. While separate from the just-approved `--from` fix, this discussion builds on the same area of code in `builtin/log.c` and represents a long-standing quality-of-life issue with cover letters. Jeff's historical context and implementation insight suggest this would be technically feasible, though the thread makes clear this is future work rather than a blocker for the current fix.
