This is the second patch in Burak Kaan Karaçay's GSoC 2026 series refactoring Git's mailmap subsystem to remove global state dependencies, part of the ongoing `the_repository` removal effort. The patch eliminates the global variables `git_mailmap_file` and `git_mailmap_blob` that previously stored mailmap configuration, replacing them with on-demand config reading via `repo_config_get_*` functions.

The changes are mechanical but important for reducing global state. The patch removes the mailmap-specific config handling from `environment.c`, updates `mailmap.c` to read config values when needed (freeing them afterward), and removes the now-unused variable declarations from `mailmap.h`. The behavior remains identical - including the fallback to "HEAD:.mailmap" in bare repositories - but without maintaining the values globally.

This follows the first patch's conversion of mailmap functions to take explicit `struct repository` parameters. Together they complete the mailmap subsystem's decoupling from implicit global state. The v2 revision fixed a header inclusion issue caught by `make hdr-check`, and Junio C Hamano has already approved the design. The changes are well-contained, touching only mailmap-related files while maintaining backward compatibility. This is a clean, focused contribution that advances the broader `the_repository` removal goal.
