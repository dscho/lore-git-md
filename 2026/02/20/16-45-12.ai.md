Bugfix addressing symlinked `.git` directory handling with security implications. This is the final version (v8) of a series that has undergone extensive review, now squashed into a single commit.

The patch fixes Git's overly restrictive rejection of symlinked `.git` directories while maintaining security by still rejecting dangerous cases like FIFOs and invalid gitfiles. Key changes include:

1. Introducing new error codes (`READ_GITFILE_ERR_STAT_ENOENT`, `READ_GITFILE_ERR_IS_A_DIR`) to distinguish directory cases from other non-file types
2. Modifying `setup_git_directory_gently_1()` to properly handle symlinks to directories while maintaining existing security checks
3. Adding comprehensive test coverage in new test script `t0009-git-dir-validation.sh` that verifies:
   - Valid symlink-to-directory cases
   - Rejection of FIFOs and symlinks-to-FIFOs
   - Handling of garbage gitfile content
   - Empty directory cases

The implementation has been carefully reviewed by Junio Hamano and Karthik Nayak across multiple iterations, with all feedback incorporated. Changes from previous versions include optimized filesystem checks, clearer error handling via switch statements, and elimination of an uninitialized variable hazard. The patch maintains all security boundaries while allowing legitimate symlink use cases.

This represents a careful balance between security and usability, building on Git's long-standing security restrictions around `.git` directory handling. The thorough test coverage and multiple rounds of review suggest this is ready for merging.
