Patrick Steinhardt's 17-patch series to unify Git's ref iteration interfaces is nearing completion, with Karthik Nayak having reviewed and approved the overall approach. The series consolidates 14 specialized ref iteration functions into a single `refs_for_each_ref_ext()` API with configurable options, while maintaining identical behavior. Significant performance improvements have been demonstrated, including a 107x speedup (115ms to 1.1ms) for glob pattern matching by handling it directly in the iteration core.

The latest patch (11/17) removes the specialized `refs_for_each_ref_in()` function, converting all its callers to use the new unified API. This affects several key areas including bisect handling, ref listing, bitmap preferred tips iteration, and core ref iteration for tags/branches/remotes. The changes are mechanical but important for reducing API surface area. Earlier patches have already addressed namespace handling, input validation, documentation improvements, and performance optimizations.

Karthik Nayak has provided thorough review throughout, with Oswald Buddenhagen also contributing to the discussion around patch ordering. The series represents a significant step in the broader ref backend modernization effort, with only minor open questions remaining about prefix trimming behavior and the future handling of the remaining specialized `refs_for_each_replace_ref()` case. The changes integrate well with existing subsystems like ls-refs and ref-filter while establishing patterns that may influence future API designs.
