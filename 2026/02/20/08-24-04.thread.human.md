Patrick Steinhardt continues his ref iteration API unification series with a third preparatory change. The thread focuses on simplifying Git's ref iteration interface by consolidating 14 specialized functions into a more general API. 

The first two patches were non-functional reorganizations - moving a function declaration and relocating an enum definition. This third patch makes a mechanical change to rename the `do_for_each_ref_flags` enum to `refs_for_each_flag` and updates all flag names to use a consistent `REFS_FOR_EACH_` prefix. The changes touch multiple ref backend implementations (files, packed, reftable) but don't alter any behavior - this is purely about establishing better naming conventions before the more complex refactoring to come.

So far the series is proceeding incrementally with uncontroversial preparatory steps. The next patches will likely introduce the more substantial changes, including the new unified `refs_for_each_ref_ext()` function that will replace many of the existing specialized iteration variants. The careful, step-by-step approach suggests Patrick is setting up for smooth integration of the more complex refactoring to follow.
