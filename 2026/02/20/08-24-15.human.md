This is patch 11 in Patrick Steinhardt's 17-part series refactoring Git's ref iteration API. The series aims to replace 14 specialized ref iteration functions with a single unified `refs_for_each_ref_ext()` interface.

This patch removes `refs_for_each_ref_in()`, converting all its callers to use the new unified API instead. The changes are mechanical - each call site is updated to pass equivalent parameters through the new options struct. The patch touches several key areas including bisect functionality, rev-parse, pack-bitmap handling, and the core refs implementation.

The conversion maintains identical behavior while removing one of the specialized iteration variants. This continues the series' pattern of methodically migrating callers to the new API before removing the old functions. The changes are straightforward and well-contained, following the established pattern from earlier patches in the series.

This is part of Patrick's broader effort to simplify and unify Git's ref handling internals, building on his recent work on the reftable backend and other ref-related improvements. The series shows careful attention to backward compatibility and incremental migration.
