This is part 16 of Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch removes `refs_for_each_namespaced_ref()` in favor of the new unified `refs_for_each_ref_ext()` API introduced earlier in the series.

The change migrates two key callers - `http-backend.c` and `upload-pack.c` - to use the new API with equivalent functionality. The conversion is straightforward: both sites now populate a `refs_for_each_ref_options` struct with the namespace and (when needed) exclude patterns, then call the unified function. The patch maintains all existing behavior including hidden ref filtering in upload-pack.

This continues the series' pattern of systematically removing specialized ref iteration functions after demonstrating their functionality can be cleanly expressed through the new options-based API. The changes touch core ref handling in HTTP and upload-pack operations but don't introduce new behavior - this is purely an internal API consolidation.

Technical details:
- Removes `refs_for_each_namespaced_ref()` from refs.c/refs.h
- Updates http-backend.c's info/refs generation to use options struct
- Modifies upload-pack.c's ref advertisement to maintain hidden ref filtering
- Preserves namespace handling via options.namespace field
- Keeps exclude_patterns behavior for hidden ref filtering
- Follows same mechanical migration approach as previous patches

The patch appears well-contained and follows the established pattern of this series. It demonstrates the flexibility of the new API by cleanly handling both simple namespace iteration (http-backend) and the more complex hidden ref case (upload-pack). With only one patch remaining in the series, this brings the ref iteration unification effort close to completion.
