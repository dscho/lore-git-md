This is a discussion about the interface design for the `git replay` command's new `--revert` feature. Junio Hamano responds to Toon Claes's suggestion to use subcommands (`revert`, `pick`, `replay`) rather than flags (`--onto`, `--advance`, `--revert`) for the different operation modes.

Junio agrees with the subcommand approach, noting it would make the distinct modes more clearly stand out and help avoid confusion about which options are incompatible. This comes after the technical implementation of `--revert` has already stabilized through multiple review iterations (now at v3), where the flag-based approach was previously the consensus.

The exchange highlights an ongoing design question about how best to structure the command's interface as it gains more functionality. While the core capability (reverting commits on bare repos for GitLab's Gitaly service) is technically sound, the user-facing API is still being refined. Junio's response suggests the subcommand approach may gain traction, though it would require restructuring the already-implemented flag-based design.
