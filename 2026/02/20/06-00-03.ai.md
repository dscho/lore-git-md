This is a refactoring patch in Jeff King's series addressing component counting in ref-filter's lstrip/rstrip functions. The patch simplifies the slash-counting logic in `normalize_component_count()` by replacing an obscure ternary-based loop with a straightforward iteration that explicitly counts slashes.

The original implementation used a confusing pointer manipulation trick that was technically correct but hard to follow - it maintained two counters (one for position, one for slashes) in a way that confused both static analyzers and human readers. Jeff's new version makes the control flow obvious by separating the slash counting from the string traversal.

The commit message thoroughly documents the reasoning behind the change, noting that while the old code worked, its cleverness obscured its purpose. The new version also drops a misleading comment about counting "components" when the code actually counts slashes (the component count is derived by adding one later).

This patch follows from Junio Hamano's review identifying the readability issue, and represents the final refinement of a series that began with Collin Funk's report of a Coverity warning. The change maintains all existing behavior while making the code more maintainable - a classic example of Git's attention to code clarity even for internal functions.
