This is a test infrastructure change that's part of Patrick Steinhardt's series to switch git maintenance's default strategy from "gc" to "geometric". The patch addresses test reliability issues that would arise from this upcoming change.

The core change introduces a new `GIT_TEST_MAINT_AUTO_DETACH` environment variable that forces maintenance tasks to run synchronously during tests rather than in the background. This prevents races where background maintenance could interfere with test assertions about repository state. The patch shows this doesn't significantly impact test suite runtime through benchmark comparisons.

Key technical details include:
- Modifies `run-command.c` to respect the new env var for maintenance auto-detach behavior
- Updates several test scripts to use `--no-detach` explicitly where maintenance is tested
- Sets the default value in `test-lib.sh` to disable auto-detach for all tests
- Includes benchmark data showing negligible performance impact

The change is motivated by the upcoming geometric strategy default, which will run maintenance more aggressively than the current gc-based approach. This thorough test preparation is characteristic of Patrick's approach to large changes - ensuring test reliability before making behavioral changes. The patch maintains backward compatibility while preventing flaky tests.
