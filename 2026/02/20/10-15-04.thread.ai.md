Key technical implementation:
- Changes in `builtin/gc.c` with corresponding documentation updates
- Three preserved strategies: "gc" (legacy), "incremental" (scheduled default), and "geometric" (new manual default)
- Test isolation measures including explicit "gc" strategy setting in `t6500` to preserve legacy behavior testing
- Geometric strategy maintains packfile progression to reduce expensive full repacks while controlling repository size
- Documentation explains all three strategy options and their interactions with Scalar
- Test infrastructure prepared with `GIT_TEST_MAINT_AUTO_DETACH` and suite updates across multiple commands

**Critical issues now under active discussion:**
1. **Geometric repack auto-condition bug**: Stefan Haller identified that `geometric-repack.auto` triggers 256× more aggressively than documented due to a legacy scaling bug in `too_many_loose_objects()`. Patrick Steinhardt proposes raising the default value from 100 to 6700 (matching `gc.auto`) to mitigate this, with a documentation update. This change is expected to reduce background repack frequency in small repositories.
2. **Concurrency failures**: Stefan Haller's report demonstrates real-world impact with "invalid object" errors, temporary file failures, and commit failures during concurrent operations. Root cause: `prune_packed_objects()` removes fanout directories while concurrent writers attempt to create temporary files, defeating Git’s single-retry mitigation. The issue predates the geometric repacking series but is now surfacing more frequently due to the more aggressive repacking introduced in Git 2.54.0. Patrick suggests the auto-threshold adjustment may mask the issue in practice, but the underlying race condition remains unaddressed.
