This is an RFC patch proposing a feature to improve the default cover letter format in `git format-patch`. The current implementation uses `git shortlog` which organizes commits by author, while the proposed change would list commits in chronological order with their patch numbers and one-line summaries.

The patch modifies `builtin/log.c` to replace the shortlog output with a new `generate_cover_commit_list()` function that formats each commit as "[N/M] abbrev-hash: oneline-subject". The author argues this provides better context for reviewers than the author-grouped shortlog format.

The implementation appears straightforward, though there are some potential concerns: the memory allocation for commit_hash_buf and strbuf could be simplified (using stack allocation instead of malloc), and there's no test coverage included. The patch references a previous discussion about cover letter usefulness but doesn't link to specific complaints about the current format.

This seems like a reasonable quality-of-life improvement for patch series authors, though the RFC status suggests the author is open to feedback on both the approach and implementation details. The change is focused solely on the cover letter generation and doesn't affect any other functionality.
