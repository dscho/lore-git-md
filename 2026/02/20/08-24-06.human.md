This is the second patch in Patrick Steinhardt's 17-part series refactoring Git's ref iteration API. The series aims to simplify the current complex landscape of 14 different `refs_for_each_*()` functions by introducing a unified interface.

This particular patch is a straightforward code organization change that moves the `do_for_each_ref_flags` enum definition higher up in refs.h, placing it near related function declarations. The enum defines flags that affect how ref iteration behaves (like including broken refs or per-worktree refs). The change is purely mechanical - no functionality is altered, just the code layout improved to better support the upcoming refactoring.

As with the first patch, this appears to be careful preparatory work from an experienced contributor, part of a well-structured series that tackles a known pain point in the codebase. The patch is small, focused, and clearly motivated by the larger refactoring goal.
