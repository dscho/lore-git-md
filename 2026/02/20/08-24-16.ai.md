Refactoring patch in Patrick Steinhardt's series to unify Git's ref iteration interfaces. This is patch 12/17, continuing the effort to consolidate the 14 specialized ref iteration functions into a single configurable API.

The patch removes `refs_for_each_rawref()` and migrates all its callers to use the new `refs_for_each_ref_ext()` interface with appropriate options. The changes touch several key areas:
- `builtin/describe.c` and `builtin/fsck.c` for ref listing
- `fetch-pack.c` for negotiation and marking refs
- Core refs handling in `refs.c` and `refs/files-backend.c`

Each conversion maintains the same behavior by setting `REFS_FOR_EACH_INCLUDE_BROKEN` in the options struct, matching `rawref`'s original semantics of including broken refs. The patch follows the established pattern from earlier in the series - mechanically converting callers while preserving functionality, then removing the old interface declaration from `refs.h`.

This continues the incremental approach seen in previous patches: first introducing the new API (patch 6), then systematically removing old variant by variant. The changes are straightforward with no apparent behavioral differences, and the patch maintains the careful attention to detail shown throughout the series.
