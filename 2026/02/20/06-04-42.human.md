This is the second patch in Burak Kaan Karaçay's GSoC 2026 series to refactor Git's mailmap subsystem, part of the ongoing `the_repository` removal effort. The patch eliminates two global configuration variables (`git_mailmap_file` and `git_mailmap_blob`) that stored mailmap settings, replacing them with on-demand config lookups via `repo_config_get_*` functions.

The changes are mechanical but meaningful - they remove persistent global state while maintaining the same behavior. The mailmap system still reads from the same sources (file and blob configurations, with a fallback to "HEAD:.mailmap" in bare repos), but now does so without keeping the config values in memory indefinitely. The implementation is clean, with proper memory management of the temporary config values.

This follows the first patch's conversion of mailmap functions to take explicit `struct repository` parameters. Junio C Hamano has already reviewed and approved the design, and this v2 revision addresses a minor header inclusion issue from v1. The changes affect `environment.c`, `mailmap.c`, and `mailmap.h`, touching several builtin commands indirectly through their mailmap usage.

The patch represents solid progress on reducing Git's global state, with no outstanding issues noted. It's a focused, well-executed contribution that aligns with the project's technical direction.
