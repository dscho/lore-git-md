This is part 2 of Adrian Ratiu's 8-patch series introducing config-based hooks, building on the prerequisite hooks-conversion series that's queued for 'next'. The patch refactors the hook execution infrastructure to support multiple hooks per event, preparing for the config-based hooks that will be added in later patches.

The changes introduce a `struct hook` to represent individual hooks (both traditional filesystem hooks and future config-based ones), with helper functions for managing lists of hooks. Patrick Steinhardt provided detailed code review suggestions that Adrian is incorporating into v3, including:
- Using `CALLOC_ARRAY` for allocations
- Renaming `hook_clear()` to `hook_free()` to match project conventions
- Adding defensive `BUG()` checks for unexpected hook kinds
- Using `string_list_clear_func()` for cleaner cleanup

The patch maintains backward compatibility while laying groundwork for the config-based hooks to come. Junio Hamano has already approved the architectural approach, and the discussion is now focused on implementation refinements. The series is in its final polishing phase with v3 expected to address all remaining review feedback.
