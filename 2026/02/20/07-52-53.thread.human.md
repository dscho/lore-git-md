This thread introduces a new feature for `git send-email` that adds support for client certificate authentication when communicating with SMTP servers that require mutual TLS. The patch proposes two new command-line options: `--smtp-ssl-client-cert` to specify a client certificate (in either PKCS12 or PEM format) and `--smtp-ssl-client-key` for the optional private key (required when using PEM certificates). 

The implementation cleanly integrates with the existing Perl-based SMTP handling code, passing these parameters through to the underlying IO::Socket::SSL library. The patch includes clear documentation explaining the new options and links to the relevant Perl module documentation for additional context. Error handling covers edge cases like specifying a key without a certificate. This addresses a real-world use case for environments where SMTP servers require client certificate authentication, filling a gap in Git's email-sending capabilities.
