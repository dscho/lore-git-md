This is an off-topic email about `git send-email` client certificate support, not actually related to the filesystem type tracking thread it was mistakenly included in. The author, David Timber, explains they've configured their mail server to require client certificates for authentication, which current `git send-email` doesn't support.

The email notes that since `git send-email` is implemented as a single Perl script (~2000 lines), adding client cert support would be relatively straightforward - they offer to contribute a patch if there's interest. The technical change would involve passing PEM certificate paths to the OpenSSL library used by the script.

This appears to be a genuine infrastructure need for users running strict mail server configurations, though the patch would be a niche addition. The author seems technically capable of implementing it given their understanding of both the mail protocol requirements and Git's codebase structure. The offer to contribute is made casually rather than as a formal RFC, suggesting they're testing the waters for interest before investing implementation effort.
