Refactoring patch from Patrick Steinhardt introducing a unified ref iteration API. This is patch 6/17 in his series to simplify Git's ref iteration interfaces.

The patch exposes the internal `do_for_each_ref()` function as a new public `refs_for_each_ref_ext()` and introduces a `struct refs_for_each_ref_options` to control iteration behavior through a single unified interface rather than the current proliferation of specialized functions. The options structure lets callers specify:
- A prefix filter
- Exclusion patterns
- Prefix trimming length
- Flags controlling which refs to include

All existing ref iteration functions (`refs_for_each_ref()`, `refs_for_each_ref_in()`, etc.) are reimplemented in terms of this new unified function. The changes are mechanical conversions that maintain identical behavior while setting up for future simplification of the API surface.

This continues Patrick's careful, incremental approach to refactoring - the preparatory patches 1-5 renamed types and removed dead code to enable this more substantive change. The patch touches core ref iteration logic but doesn't yet remove any of the now-redundant specialized functions (that comes later in the series). The migration of `repo_migrate_ref_storage_format()` shows how the new API can handle complex cases like including broken refs.

Technical details to note for future discussion:
- New `refs_for_each_ref_ext()` function and options struct in refs.h
- All existing iteration functions now delegate to the new API
- Flags remain the same but are passed through the options struct
- The `migrate_one_ref` callback demonstrates handling of edge cases
- Later patches will remove now-redundant specialized functions

This is a well-structured change that follows Patrick's typical pattern of thorough, incremental refactoring. The patch maintains backward compatibility while laying groundwork for simplifying the API in future steps.
