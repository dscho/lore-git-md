Thread identity: Feature proposal for `git send-email` regarding handling of non-ASCII characters in email subject lines, from first-time contributor Shreyansh Paliwal, now joined by Ben Knoble.

Core problem: Current `git send-email` interface for specifying character encodings when 8-bit content is detected is confusing. The prompt "Which 8bit encoding should I declare [UTF-8]?" followed by a confirmation prompt can be misinterpreted as a yes/no question, leading users to answer "y" which then gets incorrectly used as the charset name, producing malformed email headers like "=?y?q?...?=".

Current status: Shreyansh Paliwal has submitted a patch implementing Ben Knoble's suggestion to change the prompt from "[UTF-8]" to "[default: UTF-8]" in `git-send-email.perl`. The patch is minimal and focused on clarifying the prompt while maintaining existing behavior. Discussion continues about whether additional improvements might be warranted, such as warning on invalid charset inputs or falling back to UTF-8 when invalid input is provided.

Key technical details: Issue affects the interactive prompt in `git send-email` when processing email headers containing non-ASCII characters. The malformed output occurs in the MIME encoded-word syntax (RFC 2047) when the charset parameter is invalid. The change follows Git's established pattern for indicating default values in prompts, though the thread notes this convention isn't universally applied across Git's CLI.

Open questions: Whether to accept the minimal prompt change as-is or consider more substantial interface modifications. Need to evaluate if additional validation or fallback behavior would be beneficial. The thread may examine how other mail clients handle similar encoding declarations.

Participant positions: Shreyansh Paliwal reported the issue and submitted the initial patch implementing Ben Knoble's suggestion. Ben Knoble originally proposed the prompt wording change and may provide feedback on the patch. No other participants have joined yet.

Related work: General email header encoding standards (RFC 2047) and `git send-email`'s existing encoding handling infrastructure. The patch follows Git's conventions for indicating default values in interactive prompts, though this pattern isn't consistently used throughout the codebase.
