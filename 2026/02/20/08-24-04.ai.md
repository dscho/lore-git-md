This is a refactoring series from Patrick Steinhardt that aims to simplify Git's ref iteration API. The current implementation has 14 different `refs_for_each_*()` functions with subtle variations, making the API surface confusing and hard to extend. The series introduces a unified `refs_for_each_ref_ext()` function that takes an options structure, allowing callers to specify exactly what they need through configuration rather than requiring new functions for each use case.

The series starts with preparatory cleanups (patches 1-5), then introduces the new unified function and migrates some functionality to it (patches 6-9). Patch 10 adds validation for the new options structure. The remaining patches (11-17) demonstrate the payoff by removing 7 of the existing functions in favor of the new unified approach, though Patrick notes these are somewhat optional due to the churn they create.

The changes touch a wide range of files (28 modified) as the ref iteration API is used throughout the codebase. The series builds on Patrick's recent work fixing issues with `for-each-ref` functionality, suggesting this is part of his broader effort to modernize Git's ref handling internals. Given Patrick's track record with ref-related work and the careful structure of this series, it appears to be a well-considered improvement to a core API.
