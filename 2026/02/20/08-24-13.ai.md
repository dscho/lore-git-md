This is part 9/17 of Patrick Steinhardt's ref iteration API unification series. The patch generalizes `refs_for_each_fullref_in_prefixes()` to use the new `refs_for_each_ref_options` struct introduced earlier in the series, renaming it to `refs_for_each_ref_in_prefixes()` in the process.

The key change is moving from a function that took individual parameters (namespace, patterns, exclude_patterns) to one that accepts the full options struct. This maintains consistency with the unified API approach while preserving the special handling of multiple prefixes that share a common prefix. The function still computes longest common prefixes internally but now delegates the actual iteration to `refs_for_each_ref_ext()`.

The patch updates two callers - `ls-refs.c` and `ref-filter.c` - to use the new interface. Both sites now initialize an options struct locally rather than passing parameters directly. The implementation is careful to BUG() if callers try to specify a prefix via the options struct, since that would conflict with the function's purpose of handling multiple prefixes.

This continues the series' pattern of incrementally migrating specialized ref iteration functions to use the unified API while maintaining existing behavior. The change is mechanical but important for the overall goal of reducing API surface area. Performance characteristics should remain unchanged since the core prefix-handling logic is preserved.
