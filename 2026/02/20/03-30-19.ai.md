This is a discussion thread about a test case in `t1006-cat-file.sh` that exposes a fundamental limitation in `git cat-file --batch-check`'s handling of object names containing whitespace when used with the `%(rest)` format specifier.

The maintainer Junio C Hamano clarifies that the behavior is not actually a bug but rather an inherent constraint of the interface design. The documentation explicitly states that `%(rest)` will split input at the first whitespace boundary, making it impossible to properly parse object names containing spaces in this context. This means the original FIXME comment in the test was highlighting expected (if perhaps undesirable) behavior rather than a fixable issue.

The discussion has evolved from considering test modifications to recognizing this as a documented limitation of combining these features. Junio's latest response suggests the test should remain as-is to document this edge case, rather than being modified to work around it by using OIDs instead of object names. This represents a shift from earlier suggestions about hybrid approaches, now acknowledging the behavior as an intentional (if potentially surprising) design constraint.
