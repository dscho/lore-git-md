This is a test modernization patch in the ongoing repo-info subsystem refactoring series. Patrick Steinhardt is responding to Lucas Seiki Oshiro's patch that proposes simplifying the NUL-formatted output testing in `t1901-repo-structure.sh`.

The patch aims to eliminate separate NUL-formatted expected output files by using `tr` to transform the actual output to match the key-value format, but Patrick questions whether this approach actually provides a clear improvement. He notes that both the current and proposed methods require using `tr`, and neither seems obviously superior. He does suggest combining the two-step `tr` pipeline into a single command if this approach is adopted.

This is a minor optimization in test infrastructure that doesn't affect functionality. The discussion reflects Git's culture of carefully evaluating even small changes to ensure they provide clear benefits. Patrick's response indicates he's not opposed to the change but wants to understand its advantages before accepting it.
