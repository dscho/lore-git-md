Refactoring patch in Patrick Steinhardt's series to unify Git's ref iteration interfaces. This is patch 2/17 in v1 of the series.

The patch moves the `do_for_each_ref_flags` enum definition earlier in refs.h, placing it just after the `each_ref_fn` typedef rather than keeping it near the `ref_iterator` declaration. This is a purely mechanical change with no functional impact - the same flags are defined in the same way, just in a different location. The commit message explains this prepares for later changes where these flags will be used by more functions.

The enum defines four flags that control ref iteration behavior:
- `DO_FOR_EACH_INCLUDE_BROKEN` - show normally-hidden broken refs
- `DO_FOR_EACH_PER_WORKTREE_ONLY` - limit to worktree-specific refs  
- `DO_FOR_EACH_OMIT_DANGLING_SYMREFS` - filter out dangling symrefs
- `DO_FOR_EACH_INCLUDE_ROOT_REFS` - include HEAD and pseudorefs

This continues the incremental preparation work started in patch 1/17, maintaining the series' careful approach of making small, uncontroversial changes first before introducing the more substantial refactoring of the ref iteration API in later patches. The change touches only refs.h and is straightforward code reorganization with no expected controversy.
