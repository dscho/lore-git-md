This is patch 10/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces. The series aims to consolidate the 14 different `refs_for_each_*()` variants into a single configurable API.

This particular piece strengthens validation in the new unified `refs_for_each_ref_ext()` function. It now requires a non-NULL ref store (previously silently succeeding with NULL was surprising behavior) and adds BUG() checks for invalid trim_prefix cases where the refname could become empty. The commit notes these changes are safe since no existing callers rely on the old behavior.

The patch follows the series' pattern of carefully evolving the API while maintaining backward compatibility. It touches core ref iteration logic but doesn't change any actual behavior for correct callers - it just makes incorrect usage more obvious. The changes align with the series' goal of making the ref iteration API more robust and predictable.
