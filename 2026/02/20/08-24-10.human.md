This is the sixth patch in Patrick Steinhardt's 17-part series refactoring Git's ref iteration API. The patch introduces a new unified `refs_for_each_ref_ext()` function with an options structure to replace the existing proliferation of specialized ref iteration functions.

The key change exposes the internal `do_for_each_ref()` as a public API with a `struct refs_for_each_ref_options` parameter that consolidates all iteration controls (prefix filtering, exclusion patterns, trimming behavior, and flags) into a single structure. This replaces the previous approach where each combination of options required its own function.

The patch demonstrates Patrick's careful, incremental approach - it first introduces the new API while keeping all existing functions as thin wrappers around it. This maintains backward compatibility while setting up for future patches that will remove redundant functions. The options structure is well-documented in the header file with clear explanations of each field.

This is a significant step in the series' goal to simplify Git's ref iteration surface area. The change touches core ref handling code but appears mechanically sound, with all existing callers updated to use the new API correctly. As part of Patrick's broader ref backend modernization efforts, this lays groundwork for more flexible ref iteration while reducing maintenance overhead.
