This thread discusses Patrick Steinhardt's series to change git maintenance's default strategy from "gc" to "geometric". The initial series included test updates to handle the new behavior, with the core change being a one-line modification in builtin/gc.c. The motivation is to complete the transition to more flexible maintenance infrastructure while using a more efficient repacking strategy by default, particularly beneficial for large repositories.

A new patch in the series addresses test reliability concerns that would arise from the upcoming change. It introduces a `GIT_TEST_MAINT_AUTO_DETACH` environment variable to force maintenance tasks to run synchronously during tests rather than in the background, preventing races where background maintenance could interfere with test assertions. Benchmark data shows this change has negligible performance impact on the test suite. The patch updates several test scripts to explicitly use `--no-detach` where maintenance is tested and sets the default in test-lib.sh to disable auto-detach for all tests.

Patrick's approach shows his characteristic thoroughness - preparing the test infrastructure before making behavioral change. The series maintains backward compatibility while preventing flaky tests. Open questions remain about whether to initially gate the change behind feature.experimental and evaluating potential disruption from changing the default behavior.
