This is an RFC patch targeting the `git format-patch` command's cover letter generation. The author proposes changing the default commit list format in cover letters from the current author-grouped shortlog to a numbered chronological list showing each commit as "[N/M] abcd123: summary".

The patch modifies `builtin/log.c` to:
- Remove dependency on the shortlog infrastructure
- Add a new `generate_cover_commit_list()` function that produces sequential numbered output
- Maintain existing line wrapping while changing presentation order
- Use `pp_commit_easy()` for one-line summaries with proper hash formatting

The motivation is that developers often find the current author-grouped shortlog less useful for understanding patch series flow. The new format makes commit order and content more immediately apparent. The implementation appears straightforward, with proper memory handling (alloc/free balanced).

Open questions remain about whether this format should be configurable (currently hardcoded) and whether additional test coverage is needed. The patch follows prior discussion about cover letter usefulness and is marked RFC to gather design feedback before finalizing.

Key technical details:
- Changes only affect cover letter generation, not patch email subjects
- Preserves all information while reordering presentation
- Memory handling appears correct (alloc/free balanced)
- Would need accompanying documentation updates if accepted

The patch is a focused improvement to a specific pain point in the patch submission process. The change is well-contained and the implementation looks clean, though as an RFC it's explicitly seeking feedback on the design approach before finalizing.
