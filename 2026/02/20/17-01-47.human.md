This is a technical discussion about refactoring revert message formatting in the `git replay` command series. The patch in question extracts shared logic for formatting revert commit messages into a new `sequencer_format_revert_header()` function, which handles both regular reverts and reverts-of-reverts.

Toon Claes raises a concern about the split handling of `commit_use_reference` between the new helper function and the calling code, noting it creates some confusion. He references an earlier suggestion from Patrick Steinhardt that may have proposed a more unified approach. The discussion appears to be about implementation details rather than fundamental design, as the core functionality has already been agreed upon in previous rounds of review.

This is part of a larger effort to add `--revert` capability to `git replay` for server-side use cases, particularly for GitLab's Gitaly service. The current exchange focuses on code organization and maintainability as the feature nears completion.
