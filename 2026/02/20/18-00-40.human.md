This is the final version of a bugfix series addressing symlinked `.git` directory handling, with security implications. The patch refines Git's behavior to allow symlinks pointing to directories while maintaining protections against dangerous cases like FIFOs and invalid gitfiles.

Junio Hamano confirms the core functionality already works as expected (symlinks to directories are handled properly via `stat()`), but notes the patch's real value is in improving error diagnostics through new error codes. The changes distinguish between different failure modes (ENOENT, directory vs non-regular file) rather than treating them uniformly as before.

The implementation introduces three new error codes and modifies `setup_git_directory_gently_1()` to handle them appropriately. While the patch could theoretically be more aggressive about reporting invalid directories (treating them like FIFOs), the current conservative approach avoids potential regressions. All prior review feedback has been incorporated across eight iterations, with no functional changes from v7 - only minor commit message refinements remain.

This represents a careful balance between security and usability, maintaining Git's protections against malicious repository setups while allowing legitimate symlink use cases. The changes have been thoroughly vetted by Junio Hamano and Karthik Nayak, with consensus that the patch is ready for merging.
