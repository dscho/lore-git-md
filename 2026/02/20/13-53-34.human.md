This is part 3 of Adrian Ratiu's config-based hooks series, implementing the `git hook list` subcommand to display configured hooks. The patch adds a simple command that lists hooks for a given event name, currently only supporting traditional filesystem hooks (with config-based hooks coming in later patches).

Patrick Steinhardt provided review feedback on stylistic points - error and warning messages should start with lowercase letters, which Adrian acknowledges and will fix. The patch already includes defensive programming with a `BUG()` check for unknown hook kinds, which Patrick approves and Adrian confirms he'll extend to other patches in the series.

The exchange shows the series progressing through constructive review, with Adrian responsive to feedback on both implementation details and user-facing messaging. This patch is one piece of the larger configurable hooks effort that has maintainer approval and is nearing readiness for inclusion.
