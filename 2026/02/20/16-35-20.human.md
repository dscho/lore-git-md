This is a follow-up to a feature patch adding client certificate support to `git send-email`. Maintainer Junio C Hamano provides detailed documentation feedback on the proposed changes, focusing on clarity and completeness of the new options' descriptions.

Junio suggests several wording improvements to better explain when and why users would need these options. He questions whether the documentation should explicitly state that servers may require client verification (rather than just optionally supporting it). There are also minor copyedits requested - fixing typos ("More more" -> "For more"), adding missing spaces, and wrapping long lines.

The maintainer raises an interesting technical question about the interaction between PKCS12 certificates (which can contain both cert and key) and separately specified key files. He wonders about the use case for providing a separate key when the certificate already includes one, suggesting the documentation could be clearer about this edge case.

These are all documentation refinements rather than objections to the feature itself. The implementation appears sound, but the maintainer wants the accompanying explanations to be as precise as possible before merging. The author will need to address these points in a v2 submission.
