This is a v2 revision of a GSoC contribution targeting the `the_repository` removal effort, specifically focusing on the mailmap subsystem. The series refactors mailmap handling to eliminate global state dependencies, with two main changes: converting functions to take explicit `struct repository` parameters and removing global config variables in favor of on-demand config reading.

The first patch updates `read_mailmap()` and `read_mailmap_blob()` to require a repository parameter, propagating this change through all callers (including blame, log, shortlog, and ref-filter commands). The second patch removes the `git_mailmap_file` and `git_mailmap_blob` globals, replacing them with config lookups while maintaining the existing fallback behavior for bare repositories. The v2 revision addresses a header inclusion issue caught by `make hdr-check` that required forward-declaring `struct repository` in mailmap.h.

Junio C Hamano has already reviewed and approved the core design, noting the implementation is clean and properly scoped. The mailmap data structure itself (a simple string_list) remains unchanged - this is purely about removing implicit dependencies on global state. The changes touch several builtin commands but are mechanical in nature, passing `the_repository` where it was previously implicit. This represents meaningful progress on technical debt through focused subsystem work, with only minor header issues to clean up before integration.
