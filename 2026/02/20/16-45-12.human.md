This is a bugfix patch addressing symlinked `.git` directory handling, with security implications. The patch comes from Tian Yuchen as the eighth iteration of this work, now squashed into a single commit after incorporating feedback from Junio Hamano and Karthik Nayak.

The core issue fixes Git's overly restrictive handling of symlinked `.git` directories. Previously, Git would reject all symlinked `.git` directories, even when they pointed to valid directories. The patch refines this behavior while maintaining security by still rejecting dangerous cases like FIFOs and invalid gitfiles.

Key changes include:
- New error codes to distinguish between directory symlinks and other cases
- Modified `setup_git_directory_gently_1()` to properly handle symlinked directories while maintaining security checks
- Optimized filesystem access patterns by only calling `is_git_directory()` when needed
- Comprehensive new test coverage in `t0009-git-dir-validation.sh` that verifies both valid and invalid cases

The patch represents a balance between security and usability, maintaining protections against malicious repository setups while allowing legitimate symlink use cases. All prior review concerns have been addressed, including Junio's final feedback about code organization and error handling clarity. The changes are now ready for final security review and merge.
