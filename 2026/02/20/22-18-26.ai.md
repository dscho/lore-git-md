This is a follow-up in the ongoing thread about implementing Linux filesystem monitoring (fsmonitor) support using inotify. Junio Hamano, the Git maintainer, is checking on the status of the patch series after noticing discussion had gone quiet.

The core technical work appears complete - the inotify-based fsmonitor implementation has gone through four iterations addressing various issues like memory leaks, portability concerns, and build system integration. The only remaining known issues are two small memory leaks (512-byte during daemon startup and 40-byte in IPC handling) that were identified in previous reviews.

Patrick Steinhardt had contributed an additional patch adding meson build system support, noting it could land separately if needed. Junio is now asking whether the series is otherwise ready to proceed, implying the remaining leaks may not be severe enough to block merging if they can be addressed in follow-up patches.

The thread context shows this has been a carefully developed feature with extensive review and testing, now at the stage where the maintainer is considering whether to accept it pending resolution of the last minor issues. The meson build support appears to be the only outstanding question about what should be included in the final series.
