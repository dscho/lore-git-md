The change is mechanical but widespread, touching 11 files across the codebase including ref backends, ref-filter, revision handling, and worktree code. The new name makes it clearer that this is specifically for ref iteration callbacks rather than a generic "each" function.

The patch continues the series' preparatory work before introducing more substantive changes to the ref iteration API. Like the previous patches, this appears to be a straightforward improvement with no functional changes - just renaming for consistency. The changes are all local to function signatures and typedefs, with no logic modifications.
