This is a feature patch introducing a new configuration option for branch naming. Yoann Valeri proposes adding `branch.addCurrentBranchAsPrefix`, which when enabled automatically prefixes new branch names with the current branch name plus a hyphen. For example, creating branch "test" while on "main" would create "main-test" instead.

The patch modifies `git branch`, `git checkout -b/B`, and `git switch -c/C` to respect this setting. It includes tests verifying the behavior and documentation updates. The motivation is to help projects managing many branches (particularly those needing frequent backports) by reducing naming overhead.

Implementation-wise, it adds a new helper function `add_branch_prefix()` that checks the config and constructs the appropriate name. The change touches core branch creation paths but appears well-contained, with tests covering the main scenarios. The patch follows Git's standard patterns for configuration options and branch handling code.

This seems like a straightforward quality-of-life improvement for workflows involving many related branches. The implementation looks clean and the tests provide good coverage of the happy path and edge cases. The documentation clearly explains the new behavior.
