This is patch 14/17 in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch removes `refs_for_each_glob_ref_in()` by migrating all its callers to use the new unified `refs_for_each_ref_ext()` API introduced earlier in the series.

The changes follow the established pattern seen in previous patches: each caller is updated to initialize a `refs_for_each_ref_options` struct with the same parameters previously passed directly to `refs_for_each_glob_ref_in()`, then calls the new API. The patch touches several key areas:

- `builtin/bisect.c` gets the most changes, with three separate call sites updated to use the new API while maintaining the same behavior for bisect operations.
- `builtin/rev-parse.c` and `revision.c` see simpler conversions for their ref iteration needs.
- The now-unused `refs_for_each_glob_ref_in()` function is removed from both `refs.c` and `refs.h`.

This continues the series' systematic approach - each patch removes one specialized ref iteration function after migrating all its callers. The changes are mechanical but thorough, with each conversion preserving the exact same behavior through equivalent configuration of the new unified API. The patch maintains all existing functionality while reducing API surface area, in line with the series' goal of simplifying Git's ref iteration interfaces.
