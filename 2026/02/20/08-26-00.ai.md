This is the second patch in a five-part test infrastructure series addressing CI failures on Windows/MSVC platforms related to `iconv(1)` executable availability. The patch focuses on three submodule test files (t4041, t4059, t4060) that were incorrectly attempting to use the `iconv(1)` executable even when the ICONV prerequisite wasn't met.

The key change is wrapping the `iconv` calls in a `test_have_prereq ICONV` check, falling back to using the UTF-8 message directly when ICONV isn't available. This fixes test failures on systems where Git is built with ICONV support (using libiconv) but the `iconv(1)` executable isn't present, particularly affecting Windows/MSVC environments where MinGW no longer ships the executable.

The patch maintains the same test coverage while making the tests more portable. It follows the pattern established in the series of distinguishing between libiconv (a runtime dependency) and the `iconv(1)` executable (a test tool). The changes are mechanical but important for test reliability, with identical modifications applied to all three submodule test files to keep behavior consistent.

This version (v4) incorporates all feedback from previous iterations and has been reviewed by Christian Couder and Junio Hamano, with the series now considered ready for merging. The patch demonstrates careful attention to platform-specific edge cases while maintaining test correctness across all environments.
