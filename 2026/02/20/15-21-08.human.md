This is a refactoring patch in the final stages of the reference storage backend selection series, which enables zero-downtime migrations between files and reftable backends. The patch moves stub creation/deletion logic from backend-specific code to the generic refs layer, preparing for upcoming work on reference backend locations.

The change itself is straightforward - relocating stub management code to be more generally accessible while maintaining special handling for the files backend. This appears to be a mechanical refactoring with no substantive behavior changes.

The patch is part of a well-reviewed series (now at v7) that has maintainer approval from Junio Hamano and addresses feedback from multiple contributors. The overall effort provides the configuration flexibility needed for GitLab's large repository migration use case. This particular change seems uncontroversial and ready for integration.
