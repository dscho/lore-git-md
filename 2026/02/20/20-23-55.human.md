This is a design discussion about the interface for `git replay`'s operation modes, specifically whether to use subcommands instead of flags for the distinct `--onto`, `--advance`, and `--revert` actions.

Junio C Hamano responds to Toon Claes's suggestion that the command might be structured with subcommands (`revert`, `pick`, `replay`) rather than flags, noting that this could help clarify the mutually exclusive nature of these operations. Junio acknowledges that the current flag-based approach has caused some confusion among those not closely following the development, and agrees that subcommands could make the distinctions clearer.

The exchange comes after multiple rounds of technical implementation and review for the `--revert` functionality, which is now in its third iteration. While the technical design has largely stabilized, this raises a new architectural question about command structure that wasn't previously discussed in depth. Junio's response suggests openness to reconsidering the interface, though any such change would need to be weighed against the existing implementation work.
