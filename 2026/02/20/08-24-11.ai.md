This is part 7/17 of Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch focuses on optimizing `refs_for_each_glob_ref_in()` by leveraging the new unified API introduced in patch 6/17.

The key change moves the glob pattern matching logic into the core `refs_for_each_ref_ext()` function, allowing it to properly respect the prefix filtering that was previously ignored. This provides significant performance improvements when iterating over a small subset of refs in a repository with many refs outside the target prefix - the benchmark shows a 107x speedup in an extreme case with 1 million irrelevant refs.

The implementation adds a new `pattern` field to `struct refs_for_each_ref_options` and handles the glob pattern expansion internally. The existing glob functions become thin wrappers that set up the options struct and call the unified API. The change maintains all existing behavior while being more efficient.

This patch demonstrates the value of the unified API approach - by centralizing the iteration logic, optimizations like this can be implemented once and benefit all callers. The performance impact is particularly notable for commands like `git rev-parse --branches` that use glob patterns with prefixes.
