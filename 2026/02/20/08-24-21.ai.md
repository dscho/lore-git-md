This is the final patch in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The series has systematically replaced 14 specialized `refs_for_each_*()` functions with a single configurable `refs_for_each_ref_ext()` interface.

Patch 17/17 removes the last remaining specialized interface - `refs_for_each_fullref_in()` - and migrates all its callers to use the new unified API. The changes touch several key areas:
- Bisect functionality in bisect.c and revision.c
- Reference advertisement in receive-pack.c
- Reference listing in rev-parse.c and show-ref.c
- Test infrastructure in t/helper/test-ref-store.c

The patch follows the same pattern as previous interface removals in the series: each caller is updated to use `refs_for_each_ref_ext()` with appropriate options struct initialization, then the old function is deleted from refs.c and its declaration removed from refs.h. The changes are mechanical but thorough, covering all call sites across the codebase.

With this patch, the ref iteration API unification is complete except for `refs_for_each_replace_ref()`, which remains as a specialized case (likely due to its unique namespace handling). The series achieves its goal of replacing a fragmented set of functions with a single configurable interface while maintaining identical behavior throughout.
