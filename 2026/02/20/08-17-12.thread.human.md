This thread documents the addition of client certificate support to `git send-email`, now approved for merging. The feature enables certificate-based SMTP authentication in security-sensitive environments while maintaining compatibility with existing authentication methods. The implementation supports both PEM and PKCS12 certificate formats to match real-world email clients like Thunderbird and K-9 Mail.

The final version includes three new configuration options following Git's established SMTP patterns: `sendemail.smtpSSLClientCert` for certificate files, `sendemail.smtpSSLClientKey` for separate PEM keys when needed, and corresponding command-line flags. The design builds on Perl's IO::Socket::SSL library without new dependencies, automatically handling certificate presentation per RFC 8446 standards. Documentation covers security considerations, format-specific behaviors, and compatibility requirements.

Maintainer Junio C Hamano has reviewed and approved the technical approach after the author addressed questions about SSL library behavior. With all concerns resolved and documentation meeting project standards, the patch is now cleared for inclusion in the `next` integration branch, representing a complete solution for certificate authentication in Git's email workflow.
