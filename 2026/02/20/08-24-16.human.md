This is patch 12/17 in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch removes `refs_for_each_rawref()` by migrating all its callers to use the new unified `refs_for_each_ref_ext()` API introduced earlier in the series.

The changes are mechanical conversions that maintain the same behavior by setting `REFS_FOR_EACH_INCLUDE_BROKEN` in the options struct. The patch touches several key areas that iterate over refs: `git describe`, `git fsck`, fetch-pack negotiation, and the files ref backend's transaction handling. Each conversion follows the same pattern - replacing the direct call with the new API while explicitly preserving the "include broken refs" behavior through the options struct.

This continues the series' incremental approach - having introduced the new API in earlier patches, we now see the payoff as another specialized iteration function can be removed. The changes are straightforward and well-contained, with each conversion clearly maintaining the existing functionality. The patch demonstrates how the unified API can cleanly replace specialized variants while keeping the same behavior.
