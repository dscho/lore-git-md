This is the third patch in a five-part series addressing test failures on Windows/MSVC platforms when Git is built with ICONV support but the `iconv(1)` executable is unavailable. The series has already been reviewed and approved, with this version incorporating final polish from Eric Sunshine.

The patch focuses on `t4205-log-pretty-formats.sh`, which tests for pretty-format output with different alignments and encodings. The tests previously unconditionally used ISO-8859-1 encoding and marked many tests with the ICONV prerequisite, even when they didn't actually need iconv functionality. The changes:

1. Make the test encoding conditional on ICONV availability - using ISO-8859-1 when available, falling back to UTF-8 otherwise
2. Remove the ICONV prerequisite from tests that don't actually need encoding conversion
3. Keep ICONV only for tests that specifically exercise `i18n.logOutputEncoding` behavior

The patch demonstrates careful analysis of which tests truly need the ICONV capability versus those that happened to be marked with it due to the test setup. The changes maintain test coverage while improving portability, particularly for Windows/MSVC environments where the `iconv(1)` executable may not be available even when Git has libiconv support.

This is part of Patrick Steinhardt's ongoing work to improve test infrastructure, particularly for Windows/MSVC compatibility. The series is now ready for merging after three rounds of refinement addressing all reviewer feedback.
