This is part 3 of Adrian Ratiu's config-based hooks series, implementing the `git hook list` subcommand. The patch adds a command to list hooks for a given event, with output currently limited to traditional (filesystem) hooks. The implementation includes proper error handling and defensive programming with a `BUG()` for unknown hook types.

Patrick Steinhardt's review notes two style issues (error and warning messages should start with lowercase) which Adrian acknowledges will be fixed in v3. The discussion also confirms the defensive `BUG()` check for unknown hook kinds is correct and will be added to other patches in the series.

The exchange shows the series progressing through final polish stages, with maintainer-approved architecture and now focused on implementation details like error message style and defensive programming. The `git hook list` command is a key piece of the configurable hooks infrastructure, providing discoverability as hooks move from filesystem to config-based storage.
