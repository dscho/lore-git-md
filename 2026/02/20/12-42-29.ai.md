This is a follow-up to Adrian Ratiu's config-based hooks series, specifically addressing feedback on patch 1/8 which introduces internal state allocation callbacks for hook execution. The patch moves hook callback data management from stack allocation to dynamic allocation via new `feed_pipe_cb_data_alloc`/`free` functions in `run_hooks_opt`. Junio Hamano has approved the architectural approach while noting some documentation updates needed in the API comments.

He notes he will update header files and API documentation in v3 to reflect this change, ensuring the interface documentation matches the new behavior where callers no longer need to handle the `feed_ctx.buf` strbuf directly.

The exchange shows the series is in its final polishing phase, with maintainer approval for the core approach and the author addressing remaining documentation details.
