Refactoring patch from Patrick Steinhardt as part of his series to unify Git's ref iteration interfaces. This is patch 14/17 in v1 of the series, continuing the systematic replacement of specialized ref iteration functions with the new unified `refs_for_each_ref_ext()` API.

The patch removes `refs_for_each_glob_ref_in()` by converting all its callers to use the new API instead. The changes are mechanical but thorough, updating call sites in `bisect.c`, `rev-parse.c`, and `revision.c` to use the options struct pattern established earlier in the series. The function is then deleted from both `refs.c` and `refs.h`.

Key aspects:
- Maintains identical behavior while switching to the more flexible API
- Follows the same pattern seen in previous patches (11-13) for removing specialized functions
- Touches core commands like `git bisect` and `git rev-parse` that use glob-based ref iteration
- Part of the broader effort to reduce API surface area and consolidate around a single configurable ref iteration interface

The patch appears well-structured and consistent with the series' incremental approach. It builds on the foundation established in earlier patches while moving closer to the goal of a unified ref iteration API.
