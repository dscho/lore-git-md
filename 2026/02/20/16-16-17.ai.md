This is a patch series in the ongoing `the_repository` removal effort, specifically targeting the mailmap subsystem. The series has now been approved by Junio C Hamano for inclusion after a quick revision to address minor issues.

The two patches eliminate global state from Git's mailmap handling. The initial version converted `read_mailmap()` and `read_mailmap_blob()` to take explicit `struct repository` parameters instead of implicitly using `the_repository`. The second patch removes the global configuration variables `git_mailmap_file` and `git_mailmap_blob`, replacing them with on-demand config reading while maintaining the existing fallback logic for bare repositories (defaulting to "HEAD:.mailmap").

The v2 revision fixed two small issues: properly declaring `struct repository` in `mailmap.h` by including `repository.h`, and correcting some whitespace problems. Junio has reviewed the changes and found them cleanly implemented, noting that the mailmap data continues to be stored in a simple string_list without introducing any long-lived structures. The changes affect several builtin commands (blame, log, shortlog, ref-filter) but maintain backward compatibility.

This work represents meaningful progress on reducing technical debt in Git's codebase through focused subsystem refactoring. With Junio's approval and no outstanding issues, the series appears ready for integration into the main branch. The changes align with the broader project goal of eliminating implicit global state while preserving existing behavior.
