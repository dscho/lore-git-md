This is patch 13/17 in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch continues the systematic replacement of specialized ref iteration functions with the new unified `refs_for_each_ref_ext()` API.

The change removes `refs_for_each_rawref_in()` and migrates its sole caller in `builtin/remote.c` to use the new API. The migration maintains identical behavior by setting the `REFS_FOR_EACH_INCLUDE_BROKEN` flag in the options struct, which ensures broken refs are still included in the iteration (the key feature of the "rawref" variants).

The patch follows the established pattern of this series: first introducing the new API (in earlier patches), then methodically removing old interfaces after migrating all callers. This particular removal is straightforward since there was only one caller to update. The diff shows the function being deleted from both `refs.c` and `refs.h` after the migration.

This continues the series' goal of reducing API surface area while maintaining all existing functionality through the more flexible options-based interface. The change is mechanical and low-risk, following the same proven approach as previous patches in the series.
