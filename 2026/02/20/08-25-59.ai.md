This is the first patch in a five-part series addressing test infrastructure issues related to iconv support on Windows/MSVC platforms. The patch modifies the ICONV prerequisite check in the test suite to require both Git being built with iconv support *and* the presence of the `iconv(1)` executable, rather than just the former.

The change addresses a real-world problem where Git for Windows recently stopped shipping the `iconv(1)` binary, causing test failures in CI environments. While this is considered a bug that will be fixed in Git for Windows, the patch makes the test suite more robust by properly distinguishing between libiconv (linked into Git) and the `iconv(1)` executable (used in test scripts).

The patch introduces a `test_lazy_prereq` for ICONV that checks both conditions, with a NEEDSWORK comment noting that these could potentially be split into separate prerequisites in the future. This change enables subsequent patches in the series to properly skip encoding-related tests when either condition isn't met, particularly important for Windows/MSVC environments where MinGW no longer ships `iconv(1)`.

The patch is well-motivated and clearly explained, with a concrete problem (GitHub issue #6083) and solution. It's part of a larger effort to improve test reliability across platforms, particularly for Windows/MSVC CI environments. The series has already gone through multiple iterations (v4) and received approvals from both Christian Couder and Junio Hamano.
