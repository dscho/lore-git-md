This is a refactoring patch as part of the ongoing `the_repository` removal effort. Burak Kaan Karaçay's patch updates Git's mailmap subsystem to stop relying on the global `the_repository` variable by converting `read_mailmap()` and `read_mailmap_blob()` to take explicit `struct repository` parameters. This is the first of two patches in the series, focusing on the mechanical conversion of function signatures and call sites.

The changes touch several builtin commands that use mailmap functionality (`blame`, `log`, `shortlog`, etc.), updating them to pass `the_repository` where it was previously implicit. The core mailmap operations remain unchanged - they still store data in a simple string_list without introducing long-lived structures. The patch maintains backward compatibility while removing implicit global state dependencies.

This v2 revision specifically addresses a header inclusion issue caught by `make hdr-check`, properly declaring `struct repository` in `mailmap.h` via inclusion of `repository.h`. The changes are straightforward and well-scoped, with Junio C Hamano having already reviewed and approved the core design in previous discussion. The patch represents meaningful progress on technical debt through focused subsystem work, aligning with the broader `the_repository` removal effort.
