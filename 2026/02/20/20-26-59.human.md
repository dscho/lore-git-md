Junio Hamano has accepted Joaquim Rocha's patch to normalize paths in `git apply --directory` arguments. This bugfix addresses cases where paths with `./` prefixes or `././` sequences would cause the command to fail with invalid path errors. The solution uses Git's existing `strbuf_normalize_path()` function to handle these cases consistently.

The patch had gone through one revision, with Patrick Steinhardt suggesting the more comprehensive normalization approach over Rocha's initial minimal fix that only stripped `./` prefixes. Junio's acceptance indicates he found the user experience justification convincing enough to warrant the generalized solution, despite his usual preference for minimal fixes.

This change makes `git apply --directory` more forgiving of common path notations while maintaining security by still rejecting invalid `../` traversal attempts. The implementation builds on existing path normalization infrastructure with negligible performance impact.
