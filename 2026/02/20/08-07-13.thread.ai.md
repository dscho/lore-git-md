Thread summary:

This thread introduces a proposed feature for automatic branch naming via either a command-line flag or configuration option. The feature would prefix new branch names with the current branch name (e.g., creating "test" while on "main" produces "main-test"), with recursive prefixing (creating "main-test-sub" when on "main-test"). The initial proposal suggested a `branch.addCurrentBranchAsPrefix` configuration option, implemented via `add_branch_prefix()` helper in branch.c with test coverage in t2018-checkout-branch.sh, t2060-switch.sh, and t3200-branch.sh.

Junio C Hamano (maintainer) has weighed in with project policy concerns: new configuration options should typically be preceded by command-line flags that demonstrate real-world utility. He notes that even if implemented as config, a corresponding `--no-current-branch-prefix` command-line override would be needed. While not rejecting the feature outright, he sets a clear bar for acceptance - the concept should first be implemented and validated as a command-line option before consideration as a configuration setting. This follows Git's conservative approach to configuration proliferation. The technical implementation appears sound (with tests covering the recursive prefixing behavior), but the conceptual approach needs more vetting at the command-line level before progressing to configuration. The original motivation cited benefits for projects needing backports across many branches.

Junio also notes a procedural issue: the email address used in the author identity and sign-off line for the patch (Yoann Valeri) is bouncing ("550 mailbox unavailable"). He requests the author to update with a reachable address and suggests GitGitGadget maintainers consider implementing verification for first-time contributor email addresses. This is separate from the technical discussion about the branch prefix feature itself. The core technical discussion about implementing this as a command-line flag first remains open.
