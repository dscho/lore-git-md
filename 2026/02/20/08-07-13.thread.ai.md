Thread summary:

This thread introduces a proposed feature for automatic branch naming via either a command-line flag or configuration option. The feature would prefix new branch names with the current branch name (e.g., creating "test" while on "main" produces "main-test"), with recursive prefixing (creating "main-test-sub" when on "main-test"). The initial proposal suggested a `branch.addCurrentBranchAsPrefix` configuration option, implemented via `add_branch_prefix()` helper in branch.c with test coverage in t2018-checkout-branch.sh, t2060-switch.sh, and t3200-branch.sh.

Junio C Hamano (maintainer) has weighed in with project policy concern: new configuration options should typically be preceded by command-line flags that demonstrate real-world utility. He notes that even if implemented as config, a corresponding `--no-current-branch-prefix` command-line override would be needed. While not rejecting the feature outright, he sets a clear bar for acceptance - the concept should first be implemented and validated as a command-line option before consideration as a configuration setting. This follows Git's conservative approach to configuration proliferation. The technical implementation appears sound (with tests covering the recursive prefixing behavior), but the conceptual approach needs more vetting at the command-line level before progressing to configuration. The original motivation cited benefits for projects needing backports across many branches.
