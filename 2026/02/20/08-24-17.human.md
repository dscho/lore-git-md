This is patch 13/17 in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch continues the systematic replacement of specialized ref iteration functions with the new unified `refs_for_each_ref_ext()` API introduced earlier in the series.

The change removes `refs_for_each_rawref_in()` and migrates its single caller in `builtin/remote.c` to use the new API. The migration maintains identical behavior by setting the `REFS_FOR_EACH_INCLUDE_BROKEN` flag in the options struct, which ensures broken refs are still included in the iteration (the key feature of the "rawref" variant).

The patch follows the established pattern of this series: identify a specialized iteration function, replace all callers with the new unified API, then remove the now-unused function. The changes are mechanical but thorough - the diff shows the function being removed from both the implementation (`refs.c`) and header (`refs.h`), with the remote.c caller updated to use the new approach.

This is part of Patrick's broader effort to reduce API complexity in Git's ref handling code. The series has been carefully structured to maintain backward compatibility while incrementally removing redundant functions. Each patch so far has focused on one specific function replacement, making the changes easier to review and reducing risk of behavioral changes.
