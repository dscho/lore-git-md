Test infrastructure patch finalizing a series to handle iconv-related test failures on Windows/MSVC. This is the fifth and last patch in Patrick Steinhardt's v4 series addressing test failures that occur when Git is built with ICONV support (using libiconv) but the `iconv(1)` executable is unavailable - a common scenario on Windows where MinGW no longer ships the executable.

The patch modifies t6006-rev-list-format.sh to make two tests conditional on the ICONV prerequisite. When ICONV is unavailable, it falls back to using UTF-8 encoding rather than failing. The changes follow the same pattern established in earlier patches of the series: encapsulating the iconv usage in conditional blocks and providing UTF-8 as a fallback. The commit message is clear and concise, noting the problem (tests failing when iconv(1) is missing despite ICONV prereq) and the solution (UTF-8 fallback).

This completes the series which has already received approval from Christian Couder and Junio Hamano, with v4 incorporating final polish from Eric Sunshine. The approach is now consistent across all affected test files (t6006, t4205, t4041, t4059, t4060, and t5550), handling the distinction between libiconv (linked into Git) and the iconv(1) executable (used in tests) while maintaining test coverage. The series demonstrates careful attention to Windows/MSVC test portability while preserving the original test intent.
