This is a feature patch introducing a new configuration option for branch creation. The patch adds a `branch.addCurrentBranchAsPrefix` setting that, when enabled, automatically prefixes new branch names with the current branch name followed by a hyphen. For example, creating a branch "test" while on "main" would create "main-test" instead.

The change affects three commands: `git branch`, `git checkout -b/-B`, and `git switch -c/-C`. The implementation adds a new helper function `add_branch_prefix()` in branch.c that checks the config and constructs the prefixed name when needed. The patch includes thorough test coverage across all affected commands.

The motivation stated is to help projects with many branches (particularly those needing frequent backports) by reducing naming overhead. The implementation looks clean with proper documentation and tests. However, it's worth noting this could potentially cause confusion if users aren't aware the prefixing is happening, though the behavior is opt-in via config.

Key technical details for future reference:
- New config: `branch.addCurrentBranchAsPrefix` (boolean, false by default)
- Affected commands: branch, checkout, switch
- New function: `add_branch_prefix()` in branch.[ch]
- Test files updated: t/t2018-checkout-branch.sh, t/t2060-switch.sh, t/t3200-branch.sh
- Behavior is recursive (prefixes can stack if creating branches while on prefixed branches)
