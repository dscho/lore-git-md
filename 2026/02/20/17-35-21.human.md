This is a design discussion about the `git replay` command's interface, specifically regarding the `--revert` mode that was recently added in v3 of Siddharth Asthana's patch series. Toon Claes suggests that instead of using mutually exclusive flags (`--onto`, `--advance`, `--revert`), the command might be better structured as subcommands since these operations are quite distinct.

The thread context shows this is part of an ongoing effort to extend `git replay` for server-side use cases (particularly GitLab's Gitaly service) where reverting commits on bare repositories is needed. The implementation has gone through several iterations with input from key contributors like Patrick Steinhardt, Phillip Wood, and Junio Hamano, and appears technically sound.

Toon's suggestion introduces a new architectural consideration about command structure rather than challenging the core functionality. The proposal would represent a significant interface change from the current flag-based approach that's already been implemented and reviewed. This kind of high-level design feedback is valuable at this stage before the feature becomes widely used.
