This is patch 15/17 in Patrick Steinhardt's refactoring series to unify Git's ref iteration interfaces. The patch continues the systematic replacement of specialized ref iteration functions with the new unified `refs_for_each_ref_ext()` API.

The patch removes `refs_for_each_glob_ref()` and updates its callers in builtin/fetch.c, notes.c, and revision.c to use the new API with a pattern specified in the options struct. The changes follow the same pattern seen in previous patches in the series - converting callers to use the new interface while maintaining identical behavior through the options struct.

Key technical details:
- The glob pattern` field in `struct refs_for_each_ref_options` (introduced in patch 7) is used to preserve the glob matching functionality
- Call sites are updated to initialize the options struct with the pattern before calling `refs_for_each_ref_ext()`
- The function is removed from both refs.c and refs.h after all callers are migrated
- Behavior remains unchanged - glob patterns still match refs the same way as before

This continues the series' consistent approach of:
1. Introducing the new unified API (patch 6)
2. Adding capabilities to the options struct (patches 7-9)
3. Hardening the API (patch 10)
4. Systematically removing old interfaces after migrating callers (patches 11-15)

The patch touches core ref handling code but the changes are mechanical and follow the established pattern from previous patches in the series. With this change, another specialized ref iteration variant is eliminated in favor of the unified API.
