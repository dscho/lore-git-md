This is part 5 of Adrian Ratiu's 8-patch series introducing config-based hooks, focusing on the ability to disable hooks via configuration. The patch adds a `hook.<name>.enabled` option that defaults to true, allowing hooks to be disabled without removing their configuration - particularly useful for system/global hooks that need per-repo exceptions.

Patrick Steinhardt suggested storing the enabled state directly in `struct hook` rather than filtering disabled hooks during config parsing, which would enable future features like `git hook list --disabled`. Adrian confirms this is feasible and plans to implement it in v3 while keeping the scope focused on base functionality. The change will maintain the disabled state in the cache while still allowing the information to be queried, though actual enable/disable commands would be part of a future series.

The discussion shows the series progressing toward final refinements, with Adrian responsive to review feedback while keeping the scope manageable. The maintainer-approved architecture remains intact, with this being one of the last implementation details to settle before the series can be considered ready.
