Shreyansh Paliwal has proposed improving `git send-email`'s handling of non-ASCII characters in email subject lines, addressing confusion around the current interactive prompt. When 8-bit content is detected, the prompt asks "Which 8bit encoding should I declare [UTF-8]?", which users might misinterpret as a yes/no question, leading them to answer "y" - which then gets incorrectly used as the charset name, producing malformed email headers.

Ben Knoble suggested clarifying the prompt by changing "[UTF-8]" to "[default: UTF-8]" to make the expected input clearer. Shreyansh has now submitted a patch implementing this minimal change to `git-send-email.perl`. The patch is straightforward and follows Git's established pattern for indicating default values, though the discussion notes this convention isn't universally applied across Git's CLI.

While this change addresses the immediate usability issue, Shreyansh raises the question of whether additional improvements might be warranted, such as warning on invalid charset inputs or falling back to UTF-8 when invalid input is provided. This appears to be Shreyansh's first contribution to Git, building constructively on Ben Knoble's suggestion. The patch is small and focused, leaving room for potential follow-up changes if further improvements to the encoding handling logic are identified.
