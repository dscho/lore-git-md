Feature addition to `git replay` command introducing `--revert` capability, now in its third iteration. The patch series extends `git replay` to support reversing commits directly on bare repositories, primarily for GitLab's Gitaly service use case.

Toon Claes raises a design question about the command's interface, suggesting that the distinct operation modes (`--onto`, `--advance`, and `--revert`) might be better expressed as subcommands rather than flags. This comes after the technical implementation has already gone through significant review and iteration, with consensus established on treating revert as a distinct operation mode.

The current implementation handles reverts via a separate `REPLAY_REVERT` mode that swaps merge arguments to reverse commit changes, preserving commit-by-commit reversal with individual messages. It reuses infrastructure from the sequencer for consistent revert message formatting while maintaining plumbing behavior (ignoring user configurations by default).

The discussion has involved several key contributors including Patrick Steinhardt, Phillip Wood, and Elijah Newren, with the implementation showing responsiveness to prior review comments. The v3 iteration includes defensive checks, memory management improvements, and test coverage refinements. Toon's suggestion about subcommands introduces a new architectural consideration late in the process, though the technical approach itself appears well-vetted.
