Test infrastructure patch in Patrick Steinhardt's series changing git maintenance's default strategy from "gc" to "geometric". This is the third of eight patches preparing the test suite for the behavioral change.

The patch addresses a subtle interaction between test timestamps and reflog expiration that would surface when maintenance starts using the geometric strategy. Tests in the t34xx range (rebase-related) rely on reflogs but currently pass by chance - the gc strategy skips maintenance when the object database is optimized, while geometric evaluates tasks independently and may expire reflogs even when the database is otherwise optimized. 

The core issue stems from test suite timestamps being hardcoded to 2005, making reflog entries appear immediately stale against the default expiration threshold (weeks). The patch proactively disables reflog expiration in four rebase test files by setting `gc.reflogExpire` and `gc.reflogExpireUnreachable` to "never". This demonstrates Patrick's characteristic thoroughness in anticipating side effects across the test suite before making behavioral changes.

The changes are mechanical but important for maintaining test stability when the maintenance strategy changes. This follows the pattern seen in earlier patches of the series where test infrastructure is adjusted first, with the actual strategy change coming later (patch 7/8).
