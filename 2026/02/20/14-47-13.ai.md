This is part 5 of Adrian Ratiu's config-based hooks series (v2), focusing on adding the ability to disable hooks via configuration. The patch introduces a new `hook.<name>.enabled` config option that defaults to true, allowing hooks to be disabled without removing their configuration - particularly useful for system/global hooks that need repository-specific exceptions.

Patrick Steinhardt's review suggests storing the enabled state directly in `struct hook` rather than maintaining a separate disabled_hooks list, which would enable future features like `git hook list --disabled`. Adrian confirms this is feasible and plans to implement it in v3 while keeping the scope focused on base functionality. The change will preserve disabled hook information while still filtering them from execution, leaving the door open for future enhancements.

The implementation currently uses `git_parse_maybe_bool()` to handle the enabled/disabled values, with proper cleanup of the string_list when hooks are re-enabled. This continues the series' pattern of careful memory management seen in earlier patches. The discussion shows the series maturing through constructive review, with Adrian responsive to feedback about making the design more extensible while maintaining focus on the core goal of configurable hooks.
