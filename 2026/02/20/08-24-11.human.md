Performance optimization in Patrick Steinhardt's ref iteration unification series. This is patch 7/17 in a larger effort to simplify Git's ref iteration API by introducing a unified `refs_for_each_ref_ext()` interface.

The patch focuses on `refs_for_each_glob_ref_in()`, which handles glob pattern matching during ref iteration. Previously, this function would inefficiently scan all refs before filtering by pattern, even when a prefix was specified. The change moves the glob handling into the new unified iteration function, allowing it to properly respect prefixes and skip irrelevant refs early.

The performance impact is dramatic in edge cases: a benchmark with 1 million refs outside the target prefix shows the operation becoming ~100x faster (115ms -> 1.1ms). The implementation maintains all existing behavior while adding the new `pattern` field to the options struct for glob support.

This continues the series' pattern of first introducing the unified API (patch 6) then optimizing specific cases to use it. The change is mechanical but impactful, showing the benefits of the refactoring approach.
