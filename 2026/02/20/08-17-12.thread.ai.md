Thread identity: Feature patch adding client certificate support to `git send-email`, enabling certificate-based SMTP authentication.

Core problem or goal: Currently `git send-email` lacks support for client certificate authentication, which is required in some security-sensitive environments. The patch aims to add this capability while maintaining compatibility with existing SMTP authentication methods.

Current status: First version of the patch has been through initial review with maintainer Junio C Hamano. The implementation approach is technically sound but needs documentation refinements. Key clarifications provided in follow-up:
- Behavior of Perl's IO::Socket::SSL library regarding certificate handling (PKCS12 embedded key takes precedence over separate key file)
- Real-world constraints from major email clients (Thunderbird, K-9 Mail) that impose PKCS12 requirements
- Niche but legitimate use case for supporting both formats (PEM and PKCS12) to accommodate security needs while working with platform constraints

Key technical details: Adds three new settings for client certificate authentication:
- `sendemail.smtpSSLClientCert` config option and `--smtp-ssl-client-cert` flag for client certificate file (PEM or PKCS12 format)
- `sendemail.smtpSSLClientKey` config option and `--smtp-ssl-client-key` flag for private key (required for PEM certificates)
- Uses IO::Socket::SSL for implementation with documented quirks:
  - PKCS12 format: embedded key takes precedence over any separately specified key
  - PEM format: falls back to cert file for key if no separate key specified
Maintains existing SMTP configuration patterns while adding proper error handling.

Open questions and loose ends: Documentation still needs to address:
- Clearer explanations of when servers require client verification
- Explicit documentation of certificate-key relationships and format-specific behaviors
- Edge case handling for providing separate key with PKCS12 cert
- Error message formatting improvements
