This is a feature patch series (v2, 8 patches) from Adrian Ratiu that implements config-based Git hooks, allowing hooks to be defined via `hook.<name>.command`, `hook.<name>.event`, and `hook.<name>.enabled` configuration options while maintaining compatibility with traditional filesystem hooks. The series introduces infrastructure for multiple hooks per event and adds a `git hook list` subcommand.

The work builds on an earlier hooks conversion series that Junio Hamano has now marked for inclusion in the 'next' branch. Junio expresses some initial concern about discoverability of config-based hooks compared to filesystem hooks, but notes that the new `git hook list` command addresses this by providing visibility into all configured hooks.

The series has received thorough review from both Junio and Patrick Steinhardt, with feedback focused on memory management patterns, data structure choices, and API design. Key discussion points include whether to cache `struct hook` instances directly versus using strmaps, how to handle disabled hooks, and naming conventions for cleanup functions. The reviews have been constructive and supportive of the overall approach, with Adrian preparing a v3 that will incorporate the suggested improvements.

This represents significant progress toward making Git hooks more flexible and maintainable, particularly for administrators who need to manage hooks across multiple repositories. The work is in its final polishing phase, awaiting only the prerequisite series to land in 'next' before final review and integration.
