This is the fourth patch in Patrick Steinhardt's 17-part refactoring series to unify Git's ref iteration interfaces. The series aims to simplify the API by reducing the number of specialized `refs_for_each_*()` functions.

This particular patch renames the `each_ref_fn` callback function type to `refs_for_each_cb` to better match Git's current naming conventions. The change is mechanical but widespread, touching 11 files across various subsystems including ref handling, pack-bitmap, submodules, and worktree code. The new name more clearly indicates the function's role as a callback for ref iteration.

The patch does is purely a naming change with no functional impact - all call sites are updated to use the new type name while maintaining identical behavior. This continues the preparatory work from earlier patches in the series (which renamed flags and moved declarations) to establish consistent naming scheme before introducing more substantial refactoring in later patches.

Key technical details:
- Renames `each_ref_fn` to `refs_for_each_cb` throughout the codebase
- Updates all function signatures and typedefs that use this callback type
- Touches ref backends (files, packed, reftable), ref-filter, and several other subsystems
- Maintains exact same callback semantics and behavior
- Part of establishing consistent naming before introducing unified ref iteration interface

The change is straightforward and unlikely to be controversial, continuing the series' incremental approach to refactoring the ref iteration API surface.
