Refactoring patch in Patrick Steinhardt's series to unify Git's ref iteration interfaces. This is patch 11/17, continuing the effort to consolidate the 14 specialized `refs_for_each_*` functions into a single configurable API.

The patch removes `refs_for_each_ref_in()` and migrates all its callers to use the new `refs_for_each_ref_ext()` interface with an options struct. The changes are mechanical but thorough, updating call sites in bisect.c, rev-parse.c, pack-bitmap.c, refs.c, and test helpers. Each conversion preserves the exact same behavior by setting appropriate prefix and trim_prefix values in the options struct.

Key technical points:
- Removes `refs_for_each_ref_in()` declaration from refs.h
- Updates specialized functions like `refs_for_each_tag_ref()` to use the new API internally
- Maintains identical prefix handling by setting trim_prefix to the prefix length
- Touches core ref iteration across multiple commands and subsystems
- Part of the broader ref backend modernization effort
- Follows the established pattern of this series - first introducing the new API (patch 6), then migrating callers (patches 7-10), and now removing the old interface
- All changes are behavior-preserving as verified by the test suite

The patch continues the series' careful, incremental approach - each step maintains compatibility while moving toward the unified API goal. With this change, another specialized iteration function is eliminated in favor of the more flexible options-based approach.
