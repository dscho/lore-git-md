Test infrastructure patch series addressing CI failures on Windows/MSVC platforms when Git is built with ICONV support but the `iconv(1)` executable is unavailable. This v4 iteration incorporates final polish from Eric Sunshine and is now ready for merging.

The series fixes test failures that occur when Git's ICONV support is enabled (via libiconv) but the separate `iconv(1)` command-line tool isn't present - a common scenario on Windows/MSVC where MinGW environment no longer ships the executable. The key insight is properly distinguishing between libiconv (a build-time dependency) and the `iconv(1)` executable (a test-time tool).

Changes span five test scripts (t4041, t4059, t4060, t4205, t5550, t6006) with consistent handling: tests requiring `iconv(1)` now properly depend on the ICONV prerequisite, falling back to UTF-8 encoding when unavailable. The v4 changes specifically address Eric Sunshine's feedback on t5550, fixing a typo ("proprely"->"properly") and standardizing on `test_grep !` style for negated pattern matching.

The approach maintains test coverage while improving portability, particularly for Windows/MSVC CI environments. Junio Hamano and Christian Couder have approved the series, with the final v4 iteration incorporating all review feedback. The patches demonstrate a complete solution for handling the iconv distinction across all affected test files, resolving the immediate CI failures while leaving a NEEDSWORK note about potentially splitting ICONV prerequisite checks for future consideration.
