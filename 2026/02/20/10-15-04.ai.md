This is a feature patch series from Patrick Steinhardt that changes the default maintenance strategy in `git maintenance` from "gc" to "geometric". The series consists of 8 patches, with the first 7 being test adjustments to handle the new default behavior, and the final patch making the actual strategy switch.

The motivation is twofold: (1) to complete the transition to a more flexible maintenance infrastructure where tasks can be toggled individually, and (2) to use a more efficient repacking strategy by default, particularly benefiting large repositories. Patrick notes the first point is actually more significant architecturally.

The bulk of the series deals with test fallout from the change - many tests either assume the old gc behavior or are racy with the new geometric strategy. Tests are updated to either disable maintenance where it interferes with verification, or explicitly request the "gc" strategy where needed. The actual behavior change is a one-line modification in builtin/gc.c.

Patrick acknowledges this is a potentially disruptive change and is open to feedback on whether to gate it behind `feature.experimental` first. The series maintains backward compatibility by allowing users to revert to the old behavior via `maintenance.strategy=gc`.

The changes touch test scripts across multiple subsystems that might be affected by different maintenance behavior, particularly around object storage (t53xx), fetch/push (t54xx/t55xx), and maintenance-specific tests (t79xx). The final patch modifies builtin/gc.c to change the default strategy constant from MAINTENANCE_GC to MAINTENANCE_GEOMETRIC.
