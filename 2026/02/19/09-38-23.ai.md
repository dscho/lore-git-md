This patch is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection for zero-downtime migrations between files and reftable backends. It introduces infrastructure to handle reference storage payloads that will later be used for URI-based backend configuration.

The key change is adding a `payload` parameter to backend initialization functions, which will eventually carry URI information. A new `refs_compute_filesystem_location()` function is introduced to parse gitdir and payload into proper reference directory paths, handling both main and worktree cases. The files and reftable backends are updated to use this helper.

The patch's technical details include:
- New `refs_compute_filesystem_location()` function in refs.c that handles path resolution
- Updates to `files_ref_store_init()` and `reftable_be_init()` to process payloads
- Packed backend explicitly ignores payload since packed-refs only exist in common dir
- Path normalization and worktree handling logic
- Memory management for strbuf paths

This is a preparatory change - the actual URI handling will come in later patches. The implementation maintains all existing functionality while laying groundwork for the new configuration mechanism. Test coverage for this infrastructure will be added with the subsequent config extension patches.

The patch has already gone through multiple review iterations with feedback from Patrick Steinhardt and others incorporated. It represents a stable piece of the larger reference storage selection system that's now ready for merging.
