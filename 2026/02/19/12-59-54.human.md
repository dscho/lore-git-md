This is the second patch in a GSoC 2026 applicant's series to reduce global state in Git's mailmap subsystem. It follows an initial patch that converted mailmap` functions to take explicit `struct repository` parameters.

The patch removes the global variables `git_mailmap_file` and `git_mailmap_blob` that previously stored mailmap configuration values. Instead, it reads these configurations on-demand using `repo_config_get_*` functions when initializing a mailmap. The changes affect the `blame`, `log`, `shortlog`, and `ref-filter` commands that use mailmap functionality.

The implementation appears straightforward and mechanically sound, with proper cleanup of temporary variables. This continues the project's broader `the_repository` removal effort in a focused way. The patch doesn't change user-visible behavior - it just moves where and how configuration is stored. As part of a GSoC application, it demonstrates the contributor's ability to work within Git's codebase while making meaningful progress on a well-scoped task.
