This is the final iteration of a feature series implementing UTF-8 support for Git configuration subsections, specifically for aliases (e.g., `[alias "förgrena"]`). The v7 series includes four commits and has now addressed all feedback, with Junio Hamano indicating it's ready for merging into the `next` integration branch.

The key technical change in v7 is reverting the output format of the new `--aliases-for-completion` option in `git help` to match Git's established convention of using newline as the field separator between name and value within NUL-terminated records (name\nvalue\0), rather than using NUL for both separators as was briefly tried in v6. This maintains consistency with `git config -z` behavior.

The implementation now fully handles UTF-8 aliases via subsection syntax while maintaining backward compatibility, with comprehensive test coverage including Swedish, CJK, and spaces. The zsh completion has been fixed to use this new C-based implementation rather than regex parsing, ensuring proper handling of both traditional and subsection alias formats. All technical work is complete including alias listing consolidation, help.c parser refactoring, and the final zsh completion fix.

Junio Hamano has reviewed and approved the series, noting that while using LF as a separator in a -z context "makes our eyes feel dirty", it's the established convention and thus the right choice. He indicates the topic is now ready for queuing in the `next` branch, marking the successful conclusion of this seven-iteration effort to properly support UTF-8 in alias names.
