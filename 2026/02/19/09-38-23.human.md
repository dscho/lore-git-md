This is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch is the 4th in a v7 series that has already received maintainer approval from Junio Hamano.

The patch introduces infrastructure for reference backends to accept and use a "reference storage payload" that will eventually allow specifying alternate storage locations via URI in the `extensions.refStorage` config. Currently a no-op since no callers pass payloads yet, it:

1. Adds a new `refs_compute_filesystem_location()` helper that parses gitdir and payload to determine reference directory locations
2. Modifies both files and reftable backends to accept and handle the payload parameter
3. Centralizes path resolution logic for worktree and common reference directories

The changes are well-contained and mechanical, with clear commit messages explaining the transitional nature of this step. The series as a whole is mature, having addressed extensive review feedback over multiple iterations, and this patch in particular has been reviewed by Patrick Steinhardt (who helped shape the approach) and others. The implementation looks solid and aligns with the broader goal of making reference storage backend selection flexible for large-scale deployments like GitLab's.
