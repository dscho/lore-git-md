This is a refactoring patch series from a GSoC 2026 applicant, targeting the mailmap subsystem as part of the broader effort to reduce Git's global state. The series consists of two patches that work together to eliminate repository-global dependencies in the mailmap code.

The first patch removes implicit reliance on `the_repository` by adding explicit `struct repository` parameters to `read_mailmap()` and `read_mailmap_blob()`. This follows the established pattern seen in other parts of the codebase that are being converted away from global repository state. The change is mechanical but touches several callers across builtin commands like `git blame`, `git log`, and `git shortlog`.

The second patch is more substantial, removing the global configuration variables `git_mailmap_file` and `git_mailmap_blob`. Instead of storing these values globally, the patch makes the mailmap subsystem read configuration on demand using config set helpers. This better isolates configuration state and follows the project's direction toward reducing global variables.

The changes appear well-scoped and correctly implemented, with appropriate updates to all call sites. The author demonstrates awareness of ongoing work (noting an Outreachy intern's work on environment.c) and chooses a non-conflicting area to contribute. As a learning exercise, this shows good understanding of the codebase and the project's refactoring goals. The patches would need real-world testing to verify no behavioral regressions in mailmap handling across the various commands affected.
