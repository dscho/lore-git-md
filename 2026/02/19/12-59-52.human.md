This is a refactoring patch series from a GSoC 2026 applicant, targeting the mailmap subsystem as part of the broader effort to reduce Git's global state. The series consists of two patches that work together to eliminate repository-global dependencies in mailmap handling.

The first patch removes implicit reliance on `the_repository` by making the repository parameter explicit in mailmap-reading functions. The second patch goes further by eliminating the global configuration variables `git_mailmap_file` and `git_mailmap_blob`, replacing them with on-demand config reading. The changes touch several builtin commands that use mailmap functionality (blame, log, shortlog, etc.), requiring parameter passing through their call chains.

The author notes this is primarily a learning exercise, as their actual GSoC project would focus on `environment.c` (which is being worked on by someone else). The patches appear cleanly scoped to the stated goal, though as a student submission they may need review for corner cases in config handling. This fits neatly into the ongoing `the_repository` removal effort that René Scharfe and others have been driving.
