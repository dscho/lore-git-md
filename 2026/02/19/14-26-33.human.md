This is the second patch in a two-part series refactoring the worktree API as part of the ongoing `the_repository` removal effort. Phillip Wood builds on Shreyansh Paliwal's earlier work to simplify `worktree_git_path()` by removing its redundant `repository` argument now that all callers provide a non-NULL worktree parameter.

The change eliminates a potential foot-gun where callers could mismatch the repository and worktree arguments. The patch updates all call sites across several files (`builtin/fsck.c`, `builtin/worktree.c`, `revision.c`, `worktree.c`, and `wt-status.c`) to use the simplified signature. A BUG() assertion enforces the non-NULL worktree requirement.

This is a clean, mechanical change that follows naturally from the first patch in the series. It demonstrates good attention to detail by verifying all call sites and adding appropriate safeguards. The change moves the codebase incrementally closer to eliminating `the_repository` global while maintaining existing functionality. The patch appears ready for integration with no obvious loose ends.
