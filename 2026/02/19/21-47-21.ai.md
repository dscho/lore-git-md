This is a refactoring patch in Adrian Ratiu's config-based hooks series, specifically addressing the hook callback data management. The patch moves from stack-allocated callback data to dynamically allocated structures managed by the hook infrastructure itself.

The key change introduces `feed_pipe_cb_data_alloc` and `feed_pipe_cb_data_free` callbacks in the `run_hooks_opt` structure, allowing hook implementations to provide their own memory management rather than handling it manually. The patch updates both the reference transaction` and `pre-push` hooks to use this new approach.

Junio Hamano reviews the patch positively, noting the cleaner resource management pattern. He suggests a more concise way to write the BUG check for ensuring alloc/free functions are paired (using boolean negation or inequality operators) while acknowledging the style might be too clever for some tastes. The review confirms the implementation matches the stated goal of moving callback data management into the hook infrastructure.

This is part of the larger config-based hooks effort that's progressing through the integration branches, with Junio indicating the prerequisite hooks-conversion work is nearing readiness for inclusion in 'next'. The patch itself is a mechanical refactoring that enables the more user-visible hook configuration features to come later in the series.
