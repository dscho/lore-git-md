This is a bugfix patch in Patrick Steinhardt's series addressing ref iteration issues in both bitmap and bisect functionality. The patch specifically corrects how bisect operations handle ref iteration by fixing a misuse of `refs_for_each_ref_in()`.

The key changes are:
1. Adds a trailing slash to "refs/bisect" when iterating refs, which is required for proper hierarchy matching (consistent with Git's ref matching conventions established in commit 10e8a9352b)
2. Switches from `refs_for_each_ref_in()` to `refs_for_each_fullref_in()` to avoid unnecessary string manipulation, since the callback was just reconstructing the full ref name anyway
3. Simplifies the `mark_for_removal()` callback by having it use the already-complete ref name rather than reconstructing it

The changes align with the thread's broader theme of consistent ref handling and follow Jeff King's earlier improvements to string_list memory management in the bisect code. This is the third patch in a 4-part series that has already received maintainer approval from Taylor Blau, with the preparatory refactoring and bitmap fixes coming in earlier patches. The solution maintains backward compatibility while fixing edge cases where exact ref matches could trigger a BUG().
