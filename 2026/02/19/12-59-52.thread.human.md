Burak Kaan Karaçay's GSoC 2026 contribution refactors Git's mailmap subsystem to eliminate global state dependencies, now in its second revision. The two-patch series makes two key changes: first converting mailmap functions to take explicit `struct repository` parameters instead of using the implicit `the_repository` global, then removing the global configuration variables entirely in favor of on-demand config reading.

The changes affect several builtin commands (`blame`, `log`, `shortlog`, and `ref-filter`) but are mechanical in nature - passing `the_repository` where it was previously implicit. The v2 revision fixed a header inclusion issue caught by `make hdr-check`, and Junio C Hamano has reviewed and approved the core design. The implementation maintains backward compatibility while removing implicit global state, with mailmap data still stored in a simple string_list without long-lived structures.

This work aligns with the broader `the_repository` removal effort that René Scharfe and others have been driving. The series represents focused, well-contained progress on technical debt, with all known issues addressed in v2. The changes are ready for integration pending final maintainer approval, marking a clean step forward in reducing Git's global state dependencies.
