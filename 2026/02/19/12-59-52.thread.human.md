This thread introduces a patch series from a GSoC 2026 applicant that refactors Git's mailmap subsystem to reduce global state dependencies. The first patch converts `read_mailmap()` and `read_mailmap_blob()` functions to take explicit `struct repository` parameters instead of implicitly using `the_repository`, updating all callers in `blame`, `log`, `shortlog`, and `ref-filter` commands to pass `the_repository` to maintain current behavior.

The changes align with the broader `the_repository` removal effort that René Scharfe and others have been driving. The implementation appears mechanically sound, with all call sites updated consistently. The author demonstrates awareness of the context by referencing related work from an Outreachy intern on environment.c changes. 

A second patch is expected to follow that will remove the remaining global configuration variables `git_mailmap_file` and `git_mailmap_blob`. This represents a well-scoped contribution targeting a non-controversial area of the ongoing global state reduction initiative, making it a suitable project for a GSoC applicant. The changes are straightforward but meaningful, focusing on mailmap handling without venturing into more complex territory.
