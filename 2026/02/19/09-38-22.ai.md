This is part of the ongoing ref backend abstraction effort, specifically patch 3/6 in the v7 series enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch has maintainer approval from Junio Hamano and is ready for the 'next' branch.

The patch moves stub creation/deletion logic for reference backends from the reftable-specific implementation to the generic refs layer, while maintaining special handling for the files backend. The key technical changes are:

1. Moves `refs_create_refdir_stubs()` calls from reftable backend to `ref_store_create_on_disk()` in refs.c, with files backend exempted
2. Adds parallel stub deletion logic in `ref_store_remove_on_disk()`, again excluding files backend
3. Modifies files backend to directly call packed-refs cleanup to avoid stub removal attempts
4. Removes now-redundant stub handling from reftable backend

The changes support upcoming work on alternate reference backend locations by centralizing stub management. The files backend requires special treatment because it handles worktree refs/HEAD creation differently. The patch includes comprehensive error handling and maintains existing behavior while cleaning up the architecture.
