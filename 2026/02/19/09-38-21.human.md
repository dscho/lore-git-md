Refactoring patch for reference storage stubs in the reftable backend series. This is part of the larger effort to enable reference storage backend selection, now in its 7th iteration with maintainer approval.

The patch extracts duplicate stub-creation code from `builtin/clone.c` and `refs/reftable-backend.c` into a new `refs_create_refdir_stubs()` function in `refs.c`. This function creates the minimal directory structure (HEAD file and refs/ directory) that Git requires to recognize a directory as a repository, which is needed even when using alternate backends like reftable.

The new function includes an optional parameter to write a message to refs/heads/ (used by the reftable backend to indicate its format). The changes are straightforward - mostly code movement with some minor adjustments to handle the repository parameter and shared permissions consistently.

This is a clean refactoring that eliminates duplication while maintaining all existing functionality. The patch fits well into the broader series that's now considered ready for merging, with all substantive concerns addressed in previous rounds.
