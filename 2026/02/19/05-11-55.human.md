This is a security patch addressing repository discovery hardening, now in its fifth iteration. The patch series aims to prevent Git from attaching to parent repositories through malformed `.git` entries (like FIFOs or sockets) while still allowing legitimate symlinks.

The current discussion focuses on Junio Hamano's detailed review of the control flow in patch 2/2, which handles `.git` symlinks. Junio points out several critical issues that need addressing:

1. The error handling needs to properly respect the `die_on_error` flag rather than unconditionally calling `read_gitfile_error_die()`
2. The `is_git_directory()` check should only run when we explicitly know we're dealing with a directory (READ_GITFILE_ERR_IS_A_DIR)
3. The patch must maintain compatibility with all callers, particularly submodule.c

Author Tian Yuchen acknowledges these issues and notes they've already sent a v6 addressing some concerns, but will need to:
- Further refine when directory checks occur
- Potentially squash patches as Junio suggested
- Improve commit message clarity around the stat()/lstat() behavior

The security model itself remains sound - the changes are about properly implementing the error handling contracts while maintaining backward compatibility Git requires. This is the final stretch of review before the security hardening can land.
