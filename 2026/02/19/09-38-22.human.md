This is part of the ongoing ref backend abstraction effort, specifically patch 3/6 in the v7 series enabling reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch has maintainer approval from Junio Hamano and is ready for merging.

The change moves stub creation/deletion logic for reference directories from the reftable backend to the generic refs.c layer, making it available to all backends except the files backend (which handles stubs differently). This prepares for upcoming work supporting alternate reference backend locations where stubs will be needed in `$GIT_DIR` regardless of backend type.

Key technical changes:
- Moves `refs_create_refdir_stubs()` calls from reftable backend to generic `ref_store_create_on_disk()`
- Adds stub deletion logic to `ref_store_remove_on_disk()`
- Special-cases the files backend to skip stub operations
- Updates packed-refs cleanup in files backend to use direct backend calls

The patch is well-contained and follows the established pattern of this multi-version effort, with clean commit message explaining the motivation. It represents a straightforward refactoring step toward the series' goal of flexible reference storage configuration.
