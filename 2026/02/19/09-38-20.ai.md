This is a refactoring patch that's part of a larger series (v7 1/6) about reference database handling. The patch focuses on cleaning up `create_reference_database()` to remove an unexpected side effect where it was modifying the repository's ref storage format.

The key change removes the `ref_storage_format` parameter from `create_reference_database()` since the function was redundantly setting this value in two cases: during `git init` (where it was already set) and during `git clone` (where it was pointlessly resetting the existing value). The patch argues this could cause issues if future ref storage formats include dynamically allocated strings.

The changes are straightforward - removing the parameter from the function declaration and call sites in `builtin/clone.c` and `setup.c`. This appears to be a well-motivated cleanup that simplifies the code by removing duplicate operations and preventing potential future issues. The patch is part of Karthik Nayak's ongoing work on ref storage and reftable backend improvements.
