This is a CI/build system patch that fixes test slicing in Git's CI pipelines. It addresses an inconsistency where GitLab CI was unintentionally skipping the smallest test due to using 1-based indexing while the test slicing tool expected 0-based indexing.

The patch reframes the terminology from "offset/stride" to "slice number/total slices" to make the behavior more intuitive. Key changes include:
- The test slicing tool now validates that slice numbers are within bounds (1 <= slice <= total)
- GitHub Actions workflow is updated to use 1-based indexing to match GitLab
- The underlying sorting behavior remains unchanged - tests are still sorted by size before slicing

The fix ensures both CI systems will run all test slices correctly. The change is well-motivated with a detailed explanation of the problem and solution, and includes sign-off from Johannes Schindelin who maintains Git for Windows' CI infrastructure. The patch is part of a larger series (v2 2/7) improving meson build and CI integration.
