This is a bugfix series addressing ref iteration issues in bitmap and bisect functionality, now in its fourth iteration. The core problem stems from misuse of `refs_for_each_ref_in()` where exact ref matches would trigger a BUG() due to improper prefix stripping.

Patrick Steinhardt's series has evolved to use ref hierarchy matching (with trailing slashes) as established in recent ref exclusion patterns (10e8a9352b). The changes:

1. First consolidates duplicate bitmap tip iteration logic from pack-objects and midx into a new `for_each_preferred_bitmap_tip()` helper, making `bitmap_preferred_tips()` file-local to pack-bitmap.c while preserving existing behavior.

2. Fixes the bitmap exact ref match bug via hierarchy matching in the new iteration function, updating documentation to clarify the new matching semantics (with a typo fix from v3).

3. Corrects bisect ref handling by switching to `refs_for_each_fullref_in()` with proper trailing slash handling.

4. Incorporates Jeff King's improvement to simplify string_list memory management in `bisect_clean_state()` using STRING_LIST_INIT_DUP.

Testing coverage is thorough updates to t5310-pack-bitmaps.sh and t5319-multi-pack-index.sh.
