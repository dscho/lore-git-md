This is a memory management cleanup patch in the bisect subsystem, part of Patrick Steinhardt's series fixing ref iteration bugs. The patch simplifies string_list handling in `bisect_clean_state()` by using `STRING_LIST_INIT_DUP` instead of toggling strdup_strings behavior.

Jeff King identified that the original code used a confusing pattern: initializing the string_list with NODUP but then setting strdup_strings=1 just before cleanup to force freeing. With his earlier change to use plain string copies rather than formatted strings, this complexity is no longer needed. The patch makes the memory management more straightforward by letting the string_list handle duplication from the start.

This is a mechanical improvement that doesn't change functionality, just makes the code clearer and more maintainable. It's the final patch in a series that has already been reviewed and approved by Taylor Blau and incorporates Jeff King's suggested improvements. The change aligns with the thread's overall goal of cleaning up ref iteration patterns while fixing specific bugs in bitmap and bisect handling.
