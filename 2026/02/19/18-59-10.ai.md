Documentation patch finalizing the clarification of `--jobs=0` behavior in `git fetch`. This follows up on Patrick Steinhardt's suggestion to explicitly document that both the command-line `--jobs=0` and config `fetch.parallel=0` default to using `online_cpus()` (the number of available CPU cores).

Junio C Hamano notes that while the implementation has worked this way since commit c39952b92 (2023-02-20), there was likely a deliberate decision to keep the documentation vague about the specific fallback behavior. The patch thread shows consensus on improving the documentation to match reality, though Junio hints at a possible future discussion about whether `--jobs=auto` might be a clearer name for this behavior.

The change is straightforward and non-controversial, affecting only two documentation files to state the CPU count fallback explicitly. This creates symmetry between the command-line and config documentation while maintaining the existing behavior. The thread demonstrates the project's typical documentation improvement process - identifying unclear or outdated descriptions and updating them to match implementation details that users might reasonably want to know.
