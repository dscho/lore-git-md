This is a bugfix patch in Patrick Steinhardt's series addressing ref iteration issues in both bitmap and bisect functionality. The patch specifically corrects how bisect operations handle ref iteration by fixing a misuse of `refs_for_each_ref_in()`.

The key changes are:
1. Adds a required trailing slash to the "refs/bisect" prefix when iterating refs, which matches Git's established convention for ref hierarchy matching (previously missing this could cause empty string results)
2. Switches to using `refs_for_each_fullref_in()` instead of the more complex `refs_for_each_ref_in()` since the code was needlessly stripping and re-adding the prefix
3. Simplifies the `mark_for_removal()` helper by removing redundant string formatting

This is part of a larger effort to standardize ref iteration patterns across Git's codebase. The change aligns bisect's behavior with the ref matching conventions established in recent changes (like commit 10e8a9352b) and fixes potential edge cases while making the code more straightforward. The patch has already received positive feedback from maintainers and is ready for merging.
