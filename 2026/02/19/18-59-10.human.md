This is a documentation follow-up in an ongoing thread about clarifying the behavior of `git fetch --jobs=0`. Junio C Hamano responds to Patrick Steinhardt's suggestion to explicitly document that the "reasonable default" for `--jobs=0` and `fetch.parallel=0` is based on `online_cpus()` (the number of available CPU cores).

Junio notes that while the implementation has worked this way since commit c39952b92 (2023-02-20), there was likely a deliberate decision to keep the documentation vague about the specific CPU count. He suggests this was done to avoid over-specifying implementation details in user-facing docs, though he doesn't object to the clarification.

The exchange shows the project's careful balance between documenting behavior clearly and avoiding over-commitment to implementation specifics. While the thread has consensus on the current documentation improvement, Junio's response hints at the project's historical preference for keeping some flexibility in how such defaults are described. The patch itself is straightforward and uncontroversial, but the discussion surfaces an interesting tension in documentation philosophy.
