Documentation patch clarifying the behavior of `git fetch --jobs=0`. This follows up on Patrick Steinhardt's suggestion to make the documentation more precise about how parallel fetching works when the job count is set to zero.

The patch adds a note to `fetch-options.adoc` explaining that `--jobs=0` will use "some reasonable default", matching the existing documentation for the equivalent `fetch.parallel=0` config setting. Junio Hamano accepts the patch, noting that while `--jobs=auto` might have been a better name, documenting the current behavior is a good step forward.

This is a straightforward documentation improvement that brings consistency between the command-line option and config documentation. The thread remains uncontroversial, with the maintainer indicating the patch will be queued for inclusion. The change helps users understand that setting jobs to zero doesn't disable parallelism but rather lets Git choose an appropriate level based on system resources.
