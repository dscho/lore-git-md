This is the second patch in a two-part series refactoring the worktree API as part of the ongoing `the_repository` removal effort. Phillip Wood builds on Shreyansh Paliwal's earlier work to eliminate the redundant repository parameter from `worktree_git_path()`, since all callers now pass a non-NULL worktree argument.

The patch removes the repository parameter from `worktree_git_path()` and updates all callers to use the simplified signature. A BUG() assertion enforces the non-NULL worktree requirement. The changes touch several key subsystems including fsck, worktree management, revision walking, and status reporting, demonstrating how this API is used across Git's core functionality.

The implementation is straightforward - since all callers now provide a worktree, the function can directly access the embedded repository from the worktree struct rather than taking it as a separate parameter. This removes potential confusion where callers might pass mismatched repository/worktree pairs. The patch includes updates to builtins (fsck, worktree), core components (revision, worktree), and status reporting (wt-status), showing the wide impact of this API change.

This change represents a clean-up of the API introduced in the first patch of the series, removing now-redundant parameters after ensuring all callers have been updated. It's a mechanical but important step in the larger effort to eliminate `the_repository` global by making repository dependencies explicit.
