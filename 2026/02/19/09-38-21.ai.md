This is part of the ref backend abstraction effort, specifically patch 2/6 in the v7 series enabling reference storage backend selection. The patch extracts stub creation logic for Git directory recognition into a shared `refs_create_refdir_stubs()` function.

The change centralizes the creation of required stub files/directories (`HEAD` and `refs/`) that Git uses to identify a directory as a repository. Previously this logic was duplicated in the clone machinery and reftable backend. The new function handles both basic stub creation and optional `refs/heads` content (used by reftable to indicate its format).

Key technical details:
- Moves stub creation from `builtin/clone.c` and `refs/reftable-backend.c` to new `refs_create_refdir_stubs()` in `refs.c`
- Maintains same functionality while reducing duplication
- Adds proper documentation header explaining the stub requirements
- Preserves all existing behavior including:
  - Writing invalid HEAD ref
  - Creating refs directory
  - Optional message for refs/heads (used by reftable)
  - Permission adjustments

The patch is a straightforward refactoring with no behavior changes, cleaning up code in preparation for further work in the series. It follows the established pattern of this mature patch set, which has already addressed extensive review feedback across multiple iterations.
