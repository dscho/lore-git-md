This is the second patch in a GSoC 2026 applicant's series to reduce global state in Git's mailmap subsystem. It follows an initial patch that converted mailmap functions to take explicit `struct repository` parameters.

The patch removes the global variables `git_mailmap_file` and `git_mailmap_blob` that previously stored mailmap configuration values. Instead, it reads these configurations on-demand using `repo_config_get_*` functions when initializing a mailmap. The changes affect three files: `environment.c` (removing the mailmap config parsing logic), `mailmap.c` (adding on-demand config reading), and `mailmap.h` (removing the extern declarations).

The implementation appears straightforward and mechanically sound, with proper memory management (freeing the temporary config values after use). It maintains the existing fallback behavior where bare repositories default to "HEAD:.mailmap" when no blob is specified. This change is part of the broader `the_repository` removal effort that René Scharfe and others have been driving, though it stands on its own as a clean-up of unnecessary global state.

The patch shows good attention to detail - the commit message explains the motivation clearly, the diff is clean, and it handles edge cases like bare repository behavior correctly. As with the first patch, this appears ready for review, though real-world testing would be needed to verify no behavioral regressions in mailmap functionality.
