This is a CI/build system patch in a series that has already been picked up for integration, addressing a Windows-specific test-slicing issue in the GitHub workflow.

Patrick Steinhardt's original patch standardized test-slicing to use one-based numbering across both Make and Meson builds, but missed that Visual Studio builds on GitHub CI were still using zero-based numbering. Johannes Schindelin spotted this when the tests failed with "slice must be in the range 1 <= slice <= 10, got '0'" and provided a straightforward fix that increments the slice number in the GitHub workflow YAML.

The fix is now being squashed into the original patch, completing the series' goal of consistent test execution across all CI environments. With this last edge case addressed, the full series is ready for integration, demonstrating the project's attention to cross-platform testing rigor - especially important for Windows/MSVC builds.
