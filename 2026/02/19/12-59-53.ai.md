This is part 1 of a 2-patch series from a GSoC 2026 applicant refactoring Git's mailmap subsystem to reduce global state dependencies. The patch converts `read_mailmap()` and `read_mailmap_blob()` functions to take explicit `struct repository` parameters instead of implicitly using `the_repository`, updating all callers to pass `the_repository` to maintain current behavior.

The changes touch mailmap handling across several commands including `blame`, `log`, `shortlog`, and `ref-filter`. The implementation appears mechanically sound, with all call sites updated consistently. This aligns with the broader `the_repository` removal effort that René Scharfe and others have been driving.

The patch demonstrates awareness of the context by mentioning related work from an Outreachy intern on environment.c changes. While the changes are straightforward, they represent a useful incremental step in reducing global state - a non-controversial area where a GSoC contribution can make meaningful progress without stepping into more complex territory. The second patch in the series will handle removing the remaining global configuration variables `git_mailmap_file` and `git_mailmap_blob`.
