This is a memory management cleanup patch in the bisect subsystem, part of Patrick Steinhardt's series fixing ref iteration bugs. The patch simplifies string handling in `bisect_clean_state()` by using proper string_list initialization rather than manual memory management.

Jeff King identified that the code was using a confusing pattern: initializing the string_list with NODUP (no automatic duplication) but then manually allocating strings and later enabling strdup_strings just for cleanup. Since a previous commit changed the string generation to use simple xstrdup(), the patch now initializes the list with DUP from the start, letting the string_list handle all memory management automatically.

The change is straightforward and mechanical, removing 6 lines while adding 4. It maintains the same functionality while making the code more maintainable. This is the final patch in a series that has already received maintainer approval, with Taylor Blau signing off on the technical approach. The change aligns with the series' broader goal of cleaning up ref iteration patterns while fixing edge cases in both bitmap and bisect functionality.
