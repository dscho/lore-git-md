This is the final patch in a v7 series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable), now with maintainer approval. The series provides configuration (`extensions.refStorage`), environment-based (`GIT_REFERENCE_BACKEND`), and URI-based control, primarily serving GitLab's migration needs.

This specific patch adds the `GIT_REFERENCE_BACKEND` environment variable to specify reference backends dynamically, complementing the existing config-based approach. The environment variable allows modifying the reference backend and location on the fly for individual Git commands, including during `git-clone` and `git-init`. When initializing a repository with an alternate reference folder, it creates required stubs in the repository's `$GIT_DIR` while ensuring removal operations don't clean up these stubs to maintain usability.

Key technical components include:
- New environment variable handling in `setup.c` that overrides config settings
- Stub management for alternate reference directories
- Integration with repository initialization and cloning
- Comprehensive test coverage in `t1423-ref-backend.sh` verifying both config and environment variable paths

The implementation builds on prior work in the series to support URI parsing (`parse_reference_uri()`) and worktree reference location resolution. Review feedback from multiple contributors has been incorporated, and Junio Hamano has indicated readiness to merge the series to 'next'. This completes the configuration mechanisms needed for GitLab's large repository migration use case.
