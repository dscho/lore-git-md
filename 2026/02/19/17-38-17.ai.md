Documentation patch clarifying the behavior of `git fetch --jobs=0`. This follows up on Patrick Steinhardt's suggestion to improve the documentation of parallel fetch behavior by explicitly stating that a value of 0 defaults to the number of available CPU cores (from `online_cpus()`), rather than the vague "some reasonable default" phrasing.

Junio C Hamano accepts the patch as a good first step, though he muses that `--jobs=auto` might have been a better name for this behavior. The change creates symmetry between the documentation for `--jobs=0` and the already-documented `fetch.parallel=0` configuration, both of which share the same implementation. The patch is straightforward and non-controversial, simply adding two lines to `fetch-options.adoc` to clarify behavior that was introduced in commit c39952b92 but previously undocumented.

This is part of an ongoing effort to improve documentation accuracy by surfacing implementation details that help users understand Git's behavior. The thread shows consensus that this is a worthwhile clarification, though there may be future discussion about whether to rename the option to `--jobs=auto` for even greater clarity.
