This is a CI/build system patch that standardizes test execution between GitLab and GitHub CI for MSVC+Meson builds. It's part of Patrick Steinhardt's 7-patch series improving test infrastructure reliability, now picked up by Junio for integration.

The patch makes GitLab CI use the same `ci/run-test-slice-meson.sh` script that GitHub CI already employs, rather than open-coding the Meson test parameters. This ensures consistent test execution behavior across both CI systems. The change specifically affects Windows/MSVC builds under Meson, where the test slicing logic (dividing tests across parallel jobs) is now handled identically in both environments.

The implementation switches from directly calling Meson's test command to invoking the standardized bash script, using Git for Windows' bash interpreter. This matches the approach used in GitHub CI and completes the series' goal of unifying test infrastructure behavior. The patch is straightforward - a one-line change in `.gitlab-ci.yml` that replaces the direct Meson invocation with the script call.

This comes after Johannes Schindelin identified and fixed a Windows+VS specific test-slicing issue in patch 5/7, demonstrating the series' focus on cross-platform testing rigor. With this change, both CI systems now use identical test execution paths for MSVC+Meson builds, including the corrected one-based test numbering scheme.
