This is the final version of a feature series enabling flexible reference storage locations, primarily to support GitLab's zero-downtime migration needs between ref backends (files<->reftable). The series has undergone extensive review and refinement over multiple versions, with maintainer approval from Junio Hamano already secured.

The key additions in v7 include:
- More detailed commit messages and documentation
- Test coverage for stub creation when initializing new repositories
- Cleanup of whitespace and commit ordering
- Centralized stub management in the generic refs layer (with files-backend exceptions)
- The series introduces two ways to specify alternate ref storage:
  1. Via config: `extensions.refStorage` now accepts either a simple format name (`reftable`) or a URI (`reftable:///path/to/refs`)
  2. Via environment: `GIT_REFERENCE_BACKEND` can override the config

The implementation handles worktree references properly and maintains backward compatibility stubs in the main gitdir. The changes are well-tested with new test cases covering clone/init scenarios and migration workflows.

This represents the culmination of a multi-version effort to enable GitLab's large repository migration strategy, where the ability to write refs to an arbitrary location during a dry-run phase is critical for minimizing downtime. The series is now in its final polishing stage, with only minor test verification details remaining open between Patrick Steinhardt and Karthik Nayak.
