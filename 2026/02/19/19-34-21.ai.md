This is a refactoring patch that concludes a series aimed at simplifying the worktree API by removing redundant repository parameters. It's part of the ongoing `the_repository` removal effort.

The patch removes the `struct repository` parameter from `worktree_git_path()` since all callers now provide a valid `struct worktree` (which itself contains a repository reference). This eliminates potential confusion where callers might pass mismatched repository/worktree pairs. Phillip Wood provides a thorough analysis of all call sites to confirm none rely on the NULL worktree case anymore.

The changes are mechanical but touch several components: fsck, worktree management, revision walking, and status reporting. Junio Hamano approves the change, calling it a well-reasoned cleanup. This represents the completion of an API simplification that began in August 2024 (a973f60dc7c), with the intermediate step being the addition of proper worktree handling in status reporting (from the previous patch in this series).

The patch demonstrates how incremental refactoring can safely remove global state dependencies while maintaining functionality across multiple subsystems. All technical feedback from earlier reviews appears addressed, and the change is now ready for integration pending resolution of some higher-level architectural questions Junio raised about worktree/repository relationships in submodule contexts.
