This is a follow-up discussion in the thread about fixing `git format-patch`'s `--from` option handling in cover letters. D. Ben Knoble and Jeff King are clarifying historical context around how cover letters are typically generated in Git workflows.

The exchange reveals that while Jeff King originally implemented the `--from` option in 2013, he wasn't aware that most users generate cover letters via `format-patch` rather than `send-email` (contrary to his initial assumption). Knoble points out that the `send-email` documentation actually shows an example using `format-patch` to create the letter. This explains why the `--from` inconsistency persisted unnoticed for so long - the feature is rarely used, and those who do use it were likely combining it with `format-patch` in ways the original implementation didn't fully consider.

The discussion provides useful background about real-world Git email workflows, though it doesn't change the technical solution (already approved in v4 of the patch). It does highlight how documentation examples can shape user behavior in unexpected ways, and how rarely-used features can harbor subtle bugs for years. The tone is collegial, with both contributors acknowledging gaps in their understanding of how others use these commands.
