Feature patch for reference backend configuration, part of the reftable backend effort. This is patch 5/6 in a series that has already received maintainer approval from Junio Hamano and is ready for the 'next' branch.

The patch extends the `extensions.refStorage` configuration to support URI syntax (`<format>://<path>`) for specifying both the reference storage backend (files or reftable) and an alternate location for storing references. This enables zero-downtime migrations between backends and locations, primarily serving GitLab's needs.

Key changes include:
- URI parsing logic in `parse_reference_uri()`
- Worktree reference handling to store linked worktree refs in the alternate location while maintaining stubs in the original location
- Repository initialization updates to propagate the storage configuration
- Comprehensive tests in t1423-ref-backend.sh covering URI validation, backend switching, and worktree behavior

The implementation is thorough with good test coverage and has been reviewed by multiple contributors including Patrick Steinhardt, Karthik Nayak, and Jeff King. A minor TODO remains for future work to pass worktree structs directly to backends rather than paths, but this doesn't block merging.

This is the final technical piece of the series, following preparatory infrastructure patches. The changes are well-contained and focused on the configuration aspect, building on the established backend selection mechanism.
