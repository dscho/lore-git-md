This is a test fix addressing an edge case in `git cat-file --batch-check` format handling. The original test tried to use object names containing whitespace (like "HEAD:path with spaces") with the `%(rest)` placeholder, which created parsing ambiguity. The patch changes the test to use resolved object IDs (OIDs) instead, since OIDs never contain whitespace, making the parsing unambiguous.

Junio C Hamano, the maintainer, questions whether this is the right approach. He suggests an alternative that would still test with the original object name when possible (when it doesn't contain whitespace), only falling back to OIDs for problematic cases. This would better align with the original intent of commit 9fd38038, which aimed to test generic object specifiers.

The patch is simple and focused, touching only the test file `t1006-cat-file.sh`. While the technical solution works, Junio's comment indicates the approach may not fully capture the original testing intent. This suggests the patch may need revision to better balance the goals of unambiguous parsing with comprehensive testing of object name handling.

The discussion highlights Git's careful approach to test design - where even simple fixes are scrutinized to ensure they maintain or improve the test's original purpose rather than just making it pass. This is particularly relevant for `git cat-file` which is core plumbing used by many scripts and tools.
