This is the final patch in a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has maintainer approval and is ready for the 'next' branch.

The patch adds a new `GIT_REFERENCE_BACKEND` environment variable that mirrors the existing `extensions.refStorage` config option, allowing runtime specification of reference backends and their locations. This enables use cases like:
- Modifying reference backends for individual Git commands
- Specifying alternate reference directories during `git clone` and `git init`
- Supporting GitLab's large repository migration needs

Key technical aspects include:
- Environment variable overrides config when both are present
- Proper stub file creation in $GIT_DIR when using alternate reference locations
- Comprehensive test coverage verifying both config and environment variable paths
- Support for worktree operations with alternate reference backends

The implementation builds on previous patches in the series that established the URI parsing infrastructure and worktree reference resolution. Review feedback from multiple contributors (including Patrick Steinhardt, Karthik Nayak, and Eric Sunshine) has been incorporated, and the patch includes documentation updates.

This completes the series' goal of providing flexible reference storage configuration through multiple access methods (config, environment variable, and URI syntax). The changes are particularly valuable for GitLab's large repository management needs while maintaining compatibility with existing workflows.
