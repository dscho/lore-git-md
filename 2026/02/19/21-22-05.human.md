This is a maintainer ack for a refactoring patch series that reduces global state in Git's mailmap subsystem. Junio C Hamano has reviewed the two patches from Burak Kaan Karaçay (a GSoC 2026 applicant) and found them to be straightforward and well-executed.

The series is part of the ongoing `the_repository` removal effort. The first patch converts mailmap reading functions to take explicit repository parameters rather than implicitly using the global `the_repository`. The second patch eliminates two global configuration variables (`git_mailmap_file` and `git_mailmap_blob`), replacing them with on-demand config reading.

Junio notes that the changes are simpler than typical for this kind of refactoring since mailmap operations ultimately work with a simple string list rather than more complex repository state. He indicates the patches are ready to be queued for integration, signaling they've passed his review bar for merging into the main development branch. This represents a successful incremental step in the broader effort to reduce Git's reliance on global variables.
