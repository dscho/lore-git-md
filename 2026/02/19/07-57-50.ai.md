This is a bugfix patch in Patrick Steinhardt's series addressing ref iteration issues in bitmap and bisect functionality. The patch specifically fixes a BUG() that occurs when `pack.preferBitmapTips` is configured with an exact ref name rather than a ref hierarchy prefix.

The issue arises when `refs_for_each_ref_in()` attempts to trim the full refname when given an exact match, leaving an empty string. The fix follows the same pattern established in commit 10e8a9352b by treating all patterns as hierarchy matches (requiring trailing slashes) rather than allowing exact matches. This ensures consistent behavior with Git's ref matching conventions.

Key changes:
- Modifies `for_each_preferred_bitmap_tip()` to append a trailing slash if missing
- Updates documentation to clarify that patterns must be ref hierarchies
- Adds comprehensive tests in both t5310 and t5319 to verify the new behavior
- Maintains backward compatibility while fixing the edge case
