This is part of the ongoing fsmonitor feature series adding Linux support via inotify. The patch focuses on code deduplication between Unix platforms.

Paul Tarjan's patch consolidates the Unix domain socket compatibility checking logic that was previously duplicated between macOS and Linux implementations. The new shared `fsm-settings-unix.c` handles both cases, using the safer `xstrdup()` + `dirname()` approach from the macOS version while adding the "vfat" filesystem check. The changes touch build system files (Makefile, meson.build, CMakeLists.txt) to use this unified implementation for all non-Windows platforms.

Key technical details:
- Replaces platform-specific settings files with a shared Unix implementation
- Maintains the same remote filesystem and unsupported-filesystem checks (now including vfat)
- Uses more robust path handling by avoiding strbuf mutation with dirname()
- Updates all three build systems to reference the new unified file

This is the sixth version of the series, addressing feedback from Patrick Steinhardt's review of earlier iterations. The change is a straightforward cleanup that reduces duplication while maintaining the same functionality. The patch follows the series' pattern of incremental improvements to the fsmonitor implementation.
