This is a bugfix patch addressing submodule fetching behavior that incorrectly assumed all submodule remotes are named "origin". The patch adds a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes, fixing cases where `git fetch --recurse-submodules` would fail.

The implementation introduces a new helper in `builtin/submodule--helper.c` that determines the correct remote name for a submodule, falling back to "origin" if detection fails. The change affects `submodule.c` where the hardcoded "origin" assumption was removed in favor of using this new helper.

The patch includes comprehensive test coverage across multiple test files (t5526, t5572, and a new t7426) to verify the behavior with custom remote names, nested submodules, and edge cases. The solution addresses a 7-year-old NEEDSWORK comment and real-world use cases like the "repo" tool.
