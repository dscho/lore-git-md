Taylor Blau has proposed an RFC patch series introducing a new incremental MIDX/bitmap-based repacking strategy for large repositories, building on his prior work on MIDX compaction. The 14-part series aims to improve repacking by avoiding periodic full repacks in favor of geometric repacking of non-MIDX'd packs while maintaining MIDX layers.

The latest addition (patch 5/14) introduces a `--base` option for `git multi-pack-index write` and `compact`, allowing callers to specify which existing MIDX layer should serve as the base for new incremental writes. This provides more flexibility than the current behavior where operations automatically select the immediate parent layer. The patch includes thorough tests and maintains backward compatibility, requiring `--checksum-only` for certain write modes to preserve chain invariants.

Earlier patches in the series lay groundwork with infrastructure improvements: refactoring MIDX file tracking (patch 1), checksum handling (patch 3), and ODB source tracking (patch 6), plus adding utility functions like `strvec_init_alloc` (patch 7). Patch 4 introduced the `--checksum-only` flag for atomic MIDX layer assembly. The series touches core MIDX machinery and repack geometry calculations while preparing for future bitmap optimizations.

As an RFC, the proposal awaits feedback on its overall design and implementation choices. Given Taylor's expertise in the pack subsystem and the series' connection to ongoing repack machinery improvements, it will likely attract review from other pack/MIDX specialists like Patrick Steinhardt and Derrick Stolee. The preparatory patches appear straightforward, while the core geometric repacking logic will need careful evaluation.
