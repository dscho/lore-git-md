Taylor Blau has proposed an RFC series introducing incremental MIDX/bitmap-based repacking, building on his previous work on MIDX compaction. The 14-patch series aims to improve large repository maintenance by enabling geometric repacking while maintaining MIDX layer structure, with an optional append-only mode. 

Junio Hamano has contributed two infrastructure improvements to support this work. First, he refactored MIDX string handling to use `string_list` instead of manual array management. Now he's added a small but useful utility function - `strvec_init_alloc()` - that allows pre-allocating string vectors when the size is known upfront. While this creates a minor inconsistency with the existing `strvec_init()` optimization for empty vectors, Junio appears satisfied with the tradeoff.

The series remains in RFC status, awaiting broader feedback on the approach. Key open questions include default mode recommendations, flag interactions, and test coverage adequacy. The infrastructure improvements from Junio suggest the technical direction is sound, though the core repacking strategy itself still needs review from domain experts like Patrick Steinhardt (repack machinery) and Derrick Stolee (MIDX).
