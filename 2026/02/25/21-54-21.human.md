This is a discussion thread about `git log`'s decoration behavior, specifically how `--decorate=no` interacts with format placeholders like `%d`. The conversation builds on earlier technical analysis by Marc Branchaud and Junio C Hamano.

Alejandro Colomar weighs in to support Marc's proposal to make `--decorate=no` consistently disable all ref decorations, including those from `%d` format placeholders. He argues the current behavior (where `--decorate=no` acts like `--decorate=short` for `%d`) is unintuitive and likely unused in practice. The thread has identified documentation gaps around how decoration options interact with custom formats.

The discussion remains constructive, with Junio previously favoring a more conservative approach that preserves format string stability. The key open question is whether to treat the current behavior as a bug (Marc and Alejandro's view) or a design choice to be worked around (Junio's initial position). Either solution will require documentation updates to clarify the relationship between `--decorate` options and format placeholders.
