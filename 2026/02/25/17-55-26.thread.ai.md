Thread summary:

Alejandro Colomar proposed modifying `git log`'s `%d` format specifier in `pretty.c` to respect the `--decorate` option, aiming to align its behavior with other format specifiers like `%h` that honor related configurations. The current behavior shows reference decorations unconditionally, even with `--no-decorate`, which breaks consistency in custom formats.

Junio C Hamano firmly rejected changing `%d`'s behavior due to backward compatibility concerns with existing scripts that rely on the current unconditional output. Instead, he proposed introducing a new `%(decorate:optional=yes)` placeholder that would respect the `--decorate` flag, allowing new code to opt into decoration control without breaking existing usage. This maintains the project's principle of preserving backward compatibility while enabling new functionality through additive changes.

The discussion involves core formatting logic in `pretty.c` and highlights the careful balance between evolving functionality and maintaining script compatibility. Junio's position as maintainer makes his rejection of the behavior change authoritative, while his alternative proposal provides a path forward for the requested functionality. The implementation would need to carefully introduce the new placeholder while ensuring all existing format string behaviors remain unchanged.
