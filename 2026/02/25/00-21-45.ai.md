This is patch 10/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The series builds on previous MIDX compaction work to improve repacking in large repositories.

The current patch modifies `pack_geometry_init()` to handle MIDX-aware repacking by:
1. Adding logic to optionally restrict repacking candidates to only packs in the tip MIDX layer when a threshold is configured
2. Tracking whether any tip-layer packs were included in the repack (`midx_tip_rewritten`), which will be used later to update the MIDX chain

Key technical details:
- New fields added to `struct pack_geometry`: `midx_layer_threshold`, `midx_layer_threshold_set`, and `midx_tip_rewritten`
- Uses the `midx_layer_contains_pack()` helper from patch 7/14 to check pack membership
- Maintains backward compatibility when MIDX thresholds aren't set
- The threshold behavior: if tip layer has fewer packs than threshold, exclude them entirely; otherwise only repack packs from that layer

This is infrastructure work preparing for the actual geometric repacking logic to come in later patches. The changes are focused and mechanical, continuing the pattern of the series. As an RFC, it's likely to get feedback on the threshold approach and whether the tracking of rewritten packs could be handled differently.
