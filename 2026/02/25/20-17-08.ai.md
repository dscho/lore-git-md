This is a bugfix patch addressing a memory leak in the Linux fsmonitor daemon implementation. It's part of a larger series (v6 02/10) bringing Linux support for filesystem monitoring via inotify.

The patch fixes a specific issue where the `state.cookies` hashmap, used to track filesystem event cookies for rename detection, wasn't being properly cleaned up when the daemon shuts down. Paul Tarjan adds a missing `hashmap_clear()` call in the cleanup path of `fsmonitor_run_daemon()`, ensuring all allocated memory is freed.

This is a straightforward fix that follows the pattern established in previous iterations of the series. The change is minimal (just one line added) but important for correct resource management. The patch builds on extensive prior review of the Linux fsmonitor implementation, which has already addressed more complex issues like race conditions and event ordering.

The fix demonstrates good attention to detail - while the leak was likely small in practice (the hashmap typically contains few entries), proper cleanup is particularly important for long-running daemon processes like fsmonitor. The patch maintains the series' high standard for memory safety and follows the established pattern of thorough resource cleanup seen in the surrounding code.
