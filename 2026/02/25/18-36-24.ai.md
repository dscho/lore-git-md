This is a follow-up discussion about Git's log formatting behavior, specifically around the `%d` format specifier and `--decorate` option. Alejandro Colomar responds to Junio Hamano's rejection of changing `%d`'s unconditional decoration output, proposing an alternative to Junio's suggested `%(decorate:optional=yes)` solution.

Alejandro suggests extending the `--decorate` option itself with a new 'never' value that would suppress decorations even from `%d`, rather than introducing a new format placeholder. This maintains backward compatibility while providing a more direct way to control all decoration output through the existing option mechanism.

The discussion remains focused on finding a solution that preserves existing behavior while allowing new control over decorations. Junio's position as maintainer makes his preference for additive changes (new syntax rather than modifying existing behavior) the likely path forward, but Alejandro's counter-proposal offers an alternative approach that might simplify the user interface. The thread shows careful consideration of both backward compatibility and user experience in Git's formatting system.
