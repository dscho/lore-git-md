This is the final patch in a series adding Linux fsmonitor support, focusing on process management and reliability improvements for the fsmonitor daemon. The patch addresses two key issues that could cause hangs in CI environments:

1. **File descriptor inheritance**: The daemon now closes all inherited file descriptors above stderr (using the new `close_fd_above_stderr` flag) to prevent holding open pipes from parent processes like test harnesses. This ensures the parent can properly detect EOF.

2. **Process group handling**: When running detached, the daemon creates a new session via `setsid()` to avoid being tied to the parent's process group. This prevents shells with job control (like bash) from waiting indefinitely for the daemon to exit.

The patch also adds a 30-second timeout to the daemon stop command and improves test reliability by:
- Adding a start timeout to test commands
- Properly handling process groups in test helper functions
- Removing an overly aggressive 30-minute CI timeout that's no longer needed

These changes complete the Linux fsmonitor implementation by ensuring robust process management across different shell environments and CI systems. The work builds on extensive prior review and testing of the fsmonitor daemon's core functionality.
