This is the final patch in a series adding Linux fsmonitor support, focusing on process management improvements for the daemon. The patch addresses two key issues that could cause hangs in CI/test environments:

1. **File descriptor inheritance**: The daemon now closes all inherited file descriptors above stderr (using the new `close_fd_above_stderr` flag) to prevent holding open pipes from parent processes. This fixes cases where test harnesses would hang waiting for EOF on pipes the daemon unintentionally kept open.

2. **Process group handling**: When running detached, the daemon creates a new session via `setsid()` to avoid being tied to the parent's process group. This prevents shells with job control (like bash) from waiting indefinitely for the daemon when they only meant to wait for the spawning command.

The patch also adds a 30-second timeout to the daemon shutdown sequence and includes related test improvements. These changes complete the Linux fsmonitor implementation by ensuring reliable process management, particularly in CI environments where these edge cases were causing test failures.

The implementation looks solid, with careful attention to cross-platform compatibility (Windows console detachment, Unix session management) and thorough test coverage. This represents the culmination of a multi-version effort to bring production-ready fsmonitor support to Linux.
