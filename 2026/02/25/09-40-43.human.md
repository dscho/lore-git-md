This is part of the ref storage backend abstraction effort, specifically the 3rd patch in the 9th iteration of a 6-patch series that's now approved for integration. The patch moves stub creation and deletion logic for reference backends from the reftable-specific implementation to the generic refs layer.

The change ensures all non-files backends (like reftable) properly create and clean up stub files (HEAD and refs/ directories) that identify a directory as a Git repository. This prepares for upcoming work supporting alternate reference backend locations. The implementation handles both creation (with proper permissions) and deletion of these stubs, while carefully avoiding duplicate cleanup in the files backend case.

The patch has been thoroughly reviewed through nine iterations, with input from multiple contributors including Patrick Steinhardt, Toon Claes, and Eric Sunshine. It represents a small but important piece of the larger ref backend abstraction work that enables zero-downtime migrations between storage formats.
