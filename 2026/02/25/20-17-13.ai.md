This is the Linux implementation of Git's filesystem monitoring (fsmonitor) daemon, bringing Linux support to parity with existing Windows and macOS backends. The patch implements inotify-based monitoring for faster status operations by watching filesystem events rather than performing full directory scans.

Key technical aspects:
- Uses inotify with recursive directory watching via inotify_init1(O_NONBLOCK)
- Handles directory renames through IN_MOVED_FROM/TO event cookies
- Maintains bidirectional watch descriptor <-> path mappings using hashmap
- Detects remote filesystems (NFS/SMB) via statfs() unless explicitly allowed
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote
- Adds build configuration via FSMONITOR_DAEMON_BACKEND=linux
- Requires pthreads and Unix domain socket support
- Documentation updates note Linux-specific caveats about inotify watch limits
- Adds new files: fsm-listen-linux.c (main implementation), fsm-health-linux.c (stubs), fsm-path-utils-linux.c (filesystem detection)
- Build system updates for both Makefile and CMake
- Includes integrated meson build system support

The implementation appears thorough and well-considered, with careful attention to edge cases like directory renames, remote filesystems, and inotify limits. The patch builds on prior work by Eric DeCosta and Marziyeh Esipreh, and has undergone multiple rounds of review addressing technical concerns around race conditions, memory leaks, and portability. This is part of a larger effort to provide consistent fsmonitor behavior across all major platforms.
