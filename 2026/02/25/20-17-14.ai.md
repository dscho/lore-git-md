This is a test patch for the Linux fsmonitor implementation, part of the ongoing effort to bring filesystem monitoring support to Linux alongside existing Windows and macOS backends. The patch adds two key test scenarios:

1. A smoke test that verifies the filesystem actually delivers inotify events to the daemon, skipping the entire test file if event delivery fails (which can happen on certain filesystems like overlayfs with older kernels). This prevents subsequent tests from failing due to fundamental platform limitations.

2. A stress test for rapid nested directory creation that exercises race conditions in the daemon's event handling, specifically around EEXIST errors that can occur when directory watches are added concurrently during recursive scanning and event processing. This catches crashes that appeared in earlier versions of the implementation.

The patch also includes several reliability improvements to the test infrastructure:
- Adds generous timeouts (30 minutes) for fsmonitor tests in meson builds to prevent CI hangs
- Improves process cleanup handling in the test harness
- Adds platform-specific process group handling for non-MINGW systems
- Includes a new helper function (`verify_fsmonitor_works`) to validate basic fsmonitor functionality before proceeding with tests

This is patch 8/10 in the v6 series, building on previous iterations that addressed memory leaks, race conditions, and portability issues. The tests specifically target edge cases that were problematic in earlier versions, providing validation for the stabilized implementation now in Junio's 'seen' branch.
