This is the final patch in a 6-part series implementing reference storage backend selection, now approved for integration after nine iterations. The series enables zero-downtime migrations between reference backends (files<->reftable) with three configuration mechanisms: config`, environment variable, and URI-based control.

The patch adds `GIT_REFERENCE_BACKEND` environment variable support, completing the trio of configuration methods. It mirrors the existing `extensions.refStorage` config but takes precedence, allowing per-command backend overrides. The implementation handles stub creation in `$GIT_DIR` when using alternate reference locations and properly propagates the setting during repository initialization and cloning.

Key technical aspects include:
- Environment variable parsing in `setup.c` that overrides config settings
- Stub management logic in `refs.c` for alternate reference directories
- Comprehensive test coverage of clone/init, and worktree scenarios
- Documentation updates in `git.adoc`

The patch builds on prior work in the series, particularly the URI syntax support (`<format>://<payload>`) and stub management infrastructure. It maintains consistency with the established precedence rules where environment variables override config settings.

Review feedback from Jean-Noël Avila (documentation) and others has been incorporated. The implementation is now fully approved with all substantive concerns resolved through nine iterations, demonstrating the project's attention to detail in both test validation and documentation presentation.
