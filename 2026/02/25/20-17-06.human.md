This is the sixth iteration of a feature patch adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The patch series has undergone extensive review across five previous versions, with all major technical concerns addressed. Key improvements in v6 include splitting the monolithic commit into 10 focused patches, deduplicating IPC and settings logic shared with macOS, and fixing several edge cases around process handling and test reliability. The implementation uses inotify rather than fanotify since fanotify requires elevated privileges. It handles directory renames via inotify's cookie mechanism and includes remote filesystem detection via statfs().

Notable changes in this version include:
- Fixed test hangs on Fedora CI by improving process group handling
- Added proper cleanup of inherited file descriptors
- Implemented a 30-second timeout for daemon shutdown
- Added helpful error messages for inotify watch limits
- Improved portability with sysconf(_SC_OPEN_MAX) instead of hardcoded FD limits

The implementation is stable in Junio's 'seen' branch with production validation from Paul Tarjan. Patrick Steinhardt has identified a few remaining issues (race conditions in watch registration and small memory leaks) but considers them non-blocking. This appears ready for final submission once the last CI test hang is resolved.
