This is part 3 of Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The patch refactors how MIDX`keep_hashes` are handled during MIDX file cleanup operations.

The change replaces manual array management of MIDX checksums with a `strvec` structure, which provides a more ergonomic interface for maintaining the checksum list while preserving ordering requirements. The ordering matters because these checksums determine the contents of the `multi-pack-index-chain` file when using `--incremental`.

The patch touches two main areas: the MIDX writing logic in `midx-write.c` and MIDX cleanup functions in `midx.c`. It eliminates the need to pass separate `hashes_nr` parameters by encapsulating that information in the `strvec` structure. The changes are mechanical but improve code clarity and reduce error-prone manual array management.

This is preparatory work for the larger incremental repacking strategy, building on the ODB source tracking changes from patch 6/14 and the strvec utility added in patch 7/14. The implementation looks clean and focused, with thorough updates to both the writing and cleanup paths. Given Taylor's expertise in the pack/MIDX subsystem, this change is likely to be uncontroversial.
