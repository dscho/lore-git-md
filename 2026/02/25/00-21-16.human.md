This is patch 5/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The series aims to improve repacking in large repositories by avoiding periodic all-into-one repacks through geometric repacking of non-MIDX'd packs.

This particular patch adds a `--base` option to both `git multi-pack-index write` and `compact` subcommands, allowing callers to specify which existing MIDX layer should serve as the base for new incremental writes. The special value "none" can be used to create a root layer with no parent. For the `write` subcommand, this requires the new `--checksum-only` flag (introduced in patch 4) to ensure atomic chain assembly.

The change provides flexibility for the incremental repacking machinery to write layers based on intermediate ancestors rather than always appending to the tip. This will be useful when replacing bottommost layers in the chain. The patch includes thorough documentation updates and test coverage for both valid and invalid cases.

As an RFC patch from Taylor Blau (a recognized expert in Git's pack subsystem), this appears to be a well-considered addition to the MIDX machinery. The implementation is clean and maintains backward compatibility while enabling new functionality needed for the larger repacking strategy. The tests verify both happy paths and error conditions, suggesting this is production-ready code despite being marked RFC.
