This is part of the ref storage backend abstraction effort, specifically patch 3/6 in the ninth iteration of a series implementing zero-downtime migrations between reference storage backends (files<->reftable). The patch moves stub creation and deletion logic for repository identification (HEAD and refs/ directories) from backend-specific code to the generic refs layer.

The key changes are:
1. Moves `refs_create_refdir_stubs()` calls from reftable-backend.c to the generic refs.c, applying them to all non-files backends
2. Adds parallel stub deletion logic in refs.c for non-files backends
3. Modifies the files backend to skip the generic stub deletion since it handles cleanup differently via packed-refs

This refactoring prepares for upcoming work on alternate reference backend locations by centralizing the stub management that ensures repositories remain recognizable during backend transitions. The changes maintain existing behavior while making the code more maintainable and consistent across backends.

The patch shows careful attention to error handling and maintains the series' high quality standards, with clean separation of concerns between the generic and backend-specific layers. It follows the established pattern of this well-reviewed series, which has already received maintainer approval for inclusion.
