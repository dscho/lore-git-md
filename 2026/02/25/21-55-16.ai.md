This is a bugfix patch addressing submodule fetching behavior that incorrectly assumed all submodule remotes are named "origin". The patch adds a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes, fixing cases where `git fetch --recurse-submodules` would fail.

The implementation introduces a new `get-default-remote` subcommand in `builtin/submodule--helper.c` that determines the correct remote name for a submodule, falling back to "origin" if detection fails. The submodule fetching logic in `submodule.c` is updated to use this helper instead of hardcoding "origin". The change includes comprehensive test coverage across multiple test files (t5526, t5572, and new test file t7426) to verify behavior with custom remote names, nested submodules, and edge cases.

Key technical details:
- New helper command `get-default-remote` in builtin/submodule--helper.c
- Changes to submodule.c to use the new helper instead of hardcoded "origin"
- Test coverage across t5526-fetch-submodules.sh, t5572-pull-submodule.sh, and new test file t7426-submodule-get-default-remote.sh
- Fixes 7-year-old NEEDSWORK comment from commit be76c21282
- Maintains backward compatibility by falling back to "origin" if default remote detection fails
