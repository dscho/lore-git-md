This is a feature patch series implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The series represents the sixth iteration of this work, addressing feedback from Patrick Steinhardt and fixing newly discovered issues.

The implementation uses inotify rather than fanotify due to privilege requirements, with careful handling of directory watches and renames. Key technical aspects include:
- Recursive directory watching with inotify_init1(O_NONBLOCK)
- Bidirectional watch descriptor <-> path mappings using hashmap
- Special handling for directory renames via IN_MOVED_FROM/TO event cookies
- Remote filesystem detection via statfs()
- Fallback IPC socket location when .git is remote
- Build configuration via FSMONITOR_DAEMON_BACKEND=linux

The series also fixes two memory leaks in the platform-independent daemon code and deduplicates IPC/settings logic between macOS and Linux implementations. Changes since v5 include splitting into 10 focused patches, adding meson build support, fixing test hangs, and improving error handling.

The implementation has undergone extensive review across six versions and is now in Junio's 'seen' branch. While there are minor memory leaks (512-byte during daemon init, 40-byte in IPC worker thread), these are considered non-blocking. The primary remaining issue is a test hang in CI that Patrick Steinhardt is investigating.

This builds on prior work by Eric DeCosta and Marziyeh Esipreh, bringing Linux fsmonitor support to production readiness. The series touches multiple subsystems including fsmonitor, compat/, run-command, and the test suite, with changes to both core functionality and build system integration.
