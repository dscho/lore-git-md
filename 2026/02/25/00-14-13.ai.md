This is the second patch in a two-part series implementing configurable commit list formatting for `git format-patch` cover letters. The patch adds a `format.commitListFormat` configuration option that persists the formatting preference set by the command-line `--cover-letter-format` option from the first patch.

The current email shows the author (Mirko Faina) responding to Junio C Hamano's detailed review feedback. Key points addressed:

1. Memory management - Junio noted a potential leak when overriding config values, and the author agrees to use the `FREE_AND_NULL` pattern seen elsewhere in the codebase.

2. Line length/style - The author will fix an overly long conditional line.

3. Validation timing - There's discussion about when to validate the format string, with the author preferring early validation before file creation rather than waiting until the cover letter is generated.

4. Configuration precedence - Junio suggests restructuring the config/option handling to follow Git's standard pattern: built-in default -> config override -> command-line override. The author agrees to rework this flow.

The patch remains architecturally sound (validated earlier by Jeff King) but needs polishing in these implementation details. The author is actively addressing the remaining review feedback around code organization and test coverage.
