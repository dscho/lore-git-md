This is patch 12/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The patch implements the core logic for incremental MIDX repacking as part of geometric repacking.

The key addition is `write_midx_incremental()`, which builds and maintains a MIDX chain by:
1. Writing a new MIDX layer containing newly created packs and any surviving packs from rewritten tip layers
2. Compacting adjacent MIDX layers when their combined object count exceeds half the next layer's count (controlled by `repack.midxSplitFactor`)
3. Atomically updating the MIDX chain file after all steps complete

The implementation introduces a `midx_compaction_step` struct to represent each operation (copy, write, or compact) and executes them in sequence. It handles locking, atomic updates, and cleanup of unused MIDX layers. The strategy maintains backward compatibility while enabling more efficient repacking of large repositories by preserving the MIDX layer structure.

This is infrastructure workhorse code that will be used by the geometric repacking logic in later patches. The patch touches MIDX machinery, pack geometry handling, and command-line parsing, adding about 470 lines of carefully structured C code with thorough error handling. It builds on the MIDX infrastructure changes from earlier patches in the series (particularly the `--checksum-only` and `--base` options).
