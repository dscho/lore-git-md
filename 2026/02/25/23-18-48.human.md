Maintainer approval for `status.compareBranches` feature. This is the final review of Harald Nordgren's long-running patch series (28 iterations over two months) to make `git status` branch comparisons configurable. Junio Hamano confirms the implementation is ready for merging, though he suggests some minor code organization improvements around advice message handling and test isolation.

The feature introduces a new `status.compareBranches` config option that takes a space-separated list of branch specifiers (`@{upstream}` and/or `@{push}`), with `@{upstream}` remaining the default for backward compatibility. The implementation includes deduplication of comparisons and proper handling of triangular workflows, with extensive test coverage in t6040-tracking-info.sh.

While approving the overall approach, Junio notes some stylistic concerns: the warning message line length exceeds Git's standard 80-column limit, and the advice flag handling in format_branch_comparison() could be clearer. He also suggests making the test cases more self-contained by using test_config rather than global setup/teardown. These are minor polish items that don't block merging.

This represents a significant achievement for a first-time contributor navigating Git's mailing list workflow. The feature provides a clean solution to a common user request while maintaining backward compatibility and following Jeff King's earlier suggestion to focus on the core `@{upstream}`/`@{push}` cases rather than attempting to handle arbitrary branch names. With Junio's approval, the patches are now cleared for inclusion in the next release cycle.
