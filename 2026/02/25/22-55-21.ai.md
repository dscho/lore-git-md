This is a follow-up discussion in an ongoing thread about configurable cover letter formatting for `git format-patch`. The thread has evolved through multiple iterations with input from Jeff King (Peff) and Junio C Hamano, focusing on both the technical implementation and user-facing design of the patch numbering format customization.

Mirko Faina responds to Peff's suggestion about allowing customization of the patch numbering format (e.g., "[1/5]") in cover letters. Peff had outlined technical requirements for this feature, including new placeholders like `%(count)` and `%(total)`, extensions to `pretty_print_context`, and handling of width formatting, while questioning whether the complexity would justify the user benefit.

The author indicates willingness to implement this additional functionality ("I can give it a try"), suggesting the series may expand to include patch numbering customization alongside the existing cover letter format controls. This would build upon the already-reviewed format string handling that includes deferred default values, validation, and special-case processing for "shortlog" output.

Key technical considerations still open include whether to require a "log:" prefix for format strings, validation rules should apply to extended format strings, and how to handle default value timing. The implementation would need to extend `builtin/log.c` to support the new numbering placeholders while maintaining the robustness of the existing format processing.
