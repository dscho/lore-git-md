This thread explores how to make `git log`'s decoration behavior more consistent between the `--decorate` option and the `%d` format specifier. Alejandro Colomar initially proposed modifying `%d` to respect `--decorate`, which Junio Hamano initially rejected on backward-compatibility grounds, suggesting instead a new format placeholder. The discussion then shifted to Alejandro's alternative idea of extending `--decorate` with a 'never' value to suppress decorations even from `%d`, which Junio has now endorsed as a cleaner solution that works through existing mechanisms.

Marc Branchaud has now joined the conversation with valuable observations about current behavior. He notes that while `--decorate=no` doesn't currently affect `%d`, there's already some interaction between `--decorate` values and formatting - the `short`/`full` variants change how `%d` displays ref prefixes. He also identifies what may be a bug: `--decorate=auto` doesn't suppress `%d` when output is piped to a file as the man page suggests it should. Marc offers two paths forward - either make `--decorate=no` affect all decoration-related output (including the proposed new syntax) or introduce the separate 'never' value that Alejandro suggested, though he notes potential confusion between 'no' and 'never'.

The thread has converged on a solution that maintains backward compatibility while providing the requested control, with Junio's approval indicating this is likely be the direction taken. The discussion now focuses on refining the exact behavior and addressing current inconsistencies Marc has highlighted. The core challenge remains balancing intuitive control of decorations with preserving existing behavior that scripts might rely on.
