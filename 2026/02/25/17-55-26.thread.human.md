Alejandro Colomar proposed making `git log`'s `%d` format specifier respect the `--decorate` flag, similar to how other format specifiers like `%h` follow related configurations. Currently, `%d` always shows reference decorations regardless of the `--decorate` setting, which breaks consistency in some custom formats.

Junio Hamano, the Git maintainer, responded firmly that changing `%d`'s behavior would break backward compatibility for existing scripts that rely on its current unconditional output. Instead, he suggested a compromise: introducing a new `%(decorate:optional=yes)` placeholder that would honor the `--decorate` flag. This approach allows users who need decoration control to get it without disrupting existing usage.

The discussion highlights Git's careful balance between maintaining compatibility and evolving functionality. While the original proposal won't be implemented as-is, Junio's alternative provides a path forward that respects both existing users and those seeking more flexible formatting options. The change would need to be implemented carefully in `pretty.c` to maintain all current behaviors while adding the new placeholder.
