This is part of the ref backend abstraction effort, specifically enabling reference storage configuration via URI syntax in the `extensions.refStorage` config. The patch is the fifth in a v9 series that has already received maintainer approval for integration.

The patch extends the `extensions.refStorage` config to support URI syntax (`<format>://<payload>`) for specifying both the reference backend and its location. This allows storing references outside the default `$GIT_DIR`, with the payload being a filesystem path for the files/reftable backends. The implementation handles worktree references by storing them under the alternate path (`$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>`) while maintaining stubs in the original location to ensure Git directory recognition.

Key technical components include:
- URI parsing infrastructure in `setup.c` with format/payload separation
- Worktree reference path computation via new helper functions
- Centralized stub management for directory structure
- Documentation updates explaining the URI syntax
- Comprehensive tests covering validation, migration scenarios, and worktree handling

The patch includes a TODO noting the current limitation of passing `gitdir` instead of `struct worktree*` to backends due to repository initialization ordering constraints.
