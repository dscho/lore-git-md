This thread explores adding worktree path detection to the experimental `git repo info` command, a Google Summer of Code project. The initial patch implemented a `path.in-worktree` field (now renamed to `path.is-in-worktree` based on feedback) that reports whether the current directory is inside the worktree, avoiding use of the `the_repository` global by using `is_inside_dir()` with the repository's worktree path.

Discussion has centered on whether this functionality belongs in `git repo info` at all, since it relates more to current directory state than repository information. The author has thoughtfully engaged with this design question while also exploring technical implementation details - including whether to adapt the existing `is_inside_work_tree()` function (which uses a static cache) rather than reimplementing its logic. Performance considerations appear manageable, but the broader API design questions remain open.
