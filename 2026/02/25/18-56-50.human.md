This is a follow-up in the ongoing discussion about controlling reference decorations in `git log` output. Junio C Hamano responds positively to Alejandro Colomar's proposal to extend the `--decorate` option with a 'never' value rather than introducing new format syntax.

Junio expresses clear preference for Alejandro's approach of adding a 'never' value to the existing `--decorate` option, which would suppress decorations even from the `%d` format specifier. This solution maintains backward compatibility while providing the requested control over decoration output, avoiding the need for new format placeholders.

The exchange shows the project's typical pattern of preferring to extend existing mechanisms rather than add new syntax when possible. Junio's quick endorsement suggests this solution is likely to move forward, as it aligns with Git's compatibility principles while cleanly solving the original problem. The thread demonstrates how Git's maintainer evaluates proposals based on both technical merit and their fit with the project's design philosophy.
