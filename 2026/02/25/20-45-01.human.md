This is a follow-up in the UTF-8 alias support thread, addressing memory leaks found in the alias listing functionality. Junio Hamano confirms Jacob Keller's memory leak fix for `list_cmds()` (changing `string_list_clear(&list, 0)` to `free_util=1`) and identifies a second leak in `list_cmds_by_config()` where `remove_duplicates()` also needs to free the util pointers.

The patch shows Junio's proposed fix for both locations, which will be incorporated into the next version of the series. This is part of the final polish before merging the UTF-8 alias support into `next`. The thread has already addressed several other issues (empty subsections, documentation formatting) and this memory leak was one of the last remaining technical concerns.

The changes are straightforward - just two lines to ensure proper cleanup of allocated memory when listing aliases. Junio notes this should allow the series to be finalized soon, indicating the core functionality is otherwise working as intended.
