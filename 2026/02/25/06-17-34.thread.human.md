Amisha Chhajed has proposed a GSoC project to improve disk space recovery in partial clones, particularly for files outside sparse-checkout cones. Building on her prior work on sparse-checkout optimizations, the proposal explores integrating cleanup with `git gc` and `git maintenance`, with open questions around safe object removal criteria and non-cone mode strategies.

Derrick Stolee, an expert in large-repository performance, has weighed in with important technical guidance. He suggests focusing cleanup efforts on old blobs from previous checkouts rather than just spatially outside the current cone, noting this temporal approach may be more effective. Stolee also cautions about unintended consequences - some tools like VS Code's background operations might automatically refetch deleted objects, trading disk savings for increased network usage. His feedback positions this as an extension of Git's existing object lifecycle management rather than a sparse-checkout-specific feature, recommending integration with the current `git gc` infrastructure.

The discussion has evolved from its initial spatial focus (cone vs non-cone modes) to consider temporal aspects of object usefulness, with Stolee's input helping shape the project's technical direction.
