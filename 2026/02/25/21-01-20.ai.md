This is a bugfix patch in the Linux fsmonitor series, addressing a memory leak in the filesystem monitoring daemon. The patch fixes an issue where a khash table (`shown`) used for tracking duplicate events wasn't being freed when the daemon sent trivial responses to clients, causing a memory leak.

The change is straightforward and well-explained: it moves the cleanup of the hash table to a shared cleanup path and ensures it's safely called in all cases by using `kh_destroy_str()` (which handles NULL) instead of `kh_release_str()`. Junio Hamano's review confirms the fix is correct and praises the clarity of the patch.

This is part of the sixth iteration of the Linux fsmonitor implementation, which has undergone extensive review. The series is now in its final stages, with this patch addressing one of the last remaining memory management issues. The change is small (5 lines modified) but important for correct operation of the long-running daemon process.
