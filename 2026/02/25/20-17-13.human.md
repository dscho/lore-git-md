This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The patch introduces a new inotify-based listener that handles directory watches, rename tracking, and remote filesystem detection. Key technical aspects include:
- Uses inotify with recursive directory watching via inotify_init1(O_NONBLOCK)
- Tracks directory renames using inotify's cookie mechanism
- Detects remote filesystems (NFS/SMB) via statfs()
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote
- Includes documentation about inotify watch limits and configuration

This is patch 7/10 in a series that has undergone six iterations of review, addressing feedback around race conditions, memory leaks, and portability. The implementation is now stable in Junio's 'seen' branch with all major technical concerns resolved. The patch touches multiple subsystems including fsmonitor, compat/, and the test suite.

The work builds on prior contributions from Eric DeCosta and Marziyeh Esipreh, bringing Linux fsmonitor support to production-ready state. The implementation is well-crafted with thorough error handling and appears ready for inclusion.
