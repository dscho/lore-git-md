This is patch 11/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The series aims to improve repacking in large repositories through geometric repacking of non-MIDX'd packs while maintaining MIDX layer structure.

This particular change converts the `--write-midx` flag from a simple boolean to an `OPT_CALLBACK` that can accept an optional mode argument. It introduces an enum with `REPACK_WRITE_MIDX_NONE` and `REPACK_WRITE_MIDX_DEFAULT` states, preserving existing behavior when no argument is given. The patch extracts `repack_write_midx()` as a dispatcher function that will select the appropriate MIDX-writing implementations based on the mode.

Key technical details:
- Adds new enum `repack_write_midx_mode` with two initial states
- Implements `option_parse_write_midx()` callback for the new option type
- Maintains backward compatibility by keeping `-m` as a hidden alias
- Updates all boolean checks to use the new enum values
- Extracts the existing implementation into `write_midx_included_packs()`
- Adds `repack_write_midx()` as the new dispatch function

The change is primarily infrastructure work to support the incremental MIDX functionality coming in later patches. It touches command-line parsing, option handling, and MIDX writing logic while maintaining the same external interface for now. The patch follows the series' pattern of careful refactoring to enable new features without breaking existing behavior.
