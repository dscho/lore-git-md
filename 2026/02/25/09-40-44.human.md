This is part 4 of a 6-patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has gone through nine iterations and is now approved for integration into Git's 'next' branch.

The patch introduces payload handling for reference backends, preparing for upcoming URI-based configuration of alternate reference storage. It adds a new `refs_compute_filesystem_location()` function that parses gitdir and payload to determine reference storage paths, handling both main and worktree cases. The change modifies the initialization functions of both files and reftable backends to accept and process this payload, though no callers pass payloads yet (that will come in later patches).

The implementation is clean and focused, with clear separation between path computation and backend initialization. The files backend uses the computed paths directly, while the reftable backend maintains its existing worktree handling but now through the centralized path computation. The packed backend explicitly ignores payloads since packed-refs always lives in the common dir.

This is a well-constructed plumbing change that lays groundwork for the URI-based configuration coming in subsequent patches. The commit message clearly explains the transitional nature of this change (no current callers pass payloads) and the relationship to future work. The patch has already received thorough review across nine iterations, with sign-offs from key contributors including Patrick Steinhardt.
