This is the final patch in a 6-part series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has gone through nine iterations and is now approved for integration into Git's 'next' branch.

The patch adds a new `GIT_REFERENCE_BACKEND` environment variable that mirrors the functionality of the `extensions.refStorage` config option added in previous patches. This allows dynamically specifying the reference backend and location for individual Git commands, similar to how `GIT_OBJECT_DIRECTORY` works for object storage. The environment variable takes precedence over the config setting.

Key technical aspects:
- The variable uses the same URI syntax (`<format>://<payload>`) as the config option
- Properly handles repository initialization and cloning with alternate reference directories
- Maintains stub files in the repository's $GIT_DIR when using alternate storage
- Includes comprehensive tests covering both config and environment variable usage

The implementation is thorough, with careful attention to edge cases and test coverage. It completes the series' goal of providing three configuration mechanisms (config, environment variable, and URI syntax) for reference backend selection, primarily serving GitLab's migration needs. The patch represents the culmination of extensive review and refinement over nine versions, with all substantive concerns now addressed.
