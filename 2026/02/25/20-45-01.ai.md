This is a follow-up in the UTF-8 alias subsections thread, addressing a memory leak issue in the alias listing functionality. The patch series implementing UTF-8 support for config subsections is currently in `next` at v7, with these being final fixes before merging.

Junio Hamano confirms Jacob Keller's diagnosis of a memory leak in `git.c` where alias values stored in string list util fields weren't being freed when clearing the string list. He notes the fix (changing `string_list_clear(&list, 0)` to `string_list_clear(&list, 1)`) is correct but identifies a second location in `help.c`'s `list_cmds_by_config()` that needs the same treatment when removing duplicates.

The proposed diff addresses both locations:
1. In `git.c` for the main alias listing path
2. In `help.c` for the config-based command listing that also uses alias utilities

This completes the memory leak fixes identified during review, with Junio indicating these should be the final small issues to address before the series can be fully merged. The changes are straightforward - just flipping the `free_util` parameter in two existing string list cleanup calls - but important for correctness given the alias values are now dynamically allocated strings stored in the util fields.
