This is the final implementation patch for the configurable branch comparison feature in `git status` (status.compareBranches), following a 28-iteration review process. The patch adds support for showing comparisons against both upstream and push branches simultaneously, addressing triangular workflow needs where these differ.

The implementation introduces a new `status.compareBranches` config option that accepts space-separated values (`@{upstream}` and `@{push}`). It maintains backward compatibility by defaulting to `@{upstream}` behavior when unset. The feature intelligently shows context-appropriate advice messages - pull advice for upstream comparisons, push advice for push comparisons, and divergence advice when relevant.

The patch includes extensive test coverage (337 lines in t6040-tracking-info.sh) demonstrating various scenarios: duplicate branch handling, ordered comparisons, remapped refspecs, and different divergence states. The core changes are in remote.c's format_branch_comparison() function, which was refactored in the first patch of this series to support the new functionality.

This represents the culmination of a two-month review process where first-time contributor Harald Nordgren successfully navigated Git's mailing list workflow, incorporating feedback from Jeff King and others. The implementation has been simplified to focus exclusively on @{upstream}/@{push} comparisons while deferring more complex branch matching scenarios. Junio Hamano has confirmed the patch is ready for merging.
