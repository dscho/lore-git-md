This is a patch in the Linux fsmonitor support series that adds a new option to `struct child_process` for closing inherited file descriptors in child processes. The change is part of the broader effort to bring Linux filesystem monitoring to parity with existing Windows and macOS implementations.

The patch introduces a `close_fd_above_stderr` flag that, when set, causes the child process to close all file descriptors above stderr (fd 2) after forking but before exec. This prevents long-running child processes (like the fsmonitor daemon) from inheriting potentially problematic file descriptors from the parent environment, such as pipe endpoints or test harness descriptors.

Key technical details:
- Uses `sysconf(_SC_OPEN_MAX)` to determine the maximum file descriptor number, with a safety cap at 4096
- Preserves the child notifier fd (used for process communication)
- Adds documentation in `run-command.h` explaining the purpose
- The implementation is careful to avoid excessive iteration when system fd limits are very high

This change addresses a subtle issue where inherited file descriptors could cause problems in long-running daemon processes. The patch is well-contained and follows Git's established patterns for process handling, building on the existing `child_process` infrastructure. It's part of the final polishing for the Linux fsmonitor implementation, which has undergone extensive review across six versions.
