This is a bugfix patch for Git's filesystem monitor (fsmonitor) daemon, part of a larger series adding Linux support. The patch addresses a memory leak in the daemon's cleanup path where a hashmap`state.cookies` was being initialized but never freed. 

The change is straightforward - it adds a single `hashmap_clear()` call to properly clean up the hashmap when the daemon shuts down. This is the second patch in a 10-part series that has undergone extensive review over six iterations, with all major technical concerns now addressed. The series as a whole brings Linux fsmonitor support to parity with existing Windows and macOS implementations.

The patch appears well-contained and properly motivated - it fixes a clear resource leak in code that was otherwise working correctly. Given the thorough review history of the series and the straightforward nature of this particular fix, it seems likely to be merged without controversy.
