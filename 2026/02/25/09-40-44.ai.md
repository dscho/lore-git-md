This is part 4 of a 6-patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has gone through nine iterations and is now approved for integration into Git's 'next' branch.

The patch introduces payload handling for reference backends, preparing for upcoming URI-based configuration of alternate reference storage locations. It adds a new `refs_compute_filesystem_location()` function that parses gitdir and payload to determine reference directory paths, handling both main and worktree cases. The files and reftable backends are modified to use this function during initialization.

Key technical changes:
- New `refs_compute_filesystem_location()` helper in refs.c that handles path resolution for both main and worktree references
- Files and reftable backends updated to accept and process payload parameters
- Path computation respects absolute/relative payload paths and worktree configurations
- Packed backend explicitly ignores payload since packed-refs only uses common dir

The change is currently a no-op since no callers pass payloads yet, but sets up the plumbing needed for the URI configuration support coming in subsequent patches. The implementation includes proper path normalization and worktree handling while maintaining the existing behavior when no payload is provided.

This patch represents a key architectural piece of the larger reference backend selection work, with all substantive concerns having been addressed through nine rounds of review. The changes are well-contained and focused on the infrastructure needed for the URI-based configuration that follows.
