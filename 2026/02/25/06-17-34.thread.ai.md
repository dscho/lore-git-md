GSOC application proposal from Amisha Chhajed to improve disk space recovery in partial clones, building on prior sparse-checkout optimization work. Core problem involves managing disk usage by objects outside sparse-checkout cones or with infrequent access, with focus on promisor objects and storage efficiency. Key participants include Derrick Stolee (technical direction), Karthik Nayak (reftable), Christian Couder (GSOC), and Justin Tobler (ODB).

Current technical direction centers on temporal (age-based) rather than spatial (cone-based) cleanup criteria after Stolee's input, warning about tools like VS Code's `git blame` potentially repopulating deleted objects. Amisha now proposes a user-driven `git evict` command with explicit control flags (`--older-than`, `--outside-cone`) as alternative to Stolee's suggested `git gc`/`git maintenance` integration. This introduces core tension between automated background cleanup (risk of unexpected re-downloads) versus explicit user control.

Open technical questions: object lifecycle management interface (new command vs existing maintenance), safe removal criteria balancing temporal access patterns against spatial location, and handling disk-vs-network tradeoffs when tools re-request evicted objects. Design considerations include integration points with maintenance tasks, impact analysis of automated tool interactions with partial clone object stores, and whether functionality belongs in core maintenance or as separate operation.
