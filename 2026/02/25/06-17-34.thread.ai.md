GSOC application proposal from Amisha Chhajed to improve disk space recovery in partial clones, with prior contributions in sparse-checkout optimizations. Proposal focuses on integrating cleanup with `git gc`/`git maintenance` for objects outside sparse-checkout cones, addressing promisor objects and storage management. Initial reviewers include Karthik Nayak (reftable), Christian Couder (GSOC), and Justin Tobler (ODB). Open questions remain about safe removal criteria and non-cone mode strategies.

Derrick Stolee provides key technical direction, advising a shift from spatial (cone vs non-cone) to temporal (old vs new objects) cleanup criteria. He warns about tools like VS Code's `git blame` potentially repopulating deleted objects, highlighting the disk-vs-network tradeoff. Recommends leveraging existing `git gc` infrastructure rather than new mechanisms, positioning this as object lifecycle management rather than sparse-checkout-specific work. Core considerations now include: temporal object access patterns, integration points with maintenance tasks, and impact analysis of automated tool interactions with partial clone object stores.
