This is patch 13/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The series aims to improve large repository repacking by maintaining a chain of MIDX layers that are compacted geometrically over time.

This patch exposes the incremental MIDX repacking mode (implemented in the previous patch) via a new `--write-midx=incremental` option for `git repack`. The mode requires `--geometric` and introduces two new configuration options to control compaction behavior:
- `repack.midxSplitFactor` (default: 2) - determines when adjacent layers should be merged
- `repack.midxNewLayerThreshold` (default: 8) - minimum packs in tip layer before considering them for repacking

The patch includes extensive tests covering various scenarios like geometric violations, multi-round chain integrity, branching/merging histories, and threshold-based compaction. The implementation appears thorough, with careful attention to maintaining backward compatibility and proper error handling.

As an RFC, this is still awaiting review, but the approach looks well-considered and the test coverage is comprehensive. The patch builds on Taylor's previous MIDX compaction work and connects to broader efforts around repack machinery improvements. Given Taylor's expertise in the pack/MIDX subsystems, this is likely to be a high-quality contribution once any review feedback is addressed.
