This is a feature patch series (v9) that enables flexible reference directory configuration in Git, primarily to support zero-downtime migrations between reference backends (files and reftable). The series builds on extensive prior discussion and has already received maintainer approval for inclusion in the 'next' branch.

The main change in v9 is documentation formatting fixes to ensure proper rendering of the `extensions.refStorage` config section in man pages. The series now provides three ways to configure reference storage:
1. Via `extensions.refStorage` config (supporting both simple format names and URI syntax)
2. Through the `GIT_REFERENCE_BACKEND` environment variable
3. Using path-based control

The motivation comes from GitLab's need to migrate large repositories between backends with minimal downtime. The implementation allows writing references to arbitrary locations during migration, significantly reducing the window where the repository needs to be locked. The series has gone through eight previous iterations with feedback from multiple core contributors (Patrick Steinhardt, Junio Hamano, Karthik Nayak, Toon Claes, and others), addressing architecture, testing, and documentation concerns.

This version appears polished and ready for integration, with all substantive issues resolved. The changes are focused on final documentation presentation and minor test refinements. Given the extensive review history and maintainer approval, this looks like a high-quality contribution that solves a real-world problem for large-scale Git deployments.
