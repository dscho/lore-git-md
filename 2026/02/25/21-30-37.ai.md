This is a refactoring patch in the fsmonitor series, specifically addressing IPC path handling for Unix platforms.

The patch consolidates nearly identical Unix domain socket path logic between macOS and Linux into a shared implementation. Paul Tarjan notes that both platforms need the same basic checks - verifying if the .git directory is on a remote filesystem and falling back to $HOME when needed. The unified version in fsm-ipc-unix.c includes a previously missing BUG guard for NULL worktree from the Linux implementation.

Junio Hamano's review points out some discrepancies between the commit message and actual changes. The patch actually renames the existing macOS (darwin) implementation to a more generic unix version rather than merging two separate implementations. He suggests the commit message should more accurately reflect this approach. Junio also proposes a cleaner build system approach - defining FSMONITOR_DAEMON_BACKEND as 'unix' for both macOS and Linux rather than special-casing the IPC file in the build recipes.

The changes affect multiple build systems (Makefile, meson.build, CMakeLists.txt) to use the new shared file. This is part of a broader effort to deduplicate platform-specific code in the fsmonitor implementation while maintaining all existing functionality. The patch appears technically sound but could benefit from a more precise commit message aligning with the actual code changes made.
