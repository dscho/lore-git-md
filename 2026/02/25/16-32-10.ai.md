This is a documentation patch that adds a new guideline to Git's CodingGuidelines about array naming conventions. It's the first patch in an 8-part series focused on naming consistency and code organization in the `repo-info` subsystem.

The patch introduces a rule that arrays should generally be named in singular form when individual elements are accessed (e.g. `dog[0]`), but may use plural when the array is treated as a whole (e.g. `dogs` passed to `walk_all_dogs()`). This distinction comes from feedback by Eric Sunshine on the previous version of the patch.

The change is purely documentation - it doesn't modify any actual code. The rule is clearly motivated by readability concerns, making it obvious when code is working with individual elements versus the entire collection. The patch follows Git's standard documentation style and includes examples to illustrate both cases.

As the first patch in a larger series, it establishes a naming principle that will presumably be applied in subsequent patches. The change is small, focused, and uncontroversial - exactly the sort of incremental improvement that tends to be welcomed in style guideline updates.
