This is the first of two patches in the final version of Harald Nordgren's configurable branch comparison feature for `git status`. After 28 iterations over two months, the implementation has been simplified to focus exclusively on `@{upstream}`/`@{push}` comparisons while deferring more complex branch matching scenarios.

The patch refactors the `format_branch_comparison` function in `remote.c` to prepare for showing comparisons with push remote tracking branches. It extracts the comparison logic into a separate function while maintaining all existing behavior. The changes are mechanical and focused on code organization rather than functionality - the actual comparison messages remain unchanged at this stage.

Key technical details:
- Moves the branch comparison message generation into a new `format_branch_comparison` helper function
- Keeps the same message formats for all cases (up-to-date, ahead, behind, diverged)
- Maintains existing advice hints and pluralization handling
- Preserves the special case for gone upstream branches
- No behavior changes in this preparatory patch

The refactoring follows Git's typical pattern of breaking down large functions into smaller, more focused units. This sets up the second patch to cleanly add push branch comparison support while minimizing churn. The changes are straightforward and unlikely to be controversial at this late stage of review.
