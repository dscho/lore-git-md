This is part 6 of Taylor Blau's 14-patch RFC series introducing incremental MIDX/bitmap-based repacking. The series aims to improve large repository maintenance by enabling geometric repacking while maintaining MIDX layer structure, with an optional append-only mode.

Patch 6 is a refactoring that changes how `cmd_repack()` tracks the object database (ODB) source. Rather than accessing `repo->objects->sources` directly, it now stores the ODB source in the `existing_packs` struct. This is a mechanical change that aligns with the ongoing ODB abstraction effort (where Patrick Steinhardt is a key contributor).

The patch appears straightforward and well-contained, touching only the repack machinery. Taylor notes this was accidentally sent twice in the RFC version and will be deduplicated in the non-RFC iteration. As infrastructure work, this change seems uncontroversial and likely to be accepted with minimal discussion, though reviewers may check that it properly maintains the ODB source information through the repack process.
