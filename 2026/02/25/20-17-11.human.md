This is part of the ongoing Linux fsmonitor support series, specifically addressing code deduplication between Unix platforms. Patch 5/10 in the sixth iteration of this work focuses on consolidating the IPC path logic that was previously duplicated between macOS and Linux implementations.

The patch merges the nearly identical Unix domain socket path determination code from `fsm-ipc-darwin.c` into a new shared `fsm-ipc-unix.c` file. Both platforms need to handle the same cases: checking if the .git directory is on a remote filesystem and falling back to a socket path under $HOME when it is. The unified version also incorporates a missing BUG guard for NULL worktree from the Linux implementation.

The changes touch build systems (Makefile, meson.build, CMakeLists.txt) to use the new shared file for non-Windows platforms while keeping Windows-specific IPC handling separate. This is a clean refactoring that reduces maintenance overhead without changing functionality - a typical example of the kind of consolidation that happens as features mature across multiple platforms.

The patch builds on prior work in the series and shows the Linux fsmonitor implementation reaching parity with macOS's more established support. With this change, the IPC path handling becomes truly platform-agnostic for Unix systems, leaving only the OS-specific event monitoring backends to differ between implementations.
