This is a patch in the Linux fsmonitor support series that adds a new option to clean up file descriptors in child processes. It's the 9th patch in the 6th iteration of this work.

The patch introduces a `close_fd_above_stderr` flag in `struct child_process` that, when enabled, will close all file descriptors above stderr (fd 2) in child processes after forking but before exec. This prevents long-running children (like the fsmonitor daemon) from inheriting potentially problematic file descriptors from their parent process, such as pipe endpoints or test harness descriptors.

The implementation safely handles the file descriptor scan by using `sysconf(_SC_OPEN_MAX)` to determine the maximum file descriptor number, with a reasonable cap at 4096 to avoid excessive iteration on systems with very high limits. The change is small and focused, touching only the run-command infrastructure with clear documentation of the new option.

This appears to be a robust solution to a subtle issue that could affect the fsmonitor daemon's reliability, particularly in test environments. The patch builds on the extensive review and testing already done for the fsmonitor series, and the implementation looks clean and well-contained.
