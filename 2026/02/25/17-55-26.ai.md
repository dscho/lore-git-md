This is a feature request for `git log` formatting behavior. Alejandro Colomar proposes making the `%d` format specifier respect the `--decorate` option, similar to how other format specifiers like `%h` respect related configuration options.

The current situation is that Alejandro uses a custom log format that mimics `--oneline` but adds GPG signature status (`%G?`) at the start. However, the reference decorations (`%d`) in this format always appear, even when `--no-decorate` is specified. The request seeks to make this behavior consistent with other format specifiers that respect their related options (`core.abbrev` for `%h`, `log.date` for time-related specifiers).

The change would affect the `pretty.c` formatting code to make `%d` conditional on the decorate setting. This seems like a reasonable consistency improvement, though it might require careful handling to avoid breaking existing scripts that rely on the current unconditional behavior of `%d`. The patch would need to consider backward compatibility implications while making the behavior more intuitive for interactive use cases like Alejandro's custom format.
