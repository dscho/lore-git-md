This is a follow-up in the `git repo info` RFC thread, where the community is helping a GSOC contributor understand Git's plumbing command conventions. Junio C Hamano acknowledges K Jayatheerth's helpful reference to the Pro Git book's "Plumbing and Porcelain" chapter, which reinforced Junio's earlier point that plumbing commands must produce no output when given no arguments. The thread has reached clear consensus that the experimental `git repo info` command will follow this established pattern, settling a design question that arose when the contributor initially proposed showing all fields by default. The exchange demonstrates Git's mentoring culture in action, with experienced contributors guiding newcomers toward the project's design principles.
