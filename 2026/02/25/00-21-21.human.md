This is patch 6/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The patch refactors how `git repack` tracks the object database (ODB) source by moving it into the `existing_packs` struct rather than accessing it directly from the repository's objects.

The change is mechanical - the same source is still used, just accessed through a different path. But it serves two purposes: (1) it prepares for the incremental MIDX repacking machinery that will need to know the ODB to read existing MIDX files, and (2) it future-proofs for potential support of multiple object sources in repack operations.

The patch touches three files, adding a new field to `existing_packs` and updating two call sites to use it. This is infrastructure work that seems uncontroversial, though reviewers may want to confirm the source selection logic remains correct when multiple sources are present. The change aligns with the broader ODB abstraction effort in the project.
