This is the final version of Harald Nordgren's feature patch series adding configurable branch comparisons to `git status`. After 28 iterations over two months of review, the implementation has been simplified to focus exclusively on comparing against `@{upstream}` and `@{push}` references, deferring more complex branch matching scenarios for potential future work.

The patch series introduces a new `status.compareBranches` configuration option that accepts a space-separated list of special references. Currently only `@{upstream}` and `@{push}` are supported - any other values will be ignored with a warning. When unset, it defaults to `@{upstream}` to maintain backward compatibility with existing behavior.

The implementation refactors branch comparison formatting in remote.c and adds extensive test coverage (337 lines of new tests). The documentation clearly states the current limitations while leaving room for future expansion. The feature has been thoroughly reviewed by multiple contributors, with Jeff King proposing the simplified approach that was ultimately accepted.

This represents a successful navigation of Git's mailing list workflow by a first-time contributor, with the maintainer confirming the series is ready for merging. The feature provides useful functionality while keeping the initial scope manageable, and serves as a case study in persistence through Git's rigorous review process.
