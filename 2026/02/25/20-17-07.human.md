This is a bugfix patch addressing a memory leak in Git's fsmonitor daemon, part of the ongoing effort to add Linux support for filesystem monitoring. The patch fixes a case where a hash table used to track shown paths wasn't being freed when the daemon sent a "trivial" response to a client.

The issue occurs in the client handling code where a khash table (`shown`) is allocated but only freed in the non-trivial response path. When the response is trivial, the code jumps to cleanup without freeing the table. The fix initializes the table to NULL and moves cleanup to use `kh_destroy_str()` which safely handles NULL, ensuring the table is freed in all code paths.

This is the first patch in a 10-part series that has undergone extensive review over six iterations. The change is small (5 lines modified) but important for correctness, addressing one of the last remaining memory leaks in the Linux fsmonitor implementation. The patch comes from Paul Tarjan, who has been involved in testing and stabilizing this feature in production environments.
