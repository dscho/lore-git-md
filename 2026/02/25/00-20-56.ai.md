This is the first patch in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. It's a preparatory refactoring that improves how MIDX files are tracked during cleanup operations.

The patch replaces hand-rolled arrays of filenames with `string_list` structures in two MIDX cleanup functions (`clear_midx_files_ext` and `clear_incremental_midx_files_ext`). This simplifies the code by:
- Eliminating manual memory management of string arrays
- Using standard string list operations instead of linear searches
- Reducing parameter passing since the list can be passed as a single struct

The change is purely internal - no user-visible behavior is modified. The commit message notes that while this theoretically improves lookup performance (from O(n) to O(log n) after sorting), the impact is negligible in practice because the lists are typically small.

This appears to be solid infrastructure work that follows Git's coding style well. The change is focused and clearly motivated as preparation for the larger series. As the first patch in an RFC, it sets a good precedent for the quality of the subsequent changes.
