Junio C Hamano responds to Alejandro Colomar's proposal about making `%d` respect `--decorate` in `git log` output. As the maintainer, Junio immediately identifies the backward compatibility issue this would create for existing scripts that rely on `%d`'s current unconditional behavior. He firmly states that changing `%d` is a "non-starter" due to the potential breakage.

However, Junio suggests a forward path by proposing a new placeholder syntax that would allow optional decoration display. His example shows `%(decorate:optional=yes)` as a possible format that could respect the `--decorate` flag while preserving the existing `%d` behavior. This maintains backward compatibility while still addressing the original use case of having decoration display be configurable.

The response is characteristically pragmatic from Junio - rejecting an approach that would break existing usage while offering a constructive alternative that solves the problem without disruption. This suggests the thread will likely shift focus to designing and implementing the new placeholder syntax rather than modifying `%d`'s behavior.
