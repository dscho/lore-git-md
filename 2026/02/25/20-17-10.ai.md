This patch is part of the Linux fsmonitor support series, specifically focusing on improving the cookie wait mechanism in the fsmonitor daemon. It addresses a timeout issue that could cause hangs on certain filesystems.

The patch replaces an infinite `pthread_cond_wait()` with a one-second timeout using `pthread_cond_timedwait()`. This change handles cases where inotify watches succeed but events never arrive (common on some container/overlay filesystems), preventing indefinite hangs. When the timeout fires, it logs the event and returns an error, allowing the client to fall back to a full scan rather than blocking forever.

Key technical details:
- Uses `gettimeofday()` and `pthread_cond_timedwait()` to implement the timeout
- Maintains the same locking behavior with `state->main_lock`
- Adds trace logging for timeout events
- Preserves the existing error handling flow while adding the timeout case
- Part of broader fsmonitor work to handle edge cases and improve reliability
