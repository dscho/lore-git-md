This is a discussion thread about `git log`'s decoration behavior, specifically the interaction between the `--decorate` option and format placeholders (`%d`). The conversation builds on previous analysis of inconsistencies between documented and actual behavior.

Alejandro Colomar joins Marc Branchaud and Junio Hamano in discussing two key points: First, that `--decorate=auto` currently only affects the default format, not explicit `%d` placeholders, despite documentation implying a connection. Second, that `--decorate=no` currently behaves identically to `--decorate=short` when used with `%d`, which seems counterintuitive.

Colomar supports Marc's argument that changing `--decorate=no` to fully suppress decorations (including `%d`) would be safe, since any scripts relying on the current behavior could simply switch to `--decorate=short` to maintain it. The discussion highlights that these decoration behaviors are likely not used together in practice, making such a change low-risk.

The thread exemplifies Git's careful consideration of interface design, where even subtle documentation inaccuracies and behavioral quirks receive thorough analysis. Participants are weighing the tradeoffs between maintaining backward compatibility versus improving logical consistency in the command-line interface. The technical focus remains on the decoration subsystem in `pretty.c` and how it interprets format strings versus command-line options.
