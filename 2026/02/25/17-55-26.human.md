This is a feature request for `git log` formatting behavior. Alejandro Colomar proposes making the `%d` format specifier (which shows ref decorations) respect the `--no-decorate` flag, similar to how other format specifiers like `%h` respect related configuration options.

The motivation comes from a custom alias that mimics `--oneline` but includes GPG signature status (`%G?`). Currently, the ref decorations (%d) in this format can't be disabled with `--no-decorate`, which would be useful for cases where the decorations aren't wanted. The change would make behavior more consistent with other format specifiers that respect related flags.

The patch appears well-motivated and focused - it addresses a specific inconsistency in the log formatting system without introducing new complexity. The use case is clear (custom log formats that want to optionally suppress decorations) and the proposed change aligns with existing behavior patterns in Git's format specifiers. This seems like a straightforward quality-of-life improvement for users who customize their log output.
