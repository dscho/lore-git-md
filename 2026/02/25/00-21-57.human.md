This is patch 12/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The series aims to improve large repository performance through geometric repacking with MIDX (multi-pack-index) layer awareness.

The patch implements the core incremental MIDX repacking logic. It introduces a new `write_midx_incremental()` function that builds and maintains an incremental MIDX chain during geometric repacking. Unlike the default flat MIDX approach, this constructs a compaction plan that determines which MIDX layers to write, compact, or copy, executing each step using `git multi-pack-index` subcommands with the `--checksum-only` flag.

Key aspects of the strategy:
- Always writes a new MIDX layer containing newly created packs
- Merges adjacent MIDX layers when accumulated object count exceeds half the next layer's size (controlled by `repack.midxSplitFactor`)
- Evaluates remaining layers pairwise for compaction or copying
- Uses atomic moves and locking for safety
- Maintains backward compatibility

The implementation is thorough, handling edge cases like preferred pack selection, object count overflow checks, and proper cleanup. It builds on infrastructure from earlier patches in the series (MIDX write options, ODB source tracking, etc.) while introducing new concepts like the `midx_compaction_step` struct to model each operation.

This appears to be a well-considered implementation that could significantly improve repacking performance for large repositories. As an RFC, it's likely to attract review from pack/MIDX experts like Patrick Steinhardt and Derrick Stolee. The careful attention to atomic operations and backward compatibility suggests it was designed with production use in mind.
