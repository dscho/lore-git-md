This is a preparatory refactoring patch in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The patch modernizes how MIDX files are tracked during cleanup operations by replacing hand-rolled arrays with Git's standard `string_list` structure.

The change affects two functions that prune stale MIDX files while preserving specified ones. The key improvement is replacing manual array management with `string_list`'s built-in utilities, which simplifies the code by:
- Eliminating separate length tracking
- Providing sorted lookups (though the commit message notes this won't measurably impact performance)
- Reducing memory management boilerplate

The patch is purely internal cleanup with no behavior changes. It's part of the groundwork for the larger series that aims to improve repacking in large repositories through geometric MIDX strategies. Given Taylor's expertise in the pack/MIDX subsystem and the straightforward nature of this refactoring, the change appears solid and uncontroversial.
