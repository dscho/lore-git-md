This is a preparatory infrastructure patch in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. It's part of a larger effort to improve repacking strategies for large repositories.

The patch adds a new `strvec_init_alloc()` function that allows callers to pre-allocate space in a strvec when they know in advance how many elements will be storing. This avoids repeated reallocations as elements are added. The implementation allocates space for the specified number of elements plus one (for the NULL terminator) and initializes the strvec structure accordingly.

This change is a small but useful utility that will be used in subsequent patches of the series. The commit message notes this is particularly helpful when the caller knows upfront how many elements will be pushed onto the strvec. The patch itself is straightforward - it adds the new function declaration in strvec.h and implements it in strvec.c with proper memory allocation using Git's `CALLOC_ARRAY` and `st_add` helpers.

As part of an RFC series, this patch hasn't received review feedback yet. Given Taylor Blau's expertise in Git's pack subsystem and the preparatory nature of this change, it's likely to be uncontroversial. The change is self-contained and doesn't modify any existing behavior, just adds a new utility function that will be used by later patches in the series.
