This is a feature improvement for `git send-email`'s handling of character encodings, part of an ongoing thread about making the 8-bit encoding prompt more robust. The patch from Shreyansh Paliwal has gone through several iterations with feedback from Ben Knoble and Junio Hamano.

The core change replaces a length-based charset validation with proper semantic checking using Perl's `Encode::find_encoding()`. The new version also improves the prompt wording to avoid confusion with yes/no questions. Ben Knoble's latest review suggests the validation logic could be better organized by extracting helper functions rather than adding complexity to the generic `ask()` function.

The patch appears technically sound - it uses core Perl modules for validation while maintaining backward compatibility. The test updates match the new prompt text. Junio noted a minor test inconsistency in v2 which Shreyansh explained was due to a last-minute brace removal without re-testing.
