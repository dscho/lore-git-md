This is a refactoring and documentation series addressing naming consistency and test improvements in the `repo-info` subsystem. The v2 iteration incorporates feedback from Eric Sunshine and Patrick Steinhardt on array naming conventions and test modernization.

The key changes in this version:
1. Refines the proposed CodingGuidelines rule about array naming (patch 1) to distinguish between arrays accessed element-wise (singular names like `dog[]`) versus those treated as collections (plural like `dogs[]`), per Eric Sunshine's suggestion.
2. Clarifies the motivation for test changes in patch 6 - avoiding binary diffs in test failures by transforming NUL`-formatted output rather than storing NULs in test files, making failures more readable (a suggestion originally from Junio Hamano).
3. Optimizes the test transformation by combining two `tr` calls into one.

The series remains focused on mechanical improvements with no behavior changes, touching `builtin/repo.c`, test infrastructure, and documentation. Each patch is small and clearly motivated by specific prior feedback, showing systematic incorporation of review input. The discussion around array naming has progressed with the author acknowledging the nuanced distinction between element-wise versus collective array access patterns. The rationale for test modernization is now clearer with its human-facing benefits made explicit.
