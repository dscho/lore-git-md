This is a platform compatibility patch adding Windows support for timed condition variable waits, part of the larger fsmonitor Linux support effort.

Paul Tarjan contributes patch 3/10 in the v6 series, implementing `pthread_cond_timedwait()` for Windows using the native `SleepConditionVariableCS()` API. The implementation converts the absolute timeout to milliseconds and handles the `ETIMEDOUT` case correctly. This enables bounded waits on condition variables, which the fsmonitor daemon needs for proper synchronization.

The change is straightforward - 26 lines adding the new function plus a header declaration - and follows the established pattern of the Windows pthread compatibility layer. It builds on prior work in this thread to bring Linux fsmonitor support to parity with Windows/macOS, though this particular piece is Windows-specific plumbing. The patch appears well-contained and properly integrated with the existing Windows pthread emulation.
