This is patch 6/14 in Taylor Blau's RFC series introducing incremental MIDX/bitmap-based repacking. The patch refactors how `git repack` tracks the object database (ODB) source by moving the storage from `repo->objects->sources` to the `existing_packs` struct.

The change is mechanical - the same source is still used, just accessed through the new location. The motivation is twofold: (1) the upcoming incremental MIDX repacking will need this source to read existing MIDX chains, and (2) it prepares for potential future support of multiple object sources in `git repack`. The patch touches the repack machinery's internals, adding the source` field to `struct existing_packs` and updating two call sites in `builtin/repack.c` to use it.

This is an infrastructure patch that enables later functionality in the series. It follows the pattern of earlier patches in moving data structures to more logical homes while maintaining backward compatibility. The change is straightforward and unlikely to be controversial, though reviewers may check that the source assignment properly handles cases where `objects->sources` is NULL. The patch aligns with the broader ODB abstraction effort in the project.
