This is part 2 of a 5-patch series improving Gitweb's mobile responsiveness. The patch focuses specifically on fixing overflow issues in the project search bar on narrow screens (<=768px width).

The change introduces a media query block in gitweb.css that applies two key fixes to the search bar container and input field: adding 8px side padding to the container and ensuring the input field respects its container's width via `max-width: 100%` combined with `box-sizing: border-box`. This prevents the search input from forcing horizontal scrolling on mobile devices while maintaining the desktop layout unchanged.

The implementation is cleanly scoped to just the search bar overflow issue, addressing Eric Sunshine's feedback from v1 about keeping related changes together. The 12-line CSS addition is straightforward and well-explained in the commit message, which clearly states the problem (forced horizontal scrolling) and solution (padding + width constraints). 

This patch builds on part 1's viewport meta tag addition and precedes parts 3-5 which handle other mobile layout issues in Gitweb's views. The series appears to be progressing methodically through the mobile responsiveness problems, with this patch cleanly solving one specific pain point.
