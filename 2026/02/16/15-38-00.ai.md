This is a performance optimization series targeting the shallow push handling in `git receive-pack`, with changes focused on the commit parsing machinery. The series comes from Patrick Steinhardt, who notes these optimizations address real-world production issues where shallow pushes were causing excessive memory usage and multi-minute delays.

The three patches work together to improve how `lookup_commit_reference_gently()` handles commit parsing during shallow push operations. The first patch avoids unnecessary parsing of non-commit objects, the second makes `repo_parse_commit_no_graph()` more robust against corrupt objects, and the third leverages the commit graph to speed up lookups. The changes touch core object handling code in commit.c and object.c, plus related header files.

This appears to be a well-motivated optimization targeting a known pain point in large repositories. Given Patrick's track record with performance-sensitive changes and the clear production motivation, this series seems likely to be uncontroversial. The changes are focused and come with Coccinelle updates to maintain consistency. Reviewers will want to verify the edge case handling (particularly around corrupt objects) doesn't introduce new failure modes, but the approach looks sound.
