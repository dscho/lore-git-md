This is part of the ongoing `the_repository` removal effort, specifically targeting the migration of global configuration variables into `struct repo_config_values`. The patch focuses on moving `core.sparseCheckout` from a global variable to repository-specific storage.

The change affects 12 files across multiple commands (sparse-checkout, clone, worktree, grep, etc.) that interact with sparse checkout functionality. The key technical aspects are:
- Replaces direct access to `core_apply_sparse_checkout` with `cfg->apply_sparse_checkout` via the new `repo_config_values()` accessor
- Maintains identical behavior while eliminating the global variable
- Includes updates to documentation comments referencing the old variable name
- Preserves all existing conditional logic and error handling

The patch is part of a v7 series that has incorporated extensive review from Phillip Wood, who suggested the overall approach. It follows the established pattern from earlier patches in the series that migrated `core.attributesFile` and `branch.autoSetupMerge`. All tests pass, including fuzz testing which was problematic in earlier iterations.

This represents mature work that has addressed all known technical issues, though the broader series remains RFC status pending resolution of submodule initialization questions. The changes are mechanical but touch sensitive areas of the sparse checkout implementation, so careful review of the command-specific behaviors is warranted.
