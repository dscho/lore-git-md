This is part 2 of a 9-patch series implementing secure storage of promisor remote fields, specifically focusing on the `promisor.storeFields` configuration option. The patch allows clients to securely store server-advertised fields like tokens and partial clone filters in their local configuration.

The key addition is a new `promisor.storeFields` config that specifies which remote fields (currently "partialCloneFilter" and "token") should be persisted when received from a server. The implementation includes:

- Validation checks for stored values (ensuring filters parse correctly and tokens contain no control characters)
- Configuration reloading after updates
- User notifications when config changes occur
- Security protections that prevent storing fields for unconfigured remotes
- Comprehensive tests demonstrating the behavior

The patch modifies several files:
- Adds documentation in `Documentation/config/promisor.adoc` and updates protocol docs
- Implements core functionality in `promisor-remote.c` with new helper functions
- Adds test cases in `t/t5710-promisor-remote-capability.sh`

This builds on previous work that allowed servers to advertise additional fields and clients to check them. The stored fields enable dynamic updates of security tokens and filter specifications without manual client-side configuration changes. The implementation has been reviewed by Patrick Steinhardt and includes feedback from earlier iterations.
