This is part 4/5 of a series improving Gitweb's mobile responsiveness, specifically addressing footer layout issues. The patch fixes text overflow problems that occur when footer content wraps on narrow screens by switching from a fixed height to a minimum height and adding a clearfix to properly contain floated elements.

The change is straightforward - it replaces the rigid `height: 22px` with `min-height: 22px` to allow the footer to expand when needed, and adds a CSS clearfix (using the standard `::after` pseudo-element technique) to ensure floated footer elements don't cause layout problems. This maintains the existing desktop appearance while gracefully handling mobile viewports.

As with the rest of the series, this patch is well-contained and clearly motivated, with the implementation matching the problem description. The changes are minimal (just 8 lines) and focused solely on the footer component. Since this is part of an already-reviewed series that has addressed previous organizational feedback, it appears ready for inclusion.
