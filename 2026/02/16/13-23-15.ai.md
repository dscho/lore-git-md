This is the final patch in a 9-part series implementing automatic filter selection for promisor remotes. The patch wires up the `--filter=auto` functionality in clone and fetch operations, completing the LOP (Large Object Promisors) effort.

The key changes enable:
- Automatic filter computation based on server-advertised promisor remote filters when `--filter=auto` is used
- Persistence of the auto setting in config so future fetches maintain dynamic behavior
- Transport layer support for auto filters
- Comprehensive tests verifying dynamic filter updates

The implementation handles several technical challenges:
- Proper filter resolution in `fetch-pack.c` by calling `promisor_remote_construct_filter()`
- Disabling auto filters after resolution to prevent recursion
- Transport layer changes to accept auto filters during early parsing
- Detailed test coverage of the filter persistence and update behavior

The patch builds on previous work in the series that:
- Added infrastructure for storing server-advertised filters
- Implemented the core auto filter parsing logic
- Refactored filter ownership and initialization
- Documented the new functionality

Reviewers Patrick Steinhardt and Christian Couder have approved the approach, with Jeff King contributing a NULL pointer safety fix. The series is ready for merging after four iterations of review.

This completes a significant enhancement to partial clone capabilities, allowing servers to suggest optimal filters while maintaining security and backward compatibility. The auto-filter behavior will be particularly useful for large repositories where the ideal filter may change over time.
