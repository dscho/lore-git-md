This is the first patch in a performance optimization series from Patrick Steinhardt targeting shallow push handling in `git receive-pack`. The patch focuses on improving `lookup_commit_reference_gently()` to avoid unnecessary parsing of non-commit objects, which was causing significant performance issues during shallow pushes.

The key problem addressed is that when processing many non-commit references (like tags pointing to blobs or trees), the function was needlessly parsing and verifying these objects before realizing they weren't commits. The solution introduces a new `peel_object_ext()` helper that first checks the object type via peeling before full parsing, skipping the expensive work for non-commits.

The performance impact is substantial: in a test pushing to a repo with 100,000 non-commit refs, time dropped from ~62s to ~38s (1.63x faster) and memory allocations reduced from 67GB to 407MB. The patch maintains identical behavior when all refs point to commits. This is part of a larger effort to optimize shallow push handling that will continue in subsequent patches.

The changes touch core object handling code in commit.c and object.c, adding the new peeling helper while maintaining backward compatibility. Given Patrick's track record with performance-sensitive changes and the clear benchmark results, this appears to be a well-motivated optimization targeting a real-world pain point.
