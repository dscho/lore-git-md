This is the second patch in a 4-part series implementing UTF-8 support for Git configuration subsections, specifically for aliases. The series is now in its fifth iteration with all known issues addressed, including a shell completion bug fixed in v5.

The current patch prepares for subsection aliases by switching from `skip_prefix()` to `parse_config_key()` for alias parsing in `help.c`. This properly handles the three-level config key structure needed for the new `alias.*.command` subsection syntax that will be introduced in the next commit. 

The change introduces a compatibility break: previously, the parser would accept `alias.<subsection>.<key>` as defining an alias `<subsection>.<key>`, but now such entries are silently ignored unless `<key>` is "command". The commit message argues this was effectively a bug since dotted aliases were never intentionally supported or documented.

The implementation is minimal - just 7 lines changed in `help.c` to use `parse_config_key()` instead of `skip_prefix()`. The patch maintains all error checking while properly distinguishing between subsections and keys. This is a clean preparatory step for the actual UTF-8 alias support coming in the next patch.
