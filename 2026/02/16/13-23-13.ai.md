This is part 7/9 of a series implementing promisor remote enhancements, specifically focusing on storing server-advertised filters in memory. The patch adds infrastructure to support the upcoming `--filter=auto` feature by:

1. Adding an `advertised_filter` field to `struct promisor_remote` to persistently store server-suggested filters during the session, even when not configured for disk persistence via `promisor.storeFields`.

2. Modifying `filter_promisor_remote()` to capture advertised filters into a temporary list and apply them to the promisor remote structs after potential config reloading, ensuring filters remain available.

3. Introducing `promisor_remote_construct_filter()` which:
   - Iterates over accepted promisor remotes
   - Collects their advertised filters
   - Generates a combined filter spec
   - Validates filters and warns about invalid ones
   - Returns NULL if no valid filters exist

The changes touch `promisor-remote.[ch]` and are part of the larger LOP (Large Object Promisors) effort to enhance partial clone capabilities. This intermediate patch provides the memory storage mechanism needed for the auto-filter functionality coming in subsequent patches. The implementation handles edge cases like config reloading and invalid filters while maintaining clean memory management.

Key technical details include the new string_list handling for temporary filter storage, the careful memory ownership transfer to the promisor_remote structs, and the validation logic in the new construction function. The patch builds on previous refactoring work in the series and has been reviewed by Patrick Steinhardt.
