This is a refactoring patch series that continues the ongoing worktree API cleanup effort, specifically addressing how NULL worktree parameters are handled. Phillip Wood proposes two changes building on Shreyansh Paliwal's earlier RFC series:

1. The first patch introduces `get_worktree_from_repository()` to construct a worktree struct from repository data, eliminating the need to pass NULL worktree parameters to `worktree_git_path()`. This implements the approach Phillip suggested earlier in the thread, where the worktree ID is derived from comparing `gitdir` and `commondir`.

2. The second patch removes the repository parameter from `worktree_git_path()` entirely, making it always use the repository pointer stored in the worktree struct. This simplifies the API surface while maintaining the same functionality.

The changes touch several key subsystems - worktree handling, path resolution, and status reporting - with modifications to `wt-status.c`, `path.c`, and related headers. Phillip notes these changes should allow Shreyansh's parallel wt-status cleanup work to proceed independently.

This appears to be a well-scoped incremental improvement that addresses the NULL parameter ambiguity while maintaining backward compatibility. The implementation follows the architectural direction validated by Junio Hamano in earlier discussion, particularly around distinguishing between "current worktree" and "main worktree" semantics. The patch series builds logically on the ongoing thread while keeping changes focused and reviewable.
