This is part 8 of a 9-patch series implementing promisor remote enhancements, specifically focusing on the `--filter=auto` functionality. The series has been through multiple iterations (now at v4) with reviews from Patrick Steinhardt, Christian Couder, and others.

The patch refactors `promisor_remote_reply()` to separate its two responsibilities: updating repository state and generating reply strings. The function now takes an output parameter `accepted_out` that will only be populated with the reply string if requested (non-NULL), avoiding unnecessary string assembly when the caller only needs the side effects. This optimization is particularly useful for `fetch-pack` which needs the repository state updates but not the reply string.

Key changes:
- Changes return type from `char *` to `void`
- Adds `char **accepted_out` parameter for optional reply string
- Only builds reply string when `accepted_out` is non-NULL
- Updates callers (like `connect.c`) to handle new signature
- Maintains all existing functionality while improving efficiency

The change is a clean refactoring that enables more efficient usage in follow-up patches, particularly for the fetch-pack integration. The series as a whole has been thoroughly reviewed and is now considered merge-ready by Patrick Steinhardt.
