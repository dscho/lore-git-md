This is the second patch in Patrick Steinhardt's v3 series improving the `git history` command's UI. The patch focuses on early validation of merge commits before user interaction begins.

The change moves merge commit detection earlier in the execution flow by introducing a new `revwalk_contains_merges()` function that checks for commits with multiple parents (using `--min-parents=2`). This prevents users from wasting time editing commit messages when the operation would fail later due to unsupported merge commits. The validation happens in `setup_revwalk()` before any user interaction occurs.

A test is updated to use `false(1)` as the editor to verify the editor isn't launched when merge commits are detected. This maintains the test's verification of the error message while confirming the early validation works as intended. The implementation follows the series' pattern of separating validation from action, keeping the architecture clean.

The patch is well-contained, touching only the core validation logic and a single test case. It builds on the series' established approach while addressing a specific UX pain point. Review feedback from previous versions has been incorporated, and this iteration shows the polished final form of the change.
