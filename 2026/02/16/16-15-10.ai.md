This is a refactoring patch that consolidates alias listing logic between `alias.c` and `help.c` as part of the UTF-8 alias support series. The patch moves the responsibility for handling value-less definitions into `alias.c` by enhancing `list_aliases()` to store alias values via the string_list util field, then uses this unified function in `help.c` instead of its private `get_alias()` callback.

The change preserves existing error checking for malformed aliases while eliminating duplicate parsing logic. A new test case verifies that attempting to define an alias without a value still triggers the expected config error. The patch is well-contained, touching only the three relevant files with clear, focused changes.

This is the first of four patches in v5 of the UTF-8 alias support series, establishing the foundation for subsequent changes by unifying the alias listing infrastructure. The implementation remains functionally equivalent while cleaning up the code structure.
