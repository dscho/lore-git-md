This is a technical discussion thread about refactoring Git's worktree API, specifically addressing the handling of NULL parameters in worktree-related functions.

Phillip Wood clarifies the semantic meaning of NULL parameters in the worktree API, building on earlier discussion with Junio Hamano and Shreyansh Paliwal. The key points are:

1. NULL parameter semantics:
   - `wt==NULL` means "use current worktree" (resolves to repo->gitdir)
   - `wt->id==NULL` means "main worktree" (resolves to repo->commondir)

2. Current implementation details:
   - The `wt->is_current` flag is used when listing worktrees via `get_worktrees()`, while NULL parameters serve as a caller convenience shorthand
   - Most operations want the current worktree, with the main worktree being special only for certain administrative operations

3. Future direction:
   - Phillip suggests eventually embedding worktree references in the repository structure (`r->main_wt`, `r->current_wt`) but considers this out of scope for the current wt-status.c cleanup
   - The immediate focus remains on cleaning up NULL parameter handling while maintaining backward compatibility

The discussion shows steady progress in clarifying the worktree API contracts, with Phillip providing authoritative guidance on the intended semantics. The thread continues the architectural work to make worktree handling more explicit and less ambiguous, while deferring larger structural changes to the repository/worktree relationship for future work.
