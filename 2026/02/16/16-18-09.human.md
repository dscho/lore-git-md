This is a refactoring patch in Phillip Wood's series to clean up NULL worktree parameter handling, part of the broader worktree API standardization effort. The patch introduces `get_worktree_from_repository()` to construct worktree structs from repository data, eliminating NULL worktree parameters in `wt-status.c` functions.

Key changes:
- Adds a new function to create worktree structs from repository data
- Converts NULL worktree checks to BUG() assertions in rebase/bisect checks
- Updates `wt_status_get_state()` to use the new constructor
- Maintains backward compatibility while reducing NULL parameter ambiguity

The patch follows Junio Hamano's suggested approach of comparing gitdir/commondir to identify worktrees. It's a well-contained change that moves toward embedding worktree references in repository structures while cleaning up the wt-status interface. The implementation looks solid with proper memory management (freeing the constructed worktree) and maintains existing behavior.
