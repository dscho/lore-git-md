Performance optimization patch from Patrick Steinhardt, part 2 of a series improving shallow push handling in `git receive-pack`. This patch makes `repo_parse_commit_no_graph()` more robust when dealing with commits that were previously parsed via the commit-graph but need to be re-parsed without it.

The issue arises when writing a commit-graph while simultaneously needing to parse commits - a rare but possible scenario that currently causes segfaults. The fix ensures proper tree population by first unparsing any commit that came from the graph before re-parsing it without graph assistance. Patrick notes this shouldn't impact performance since the function is only called in commit-graph.c and commits are re-parsed at most once.

The patch includes both the core fix (adding unparse-then-reparse logic) and a related Coccinelle rule update to avoid false positives from the semantic patching system. While the triggering case is currently limited to test scenarios with `GIT_TEST_COMMIT_GRAPH=1`, Patrick flags this as preventing a latent issue that could surface in production. The change builds on his ongoing work optimizing object handling, particularly around shallow operations.
