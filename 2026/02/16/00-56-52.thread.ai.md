Thread summary:

Feature request for a new `git stash diff [stashname]` command to simplify viewing stash diffs, proposed by Pierre Houston. Currently users must either know to use `git diff 'stash@{0}^' 'stash@{0}'` (understanding stash implementation details) or discover `git stash show -p` (documented indirectly via "diff-options" mention). Eric Sunshine responds to the proposal by noting the existing `show -p` functionality while acknowledging the discoverability issue. He suggests improving documentation to highlight the `--patch` option for both `show` and `list` subcommands would be preferable to adding a new command. The discussion centers on whether adding an explicit `diff` subcommand would improve usability despite the existing capability, touching on Git's porcelain/plumbing design principles. Open questions remain: (1) whether the cognitive overhead of learning `show -p` justifies a new command, (2) if the command should default to most recent stash when no argument given (matching `stash show` behavior), and (3) whether documentation improvements alone would sufficiently address the discoverability issue. No other participants have weighed in beyond the initial exchange between Houston and Sunshine.
