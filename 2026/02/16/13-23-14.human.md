This is part 8 of a 9-patch series implementing promisor remote enhancements, specifically focusing on the `--filter=auto` functionality. The patch refactors the `promisor_remote_reply()` function to separate its two responsibilities: updating repository state and assembling a reply string.

Christian Couder modifies the function to take an output parameter `accepted_out` that will only be populated when needed, avoiding unnecessary string assembly when the caller (like `fetch-pack`) only needs the side effect of updating the repository configuration. The change maintains all existing behavior while making the API more efficient for cases where the reply string isn't required.

The patch touches three files:
- `connect.c` (call site update)
- `promisor-remote.[ch]` (implementation and header change)

This is a clean refactoring that follows the series' goal of improving promisor remote handling, with Patrick Steinhardt having reviewed the technical approach. The change is well-contained and doesn't introduce new functionality, just optimizes the existing code path in preparation for the final patch in the series.
