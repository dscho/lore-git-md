Performance optimization patch from Patrick Steinhardt improving shallow push handling in `git receive-pack`. This is the first of three patches targeting excessive memory usage and slow performance during shallow pushes when repositories have many non-commit refs.

The change modifies `lookup_commit_reference_gently()` to first use `peel_object()` (via new `peel_object_ext()`) to determine object types before parsing, avoiding unnecessary parsing and hash verification of non-commit objects. This provides dramatic improvements in both speed and memory usage for repositories with many non-commit refs - benchmark shows a 1.63x speedup and 60x reduction in memory allocations for a test case with 100,000 refs. The optimization has no impact when all refs point to commits.

Key technical changes include:
- New `peel_object_ext()` variant that returns the peeled object type
- Modified commit lookup logic to check object type before parsing
- Maintained error handling for non-commit objects
- Coccinelle updates for the new peeling interface

This builds on Patrick's ongoing work optimizing Git's object handling, particularly around shallow operations. The patch touches core object parsing internals but appears carefully implemented with thorough benchmarking. Reviewers will want to verify edge cases around corrupt objects and the interaction with the commit graph (which is addressed in subsequent patches).
