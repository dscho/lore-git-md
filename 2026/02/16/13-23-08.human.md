This is part 2 of a 9-patch series (v4) enhancing Git's promisor remote functionality. The patch introduces a new `promisor.storeFields` config option that allows clients to securely store additional fields (like tokens and filters) received from servers during promisor remote advertisements.

The key addition is the ability to persist server-provided values for `partialCloneFilter` and `token` fields in the client's configuration. This is particularly useful for tokens that may need frequent updates - the server can push new tokens to clients automatically rather than requiring manual updates. The implementation includes validation layer to ensure stored filters are syntactically valid and tokens don't contain control characters.

The patch ensures security by:
1. Only storing fields for already-configured remotes (no new remotes are created)
2. Validating filter syntax before storage
3. Sanitizing token contents
4. Emitting warnings when config changes occur

The changes touch documentation, core promisor-remote handling code, and include new test coverage. This builds on previous work that allowed clients to check fields from servers, now adding the storage capability while maintaining all existing security constraints. The patch has been reviewed by Patrick Steinhardt and others through multiple iterations.
