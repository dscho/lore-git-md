This is the final patch in a series implementing UTF-8 support for Git configuration subsections, specifically addressing an edge case in zsh shell completion. The series has gone through five iterations with all technical issues resolved, and this patch fixes the last remaining problem.

The issue occurs when zsh completion tries to handle subsection-style aliases (like `[alias "förgrena"]`). The zsh completion script was incorrectly processing these aliases by stripping too much of the config key, leaving malformed completion candidates. The patch adds a new hidden `--aliases-for-completion` option to `git help` that properly outputs alias names and values in a format zsh can use, matching the behavior already working in bash completion.

The implementation:
- Adds the new option to `builtin/help.c` that outputs NUL-separated alias name/value pairs
- Updates the zsh completion script to use this new interface
- Maintains all the UTF-8 handling and case sensitivity improvements from earlier patches

This appears to be a clean, focused fix that completes the series. The patch is small (16 lines added/changed) and builds on the existing `--config-for-completion` pattern. With this final piece in place, the UTF-8 alias support implementation is functionally complete and ready for merging.
