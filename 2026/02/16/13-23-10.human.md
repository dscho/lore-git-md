This is part 4/9 of a v4 series implementing secure storage of promisor fields and auto-filtering for partial clones. The patch focuses on code clarity in the fetch machinery.

Christian Couder refactors how filter options are handled in `builtin/fetch.c`, making the `filter_options` variable local to `cmd_fetch()` rather than a file-scoped static variable. This change clarifies ownership and prepares for upcoming filter-related work in the series. The patch passes the filter options through several helper functions (`prepare_transport()`, `do_fetch()`, etc.) to maintain functionality while making the data flow more explicit.

The change is mechanical but important for maintainability - it makes the code's behavior clearer at the cost of adding some parameter passing. Patrick Steinhardt has reviewed this change as part of the larger series, which has already gone through several iterations and is now considered merge-ready. This particular patch helps set up the infrastructure needed for the auto-filter feature coming in later patches.
