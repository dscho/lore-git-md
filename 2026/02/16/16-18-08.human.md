This is a refactoring patch series that continues the ongoing worktree API cleanup effort, specifically addressing how NULL worktree parameters are handled. Phillip Wood builds on Shreyansh Paliwal's earlier RFC series with two focused changes:

1. The first patch introduces `get_worktree_from_repository()` to construct a worktree struct from repository data, eliminating the need to pass NULL worktree parameters to `worktree_git_path()`. This implements the approach Phillip suggested earlier in the thread, where the worktree ID is derived from `repo->gitdir` when it differs from `repo->commondir`.

2. The second patch then removes the repository parameter from `worktree_git_path()` entirely, since the worktree struct now contains the repository reference. This simplifies the API surface while maintaining the same functionality.

The changes touch several key subsystems including the worktree machinery, path handling, and wt-status, but the modifications are mechanical and focused. Phillip notes that these changes should allow Shreyansh's wt-status cleanup patches to proceed independently. The series appears well-contained with a clear migration path from the old NULL-based API to the more explicit struct-based approach that the thread has been converging toward.
