This is the third patch in Patrick Steinhardt's v3 series improving the `git history` command's UI. The patch focuses on replacing the technical `--ref-action=print` option with a more user-friendly `--dry-run` flag.

The change makes the dry-run functionality more discoverable and flexible. Previously, `--ref-action=print` would only show updates for all branches, while the new `--dry-run` flag can be combined with either `--ref-action=branches` or `--ref-action=head` to see the corresponding updates. The implementation introduces a new `handle_ref_update()` helper that centralizes the logic for both actual updates and dry-run output.

The patch includes comprehensive updates to documentation and tests. The man page now clearly explains the dry-run behavior, including noting that it writes necessary new objects to the repository. The test suite verifies that both ref-action modes work correctly with dry-run, checking that references remain unchanged while the expected update commands are printed.

This change follows through on the series' goal of making `git history` more user-friendly while maintaining its underlying capabilities. The implementation is clean, with the ref update logic now more clearly separated between validation and execution phases. With this patch, users get a more intuitive way to preview changes before actually rewriting history.
