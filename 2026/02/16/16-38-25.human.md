Part of the `the_repository` removal effort, this patch migrates the `core.attributesFile` configuration from a global variable to repository-specific storage. The change is part of a larger series by Outreachy intern Olamide Caleb Bello (mentored by Christian Couder and Usman Akinyemi) that introduces `struct repo_config_values` to hold repository-dependent config values.

The patch moves `git_attributes_file` into the new struct while maintaining the same behavior, adding safety checks to prevent access to uninitialized repositories. It includes fixes for fuzz testing regressions (via memset() clearing) that were identified in earlier iterations, with Phillip Wood confirming the technical approach looks good.

Key changes:
- Introduces `repo_config_values()` accessor with repository validity assertions
- Adds initialization tracking via a new `initialized` flag in `struct repository`
- Preserves BSS zero-initialization behavior while moving storage
- Updates attribute handling in `attr.c` to use the new access pattern

The implementation appears solid after seven iterations, with all tests passing including fuzz tests. The main remaining architectural question (handled in later patches) is how this will work with submodule repositories, which need config access but are distinct repository instances.
