This is the first patch in Patrick Steinhardt's v3 series improving the `git history` command's validation flow. The patch refactors the command to perform revwalk validation checks before* asking for user input, preventing wasted effort when the operation would fail later anyway.

The key change splits the existing `handle_reference_updates()` function into two parts: `setup_revwalk()` for early validation and the original function for the actual reference updates. This ensures checks like verifying the rewritten commit is an ancestor of HEAD happen before the user edits a commit message. The test is updated to use `false(1)` as editor to verify the validation happens pre-edit.

This continues the series' focus on improving the command's robustness and user experience by catching errors early. The change maintains all existing functionality while making the failure mode more user-friendly. The patch has already been reviewed in previous iterations with no new concerns raised in v3.
