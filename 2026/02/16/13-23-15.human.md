This is the final patch in a 9-part series implementing automatic filter selection for partial clones. The series has been through multiple rounds of review and is now ready for merging.

The patch wires up the `--filter=auto` functionality in `git clone` and `git fetch`, allowing Git to automatically determine the optimal partial clone filter based on what the server advertises. When enabled, the "auto" setting persists in the config so future fetches will continue using the server's recommended filter without requiring the flag.

Key technical changes include:
- Enabling auto-filter support in clone/fetch commands and transport layer
- Having fetch-pack compute and send the resolved filter to the server
- Parsing server-advertised promisor remotes and their filters
- Comprehensive tests verifying the dynamic filter updates

The implementation builds on earlier infrastructure patches that:
- Added secure storage for server-advertised fields
- Refactored filter ownership and initialization
- Documented the new auto-filter behavior
- Optimized the promisor remote reply handling

Reviewers Patrick Steinhardt, Christian Couder, and Jeff King have vetted the approach across four iterations. The patch includes Jeff's fix for NULL pointer handling in filter release logic. With all feedback addressed and thorough test coverage, this completes the LOP (Large Object Promisors) effort to make partial clones more flexible and server-guided.
