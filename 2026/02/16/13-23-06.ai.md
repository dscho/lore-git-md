This is a v4 cover letter for a 9-patch series implementing two major features for Git's promisor remote functionality: secure field storage and dynamic filter combination. The series builds on previous work in the LOP (Large Object Promisors) effort and has been reviewed by key contributors including Patrick Steinhardt, Jeff King (Peff), and Jean-Noël Avila.

The first part introduces `promisor.storeFields`, a new security-conscious configuration option that allows clients to store server-advertised fields (like tokens and filters) in their local config. This enables workflows where servers can rotate credentials while maintaining access to promisor remotes. The implementation includes validation to ensure only pre-configured remotes are updated.

The second part implements `--filter=auto` mode for clone/fetch operations. When used, this mode dynamically combines server-suggested filters from accepted promisor remotes rather than using a static local configuration. This maintains backward compatibility while allowing servers to optimize filter specifications over time. The implementation leverages Git's existing filter combination mechanism.

The v4 iteration addresses all previous review feedback, with the only change being a robustness fix in patch 6/9 to properly handle NULL filter_options in `list_objects_filter_release()`. The series has been rebased on current master and includes comprehensive tests across multiple subsystems. Patrick Steinhardt has approved the series as merge-ready, and it represents a significant enhancement to partial clone capabilities.

Key technical components touched include `promisor-remote.c`, `list-objects-filter-options.c`, and the clone/fetch builtins. The work enables new server-guided optimization of partial clone workflows while maintaining security through careful validation of all remote-provided data. Future work may build on this to make promisor remote fallback order configurable.
