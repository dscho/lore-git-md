This is a follow-up discussion in the ongoing thread about test failures related to iconv availability on Windows/MSVC platforms. Christian Couder provides feedback on Patrick Steinhardt's patch series that modifies test expectations when the `iconv(1)` executable is unavailable.

Christian agrees with the core approach of tying test expectations to the ICONV prerequisite rather than introducing a new ICONV_EXECUTABLE prereq. However, he points out that the series doesn't address the documentation gap around the relationship between the NO_ICONV build knob and the ICONV test prerequisite. He suggests updating the Makefile to clarify that the test suite now assumes iconv(1) availability matches NO_ICONV's definition, and provides a sample documentation patch.

The discussion highlights an important distinction between build-time configuration (NO_ICONV) and test prerequisites (ICONV), which had previously been implicitly linked. Christian notes this could be addressed either as part of this series or in a follow-up, but argues the cover letter should at least acknowledge the documentation gap. This maintains the thread's focus on test behavior while surfacing a related build-system concern that may need separate attention.
