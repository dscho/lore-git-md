This is a refactoring patch in Phillip Wood's series to clean up NULL worktree parameter handling, part of the broader worktree API standardization effort. The patch introduces `get_worktree_from_repository()` to construct worktree structs from repository data, eliminating NULL worktree parameters in several key functions.

The changes focus on `wt-status.c`, where `wt_status_check_bisect()` and `wt_status_check_rebase()` now BUG() on NULL worktree parameters instead of silently accepting them. The main caller, `wt_status_get_state()`, is updated to construct a temporary worktree struct when needed. The patch maintains backward compatibility while making the API boundaries more explicit.

Key technical changes include:
- New `get_worktree_from_repository()` helper in worktree.c that constructs a worktree struct by comparing gitdir and commondir paths
- Conversion of NULL checks to BUG() assertions in the bisect/rebase status checkers
- Updated call paths in wt-status.c to use the new worktree construction
- Preservation of existing behavior through proper worktree struct initialization

The patch represents concrete progress on the NULL parameter cleanup approach validated by Junio Hamano, moving toward the goal of embedding worktree references in repository structures. It interacts with Shreyansh Paliwal's parallel wt-status cleanup work while maintaining incremental refactoring safety. The changes are focused and well-contained, touching only the necessary call sites with clear commit message explanations of the affected call chains.
