This is the second patch in Patrick Steinhardt's performance optimization series targeting shallow push handling in `git receive-pack`. The patch focuses on making `repo_parse_commit_no_graph()` more robust when dealing with commits that were previously parsed via the commit-graph.

The core issue occurs when a commit is parsed from the commit-graph (leaving its `maybe_tree` field unpopulated) and then needs to be re-parsed while the commit-graph is being written. The current implementation fails to properly re-populate the tree information in this case, leading to potential segfaults when accessing the tree.

The patch introduces a fix by having `repo_parse_commit_no_graph()` first unparse commits that were loaded from the commit-graph (detected by `parsed && !maybe_tree`), ensuring proper re-parsing of the raw object data. This change is particularly relevant for the commit-graph writing process, where it prevents crashes that could occur in `write_graph_chunk_data()`.

While the issue was only observed in test scenarios (`GIT_TEST_COMMIT_GRAPH=1`), the patch proactively addresses what could become a more general problem. The solution maintains performance by only unparsing when necessary and includes a Coccinelle rule update to allow direct `maybe_tree` access in this specific case.

This change builds on the first patch's optimizations while setting up for the third patch's planned commit-graph integration improvements. The implementation appears carefully considered, with attention to edge cases and performance implications.
