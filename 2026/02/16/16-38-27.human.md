This is part of the ongoing `the_repository` removal effort, specifically targeting the migration of global configuration variables into `struct repo_config_values`. This patch (v7 3/3 in the series) moves the `branch.autoSetupMerge` config value into the repository-specific struct, eliminating the global `git_branch_track` variable.

The change affects several commands that use branch tracking behavior (`branch`, `checkout`, `push`, and `submodule--helper`), updating them to access the value via `repo_config_values(the_repository)`. The patch preserves the default `BRANCH_TRACK_REMOTE` behavior while making it repository-specific.

This iteration incorporates feedback from Phillip Wood and resolves all known issues from previous versions, including fuzz testing regressions. The series has reached technical maturity through seven iterations, though some architectural questions remain open regarding submodule initialization and cross-repository config scoping.

The patch demonstrates the established pattern for eliminating global configuration variables in the project, with all tests passing and safety mechanisms in place to catch edge cases. While still marked RFC pending submodule handling resolution, this represents solid progress in the broader effort to libify Git by removing globals.
