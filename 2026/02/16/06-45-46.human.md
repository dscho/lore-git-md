This is the third patch in Patrick Steinhardt's v3 series improving the UI of the new `git history` command. The patch focuses on making the dry-run functionality more user-friendly by replacing the technical `--ref-action=print` option with a clearer `--dry-run` flag.

The change addresses two key issues with the original implementation: the dry-run mode was hidden behind a plumbing-style option name, making it less discoverable, and it only worked with branch updates rather than also supporting HEAD-only updates. The new `--dry-run` flag works consistently with both `--ref-action=branches` and `--ref-action=head`.

The implementation introduces a new `handle_ref_update()` helper function that either prints ref updates (for dry-run) or performs them via a transaction (for actual execution). The patch includes tests verifying the new behavior works as expected with both ref update modes.

This is a well-justified UI improvement that makes the command more intuitive while maintaining all existing functionality. The patch builds on the series' earlier work to separate validation from execution, and follows through on the goal of making `git history` more user-friendly than its plumbing counterpart `git replay`.
