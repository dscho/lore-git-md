This is a feature patch series (v4) implementing two enhancements to Git's promisor remote functionality: secure storage of remote fields via `promisor.storeFields` config and dynamic filter combination with `--filter=auto`. The series is now ready for merging after addressing all review feedback.

Christian Couder's v4 series builds on previous iterations reviewed by Patrick Steinhardt, Jean-Noël Avila, Jeff King (Peff), and Junio Hamano. The only change from v3 is a minor fix in patch 6/9 to properly initialize a variable after NULL check in the filter release logic, addressing Jeff King's robustness concern.

The series enables two key workflows: 1) secure token rotation by allowing servers to update client-side tokens via `promisor.storeFields`, and 2) dynamic filter optimization by letting servers suggest optimal filters through the new `--filter=auto` mode. The auto-filter mode combines server-suggested filters while maintaining backward compatibility with existing partial clone workflows.

Implementation touches multiple subsystems including promisor-remote handling, list-objects filtering, and fetch-pack integration. The series includes comprehensive tests and documentation updates, with security-conscious design that requires pre-configured remotes for field storage. Patrick Steinhardt has approved the technical approach, and all reviewer feedback has been incorporated across four iterations.

This completes the LOP (Large Object Promisors) effort documented in Git's technical documentation, representing a significant enhancement to partial clone capabilities. The series is rebased on current master and ready for final integration.
