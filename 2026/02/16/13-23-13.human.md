This is part 7/9 of a series implementing `--filter=auto` for promisor remotes, allowing clients to dynamically use server-suggested filters. The patch focuses on storing advertised filters in memory for the current session.

The change adds an `advertised_filter` field to `struct promisor_remote` to persist server-suggested filters even when not configured for disk storage. It introduces logic to capture these filters during remote acceptance and mark remotes as accepted in the repository state. A new `promisor_remote_construct_filter()` function is added to combine filters from all accepted remotes into a single filter spec.

The implementation handles edge cases like invalid filters (emitting warnings) and properly manages memory allocation. This is a key building block for the upcoming `--filter=auto` functionality, enabling dynamic filter composition based on server advertisements while maintaining backward compatibility.

The patch has been reviewed by Patrick Steinhardt and addresses feedback from previous iterations. It's part of a well-structured series that's now in its fourth version, indicating thorough vetting of the approach.
