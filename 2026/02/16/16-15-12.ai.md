This is the main implementation patch in a series adding UTF-8 support for Git aliases via config subsections. The patch enables non-ASCII alias names by allowing them to be defined using the `[alias "name"]` subsection syntax, while maintaining backward compatibility with the traditional `alias.name` format.

The implementation handles several key aspects:
- Adds support for case-sensitive matching of subsection aliases (while keeping traditional aliases case-insensitive)
- Uses `parse_config_key()` to properly handle the three-level config key structure
- Updates the help` subsystem to list subsection aliases correctly in `git help -a`
- Implements UTF-8-aware column alignment using `utf8_strwidth()`
- Includes comprehensive tests covering Swedish, CJK, and space-containing aliases

The patch builds on preparatory work in earlier patches in the series and addresses all feedback from previous iterations. It maintains strict validation - silently rejecting malformed dotted aliases unless the key is explicitly "command". Documentation is updated with clear examples showing both syntax forms.

Test coverage verifies:
- Case sensitivity differences between syntaxes
- Proper handling of NULL values
- Correct listing in help output
- Edge cases around subsection syntax validation
- UTF-8 display alignment

The implementation is now complete with all known issues addressed, including a shell completion fix that was added in v5. The changes touch `alias.c`, `help.c`, documentation, and tests, with careful attention to backward compatibility and clear error reporting.
