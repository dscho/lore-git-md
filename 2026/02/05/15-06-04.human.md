This is a documentation patch clarifying the behavior of `git merge-file` with respect to the `merge.conflictStyle` configuration.

Yannik Tausch noticed that `git merge-file` only respects the `merge.conflictStyle` setting when run inside a Git repository, falling back to default behavior when run outside. This appears to be based on a 2008 commit that explicitly tied config reading to repository context, but this limitation wasn't documented.

The patch proposes adding a note to the `git-merge-file` man page explaining that the configuration only takes effect inside a repository, while the `--diff3`/`--zdiff3` flags work in any context. This is a straightforward documentation improvement that would help users understand the tool's behavior without having to dig through commit history.

The change is small and focused, addressing a clear gap in the documentation. The behavior being documented appears intentional and stable, so this seems like a useful clarification to add.
