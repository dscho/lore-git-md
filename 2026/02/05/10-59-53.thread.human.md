This thread discusses the potential deprecation of the legacy `git whatchanged` command, which shows commit logs with diff output - functionality largely duplicated by `git log -p`. The discussion began with Sam Berney expressing strong opposition to removing the command, though without presenting technical justification or specific use cases that `git log -p` couldn't address.

Kristoffer Haugsbakk has since responded, explaining that both commands share the same underlying implementation and providing specific instructions for replicating `whatchanged` behavior using `git log` options (noting that `whatchanged` defaults to `--no-merges --raw` output). He points out that without usage telemetry, mailing list feedback like Sam's is the primary way to gauge user needs, though no technical obstacles to deprecation have been raised beyond personal preference.

So far no maintainers have weighed in on whether there's an active deprecation effort underway. The discussion remains focused on user sentiment rather than concrete maintenance concerns, with one user strongly attached to the command but no evidence yet presented of broader reliance on its unique behavior.
