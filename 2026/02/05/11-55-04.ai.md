This is a CI/build system patch addressing a Windows-specific issue in the Meson build integration for gitk. Patrick Steinhardt responds to Jeff King's report of a CI failure where the Windows Meson build fails due to a missing `msgfmt` tool (part of gettext).

The issue stems from the gitk build requiring `msgfmt` for localization but not properly marking it as optional when unavailable. The fix adds `required: false` to the `find_program()` call, matching the existing conditional logic that already handles cases where `msgfmt` is missing. This maintains consistency with the Makefile's behavior while fixing the Windows CI breakage.

Notably, this confirms the symlink-based approach for gitk subproject integration works on Windows, as the failure occurs after the symlink setup completes successfully. The fix has already been submitted as a pull request to the gitk repository (j6t/gitk#37), showing the issue is isolated to the gitk build configuration rather than the broader Meson integration work.

This represents one of the final hurdles in the Meson build system modernization effort, specifically addressing a Windows toolchain dependency that wasn't properly accounted for in the initial implementation. The change is small and focused, with clear justification tying it back to existing behavior in the Makefile-based build.
