This is the third patch in a refactoring series targeting `wt-status.c` as part of the ongoing `the_repository` removal effort. The patch systematically replaces remaining uses of the global `the_hash_algo` with repository-specific hash algorithms from `s->repo->hash_algo` or `r->hash_algo` in the repository parameter.

The changes affect three key areas in `wt-status.c`:
1. Cherry-pick and revert state initialization now uses the repository's hash algorithm when copying null OIDs
2. The detached HEAD check for uncommitted changes uses the repository's empty tree hash rather than the global one

The patch follows the established pattern seen in earlier parts of this series, consistently propagating repository context through function parameters rather than relying on globals. This maintains behavior while improving encapsulation, though as noted in the thread summary, some global dependencies remain (like `comment_line_str` and `DEFAULT_ABBREV`) that will need separate follow-up work.

The changes are mechanical and straightforward, with each modification simply replacing `the_hash_algo` with the appropriate repository-local reference. The patch has already gone through review cycles addressing parameter passing safety and NULL case handling, suggesting it's ready for inclusion as part of the broader `the_repository` elimination effort.
