Refactoring of `git merge-file` configuration handling, following up on earlier documentation and implementation work.

Junio C Hamano suggests a simpler approach to the recently proposed change that makes `merge-file` respect `merge.conflictStyle` outside repositories. The original patch by Yannik Tausch added explicit handling for non-repository contexts using `read_very_early_config()`, but Junio points out this duplicates logic already present in `repo_config()`. His proposed alternative would have `cmd_merge_file()` pass its `repo` parameter directly to `repo_config()`, letting that function handle both repository and non-repository cases appropriately.

This is a classic Git maintainer refinement - spotting an opportunity to use existing infrastructure more cleanly. The change would maintain all the same behavior (respecting configs both inside and outside repositories while preserving command-line flag precedence) but with simpler code. The implementation would need to drop the `UNUSED` attribute from the `repo` parameter and pass it through, which is safe since the function's callers already provide either `the_repository` or NULL appropriately.

The thread shows the project's typical pattern of incremental improvement: first documenting existing behavior, then enhancing it, and now refining the implementation. Junio's suggestion demonstrates deep knowledge of Git's config handling internals while keeping the change focused and minimal. No test changes would be needed since the behavior remains identical, just implemented via a different code path.
