Hook infrastructure refactoring for configurable hooks.

Junio Hamano provides review feedback on Adrian Ratiu's patch series that refactors Git's hook execution to support config-based hooks. This particular patch focuses on the infrastructure changes needed to run a list of hooks rather than a single hook file.

The key changes include:
- Introducing a new `list_hooks()` function that will eventually consolidate both config-based and traditional hooks (though only traditional hooks are implemented in this patch)
- Modifying the hook callback mechanism to handle multiple hooks in sequence
- Updating `hook_exists()` to use the new list-based approach
- Adding specific error messages that distinguish between config-based and traditional hooks

Junio notes several areas for potential improvement:
- The current implementation uses an empty string to represent traditional hooks, which he suggests could be made more explicit with a proper enum or struct to clearly indicate hook source
- Questions whether callers will need to distinguish between different hook types (traditional vs config-based)
- Points out that the current implementation re-runs `find_hook()` unnecessarily when executing traditional hooks

The review is generally positive but highlights some design choices that could be made more explicit as the series progresses. This patch appears to be laying groundwork for subsequent patches that will introduce config-based hook support. The changes are focused on internal plumbing rather than user-facing features at this stage.
