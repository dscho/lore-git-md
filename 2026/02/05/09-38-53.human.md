This is a final follow-up in a bugfix thread about GPG signature verification behavior. The patch, now being integrated by Junio Hamano, fixes a discrepancy where Git was rejecting signatures from keys that were valid when created but later expired, while GnuPG itself considered them valid (just noting the expiration). This caused problems for projects like the Linux kernel that rely on commit signing.

The change modifies `gpg-interface.c` to accept both `GOODSIG` and `EXPKEYSIG` status lines from GnuPG, and recognize expired-key results alongside good signatures. The security implications were vetted during review, with consensus that this better matches GnuPG's behavior and real-world signing practices.

Uwe Kleine-König confirms the final version looks good, and Junio has already queued it with a minor formatting tweak (wrapping an overlong line). The thread is now complete with no further action needed from the author. This resolves a long-standing behavioral mismatch that particularly affected Linux kernel development workflows.
