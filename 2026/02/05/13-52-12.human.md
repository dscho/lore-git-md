This is part of an ongoing RFC discussion about optimizing config access for tools like `git-credential-manager` on Windows, where individual `git config` calls create significant overhead. Derrick Stolee originally proposed a new `git config-batch` builtin, but brian m. carlson suggests that existing interfaces like `git config -l -z` might suffice for read operations, questioning whether write operations justify the complexity of a new protocol.

Stolee acknowledges this as a potentially simpler solution, noting that while credential managers do need write access, the performance-critical paths may only require reads. He references Git LFS's config handling (without NUL termination) as a similar use case, though he hasn't analyzed its exact usage patterns. The thread remains open on whether to extend existing commands or introduce new ones, with the performance benefits for Windows credential management still the primary motivator.
