This is the third patch in a 4-part series refactoring Git's TRACE2 process ancestry tracing, specifically targeting the Windows implementation. The patch refactors how Windows process ancestry information is collected and emitted, separating the data collection from the JSON formatting.

The key changes:
- Splits the ancestry collection into two phases: first gathering process names into a `strvec`, then formatting them into JSON
- Maintains the same data_json event format for backward compatibility
- Prepares for a future change to use the newer `cmd_ancestry` event (which will be introduced in patch 4)
- Keeps all the same process discovery logic and cycle detection from the original implementation

The refactoring is mechanical and doesn't change the observable behavior - it still emits the same JSON-formatted ancestry chain via `trace2_data_json()`. The separation of concerns makes the code more maintainable and paves the way for the format unification coming in the next patch.

This continues the series' pattern of careful cross-platform alignment while preserving backward compatibility. The changes are confined to Windows-specific code in `compat/win32/` and follow the same process discovery limits (10-level depth) and error handling (cycles, truncation) as before.
