This is a documentation patch addressing a usability issue with Git's performance tests. Seth McDonald reports that the performance test suite silently fails when run without GNU `time` installed, despite this being a hard requirement. The issue was discovered on Debian GNU/Linux 13 where the default `time` command wasn't GNU-compatible.

The email suggests two potential solutions: either better document the GNU `time` requirement in relevant files (INSTALL, t/README, or t/perf/README), or have the tests explicitly check for and report the missing dependency. The author notes they're not yet familiar enough with the codebase to submit a patch themselves.

This appears to be a straightforward quality-of-life improvement that would help new contributors avoid confusion when running performance tests. The issue seems well-motivated and the proposed solutions reasonable, though the actual implementation would need to be done by someone more familiar with the test infrastructure.
