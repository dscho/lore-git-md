This is the third patch in a series refactoring Git's process ancestry tracing for TRACE2, specifically targeting Windows compatibility. The patch refactors the Windows implementation to separate the collection of process ancestry data from its JSON formatting, preparing for future unification with the Unix-style `cmd_ancestry` event format.

The key changes:
- Splits the Windows process info collection into two steps: gathering parent process names into a `strvec` first, then formatting as JSON separately
- Maintains backward compatibility by still emitting the existing `data_json` event with the same content
- Keeps all the existing process lookup logic and cycle detection from the original implementation

The refactoring is clean and focused, with no behavior changes yet - this is groundwork for patch 4 which will presumably introduce the new event format. The commit message clearly explains the motivation and connects it to prior work (353d3d77 for Windows tracing and 2f732bf1 for the Unix ancestry event).

This continues the series that has been well-structured so far, showing attention to cross-platform consistency while maintaining backward compatibility for existing TRACE2 consumers. The changes are confined to Windows-specific code, touching only the process info collection implementation.
