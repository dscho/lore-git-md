Bugfix addressing edge cases in symlink whitespace handling during diffs and applies. This is a follow-up to Junio C Hamano's initial patch that prevented incorrect incomplete-line checks (WS_INCOMPLETE_LINE) on symbolic links.

The discussion focuses on refining the conditions under which these whitespace checks should be skipped. Patrick Steinhardt suggests more precise rules: only disable checks when one side is missing and the other is a symlink, or when both sides are symlinks. Junio agrees this is a good starting point but notes it may need further adjustment for text-to-symlink transitions.

A secondary question arises about whether to support newline-terminated symlink targets, though both participants consider this an extreme edge case not worth worrying about. Junio also clarifies that Git doesn't track or diff symrefs (like those in .git/refs/) in the first place.

The patch appears technically sound but needs minor refinement to handle mode changes properly. This is a focused fix to a specific edge case in the diff/apply machinery, with the maintainer and a core contributor aligned on the general approach.
