Karthik Nayak confirms understanding of a key architectural constraint in the current implementation - the limitation to single transactions per Git process. The exchange documents that while this is a current limitation of the files backend implementation, the architecture leaves room for future backends to potentially support parallel transactions if they can manage the storage layer differently.

The discussion serves as important documentation of the design boundaries for future work, noting that the transaction API could evolve if the underlying object writing architecture changes.
