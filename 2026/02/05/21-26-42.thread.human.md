This thread addresses CI breakage in Git's GitHub Actions workflows caused by a buggy `dirname` implementation in uutils coreutils v0.2.2 that recently landed in Ubuntu's rolling release. The issue affects 7 CI job configurations when `dirname "foo/."` incorrectly outputs "." instead of "foo".

Three solution approaches were considered: Junio Hamano initially proposed switching from `ubuntu:rolling` to `ubuntu:latest` Docker images for stability, while Collin Funk suggested co-installing GNU coreutils. Patrick Steinhardt advocated a middle path of targeted workarounds while engaging upstream. Colin Stagner then implemented Patrick's approach by modifying `ci/install-dependencies.sh` to create a symlink from `/usr/bin/dirname` to GNU coreutils' implementation when available.

Junio has now accepted Colin Stagner's solution as the immediate fix, though he noted the `-T` flag in the symlink command is non-POSIX and unnecessary. He maintains a pragmatic stance, willing to try this targeted approach first while keeping the fallback option of abandoning `ubuntu:rolling` if further breakages occur. The discussion reflects Git's careful balance between testing with cutting-edge dependencies and maintaining CI stability, with the project showing preference for precise fixes over broad workarounds when possible.

The thread demonstrates Git's CI infrastructure evolution and its role as a test case for emerging platform changes. While this specific `dirname` issue appears resolved, the broader questions about Git's CI philosophy regarding bleeding-edge versus stable dependencies remain open for future discussion. Patrick Steinhardt is positioned to drive any follow-up work engaging with the uutils project for longer-term stabilization.
