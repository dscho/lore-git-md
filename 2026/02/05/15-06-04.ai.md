Documentation patch clarifying `merge-file` behavior with `merge.conflictStyle`.

This is a documentation patch that aims to clarify an edge case in `git merge-file`'s behavior. The author, Yannik Tausch, notes that while `git merge-file` accepts `--diff3` and `--zdiff3` flags anywhere, it only respects the `merge.conflictStyle` configuration when run inside a Git repository. This behavior, while intentional (dating back to 2008), is not currently documented.

The proposed change would add a note to the `git-merge-file` man page explaining this limitation. The patch appears straightforward and well-motivated - it addresses a real point of confusion without making any functional changes. The suggested wording is clear and appropriately concise for a man page note.

This touches the documentation subsystem and relates to configuration handling, though it doesn't require any code changes. The patch seems uncontroversial and likely to be accepted, assuming the maintainers agree the clarification is useful. The author appears to have done their homework by checking the historical context before proposing the doc change.
