This is a discussion about the potential deprecation of the legacy `git whatchanged` command, which shows commit logs with diff output. The thread was initiated by a user complaint, with Kristoffer Haugsbakk now responding to clarify the rationale for considering removal.

Haugsbakk explains that `git whatchanged` is essentially redundant with `git log -p`, as both commands use the same underlying machinery but with different defaults. He provides specific migration advice, noting that `git log --no-merges --raw` can serve as a direct replacement, while suggesting `--stat` or `--name-only` might be more readable alternatives for human consumption.

The response highlights Git's lack of telemetry, framing mailing list discussions as the project's primary feedback mechanism. While acknowledging the user's attachment to the command, Haugsbakk maintains a pragmatic stance about its technical redundancy. No active deprecation timeline is mentioned, but the exchange makes clear this is part of an ongoing conversation about streamlining Git's command set by removing functionally duplicated legacy tools.
