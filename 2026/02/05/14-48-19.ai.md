This is a follow-up in the ongoing security discussion about ANSI escape sequence sanitization in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). Junio Hamano revisits his earlier position on the patch series' rollout strategy, now acknowledging that Johannes Schindelin's approach of shipping the sanitization by default (with opt-out via `WITH_BREAKING_CHANGES`) may be more practical for real-world testing than his previously suggested opt-in model.

The key shift is Junio recognizing that testing the sanitization behavior requires broad exposure - something only achievable if the changes are active by default in the `next` branch, where more contributors run the code daily. His initial concern about breaking existing workflows remains, but he now sees value in catching those breaks early through wider deployment rather than limiting testing to a small subset of users who would explicitly opt-in via compile-time flags.

This email signals the maintainer's evolving stance on balancing security hardening against compatibility, moving toward accepting that some breakage may be necessary to properly evaluate the real-world impact of these protections. The discussion continues to center on how to handle legitimate uses of control sequences (like terminal title updates) while preventing malicious injection, but the implementation strategy debate appears to be resolving in favor of Schindelin's default-on approach.
