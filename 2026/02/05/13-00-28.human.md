This is a documentation patch that adds AI-assisted translation guidelines to Git's l10n (localization) workflow. It's the second part of a two-patch RFC series from Jiang Xin, the Chinese translation maintainer, proposing optional AI tooling for .po file translations while maintaining human oversight.

The patch significantly expands po/README.md with detailed instructions for using AI in translation work, covering:
- Clear boundaries on AI's role (assistant only, with humans retaining control)
- Technical specifications for AI tools to follow when processing .po files
- Quality checklists and workflows for reviewing AI-generated translations
- Practical guidance on splitting large files and handling plural forms
- Updated `git-po-helper` command examples with the `--pot-file=build` option

The documentation takes a pragmatic approach - it doesn't resolve the ongoing philosophical debate about AI-generated content (raised by brian m. carlson and others in the thread) but provides concrete technical guidelines for those who choose to use AI tools. The implementation appears thorough and well-considered, with particular attention to maintaining translation quality and consistency.

This builds on the first patch in the series (which added .gitattributes rules for location filtering) to complete the infrastructure for optional AI-assisted workflows in Git's localization process. The documentation is comprehensive while keeping all l10n guidance consolidated in README.md rather than splitting it across files.
