This is a refactoring patch that addresses compiler warnings introduced by glibc 2.43's stricter const-correctness for string functions in C23 mode. The patch makes pointers const when they point to data that isn't modified, particularly for return values from functions like strrchr() and memchr().

The change was prompted by new warnings from glibc 2.43 when compiling with GCC 15 in C23 mode (-std=gnu23). The warnings occur when assigning the result of string functions to non-const pointers when the input was const-qualified. The patch touches 28 files across the codebase, consistently applying the same pattern: changing pointer declarations to const when they receive the result of string search functions where the pointed-to data isn't modified.

The changes are mechanical and focused on eliminating compiler warnings rather than changing behavior. Each modification follows the same straightforward pattern of adding const to pointer declarations that receive results from string search operations. The patch appears well-scoped and correctly targeted - it only touches cases where the returned pointer is clearly not used for modification.

This is part of the ongoing effort to maintain compatibility with modern C standards and compiler versions. The changes are low-risk since they only affect type declarations without altering the underlying operations. The patch demonstrates good attention to detail by catching all the similar cases across the codebase in a single pass.
