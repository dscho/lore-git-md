This thread introduces a 4-patch series extending Git's TRACE2 process ancestry tracing to macOS while refactoring the Windows implementation. The work builds on prior commits 353d3d77 (Windows) and 2f732bf1 (Linux). Patch 1 adds macOS support via new `compat/darwin/procinfo.c` using macOS syscalls (`sysctl` with `KERN_PROC`) to recursively gather parent process IDs and names up to PID 1 (launchd) with depth limit of 10 (NR_PIDS_LIMIT) to prevent cycles. It emits ancestry via `trace2_cmd_ancestry()` to match Linux's format rather than Windows's `data_json`, ensuring consistent Unix behavior.

Patch 2 adds build system support for the new `compat/darwin/procinfo.c` across all three supported build systems (Makefile, CMake, Meson), following existing patterns for platform-specific code. Each build system conditionally includes the Darwin implementation when building on macOS.

Patch 3 refactors the Windows implementation to separate data collection from JSON formatting while maintaining backward compatibility. It splits ancestry collection into two phases: gathering process names into a `strvec` first, then formatting them into JSON via `trace2_data_json()`. The changes are mechanical with no behavior change, keeping the same process discovery logic, cycle detection, and 10-level depth limit. This prepares for format unification in patch 4.

Pending patch 4 will complete the series by aligning Windows to use the newer `cmd_ancestry` event format while maintaining backward compatibility. The changes remain confined to platform-specific compatibility code (Darwin/Windows) and build files, showing careful attention to cross-platform consistency. No reviews or objections have been raised yet; the thread contains only the initial submission and follow-up patches.
