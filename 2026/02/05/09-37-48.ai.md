This is a build system patch discussion regarding Meson integration of Git's GUI components (gitk and git-gui). Jeff King reports a build failure in the GitHub Actions Windows+Meson CI job where `msgfmt` (a gettext utility) is not found when building gitk.

The issue occurs in the v2 patch series from Patrick Steinhardt that wires up gitk and git-gui as Meson subprojects using a symlink approach to preserve the original source layout. While the core architectural questions about the symlink approach have been resolved, this new report highlights a practical Windows build issue where the gettext toolchain appears to be missing in the CI environment.

The failure suggests that while the symlink approach works in principle (as confirmed by earlier reviews), there may be additional toolchain dependencies that need to be handled for Windows builds. This is particularly relevant given Junio Hamano's earlier concerns about Windows symlink reliability and the need for Developer Mode - the current issue is separate from those concerns but shows another Windows-specific consideration.

The thread has progressed from architectural discussions to practical implementation issues, with this being the first concrete CI failure reported against the v2 series. The missing `msgfmt` suggests either a need to make the gettext dependency optional (as it may not be strictly required for gitk) or to ensure the Windows CI environment is properly provisioned with gettext tools.
