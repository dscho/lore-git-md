This is the final patch in a 4-part series unifying process ancestry tracing across platforms, specifically bringing Windows in line with the newer `cmd_ancestry` event format while maintaining backward compatibility.

The patch modifies the Windows implementation to emit ancestry data through both the existing JSON format (preserved for compatibility) and the newer `trace2_cmd_ancestry()` interface introduced for Linux and macOS in earlier patches. The change is confined to `compat/win32/trace2_win32_process_info.c` where it adds the new emission path alongside the old one, with a clear comment explaining the dual-emission strategy.

The implementation follows the pattern established in patch 3's refactoring, where process names were separated from JSON formatting. Now those names can be reused for the new event type without additional data collection. The patch maintains all existing behavior around cycle detection (10-level depth limit) and process name gathering.

This completes the series' goal of consistent ancestry tracing across platforms while carefully handling backward compatibility for existing TRACE2 consumers. The changes are minimal and focused, building logically on the preparatory work in earlier patches. No behavioral changes are introduced beyond the additional event emission.
