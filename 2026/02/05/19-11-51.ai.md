This is a documentation patch discussion about `git merge-file`'s configuration behavior, with the maintainer suggesting a potential extension beyond the original scope.

Junio C Hamano responds to Yannik Tausch's observation that `git merge-file` only respects the `merge.conflictStyle` configuration when run inside a Git repository. While agreeing the current behavior should be documented, Junio proposes going further by allowing the command to read system and user-level settings even outside a repository - a capability that didn't exist when the original behavior was implemented in 2008.

The thread shows the maintainer recognizing a legitimate documentation gap while simultaneously identifying an opportunity to improve the feature's behavior. This suggests the discussion may evolve from a simple documentation clarification to a small feature enhancement, though the core issue remains accurately documenting the current repository-dependent behavior of `merge.conflictStyle` configuration.

Key technical points for future reference: the command currently checks for repository context before reading any configuration (per 2008's b541248467), but could potentially be modified to honor system/user config files regardless of repository context. The `--diff3` and `--zdiff3` flags work universally as they bypass configuration entirely.
