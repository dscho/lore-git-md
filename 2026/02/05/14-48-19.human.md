This is a follow-up in the ongoing security discussion about ANSI escape sequence handling in Git's sideband channel. Junio Hamano, the Git maintainer, is reconsidering his earlier position on how to structure the patch series for sanitizing control characters in remote messages.

Junio now agrees with Johannes Schindelin's approach of implementing the sanitization changes first (keeping the current permissive behavior by default) before flipping the default to be restrictive. His change of heart comes from recognizing that testing the new sanitization code in the wild requires it to be active in `next` - something that wouldn't happen if it were opt-in only. He notes that while color sequences are known to be widely used, this approach will help surface any legitimate uses of other control sequences before locking things down.

The thread has seen significant back-and-forth about security versus functionality tradeoffs, with Junio previously advocating for an opt-in model and raising concerns about breaking legitimate uses like terminal title updates. This email marks a pragmatic shift toward Johannes's implementation strategy while still leaving open the larger architectural questions about whitelist vs. blacklist approaches to control character handling. The discussion remains active but now appears headed toward merging the technical infrastructure first before settling the default behavior.
