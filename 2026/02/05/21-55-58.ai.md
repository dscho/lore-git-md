This is a bugfix and documentation patch for `git merge-file`'s handling of the `merge.conflictStyle` configuration. The patch follows up on earlier discussion that identified an inconsistency where the command would respect this config only in repository contexts while accepting command-line flags universally.

The implementation now leverages Git's existing config machinery more cleanly by passing the `repo` parameter directly to `repo_config()`, which automatically handles both repository and non-repository cases. This matches Junio Hamano's suggestion to simplify the code while maintaining identical behavior. The change demonstrates how Git's config system has evolved to handle both contexts uniformly.

Documentation updates clarify that `merge.conflictStyle` is honored in all contexts, with Kristoffer Haugsbakk's suggested improvements to wording and formatting incorporated. The test suite gains a new case verifying the behavior outside a repository context, using the standard expect/actual naming convention.

The patch represents the final iteration of this fix, having addressed all feedback from both technical and documentation reviewers. It provides a clean solution to a long-undocumented inconsistency while following Git's principle of reusing existing infrastructure where possible. The change is small but meaningful for users who rely on consistent conflict style behavior across repository and non-repository contexts.
