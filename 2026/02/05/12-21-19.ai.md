Bugfix follow-up discussing edge cases in symlink whitespace handling. Patrick Steinhardt raises two technical considerations about Junio's proposed fix for incorrect WS_INCOMPLETE_LINE checks on symbolic links.

First, he notes the current patch would disable incomplete-line checks for both sides of a diff if either side is a symlink, which could be problematic when a diff includes a mode change (e.g., converting a regular file to a symlink). He suggests more precise conditions: only disable the check when either one side is missing and the other is a symlink, or when both sides are symlinks.

Second, he questions whether symlinks with newline-terminated targets should theoretically be supported, acknowledging this is an extreme edge case that likely doesn't worth worrying about in practice. The comment suggests the overall approach is sound but could benefit from tighter handling of the mode-change case.

This is a focused technical review from a core contributor, identifying a subtle interaction the original patch didn't account for. The tone is constructive and the concerns are well-motivated, though the second point is explicitly downplayed as not critical. The thread appears headed toward a small refinement of the fix rather than any fundamental rethinking.
