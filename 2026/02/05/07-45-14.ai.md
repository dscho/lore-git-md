This is a documentation patch addressing a missing requirement for Git's performance tests. Seth McDonald reports that the performance test suite silently fails when run without GNU time installed, as the tests depend on GNU-specific features of the `time` command. The issue was discovered on Debian GNU/Linux 13 where the default `time` command is not the GNU version.

The email suggests two potential solutions: either document the GNU time requirement more prominently (in INSTALL, t/README, or t/perf/README), or have the tests explicitly error out when GNU time is not found. The author notes they're not yet familiar enough with the codebase to submit a patch themselves, so this is effectively a bug report rather than a proposed fix.

The issue touches the performance test infrastructure (t/perf/) and would primarily affect new contributors or developers setting up test environments. The problem is particularly subtle because the tests fail silently rather than providing a clear error message about the dependency. This matches a known pattern in Git's test infrastructure where platform-specific requirements sometimes aren't well-documented until someone hits the issue.
