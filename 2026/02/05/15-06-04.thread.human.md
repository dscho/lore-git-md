This thread documents and improves the behavior of `git merge-file` when reading the `merge.conflictStyle` configuration. The original implementation from 2008 worked inconsistently - respecting the config only in repository contexts while accepting command-line flags everywhere. Yannik Tausch identified this discrepancy and proposed a solution through multiple iterations.

The final patch makes the config work consistently outside repositories by properly using Git's config infrastructure. Junio Hamano provided key guidance to simplify the implementation, while Kristoffer Haugsbakk reviewed the documentation and test organization. Patrick Steinhardt has now confirmed the technical soundness of the approach, particularly noting that error handling for unknown config keys is already properly managed. 

The solution maintains the existing precedence order (command-line flags override repo config which overrides global config) while working in all contexts. A new test case verifies the behavior outside repositories. With all feedback addressed and multiple experienced reviewers approving, this change is ready for integration. It will provide more consistent behavior while being simpler and better documented than before. The thread also serves as a good example of the Git patch submission and review process.
