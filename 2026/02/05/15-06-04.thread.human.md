This thread documents and implements consistent behavior for `git merge-file`'s handling of the `merge.conflictStyle` configuration. The original issue was that the command respected this config only in repository contexts while accepting command-line flags universally - behavior that had existed since 2008 but was never properly documented.

Yannik Tausch drove the solution through multiple iterations, initially documenting the existing behavior before implementing a fix that would work outside repositories. Junio Hamano provided key architectural guidance, suggesting using the existing `repo_config()` infrastructure rather than introducing new config-reading logic. Kristoffer Haugsbakk contributed documentation polish and test style observations.

The final version uses `repo_config()` directly, maintains the existing precedence order (CLI flags > repo config > global config), and adds a new test case verifying the behavior outside repositories. The documentation has been updated to accurately describe the behavior. Junio also took the opportunity to provide detailed guidance about Git mailing list conventions, emphasizing that patches should generally be sent as separate messages rather than embedded in replies.

With Kristoffer confirming his feedback has been addressed and no remaining open issues, this thread serves both as a complete technical solution and as a reference for proper patch submission practices. The change is small but meaningful for users relying on consistent conflict style behavior, demonstrating Git's config system evolution to handle both repository and non-repository cases uniformly.
