This thread addressed an inconsistency in how `git merge-file` handles the `merge.conflictStyle` configuration. The command previously respected this setting only when run inside a repository, while accepting command-line flags universally - behavior that had gone undocumented since its 2008 introduction. Yannik Tausch identified the issue and drove the solution through multiple iterations, with key input from Junio Hamano, Kristoffer Haugsbakk, and Patrick Steinhardt.

The final patch makes the behavior consistent by using Git's standard `repo_config()` infrastructure to read the setting regardless of repository context, while maintaining the existing precedence order (command-line flags override config). Patrick verified the error handling remains correct through the existing `git_xmerge_config()` mechanism. The solution includes proper documentation updates and a new test case verifying the behavior outside repositories. 

Junio has given his final approval, marking this ready for merging. The thread serves as a good example of identifying and fixing a long-standing inconsistency while following Git's development practices - from initial problem identification through architectural refinement, documentation standards, and multi-reviewer validation.
