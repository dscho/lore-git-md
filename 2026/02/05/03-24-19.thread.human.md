Collin Funk has been working on a series to address const-correctness warnings that appear when compiling Git with GCC 15 in C23 mode. The changes add const qualifiers to pointers that receive results from string search functions like strrchr() and memchr() where the underlying data isn't modified. This is a mechanical change affecting 28 files but doesn't alter any behavior - it makes the code properly const-correct for modern compilers.

Jeff King (Peff) reviewed the series and confirmed the technical correctness, though he noted that removing a NULL initialization in gpg-interface.c (from an earlier patch) might have been better as a separate change. Junio Hamano has now also reviewed and approved the series, agreeing with Peff's assessment. While the gpg-interface.c change could have been split out, the series as a whole is ready to be merged. This work continues Git's ongoing effort to maintain compatibility with modern C standards and follows similar const-correctness patterns that Peff has worked on before.
