This is a bugfix and documentation patch for `git merge-file`'s handling of the `merge.conflictStyle` configuration. The patch ensures the command respects this config setting even when run outside a Git repository, matching the behavior with command-line flags.

Yannik Tausch's patch follows up on feedback from Junio C Hamano and Kristoffer Haugsbakk. The key change simplifies the implementation by using `repo_config()` directly rather than checking `have_repository`, since `repo_config()` already handles non-repository cases. The patch also documents that `merge.conflictStyle` affects the command's output format.

The changes since v1 incorporate Junio's architectural suggestion to leverage existing config machinery and Kristoffer's documentation formatting improvements. Tests confirm the config is now properly read outside repositories, with conflict markers appearing in the configured style. The patch maintains backward compatibility while fixing an inconsistency that dates back to 2008.
