This is a feature patch series adding process ancestry tracing for macOS to Git's TRACE2 system, while refactoring the existing Windows implementation to match the Linux approach.

The series builds on prior work that added process ancestry tracking - Windows got a custom JSON event in commit 353d3d77, while Linux uses procfs (2f732bf1). This patch set:
1. Implements macOS process ancestry collection using system APIs
2. Refactors the Windows code to emit the same `cmd_ancestry` event type as Linux/macOS, while maintaining backward compatibility
3. Adds the necessary build system changes to include the new macOS implementation

The changes are platform-specific, touching Windows and macOS compatibility code. The macOS implementation appears thorough, using `sysctl` and `proc_pidinfo` to walk the process tree. The Windows refactoring keeps the old behavior while aligning with the newer event type convention.

This looks like a well-scoped addition that follows existing patterns. The backward compatibility consideration for Windows TRACE2 consumers shows good attention to real-world impact. The series would be of interest to anyone using TRACE2 for performance monitoring or debugging, particularly on macOS where this functionality was previously missing.
