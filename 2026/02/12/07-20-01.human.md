Bugfix for diffcore-break in partially cloned repositories, addressing a dangling pointer issue during diff operations with prefetched blobs. This is the second version of the patch from Han Young (first-time contributor), now including a test case as requested by maintainer Junio C Hamano.

The patch fixes a segmentation fault that could occur in blobless clones (`--filter=blob:none`) when performing operations like `git reset` that involve diff calculations on large files. The root cause was that `diffcore_break()` freed a queue structure without NULLing the pointer, which could lead to crashes when blob prefetching occurred. The fix is straightforward - setting the queue entry to NULL after freeing the file pair.

This version adds a test case that demonstrates the issue by using `git reset` to trigger the faulty diff operation, as the bug doesn't manifest with regular `git diff` commands. The test follows the pattern of a similar fix from December 2025 (commit 56d388e6) for a related segfault in the diff machinery.

The patch shows good understanding of both the diff machinery and partial clone interactions. With the test case now included and the prior feedback addressed, this looks ready for consideration. The fix is narrowly scoped to the specific issue, though it may prompt maintainers to consider whether a broader audit of similar patterns in the diff machinery is warranted.
