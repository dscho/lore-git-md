This is a follow-up patch series in the ongoing ODB (object database) abstraction effort, focusing on cleaning up flag definitions related to object information queries. Patrick Steinhardt sends a five-patch series that addresses inconsistencies in how `OBJECT_INFO_*` and `HAS_OBJECT_*` flags are defined and used.

The changes are relatively mechanical but touch several subsystems that interact with object storage. The thread context shows this builds on prior discussion about enum type safety in the ODB API, with contributions from multiple reviewers validating the changes across different parts of the codebase. The series appears well-tested and addresses a real inconsistency, though the impact is primarily internal code quality rather than user-visible behavior.
