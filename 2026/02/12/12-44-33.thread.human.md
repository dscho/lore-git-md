This thread discusses Patrick Steinhardt's improvements to the new `git history` command's user interface, focusing on making it more robust and user-friendly. The 4-patch series addresses two main pain points: validation timing and option naming.

The first patch, which just arrived, restructures when validation checks occur during command execution. Previously, users could spend time crafting a commit message only to have the command fail later due to invalid conditions (like trying to rewrite non-ancestor commits). The new version performs all validation upfront before any user interaction begins, preventing wasted effort. The changes are carefully isolated to maintain existing behavior when validation succeeds while moving failure detection earlier in the process.

The series will continue with three more patches that rename technical options (`--ref-action`) to clearer alternatives (`--dry-run` and `--update-refs`), but this first patch stands alone as an important usability fix. The implementation shows Patrick's characteristic attention to incremental improvement, with clean separation between validation timing changes and the upcoming option renaming work. Test updates verify the new behavior, particularly around critical cases like `--ref-action=head` validation.
