This is part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically addressing flag handling in the object storage layer. The patch focuses on cleaning up gaps in the `OBJECT_INFO_*` flag values in `odb.h`.

The change removes historical gaps in the flag bit values that were left behind when previous flags (`OBJECT_INFO_SKIP_CACHED` and `OBJECT_INFO_ALLOW_UNKNOWN_TYPE`) were removed. The patch renumbers the remaining flags to use consecutive bits (0-3) with explicit shift operations, making the sequence more logical and removing potential confusion about missing values.

This is a straightforward refactoring that maintains all existing behavior while improving code clarity. It follows earlier work in this thread that addressed similar inconsistencies in both `OBJECT_INFO_*` and `HAS_OBJECT_*` flag usage. The change is mechanical but meaningful - it helps prevent future maintainers from wondering whether the gaps indicate some hidden meaning or flags defined elsewhere.

The patch has already been reviewed by Justin Tobler and Karthik Nayak in previous iterations, with Junio Hamano overseeing the broader ODB API design decisions. This appears to be a non-controversial cleanup that aligns with the thread's focus on improving type safety and consistency in the object storage layer.
