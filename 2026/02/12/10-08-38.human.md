This is part 7/9 of a series implementing the LOP (Large Object Promisors) effort, focusing on storing server-advertised filters in memory. The patch adds infrastructure needed for the upcoming `--filter=auto` feature.

The key changes in this patch are:

1) Adds an `advertised_filter` field to `struct promisor_remote` to persistently store filters advertised by servers during the current session, even when not configured for disk storage via `promisor.storeFields`.

2) Modifies `filter_promisor_remote()` to capture advertised filters into a temporary list and apply them to the promisor remote structs after any configuration reload, ensuring filters remain available.

3) Introduces a new `promisor_remote_construct_filter()` function that combines filters from all accepted promisor remotes into a single filter spec. This handles validation and memory management while warning about invalid filters.

The implementation carefully tracks which remotes have been accepted and ensures their filters remain available for the session. This enables the subsequent patch's `--filter=auto` functionality while maintaining security and validation. The changes are well-contained to the promisor-remote subsystem and include proper memory management.

Christian Couder has addressed feedback from Patrick Steinhardt and others in previous iterations, and the patch appears ready for inclusion as part of the larger series. The changes are technical plumbing work that enables the more user-visible `--filter=auto` feature coming in patch 9/9.
