This is a follow-up discussion in the ongoing patch series about inter-file navigation in Git's hunk selection interface. Junio Hamano is responding to Samuel Abraham's proposal for handling the UI when all hunks in a file have been decided.

Junio expresses cautious approval of Samuel's compact prompt design ("What now? (was: n) [y,n,q,a,d,s,e,>,<,p,P,?]?") but raises concerns about potential user confusion when switching between "Stage this" and "What now" phrasing. He questions whether explicitly indicating all hunks are decided is necessary, suggesting the existing (was: X) notation combined with disabled navigation keys might provide sufficient cues.

The discussion reveals a tension between UI compactness and clarity - while the maintainer personally prefers the minimal approach, he's considering the broader user experience impact. Junio floats the idea of moving detailed status information to the help text ('?') as a compromise, keeping the main prompt clean while still making the information available when needed.

This exchange represents the final open question in an otherwise technically solid series, with the prompt design being the last design decision before finalization. The author has been responsive to feedback throughout, and this iteration shows both parties thoughtfully considering edge cases and user experience implications.
