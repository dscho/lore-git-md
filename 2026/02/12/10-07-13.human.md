This is a technical discussion about the LOP (Large Object Promisors) patch series, specifically addressing how Git handles missing objects when multiple promisor remotes are configured.

Christian Couder clarifies the current behavior when objects are missing from multiple promisor remotes: Git attempts to fetch them in the order the remotes appear in the config file, falling back to the main remote if needed. He notes this behavior predates the current patch series and is documented in the partial clone documentation. 

The email also mentions a longer-term plan to make the fetch order configurable, referencing a proposed GSoC 2026 project ("Implement promisor remote fetch ordering") that would address this. This provides useful context about future directions while confirming the current implementation's behavior remains unchanged by the LOP series.

The discussion shows the series is nearing completion, with most documentation and implementation details already resolved. The remaining open question about object location works with multiple promisor remotes appears to be more of a design consideration for future work rather than a blocker for the current series.
