This is a performance optimization patch targeting Git's diff machinery, specifically the `--anchored` mode in the patience diff algorithm. Phillip Wood proposes a change to how anchor lines are checked during diffing to avoid unnecessary work.

The key insight is that an anchor line must appear exactly once in each file being compared. The current implementation checks every line for anchor status upfront and caches the result, but this patch delays the check until we know a line appears exactly once in both files. This eliminates redundant checks for lines that can't possibly be anchors.

The patch shows measurable speedups - about 2% for typical cases (like diffing 5000 commits in git.git) and up to 16% for extreme cases with many deletions. The implementation removes the `anchor` field from hashmap entries since caching is no longer needed, and moves the `is_anchor()` check to the point where we know we have a potential match.

The change is focused and well-motivated, touching only the xdiff patience implementation while maintaining the same behavior. The commit message provides clear before/after performance numbers and includes a minimal test case demonstrating the improvement. This appears to be a straightforward optimization that should be uncontroversial.
