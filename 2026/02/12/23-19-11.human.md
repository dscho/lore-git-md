This is a documentation patch that has now been finalized and is ready for integration. The patch adds explicit warnings about the security risks of round-tripping patches through `git format-patch` and `git am`, particularly highlighting how embedded diffs in commit messages can be misinterpreted during patch application.

The patch has gone through three iterations (v3) with feedback from Phillip Wood and others, and Junio Hamano has now reviewed and approved the final version. The documentation changes will appear in multiple man pages (`git-am`, `git-format-patch`, `git-send-email`) via shared include files, warning users about parsing hazards when patches contain ambiguous content that might be mistaken for part of the patch itself.

This is part of a broader security-focused discussion about making `git am` safer when processing patches, with multiple complementary solutions being considered (including Jeff King's proposed `--strict` mode and Patrick Steinhardt's `--accept-ambiguous-patch` flag). The documentation serves as an immediate improvement while the technical solutions are being finalized.

Junio indicates he plans to queue this for the 'next' integration branch, meaning it will likely appear in an upcoming Git release unless issues surface during final testing. The patch appears well-vetted at this point, having incorporated feedback from security-conscious contributors.
