This is the third patch in Patrick Steinhardt's series improving the `git history` command's UI. The patch focuses on making the dry-run functionality more user-friendly by replacing the technical `--ref-action=print` option with a clearer `--dry-run` flag.

The change addresses two issues with the current implementation: the dry-run mode was hidden behind a plumbing-style option name, and it only worked with branch rewrites (not HEAD-only updates). The new `--dry-run` flag works consistently with both `--ref-action=branches` and `--ref-action=head`, making it more discoverable and flexible.

The implementation refactors the reference update logic to handle both actual updates and dry-run printing through a new `handle_ref_update()` helper function. The patch includes thorough test updates to verify the new behavior works as expected with both reference update modes.

This continues the series' theme of improving user experience while maintaining robust functionality. The change is well-contained and builds on the previous validation improvements, keeping the command's behavior predictable and well-tested.
