This is a follow-up review of a patch in Patrick Steinhardt's series improving the `git history` command's dry-run functionality. Junio C Hamano acknowledges the usability improvement of replacing the technical `--ref-action=print` option with a more intuitive `--dry-run` flag, but raises an important clarification about object creation behavior.

The key technical point is that while the dry-run mode doesn't update references (as documented), Junio wants explicit confirmation that it still creates the necessary commit objects in the object database. This ensures users could later point references to these objects without corruption. The implementation appears sound otherwise, with tests verifying the new flag works with both `--ref-action=head` and `--ref-action=branches` modes.

This continues the thread's pattern of refining the command's interface while maintaining technical correctness.
