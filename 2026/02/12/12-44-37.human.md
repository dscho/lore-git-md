This is the final patch in Patrick Steinhardt's series improving the `git history` command's reference update behavior. The patch renames the `--ref-action` option to `--update-refs` to better reflect its current functionality after the previous changes in the series.

The change is straightforward: since the option now only controls *which* references will be updated (branches or just HEAD) rather than *how* they're updated, the new name is more accurate. The patch updates the documentation, command-line help text, and tests to use the new option name while maintaining all existing behavior.

This completes the series' goal of improving the command's UI by:
1. Moving validation earlier (patches 1-2)
2. Adding flexible dry-run functionality (patch 3)
3. Using clearer option names (this patch)

The changes are well-contained and maintain compatibility with both existing use and planned future features like `git history split`. As with the rest of the series, this patch demonstrates Patrick's attention to both technical correctness and user experience.
