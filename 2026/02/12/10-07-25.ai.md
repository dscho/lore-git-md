This is part 8 of a 9-patch series implementing `--filter=auto` mode for promisor remotes, building on the LOP (Large Object Promisors) effort. The patch addresses naming feedback from Patrick Steinhardt and Junio C Hamano regarding how to refer to the subset of advertised filters that a client accepts. The key change is renaming the variable from `advertised_filter` to `accepted_filters` to better reflect that it represents only the filters the client has chosen to use, not the full set advertised by the server.

The discussion confirms the conceptual model where servers advertise available filters and clients select a subset to accept. This patch follows through on Patrick's suggestion to make this distinction clearer in the code. Junio's approval of the naming choice helps resolve this minor point in the series. The change is straightforward and doesn't affect the overall design or functionality - it's purely about improving code clarity and maintainability through better variable naming.

This continues the series' pattern of incorporating review feedback to refine implementation details while maintaining the core technical approach. The patch remains focused on the promisor remote infrastructure work, specifically how filter information flows between client and server in the auto-filter mode.
