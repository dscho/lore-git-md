This is a bugfix patch in Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically addressing flag handling in `builtin/fsck.c`. The patch corrects an issue where `mark_object()` was passing a hardcoded value of `1` to `odb_has_object()` instead of the proper `HAS_OBJECT_RECHECK_PACKED` flag.

The incorrect usage dates back to a 2020 commit that aimed to skip lazy fetches of promisor objects during fsck operations. While the hardcoded value coincidentally mapped to the desired flag, this was fragile and could break if flag values changed. The patch makes the intention explicit by using the named constant, maintaining the original behavior (rechecking packed objects without fetching promisor objects) while making the code more robust.

This is part of a larger series (v2 2/5) improving type safety around object storage flags, with previous discussion establishing that `HAS_OBJECT_RECHECK_PACKED` is indeed the correct flag for this case. The change is small but meaningful, eliminating a potential maintenance hazard in the fsck machinery.
