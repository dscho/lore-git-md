This is a feature patch series (v3) implementing `promisor.storeFields` configuration and `--filter=auto` mode for Git's promisor remote functionality. The series builds on previous work to enhance how Git handles partial clones and promisor remotes.

The key additions in this version are:

1. A new `promisor.storeFields` config option that allows clients to store fields (like tokens and filters) from server-advertised promisor remotes, with security checks to only store fields for pre-configured remotes.

2. A `--filter=auto` mode that dynamically combines filter specs from accepted promisor remotes during fetch operations, while maintaining backward compatibility with existing partial clone workflows.

The series has undergone significant review iteration, with Patrick Steinhardt, Jean-Noël Avila, and Junio Hamano providing feedback. Notable changes in v3 include:
- Added test coverage showing stored filters can be updated via subsequent fetches
- Improved commit messages and documentation
- Renamed variables for clarity (`captured_filters` -> `accepted_filters`)
- Added a new patch (8/9) to clean up the `promisor_remote_reply()` API
- Simplified error handling in the auto-filter resolution code

The implementation touches multiple subsystems including promisor-remote handling, list-objects filtering, and fetch/clone plumbing. Documentation is updated across several man pages to explain the new behaviors. The series appears well-tested and ready for final review, with all CI tests passing. The changes enable more dynamic promisor workflows while maintaining security and backward compatibility.
