This is the third patch in Patrick Steinhardt's series improving the `git history` command's user interface. The change focuses on making the dry-run functionality more discoverable and flexible.

The patch replaces the technical `--ref-action=print` option with a more standard `--dry-run` flag that works in combination with either `--ref-action=head` or `--ref-action=branches`. This allows users to preview updates to either just HEAD or all branches, addressing a limitation where the old print mode only showed updates for all branches. The implementation consolidates the ref update logic into a new `handle_ref_update()` helper that conditionally prints or executes updates based on the dry-run flag.

The change includes documentation updates and test coverage verifying both ref-action modes work with dry-run. This continues the series' theme of improving user experience while maintaining technical correctness - the implementation cleanly separates the dry-run printing from actual ref updates while reusing the same core logic. The patch touches `builtin/history.c` extensively but follows a clear pattern that should be easy to review.

For future summarizers: key technical points are the new `handle_ref_update()` function, the removal of `REF_ACTION_PRINT` enum value, and the interaction between `--dry-run` and `--ref-action` options. The change maintains compatibility with the upcoming `git history split` feature mentioned in earlier patches.
