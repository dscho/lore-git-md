This is a performance optimization patch for the `--anchored` diff algorithm, authored by Phillip Wood, a contributor known for his work on Git's diff and merge machinery.

The patch improves the performance of `git diff --anchored` by deferring the check for whether a line is an "anchor" (a line that appears exactly once in each file being compared) until it's actually needed. The current implementation checks and caches this information for every line upfront, which is unnecessary since an anchor line must by definition appear exactly once in each file. The new approach avoids this upfront work and drops the caching field from the hashmap entries.

The change provides a modest 2% speedup when diffing 5000 recent commits in git.git, and a more substantial 16% improvement in an extreme test case with many deletions. The implementation is clean - it simply moves the anchor check to the point where the information is actually used, while removing the now-unnecessary caching field.

The patch touches only the xdiff patience diff implementation, modifying how it handles the anchor matching that was introduced to support the `--anchored` option. The change is well-motivated and the commit message provides clear before/after performance measurements. Given Phillip Wood's expertise in this area and the straightforward nature of the optimization, this seems like a solid improvement to the diff machinery.
