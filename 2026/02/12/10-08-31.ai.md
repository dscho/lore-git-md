This is a 9-patch v3 series implementing `promisor.storeFields` configuration and `--filter=auto` mode for Git's promisor remote functionality. The series builds on previous work to enhance partial clone capabilities by allowing dynamic filter updates from servers.

The first part introduces `promisor.storeFields` config to securely store remote fields (like tokens and filters) on the client side when they are advertised by the server. This enables workflows where servers can rotate credentials and clients can update them through normal fetches.

The second part implements `--filter=auto` mode for clone/fetch, which allows clients to dynamically combine filter specs from accepted promisor remotes rather than using a fixed filter. This is built on existing combine-filter infrastructure and maintains backward compatibility.

Key technical changes in v3 include:
- Added test coverage for config updates during fetch in patch 2/9
- Fixed a conflict with master in patch 4/9
- Improved commit message clarity in patch 5/9
- Renamed `captured_filters` to `accepted_filters` in patch 7/9
- Added new patch 8/9 to clean up `promisor_remote_reply()` API
- Simplified fetch-pack interaction and error handling in patch 9/9
