This is a feature patch adding 'auto' filter mode infrastructure to Git's partial clone/promisor remote functionality. It's part 6/9 of a larger series implementing LOP (Large Object Promisors) enhancements.

The patch introduces several key components to support `--filter=auto`:
- A new `LOFC_AUTO` filter choice and `allow_auto_filter` flag in `struct list_objects_filter_options` to control which commands can use auto mode
- Parsing logic in `gently_parse_list_objects_filter()` that validates auto filter usage
- Safety checks preventing auto from being combined with other filters
- A new unit test file (`u-list-objects-filter-options.c`) verifying the parsing behavior

The implementation ensures auto filters must be resolved to concrete filters before actual filtering begins (triggering a BUG() if not). The patch maintains careful memory management through `list_objects_filter_release()` while preserving the `allow_auto_filter` flag during resets.

Christian Couder addresses potential future extensions in the commit message, noting that while combining auto with other filters could theoretically be allowed later, the current implementation keeps things simple by prohibiting it. The patch has already incorporated feedback from Patrick Steinhardt on error message formatting and other implementation details.

This foundational work enables the actual `--filter=auto` functionality that will be wired up in later patches of the series, particularly patch 9/9. The changes are well-contained to the filter options infrastructure with comprehensive test coverage, following the pattern established by earlier patches in the series.
