This is a performance optimization patch for `git pack-objects` that addresses unnecessary object fetches during geometric repacking of promisor packs in partial clone scenarios. The patch has already received review and approval from Junio Hamano, with only a minor typo fix ("passe" -> "pass") noted during final review.

The change prevents backfill fetches that were being triggered during the localized rev walk used for delta selection heuristics when merging packs with `--stdin-packs`. This walk was introduced to compensate for not having full object names during pack merging, but in promisor pack scenarios it could cause unwanted network fetches. The solution temporarily disables fetching during this specific operation using a global variable, which is safe since only one pack operation runs at a time.

The patch builds on commit dcc9c7ef47 which enabled geometric repacking of promisor packs, and specifically targets a performance regression that emerged from that change. The implementation is notably simple and well-contained, with Junio praising both the clear explanation and straightforward solution. This optimization will particularly benefit large repositories using partial clones where unnecessary fetches impact performance. The thread shows consensus around the change, with Jeff King having previously reviewed test coverage and Taylor Blau supporting the optimization direction. With Junio's approval, the typo fix applied, this is now queued for inclusion in the next release.
