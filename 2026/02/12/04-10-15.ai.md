This is a refactoring patch series addressing edge cases in string list sorting behavior. The cover letter explains that some code paths currently rely on an implicit sorting order that could break if the processing logic changes. The series replaces calls to `string_list_remove_duplicates()` with `string_list_sort_u()` in two locations to ensure consistent sorted output.

The first patch updates `builtin/sparse-checkout.c` while the second touches `builtin/help.c`. Both changes are small (totaling 5 lines modified) and appear to be straightforward correctness fixes. The cover letter includes a reproduction recipe showing how the current behavior can diverge from `sort -u` expectations when processing certain config patterns.

The motivation is clear and the changes look focused - this seems like a reasonable cleanup to make the code more robust against future modifications. The patches are part of an ongoing effort to standardize string list handling patterns across the codebase.
