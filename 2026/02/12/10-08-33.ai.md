This is part 2/9 of a v3 series implementing secure storage of promisor remote fields. The patch introduces a new `promisor.storeFields` configuration that allows clients to automatically store server-advertised fields (currently supporting "partialCloneFilter" and "token") in their local config.

The implementation includes security-conscious validation:
- Filters are parsed to ensure they're valid before storage
- Tokens are checked for control characters
- Changes are only made for pre-configured remotes (no new remotes created)
- Users are notified via stderr when config changes occur

The patch adds comprehensive documentation in both config and protocol docs, explaining the security model and behavior. Test coverage verifies:
- Filter storage and updates work correctly
- Tokens remain unchanged when not in storeFields
- Unknown remotes aren't affected
- User notifications appear as expected

This builds on previous work that allowed servers to advertise additional fields and clients to check them. The storage capability enables dynamic credential/configuration updates without manual client-side changes.
