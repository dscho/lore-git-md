This is part 7/9 of a series implementing the LOP (Large Object Promisors) effort, focusing on storing server-advertised filters in memory for dynamic filter combination. The patch adds infrastructure to support the upcoming `--filter=auto` feature by:

1. Adding an `advertised_filter` field to `struct promisor_remote` to persistently store server-advertised filters during the session, even when not persisted to disk via `promisor.storeFields`.

2. Modifying `filter_promisor_remote()` to capture advertised filters into a temporary list and apply them to the promisor remote structs after potential configuration reloads, while also marking accepted remotes.

3. Introducing `promisor_remote_construct_filter()` which:
   - Iterates through accepted promisor remotes
   - Collects their advertised filters
   - Generates a combined filter spec while validating each one
   - Issues warnings for invalid filters but continues processing others

The implementation handles memory management carefully with proper cleanup and includes validation with user-friendly warnings. This prepares for the `--filter=auto` functionality in patch 9/9 that will use these stored filters to dynamically combine server-suggested filter specifications.

Key technical details:
- Filters are stored per-remote in the new `advertised_filter` field
- The construction function returns a newly allocated string that must be freed
- Invalid filters are skipped with warnings rather than failing the operation
- The code maintains compatibility with existing partial clone workflows

The patch follows the series' pattern of careful, incremental changes with Patrick Steinhardt providing technical review and Christian Couder addressing feedback. It builds on previous refactoring while enabling the final auto-filter implementation.
