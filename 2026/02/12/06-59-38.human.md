This is a bugfix patch in Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically addressing flag handling in `builtin/fsck.c`. 

The patch corrects a hardcoded value `1` that was being passed to `odb_has_object()` in the `mark_object()` function. The original value was undocumented and potentially fragile, as it happened to map to `HAS_OBJECT_RECHECK_PACKED` by coincidence rather than design. The change makes the intent explicit by using the named flag constant instead.

The fix maintains the original behavior from commit 9eb86f41de, which was meant to skip lazy fetches of promisor objects while still checking packed objects. This is part of a broader series improving type safety and flag consistency in the object storage layer, with previous patches having addressed similar issues in `builtin/backfill.c` and flag definitions.

The change is small but meaningful - it replaces a "works by accident" implementation with one that properly documents its intent through the use of the correct flag name. The patch follows the pattern seen elsewhere in this thread of making flag usage more robust and self-documenting.
