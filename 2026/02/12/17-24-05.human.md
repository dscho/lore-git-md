Security hardening for repository discovery. This is the second version of Tian Yuchen's patch to make Git fail explicitly when encountering a malformed `.git` entry (like a named pipe) during repository discovery, rather than silently continuing the search. The current behavior could potentially lead to unsafe attachment to a parent repository if the `.git` entry is corrupted or maliciously replaced.

The patch now checks the file type via `lstat()` only after the normal directory check fails, addressing Junio Hamano's performance concern from the RFC discussion. When encountering an invalid `.git` (neither file nor directory), it either dies with an error message (if `die_on_error` is true) or returns a specific error code (`GIT_DIR_INVALID_GITFILE`).

The security benefit remains debated - Junio noted that an attacker who can replace `.git` likely has broader access already. However, the change does help surface filesystem corruption sooner. The patch is small (15 lines net change) and focused on `setup.c`, touching a sensitive path but with clear error handling. It remains to be seen whether the project will accept this as a hardening measure or view it as unnecessary given the limited threat model.
