This is a cover letter for a 4-patch series introducing UI improvements to the new `git history` command, part of Patrick Steinhardt's ongoing work to expand Git's built-in command set. The series focuses on making the command more user-friendly by moving validation earlier in the process and simplifying some option names.

The first two patches restructure when validation happens - moving revwalk checks and merge detection before any user interaction begins. This prevents users from answering prompts only to then hit an error. The last two patches rename the technical-sounding `--ref-action` option into two clearer alternatives: `--dry-run` for previewing changes and `--update-refs` for controlling reference updates.

The changes are relatively small but meaningful quality-of-life improvements, particularly the validation reordering which makes the command more predictable. The series appears to be a stepping stone before a larger `git history split` feature, and Patrick notes it resolves some conflicts with another in-flight series. The test updates show the changes are well-covered, and the diffstat suggests the implementation is straightforward despite touching core command logic.
