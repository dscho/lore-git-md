This is a review comment from Junio Hamano on Patrick Steinhardt's patch to improve the `git history` command's validation timing. The patch moves verification checks before user input is requested, preventing wasted effort when invalid operations are attempted.

Junio acknowledges the usability improvement but questions the test change that uses `-c core.editor=false`. He's concerned this might produce a different error than intended, since a failing editor would normally trigger its own error message rather than the validation error being tested. The test appears to be verifying that invalid operations fail before reaching the editor prompt, but the mechanism for bypassing the editor isn't clearly explained in the commit message.

The exchange shows Junio's characteristic attention to detail in test correctness, even while approving the overall direction of the change. The patch itself is part of a larger series refining the new `git history` command's interface and behavior.
