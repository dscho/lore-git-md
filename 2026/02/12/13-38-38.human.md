This is a feature proposal for introducing a `.gitallow` file to Git's security model. The author, Sébastien, suggests a mechanism similar to `.gitignore` but for controlling which Git commands can be run in a repository, with the goal of preventing potentially dangerous operations (like `git push --force`) from being executed accidentally or maliciously.

The proposal outlines a system where repository owners could specify allowed/disallowed commands in `.gitallow`, with inheritance from parent directories and support for wildcards. The author acknowledges this is inspired by similar mechanisms in other tools and asks whether this has been discussed before in the Git community.

The email is exploratory rather than a concrete patch submission - the author is seeking feedback on whether this idea has prior art in Git's history and whether it would be welcome as a contribution. The proposal appears well-intentioned but lacks implementation details or a prototype. Given Git's conservative approach to security features, this would likely need significant discussion about threat models and use cases before being considered for inclusion.
