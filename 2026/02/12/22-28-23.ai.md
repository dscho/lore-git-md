This is a documentation patch addressing security concerns around patch round-tripping in Git's email workflow. It's the third iteration of Kristoffer Haugsbakk's effort to clearly document how `git format-patch` and `git am` handle commit message delimiters, particularly focusing on cases where diffs or other content in commit messages can be misinterpreted as patch content.

The patch adds new documentation files (`format-patch-caveats.adoc` and `format-patch-end-of-commit-message.adoc`) that explain the parsing rules and potential pitfalls when round-tripping patches through email. Key points covered include:
- How unindented diffs in commit messages can be accidentally applied
- The specific delimiter patterns (`---`, `diff -`, `Index:`) that trigger patch parsing
- Workarounds (indenting problematic content)
- Real-world impact scenarios like Linux distribution workflows

The documentation is included in multiple man pages (`git-am`, `git-format-patch`, `git-send-email`) via shared include files. Changes from v2 include:
- Dropping GitHub-specific references per Phillip Wood's feedback
- Restructuring the delimiter rules section
- Adding back a solution paragraph about indenting problematic content
- Using a subheading instead of thematic break for better man page rendering
- Changing "roundtripping" to "round-tripping" per dictionary guidance

The patch has been reviewed by Phillip Wood and incorporates feedback from Junio Hamano. It's now in its final form and has been queued by Junio for merging. This documentation serves as an important complement to the ongoing technical solutions being discussed in parallel (boundary markers, strict modes, etc.) for the patch parsing security issue.
