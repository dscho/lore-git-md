This is part 8/9 of a series implementing promisor remote enhancements, specifically modifying the `promisor_remote_reply()` API to be more flexible. The patch changes the function signature to separate its two responsibilities: processing server advertisements (which always needs to happen) from constructing reply strings (which is now optional).

The key change makes `promisor_remote_reply()` take a `char **accepted_out` parameter that will only be populated if non-NULL, allowing callers that don't need the reply string (like upcoming fetch-pack changes) to skip the string construction work. The existing connect.c caller is updated to pass a pointer and still gets the same behavior.

This is a clean refactoring that improves the separation of concerns while maintaining all existing functionality. The change was suggested by Patrick Steinhardt in review of v2 and fits well with the series' goal of making promisor remote handling more flexible. The implementation looks straightforward with proper memory management preserved.
