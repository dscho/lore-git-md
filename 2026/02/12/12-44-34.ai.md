This is the first patch in a 4-part series improving the `git history` command's user interface, focusing on validation timing and option clarity. The patch addresses a usability issue where validation checks (revwalk setup and merge detection) were happening *after* users had already provided their commit message input, potentially wasting their effort.

The key change splits the reference update handling into two phases: `setup_revwalk()` now performs all validation upfront before any user interaction, while `handle_reference_updates()` retains the actual reference updating logic. This prevents users from losing work when invalid conditions (like non-ancestor commits) are detected. The patch includes test updates to verify the new behavior, particularly around the `--ref-action=head` case where ancestor validation is critical.

The implementation is cleanly separated from the rest of the series' changes (which will rename options in later patches), showing Patrick's characteristic attention to incremental improvement. The changes touch core command flow in `builtin/history.c` but maintain the existing behavior when validation succeeds, just moving failure cases earlier in the process. This sets up the subsequent patches to build on this improved foundation while keeping the series bisectable.
