This is part 2/9 of a series implementing secure storage of promisor remote fields, specifically focusing on adding the `promisor.storeFields` configuration option. The patch allows clients to securely store server-advertised fields like tokens and partial clone filters in their local configuration.

The implementation includes validation checks for security: filters are parsed to ensure they're valid, and tokens are checked for control characters before storage. When values change, warnings are emitted to notify users. The patch also documents the new config option and updates protocol documentation to explain how stored fields integrate with the promisor remote capability.

Test coverage verifies that:
- Only configured fields are stored
- Invalid values are rejected
- Users are notified of changes
- Existing values aren't overwritten unnecessarily
- Unknown remotes can't have fields stored

This is a well-structured patch with thorough documentation and testing. It builds on previous work in the series while maintaining security boundaries - no new remotes can be created through this mechanism, only existing configurations can be updated. The implementation handles edge cases reviewers would expect (validation, idempotency, user notification) and fits cleanly into the existing promisor remote infrastructure.
