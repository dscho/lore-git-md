Bugfix for diffcore-break machinery addressing a dangling pointer issue in partially cloned repositories. This is version 2 of the patch from first-time contributor Han Young, now including both the required Signed-off-by line and a test case as requested in the initial review.

The fix targets a specific crash scenario in blobless clones (`--filter=blob:none`) where `diffcore_break()` frees a file pair during diff operations but leaves the queue pointer dangling. This manifests when running commands like `git reset` that trigger diff operations on prefetched blobs, particularly with large files. The one-line fix in diffcore-break.c NULLs the queue entry after freeing the file pair.

The accompanying test case demonstrates the fault by creating a repository with large YAML files, performing a blobless clone, and then exercising the diff machinery through checkout and reset operations that would previously crash. This follows a similar pattern to a December 2025 fix (commit 56d388e6) for related diff machinery issues, suggesting this may be part of a broader class of memory handling bugs in partial clone scenarios.

The patch appears well-constructed - it addresses both technical correctness and test coverage, and the author has responded promptly to maintainer feedback. While the immediate issue is resolved, this may warrant a broader audit of similar patterns in the diff machinery when operating with partial clones.
