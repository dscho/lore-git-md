Thread identity: Performance optimization for `--anchored` mode in Git's patience diff algorithm, proposed by Phillip Wood.

Core problem: The current implementation of `--anchored` in the patience diff algorithm checks and caches anchor status for every line upfront, even though anchor lines must appear exactly once in each file. This wastes work on lines that cannot possibly be anchors.

Current status: Initial proposal showing 2-16% speedups depending on workload, with the largest gains in cases with many deletions. The patch removes the `anchor` field from hashmap entries and moves the `is_anchor()` check to the point where we know we have a potential match.

Key technical details: Changes limited to `xdiff/xpatience.c`:
- Removes cached `anchor` field from hashmap entries
- Moves `is_anchor()` check to occur only after confirming a line appears exactly once in both files
- Maintains identical behavior while avoiding redundant work

Open questions: None raised yet - appears uncontroversial.

Participant positions: Phillip Wood as author proposing the optimization with performance measurements.

Related work: Part of ongoing optimizations to Git's diff machinery, though not tied to any larger named effort.
