This is a feature patch in Patrick Steinhardt's series improving the `git history` command's UI. It replaces the technical `--ref-action=print` option with a more user-friendly `--dry-run` flag that works consistently across different reference update modes.

Junio Hamano's review focuses on clarifying the behavior of the new `--dry-run` mode. While he approves of the clearer interface, he asks whether the command still creates the necessary objects during a dry run (just without updating references). This is important because users might want to inspect the objects before deciding whether to proceed with the actual reference updates.

The patch appears well-received overall, with Junio's feedback being more about documentation clarity than any fundamental issue with the approach. This continues the series' trend of making `git history` more approachable while maintaining its underlying capabilities. The discussion remains technical and focused, suggesting this change is likely to progress smoothly once the dry-run behavior is properly documented.
