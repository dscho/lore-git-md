This is part of Patrick Steinhardt's ongoing ODB (object database) abstraction effort, specifically addressing type safety for object info flags. The patch converts the `OBJECT_INFO_*` flag macros into a proper enum type and updates all related function signatures to use this enum instead of raw integers.

The change improves code clarity by making function signatures self-documenting - callers now explicitly see which flags are expected rather than passing generic integers. It also enables limited compiler warnings when incorrect flag types are passed, though the protection isn't absolute (bitwise OR operations still produce integers that bypass type checking).

The patch touches several key files in Git's object storage layer (`object-file.[ch]`, `odb.[ch]`, `packfile.[ch]`), updating function declarations to use the new `enum object_info_flags`. The flags themselves maintain their existing semantics, with `OBJECT_INFO_FOR_PREFETCH` still combining `SKIP_FETCH_OBJECT` and `QUICK` flags. The diff shows careful attention to maintaining backward compatibility while improving type safety.

This is the fourth patch in a five-part series that has seen active discussion from core contributors like René Scharfe and Justin Tobler. The changes are part of the larger ODB abstraction work to make Git's object storage more modular and type-safe. While the behavioral impact is minimal, the improved type safety and documentation make this a worthwhile cleanup that aligns with the project's ongoing code quality efforts.
