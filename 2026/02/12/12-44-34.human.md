This is the first patch in a 4-part series improving the `git history` command's user experience, part of Patrick Steinhardt's ongoing work to expand Git's built-in functionality. The patch focuses on moving validation checks earlier in the execution flow to prevent users from losing their work when errors occur.

The change restructures the `git history reword` command to perform revwalk validation before prompting the user's commit message edit. Previously, users could spend time writing a message only to have the command fail later due to invalid revision specifications. The patch splits the validation logic into a separate `setup_revwalk()` function and calls it before the editor is invoked.

The implementation is clean and well-tested, with corresponding updates to the test suite. This is a clear usability win that follows Git's principle of failing fast when invalid input is detected. The change is part of preparing for a larger `git history split` feature mentioned in the series cover letter.
