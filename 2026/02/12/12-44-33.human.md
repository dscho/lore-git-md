This is a patch series introducing UI improvements to the `git history` command, part of Patrick Steinhardt's ongoing work on this new built-in. The series consists of four small but focused changes to make the command more user-friendly and less implementation-detail-oriented.

The first two patches move validation checks (revwalk verification, merge detection) earlier in the process so users get feedback before being prompted for input. The last two patches rework the `--ref-action` option into two separate flags: `--dry-run` for previewing changes and `--update-refs` for controlling reference updates. This splits a technical implementation detail into more intuitive user-facing options.

The changes are straightforward and well-motivated, with accompanying test updates. As a follow-up to Patrick's earlier `git history` work, this continues the pattern of careful, incremental improvements to the new command's interface. The patches touch documentation, implementation, and tests in a balanced way, suggesting they're ready for review.
