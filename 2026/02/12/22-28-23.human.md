This is a documentation patch addressing security concerns around patch round-trip fidelity between `git format-patch` and `git am`. The patch has completed final review and is now queued by Junio.

Kristoffer Haugsbakk's patch adds explicit warnings about how certain commit message content (particularly unindented diffs) can be misinterpreted as patch content when round-tripping through email. The documentation explains that lines matching patch delimiters ("---", "diff -", "Index: ") will prematurely terminate the commit message during application, potentially causing the wrong content to be applied or patch application to fail.

The v3 iteration incorporates feedback from Phillip Wood and Junio Hamano, dropping GitHub-specific references and improving phrasing. The documentation now appears in multiple man pages via shared include files, covering `git-am`, `git-format-patch`, and `git-send-email`. The warnings are particularly relevant for distribution maintainers who apply patches in bulk, where misinterpreted content could go unnoticed.

This patch is part of a broader security discussion about patch parsing ambiguities, with parallel technical solutions being explored (boundary markers, strict modes, and reversible quoting). The documentation serves as an immediate mitigation while those solutions are developed.
