This is a refactoring patch in the reference backend selection series, which aims to enable zero-downtime migrations between ref storage backends (files<->reftable). The patch simplifies `create_reference_database()` by removing its side effect of modifying the repository's ref storage format.

The key change removes the redundant `repo_set_ref_storage_format()` call from `create_reference_database()`, since the format is already set correctly in both call sites (git-init and git-clone). The patch notes this prevents potential issues with future fields in the ref storage format, particularly with dynamic string allocation.

The changes are mechanical and straightforward, touching only the setup infrastructure. This is part of a larger effort to make ref backend switching more robust, particularly for GitLab's needs with large repositories. The patch has already received maintainer approval and is in final polishing before merging.
