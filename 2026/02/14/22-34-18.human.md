This is part of the ongoing ref backend abstraction effort, specifically enabling URI-based configuration for reference storage locations. The patch extends the `extensions.refStorage` config to support both simple format names (e.g., `reftable`) and URIs (e.g., `reftable:///path/to/refs`), with the latter allowing specification of an alternate storage location.

Key changes include:
- Adding URI parsing logic to handle the new format
- Propagating the storage location payload to repository initialization
- Modifying worktree setup to store references in the alternate location while maintaining compatibility stubs
- Comprehensive test coverage for the new functionality

The implementation handles edge cases like relative paths (resolved against $GIT_DIR) and ensures worktree references follow the same storage scheme as the main repository. A TODO notes the need for future work to pass worktree structs directly to backends rather than paths.

This is patch 5/6 in a series that has already received maintainer review and is in its final polishing phase. The changes here build on previous work to enable zero-downtime migrations between ref backends, a capability particularly important for GitLab's large-scale deployments. The test suite demonstrates interoperability between files and reftable backends with various path configurations.
