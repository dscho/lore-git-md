Feature addition for interactive patch commands (`add -p`, `checkout -p`, `reset -p`, `stash -p`).

This is the first patch in a 4-part series introducing a new `--auto-advance` option (with `--no-auto-advance` variant) for interactive patch selection. The option controls whether the interface automatically moves to the next file after processing hunks or stays on the current file to allow reworking. Default behavior remains unchanged (auto-advancing).

The patch adds the option plumbing across all relevant commands, initializing the flag in the `add_i_state` struct and exposing it through each command's option parsing. The implementation touches multiple builtins (`add`, `checkout`, `reset`, `stash`) to maintain consistent behavior. Error handling ensures the option is only used with `-p/--patch`.

This appears to be a well-scoped, carefully implemented feature that addresses a real workflow need for more control during interactive patch selection. The series has gone through multiple review iterations (now at v5) with clear commit messages explaining each step. Subsequent patches will build on this foundation with the actual navigation logic and tests.
