This is the second patch in a two-part series adding a `--keys` flag to `git repo info` for programmatic repository metadata access. The series has gone through six iterations with input from Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila on documentation.

The patch implements the `--keys` option to list available metadata keys without their values, supporting both newline-delimited and NUL-terminated output formats. The implementation includes:
- A new `print_keys()` function in `builtin/repo.c` handling the output formatting
- Comprehensive test coverage in `t/t1900-repo.sh` verifying format behavior and option validation
- Documentation updates in `Documentation/git-repo.adoc` explaining the new flag

Key technical details:
- Uses `FORMAT_NEWLINE_TERMINATED` internally while presenting "lines" to users
- Strictly validates against combining `--keys` with `--all` or explicit key requests
- Follows established conventions for NUL-terminated output (`_NUL_` in docs)
- Maintains backward compatibility while improving naming accuracy

The series is now ready for integration, having resolved all substantive feedback. A minor documentation capitalization issue will be addressed in a follow-up. This completes the experimental `git repo` command's interface stabilization before wider adoption.
