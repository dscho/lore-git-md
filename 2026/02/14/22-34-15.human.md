This is a refactoring patch in the final stages of the reference backend selection series, which enables switching between files and reftable backends. The patch extracts duplicate stub-creation code into a shared `refs_create_refdir_stubs()` function.

The change centralizes the logic for creating minimal directory structures that make Git recognize a directory as a repository (HEAD file and refs/ directory). Previously this was duplicated in clone.c and reftable-backend.c, with the reftable version also creating an explanatory file in refs/heads/. The new function handles both cases through an optional message parameter.

This is a straightforward cleanup that follows the pattern of earlier review feedback in the thread. The implementation looks clean and maintains all existing functionality while reducing duplication. With maintainer approval already secured for the overall series, this refinement should be uncontroversial.
