This is the first patch in a 4-part series introducing a new `--auto-advance` option for interactive patch selection commands (`add -p`, `checkout -p`, `reset -p`, `stash -p`). The option allows controlling whether the interface automatically moves to the next file after processing hunks (current default behavior) or stays on the current file until manually advanced.

The patch adds the core infrastructure for the feature by:
1. Extending `struct add_p_opt` and `struct add_i_state` to track the auto-advance setting
2. Adding `--auto-advance` flags to all relevant commands (defaulting to true to maintain current behavior)
3. Ensuring the option is only used with interactive patch mode via validation checks
4. Updating shell completion for `git checkout`

The implementation touches multiple builtin commands through consistent changes to their option parsing and validation. This appears to be a well-scoped change that cleanly extends the existing interactive patch infrastructure. The commit message clearly explains the motivation and behavior, though it doesn't mention the planned manual navigation commands ('>' and '<') that will be added in later patches.

This is part of a mature series (now at v5) that has evolved through review feedback. The changes are focused and the test coverage in later patches suggests the feature has been thoroughly validated. The option provides useful flexibility for users who want more control over multi-file interactive patch workflows.
