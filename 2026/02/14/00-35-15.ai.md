This is the first patch in a two-part series that finalizes the format naming for Git's experimental `repo` command. The patch renames the "keyvalue" output format to "lines" to better reflect its newline-delimited nature and allow for future extensions that may not strictly be key-value pairs. The change is motivated by three key issues with the old name: it didn't indicate newline-delimited output, was redundant since both formats have keys/values, and was too restrictive for potential future use cases.

The implementation updates documentation, enum names (changing `FORMAT_KEYVALUE` to `FORMAT_NEWLINE_TERMINATED` while keeping the user-facing "lines" name), and test cases. The patch maintains all existing functionality while improving the naming to be more accurate and extensible. This is part of the ongoing refinement of the experimental `git repo` command's interface before it stabilizes.

The patch has been through multiple iterations (v1-v6) with input from Patrick Steinhardt and Junio Hamano, and is now in its final form ready for integration. A minor documentation capitalization issue will be addressed in a follow-up. The changes are well-contained, touching only the relevant command implementations and tests while maintaining backward compatibility with the experimental feature's users.
