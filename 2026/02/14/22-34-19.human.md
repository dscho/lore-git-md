This is the final patch in a series implementing environment-variable control for Git's reference storage backend selection, part of the larger ref backend abstraction effort. The patch adds `GIT_REFERENCE_BACKEND` as an environment variable counterpart to the existing `extensions.refStorage` config option, allowing runtime specification of reference storage format and location (files or reftable:// URIs).

The implementation enables two key workflows: cloning/initializing repositories with alternate reference directories, and modifying reference backends for individual commands. The patch includes comprehensive test coverage validating both configuration methods (environment vs config) across various operations like ref listing, tag deletion, and worktree handling. 

Notable technical aspects include:
- Centralized stub creation/removal in the generic refs layer
- Worktree reference directory setup integration
- Path resolution infrastructure via `refs_compute_filesystem_location()`
- Const-correctness fixes throughout string handling code

The series has undergone extensive review from multiple contributors (Patrick Steinhardt, Karthik Nayak, Derrick Stolee, Eric Sunshine, and others) and has maintainer approval from Junio Hamano. This final patch completes the configuration options while maintaining the zero-downtime migration capability critical for GitLab's large repositories. The implementation appears robust and well-tested, with all substantive technical concerns resolved in previous iterations.
