This is the second patch in a documentation series improving the `git-patch-id` man page, now in its second version. The patch adds a practical shell script example demonstrating how to use patch IDs to correlate commits between branches, addressing feedback from the previous version by adding cleanup of temporary files.

The script takes an upstream branch and local branch as arguments, generates sorted lists of patch IDs for each, then joins them to show matching commits. It includes options to limit the comparison by commit count or date range. The example illustrates the batch processing capability highlighted in the first patch of the series, showing how patch IDs enable comparing sets of commits rather than individual patches.

The patch builds on Linus Torvalds' observation that `git-patch-id` is primarily useful in scripts rather than one-liners. The example provides concrete guidance for a common use case - mapping equivalent commits between branches - that was previously only implied by the documentation. The script handles temporary file cleanup (added in v2 per D. Ben Knoble's review) and uses consistent footnote styling across the series.

This is a well-motivated addition to the documentation, providing the kind of practical example that helps users understand how to apply the command's capabilities. The script is pedagogically useful while also being robust enough for real use. With the temporary file handling added, it addresses the only substantive feedback from review and appears ready for merging.
