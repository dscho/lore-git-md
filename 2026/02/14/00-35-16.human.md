Feature addition to the experimental `git repo` command, finalizing the `--keys` flag implementation for programmatic repository metadata access.

This patch adds the `--keys` flag to `git repo info`, allowing users to list available metadata keys without showing their values. The implementation includes:

1. A new `print_keys()` function that outputs keys in either newline` or NUL-terminated format (matching the existing format options)
2. Strict validation preventing `--keys` from being combined with `--all` or explicit key requests
3. Comprehensive test coverage verifying format behavior and option validation
4. Documentation updates explaining the new flag and its format options

The patch represents the final iteration of this feature after several rounds of review, with all substantive feedback addressed. Notable changes from previous versions include:
- Renamed internal format enum to `FORMAT_NEWLINE_TERMINATED` (from `FORMAT_LINES`) while keeping the user-facing "lines" name
- Removed redundant "keyvalue" format in favor of clearer naming
- Added detailed commit message explaining the format changes

This is the second patch in a 2-patch series that has been approved for integration into the `next` branch, replacing an earlier queued version. The implementation appears clean and thorough, with careful attention to both functionality and user experience.
