This is the final patch in a series implementing environment variable support for reference backend selection, completing the configuration options for zero-downtime migrations between ref backends (files<->reftable). The patch adds `GIT_REFERENCE_BACKEND` environment variable support, complementing the existing `extensions.refStorage` config option added in previous patches.

Key technical changes:
- Introduces `GIT_REFERENCE_BACKEND` environment variable that accepts the same URI format as `extensions.refStorage` (e.g. `files://path` or `reftable://path`)
- Environment variable takes precedence over config when both are set
- Properly handles stub creation/removal in `$GIT_DIR` for alternate reference locations
- Adds comprehensive test coverage for clone/init operations with alternate ref directories
- Maintains compatibility with worktree operations when using alternate ref locations

The implementation builds on prior work in the series by:
- Reusing the URI parsing from `parse_reference_uri()`
- Leveraging the ref storage payload infrastructure added earlier
- Extending the test framework to validate both config and environment variable paths

This completes the series' goal of enabling flexible reference storage locations through multiple configuration mechanisms, with all substantive technical concerns addressed through prior review iterations. The patch is well-tested and appears ready for inclusion, representing the culmination of a multi-version effort to support GitLab's large repository migration needs.
