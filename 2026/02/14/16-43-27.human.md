This is a performance optimization discussion about using the `sendfile()` system call for file copying in Git. Phillip Wood reviews George Hu's proposed Linux-specific implementation, pointing out several technical concerns that need addressing before the patch could be merged.

Phillip notes that Git's practice is to put platform-specific implementations in `compat/` directories rather than using `#ifdef`s directly in the main code. He identifies several issues with the current implementation: missing error handling for `fstat()` failures, not properly propagating `sendfile()` errors to the caller, and lack of handling for non-blocking writes (EAGAIN). He also suggests falling back to the read/write loop when encountering EINVAL, as `sendfile()` has restrictions on the types of file descriptors it can handle.

The discussion remains focused on implementation details rather than questioning the optimization's premise, though Phillip does ask whether Git actually copies files large enough for this optimization to make a noticeable difference - a question that wasn't answered in the original proposal. The thread shows the careful scrutiny patches receive on the list, with an experienced contributor (Phillip, known for his work on the sequencer and worktree handling) identifying subtle but important edge cases.
