This is a feature patch series finalizing the `git repo info --keys` implementation and unifying output format naming across `git repo` subcommands. The series is ready for integration into `next` after several iterations addressing review feedback.

The main changes in v6:
1. Renames the output format from "keyvalue" to "newline_terminated" (following Patrick Steinhardt's suggestion) to better describe the format's behavior rather than its content structure
2. Expands the commit message to thoroughly justify the format renaming
3. Fixes capitalization in documentation paragraphs
4. Maintains all previously implemented functionality including strict option validation and comprehensive test coverage

The series builds on prior work to add machine-readable `--keys` output capability while ensuring consistent format handling between `repo info` and `repo structure` subcommands. The implementation includes proper NUL-terminated output support and prevents invalid combinations like `--keys` with `--all`.

While the technical implementation is now complete, there remains some discussion about whether "newline_terminated" is the ideal name versus the author's preference for "lines". The series is otherwise ready for integration, with Junio Hamano having approved the naming approach. This represents the final polish on a feature that will improve scriptability of repository metadata access.
