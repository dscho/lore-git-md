This is a maintainer confirmation of longstanding behavior regarding Git's date parsing. Junio C Hamano responds to a question about `--since` date interpretation, explaining that when given a date (without time), Git intentionally uses the current local time rather than defaulting to 00:00:00. 

Junio traces this design back to a 2005 decision by Linus Torvalds, noting that while both approaches (current time vs midnight) are valid, the current behavior is more convenient for common human workflows like checking "what changed in the last 24 hours." He points out that users who specifically want midnight can explicitly specify the time, whereas getting the current time would be more cumbersome if the default were midnight.

The response confirms this is not a bug but a deliberate choice that has stood for nearly two decades. Junio suggests documentation could potentially be updated to clarify this behavior, but indicates no plans to change the implementation as it would break backward compatibility without clear benefit. This closes the thread with the status quo maintained.
