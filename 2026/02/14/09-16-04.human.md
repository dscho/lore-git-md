This is the first patch in a v4 series introducing a new `--no-auto-advance` flag for interactive patch commands (`git add -p`, `checkout -p`, `reset -p`, `stash -p`). The flag allows users to navigate between files when interactively selecting hunks, rather than automatically advancing to the next file after processing all hunks in the current file.

Junio Hamano points out two implementation issues in his review: (1) the `auto_advance` initialization in `init_add_i_state()` could be simplified by directly copying from `add_p_opt->auto_advance` rather than defaulting to 1 then conditionally overriding, and (2) the new `auto_advance` field is poorly placed in the `add_i_state` struct, grouped with unrelated diff context settings rather than with other interactive state fields. The author acknowledges both points and indicates they will be addressed.

The patch series as a whole adds core infrastructure for the new feature while maintaining backward compatibility (auto-advance remains the default). Subsequent patches will implement the actual navigation functionality and test coverage. This foundational patch touches several builtin commands to expose the new flag while keeping the core logic in the interactive add machinery.
