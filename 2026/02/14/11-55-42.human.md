This is the second patch in a documentation series improving the `git-patch-id` man page, now in its fourth iteration. The patch adds a practical shell script example showing how to use patch IDs to correlate commits between branches.

The script demonstrates a real-world use case: mapping commits from a local branch to their equivalent versions in an upstream branch by generating and comparing sorted patch ID lists. It includes options to limit the comparison by commit count or date range, and now properly cleans up temporary files as suggested in review. The example illustrates the batch processing capabilities highlighted in the first patch of the series.

The patch has already gone through review, with D. Ben Knoble providing constructive feedback that was incorporated in this version. The changes are purely additive (+40 lines) and non-controversial, focused on making the command's scripting use case more accessible. The example ties directly to prior discussion about `git-patch-id` being primarily a scripting tool, referencing Linus Torvalds' comments on its intended usage patterns.
