This is a refactoring patch in the final stages of a series enabling reference backend selection for zero-downtime migrations between files and reftable storage formats. The patch simplifies `create_reference_database()` by removing its redundant setting of the repository's ref storage format, which was causing potential issues with memory management and duplicated logic.

The change is straightforward: the function no longer takes a `ref_storage_format` parameter since the format is already set in the repository structure before this function is called. The patch updates the two call sites (in `git-init` and `git-clone`) to match the new signature. This cleanup prevents future problems if the format structure grows to include dynamically allocated fields.

As part of a well-reviewed series that has maintainer approval, this patch represents final polishing of the implementation. The change is small but meaningful, eliminating a subtle source of potential bugs in the larger ref backend selection feature.
