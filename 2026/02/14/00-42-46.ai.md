This is a performance improvement series patch from Derrick Stolee, part of the ongoing effort to optimize `git config list --type=<X>` filtering. The patch establishes the core pattern for type-specific formatters that will be reused throughout the series.

The patch introduces `format_config_int64()`, which handles both gentle parsing (returning errors) and strict parsing (potentially dying) for 64-bit integer config values. The function follows a clear pattern: try gentle parsing first if requested, fall back to strict parsing otherwise, then format the result. Junio notes the implementation looks good but suggests a blank line be moved for better readability - a minor style point that doesn't affect functionality.

This is infrastructure work that enables the subsequent patches to implement similar formatters for other config types (boolean, path, color, etc.). The approach maintains backward compatibility while allowing more efficient filtering during config parsing rather than after. The thread shows the maintainer is satisfied with the direction and pattern being established here.
