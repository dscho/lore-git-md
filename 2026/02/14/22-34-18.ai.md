This patch extends the reference backend configuration to support URI-based storage locations, allowing references to be stored outside the main repository directory. It's part of the ongoing ref backend abstraction effort led by Patrick Steinhardt and Karthik Nayak, now in its final polishing phase with maintainer approval.

The patch introduces URI syntax for the `extensions.refStorage` config, supporting both format-only (`files`) and location-specified (`reftable:///path/to/refs`) configurations. For worktrees, references will now be stored under the alternate path when specified (`$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>`), while maintaining stubs in the original location for compatibility. The implementation includes comprehensive test coverage in t1423-ref-backend.sh, verifying both read and write operations across backend migrations.

Key technical changes include:
- New URI parsing in `parse_reference_uri()`
- `ref_storage_payload` field added to `struct repository` and `struct repository_format`
- Worktree reference directory setup in `setup_alternate_ref_dir()`
- Path resolution infrastructure for upcoming URI support
- Const-correctness fixes throughout the string handling code

The patch builds on previous work to enable zero-downtime migrations between backends, particularly important for GitLab's large-scale repository needs. A TODO notes the desire to eventually pass `struct worktree *` to backends instead of paths, but this is deferred due to current architectural constraints around `the_repository` usage.
