This is a small refactoring patch that fixes a compiler warning in the ref-filter code. The issue arises when compiling with glibc-2.43, where a `const` qualifier is being discarded when initializing a pointer from `strrchr()`.

The patch removes the `const` qualifier from the `start` variable in `rstrip_ref_components()` since it's initialized with `xstrdup()` (which returns a non-const pointer) and is later modified through another pointer. The change is straightforward and correct - the variable was incorrectly marked as `const` when it was actually being modified.

The commit message notes there's a broader stylistic question about using `const` in this code (leading to awkward casts when freeing), but the author wisely keeps this patch focused on just fixing the warning. The change is minimal (one line) and low-risk, touching only the internal ref-filter machinery.
