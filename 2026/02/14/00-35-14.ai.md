This is a feature addition to the `git repo` command, finalizing the `--keys` flag implementation and format unification. The patch set from Lucas Seiki Oshiro represents the sixth iteration of this work, now ready for integration after addressing all substantive review feedback.

The series makes two key changes: First, it renames the output format from "keyvalue" to "newline_terminated" (following Patrick Steinhardt's suggestion) to better reflect the format's actual behavior and allow for future extensibility. The commit message now thoroughly explains why "keyvalue" was problematic - it didn't indicate newline-delimited output, was redundant with the NUL format, and constrained future additions. Second, it adds the `--keys` flag to `git repo info` to enable programmatic discovery of available metadata keys, with both newline and NUL-terminated output options.

The implementation spans the `builtin/repo.c` core logic, test updates in `t/t1900-repo.sh` and `t/t1901-repo-structure.sh`, and documentation adjustments. Notable technical details include the new `print_keys()` function handling format-specific output, strict validation preventing `--keys` from being combined with other options, and comprehensive test coverage of the new functionality.

While the series is functionally complete, one minor documentation capitalization issue remains to be fixed in a follow-up. The naming discussion between "lines" and "newline_terminated" formats has been resolved in favor of the more explicit `FORMAT_NEWLINE_TERMINATED` enum value, though the user-facing option remains "lines" for consistency with other Git commands. Junio Hamano has approved the series for integration, replacing the previously queued `lo/repo-info-keys` topic.
