This is the final version of a feature series enabling reference backend selection for zero-downtime migrations between backends (files<->reftable), primarily serving GitLab's needs. The series has maintainer approval from Junio Hamano and is in its final polishing phase.

The implementation allows specifying reference storage via:
- `extensions.refStorage` config (accepting either format names like "reftable" or URIs like "reftable:///path")
- `GIT_REFERENCE_BACKEND` environment variable (overriding config)

Key technical aspects:
- Supports worktree references in alternate locations
- Handles relative paths resolved against GIT_DIR
- Creates necessary stubs in GIT_DIR when using alternate locations
- Includes comprehensive test coverage in t1423-ref-backend.sh

The series has undergone extensive review from multiple contributors (Patrick Steinhardt, Karthik Nayak, Jeff King, Eric Sunshine, and others) with all substantive feedback addressed. The latest changes focus on const-correctness fixes, documentation refinements, and test coverage expansion.

This represents the culmination of a multi-version effort to enable seamless reference backend switching, particularly for large repositories where migration downtime must be minimized. The implementation is now ready for final acceptance into the 'next' branch.
