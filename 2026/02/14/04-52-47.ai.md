Security patch hardening Git's discovery of repository directories by validating `.git` file types. This v3 iteration implements Junio Hamano's suggested error taxonomy from the v2 discussion, distinguishing between different failure modes when checking `.git` entries.

The patch modifies `read_gitfile_gently()` to:
1. Explicitly handle ENOENT (file not found) separately from other stat failures
2. Detect and properly report directory cases via new `READ_GITFILE_ERR_IS_A_DIR`
3. Reject non-file/non-directory entries (FIFOs, etc.) with `READ_GITFILE_ERR_NOT_A_FILE`
4. Preserve symlink support by using `stat()` rather than `lstat()`

The changes address both security concerns (preventing attachment to maliciously crafted parent repositories) and filesystem corruption detection, while maintaining backward compatibility with valid workflows using `.git` symlinks. The implementation now cleanly separates error conditions that should be fatal from those that should continue repository discovery.

Key technical changes include new error codes in `setup.h` and updated logic in `setup_git_directory_gently_1()` to handle the refined error taxonomy. The patch includes test coverage for various `.git` file types (regular files, symlinks, FIFOs) showing the new validation behavior.
