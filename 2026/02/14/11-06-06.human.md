This is part 3 of a 4-patch series introducing a `--auto-advance` option for interactive patch selection commands like `git add -p`. The series is currently at version 5.

The patch refactors the patch application logic in `add-patch.c` to prepare for upcoming navigation commands. It extracts the hunk application code into a new `apply_patch()` function, which will be reused when implementing the planned '>' (next) and '<' (previous) navigation commands. The change is mechanical - it maintains the existing behavior while making the code more modular.

The commit message explains the motivation: currently, when using `--no-auto-advance`, if a user changes their mind about a hunk (from USE to SKIP) after moving between files, the change isn't properly registered. The refactoring here will help fix that issue in subsequent patches.

The changes are well-scoped and focused on the immediate need while keeping the door open for the planned navigation features. The patch follows the series' pattern of careful, incremental changes to the interactive patch machinery. Later patches in the series will add test coverage for the new behavior.
