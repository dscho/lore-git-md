This is a documentation patch (v2) from Kristoffer Haugsbakk that updates the `git-patch-id` man page to better emphasize its batch processing capabilities. The change is part of a larger series improving the patch-id documentation with practical examples.

The update makes three small but meaningful changes to the man page (+4/-3 lines):
1. Changes the command description from singular to plural ("Compute unique ID" -> "Compute unique IDs")
2. Updates the input description to reflect multiple patches ("Read a patch" -> "Read patches")
3. Clarifies that the commit ID mapping works for sets/ranges of commits, not just individual patches

The commit message provides concrete performance data showing a ~9x speedup when processing 78K commits in bulk (1 minute) versus one-by-one (9 minutes). It also includes a footnote reference to a Stack Overflow discussion showing the common but inefficient pattern of shelling out to patch-id per commit.

This patch establishes the batch-processing context for the rest of the series, which will add practical examples of using patch IDs to correlate commits across branches. The changes are purely documentation-focused and non-controversial, with the commit referencing prior discussion and performance measurements to justify the emphasis on bulk processing. The v2 update standardizes the footnote style ("†" markers) across the series.
