Feature patch completing the `--no-auto-advance` option for interactive patch selection commands. This is the final patch in a 4-part series that adds manual file navigation to `git add -p` and related commands.

The patch is applied, this implements the actual navigation behavior when `--no-auto-advance` is used with interactive patch commands (`add -p`, `checkout -p`, `reset -p`, `stash -p`). Key changes:

- Adds '>' and '<' commands to move between files while keeping hunks in their current state
- Shows a hunk summary when all hunks in a file are decided
- Only applies patches when quitting (for manual mode) rather than after each file
- Includes extensive test coverage verifying the new navigation behavior

The implementation builds on the preparatory refactoring from earlier patches in the series. The changes are well-scoped and maintain backward compatibility - the default auto-advance behavior remains unchanged. The tests demonstrate the flexibility this provides for selective staging across multiple files.

This appears ready for merging - the series has gone through multiple review iterations (now at v5) and the final implementation is clean with thorough test coverage. The feature will be particularly useful for complex multi-file interactive staging sessions.
