Performance optimization discussion for `sendfile()` implementation, revealing platform-specific constraints.

Chris Torek points out a critical limitation in the ongoing discussion about using `sendfile()` for efficient file copying - FreeBSD's implementation only works with sockets, unlike Linux's more general file-to-file copying capability. This confirms George Hu's earlier observation about significant API differences between platforms, making a truly portable solution more complex than initially hoped.

The exchange highlights two key technical barriers: 1) FreeBSD's socket-only restriction fundamentally limits the optimization's applicability on BSD systems, and 2) both platforms would still need fallback code for cases where `sendfile()` cannot be used. This follows Phillip Wood's earlier review that identified several implementation issues with the Linux-specific approach.

The thread remains focused on technical feasibility rather than revisiting the optimization's premise, though still lacks concrete benchmark data to quantify the expected performance gains. With FreeBSD's socket limitation now established, the path forward appears to require either accepting a platform-specific optimization (Linux-only) or developing a more sophisticated compatibility layer that can handle the divergent APIs and capabilities across operating systems.
