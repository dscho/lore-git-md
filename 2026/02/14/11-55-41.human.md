This is a documentation patch (v2) from Kristoffer Haugsbakk that improves the `git-patch-id` man page to better emphasize its batch processing capabilities. The patch is part of a series that adds practical examples and cross-references to related functionality.

The change updates the command description to use plural forms ("patches" instead of "patch") and adds performance data showing a ~9x speedup when processing multiple patches at once (1 minute vs 9 minutes for 78K commits). The commit message explains that while many discussions show patch-id being called in a loop for each commit, it's more efficient to pipe multiple diffs directly to the command.

The patch makes three small but meaningful documentation improvements:
1. Changes the command description from "Compute unique ID for a patch" to "Compute unique IDs for patches"
2. Updates the standard input description to use plural forms
3. Clarifies that the mapping capability works for sets/ranges of commits

This is a straightforward documentation improvement that helps users understand the command's efficient batch processing capabilities. The patch has already gone through one revision to address footnote styling consistency, and is part of a well-received series that D. Ben Knoble described as "short and sweet." The changes are purely additive and non-controversial.
