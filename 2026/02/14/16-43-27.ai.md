Performance optimization patch review focusing on Linux's `sendfile()` implementation.

Phillip Wood reviews George Hu's proposed patch to use Linux's `sendfile()` system call for more efficient file copying in `copy.c`. While acknowledging the potential performance benefits, Phillip raises several technical concerns about the current implementation. He notes the project's convention of placing platform-specific code in `compat/` directories rather than using `#ifdef`s directly in main code. The review identifies missing error handling for `fstat()` failures and points out that the current implementation doesn't properly propagate `sendfile()` errors to callers. Phillip also suggests handling `EAGAIN` for non-blocking writes and falling back to read/write loops when encountering `EINVAL`, as the man page documents various restrictions on `sendfile()`'s file descriptor usage.

The exchange continues the thread's technical focus on implementation details rather than revisiting the optimization's premise. Phillip's comments suggest the patch needs more robust error handling and alignment with Git's platform abstraction patterns before it could be considered mergeable. Notably absent from both the original proposal and this review are concrete benchmark numbers showing the performance impact of this change, which would help assess whether the complexity is justified. The discussion remains between the original participants, with Phillip bringing maintainer-level attention to code quality concerns.
