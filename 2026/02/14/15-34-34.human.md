This is a technical discussion about refactoring Git's worktree API to clarify the distinction between "current worktree" and "main worktree" cases.

Junio Hamano responds to Phillip Wood's analysis of the worktree parameter semantics in Shreyansh Paliwal's patch series. Phillip had identified that `wt==NULL` historically meant "use current worktree" while `wt->id==NULL` meant "main worktree" - a distinction the project had been conflating incorrectly.

Junio agrees with Phillip's proposal to introduce a `get_current_worktree()` helper function to properly handle the current worktree case, allowing gradual cleanup of NULL usage. He also raises concerns about the current implementation's `is_current` bit being potentially unreliable, suggesting comparing gitdir and commondir might be a more robust approach.

The discussion reveals deeper architectural questions about how worktrees should be represented in the API, with Junio noting the patch series moves toward a cleaner design but still needs to address edge cases and error handling. This is part of ongoing work to make worktree handling more explicit and maintainable.
