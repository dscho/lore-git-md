This is a refactoring patch in the final stages of the reference backend selection series, which enables zero-downtime migrations between files and reftable backends. The patch extracts common stub-creation logic into a new `refs_create_refdir_stubs()` function, consolidating duplicate code from clone.c and reftable-backend.c.

The function creates minimal directory structures (HEAD file and refs/ directory) that Git requires to recognize a directory as a repository, even when using alternate reference backends like reftable. The patch maintains the existing behavior while making it reusable - the reftable backend now uses this shared function and provides a custom message for the refs/heads file.

This change is part of the ref backend abstraction effort led by Patrick Steinhardt and Karthik Nayak, with the series already having maintainer approval from Junio Hamano. The patch follows the project's pattern of identifying duplicated functionality and extracting it to shared locations, improving maintainability as more reference backends may be added in the future. The implementation includes proper permission handling via `adjust_shared_perm()` and uses strbuf for safe path construction.
