This is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection for zero-downtime migrations between files and reftable backends. The patch is in its final polishing phase with maintainer approval already secured.

The patch introduces infrastructure to handle reference storage payloads that will be used to specify alternate reference locations via a future `extensions.refStorage` config. It adds a new `refs_compute_filesystem_location()` helper that parses the gitdir and payload to determine where references should be stored, handling both main and worktree cases. The change modifies all three backends (files, packed, reftable) to accept this payload parameter, though it's currently unused.

Key technical aspects:
- Adds payload parameter to backend init functions
- Introduces path resolution logic for reference storage locations
- Maintains compatibility with existing worktree handling
- Prepares for upcoming URI-based reference location configuration

The implementation looks solid and well-integrated with existing ref backend infrastructure. This is a foundational piece for the larger backend switching capability that's been under development, with careful attention to path handling and worktree support.
