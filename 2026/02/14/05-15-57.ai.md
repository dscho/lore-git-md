This is a small refactoring patch targeting the ref-filter subsystem, specifically addressing a compiler warning about discarded const qualifiers.

The patch fixes a warning that appears with glibc-2.43 where a `strrchr()` call on a `const char*` requires casting away constness. The issue occurs in `rstrip_ref_components()` where the function declares its strdup'd buffer as `const` even though it later modifies the buffer through a pointer. The fix simply removes the const` qualifier from the `start` variable since it's already a writable strdup'd copy.

The commit message explains the rationale clearly - the const qualifier wasn't providing any real protection since the buffer is modified, and removing it eliminates the need for awkward casts. The author notes they considered a broader cleanup of similar const usage patterns but decided to keep this patch focused on the immediate issue.

The change is straightforward and low-risk, touching only one line in ref-filter.c. It follows the project's preference for small, focused patches that address specific issues. The patch appears well-motivated and correctly implemented, though it might be worth noting that similar const usage patterns exist elsewhere in the codebase that could benefit from the same treatment.
