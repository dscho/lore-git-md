This is a feature patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable), primarily serving GitLab's needs. The series is now in its final polishing phase with maintainer approval secured.

The key additions in v6 are support for using the environment variable with `git-clone` and `git-init`, moving stub creation/removal to the generic layer, and expanding test coverage. The implementation allows both configuration (`extensions.refStorage`) and environment-based (`GIT_REFERENCE_BACKEND`) control over reference storage location.

Technical highlights include:
- Worktree reference location resolution with comprehensive const-correct string handling
- Filesystem path handling improvements
- Git directory detection timing fixes
- URI parsing and validation (now with const-correct string handling for both `schema_end` and `wt_id`)
- Comprehensive test coverage in t1423-ref-backend.sh

The series has undergone extensive review from multiple contributors including Patrick Steinhardt, Karthik Nayak, Jeff King, and Junio Hamano, with all substantive technical concerns resolved. The latest refinements complete the const-correctness work across the implementation.

This represents the culmination of a multi-version effort to enable seamless reference backend switching for large-scale repository migrations, with particular attention to GitLab's deployment needs where zero downtime is critical for repositories with millions of references.
