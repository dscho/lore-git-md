This is a maintainer confirmation of historical design intent regarding Git's date parsing behavior. Junio C Hamano responds to Gregor's question about why `--since=<date>` uses the current time rather than midnight when given a date without an explicit time component.

Junio confirms this is the established behavior dating back to Git's early days, referencing a 2005 email from Linus Torvalds that set this precedent. He explains the design rationale: using the current time for incomplete date specifications makes common queries like "what happened in the last 24 hours" more convenient, while users who specifically want midnight can explicitly specify 00:00:00. The current approach is seen as the more practical default for human use cases.

The response effectively closes the discussion by affirming this is not a bug but a deliberate choice, though Junio notes both conventions would be technically valid. This maintains Git's historical behavior while acknowledging the alternative interpretation could also make sense in theory. The thread shows how Git preserves early design decisions even when they might not be immediately obvious to new users.
