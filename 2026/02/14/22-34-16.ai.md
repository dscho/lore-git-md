This is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection for zero-downtime migrations between files and reftable backends. The patch prepares for upcoming URI-based configuration by modifying backend initialization to accept a payload parameter that will specify alternate reference storage paths.

Key changes in this patch:
1. Introduces `refs_compute_filesystem_location()` to handle path resolution for reference storage, accounting for both main and linked worktrees
2. Updates the files and reftable backends to use this new helper function
3. Makes the packed backend ignore payloads since packed-refs always lives in the common dir
4. Adds const-correct string handling throughout the path resolution logic

The implementation carefully handles both absolute and relative payload paths, with proper realpath resolution. Worktree support is maintained through detection of common dirs and worktree-specific path construction. This is a foundational change that enables the subsequent patches in the series to implement the URI-based configuration.

The patch has received extensive review from multiple contributors (Patrick Steinhardt, Jeff King, Karthik Nayak, and others) and appears ready for merging, with only minor documentation and test coverage additions remaining in later patches of the series.
