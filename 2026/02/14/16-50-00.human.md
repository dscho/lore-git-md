Performance optimization for file copying using platform-specific `sendfile()` system calls. This is a follow-up in the ongoing discussion about optimizing file copying in Git by using the Linux `sendfile()` system call to avoid user-space read/write loops.

Chris Torek points out a key limitation in the BSD `sendfile()` implementation - it only works with sockets, unlike Linux's version which handles regular files. This makes a truly portable implementation more complex than initially hoped. The thread has already established that Linux and BSD have incompatible `sendfile()` APIs, with different parameter orders and BSD requiring additional control structures.

The discussion remains technical and focused on implementation details rather than revisiting the optimization premise. Phillip Wood's earlier review identified several code quality issues that would need addressing before merge, including better error handling and moving platform-specific code to `compat/`. 

Notably absent from the thread so far are any benchmark results showing the actual performance improvement this change would provide. The technical challenges of a cross-platform solution may make this optimization Linux-specific unless someone demonstrates compelling performance gains that justify the complexity.
