This is part of the ongoing ref backend abstraction effort, specifically addressing stub file management when switching between reference storage formats (files<->reftable). The patch moves stub creation and deletion logic from backend-specific implementations to the generic refs layer, with special handling for the files backend.

The key changes are:
1. Moves `refs_create_refdir_stubs()` call into the generic ref_store_create_on_disk() function, applying it to all non-files backends
2. Implements stub deletion in ref_store_remove_on_disk() for non-files backends
3. Modifies the files backend to bypass the generic removal when cleaning up packed refs
4. Removes now-redundant stub handling from the reftable backend

This refactoring prepares for upcoming URI-based reference directory configuration by centralizing the stub management that ensures Git can recognize repositories regardless of their ref storage format. The changes maintain compatibility while simplifying the backend implementations, with careful error handling for stub file operations.

The patch is part of a mature series (v6) that has already received extensive review and maintainer approval, with this particular change addressing final polishing before integration. It builds on previous work to enable zero-downtime migrations between ref backends, a critical feature for large deployments like GitLab.
