This is a discussion about refactoring Git's worktree API to handle primary worktree representation more explicitly. Phillip Wood weighs in on Junio C Hamano's question about the difference between `wt==NULL` and `wt->id==NULL` in the worktree code.

Phillip clarifies that `wt==NULL` historically meant "use the current worktree" while `wt->id==NULL` meant "this is the main worktree". He suggests introducing a new `get_current_worktree()` function to properly handle the current worktree case, allowing the gradual removal of NULL worktree parameters across the codebase. This would be a more incremental approach than Shreyansh Paliwal's current patch series which treats both NULL cases uniformly.

The discussion reveals an important distinction in the existing API that wasn't fully documented, and Phillip's proposal aims to preserve this while still moving toward more explicit worktree handling. The thread shows active collaboration to refine the approach before the patch series moves beyond RFC status.
