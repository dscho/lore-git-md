This is a feature patch series introducing a new `--auto-advance` option for interactive patch selection in Git commands like `add -p`, `checkout -p`, and `reset -p`. The series comes from Abraham Samuel Adekunle and is now in its fifth iteration.

The main goal is to give users more control during interactive sessions by:
1. Adding a `--no-auto-advance` flag that stops automatic progression to the next file after processing hunks
2. Enabling navigation between files with '>' (next file) and '<' (previous file) commands
3. Allowing all-or-none application of patches to files

The implementation touches several built-in commands and includes comprehensive tests. The changes look well-structured, with each patch building logically on the previous ones. The author has incorporated feedback from previous versions, notably renaming the option from earlier proposals to the clearer `--auto-advance`/`--no-auto-advance` pair.

This would be particularly useful for users who want to review changes across multiple files before deciding which hunks to stage, rather than being forced to decide file-by-file in sequence. The patch series appears ready for review, with clean commit messages and good test coverage.
