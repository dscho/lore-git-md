Security-focused enhancement to the `commit-msg` hook template that detects and prevents commit messages containing separator lines ("---") that could confuse `git am`'s. This is the third patch in a series addressing the long-standing security vulnerability where `git am` can misinterpret commit messages containing unindented diffs or separator lines.

The patch modifies the sample hook to:
1. Strip commented lines (handling custom comment characters via `core.commentChar`/`core.commentString`)
2. Detect standalone "---" separator lines that would cause `git am` to truncate the commit message
3. Provide clear error messages explaining how to fix the issue by indenting problematic content

This builds on Phillip Wood's earlier work standardizing hook infrastructure and complements the existing diff detection in the hook. The implementation is careful to maintain backward compatibility while adding the new security check, and handles edge cases like custom comment characters that end with "$".

The change represents a practical mitigation for the parser ambiguity issue while deeper solutions to `git am`'s parsing behavior continue to be debated. Projects adopting this enhanced hook will gain protection against commit messages that could trigger unexpected behavior during patch application. The error messages guide users toward the safe practice of indenting diffs and separator lines in commit messages.
