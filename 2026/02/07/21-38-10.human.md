This is a discussion about security hardening for `git am`'s patch parsing, specifically addressing the commit-msg hook's handling of separator lines ("---") that could be misinterpreted as patch boundaries.

Kristoffer Haugsbakk responds to Junio Hamano's concern that the proposed security check would break his workflow of intentionally using "---" lines in commit messages as reminders for future patch formatting. Junio notes that while the hook's interruption can be bypassed with `--no-verify`, it may still inconvenience users who legitimately use this pattern.

Haugsbakk suggests an alternative approach: having the hook respect an environment variable to disable the check, with the error message pointing users to this escape hatch. This would maintain security for the default case while accommodating specialized workflows like Junio's.

The exchange highlights the tension between security hardening and backward compatibility in Git's email-based workflow. The thread shows the project carefully considering real-world usage patterns while addressing a known vulnerability where separator lines in commit messages could be misinterpreted during patch application.
