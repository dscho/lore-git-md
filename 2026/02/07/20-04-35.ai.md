This is part of the Rust infrastructure series introducing SHA-1/SHA-256 interoperability, specifically focusing on the hash algorithm abstraction layer in Rust. The patch adds core functionality for working with hash algorithms and object IDs in Rust while maintaining compatibility with Git's existing C implementation.

The key technical elements include:
- A new `InvalidHashAlgorithm` error type for handling unknown algorithm IDs
- Extension of the `ObjectID` struct with methods for safely accessing hash slices (`as_slice()` and `as_mut_slice()`) that respect the algorithm's raw length
- A `HashAlgorithm` enum representing supported algorithms (SHA-1 and SHA-256) with associated constants and methods
- Constants for special object IDs (null OID, empty tree, empty blob) in both algorithms
- Conversion methods between numeric IDs and algorithm types
- Utility methods for algorithm properties (name, format ID, lengths)

The implementation carefully mirrors Git's C-side hash algorithm handling while adapting to Rust idioms - using `Option` instead of an "unknown" sentinel value, and providing slice access that validate the algorithm. The `#[repr(C)]` attribute maintains binary compatibility with C code. This forms a foundational piece of the Rust/C interop needed for the hash algorithm work.

The patch is part of a larger coordinated effort between brian m. carlson (core functionality) and Ezekiel Newren (CI/build system), with Junio Hamano overseeing the integration. It builds on brian m. carlson's prior work making Git's internals hash-algorithm-agnostic, now introducing Rust components to enable SHA-1/SHA-256 interoperability.
