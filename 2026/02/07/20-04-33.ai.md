This is a refactoring patch that changes the type used to represent hash algorithms from `int` to `uint32_t` across several files. It's part of brian m. carlson's larger series introducing Rust infrastructure for SHA-1/SHA-256 interoperability.

The patch standardizes on `uint32_t` for hash algorithm identifiers to ensure consistent representation between C and Rust code. This is preparatory work for upcoming Rust components that will need to interoperate with these data structures. The changes are mechanical but important for type safety - they affect core data structures like `struct object_id` and touch hash algorithm lookup functions, repository configuration, and protocol handling.

Key changes include:
- Converting the `algo` field in `struct object_id` from `int` to `uint32_t`
- Updating all related function signatures (`hash_algo_by_name`, `hash_algo_by_id`, etc.)
- Modifying repository setup functions to use the new type
- Adjusting protocol code in `serve.c` to match

The patch maintains the same constants and behavior, just with more explicit typing. It's a straightforward change that helps pave the way for Rust integration while being low-risk since it doesn't alter any actual logic. The series as a whole is carefully coordinated with Ezekiel Newren's work on CI infrastructure to ensure proper testing of the Rust/C interop.
