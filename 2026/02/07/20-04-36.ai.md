This is a Rust infrastructure patch in the ongoing hash algorithm interoperability series. It adds FFI (Foreign Function Interface) glue between Git's C and Rust code for hash algorithm handling.

The patch introduces a new C function `hash_algo_ptr_by_number()` that safely looks up a hash algorithm structure by its numeric ID, returning NULL for invalid inputs. This is then exposed to Rust through FFI bindings, allowing Rust code to obtain pointers to the C `git_hash_algo` structures when needed for calling into C functions.

Key technical details:
- Adds `hash_algo_ptr()` method to Rust's `HashAlgorithm` enum that returns a raw pointer to the corresponding C structure
- Uses `*const c_void` for FFI safety rather than exposing the full C struct type
- Maintains Rust's safety guarantees by validating algorithm numbers before pointer access
- Located in `src/hash.rs` alongside other hash algorithm abstractions

This is a foundational piece for the larger effort to enable SHA-1/SHA-256 interoperability through Rust components. The careful pointer handling shows attention to Rust/C boundary safety while maintaining the performance needed for core Git operations. The patch fits cleanly into the series' architecture and doesn't appear to introduce new risks - the NULL check ensures invalid algorithm numbers won't cause undefined behavior.
