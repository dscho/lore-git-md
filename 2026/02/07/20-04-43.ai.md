This is part of the Rustification effort (patch 13/16 in v3 of the second part of the series), introducing Rust-based cryptographic hashing functionality for Git objects. The patch builds on prior work to expose Git's hash algorithms to Rust via FFI, now adding a safe, idiomatic Rust interface for hashing data and producing ObjectIDs.

The core addition is the `CryptoHasher` struct, which wraps Git's C hash implementation with Rust memory safety guarantees (proper initialization, cloning, and cleanup via `Drop`). It implements a `CryptoDigest` trait with methods for updating the hash state and finalizing to either an `ObjectID` or raw bytes. The implementation also supports the standard `Write` trait for easy integration with Rust's I/O ecosystem.

Key technical details include:
- Safe FFI calls to Git's hash functions (`git_hash_alloc`, `git_hash_init`, etc.)
- Memory management through `Clone` and `Drop` implementations
- Support for both incremental hashing and one-shot operations
- Comprehensive test coverage including empty blob/tree cases
- Algorithm-agnostic design working with both SHA-1 and SHA-256

The patch follows the series' pattern of careful, incremental Rust integration - it builds on the earlier FFI exposure of hash operations while maintaining safety and adding Rust-native conveniences. The implementation demonstrates how Rust can provide stronger guarantees (like automatic cleanup) while interoperating with Git's existing C codebase.

This functionality will be used by subsequent patches in the series for object map operations, representing a key building block in the SHA-1/SHA-256 interoperability work. The patch maintains the series' high standard for safety and cross-platform compatibility while introducing no new dependencies beyond what was already established in earlier patches.
