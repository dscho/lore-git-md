This is part 9 of a 16-patch series introducing Rust infrastructure for SHA-1/SHA-256 interoperability, specifically adding fsync support for a new object map component. The patch comes from brian m. carlson as part of their ongoing work to enable hash algorithm interoperability with Rust components.

The change adds `FSYNC_COMPONENT_OBJECT_MAP` to the `fsync_component` enum in `write-or-die.h`, which will be used to properly fsync a new object map file that will be written using the hashfile code. This is a straightforward preparatory change that follows the existing fsync pattern used for other Git components like loose objects, packfiles, and references. The patch includes the new component in both the enum definition and the default fsync components mask.

This appears to be a well-contained infrastructure change that maintains consistency with Git's existing fsync handling. The commit message clearly explains the purpose and the change is minimal and focused. As part of the larger Rust interoperability effort, this small piece of plumbing helps ensure data integrity for the new object map component that will be introduced later in the series.
