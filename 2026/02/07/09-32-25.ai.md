This is a follow-up discussion in the RFC thread for a proposed `git log --graph --untangle` feature that would simplify history visualization by suppressing ancestry lines in merge-heavy graphs. Johannes Sixt (Hannes) raises several technical concerns about edge cases and visualization clarity in the current proposal.

Hannes questions whether the simplified output accurately represents history when links are truncated, suggesting the example provided is too small to demonstrate meaningful improvement. He probes how the feature would handle complex scenarios like criss-cross merges and backward merges, which could produce misleading or ambiguous graphs. The interaction with `--boundary` is also flagged as potentially problematic given how boundary commits are currently rendered.

The email highlights key unresolved technical questions about the proposal's behavior in non-trivial cases. Hannes' closing remark about boundary commit ordering hints at an alternative approach that might address graph clutter without truncating ancestry lines. This moves the discussion toward implementation tradeoffs while maintaining the maintainer's previously expressed interest in improving graph visualization. The thread remains in exploratory phase with clear next steps: the author needs to address these edge cases and demonstrate the feature's value on more complex histories.
