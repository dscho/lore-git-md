This is part 9 of a 16-patch series introducing Rust infrastructure for SHA-1/SHA-256 interoperability, marking Git's first major Rust usage. The series builds on brian m. carlson's prior work to make Git's internals hash-algorithm-agnostic.

The current patch adds fsync support for a new object map that will be written using Git's hashfile code. It introduces `FSYNC_COMPONENT_OBJECT_MAP` to the fsync component enum and includes it in the default fsync components. This is a straightforward plumbing change that prepares for upcoming patches that will write this object map.

The change is mechanical and well-contained, touching only `write-or-die.h` to add the new component. It follows the existing pattern for fsync components and maintains consistency with how other data structures are handled. The patch is part of the larger effort to enable SHA-1 and SHA-256 repositories to exchange objects through new infrastructure that includes Rust components.
