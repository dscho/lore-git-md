CI / build system patch addressing the ongoing uutils coreutils breakage in GitHub Actions. Colin Stagner proposes a targeted fix that replaces only the problematic `dirname` command with GNU coreutils' implementation while keeping the rest of the rolling release CI environment intact.

The patch modifies `ci/install-dependencies.sh` to create a symlink from `/usr/bin/dirname` to `/usr/bin/gnudirname` when available, working around a specific bug in uutils coreutils v0.2.2 where `dirname "foo/."` incorrectly outputs "." instead of "foo". This approach follows the same pattern as an existing sudo.ws workaround in the same file.

This solution offers a middle ground between Junio Hamano's initial proposal to switch entirely to stable images and Patrick Steinhardt's suggestion for selective workarounds. The change is minimal and focused, affecting only the broken command while allowing other tests to continue running against the rolling release. The commit message references the upstream uutils/coreutils issue #10508, positioning this as a temporary measure until the root cause is fixed.

The patch appears well-contained and low-risk, though it does raise the broader question of how aggressively Git should test against bleeding-edge dependencies versus maintaining stability. The discussion continues to balance immediate CI needs with longer-term platform evolution goals.
