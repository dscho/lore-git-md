This is part of the Rustification effort (patch 14/16 in v3) introducing a new binary object map format for loose objects and other non-packed object IDs. The patch comes from brian m. carlson, who has been leading the SHA-1/SHA-256 interoperability work.

The new format addresses inefficiencies in the current loose object handling by providing a sorted binary format that can efficiently map between hash algorithms (SHA-1 and SHA-256). It also supports storing metadata about special object types like shallow entries and submodules. The implementation includes:

1. A new `LMAP` file format under `objects/object-map/` with versioned headers and alignment requirements
2. Rust data structures for in-memory mapping (`ObjectMemoryMap`) and batched writing (`ObjectMap`)
3. Memory-mapped reading support (`MmapedObjectMap`) with binary search capabilities
4. Comprehensive test coverage including round-trip verification and edge cases

The patch builds on prior work in the series that introduced Rust infrastructure and hash algorithm abstractions. It demonstrates careful attention to cross-language interoperability (via FFI) and maintains the series' pattern of thorough documentation and testing. The implementation includes optimizations like minimal prefix matching and proper alignment handling.

This represents a key piece of the object storage layer modernization, providing the foundation for efficient SHA-1/SHA-256 conversion while introducing Git's first production Rust code for core object handling. The design resembles pack index v3 format but extends it to handle multiple hash algorithms and metadata.
