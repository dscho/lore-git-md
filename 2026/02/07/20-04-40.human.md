This is part of the ongoing Rustification effort, specifically patch 10/16 in the third version of a series introducing Rust infrastructure for SHA-1/SHA-256 interoperability. The patch focuses on exposing Git's hash context functions to Rust code.

The change moves several inline hash operations from `hash.h` to `hash.c` and adds new allocation functions, making them available for Rust's FFI (Foreign Function Interface). Key changes include:
- Adding `git_hash_alloc()` and `git_hash_free()` for memory management
- Moving hash operations (`init`, `clone`, `update`, `final`) to non-inline implementations
- Keeping the same functionality but making it accessible to Rust

The patch follows the series' pattern of carefully exposing C functionality to Rust while maintaining type safety. It's a technical plumbing change that enables future Rust code to use Git's hashing infrastructure directly. The commit message clearly explains the motivation - avoiding manual memory management and inline functions that can't be linked across language boundaries.

This is one of the foundational pieces in the larger effort to build Rust components for Git's object storage system, though it doesn't yet introduce any Rust code itself. The changes are straightforward and well-contained, following established patterns for FFI functionality.
