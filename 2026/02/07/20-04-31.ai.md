This is the first patch in a 16-part series introducing Rust infrastructure for SHA-1/SHA-256 interoperability, marking Git's first major Rust usage. The patch comes from brian m. carlson as part of the ongoing Rustification effort.

The patch makes Rust a hard requirement for hash algorithm interoperability support, specifically for the loose object map functionality. It adds compile-time enforcement that Rust must be present when compatibility hash algorithms are configured, with a clear error message if not available. The changes include:

1. Modifying `repo_set_compat_hash_algo()` to fail if Rust support isn't compiled in
2. Adding a new `RUST` test prerequisite to check for Rust functionality
3. Updating several test scripts to conditionally run compatibility tests only when Rust is available
4. Splitting test setup into Rust-dependent and Rust-independent parts

The commit message acknowledges this is technically a regression in functionality, but argues it's acceptable since the interoperability features are already marked experimental and not fully functional. The patch demonstrates careful consideration of backward compatibility while moving forward with Rust integration.

Key technical details:
- Introduces `WITH_RUST` compile-time check
- Adds `RUST` test prerequisite via `build_option rust`
- Modifies repository.c to enforce Rust requirement
- Updates multiple test scripts to handle Rust dependency
- Maintains existing behavior when Rust is present

This foundational change paves the way for subsequent patches to implement the loose object map in Rust while ensuring the build system properly enforces the new dependency. The patch shows thoughtful integration with existing test suites and clear handling of the transition period.
