Security-focused documentation patch series addressing the `git am` parsing vulnerability. Phillip Wood proposes updating the sample `commit-msg` hook to reject problematic commit messages that could be misinterpreted as patches when later processed by `git am`. This is a defensive measure in response to the long-standing issue where `git am` can't reliably distinguish between intended patch content and commit messages containing diff-like text.

The series consists of three patches that would modify Git's template files to:
1. Add proper `.gitattributes` handling for sample hooks
2. Detect and reject commit messages containing diff output
3. Catch messages with separator lines that could confuse the patch parser

The cover letter acknowledges that while fixing `git am` itself remains challenging due to backward compatibility concerns, improving documentation and adding guardrails via the sample hook could help prevent accidents. The approach is pragmatic - since the root issue in `git am` parsing is complex and involves tradeoffs, this provides immediate protection at the commit-message level.

This is a well-motivated series that addresses a real security concern while avoiding the thornier questions of modifying `git am`'s behavior. The patches are focused and clearly explained, though they represent a mitigation rather than a complete solution to the underlying parsing ambiguity.
