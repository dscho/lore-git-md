This is a documentation and bugfix patch for `git merge-file`'s handling of the `merge.conflictStyle` configuration. The patch ensures the command respects this config setting even when run outside a Git repository, bringing its behavior in line with other Git commands that read config globally.

The change is straightforward: instead of only reading config when inside a repository (checked via `startup_info->have_repository`), it now unconditionally passes the `repo` parameter to `repo_config()`, which already handles the non-repo case by falling back to system and user config. The patch also documents that `merge.conflictStyle` affects the command's behavior.

A new test case verifies the fixed behavior by setting a global config and running `git merge-file` outside a repository, checking that the configured conflict style (diff3) is honored. The test follows Git's standard expect/actual pattern and includes proper cleanup of temporary files.

This is version 2 of the patch, incorporating feedback from Junio Hamano (to use `repo_config()` directly) and Kristoffer Haugsbakk (documentation formatting and test style). The implementation is now simpler and more maintainable than the initial approach while preserving the same behavior precedence (command-line flags override config).
