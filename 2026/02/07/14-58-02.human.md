Security-focused enhancement to the `commit-msg` hook template, addressing a long-standing `git am` parsing vulnerability. This is the third patch in a series that provides practical mitigation for the issue where unindented diffs or separator lines ("---") in commit messages can confuse `git am`'s parser, potentially leading to security risks.

Phillip Wood extends the sample hook to now also detect and reject commit messages containing unindented "---" separator lines, which `git am` would interpret as the start of a patch). The hook already checked for unindented diffs, and this change adds similar protection against separator lines. The implementation handles edge cases like configurable comment characters and maintains backward compatibility.

The patch is part of a layered approach to this security issue - while deeper parser improvements are still being debated, this provides immediate protection for projects that choose to enable the enhanced hook. The change is well-contained, touching only the hook template file, and includes clear error messages to help users understand and fix the issue.
