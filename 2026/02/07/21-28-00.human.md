This is a documentation and implementation patch addressing `git merge-file`'s handling of `merge.conflictStyle` configuration. The patch series has evolved through multiple iterations with input from Junio C Hamano and Kristoffer Haugsbakk, and is now in its final form.

The patch fixes an inconsistency where `git merge-file` respected the `merge.conflictStyle` config only in repository contexts while accepting command-line flags universally. The solution uses Git's existing `repo_config()` infrastructure to handle both repository and non-repository cases uniformly, maintaining the existing precedence order (CLI flags > repo config > global config). A new test case in `t6407-merge-binary.sh` verifies the behavior outside repository contexts, and documentation has been updated to accurately describe the behavior.

Junio provided additional feedback about Git mailing list conventions, emphasizing that patches should generally be sent as separate messages rather than embedded in replies, and when including patches inline, proper formatting with a scissors line (`--- >8 ---`) should be used. This guidance is process-related rather than technical, as the technical solution was already settled.

The change is small but meaningful for users relying on consistent conflict style behavior, and demonstrates Git's config system evolution to handle both repository and non-repository cases uniformly. The documentation updates and new test case ensure the behavior remains correct and well-documented going forward.
