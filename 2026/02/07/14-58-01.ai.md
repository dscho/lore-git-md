Security-focused patch adding commit message validation to prevent `git am` confusion. This is part of Phillip Wood's series addressing the long-standing issue where unindented diffs in commit messages can be misinterpreted by `git am` as actual patches to apply, potentially introducing malicious code.

The patch enhances the sample `commit-msg` hook to detect and reject commit messages containing unindented diffs that could trigger this parser ambiguity. It handles several edge cases: checking for diffs only above the scissors line (where commit message cleanup would remove them), and properly detecting the comment character used in the scissors line (which can be configured via Git's `core.commentChar` or `core.commentString` settings).

The implementation looks robust, scanning for both traditional `diff -` and `Index:` headers while respecting the commit message structure. This builds on Wood's earlier infrastructure work to standardize hook file handling, and provides a practical mitigation while the deeper parser issues continue to be debated. The commit message cites multiple real-world cases where this confusion caused problems, showing clear motivation.

This is a defensive measure that doesn't break existing workflows - it simply makes the sample hook more security-conscious. Projects adopting the hook would get protection against accidental or malicious injection of unindented diffs, while still allowing properly indented diffs in commit messages. The patch maintains the hook's existing Signed-off-by line checking while adding the diff detection.
