This is a documentation patch addressing a known security issue in `git am`'s patch application behavior. Kristoffer Haugsbakk responds to Matthias Beyer's report about how `git am` can mistakenly apply diffs embedded in commit messages, citing a real-world incident where this caused a `sleep(1)` call to be unintentionally into the Debian i3 package.

The thread has established that this is a long-standing issue affecting both `git am` and the traditional `patch(1)` tool, with prior discussions dating back years. Phillip Wood has already implemented security-focused enhancements to the sample `commit-msg` hook to detect and prevent such cases, though some workflow compatibility questions remain open.

Haugsbakk's contribution here focuses specifically on improving the documentation to warn users about this pitfall. While the technical solutions are being worked on separately, this patch would help raise awareness of the issue in the meantime. Given the demonstrated real-world impact (the Debian incident) and the security implications, this documentation update seems well-motivated and timely.
