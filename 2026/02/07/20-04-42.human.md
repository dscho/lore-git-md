This is part of the ongoing Rustification effort in Git, specifically patch 12/16 in the third iteration of a series introducing Rust infrastructure for SHA-1/SHA-256 interoperability. The patch comes from brian m. carlson, who has been leading this work.

The patch adds a `build.rs` script to handle linking requirements for Rust test binaries. This is preparatory work for future changes where test binaries will need to link against `libgit.a`. The script specifies the search path and libraries (`git` and `z`) that Rust's build system should use when compiling tests. The Makefile is also updated to ensure the static library is built before the Rust components to prevent race conditions during parallel builds.

This is a small but important infrastructure piece in the larger Rust integration effort. The change is straightforward and well-contained, focusing specifically on build system coordination between Rust and Git's existing C components. It follows the pattern seen in other projects that use Rust's build scripts to manage linking against C libraries. The patch appears technically sound and uncontroversial, though it's part of a broader series that has generated discussion about Rust's role in Git.
