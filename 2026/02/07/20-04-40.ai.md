This is part of the ongoing Rust infrastructure work for SHA-1/SHA-256 interoperability, specifically patch 10/16 in the third iteration of part 2 of the series. The patch focuses on exposing Git's hash context functions to Rust code in a way that maintains memory safety and proper FFI boundaries.

The key changes move several inline hash functions from `hash.h` to `hash.c` and make them non-inline, while adding new allocation and initialization functions (`git_hash_alloc`, `git_hash_free`, `git_hash_init`). This allows Rust code to safely create, use, and destroy hash contexts through FFI calls without needing to know the internal structure size or manage memory manually. The patch follows the series' pattern of carefully exposing C functionality to Rust while maintaining type safety and proper resource management.

The implementation provides the full suite of hash operations (init, clone, update, final) as callable functions rather than inlines, which is necessary for FFI compatibility. This builds on earlier work in the series that established the Rust infrastructure and type-safe interfaces. The changes are preparatory for Rust code that will need to compute object hashes while maintaining the same cryptographic properties as the C implementation.
