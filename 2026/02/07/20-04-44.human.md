This is part of the ongoing Rustification effort and SHA-1/SHA-256 interoperability work, specifically introducing a new binary object map format for loose objects. The patch comes from brian m. carlson as part 14/16 in a larger series.

The patch adds a Rust implementation of a binary object map that stores mappings between SHA-1 and SHA-256 object IDs for loose objects and other special cases (like shallow entries and submodules). The format resembles Git's pack index v3 format and includes:

- A new `$GIT_DIR/objects/object-map/map-*.map` file format with documented structure
- In-memory and mmap-based implementations for efficient lookups
- Support for batched writes to optimize disk I/O
- Comprehensive test coverage including round-trip verification

The motivation is to solve inefficiencies in the current loose object handling, particularly when working with repositories that need to maintain compatibility between different hash algorithms. The implementation carefully handles alignment requirements and includes safety checks for memory access.

This represents a significant piece of infrastructure for the broader hash algorithm transition work, providing the storage layer needed to maintain object identity across algorithms. The code appears well-structured with thorough documentation and testing, though some functionality (like actual file I/O) is deferred to future patches that will integrate with Git's C code.
