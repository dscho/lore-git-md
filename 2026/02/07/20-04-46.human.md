This is the final patch in a 16-part series introducing Rust infrastructure for SHA-1/SHA-256 interoperability, marking Git's first major Rust usage. The patch addresses a subtle edge case in object ID handling where zero-initialized object IDs (with algo=0) could cause issues with the new Rust-based loose object map code.

The core issue is that the Rust object map implementation strictly validates algorithm numbers, while some legacy C code paths create object IDs with algo=0 (an invalid value) that would normally get papered over by using the repository's default algorithm. The fix ensures these invalid algo values are normalized early in the conversion process by creating a temporary copy with the correct algorithm.

This is a defensive change that maintains compatibility with existing code while ensuring the new Rust components work reliably. It follows the series' pattern of careful attention to type safety and cross-language boundary issues. The patch is small and focused, with a clear commit message explaining both the problem and solution.

As the concluding patch in this substantial series, it helps ensure robust handling of edge cases as Git moves toward supporting multiple hash algorithms simultaneously through its new Rust infrastructure.
