This is a security-focused enhancement to the sample `commit-msg` hook, part of the ongoing effort to prevent `git am` parsing vulnerabilities. Phillip Wood's patch adds detection for commit messages containing "---" separator lines that could cause `git am` to truncate messages unexpectedly.

Junio Hamano raises a valid counterpoint - some experienced contributors (including himself) intentionally use "---" in commit messages as a workflow aid when preparing patches. The hook would block this legitimate use case, forcing users to bypass it with `--no-verify`. While the security benefit is clear, the tradeoff is disrupting established workflows.

The technical implementation handles edge cases well: it strips comment lines (respecting configurable comment characters) before checking for separators, and provides clear error messages. However, Junio's feedback suggests this may need to be optional or configurable rather than enabled by default in the sample hook.

This patch represents a practical mitigation while deeper parser improvements are debated, but the discussion highlights the tension between security hardening and backward compatibility in Git's email-based workflow. The thread shows maintainers carefully weighing these factors before deciding whether to accept the change.
