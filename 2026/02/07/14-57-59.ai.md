This is a documentation and tooling patch series addressing the long-standing `git am` security vulnerability where commit message diffs can be misinterpreted as patches. Phillip Wood proposes updating the sample `commit-msg` hook to reject problematic commit messages that could confuse `git am`'s parser.

The series acknowledges that while fixing `git am`'s parsing ambiguity remains challenging (as discussed in prior threads from 2015-2024), we can at least prevent dangerous patterns from entering the commit history in the first place. The patches would modify Git's template hooks to detect and reject two specific cases: commit bodies containing raw diffs (which could be misinterpreted as patches) and commit messages containing separator lines ("---") that `git am` uses to split messages from patches.

The implementation adds pattern matching to the sample hook while maintaining backward compatibility. Phillip suggests this could be complemented by improved documentation warnings in `git am` and `git format-patch` to educate users about the risks. The approach is pragmatic given the technical constraints - since we can't reliably fix the parser ambiguity without breaking workflows, we instead prevent the dangerous inputs from being created.

Key technical details include the new `.gitattributes` entry ensuring hook files maintain executable permissions, and the specific regex patterns added to detect diff content and separator lines. The changes are focused on the sample hook templates rather than core Git behavior, making them low-risk to merge while still providing real security benefits. This represents a defensive programming approach to a known vulnerability that has already caused real-world incidents (like the Debian i3 window manager case where `sleep(1)` was accidentally introduced from a commit message).
