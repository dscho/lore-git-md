This is a documentation patch from Kristoffer Haugsbakk, part of a series improving the `git-patch-id` man page. The patch emphasizes that `git patch-id` can efficiently process multiple patches at once, rather than requiring a slow shell script that processes commits one by one. It updates the command description to use plural forms ("patches" instead of "patch") and adds a note about processing sets or ranges of commits.

The commit message provides concrete performance numbers showing the bulk processing approach is about 9x faster than the naive loop approach (1 minute vs 9 minutes for 78K commits). The changes are purely additive and non-controversial, focusing on making existing functionality more discoverable in the documentation. This continues the author's pattern of refining the patch-id documentation with practical usage guidance.
