Feature proposal for `git clean` to respect ignored files.

Sylvain Rabot proposes adding an option to make `git clean -fdx` respect certain ignored files, preventing accidental deletion of valuable configuration files. The motivation comes from personal experience where editor/debug configurations kept getting deleted by the aggressive cleaning. 

The patch (generated by an AI) modifies `builtin/clean.c` to add a new `--keep-ignored` flag that would make `git clean` skip files matching patterns in `.gitignore`. The author acknowledges they're not a C developer and doesn't expect the patch to be merged as-is, but is seeking feedback on whether this functionality would be desirable in principle.

This touches on a real pain point - the current behavior forces users to choose between thorough cleaning (risking data loss) and manual selective cleaning (more work). The proposal seems well-intentioned but the implementation would need careful review, particularly around edge cases like nested ignore rules and performance impact when checking ignores. The mailing list will likely discuss whether this belongs in core Git or could be handled via existing mechanisms like custom clean scripts.
