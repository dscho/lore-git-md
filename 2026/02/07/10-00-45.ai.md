This is part 3/3 of a refactoring series targeting `wt-status.c` as part of the ongoing `the_repository` removal effort. The series eliminates direct dependencies on global variables `the_repository` and `the_hash_algo` in the working tree status machinery.

The final patch replaces remaining uses of the global `the_hash_algo` with the hash algorithm stored in the respective repository instance. This completes the technical work to remove direct global variable dependencies from `wt-status.c`, though the `USE_THE_REPOSITORY_VARIABLE` macro cannot yet be removed due to other global dependencies (notably `comment_line_str` and `DEFAULT_ABBREV` which will be addressed separately).

The changes are mechanical but important for the larger architectural goal of eliminating implicit global state. The patch updates hash algorithm access in `wt-status.c` functions to use `r->hash_algo` where a repository is available, and `s->repo->hash_algo` when working with `struct wt_status`. This maintains consistency with the direct parameter passing approach established in earlier patches.

The series has progressed through three versions with review input from Karthik Nayak, Junio C Hamano, Phillip Wood, and Kristoffer Haugsbakk. All test failures from earlier versions have been resolved, and Phillip Wood's feedback about eliminating new `the_repository` usages in callers has been incorporated. The implementation now cleanly passes repository context through the call chain while properly handling NULL worktree cases.

For future work, two global dependencies remain that prevent full removal of `USE_THE_REPOSITORY_VARIABLE` - these are explicitly scoped for follow-up RFC series. The patterns established here for safely passing repository context may influence future `the_repository` removal efforts in other subsystems.
