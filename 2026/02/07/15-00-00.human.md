This is a discussion thread about Sylvain Rabot's proposal to add a `--keep-ignored` option to `git clean -fdx` that would preserve certain ignored files (like editor configurations) from deletion. Kristoffer Haugsbakk points to a related GitHub pull request that appears to tackle the same or similar functionality.

The core tension is between the convenience of `git clean -fdx` (which currently removes all untracked files, including ignored ones) and the risk of accidentally deleting valuable ignored files. Sylvain's use case focuses on preserving editor/debug files that are typically ignored but still important to keep. The thread is weighing whether this functionality belongs in core Git versus being handled by wrapper scripts, and how it should interact with nested ignore rules.

The discussion is still in early stages, with the main questions being about the design approach rather than implementation details. Kristoffer's reference to a related PR suggests there may be prior work to consider in this space. The patch itself is currently marked as a proof-of-concept from a non-C developer, indicating it will need significant review and likely revision if the concept gains traction.
