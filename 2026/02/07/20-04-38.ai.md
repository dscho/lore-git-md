This is a type-safety patch in the ongoing Rust interoperability series from brian m. carlson. It changes the `count` parameter of `hashwrite()` from `unsigned int` to `uint32_t` to ensure consistent type sizes when calling from Rust side of the codebase.

The change is straightforward - it standardizes on a fixed-width type for cross-language compatibility. The commit message notes this is motivated by Rust interop needs, where having predictable type sizes simplifies FFI boundaries. The patch affects both the declaration in `csum-file.h` and implementation in `csum-file.c`.

This appears to be a mechanical change with no behavior impact, just type system alignment. It's part of the larger effort to enable Rust/C interoperation for the SHA-1/SHA-256 object exchange work. The patch is narrowly focused and well-contained, touching only the hashfile I/O subsystem.
