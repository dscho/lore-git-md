This is a build system patch in the ongoing Rustification effort, specifically part 2 of brian m. carlson's series to enable SHA-1/SHA-256 interoperability through Rust infrastructure. The patch addresses a Windows/MSVC-specific linking issue that arises when building with Cargo under MSYS (as in Git for Windows CI).

The core problem is that MSYS's PATH ordering causes Cargo to find the wrong `link` binary (the Unix utility rather than MSVC's linker) when linking Rust binaries. The solution modifies `src/cargo-meson.sh` to reorder PATH during Windows/MSVC builds, ensuring the compiler's linker is found first while still allowing access to Unix tools. The change is particularly important now that Rust build scripts (`build.rs`) will be involved in the linking process.

The patch moves the LIBNAME determination earlier in the script and adds the PATH adjustment logic specifically for MSVC targets. It maintains compatibility with existing build flows while fixing the linking issue that would otherwise break Rust build script execution. The change is co-authored with Ezekiel Newren, who is handling the CI infrastructure aspects of this series.

This is a targeted fix that follows the pattern seen elsewhere in the series of addressing Windows/MSVC-specific concerns as they arise during Rust integration. The patch appears straightforward and well-motivated, with clear explanation of both the problem and solution in the commit message.
