This is a security-related patch that adds a check to the sample `commit-msg` hook to prevent commit messages containing unindented diffs, which can confuse `git am`'s parsing logic. The patch is part of an ongoing effort to address a long-standing security vulnerability where `git am` can misinterpret embedded diffs in commit messages as actual patches to apply.

Phillip Wood's patch enhances the default hook to detect two problematic patterns that trigger this parser confusion: lines starting with "diff -" and "Index: ". The hook now checks for these patterns above any scissors line" (the `--- >8 ---` marker that separates commit messages from comments), as the message content before that point is what `git am` will process.

The implementation handles several edge cases: it respects the configured comment character (which can vary across projects) and ignores diffs below the scissors line. The check runs alongside the existing duplicate Signed-off-by detection, maintaining the hook's non-zero exit status if either check fails.

This is a practical mitigation while broader parser improvements continue to be debated. The patch follows preparatory infrastructure changes (in the previous patch of this series) that standardized sample hook file handling. The approach reflects a defensive strategy - catching problematic patterns at commit creation time rather than trying to make `git am` perfectly parse all possible inputs.
