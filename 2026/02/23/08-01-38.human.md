This is part of the ref backend abstraction effort, specifically focusing on stub management for repository recognition. The patch moves stub creation and deletion logic from backend-specific code to the generic refs layer, with special exception handling for the traditional files backend.

Karthik Nayak's patch (v8 3/6 in the series) centralizes the creation and removal of stub files (HEAD and refs/ directories) that help Git recognize a directory as a repository. The change prepares for upcoming work supporting alternate reference backend locations by making stub handling consistent across all backends except the files backend, which retains its own special behavior.

The implementation carefully preserves existing functionality while moving the logic - stub creation now happens in the generic `ref_store_create_on_disk()` function, and stub removal in `ref_store_remove_on_disk()`. The files backend gets an explicit bypass to avoid duplicate stub handling since it manages its own packed-refs cleanup.

This appears to be a well-considered mechanical change in a mature series that has already received extensive review. The patch follows the established pattern of the ref backend abstraction work and maintains clear separation between the files backend special cases and the generic handling needed for other backends like reftable.
