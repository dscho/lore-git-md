Performance improvement for `git config list --type=expiry-date`. This is patch 9/13 in Derrick Stolee's series optimizing config value filtering by type. The series was originally motivated by performance issues in git-credential-manager when handling path-type config values.

This patch moves expiry date parsing into its own helper function `format_config_expiry_date()` and implements quiet parsing for invalid dates when using `--type=expiry-date`. The change makes the behavior consistent with other type filters in the series, though it notes an asymmetry in Git's date parsing APIs - `git_config_expiry_date()` shows errors but doesn't die like most other config parsers.

The patch updates tests to verify that invalid dates are now silently skipped rather than producing error messages. This completes the type-specific handling pattern established in earlier patches for integers, booleans, bool-or-int, bool-or-str, and path values. The implementation follows the same approach used throughout the series, maintaining consistency while improving performance by filtering during initial parsing rather than after.
