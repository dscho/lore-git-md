This is part of the ref backend abstraction effort, specifically patch 3/6 in the v8 series that implements reference storage backend selection. The patch moves stub creation/deletion logic for repository recognition from backend-specific code to the generic refs layer.

The key changes are:
1. Moves `refs_create_refdir_stubs()` calls from reftable backend to the generic `ref_store_create_on_disk()` function
2. Adds stub deletion logic to `ref_store_remove_on_disk()` for non-files backends
3. Special-cases the files backend to avoid redundant stub operations since it handles this differently
4. Prepares for upcoming work on alternate reference backend locations by centralizing this logic

The patch is part of the infrastructure needed for zero-downtime migrations between ref backends (files<->reftable). It follows the established pattern of this well-reviewed series, with maintainer approval already secured. The changes are mechanical but important for the overall architecture, moving backend-specific behavior into shared infrastructure where appropriate while preserving special cases for the traditional files backend.
