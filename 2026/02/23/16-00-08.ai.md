This is the third patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch refactors object streaming internals to enable direct packfile access during verification.

The change extracts a new `packfile_read_object_stream()` function from `packfile_store_read_object_stream()`, making the lower-level packfile access available to callers who already know the packfile and offset. The new function maintains all existing behavior including corruption marking when encountering bad objects, while allowing direct access without requiring an object lookup. The original function is reimplemented as a thin wrapper that performs the pack entry lookup before calling the new function.

Key technical details:
- New function signature takes explicit `pack` and `offset` parameters instead of looking them up
- Preserves all error handling and corruption marking behavior from original
- Maintains identical streaming interface via `struct odb_read_stream`
- Changes span `packfile.c` and `packfile.h` with no test modifications needed
- Part of preparing for the final fix that will use direct pack access to avoid MRU-triggered infinite loops

This is a clean refactoring that enables the subsequent fix while maintaining all existing functionality. The change has been reviewed by Jeff King and incorporates his suggestions from v1. The patch is well-contained and clearly motivated by the series' overall goal of fixing fsck verification issues.
