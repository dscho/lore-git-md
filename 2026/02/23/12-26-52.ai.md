This is patch 10/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series aims to optimize config value parsing by implementing type-specific handling during initial parsing rather than filtering after full parsing.

This particular patch introduces `color_parse_quietly()` to complement the existing color parsing functionality. The change factors out the core color parsing logic into a helper function `color_parse_mem_1()` that takes a `quiet` parameter, then provides both the original error-reporting behavior (`color_parse()`) and a new quiet variant that silently returns -1 on failure.

The implementation follows the same pattern seen in earlier patches for other config types (bool, int, path, etc.), maintaining consistency with the series' approach to gentle parsing. The patch includes the necessary header declaration and minimal code reorganization to keep related functions together while respecting declaration order dependencies.
