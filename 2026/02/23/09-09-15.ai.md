This is a refactoring patch from Patrick Steinhardt's series to unify Git's ref iteration interfaces. Patch 10/17 adds stricter validation to the new `refs_for_each_ref_ext()` API, which is replacing multiple specialized ref iteration functions.

The patch introduces two key safety checks: it now requires a non-NULL ref store (BUG-ing if NULL) and adds validation for prefix trimming logic. The prefix trimming validation ensures that trimming is only done when a prefix exists, and that the prefix ends with a trailing slash to prevent empty refnames. Karthik Nayak reviewed the patch, suggesting a minor wording tweak ("refs" -> "ref store") for the BUG message but otherwise approving the changes.

The validation changes are safe because an audit showed no existing callers rely on the previous lenient behavior. This continues the series' pattern of carefully maintaining behavior while making the API more robust. The patch touches the core refs.c file but is a focused change that doesn't affect other subsystems.
