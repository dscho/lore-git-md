This is patch 11/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series addresses inefficiencies in config value parsing by implementing type-specific handling during initial parsing rather than filtering after full parsing.

This particular patch focuses on color value handling, extracting the logic into a new `format_config_color()` helper function that follows the established pattern from previous type handlers. The key changes are:

1. Introduces quiet parsing for color values via `color_parse_quietly()`, suppressing error messages when checking if a value matches the color type during filtering. This matches the behavior implemented for other types in earlier patches.

2. Updates the test to verify that invalid color values no longer produce error messages when using `--type=color` filtering, while still correctly filtering to only show valid color values.

The patch maintains consistency with the series' approach of moving type-specific logic into dedicated functions and using gentle parsing during filtering. It builds on the foundation established in patches 1-10, which implemented similar handling for integers, booleans, bool-or-int, bool-or-str, paths, and expiry dates.

Performance measurements from earlier in the series confirm the approach successfully addresses the git-credential-manager bottleneck that motivated the work. All substantive design questions appear resolved at this point in the series.
