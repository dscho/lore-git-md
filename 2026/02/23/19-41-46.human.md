Feature patch for `git fast-import` adding a new signature handling mode. This is the second patch in a series from Justin Tobler, building on Christian Couder's initial work.

The patch introduces a `re-sign-if-invalid` mode for `--signed-commits` that will regenerate signatures for commits with invalid signatures during import, rather than just stripping them. The new mode uses the current user's signing key and only signs with the repository's primary hash algorithm, ignoring any compatibility object formats that may have been used for additional signatures in the original commit.

The implementation touches several areas: the fast-import/fast-export code, gpg-interface plumbing, and updates the test suite to verify the new behavior. The tests show the mode correctly handles various signature types (OpenPGP, X.509, SSH) and properly regenerates signatures when they're invalidated by message changes.

This appears to be a well-constructed patch with thorough test coverage. The commit message clearly explains the behavior and current limitations (not handling compatObjectFormat signatures). The change builds logically on existing signature handling in fast-import while providing a useful new capability for repository migrations where signature validity needs to be preserved.
