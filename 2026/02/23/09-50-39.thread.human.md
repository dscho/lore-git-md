This thread addresses a bugfix series from Patrick Steinhardt that fixes an infinite loop in `git fsck` when verifying large objects across multiple packfiles, originally reported by brian m. carlson. The four-patch series begins with test infrastructure improvements and preparatory refactoring before delivering the core fix, which replaces `odb_read_stream_open()` with direct packfile access via `packfile_read_object_stream()` to prevent MRU-triggered infinite loops.

Jeff King has thoroughly examined each patch, confirming the technical soundness of the changes while providing focused feedback. He particularly praised the final fix as "delightfully simple" but noted the test case could be strengthened to more rigorously verify corruption detection when the same object exists in multiple packs (with one corrupt and one valid). Patrick acknowledges this gap and plans to investigate solutions for version 2 of the series, noting the challenge of reliably creating corrupted objects with hash mismatches for testing purposes.

The changes span several files including `pack-check.c`, `packfile.c`, and `object.c`, with test coverage in `t1450-fsck.sh` and `t1050-large.sh`. While the core fix is complete and addresses the original issue, the discussion has identified remaining work to improve test robustness around MRU pack ordering behavior before finalizing the series.
