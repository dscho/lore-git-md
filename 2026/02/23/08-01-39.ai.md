This patch is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection with payload support for zero-downtime migrations between backends (files<->reftable). It's the 4th patch in the v8 series of 6, which has maintainer approval and is ready for integration.

The patch introduces payload handling for reference backends, allowing alternate storage paths to be specified. Key changes include:

1. Adding a new `refs_compute_filesystem_location()` function that calculates reference directory paths based on gitdir and an optional payload, handling both main and worktree cases
2. Modifying backend initialization to accept a payload parameter (files, packed, and reftable backends)
3. Updating the files and reftable backends to use the new path computation logic
4. Preserving special handling for packed-refs in the common directory

The changes are preparatory work for upcoming URI-based backend configuration via `extensions.refStorage`. The patch maintains backward compatibility since no callers currently pass a payload. The implementation includes proper path resolution and worktree handling while keeping the packed backend's special behavior.

This is a well-structured patch with clear commit message and implementation. It follows the series' architectural direction while handling edge cases like worktree references and path resolution. The changes are focused and maintain existing behavior when no payload is provided, making it a safe incremental step toward the larger migration feature.
