This is patch 14/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces. The series is in its final polishing stage with Karthik Nayak's approval.

The patch removes the specialized `refs_for_each_glob_ref_in()` function, replacing all its callers with the new unified `refs_for_each_ref_ext()` interface. The conversion affects several key areas: bisect` functionality (tracking good/bad refs), `rev-parse` (reference listing), and revision walking (handling branch/tag/remote patterns).

The changes maintain identical behavior while using the new options struct pattern, with each caller properly initializing the required fields (pattern, prefix, and trim_prefix). The patch demonstrates the series' goal of simplifying the API surface - this is the last remaining glob iteration function being removed.

Performance impact was already demonstrated in earlier patches (a 107x speedup for glob matching), and all behavior-preserving conversions have been thoroughly reviewed. The series is clearly well-crafted and addresses a real need in the codebase's evolution.
