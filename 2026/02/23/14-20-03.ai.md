This is a refactoring patch that fixes incorrect `strbuf_attach()` calls across several Git subsystems. The patch is part of Vaidas Pilkauskas's ongoing work to properly handle buffer allocations when attaching strings to strbufs.

The core issue is that `strbuf_attach()` requires the allocated size parameter to be at least len+1 bytes to accommodate the NUL terminator, but several call sites were passing alloc == len. While this worked due to strbuf_grow()'s reallocation behavior, it was technically incorrect and could lead to inefficient memory usage.

The patch updates five call sites in builtin/am.c, builtin/fast-import.c, mailinfo.c, refs/files-backend.c, and trailer.c to properly pass len+1 as the allocation size when attaching NUL-terminated strings. Each change is straightforward and mechanical - just adding +1 to the alloc parameter where appropriate.

This builds on prior discussion in the thread where Junio Hamano noted that strbuf_attach's space optimization provides measurable performance advantages, so the consensus was to keep using it but fix the incorrect allocations. The changes are minimal and focused, touching only the allocation size parameter without altering the surrounding logic.

The patch appears well-scoped and correctly implements the agreed-upon fix from the thread discussion. It follows Git's coding style and includes a clear commit message explaining both the problem and solution. As a follow-up to prior consensus, this seems unlikely to generate controversy and should be ready for merging.
