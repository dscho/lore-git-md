Refactoring patch in Patrick Steinhardt's series unifying Git's ref iteration API. This is patch 10/17 in the "refs: unify ref iteration interfaces" effort, which has already received overall approval from primary reviewer Karthik Nayak.

The patch strengthens validation in the new `refs_for_each_ref_ext()` function by adding BUG() assertions for invalid input cases that were previously silently accepted. Specifically, it now requires:
- A non-NULL ref store (previously silently returned success for NULL)
- That prefix trimming only occurs when a prefix is specified
- That trimmed prefixes end with a trailing slash to prevent empty refnames

The changes are defensive programming measures that don't affect current callers (an audit confirmed none rely on the previous permissive behavior). The patch continues the series' pattern of making the ref iteration API more robust while maintaining identical external behavior. 

Key technical details:
- Adds three new BUG() checks with descriptive messages
- Maintains the same function signature and options struct
- Preserves all existing functionality for valid inputs
- Follows the series' goal of API unification without behavior changes

This is part of the broader ref backend modernization effort that Patrick Steinhardt has been leading, with Karthik Nayak as primary reviewer. The series is in its final polishing stages with all major technical points already resolved.
