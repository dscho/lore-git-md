This is the final patch in a bugfix series from Patrick Steinhardt addressing pack validation issues with large objects. The problem was originally reported by brian m. carlson, where `git fsck` could enter an infinite loop when processing packfiles containing large blobs (those exceeding core.largeFileThreshold).

The root cause stems from how large objects are verified - the code was using `odb_read_object_stream()` which performs an object lookup that can trigger updates to Git's MRU (most recently used) packfile list. When verifying multiple large objects across different packfiles, this could create an infinite loop as the MRU list gets constantly reshuffled.

The fix changes the verification to use `packfile_read_object_stream()` directly instead, which reads the object from the specific pack being verified without triggering MRU updates. This both prevents the infinite loop and ensures we're actually verifying the object from the pack we intended to check, rather than potentially reading it from another pack.

The patch includes a test that reproduces the original failure case by creating two large blobs in separate packfiles and verifying them with fsck. This is the culmination of a series that started with preparatory refactoring in earlier patches to enable this fix. The changes are focused in pack-check.c and maintain the existing behavior while fixing the edge case.
