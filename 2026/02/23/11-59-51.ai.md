Refactoring patch completing Patrick Steinhardt's series to unify Git's ref iteration API. This final patch (17/17) removes the now-obsolete `refs_for_each_fullref_in()` function, converting all remaining callers to use the new unified `refs_for_each_ref_ext()` interface with its `struct refs_for_each_ref_options`.

The conversion touches several key areas: bisect cleanup in `bisect.c`, ref advertisement in `receive-pack.c`, rev-parse's bisect handling, show-ref's pattern matching, and revision walking's bisect support. Each case now initializes an options struct to pass prefix/exclude patterns rather than using the old function's direct parameters. The patch also removes the function declaration from `refs.h` and its now-unused implementation in `refs.c`.

This completes the series' goal of consolidating specialized ref iteration functions into a single configurable API, with only `refs_for_each_replace_ref()` remaining as a special case. The changes maintain identical behavior while simplifying the codebase, following Karthik Nayak's thorough review of the entire series. Performance-critical paths like ref advertisement and bisect operations now benefit from the series' earlier optimizations (notably the 107x speedup for glob matching).
