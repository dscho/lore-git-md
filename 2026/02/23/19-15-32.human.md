This is a test case documenting a bug in the interaction between `receive.denyCurrentBranch=updateInstead` and worktrees with unborn branches in bare repositories. The test shows that when pushing to a bare repo with a worktree where the bare HEAD points to an unborn branch (different from the worktree branch), Git incorrectly rejects the push with "Working directory has staged changes" even though the worktree is clean.

Junio Hamano questions whether this ever worked correctly, suggesting the behavior might not be a regression but rather a long-standing edge case. The test is currently `test_expect_failure`, meaning it documents broken behavior that should be fixed. The scenario appears to stem from `builtin/receive-pack.c` checking the bare repo's HEAD state rather than the actual worktree state when making its decision. This looks like a genuine bug in a relatively obscure corner of worktree handling that could affect users with this specific configuration. The test provides a clear reproduction case for future fixes.
