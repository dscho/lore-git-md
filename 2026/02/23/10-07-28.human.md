Bugfix for a potential undefined behavior case in `git fetch`'s URL handling.

This is a small but important correction to the URL trailing-slash trimming logic in `builtin/fetch.c`. The current code could attempt to access `url[i]` when `i` is -1, which would be undefined behavior. The patch simply reorders the conditions in the for-loop to check the array bounds before accessing the element.

The fix is straightforward and clearly correct - it matches the standard pattern for safe array traversal. The commit message could be more detailed about the potential impact (though in practice this might only manifest on malformed URLs), but the change itself looks solid. This is the kind of subtle edge case that's easy to miss in code review, so it's good to catch.
