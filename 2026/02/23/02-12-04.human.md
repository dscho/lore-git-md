Performance improvement series for `git config list --type=<X>` filtering, part 11/13. This patch focuses on the color parsing subsystem, adding a gentle parsing variant that avoids printing error messages when invalid color values are encountered.

The discussion centers on naming conventions for the new parsing function. Junio C Hamano questions whether the term "gently" fits the behavior (which suppresses error messages rather than avoiding die()), while Patrick Steinhardt suggests focusing on the error message aspect. Derrick Stolee proposes using "quiet" terminology instead to better match the actual behavior, though he notes this creates some asymmetry with how the 'gently' parameter is used elsewhere in the config code.

This is a relatively minor naming discussion in an otherwise settled series - the technical approach is sound and the patch follows the established pattern from earlier in the series. The change is part of the larger performance improvement that enables type-filtering during initial config parsing rather than after full parsing.
