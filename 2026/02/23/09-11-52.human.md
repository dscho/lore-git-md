This is part 11 of Patrick Steinhardt's 17-patch series to unify Git's ref iteration interfaces. The series replaces 14 specialized ref iteration functions with a single configurable `refs_for_each_ref_ext()` interface.

This particular patch converts callers of `refs_for_each_ref_in()` to use the new unified API. The changes are mechanical - replacing direct calls with equivalent configurations of the new options struct. The patch touches several key areas including bisect, rev-parse, and pack-bitmap code paths.

Karthik Nayak raises a question about whether the `trim_prefix` parameter could be simplified to a boolean since it always matches the prefix length in current usage. This suggests potential for further API refinement, though the current implementation maintains maximum flexibility.

The changes appear straightforward with no behavior modifications, continuing the series' pattern of careful, incremental refactoring. Karthik's review suggests the patch is technically sound while identifying an opportunity for possible future simplification.
