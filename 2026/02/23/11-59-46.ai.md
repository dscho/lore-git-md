Part 12/17 of Patrick Steinhardt's ref iteration unification series, removing the specialized `refs_for_each_rawref()` function and converting all callers to use the new `refs_for_each_ref_ext()` interface. This continues the effort to consolidate Git's ref iteration APIs into a single configurable function.

The patch:
- Removes `refs_for_each_rawref()` declaration from refs.h
- Implements its removal in refs.c, where it was just a thin wrapper around `refs_for_each_rawref_in()`
- Updates all callers (describe.c, fsck.c, fetch-pack.c, files-backend.c) to use `refs_for_each_ref_ext()` with `REFS_FOR_EACH_INCLUDE_BROKEN` flag
- Maintains identical behavior while using the new unified API

Key technical points:
- Each conversion adds explicit `struct refs_for_each_ref_options` initialization
- The `INCLUDE_BROKEN` flag preserves the original behavior of including broken refs in iteration
- Callbacks remain unchanged, just routed through the new interface
- The files-backend.c change is particularly notable as it affects ref transaction validation

This is a straightforward mechanical conversion that follows the pattern established in earlier patches of the series. With this change, only `refs_for_each_replace_ref()` remains as a specialized ref iteration function outside the unified API.
