Feature patch adding a re-signing mode to `git fast-import` for invalid commit signatures. This is the second patch in a 2-part series from Justin Tobler, building on Christian Couder's earlier work on signature handling in fast-import.

The patch introduces a new `re-sign-if-invalid` mode for `--signed-commits` that will regenerate signatures for commits with invalid signatures during import, using the current user's signing key. This provides a middle ground between the existing options of either preserving invalid signatures verbatim or stripping them entirely.

Key technical changes include:
- Adds `SIGN_RESIGN_IF_INVALID` enum value to gpg-interface.h
- Modifies signature handling logic in fast-import.c to optionally re-sign when invalid signatures are detected
- Updates tests to verify the new behavior works with GPG, X.509 and SSH signatures
- Documents the new mode in git-fast-import.adoc

The implementation currently only regenerates signatures using the repository's primary hash algorithm, ignoring any `extensions.compatObjectFormat` setting that might require additional signatures. The commit message notes this as a potential area for future improvement but leaves it as-is for this initial implementation.

The patch appears well-structured with thorough test coverage. It follows the pattern established by the existing signature handling modes while adding the new functionality. The changes are focused on the fast-import/fast-export code paths and gpg-interface plumbing.
