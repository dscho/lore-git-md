This is a feature patch series for `git fast-import`, adding a new mode to handle invalid commit signatures. The series builds on previous work that allowed stripping invalid signatures during import.

The first patch is a minor cleanup removing an unused forward declaration in `commit.h`. The second and main patch introduces a `re-sign-if-invalid` mode for `--signed-commits` that will automatically re-sign commits with invalid signatures during import, rather than just stripping them.

The author notes an open question about handling `extensions.compatObjectFormat` - currently the new signatures ignore this setting, which would require reconstructing compatibility objects for the full commit chain. They're unsure whether to address this now or later, and are open to feedback on the approach.

The implementation touches the fast-import and fast-export code, gpg-interface plumbing, and includes substantial test updates. The changes look focused and well-contained, with clear commit messages explaining the rationale. This appears to be a logical extension of the existing signature handling functionality, though reviewers may want to weigh in on the compatibility format question before merging.
