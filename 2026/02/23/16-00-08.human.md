This is the third patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch refactors object streaming internals to enable direct packfile access during verification.

The change extracts a new `packfile_read_object_stream()` function from `packfile_store_read_object_stream()`, making the lower-level packfile access available to callers who already know the pack and offset. This prepares for the final fix that will prevent infinite loops during `git fsck` verification of large objects across multiple packfiles.

The refactoring maintains all existing behavior, including marking corrupt objects via `mark_bad_packed_object()`, while splitting the functionality into more reusable components. The patch touches `packfile.c` and `packfile.h`, with careful attention to error handling and type safety.

This is a well-contained preparatory change that follows the series' pattern of incremental improvements to the object streaming infrastructure. The commit message clearly explains the motivation and the relationship to the upcoming final fix. Review feedback from Jeff King has already been incorporated in this v2 submission.
