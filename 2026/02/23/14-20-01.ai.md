This is a feature patch series adding HTTP 429 rate limit retry support to Git's HTTP client. The v5 iteration from Vaidas Pilkauskas focuses on the HTTP improvements while dropping some strbuf_attach cleanup patches that were deemed unnecessary after discussion.

The main change in this version is the removal of a patch that would have enforced strbuf_attach() contract via BUG() checks, following feedback that the optimization of reusing buffer slack space is valuable. The series now only fixes strbuf_attach() calls that don't need reallocation.

The HTTP 429 support remains the core feature, allowing Git to automatically retry requests when rate-limited by servers. Key aspects include:
- Support for Retry-After headers (both delay-seconds and HTTP-date formats)
- Configurable via http.maxRetries, http.retryAfter, and http.maxRetryTime
- Fallback to manual header parsing on older curl versions
- Simplified retry architecture using blocking sleep() instead of complex timing logic
- Improved error messages and test portability

The implementation includes a new show_http_message_fatal() helper in remote-curl.c to reduce boilerplate and provide a clean hook for retry logic. The test coverage is thorough, adding new test scripts to verify the retry behavior under various conditions.

This appears to be a well-considered implementation of a useful feature for working with rate-limited Git servers. The series has gone through multiple iterations incorporating feedback from Jeff King and Taylor Blau, suggesting it has received solid technical scrutiny. The removal of the strbuf_attach BUG() enforcement patch shows responsiveness to maintainer feedback about performance tradeoffs.
