This is the final patch in a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has maintainer approval and is ready for integration.

The patch adds a `GIT_REFERENCE_BACKEND` environment variable that mirrors the functionality of the `extensions.refStorage` config introduced earlier in the series. This allows dynamically specifying the reference backend and its storage location on a per-command basis, which is particularly useful for `git-clone` and `git-init`. The environment variable takes precedence over the config setting.

Key technical aspects include:
- Proper handling of stub files in the repository's $GIT_DIR when using alternate reference storage
- Integration with repository initialization and cloning workflows
- Comprehensive test coverage verifying both config and environment variable approaches
- Preservation of the existing reference format when the environment variable is unset

The implementation builds on earlier patches that centralized stub management and added URI parsing infrastructure. This final version includes refinements from review feedback, including test optimizations and documentation improvements from Jean-Noël Avila. The series as a whole provides GitLab with the migration capabilities they need while maintaining backward compatibility.

With all substantive concerns addressed and maintainer approval secured, this concludes the reference backend selection work. The patch is well-tested and ready for merging into the 'next' branch.
