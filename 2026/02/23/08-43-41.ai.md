Bugfix for `git fsck` packfile verification with deeper architectural implications. Patrick Steinhardt responds to brian m. carlson's patch addressing an infinite loop in packfile verification, agreeing with the immediate fix but uncovering additional complexity in the underlying issue.

The immediate problem occurs when `git fsck` verifies multiple packfiles - accessing large objects (exceeding core.bigFileThreshold) during verification updates the MRU list mid-iteration, causing an infinite loop. brian m. carlson's solution adds a `skip_mru_updates` flag to stabilize iteration.

Patrick identifies two deeper concerns: First, the test case placement in t1050-large.sh is non-obvious because the issue only manifests with both multiple packs and large objects. Second, and more significantly, the current design may verify objects from wrong packs when duplicates exist, since large objects bypass the direct offset-based verification path.

The response suggests Patrick has follow-up patches coming that will address these architectural issues more fundamentally, part of his ongoing work to eventually eliminate `repo_for_each_pack()`. He notes a minor edge case with the current patch where early loop termination could leave the MRU flag set, suggesting a callback-based approach might be cleaner.

This exchange highlights how a simple bugfix touches on core object storage design questions that Patrick is actively working to resolve through the ODB abstraction effort. The thread now contains both an immediate solution and seeds for more substantial future changes to pack verification.
