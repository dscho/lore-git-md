This is part of the ongoing ref backend abstraction effort, specifically patch 4/6 in the v8 series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has maintainer approval from Junio Hamano and is ready for integration.

The patch introduces payload handling for reference backends, allowing alternate storage locations to be specified via future URI-based configuration. It adds a new `refs_compute_filesystem_location()` helper that parses gitdir and payload to determine reference storage locations, handling both main and worktree cases. The change is currently a no-op since no callers pass payloads yet, but lays groundwork for upcoming URI support in `extensions.refStorage` config.

Key technical changes:
- Modifies backend `init()` functions to accept a payload parameter
- Adds path resolution logic for worktree and common reference directories
- Preserves special handling for files backend while making the infrastructure backend-agnostic
- Includes optimizations from reviewers like path safety checks and strbuf handling

The patch has undergone extensive review with feedback incorporated from Patrick Steinhardt, Derrick Stolee, Toon Claes and others. It represents a well-vetted piece of the larger backend selection architecture that's now ready for merging.
