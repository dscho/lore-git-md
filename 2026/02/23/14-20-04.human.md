This is part of Vaidas Pilkauskas's v5 series adding HTTP 429 rate limit retry support to Git's HTTP client. The patch introduces a new helper function `show_http_message_fatal()` in remote-curl.c that combines the common pattern of showing an error message from the server and then terminating with `die()`. 

The change is a refactoring that reduces code duplication by consolidating five similar error-handling patterns into a single helper. The new function handles displaying the server's error message (if it's text/plain) and then terminates with a formatted error, while properly cleaning up allocated resources. This prepares the codebase for upcoming HTTP 429 rate limiting support by establishing a consistent error reporting pattern.

The patch has already incorporated feedback from Taylor Blau (who suggested the helper approach) and Jeff King through previous iterations. The changes are mechanical but improve maintainability, and the patch includes thorough updates to all relevant call sites in remote-curl.c. This is part of a well-structured series that has been through multiple rounds of review.
