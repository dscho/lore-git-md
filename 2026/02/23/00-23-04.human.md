Post-merge follow-up discussion on `.git` directory validation error handling. Junio Hamano proposes treating `ENOTDIR` (path component not a directory) the same as `ENOENT` (file not found) when checking submodule `.git` files, since both indicate the path doesn't exist as a valid Git directory. He provides a patch that groups these error codes under a new `READ_GITFILE_ERR_STAT_MISSING` constant, but notes uncertainty about whether this change should apply globally or just for submodule cases.

The discussion continues from a recently merged 10-patch series by Tian Yuchen that improved error classification for `.git` file/directory detection. This follow-up examines an edge case where a submodule directory is replaced with a regular file, which currently returns `ENOTDIR` rather than the expected `ENOENT`. Junio's patch demonstrates the proposed change but leaves it as a separate patch for further discussion rather than squashing it, recognizing that other code paths might need to distinguish between these error conditions.
