This is the final patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch fixes an infinite loop in `git fsck` that could occur when verifying large objects that exist in multiple packfiles, originally reported by brian m. carlson.

The core issue stems from how `odb_read_object_stream()` would perform a full object lookup (potentially updating the MRU list of packfiles) when verifying large objects, which could create an infinite loop when the same object exists in multiple packs. The fix replaces this with direct packfile access via `packfile_read_object_stream()`, ensuring we verify the specific object in the pack we're checking rather than any available instance.

The patch includes a thorough test case that:
1. Creates two packfiles with overlapping large objects
2. Deliberately corrupts different objects in each pack
3. Verifies `git fsck` correctly identifies both corruptions without getting stuck in a loop

This completes the series' technical work after incorporating feedback from Jeff King and Eric Sunshine. The changes have been through multiple iterations (v2 here) with all reviewer concerns addressed. The solution is now demonstrates robust handling of large objects across multiple packfiles while maintaining clear error reporting about which specific pack contains corruption.
