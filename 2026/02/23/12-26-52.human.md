Performance improvement series for `git config list --type` filtering (patch 10/13)

This patch adds a `color_parse_quietly()` function to Git's color parsing infrastructure, continuing Derrick Stolee's series to improve type-specific filtering in `git config list`. The new function allows color values to be parsed without emitting error messages when invalid, matching the pattern established in earlier patches for other config types.

The change refactors the existing color parsing code to extract a common implementation (`color_parse_mem_1()`) that takes a `quiet` parameter, then provides both the original `color_parse()` and new `color_parse_quietly()` as thin wrappers. This maintains the existing behavior while adding the quiet mode needed for efficient config filtering.

The patch follows the same approach used for other config types in the series (integers, booleans, paths, etc.), where invalid values are silently skipped during filtering rather than producing errors. The implementation is straightforward and maintains the existing color parsing logic while just adding the quiet mode option.

This is part of a well-structured series that has already addressed all substantive feedback in previous iterations. The change is focused and follows the established pattern from earlier patches, making it a low-risk addition to the overall performance improvement effort.
