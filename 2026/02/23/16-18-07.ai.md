This is part 16/17 of Patrick Steinhardt's ongoing refactoring series to make Git's object database (ODB) subsystem pluggable. The patch converts the `write_alternate()` functionality to use the callback pattern established in previous patches, continuing the systematic conversion of ODB operations to be backend-agnostic.

The change moves the files-backend implementation of alternate writing from `odb.c` to `source-files.c` and introduces a new callback in `struct odb_source`. The implementation maintains the existing behavior of atomically updating the alternates file while avoiding duplicates. The callback contract specifies that new alternates should be appended while preserving existing ones, matching Git's current semantics.

This follows the same proven pattern seen in earlier patches of the series: defining type-safe interfaces, converting operations one by one, documenting behavioral contracts, and preserving existing files backend functionality. The patch is mechanically similar to the `read_alternates()` conversion done in patch 15/17, showing the consistent methodology being applied across the ODB interface.

The work continues incrementally toward the architectural goal of fully pluggable ODB backends while maintaining backward compatibility. With this change, both reading and writing alternates are now callback-based, leaving any remaining ODB operations to be converted in future work.
