This is a feature patch in the "enhanced repository path reporting" series, adding a `--path-format` option to control absolute vs relative path output in `git repo info`.

The patch introduces path formatting control to the repository information command, allowing callers to explicitly request either absolute or relative paths for all path-related output. This matches existing conventions from `git rev-parse` and centralizes path conversion logic in the `repo_info_add_path()` helper function. The implementation adds a new `path_format` enum to the `repo_info` context structure and handles relative path conversion using Git's existing `relative_path()` utility when requested.

Key technical details:
- New `--path-format=(absolute|relative)` option added to command interface
- Path formatting state stored in `repo_info` context structure
- Relative path conversion uses `relative_path()` with proper memory management
- Maintains consistency with `rev-parse` behavior patterns
- Follows the series' pattern of avoiding global state

The change is well-contained and builds logically on the previous patches in the series. The implementation looks clean, with proper error handling for invalid format values and memory management for the temporary working directory string.
