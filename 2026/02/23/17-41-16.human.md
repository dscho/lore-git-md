Refactoring patch in Justin Tobler's repository statistics series (1/5). This patch restructures how object statistics are collected in `builtin/repo.c`, moving from batch processing of object arrays to per-object updates. The change prepares for more granular statistics tracking while maintaining the same functionality - it still counts objects by type (tags, commits, trees, blobs) and tracks their inflated and on-disk sizes.

The key change moves the statistics update logic inside the object iteration loop, processing each object individually rather than accumulating totals first. This is a mechanical refactoring with no behavior change, but it enables future patches in the series to more easily track per-object metrics like largest objects by type. The patch follows Git's style guidelines and includes a clear commit message explaining the motivation.
