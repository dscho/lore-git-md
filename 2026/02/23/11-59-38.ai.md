This is part 4/17 of Patrick Steinhardt's ref iteration API unification series, which has Karthik Nayak's overall approval and is in final polishing stages. The patch performs a mechanical rename of the `do_for_each_ref_flags` enum to `refs_for_each_flag` to better match Git's naming conventions, updating all related flag names (e.g. `DO_FOR_EACH_INCLUDE_BROKEN` becomes `REFS_FOR_EACH_INCLUDE_BROKEN`).

The change affects six files across the codebase, primarily in the refs subsystem, updating both the enum declaration and all its uses. The flags control various aspects of ref iteration behavior including broken ref handling, worktree ref filtering, and root ref inclusion. This is a straightforward naming improvement that doesn't modify functionality but helps standardize the API surface being unified in this series.

The patch follows the series' pattern of incremental, focused changes - here addressing a naming consistency issue identified during review. All callers are updated in lockstep, and the diff shows the mechanical nature of the change. This continues the broader effort to consolidate Git's ref iteration interfaces into a single configurable API while maintaining identical behavior.
