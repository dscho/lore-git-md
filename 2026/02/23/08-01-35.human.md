This is the final version (v8) of a feature series enabling flexible reference storage backend selection, primarily to support zero-downtime migrations between backends like files and reftable. The series has undergone extensive review and refinement over 8 iterations, with maintainer approval from Junio Hamano now secured.

The key addition is support for specifying reference storage locations via three mechanisms:
1. The `extensions.refStorage` config can now take either a simple format name (e.g. "reftable") or a URI format (`<format>://<payload>`)
2. A new `GIT_REFERENCE_BACKEND` environment variable that can override the config
3. Support for worktree references in alternate locations

The primary use case comes from GitLab's need to migrate large repositories between backends with minimal downtime. The implementation allows writing references to an arbitrary location during a dry-run phase before atomically swapping to the new backend. The series includes comprehensive test coverage in t1423-ref-backend.sh and has addressed all feedback from reviewers including Junio Hamano, Patrick Steinhardt, and Karthik Nayak.

Changes in v8 are minor final tweaks - fixing a documentation typo, optimizing test file comparisons, and small cleanups. The series is now ready for integration with all technical and stylistic concerns resolved.
