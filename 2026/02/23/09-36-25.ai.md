This is a technical discussion about the ongoing `git fsck` packfile verification issues, specifically addressing the root causes of the MRU (Most Recently Used) list iteration problems. Patrick Steinhardt is responding to Jeff King's concerns about the fundamental fragility of the MRU list design.

Patrick acknowledges that while the immediate issue (infinite loop during iteration) was fixed with the `skip_mru_updates` flag, the deeper architectural problem remains - any iteration that calls `find_pack_entry()` risks modifying the MRU list being traversed. He suggests two potential solutions: either maintain a separate list for iteration (reverting to the pre-MRU design) or extend `repo_for_each_pack()` to handle MRU updates safely.

The discussion reveals Patrick's longer-term vision to eliminate `repo_for_each_pack()` entirely as part of the object database (ODB) abstraction work, which would naturally contain the MRU iteration risks within backend implementations. This aligns with his broader efforts to refactor Git's object storage layer. The exchange highlights the tension between immediate fixes and architectural improvements, with both Patrick and Jeff recognizing the need for more robust iteration semantics while differing slightly on the best path forward.
