This is a refactoring patch in the ongoing ref backend abstraction effort, specifically part of the v8 series enabling zero-downtime migrations between reference storage backends (files<->reftable). The patch has already received maintainer approval from Junio Hamano.

The change extracts duplicate stub-creation logic from two locations (clone.c and reftable-backend.c) into a new shared function `refs_create_refdir_stubs()`. These stubs (HEAD file and refs/ directory) are required for Git to recognize a directory as a repository, even when using alternate backends like reftable that store references differently. The new function also adds flexibility by allowing customization of the refs/heads content message.

The patch is well-contained and clearly motivated, with clean separation of concerns. It's part of a mature series that has undergone extensive review, with this particular change being a straightforward code organization improvement rather than introducing new functionality. The implementation preserves all existing behavior while reducing duplication, and includes appropriate documentation for the new API.
