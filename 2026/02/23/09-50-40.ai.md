Test infrastructure improvement from Patrick Steinhardt, part of a series fixing pack validation issues with large objects. This first patch enhances the `test-tool genrandom` helper to better handle size specifications and error cases.

The helper now uses `git_parse_ulong()` to:
- Properly validate numeric inputs (rejecting malformed strings like "200xyz")
- Support human-readable size suffixes (k/m/g for kilo/mega/gigabytes)

The change updates several test scripts to use the new suffix support, replacing hardcoded byte counts with more readable values (e.g. "1048576" becomes "1m"). Affected tests span multiple areas including pack handling, fsck verification, and promisor remotes.

This is a straightforward quality-of-life improvement for test writers that doesn't change any core functionality. The patch is well-contained, touching only test code, and includes updates to maintain consistency across the test suite. As the first in a series addressing pack validation issues, it establishes better test infrastructure before the subsequent bugfixes.
