This is patch 5/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series addresses inefficiencies in config value filtering, originally motivated by git-credential-manager's performance issues with path-type config values.

This specific patch moves boolean value formatting into a dedicated `format_config_bool()` helper function and implements gentle parsing for boolean values when needed. The key change makes `git config list --type=bool` quietly filter out non-boolean values rather than failing, matching the behavior pattern established for other types in earlier patches. The implementation follows the same gentle/strict parsing duality seen in the integer handling from patch 4/13, using `git_parse_maybe_bool()` for gentle parsing while maintaining the existing `git_config_bool()` behavior for strict cases.

The patch includes a test update to verify the new behavior - where previously the command would fail on non-boolean values, it now silently filters them out while correctly listing valid boolean values. This maintains consistency with the series' goal of efficient type filtering during initial parsing rather than post-processing.

As with the rest of the series, the implementation appears clean and well-tested, with Junio C Hamano and Patrick Steinhardt having already approved the technical approach in earlier reviews.
