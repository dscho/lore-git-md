This is the 8th patch in Patrick Steinhardt's 17-part series refactoring Git's object database (ODB) subsystem to support pluggable backends. The series is systematically converting direct function calls into callback-based operations.

This patch makes the `close()` operation pluggable by:
1. Adding a `close` callback to `struct odb_source` with clear documentation about its contract (must leave source usable but may require reopening)
2. Moving the files backend's close logic into a new `odb_source_files_close()` function
3. Replacing direct `packfile_store_close()` calls in `odb_close()` with the new callback mechanism
4. Registering the files backend's close function during initialization alongside existing callbacks

The change follows the established pattern seen in earlier patches (6/17 for `free`, 7/17 for `reprepare`), continuing the incremental conversion of ODB operations to the callback model. The files backend implementation remains behaviorally identical - this is purely an architectural change to enable future alternative backends.

The patch in this series is focused and well-contained, touching only the necessary files while maintaining the overall goal of making object storage pluggable. The commit message could be slightly more detailed about why this particular operation needs to be pluggable, but the technical content is solid and follows the project's standards for incremental refactoring.
