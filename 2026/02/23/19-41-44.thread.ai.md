Thread identity: Feature patch series for `git fast-import` adding a `re-sign-if-invalid` mode to handle invalid commit signatures during import, originally authored by Christian Couder, with second patch contributed by Justin Tobler. Builds on prior work allowing signature stripping during import.

Core problem: Currently `git fast-import --signed-commits` can either preserve or strip invalid signatures. This series adds a third option to re-sign commits with invalid signatures during import using the user's current signing key.

Current status: Two-patch series with v1 from Christian Couder (cleanup) and v1 from Justin Tobler (feature implementation). The implementation:
- Adds `SIGN_RESIGN_IF_INVALID` enum to gpg-interface.h
- Modifies fast-import.c signature handling
- Supports GPG/X.509/SSH signatures in tests
- Documents new mode in git-fast-import.adoc

Key technical details:
- New mode added to `--signed-commits` option
- Touches fast-import/fast-export code and gpg-interface plumbing
- Test coverage verifies behavior with multiple signature types
- Signatures regenerated using current user's key
- Does not yet handle `extensions.compatObjectFormat` for signature regeneration
- Cleanup patch removes obsolete `sign_with_header()` declaration from commit.h

Open questions:
- Whether to respect `extensions.compatObjectFormat` when regenerating signatures (currently ignored)
- Potential need to reconstruct compatibility objects for full commit chain

Participant positions:
- Christian Couder: Original author of cleanup patch and maintainer of fast-import/fast-export
- Justin Tobler: Implemented core feature in second patch with thorough test coverage

Related work: Builds on previous signature handling work in fast-import, particularly commit 6206089bd which removed the now-declared-obsolete `sign_with_header()` function.
