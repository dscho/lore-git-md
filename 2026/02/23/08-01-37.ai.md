This is a refactoring patch in the final v8 series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch has maintainer approval and is ready for integration.

The change extracts duplicate stub creation logic from `builtin/clone.c` and `refs/reftable-backend.c` into a new `refs_create_refdir_stubs()` function in the generic refs layer. This function creates the minimal directory structure (HEAD file and refs/ directory) that Git requires to recognize a directory as a repository, which is needed even for backends like reftable that store references differently. The function also optionally creates a heads file with a custom message (used by reftable to indicate its format).

The patch is part of a larger effort to support multiple ref storage backends, primarily serving GitLab's migration needs. It follows previous discussion and review feedback, with the implementation now centralized in the refs layer while preserving files backend special handling. The change is mechanical and well-contained, touching only the expected files with straightforward modifications.
