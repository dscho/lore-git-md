This is a discussion about interface design for the `git replay` command's revert functionality, which is part of an ongoing feature addition primarily for GitLab's Gitaly service. The thread has shifted from technical implementation details to command structure philosophy.

Christian Couder responds to Toon Claes' suggestion of using subcommands (`revert`, `pick`, `replay`) instead of flags (`--revert`, `--advance`, `--onto`). Christian agrees with the subcommand approach in principle but suggests deferring the change until after the current `--revert` implementation is merged, allowing for more real-world usage experience. He also questions whether the `--base=<branch>` parameter (proposed by Toon) is necessary if the base branch will nearly always be required, proposing instead direct positional arguments.

The discussion reveals two competing interface design philosophies:
1. The current flag-based approach that groups related operations under a single command
2. A proposed subcommand model that would make the distinct operations more explicit

Christian's response indicates openness to change but cautions against disrupting the already-stabilized technical implementation in the current series. The exchange highlights how interface design can become a late-stage consideration even after technical approach has been vetted through multiple iterations (this is v3 of the patch series). The thread shows the project's careful balancing of immediate needs (GitLab's use case) with long-term command usability.
