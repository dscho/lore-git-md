This is patch 7/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series addresses inefficiencies in config value filtering, originally motivated by git-credential-manager's performance issues with path-type config values.

This particular patch moves the logic for formatting bool-or-string config values into a dedicated helper function, `format_config_bool_or_str()`. The change is purely structural - it doesn't modify behavior since this case was already handling parsing gently. The refactoring matches the pattern established in earlier patches for other config types (bool, int, bool-or-int) where type-specific formatting is extracted into separate functions.

The patch is straightforward and follows the established approach of the series. It's part of the broader effort to make config value filtering more efficient by handling type-specific formatting during initial parsing rather than after. The change is well-contained and maintains consistency with the rest of the series' architecture.
