Bugfix series from Patrick Steinhardt addressing pack validation issues with large objects, originally reported by brian m. carlson. The four-patch series begins with test infrastructure improvements and preparatory refactoring before delivering the core fix for an infinite loop in `git fsck` when verifying large objects across multiple packfiles.

Key technical details:
- Test infrastructure enhanced with size suffixes (k/m/g) in `test-tool genrandom` and input validation via `git_parse_ulong()`, with error handling corrected per Jeff King's review to properly check boolean return value rather than negative error codes (Patrick has acknowledged this specific feedback and will fix in v2)
- Refactored `stream_object_signature()` to accept preconstructed `odb_read_stream`, shifting stream lifecycle control to callers (Jeff King reviewed this change, noting the approach is sound but suggesting minor improvements to error messages and redundant checks; Patrick agrees to incorporate repository parameter clarification and more precise error handling in v2 while noting hash algorithm tracking limitations in current ODB stream interface)
- Extracted new `packfile_read_object_stream()` from `packfile_store_read_object_stream()` for direct packfile access (Jeff King confirmed the core refactoring is sound but noted: 1) removal of redundant delta checks is acceptable, 2) potential pre-existing issue with bad object marking in streaming path)
- Final fix replaces `odb_read_object_stream()` with direct packfile access in `pack-check.c`, preventing MRU-triggered infinite loops (Jeff King approves as "delightfully simple" but suggests improving test case specificity)
- Patrick now adds explicit handling for `OBJ_BAD` cases in `packfile_read_object_stream()` by:
  - Adding `oid` parameter to identify objects that fail header parsing
  - Calling `mark_bad_packed_object()` when `unpack_object_header()` returns `OBJ_BAD`
  - Updating call site in `packfile_store_read_object_stream()` to pass through the OID
- Current test in `t1450-fsck.sh` verifies basic functionality with 200KB blobs across multiple packs but needs enhancement to:
  - Explicitly verify corruption detection when same object exists in multiple packs (one corrupt, one valid)
  - Demonstrate fsck correctly identifies which specific pack contains corruption
  - Avoid nondeterministic results based on MRU pack ordering
- Patrick acknowledges test coverage gap and plans to investigate solutions for reliably creating corrupted objects with hash mismatches in version 2
- Changes span `pack-check.c`, `packfile.c`, `object.c` with test coverage in `t1450-fsck.sh` and `t1050-large.sh`
- Fixes regression from c31bad4f7d (packfile MRU list changes)

Jeff King has reviewed all patches in the series, confirming the technical soundness of each change while providing focused feedback on test coverage and error handling. The core fix is complete and addresses the original infinite loop issue reported by brian m. carlson, with only test improvements remaining before finalization. Patrick Steinhardt has now additionally addressed the pre-existing issue with marking corrupted objects during streaming reads, demonstrating attention to edge cases beyond the primary bug report. The discussion around `stream_object_signature()` revealed deeper considerations about the ODB stream interface's limitations regarding hash algorithm tracking, though these are noted as out of scope for the current bugfix series. All reviewer feedback has been addressed or acknowledged, with the series awaiting test case enhancements before version 2 submission.
