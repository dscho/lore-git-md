Bugfix series from Patrick Steinhardt addressing pack validation issues with large objects, originally reported by brian m. carlson. The four-patch series improves test infrastructure, refactors object streaming internals, and fixes an infinite loop in `git fsck` when verifying large objects across multiple packfiles.

Key technical details:
- Test infrastructure enhanced with size suffixes (k/m/g) in `test-tool genrandom` and input validation via `git_parse_ulong()`, with error handling corrected per Jeff King's review (Eric Sunshine's typo fix for "argumemnt" -> "argument" incorporated in v2)
- Refactored `stream_object_signature()` to accept preconstructed `odb_read_stream`, with improved error reporting in `parse_object_with_flags()` to distinguish between stream opening failures and hash mismatches
- Extracted new `packfile_read_object_stream()` from `packfile_store_read_object_stream()` for direct packfile access, maintaining object corruption marking behavior
- Final fix replaces `odb_read_object_stream()` with direct packfile access in `pack-check.c`, preventing MRU-triggered infinite loops during verification
- Test coverage in `t1450-fsck.sh` now explicitly verifies corruption detection when same object exists in multiple packs (one corrupt, one valid) and demonstrates fsck correctly identifies which specific pack contains corruption
- Changes span `pack-check.c`, `packfile.c`, `object.c` with test coverage in `t1450-fsck.sh` and `t1050-large.sh`
- Fixes regression from c31bad4f7d (packfile MRU list changes)

Reviewer feedback incorporated:
