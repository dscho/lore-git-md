Bugfix series from Patrick Steintardt addressing pack validation issues with large objects, originally reported by brian m. carlson. The four-patch series begins with test infrastructure improvements and preparatory refactoring before delivering the core fix for an infinite loop in `git fsck` when verifying large objects across multiple packfiles.

Key technical details:
- Test infrastructure enhanced with size suffixes (k/m/g) in `test-tool genrandom` and input validation via `git_parse_ulong()`
- Refactored `stream_object_signature()` to accept preconstructed `odb_read_stream`, shifting stream lifecycle control to callers (Jeff King reviewed this change, noting the approach is sound but suggesting minor improvements to error messages and redundant checks)
- Extracted new `packfile_read_object_stream()` from `packfile_store_read_object_stream()` for direct packfile access
- Final fix replaces `odb_read_object_stream()` with direct packfile access in `pack-check.c`, preventing MRU-triggered infinite loops
- New test in `t1450-fsck.sh` verifies fix with 200KB blobs across multiple packs
- Changes span `pack-check.c`, `packfile.c`, `object.c` with test coverage in `t1450-fsck.sh` and `t1050-large.sh`
- Fixes regression from c31bad4f7d (packfile MRU list changes)

The series follows Patrick Steintardt's characteristic approach of careful structural refactoring (first three patches) before implementing the core fix, with Jeff King providing review feedback on the interface changes in patch 2. The final patch resolves both the infinite loop and ensures precise verification by checking the exact packed object rather than potentially verifying a different instance. Original failure case described as "broken" in commit messages is now fully resolved.
