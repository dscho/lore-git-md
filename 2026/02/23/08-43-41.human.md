This is a follow-up discussion on a bugfix for `git fsck`'s verification that uncovered deeper architectural issues with packfile MRU list handling. Patrick Steinhardt confirms brian m. carlson's fix for the immediate infinite loop issue (caused by MRU updates during iteration) but identifies additional complexity: the problem only manifests when verifying large files (exceeding core.bigFileThreshold) across multiple packs, as this triggers object lookups that update the MRU list.

Patrick notes the current fix (adding skip_mru_updates flag) is a good stopgap but highlights two broader concerns: 1) the verification might miss duplicate objects in different packs when falling back to object-ID lookups, and 2) the flag-based solution is fragile if iteration breaks early. He mentions having patches in progress to address these deeper issues with the verification logic.

The discussion reveals this isn't just about fsck - it touches core packfile iteration semantics that affect multiple subsystems. Patrick indicates plans to eventually replace repo_for_each_pack() entirely, suggesting this may be part of his ongoing ODB abstraction work. The thread shows how a simple bugfix can uncover significant design questions about Git's object storage internals.
