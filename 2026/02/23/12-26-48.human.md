This is the sixth patch in Derrick Stolee's 13-part series improving `git config list --type=<X>` filtering performance. The series addresses inefficiencies in config value parsing by implementing type-specific handling during initial parsing rather than filtering after full parsing.

Patch 6/13 focuses on boolean-or-integer type handling, extracting the logic into a new `format_config_bool_or_int()` helper function. The key changes are:

1. Introduces gentle parsing for bool-or-int values when requested (using `git_parse_maybe_bool_text()` and `git_parse_int()`)
2. Maintains existing strict parsing behavior when gentle mode is off (using `git_config_bool_or_int()`)
3. Updates the test to verify successful output rather than expecting failure

The patch follows the established pattern from earlier patches in the series, applying the same gentle/strict parsing duality seen in the config subsystem. It's a clean refactoring that improves performance while maintaining backward compatibility. The test change confirms the new implementation correctly handles valid bool-or-int values where the previous version would incorrectly fail.

This continues the series' steady progress toward more efficient config parsing, with all substantive design questions already resolved in earlier iterations. The implementation looks solid and well-tested.
