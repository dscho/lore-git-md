This thread explored whether to formally recognize several special date keywords in Git's documentation for `git commit --date`, including "now", "yesterday", "noon", and others. While these keywords have worked in Git's date parser for years, they were never officially documented. The patch author, Md Ferdous Alam, initially proposed adding them to the manual pages, seeing them as useful features.

Maintainer Junio C Hamano pushed back, explaining these were intentionally left undocumented as "easter eggs" rather than supported features. He noted that only "now" has clear practical value for commits, while others like "tea" (5pm) or "never" (maximum timestamp) are more curiosities than tools. Junio also pointed out the inconsistency of documenting some informal features while leaving out others like "7.days.ago".

After considering this feedback, the author withdrew the patch, accepting that these keywords are better left as undocumented conveniences. The discussion revealed Git's preference for keeping a clear line between supported functionality and implementation quirks, even longstanding ones. This maintains documentation clarity while preserving some playful elements in the codebase.
