This thread discusses whether to officially document special date keywords like "now", "yesterday", and "tea" (5pm) that Git's date parser has long supported but never formally documented. The initial patch from Md Ferdous Alam proposes adding these to the DATE FORMATS section of the documentation, noting they're already functional in Git's date parsing code.

Junio Hamano, Git's maintainer, has expressed reservations about documenting these keywords. He suggests they may have been intentionally left as undocumented "easter eggs" rather than formally supported features. While acknowledging "now" is genuinely useful for commits, he questions the value of documenting the others, pointing out other undocumented relative formats like "7.days.ago" that aren't included in this proposal. His response indicates he's not outright rejecting the idea but is skeptical about whether formal documentation would actually help users.

The discussion highlights Git's occasional informal approach to features - some functionality exists in the code but isn't officially blessed with documentation. The thread remains open, with the original author yet to respond to Junio's concerns about whether elevating these keywords to documented status is the right approach.
