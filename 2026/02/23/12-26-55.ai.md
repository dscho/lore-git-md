This is the final patch in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The patch converts the config type handling from macro-defined constants to a proper enum, improving type safety and maintainability.

The change moves the enum definition earlier in the file to ensure it's available where needed, and explicitly initializes the type field to TYPE_NONE in the config_display_options struct (though zero initialization would have the same effect). This helps validate that the switch statement added in the previous patch properly handles all possible enum values.

The patch is a straightforward mechanical conversion that:
1. Replaces numeric macros with an enum
2. Maintains the same values (TYPE_NONE=0 through TYPE_BOOL_OR_STR=7)
3. Preserves all existing behavior while making the code more self-documenting

This completes the 13-patch series that originally aimed to improve performance for git-credential-manager by enabling type filtering during config parsing rather than after. The series has received maintainer approval and addresses all feedback from earlier versions.
