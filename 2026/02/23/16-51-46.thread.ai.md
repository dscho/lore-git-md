This thread addresses a bug causing zombie processes when Git runs as PID 1 in containers during abnormal exits from network operations (git-remote-https, ssh). The core issue occurs when transport errors trigger exit(128) before normal cleanup paths (disconnect_helper, finish_connect) can reap child processes, leaving them as zombies when Git is PID 1.

The proposed solution adds atexit handlers in transport-helper.c and connect.c to ensure child process reaping regardless of exit path, while preserving existing cleanup behavior for normal exits. The changes are focused and well-explained, with clear comments linking the new handlers to the container-specific issue. The patch touches two key files (connect.c and transport-helper.c) with symmetric changes to handle both transport helper and direct connection cases.
