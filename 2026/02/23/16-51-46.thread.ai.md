Thread addressing zombie process cleanup in containerized Git operations, specifically for orphaned network helper processes (git-remote-https, ssh) during abnormal exits. Andrew Au's patch series (v4) implements proper cleanup via Git's `run-command` infrastructure by setting `clean_on_exit` and `wait_after_clean` flags in `connect.c` (proxy connections) and `transport-helper.c`. The solution uses SIGTERM-then-wait to avoid both zombie processes and deadlocks, addressing observed cases of 6,500+ zombies while maintaining narrow scope for network operation exits.

Junio C Hamano has queued the v4 patch for merging after it received final technical approval from Jeff King and addressed all concerns. The patch solves the specific problem of network helper processes becoming zombies when Git exits abnormally in containers, leveraging existing `run-command` infrastructure with a minimal 6-line change across three spawn points in the transport layer. The solution builds on prior work (commit afe19ff7b5) and avoids potential deadlocks through careful kill-then-wait sequencing.
