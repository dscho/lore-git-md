Thread addressing zombie process cleanup in containerized Git operations, with focus on abnormal exits from network operations (git-remote-https, ssh). The original problem statement described Git running as PID 1 in containers, but follow-up discussion reveals the actual deployment involves a long-running service (not Git) as PID 1 spawning Git processes. Andrew Au's v2 patch adds symmetric atexit handlers in transport-helper.c and connect.c (using conn_to_reap and helper_to_reap tracking variables) to ensure child process reaping regardless of exit path, while preserving normal cleanup behavior.

Jeff King (Peff) raised technical concerns about potential deadlock if atexit handlers wait for children that might themselves be waiting on the parent, suggesting kill-then-wait via the existing `clean_on_exit` flag in `child_process`. He also questioned whether child cleanup should be default behavior in run-command infrastructure (referencing commit afe19ff7b5). Junio C Hamano now seeks clarification on the deployment context - whether Git is truly PID 1 or a child process, and whether the service spawning Git should handle cleanup instead.
