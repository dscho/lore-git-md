Thread addressing zombie process issue when Git runs as PID 1 in containers during abnormal exits from network operations (git-remote-https, ssh). The core problem occurs when transport errors trigger exit(128) before normal cleanup paths (disconnect_helper, finish_connect) can reap child processes, leaving them as zombies when Git is PID 1.

Andrew Au's v2 patch adds symmetric atexit handlers in transport-helper.c and connect.c to ensure child process reaping regardless of exit path, while preserving existing cleanup behavior for normal exits. The solution introduces:
- connect.c: conn_to_reap tracking variable and cleanup_conn_on_exit handler
- transport-helper.c: helper_to_reap and cleanup_helper_on_exit handler
Handlers are registered when child processes start (git_proxy_connect, git_connect, get_helper) and cleared during normal cleanup paths to avoid double-waiting.
