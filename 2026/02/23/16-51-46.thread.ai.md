Thread addressing zombie process issue when Git runs as PID 1 in containers during abnormal exits from network operations (git-remote-https, ssh). The core problem occurs when transport errors trigger exit(128) before normal cleanup paths (disconnect_helper, finish_connect) can reap child processes, leaving them as zombies when Git is PID 1.

Andrew Au's v2 adds symmetric atexit handlers in transport-helper.c and connect.c to ensure child process reaping regardless of exit path, while preserving normal cleanup behavior. The solution introduces conn_to_reap and helper_to_reap tracking variables with corresponding cleanup_on_exit handlers, registered when child processes start (git_proxy_connect, git_connect, get_helper) and cleared during normal cleanup to avoid double-waiting. Jeff King (Peff) raises concerns about potential deadlock if the atexit handler waits for children that might themselves be waiting on the parent, suggesting instead using the existing `clean_on_exit` flag in `child_process` to kill-then-wait. He also questions whether child cleanup should be the default behavior in Git's run-command infrastructure, referencing commit afe19ff7b5 where optional cleanup was introduced.

The thread has established real-world impact through Andrew's deployment scenario showing zombie accumulation in containerized services monitoring repositories (over 6,500 zombies observed). The technical discussion now focuses on implementation safety, with Peff's review suggesting:
1. Replace direct wait with kill-then-wait to prevent deadlock
2. Consider making child cleanup default behavior in run-command
3. Preserve the existing ability to opt-out of cleanup where needed

Open questions include:
- Whether to modify the patch to use kill-then-wait as Peff suggests
- If the run-command infrastructure should be addressed separately
- Testability of the abnormal exit scenario remains challenging

The solution continues to target container deployment pain points while maintaining behavior for non-container cases, with implementation details now under review for potential deadlock risks.
