This is patch 11/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces. The patch removes the specialized `refs_for_each_ref_in()` function, replacing all its callers with the new unified `refs_for_each_ref_ext()` API. The conversion is straightforward - each call site is updated to pass the same prefix via the new options struct, with the prefix length explicitly specified for trimming.

The changes touch several key areas: bisect.c (bisect ref handling), rev-parse.c (ref listing), pack-bitmap.c (preferred tips iteration), and the refs subsystem itself (tag/branch/remote ref iteration). The patch also removes the now-unused function declaration from refs.h and updates the test helper to use the new API.

This continues the series' pattern of methodically replacing specialized ref iteration functions with the unified interface while maintaining identical behavior. The changes are mechanical but important for reducing API surface area and consolidating functionality. Karthik Nayak has already reviewed and approved the overall approach in earlier iterations.
