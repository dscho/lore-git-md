This is a refactoring patch that's part of a larger series (v8 1/6) implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series has maintainer approval and is ready for integration.

The patch cleans up `create_reference_database()` to remove an unnecessary side effect where it was modifying the repository's ref storage format. The function is only used in two places (git-init and git-clone), and in both cases the format is already handled elsewhere, making this redundant. The change prevents potential issues if future versions of `repo_set_ref_storage_format()` handle dynamically allocated strings.

The modification is straightforward - it removes the format parameter and associated call to `repo_set_ref_storage_format()`, updating the two call sites accordingly. This is a mechanical change that improves code clarity without affecting functionality, as part of the broader ref backend selection work that's been thoroughly reviewed across 8 iterations.
