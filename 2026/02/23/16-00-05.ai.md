This is a bugfix series from Patrick Steinhardt addressing pack validation issues with large objects, building on feedback from Jeff King and Eric Sunshine. The four-patch series improves test infrastructure, refactors object streaming internals, and fixes an infinite loop in `git fsck` when verifying large objects across multiple packfiles.

The first patch enhances the test helper `test-tool genrandom` to support size suffixes (k/m/g) and improves error handling via `git_parse_ulong()`, incorporating Eric Sunshine's typo fix in the commit message. The second patch modifies `stream_object_signature()` to accept a preconstructed stream, with improved error reporting in `parse_object_with_flags()` to distinguish between stream opening failures and hash mismatches.

The third patch extracts `packfile_read_object_stream()` from `packfile_store_read_object_stream()` for direct packfile access, maintaining object corruption marking behavior. The final patch fixes the core issue by replacing `odb_read_object_stream()` with direct packfile access in `pack-check.c`, preventing MRU-triggered infinite loops during verification. The test suite now explicitly verifies corruption detection when the same object exists in multiple packs (one corrupt, one valid).

Key technical changes span `pack-check.c`, `packfile.c`, and `object.c`, with test coverage in `t1450-fsck.sh` and `t1050-large.sh`. The series fixes a regression from commit c31bad4f7d (packfile MRU list changes). Jeff King has reviewed all patches, confirming the technical soundness while providing focused feedback on test coverage and error handling that Patrick has incorporated in this v2 submission.
