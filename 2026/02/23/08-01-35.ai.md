This is the final version (v8) of a feature series enabling flexible reference storage backend configuration, primarily to support zero-downtime migrations between ref backends like files and reftable. The series has maintainer approval from Junio Hamano and is ready for integration.

The key addition is allowing the `extensions.refStorage` config to specify both format and location via URI syntax (`<format>://<payload>`), plus a `GIT_REFERENCE_BACKEND` environment variable override. This enables writing refs to arbitrary locations, which GitLab needs for their migration strategy that minimizes downtime by first preparing refs in a staging area before atomically switching.

The v8 changes are minor refinements: fixing a documentation typo, optimizing test file comparisons, and adjusting some test assertions to verify content directly rather than through intermediate files. The series has evolved through extensive review, with all substantive feedback addressed across 8 iterations. Reviewers have included Patrick Steinhardt, Karthik Nayak, Derrick Stolee, Toon Claes, Eric Sunshine, and others, covering architecture, URI syntax, worktree handling, tests, and documentation.

Technical highlights include centralized stub management in the generic refs layer, worktree reference location resolution, comprehensive test coverage in t1423-ref-backend.sh, and careful handling of path safety invariants. The implementation supports both absolute and relative paths (resolved relative to GIT_DIR) and properly integrates with clone/init operations.
