Bugfix targeting `git for-each-repo` in worktree contexts. This patch identifies and explains a subtle issue where `for-each-repo` inherits and propagates the `GIT_DIR` environment variable incorrectly when run from a worktree, causing commands to execute in the wrong repository context.

Matthew Gabeler-Lee reports that scripts using `git for-each-repo` fail when run from a worktree directory, though they work correctly from the main repository. Through investigation with strace, they pinpoint the issue to `GIT_DIR` being set in the `for-each-repo` process and incorrectly passed to child Git invocations. This causes commands to execute relative to the worktree's parent repository rather than the intended target repositories specified in the config.

The bug manifests when running commands like `git for-each-repo --config=foo.bar -- branch` from a worktree, which effectively executes as `GIT_DIR=/worktree-parent/.git git -C /unrelated-repo branch`. The patch doesn't include a fix but clearly describes the problematic behavior and provides enough technical detail for someone familiar with Git's worktree and environment handling to address it. The reporter notes they've checked recent changes and found nothing that would resolve this issue, suggesting it remains unfixed in current master.
