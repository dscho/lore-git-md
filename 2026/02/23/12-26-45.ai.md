Performance improvement patch implementing type filtering for `git config list`. This is patch 3/13 in Derrick Stolee's series to optimize config value parsing, originally motivated by git-credential-manager's performance needs with path-type configs.

The patch makes `--type=<X>` actually work with `git config list`, where previously it was silently ignored. Each key-value pair is now parsed through `format_config()` with gentle parsing enabled (first real use of this parameter). Invalid values are omitted from output rather than causing errors, maintaining backward compatibility since raw values remain available without `--type`.

Key technical changes:
- Adds `display_options_init_list()` helper to properly initialize output formatting
- Uses `fwrite()` for config output to handle configurable terminators
- Updates documentation to clarify `--type` behavior in list mode
- Adds comprehensive tests showing current behavior (some failing) that will be fixed in later patches

The implementation shows the performance-oriented approach of the series - filtering during parsing rather than after. This comes with a behavior change (now respecting `--type` where it was ignored before) that could surprise users, though the commit argues this is justified since the option was previously non-functional.

Test coverage is thorough, exercising all config types (bool, int, path, color, etc.) and their error cases. Some tests are marked as failing to document current behavior that will be improved in subsequent patches. The tests help justify the upcoming refactoring of `format_config()` in later parts of the series.
