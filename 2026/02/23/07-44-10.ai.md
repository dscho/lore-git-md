This is a bugfix patch (v11) from Tian Yuchen that refines error handling for `.git` file/directory detection, addressing security implications around repository validation. It builds on the merged v10 series that consolidated error codes for ENOTDIR/ENOENT cases.

The patch introduces two new error codes (`READ_GITFILE_ERR_MISSING` and `READ_GITFILE_ERR_IS_A_DIR`) to better distinguish between different failure modes when checking `.git` paths. Key changes include:

1. More precise error classification in `read_gitfile_gently()` to separate missing files from other stat failures and directory cases
2. Updated handling in `setup_git_directory_gently_1()` to properly process these new error codes while maintaining security boundaries (still rejecting FIFOs/sockets)
3. Caller updates in `submodule.c` and `worktree.c` to handle the refined error codes
4. A comprehensive new test suite (`t0009-git-dir-validation.sh`) that verifies behavior with symlinks, FIFOs, garbage content, and empty directories

The implementation follows Junio Hamano's guidance on error code consolidation and incorporates Karthik Nayak's test suite feedback. The patch appears well-tested and maintains Git's security posture by continuing to reject non-file `.git` entries (like FIFOs) with clear error messages. Some `NEEDSWORK` comments remain for future consideration around empty/unrelated directory handling.
