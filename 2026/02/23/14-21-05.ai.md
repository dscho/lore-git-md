Feature patch adding repository topology metrics to `git repo` command.

This is patch 5/9 in Eslam Reda Ragheb's v2 series enhancing the `git repo` command with detailed repository structure reporting. The patch introduces several new metrics about repository topology that help diagnose complex histories:

- Maximum commit parent count (fanout)
- Maximum tree entry count
- Maximum blob path length and depth
- Maximum tag chain depth

The implementation traverses reachable objects to gather these statistics, adding them to both the human-readable table and machine-readable key-value output formats. The metrics are calculated during the existing object counting pass, with new helper functions for each metric type. The patch modifies 171 lines in builtin/repo.c, primarily adding the new tracking infrastructure.

This continues the series' pattern of building comprehensive repository diagnostics while maintaining backward compatibility. The metrics overlap somewhat with Justin Tobler's parallel work on repository introspection, particularly around object statistics, though the approaches differ in scope and implementation details. The patch follows Git's established patterns for command plumbing and includes thorough memory management via `strbuf` and proper object lifecycle handling.

Key technical details include:
- New fields in `struct object_stats` for each metric
- Helper functions like `get_commit_parent_count()` and `get_tag_chain_depth()`
- Integration with the existing object counting callback
- Both table and key-value output formats updated
- Maintains the series' repository-aware design (no global state)
