This is a refactoring patch from Karthik Nayak that removes an unnecessary side effect in `create_reference_database()`. The function was modifying the repository's ref storage format even though this information is already set by the callers (`git-init` and `git-clone`). The change eliminates redundant format-setting and prevents potential issues with future dynamically allocated fields in the format structure.

The patch is part of the v8 series implementing reference storage backend selection, but this particular change is a clean-up that stands on its own. It simplifies the initialization flow by making `create_reference_database()` purely about creating the reference storage structures without also setting their format. The modification touches three files - `builtin/clone.c`, `setup.c`, and `setup.h` - with straightforward changes to function signatures and call sites.

This appears to be a well-justified cleanup that follows the principle of minimizing side effects. The commit message clearly explains the current behavior and why the change is beneficial, noting that the format is already properly set by the initialization flow. The patch maintains all existing functionality while making the code more robust against future modifications.
