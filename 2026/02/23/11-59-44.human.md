This is part 10/17 of Patrick Steinhardt's series to unify Git's ref iteration interfaces. The patch strengthens validation of the options passed to the new unified `refs_for_each_ref_ext()` function.

The changes add two key safety checks:
1. The ref store parameter can no longer be NULL (previously this silently succeeded)
2. When prefix trimming is requested, the function now verifies that:
   - A prefix was actually provided
   - The prefix ends with a trailing slash if it would be fully trimmed
   - The trim length doesn't exceed the prefix length

These are defensive programming measures that catch invalid usage patterns early. The commit message notes that no existing callers rely on the previous lenient behavior, so this shouldn't break anything. The patch follows the pattern of the series by making the API more robust while maintaining backward compatibility where it matters.

Karthik Nayak has already reviewed the full series and given it his approval, so this patch is in the final polishing stage before potential merging.
