Performance optimization in Patrick Steinhardt's ref iteration API unification series. This patch (7/17) speeds up `refs_for_each_glob_ref_in()` by leveraging the new unified `refs_for_each_ref_ext()` interface to avoid unnecessary iteration over refs outside the specified prefix.

The key change moves the glob pattern matching into the extended iteration API, allowing backends to skip refs that don't match the prefix early. Benchmark shows dramatic improvement - from 115ms to 1.1ms in a test case with 1M refs outside the prefix and 1 inside. Karthik Nayak reviews positively but questions whether the prefix trimming in `for_each_filter_refs()` can now be removed since the backend handles prefix matching.

This is part of the larger effort to consolidate Git's ref iteration interfaces, with all specialized functions being replaced by the configurable `refs_for_each_ref_ext()`. The patch maintains behavior while improving performance for the glob case, demonstrating the benefits of the unified API approach. The series has been carefully reviewed by Karthik Nayak, with minor suggestions like this one being incorporated.
