This patch continues Patrick Steinhardt's series to make Git's object database (ODB) storage pluggable. It introduces a type system for ODB sources to enable future backend implementations beyond the current files-based storage.

The change adds an `enum odb_source_type` with two values: `ODB_SOURCE_UNKNOWN` (for error detection) and `ODB_SOURCE_FILES` (the current implementation). Each `struct odb_source` now tracks its type, and the files backend downcast helper `odb_source_files_downcast()` includes a type check that will BUG() if called on the wrong source type. The patch updates initialization code to pass the type parameter through the creation chain.

While currently only the files backend exists, this change lays groundwork for future alternative backends by enforcing type safety when accessing backend-specific functionality. The implementation follows Git's standard pattern for pluggable subsystems, similar to how ref backends work. This is a small but important step in the larger ODB abstraction effort, ensuring safe downcasting between generic and backend-specific types as more implementations are added.
