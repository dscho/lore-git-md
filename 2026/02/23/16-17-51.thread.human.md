This thread introduces a major architectural change to Git's object database (ODB) subsystem, part of Patrick Steinhardt's ongoing effort to make object storage backends pluggable. The 17-patch series reworks core ODB operations into callback-based interfaces, moving backend-specific logic into `struct odb_source` implementations. The changes touch nearly every part of Git that interacts with objects, from basic reads/writes to transaction handling and alternate management, primarily affecting `object-file.c` and introducing new headers in `odb/source*`.

The series represents a significant step toward pluggable storage backends, though several important features remain for future work: object counting, OID abbreviation, consistency checks, packfile generation, and the "objectStorage" extension. Patrick has structured the changes carefully, with each patch focusing on one callback family, and the cover letter clearly delineates what's in scope versus what will come later. Given Patrick's track record with large refactorings and his leadership of the ODB abstraction effort, this appears to be a well-planned foundation for future storage backend implementations.
