This thread continues Patrick Steinhardt's major refactoring of Git's object database (ODB) subsystem to make storage backends pluggable. The series has grown to 18 patches, with each carefully converting one ODB operation at a time to a callback-based interface while maintaining all existing behavior.

The latest patch (10/18) introduces a `read_object_stream` callback, moving the streaming object access logic from the central `odb/streaming.c` into backend-specific implementations. The files backend now handles both packed and loose object streaming through `odb_source_files_read_object_stream()`, following the pattern established in earlier patches for other operations like `read_object_info` and `close`.

The series is progressing methodically through the ODB operations:
- Early patches (1-5) established type safety and basic infrastructure
- Subsequent patches (6-10) have converted free, reprepare, close, read_object_info, and now read_object_stream to the callback pattern
- Each change maintains backward compatibility while enabling future alternative backends

The work represents a significant architectural shift in how Git handles object storage, with all changes carefully documented and reviewed. While the series is not yet complete - remaining operations like write still need conversion - it continues to follow Git's established approach for making subsystems pluggable through incremental, behavior-preserving changes.
