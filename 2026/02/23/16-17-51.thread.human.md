This thread documents Patrick Steinhardt's major refactoring of Git's object database (ODB) subsystem to enable pluggable storage backends, now successfully merged as a 17-part series. The work systematically converted ODB operations to a callback-based dispatch model while maintaining compatibility with the existing files backend. Key architectural changes included establishing type safety, relocating infrastructure, and making all core operations (including alternates handling) pluggable.

Justin Tobler has been closely reviewing the implementation details, first raising a post-merge question about header inclusion practices, and now providing feedback on patch 2/17's structural reorganization. His latest review focuses on the transitional state where the backend hierarchy is being inverted - currently the files source still references the base ODB structure directly, though this relationship will change in later patches. Justin flags several details needing attention, including an outdated comment about packfile access restrictions and the eventual need for type casting rather than direct implementation access.

The discussion exemplifies Git's careful, iterative approach to major refactoring - even after architectural acceptance and merging, reviewers like Justin continue scrutinizing transitional states and implementation details. With the core ODB abstraction now in place, future work remains to convert additional features like object counting and implement configuration for alternate backends.
