This thread documents Patrick Steinhardt's completed 17-part series refactoring Git's object database (ODB) subsystem to enable pluggable storage backends. The series systematically converted all core ODB operations to callback-based dispatch while maintaining existing files backend behavior, with Justin Tobler providing thorough review and giving a final Reviewed-by. The work represents a major architectural milestone in abstracting Git's object storage layer.

After the series was considered complete, Junio Hamano raised a design question about callback contracts in the new interface. He noted that while the abstraction is clean, the header files don't specify which callbacks are mandatory versus optional for backend implementations. The current wrapper functions directly dereference function pointers without NULL checks, which could cause crashes if a backend omits certain operations. Junio suggested either documenting mandatory callbacks in `struct odb_source` or adding NULL checks to wrappers with appropriate error handling.

This late-stage discussion touches on an important design consideration for the pluggable interface - how strictly to enforce implementation requirements versus allowing partial implementations. While the series is otherwise ready for integration, this architectural question about future-proofing the abstraction merits consideration as alternative backends are developed. The thread awaits Patrick's response to Junio's feedback.
