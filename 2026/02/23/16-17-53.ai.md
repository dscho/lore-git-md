This is part 2/17 of Patrick Steinhardt's series to make Git's object storage backends pluggable, continuing the architectural work to abstract the ODB layer. The patch introduces a new "files" source type that encapsulates both loose object files and packfile storage, analogous to how the "files" ref backend handles loose refs alongside packed-refs.

The change moves existing loose object and packfile handling into a new `struct odb_source_files` that combines both storage types, with corresponding new source-files.[ch] files. The patch is primarily mechanical, updating callers throughout the codebase to access packfiles and loose objects via the new `source->files` member rather than directly through `source->packfiles` and `source->loose`. The architecture will be inverted in the next patch to make the files source contain the `struct odb_source` rather than vice versa.

This affects nearly all object access paths, with changes across builtins (cat-file, fast-import, grep), core object handling (object-file.c, odb.c), and packfile operations (packfile.c, midx.c). The patch maintains existing behavior while establishing the structure needed for the callback-based operations coming in later patches. As with Patrick's other large refactoring series, this follows an incremental approach where each commit tackles one coherent piece of the overall change.
