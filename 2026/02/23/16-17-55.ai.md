This is part 4/17 of Patrick Steinhardt's series to make Git's object database (ODB) storage pluggable. The patch moves path reparenting logic - which updates relative paths when changing working directories - from the generic ODB layer into the specific subsystems that need it (the files backend and temporary object directories).

The change relocates the reparenting implementation details to where they belong: the "files" source backend now handles path updates for its own storage, and tmp-objdir manages its own path adjustments. This makes the code more modular by keeping backend-specific logic with the backend rather than in the core ODB layer. The patch removes the now-unused `tmp_objdir_unapply_primary_odb()` and `tmp_objdir_reapply_primary_odb()` functions since their functionality is handled internally.

This continues the architectural pattern seen in earlier patches of moving implementation details out of the generic ODB interface and into backend-specific code. The change is mechanical but important for the larger goal of making the ODB subsystem properly abstracted and pluggable. The patch 3/17 summary noted this would be needed when introducing the downcast pattern for backend access.
