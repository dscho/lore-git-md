This is patch 4/5 in Justin Tobler's series adding repository structure statistics to `git repo`. The patch focuses on tracking the commit with the most parents, which helps identify complex merge histories (like octopus merges) in a repository.

The key changes:
- Adds a new `parent_count` field to track maximum parent count alongside other object statistics
- Introduces `stats_table_object_count_addf()` helper for displaying count-based metrics in the table output
- Updates the object counting logic to parse commits and count their parents
- Includes corresponding test updates to verify the new statistics in table, keyvalue, and nul formats

The implementation carefully handles edge cases like NULL OIDs and maintains consistency with the series' existing statistics framework. The tests show the new output format with parent counts integrated alongside the existing size metrics.

This continues the series' pattern of well-structured, incremental additions to the repository statistics functionality, with thorough test coverage. The change is focused and clearly motivated - identifying merge complexity is a useful metric for repository analysis.
