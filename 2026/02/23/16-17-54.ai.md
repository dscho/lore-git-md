This is part 3/17 in Patrick Steinhardt's series to make Git's object storage backends pluggable, continuing the architectural inversion of the previous patches. The patch refactors the "files" backend to embed the base `struct odb_source` within `struct odb_source_files`, following Git's standard pattern for pluggable backends (as seen in ref stores and object streams). 

The change provides several benefits: it eliminates an allocation, hides implementation details, enables compile-time offset calculations for type casting, and makes backend-specific dependencies more visible. The patch introduces `odb_source_files_downcast()` to safely convert between the generic and files-specific types, though it always succeeds for now since only the files backend exists. Future patches will make this cast fail for non-files backends.

The diff shows widespread mechanical changes updating callers to use the new downcast function when accessing files backend internals. While many direct accesses remain (to be addressed later), this establishes the proper architectural pattern before introducing additional backend types. The changes span object access, packfile handling, and loose object management across builtins and core components like the object database and packfile subsystems.

This continues Patrick's characteristically thorough approach to large-scale refactoring - each patch makes one clear change while maintaining existing behavior, with the series carefully structured to enable pluggable storage backends incrementally. The changes are mechanical but foundational for the ODB abstraction effort.
