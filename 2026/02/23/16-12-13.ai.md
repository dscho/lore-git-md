Test modernization patch relocating a branch checkout test case from t0050-filesystem.sh to t2018-checkout-branch.sh, with improvements to the test itself.

The patch moves a test that verifies correct branch checkout behavior when a repository contains both a file ("Gitweb") and a directory ("gitweb") with case-insensitive naming conflicts. While originally placed in the filesystem test suite with a CASE_INSENSITIVE_FS prerequisite, the test actually exercises core checkout functionality and belongs with other branch checkout tests.

Junio C Hamano's review notes two technical considerations: First, the test needs to account for Git 3.0's default branch name change from 'master' to 'main' (currently it uses 'master'). Second, he suggests explicitly setting the initial branch name when creating the test repository rather than relying on the global GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME setting. These points will likely need addressing in a v2 of the patch.

The test improvements include:
- Removal of the unnecessary CASE_INSENSITIVE_FS prerequisite
- More descriptive test title
- Added verification of file existence post-checkout (test_path_is_file)
- Slight variable name changes (repo -> repo-case, todo -> other)

This appears to be a straightforward test suite cleanup that better organizes tests by functionality. The patch is small and focused, though it will need minor adjustments based on Junio's feedback about branch naming. The test case itself exercises an edge case in branch switching that could potentially surface bugs in the checkout machinery's handling of case-sensitive vs case-insensitive filesystem interactions.
