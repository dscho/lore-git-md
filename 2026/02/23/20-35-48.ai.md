This is the final patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch specifically resolves an infinite loop in `git fsck` that could occur when verifying large objects that exist in multiple packfiles, originally reported by brian m. carlson.

The root cause stems from how large objects (exceeding core.bigFileThreshold) are handled during verification. The existing code used `odb_read_object_stream()` which could trigger MRU list updates, potentially causing infinite iteration when the same object exists in multiple packs. Patrick's solution replaces this with direct packfile access via `packfile_read_object_stream()`, ensuring we verify the specific object in the target pack without triggering MRU updates.

The patch includes a new test case in t1450-fsck.sh that demonstrates the fix by creating two large blobs in separate packs and verifying fsck handles them correctly. Junio Hamano's review confirms the technical soundness of the approach while noting the fragility of the underlying MRU mechanism. The change is minimal (just 2 lines in pack-check.c) but effectively prevents the infinite loop while maintaining proper corruption detection.

This completes the series which has gone through multiple iterations incorporating feedback from Jeff King and Eric Sunshine. The changes improve Git's reliability when dealing with large objects across multiple packfiles, particularly important for repositories storing binary assets.
