This thread addresses a subtle edge case in Git's `receive.denyCurrentBranch=updateInstead` behavior when pushing to bare repositories that have associated worktrees. The issue was first identified by Runxi Yu, who submitted a test case showing that Git incorrectly rejects pushes when: (1) the bare repository's HEAD points to an unborn branch, (2) there's an associated worktree, and (3) the worktree itself is clean.

Pablo Sabater has led the technical response, first proposing a fix that modifies `builtin/receive-pack.c` to properly check the worktree's HEAD rather than the bare repository's HEAD, and then improving the test infrastructure to ensure clean test isolation. The latest patch completes this effort by refining the implementation to use the worktree's path and HEAD oid directly, removing unnecessary code and converting the test from `test_expect_failure` to `test_expect_success`.

The solution is well-scoped, touching only the specific worktree interaction case while maintaining existing behavior for non-worktree scenarios. The series shows clear progression from problem identification through solution implementation, with careful attention to test hygiene. The changes are now ready for final review, with no outstanding technical questions remaining. The main remaining step is for maintainers to evaluate the patch for inclusion.
