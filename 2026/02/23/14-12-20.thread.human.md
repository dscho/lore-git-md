This thread documents a bug in how `receive.denyCurrentBranch=updateInstead` interacts with worktrees when the bare repository's HEAD points to an unborn branch. The test case shows that Git incorrectly rejects pushes in this scenario, claiming there are staged changes in the worktree when none exist. The issue appears to stem from `receive-pack` checking the bare repository's HEAD state rather than the actual worktree state.

Junio Hamano has asked for historical context about when this behavior regressed, suggesting the test may need additional information about when the bug was introduced. The test is currently marked as expected-to-fail while awaiting a fix. The original report indicates this was discovered through real-world usage of worktrees with the `updateInstead` setting, highlighting an edge case in how these features interact.
