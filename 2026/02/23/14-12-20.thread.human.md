This thread documents a bug in how `receive.denyCurrentBranch=updateInstead` interacts with bare repositories that have worktrees. The issue occurs when pushing to a bare repo where the bare HEAD points to an unborn branch (different from the worktree's branch) - Git incorrectly rejects the push with a "Working directory has staged changes" error even when the worktree is clean.

The test case demonstrates that this behavior has been broken since the original 2021 implementation by Anders Kaseorg that added worktree support for bare repos. The root cause is in `builtin/receive-pack.c`, where the code checks the bare repository's HEAD (via `head_has_history`) rather than the worktree's HEAD when determining staged changes. This causes it to incorrectly use the empty tree as a comparison base when the bare HEAD is unborn.

Junio Hamano has questioned whether this behavior ever worked correctly, and the test confirms it has been broken from the start. The test is marked as `test_expect_failure` to document the current incorrect behavior while awaiting a fix. The commit provides useful context about the real-world scenario that uncovered this edge case in the worktree/updateInstead interaction. Key files involved are `builtin/receive-pack.c` and the test script in `t/`. While not a regression, the test serves as important documentation of the bug and will help verify any future fix.
