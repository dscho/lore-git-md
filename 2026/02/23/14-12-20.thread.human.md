This thread documents a bug in how `receive.denyCurrentBranch=updateInstead` handles pushes to bare repositories with worktrees. The issue occurs when the bare repo's HEAD points to an unborn branch that doesn't match the worktree branch - Git incorrectly rejects the push with a "Working directory has staged changes" error even though the worktree is clean.

The problem stems from `builtin/receive-pack.c` checking the bare repository's HEAD (via `head_has_history`) rather than the worktree's HEAD when determining staged changes. Junio Hamano questioned whether this behavior ever worked as intended, and investigation suggests it has been broken since the worktree support for bare repos was added in 2021. The test case has been marked as `test_expect_failure` to document the current incorrect behavior while the fix is being determined.

The key open question is how to properly fix this - likely by modifying the logic to check the worktree HEAD instead of the bare HEAD when detecting staged changes. The test provides valuable context about the real-world scenario that uncovered this edge case in the interaction between worktrees and the `updateInstead` configuration.
