This is patch 11/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces. The patch converts `refs_for_each_ref_in()` callers to use the new unified `refs_for_each_ref_ext()` API, which accepts a configuration struct (`refs_for_each_ref_options`) rather than individual parameters.

Karthik Nayak reviews the conversion and raises a question about whether the `trim_prefix` field should be a boolean rather than requiring callers to pass the prefix length. The current implementation requires callers to calculate `strlen(prefix)` themselves, which Karthik suggests might be redundant since the length could be computed internally. This is a minor API ergonomics point rather than a functional concern.

The patch touches several key areas that iterate over refs: bisect, rev-parse, pack-bitmap, and test infrastructure. Each conversion follows the same pattern - replacing the direct prefix parameter with a structured options object while maintaining identical behavior. The changes are mechanical but important for the series' goal of reducing API surface area.

This continues the thread's pattern of careful review from Karthik, who has been consistently providing feedback on API design details throughout the series. The question about `trim_prefix` doesn't block the patch but may lead to follow-up discussion about whether the API could be made more ergonomic.
