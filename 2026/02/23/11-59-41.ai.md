Performance optimization in Patrick Steinhardt's ref iteration API unification series. This patch (7/17) dramatically speeds up glob-based ref iteration by properly handling prefixes in the new `refs_for_each_ref_ext()` interface.

The key change moves glob pattern matching into the extended iteration API rather than filtering all refs in a post-processing step. This allows early termination when refs outside the target prefix are encountered. The benchmark shows a 107x speedup (115ms -> 1.1ms) for a case with 1 million irrelevant refs and one matching ref.

The implementation introduces a `pattern` field in `struct refs_for_each_ref_options` and modifies the filtering callback to handle prefix trimming via the new `trim_prefix` parameter. The patch preserves all existing behavior while eliminating the need to scan irrelevant refs. Karthik Nayak has already reviewed and approved the overall series, with this patch specifically addressing his earlier feedback about prefix handling efficiency.

This is part of the larger effort to consolidate Git's 14 specialized ref iteration functions into a single unified API. The series is in its final polishing stages, with only minor documentation tweaks and one open question about prefix trimming mechanics remaining. The performance gains here validate the architectural approach of moving filtering logic into the iteration core.
