This is the final patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch fixes an infinite loop in `git fsck` that could occur when verifying large objects that exist in multiple packfiles, originally reported by brian m. carlson.

The core issue stems from how `git fsck` verifies large objects (those exceeding core.largeFileThreshold) by using `odb_read_object_stream()`, which performs a full object lookup and can trigger updates to the packfile MRU list. When the same large object exists in multiple packs, this creates a circular dependency that leads to the infinite loop.

The fix replaces the indirect object streaming approach with direct packfile access via `packfile_read_object_stream()`, which avoids the MRU list updates while also ensuring we verify the specific packfile entry we intended to check. The patch includes a thorough test case that creates two packfiles with overlapping large objects, corrupts one object in each pack, and verifies `git fsck` correctly identifies both corruptions.

This is a well-constructed patch that addresses both the immediate infinite loop issue and ensures proper corruption detection. The test case is particularly robust, demonstrating the fix handles the edge case while maintaining expected fsck behavior. With Jeff King's review feedback incorporated across the series, this appears ready for merging.
