This is the third patch in Patrick Steinhardt's series fixing pack validation issues with large objects. It refactors the object stream reading infrastructure in preparation for the actual bugfix.

The patch extracts a new `packfile_read_object_stream()` function from the existing `packfile_store_read_object_stream()`, making the lower-level functionality available for direct use. The new function takes a packfile and offset directly rather than looking them up via an object ID. This allows callers to work with specific packfile locations without going through the object lookup layer.

Key technical details:
- New `packfile_read_object_stream()` function added to packfile.h
- Existing `packfile_store_read_object_stream()` now just a thin wrapper that does the OID lookup
- Stream initialization logic moved to the new function
- Still maintains the same big-file threshold check from the original
- Touches core packfile handling code in packfile.c

This is a mechanical refactoring that doesn't yet implement the promised large-object validation fixes, but establishes the necessary plumbing. The changes are focused and well-contained, with the original function preserved as a compatibility wrapper. The patch follows the series' pattern of preparatory changes before the actual bugfix.
