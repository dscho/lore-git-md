This is a patch in Patrick Steinhardt's ongoing ref iteration API unification series, specifically addressing verification of options for the new `refs_for_each_ref_ext()` interface. Karthik Nayak provides a review with a suggested wording tweak for a BUG() message.

The patch tightens validation of the refs_for_each_ref_ext() options by:
1. Making a NULL ref_store parameter trigger a BUG() rather than silently succeeding
2. Adding checks to prevent invalid prefix trimming cases that could produce empty strings

Karthik's review is light - he suggests clarifying "refs" to "ref store" in the BUG() message for readability, though notes it's not strictly necessary. The changes look like straightforward hardening of the new API's edge case handling, with no functional impact expected since existing callers don't rely on the relaxed behavior being removed.

This continues the series' pattern of carefully migrating functionality to the unified interface while maintaining strict backwards compatibility. The review interaction shows the series is now in fine-tuning mode, with only minor nits being raised on these later patches.
