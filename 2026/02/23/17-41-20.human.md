This is the final patch in Justin Tobler's 5-part series adding repository statistics to `git repo`. The series tracks various metrics about repository objects, with this patch specifically identifying the tree with the most entries.

The patch adds tree entry counting to the statistics collection, showing both the maximum number of entries in any single tree and which tree holds that record. It builds on the existing infrastructure from earlier patches that tracks largest objects by type (blobs, trees, tags) and commits with most parents.

Implementation-wise, it:
- Adds a new `tree_entries` field to track maximum entries
- Introduces `count_tree_entries()` to walk tree objects and count their entries
- Updates both the formatted table output and key-value output formats
- Includes test updates to verify the new functionality

The changes are cleanly integrated with the existing code, following the pattern established in previous patches. Test coverage shows the feature works in both empty repositories and populated ones, with proper handling of the reference numbering system for OID annotations.

This completes the core functionality of the repository statistics feature, giving users visibility into both object sizes and tree complexity. The series has evolved through multiple iterations based on feedback from Junio Hamano and Patrick Steinhardt, with this final patch maintaining the clean, focused approach of the earlier versions.
