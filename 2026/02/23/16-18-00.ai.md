This is patch 9/17 in Patrick Steinhardt's ongoing series to make Git's object database (ODB) subsystem pluggable. The patch converts the `read_object_info()` operation to use callback-based dispatch, continuing the systematic refactoring of ODB operations.

The key technical changes include:
- Adding a `read_object_info` callback to `struct odb_source` with detailed documentation of its contract and expected behavior
- Introducing a new `OBJECT_INFO_SECOND_READ` flag to handle the special case where objects may appear after repacking
- Moving the files backend implementation to `odb_source_files_read_object_info()`
- Updating the core object lookup logic in `odb.c` to use the new callback interface

The patch handles a tricky edge case where objects may appear after repacking by introducing the `OBJECT_INFO_SECOND_READ` flag rather than trying to move the entire two-phase lookup logic into individual backends. This maintains the existing behavior while making the operation pluggable.

The changes are focused and well-explained in the commit message, which clearly describes the technical challenge and chosen solution. This continues the series' pattern of methodically converting ODB operations to callback-based dispatch while preserving existing functionality. The patch touches core object lookup paths but does so in a way that maintains backward compatibility.
