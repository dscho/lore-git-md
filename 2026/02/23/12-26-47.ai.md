This patch is part of Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering, now at version 3 with 13 patches. Patch 5/13 focuses on boolean value handling in config listing.

The change moves boolean formatting logic into a dedicated `format_config_bool()` helper function, mirroring the pattern established for integers in patch 4/13. The key improvement is adding "gentle parsing" behavior when listing config values with `--type=bool` - invalid boolean values are now quietly filtered out rather than causing the command to fail. This maintains consistency with how other types are handled in the series.

The implementation provides both gentle parsing (using `git_parse_maybe_bool()`) and strict parsing (using `git_config_bool()`) paths, controlled by the `gently` parameter. The test is updated to verify that invalid boolean values are now silently filtered rather than causing errors, while valid values are properly formatted as "true" or "false".

This patch follows the established pattern of the series by:
1. Extracting type-specific formatting into dedicated helpers
2. Supporting both gentle and strict parsing modes
3. Maintaining backward compatibility with existing behavior
4. Including corresponding test updates

The change is straightforward and builds on the foundation laid by previous patches in the series. It addresses a specific case of the broader performance improvement goal by avoiding unnecessary parsing of values that will ultimately be filtered out.
