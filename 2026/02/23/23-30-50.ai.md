Behavioral change for `format.noprefix` configuration.

This patch changes `format.noprefix` to strictly validate as a boolean value, fixing an inconsistency where it previously accepted any value as implicitly true. The change aligns with the documented behavior that `format.noprefix` should mirror `diff.noprefix`. The implementation now uses `git_parse_maybe_bool()` and provides clear error messages when invalid values are encountered, including an advisory note about the behavioral change for users who may have relied on the old permissive parsing.

The patch includes tests verifying:
- The new strict boolean validation rejects non-boolean values with appropriate error messages
- `false` now correctly disables the no-prefix behavior
- The `--default-prefix` option still overrides the config as expected

While technically a breaking change, the author argues this is justified as a bug fix since the documentation always described boolean behavior. The advisory message helps transition users who may have relied on the undocumented permissive parsing. The change has already been reviewed and approved by Junio Hamano and Jeff King, with consensus that this properly aligns implementation with documentation.
