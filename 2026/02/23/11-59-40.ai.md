Refactoring patch introducing a unified ref iteration API as part of Patrick Steinhardt's ongoing refs subsystem consolidation effort.

This patch (6/17 in the series) exposes the internal `do_for_each_ref()` as a public `refs_for_each_ref_ext()` function and introduces a new `struct refs_for_each_ref_options` to control iteration behavior through a single composable interface. The options structure handles prefix matching, exclude patterns, prefix trimming, and iteration flags (like including broken refs). All existing ref iteration functions (`refs_for_each_ref()`, `refs_for_each_ref_in()`, etc.) are reimplemented as thin wrappers around this new unified API.

The change maintains identical behavior while reducing API surface area and eliminating combinatorial explosion of specialized iteration functions. Performance-critical paths like `repo_migrate_ref_storage_format()` are updated to use the new interface. The patch includes thorough documentation of the options structure fields and their purposes.

This is a key step in the larger refs API unification effort that has been under review by Karthik Nayak, with all feedback incorporated. The series has demonstrated measurable performance improvements (115ms to 1.1ms for glob iteration) while simplifying the codebase. The remaining patches in the series will build on this foundation to further consolidate the ref iteration API surface.
