This is a test case documenting a bug in the interaction between `receive.denyCurrentBranch=updateInstead` and worktrees with unborn bare repository HEADs. The test demonstrates that when pushing to a bare repository with a worktree where the bare HEAD points to an unborn branch (not matching the worktree branch), Git incorrectly rejects the push with "Working directory has staged changes" even when the worktree is clean.

The test sets up a scenario with a bare repository containing a worktree, configures `updateInstead`, points the bare repository's HEAD to an unborn branch, then attempts a push to the worktree branch - which fails when it should succeed. The issue appears to stem from `builtin/receive-pack.c` comparing against the bare repository's HEAD rather than the worktree state.
