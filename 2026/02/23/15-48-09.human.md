This is the final patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The thread has seen active discussion between Patrick and Jeff King, with Jeff providing detailed review feedback that Patrick has incorporated.

The core issue fixed here is an infinite loop in `git fsck` when verifying large objects that exist across multiple packfiles. The solution replaces `odb_read_object_stream()` with direct packfile access in `pack-check.c`, avoiding MRU-triggered infinite loops. Jeff King describes the fix as "delightfully simple" while suggesting test improvements.

Current discussion focuses on refining error handling approaches - specifically whether to add an OID parameter to `packfile_read_object_stream()` for marking corrupt objects or use detailed error codes instead. Jeff advocates for either comprehensive error handling or minimal interface changes rather than partial solutions. Patrick has demonstrated responsiveness to feedback, already incorporating suggestions like using `do_corrupt_object()` from t5303 for more precise test cases.

The changes span `pack-check.c`, `packfile.c`, and `object.c` with test coverage in `t1450-fsck.sh` and `t1050-large.sh`. This fixes a regression from commit c31bad4f7d (packfile MRU list changes).
