Feature patch series adding HTTP 429 rate limit handling to Git's HTTP client. This is the fifth iteration from Vaidas Pilkauskas, now focused solely on the HTTP improvements after splitting out strbuf fixes to a separate thread.

The series teaches Git to recognize HTTP 429 "Too Many Requests" responses and automatically retry after the delay specified in the Retry-After header (or a configured default). Key improvements since v4 include simplifying the retry mechanism to use blocking sleep() instead of a complex non-blocking approach, better handling of Retry-After: 0 cases, and more portable test infrastructure.

The implementation adds three new config options: http.maxRetries, http.retryAfter, and http.maxRetryTime to control the retry behavior. The tests demonstrate handling of both delay-seconds and HTTP-date Retry-After formats, with timing-sensitive checks using Git's test-tool date utilities.

This appears well-considered, with thoughtful responses to prior review feedback from Jeff King and Taylor Blau. The test coverage is thorough, exercising various edge cases of the HTTP 429 handling. The changes to remote-curl.c and http.c are substantial but focused, and the documentation updates clearly explain the new configuration options. This looks ready for serious consideration by the HTTP client experts.
