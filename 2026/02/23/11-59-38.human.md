This is patch 4/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces. The series has already been reviewed and approved by Karthik Nayak, with only minor polishing remaining.

The current patch performs a straightforward renaming of the `do_for_each_ref_flags` enum to `refs_for_each_flag` to better match Git's naming conventions. All related flag values are similarly renamed (e.g., `DO_FOR_EACH_INCLUDE_BROKEN` becomes `REFS_FOR_EACH_INCLUDE_BROKEN`). The changes are mechanical and touch multiple files that use these flags, including the core refs code and all three ref backends (files, packed, and reftable).

This is part of the broader effort to consolidate Git's ref iteration API into a single `refs_for_each_ref_ext()` function that can replace 14 specialized variants. The series has already demonstrated significant performance improvements (115ms to 1.1ms for glob iteration) while maintaining identical behavior across all callers.
