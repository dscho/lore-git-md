This is part of Patrick Steinhardt's ongoing series to make Git's object database (ODB) storage pluggable. Patch 4/17 refactors how Git handles path reparenting when the working directory changes, moving this logic from the generic ODB layer into the specific "files" backend and temporary object directory subsystems.

The change recognizes that path reparenting is an implementation detail specific to filesystem-based storage backends, not a general ODB concern. The patch removes the centralized reparenting logic from `odb.c` and distributes it to where it belongs: `odb/source-files.c` now handles path updates for regular object storage, while `tmp-objdir.c` manages the same for temporary object directories used during transactions.

This continues the architectural pattern seen in earlier patches of moving backend-specific knowledge out of generic interfaces. The implementation remains behaviorally equivalent but better localized - a typical Steinhardt-style refactoring that incrementally advances the pluggable ODB effort while keeping each change focused and reviewable. The patch touches core object storage paths but doesn't introduce new functionality or behavior changes.
