This is patch 4/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series addresses inefficiencies in config value parsing, particularly benefiting git-credential-manager's handling of path-type config values.

The current patch focuses on integer value handling, extracting the int64 formatting logic into a dedicated helper function `format_config_int64()`. This refactoring enables gentle parsing (non-fatal error handling) when requested, while maintaining the existing strict parsing behavior otherwise. The change makes `--type=int` filtering properly functional in list mode where it was previously ignored.

Key technical changes:
- New `format_config_int64()` helper encapsulates integer parsing/formatting
- Uses `git_parse_int64()` for gentle parsing mode (returns -1 on failure)
- Falls back to `git_config_int64()` for strict parsing (may die() on error)
- Updates tests to verify successful gentle parsing of valid integers
- Maintains consistent error handling pattern with other config types

The patch is part of a well-structured series where earlier patches laid the groundwork (code movement, gentle parsing infrastructure) and this one implements the first type-specific gentle parsing logic. Performance improvements have been confirmed in real-world git-credential-manager usage. All design questions appear resolved at this point in the series.
