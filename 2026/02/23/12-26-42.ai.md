This is a performance-focused feature series by Derrick Stolee that improves `git config list --type=<X>` filtering. The series has gone through three iterations (v1 was RFC, v2 incorporated feedback, v3 adds more tests and refinements) and is now a complete 13-patch set ready for merging.

The core motivation comes from git-credential-manager's performance bottleneck when dealing with path-type config values. The key insight is that `git config list` was parsing all values before filtering by type, creating unnecessary overhead. The series refactors config parsing to filter by type during initial parsing, with particular attention to path-type values.

Technical highlights include:
- Early filtering during parsing for performance
- Gentle/quiet parsing variants to avoid die() calls when filtering
- Careful handling of path values with `:(optional)` macros
- Conversion of type handling to an enum for clarity
- Comprehensive test coverage demonstrating the new behavior

The series has been thoroughly reviewed with all design questions resolved. Notable discussion points included:
- Path-type handling semantics for optional paths
- Naming conventions for parsing variants (settled on "quiet" terminology)
- Output formatting efficiency (confirmed `fwrite()` is needed)
- Defensive programming in the switch statement for type handling

The implementation is now polished with all test cases passing. Performance measurements in git-credential-manager show the expected improvements. The series represents a significant optimization for config operations while maintaining Git's existing config model.
