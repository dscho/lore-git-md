This is the final patch in a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The patch adds support for specifying the reference backend via the `GIT_REFERENCE_BACKEND` environment variable, complementing the existing `extensions.refStorage` config option.

The environment variable follows the same URI syntax (`<format>://<payload>`) as the config option and takes precedence when both are set. Key additions include:
- New `GIT_REFERENCE_BACKEND` environment variable handling in `setup.c`
- Stub creation in `refs.c` for repositories using alternate reference directories
- Comprehensive test coverage verifying:
  - Environment variable overrides config
  - Works with both files and reftable backends
  - Handles clone and init operations
  - Maintains consistency across worktrees
  - Validates URI parsing

The implementation builds on the series' earlier work centralizing stub management and reference location computation. Tests demonstrate the environment variable's behavior matches the config-based approach while providing runtime flexibility. The patch includes optimizations from earlier review feedback, particularly around test file comparisons and documentation.

With this addition, the series now provides three complete mechanisms for reference backend selection (config, environment variable, and URI-based control) to support GitLab's migration needs. Maintainer approval has been secured and all substantive technical concerns addressed through eight iterations of review.
