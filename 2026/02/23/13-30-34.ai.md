This is a follow-up discussion about the configurable branch comparison feature for `git status` (status.compareBranches), which remains in a "Stalled" state pending maintainer evaluation. Jeff King weighs in with technical suggestions to simplify the initial implementation while keeping future extensibility options open.

Jeff acknowledges he doesn't personally need the feature (his prior involvement was ensuring it could be disabled) but offers a phased approach to address earlier concerns about ref resolution edge cases. He proposes initially supporting only @{upstream} and @{push} comparisons with manual resolution, explicitly documenting this limitation. This would defer more complex dwim_ref() handling and substitution syntax (%s-style placeholders) for potential future expansion.

The suggestion aims to balance implementation safety with forward compatibility - the simpler initial version wouldn't preclude later enhancements while avoiding the corner cases Jeff previously identified. This comes as the thread has progressed from technical readiness to evaluating real-world utility, with D. Ben Knoble having recently provided the first concrete use case for the feature.

The patch series remains technically complete (337 lines of tests, all edge cases addressed) but its merge now hinges on whether Junio considers the demonstrated interest sufficient, with Jeff's proposal offering a possible path to reduce risk if the feature proceeds. No changes to the existing implementation are suggested at this time - this is purely a discussion of potential constraints to make the feature more maintainable if adopted.
