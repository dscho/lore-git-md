This is part 3/17 of Patrick Steinhardt's ongoing series to make Git's object storage backends pluggable, continuing the architectural refactoring of the ODB subsystem. 

The change flips the relationship between the generic `struct odb_source` and the files-specific `struct odb_source_files`, embedding the former within the latter rather than having a pointer. This follows Git's standard pattern for pluggable backends (like ref stores) and provides several benefits: avoiding an allocation, hiding implementation details, enabling compile-time offset calculations, and making backend-specific dependencies more visible through explicit downcasting.

The patch introduces a `odb_source_files_downcast()` helper and updates ~90 call sites across the codebase to use it when accessing files backend internals. While many of these accesses will eventually be replaced with proper callback interfaces (coming later in the series), this intermediate step maintains existing behavior while establishing the new structural pattern.

The changes are mechanically straightforward but wide-ranging, touching builtins (cat-file, fast-import, grep), core object handling, and packfile operations. This continues Patrick's characteristically thorough approach to large-scale refactoring - each patch in the series tackles one well-defined piece of the overall architecture change.
