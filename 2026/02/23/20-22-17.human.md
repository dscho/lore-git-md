This is a follow-up discussion about a minor documentation formatting issue in the recently merged UTF-8 alias support feature. The core implementation (now in the `next` branch) allows Git config subsections to use non-ASCII characters for aliases (like `[alias "förgrena"]`), with full zsh completion support via a new `--aliases-for-completion` option.

Kristoffer Haugsbakk noticed that the rendered HTML documentation shows visible AsciiDoc list continuation markers (`+`) in three places where they should have been processed as formatting directives. He suggests using `Documentation/doc-diff` to verify the rendering in future work. Junio Hamano confirms this applies to the final v7 version that was merged.

The issue is purely cosmetic and doesn't affect functionality. The feature itself is complete and well-reviewed after seven iterations, with all technical aspects (including UTF-8 handling, shell completion, and case sensitivity) properly addressed. This appears to be the last minor polish needed for what has been a thorough implementation process.
