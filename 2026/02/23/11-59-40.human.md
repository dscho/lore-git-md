This is patch 6/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces, now in final polishing stage with Karthik Nayak's approval. The patch introduces `refs_for_each_ref_ext()` as the new unified API for ref iteration, replacing the internal `do_for_each_ref()` function and its many specialized wrappers.

The key change exposes the iteration functionality through a new `struct refs_for_each_ref_options` that consolidates all configuration parameters (prefix patterns, exclusion patterns, trim length, and behavior flags). This allows callers to precisely control iteration behavior without needing separate functions for each combination of options. The patch mechanically converts all existing iteration functions to use this new interface while maintaining identical behavior.

Notable aspects:
- Preserves all existing functionality while simplifying the API surface
- Introduces clear documentation for the options structure
- Handles edge cases like namespace prefixes and broken ref inclusion
- Follows the pattern seen in other subsystems moving toward more composable interfaces
- Part of a broader effort to modernize Git's refs subsystem
- Builds on earlier work standardizing callback types (patch 5/17)
- Sets foundation for future optimizations and extensions

The patch has already been reviewed by Karthik Nayak and incorporates all feedback from earlier rounds, including improved documentation and namespace handling. It represents a significant step in consolidating Git's ref iteration APIs while maintaining backward compatibility.
