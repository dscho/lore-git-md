Performance improvement for `git config list --type=<X>` filtering. This is patch 3/13 in Derrick Stolee's series addressing a performance bottleneck in git-credential-manager when dealing with path-type config values.

The patch implements the core functionality to make `--type` filtering work in `git config list` mode, where previously the option was silently ignored. Now each config value is parsed according to the specified type, and only successfully parsed values are included in the output. This changes behavior for users who were unknowingly using `--type` with `list` before, but the impact is likely minimal since the option wasn't doing anything previously.

The implementation introduces a new `display_options_init_list()` helper to properly initialize output formatting for list mode, and modifies `show_all_config()` to use the `format_config()` function with gentle parsing enabled. The patch includes extensive test suite updates that document both the new behavior and some remaining edge cases (particularly around path handling) that will be addressed in later patches.

This is a well-structured change that builds on the preparatory refactoring from earlier patches in the series. The commit message clearly explains the behavior change and rationale, and the test coverage is thorough. The patch moves the series closer to its goal of improving performance for type-filtered config operations.
