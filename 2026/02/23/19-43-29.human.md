Feature patch adding path reporting to `git repo info`, part of a series to provide structured repository metadata access.

This is the second patch in a 5-part series that enhances the experimental `git repo info` command with comprehensive path reporting functionality. The patch introduces 13 new `path.*` fields that expose common repository locations (worktree, gitdir, objects, refs, etc.) through a structured interface, replacing the need for multiple `git rev-parse` calls in scripts.

The implementation follows the series' pattern of using a `struct repo_info` to avoid global state, with each path being resolved through dedicated helper functions. The paths are added to the existing field lookup system alongside layout and object format fields from earlier patches. The implementation handles both absolute and relative paths (controlled by a new `--path-format` option introduced in the series).

The patch appears well-constructed with thorough coverage of key repository paths and proper memory management via `strbuf`. It fits cleanly into the series' goal of providing programmatic access to repository metadata while removing reliance on global state. The changes are focused and maintainable, with each path getting its own clearly named function. This continues the series' trend of high-quality, well-documented additions to the repository introspection toolkit.
