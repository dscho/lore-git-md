This is the first patch in a four-part bugfix series from Patrick Steinhardt addressing pack validation issues with large objects. The series was prompted by a bug found by brian m. carlson where `git fsck` could enter an infinite loop when verifying large objects across multiple packfiles.

This particular patch improves the `test-tool genrandom` helper by adding proper argument parsing with `git_parse_ulong()`, which provides better error handling and support for size suffixes (k/m/g). The change makes test scripts more readable by allowing them to specify sizes like "10k" or "1m" rather than raw byte counts. The patch updates several test scripts to use the new syntax.

The change is straightforward and well-contained, touching only test infrastructure. It's a clear improvement that makes test suite maintenance easier. The patch has already been reviewed by Jeff King, who confirmed its technical soundness, and incorporates feedback from Eric Sunshine about error message wording. This is a solid foundation for the more substantial fixes that follow in the series.
