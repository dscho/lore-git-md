This is part 2/5 of Justin Tobler's series adding repository statistics to `git repo`. The patch focuses on tracking the largest objects in a repository by type (commits, trees, blobs, tags).

The change adds new functionality to record both the size and OID of the largest object encountered for each type during repository traversal. This helps users spot unusually large objects that may be contributing significantly to repository size. The information is displayed in the table output format and included in key-value output.

Key technical aspects:
- Introduces `struct largest_objects` to track max sizes and OIDs per object type
- Adds `check_largest()` helper to update tracking when larger objects are found
- Updates table and key-value output formats to show the new statistics
- Includes test cases verifying the output formats and edge cases

The implementation is clean and well-tested, with clear documentation updates. This builds on the series' goal of providing actionable repository statistics while maintaining the existing output formats. The patch is part of an ongoing refinement based on feedback from Junio Hamano and Patrick Steinhardt.
