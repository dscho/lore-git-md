This is a documentation/style compliance patch series for `git cat-file` error messages, now split into two parts based on Junio Hamano's feedback. The first patch standardizes the "Not a valid object name" message across multiple files, while the second addresses remaining message formatting in `cat-file.c`.

The author has done significant research into potential downstream impacts, finding that many major projects (Gitea, Gogs, GitLab Gitaly, IntelliJ) do case-sensitive matching on the current capitalized error message format. This creates a compatibility concern that wasn't apparent in the initial patch. The second patch's changes to less commonly parsed messages ("Cannot read object" and promisor remotes warning) appear safer.

Key technical details:
- Patch [1/2] modifies "Not a valid object name" in 6 files (cat-file.c, describe.c, ls-tree.c, merge-base.c, read-tree.c, unpack-file.c) and their tests
- Patch [2/2] changes "Cannot read object" and promisor remotes warning in cat-file.c
- Test updates required in t1006-cat-file.sh and t8007-cat-file-textconv.sh

The thread now faces a decision point about whether to proceed with the more disruptive first patch given the ecosystem impact, or limit changes to the lower-risk second patch. Junio's initial review was positive about the mechanical changes but raised these exact compatibility concerns that the author's research has now quantified.
