This is a bugfix addressing zombie processes when Git runs as PID 1 in containers. The patch targets an edge case where Git processes spawned during network operations (like git-remote-https or ssh) become zombies when the parent Git process exits abnormally (via exit(128)) on transport errors.

The core issue occurs because the normal cleanup paths (disconnect_helper, finish_connect) are bypassed during abnormal exits, and PID 1 processes have no parent to reap their children. The solution adds atexit handlers in transport-helper.c and connect.c to ensure child processes are reaped regardless of exit path, while maintaining the existing cleanup behavior for normal exits.

The patch appears well-motivated with a clear explanation of the container-specific edge case and includes a link to a detailed blog post documenting the investigation. The changes are focused on two key files (connect.c and transport-helper.c) with straightforward atexit handler additions. This looks like a targeted fix for a real-world containerization pain point.
