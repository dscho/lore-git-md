This is a documentation patch thread that has reached a conclusion. The original proposal sought to document special date keywords ("now", "yesterday", etc.) for `git commit --date`, but maintainer Junio C Hamano has clarified these were intentionally undocumented as "easter eggs" rather than formal features. The author, Md Ferdous Alam, has accepted this reasoning and withdrawn the patch.

The thread reveals an interesting policy question about what constitutes a supported feature versus an implementation detail. Junio notes that while these keywords work, they serve more as curiosities than practical tools (with "now" being the partial exception). He also points out the inconsistency of documenting some informal features while omitting others like "7.days.ago".

For future reference, this establishes that Git's date parsing intentionally maintains undocumented conveniences alongside its formal date formats. The discussion suggests the project prefers to keep the distinction between documented, supported functionality and undocumented parser quirks clear, even when those quirks are long-standing and reliably implemented.
