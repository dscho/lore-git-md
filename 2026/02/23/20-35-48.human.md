This is the final patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch fixes an infinite loop in `git fsck` that could occur when verifying large objects that exist in multiple packfiles, originally reported by brian m. carlson.

The root cause was that `fsck` would use `odb_read_object_stream()` to verify large objects (those above core.bigFileThreshold), which could trigger MRU list updates and cause infinite iteration. The same object existing in multiple packs (one corrupt, one valid) would exacerbate the issue. The fix replaces this with direct packfile access via `packfile_read_object_stream()`, ensuring we verify the specific object in the pack we're checking.

The patch includes a new test case that creates two large blobs in separate packs and verifies `fsck` can handle this case without hanging. Junio Hamano notes the fix is sound and expresses surprise that this fragility wasn't exposed more often. The series has gone through multiple iterations with thorough review from Jeff King and Eric Sunshine, and appears ready for merging.

This completes a robust solution to a subtle but serious verification issue, particularly important for repositories with large binary assets stored across multiple packs. The changes maintain backward compatibility while preventing hangs during repository verification.
