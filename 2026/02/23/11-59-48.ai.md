This is patch 14/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces, now removing the specialized `refs_for_each_glob_ref_in()` function in favor of the new unified `refs_for_each_ref_ext()` API.

The patch converts all callers of `refs_for_each_glob_ref_in()` to use the new interface, which handles glob patterns through the `pattern` field in `struct refs_for_each_ref_options`. Key conversions include:

- Bisect operations that count good/bad refs under `refs/bisect/`
- `rev-parse`'s ref listing functionality
- Revision walk setup for branches, tags and remotes with glob patterns

Each conversion follows the same pattern: initialize an options struct with the glob pattern and prefix, then call the unified iterator. The patch demonstrates the API's flexibility by handling both simple glob matches (like counting bisect refs) and more complex cases (like revision walking with multiple prefix patterns).

The removal of `refs_for_each_glob_ref_in()` from refs.c and refs.h completes the deprecation of this specialized function, continuing the series' goal of reducing API surface area while maintaining identical behavior. Performance-critical glob matching was already optimized in patch 7/17 of this series, so these conversions inherit that benefit.

With Karthik Nayak's review approval on the full series, this patch represents another step toward the unified ref iteration API that will simplify future ref-related development.
