This is a refactoring patch in Vaidas Pilkauskas's strbuf_attach fixes series (v5 2/4). It corrects several call sites that were passing alloc == len to strbuf_attach(), which violates the function's requirement that alloc must be at least len+1 to accommodate the NUL terminator. The patch updates five call sites across mailinfo, am, refs/files-backend, fast-import, and trailer subsystems to properly account for the terminator.

The changes are straightforward mechanical fixes - each instance simply adds +1 to the alloc parameter when the buffer is known to be NUL-terminated. This builds on prior discussion where Junio Hamano noted strbuf_attach's space optimization provides measurable performance benefits, so the approach preserves the optimization while fixing the allocation size.

This is part of a larger effort to audit and correct strbuf_attach usage throughout the codebase. The patch series has gone through multiple iterations with review feedback incorporated. The changes are narrow in scope and unlikely to be controversial, focusing purely on fixing allocation sizes without changing behavior.
