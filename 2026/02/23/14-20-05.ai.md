Feature: HTTP 429 rate limit retry support in Git's HTTP client

This final patch in Vaidas Pilkauskas's series adds comprehensive support for handling HTTP 429 (Too Many Requests) responses with automatic retries. The implementation supports both delay-seconds and HTTP-date formats for the Retry-After header, with configurable limits via http.maxRetries, http.retryAfter, and http.maxRetryTime settings. The patch includes extensive test coverage through new test scripts that verify various scenarios including header parsing, configuration combinations, and edge cases.

Key technical details include:
- New HTTP_RATE_LIMITED result code (7) added to http.h
- Retry-After header parsing works on both modern curl (using CURLINFO_RETRY_AFTER) and older versions (manual parsing)
- Fail-fast behavior when delays exceed http.maxRetryTime
- Trace2 integration for monitoring retry attempts and delays
- Environment variable overrides (GIT_HTTP_*) for all config options
- New test infrastructure in t/lib-httpd/http-429.sh that simulates rate-limited responses

The implementation takes a conservative approach to retries, defaulting to no retries (http.maxRetries=0) unless explicitly configured. This matches Git's general philosophy of failing fast rather than waiting indefinitely. The test suite thoroughly exercises the retry logic with various header formats, configuration combinations, and edge cases.

This patch builds on feedback from Jeff King and Taylor Blau through multiple iterations, with the final version incorporating Taylor's suggestion for consistent error handling. The changes affect remote-curl.c, http.c, and add new test infrastructure, completing the HTTP rate limiting support that was proposed in the earlier patches of this series.
