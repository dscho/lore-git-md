This is patch 9/13 in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. The series refactors config parsing to enable type filtering during initial parsing rather than after, improving efficiency particularly for path-type values.

This specific patch moves expiry date handling into its own helper function `format_config_expiry_date()`, similar to the pattern established in previous patches for other types. The key changes are:

1. Extracts expiry date formatting logic from the main `format_config()` function into a dedicated helper
2. Implements quiet parsing for expiry dates when requested, matching the series' approach for other types
3. Updates tests to reflect that invalid dates are quietly skipped rather than producing error messages

The patch notes an asymmetry in Git's expiry date parsing - unlike most config parsers, `git_config_expiry_date()` shows errors but doesn't die on bad input. The implementation works around this by treating positive returns from `parse_expiry_date()` as errors during quiet parsing.

This continues the series' consistent pattern of:
- Moving type-specific handling to dedicated functions
- Supporting gentle/quiet parsing modes
- Maintaining existing behavior while improving performance
- Adding test coverage

The change is well-contained and follows the established pattern from previous patches in the series. With this patch, the series now has type-specific handling implemented for integers, booleans, bool-or-int, bool-or-str, paths, and expiry dates.
