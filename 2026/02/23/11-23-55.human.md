This is a discussion about evolving the interface design for the `git replay` command's revert functionality, which is currently implemented as a flag-based approach (`--revert` mode). Toon Claes and Christian Couder are exploring whether to restructure it as subcommands (`revert`, `pick`, `rebase`) instead.

Christian agrees with the subcommand direction but suggests deferring the change until after the current `--revert` implementation merges. He questions the need for the `--base=<branch>` parameter, proposing direct positional arguments instead. Toon responds with a more detailed subcommand proposal that distinguishes between `--ref` (for branch targets) and `--onto` (for commit targets), addressing a limitation where `git-replay` currently can't operate on bare commit IDs.

The exchange reveals competing interface philosophies: flag-based grouping versus explicit subcommand separation. While the technical implementation is sound (as seen in previous patch versions), the interface design remains an open question. Toon's latest proposal attempts to unify the approaches while solving additional use cases, but consensus on timing and specifics is still forming. The discussion remains constructive, with both contributors working toward a design that balances immediate needs with long-term usability.
