This is patch 3/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces, which has already received overall approval from primary reviewer Karthik Nayak. The series aims to consolidate 14 specialized ref iteration functions into a single `refs_for_each_ref_ext()` interface.

The current patch is a mechanical refactoring that moves the `do_for_each_ref_flags` enum definition earlier in refs.h to prepare for its use by additional functions in subsequent patches. The enum defines four flags that control ref iteration behavior (including broken refs, worktree refs, dangling symrefs, and root refs). The change is straightforward - it relocates the enum while preserving all its documentation and values exactly.

This is part of the broader ref backend modernization effort that Patrick has been leading. The patch series has already addressed documentation improvements and performance optimizations (notably a 100x speedup for glob pattern matching), with only minor open questions remaining about prefix handling details. This particular patch appears uncontroversial and well-positioned in the series, following Oswald Buddenhagen's suggested ordering.
