This is a documentation and behavior cleanup patch in Kristoffer Haugsbakk's series about the `format.noprefix` configuration. The patch finalizes the transition to treating `format.noprefix` as a proper boolean value, rejecting non-boolean inputs with clear error messages.

The discussion with Junio C Hamano has settled on making the error message more explicit about the behavioral change - it accepted any value before (treating all as true), but now strictly requires boolean values. Junio also suggested using direct `advise()` calls rather than the configurable `advise_if_enabled()` since configuration corrections should always show these messages.

Kristoffer agrees with both points and notes this approach aligns with how `core.commentString` was handled during its transition. The change is technically breaking for any non-boolean values, but since the only meaningful use was to enable the feature (by setting any value), the impact should be minimal. The improved error messaging will help users transition their configurations.

This patch follows Jeff King's earlier approval of the direction, where he noted this aligns with the documented boolean nature of the setting. The series is now complete with all feedback incorporated, and the changes are expected to be merged.
