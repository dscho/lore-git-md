Refactoring patch in Patrick Steinhardt's ref iteration API unification series.

This is the first patch in a 17-part series that aims to simplify Git's ref iteration API by replacing 14 specialized `refs_for_each_*` functions with a single configurable interface. The patch moves `refs_head_ref_namespaced()` to be grouped with `refs_head_ref()` rather than with the for-each functions, since it operates on a single ref (HEAD) rather than iterating multiple refs.

Karthik Nayak provides minor review feedback, suggesting two wording clarifications in the commit message. The changes are purely mechanical - relocating the function declaration in refs.h to better reflect its logical grouping. This is a preparatory patch that doesn't yet modify behavior, just reorganizes the code to make the subsequent API unification cleaner.

The patch touches the refs.h header file, moving the declaration of `refs_head_ref_namespaced()` from near other iteration functions to be adjacent to its related single-ref function `refs_head_ref()`. This change is uncontroversial and aligns with the series' goal of making the ref iteration API more consistent and maintainable.
