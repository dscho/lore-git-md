Bugfix addressing zombie processes when Git runs as PID 1 in containers. The patch targets abnormal exit paths in network operations (git-remote-https, ssh) where transport errors cause exit(128) before normal cleanup can reap child processes.

The solution introduces atexit handlers in transport-helper.c and connect.c to ensure child processes are reaped regardless of exit path, while maintaining existing cleanup for normal exits. The changes are focused and well-explained, with clear comments linking the new handlers to the container-specific issue. The patch touches two key files (connect.c and transport-helper.c) with symmetric changes to handle both transport helper and direct connection cases.

This appears to be a well-motivated fix for a real-world deployment pain point in containerized environments. The author has clearly identified the specific edge case (Git as PID 1) and provided a targeted solution. The patch is marked RFC but looks production-ready - the atexit approach seems appropriate given the abnormal exit scenario being addressed. No test is included, which might be worth discussing given the potential impact on process handling behavior.
