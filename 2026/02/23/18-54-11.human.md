This is a documentation/style compliance patch series for `git cat-file` error messages, now split into two parts based on Junio Hamano's feedback. The first patch standardizes the "Not a valid object name" message across multiple files, while the second handles remaining message formatting in `cat-file.c`.

The author has done significant research into potential downstream breakage, finding that many popular tools (Gitea, Gogs, GitLab's Gitaly, IntelliJ) do case-sensitive matching on the current capitalized error message format. This raises compatibility concerns, as changing these messages could silently break error detection in these projects.

The second patch, which addresses less commonly parsed messages ("Cannot read object" and promisor remotes warning), appears safer to proceed with. The author is now seeking guidance on whether to:
1. Proceed with both patches despite compatibility risks
2. Only apply the safer second patch
3. Consider an alternative approach

This demonstrates careful consideration of both Git's style guidelines and real-world ecosystem impacts - a good example of how even seemingly simple documentation changes can have wide-ranging consequences in a widely-used tool like Git.
