The thread discusses a bug in `git for-each-repo` when used from worktree contexts. Matthew Gabeler-Lee reports that scripts using this command fail when run from worktrees, though they work fine from the main repository. Through investigation with strace, they identified that `for-each-repo` incorrectly inherits and propagates the `GIT_DIR` environment variable, causing child Git commands to execute in the wrong repository context.

The issue occurs because the command passes along the worktree's parent repository's `GIT_DIR` to child processes, making them operate on the wrong repository. For example, running `git for-each-repo --config=foo.bar -- branch` from a worktree effectively executes as `GIT_DIR=/worktree-parent/.git git -C /unrelated-repo branch`. The reporter notes this appears to be an unfixed issue in current master, as they found no recent changes addressing it. The detailed report provides enough technical context for someone familiar with Git's worktree and environment handling to develop a fix.
