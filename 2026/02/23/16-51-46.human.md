Bugfix addressing zombie processes when Git runs as PID 1 in containers. Andrew Au identifies a scenario where Git processes spawned during network operations (like git-remote-https or ssh) become zombies when Git exits abnormally (e.g., on transport errors) while running as the init process in a container. Since PID 1 has no parent to clean up its children, these zombies persist indefinitely.

The patch adds atexit handlers in transport-helper.c and connect.c to ensure child processes are reaped even when Git exits via error paths that bypass normal cleanup routines. The author provides a detailed blog post explaining the investigation and solution.

This appears to be a well-motivated fix for a real issue in containerized environments. The patch is small, focused, and comes with clear explanation of both the problem and solution. The changes are limited to two files and follow the pattern of existing cleanup code. This seems like a straightforward improvement that should be uncontroversial.
