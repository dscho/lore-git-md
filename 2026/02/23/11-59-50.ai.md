This is part 16/17 of Patrick Steinhardt's series to unify Git's ref iteration interfaces, now removing the specialized `refs_for_each_namespaced_ref()` function in favor of the new unified `refs_for_each_ref_ext()` API.

The patch converts the remaining callers in `http-backend.c` and `upload-pack.c` to use the new interface with a `namespace` field in the options struct, while removing the now-obsolete implementation and declaration from `refs.c` and `refs.h`. The behavior remains identical - the namespace handling and optional exclude patterns are now configured through the options struct rather than separate parameters.

Key technical details:
- Maintains the same hidden ref filtering in upload-pack by translating the exclude patterns to the new options struct
- Preserves the namespace prefixing behavior for both HTTP ref advertisement and upload-pack's ref enumeration
- Completes the elimination of another specialized ref iteration function, leaving only `refs_for_each_replace_ref()` as the remaining outlier
- Demonstrates the flexibility of the new API to handle both simple namespace cases (http-backend) and more complex filtering (upload-pack)

The change is straightforward and builds on the extensive groundwork laid in earlier patches, with Karthik Nayak having already approved the overall approach. This represents one of the final steps in consolidating Git's ref iteration API surface.
