Here's a human-readable summary of the thread:

Christian Couder has proposed a new feature for `git fast-import` that would allow it to automatically re-sign commits with invalid signatures during import, using the current user's signing key. This provides a middle ground between the existing options of either preserving invalid signatures or stripping them entirely. The initial patch series consists of two parts - first a cleanup removing an obsolete function declaration, followed by the main implementation adding the new `re-sign-if-invalid` mode.

Justin Tobler has now sent the second patch implementing the core functionality. The changes add proper support for GPG, X.509 and SSH signatures with comprehensive test coverage. One open question remains about whether the implementation should respect `extensions.compatObjectFormat` when regenerating signatures - currently it only uses the repository's primary hash algorithm. The author has left this as a potential future improvement for now.

This builds on Christian's previous work on signature handling in fast-import, particularly the ability to strip invalid signatures. The changes are focused on the fast-import/fast-export code paths and gpg-interface plumbing, with thorough test coverage for the new functionality.
