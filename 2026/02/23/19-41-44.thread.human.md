The `git fast-import` signature handling series has now been successfully merged after multiple rounds of review and refinement. This work, building on earlier contributions from Christian Couder and Justin Tobler, introduces a new `sign-if-invalid` mode that complements the existing `strip-if-invalid` option. The implementation consolidates signing logic into a reusable `sign_buffer()` API while maintaining a clear distinction between creating new signatures and re-signing invalid ones.

Key reviewers played crucial roles in shaping the final version: Jeff King caught an incorrect test branch reference, while Patrick Steinhardt approved the clarified warning messages about signature replacement (not creation). The series now includes comprehensive test coverage for OpenPGP, X.509, and SSH signature scenarios. The syntax for the new mode intentionally matches `git commit --gpg-sign` for consistency, while explicitly limiting re-signing to previously-signed-but-invalid commits.

The successful conclusion of this effort demonstrates Git's collaborative development model, where features evolve through careful review rounds with domain experts providing key improvements. While this series is now merged, future work could extend the functionality to unsigned objects or tags, which remain as separate potential follow-up efforts.
