This thread introduces a new `re-sign-if-invalid` mode for `git fast-import`, allowing commits with invalid signatures to be re-signed during import rather than just preserved or stripped. Christian Couder kicked off the series with a cleanup patch removing an obsolete function, followed by Justin Tobler's implementation of the new mode.

The feature has drawn detailed review from Patrick Steinhardt and Christian (who maintains the fast-import/fast-export code). The current version handles GPG/X.509/SSH signatures but doesn't yet respect `extensions.compatObjectFormat` when regenerating signatures - a limitation reviewers agree should be documented. Patrick also suggested improving warning messages and potentially allowing key specification (like git-commit's --gpg-sign), which Justin plans to address in the next version.

The technical approach has consensus, with Christian approving the direction while suggesting minor doc fixes (like correcting "valid commits" to "valid commit signatures"). The series appears ready to progress after addressing the remaining documentation and warning message polish. This fills a clear gap between the existing preserve/strip options for handling invalid signatures during import.
