This thread discusses a new feature for `git fast-import` that would allow re-signing commits with invalid signatures during import, using the user's current signing key. The two-patch series comes from Christian Couder (who contributed a cleanup patch) and Justin Tobler (who implemented the core feature). 

The feature adds a `re-sign-if-invalid` mode to `--signed-commits`, providing a middle ground between the existing options to either keep or strip invalid signatures. The implementation touches fast-import/fast-export code and gpg-interface plumbing, with tests covering GPG, X.509 and SSH signatures. Patrick Steinhardt has reviewed the series and acknowledged the cleanup patch, while raising several technical points about the implementation.

Christian Couder has now replied to Justin's submission, agreeing with the decision to defer handling of `extensions.compatObjectFormat` (which affects signature regeneration for repositories using alternative hash algorithms) and providing minor documentation fixes. The remaining open questions include whether to show warnings when re-signing occurs and whether to allow specifying which key to use for re-signing. The series appears to be converging, with the main technical concerns addressed and only minor documentation tweaks remaining.
