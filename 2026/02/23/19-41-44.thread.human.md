This thread documents the evolution of `git fast-import`'s signature handling capabilities, culminating in a v5 series that enables re-signing commits with invalid signatures. The work builds on Christian Couder and Justin Tobler's earlier v2 series (already merged) which first introduced signature verification and stripping capabilities.

The current focus is implementing `sign-if-invalid[=<keyid>]` mode, which verifies commits and replaces invalid signatures while preserving valid ones. The implementation shares infrastructure with the existing `strip-if-invalid` mode but adds signing capability through a consolidated `sign_buffer()` function. Key technical improvements include proper handling of OpenPGP/X.509/SSH signatures, comprehensive test coverage, and clear separation between signature creation and stripping concerns.

Junio C Hamano has suggested natural extension points for future work, including signing unsigned objects via a new `--sign-commits=all` option. Justin Tobler and Patrick Steinhardt have collaborated on refining the implementation, with Steinhardt successfully proposing the consolidated signing function approach. The series appears ready for merging, with only minor warning message cleanup remaining for a follow-up patch. Future directions may include tag signature support and handling of unsigned commits during history rewriting.
