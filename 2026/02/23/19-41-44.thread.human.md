This thread covers a three-patch series that enhances `git fast-import` to support re-signing commits with invalid signatures during import operations. The original work was proposed by Christian Couder, with implementation by Justin Tobler. The series has gone through two versions and has now been merged, with some post-merge refinements.

The core addition is a new `re-sign-if-invalid[=<keyid>]` mode that allows `git fast-import` to re-sign commits when their original signatures are invalid, matching the syntax used by `git commit --gpg-sign`. The implementation involved refactoring signing logic into gpg-interface.c and adding comprehensive test coverage for various signature types (OpenPGP, X.509, SSH).

Christian Couder contributed a cleanup patch removing an obsolete function declaration that was missed when `sign_with_header()` was previously removed. This final housekeeping change ensures the header files accurately reflect available interfaces. The series received thorough review from Patrick Steinhardt and others, with all feedback addressed across the two versions. Junio Hamano merged the changes with no objections.

Some future work remains open, including adding similar support for tag signatures and addressing interoperability cases. The changes were implemented conservatively as an experimental feature, with explicit failure modes where needed. The series builds on existing signature handling infrastructure and follows Git's standard patterns for moving shared functionality to common locations.
