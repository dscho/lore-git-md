This is a bugfix series from Patrick Steinhardt addressing an issue in pack validation for large objects. The four-patch series improves test infrastructure, refactors object streaming code, and ultimately fixes an infinite loop in `git fsck` when verifying large objects across multiple packfiles.

The series has already gone through one round of review with Jeff King, who confirmed the technical approach while suggesting improvements to test coverage and error handling. Patrick has incorporated this feedback in v2, including better test cases that verify corruption detection when the same object exists in both corrupted and valid forms across different packs. The changes span several core files (`pack-check.c`, `packfile.c`, `object.c`) with test updates in `t1450-fsck.sh` and `t1050-large.sh`.

The key fix replaces `odb_read_object_stream()` with direct packfile access in `pack-check.c`, preventing MRU-triggered infinite loops. The discussion revealed careful consideration of edge cases in the packfile streaming path, though some gaps in zlib error detection remain as known limitations. The series appears well-tested and ready for merging after this final round of review.
