This is a review response from Jeff King (Peff) on Patrick Steinhardt's patch to refactor packfile object streaming as part of a bugfix series addressing fsck issues with large objects.

Peff generally approves the approach to extract `packfile_read_object_stream()` from `packfile_store_read_object_stream()`, noting it makes sense for the planned changes. He identifies two subtle points:

1. The refactored version drops some redundant delta checks, which is fine since the streaming code already rejects deltas later. The new flow is actually slightly more efficient.

2. There's a potential (but pre-existing) issue where broken objects might not get marked as "bad" when streaming, since the refactored code skips the object info check that could detect corruption. Peff notes this isn't materially worse than before and can be addressed separately.

The review is technical but positive, with Peff working through the implications of the interface change. This patch is the third in a series where the first two established test coverage and preparatory refactoring, with the final patch expected to use this new function to fix the core infinite loop issue. Peff's feedback suggests the series is on track with only minor concerns about error handling edge cases.
