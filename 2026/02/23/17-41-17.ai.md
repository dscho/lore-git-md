This is part 2/5 of Justin Tobler's series to add repository statistics to `git repo`, focusing on tracking the largest objects by type (commits, trees, blobs, tags). The patch introduces infrastructure to record and display maximum object sizes alongside their OIDs, addressing a gap where the existing statistics only showed aggregate sizes.

The key technical additions are:
- A new `largest_objects` struct tracking the biggest object seen for each type (commit, tree, blob, tag) by size and OID
- `check_largest()` helper to update these records during object iteration
- Integration with the existing table and key-value output formats
- Test coverage verifying the new statistics appear correctly in all output formats

The implementation handles both SHA-1 and SHA-256 repositories through OID abstraction. The table output shows sizes only (with OID annotations coming in a later patch), while the key-value format includes both size and OID for each maximum. Empty repository edge cases are handled by initializing all sizes to zero.

This builds on the v2 1/5 refactoring that changed the counting logic to process objects individually rather than in batches, enabling per-object statistics collection. The patch maintains a clean separation between the statistics gathering and presentation layers, with the new maximum-size tracking fitting naturally into the existing output framework.
