This is part of Vaidas Pilkauskas's v5 series adding HTTP 429 rate limit retry support to Git's HTTP client. The patch introduces a new helper function `show_http_message_fatal()` in remote-curl.c that combines the common pattern of showing HTTP error messages followed by terminating with an error. 

The new helper centralizes error handling for HTTP responses by:
1. Displaying server error messages (filtering for text/plain content)
2. Calling die() with the provided error message
3. Including NORETURN annotation for compiler optimization

The patch refactors four existing error cases in remote-curl.c to use this helper, reducing code duplication. The changes are mechanical - the behavior remains identical, just more maintainable. This refactoring prepares for upcoming HTTP 429 rate limiting support by establishing a consistent error handling pattern.

The implementation follows Taylor Blau's suggestion and maintains all existing functionality while making the code more robust. The patch is well-contained, touching only remote-curl.c, and includes thorough error handling for the strbuf parameters. This is a clean preparatory change that improves the codebase without introducing new behavior.
