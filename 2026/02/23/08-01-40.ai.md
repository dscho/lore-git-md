This is part of the ongoing ref backend abstraction effort, specifically enabling reference storage location configuration via URI syntax in the `extensions.refStorage` config. The patch is the 5/6 in an approved v8 series that's ready for integration into the 'next' branch.

The patch extends the `extensions.refStorage` config to support URI syntax (`<format>://<payload>`) for specifying both the backend format and storage location. For files and reftable backends, the payload is a filesystem path where references will be stored (defaulting to the commondir if unspecified). The implementation handles worktree references by storing them in the alternate location while maintaining Git directory recognition through stub files.

Key technical changes include:
- URI parsing infrastructure in `setup.c` to separate format from payload
- Propagation of the payload to backends via `repo->ref_storage_payload`
- Worktree reference location resolution in `builtin/worktree.c`
- Comprehensive test coverage in `t1423-ref-backend.sh` for various URI formats and worktree scenarios

The patch includes a TODO noting the current limitation where worktree handling is done via paths rather than `struct worktree*` due to repository initialization ordering constraints. Review feedback from Patrick Steinhardt and others has been incorporated, with maintainer approval secured. The series represents the final state of the reference backend selection implementation for zero-downtime migrations between backends.
