This is the first patch in a 9-part series introducing enhanced repository information reporting to `git repo`. The series is part of a broader effort to improve repository introspection capabilities, with some overlap with Justin Tobler's parallel work on repository structure reporting.

The patch introduces a `repo_info` context struct to encapsulate repository state, removing direct coupling to global variables. It also adds category-based key expansion, allowing users to query groups of related fields (like "layout.*") rather than specifying individual keys. The implementation includes:

- A new `struct repo_info` to pass repository context
- Refactored value-getter functions to use this context
- Category expansion that automatically includes all matching keys (e.g. "layout" expands to all "layout.*" fields)
- Maintained backward compatibility with explicit key queries

The changes are well-contained to `builtin/repo.c` and include comprehensive updates to handle the new category syntax while preserving existing behavior. This appears to be a solid foundation for the rest of the series, which will build on this infrastructure to add more repository metrics and reporting options.

The patch follows good practices by:
- Keeping changes focused and mechanical
- Maintaining backward compatibility
- Using the new context struct to support future `the_repository` removal
- Including clear error messages for unknown keys/categories

This looks like a clean technical start to the series, though coordination with Justin Tobler's overlapping work on repository structure reporting will likely be addressed in later patches or follow-up discussion.
