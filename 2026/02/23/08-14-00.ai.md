This is part of Patrick Steinhardt's ongoing ref iteration API unification series (v1, 17 patches). Patch 6/17 introduces the core `refs_for_each_ref_ext()` function and accompanying options struct that will replace the existing proliferation of specialized ref iteration functions.

The patch exposes the internal `do_for_each_ref()` as a public API with a structured options approach rather than individual parameters. All existing iteration functions (`refs_for_each_ref()`, `refs_for_each_ref_in()`, etc.) are rewritten to use this new interface while maintaining identical behavior. The options struct centralizes control over prefix matching, exclusion patterns, trimming behavior, and special flags.

Karthik Nayak's review confirms the mechanical correctness of the conversion and notes the improved readability from renaming `fn` to `cb`. The changes are systematic and thorough, touching ref iteration calls throughout the codebase including in the ref storage migration path. This establishes the foundation for subsequent patches to remove the now-redundant specialized iteration functions.

The patch demonstrates careful attention to maintaining backward compatibility during the transition, with all existing callers updated to use the new interface while preserving their exact current behavior. This is a key step in the larger effort to simplify Git's ref iteration API surface.
