Refactoring patch in Derrick Stolee's performance improvement series for `git config list --type=<X>` filtering. This is patch 12/13 in the v3 series, which restructures the `format_config()` function to use a switch statement instead of nested if/else conditions. The change improves readability by:

1. Replacing the chain of if/else conditions with a cleaner switch statement that dispatches to the appropriate type-specific formatting function (all of which were introduced in previous patches)
2. Adding a `TYPE_NONE` case (value 0) to handle untyped config values
3. Using a `goto terminator` to reduce nesting depth when skipping values
4. Adding a `BUG()` check for undefined types as a defensive programming measure

The patch maintains all existing functionality while making the control flow more straightforward. This comes after the series has already established the type-specific handlers in patches 4-11 (for int, bool, bool-or-int, bool-or-str, path, expiry date, and color values). The change is purely structural - there are no behavior changes or performance implications beyond potential micro-optimizations from the compiler being able to better optimize the switch statement.
