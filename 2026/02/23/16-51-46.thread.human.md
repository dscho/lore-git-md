This thread addresses zombie process cleanup in containerized Git operations, particularly when network operations like git-remote-https or ssh exit abnormally. The discussion initially considered whether Git should handle being PID 1 (with brian m. carlson recommending the tini init system), but Andrew Au's v3 patch has shifted focus to general correctness by leveraging Git's existing `clean_on_exit` mechanism in `run-command` rather than introducing new atexit handlers.

The technical solution, now approved by Jeff King (Peff), specifically targets child processes in `connect.c` and `transport-helper.c` using a SIGTERM-then-wait pattern to avoid deadlocks. While the patch has reached consensus on its narrow scope for network operations, broader questions remain about the boundary between Git's responsibilities and those of service/init systems, as well as whether other child processes (like hooks or filters) might need similar handling.

In the latest email, Peff provided non-technical feedback about patch formatting, noting that AI attribution (from tools like Copilot) should follow standard trailer conventions without blank lines and shouldn't include the AI's email in CC headers. This doesn't affect the technical merits of the solution, which remains sound.
