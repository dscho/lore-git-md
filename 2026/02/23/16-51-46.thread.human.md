This thread addresses a subtle but impactful issue where Git processes can leave behind zombie children when running as PID 1 in containers, particularly during abnormal exits from network operations. Andrew Au's v2 patch introduced atexit handlers to ensure child processes are reaped regardless of exit path, with demonstrated real-world impact in containerized monitoring systems where thousands of zombies could accumulate.

Jeff King (Peff) has now raised an important technical concern about the implementation: the current approach of waiting directly in the atexit handler could deadlock if the child is waiting for the parent. He suggests modifying the solution to use Git's existing `clean_on_exit` mechanism, which would kill the child before waiting, avoiding this risk. Peff also questions whether child cleanup should be the default behavior in Git's subprocess handling, given that most children shouldn't outlive their parent.

The core problem and solution direction remain valid, but the implementation needs adjustment to handle this edge case. Andrew will likely need to send a v3 incorporating Peff's feedback about using kill-then-wait rather than direct waiting in the cleanup handlers. The discussion has moved from establishing the problem's reality to refining the technical details of the fix.
