This thread addresses a bug where Git running as PID 1 in containers would leave zombie processes when network operations (git-remote-https, ssh) exited abnormally. Andrew Au proposed adding atexit handlers to ensure child processes are properly reaped regardless of exit path, with the initial version prompting a minor contributor identity correction.

The v2 patch maintains the same technical approach - adding symmetric cleanup handlers in transport-helper.c and connect.c - while fixing the email consistency issue from v1. The changes introduce tracking variables (conn_to_reap, helper_to_reap) and corresponding atexit handlers that activate during abnormal exits but avoid double-waiting during normal operation. The implementation is focused and well-commented, specifically targeting the container deployment scenario where this issue manifests.

The thread has seen limited technical discussion so far, with Kristoffer Haugsbakk's initial note about contributor identity being the only feedback addressed between versions. The patch appears ready for review, though the absence of a test case may warrant discussion if reviewers consider it important for regression prevention. The changes are contained to two files with clear linkage between the new handlers and the container-specific problem being solved.
