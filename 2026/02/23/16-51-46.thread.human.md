This thread addressed a specific issue with zombie processes in containerized environments, where network helper processes (git-remote-https, ssh) would remain as zombies after abnormal Git exits. Andrew Au proposed a solution through a patch series that reached version 4, implementing proper cleanup via Git's existing `run-command` infrastructure.

The technical approach - using `clean_on_exit` and `wait_after_clean` flags in `connect.c` and `transport-helper.c` - received approval from Jeff King (Peff), who confirmed its safety and deadlock avoidance. The solution is narrowly scoped to network operations, deliberately avoiding broader process management changes. brian m. carlson's suggestion to use tini init for PID 1 was acknowledged but considered out of scope for this fix.

Junio C Hamano provided the final approval after documentation issues in v3 (trailer formatting and removal of Copilot AI attribution) were addressed in v4. The patch is now queued for merging, representing a minimal but effective 6-line change that builds on existing commit afe19ff7b5. This solution will prevent the accumulation of thousands of zombie processes in container deployments during transport operations, concluding the thread with all technical and documentation concerns resolved.
