This is patch 4/5 in Justin Tobler's v2 series for repository statistics in `git repo`, adding tracking of commits with the most parents. The patch builds on the existing infrastructure for tracking largest objects by type, now extending it to identify merge commits with unusually high parent counts.

The key technical changes include:
- Adding a `parent_count` field to `struct largest_objects` to track maximum parent count
- Introducing `stats_table_object_count_addf()` for formatted count output in tables
- Parsing commit objects during iteration to access parent information
- Updating the key-value and table output formats to include parent count metrics
- Adjusting test expectations to account for the new parent count field

The implementation handles edge cases like NULL OIDs and maintains the existing annotation system for OID references in table output. Test coverage in t1901 verifies the new functionality works with both empty repositories and populated test cases.

This continues the series' focus on identifying repository anomalies through statistical analysis, though it notably avoids tracking octopus merges specifically after Junio Hamano's objections in earlier rounds. The changes are well-contained within the established architecture and maintain consistent output formatting with the rest of the statistics.
