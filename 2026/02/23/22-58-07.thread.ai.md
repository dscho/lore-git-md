`git for-each-repo` worktree bug report and fix in progress. Matthew Gabeler-Lee originally identified incorrect `GIT_DIR` propagation when run from worktrees, causing commands to execute in wrong repository context by inheriting the worktree's `GIT_DIR` and applying it to target repositories from config. Derrick Stolee confirms the issue and acknowledges it as a worktree environment handling oversight, with a fix being prepared in GitGitGadget PR #2056 (not yet on list). The bug manifests when running `for-each-repo` from a worktree, making child processes operate on the parent repository instead of intended targets due to leaked `GIT_DIR`. Stolee's upcoming patch series will correct the environment variable handling and add test coverage. This affects current master but has limited real-world impact so far, as `for-each-repo` (added in v2.30) is relatively new and worktree usage exposes this specific edge case. The fix appears straightforward but requires careful environment isolation between the worktree context and target repository operations.
