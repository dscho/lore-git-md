`git for-each-repo` worktree bug report. Matthew Gabeler-Lee identifies incorrect `GIT_DIR` propagation when run from worktrees, causing commands to execute in wrong repository context. The issue occurs because `for-each-repo` inherits and passes the worktree's `GIT_DIR` to child Git processes, making them operate on the parent repository instead of the intended targets from config. Example failure case: `git for-each-repo --config=foo.bar -- branch` from a worktree effectively runs as `GIT_DIR=/worktree-parent/.git git -C /unrelated-repo branch`. The bug remains unfixed in current master. No patch provided yet, but detailed strace analysis confirms the behavior.
