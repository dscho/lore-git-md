This is the second patch in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch refactors the object streaming infrastructure to better handle hash verification.

The change modifies `stream_object_signature()` to accept a preconstructed `odb_read_stream` rather than creating its own, allowing callers more control over the stream lifecycle. This prepares for subsequent changes where direct packfile access will be needed. The patch also improves error reporting in `parse_object_with_flags()` to distinguish between stream opening failures and hash mismatches.

Key technical details:
- `stream_object_signature()` now takes a stream parameter and no longer manages stream lifecycle
- `parse_object_with_flags()` gains explicit error messages for stream opening failures vs hash mismatches
- `pack-check.c` updated to handle the new streaming interface while maintaining existing corruption detection behavior
- Changes span `object-file.c`, `object-file.h`, `object.c`, and `pack-check.c`
- Maintains backward compatibility with existing callers through careful interface design

The patch builds on Jeff King's review feedback from v1, particularly around error handling clarity. This is a preparatory change for the core fsck fix coming in patch 4/4, with the streaming interface refactoring enabling the final solution while improving error reporting along the way.
