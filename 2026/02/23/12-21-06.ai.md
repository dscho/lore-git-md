This is a technical follow-up in Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The discussion focuses on handling corrupted objects during streaming reads from packfiles.

Jeff King had noted that the refactored `packfile_read_object_stream()` might miss marking corrupted objects as "bad" when header parsing fails, though he acknowledged this was a pre-existing issue. Patrick proposes an amendment to explicitly handle `OBJ_BAD` cases by marking the corrupt object and propagating the error.

The key changes in Patrick's proposed diff:
- Adds an `oid` parameter to `packfile_read_object_stream()` to identify objects that fail header parsing
- Calls `mark_bad_packed_object()` when `unpack_object_header()` returns `OBJ_BAD`
- Updates the call site in `packfile_store_read_object_stream()` to pass through the OID

This addresses a subtle edge case in the error handling path while maintaining the series' core goal of preventing infinite loops during `git fsck` of large objects spread across multiple packs. The change demonstrates Patrick's attention to edge cases even when they weren't the primary focus of the original bug report. Jeff King had already approved the overall approach, so this refinement is likely to be uncontroversial.
