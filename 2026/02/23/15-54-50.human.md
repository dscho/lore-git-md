Maintainer feedback on a documentation/style compliance patch for `git cat-file` error messages.

Junio Hamano responds to Md Ferdous Alam's patch that standardizes error and warning message formatting in `builtin/cat-file.c` to follow Git's style guidelines (lowercase initial letters, no trailing periods). While acknowledging the patch looks good overall, Junio suggests two improvements:

1. Handling the "Not a valid object name" message consistently across all files that use it (5 other .c files) in a separate patch, then doing the remaining cat-file changes in another patch.

2. Raising a concern about backward compatibility - whether third-party tools might be parsing these error messages and could break if the wording changes, even though the changes are purely stylistic.

The patch itself is straightforward, changing message capitalization and punctuation in `die()` and `warning()` calls, with corresponding test updates. This appears to be a standalone contribution rather than part of a larger series, and Junio's feedback suggests it may evolve into a two-patch series with more comprehensive handling of the common error message.
