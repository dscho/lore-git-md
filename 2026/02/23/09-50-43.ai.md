Bugfix addressing an infinite loop in `git fsck` when verifying large objects across multiple packfiles. This is the final patch in Patrick Steinhardt's series addressing pack validation issues originally reported by brian m. carlson.

The root cause involves how `git fsck` verifies large objects (those exceeding `core.largeFileThreshold`). Previously, it used `odb_read_object_stream()` which could trigger an MRU list update in the packfile cache, potentially causing an infinite loop when processing multiple large blobs across different packs. More critically, this approach could verify the wrong object instance since it might open any copy of the object rather than the specific one in the target packfile.

The fix replaces `odb_read_object_stream()` with direct packfile access via `packfile_read_object_stream()`, ensuring we verify the exact object from the pack being checked. The patch includes a test case that would have triggered the infinite loop, creating two large blobs in separate packfiles and verifying them with `git fsck`.

Key technical details:
- Changes the verification path in `pack-check.c` to use direct packfile access
- Introduces new test in `t1450-fsck.sh` with 200KB blobs (exceeding default threshold)
- Builds on earlier refactoring that separated stream creation from verification
- Fixes a regression introduced by c31bad4f7d (packfile MRU list changes)

The patch cleanly resolves the reported issue while also making the verification more precise by ensuring we check the specific packed object rather than potentially verifying a different instance. This follows Patrick Steinhardt's characteristic approach of combining careful refactoring with targeted fixes.
