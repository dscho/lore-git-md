This is part of the ongoing ref backend abstraction effort, specifically enabling reference storage backend selection with location specification. The patch is the fifth in a v8 series that has already received maintainer approval from Junio Hamano.

The patch extends the `extensions.refStorage` configuration to support URI syntax (`<format>://<payload>`), allowing users to specify both the backend type (files/reftable) and an alternate storage location. This enables zero-downtime migrations between backends and out-of-tree reference directories. The implementation handles worktree references by storing them in the alternate location while maintaining stubs in the original path to preserve Git directory recognition.

Key technical changes include:
- URI parsing infrastructure in `setup.c`
- Worktree reference directory setup in `builtin/worktree.c`
- Payload propagation through repository initialization
- Comprehensive test coverage in `t1423-ref-backend.sh`

The series has undergone extensive review with all feedback incorporated, including stylistic refinements to URI parsing control flow and documentation polish. This final version represents minor test and documentation improvements over the already-reviewed v7, with the implementation now complete and ready for integration.

The patch maintains backward compatibility while providing the foundation for future backend implementations to support additional payload schemes beyond filesystem paths. A TODO notes the desire to eventually pass `struct worktree *` to backends rather than just paths, though this is deferred due to current architectural constraints.
