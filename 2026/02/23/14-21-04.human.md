Feature patch adding object size metrics to `git repo` command. This is part of Eslam Reda Ragheb's v2 series enhancing repository structure reporting, running in parallel with Justin Tobler's related work on repository introspection.

The patch extends the `git repo` command to report maximum object sizes (both inflated and on-disk) per object type (commits, trees, blobs, tags) as well as overall maxima. This helps identify unusually large objects that may indicate repository bloat. The implementation tracks these metrics while walking reachable objects and presents them in both human-readable table format and machine-parsable key-value output.

The changes are focused on `builtin/repo.c`, adding new fields to track maxima and updating the display logic. The implementation appears thorough, with proper memory management via `strbuf` and comprehensive test coverage mentioned in the thread context. This complements existing object count and size totals with outlier detection capabilities.

The patch is part of a larger effort to enhance repository diagnostics while removing reliance on global state, aligning with the ongoing `the_repository` removal initiative. It shows coordination with Justin Tobler's parallel work, though the exact division of responsibilities between their approaches remains to be finalized. The implementation looks clean and follows established patterns for command plumbing.
