Thread summary:

Test case demonstrating a bug in `receive.denyCurrentBranch=updateInstead` behavior with bare repositories and worktrees. When pushing to a bare repo with a worktree where the bare HEAD points to an unborn branch (not matching the worktree branch), the push is incorrectly rejected with "Working directory has staged changes" despite the worktree being clean. The test creates this scenario: sets up a bare repo with worktree, configures `updateInstead`, points bare HEAD to unborn branch, then attempts push to worktree branch which fails when it should succeed. The issue appears to be in `builtin/receive-pack.c` comparing against bare repo's HEAD rather than worktree state. The test is marked `test_expect_failure` as it documents current broken behavior. The commit message provides context about the real-world scenario that uncovered this edge case in worktree/updateInstead` interaction.
