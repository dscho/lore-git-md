This is part 2 of Patrick Steinhardt's bugfix series addressing pack validation issues with large objects. The patch refactors `stream_object_signature()` to accept a preconstructed `odb_read_stream` rather than opening/closing it internally, shifting stream lifecycle control to callers. This is preparatory work for the core fix in patch 4 that prevents infinite loops during `git fsck` of large objects across multiple packs.

Jeff King reviewed the change and confirmed the technical approach is sound, suggesting minor improvements to error messages and redundant checks. The discussion reveals two key technical points: 1) the repository parameter remains necessary because the stream struct doesn't track hash algorithm information, and 2) the error handling could be more precise by separating stream opening failures from hash mismatches. Patrick agrees with these observations and indicates he'll incorporate them in v2, though keeping the repository parameter is unavoidable without broader structural changes to the ODB stream interface.

The change affects `object-file.c` and its callers, with the main impact being clearer separation of concerns between stream management and hash verification. This intermediate refactoring enables the subsequent fix while maintaining existing behavior - an example of Patrick's characteristic incremental approach to complex changes.
