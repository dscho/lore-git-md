This is part 9/17 in Patrick Steinhardt's series to unify Git's ref iteration interfaces, now in its final polishing stage with Karthik Nayak's approval. The patch generalizes `refs_for_each_fullref_in_prefixes()` to use the new `refs_for_each_ref_options` struct rather than taking individual parameters.

The key change is making the function accept the full options structure instead of separate parameters for namespace, patterns, and exclude patterns. This aligns with the series' goal of consolidating ref iteration APIs. The function still handles its special case of multiple prefix patterns by computing longest common prefixes, but now does so while integrating with the unified options structure.

The patch updates two callers (`ls-refs.c` and `ref-filter.c`) to use the new interface, passing their existing parameters via the options struct. The implementation carefully avoids allowing callers to specify both a prefix via the options struct and via the prefixes parameter, which would be ambiguous.

This change is part of the broader ref backend modernization effort, building on earlier patches that introduced the options struct and standardized callback types. It maintains all existing behavior while further reducing API surface area. The series as a whole is showing significant performance improvements (115ms->1.1ms for some operations) through these consolidations.
