This is the third patch in Patrick Steinhardt's series fixing pack validation issues with large objects. The patch refactors packfile object streaming functionality to expose a lower-level interface that works directly with packfile offsets rather than requiring an object ID.

The change extracts the core logic from `packfile_store_read_object_stream()` into a new `packfile_read_object_stream()` function that takes a packfile and offset directly. The original function is then reimplemented as a thin wrapper that looks up the pack entry before calling the new function. This prepares for future changes that need to work with raw pack offsets rather than object IDs.

The patch is a mechanical refactoring that doesn't change behavior - it just makes the streaming functionality more flexible for callers. The commit message clearly explains the motivation (needing to work with pack offsets directly in a future change) and the change itself is straightforward, splitting an existing function while preserving all the existing logic. This continues the series' pattern of careful, incremental preparation for the actual bugfixes to come.
