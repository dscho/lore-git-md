Bugfix for `git for-each-repo` in worktrees. Matthew Gabeler-Lee reports that when run from a worktree, `git for-each-repo` incorrectly passes the worktree's GIT_DIR to child processes, causing commands to execute in the wrong context. The issue manifests when scripts using `for-each-repo` work normally from a main repository but fail when run from a worktree.

The problem occurs because the worktree's GIT_DIR environment variable leaks into the child processes spawned by `for-each-repo`. This makes commands like `git for-each-repo --config=foo.bar -- branch` effectively run with the wrong repository context. The reporter has verified this behavior in Git 2.51.0 and notes that the issue appears to exist in current master as well.

This looks like a legitimate bug in environment variable handling that affects a specific but important use case (running maintenance scripts from worktrees). The report includes clear technical details and reproduction steps, suggesting it's well-researched and likely to be actionable. The fix would presumably involve cleaning the environment before spawning child processes in the `for-each-repo` command.
