This is a bugfix targeting zombie processes in container environments where Git runs as PID 1. The patch addresses a specific edge case where network operations (like git-remote-https or ssh) fail abnormally, causing Git to exit before properly reaping child processes.

The core issue occurs when transport errors trigger an immediate exit(128), bypassing the normal cleanup paths in transport-helper.c and connect.c. When Git is the init process (PID 1) in containers, these un-reaped children become zombies since there's no parent process to clean them up.

Andrew Au's solution introduces atexit handlers in both files to ensure child processes are reaped regardless of the exit path. The handlers are cleared during normal cleanup to avoid double-waiting. The changes are focused and well-explained, with clear motivation linking to real-world container scenarios. The patch appears technically sound and addresses a concrete pain point in containerized deployments.

This is marked as RFC, suggesting the author may be open to feedback on the atexit approach before finalizing. The fix should be particularly high-value for users running Git in containerized CI/CD pipelines or other PID 1 scenarios.
