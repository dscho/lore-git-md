This is a feature patch series adding `--trailer` support to `git rebase`, allowing users to automatically append trailers (like Signed-off-by) to commit messages during rebase. The series is now in its 7th iteration, showing significant refinement based on reviewer feedback.

The core change enables in-process trailer manipulation rather than forking `git interpret-trailers`, improving performance. The first four patches refactor trailer handling to make this possible, moving functionality from `builtin/interpret-trailers.c` to `trailer.c` so it can be reused by multiple commands. The final patch adds the actual `--trailer` option to rebase, currently only supporting the merge backend.

Key technical details include:
- New `append_trailers()` function in trailer.c that handles in-process trailer manipulation
- `OPT_STRVEC` parsing for trailers in commit/tag commands
- Early validation of trailer arguments in rebase
- New test file `t/t3440-rebase-trailer.sh` with 147 lines of test coverage
- Careful preservation of `--in-place` semantics via tempfile+rename

The patch appears well-considered, with thorough test coverage and clear attention to edge cases. The multi-patch refactoring approach makes the change easier to review, and the series has already incorporated feedback from several experienced contributors (Phillip Wood, Kristoffer Haugsbakk, Junio Hamano). The main limitation is the merge-backend-only support, which the commit message explicitly calls out as a current restriction.
