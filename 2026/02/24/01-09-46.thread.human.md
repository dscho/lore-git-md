This thread discusses a bugfix for incorrect diffstat width calculations when line prefixes contain ANSI color codes. A GSoC contributor has submitted a two-patch series to address the issue, which Junio Hamano had previously identified in discussion. The problem occurs when Git uses strlen() on strings containing ANSI codes - these control sequences don't take up visible space but are counted in the length, throwing off the width calculations.

The first patch fixes the core issue in diff.c by replacing strlen() with utf8_strnwidth(), which properly skips ANSI sequences when calculating display width. This affects commands like `git log --graph` that use colored prefixes. The change also removes a NEEDSWORK comment from commit ce8529b2 that had explicitly noted this problem. The second patch adds regression tests in t4074 to verify the corrected behavior.
