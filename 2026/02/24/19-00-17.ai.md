This is a refactoring patch in Taylor Blau's multi-pack-index compaction series, specifically addressing pack permutation handling during MIDX compaction. The patch introduces a new helper function `midx_pack_perm()` to safely access the `pack_perm` array when compacting MIDX layers with different pack ID ranges.

The core issue arises when compacting MIDX layers where pack IDs from upper layers could exceed the allocated `pack_perm` array size. The patch prepares for a future solution that will offset these IDs rather than allocating more memory, though the actual offset calculation isn't implemented here yet. This is a preparatory change that maintains current behavior while making the code safer and more maintainable.

The patch touches several MIDX-writing functions that need to access pack permutations, replacing direct array access with the new helper. This affects object offset writing, pack ordering, bitmap position assignment, and packing data preparation. The changes are mechanical and behavior-preserving, with all existing test coverage remaining valid.

This is part of the larger effort to enable `git multi-pack-index compact` functionality while maintaining bitmap compatibility across MIDX versions. The series has already addressed technical feedback in previous iterations and is now in its final review stages before potential merging.
