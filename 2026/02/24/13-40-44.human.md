This is a feature patch series for `git fast-import` that adds a new `re-sign-if-invalid` mode to handle invalid commit signatures during import. The series builds on prior work that allowed signature stripping during import.

The second patch in the series, implemented by Justin Tobler, introduces the new mode that will re-sign commits with invalid signatures using the user's current signing key. This provides a middle ground between the existing options of either preserving invalid signatures or stripping them entirely. The implementation supports GPG, X.509, and SSH signatures and includes thorough test coverage.

Christian Couder, who maintains the fast-import/fast-export code, has reviewed the series and agrees with the approach. He notes some minor typos in the cover letter but supports deferring the handling of `extensions.compatObjectFormat` for signature regeneration to a future patch. Patrick Steinhardt has provided detailed technical review feedback on the implementation, raising questions about warning messages and function naming that may need to be addressed in future iterations.

The series appears well-structured with a preparatory cleanup patch followed by the feature implementation. The commit messages are clear and the test coverage looks comprehensive. This seems like a useful addition to `git fast-import`'s signature handling capabilities, particularly for users who need to import repositories with some invalid signatures they want to replace rather than just strip.
