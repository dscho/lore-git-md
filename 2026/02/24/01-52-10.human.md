This is a bugfix for `git for-each-repo` when run from a worktree. Derrick Stolee confirms Matthew Gabeler-Lee's report that the command incorrectly propagates the worktree's `GIT_DIR` environment variable to child processes, causing them to operate on the wrong repository context. The issue occurs because the worktree sets `GIT_DIR` to point to the parent repository, and `for-each-repo` passes this along when it should instead let each child process determine the correct repository context based on the target directory.

Stolee indicates he has a fix in progress (linked to a GitHub PR) that includes a regression test. The patch appears to be straightforward, addressing a clear behavioral bug that affects worktree users. Since Stolee is a respected contributor with deep knowledge of Git's internals, the fix is likely to be well-considered and merge-ready once sent to the list.
