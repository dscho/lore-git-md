This is a discussion thread about the behavior of the experimental `git repo info` command, part of the GSOC "Improve repo" project. Junio C Hamano weighs in on SoutrikDas's RFC patch that proposed changing the default behavior to show all fields when no arguments are given.

Junio strongly advocates for maintaining the current plumbing-style behavior where the command outputs nothing when no fields are specified. He argues this is more predictable for scripting use cases - the rule "you get what you explicitly ask for" is simpler and more consistent than having special cases based on argument count. He dismisses the "user friendly" justification for showing all fields by default, emphasizing that plumbing commands prioritize predictability over interactive convenience.

The exchange highlights the core tension in the thread: Phillip Wood's original design (plumbing discipline with explicit field requests) versus the proposed porcelain-like convenience (default show-all behavior). Junio's response suggests he views this as settled in favor of the plumbing approach, though the thread remains in RFC status indicating the discussion may continue. The technical implementation question (a simple conditional change in `builtin/repo.c`) is secondary to this design philosophy debate about the command's intended use case and audience.
