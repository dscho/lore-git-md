This is a code style refinement in the ongoing `git send-email` charset validation series. Junio C Hamano points out that the patch's Perl code should use consistent brace style - the original omitted braces for single-statement blocks, while Git's style prefers explicit braces in all cases. The change is purely stylistic, adding braces to the `if/else` blocks in the charset validation logic that was recently added to prevent malformed email headers when users accidentally enter "y" instead of a proper charset name.

The patch makes no functional changes - it just brings the new validation code in line with Git's coding style guidelines. This follows the project's convention of using explicit braces even for single-statement blocks, maintaining consistency with the surrounding codebase. The change is minimal (5 insertions, 3 deletions) and focused solely on the `git-send-email.perl` file.

This refinement comes after several iterations of the charset validation feature, where the substantive changes to improve the prompt and add proper encoding checks have already been discussed and approved. Junio's comment here is strictly about code presentation, not functionality.
