This is an RFC patch proposing a behavior change for the experimental `git repo info` command, part of the GSOC "Improve repo" project. The patch comes from a new contributor engaging with prior discussion about the command's design.

The change makes `git repo info` show all available fields by default when no arguments are given, rather than showing nothing as it currently does. This moves the command toward porcelain-style convenience at the expense of strict plumbing discipline (where explicit field requests were previously required). The one-line implementation is simple but reveals some duplicate conditions that would need cleanup.

The patch acknowledges this is a design tradeoff between usability and explicitness, continuing a thread where Phillip Wood had advocated for the plumbing-style approach. As an RFC from a new contributor, it shows engagement with the project's design discussions while leaving the core tension unresolved. The change would need implementation cleanup and backward compatibility consideration if pursued further.
