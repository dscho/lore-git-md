This is a refactoring patch in Phillip Wood's series to add `--trailer` support to `git rebase`. It's the first of five patches in the seventh iteration of the series.

The patch extracts the core trailer rewriting logic from `interpret_trailers()` into a new `process_trailers()` helper function that operates on strbufs rather than directly handling file I/O. This separation makes the trailer manipulation logic reusable by other commands (like the upcoming rebase integration) while keeping the file handling concerns in the original function.

Key changes:
- New `process_trailers()` takes input/output strbufs instead of file operations
- Original `interpret_trailers()` now handles just the I/O layer
- Uses `strbuf_write()` for output to maintain atomicity when using `--in-place`
- No behavior change - this is purely an internal restructuring

The patch is part of the larger effort to enable in-process trailer manipulation during rebase operations. By making the trailer processing logic more modular, it paves the way for the rebase command to reuse this functionality without forking `git interpret-trailers`. The changes are focused and well-contained, with the diff showing clear separation of concerns between the new helper and the original file-handling code.
