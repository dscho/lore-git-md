This is a patch series from Vaidas Pilkauskas adding HTTP 429 rate limit retry support to Git's HTTP client, now in its fifth iteration. The series has been reviewed by Jeff King and Taylor Blau in previous rounds, with Junio Hamano now weighing in to say the first three patches (strbuf_attach fixes and a remote-curl helper function) look reasonable to him. He suggests the final patch - the actual HTTP 429 implementation - should get another look from someone more familiar with the HTTP transport code before merging.

The technical scope includes:
- Fixes to strbuf_attach usage across several files (builtin/am.c, builtin/fast-import.c etc.) ensuring proper NUL termination
- A new show_http_message_fatal() helper in remote-curl.c
- HTTP 429 support with Retry-After header handling (both delay-seconds and HTTP-date formats)
- Configurable via http.maxRetries, http.retryAfter, http.maxRetryTime with environment overrides
- New HTTP_RETRY_LIMITED result code
- Conservative defaults (maxRetries=0) maintaining Git's fail-fast philosophy
- Extensive test coverage via new t/lib-httpd/http-429.sh

The series appears ready for final review, with only the HTTP transport experts' sign-off remaining before potential inclusion. The strbuf fixes and helper function have Junio's approval, suggesting they could potentially be queued independently if the HTTP patch needs more work.
