This is the second patch in a two-part series improving environment handling in `git for-each-repo`, focusing on worktree support. The patch addresses how the command interacts with Git's environment variables when run from a worktree context.

The key changes in this v2 patch:
1. Modifies `run_command_on_repo()` to properly save, unset, and restore all Git-specific environment variables (GIT_DIR, GIT_WORK_TREE, etc.) using Git's `local_repo_env` mechanism
2. Updates the test script to include a worktree scenario and verify correct behavior
3. Demonstrates the command works both from a worktree and with repository-less operation
4. Maintains compatibility with existing use cases while adding the new worktree support

The implementation shows careful handling of environment variables - saving their values before unsetting them for the child process, then restoring them afterward. This ensures proper isolation while maintaining the parent process's environment. The test changes verify the worktree case works while preserving all existing functionality.

This builds on feedback from v1 where Jeff King identified environment isolation requirements and Patrick Steinhardt noted NULL-safety concerns. The solution now handles Git's full set of repository-local environment variables while maintaining robust error handling. The test changes help surface edge conditions while demonstrating the command's expanded capabilities.

The patch reveals one remaining architectural limitation - the need for `the_repository` global when accessing config - but this doesn't block the current improvements to worktree support. The changes represent a solid step forward in making `for-each-repo` more robust across different repository contexts.
