This is a feature patch for `git fast-import` that adds a new `re-sign-if-invalid` mode to handle invalid commit signatures during import. The patch builds on prior work allowing signature stripping and is the second in a two-patch series (the first being a cleanup of obsolete declarations).

The core change introduces a new mode for `--signed-commits` that re-signs commits with invalid signatures using the user's current signing key, rather than just stripping them. The implementation touches the fast-import machinery and gpg-interface plumbing, with test coverage for GPG/X.509/SSH signatures. Currently it only re-signs using the repository's primary object format, ignoring any `extensions.compatObjectFormat` signatures.

Patrick Steinhardt's review raised several technical points that Justin Tobler plans to address in the next version: clarifying documentation around the "same as strip-if-invalid" wording, improving warning messages when re-signing, better explaining the compatObjectFormat limitation (with a NEEDSWORK comment), and potentially adding support for specifying which key to use (similar to git-commit's --gpg-sign). Christian Couder (the fast-import/fast-export maintainer) has also reviewed the patch, suggesting minor doc fixes while agreeing with the technical approach.

The patch appears well-structured with thorough test coverage, though some edge cases around compatibility hashes and key specification remain to be resolved. The feature fills a clear gap between the existing "preserve" and "strip" modes for handling invalid signatures during import.
