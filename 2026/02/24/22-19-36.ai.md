This is a bugfix report for the UTF-8 alias support series currently in `next`. Jacob Keller identifies a memory leak in the `--list-cmds=alias` functionality introduced by Jonatan Holmgren's patch that consolidated alias listing logic between `help.c` and `alias.c`.

The issue occurs because the new implementation stores alias values in the string list's `util` field (via `xstrdup`) but doesn't free them when clearing the list. The `list_cmds()` function in `git.c` calls `string_list_clear()` with `free_util=0`, leaving these allocations dangling. Jacob provides a simple fix that changes this to `free_util=1`.

This is a straightforward memory management oversight in the refactoring - the consolidation of alias listing was meant to be behavior-preserving but missed this cleanup detail. The fix is small and low-risk, just needing to properly free the allocated strings when done with them. Since this series is already in `next` and addresses a regression from earlier versions, this fix will likely be folded into the existing topic rather than requiring a full re-roll.
