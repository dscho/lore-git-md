This is a follow-up to an RFC patch proposing a behavior change for the experimental `git repo info` command (part of a GSOC project). The patch changes the default behavior from showing nothing when no fields are specified (the original plumbing-style design) to showing all available fields by default, making it more user-friendly porcelain.

The v2 patch corrects an accidental diff snippet that was included in the initial submission, keeping only the intended change - modifying the condition to trigger `print_all_fields` when either `--all` is specified OR no arguments are given. The implementation remains simple, just altering one conditional in `builtin/repo.c`.

The underlying design question - whether this experimental command should follow strict plumbing conventions (require explicit field requests) or prioritize usability (show everything by default) - remains unresolved from the thread discussion. The patch comes from a new contributor engaging with prior feedback, though the RFC status suggests it's still exploring the design space rather than proposing a firm direction.
