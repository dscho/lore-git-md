This is a bugfix patch addressing a memory leak in the UTF-8 alias support series. Jacob Keller reports that the `git --list-cmds=alias` command leaks memory because the alias values stored in the string list's util field are not being freed. The leak was introduced when Jonatan Holmgren consolidated the alias listing logic but didn't update the cleanup path to free these values.

The fix is straightforward - changing `string_list_clear(&list, 0)` to `string_list_clear(&list, 1)` in `git.c` to properly free the util pointers. This is a clear regression that needs to be addressed before the series can graduate from `next` to `master`. The patch demonstrates good debugging with LeakSanitizer output showing the exact allocation path and size of the leak.

This follows up on the ongoing UTF-8 alias support work, which has already seen several iterations addressing various edge cases and documentation issues. While the core functionality is working well, this memory leak shows the importance of thorough testing of all code paths when refactoring configuration handling.
