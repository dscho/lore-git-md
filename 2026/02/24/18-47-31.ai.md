This is a technical discussion about the MIDX compaction series, specifically addressing implementation details of patch 10/18 which removes the lexicographic pack ordering requirement.

Taylor Blau responds to Patrick Steinhardt's review feedback on the MIDX version handling and pack name sorting implementation. The exchange clarifies several design decisions:

1. **Version handling**: Taylor explains why he used an `int` rather than an `enum` for the MIDX version field - the enum values would have mapped to the same integers anyway, making the enum redundant.

2. **Sorting implementation**: Patrick questions the use of an index array for sorting pack names rather than sorting the names directly. Taylor defends the index array approach as having clearer ownership semantics, though acknowledges it may be slightly less intuitive to read.

3. **Alternative approaches**: Patrick suggests a lazy-sorting approach with a `bool sorted` flag, but Taylor explains this isn't feasible because the original pack_int_id ordering must be preserved for correct operation.

The discussion shows careful consideration of implementation tradeoffs in the MIDX compaction logic, with Taylor providing rationale for his design decisions. This is part of the broader effort to enable MIDX compaction while maintaining backward compatibility and proper object ordering for bitmaps.
