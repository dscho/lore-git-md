This is part 4 of Phillip Wood's ongoing series to add `--trailer` support to `git rebase`, now in its 7th iteration. The series refactors Git's trailer handling to make it reusable across commands without forking `git interpret-trailers`.

This particular patch simplifies the trailer argument handling in `git commit` and `git tag` by switching from `OPT_PASSTHRU_ARGV` to `OPT_STRVEC` for the `--trailer` option. The change means the trailer arguments no longer need to be prefixed with `--trailer=`, allowing removal of the prefix-stripping logic in `amend_file_with_trailers()`. 

The patch is a straightforward cleanup that builds on earlier refactoring work in the series. It maintains backward compatibility while making the code more direct by having the option parser handle the trailer values directly rather than passing through raw argv-style strings. The change affects both the commit and tag commands equally, with corresponding updates to the trailer API documentation.

As with the rest of the series, this appears to be a well-considered change that moves toward the goal of making trailer handling more flexible for use in rebase operations. The patch is focused and follows the established pattern of the series.
