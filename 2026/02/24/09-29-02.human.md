This is the second patch in a two-part series adding configurable commit list formatting for `git format-patch` cover letters. It introduces a `format.commitListFormat` configuration option that persists the commit list format setting, complementing the command-line `--cover-letter-format` option added in patch 1/2.

The implementation stores the config value in a new `fmt_cover_letter_commit_list` field in the `format_config` struct, with proper memory management via `format_config_release()`. When no format is specified on the command line, it falls back to this config value. The format string follows the same rules as the command-line option - either "shortlog" for the default behavior or "log:<format>" for custom formatting.

The patch maintains backward compatibility by defaulting to the traditional format when neither config nor command-line option is set. It also includes validation to ensure the format string matches the expected pattern, mirroring the checks from patch 1/2.

This completes the feature by providing both transient (command-line) and persistent (config) control over cover letter commit list presentation. The implementation appears clean and follows Git's established patterns for config handling. With both patches now addressing the major technical concerns raised in review, this series looks ready for final consideration.
