This is a follow-up patch series addressing minor issues in the recently merged UTF-8 alias subsection support. The series contains two small fixes: one for the documentation and one for backward compatibility.

The first patch corrects a formatting issue in the alias documentation where list continuation markers were missing in an example showing the equivalence between `alias.last` and `alias.last.command` syntax. This is purely a documentation polish.

The second patch fixes a compatibility regression where empty subsections (`[alias ""]`) were not being treated the same as plain `[alias]` sections. This could cause existing configurations using the empty subsection syntax to be silently ignored. The patch adds explicit handling to treat them equivalently and includes a test case to verify the behavior.

Both changes are straightforward and uncontroversial, addressing issues that emerged after the main feature was merged into `next`. The documentation fix is minor formatting, while the empty subsection handling preserves backward compatibility case that was overlooked in the initial implementation. The patches come with test coverage and touch minimal code, making them low-risk follow-ups to the larger feature work.
