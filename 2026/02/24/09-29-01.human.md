This is a feature patch adding configurable commit list formatting for `git format-patch` cover letters. It's the first of a two-patch series that emerged from an RFC discussion where Jeff King (Peff) helped refine the technical approach.

The patch introduces a new `--cover-letter-format` option that lets users customize how commits are listed in the cover letter. The default remains the traditional shortlog format (grouped by author), but users can now specify an alternative format string prefixed with "log:" to get chronological commit listings with custom formatting. For example, `--cover-letter-format="log:%s (%an)"` would show each commit's subject and author name in order. The implementation uses `repo_format_commit_message()` to handle the formatting, following Peff's guidance to avoid global state.

The changes are focused in `builtin/log.c` and maintain backward compatibility. The patch looks well-structured with clear separation between the new formatting logic and existing shortlog handling. While the commit message could better explain why chronological ordering is useful (beyond just saying developers find shortlog "less useful"), the technical implementation appears solid and addresses the concerns raised in the RFC discussion.
