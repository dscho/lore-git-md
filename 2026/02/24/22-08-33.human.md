This is a follow-up in an RFC thread about changing the default behavior of the experimental `git repo info` command (part of a GSOC project). The original proposal suggested showing all fields when no arguments are given, but Junio Hamano has firmly opposed this, arguing that plumbing commands should only output explicitly requested data for scripting predictability.

The contributor (SoutrikDas) acknowledges Junio's feedback, showing they now understand the distinction between plumbing (script-oriented) and porcelain (user-oriented) commands. The technical implementation remains a simple conditional change in `builtin/repo.c`, but the core disagreement is about design philosophy rather than code.

The thread highlights the challenge new contributors face when navigating Git's established norms around command behavior. While the patch itself is small and well-formed, its future appears uncertain given the maintainer's strong stance on plumbing discipline. The contributor demonstrates good engagement with feedback, though the fundamental design question seems settled in favor of the current explicit-output approach.
