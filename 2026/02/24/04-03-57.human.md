This is the second patch in a 3-part series implementing configurable cover letter formats for `git format-patch`. The patch adds a new `--cover-letter-format` command-line option that allows specifying either "shortlog" (the current behavior) or a printf-style format string prefixed with "log:" to customize how commit summaries appear in cover letters.

The implementation introduces a new `generate_commit_list_cover()` function that handles the formatted output, while maintaining backward compatibility with the existing shortlog-based approach. The format strings can include placeholders like `%s` for commit subject and `%a` for author name. The patch modifies `builtin/log.c` to parse the new option and route output generation appropriately.

This follows Junio Hamano's design direction from the RFC discussion, providing both configuration flexibility and command-line control. The implementation appears clean and focused, with clear separation between the new formatting logic and existing shortlog handling. The patch maintains Git's standard coding style and includes appropriate error handling for invalid formats.

As part of a well-structured series, this patch builds on the foundation laid in patch 1/3 (which fixed a NULL dereference issue) and sets up for patch 3/3 (expected to add config file options). The change addresses a real usability pain point where the default shortlog output can obscure commit ordering and context.
