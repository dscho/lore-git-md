This is a bugfix patch addressing a NULL pointer dereference in `pretty.c`'s `commit_format_is_empty()` function. The issue occurs when checking user-supplied commit formats without first verifying the `user_format` pointer is non-NULL.

Maintainer Junio C Hamano questions whether silently handling the NULL case is correct, suggesting it might be better to treat this as a programming error via `BUG()`. The current implementation checks `!*user_format` (dereferencing first) rather than `!user_format` (checking the pointer itself), which could crash if no format was set.

The patch is part of a larger series introducing configurable cover letter formatting, but this particular fix stands alone as a correctness improvement. Junio's response indicates the existing code paths may already prevent the NULL case through design, making the silent fix potentially masking a deeper issue. This suggests the patch may need revision to either:
1. Keep the NULL check but add assertions about expected invariants
2. Convert to an explicit `BUG()` as Junio proposes
3. Document why the NULL case is reachable and needs graceful handling

The thread context shows this is the first of three patches, with the subsequent ones depending on this fix. The maintainer's scrutiny here suggests careful attention to error handling invariants will be important for the series' acceptance.
