This is a technical patch in Taylor Blau's ongoing multi-pack-index compaction series (now at v3). It fixes a subtle issue in the MIDX bitmap position assignment logic that would cause problems when the upcoming compaction feature is implemented.

The patch changes how `midx_pack_order()` processes packs when assigning bitmap positions. Currently it uses the `ctx->pack_perm` array to index into pack info, but this becomes problematic for compaction which will introduce a wrapper around `pack_perm`. The fix is straightforward - just index directly through `ctx->info` array instead since there's no need for the indirection here.

The change is small (just one line) but important for the series' correctness. It demonstrates careful forward-thinking about how current code will interact with upcoming features. The commit message thoroughly explains both the current safe behavior and why the change is needed for compaction support.
