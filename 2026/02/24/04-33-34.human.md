This is a test case documenting a bug in the interaction between `receive.denyCurrentBranch=updateInstead` and worktrees with unborn bare repository HEADs. The test demonstrates that when pushing to a bare repo with a worktree where the bare HEAD points to an unborn branch (different from the worktree branch), Git incorrectly rejects the push with a "Working directory has staged changes" error even when the worktree is clean.

The issue stems from `builtin/receive-pack.c` comparing against the bare repository's HEAD rather than the worktree state when determining whether to allow the push. Runxi Yu traces this behavior back to a 2021 commit by Anders Kaseorg that added worktree protection for bare repositories, noting the logic has always worked this way rather than being a recent regression. The test is marked as `test_expect_failure` to document the current broken behavior while awaiting a fix.

The discussion reveals an interesting edge case in how Git handles worktree state versus bare repository state, particularly around unborn branches. This could affect users who maintain bare repositories with worktrees and use the `updateInstead` configuration. The test provides a clear reproduction scenario that will help verify any future fix for this behavior.
