The thread began with an RFC patch series proposing a behavior change for the experimental `git repo info` command (part of a GSOC project by SoutrikDas). The original plumbing-style design showed nothing when no fields were specified, while v2 proposed showing all fields by default when no arguments were given. Junio Hamano strongly objected to this, insisting that plumbing commands must produce zero output with zero arguments for scripting predictability - a core Git design principle.

After Junio's definitive stance, the discussion shifted to helping the contributor understand Git's plumbing/porcelain distinction. K Jayatheerth followed up by pointing SoutrikDas to the "Plumbing and Porcelain" chapter in Pro Git, reinforcing the maintainer's position. The technical question is now settled: the command will follow strict plumbing conventions, showing nothing by default. 

This thread demonstrates how the Git community educates new contributors about the project's design norms, prioritizing consistency with established patterns over local convenience for new commands. While the implementation change in `builtin/repo.c` remains simple, the more significant outcome is the contributor's growing understanding of Git's underlying principles.
