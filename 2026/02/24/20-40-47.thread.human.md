This thread discusses an RFC patch series proposing changes to the experimental `git repo info` command from the GSOC "Improve repo" project. The original version (v1) suggested making the command more user-friendly by showing all available fields by default when no arguments are given, rather than the current plumbing-style behavior of showing nothing. The v2 iteration fixed an accidental diff snippet while maintaining this core change.

Junio C Hamano has now weighed in strongly in favor of keeping the current plumbing behavior, arguing that the explicit "you get what you ask for" approach is more predictable for scripting use cases. He dismisses the convenience argument for showing all fields by default, emphasizing that plumbing commands should prioritize consistency over interactive usability. This reinforces Phillip Wood's original design rationale for the command.

While the technical implementation would be a simple conditional change in `builtin/repo.c`, the discussion has shifted to a fundamental design question about whether this command should follow plumbing or porcelain conventions. Junio's response suggests he considers the plumbing approach settled, though as an RFC the thread remains open for further discussion. The patch author has shown responsiveness to feedback through iterative revisions, but the core tension between scripting predictability and user convenience remains unresolved.
