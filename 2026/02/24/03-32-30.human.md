This is the second patch in a two-part series fixing issues in `git for-each-repo`. The first patch was a mechanical `the_repository` removal; this one addresses a worktree-specific bug.

The patch fixes `git for-each-repo` when run from a worktree by properly handling the GIT_DIR environment variable. The issue was reported by Matthew Gabeler-Lee - the command would fail when invoked from a worktree due to incorrect path resolution. The solution is straightforward: unset GIT_DIR before processing repositories to prevent it from interfering with child processes.

The test changes demonstrate the fix by:
1. Creating a worktree in the test setup
2. Moving the test config from local to global scope (showing it works in non-worktree cases)
3. Adding a new test case that runs the command from the worktree
4. Verifying the command affects the correct repositories

The patch follows Derrick Stolee's typical style - focused changes with thorough test coverage. While the fix itself is small (just 4 lines of code), the test updates are more extensive (22 lines) to properly validate the behavior.
