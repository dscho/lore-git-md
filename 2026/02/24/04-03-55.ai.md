Implementation of configurable cover letter format for `git format-patch`. This patch series follows up on the RFC discussion where Junio Hamano established the direction for a flexible printf-style format configuration. The series introduces both a command-line option (`--cover-letter-format`) and configuration setting (`format.commitListFormat`) to customize how commits are listed in cover letters.

The implementation addresses several technical aspects:
- Adds new `format.commitListFormat` config accepting printf-style format strings (with %s for subject, %a for author)
- Introduces `--cover-letter-format` command-line option as counterpart to the config
- Fixes a NULL dereference in `commit_format_is_empty()` that was discovered during development
- Maintains backward compatibility by falling back to current shortlog format when unset

The patches show careful attention to the maintainer's requirements from the RFC discussion, particularly around configuration flexibility and command-line override capability. The implementation appears clean, with logical separation between the config and command-line option additions. The NULL dereference fix in patch 1/3 is a straightforward correctness improvement that stands on its own merit.

This represents the implementation phase of a feature that already passed design review, with all architectural questions settled. The changes touch `builtin/log.c` and `pretty.c`, focusing on the cover letter generation logic while preserving the existing behavior as default. The series is well-structured with each patch building logically on the previous one.
