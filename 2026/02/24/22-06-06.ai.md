This is a refinement to the ongoing `git send-email` character encoding validation effort, now in its second iteration. The patch improves the interactive prompt for non-ASCII email headers by replacing a length-based charset validation heuristic with proper semantic validation using Perl's `Encode::find_encoding()`. It also clarifies the prompt wording to prevent misinterpretation as a yes/no question.

Key technical changes in v2:
- Adds explicit braces in if-else blocks to match Git's coding style (the only change from v1)
- Maintains the core improvements from v1:
  * Validates charset names semantically rather than by length
  * Relaxes input rules to accept any non-blank string while warning about invalid charsets
  * Updates prompt wording to "Declare which 8bit encoding to use [default: UTF-8]?"
  * Preserves the confirmation flow for questionable inputs
