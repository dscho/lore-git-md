This is the second patch in a two-part series adding configurable commit list formatting for `git format-patch` cover letters. The series implements both command-line (`--cover-letter-format`) and config-based (`format.commitListFormat`) control over how commits are listed in cover letters.

The patch adds the config option `format.commitListFormat` to complement the command-line option introduced in patch 1/2. When set, this config value specifies the format string for commit list presentation in cover letters, with the same syntax as the command-line option ("shortlog" or "log:<format>"). The implementation handles memory management through `format_config_release()` and falls back to traditional shortlog format when unconfigured.

Key technical details:
- Config parsing happens in `git_format_config()` with proper string handling
- The format string is prefixed with "log:" when stored (matching the command-line syntax)
- Defaults to "%s" format when config is set but empty
- Validates format strings against the same rules as the command-line option
- Changes are focused in `builtin/log.c` with a 22-line diff

The patch builds on the architectural foundation established in v1 and refined through review feedback, particularly from Jeff King (Peff) regarding proper API usage and NULL handling. With both command-line and config options now implemented, the series provides flexible control over cover letter formatting while maintaining backward compatibility.
