Feature implementation for Linux fsmonitor using inotify. This is the fifth iteration of a patch series that brings Linux support for Git's filesystem monitoring on par with existing Windows and macOS implementations.

The patch implements fsmonitor for Linux using the inotify API, which requires watching individual directories rather than a single root like macOS's FSEvents. It handles directory renames and moves using inotify's cookie mechanism to track IN_MOVED_FROM/IN_MOVED_TO event pairs. Key aspects include non-blocking event monitoring, bidirectional path-watch descriptor mappings, dynamic handling of directory operations, and detection of remote filesystems.

The implementation has undergone extensive review across four previous versions, with all major technical concerns addressed. Paul Tarjan reports it has been stable in production for two months. The current version includes fixes for crashes during rapid nested directory creation and adds meson build system support. Two small memory leaks remain (512-byte during startup and 40-byte in IPC handling) but are considered non-blocking.

The patch enables significant performance improvements for status operations on Linux by avoiding full directory scans. Testing shows it handles stress cases well, including parallel file operations, deep directory structures, and rapid renames. Documentation is updated to cover Linux-specific considerations like inotify watch limits.
