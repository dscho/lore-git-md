Bugfix for a leak in the UTF-8 alias subsection implementation. Jacob Keller reports a memory leak in the `--list-cmds=alias` functionality that was introduced in v7 series of the UTF-8 alias support patches. The leak occurs when alias values are stored in the string list's util field` but not freed during cleanup.

The issue stems from `list_aliases()` populating the string list with alias values (via `xstrdup`) in the util field, but `list_cmds()` calling `string_list_clear()` with `free_util=0`. Jacob provides a simple fix - changing this to `free_util=1` properly cleans up the allocated memory. The leak was detected via AddressSanitizer showing 37 allocations totaling 1453 bytes.

This is a straightforward technical fix that needs to be folded into the ongoing UTF-8 alias work. The core functionality remains sound - this just addresses a resource management oversight in one code path. The fix is low-risk and should be uncontroversial to include in the next iteration of the series.

The thread context shows this is one of several follow-up issues being addressed after the v7 series was merged to `next`. Other outstanding items include documentation formatting fixes and a regression with dot-prefixed aliases, but this memory leak is now the most pressing technical issue to resolve before finalizing the feature.
