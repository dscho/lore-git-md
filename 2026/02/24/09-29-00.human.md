Feature enhancement for `git format-patch` allowing customizable cover letter commit list formatting. This is the second version of a series that was previously discussed and refined based on Jeff King's technical review.

The series now consists of two patches (down from three in v1) after dropping the first patch due to resolved NULL handling concerns. The remaining patches add:
1. A `--cover-letter-format` command-line flag
2. A `format.commitListFormat` configuration option

Key improvements in this version:
- Uses `repo_format_commit_message()` as recommended by Jeff King to avoid problematic global state
- Maintains backward compatibility by falling back to traditional shortlog when unconfigured
- Follows Git's standard precedence where command-line options override config settings

The implementation touches `builtin/log.c` with significant but focused changes (71 insertions, 16 deletions). The author (Mirko Faina) has incorporated the architectural feedback from the previous discussion, particularly around proper API usage for commit message formatting.

This looks like a well-considered iteration that addresses the core technical concerns raised in review. The feature provides useful flexibility for those who generate patch series frequently and want more control over how commits are summarized in cover letters. With the major architectural questions resolved, this version appears ready for final review and potential merging.
