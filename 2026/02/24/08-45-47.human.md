This is the third patch in Patrick Steinhardt's series to make geometric repacking the default maintenance strategy, focusing on test reliability. The patch addresses an issue where the test suite's hardcoded 2005 timestamps would cause reflog entries to be immediately expired under the new geometric maintenance strategy.

The current "gc" strategy skips maintenance when the object database is optimized, but the geometric strategy evaluates each subtask independently. This means it may expire reflogs even when the repository is otherwise optimized. Since test reflog entries use the same 2005 timestamps as commits, they appear stale and would be purged during maintenance.

The patch modifies four rebase-related test scripts (t34xx range) to disable reflog expiration by setting `gc.reflogExpire` and `gc.reflogExpireUnreachable` to "never". This preserves the reflogs these tests depend on while allowing the geometric maintenance strategy to be tested properly.

The change is well-motivated and follows the series' pattern of addressing test reliability before the final behavior change. It demonstrates careful consideration of how the new maintenance strategy interacts with existing test assumptions.
