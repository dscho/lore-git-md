This is a follow-up discussion in the UTF-8 aliases thread, addressing documentation questions about the syntax for non-alphanumeric alias names. The patch series implementing UTF-8 support for Git config subsections (like `[alias "förgrena"]`) has already been merged into `next` at v7, but some documentation clarifications are still being worked out.

Jonatan Holmgren confirms that the example alias `"rätta till"` with a space is intentional, demonstrating that spaces work correctly in the new UTF-8 alias syntax. He explains that users would type the quoted alias name (or escape the space) when invoking it from the command line, with tab completion working as expected.

The exchange is part of final polish for the feature, addressing Kristoffer Haugsbakk's questions about example clarity in the documentation. While the core functionality is working, there remains a more serious regression with dot-prefixed aliases that will need separate attention. This particular email focuses narrowly on confirming the intended behavior of space-containing aliases in the documentation examples.
