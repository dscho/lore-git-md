This is a follow-up in an RFC thread about changing the default behavior of the experimental `git repo info` command (part of a GSOC project). The original proposal suggested showing all fields when no arguments were given, but Junio Hamano strongly opposed this as violating Git's plumbing command principles - plumbing commands should output only explicitly requested data for scripting predictability.

The contributor (SoutrikDas) acknowledges Junio's feedback, recognizing they were unaware of the distinction between plumbing and porcelain commands. Junio's position is clear: commands must remain predictable by only outputting what is explicitly requested (zero arguments means zero output). This appears to settle the design question, as the maintainer's plumbing discipline stance overrides any convenience arguments for interactive use.

The exchange demonstrates a new contributor learning Git's design norms through maintainer feedback. While the technical change was simple (a conditional in `builtin/repo.c`), the more significant outcome is establishing that this experimental command will follow established plumbing conventions rather than adopting porcelain-like defaults. The thread shows the project's strong preference for consistency with existing patterns over local convenience, even for new commands.
