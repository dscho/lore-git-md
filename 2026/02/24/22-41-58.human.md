This is a follow-up in the UTF-8 config subsections thread, addressing a memory leak in the alias listing functionality. Junio C Hamano confirms Jacob Keller's diagnosis of a leak in `list_cmds()` where alias values stored in the string list's util field weren't being freed. The fix is straightforward - changing `string_list_clear(&list, 0)` to use `free_util=1`.

Junio notes this appears correct but points out a similar potential leak in `list_cmds_by_config()` which also handles the util field without proper cleanup. The thread shows the project's typical attention to detail in memory management, with multiple contributors verifying and expanding on the original report. This is one of three remaining issues (along with dot-prefixed alias handling and documentation formatting) before the UTF-8 subsection series can be finalized.
