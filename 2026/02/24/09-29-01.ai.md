Feature patch adding configurable cover letter formatting to `git format-patch`. This is the first of two patches in a revised series that follows up on Jeff King's (Peff) review of the initial RFC.

The patch introduces a new `--cover-letter-format` option that allows specifying how commit lists appear in cover letters. The option accepts either "shortlog" (the current behavior) or a format string prefixed with "log:" (e.g. "log:%s (%an)"). The implementation uses `repo_format_commit_message()` for one-off formatting without global state, addressing Peff's earlier concerns about API usage.

Key changes from v1:
- Dropped the NULL handling patch that was controversial in the initial series
- Correctly uses `repo_format_commit_message()` instead of the problematic `get_commit_format()`/`pp_commit_easy()` approach
- Maintains backward compatibility by defaulting to shortlog format
- Adds assertions for format string validation

The patch focuses on the command-line interface, while the companion patch (2/2) will add the config option counterpart (`format.commitListFormat`). The implementation is cleanly scoped to `builtin/log.c` with a 65-line diff (49 insertions, 16 deletions).

This provides useful flexibility for patch submitters who want more control over how their changes are presented in cover letters, particularly for maintaining chronological order rather than author grouping. The technical approach now aligns with Git's internal contracts after the v1 review feedback.
