Memory leak fix for alias listing in UTF-8 config subsections work. This is part of the ongoing UTF-8 support for Git configuration subsections (currently in `next` as v7), specifically addressing a memory leak in the `--list-cmds=alias` functionality.

Jacob Keller identified a memory leak (37 allocations totaling 1453 bytes) occurring when listing aliases, caused by the string list being cleared with `free_util=0` while the alias values are stored in the util` field. The proposed fix changes this to `free_util=1` in `git.c`. Junio notes this appears correct but points out a similar potential leak in `list_cmds_by_config()` which also processes the util field without proper cleanup.

The issue stems from the new UTF-8 alias handling implementation where alias values are copied into the util field during listing. While the immediate fix is straightforward, Junio's observation suggests the solution may need to be applied more broadly to ensure all code paths handling these alias lists properly free their resources. This is a technical follow-up to the main UTF-8 subsections feature rather than a user-facing change.
