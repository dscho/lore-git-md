Documentation clarification for `git fetch` parallel job defaults. This email from Daniel Beck responds to the ongoing discussion about documenting the behavior of `--jobs=0` and `fetch.parallel=0` in Git's fetch operations. The thread has established that these settings fall back to using `online_cpus()` (the available CPU count) when set to 0, but the original documentation was vague about this behavior.

Daniel offers a user perspective, explaining that he submitted the original patch because as a user he wanted clear guidance on reasonable job counts. While acknowledging the current implementation uses `online_cpus()`, he suggests that if the goal is to maintain flexibility in the implementation, the documentation could use a more abstract term like `--jobs=auto` rather than specifying the CPU-counting behavior. This would preserve the "don't make me think" quality while allowing future optimization strategies.

The email also raises the possibility of using more descriptive names like `--jobs=cpus` if the implementation details are meant to be meaningful to users. The thread remains open while awaiting input from Johannes Schindelin about the original vague documentation was intentional. This represents a thoughtful user perspective in the ongoing documentation improvement effort.
