This is the final patch in a bugfix series addressing pack validation issues with large objects. The patch specifically resolves an infinite loop in `git fsck` that could occur when verifying large objects that exist in multiple packfiles (one corrupt, one valid). 

Patrick Steinhardt explains that the fix works by directly creating object streams via `packfile_read_object_stream()` rather than going through the MRU cache, which was causing the infinite loop. He notes that while an earlier test case from brian m. carlson also happened to trigger this bug, he added a more reliable test in t1450-fsck.sh that specifically demonstrates the problematic scenario.

Junio Hamano confirms the fix works with both test cases. The series has gone through multiple iterations (v2 and v3) with feedback from Jeff King, Eric Sunshine, and Junio incorporated. The changes improve Git's ability to reliably verify large objects across multiple packs while maintaining clear error reporting about which pack contains corruption.

This represents a significant improvement in packfile validation reliability, particularly for repositories with large objects. The technical work is complete and ready for merging.
