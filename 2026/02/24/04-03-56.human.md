Bugfix patch addressing a NULL pointer dereference in `commit_format_is_empty()` discovered during implementation of configurable cover letter formats. This is the first of three patches in a series introducing flexible formatting for `git format-patch` cover letters.

The issue occurs when checking if a user-specified format string exists - the function incorrectly dereferences `user_format` before checking if it's NULL. The fix changes the pointer check to avoid the crash. This is a straightforward correctness fix with no behavior change when the pointer is valid.

The patch is part of a larger effort to make cover letter commit lists configurable via printf-style format strings, following maintainer Junio C Hamano's design requirements. This particular fix was uncovered during that implementation work. The change is minimal and focused, touching only the NULL check in `pretty.c`.

While this is a simple one-line fix, it's notable that it was caught during development of a new feature rather than being reported as a standalone bug. The patch follows Git's standard style and includes a clear commit message explaining both the problem and solution. It provides a solid foundation for the subsequent patches that build the new formatting functionality.
