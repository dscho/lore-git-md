This is a bugfix patch for `git send-email` that improves the handling of character encoding prompts when sending emails with non-ASCII content. The patch comes from first-time contributor Shreyansh Paliwal and has gone through several iterations with review feedback.

The core issue is that the current prompt for specifying character encodings can be misinterpreted as a yes/no question, leading users to accidentally enter "y" which then gets incorrectly used as the charset name. The patch makes several improvements:

1. Changes the prompt wording from "Which 8bit encoding should I declare [UTF-8]?" to the clearer "Declare which 8bit encoding to use [default: UTF-8]?"
2. Replaces a length-based charset validation heuristic with proper semantic validation using Perl's `Encode::find_encoding()`
3. Improves the warning message when an invalid charset is entered
4. Maintains backward compatibility while making the flow more intuitive

The patch has been through multiple rounds of review with input from Ben Knoble, Philip Oakley, and maintainer Junio Hamano. In this v2, Shreyansh addresses Junio's style feedback by adding explicit braces in if-else blocks. Junio notes a test inconsistency but indicates readiness to integrate the change once that's resolved.

This appears to be a well-motivated improvement to a real usability issue, with careful attention to review feedback. The changes are focused and maintain backward compatibility while making the interface more robust. The patch is nearing readiness for integration.
