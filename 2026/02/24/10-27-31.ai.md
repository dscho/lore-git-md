This is a bug report from Patrick Steinhardt regarding a regression in Git's alias handling introduced by Jonatan Holmgren's UTF-8 subsection alias support. The issue affects an edge case where aliases with leading dots (like `.foobar`) worked previously but now fail due to the new subsection-based alias parsing.

The regression breaks existing workflows, notably Johannes Schindelin's "shears" script which creates temporary aliases with leading dots. Patrick provides a test case demonstrating the issue and notes this was likely an unintended side effect rather than a deliberate design choice in the original patch.

The core technical conflict is between the new subsection-based alias syntax (which treats dots as subsection delimiters) and the previous behavior that allowed dots in alias names. This affects real-world usage, though the specific case is admittedly esoteric. The thread context shows the original UTF-8 alias work is already merged to `next` with only minor documentation issues remaining, making this a late-discovered regression.
