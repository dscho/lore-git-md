This is a feature patch series adding `--trailer` support to `git rebase`, allowing users to automatically add trailers (like Signed-off-by) to commit messages during rebase. The series refactors trailer handling to avoid fork/exec overhead and makes the functionality available across multiple commands.

The series has gone through 7 iterations, with v7 rebased on current master. It splits out a new patch to handle `--trailer` parsing consistently in `git commit` and `git tag`, and restores the original `--in-place` behavior via tempfile+rename. The implementation now validates trailer arguments early and drops some redundant rebase state handling.

Key technical points:
- First 4 patches refactor trailer handling into reusable in-process helpers
- Final patch adds `--trailer` to rebase (merge backend only)
- Includes new test file `t/t3440-rebase-trailer.sh` with 147 lines of tests
- Affects multiple commands (rebase, commit, tag) but focuses on rebase integration

The patch appears well-considered after multiple rounds of review, with thorough test coverage. The changes touch core trailer handling code, so careful review of the refactoring would be warranted, but the approach of consolidating trailer processing seems sound. The rebase integration is currently limited to the merge backend, which the commit message explicitly calls out as a known limitation.
