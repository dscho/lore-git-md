This is part 10/17 of Taylor Blau's series implementing `git multi-pack-index compact` functionality with bitmap support. The patch removes a key limitation in the MIDX format that was preventing efficient compaction of MIDX layers.

The core issue is that MIDX v1 required packs to be stored in lexicographic order, which created problems when trying to combine adjacent MIDX layers while preserving bitmap compatibility. This patch introduces MIDX v2 format which relaxes this ordering constraint. Instead of requiring sorted packs, it lazily builds a sorted index when needed for pack lookups.

The change is backward compatible - older Git versions will still work with MIDX v1 files, and new versions can read both formats. The implementation adds a version field to the MIDX header and makes the pack ordering behavior version-dependent. Tests are updated to verify the new behavior while maintaining checks for v1 format requirements.

This is a well-motivated change that enables the compaction functionality being added in the rest of the series. The patch includes thorough documentation updates and test coverage. As part of a larger technical effort that has already undergone multiple rounds of review, this appears ready for merging.
