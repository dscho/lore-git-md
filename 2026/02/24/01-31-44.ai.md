Feature implementation for Linux fsmonitor using inotify, bringing parity with existing Windows and macOS backends. This is the fifth iteration of the patch, now including meson build system integration and addressing all previous review feedback.

The implementation uses inotify to monitor filesystem events, with careful handling of directory renames via IN_MOVED_FROM/TO event pairs. Key aspects include:
- Non-blocking inotify_init1 with O_NONBLOCK
- Bidirectional watch descriptor to path mappings using hashmap
- Dynamic handling of directory creation/deletion/renames
- Remote filesystem detection via statfs()
- Fallback to $HOME/.git-fsmonitor-* for socket when .git is remote

The patch has undergone extensive stress testing across various scenarios including parallel file operations, deep nesting, rapid renames, and sustained load. Two small memory leaks remain (512-byte during startup and 40-byte in IPC handling) but are considered non-blocking. 

The implementation builds on prior work from Eric DeCosta and Marziyeh Esipreh, addressing all review comments from PRs #1352 and #1667. Changes since v4 include a fix for crashes during rapid nested directory creation and additional stress testing. The patch is now integrated with meson builds and includes documentation updates about inotify watch limits.
