Test infrastructure patch in Patrick Steinhardt's series to make geometric repacking the default maintenance strategy. This third patch addresses an interaction between the test suite's hardcoded dates and reflog expiration that would surface when switching from "gc" to "geometric" maintenance.

The patch modifies four rebase-related test scripts (t34xx range) to disable reflog expiration. The issue stems from Git's test suite using fixed 2005 timestamps - which makes all reflog entries appear immediately stale under the geometric strategy's more aggressive expiration. The current "gc" strategy coincidentally avoided this by skipping maintenance when the object database was already optimized.

Each modified test now sets `gc.reflogExpire` and `gc.reflogExpireUnreachable` to "never" in their setup. This preserves reflogs that the tests rely on, particularly for verifying rebase behavior. The change is mechanical but necessary - the geometric strategy's independent task evaluation would otherwise expire these test reflogs immediately.

This continues the pattern from earlier patches in the series where infrastructure is hardened before the final behavior change. The patch maintains the careful progression from test reliability (patches 1-3) through to the actual strategy switch (planned for patch 8). Reviewers familiar with the test suite and maintenance machinery (like Derrick Stolee and Justin Tobler) will likely find this a straightforward preparation step.
