RFC patch series (v1->v2) for experimental `git repo info` command (GSOC "Improve repo" project by SoutrikDas) addressing behavior when no fields specified. Original plumbing-style design (Phillip Wood) showed nothing by default. V2 proposed showing all fields when either `--all` given OR no arguments, but Junio C Hamano strongly opposed this as violating Git's plumbing command principles (zero arguments must mean zero output for scripting). K Jayatheerth reinforces this by pointing contributor to "Plumbing and Porcelain" chapter in Pro Git book, confirming maintainer's stance that new commands must follow established plumbing conventions regardless of porcelain convenience. Thread demonstrates GSOC contributor learning Git's design norms through community feedback, with technical implementation (simple conditional in `builtin/repo.c`) now clearly constrained by plumbing behavior requirements. Design question settled - experimental command will produce no output by default, maintaining consistency with Git's plumbing commands despite initial interactive-use arguments. Community consensus affirms Junio's position as final, closing discussion on this aspect.
