RFC patch series (v1->v2) for experimental `git repo info` command (GSOC "Improve repo" project by SoutrikDas) addressing behavior when no fields specified. Original plumbing-style design (Phillip Wood) showed nothing by default. V2 proposed showing all fields when either `--all` given OR no arguments, but Junio C Hamano strongly opposed this as violating Git's plumbing command principles (zero arguments must mean zero output for scripting). K Jayatheerth reinforced this by pointing contributor to "Plumbing and Porcelain" chapter in Pro Git book, confirming maintainer's stance that new commands must follow established plumbing conventions regardless of porcelain convenience. Lucas Seiki Oshiro further endorsed this position, reinforcing the educational value of Pro Git's documentation. Contributor SoutrikDas has now acknowledged the community feedback and accepted the design constraint that the command must produce no output by default, maintaining consistency with Git's plumbing command conventions. Technical implementation in `builtin/repo.c` will proceed under these guidelines, with the Pro Git reference having successfully conveyed Git's architectural philosophy to the GSOC participant. Thread demonstrates community consensus affirming Junio's position as final, with multiple participants (Jayatheerth, Oshiro) providing supporting documentation and pedagogical context to reinforce the maintainer's guidance on plumbing command conventions. Design question settled - experimental command will show nothing by default, maintaining scripting-oriented behavior.
