This is the fifth patch in a 7-part series adding `--trailer` support to `git rebase`. The patch implements the actual rebase integration after the preparatory refactoring in earlier patches.

The patch adds a `--trailer=<trailer>` option to `git rebase` that appends specified trailers (like Signed-off-by) to each rewritten commit message. The implementation:
- Only works with the merge backend (rejects --apply)
- Implies `--force-rebase` to rewrite fast-forwarded commits
- Validates trailer arguments early before starting rebase
- Handles trailer insertion during both non-interactive and interactive rebases
- Preserves trailers through conflict resolution
- Properly handles fixup/squash commands in interactive rebase
- Adds extensive test coverage (147 lines) for error cases and various rebase scenarios
- Updates documentation to describe the new option

The implementation builds on the refactored trailer infrastructure from earlier patches, using the new `amend_strbuf_with_trailers()` helper. The patch maintains backward compatibility while adding the new functionality.

Key technical details:
- Adds `trailer_args` to `struct rebase_options` and `struct replay_opts`
- Stores trailers in `rebase-merge/trailer` state file
- Uses `validate_trailer_args()` for early validation
- Updates sequencer to apply trailers during commit message rewriting
- Handles edge cases like empty trailers and duplicate keys
- Preserves existing trailer behavior (replace vs append policies)

The patch appears well-tested and follows the pattern of other rebase option additions. It completes the series' goal of enabling in-process trailer manipulation during rebase operations.
