This is a response from the Git maintainer to a feature proposal about selective file/folder merging between branches. Junio C Hamano explains why the proposed feature could lead to problematic scenarios, despite its surface appeal.

Junio argues that a merge commit represents a complete integration of two branches' states, and selectively merging only parts of a branch while recording it as a full merge would create confusion. He describes how this could cause issues when trying to track whether fixes were actually merged, and how it would mislead tools that check branch relationships. The maintainer suggests that while users can achieve partial merges today using `git merge --no-commit` followed by manual adjustments, they should carefully consider the implications before doing so.

The response effectively shuts down the proposal by highlighting fundamental problems with the concept rather than technical implementation challenges. Junio's position carries significant weight as the project maintainer, making this unlikely to progress further without a substantially different approach that addresses these conceptual concerns.
