This is a maintainer comment on the `git fast-import` feature patch series that would add a `re-sign-if-invalid` mode for handling invalid commit signatures during import.

Junio C Hamano weighs in on brian m. carlson's technical review of the series, agreeing with the recommendation to make the feature explicitly fail (rather than silently ignore) when encountering `extensions.compatObjectFormat` cases. This conservative approach makes sense given the experimental nature of the hash interoperability work. Junio also implicitly endorses brian m. carlson's suggestion to add more thorough test coverage, particularly for tag handling which has special cases in the signature conversion logic.

The exchange shows the series is receiving careful scrutiny from both the maintainer and the project's hash algorithm expert, with clear technical direction emerging for the next iteration. The feature appears well-motivated but needs to properly handle edge cases before merging.
