This is patch 16/17 in Taylor Blau's series implementing MIDX compaction functionality, a feature targeting Git's multi-pack-index subsystem. The patch introduces the core `git multi-pack-index compact` command that combines adjacent MIDX layers while preserving the chain structure and bitmap compatibility.

The compaction feature addresses several limitations of the existing `--stdin-packs` approach, which couldn't preserve the MIDX chain or maintain valid bitmaps for subsequent layers. The implementation:

1. Adds a `compact` subcommand that takes range endpoints (MIDX checksums) to specify which layers to combine
2. Introduces `fill_packs_from_midx_range()` to walk backwards through the compaction range while preserving pseudo-pack order
3. Handles pack ID adjustments during fanout layer computation to maintain original pack_int_id mappings
4. Includes validation to prevent self-compaction and ensure proper ancestry relationships
5. Adds comprehensive tests covering lex/non-lex pack ordering and error cases

The patch builds on earlier infrastructure from the series including the new `struct write_midx_opts`, `midx_pack_perm()` helper, and version-aware pack ordering. Test coverage verifies both happy paths and edge cases like missing endpoints and version compatibility.

Key technical details:
- Requires MIDX v2 format due to fundamental v1 limitations
- Preserves pseudo-pack order except for preferred packs
- Uses new midx_fanout_add_compact() helper for range-based fanout handling
- Maintains bitmap validity for layers after the compaction range
- Adds t5335 test script with object uniqueness verification

The implementation appears thorough with careful attention to edge cases and backward compatibility. As the penultimate patch in the series, this completes the core functionality with all prior review feedback addressed.
