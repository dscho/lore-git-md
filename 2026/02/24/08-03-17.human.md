This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The patch represents the fifth iteration of this work, now in final debugging phase with Patrick Steinhardt investigating a test hang in CI - the last remaining issue before merging.

The implementation enables faster status operations by watching filesystem events rather than performing full directory scans. It uses inotify with recursive directory watching, maintains bidirectional watch descriptor/path mappings, and handles directory renames through IN_MOVED_FROM/TO event cookies. The code detects and rejects remote filesystems (NFS/SMB) via statfs() unless explicitly allowed, and falls back to $HOME/.git-fsmonitor-* for IPC sockets when .git is remote.

Patrick's review identifies several areas needing attention: the commit message should better explain why inotify was chosen over alternatives like fanotify, some memory leak fixes should be split into separate commits, and there are opportunities to deduplicate code with the macOS implementation. He raises technical questions about potential race conditions in watch handling and event ordering that may need addressing.

The patch has been stable in production for two months according to author Paul Tarjan, with only two small known memory leaks remaining (512-byte during daemon init and 40-byte in IPC handling). These are considered non-blocking given their size. The implementation is technically complete and in Junio's 'seen' branch, awaiting resolution of the CI test hang before final submission.
