This is a feature patch for `git fast-import` that adds a new `re-sign-if-invalid` mode to handle invalid commit signatures during import. The patch builds on prior work allowing signature stripping and is part of a two-patch series (the first being a cleanup patch that has already been acked).

The core change allows `git fast-import --signed-commits=re-sign-if-invalid` to replace invalid signatures with new ones using the user's current signing key, rather than just stripping them. The implementation touches signature handling in fast-import.c and adds the new mode to gpg-interface.c, with test coverage for GPG/X.509/SSH signatures.

Review feedback from Patrick Steinhardt and Christian Couder has identified several areas for improvement in the next version: better documentation of the current limitation around `extensions.compatObjectFormat` (which is ignored when re-signing), clearer warning messages when signatures are replaced, and potential future support for specifying which key to use (similar to `git commit --gpg-sign`). The patch appears technically sound but will see minor revisions based on the review discussion.

This is a useful addition for workflows that need to preserve signed commits during import while ensuring signature validity, though users should be aware of the current limitations regarding compatibility hashes. The thorough test coverage and careful review process suggest this will be a robust addition once the documentation and warning messages are refined.
