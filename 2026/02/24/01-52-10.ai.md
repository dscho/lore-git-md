Bugfix for `git for-each-repo` worktree behavior. Derrick Stolee confirms Matthew Gabeler-Lee's report that `for-each-repo` incorrectly propagates the `GIT_DIR` environment variable when run from a worktree, causing child Git processes to operate on the wrong repository. The issue occurs because the worktree's `GIT_DIR` leaks into the command execution context, making targeted repository operations unintentionally affect the parent repository instead. Stolee acknowledges this as a subtle oversight in the worktree variable handling and indicates a fix is in progress (GitGitGadget PR #2056), though the patch series hasn't been sent to the list yet. This appears to be a straightforward correction of an edge case in worktree environment handling, with test coverage being added. The bug affects current master but doesn't appear to have widespread impact yet, likely because `for-each-repo` is a relatively new command (added in Git 2.30) and worktree usage exposes this particular environment variable propagation quirk.
