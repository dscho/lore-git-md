This is a feature patch adding Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations through filesystem event watching rather than full directory scans.

Patrick Steinhardt provides detailed review feedback on the fifth iteration of this work. He raises several technical concerns about the implementation, including potential race conditions in watch registration, memory leak fixes that should be split into separate commits, and questions about error handling edge cases. The review focuses on the inotify-specific portions of the code, particularly around directory watching and event processing.

Key technical points from the review include concerns about EEXIST handling during concurrent directory renames, whether deleted directory watches are properly unregistered, and potential event ordering issues. Steinhardt also notes opportunities to deduplicate code with the macOS implementation and suggests improvements to the commit message structure.

The review represents the final round of feedback before merging, with Steinhardt now investigating a test hang in CI that appears to be a race condition in the fsmonitor daemon's test behavior. This is the last remaining issue, as the implementation has been stable in production for two months across a large deployment according to the original author Paul Tarjan.

The patch touches several areas:
- New files in compat/fsmonitor/ for Linux-specific implementations
- Memory leak fixes in builtin/fsmonitor--daemon.c
- Test additions in t/t7527-builtin-fsmonitor.sh
- Build system changes to support the Linux backend

The review suggests this is nearing readiness for merging pending resolution of the CI test hang, with all major technical concerns from previous iterations having been addressed. The remaining issues are relatively minor - two small memory leaks and the test race condition - but the review maintains Git's high standards for correctness in filesystem monitoring code.
