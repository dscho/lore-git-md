This is a follow-up discussion about the ongoing documentation cleanup effort to replace the `{litdd}` macro with `\--` in Git's documentation. The original patch proposed this mechanical change to simplify the documentation toolchain and improve HTML output consistency, but maintainer Junio C Hamano expressed skepticism about whether the benefits justified the churn.

Author Michael Ryzhikov now provides a more detailed rationale, noting that `{litdd}` was originally introduced over a decade ago to work around AsciiDoc syntax changes and converter bugs. He reports successful local testing with `make all doc` using `\--` and questions whether the legacy workaround is still needed. The email includes an extensive list of historical mailing list references about `{litdd}` usage and poses several practical questions about testing requirements across platforms.

The discussion remains open, with the key question being whether the claimed maintainability benefits outweigh the mechanical changes required. No other reviewers have weighed in yet beyond Junio's initial skepticism. The thread touches on broader documentation workflow questions, including whether such discussions should happen on Discord rather than the mailing list.
