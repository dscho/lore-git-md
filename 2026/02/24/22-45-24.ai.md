This is a follow-up discussion in the `git fast-import` feature series that adds a `re-sign-if-invalid` mode for handling invalid commit signatures during import. The thread has progressed with technical reviews from Patrick Steinhardt and brian m. carlson, and now includes input from maintainer Junio C Hamano.

The core technical discussion revolves around how to handle `extensions.compatObjectFormat` when re-signing commits. brian m. carlson strongly recommends either properly implementing hash algorithm conversion (using `repo_oid_to_algop` and `convert_object_file` APIs) or explicitly failing when encountering this experimental feature, rather than silently ignoring it. Junio concurs with this conservative approach, agreeing that dying with an unsupported message would be prudent given the experimental nature of the compatibility format.

brian m. carlson also suggests adding more rigorous test coverage, specifically recommending a test similar to t7004's "signed tag with embedded PGP message" if the feature will be applied to tags as well as commits. This would help ensure proper handling of signature generation cases that require special treatment in the interoperability code.

The exchange indicates the series is nearing readiness, with the remaining work being:
1. Implementing proper handling (or explicit rejection) of `extensions.compatObjectFormat`
2. Adding the recommended test coverage for tag signatures
3. Potentially addressing other minor feedback about warning messages and function naming

Junio's brief but authoritative "Thanks!" suggests he's following the discussion and approves of the direction being taken, though he hasn't yet indicated whether he'll queue the series for integration. The technical concerns raised are substantive but appear resolvable, and the feature itself seems uncontroversial as long as these edge cases are properly handled.
