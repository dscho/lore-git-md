This is a bugfix addressing incorrect diffstat width calculation when line prefixes contain ANSI color codes, part of a GSoC contribution. The patch series was prompted by a NEEDSWORK comment from Junio Hamano in commit ce8529b2, which noted the issue with using `strlen()` for display width calculations.

Junio clarifies in this response that while he originally noted the issue (via the NEEDSWORK comment), he doesn't need formal attribution via Reported-by/Suggested-by tags since this was an old observation rather than a recent report. He also provides helpful context about the underlying problem - that ANSI color escape codes in prefixes (like those from `git log --graph`) require proper display-aware width calculation rather than simple string length.

The fix itself (in the first patch) replaces `strlen()` with `utf8_strnwidth()` to properly account for both UTF-8 characters and ANSI escape sequences when calculating display width. The second patch adds regression tests. Junio's response indicates the changes look good, with his comment serving as a clarification rather than a request for changes. This appears to be a straightforward, well-contained fix for a known issue.
