Junio C Hamano weighs in on the RFC discussion about changing the default behavior of the experimental `git repo info` command. He firmly opposes making the command show all fields by default when no arguments are given, countering the usability argument with a strong emphasis on predictability for plumbing commands. 

The maintainer's position is clear: plumbing commands should follow the principle of "you get exactly what you ask for, nothing more" - a consistent behavior that makes them reliable building blocks for scripts. He dismisses the number of fields (currently four) as irrelevant to the design decision and suggests that any UI wanting to show all information can explicitly request it with `--all` or determine when to skip the command call entirely.

This authoritative response from the maintainer effectively settles the debate, reinforcing Phillip Wood's earlier argument for strict plumbing behavior. The thread shows a new contributor engaging with design principles while receiving clear guidance about Git's plumbing/porcelain distinctions. Junio's intervention suggests this RFC is unlikely to proceed as proposed.
