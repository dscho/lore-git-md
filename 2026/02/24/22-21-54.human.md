This is a bugfix patch addressing a memory leak in the UTF-8 alias support series. Jacob Keller reports that the `--list-cmds=alias` functionality introduced in v7 of the series leaks memory because it stores alias values in the string list's util` field but doesn't free them when clearing the list. The leak was detected by AddressSanitizer and affects 37 allocations totaling 1453 bytes.

The fix is straightforward - changing `string_list_clear(&list, 0)` to `string_list_clear(&list, 1)` in `git.c` to properly free the stored alias strings. This is a clear oversight in the original patch that consolidates alias listing logic, where the new `list_aliases()` function stores values but the cleanup wasn't properly updated to match.

This is one of several follow-up issues being addressed in the UTF-8 alias support series, which is currently in `next`. The series has already dealt with empty subsection compatibility and documentation formatting issues, with this memory leak being the latest technical problem to surface. Jacob's report includes the full ASan trace and a minimal fix, making this easy to verify and incorporate.
