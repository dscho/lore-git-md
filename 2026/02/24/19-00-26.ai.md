This is a refactoring patch in Taylor Blau's multi-pack-index compaction series, specifically addressing how pack IDs are enumerated during MIDX writing. The change simplifies the `fill_packs_from_midx()` function by directly iterating over the actual `pack_int_id` range rather than calculating it from an offset.

The patch modifies the loop indices to use the natural pack ID range `[m->num_packs_in_base, m->num_packs_in_base + m->num_packs)` instead of the previous approach that iterated `[0, m->num_packs)` and then added the base offset. This makes the code more straightforward by removing the need for runtime offset calculations when calling `fill_pack_from_midx()`.

The change is purely internal - it doesn't affect functionality but improves code clarity by aligning the iteration with the actual ID values being used. This follows the series' pattern of refining MIDX internals to support the new compaction feature while maintaining backward compatibility. The patch has minimal impact (3-line diff) and builds on the earlier introduction of the `fill_pack_from_midx()` helper in this series.
