This is a test case documenting a bug in the interaction between `receive.denyCurrentBranch=updateInstead` and bare repositories with worktrees. The issue occurs when pushing to a bare repo that has a worktree, if the bare repo's HEAD points to an unborn branch (different from the worktree's branch). Git incorrectly rejects the push with a "Working directory has staged changes" error even when the worktree is clean.

The test demonstrates that the bug exists in both current Git and in the original 2021 implementation by Anders Kaseorg that added worktree support for bare repos. The root cause appears to be in `builtin/receive-pack.c` where the code checks the bare repository's HEAD (via `head_has_history`) rather than the worktree's HEAD when determining whether there are staged changes. This causes it to incorrectly use the empty tree as a base for comparison when the bare HEAD is unborn, leading to false positives about staged changes.

The test is marked as `test_expect_failure` to document the current broken behavior while awaiting a fix. The commit provides useful context about the real-world scenario that uncovered this edge case in the worktree/updateInstead interaction. Key files involved are `builtin/receive-pack.c` and the test script in `t/`. While not a regression in the traditional sense (the behavior appears to have worked correctly), the test serves as an important documentation of the bug and will help verify any future fix.
