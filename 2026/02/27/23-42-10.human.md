This is part 2 of a 5-patch series refactoring Git's oidmap cleanup API. The patch converts `rev-list`'s missing objects tracking to use the new `oidmap_clear_with_free()` function introduced in the first patch.

The change moves the cleanup logic for `missing_objects_map_entry` structures into a dedicated callback function, consolidating what was previously manual cleanup of path strings followed by a generic `oidmap_clear()`. The new approach makes the memory management more explicit and type-safe, particularly important since these entries contain dynamically allocated path strings.

The patch is straightforward - it adds the callback function and updates the cleanup call site. This appears to be a mechanical conversion as part of the larger series, with no behavior changes beyond the internal cleanup mechanism. The series as a whole looks like a well-structured improvement to Git's internal APIs for better resource management.
