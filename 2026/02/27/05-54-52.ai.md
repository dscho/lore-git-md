Feature patch introducing a `pre-add` hook for index validation. This is version 3 of the series, incorporating all technical feedback from maintainer review. The hook runs after `git add` computes the new index state but before committing it to disk, receiving two arguments: the path to the current index file and the lockfile containing the proposed changes.

Key technical details:
- Hook receives stable paths ($1 = index path, $2 = lockfile path)
- Uses new `SKIP_INDEX_CHANGE_HOOK` flag to properly sequence `post-index-change` hook
- Handles mixed-result adds (tracked changes + ignored files) correctly
- Includes comprehensive tests in t/t3706-pre-add-hook.sh
- Documents the hook in both `git-add` and `githooks` man pages

The implementation ensures the original index remains unchanged if the hook rejects the changes. Example use cases shown in tests include blocking `.env` files and secret keys in content. The patch is now in final form pending minor message wording improvements noted by Junio Hamano.
