Thread subject: option parser silently accepts duplicate long options. Thread type: bug report. Originating author: Junio C Hamano.

Core problem: Git's option parsing infrastructure (`parse-options.c`) silently accepts duplicate long-form option names in command option tables, demonstrated by duplicate `--batch-check` in `cat-file` and redundant `--stdin-packs` in `pack-objects`.

Current status: René Scharfe's two-patch series addresses the issue. First patch fixed the concrete `pack-objects` case by removing shadowed `OPT_BOOL` version of `--stdin-packs`. Second patch adds comprehensive runtime verification of option tables via `parse_options_check()`, detecting duplicate long names and numerical options using a `strset`.

Key technical details: Validation now checks for: 1) duplicate long names via `strset`, 2) multiple `OPTION_NUMBER` entries, while maintaining existing short option checks. Jeff King (Peff) provided benchmark data showing validation adds ~10ms overhead for 100,000 options (~100ns/option), comparable to 50-100 syscalls for typical command option counts. Suggested micro-optimization using `strset_add()` return value instead of separate `strset_contains()` call yields 1% improvement in extreme cases, though string allocation remains dominant cost factor. Implementation discussion favors keeping validation always-on rather than DEVELOPER-mode-only.

Open questions: Deployment strategy (always-on vs conditional) remains primary open item. Performance data suggests overhead is negligible for normal usage but could be optimized further if startup time becomes critical.
