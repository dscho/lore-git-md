Feature patch adding configurable cover letter formatting to `git format-patch`. This is part 3/5 of a series that has gone through five iterations and is now ready for merging, with maintainer approval.

The patch introduces a new `--cover-letter-format` option that allows specifying either "shortlog" (the current default behavior) or a custom format string prefixed with "log:". The custom format can use placeholders like `%(count)` (patch number), `%(total)` (series size), `%s` (subject), and `%an` (author name) to create structured cover letters. For example, `--cover-letter-format="log:[%(count)/%(total)] %s (%an)"` produces numbered entries with subject and author.

Implementation includes:
- New `generate_commit_list_cover()` function in `builtin/log.c` to handle custom formats
- Integration with existing cover letter generation in `make_cover_letter()`
- Comprehensive test coverage in `t4014-format-patch.sh` verifying:
  - Custom format strings with subject/author/numbering
  - Shortlog fallback behavior
  - Default behavior when no format is specified
- Bash completion support

The design maintains backward compatibility while providing flexibility. The "log:" prefix requirement (established in earlier discussion) ensures clear distinction between shortlog and custom formats. This patch builds on previous work modularizing shortlog generation into `generate_shortlog_cover_letter()` and implements the core formatting system that was RFC'd in earlier series iterations.

Key technical details:
- Uses `repo_format_commit_message()` for formatting
- Handles memory management for format strings
- Validates format strings and context
- Preserves all existing cover letter features (diffstat, signature, etc.)
- Follows the numbering scheme designed by Jeff King (Peff)

The patch is well-tested and integrates cleanly with the series' other components (documentation, config support, etc.). It represents the production-ready implementation of a feature that has been thoroughly reviewed through multiple iterations.
