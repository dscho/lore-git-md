Performance optimization for `git upload-pack` to reduce lock contention during high-concurrency scenarios. This is a two-patch series from Patrick Steinhardt addressing a bottleneck observed when hundreds of `upload-pack` processes simultaneously write data at multi-gigabit speeds.

The first patch fixes a debug statement that was incorrectly placed, while the second (main) patch reduces lock contention when writing packfile data to pipes. The motivation comes from real-world performance profiling at GitLab, with flame graphs showing the contention clearly. The changes are focused and surgical, touching only `upload-pack.c` with minimal modifications (8 insertions, 3 deletions).

This appears to be a well-motivated optimization targeting a measurable performance issue in high-scale Git server environments. Given Patrick's track record with performance work and the clear evidence provided, this seems like a solid improvement worth reviewing for server operators.
