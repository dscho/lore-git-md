This is the third version of a feature patch introducing a `pre-add` hook, which allows inspecting or rejecting staged changes before they are committed to the index. The hook runs after `git add` computes the new index state but before writing it to disk.

The implementation has been refined through review feedback. Key changes in v3 include:
- Simplified argument passing to the hook (now just the index path and lockfile path)
- Fixed handling of mixed-result adds (tracked modifications combined with ignored paths)
- Added a new `SKIP_INDEX_CHANGE_HOOK` flag to properly coordinate with the `post-index-change` hook
- Improved test coverage with 20+ test cases

The hook provides two paths - the current index and proposed lockfile - allowing hook authors to inspect changes using standard Git tools. Example use cases shown in tests include blocking `.env` files or secret keys from being staged. The hook can be bypassed with `--no-verify` and is not invoked for interactive/patch/dry-run modes.

Maintainer Junio Hamano has confirmed the technical approach and naming, with only final message wording polish remaining before merge. This appears to be a well-considered addition to Git's hook system, with thorough test coverage and clear documentation.
