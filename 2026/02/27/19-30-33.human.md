Feature patch adding object size metrics to `git repo info`, part of a larger series on repository reporting.

This patch (4/11 in v5) extends the repository structure reporting with maximum object size metrics, tracking both inflated and on-disk sizes per object type (commits, trees, blobs, tags) as well as overall maxima. The implementation walks reachable objects to collect these statistics, then exposes them through both human-readable table output and script-friendly key-value pairs.

The patch adds new fields to track maxima in the `object_stats` struct and updates the counting logic to maintain these values during object traversal. Output formatting is added for both display modes, with localized strings for the human-readable table. This builds on the series' goal of providing structured repository information while avoiding shell-outs.

While the patch appears technically sound, it's worth noting this reintroduces structural metrics that were split out in v5's narrowed scope. The implementation follows Git's object handling patterns but may need review for edge cases with very large objects or corrupted repositories. The metrics could be useful for repository analysis tools, though their practical value depends on how often maximum sizes are truly diagnostic versus just reflecting normal repository structure.
