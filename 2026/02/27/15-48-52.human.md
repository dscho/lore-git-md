This is part 1 of a 2-patch series introducing automatic branch prefixing, a feature that automatically prepends the current branch name when creating new branches. The series follows Junio Hamano's feedback to demonstrate utility via command-line first (in part 2) before adding configuration.

The patch adds a `branch.addCurrentBranchAsPrefix` config option that, when enabled, automatically prefixes new branch names with the current branch name (e.g., creating "test" while on "main" produces "main-test"). The implementation supports recursive prefixing (creating "main-test-sub" when on "main-test"). The change affects `git branch`, `git checkout -b`, and `git switch -c` commands.

The motivation is to help projects managing many branches (particularly for backport workflows) by reducing naming overhead. The implementation appears solid with comprehensive test coverage across all affected commands in t2018, t2060, and t3200 test scripts. However, the author's address continues to bounce, raising maintainability concerns, and the feature's broader utility beyond the stated use case remains unvalidated by other list participants.

This is a feature addition that touches core branch creation behavior, so while technically sound, it may warrant discussion about whether this belongs in core Git versus being implemented as a script or alias. The recursive prefixing behavior in particular be a point of discussion.
