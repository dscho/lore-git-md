This is the first patch in a feature series enhancing repository path reporting in `git repo info`. The patch introduces a `struct repo_info` context to thread repository state through the path reporting code, replacing direct access to repository globals. It also adds category-based key expansion, allowing scripts to request groups of related fields (like "layout.*") rather than individual keys.

The changes include:
- New `repo_info` struct to bundle repository state (repo pointer and prefix)
- Conversion of all value-getter functions to use the context
- Category expansion that maps "layout" to all matching "layout.*" keys
- Maintained backward compatibility for explicit key requests
- Clear error reporting for unknown keys/categories

This is part of the larger effort to remove `the_repository` global usage, though the patch doesn't explicitly frame it as such. The implementation appears clean and focused, with all existing tests passing. The category expansion feature seems particularly useful for scripting while keeping the explicit key access for precise control.

The patch builds on Phillip Wood's earlier feedback by improving the internal structure before adding new features, though the path key naming discussion from v4 reviews remains unresolved. This foundational change will support the path reporting features in subsequent patches while making the code more maintainable.
