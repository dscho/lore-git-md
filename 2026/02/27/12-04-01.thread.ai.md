Thread identity: Bug report about `git clone --bundle-uri` failing to follow HTTP redirects when fetching bundle files, affecting real-world use cases like cloning the Linux kernel.

Core problem: The `--bundle-uri` feature silently fails when encountering HTTP redirects for bundle files, unlike common tools like wget which follow redirects by default. This breaks workflows for major repositories like the Linux kernel that use redirects for bundle distribution.

Key technical details:
- The Linux kernel's advertised bundle URI `https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/clone.bundle` redirects to a mirror location
- Git's HTTP client (curl) doesn't follow redirects by default in this context
- Current behavior only shows a warning without indicating the root cause
- This contradicts the expected behavior for bundle URIs which should "just work" like other Git operations

Impact: The issue affects the Linux kernel's recommended cloning workflow and potentially other public repositories using similar redirect-based bundle distribution. The report comes from Xavier Morel and includes references to kernel.org's official documentation about bundle usage. No patch is proposed yet - this is an initial bug report identifying the problem behavior.
