This thread has finalized a two-patch series introducing type-safe cleanup for oidmap structures via a new `oidmap_clear_with_free()` API. The series was narrowed down from a broader scope after maintainer feedback, focusing only on converting the rev-list (missing_objects) and odb (replace_map) use cases while definitively dropping other potential conversions.

The rev-list patch being discussed here converts the `missing_objects` map to use the new API, introducing a callback that properly handles cleanup of both path strings and entry structs. The implementation changes the path field from const to mutable to enable proper freeing, while maintaining the same behavior through explicit cleanup semantics. Both Junio and Patrick Steinhardt have approved the approach, with the callback name updated in v3 per Patrick's request. Comprehensive unit tests verify the API behavior.

The series appears ready for merging, with all maintainer feedback addressed and the scope clearly defined. While one minor question about `map->map.cmpfn` remains open, it doesn't block these approved conversions. Seyi Kuforiji, the author, has incorporated all feedback including adding new test coverage in the final iteration.
