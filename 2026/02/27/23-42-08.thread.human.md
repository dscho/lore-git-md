This thread documents a 5-patch series that refactors Git's oidmap cleanup mechanism to use explicit, type-safe memory management via callbacks rather than implicit structure assumptions. The series introduces a new `oidmap_clear_with_free()` API that accepts a callback for entry freeing, using the `container_of` pattern for safe structure access.

Junio C Hamano has reviewed and approved the core API change and three of the four subsystem conversions (rev-list, list-objects-filter, and odb), each following the same careful pattern of minimal diffs and maintained behavior. The final patch now converts the sequencer subsystem, introducing a `free_string_entry()` helper. While Junio notes this particular change offers little immediate benefit since the string entries are simple, it maintains consistency with the series' approach and would ease future maintenance if the entries grow more complex.

The only remaining open question is Junio's query about the `map->map.cmpfn` check requirement in the foundational API. With all planned conversions now submitted and most already approved, the series appears ready for merging once this final point is addressed. The work demonstrates a thorough, maintainer-approved approach to making memory management more explicit while preserving backward compatibility through the existing `oidmap_clear()` wrapper.
