Seyi Kuforiji's series refactoring Git's oidmap cleanup API to replace the boolean-flag approach with explicit callback functions has been progressing well, with conversions already completed for the rev-list, list-objects-filter, odb, and sequencer subsystems. Each patch introduced type-safe cleanup callbacks while maintaining existing behavior - until Junio spotted an issue in the rev-list conversion.

In his review of patch 2/5, Junio pointed out that while the new `free_missing_objects_entry()` callback properly handles the `missing_objects_map_entry` structures, it fails to free the path strings they contain - a regression from the original code that did clean up both. This is a substantive concern about resource management correctness in what was meant to be a straightforward API modernization. The oversight suggests the conversion needs revisiting to ensure all nested resources are properly handled in the new callback-based approach. Seyi will need to address this before the series can proceed further.
