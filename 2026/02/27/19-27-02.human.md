This is a bugfix patch targeting Git's option parsing infrastructure, specifically addressing silent acceptance of duplicate long options. It's the second in a two-patch series responding to Junio Hamano's report of this issue.

René Scharfe extends the existing duplicate-checking in `parse-options.c` to catch duplicate long option names and numerical options, similar to how it already checks for duplicate short options. The implementation uses a `strset` to track seen long names and a boolean flag for numerical options. While the check adds some overhead, René notes this is consistent with other existing checks in the parser.

The patch follows naturally from the thread's earlier discussion where Junio identified the general issue and René fixed a concrete instance in `pack-objects`. This second patch provides the systematic solution Junio suggested, though it leaves open whether to make these checks always-on or developer-build-only - a question René explicitly leaves for others with stronger benchmarking skills.

The change is straightforward and well-contained, touching only the option parsing validation logic. Given René's reputation for careful, hygienic patches and the clear motivation from Junio's original report, this looks like a solid improvement to Git's internal consistency checking.
