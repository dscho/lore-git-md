This is a bug report about `git clone --bundle-uri` not following HTTP redirects when fetching bundle files. The author, Xavier Morel, demonstrates the issue by attempting to clone the Linux kernel using its advertised bundle URI, which results in failure because Git's underlying HTTP client (curl) does not follow the redirect by default.

The key technical details are:
- The bundle URI `https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/clone.bundle` redirects to a mirror location
- Git currently fails silently with only a warning when the redirect isn't followed
- The behavior differs from common tools like wget which follow redirects by default
- The issue affects real-world use cases like the Linux kernel's recommended cloning workflow

This appears to be a legitimate usability issue in the bundle URI feature, particularly for public repositories that use redirects for their bundle distribution. The patch doesn't propose a solution but clearly identifies the problem behavior and its impact on a major real-world use case (Linux kernel clones). The report is well-documented with references to kernel.org's official documentation about bundle usage.
