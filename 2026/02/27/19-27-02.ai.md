This is a bugfix patch targeting Git's option parsing infrastructure. It's the second in a two-patch series addressing the issue of duplicate long option names being silently accepted.

René Scharfe builds on Junio Hamano's initial report by adding comprehensive duplicate detection for long option names and numerical options in `parse-options.c`. The patch introduces checks using a `strset` to track long names and a boolean flag for numerical options, similar to the existing short option validation.

The implementation adds runtime verification that:
1. Long option names aren't duplicated across a command's option table
2. Only one `OPTION_NUMBER` can be specified per command
3. Maintains the short option duplicate checking that was already present

The author notes there's a performance cost to these checks but leaves optimization (like making them DEVELOPER-mode only) as future work. The patch includes the necessary `strmap.h` include and proper cleanup of the `strset` to avoid memory leaks.

This is a direct response to the concrete cases Junio identified (duplicate `--batch-check` in `cat-file` and redundant `--stdin-packs` in `pack-objects`), providing a systematic solution rather than just fixing individual instances. The change is focused and well-contained, touching only `parse-options.c` with clear additions to the validation logic.
