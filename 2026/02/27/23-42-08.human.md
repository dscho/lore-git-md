This is a refactoring patch series that improves the cleanup mechanism in Git's oidmap (object ID map) data structure. The series introduces a new `oidmap_clear_with_free()` function to replace the less explicit `oidmap_clear(map, 1)` pattern, which previously relied on an implicit assumption that entries should be freed with a simple `free()` call.

The key change is moving from a boolean flag (where `1` meant "free entries") to an explicit callback-based approach. This makes the cleanup semantics clearer and more flexible, particularly when oidmap entries are embedded in larger structures. The series then updates several call sites across the codebase to use this new API.

The changes touch multiple subsystems including rev-list, object filtering, object database handling, and the sequencer. Each patch in the 5-part series focuses on migrating one usage site to the new API while maintaining the appropriate cleanup behavior. The implementation looks thorough, with test updates included to verify the new behavior.

This appears to be a well-motivated cleanup that improves code clarity and maintainability. The series follows Git's typical pattern of introducing a new API while maintaining backward compatibility, then migrating callers to the new approach. The changes are focused and mechanical, making them relatively low-risk while providing clear benefits for future development.
