This is a bug report about `git clone --bundle-uri` not following HTTP redirects when fetching bundle files. The author, Xavier Morel, encountered the issue when trying to clone the Linux kernel repository using its advertised bundle URL, which redirects to a mirror. Git fails silently with only a generic warning message, while tools like wget would follow the redirect automatically.

The core problem is that Git's underlying HTTP transport (using libcurl) isn't configured to follow redirects by default when fetching bundles, unlike regular clone/fetch operations. This creates a poor user experience since the failure mode is opaque and the workaround (manually resolving the redirect chain) defeats the purpose of the bundle-uri feature.

The report includes specific reproduction steps using the Linux kernel's public bundle URL and notes that this affects one of the few prominent real-world use cases for bundle-uri. The patch would need to modify Git's bundle-uri HTTP handling to match the redirect behavior of other Git HTTP operations.
