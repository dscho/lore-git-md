This is the final patch in a 5-part series refactoring Git's oidmap cleanup API, converting the sequencer subsystem to use the new callback-based memory management. The series replaces the old `oidmap_clear(map, 1)` pattern with explicit `oidmap_clear_with_free()` calls and dedicated cleanup functions.

The patch focuses on the sequencer's string_entry handling, introducing a new `free_string_entry()` helper that properly frees each `struct string_entry` via the container_of pattern. It updates two oidmap cleanup sites in `make_script_with_merges()` to use the new API, maintaining identical behavior while making the memory management explicit. The change is straightforward - an 8-line addition for the helper function and 2-line modification of the cleanup calls.

This completes the series' migration of all oidmap cleanup sites to the new API. The implementation follows the same pattern seen in previous patches: type-safe callback functions that know how to free their specific entry types, replacing the old boolean-flag approach that required the map to know about its entries' memory layout. The series as a whole improves code organization and API contracts while preserving behavior, with each patch handling a distinct subsystem (rev-list, list-objects-filter, odb, and now sequencer). Test coverage comes from existing sequencer tests, as the change is purely an internal cleanup with no user-visible effects.
