Feature proposal for automatic branch name prefixes, now with command-line option.

This is a resubmission of Yoann Valeri's proposal to automatically prefix new branch names with the current branch name (e.g., creating "test" while on "main" would produce "main-test"). The v2 series adds a `--no-prefix` command-line option in response to Junio Hamano's feedback that new configuration options should first be introduced as command-line flags to demonstrate real-world utility.

The implementation adds a new `branch.addCurrentBranchAsPrefix` configuration option and corresponding `--no-prefix` flag to override it. The prefixing behavior is recursive - creating a branch while on "main-test" would produce "main-test-sub". Tests cover the behavior in `git branch`, `git checkout -b`, and `git switch -c` commands.

Junio previously raised concerns about configuration proliferation and suggested validating the concept via command-line flags first. While this version adds the flag, it still introduces the config option in the same series, which may not fully address the maintainer's concerns. The original motivation cites benefits for projects needing backports across many branches, but the patch doesn't include real-world usage data to support the need.

A separate issue remains - the author's email address is bouncing, which Junio noted needs to be fixed before the patch can be considered. The technical implementation appears sound with thorough test coverage, but the conceptual approach still needs more vetting at the command-line level before progressing to configuration.
