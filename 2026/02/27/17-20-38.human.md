This is the final iteration of a bugfix addressing submodule fetching behavior that incorrectly assumed all submodule remotes are named "origin". The patch series introduces a new `get-default-remote` helper command to properly handle submodules with differently-named remotes, fixing cases where `git fetch --recurse-submodules` would fail.

The solution has undergone thorough review across four versions, with feedback from Junio Hamano, Jacob Keller, and Ben Knoble addressing both technical implementation and test coverage. Key improvements in v4 include removing unnecessary `parse_options()` from the helper (as suggested by Junio), fixing test portability issues around branch name assumptions, and ensuring consistent test file naming (now t7426-submodule-get-default-remote.sh).

The patch maintains backward compatibility by falling back to "origin" if default remote detection fails, and includes comprehensive test coverage across multiple test files. Jacob Keller has reconfirmed the technical soundness of the approach despite minor changes from his originally reviewed version. With all identified issues resolved and Junio's final ack, this is now ready for integration.
