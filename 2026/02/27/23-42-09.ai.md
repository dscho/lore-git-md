Refactoring of oidmap cleanup API to improve type safety and explicit resource management.

This is the first patch in a 5-part series that refactors Git's oidmap implementation to make memory cleanup more explicit and type-safe. The change replaces the existing `oidmap_clear(map, 1)` pattern with a new `oidmap_clear_with_free()` function that takes an explicit callback, removing reliance on struct layout assumptions in the hashmap implementation.

The patch introduces a new `oidmap_free_fn` typedef for cleanup callbacks and implements the new clearing logic by iterating through entries rather than using the internal `hashmap_clear_()` function. Two new unit tests verify the behavior: one showing entries are freed when a callback is provided, and another showing they remain when no callback is given.

This change touches core data structures but maintains existing behavior while improving maintainability. The series appears well-structured with clear commit messages and thorough test coverage. The changes are mechanical but meaningful, aligning with ongoing efforts to improve Git's internal APIs. The patch updates the oidmap implementation while leaving all call sites to be converted in subsequent patches.
