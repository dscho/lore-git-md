This is a performance optimization for the option parsing validation patch in the ongoing thread about Git's silent acceptance of duplicate long options.

Junio Hamano agrees with Jeff King's suggested micro-optimization for René Scharfe's validation patch, which checks for duplicate long option names in command option definitions. The optimization replaces a two-step `strset_contains()`+`strset_add()` with a single `strset_add()` that returns a boolean indicating whether the string was already present. This provides a small (~1%) performance improvement in Jeff King's benchmarks while also making the code slightly shorter.

The change is straightforward and clearly correct - as Junio notes, it avoids hashing the same string twice unnecessarily. This comes after earlier benchmarking showed the validation adds about 10ms overhead for 100,000 options, which was deemed acceptable. The thread has already established consensus that this validation should remain always-on rather than being DEVELOPER-mode-only, and this micro-optimization further reduces any performance concerns.

This email represents the final refinement of the validation approach before the patch series is likely to be merged. The core functionality (detecting duplicate long names and numerical options) remains unchanged from René's original patch; this is purely an implementation detail optimization.
