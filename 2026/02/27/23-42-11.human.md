This is the third patch in a 5-part series refactoring Git's oidmap cleanup API to use explicit callback-based memory management. The patch converts the list-objects-filter subsystem to use the new `oidmap_clear_with_free()` function instead of the old boolean-flag approach.

The change updates `filter_trees_free()` to handle cleanup of `seen_map_entry` structures through a dedicated `free_seen_map_entry()` callback. This makes the memory management more explicit and type-safe compared to the previous approach that relied on a boolean flag to trigger generic `free()` calls. The patch maintains identical behavior while improving code clarity.

This continues the series' pattern of demonstrating the new API with real-world use cases - here showing how it handles container objects in the list-objects-filter subsystem. The implementation is straightforward and well-contained, with clear commit message and proper test coverage (established in earlier patches). The change touches core filtering logic but doesn't modify behavior, just the cleanup mechanism.
