This is part of a feature series introducing structured path reporting to `git repo info`. The patch adds 13 path-related fields to expose repository locations that are commonly retrieved via `git rev-parse` or other plumbing commands.

The key additions are:
- A new "path" category in `repo_info_fields` with entries like `path.git-dir`, `path.worktree`, and `path.hooks-directory`
- Dedicated getter functions for each path that use the new `repo_info` context
- Absolute path resolution through `repo_info_add_path()`
- Support for both bare and worktree repositories
- Integration with existing repository path APIs like `repo_get_git_dir()` and `repo_get_work_tree()`

The patch follows the series' pattern of adding functionality while maintaining backward compatibility. It touches several subsystems (refs, objects, hooks) by exposing their standard locations through a unified interface. The implementation appears thorough, with careful handling of edge cases like bare repositories and submodules.

This is patch 2/11 in v5 of the series, which has been narrowed to focus exclusively on path reporting after splitting out structural metrics into a parallel effort. The changes align with the ongoing `the_repository` removal work by using repository-aware path resolution. Review discussion from Phillip Wood about path key naming (`path.git-prefix` vs `path.prefix`) and reftable compatibility remains unresolved.
