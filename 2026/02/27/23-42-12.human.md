This is the fourth patch in a series refactoring Git's oidmap cleanup API, specifically targeting the object database (odb) subsystem. The patch converts the odb's `replace_map` cleanup to use the new `oidmap_clear_with_free()` API introduced earlier in the series.

The change replaces an implicit cleanup (via boolean flag) with an explicit callback-based approach, adding a new `free_replace_map_entry()` helper that properly frees each `struct replace_object` stored in the map. The implementation follows the pattern established in previous patches, using `container_of` to safely access the containing structure from the oidmap entry.

This continues the series' consistent approach of making memory management more explicit and type-safe while maintaining identical behavior. The change is small (11 lines net) and focused, touching only the odb.c file. As with previous patches, it includes thorough documentation of the change in the commit message and preserves all existing functionality while improving code organization.

The patch demonstrates the same careful attention to detail seen throughout the series, with clear separation of concerns and proper handling of the replace_map's initialization state. It represents another incremental step in modernizing Git's internal APIs for better resource management.
