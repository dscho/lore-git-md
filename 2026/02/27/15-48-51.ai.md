Feature proposal for automatic prefixing of new branch names, now with command-line option.

This is the second version of a patch series proposing a new feature that would automatically prefix new branch names with the current branch name (e.g., creating "test" while on "main" would produce "main-test"). The key change in v2 is the addition of a `--no-prefix` command-line option, addressing Junio Hamano's feedback that configuration options should typically be preceded by demonstrating the feature's utility via command-line flags first.

The implementation adds both a `branch.addCurrentBranchAsPrefix` config option and the new `--no-prefix` flag to disable the behavior. The patches modify `git branch`, `git checkout`, and `git switch` commands to support this feature, with test coverage across multiple test files (t2018, t2060, t3200). The recursive prefixing behavior (where "test" created from "main-test" becomes "main-test-test") remains unchanged from v1.

Junio had raised concerns about the original approach introducing a new config option without first proving the concept via command-line usage, as well as noting the author's email address was bouncing. While the email issue appears unresolved (the same address is used in v2), the technical response to Junio's feedback is clear - the command-line interface now exists alongside the config option, following Git's preferred pattern. The implementation looks technically sound with thorough test coverage, though the conceptual need for this feature still needs broader discussion on the list. The original motivation cited benefits for projects needing backports across many branches, but this hasn't been deeply examined yet.
