Feature patch adding configurable commit list formatting for `git format-patch` cover letters.

This is the final patch in a series that introduces flexible formatting for the commit list in `git format-patch` cover letters. The patch adds a new `format.commitListFormat` configuration option that allows users to specify a default format for the commit list, avoiding the need to pass `--cover-letter-format` each time.

The config option supports several modes:
- When set to a format string (like `[%(count)/%(total)] %s`), it will use that format
- When set to "shortlog", it maintains the traditional shortlog output
- When unset, it defaults to shortlog behavior
- When set but empty, it uses `[%(count)/%(total)] %s` as a default format

The implementation builds on previous patches in the series that added placeholders for patch numbering (`%(count)` and `%(total)`) and refactored the shortlog generation. The patch includes comprehensive tests verifying all configuration scenarios and format combinations.

The design follows maintainer feedback from earlier iterations, with clean integration into the existing format-patch infrastructure. The implementation handles both command-line and config-specified formats while maintaining backward compatibility. This completes the feature set for customizable cover letter formatting that was proposed in the RFC phase.
