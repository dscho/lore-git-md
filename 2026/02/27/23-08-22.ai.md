This is a performance discussion in the ongoing thread about duplicate option detection in Git's option parser. Jeff King (Peff) responds to René Scharfe's implementation of runtime validation for option tables, providing concrete benchmark data and micro-optimization suggestions.

Peff demonstrates that the new validation adds measurable overhead - about 10ms for 100,000 options, or roughly 100ns per option. While this is small in absolute terms (comparable to 50-100 syscalls for typical command option counts), he notes it could be optimized further if startup time becomes critical. His benchmark uses `git rev-parse --parseopt` with a synthetic 100,000-option input to stress the system.

The email also suggests a one-line optimization to René's implementation: using `strset_add()`'s return value to detect duplicates rather than making a separate `strset_contains()` call. Peff measures this as a 1% improvement in his extreme benchmark case, though he acknowledges the string allocation overhead likely dominates. The change has the side benefit of making the code slightly shorter.

Peff maintains his earlier position that runtime configurability would be preferable to DEVELOPER-mode-only checks, while providing data to inform that decision. The exchange reflects Git's culture of careful optimization even for small gains, while keeping the primary focus on correctness.
