This is the final patch in a feature series adding configurable cover letter formatting to `git format-patch`. The patch introduces a new `format.commitListFormat` configuration option that allows users to specify a default format for the commit list in cover letters, rather than requiring it to be passed via `--cover-letter-format` each time.

The config option follows a clear precedence and fallback chain:
- If unset, falls back to the traditional shortlog format
- If set but empty, uses a default format showing patch numbering (`[%(count)/%(total)] %s`)
- If set to "shortlog", uses the traditional format
- If set to any other value, uses that as the format string (without requiring the "log:" prefix)

The implementation adds the config handling in `builtin/log.c` alongside other format-patch configurations, with proper memory management. The accompanying tests verify all the config scenarios, including edge cases like empty values and the "shortlog" special case. This completes the feature set that was introduced in earlier patches, providing both command-line and config-based control over cover letter formatting.

The patch has already gone through multiple iterations (v4) and has received maintainer approval, with Junio C Hamano confirming the implementation addresses all requirements. The series as a whole provides a flexible system for customizing cover letter output while maintaining backward compatibility with existing workflows.
