This is the first patch in a series enhancing Git's repository path reporting capabilities. The patch introduces a `struct repo_info` to thread repository context through the path lookup and printing functions, removing direct coupling to repository globals. It also adds category-based key expansion, allowing scripts to request groups of related fields (like "layout.*") rather than listing each key individually.

The changes are part of a larger effort to provide structured, programmatic access to repository metadata, replacing shell-outs to `git rev-parse`. This version (v5) has been narrowed to focus solely on path reporting after splitting out structural metrics into a separate series.

Key technical changes include:
- New `repo_info` struct to carry repository context
- Category expansion for field lookups (e.g. "layout" expands to all "layout.*" fields)
- Threaded context through all value-getter functions
- Maintained existing behavior for explicit key requests
- Clear error reporting for unknown keys/categories

The patch appears well-structured and focused changes, though some interface design questions remain open from Phillip Wood's review (particularly around path key naming conventions). This foundational change enables the subsequent patches in the series to build out the full path reporting functionality.
