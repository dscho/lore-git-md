Bugfix discussion for `git fetch --dry-run` behavior with shallow repositories.

Jeff King (Peff) responds to Tyler Breisacher's report that `git fetch --dry-run --depth=1` creates a `.git/shallow` file in non-shallow clones, contrary to dry-run expectations. Peff explains this is somewhat intentional - while `--dry-run` avoids updating refs, it still performs object transfers and needs to mark shallow objects to prevent corruption. He references a prior discussion about whether a truly read-only dry-run mode would be useful, suggesting this behavior may be working as designed rather than being a bug.

The key technical detail is that shallow markers are considered part of the object transfer process rather than a repository update, which explains why they're created even in dry-run mode. Peff proposes updating the documentation to clarify this behavior rather than changing the implementation. This thread touches core fetch functionality and the sometimes subtle distinctions between what constitutes a "dry run" versus a repository modification. The discussion remains open-ended, with Peff's response suggesting the current behavior is defensible but the documentation could better explain it.
