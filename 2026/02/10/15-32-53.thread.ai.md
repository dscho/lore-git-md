Thread identity: Proposal for a new `pre-add` hook, allowing validation of staged changes before they enter the index. Originating author not specified in this summary.

Core problem/goal: Git currently lacks a hook point between pathspec validation and actual staging of changes. This patch introduces a `pre-add` hook to fill that gap, enabling use cases like linting, license checking, or policy enforcement before files enter the index.

Current status: Initial proposal (v1). Implements:
- New `pre-add` hook location
- `--no-verify` flag for `git add` (long form only)
- Direct use of `run_hooks_opt()` rather than commit hook wrapper
- Comprehensive test coverage (8 scenarios in t/t3706-pre-add-hook.sh)

Key technical details:
- Hook runs after pathspec validation but before staging
- Receives `GIT_INDEX_FILE` in environment
- Bypassed with `--no-verify`
- Not invoked for interactive/patch/dry-run modes or `git commit -a`
- New test file: t/t3706-pre-add-hook.sh

Open questions:

- Long-term behavior with `git commit -a` - is exclusion here the right choice?
