Thread identity: Proposal for a new `pre-add` hook, allowing validation of staged changes before they enter the index. Originating author not specified in this summary. Current version is v1.

Core problem/goal: Git currently lacks a hook point between pathspec validation and actual staging of changes. This patch introduces a `pre-add` hook to fill that gap, enabling use cases like linting, license checking, or policy enforcement before files enter the index. Maintainer Junio Hamano has raised significant technical concerns about the current implementation's design and proposed an alternative architecture.

Current status: Initial proposal (v1) under active discussion with maintainer feedback suggesting fundamental redesign. Key implementation details:
- New `pre-add` hook location
- `--no-verify` flag for `git add` (long form only)
- Direct use of `run_hooks_opt()`
- Comprehensive test coverage (t/t3706-pre-add-hook.sh)

Key technical details:
- Original design runs hook after pathspec validation but before staging
- Receives `GIT_INDEX_FILE` in environment (questioned by Junio)
- Bypassed with `--no-verify`
- Skips interactive/patch/dry-run modes and `git commit -a`
- New test file: t/t3706-pre-add-hook.sh

Maintainer feedback (Junio Hamano):
1. Current hook runs too early - lacks context about operation mode (-u/--renormalize)
2. Proposed alternative: Split `write_locked_index()` into two phases
3. New design would provide hook with both original and proposed index states
4. Enables diff-based inspection of changes before finalization
5. Requires temporary index files and rollback capability
6. `GIT_INDEX_FILE` may be unnecessary with this approach
