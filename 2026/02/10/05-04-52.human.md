Performance optimization for `git config list --type` filtering, part of a series addressing a bottleneck in git-credential-manager. This is patch 3/5 in Derrick Stolee's RFC series.

The patch modifies `format_config()` to support a "gentle" parsing mode where type mismatches result in skipping the value rather than failing the entire command. This prepares for using the function in `git config list --type=<X>` where users expect non-matching values to be filtered out rather than causing errors. The implementation maintains the existing behavior when `die_on_parse` is true (the current default).

Junio C Hamano suggests two potential refinements: using a more conventional `bool gently` parameter name rather than `die_on_parse`, and possibly factoring the type-specific formatting into separate helper functions for cleaner code organization. These appear to be style suggestions rather than objections to the core approach.

The series remains in RFC status while Junio evaluates whether type-based filtering conceptually aligns with Git's config model (where values are fundamentally strings). This patch represents solid technical groundwork for the feature, but its ultimate inclusion depends on resolving that higher-level design question.
