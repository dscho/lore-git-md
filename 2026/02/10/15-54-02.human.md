This is a documentation patch addressing an edge case in Git's patch generation workflow. Kristoffer Haugsbakk follows up on a thread about `diff.noprefix` configuration affecting `git format-patch` output, pointing out that the related `format.noprefix` option behaves differently from its `diff.*` counterpart.

The thread began when a patch for a man page failed to apply due to path handling issues caused by the sender having `diff.noprefix=true` set locally. While `git add -p` handles such prefixless patches, `git am` does not, creating workflow friction. Junio Hamano had previously indicated a fix would be queued to make `format-patch` ignore `noprefix`, but the current status of that change appears unclear.

Haugsbakk's contribution clarifies that `format.noprefix` (unlike `diff.noprefix`) accepts any value to enable the behavior, not just boolean `true`. He questions whether the documentation should explicitly state this difference in behavior between the two similarly-named options. The patch suggests updating the documentation to be more precise about how the option works, potentially helping users avoid similar issues in the future.

The email serves both as a documentation improvement proposal and as a gentle nudge about the broader `noprefix` handling issue that remains unresolved despite prior discussion. It's a focused, well-reasoned contribution that addresses a real pain point while maintaining the project's documentation standards.
