This is a bug report about `git fast-export` silently skipping GPG signatures when exporting commits, which breaks `git filter-repo`. The reporter, Matthias Urlichs, provides a concrete example showing a signed commit where the signature is present in `git cat-file` output but missing from `git fast-export` output even with `--signed-tags=verbatim` (which only affects tags, not commits).

The commit shown has a GPG signature block in its header, yet `fast-export` omits this signature while preserving the rest of the commit metadata and file changes. This behavior is problematic for tools like `git filter-repo` that rely on `fast-export` for repository rewriting operations, as it causes signature information to be lost during the process.

The report doesn't propose a specific fix but clearly demonstrates the discrepancy between commit object content and export output. This appears to be a long-standing oversight in `fast-export`'s handling of signed commits rather than a regression. The bug affects the integrity of repository operations that need to preserve cryptographic signatures.
