Security-focused documentation patch refinement. Phillip Wood and Kristoffer Haugsbakk are refining the warning text about patch roundtrip hazards in Git's documentation, following up on the recent security vulnerability where `git am` could misinterpret diffs embedded in commit messages. The discussion focuses on precise wording to describe how patches can be misapplied when roundtripped through `format-patch` and `am`, particularly when commit messages contain unindented diff-like content.

Key points in this exchange:
- They clarify that the risk is not just incorrect commit messages but also potential misapplication of the patch content itself (though initial test results were inconclusive)
- The text now explicitly warns that `patch(1)` is even more aggressive than `git am` at applying embedded diffs
- They debate the inclusion of GitHub-flavored Markdown examples, with Phillip noting the project's neutrality toward forges
- The language is being tightened to lead with the problem rather than burying it in the sentence structure

This is part of the layered response to the security issue, complementing Phillip Wood's proposed `commit-msg` hook changes and Patrick Steinhardt's `--accept-ambiguous-patch` flag. The documentation improvements have already been queued by Junio, showing the project's urgency in addressing this long-standing vulnerability. The exchange demonstrates the careful attention to wording that characterizes Git's documentation process, even for security warnings.
