This is a reply from the Git maintainer Junio C Hamano to Derrick Stolee's RFC patch series to improve type filtering in `git config list`. The series aims to make `--type=<X>` work efficiently by filtering during parsing rather than after.

Junio acknowledges the technical challenges Derrick addressed in the patches (die-on-parse behavior, path parsing helpers, display option standardization) but raises a conceptual concern about the nature of config types. He notes that config variables don't have inherent types - they're just strings that callers interpret differently. The exception is valueless keys which are inherently boolean.

The maintainer is reserving judgment on the final filtering behavior until seeing the implementation, as he's unsure about treating all values as having a specific type. This suggests the series may need to clarify its type semantics before merging, though the infrastructure improvements look sound.

Junio's response indicates this is moving in the right direction but may require some design discussion about how type filtering should conceptually work for config values that are fundamentally typeless strings. His tone is constructive but signals this isn't quite ready to merge as-is.
