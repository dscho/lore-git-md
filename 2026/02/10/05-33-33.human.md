This is a bug report about unexpected behavior in `git fetch --dry-run`. Tyler Breisacher reports that when running `git fetch --depth=1 --dry-run` in a non-shallow repository, Git creates a `.git/shallow` file containing a SHA, despite the `--dry-run` flag which should prevent any repository modifications.

The issue appears to affect all non-shallow repositories, suggesting it's a general bug in how `--dry-run` is implemented for shallow fetch operations. The behavior contradicts the expected semantics of `--dry-run`, which should only show what would happen without making actual changes.

The report is concise but clearly demonstrates the problem with reproducible steps. This looks like a legitimate bug that would need investigation from someone familiar with the fetch and shallow clone machinery. The fix would likely involve ensuring the dry-run path doesn't write the shallow file when in simulation mode.
