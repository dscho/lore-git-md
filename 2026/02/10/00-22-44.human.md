This is a bug report discussion about `git send-email`'s recipient suppression options. Junio C Hamano responds to Jim Cromie's report that `--suppress-to` and related flags are being incorrectly passed to `format-patch` instead of being handled by `send-email` itself, causing fatal errors.

Junio clarifies that `--suppress-to` doesn't actually exist as a valid option - the available suppression flags are `--suppress-cc` and `--suppress-from`. He notes that `--no-cc` and `--no-to` only suppress command-line and config-specified recipients, not those listed in patch files. The behavior Jim observed appears to be working as (currently) documented, though the documentation may need updating to make this clearer.

The exchange highlights a gap between user expectations and actual functionality - users expect these flags to control all recipient additions, but the current behavior is more limited in scope. This isn't a bug in the technical sense but rather a documentation/UX issue where the commands don't behave as users might intuitively expect. Junio's response suggests the next step would be to clarify the documentation rather than change the implementation.
