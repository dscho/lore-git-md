The bug affects tools that rely on `fast-export` for repository rewriting operations where signature preservation is important.

In a follow-up, Matthias noted there's actually an existing `--signed-commits` option that controls this behavior, which he had initially overlooked. He suggests improving the interface by making this option default to matching whatever `--signed-tags` is set to, unless explicitly overridden. This would create more consistent behavior between how commit and tag signatures are handled during export.

While this doesn't yet address the core issue of signature preservation, it highlights an opportunity to make the command's behavior more intuitive. The thread remains open for discussion about both the default behavior and the underlying signature handling.
