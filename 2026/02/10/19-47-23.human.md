This is a feature patch adding UTF-8 support for Git aliases via config subsections, now in its second iteration. The patch enables non-ASCII alias names like `[alias "förgrena"] command = branch` while maintaining backward compatibility with the traditional `[alias] co = checkout` syntax. The implementation handles case sensitivity differences between the two forms (subsection aliases are case-sensitive while traditional ones remain case-insensitive) and ensures proper display in help output using `utf8_strwidth()` for column alignment.

The patch includes comprehensive test coverage in `t/t0014-alias.sh` with Swedish, CJK, and space-containing aliases. Documentation has been updated to clearly explain the two syntax forms and their limitations. Junio Hamano's review identified a few edge cases needing attention - particularly around NULL values and dot-containing aliases in the refactored parsing logic - but the core functionality has been validated by Jeff King and the documentation wording approved by Junio.

Windows support remains an open question deferred to future work, but the Unix implementation is ready for merging once the final documentation tweaks are applied. This represents a careful expansion of Git's UTF-8 support that maintains backward compatibility while addressing a real need for non-English speakers to use aliases in their native languages.
