Performance improvement patch in Derrick Stolee's series to optimize `git config list --type=<X>` filtering. This is patch 3/5 in the RFC series addressing a bottleneck found in git-credential-manager.

The patch modifies `format_config()` in `builtin/config.c` to support two parsing modes: the existing "die on error" behavior and a new "gentle" mode that skips invalid entries rather than failing the entire command. This prepares for efficient type filtering in `git config list` by allowing early rejection of values that don't match the requested type without parsing everything first.

Key changes:
- Adds a `die_on_parse` parameter to control error handling
- For each config type (int, bool, path, etc.), implements both strict and gentle parsing variants
- Maintains backward compatibility by defaulting to strict mode for existing callers
- Lays groundwork for subsequent patches to use gentle parsing when filtering by type

The implementation carefully preserves all existing behavior while adding the new capability, with clear separation between the two modes in the code structure. This continues Stolee's systematic approach seen in earlier patches of the series.
