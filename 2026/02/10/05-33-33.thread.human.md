Here's the updated human-readable thread summary:

Tyler Breisacher reported that `git fetch --dry-run --depth=1` unexpectedly creates a `.git/shallow` file in non-shallow clones, which appears to violate the read-only expectation of dry-run operations. The behavior is reproducible and affects core fetch functionality, though no fix was proposed initially.

Jeff King (Peff) has now responded, explaining that this behavior is somewhat intentional. While `--dry-run` avoids updating refs, it still needs to perform object transfers and mark shallow objects to prevent repository corruption. Peff notes this reflects a design choice where shallow markers are considered part of the transfer process rather than a repository update. He suggests the current implementation may be working as designed, and proposes clarifying the documentation rather than changing the behavior. The discussion remains open, with Peff's analysis indicating this might not be a bug per se, but rather a case where the documentation could better explain the nuances of what dry-run operations do and don't modify.
