RFC proposal for `git repo info` to expose repository paths, starting with `--git-dir` equivalent. Author Pushkar Singh suggests structured output for repository metadata as more discoverable alternative to `git rev-parse`, maintaining both interfaces. Patrick Steinhardt supports the general direction, noting `git rev-parse` has grown beyond its original revision-parsing purpose and agreeing repository metadata belongs in `git repo` long-term. Open questions remain about path formatting (absolute vs relative) and scope (starting with git-dir vs including other paths like common dir, hooks). Patrick recalls Lucas Skeggs previously suggested configurable path resolution but does not detail that proposal here. The discussion positions this as part of broader effort to rationalize Git's command structure, with `git repo` as future home for repository introspection features. Tone is collaborative with alignment on direction but technical specifics still to be resolved.
