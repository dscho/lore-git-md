RFC proposal for `git repo info` to expose repository paths as structured alternative to `git rev-parse`, with Pushkar Singh and Patrick Steinhardt collaborating on design. Pushkar's latest patch proposes adding stable path outputs (`path.git-dir`, `path.common-dir`, `path.objects-dir`) to the structured format, building on Lucas Skeggs' earlier `--format`/`--keys` work for `repo_info_fields[]`. The implementation would use existing repository path APIs (`repo_get_git_dir()` etc.) while avoiding invocation-dependent values, keeping scope focused on repository-derived metadata.

Patrick Steinhardt supports moving repository introspection from `git rev-parse` to `git repo` long-term, noting `rev-parse` has outgrown its original purpose. Open questions remain about path formatting (absolute vs relative), with the proposal deferring to a parallel `--path-format` discussion. The thread maintains consensus on making `git repo` the canonical home for this functionality while keeping technical scope narrow - focusing first on exposing existing repository state through structured output rather than redesigning path resolution semantics. Lucas Skeggs' prior work on configurable path resolution is acknowledged but not directly incorporated in this iteration.
