RFC proposal for `git repo info` to expose repository paths as structured alternative to `git rev-parse`, with Pushkar Singh and Patrick Steinhardt collaborating on design. The series would add `path.git-dir` and `path.common-dir` fields to structured output, building on Lucas Skeggs' `--format`/`--keys` work for `repo_info_fields[]`. Implementation uses existing repository path APIs (`repo_get_git_dir()`, `repo_get_common_dir()`) while avoiding invocation-dependent values.

Patrick Steinhardt supports moving repository introspection from `git rev-parse` to `git repo` long-term, noting `rev-parse` has outgrown its purpose. The series integrates with `--path-format` for consistent path representation while deferring broader path resolution semantics discussions. Each patch adds one field with tests following established pattern: latest adds `path.common-dir` via `get_path_common_dir()` using `repo_get_common_dir()`, mirroring `rev-parse --common-dir` but in machine-readable format.

Jayatheerth Kulkarni identified gaps: (1) test file `t/t1900-repo-info.sh` lacks verification of path handling across OS environments for both `--path-format=absolute` and `--path-format=relative` cases, particularly around NULL path returns with `--all`; (2) documentation (`Documentation/git-repo.adoc`) needs updating to include these new fields.

Lucas Seiki Oshiro raised concerns about the foundational `git repo info` infrastructure's acceptance status, suggesting the base implementation may face resistance. Pushkar Singh has now acknowledged this procedural uncertainty. Junio C Hamano has intervened to express concern about the lack of coordination around this effort, highlighting that multiple contributors appear to be working independently on path-related fields without sufficient alignment. He implies skepticism about whether this effort is properly scoped given the unresolved status of the base command.
