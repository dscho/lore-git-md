This is a follow-up in a thread about `git send-email` recipient suppression options. Jim Cromie confirms Junio Hamano's earlier clarification that `--suppress-to` is not a valid option (despite appearing in some documentation) and that `--no-to`/`--no-cc` only suppress addresses from command-line arguments and configuration, not those parsed from patch files.

The exchange reveals a documentation issue - the current behavior is working as designed but the man page could be clearer about the limited scope of these options. Jim notes that describing the suppression as affecting "config" rather than "options" is ambiguous. This appears to be a straightforward case where the documentation needs minor clarification to better match the actual behavior, rather than any code changes being required.

The thread shows a typical Git mailing list interaction where a user reports unexpected behavior, the maintainer quickly identifies the actual constraints, and they collaboratively identify a documentation improvement opportunity. No further action seems needed beyond updating the man page wording.
