This is a refactoring patch that consolidates alias handling logic in preparation for UTF-8 support in Git configuration subsections. It's the first of two patches in the v2 series implementing UTF-8 aliases.

The patch eliminates duplicate alias parsing code by modifying `list_aliases()` in alias.c to store alias values (via string_list's util field) and using this unified function in help.c instead of the private `get_alias()` callback. This change makes the code more maintainable by having a single source of truth for alias parsing.

A second technical improvement switches `git_unknown_cmd_config()` from using `skip_prefix()` to `parse_config_key()` for alias parsing. This better handles the config key structure and paves the way for multi-level alias config keys (needed for UTF-8 subsection support in the next patch).

The changes are purely internal - no user-visible behavior changes in this patch. The implementation has been reviewed by Jeff King and the approach validated. This refactoring represents careful preparation work before introducing the actual UTF-8 support in the following patch.

Key technical details:
- Modified files: alias.c, help.c
- New behavior: `list_aliases()` now populates string_list->util with alias values
- Removed: private `get_alias()` callback in help.c
- Improved: `parse_config_key()` usage for more robust alias parsing
- Maintains: all existing functionality while cleaning up implementation

The patch is part of a well-reviewed series that has addressed all feedback from v1 and is now in its final polishing stage before merging.
