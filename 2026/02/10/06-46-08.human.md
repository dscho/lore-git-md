This is a security-focused discussion about patch parsing vulnerabilities in `git am`. Jeff King (Peff) weighs in on Phillip Wood's earlier message about commit messages that could confuse `git am` when patches are applied.

Peff acknowledges that while email-based workflows are less common now, people still download patches from GitHub and apply them, sometimes using `git am`. He agrees with Wood's assessment that focusing on `git am` behavior is reasonable, even though the issue also affects plain `patch(1)` in some cases. The discussion reflects the ongoing tension between security hardening and backward compatibility in patch parsing.

This exchange is part of a larger thread that has already produced concrete improvements: Kristoffer Haugsbakk's documentation warnings have been queued by Junio, and Phillip Wood is reconsidering the sample `commit-msg` hook's detection of "---" lines after Peff pointed out legitimate uses.
