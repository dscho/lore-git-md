This is a documentation patch addressing the security vulnerability in `git am`'s patch application behavior, now in its final review stage. Phillip Wood gives his approval to Kristoffer Haugsbakk's v2 patch, noting only minor remaining wording concerns about GitHub Markdown references mentioned in a separate email.

The patch adds comprehensive warnings about how `git format-patch` and `git am` handle delimiters in commit messages, particularly focusing on the risk of unindented diffs being misinterpreted as patches. It documents three specific termination patterns (three-dash lines, "diff -" lines, and "Index:" lines) that can prematurely end commit message parsing. The documentation emphasizes that this affects not just email workflows but also distribution maintainers applying patches in bulk.

The patch has evolved through review, with v2 incorporating feedback to remove redundant examples, clarify the Linux distribution use case, and better explain the potential failure modes. It now shared documentation across multiple man pages via include files. Junio has already queued the patch, indicating it's likely to be merged once these final wording tweaks are addressed.
