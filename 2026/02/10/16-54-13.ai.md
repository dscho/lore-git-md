This is a follow-up in an ongoing thread about patch application issues related to `diff.noprefix` and `format.noprefix` configurations. Junio Hamano responds to Alejandro Colomar's query about the status of a fix from 3 years ago (commit 15108de2) that added `format.noprefix` to address prefixless patch generation/application problems.

Junio clarifies that the change is long since merged (in v2.41.0-rc0) and humorously chides Alejandro for asking about a 3-year-old patch. The response confirms the current state relies on `format.noprefix` rather than any pending fix to make `format-patch` ignore `diff.noprefix`. This closes the loop on whether Junio's original proposed solution was implemented - it wasn't, as the separate `format.noprefix` config was used instead.

The thread continues to highlight the real-world impact of this configuration mismatch, with Alejandro and наб reporting persistent workflow issues when applying patches between systems with different diff/format prefix settings. The documentation improvements proposed by Kristoffer Haugsbakk would help clarify the boolean vs any-value distinction between these settings.
