This is part of Adrian Ratiu's ongoing series to make Git hooks configurable via Git configuration, now at version 4. The current patch focuses on implementing config-based hooks through `hook.<name>.command` and `hook.<name>.event` options while maintaining compatibility with filesystem hooks.

The key discussion point here is whether to cache hook configurations in the repository object for performance. Patrick Steinhardt makes a strong case for caching, citing the `reference-transaction` hook as a real-world example where hooks can be called tens of thousands of times in a single process (three times per reference update in some code paths). Adrian initially questioned the performance benefit versus implementation complexity but is now convinced to include caching in the next version.
