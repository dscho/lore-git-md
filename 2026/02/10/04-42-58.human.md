Performance optimization patch for `git config list` type filtering, part 4/5 in Derrick Stolee's series. This patch focuses on initialization differences needed when listing multiple config values versus single-value operations.

The change introduces a new `display_options_init_list()` helper that sets up output formatting defaults specific to list mode, ensuring keys are shown with appropriate delimiters. It handles both `git config list` and `git config --list` invocation styles consistently. The patch modifies two call sites to use this new initialization.

This continues the series' goal of optimizing type-filtered config listing by preparing the infrastructure for efficient filtering. The changes are mechanical and focused on output formatting rather than the core filtering logic, which will come in subsequent patches. The implementation maintains backward compatibility while cleaning up some initialization edge cases.
