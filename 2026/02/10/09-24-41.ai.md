This is a technical discussion thread about object database flag handling in Git's ODB abstraction effort, specifically examining the interaction between `OBJECT_INFO_*` and `HAS_OBJECT_*` flags in `builtin/backfill.c`. Karthik Nayak responds to Patrick Steinhardt's earlier patch that fixed incorrect flag passing in `fill_missing_blobs()`.

Karthik confirms the current behavior works correctly by coincidence - passing `OBJECT_INFO_FOR_PREFETCH` (which `HAS_OBJECT_*` flags are not equivalent) happens to result in the same internal flag settings as passing no flags at all. While agreeing with Patrick's fix to remove the incorrect flags, Karthik suggests further improving type safety by making the `HAS_OBJECT_*` enum non-anonymous and using it directly in `odb_has_object()`'s signature.

The exchange demonstrates careful validation of low-level flag handling in the ODB API, with both contributors cross-checking how flags propagate through multiple function layers. Karthik's suggestion about enum typing connects to the broader thread discussion about compiler-assisted validation of flag usage patterns. The patch itself is non-controversial (already merged) but this follow-up explores opportunities for additional type safety improvements in the ongoing ODB abstraction work.
