This is a feature patch implementing UTF-8 support for Git aliases via config subsections, now in its second iteration. The patch allows non-ASCII alias definitions like `[alias "förgrena"] command = branch` while maintaining backward compatibility with the traditional `[alias] co = checkout` syntax. The implementation handles case sensitivity differences between the two forms (subsection aliases are case-sensitive while traditional ones remain case-insensitive) and ensures proper display of UTF-8 aliases in help output using `utf8_strwidth()`.

Key technical changes include:
- New config parsing logic in `alias.c` that distinguishes between subsection and traditional syntax
- UTF-8-aware column alignment in `help.c` for alias listings
- Comprehensive test coverage in `t/t0014-alias.sh` including Swedish, CJK, and space-containing aliases
- Documentation updates explaining the two syntax forms and their limitations

Junio Hamano's review identifies several edge cases needing attention:
- Silent ignoring of malformed subsection entries (like `[alias "foo"] command` without a value)
- Potential future expansion points for subsection variables beyond just `command`
- Open question about whether to preserve legacy behavior for dot-containing aliases

The patch represents a careful expansion of Git's Unicode support while maintaining backward compatibility. All technical feedback from v1 has been addressed, and the implementation is now merge-ready pending resolution of the edge cases Junio noted. Windows support remains a known limitation to be addressed separately.
