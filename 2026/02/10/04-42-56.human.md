Performance improvement patch in a series to optimize `git config list --type` filtering. This is the second of five patches in Derrick Stolee's RFC series addressing a performance bottleneck found in git-credential-manager.

The patch extracts pathname parsing logic from `config.c` into a new `git_parse_maybe_pathname()` function in `parse.c`, making it reusable elsewhere. The key change is that this new version doesn't call `die()` on failure, instead returning an error code - a necessary step for the planned type-filtering optimizations where we'll want to try parsing without fatal errors.

The change is purely internal refactoring at this stage - no user-visible behavior changes yet. The series is still in RFC status as the author seeks feedback on the approach before implementing the full performance improvements for `git config list --type`.
