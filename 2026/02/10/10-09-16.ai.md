This is a refactoring patch in the ongoing ref backend abstraction effort, specifically preparing for URI-based reference storage configuration. The patch modifies the files and reftable backends to accept a "payload" parameter during initialization, which will later be used to specify alternate reference storage locations via a URI format.

Karthik Nayak addresses Patrick Steinhardt's review comments on the v5 series, agreeing to several improvements:
1. Adding clarification about worktree path handling in `refs_compute_filesystem_location()`
2. Optimizing strbuf usage by removing redundant resets
3. Considering passing NULL to `packed_ref_store_init()` since packed refs should follow the main backend's gitdir
4. Adding documentation about why packed backend ignores the payload
5. Simplifying the backend documentation wording

The changes focus on internal plumbing to support future URI configuration while maintaining current behavior, as no callers exist yet. This represents incremental progress in the larger effort to enable seamless reference backend switching, with the series nearing completion pending final test coverage expansion. The review discussion shows careful attention to edge cases and optimization opportunities in the path resolution logic.
