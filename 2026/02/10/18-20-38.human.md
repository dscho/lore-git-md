This is a documentation patch finalizing warnings about patch roundtrip hazards in Git's email-based workflow. Kristoffer Haugsbakk is making a minor formatting adjustment to the documentation that was previously reviewed and approved by Phillip Wood, now queued by Junio. The change switches from using a thematic break to an explicit "Patch application" heading in the shared `format-patch-caveats.adoc` file that gets included across multiple man pages.

The patch is part of a broader security-focused effort to document the risks around `git am` parsing ambiguities, particularly when commit messages contain unindented diffs that can be misinterpreted as part of the patch. The documentation now clearly warns about this hazard in vendor-neutral terms, covering parsing behaviors around separator lines (---, diff -, Index:) and limitations of alternative tools like `patch(1)`.

This appears to be the final polish on documentation that has already gone through multiple rounds of review, with the substantive content settled. The current change is purely about presentation - using a heading rather than a break for better structure. Given the careful review history and Junio's queueing of the prior version, this seems like a straightforward improvement that maintains the clarity of the security warnings while making the document structure slightly more formal.
