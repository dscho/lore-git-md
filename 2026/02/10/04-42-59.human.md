Performance improvement to `git config list` with type filtering. This is the final patch in Derrick Stolee's RFC series addressing a performance bottleneck in `git config list --type=<X>` operations, particularly for path-type values.

The patch makes `--type=<X>` actually work with `git config list`, where previously the option was silently ignored. Now it properly filters config entries by attempting to parse each value according to the specified type (bool, int, path, etc.), skipping any that fail to parse. This matches the behavior of `git config get --type` while improving performance by doing the filtering during initial parsing rather than after collecting all values.

The change includes documentation updates and new tests verifying the filtering behavior. Stolee notes this is technically a behavior change (previously invalid values would be shown, now they're filtered out), but argues it's justified since the option was non-functional before. The implementation builds on earlier refactoring in the series to enable non-fatal type checking.

This completes the series' goal of optimizing config value filtering, particularly benefiting tools like git-credential-manager that need to efficiently query path-type configs. The changes are well-contained to the config command's internals while maintaining backward compatibility.
