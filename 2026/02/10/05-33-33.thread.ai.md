Git thread summary:

Bug report from Tyler Breisacher about `git fetch --dry-run` creating a `.git/shallow` file when used with `--depth=1` in a non-shallow clone, violating the read-only expectation of dry-run operations. Jeff King (Peff) explains this is somewhat intentional - while `--dry-run` avoids updating refs, shallow markers are considered part of the object transfer process needed to prevent corruption, not a repository update. Peff references prior discussions about dry-run semantics and suggests documenting this behavior rather than changing it. The technical distinction is that shallow markers are treated as transfer metadata rather than repository state changes. The thread remains open with Peff's position being that the current behavior is defensible but underdocumented, leaving room for either documentation updates or potential reconsideration of dry-run semantics for shallow operations. No other contributors have weighed in yet on Peff's analysis.
