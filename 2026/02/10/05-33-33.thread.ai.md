Git thread summary:

Bug report from Tyler Breisacher about `git fetch --dry-run` creating a `.git/shallow` file when used with `--depth=1` in a non-shallow clone, despite dry-run operations being expected to leave the repository unchanged. The issue demonstrates that the fetch operation marks the repository as shallow (via `.git/shallow` creation) even in dry-run mode, which violates the read-only expectation of dry-run. The report provides clear reproduction steps but no proposed fix. The behavior affects core fetch functionality and could impact users combining `--dry-run` with depth-limiting options. No responses or analysis from other contributors yet.
