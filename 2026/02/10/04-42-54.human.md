This is an RFC patch series from Derrick Stolee proposing changes to `git config list` to make it properly respect the `--type` parameter. The command currently ignores type specifications when listing all config values, which creates performance issues for tools that need to filter config values by type (particularly path values).

The series stems from earlier discussions about `git config-batch` and aims to optimize config value retrieval by allowing type-based parsing and filtering during listing. Key changes include:
- Adding a "maybe" variant of path parsing that doesn't die on failure
- Refactoring the config display logic to share formatting between list and get modes
- Implementing type filtering for the list command

The changes could affect existing tools using `--type` with `git config list`, though the impact should be minimal since the current behavior is effectively broken for this use case. The series is marked RFC pending additional testing and feedback about the behavior change.

Stolee notes this addresses a critical performance bottleneck when querying path-formatted config values, where the current implementation requires loading all values before filtering. The patches demonstrate his characteristic attention to performance-sensitive plumbing improvements.
