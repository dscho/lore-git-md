This is a bug report about `git fast-export` failing to properly handle signed commits. Matthias Urlichs demonstrates that when exporting a commit containing a GPG signature, `git fast-export` silently drops the signature block while keeping the rest of the commit message. This causes problems for tools like `git filter-repo` that rely on the exported data being complete.

The example shows a GitHub-signed commit where the signature is clearly present in the original object (`git cat-file` output) but missing from the same commit's fast-import stream. The reporter notes they tried `--signed-tags=verbatim` (which controls tag signature handling) but this flag doesn't affect commit signature behavior.

This appears to be a genuine bug in `git fast-export`'s commit export logic. The behavior is clearly unintentional since there's no documented reason why signatures should be stripped from commits during export. The impact is significant for workflows that need to preserve cryptographic signatures across repository transformations. The report is well-formed with a clear reproduction case, making it easy to verify and debug.
