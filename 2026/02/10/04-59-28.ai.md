Junio C Hamano's response to Derrick Stolee's RFC patch series on `git config list --type` filtering. This is a maintainer review comment in an ongoing thread about performance of type-filtered config listing.

Junio acknowledges the technical challenge of implementing type filtering given that config system doesn't store type information - values are just strings that callers interpret. He notes that while "auto" type detection wouldn't make sense (since types are determined by usage context), forcing path interpretation for all values (with expected failures on non-path values) might be an acceptable tradeoff.

The review focuses on conceptual approach rather than implementation details, reserving judgment on the actual filtering behavior until seeing the code. Junio highlights the fundamental tension in the design: config values don't have inherent types except for valueless booleans, so any type-based behavior is necessarily an interpretation layer.

This maintains the thread's technical focus while signaling the maintainer's perspective on the core design question. The RFC status and potential behavior change noted in Stolee's cover letter remain open considerations, with Junio's comments suggesting he's weighing whether the filtering approach aligns with Git's config model.
