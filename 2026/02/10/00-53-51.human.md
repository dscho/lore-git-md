This is a follow-up discussion on the recently queued documentation patch about `git am`'s patch parsing vulnerabilities. Christoph Anton Mitterer raises a valid point that while documenting the issue is helpful, fixing the underlying problem would be preferable. The thread context shows this is part of an ongoing security discussion around `git am`'s difficulty distinguishing between intended patches and embedded diffs in commit messages.

The documentation patch (from Kristoffer Haugsbakk) has already been queued after incorporating feedback, explicitly warning about three specific patterns that can trigger incorrect parsing. However, as Mitterer notes, documentation alone may not be sufficient given the security implications and the likelihood that many users won't see the warnings. The thread shows there are multiple proposed technical solutions in progress, including Phillip Wood's security-focused hook enhancements and Patrick Steinhardt's proposed `--accept-ambiguous-patch` flag.

This email serves as a reminder that while documentation is a good first step, the community recognizes the need for deeper technical solutions to this long-standing issue that particularly affects distribution workflows. The discussion continues to balance security hardening against backward compatibility concerns, with Junio Hamano having demonstrated some maintainer workflows that rely on the current behavior.
