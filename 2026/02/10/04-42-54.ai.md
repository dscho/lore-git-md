This is an RFC patch series proposing to make `git config list --type=<X>` properly filter and parse config values by type. The `--type` flag currently works with `git config get` but not with `list`.

The series stems from performance optimization needs in git-credential-manager, where Derrick Stolee found that path-type config values were a bottleneck. The current implementation requires parsing all config values first, then filtering by type, which is inefficient. The proposed changes would allow type filtering during the initial config parsing.

Key technical changes include:
1. Moving `show_all_config()` to make it accessible for modification
2. Adding a non-fatal path parser (`git_parse_maybe_pathname()`)
3. Modifying `format_config()` to handle type filtering
4. Special initialization for list mode
5. Making `--type` work with `git config list`

The series touches `builtin/config.c`, `config.c`, and adds new parsing logic in `parse.c`. Test coverage is added in `t/t1300-config.sh`. The changes are marked RFC due to potential behavior changes for tools using `--type` with `config list`, though the impact appears limited.

This appears to be a well-motivated performance optimization that fills a gap in the config command's functionality. The implementation looks thorough, addressing both the core filtering need and edge cases like error handling. The RFC status suggests the author is particularly interested in feedback about the behavior change implications.
