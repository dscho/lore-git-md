Feature proposal for a new pre-add hook. This patch introduces a `pre-add` hook that runs after pathspec` validation but before files are staged, allowing users to validate or reject additions to the index. The hook receives `GIT_INDEX_FILE` in its environment and can be bypassed with `--no-verify`. It is not invoked for interactive/patch/dry-run modes or `git commit -a`.

The implementation adds a new `--no-verify` flag to `git add` (long form only, since `-n` is already taken) and calls `run_hooks_opt()` directly rather than using the `run_commit_hook()` wrapper. The patch includes thorough documentation updates and a new test script (`t/t3706-pre-add-hook.sh`) with 8 test cases covering various scenarios: no hook, non-executable hook, successful/failing hooks, environment variable passing, and dry-run behavior.

The author notes AI assistance was used in development but emphasizes all code and tests were hand-reviewed. The implementation appears clean and well-tested, though the choice to bypass the hook for interactive modes may warrant discussion. This fills a clear gap in Git's hook coverage between working directory changes and commit-time validation.
