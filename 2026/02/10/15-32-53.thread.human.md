The thread discusses a proposal to introduce a new `pre-add` hook that would allow validation of changes before they enter the index. The initial patch (v1) implements the basic hook infrastructure with a `--no-verify` option and comprehensive tests, aiming to support use cases like linting and policy enforcement. However, the hook currently runs very early in the process, before pathspec processing completes.

Junio Hamano, the Git maintainer, has raised significant technical concerns in his review. He points out that the hook executes too soon to be practically useful, lacking critical context about the operation mode (-u/--renormalize) and pathspec details. He also questions whether passing GIT_INDEX_FILE is necessary, since `git add` only operates on the main index. While not rejecting the concept outright, Junio's feedback indicates the current implementation needs substantial rework around timing and information flow.

Key open questions now center on when exactly the hook should run, what information it needs, and how to handle various `git add` modes consistently. The proposal remains active but will require addressing these fundamental design issues before progressing further. The author will likely need to send a revised version that incorporates this feedback.
