This limitation means users would need to either run the hook multiple times during staging or duplicate checks in a `pre-commit` hook, significantly reducing its practical value.

While the code itself is technically sound (having addressed all earlier feedback about index handling, path management, and hook sequencing), there's now serious doubt about whether the feature provides enough benefit over existing `pre-commit` hooks to justify its inclusion. The thread appears to be shifting from implementation details to a more basic question: is this the right solution to the problem it aims to solve?
