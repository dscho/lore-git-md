Performance improvement to `git config list` with type filtering.

This is the final patch in Derrick Stolee's series to optimize `git config list --type=<X>` by filtering during parsing rather than after. The series was motivated by a performance bottleneck in git-credential-manager when checking path-type config values.

This patch wires up the actual filtering behavior for `git config list --type=<X>`, which previously ignored the type parameter. Now it uses the refactored `format_config()` from earlier in the series to parse and filter each value during iteration, skipping non-matching types. The change is documented in the man page and tested with new cases in t1300.

The behavioral change means some config entries that were shown before may now be omitted if they don't parse as the requested type. The commit notes this could cause confusion but argues it's justified since the previous behavior of ignoring --type was effectively a bug. The patch maintains backward compatibility when --type isn't specified.

Key technical details:
- Uses the new `format_config()` with `die_on_parse=0` to test type parsing without failing
- Skips output for values that don't parse as the requested type
- Updates documentation to clarify --type behavior in list mode
- Adds tests showing bool and path type filtering
- Maintains all other existing list-mode features (origin/scope, delimiters)

The series touches `builtin/config.c`, `config.c`, `parse.c`, and adds tests in `t/t1300-config.sh`. This final piece completes the performance optimization while being careful to document the behavior change.
