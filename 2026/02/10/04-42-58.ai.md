Performance optimization patch in Derrick Stolee's series to improve `git config list --type=<X>` filtering. This is patch 4/5 in the RFC series addressing a performance bottleneck found in git-credential-manager.

The patch introduces `display_options_init_list()`, a specialized initialization function for list mode that ensures consistent output formatting when listing multiple config values. It handles both `git config list` and `git config --list` modes, setting appropriate delimiters (newline or NUL) and showing keys by default. The changes are focused in `builtin/config.c` and maintain backward compatibility while preparing for the type-filtering improvements to come in later patches.

This continues the incremental refactoring approach seen in earlier patches, separating concerns to enable the eventual performance optimization where type checking will occur during initial config parsing rather than after collecting all values. The patch appears straightforward and well-contained, with clear motivation from the series' overall goal.
