This is the second patch in a 3-part series implementing UTF-8 support for Git configuration subsections, specifically focused on aliases. The patch is a refactoring that prepares for the main feature by changing how aliases are parsed from the config file.

The key change replaces the simple `skip_prefix()` approach with `parse_config_key()`, which properly handles the three-level config key structure needed for subsection support. This introduces a compatibility break - previously, Git would accept malformed alias entries like `alias.foo.bar` and treat them as an alias named "foo.bar". Now such entries will be silently ignored unless they use the proper subsection syntax (which will be implemented in the next patch).

The patch is well-motivated as part of the larger effort to support UTF-8 in alias names via subsections. It addresses a long-standing quirk in the alias parsing code while maintaining backward compatibility with existing simple aliases. The change has been reviewed by Jeff King and Junio Hamano, with all technical feedback addressed in this v3 iteration.

This is a focused, mechanical change that touches only `help.c` and serves as groundwork for the more user-visible changes coming in patch 3/3. The commit message clearly explains both the technical change and its implications for backward compatibility.
