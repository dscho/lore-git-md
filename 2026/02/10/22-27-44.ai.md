This is the second patch in a 3-part series implementing UTF-8 support for Git configuration subsections, specifically focusing on alias definitions. The patch performs a preparatory refactoring that changes how aliases are parsed from the config file.

The key change replaces the simple `skip_prefix()` approach with `parse_config_key()`, which properly handles the three-level config key structure needed for subsection support. This is technically a compatibility break - the old code would incorrectly accept malformed alias definitions like `alias.foo.bar` as defining an alias named "foo.bar", while the new code will ignore these unless the key is "command" (which gets special handling in the next patch).

The patch touches `help.c` to modify the `git_unknown_cmd_config()` function, which is used for command lookup. The change makes the alias parsing more strict and prepares for the upcoming subsection syntax while maintaining the existing simple alias functionality. The commit message notes this was arguably fixing a bug since dotted aliases were never intentionally supported.

This refactoring is part of the larger effort to enable UTF-8 in config subsections while maintaining backward compatibility. The change has been reviewed by Jeff King and Junio Hamano, with all technical feedback addressed in this v3 iteration. The patch appears well-contained and focused on its specific preparatory task before the main feature implementation in the next commit.
