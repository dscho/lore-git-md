This is a test infrastructure patch addressing CI failures on Windows/MSVC platforms, part of an ongoing discussion about handling `iconv(1)` executable availability when Git's ICONV support is enabled.

Patrick Steinhardt responds to feedback from Torsten Bögershausen and Junio Hamano about his patch series that fixes test failures occurring when Git is built with ICONV support but the `iconv(1)` executable is unavailable. The core issue stems from MinGW/Git for Windows no longer shipping the `iconv(1)` binary, causing test failures in several submodule-related test scripts.

The discussion has clarified two distinct concerns: libiconv (linked into Git for encoding support) versus the `iconv(1)` executable (used in test scripts). Patrick defends his approach of modifying test expectations rather than skipping encoding tests entirely, arguing that many tests are valuable even without ICONV support. He notes that when ICONV is unavailable, tests fall back to UTF-8 encoding which should behave identically to the no-ICONV case.

Torsten suggests restoring the `iconv(1)` binary in Git for Windows as an alternative solution (referencing GitHub issue #6083), but Patrick maintains that his changes would benefit other platforms lacking iconv support entirely. The patch series remains under discussion with no clear resolution yet between Junio's preference for skipping encoding tests versus Patrick's more surgical test modifications.
