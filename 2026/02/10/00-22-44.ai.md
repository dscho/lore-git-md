Bugfix for `git send-email` recipient suppression options. Junio C Hamano responds to Jim Cromie's bug report about `--suppress-to` and related options failing when used with `git send-email`. The maintainer clarifies that `--suppress-to` doesn't actually exist as a valid option, while `--no-to` and `--no-cc` only suppress command-line/configuration addresses, not those in patch files. 

This appears to be a documentation/expectation mismatch rather than a code bug - the reported errors occur because users are trying to use non-existent options (`--suppress-to`) or misunderstanding the scope of existing ones (`--no-to`/`--no-cc`). The thread suggests the documentation needs clarification about which suppression options are actually available and what they control. No code changes are proposed yet, but the discussion highlights a clear gap between user expectations and actual functionality that may need addressing either through documentation updates or behavioral changes.
