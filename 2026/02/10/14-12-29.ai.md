This is a test infrastructure patch addressing CI failures on Windows/MSVC platforms, part of an ongoing discussion about handling encoding tests when the `iconv(1)` executable is unavailable despite Git being built with ICONV support.

Patrick Steinhardt responds to feedback from Torsten Bögershausen and Junio Hamano about his patch series that modifies test expectations rather than skipping encoding tests when `iconv(1)` is missing. The key points in this reply are:

1. Patrick defends his approach of conditionally using `iconv(1)` only when the ICONV prerequisite is met, noting that tests default to UTF-8 encoding which should be a no-op when ICONV is unavailable. This maintains test coverage while working around the missing binary.

2. He acknowledges Torsten's clarification about the distinction between libiconv (linked into Git) and the `iconv(1)` executable (used in tests), with the latter no longer being shipped by MinGW/Git for Windows.

3. While agreeing the duplicated logic across test files is suboptimal, Patrick prioritizes fixing immediate CI failures over refactoring, though he leaves the door open for future deduplication.

4. The discussion reveals platform-specific nuances: Windows systems may have libiconv support while lacking the `iconv(1)` binary, and there's an open question about whether Git for Windows should restore the binary (GitHub issue #6083).

The patch remains in discussion with no clear resolution yet between Junio's preference for skipping encoding tests entirely without ICONV versus Patrick's more surgical approach of modifying test expectations.
