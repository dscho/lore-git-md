This is a build system patch addressing macOS-specific credential helper compilation issues. The change moves the build targets for `git-credential-osxkeychain` from its local Makefile to the top-level Makefile to ensure consistent flag definitions.

The patch notes that recent macOS-specific changes to the top-level Makefile (like Homebrew configuration and iconv workarounds) broke the standalone build of the credential helper, which now links against libgit.a. The current solution of manually adjusting the helper's Makefile is deemed fragile.

The technical changes:
- Adds new targets in the top-level Makefile for building, installing, and cleaning the credential helper
- Simplifies the local Makefile to delegate all operations to the top-level targets
- Maintains the same Security/CoreFoundation framework linkage needed for macOS keychain access

This appears to be a straightforward build system improvement that follows the pattern of other credential helpers. The change is well-motivated by recent build breakages and reduces maintenance burden by centralizing the build logic. The patch references three recent commits that necessitated this change, showing good attention to the problem's context.
