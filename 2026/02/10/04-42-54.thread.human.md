Derrick Stolee has proposed an RFC patch series to improve the performance of `git config list --type=<X>` by enabling type filtering during initial config parsing, rather than after parsing all values. This addresses a bottleneck observed in git-credential-manager. The five-patch series is currently at version 1.

The core design question remains whether skipping non-matching values during type-filtered listing aligns with Git's string-based config model - a point raised by maintainer Junio Hamano. In the latest exchange, Stolee engages with Junio's specific code review feedback on patch 3/5, agreeing to rename the `die_on_parse` parameter to `gently` (for consistency with Git conventions) and to refactor the cascading conditionals in `format_config()` into separate helper functions for each type. Stolee notes he'll implement these changes if the series proceeds to v2, showing a balanced approach to RFC-stage implementation effort.

The technical changes involve modifications to `builtin/config.c`, `config.c`, and `parse.c`, with test coverage in `t/t1300-config.sh`. The series builds on existing `--type` functionality while introducing infrastructure changes like `git_parse_maybe_pathname()` and `display_options_init_list()`. The discussion remains active on both the high-level design approach and specific implementation details.
