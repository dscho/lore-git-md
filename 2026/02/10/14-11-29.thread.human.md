This RFC thread proposes a new `git repo info` command to provide structured access to repository metadata like the Git directory path, addressing limitations in the current `git rev-parse` interface. Pushkar Singh's initial proposal focuses on exposing core repository paths (git-dir, common-dir, objects-dir) through a stable output format, building on Lucas Skeggs' earlier work adding `--format` support to the command.

Patrick Steinhardt has endorsed the general direction, agreeing that repository introspection belongs in `git repo` rather than `git rev-parse`, which has grown beyond its original purpose. The discussion recognizes this as part of a broader effort to rationalize Git's command structure. 

The latest patch from Pushkar narrows the scope to repository-derived paths while avoiding invocation-dependent values, proposing to reuse the existing `repo_info_fields[]` mechanism. The thread shows consensus on moving forward with this approach, though some technical details remain open - particularly around path formatting (absolute vs relative) which is being discussed in parallel. The tone remains collaborative, with participants aligned on the strategic goal of making `git repo` the canonical home for repository introspection features.
