The thread discusses Pushkar Singh's RFC proposal for a new `git repo info` command that would expose repository paths in a structured way, starting with the Git directory path as a more discoverable alternative to `git rev-parse`. Patrick Steinhardt has voiced support for the general direction, agreeing that repository metadata has outgrown `git rev-parse` and belongs in the `git repo` command family. 

While there's consensus on the high-level approach, key implementation details remain open, particularly whether paths should be reported as absolute or relative (a question Lucas Skeggs had previously explored without resolution). The discussion suggests this is part of a broader effort to rationalize Git's command structure, with `git repo` positioned as the natural home for repository introspection features. The initial scope focuses on the Git directory path, but the design leaves room to expand to other paths like the common directory or hooks location based on future feedback.
