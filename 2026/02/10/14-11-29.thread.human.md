This thread is discussing the migration of repository introspection functionality from `git rev-parse` to a new `git repo info` command, with Pushkar Singh and Patrick Steinhardt collaborating on the design. The latest patch series adds structured output for repository paths, specifically introducing `path.git-dir` and `path.common-dir` fields that mirror existing `rev-parse` functionality but with more consistent formatting via a new `--path-format` flag.

The implementation builds on Lucas Skeggs' earlier work on configurable path resolution while deliberately keeping the changes focused and mechanical - each patch adds one well-tested field using established repository path functions like `repo_get_git_dir()`. There's clear consensus that `git repo` should become the long-term home for this functionality, as `rev-parse` has outgrown its original purpose. The patches are progressing smoothly by avoiding broader unresolved questions about path semantics (like absolute vs relative formatting) that are being discussed in parallel. The latest addition for `path.git-dir` follows the same careful approach, suggesting this effort will likely land without significant controversy.
