This RFC thread proposes adding structured repository path introspection to `git repo info` as a more maintainable alternative to `git rev-parse`. Pushkar Singh and Patrick Steinhardt are collaborating on the design, which currently exposes `path.git-dir` and `path.common-dir` fields using existing repository path APIs. The approach has broad agreement, with Patrick noting this aligns with the long-term goal of moving repository metadata out of `rev-parse`.

Jayatheerth Kulkarni's review identifies two specific gaps: the test suite needs verification of path handling across different OS environments (particularly for absolute vs relative path formatting), and the documentation should be updated to include the new fields. While the core patches are mechanically sound and build on Lucas Skeggs' prior work, these practical concerns about test coverage and docs will need addressing before merging. The thread remains focused on technical implementation details, with no fundamental objections to the direction.
