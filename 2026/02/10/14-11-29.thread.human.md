This RFC thread continues the collaborative effort between Pushkar Singh and Patrick Steinhardt to move repository introspection functionality from `git rev-parse` to a new `git repo info` command. The latest patch adds structured output field `path.common-dir` to expose the common directory path, following the same pattern as previous additions like `path.git-dir`. 

The implementation builds on Lucas Skeggs' earlier work on configurable path resolution while maintaining a narrow technical scope - each patch adds one field with corresponding tests, using established repository path APIs like `repo_get_common_dir()`. The changes deliberately avoid broader questions about path formatting semantics that are being discussed in parallel threads. Patrick Steinhardt has been advocating for this incremental approach, and the thread shows consensus that `git repo` should become the canonical home for this functionality.

The latest addition follows the series' established pattern of mechanical, focused changes that mirror existing `rev-parse` behavior while providing more machine-readable output. With each field addition following the same uncontroversial template and using stable internal APIs, the patches are progressing smoothly toward integration. The remaining open questions about path representation (absolute vs relative) are being handled separately, allowing this series to move forward without blocking on those discussions.
