Here's a human-readable summary of the thread so far:

Pushkar Singh has proposed adding repository path information to `git repo info` as a more discoverable alternative to using `git rev-parse` for querying paths like the Git directory. The RFC suggests starting with exposing just the Git directory path (equivalent to `--git-dir`) as a first step, while leaving open questions about path representation (absolute vs relative) for discussion.

The author clarifies this isn't meant to replace `git rev-parse` but rather to complement it with a more structured interface for repository metadata. The proposal is in early stages, with key technical considerations being which paths to expose and how to format them. This could affect scripts and tools that currently use `rev-parse` for path queries, though the change would be purely additive. Feedback is being sought before implementation.
