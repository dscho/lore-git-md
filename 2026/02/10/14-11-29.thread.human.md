This RFC thread proposes adding structured path information fields (`path.git-dir` and `path.common-dir`) to `git repo info` as a more maintainable alternative to `git rev-parse`. The technical implementation by Pushkar Singh builds cleanly on Lucas Skeggs' prior work and uses established path APIs, with Patrick Steinhardt supporting the long-term goal of moving repository introspection to `git repo`. Reviewers identified minor gaps in testing cross-platform path handling and documentation that need addressing.

However, Lucas Seiki Oshiro has now raised concerns about the foundational `git repo info` infrastructure not yet being accepted, casting uncertainty over whether these incremental additions can proceed independently. While the technical approach remains sound and the patches follow a clear precedent, the series may need to wait for broader architectural approval of the base command before these fields can be considered. The thread now awaits clarification on whether the core `git repo info` functionality will be accepted, which will determine next steps for this work.
