This is a documentation clarification thread related to the `diff.noprefix` and `format.noprefix` configuration settings, using a man page patch as a test case. The discussion reveals that the fix for prefixless patch handling (commit 15108de2) was incorrectly attributed to Git 2.39.5 when it actually landed in v2.41.0-rc0.

Alejandro Colomar identifies the root cause of the patch application failure - the sender (наб) is using an older Git version (2.39.5) that doesn't include the `format.noprefix` feature. This explains why their `diff.noprefix=true` setting is still affecting `git format-patch` output, causing the patches to fail when applied by recipients.

Kristoffer Haugsbakk raises a documentation question about how to properly document the difference in value handling between the boolean `diff.noprefix` and the any-value `format.noprefix` settings. The current documentation uses "If set" phrasing which doesn't clearly indicate that `format.noprefix` accepts any value rather than requiring a boolean.

The thread confirms that the technical solution (introducing `format.noprefix` in v2.41.0) is working as intended, but highlights two remaining issues: users on older Git releases will still encounter problems, and the documentation could be clearer about the configuration value semantics. The discussion remains focused on the documentation aspect, with Jeff King (Peff) cc'd for his input as the author of the original fix.
