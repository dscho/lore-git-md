This is a review response from Junio Hamano on the proposed `pre-add` hook patch. The maintainer raises several technical concerns about the current implementation.

Junio identifies two main issues with the hook design: (1) it runs too early in the process, before the command has processed the pathspec or determined the operation mode (-u/--renormalize), leaving the hook without critical context to make decisions; and (2) passing GIT_INDEX_FILE may be unnecessary since `git add` only ever operates on the main index file, unlike `git commit` which can work with multiple index files.

The review suggests the hook as currently implemented may not be practically useful due to these design limitations. Junio's critique focuses on the technical specifics of when and how the hook executes rather than rejecting the concept outright. This indicates the proposal needs significant rework to address the timing and information-flow concerns before it could be considered for inclusion.

Key points for future discussion in the thread will likely center around:
- When exactly the hook should run in the add workflow
- What information needs to be passed to the hook (pathspec, operation type)
- Whether GIT_INDEX_FILE is actually needed
- How to handle the various add modes (-u, -A, --renormalize) consistently

The maintainer's feedback suggests this version won't be accepted without addressing these fundamental design questions.
