This is a technical discussion about implementing config-based Git hooks, part of Adrian Ratiu's ongoing series to make hooks configurable via Git configuration. The exchange focuses on implementation details of the `list_hooks()` function in hook.c, which consolidates hooks from both filesystem and config sources.

Patrick Steinhardt identifies two issues in the current implementation: an unnecessary `r->gitdir` check (which Adrian confirms is a leftover from earlier refactoring) and the surprising use of empty strings to identify filesystem hooks. Adrian acknowledges both points, noting that Junio Hamano had previously suggested using a proper struct/union to distinguish between hook types rather than relying on naming conventions.

The discussion remains constructive, with Adrian committing to address both points in v2 of the patch series. This includes moving the gitdir check to a more appropriate location and implementing typed hook identification as suggested by Junio. The exchange demonstrates the careful attention to implementation quality in this feature, with Patrick providing focused technical review and Adrian actively incorporating feedback while maintaining the series' overall direction.
