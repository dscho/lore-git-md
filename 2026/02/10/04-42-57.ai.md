Performance improvement patch for `git config list --type` filtering, part 3/5 in Derrick Stolee's series. This patch modifies `format_config()` in `builtin/config.c` to support non-fatal type checking, a prerequisite for efficient `--type` filtering in `git config list`. The key change introduces a `die_on_parse` parameter that determines whether parsing failures should terminate the program (current behavior) or be handled gracefully (needed for list filtering).

The patch systematically updates each type handler (INT, BOOL, PATH, etc.) to have both fatal and non-fatal variants, with the non-fatal versions using the new parsing helpers introduced in patch 2. The changes maintain backward compatibility while enabling the future optimization where `git config list --type=<X>` can skip invalid entries rather than failing the entire command.

This is a mechanical but careful refactoring that touches core config parsing logic. The patch follows the series' incremental approach, building on the foundation from previous patches while keeping each change focused. The next patches will wire up the actual list-mode filtering using these new capabilities.
