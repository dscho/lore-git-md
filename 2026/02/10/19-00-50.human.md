This is a reply from Git maintainer Junio C Hamano to a proposal for a new `pre-add` hook. The thread concerns adding validation capabilities before changes enter the index.

Junio raises substantive concerns about the current implementation's design, arguing the hook runs too early and lacks critical context about the operation mode (like `-u` or `--renormalize`). He proposes an alternative approach that would split `write_locked_index()` into two phases, allowing the hook to compare the original and proposed index states more effectively.

The suggested redesign would provide the hook with two index files: the original state and the proposed new state. This would enable more sophisticated validation, like detecting if specific patterns (e.g., "company secret") are being added. Junio's feedback indicates the current patch needs significant architectural changes before it could be considered.

This is a technical discussion about hook placement and interface design rather than outright rejection. The maintainer is engaging constructively to shape the feature into something more robust, though the required changes are non-trivial. Contributors interested in Git's internals or hook infrastructure should follow this thread for the eventual v2 design.
