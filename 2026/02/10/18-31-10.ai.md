This is the second patch in a two-part series implementing UTF-8 support for Git configuration subsections, specifically focused on aliases. The patch enables non-alphanumeric alias names (including UTF-8 characters) through the subsection syntax (`[alias "förgrena"]`), while maintaining backward compatibility with the traditional case-insensitive syntax (`[alias] co = checkout`).

The implementation handles several key aspects:
- Case sensitivity differences between the two syntax forms (subsection names are case-sensitive while traditional aliases remain case-insensitive)
- UTF-8 support in alias names and proper display alignment using `utf8_strwidth()`
- Consolidated alias listing logic in the help system
- Comprehensive test coverage including Swedish, CJK, and space-containing aliases

The patch builds on feedback from the first iteration, with Jeff King (Peff) providing design input and Junio Hamano reviewing the documentation. The changes touch `alias.c`, `help.c`, and the config documentation, with new tests in `t/t0014-alias.sh`. Windows support remains an open question deferred to future work, but the Unix implementation is complete and ready for merging after minor documentation tweaks.

This represents a careful expansion of Git's Unicode support while maintaining backward compatibility, with clear documentation of the two syntax forms and their behavioral differences. The implementation is cleanly integrated with existing config infrastructure and includes thorough test coverage for the new functionality.
