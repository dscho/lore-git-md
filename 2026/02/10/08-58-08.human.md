This is a follow-up in a bug report thread about `git fast-export` dropping GPG signatures from commits. The original report identified that commit signatures were being lost during export, unlike tag signatures which can be preserved with `--signed-tags=verbatim`.

Matthias Urlichs notes in this follow-up that there actually is an existing `--signed-commits` option to control this behavior, which they had initially missed. They suggest that this option should probably mirror the behavior of `--signed-tags` by default unless explicitly overridden, implying the current default behavior may be surprising.

The thread reveals an inconsistency in signature handling between commits and tags in `git fast-export`, with the follow-up pointing to an existing (but perhaps not well-known) solution. This suggests the issue might be more about discoverability and default behavior than a missing feature. The discussion appears to be moving toward considering whether the defaults should be aligned between commit and tag signature handling.
