This is a platform compatibility discussion about Git's build system, specifically around meson deprecation warnings and path handling differences between make and meson builds.

Ramsay Jones reports that the meson build system shows different behavior between Linux and Cygwin platforms, with version number discrepancies and path differences in the built git-gui executable. Patrick Steinhardt investigates and determines that a meson deprecation warning (about `configure_file` copy arguments) was rolled back in meson 1.5.0, making the warning a non-issue. 

The discussion reveals two concrete issues: first, the meson build incorrectly sets `GIT_CEILING_DIRECTORIES` when git-gui is built as a subproject, causing version number discrepancies; second, there are path differences (`/bin/sh` vs `/usr/bin/sh`) in the generated scripts. Patrick has submitted a PR to address these issues, noting they align with similar fixes previously made in Git's main build system. The changes aim to make meson builds behave consistently with traditional Makefile builds across platforms.

This exchange is part of the ongoing effort to modernize Git's build system with meson while maintaining platform compatibility. The issues discussed are relatively straightforward build system quirks rather than deep technical problems, and Patrick's prompt response with a fix suggests these are minor bumps in the meson integration work rather than major obstacles. The thread demonstrates the project's attention to cross-platform consistency even in build system details.
