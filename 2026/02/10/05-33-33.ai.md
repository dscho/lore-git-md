This is a bug report about unexpected behavior in `git fetch --dry-run`. Tyler Breisacher observes that even with `--dry-run`, running `git fetch --depth=1` creates a `.git/shallow` file when none existed before, which contradicts the expectation that dry-run operations should not modify the repository.

The issue occurs specifically in non-shallow clones where the `--depth` option is used. The presence of a `.git/shallow` file indicates the repository has been marked as shallow, which is a persistent change that affects future operations. This behavior appears to violate the principle that dry-run modes should be read-only.

The report is concise but clearly demonstrates the problem with reproducible steps. No workaround or proposed fix is included - it's presented purely as an observation of unexpected behavior that warrants investigation. The issue touches core fetch functionality and could affect any user employing `--dry-run` with depth-limiting options.
