This is a follow-up in the ongoing discussion about a proposed `config-batch` builtin for optimizing config operations, particularly for credential manager workflows. Derrick Stolee responds to brian m. carlson's suggestion that existing `git config -l -z` might suffice by revealing a key limitation: Git credential manager (GCM) relies on `--type=<X>` filtering which isn't compatible with the list mode.

Stolee shares a new RFC (linked) that adds `--type` support to `git config list`, acknowledging this as a simpler interim solution despite being a breaking change. He notes this provides immediate performance benefits for GCM's path-type queries (the most frequent/slowest case), though still requiring multiple commands for full type coverage. The original batch proposal is temporarily shelved while Stolee pursues these incremental gains, but he outlines future considerations including subcommand integration, server-mode implementation, and comprehensive option support.

The exchange demonstrates how real-world tool requirements (GCM's type filtering) can surface non-obvious constraints in proposed alternatives. Stolee's pragmatic approach - pursuing quick wins while keeping the larger design questions open - shows responsiveness to feedback while maintaining focus on the core performance motivation. The thread continues to balance interface minimalism against workflow needs, with this email adding concrete data about type-filtering requirements that wasn't previously discussed.
