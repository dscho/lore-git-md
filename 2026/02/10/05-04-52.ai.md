Performance optimization for `git config list --type` filtering, part of a series addressing a git-credential-manager bottleneck.

This is patch 3/5 in Derrick Stolee's series to improve `git config list --type` performance by filtering during parsing rather than after. The patch modifies `format_config()` to optionally skip invalid values (when `die_on_parse=0`) rather than failing the entire command, preparing for type-based filtering in `git config list`.

Key changes:
- Adds `die_on_parse` parameter to control error handling
- Restructures type-specific formatting as cascading conditionals
- Maintains existing die-on-error behavior for current callers
- Lays groundwork for patch 5's type-aware filtering

Junio C Hamano suggests two readability improvements in his review: using a more conventional `bool gently` parameter name, and considering helper functions for each type case to reduce `format_config()` complexity. The thread's main design question remains whether filtering invalid typed values (rather than failing) aligns with Git's string-based config model, but this patch focuses on the mechanical changes needed regardless of that decision.

The patch touches `builtin/config.c` and is part of a performance optimization that builds on existing `--type` handling from `git config get`. Test coverage will come in patch 5 of the series.
