Feature proposal for a new pre-add hook. This patch introduces a `pre-add` hook that runs after pathspec validation but before files are staged, allowing users to validate or reject additions to the index. The hook receives GIT_INDEX_FILE in its environment and can be bypassed with `--no-verify`. It's explicitly not invoked for interactive/patch/dry-run modes or when files are staged via `git commit -a`.

The implementation adds the hook infrastructure to `builtin/add.c` with minimal performance impact when no hook is installed. The accompanying tests verify behavior for successful/failing hooks, environment variable passing, and various `git add` modes. Documentation updates cover both the new hook and the `--no-verify` option.

The patch appears well-structured with thorough test coverage. The use case is clearly motivated - currently users must either wrap `git add` or wait until pre-commit to validate changes. The implementation follows existing hook patterns while accounting for `git add`'s specific behaviors. The disclosure of AI-assisted development is notable but doesn't raise quality concerns given the manual review stated.
