Performance improvement series for `git config list --type` filtering (part 2/5).

This patch introduces `git_parse_maybe_pathname()`, a non-fatal version of the existing `git_config_pathname()` function. The new helper moves path parsing logic from `config.c` to `parse.c` while maintaining the same behavior - it handles both regular and `:(optional)`-prefixed paths, expanding user directories and checking file existence. The key difference is that it returns an error code rather than calling `die()` on failure, making it suitable for use in the planned type-filtering optimization where we want to continue processing other config entries even if one path fails to parse.

The change is mechanical and well-contained, touching only three files: moving the implementation from `config.c` to `parse.c` while updating the header, and modifying `git_config_pathname()` to be a thin wrapper around the new function. This prepares for patch 3/5 which will use this helper for early type filtering during config parsing. The patch maintains backward compatibility since `git_config_pathname()` still exists and behaves identically for existing callers.
