This is a follow-up in a bug report thread about `git fast-export` dropping GPG signatures from commits. The original report identified that commit signatures were being silently omitted during export, unlike tag signatures which can be preserved with `--signed-tags=verbatim`.

Matthias Urlichs now notes that there is already an existing `--signed-commits` option to control this behavior, which he had initially missed. He suggests that the option should probably default to matching whatever `--signed-tags` is set to unless explicitly overridden. This would make the behavior more consistent between commit and tag signature handling.

The email doesn't propose a patch but identifies a potential improvement to the default behavior that could make the interface more intuitive. The observation builds on the original bug report's findings about signature preservation inconsistencies in the export process. This appears to be a minor UX suggestion rather than a technical fix for the underlying signature-dropping behavior.
