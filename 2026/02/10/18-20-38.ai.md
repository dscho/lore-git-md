This is a documentation patch finalizing warnings about patch roundtrip hazards in Git's man pages. Kristoffer Haugsbakk is addressing a minor formatting issue in the previously approved documentation changes, switching from a thematic break to an explicit heading ("=== Patch application") for better man page rendering. The patch is part of the layered solution to the `git am` security vulnerability where unindented diffs in commit messages can be misinterpreted during patch application.

The technical content remains unchanged from the version already reviewed by Phillip Wood and queued by Junio - this is purely a presentation tweak. The documentation warns about parsing ambiguities (unindented diffs, separator lines) that can cause security issues when patches are applied, particularly affecting distribution workflows. The warnings appear in multiple man pages via a shared include file (`format-patch-caveats.adoc`).

This refinement shows the attention to detail in Git's documentation process, where even minor rendering issues in man page output are addressed before final merging. The change is uncontroversial and unlikely to require further discussion, as it follows directly from prior review feedback about the documentation's presentation.
