This is a follow-up in the ongoing discussion about `diff.noprefix` and `format.noprefix` configuration options. Alejandro Colomar confirms that while the fix (commit 15108de2 adding `format.noprefix`) is in Git v2.41.0+, users on older stable distributions will continue to encounter issues with patch application when `diff.noprefix` is set. The email serves as a recognition that this remains a practical problem for users stuck on older Git versions, though there's no proposed solution beyond acknowledging the version constraint.

The thread context shows this is part of a larger documentation and version clarification effort led by Kristoffer Haugsbakk, with Junio Hamano and Jeff King involved in earlier participants. The key technical detail here is the confirmation that `format.noprefix` (which accepts any value) is the proper solution for patch prefix handling in v2.41.0+, while `diff.noprefix` (a boolean) remains problematic for older versions. The email doesn't advance the documentation work but reinforces the real-world impact of the version mismatch.
