This is an RFC proposal for adding repository path information to `git repo info`. The author, Pushkar Singh, notes that while `git rev-parse` is currently used to query paths like the Git directory, common directory, and hooks path, these could be more discoverable if exposed through the structured output of `git repo info`.

The proposal suggests starting with adding the Git directory path (`--git-dir` equivalent) as a first step, with questions remaining about whether paths should be reported as absolute or relative. The author is explicitly not proposing to replace `git rev-parse`, but rather to complement it with a more user-friendly interface for repository metadata.

This appears to be an early-stage proposal seeking feedback before implementation. The key technical considerations are which paths to expose (starting with git-dir) and how to represent them (absolute vs relative paths). The change would affect scripts and tooling that currently rely on `git rev-parse` for path information, though the author emphasizes this would be additive rather than a replacement.
