This thread addresses a configuration mismatch between `diff.noprefix` and `format.noprefix` that affects patch generation and application workflows. The core issue arises when `diff.noprefix=true` creates prefixless patches that work with `git add -p` but fail with `git am`. The solution, implemented in commit 15108de2 (merged in v2.41.0-rc0), introduced `format.noprefix` to control this behavior separately.

Key participants include Alejandro Colomar and наб (Ahelenia Ziemiańska) who reported the workflow issues, Kristoffer Haugsbakk who identified documentation gaps, and Junio Hamano who confirmed the current implementation. Jeff King (Peff) has been consulted as the code area authority.

Kristoffer recently clarified that while the original patch signature claimed the change was in Git 2.39.5, it actually landed in v2.41.0-rc0 - an important correction for tracking the solution's availability. Junio confirmed this with his characteristic dry humor, noting the change is already in released code.

The remaining open question is whether the current implementation fully resolves the reported workflow discontinuity, particularly for users moving patches between differently configured systems. Kristoffer's documentation improvements to clarify the boolean vs any-value distinction between these settings are still pending. The discussion remains focused on ensuring users understand how to properly configure these options for consistent patch handling.
