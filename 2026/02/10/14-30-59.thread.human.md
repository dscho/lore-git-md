This thread discusses an issue with Git's patch generation and application when the `diff.noprefix` configuration is enabled. The problem arose when наб (Ahelenia Ziemiańska) tried to apply a patch for the `futex_waitv.2` man page, but it failed due to path issues. The root cause was that наб had `diff.noprefix=true` set locally, which caused `git format-patch` to omit the usual `a/` and `b/` prefixes in the diff output. While наб expected `git am` to handle such prefixless patches (as `git add -p` does), the application failed.

Alejandro Colomar notes this is a recurring problem and asks Junio Hamano for an update on a previously discussed fix—Junio had mentioned he would queue a change to make `format-patch` ignore `noprefix`, but this hasn't been implemented yet. The discussion remains focused on this edge case in Git's diff handling rather than the content of the original man page patch. The key open question is whether and when Junio will address the `format-patch` behavior regarding `noprefix`.
