Here's a human-readable summary of the thread's current state:

This thread addresses a long-standing quirk in Git's patch generation where the `diff.noprefix` configuration can unexpectedly affect `git format-patch` outputting patches without standard `a/` and `b/` prefixes. While `git add -p` can handle these prefixless patches, `git am` fails on them, creating workflow issues - as experienced by наб and Alejandro Colomar when working with man page patches.

Junio Hamano had previously indicated he would queue a fix to make `format-patch` ignore `noprefix` settings, though its current status remains unclear. Meanwhile, commit 15108de2 introduced `format.noprefix` to explicitly control this behavior, but the documentation wasn't entirely clear about how it differs from `diff.noprefix`.

Kristoffer Haugsbakk has now proposed a documentation patch to clarify that `format.noprefix` works differently from its `diff.*` counterpart - it's enabled by any value being set, not just `true`. The patch aims to prevent future confusion for users who, like the thread participants, have encountered this subtle but impactful behavior difference. With Jeff King CC'd for review, this documentation improvement may help bridge the gap while awaiting Junio's promised behavioral fix.
