This is a follow-up in a thread about `git send-email` recipient suppression options. Jim Cromie confirms Junio C Hamano's earlier clarification that `--suppress-to` is not a valid option (despite appearing in some documentation) and that `--no-to`/`--no-cc` only suppress addresses from command line and configuration, not from patch files. 

The exchange reveals a documentation issue - the current man page description of `--no-to`/`--no-cc` as clearing addresses "previously set via config" is ambiguous. Jim suggests "options" would be clearer than "config" to better reflect that these flags affect both command-line and configured addresses. 

This appears to be closing the loop on the original confusion, with no new technical issues raised. The thread has established that the current behavior is intentional (patch file recipients are always included unless manually edited) but the documentation could be clearer about the scope of these suppression options. No patch is proposed in this email - it's primarily an acknowledgement of the maintainer's explanation and a minor documentation suggestion.
