This is a bugfix discussion thread about `git log --graph` output formatting when combined with `-p/--patch` and custom pretty formats. The maintainer Junio C Hamano chimes in to clarify a technical detail about the workaround.

The thread has already identified that the bug occurs when using `--graph --pretty='format:%h' -p` (without a trailing newline), causing graph connection characters to appear incorrectly at line endings. D. Ben Knoble previously noted two workarounds: using `tformat:` instead of `format:`, or explicitly adding `%n` to the format string.

Junio's contribution here is to point out that `--format=<whatever>` is actually a shorthand for `--pretty=tformat:<whatever>`, which may be more convenient for users than typing out the full `tformat:` syntax. This doesn't change the technical analysis but provides a usability tip for implementing one of the known workarounds.

The discussion remains focused on documenting and working around the issue rather than proposing a deeper fix to the underlying output formatting logic in `log-tree.c`. As the maintainer, Junio's brief intervention suggests the workarounds are considered sufficient for now, though the core bug remains unaddressed.
