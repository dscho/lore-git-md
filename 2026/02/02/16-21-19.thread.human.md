Here's a human-readable thread summary:

A bug report highlights incorrect graph formatting in `git log` when combining `--graph`, custom pretty formats, and `-p`. The issue causes graph connection characters (like `|`) to appear at the end of commit lines rather than properly aligned at the start, breaking the visual hierarchy. This occurs specifically with `--pretty=format:` (not `tformat:`) when the format string lacks a trailing newline and `-p` is used to show patches.

The reporter provided clear reproduction steps and output comparisons showing the misalignment, noting the bug has existed since at least Git 2.51.0. Two workarounds were suggested - using `tformat:` instead of `format:` or adding `%n` to the format string - though these introduce minor visual differences in spacing. The core issue appears to stem from how `log-tree.c` interleaves graph and patch output when processing format strings without newlines. No maintainer response or proposed fix has appeared yet in the thread.
