Here's the updated human-readable summary:

This thread examines a long-standing bug in `git log --graph` output formatting when combined with `-p/--patch` and custom pretty formats that lack newlines. The issue manifests when using commands like `--graph --pretty='format:%h' -p`, causing graph connection characters (`|`, `\`, `/`) to appear incorrectly at line endings rather than starts. Pushkar Singh and the original reporter confirmed this behavior persists from Git 2.43.0 through 2.51.0.

D. Ben Knoble pinpointed the root cause as the missing newline in the format specifier and suggested two workarounds: using `tformat:` instead (with slightly different color behavior) or explicitly adding `%n` to the format string. Maintainer Junio C Hamano later clarified that `--format=<whatever>` is actually shorthand for `--pretty=tformat:<whatever>`, providing a more convenient way to implement one workaround. While the thread has clearly documented reproduction steps and practical solutions, the core issue in `log-tree.c`'s output formatting logic remains unaddressed for now, with the workarounds being deemed sufficient.
