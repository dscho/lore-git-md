Here's the updated human-readable thread summary:

This thread reports a bug in `git log --graph` output when combined with custom pretty formats and patch display (`-p`). The issue occurs when using a format string without a trailing newline (like `--pretty='format:%h'`), causing graph connection characters (`|`, `\`, `/`) to appear at line ends instead of starts, breaking the visual graph structure. Multiple users have confirmed the bug affects Git versions from 2.43.0 through 2.51.0, showing it's a long-standing issue in `log-tree.c`'s output formatting logic.

D. Ben Knoble analyzed that the problem stems from the missing newline in the format specifier. Two workarounds exist: using `tformat:` instead of `format:` (though this affects color handling) or explicitly adding `%n` to the format string (which alters spacing). While these solutions address the immediate problem, they may not be ideal for all use cases. The thread has established clear reproduction steps but hasn't yet produced a deeper technical analysis of the root cause or proposed fixes to properly handle newline-less formats in the graph/patch output pipeline.
