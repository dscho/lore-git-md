Bugfix regression in `git subtree` validation logic. Junio C Hamano acknowledges Josh Steadmon's report that the recent patch fixing `--prefix` validation in `git subtree split` has caused test case 17 to fail. The test verifies that the `--prefix` path must exist, and the new commit-based validation appears to be too strict in some scenarios.

The patch had been through three iterations to address inconsistent validation behavior, with v3 specifically adding regression test coverage and fixing style issues. However, real-world usage at Google has revealed an edge case where the validation now fails where it previously worked. Junio notes the importance of catching this while the patch is still in the 'next' branch, allowing for reversion before it reaches 'master'.

This appears to be a case where fixing one validation inconsistency created another, showing the delicate balance required when modifying long-standing behavior in contrib scripts. The original author (Pushkar Singh) will likely need to investigate whether the validation logic needs adjustment, the test expectations need updating, or both. The thread shows the project's responsiveness to regression reports, even for components like `contrib/subtree` that aren't part of Git's core.
