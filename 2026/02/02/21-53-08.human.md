This is a discussion about the proposed `@{default}` shorthand for referencing a repository's primary branch, now in its fourth iteration. Kristoffer Haugsbakk responds to Harald Nordgren's defense of the branch-attached workflow requirement, which is being questioned by Junio Hamano.

Kristoffer argues that a detached HEAD (pointing directly to the remote-tracking branch) suffices for common use cases like bug investigation and comparison operations. He demonstrates this with concrete examples: using `git diff` to check if a bug exists in the main branch, examining history with `git log`, and setting upstream branches - all of which can be done without being on a local branch.

The email highlights a key tension in the thread: while Harald maintains that being on a branch is essential, Kristoffer and others (including Junio) are questioning whether this requirement is truly necessary given that detached HEADs can serve many of the same purposes. This challenges one of the original justifications for introducing new syntax.

The discussion has reached a critical point where proponents of the feature need to either demonstrate workflows that absolutely require being on a branch (not just a detached HEAD) or accept that the convenience may not justify the complexity. The technical implementation remains sound, but the philosophical justification is under scrutiny.
