This is the first patch in a v4 series implementing reference backend selection for zero-downtime migrations between files and reftable backends. The patch extends the `extensions.refStorage` config to support URI-style specification of both the backend type and location (e.g. `reftable:///path/to/refs`), enabling out-of-tree reference directories.

Key changes in this patch:
- Adds `ref_storage_payload` field to `struct repository` and `struct repository_format` to store the URI/path component
- Introduces `parse_reference_uri()` to split URIs into format and payload components
- Updates repository initialization to handle the payload throughout the setup chain
- Modifies `create_reference_database()` to accept the payload parameter
- Maintains backward compatibility with simple format names (non-URI values)

The implementation touches core repository setup code, adding plumbing to propagate the reference location information while preserving the existing behavior when no location is specified. This is part of GitLab's planned zero-downtime migration strategy for large repositories.

The patch appears well-structured with thorough updates to all affected functions and clear separation between the format and payload components. It builds on previous discussion and review feedback, particularly from Patrick Steinhardt who is credited as a helper. The changes are focused and mechanical, primarily adding the plumbing needed for subsequent patches to implement the actual backend handling.
