This is a discussion about the proposed `@{default}` shorthand for referencing a repository's primary branch, now in its fourth iteration. Kristoffer Haugsbakk responds to Harald Nordgren's defense of the branch-attached workflow requirement, providing concrete examples where working on a branch (rather than detached HEAD) is necessary.

The email reinforces the use case for needing to be on an actual branch rather than a detached HEAD, specifically for:
1. Comparing work against the primary branch baseline (bug investigation)
2. Using in git-diff and git-log ranges
3. Setting upstream branches with `git branch --set-upstream-to`

This comes as a direct response to Junio Hamano's recent questioning of whether detached HEAD could suffice for read-only operations. Kristoffer's examples aim to demonstrate scenarios where branch attachment is functionally required, not just a preference. The discussion remains at a critical juncture where proponents must either strengthen the justification for branch-attached requirements or potentially see the feature deprioritized.

The technical implementation (resolving via remote-tracking branch infrastructure) remains sound, but the debate has shifted to fundamental questions about whether the syntax is solving a real workflow gap or merely providing syntactic sugar. Kristoffer's examples represent an attempt to show the former by highlighting operations that genuinely require branch context.
