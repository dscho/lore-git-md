This is the fourth version of a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories. The key addition in v4 is worktree reference handling, which was the last major technical blocker from the v3 discussion.

The series introduces two ways to specify reference backends and locations:
1. A URI format in `extensions.refStorage` config (e.g. `reftable:///path/to/refs`)
2. A new `GIT_REFERENCE_BACKEND` environment variable override

The primary use case is enabling GitLab's zero-downtime migration strategy for large repositories with millions of references. The patch set allows writing refs to arbitrary locations during the migration window, minimizing downtime to just the duration of reference writes between locking steps.

Notable changes in v4:
- Complete rewrite to properly handle worktree references, storing them in `ref_dir/worktrees/wt_id` with corresponding stubs in the git dir
- Support for relative paths in reference directories (resolved relative to GIT_DIR)
- All architectural decisions from previous discussions are now implemented

The implementation touches core ref storage initialization, URI parsing, worktree integration, and adds comprehensive test coverage in t1423-ref-backend.sh. With worktree support now addressed, this version appears ready for final review and potential integration.
