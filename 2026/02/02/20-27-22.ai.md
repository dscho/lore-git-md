This is a bugfix discussion for `git log --graph` output formatting when combined with custom pretty formats and patch output. The thread has established that when using `--graph --pretty='format:%h' -p` (without a trailing newline in the format string), graph connection characters (`|`) appear incorrectly at the end of commit lines rather than at the start of diff lines where they belong. D. Ben Knoble confirms the issue stems from the missing newline in the format:` specifier, noting that either switching to `tformat:` or explicitly adding `%n` to the format string works around the problem. 

The bug appears long-standing (confirmed on Git 2.43.0 through 2.51.0) and affects the interaction between `log-tree.c`'s graph rendering and patch output logic. While the workarounds exist, they may not be ideal for all use cases - `tformat:` has slightly different behavior regarding color codes, and adding `%n` changes the output formatting. The discussion now has clear reproduction steps but lacks analysis of the underlying code path or proposed fixes to properly handle the newline-less format case.
