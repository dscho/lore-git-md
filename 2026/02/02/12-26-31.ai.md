This is part 2 of a 4-patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable). The series is now in its fourth iteration with all major technical challenges resolved.

The patch extracts common code for creating reference directory stubs into a new `refs_create_refdir_stubs()` function. Git requires certain filesystem artifacts (HEAD file and refs/ directory) to recognize a directory as a Git repository, even when using alternative backends like reftable that don't natively use these paths. The function centralizes this stub creation logic, which was previously duplicated in clone.c and reftable-backend.c.

Key changes in this version:
- New public function in refs.h with documentation
- Handles both basic stubs (HEAD and refs/) and optional refs/heads message
- Maintains existing permissions behavior via adjust_shared_perm()
- Updates both call sites to use the new helper

The change is a straightforward refactoring that doesn't modify behavior, just consolidates duplicate code in preparation for future use. It's part of the larger effort to make reference backends properly pluggable while maintaining compatibility with existing Git tooling expectations.
