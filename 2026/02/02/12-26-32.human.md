This is part 3 of a 4-patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories. The series is now in its fourth iteration with all architectural decisions implemented.

The patch focuses on parsing and utilizing the reference storage payload that specifies where to store references for a given directory. Key changes include:

1. Adding support for URI-style configuration (`<format>://<location>`) in `extensions.refStorage` alongside simple format names
2. Implementing `refs_compute_filesystem_location()` to handle path resolution for both main and worktree references
3. Modifying worktree reference storage to use the specified alternate path while maintaining Git directory compatibility through stubs
4. Updating both files and reftable backends to use the new path computation logic
5. Adding comprehensive tests in t1423-ref-backend.sh covering URI parsing, backend switching, and worktree integration

The implementation appears thorough, with clear documentation of the URI format and careful handling of relative paths. The worktree integration in particular shows attention to backward compatibility needs. The patch builds on previous iterations' feedback and seems ready for final review.
