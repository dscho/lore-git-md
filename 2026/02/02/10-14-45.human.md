This is the latest in a long-running thread about adding a shorthand for switching to a repository's default branch. Harald Nordgren responds to Phillip Wood's questions about the use case and clarifies his workflow needs.

The patch proposes `@{primary}` (previously `@{default}`) as a shorthand that would resolve to the local branch tracking the remote's default (e.g., `main` or `master`). Harald provides concrete examples showing how this would work across repositories where the default branch has different names (main/master/trunk). He explains his specific workflow where he needs to frequently switch to the default branch for releases and bug investigation, but never commits directly to it.

.

The discussion points center on whether the shorthand should resolve based on remote-tracking branches (Harald's approach) or local configuration (Phillip's suggested `@{local}` alternative). Harald defends the remote-tracking approach as more flexible for real-world use across repositories with varying conventions. His examples demonstrate the current manual workaround is cumbersome, requiring shell pipelines to achieve what the shorthand would provide directly.

.

The thread remains unresolved on key questions: whether to prioritize conceptual purity (aligning with local config) or practical utility (Harald's remote-tracking approach), and what naming best captures the semantics (`@{primary}` vs `@{default}` vs `@{local}`). Harald's latest email strengthens the case for the shorthand's practical value but doesn't fully address the architectural concerns raised earlier in the thread.
