This is the final patch in a series implementing reference backend selection for zero-downtime migrations between files and reftable backends. The series has been through multiple rounds of review and addresses GitLab's migration needs.

The patch adds a `GIT_REFERENCE_BACKEND` environment variable that mirrors the existing `extensions.refStorage` config option, allowing runtime override of the reference backend for individual commands. The implementation:
- Parses the environment variable during repository setup
- Overrides any config-based backend specification
- Uses the same URI format as the config option (`backend://path`)
- Includes comprehensive test coverage in t1423-ref-backend.sh

The tests verify both valid and invalid cases, including unknown backends and malformed URIs. Worktree support is also tested, confirming references are properly isolated between worktrees when using alternate backends.

This completes the series' technical implementation, with all architectural decisions now implemented. The environment variable provides flexibility for migration workflows where temporary backend switching is required. The patch builds on previous work that added core URI parsing and worktree integration.
