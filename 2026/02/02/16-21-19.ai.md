Bugfix targeting the `git log --graph` output formatting when combined with `-p/--patch` and custom pretty formats. The reporter demonstrates that when using `--graph --pretty='format:%h' -p`, graph characters (like `|` for connecting lines) are misplaced - appearing at the end of commit lines rather than at the start where they belong. This breaks the visual graph structure.

The bug manifests when:
1. Using `--graph` with a custom `--pretty=format:` (not `tformat:`)
2. Adding `-p` to show patches
3. The format string doesn't end with a newline (`%h` vs `%h%n`)

The reporter provides two workarounds (using `tformat:` or adding `%n` to the format string) but notes these have their own visual quirks. The core issue appears to be in how the graph output is interleaved with patch output when using custom formats without newlines.

This affects the graph rendering logic in `log-tree.c` where commit messages and diff output are formatted. The bug report includes clear reproduction steps and expected/actual output comparisons, making it straightforward to verify. The issue has been present since at least Git 2.51.0 and hasn't been addressed in recent development branches.
