This is a CI infrastructure patch from Junio C Hamano, spun off from a bugfix thread about `git subtree`. The patch aims to catch contrib/ breakages earlier by adding contrib/ tests to the CI pipeline.

The context comes from a regression in Pushkar Singh's `git subtree` fix (v3) that wasn't caught before merging to 'next'. The original patch changed how `--prefix` validation worked during splits, but broke test case 17. Junio is now proposing to prevent similar oversights by making CI run contrib/ tests by default via a new TEST_CONTRIB_TOO flag.

The patch adds a top-level contrib/Makefile that delegates test targets to known testable contrib/ subdirectories (currently diff-highlight and subtree). It also modifies the main Makefile and CI script to optionally include these tests. The implementation is straightforward but Junio notes there might be cleaner ways to auto-discover testable contrib/ directories in the future.

This is a sensible preventative measure following the subtree regression, though it's a bit ironic that the patch introducing CI coverage for contrib/ comes *after* the breakage it might have caught. The change is low-risk since it only affects testing infrastructure, not production code. It will help maintain quality in the often-overlooked contrib/ area, which contains useful but less rigorously tested components like subtree.
