Git thread summary:

Bug report and analysis of `git log --graph` misplacement of graph characters when combined with `-p/--patch` and custom pretty formats lacking newlines. The issue manifests when using `--graph --pretty='format:%h' -p` (without trailing newline), causing graph connection characters (`|`, `\`, `/`) to appear incorrectly at line ends rather than starts. Pushkar Singh (Git 2.43.0) and original reporter (Git 2.51.0) confirm identical behavior across versions, establishing this as a long-standing bug in `log-tree.c`'s graph/patch output interleaving.

D. Ben Knoble identifies the root cause as the missing newline in `format:` specifier, noting two workarounds: (1) using `tformat:` instead (with minor color code behavior differences) or (2) explicitly adding `%n` to the format string (changes output formatting). Maintainer Junio C Hamano adds that `--format=<whatever>` is actually a shorthand for `--pretty=tformat:<whatever>`, providing a more convenient way to implement the first workaround. This maintainer input suggests the workarounds are considered sufficient for now, though the core bug in `log-tree.c`'s handling of newline-less formats with graph/patch combination remains unaddressed.

The thread has clear reproduction steps, technical analysis of the cause, and documented workarounds, but lacks proposals for deeper fixes to the output formatting pipeline. The discussion appears to have reached a natural conclusion with the maintainer's implicit endorsement of the workarounds as the current resolution path.
