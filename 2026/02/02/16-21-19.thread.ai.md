Git thread summary:

Bug report: `git log --graph` misplaces graph characters when combined with `-p/--patch` and custom pretty formats lacking newlines, with two independent confirmations. The issue occurs when using `--graph --pretty='format:%h' -p`, causing graph connection characters (`|`, `\`, `/`) to appear at line ends rather than starts, breaking the visual graph structure. Reproduction requires: (1) `--graph` with custom `--pretty=format:` (not `tformat:`), (2) `-p` flag, (3) format string without trailing newline (`%h` vs `%h%n`). Pushkar Singh confirms identical behavior on Git 2.43.0 (WSL/Linux), matching the original report for 2.51.0, establishing this as a long-standing bug in `log-tree.c`'s graph/patch output interleaving logic. Workarounds exist (using `tformat:` or adding `%n`) but introduce formatting quirks. The thread now has clear reproduction steps from two environments but lacks proposed fixes or deeper technical analysis of the root cause in the output formatting pipeline.
