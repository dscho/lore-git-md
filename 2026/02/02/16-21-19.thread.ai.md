Git thread summary:

Bug report and analysis of `git log --graph` misplacement of graph characters when combined with `-p/--patch` and custom pretty formats lacking newlines. The issue manifests when using `--graph --pretty='format:%h' -p` (without trailing newline), causing graph connection characters (`|`, `\`, `/`) to appear incorrectly at line ends rather than starts. Pushkar Singh (Git 2.43.0) and original reporter (Git 2.51.0) confirm identical behavior across versions, establishing this as a long-standing bug in `log-tree.c`'s graph/patch output interleaving.

D. Ben Knoble identifies the root cause as the missing newline in `format:` specifier, noting two workarounds: (1) using `tformat:` instead (with minor color code behavior differences) or (2) explicitly adding `%n` to the format string (changes output formatting). The thread now has clear reproduction steps and workarounds but lacks deeper technical analysis of the output formatting pipeline or proposed fixes to properly handle newline-less formats in the graph/patch combination case. The bug appears isolated to the interaction between three specific conditions: `--graph`, custom `--pretty=format:` (not `tformat:`), and `-p` flag with no trailing newline in format string.
