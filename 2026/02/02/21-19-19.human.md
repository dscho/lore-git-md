This is a brief follow-up in the ongoing discussion about adding a shorthand syntax for referencing a repository's primary branch. Harald Nordgren responds to D. Ben Knoble's suggestion of using `git switch -d origin` as an alternative to the proposed `@{default}` syntax.

Harald clarifies that the use case requires being on an actual branch rather than a detached HEAD state, which `git switch -d` would produce. The exchange highlights a key distinction in workflow preferences - while some developers may work comfortably in detached HEAD states, Harald indicates this isn't their normal practice.

The response reinforces the original motivation for the `@{default}` shorthand by showing that existing commands don't fully address the need to quickly reference and switch to the primary branch while maintaining normal branch-based workflow. This keeps the discussion focused on whether new syntax is justified versus adapting to existing command behavior.
