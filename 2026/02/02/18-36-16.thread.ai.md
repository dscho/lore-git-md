Git project governance and contribution guidelines as outlined by maintainer Junio C Hamano. This canonical reference describes the mailing list workflow (including anti-spam measures and archive locations), bug reporting expectations, and repository structure (primary and mirrors). The four integration branches are defined: master for production-ready code, next for testing new features, seen for experimental work that may graduate to next, and maint for stable maintenance. Version numbering uses two-dotted decimal for feature releases. Security reporting procedures are specified, along with pointers to related projects (git-gui, gitk, localization files) that have their own maintainers. The note distinguishes core Git from third-party resources like git-scm.com and Git for Windows, indicating where issues for those should be reported. This document serves as the authoritative source for understanding Git's development process and sets expectations for contributor behavior while acknowledging mailing list noise and the iterative nature of patch review. Regularly updated by the maintainer to reflect current practices.
