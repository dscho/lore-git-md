This is the fourth version of a series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories. The key addition in this version is worktree support, which was the last major technical blocker.

Karthik Nayak from GitLab has been driving this effort to enable migrations without downtime for repositories with millions of references. The series introduces a URI syntax (`<format>://<location>`) for the `extensions.refStorage` config to specify both format and location, along with a `GIT_REFERENCE_BACKEND` environment variable override. The main use case is migrating server-side repositories from files to reftable backend with minimal downtime by first building the reftable in a dry-run location before atomically swapping it in.

Version 4 specifically adds support for worktree references, storing them in `ref_dir/worktrees/wt_id` with corresponding stubs in the git directory. It also adds support for relative paths resolved relative to `GIT_DIR`. The implementation includes core refactoring with URI-aware store creation, strict `://` separator requirements, and comprehensive test coverage in t1423-ref-backend.sh.

All architectural decisions appear settled at this point, with the worktree integration being the last substantive piece that needed resolution. The series is in good standing with Junio Hamano, having been temporarily removed from 'seen' only for branch housekeeping rather than due to technical concerns. This looks ready for final review and potential merging once any remaining minor feedback is addressed.
