This is a bugfix discussion for `git log --graph` output formatting when combined with `-p/--patch` and custom pretty formats. The issue causes graph connection characters (`|`, `\`, `/`) to appear incorrectly at line ends rather than starts when using `--pretty='format:%h'` (without a trailing newline) alongside `-p`. 

D. Ben Knoble confirms the behavior and notes that using `tformat:` or explicitly adding a newline (`%n`) to the format string avoids the issue. This suggests the bug lies in how `log-tree.c` handles line buffering when interleaving graph output with patch content. The workaround is functional but may not be ideal for all use cases, as it changes the output formatting.

The thread now has clear reproduction steps and a workaround, but no proposed fix yet. This appears to be a long-standing issue affecting multiple Git versions (confirmed on both 2.43.0 and 2.51.0). The bug impacts users who combine custom graph formats with patch output, particularly those who build aliases expecting these features to work together cleanly.
