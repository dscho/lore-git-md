This is a documentation patch continuing Jean-Noël Avila's effort to standardize Git man pages using AsciiDoc synopsis-style formatting. Kristoffer Haugsbakk provides follow-up feedback on the `git-clone` documentation conversion, specifically addressing the formatting of long options.

The discussion centers on whether to use "stuck form" (`--option=<value>`) versus "unstuck form" (`--option value`) for command-line options in the documentation. Haugsbakk notes that gitcli(7) recommends the stuck form for long options, and the current documentation uses a mix of both styles. While this particular email doesn't include the actual documentation changes, it confirms there's no automated tool to enforce this style, meaning the conversion will need to be done manually.

This is part of a larger, meticulous effort to improve documentation consistency across Git's man pages. The exchange shows the careful attention to detail that characterizes this documentation standardization project, with contributors cross-referencing style guidelines and considering long-term maintainability implications. The changes are purely about presentation and don't affect command behavior.
