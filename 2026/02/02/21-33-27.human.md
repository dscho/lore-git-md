This is a discussion about the proposed `@{default}` shorthand for referencing a repository's primary branch, now in its fourth iteration. Junio Hamano responds to D. Ben Knoble's suggestion that `git switch -d origin` could serve as an alternative to the new syntax.

Junio clarifies the key distinction: while `git switch -d origin` works for detached HEAD operations, the `@{default}` shorthand is specifically designed for cases where you need to *name* the branch itself (e.g., when checking out or when two branches point to the same commit). This reinforces Harald Nordgren's earlier point about the branch-attached requirement that makes existing commands insufficient for the core use case.

The exchange shows the discussion maturing, with Junio now explicitly acknowledging the technical need that motivates new syntax rather than command alternatives. His response suggests the remote-tracking approach (resolving via origin/HEAD) may be gaining favor as the solution that best addresses both repository relevance and branch-naming requirements.
