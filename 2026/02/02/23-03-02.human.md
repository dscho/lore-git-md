This is a follow-up in the thread discussing syntax for referencing a repository's primary branch. Harald Nordgren responds to the practical challenges of determining the correct remote name, particularly in GitHub fork-and-PR workflows where the `gh` CLI tool renames `origin` to `upstream`. 

The email highlights a real-world pain point: even with the earlier consensus that `git switch -d origin` (with suppressed detached-HEAD warnings) solves the basic read-only access need, discovering which remote to use remains non-trivial. Harald shares his workaround using `git remote | rg '^(origin|upstream)$' | tail -n1` to handle GitHub's remote renaming behavior.

This reinforces that while the detached-HEAD approach addresses the core functionality, there may still be usability gaps around remote discovery that could motivate additional tooling or syntax improvements. The discussion appears to be narrowing to these practical workflow considerations rather than fundamental syntax debates.
