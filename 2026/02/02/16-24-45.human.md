This is a bugfix for `git blame`'s coloring behavior when using both `--color-lines` and `--ignore-rev` together. The patch from René Scharfe corrects an issue where consecutive lines that should be colored the same (after ignoring a specified revision) were incorrectly following pre-ignored revision history for their coloring.

The fix modifies the coloring logic in `builtin/blame.c` to properly check the previous line's commit when determining repeated-line coloring, specifically handling the `--ignore-rev` case. While Junio Hamano notes this might be addressing a specific case rather than a more general pattern in the blame machinery, he confirms the current patch is correct and thanks René for including a test case.

The change ensures consistent coloring between cases where `--ignore-rev` is and isn't used, with consecutive lines from the same commit (after ignoring) now properly colored cyan. The fix is minimal and doesn't affect other blame functionality. A new case in `t/t8012-blame-colors.sh` verifies the corrected behavior by creating a commit changing whitespace and checking the coloring with these options. The original reporter confirmed the fix works across multiple Git versions.
