Refactoring patch for reference backend compatibility. This is part of the ongoing effort to support multiple reference storage formats (files vs reftable) in Git repositories.

The patch extracts duplicate code that creates stub reference directories into a new `refs_create_refdir_stubs()` function. These stubs (HEAD and refs/ directories) are required for Git to recognize a directory as a repository, even when using alternative backends like reftable that store references differently. The change consolidates this logic from two existing locations (clone.c and reftable-backend.c) into a single reusable implementation.

The patch appears well-scoped and mechanical, with clear motivation explained in the commit message. It's part of a larger v4 series that has already addressed previous technical concerns, including worktree reference handling. The changes are straightforward - moving code rather than changing behavior - and include appropriate documentation for the new public function.
