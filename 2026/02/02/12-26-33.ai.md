This is the final patch in a 4-part series implementing reference backend selection for zero-downtime migrations between backends (files<->reftable), primarily targeting GitLab's migration needs. The series has gone through multiple rounds of review and addresses all technical blockers.

The patch adds a `GIT_REFERENCE_BACKEND` environment variable that mirrors the functionality of the `extensions.refStorage` config option introduced earlier in the series. This allows runtime override of the reference backend for individual Git commands, similar to how `GIT_OBJECT_DIRECTORY` works for object storage. The environment variable takes the same URI syntax (`backend://path`) as the config option.

Key implementation details:
- The variable is checked during repository setup in `setup.c` after config is loaded but before ref storage initialization
- It overrides any `extensions.refStorage` config setting
- Includes comprehensive test coverage in t1423-ref-backend.sh, verifying both config and environment variable paths
- Documents the new variable in git.adoc alongside other environment variables

The tests verify:
- Invalid URI formats are rejected
- Unknown backends are caught
- Both files<->reftable migrations work correctly
- Worktree integration behaves as expected
- The environment variable takes precedence over config

This completes the series' goal of providing both persistent (config) and ephemeral (environment) control over reference backend selection. With all architectural decisions settled and all feedback from previous rounds addressed, the series appears ready for final review and potential integration.
