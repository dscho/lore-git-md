Junio C Hamano proposes a CI improvement to catch contrib/ subtree test failures earlier, prompted by a regression in the `git subtree` script. This is a build system patch that would enable automated testing of contrib/ components during CI runs.

The patch adds a new `TEST_CONTRIB_TOO` flag that, when set, makes `make test` recursively run tests in contrib/ subdirectories (currently targeting diff-highlight and subtree). It modifies three files:
- Top-level Makefile to accept the flag
- ci/run-build-and-tests.sh to enable it in CI
- New contrib/Makefile to coordinate testing across contrib/ components

The motivation comes from a recently discovered regression where Pushkar Singh's `git subtree` validation changes (merged to 'next') broke test case 17 in contrib/subtree/t/t7900-subtree.sh. Josh Steadmon from Google bisected this failure, which involves prefix path validation during split operations.

This is a preventative measure - the patch doesn't fix the subtree regression itself (which will need separate attention from Pushkar Singh) but aims to catch similar issues earlier by making contrib/ testing part of the standard CI workflow. The implementation is deliberately minimal, with Junio noting there may be cleaner ways to handle future contrib/ test targets.
