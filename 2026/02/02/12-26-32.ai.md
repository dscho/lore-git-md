This is part 3 of a 4-patch series implementing reference storage backend selection for zero-downtime migrations between backends (files<->reftable) in large repositories. The series is now in its fourth iteration with all architectural decisions implemented.

The patch focuses on parsing and utilizing the reference storage payload from the `extensions.refStorage` config. Key changes include:

1. Adding support for URI-formatted payloads (`<format>://<location>`) that specify both backend format and storage location
2. Implementing `refs_compute_filesystem_location()` to handle path resolution for both main and worktree references
3. Modifying worktree reference storage to use the alternate path when specified (storing in `$ALTERNATE_REFERENCE_DIR/worktrees/<wt_id>` while maintaining stubs in the original location)
4. Updating both files and reftable backends to use the new path resolution logic
5. Adding comprehensive tests in t1423-ref-backend.sh covering URI parsing, path resolution, and worktree integration

The implementation maintains backward compatibility while enabling the primary use case of GitLab's zero-downtime migration strategy. The patch builds on previous versions' work addressing feedback from multiple reviewers (Patrick Steinhardt, Karthik Nayak, Eric Sunshine, and others) and appears technically sound with thorough test coverage.
