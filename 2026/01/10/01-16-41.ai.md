This is a refactoring patch that moves the core replay logic from `builtin/replay.c` into a new `replay.c` library file as part of the `git-history` command development. The patch is part of a larger series (v9 2/7) to enable history editing operations.

Elijah Newren provides technical review feedback on the extraction, noting several opportunities for cleanup and improvement:
1. The `oidset.h` include appears unused and could be removed
2. Questions whether `parse-options.h` belongs in the library code
3. Suggests explicitly including `strmap.h` since it's used directly
4. Points out redundancy between the `merge_conflict` field and return value in the replay API
5. Notes a stray extra line in `replay.h`

The patch itself:
- Moves 355 lines of replay logic into new `replay.c`/`replay.h` files
- Updates build system (Makefile/meson.build) to include the new files
- Leaves the command-line interface in `builtin/replay.c`
- Maintains all existing functionality while cleaning up some warnings
- Continues progress on removing `the_repository` global

Newren's feedback focuses on polishing the library interface - these are straightforward fixes that would improve the code quality before merging. The core architectural approach of extracting the replay logic appears sound and aligns with the series' goal of creating reusable components for history editing operations.
