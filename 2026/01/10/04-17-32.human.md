Bugfix and feature enhancement for shallow repository handling. This is the second patch in Samo Pogačnik's v2 series addressing shallow fetch operations, following up on the memory leak fix in patch 1/2.

The patch implements relative-depth fetching (`--deepen`) by modifying `get_shallow_commits()` to track minimum depth of existing shallow commits and introducing a new `get_shallows_depth()` function. The changes unify absolute and relative deepening logic while removing the now-unnecessary `get_reachable_list()` function. Key technical changes include:

1. Enhanced `get_shallow_commits()` now takes additional parameters for shallows tracking and relative depth calculation
2. New depth calculation logic that properly handles graft points
3. Removal of redundant code paths in upload-pack.c
4. Added test coverage in t5500-fetch-pack.sh for the deepen-beyond-merged-branch case

Junio Hamano's review note points out a minor formatting issue in the commit message where unindented example output could confuse `git am`. The patch appears technically sound, having already incorporated thorough review feedback from Patrick Steinhardt in the v1 iteration. The implementation demonstrates careful attention to edge cases and maintains backward compatibility while adding the new relative-depth functionality.
