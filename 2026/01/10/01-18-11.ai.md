This is a bugfix patch for the `git subtree` contrib script that improves its handling of rebased or cherry-picked subtree commits. The patch comes with extensive test coverage and addresses a performance issue in the split operation.

The core issue is that `git subtree split` currently fails to properly detect when subtree merge commits have been rebased or cherry-picked, which can lead to incomplete history being generated during splits. The patch adds validation logic that checks the consistency of subtree metadata trailers (`git-subtree-dir`, `git-subtree-mainline`, `git-subtree-split`) to identify rewritten commits.

Key technical changes:
- Introduces `find_other_splits()` function to efficiently detect invalid subtree commits in a single `git log` pass
- Adds caching of ignored commits to avoid repeated history traversals
- Removes the less reliable `should_ignore_subtree_split_commit()` function
- Improves performance by using `git rev-list --stdin` with pre-computed negative refs
- Adds test cases verifying correct behavior with rebased subtree commits

The patch appears well-constructed with:
- Clear commit message explaining the problem and solution
- Comprehensive test coverage including edge cases
- Performance optimizations for the split operation
- Careful handling of the metadata trailers that identify subtree operations

This fixes a real issue that could affect users who rebase their history after using subtree merges, and the performance improvements will benefit all subtree users. The changes are focused on the contrib/subtree component and shouldn't impact core Git functionality.
