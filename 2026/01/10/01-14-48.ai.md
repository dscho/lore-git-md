This is a refactoring patch from Elijah Newren providing review feedback on Patrick Steinhardt's v9 series introducing the `git-history` command. The patch in question extracts core replay logic into a standalone function as part of preparing it for library inclusion.

Elijah identifies several technical issues in the implementation:

1. Questions why both `repo` and `revs` parameters are needed when `revs->repo` could provide the repository context
2. Points out an incorrect error code mapping where merge conflicts currently return -1 but should return 1 to match existing replay behavior
3. Suggests simplifying the error handling flow by using consistent return values rather than special casing merge conflicts
4. Notes the overall approach looks reasonable aside from these specific concerns

The changes are part of a larger effort to refactor Git's replay machinery into a reusable library component while adding new history editing capabilities. This particular patch focuses on the mechanical extraction of core logic while maintaining existing behavior, with Elijah's review ensuring the changes align with Git's established patterns.
