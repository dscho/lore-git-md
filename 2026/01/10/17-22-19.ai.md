This is a performance confirmation for the `git subtree` regression fix. George Dietrich reports that Colin Stagner's patch not only corrects the commit hash output (restoring the pre-regression behavior) but also significantly improves performance compared to both the broken Git 2.52.0 version and even the working Git 2.51.1 version. The fixed version completes the subtree split operation in about 1/3 the time of the original working version (10.8s vs 33.0s) and nearly twice as fast as the broken version (10.8s vs 18.7s). This confirms that removing the problematic `should_ignore_subtree_split_commit` heuristic was the right approach, as it was both causing incorrect behavior and acting as a performance bottleneck. The test case uses a subtree split operation on a clock component in what appears to be a real-world repository.
