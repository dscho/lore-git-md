This is the second patch in Samo Pogačnik's v3 series addressing shallow repository issues, specifically focusing on fixing relative-depth fetching (`--deepen`). The patch implements correct handling of relative-depth fetches when deepening beyond merged branches, where previous versions could leave unreachable shallow commits.

The key technical changes include:
- A new `get_shallows_depth()` function that calculates minimum depths of existing shallow commits
- Removal of the redundant `get_reachable_list()` function
- Unified depth calculation logic between absolute and relative deepening
- A new test case in t5500-fetch-pack.sh that verifies correct behavior when fetching beyond merged branches
- Use of a `commit_depth` slab to track depths efficiently

The implementation now properly handles graft points and ensures all shallow commits remain reachable after relative-depth fetches. The patch has undergone multiple rounds of review from Patrick Steinhardt and Junio C Hamano, with v3 incorporating documentation formatting improvements suggested by Junio. The changes are well-contained within shallow.c and upload-pack.c, with comprehensive test coverage confirming the fixes work as intended.

This appears to be a well-justified improvement to shallow repository handling, addressing a real edge case in the fetch machinery. The patch series as a whole (including the memory leak fix in part 1) looks ready for integration after clearing both technical and documentation review hurdles.
