This is a feature patch introducing the new `git history` command, part of Patrick Steinhardt's ongoing effort to provide more flexible history editing capabilities. The patch establishes the basic command infrastructure while marking it as experimental, with placeholder documentation and minimal initial functionality.

The command is positioned as a more opinionated alternative to `git rebase` that can worktree/index operations and handle branch updates more comprehensively. The documentation outlines key differences from rebase (bare repo support, no hooks, automatic branch updates) but currently lacks complete sentences in some sections and omits listing the planned subcommands. Elijah Newren notes these documentation gaps, suggesting they be addressed when actual subcommands are added in later patches.

The implementation adds the command skeleton across all build systems (Makefile, meson) with basic argument parsing and two trivial tests verifying empty invocation and unknown argument handling. The patch follows Git's standard pattern for new commands but currently contains no substantive functionality - that comes in subsequent patches of the series.

Key technical details:
- New files: `builtin/history.c`, `Documentation/git-history.adoc`, `t/t3450-history.sh`
- Build system integration in Makefile and meson.build
- Command registered in command-list.txt as mainporcelain
- Initial test coverage for basic error cases

The patch appears mechanically sound but the documentation issues flagged by Newren will need addressing in a follow-up. This is clearly just the scaffolding for a larger feature, with the real functionality coming in later patches of the series.
