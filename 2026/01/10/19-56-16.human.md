Feature enhancement to `git status` showing both upstream and push tracking divergence, now merge-ready after extensive review.

This patch implements a long-requested feature where `git status` will show divergence information for both the upstream tracking branch and the push tracking branch when they differ. The implementation comes after 22 iterations of review, with input from Junio C Hamano, Ben Knoble, and Phillip Wood, and is now considered ready for merging.

The key change is that when a branch tracks one remote branch for pulls (upstream) but pushes to a different branch (common in feature branch workflows), `git status` will show both relationships. For example, if tracking `origin/main` but pushing to `origin/feature`, it will show divergence from `origin/main` on one line and the relationship to `origin/feature` on the next. The output format matches the existing style exactly, just adding the extra line when needed.

The implementation introduces a new `get_remote_push_branch()` helper to resolve the push tracking branch, extends `format_tracking_info()` to handle both cases, and adds comprehensive test coverage (262 new test lines) for all combinations of upstream/push relationships. The changes maintain all existing behavior including the `--no-ahead-behind` mode and advice messages.

This is a well-executed enhancement that addresses a real workflow need while carefully preserving backward compatibility. The extensive review process and test coverage give confidence in the implementation quality.
