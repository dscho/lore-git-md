This is a performance confirmation for a bugfix in the `git subtree` functionality. George Dietrich reports that Colin Stagner's patch (from the ongoing thread about squashed subtree operations) not only fixes the regression but also significantly improves performance compared to both the broken Git 2.52.0 version and the older working Git 2.51.1 version.

The timing data shows the fixed version (2.52.0.408.gecb62f5599) produces the correct commit hash (matching 2.51.1's output) while being nearly 3x faster than the working-but-slow 2.51.1 version and about 1.7x faster than the broken-but-faster 2.52.0 version. This confirms that removing the problematic heuristic in `should_ignore_subtree_split_commit()` was the right approach - it eliminates the functional regression while also making the operation more efficient. The fix appears ready for merging.
