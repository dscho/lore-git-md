Thread identity: Bugfix patch for `git subtree` contrib script addressing handling of rebased/cherry-picked subtree commits, with performance improvements for split operation.

Core problem: `git subtree split` fails to properly detect when subtree merge commits have been rebased or cherry-picked, potentially generating incomplete history. The issue stems from unreliable detection of rewritten commits via subtree metadata trailers (`git-subtree-dir`, `git-subtree-mainline`, `git-subtree-split`).

Current status: Initial patch version proposing solution with comprehensive test coverage. Not yet picked into any integration branch.

Key technical details:
- New `find_other_splits()` function performs efficient single-pass `git log` traversal to detect invalid subtree commits
- Caching mechanism for ignored commits avoids repeated history traversals
- Removal of unreliable `should_ignore_subtree_split_commit()` function
- Performance optimization via `git rev-list --stdin` with pre-computed negative refs
- Tests verify correct behavior with rebased subtree commits and edge cases
