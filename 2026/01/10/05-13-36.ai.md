This is a bugfix patch series (v3) addressing issues with shallow repository handling during fetch operations. The two-patch series has been through multiple rounds of review from Patrick Steinhardt and maintainer feedback from Junio C Hamano, with all suggestions incorporated.

The first patch fixes a memory leak in `get_shallow_commits()` by properly freeing the `object_array` stack allocation in shallow.c. This straightforward fix is validated by test coverage added in the second patch.

The second patch implements correct relative-depth fetching (`--deepen`) behavior by:
1. Adding a new `get_shallows_depth()` function to calculate proper relative depths
2. Removing the redundant `get_reachable_list()` function
3. Modifying `get_shallow_commits()` to track minimum depth of existing shallow commits
4. Adding test cases in t5500-fetch-pack.sh that demonstrate both the problem and the fix

Key technical changes include:
- New use of `commit_depth` slab for tracking depths
- Proper handling of graft points
- Unified depth calculation algorithm that works for both absolute and relative deepening
- CI validation through leak-checking tests

The commit message formatting has been polished per Junio's suggestion to properly indent commit graphs and shallow commit lists in the examples. The series appears ready for integration, having addressed both technical correctness (validated by Patrick) and documentation quality (noted by Junio). The changes are focused in shallow.c and upload-pack.c, with test coverage confirming the fixes work as intended.
