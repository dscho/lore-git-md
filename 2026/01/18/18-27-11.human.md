This is a feature patch from Derrick Stolee adding a new `--maximal` option to `git rev-list`, part of an ongoing discussion about the interface design. The option filters commit output to only show those that aren't reachable from others in the input range - essentially the "frontier" commits in the reachability order.

The patch is technically complete with implementation in revision.c/commit.c and thorough test coverage, but Johannes Sixt has raised several interface concerns in review. The documentation wording is unclear (admitting it took multiple readings to understand), the option name "maximal" may be too mathematical/obscure (suggesting alternatives like "--topmost-only"), and the placement in the man page may be incorrect. Stolee acknowledges these points and plans to address them in v2, while defending the mathematical precision of "maximal" given the commit graph's partial ordering properties.

The discussion highlights the challenge of naming and documenting specialized revision-walking features in ways that balance mathematical precision with approachability for general Git users. The patch appears well-implemented but the interface questions suggest it may need refinement before merging.
