Thread identity: Feature patch from Derrick Stolee adding `--maximal` option to `git rev-list` to filter output to commits not reachable from others in the range.

Core problem/goal: Provide a way to select minimal reference points (e.g. for bundle URIs) by showing only commits that are maximal in the reachability order. This helps identify "frontier" commits that aren't dominated by others in the input set.

Key technical details:
- New `--maximal` option for `git rev-list`
- Adds `CHILD_VISITED` flag (bit 28) to track reachability during walk
- Extends Git's object flag space usage to 29/32 bits
- Implementation in revision.c and commit.c
- Thorough test coverage including interaction with `--first-parent`

Current status: Initial version with complete implementation and tests. Interface design under discussion.

Open questions:
- Flag bit allocation concern (28/32 bits used) may need broader discussion
- Documentation clarity and placement - Johannes Sixt suggests current description is unclear and option may be misclassified among simplification options
- Option naming debate:
  * Stolee defends mathematical precision of `--maximal` from order theory
  * Johannes Sixt proposes alternatives like `--starting-point` or `--topmost-only`
- Potential applications beyond bundle URIs (e.g. reachability bitmap optimization)

Participant positions:
