Thread identity: Feature patch from Derrick Stolee adding `--maximal` option to `git rev-list` to filter output to commits not reachable from others in the range.

Core problem/goal: Provide a way to select minimal reference points (e.g. for bundle URIs) by showing only commits that are maximal in the reachability order, helping find "frontier" commits not dominated by others in the input set.

Key technical details:
- New `--maximal` option for `git rev-list` (implementation in revision.c/commit.c)
- Adds `CHILD_VISITED` flag (bit 28) to track reachability during walk
- Extends Git's object flag space usage to 29/32 bits
- Thorough test coverage including interaction with `--first-parent`
- Potential interaction with `--boundary` that may need resolution

Current status: Initial version with complete implementation and tests. Interface design under active discussion, particularly naming and documentation. Naming debate has intensified with new considerations about user expectations in `git-log` contexts.

Open questions:
