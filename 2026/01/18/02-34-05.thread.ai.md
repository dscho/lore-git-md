Thread identity: Feature patch from Derrick Stolee adding `--maximal` option to `git rev-list` to filter output to commits not reachable from others in the range.

Core problem/goal: Provide a way to select minimal reference points (e.g. for bundle URIs) by showing only commits that are maximal in the reachability order. This helps identify "frontier" commits that aren't dominated by others in the input set.

Key technical details:
- New `--maximal` option for `git rev-list`
- Adds `CHILD_VISITED` flag (bit 28) to track reachability during walk
- Extends Git's object flag space usage to 29/32 bits
- Thorough test coverage including interaction with `--first-parent`
- Implementation in revision.c and commit.c

Current status: Initial version with complete implementation and tests. Johannes Sixt has reviewed the interface design.

Open questions:
- Flag bit allocation concern (28/32 bits used) may need discussion
- Potential applications beyond bundle URIs (e.g. reachability bitmap optimization)
- Documentation clarity and placement - Johannes Sixt suggests the description is unclear and the option may be misclassified
- Option naming - Johannes proposes alternatives like `--starting-point` or `--topmost-only` instead of `--maximal`

Participant positions:
- Derrick Stolee (author) argues feature utility justifies flag bit usage
- Johannes Sixt raises interface concerns but doesn't challenge implementation:
  * Finds documentation wording unclear
  * Questions if `--maximal` is the best name
  * Suggests option may belong in different documentation section

Related work: Builds on existing revision walking infrastructure. May relate to bundle URI and reachability bitmap work. Interface questions parallel existing options like `--boundary`.
