This is a feature patch implementing configurable branch comparison in `git status`, part of Harald Nordgren's ongoing effort to improve branch tracking information. The patch introduces a new status.compareBranches` configuration that allows users to specify multiple branches (including `@{upstream}` and `@{push}`) to compare against in status output.

The implementation adds:
- A new `resolve_compare_branch()` helper for branch-to-ref resolution
- Context-aware advice messages that vary by comparison type (pull advice for upstream, push advice for push branches)
- Support for triangular workflows where upstream and push branches differ
- Extensive test coverage in t6040-tracking-info.sh for various scenarios including remapped refspecs and multiple comparisons

The configuration accepts space-separated branch specs with special handling for `@{upstream}` and `@{push}`. When unset, it defaults to `@{upstream}` behavior for backward compatibility. The patch builds on previous work that showed divergence from both upstream and push tracking branches, now implementing Junio Hamano's proposed configuration framework.

Key technical details:
- Uses `repo_config_get_string()` for configuration parsing
- Maintains separate flags for different advice types (pull/push/divergence)
- Handles quick mode (`AHEAD_BEHIND_QUICK`) consistently across comparisons
- Preserves existing behavior when configuration is not set

The patch appears structurally complete with thorough test coverage, though the thread summary notes an outstanding memory leak that remains to be addressed. This represents a significant step toward flexible branch comparison in status output while maintaining backward compatibility.
