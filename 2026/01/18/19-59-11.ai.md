This is a feature patch series implementing Junio Hamano's proposed `status.compareBranches` configuration for customizable branch comparison in `git status` output. The v26 iteration from Harald Nordgren builds on the previously merged push-tracking functionality, now allowing users to specify multiple branches (including `@{upstream}` and `@{push}`) for comparison.

The key changes in this version:
- Introduces a new `status.compareBranches` config accepting space-separated branch specifications
- Maintains backward compatibility by defaulting to `@{upstream}` behavior when unset
- Context-aware advice messages (pull/push/divergence) based on comparison type
- Handles triangular workflows where upstream and push branches differ
- Includes extensive test coverage for various configurations and edge cases

Technical implementation details:
- New `resolve_compare_branch()` helper resolves branch names to full refs
- Refactors `format_branch_comparison()` to handle multiple comparisons
- Adds configuration parsing via `repo_config_get_string()`
- Tests cover remapped refspecs, multiple comparisons, and various push.default settings

The patch appears well-structured with thorough test coverage. The implementation follows Junio's suggested extensible design, though the memory leak noted in previous iterations remains unresolved. This represents a significant enhancement to `git status`'s tracking information display, particularly for complex workflows with multiple remotes or divergent push targets.
