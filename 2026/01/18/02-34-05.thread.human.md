Derrick Stolee has proposed adding a `--maximal` option to `git rev-list` that would output only commits not reachable from others in the specified range - essentially the "frontier" commits in the reachability order. This could be useful for bundle URIs and other reachability optimizations. The implementation introduces a new `CHILD_VISITED` flag (using bit 28 of Git's object flags) and includes thorough test coverage.

Johannes Sixt has reviewed the patch, raising several interface concerns while not objecting to the implementation itself. He finds the documentation wording unclear and questions whether "maximal" is the most intuitive name, suggesting alternatives like `--starting-point` or `--topmost-only`. Stolee defends the mathematical precision of "maximal" from order theory but remains open to better naming suggestions. Johannes also notes the option is currently documented among simplification options when it really controls output selection.

The discussion continues on these interface questions, particularly around naming and documentation placement, while the technical implementation appears sound. The flag bit usage (now 29/32 bits used) may warrant broader discussion given the limited remaining flag space.
