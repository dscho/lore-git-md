Derrick Stolee has proposed adding a `--maximal` option to `git rev-list` that would filter output to show only commits that aren't reachable from others in the specified range - essentially identifying "frontier" commits that could be useful for operations like bundle URIs. The initial implementation is complete with thorough test coverage, including how it interacts with `--first-parent`, and introduces a new `CHILD_VISITED` flag in Git's object flag space.

Johannes Sixt has raised the first substantive review feedback, focusing on the user-facing aspects rather than the implementation. He finds the documentation wording unclear in describing what constitutes a "maximal" commit, and questions whether the option name itself (`--maximal`) is too generic, suggesting alternatives like `--starting-point` or `--topmost-only`. Johannes also notes the option might be misclassified in the documentation since it affects output selection rather than simplification behavior. While he doesn't challenge the technical approach or flag bit usage, his review indicates the interface needs refinement to clearly communicate the feature's purpose to users.

The discussion is still in its early stages, with the core technical approach appearing sound but the naming and documentation needing work. Derrick will likely respond to these points about how best to describe and name this specialized filtering capability.
