This thread discusses Derrick Stolee's proposal to add a `--maximal` option to `git rev-list` that would filter output to show only commits not reachable from others in the input range - essentially identifying the "frontier" commits in a commit graph. The initial implementation is technically sound, with thorough test coverage and a new CHILD_VISITED flag (bit 28) to track reachability during walks.

The main discussion has centered on interface design rather than implementation. Johannes Sixt has raised concerns that the mathematically precise term "--maximal" may be too abstract for typical Git users, suggesting more intuitive alternatives like "--starting-point", "--topmost-only", or "--range-head-only". In the latest email, he adds "--only-maximal" and "--hide-reachable" to the list of possibilities, noting Git's general preference for descriptive over mathematical terminology. He also identified a potential interaction issue with the existing `--boundary` option that may need resolution.

Stolee has defended the current name's mathematical accuracy from order theory while remaining open to better alternatives. The discussion remains productive, with Johannes providing constructive naming suggestions without challenging the feature's underlying utility. Other open questions include documentation placement and whether the flag bit allocation (now using 28 of 32 available bits) warrants broader discussion. The feature's primary use case is for bundle URIs, but participants have noted potential applications in reachability bitmap optimizations as well.
