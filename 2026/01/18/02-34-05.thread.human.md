Derrick Stolee's patch series adding a `--maximal-only` option to `git rev-list` has reached consensus in its second iteration. The feature identifies "frontier" commits - those not reachable from others in a given range, which will help optimize bundle URI selection and bitmap generation. After discussion, the option was renamed from `--maximal` to `--maximal-only` based on Johannes Sixt's feedback, and the implementation now includes thorough documentation of its incompatibility with `--boundary`.

Junio Hamano provided key conceptual clarification, helping distinguish this feature from the similar-sounding `git merge-base --independent`. While both find maximal elements, `--maximal-only` operates on the union of commit ranges (selecting commits not reachable from others in contrast to `--independent` which works on the intersection. The patch includes comprehensive tests covering various graph topologies and edge cases, and uses bit 28 in Git's limited flag space.

All open questions from the first version have been addressed, though future optimizations for the bundle URI use case may follow. With the technical explanation finalized and all feedback incorporated, the patch appears ready for merging.
