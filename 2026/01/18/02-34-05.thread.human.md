Derrick Stolee's patch series adding a `--maximal-only` option to `git rev-list` has reached a clear resolution after thorough discussion. The feature enables selecting "frontier" commits (those not reachable from others in the input range) for use with bundle URIs and bitmap optimizations. 

The thread saw active participation from key contributors, with Johannes Sixt providing important behavioral clarification and Junio C Hamano guiding the conceptual framing. The final version (v2) settled on the `--maximal-only` name after debate, documented its incompatibility with `--boundary`, and included comprehensive tests. A key insight emerged that the difference from `git merge-base --independent` lies not in set operations (both filter an input set) but in `--maximal-only`'s support for negative revisions.

With all feedback addressed and Junio's confirmation of the underlying behavior, this feature appears ready for merging. The discussion also surfaced opportunities for future work, including potential documentation updates to `--independent` and optimizations for the bundle URI use case. The thread demonstrates Git's careful approach to adding new revision-walking primitives, ensuring clear conceptual models before introducing new functionality.
