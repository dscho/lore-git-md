Derrick Stolee has proposed adding a new filtering option to `git rev-list` that would select "frontier" commits - those not reachable from others in the input range, which is useful for operations like bundle URIs. After initial discussion about naming the option `--maximal` (mathematically precise but potentially confusing), the thread has now reached consensus on renaming it to `--maximal-only` to better reflect its behavior. 

The implementation is technically complete, using bit 28 in revision.c's flag space, with thorough test coverage. Junio C Hamano confirmed the option must be incompatible with `--boundary` since their semantics conflict (boundary shows parents of minimal commits while maximal-only shows commits not reachable from others). While the mathematical concept was initially central to the naming discussion, the resolution favors clarity for Git users over strict precision.

This feature provides an important primitive for operations needing to identify reference points in commit graphs, with applications in bundle URIs and reachability optimizations. With the naming debate now settled on `--maximal-only` and the boundary incompatibility acknowledged, the patch appears ready for final review and potential merging.
