Derrick Stolee's proposed `--maximal` option for `git rev-list` continues to generate discussion about naming and interface design. The feature would filter commits to show only those not reachable from others in the input set - useful for identifying "frontier" commits in bundle URIs and similar cases. The technical implementation (using bit 28 for a new `CHILD_VISITED` flag) appears solid with thorough test coverage.

The debate has intensified around naming, with Stolee defending the mathematically precise `--maximal` term while Johannes Sixt proposes more intuitive alternatives like `--topmost-only` or `--hide-reachable`. Sixt has raised concerns about potential confusion with the existing `--boundary` option and whether they should be mutually exclusive. Documentation clarity also remains an open question.

While the implementation quality isn't in dispute, the discussion suggests the patch may need another revision to settle on naming and interface details that align with Git's tradition of favoring intuitive terminology over mathematical precision. The flag bit usage (now at 28 of 32 bits) may also prompt broader discussion about Git's long-term object flag space management.
