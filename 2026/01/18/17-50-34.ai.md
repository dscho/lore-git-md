This is a maintainer comment in the ongoing `git-history` command discussion, specifically about the `reword` subcommand's default behavior for branch updates.

Junio Hamano (the Git maintainer) is responding to Elijah Newren's defense of the current design where `git history reword` by default updates all local branches that contain the rewritten commit. The key point is about recovery scenarios - if the command only updated some branches by default, users might have no way to recover the state of other branches that were left pointing to now-orphaned commits. Updating all branches makes recovery via reflog straightforward.

The exchange shows Junio coming around to Elijah's position after initially being concerned about the all-branches default. This suggests the maintainer is now satisfied with the safety characteristics of the design, which is significant given earlier concerns raised by SZEDER Gábor about this being unconventional behavior for Git porcelain.

The discussion remains focused on the philosophical question of whether Git's traditional single-branch focus should yield to multi-branch awareness in new commands, with the maintainer now appearing to accept that the reflog-based recovery story justifies the more expansive default behavior. This moves the thread closer to resolution, though documentation about these tradeoffs may still need attention.
