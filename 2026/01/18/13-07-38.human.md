This is a performance optimization patch for the sparse-checkout subsystem, now in its final review stages. Amisha Chhajed has addressed all feedback on her patch that converts the sparse-checkout pattern sorting from O(n^2) to O(n log n) by using string_list_append() followed by sorting rather than the original string_list_insert() approach.

The patch is now merge-ready with Junio C Hamano's approval, though Derrick Stolee has suggested follow-up test improvements to better demonstrate the optimization's impact. These would involve adding duplicate pattern handling verification to the test suite and creating a performance benchmark with 1000 identical directory patterns to show the transition from quadratic to linearithmic growth.

Amisha confirms through testing that the performance improvement is most visible when handling many patterns, though existing tests don't stress this case enough to show dramatic differences. She also notes the common occurrence of the string_list_sort() + string_list_remove_duplicates() pattern throughout the codebase, responding to Junio's observation about potentially combining these operations.

The patch represents a clean conclusion to this optimization effort, with clear next steps identified for test coverage improvements. It fits into the broader sparse-checkout/sparse-index optimization work while maintaining compatibility with existing behavior.
