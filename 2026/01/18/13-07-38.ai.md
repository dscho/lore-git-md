Performance optimization for sparse-checkout pattern handling, completing the O(n^2) to O(n log n) transition with duplicate removal.

Amisha Chhajed follows up on the now-approved sparse-checkout optimization patch, addressing Junio C Hamano's questions about performance impact and test coverage. The core optimization (switching from insertion-sort to append-then-sort) is already complete in v4, but this email provides additional context about its validation.

Key points:
- Performance testing confirms the theoretical improvement, but only becomes visible with many duplicate patterns - Derrick Stolee suggested a specific test case with 1000 identical directory patterns to demonstrate the transition from quadratic to linearithmic growth.
- The existing test suite didn't catch duplicate-handling issues because it lacked explicit duplicate pattern tests. Amisha has locally developed a test that would fail if duplicates remain, similar to Jeff King's earlier reproduction case.
- A grep across builtins shows the string_list_sort() + string_list_remove_duplicates() pattern appears frequently (clone.c, fast-export.c, fetch.c, etc.), supporting Junio's observation that a combined string_list_sort_u() helper might be worthwhile future work.

The patch itself is merge-ready, with these being follow-up considerations:
1. Adding duplicate-handling verification to t1091-sparse-checkout-builtin.sh
2. Creating a performance benchmark in t/perf/p2000-sparse-operations.sh
3. Potential future API improvement with string_list_sort_u()

The changes specifically affect pattern collection in sparse_checkout_list() and write_cone_to_file() in builtin/sparse-checkout.c, maintaining correctness while improving performance. This work fits into the broader sparse-checkout optimization efforts led by Derrick Stolee and Elijah Newren.
