This is a feature patch adding a new `--maximal` option to `git rev-list`. The option filters the output to only show commits that are not reachable from any other commit in the specified range, which could be useful for selecting a minimal set of reference points (like when creating bundles).

Derrick Stolee proposes this as a more efficient alternative to manually filtering commit lists to find "maximal" commits (those with no descendants in the range). The implementation adds a new `CHILD_VISITED` flag bit to track reachability during the walk, though this does consume one of Git's limited object flag bits (now using 28 of 32 available).

The patch includes thorough tests demonstrating the behavior with various commit range scenarios, including positive refs, negative refs, and combinations with other walk-modifying flags like `--first-parent`. The commit message thoughtfully discusses the tradeoff of using another flag bit and potential alternative applications like reachability bitmap selection.

This appears to be a clean, well-motivated addition that could simplify certain repository analysis tasks. The implementation is straightforward and the tests provide good coverage of edge cases. The flag bit usage is the only notable concern, but seems justified given the functionality.
