This is a discussion about the default behavior of the new `git history reword` subcommand, specifically whether it should rewrite all local branches by default or just the current branch. The exchange comes after Junio Hamano had already approved the patch series but now engages with Elijah Newren's defense of the all-branches default.

Elijah argues that rewriting all branches by default is the safer choice because users can easily recover via reflog if they didn't want other branches changed. Junio acknowledges this point, noting that the reverse scenario (where branches are left behind during a rewrite) could leave users with no easy way to recover the original state. This discussion reveals a philosophical tension between Git's traditional single-branch focus and newer tools' multi-branch awareness.

The thread shows that while the technical implementation has been thoroughly vetted across 11 iterations, there remains debate about porcelain conventions versus modern workflow needs. The series remains approved but this exchange suggests the default behavior may need follow-up documentation or configuration options (like the proposed `history.scope` setting) to address concerns about safety and user expectations.
