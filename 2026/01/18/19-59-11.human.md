This is a feature patch series implementing configurable branch comparisons in `git status`, building on Harald Nordgren's previous work to show both upstream and push tracking branch status.

The v26 series introduces a new `status.compareBranches` configuration that lets users specify multiple branches to compare against in `git status` output. Each entry can be a remote-tracking branch name, `@{upstream}`, or `@{push}`. The implementation handles triangular workflows where upstream and push branches differ, showing appropriate advice messages for each comparison (e.g. "git pull" for upstream, "git push" for push branches).

The patch:
1. Refactors `format_branch_comparison()` to prepare for multiple comparisons
2. Adds the new config option with comprehensive test coverage of various workflow scenarios

Key improvements in v26:
- Resolves the memory leak from previous versions
- Adds support for arbitrary branch names alongside `@{upstream}`/`@{push}`
- Includes extensive test cases for remapped refspecs and multiple comparisons
- Preserves backward compatibility by defaulting to `@{upstream}` behavior

The implementation looks solid with thorough test coverage. This addresses a real workflow need (particularly for triangular workflows) while maintaining flexibility for future extension. The series appears ready for merging once any final review feedback is addressed.
