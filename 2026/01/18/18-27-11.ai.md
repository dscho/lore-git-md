Feature patch from Derrick Stolee adding a `--maximal` option to `git rev-list`, with ongoing discussion about interface design.

This patch introduces a new `--maximal` flag to `git rev-list` that filters the output to only commits that are not reachable from any other commits in the specified range - essentially the "frontier" commits in the reachability order. The implementation adds a new `CHILD_VISITED` flag (bit 28) to track reachability during the walk, bringing Git's object flag space usage to 29 out of 32 bits.

The thread shows Johannes Sixt raising several interface concerns while not challenging the implementation itself. He finds the documentation wording unclear and suggests alternatives like `--starting-point` or `--topmost-only` instead of `--maximal`. Stolee defends the mathematical precision of "maximal" from order theory but remains open to better names. Johannes also notes the option is currently misplaced in the documentation among simplification options when it really controls output selection.

Key technical points for future reference: the flag uses bit 28 (leaving only 3 unused bits remaining), the implementation is in revision.c and commit.c, and tests cover interactions with `--first-parent`. The discussion touches on parallels with `--boundary` but notes this is more about restricting output than adding boundary commits. The feature appears motivated by bundle URI use cases but could have broader applications in reachability optimizations.
