Refactoring of branch comparison display logic in preparation for push tracking support. This is part of Harald Nordgren's ongoing effort to make `git status` branch comparisons configurable via the new `status.compareBranches` setting.

The patch extracts the core comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` helper function. This prepares for upcoming changes that will allow showing both upstream and push tracking branch status. The refactoring:

1. Separates the "upstream gone" case from the main comparison logic
2. Makes the comparison output generation reusable by taking explicit parameters
3. Preserves all existing behavior including:
   - Quick mode (`AHEAD_BEHIND_QUICK`)
   - Up-to-date messages
   - Ahead/behind counts
   - Divergence advice
4. Maintains identical output strings and advice hints

The changes are purely structural - no user-visible behavior is modified yet. This follows the incremental approach seen in previous iterations of the series, where foundational refactoring precedes new functionality. The patch includes thorough test coverage in t6040-tracking-info.sh (not shown in the diff).

This appears to be a well-scoped preparatory change that cleanly separates concerns while maintaining all existing functionality. The extracted function will be reused in the next patch to handle multiple comparison types.
