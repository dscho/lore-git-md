RFC proposal for enhancing `git add -p` interactive workflow, allowing users to revisit and modify hunk decisions after completing a file. Originated from Junio C Hamano's prior UI improvement suggestions.

Core changes:
- Implements "what_now" prompt after all file hunks are decided
- Adds navigation controls (J/K to move between hunks, 'q' to quit, '>' to advance)
- Maintains decided-file state while allowing hunk rework
- Modifies `add-patch.c` (65+/-6 lines) with focused changes
- Introduces `skip_what_now` flag for prompt state management
- Preserves color/interactive display state during navigation

Current status:
- Addresses 2 of 3 suggested enhancements from Junio
- Does not yet implement file-switching between decided files
- Builds on author's prior work showing previous hunk decisions
- Maintains backward compatibility with existing workflows
