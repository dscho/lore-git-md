This is part 6 of a 12-patch series refactoring Git's hook subsystem to support parallel execution and standardized hook handling. The series as a whole converts all core hook types to use the new `hook.h` API while maintaining backward compatibility.

This particular patch makes the hook API's stdout/stderr handling configurable rather than always merging stdout to stderr. It introduces a `stdout_to_stderr` flag in `struct run_hooks_opt` (defaulting to 1 for backward compatibility) and updates the hook execution logic to respect this setting. The change is straightforward - just plumbing the option through from the hook callback to the child process configuration.

Reviewer Patrick Steinhardt noted two minor documentation nits: the commit message should use present tense ("assumes" rather than "assumed") and the header file should explicitly document that stdout-to-stderr merging is the default behavior. The author confirms these will be addressed in a planned v8 reroll that will incorporate all accumulated feedback. The patch has otherwise received positive review and is considered technically sound.

This is one of the final patches in a series that has already resolved all major technical concerns and achieved maintainer approval, with only minor documentation polish remaining before merging. The series represents a multi-year effort to modernize Git's hook subsystem with contributions from several key developers including Jeff King, Junio Hamano, and brian m. carlson.
