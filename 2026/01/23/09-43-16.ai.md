This is a technical discussion about mtime handling in Patrick Steinhardt's ODB abstraction series (v3 12/14), part of the larger effort to make Git's object storage layer support pluggable backends. The exchange focuses on how to best expose object modification times (mtime) through the new object database API, particularly for garbage collection purposes.

Taylor Blau questions whether exposing mtime at the ODB layer is the right abstraction, suggesting it might conflate general object mtime needs with GC-specific semantics. He proposes an alternative approach using a generic `statp` field in `struct object_info` with GC-specific logic moved to a helper function (`object_info_gc_mtime()`). Patrick counters that this would break pluggability by putting backend-specific logic outside the backends, and that his approach keeps the logic fully contained within each backend implementation.

The discussion reveals two key technical points: (1) Patrick's current implementation handles cruft pack mtimes internally within the packfile store backend, while (2) Taylor's proposal would move this logic to a higher level while providing more general stat structure. Patrick acknowledges the feedback but maintains his design better serves the pluggable backend goal, though he agrees to keep passing the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag for safety.

This exchange represents one of the last open design questions in the otherwise largely settled ODB abstraction series. The mtime abstraction discussion touches on core architectural concerns about where GC-specific logic should live and how to balance generality with pluggability in the new API. While technical review has converged on most other aspects of the series, this particular design point remains pending further discussion before the series can be merged.
