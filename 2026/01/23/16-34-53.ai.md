This is a documentation and code refactoring patch that's part of the `git repo info --keys` feature series. The patch renames the output format "keyvalue" to "lines" across the codebase for better clarity and consistency.

The change affects both the man pages and implementation code, updating:
1. Command documentation in `Documentation/git-repo.adoc` to use "lines" instead of "keyvalue"
2. The enum value `FORMAT_KEYVALUE` to `FORMAT_LINES` in `builtin/repo.c`
3. Test descriptions and invocations in `t/t1900-repo.sh` and `t/t1901-repo-structure.sh`

The rationale is that "lines" better describes the actual output format (one key-value pair per line) without implying a specific key-value relationship. This naming was suggested during review and helps unify terminology across related commands. The patch maintains all existing functionality while making the code and documentation more intuitive.

This is the first of two patches in the final version of the series, which has already received thorough review from Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila. The changes are mechanical but important for long-term maintainability and user experience.
