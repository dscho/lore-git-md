This is a technical clarification in the ongoing discussion about the `--maximal-only` feature for `git rev-list`. Junio C Hamano responds to Johannes Sixt's question about the relationship between `--maximal-only` and `git merge-base --independent`, correcting a potential misunderstanding about how union/intersection semantics apply.

Junio explains that `git merge-base --independent` does not actually compute merge bases between the input commits (which would involve intersections of histories) - it simply filters the input set to find commits not reachable from others in that set. This means the earlier discussion about union vs intersection behavior was somewhat misplaced, as both commands fundamentally operate on reachability within the input set.

The key distinction Junio confirms is that `--maximal-only` differs from `--independent` primarily by supporting negative revisions, not by any fundamental difference in set operations. When given only positive revisions, both commands should produce identical results. This clarification helps solidify the conceptual model for how these related but distinct features interact with Git's revision walking machinery.
