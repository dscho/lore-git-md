This is the final patch (6/6) in a bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses on the fetch subsystem, completing the restoration of detailed error messages that were lost when batched updates were introduced.

The core change introduces a new `ref_update_display_info` structure to collate update outcomes, delaying their display until after the transaction commits. This maintains deterministic output order while restoring detailed error context. The structure owns its string fields (summary, details, ref names) and properly cleans them up, as confirmed by Junio Hamano's review. The implementation shows minimal overhead (1% for 1000 refs) while fixing the regression.

Key technical points include the `ref_update_display_info_array` for collecting updates, modified display logic in `do_fetch()`, and integration with the existing rejection handling via `strmap`. The patch builds on earlier work in the series that prepared the callback infrastructure for detailed reporting. Test coverage was expanded in previous patches, and CI confirms no memory leaks.

This completes the technical solution, with Junio having already accepted the series in v3 form. The v4 iteration incorporates Phillip Wood's optimization suggestions and addresses all outstanding review feedback. The only remaining loose end is header cleanup in `refs.c`, which depends on resolution of the unrelated 'ar/run-command-hook' series.
