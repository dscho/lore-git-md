This is a bugfix series for the `git last-modified` command, addressing issues when non-commit revisions (like tree OIDs) are passed as input. The series has gone through several iterations (now at v4) with feedback incorporated at each stage.

The core issue is that passing a tree OID would trigger a BUG() rather than producing a sensible error message. The series fixes this by:
1. Validating input revisions are commit-ish using `repo_peel_to_type()`
2. Improving error messages to clearly indicate when non-commit inputs are provided
3. Fixing memory leaks in error paths
4. Cleaning up duplicate error messages

Key technical changes include:
- New commit object validation in `builtin/last-modified.c` with precise error reporting
- Expanded test coverage including annotated tags and tree OID cases
- Error message refinements per maintainer feedback (e.g. "revision argument 'HEAD^{tree}' is a tree, not a commit-ish")

The series demonstrates a complete lifecycle from initial bug report through multiple rounds of review and refinement, culminating in robust input validation and clear user feedback. It's now in good shape with comprehensive test coverage and maintainer error handling.
