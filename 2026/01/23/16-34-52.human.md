This is a feature patch series that finalizes the `git repo info --keys` implementation and unifies format naming across related commands. The series comes from Lucas Seiki Oshiro and has been through several review iterations with input from Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila.

The main changes in this version are the renaming of the "keyvalue" output format to "lines" (for consistency across commands) and the removal of the redundant "default" format. The `--keys` flag now supports two formats: "lines" (one key per line) and "nul" (NUL-terminated output). The implementation includes thorough tests and documentation updates.

The series is now considered complete with all review feedback addressed, and it's ready to be integrated into the `next` branch. The changes touch `builtin/repo.c`, test files, and documentation, with careful attention to maintaining consistent behavior between the `repo info` and `repo structure` subcommands.

This represents the culmination of a well-reviewed effort to add machine-readable repository metadata access while keeping the interface clean and predictable. The final naming choices ("lines" instead of "keyvalue") reflect consensus from multiple contributors and maintainers.
