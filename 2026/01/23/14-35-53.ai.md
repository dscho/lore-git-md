Bugfix for `git subtree split --prefix` validation in the contrib/subtree command. This is the fourth iteration of a patch that fixes incorrect path validation when splitting older commits.

The patch corrects a subtle but important issue where `git subtree split --prefix` was validating the given path against the current working tree rather than the target commit being split. This could cause the command to fail unnecessarily when the working tree state differed from the commit being split - for example, if the subtree had been removed in later commits but still existed in the commit being split.

The fix modifies the shell script implementation in contrib/subtree/git-subtree.sh to use `git ls-tree` to validate paths against the correct commit. The patch also adds 22 lines of test coverage in t/t7900-subtree.sh that specifically verifies the command works correctly when the prefix exists in the commit but not in the working tree.
