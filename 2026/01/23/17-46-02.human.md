This is a discussion about CI optimization and test scope in the context of memory leak detection. Junio C Hamano responds to Phillip Wood's earlier point about test exclusions, clarifying the project's stance on leak checking for foreign dependencies.

Junio argues that regardless of implementation language (Perl or C), Git should not take responsibility for detecting leaks in external dependencies like Perl interpreters or libsvn. The rationale is that Git neither ships these components nor controls their versions on users' systems, making leak detection in them an impractical use of CI resources. This extends the earlier discussion about skipping git-svn tests to a broader principle about test scope.

The exchange shows careful consideration of what constitutes Git's testing responsibility versus system-level concerns. Junio's position suggests the project will maintain its current approach of focusing leak detection on Git's own C code, even if that means excluding some tests that interface with foreign code. The thread remains open-ended about how to best name and structure these exclusions, but the core principle about test scope appears settled.
