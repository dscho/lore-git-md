This is a feature patch series that finalizes the `git repo info --keys` implementation and unifies format naming across related commands. The series from Lucas Seiki Oshiro represents the culmination of several iterations (v1-v4) that have been reviewed by Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila.

The key changes in v5 are:
1. Renaming the "keyvalue" output format to "lines" for consistency between `git repo info` and `git repo structure` commands
2. Removing the redundant "default" format in favor of making "lines" the implicit default
3. Adding comprehensive tests for the new `--keys` flag and its format options

The implementation now provides:
- `git repo info --keys` to list available metadata keys in either newline-separated or NUL-terminated format
- Consistent format naming ("lines" and "nul") across all `git repo` subcommands
- Strict validation to prevent invalid format combinations
- Updated documentation following the project's `_NUL_` convention

The series is now ready for integration into `next`, replacing the previously queued `lo/repo-info-keys` implementation. All review feedback has been addressed, including Junio's confirmation of the naming choices and Patrick's verification of the test coverage. The changes touch `builtin/repo.c`, documentation, and test scripts, with careful attention to maintaining backward compatibility while improving consistency.
