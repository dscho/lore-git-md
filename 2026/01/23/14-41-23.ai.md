This is the final patch (6/6) in a bugfix series addressing a regression in error message reporting for batched reference updates. The patch completes the solution by introducing a `ref_update_display_info` structure to collate update outcomes and delay their display until after the transaction commits.

The core change restores detailed error messages that were lost when reference updates were batched, while maintaining backward compatibility. The implementation uses a dynamic array to track each update's status and details, then displays them in order after the transaction completes. Benchmarking shows only a 1% overhead for repositories with 1000 refs.

Key technical elements include:
- New `struct ref_update_display_info` to hold per-update metadata
- `ref_update_display_info_append()` helper for building the display list
- Modified `update_local_ref()` to append to display list rather than print immediately
- Transaction commit handler marks failed updates via `strmap`
- Final output phase shows all updates with status in deterministic order
- Expanded test coverage in t5516 to verify error message restoration

Phillip Wood reviewed the array handling and confirmed it looks good, marking the final technical approval for this series. The patch builds on earlier work in the series that prepared the callback infrastructure for detailed error reporting while maintaining backward compatibility.

This completes the restoration of pre-batched-update error reporting functionality across `git fetch`, `git update-ref --batch-updates`, and `git receive-pack`, fixing a regression first reported by Jeff King. The solution maintains the performance benefits of batched updates while bringing back the detailed error messages that were lost.
