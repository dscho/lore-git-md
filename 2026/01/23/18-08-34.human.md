This is a follow-up discussion on the `--maximal-only` feature for `git rev-list`, which is now ready for merging after reaching consensus on its behavior and relationship to the existing `--independent` option. The patch from Derrick Stolee adds a way to select "frontier" commits (maximal in reachability order) for use with bundle URIs and bitmap optimization.

Junio C Hamano confirms that both `--maximal-only` and `--independent` fundamentally filter input sets for commits not reachable from others, with the key difference being `--maximal-only`'s support for negative revisions. He suggests the possibility of eventually deprecating `merge-base --independent` in favor of this more flexible approach, though this isn't part of the current patch.

The discussion has clarified that `show-branch` and `merge-base` weren't ideal homes for this functionality, and that `rev-list` provides better flexibility with its output options. The implementation is complete with comprehensive test coverage and documentation, having incorporated feedback from Johannes Sixt and final conceptual alignment from Junio. No technical questions remain open, making this feature ready for integration.
