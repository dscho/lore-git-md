This is a follow-up bugfix in the `git last-modified` series, addressing a minor UX issue with error messaging. The patch removes a redundant and uninformative error message that appeared when users provided multiple revisions to the command. 

The command already outputs a clear error ("last-modified can only operate on one revision at a time") when given multiple revisions, but was following it with a generic "unable to setup last-modified" message. This second message added no useful information and could confuse users, so Toon Claes removes it by changing the error return to a simple `-1` rather than calling `error()`. 

This is a straightforward cleanup that follows through on the series' goal of refining the command's error handling and user feedback. The change is minimal (just one line modified) and well-justified in the commit message. Since this is part of an already-merged series, it represents final polish rather than introducing new functionality.
