This is an RFC patch proposing an enhancement to `git add -p`'s interactive interface, allowing users to revisit and modify hunk decisions after completing a file. The patch builds on prior suggestions from Junio C Hamano for improving the interactive add workflow.

The key change introduces a "what_now" prompt that appears after all hunks in a file have been decided, offering navigation controls (J/K for moving between hunks, 'q' to quit, '>' to advance to next file). The implementation modifies `add-patch.c` with 65 lines added and 6 removed, focused on preserving decided-file state while enabling hunk rework.

The patch addresses two of three enhancements Junio previously suggested, leaving file-switching between decided files for future work. It builds on the author's prior work showing previous hunk decisions. The changes are contained to the necessary parts of `add-patch.c`, introducing a new interaction mode that returns to the "what_now" prompt after hunk modifications.

Technical details include handling of the new prompt state via a `skip_what_now` flag, careful management of hunk navigation, and after the prompt, and preservation of color/interactive display state. The implementation maintains backward compatibility while adding the new navigation capabilities.

The RFC specifically requests feedback on the interaction design and implementation approach, particularly regarding the remaining unimplemented enhancement (file switching) and the general usability of the proposed workflow. This appears to be a focused, incremental improvement to the interactive add interface that follows Junio's prior suggestions while leaving room for further refinement based on list feedback.
