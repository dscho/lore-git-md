This is a CI optimization discussion about test exclusions in leak-checking jobs. Phillip Wood is responding to Junio C Hamano's suggestion about generalizing the mechanism for skipping certain tests.

The thread has already agreed to skip git-svn, CVS and Perforce tests in leak-checking jobs since they exercise minimal Git code while adding significant runtime. Now the discussion is considering two extensions: (1) applying the same exclusions to ASan (AddressSanitizer) jobs, and (2) potentially replacing the individual SCM-specific skip flags (NO_SVN_TESTS etc.) with a more general variable like NO_FOREIGN_CODE_TESTS.

Phillip agrees with both ideas in principle but notes the naming challenge - the tests are being skipped because they're scripted tests that duplicate coverage, not because they interact with foreign SCMs. He points out that if git-svn were a C implementation, they'd want to check it for leaks regardless of its foreign SCM integration.

The exchange shows the project thoughtfully considering both immediate CI improvements and maintainable long-term solutions. Phillip's technical perspective helps clarify that the optimization is about test implementation (scripted vs. core Git code) rather than the tests' subject matter.
