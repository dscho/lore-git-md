This is a bugfix patch for the `git last-modified` command, part of a completed and merged series that hardened the command's input validation and error handling. The patch specifically addresses a case where passing a tree OID (like `HEAD^{tree}`) would trigger a BUG() assertion rather than providing a helpful error message.

The fix adds validation using `repo_peel_to_type()` to ensure the input is a commit-ish (something that can be resolved to a commit), and provides a clear error message when it isn't. The patch also includes test coverage for both the positive case (handling annotated tags correctly) and the negative case (rejecting tree OIDs with an appropriate error).

This represents the final polish on a series that went through multiple iterations to get the error messages, terminology, and resource management right. The implementation is clean and well-tested, with clear commit messages explaining each change. The patch follows the project's standards for error reporting and test coverage.
