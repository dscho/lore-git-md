This is an RFC (Request for Comments) proposing UI improvements to Git's interactive add mode (`git add -p`), specifically focusing on allowing users to revisit and modify hunk decisions after completing a file. The patch is part of an ongoing discussion about enhancing the interactive add workflow.

The proposal addresses two of three UI enhancements suggested by Junio C Hamano in a previous thread:
1. Allowing rework of a file's hunks after all decisions are made (without auto-advancing)
2. Potentially adding file-switching between already-decided files (though this isn't implemented yet)

The current implementation introduces a "what_now" prompt that appears after all hunks in a file are decided, offering navigation options (J/K to move between hunks, 'q' to quit, '>' to advance). If users return to a hunk via J/K and make new decisions, they're returned to the "what_now" prompt since the file was previously considered decided.

The patch modifies `add-patch.c` with 65 lines added and 6 lines removed, introducing this new interaction mode. As an RFC, the author explicitly seeks feedback on the design approach before finalizing the implementation. The changes appear focused and well-scoped, building on prior work the author did for another part of Junio's suggested improvements (showing previous hunk decisions when navigating back).

This looks like a thoughtful contribution to improving Git's interactive workflow, though as an early RFC it will likely undergo significant iteration based on list feedback, particularly around the interaction model and whether/how to handle the third suggested enhancement (file switching). The patch demonstrates good awareness of the existing discussion and a clear incremental approach.
