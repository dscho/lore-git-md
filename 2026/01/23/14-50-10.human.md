This is the final patch in a bugfix series addressing regression in error message reporting for batched reference updates. The series, co-authored by Karthik Nayak and Jeff King, restores detailed error messages that were lost when batched updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The patch implements Phillip Wood's suggested optimization using `ALLOC_GROW()` for the array handling in the display logic. It completes the solution by introducing a `ref_update_display_info` structure to collate update outcomes and delay display until after transaction commits, restoring detailed error messages while maintaining backward compatibility. Benchmarks show only 1% overhead for 1000 refs.

The series has already been merged by Junio Hamano in v3 form, with this final optimization now implemented in v4. Phillip Wood has reviewed the changes and confirmed the array handling looks good. The solution maintains compatibility with pre-batched-update error reporting while fixing the regression from commit 9d2962a7c4.
