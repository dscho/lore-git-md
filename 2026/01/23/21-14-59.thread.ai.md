Jean-Noël Avila's documentation standardization effort continues with parallel work on multiple Git man pages, including `git-submodule`, `git-show`, `git-clone`, and `for-each-ref-options`. The latest patches refine both `git-show` and `git-clone` documentation as part of this multi-year initiative to achieve AsciiDoc synopsis-style consistency across all documentation.

Key technical changes include: standardizing option presentation (explicit `--reject-shallow`/`--no-reject-shallow` instead of `--[no-]` shorthand), converting manual `*NOTE*` markup to proper AsciiDoc `NOTE:` macros, fixing placeholder formatting (e.g., `_<when>_`), and using imperative mood for option descriptions. The `git-show` patch specifically introduces synopsis-style block definitions in `asciidoc.conf.in`, converts command syntax blocks to `[ synopsis]` markup, and restructures the pretty formats section with clearer hierarchy. The changes maintain cross-toolchain compatibility between asciidoc.py and asciidoctor while improving presentation clarity.

Kristoffer Haugsbakk's review feedback from earlier iterations continues to shape the effort, with systematic incorporation of precise formatting improvements like standardized placeholder display and consistent quoting styles. The work remains strictly focused on documentation presentation - no command behavior is introduced or altered. The patches demonstrate meticulous attention to detail in converting mixed formatting to uniform backtick-wrapped options (`--server-option=<option>`) and normalizing cross-references, building on previous v2 series that addressed multiple documentation files.
