Jean-Noël Avila's documentation standardization effort continues with parallel conversions of multiple Git man pages (`git-submodule`, `git-show`, `git-clone`, `for-each-ref-options`, `pretty-formats.adoc`, `ref-storage-format.adoc`) to consistent AsciiDoc synopsis-style formatting. The v3 series includes completed conversions of `git-submodule.adoc` (with Kristoffer Haugsbakk's Reviewed-by) and `git-show.adoc`, along with final polish on previously converted pages. The latest patch finalizes `git-clone.adoc` and `for-each-ref-options.adoc` conversions while making minor tweaks to `ref-storage-format.adoc`, applying the stuck-form convention (`--option=<value>`) that Junio Hamano endorsed earlier, with Kristoffer Haugsbakk reviewing and signing off on the changes. Key refinements include standardizing option presentation (including splitting `--[no-]reject-shallow` into two options), fixing decoration option rendering (particularly `->` pointer symbols in `pretty-formats.adoc`), converting manual `*NOTE*` markup to proper AsciiDoc `NOTE:` macros, standardizing placeholder formatting (`_<name>_`), and adjusting configuration option presentation (`-c<key>=<value>`). The work introduces synopsis-style block definitions in `asciidoc.conf.in` while maintaining cross-toolchain compatibility between asciidoc.py and asciidoctor. For `git-submodule.adoc`, the conversion uses proper stuck-form options and definition lists for complex command variants, while `git-clone.adoc` now has consistent stuck-form options following Junio's endorsement. The latest patch specifically focuses on `git-show.adoc` and `pretty-formats.adoc`, adding `blockdef-open` definitions in `asciidoc.conf.in` to support synopsis-style blocks across docbook and xhtml backends, converting `git-show`'s command syntax to use the new `[synopsis]` block with proper stuck-form options and placeholders, and reformatting `pretty-formats.adoc` to use definition lists for each format type with nested synopsis blocks showing the format structure. Kristoffer Haugsbakk has reviewed and signed off on these changes. Remaining work includes addressing rendering nuances like decoration option consistency and potentially developing custom parser extensions for special character handling. The effort remains focused on documentation presentation quality without altering command behavior, with each iteration systematically improving formatting details across the targeted man pages.
