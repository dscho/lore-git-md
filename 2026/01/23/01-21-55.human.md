This is a technical discussion about mtime handling in the ODB abstraction series, specifically focusing on patch 12/14 which converts `builtin/pack-objects` to use the new `packfile_store_for_each_object()` API.

Taylor Blau raises thoughtful questions about whether the current approach of exposing GC-specific mtime semantics at the object_info layer is the right design. He suggests an alternative where the object_info struct would provide more generic stat information (via a `statp` pointer) and let callers implement their own mtime interpretation logic. This would keep the ODB layer more general while still supporting the cruft pack use case through a helper function like `object_info_gc_mtime()`.

The discussion also touches on subtle differences in how locality is handled between the old and new iteration approaches, with Taylor noting that the check for local-only objects appears in both the caller and callee but might not be exactly equivalent. This suggests the design might benefit from clearer ownership of the locality filtering responsibility.

This email represents one of the final open discussions in the otherwise technically approved ODB abstraction series. The mtime semantics question is particularly important as it affects how future backends will need to implement object metadata reporting. Taylor's feedback indicates he's generally comfortable with the direction but wants to ensure the design is robust enough to handle both current and potential future use cases.
