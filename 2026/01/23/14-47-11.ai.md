This is a follow-up discussion about CI test optimizations, specifically around skipping certain tests in leak-checking and ASan jobs. Phillip Wood responds to Junio C Hamano's suggestion about potentially generalizing the test-skipping mechanism from individual SCM flags (NO_SVN_TESTS, NO_CVS_TESTS) to a more comprehensive NO_FOREIGN_CODE_TESTS variable.

Phillip agrees with the technical approach but notes the naming challenge - the tests are being skipped because they're scripted and exercise minimal C code (where leaks would occur), not because they interface with foreign SCMs. He points out that if `git svn` were implemented in C, it would still need leak checking despite calling foreign programs. The discussion remains open-ended about finding the right abstraction for these test exclusions.

The thread shows thoughtful consideration of CI optimization patterns, with participants carefully distinguishing between the incidental characteristic (foreign SCM interaction) and the actual rationale (minimal C code coverage). This builds on the earlier consensus to skip Perl-based tests in leak-checking jobs, now exploring how to extend and generalize that approach.
