This is a discussion about code style and memory ownership patterns in the final patch of a bugfix series addressing reference update error reporting.

Junio Hamano is providing feedback on the memory ownership model used in the newly introduced `ref_update_display_info` structure. He notes there are two common approaches to marking string fields in such structures: using `const char*` to indicate the structure won't modify the strings (even though it owns them), versus using non-const pointers to clearly signal ownership. While Junio personally prefers the const approach for its safety benefits, he acknowledges most Git developers follow the non-const convention for clearer ownership signaling.

The discussion stems from Karthik Nayak's implementation where string fields are marked const but require const-casting when freed, confirming these are owned (not borrowed) strings. Junio suggests aligning with the project's predominant style by using non-const pointers, which would eliminate the need for casts while making ownership more immediately obvious to readers.

This is a stylistic refinement to an otherwise complete and merged solution for restoring detailed error messages in batched reference updates. The technical functionality isn't in question - the thread confirms the memory management is correct and the series has addressed all substantive feedback through its four iterations.
