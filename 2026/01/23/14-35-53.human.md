Bugfix for `git subtree split --prefix` validation in the contrib/subtree command. This is the fourth iteration of a patch from Pushkar Singh (not D. Ben Knoble as the thread summary indicated) that corrects how path validation works when splitting older commits.

The core issue is that `git subtree split --prefix` was incorrectly checking paths against the current working tree rather than the target commit being split. This could cause failures when trying to split historical commits where the subtree existed but has since been removed from the working directory. The fix changes the validation to use `git ls-tree` against the specified commit instead.

The patch adds a regression test that verifies the corrected behavior by:
1. Creating a commit with a subtree
2. Removing that subtree in a later commit
3. Confirming `split --prefix` still works when targeting the original commit

This version incorporates feedback from previous iterations, including proper indentation fixes and the promised test case. The changes are focused and well-contained to the subtree contrib script and its test file. The commit message clearly explains the problem and solution, making this a straightforward bugfix that appears ready for review.
