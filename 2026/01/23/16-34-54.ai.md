Feature addition to `git repo info` command, final patch in a series implementing `--keys` flag for machine-readable repository metadata discovery.

This patch adds the `--keys` flag to `git repo info`, allowing users to programmatically discover available metadata keys without having to parse documentation or use `--all`. The implementation follows the thread's established conventions: it supports both newline-delimited and NUL-terminated output formats (via `--format=lines`/`--format=nul` or `-z`), maintains strict validation of option combinations, and includes comprehensive tests.

The patch completes the naming unification effort by using "lines" format consistently across all `git repo` subcommands, replacing the temporary "keyvalue" name from earlier iterations. Documentation follows the project's `_NUL_` convention for describing NUL-terminated output. The implementation includes:
- New `print_keys()` function handling format-specific output
- Validation preventing `--keys` from being combined with `--all` or explicit key requests
- Tests verifying format behavior, option validation, and default format selection
- Documentation updates for the new flag

This is the final version of a well-reviewed series that has addressed all feedback, with Junio Hamano confirming the naming choices and Patrick Steinhardt verifying the technical implementation. The patch is ready for integration into `next`, replacing the earlier queued version (ac3e74d2). The changes are focused and mechanical, completing the feature's implementation without introducing new complexity.
