This is a minor documentation clarification in the ongoing hook subsystem refactoring series. Patrick Steinhardt provides two small nits on Adrian Ratiu's patch that allows hooks to have separate stdout and stderr streams rather than always merging them.

The first note points out that commit messages should use past tense ("assumes" rather than "assumed") for describing current behavior. The second suggests mentioning in the hook.h documentation that merging stdout to stderr is the default behavior, which the code already implements via the RUN_HOOKS_OPT_INIT macro setting stdout_to_stderr=1.

Patrick explicitly states these are not worth a reroll - they're minor enough to be fixed during application if desired. The patch itself has already been through extensive review and is part of a series that has achieved maintainer consensus, with only final documentation polish remaining before merging. The changes touch the hook execution infrastructure in hook.c and the options structure in hook.h, maintaining backward compatibility while adding flexibility for hook authors who need separate output streams.
