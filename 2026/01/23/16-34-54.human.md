This is a feature patch adding a `--keys` flag to `git repo info` for programmatic repository metadata access. It's the final version (v5) of a series that has been through several iterations with review feedback from Junio Hamano and Patrick Steinhardt.

The patch introduces a new `--keys` option that lists available metadata keys without their values, making it easier for scripts to discover what information is available. The output format can be specified as either newline-separated (`lines`, the default) or NUL-terminated (`nul`). The implementation includes:
- A new `print_keys()` function in `builtin/repo.c`
- Comprehensive tests verifying the new flag's behavior
- Documentation updates showing the new option
- Validation to prevent invalid combinations with other flags

The series has evolved through multiple versions to unify format handling across `git repo` subcommands, with this final patch completing the naming consistency by replacing "keyvalue" format with "lines" format. The implementation looks clean and well-tested, with all review feedback addressed. This appears ready for integration into `next`.
