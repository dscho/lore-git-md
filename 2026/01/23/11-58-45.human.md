Feature enhancement for `git add -p` interactive workflow. This RFC patch from Abraham Samuel Adekunle implements a "what now" prompt that appears after all hunks in a file have been decided, allowing users to revisit and modify their hunk selections before moving on. The change builds on prior suggestions from Junio C Hamano for improving the interactive add interface.

The patch modifies `add-patch.c` to introduce navigation controls (J/K to move between hunks, 'q' to quit, '>' to advance) while maintaining the decided-file state. This addresses two of three enhancements Junio previously proposed, though file-switching between decided files remains unimplemented. The implementation is focused, touching only the necessary parts of the interactive loop with about 65 lines changed.

The author requests feedback on the interaction design and general usability. The patch appears well-contained and follows the established pattern of the interactive add code. It doesn't yet handle all suggested features, but provides a clear incremental improvement to the workflow. Those who frequently use `git add -p` may want to test this proposed enhancement to see if the new navigation model feels intuitive.
