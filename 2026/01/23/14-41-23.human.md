This is the final patch (6/6) in a bugfix series from Karthik Nayak and Jeff King that restores detailed error messages for batched reference updates in `git fetch`. The series addresses a regression where error messages became less informative after the introduction of batched updates.

The patch introduces a `ref_update_display_info` structure to collate update outcomes and delays displaying them until after the transaction commits. This allows proper error reporting while maintaining the performance benefits of batched updates. Benchmarking shows only a 1% overhead for repositories with 1000 refs.

Phillip Wood provides a brief review note confirming the array handling looks good, indicating this well-tested series is ready for merging. The patch builds on earlier work in the series that prepared the callback infrastructure for detailed error reporting while maintaining backward compatibility.

Key improvements include:
- Restores pre-batched-update behavior of showing specific error messages (like "trying to write non-commit object")
- Maintains machine-parsable stdout format while adding detailed errors to stderr
- Uses efficient strmap and dynamic array structures to track failed updates
- Adds test coverage for the restored error message behavior

This completes the series that was already merged in v3 form, now incorporating Phillip Wood's optimization suggestions. The solution maintains compatibility while fixing the regression in error reporting that affected debugging workflows.
