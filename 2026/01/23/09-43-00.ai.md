Feature: ODB abstraction series (part 10/14)

This patch continues Patrick Steinhardt's ongoing effort to abstract Git's object storage layer, focusing on removing direct uses of `for_each_loose_object()` and `for_each_packed_object()` in favor of the new ODB iteration API. The exchange with Taylor Blau clarifies two key points about the current state of the conversion.

First, the patch includes a temporary workaround in `builtin/cat-file.c` that manually iterates through object sources rather than using the new unified `odb_for_each_object()` function. Patrick explains this is because full filter support (like "--filter=blobs:none") will be implemented in a follow-up series via a new `struct odb_for_each_object_options` that will handle filtering at the backend level. He agrees to add a TODO comment marking this as temporary.

Second, the discussion reveals the planned direction for the filtering API, which will support object ID prefixes (for `object-name.c`), object filters, and potentially other iteration parameters. This design would move filtering logic into the backend, allowing optimizations like bitmap-based filtering for packfiles. The patch itself is largely mechanical, converting callers to the intermediate API while the thread focuses on the roadmap for completing the filtering functionality.

This exchange shows the series transitioning from core API design to implementation details, with Taylor's review shifting from architectural concerns to specific caller adaptations. The technical approach appears settled, with only minor documentation and temporary markings needed before this piece can be considered complete. The thread confirms this part of the series is nearing readiness while leaving the door open for the planned filtering enhancements in future work.
