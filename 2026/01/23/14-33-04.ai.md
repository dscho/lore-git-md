Bugfix for `git last-modified` command hardening. This is the final patch in a series that has already been merged, adding input validation to prevent BUG behavior when given tree OIDs. The patch ensures the command properly verifies its input is commit-ish (not trees or blobs) using `repo_peel_to_type()`, with corresponding test coverage.

The change adds a check in `populate_paths_from_revs()` that rejects non-commit objects with a clear error message ("revision argument X is a Y, not a commit-ish"). The test suite is expanded to verify this behavior by attempting to pass `HEAD^{tree}` and checking the error output. An additional positive test case for annotated tags is also included, demonstrating proper handling of tag objects that resolve to commits.

This completes the hardening work on the command after earlier rounds addressed memory leaks and terminology issues. The implementation now robustly handles all input cases with appropriate validation and error reporting. The patch follows the project's pattern of defensive programming while maintaining clear user feedback when constraints are violated.
