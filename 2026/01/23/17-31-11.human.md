This is a follow-up discussion about localization in error messages for the recently merged `git last-modified` bugfix series. Junio C Hamano raises a question about how to handle mixed localized and non-localized strings in error messages, specifically when reporting object type mismatches.

The issue centers on the message "revision argument '%s' is a %s, not a commit-ish" where:
- The type name (from `type_name()`) will always be in English (C locale)
- The "commit-ish" term might be localized
- This creates an inconsistent mix of languages in the output

Junio suggests two possible approaches:
1. Leave as-is for now (with the language mix) and address later
2. Force English for both parts by making "commit-ish" non-localized
