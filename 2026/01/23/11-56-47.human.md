This is an RFC patch proposing UI improvements for `git add -p`'s interactive mode, focusing on allowing users to revisit and modify hunk decisions after initially completing a file.

The patch addresses one of three UI enhancements suggested by Junio C Hamano in an earlier discussion. Specifically, it implements the ability to rework a file's hunks after all have been decided, without automatically advancing to the next file. The current implementation shows a "what_now" prompt after all hunks are decided, allowing navigation back to previous hunks (with J/K), quitting (q), or proceeding to the next file (>).

The author acknowledges this is an early design meant to solicit feedback, particularly on the interaction model when returning to previously decided hunks. The patch modifies `add-patch.c` with about 70 lines of changes to implement this workflow. 

This appears to be a well-motivated quality-of-life improvement for interactive staging, following up on specific maintainer feedback. The implementation looks focused and the author is clearly seeking design input before finalizing the approach. The patch is part of a broader effort to enhance `git add -p`'s usability, with the author having previously worked on another of Junio's suggested improvements (showing previous hunk decisions when navigating back).
