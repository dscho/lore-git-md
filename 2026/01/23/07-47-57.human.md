This is part 6 of a 12-patch series refactoring Git's hook subsystem to support parallel execution and standardized behavior. The series as a whole has already addressed major technical concerns and is nearing final approval, with only minor documentation tweaks remaining.

This particular patch makes the hook's stdout-to-stderr behavior configurable rather than hardcoded, while maintaining the existing behavior (stdout merged to stderr) as the default. The change is straightforward - adding a flag to `struct run_hooks_opt` and using it in the hook execution logic. Patrick Steinhardt noted two minor documentation nits (commit message tense and explicitly documenting the default behavior) which Adrian Ratiu confirms will be fixed in the next version.

The patch is part of a well-reviewed series that has maintainer consensus and CI validation. The changes here are incremental and uncontroversial, focused on giving hook implementers more control over output stream handling while preserving backward compatibility.
