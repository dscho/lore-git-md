This is a follow-up in the git-gui bugfix thread about tab alignment in the diff viewer. Chris Idema confirms Johannes Sixt's concern that converting tabs to spaces for display purposes breaks the "Stage Line/Hunk for Commit" functionality, as the copied text no longer matches the original file contents. 

The key technical issue is that the proposed solution (expanding tabs to spaces) creates a mismatch between what's displayed and what's actually in the file, which affects the staging mechanism that extracts text from the diff widget. Chris acknowledges this is a problem but doesn't yet have a solution that preserves both proper visual alignment and correct staging behavior.

The thread has now identified a hard requirement: any fix must maintain the ability to stage changes accurately from the diff viewer. This likely means the tab-to-space conversion approach needs rethinking, as it fundamentally alters the text that the staging mechanism operates on. The next steps would be either to find a way to make Tk render tabs correctly without conversion, or to modify the staging logic to handle space-converted text appropriately.
