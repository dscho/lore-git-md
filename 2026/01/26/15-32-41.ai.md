Bugfix attempt for git-gui tab alignment issue. Chris Idema reports finding a potential solution to the long-standing tab display misalignment between git-gui and gitk on Windows by using Tk's `apply_tab_size` setting. This follows previous discussion where Johannes Sixt (Git GUI maintainer) firmly rejected approaches that modify the actual diff text (like converting tabs to spaces) because they would break the staging functionality.

The proposed fix appears to involve configuring Tk's native tab rendering rather than text manipulation, which would satisfy the maintainer's core requirement of preserving the original text content. However, Chris notes uncertainty about the proper placement of this configuration directive, suggesting this is still an experimental finding rather than a fully baked solution.

This moves the thread forward by shifting from the previously blocked text-conversion approach to investigating Tk's display configuration options. If viable, this path could resolve the visual inconsistency without compromising the staging functionality that depends on unaltered text. The next steps would involve testing the configuration in various contexts and confirming it doesn't introduce new display artifacts.
