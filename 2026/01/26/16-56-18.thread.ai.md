RFC performance optimization for the p3400 rebase test setup. Tian Yuchen investigates replacing the shell loop (29s setup) with git fast-import (18s setup, 38% faster) while maintaining identical commit history structure. The fast-import approach precomputes file contents and creates commits in one operation, avoiding process spawning. Initial results show setup speed improvement but an unexpected rebase performance regression (2s -> 5s), suggesting underlying repository state differences despite surface-level equivalence.

Key technical details: The test generates 100 commits with alternating forward/reversed file contents. Tian hypothesizes the regression may stem from fast-import producing non-delta-compressed packfiles, as hinted by fast-import documentation recommending post-import repacking. This could significantly impact Git's object access patterns during rebase.
