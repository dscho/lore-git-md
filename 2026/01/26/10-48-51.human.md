This is a performance-oriented refactoring of Git's xdiff engine, part of an ongoing cleanup series. Phillip Wood proposes removing the `line_hash` field from `xrecord_t` since it's only used temporarily during line classification, not for the actual diff computation. The change reduces memory usage by 25-40% per line (significant given xdiff engine creates one struct per input line).

The patch is a focused optimization that doesn't change diff output - it reorganizes where the temporary hash value is stored during processing. Phillip notes this builds on prior work (commit 6a26019c81) that split the hash field's dual-purpose use. The change is small (6 lines net) and touches only xdiff internals, suggesting low risk.

As part of a larger xdiff cleanup effort, this patch needs coordination with the conflicting 'en/xdiff-cleanup-3' series. Phillip's approach here represents a conservative optimization from an experienced contributor (he maintains Git's interactive rebase and diff-related code). The memory savings make this worth considering, though the final form may need adjustment based on how the competing cleanup series progresses.
