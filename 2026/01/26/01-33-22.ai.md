This is a bugfix patch for the fsmonitor-watchman hook, addressing two issues in the error handling and protocol compliance of the watchman integration. The first bug silently ignored errors from watchman_clock() by checking the wrong variable (`$output->{error}` instead of `$o->{error}`). The second bug caused the hook to output two clock tokens when falling back to a full scan, violating Git's fsmonitor v2 protocol which expects exactly one response.

The fix removes a recursive call to launch_watchman() that was causing the duplicate output, since the "/" flag already tells Git to do a full scan. The same changes are applied to both the sample hook and test helper scripts in t/t7519/. The patch appears straightforward and well-motivated, with clear explanations of both the bugs and their fixes.
