This is part 10 of a 12-part series refactoring Git's hook subsystem to support parallel execution. The patch focuses on improving I/O handling in `run-command.c` when feeding input to child processes.

The change addresses a throughput bottleneck where child processes could experience artificial 100ms delays due to polling only on output while buffering input. The patch refactors the I/O loop to poll both stdin and stdout file descriptors, eliminating potential deadlocks and improving performance when running hooks in parallel. The core change replaces separate stdin/stderr handling with a unified `pp_buffer_io()` function that manages both directions.

Key technical details:
- Doubles the pollfd array size to accommodate both input and output FDs
- Introduces `child_is_receiving_input()` helper to match existing `child_is_working()`
- Maintains backward compatibility with sequential execution (ungroup=1)
- Preserves the 100ms timeout but now applies it to both input and output operations

The patch has already addressed most review feedback, with only minor documentation nits remaining.
