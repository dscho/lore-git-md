This thread focuses on optimizing Git's xdiff (diff engine) subsystem to reduce memory usage, continuing prior cleanup work. Phillip Wood proposed two targeted optimizations: removing the unused `line_hash` field from `xrecord_t` and restructuring `xdlclass_t` to store only essential line data. These changes reduce memory consumption while maintaining the existing diff algorithm's behavior.

Junio C Hamano, as maintainer, has decided to move forward with Phillip's conservative approach rather than Elijah Newren's more aggressive 'en/xdiff-cleanup-3' series, which would have restructured when lines are classified during diff preparation. Junio temporarily removed Elijah's competing series from the integration branch to prioritize Phillip's changes, which are now being tested. The optimizations are mechanical and localized to `xdiff/xprepare.c` and `xtypes.h`, focusing on memory efficiency in frequently allocated structures during diff operations.

The decision reflects Junio's preference for incremental improvements that don't disrupt the existing classification timing, while leaving open the possibility of revisiting more substantial changes later. This careful approach is typical for performance-critical subsystems like xdiff engine, where even mechanical optimizations receive thorough scrutiny. With Junio's approval, Phillip's changes are now the path forward, though the discussion about classification timing may resurface in future work.
