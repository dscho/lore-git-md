Tian Yuchen has been exploring ways to optimize the setup time for the p3400 rebase performance test, which currently uses a shell script to generate 100 commits with alternating file contents (taking ~29 seconds). The RFC thread examines replacing this with `git fast-import`, which initially showed promising 38% speedup in setup (18.1s) but caused rebase performance to regress from 2s to 5s due to differences in delta compression.

The v2 patch refines this approach by pre-generating file contents and adding a repack step, achieving a 26% setup improvement (22.2s) while keeping rebase times comparable to the original (12.78s vs 13.34s). This addresses the delta compression issue that caused earlier inconsistencies. The solution carefully replicates both the commit graph topology and file contents from the original test while normalizing object storage characteristics through repacking.

While this specific optimization appears successful, the broader discussion raises questions about test design philosophy - whether performance test setups should precisely mimic real-world repository states (with their natural delta compression patterns) or prioritize consistent measurement conditions. The patch sidesteps this debate by achieving both goals in this case, though storage experts like Jeff King or Patrick Steinhardt may still want to weigh in on the general principles.
