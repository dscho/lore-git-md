This is a performance optimization patch in the hook subsystem refactoring series, addressing I/O throughput issues in parallel hook execution. The patch refactors the run-command.c I/O polling to handle both child input and output simultaneously, eliminating artificial 100ms delays that were throttling performance when feeding data to multiple hooks in parallel.

The change comes in response to reports from Kristoffer Haugsbakk about throughput problems and Jeff King's observation about potential deadlocks when parent and child processes block waiting for each other. The solution introduces a new `pp_buffer_io()` helper that polls both stdin and stdout file descriptors, replacing the previous separate handling of input and output streams.

Emily Shaffer provides a minor review comment suggesting the use of a helper function (like `child_is_working()`) for checking the error file descriptor condition, but otherwise the patch appears technically sound. The change maintains backward compatibility with sequential execution while improving parallel performance, and is part of a well-vetted series that has already received maintainer approval.
