This is patch 5/14 in Patrick Steinhardt's v4 series abstracting Git's object database (ODB) layer. The patch refactors packed object iteration by extracting the core logic from `for_each_packed_object()` into a new helper function `packfile_store_for_each_object_internal()`.

The change prepares for upcoming backend-agnostic iteration by isolating the packfile-specific iteration code. The new helper maintains all existing functionality - handling the same flags (LOCAL_ONLY, PROMISOR_ONLY, etc.) and error conditions while making the control flow clearer by separating the per-packfile iteration from the repository-wide source traversal.

The patch is a straightforward mechanical refactoring with no behavior change, splitting the original function into two while preserving all filtering logic. It follows the series' pattern of introducing backend-independent interfaces while maintaining compatibility. The extracted function will be reused in the next patch to implement the new ODB iteration API for packed objects, mirroring the loose object iteration introduced in patch 4/14.

This continues the systematic conversion of Git's object storage layer to use abstracted interfaces, with Taylor Blau and others having reviewed similar conversions in related areas (fsck, commit-graph). The changes align with the series' goal of making object storage backends pluggable while keeping existing behavior intact.
