This is a refactoring patch series addressing inconsistencies in the `OBJECT_INFO_*` flag definitions and usage. The series comes from Patrick Steinhardt, who is actively involved in the object database (ODB) abstraction effort.

The cover letter explains that the series originated from noticing gaps in the `OBJECT_INFO_*` flag values, which turned out to be historical artifacts from removed flags. While investigating, Patrick discovered that some code was incorrectly passing these flags to `odb_has_object()`, though this wasn't causing actual bugs due to coincidental flag values. The first two patches fix these incorrect flag usages in `builtin/backfill.c` and `builtin/fsck.c`, while the third patch reorganizes the flag definitions to eliminate the gaps and converts them to use an enum for better type safety.

The changes are small and focused, touching only three files. The series appears to be a straightforward improvement to code hygiene rather than fixing any user-visible behavior. Given Patrick's deep involvement in the ODB work and the mechanical nature of these changes, the patches are likely to be uncontroversial. The commit messages explain the rationale clearly, though they don't mention whether there are any performance or compatibility implications from the flag value changes (the cover letter suggests there aren't any actual bugs being fixed here).
