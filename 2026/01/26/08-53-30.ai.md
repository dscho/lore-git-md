This is a technical follow-up in Patrick Steinhardt's ODB abstraction series (v3 11/14), addressing Taylor Blau's feedback about object info request/response handling. The patch modifies the iteration API to separate request and response object_info structs for safer field initialization.

The change makes object_info parameters const when used as input requests, ensuring callers can't modify the request struct during iteration. For responses, it introduces local copies of the struct to guarantee proper initialization of all fields before the callback receives them. This prevents potential issue where future contributors might forget to initialize new fields (like mtime) by ensuring each iteration starts with a fresh copy.

The implementation touches several key ODB iteration points:
- odb_source_loose_for_each_object()
- packfile_store_for_each_object()
- The core odb_for_each_object() interface

Patrick adopts Taylor's suggestion while noting it's an interim solution - a more comprehensive split between request/response structs is planned for future work. The change maintains the series' goal of supporting pluggable backends while improving safety during the transition period. This represents one of the final refinements to the ODB abstraction before the mtime handling discussion (the last major open question) can be resolved.
