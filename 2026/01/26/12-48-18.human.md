This is a feature proposal discussion about supporting repositories with intentionally missing objects, specifically for Debian's use case of storing source packages while excluding non-redistributable files. Philip Oakley continues the thread by exploring technical approaches to allow partial repository contents while maintaining integrity.

Philip references prior "obliterate" discussion from Git Merge 2020 and suggests speculative ideas for handling missing objects through specially-formatted replacement objects that could preserve commit graph structure. He distinguishes between completely removing objects (which wouldn't work for this use case) and creating tailored solution that marks certain objects as omitted while keeping the repository functional.

The key challenge is maintaining Git's hash-based integrity model while allowing exceptions for specific content. Philip proposes concepts like counterfeit objects with self-referential OIDs and authenticated facsimile objects, though acknowledges these are unproven ideas. He also suggests a simpler alternative of creating a separate commit that omits unwanted files, leveraging Git's content deduplication.

The discussion remains at the conceptual level, with no concrete implementation proposed yet. The thread is exploring whether such a feature could theoretically work within Git's design principles while addressing Debian's specific needs around package distribution. Technical concerns center on how to handle verification of partial repositories and whether any solution could maintain sufficient integrity guarantees.
