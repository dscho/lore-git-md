This is a follow-up in the `git subtree` regression thread, confirming the planned revert of the problematic commit.

Junio C Hamano confirms he has reverted commit 28a7e27cff ("contrib/subtree: detect rewritten subtree commits") as planned for Git 2.53.0-rc2, in response to Colin Stagner's acknowledgment that a proper fix would not be ready in time. The revert addresses the regression where `git subtree push` was incorrectly failing with "non-fast-forward" errors, particularly impacting Arch Linux AUR package repository synchronization.

Colin had previously analyzed that the root cause was an interaction between this commit and an earlier optimization (98ba49ccc2) that changed subtree split behavior in ways that violated the command's documented stability guarantees. While Colin had proposed making the optimization opt-in via a new flag, he recognized the immediate need for a revert to restore functionality.

The email confirms the project's prioritization of stability over optimization in this case, especially given the impact on real-world workflows like the Arch Linux AUR system. This maintains the thread's consensus that the regression needed prompt addressing, while leaving open the question of how to properly reconcile the optimization with behavioral consistency in a future update.
