This thread addresses a long-standing but subtle tab alignment inconsistency in git-gui's diff viewer on Windows, where tabs have been misaligned compared to gitk's correct display. The discussion has evolved through several technical approaches, with the current solution settling on using Tk's native `apply_tab_size` configuration to match gitk's behavior while preserving the staging interface functionality.

Chris Idema has implemented and confirmed the solution works across all diff contexts (regular, combined, and untracked files), with different tab offsets for each case. Maintainer Johannes Sixt initially rejected an earlier text conversion approach but now supports this direction. Junio Hamano provided historical context, noting gitk has handled this correctly since 2007, and offered specific wording guidance for the commit message to clarify that the tabstop adjustment compensates for diff markers in the first column.

While the visual difference is subtle enough that it went unnoticed for nearly two decades, the consensus is to fix it for consistency with gitk. The patch is now in its final stages, needing only completion of context detection logic, verification against gitk's implementation, and maintainer approval. Junio's observation about the issue's low severity suggests this isn't urgent, but the technical solution is now clearly defined and agreed upon by all participants.
