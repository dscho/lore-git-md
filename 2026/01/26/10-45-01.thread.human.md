This thread addresses a bug in git-gui's diff viewer where tab alignment appears inconsistent between git-gui and gitk on Windows systems running Tcl/Tk 8.6. The original patch from Chris Idema proposed converting tabs to spaces, but maintainer Johannes Sixt rejected this approach as it would break the "Stage Line/Hunk for Commit" functionality. The current solution instead uses Tk's native `apply_tab_size` configuration to adjust tab rendering without modifying the text content.

Junio Hamano raised important technical considerations about how this change might interact with combined diffs (those showing changes from multiple parents), referencing historical behavior from commit a43c5f51 (2012). The discussion revealed that regular diffs currently use `apply_tab_size 0` while combined diffs use `apply_tab_size 1`, and the patch would make both use `apply_tab_size 1`. Chris Idema's latest response clarified the evolution of the patch and emphasized the goal of visual consistency with gitk and command-line `git diff`, though it didn't fully address Junio's concerns about combined diffs.

The key unresolved questions center on whether a uniform tab size setting would cause problems with combined diffs, particularly regarding their two-column prefix format. The solution needs to preserve staging functionality while providing correct display in all contexts, maintaining compatibility with gitk's rendering and command-line output. While the architectural approach using Tk configuration appears sound, the patch may need refinement to properly handle both regular and combined diffs. The thread remains open pending further analysis of these edge cases.
