This thread addressed a long-standing but subtle tab alignment inconsistency in git-gui's diff viewer, where tabs appeared misaligned compared to gitk when using Tcl/Tk 8.6 on Windows. The issue, which had existed for nearly two decades without significant complaint, was brought to attention by Chris Idema, who initially proposed a text conversion solution. Maintainer Johannes Sixt rejected that approach as it would break the "Stage Line/Hunk for Commit" functionality, instead advocating for using Tk's native `apply_tab_size` configuration.

After thorough discussion, the solution settled on applying different tabstop offsets (1 for regular diffs to account for +/- markers, 2 for combined diffs) to match gitk's behavior since 2007. The implementation preserves all staging functionality while fixing the alignment issue across all primary contexts (regular, combined, and untracked file diffs), with octopus merges explicitly excluded from scope as they're not handled by git-gui's diff display. 

Junio Hamano provided historical context and commit message guidance, noting that while the issue wasn't critical, the fix would improve real-world code review workflows. With all technical questions resolved and Johannes Sixt's approval of the solution's scope, the patch is now ready for final documentation polish and merging as a routine bugfix. The thread demonstrates how even subtle UI inconsistencies can receive careful consideration in the Git project, with maintainers balancing technical purity against practical workflow concerns.
