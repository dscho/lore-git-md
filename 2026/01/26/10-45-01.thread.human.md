This thread addresses a critical tab alignment issue in git-gui's diff viewer that makes diffs effectively unreadable on Windows with Tcl/Tk 8.6 (Git for Windows 2.52.0.windows.1). While gitk displays tabs correctly, git-gui shows misaligned output. After initial debate about solution approaches, maintainer Johannes Sixt has provided exact specifications for handling different contexts: regular diffs need a 1-character offset, combined diffs (merge conflicts) need 2, and untracked files need 0. This builds on prior work for 3-way diff handling (commit a43c5f51a4b1).

Chris Idema is now implementing the final solution using Tk's native `apply_tab_size` configuration, having tested across all diff states. The remaining work involves context to apply the correct offsets while preserving the staging interface functionality, with the commit message to frame this as "shifting tabstops to account for first column." The fix is particularly urgent for Windows users where the issue is most severe, and represents the culmination of technical consensus after Johannes Sixt overruled earlier text conversion approaches in favor of this configuration-based solution that maintains compatibility with gitk's behavior.
