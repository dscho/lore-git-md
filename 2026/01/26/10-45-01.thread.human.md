This thread addresses a long-standing but minor inconsistency in git-gui's diff viewer where tabbed text would display misaligned compared to gitk, particularly noticeable on Windows with Tcl/Tk 8.6. After thorough discussion, the solution involves a small but precise two-line change in `diff.tcl` that applies Tk's native tab size adjustments with different offsets (1 column for regular diffs, 2 for combined diffs) to compensate for diff markers while preserving the staging interface functionality.

The fix matches gitk's behavior that has been in place since 2007, though it's worth noting this is considered more of an improvement than a strict bugfix since the issue existed for nearly two decades without significant complaints. Johannes Sixt, who maintains gitk, has reviewed and approved the technical approach, confirming it correctly handles all in-scope cases (regular/combined/untracked diffs) while explicitly excluding octopus merges beyond git-gui's scope. He also rewrote the commit message for clarity. Junio Hamano validated the historical context and confirmed the patch is ready for merging as a routine improvement.

The thread shows clear consensus that this small change properly aligns git-gui's behavior with gitk's while maintaining all existing functionality, concluding a subtle but workflow-improving inconsistency that dates back to the early days of these tools.
