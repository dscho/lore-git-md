This thread addresses a persistent tab alignment inconsistency in git-gui's diff viewer on Windows, where tabs appear misaligned compared to gitk's correct display. The discussion has centered on finding a solution that maintains visual consistency without breaking git-gui's staging functionality, which relies on unmodified text content.

The original proposal from Chris Idema involved converting tabs to spaces, but Johannes Sixt (Git GUI maintainer) firmly rejected this approach as it would disrupt the "Stage Line/Hunk for Commit" feature. The thread was at an impasse between fixing Tk's native tab display (with no known solution) or adapting the staging logic (an unproven path). Chris has now reported progress by discovering Tk's `apply_tab_size` setting, which might configure tab rendering without altering the underlying text—potentially satisfying both visual and functional requirements.

While this represents a promising direction, the solution isn't yet fully baked. Chris notes uncertainty about proper configuration placement, and further testing is needed to ensure no new display artifacts emerge. Johannes's core position remains unchanged: any solution must preserve the decades-old patch display conventions and staging behavior. The thread now awaits validation of this Tk configuration approach or alternative solutions that meet these constraints.
