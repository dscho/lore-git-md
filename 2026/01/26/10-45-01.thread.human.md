This thread addresses a bug in git-gui where tab alignment in the diff viewer appears misaligned compared to gitk on Windows with Tcl/Tk 8.6. The original patch from Chris Idema proposed modifying text content to fix alignment, but maintainer Johannes Sixt rejected this approach as it would break the "Stage Line/Hunk for Commit" functionality. The current solution instead uses Tk's native `apply_tab_size` configuration to adjust tab rendering without altering text.

Junio C Hamano's review introduced new technical considerations, pointing out that the patch's uniform application of `apply_tab_size 1` may conflict with existing behavior for combined diffs (which already use this setting to accommodate their two-column prefix). He identified potential off-by-one errors and suggested the solution may need context-sensitive adjustments depending on whether the diff is regular (single parent) or combined (multiple parents). The thread references commit a43c5f51 from 2012 that originally introduced this tab size configuration, providing historical context.

The discussion now focuses on determining correct tab size settings for different diff contexts while maintaining the core constraints: no text modification, preserved staging functionality, and minimal changes. Johannes Sixt's original requirements remain in place, but Junio's review adds the need for careful handling of combined diff edge cases. The solution appears architecturally sound but awaits verification of combined diff behavior and potential adjustments to handle different diff types appropriately before final approval.
