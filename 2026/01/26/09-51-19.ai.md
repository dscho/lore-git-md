This is part 3/14 of Patrick Steinhardt's ODB abstraction series (v4), focusing on refactoring object-file handling. The patch extracts a new `read_object_info_from_path()` function from the existing `odb_source_loose_read_object_info()` to handle reading object information given a direct path, rather than requiring an OID lookup first. This prepares for future introduction of a generic object iteration API.

Key changes include:
- The new function takes a direct path parameter rather than deriving it from the OID
- Removes the now-unused `stat_loose_object()` helper since its functionality is handled inline
- Preserves all existing behavior while making the code more modular
- The original `odb_source_loose_read_object_info()` becomes a thin layer that just resolves the path before calling the new function

This is a clean refactoring that follows the series' goal of making object storage more backend-agnostic. The change is well-contained to `object-file.c` and maintains all existing functionality while improving code organization. The commit message clearly explains the motivation and impact. This appears ready for integration as part of the larger series.
