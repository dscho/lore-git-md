This is a refactoring patch series targeting Git's xdiff (diff engine) subsystem, building on previous cleanup work in the 'en/xdiff-cleanup-2' series. Phillip Wood proposes two structural changes to reduce memory usage in the diff calculation internals.

The first patch removes the `line_hash` field from `xrecord_t`, which stores information about individual lines being diffed. The commit message explains this hash was only used during the initial line classification phase and can be discarded afterward. The second patch similarly removes unused data from `xdlclass_t`, another internal diff structure.

The series conflicts with another in-progress xdiff cleanup series ('en/xdiff-cleanup-3') that changes when line classification occurs. Phillip notes some skepticism about that approach but suggests if it's kept, the hashes could be passed separately rather than stored in `xrecord_t`.

These changes are purely internal optimizations - they don't affect diff output or user-visible behavior. The patches are small and focused, touching only xdiff preparation code. Phillip is a known contributor with expertise in Git's diff/merge machinery, so these changes likely represent well-considered cleanups rather than speculative tinkering. The conflict with another active series suggests this may need coordination before merging.
