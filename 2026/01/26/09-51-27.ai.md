Part of Patrick Steinhardt's ongoing ODB abstraction series (v4 11/14), this patch introduces mtime tracking for objects in the object database. The change adds a new `mtimep` field to `struct object_info` to expose modification times of objects, which is particularly important for garbage collection of unreachable objects.

The patch acknowledges the inherent ambiguity of mtimes when objects exist in multiple locations (loose objects vs packed), leaving it to callers to disambiguate based on their specific needs. It explicitly warns against using `odb_read_object_info()` for mtime queries since that interface lacks context about object locations, recommending `odb_for_each_object()` instead.

Implementation touches multiple subsystems:
- Adds mtime handling in loose object reading via stat()
- Includes mtime support for packed objects, with special handling for cruft packs' .mtimes files
- Documents the mtime field's limitations and proper usage patterns
- Maintains backward compatibility while extending the object info interface

This continues the series' pattern of incremental ODB abstraction while addressing a concrete use case (pruning). The change appears well-considered, with clear documentation about edge cases and appropriate warnings about interface limitations. As with previous patches in the series, this maintains the existing behavior while paving the way for future backend-agnostic implementations.
