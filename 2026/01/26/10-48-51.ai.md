This is a refactoring patch targeting Git's xdiff (diff engine) subsystem, part of an ongoing effort to optimize memory usage in the diff machinery. Phillip Wood proposes removing the `line_hash` field from `xrecord_t` since it's only used temporarily during line classification, not for the actual diff computation. The field was previously split from the `ha` field in an earlier commit (6a26019c81).

The change moves the hash storage to `xdlclass_t` where it's actually needed, reducing `xrecord_t` size by 25-40% depending on platform. Since Git creates one `xrecord_t` per input line during large diffs this could yield meaningful memory savings. The patch touches only xdiff preparation code in `xprepare.c` and the type definition in `xtypes.h`, with straightforward mechanical changes to pass the hash separately during classification.

This is the first of two patches in a series that conflicts with another active xdiff cleanup effort ('en/xdiff-cleanup-3'). Phillip's approach here is more conservative than that competing series, keeping the same basic flow but optimizing storage. As a contributor with deep diff/merge expertise, his changes are likely well-considered, though coordination will be needed with the parallel effort before either can merge.
