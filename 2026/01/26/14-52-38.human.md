This is a bugfix discussion for git-gui's diff viewer, specifically about tab alignment issues in Windows environments. The thread has revealed a critical conflict between fixing visual tab rendering and maintaining the functionality of Git's staging mechanism.

Johannes Sixt (the Git GUI maintainer) confirms that the tab alignment issue occurs with default tab widths too, not just custom settings. More importantly, he identifies a showstopper problem: the current approach of converting tabs to spaces for display breaks the "Stage Line/Hunk for Commit" functionality, as the staging mechanism relies on the original text matching what's displayed.

The discussion highlights two key constraints: First, any solution must preserve the staging mechanism's ability to work with the original file contents. Second, Sixt expresses skepticism about changing the traditional patch display format that developers have grown accustomed to, where some misalignment is expected behavior.

The thread is currently blocked on finding a solution that satisfies both the visual alignment needs and the functional requirements of the staging system. This appears to be a deeper technical challenge than initially anticipated, requiring either a Tk display-level fix or modifications to the staging logic itself.
