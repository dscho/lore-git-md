This is the second patch in Patrick Steinhardt's series to clean up `OBJECT_INFO_*` flag usage, part of his ongoing ODB abstraction work. The patch fixes incorrect flag passing in `builtin/fsck.c` where `mark_object()` was using a hardcoded `1` instead of the proper `HAS_OBJECT_RECHECK_PACKED` flag when calling `odb_has_object()`. 

The change ensures correct behavior when checking for object existence during fsck operations, particularly around promisor objects. While the existing code worked by coincidence (the numeric value happened to match the intended flag), this patch makes the intention explicit and future-proof. The fix is minimal (3 lines changed) and maintains the same runtime behavior while properly documenting the intent through the named constant.

This continues the pattern seen in patch 1/3 of replacing magic numbers with proper flag constants in the ODB layer. The change is low-risk since it doesn't modify behavior - it just makes the existing behavior more maintainable and explicit. As with the rest of the series, this is internal code hygiene with no user-facing impact.
