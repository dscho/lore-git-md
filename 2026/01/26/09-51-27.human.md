This is part 11/14 of Patrick Steinhardt's ongoing ODB (object database) abstraction series, focusing on adding mtime tracking for objects. The patch introduces a new `mtimep` field in `struct object_info` to track modification times, which is particularly important for garbage collection of unreachable objects.

The change acknowledges that mtimes can be ambiguous when objects exist in multiple locations (loose objects vs packed), so the responsibility for disambiguating falls to callers. The implementation handles both loose objects (via filesystem mtime) and packed objects (using packfile mtimes or .mtimes files for cruft packs). The documentation strongly recommends using this only with `odb_for_each_object()` rather than single-object lookups due to the ambiguity.

This continues the series' pattern of careful, incremental changes to the object storage layer while maintaining backward compatibility. The patch touches core object-handling code in `object-file.c`, `packfile.c` and related headers, with thorough documentation of the new field's limitations. As with previous patches in the series, this appears to be a well-considered change that moves the ODB effort forward while properly handling edge cases.
