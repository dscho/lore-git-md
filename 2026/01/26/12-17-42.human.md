This is the second patch in Patrick Steinhardt's series cleaning up `OBJECT_INFO_*` flag usage as part of the ODB abstraction effort. It fixes an incorrect flag passing in `builtin/fsck.c` where a hardcoded `1` was being passed to `odb_has_object()` instead of the proper `HAS_OBJECT_RECHECK_PACKED` flag.

The patch explains that this was introduced in 2019 to avoid lazy-fetching promisor objects during fsck, but the hardcoded value was relying on implementation detail (the numeric value of the flag) rather than the documented interface. The change makes the intent explicit by using the named constant while maintaining the same behavior - the object database will recheck packed storage but won't fetch missing objects.

This is a straightforward correctness fix that aligns with Patrick's broader work on the ODB layer. The change is small (3 lines modified) and well-explained, with a clear commit message tracing the history and rationale. As with the first patch in the series, this appears to be a solid improvement with no expected controversy.
