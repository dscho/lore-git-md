This is a feature proposal discussion about supporting repositories with intentionally missing objects, specifically for Debian's use case of storing source packages while excluding non-redistributable files or vendored dependencies. Philip Oakley continues the thread by Simon Richter, exploring technical approaches to allow partial repository contents while maintaining integrity.

Philip references prior discussions about object redaction from Git Merge 2020, noting no clear solution emerged. He suggests speculative approaches for handling blob and tree objects through specially-formatted replacement objects that preserve commit graph structure, while acknowledging these are unproven ideas. The key challenge is maintaining Git's hash-based integrity model while allowing exceptions for omitted content.

The discussion focuses on whether a minimal viable feature could work within Git's design principles to address Debian's specific need. Philip proposes that creating a separate commit with deletions might be a lightweight solution, leveraging Git's content deduplication. He distinguishes between metadata (which must remain intact for graph integrity) and content (where exceptions might be possible).

The thread remains at a conceptual stage, with open questions about verification of partial repositories and whether any solution could maintain sufficient integrity guarantees. This represents an ongoing challenge in balancing Git's object model with practical use cases that require selective content exclusion.
