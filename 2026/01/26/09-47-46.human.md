This is a CI optimization discussion about test exclusions for leak checking. Phillip Wood responds to Junio C Hamano's earlier point about the principles behind skipping certain tests in leak-detection jobs. The thread has established that tests interacting with foreign SCMs (like SVN, CVS, and Perforce) should be excluded from leak checking since Git can't control leaks in their dependencies.

Phillip clarifies his position on hypothetical scenarios - if `git svn` were rewritten in C but still linked against libsvn, leaks in that library would still be outside Git's control. He notes that without proper instrumentation (-fsanitize=leak), the leak checker wouldn't catch issues in external libraries anyway. The discussion remains theoretical since these scripts aren't likely to be rewritten in C.

The exchange shows careful consideration of the boundaries between what Git can reasonably be responsible for versus external dependencies, with both participants agreeing on the practical outcome while exploring the underlying principles. The actual patch implementation (adding NO_SVN_TESTS and related variables) is already been agreed upon and merged earlier in the thread.
