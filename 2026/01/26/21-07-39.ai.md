This is a follow-up discussion in the completed ODB abstraction thread about flag usage in `odb_has_object()`. The original patch from Patrick Steinhardt fixed incorrect `OBJECT_INFO_FOR_PREFETCH` flags being passed to `odb_has_object()` in `fill_missing_blobs()`, where the function expects `HAS_OBJECT_*` flags instead. While the code happened to work due to coincidental bit patterns, Derrick Stolee confirms this was dangerous and supports removing the flags entirely. Junio Hamano chimes in to acknowledge both contributors' work on this fix.

The exchange serves as a post-merge validation of the earlier patch series, with Stolee's review confirming the technical analysis and solution. This particular issue is now resolved, while the broader thread continues exploring enum type safety considerations for future ODB work. The discussion demonstrates how even after patches are merged, the mailing list serves as a venue for validating solutions and building consensus around implementation details.
