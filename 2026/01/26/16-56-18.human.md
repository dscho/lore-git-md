This is a performance optimization for the Git test suite, specifically targeting the setup phase of the `p3400-rebase.sh` performance test. The patch replaces a slow shell loop that generates test commits with a faster `git fast-import` approach.

The current implementation uses a shell loop to create 100 commits, each containing a file with 1000 lines of generated content. This involves repeatedly calling `test_seq`, `sort`, and Git commands, which adds significant overhead. The new version precomputes the file contents once and streams all commits through `fast-import`, cutting the setup time from 29 seconds to 18 seconds (a 38% improvement) on the author's test system.

The change is well-motivated - performance test setup should ideally be fast so it doesn't skew the actual measurements. The implementation looks straightforward: it keeps the same commit structure and file contents, just generates them more efficiently. The commit message clearly shows the before/after timing and explains the approach.

As an RFC (Request For Comments), this appears ready to move forward as a non-controversial optimization. The only question might be whether the `fast-import` approach is maintainable compared to the more readable shell loop, but the performance gain seems worth the tradeoff for a performance test where setup time matters.
