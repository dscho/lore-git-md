This is a follow-up discussion in an ongoing thread about Amisha Chhajed's RFC patch series introducing `string_list_sort_u()`, a combined sort-and-deduplicate utility for Git's string-list API. Junio Hamano is responding to the second patch in the series, which mechanically converts existing call sites to use the new function.

Junio identifies two remaining callers of `string_list_remove_duplicates()` that weren't converted in the series, both of which he flags as potentially problematic. The first is in `builtin/fetch.c`, where duplicates are removed from an unsorted list of remotes - Junio notes this violates the function's preconditions and suggests adding a test to demonstrate the issue. He also raises concerns that sorting before deduplication might change the expected remote processing order. The second questionable caller is in `builtin/help.c`, where Junio suspects the list might become unsorted after key munging, again making deduplication unsafe.

The response indicates the series is making good progress (Junio doesn't object to the core implementation) but surfaces two edge cases that need investigation before finalizing the API change. Junio's comments suggest the next steps should be: 1) writing tests to confirm the behavior of these edge cases, and 2) deciding how to handle them - whether to fix the callers, modify the API contract, or document the limitations. The thread remains in RFC state while these questions are resolved.
