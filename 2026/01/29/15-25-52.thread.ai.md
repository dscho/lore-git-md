Thread introduces `@{default}` shorthand for repository's default branch (typically "main" or "master"), following pattern of existing shorthands like `@{upstream}`. Initial patch from Harald Nordgren adds `branch_get_default_ref()` resolving default branch via `init.defaultBranch` config (falling back to "main"/"master"), with integration into revision parsing and updated docs/tests.

Junio Hamano raised design concerns: questioned per-branch syntax (now rejected by author) and noted edge cases where configured default name might mismatch actual branches. Harald provided workflow examples showing utility when working across repositories with different default names (`master`, `main`, `develop`), but testing revealed widespread issues - many repositories have `init.defaultBranch` values that don't match any existing branch (due to renaming, deletion, or non-standard initialization). This concrete problem strengthens Junio's skepticism about edge cases.

Core tension remains between Junio's view that default branch naming should be standardized globally versus Harald's case for handling multiple conventions. Technical implementation is now limited to repository-wide `@{default}` (no per-branch syntax), but the discovered prevalence of config/branch mismatches raises new doubts about real-world reliability. Open questions: whether fallback behavior could be improved, whether the feature's utility justifies its fragility in mismatched cases, and if the problem space might better be addressed through improved branch naming hygiene rather than new syntax. Discussion continues with these newly surfaced practical concerns.
