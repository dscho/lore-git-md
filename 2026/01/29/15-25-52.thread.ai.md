Thread introduces `@{default}` shorthand for repository's primary branch, with initial implementation resolving via `init.defaultBranch` config (falling back to "main"/"master"). After v2 addressed Junio Hamano's concerns about per-branch syntax and added branch existence verification, Junio now raises deeper objections to the config-based approach, arguing it is unreliable due to:

1. Frequent mismatches between configured default names and actual branches (from renaming or non-standard initialization)
2. Better indicator being remote's HEAD (refs/remotes/origin/HEAD) in cloned repositories
3. Potential naming confusion between initialization behavior (`@{default}`) and current primary branch status

Junio proposes alternative syntax (`@{primary}` or `@{dumbo}`) modeled after `@{push}` that would track remote HEAD instead of local config. Core tension remains between Harald Nordgren's goal of simple shorthand and Junio's insistence on semantic precision for real-world cases where local/remote branch names diverge from initialization defaults. Open questions include whether to:
- Redesign around remote HEAD tracking
- Rename the feature to better reflect actual behavior
- Reconsider if the problem space might better be addressed through improved branch naming hygiene rather than new syntax
