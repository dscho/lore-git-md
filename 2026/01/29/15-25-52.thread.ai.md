Thread introduces `@{default}` shorthand for repository's default branch (typically "main" or "master"), following pattern of existing shorthands like `@{upstream}`. Initial patch from Harald Nordgren adds `branch_get_default_ref()` resolving default branch via `init.defaultBranch` config (falling back to "main"/"master"), with integration into revision parsing and updated docs/tests.

Junio Hamano raised design concerns about per-branch syntax (now rejected in v2) and edge cases where configured default name might mismatch actual branches. Testing revealed widespread issues - many repositories have `init.defaultBranch` values that don't match any existing branch (due to renaming, deletion, or non-standard initialization). The v2 iteration restricts syntax to repository-wide use and adds more test coverage, with `branch_get_default_ref()` now verifying branch existence before returning.

Core tension remains between Junio's view that default branch naming should be standardized globally versus Harald's case for handling multiple conventions. The implementation fails gracefully when config/branch mismatches occur, but their prevalence raises doubts about real-world reliability. Open questions persist about whether fallback behavior could be improved, if the feature's utility justifies its fragility in mismatched cases, and if the problem space might better be addressed through improved branch naming hygiene rather than new syntax. Discussion continues with these practical concerns now better documented through testing.
