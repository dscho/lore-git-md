Thread introduces `@{default}` shorthand for repository's default branch (typically "main" or "master"), following pattern of existing shorthands like `@{upstream}`. Initial patch from Harald Nordgren adds `branch_get_default_ref()` resolving default branch via `init.defaultBranch` config (falling back to "main"/"master"). Implementation integrates with existing branch mark handlers in revision parsing, with updated docs/tests.

Junio Hamano raises substantive concerns about design and utility: questions per-branch syntax (`<branch>@{default}`) since default branch is repository-wide, not branch-specific; notes edge cases where configured default name might mismatch actual branches (e.g. after manual renaming); expresses skepticism about real-world need given most users standardize default branch names globally rather than needing per-repo resolution. Implementation appears technically sound but faces conceptual challenges around resolution behavior. Discussion ongoing with no resolution yet - feature may need stronger motivation to justify inclusion. Key open questions: whether shorthand should exist at all given Junio's concerns, and if so, what exact semantics should handle edge cases.
