Git-gui bugfix addressing tab alignment in diff viewer, now ready for merge after thorough review. This final version resolves a long-standing inconsistency where git-gui's diff display misaligned tabs compared to gitk, particularly on Windows with Tcl/Tk 8.6. The solution applies different tabstop offsets (1 for regular diffs, 2 for combined diffs) to compensate for diff markers in the first column, matching gitk's behavior since 2007.

The patch follows maintainer Johannes Sixt's guidance to use Tk's native `apply_tab_size` configuration rather than text conversion, preserving the staging interface functionality. It handles all primary contexts (regular/combined/untracked diffs) while explicitly excluding octopus merges from scope. Junio Hamano provided commit message guidance to clarify the historical context and rationale.

Key technical points:
- First column always contains diff markers (never tabs)
- gitk's tabstops (9,17,25,...) remain the reference
- One-line change applies tab size before inserting diff lines
- Preserves all staging functionality while fixing alignment
