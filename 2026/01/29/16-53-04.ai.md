This is a bugfix for the histogram diff algorithm in xdiff, addressing an edge case where shifted change groups during compaction produce redundant matching lines in the diff output. The patch is part of an ongoing thread where technical concerns have been largely resolved, with consensus reached on the approach.

The fix adds logic in `xdl_change_compact()` to detect when shifting creates new matching groups, then re-diffs those sections using Myer's algorithm via `xdl_fall_back_diff()` while preserving all original diff flags (including `--ignore-all-space` handling). The implementation has been refined based on feedback - checking only one group rather than both, using safer memory handling patterns, and moving the new logic into a helper function for clarity as Junio suggested.

Phillip Wood confirmed that completely disabling group shifting (as initially considered) would be worse, preventing useful coalescing of changed lines and interfering with the indent heuristic. He also observed that histogram diff sometimes produces harder-to-read diffs than patience diff as an inherent characteristic, though this patch doesn't address that broader issue.

The commit message provides clear motivation with abstract/concrete examples, noting this affects <1% of diffs but fixes clearly undesirable output when it occurs. Test coverage in t4073-diff-shifted-matched-group.sh verifies the fix across scenarios. The patch appears ready for merging with only minor implementation refinements remaining.
