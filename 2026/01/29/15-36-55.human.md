This is a bugfix and i18n patch for `git show-index`, part of an ongoing thread about hash algorithm detection and repository-global variable usage. Shreyansh Paliwal addresses the silent SHA-1 fallback behavior when `show-index` runs outside a repository by adding a warning message, while also internationalizing error messages with `_()` wrappers.

The patch modifies `builtin/show-index.c` to warn when falling back to SHA-1 without explicit `--object-format` specification, making the implicit assumption visible to users. All error messages are wrapped for translation, improving accessibility. The changes are straightforward and focused, touching only the user-facing output while maintaining existing functionality.

This follows previous discussion where Patrick Steinhardt advocated for removing automatic detection entirely, while Junio Hamano suggested structural improvements. The current compromise maintains backward compatibility while making the behavior more transparent. The patch leaves room for future index format changes (mentioned in a TODO comment) that could provide a more robust solution than size-based guessing.

The changes are uncontroversial and well-contained, addressing two distinct but related quality-of-life issues in the command. The warning provides immediate clarity while the i18n work aligns with broader project standards.
