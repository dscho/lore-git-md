This is a cover letter for a two-patch series improving advice messages in `git switch` when dealing with ambiguous remote branch names. The series follows up on feedback from Simon Cheng, who noticed that `git switch` was suggesting `git checkout --track` in its advice when it should have suggested `git switch --track` instead.

The first patch (already discussed in the thread) refactors the checkout/switch/restore command infrastructure to pass an enum rather than strings through the call chain, setting up for the behavior change. The second patch now uses that enum to provide command-specific advice - when the failure occurs during `git switch`, it will suggest `git switch --track` rather than `git checkout --track`.

Junio notes this version incorporates Kristoffer Haugsbakk's feedback by simplifying some test assertions and rewording the commit message. The changes are well-contained, touching only the advice message generation while maintaining thorough test coverage. The series demonstrates Git's typical pattern of separating refactoring (patch 1) from behavior changes (patch 2), resulting in a clear user experience improvement that makes the advice more consistent with the command actually used.
