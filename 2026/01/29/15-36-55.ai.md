This is a bugfix and i18n patch for `git show-index`, part of an ongoing thread about hash algorithm detection in repository-less contexts. Shreyansh Paliwal addresses the silent SHA-1 fallback behavior when `show-index` runs outside a Git repository by adding a warning message. The patch also internationalizes error messages with `_()` wrappers for translation.

The change makes explicit what was previously an implicit assumption - that SHA-1 is the default hash algorithm when no repository context exists. The warning nudges users toward explicitly specifying `--object-format` when needed, while maintaining backward compatibility. This implements the middle ground Shreyansh proposed earlier in the thread, between Patrick Steinhardt's preference for keeping silent fallback and Brian m. carlson's longer-term index format solution.

The implementation touches `builtin/show-index.c`, adding the warning and converting all error messages to use `_()`. The patch is narrowly focused on these two improvements while leaving the deeper questions about index format changes and hash detection for future work. It represents a pragmatic step forward in the transition to hash-algorithm-agnostic tooling, with clear technical boundaries and uncontroversial i18n improvements.
