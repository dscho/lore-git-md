This is a follow-up code simplification to Patrick Steinhardt's bisect ref-handling fix. Jeff King points out that the string_list memory management in the bisect cleanup code can be made simpler and more consistent.

The patch changes the refs_for_removal string_list initialization from NODUP to DUP mode, eliminating manual string duplication and cleanup. This works because the ref names are now passed directly from the ref iteration (via xstrdup) rather than being formatted. The change removes redundant memory handling while maintaining the same functionality.

Jeff notes this simplification was possible even before Patrick's changes but became particularly clean after them. The patch touches only bisect.c, modifying the string_list usage pattern to let the container handle allocations automatically. This is a straightforward improvement that builds on the already-reviewed ref iteration fixes.
