This is a technical discussion about refactoring the object database (ODB) transaction infrastructure, part of the ongoing ODB abstraction effort led by Patrick Steinhardt with Justin Tobler implementing this specific work. The exchange focuses on patch 1/4 in a series that prepares for pluggable ODB backends to handle transactions differently while sharing common logic.

Patrick Steinhardt raised an architectural concern about whether the transaction directory creation should be tied to the repository's object directory (current behavior) or made truly source-agnostic by refactoring `tmp_objdir_create()` to accept an ODB source rather than a repository. Justin Tobler agrees with this direction and plans to address it in the next version with a preparatory commit that modifies `tmp_objdir_create()` before proceeding with the rest of the series.

The discussion reveals an important design consideration for future extensibility: while the current implementation works correctly for the existing single-source case, making the temporary directory handling properly source-aware would better support future non-filesystem backends that wouldn't need filesystem transactions at all. This is a typical example of the careful architectural thinking that characterizes the ODB abstraction work, where each change must balance immediate needs against long-term flexibility.
