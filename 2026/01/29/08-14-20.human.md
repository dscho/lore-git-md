This is a follow-up code simplification to Patrick Steinhardt's bisect ref-handling fix. Jeff King points out that the string_list memory management in the bisect cleanup code can be made simpler and more straightforward. 

The original patch had used a NODUP string_list with manual string allocation, then toggled strdup_strings just for cleanup. Jeff's proposed simplification uses STRING_LIST_INIT_DUP from the start, letting the string_list handle all allocations automatically. This makes the code more maintainable while preserving the same functionality.

The change is small and focused - just 6 lines changed in bisect.c - and builds on the refactoring work Patrick already did to fix the ref iteration. Jeff notes this could have been done even before Patrick's changes, but Patrick's switch to xstrdup() makes it particularly clean now.

This appears to be a straightforward improvement that follows naturally from the thread's earlier work. The technical approach looks sound, and since it's a cleanup of recently changed code, it's unlikely to introduce new issues. The patch maintains all existing functionality while making the memory handling more idiomatic.
