This is a bugfix patch for git-gui that addresses tab alignment inconsistencies in the diff viewer between git-gui and gitk on Windows with Tcl/Tk 8.6. The patch follows up on earlier discussion where a text conversion approach was rejected in favor of using Tk's native `apply_tab_size` configuration.

Junio Hamano provides review feedback on the commit message, suggesting more precise wording to clarify that the issue specifically affects diff views (not plain file views) due to the +/- markers consuming the first column. He also points out that gitk handles octopus merges (more than two parents) while git-gui currently assumes two-parent merges, though he considers that out of scope for this fix.

The technical solution involves setting tabstops at offset positions (1 for regular diffs, 2 for combined diffs) to compensate for the diff markers. Testing has confirmed this works across all diff states while preserving staging functionality. The patch appears ready for final review from maintainer Johannes Sixt, with minor commit message adjustments per Junio's suggestions.

While the issue has existed for nearly two decades without major complaints, the solution aligns with gitk's long-standing behavior and provides a clean fix for the Windows Tcl/Tk environment. The patch is small and focused, touching just one line in diff.tcl to apply the tab size adjustment before inserting lines.
