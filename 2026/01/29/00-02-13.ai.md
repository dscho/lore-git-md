This is a bugfix patch addressing tab alignment in git-gui's diff viewer on Windows with Tcl/Tk 8.6, making it consistent with gitk's behavior. The patch is part of an ongoing thread where previous approaches were rejected for breaking staging functionality.

Junio Hamano provides detailed feedback on the commit message, suggesting clearer wording to explain that the tabstop adjustment compensates for the leftmost column being used by diff markers (+/-). He notes gitk handles this by shifting tabstops - by 1 column for regular diffs and 2 for merge diffs - and recommends git-gui follow the same pattern. The implementation already accounts for regular diffs (offset 1) and combined diffs (offset 2), matching gitk's behavior since 2007.

The patch itself is minimal - a one-line change to apply tab size adjustment before inserting diff lines. Junio points out this doesn't yet handle octopus merges (more than 2 parents) but considers that out of scope for this fix. The thread shows consensus forming around this technical approach after earlier rejections, with the maintainer now clearly specifying the expected behavior.
