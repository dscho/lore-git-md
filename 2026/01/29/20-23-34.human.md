This is a feature proposal introducing a `@{default}` shorthand for referring to a repository's default branch, similar to existing shorthands like `@{upstream}`. The patch comes from Harald Nordgren, with Junio Hamano providing initial feedback.

Junio raises several thoughtful concerns about the design. He questions whether the per-branch syntax (`<branch>@{default}`) makes sense since the default branch is repository-wide, not branch-specific. He also points out edge cases where the configured default branch name might not match any existing branch (like after a rename), and wonders about practical utility given users typically standardize their default branch names globally.

The implementation appears technically sound but may need to address these semantic questions. Junio's feedback suggests the feature might need refinement around error cases and syntax before proceeding. This isn't a rejection, but signals the proposal needs stronger motivation and clearer handling of edge cases to justify adding a new syntax to Git's revision parsing.

For now, this remains an open discussion - the next steps would be for the original author to respond to these concerns, either by adjusting the design or providing more compelling use cases. The patch touches revision parsing, branch handling, and documentation, but may need revisions based on this feedback.
