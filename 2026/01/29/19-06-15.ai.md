Refactoring patch in Junio Hamano's series to standardize command-specific behavior in checkout/switch/restore commands.

This is the first of two patches that improve how `git switch` handles ambiguous remote branch names. It introduces an internal refactoring to track which command (`checkout`, `switch`, or `restore`) is being executed, replacing the previous string-based approach with an enum. The change is purely mechanical at this stage - the enum is only used to select the appropriate usage string, maintaining identical external behavior.

The patch moves the usage strings inside `checkout_main()` and adds a new `enum checkout_command` to distinguish between the three front-end commands. Each command entry point (`cmd_checkout`, `cmd_switch`, `cmd_restore`) now passes its corresponding enum value rather than a usage string. This sets up the infrastructure for the second patch, which will use the enum to customize advice messages based on the actual command being run.

The changes are well-contained to `builtin/checkout.c` and follow Git's standard practice of separating refactoring from behavior changes. The patch has already been reviewed by Kristoffer Haugsbakk in the thread, with minor test-related suggestions that were incorporated. This is a clean preparatory change that enables the more user-visible improvement in the following patch.
