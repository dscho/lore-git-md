This is a feature patch from Derrick Stolee adding a `--maximal-only` option to `git rev-list`, now in its second iteration with full consensus from Junio C Hamano and other reviewers. The option filters commit output to show only those that are maximal in the reachability order (not reachable from any other commit in the input set), which is useful for bundle URI selection and bitmap optimizations.

The thread has reached clear agreement on both the implementation and long-term direction. Junio confirms this should eventually replace the existing `--independent` flag in other commands like `git show-branch` and `git merge-base`, though that migration will happen in future work. The key technical distinction is that `--maximal-only` properly handles negative revisions while maintaining the same core filtering behavior for positive-only cases.

Stolee provides a detailed example showing how maximal commits differ from merely independent sets in complex graphs, solidifying the naming choice. The implementation uses bit 28 in revision.c's flag space and includes comprehensive tests covering edge cases. With all feedback addressed and Junio's approval, this appears ready for merging as part of Git's ongoing reachability optimization efforts.
