This is a bugfix patch for git-gui that corrects tabstop alignment in the diff viewer. The issue caused tabs to appear misaligned compared to gitk when viewing diffs, particularly on Windows with Tcl/Tk 8.6. The patch follows a discussion thread where the maintainer Johannes Sixt initially rejected a text conversion approach but ultimately approved this configuration-based solution.

The fix adjusts tabstops to account for the first column of context diffs (which contains +/- markers) by applying different offsets: 1 for regular diffs (compensating for the single diff marker), 2 for combined diffs (handling 3-way merge markers), and 0 for untracked files. This matches gitk's behavior that has been in place since 2007. The patch preserves all staging functionality while making the visual alignment consistent with gitk.

The thread revealed this was a long-standing but low-priority issue - present for nearly two decades without significant complaints - that primarily impacts code review workflows. The solution is now considered complete after addressing edge cases and receiving maintainer approval, with only final commit message polishing remaining before merging.
