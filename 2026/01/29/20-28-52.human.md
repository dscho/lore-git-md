This is a technical discussion about the ongoing ODB (object database) abstraction effort, specifically around transaction handling for pluggable backends. Junio C Hamano weighs in on Justin Tobler's observation that temporary object directory management (`tmp_objdir`) could be better handled through the ODB transaction abstraction rather than as a separate mechanism.

Junio strongly agrees with Justin's assessment that managing temporary objects through transaction semantics ("prepare/commit/abort") is the right level of abstraction, rather than directly exposing temporary directory creation. He notes that the current three users of `tmp_objdir` (remerge-diffs, receive-pack, and ODB transactions) would all be better served by using the transaction interface, even if some cases (like remerge-diffs) would always abort the transaction.

This email represents an important conceptual alignment between Junio (as maintainer) and Justin (implementing the ODB changes) on the architectural direction. The discussion suggests the transaction abstraction is maturing to the point where it can subsume lower-level mechanisms like direct tmpdir management. This moves the ODB abstraction effort forward by clarifying how temporary object handling should work across different storage backends.
