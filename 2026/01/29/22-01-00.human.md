This is an update on the SHA-1/SHA-256 interoperability work, part of the ongoing Rustification effort in Git. brian m. carlson responds to Junio Hamano's query about CI breakages in their 15-part Rust-based series that introduces object ID mapping between hash algorithms.

The author has identified the root cause of the Windows CI failures: a PATH conflict where both MSVC and MSYS linkers are named `link.exe`, with the MSYS version taking precedence when building with Rust against MSVC. This occurs because the Git for Windows SDK installation likely puts the MSYS linker first in PATH. While they haven't yet resolved the issue (having not gotten a Windows VM working), they confirm they're working on a patch to address this and will send it once CI passes.

This technical hurdle represents one of the final blockers for this complex series that touches core object-handling infrastructure. The problem illustrates the platform-specific challenges that arise when introducing Rust into Git's build system, particularly on Windows where toolchain interactions can be subtle. The fix will need to carefully handle linker selection without disrupting existing Git for Windows workflows.
