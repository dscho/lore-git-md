This is a technical discussion about the ongoing ODB (object database) abstraction effort, specifically addressing patch 3/4 in a series preparing transaction handling for pluggable backends. Patrick Steinhardt provides review feedback on Justin Tobler's patch that splits the transaction structure into generic and backend-specific parts.

Patrick suggests improving the patch's wording to clarify that transactions handle "generic" sources rather than implying support for multiple sources simultaneously. He questions whether the transaction structure should be specific to loose objects backend or the broader "files" backend, noting that packfiles are also involved in the current implementation. The discussion reveals an architectural detail - while the patch moves loose-object-specific functionality into `struct odb_transaction_loose`, the transaction handling still interacts with packfiles through `prepare_packfile_transaction()`.

The exchange highlights the careful balance required in this refactoring: making structures generic enough for future backends while maintaining current behavior. Patrick confirms the technical approach of splitting the transaction structure and notes that some functions can become private once the indirection through function pointers is in place. This is part of the larger pattern in the ODB abstraction work where public interfaces are being converted to vtable-style operations.
