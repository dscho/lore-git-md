This is a technical discussion about object database (ODB) transaction handling, part of the ongoing ODB abstraction effort. Justin Tobler responds to feedback from Junio C Hamano and Patrick Steinhardt about how temporary object directories should interact with the new ODB source-aware transaction infrastructure.

The key points center around `tmp_objdir_create()`, which currently creates temporary directories in the repository's object directory. Junio notes this may not suit future non-filesystem ODB backends, while Patrick had suggested making it source-aware. Justin observes that all current tmpdir users (remerge-diffs, receive-pack, and ODB transactions) could potentially use ODB transactions directly instead of managing tmpdirs themselves. He also notes the process-wide `the_tmp_objdir` global suggests per-source configuration may be overkill, especially since only the files backend would use it.

Justin proposes an alternative path: making tmpdir management an internal detail of the files backend's transaction implementation, passing the concrete files source rather than the repository. This would keep the abstraction clean for future non-filesystem backends while simplifying the current implementation. The discussion reveals architectural considerations for how transaction handling should evolve to support pluggable backends, with consensus that the current approach works for now but may need adjustment for more exotic storage backends.
