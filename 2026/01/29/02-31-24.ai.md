Taylor Blau raises important considerations about the behavior of `pack.preferBitmapTips` when matching exact refs versus ref prefixes. This is a follow-up to Patrick Steinhardt's patch that fixed a BUG() when using exact ref matches, where Taylor questions whether the current matching semantics (where "refs/heads/base" would match both itself and "refs/heads/base-something") are desirable.

Taylor notes this behavior contradicts the direction taken in commit 10e8a9352bc, which stopped matching non-directory prefixes in exclude patterns. He suggests the interface should either be made consistent with that change or at minimum documented in git-config(1). He also points out that the configuration doesn't guarantee all specified tips will receive bitmaps due to the chunked selection algorithm in `bitmap_writer_select_commits()`.

This email doesn't propose concrete changes but flags an inconsistency in the ref-matching behavior that warrants discussion. The thread has already seen technical approval from Karthik Nayak, but Taylor's comments suggest there may be design considerations around the user-facing behavior that should be resolved before merging. The discussion touches on both technical correctness (the original BUG() fix) and interface design (how ref matching should work), with the latter being the new point raised here.
