This is the second patch in Junio Hamano's series to improve `git switch` advice messages when encountering ambiguous remote branch names. The patch modifies the advice text to match the command being used (`checkout` or `switch`) rather than always suggesting `git checkout --track`.

The key change passes the `which_command` enum (added in patch 1) through to `parse_remote_branch()`, where it selects the appropriate command name for the advice message. The patch also adds new test cases that verify both `checkout` and `switch` produce the correct command-specific messages when failing to DWIM (Do What I Mean) with ambiguous branch names.

The implementation is clean and focused - it touches only the advice message generation while maintaining thorough test coverage. The changes demonstrate Git's approach to cleanly separating refactoring (done in patch 1) from behavior changes. This results in more consistent user experience by matching advice to the actual command used.

The patch follows up on feedback from Simon Cheng about confusing advice messages, showing how Git's advice system can be made more context-aware. The test additions help ensure this behavior remains correct going forward.
