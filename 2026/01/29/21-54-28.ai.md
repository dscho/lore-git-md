This is a technical follow-up in the ongoing ODB abstraction effort, specifically addressing transaction handling for pluggable object database backends. Justin Tobler responds to Junio C Hamano's strong agreement with his earlier observation that temporary object directory (`tmp_objdir`) management could be better handled through the ODB transaction API rather than direct `tmp_objdir_create()` calls.

The exchange confirms consensus on moving from low-level temporary directory management to higher-level transactional semantics. Justin notes three current users of `tmp_objdir_create()` (remerge-diffs, receive-pack, and ODB transactions) that could potentially switch to using ODB transactions directly, with remerge-diffs specifically needing abort-only transactions. He defers this refactoring to a future series, keeping the current patch series focused on the core ODB transaction infrastructure changes.

This email represents architectural alignment between Justin and Junio on the direction of the ODB transaction work, with Justin planning to address the temporary directory unification in subsequent work. The discussion builds cleanly on prior patches that restructured transaction handling to support different ODB backends while maintaining the files backend's existing behavior.
