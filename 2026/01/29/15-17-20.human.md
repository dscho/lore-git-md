This is a bugfix for git-gui's diff viewer, finalizing the solution to align tab display with gitk's behavior on Windows. The patch thread has reached consensus after thorough review, with all technical questions resolved.

The fix addresses a long-standing inconsistency where git-gui's tab alignment in diffs didn't match gitk's correct display, particularly noticeable on Windows with Tcl/Tk 8.6. The solution uses Tk's native `apply_tab_size` configuration with different offsets (1 for regular diffs, 2 for combined diffs) to account for diff markers while preserving all staging functionality.

Key points from the final discussion:
- The scope is confirmed to cover regular diffs, combined diffs, and untracked files, while explicitly excluding octopus merges (which git-gui doesn't display)
- gitk's tabstop behavior (in place since 2007) is accepted as the reference implementation
- Junio provided final guidance on commit message wording to document the diff marker compensation

The patch is now documentation-complete and ready for merging as a routine bugfix that improves workflow consistency between git-gui and gitk. While the issue existed for nearly two decades without major complaints, the fix is considered worthwhile for aligning behavior with gitk's established precedent.
