This is a technical discussion about object database (ODB) transaction handling, part of the ongoing ODB abstraction effort. The email from Junio C Hamano responds to Patrick Steinhardt's review of Justin Tobler's patch that prepares for pluggable ODB backends by making transactions source-aware rather than ODB-aware.

Junio agrees with Patrick's observation that the current implementation still ties transactions to the repository's object directory, even after the refactoring. He notes this doesn't affect current behavior since only the primary object source is used, but raises a forward-looking concern: future non-filesystem-based ODB backends wouldn't need filesystem temporary directories at all. For multiple filesystem-based sources sharing a repository, Junio suggests the current approach might be acceptable as long as sources don't cross-contaminate their transaction directories.

The exchange shows the maintainer thinking through the long-term architectural implications of the change, balancing immediate needs against future flexibility. While not blocking the current series, it surfaces an area that may need attention when implementing alternative backends. The tone is collaborative, with Junio validating Patrick's technical concern while offering a pragmatic perspective on when the current limitation might remain acceptable.
