This is a follow-up bug report about a test failure in the recently merged `git last-modified` series. The issue appears when running the tests under Meson on Windows, where the output format differs from expectations - specifically, a file modification timestamp is being replaced with a tag name (`t2^0`) in the expected output.

The failure occurs in the recursive mode test case where the command checks modification times across a directory structure. While the series was already merged with Junio's approval, this Windows-specific behavior wasn't caught during review. The error suggests either a platform-specific output formatting difference or a subtle bug in how the command handles tag references on Windows.

The patch author (Toon Claes) is reporting this as a known issue that should be addressed separately, noting it's better to leave the failing test out of the Windows/Meson build for now. This appears to be a relatively minor post-merge cleanup item rather than a fundamental flaw in the series.
