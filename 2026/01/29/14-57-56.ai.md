This is a feature patch from Derrick Stolee adding the `--maximal-only` option to `git rev-list`, now in its second version with final conceptual alignment from Junio C Hamano. The thread has reached full consensus and is effectively concluded.

The patch introduces a new option to select "frontier" commits - those maximal in reachability order - which is particularly useful for bundle URIs and bitmap optimization. Junio has confirmed this as the canonical approach moving forward, with `--maximal-only` intended to eventually replace the existing `--independent` functionality across Git commands. The key technical differentiator is `--maximal-only`'s support for negative revisions, which `--independent` lacks.

Stolee provides a detailed example illustrating the distinction between "independent" and "maximal" commits in a graph, clarifying why "maximal" is the more precise term for this operation. The implementation uses bit 28 (`CHILD_VISITED` flag) in revision.c/commit.c and includes comprehensive tests covering various edge cases. Documentation has been updated with precise behavioral descriptions.

Junio has endorsed both the implementation and long-term direction, agreeing that future work can extend this to other commands like `git show` while maintaining `--maximal-only` as the preferred interface.
