This is the second patch in Junio Hamano's series improving `git switch` advice messages when encountering ambiguous remote branch names. The patch modifies the advice text to match the command being used (`checkout` or `switch`) rather than always suggesting `git checkout --track`.

The key change passes the `which_command` enum (introduced in patch 1) through to `parse_remote_branch()`, where it selects the appropriate command name for advice messages. When a branch name is ambiguous, the advice now suggests `git switch --track` for `switch` operations while maintaining `git checkout --track` for legacy `checkout` cases.

The patch adds test coverage verifying both commands produce correct advice, creating two test remotes with conflicting `trunk` branches to trigger the ambiguity case. The tests confirm the hint messages match the invoked command. The implementation is clean and focused, touching only the advice generation while maintaining the existing behavior for unambiguous cases.

This completes the series' goal of making `git switch`'s advice consistent with the command actually used, addressing Simon Cheng's report about confusing `checkout` suggestions during `switch` operations. The changes are well-contained within the checkout machinery and demonstrate Git's careful approach to maintaining backward compatibility while improving user experience.
