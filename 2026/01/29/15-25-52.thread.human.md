This thread introduces a proposed new `@{default}` shorthand for referring to a repository's default branch, similar to existing shorthands like `@{upstream}`. The initial patch from Harald Nordgren implements the feature with tests and documentation, providing a way to reference the default branch without hardcoding names like "main" or "master".

Junio Hamano, the Git maintainer, has raised several concerns in response. He acknowledges the technical implementation is sound but questions the fundamental design and utility. He points out that the per-branch syntax may not make sense since the default branch is repository-wide concept, not branch-specific. He also highlights edge cases where the configured default branch name might not match any existing branch. Most significantly, Junio expresses skepticism about the real-world need, noting most users standardize their default branch names globally rather than needing per-repository resolution.

The discussion is ongoing, and the feature's future remains uncertain. While technically well-implemented, it may need stronger justification to address Junio's concerns about its conceptual fit and practical usefulness in typical workflows. The author will likely need to either refine the proposal or provide compelling use cases to move forward.
