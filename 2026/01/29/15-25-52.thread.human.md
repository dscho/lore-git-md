This thread explores how Git should reference a repository's default branch, with two main syntax proposals on the table: `@{default}` (Harald Nordgren's original suggestion to resolve to origin/HEAD) and `@{local}` (Phillip Wood's alternative that finds the local branch pushing to a given tracking branch). The discussion has evolved through multiple iterations with Junio C Hamano carefully evaluating the technical merits, particularly around modifier chaining semantics (like `feature@{upstream}@{local}`) and whether additional "reverse" modifiers might be needed.

A recent exchange between Harald Nordgren and D. Ben Knoble highlighted another workflow dimension - some users prefer working with the default branch in detached-HEAD mode (via `git switch -d origin`) to avoid maintaining local tracking branches, even suppressing the detached-HEAD warning for this case. This reinforces that default branch access needs to accommodate both branch-attached and detached-HEAD workflows.

While the implementation approach is technically sound, the core debate remains unresolved. Junio continues to weigh whether the demonstrated use cases justify adding new syntax, with modifier chaining scenarios being a key consideration. The thread now awaits his evaluation of whether these needs warrant syntax additions, along with community feedback on the `@{default}` vs `@{local}` preference and resolution of remaining technical questions about fallback behavior and configuration overlap with `git var GIT_DEFAULT_BRANCH`.
