This thread discusses Harald Nordgren's proposal to add a `@{default}` shorthand for referring to a repository's default branch (like `main" or `master`), similar to existing shorthands such as `@{upstream}`. The initial implementation would resolve the default branch via the `init.defaultBranch` config, falling back to conventional names.

Junio Hamano raised important concerns about the design, questioning the need for per-branch syntax (since the default branch is repository-wide) and pointing out edge cases where the configured default name might not match actual branches. Harald agreed to drop the per-branch syntax but defended the feature's utility for working across repositories with different default branch conventions.

A new complication has emerged: Harald found that many repositories on his system don't properly recognize `@{default}` because their configured default branch names don't match any existing branches. This could happen if branches were renamed or if repositories were initialized with non-standard defaults. This practical issue strengthens Junio's earlier concerns about edge cases and suggests the shorthand might fail in more real-world scenarios than anticipated.

The discussion now centers on whether the feature's convenience outweighs these reliability concerns. While the technical implementation is sound, the discovery of widespread mismatch between configured and actual default branches raises questions about how useful the shorthand would be in practice. The thread remains open with no clear resolution yet on whether to proceed with the feature given these challenges.
