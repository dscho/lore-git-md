Harald Nordgren has proposed adding a `@{default}` shorthand to refer to a repository's default branch (typically "main" or "master"), similar to existing shorthands like `@{upstream}`. The initial version allowed per-branch syntax like `branch@{default}`, but Junio Hamano raised design concerns and this was removed in v2, which now only supports repository-wide `@{default}` usage.

The implementation checks the `init.defaultBranch` config (falling back to "main" or "master") and verifies the branch exists before resolving the reference. While technically sound, testing revealed a practical problem: many repositories have mismatched `init.defaultBranch` values that don't correspond to any existing branch, often due to branch renaming or deletion. This discovery has shifted the discussion - while the feature aims to help workflows across repositories with different default names, the prevalence of these mismatches calls into question how reliably it would work in practice.

Junio remains skeptical, seeing this as potentially encouraging poor branch hygiene rather than solving a real need. The thread is now weighing whether the feature's benefits outweigh its fragility when configs and branches don't align, and whether improving branch naming practices might be a better solution than adding new syntax.
