This is a technical discussion about object database (ODB) transaction handling, part of the ongoing ODB abstraction effort. Junio C Hamano weighs in on Justin Tobler's proposal to make temporary object directory (`tmp_objdir`) management an internal implementation detail of the files backend's transaction handling rather than exposing it as a separate API.

Junio strongly agrees with Justin's observation that the current three users of `tmp_objdir_create()` (remerge-diffs, receive-pack, and ODB transactions) would be better served by using the ODB transaction abstraction directly. He frames this as moving from a low-level "give me a temporary directory" API to the higher-level operations of beginning a transactionally-safe object creation session, then either committing or aborting it.

The exchange suggests consensus is forming around making `tmp_objdir` an internal implementation detail of the files backend's transaction support, which would simplify the API surface and better encapsulate the filesystem-specific aspects of temporary object handling. This aligns with the series' goal of making the ODB layer properly abstract while maintaining existing behavior for the files backend.

Junio's approval of this direction carries significant weight as maintainer, indicating the architectural approach is sound. The discussion appears to be converging toward a solution that will likely be incorporated into the next version of the patch series.
