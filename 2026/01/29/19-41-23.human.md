This is part 3 of a 4-patch series refactoring Git's object database transaction handling to support pluggable backends, part of the ongoing ODB abstraction effort led by Patrick Steinhardt with Justin Tobler contributing this work.

The patch splits the transaction structure into a generic base (`struct odb_transaction`) containing common fields and a function pointer, and a backend-specific implementation (`struct odb_transaction_loose`). Patrick Steinhardt suggests renaming the latter to `odb_transaction_files` since it handles both loose objects and packfiles, which Justin agrees with for the next version. There's also discussion about better explaining the motivation for making transactions source-specific in the commit message.

The changes maintain existing behavior while making the architecture more flexible for future backends. The implementation appears sound, with Patrick offering only minor wording suggestions and one naming clarification. Justin plans to address these points in the next revision, indicating this series is in its final polishing phase before potential merging.
