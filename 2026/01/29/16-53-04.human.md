This is a bugfix for the histogram diff algorithm in xdiff, addressing an edge case where shifted change groups during compaction produce redundant matching lines in the diff output. The patch is now in its final review stage after addressing feedback from Junio C Hamano and Phillip Wood.

The fix detects when shifting creates new matching groups and re-diffs those sections using Myer's algorithm while preserving all original diff flags. This maintains the compaction benefits of histogram diff while avoiding the problematic edge case. Phillip Wood confirmed that completely disabling group shifting would be worse, as it would prevent useful coalescing of changed lines and interfere with the indent heuristic.

The discussion revealed some interesting nuances about diff algorithms - notably that histogram diff sometimes produces harder-to-read diffs than patience diff as an inherent characteristic, despite being marketed as an "improved" version. The patch authors have addressed all technical concerns, including memory safety improvements and code organization suggestions from Junio.

This appears to be a well-considered fix for a subtle edge case that affects less than 1% of diffs. The thread has reached consensus and the patch is likely to be merged soon in its next iteration.
