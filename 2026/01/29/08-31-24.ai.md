This is a bugfix thread for git-gui addressing tab alignment inconsistencies in the diff viewer. Chris Idema responds to Junio Hamano's feedback about the severity of the issue, clarifying that while calling it a "show stopper" may have been overstated, the misalignment does impact real-world code review workflows where git-gui is preferred for reviewing multi-file changes. 

The email confirms the proposed solution using Tk's `apply_tab_size` works across all diff states (modified, staged, merge conflicts, untracked files) with appropriate offsets (1 for regular diffs, 2 for merges, 0 for untracked files). Chris notes this matches gitk's long-standing behavior and provides a practical workaround for git-diff's tab configuration. 

The thread shows the patch is now well-tested and addresses all identified use cases, though Chris seeks clarification on handling octopus merges (>2 parents) which Junio had mentioned as a potential edge case. The discussion has moved from technical debate to final implementation details, with the solution approach now clearly validated against gitk's precedent.
