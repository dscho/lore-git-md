This is a bugfix thread for git-gui addressing tab alignment inconsistencies in the diff viewer. The discussion has reached technical consensus on a solution that uses Tk's native `apply_tab_size` configuration to match gitk's behavior, after an earlier text conversion approach was rejected for breaking staging functionality.

Johannes Sixt (the git-gui maintainer) clarifies that octopus merges (with more than two parents) are not relevant for git-gui's diff display, since git-gui only handles the standard 3-way diff case between "theirs" and "ours" in the index. This answers Chris Idema's question about whether git-gui needs to handle more complex merge scenarios.

The thread shows the patch is nearly ready for merging, with all core functionality validated. The only remaining open question (about octopus merges) has now been resolved as out of scope for git-gui. The solution preserves the staging interface while fixing the tab alignment issue that impacts code review workflows, matching gitk's behavior that has been stable since 2007. Junio Hamano has provided guidance for the final documentation of the fix in the commit message.
