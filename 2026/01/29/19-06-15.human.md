This is a refactoring patch from Junio C Hamano that prepares the shared checkout/switch/restore implementation for more precise command-specific behavior. It's the first of a two-patch series aimed at improving advice messages when dealing with ambiguous remote branch names.

The patch introduces an `enum checkout_command` to track whether operations originate from `checkout`, `switch`, or `restore` commands, replacing the previous mechanism that passed usage strings. While this change doesn't yet modify any user-visible behavior, it sets up the infrastructure needed for the second patch to customize advice messages based on which command was invoked.

The implementation maintains all existing functionality while making the code more maintainable - the enum is used consistently across all three command entry points (`cmd_checkout`, `cmd_switch`, `cmd_restore`). This follows Git's standard practice of cleanly separating refactoring from behavior changes.

The changes are well-contained, touching only the checkout implementation while preserving the same external behavior. This is a typical preparatory patch that enables follow-on improvements while minimizing risk of introducing regressions.
