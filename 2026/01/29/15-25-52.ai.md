This is a feature patch introducing a new `@{default}` shorthand for referring to a repository's default branch (typically "main" or "master"). The patch follows the established pattern of similar shorthands like `@{upstream}` and `@{push}`.

The implementation adds a new `branch_get_default_ref()` function that resolves the default branch name by checking `init.defaultBranch` configuration, falling back to "main" (or "master" in older Git versions). The shorthand is integrated into the revision parsing logic alongside existing branch mark handlers. Documentation is updated to explain the new syntax, and tests are added to verify the behavior.

The motivation is clear: users frequently need to reference the default branch without hardcoding its name, especially when working across repositories with different default branch names. The patch provides a consistent way to do this, similar to how `@{upstream}` provides consistency for tracking branches.

The implementation appears straightforward and well-contained, touching only the necessary components (revision parsing, remote/branch handling, documentation, and test cases). The tests cover both the basic functionality and integration with existing features. This seems like a useful quality-of-life improvement that aligns with Git's existing conventions for branch references.
