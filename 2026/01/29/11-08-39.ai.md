This is a technical discussion about interface design for Git's object database (ODB) abstraction effort, specifically regarding how to expose backend-specific information to callers. Jeff King (Peff) responds to Patrick Steinhardt's earlier message about handling object modification times (mtimes) in the ODB interface.

The discussion centers on two potential approaches for exposing backend-specific details like filesystem paths and mtimes. Option 1 would provide an opaque context struct that callers pass back to the ODB for operations, keeping the interface clean but requiring more functionality to be pushed into the ODB layer. Option 2 would expose a set of potentially available information (like paths) that callers can query, putting more responsibility on callers to handle cases where information isn't available.

Peff expresses a leaning toward Option 2, arguing it keeps specialized logic together in the callers (like fsck and repack) rather than splitting it between callers and backends. He notes this is particularly important for operations that make subtle assumptions about object storage details. The discussion doesn't propose immediate changes to the current ODB series but explores design considerations that will influence future iterations of the interface.
