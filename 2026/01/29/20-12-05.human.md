This is a technical discussion about object database (ODB) transaction handling, part of the ongoing ODB abstraction effort. Justin Tobler responds to feedback from Junio C Hamano and Patrick Steinhardt about how temporary directories should be managed for filesystem-based ODB backends.

The key point under discussion is whether `tmp_objdir_create()` should be refactored to work with ODB sources rather than repositories, as currently it assumes filesystem-based storage. Justin observes that all current tmpdir users (remerge-diffs, receive-pack, and ODB transactions) could potentially use ODB transactions directly instead. He suggests making the tmpdir an internal detail of the files backend's transaction implementation.

Junio had raised concerns about non-filesystem backends not needing tmpdirs at all, while noting that multiple filesystem sources sharing a repository's tmpdir might be acceptable if they don't interfere. Justin agrees, pointing out Git already enforces a single tmpdir per process globally via `the_tmp_objdir`.

The exchange shows the careful balancing act in this refactoring - maintaining current behavior while designing for future extensibility. Justin appears to be converging on a solution that keeps tmpdir handling within the files backend's transaction code, which would satisfy both the immediate needs and future flexibility requirements. This discussion will inform the next version of his patch series.
