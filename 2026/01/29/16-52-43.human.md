This is a follow-up discussion in an ongoing thread about bitmap and bisect functionality when handling exact ref matches. Junio C Hamano responds to Taylor Blau's concerns about the semantics of `pack.preferBitmapTips` configuration.

Junio notes that while the current behavior of `bitmap_writer_select_commits()` is documented (it doesn't guarantee bitmaps for all specified tips due to chunking), the documentation lacks rationale for why this design was chosen. He suggests adding an explanation about how the chunking approach saves space by avoiding similar bitmaps for closely-related commits.

The discussion also touches on the potentially confusing wording in the documentation about "suffix" matching - Junio questions whether phrasing like "refs/heads/foobar" being a suffix of "refs/heads/foo" is the clearest way to describe the matching behavior. This appears to be the last remaining open question in the thread, as the technical aspects of the fix have already been approved by Karthik Nayak and Junio.

The exchange shows the project's attention to detail in both technical behavior and documentation clarity, with Junio weighing in on what would make for clearer user-facing explanations of the bitmap selection algorithm.
