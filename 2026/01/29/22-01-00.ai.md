This is a status update on the SHA-1/SHA-256 interoperability work, part of the ongoing Rustification effort. brian m. carlson responds to Junio Hamano's query about CI failures in their 15-part Rust-based series that introduces object ID mapping between hash algorithms.

The author has identified the root cause of the Windows CI failures: a PATH conflict where both MSVC and MSYS linkers are named `link.exe`, with the MSYS version taking precedence when building with Rust against MSVC. This occurs because the Git for Windows SDK installation likely puts the MSYS linker first in PATH. The author is working on a fix to ensure the correct linker is used.

This update represents progress on a critical blocker for merging this complex series, which introduces Rust wrappers for hashfile operations, a binary object map format, and cross-algorithm lookup infrastructure. The technical challenge intersects with platform compatibility concerns, particularly around Windows toolchain integration. The fix will need to address the build system's handling of competing linkers while maintaining compatibility with Git for Windows SDK installations.

The series remains important for Git's long-term hash algorithm flexibility, and resolving this Windows-specific build problem is the last known obstacle before the work can progress toward merging. The author indicates they will submit the fix once CI passes, suggesting the solution is understood and in progress.
