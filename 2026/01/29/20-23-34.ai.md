This is a feature proposal introducing a `@{default}` shorthand for referring to a repository's default branch, similar to existing shorthands like `@{upstream}`. The patch comes from Harald Nordgren and is now receiving feedback from Junio Hamano.

Junio raises several technical and practical concerns about the proposal. He questions whether the per-branch syntax (`<branch>@{default}`) makes sense since the default branch is repository-wide, not branch-specific. He also points out edge cases where the configured default branch name might not match any existing branch (e.g. after manual renaming). Most significantly, he expresses skepticism about the real-world utility, suggesting users typically control their default branch names globally rather than needing to query per-repository defaults.

The implementation appears technically sound but faces conceptual challenges around when and how the shorthand should resolve versus error out. Junio's feedback suggests the feature may need stronger motivation to justify its inclusion, particularly given his observation that most users standardize their default branch names globally rather than needing per-repository resolution. The thread is still in discussion phase with no clear resolution yet.
