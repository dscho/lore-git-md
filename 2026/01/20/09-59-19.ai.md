This is a bugfix patch from Karthik Nayak addressing an issue in reference verification during batched updates. The patch is part of a larger series (v3 1/6) focused on regression fixes for reference handling.

The core problem occurs in `refs_verify_refnames_available()` where nested loops check for filesystem conflicts. Currently, when a conflict is detected, the code uses `continue` which only skips the inner loop iteration, causing the same reference to be repeatedly rejected. The fix replaces this with a `goto` to properly skip to the next reference in the outer loop.

The patch makes several related changes:
1. Modifies the rejection handling to properly skip to the next reference
2. Adds storage for rejection details in the ref_update struct
3. Updates the rejection API to accept error details
4. Applies consistent changes across all ref backends (files, packed, reftable)

This appears to be a well-scoped fix with thorough coverage across all ref backend implementations. The changes are mechanical but important for correct behavior during batched reference updates. The patch follows Git's established patterns for reference handling and maintains consistency with existing error reporting mechanisms.
