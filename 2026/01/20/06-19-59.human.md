This is a bug report about a regression in `git fetch` output behavior introduced in Git 2.51. The reporter, Stepan Tsymbal from Atlassian, explains that their Bitbucket mirror synchronization system relies on parsing `git fetch` output to detect failed reference updates.

The key issue is that while Git 2.50 clearly showed which refs failed to update (particularly for directory/file conflicts), Git 2.51's batched reference updates no longer provide this information in the output. The reporter provides a clear reproduction case and asks whether this is the expected new behavior or if there are workarounds to identify failed refs.

This appears to be an unintended side effect of the batched reference updates feature (commit 0e358de) that improved performance but lost some error reporting fidelity. The reporter notes that even the reference-transaction hook doesn't help here as it lists all refs as committed.

The patch seems well-motivated and clearly explained, with a real-world impact on mirror synchronization systems. The reporter is seeking guidance on whether this is intentional and if there are alternative ways to get the failed ref information they need. This would likely be of interest to anyone using `git fetch` output parsing in automation.
