[Security] Discussion continues on ANSI escape sequence injection mitigation, focusing on security vs compatibility tradeoffs.

D. Ben Knoble enters the thread with a response to brian m. carlson's argument against default-enabled filtering of control sequences in Git's sideband channel. Knoble challenges the "other holes exist" reasoning, pointing out that security typically follows a "swiss cheese" model where multiple layers of protection are valuable even if no single layer is perfect. This counters carlson's position that since SSH and other tools allow similar behavior, Git shouldn't treat this as a security issue requiring breaking changes.

The exchange highlights the core tension in the thread: Patrick Steinhardt and Johannes Schindelin frame the control sequence filtering as a security fix (CVE-2024-32002, CVE-2024-52005) that should be enabled by default to prevent potential arbitrary code execution, while carlson maintains this is better handled as an opt-in feature to avoid breaking existing workflows (notably GitHub pre-receive hooks) and because modern terminals already mitigate the risk.

Knoble's intervention doesn't introduce new technical details about the implementation (which remains uncontested) but strengthens the security-first perspective by questioning the logic of leaving known vulnerabilities unaddressed just because other attack vectors exist. The thread remains at an impasse between those prioritizing security hardening and those concerned about backward compatibility, with no clear consensus yet on whether the filtering should be opt-in or enabled by default.
