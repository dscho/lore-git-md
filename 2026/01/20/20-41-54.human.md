This is a follow-up in a thread about fixing Git's inconsistent handling of global config files. The original patch series (from October 2025) addressed an issue where `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that and `$XDG_CONFIG_HOME/git/config`. 

Junio C Hamano notes that the thread has been dormant for two months since the last discussion, where Delilah Ashley Wu acknowledged Kristoffer Haugsbakk's clarification that the discrepancy only occurs when both config files exist. While Junio plans to drop the topic from the 'seen' branch soon, he makes clear this doesn't mean the patch is unwelcome - just that an updated version would need to be submitted to restart consideration.

The technical details were previously worked out with reviews from Johannes Schindelin and feedback from Junio, so this appears to be a straightforward case of the author to resubmit with the noted clarifications. The patch series was technically sound but got stalled in the queue.
