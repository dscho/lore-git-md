This is part 3/6 of a bugfix series from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series restores detailed error messages that were lost when batched updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

This particular patch focuses on `git update-ref`, ensuring it properly outputs detailed error messages to stderr while maintaining the existing machine-parsable output format on stdout. The changes include:

1. Modifying the error callback to print detailed messages (when available) to stderr
2. Keeping the structured rejection output on stdout for machine parsing
3. Updating tests to verify both the detailed error messages and structured output

The patch is well-structured with thorough test coverage, updating 71 lines of test code to verify the new behavior across various error cases (invalid objects, ref conflicts, incorrect old values, etc.). This continues the series' goal of restoring useful debugging information while maintaining backward compatibility with existing scripts that parse the machine-readable output.
