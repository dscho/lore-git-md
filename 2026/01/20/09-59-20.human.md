This is part 2 of a 6-part bugfix series addressing a regression in error message reporting for batched reference updates. The patch extends the callback function signature for handling rejected ref updates to include detailed error message strings that were previously lost.

The change adds a `details` parameter to `ref_transaction_for_each_rejected_update_fn` and updates all callers (in fetch.c, receive-pack.c, and update-ref.c) to handle this new parameter. While the parameter is currently marked UNUSED in these callers, the commit message notes it will be used in upcoming patches to restore detailed error reporting.

The patch is straightforward plumbing work that maintains backward compatibility while setting up the infrastructure needed for the full fix. It's co-authored by Jeff King (Peff) and Karthik Nayak, both experienced contributors to Git's ref handling code. The change is part of a well-structured series that has already gone through multiple iterations and review cycles.
