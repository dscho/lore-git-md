Bugfix in the refs subsystem addressing a regression in batched reference updates. This is part 1 of a 6-patch series (no cover letter seen yet).

The patch fixes an issue where rejected reference updates in `refs_verify_refnames_available()` would incorrectly continue processing the same reference multiple times. The problem occurs because a `continue` statement only skipped the inner loop checking filesystem conflicts, not the outer loop processing each reference. The fix replaces this with a `goto` to properly skip to the next reference.

Karthik Nayak's changes affect multiple ref backends (files, packed, and reftable) and include improvements to error handling by properly propagating rejection details.
