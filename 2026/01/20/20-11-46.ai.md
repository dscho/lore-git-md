[Security] ANSI escape sequence injection mitigation with trust-tiered configuration

This email from Junio C Hamano responds to Jeff King's suggestion about using `GIT_PROTOCOL_FROM_USER` as a model for differentiating trust levels in sideband control character filtering. The thread concerns security hardening against terminal escape sequence injection (CVE-2024-32002 and CVE-2024-52005), where the current patch series introduces configurable sanitization via `sideband.allowControlCharacters`.

Junio acknowledges Peff's proposal to distinguish between user-specified URLs (like command-line clones) and automated redirections (like `.gitmodules`), but rejects it on two grounds. First, he notes that protocol trust (HTTPS vs file://) doesn't necessarily imply terminal output trust - a manually specified HTTPS repository might still be untrusted content. Second, he observes that even manually cloned repositories deserve suspicion until vetted, making the command-line vs automated distinction unhelpful for this purpose.

The response maintains the security-focused stance of the overall series while engaging with Peff's implementation concerns. Junio's position suggests the need for a different trust model than protocol origins, though he doesn't propose an alternative here. This keeps the thread focused on the core security/UX tradeoff without reopening the broader debate about strict defaults that earlier messages had settled. The technical implementation of the filtering itself remains uncontested, with this exchange addressing only the peripheral question of how to handle trust gradations.
