Hook infrastructure access control inquiry. Chris Packham seeks mechanism to distinguish push sources in pre-receive hooks when multiple automated systems (Gerrit replication and CI) share same user identity. Current setup rejects all non-replication pushes but needs finer-grained control. Core question remains whether Git exposes push origin information to hooks.

Randall S. Becker responds that Git provides no direct mechanism for hooks to identify push sources. He outlines theoretical but non-portable OS-level approaches (stdin endpoint inspection, process context examination) while cautioning these would be unreliable. His practical recommendation is to implement network-level controls via firewall rules to block CI system pushes rather than attempting distinction within Git. This confirms the core functionality Chris needs isn't currently exposed through Git's hook interface, leaving enterprise-scale access control scenarios requiring push source differentiation to external solutions.
