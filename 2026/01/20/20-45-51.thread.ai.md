Hook infrastructure access control inquiry. Chris Packham seeks mechanism to distinguish push sources in pre-receive hooks when multiple automated systems (Gerrit replication and CI) share same user identity. Core question remains whether Git exposes push origin information to hooks, with current setup rejecting all non-replication pushes but needing finer-grained control.

Randall S. Becker confirms Git provides no direct mechanism, outlining theoretical but non-portable OS-level approaches while cautioning about reliability. Recommends network-level controls via firewall rules. Jeff King (Peff) expands solution space with transport-specific workarounds: for SSH suggests examining $SSH_CLIENT or authorized_keys environment variables; for HTTP recommends checking $REMOTE_ADDR or $REMOTE_USER, with Apache configuration examples in git-http-backend docs.

In a practical debugging tip, Peff suggests adding `env >&2` to pre-receive hooks to dump all environment variables to stderr during push attempts, helping administrators inspect what transport-specific information (SSH_CLIENT, REMOTE_ADDR etc.) is actually available in their server configuration. This provides concrete way to implement transport-specific access controls without requiring Git changes.

Key technical details: pre-receive hook context lacks native push source metadata, forcing reliance on transport-layer solutions. No changes to Git's hook interface proposed - all approaches involve external configuration (firewall rules, SSH authorized_keys, HTTP server vars) or transport inspection. Open question remains whether Git should expose push source information natively, though thread participants have focused on advocating for such an extension. Current consensus favors transport-specific solutions with Peff's environment dump technique providing practical debugging aid.
