Hook infrastructure enhancement request. Chris Packham asks about distinguishing between different push sources in a pre-receive hook, specifically needing to differentiate between pushes from a Gerrit replication system and a CI system that both run as the same user.

The current situation involves migrating from a mixed Git/Gerrit setup to using Gerrit as primary, with replication maintaining a legacy server. Their pre-receive hook currently rejects all pushes except those from the replication user, but now needs finer-grained control to also block pushes from a CI system that shares the same user identity.

The core question is whether Git's hook system provides any mechanism to detect the originating system of a push operation. This would help enforce more granular access control when multiple automated systems share a single account. The request touches on Git's hook interface and authentication/authorization boundaries, though it's unclear if the needed information is currently exposed to hooks.

The email doesn't propose a specific solution but rather probes for existing capabilities or potential directions to solve their access control problem. The use case appears legitimate for enterprise environments where multiple automated systems interact with repositories.
