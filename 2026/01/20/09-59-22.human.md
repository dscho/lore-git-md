This is part 4 of a 6-part bugfix series addressing a loss of detailed error messages in batched reference updates. The patch focuses specifically on `git fetch`, restoring the detailed error reporting that was lost when batched updates were introduced.

The change modifies `builtin/fetch.c` to use the detailed error messages provided by the ref transaction API when available, falling back to generic messages only when no details are present. This fixes a regression where users would only see generic errors like "reference already exists" rather than the specific underlying issue (e.g., lock file conflicts or case sensitivity problems).

The patch includes updates to several tests in `t/t5510-fetch.sh` to verify the restored error messages match the expected detailed output. The test changes show the error messages now include specific file paths and lock file details that help diagnose the root cause of reference update failures.

This is a well-contained change that builds on the ref transaction callback changes from earlier in the series. The commit message clearly explains the regression being fixed and includes co-authorship from Jeff King, indicating thorough review. The test updates demonstrate the improved error reporting works as intended.
