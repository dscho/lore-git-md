This is part 5/6 of a bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses on `git receive-pack`, restoring detailed error messages that were lost when the command switched to batched updates in 9d2962a7c4.

The key change propagates detailed error messages from the ref transaction system to the client via `rp_error()`. This means users pushing invalid references (like trying to write a tag object to a branch) will now see specific error messages rather than generic ones. The patch includes a test case verifying this behavior when attempting to push a tag as a branch.

The implementation handles memory management carefully by duplicating error strings when needed (`cmd->error_string_owned`). While the current output can be verbose with repeated refnames (a known issue noted in the commit message), this provides immediate value by restoring lost debugging information. The series as a whole has been through multiple iterations (now at v3) with thorough test coverage across `update-ref`, `fetch`, and `receive-pack`.

This patch builds on earlier work in the series that established the error reporting infrastructure, and maintains consistency with the fixes already applied to `git update-ref` and `git fetch`. The remaining work (patch 6/6) will address deterministic output ordering, completing the regression fix.
