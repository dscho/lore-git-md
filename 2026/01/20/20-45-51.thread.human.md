This thread discusses a request to enhance Git's hook infrastructure to better handle push source identification. Chris Packham describes a migration scenario where their organization is moving from a mixed Git/Gerrit setup to using Gerrit as primary, with replication maintaining a legacy server. Their current pre-receive hook rejects all pushes except those from a replication user, but they now need to distinguish between pushes from the replication system and a CI system that shares the same user identity.

The core challenge is that Git's hook system currently provides no mechanism to detect the originating system of a push operation, making it difficult to implement granular access control when multiple automated systems share a single account. The discussion touches on Git's hook interface and authentication/authorization boundaries, though it's unclear if the needed information is currently exposed to hooks. The use case appears legitimate for enterprise environments where multiple automated systems interact with repositories, but no solutions or workarounds have been proposed yet in this initial inquiry.
