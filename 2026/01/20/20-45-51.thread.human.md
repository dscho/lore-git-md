This thread explores how Git hooks can distinguish between different push sources when multiple automated systems (like Gerrit replication and CI) share the same user identity. The core issue is that Git's pre-receive hooks lack built-in metadata about the push origin, forcing administrators to find workarounds.

Chris Packham initiated the discussion seeking a way to implement finer-grained access control. Randall S. Becker confirmed Git provides no direct mechanism, suggesting network-level controls as the most robust solution. Jeff King (Peff) then offered transport-specific approaches - examining SSH_CLIENT for SSH pushes or REMOTE_ADDR for HTTP - while noting these rely on server configuration rather than Git itself. In his latest contribution, Peff provides a practical debugging tip: adding `env >&2` to a hook script dumps all available environment variables, helping administrators see exactly what information their specific setup provides.

The emerging consensus is that solutions will be transport-specific rather than requiring Git changes. While the thread hasn't settled on a single approach, it has mapped out the problem space clearly: network controls are most robust, but when those aren't feasible, transport-layer environment variables offer workable alternatives. Peff's debugging suggestion gives administrators a concrete way to explore what's possible in their environment.
