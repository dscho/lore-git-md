Thread summary:

Bug report about a regression in `git fetch` error reporting after batched reference updates (Git 2.51). Stepan Tsymbal (Atlassian) identifies a loss of specificity when ref updates fail due to directory/file conflicts - previously showed exact failed refs, now only generic "some local refs could not be updated" message. This impacts automation (e.g. Bitbucket mirror sync) needing precise failure info. Test case demonstrates the issue is specific to D/F conflicts; other errors still show per-ref messages. The `reference-transaction` hook doesn't help as it shows all refs as committed. Core problem: batched updates optimization unintentionally obscured actionable error details for this specific failure mode. Open question: is this the intended behavior, and if not, what are the workaround options for automation? The regression affects tools parsing `git fetch` output to identify exactly which refs failed to update.
