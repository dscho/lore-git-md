This is a performance optimization patch in the sparse-checkout subsystem, part of an ongoing series from Amisha Chhajed that changes the pattern list construction from O(n^2) to O(n log n) by switching from string_list_insert() to string_list_append() followed by sorting.

The patch addresses feedback from Derrick Stolee about duplicate handling in the pattern list construction. Amisha explains that while the parent_hashmap already prevents duplicates (via checks in git/dir.c), the test cases in v6 revealed that string_list_remove_duplicates() is still needed in some cases. She notes it was tricky to create a test case that directly exercises the 'list' command's duplicate handling, but she was able to do so in v6 following Derrick's guidance.

The discussion highlights some subtle considerations around cone mode vs non-cone mode behavior (where order matters) and the importance of proper test coverage for edge cases. The optimization itself is straightforward - replacing insertion sort with append+sort - but the surrounding context requires careful handling of Git's sparse-checkout semantics.

This appears to be a well-considered optimization that has gone through multiple rounds of review, with v6 addressing all identified concerns. The changes are localized to builtin/sparse-checkout.c and come with expanded test coverage.
