[RFC PATCH] symlinks: use unsigned int for bitmask flags  
Author: Tian Yuchen  
Files: symlinks.c, symlinks.h  

Core change: Converts `int` to `unsigned int` for bitmask flags in symlink handling code (`flags` and `track_flags` in `struct cache_def` and related functions) to properly represent bitmask semantics and prevent undefined behavior with shifts. No functional changes.  

Technical details:  
- Targets symlink caching/tracking logic in symlinks.c  
- Follows C best practices for bitmask operations (current code works via implicit conversions)  
- Patrick Steinhardt's review notes:  
  1. Incorrectly changed signed variables (`ret`, `saved_errno`) should remain signed  
  2. Flags used as booleans in some functions could use proper boolean returns  
- External user (preload-index.c) doesn't interact with flag fields directly  

Current status:  
- RFC seeking guidance on Git's type conventions for bitmasks  
- Patrick confirms technical merit but requests corrections  
- Provides broader context on Git's pragmatic approach to type safety:  
  - Implicit conversions are common but increasingly seen as code smells  
  - Incremental improvements welcome, but large-scale conversions discouraged  
  - No strict rules, but changes should have clear benefit  

Open questions:  
- Whether to pursue boolean return type follow-up for affected functions  
- Potential addition of bitmask type guidelines to CodingGuidelines

  - Approved concept but identified scope issues
