This is a feature patch (with some refactoring aspects) that improves `git show-index`'s hash algorithm detection when run outside a repository. It's the first of a 3-part series from a new contributor.

The patch implements automatic hash algorithm detection for v2 pack index files by analyzing file size patterns, addressing a known TODO in the code. When no repository context is available, the command currently defaults to SHA-1, which can fail with SHA-256 pack files. The new logic calculates expected file structure sizes to distinguish between SHA-1 (20-byte hashes) and SHA-256 (32-byte hashes), falling back to requiring explicit `--object-format` when detection isn't possible (like with 64-bit offsets).

The implementation modifies only `builtin/show-index.c`, adding 34 lines while removing 11. It introduces local variables for hash detection calculations where globals were previously used, aligning with the project's `the_repository` removal trend. The patch includes gettext wrappers for new error messages, though the series' later patches focus more on i18n.

Key technical details: the detection works by computing remaining file size after fixed header/table sections, then dividing by object count to infer hash size. This approach won't work with 64-bit offsets, which the commit message clearly. The patch leaves open how to handle edge cases in testing and whether documentation updates are needed - points the author will address based on list feedback.
