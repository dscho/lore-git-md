This is the final patch in a bugfix series (v3, 6/6) from Karthik Nayak addressing a regression in error message reporting for batched reference updates. The series restores detailed error messages that were lost when batched updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The patch focuses on `git fetch`, implementing a solution to delay status output until after the transaction is committed, ensuring error details are available. It introduces a new `ref_update_display_info` structure to track update outcomes and maintains deterministic output by using both an array and strmap. Benchmarking shows minimal performance impact (1-2% overhead for 1000 refs).

The series has been through multiple iterations with input from Jeff King (who originally reported the issue) and Phillip Wood (who suggested the array-based approach for deterministic ordering). While the core functionality is stable, one follow-up remains to finalize the output ordering in `git fetch`.

This completes the restoration of pre-batched-update error reporting behavior across all affected commands while maintaining backward compatibility. The changes are well-tested and have minimal performance impact, making this a solid fix for the regression.
