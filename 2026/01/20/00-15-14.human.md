This is a follow-up discussion in the gettext detection feature thread, where Junio C Hamano responds to Patrick Steinhardt's concern about distinguishing between older Git versions that lack gettext detection entirely versus newer versions that have it but disabled the feature.

Junio points out that the version number reported by `git version --build-options` already provides the necessary context to differentiate these cases - if the version is old enough to predate the gettext detection feature, the absence of a gettext line indicates the feature didn't exist yet, while in newer versions it would indicate gettext is disabled. This reinforces the design choice in Jiang Xin's v2 patch to only report "gettext: enabled" when present, keeping the output clean while still providing sufficient diagnostic information.

The exchange shows the maintainer's preference for minimal output that leverages existing version information rather than adding explicit "disabled" states. This appears to be the final word in the discussion, as no further objections are raised after Junio's clarification. The thread seems ready for the patch to proceed with the simplified output approach.
