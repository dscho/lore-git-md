This is a status update on the ref backend selection series, which aims to enable zero-downtime migrations between reference storage backends (files <-> reftable) in large repositories. The thread has progressed through three versions and is now awaiting a v4 implementation to address worktree reference handling.

Junio Hamano notes he will soon remove the current version from his 'seen' integration branch to declutter, but emphasizes this is not a rejection - the topic remains welcome for future submission. Karthik Nayak had previously indicated the delay was due to vacation time, with Patrick Steinhardt's internal review identifying worktree integration as the remaining technical hurdle.

The series has otherwise reached consensus on key design points including config-based URI syntax via `extension.refStorage`, environment variable override behavior with `GIT_REFERENCE_BACKEND`, and migration workflows. The worktree reference initialization sequence - particularly around Git directory detection timing - is the final substantive issue before the series can be integrated. Karthik is expected to address this in v4 along with finalizing the remaining implementation details.
