This is part 11/14 of Patrick Steinhardt's ODB abstraction series, introducing mtime tracking for objects as part of the larger object database refactoring effort.

The patch adds mtime (modification time) support to Git's object storage layer by introducing a new `mtimep` field in `struct object_info`. This allows callers to request an object's modification time through a unified interface, whether the object is stored loose or packed. The implementation handles three cases: loose objects use their filesystem mtime, regular packed objects use the packfile's mtime, and cruft pack objects use their individual mtime from the `.mtimes` index.

Key technical changes include:
- New `mtimep` pointer in `struct object_info` for returning timestamps
- Modified `read_object_info_from_path()` to populate mtime for loose objects
- Enhanced `packed_object_info()` with new `packed_object_info_with_index_pos()` helper to handle mtime lookup
- Special handling for cruft packs to read per-object mtimes from `.mtimes` index
- Updates to the packed object iteration callback to pass through index position for efficient mtime lookup

The change is preparatory work for future functionality like more precise object pruning based on modification times. The implementation maintains all existing behavior while adding the new capability, with careful handling of edge cases like empty object files and error conditions.

This continues the series' pattern of introducing symmetric interfaces across loose and packed object storage while maintaining backward compatibility. The patch follows the established code style and builds on previous infrastructure from the series, particularly the object info request machinery.
