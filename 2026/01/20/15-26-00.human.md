This is part 4/14 of Patrick Steinhardt's ODB abstraction series, which is nearing final integration. The patch introduces a new function `odb_source_loose_for_each_object()` to provide a unified interface for iterating through loose objects, replacing the existing `for_each_loose_object()` which will be removed later in the series.

The new function accepts a `struct object_info` parameter that gets populated similarly to a direct object read, allowing callers to access object metadata during iteration. This change helps standardize the object iteration interface across different backends (loose and packed objects), a key step in making Git's object storage backend-agnostic.

The implementation includes a wrapper callback that handles the object info population and passes control to the caller's callback. The patch maintains existing behavior around promisor and local-only object filtering. Reviewers have already validated the approach, with Karthik Nayak specifically verifying the path handling optimizations in earlier patches of this series.

This is a well-structured technical change that moves the ODB abstraction effort forward by addressing one of the interface inconsistencies between different object storage types. The commit message clearly explains the motivation and expected future changes in the series.
