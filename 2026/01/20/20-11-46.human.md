This is a security patch discussion about controlling ANSI escape sequence injection in Git's sideband channel. The thread has been debating how to configure trust levels for remote repositories when deciding which control sequences to allow through.

Junio C Hamano responds to Jeff King's suggestion of reusing the `GIT_PROTOCOL_FROM_USER` mechanism to distinguish trusted vs untrusted remotes. While acknowledging the appeal of the parallel, Junio points out a key difference: just because a user manually provides a URL doesn't mean they trust its terminal output. He gives the example of cloning a repository from someone you just met - you might want to inspect the code without fully trusting its sideband output.

The exchange highlights the ongoing tension between security (wanting strict defaults to prevent terminal injection attacks) and compatibility (not breaking existing workflows that rely on certain control sequences). Junio's response suggests he's skeptical that protocol trust levels cleanly map to terminal output trust, which was one of the proposed solutions in this long-running discussion about how to safely handle remote control sequences.
