This is the final patch in a series implementing depth control for the experimental `git-last-modified` command. The patch changes the default behavior to be non-recursive (max-depth=0) rather than recursive, which better matches user expectations when operating on specific paths. The change means that when given a path like `path/file`, the command will now show the modification time of that exact file rather than its parent directory.

The implementation simplifies the code by removing the separate `recursive` flag and handling everything through the `max_depth` parameter (-1 means unlimited recursion, 0 means non-recursive, positive numbers limit depth). The `-r/--recursive` option now sets `max_depth=-1` to maintain backward compatibility with existing uses. Documentation is updated to clarify the new behavior and the relationship between options.

New test cases verify the behavior with subdirectories and various depth settings, including the interaction with wildcard pathspecs. The changes implement all planned simplifications from earlier discussion while preserving functionality, with the documentation now fully aligned with the implementation.
