This is part of Patrick Steinhardt's ongoing ODB abstraction series (now 14 parts), converting the reachable object enumeration to use the new `odb_for_each_object()` API. The patch refactors `reachable.c` to use the unified object iteration interface rather than separate paths for loose and packed objects.

The change replaces three functions (`add_recent_loose`, `add_recent_packed`, and part of `add_recent_object`) with a single callback that handles both storage types through the new ODB interface. The key technical aspects are:

1. The new `add_recent_object` callback now receives a `struct object_info` containing pre-computed mtime and type information, eliminating redundant lookups.
2. Pack-specific handling (cruft pack mtimes, packfile offsets) now comes through the `oi->u.packed` union when `oi->whence` indicates a packed object.
3. The patch maintains all existing behavior flags (`LOCAL_ONLY`, `SKIP_IN_CORE_KEPT_PACKS`) while simplifying the control flow.
4. Error handling is consolidated - the single callback return value replaces separate error paths for loose/packed objects.

The conversion demonstrates the ODB API's ability to unify object iteration patterns while preserving all existing functionality. This is the 13th patch in a series that has undergone extensive review, with previous iterations addressing documentation, type signatures, and interface design. The changes here are mechanical but impactful, removing 90 lines of redundant code while maintaining the same reachability checking behavior.
