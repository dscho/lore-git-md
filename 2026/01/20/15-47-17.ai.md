Performance optimization for sparse-checkout pattern handling, addressing feedback on duplicate removal in cone mode.

This email from Amisha Chhajed responds to Derrick Stolee's review of her v5 patch optimizing sparse-checkout pattern list construction. The key discussion point is whether duplicate pattern removal is needed when building the string list from parent_hashmap entries, since the hashmap itself should prevent duplicates. Amisha notes that while the parent_hashmap prevents duplicates via a warning in dir.c, she found through testing that removing the duplicate check elsewhere in the code causes test failures, suggesting there are edge cases where duplicates can still occur.

Derrick had pointed out that the test coverage needed improvement to properly exercise the 'list' command's deduplication behavior, since the 'add' command already handles duplicates. He also cautioned about the distinction between cone mode (where order doesn't matter) and non-cone mode (where pattern order is significant). Amisha confirms she addressed these points in v6 of her patch series.

The technical context involves changes to builtin/sparse-checkout.c where string_list_insert() is replaced with string_list_append() followed by sorting, improving performance from O(n^2) to O(n log n). The discussion reveals subtle aspects of Git's sparse-checkout implementation, particularly around how patterns are normalized and deduplicated at different stages of processing. This patch is part of the ongoing sparse-checkout optimizations led by Derrick Stolee and Elijah Newren.
