This is a refactoring patch in Patrick Steinhardt's ODB abstraction series, specifically addressing object-file path handling. Karthik Nayak provides a review of patch 3/14, which extracts a new `read_object_info_from_path()` function from `odb_source_loose_read_object_info()` and removes the now-unused `stat_loose_object()` helper.

The key changes are:
- Introduces `read_object_info_from_path()` that takes a precomputed path rather than computing it internally
- Eliminates `stat_loose_object()` since its functionality is now handled directly via `lstat()`
- Maintains the same external interface through a thin `odb_source_loose_read_object_info()` wrapper
- Reduces code by ~23 lines while preserving all functionality

Karthik notes the patch looks good, though expresses initial confusion about the `odb_loose_path()` extraction that's apparently explained in the next commit. He observes this leaves `open_loose_object()` with only one remaining caller, though doesn't flag this as requiring immediate cleanup.
