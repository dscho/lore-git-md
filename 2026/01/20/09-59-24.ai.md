Bugfix completing a series to restore detailed error messages in batched reference updates, particularly affecting `git fetch` output. This final patch (6/6) from Karthik Nayak with Jeff King addresses the regression where batched updates lost per-ref error details that were previously shown to users.

The patch introduces a `ref_update_display_info` structure to collate update outcomes during the transaction, then displays them after commit. This maintains the familiar output format while properly showing which references failed and why. The implementation uses a dynamic array to track updates, with benchmarking showing minimal performance impact (1% slower for 1000 refs).

Key technical changes:
- New `struct ref_update_display_info` holds per-ref status codes, messages, and OIDs
- `update_local_ref()` now appends to display list rather than printing immediately
- Transaction commit tracks rejected refs via `strmap`
- Final display phase shows all updates with proper failure indicators
- Test added to verify error message for pushing non-commit objects

This completes the series restoring pre-batched-update error reporting behavior while maintaining the batching benefits. The approach avoids more invasive transaction API changes by handling display logic in `fetch.c`. Performance impact appears negligible based on included benchmarks.
