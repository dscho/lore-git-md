This is the final version of a feature patch series adding `--keys` and format unification to the `git repo` subcommands. The series has gone through four iterations with feedback from Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila, and is now ready for integration into `next`.

The key addition is a `--keys` flag for machine-readable repository metadata access, with standardized output formatting across `git repo` commands. The implementation includes NUL-terminated output options (documented as `_NUL_` per project conventions) and introduces a `FORMAT_LINES` enum (where "default" is a synonym for "lines") to clarify the output format naming. Patrick Steinhardt suggested the "lines" terminology over "newline" for better user clarity, which has been implemented.

The series replaces the previously queued `lo/repo-info-keys` topic and builds on earlier infrastructure work. All review feedback has been addressed, including documentation standardization from Jean-Noël Avila and format validation improvements. The patches include comprehensive tests and handle various edge cases around option combinations.

Junio confirms the naming choice feels natural and the series is now complete with no outstanding issues, marking the conclusion of this development cycle before integration. The work demonstrates careful attention to both technical implementation and user experience considerations.
