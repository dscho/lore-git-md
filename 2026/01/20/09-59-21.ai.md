Bugfix patch in a series restoring detailed error messages for batched reference updates. This is part 3/6 of a v3 series from Karthik Nayak and Jeff King addressing a regression where batched reference updates (`git update-ref --batch-updates`) lost detailed error messages, only returning generic error codes.

The patch modifies `builtin/update-ref.c` to output detailed error messages to stderr when available, while maintaining the existing machine-parsable output format on stdout. The test suite is extensively updated to verify both the detailed error messages and the machine-readable output for various failure cases (invalid objects, ref conflicts, incorrect old values, etc.).

Key technical details:
- Error details are now passed through from the refs subsystem via the `details` parameter in the callback
- Existing tests are enhanced to check both stdout (machine output) and stderr (human-readable details)
- Error cases covered include: invalid object types, ref existence checks, symref conflicts, case sensitivity issues
- Maintains backward compatibility with existing scripts parsing the stdout format

This builds on previous patches in the series that plumbed the error details through the ref transaction machinery. The changes are focused on the `update-ref` command but are part of a broader fix affecting `fetch` and `receive-pack` as well. The patch series has already seen significant review and iteration, with this version addressing feedback on callback signatures and error handling.
