This is a brief discussion about memory management in Git's remote tracking reference handling, specifically regarding the `error_buf()` function signature. The exchange occurs between Patrick Steinhardt and Junio C Hamano as part of reviewing Jeff King's completed 4-patch series that established clearer ownership semantics for push tracking references.

Patrick notes that while Jeff's change to make `error_buf()` return a non-const pointer (from `const char*` to `char*`) helps indicate ownership transfer, the function's signature remains somewhat misleading in its design. Junio agrees with this assessment, suggesting the function might be better as `void` if it doesn't return useful values, though he recognizes the current pattern may be following the convention of using NULL returns to signal errors (similar to `error()`).

The discussion highlights ongoing attention to API design details in Git's reference handling code, even after the main technical fixes have been approved. Both reviewers acknowledge the current implementation isn't ideal but recognize this isn't a blocker for the series, which has already addressed the core memory management issues. The exchange shows the project's careful consideration of API semantics, even for small utility functions.
