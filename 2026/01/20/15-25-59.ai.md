This is part 3/14 of Patrick Steinhardt's ODB abstraction series, which aims to make Git's object storage backend-agnostic. The patch refactors loose object handling in `object-file.c` to extract a new `read_object_info_from_path()` function that reads object information directly from a given path, eliminating the intermediate `stat_loose_object()` wrapper.

The key changes are:
1. Removes `stat_loose_object()` which was just a thin wrapper around path generation and `lstat()`
2. Introduces `read_object_info_from_path()` that takes a precomputed path and handles the object reading logic
3. Makes `odb_source_loose_read_object_info()` a thin wrapper that generates the path and calls the new function

The patch follows the series' pattern of breaking down monolithic functions into more modular components that will be easier to adapt for different storage backends. Karthik Nayak has already reviewed and verified the path handling optimizations in this change. The diff shows a net reduction of 7 lines while improving code organization - a typical Patrick Steinhardt quality refactoring that moves the ODB abstraction effort forward.
