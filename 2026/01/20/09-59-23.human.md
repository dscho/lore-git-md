Bugfix patch (5/6 in series) restoring detailed error messages for failed reference updates in `git receive-pack`. This addresses a regression introduced when batched reference updates were added, where users only saw generic error codes rather than specific diagnostic messages.

The patch modifies `receive-pack` to propagate detailed error messages from the ref transaction system to the client through the `rp_error` mechanism. For example, when attempting to push a non-commit object to a branch, users will now see the specific error about the object type mismatch rather than just a generic rejection message. The implementation includes a new test case verifying this behavior.

While this restores the lost functionality, the authors note that the error output could be verbose and contains some redundancy (like repeated refnames) that might be cleaned up in future work. The patch builds on previous changes in the series that modified the callback signatures and error handling infrastructure across multiple commands (`update-ref`, `fetch`, and now `receive-pack`).

This is part of a coordinated fix by Karthik Nayak and Jeff King to maintain backward compatibility while restoring the detailed error reporting that existed before the batched updates were introduced. The series has already seen multiple iterations and careful review, with this patch representing one of the final pieces addressing the regression across Git's reference update commands.
