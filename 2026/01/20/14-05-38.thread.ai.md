RFC patch series modernizing `git show-index` from Shreyansh Paliwal, progressing through standard modernization steps: hash algorithm detection when run outside repositories (SHA-1 vs SHA-256 via file size pattern analysis), i18n support (wrapping error messages in `_()`), and removing global state as part of `the_repository` elimination effort. The third patch converts all remaining uses of `the_repository` and `the_hash_algo` to use explicit `repo` parameter and `repo->hash_algo`, touching 19 lines in `builtin/show-index.c` while maintaining existing hash detection logic.

Junio C Hamano provided initial feedback on the hash detection implementation, suggesting structural improvements while accepting the approach: extract hash detection into a helper function returning `GIT_HASH_UNKNOWN` for non-regular files rather than dying; handle SHA-1/SHA-256 size assumptions more robustly; convert fatal errors to warnings; let caller handle SHA-1 fallback. Junio noted style violations (missing space after `if`) and emphasized separation of concerns.

Patrick Steinhardt subsequently weighed in on the hash detection approach, agreeing with Junio about the fragility of size-based guessing, especially for future hash algorithms. He notes the fundamental limitation that pack index formats lack explicit hash algorithm identification, making reliable detection impossible without user input (via existing `--object-format` option). Patrick suggests a proper solution would require introducing index format v5 with explicit hash algorithm metadata, but questions whether this complexity is justified for `show-index` as primarily a debugging tool.

Technical implementation remains focused on `builtin/show-index.c`, with each patch addressing a distinct modernization aspect (hash detection, i18n, global state removal) without altering core functionality. The discussion reveals deeper architectural questions about maintaining legacy formats versus introducing breaking changes for correctness. Open questions from initial review about testing edge cases and documentation updates remain unaddressed.
