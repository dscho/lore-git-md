This thread began as an RFC patch series from Shreyansh Paliwal modernizing `git show-index`, but has evolved into a broader discussion about the scope of the `the_repository` removal effort. The original patches addressed hash algorithm identification, i18n support, and removing global variables from the command.

Junio Hamano and Patrick Steinhardt provided substantive technical feedback on the hash detection approach, with Junio suggesting structural improvements and Patrick questioning the reliability of size-based guessing. Phillip Wood then shifted the conversation by challenging whether builtin commands like `show-index` should be part of the `the_repository` removal effort at all, arguing they inherently operate on a single repository.

The discussion has now reached consensus on an important architectural boundary: library functions should be parameterized to work with any repository, while builtin commands can continue using `the_repository` since they are single-repository operations by nature. Shreyansh has acknowledged this and plans to drop the repository parameterization from his series, instead focusing his contributions on library code like `wt-status.c`. The i18n patches remain uncontroversial, while the hash detection approach still needs resolution between Junio's structural improvements and Patrick's concerns about format guessing.
