This RFC thread explores modernizing the low-level `git show-index` command, with discussions revealing deeper questions about Git's evolution. Shreyansh Paliwal's initial series proposed three improvements: better hash algorithm detection, i18n support, and removing repository globals. While the i18n changes proved uncontroversial, the other aspects sparked substantive debate.

The thread reached consensus that builtin commands like `show-index` should retain their `the_repository` usage, as Phillip Wood and Junio Hamano demonstrated that forcing repository parameterization created unnecessary complexity. Shreyansh will focus future `the_repository` removal efforts on library code instead.

The remaining debate centers on hash detection when operating outside repositories. Patrick Steinhardt now argues against requiring explicit `--object-format` specification, despite earlier concerns about the fragility of size-based guessing. He emphasizes backward compatibility, noting that some users rely on the current SHA-1 fallback behavior. This reflects Git's conservative approach to changes that might break obscure but valid use cases, even when technically justified. The discussion continues to explore how to balance correctness with compatibility in this niche but revealing corner of Git's plumbing.
