This thread discusses an RFC patch series modernizing the rarely-used `git show-index` plumbing command, which displays pack index contents for debugging. Shreyansh Paliwal's initial patches addressed hash algorithm detection (SHA-1 vs SHA-256 via file size analysis), i18n support, and removal of global state as part of the `the_repository` elimination effort.

Junio C Hamano provided structural feedback on the hash detection implementation, suggesting moving the logic to a helper function with better error handling while maintaining the core size-based approach. The discussion has shifted to deeper questions about the reliability of this detection method. Patrick Steinhardt has now joined the conversation, agreeing with Junio that the current size-based detection is fragile, especially as new hash algorithms emerge. He notes the fundamental limitation that pack index files lack explicit hash algorithm metadata, making reliable auto-detection impossible without format changes.

Both maintainers acknowledge that while introducing a new index format version with proper hash algorithm metadata would solve the problem technically, it may not be worth the complexity for this debugging-oriented command. The thread remains open on whether to proceed with the current pragmatic approach (with Junio's suggested improvements) or defer deeper changes until a broader index format revision. No new patch versions have been posted since this architectural discussion emerged.
