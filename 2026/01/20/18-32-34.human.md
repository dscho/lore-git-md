This is the final version of a feature patch adding PID file debugging for Git locks, now ready for merging. Paulo Casaretto has implemented a system that creates companion PID files (e.g. `index~pid.lock`) alongside lock files when `core.lockfilePid` is enabled, helping diagnose stale lock issues. The feature has gone through multiple iterations with input from Jeff King, Patrick Steinhardt, Taylor Blau, Ben Knoble, and Junio Hamano.

The implementation handles edge cases like Windows compatibility (via mingw_kill() updates), PID file parsing, and cleanup. Error messages now carefully acknowledge PID reuse limitations while still providing useful diagnostics. The 139-line test suite (t0031) verifies behavior for running processes, stale locks, and cleanup scenarios.

Key technical details: PID files use tilde separator to avoid refname collisions, follow Git header style (`pid <value>`), and are registered as tempfiles for proper cleanup. The solution works cross-platform and maintains backward compatibility - existing PID files are read for diagnostics even when the feature is disabled.

This represents the culmination of thorough discussion addressing all technical concerns, with consensus that the implementation is production-ready. The patch touches lockfile.c/h, adds config documentation, and includes comprehensive tests. No further changes are expected.
