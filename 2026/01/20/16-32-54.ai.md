This is part 7/10 of Ezekiel Newren's series refactoring the xdiff subsystem, with a focus on preparing for future optimizations and Rust interoperability. The patch moves the `dstart` field from `xdfile_t` to `xdfenv_t` as `delta_start`, since this value is always the same for both files being compared. Phillip Wood notes this explains why earlier patches started passing `xdfenv_t` around more.

The changes update all references to `dstart` across xdiff's histogram and patience diff algorithms, cleanup routines, and initialization code. The field is now consolidated in the environment structure rather than duplicated per-file. This is a structural change that builds on earlier patches in the series while maintaining the same diff behavior.

Key technical points for future reference:
- `delta_start` now initialized in `xdl_prepare_env()`
- All algorithm calls updated to use `env->delta_start` instead of file-specific values
- `xdl_trim_ends()` now sets the shared `delta_start` value
- Type remains `ssize_t`/`ptrdiff_t` for pointer arithmetic
- Changes affect core diff calculation paths but preserve existing behavior

The patch appears to be a straightforward mechanical change that follows logically from the series' direction, with Phillip Wood raising no new concerns beyond his earlier reviews of the structural changes.
