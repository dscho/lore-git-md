Performance optimization for sparse-checkout pattern handling, completing a series that changes the pattern list construction from O(n^2) to O(n log n) by switching from insertion sort to append-and-sort. This v6 patch from Amisha Chhajed finalizes the optimization and adds test coverage for pattern deduplication behavior that was previously untested.

The patch modifies `builtin/sparse-checkout.c` to use `string_list_append()` followed by sorting and deduplication, rather than the previous `string_list_insert()` that performed an insertion sort. This affects both the pattern listing output (`sparse-checkout list`) and the file writing logic. The changes maintain the distinction between cone mode (where order doesn't matter) and non-cone mode (where it does), while properly handling duplicates that can appear in the recursive_hashmap from user input.

New tests in `t1091-sparse-checkout-builtin.sh` verify that:
1. Repeated patterns in cone mode are properly deduplicated when written to the sparse-checkout file
2. The `sparse-checkout list` command correctly reports each pattern only once

This version addresses all previous feedback and has Junio's approval, with the performance testing discussion resolved (Jeff King and Junio agreed the algorithmic improvement is well-understood and doesn't require extensive benchmarking). The only remaining open question is about adding path normalization test cases, which Pushkar Singh raised separately from this optimization.
