This is part 7/10 of a refactoring series for the xdiff subsystem, with Rust interoperability considerations. The patch moves the `dstart` field from `xdfile_t` to `xdfenv_t` as `delta_start`, since this value is always the same between the two files being compared. Phillip Wood notes this explains why earlier patches started passing `xdfenv_t` around rather than `xdfile_t`.

The changes are mechanical updates to use the new location of this shared value across the xdiff implementation files (xhistogram.c, xpatience.c, xprepare.c) and type definitions (xtypes.h). The patch appears to be a straightforward structural improvement that better reflects the actual usage pattern of this field.

This continues the series' pattern of preparing xdiff internals for future optimizations while maintaining compatibility with Rust integration goals. The change looks well-contained and properly motivated as part of the larger refactoring effort.
