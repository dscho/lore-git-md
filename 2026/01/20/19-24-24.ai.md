This is a contributor housekeeping patch discussion that clarifies Git's mailmap behavior regarding commit trailers. Jeff King (Peff) responds to Junio Hamano's demonstration that .mailmap entries do not modify Signed-off-by trailers in commit metadata, though they do affect author/committer fields.

Peff notes that while mailmap doesn't change the raw trailer contents, some Git tools like `git shortlog` do apply mailmap when displaying trailer information by attempting to parse trailers as idents. He references commit 56d5dde752 which implemented this behavior. Peff also mentions an old proof-of-concept patch he wrote to make mailmap apply more broadly to trailers, though it was never merged.

The discussion serves as useful documentation of mailmap's current scope - normalizing author/committer names while leaving trailers intact unless specifically parsed by tools like shortlog. This maintains flexibility for trailers that may contain non-email content or intentionally omit email addresses. The thread doesn't propose any immediate changes to Phillip Wood's original mailmap patch, which remains valid for its stated purpose of standardizing author attribution.
