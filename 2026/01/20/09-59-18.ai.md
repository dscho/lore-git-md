This is the final patch (6/6) in a bugfix series from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series restores detailed error messages that were lost when batched updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The current patch focuses specifically on `git fetch`, implementing a solution to delay status output until after the reference transaction is committed. This ensures error details are available when displaying results. The implementation uses a dynamic array and strmap to maintain update information, with Phillip Wood's suggestion to use an array-based approach for deterministic ordering.

Key technical changes include:
- New `struct ref_update_display_info` to hold per-update status
- Modified `update_local_ref()` to append to display list rather than output immediately
- Transaction commit handler marks failed updates in the display list
- Final output phase shows all updates with their success/failure status

Benchmarking shows minimal performance impact (1-2%) for repositories with 1000 refs. The patch maintains compatibility while fixing the regression where detailed error messages were lost. This completes the series' goal of restoring pre-batched-update error reporting functionality across all affected commands.

The series is now complete with all 6 patches merged, though one follow-up remains for deterministic output ordering in `git fetch`. This final patch represents the culmination of work to properly propagate reference update errors while maintaining the performance benefits of batched updates.
