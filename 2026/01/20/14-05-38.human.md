This is an RFC patch series to modernize `git show-index`, focusing on hash algorithm detection and code cleanup. The series comes from a relatively new contributor and appears to be their first submission to the list.

The main goal is to make `show-index` automatically detect the hash algorithm used in index files rather than defaulting to SHA-1 when run outside a repository. The implementation currently has a known limitation - it can't detect the hash when 64-bit offsets are present in the index. The author explicitly asks for guidance on whether this approach is appropriate and what tests or documentation might be needed.

The three patches:
1. Add auto-detection for hash algorithms (with the 64-bit offset caveat)
2. Improve error message formatting using gettext
3. Remove global state variables as part of code modernization

The changes are focused entirely on `builtin/show-index.c` and appear to be a self-contained improvement. The author seems to be following good practices by breaking changes into logical steps and asking for early feedback. The patch series looks like a promising start, though reviewers will likely want to understand more about the 64-bit offset limitation and whether the hash detection approach is robust enough.
