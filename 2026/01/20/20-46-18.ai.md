This is a follow-up in an ongoing thread about `git add`'s handling of exclude patterns (`:(exclude)`) with `.gitignore` rules. The thread started with a bug report from René Rahn about `git add` incorrectly warning about ignored files when they were explicitly excluded via pathspec magic.

Junio Hamano initially proposed a fix that modified `dir.c` to properly handle exclude patterns, but now expresses uncertainty about the architectural approach. The current email indicates Junio is considering dropping the topic from the 'seen' branch due to lack of feedback, while leaving the door open for others to continue the work.

The core issue involves whether the current implementation (using a separate `exclude_matches_pathspec` function) is the right approach, or if the pathspec matching logic should be unified. The patch passes existing tests but there are concerns about potential edge cases in other commands that use similar magic (like `git log` and `git diff`).

Key technical points:
- The fix targets pathspec processing in `dir.c`
- Historical context points to changes from 2010 and 2017 that may have introduced the current behavior
- The architectural question remains whether to refactor to use the main `match_pathspec` infrastructure

The thread has evolved from a specific bug report to a broader discussion about pathspec handling architecture in Git. While the immediate fix works, there are open questions about whether a deeper refactoring would be more appropriate long-term. Junio's current stance is neutral - not actively pushing the fix forward but not rejecting it either, leaving room for other contributors to pick it up.
