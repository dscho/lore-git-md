This is part 4 of a 6-patch bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses specifically on `git fetch`, restoring detailed error messages that were lost when the command switched to batched updates.

The change modifies `builtin/fetch.c` to use the detailed error messages provided by the ref transaction machinery when available, falling back to generic messages only when no details are present. This affects several error cases including reference locks, case sensitivity conflicts, and directory/file conflicts. The corresponding tests are updated to expect the more specific error messages.

Key technical changes include:
- Modified `ref_transaction_rejection_handler` to check for and use `details` parameter
- Updated test assertions to match the more specific error messages
- Maintains backward compatibility by falling back to generic messages when needed

The patch is well-contained with clear test coverage for the restored functionality. It builds on the ref transaction callback changes introduced in earlier patches of the series. The changes align with the series' goal of restoring pre-batched-update error reporting quality while maintaining the performance benefits of batched operations.
