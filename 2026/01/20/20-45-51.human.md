This is a feature request for pre-receive hook functionality to distinguish between different push sources when they share the same user identity.

Chris Packham describes a real-world migration scenario where their organization is moving from a direct Git server setup to using Gerrit as the primary system, while maintaining a legacy server for compatibility. The current pre-receive hook can only reject/allow based on user identity, but they need finer-grained control to distinguish between Gerrit replication pushes and CI system pushes that happen to use the same user account.

The email clearly explains the motivation and use case - they want to prevent CI system pushes while allowing Gerrit replication pushes, but both operations currently appear identical to the hook. This appears to be a legitimate gap in Git's hook system that affects real-world deployment scenarios.

The request is well-articulated and grounded in practical experience, though it doesn't propose a specific solution. This seems like the kind of feature that could generate useful discussion about how to expose more context to hooks while maintaining security boundaries. The thread may attract input from hook subsystem experts like Adrian Ratiu or those with Gerrit integration experience.
