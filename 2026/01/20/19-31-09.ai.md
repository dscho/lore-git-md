This is a security discussion thread continuation about ANSI escape sequence filtering in Git's sideband channel. Jeff King (Peff) responds to Junio Hamano's proposal for differentiated default behavior based on remote trust levels, suggesting the existing `GIT_PROTOCOL_FROM_USER` mechanism as a possible model while acknowledging its limitations.

Peff notes that Git already makes trust distinctions for protocol selection (like blocking `file://` from `.gitmodules` while allowing it from direct command-line use), but raises two concerns: the complexity of such heuristics, and that protocol trust doesn't necessarily imply terminal output trust. His comment serves as a technical reality check on Junio's proposed trust-tiered approach, pointing out that while the idea has precedent, the security boundaries may not align cleanly.

The exchange highlights the ongoing tension between security benefits and usability impact in this feature. Peff's measured skepticism suggests the need for careful consideration before implementing graduated trust levels, as the existing protocol trust mechanism may not cleanly map to the sideband filtering use case. This moves the discussion toward practical implementation constraints rather than reopening the core debate about filtering necessity.
