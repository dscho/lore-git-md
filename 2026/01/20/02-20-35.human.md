This is a bug report about `git submodule update --remote` behavior when a submodule's upstream repository changes its default branch name (e.g. from master to main). D. Ben Knoble encountered an error when the submodule's remote HEAD reference didn't match the actual branch name, despite the repository being otherwise functional.

The issue manifests when the submodule's `.git/modules` directory still references the old branch name in its remote HEAD, while the actual remote repository has updated to use a new default branch name. The error message ("Unable to find refs/remotes/origin/HEAD revision") is confusing and doesn't clearly indicate the root cause.

Knoble found a manual workaround using `git remote set-head`, but suggests the submodule machinery could either handle this case automatically or provide better diagnostics. The report doesn't propose a specific solution, but raises the question of whether Git should be more resilient to this common repository configuration change.
