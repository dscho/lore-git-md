This is a feature patch in the `git repo info`/`git repo structure` series, adding a `default` format option to unify output format handling across commands. The patch is the first of two in v4 of the series, which has already addressed all previous review feedback and is ready for integration.

The change introduces `FORMAT_DEFAULT` as an enum value that serves as a synonym for each command's native format (`keyvalue` for `repo info`, `table` for `repo structure`). This allows users to explicitly request the default format, which is particularly helpful when needing to reset format selection after earlier `--format` options. The implementation includes thorough documentation updates and test coverage verifying the new behavior works as expected.

The patch maintains consistency with the thread's established conventions, including the `_NUL_` documentation standard and the format naming resolution ("lines"/"default") suggested by Patrick Steinhardt. It touches the command implementations in `builtin/repo.c`, updates the man page in `Documentation/git-repo.adoc`, and adds tests in both `t1900-repo.sh` and `t1901-repo-structure.sh`.

This change is part of the larger effort to provide consistent interface for programmatic repository metadata access through the `git repo` command family. The series has evolved through multiple iterations with input from key reviewers including Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila, and now appears ready for final integration.
