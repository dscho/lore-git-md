This is the second patch in Jeff King's 4-part series fixing memory leaks and const-correctness issues in Git's push tracking reference handling. The patch focuses on `tracking_for_push_dest()` in remote.c, changing its return type from `const char *` to `char *` to properly indicate that the function transfers ownership of the allocated string to its caller.

The change is part of a larger effort to clean up the "hacky memory management scheme" introduced in the original 2015 implementation of push tracking. While this particular change doesn't fix any active bugs, it lays groundwork for future improvements by making the ownership semantics clearer in the function signature. The patch updates both the function declaration and the variables that store its result, with no functional changes to the runtime behavior.

This continues the series' pattern of small, precise changes to improve memory handling - a characteristic approach seen in many of Jeff King's contributions. The changes are limited to remote.c and maintain compatibility with existing callers while preparing for subsequent patches that will address actual memory leaks.
