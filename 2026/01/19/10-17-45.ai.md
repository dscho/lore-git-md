This is a feature patch about gettext support detection in Git's version reporting. Jiang Xin's v2 patch implements Junio C Hamano's suggestion to simplify the output by only showing "gettext: enabled" when support exists, remaining silent when disabled. This follows the precedent set by libcurl version reporting rather than the Rust detection approach that shows explicit disabled states.

The patch modifies `help.c` to conditionally report gettext support based on the `NO_GETTEXT` define. Patrick Steinhardt raises a counterpoint that explicit "disabled" reporting helps distinguish between intentionally disabled builds versus older Git versions that lack the feature entirely, though he notes this is not a strong objection. Jiang Xin responds that the Git version number already provides enough context to make this distinction.

The discussion touches on a broader design question about whether diagnostic tools should report negative states or only positive ones. The Rust detection code (commit cb2badb4) currently shows disabled states, while libcurl reporting does not. This patch does not propose changing either existing behavior, focusing only on the new gettext reporting. The thread remains open for further design discussion but appears ready for inclusion in its current form.
