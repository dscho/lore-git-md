Feature patch adding `--maximal` option to `git rev-list`, with ongoing naming discussion.

This email continues the thread about Derrick Stolee's proposed `--maximal` option for `git rev-list`, which would filter the output to show only commits that are not reachable from other commits in the input set (mathematically "maximal" elements in the reachability order). Johannes Sixt raises concerns about the option name being too generic and potentially confusing for average Git users, suggesting alternatives like `--only-maximal`, `--hide-reachable`, or `--range-head-only`.

The technical implementation appears sound, but the interface design remains under debate. Johannes notes that Git typically avoids mathematical terminology in favor of more intuitive names, and suggests the bare `--maximal` may be too vague. He also points out an unexpected interaction with `--boundary` that might need to be addressed by making the options mutually exclusive.

Derrick had previously defended the mathematical precision of `--maximal` from order theory, but Johannes' reply suggests this may not align with Git's usual naming conventions. The discussion remains constructive, with Johannes offering multiple alternative naming possibilities while not challenging the feature's utility or implementation. This thread represents the typical Git mailing list process where interface details receive careful scrutiny even when the underlying code is technically solid.
