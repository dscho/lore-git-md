This is a performance optimization patch in the sparse-checkout subsystem, part of an ongoing series from Amisha Chhajed. The patch changes the pattern sorting implementation from O(n^2) to O(n log n) by switching from `string_list_insert()` to `string_list_append()` followed by sorting.

The thread has reached consensus that the optimization is correct and ready to merge, with Junio C Hamano and Jeff King agreeing that while the algorithmic improvement is clear, the performance impact in practice may not be dramatic enough to warrant dedicated performance tests. Jeff King suggests a one-off benchmark in the commit message would suffice rather than adding permanent perf tests.

Derrick Stolee provided final review feedback suggesting squashing test coverage improvements into the main patch, while Pushkar Singh noted an additional test gap around path normalization cases (e.g. handling "folder1" vs "folder1/"). The optimization itself is considered complete, with any remaining discussion focused on whether to expand test coverage for edge cases before merging.

The changes affect pattern collection in `sparse_checkout_list()` and `write_cone_to_file()` in `builtin/sparse-checkout.c`, maintaining the distinction between cone mode (order-independent) and non-cone mode (order-sensitive) behavior. This work builds on the broader sparse-checkout/sparse-index optimizations led by Derrick Stolee and Elijah Newren.
