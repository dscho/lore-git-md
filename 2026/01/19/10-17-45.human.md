This is a feature patch in an ongoing discussion about how Git should report its gettext (localization) support status in `git version --build-options`. The thread has progressed through two versions, with Jiang Xin implementing maintainer feedback to simplify the output.

The current state shows only "gettext: enabled" when support exists, remaining silent when disabled - a design Junio C Hamano prefers for its simplicity. However, Patrick Steinhardt raises a thoughtful counterpoint that explicit "disabled" reporting helps distinguish between intentionally disabled builds versus older Git versions that lack the feature entirely. Jiang Xin's response notes the version number already provides this context, making the distinction moot.

The patch itself is small and focused, touching only `help.c` to add the gettext detection. While the discussion has expanded to consider similar cases like Rust and libcurl reporting, no code changes beyond the original gettext scope are proposed. The exchange remains constructive, with Patrick explicitly noting he doesn't feel strongly enough to block the current approach.

This appears ready for inclusion unless new design objections emerge. The patch provides clear value for troubleshooting localization issues while following the maintainer's preferred output style. The surrounding discussion about diagnostic reporting philosophy may inform future similar features but doesn't impede this change.
