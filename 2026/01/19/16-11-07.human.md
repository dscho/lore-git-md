This is a follow-up discussion in a bugfix series about reference update error messages. The series (now merged) restored detailed error reporting that was lost when batched reference updates were introduced, affecting `git fetch`, `git update-ref --batch-updates`, and `git receive-pack`.

In this email, Karthik Nayak responds to Phillip Wood's review about the ordering of error messages in `git fetch` output. Phillip pointed out that the current implementation relies on `strmap_for_each()` iteration order, which could change unpredictably. He suggests an alternative approach using arrays to maintain deterministic output ordering.

Karthik acknowledges the concern and indicates he's working on a revised version that will:
1. Collect all updates in an array during `update_local_ref()`
2. Track errors separately in a strmap
3. Print messages in the original order by iterating through the array and looking up errors

This maintains the restored error reporting while addressing the ordering stability issue. The exchange shows the careful attention to detail in Git's output behavior, even when fixing regressions. The discussion is technical but constructive, with Karthik quickly recognizing the merit in Phillip's suggestion.
