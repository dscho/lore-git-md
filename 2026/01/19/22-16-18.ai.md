This is a security discussion thread about ANSI escape sequence handling in Git's sideband channel. brian m. carlson pushes back against Patrick Steinhardt's characterization of the patch series as a security fix rather than a feature, arguing that the threat model is already addressed by other means (SSH already allows similar behavior) and that the changes could break existing pre-receive hooks on GitHub.

The key technical disagreement centers on whether the ANSI sequence filtering should be enabled by default - brian argues it should be opt-in, noting that many users run older Git versions from their distros and might not notice breakage. They point out that terminal title bar injection (a potential attack) is already disabled in modern terminals, and that similar risks exist in other common tools like SSH and `cat`.

The thread context shows this is part of an ongoing discussion about CVE-2024-32002/CVE-2024-52005, where Johannes Schindelin's implementation has evolved through multiple versions to provide granular control over which ANSI sequences are allowed. While the technical implementation has been reviewed and tested (including in production at Git for Windows and Red Hat), brian's comments suggest the security justification may be overstated given existing terminal behaviors and the potential for breaking existing workflows.
