This is the third patch in Jeff King's 4-part series fixing memory leaks and ownership issues in Git's push tracking reference handling. The patch addresses a specific leak in `branch_get_push_1()` when invalid "simple" push configuration is encountered.

The leak occurs when Git's push destination doesn't match the upstream in "simple" push mode - the code returns an error but fails to free the computed push value. While existing tests exercise this path, they don't catch the leak due to LSan (LeakSanitizer) false negatives. Jeff adds a new test using `for-each-ref` that reliably exposes the issue.

The fix is straightforward - adding a `free(cur)` before returning the error. The patch modifies 4 lines in remote.c and adds a 9-line test case in t/for-each-ref-tests.sh. This continues the series' pattern of careful memory management, with each patch building toward cleaning up what Jeff describes as a "hacky memory management scheme" from 2015.

The changes remain focused on remote.c and branch.c, with no user-visible behavior changes beyond fixing the leak. This is typical of Jeff's work - thorough, precise fixes to subtle issues that might otherwise go unnoticed.
