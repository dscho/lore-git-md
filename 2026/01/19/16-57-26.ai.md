Test patch for sparse-checkout cone mode path normalization.

This is the third patch in a series (though no cover letter was provided for context). The test confirms that different forms of the same path ("folder1", "folder1/", "./folder1") all collapse to a single canonical "folder1" entry in the output.

The patch is narrowly focused on testing behavior rather than implementing new functionality. It follows Git's standard test pattern of:
1. Setting up a test repo
2. Performing operations with different path formats
3. Verifying the output matches expected canonical form

The test appears well-constructed and clearly demonstrates the behavior it aims to verify. Since this is part of the sparse-checkout subsystem (an area with active development around performance and usability), such normalization tests help prevent regression of edge cases in path handling.
