Bugfix follow-up addressing output ordering in batched reference updates. This is the final patch in a merged series that restored detailed error messages for batched ref operations (`git fetch`, `git update-ref --batch-updates`, `git receive-pack`), fixing a regression where these messages were lost.

Karthik Nayak responds to Phillip Wood's review of patch 7/7, which handles `git fetch` output. Phillip pointed out that the current implementation's message ordering depends on `strmap_for_each()` iteration, which is unstable. He suggests instead collecting updates in an array and errors in a strmap, then correlating them during output to maintain deterministic ordering.

Karthik confirms this approach has merit and indicates he has a working implementation that will appear in the next version. This addresses the last open issue in the series, though the core functionality (restoring detailed error messages) is already merged and working. The change affects only the display order of success/failure messages during `git fetch`, not the underlying error reporting mechanism.
