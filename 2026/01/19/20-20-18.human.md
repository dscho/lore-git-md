This is the final version of a feature patch series adding `--keys` support to `git repo info` and unifying output format handling across `git repo` subcommands. The series is now ready for integration into `next`, replacing an earlier queued version.

The main addition is a new `--keys` flag that lists available repository metadata keys in a machine-readable format, with options for newline or NUL-terminated output. The implementation standardizes format handling by introducing a `FORMAT_DEFAULT` enum and making "default" a synonym for the "lines" format (rather than "newline" as originally suggested, since the author felt "lines" would be clearer to users).

The series has gone through multiple rounds of review with input from Junio Hamano, Patrick Steinhardt, and documentation feedback from Jean-Noël Avila. All feedback has been addressed, including:
- Using `_NUL_` consistently in documentation
- Adding comprehensive tests for format combinations and default behavior
- Ensuring cross-subcommand consistency in format handling

The implementation touches `builtin/repo.c` for the core functionality and updates documentation and tests. The changes are well-contained and build on existing format infrastructure. With all review feedback incorporated and Junio confirming this properly replaces the earlier queued version, this looks ready to move forward.
