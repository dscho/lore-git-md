This is a performance optimization discussion regarding the sparse-checkout pattern sorting patch series. Jeff King (Peff) responds to Junio C Hamano's question about demonstrating the claimed O(n^2) to O(n log n) improvement in the test suite.

Peff argues that while the performance improvement could theoretically be demonstrated by feeding a very long list of patterns to `git sparse-checkout add --stdin`, such a test would be artificial and not worth adding to the already expensive perf suite. He notes this is a well-understood optimization pattern (replacing sorted insertion with append+sort) that doesn't necessarily require empirical proof, though a one-off benchmark in the commit message would suffice if needed.

The discussion occurs after the v4 patch from Amisha Chhajed has already been approved, with Junio and Derrick Stolee having reviewed the changes. Peff's response suggests the optimization is sufficiently obvious that extensive performance testing isn't required, though the thread shows the project's general preference for empirical validation of performance claims. This comes as part of the ongoing sparse-checkout optimizations led by Derrick Stolee and Elijah Newren.
