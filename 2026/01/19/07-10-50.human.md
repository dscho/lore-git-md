This is a technical discussion email in Patrick Steinhardt's ODB abstraction series, specifically addressing patch 7/14 which introduces the `odb_for_each_object()` interface. The email clarifies the design rationale behind passing `struct object_info` to the iteration function.

Justin Tobler had questioned why callers would need access to the populated `object_info` data beyond configuring attributes. Patrick explains three key reasons: (1) some callers need metadata like object mtimes, (2) the `whence` field identifies the source backend, and (3) performance optimization - it's more efficient to populate object info during iteration than making separate calls afterward, especially for the packfile backend.
