This is a feature patch adding a `--keys` flag to `git repo info` for programmatic repository metadata access, part of a series that's now ready for integration after multiple iterations.

The patch introduces a new `--keys` option that lists available metadata keys without their values, addressing a gap where users previously had to either check documentation or use `--all` to see all key-value pairs. The implementation includes format handling (defaulting to line-based output with NUL`-terminated alternatives) and strict validation to prevent invalid combinations with other options.

Key technical details include:
- New `print_keys()` function handling format-specific output
- `FORMAT_LINES` enum added alongside existing format types
- Documentation updates following the project's `_NUL_` convention
- Comprehensive tests verifying format behavior and option validation
- The implementation builds on prior format unification work and replaces an earlier queued topic (`lo/repo-info-keys`)

The patch has gone through four iterations with feedback from Junio Hamano, Patrick Steinhardt, and Jean-Noël Avila, addressing all review comments including format naming standardization and documentation consistency. This appears to be the final version before integration into `next`.
