This is a bugfix series addressing memory leaks in remote.c, triggered by an upcoming topic. Jeff King (Peff) has identified and fixed several issues in the most critical being a leak that occurs with invalid "simple" push configuration.

The series starts with two preparatory cleanups (patches 1-2) that adjust function signatures to better handle memory ownership. The main fix (patch 3) plugs a leak in `branch_get_push_1()` when parsing malformed push configuration, adding a new test case to prevent regression. The final patch (4) fixes a theoretical leak that isn't currently triggerable, making it more of a proactive cleanup.

The changes are relatively small (24 lines modified across 3 files) but important for correctness. As Peff notes, these aren't urgent but should be merged before the related "hn/status-compare-with-push" topic. The patches follow Peff's characteristic style - precise, well-explained, and thoroughly tested.
