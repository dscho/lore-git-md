This is a follow-up discussion about a feature patch to report gettext support in Git's version output. The thread involves maintainer preferences around feature detection visibility.

Patrick Steinhardt weighs in on Junio Hamano's suggestion to simplify the gettext detection output to only show "enabled" (omitting the "disabled" state). While acknowledging Junio's preference, Patrick makes a case for explicit disabled reporting to distinguish between:
1. Modern Git built without gettext (would show "disabled")
2. Older Git that lacks the detection feature entirely (would show nothing)

He extends this reasoning to libcurl version reporting as well, suggesting similar explicit disabled states would be useful there too. However, Patrick notes he doesn't feel strongly about this and is just presenting the counter-argument.

The discussion remains technical and collegial, with Patrick's email serving as a thoughtful counterpoint rather than a challenge. This follows Jiang Xin's v2 patch which already implemented Junio's simpler approach in `help.c`, showing only positive gettext detection. The Rust detection precedent (showing both states) remains unchanged for now.

Key technical detail: the debate centers around the diagnostic value of negative state reporting versus output simplicity, with implications for similar features like libcurl version strings. The patch itself is straightforward - it's the design philosophy that's being discussed.
