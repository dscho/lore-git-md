This is the third patch in Jeff King's 4-part series addressing memory leaks and const-correctness in Git's push tracking reference handling. The patch fixes a specific memory leak in `branch_get_push_1()` that occurs when invalid "simple" push configuration is detected.

The issue occurs when Git's push tracking reference is computed but then rejected due to a mismatch with the upstream reference in "simple" push mode. While the error is correctly reported, the allocated string for the push reference was being leaked. Peff's fix adds the missing `free()` call in this error path.

Interestingly, the existing tests didn't catch this leak under LSan (LeakSanitizer), likely because the test cases triggered an early exit. Peff demonstrates how to reliably reproduce the leak using `git for-each-ref` and includes a new test case that verifies the fix. The change is minimal (just 4 lines modified in remote.c) but important for correct memory management.

This continues Peff's characteristic thorough approach to memory management issues - catching and fixing leaks proactively, even when they might not be immediately problematic. The patch builds on the groundwork laid in the first two patches of the series by applying the cleaner ownership semantics to fix a real leak scenario.
