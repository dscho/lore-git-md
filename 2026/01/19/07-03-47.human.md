This is a follow-up discussion about a feature patch to report gettext support in Git's version output. Patrick Steinhardt weighs in on Junio C Hamano's suggestion to simplify the output by only showing "gettext: enabled" when support exists (omitting the disabled state).

Patrick makes a nuanced argument for keeping the disabled state reporting, noting it helps distinguish between:
1. Modern Git built without gettext (would show "disabled")
2. Older Git versions that don't support this reporting at all (would show nothing)

He extends this reasoning to libcurl version reporting as well, suggesting consistency in showing disabled states could be diagnostically useful. However, Patrick explicitly states he doesn't feel strongly about this position, leaving the final decision to the maintainer.

The exchange shows careful consideration of backward compatibility and diagnostic clarity, with Patrick deferring to Junio's judgment despite offering a counter-perspective. The thread appears to be wrapping up with no major contention - just a thoughtful last-minute consideration before the patch gets finalized.
