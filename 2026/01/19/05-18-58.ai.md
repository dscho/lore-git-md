This is a bugfix series addressing memory leaks in the remote.c subsystem, with Jeff King (Peff) as the author. The series consists of 4 patches that clean up and fix memory handling around push tracking references.

The first two patches are preparatory cleanups that change function signatures to be more consistent with memory ownership rules - removing const returns from functions that allocate memory. The third patch fixes an actual memory leak that was exposed by Harald's "status-compare-with-push" topic, where invalid "simple" push configuration could cause a leak in branch_get_push_1(). The fourth patch is a defensive cleanup that ensures memory is always allocated for branch.push_tracking_ref, even though the leak likely can't be triggered in practice.

The changes are relatively small (24 lines modified across 3 files) but demonstrate Jeff King's characteristic attention to detail in memory management. The series includes new test coverage in t/for-each-ref-tests.sh to verify the fixes. While not urgent (the leaks are old), the patches are well-motivated by upcoming changes and follow the project's standards for thoroughness.
