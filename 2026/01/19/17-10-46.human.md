Platform compatibility fix for a flaky reftable test on Cygwin. This is a follow-up to an earlier discussion about intermittent test failures when running t0610-reftable-basics.sh in parallel on Windows 11.

Ramsay Jones reports that test #29 ('ref transaction: corrupted tables cause failure') fails sporadically when run with parallel jobs (-j8), but passes when run serially. The failure occurs when trying to corrupt reftable files using shell redirection (`: >file`), resulting in a "Permission denied" error. The patch replaces this shell redirection with a call to `test-tool truncate`, which appears to work around the issue.

Patrick Steinhardt confirms this approach based on prior experience with similar Cygwin issues, though the root cause remains unclear (Ramsay investigated with strace but couldn't pinpoint it). The one-line change is minimal and follows Git's established pattern of preferring test helpers over shell builtins for reliability on Windows platforms. Both contributors agree the fix is worth merging despite the unknown underlying cause.

This continues Git's ongoing efforts to improve test stability, particularly for the reftable backend on Windows. The discussion references previous similar fix for Cygwin-specific test flakiness, showing this is a known pattern in the test infrastructure.
