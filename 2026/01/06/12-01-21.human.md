This is a UI improvement patch for `git add -p`'s interactive hunk selection interface. The patch modifies the prompt to show whether a hunk was previously marked for use ('y') or skip ('n') when navigating between hunks.

The change makes it clearer for users to see their previous decisions when moving between hunks with K/J' navigation keys. The implementation adds a "(previous decision: use/skip)" indicator in the prompt string for each hunk type (mode change, deletion, addition, etc.) across all patch modes (stage, stash, unstage, etc.).

The patch is in its 6th iteration, with Junio C Hamano having originally reported the issue. The changes are focused and well-contained, touching only the prompt strings in `add-patch.c` and updating corresponding test expectations. The test changes verify the new behavior works correctly with various navigation commands (g, /, p) and maintains color output consistency.

This appears to be a straightforward quality-of-life improvement that makes the interactive interface more user-friendly without introducing complexity. The patch looks clean and well-tested, with no obvious issues in the implementation.
