This is the first patch in Patrick Steinhardt's two-patch bugfix series addressing memory management issues, now in its third iteration. The patch fixes two related bugs in the commit-graph auto-generation logic within `builtin/gc.c`:

1. A memory leak occurring when counting merge commits, caused by incorrect use of `commit_list_append()` which was dropping parent commits from the traversal stack. The fix replaces this with `commit_list_insert()` to properly maintain the stack.

2. A miscounting issue where tip objects weren't marked with the SEEN flag, causing them to be counted multiple times if reachable via multiple references. The patch adds proper SEEN flag handling.

The changes are accompanied by a new test case in `t/t7900-maintenance.sh` that verifies correct behavior with merge commits. The test creates a repository with merge commits and verifies the auto-generation threshold works as expected.

This patch has gone through multiple review iterations with feedback from Justin Tobler, Karthik Nayak, and Toon Claes. All technical concerns have been addressed, and the patch has received final review acks. The changes are focused and well-contained, touching only the necessary parts of the commit-graph generation logic while adding robust test coverage.

The patch is part of a larger effort to improve Git's memory management, particularly around maintenance operations. It stands independently from the second patch in the series which fixes a separate ODB leak in submodule handling. Both patches are now considered merge-ready with all reviewer feedback incorporated.
