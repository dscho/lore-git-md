This is part 3/7 of Patrick Steinhardt's v3 series refactoring Git's object info handling, focusing on the packfile subsystem. The patch extends the `is_delta` boolean field in `struct object_info` to a 4-state enum that can represent unknown, full, ref-delta, and ofs-delta object types. 

The change prepares for future improvements where we may not always know an object's delta status - particularly when skipping full object parsing for size-only queries. While callers currently only check for "is delta" vs "not delta", the more granular tracking preserves information that could help abstract packfile implementation details from generic object handling interfaces later. The patch touches `odb.h` (adding the enum) and updates two packfile.c functions to use it, maintaining all existing behavior while enabling future optimizations.

This continues the series' theme of interface improvements for the ODB abstraction effort, with Patrick noting the current lack of an immediate use case for the "unknown" state while justifying its inclusion for future-proofing. The implementation is straightforward, converting the simple delta check to a switch statement while preserving all existing functionality.
