This is a test infrastructure patch fixing an issue in Git's performance test framework. Jeff King (Peff) identifies and corrects a bug in how `TEST_OUTPUT_DIRECTORY` gets assigned when running performance tests, which was causing test results to be written to the wrong location.

The problem manifests when running performance tests from a vanilla build - the test aggregation script fails because it can't find the output files, which are being written to `t/test-results` instead of the expected `t/perf/test-results`. The root cause is a timing issue in variable assignment: the performance test script was setting `TEST_OUTPUT_DIRECTORY` before loading `GIT-BUILD-OPTIONS`, which would then clobber that value.

The fix is straightforward - delay setting `TEST_OUTPUT_DIRECTORY` until after loading the build options, and only set it if not already defined. This preserves the out-of-tree build fix from commit 5756ccd181 while restoring the correct behavior for in-tree builds. The patch includes a thorough explanation of the issue, why it went unnoticed (aggregation isn't commonly used and stale files might mask it), and how the solution works.

This is a mechanical but important fix to the test infrastructure, coming from one of Git's most experienced test framework contributors. The change is small (3 lines modified) and focused, with clear justification in the commit message. It's part of a two-patch series addressing performance test issues, with the second patch handling environment variable preservation.
