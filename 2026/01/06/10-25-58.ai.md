Performance optimization for `git cat-file` bitmap usage. This patch fixes a regression introduced in commit 8002e8ee18 where `git cat-file` would unnecessarily load bitmap indexes even when not filtering objects, causing significant performance degradation for non-filtered operations. Jeff King provides detailed performance measurements showing a 331% slowdown when listing all objects in sorted order, while confirming bitmap usage remains beneficial for filtered cases (65% speedup when listing blobs).

The fix modifies `builtin/cat-file.c` to only prepare and use bitmaps when an object filter is actually enabled. The patch includes new performance tests that clearly demonstrate the regression and its resolution. The changes maintain the bitmap optimization for filtered operations while restoring original performance for unfiltered cases.

Key technical details:
- Bitmaps are now only loaded when `opt->objects_filter.choice` indicates an active filter
- The performance tests measure three scenarios: sorted object listing (regressed case), unsorted listing, and filtered listing
- The fix avoids unnecessary bitmap loading and expensive sorting operations when no filtering is needed

This is a well-motivated performance fix from a trusted contributor, with clear benchmark evidence showing both the problem and solution. The patch is focused and maintains existing functionality while fixing a clear regression.
