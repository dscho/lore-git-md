This is part 2/7 of Patrick Steinhardt's v3 series refactoring Git's object info handling, focused on simplifying the interface by removing the OI_DBCACHED distinction. The patch eliminates the special case for objects in the delta base cache, treating them all as OI_PACKED instead.

The change simplifies the object info interface by removing what was essentially an implementation detail (whether an object was in the delta base cache) that callers didn't need to know about. The patch notes that the three callers that do check the `whence` field either get strictly more information (by now including deltified objects) or were potentially making incorrect assumptions about promisor packs by excluding cached objects.

The implementation is straightforward - just removing the OI_DBCACHED enum value and always returning OI_PACKED. This continues the series' theme of cleaning up the object info interface while maintaining all existing functionality. The patch has already been reviewed in previous iterations, with Toon Claes having confirmed the approach in v2.
