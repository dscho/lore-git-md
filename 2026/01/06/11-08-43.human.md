This is a UI improvement for `git add -p` that adds visual feedback about previous hunk decisions. The patch (now at v5) modifies the interactive interface to show whether each hunk was previously marked for use ('y') or skip ('n') when navigating between hunks. 

The change originated from a report by Junio C Hamano and has gone through several iterations to address feedback. The latest version fixes an uninitialized variable issue found in testing. The implementation touches the prompt strings in `add-patch.c` and includes corresponding test updates in `t3701-add-interactive.sh`.

The patch appears well-tested and addresses a clear usability issue. Kristoffer Haugsbakk notes a minor documentation nit (a duplicated "Reported-by" line) but this doesn't a technical concern. With all previous feedback addressed and no outstanding objections, this looks ready for merging as a straightforward quality-of-life improvement to the interactive patch interface.
