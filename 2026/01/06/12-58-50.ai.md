This is a bugfix patch addressing a submodule ODB (object database) memory leak. It's the second and final patch in Patrick Steinhardt's v3 series of memory management fixes, now fully reviewed and ready for merging.

The patch fixes a 192-byte memory leak that occurs during `git grep` operations on submodules. The root cause is an incorrect cleanup sequence in `odb_free()` where sources were being freed before being closed, making the subsequent close operation a no-op. The fix simply reorders these operations to ensure proper cleanup.

Key technical details:
- The leak occurs when reading from submodules via `repo_submodule_init()`
- The fix changes the cleanup order in `odb.c` to call `odb_close()` before `odb_free_sources()`
- The patch is minimal (a single line change) but effectively plugs the leak
- Includes a detailed stack trace showing the leak's origin and reproduction scenario

The patch has gone through multiple review iterations with Justin Tobler and Karthik Nayak providing final acks. It's now considered technically sound and ready for integration, with no outstanding concerns. This completes the series of memory management improvements that started with the commit-graph writing fix in the first patch.
