This is a UI refinement patch for `git add -p`'s interactive hunk selection, part of an ongoing GSoC project. The discussion focuses on optimizing the display of previous hunk decisions ('y' or 'n') during navigation.

Ben Knoble suggests displaying the decision status on a separate line before the prompt to avoid length issues, responding to Phillip Wood's concern that the current implementation makes some prompts exceed 80 characters. This builds on Abraham Samuel Adekunle's v6 patch that added the decision indicators, which Junio Hamano originally suggested to improve navigation clarity.

The exchange represents thoughtful iteration on the UI wording - while the core functionality is sound and well-contained in `add-patch.c`, the team is now fine-tuning the presentation for optimal readability. The patch remains focused on improving user experience without altering the underlying hunk selection logic.
