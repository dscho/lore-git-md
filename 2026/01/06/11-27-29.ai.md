Bugfix addressing commit-graph memory leak and miscounting issues in `builtin/gc.c`. This is the first patch in Patrick Steinhardt's v2 series that has already received review acks and is ready for merging.

The patch fixes two distinct but related problems in the commit-graph auto-generation logic. First, it corrects a memory leak that occurred when processing merge commits by replacing `commit_list_append()` with `commit_list_insert()`. The original code was incorrectly using the append function, causing it to lose track of all but the most recent parent commit. This both leaked memory and caused incorrect counting of commits not covered by the graph.

Second, the patch fixes a miscounting issue where objects at the tip of references weren't properly marked as SEEN, causing them to be counted multiple times if reachable via multiple references. The fix ensures proper SEEN flag handling while maintaining the depth-first search behavior.

Karthik Nayak's review confirms the technical correctness of the changes but raises two follow-up questions: whether the fix might make commit-graph generation slower for repositories with many merges (since it now properly follows all parent paths), and whether the test case should also verify the double-counting fix for tip objects. These don't appear to block the patch's acceptance but may warrant future consideration.

The patch includes new test coverage in `t/t7900-maintenance.sh` that verifies the merge commit handling works correctly, though as noted in review, it doesn't explicitly test the tip object counting fix. The changes are well-contained and have been reviewed by multiple contributors, with Justin Tobler providing the final ack.
