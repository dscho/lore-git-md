This is a bug report about unexpected behavior in `git diff --relative`. Johannes Sixt (Hannes) demonstrates that when using `--relative=Makefile`, Git treats the argument as a text prefix rather than interpreting it as a directory path. The example shows that `--relative=Ma` matches and strips the prefix from "Makefile", producing the nonsensical output "kefile".

The issue appears to be in how `--relative` processes its argument - it's doing simple string prefix matching when it should likely be treating the argument as a directory path and doing path-based prefix stripping. This could affect any use of `--relative` with partial path components.

The bug is concise and clearly demonstrated, though it doesn't specify whether this is a regression or long-standing behavior. The reporter is a known Windows/Git for Windows expert, suggesting this likely came up in real usage rather than being a theoretical concern. The behavior does seem clearly incorrect based on the example provided.
