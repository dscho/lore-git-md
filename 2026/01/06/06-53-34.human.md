This is a performance investigation thread about `git pack-refs --all` slowness on large repositories with millions of refs. Patrick Steinhardt responds to Martin Fick's latest analysis, which shows that Git spends most of its time (4 out of 4.15 minutes) in gaps between writes rather than in the writes themselves.

Martin's new theory is that the slowdown may come from slow mmap reads of the packed-refs file over NFS, or possibly inefficient in-memory ref lookups. Patrick confirms that NFS has been problematic at GitLab (leading them to stop using it entirely) and asks if any special NFS mount flags are in use. He also suggests using `perf` to generate a flame graph to pinpoint where Git is spending time.

The thread has evolved from initial I/O-focused theories to now examining memory access patterns, particularly around mmap behavior over NFS. Patrick's response keeps the investigation moving forward with concrete next steps while validating Martin's latest findings. The exchange shows productive technical collaboration to diagnose a complex, real-world performance issue.
