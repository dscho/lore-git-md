Performance test infrastructure fix by Jeff King addressing an output directory issue in the performance test framework.

This is the first of two patches fixing issues in Git's performance test infrastructure (`t/perf/`). The problem occurs when running performance tests in a vanilla build - the test results end up in the wrong directory (`t/test-results` instead of `t/perf/test-results`), causing the aggregation script to fail when it can't find the expected output files.

The root cause traces back to commit 5756ccd181 which fixed out-of-tree builds but inadvertently broke the default case. Jeff's solution is to defer setting `TEST_OUTPUT_DIRECTORY` until after loading build options, ensuring the correct path is used. The patch is straightforward with a small, focused change to `t/perf/perf-lib.sh`.

This appears to be a well-constructed fix from a trusted contributor in the test infrastructure domain. The commit message thoroughly explains both the problem and solution, including why the issue may have gone unnoticed (aggregation isn't commonly used, and stale results might mask the problem). The change maintains the fix for out-of-tree builds while restoring the correct behavior for vanilla builds.
