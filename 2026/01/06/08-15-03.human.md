This is a bug report about `git diff --relative` behavior. Johannes Sixt (Hannes) demonstrates that when using `--relative=Makefile`, Git appears to treat the argument as a text prefix rather than interpreting it as a directory path. The example shows `git diff --name-only --relative=Makefile` producing unexpected output when run after modifying the Makefile.

The issue suggests a mismatch between the documented/intended behavior (where `--relative` should take a directory path) and the actual implementation (which seems to do simple string prefix matching). This could affect users who rely on `--relative` for filtering diff output to specific subdirectories.

The report is concise but clear, coming from an experienced contributor (the Git GUI and gitk maintainer) who specializes in Windows and low-level behavior. The impact appears limited to this specific edge case of `--relative` usage, but the behavior does seem counterintuitive enough to warrant investigation.
