This is the first patch in Patrick Steinhardt's v3 series refactoring Git's object info handling, part of the ongoing ODB (object database) abstraction effort. The patch fixes an inconsistency in `odb_source_loose_read_object_info()` where early return paths weren't properly setting the `OI_LOOSE` flag in the `object_info` struct, even though the object being examined was indeed loose.

The change ensures `oi->whence` is always set to `OI_LOOSE` when successfully reading a loose object, regardless of which code path is taken. While no current callers rely on this field in these cases, the patch prevents future bugs by making the behavior consistent. The implementation carefully maintains all existing functionality while adding the missing assignments, touching only the loose object handling code in `object-file.c`.

This is a straightforward cleanup that improves interface consistency without changing behavior, setting the stage for later patches in the series that build on these object info interfaces. The change has already been reviewed in previous iterations (v1 and v2) and now includes minor documentation fixes from Kristoffer Haugsbakk.
