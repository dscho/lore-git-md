This is patch 4/7 in Patrick Steinhardt's series refactoring Git's object info handling, part of the ongoing ODB (object database) abstraction effort. The patch addresses an inconsistency in how packfile-specific object information is populated when reading objects.

The key change ensures that `packed_object_info()` always fills in the pack-specific fields of the `object_info` struct (offset, pack pointer, and delta type) rather than sometimes leaving them unset. This makes behavior consistent between the two main paths for reading packed objects - `packed_object_info()` and `packfile_store_read_object_info()`.

The implementation moves the pack-specific field population from `packfile_store_read_object_info()` to `packed_object_info()`, where it logically belongs since these fields are inherently pack-related. The diff shows the code being deleted from one function and added to the other while maintaining identical functionality.

This is a straightforward cleanup that removes a subtle inconsistency in the object info API, making it more predictable for callers. As with the rest of the series, this change supports the larger goal of abstracting Git's object storage layer while improving internal consistency. The patch appears well-contained and low-risk, touching only packfile.c with no interface changes.
