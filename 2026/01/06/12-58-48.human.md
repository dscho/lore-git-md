This is a bugfix series from Patrick Steinhardt addressing two memory management issues in Git's object database handling. The v3 iteration has incorporated all review suggestions and is now merge-ready.

The first patch fixes a commit-graph writing condition in `builtin/gc.c` that was both leaking memory and double-counting objects during depth-first searches. The fix replaces `commit_list_append()` with `commit_list_insert()` and properly handles SEEN flags. Test coverage has been strengthened to verify the fix handles merge commits correctly.

The second patch corrects a submodule ODB leak in `odb.c` where sources weren't being properly closed before being freed, causing a 192-byte leak per submodule access during `git-grep` operations. This is a minimal but important fix.

The series has gone through multiple rounds of review with Justin Tobler, Karthik Nayak, and Toon Claes verifying the technical correctness. All feedback has been addressed in this final iteration, with only one non-blocking test suggestion from Karthik left for potential future work. The patches are cleanly separated from a withdrawn geometric repack patch that uncovered deeper promisor pack issues needing separate attention.
