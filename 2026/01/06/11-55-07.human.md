Bugfix for commit-graph memory leak and miscounting in auto-maintenance. This is the final version of Patrick Steinhardt's patch series addressing two issues in the commit-graph writing logic during `git maintenance`.

The first patch fixes a memory leak that occurred when counting merge commits during the depth-first search to determine if a new commit-graph is needed. The root cause was incorrect use of `commit_list_append()` which discarded parent commits. The fix replaces it with `commit_list_insert()` and includes new test coverage for merge commit scenarios.

The second issue fixed is a miscounting problem where tip objects weren't properly marked as seen, causing them to be counted multiple times if reachable via multiple references. The test case has been updated to catch this by using `test_commit()` which creates lightweight tags.

The series has been thoroughly reviewed by Justin Tobler and Karthik Nayak, with Karthik's suggestion to add additional test coverage for the tip object counting being noted as a potential future improvement. Both patches are now merge-ready with all feedback addressed. The changes are well-contained and focused specifically on fixing these memory management issues in the commit-graph auto-generation logic.
