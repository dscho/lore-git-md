This is a proposal to add Bazel build support to Git, currently facing significant technical objections. Son Luong Ngoc responds to brian m. carlson's concerns about their initial implementation, which hardcodes paths and platform assumptions in ways that would break existing Git build flexibility.

The author acknowledges the maintenance burden of supporting a fourth build system (alongside Make, Meson, and contrib/CMake) and indicates they'll pursue an out-of-tree approach unless more community maintainers step forward. They outline how Bazel's toolchain system could eventually address the configurability issues raised, particularly around shell/perl/python paths, but this remains unimplemented.

The exchange highlights the tension between Bazel's opinionated build philosophy and Git's need for platform flexibility. While the author shows technical understanding of how to improve the implementation, the path forward remains uncertain - either as an unofficial community-maintained option in the Bazel Central Registry or (less likely) as an in-tree build system if configurability gaps can be closed. The thread leaves open whether this will gain enough traction to overcome the project's general reluctance to additional build system complexity.
