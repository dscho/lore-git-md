Bugfix for `git diff --relative` path handling. This is a response to Harrison McCullough's bug report about unexpected filename processing when using `--relative=<path>`, where the option strips prefixes from directory paths and also from unrelated filenames that happen to start with the same prefix (e.g., showing `foo.txt` as `.txt` when using `--relative=foo`).

Ben Knoble confirms the bug is easily reproducible and suggests the current behavior may stem from a documentation ambiguity. He interprets the man page as implying `--relative=<path>` is primarily intended for bare repositories, with working trees expected to use `--relative` from within the target directory (via `cd`). The response hints that while the current prefix-stripping behavior might have niche scripting uses, the documentation should be clearer about intended usage patterns.

The thread now has two clear positions: Harrison's original report frames this as a bug in path matching logic, while Ben's response suggests it might be a documentation issue.
