This is a bugfix patch in the commit-graph writing logic that has already gone through multiple rounds of review and is now receiving final acks before merging.

Karthik Nayak confirms the technical correctness of Patrick Steinhardt's fix for a memory leak and commit counting issue in `builtin/gc.c`. The problem occurred when using `commit_list_append()` incorrectly during commit graph generation, causing merge commit parents to be miscounted and leaking memory. The fix replaces this with `commit_list_insert()` to properly handle all parents.

The discussion reveals that while the fix makes the traversal more thorough (now correctly following all merge parents), the performance impact should be negligible because the walk is bounded by the `maintenance.commit-graph.auto` threshold (default 100 commits) and stops at commits already covered by the graph. Karthik notes the fix was necessary regardless of any potential impact.

This patch is part of a two-patch series that has now received final review acks from multiple reviewers (Karthik Nayak, Justin Tobler, Toon Claes) and appears ready for merging. The other patch in the series fixes a separate submodule ODB leak. Both address memory management issues that were identified during review of a larger geometric repack effort, though the repack work itself has been deferred due to deeper promisor pack issues.
