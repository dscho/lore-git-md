This is a bugfix patch addressing memory management issues in the commit-graph writing logic, now in its final reviewed state. The patch fixes two distinct issues in `builtin/gc.c`:

1. A memory leak during depth-first search when counting commits for commit-graph generation, where `commit_list_append()` was incorrectly used and would lose parent commits. The fix replaces it with `commit_list_insert()` to properly maintain the commit list.

2. A miscounting issue where tip objects weren't marked as SEEN, causing them to be double-counted if reachable via multiple references. The patch ensures proper SEEN flag handling.

The changes are well-validated with:
- A new test case in `t/t7900-maintenance.sh` covering merge commit scenarios
- Confirmation from multiple reviewers (Karthik Nayak, Justin Tobler, Toon Claes)
- Clear reproduction scenarios for both issues
- Karthik noted the test could be enhanced to explicitly verify tip object counting, though this isn't blocking
- Performance impact is expected to be negligible in practice due to the bounded nature of the walk
- The fixes are contained to commit-graph auto-generation logic
- All feedback has been addressed in this final iteration
- The patch is now merge-ready with multiple acks

Technical details for future reference:
- Changes focus on `should_write_commit_graph()` in `builtin/gc.c`
- Uses depth-first search via `dfs_on_ref()` helper
- Bounded by `maintenance.commit-graph.auto` threshold (default 100)
- Test covers merge commit counting behavior
- Performance scales with number of refs but remains bounded
