This is a documentation clarification regarding the `git diff --relative` behavior reported as a bug. Ben Knoble responds to Harrison McCullough's report about `--relative=foo` unexpectedly stripping "foo" from filenames like `foo.txt` (producing `.txt`) in addition to correctly showing files under `foo/`.

Ben suggests the documentation may be unclear about intended usage - that `--relative` without a path is meant for working trees (where you'd cd into the directory first), while `--relative=<path>` is primarily for bare repositories. He notes the current behavior could be useful for ad-hoc scripting but agrees the docs should be clearer about the distinction.

The response doesn't propose a code fix but focuses on interpreting the documentation's intent, implying the behavior might be working as designed (if poorly documented) rather than being an outright bug. This shifts the discussion toward whether to clarify the docs or change the implementation to match user expectations.
