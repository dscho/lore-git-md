This is a performance investigation email in an ongoing thread about `git pack-refs --all` slowness on large repositories with millions of refs. Jeff King (Peff) responds to Martin Fick's latest findings, which show that the actual write operations are fast but there are long gaps between them, suggesting memory access patterns rather than I/O as the bottleneck.

Peff analyzes several possibilities: reading object data from packfiles (which would involve random access), sequential reading of the packed-refs file via mmap (which might suffer from poor NFS read-ahead), and binary search operations (which he rules out for this phase). He suggests two concrete next steps: using perf to profile where time is being spent, and trying a NO_MMAP build to make I/O patterns more visible in strace.

The email advances the investigation by narrowing the focus to memory access patterns, particularly around mmap behavior with NFS, while maintaining the thread's technical rigor.
