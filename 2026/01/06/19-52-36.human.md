This is a bugfix discussion about Git's handling of non-UTF-8 encoded `.gitignore` (exclude) files, particularly focusing on Windows UTF-16LE files with BOM that PowerShell creates. The thread has evolved from a technical implementation discussion to a deeper design question about Git's text handling philosophy.

Matthieu Beauchamp-Boulay originally proposed comprehensive Unicode handling that would convert all exclude files to UTF-8, but Junio C Hamano and brian m. carlson have challenged the fundamental premise. They point out that Git historically treats exclude patterns as byte sequences that should match the platform's native encoding of filesystem paths, not necessarily UTF-8. The discussion now centers on whether to:
1. Implement full Unicode conversion (original approach)
2. Make a narrow fix just for Windows UTF-16LE BOM cases
3. Maintain the status quo with better user education

The patch author acknowledges misunderstanding Git's encoding assumptions and plans to revise the approach. This touches on cross-platform consistency questions and how Git handles text encoding in various subsystems (config files, attributes, etc.). The thread remains active with no clear resolution yet, but appears to be moving toward a more limited solution that preserves Git's existing byte-sequence matching behavior while possibly adding Windows-specific handling.
