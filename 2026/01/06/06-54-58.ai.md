This is part 2/7 of Patrick Steinhardt's performance and refactoring series for Git's object info handling, specifically focusing on simplifying the interface by removing the OI_DBCACHED distinction. The patch removes an implementation detail that callers don't actually need - the difference between objects stored in packfiles versus those in the delta base cache.

The change eliminates the OI_DBCACHED enum value entirely, making all packfile-sourced objects report as OI_PACKED. This simplification is justified because:
1. The delta base cache status can already be determined via the existing `is_delta` field
2. The three callers that check `whence` either want to confirm packfile membership (which should include cached deltas) or are checking promisor pack status (where cache residency shouldn't affect the answer)

The patch touches `odb.h` (removing the enum value) and `packfile.c` (removing the conditional assignment). This continues the series' theme of interface simplification while maintaining all functionality - a clean improvement that reviewers have already approved in previous iterations. The change is small but meaningful, removing a distinction that added complexity without providing value to callers.
