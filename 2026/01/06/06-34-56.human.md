This is part 3/7 of Patrick Steinhardt's series refactoring Git's object info handling, focusing on delta object representation. The patch extends the `is_delta` field to track not just whether an object is a delta, but what kind (ref-delta or ofs-delta) or if the state is unknown (when skipping full object parsing).

Toon Claes raised a question about whether distinguishing between ref-delta and ofs-delta types is necessary at this interface level, noting that current callers don't use this distinction. Patrick explains that while not immediately needed, preserving this information now makes future work easier - specifically for eventually removing the `OBJ_*_DELTA` constants that currently leak packfile implementation details into generic interfaces.

The change is preparatory for patch 6/7 which will properly handle cases where object parsing is skipped (yielding "unknown" delta state). Patrick has already incorporated Toon's minor documentation feedback about clarifying which subsequent commit implements the new state. The discussion shows careful interface design balancing immediate needs with long-term architectural goals in the ODB abstraction effort.
