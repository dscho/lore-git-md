This is a bugfix discussion thread about Git's handling of encoding in `.gitignore` (exclude) files, particularly focusing on Windows UTF-16LE files with BOM. The original patch proposed comprehensive Unicode handling, but the discussion has shifted to fundamental design questions after brian m. carlson demonstrated Git's existing ability to match non-UTF-8 patterns.

Matthieu Beauchamp-Boulay responds to Junio C Hamano's feedback, acknowledging two key points: (1) Git does not universally assume UTF-8 for paths (contrary to the original patch's premise), and (2) the terminology should use "exclude" rather than "ignore" to match Git's codebase conventions. The author indicates these will be addressed in a revision.

The thread now faces deeper questions about whether exclude files should follow UTF-8 assumptions (which would help Windows users) or maintain Git's historical byte-sequence matching behavior. This connects to broader concerns about consistency with other subsystems like config and attributes. The discussion remains active with no clear resolution yet on the fundamental approach.
