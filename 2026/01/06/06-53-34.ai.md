This is a performance investigation thread about `git pack-refs --all` slowness on large repositories with millions of refs. Patrick Steinhardt responds to Martin Fick's latest analysis showing that the performance bottleneck appears to be in memory access patterns rather than I/O operations.

The key new insight is that while actual write operations execute quickly (29K writes completing in just 15 seconds total), Git spends about 4 minutes of the 4m15s runtime in gaps between writes. Martin hypothesizes this could be due to slow mmap reads of the packed-refs file over NFS or inefficient in-memory ref lookup algorithms. Patrick confirms NFS has been problematic in their experience at GitLab and suggests using perf(1) to generate a flame graph to pinpoint the exact bottleneck.

The discussion has shifted from earlier focus on write buffering and verification overhead to now examining memory access patterns, particularly how Git interacts with mmap over NFS. This remains part of the broader investigation into why Git's files backend performs significantly slower than JGit in high-refcount Gerrit environments, despite both doing equivalent object verification.
