This is patch 5/7 in Patrick Steinhardt's series refactoring Git's object info handling for ODB abstraction. The patch simplifies the return value semantics of `packed_object_info()` to return only success/failure status rather than mixing object type information with error codes.

The key change is making `packed_object_info()` return 0 on success and negative on error, rather than returning an `enum object_type` that was previously used to encode both object types and error conditions. This cleanup is possible because the last caller that relied on the object type return value was removed in the previous patch. The change also enables a small optimization by allowing the function to skip reading the object type in some cases.

The patch touches `packfile.c` and `packfile.h`, updating the implementation and adding clearer documentation about the return value contract. All error paths are converted to return -1 consistently, and the calling function `packfile_store_read_object_info()` is updated to match the new return value convention.

This is a straightforward cleanup that follows naturally from the previous changes in the series, maintaining the high quality standard seen so far. The change is well with the ODB abstraction effort by making the packed object info interface more predictable and easier to work with.
