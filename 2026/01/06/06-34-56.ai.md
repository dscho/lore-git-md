This is a performance optimization patch in Patrick Steinhardt's ongoing ODB abstraction effort, specifically addressing delta object handling in packfiles. The patch extends the `is_delta` field in `struct object_info` from a simple boolean to a 4-state enum (unknown/full/ref-delta/ofs-delta) to properly handle cases where object parsing is skipped for performance reasons.

Toon Claes raised a question about whether distinguishing between ref-delta and ofs-delta types is necessary at this interface level, noting that current callers don't use this distinction. Patrick acknowledges this but explains the distinction serves future-proofing purposes - it preserves information that could help eventually remove packfile implementation details (OBJ_*_DELTA constants) from generic object interfaces. The thread shows careful consideration of interface design tradeoffs between current simplicity and future flexibility.

The change is part of a larger series that already has Toon's approval for the OI_DBCACHED removal in patch 2/7, with this patch 3/7 preparing for the size-optimization in patch 6/7 that skips full object parsing when only size information is needed. Patrick has already incorporated Toon's minor documentation suggestion about clarifying the "next commit" reference. The discussion demonstrates the project's attention to interface design while making measurable performance improvements (~9% speedup in certain cases).
