This is a refactoring patch in Patrick Steinhardt's ongoing series to make packfile storage source-aware in preparation for pluggable object database backends. The patch focuses specifically on the kept-pack cache, which tracks packfiles marked as kept (either on-disk via .keep" files or in-memory flags).

The key changes:
- Moves the kept-pack cache from being repository-scoped to being owned by the packfile store
- Renames the cache accessor from `kept_pack_cache()` to `packfile_store_get_kept_pack_cache()`
- Documents the `enum kept_pack_type` bitfield usage more clearly
- Updates callers in pack-objects, reachable, and revision code to use the new interface

Toon Claes reviews the patch positively, noting appreciation for the clearer documentation of the bitfield usage and the improved function naming. The changes are mechanical but important for the larger architectural goal of making packfile operations properly track their owning source. This is patch 3/10 in a series that has already seen review from Justin Tobler on the early patches.
