Bugfix for commit-graph memory leak and miscounting in auto-maintenance. This is a follow-up review in a thread where Patrick Steinhardt's v2 series has already been reviewed and acked by Justin Tobler and Toon Claes.

Karthik Nayak raises two technical questions about the implications of the fix:

1. The switch from `commit_list_append()` to `commit_list_insert()` means we now properly traverse all parents of merge commits, which could make commit-graph generation slower for repos with many merges since we're no longer skipping some paths.

2. The test case added verifies the parent traversal fix but doesn't explicitly test the SEEN flag fix that prevents double-counting commit tips referenced by multiple refs.

The patch itself fixes two issues in `builtin/gc.c`:
- A memory leak during depth-first search by replacing `commit_list_append()` with `commit_list_insert()`
- Incorrect SEEN flag handling that could cause double-counting of commit tips

The changes are small but important for correctness, and the series is already merge-ready with multiple acks. Karthik's questions don't indicate problems with the patch but rather seek to understand its broader implications - particularly whether the more thorough traversal might have performance impacts in merge-heavy repositories.
