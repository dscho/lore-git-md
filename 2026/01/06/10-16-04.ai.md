This is the second patch in Jeff King's two-part series fixing performance test infrastructure issues, specifically addressing environment variable preservation in the `t/perf/run` script.

The patch solves a regression where `GIT_PERF_*` environment variables (like `GIT_PERF_LARGE_REPO`) were being clobbered when running tests through the `run` helper script. The issue stems from how `GIT-BUILD-OPTIONS` loading overwrites these variables, a problem that was previously fixed in `perf-lib.sh` but reappeared when the `run` script started loading build options itself.

Jeff implements a similar solution here - preserving the variables by capturing them from the environment before loading `GIT-BUILD-OPTIONS` and restoring them afterward. The implementation uses a shell snippet that carefully escapes and reconstructs the variable assignments. While noting this is "quite ugly", he justifies it as the pragmatic solution given the current infrastructure.

The patch maintains compatibility with both direct test invocation and aggregated runs via the `run` script. It follows the same pattern as the earlier fix in `perf-lib.sh` (32b74b9809), creating consistency between the two code paths. The commit message provides thorough historical context, tracing the issue through related changes in the build system (4638e8806e) and perf infrastructure (5756ccd181).

This is a focused, well-explained fix from a core contributor with deep test infrastructure knowledge. The change is small but important for correct performance test execution, particularly when comparing results across multiple Git versions. The patch completes the series' goal of ensuring test environment settings behave consistently regardless of how the performance tests are invoked.
