This is a bugfix patch addressing memory leaks and object counting issues in Git's commit-graph auto-maintenance logic. It's the first of two patches in Patrick Steinhardt's third iteration of this series, which has already gone through extensive review and is now merge-ready.

The patch fixes two distinct but related problems in `builtin/gc.c`:

1. A memory leak occurring when counting merge commits, caused by incorrect use of `commit_list_append()` that was discarding parent commits. The fix replaces this with `commit_list_insert()` to properly maintain the commit list.

2. An object counting bug where tip objects weren't marked as SEEN, causing them to be potentially counted multiple times if reachable via multiple references.

The patch includes a new test case in `t/t7900-maintenance.sh` that verifies the fix works correctly for merge commit scenarios. The test creates a repository with merge commits and checks that the commit-graph auto-maintenance threshold is correctly calculated.

Reviewers (Justin Tobler, Karthik Nayak, and Toon Claes) have confirmed the technical correctness of the fix through multiple iterations. While Karthik suggested additional test coverage as potential future work, this is not required for merging the current patch. The changes are well-contained and the performance impact is negligible since the depth-first search is bounded by the `maintenance.commit-graph.auto` threshold.
