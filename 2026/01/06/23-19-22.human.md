This is a bugfix patch addressing race conditions in `git fsck` when run on live repositories with concurrent modifications. The patch builds on earlier work by Elijah Newren and Jeff King to make `fsck` more robust by taking snapshots of refs at operation start.

The key improvement here responds to Junio Hamano's feedback about the data structure used for ref snapshots. Instead of maintaining parallel arrays for refnames and OIDs, the patch will switch to using a single array of structs combining both fields. This makes the code more maintainable and leaves room for future enhancements like tracking reflog entries.

While the current solution uses a timestamp-based approach to filter reflog entries (which works for most cases), the discussion notes this could be improved to handle network filesystems with clock skew by using reflog entry contents as a more robust marker. The patch leaves this as a TODO for future work, focusing first on the core ref snapshotting functionality.

The changes are particularly relevant for forge operators and automated maintenance jobs where `fsck` might run concurrently with other repository operations. The thread shows active collaboration between domain experts (Newren on merges/reflogs, Peff on low-level conditions) to handle increasingly subtle edge cases while keeping the solution practical.
