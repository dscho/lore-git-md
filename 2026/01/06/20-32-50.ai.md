This is a bugfix discussion thread about handling of non-UTF-8 encoded `.gitignore` (exclude) files, particularly focusing on UTF-16LE files with BOM created by Windows PowerShell. The conversation has evolved from implementation details to fundamental design questions about Git's text handling policies.

The thread reveals a platform mismatch where Windows tools create UTF-16LE files while Git expects UTF-8. The original proposal for universal UTF-8 conversion now faces challenges regarding Git's historical handling of arbitrary byte sequences and consistency with other subsystems. Key technical points include BOM detection, UTF-16/32 to UTF-8 conversion in `utf8.c`, and changes to `dir.c` for exclude file handling with a warning system.

brian m. carlson's intervention demonstrated Git's existing ability to match non-UTF-8 patterns, shifting the discussion from implementation to core design questions. Three approaches are now under consideration: comprehensive Unicode handling, a narrow technical fix for Windows UTF-16LE BOM case, or maintaining status quo with user education.

The author (Matthieu Beauchamp-Boulay) is incorporating feedback about terminology ("exclude" vs "ignore" files) and reconsidering the UTF-8 assumption. Torsten Bögershausen suggests simpler technical approaches and questions whether Git should handle UTF-16 at all, proposing to bail out on files containing null bytes. The discussion now needs resolution on core encoding philosophy for exclude files before implementation can proceed.
