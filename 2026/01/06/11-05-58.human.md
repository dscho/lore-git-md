This is a UI improvement patch for `git add -p` (interactive patch staging). The patch modifies the interactive prompt to show whether a hunk was previously marked for use ('y') or skip ('n') when navigating between hunks.

The change makes it clearer for users to see their previous decisions when moving back and forth between hunks using the navigation keys (K/J for previous/next). The prompt now includes either "(previous decision: use)" or "(previous decision: skip)" when applicable.

The patch was originally reported by Junio C Hamano and has gone through 5 iterations, with the latest version addressing an uninitialized variable issue spotted by SZEDER Gábor. The changes are focused on the `add-patch.c` file, modifying prompt strings across all patch modes (stage, stash, reset, checkout, etc.), and updating corresponding tests in `t3701-add-interactive.sh`.

This appears to be a well-motivated quality-of-life improvement for a commonly used interactive command. The implementation is straightforward and the test coverage looks thorough, with updates to multiple test cases to verify the new prompt behavior.
