Documentation patch providing improved comments and naming for the kept-pack cache in Patrick Steinhardt's packfile store refactoring series.

This is a review response to patch 3/10 in Patrick Steinhardt's ongoing series to refactor Git's packfile storage to track packs per object database source. The patch being reviewed moves the kept-pack cache (which tracks packfiles marked as kept either on disk or in-memory) to work with packfile stores rather than repositories directly, as part of making packfile operations properly source-aware.

Toon Claes approves of the changes, specifically noting the improved clarity around:
- The enum being explicitly documented as a bitfield
- The renamed function (`packfile_store_get_kept_pack_cache`) being more descriptive
- The added documentation explaining when the cache gets recomputed

The changes are mechanical but important for the larger architectural goal of making packfile operations properly track their object database source. This is part of enabling pluggable ODB backends by ensuring all packfile-related data is properly scoped to individual sources. The review indicates the patch achieves its goal while improving clarity.
