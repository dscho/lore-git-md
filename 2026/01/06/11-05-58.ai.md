This is a feature patch improving the interactive `git add -p` interface. The patch adds visual feedback showing whether a hunk was previously marked for use ('y') or skip ('n') when navigating between hunks. 

The change modifies the prompt strings in all patch modes (stage, stash, reset, checkout, etc.) to include a "(previous decision: use/skip)" indicator when applicable. The implementation tracks the hunk decision state and inserts the appropriate text into the prompt string before displaying it. 

The patch originated from a report by Junio C Hamano and has gone through 5 iterations, with the latest version addressing an uninitialized variable issue found by SZEDER Gábor. The changes are focused in `add-patch.c` where the prompt strings are defined and displayed, with corresponding test updates in `t3701-add-interactive.sh` to verify the new behavior.

This is a user experience improvement that makes it easier to track decisions when working through multiple hunks interactively. The implementation appears clean and well-tested, with comprehensive updates to all related prompt strings and test coverage for the new behavior.
