Performance test infrastructure discussion with build system implications.

Ramsay Jones responds to Jeff King's two-patch series fixing `t/perf` issues, noting a broader concern about `GIT-BUILD-OPTIONS` handling. While acknowledging Jeff's specific fixes (correct output directory assignment and environment variable preservation), Ramsay surfaces a related but distinct problem: the inability to selectively override `GIT-BUILD-OPTIONS` values via environment variables. He shares a prototype patch from an old `meson-wip` branch that attempted this through shell variable evaluation, but notes it was abandoned due to being a "disgusting hack" and the unresolved question of which options should be overrideable. The patch demonstrates the technical approach (reading `GIT-BUILD-OPTIONS` line-by-line while allowing env vars to supersede values) but Ramsay suggests a proper solution would require splitting the file into overrideable and non-overrideable sections. This tangent highlights a deeper design question in the test infrastructure that emerged during meson integration but remains unresolved. The discussion connects to Jeff's immediate fixes while opening a separate architectural consideration about build/test system flexibility.
