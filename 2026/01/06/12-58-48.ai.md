This is a bugfix series addressing memory management issues in Git's object database handling, now in its third iteration. The series has been thoroughly reviewed and is considered merge-ready, with all feedback addressed.

The first patch fixes a commit-graph writing condition in `builtin/gc.c` that was causing both memory leaks and incorrect object counting. It corrects the depth-first search implementation by using `commit_list_insert()` instead of `commit_list_append()` and properly handles SEEN flags to prevent double-counting of tip objects. The patch includes enhanced test coverage in `t/t7900-maintenance.sh` that verifies the fix works with merge commits. Reviewers confirmed the technical correctness, with Karthik Nayak suggesting additional test coverage as non-blocking follow-up work.

The second patch fixes a submodule ODB leak in `odb.c` where sources weren't properly closed before being freed, causing a 192-byte leak per submodule access during `git-grep` operations. This is a minimal single-line change with a straightforward reproduction scenario.

Key technical details include:
- Commit-graph changes target `should_write_commit_graph()` and use `dfs_on_ref()` helper
- Submodule fix reorders cleanup operations in `odb_free()`
- Withdrawn geometric repack patch revealed deeper promisor pack issues needing separate work

The series has received final review acks from Justin Tobler and Karthik Nayak, with Toon Claes confirming correctness. All feedback has been addressed, and the patches are now in their final state with no outstanding technical concerns. The withdrawn geometric repack/promisor interaction work has been properly deferred to future efforts.
