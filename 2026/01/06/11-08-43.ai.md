This is a feature patch for the interactive `git add -p` interface, part of a GSoC project that has gone through five iterations. The patch adds visual feedback showing users their previous hunk decisions (use/skip) when navigating between hunks in interactive patch modes (stage, stash, reset, checkout). 

The implementation tracks hunk->use state and modifies prompt strings to include "(previous decision: use/skip)" indicators. The change originated from a report by Junio C Hamano and has been thoroughly reviewed across its five versions, with v5 fixing an uninitialized variable issue found by SZEDER Gábor. Test coverage in t3701-add-interactive.sh verifies the behavior across all affected modes.

The patch touches add-patch.c for the prompt modifications and decision tracking, plus corresponding test updates. It maintains the existing decision logic while adding the visual feedback layer. All earlier concerns about string consistency, memory leaks, and variable initialization have been addressed in previous iterations. The implementation appears clean and well-tested, with no outstanding technical objections noted in the thread.
