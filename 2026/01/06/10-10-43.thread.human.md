Jeff King (Peff) has posted a two-patch series fixing issues in Git's performance test infrastructure. The first patch addressed a problem where test output files were being written to the wrong directory when running performance tests from vanilla builds. The second patch, just posted, fixes a regression where `GIT_PERF_*` environment variables (used to configure test behavior) were being clobbered when running tests through the `run` helper script.

The root cause in both cases relates to how `GIT-BUILD-OPTIONS` is loaded, with the first patch fixing premature variable assignment and the second preserving environment settings that were being overwritten. Peff's solution for the environment variables involves carefully capturing and restoring them around the build options load, which he acknowledges is "quite ugly" but necessary given the current infrastructure. Both changes maintain compatibility with different ways of running the tests (direct invocation or through the `run` script) and build configurations (in-tree or out-of-tree).

As a core contributor with deep knowledge of Git's test infrastructure, Peff provides thorough historical context in his commit messages, tracing how these issues emerged from earlier changes to the build system and performance test framework. The series appears complete and well-justified, addressing subtle but important correctness issues that affect performance test execution and result aggregation.
