This is a test patch adding HTTP authentication test cases for netrc credential handling. It's the second version of a patch that was previously reviewed by Junio Hamano.

The patch adds test coverage for three scenarios when using .netrc files with HTTP authentication:
1. Successful cloning with correct netrc credentials
2. Handling of unauthorized credentials (triggering a prompt after 401 response)
3. Immediate failure for forbidden credentials (403 response)

Key technical changes include:
- New helper functions `set_netrc()` and `clear_netrc()` in t/lib-httpd.sh
- Apache test configuration modified to support forbidden user cases
- Three new test cases in t5550-http-fetch-dumb.sh
- Cleanup operations moved to use `test_when_finished` per Junio's feedback

The patch addresses Junio's review comments from v1 by:
- Making `clear_netrc()` idempotent with `rm -f`
- Using proper spacing in function definitions
- Quoting variables in redirections
- Moving cleanup operations inside test blocks with `test_when_finished`

The changes are focused on test infrastructure and don't modify any production behavior. The test assertions verify credential helper interaction with HTTP authentication flows, particularly around the 401/403 response cases. While Junio conceptually approved the testing approach in v1, he hinted at broader questions about whether Git should support netrc at all - though this patch doesn't attempt to address that larger discussion.
