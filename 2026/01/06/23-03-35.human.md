This is a performance investigation thread about `git pack-refs --all` slowness on large repositories with millions of refs. Martin Fick reports that while the actual write operations complete quickly (29K writes in 15s), Git spends ~4 minutes in gaps between writes when running on an NFS-backed Gerrit server with ~3M refs. 

Key findings from this email:
- The bottleneck appears to be mmap access patterns over NFS rather than write operations or binary search lookups
- Pre-reading the pack file (but not the packed-refs file) speeds up the operation significantly
- Jeff King suggests building Git with NO_MMAP to make I/O costs more visible via strace
- Martin notes this would be more useful as a runtime configuration since some use cases may benefit from mmap while others don't

The discussion has evolved from initial I/O concerns to focus on mmap/NFS interaction and lock duration optimization. The thread remains active with Martin continuing to test different approaches while Jeff King and Patrick Steinhardt provide technical guidance. The core tension is between Git's current implementation and the needs of large-scale Gerrit deployments that require NFS for mirroring.
