This is a performance investigation into `git pack-refs --all` slowness on large repositories with millions of refs. Jeff King (Peff) responds to Martin Fick's latest findings, which show that the actual write operations complete quickly (29K writes in 15s total) but Git spends ~4 minutes in unexplained gaps between writes during the ref packing process.

Key technical points from the exchange:
- Earlier hypotheses about loose objects or pack file counts as bottlenecks have been ruled out
- The slowdown appears related to memory access patterns rather than I/O, possibly involving mmap performance over NFS
- Git uses sequential access for packed-refs during write-out (not binary search as Martin speculated)
- Peff suggests building with NO_MMAP to make I/O costs more visible via strace, and reiterates Patrick Steinhardt's recommendation to use perf for flame graphs

The discussion has shifted focus from verification overhead to understanding memory access patterns, particularly mmap behavior over NFS. Next steps involve deeper profiling to pinpoint whether the bottleneck lies in NFS mmap performance or in-memory operations.
