This is a technical discussion about hook execution improvements, specifically addressing performance and deadlock issues in the stdin feeding mechanism for Git hooks. The email is part of an ongoing thread where Jeff King (Peff) has identified concrete problems with the current implementation.

The key issue being discussed is how `feed_receive_hook_cb()` handles stdin feeding to hooks, which currently uses a problematic batching approach. Peff demonstrates two specific issues: 1) a potential deadlock when the pipe buffer fills up, and 2) a 100ms performance penalty when sending more than 500 lines due to an unnecessary polling timeout. He provides reproducible test cases showing these problems in action.

Adrian Ratiu responds that he'll address these by implementing a proper poll loop for server-side hooks (to avoid both the deadlock and performance issues) while keeping the existing behavior for single non-parallel hooks. For client-side hooks, he plans to send a v3 patch series fixing the previously reported stdout/stderr separation regressions.

The discussion reveals deeper architectural considerations about hook execution design, particularly around the tradeoffs between real-time output and buffering. Peff's analysis provides concrete measurements and test cases that will inform the solution, moving the discussion from theoretical concerns to actionable improvements based on observable behavior.
