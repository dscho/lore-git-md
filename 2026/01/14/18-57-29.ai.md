Hook subsystem bugfix series addressing two regressions from recent hook API changes. This is the third iteration of fixes for issues reported by Chris Darroch and Kristoffer Haugsbakk, now split into two distinct patches.

The first patch restores stdout/stderr separation for pre-push hooks, which was lost during the hook API conversion. It introduces a `stdout_to_stderr` flag in `run_hooks_opt` (defaulting to 1 for backward compatibility) and explicitly sets it to 0 for pre-push hooks in transport.c. This maintains compatibility with existing hooks that expect separate streams.

The second patch changes the `ungroup` flag behavior to be opt-out rather than opt-in, based on Jeff King's analysis of historical behavior from commit 857f047e40. This addresses initialization issues and ensures consistent behavior across hook types. The change affects several hook call sites including receive-pack and commit.c.

The series includes extensive test coverage in t/t1800-hook.sh, with 176 lines of new tests verifying the stdout/stderr separation and ungroup behavior. Adrian Ratiu notes that server-side hook I/O polling improvements will come in a separate follow-up patch, as that work is still in progress. The patches are based on master and have passed CI testing.
