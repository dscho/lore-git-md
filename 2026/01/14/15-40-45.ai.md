This is the fourth patch in a bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses on `git update-ref --batch-updates`.

The patch modifies `builtin/update-ref.c` to utilize the detailed error messages now available through the ref transaction infrastructure (added in patch 2/6). Previously, `update-ref` would only show generic error codes when reference updates failed. Now it displays the full error details from the refs backend when available, falling back to the generic message only when no details exist. The changes are straightforward - the callback function now checks for and prioritizes the detailed message over the generic one.

The test suite (`t/t1400-update-ref.sh`) is updated to expect these more specific error messages. The test changes are mechanical but extensive, with 15 test cases modified to check for the new detailed messages instead of the old generic ones. The new messages are more descriptive, including specific ref names and the exact nature of failures (e.g., "cannot lock ref 'refs/heads/ref2': is at $head but expected $old_head" instead of just "incorrect old value provided").

This patch builds on the infrastructure changes from earlier in the series and represents the first user-visible improvement - actual error messages being restored to their previous usefulness. The changes are well-contained and focused, with Karthik Nayak and Jeff King continuing their methodical approach to fixing this regression.
