Bugfix for remote-curl authentication when handling large requests. This patch addresses an issue where the `probe_rpc()` path in the remote-curl transport would omit authentication headers, despite successful initial authentication. The problem surfaces in scenarios like cloning with blob filters when the request size exceeds `http.postBuffer`, causing subsequent blob requests to fail with HTTP 401 errors.

The fix is straightforward - modifying `remote-curl.c` to include auth headers in `probe_rpc()` calls to match other request paths. The patch comes with a comprehensive test that:
1. Creates a repo with 2000 refs to ensure large request size
2. Configures a small `http.postBuffer` to force the `probe_rpc()` path
3. Sets up bearer token authentication
4. Verifies successful clone with proper auth handling

This is the fourth iteration of the patch, with v4 addressing style nits from review and improving test portability by using `xargs`. The changes are minimal and focused, touching only `remote-curl.c` and `t/lib-httpd.sh`. The patch appears well-tested and ready for inclusion, with both the original reporter (Aaron Plattner) and a third party (Lucas De Marchi) having verified the fix.
