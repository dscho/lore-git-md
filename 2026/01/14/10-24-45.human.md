This is the first patch in a bugfix series for the `git last-modified` command, addressing input validation and error handling issues. The patch focuses on improving error messaging and fixing a memory leak.

The change rewrites an error message that was technically incorrect - the command expects revisions that resolve to commits, not trees, so the error now says "revision" instead of "tree". This matches the actual input requirements that Junio confirmed in v1 review. The patch also fixes a memory leak in the error path of `populate_paths_from_revs()` by properly cleaning up the diff options' pathspec when bailing out.

The accompanying test is updated to match the new error message. This is part of a v2 series that incorporates all feedback from the initial round, including Patrick Steinhardt's suggestions about error message clarity and test coverage. The changes are straightforward and uncontroversial, with the technical approach already validated by reviewers in v1.
