This is the final patch in a bugfix series addressing regression in error message reporting for batched reference updates. The patch completes the work by fixing `git receive-pack` to properly propagate detailed error messages when reference updates fail during push operations.

The change modifies `ref_transaction_rejection_handler` in `builtin/receive-pack.c` to use the detailed error message (`details` parameter) when available, falling back to the generic error message only when details are absent. A new test case in `t/t5516-fetch-push.sh` verifies that pushing a non-commit object (like a tag) to a branch now correctly reports the specific error about attempting to write a non-commit object.

The patch acknowledges one remaining issue - the error messages can be verbose with repeated refnames due to how messages propagate through the stack. The authors suggest this could be cleaned up in a future commit, but consider it out of scope for this regression fix.

With this patch, the series now fully restores detailed error reporting across all three affected commands (`git update-ref`, `git fetch`, and `git receive-pack`) that was lost when they switched to batched reference updates. The changes maintain consistency with the earlier patches in the series and complete the regression fix reported by Elijah Newren.
