This is the final patch in a bugfix series addressing a regression in error message reporting for batched reference updates. The patch completes the work by fixing `git receive-pack` to properly propagate detailed error messages when reference updates fail during push operations.

The change ensures users see specific error messages (like "trying to write non-commit object to a branch") rather than generic error codes when pushing invalid references. The implementation follows the same pattern as earlier patches in the series, modifying the ref transaction rejection handler to use detailed error messages when available.

A minor downside noted is that some error cases may produce verbose output with repeated refnames, though the authors suggest this could be cleaned up in future work. The patch includes a new test case verifying the improved error reporting when attempting to push a tag object to a branch reference.

This concludes the series that began with infrastructure changes (patches 1-4), fixed `git update-ref` (patch 4), addressed `git fetch` (patch 5), and now completes with `git receive-pack`. The changes are well-tested with updates to multiple test scripts across the series. The regression was originally reported by Elijah Newren, with Karthik Nayak and Jeff King collaborating on the fix.
