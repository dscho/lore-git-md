This is a preparatory patch in Taylor Blau's MIDX compaction series, addressing a subtle issue with how bitmapped packs are processed during MIDX generation. The change removes reliance on the `pack_perm` array when assigning `bitmap_pos` values, which will become problematic when compaction support is added.

The patch fixes a potential crash scenario that would occur when compacting MIDX layers with a non-zero base layer. Currently, the code works because `pack_perm` always covers the full range of packs, but the upcoming compaction changes will introduce a wrapper that makes this assumption unsafe. The solution is straightforward - process packs in their natural order rather than permuted order when setting bitmap positions.

This is a small but important technical correction that enables the larger compaction functionality while maintaining correct bitmap handling. The change is minimal (just one line modified) and well-explained in the commit message, which clearly describes both the current safe behavior and why it needs to change for future work.
