This is a bugfix patch addressing a regression in Git's hook subsystem where pre-push hooks lost their ability to keep stdout and stderr streams separate after being converted to the new hook API. The patch is part of a series (v3 1/2) that Adrian Ratiu is working on to fix multiple hook execution issues.

The core change introduces a new `stdout_to_stderr` flag in the `run_hooks_opt` struct, defaulting to 1 (merge streams) for backward compatibility with most hooks, while explicitly setting it to 0 for pre-push hooks in transport.c. This maintains the pre-push hook behavior that existing implementations rely on.

The patch adds extensive test coverage in t/t1800-hook.sh, verifying stream separation for pre-push hooks and merged streams for all other hook types (client-side and server-side). The tests are designed to work independently of future changes like parallel hook execution or config-based hooks.

This appears to be a well-considered fix that carefully balances backward compatibility with the new hook API's design. The test coverage is thorough, exercising all major hook types across both client and server scenarios. The patch follows up on reports from Chris Darroch and incorporates feedback from brian m. carlson.
