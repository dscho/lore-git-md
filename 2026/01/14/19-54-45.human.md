This is part 10/18 of Taylor Blau's MIDX compaction series, focusing on performance improvements for multi-pack-index handling. The patch removes a longstanding requirement that pack files in MIDX be sorted lexicographically by name, which was previously needed for efficient binary search lookups.

The key change introduces a version bump (to MIDX v2) that allows packs to be stored in any order while maintaining backward compatibility. To preserve the O(log n) lookup performance, the patch adds a lazily-initialized sorted index (`pack_names_sorted`) that's used only for lookups while the on-disk format remains flexible. This enables more efficient MIDX compaction by allowing adjacent layers to be combined without reordering packs in a way that would invalidate existing bitmaps.

The change is well-motivated by the compaction use case and comes with thorough documentation updates and test coverage. The implementation carefully maintains backward compatibility while solving a real performance constraint in the series' larger goal of efficient MIDX compaction. This continues the series' trend of thoughtful API evolution through incremental, well-tested changes.
