This is a bugfix series for the `git last-modified` command, addressing input validation issues and error handling. The series has evolved based on feedback from Junio C Hamano and Patrick Steinhardt.

The core issue was that `git last-modified` would hit a BUG() when given a tree OID (like HEAD^{tree}) instead of a commit, and had a memory leak in error paths. The v2 series expands the scope with three distinct improvements:

1. First patch rewrites the error message when multiple revisions are given to be more technically accurate (changing "tree" to "revision" since the command expects commit-ish inputs)
2. Second patch removes a duplicate error message that could appear in certain cases
3. Third patch (carried over from v1) adds validation to reject non-commit objects with a clear error message and fixes the memory leak

The series now includes test coverage for annotated tags as suggested by Patrick Steinhardt in v1 review. The changes touch builtin/last-modified.c and its test file t/t8020-last-modified.sh. The technical approach remains sound - validating inputs before processing and cleaning up resources properly in error paths.

This appears ready for merging with the improved error messaging and expanded test coverage. The changes are focused and well-explained, addressing all feedback from the initial review while maintaining the core fix's correctness.
