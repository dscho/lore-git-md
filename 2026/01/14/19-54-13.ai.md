This is a cover letter for an 18-patch series implementing MIDX (multi-pack-index) compaction functionality, with reachability bitmaps support. The series is a resend of an earlier version with updates addressing reviewer feedback.

The core feature allows compacting a range of MIDX layers into a single layer while preserving reachability bitmaps. Key technical aspects:

- Introduces a new `git multi-pack-index compact` subcommand that takes "from" and "to" MIDX layer checksums
- Bumps MIDX format to version 2 to support non-lexicographic pack ordering
- Handles edge cases like invalid ranges, identical endpoints, and missing layers
- Preserves bitmap coverage by combining bitmaps from compacted layers
- Adds extensive test coverage including bitmap verification

The series has gone through multiple rounds of review, with Patrick Steinhardt providing thorough feedback that has been incorporated. Notable changes since v1:

- MIDX format version bump to avoid breaking external tools
- Function renaming to follow project conventions (`midx_get_checksum_hash/hex`)
- Documentation fixes around `--bitmap`/`--incremental` compatibility
- Additional test cases for edge case handling
- Memory leak fixes in test tooling

The implementation appears robust, with careful attention to backward compatibility and edge cases. The bitmap handling in particular shows thoughtful consideration of how to maintain coverage across compaction operations. The test coverage is comprehensive, exercising both happy paths and error conditions.

This represents a significant enhancement to Git's multi-pack-index functionality, particularly for large repositories where MIDX chains can grow long over time. The ability to compact ranges while preserving performance-critical bitmap data should help keep these repositories efficient.
