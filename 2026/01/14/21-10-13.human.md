This is a discussion about configuring the display of branch comparison information in `git status` and `git checkout`. The thread builds on Harald Nordgren's earlier work to show divergence from both upstream and push tracking branches.

Jeff King (Peff) responds to Junio Hamano's proposal for making the additional push tracking display configurable. While acknowledging the value of configurability, Peff suggests a cautious approach to changing defaults - first implementing the feature as opt-in, then potentially flipping the default based on user feedback. He agrees with Junio's flexible configuration proposal using `status.compareBranches` but questions how often users would need to compare against branches other than `@{upstream}` and `@{push}`.

The exchange highlights the ongoing tension between discoverability and cleanliness in Git's output. Peff's perspective as the original author of `@{push}` syntax lends weight to his technical assessment, though he defers to Junio on the configuration design. The thread appears to be converging on an implementation path that maintains the core functionality while addressing concerns about output verbosity through configurable display options.
