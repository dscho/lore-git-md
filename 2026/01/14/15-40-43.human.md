This is the second patch in a bugfix series addressing a regression in error message reporting for batched reference updates. The patch focuses on preserving detailed error messages that were being lost during batched operations in `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The change modifies the ref transaction infrastructure to store rejection details alongside error codes when reference updates fail. The patch adds a new `rejection_details` field to the `ref_update` struct and updates the `ref_transaction_maybe_set_rejected()` function to accept and store error messages. This ensures that when a reference update fails, the specific error message (like "'refs/heads/foo' exists; cannot create 'refs/heads/bar'") is preserved rather than being replaced by just an error code.

The implementation touches all three ref backends (files, packed, and reftable) to ensure consistent behavior across storage formats. The patch is well-structured, with clear commit message explaining the change and its motivation, and includes a Co-authored-by from Jeff King who provided the initial report. This appears to be a solid technical improvement that will help users better understand reference update failures.
