This is a bugfix discussion thread about error message formatting in `git update-ref --batch-updates`, specifically addressing how to present detailed error information from lower layers while maintaining machine-readable output.

Jeff King (Peff) responds to Junio Hamano's review of Karthik Nayak's patch 4/6 in the series fixing batched reference update error reporting. The core question is whether the proposed error message formatting in `print_rejected_refs()` should prioritize the backend-provided details over the structured "rejected..." format that was previously machine-readable. Peff notes the existing format appears documented in git-update-ref(1) and suggests it may need test coverage if considered stable.

Peff proposes a short-term solution: simply outputting the raw details to stderr via `error()` while preserving the current machine-readable format. This would restore visibility of the team considers how to best combine both information sources. He identifies several concerns with the current approach - potential redundancy in the details (which already include refnames), possible loss of machine-readability, and uncertainty about whether backend messages will always be more informative than the standard error codes.

The discussion occurs after the series has been merged, suggesting this is post-merge refinement rather than blocking feedback. It focuses narrowly on the presentation layer of error messages while accepting the underlying infrastructure changes from earlier patches (which added the `rejection_details` field and plumbing to propagate errors). The thread demonstrates the project's attention to both functionality and output stability, even for edge cases in error reporting.
