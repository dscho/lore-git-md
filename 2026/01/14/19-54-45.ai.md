This is patch 10/18 in Taylor Blau's MIDX compaction series, focusing on relaxing the lexicographic ordering requirement for pack files in MIDX (multi-pack-index) files. The change enables more flexible MIDX compaction while maintaining bitmap compatibility.

The patch removes the constraint that pack files must be sorted lexicographically in MIDX files. Currently this ordering is required to enable binary search in `midx_contains_pack()`, but it prevents efficient compaction of MIDX layers since the ordering may need to change during compaction. The solution introduces a version bump (to MIDX v2) and adds a lazily-initialized sorted array of pack names to maintain the binary search capability without requiring the packs themselves to be sorted.

Key technical changes:
- Introduces MIDX_VERSION_V2 (2) while keeping support for V1
- Adds `pack_names_sorted` array to `struct multi_pack_index` for V2 files
- Modifies `midx_contains_pack()` to use the sorted array when available
- Updates documentation to clarify version differences
- Adds tests to verify behavior with both V1 and V2 MIDX files

The change is backward compatible - older Git versions will continue to work with V1 MIDX files, and the code handles both formats. This prepares for the compaction functionality where maintaining strict ordering would be problematic. The patch maintains all existing behavior while removing a constraint that was blocking future work.
