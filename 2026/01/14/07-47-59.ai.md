This is the final documentation patch in a series that aligns `git add` behavior with other commands when handling submodules with `ignore=all` configuration. The patch updates three documentation files to reflect the new requirement that `--force` must be used to stage changes to submodules marked with `ignore=all`.

The changes clarify that while `ignore=all` still prevents submodules from showing as modified in status/diff output by default, users can now override this by explicitly specifying the submodule path with `git add --force`. The documentation maintains consistency with the implementation by:
1. Updating the submodule config description to mention the `--force` requirement
2. Adding the submodule case to `git add --force`'s documentation
3. Clarifying which commands are affected by the `ignore` setting

This patch completes the series by ensuring the documentation matches the implemented behavior, which was thoroughly tested in previous patches. The wording is clear and maintains Git's technical precision while being accessible to users who need to understand the interaction between submodule ignore settings and the add command.
