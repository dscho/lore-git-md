This is the third patch in a bugfix series addressing a regression in error message reporting for batched reference updates. The series is co-authored by Karthik Nayak and Jeff King, building on a report from Elijah Newren.

The patch extends the ref transaction callback infrastructure to pass rejection details (error messages) alongside error codes when reference updates fail. It modifies the callback function type in `refs.h` to include a new `details` parameter, then updates all three affected commands (`fetch`, `receive-pack`, and `update-ref`) to accept this parameter (though they don't yet use it - that comes in later patches). The changes are mechanical but important plumbing work that sets up the infrastructure for actually surfacing the detailed error messages to users in subsequent patches.

This continues the careful, incremental approach seen in the series so far - each patch does one clear thing to move toward the goal of restoring lost error messages. The changes touch core refs code and multiple command implementations, showing the regression affects several parts of Git's reference update machinery. The patch appears well-structured and maintains backward compatibility while moving the codebase toward better error reporting.
