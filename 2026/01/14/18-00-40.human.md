This is a bugfix follow-up discussion about error reporting in `git fetch` after a merged patch series restored detailed error messages for batched reference updates.

Jeff King (Peff) notes that while Karthik Nayak's patch successfully restored detailed error messages to stderr, it inadvertently changed the status table output in `git fetch`. Where older versions would show a clear "!" marker and "unable to update local ref" message in the status table, the stderr-only approach now leaves the status table unchanged, potentially making failures less visible to users scanning the output.

The example shows fetching a tag into a branch (which should fail since tags point to tags, not commits) - the new behavior prints the detailed error but doesn't flag the failure in the status table. This appears to be an oversight in the original fix rather than an intentional change, as the status table markers were previously part of Git's established user interface for showing reference update problems.

The discussion suggests this may warrant a follow-up fix to restore the status table indicators while keeping the new detailed error messages. Jeff's comparison with v2.50.0 behavior implies the status table markers were a deliberate design choice that shouldn't have been lost in the refactoring.
