This is the second patch in a bugfix series for the `git last-modified` command, addressing error message clarity. The patch removes a redundant and uninformative error message that was being shown alongside the more specific "can only operate on one revision at a time" message when multiple revisions were provided.

The change is straightforward - it modifies the error handling in `last_modified_init()` to simply return -1 rather than printing a generic error when `populate_paths_from_revs()` fails. This leaves the more specific error message from the earlier validation as the only output shown to users.

The patch builds on the v1 feedback where reviewers noted the error messaging could be improved. It's part of a coordinated series where:
1. Patch 1 adds input validation and fixes a memory leak
2. This patch (2) cleans up redundant error messages
3. Patch 3 (not shown here) further improves error messaging

The changes are minimal (just one line modified) but improve the user experience by removing noise from the output. The patch maintains all the existing functionality while making error cases clearer. Since this was specifically requested in v1 reviews and the implementation matches the agreed approach, it should be uncontroversial.
