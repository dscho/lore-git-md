This is a bugfix patch series addressing inconsistent behavior with submodules marked `ignore=all` across Git commands. The series aligns `git add`'s behavior with `git status` and `git diff`, which already respect this setting.

The core change makes `git add` skip submodules with `ignore=all` by default, requiring explicit use of `--force` (originally proposed as `--include-ignored-submodules`) when users truly want to stage submodule changes. This prevents accidental staging of submodule updates while still allowing intentional updates when needed. The implementation includes comprehensive tests and documentation updates.

The series has gone through multiple iterations with significant review input, particularly from Phillip Wood and Junio C Hamano. Key technical decisions include preserving the existing warning system while adding new trace diagnostics, and splitting changes between plumbing and behavior layers. The current version addresses style and organization feedback from Junio while maintaining the agreed-upon functionality.

Documentation now clearly explains the new behavior and how it interacts with existing submodule workflows. The changes enable safer submodule branch tracking while maintaining consistency with how Git handles ignored files. With test coverage complete and implementation refined, this appears ready for final review pending resolution of the remaining naming discussion around `--force` versus more explicit alternatives.
