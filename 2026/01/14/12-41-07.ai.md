This is a bug report describing inefficient push behavior in Git's object negotiation logic. The reporter, Rajiv Sharma, demonstrates that when pushing a new branch pointing to an existing commit (HEAD~1) that's already known to the remote, Git unnecessarily sends multiple GBs of data - specifically the HEAD commit and all its ancestors except those that are also ancestors of other branches.

The issue occurs when:
1. A user creates a new branch pointing to an existing commit (HEAD~1)
2. The commit is already present on the remote
3. Instead of being a lightweight operation, Git sends excessive data

The reporter provides a clear reproduction scenario and analysis showing the push sends:
- HEAD commit and its ancestors
- But excludes commits that are ancestors of other branches
This leads to significant unnecessary data transfer for repositories with long branch histories.

While the reporter notes a workaround exists (doing a `git pull` first), they argue this inefficient behavior should be fixed. The issue appears cross-platform and version-independent. The bug likely resides in Git's push negotiation logic where it fails to properly optimize for this common scenario of creating new refs to existing objects.
