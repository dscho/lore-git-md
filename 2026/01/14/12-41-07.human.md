This is a bug report about `git push` unnecessarily sending large amounts of data when creating a new branch pointing to an existing commit that's already known to the remote. The reporter, Rajiv Sharma, provides a clear reproduction case showing that when pushing a new branch pointing to HEAD~1 (an ancestor of the remote's current branch), Git sends all commits in the ancestry chain except those that are also ancestors of other remote refs.

The issue appears to be in the client-side negotiation logic during push operations. While there's a simple workaround (doing a `git pull` first to sync with the remote), the current behavior can result in multi-gigabyte transfers when working with long-running branches, which is clearly suboptimal.

The report is well-documented with ASCII diagrams showing the commit graph and which objects get unnecessarily transmitted. It affects multiple platforms and Git versions (tested on 2.47.3). This looks like a legitimate performance issue that could be worth investigating, particularly for users working with large repositories and long branch histories.
