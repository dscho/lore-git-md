This is part 9/18 of Taylor Blau's MIDX compaction series, focusing on refactoring the MIDX writing code to prepare for the upcoming compaction functionality.

The patch introduces a `struct write_midx_opts` to consolidate the six parameters currently passed to `write_midx_internal()` into a single structure. This change:

1. Replaces the direct parameters with a structured approach that will make it easier to add new options for MIDX compaction in future patches
2. Maintains all existing functionality while making the code more maintainable
3. Allows callers to zero-initialize the struct, avoiding the need to pass default values for new fields in existing call sites

The change affects four MIDX-writing functions that wrap `write_midx_internal()`:
- `write_midx_file()`
- `write_midx_file_only()`
- `expire_midx_packs()`
- `midx_repack()`

Each has been updated to use the new options struct while preserving their current behavior. The patch includes comprehensive updates to all call sites to ensure consistent behavior.

Key technical details:
- The struct contains all parameters previously passed to `write_midx_internal()`
- Source ODB remains a required field (non-NULL)
- Other fields (packs_to_include, packs_to_drop, etc.) remain optional as before
- Flags handling remains unchanged but is now part of the options struct

This is a preparatory refactoring that enables cleaner addition of compaction-related parameters in subsequent patches while maintaining the series' careful approach to API design. The change demonstrates good forward-thinking design by anticipating the need for additional parameters without requiring immediate implementation.
