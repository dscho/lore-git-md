This is a bugfix patch for the remote-curl transport, addressing an authentication issue in the probe_rpc() path. The problem occurs when large requests (like those with blob filters) trigger probe_rpc() after successful initial authentication - the auth headers were being omitted in this path, causing subsequent requests to fail with HTTP 401 errors.

The fix is straightforward: modify remote-curl.c to include auth headers in probe_rpc() just like other request paths. The patch comes with a comprehensive test that:
1. Creates a repo with 2000 refs to ensure large request size
2. Configures a small http.postBuffer to force the probe_rpc() path
3. Sets up bearer token authentication
4. Verifies successful clone with proper auth handling

Version 4 addresses style nits from review and improves test portability by using xargs. The patch has been tested by Lucas De Marchi and looks ready for merging. While the technical change is small, the impact is significant for users encountering authentication failures during large requests. The test coverage appears thorough, exercising both the auth header handling and the edge case that triggers probe_rpc().
