This is part of Taylor Blau's ongoing MIDX compaction series (patch 4/18), which aims to improve multi-pack-index handling for large repositories. The patch focuses on a small but practical improvement to the `git multi-pack-index` command's option handling.

The change moves the `--progress` option from being individually declared in each subcommand (write, verify, repack, expire) to being defined once in the common options structure. This is a straightforward refactoring that eliminates duplicate declarations while maintaining the same functionality. The documentation is also updated to note that `--progress` is available across all subcommands.

This is a clean, mechanical change that follows established patterns in the codebase. It doesn't introduce new behavior but makes the code more maintainable by reducing duplication. The patch is well-contained, touching only the expected files (command implementation and documentation), and includes the necessary documentation update to match the code changes.

As part of the larger MIDX compaction effort, this small refactoring helps keep the codebase tidy while preparing for more substantial changes to come in later patches of the series.
