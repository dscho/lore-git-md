Bugfix for submodule fetching that removes the hardcoded "origin" remote assumption. This patch implements a 7-year-old NEEDSWORK item from commit be76c21282 by introducing a new `get-default-remote` submodule helper command. The change allows `git fetch --recurse-submodules` to work correctly when submodules use non-origin remote names, which is particularly useful for projects like the "repo" tool that use custom remote names.

The implementation adds the new command to submodule--helper and updates the submodule fetching logic to use it, falling back to "origin" if the helper fails. The patch includes extensive test coverage across three test files (t5526, t5572, and a new t7425) that verify behavior with custom remote names, pull operations, and edge cases like nested submodules and missing remotes.

Review feedback from v1 has been addressed, including fixing style issues like comment formatting and commit message conventions. Jacob Keller has reviewed the technical approach and confirmed it's sound. The patch is now ready for integration after these presentation fixes. This is a well-motivated change that solves a real limitation in submodule handling while maintaining backward compatibility.
