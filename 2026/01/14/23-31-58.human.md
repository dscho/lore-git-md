This is a discussion about configuring `git status` to show divergence from multiple tracking branches, continuing the long-running thread about push/pull tracking display.

Junio Hamano responds to Harald Nordgren's position that push/pull relationships should have special status in `git status` output. He argues against artificially limiting branch comparisons to just `@{upstream}` and `@{push}`, suggesting this would repeat the same mistake made when the original ahead/behind display was designed to only show `@{upstream}` divergence. 

Junio makes the case for a more flexible configuration that could compare against arbitrary reference points, giving the example of comparing against release tags as potentially useful for maintainers. His tone is characteristically light but pointed, using the "falling into the same trap" framing to suggest the push/pull focus may be too narrow.

The exchange highlights a philosophical divide: Harald sees push/pull as fundamental Git operations deserving special UI treatment, while Junio advocates for a more general mechanism that could serve diverse workflows. This continues the thread's exploration of how much configurability to expose versus keeping the interface focused on common cases. The technical implementation appears capable of supporting either approach, making this primarily a design question about Git's workflow model.
