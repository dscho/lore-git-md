This is a bugfix patch addressing a regression in Git's hook subsystem, specifically affecting the pre-push hook's output handling. The patch comes from Adrian Ratiu as part of an ongoing discussion involving several key contributors.

The core issue stems from a recent change that redirected all hook output to stderr by default, which broke the pre-push hook's ability to maintain separate stdout and stderr streams. Adrian's v2 patch introduces a `stdout_to_stderr` flag in the hook API (defaulting to 1 for backward compatibility) while explicitly setting it to 0 for pre-push hooks to restore the previous behavior.

The patch includes comprehensive test coverage to prevent similar regressions, addressing feedback from Junio Hamano and Patrick Steinhardt. It also fixes an interaction with the `ungroup` flag that was identified during development. The solution preserves the special case for pre-push hooks while maintaining the general hook API's consistency.

This fix is validated and ready, though Jeff King has identified a separate stdin feeding issue in the hook execution machinery that may require follow-up work. The patch represents a well-considered solution to the immediate regression, with thorough test coverage that will benefit future hook-related changes.
