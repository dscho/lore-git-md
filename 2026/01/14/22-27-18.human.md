This is a bugfix patch addressing UTF-8 display issues in Git's diffstat output. The problem occurs when filenames containing UTF-8 characters are truncated to fit within the `name-width` limit - currently the code incorrectly assumes display width equals byte count, leading to garbled output when cutting multi-byte UTF-8 characters.

The patch comes from Lorenzo Pegorari as part of Google Summer of Code (GSoC). It modifies `show_stats()` in `diff.c` to properly handle UTF-8 characters by using the existing `utf8_width()` function to count display columns rather than raw bytes when truncating filenames. The change is small (4 lines added, 11 removed) and focused, with a clear before/after example showing the fix in action.

The patch looks well-crafted for its scope - it solves a real display issue without introducing complexity, maintains the existing behavior for ASCII filenames, and uses existing Git infrastructure (`utf8_width()`). As a GSoC contribution, it's a good example of a contained improvement that touches a visible user-facing feature while working within established code patterns.
