This is a discussion about configuring the display of push branch comparisons in `git status`, part of Harald Nordgren's previously merged series that enhanced branch tracking information.

D. Ben Knoble weighs in on Jeff King's suggestion to make the push branch comparison feature configurable (via `status.compareBranches`), responding to Harald's question about whether users with mirror workflows would want the push comparison disabled by default. Knoble expresses mild preference for keeping it enabled by default but emphasizes the importance of not disrupting existing workflows - the key concern being that the new feature shouldn't force users to change how they currently push branches to remote mirrors.

The exchange highlights the ongoing configuration design discussion's focus on balancing discoverability of the new feature against maintaining backward compatibility, particularly for users who rely on simple `git push` to mirror repositories. Knoble's input suggests the thread is converging toward making the behavior configurable while preserving current workflows.
