This is a continuation of the ongoing discussion about `git status` branch comparison display, specifically addressing Junio Hamano's proposal for a configurable `status.compareBranches` setting. Harald suggests maintaining the current distinction between upstream and push tracking branches rather than generalizing to arbitrary branch comparisons, though he acknowledges the technical feasibility of supporting Junio's proposal.

This positions Harald between Junio's flexible configuration approach and Jeff King's more conservative stance, while still preserving the core functionality of the merged implementation. The discussion continues to balance technical feasibility with user experience considerations, now touching on Git's fundamental workflow patterns.
