This is a bugfix patch addressing a regression in Git's hook subsystem, specifically the `ungroup` flag behavior. It's part of a series fixing multiple hook execution issues, with this patch focusing on making the `ungroup` option opt-out rather than opt-in.

The patch corrects an accidental behavior change introduced in commit 857f047e40 where the `ungroup` flag was made opt-in, causing regressions in pre-push hooks. The fix restores the original behavior by setting `ungroup=1` in the `run_hooks_opt` initializer, while explicitly setting `ungroup=0` only where needed (in receive-pack for sideband output). 

The change is well-motivated with clear references to the regression and includes comprehensive test coverage for receive-pack sideband output scenarios that were previously untested. The patch follows the discussion thread's consensus to separate fixes while maintaining backward compatibility.

This appears to be a solid fix that:
1. Clearly identifies the regression source
2. Provides a clean solution with minimal code changes
3. Adds valuable test coverage for edge cases
4. Maintains consistency with the broader hook subsystem work

The patch is ready for consideration alongside the first patch in the series (which addressed stdout/stderr separation) while deferring more complex I/O polling improvements to future work.
