Hook subsystem bugfix addressing two distinct issues in the pre-push hook execution. This is Adrian Ratiu's response to Jeff King's review of v2, where he identifies that the patch was incorrectly combining fixes for two separate problems.

The first issue (reported by Chris Darroch) involves stdout/stderr separation in hook output, where recent changes caused all hooks to redirect stdout to stderr by default, breaking the pre-push hook's ability to use separate streams. The v2 patch already addressed this with a new `stdout_to_stderr` flag in `run_hooks_opt` and explicit handling for pre-push hooks.

The second issue (reported by Kristoffer Haugsbakk) involves stdin feeding performance in `feed_pipe` when not using `ungroup=1`. Jeff King's analysis shows the current implementation hits poll timeouts for each ref, causing significant slowdowns. Adrian acknowledges this is a separate problem requiring its own fix, either by requiring `ungroup=1` when using `feed_pipe` or enhancing the poll mechanism to properly handle child input readiness.

Adrian plans to split these into two patches in v3: one maintaining the stdout/stderr separation fix, and another addressing the stdin feeding performance by batching ref processing in the callback similar to how `feed_receive_hook_cb()` works. The thread shows good technical engagement with Jeff King providing detailed analysis and Adrian responding with a clear plan to address both issues separately.
