This is part 3 of a 3-patch series moving repository-specific configuration values from global variables into `struct repo_config_values`, as part of the ongoing `the_repository` removal effort. The current patch focuses on migrating `branch.autoSetupMerge` (stored in `git_branch_track`) to the new structure.

The discussion with Junio reveals some key considerations about the migration approach. While the patch correctly moves the variable, Junio questions whether all config values being moved are truly repository-scoped, and raises concerns about initialization sequencing when multiple repositories are involved. The author clarifies they are only moving repository-dependent variables, not all globals, and explains the current initialization strategy replicates existing behavior where `git_branch_track` gets a default value before config parsing.

This patch continues the mechanical work of the series while leaving larger architectural questions open - particularly around how to safely populate config values when working with multiple repositories. The implementation appears technically sound for the single-repository case, but the thread suggests more design work is needed to fully realize the multi-repo vision that motivates these changes.
