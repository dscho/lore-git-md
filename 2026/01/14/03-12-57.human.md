This is a bugfix discussion about Git's hook subsystem, specifically addressing a regression in the pre-push hook's output handling. Jeff King (Peff) joins the thread to provide deeper technical analysis of an underlying problem with how feed_pipe callbacks interact with the hook execution machinery.

Peff identifies that the current fix (setting `ungroup=1` for pre-push hooks) works around a more fundamental issue: the feed_pipe mechanism doesn't properly coordinate with the poll loop when writing to child processes. He demonstrates through strace analysis that without ungrouping, the hook input gets written in inefficient 100ms chunks due to poll timeouts.

The core observation is that feed_pipe callbacks are fundamentally incompatible with grouped output (where stdout/stderr are collected), since the poll loop that manages grouped output doesn't account for the pipe feeding case. Peff suggests this should be documented as a hard requirement (perhaps via a BUG() assertion) or the implementation should be fixed to properly handle pipe feeding during polling.

This analysis goes beyond the immediate stdout/stderr separation issue that was the original focus of the thread, uncovering a more systemic problem in the hook execution machinery. While the current patch solves the immediate regression, Peff's comments suggest there may be deeper architectural work needed to properly support feed_pipe callbacks in all cases.
