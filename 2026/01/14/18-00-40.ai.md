This is a post-merge discussion about error message formatting in the recently merged bugfix series for batched reference updates. Jeff King (Peff) identifies a regression in `git fetch`'s output where detailed error messages no longer appear in the status table, only on stderr.

The key observation is that while the merged patches correctly restore detailed error messages via stderr, they inadvertently changed `git fetch`'s behavior - previously it would mark failed ref updates with a "!" prefix and explanatory text in the status table, but now only shows the error on stderr while reporting success in the table. This creates a discrepancy with Git 2.50.0 and earlier behavior.

Jeff King's message serves as a gentle heads-up about this behavioral change, noting it may be worth addressing in follow-up work. The tone is constructive - he provides clear before/after examples and frames it as something the original author (Karthik Nayak) may want to look at, rather than demanding an immediate fix. This fits the project's typical post-merge refinement process where minor issues are often caught and fixed after initial integration.
