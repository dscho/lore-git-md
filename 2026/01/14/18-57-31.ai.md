This is a bugfix patch addressing a regression in Git's hook subsystem, specifically around the `ungroup` flag behavior. It's the second part of a two-patch series (v3) that follows up on earlier discussion about hook execution issues.

The patch changes the `ungroup` flag from opt-in to opt-out behavior, reverting an accidental change introduced in commit 857f047e40. The key change is initializing `ungroup=1` in the `RUN_HOOKS_OPT_INIT` macro, making it the default while still allowing explicit opt-out where needed (primarily in receive-pack for sideband output). This matches the original intended behavior and fixes a regression in pre-push hooks.

The patch includes comprehensive test coverage for receive-pack's sideband output handling across all four relevant hook types (pre-receive, update, post-receive, post-update). The tests verify proper separation of stdout and stderr when `ungroup=0` is set for sideband output. This builds on the test infrastructure added in the first patch of the series.

The change is well-motivated by the regression report from Kristoffer Haugsbakk and incorporates Jeff King's suggestion to make the behavior opt-out rather than opt-in. The implementation is clean separation of concerns - the default is set once in the macro while receive-pack explicitly opts out where needed for sideband compatibility. The extensive new tests provide confidence in the fix and will help prevent future regressions.
