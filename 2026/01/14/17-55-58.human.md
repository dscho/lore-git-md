This is a follow-up discussion about error message formatting in the batched reference updates bugfix series, specifically addressing patch 4/6 which deals with `git update-ref`.

Jeff King raises two key concerns about the error message handling in the patch:

1. **Machine-readability vs. detail**: He notes the current "rejected..." output format appears designed for parsing (and is documented in the man page), while the new detailed error messages might not maintain this property. He suggests the test suite should cover this stable format if it's meant to be machine-readable.

2. **Message redundancy**: The detailed error messages often repeat information (like refnames) that's already in the structured rejection line, potentially creating verbose or confusing output.

As a short-term solution, Jeff proposes simply printing the detailed errors to stderr while maintaining the current machine-readable format, deferring any more sophisticated integration of the two message types. This would restore the pre-regression behavior where details were at least available, while preserving the structured output format.

The discussion shows careful consideration of both user-facing output and programmatic use cases, with Jeff advocating for a conservative approach that maintains backward compatibility while the team considers how best to combine detailed errors with the structured format in the future. This follows the pattern seen throughout the thread of prioritizing regression fixes first, with potential optimizations and refinements to come later.
