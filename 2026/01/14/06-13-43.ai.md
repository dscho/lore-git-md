This is a bugfix patch in the hook subsystem, addressing a regression in pre-push hook behavior. The patch from Adrian Ratiu (v2) fixes an issue where recent changes to the hook API caused all hooks to redirect stdout to stderr by default, breaking the pre-push hook's special case of keeping the streams separate.

The solution introduces a `stdout_to_stderr` flag in the hook API (defaulting to 1 for backward compatibility) while explicitly setting it to 0 for pre-push hooks. The patch includes comprehensive test coverage to prevent future regressions and addresses feedback from Junio Hamano and Patrick Steinhardt on the initial version. The fix maintains backward compatibility while properly handling the pre-push hook's unique requirements.

Kristoffer Haugsbakk's email serves as ack/review, confirming the patch addresses the reported issue about slow pre-push hooks waiting for stdin. The thread context shows this is part of ongoing hook subsystem improvements, though not directly tied to Adrian Ratiu's larger hook configuration work. The patch appears well-tested and addresses all raised concerns, making it likely to be accepted.
