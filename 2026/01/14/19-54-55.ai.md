This is part 13 of Taylor Blau's 18-patch series implementing MIDX compaction with bitmap support. The series is now in its second iteration after addressing Patrick Steinhardt's review feedback.

The current change extracts a helper function `fill_pack_from_midx()` from the existing `fill_packs_from_midx()` function in `midx-write.c`. This prepares for upcoming compaction work where the same pack-filling operation will be needed in a different context. The extracted function handles loading a pack from a MIDX by its integer ID and populating a `pack_info` struct with its details.

This is a straightforward refactoring that:
- Moves the pack preparation and info-filling logic into a reusable function
- Maintains the same error handling behavior
- Keeps the same memory growth pattern via `ALLOC_GROW`
- Preserves the existing pack ID offset calculation (`num_packs_in_base + i`)

The change is part of the ongoing effort to build infrastructure for MIDX compaction while keeping the codebase clean and maintainable. It follows the pattern seen in earlier patches of the series where functionality is carefully decomposed into reusable components before being wired together for the new compaction feature.
