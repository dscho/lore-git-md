Bugfix patch addressing error message regression in `git fetch`.

This is the fifth patch in a six-part series fixing a regression where batched reference updates lost detailed error messages, leaving users with generic error codes. The series was prompted by a report from Elijah Newren, with Karthik Nayak and Jeff King collaborating on the fix.

This specific patch updates `git fetch` to use the new error reporting infrastructure introduced in earlier patches. When reference updates fail during fetch, the command will now show detailed error messages (like "cannot lock ref 'refs/heads/foo'") rather than generic ones. The changes touch the rejection handler callback in `builtin/fetch.c` and update several test cases in `t/t5510-fetch.sh` to expect the more specific error messages.

The patch follows the same pattern as the previous one for `git update-ref`, showing the team is systematically working through each affected command. One test case checks that FETCH_HEAD is still updated even when ref updates fail, maintaining existing behavior while improving error reporting. The changes are methodical and focused, with clear test coverage for the fixed scenarios.

One remaining patch in the series will complete the fix by addressing `git receive-pack`. The work is part of broader ref backend improvements but specifically targets restoring lost diagnostic information that helps users debug failed reference operations.
