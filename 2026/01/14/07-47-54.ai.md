This is a bugfix patch series addressing inconsistent behavior of submodules with `ignore=all` configuration across Git commands. The series aligns `git add` with how `git status` and `git diff` handle ignored submodules.

The v3 series implements the agreed-upon design from earlier discussion, now using `--force` rather than `--include-ignored-submodules` as the flag name. The core change makes `git add` skip submodules marked `ignore=all` by default, requiring explicit use of `--force` when users want to stage changes to these submodules. This matches the behavior of regular ignored files while supporting workflows where submodules track branches without accidentally staging their updates.

The implementation splits changes between plumbing (patch 1) and behavior (patch 2), with patch 2 adding a new helper function `skip_submodule()` that checks pathspec matches and ignore rules. The series includes comprehensive test coverage (patch 3) and updates existing tests (patch 4) to use the new `--force` requirement. Documentation updates (patch 5) clarify the behavior across all affected commands.

Key technical details for future reference:
- New `ignored_too` parameter in `add_files_to_cache()`
- `skip_submodule()` helper in `read-cache.c` handles pathspec matching
- Warning system preserved through `override_submodule_config`
- Tests verify both `.gitmodules` and command-line config
- Documentation updates cover `--force` behavior with submodules

The series appears ready for final review pending resolution of minor style issues in patch 1 noted by Junio. The naming discussion around `--force` vs `--include-ignored-submodules` seems settled in favor of `--force` for consistency with other commands.
