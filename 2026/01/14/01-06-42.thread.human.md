This thread addresses a bug in Git's remote-curl transport where authentication headers were missing from probe_rpc() requests, causing HTTP 401 failures during operations like cloning with blob filters when requests were large enough to trigger this code path. The issue was particularly noticeable when using bearer token authentication.

The patch author has submitted a well-constructed fix (now at v4) that modifies remote-curl.c to properly include authentication headers in probe_rpc() requests, matching the behavior of other request paths. The solution is minimal - just adding the auth header append call where it was missing. The patch includes a comprehensive test case that reproduces the issue by creating a repository with enough refs to trigger large requests, configuring a small http.postBuffer to force the probe_rpc() path, and setting up bearer token authentication to verify the fix works.

The latest iteration has incorporated style nits from previous reviews and improved test portability by using xargs. The changes are confined to just two files with minimal impact on core logic. The commit message clearly explains both the problem and solution, and the test coverage appears thorough, making this a solid candidate for merging.
