Thread identity: Bugfix series addressing regression in error message reporting for batched reference updates in `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

Core problem: When performing batched reference updates, these commands lost detailed error messages that were previously available, only returning generic error codes. This regression affected user debugging when reference updates failed.

Current status: Series from Karthik Nayak and Jeff King (v1, 6/6) merged by Junio Hamano. Post-merge discussion reveals three distinct output formatting issues:
1. `git update-ref --batch-updates` machine-readable output vs stderr details
2. `git fetch` status table regression where failed refs incorrectly show as successful
3. `git receive-pack` verbosity with repeated refnames in error messages (new focus)

Key technical details: Changes include:
- Added `rejection_details` field to `struct ref_update` with Jeff King reviewing implementation
- Modified callback signatures throughout refs code
- Implemented detailed error display in `builtin/update-ref.c`, `builtin/fetch.c`, and `builtin/receive-pack.c`
- Test suite expanded with 20 test cases across multiple test files
- All three ref backends updated to pass through error messages
- Current focus areas:
  * `print_rejected_refs()` output format (machine-readable vs stderr details)
  * `git fetch` status table regression
  * `git receive-pack` error message verbosity (new discussion)
- Identified concerns: output consistency, backward compatibility, test coverage gaps
