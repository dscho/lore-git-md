Thread identity: Bugfix series addressing regression in error message reporting for batched reference updates in `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

Core problem: When performing batched reference updates, these commands lose detailed error messages that were previously available, only generic error codes are returned. This regression affects user debugging when reference updates fail.

Current status: Series from Karthik Nayak (v1, 2/6), building on report from Elijah Newren and initial patch from Jeff King. First patch (1/6) removed unused headers from refs.c as preparatory cleanup. This second patch (2/6) modifies the ref transaction infrastructure to store rejection details alongside error codes when reference updates fail.

Key technical details: Changes include adding a `rejection_details` field to `struct ref_update` to preserve error messages, modifying `ref_transaction_maybe_set_rejected()` to accept/store error details, and updating all three ref backends (files, packed, reftable) to pass through error messages. Proper memory management ensures rejection details are freed when transactions are freed. This sets up foundation for subsequent patches to surface error messages to users.

Participant positions: Karthik Nayak driving the fix with Jeff King as co-author, based on Elijah Newren's report. The first patch was straightforward header cleanup; this second patch is the first substantive change implementing the core infrastructure for preserving error details. No reviews or objections noted in this submission.

Related work: Part of ongoing ref backend work (reftable/files/packed backend unification), though primarily focused on fixing a regression in error reporting behavior. The changes are mechanical but thorough, touching core refs code and all backend implementations while maintaining backward compatibility.
