Thread identity: Bugfix series addressing regression in error message reporting for batched reference updates in `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

Core problem: When performing batched reference updates, these commands lost detailed error messages that were previously available, only returning generic error codes. This regression affected user debugging when reference updates failed.

Current status: Series from Karthik Nayak and Jeff King (v1, 6/6) now complete and merged by Junio Hamano. All patches applied:
1. Infrastructure changes (1/6-4/6) including final header cleanup removing unused `run-command.h` and `sigchain.h` from `refs.c`
2. Fixed `git update-ref` (4/6)
3. Fixed `git fetch` (5/6) - confirmed by Junio Hamano's review that backend-provided error details contain sufficient refname information
4. Fixed `git receive-pack` (6/6)

Key technical details: Changes include:
- Added `rejection_details` field to `struct ref_update` (patch 2)
- Modified callback signatures throughout refs code (patch 3)
- Implemented detailed error display in `builtin/update-ref.c`, `builtin/fetch.c`, and `builtin/receive-pack.c`
- Test suite expanded with 20 test cases across `t/t1400-update-ref.sh`, `t/t5510-fetch.sh`, and new case in `t/t5516-fetch-push.sh`
- All three ref backends (files, packed, reftable) updated to pass through error messages
- Memory management ensures proper cleanup throughout stack
- Final cleanup removes unused headers from `refs.c` with no functional impact

Open questions and loose ends: One known issue remains - error messages can be verbose with repeated refnames due to message propagation. Authors suggest future cleanup but consider this out of scope for regression fix. Junio Hamano's review confirmed the technical correctness of the approach, particularly validated the fetch-specific implementation in patch 5/6.
