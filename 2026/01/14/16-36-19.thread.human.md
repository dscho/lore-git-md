This thread addresses a bug in Git's remote-curl transport where authentication headers were missing during probe_rpc() calls, causing HTTP 401 failures when cloning large repositories with bearer token authentication. The issue specifically affects users of authentication methods like git-credential-msal.

The patch, now in its fifth iteration (v5), fixes the problem by ensuring probe_rpc() includes authentication headers just like other RPC calls. The author has provided a detailed reproduction scenario showing how clones would fail midway when the probe_rpc() path was triggered due to missing auth headers. The fix is straightforward but important for affected users.

Lucas De Marchi has tested the patch, which includes a comprehensive test case that verifies the fix works by creating a large repository, forcing the probe_rpc() path with a small http.postBuffer, and confirming successful authentication during clone operations. The patch appears to have gone through thorough review over its five versions and addresses a real-world problem for users of bearer token authentication with large repositories.
