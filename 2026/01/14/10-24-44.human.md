This is a bugfix series for the `git last-modified` command, addressing invalid input handling issues. The series builds on v1 feedback from Junio C Hamano and Patrick Steinhardt, expanding the scope to improve error messaging and test coverage.

The core issue was that passing a tree OID (like HEAD^{tree}) would trigger a BUG() rather than producing a helpful error message. The v2 series now includes three commits:

1. Improves the error message when multiple revisions are given, changing "tree" to "revision" for accuracy since the command expects commit-ish inputs. Also fixes an unrelated memory leak.

2. Removes a duplicate error message that could appear in certain cases.

3. Adds validation to reject non-commit objects with a clear error message, addressing the original reported bug. This includes test coverage for both tree objects and annotated tags.

The changes touch builtin/last-modified.c and its test file, with careful attention to error handling and memory management. The series shows good responsiveness to review feedback, particularly around message clarity and test completeness. The technical approach has maintainer approval from Junio, and the additional polish in v2 makes this ready for merging.
