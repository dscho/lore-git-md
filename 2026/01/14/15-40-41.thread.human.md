This thread addresses a regression where batched reference updates (used by `git update-ref --batch-updates`, `fetch`, and `receive-pack`) lost detailed error messages, only returning generic error codes. Karthik Nayak and Jeff King are leading the fix with a v3 patch series that restores detailed error reporting while maintaining backward compatibility.

The latest patch (3/6) focuses on `update-ref`, modifying it to output detailed error messages to stderr while keeping the machine-parsable format on stdout. The test suite has been extensively updated to verify both output formats across various failure cases like invalid objects and ref conflicts. This builds on earlier work that plumbed error details through the ref transaction machinery.

The series is nearly complete, with core functionality working and just a few loose ends remaining: finalizing deterministic output ordering in `fetch`, standardizing error message patterns, and some message formatting cleanup. A header cleanup is also pending but depends on resolution of unrelated hook API changes. The changes have seen thorough review, with Phillip Wood suggesting improvements to the output ordering approach and Junio Hamano having already accepted an earlier version of the series.
