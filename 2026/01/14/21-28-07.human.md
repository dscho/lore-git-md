This is a patch in Taylor Blau's series implementing `git multi-pack-index compact` with bitmap support, specifically addressing version handling for MIDX files. The patch removes the requirement for packs to be sorted lexicographically in MIDX v2, while maintaining backward compatibility with v1.

Junio C Hamano provides a review of the changes, questioning whether some of the version parameter additions are truly necessary since the code will always write v2 MIDX files. He notes that the version handling makes sense for reading existing files, where v1 and v2 may need different treatment, but suggests the writer-side changes might be overkill since v1 writing is effectively deprecated.

The patch introduces version-aware handling throughout the MIDX writing code, adding a `version` field to the write context and making various functions version-sensitive. Junio's review focuses on whether this complexity is justified given that new MIDX files will always be written as v2. He ultimately accepts the changes as making sense for reading existing files, but his questions highlight that some of the writer-side version checks may be redundant.

This is patch 10/18 in a series that has already received significant review and is now in its final stages, with Junio providing the last round of feedback before merging. The series as a whole represents a major enhancement to Git's multi-pack-index capabilities for large repositories.
