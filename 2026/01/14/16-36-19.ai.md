This is a bugfix patch addressing an authentication issue in the remote-curl transport when handling large requests. The problem occurs when a large request triggers the probe_rpc() path, which wasn't properly including authentication headers, causing HTTP 401 failures during clone operations with bearer token authentication.

The patch modifies remote-curl.c to include auth headers in probe_rpc() requests, matching the behavior of other RPC calls. The author provides a detailed reproduction scenario showing how a clone operation with blob filters would fail midway when the probe_rpc() path is hit, due to missing auth headers. The fix is straightforward - just adding the auth header append call that was missing.

The patch includes a comprehensive test case that:
1. Creates a large repository with many refs
2. Configures a small http.postBuffer to force the probe_rpc() path
3. Sets up bearer token authentication
4. Verifies the clone succeeds with proper authentication

The change is well-justified and the test case provides good coverage of the scenario. The patch has been tested by Lucas De Marchi and this is the fifth iteration (v5) of the patch, suggesting it's been through review. The fix addresses a real-world authentication problem that affects users of bearer token auth (like git-credential-msal) when cloning large repositories.
