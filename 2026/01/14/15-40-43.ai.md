Bugfix patch in a series addressing lost error messages in batched reference updates. This is the second of six patches fixing a regression where detailed error messages were being dropped during batched reference operations in `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The patch modifies the ref transaction infrastructure to store rejection details alongside error codes when reference updates fail. Key changes include:
- Adds a `rejection_details` field to `struct ref_update` to preserve error messages
- Modifies `ref_transaction_maybe_set_rejected()` to accept and store error details
- Updates all three ref backends (files, packed, reftable) to pass through error messages
- Ensures proper memory management by freeing rejection details when transactions are freed

The changes are mechanical but thorough, touching the core refs infrastructure and all backend implementations. This sets up the foundation for subsequent patches that will surface these error messages to users through the affected commands. The patch maintains backward compatibility while adding the missing functionality.

Co-authored with Jeff King, this appears to be a well-scoped technical fix that directly addresses the reported regression without introducing new complexity. The changes are focused on the refs subsystem and don't appear to have wider implications.
