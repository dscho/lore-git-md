This is a bugfix patch addressing an authentication issue in the remote-curl transport when handling large requests. The problem occurs when a clone operation needs to split a large request into chunks - the initial probe request wasn't including authentication headers, causing failures when fetching from servers requiring Bearer token authentication.

The patch demonstrates a clear real-world impact: cloning large repositories with blob filters from secured servers would fail during checkout when the authentication token wasn't properly passed to the probe request. The fix is straightforward - just one line to add auth headers to the probe_rpc() call - but comes with a thorough test case that:
1. Creates a repository with thousands of refs to trigger the probe path
2. Configures a small http.postBuffer to force chunking
3. Verifies the clone works with Bearer auth

The test coverage is excellent, reproducing the exact failure scenario and verifying the fix works. The commit message includes detailed trace logs showing the authentication failure and explains why the http_auth.multistage logic wasn't kicking in. This looks like a well-researched and properly tested fix for a real pain point in secured environments.
