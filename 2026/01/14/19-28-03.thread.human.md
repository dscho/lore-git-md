This thread covers a performance optimization in Git's sparse-checkout feature, specifically improving how pattern lists are sorted when building the cone-mode checkout configuration. The original implementation used an O(n^2) insertion sort via string_list_insert(), which Jeff King (Peff) identified as inefficient since the hashmap source already guarantees unique entries.

Amisha Chhajed's initial version addressed one location, but Peff suggested expanding the optimization to all three similar cases in builtin/sparse-checkout.c. The now-final v3 patch completes this work, switching all locations to use string_list_append() followed by string_list_sort() for O(n log n) performance. The changes affect pattern collection in sparse_checkout_list() and two spots in write_cone_to_file(), while removing now-redundant duplicate checks.

The technical approach is uncontested and the patch appears ready for merging, representing a clean performance win in the sparse-checkout subsystem. This fits within the broader sparse-checkout/sparse-index optimization efforts led by Derrick Stolee and Elijah Newren, though it's a more localized improvement. With all review feedback addressed and no outstanding questions, this optimization is now complete and awaits maintainer pickup.
