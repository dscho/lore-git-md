This thread discusses a performance optimization for sparse-checkout pattern sorting, changing the algorithm from O(n²) to O(n log n) by switching from sorted insertion to append-then-sort. Amisha Chhajed originally proposed the change, which has now reached its fourth iteration with all feedback addressed.

The core improvement replaces string_list_insert() with string_list_append() followed by sorting, with special handling for duplicate patterns that can appear in user input. The patch is merge-ready with Junio's approval, having been thoroughly reviewed by Jeff King (who caught an edge case) and Derrick Stolee. Performance testing confirms the improvement, particularly with many duplicate patterns.

A recent exchange between Jeff King and Junio addressed whether the optimization needs explicit performance tests in the suite. Peff argued that while possible to demonstrate via artificial test cases, the improvement follows a well-understood pattern that doesn't require empirical proof, though a benchmark in the message would suffice. This comes as the final discussion point on an otherwise complete patch series.

Derrick Stolee had earlier suggested additional test improvements to better validate the change, which Amisha acknowledged but hasn't yet implemented. The thread shows the project's careful balance between rigorous validation and avoiding unnecessary test overhead for clear optimizations. This work fits into the broader sparse-checkout optimizations led by Stolee and Elijah Newren.
