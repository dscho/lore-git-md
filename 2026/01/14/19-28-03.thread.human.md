Amisha Chhajed has completed a performance optimization for sparse-checkout pattern handling, changing the sorting algorithm from O(n²) to O(n log n) by replacing the previous string_list_insert() approach with string_list_append() followed by sorting. The final version (v4) properly handles edge cases where user input might contain duplicate patterns in the recursive_hashmap while maintaining the optimization's performance benefits.

The patch has been thoroughly reviewed, with Jeff King initially identifying a regression in v3 related to duplicate handling, which Amisha addressed in this final version. Junio C Hamano has confirmed the technical correctness of the solution, noting it correctly distinguishes between the parent_hashmap (which guarantees unique entries) and recursive_hashmap (which may contain duplicates). While the patch is considered merge-ready, Junio suggested two optional follow-ups: adding performance measurements to quantify the improvement, and creating a test case to catch potential duplicate-handling regressions. He also floated the idea of a future API improvement (a combined sort-and-deduplicate function) but explicitly kept this out of scope for the current change.

This marks the completion of a focused optimization to the sparse-checkout subsystem's pattern handling, building on earlier work by Derrick Stolee and Elijah Newren. The changes maintain the delicate balance between pattern uniqueness guarantees and performance in cone mode pattern lists, with all reviewers agreeing the core optimization is correct and valuable. The remaining suggestions are enhancements rather than blockers, leaving the patch ready for merging into the next release cycle.
