Amisha Chhajed's optimization for sparse-checkout pattern sorting has progressed through several iterations, with the core goal of changing the algorithm from O(n²) to O(n log n) by replacing string_list_insert() with string_list_append() followed by sorting. While the performance improvement itself is uncontested, Jeff King and René Scharfe identified an edge case where the change could allow duplicate patterns to appear in the output when processing user input through recursive_hashmap.

The discussion has clarified that while parent_hashmap entries are guaranteed unique, recursive_hashmap may contain duplicates from commands like `git sparse-checkout add --stdin`. Amisha noted some confusion about why existing tests didn't catch this, suggesting the original implementation may have had redundant deduplication. There's now clear consensus on the solution: maintain the sorting optimization but restore duplicate removal where needed for recursive_hashmap cases.

The patch touches three locations in builtin/sparse-checkout.c's cone mode handling. With René confirming Jeff's analysis and the technical approach settled, the thread appears ready for a final version that addresses this edge case before Junio can merge the optimization. This represents a localized but meaningful improvement to the sparse-checkout subsystem's performance characteristics.
