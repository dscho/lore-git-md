Amisha Chhajed's patch series optimizes the sparse-checkout pattern sorting from O(n^2) to O(n log n) by replacing string_list_insert() with string_list_append() followed by sorting. The initial versions missed handling duplicate patterns in the recursive_hashmap case, which Jeff King identified. Amisha addressed this in v4 by adding explicit duplicate removal with string_list_remove_duplicates() after sorting.

Junio Hamano has now reviewed v4 and notes that while the tests pass, they may lack explicit coverage for the duplicate pattern case. He suggests adding a test based on Jeff King's example as follow-up work, though this doesn't block merging the current optimization. The changes affect pattern collection in sparse_checkout_list() and write_cone_to_file() in builtin/sparse-checkout.c, properly distinguishing between the parent_hashmap (guaranteed unique) and recursive_hashmap (may contain duplicates) cases.

The patch now correctly handles both scenarios while maintaining the performance improvement, and appears ready for merging as part of the ongoing sparse-checkout optimizations led by Derrick Stolee and Elijah Newren. The only remaining loose end is potential test coverage improvement, which Junio has provided guidance.
