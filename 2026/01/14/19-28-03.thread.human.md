This thread introduces a performance optimization for the sparse-checkout subsystem, specifically improving how pattern lists are built. The patch changes the implementation from using `string_list_insert()` (which maintains sorting during insertion with O(n^2) complexity) to a more efficient `string_list_append()` followed by a single pass sort (O(n log n)).

The change is small and focused, modifying just `builtin/sparse-checkout.c` to gather patterns unsorted from the hashmap before sorting them once. The author explains in the commit message that since hashmap entries are already unique, the uniqueness guarantee of `string_list_insert()` isn't needed, making this optimization safe. The patch appears well-motivated and correctly implemented, with a clear explanation of both the problem and solution. This seems like a straightforward, uncontroversial improvement to the sparse-checkout machinery.
