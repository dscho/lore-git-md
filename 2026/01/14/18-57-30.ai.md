This is a bugfix patch addressing a regression in Git's hook subsystem where stdout and stderr streams were incorrectly merged for pre-push hooks. The patch is part of a v3 series (1/2) from Adrian Ratiu, with the second patch focusing on the `ungroup` flag behavior.

The fix introduces a new `stdout_to_stderr` flag in `run_hooks_opt` that defaults to 1 (merge streams) for backward compatibility, while explicitly setting it to 0 for pre-push hooks in transport.c. This maintains the pre-push hook's historical behavior of keeping stdout and stderr separate, which many existing hooks rely on.

The patch includes extensive test coverage in t/t1800-hook.sh, verifying stream behavior for various client and server-side hooks. The tests are implementation-agnostic and will continue to validate behavior even as the hook subsystem evolves. The test suite now explicitly checks both the pre-push hook's special case and the default merged-stream behavior of other hooks.

This appears to be a well-constructed fix that:
1. Clearly identifies the regression (introduced in commit 3e2836a742d8)
2. Provides a backward-compatible solution
3. Adds comprehensive test coverage
4. Documents the new flag
5. Explicitly handles the pre-push hook special case

The patch follows the discussion thread where Chris Darroch reported the issue and brian m. carlson suggested this solution. The v3 iteration shows the author has incorporated feedback from previous rounds, particularly around test coverage and backward compatibility concerns.
