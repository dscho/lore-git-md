This is a discussion about configuring the default behavior of `git status`'s new branch comparison feature, specifically regarding triangular workflows (where push and pull remotes differ). The thread builds on Harald Nordgren's merged implementation that shows divergence from both upstream and push tracking branches.

Harald responds to D. Ben Knoble's argument for making push tracking display (`@{push}`) enabled by default, particularly to help users discover triangular workflows. He agrees with Ben's position, noting that most users don't have separate tracking and push branches anyway, so the default-on approach wouldn't affect them negatively. Harald also acknowledges Jeff King's more conservative stance on configuration defaults while suggesting that advanced users who need triangular workflows would be capable of adjusting the setting if needed.

The email highlights the ongoing tension between discoverability (showing push tracking by default to expose triangular workflow capabilities) and UI cleanliness (avoiding potentially confusing output for simple workflows). Harald's position leans toward the discoverability side, seeing little downside since most users wouldn't see the push tracking output unless they specifically configured triangular workflows. The discussion remains unresolved but continues to refine the understanding of real-world implications for different workflow types.
