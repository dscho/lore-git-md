This is the second patch in a 5-part series implementing consistent `ignore=all` behavior for submodules across Git commands, with a focus on aligning `git add` with `git status` and `git diff`. The patch introduces core behavior changes in `read-cache.c` to skip submodules marked with `ignore=all` during add operations unless explicitly forced with `--force`.

The implementation adds a new `skip_submodule()` helper function that checks several conditions before deciding whether to skip a submodule: it verifies the path is a directory, confirms the submodule has `ignore=all` configured, checks pathspec matching, and respects the `--force` flag. When skipping, it provides an advice message similar to how ignored files are handled. The change maintains the existing warning system through `override_submodule_config` while adding tracing for debugging.

The patch follows the design agreed upon in earlier discussion rounds, using `--force` as the override mechanism (settling a naming debate from previous versions). It builds on the plumbing changes from patch 1 (which added the `ignored_too` parameter) and will be followed by test updates and documentation in subsequent patches. The implementation appears thorough, with clear attention to edge cases like pathspec matching and sparse checkout compatibility.

This change enables workflows where submodules can be used more flexibly (similar to Google's repo tool) by making `git add` behavior consistent with other commands regarding ignored submodules. The patch maintains backward compatibility while adding the new `--force` requirement for updating ignored submodules.
