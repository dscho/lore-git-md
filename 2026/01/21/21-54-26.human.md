This is part of a larger hook subsystem refactoring series (patch 2/12) that introduces parallel execution support for Git hooks. The patch focuses on improving the run-command infrastructure that will be used by the parallel hook execution system.

Adrian Ratiu introduces a named `parallel_child` structure and a helper function `child_is_working()` to make the parallel process state checks more readable. This replaces repeated direct state checks with a named function, following a suggestion from Junio Hamano. The change is mechanical but improves code clarity - all existing state checks for `GIT_CP_WORKING` are updated to use the new helper.

The patch is a small but meaningful step in the series' goal of enabling parallel hook execution. It doesn't change behavior but makes the code more maintainable for the subsequent patches that will build on this foundation. The change is well-contained and clearly explained in the commit message.
