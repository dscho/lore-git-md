This is a performance optimization patch in the ongoing hook subsystem refactoring series, addressing throughput issues in parallel hook execution. The patch modifies the I/O polling in `run-command.c` to monitor both child input and output descriptors simultaneously, eliminating artificial 100ms latencies that were occurring when feeding data to multiple child processes in parallel.

The change was prompted by reports from Kristoffer Haugsbakk about throttled throughput and Jeff King's observation about potential deadlocks when pipes fill up. The solution refactors the polling loop to handle both directions of I/O, while maintaining the existing behavior for sequential execution (which uses different settings).

Junio Hamano raises a technical question about the assumption that child process error descriptors will always be positive integers, suggesting this may need clarification or adjustment. The patch touches core process management code but is narrowly focused on the parallel execution case, building on the `parallel_child` infrastructure introduced earlier in the series.

This appears to be a well-motivated optimization that solves a concrete performance problem while maintaining the series' overall goal of enabling efficient parallel hook execution. The change has already benefited from review from both the original reporter and Jeff King, and now awaits Junio's final assessment of the descriptor handling question.
