This is a follow-up technical note in an ongoing discussion about distinguishing push sources in Git hooks. Jeff King (Peff) provides a practical debugging tip for examining the environment variables available to pre-receive hooks when pushes occur via different transport protocols (SSH or HTTP).

The key suggestion is to add `env >&2` to a pre-receive hook, which will output all environment variables to stderr - visible to the client during push attempts. This allows administrators to inspect exactly what transport-specific variables (like SSH_CLIENT or REMOTE_ADDR) are available for differentiating push sources when multiple automated systems share the same user identity.

The email doesn't propose any changes to Git itself, but offers a concrete troubleshooting technique that builds on the thread's earlier transport-specific solutions. It's characteristic of Peff's style - providing immediately actionable technical advice that helps solve real-world problems without requiring core changes. The suggestion is particularly useful because it helps validate whether the transport-layer variables discussed earlier are actually present and usable in a given deployment scenario.
