This is part 3 of a 12-patch series refactoring Git's hook subsystem to support parallel execution and standardized APIs. The series has been through multiple iterations with input from Jeff King and Junio Hamano.

The patch introduces a stdin callback mechanism for `run_processes_parallel()`, allowing callers to stream large amounts of data to child processes without buffering everything in memory. This solves a practical problem seen in hooks like pre-push where input data might exceed pipe buffer sizes. The implementation adds a `feed_pipe_fn` callback interface that gets called repeatedly to write chunks of data to each child's stdin until completion.

Key technical changes include:
- New `feed_pipe` callback in `run_process_parallel_opts` struct
- Helper functions `child_is_ready_for_cleanup()` and `child_is_receiving_input()`
- Centralized I/O handling via `pp_handle_child_IO()`
- SIGPIPE handling during parallel execution
- Comprehensive test coverage in t0061 demonstrating stdin streaming

The patch maintains backward compatibility while providing the foundation for converting existing hooks to use the new parallel API. It's part of the broader hook subsystem modernization that will enable config-based hooks and parallel execution. The implementation follows Jeff King's suggested design and has already received positive feedback in earlier iterations.
