Feature: Conversion of receive-pack update hooks to new hook API.

This patch converts the update and post-update hooks in receive-pack.c to use the new hook API introduced in this series. The changes maintain all existing functionality while preparing for future parallel execution and config-based hook specification. The key technical aspects are:

1. Replaces direct child_process usage with run_hooks_opt, removing manual hook path finding and argument handling
2. Preserves sideband output handling for both sequential (via async muxer thread) and future parallel execution (via ungroup=0 output capture)
3. Maintains the same error handling and return codes as the original implementation
4. Adds proper cleanup of file descriptors and async muxer state

The conversion follows the pattern established in earlier patches of the series, with careful handling of stderr redirection being particularly important for receive-pack's sideband communication. The changes are mechanical but thorough, touching both the update hook (run per reference) and post-update hook (run once at the end).

This patch builds on the infrastructure from earlier in the series, particularly the stdin/stdout handling from patch 3 and the parallel execution groundwork from patch 9. It represents one of the final core hook conversions needed before the new API can be considered complete. The implementation has been reviewed by multiple contributors including Jeff King and incorporates his suggestions about output handling.
