This is a performance optimization patch in the ongoing hook subsystem refactoring series, addressing throughput throttling in parallel hook execution. The change modifies I/O polling in `run-command.c` to monitor both child input and output descriptors simultaneously, eliminating 100ms latencies that were occurring when feeding data to multiple child processes. The issue was reported by Kristoffer Haugsbakk and diagnosed by Jeff King, who noted the potential for deadlocks when pipes fill up.

The technical solution involves refactoring the polling loop to handle both directions of communication, with careful consideration given to maintaining backward compatibility with sequential execution (which uses different pipe handling). The patch doubles the pollfd array size to accommodate monitoring both input and output descriptors for each child process.

Junio Hamano raises a question about the safety of assuming child process error descriptors will never be 0 (stdin), suggesting this might need clarification or adjustment in the implementation. This reflects the maintainer's attention to edge cases in the parallel process management infrastructure.

The change builds on prior work in the series while maintaining the existing behavior for sequential execution cases. It represents a key optimization for the parallel hook execution capability being introduced in this multi-part refactoring effort.
