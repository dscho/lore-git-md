This is part 9/14 of Patrick Steinhardt's ODB abstraction series, continuing the refactoring of Git's object storage layer to support pluggable backends. The patch converts promisor object enumeration to use the new `odb_for_each_object()` API introduced earlier in the series.

The change affects three key areas that handle promisor objects (objects stored in remote packs that can be fetched on demand): `packfile.c`, `repack-promisor.c`, and `revision.c`. Each previously used `for_each_packed_object()` with the `PROMISOR_ONLY` flag, which is now replaced with the unified iteration API. The patch demonstrates how the new API simplifies callback signatures by eliminating unused parameters like `pack` and `pos`, while maintaining all existing functionality.

Notable technical details:
- The `add_promisor_object()` callback in `packfile.c` now takes a context structure to pass repository and oidset data
- All three callbacks are updated to use the new `object_info` parameter pattern
- The `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` flag behavior is preserved
- The changes reduce code duplication while keeping the same promisor object handling logic

This conversion follows the pattern established in part 8's fsck changes, showing the API's applicability across different subsystems. The patch continues the series' methodical approach, with each step building confidence in the larger ODB abstraction effort.
