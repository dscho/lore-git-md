This is a discussion about removing global state (`the_repository` and `the_hash_algo`) from `git show-index`, part of Shreyansh Paliwal's RFC series modernizing this plumbing command. Phillip Wood raises concerns about the approach, noting that passing a `struct repository*` parameter causes problems when the command runs outside a repository (a supported use case for this low-level tool).

Phillip argues that builtin commands should continue using `the_repository` since they operate on a single repository anyway, and suggests focusing modernization efforts on library code instead. He points to `wt-status.c` as a more productive target for removing global state. The technical disagreement highlights a tension in the `the_repository` removal effort - while the goal is laudable, some commands may need special consideration for their edge cases.

The email also reveals broader skepticism about the value of converting builtins, with Phillip calling the repository parameter addition "a mistake" that creates new problems while distracting from more impactful cleanup work. This patch sits at the intersection of two ongoing efforts: removing global state and modernizing `git show-index`'s hash detection, with the former complicating the latter in this case.
