This is part 7 of a 12-part series refactoring Git's hook subsystem to use a standardized API. The patch converts the pre-push hook implementation in `transport.c` from direct `run-command` usage to the new `hook.h` interface.

The key changes include:
- Replacing the manual child process setup with a `run_hooks_opt` structure
- Moving the ref iteration logic into a `pre_push_hook_feed_stdin` callback that streams ref data to the hook process
- Preserving the pre-push hook's expectation of separate stdout/stderr streams via a new `stdout_to_stderr` flag
- Maintaining all existing functionality while simplifying the code by about 40 lines

The patch builds on earlier work in the series that introduced stdin streaming capabilities and parallel execution support. It addresses a regression reported by Chris Darroch regarding stdout/stderr handling in pre-push hooks, with design input from brian m. carlson. The implementation follows Jeff King's suggested approach for sideband output and child process communication.

This conversion is part of the broader effort to standardize hook execution across Git, with all major technical concerns now resolved according to the thread summary. The patch carries sign-offs from both the original author (Emily Shaffer) and major contributor (Ævar Arnfjörð Bjarmason), indicating consensus on the approach.
