This is a feature proposal for Git to support repositories with intentionally missing objects, aimed at Debian's use case of storing source packages while omitting non-redistributable files or vendored dependencies.

Simon Richter outlines Debian's goal to move from tarballs to Git-based storage while needing to exclude certain files from upstream repositories. The key requirements are:
1. Verifying unmodified files in received bundles
2. Listing removed paths (potentially entire subdirectories)
3. Allowing continued work on clones as long as omitted paths aren't touched
4. The minimal archive would contain a commit, its tree, dependencies, and optionally a signed tag - similar to `git archive` output but with tag signatures and clone capability.

The proposal suggests this could also help recover repositories with broken/missing objects. Simon is seeking feedback on whether this violates Git's design principles or if better approaches exist.

The email frames this as an early discussion starter rather than a concrete implementation plan. The use case appears legitimate for Debian's packaging workflow, though the technical feasibility within Git's object model would need exploration - particularly how to maintain integrity while allowing intentional omissions. The proposal doesn't suggest specific interface changes yet, focusing first on conceptual validation.
