Git thread summary:

Feature proposal for Git to support repositories with intentionally missing objects, targeting Debian's use case of storing source packages while excluding non-redistributable files or vendored dependencies. Simon Richter's original proposal outlined requirements: verifying unmodified files in received bundles, listing removed paths, allowing work on clones that avoid omitted paths, and maintaining minimal archive contents (commit, tree, dependencies, optionally signed tag). Philip Oakley responds by referencing prior discussions about object redaction from Git Merge 2020, noting no clear solution emerged, and explores technical challenges around maintaining repository integrity while allowing omissions. He suggests speculative approaches for handling blob and tree objects through specially-formatted replacement objects that preserve commit graph structure, while acknowledging these are unproven ideas.

Key technical constraints under discussion include Git's hash-based integrity model, the metadata vs content distinction, and the difficulty of creating exceptions to Git's object model without breaking fundamental properties. The conversation remains at conceptual stage, focused on finding a minimal viable feature that could work within Git's design principles while addressing Debian's specific need to exclude non-redistributable files from packaged repositories. No concrete implementation proposals have been made yet - the thread is validating whether such a feature could theoretically coexist with Git's core object model. Open questions remain about how to handle verification of partial repositories and whether any solution could maintain sufficient integrity guarantees for distributed workflows.
