Git thread summary:

Feature proposal for Git to support repositories with intentionally missing objects, targeting Debian's use case of storing source packages while excluding non-redistributable files or vendored dependencies. Simon Richter outlines requirements: verifying unmodified files in received bundles, listing removed paths, allowing work on clones that avoid omitted paths, and maintaining minimal archive contents (commit, tree, dependencies, optionally signed tag). The proposal seeks feedback on whether this violates Git's design principles or if better approaches exist, positioning it as an early discussion starter rather than concrete implementation. Potential applications include Debian's packaging workflow and recovery of repositories with broken objects. Technical feasibility within Git's object model remains to be explored, particularly integrity maintenance with intentional omissions. No specific interface changes proposed yet - focused on conceptual validation first.
