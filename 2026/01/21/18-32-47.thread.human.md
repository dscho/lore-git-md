This thread reports an unexpected behavior in `.gitignore` pattern matching. Alf Clement found that adding `backup_STOCKS*/` to `.gitignore` causes Git to ignore not only the intended `backup_STOCKS_*` directories but also an unrelated `backups/` directory that shouldn't match the pattern. The report includes clear reproduction steps showing the behavior in Git 2.43.0 on WSL2/Linux.

The issue appears to be a bug in Git's pattern matching logic where the `backup_STOCKS*/` pattern is incorrectly matching the shorter `backups/` directory name. The report is well-documented with all necessary details to reproduce, making it a solid bug report that would need investigation from someone familiar with Git's directory handling code (likely in dir.c or dir.h). No responses or analysis from other contributors have been posted yet.
