Thread identity: Discussion about unexpected `.gitignore` behavior with directory patterns, specifically how unanchored patterns like `backup_STOCKS*/` can cause Git to skip entire directories during traversal.

Core problem: When a directory matches an unanchored ignore pattern, Git stops traversing that directory entirely, making it appear empty in `git status` output. This is standard Git behavior but can be surprising to users, particularly regarding how Git handles directories containing only ignored files.

Key technical details:
- Unanchored patterns (without leading `/`) match anywhere in the path
- Directory patterns ending with `/` cause Git to skip the entire directory
- Git doesn't report directories as untracked when they contain only ignored files
- This affects commands like `git status` that rely on directory traversal
- Behavior can be demonstrated by observing `git status` output changes as files are added/ignored

Solutions provided:
1. Anchor the pattern with leading slash (`/backup_STOCKS_*/`) to make it only match at top level
2. Use `git check-ignore -v` to diagnose which ignore rule affects a path
