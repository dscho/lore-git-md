This is a performance improvement patch in the ongoing hook subsystem refactoring series. It addresses a throughput throttling issue in parallel hook execution reported by Kristoffer Haugsbakk, where Jeff King identified a potential deadlock risk when feeding data to child processes.

The patch modifies the I/O polling in `run-command.c` to monitor both child input and output file descriptors simultaneously, eliminating artificial 100ms latencies that could occur when feeding multiple parallel hooks. The change ensures hooks receive data promptly while maintaining responsiveness for sideband output. The solution preserves the existing sequential execution behavior (which uses different settings) while optimizing the parallel case.

Key technical changes include refactoring the I/O loop to handle bidirectional polling and addressing edge cases where full pipes could cause deadlocks. The patch builds on prior work in the series that introduced parallel execution infrastructure via `struct parallel_child` and maintains compatibility with the hook API standardization effort.
