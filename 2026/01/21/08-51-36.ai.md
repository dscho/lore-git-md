This is a follow-up discussion in Taylor Blau's multi-pack-index compaction series, specifically addressing the removal of overflow helper functions. Patrick Steinhardt responds to Taylor's patch that drops the `u64_add()` and `u64_mult()` helpers from `git-compat-util.h`, suggesting an alternative approach that combines the benefits of both the original helpers and the new inline checking.

Patrick points out that Taylor's approach of using `unsigned_mult_overflows()` directly requires repeating the computation, which could lead to errors if the check and actual computation diverge. He proposes a hybrid solution - a function that performs the check and computation together while allowing the caller to handle failures, giving an example implementation of `u64_mult()` that returns a boolean success/failure and writes the result to an output parameter.

This feedback comes after Junio C Hamano had previously suggested removing these helpers in favor of more contextual error messages, which Taylor implemented in his patch. Patrick's suggestion aims to maintain the safety of the original helpers while addressing Junio's concern about opaque error messages by keeping the failure handling with the caller.

The discussion shows careful consideration of API design tradeoffs in Git's low-level utilities, balancing safety against flexibility and maintainability. Patrick's alternative would preserve the atomic check-and-compute operation while still allowing callers to provide their own error handling context. This exchange demonstrates the project's attention to detail in foundational code that handles potentially dangerous operations like integer arithmetic.
