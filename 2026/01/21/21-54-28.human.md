This is part 4 of a 12-patch series refactoring Git's hook subsystem to support parallel execution and streaming input. The patch introduces a callback mechanism for feeding stdin to hooks, complementing the existing file-based stdin approach.

The change allows hooks to receive large amounts of input data without buffering everything in memory or going through the filesystem. This is particularly useful for hooks like pre-push that may process substantial input. The implementation builds on the parallel stdin callback mechanism added in the previous patch, adding hook-specific plumbing to manage the streaming interface.

Key technical changes include:
- A new `feed_pipe` callback in `struct run_hooks_opt`
- Support for context and state management via `feed_pipe_ctx` and `feed_pipe_cb_data` fields
- Safety checks to prevent mixing file-based and callback-based stdin
- Integration with the parallel execution infrastructure from patch 3

The patch maintains the series' high quality with thorough documentation of the new interfaces and clear error handling. It's a well-motivated improvement that solves a real limitation in how hooks currently handle input, while fitting cleanly into the broader hook refactoring effort.
