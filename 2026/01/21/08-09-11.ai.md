This is a technical discussion about hash algorithm detection in `git show-index`, part of an ongoing RFC patch series modernizing the command. Patrick Steinhardt weighs in on Junio C Hamano's earlier feedback about the fragility of detecting hash algorithms by file size patterns in pack index files.

Patrick agrees with Junio that the current approach of guessing between SHA-1 and SHA-256 based on file size is problematic, especially considering future hash algorithm changes. He notes the index format lacks explicit hash algorithm identification, making reliable detection impossible without user input. The existing `--object-format` option already provides a manual override for this case.

The key technical point is Patrick's suggestion that a proper fix would require introducing a new index format version (v5) with explicit hash algorithm metadata in its header. However, he questions whether this complexity is justified for `show-index`, which is primarily a debugging tool for pack files. The discussion highlights the tension between correctness and practicality when maintaining legacy formats, with both contributors acknowledging the limitations while stopping short of proposing immediate action.
