This is part 3 of a 12-patch series refactoring Git's hook subsystem to support parallel execution and standardized APIs. The series has been through multiple iterations and is now in its 7th version, with all major technical concerns addressed and consensus reached.

The current patch introduces a stdin callback mechanism for `run_processes_parallel()`, allowing callers to stream large inputs to child processes without buffering everything in memory. This solves a real problem where hook input could exceed pipe buffer sizes or available memory. The implementation follows Jeff King's design suggestions and includes comprehensive test coverage.

Key changes in this version:
- New `feed_pipe_fn` callback type for incremental stdin writing
- Helper functions to track child process stdin state
- SIGPIPE handling to prevent crashes during parallel writes
- Test cases verifying stdin streaming behavior

The patch is well-structured with clear documentation of the new API. It maintains backward compatibility while enabling the hook subsystem's transition to parallel execution. The changes demonstrate careful attention to edge cases and proper resource cleanup.
