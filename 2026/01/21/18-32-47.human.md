This is a bug report about unexpected behavior in `.gitignore` pattern matching. Alf Clement reports that adding `backup_STOCKS*/` to `.gitignore` not only ignores the intended `backup_STOCKS_*` directories as expected, but also unexpectedly ignores a separate `backups/` directory that should remain visible.

The report includes clear reproduction steps showing the before-and-after `git status` output, demonstrating that after adding the pattern, both `backup_STOCKS_*/` and `backups/` disappear from the untracked files list. The behavior appears to violate Git's documented pattern matching rules, where `backup_STOCKS*/` should only match directories starting with exactly "backup_STOCKS".

The bug appears in Git 2.43.0 on Linux/WSL2. The report is well-formatted with complete system information and follows Git's bug reporting template. This looks like a legitimate pattern-matching issue that warrants investigation, particularly since it affects a core functionality (ignoring files) that many users rely on daily.
