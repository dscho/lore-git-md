This is part 9/10 of Ezekiel Newren's xdiff refactoring series aimed at preparing the diff subsystem for Rust interoperability. The patch focuses on `xdl_cleanup_records()`, decoupling it from the classifier to enable moving it between files.

Phillip Wood questions the performance impact of this change, noting it appears to save little work for patience/histogram diffs while adding a second pass for Myers diffs. He suggests the Rust conversion rationale might be more compelling than performance claims. The review also echoes René Scharfe's earlier concern that this doesn't sufficiently demonstrate the IVec API's capabilities.

Key technical changes:
- Removes line counting from `xdl_classify_record()`
- Introduces new `xoccurrence` struct and IVec to track line matches
- Moves line counting into `xdl_cleanup_records()` using the new structure
- Adds `mph_size` field to `xdfenv_t` to track classifier count
- Maintains same cleanup logic but with independent counting mechanism

The patch continues the series' pattern of structural changes to support Rust compatibility while preserving diff behavior. Phillip's review indicates this change may need stronger justification around either performance impact or Rust integration benefits to be fully convincing. The discussion reflects ongoing tension between immediate performance considerations and long-term architectural goals in the Rustification effort.
