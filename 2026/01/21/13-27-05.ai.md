This is a documentation patch addressing a linter issue related to conditional section inclusion in man pages. Jean-Noël Avila proposes a refinement to `Documentation/lint-gitlink.perl` to better handle `ifdef`/`ifndef`/`endif` block macros in AsciiDoc files.

The change simplifies the linter by preemptively skipping any line that starts with these block macro directives, rather than trying to handle them inline with the linkgit macro checks. This avoids false positives when the linter encounters the new multiple-attribute `ifndef` syntax (like `ifndef::git-replay+git-shortlog[]`) that was recently introduced for `git-replay` and `git-shortlog` documentation.

The patch follows Junio C Hamano's earlier observation that the linter needed updating to accommodate this new syntax pattern. Jean-Noël notes this approach is both more efficient and safer than the previous broad regex matching, since it specifically targets the block macro lines that were causing issues. The change maintains the linter's original purpose of catching malformed linkgit references while being more permissive with conditional documentation directives.

This is a straightforward technical improvement to Git's documentation tooling that should allow the previously discussed `git-replay` formatting options cleanup to proceed without linter warnings. The patch appears well-considered and builds on established patterns for handling AsciiDoc conditionals in Git's documentation.
