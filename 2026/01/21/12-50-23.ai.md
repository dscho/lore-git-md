This is part 7/14 of Patrick Steinhardt's v3 series refactoring Git's object database (ODB) layer to support pluggable backends. The patch introduces a new high-level API function `odb_for_each_object()` that provides unified iteration over all objects in the database, whether they are stored as loose objects or in packfiles.

The new function serves as a coordinator between the lower-level iteration mechanisms introduced in previous patches (parts 4-6). It:
1. Handles the alternates chain by calling `odb_prepare_alternates()`
2. Iterates through each ODB source while respecting the LOCAL_ONLY and PROMISOR_ONLY flags
3. Delegates to `odb_source_loose_for_each_object()` and `packfile_store_for_each_object()` for the actual iteration work
4. Propagates any errors from the callback or iteration

The implementation maintains the same callback interface used throughout the series, taking a `struct object_info` parameter and supporting the same flag behaviors. The header documentation clearly notes the possibility of duplicate iteration when objects exist in multiple sources.

This patch represents a key integration point in the series, bringing together the loose and packed object iteration paths under a single API. The careful preservation of existing behavior (like flag handling and error propagation) continues the series' pattern of methodical refactoring. Subsequent patches will migrate callers to use this new unified interface.
