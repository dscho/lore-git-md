Bugfix for `git stash` with intent-to-add files. This email reports that a known issue with `git stash` failing on files added with `--intent-to-add` still persists in Git 2.52.0, nearly five years after the original report. The bug manifests when trying to stash a new file that was marked with `git add --intent-to-add` - instead of stashing the file, Git errors out with "Entry not uptodate" message.

The reporter confirms the behavior matches the original 2021 bug report, where the stash operation incorrectly rejects files in this state rather than saving them. This appears to be a long-standing edge case in the stash implementation's handling of intent-to-add files. The email serves as a reminder that this issue remains unresolved across multiple Git versions.

While the email doesn't propose a fix, it provides useful context by linking to the original GitHub issue that surfaced the problem in the lint-staged project. The persistence of this bug suggests it may require deeper changes to how stash interacts with the index state for intent-to-add files.
