This is part of a larger hook subsystem refactoring series (v7, patch 9/12) that standardizes Git's hook execution on a new `hook.h` API. The patch adds parallel execution capability by introducing a `jobs` option to control how many hook processes can run simultaneously.

The change allows callers to specify parallelization while defaulting to sequential execution (jobs=1) to maintain current behavior. When jobs>1, output is buffered to prevent interleaving, using `run-command`'s existing buffering rather than reinventing it. The commit includes ASCII diagrams showing both sequential and parallel execution flows, with the parallel case routing output via a sideband muxer thread as suggested in earlier discussion.

This appears to be a well-considered incremental step in the hook refactoring effort, building on Jeff King's design suggestions and maintaining compatibility with existing hook behavior. The patch is nearing merge readiness with sign-offs from key contributors and no outstanding objections.
