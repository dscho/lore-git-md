This is a performance improvement patch in the ongoing hook subsystem refactoring series. It addresses I/O bottlenecks in parallel hook execution by making the parent process poll both child input and output file descriptors simultaneously rather than just outputs.

The change eliminates artificial 100ms latency spikes that could occur when feeding data to multiple child processes, as reported by Kristoffer Haugsbakk. It also prevents potential deadlocks where parent and child processes could block waiting for each other, a scenario Jeff King identified. The implementation refactors the I/O handling loop in `run-command.c` to manage both directions of communication more efficiently using a single `poll()` call with twice as many file descriptors.

While this patch touches core process management code, its impact is currently limited to parallel hook execution scenarios (sequential execution remains unchanged). The change demonstrates careful attention to edge cases like signal handling and process cleanup, with the existing test suite providing validation. This represents one of the final refinements to the hook infrastructure before the series can be merged.
