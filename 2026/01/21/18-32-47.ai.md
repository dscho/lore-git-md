This is a bug report about unexpected behavior in `.gitignore` pattern matching. The reporter, Alf Clement, describes a case where adding `backup_STOCKS*/` to `.gitignore` unexpectedly suppresses both `backup_STOCKS*` directories *and* a separate `backups/` directory that should not match the pattern.

The report includes clear reproduction steps showing:
1. Initial state with multiple untracked `backup_STOCKS_*` directories and a `backups/` directory visible in `git status`
2. After adding `backup_STOCKS*/` to `.gitignore`, both the targeted patterns and the unrelated `backups/` directory disappear from untracked files
3. The full `.gitignore` contents showing no other patterns that would explain this behavior

The behavior appears to be a bug in Git's pattern matching where the `backup_STOCKS*/` pattern is somehow also matching the shorter `backups/` directory name. The report includes system information showing Git 2.43.0 running on WSL2/Linux 6.6.87.2.

This looks like a legitimate pattern matching issue that would need investigation from someone familiar with Git's dir.c or dir.h internals. The report is well-formatted with clear reproduction steps and system details, making it easy to verify.
