This is a follow-up discussion in Taylor Blau's multi-pack-index compaction series, specifically addressing error handling for arithmetic operations. Patrick Steinhardt responds to Taylor's patch that removes the `u64_add()` and `u64_mult()` helper functions from git-compat-util.h.

Patrick acknowledges Taylor's approach of removing the helpers in favor of direct overflow checks with better error messages, but suggests an alternative design that combines the benefits of both approaches. He proposes a new helper function signature that would:
1. Perform the overflow check
2. Store the result in an output parameter
3. Return a boolean

This would allow callers to handle failures while avoiding code duplication between the check and the actual computation. The suggested pattern would make the calling code cleaner while maintaining the ability to provide detailed error messages.

The discussion shows careful consideration of API design tradeoffs in error handling, with Patrick building on Junio Hamano's earlier feedback about improving error messages. This is a technical refinement to an already mature patch series that has received extensive review.
