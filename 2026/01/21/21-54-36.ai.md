This is the final patch in a 12-part series converting Git's hook subsystem to a new API, specifically targeting receive-pack's update and post-update hooks. The conversion brings these hooks in line with the standardized `hook.h` interface that has been progressively applied to other hook types throughout the series.

The patch replaces direct `child_process` usage with the new `run_hooks_opt` API while carefully preserving receive-pack's sideband output handling - a critical feature for remote operations. Key technical changes include:

1. Reimplementing the hook feeding mechanism via a new `feed_receive_hook_cb` callback that handles the same ref update streaming as before but through the new API's pipe interface
2. Maintaining push certificate and push option environment variable setup by moving them into the `run_hooks_opt` structure
3. Preserving the async muxer thread for sideband output during both sequential and future parallel execution
4. Adding proper cleanup of file descriptors and async muxer state

The implementation follows the pattern established in earlier conversions, with particular attention to stderr redirection for receive-pack's sideband communication. The changes have been reviewed by Jeff King and incorporate his suggestions about output handling. This completes the foundation for config-based hooks and parallel execution in future work.

The patch demonstrates careful attention to backward compatibility while modernizing the implementation. It represents the culmination of a multi-year effort to standardize Git's hook subsystem, with all major technical concerns addressed and consensus reached among maintainers. The series is now in its final form and ready for merging.
