This is part 8 of a 12-patch series refactoring Git's hook subsystem to use a unified API. The patch converts the reference-transaction hook implementation from direct `run-command` calls to the new `hook.h` interface.

The change removes manual child process setup and signal handling, replacing it with the hook API's built-in capabilities. The ref update data is now streamed to the hook process via a callback function (`transaction_hook_feed_stdin`) that processes one ref update per call, though the commit message notes this could be batched for better throughput if needed.

Key technical changes:
- Removes `run-command.h` and `sigchain.h` includes as they're no longer needed
- Introduces a `transaction_feed_cb_data` struct to track state between callback invocations
- Replaces the manual process management with a `run_hooks_opt` structure
- Maintains all existing functionality while simplifying the code by about 50 lines

The patch has sign-offs from both Emily Shaffer (original author of the hook API work) and Ævar Arnfjörð Bjarmason (a major contributor to the series), indicating consensus on the approach. This continues the series' pattern of incrementally converting each hook type to the new API while preserving behavior.
