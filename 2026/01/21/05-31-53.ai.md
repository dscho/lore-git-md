This is a follow-up technical note in an ongoing discussion about hook access control. Jeff King (Peff) provides a practical debugging tip for examining the environment variables available to pre-receive hooks when trying to a Git server. He suggests adding `env >&2` to the hook script to dump all environment variables to stderr, which will be visible to the client during a push attempt.

The context from earlier in the thread establishes that Git itself doesn't provide push source information to hooks, but various transport mechanisms (SSH, HTTP) may expose relevant details through environment variables like SSH_CLIENT or REMOTE_ADDR. Peff's suggestion offers a straightforward way for administrators to inspect what information is actually available in their specific server configuration, which could help implement transport-specific access controls.

This is a small but useful contribution to the thread - not proposing any changes to Git itself, but providing a concrete debugging technique that helps answer the original question about what information hooks can access. The approach is consistent with the thread's emerging consensus that solutions will need to be transport-specific rather than relying on core Git functionality.
