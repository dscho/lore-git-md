Maintainer comment on type safety verification in xdiff refactoring.

Junio C Hamano weighs in on the discussion about verifying type safety in the xdiff refactoring series, specifically addressing Jeff King's concerns about runtime tests for undefined behavior. The maintainer agrees with Jeff's position that testing undefined behavior is "more or less pointless" while allowing that implementation-defined behavior might be testable in some cases.

This brief comment serves to reinforce the technical caution expressed earlier in the thread about the proposed `clar` unit tests for IVec type sizes and layouts. Junio references a potential prior discussion about using unions as an alternative approach, though he's uncertain if this was in the same thread context.

The exchange highlights the maintainer's preference for avoiding tests that rely on undefined behavior, which aligns with Git's general emphasis on portable, well-defined code. This positions the discussion as part of Git's ongoing focus on platform compatibility and type safety, particularly relevant given the Rust interoperability goals of the larger refactoring effort.
