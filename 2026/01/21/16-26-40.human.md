This is a refactoring patch targeting the symlink handling code. Tian Yuchen changes the type of several flag variables from `int` to `unsigned int` in `symlinks.c` and `symlinks.h` to better reflect their usage as bitmasks and avoid potential undefined behavior with signed integer operations.

The patch follows up on feedback from Patrick Steinhardt in v1, where the author had initially made `ret` and `saved_errno` unsigned as well - these have been reverted to signed types since they need to hold negative values (like -1 from `lstat()`). The changes are straightforward and focused, touching only the type declarations while keeping all the logic identical.

This appears to be a sensible improvement that makes the code's intent clearer and avoids potential pitfalls with signed bitwise operations. The patch is small, well-explained, and addresses a real (if somewhat theoretical) issue in a way that matches common C practices for bitmask handling.
