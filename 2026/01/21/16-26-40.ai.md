This is a refactoring patch that changes the type of bitmask flags in the symlinks code from `int` to `unsigned int`. The change addresses potential undefined behavior when performing bitwise operations on signed integers, particularly if the most significant bit is set. The patch affects several functions in the symlinks subsystem that use these bitmasks for tracking file status flags.

The v2 iteration properly separates the signed return values (like `lstat()` results and errno) from the unsigned flag variables, addressing feedback from Patrick Steinhardt. The changes are mechanical but important for correctness, touching both the implementation in symlinks.c and the struct definition in symlinks.h.

The patch appears well-justified and narrowly focused - it doesn't change any behavior, just makes the type usage more correct according to C standards. The commit message clearly explains the motivation and the v2 changes. This seems like a straightforward improvement that should be uncontroversial to merge.
