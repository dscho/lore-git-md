This is a bugfix for the histogram diff algorithm in xdiff, addressing a rare edge case where shifted change groups during compaction can produce redundant diff output that includes matching lines from both files. The issue was originally reported and fixed by Yee Cheng Chin, and Junio C Hamano is now reviewing the patch.

The problem occurs when the histogram diff's compaction phase shifts change groups across anchor points, sometimes resulting in diffs that show unchanged lines as modified. The fix detects when shifting has created new matching groups and re-diffs those sections using Myer's algorithm while preserving all original diff flags. Junio confirms the problem is real ("So true") and the solution correct ("OK"), but raises two review points:

1. He questions whether the 1% occurrence rate is actually acceptable, suggesting it might be too high for production use.
2. He suggests the implementation could be clearer by moving the new logic into a helper function called specifically from the "slide-up" case, since that's the only path where the new code is relevant.

The patch appears well-motivated with clear examples and test coverage (including a new test file t4073-diff-shifted-matched-group.sh). While the issue is rare (affecting <1% of diffs in surveyed repositories), the fix eliminates clearly undesirable output when it does occur. Junio's review focuses on code organization rather than the core algorithm, indicating the technical approach is sound.
