This is a performance improvement patch in the ongoing hook subsystem refactoring series. It addresses a throughput throttling issue reported by Kristoffer Haugsbakk, where child processes in parallel hook execution could experience artificial 100ms delays due to I/O polling behavior. The patch modifies the run-command I/O loop to poll both child input and output file descriptors, eliminating potential deadlocks (as noted by Jeff King) and ensuring data is fed to parallel hooks as quickly as possible while maintaining output responsiveness. The change specifically benefits parallel execution while leaving sequential hook behavior unchanged.

The solution builds on prior work in the series that introduced parallel hook infrastructure, and it follows the established pattern of addressing real-world performance issues that emerge during the large-scale hook refactoring. With maintainer approvals already in place and CI validation complete, this appears to be a well-vetted technical improvement to the series' core parallel execution mechanism.
