This is part 10/14 of Patrick Steinhardt's ongoing ODB abstraction series, continuing the effort to enable pluggable object storage backends in Git. The patch refactors two key areas - `builtin/cat-file.c` and `commit-graph.c` - to stop using the direct `for_each_loose_object()` and `for_each_packed_object()` functions in preparation for their eventual removal.

The changes introduce new callback-based iteration patterns using the intermediate `odb_source_loose_for_each_object()` and `packfile_store_for_each_object()` APIs. In `cat-file`, this involves restructuring the loose and packed object iteration to work through the ODB source chain, while maintaining the same filtering behavior. For the commit-graph generation, it consolidates the packed object handling into a shared callback that works with both the old and new iteration styles.

Notable technical details:
- Introduces new `batch_one_object_oi()` and `add_packed_commits_oi()` callbacks that handle both loose and packed objects through a unified interface
- Preserves existing progress reporting and filtering capabilities during the transition
- Explicitly notes that some callers can't yet use the fully generic `odb_for_each_object()` API due to architectural constraints
- Maintains backward compatibility by keeping the same callback signatures where needed

The patch continues the series' pattern of careful, incremental refactoring - each subsystem conversion builds on the foundational work from earlier patches while keeping the changes focused and reviewable. The ODB abstraction effort is clearly progressing methodically through Git's object storage layer.
