This is a discussion about hook access control, continuing a thread where Chris Packham seeks a way to distinguish push sources in pre-receive hooks when multiple automated services share the same user identity.

Jeff King (Peff) responds with practical suggestions for identifying push sources through transport-specific environment variables. For SSH connections, he notes `$SSH_CLIENT` may contain source IP information, while HTTP pushes might expose `$REMOTE_ADDR` or `$REMOTE_USER`. He also suggests SSH key-based solutions using `authorized_keys` environment fields or command restrictions.

The response confirms Git itself doesn't track push sources natively, but provides workable approaches leveraging the transport layer's metadata. Peff's suggestions are characteristically thorough, offering multiple angles to solve the real-world problem while acknowledging the limitations of Git's hook interface. The advice focuses on transport-layer identification rather than trying to modify Git's core behavior.
