This is a discussion about the ongoing `the_repository` removal effort, specifically regarding whether builtin commands should retain the global variable. The thread started with an RFC patch series modernizing `git show-index`, but has shifted to a broader debate about the scope of the global variable removal.

Junio C Hamano concurs with Phillip Wood's critique that builtin commands should continue using `the_repository` since they inherently operate on a single repository. Phillip had argued that forcing repository parameters onto builtins creates unnecessary complexity (as seen in a segfault in the original patch) and distracts from the more valuable work of removing globals from library code.

This exchange helps establish an important boundary for the `the_repository` removal effort: library functions should be parameterized to work with any repository, while builtin commands can reasonably keep using the global since they are inherently single-repository operations. The discussion shows consensus forming around focusing the refactoring effort where it provides the most architectural benefit.
