This is a review comment on Patrick Steinhardt's ODB abstraction series, specifically addressing patch 02/14 which proposed changing flag parameters from enum types to unsigned integers.

Jeff King (Peff) argues that using the enum type is preferable for flag parameters, citing two main reasons: better human readability (the enum documents which flags are expected) and potential compiler benefits for large flag sets. He suggests the patch should instead standardize on using the enum type consistently rather than switching to unsigned.

The exchange highlights an ongoing tension in the codebase between type safety/readability and simplicity. Peff's review carries weight given his long history of careful, precise contributions to Git. His suggestion aligns with existing patterns seen elsewhere in the codebase where flags are passed as enum types.

This is a focused technical discussion about API design within the larger ODB abstraction effort. While not blocking the series' progress, it represents the kind of detailed review that helps maintain code quality in a complex refactoring.
