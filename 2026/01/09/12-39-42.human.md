This is part 13 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend verification. The patch fixes a bug in the reftable backend's consistency checking behavior with worktrees.

Currently, when running ref verification (`git refs verify`), the reftable backend incorrectly checks all worktree refs regardless of which worktree is specified, unlike the files backend which correctly limits checks to the requested worktree. The patch shows this was doubly wrong - not only was it checking the wrong scope, but the iteration mechanism wasn't even working properly, causing it to only check the main worktree's refs.

The fix properly scopes verification to just the requested worktree by:
1. Using the new `backend_for_worktree()` helper from the previous patch
2. Distinguishing between main and non-main worktrees
3. Adding proper error handling for broken worktree stacks

The patch includes new tests that verify the fixed behavior by:
- Creating a worktree and checking both main and worktree ref stores
- Simulating broken reftable stacks and verifying the correct error messages
- Confirming each worktree's verification is independent

This continues the series' focus on aligning reftable backend behavior with the files backend while improving verification infrastructure. The changes are mechanical but important for correctness, with clear test coverage demonstrating the fixed behavior.
