Platform compatibility patch adding Windows directory symlink support, part of a larger series to complete comprehensive symlink handling on Windows. This patch specifically handles the case where symlink targets are directories, which requires special handling on Windows since symlinks must be explicitly marked as pointing to files vs directories.

The implementation creates a mechanism to track "phantom" symlinks (those created before their target exists) and processes them when new directories are created. It uses Windows APIs like `CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS` to properly detect directory targets, and maintains a thread-safe list of pending symlinks to process. The approach handles edge cases like targets changing type or being created in another process, though with acknowledged limitations in those scenarios.

Key technical elements include:
- New `process_phantom_symlink()` function to check and convert symlink types
- Thread-safe `phantom_symlinks` list management using critical sections
- Integration with `mingw_mkdir()` to trigger processing of pending symlinks
- Path normalization and relative path handling utilities
- Windows-to-POSIX error code conversion

The patch has been signed off by both Karsten Blees and Johannes Schindelin (Dscho), indicating consensus from the Windows platform experts. It represents one of the final pieces in a multi-year effort to bring comprehensive symlink support to Git on Windows, building on Git for Windows' foundational work. The implementation appears thorough, with careful attention to edge cases and thread safety.
