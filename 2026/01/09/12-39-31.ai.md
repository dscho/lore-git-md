This is the second patch in Patrick Steinhardt's 17-part series improving ref consistency checks across Git's ref backends. The patch focuses on refactoring the files backend's fsck verification code.

The change moves the fsck verification function array from being passed down through the call stack to being declared as a static global constant. This simplifies the code by eliminating an unnecessary parameter that was always the same set of functions (`files_fsck_refs_name` and `files_fsck_refs_content`). The modification affects `refs/files-backend.c`, removing the parameter from `files_fsck_refs_dir()` and making the function signature more straightforward.

This is a preparatory refactoring that makes the code more maintainable by reducing indirection, while keeping the same functionality. It's part of the larger effort to unify and improve ref verification across different backend implementations. The change is mechanical and low-risk, touching only internal implementation details without affecting user-visible behavior.
