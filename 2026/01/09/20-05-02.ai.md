This is a platform compatibility patch in the Windows symlink support series, specifically teaching Git's dirent implementation about symlinks on Windows. The patch moves symlink detection logic into a shared helper function and adds proper `DT_LNK` handling in the Windows dirent implementation.

The key changes are:
1. Moves the `S_IFLNK` detection from `mingw_lstat()` to `file_attr_to_st_mode()`, which now takes an additional `tag` parameter to identify symlink reparse points.
2. Updates `file_attr_to_st_mode()` to check for symlinks first (via the reparse point tag) before falling back to directory/file detection.
3. Implements `DT_LNK` detection in the Windows `readdir()` implementation by checking for symlink reparse points in directory entries.

The patch is part of a larger effort to provide comprehensive symlink support on Windows, building on Git for Windows work. It's been signed off by both Karsten Blees (the original author) and Johannes Schindelin (Git for Windows maintainer), indicating technical approval. The changes are focused and mechanical, touching only Windows-specific compatibility code in `compat/mingw.c`, `compat/win32.h`, and `compat/win32/dirent.c`.

This appears to be a well-contained refactoring that centralizes symlink detection logic while maintaining the same behavior. The patch follows the series' pattern of incrementally improving Windows symlink support while keeping the changes minimal and focused.
