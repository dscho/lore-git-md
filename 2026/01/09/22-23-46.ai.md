This is the second patch in Samo Pogačnik's 2/2 series addressing shallow repository issues, specifically focusing on relative-depth fetching (`--deepen`). The patch implements a new `get_shallows_depth()` function to properly handle cases where deepening fetches go past merged branches, preventing unreachable shallow commits from being left behind.

The key technical changes include:
- Modifying `get_shallow_commits()` to optionally track minimum depth of existing shallow commits when passed a `shallows` array and `deepen_relative` pointer
- Adding `get_shallows_depth()` which uses the modified `get_shallow_commits()` to calculate relative depths
- Removing the now-redundant `get_reachable_list()` function from upload-pack.c
- Adding a test case that verifies correct behavior when fetching beyond merged branches

The patch demonstrates careful attention to Patrick Steinhardt's prior review feedback, with:
- Clear commit message including ASCII graph examples showing both the problem and solution
- Proper test coverage validating the fix
- Clean removal of debug output and unused code
- Logical sharing between `get_shallows_depth()` and `get_shallow_commits()`

The changes are well-contained to shallow.c and upload-pack.c, with test coverage in t5500-fetch-pack.sh. The implementation appears technically sound, building on the memory leak fix from patch 1/2 while addressing a real-world edge case in shallow repository handling.
