This is a performance optimization patch in a series preparing for Windows symlink support. The change improves `strbuf_readlink()` to avoid making redundant system calls when reading symlink targets.

The patch modifies the function to allocate and pass a buffer that is one byte larger than the requested size hint (typically from `lstat()`). This prevents an edge case where a symlink target exactly matching the hint size would require a second `readlink()` call to confirm the buffer wasn't too small. The change is minimal - just three lines altered in `strbuf.c` - but eliminates unnecessary system calls in this specific scenario.

This is part of a larger effort (with Johannes Schindelin) to improve symlink handling on Windows, where the team has already addressed config timing issues and PATH_MAX limitations in earlier patches. The implementation is straightforward and unlikely to be controversial, with both authors having signed off. The change maintains the function's safety properties while making it slightly more efficient in common cases.
