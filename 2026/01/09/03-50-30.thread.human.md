Here's a human-readable summary of the thread so far:

Simon Cheng has proposed adding a new flag to `git clean` that would allow it to remove ignored nested Git repositories. Currently, `git clean -dxf` skips these repositories, which can be inconvenient for workflows like Arch Linux's AUR package builds where temporary nested repositories are created in ignored paths (specifically in `./src/NAME` directories during `makepkg` runs).

The proposal is motivated by a concrete real-world use case where the current behavior makes post-build cleanup more cumbersome than necessary. While the idea seems straightforward at first glance, there are important considerations around edge cases - particularly the risk of accidentally removing nested repositories that should be preserved. The thread is currently at the discussion stage, with no implementation yet proposed. The change would primarily affect `builtin/clean.c` and would likely require corresponding documentation updates.
