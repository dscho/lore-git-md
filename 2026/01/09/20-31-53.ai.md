This is a feature patch adding a `--keys` flag to `git repo info` as part of a series to improve programmatic access to repository metadata. The patch follows up on Junio Hamano's original suggestion and builds on previous work to standardize format handling across `git repo` subcommands.

The new `--keys` option lists available metadata keys without showing values, addressing the current need to either read documentation or use `--all` to discover keys. The implementation includes strict validation to prevent invalid combinations with `--all` or specific key requests, and supports both newline-delimited and NUL-terminated output formats. 

Key technical details include:
- New `print_keys()` function handling format-specific output
- Error paths for invalid option combinations (`--keys` vs `--all`/specific keys)
- Comprehensive test coverage including format combinations and error cases
- Documentation synopses updated to include the new option
- Test style standardized to use `>expect` convention

The patch represents the final implementation after three iterations, with all review feedback addressed. It completes the series by providing the last piece needed for consistent machine-readable repository metadata access while reducing test maintenance burden through unified format handling.
