This is a discussion about the implementation details of the `git status` branch tracking enhancement series, specifically around how to handle advice flags for push and pull tracking comparisons.

Ben Knoble responds to Harald Nordgren's explanation of using an enum with bitmasking to control advice display in the branch comparison output. Ben points out that Git's convention is to use integer constants rather than enums for bitmask flags, since combining flags with OR operations produces values outside the enum's defined range. He suggests this would be a more idiomatic approach for the current implementation.

The exchange reveals that Harald's design keeps the advice logic inside `format_branch_comparison()` to maintain consistency with the original code structure, using flags to selectively disable push or pull advice when showing the other type of comparison. Ben isn't objecting to the functionality but notes there's a more standard way to implement such flags in the Git codebase.

This is a relatively minor implementation detail in the larger series, which has already gone through extensive review and is considered merge-ready. The discussion shows the careful attention to Git's coding conventions even for well-tested features.
