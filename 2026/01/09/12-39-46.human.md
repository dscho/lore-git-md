This is the final patch in Patrick Steinhardt's series refactoring Git's ref backend verification, completing the migration of fsck checks into the refs subsystem. The patch removes the now-redundant `fsck_head_link()` function, which previously performed HEAD ref validation but has been superseded by the new `refs_fsck_symref()` infrastructure introduced earlier in the series.

The commit explains that `fsck_head_link()`'s remaining check - verifying `refs_resolve_ref_unsafe()` doesn't return NULL - is either redundant (covered by other checks) or unlikely to trigger in practice (like a missing HEAD ref). The change simplifies the code by inlining the remaining ref resolution while maintaining all necessary validation through the new backend-agnostic checks.

This completes the series' goal of centralizing ref verification in the refs subsystem, with both files and reftable backends now performing identical checks. The patch follows the established pattern of the series, removing legacy code after migrating its functionality to the shared infrastructure. With this change, all ref verification logic has been moved out of `builtin/fsck.c` and into the refs backends.
