This is patch 13/17 in Patrick Steinhardt's series refactoring Git's ref backends (files and reftable) for better consistency checks. The patch fixes a bug in the reftable backend's verification logic where it was incorrectly checking all worktree refs rather than just those for the target worktree.

The key changes are:
1. The `reftable_be_fsck()` function now properly restricts verification to the specified worktree's refs using the `backend_for_worktree()` helper introduced in patch 12.
2. It adds proper error handling when the worktree's reftable stack is broken.
3. New tests verify the behavior with both valid and invalid worktree ref stores.

The fix ensures `git refs verify` will only check the intended worktree's refs rather than potentially checking them multiple times or missing broken stacks. This aligns the reftable backend's behavior with the files backend and the expected contract of the ref verification API.

The patch maintains the series' focus on ref backend verification while addressing a specific inconsistency in the reftable implementation. Test coverage is thorough, exercising both successful verification and error cases for worktree ref stores.
