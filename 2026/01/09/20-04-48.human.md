This is a platform compatibility patch in the final stages of a major Windows symlink support series. Johannes Schindelin (Dscho) responds to Johannes Sixt's observation that the `readlink()` implementation's commit message contains an obsolete reference to failing with `ENOSYS` when symlinks are disabled. 

The patch implements POSIX-like `readlink()` functionality on Windows by reading NTFS reparse points, building on earlier infrastructure in the series. Dscho explains that the `ENOSYS` behavior was intentionally removed in Git for Windows v2.19.2, as the ability to read symlinks should not depend on whether creation is enabled (`core.symlinks`). While he can't locate the original discussion, the rationale was that symlinks might exist even when creation is disabled, so Git should still handle them properly.

This is a minor documentation correction for an otherwise complete and reviewed patch. The series as a whole represents a significant improvement to Windows symlink support, with all technical issues resolved and maintainer approval for integration. The exchange shows the careful attention to detail in finalizing this long-running effort.
