This is a platform compatibility patch in the ongoing Windows symlink support series. It modifies `mingw_chdir()` to properly resolve symlinks when changing directories on Windows, matching POSIX behavior. The change is necessary because Git's `real_path()` function relies on this symlink-resolving property of `chdir()`.

The patch adds symlink resolution by using Windows API calls (`CreateFileW` and `GetFinalPathNameByHandleW`) when symlinks are enabled, while maintaining the existing behavior when they're not. The implementation handles error cases properly by translating Windows error codes to POSIX equivalents. A caveat in the commit message notes the MAX_PATH limitation on Windows, which may cause issues with symlinks and long paths.

This appears to be a well-considered change from experienced Windows contributors (Karsten Blees and Johannes Schindelin), building on their extensive work to bring comprehensive symlink support to Windows. The patch is part of a mature series (now at v5) that has been thoroughly reviewed and is ready for integration.
