This is part of the ongoing `the_repository` removal effort, specifically the third patch in a 10-part series by René Scharfe. The patch converts one of the 41 call sites identified in the series to use the new repository-aware `repo_parse_tree_indirect()` function instead of the legacy `parse_tree_indirect()` that implicitly relies on the global `the_repository`.

The change is straightforward - replacing one function call with its repository-aware counterpart while passing along the repository pointer (`s->r`) that was already available in the context. This follows the established pattern for these conversions: first introduce the new API variants (done in patch 02/10), then systematically update callers. The commit message notes this builds on prior work from December 2024 that removed other explicit `the_repository` uses from `add-interactive.c`.

As with René's typical contributions, this is a mechanical but carefully executed change with a clear commit message linking it to both the immediate series and related prior work. The patch touches only `add-interactive.c`, modifying a single line in the `run_revert()` function where tree parsing occurs during interactive add/revert operations. No behavior changes are expected - this is purely an internal refactoring to eliminate implicit global state.
