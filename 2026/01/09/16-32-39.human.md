This is a brief discussion about coding style for bitmask flags in Git, specifically related to Harald Nordgren's ongoing work to enhance `git status` with push tracking branch information.

Patrick Steinhardt clarifies a point about flag handling in response to Ben Knoble's comment on Harald's patch. Ben had noted that Git typically uses integer constants rather than enums for bitmask operations, since bitwise OR operations produce values outside the enum's defined range. Patrick confirms this observation but adds that while flags are declared as enums, the parameter type accepting the bitmask should be `unsigned`.

The exchange is part of the final refinements to Harald's long-running patch series (now at v17) that adds push branch tracking to `git status`. This particular thread focuses on a minor but important implementation detail - how to properly represent and handle the flags that control advice display in the branch comparison output. The discussion doesn't introduce new functionality but helps ensure the implementation aligns with Git's established patterns.
