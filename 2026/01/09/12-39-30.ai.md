This is the first patch in Patrick Steinhardt's 17-part series improving ref consistency checks across Git's ref backends. It's a refactoring of the files backend's root ref iteration logic.

The patch simplifies how Git iterates through root refs in the files backend by removing an unnecessary indirection through the loose ref cache. Currently, the code retrieves the root directory path via `refs->loose->root->name` (which is always empty) before passing it to `files_ref_path()`. This creates both confusion and a potential segfault since the loose ref cache may not be initialized when this code runs.

The change makes the code more straightforward by directly passing an empty string to `files_ref_path()`, which is the correct way to get the root refs directory. This eliminates the need to access the loose ref cache entirely, fixing both the potential crash and the confusing indirection. The patch also cleans up some related string buffer handling that was made redundant by this change.

This is a typical Patrick Steinhardt patch - focused, well-explained, and addressing both immediate technical debt and potential future issues. It touches `refs/files-backend.c` and serves as groundwork for the larger ref verification improvements that follow in the series.
