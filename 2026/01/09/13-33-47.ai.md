This is a follow-up discussion about a whitespace checking patch that introduces a new "tab-between-non-ws" check for documentation files. The patch has gone through several iterations and is now technically complete, with all test improvements from Johannes Sixt incorporated.

The core functionality detects when tabs appear between non-whitespace characters in documentation (particularly .adoc files) where a space was likely intended, while preserving legitimate tab usage for indentation. The implementation tracks both character position and visual column position to determine when a tab would visually appear as a single space.

While the technical implementation is sound (with modifications to ws.c, new test coverage in t4124, and .gitattributes configuration), Johannes Sixt raises philosophical concerns about false positives in tables where tabs are deliberately used for column alignment. Adrian Ratiu, the patch author, notes this was requested by Junio Hamano and leaves the decision about usefulness to him, while offering to potentially improve the heuristic to better detect table formatting patterns.

The patch appears well-crafted with thorough test coverage, but its practical utility remains under discussion. The conversation has shifted from implementation details to whether the check's scope should be adjusted to avoid catching legitimate table formatting cases. This represents the final open question before potential merging.
