Platform compatibility patch fixing Windows symlink resolution in `getcwd()`. This is the first of five preparatory patches for improved Windows symlink support, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees.

The patch modifies `mingw_getcwd()` to properly resolve symbolic links by using `GetFinalPathNameByHandleW()` directly, rather than only as a fallback when `GetLongPathNameW()` fails. This fixes a bug where `git rev-parse --is-inside-work-tree` would fail when the current directory path contained symlinks. The change is safe now that Windows Vista+ API can be used unconditionally, since Git no longer supports Windows XP.

The implementation is clean and focused - it restructures the function to try the symlink-resolving API first, falling back to simpler path handling only when necessary. The diff shows a net reduction of 11 lines while improving functionality. This patch has already been through review in the v1 discussion and the approach is well-validated.
