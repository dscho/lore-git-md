This is a platform compatibility patch in the ongoing Windows symlink support series. It modifies `mingw_chdir()` to resolve symlinks when changing directories, matching POSIX behavior. The change is necessary for Git's `real_path()` function to work correctly on Windows when symlinks are enabled.

The patch adds symlink resolution by using Windows API calls (`CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS` and `GetFinalPathNameByHandleW`) when `has_symlinks` is true. It maintains proper error handling by translating Windows error codes to POSIX equivalents via `err_win_to_posix()`. The implementation notes the Windows MAX_PATH limitation which may cause issues with long paths and symlinks.

This is patch 12/18 in v2 of the series, with sign-offs from both Karsten Blees and Johannes Schindelin (Dscho), indicating it has gone through review. The change is part of the broader effort to bring comprehensive symlink support to Windows, building on Git for Windows' symlink implementation.
