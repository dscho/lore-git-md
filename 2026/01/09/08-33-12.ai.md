This is part 4 of Patrick Steinhardt's 10-patch series refactoring packfile storage to support pluggable ODB backends. The patch focuses on cleaning up the `unuse_one_window()` function in packfile.c, which handles memory management for packfile windows.

The key change is replacing the misleading `current` parameter (a `struct packed_git*` that was never NULL in practice) with a direct `struct object_database*` parameter. The function now consistently scans all packfiles in the ODB rather than having special-case logic for a "current" packfile that was vestigial from older code. 

The commit message provides historical context tracing how this function evolved from its 2017 introduction through subsequent changes that made the NULL check obsolete. The change is mechanical but improves clarity by removing dead code paths and making the function's behavior more straightforward. 

This continues the series' broader goal of moving packfile management responsibilities to the ODB layer while maintaining identical runtime behavior. The patch touches core packfile operations but doesn't introduce new functionality - it's a cleanup that removes historical artifacts while preparing for the larger architectural changes coming in later patches.
