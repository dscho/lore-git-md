Platform compatibility patch implementing Windows symlink creation. This is part of a larger series (now at v5) to bring comprehensive symbolic link support to Git on Windows, building on Git for Windows' symlink implementation. The current patch focuses specifically on file symlinks (directory symlinks will come in a follow-up).

Karsten Blees and Johannes Schindelin (Dscho) have signed off on this implementation, which provides the basic `symlink()` function for creating file symlinks in the MinGW compatibility layer. The function fails with `ENOSYS` if symlinks are disabled or unsupported (e.g. on Windows XP). The implementation handles path conversion between UTF-8 and Windows' wide character format, normalizes path separators, and translates Windows error codes to POSIX equivalents.

This is one of the final pieces in a long-running effort to properly support symlinks on Windows, with all technical issues now resolved according to the thread summary. The patch series is maintainer-approved and ready for integration, representing a significant step forward in Windows compatibility.
