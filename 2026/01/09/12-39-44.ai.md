This is part of Patrick Steinhardt's ongoing ref backend refactoring series, specifically moving fsck validation checks into shared infrastructure. Patch 15/17 migrates the zero-OID ref check from `fsck_head_link()` to the new `refs_fsck_ref()` function used by both files and reftable backends.

The change makes the zero-OID check consistent across backends and properly integrates it with fsck's reporting system (adding a new `badRefOid` message ID). The patch removes error handling from `fsck_head_link()` since its caller ignores the return value anyway, and updates test expectations to match the new fsck message format. This is a straightforward mechanical change that continues the series' goal of unifying ref verification between backends.

Key technical details:
- Adds `FSCK_MSG_BAD_REF_OID` to `fsck.h`
- Moves zero-OID detection from `fsck_head_link()` to `refs_fsck_ref()`
- Updates tests in t1450 to expect the new structured error message
- Touches `builtin/fsck.c`, `refs.c`, and related headers
- Part of the larger ref backend verification unification effort
- Follows the pattern established in earlier patches of the series
