This is patch 9/17 in Patrick Steinhardt's series refactoring Git's ref backend verification. The patch extracts generic symref validation checks from the files backend into a shared `refs_fsck_symref()` function that can be used by all backends (including the upcoming reftable backend).

The new function in `refs.c` performs three key checks that apply universally to symref targets: (1) skips root refs (like HEAD), (2) validates the target refname format, and (3) ensures the target points to something under `refs/` or `worktrees/`. The patch also improves error reporting by avoiding redundant messages when the target refname is invalid.

The files backend implementation is simplified to use this shared function while retaining its own handling of symlink-specific whitespace and newline checks. The patch introduces some `UNUSED` parameters that will be utilized in later commits, suggesting this is part of a planned sequence of changes to the verification infrastructure.

This continues the series' pattern of reducing backend-specific duplication while maintaining thorough validation. The changes appear focused and well-contained, touching only the expected files (`refs.c`, `refs.h`, `refs/files-backend.c`) with no test modifications needed since the behavior remains equivalent.
