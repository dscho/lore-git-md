This is a refactoring patch that prepares for showing push remote tracking branch comparisons in `git status`. It's the first of a 2-patch series by Harald Nordgren that has undergone extensive review (18 iterations) and is now ready for merging.

The patch extracts the branch comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` function. This modularization will allow the upcoming second patch to reuse this logic for push tracking comparisons while maintaining all existing behavior. Key changes include:

- Separates message formatting from advice generation
- Preserves the exact control flow of the original, including the quick mode (AHEAD_BEHIND_QUICK) handling
- Converts some parameters to `bool` for clarity (per Phillip Wood's review)
- Renames the `sti` parameter to `up_to_date` for better readability
- Maintains all existing edge case handling (gone upstream, diverged branches)

The refactoring has been thoroughly vetted through the review process, with Junio C Hamano, Phillip Wood, Ben Knoble, and Patrick Steinhardt all contributing feedback that has been incorporated. The patch now correctly preserves the original behavior where both the `!sti` and `!ours && !theirs` checks are needed in their original sequence to maintain test-passing behavior.

This is a clean preparatory change that enables the push tracking feature while improving code organization. The second patch will build on this to show comparisons with push remotes when they differ from the upstream.
