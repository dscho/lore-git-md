HTTP authentication bugfix for remote-curl when handling large requests with probe_rpc(). This patch addresses a specific issue where filtered clones (`--filter=blob:none`) would fail when the initial authentication succeeds for commit history but subsequent blob requests fail with 401 errors due to missing auth headers in probe_rpc() calls.

The change is minimal (just 2 lines adding `http_append_auth_header()` to probe_rpc() in remote-curl.c) but solves a real pain point in the HTTP transport layer. The problem was particularly visible with git-credential-msal and Bearer token flows, though the fix isn't limited to that authentication method. Lucas De Marchi has tested and confirmed the fix works (Tested-by).

Patrick Steinhardt's review notes the change matches existing auth handling patterns in post_rpc() and suggests adding a test case based on t5563-simple-http-auth. The patch explicitly leaves HTTP_REAUTH cases for future work, as the immediate issue was about missing headers rather than token expiration. This is a focused, well-contained fix for a demonstrated authentication failure in filtered clone operations.
