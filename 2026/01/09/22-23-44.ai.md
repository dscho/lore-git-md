This is a cover letter for a 2-patch series addressing issues with shallow repository handling, particularly around relative-depth fetching (`--deepen`). The series comes from Samo Pogačnik and represents version 2 of the work.

The first patch fixes a memory leak in `get_shallow_commits()` by properly freeing an `object_array` allocation in shallow.c. The second patch implements correct relative-depth fetching by introducing a new `get_shallows_depth()` function that unifies the handling of absolute and relative depth calculations. This eliminates some redundant code by removing `get_reachable_list()`.

The cover letter provides detailed commit graph examples showing the problem scenario where relative-depth fetches could leave unreachable shallow commits, and how the patch fixes this. It also notes that the memory leak fix in patch 1 is validated by the test case in patch 2 failing leak-checking CI runs without it.

The series has been through review from Patrick Steinhardt, who confirmed the technical correctness but requested several documentation and test hygiene improvements. Samo has incorporated this feedback in v2, including adding clearer commit message explanations and test case cleanup. The technical changes remain focused on shallow.c and upload-pack.c, with tests in t5500-fetch-pack.sh.

This appears to be a well-motivated series addressing a real edge case in shallow repository handling. The author has been responsive to review feedback and the patches show steady progress toward finalization. The changes are technically sound and the test coverage helps validate the fixes. The series looks ready for final review with the remaining documentation polish.
