This is part of a major platform compatibility effort to implement comprehensive Windows symbolic link support (patch 2/18 in the series). The patch focuses on making `mingw_stat()` properly resolve symlinks by using `GetFileInformationByHandle()` after opening the file, rather than treating it like `lstat()`. 

The change is well-motivated - currently `mingw_stat()` behaves almost identically to `mingw_lstat()`, which is incorrect POSIX behavior since `stat()` should follow symlinks. The implementation looks solid, using minimal permissions when opening the file and properly cleaning up the handle. 

Karsten Blees and Johannes Schindelin have both signed off, indicating this has gone through proper review. The patch is part of a mature series (now at v5) that has addressed all technical concerns and is ready for integration. This particular change helps align Windows behavior with POSIX expectations for symlink handling.
