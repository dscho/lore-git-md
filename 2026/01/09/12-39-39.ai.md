This is part 10 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend verification. The series is systematically improving consistency checks across both the files and reftable backends.

This patch introduces a new empty function `refs_fsck_ref()` in `refs.c` that will eventually contain generic validation logic for direct (non-symref) references. The function follows the same pattern as the recently added `refs_fsck_symref()` from patch 9, taking similar parameters (ref store, fsck options, report struct, refname, and OID) but currently just returns 0. The files backend is updated to call this new function when processing each reference.

The change is purely preparatory - the actual validation logic will come in subsequent patches. This continues the series' pattern of first establishing the architectural hooks before implementing the functionality. The patch touches the same key files as previous entries (`refs.c`, `refs.h`, and `refs/files-backend.c`) and maintains the focus on reducing backend-specific code while centralizing verification logic.

As with earlier patches in the series, this is a well-structured incremental change that moves toward the goal of unified ref verification while keeping each step small and reviewable. The commit message clearly states the transitional nature of the change and its role in the larger effort.
