Windows symlink support patch (4/5): Removing PATH_MAX limitation for symlink targets

This is the fourth patch in a 5-part series preparing for better symlink support on Windows, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees. The series has already addressed mingw compatibility issues and config parsing timing.

The current patch focuses on `strbuf_readlink()`, which previously limited symlink targets to 2*PATH_MAX (typically 520 bytes on Windows). The change replaces this with a hardcoded 32,767 byte limit, matching Windows' actual maximum path length support while maintaining safety. The rationale explains that symlink targets can legitimately exceed PATH_MAX due to containing unnormalized paths (like repeated `a/../` segments), particularly on Windows where the practical limit is much higher than the legacy PATH_MAX of 260.

The patch is minimal - just a one-line change to the buffer size in strbuf.c. It builds on earlier discussion where Patrick Steinhardt raised concerns about unbounded growth, leading to Junio Hamano's suggestion of this fixed upper bound approach. The solution cleanly handles cross-platform needs while specifically addressing Windows' requirements.

With all reviewers' concerns addressed in v2 and the change being straightforward, this patch appears ready for integration as part of the overall symlink support effort. The series as a whole shows careful attention to both technical correctness and maintainability across platforms.
