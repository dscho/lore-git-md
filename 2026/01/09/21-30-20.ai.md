This is part 9/10 of René Scharfe's ongoing series to remove implicit `the_repository` dependencies, specifically targeting tree parsing functions. The patch converts the remaining compatibility wrappers (`parse_tree_gently()`, `parse_tree()`, and `parse_tree_indirect()`) into macros that still use `the_repository`, but now require explicit `USE_THE_REPOSITORY_VARIABLE` definition. This pushes the responsibility for handling the global repository variable to the callers rather than the tree subsystem itself.

The changes are mechanical and consistent with the series' approach: first introduce repository-aware variants (done in earlier patches), then systematically convert callers, and finally remove the old wrappers. This patch removes the function implementations from `tree.c` and replaces their declarations in `tree.h` with macro versions that maintain backward compatibility while encouraging migration to the new repository-aware API.

The patch continues the established pattern seen in previous parts of the series, with clean removal of 18 lines and addition of 3 lines (the macro definitions). It builds on the foundation laid by earlier patches that introduced `repo_parse_tree*()` variants and converted several call sites. No behavior changes are introduced - this is purely an API refactoring step in the multi-year effort to eliminate `the_repository` global variable usage across Git's codebase.
