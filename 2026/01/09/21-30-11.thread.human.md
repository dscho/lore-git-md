René Scharfe continues his systematic work to remove implicit `the_repository` dependencies from Git's codebase, this time focusing on the bloom filter subsystem. The series, which began by introducing repository-aware variants of tree parsing functions, now converts a call site in `bloom.c` from the global `parse_tree()` to the new `repo_parse_tree()`, passing through the available repository pointer.

This latest patch follows the established pattern of the series: mechanical, low-risk conversions that simply plumb repository context through to core functions. The change affects how bloom filters handle trees with entries that have the high bit set in their mode bits, though no behavior change is expected. Like previous patches in the series, this one is straightforward since the calling code already had repository context available.

The work builds on René's December 2024 refactoring of `add-interactive.c` and continues his characteristic approach of methodically converting call sites after introducing the new repository-aware APIs. With 40 call sites remaining after this conversion, the series is progressing steadily toward its goal of eliminating this implicit global state from tree parsing. Given René's expertise in this type of refactoring and the careful execution so far, the changes continue to move smoothly toward eventual merging.
