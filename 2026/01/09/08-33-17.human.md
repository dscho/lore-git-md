This is part 9 of Patrick Steinhardt's series refactoring Git's packfile storage to support pluggable object database backends. The patch focuses on `find_pack_entry()`, which previously operated at the repository level but is now made to work with individual packfile stores.

The key change moves the iteration over ODB sources out of `find_pack_entry()` and into its callers, making the function operate on a single packfile store. This better matches the behavior of related functions like `packfile_store_freshen_object()` and `packfile_store_read_object_info()`, which already expect to work with individual stores. The one exception was `has_object_pack()`, which Patrick adapts to handle the source iteration itself.

The patch continues the series' pattern of simplifying internal interfaces while maintaining identical behavior. It's a well-contained change (43 lines modified) that fits cleanly into the larger architectural effort to make packfile storage more modular. With all prior review feedback addressed in v3, this appears ready for inclusion as part of the broader ODB abstraction work.
