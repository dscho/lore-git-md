This is a feature addition to the `git repo` command family, specifically adding `--format=default` support and a new `--keys` flag. The patch series by Lucas Seiki Oshiro builds on prior work to improve programmatic access to repository metadata.

The main changes in v3 extend the format handling to consistently support a `default` format option across both `git repo info` and `git repo structure` subcommands. This allows resetting the output format to the command's default (keyvalue for info, table for structure) after specifying other formats. The implementation adds a `FORMAT_DEFAULT` enum value and updates documentation to reflect the new option.

The second patch introduces the `--keys` flag to `git repo info`, which lists available metadata keys without their values. This implements a suggestion from Junio Hamano to enable programmatic discovery of available keys. The flag supports both default (newline-separated) and NUL-terminated output formats.

Technical changes include updates to `builtin/repo.c` to handle the new options, documentation synopsis updates, and new test cases verifying the behavior. The tests cover format resetting, NUL-terminated output, and proper error handling when combining `--keys` with other options.

The series appears well-structured with thorough test coverage. It follows through on prior discussion points and maintains consistency with existing command behavior. The changes are focused and clearly motivated by the goal of improving machine-readability and discoverability of repository metadata.
