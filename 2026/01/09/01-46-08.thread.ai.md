Thread summary:

Documentation patch updating the Git FAQ to recommend stash import/export for syncing working trees across machines, following Git 2.51's new stash import/export functionality. The patch rewrites the FAQ section to prioritize this new mechanism over direct filesystem syncing with rsync, explaining the three-step process of creating/exporting stashes (including untracked files with --include-untracked), transferring them via Git push/fetch, and importing/applying them on the destination machine. Maintainer Junio C Hamano has reviewed the text and raised a terminology concern about describing the mechanism as "secure" when "robust" would be more accurate, suggesting this wording may need adjustment in a future revision. While still mentioning rsync as an alternative, the revised text clearly positions it as a secondary option with more caveats, maintaining but reframing the existing warnings about rsync's data integrity risks as fallback advice rather than primary recommendation. The discussion remains focused on documentation wording, with both brian m. carlson and Junio agreeing on the core technical recommendation while fine-tuning its presentation. The open question is whether to modify the "secure" descriptor in response to Junio's feedback.
