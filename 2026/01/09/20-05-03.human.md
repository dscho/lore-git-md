This is a platform compatibility patch (part of a larger Windows symlink support series) that fixes how Git for Windows reports symlink sizes in `mingw_lstat()`. The patch ensures Windows symlinks report their target path length in `st_size`, matching POSIX behavior, rather than using MAX_PATH as a shortcut.

The change addresses a real interoperability issue where different Git implementations (Windows vs Cygwin/WSL) would disagree about whether symlinks had changed, causing unnecessary index updates. The fix involves reading the reparse point data to get the actual target path length, which adds some overhead but provides correct behavior.

This is patch 6/18 in the v2 series, which has already been through several iterations and received sign-offs from key Windows contributors (Johannes Schindelin and Karsten Blees). The implementation looks solid, introducing a new `read_reparse_point()` helper function to properly handle the Windows-specific reparse point data structures while maintaining the existing error handling patterns.

The patch is part of a mature effort to bring comprehensive symlink support to Windows that's been in development since 2015, with all major technical issues now resolved. This particular change helps ensure consistent behavior across different Windows Git implementations.
