This is patch 16/17 in Patrick Steinhardt's series refactoring Git's ref backend verification. The series aims to unify validation checks between the files and reftable backends by moving them into shared infrastructure.

This patch moves the check for invalid HEAD ref targets (where HEAD points to something other than a branch) from `fsck_head_link()` into the new `refs_fsck_symref()` function. This ensures the check applies consistently across both ref backends. The change:

1. Introduces a new `FSCK_MSG_BAD_HEAD_TARGET` error type
2. Updates the fsck documentation to document this error case
3. Adjusts test expectations to match the new structured error format
4. Simplifies `fsck_head_link()` by removing the now-redundant check

The patch follows the series' pattern of centralizing verification logic while maintaining identical behavior - it just reports errors through the new shared infrastructure. Test changes show the same validation is happening, just with more structured output. This continues the architectural cleanup that makes the ref backends more consistent.
