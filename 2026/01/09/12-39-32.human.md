This is the third patch in Patrick Steinhardt's 17-part series improving ref consistency checks across Git's ref backends. The patch simplifies the files backend's reference verification by removing the redundant `refs_check_dir` parameter, which was always hardcoded to "refs" in practice.

The change eliminates an unnecessary parameter from `files_fsck_refs_dir()` and its callers, making the code more straightforward. Since the function always checks the complete refs hierarchy under "refs/", there's no need to pass this directory as a parameter. The patch follows logically from the previous refactoring work in the series, continuing to clean up the verification infrastructure before introducing shared validation logic in later patches.

The modification is small but meaningful - it removes a potential source of confusion by making the function's scope explicit rather than parameterized. This is part of the series' broader goal of creating cleaner foundations for the upcoming verification improvements that will span both files and reftable backends.
