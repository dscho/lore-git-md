This is the second patch in a 5-part series preparing for Windows symlink support, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees. The patch focuses on config parsing during repository initialization.

The change ensures all `core.*` config settings are parsed early in `git init`, before template copying occurs. This is particularly important for Windows where `core.symlinks` defaults to false - the setting needs to be known before handling template files that might contain symlinks. The patch makes `git_default_core_config()` non-static and calls it directly during init rather than the more limited `platform_core_config`.

The implementation touches three files with a net 2-line addition, exposing the core config handler in environment.h and switching the init codepath to use it. This is a straightforward change that addresses a real issue (Git for Windows #3414) while maintaining cross-platform compatibility. The patch is part of a well-reviewed series that has already incorporated feedback and appears ready for integration.
