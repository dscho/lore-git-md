This is the fourth patch in a 5-part series preparing for improved Windows symlink support, focusing on path length handling in `strbuf_readlink()`. The change replaces the platform-dependent `2*PATH_MAX` limit with a fixed 32,767-character buffer size, matching Windows' actual maximum path length capability while maintaining cross-platform compatibility.

The patch addresses a specific limitation where symlink targets (which can contain unnormalized paths like repeated `a/../` segments) frequently exceed traditional `PATH_MAX` limits, especially on Windows where the practical limit is much higher than the legacy 260-character `PATH_MAX`. The new constant `STRBUF_MAXLINK` is set to 32,767 characters, aligning with Windows' maximum path length while avoiding platform-specific code paths.

This change follows discussion in earlier iterations where Patrick Steinhardt raised concerns about unbounded growth and Junio Hamano suggested this cross-platform solution. The implementation is minimal - just a one-line constant change in `strbuf.c` - but has significant implications for Windows users working with deep directory structures or complex symlinks. The patch carries sign-offs from both Johannes Schindelin (Git for Windows maintainer) and Karsten Blees (original patch author), indicating consensus on the Windows-specific aspects.

As part of the larger symlink support effort, this change enables more robust handling of long symlink targets while maintaining the safety guarantees of the `strbuf` interface. The series has completed review with all technical concerns addressed, and this patch represents the final refinement of the path length handling approach.
