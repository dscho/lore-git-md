This is a platform compatibility patch that changes the default behavior of symlink support on Windows. It's part of the larger Windows symlink support series (now at v5) that has been extensively reviewed and is ready for integration.

The patch modifies the default setting of `core.symlinks` to false on Windows, requiring users to enable it explicitly via configuration. This change accounts for Windows' different symlink behavior (separate types for files/directories) and the privilege requirements for symlink creation on most Windows setups. The patch includes a special case for the test suite, allowing symlink testing when running under MSYS2 with the `winsymlinks:nativestrict` environment variable.

Key technical details:
- Modifies `compat/mingw.c` to set `has_symlinks = 0` by default
- Preserves symlink capability for test suite when running under MSYS2 with specific environment variable
- Signed off by both Karsten Blees and Johannes Schindelen (Dscho), indicating consensus from Windows platform experts

This is a well-justified change that aligns with Windows' security model while maintaining testing flexibility. The patch is straightforward and fits cleanly into the larger symlink support effort that has already received extensive review.
