HTTP authentication bugfix for remote-curl's probe_rpc() function, specifically affecting Bearer token flows in filtered clones. This is a follow-up to the initial patch that added auth headers to probe_rpc() calls, addressing Patrick Steinhardt's request for a test case.

Aaron Plattner reports that while the fix works, creating a test case revealed an interesting nuance: the issue doesn't reproduce with Basic auth because curl handles those credentials automatically. The problem specifically manifests with Bearer tokens, where git must explicitly add the auth header. The proposed test would create a large repository (2000 branches) to trigger the large_request path and use a dummy Bearer token credential helper.

The thread reveals deeper considerations about HTTP_REAUTH handling and whether to use CURLOPT_XOAUTH2_BEARER, though the current approach keeps the fix minimal and focused. Aaron seeks input from Rahul Rameshbabu (more familiar with credential handling) before preparing a v2 with the test case. The patch remains well-contained and clearly addresses a real-world authentication pain point in filtered clones.
