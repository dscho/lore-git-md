This is a bugfix patch addressing a memory leak in the shallow repository handling code. The patch fixes an oversight in `get_shallow_commits()` where a local `object_array` called 'stack' was not being freed before the function, causing memory leaks. The leak manifests in CI test runs (`linux-leaks` and `linux-reftable-leaks`) when testing the companion patch in this series that implements relative-depth fetching.

The fix is straightforward - adding a single `object_array_clear(&stack)` call before returning. The commit message notes this corrects the original omission while also observing that the test case from the follow-up patch would fail leak checking without this correction. This shows good test coverage validating the fix.

This is part of a 2-patch series (v2) where the second patch implements relative-depth fetching functionality. The memory leak fix here is a prerequisite for that feature to pass CI checks. The patch has already been reviewed by Patrick Steinhardt, who confirmed the technical correctness while requesting some documentation improvements in the commit message, which the author has incorporated in this v2 iteration.

The change is minimal and focused - just the one line addition in `shallow.c` to properly clean up allocated memory. Given the clear motivation, straightforward implementation, and test coverage through the companion patch, this appears ready for inclusion.
