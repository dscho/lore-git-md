Platform compatibility patch in the Windows symlink support series. This is patch 17/18 in v2 of the series, addressing a specific edge case in `mingw_stat()` when dealing with directories that have restricted permissions.

The patch modifies Windows-specific stat emulation to better match POSIX behavior when encountering permission-denied errors. When `CreateFile()` fails with `ERROR_ACCESS_DENIED`, it now falls back to `mingw_lstat()` to retrieve basic information about the path - but only if the path isn't a symlink (since resolving symlinks would still require file handle access). This fixes a real-world issue where Git couldn't create directories when parent directories had restrictive permissions.

The change is narrowly scoped to `compat/mingw.c` and Johannes Schindelin (the Git for Windows maintainer) has signed off on it. The patch includes a clear explanation of both the problem and solution, with a reference to the GitHub issue it resolves. This appears to be a well-justified refinement of Windows compatibility behavior that maintains the security properties of the existing code while improving usability in permission-restricted scenarios.
