This is part 15 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend verification. The patch moves the check for invalid (all-zero) object IDs from `fsck_head_link()` into the shared `refs_fsck_ref()` infrastructure that both the files and reftable backends use.

The change makes the zero-OID check consistent across both backends and properly integrates it with fsck's reporting system (adding a new `badRefOid` message ID). The patch also simplifies `fsck_head_link()` by removing its return value since callers weren't checking it anyway - this function will be removed entirely in a later patch.

Test updates verify the new behavior matches expectations, with invalid HEAD references now being reported through the standard fsck message format rather than direct error messages. This continues the series' work of unifying verification behavior between the files and reftable backends.
