Refactoring patch in Patrick Steinhardt's series improving ref backend verification. This seventh installment extends consistency checks to root refs (like HEAD) in the files backend, which were previously skipped. The change adds proper validation for these special refs while maintaining the same error reporting standards used elsewhere.

The patch introduces a new callback function `files_fsck_root_ref` that handles root ref verification, with careful attention to worktree cases. It plugs into the existing fsck infrastructure while adding new test cases that verify both main repository and worktree scenarios. The implementation follows the series' pattern of reducing indirection - here by eliminating a special case that bypassed root ref validation.

This continues the systematic approach seen in earlier patches, with clear test coverage demonstrating the new checks catch invalid root refs (like those with "refs/../" paths). The changes are focused and mechanical, staying within the refs/files-backend.c scope while building toward the series' larger goal of unified verification across backends.
