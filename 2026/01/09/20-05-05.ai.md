This is the first patch in a 5-part series preparing for Windows symlink support, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees. The patch fixes a bug where `git rev-parse --is-inside-work-tree` would fail when the current directory path contained symbolic links on Windows.

The root cause was that Git's Windows-specific `mingw_getcwd()` implementation wasn't resolving symlinks as POSIX `getcwd()` is expected to do. The patch simplifies the function by directly using `GetFinalPathNameByHandleW()` (which resolves symlinks) rather than first trying `GetLongPathNameW()`. This change is safe now that Git no longer supports Windows XP, which lacked the symlink-resolving API.

The implementation opens a handle to the current directory and uses it to get the final resolved path, falling back to the unresolved path only if that fails. This matches the behavior expected by Git's higher-level code that assumes `getcwd()` resolves symlinks. The change is relatively straightforward, touching only `compat/mingw.c` with a net reduction of 4 lines.

This is a well-motivated fix for a concrete Windows compatibility issue, coming from the Git for Windows maintainer with clear sign-off. It's part of a larger effort to improve symlink handling that has already gone through review and reached consensus on the technical approach.
