This is a platform compatibility patch in the ongoing Windows symlink support series. It refactors the retry logic used in several Windows-specific functions (`mingw_unlink()`, `mingw_rmdir()`, and file renaming) into a common helper function `retry_ask_yes_no()`.

The patch consolidates the previously duplicated retry logic that handles cases where file operations fail due to temporary locks (e.g., when another process has the file open). The new helper:
1. Implements consistent retry behavior with increasing delays (0, 1, 10, 20, 40ms)
2. Preserves `errno` when falling back to user interaction
3. Handles the "ask user to retry" flow consistently
4. Simplifies the calling code by removing duplicate retry loops

Key changes include moving the retry logic out of `mingw_unlink()` and `mingw_rmdir()` into the new helper, while maintaining all existing functionality. The patch also cleans up related functions like `ask_yes_no_if_possible()` to work better with the new helper.

This is part of the larger effort to improve Windows symlink support, with Karsten Blees and Johannes Schindelen (Dscho) both signing off. The change follows the established pattern of the series by focusing on code quality and consistency while implementing platform-specific behavior. The patch appears well-contained and builds on prior work in the thread.
