This is the second patch in Samo Pogačnik's series addressing shallow repository issues, specifically focusing on relative-depth fetching (`--deepen`). The patch introduces a new `get_shallows_depth()` function to properly handle cases where deepening a shallow clone beyond a merged branch could leave unreachable shallow commits.

The key changes unify absolute and relative deepening by modifying `get_shallow_commits()` to optionally calculate relative depths when provided with a shallows array. The patch removes the now-redundant `get_reachable_list()` function and adds a test case that demonstrates the fix for the problematic scenario where relative-depth fetches could create unreachable shallow commits.

The implementation shows careful consideration of edge cases, with the commit message including clear ASCII graph examples showing both the problem case and the corrected behavior. The changes touch `shallow.c`, `shallow.h`, `upload-pack.c`, and add a new case to `t/t5500-fetch-pack.sh` to validate the fix.

This appears to be a well-constructed solution to a subtle edge case in shallow repository handling, with thorough test coverage and clear documentation of both the problem and solution.
