This is the second patch in a 5-part series preparing for Windows symlink support, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees. The patch focuses on config parsing during repository initialization.

The change ensures all `core.*` config settings are parsed early in `git init`, before template copying occurs. This is particularly important for Windows where `core.symlinks` defaults to false - the setting needs to be known before handling template files that might contain symlinks. The patch makes `git_default_core_config()` non-static and calls it directly during init rather than the platform-specific `platform_core_config`.

The implementation touches three files with minimal changes: exporting the config function in environment.c, adding its declaration to environment.h, and modifying the call in setup.c. This is a straightforward change that addresses a real issue (#3414 in Git for Windows) while maintaining clean cross-platform behavior. The patch has already been reviewed and approved as part of the finalized v2 series.
