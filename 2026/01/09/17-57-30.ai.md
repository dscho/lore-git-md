This is a bugfix for HTTP authentication in remote-curl, specifically addressing an issue where probe_rpc() requests fail due to missing auth headers during filtered clones (`--filter=blob:none`). The problem manifests when initial requests succeed but subsequent blob fetches fail with 401 errors.

The patch adds `http_append_auth_header()` to probe_rpc() in remote-curl.c, mirroring the auth handling already present in post_rpc(). While demonstrated with git-credential-msal and Bearer tokens, the fix applies broadly to all HTTP auth methods. Patrick Steinhardt has reviewed the change, noting it matches existing patterns while suggesting a test case could be added based on t5563-simple-http-auth.

The thread reveals interesting details about HTTP_REAUTH handling - the current behavior depends on http_auth.multistage being set, which isn't appropriate for Bearer token flows. The patch deliberately focuses on the immediate credential reuse issue while leaving broader HTTP_REAUTH cases for future work. Aaron Plattner provides detailed trace logs showing the authentication failure sequence, clearly demonstrating the real-world impact on filtered clone operations.
