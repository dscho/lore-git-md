This is a feature request proposing a new flag for `git clean` to remove ignored nested Git repositories. Currently, `git clean -dxf` skips such repositories, which can be problematic for workflows like AUR package builds where nested repos are created in ignored paths.

The author, Simon Cheng, provides a concrete use case from Arch Linux's AUR packaging system where `makepkg` creates source repositories in `./src/NAME` directories. The current behavior makes cleanup after builds more complicated than necessary.

The patch appears well-motivated with a clear real-world use case, though it's currently just a request rather than an implementation. The change would affect the `builtin/clean.c` implementation and potentially require updates to the documentation. The proposal seems straightforward but would need careful consideration of edge cases (like accidentally removing nested repos that should be preserved) and whether this should be a new flag or modify existing behavior.
