This is the sixth patch in Patrick Steinhardt's v9 series introducing a new `git history` command, which aims to provide a more opinionated and user-friendly way to rewrite Git commit history compared to `git rebase`. The patch adds the core command infrastructure while marking it as experimental.

The new `git history` command is positioned as an alternative to interactive rebase for common history editing operations like reordering, splitting, dropping, or squashing commits. Key differences from rebase include working in bare repositories, not executing hooks (for now), and automatically updating descendant branches by default - addressing a pain point for users of stacked branch workflows.

The implementation here is minimal scaffolding: it adds the command skeleton with basic argument parsing and empty test cases. The documentation outlines the command's goals and limitations, notably that it doesn't yet support merge commits or operations that could cause conflicts. The command is explicitly marked as subject to future behavior changes.

This patch builds on previous work in the series that refactored Git's replay machinery into a library and added supporting infrastructure. As part of a larger effort, it shows Patrick's continued focus on making Git's history manipulation more flexible and user-friendly while maintaining careful, incremental development. The series has already addressed previous feedback around naming, error handling, and scope.
