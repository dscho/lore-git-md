This is a refactoring patch that extracts the core revision replay logic from `builtin/replay.c` into a standalone `replay_revisions()` function, as part of Patrick Steinhardt's ongoing `git-history` command series (v9). The change prepares the code for future library use while maintaining identical behavior.

The patch introduces a new `replay_result` structure (renamed from `replay_ref_updates` in v9) to track reference updates and merge results. The extracted function handles the main workflow: preparing revisions, applying them via the merge machinery, and recording any reference updates. Error handling follows the newly documented convention (128 for errors, 1 for conflicts, 0 for success).

Key technical details include:
- New `replay_revisions_options` struct consolidates command-line options
- `replay_result` tracks reference updates and merge conflicts
- The extracted logic maintains all existing functionality while being more reusable
- Error codes now match the series' documented convention
- The change is preparatory for moving this code into libgit.a in a follow-up patch

This is a mechanical refactoring with no intended behavior change, part of the larger effort to build history editing capabilities on top of Git's replay infrastructure. The patch follows the series' established patterns and addresses previous feedback about naming and error handling.
