This is a platform compatibility patch addressing macOS iconv issues, specifically the second in a two-part series. René Scharfe provides review feedback on Torsten Bögershausen's patch that enables a workaround (`ICONV_RESTART_RESET`) for macOS 14/15's problematic system iconv implementation.

The patch adds build system logic to detect when the workaround is needed (Darwin 24+ systems without MacPorts/Homebrew iconv installed). René suggests several improvements: fixing stylistic issues in the commit message, questioning whether MacPorts detection is too optimistic (currently just checks for the directory, not the actual library), and proposing more precise variable naming that matches the C macro (`ICONV_RESTART_RESET` rather than `NEEDS_GOOD_LIBICONV`).

The review is constructive and focused on making the detection more robust while maintaining the clear intent of the original patch. This continues the thread's technical discussion about properly handling macOS's problematic iconv implementation while avoiding false positives when good alternatives are present.
