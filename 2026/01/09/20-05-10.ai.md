Platform compatibility patch implementing Windows symlink support. This is patch 13/18 in the v2 series that introduces comprehensive POSIX-like symlink operations on Windows via the MinGW compatibility layer. The patch implements `readlink()` by leveraging NTFS reparse points through the previously introduced `read_reparse_point()` function, handling both symlinks and directory junctions.

The implementation converts the path to Windows format, reads the reparse point data into a temporary buffer, then copies up to the requested number of bytes to the output buffer (including proper handling of UTF-8 sequences and buffer size limitations). The change removes the previous stub implementation from `mingw-posix.h` and adds the real implementation to `mingw.c`.

Key technical details include:
- Uses `xutftowcs_path()` for path conversion
- Relies on `read_reparse_point()` for the core functionality
- Handles the POSIX `readlink()` API quirks (partial buffer filling is not an error)
- Maintains proper string termination even when truncating
- Works with both symlinks and directory junctions

The patch is signed off by both Karsten Blees and Johannes Schindelin (Dscho), indicating Windows platform expertise review. This is part of a larger effort to mature Windows symlink support in Git that has been ongoing since 2015, with this particular series representing the final push to upstream integration after extensive review and refinement.
