Platform compatibility patch improving Windows symlink support, specifically focusing on robust renaming operations. This is patch 11/18 in a completed v5 series that has already been approved for integration.

The patch replaces MSVCRT's problematic `_wrename()` with direct `MoveFileEx()` calls when handling renames of symlinks on Windows, adding proper error handling and the `MOVEFILE_COPY_ALLOWED` flag. Johannes Schindelin confirms this is battle-tested code despite its complexity, noting the historical evolution of the logic. The change removes fragile CRT behavior where older versions would silently fail when renaming symlinks over existing files.

Key technical details include proper attribute handling during retries, Windows-specific error code translation, and maintaining the existing retry mechanism for access-denied cases. The patch touches `compat/mingw.c`, modifying the `mingw_rename()` function to be more robust when dealing with symlinks. Johannes Sixt reviewed the change and while noting the convoluted logic, accepted it based on its proven reliability in Git for Windows.

This represents the final form of the patch after all technical discussion and typo fixes in earlier iterations. The series as a major step forward in Windows-POSIX compatibility for symlink operations.
