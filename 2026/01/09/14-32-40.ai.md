# Documentation patch refining stash-based workflow advice

This is a documentation patch that follows up on brian m. carlson's earlier update to the Git FAQ about using stash import/export for syncing working trees across machines. Junio C Hamano provides a brief but pointed review, questioning the use of "secure" to describe the stash import/export mechanism when "robust" already covers the safety aspects. The thread context shows the original patch introduced this new recommended workflow in Git 2.51, positioning stash import/export as superior to direct filesystem syncing with rsync. While Junio's reply doesn't propose specific changes to the text, his query about terminology suggests the "secure" claim might need clarification or removal in a future revision. The discussion remains focused on documentation wording rather than technical implementation, with both participants clearly agreeing on the core recommendation while fine-tuning how it's presented.
