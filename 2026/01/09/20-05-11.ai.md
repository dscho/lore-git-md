Platform compatibility patch implementing Windows symlink creation for files (not directories) in the MinGW layer. This is part of a larger series (now at v5) to bring comprehensive symlink support to Windows.

The patch removes the stub `symlink()` implementation from `compat/mingw-posix.h` and adds a real implementation in `compat/mingw.c` that creates file symlinks via `CreateSymbolicLinkW()`. The implementation handles path conversion between UTF-16 and UTF-8, normalizes path separators, and returns proper POSIX error codes. It fails with `ENOSYS` if symlinks are disabled or unsupported (e.g. on Windows XP).

This builds on previous work in the series that added symlink detection and handling. The implementation is intentionally limited to file symlinks in this patch, with directory symlink support coming in subsequent commits. The patch has been signed off by both Karsten Blees and Johannes Schindelin (Dscho), indicating Windows platform expertise approval.

Key technical details:
- Uses `xutftowcs_path()` for path conversion
- Normalizes forward slashes to backslashes in target paths
- Sets `SYMBOLIC_LINK_FLAG_FILE` (0) for file symlinks
- Translates Windows errors to POSIX via `err_win_to_posix()`
- Returns `ENOSYS` if symlinks are disabled (controlled by `has_symlinks`)

The patch is part of a mature series that has gone through multiple iterations and is now ready for integration, having addressed all technical feedback. It represents a significant step in completing Windows symlink support in Git's MinGW compatibility layer.
