This is part 3 of Patrick Steinhardt's 10-patch series refactoring Git's packfile storage to support pluggable object database backends. The series is in its third iteration and has received thorough review from Justin Tobler and Toon Claes.

The current patch focuses on the "kept pack cache" - a mechanism that tracks packfiles marked as kept (either via on-disk ".keep" files or in-memory flags). The key change moves this cache from being repository-global to being owned by individual packfile stores, which is part of the larger effort to make object storage backend-aware.

The patch renames several constants (`ON_DISK_KEEP_PACKS` -> `KEPT_PACK_ON_DISK`, `IN_CORE_KEEP_PACKS` -> `KEPT_PACK_IN_CORE`) and the main accessor function (`kept_pack_cache()` -> `packfile_store_get_kept_pack_cache()`). It updates all callers across multiple commands (pack-objects, revision walking, reachability checking) to use the new interface.

The changeset is mechanical but wide-ranging, touching core packfile operations. The patch appears well-structured with clear commit message explaining the change and its motivation. Review feedback has been incorporated and the series is now in good shape for inclusion. This is a foundational change enabling the larger ODB backend work.
