This is part of a major platform compatibility effort to implement comprehensive Windows symbolic link support (patch 2/18 in the series). The patch specifically focuses on making `mingw_stat()` properly resolve symlinks by using `GetFileInformationByHandle()` after opening the file, rather than treating it like `mingw_lstat()` which examines the link itself.

The change is technically sound - it properly distinguishes between stat (which should follow symlinks) and lstat (which should not) by actually opening the target file when possible. The implementation uses Windows' native file handle operations and converts paths appropriately. Johannes Schindelin has signed off, indicating this meets Git for Windows' requirements.
