Platform compatibility patch addressing a Windows-specific index corruption edge case in symlink size recording. This is the final patch in a 29-patch series (v5) that comprehensively implements Windows symlink support, now adding special handling for a bug where symbolic links' target path sizes were incorrectly recorded as 4096 (MAX_PATH) in Git for Windows v2.27.0.

The patch modifies `read-cache.c` to detect and handle this specific corruption pattern by forcing a re-check of any symlink recorded with size 4096, treating it as modified. This avoids the confusing state where `git status` would show such symlinks as modified while `git diff` would not, requiring an explicit `git add` to resolve. The change is Windows-specific (guarded by `GIT_WINDOWS_NATIVE`) and maintains backward compatibility while fixing the edge case.

Johannes Schindelin (Dscho) signs off on this final refinement to the symlink series, which has already received sign-offs from Karsten Blees and Johannes Sixt. The series as a whole has been maintainer-approved for integration after addressing all technical points, with this patch representing the last loose end in the comprehensive Windows symlink support effort that builds on Git for Windows' maturing implementation since 2015.
