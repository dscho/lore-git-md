Patrick Steinhardt introduces a 17-patch series improving ref consistency checks across Git's ref backends, with focus on the "files" and "reftable" implementations. The series has three primary objectives: (1) enhancing files backend validation, (2) creating shared verification infrastructure between backends, and (3) migrating some fsck checks into the ref verification system.

The first patch refactors the files backend's root ref iteration logic, simplifying how Git iterates through root refs by removing an unnecessary indirection through the loose ref cache. It eliminates the current path of `refs->loose->root->name` (which is always empty) in favor of directly passing an empty string to `files_ref_path()`. This fixes both a potential segfault (when the loose ref cache isn't initialized) and confusing indirection, while cleaning up related string buffer handling. The change touches `refs/files-backend.c` and serves as groundwork for the larger verification improvements.

Technical changes in subsequent patches will include new root ref validation in the files backend, common validation logic extraction (refs/files-backend.c, refs/reftable-backend.c), and reftable worktree handling fixes. Test coverage expands through t0602 and t0614 modifications. The series introduces shared validation infrastructure in patches 9-14 and migrates fsck checks to ref verification in patches 15-17. Key files affected: refs.c, refs/files-backend.c, refs/reftable-backend.c, builtin/fsck.c, t/t0602-reftable-basics.sh, t/t0614-reftable-fsck.sh. This represents a significant but focused improvement to ref validation that should enhance maintainability while adding missing checks.
