This is part 4 of Patrick Steinhardt's 17-patch series improving ref consistency checks across Git's ref backends. The patch removes an unnecessary indirection in the files backend's fsck implementation by inlining the `files_fsck_refs()` function into its single caller `files_fsck()`. 

The change simplifies the control flow by eliminating a function that merely forwarded all parameters unchanged. It also fixes the error handling - instead of bitwise OR-ing the return values (which could mask errors), it now properly propagates any failure from either the loose refs check (`files_fsck_refs_dir`) or the packed refs check.

This is a straightforward refactoring that maintains identical behavior while making the code more direct and easier to follow. The patch continues the series' pattern of cleaning up the files backend implementation in preparation for introducing shared verification logic between backends in later patches. The change is limited to `refs/files-backend.c` and doesn't affect any user-visible behavior.
