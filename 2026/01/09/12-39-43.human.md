This is patch 14/17 in Patrick Steinhardt's series refactoring Git's ref backend verification, focusing on the reftable backend. The patch wires up generic ref validation checks (introduced in earlier patches) to the reftable backend, ensuring consistent behavior between the files and reftable backends.

The key changes are:
1. The reftable backend now performs the same validation checks for both direct refs (checking object IDs) and symrefs (validating target refnames) that were previously only done in the files backend.
2. It uses a low-level reftable iterator to catch broken refs that higher-level iterators might skip.
3. The patch includes a new test case that invalid symrefs are properly detected and reported.

The implementation carefully handles worktree-specific cases and maintains proper error reporting. This continues the series' pattern of first establishing shared verification infrastructure (patches 9-14) before migrating fsck checks (coming in 15-17). The changes are well-contained to the reftable backend code with corresponding test coverage.
