This is a platform compatibility patch in the final stages of a major Windows symlink support series. The email clarifies historical context around the `readlink()` implementation in Git for Windows, specifically addressing Johannes Sixt's observation that the commit message incorrectly claimed the function would fail with `ENOSYS` when symlinks are disabled.

The key technical point is that the implementation intentionally allows reading symlinks regardless of the `core.symlinks` setting, since symlinks may exist even if Git isn't permitted to create them. Johannes Schindelin traces this back to a 2018 change in Git for Windows v2.19.2 where the `ENOSYS` check was removed, though the commit message wasn't updated to reflect this. The patch is part of a larger effort to upstream comprehensive Windows symlink support that has been maturing in Git for Windows since 2015.

This email represents final cleanup before the series is integrated, with all technical issues now resolved. The discussion shows careful attention to historical accuracy in commit messages and cross-platform behavior consistency, particularly around the interaction between symlink creation and reading capabilities.
