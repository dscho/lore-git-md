This is part of the ongoing `the_repository` removal effort, specifically patch 6/10 in René Scharfe's series converting tree parsing functions to be repository-aware. The patch modifies `pack-bitmap-write.c` to use the new `repo_parse_tree()` function instead of the older `parse_tree()` that implicitly relied on the global `the_repository`.

The change is straightforward - a single line modification that passes the repository pointer already available in the `bitmap_writer` struct. This builds on prior work from March 2025 that removed explicit `the_repository` usage from this file. The patch follows the established pattern of the series: mechanical conversion with no behavior change, just plumbing through the repository context.

As with previous patches in the series, this is a well-executed step in the larger refactoring effort. René Scharfe has been consistently reliable in this type of systematic cleanup work, and the change appears uncontroversial. The patch maintains the existing error handling where failed tree parsing results in a die() call, which is appropriate for this bitmap-writing context.
