Documentation patch revising the Git FAQ's guidance on syncing working trees across machines. This is a follow-up to brian m. carlson's earlier patch that introduced stash import/export functionality in Git 2.51.

Junio C Hamano provides a brief but positive review, noting the patch is "superbly good" overall while questioning the use of "secure" to describe the stash transfer method (he suggests "robust" already covers the safety aspects). The original patch from brian m. carlson rewrote the FAQ section to recommend stash import/export as the primary method for syncing working trees, positioning it as more reliable than the previous rsync-based approach. The new guidance explains the three-step workflow (stash+export, transfer via Git, import+apply) and maintains but demotes the rsync instructions to a fallback option with appropriate warnings.

This appears to be a straightforward documentation improvement that incorporates new Git capabilities while maintaining the FAQ's cautious tone about repository integrity. Junio's minor wording quibble aside, the patch seems ready to proceed.
