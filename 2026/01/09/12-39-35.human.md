Bugfix in Patrick Steinhardt's ongoing ref backend verification series (patch 6/17). This patch addresses error handling issues in symref verification within the files backend.

The current implementation has two problems: it can accidentally swallow previous errors when ignoring specific issues, and it bails out early when encountering an invalid target reference without checking for additional problems. The fix changes the error reporting to consistently use bitwise OR (`|=`) to accumulate errors and removes the early bailout, ensuring all validation checks run regardless of previous failures.

This is a focused change to `refs/files-backend.c` that maintains the same validation logic but makes the error reporting more robust. The patch fits into the larger goal of improving ref verification across both files and reftable backends, with this particular change being a straightforward improvement to error handling that should be uncontroversial.
