[PATCH 0/10] tree: remove implicit `the_repository` dependency

Series by René Scharfe continuing the multi-year `the_repository` removal effort, focusing on tree parsing functions. First patch moved `core.maxTreeDepth` from global to repository-specific settings in `struct repo_settings`. Second patch introduced repository-aware variants of tree parsing functions: `repo_parse_tree_gently()`, `repo_parse_tree()`, and `repo_parse_tree_indirect()`. Third patch converted first call site in `add-interactive.c` to use `repo_parse_tree_indirect()`. New fourth patch converts bloom filter code in `bloom.c` from `parse_tree()` to `repo_parse_tree()`, passing available repository pointer.

Changes so far include:
- Removal of global `max_allowed_tree_depth` variable and config handling
- Addition of repository-specific `max_allowed_tree_depth` field
- New `repo_parse_tree*()` variants in `tree.c`/`tree.h`
- Caller conversions in `add-interactive.c` and `run_revert()`
- Bloom filter conversion in `bloom.c` for tree parsing with high-bit modes
- Preservation of existing API via wrapper functions

Series follows established refactoring approach: add repository-aware variants first, then convert callers systematically. Remaining patches will address 39 more call sites across builtins, diff, merge, and test code. Final patch will provide Coccinelle semantic patch for future conversions. Builds on prior December 2024 work removing `the_repository` from `add-interactive.c`. All changes mechanical with thorough coverage; no behavior changes expected. No open questions or objections raised - given author's expertise in this type of refactoring and careful execution, series continues progressing toward merge.
