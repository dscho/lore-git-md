This is patch 5/7 in Patrick Steinhardt's v9 series introducing the `git history` command, which provides flexible history editing operations. The patch adds infrastructure needed for the upcoming `split` subcommand by extending the working tree status machinery.

The patch is part of the `git history` feature effort, specifically focusing on the supporting infrastructure. It introduces a new function `wt_status_collect_changes_trees()` that diffs two arbitrary trees (rather than comparing the working tree/index) and formats the changes in the same way as working tree status would. This will be used by the `split` subcommand to show changes between tree states during history editing operations.

The implementation reuses the existing diff and status formatting infrastructure while adding a clean interface for tree-to-tree operations. The change is well-contained, adding 33 lines across two files with clear documentation of the new function's purpose. As with the rest of the series, this continues the pattern of careful refactoring to support the new functionality while maintaining code quality.
