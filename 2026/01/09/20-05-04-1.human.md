This is a platform compatibility patch in the Windows symlink support series, specifically focusing on retry logic for file operations. The patch refactors duplicate retry-and-prompt code from `mingw_unlink()` and `mingw_rmdir()` into a new helper function `retry_ask_yes_no()`. 

The change standardizes the retry behavior across file operations on Windows, where processes may temporarily lock files. The new helper handles:
- Automatic retries with increasing delays (0ms, 1ms, 10ms, 20ms, 40ms)
- User prompting when retries are exhausted
- Proper `errno` preservation
- Consistent error handling for file-in-use scenarios

The patch is part of a larger effort to mature Windows symlink support, with Johannes Schindelin and Karsten Blees (a Windows Git expert) both signing off. It follows established patterns for Windows file operation retries and appears well-tested, with the series already approved for integration after multiple iterations. The change is a clear improvement over the previous duplicated code, though it doesn't introduce new functionality - just better organization of existing behavior.
