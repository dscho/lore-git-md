This is part of Patrick Steinhardt's ongoing refactoring of Git's ref backend verification, specifically addressing the files backend. Patch 7/17 in the series extends consistency checks to root refs (like HEAD) which were previously skipped.

The change introduces a new `files_fsck_root_ref()` helper that verifies root refs by:
1. Properly constructing refnames for both main worktree and linked worktrees
2. Checking ref existence via `stat()`
3. Reusing the existing `files_fsck_ref()` logic for validation

The patch adds test coverage for two scenarios: invalid HEAD refs in the main repository and in worktrees. Both tests verify that malformed root refs (containing path traversal like "refs/../HEAD") are properly detected and reported.

This continues the series' pattern of reducing verification gaps between different parts of the ref storage system while maintaining the existing error reporting structure. The changes are focused on `refs/files-backend.c` with corresponding test additions in t0602. The implementation carefully handles worktree cases through the new `files_fsck_root_ref_data` struct that tracks context across callbacks.
