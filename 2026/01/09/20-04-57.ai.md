This is the final version (v2) of a major platform compatibility patch series introducing comprehensive Windows symbolic link support, now ready for integration. The 18-patch series builds on Git for Windows' symlink implementation that has been maturing since 2015, with contributions from Bill Zissimopoulos, Johannes Schindelin, Karsten Blees, and Johannes Sixt.

The series implements POSIX-like symlink operations in the MinGW compatibility layer, covering creation, reading, stat'ing, directory handling, renaming, and edge cases like index corruption. Key technical components include proper `stat()`/`lstat()` implementation using `GetFileInformationByHandle()`, `readlink()` functionality via NTFS reparse points, directory symlink handling in `unlink()`/`chdir()`, symlink-specific error codes, robust rename operations using `MoveFileEx()`, and index compatibility fixes for MAX_PATH edge cases.

All technical and administrative issues from previous iterations have been resolved, including:
- Updated attribution for Karsten Blees with his current email
- Clarified historical behavior around `ELOOP` handling (intentionally removed to support `core.symlinks=false` on Windows 7)
- Fixed a typo in patch 10 ("woutl" -> "would") caught by Ben Knoble
- Documented that `readlink()` intentionally allows reading symlinks regardless of `core.symlinks` setting (a behavior change from Git for Windows v2.19.2)
- Final patch 18 adds Windows-specific condition in `ie_modified()` for MAX_PATH symlink sizes

The implementation touches `compat/mingw*` files and `read-cache.c`, with careful attention to Windows-specific behaviors while maintaining POSIX compatibility where possible. The series represents a major step forward in Windows-POSIX compatibility for symlink operations and concludes the `js/prep-symlink-windows` foundation work. Maintainer Junio Hamano has approved it for integration after all technical points were addressed.
