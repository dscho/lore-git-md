Platform compatibility patch implementing correct symlink size calculation for Windows.

This patch from Bill Zissimopoulos (with sign-off from Johannes Schindelin) fixes how Git for Windows reports symlink sizes in `mingw_lstat()`. The key issue is that POSIX requires `lstat()` to report the actual length of the symlink target path, but Git for Windows had been hardcoding MAX_PATH instead. This caused problems when repositories were accessed by both Git for Windows and other implementations (Cygwin/WSL), as they would disagree about whether symlinks had changed.

The solution introduces a new `read_reparse_point()` helper that properly reads the reparse point data to determine the actual symlink target length. The implementation handles both symbolic links and mount points (junctions), falling back to MAX_PATH for unknown reparse point types. The patch also includes the necessary Windows API definitions for working with reparse points.

This is part of the larger Windows symlink support series that has been through multiple iterations with extensive review from Windows experts like Johannes Schindelin and Karsten Blees. The technical approach here is sound and addresses a real interoperability pain point. The patch follows Git's coding style and includes a thorough commit message documenting both the problem and solution.
