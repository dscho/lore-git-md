Bugfix in the files ref backend's symref verification, part of Patrick Steinhardt's ongoing ref backend refactoring series. This patch (6/17) addresses two error-handling issues in `files_fsck_symref_target()`:

1. Error reporting could incorrectly swallow previous errors when `fsck_report_ref()` was told to ignore specific issues, due to direct assignment rather than bitwise OR of return values.
2. Early bailout when encountering invalid refnames meant subsequent checks (like newline validation) were skipped.

The changes make error handling more consistent by:
- Using `|=` to accumulate errors rather than overwriting them
- Removing the early return for bad refnames
- Standardizing the final return to convert accumulated errors to -1/0

This maintains the series' focus on improving verification infrastructure while preserving behavior - all checks still run, but now properly report all detected issues rather than stopping at the first problem. The patch touches only `refs/files-backend.c` with mechanical changes to error handling patterns.
