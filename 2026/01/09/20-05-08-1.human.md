This is a platform compatibility patch in the ongoing Windows symlink support series. It specifically addresses an issue where older Windows CRT libraries fail to properly rename symlinks over existing files. The patch replaces the problematic `_wrename()` call with a direct `MoveFileEx()` implementation that includes proper error handling and retry logic.

The change is part of a larger effort to bring comprehensive POSIX-like symlink support to Git on Windows, building on years of work in Git for Windows. This particular patch was signed off by both Karsten Blees (the original author) and Johannes Schindelin (Git for Windows maintainer), indicating it has gone through thorough review.

The implementation now uses `MoveFileEx()` with appropriate flags for symlink handling, adds proper error code translation between Windows and POSIX systems, and maintains the existing retry mechanism for cases where files might be temporarily locked. The patch also includes careful handling of file attributes to ensure they're properly restored if the operation fails.

This appears to be a well-considered change that addresses a specific edge case in Windows filesystem operations while maintaining compatibility with Git's cross-platform behavior. As part of the now-complete v5 series, it's ready for integration into mainline Git.
