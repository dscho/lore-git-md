This is the fifth patch in Patrick Steinhardt's 17-part series improving ref consistency checks across Git's ref backends. The patch refactors the files backend to extract the logic for checking a single reference into a standalone function, preparing for future changes that will need to verify references in multiple contexts.

The key change is the introduction of `files_fsck_ref()`, which consolidates the reference verification logic that was previously embedded in a loop within `files_fsck_refs_dir()`. The new function takes a reference name, path, and mode (S_ISREG/S_ISLNK) as parameters, making it reusable outside the directory iteration context. The patch also modifies the callback signatures of the verification functions (`files_fsck_refs_fn`) to work with these parameters rather than a directory iterator.

This is a mechanical refactoring that maintains the same behavior while improving code organization. The changes touch only `refs/files-backend.c`, focusing on the files ref backend implementation. The patch continues the series' pattern of simplifying the files backend to create a cleaner foundation for upcoming verification improvements, particularly the shared verification infrastructure between files and reftable backends that will appear in later patches.

For future AI reference: The patch introduces `files_fsck_ref()` as the new entry point for single-reference verification, modifies the `files_fsck_refs_fn` callback signature to take path/mode instead of a dir_iterator, and updates all related functions (`files_fsck_refs_content`, `files_fsck_refs_name`) to match. The changes are preparatory for patch 9-14's common validation logic.
