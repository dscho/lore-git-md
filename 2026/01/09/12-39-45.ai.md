This is part 16/17 of Patrick Steinhardt's series to refactor Git's ref backend verification, focusing on moving fsck checks into shared infrastructure. The patch migrates the HEAD ref validation from `builtin/fsck.c` to the new `refs_fsck_symref()` function in `refs.c`, making this check consistent across both files and reftable backends.

The change introduces a new `FSCK_MSG_BAD_HEAD_TARGET` error for HEAD refs that don't point to a branch (previously this was a plain error message). The validation now happens in `refs_fsck_symref()` where it can be shared by both backends, continuing the series' pattern of centralizing verification logic. The patch updates test expectations in t0602 and t1450 to match the new structured error format.

This builds on earlier work in the series that established the `refs_fsck_ref()` and `refs_fsck_symref()` infrastructure (patches 10-14). The change is mechanical but important for consistency between backends - the reftable backend will now perform the same HEAD validation as the files backend. One test case in t0602 is adjusted to use a more realistic invalid ref (`refs/heads/../HEAD` instead of `refs/../HEAD`) while maintaining the same verification behavior.
