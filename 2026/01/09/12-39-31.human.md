This is the second patch in Patrick Steinhardt's 17-part series improving ref consistency checks across Git's ref backends. The patch focuses on code organization in the files backend.

The change moves two ref verification functions (`files_fsck_refs_name` and `files_fsck_refs_content`) from being passed as parameters through the call stack to being defined as a static global array. This simplifies the code since these functions never change between calls. The modification touches only `refs/files-backend.c`, removing the parameter from `files_fsck_refs_dir()` and its callers.

This is a straightforward refactoring that improves code clarity by eliminating unnecessary parameter passing. It's part of the larger effort to unify and strengthen ref verification across Git's storage backends. The patch appears clean and well-contained, with no behavioral changes - just moving where the function pointers are stored.
