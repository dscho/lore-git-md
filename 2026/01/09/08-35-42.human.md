Feature implementation in the `git-history` series. This is the final patch (7/7) in Patrick Steinhardt's v9 series introducing the `reword` subcommand for `git-history`. The command provides a faster, in-memory alternative to interactive rebase for rewriting commit messages, with several key differences from `git-rebase`:

The `reword` subcommand operates entirely in-memory (no checkout), works with dirty working trees, and by default updates all local branches containing the commit being reworded. It includes three reference update modes via `--ref-action`: updating all branches (`branches`), just HEAD (`head`), or printing updates for `git-update-ref` (`print`).

The implementation builds on Git's replay subsystem and includes comprehensive tests covering:
- Rewording tips, middle commits, and root commits
- Operation in bare repositories
- Branch handling and merge commits
- Reference update modes
- Editor behavior and status display
- Working tree/index preservation

Notable technical details:
- Uses `wt_status_collect_changes_trees()` to show changes in editor
- Implements custom reference update logic via `replay_revisions()`
- Explicitly avoids hook execution (for now)
- Includes extensive test coverage in `t/t3451-history-reword.sh`

This appears to be a well-considered implementation with thorough testing, though some open questions remain about stacked branch workflows and hook policies. The series has evolved through multiple rounds of review, with this final patch completing the core functionality while leaving room for future extensions.
