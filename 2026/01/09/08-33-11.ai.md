Refactoring patch in Patrick Steinhardt's ODB abstraction series, focusing on packfile store management. This is patch 3/10 in v3 of the series, which moves the kept-pack cache functionality to operate on packfile stores rather than repositories. The change prepares for making packfile stores per-object-source entities.

Key technical changes:
- Renames `kept_pack_cache()` to `packfile_store_get_kept_pack_cache()`
- Updates flag names from `ON_DISK_KEEP_PACKS`/`IN_CORE_KEEP_PACKS` to `KEPT_PACK_ON_DISK`/`KEPT_PACK_IN_CORE`
- Moves cache invalidation and lookup logic to work with `struct packfile_store` instead of `struct repository`
- Updates callers in `pack-objects`, `reachable`, and `revision` to use new API
- The patch is part of a larger effort to make object storage backend pluggable by decoupling packfile management from the repository object database
- Changes are mechanical but touch several core packfile operations
- Follows prior review feedback from Justin Tobler and Toon Claes
- Maintains identical behavior while restructuring internal ownership

The patch continues the architectural work to support pluggable ODB backends, with all open questions from review resolved in this iteration. Changes are focused and well-contained within the packfile subsystem.
