Platform compatibility patch in the Windows symlink support series. This is patch 17/18 in the v2 iteration of a comprehensive effort to improve symlink handling on Windows, now focusing on making `stat()` behave more like POSIX when encountering permission-denied directories.

The patch addresses a specific edge case where Git needs to stat directories that the current user cannot access. On Windows, the current implementation would fail completely when `CreateFile()` is denied permission, but POSIX allows `stat()` to proceed in this scenario. Johannes Schindelin modifies `mingw_stat()` to fall back to `mingw_lstat()` when access is denied, while carefully preserving the failure case for symbolic links (which still require handle creation to resolve).

This change fixes a real-world issue reported in Git for Windows (#2531) where directory creation could fail unnecessarily. The implementation is careful to maintain security boundaries by not allowing the fallback for symlinks. The patch is part of a mature series that has already gone through multiple iterations and received sign-offs from key Windows contributors.
