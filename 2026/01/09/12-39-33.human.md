This is part 4 of Patrick Steinhardt's 17-patch series improving ref consistency checks across Git's ref backends. The series aims to enhance validation in the files backend, create shared verification infrastructure, and migrate fsck checks into ref verification.

This patch removes an unnecessary indirection in the files backend code by inlining the `files_fsck_refs()` function, which was just forwarding all arguments to `files_fsck_refs_dir()`. It also fixes the error handling - instead of bitwise OR'ing return values (which could mask errors), it now properly checks each function's return value separately.

The change is straightforward and improves code clarity without altering functionality. It's part of the preparatory work to simplify the files backend before introducing more substantial verification improvements in later patches. The patch follows the series' pattern of removing indirection and cleaning up the codebase to make the subsequent changes easier to implement and review.
