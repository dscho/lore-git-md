Feature enhancement for `git status` showing push tracking branch status. This is the second patch in a 2-part series that adds push tracking branch comparison to `git status` output when it differs from the upstream branch.

The patch implements the core functionality by:
1. Adding a new `get_remote_push_branch()` helper that resolves the push tracking reference through the full refspec resolution chain
2. Extending `format_tracking_info()` to handle both upstream and push comparisons
3. Showing push comparison only when it differs from upstream status
4. Maintaining existing advice messages while adding push-specific advice when relevant
5. Including comprehensive test coverage (262 lines) for all edge cases

Key technical details:
- Uses `pushremote_for_branch()` for push reference resolution
- Output format matches Git conventions in all states
- Preserves quick mode (AHEAD_BEHIND_QUICK) special case handling
- Maintains header file interface stability
- Implements enum flags for branch modes (PULL/PUSH) with unsigned parameters for bitfields as confirmed by Patrick Steinhardt
- Handles remapped push refspecs and multiple remote scenarios

The implementation has gone through 18 iterations with extensive review from Phillip Wood, Ben Knoble, and Patrick Steinhardt, addressing:
- Reference resolution approach (keeping current chain rather than `branch_get_push()`)
- Advice display logic refinement with boolean flags
- Flag style implementation (enum declarations with unsigned parameters)
- Parameter naming improvements (`sti` -> `up_to_date`)
- Type safety enhancements with bool conversions

The series is now merge-ready with all technical requirements satisfied and no outstanding objections. The extensive test coverage verifies behavior across various scenarios including diverged branches, remapped refspecs, and multiple remote configurations.
