This is a refactoring patch from Patrick Steinhardt, part of the v9 series introducing the new `git-history` command. The patch extracts the core revision logic from `builtin/replay.c` into a new `replay_revisions()` function, preparing it for library use in the upcoming history editing features.

The changes:
- Introduces `replay_revisions_options` and `replay_result` structs to encapsulate parameters and results
- Moves the commit replaying logic into a standalone function that can be called independently
- Maintains all existing functionality while making the code more modular
- Improves error handling with explicit return codes (128 for errors, 1 for conflicts, 0 for success)

This is foundational work for the history editing capabilities being built on top of Git's replay machinery. The patch is well-structured and clearly motivated as preparation for upcoming functionality. It follows the project's pattern of careful refactoring before adding new features.
