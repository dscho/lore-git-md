This is part 9 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend verification. The patch extracts generic symref validation checks from the files backend into a shared `refs_fsck_symref()` function that can be used by all backends (including the upcoming reftable backend).

The new function centralizes checks that apply to all symref targets regardless of backend: verifying the target refname format and ensuring it points to a valid ref (either under refs/ or worktrees/). The patch also improves error reporting by avoiding redundant messages when a target has multiple validation issues.

The changes touch `refs.c` (adding the new function), `refs.h` (exposing the API), and `refs/files-backend.c` (adapting to use the shared function). The implementation maintains all existing behavior while reducing code duplication - a typical Steinhardt-style refactoring that moves toward more modular backend infrastructure. The unused parameters hint at future extensions coming in later patches.
