Patrick Steinhardt continues his refactoring work to unify validation between Git's files and reftable ref backends with patch 5/17 in the series. The thread began with foundational cleanups to the files backend, removing indirection and redundant functions. This latest patch takes the next logical progression by extracting the per-ref validation logic from `files_fsck_refs_dir()` into a new standalone `files_fsck_ref()` function.

The changes are primarily organizational - modifying callback signatures to take path/mode directly and moving file type checking into the new function - while carefully preserving all existing error handling behavior. This prepares the codebase for sharing validation between backends, a key goal of the series. Shejialuo has been providing thorough reviews of prior versions, with some remaining discussion about HEAD detection centralization. The work demonstrates Patrick's characteristic approach of methodical, incremental refactoring that builds toward architectural improvements while maintaining stability.
