Performance optimization in the Windows symlink support series. This is the third patch in a 5-part series preparing for better symlink handling on Windows, co-authored by Karsten Blees and Johannes Schindelin (Git for Windows maintainer).

The patch optimizes `strbuf_readlink()` to avoid making redundant `readlink()` system call when the hint size exactly matches the link target length. Currently, when given a hint matching the target size (e.g. from `lstat()`), the function would call `readlink()` twice - once to find the size was exact, then again to confirm it wasn't truncated. The change adds +1 to the buffer size hint, allowing a single call to both detect and read the full link when the size is known.

This is a small but meaningful optimization that touches only 3 lines in `strbuf.c`, with the core change being the `hint + 1` buffer sizing. The patch is straightforward and well-contained, building on the previous work in the series to improve symlink handling performance. With sign-offs from both authors and no outstanding review comments, it appears ready for inclusion.
