This is a 2-patch series from Samo Pogačnik addressing issues with shallow repository handling, particularly around relative-depth fetching (`--deepen`). The series has been through one round of review from Patrick Steinhardt, who confirmed the technical approach but requested some commit message and test improvements.

The first patch fixes a memory leak in `get_shallow_commits()` by properly freeing an `object_array` allocation. The second patch implements correct relative-depth fetching by introducing a new `get_shallows_depth()` function that calculates appropriate depths for existing shallow commits when doing a `--deepen` fetch. This replaces the previous `get_reachable_list()` approach which had issues with merged branches.

The cover letter includes a detailed example showing the problem scenario where a `--deepen` fetch could leave unreachable shallow commits, and how the new approach correctly handles this case. The changes touch `shallow.c`, `upload-pack.c`, and add tests in `t5500-fetch-pack.sh`.

Patrick's review noted the core algorithm is sound but requested: better commit messages (including ASCII graphs to illustrate the problem), removal of debug output, shell loop fixes in tests, and potential code deduplication between the new `get_shallows_depth()` and existing `get_shallow_commits()` functions. Samo has acknowledged all feedback and indicates plans to address these points in the v2 submission.

This appears to be a well-motivated change addressing a real edge case in shallow repository handling, with careful attention to both the technical solution and documentation. The interaction between author and reviewer shows productive collaboration toward a clean final result.
