This is part of Patrick Steinhardt's ongoing ref backend refactoring series, specifically patch 14/17 which introduces generic reference validation checks for the reftable backend. The patch wires up the shared verification infrastructure (introduced in earlier patches) to perform consistency checks on reftable references.

The key changes are:

1. The reftable backend now performs the same validation checks as the files backend, including:
   - Direct reference validation via `refs_fsck_ref()`
   - Symbolic reference validation via `refs_fsck_symref()`
   - Worktree-specific reference handling using the new `backend_for_worktree()` helper

2. Implementation uses low-level reftable iteration to catch broken refs that higher-level iterators might skip, with proper error handling for:
   - Broken worktree reftable stacks
   - Iterator creation failures
   - Record reading errors

3. Added test case verifies detection of invalid symref targets, matching the files backend's behavior.

The patch maintains the series' focus on cross-backend consistency while handling reftable-specific details like hash algorithm detection. It's a technical but well-contained change that moves the reftable backend closer to feature parity with the files backend for verification purposes. The implementation looks thorough, with appropriate error handling and test coverage.
