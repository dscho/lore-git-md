This is a platform compatibility patch that changes the default behavior of symlink support on Windows. It's part of a larger series (v5, 18 patches) introducing comprehensive Windows symlink support, now in its final refinements.

The patch changes `core.symlinks` to default to false on Windows, requiring users to explicitly enable it via config. The rationale is that Windows symlinks work differently than Unix (requiring admin privileges in most cases) and have different types for files vs directories. The change ensures Git won't attempt symlink operations unless specifically configured to do so.

A notable aspect is the test suite handling - since tests ignore system config, the patch adds special logic to detect when running under MSYS2 with native symlinks enabled (via an environment variable), allowing the test suite to exercise symlink functionality when available. The implementation touches just the Windows-specific `compat/mingw.c` file, adding the new default behavior while maintaining backward compatibility for testing scenarios.

The patch has been signed off by both Karsten Blees and Johannes Schindelin (Dscho), indicating consensus from key Windows platform experts. It represents a sensible default given Windows' symlink constraints while preserving the ability to opt-in for users who need the functionality.
