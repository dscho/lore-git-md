This is a cover letter for a 5-patch series preparing for Windows symlink support, co-authored by Johannes Schindelin (Git for Windows maintainer) and Karsten Blees. The series builds on previous work to enable proper symlink handling on Windows, addressing several technical prerequisites across mingw compatibility, config parsing, strbuf utilities, and path handling.

The key changes in v2 include fixing Karsten's email address and replacing the previous approach of unlimited symlink target lengths with a more conservative 32,767 character limit (matching Windows' practical path length maximum). The series touches 6 files with a net reduction of 20 lines.

Patch 1 fixes `mingw_getcwd()` to properly resolve symlinks via Windows APIs. Patch 2 ensures core.* config settings are parsed early during `git init`. Patches 3-5 focus on strbuf and path handling improvements, with the most significant change being the adoption of a fixed 32kB buffer size for symlink targets (replacing the previous PATH_MAX-based limit) as suggested by Junio Hamano in the thread discussion.

The series represents the final preparatory work needed before upstreaming Git for Windows' symlink support, with all technical concerns now resolved through review feedback. The changes are well-contained and focused, with clear commit messages explaining each improvement's purpose. The v2 iteration incorporates all requested changes from reviewers, making this ready for integration.
