This is part 4 of Patrick Steinhardt's series to refactor Git's packfile storage in preparation for pluggable object database backends. The patch cleans up a misleading code path in `unuse_one_window()`, which handles memory management for packfile windows.

The function previously took a `packed_git` parameter that was never NULL in practice) and had confusing logic around repository access. The patch simplifies this by having it take the object database directly instead. The change is mechanical but improves clarity - the old code was misleading about its NULL handling despite that case being impossible since 2019.

This continues the series' pattern of moving packfile-related functionality from repository-global contexts to more localized storage. The change affects core packfile operations but maintains identical behavior, just with clearer ownership semantics. Reviewers Justin Tobler and Toon Claes have already signed off on earlier versions of this refactoring.
