This is part 5 of Patrick Steinhardt's 17-patch series improving ref consistency checks across Git's ref backends. The series aims to enhance validation in the files backend, create shared verification infrastructure between backends, and migrate fsck checks into ref verification.

This patch refactors the files backend's reference checking logic by extracting the per-ref validation into a standalone `files_fsck_ref()` function. Previously this logic was embedded directly in the directory iteration loop, making it harder to reuse. The change simplifies the control flow in `files_fsck_refs_dir()` while maintaining identical behavior, and prepares for upcoming patches that will need to verify references in additional contexts.

The patch touches only `refs/files-backend.c`, modifying how reference validation is structured without changing what is validated. It's a clean refactoring that makes the code more modular while keeping all existing functionality, including the same error reporting and file type checks. This continues the series' pattern of preparatory changes that simplify the files backend implementation before introducing new verification features.
