This is part 4 of René Scharfe's ongoing series to remove implicit `the_repository` dependencies, focusing this time on the bloom filter code. The patch converts one call site in `bloom.c` from the global `parse_tree()` to the new repository-aware `repo_parse_tree()` variant, passing through the available `struct repository *r` parameter.

The change is straightforward - a single line modification in `bloom.c` that replaces the global tree parsing function with its repository-specific counterpart. This follows the established pattern seen in earlier patches of the series: first introducing the repository-aware API variants, then systematically converting callers to use them while maintaining the same behavior.

As with previous patches in this series, the change is mechanical and well-contained, coming from a contributor with deep experience in this type of refactoring. The patch maintains the existing functionality while progressing the larger goal of removing global state from Git's codebase. No behavior changes or new edge cases are introduced - this is purely an internal API modernization.
