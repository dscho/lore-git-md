This is a platform compatibility patch in the ongoing Windows symlink support series, specifically addressing permission requirements for symlink creation on Windows 10 and later.

The patch modifies Git's MinGW compatibility layer to take advantage of a Windows 10 feature (Build 14972+) that allows creating symbolic links without elevated administrator privileges when Developer Mode is enabled. Johannes Schindelin adds a new `adjust_symlink_flags()` function that checks the Windows version and conditionally sets the `SYMBOLIC_LINK_FLAG_ALLOW_UNPRIVILEGED_CREATE` flag (0x02) for both file and directory symlink operations.

The change is backward compatible - older Windows versions that don't support this flag will continue to require elevated permissions. The implementation carefully avoids breaking existing behavior by checking the build number before applying the new flag. This follows the established pattern in the symlink series of gracefully handling different Windows versions while progressively improving functionality.

This is patch 16/18 in v2 of the series, building on the comprehensive Windows symlink support that has been in development across multiple iterations. The thread context shows this work has already received sign-offs from key Windows experts (Karsten Blees, Johannes Sixt) and maintainer approval from Junio Hamano. The patch appears ready for integration, representing one of the final refinements to the Windows symlink implementation.
