This is a feature request for `git clean` to add an option for removing ignored nested repositories. The author, Simon Cheng, notes that currently `git clean -dxf` skips repositories under ignored paths, which complicates cleanup workflows - particularly for AUR package builds where source repos are cloned into ignored directories.

The proposed flag would allow forcibly removing these nested repositories during cleanup. The use case is well-explained with a concrete example from Arch Linux's AUR packaging system, where this would simplify post-build cleanup. The patch appears motivated by a real workflow pain point, though as an initial proposal it lacks implementation details or a proposed flag name.

The change would affect the `git clean` command's behavior regarding nested repositories, potentially touching the `builtin/clean.c` implementation. The request seems reasonable for users who manage nested repositories and need thorough cleanup, though the safety implications of recursively removing repositories would need careful consideration in any implementation.
