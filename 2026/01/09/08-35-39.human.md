This is part 4 of Patrick Steinhardt's v9 series introducing the `git history` command, which provides history editing capabilities inspired by Jujutsu. The patch focuses on exposing the final rewritten commit's object ID through the replay machinery.

The change adds a `final_oid` field to the `replay_result` struct, which will be used by the upcoming `git history` command to support a mode that only modifies the HEAD reference. The commit message clearly explains the limitations of this field - it's most reliable when rewriting a single strand of commits, and may have undefined behavior with more complicated branch topologies.

The implementation is straightforward, storing the last rewritten commit's OID in the result struct. The accompanying documentation in the header file provides clear guidance about when and how this field should be used. This appears to be a well-contained change that enables the planned HEAD-update mode while maintaining the existing replay functionality.

This continues the series' pattern of careful, well-documented additions to the replay infrastructure to support the new history editing features. The change is technically sound and fits cleanly into the larger effort.
