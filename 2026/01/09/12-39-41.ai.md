This is part 12 of Patrick Steinhardt's 17-patch series refactoring Git's ref backends (files and reftable) to improve consistency checks. The patch focuses on the reftable backend implementation.

The change extracts the worktree backend retrieval logic from `backend_for()` into a new helper function `backend_for_worktree()`. This is a preparatory refactoring that will be used in subsequent patches to implement validation logic. The new function handles:
1. Checking for an existing cached backend
2. Initializing a new backend if needed
3. Storing the backend in the worktree_backends strmap

The patch maintains the existing behavior while making the control flow in `backend_for()` clearer by moving the worktree-specific logic into its own function. This aligns with the series' goal of improving the verification infrastructure for ref backends.

Technical details:
- Touches `refs/reftable-backend.c`
- Introduces new function `backend_for_worktree()`
- Preserves all existing error handling and memory management
- Keeps the same strmap-based caching of worktree backends

This is a mechanical refactoring that doesn't change behavior but prepares for upcoming validation work in the series. The change is well-contained and follows Git's coding style.
