This is another patch in René Scharfe's ongoing `the_repository` removal series, specifically converting bloom filter code to use repository-aware tree parsing functions. 

The patch changes a single call site in `bloom.c` from the implicit `parse_tree()` to the new explicit `repo_parse_tree()`, passing through the available repository pointer. This is a straightforward conversion following the pattern established earlier in the series - replacing global API calls with their repository-aware counterparts when a repository context is available.

The change affects the bloom filter subsystem's handling of trees with entries that have high bit set in their mode bits. The modification is mechanical and low-risk, just plumbing the repository pointer through to the tree parsing function. As with previous patches in the series, there's no expected behavior change - this is purely about removing implicit dependency on the global repository state.

This continues the systematic approach seen in earlier patches: first introducing the repository-aware variants of core functions, then converting callers one by one. The bloom filter conversion is simpler than some other cases since it already had the repository context available. The patch follows René's characteristic style - minimal, focused changes with clear commit messages.
