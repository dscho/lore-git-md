This is a bugfix for HTTP authentication in remote-curl, specifically addressing an issue with probe_rpc() requests during filtered clones (`--filter=blob:none`). The problem causes initial authentication to succeed for commit history while subsequent blob requests fail with 401 errors due to missing auth headers in probe_rpc() calls.

Aaron Plattner reports that when using git-credential-msal with Bearer tokens, filtered clones would fail partway through because probe_rpc() wasn't including authentication headers. The patch adds `http_append_auth_header()` to probe_rpc() in remote-curl.c, matching the existing auth handling pattern from post_rpc(). This is a minimal 2-line change that fixes the immediate issue.

Patrick Steinhardt reviewed the change, noting it matches existing auth patterns while suggesting a test case based on t5563-simple-http-auth could be added. The fix has been tested and confirmed working by Lucas De Marchi (Tested-by). The patch explicitly notes that HTTP_REAUTH cases remain for future work, keeping the scope focused on the immediate authentication header issue.

This is a well-contained fix for a real-world pain point in the HTTP transport layer that affects filtered clones with authenticated servers. The change is small but impactful, and the discussion shows careful consideration of edge cases while keeping the solution minimal.
