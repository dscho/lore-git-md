This is a documentation discussion thread about the Git stash import/export functionality for syncing working trees across machines. The patch in question updates the Git FAQ to recommend this new mechanism (introduced in Git 2.51) over direct filesystem syncing with rsync.

The current discussion focuses on a wording choice in the commit message - whether to describe the stash transfer mechanism as "secure and robust" or just "robust". brian m. carlson defends the "secure" descriptor by noting that stash transfer avoids potential security issues present in rsync-based approaches (like executing arbitrary code via hooks/config or accidentally transferring sensitive ignored files). However, they defer to Junio Hamano's judgment on whether to keep or remove the term.

The technical substance appears settled - both parties agree stash import/export is the preferred method, with rsync demoted to a fallback option. The open question is purely about whether the security benefits warrant explicit mention in the documentation. The patch is likely to proceed with either minor wording tweaks or as-is, depending on Junio's final decision.
