This is part 5 of Patrick Steinhardt's 10-patch series refactoring Git's packfile storage to support pluggable object database (ODB) backends. The series moves packfile store ownership from the ODB layer to individual ODB sources, continuing the architectural work to make object lookup source-aware.

This patch specifically moves the packfile store from `struct object_database` to `struct odb_source`, recognizing that each source connected to the database has its own set of packfiles. The change affects packfile operations across multiple commands (fast-import, grep, pack-objects) and core packfile handling code. While the diff is large (11 files modified), most callers don't need adaptation since they use high-level iteration functions like `repo_for_each_pack()`.

Key technical changes include:
- Packfile stores are now initialized per-source rather than per-ODB
- The patch updates packfile operations to iterate through sources when needed
- Core functions like `unuse_one_window()` and `close_one_pack()` now scan all sources
- The series maintains identical behavior while restructuring the ownership model

The changes are mechanical but wide-ranging, touching packfile window management, object lookup, and packfile iteration. This represents an important step toward the larger goal of pluggable ODB backends, though Patrick notes the abstractions remain "leaky" at this stage. The patch builds on two recently merged topics and has incorporated all review feedback from Justin Tobler and Toon Claes.
