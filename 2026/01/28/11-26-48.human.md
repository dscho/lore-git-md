This is a feature patch from Abraham Samuel Adekunle improving the interactive staging interface in `git add -p`. The patch adds context-sensitive '<' and '>' navigation options that appear only when movement between files is possible (hidden for single file, only '<' at first file, both in middle files), while preserving the existing 'q' submission behavior.

The patch is now in its second iteration, having received detailed technical feedback from maintainer Junio C Hamano. While the core navigation concept has approval, implementation details face scrutiny. Key concerns include the `get_file_diff_index()` helper function interface, patch application timing changes, and the need to replace magic numbers with enums. The author has agreed to make the feature optional via configuration and split the changes into more focused patches.

The navigation options only appear after all hunks in the current file are decided, with a new "All hunks decided. What now?" prompt. The implementation maintains linear navigation (no circular behavior) and introduces new `ALLOW_GOTO_PREVIOUS_FILE` and `ALLOW_GOTO_NEXT_FILE` flags to track navigation state.

This represents a quality-of-life improvement for the interactive staging workflow, though the implementation approach may need restructuring based on maintainer feedback. The next version is expected to address the architectural concerns while preserving the approved navigation behavior.
