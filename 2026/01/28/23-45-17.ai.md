This is part 2 of a 4-patch series in the ongoing ODB (object database) abstraction effort, specifically preparing for pluggable transaction handling across different ODB backends. The patch renames transaction-related functions from `object_file_transaction_{begin,commit}` to `odb_transaction_loose_{begin,commit}` to better reflect their role as loose-object-specific implementations. The changes are mechanical - updating function names in `object-file.c`, `object-file.h`, and `odb.c` while preserving all existing behavior. This appears to be a straightforward preparatory step for the subsequent patch that will generalize transaction handling, with clear commit message explaining the rename's purpose. The patch maintains the series' focus on making the ODB layer more modular while keeping the loose objects backend working exactly as before. Reviewers will want to verify the rename doesn't break any external callers, though the limited scope suggests low risk.
