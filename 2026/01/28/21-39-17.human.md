This is part 2/12 of a series refactoring Git's hook subsystem to support parallel execution. The patch introduces a named `struct parallel_child` and a helper function `child_is_working()` to make the parallel process state checks more readable throughout `run-command.c`.

The change is straightforward - it touches several places where the code was checking child process states directly via `pp->children[i].state == GIT_CP_WORKING`. By introducing the named struct and helper function, the code becomes more self-documenting. The patch was suggested by Junio Hamano and follows the pattern of the series - incremental improvements to the parallel execution infrastructure.

This is a mechanical refactoring that doesn't change behavior, just improves code organization. It's part of the larger effort to enable parallel hook execution while maintaining backward compatibility. The series as a whole has already gone through extensive review and is in its final polishing stages.
