Documentation patch clarifying `git worktree prune` behavior and terminology. This is the third iteration of a series that standardizes the language around missing worktrees and the `--expire` option.

The patch makes several documentation improvements:
1. Expands the `prune` subcommand description to explain when to use it (after manual worktree removal) and when to prefer `worktree remove` or `worktree repair` instead
2. Consistently uses "prune" rather than "expire" when describing the action on missing worktrees
3. Clarifies that `--expire` only affects worktrees whose working directory path no longer exists (missing worktrees)

The changes have been reviewed by both Eric Sunshine and Junio C Hamano, with Junio suggesting the expanded subcommand description. The author has squashed previous iterations into a single commit as requested. The changes are mechanical and focused solely on documentation clarity, with no behavior modifications.

This appears ready for merging, representing the culmination of discussion that started with terminology and has now addressed all feedback. The patch touches Documentation/git-worktree.adoc and builtin/worktree.c help text, standardizing language that was previously inconsistent between the two.
