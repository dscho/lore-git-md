This is part 3 of a 4-patch series in the ongoing ODB (object database) abstraction effort, focusing on making transaction handling more flexible for different object storage backends. The patch refactors `struct odb_transaction` to support multiple source types by introducing a base structure with common fields and moving loose-object-specific functionality into a new `struct odb_transaction_loose` that inherits from it. 

Key technical changes include:
- Adding a commit callback function pointer to the base transaction structure, allowing different backends to implement their own commit logic
- Renaming and restructuring transaction-related functions to clearly separate the loose objects backend implementation
- Moving the loose objects transaction implementation details from `object-file.h` to `odb.h` where they better belong with the ODB abstraction
- Converting direct field access to use the new base structure indirection

The changes maintain existing behavior while making the architecture more extensible, with straightforward mechanical transformations that replace direct field access with the new indirection pattern. This appears to be a well-structured incremental step in the larger ODB abstraction work, building on prior patches in the series. Reviewers will want to verify the transaction semantics remain correct, though the direct mapping between old and new access patterns suggests minimal risk.
