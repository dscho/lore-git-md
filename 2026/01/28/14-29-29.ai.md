This is a feature patch adding a `--maximal-only` option to `git rev-list` and related commands, marking commits that are not reachable from any other commit (effectively the "tips" of the commit graph). The patch was previously discussed in Junio's "What's cooking" report and has now reached consensus for merging into the 'next' integration branch.

Derrick Stolee confirms that while there were discussions about potentially using the `git merge-base --independent` algorithm or extending the option to other commands, those can be deferred to future work. The current implementation appears ready to proceed, suggesting it addresses the core use case cleanly without obvious technical objections. This fits into Stolee's broader work on graph-theoretical optimizations in Git's revision walking machinery. The patch looks like a focused, well-vetted addition that should graduate cleanly through the integration branches.
