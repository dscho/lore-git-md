This is a bugfix for git-gui's diff viewer tab alignment on Windows, part of an ongoing thread about inconsistent tab rendering between git-gui and gitk. Maintainer Johannes Sixt now agrees the alignment issues make git-gui diffs effectively unreadable, marking a shift from his earlier hesitation about changing the behavior.

The core issue involves how tabs are displayed in different contexts - regular diffs, combined diffs, and untracked files. While Chris Idema's simple one-line `apply_tab_size 1` solution fixes the immediate problem for regular diffs, Johannes notes it may not handle combined diffs correctly (which need offset 2) and untracked files (which shouldn't offset tabstops at all).

A technical blocker remains: the current patch fails due to an undefined `have_tk85` variable that was eliminated in earlier versions. Johannes indicates this was just illustrative code from an old patch, not part of the actual solution path. The thread shows progress toward consensus that git-gui can diverge from terminal behavior for better readability, but the implementation needs to account for all diff contexts properly.
