This is part 3 of a 4-patch series in the ongoing ODB (object database) abstraction effort, preparing Git's transaction handling to support pluggable backends. The patch refactors `struct odb_transaction` to store a commit callback specific to its object source type, moving from direct function calls to a callback-based approach.

The key change introduces a new `struct odb_transaction_loose` that wraps the base transaction structure, with all loose-object-specific transaction handling now going through this wrapper. The commit operation is now invoked via a callback (`odb_transaction_commit_fn`) stored in the base structure. This maintains existing behavior while making the architecture more flexible for future backend implementations.

The patch touches several files but focuses on `object-file.c` where most transaction handling lives, updating all transaction-related functions to work with the new structure. The changes appear mechanical and well-contained, with clear 1:1 mappings between old and new patterns. This looks like a solid incremental step in the larger ODB abstraction work, continuing the effort to make Git's object storage layer more modular.
