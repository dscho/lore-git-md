This is part 4/12 of a hook subsystem refactoring series introducing a callback mechanism for feeding stdin to hooks. The patch builds on the parallel execution support added in the previous patches, allowing hooks to receive stdin data incrementally via a callback rather than requiring the full input to be buffered or read from a file.

The key addition is a `feed_pipe` callback in `struct run_hooks_opt` that can stream data to a hook's stdin without going through the filesystem. This is particularly useful for large inputs like ref lists during pushes. The patch ensures the new callback is mutually exclusive with the existing `path_to_stdin` file-based approach (enforced via BUG checks).

The implementation passes callback context through the parallel execution infrastructure while maintaining backward compatibility. The documentation in hook.h thoroughly explains the new fields and their usage patterns. This appears to be a well-considered addition to the hook API that addresses real performance concerns around large inputs.

The patch has already gone through multiple iterations (now at v8) with sign-offs from both the original author (Emily Shaffer) and the series maintainer (Adrian Ratiu), suggesting it's reached consensus. The changes are focused and the commit message clearly explains the motivation and technical approach.
