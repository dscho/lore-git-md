Hook subsystem refactoring (part 5/12): This patch updates the post-rewrite hook in sequencer.c to use the new hook API, replacing direct run-command calls. The change simplifies the code by leveraging the standardized hook infrastructure while maintaining identical functionality.

The patch introduces a new `pipe_from_strbuf` callback function that handles stdin piping through the hook API's feed_pipe mechanism. This replaces the manual process management and SIGPIPE handling that was previously required when using run-command directly. The callback writes the commit hash information (passed via a strbuf) to the hook's stdin, with proper error handling for EPIPE cases.

Key technical details:
- Maintains the same input format (oldoid + newoid pairs) as before
- Uses the hook API's built-in SIGPIPE handling
- Preserves the "amend" argument passed to the hook
- Keeps the same stdout-to-stderr redirection behavior
- Still skips silently if no post-rewrite hook is configured

The change is part of a larger series standardizing Git's hook execution, with this patch specifically focusing on the sequencer's post-rewrite hook. The implementation appears straightforward and well-contained, with no obvious behavioral changes from the previous version.
