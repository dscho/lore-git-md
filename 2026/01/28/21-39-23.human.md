Hook subsystem refactoring continues with patch 8/12 in Adrian Ratiu's series, converting the reference-transaction hook to use the new hook API. This follows the pattern established in previous patches, eliminating direct use of `run-command` and manual process management in favor of the standardized API.

The patch removes about 50 lines of custom hook-handling code from `refs.c`, replacing it with a callback-based approach that feeds ref updates one at a time to the hook process. The implementation maintains all existing functionality while simplifying the control flow - no more manual signal handling, pipe management, or process lifecycle tracking. The callback (`transaction_hook_feed_stdin`) handles the same ref update formatting as before, just within the new API's streaming model.

This conversion demonstrates the hook API's flexibility for cases where hooks need to process structured input, following similar migrations of the post-rewrite and pre-push hooks in the series. The patch carries sign-offs from both Emily Shaffer (who co-designed the parallel execution aspects) and Ævar Arnfjörð Bjarmason (who reviewed earlier API iterations), suggesting consensus on the approach. With the reference-transaction hook now converted, the series has addressed three major real-world hook types, further validating the API design.
