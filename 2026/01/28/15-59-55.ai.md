This is a bugfix thread for git-gui addressing tab alignment issues in the diff viewer on Windows. The discussion has evolved through several iterations, with Johannes Sixt (the git-gui maintainer) now reconsidering his initial resistance to a simple fix after recognizing gitk already customizes tabstops.

The core issue makes git-gui diffs effectively unreadable due to misaligned tabs when viewing both staged changes and untracked files. The current proposed solution uses Tk's `apply_tab_size` configuration, but implementation details remain unresolved:

1. The patch currently fails with a "no such variable" error for `have_tk85`, requiring a fix to variable handling before proceeding.
2. Johannes notes the solution must handle different contexts - regular diffs (offset 1), combined diffs (offset 2), and untracked files (offset 0).
3. While Chris Idema's one-line fix works for regular diffs, Johannes now agrees git-gui need not strictly emulate terminal behavior but wants to ensure proper handling of all cases.

The thread shows progress toward consensus, with Johannes shifting from opposition to conditional acceptance while emphasizing the need for correct handling of combined diffs. The severity of the usability impact (making diffs unreadable) appears to be motivating a practical solution despite the technical complexities around different diff contexts.
