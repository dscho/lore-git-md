This is the final patch in a 4/4 series on ODB transaction handling, part of the ongoing ODB abstraction effort led by Patrick Steinhardt with Justin Tobler contributing this specific work. The patch moves common transaction management logic - enforcing single-transaction-at-a-time semantics and proper cleanup - from the loose objects backend into the generic ODB layer. 

The patch relocates two key behaviors: checking for/clearing pending transactions during begin/commit operations, and the transaction pointer management that ensures only one transaction can be active at a time. These are moved from `object-file.c` (the loose objects implementation) to `odb.c` (the generic ODB interface), where they properly belong as they apply to all transaction types, not just loose objects. The changes are straightforward - removing the now-redundant checks from the loose backend and adding equivalent ones in the ODB layer while maintaining identical behavior.

This completes the transaction refactoring work in the series, leaving the ODB infrastructure with cleaner separation between generic transaction handling (now in `odb.c`) and backend-specific implementations (remaining in `object-file.c` for loose objects case). The patch follows the series' pattern of incremental, well-explained changes that move the ODB abstraction forward while preserving existing behavior. Reviewers will want to verify the transaction state management remains correct, particularly around error cases, though the direct mapping between old and new code suggests low risk.
