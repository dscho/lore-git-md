This is part 3/12 of a series refactoring Git's hook subsystem to support parallel execution, building on the test infrastructure established in patches 1-2. The patch introduces stdin handling for parallel processes via a new callback API in `run-command.c`.

The core change adds a `feed_pipe_fn` callback that lets callers stream large inputs to child processes without buffering everything in memory. This solves a practical limitation where hook inputs (like pre-push data) could exceed pipe buffers. The implementation:

1. Adds new process state helpers (`child_is_ready_for_cleanup`, `child_is_receiving_input`) to manage stdin lifecycle
2. Introduces `pp_buffer_stdin()` to handle the feeding logic, calling back to the provided `feed_pipe` function
3. Combines stdin/stdout handling in a new `pp_handle_child_IO()` function
4. Adds SIGPIPE handling since broken pipes are expected during streaming
5. Includes comprehensive tests demonstrating the streaming behavior

The patch maintains backward compatibility by making the callback optional - when absent, it simply closes stdin. Test coverage verifies the streaming behavior works across multiple parallel processes. This infrastructure will be used by subsequent patches to convert existing hooks to the parallel API while handling their stdin needs properly.

The changes are well-contained to `run-command.c` with minimal interface additions to `run-command.h`. The test additions follow existing patterns in t0061. Review feedback from v7 appears addressed, with clean separation between the parallel execution mechanics and hook-specific logic that will build on top.
