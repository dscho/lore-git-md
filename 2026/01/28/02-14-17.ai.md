This is a discussion response in the ongoing thread about supporting multiple named ignore files in Git. brian m. carlson raises several technical and philosophical objections to the proposal while suggesting alternative approaches.

The response makes three main points: First, it argues that editor-specific ignore rules should be handled in personal ignore files rather than project files, since different contributors use different editors. Second, it notes that automatic loading of additional ignore files would not be truly backward compatible, as older Git versions wouldn't honor them. Third, it suggests that an explicit inclusion syntax (with a special pragma) might be preferable to automatic file loading, though implementing this cleanly would be challenging.

The reply includes practical observations about current ignore file sizes in various projects (Go, Rust, Git itself) and suggests that better organization of build outputs could reduce the need for large ignore files. While not outright rejecting the idea, the response clearly favors more conservative solutions and questions whether the proposed feature is actually needed given existing mechanisms like per-directory `.gitignore` files. The tone is characteristically opinionated, emphasizing conventional approaches and backward compatibility concerns.
