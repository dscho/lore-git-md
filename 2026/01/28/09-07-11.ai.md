This is a bugfix patch for git-gui's diff viewer tab alignment, part of an ongoing thread about inconsistencies between git-gui and gitk's display behavior on Windows. The patch proposes using Tk's `apply_tab_size 1` configuration to fix misaligned tabs in single-parent diffs, matching gitk's behavior.

The author Chris Idema responds to Junio Hamano's review questions about why the patch series initially added then removed a tab expansion function. He explains the evolution of the initial approach (now considered inferior) to the current Tk configuration solution, though the response includes some frustration with the mailing list workflow. The key technical justification is visual consistency - git-gui currently shows different tab alignment than gitk and command-line `git diff`, which makes code review difficult.

The thread context reveals deeper technical considerations about historical behavior (dating back 14 years to commit a43c5f51) where different tab size settings were intentionally used for single-parent (0) versus combined diffs (1). Junio's review raises valid concerns about whether changing this longstanding convention might introduce new inconsistencies, particularly for combined diffs. The author provides visual evidence of the current misalignment but doesn't directly address the combined diff implications.

This appears to be a well-motivated fix for a real usability issue, but the patch may need refinement to handle combined diff cases properly. The architectural approach (using Tk's native tab configuration) seems sound, but the thread suggests more analysis is needed to ensure the change doesn't break other diff contexts. The patch is likely to progress once these edge cases are addressed.
