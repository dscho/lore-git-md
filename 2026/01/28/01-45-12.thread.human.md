The thread documents an interaction issue between Git's maintenance services and address sanitizer (ASAN) when running under systemd. Jacob Keller reported that maintenance services built with ASAN get stuck in an infinite loop during shutdown, traced to ASAN's leak detection behavior under systemd's process isolation. While the exact root cause remains unclear, the problem manifests as the process repeatedly calling `sched_yield()` when ASAN attempts to report leaks during shutdown.

The report primarily serves to document the issue and provide a workaround rather than proposing code changes to Git itself. The solution involves disabling leak detection via `ASAN_OPTIONS=detect_leaks=0` in a systemd service override file, which allows the maintenance services to complete successfully. This affects developers who build Git with sanitizers enabled and run maintenance under systemd, but doesn't indicate a bug in Git's core functionality - rather, it's an interaction between systemd's process management and ASAN's shutdown behavior.
