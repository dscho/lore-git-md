This is a bugfix patch for git-gui addressing tab alignment inconsistencies in the diff viewer. The patch follows up on previous discussion where an initial approach of converting tabs to spaces was rejected because it broke the "Stage Line/Hunk for Commit" functionality.

The current solution uses Tk's native `apply_tab_size` configuration to adjust tab rendering without modifying the underlying text content. This aims to make git-gui's tab display consistent with gitk and command-line `git diff` output. The one-line change sets `apply_tab_size 1` when inserting diff lines into the viewer.

While this approach satisfies the maintainer's requirement to preserve staging functionality, Junio Hamano has raised concerns about how it might interact with combined diffs (those showing changes from multiple parents). The patch doesn't yet address whether this uniform tab size would create issues for combined diffs' two-column prefix format, which historically used different tab sizing.

The patch appears technically sound for regular diffs, but the thread remains open pending resolution of these combined diff considerations. The author has demonstrated the visual improvement for standard cases but hasn't yet shown the solution works correctly in all diff contexts.
