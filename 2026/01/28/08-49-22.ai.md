This is the third patch in Patrick Steinhardt's series fixing misuse of `refs_for_each_ref_in()` in bitmap and bisect handling. This matches the pattern established in the earlier bitmap-related patches of the series, where exact ref handling needed similar fixes. The modification is straightforward - instead of stripping and re-adding the prefix, it preserves the full refname throughout.

The patch maintains the existing behavior where refs like "refs/bisect/base" are still properly handled while avoiding the edge case where an exact "refs/bisect" ref would cause problems. This completes the series' goal of fixing all cases where the ref iteration API was being used in ways that could trigger assertions when processing exact ref matches. The changes are confined to bisect.c with no test updates needed, as the existing test coverage for bisect state cleanup remains valid.
