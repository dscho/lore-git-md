This is a test patch in the hook subsystem refactoring series, specifically adding test coverage for hook output stream behavior. As the first patch in v8 of this 12-part series, it establishes baseline verification that hooks write to stdout and stderr as expected, addressing gaps that previously led to regressions during the hook API conversion.

The patch introduces comprehensive test coverage for both client-side and server-side hooks, verifying whether each hook type keeps stdout and stderr separate or merges them as required. It adds helper functions `check_stdout_separate_from_stderr()` and `check_stdout_merged_to_stderr()` to validate the output streams, then exercises this across all major hook types including pre-push, commit, checkout, merge, rebase, and server-side receive hooks.

Key technical details include:
- The pre-push hook is special-cased to maintain separate stdout/stderr streams
- All other hooks (including server-side ones) are verified to merge stdout to stderr
- Tests cover both the happy path and edge cases like empty commits and branch operations
- The test structure follows Git's standard test organization with proper cleanup

The patch has already incorporated feedback from Patrick Steinhardt and Junio Hamano (both credited as Suggested-by) and represents the final iteration of this test infrastructure before the substantive hook changes in subsequent patches. As the foundation for the series, it provides the verification framework needed to ensure the parallel execution changes don't break existing hook output behavior.
