This is a performance optimization RFC for the p3400 rebase test setup, where Tian Yuchen is investigating why switching from a shell loop to git fast-import for test repository creation shows mixed results. While the setup phase becomes 38% faster (29s -> 18s), the actual rebase operation regresses from 2s to 5s.

The author suspects the performance regression may stem from fast-import producing non-delta-compressed packfiles, as hinted by the fast-import documentation's recommendation to repack afterward. This is a plausible hypothesis since delta compression significantly affects Git's object access patterns. The thread needs input from fast-import experts to confirm whether this is indeed the root cause and whether repacking between setup and measurement would resolve the discrepancy.

Key technical details for future reference: The test creates 100 commits with alternating file contents, currently comparing shell-based creation against fast-import. The fast-import approach avoids process spawning by precomputing file contents. The open question is whether the repository characteristics differ meaningfully between methods despite producing identical commit graphs, and if so, whether this invalidates the performance comparison or can be mitigated by post-import repacking.
