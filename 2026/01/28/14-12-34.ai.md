This is a feature proposal addressing a limitation in `git config --get-regexp`'s case-insensitive matching behavior. Pushkar Singh identifies that the current implementation naively lowercases parts of regex patterns before compilation, which breaks complex expressions like `^[^.]*Foo.*`. The proposal suggests using `REG_ICASE` instead to properly handle case-insensitive matching without modifying the user's regex pattern.

The change would affect `builtin/config.c`'s handling of regex compilation, specifically around the `get_value()` function where the current approach is marked with a NEEDSWORK comment. This would make the behavior more predictable for users trying to write complex patterns while maintaining case-insensitive matching as documented.

The proposal is well-motivated, pointing to both technical limitations (broken complex patterns) and documentation inconsistencies (claiming canonicalized matching while actually modifying patterns). If implemented, this would resolve a long-standing quirk in config regex matching without introducing backward compatibility issues, as the case-insensitive behavior itself isn't changing - just how it's achieved.
