This thread addresses a bug in Git's handling of exact branch names during ref iteration, which was causing crashes in both bitmap and bisect operations. Patrick Steinhardt's patch series first consolidated bitmap tip iteration code and then fixed the core issue by replacing `refs_for_each_ref_in()` with `refs_for_each_fullref_in()` to properly handle exact ref matches. The latest patch in the series, now in its second version, cleans up memory management in the bisect subsystem by simplifying string_list handling - a refinement suggested earlier by Jeff King.

The technical approach has been reviewed and approved by both Karthik Nayak and Junio Hamano, with Junio defending the use of helper functions for readability. While there was some discussion about whether to maintain prefix-matching behavior or require explicit trailing slashes for hierarchy matching, the consensus leaned toward maintaining backward compatibility while clearly documenting the current behavior. The series is now complete with this final cleanup patch, which makes the bisect ref handling more robust without changing functionality. All tests in t5310 and t5319 verify the fixes, and the documentation has been updated to clarify the ref-matching semantics.
