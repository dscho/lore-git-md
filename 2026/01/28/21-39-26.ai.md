Hook subsystem refactoring series (v8, 11/12) by Adrian Ratiu and Emily Shaffer converts receive-pack's update and post-update hooks to the new hook API. This patch builds on the parallel execution infrastructure from earlier in the series while maintaining sequential execution as the default (jobs=1).

The key changes replace direct child_process usage with run_hooks_opt calls, adding sideband handling for hook output when use_sideband is enabled. The implementation introduces helper functions prepare_sideband_async() and finish_sideband_async() to manage the async thread that redirects hook stderr to the sideband when needed. The patch preserves existing behavior for sequential execution while laying groundwork for potential future parallel execution of these hooks.

Notable technical details include:
- Maintains backward compatibility with existing hook behavior
- Uses the new sideband_async thread for output redirection when use_sideband=1
- Preserves real-time output performance in sequential mode via ungroup=1
- Prepares for parallel execution with output de-interleaving when jobs>1
- Converts both update and post-update hooks to the new API
- Includes sign-offs from key contributors Emily Shaffer and Ævar Arnfjörð Bjarmason

This continues the series' pattern of converting real-world use cases to demonstrate the new hook API's viability, with receive-pack being a particularly important case due to its server-side role. The patch appears well-integrated with the series' overall architecture and maintains the careful attention to backward compatibility seen in previous iterations.
