This is the final patch (12/12) in a series converting Git's hook subsystem to a new API, specifically targeting receive-pack's update and post-update hooks. The series has been through multiple iterations (now at v8) with significant review and input from key contributors like Emily Shaffer, Jeff King, and Ævar Arnfjörð Bjarmason.

The patch converts receive-pack's hook handling to use the new `run_hooks_opt` API, bringing several benefits:
- Eliminates manual signal handling
- Removes custom `child_process` management
- No longer needs explicit `find_hook()` calls
- Prepares for future config-based hook specification
- Maintains backward compatibility

Key technical aspects include:
- Replaces direct process management with `run_hooks_opt` infrastructure
- Implements a callback-based feed mechanism (`feed_receive_hook_cb`) for streaming ref updates to the hook
- Handles sideband output via `prepare_sideband_async`/`finish_sideband_async`
- Preserves push certificate and push option environment variables
- Maintains the existing skip-broken-refs behavior

The conversion follows the pattern established in earlier patches of the series, demonstrating the API's flexibility across different hook types. The implementation has been reviewed by multiple core contributors and appears ready for merging, completing the hook subsystem modernization effort.
