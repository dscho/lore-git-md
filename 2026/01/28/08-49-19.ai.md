This is a bugfix series addressing incorrect usage of `refs_for_each_ref_in()` in the bitmap and bisect code. The primary issue occurs when "pack.preferBitmapTips" is configured with an exact branch name, causing Git to hit a BUG() due to improper refname handling.

The root problem lies in how `refs_for_each_ref_in()` strips the prefix from refnames - when given an exact match, it produces an empty string which triggers an assertion. Patrick Steinhardt identifies two affected callers: the bitmap preference logic and bisect's ref iteration. The series first deduplicates bitmap tip iteration logic between pack-objects and midx repacking, then fixes both the bitmap and bisect cases. New tests verify the fixes handle exact ref matches correctly.

The patches show typical Steinhardt thoroughness - clean refactoring alongside the bugfixes, with comprehensive test coverage added for both affected areas. Given the straightforward nature of the fixes and their potential to trigger crashes in edge cases, this series seems likely to be merged quickly. The changes are contained to relatively obscure corners of the codebase (bitmap handling and bisect internals), so most users wouldn't notice unless they hit these specific edge cases.
