This is patch 11/12 in a series refactoring Git's hook subsystem to support parallel execution and configurable hooks. The patch converts receive-pack's update and post-update hooks to use the new hook API.

The changes replace direct child_process handling with the new run_hooks_opt infrastructure while maintaining the existing sideband behavior for remote clients. The key improvements are:

1. Replaces manual hook setup (find_hook, child_process) with run_hooks_opt calls
2. Preserves sideband output when use_sideband=1 by using new helper functions prepare_sideband_async/finish_sideband_async
3. Maintains sequential execution (jobs=1) for these hooks
4. Keeps the same real-time output performance via ungroup=1 when not using sideband

The patch builds on previous work in the series that introduced parallel execution capabilities and optimized I/O handling. It demonstrates the API's flexibility by cleanly converting two real-world hooks while preserving their existing behavior. The changes have been reviewed by multiple contributors including Jeff King and Ævar Arnfjörð Bjarmason, indicating technical consensus.

This continues the series' pattern of methodically converting core hooks while maintaining backward compatibility and performance. With only one patch remaining, the hook refactoring effort appears close to completion.
