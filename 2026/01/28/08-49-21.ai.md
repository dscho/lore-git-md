Bugfix targeting the pack-bitmap subsystem, part of Patrick Steinhardt's series addressing `refs_for_each_ref_in()` misuse. This patch fixes a BUG() that occurs when "pack.preferBitmapTips" contains an exact branch name rather than a prefix like "refs/heads/". The issue stems from how `refs_for_each_ref_in()` attempts to strip the full refname when given an exact match, leaving an empty string that triggers the BUG.

The fix replaces `refs_for_each_ref_in()` with `refs_for_each_fullref_in()`, which doesn't strip the prefix. This maintains the expected behavior while avoiding the BUG condition. The change introduces a minor semantic quirk where a ref like "refs/heads/base" would now match both itself and "refs/heads/base-something", but the patch deliberately leaves this edge case unchanged to avoid potential regressions.

The patch includes comprehensive tests in both t5310-pack-bitmaps.sh and t5319-multi-pack-index.sh that verify the fix works for both regular pack bitmaps and MIDX-based bitmaps. The tests create a scenario where some commits intentionally don't get bitmap coverage, then demonstrate that configuring an exact ref in pack.preferBitmapTips correctly adds that commit to the bitmap coverage. This is characteristic of Steinhardt's thorough approach - combining a focused bugfix with robust test coverage across related subsystems.
