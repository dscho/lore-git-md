This is part 3/12 of a series refactoring Git's hook subsystem to support parallel execution, building on previous work to standardize hook execution via the `hook.h` API. The patch introduces a stdin callback mechanism for `run_processes_parallel()` to handle large input streams efficiently without buffering everything in memory. 

The key addition is a `feed_pipe_fn` callback that lets callers incrementally write data to child processes' stdin pipes. This solves a real problem where hook implementations like `pre-push` need to stream large amounts of data without hitting pipe buffer limits. The implementation carefully handles SIGPIPE and includes new helper functions (`child_is_ready_for_cleanup`, `child_is_receiving_input`) to manage process state.

The patch comes with thorough test coverage, including a new test case that verifies stdin handling works correctly across multiple parallel processes. It's part of a well-reviewed series that has already addressed feedback from key reviewers like Jeff King and Patrick Steinhardt. The changes look solid and focused - this is clearly a necessary piece of infrastructure for the parallel hooks effort.
