This is part 4/12 of a series refactoring Git's hook subsystem to support parallel execution and stdin streaming. The patch introduces a callback mechanism for feeding stdin to hooks without buffering entire inputs in memory or files.

The key addition is a `feed_pipe_fn` callback in `struct run_hooks_opt` that allows streaming large amounts of data to hook processes incrementally. This complements the existing `path_to_stdin` option (which reads from a file) and is particularly useful for hooks processing large inputs like ref lists during pushes. The implementation ensures the two stdin mechanisms are mutually exclusive via BUG() assertions.

The patch builds on the parallel execution support added in patch 3/12, with careful attention to backward compatibility. It includes thorough documentation of the new callback API and its associated context pointers (`feed_pipe_ctx` for initialization data and `feed_pipe_cb_data` for per-hook state). The changes are well-contained, touching only `hook.c` and `hook.h` while maintaining the existing hook behavior when the new callback isn't used.

This represents a significant technical milestone in the hook refactoring series, enabling efficient streaming of hook inputs while preserving the simple file-based stdin approach for simpler cases. The implementation has been reviewed by multiple core contributors (Emily Shaffer, Ævar Arnfjörð Bjarmason) and appears ready for merging.
