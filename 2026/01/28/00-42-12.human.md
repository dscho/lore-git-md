Feature proposal for multiple named ignore files. ZH L suggests expanding Git's ignore mechanism to support additional files like editor.gitignore and build.gitignore alongside the standard .gitignore, with clear precedence rules. The motivation is to better organize ignore rules in large repositories where different types of patterns (editor-specific, build artifacts, etc.) currently get mixed together in a single file.

The proposal is framed as an exploratory question rather than a concrete implementation, asking whether this has been considered before and whether there are fundamental objections. The author notes this could reduce the need for external scripts that currently generate .gitignore files, suggesting they've encountered this pain point in practice.

This appears to be a well-motivated quality-of-life improvement that wouldn't break existing workflows. The idea seems plausible from a technical standpoint, though the email doesn't propose specific precedence rules or implementation details. The thread is just starting, so we'll need to see how maintainers respond to whether this aligns with Git's design philosophy for ignore rules.
