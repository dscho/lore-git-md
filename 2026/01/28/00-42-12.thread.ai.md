Multiple named ignore files proposal (RFC) from ZH L explores extending Git's ignore mechanism to automatically include `*.gitignore` files alongside `.gitignore`, aiming to organize rules in large repositories while maintaining compatibility. brian m. carlson objects, arguing editor-specific rules belong in personal ignore files, automatic loading isn't truly backward compatible (older Git versions would ignore them), and suggests explicit inclusion via pragma might be preferable. ZH L now acknowledges these concerns, agreeing editor rules should be personal and recognizing backward compatibility risks, clarifying they sought discussion rather than pushing for adoption. Core objections remain unresolved: whether the feature is needed given existing per-directory `.gitignore` mechanisms, how to handle version compatibility if implemented, and whether explicit includes would be preferable to automatic pattern matching. The thread shows no movement toward consensus, with ZH L stepping back from advocacy while brian m. carlson maintains skepticism about the proposal's value versus complexity.
