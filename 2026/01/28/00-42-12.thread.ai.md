Multiple named ignore files proposal (RFC) from ZH L explores extending Git's ignore mechanism to automatically include `*.gitignore` files alongside `.gitignore`, aiming to organize rules in large repositories while maintaining compatibility. The proposal seeks feedback on naming patterns (`*.gitignore` alternatives), precedence rules, interaction with global/info/exclude, and performance impact before implementation. brian m. carlson raises objections, arguing editor-specific rules belong in personal ignore files, automatic loading isn't truly backward compatible (older Git versions would ignore them), and suggests explicit inclusion via pragma might be preferable. They note current ignore file sizes in Go/Rust/Git and propose better build output organization could reduce need for large ignore files. The response favors conservative solutions using existing per-directory `.gitignore` mechanisms. Open questions remain about whether the feature is needed given current alternatives and how to handle backward compatibility if implemented. The discussion continues with no clear consensus yet on whether to pursue the approach or stick with existing ignore file patterns.
