Hook subsystem refactoring: This is the 7th patch in a 12-part series modernizing Git's hook infrastructure. It converts the pre-push hook from direct `run-command` usage to the new hook API, while maintaining the hook's requirement for separate stdout/stderr streams.

The patch replaces the custom child process handling with the new hook API's `run_hooks_opt` structure. Key changes include:
- Moving the ref filtering logic into a `pre_push_hook_feed_stdin` callback
- Using the new `stdout_to_stderr=0` flag to preserve the pre-push hook's stream separation
- Simplifying error handling while maintaining the same semantics

The conversion demonstrates the hook API's flexibility - it cleanly handles the pre-push hook's special requirements while eliminating boilerplate code. The patch has already collected sign-offs from Emily Shaffer (original parallel execution design) and Ævar Arnfjörð Bjarmason (API review), suggesting it's a well-vetted change.

This continues the series' pattern of migrating individual hooks to the new infrastructure while preserving their existing behavior. The pre-push hook is particularly important case as it's widely used in CI/CD pipelines, so maintaining backward compatibility here was essential.
