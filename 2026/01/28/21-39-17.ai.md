This is part 2/12 of the hook subsystem refactoring series, introducing parallel execution support. The patch focuses on code organization in `run-command.c` to improve readability of parallel process state checks.

The change extracts the anonymous child process state tracking struct into a named `parallel_child` type and adds a `child_is_working()` helper function. This replaces repeated direct state comparisons with clearer function calls throughout the parallel process management code. The helper centralizes the check for whether a child process is actively running (state `GIT_CP_WORKING`).

The patch is a straightforward refactoring that doesn't change behavior - it makes the subsequent parallel hook execution patches more maintainable by providing better abstraction. It follows Junio Hamano's suggestion to name the structure and was signed off by the primary author Adrian Ratiu. The change touches only `run-command.c` and maintains all existing functionality while making the code more self-documenting.

This is a preparatory change for the parallel hook execution work that follows in the series. The helper function will be used extensively in later patches that implement the actual hook parallelization. The patch has already been reviewed and approved as part of the larger series.
