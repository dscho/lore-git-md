This is the final patch in a 12-part series refactoring Git's hook subsystem to use a new unified API. Patch 12/12 converts the remaining receive-pack hooks (update and post-update) to the new hook infrastructure, completing the series' goal of modernizing all core hooks.

The conversion follows the pattern established in previous patches: replacing direct child_process handling with the new run_hooks_opt API while maintaining backward compatibility. Key changes include:

1. Replacing the custom run_and_feed_hook implementation with the standard hook API's feed_pipe callback mechanism
2. Moving environment variable setup into the run_hooks_opt struct
3. Integrating with the series' sideband output handling infrastructure
4. Preserving all existing hook functionality including push certificates and options

The patch builds on work from earlier in the series, particularly the parallel execution infrastructure (patches 9/12 and 10/12) and stdin streaming capabilities (patches 3-4/12). While this final conversion defaults to sequential execution (jobs=1), the infrastructure is now in place to enable parallel hook execution in the future.
