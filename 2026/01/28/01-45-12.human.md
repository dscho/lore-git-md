This is a bugfix for an interaction between Git's maintenance services and address sanitizer (ASAN) builds. Jacob Keller reports that when running `git maintenance` services on a system where Git was built with ASAN enabled, the processes would get stuck in an infinite loop calling `sched_yield()` during leak detection at shutdown.

The backtrace shows the issue occurs in ASAN's leak detection during process termination. While the root cause isn't fully understood, it appears related to how systemd isolates processes. The workaround is to disable leak detection in ASAN via an environment variable (`ASAN_OPTIONS=detect_leaks=0`) in a systemd service override file.

This is a niche issue that would only affect users who both build Git with ASAN and run maintenance services via systemd. The patch doesn't propose a code change - it's more of a documentation/awareness note about the workaround. The problem appears to be in the interaction between ASAN and systemd rather than in Git itself, but it's useful to have this workaround documented for others who might encounter it.
