This is a bugfix proposal targeting `git config --get-regexp`'s case-insensitive matching behavior.

Pushkar Singh identifies a problem where Git currently implements case-insensitive regex matching by naively lowercasing parts of the user's regex pattern before compilation. This breaks complex patterns like `^[^.]*Foo.*` and makes it impossible to express certain valid regexes. The issue is marked with a NEEDSWORK comment in the code.

The proposal suggests using POSIX's `REG_ICASE` flag during regex compilation instead of rewriting the pattern. This would preserve the user's original regex while still providing case-insensitive matching, and would eliminate the current limitations. The change would make the behavior more predictable and support more sophisticated regex patterns.

The patch appears well-motivated and addresses a clear limitation in the current implementation. The proposed solution seems straightforward and aligns with standard regex handling practices. This would be a welcome improvement for users who needs precise control over their config regex patterns.
