This is a bugfix patch in Patrick Steinhardt's series addressing issues with exact ref matches in bitmap and bisect functionality. The patch specifically fixes a BUG() condition that occurs when `pack.preferBitmapTips` is set to an exact ref name rather than a prefix, by switching from `refs_for_each_ref_in()` to `refs_for_each_fullref_in()` in the bitmap handling code.

Karthik Nayak's review confirms the fix works as intended, noting that the new behavior (where an exact ref like "refs/heads/base" will match both itself and "refs/heads/base-something") is actually preferable to the previous behavior that would have been a BUG. The patch includes comprehensive tests in t5310-pack-bitmaps.sh that demonstrate the fix by creating a scenario where a commit without bitmap coverage is given coverage after being specified via exact ref in pack.preferBitmapTips.

The change maintains the existing prefix-matching behavior while properly handling exact ref matches, addressing the root cause where the ref iteration API was stripping too many characters from exact ref names. This is part of Steinhardt's broader effort to clean up ref iteration patterns across the codebase, with this patch specifically focusing on the bitmap generation path. The review indicates the changes are technically sound and ready for merging.
