This is a bugfix thread for git-gui's diff viewer alignment, specifically addressing tab rendering inconsistencies between git-gui and gitk on Windows. Johannes Sixt (the gitk maintainer) responds to Junio Hamano's technical concerns about the proposed solution's interaction with combined diffs.

The discussion centers on the `apply_tab_size` configuration in Tcl/Tk, which currently uses different settings for single-parent diffs (`0`) versus two-parent diffs (`1`). Johannes agrees with Junio that the patch needs to justify why changing this long-standing behavior (dating back to commit a43c5f51 in 2012) is correct, rather than simply applying `1` universally.

Johannes identifies two key technical issues with the current patch: First, the tabstop calculations appear suboptimal since diff output always starts with a character ('+', '-', or space), making the first tabstop position at column 1 ineffective. Second, he references historical context from gitk's development where similar initial tabstop settings were later revised.

The thread reveals deeper architectural questions about how git-gui should handle tab rendering across different diff contexts (regular diffs, combined diffs, and unstaged file views). While the patch solves the immediate alignment issue for regular diffs, it hasn't yet addressed the implications for combined diffs or justified overriding the historical single-parent diff behavior. Johannes's comments suggest the solution may need to be more nuanced, potentially requiring different `apply_tab_size` values per context rather than a uniform setting.
