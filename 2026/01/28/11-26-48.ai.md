This is a feature patch from Abraham Samuel Adekunle improving file navigation in `git add -p`'s interactive staging interface (v2). The patch adds context-sensitive '<' and '>' navigation options that only appear when movement between files is possible, addressing maintainer feedback from Junio C Hamano.

The navigation options appear after all hunks in the current file are decided, with a new "All hunks decided. What now?" prompt. The implementation introduces ALLOW_GOTO_PREVIOUS_FILE and ALLOW_GOTO_NEXT_FILE flags to track navigation state while maintaining the existing linear navigation model (no circular behavior). The author confirms willingness to make this an optional feature and address several technical concerns raised by Junio.

Key changes in this version include moving patch application from patch_update_file() to its caller run_add_p() to properly handle cases where users change their mind about hunks after navigating between files. The author explains this prevents inconsistent states where initial hunk decisions would persist even if later changed. Junio questions this architectural change, noting it makes updates all-or-nothing rather than incremental, potentially worsening the interactive experience.

The thread shows productive technical discussion, with Junio suggesting:
1. Making the navigation feature optional via configuration
2. Replacing the get_file_diff_index() helper by passing file indices directly
3. Using enums instead of magic numbers for navigation states
4. Possibly splitting the patch into smaller logical changes

The author agrees with these suggestions and indicates they'll be addressed in the next version. While the core navigation concept has approval, the implementation approach remains under review, particularly around the patch application timing change and helper function design. This represents a quality-of-life improvement for interactive staging that's progressing through careful technical review.
