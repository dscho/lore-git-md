This is a patch series introducing infrastructure for pluggable object database (ODB) backends to handle transactions differently. It's part of the ongoing ODB abstraction effort led by Patrick Steinhardt, with Justin Tobler contributing this specific piece.

The series prepares the ground for different ODB sources (like loose objects, packfiles, or future pluggable backends) to implement their own transaction handling while keeping common transaction logic in a shared layer. The key changes are:
1. Adding ODB source awareness to transaction structures
2. Renaming transaction-related functions for clarity
3. Introducing a generic `odb_transaction` structure that can hold backend-specific callbacks
4. Moving common transaction behavior out of backend-specific code

The implementation currently maintains the existing loose objects backend behavior while making the architecture more flexible. The changes touch core object-file handling code and the new odb abstraction code, with careful attention to maintaining existing functionality during the transition.

This appears to be a well-structured incremental step in the larger ODB abstraction work. The commit messages clearly explain the motivation and changes, and the patches follow the project's preference for small, focused changes. Reviewers will likely want to check that the transaction semantics remain correct across all edge cases, but the approach looks sound.
