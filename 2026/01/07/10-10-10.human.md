This is part 2 of Patrick Steinhardt's v8 series introducing a new `git-history` command, focused on refactoring the replay infrastructure. The patch moves the core commit replay logic from `builtin/replay.c` into a new `replay.c` library file, making it reusable by other commands (notably the upcoming `git-history`).

The changes are mechanical but substantial - 358 lines removed from the builtin and 347 lines added to the new `replay.c`, with a 61-line header file defining the public interface. The refactoring eliminates `the_repository` usage and sign-comparison warnings while maintaining all existing functionality. The new API provides structured ways to specify replay options (`replay_revisions_options`) and collect reference updates (`replay_ref_updates`).

This is a foundational change for the series, enabling the subsequent introduction of `git-history` to build on the replay machinery rather than reimplementing it. The implementation looks solid, with careful attention to maintaining behavior while improving code organization. As part of a larger effort, this patch doesn't introduce user-facing changes but sets up important infrastructure.
