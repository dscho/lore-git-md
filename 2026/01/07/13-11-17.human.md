This is patch 5/10 in Patrick Steinhardt's series refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB. The patch moves the packfile store from `struct object_database` to `struct odb_source`, better aligning the storage model with the conceptual ownership of packfiles by individual sources (main repo/alternates).

The changes touch 11 files, with the bulk being mechanical updates to callers that directly interact with packfiles (fast-import, grep, pack-objects, etc.). The key insight is that most callers don't need modification because they use higher-level interfaces like `repo_for_each_pack()` that already handle source enumeration. Toon Claes notes a minor documentation clarification about `packfile_store_prepare()` behavior that will be addressed in a follow-up patch.

This continues the series' clean architectural progression toward making packfile operations properly source-aware, a prerequisite for pluggable ODB backends. The changes maintain identical behavior while setting up for future patches that will fully isolate packfile operations per source.
