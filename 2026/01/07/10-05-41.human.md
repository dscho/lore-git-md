This is a technical review response in the ongoing promisor remote enhancement series (patch 8/9). Patrick Steinhardt provides feedback on Christian Couder's implementation of storing server-side advertised filters in memory for promisor remotes.

Patrick suggests two improvements: first, renaming `captured_filters` to `advertised_filters` for clarity, as "captured" might be confusing terminology. Second, he questions whether we should handle the case where an accepted promisor remote lacks an advertised filter - suggesting we might want to `BUG()` in such cases if it's an invalid state.

The patch is part of a larger effort to implement `--filter=auto` functionality that dynamically combines filters from accepted promisor remotes. This specific patch adds infrastructure to store server-advertised filters in memory and provides a function to construct combined filters from accepted remotes. Patrick's review focuses on naming consistency and error handling robustness, continuing his pattern of thorough technical feedback throughout this series.
