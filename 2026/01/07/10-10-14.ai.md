This is patch 6/7 in Patrick Steinhardt's v8 series introducing the new `git history` command, a feature aimed at providing more intuitive history rewriting capabilities compared to `git rebase`. The patch adds the core command infrastructure including documentation, build system integration, and basic tests.

The new command is positioned as an experimental alternative to `git rebase` with key differences: it works in bare repositories, doesn't execute hooks (currently), and by default updates all descendant branches of rewritten commits. The documentation outlines planned subcommands for common history editing operations like reordering, splitting, and dropping commits, though the initial implementation here is just the scaffolding.

The patch adds:
- Basic command plumbing in `builtin/history.c`
- Documentation in `git-history.adoc` explaining the command's purpose and limitations
- Build system integration (Makefile, meson.build)
- A simple test script verifying basic argument handling

Notable technical details:
- Currently a no-op command that just parses options
- Marked as experimental in documentation
- Explicitly documents limitations around merge commits and conflicts
- Sets up infrastructure for future subcommands
- Uses standard Git command-line parsing patterns

This is part of a larger effort to provide Jujutsu-inspired history editing capabilities while building on Git's existing replay infrastructure. The patch appears well-structured and follows Git's coding style, though the actual functionality will come in subsequent patches of the series.
