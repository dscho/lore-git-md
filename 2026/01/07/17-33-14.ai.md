This is a documentation-focused whitespace checking feature, extending Git's existing whitespace infrastructure to catch tabs that should be spaces in documentation files. Johannes Sixt provides review feedback on Adrian Ratiu's v2 patch implementing Junio Hamano's suggestion for a new whitespace rule.

The patch adds a `tab-between-non-ws` check (likely to be renamed `tab-instead-of-space` per prior discussion) that detects when tabs appear between non-whitespace characters in documentation where a space was likely intended. The implementation tracks both character position and visual column position to determine when a tab would visually appear as a single space.

Johannes' review focuses on test improvements, suggesting:
- Using `test_config` for temporary config changes
- More comprehensive test cases that verify only the problematic tabs are flagged
- Proper negative test syntax (`test_grep !`)
- Possibly moving the `git apply` tests to t4124
- Clarifying why tabwidth=8 is explicitly set when it's the default

The feedback indicates the core implementation is sound but needs polish in the test presentation. No technical objections remain - this is now down to naming and test case quality before finalization. The feature will help maintain documentation quality as part of broader efforts like Jean-Noël Avila's synopsis-style conversion work.
