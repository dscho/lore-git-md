This is part 4 of Patrick Steinhardt's 7-patch series refactoring Git's object info handling for the ODB abstraction effort. The patch ensures consistent population of pack-specific fields when reading object information, eliminating a discrepancy between two code paths that could lead to different behavior.

The change moves the packfile-specific field population into `packed_object_info()` where it logically belongs, rather than having it handled in `packfile_store_read_object_info()`. This makes the behavior more predictable - callers can now always expect these fields to be populated when reading from a packfile. The diff shows the straightforward movement of this logic, with the fields now being set in one place rather than conditionally in another.

This is a well-contained change that follows naturally from the series' goal of cleaning up the object info interfaces. It has already been through multiple review rounds with the GitLab ODB team (including Karthik Nayak) and addresses all feedback. The series as a whole is now approved and represents a significant step in the ongoing ODB abstraction work.
