This is a feature patch adding a new whitespace check to detect tabs between non-whitespace characters where a space was likely intended. The patch comes from Adrian Ratiu and implements a suggestion from Junio Hamano.

The new `tab-between-non-ws` check looks for tabs that would visually appear as a single space (i.e. when they land on a tab stop boundary) when surrounded by non-whitespace characters. This helps catch cases where a space was likely intended but a tab was accidentally used instead. The check is initially enabled for AsciiDoc documentation files where these issues were observed.

The patch includes:
- Core detection logic that tracks both character positions and visual columns
- Support for highlighting the problematic tabs in diff output
- Automatic fixing via `git apply --whitespace=fix`
- Comprehensive test coverage of various edge cases
- Integration with the existing whitespace checking infrastructure

The implementation is thorough, with careful handling of tab width calculations and visual column tracking. The v2 iteration incorporates Junio's feedback to improve highlighting and fixing behavior. This looks like a well-constructed addition to Git's whitespace handling that should help maintain documentation consistency.
