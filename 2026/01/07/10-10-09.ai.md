This is a refactoring patch from Patrick Steinhardt, part of a larger series (v8 1/7) to move replay functionality into libgit. The patch extracts the core revision replay logic from `builtin/replay.c` into a new function `replay_revisions()` that will eventually be moved to a library file.

The new function takes:
- A repository and rev_info struct
- Options struct containing --onto/--advance parameters
- A ref_updates struct to record resulting reference changes

Key changes:
- Moves the commit replay loop and ref update logic into the new function
- Introduces new structs to pass parameters and results cleanly
- Maintains all existing functionality (no behavior change)
- Still has FIXMEs about unsupported cases (root/merge commits)

This is clearly a preparatory step in a larger architectural effort to make the replay functionality available as a library. The patch is well-structured with clear commit message and follows Git's coding style. As noted, this doesn't change user-visible behavior - it's purely internal restructuring to enable future work.

The patch touches core revision walking and merge machinery, but the changes are localized to the replay command's implementation. Given Patrick's track record with large refactorings and the careful separation of concerns shown here, this appears to be a solid step in the series.
