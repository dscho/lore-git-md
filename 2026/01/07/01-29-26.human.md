Bugfix patch addressing race conditions in `git fsck` when run on live repositories, part of an ongoing collaboration between Elijah Newren and Jeff King (Peff) under Junio Hamano's guidance. This v2 iteration refines the solution based on previous feedback.

The core issue is that `git fsck` can report false positives when run concurrently with repository modifications, as it reads refs at operation start/end. This is particularly problematic for automated maintenance and forge operations. The patch introduces a snapshot mechanism to capture ref states at program start, then verifies against that snapshot rather than live refs.

Key changes in v2 include:
- Adopting Junio's suggested `struct ref_snapshot` design
- Handling both forward (new objects) and reverse (GC deletion) race cases
- Extending to command-line specified refs (addressing Peff's edge case)
- Adding `odb_reprepare()` for fresh object DB state
- Retaining timestamp-based reflog filtering with TODO markers for future improvement
- The implementation now clearly documents worktree/index limitations

The patch demonstrates careful attention to review feedback while maintaining the core approach's integrity. It shows good test coverage via the included script and appears production-ready, though it leaves some edge cases (like network filesystem clock skew) as future work. The changes are concentrated in `builtin/fsck.c` with about 90 lines modified.

This solution will be valuable for forge operators and anyone running automated maintenance jobs where concurrent repository access is likely. The patch represents a significant improvement in `fsck`'s reliability for live repositories.
