This is part 1 of a 7-patch series introducing a new `git replay` command, focused on refactoring the core logic into a reusable function. The patch comes from Patrick Steinhardt, a major contributor working on Git's architectural improvements.

The patch extracts the core revision replaying logic from `cmd_replay()` into a new `replay_revisions()` function that:
1. Takes revision ranges and replay options as input
2. Performs the commit replay operation
3. Records resulting ref updates in a caller-owned structure

This is preparatory work for moving the logic into libgit.a in subsequent patches. The change is purely internal - no user-visible behavior changes. The code handles both `--onto` and `--advance` modes, though it still has limitations noted in FIXME comments (no root commit or merge commit support yet).

The patch shows typical Steinhardt quality: thorough, well-structured, with clear commit message explaining the change. It's part of his ongoing effort to build out Git's`libgit` library with reusable components. The series appears to be heading toward making the replay functionality available to other Git commands.
