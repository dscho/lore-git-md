This is the final version (v8) of a feature series implementing configurable submodule gitdir paths through a new `extensions.submodulePathConfig` extension. The series has been through extensive review and is now ready for merging after addressing final nits.

The core feature allows users to specify custom gitdir paths for submodules via `submodule.<name>.gitdir` configuration, with automatic encoding to prevent filesystem conflicts. This solves issues like case-insensitive filesystem collisions when creating submodules named `foo" and `Foo`. The implementation includes:

1. A four-tier fallback system for path resolution (plain -> encoded -> numbered -> hashed)
2. Case-folding protection via RFC3986 encoding
3. An atomic migration command (`git submodule--helper migrate-gitdir-configs`)
4. Comprehensive test coverage including nested submodules and case-insensitive filesystems

Key changes in v8:
- Added test verifying gitdir config paths are relative for both absolute and relative URLs
- Improved error messages and added advice when gitdir validation fails
- Renamed `init.autoSetupSubmodulePathConfig` to `init.defaultSubmodulePathConfig` and moved its initialization logic
- Fixed repository format version handling to not overwrite potential future versions
- Fixed test file operators and spacing per review feedback
- The series touches `submodule.c`, `builtin/submodule--helper.c`, `setup.c`, and `url.[ch]`, introducing new configs:
  - `extensions.submodulePathConfig` (repository extension)
  - `submodule.<name>.gitdir` (per-submodule path)
  - `init.defaultSubmodulePathConfig` (global default)
