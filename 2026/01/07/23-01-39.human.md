This is part 5 of an 11-patch series implementing runtime configuration for submodule gitdir paths via a new `extensions.submodulePathConfig` extension. The series has been through multiple rounds of review and is now in its final form, with Junio Hamano having acked it for merging.

This particular patch adds a new `init.defaultSubmodulePathConfig` option that allows enabling the submodule path extension by default for new repositories (those created via `git init` or `git clone`). Importantly, this only affects new repositories - existing ones will still need explicit migration. The implementation includes comprehensive test coverage for various init/clone scenarios with and without the extension enabled.

The patch follows the series' architectural approach of centralized path resolution through `submodule_name_to_gitdir()`. It builds on previous work that established the four-tier fallback system for path encoding and case-folding protection. The tests verify both the basic functionality and edge cases like recursive submodule handling.

This is a well-polished addition to the series, with clear documentation and thorough test coverage. The implementation is straightforward, modifying `setup.c` to check the new config during repository initialization while maintaining the existing version handling logic. The patch has already incorporated feedback from previous rounds, including suggestions from Patrick Steinhardt and Junio Hamano about the config naming and initialization behavior.
