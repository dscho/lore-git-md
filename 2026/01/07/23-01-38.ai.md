This is a feature patch introducing the `extensions.submodulePathConfig` extension, part of an 11-patch series addressing submodule gitdir path encoding. The series has reached its 8th iteration and is now ready for merging with Junio Hamano's ack.

The patch establishes a new repository extension that makes `submodule.<name>.gitdir` the single source of truth for submodule gitdir paths when enabled. This solves filesystem conflicts in submodule gitdirs (particularly on case-insensitive systems) and enables custom layouts. The extension requires explicit configuration for existing submodules while automatically setting paths for new ones.

Key technical details:
- New `repository_format_submodule_path_cfg` flag tracks extension state
- Path validation centralized in `validate_submodule_git_dir()`
- Automatic config generation via `create_default_gitdir_config()`
- Comprehensive test coverage in new `t7425-submodule-gitdir-path-extension.sh`
- Documentation updates in `Documentation/config/extensions.adoc` and `submodule.adoc`

The implementation maintains backward compatibility while enforcing the new config requirement when the extension is active. Error messages guide users through migration, suggesting commands like `git config submodule.foo.gitdir .git/modules/foo` for existing submodules.

This represents the core architectural piece of the series, with subsequent patches building on this foundation to handle migration and edge cases. The approach has been thoroughly reviewed by key contributors including Patrick Steinhardt and Phillip Wood, with all feedback from previous iterations addressed.
