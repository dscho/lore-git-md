This is part 9/11 of a series implementing submodule gitdir path encoding to prevent filesystem conflicts. The patch specifically addresses case-folding collisions on case-insensitive filesystems when `extensions.submodulePathConfig` is enabled.

The key addition is a new check that detects potential case-folding conflicts in `.git/modules/` and forces percent-encoding of uppercase characters when needed. The implementation:

1. Introduces `is_casefolding_rfc3986_unreserved()` helper in `url.[ch]` that treats uppercase as reserved characters
2. Adds case-folding conflict detection in `submodule.c` that scans the modules directory for name collisions
3. Implements a fallback strategy that first tries RFC3986 encoding, then case-folding-aware encoding, then numbered suffixes
4. Includes comprehensive tests demonstrating the collision prevention for various case combinations

The patch maintains the series' architectural approach of centralized path resolution through `submodule_name_to_gitdir()` while adding this new safety check. It's part of the broader effort to enable custom gitdir layouts while preventing filesystem conflicts, with all review feedback from previous iterations addressed.
