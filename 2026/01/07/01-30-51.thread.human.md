This thread has finalized a patch series by Adrian Ratiu that introduces a new whitespace check for documentation files, specifically detecting when tabs appear between non-whitespace characters where spaces were likely meant. The feature preserves legitimate tab usage for indentation while helping catch accidental tab characters in running text.

The implementation has gone through several iterations with thorough review from both Junio Hamano and Johannes Sixt. All technical feedback has been addressed, including test improvements suggested by Johannes. The current version is technically complete and ready for merging, with comprehensive test coverage in t4124 that verifies the behavior with different tab width settings.

In the final exchange, Johannes Sixt raised some thoughtful concerns about the practical utility of the check, noting that while occasionally useful, tabs mistakenly used as spaces are relatively rare compared to other whitespace issues. He also pointed out potential false positives in tables where tabs are deliberately used for column alignment. While these comments don't block merging (the implementation correctly handles these cases), they provide valuable context for future decisions about where to enable this check via .gitattributes.

With all technical boxes checked and no outstanding objections, this series appears ready for Junio to pick up in the next integration cycle. The discussion has been productive, with Adrian responsive to feedback and the reviewers providing constructive input that improved both the implementation and test coverage.
