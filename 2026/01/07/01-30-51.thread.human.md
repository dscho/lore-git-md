This thread concerns a new whitespace check for Git's AsciiDoc documentation files, proposed by Junio Hamano and implemented by Adrian Ratiu. The check detects when tabs appear between non-whitespace characters where spaces were likely meant (like mid-sentence), while preserving legitimate tab usage for indentation. The implementation tracks visual column positions to handle tab expansion widths correctly.

The discussion has progressed through two versions, with v2 incorporating Junio's initial feedback about highlighting and fixing capabilities. The remaining questions are minor: finalizing the rule's terminology (likely changing from "tab-between-non-ws" to "tab-instead-of-space") and improving test case presentation by using complete lines rather than fragments. Both Junio and Adrian agree on these refinements.

The feature integrates with Git's existing whitespace infrastructure, enabling automatic highlighting in diffs and fixing via `git apply`. It will be enabled by default for all .adoc files in the Documentation directory. With no technical objections remaining, this appears ready for merging once these last naming and testing polish items are addressed.
