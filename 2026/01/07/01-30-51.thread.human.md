This thread introduces a new whitespace check for documentation files, particularly targeting cases where tabs appear between non-whitespace characters when a space was likely intended. The feature was originally proposed by Junio Hamano and implemented by Adrian Ratiu, with the whitespace rule initially named `tab-between-non-ws` but now converging on `tab-instead-of-space` after naming feedback.

The implementation extends Git's existing whitespace infrastructure, tracking both character position and visual column position to properly handle tab expansion. It will be enabled by default for AsciiDoc files in the Documentation directory. The v2 patch addressed Junio's initial feedback about highlighting and fixing capabilities, and now Johannes Sixt has reviewed the tests, suggesting improvements to make them more robust and comprehensive.

All technical aspects appear settled, with the discussion focused on final polish: confirming the rule naming, improving test presentation (including using proper negative test syntax and possibly reorganizing some cases), and clarifying configuration defaults. The feature will help maintain documentation quality as part of broader efforts like Jean-Noël Avila's synopsis-style conversion work. With no outstanding technical concerns, this appears ready for finalization once the test improvements are addressed.
