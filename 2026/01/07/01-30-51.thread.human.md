This thread concerns a new whitespace check for documentation files, originally called `tab-between-non-ws` but now being renamed to "tab-instead-of-space" per Junio Hamano's suggestion. Adrian Ratiu is implementing the change to detect when tabs appear between non-whitespace characters in .adoc files where spaces were likely meant, while preserving legitimate tab usage for indentation. The check will be enabled by default for documentation files via .gitattributes.

The patch has gone through three iterations with constructive feedback from both Junio and Johannes Sixt. The core implementation is settled, involving modifications to ws.c to track character positions and visual columns, plus tab highlighting in diff output. Current discussion focuses on final test improvements suggested by Johannes - including using test_config for temporary changes, better test case organization, and clarifying the default tab width behavior. Adrian has accepted these suggestions and will incorporate them in the next version.

With no remaining technical objections, the patch appears ready for merging once these final test refinements are complete. This work fits into the broader effort to improve documentation quality, complementing Jean-Noël Avila's synopsis-style conversion work. The collaborative review process has helped shape a focused, well-considered addition to Git's whitespace checking capabilities.
