Feature patch in the submodule gitdir path encoding series (10/11). This patch adds a final fallback mechanism for submodule gitdir path resolution by hashing the submodule name when all other conflict avoidance strategies fail. It's part of the larger effort to enable configurable submodule paths through the `extensions.submodulePathConfig` extension.

The implementation introduces a hashing step (case 2.4) that kicks in after the previous attempts (plain name, encoded name, numbered variants) have been exhausted. The hash is computed using Git's object hashing algorithm to ensure consistency with other parts of the system. While this loses human readability of the path, it provides a reliable last-resort solution for pathological naming conflicts.

The accompanying test demonstrates the fallback in action by creating a scenario with numerous conflicting submodule names (including case variants and encoded names) until the hashing mechanism is triggered for an uppercase "Foo" submodule. The test verifies all intermediate paths resolve correctly before reaching the hashed fallback.

This patch maintains the series' architectural approach of centralized path resolution through `submodule_name_to_gitdir()` while adding the final safety net. The implementation is clean and follows the established pattern, with thorough test coverage that exercises the edge case being addressed.
