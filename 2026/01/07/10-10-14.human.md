This is the sixth patch in Patrick Steinhardt's v8 series introducing the new `git history` command, a feature aimed at providing more intuitive history rewriting capabilities compared to `git rebase`. The patch adds the basic scaffolding for the command while the actual functionality will come in subsequent patches.

The patch creates the new `git-history` command with minimal initial implementation - just enough to handle basic argument parsing and show usage. It adds the command to all the necessary build systems (Makefile, meson.build), documentation (including a new man page stub), and includes a simple test verifying the command doesn't crash with no arguments and rejects unknown arguments.

The accompanying documentation positions `git history` as an experimental alternative to `git rebase` that can work in bare repositories and automatically updates descendant branches, while being more opinionated and simpler to use. Key limitations noted are no merge support and no handling of merge conflicts.

As part of a larger series that has seen extensive discussion, this infrastructure patch is straightforward and uncontroversial - it just sets up the framework for the actual history rewriting commands that will follow. The thread context shows the series has already addressed many design questions around scope and performance, with remaining open questions focused on stacked branch workflows and hook execution.
