Test patch adding HTTP authentication scenarios for .netrc files.

This is the third version of a test-only patch that adds coverage for HTTP authentication using .netrc files, specifically handling 401 (Unauthorized) and 403 (Forbidden) responses. The patch builds on previous iterations that were reviewed by Junio C Hamano, incorporating all his feedback about test suite conventions and adding more detailed commit message explaining the test coverage.

The patch introduces three new test cases in t5550-http-fetch-dumb.sh that verify different authentication scenarios when using .netrc files: successful cloning with valid credentials, handling of invalid credentials (401 response with credential prompt), and rejection of valid-but-forbidden credentials (403 response with no retry). The tests use new helper functions set_netrc() and clear_netrc() in t/lib-httpd.sh to manage .netrc files during testing, and modify the Apache test configuration to support the 403 scenario.

The implementation appears solid, with proper test cleanup via test_when_finished and clear error checking. While there's an ongoing discussion about the future of .netrc support in Git (hinted at by Junio's earlier comments and brian m. carlson's suggestion to deprecate it), this patch remains narrowly focused on testing current behavior. The test infrastructure changes are well-contained and the commit message now clearly explains what gaps these tests are filling. This looks ready for inclusion pending any final minor tweaks Junio might request.
