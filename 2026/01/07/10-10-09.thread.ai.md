[PATCH v8 1/7] replay: extract core replay logic into replay_revisions()

This is the eighth iteration of Patrick Steinhardt's series to refactor the replay functionality into a library interface. The core change extracts the revision-walking and commit-replaying logic from builtin/replay.c into a new replay_revisions() function that will eventually live in libgit.

The function takes three main inputs: a repository struct, rev_info for revision walking parameters, and a new options struct that encapsulates the --onto and --advance command-line parameters. Results are returned in a ref_updates struct that records the new commit hashes and their intended ref destinations.

Implementation details:
- The commit replay loop and ref update generation are moved verbatim from the original command implementation
- New structs (replay_opts, replay_ref_update) cleanly separate parameters from results
- Current limitations (FIXMEs remain for root/merge commit handling) are preserved
- All existing test coverage continues to pass unchanged

This is a pure refactoring with no behavior changes. The patch touches builtin/replay.c and introduces new types in replay.h, but leaves the command's user-facing behavior identical. The changes are part of a longer-term effort to make Git's revision control operations available as library functions, following Patrick's ongoing work on abstracting core subsystems.

Series context:
- Builds on prior versions reviewed by Junio Hamano, Christian Couder, and others
- Follows established patterns from Patrick's previous refactorings of core components
- Remaining work in the series will move this function into libgit proper and expose it through the library interface
