This is a documentation patch (specifically whitespace checking for .adoc files) that's part of an ongoing effort to improve Git's whitespace handling. The patch series introduces a new whitespace rule to detect when tabs are mistakenly used where spaces were intended in documentation files, particularly in AsciiDoc (.adoc) format.

The current discussion focuses on final naming and test presentation refinements. Junio Hamano suggested renaming the whitespace rule from "tab-between-non-ws" to something more descriptive like "tab-instead-of-space", which Adrian Ratiu agrees with. There's also agreement to improve the test cases by using complete lines with newlines rather than the current partial-line tests.

The technical implementation involves tracking both character position and visual column position to determine when a tab would visually appear as a single space (at specific column positions like the 7th column). The check is enabled by default for Documentation/**/*.adoc files via .gitattributes and integrates with Git's existing whitespace infrastructure for highlighting and fixing.

This appears to be a well-considered addition to Git's documentation tooling, with the discussion now focused on final polish rather than substantive changes. The patch builds carefully on existing whitespace checking infrastructure and addresses a real pain point in documentation maintenance.
