This is a refactoring patch in Patrick Steinhardt's v8 series introducing the `git history` command. The patch adds infrastructure to support the upcoming `split` subcommand by exposing tree diff functionality through the working tree status machinery.

The change introduces `wt_status_collect_changes_trees()`, which diffs two arbitrary trees and formats the results using the same callback mechanism that `git status` uses for working tree changes. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic that already exists in the codebase.

The implementation is straightforward - it sets up a diff between two tree objects using the same rename detection and formatting options that would be used for working tree status. This will be used by the `split` subcommand to show changes between tree states during history editing operations.

As part of the larger `git history` effort, this mechanical change helps enable more sophisticated history operations while maintaining code reuse. The patch appears well-contained and follows established patterns, though its real value will become clearer when the `split` subcommand that uses it is introduced in a later patch.
