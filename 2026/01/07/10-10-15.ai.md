Feature implementation for `git history reword` subcommand, part of Patrick Steinhardt's ongoing history editing series. This patch introduces the first concrete subcommand for the experimental `git history` tool, implementing commit message rewriting functionality. The `reword` subcommand allows editing a single commit's message while maintaining all other commit metadata, similar to an interactive rebase's reword action but with key differences: it operates in-memory without checking out files, doesn't execute hooks, and by default updates all local branches containing the commit.

The implementation builds on Git's replay infrastructure rather than the sequencer, enabling faster operation and working tree independence. It includes:
- Core reword logic that preserves authorship and tree while editing messages
- Reference update handling with three modes (update all branches, just HEAD, or print updates)
- Comprehensive test coverage of basic usage, edge cases, and bare repository support
- Documentation of the new subcommand and its `--ref-action` option

The patch follows the scaffolding established in earlier series patches, completing the initial implementation while leaving some design questions open (like hook execution policy and stacked branch workflow implications). It represents a significant step toward providing an alternative history editing interface that complements rather than replaces rebase.
