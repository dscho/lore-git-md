This is a bugfix patch in the submodule gitdir path encoding series, addressing case-folding filesystem collisions. The patch adds detection and prevention of case conflicts when `extensions.submodulePathConfig` is enabled, using stricter URI encoding for uppercase characters only when necessary.

The key changes introduce:
1. A new `is_casefolding_rfc3986_unreserved()` helper that treats uppercase as reserved (forcing percent-encoding)
2. Case-folding conflict detection via `check_casefolding_conflict()`
3. A fallback mechanism that tries encoded paths first, then falls back to numbered variants if conflicts exist
4. Comprehensive tests demonstrating the collision prevention behavior

The implementation maintains backward compatibility while adding protection for case-insensitive filesystems. When conflicts are detected, the patch automatically applies stricter encoding or appends digits to create unique paths. The test cases show this working with various combinations of uppercase, lowercase, and encoded submodule names.

This is patch 9/11 in a series that has already received Junio Hamano's ack for merging. The series as a whole implements runtime configuration of submodule gitdir paths to prevent filesystem conflicts and enable custom layouts. This particular patch addresses one of the final edge cases - case-folding collisions - in a way that minimizes impact on case-sensitive filesystems.
