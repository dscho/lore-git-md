This is part 6 of a 9-patch series enhancing Git's promisor remote functionality, focusing on implementing the `--filter=auto` mode infrastructure. The patch adds core support for the new filter mode while maintaining strict validation rules.

The changes introduce an `allow_auto_filter` flag in `struct list_objects_filter_options` to control which commands can accept the "auto" filter spec. The parsing logic in `gently_parse_list_objects_filter()` is updated to handle the new mode while enforcing that "auto" cannot be combined with other filters. The patch also adds a new `LOFC_AUTO` choice in the filter options enum, though using it directly for filtering would trigger a BUG() since it must be resolved to a concrete filter first.

Patrick Steinhardt provides review feedback on several implementation details: suggests adjusting indentation in an error message, recommends using `goto cleanup` consistently in the subfilter parsing logic, and questions the need to preserve `allow_auto_filter` across filter releases. He also notes the function's name doesn't match its clearing semantics, though considers this out of scope for the current series. The changes build on previous refactoring work (patches 3-5) that moved filter options handling away from global state, and will be used by subsequent patches (7-9) that implement the full auto-filter behavior combining server-advertised filters.
