This is a feature patch in the ongoing LOP (Large Object Promisors) effort, specifically addressing the `--filter=auto` implementation in fetch-pack. Patrick Steinhardt provides review feedback on patch 9/9 of the series, which wires up the auto-filter logic for clone/fetch operations.

The patch enables automatic filter specification by combining server-advertised filters from accepted promisor remotes. Patrick raises two key points: First, he questions whether locally configured promisor filters should also be considered in the auto-filter case, suggesting the behavior might need clarification in the documentation. Second, he critiques the error handling pattern in `promisor_remote_construct_filter()`, suggesting a more conventional error code return approach would be better than checking an error buffer's length.

The changes touch several key files including `fetch-pack.c`, `builtin/clone.c`, and `builtin/fetch.c`, with documentation updates in `fetch-options.adoc`. The implementation builds on previous patches in the series that introduced filter combination infrastructure and promisor remote configuration handling. Patrick's feedback indicates the technical approach is sound but could benefit from some interface refinements.
