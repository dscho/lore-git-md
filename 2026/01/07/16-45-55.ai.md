This is a bugfix patch that adds PID tracking for Git lock files to help diagnose stale locks. The patch implements companion PID files (named with a `~pid` infix) that record which process holds each lock, with configurable behavior via `core.lockfilePid`.

Key technical details:
- PID files use `~pid.lock` naming (e.g. `index~pid.lock`) to avoid refname collisions
- Files contain a single `pid <value>` line
- Configuration is now a simple boolean (`core.lockfilePid`) rather than per-component
- Windows support via `mingw_kill()` updates
- Comprehensive 139-line test suite in t0031
- Automatic cleanup of PID files when locks are released

The implementation handles stale lock detection by checking if the recorded PID is still running, providing context-aware error messages. The patch has gone through multiple iterations with input from Jeff King and Patrick Steinhardt, who helped simplify the configuration interface.

This appears production-ready with thorough test coverage and cross-platform support. The main open question from Junio's review was documentation accuracy, which has been addressed in this version. The solution provides clear benefits for debugging lock contention while maintaining backward compatibility.
