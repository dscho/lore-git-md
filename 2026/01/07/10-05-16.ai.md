This is part 2 of a 9-patch series introducing new promisor remote functionality. The patch adds a `promisor.storeFields` config option that allows clients to store specific fields (like authentication tokens and filter specs) from server-advertised promisor remotes into their local configuration. This enables secure token rotation and dynamic filter updates without manual client-side reconfiguration.

The implementation validates stored fields (checking filter syntax and rejecting control characters in tokens) and emits warnings when configuration changes occur. The changes are focused in `promisor-remote.c` with corresponding test additions in `t5710-promisor-remote-capability.sh`. Patrick Steinhardt raises several technical points in review: suggesting naming convention fixes (`store_info_new` vs `new_store_info`), questioning the worktree config storage choice, and noting missing test coverage for subsequent fetch operations updating the config.

The patch builds on previous work that allowed servers to advertise additional promisor remote fields and clients to check them. It's part of the broader LOP (Large Object Promisors) effort to improve promisor remote functionality. The implementation appears thorough with attention to security (token validation) and backward compatibility, though some design choices around config storage and naming may warrant discussion.
