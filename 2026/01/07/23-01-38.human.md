This is part of a feature series introducing a new submodule gitdir path configuration system via the `extensions.submodulePathConfig` extension. Patch 4/11 in the v8 series, which has been acked by Junio Hamano for merging, implements the core extension infrastructure.

The patch adds a new repository extension that makes `submodule.<name>.gitdir` the single source of truth for submodule gitdir paths when enabled. This solves filesystem conflicts that arise with case-insensitive systems or nested submodule names. The extension automatically sets gitdir configs for new submodules, while existing ones must be manually migrated by setting their gitdir paths (e.g. `git config submodule.foo.gitdir .git/modules/foo`).

Key technical changes include:
- New `repository_format_submodule_path_cfg` flag in repository structs
- Extension handling in `setup.c` and repository initialization
- Automatic gitdir config creation during submodule init/add
- Validation and fallback logic in `submodule_name_to_gitdir()`
- Comprehensive tests covering migration, relative paths, and mixed extension/non-extension clones

The implementation maintains backward compatibility while providing a clean path forward for users needing more flexible submodule layouts. The series has undergone extensive review, with this patch addressing all remaining feedback from v7. It's now ready for merging as part of the complete solution to submodule path conflicts.
