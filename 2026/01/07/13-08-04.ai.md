This is patch 5/7 in Patrick Steinhardt's v4 series refactoring object info handling as part of the ODB abstraction effort. The patch simplifies the return value of `packed_object_info()` to just indicate success/failure rather than also encoding object type information, since no callers need that dual-purpose return value anymore.

The change makes the interface cleaner by removing the overloaded return value that previously could indicate either an object type or an error. Now it consistently returns 0 for success or a negative error code. This also enables a future optimization where the object type parsing can be skipped entirely when not needed.

The implementation updates all error paths to use the new error return convention and adjusts the single caller in `packfile_store_read_object_info()` to match. The patch includes documentation clarifying the new simpler contract in `packfile.h`.

This is a straightforward mechanical change that follows naturally from the previous patch's removal of the last caller that needed the object type return value. The series has already received thorough review from Karthik Nayak and others, with all feedback addressed in prior iterations. This patch appears ready for integration as part of the larger ODB abstraction work.
