This is part 2 of a 9-patch series enhancing Git's promisor remote functionality, focusing on allowing clients to store specific fields from server-advertised promisor remotes. The patch introduces a new `promisor.storeFields` config option that lets clients automatically store certain fields (currently supporting `partialCloneFilter` and `token`) from promisor remotes into their local configuration.

The key use case is enabling secure token rotation and filter updates - when a server advertises new values for these fields, clients can automatically update their config rather than requiring manual updates. The implementation includes validation checks (ensuring filters parse correctly and tokens don't contain control characters) and emits warnings when config changes occur.

Patrick Steinhardt raises several technical points in his review: questioning whether the storage should be in worktree vs local config, suggesting naming convention fixes (`store_info_new` vs `new_store_info`), and noting missing test coverage for subsequent fetch operations. He also asks whether automatic configuration of new promisor remotes (as opposed to just updating existing ones) will be handled in a future series.

This is a well-structured patch that builds logically on previous work in the series, with clear motivation and thorough validation. The review feedback suggests some implementation refinements but doesn't challenge the core approach. As part of the larger LOP (Large Object Promisors) effort, this contributes important infrastructure for dynamic promisor remote configuration.
