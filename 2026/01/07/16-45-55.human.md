This is a bugfix patch that adds PID tracking for Git lockfiles to help diagnose stale locks. The patch is the fourth iteration (v4) of a series that has seen significant discussion on the mailing list.

The key changes in this version simplify the configuration from a per-component granularity (like core.fsync) to a simple boolean core.lockfilePid setting, as suggested by Jeff King and Patrick Steinhardt. When enabled, Git will create companion PID files (named with a ~pid.lock suffix) alongside lockfiles, containing the process ID of the lock holder. This helps identify stale locks left by crashed processes.

The implementation handles cleanup via tempfile registration, works cross-platform (including Windows), and provides helpful error messages when lock conflicts occur. A comprehensive test suite (t0031) verifies the behavior. The patch also includes Windows-specific fixes for process detection via mingw_kill().

The thread context shows this has been through several rounds of review, with consensus forming around the simplified boolean configuration approach. Junio Hamano identified some final documentation and error handling refinements needed before merging. The solution appears production-ready with safe namespace separation, cross-platform support, and backward compatibility.
