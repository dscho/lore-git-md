This is the final patch in Patrick Steinhardt's v8 series introducing the new `git history` command, specifically implementing the "reword" subcommand. The patch builds on Git's replay infrastructure to provide a faster, in-memory alternative to interactive rebase for editing commit messages.

The "reword" subcommand allows modifying a single commit's message without checking out the commit, working even with dirty working trees. Key features include:
- Operates purely in-memory for better performance
- Updates all local branches containing the rewritten commit by default
- Supports bare repositories
- Provides `--ref-action` option to control which references get updated (branches, HEAD, or just print the updates)

The implementation includes thorough test coverage of various scenarios: rewording tips, middle commits, root commits, merge commits, and branch handling. Notable limitations include no hook execution (though the design leaves room for future addition) and no support for rewriting merge commits embedded in history (only direct merge commits can be reworded).

This represents a significant addition to Git's history editing capabilities, particularly useful for stacked branch workflows where multiple branches share common commits. The implementation is careful to maintain existing behavior where appropriate while introducing new functionality through the experimental `git history` command.
