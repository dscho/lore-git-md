This is part 8/11 of a feature series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series introduces a new `extensions.submodulePathConfig` extension that enables URL-encoding of submodule gitdir paths when needed to avoid collisions.

This specific patch adds the core path encoding functionality using RFC3986 encoding (via the relocated `is_rfc3986_unreserved()` helper from `url.[ch]`). It implements a three-step fallback for gitdir path resolution: first trying the unencoded path, then the encoded version if that fails, and finally erroring out if neither works. The patch includes tests verifying the encoding handles nested submodule paths correctly, including parallel cloning scenarios.

Key technical details:
- New `validate_submodule_encoded_git_dir()` function for path validation when the extension is enabled
- Maintains backward compatibility via `validate_submodule_legacy_git_dir()`
- Tests demonstrate the encoding prevents collisions between paths like `hippo` and `hippo/hooks`
- Shows the extension can be toggled to control whether encoding is required

The implementation follows the design agreed upon in earlier discussion, with Junio Hamano and Patrick Steinhardt having signed off on the approach. The patch appears well-tested and integrates cleanly with the series' overall architecture of centralized path resolution through `submodule_name_to_gitdir()`.
