This is a refactoring patch in Patrick Steinhardt's v8 series introducing the `git history` command. The patch adds infrastructure to support the upcoming `split` subcommand by exposing tree diff functionality from the working tree status machinery.

The patch introduces `wt_status_collect_changes_trees()`, which diffs two arbitrary trees and formats the changes as if they were staged in the index. This will be used by the `split` subcommand to show changes between trees without requiring a working tree or index. The implementation reuses existing diff callbacks from the working tree status code while generalizing them to work with any tree pair.

Key technical details:
- New function in `wt-status.c` that wraps the diff machinery with working-tree-status formatting
- Takes two tree OIDs as input and populates a `wt_status` struct with the changes
- Reuses the existing `wt_status_collect_updated_cb` callback for consistent output
- Maintains all existing diff options (rename detection, recursive behavior)
- Header declaration in `wt-status.h` documents the tree-to-tree comparison behavior

This is a mechanical change that doesn't affect functionality yet - the function will be used by a subsequent patch in the series. It continues the pattern of building on Git's existing infrastructure (here the working tree status and diff machinery) rather than introducing new standalone components.
