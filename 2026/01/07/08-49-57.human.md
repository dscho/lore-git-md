This is a UI improvement patch for `git add -p`, part of Abraham Samuel Adekunle's GSoC project (now at v6). The patch adds visual feedback showing whether each hunk was previously marked for use ('y') or skip ('n') when navigating between hunks, addressing Junio Hamano's earlier feedback about unclear terminology.

The current discussion focuses on finding the most compact yet clear way to display this information without exceeding the 80-column convention. Abraham proposes several variations like "(choice: use)", "(you chose yes)", and the very compact "(was: y)". The thread shows active collaboration between Phillip Wood (a sequencer expert), Ben Knoble, and the author to refine the prompt display.

The implementation remains contained within interactive add-patch UI without altering core behavior, with full test coverage maintained. Junio has weighed in emphasizing the need to balance functionality with minimal UI impact, though hasn't prescribed a specific solution. The patch appears well-considered and addresses a real usability pain point in the interactive staging workflow.
