This is a follow-up in the ongoing performance investigation of `git pack-refs --all` slowness on NFS storage with large repositories (~3M refs). Martin Fick provides the specific NFS mount options used in their Gerrit server environment, which include standard performance-oriented settings like larger rsize/wsize (32KB) and TCP transport. The thread has already established that mmap'd packfile access is the primary bottleneck, with Patrick Steinhardt advocating for moving to the reftable backend rather than optimizing the current files backend. Martin's confirmation of the NFS configuration helps rule out unusual mount options as a contributing factor to the observed slowness. The discussion remains technically focused, with clear evidence pointing to mmap/NFS interaction as the root cause.
