This is a performance investigation thread about `git pack-refs --all` slowness on NFS with high ref counts. Martin Fick provides additional technical details about their NFS mount configuration in response to Patrick Steinhardt's query. The mount flags shown (rw,intr,retrans=10,timeo=600,hard,rsize=32768,wsize=32768,tcp,noacl,_netdev) are fairly standard for NFSv3 setups, with 32KB read/write sizes and TCP transport. 

The thread has already established that mmap'd packfile access is the bottleneck in this Gerrit server environment with ~3M refs, where `git pack-refs` takes 5+ minutes compared to JGit's 20s. Martin's previous testing showed pre-reading the pack file reduces runtime dramatically, confirming the mmap/NFS interaction as the core issue. 

Patrick Steinhardt has been steering the discussion toward adopting the reftable backend as the long-term solution rather than optimizing the files backend further. This latest exchange provides useful context about the production environment's NFS configuration, though it doesn't change the fundamental technical understanding of the problem. The thread remains focused on choosing between short-term workarounds (like NO_MMAP builds) versus architectural shift to reftable.
