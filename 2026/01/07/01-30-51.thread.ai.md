Thread identity: Patch series introducing new whitespace check for documentation files (originally named `tab-between-non-ws`), authored by Adrian Ratiu, with Junio Hamano providing naming and testing feedback.

Core problem/goal: Detect and optionally fix cases where tabs appear between non-whitespace characters in documentation (particularly .adoc files) where a space was likely intended, while preserving legitimate tab usage for indentation/alignment. Requires accounting for tab expansion width to determine when a tab would visually appear as a single space.

Current status: v2 of patch incorporating Junio's initial feedback about highlighting and fixing capabilities. Discussion has converged on renaming the whitespace rule to "tab-instead-of-space" and improving test presentation with complete lines including newlines.

Key technical details:
- New WS_TAB_BETWEEN_NON_WS flag in ws.h (name being finalized as "tab-instead-of-space")
- Core logic in ws.c tracks character position and visual column position
- emit_middle_section() modified for tab highlighting
- Enabled by default for Documentation/**/*.adoc via .gitattributes
- Test cases being updated to use complete lines with newlines
- Supports git diff highlighting and git apply --whitespace=fix

Open questions and loose ends:
