This is part 5 of an 11-patch series implementing runtime configuration for submodule gitdir paths via the new `extensions.submodulePathConfig` extension. The series has been through multiple rounds of review and is now in its final form, with Junio Hamano having acked it for merging.

The patch adds a new configuration option `init.defaultSubmodulePathConfig` that allows enabling the submodule path extension by default for new repositories (those created via `git init` or `git clone`). Importantly, this only affects new repositories - existing ones still require explicit migration. The implementation adds the config handling in `setup.c` and includes comprehensive tests verifying the behavior with various combinations of `init`, `clone`, and submodule operations.

Key technical details:
- The new config is checked during repository initialization in `initialize_repository_version()`
- When enabled, it sets `extensions.submodulePathConfig` to true and ensures the repository format version is at least 1
- Tests cover both direct initialization and cloning scenarios, including recursive submodule handling
- The change maintains backward compatibility while providing a migration path for new repositories

This is a well-tested addition to the larger submodule path encoding effort, with clear documentation and thorough test coverage. The patch follows the series' architectural approach of centralized path resolution while providing a smooth configuration path for adopters of the new extension.
