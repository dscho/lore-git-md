This is a documentation-focused whitespace checking patch, part of an ongoing effort to improve documentation formatting. Adrian Ratiu is implementing a new check to catch tabs that appear between non-whitespace characters in documentation files (particularly .adoc files) where a space was likely intended, while preserving legitimate tab usage for indentation.

The patch is now in its third iteration, with Johannes Sixt providing detailed test improvement suggestions. Key changes in this version include renaming the whitespace rule from "tab-between-non-ws" to "tab-instead-of-space" (per Junio Hamano's earlier suggestion) and refining the test cases. Johannes' review focused on test quality improvements: using test_config for temporary config changes, more comprehensive test patterns, and possibly relocating some tests to t4124.

The implementation tracks both character position and visual column position to determine when a tab would visually appear as a single space (accounting for tab expansion width). The check is enabled by default for Documentation/**/*.adoc via .gitattributes. The patch appears well-considered and addresses a real documentation quality issue, with the discussion now focused on final polishing of the test coverage.
