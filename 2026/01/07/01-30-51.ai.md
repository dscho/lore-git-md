Feature: New whitespace check for tabs between non-whitespace characters

This patch introduces a new whitespace check called `tab-between-non-ws` that detects when a tab appears between two non-whitespace characters where a space was likely intended. The check is particularly useful for documentation files where such tabs can cause formatting issues. The implementation is non-trivial because it needs to account for tab expansion width to determine when a tab would visually appear identical to a single space.

The patch comes from Adrian Ratiu in response to a suggestion by Junio Hamano. It includes comprehensive test coverage in t4015-diff-whitespace.sh that verifies the new check works with different tabwidth settings and only flags tabs that would expand to a single space. The implementation also adds highlighting support for tools like `git diff` and `git apply --whitespace=fix` capability.

Key technical details:
- New WS_TAB_BETWEEN_NON_WS flag added to ws.h
- Core logic in ws.c tracks both character position and visual column position
- Special handling in emit_middle_section() for highlighting tabs
- Enabled by default for Documentation/**/*.adoc files via .gitattributes
- Includes extensive test cases covering various tab positions and widths

The patch appears well-considered with thorough test coverage and clear commit messages. It addresses a real formatting issue that can affect documentation readability while being careful not to flag tabs used for legitimate indentation or alignment. The v2 iteration incorporates Junio's feedback about highlighting and fixing capabilities.
