This is part 8 of an 11-patch series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series has been through extensive review and is now ready for merging, with Junio Hamano's ack.

The patch focuses on fixing filesystem collisions by URL-encoding gitdir paths when `extensions.submodulePathConfig` is enabled. It introduces a three-step fallback system for path resolution (plain name -> encoded name -> error) and adds validation for encoded paths. The implementation uses RFC3986 encoding via a relocated helper function from `url.[ch]`.

Key technical aspects:
- New `validate_submodule_encoded_git_dir()` function for path validation with encoding
- Maintains backward compatibility when the extension is disabled
- Adds comprehensive tests for nested submodules and parallel cloning scenarios
- Shows how enabling/disabling the extension affects behavior

The patch builds on design input from Junio Hamano and Patrick Steinhardt, with the encoding only applied when necessary to new submodules. Existing modules continue working without changes. The implementation is careful to maintain atomic operations and clear error messages.

This is a well-polished piece of a larger effort that has gone through multiple review iterations. The tests demonstrate real-world scenarios (including parallel operations) and verify both the happy path and edge cases. The patch fits cleanly into the series' overall architecture of centralized path resolution through `submodule_name_to_gitdir()`.
