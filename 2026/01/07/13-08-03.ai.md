This is part 4 of Patrick Steinhardt's 7-patch series refactoring Git's object info handling for the ODB abstraction effort. The patch ensures consistent population of pack-specific fields when reading object information, eliminating a discrepancy between two code paths that could lead to different object info states.

The change makes `packed_object_info()` always populate the pack-specific fields (offset, pack pointer, and delta type) rather than sometimes leaving them unset. This creates a more reliable invariant that callers can depend on - when an object comes from a pack, these fields will always be available. The patch removes the redundant field-setting from `packfile_store_read_object_info()` since the information is now guaranteed to be set earlier in the call chain.

This is a straightforward cleanup that improves interface consistency as part of the larger ODB abstraction work. The change has been reviewed and approved by Karthik Nayak (GitLab ODB team) with no outstanding concerns. The series as a whole is now ready for integration after multiple rounds of review addressing both technical and style feedback.
