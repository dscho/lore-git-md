This is a documentation patch (specifically about whitespace checking in AsciiDoc files) that's part of an ongoing effort to improve Git's handling of tabs in documentation. The patch series introduces a new whitespace rule to catch cases where tabs appear between non-whitespace characters when a space was likely intended, while preserving legitimate tab usage for indentation.

The current version (v2) incorporates feedback from Junio Hamano, who suggested the feature initially. The main discussion points now are about naming the new whitespace rule (with "tab-instead-of-space" emerging as the leading candidate) and improving test cases to use complete lines rather than incomplete ones. The technical implementation appears solid, building on Git's existing whitespace infrastructure.

Adrian Ratiu, the author, indicates he'll wait briefly for any alternative naming suggestions before sending a v3 with these refinements. The patch seems likely to proceed to merging once these final polish items are addressed, as Junio's feedback has been positive and no technical objections remain. This is a focused improvement that should help maintain consistency in Git's documentation formatting.
