This is a documentation whitespace checking patch that's part of an ongoing effort to improve consistency in Git's documentation formatting. Junio Hamano is providing feedback on v2 of Adrian Ratiu's patch that introduces a new whitespace check for tabs that should have been spaces in documentation files.

The core of this email focuses on naming and test case improvements. Junio suggests the current name "tab-between-non-ws" doesn't fully capture the intent - it's meant to catch tabs that were mistakenly used when a space was intended. He proposes alternatives like "tab-instead-of-space" that might better convey the check's purpose. 

Junio also notes the test cases use incomplete lines (without newlines) which could give the misleading impression that the check only applies to such cases. He suggests adding newlines to make the tests more representative of typical documentation content.

The patch appears technically sound and well-tested, with Junio's feedback focusing on polish rather than fundamental issues.
