Feature implementation for the new `git-history` command's `reword` subcommand, completing Patrick Steinhardt's v11 series. This patch adds the user-facing functionality for rewriting commit messages in-memory without checking out files, building on the replay infrastructure introduced earlier in the series.

The `reword` subcommand provides a faster alternative to interactive rebase for changing commit messages, with key differences:
- Operates entirely in-memory without touching the working tree
- Updates all local branches containing the rewritten commit by default
- Supports three reference update modes via `--ref-action` (branches|head|print)
- Includes 391 lines of test coverage across various scenarios

The implementation handles edge cases like:
- Detached HEAD states
- Root commits
- Merge commits (though replaying merges in history remains unsupported)
- Bare repositories
- Empty commit messages (which abort the operation)

Notable technical details:
- Uses the new `wt_status_collect_changes_trees()` from patch 6/8 for diff display
- Integrates with the `replay_revisions()` infrastructure moved to libgit.a in patch 2/8
- Follows Git's standard conflict reporting conventions (using `1` for conflicts)
- Includes comprehensive reference update logic for branches and detached HEAD
- Preserves working tree and index state during operation

The patch completes the series' goal of providing a performant history editing primitive while avoiding the working tree impact of traditional rebase. With Elijah Newren's final sign-off on the technical approach and all feedback addressed, this appears ready for maintainer evaluation.
