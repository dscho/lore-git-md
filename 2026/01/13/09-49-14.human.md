This is a follow-up in an ongoing discussion about a regression in pre-push hook behavior where hook output was unintentionally redirected from stdout to stderr. Adrian Ratiu responds to Chris Darroch's initial report about how this change broke Git LFS's test suite and existing workflows.

Adrian acknowledges the regression and agrees with brian m. carlson's earlier suggestion that reverting to the previous behavior would be best for now. He mentions this is exactly the kind of compatibility issue he warned about in his "Extending git without breaking it" presentation. While he suggests a future breaking change could standardize hook output to stderr, he emphasizes maintaining backward compatibility for now.

The response indicates Adrian will test the issue with his parallel work on config-based hooks (which this change was building towards) and verify the fix against Git LFS's test suite. This shows the discussion is moving towards a practical solution while being mindful of real-world impacts on tools like Git LFS that have relied on the old behavior since at least 2017. The tone remains constructive, focused on finding a resolution that doesn't break existing users while keeping the door open for future improvements.
