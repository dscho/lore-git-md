This is a review comment from Junio C Hamano on part 1 of Olamide Caleb Bello's RFC patch series to eliminate global configuration variables as part of the `the_repository` removal effort. The series moves config values into a new `struct repo_config_values` embedded in `struct repository`.

Junio raises an important architectural question about the scope of config variables - whether they should remain global (system/user-wide) or become repository-specific. He points to several other global variables in the same code region (whitespace handling, compression levels) that may need similar treatment, asking whether they are per-repository or truly system-wide settings.

The comment suggests Junio is evaluating whether the proposed approach of making *all* config values repository-scoped is appropriate, or if some should remain global. This touches on a key design decision for the series - the patch assumes these values should be repository-specific, but Junio is questioning that assumption for at least some of them.

This feedback could lead to a revision of the series' scope or approach, potentially requiring differentiation between repository-specific and truly global config values. The question implies the series may need to handle these cases differently rather than applying a uniform pattern to all config values.
