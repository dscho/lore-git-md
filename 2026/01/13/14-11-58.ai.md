This is a bugfix addressing a regression in Git's hook subsystem output handling, specifically for the pre-push hook. The patch follows up on Junio Hamano's confirmation that pre-push was historically the only hook that didn't divert stdout to stderr, validating the need for this special case.

Adrian Ratiu's patch introduces a `stdout_to_stderr` flag in the `run_hooks_opt` struct (defaulting to 1 for backward compatibility with most hooks) while explicitly setting it to 0 for pre-push hooks. The changes touch `hook.c`, `hook.h`, and `transport.c`, with the main logic being in `pick_next_hook()` where the stdout redirection behavior is now configurable.

Junio has reviewed and approved the approach after examining historical behavior through functions like `run_receive_hook()`. The discussion revealed gaps in test coverage for hook output behavior, which Adrian plans to address in a follow-up. The patch maintains the pre-push hook's special case while fixing the regression caused by recent hook API changes.

This is a focused fix that preserves backward compatibility while properly documenting the hook output behavior through the new configuration option. The solution has consensus from key participants including Junio, Patrick Steinhardt, and the original reporter Chris Darroch. The only remaining action is adding test coverage, which will be handled separately.
