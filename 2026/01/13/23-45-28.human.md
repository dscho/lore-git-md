This is a bugfix addressing a regression in Git's hook subsystem, specifically for the pre-push hook's output handling. The patch comes from Adrian Ratiu as version 2, incorporating feedback from Junio Hamano and Patrick Steinhardt.

The issue stems from a recent change that made all hooks redirect stdout to stderr by default, which broke the pre-push hook's special behavior of keeping these streams separate. Historical analysis confirmed pre-push was the only hook that needed this distinction. The fix adds a `stdout_to_stderr` flag to the hook API (defaulting to 1 for backward compatibility) while explicitly setting it to 0 for pre-push hooks.

The patch is thorough, adding comprehensive test coverage for all hook types to verify their output behavior matches expectations. It touches `hook.c`, `hook.h`, and `transport.c`, with the core change being a simple flag check in `pick_next_hook()`. The implementation looks clean and well-justified, with clear documentation of the special case for pre-push hooks.

This appears ready for merging - all participants (including Junio) have signed off on the approach, and the extensive new tests should prevent similar regressions. The patch maintains backward compatibility while properly formalizing the pre-push hook's unique requirements in the API.
