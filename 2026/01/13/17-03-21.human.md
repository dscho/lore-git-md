This is a follow-up discussion about the recently merged push-tracking feature in `git status`. Jeff King (Peff) raises a practical concern about the new behavior in triangular workflows where the push branch comparison may not always be useful.

Peff notes that while the feature works as designed (showing both upstream and push branch comparisons), in his specific workflow where he uses a mirror-like push destination, the push branch information is just noise. He points out two limitations of the current implementation:

1. The `status.aheadbehind` config disables both upstream and push comparisons, when he only wants to suppress the push branch info
2. The same comparison appears in `git checkout` output without any way to disable it

This isn't proposing a change to the feature itself, but rather identifying a real-world use case where the current behavior may be suboptimal. The thread appears to be just starting, so we may see responses from the feature author (Harald Nordgren) or others about whether this warrants a follow-up patch to make the display more configurable.

The feature itself remains well-implemented and thoroughly tested as noted in the thread summary, but this highlights how even carefully designed features can have unexpected interactions with different workflow patterns.
