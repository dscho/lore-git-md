This is part of Patrick Steinhardt's ongoing `git-history` feature series, now at version 10. The thread has reached consensus on most technical points, with this patch focusing on extracting core replay logic into a library function.

The patch moves 369 lines of replay logic from `builtin/replay.c` to `libgit.a`, creating a new `replay_revisions()` function that takes only a `revs` parameter. It also addresses Elijah Newren's feedback about error handling - changing conflict return codes from `-1` to `1` to match Git's merge machinery, though Patrick initially preferred the negative value for clearer error distinction. The patch drops an unused `merge_conflict` field that was intended for future use.

Notably, Patrick defers on some suggested cleanup of option validation logic, considering it out of scope for this series. The changes appear well-contained and maintain compatibility with the existing replay infrastructure while preparing for future `git-history` functionality. With Newren's technical sign-off on the approach, this foundational piece seems ready for integration.
