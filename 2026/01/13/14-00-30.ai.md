This is a bugfix patch addressing a regression in Git's hook subsystem output handling, specifically for the pre-push hook. The patch comes from Junio C Hamano in response to Adrian Ratiu's proposed fix.

The issue stems from a recent change that made all hooks redirect stdout to stderr by default, which broke the pre-push hook's ability to use the streams separately. The patch makes this behavior configurable via a new `stdout_to_stderr` flag in `run_hooks_opt`, defaulting to 1 (maintaining backward compatibility for most hooks) while explicitly setting it to 0 for pre-push hooks.

Junio confirms this appears to be a proper regression fix, noting that pre-push was indeed the only hook that previously didn't divert stdout to stderr. He validates this by examining the history of changes around the hook API conversion. The patch maintains the special case for pre-push hooks while enforcing consistent behavior for other hooks, which Junio agrees is the right approach to avoid breaking existing pre-push hook implementations.

The change touches `hook.c`, `hook.h`, and `transport.c`, adding the new configuration option and applying it to the pre-push hook case. This is part of ongoing work on the hook subsystem, though not directly tied to Adrian Ratiu's larger hook configuration efforts. The discussion revealed gaps in test coverage for hook output behavior that allowed this regression to slip through.
