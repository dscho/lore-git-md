This is a bugfix patch in the v11 series introducing the `git-history` command, specifically addressing empty commit range handling in the replay subsystem. The patch fixes an edge case where initializing `struct merge_result` with zeros would incorrectly indicate a merge conflict when replaying an empty commit range (which can occur when the starting commit has no descendants).

The change initializes the `.clean` flag to `1` by default, correctly indicating no conflicts when no actual merging occurs. This prepares the infrastructure for future users of the replay subsystem that may legitimately process empty ranges, though the current `git-replay` command still doesn't use this case. The fix is small (3 lines changed) but important for the subsystem's robustness.

The patch has already been reviewed by Elijah Newren, who provided the commit message clarification about branch tip handling, and carries his sign-off. It's part of the larger effort to extract core replay logic into a reusable library while continuing the `the_repository` removal work. With all technical feedback addressed in this series, this patch represents one of the final refinements before potential merging.
