This is a bugfix for HTTP authentication in `remote-curl.c`, specifically addressing an issue where `probe_rpc()` requests during clone operations weren't including authentication headers when bearer tokens were used. The patch comes from Patrick Steinhardt in response to Aaron Plattner's initial report.

The core issue occurs when cloning large repositories with blob filters - if the request exceeds `http.postBuffer`, the `probe_rpc()` call fails with 401 errors because it wasn't propagating the authentication headers, despite the main request having successfully authenticated. This particularly affects bearer token authentication flows.

The fix is minimal (just adding `http_append_auth_header()` to `probe_rpc()`) but comes with thorough test coverage. The test creates a repository with 2000 refs to force large requests, configures a small `http.postBuffer` to trigger `probe_rpc()`, and uses `git-credential-msal` for bearer token auth testing. Patrick confirms the test fails without the fix and passes with it.

Patrick suggests two minor test improvements (removing redundant directory cleanup and inlining setup) but indicates the patch is already solid. Given the narrow scope, good test coverage, and Patrick's approval (as a major contributor familiar with the HTTP transport layer), this fix is likely to be accepted unless other HTTP experts spot issues. The patch cleanly addresses a real-world authentication edge case in a maintainable way.
