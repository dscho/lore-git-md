This is a bugfix targeting the HTTP authentication handling in `remote-curl.c`. The patch addresses an issue where `probe_rpc()` requests (used when large requests exceed `http.postBuffer`) fail to include authentication headers, causing 401 errors during clone operations with bearer tokens.

The problem manifests when cloning large repositories with blob filters - the initial authentication succeeds for the main request, but the subsequent `probe_rpc()` call fails due to missing auth headers. The patch fixes this by adding `http_append_auth_header()` to `probe_rpc()`.

The commit includes a detailed reproduction scenario using `git-credential-msal` and adds a test case that:
1. Creates a repository with 2000 refs to force large requests
2. Configures a small `http.postBuffer` to trigger `probe_rpc()`
3. Verifies successful clone with bearer auth

The fix is straightforward - just two lines adding the auth header call.
The test coverage is thorough, exercising both the failure case and the fix.
This appears to be a real issue affecting users of bearer token authentication with large repositories.
