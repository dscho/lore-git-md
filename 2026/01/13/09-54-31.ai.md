This is the v11 iteration of Patrick Steinhardt's feature series introducing a new `git history` command, focused on implementing the `reword` subcommand for commit message editing. The series builds on Git's replay machinery and represents a significant architectural refactoring to support in-memory operations and library integration.

The v11 changes address final technical feedback from Elijah Newren and Junio Hamano, including:
- Fixing an overly clever `BUG()` condition
- Removing the now-unnecessary `merge_conflict` field from `struct replay_result`
- Standardizing conflict reporting to return `1` (matching Git's merge machinery conventions)
- Improving a commit message about empty commit range handling
- Fixing argument validation in `setup_revisions_from_strvec()`

The series now:
- Moves core replay logic into libgit.a (369 lines relocated)
- Adds full detached HEAD support with expanded test coverage
- Introduces `wt_status_collect_changes_trees()` for tree-to-tree diffs
- Implements the `reword` subcommand with 391 lines of test coverage
- Handles empty commit ranges properly
- Standardizes conflict reporting to match Git conventions

With all technical feedback addressed and no outstanding objections, this appears ready for maintainer evaluation. The implementation is technically sound, well-tested, and builds on existing replay infrastructure while preparing for future history editing commands. The changes are focused and incremental, with the controversial `split` subcommand deferred to a follow-up series.
