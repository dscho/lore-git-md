Feature: Implementation of `git history reword` subcommand for in-memory commit message editing

This is the final patch in Patrick Steinhardt's 8-part series introducing the new `git history` command, specifically implementing the `reword` subcommand. The command allows rewriting commit messages without checking out the commit, working entirely in-memory for better performance and allowing history edits even with uncommitted changes.

The `reword` subcommand provides several advantages over using interactive rebase:
- Operates in-memory (no working tree changes required)
- Preserves local changes in working tree/index
- By default rewrites all local branches containing the commit (helpful for stacked branches)
- Supports detached HEAD scenarios
- Includes options to control which refs get updated (`--ref-action=branches|head|print`)

The implementation builds on Git's replay infrastructure (moved to libgit.a in earlier patches) and introduces a new `wt_status_collect_changes_trees()` helper for showing tree-to-tree diffs in the editor. The patch includes extensive test coverage (391 lines) verifying behavior with different ref states and edge cases.

This appears ready for merging - it has received Elijah Newren's technical sign-off and addresses all previous feedback. The implementation is thorough, with careful handling of edge cases like merge commits and detached HEAD states. The documentation clearly positions this relative to rebase and explains the tradeoffs.

The series represents a significant new capability for Git, providing a faster, more flexible alternative to interactive rebase for simple message rewording while laying groundwork for future history editing commands. The in-memory operation and branch-aware rewriting are particularly notable improvements over existing tools.
