Refactoring patch extracting core replay logic for library integration, part of Patrick Steinhardt's `git-history` RFC series (v11). This is the first of eight patches preparing the replay infrastructure for use by the new `git-history` command.

The patch moves the core revision-walking and commit-replaying logic from `cmd_replay()` into a new `replay_revisions()` function that will later be moved to libgit.a. The extracted function takes a `rev_info` struct and options, then returns a `replay_result` containing reference updates. The change is purely structural - no behavior modifications - but enables future patches to reuse this logic in the history command.

Key technical details:
- Introduces `replay_revisions_options` struct to pass parameters
- Defines `replay_result` struct to collect reference updates
- Moves 162 lines of core logic while maintaining same control flow
- Fixes a BUG() condition check for option validation
- Keeps all existing error handling and edge cases
- Prepares for next patch that will move this to a library file

This is part of the larger effort to enable flexible history editing operations while sharing infrastructure with Git's existing replay machinery. The series has already addressed extensive review feedback and appears technically sound.
