This is a bugfix patch addressing a regression in Git's hook subsystem output handling, specifically for the pre-push hook. The patch comes from Adrian Ratiu as a follow-up to earlier discussion with Chris Darroch, Patrick Steinhardt, and others.

The issue stems from a recent change that made all hooks redirect stdout to stderr by default, which broke the pre-push hook's ability to use the streams separately. The patch makes this behavior configurable via a new `stdout_to_stderr` flag in `run_hooks_opt`, defaulting to 1 (maintaining backward compatibility for most hooks) while explicitly setting it to 0 for pre-push hooks.

Junio Hamano's review confirms this is indeed a regression fix, noting that pre-push was historically the only hook that didn't divert stdout to stderr. The patch maintains this special case while keeping the new default behavior for other hooks. This appears to be a well-justified compromise between fixing the regression and not breaking existing pre-push hook implementations.

The change is relatively small but important, touching `hook.c`, `hook.h`, and `transport.c` to implement the configurable behavior. This is part of ongoing work on the hook subsystem but stands as an independent fix rather than being tied to larger refactoring efforts.
