This thread addresses a bug in HTTP authentication where `probe_rpc()` calls during large clone operations with bearer tokens were failing with 401 errors. The issue occurs when cloning repositories with blob filters where requests exceed `http.postBuffer` - while the main request authenticates successfully, the probe requests weren't including authentication headers.

The original patch (v1) proposed a simple 2-line fix adding `http_append_auth_header()` to `probe_rpc()` in `remote-curl.c`, accompanied by comprehensive tests simulating the failure scenario with a 2000-ref repository and small buffer settings. Version 2 incorporated feedback from Patrick Steinhardt, who confirmed the test properly demonstrates the issue but suggested minor improvements to the setup and cleanup procedures. Patrick indicated the patch is acceptable as-is, though the author may send a v3 with the suggested test refinements.

The fix is narrow in scope but important for users relying on bearer token authentication, particularly in large-repository scenarios. With Patrick's review and the thorough test coverage, this appears ready for merging once any final test polish is applied. No other reviewers have raised concerns about the technical approach.
