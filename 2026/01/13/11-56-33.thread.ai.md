Thread identity: Bugfix discussion addressing a regression in Git's hook subsystem output handling, specifically for the pre-push hook. Authored by Chris Darroch with participation from brian m. carlson, Patrick Steinhardt, Adrian Ratiu, and now Junio C Hamano.

Core problem: A recent change caused all hooks to redirect stdout to stderr by default, breaking the pre-push hook's ability to use streams separately. The discussion has converged on maintaining this behavior for most hooks while preserving the pre-push hook's special case for backward compatibility.

Current status: Junio C Hamano has reviewed and validated the approach, confirming through historical analysis that pre-push was indeed the only hook that previously didn't divert stdout to stderr. The solution adds a `stdout_to_stderr` flag to `run_hooks_opt` (defaulting to 1 for backward compatibility) while explicitly setting it to 0 for pre-push hooks.

Technical details: Changes affect `hook.c`, `hook.h`, and `transport.c`, introducing the new configuration option while maintaining the pre-push special case. The discussion revealed significant gaps in test coverage for hook output behavior that allowed this regression to slip through. Comprehensive tests will be added in `t/` to verify stdout/stderr behavior across all hook types.

Open questions: Whether the new test coverage will be sufficient to prevent similar regressions. The special case for pre-push hooks remains justified by backward compatibility needs, though the principle of consistent behavior for other hooks is now established.

Participant positions: Chris Darroch initially proposed the configurable solution. Patrick Steinhardt raised concerns about test coverage and design consistency. Adrian Ratiu revised the approach to maintain the pre-push special case while adding tests. Junio C Hamano has now validated the historical context and agrees with the solution, confirming pre-push was the only hook with different output behavior.
