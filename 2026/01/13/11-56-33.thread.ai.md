Thread identity: Bugfix discussion addressing a regression in Git's hook subsystem output handling, specifically for the pre-push hook. Authored by Chris Darroch with participation from brian m. carlson, Patrick Steinhardt, Adrian Ratiu, and Junio C Hamano.

Core problem: A recent change caused all hooks to redirect stdout to stderr by default, breaking the pre-push hook's ability to use separate streams. Junio's historical analysis confirmed pre-push was the only hook that historically kept streams separate, validating the need for a targeted fix.

Current status: Adrian Ratiu's v2 patch implements the agreed-upon solution with comprehensive test suite. The implementation adds a `stdout_to_stderr` flag to `run_hooks_opt` (defaulting to 1) while explicitly setting it to 0 for pre-push hooks, plus an output ungrouping fix. The patch touches `hook.c`, `hook.h`, and `transport.c`, with core logic in `pick_next_hook()`. New tests in `t/t1800-hook.sh` systematically verify stream behavior across all hook types.

Technical details: The solution preserves the pre-push special case while fixing the regression from recent hook API changes. Key changes include:
- New `stdout_to_stderr` configuration option in hook API
- Special handling for pre-push hook in transport.c
- Output ungrouping fix for pre-push case
- Comprehensive test coverage for all hook output behaviors
