This is the first patch in Patrick Steinhardt's v11 series introducing the `git-history` command, specifically focused on extracting core replay logic into a library function. The patch refactors the existing `cmd_replay()` implementation to pull out the revision replaying logic into a new `replay_revisions()` function that will later be moved to libgit.a.

The changes include:
- Introducing a new `replay_revisions()` function that encapsulates the core commit replay logic
- Adding supporting data structures (`replay_revisions_options` and `replay_result`) to pass parameters and results
- Moving ref update handling into the result queue rather than processing them inline
- Fixing a BUG() condition check for the --onto/--advance options
- The patch maintains all existing functionality while preparing for library integration
- It's part of a larger effort to enable in-memory index operations and support the `git-history` command's `reword` subcommand
- The changes are well-contained and mechanical, with no intended behavior changes

This foundational work is part of the series' goal to provide flexible history editing capabilities while integrating with Git's existing replay machinery. The patch has already gone through multiple rounds of review and incorporates feedback from previous versions.
