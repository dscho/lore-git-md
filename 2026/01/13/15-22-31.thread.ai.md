Git shortlog --committer documentation inconsistency

Thread identity: Documentation and implementation mismatch for `git shortlog --committer` option behavior. Originating author Manuel Rego Casasnovas. Thread type: bug report leading to documentation fix.

Core problem: The `git shortlog` man page documents both `--committer` (no value) and `--committer=<pattern>` forms, but only the no-value form is implemented. Junio C Hamano's analysis confirmed this inconsistency and recommended against implementing pattern matching due to parsing ambiguities and misalignment with `git log` behavior.

Current status: Pushkar Singh is preparing a documentation patch to resolve the mismatch by making the options unambiguous in the man page. This follows the consensus to update documentation rather than extend implementation, as supporting pattern matching would create user confusion with `git log` conventions and introduce parsing ambiguities (e.g., `--committer -n` interpretation).

Key technical details: Affects `Documentation/git-shortlog.txt` documentation. Implementation in `builtin/shortlog.c` rejects `--committer=foo` with "takes no value" error. The `--committer` option functions strictly as `--group=committer` filter without pattern matching. The documentation inherited pattern-matching syntax from `rev-list-options.adoc` incorrectly.

Open questions: Exact wording for documentation update needs to clearly explain `--committer` as a no-value alias for `--group=committer` while removing the unimplemented pattern-matching variant. The patch should maintain consistency with Junio's technical assessment.

Participant positions: Manuel Rego Casasnovas identified original issue. Randall S. Becker provided alternative interpretation. Junio C Hamano provided authoritative technical analysis favoring documentation update. Pushkar Singh is implementing the documentation fix following this consensus. No objections to the direction.

Related work: Comparison with `git log` option parsing behavior informed the decision. The resolution follows Git's principle of favoring simple, unambiguous interfaces when edge cases exist. The fix will remove inherited documentation from `rev-list-options.adoc` that doesn't match implementation.
