This is a bugfix for the hook subsystem, specifically addressing a regression in pre-push hook output handling. The patch comes from Adrian Ratiu in response to feedback from Junio Hamano and others in the thread.

The issue stems from a recent change that made all hooks redirect stdout to stderr by default, which broke the pre-push hook's special behavior of keeping the streams separate. Junio's historical analysis confirmed that pre-push was indeed the only hook that needed this exception. Adrian's v2 patch will implement Junio's suggested title change to "hook: allow stdout_to_stderr optionally off" and includes an additional fix for ungrouping output to fully restore the pre-push hook's original behavior.

The solution adds a `stdout_to_stderr` flag to `run_hooks_opt` (defaulting to true for backward compatibility) while explicitly setting it to false for pre-push hooks. The patch touches `hook.c`, `hook.h`, and `transport.c`, with the core logic in `pick_next_hook()`. Adrian is also adding tests to verify the behavior matches both before and after the regression.

This appears to be a well-justified fix that preserves backward compatibility while properly capturing the special case through the new configuration option.
