Part of the `the_repository` removal effort, this patch concludes Olamide Caleb Bello's Outreachy internship series (mentored by Christian Couder) by moving the `branch.autoSetupMerge` enum configuration from global `git_branch_track` to `struct repo_config_values`. Following parts 1 (string config) and 2 (boolean config), this demonstrates the pattern for enum-type configurations.

The patch removes the global `git_branch_track` variable, replacing it in `struct repo_config_values` with a new `git_branch_track` field initialized to `BRANCH_TRACK_REMOTE`. All access points across branch, checkout, push, and submodule commands are updated to read from `the_repository->config_values.git_branch_track`. The config parsing in `git_default_branch_config()` now writes directly to the repository's config struct.

Key technical changes include adding the enum field to `environment.h`'s config struct, implementing initialization in `repo_config_values_init()`, and updating 5 command implementations. The approach maintains Phillip Wood's v1 feedback by keeping direct struct embedding rather than pointer allocation. One notable quirk is the mixed location of config values - while branch-related`, the enum lives in `environment.[ch]` alongside core configs rather than with branch-specific code.

This completes the series' demonstration of handling all three major config value categories (string, boolean, enum) through repository-scoped storage. As an Outreachy contribution, it shows promising progress on eliminating globals while raising questions about long-term organization of the growing `repo_config_values` struct. The changeset is cleanly focused with straightforward mechanical conversions and proper initialization/cleanup.
