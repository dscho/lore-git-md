This is part 5 of an 8-patch series introducing the `git-history` command, specifically focusing on adding support for updating detached HEAD during history replay.

The patch enhances the replay machinery to properly handle detached HEAD states when rewriting history. Previously, the code only updated local branch refs (`DECORATION_REF_LOCAL`) but ignored HEAD decorations (`DECORATION_REF_HEAD`). The change introduces logic to detect when HEAD is detached (via `RESOLVE_REF_NO_RECURSE` flag check) and includes HEAD updates in those cases. The implementation:
- Adds a `detached_head` parameter to track HEAD state
- Refactors the decoration iteration loop for clarity
- Adds a new test case verifying detached HEAD updates
- Maintains the existing behavior for non-detached HEAD (where the branch ref would already be updated)

This builds on Elijah Newren's earlier work and is part of the larger effort to make the replay infrastructure more flexible for the upcoming `git-history` command. The change is well-contained with clear test coverage and follows the established pattern of the series. With Elijah's sign-off and no outstanding technical concerns, this appears ready for integration.
