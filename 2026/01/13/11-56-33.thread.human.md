This thread addresses several interrelated issues in Git's hook subsystem, focusing on stdout/stderr separation in pre-push hooks and the behavior of the `ungroup` flag. This fixed a regression from commit 3e2836a742d8 and included extensive new test coverage.

The second patch, now under discussion, changes the `ungroup` flag behavior from opt-in to opt-out, reverting an accidental change from commit 857f047e40. The patch makes `ungroup=1` the default in `RUN_HOOKS_OPT_INIT` while allowing explicit opt-out where needed (particularly in receive-pack for sideband output). It includes comprehensive tests for receive-pack's sideband output across all relevant hook types, building on the test infrastructure from the first patch.

Performance considerations and potential deadlocks in hook execution have been identified but deferred to future work, with server-side hooks expected to use proper poll() implementation while client-side hooks maintain current behavior. The discussion has been productive, with clear consensus emerging on separating the fixes while maintaining backward compatibility.
