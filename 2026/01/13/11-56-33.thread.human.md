Chris Darroch initially identified the issue, with Adrian Ratiu, Patrick Steinhardt, and brian m. carlson contributing to the discussion.

Junio C Hamano has now weighed in with a patch that implements this approach, adding a `stdout_to_stderr` flag to the hook infrastructure while explicitly setting it to 0 for pre-push hooks.

Junio confirmed this is a proper regression fix by examining the hook API's history, noting pre-push was indeed the only hook that previously maintained separate streams. The changes touch `hook.c`, `hook.h`, and `transport.c`. A key lesson from this discussion was the need for better test coverage of hook output behavior, which was lacking and allowed this regression to slip through. The fix maintains compatibility with existing pre-push hook implementations while establishing consistent behavior for other hooks.
