This thread addresses a documentation inconsistency in `git shortlog --committer`, where the man page suggests the option supports both a no-value form and pattern matching (`--committer=<pattern>`), but only the no-value form is actually implemented. Manuel Rego Casasnovas initially reported the issue, with Randall S. Becker speculating it might be intentional. Junio C Hamano provided the key analysis, explaining that implementing pattern matching would create parsing ambiguities and misalign with `git log` behavior, recommending instead to update the documentation.

The thread has reached consensus on this approach, with Pushkar Singh now stepping up to prepare the documentation patch. The fix will clarify that `--committer` is simply a no-value alias for `--group=committer`, removing references to the unimplemented pattern-matching variant. This is a straightforward resolution following Junio's guidance, and the patch should be uncontroversial as it aligns with the maintainer's preferred direction. The implementation in `builtin/shortlog.c` already enforces this behavior by rejecting values with the option, so the documentation update will bring the man page in line with reality.
