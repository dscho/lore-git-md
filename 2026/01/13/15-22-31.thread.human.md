This thread addresses a documentation inconsistency in `git shortlog --committer`, where the man page incorrectly suggests the option supports both a no-value form and pattern matching (`--committer=<pattern>`). Manuel Rego Casasnovas originally reported that only the no-value form actually works, with `--committer=foo` being rejected by the implementation. 

Junio C Hamano analyzed the issue and determined that implementing pattern matching would create parsing ambiguities (like interpreting `--committer -n`) and inconsistencies with `git log` behavior. The consensus is to fix the documentation rather than extend the implementation. Pushkar Singh is preparing a patch to clarify that `--committer` is simply a no-value alias for `--group=committer`, removing the unimplemented pattern-matching variant from the docs. 

The documentation error stems from `git-shortlog.txt` incorrectly inheriting pattern-matching syntax from `rev-list-options.adoc`. Pushkar's upcoming patch will clean this up, making the option's behavior unambiguous while maintaining consistency with Git's preference for simple, clear interfaces when edge cases exist. There are no outstanding objections to this approach.
