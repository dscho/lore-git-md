This is a refactoring patch in Patrick Steinhardt's ongoing `git-history` command series (v11, patch 6/8). It introduces a new utility function for comparing changes between two arbitrary trees, rather than between the working tree/index as the existing status machinery does.

The patch adds `wt_status_collect_changes_trees()` to the working tree status subsystem, which diffs two provided tree objects and formats the results using the same callback mechanism as regular status collection. The function handles rename detection and other diff options according to the `wt_status` configuration. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic that's already well-tested in the status code.

This infrastructure will be used in subsequent patches for the `reword` subcommand of `git-history`, which needs to display changes between commit trees during history editing operations. The implementation follows Git's standard diff machinery patterns and maintains all existing behavior while adding the new tree-to-tree comparison capability.

The patch-specific changes include:
- New public function in `wt-status.h` with documentation
- Implementation in `wt-status.c` that reuses existing diff callbacks
- Support for all standard diff/rename detection options from `wt_status`
- Proper cleanup of diff resources
- Integration with the repository state collection

This is a straightforward addition that enables the history editing functionality while keeping the diff display consistent with Git's existing status output.
