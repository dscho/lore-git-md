This thread addresses a bug in gitk's color configuration where certain color settings for refs and tags were being ignored. The original patch fixed two specific problems: the `tagfgcolor` setting was unused (with all labels defaulting to `headfgcolor`), and head outlines were hardcoded black instead of respecting the `headoutlinecolor` setting. The changes are limited to the `drawtags` procedure and maintain backward compatibility for non-head ref colors.

Johannes Sixt (Hannes) reviewed the patch and found the implementation sound but suggested improving the commit message. He recommended better documenting gitk's ref styling system and being explicit about what remains hardcoded versus what becomes configurable. He also raised a valid concern about backward compatibility, since these color settings aren't exposed in gitk's UI and users could be surprised by the change. The patch appears ready to merge once the commit message is updated to address these documentation concerns. The issue was discovered while working on VSCode theme export functionality, and the fix adds no new complexity while making the color configuration more consistent.
