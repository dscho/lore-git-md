This is a bugfix patch addressing a regression in Git's hook subsystem, specifically for the pre-push hook's output handling. The patch is part of an ongoing discussion about hook behavior that has involved multiple contributors.

Adrian Ratiu is responding to Junio Hamano's review of his initial patch, which makes the `stdout_to_stderr` hook option configurable. Junio confirmed through historical analysis that pre-push was indeed the only hook that didn't divert stdout to stderr, validating the regression fix approach. He also suggested improving the patch title to better reflect that stdout-to-stderr is on by default but can be opted out of.

Ratiu acknowledges the title suggestion and notes he'll include it in v2, along with one additional line needed to fully restore pre-push hook functionality (ungrouping output). The patch touches core hook infrastructure in `hook.c` and `hook.h`, plus the pre-push hook integration in `transport.c`. This represents the final refinement before merging, with Junio's approval signaling the technical approach is sound.

The discussion has revealed broader test coverage issues around hook output behavior that Ratiu plans to address separately. This fix maintains backward compatibility while properly documenting the behavior through the new configuration option, resolving a regression introduced by recent hook API changes.
