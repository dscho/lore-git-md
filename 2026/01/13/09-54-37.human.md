This is a refactoring patch from Patrick Steinhardt's ongoing `git-history` command series (v11 6/8). It introduces a new utility function `wt_status_collect_changes_trees()` that computes and formats the differences between two arbitrary trees, treating them as if they were staged changes in the working tree status machinery.

The patch is part of the infrastructure work needed for the `reword` subcommand, which will use this to show changes when rewriting commit messages. While the function is currently unused, it will be wired up in a subsequent commit. The implementation reuses existing diff machinery and working tree status callbacks, though the author acknowledges it's a slight conceptual stretch to put tree diffs in the "wt-status" subsystem.

This is a well-contained change that follows the series' pattern of extracting reusable components. The implementation looks straightforward, building on Git's existing diff infrastructure while maintaining the same callback-based approach used for working tree status. The patch has no outstanding review comments and appears ready for inclusion.
