This thread addresses a bug in remote-curl's HTTP authentication handling, specifically in the `probe_rpc()` path used for capability checks on large requests. The issue caused authentication failures when fetching from servers requiring Bearer tokens, particularly affecting operations like filtered clones of large repositories. 

The fix adds proper authentication header handling to `probe_rpc()`. The test case demonstrates the scenario by creating a repository with 2000 refs (to trigger the probe), setting a small `http.postBuffer` to force the capability check, and verifying successful clone with Bearer authentication. 

Patrick Steinhardt reviewed the patch, suggesting improvements to combine setup and test into a single subtest and ensure proper cleanup. The v3 iteration incorporates this feedback and has received Patrick's approval, indicating it's ready for merging. This resolves an edge case affecting users of token-based authentication with large repositories.
