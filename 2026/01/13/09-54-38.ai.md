This is the 7th patch in an 8-part v11 series introducing a new `git history` command, authored by Patrick Steinhardt. The series builds on Git's replay machinery to provide imperative history editing capabilities inspired by Jujutsu's approach.

The patch adds the core `git-history` command infrastructure including:
- Basic command scaffolding in `builtin/history.c`
- Documentation outlining the command's purpose and differences from `git rebase`
- Build system integration (Makefile, meson.build)
- A simple test verifying basic command behavior

Key aspects of the new command:
- Designed for common history editing operations (reordering, splitting, dropping commits)
- Works in bare repositories unlike rebase
- Currently no hook execution (may change later)
- Updates dependent branches by default
- Explicitly experimental with behavior subject to change

The documentation positions this as a more opinionated alternative to rebase for specific use cases, while acknowledging current limitations (no merge support, no conflict handling). The implementation is minimal in this patch - just enough to make the command exist - with actual functionality coming in subsequent patches.

This is part of a larger effort to provide more flexible history editing capabilities in Git, building on the replay infrastructure while drawing inspiration from tools like Jujutsu. The series has undergone extensive review and iteration, with all technical feedback addressed by this v11 iteration.
