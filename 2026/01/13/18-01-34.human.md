Documentation fix for `git shortlog --committer` parsing behavior.

This email thread clarifies that the issue with `git shortlog --committer=<pattern>` is not a documentation error as initially thought, but rather a parsing limitation in the command-line option handling. Pushkar Singh confirms that both forms (`--committer` for grouping and `--committer=<pattern>` for commit limiting) are correctly documented, but the implementation rejects the pattern form due to parsing ambiguities.

The discussion follows up on Junio C Hamano's earlier analysis that implementing pattern matching would create confusion with `git log` behavior and introduce parsing edge cases. Pushkar notes this stems from `git-shortlog` inheriting documentation from `rev-list-options.adoc` that doesn't match the actual implementation.

While the thread initially appeared headed toward a documentation fix, Pushkar's latest message indicates the documentation is actually correct - the limitation is in the option parser itself. This leaves the situation in an interesting state where the documented functionality exists but cannot be used due to implementation constraints. The thread shows the careful consideration given to Git's command-line interface design, where parsing ambiguities can outweigh the benefits of feature parity with related commands.
