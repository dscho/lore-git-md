This is a documentation issue regarding the `git shortlog` command's `--committer` option. Manuel Rego Casasnovas points out an inconsistency between the documented behavior and actual implementation.

The documentation currently lists both `--committer` (which takes no value) and `--committer=<pattern>` (which suggests it should accept a pattern) as valid options. However, in practice (tested with Git 2.51.0), passing `--committer=foo` results in an error stating the option takes no value.

The patch doesn't propose a specific solution but suggests two possible paths: either implement support for the pattern-matching version of the option (to match the documentation), or correct the documentation to remove the conflicting information. The issue appears straightforward but touches on command-line interface consistency, which is important for user experience.
