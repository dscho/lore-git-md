This is the second patch in Harald Nordgren's 2-part series to enhance `git status` with push tracking branch comparison. The implementation is now finalized and approved for merging into `next`.

The patch extends `git status` to show divergence information for both the upstream tracking branch (existing behavior) and the push tracking branch (new) when they differ. The push branch comparison appears on a new line using the same format as the upstream status. For example, when tracking `origin/main` but pushing to `origin/feature`, it will display both relationships.

Key technical changes:
- Introduces `get_remote_push_branch()` helper to resolve the push tracking branch
- Extends `format_tracking_info()` to handle both upstream and push comparisons
- Uses new flag constants (`ENABLE_ADVICE_PULL/PUSH/DIVERGENCE`) to control advice display
- Maintains all existing output formats and edge case handling
- Adds 262 lines of test coverage in t6040-tracking-info.sh covering various scenarios:
  - Diverged upstream vs ahead push
  - Remapped push refspecs
  - Multiple remote configurations
  - `--no-ahead-behind` behavior
  - Push default interactions

The implementation cleanly separates concerns between branch resolution and status formatting while preserving all existing behavior. The advice display logic was refined through review discussion to ensure consistent behavior between upstream and push tracking cases.

This represents the culmination of 24 iterations of review and refinement, with all feedback addressed. The patch is now in its final form and ready for wider testing in `next`. The remaining open question about `push.default` interactions can be addressed in follow-up work if needed.
