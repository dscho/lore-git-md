This is a bug report about pre-push hook performance degradation when reading from standard input. The issue appears to have been introduced in commit 857f047e ("hook: allow overriding the ungroup option", 2025-12-26).

The reporter demonstrates that when a pre-push hook contains a loop reading stdin (even an empty one), the push operation becomes significantly slower - taking over a minute compared to a few seconds when using `--no-verify` to skip hooks. They've created a minimal test case using just `cat` in the hook to reproduce the issue, and have bisected it to the regression point.

The slowdown occurs across Git's integration branches (master, next, seen) and affects pushes to remote repositories (tested with Bitbucket Cloud). The reporter provides detailed reproduction steps including a shell script that sets up a test repository with the problematic hook configuration. The issue appears to be related to how stdin is handled in hooks after the regression commit.

Key technical details:
- Affects pre-push hooks that read stdin
- Regression introduced in 857f047e
- Reproducible with minimal `cat` hook
- Timeout-based bisection confirms the behavior change
- Present in current integration branches
- System info shows SHA-1 as default hash, files ref backend

The report is thorough, with clear steps to reproduce and evidence of the regression. The impact appears significant for users relying on pre-push hooks that process stdin, particularly in CI/CD pipelines where push performance matters.
