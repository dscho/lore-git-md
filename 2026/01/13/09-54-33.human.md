This is part 2 of an 8-patch series refactoring Git's replay machinery to support a new `git-history` command. The series is authored by Patrick Steinhardt and has reached its 11th iteration, indicating significant review and refinement.

The patch moves the core replay logic from `builtin/replay.c` into `replay.c` in libgit.a, making it available as a library function. This is infrastructure work to enable the upcoming `git-history` command while also removing dependencies on `the_repository` global variable (part of that ongoing effort). The commit message notes this eliminates sign-comparison warnings and repository dependencies.

The changes are mechanical - 366 lines are removed from the builtin and 354 nearly identical lines are added to the new library file, with a new header file defining the public interface. The functionality remains the same, just relocated. The new `replay_revisions()` function takes a `rev_info` and options struct, returning results via an out-parameter.

This appears to be a well-executed refactoring that follows Git's conventions. The patch is part of a mature series that has addressed all technical feedback through 10 previous iterations, including sign-offs from key contributors like Elijah Newren. The changes are focused and clearly motivated by the need to share replay logic between commands.
