This is patch 16/17 in Taylor Blau's MIDX compaction series, addressing final review feedback from Patrick Steinhardt. The patch implements the core `git multi-pack-index compact` command, which creates a new MIDX containing only objects from a specified range of existing MIDX layers.

Key points from the discussion:
- Patrick confirmed that compacting without `--incremental` completely replaces the MIDX with just the specified range
- Taylor clarified that bitmap ordering during compaction must match the original MIDX's bitmap state (can't introduce new bitmaps during compaction)
- Several edge cases were identified that should be tested (equal from/to, invalid ranges) which Taylor agrees should be added
- A minor documentation issue about `--bitmap` flag was fixed (removed premature mention)

The technical implementation appears sound, with thorough test coverage already in place.
