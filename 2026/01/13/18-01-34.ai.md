Documentation clarification for `git shortlog --committer` option behavior.

Pushkar Singh follows up on the thread about the `--committer` option in `git shortlog`, confirming that while both forms (`--committer` and `--committer=<pattern>`) appear in the documentation, only the no-value form is actually implemented. The issue stems from how the option parser handles the `=` syntax, rejecting `--committer=foo` even though the documentation suggests it should work as a pattern filter.

The thread had previously established that implementing pattern matching would create parsing ambiguities and inconsistencies with `git log` behavior, leading to consensus that the documentation should be updated rather than extending the implementation. Pushkar now notes that the documentation mismatch originates from `git-shortlog` inheriting options documentation from `rev-list-options.adoc` where the pattern-matching variant is incorrectly included.

This email doesn't introduce new technical details but confirms the path forward - updating the documentation to clearly present `--committer` as a no-value alias for `--group=committer` while removing references to the unimplemented pattern-matching variant. The patch will need to carefully disentangle the inherited documentation to avoid future confusion about this option's behavior.
