This is a follow-up discussion about the recently merged `git status` push-tracking feature, specifically addressing Jeff King's workflow concerns. 

Harald Nordgren, the original author of the push-tracking patches, responds to Jeff's complaint about push status being noisy in triangular workflows (where the push remote acts as a mirror). Harald suggests Jeff's workflow might be suboptimal and proposes an alternative approach - using the full `git push origin my-mirror` syntax for mirror pushes while reserving the simpler `git push` for more frequent pushes to a different destination. 

The exchange highlights differing workflow preferences rather than technical issues with the implementation. Harald's response maintains the feature works as designed but suggests configuration through push destinations rather than adding new status display toggles. This continues the post-merge discussion about how the feature fits into real-world usage patterns, though no concrete changes to the code are proposed here.
