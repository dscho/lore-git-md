This is a feature patch implementing the `reword` subcommand for the new `git history` command, part of Patrick Steinhardt's ongoing effort to bring Jujutsu-like history editing capabilities to Git. The subcommand allows rewriting commit messages without checking out the commit, operating entirely in-memory for better performance and working tree flexibility.

The implementation builds on Git's replay machinery rather than the sequencer, offering several advantages: no working tree checkout required (enabling use with dirty states), no hook execution (though this may change), and automatic rewriting of all local branches containing the commit (useful for stacked workflows). The patch includes extensive test coverage (391 lines across 18 test cases) and handles detached HEAD cases through ref flags.

Elijah Newren, the merge machinery expert, has reviewed the patch and approves the technical implementation, though he maintains an objection to the non-standard `-1` conflict return code. The patch now incorporates all previous feedback and appears ready for merging, with some remaining design questions about future conflict handling deferred for later discussion. This represents the final piece of the v10 series that has been under review for several months.
