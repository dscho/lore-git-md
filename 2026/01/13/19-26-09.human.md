This is a review comment from Junio C Hamano on part 1 of Olamide Caleb Bello's RFC series to eliminate global configuration variables as part of the `the_repository` removal effort. The series introduces `struct repo_config_values` to store config values at the repository level rather than globally.

Junio notes that while this patch addresses moving `core.attributesFile` from a global variable to the new struct, there are many other similar globals (listing several examples like `apply_default_whitespace` and `pack_compression_level`) that would need the same treatment. He raises an important architectural question - whether all these config values should indeed be repository-specific, or if some are inherently system/user-level settings that should remain global.

The comment doesn't reject the approach but suggests the series may need to consider a more comprehensive strategy for classifying which configs should be moved versus which should stay global. This is typical of Junio's review style - identifying broader implications rather than focusing on implementation details of the specific patch. The comment will likely prompt discussion about the scope and categorization of config values in future iterations of the series.
