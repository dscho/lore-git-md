This is a bugfix for HTTP authentication in `remote-curl.c`, specifically addressing an issue where `probe_rpc()` requests during clone operations weren't including authentication headers despite the main request having successfully authenticated. The patch is now in its second iteration, with Junio Hamano providing final stylistic feedback before potential merging.

The core issue manifests when cloning large repositories with blob filters where requests exceed `http.postBuffer` - the `probe_rpc()` call fails with 401 errors, breaking bearer token authentication flows. The fix is minimal (adding `http_append_auth_header()` to `probe_rpc()`), but the test setup is comprehensive, creating a repository with 2000 refs to force large requests and using `git-credential-msal` for bearer token testing.

Junio's review focuses on minor presentation details: suggesting lowercase "use" in the subject line (following Git convention), questioning whether a blank line before the auth header addition is needed, and noting a potential portability concern with `test_seq 2000` on systems with small ARG_MAX limits. These are all polish-level comments - the technical approach has already been approved by Patrick Steinhardt in previous reviews. The patch appears ready to merge once these minor suggestions are addressed.
