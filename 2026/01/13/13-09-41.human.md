Bugfix for HTTP authentication in `remote-curl.c` affecting clone operations with bearer tokens. This is version 2 of the patch, addressing feedback from Patrick Steinhardt while maintaining the core fix.

The issue occurs when cloning large repositories with blob filters where requests exceed `http.postBuffer`. The `probe_rpc()` call fails with 401 errors because it wasn't including authentication headers, despite the main request having successfully authenticated. This breaks bearer token authentication flows for large requests.

The fix is minimal - just two lines adding `http_append_auth_header()` to `probe_rpc()` in `remote-curl.c`. The test coverage is thorough, creating a repo with 2000 refs to force large requests and using `git-credential-msal` for bearer token auth testing. Junio C Hamano provides minor style suggestions about the commit message subject line and code formatting, but confirms the technical approach is sound. He also notes a potential portability concern with `test_seq` on systems with small ARG_MAX limits, suggesting an alternative implementation using `xargs`.

Patrick Steinhardt has already indicated the patch is acceptable as-is, though the author may choose to incorporate Junio's suggestions in a potential v3. The thread appears ready for merging once these final polish items are addressed.
