This is part of Patrick Steinhardt's ongoing effort to introduce a new `git-history` command, specifically patch 2/8 in the v11 series. The patch moves the core replay logic from `builtin/replay.c` into a new `replay.c` in libgit.a, making it available as a library function for reuse.

The change extracts 354 lines of core functionality into the new `replay.c` file while leaving only the command-line interface in `builtin/replay.c`. Key technical details include:
- New `replay_revisions()` function that takes a `rev_info` and options struct
- `replay_result` struct to collect reference updates
- Maintains all existing behavior while enabling library reuse
- Removes dependency on `the_repository` global
- Eliminates sign-comparison warnings

The patch is part of a larger series that has already addressed all technical feedback, including conflict reporting standardization and validation fixes from Elijah Newren and Junio Hamano. This infrastructure refactoring prepares for the introduction of the new `git-history` command while keeping the existing replay functionality intact.

The changes are mechanical and well-contained, with 366 lines removed from the builtin and 354 added to the new file plus headers. The series has reached consensus on technical implementation and appears ready for maintainer evaluation.
