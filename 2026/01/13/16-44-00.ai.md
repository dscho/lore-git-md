This is part 1 of a 3-patch series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) that moves configuration values from global variables into `struct repository` as part of the ongoing `the_repository` removal effort. This specific patch targets the `core.attributesFile` configuration.

The patch eliminates the global `git_attributes_file` variable by moving it into a new `repo_config_values` struct embedded directly in `struct repository`. The change maintains the existing eager-loading behavior while making the configuration repository-specific. The implementation follows Phillip Wood's feedback from v1 by embedding the config storage directly rather than allocating it separately.

Key technical changes include:
- Adding `attributes_file_path` field to new `struct repo_config_values`
- Updating access patterns in `attr.c` to use the repository-stored value
- Removing the global declaration from `environment.h`
- Adding the config struct to `repository.h`

The patch demonstrates the approach for string-type configurations, with parts 2 and 3 of the series handling boolean and enum types respectively. As an Outreachy intern project, this represents mentored progress on the larger `the_repository` removal effort while introducing proper repository-aware configuration handling. The changes affect attribute handling but maintain backward compatibility with existing behavior.
