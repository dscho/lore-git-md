This is a bugfix for gitk, the Git repository browser GUI. The patch addresses two color configuration issues that were not being properly respected:

1. The `tagfgcolor` setting was being ignored - all label text was using `headfgcolor` regardless of whether it was a tag or not.
2. The outline color for heads was hardcoded to black instead of using the `headoutlinecolor` setting.

The changes make gitk respect these existing but unused color settings while maintaining the current hardcoded colors for non-head refs. The patch is small and focused, touching only the `drawtags` procedure in gitk's Tcl code. The author provides a clear explanation of the changes and includes a screenshot showing the working configuration.

This appears to be a straightforward fix that makes gitk behave as expected with its documented color settings. The patch comes from someone who was working on a VSCode extension that interacts with gitk's colors, suggesting they have practical experience with the affected functionality.
