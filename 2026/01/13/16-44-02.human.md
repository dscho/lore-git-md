Part of the `the_repository` removal effort, this is the third patch in Olamide Caleb Bello's Outreachy internship series moving configuration variables from global scope into `struct repo_config_values`. This installment tackles the enum-type `branch.autoSetupMerge` configuration, previously stored in the global `git_branch_track`.

The patch follows the established pattern from parts 1 and 2 (which handled string and boolean configs respectively), embedding the config value directly in the repository structure. The changes affect several commands that use branch tracking behavior - branch, checkout, push, and submodule operations - updating them to access the value via `the_repository->config_values.git_branch_track` instead of the global variable.

Key technical aspects include adding the enum field to `struct repo_config_values`, initializing it in `repo_config_values_init()`, and updating the config callback in `git_default_branch_config()`. The global variable declaration is removed from branch.h, completing the transition to repository-scoped storage.

As with the previous patches in the series, this demonstrates a clean approach to eliminating global state while maintaining existing behavior. The changes are well-contained and follow Phillip Wood's earlier feedback about direct struct embedding. This represents solid progress in the broader effort to make Git's configuration handling more repository-aware.
