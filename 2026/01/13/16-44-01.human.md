This is part 2 of a 3-part series (part of the `the_repository` removal effort) that moves configuration variables from global storage to repository-specific storage. The patch focuses on converting the `core.sparseCheckout` boolean config value, following the same pattern established in part 1 for `core.attributesFile`.

The changes are mechanical but widespread, updating 12 files to reference the new repository-scoped `sparse_checkout` field in `struct repo_config_values` instead of the old global `core_apply_sparse_checkout` variable. The patch maintains all existing behavior while making the configuration properly repository-aware.

As an Outreachy intern project mentored by Christian Couder, this represents solid progress on the ongoing effort to eliminate global state. The changes are straightforward and follow the established pattern from part 1, suggesting this approach scales well to different config value types (string in part 1, boolean here, enum coming in part 3). The patch appears well-tested, with updates to all the key sparse-checkout related commands and careful handling of edge cases.
