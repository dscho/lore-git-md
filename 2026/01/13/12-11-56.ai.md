This is the second patch in Harald Nordgren's 2-part series enhancing `git status` to show divergence from both upstream and push tracking branches. The implementation has been through 25 iterations of review and is now approved by Junio C Hamano for merging into `next`.

The patch extends `git status` to show an additional comparison when the push destination tracking branch differs from the upstream tracking branch. The new push branch comparison appears on a separate line after the upstream branch information, using the same format. For example, when tracking `origin/main` but pushing to `origin/feature`, status will now show both relationships.

Key technical details:
- Adds `get_remote_push_branch()` helper to resolve push tracking references
- Extends `format_tracking_info()` to handle both upstream and push comparisons
- Introduces flag constants (ENABLE_ADVICE_PULL/PUSH/DIVERGENCE) for advice control
- Maintains all existing behavior including quick mode (`--no-ahead-behind`)
- Shows appropriate advice messages for each divergence scenario
- Handles remapped push refspecs and multiple remote configurations
- Includes 285 lines of new test coverage in t6040-tracking-info.sh

The implementation cleanly separates concerns between the caller and helper functions while preserving all edge case handling from previous versions. The extensive test coverage verifies behavior across various scenarios including diverged upstream vs ahead push, remapped refspecs, and different push.default configurations.

This represents the final version of a well-reviewed feature that has addressed all feedback through 25 iterations, with particular attention to advice display behavior and test coverage. The patch follows project conventions and is ready for wider testing in `next`.
