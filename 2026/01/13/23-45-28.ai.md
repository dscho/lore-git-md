Hook subsystem fix preserving pre-push hook's separate output streams. This is a bugfix addressing a regression where recent hook API changes caused all hooks to redirect stdout to stderr by default, breaking the pre-push hook's historical behavior of keeping the streams separate.

Adrian Ratiu's v2 patch implements the agreed-upon solution after discussion with Junio Hamano, Patrick Steinhardt, and others. The fix introduces a `stdout_to_stderr` flag in the hook API (defaulting to 1 for backward compatibility) while explicitly setting it to 0 for pre-push hooks. The patch also includes an output ungrouping fix for the pre-push case and adds comprehensive test coverage to verify stream behavior across all hook types.

The changes touch `hook.c`, `hook.h`, and `transport.c`, with the core logic in `pick_next_hook()`. The extensive new tests in `t/t1800-hook.sh systematically verify that pre-push maintains separate streams while other hooks continue merging stdout to stderr. This regression fix is part of ongoing hook subsystem improvements but stands independently from Adrian's larger hook configuration work.

The patch has incorporated all feedback from v1, including Junio's suggested title change and Patrick's test coverage concerns. With the historical behavior now properly documented and tested, this solution is ready for merging. The discussion has also highlighted broader test coverage gaps in hook output handling that may warrant follow-up work.
