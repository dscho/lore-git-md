This is the second patch in Harald Nordgren's 2-part series enhancing `git status` to show divergence from both upstream and push tracking branches. The series has been through 24 iterations and is now approved for merging into `next`.

The patch implements push tracking branch comparison in `git status` output when the push destination differs from the upstream branch. The new output appears on a separate line after the existing upstream status, maintaining the same format. For example, when tracking `origin/main` but pushing to `origin/feature`, status will show both comparisons with appropriate advice messages.

Key technical aspects:
- Adds `get_remote_push_branch()` helper to resolve push tracking refs
- Extends `format_tracking_info()` to handle both upstream and push comparisons
- Introduces `ENABLE_ADVICE_*` flags to control which advice messages appear
- Includes extensive test coverage (262 lines) in t6040-tracking-info.sh
- Handles edge cases like remapped push refspecs and different remote configurations

The implementation is clean separation from the first patch's refactoring and maintains all existing behavior. Junio Hamano has approved the series after final naming and parameter simplifications in v24. While the current implementation assumes `push.default=current`, any follow-up work for other push.default settings can be addressed separately.
