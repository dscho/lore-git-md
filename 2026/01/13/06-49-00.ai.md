Bugfix for HTTP authentication in `remote-curl.c` affecting bearer token flows during large clone operations. This is version 2 of the patch, addressing feedback on the test setup from Patrick Steinhardt.

The issue occurs when cloning large repositories with blob filters where requests exceed `http.postBuffer`. The `probe_rpc()` call fails with 401 errors because it wasn't including authentication headers, despite the main request having successfully authenticated. The fix adds `http_append_auth_header()` to `probe_rpc()` to ensure auth headers are included in these probe requests.

The patch includes comprehensive test that:
1. Creates a repository with 2000 refs to force large requests
2. Configures a small `http.postBuffer` to trigger `probe_rpc()`
3. Uses `git-credential-msal` for bearer token auth testing
4. Verifies both the failure case and successful fix

Patrick Steinhardt has reviewed v2 and confirmed the test fails without the fix, though he suggests two test improvements: using `test_when_finished` for cleanup and inlining the test repo setup. He indicates the patch is acceptable as-is but may be rerolled to incorporate these suggestions.

This appears to be a straightforward and well-tested fix for a specific authentication edge case in the HTTP transport layer. The change is minimal (2 lines) but comes with thorough test coverage, making it low-risk for inclusion.
