This is a bugfix patch addressing a regression in Git's hook subsystem, specifically targeting the pre-push hook's output handling. The patch comes from Adrian Ratiu as version 2 of a fix that has already undergone significant discussion on the mailing list.

The core issue stems from a recent change that made all hooks redirect stdout to stderr by default, which broke the pre-push hook's special behavior of keeping the streams separate. Junio Hamano's historical analysis confirmed that pre-push was indeed the only hook that historically maintained this distinction, validating the need for a targeted fix.

The patch makes two key changes: it adds a `stdout_to_stderr` flag to `run_hooks_opt` (defaulting to true for backward compatibility) while explicitly setting it to false for pre-push hooks, and includes an additional fix for ungrouping output in the pre-push case. The implementation touches `hook.c`, `hook.h`, and `transport.c`, with the main logic residing in `pick_next_hook()`.

Adrian has incorporated all feedback from the thread, including Junio's suggestion to rename the patch from "make stdout_to_stderr optional" to "hook: allow stdout_to_stderr optionally off" to better reflect that the default remains true. The discussion also revealed gaps in test coverage for hook output behavior that will be addressed separately.

The solution maintains backward compatibility while properly capturing the pre-push hook's special requirements through the new configuration option. With all concerns addressed and Junio's approval of the approach, this patch appears ready for merging as a regression fix for the hook subsystem.
