Pushkar Singh follows up on the thread about `git shortlog --committer` documentation inconsistencies, confirming Junio C Hamano's earlier analysis. The issue stems from `git-shortlog.txt` including documentation for `--committer=<pattern>` (inherited from `rev-list-options.adoc`) while the implementation only supports `--committer` as a no-value alias for `--group=committer`. 

Pushkar plans to submit a documentation patch to resolve this mismatch by making the options unambiguous in the man page. This aligns with Junio's earlier recommendation to update the documentation rather than extend the implementation, as supporting pattern matching would create parsing ambiguities and misalign with `git log` behavior. The patch will need to clearly document `--committer` as a simple flag while removing references to the unimplemented pattern-matching variant.

This is a straightforward documentation fix that follows the thread's consensus. The patch should be uncontroversial as it implements the direction already endorsed by the maintainer. The key technical detail is that `builtin/shortlog.c` currently rejects `--committer=foo` with an error, and the documentation needs to reflect this reality rather than the inherited pattern-matching behavior from `git log`.
