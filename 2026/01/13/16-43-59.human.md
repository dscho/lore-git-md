This is part of the ongoing `the_repository` removal effort, specifically targeting configuration variables that are currently stored globally. The patch series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) introduces a new `struct repo_config_values` (embedded directly in `struct repository`) to store configuration values that were previously global.

The series demonstrates the approach with three configuration variables:
1. `core.attributesFile` (string)
2. `core.sparseCheckout` (boolean) 
3. `branch.autoSetupMerge` (enum)

Key changes in v2:
- Renamed the struct from `config_values` to `repo_config_values`
- Moved the struct and related declarations to `environment.[ch]`
- Embedded the struct directly in `struct repository` (avoiding separate allocation)
- Updated all access sites to use the new repository-scoped storage

The approach preserves the current eager loading behavior while eliminating globals, addressing concerns raised in previous discussions. Phillip Wood provided key architectural guidance, suggesting the direct embedding pattern that matches how `repo_settings` works. The changes affect over 20 files across various commands that interact with these configuration values.

This appears to be a solid technical approach to the problem, with careful attention to maintaining existing behavior while moving toward the project's architectural goals. As an RFC, it's seeking feedback on the overall design before extending it to more configuration variables. The intern has clearly incorporated previous review feedback and the patches show good attention to detail in updating all affected call sites.
