This is a bugfix patch for gitk, the Git repository browser GUI. The patch addresses two color configuration issues in the ref/tag drawing code:

1. The `tagfgcolor` setting was being ignored - all labels were using `headfgcolor` regardless of type
2. The outline color for heads was hardcoded to black instead of respecting the `headoutlinecolor` setting

The changes make gitk actually use these existing but previously ignored color configuration options. The patch is small and focused, touching only the `drawtags` procedure in gitk. It maintains backward compatibility by keeping the hardcoded colors for non-head refs (black outline and #ddddff fill) while making the configurable colors work for heads and tags.

The author notes they discovered this while working on a VSCode extension that exports color themes to gitk, which led them to notice the configuration wasn't having any effect. The patch includes a link to a screenshot showing the working colors after the fix.

This appears to be a straightforward, well-scoped fix for a clear bug where configuration options weren't being respected. The changes are minimal and focused on the specific issue without introducing new complexity.
