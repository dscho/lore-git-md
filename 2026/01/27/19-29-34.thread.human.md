Junio Hamano has sent a two-patch series improving how `git switch` handles ambiguous remote branch names. Currently, when multiple remotes have branches with the same name, `git switch` correctly fails but suggests using `git checkout` in its advice message - an inconsistency since `git switch` is meant to be the modern replacement for branch-switching operations.

The first patch refactors the internal checkout machinery to track whether an operation originated from `git checkout`, `git switch`, or `git restore`. The second patch then uses this information to provide appropriate advice - when the failure comes from `git switch`, it will now suggest `git switch --track` rather than `git checkout --track`. The changes touch the checkout implementation in builtin/checkout.c and include tests verifying the improved messaging.

This is a small but thoughtful improvement that makes Git's behavior more consistent and user-friendly, ensuring the advice matches the command the user actually ran. The changes are straightforward with clear test coverage, addressing a real-world usability issue reported by a user.
