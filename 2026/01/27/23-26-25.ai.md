This is a bugfix thread addressing tab alignment in git-gui's diff viewer, specifically the inconsistency between git-gui and gitk on Windows with Tcl/Tk 8.6. The current discussion focuses on technical concerns raised by Junio C Hamano about the proposed solution's interaction with combined diffs.

Junio points out that the patch's use of `apply_tab_size 1` for regular diffs may conflict with the existing behavior for combined diffs (which already uses `apply_tab_size 1` to account for their two-column prefix). He questions whether both uses can be correct simultaneously, suggesting this might indicate an off-by-one error in either the original code or the new patch. The thread references commit a43c5f51 from 2012 which introduced the tab size configuration, showing the historical context for this behavior differences.

The core issue now is determining the correct tab size settings for different diff contexts:
- Regular diffs (single parent) currently use `apply_tab_size 0`
- Combined diffs (two parents) use `apply_tab_size 1`
- The new patch would make regular diffs also use `apply_tab_size 1`

Junio suggests the solution may need to distinguish between these cases more carefully, possibly requiring different tab size settings for different diff types. The thread awaits clarification on whether the combined diff handling needs adjustment and verification that there are no display errors in either context. The original constraints (no text modification, preserving staging functionality) remain, but the solution now needs to handle these newly identified edge cases.
