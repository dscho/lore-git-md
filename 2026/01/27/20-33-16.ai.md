This is a bugfix patch for git-gui that addresses tab alignment issues in the diff viewer. It's the second approach in a thread where the maintainer Johannes Sixt previously rejected a text-conversion solution because it broke staging functionality.

The patch removes the problematic `expand_tabs` function (which converted tabs to spaces) and instead uses Tk's native `apply_tab_size` configuration to adjust tab rendering without modifying the underlying text. This preserves the ability to stage individual lines/hunks while fixing the visual misalignment between git-gui and gitk on Windows.

The change is minimal - just 1 line added and 23 removed - showing the simpler solution that maintains compatibility with git-gui's existing behavior. The patch appears well-aligned with the maintainer's requirements from earlier in the thread, though it will need verification that the tab display works correctly in all contexts without introducing new display artifacts.

This represents the technically preferred solution compared to the previously rejected approach, as it fixes the visual issue without changing the text content that staging operations depend on. The patch is part of an RFC v2 series where the author is presenting both approaches for comparison, though this one clearly matches the maintainer's stated constraints better.
