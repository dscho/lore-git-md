This is a bugfix patch for the `git last-modified` command, part of a completed series that has already been merged. The patch adds validation to ensure the input revision is commit-ish (can be resolved to a commit) rather than accepting any object type, which previously triggered a BUG().

The change prevents crashes when users pass tree objects (like `HEAD^{tree}`) by using `repo_peel_to_type()` to verify the input resolves to a commit. It includes a clear error message when validation fails and adds test coverage for both the new validation and proper handling of annotated tags.

This was the final technical patch in the series, following earlier work on input validation, error handling, and memory leak fixes. The patch demonstrates careful attention to edge cases and maintains the series' high standard of test coverage. While the technical implementation is now complete, there remains an ongoing discussion about documentation terminology around "revision" vs "commit" semantics in Git's object model.
