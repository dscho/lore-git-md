Thread identity: Bug report and proposed fix for `git switch`'s ambiguous remote branch tracking hint, where it incorrectly suggests using `git checkout --track` instead of `git switch --track`.

Core problem: When `git switch` fails to find a unique remote tracking branch, the error message shows an example using the older `git checkout --track` syntax rather than the newer `git switch --track` equivalent, creating user confusion during branch switching operations.

Current status: Junio C Hamano (maintainer) has provided an unfinished patch implementing command-specific hints - `git switch` will suggest `git switch --track` while `git checkout` keeps suggesting `git checkout --track`. This approach is explicitly preferred over standardizing on `git switch` recommendations, as `git checkout` is not being deprecated. The patch needs test coverage and usage string consolidation before being ready for merging.

Key technical details: The fix modifies `builtin/checkout.c`'s shared implementation between `git switch` and `git checkout`. It introduces a new enum to track the command type (SWITCH/CHECKOUT) which flows through `parse_branchname_arg()` to `parse_remote_branch()`, allowing command-appropriate error messages. The changes are localized to these functions while maintaining the existing behavior for each command.

Open questions: None remaining on technical approach - Junio's direction resolves the original debate. Implementation tasks remain: (1) consolidate usage strings across commands, (2) add tests verifying the command-specific hints work as intended.

Participant positions: Original reporter identified the inconsistency. Junio C Hamano has settled the design question in favor of command-specific hints (not standardizing on `git switch`) and provided implementation direction. No other contributors have commented yet on the specific patch.

Related work: Part of Git's ongoing effort to migrate users from multi-purpose `git checkout` to focused commands `git switch` (branch operations) and `git restore` (file operations), while maintaining backward compatibility for existing `git checkout` usage. Similar transitions have occurred in documentation and other error messages.
