This is the final patch in a series adding a `--keys` flag to `git repo info` for machine-readable repository metadata access. The thread has seen several iterations addressing format handling and naming consistency, with this version incorporating all substantive feedback.

The patch implements strict validation to prevent `--keys` from being combined with `--all` or explicit key requests, adds comprehensive tests, and unifies the output format naming to "lines" (replacing the redundant "keyvalue" format). Patrick Steinhardt noted a minor capitalization issue in the documentation that the author will fix, along with collecting similar nits for a future cleanup series.

The implementation is now ready for integration into `next`, replacing the earlier queued version.
