Feature patch improving `git add -p` navigation between files. This is the second version of a patch from Abraham Samuel Adekunle that enhances the interactive staging interface by adding '<' and '>' options to move between files when all hunks in the current file have been decided.

The key changes in this version:
- Adds explicit navigation between files ('<' for previous, '>' for next) that only appear when contextually relevant (not shown for single files, only '<' at first file)
- Modifies the workflow so users can continue editing a file even after deciding all hunks by pressing 'q' to submit all decisions
- Changes are focused in `add-patch.c` with significant but targeted modifications to the state handling and UI flow

The patch appears well-structured with clear commit messages explaining the behavior changes. The author notes that test updates in t/3701-interactive.sh are still pending, which will be needed before this could be merged. This looks like a useful quality-of-life improvement for the interactive staging workflow, particularly when working with multiple files.
