This is a feature proposal to add 'ls' as an alias for 'list' subcommands in Git. The thread discusses whether there's precedent for such aliases in Git's existing commands, with Daniel Tang pointing to `git remote rm` being an alias for `git remote remove` as a similar case. They argue that many CLI tools use 'ls' as shorthand for 'list' and that programmers frequently expect this convention.

The email notes that while some Git commands like `git-ls-files` use 'ls', others like `git stash list` and `git worktree list` don't accept the shorter form. The author suggests this inconsistency causes friction, mentioning they personally encounter this mismatch about once a week. They cite examples from npm and Docker where 'ls' is accepted as an alias.

The proposal appears motivated by improving user experience through consistency with common CLI conventions, though it doesn't yet include a concrete implementation.
