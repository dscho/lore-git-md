This is a bugfix patch series for git-gui, addressing tab alignment inconsistencies in the diff viewer between git-gui and gitk on Windows. The series represents a significant pivot from the original approach after maintainer feedback.

The first patch retains the initial space-conversion solution that was previously rejected by Johannes Sixt (Git GUI maintainer) due to breaking staging functionality. The second patch introduces a new approach using Tk's native `apply_tab_size` setting, which appears to align with Johannes Sixt's requirement to preserve original text content while fixing visual alignment.

The key technical insight is maintaining compatibility with git-gui's "Stage Line/Hunk for Commit" feature, which fails when working with space-converted text. The new solution avoids text modification entirely by configuring Tk widget behavior directly. This addresses the root visual inconsistency while respecting the decades-old patch display conventions that Johannes Sixt emphasized must be preserved.

The patch series is marked RFC (Request For Comments) and version 2, indicating the author is still seeking feedback on the new direction. Testing will be needed to verify the `apply_tab_size` approach works reliably across different contexts without introducing new display artifacts. The solution is minimal - just 3 lines changed in `git-gui/lib/diff.tcl` - but could resolve a long-standing UI inconsistency if proven robust.
