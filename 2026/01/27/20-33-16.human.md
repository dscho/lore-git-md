Bugfix for git-gui's diff viewer tab alignment, following maintainer guidance.

This is the second of two competing approaches to fix tab alignment in git-gui's diff viewer, where tabs were rendering inconsistently compared to gitk on Windows. The maintainer Johannes Sixt had previously rejected a text-conversion approach (submitted in patch 1/2) because it broke the "Stage Line/Hunk for Commit" functionality by modifying the actual text content.

This patch instead takes the maintainer's preferred approach: using Tk's native `apply_tab_size` configuration to adjust tab rendering without changing the underlying text. The change is minimal (just 1 line added and 23 removed) and preserves the exact text content needed for staging operations. The patch removes the now-unnecessary `expand_tabs` helper function entirely.

Given the maintainer's clear technical constraints and this solution's alignment with them, this approach is likely to be accepted if testing confirms it works reliably across all git-gui contexts. The patch appears well-targeted to solve the visual misalignment while maintaining all existing functionality exactly as the maintainer requires.
