Feature patch improving `git add -p` navigation between files. This is the second version of a patch from Abraham Samuel Adekunle that enhances the interactive staging interface by adding '<' and '>' navigation between files when all hunks in a file have been decided.

The key changes in this version:
- Adds explicit '<' and '>' navigation options that appear in the UI only when contextually relevant (not shown for single files, only '<' at first file, both in middle files)
- Modifies the workflow so that after deciding all hunks in a file, the session doesn't automatically advance - users must explicitly choose to move forward/backward or quit
- Fixes an undocumented behavior where 'q' would submit all decisions when hunks were decided
- Restructures the patch application to happen after all file navigation is complete rather than per-file

The implementation touches `add-patch.c` with significant changes to the state handling and UI flow (102 insertions, 37 deletions). The patch appears well-structured with clear commit message explaining the behavioral changes. Notably missing are test changes in t/3701-interactive.sh which the author indicates will come after UI design consensus.

This continues the thread's focus on improving the interactive staging workflow quality-of-life without major architectural changes. The dynamic UI showing navigation options only when relevant is a thoughtful touch that maintains simplicity while adding functionality.
