This is a two-patch series from maintainer Junio C Hamano that improves the advice messages from `git switch` when dealing with ambiguous remote branch names. The series stems from a user report where `git switch` correctly failed when multiple remotes had branches with the same name, but then suggested using `git checkout` in its advice message rather than `git switch`.

The first patch refactors the internal call chain of checkout/switch/restore commands to pass a program-readable token identifying which top-level command is being executed. This allows lower-level helper functions to know whether they're being called from `git checkout`, `git switch`, or `git restore`. The second patch then uses this information to tailor the advice message - when the operation originated from `git switch`, it will now suggest using `git switch --track` rather than `git checkout --track`.

The changes touch the checkout machinery in builtin/checkout.c and add tests in t2027-checkout-track.sh to verify the improved advice messages. This is a straightforward quality-of-life improvement that makes Git's behavior more consistent and user-friendly when suggesting next steps after an ambiguous branch name error.
