This is a refactoring patch that prepares for improved advice messages in the `git checkout`/`switch`/`restore` command family. It's the first of a two-patch series from the maintainer Junio C Hamano.

The patch introduces an enum to track which of the three commands (`checkout`, `switch`, or `restore`) is being executed, replacing the previous approach of passing usage strings. While this doesn't yet change any user-visible behavior, it sets up the infrastructure needed for the second patch to customize advice based on the specific command invoked.

Key technical changes:
- Adds `enum checkout_command` with values for each command type
- Moves the usage strings inside `checkout_main()` and selects them via the enum
- Updates all three command entry points (`cmd_checkout`, `cmd_switch`, `cmd_restore`) to pass their respective enum values
- Maintains identical external behavior at this stage

The patch is cleanly focused - it touches only `builtin/checkout.c` and makes no functional changes yet. This is clearly preparatory work for the behavior improvements coming in patch 2/2, where the enum will be used to provide more appropriate advice messages when branch switching fails due to ambiguous remote names.
