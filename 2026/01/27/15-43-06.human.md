This is a feature patch for the `git add -p` interactive hunk selection interface, part of an ongoing effort to improve the workflow when staging changes across multiple files.

The patch introduces new navigation options ('<' and '>') to move between files when all hunks in the current file have been decided. It also modifies the behavior when all hunks are decided, showing a "What now?" prompt that allows reworking the file, moving to adjacent files, or submitting the decisions. The author notes some inconsistencies in the current behavior of 'q' (quit) that this change surfaces but doesn't yet address.

The patch appears to be a second iteration after feedback from Junio Hamano, focusing specifically on the multi-file navigation aspect. The author acknowledges that test updates (t3701) will come later once the UI approach is settled. The changes are concentrated in add-patch.c with significant but focused modifications (102 insertions, 37 deletions).

This looks like a thoughtful improvement to a common workflow pain point, though the discussion around the 'q' behavior suggests there may be more edge cases to consider before finalizing the approach. The patch seems ready for review but may need another iteration to address any feedback about the quit behavior and to add tests.
