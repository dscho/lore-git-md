This is the second patch in Junio C Hamano's series improving `git switch` advice messages when encountering ambiguous remote branch names. Building on the infrastructure changes from patch 1 (which introduced an `enum checkout_command`), this patch modifies the advice text to match the command actually used - suggesting `git switch --track` instead of `git checkout --track` when the failure occurs during `git switch`.

The key change is passing the `which_command` enum through to `parse_remote_branch()`, where it's used to select the appropriate command name in the advice message. The patch includes tests verifying both the old `checkout` behavior and new `switch` behavior, ensuring the correct command appears in the hint text. This is a clear user experience improvement that makes Git's behavior more consistent by matching advice to the command actually used.

The changes are well-contained, touching only the advice message generation while maintaining all existing functionality. The test coverage is thorough, checking both the positive case (correct command appears) and negative case (wrong command doesn't appear) for both `checkout` and `switch`. As the second part of a two-patch series, this completes the refactoring-to-feature progression started in patch 1.
