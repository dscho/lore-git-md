This thread proposes adding 'ls' as an alias for 'list' subcommands across Git, citing CLI convention and existing partial precedents like `git remote rm/remove`. Daniel Tang argues the change would improve UX by matching programmer expectations, noting frequent personal encounters with the current inconsistency between commands that do (`git-ls-files`) and don't (`git stash list`, `git worktree list`) support the shorthand.

The discussion centers on whether this aligns with Git's design principles, with Junio Hamano expressing initial skepticism about expanding aliases without stronger internal precedent. Key open questions include whether the UX benefit justifies the change, and if so, which commands should be included. The thread references external CLI conventions (npm, Docker) but lacks concrete implementation details or consensus on scope. No patches have been proposed yet.
