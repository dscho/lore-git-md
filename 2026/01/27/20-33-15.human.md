This is a bugfix patch for git-gui's diff viewer, addressing tab alignment issues on Windows with Tcl/Tk 8.6. It's part of an ongoing thread where the maintainer Johannes Sixt has rejected previous approaches that modified the text content, insisting on preserving the original text for staging operations.

The patch proposes converting tabs to spaces before rendering in Tk, which would visually fix the misalignment but was already rejected in the thread for breaking the "Stage Line/Hunk for Commit" functionality. The author has submitted this alongside an alternative approach (in RFC v2) that uses Tk's native display configuration instead, which appears more likely to meet the maintainer's requirements.

The technical change adds an `expand_tabs` procedure that replaces tabs with spaces according to `gui.tabsize`, modifying the text before it's inserted into the diff viewer. While this would visually align tabs like gitk does, the thread context indicates this approach won't be accepted as it violates the constraint of preserving original text content for staging operations. The patch serves mainly as a comparison point against the preferred solution that doesn't modify the text.
