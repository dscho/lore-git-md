This is a bugfix patch for the `git last-modified` command, part of a completed series that has already been merged. The patch adds validation to ensure the input revision is commit-ish (can be resolved to a commit object), preventing a BUG() when given a tree object directly.

The change introduces `repo_peel_to_type()` to verify the object type before processing, with a clear error message when the input isn't commit-ish. The test suite is expanded to cover both the happy path (annotated tags resolve correctly) and error case (tree objects are rejected with appropriate messaging).

This represents the final hardening of the command's input validation, following earlier patches that addressed memory leaks and error handling. The implementation now cleanly handles all error cases with proper resource cleanup via `goto out` patterns. The error message wording reflects ongoing discussions about "revision" vs "commit" terminology in Git's documentation, though the technical behavior here is uncontroversial - it simply enforces that the command operates on commit objects.
