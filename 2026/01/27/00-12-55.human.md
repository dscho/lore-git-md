This is part 11 of a 12-part series refactoring Git's hook subsystem to use a new standardized API with parallel execution support. The patch converts receive-pack's update and post-update hooks to the new `run_hooks_opt` interface while maintaining the existing sequential execution behavior (via `.jobs == 1` default).

The key changes replace direct `child_process` setup with the new hook API, while preserving the sideband output behavior for remote clients. The patch handles stderr redirection carefully when sidebands are enabled, using async muxer threads to properly route hook output. Emily Shaffer raises a question about whether the muxer setup correctly handles multiple hooks' output when parallel execution is eventually enabled.

The series has already received extensive review and is in its final polishing stages, with only minor documentation tweaks and naming decisions remaining. This particular patch carries sign-offs from both primary authors (Adrian Ratiu and Emily Shaffer) as well as key reviewers (Jeff King and Ævar Arnfjörð Bjarmason), indicating broad consensus on the technical approach.
