This is a feature proposal to add 'ls' as an alias for 'list' subcommands in Git. Daniel Tang suggests aligning with common CLI conventions where tools like npm and Docker accept abbreviated subcommands (e.g., 'ls' for 'list'). The patch specifically targets commands like `git stash list` and `git worktree list`, proposing to make them also respond to `git stash ls` and `git worktree ls`.

The proposal references existing Git patterns where subcommands have aliases (like `git remote rm` for `git remote remove`), and notes that some Git commands already use 'ls' (like `git ls-files`), creating inconsistency. The author mentions frequently encountering this friction in their own workflow.
