This is a bugfix targeting the shared checkout/switch/restore implementation in `builtin/checkout.c`. The patch addresses an inconsistency where `git switch` would suggest using `git checkout --track` in its error message when no unique remote branch is found, rather than recommending the equivalent `git switch --track` syntax.

Junio C Hamano (the maintainer) provides an unfinished patch that would make the error message match the command being run (`git switch` suggests `git switch --track`, `git checkout` suggests `git checkout --track`). He explicitly states a preference for this approach over standardizing on `git switch` recommendations, noting that `git checkout` is not being deprecated. The patch introduces an enum to track which command is being executed and uses it to select the appropriate command name in the error message.

The changes are focused on the `parse_remote_branch()` and `parse_branchname_arg()` functions, with plumbing to pass the command type through from the top-level `cmd_switch()` and `cmd_checkout()` functions. Junio notes two remaining tasks: consolidating usage strings and adding tests. The patch appears straightforward and well-scoped, addressing a clear inconsistency in the user experience when dealing with ambiguous remote branches.
