This is the second patch in Junio C Hamano's series improving `git switch` advice messages when encountering ambiguous remote branch names. Building on the infrastructure changes from the first patch (which introduced an `enum checkout_command`), this update makes the advice messages context-aware - suggesting `git switch --track` instead of `git checkout --track` when the failure occurs during `git switch`.

The patch modifies `parse_remote_branch()` to accept the command type parameter and use it to generate appropriate advice. The test fails when run with `git switch`, it now suggests using `git switch --track` rather than the previous `git checkout --track` advice. The change maintains consistency with the command the user actually ran, reducing confusion.

The implementation is clean and well-tested, with new test cases in t2027-checkout-track.sh that verify both the old `checkout` behavior and new `switch` behavior. This is a logical follow-up to the first patch's refactoring, demonstrating the value of the enum infrastructure for command-specific behavior. The change addresses a real user experience issue reported by Simon Cheng, where the advice didn't match the command being used.
