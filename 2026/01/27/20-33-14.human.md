Bugfix for git-gui's tab display alignment on Windows, addressing a visual inconsistency with gitk. This is the second iteration of Chris Idema's patch series, now proposing a different approach after feedback from Johannes Sixt (Git GUI maintainer).

The core issue is that git-gui displays tabs misaligned compared to gitk when using Tcl/Tk 8.6 on Windows. The initial solution converted tabs to spaces, but Johannes Sixt vetoed that approach because it would break the "Stage Line/Hunk for Commit" functionality which relies on the original text.

This v2 series keeps the original tab-conversion patch (for reference) but adds a new approach using Tk's native `apply_tab_size` setting instead. This appears to satisfy the maintainer's requirement of preserving the original text while fixing the visual alignment. The solution is marked as RFC" as Chris notes it needs further testing to confirm it works in all contexts without introducing new display issues.

The patch is small (3 lines changed) and focused on the diff viewer in `git-gui/lib/diff.tcl`. Johannes Sixt's previous feedback makes clear the solution must not modify the actual text content, so this configuration-based approach seems promising if it proves reliable across different Tk environments. The thread shows good progress from initial blocked state to a potentially viable path forward.
