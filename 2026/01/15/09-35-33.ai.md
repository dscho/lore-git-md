This is the second patch in a refactoring series to standardize commit list function names. Building on the first patch that renamed `copy_commit_list()` to `commit_list_copy()`, Patrick Steinhardt now renames `reverse_commit_list()` to `commit_list_reverse()` to match Git's naming conventions where functions operating on a struct are prefixed with the struct name.

The change affects merge operations (merge-tree, merge-ort, sequencer), stash export, and commit list manipulation. Like the first patch, this includes a temporary compatibility wrapper that will be removed after Git 2.53, allowing in-flight topics to transition gradually. The patch touches core merge machinery but makes no functional changes - it's a straightforward mechanical rename that improves API consistency.

The series demonstrates Patrick's characteristic attention to backward compatibility during refactoring, with each patch handling one focused rename operation. This particular change affects fewer files (6) than the upcoming `free_commit_list()` rename (which will touch 40 files), but follows the same careful pattern of maintaining the old name temporarily to avoid breaking existing code.
