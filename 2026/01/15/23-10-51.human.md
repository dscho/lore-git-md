This is a security-related discussion about controlling ANSI escape sequences in Git's sideband channel. The thread has been working through the tradeoffs between security and backward compatibility for handling control characters in Git's output.

brian m. carlson agrees with Jeff King's proposal to make the new security controls opt-in rather than enabled by default. This preserves backward compatibility while still giving security-conscious users the ability to restrict potentially dangerous control sequences. The discussion has reached consensus on this approach after considering real-world breakage scenarios (like Heroku deployments and Cargo builds) that would be affected by stricter defaults.

The implementation will use a new `sideband.allowControlCharacters` configuration option with bitmask flags to control different types of sequences (color, cursor movement, erase). Windows will maintain stricter defaults due to platform-specific security considerations. The thread shows Git's typical security response pattern - technical implementation first, then policy refinement based on real-world impact, with the maintainer making the final call balancing security and compatibility.
