This is a bugfix for the `git subtree` contrib script, specifically addressing an inconsistency in how the `--prefix` argument is validated during split operations.

The patch fixes a subtle issue where `git subtree split` was checking the prefix directory against the working tree rather than the specified commit. This could lead to incorrect behavior when splitting a historical commit where the directory structure differed from the current working tree. The change ensures the prefix validation uses `git ls-tree` against the target commit itself.

The modification is straightforward - it adds a new validation check in the `cmd_split` function while preserving all existing behavior. The patch appears well-contained and correctly handles the edge case it aims to address. Since `git subtree` is a widely used contrib script for managing project subtrees, this fix helps prevent potential confusion when working with historical states.
