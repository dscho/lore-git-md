The thread addresses a bug in `git subtree` where the `--prefix` validation during split operations was checking the working tree rather than the target commit, causing failures when splitting older commits where the subtree existed but was later removed. Pushkar Singh's v3 patch fixed this by using `git ls-tree` against the target commit while keeping working tree validation for add/merge commands. The patch added test coverage and fixed style issues as requested by Junio C Hamano, appearing complete.

However, Josh Steadmon has now reported a regression from this fix - test case 17 ("split requires path given by option --prefix must exist") is failing in real-world use. While the patch correctly handles the original case of splitting older commits, it appears the new validation logic may be too strict in other scenarios. This was discovered through a build system failure that bisected to this commit, indicating the issue affects actual usage. The patch will likely need another revision to properly handle this edge case while maintaining the intended fix for the original problem. The thread has shifted from celebrating a completed fix to investigating this newly discovered regression.
