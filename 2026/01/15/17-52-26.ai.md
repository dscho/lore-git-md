Bugfix for the `git subtree` contrib script, addressing validation of the `--prefix` argument during split operations. This is the third iteration of a patch that fixes an inconsistency where `git subtree split` was validating the prefix path against the working tree rather than the specified commit.

The patch modifies `contrib/subtree/git-subtree.sh` to use `git ls-tree` against the target commit for validation during split operations, while maintaining working tree validation for add/merge commands. This fixes cases where splitting an older commit would fail if the subtree existed in that commit but was later removed from the working tree.

Key technical changes:
- Adds commit-based validation using `git ls-tree -d` in the split command
- Keeps working tree validation for add/merge commands
- Adds a new test case in `contrib/subtree/t/t7900-subtree.sh` that verifies the fix by:
  - Creating a commit with a subtree
  - Removing the subtree in a later commit
  - Verifying split still works when targeting the earlier commit

The v3 patch addresses Junio C Hamano's feedback from v2 by adding the missing test coverage and fixing indentation issues. The implementation appears clean and focused, with the test case clearly demonstrating the fixed behavior. This resolves the original inconsistency while maintaining the existing validation patterns for other operations.
