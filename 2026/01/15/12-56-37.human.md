Performance optimization for sparse-checkout pattern sorting. This is a follow-up to amisha's initial patch that improves the efficiency of building sorted pattern lists in the sparse-checkout code.

The patch addresses all three locations in `builtin/sparse-checkout.c` where patterns were being inserted one by one into a string_list with O(n^2) complexity. As Jeff King noted in the review, the v1 patch only fixed one of these locations. The new version consistently changes all three instances to use `string_list_append()` followed by a single `string_list_sort()`, bringing the complexity down to O(n log n).

The changes maintain identical functionality while being more efficient, since the hashmap entries are already guaranteed to be unique (making the explicit `string_list_remove_duplicates()` calls redundant). The patch is clean and focused, exactly following the optimization approach suggested in the review.

This appears ready for merging - it's a straightforward performance win with no behavior change, and the implementation now covers all relevant cases in the sparse-checkout code. The commit message could perhaps be slightly expanded to mention that it addresses all three locations (not just the initial one), but the technical content is solid.
