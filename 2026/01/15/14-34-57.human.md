This is a follow-up discussion about terminology in error messages for the recently merged `git last-modified` bugfix series. The thread has already concluded with all technical changes merged, but Kristoffer Haugsbakk raises a point about the glossary definition of "revision" versus "commit-ish". 

The core of this email is a minor clarification about Git's documentation: while the gitglossary(7) defines "revision" as a synonym for commit, Kristoffer notes that "commit-ish" is also a documented term in the IDENTIFIER TERMINOLOGY section of git(1). This doesn't change the already-merged patches but provides additional context for future discussions about error message wording.

The discussion shows how terminology choices can continue to be refined even after technical consensus is reached. In this case, the series author Toon Claes had already made a conscious choice to use "revision" in error messages for end-user clarity, despite Patrick Steinhardt's suggestion to use the more technically precise "commit-ish". The thread demonstrates Git's attention to both technical precision and user-facing communication.
