This is a bugfix patch in a series addressing regression in error message reporting for batched reference updates. The patch focuses on `git update-ref --batch-updates` specifically.

The discussion centers around how to best present error messages when reference updates fail. The current implementation in patch 4/6 would replace the structured "rejected REF OLD NEW REASON" output format (documented in git-update-ref(1)) with potentially less structured backend error messages. Jeff King points out this would break the documented machine-readable format and suggests alternatives.

Key technical points:
1. The existing output format is documented and should remain stable
2. Backend error messages often include redundant information already shown in the structured format
3. Jeff proposes a short-term solution of showing backend errors via stderr while preserving the structured format
4. Karthik agrees this is a good compromise and suggests deferring format improvements

The patch will be modified to maintain the documented output format while ensuring error details remain available, with future work planned to better integrate the two. This maintains backward compatibility needed while still addressing the core regression where detailed messages were being lost.

The discussion shows careful consideration of both user-facing output stability and debugging needs, with Jeff's review catching an important documentation constraint. The resolution preserves existing behavior while leaving room for future improvements to error message presentation.
