Performance optimization for sparse-checkout pattern sorting with a follow-up on duplicate handling.

René Scharfe points out a subtle issue in Amisha Chhajed's v3 patch that optimizes sparse-checkout pattern sorting from O(n²) to O(n log n). While the performance improvement itself is sound, René questions the removal of `string_list_remove_duplicates()` calls in the conversion from `string_list_insert()` to `string_list_append()` followed by sorting.

The key observation is that while `string_list_insert()` inherently prevents duplicates, the new approach using `string_list_append()` would need explicit duplicate removal when dealing with the `recursive_hashmap` case, where user input can contain duplicate patterns. This doesn't affect the `parent_hashmap` case where entries are guaranteed unique.

The thread has established consensus on the core optimization approach, with Jeff King having previously identified this edge case. René's email serves as a final verification before the patch can be merged, ensuring the optimization doesn't accidentally reintroduce duplicate patterns in the sparse-checkout configuration. This is part of the ongoing sparse-checkout performance work, though focused on a localized improvement rather than architectural changes.
