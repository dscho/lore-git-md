Refactoring patch to standardize commit list function naming. This is the first in a 3-part series from Patrick Steinhardt that renames `copy_commit_list()` to `commit_list_copy()` to match Git's established pattern of `struct_name_verb()` function naming. The change affects 6 files across core commands (commit, merge, revision, sequencer) and includes a compatibility wrapper to avoid breaking in-flight work. The wrapper will be removed after Git 2.53.

The patch is purely mechanical with no functional changes - it simply makes the API more consistent. Each subsequent patch in the series will handle renaming other commit list functions (`reverse_commit_list` and `free_commit_list`) to follow the same pattern. The changes touch merge machinery, revision walking, and commit creation paths, but since this is just a refactoring, there should be no observable behavior difference. The careful addition of compatibility wrappers shows attention to minimizing disruption during the transition.
