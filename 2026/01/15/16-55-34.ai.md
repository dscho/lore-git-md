Junio argues that the current behavior - allowing explicitly named files to be added even when other named files are ignored - makes practical sense. He notes that if ignored files blocked all additions, common patterns like `git add .` or `git add *` would become unusable when any ignored files are present. He also points out the technical challenge of distinguishing between explicitly typed filenames and shell-expanded ones.

The maintainer suggests that changing this behavior would constitute a new design rather than a bugfix, and expresses skepticism about whether such a change would be useful given the shell expansion limitations. The discussion remains open-ended, with Junio not taking a firm position on whether the behavior should be standardized or documented differently.
