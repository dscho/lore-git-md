This is a bug report about inconsistent behavior in `git add` when dealing with ignored versus non-existent files. Jon Forrest observes that:

1. When adding a mix of existing and non-existent files (`git add x bogus_file`), the entire command fails and nothing is added to the index (as previously confirmed by Jeff King).

2. However, when adding a mix of existing and ignored files (`git add file1 jon` where file1 is ignored), Git warns about the ignored file but still adds the non-ignored file (jon) to the index.

The reporter expected both cases to behave consistently - either failing completely or proceeding partially in both scenarios. The current behavior appears inconsistent, with ignored files triggering a warning but allowing partial operation, while missing files cause complete failure. The email seeks confirmation whether this is intentional design or a bug worth reporting.

The issue touches core index manipulation behavior in `git add`, specifically how it handles different types of invalid paths. The inconsistency could affect scripts or tools that rely on predictable failure modes when adding files. While not a critical bug, it represents a subtle behavioral edge case that might warrant documentation or standardization.
