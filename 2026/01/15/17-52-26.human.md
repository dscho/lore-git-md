Bugfix for the `git subtree` contrib script, addressing validation of the `--prefix` argument during split operations. This is the third version of a patch that fixes an inconsistency where `git subtree split` was validating the prefix path against the working tree rather than the specified commit.

The patch makes two key changes:
1. Modifies the split command to validate the prefix using `git ls-tree` against the target commit rather than checking the working tree
2. Adds a test case that verifies the fix works when splitting a commit where the subtree existed but was later removed

The v3 iteration addresses Junio C Hamano's feedback from v2 by:
- Adding the missing test coverage that was previously noted
- Maintaining consistent indentation style (using tabs)
- Keeping the change focused on just the split command's validation needs

The fix is well-contained and follows the established error message patterns in the script. The new test provides clear regression protection for this case. This appears ready for inclusion, solving a real inconsistency in the subtree command's behavior.
