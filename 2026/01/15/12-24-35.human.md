This is a bugfix for the `git subtree` contrib script, addressing validation of the `--prefix` argument during split operations. The patch fixes an inconsistency where the script validates prefix existence for `add` and `merge` commands but not for `split`, which could lead to confusing behavior when splitting commits where the prefix doesn't exist in the working tree but does exist in the target commit.

The change modifies `cmd_split` to use `git ls-tree` to verify the prefix directory exists in the specified revision before proceeding, rather than checking the working tree. This makes the behavior more consistent with user expectations when working with historical commits. The implementation is clean and focused, maintaining the script's existing style while closing a clear gap.

The fix addresses a real pain point for users who need to split subtrees from older commits, though the commit message could better illustrate the problematic scenario. This appears ready for inclusion as a straightforward improvement to the subtree script's reliability.
