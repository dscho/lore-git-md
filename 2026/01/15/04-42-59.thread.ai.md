Bug report for `git subtree split -P` path validation: The command incorrectly checks for the specified path in the working directory rather than the target revision when splitting from a non-checked-out branch. This causes misleading "does not exist" errors when the path exists in the revision but not locally, particularly problematic on Windows where some paths in the branch may be incompatible. The reporter (using Git for Windows 2.52.0) suggests validating against the revision's tree instead of the working copy. The issue appears in core `git subtree` logic, not platform-specific code. No proposed patch yet, but the analysis indicates the validation occurs in the command's early path-checking phase.
