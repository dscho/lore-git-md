This is part 7/14 of Patrick Steinhardt's ongoing object database (ODB) abstraction series, introducing a unified interface for iterating over objects in Git's storage layer. The patch adds `odb_for_each_object()`, which provides a single entry point for iterating through all objects (both loose and packed) in a given object database.

The new function wraps the iteration logic that was previously split across loose and packed storage backends, using the standardized callback type `odb_for_each_object_cb` introduced earlier in the series. It handles both local and alternate object databases, with flags to control whether to include promisor objects or restrict to local-only sources.

This is a key piece of infrastructure for the larger ODB abstraction effort, which aims to make Git's object storage backend pluggable. The implementation is clean and well-documented, with clear header comments explaining the function's behavior and return value semantics. As noted in the commit message, subsequent patches will migrate existing callers to use this new unified interface.

The patch follows the series' established pattern of introducing new APIs while temporarily maintaining old ones, allowing for incremental conversion of callers. This careful approach minimizes disruption while moving toward the long-term goal of backend-agnostic object storage.
