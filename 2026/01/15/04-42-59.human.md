This is a bug report for the `git subtree` command, specifically about its `split` subcommand's path validation behavior. The author, book lv, describes a scenario where they wanted to split a subdirectory from a branch that couldn't be checked out on Windows due to problematic paths, even though the specific subdirectory they wanted was valid.

The current implementation incorrectly checks for the path's existence in the working directory rather than in the specified revision. This leads to a misleading error message ("does not exist; use 'git subtree add'") when the path actually exists in the target revision but not locally. The author provides a workaround (creating the directory locally) but argues this behavior should be fixed to check the revision instead.

The bug appears to be Windows-specific in its manifestation (due to path handling limitations), but the underlying issue affects all platforms. The patch would need to modify the path validation logic in `git subtree split` to examine the specified revision rather than the working tree. This seems like a reasonable and focused improvement to the command's behavior.
