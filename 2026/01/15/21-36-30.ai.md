This is a security-related discussion about ANSI escape sequence handling in Git's sideband channel, continuing the thread about CVE-2024-32002 and CVE-2024-52005. Junio C Hamano responds to Jeff King's proposal to make the new security controls opt-in rather than enabled by default.

The core technical implementation (bitmask flags for controlling color, cursor movement, and erase sequences) remains stable, but the debate has shifted to the default policy. Jeff King argues for maintaining backward compatibility by keeping the permissive behavior as default while providing the security controls as an opt-in feature for those who need stricter security. Junio expresses agreement with this approach, noting it would avoid breaking existing setups while still giving users the tools to lock down their configuration if desired.

This marks a potential resolution to the ongoing debate between Johannes Schindelin's original strict-defaults proposal and the real-world compatibility concerns raised by Brian m. carlson and others. The thread shows the project's typical pattern of technical implementation stabilizing first, followed by policy decisions informed by both security considerations and practical deployment experience. The configuration system's flexibility means the same code can support either security model, allowing the policy discussion to proceed without blocking the technical fixes.
