Git thread summary:

Bug report from Jon Forrest about inconsistent behavior in `git add` when handling invalid paths, with current behavior differing between:
- Non-existent files (`git add x bogus_file`): entire command fails, nothing added to index (confirmed by Jeff King)
- Ignored files (`git add file1 jon` where file1 is ignored): warns about ignored file but still adds non-ignored file (jon)

Junio C Hamano provides maintainer perspective on the ignored file case, arguing the current behavior makes practical sense for common workflows like `git add .` or `git add *` where some files may be ignored. He notes technical challenges in distinguishing explicitly typed filenames from shell-expanded ones, and suggests changing this would constitute a new design rather than a bugfix. 

The discussion highlights key technical constraints: the distinction matters for scripting use cases, and the current implementation treats shell-expanded paths the same as explicitly named ones once they reach `git add`. Junio remains open to discussion but skeptical about changing behavior given workflow implications. Open questions remain about standardizing/documenting the behavior and whether the current approach should be considered intentional design.
