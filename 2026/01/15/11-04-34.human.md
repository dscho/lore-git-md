This is patch 5/14 in Patrick Steinhardt's series on object database iteration, part of the broader ODB abstraction effort. The patch refactors packed object iteration to prepare for a backend-agnostic API.

The change extracts the core iteration logic from `for_each_packed_object()` into a new helper function `packfile_store_for_each_object_internal()`. This internal function handles the actual work of iterating through objects in a single packfile store while respecting the various iteration flags (LOCAL_ONLY, PROMISOR_ONLY, etc.). The original function now becomes a thin wrapper that coordinates across multiple packfile stores.

This is a mechanical refactoring with no behavior change - it's groundwork for the next patch which will introduce the new packed object iteration interface matching the loose object iteration API from patch 4/14. The changes are focused on packfile.c and maintain all existing functionality while making the code more modular.

The patch continues the series' pattern of carefully separating interface from implementation in service of the ODB abstraction. It touches core object storage code but is relatively low-risk since it's just reorganizing existing logic. The work relates to Taylor Blau's pack improvements and builds toward a unified object iteration API.
