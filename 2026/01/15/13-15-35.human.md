Performance optimization for sparse-checkout pattern handling, completing a series that improves sorting from O(n^2) to O(n log n). This v3 patch from Amisha Chhajed addresses all three locations in `builtin/sparse-checkout.c` where patterns were being inserted in O(n^2) time via `string_list_insert()`, switching them to use `string_list_append()` followed by a single sort. The changes maintain the same functionality while being more efficient for large pattern sets.

The patch also eliminates redundant `string_list_remove_duplicates()` calls since the patterns come from a hashmap that already guarantees uniqueness. This cleanup was suggested by Jeff King (Peff) in earlier review feedback, which also noted the opportunity to apply the optimization more broadly. The implementation is clean and focused, touching only the cone mode pattern handling code paths.

This appears to be the final iteration of this optimization, having incorporated all review feedback. The changes are well-contained within the sparse-checkout subsystem and align with ongoing performance work in this area (though this is a localized improvement rather than architectural). The patch looks ready for inclusion.
