Performance investigation follow-up on `git pack-refs --all` slowness. Jeff King (Peff) analyzes Martin Fick's performance data and identifies a likely culprit in the interaction between Git and JGit's handling of packed-refs files. The key insight is that JGit writes packed-refs without the "sorted" marker, forcing Git to perform extra validation passes on the file contents.

Peff explains that Git optimizes packed-refs access by binary-searching when the file is marked as sorted, but must fall back to linear scanning when this marker is missing. Since Gerrit uses JGit to write packed-refs files (without the marker), each Git operation incurs this overhead. He suggests testing this theory by manually adding the sorted marker to see if performance improves.

The email also notes that JGit should ideally support both the "sorted" and "fully-peeled" markers for better interoperability. While this doesn't directly address the NFS performance issues identified earlier, it provides a concrete optimization path that could significantly reduce the mmap/NFS overhead by minimizing file scans.
