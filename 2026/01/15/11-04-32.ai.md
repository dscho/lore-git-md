This is part 3 of Patrick Steinhardt's 14-part series introducing a new object database iteration API, continuing the ODB abstraction effort. The patch refactors loose object handling in `object-file.c` to extract a new `read_object_info_from_path()` function that reads object information given a filesystem path, replacing the previous two-step process that involved `stat_loose_object()` and `open_loose_object()`.

The change simplifies the object info reading logic by eliminating an intermediate stat call and combining path handling with the actual object reading. The existing `odb_source_loose_read_object_info()` function is modified to use this new helper while maintaining the same external interface. This appears to be a preparatory change for the larger ODB iteration API work, making the code more straightforward before introducing new iteration functionality in later patches.

The patch touches core object storage paths but maintains backward compatibility. It follows the series' pattern of careful, incremental refactoring - each change is small and focused, with clear motivation stated in the commit message. The removal of `stat_loose_object()` is a nice simplification, though the static `strbuf` for path handling remains (a common pattern in Git's codebase).
