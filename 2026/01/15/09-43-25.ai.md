This is a follow-up in an ongoing discussion about inefficient push behavior when creating new branches pointing to existing commits. Karthik Nayak confirms that Junio C Hamano's suggestion of using the existing `push.negotiate` configuration solves the problem, though he notes it's not widely known. The configuration, when enabled, avoids unnecessary object transfer by allowing the client and server to negotiate which objects are already present rather than conservatively sending everything.

The thread has progressed from identifying the issue (excessive data transfer when pushing new refs to existing objects) through several proposed solutions to validating that the existing `push.negotiate` feature works as intended. The key files involved are refs/remote.c and builtin/send-pack.c where the negotiation logic is implemented. While the immediate technical issue is resolved by enabling this configuration, the discussion leaves open whether `push.negotiate` should become the default behavior and whether protocol-level changes might still be warranted for other use cases.
