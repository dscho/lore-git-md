This is a refactoring patch targeting Git's oidmap implementation, with a focus on making cleanup behavior more explicit and testable. The patch comes from Seyi Kufoiji, who appears to be a relatively new contributor based on the email address.

The change modifies `oidmap_clear()` to explicitly handle entry cleanup rather than relying on implicit behavior, which should make the API's contract clearer to callers. The patch includes both the implementation changes and new unit tests to verify the cleanup behavior. The tests are written for the `clar` unit test framework, which Patrick Steinhardt has been promoting as a complement to Git's traditional shell-based tests.

The motivation is sound - making ownership semantics explicit generally leads to fewer bugs - and the patch appears well-structured with both implementation and test coverage. The change is small but meaningful, touching only the oidmap subsystem. Given that oidmap is a relatively low-level data structure used in various parts of Git, this improvement could help prevent subtle memory management issues in code that uses it.

For readers tracking the project's test modernization efforts, this is another example of the growing adoption of `clar` for unit testing C code. The patch looks like a straightforward improvement that should be uncontroversial to merge.
