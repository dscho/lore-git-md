Refactoring of Git's oidmap implementation to make memory management more explicit. This single-patch series from Seyi Kuforiji modifies the oidmap API to require callers to explicitly handle entry cleanup when clearing the map.

The patch introduces a new `oidmap_clear_with_free()` function that takes a callback for freeing entries, while keeping the existing `oidmap_clear()` as a wrapper for backward compatibility. The implementation replaces the previous layout-dependent approach with explicit iteration through entries, making the memory management behavior more transparent. Two new unit tests verify the behavior - one confirming entries are freed when a callback is provided, and another showing they remain when no callback is given.

Key technical changes:
- Adds `oidmap_free_fn` typedef for cleanup callbacks
- Implements new `oidmap_clear_with_free()` in oidmap.c
- Modifies existing `oidmap_clear()` to use the new function
- Adds test cases in t/unit-tests/u-oidmap.c
- Maintains same header file API while changing internal behavior

The change appears well-motivated, addressing implicit behavior in the original implementation. The patch includes thorough test coverage and maintains backward compatibility. This aligns with Git's ongoing efforts to improve code clarity and maintainability in core data structures. The implementation looks clean and the commit message clearly explains the rationale.
