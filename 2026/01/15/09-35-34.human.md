Refactoring patch standardizing commit list function names. This is the third and final patch in Patrick Steinhardt's series to align commit list function names with Git's coding guidelines. It renames `free_commit_list()` to `commit_list_free()` to match the `S_<verb>()` pattern used for other functions operating on `struct commit_list`. 

The change is mechanical but extensive, touching 40 files across merge, rebase, log, commit-graph, revision, and test code. A compatibility wrapper preserves the old name temporarily to avoid conflicts with in-flight patches, to be removed after Git 2.53. The previous patches in the series similarly renamed `copy_commit_list()` and `reverse_commit_list()`.

This is a well-executed, low-risk refactoring that improves API consistency. The patch follows Patrick's characteristic approach - thorough, with clear commit messages and temporary compatibility layers. It completes the standardization of commit list function names across the codebase.
