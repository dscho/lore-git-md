This is a post-merge documentation refinement for a bugfix series that addressed input validation and error handling in the `git last-modified` command. The series had already been merged when Kristoffer Haugsbakk noticed some redundant wording in the commit message ("peels to a commit-ish") and suggested either simplifying to "commit-ish" or using "peels to commit" for better precision.

The original series fixed several issues with the command: preventing BUG() behavior when given tree or blob OIDs, fixing memory leaks, removing redundant error messages, and improving error messaging for multiple revisions. All technical changes were reviewed and merged in v2, with Patrick Steinhardt confirming the correctness of the error message handling.

The current discussion is purely about documentation style - a characteristic example of Git's attention to precise wording even after technical consensus is reached. Junio acknowledges Kristoffer's observation with a brief but appreciative comment, though no further action is needed since the patches are already merged. This serves as a reference point for future commit message writing.
