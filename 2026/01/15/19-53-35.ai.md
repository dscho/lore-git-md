This is a discussion about configuring `git status` output for push tracking comparisons, building on Harald Nordgren's merged series that added push remote tracking branch display.

Jeff King (Peff) and Phillip Wood are discussing workflow preferences for the status output. Phillip notes that in triangular workflows (where fetch and push remotes differ), he primarily cares about binary states - whether the local branch is behind upstream (indicating a potentially difficult rebase) and whether it matches the push branch (indicating whether a push is needed). He finds the exact ahead/behind counts distracting rather than useful. Jeff agrees, adding that the counts he finds valuable are extreme outliers that signal misconfigured tracking branches.

The conversation suggests designing the configuration system to accommodate both the current detailed output and a potential simplified binary-state mode, though they agree this doesn't need to be implemented immediately. The key technical points are:

- The existing implementation in `format_branch_comparison()` and push tracking via `get_remote_push_branch()` is stable
- Configuration should be extensible to support future output formats
- Triangular workflow users (like both participants) often prefer `push.default=current`
- The discussion continues to balance immediate needs against long-term configurability

This exchange reinforces that while the core functionality is settled, there's ongoing design work around how to best present the information to users with different workflow preferences. The thread remains focused on configuration design rather than implementation changes.
