This is part 3 of Patrick Steinhardt's 14-part series introducing a new object database iteration API, part of the ongoing ODB abstraction effort. The patch refactors how Git reads loose object information by extracting a new `read_object_info_from_path()` function that handles the actual reading of object data given a path, while the existing `odb_source_loose_read_object_info()` becomes a wrapper that just computes the path first.

The change removes the intermediate `stat_loose_object()` helper since its functionality is now handled directly by callers. This appears to be a straightforward code organization improvement that makes the object reading logic more modular and reusable - the new function will be useful for the upcoming iteration API where callers may already have the object path available.

The patch touches core object storage paths but maintains the same behavior, just with a more flexible internal structure. As with the rest of this series, it's a preparatory change that builds toward making object iteration backend-agnostic. The implementation looks clean and focused, with no obvious issues in the diff.
