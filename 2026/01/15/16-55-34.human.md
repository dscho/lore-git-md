This is a discussion about the behavior of `git add` when encountering invalid or ignored paths. Junio C Hamano responds to Jon Forrest's report about inconsistent behavior between non-existent files (which cause the entire command to fail) and ignored files (which still allow other files to be added while warning about the ignored ones).

Junio argues that the current behavior for ignored files is intentional and useful - if `git add` failed entirely when encountering ignored files during wildcard expansion (like `git add *`), it would be frustrating for users. He notes that treating explicitly named paths differently from wildcard-expanded ones could be a new feature, but doesn't see it as a bug fix.

The response suggests the current behavior is working as designed, though Junio acknowledges the inconsistency Jon pointed out. This appears to be closing the discussion rather than proposing any changes, implying the status quo will remain unless someone makes a stronger case for changing the behavior.
