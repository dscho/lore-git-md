This is a feature discussion about `git status` output configuration, specifically around showing branch comparison information. Phillip Wood chimes in on an ongoing thread about push/pull tracking display in `git status`, suggesting that the ahead/behind counts themselves may not be as useful as simpler yes/no indicators of divergence.

Phillip describes his triangular workflow use case where exact commit counts are less important than knowing whether a rebase will be difficult or if a push is needed. He proposes that the configuration system being designed should allow for both toggling push branch comparisons and potentially simplifying the output format to focus on divergence state rather than counts.

The comment comes as part of a broader discussion that has evolved from technical implementation to philosophical debates about Git's workflow model. While Phillip's suggestion about simplified output isn't part of the current patch series, he raises it as a forward-looking consideration for the configuration design. The thread shows how real-world workflow differences continue to shape the discussion around this feature.
