This is a bug report about inconsistent behavior in `git add` when dealing with ignored versus non-existent files.

Jon Forrest reports that `git add` behaves differently when given:
1. A mix of existing and non-existent files (fails completely, adds nothing)
2. A mix of existing and ignored files (partially succeeds, adds the non-ignored files)

The behavior is demonstrated with clear test cases showing that `git add file1 jon` (where file1 is ignored) adds `jon` to the index, while the same command with a non-existent file instead of `file1` would add nothing. The reporter questions whether this inconsistency is intentional.

The report is well-structured with reproducible examples and shows careful investigation. It follows up on a previous discussion with Jeff King (Peff) about related behavior. The core question is whether Git should treat these error cases consistently (either always failing completely or always succeeding partially), suggesting this may warrant a closer look from the `git add` maintainers.
