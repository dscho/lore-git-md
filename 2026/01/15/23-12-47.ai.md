This is a security-related follow-up in the ongoing discussion about ANSI escape sequence handling in Git's sideband channel. Johannes Schindelin pushes back against Junio C Hamano and Jeff King's preference for permissive defaults, arguing that existing use cases for non-color ANSI sequences are both rare and fundamentally flawed in their approach.

Schindelin maintains that:
1. Current implementations relying on raw ANSI sequences are broken by design since they can't guarantee terminal compatibility
2. The correct approach would be for Git to natively support such formatting (as it does for keyword highlighting)
3. His compromise to allow color sequences by default already addresses the main legitimate use case (colored pre-receive hook errors)
4. Permissive defaults would perpetuate an insecure practice that other tools (like GNU tar and cURL) avoid

The email reveals a philosophical divide between security priorities (Schindelin advocating for secure-by-default) and compatibility concerns (Hamano/Peff preferring minimal disruption). While the technical implementation appears settled (bitmask-based configuration), this exchange shows the policy debate continuing around default behavior - particularly whether rare-but-real use cases justify maintaining potentially risky functionality out of the box. Schindelin's position reflects his Windows-focused security perspective, where terminal injection risks are more acute.
