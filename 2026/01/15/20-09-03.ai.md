Performance optimization follow-up for sparse-checkout pattern sorting. Jeff King (Peff) identifies a subtle correctness issue in Amisha Chhajed's v3 patch that converted the pattern list construction from O(n^2) to O(n log n). While the performance improvement itself is sound, Peff points out that the patch inadvertently removed duplicate suppression that was actually needed in one case - the recursive_hashmap can contain duplicates from user input, unlike the parent_hashmap which enforces uniqueness.

The issue manifests when users provide duplicate patterns via `git sparse-checkout add --stdin`, where the new code would write duplicate entries to the sparse-checkout file. Peff provides a concrete test case demonstrating this and confirms the original string_list_insert() approach implicitly handled duplicates while the new string_list_append() + sort approach needs to keep the explicit string_list_remove_duplicates() call.

This is a focused technical correction to an otherwise ready optimization. The thread shows the patch was nearly complete, with Junio C Hamano having already reviewed the formatting. Peff's review catches this last edge case, suggesting the fix is to restore the duplicate removal while keeping the improved O(n log n) sorting. The change remains contained to builtin/sparse-checkout.c's pattern handling code.
