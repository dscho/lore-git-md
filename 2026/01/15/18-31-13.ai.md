This is a refactoring patch in Patrick Steinhardt's ongoing object database (ODB) abstraction series. Justin Tobler is reviewing patch 3/14, which extracts a helper function for reading object info from a path rather than recomputing it redundantly.

The change moves path handling logic into a new `read_object_info_from_path()` function that takes a precomputed path, eliminating the redundant `stat_loose_object()` wrapper. The existing `odb_source_loose_read_object_info()` now uses this helper after computing the path once. Justin confirms the change looks correct, noting the path was already available before this refactoring made the redundancy explicit.

This is a straightforward mechanical improvement that removes duplicate path computation while maintaining the same behavior. The patch is part of the larger ODB abstraction effort to support pluggable storage backends, with this particular change cleaning up loose object handling. Justin's review indicates the change is technically sound and ready for integration.
