This thread reports a bug in `git subtree split`'s path validation behavior. When splitting a subdirectory from a branch that can't be fully checked out (due to Windows-incompatible paths elsewhere in the branch), the command incorrectly checks for the path's existence in the working directory rather than in the specified revision. This forces users to create dummy directories locally as a workaround, even when the path exists in the target revision.

The reporter encountered this on Git for Windows 2.52.0 but notes the issue appears to be in the core `git subtree` logic. They provide clear reproduction steps and propose changing the validation to check the specified revision rather than the working tree. The suggested fix seems reasonable and focused, though it would need implementation and testing. This is a legitimate bug that particularly affects Windows users dealing with path limitations.
