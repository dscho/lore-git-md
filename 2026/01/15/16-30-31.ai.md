This is a bugfix for the `git subtree` contrib script, specifically addressing validation of the `--prefix` argument during split operations. The patch is now at version 2, with Junio C Hamano providing review feedback.

The core issue is that `git subtree split` was checking the prefix path against the working tree rather than the specified commit, causing failures when splitting older commits where the subtree existed but was later removed. The v2 patch fixes this by using `git ls-tree` against the target commit for validation during split operations, while maintaining working tree validation for add/merge commands.

Junio's review notes two points for potential improvement:
1. Suggests adding a test case in `contrib/subtree/t/t7900-subtree.sh` to prevent future regressions
2. Points out inconsistent indentation in the patch (using spaces where tabs are expected)

The patch modifies `contrib/subtree/git-subtree.sh` to skip working tree validation for split commands, with a comment indicating validation will happen later against the commit. The change appears well-contained and addresses the described inconsistency, though the test coverage suggestion would strengthen it further. The thread shows consensus that the validation behavior needed fixing, with this version narrowing the scope to just the split command's validation needs.
