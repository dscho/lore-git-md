This is patch 13/14 in Patrick Steinhardt's series refactoring Git's object database (ODB) layer to support pluggable backends. The patch converts the reachability checking code in `reachable.c` to use the new `odb_for_each_object()` interface rather than separate loose and packed object iteration.

The key change replaces the previous dual-path approach (with separate `add_recent_loose()` and `add_recent_packed()` functions) with a unified `add_recent_object()` callback that works for both object types. The callback now receives an `object_info` struct containing the object's type and mtime, which were previously fetched separately for each object type. This continues the series' pattern of consolidating object storage operations behind the ODB abstraction.

The patch maintains all existing functionality while simplifying the code by eliminating about 90 lines of redundant object-type-specific handling. It builds on the mtime tracking capability added in patch 11/14, using the same `object_info` structure to request modification times. The change is behavior-preserving but prepares the codebase for future ODB backends that may implement object iteration differently.

This is a typical patch in the series - focused, mechanical, and clearly part of a larger architectural effort. The commit message could better explain why this particular conversion is valuable (beyond just being consistent with the series' approach), but the implementation appears solid and follows the established pattern.
