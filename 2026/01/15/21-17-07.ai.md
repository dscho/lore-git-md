This is a review comment on patch 7/14 of Patrick Steinhardt's ODB abstraction series, where Justin Tobler is confirming his understanding of the new `odb_for_each_object()` interface. The patch introduces a unified iteration function that wraps both loose and packed object access across all configured ODB sources (main repo plus alternates).

Justin notes that while the current implementation still explicitly separates loose and packed object iteration (via `odb_source_loose_for_each_object()` and `packfile_store_for_each_object()`), this is expected to evolve into a more backend-agnostic interface as the abstraction matures. The discussion confirms this is part of the larger transition where the files-backend specifics will eventually be encapsulated behind the ODB interface.

The review highlights that the new function properly handles the flags controlling iteration scope (`ODB_FOR_EACH_OBJECT_LOCAL_ONLY` and `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY`) while maintaining the existing behavior of iterating through alternates. This is a key building block in the series' goal to make object storage backend pluggable, though as Justin observes, some backend-specific knowledge still leaks through in this intermediate state. The implementation looks correct for its position in the series' progression.
