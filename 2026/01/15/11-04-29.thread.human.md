This thread tracks Patrick Steinhardt's ongoing 14-part series refactoring Git's object database (ODB) layer to support pluggable backends. The work systematically replaces direct storage access with abstracted interfaces, enabling future alternative storage implementations while maintaining Git's performance characteristics.

The series has progressed through several key milestones, with Justin Tobler providing thorough reviews of multiple patches. Recent work converted `git fsck` to use the new `odb_for_each_object()` interface (patch 8/14), eliminating redundant code while maintaining functionality. Junio Hamano noted a procedural issue with the final patch's commit references but indicated readiness to merge the series once addressed.

The latest patch (10/14) continues this mechanical conversion, updating `builtin/cat-file.c` and `commit-graph.c` to use the new iteration interfaces. Justin observed that the changes maintain backend-specific iteration rather than full transparency, possibly due to bitmap handling requirements. This represents an intermediate step as the series moves toward complete abstraction while preserving existing features.

The work spans multiple subsystems, eliminating over 230 lines of code while introducing consistent naming (`ODB_*` prefixes) and unified interfaces. With the core technical work reviewed and approved, the series appears ready for integration pending final procedural adjustments. This foundational change will enable future development of alternative storage backends without disrupting Git's core operations.
