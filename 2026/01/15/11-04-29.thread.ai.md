[PATCH 0/14] object iteration: make it possible to iterate ODB objects

This series by Patrick Steinhardt introduces a new object database iteration API as part of the ongoing ODB abstraction effort. The first two patches (v1 1/14 and 2/14) establish foundational changes: 1/14 performs a mechanical rename of `FOR_EACH_OBJECT_*` flags to use an `ODB_` prefix across 11 files including `packfile.c` and `object-file.c`, while 2/14 standardizes the flags parameter type to `unsigned` to match Git's bitfield conventions. Both changes are preparatory, maintaining existing semantics while aligning with the upcoming `odb_for_each_object()` API.

The series will introduce `struct object_iteration_context` and make object iteration backend-agnostic, building on recently merged topics. Planned conversions include `fsck.c`, `pack-objects.c`, `commit-graph.c`, and promisor-remote handling. The changes touch core object storage paths but maintain backward compatibility, with callers being updated to use new signatures. Patch 2/14 specifically modifies function signatures in object-file and packfile handling code without introducing new functionality.

No technical concerns have been raised yet, but the fundamental nature of object iteration suggests this will need careful review from object storage experts (Jeff King, Taylor Blau, Justin Tobler). The series is at v1 with no prior discussion. Related work includes Patrick's broader ODB abstraction series and Taylor Blau's pack-related improvements. These early patches focus on establishing consistent interfaces that will work across different storage backends as part of the ODB abstraction effort.
