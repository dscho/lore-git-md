This is a performance optimization patch in the sparse-checkout subsystem, part of an ongoing thread about improving pattern sorting from O(n^2) to O(n log n). René Scharfe points out a subtle issue in Amisha Chhajed's v3 patch regarding duplicate pattern handling.

The patch had removed `string_list_remove_duplicates()` calls when switching from `string_list_insert()` (which checks for duplicates during insertion) to `string_list_append()` followed by sorting. René notes this could be problematic for the recursive_hashmap case, where user input may contain duplicate patterns. The parent_hashmap case remains safe since it's guaranteed unique.

The thread shows consensus on the core optimization approach but needs resolution on this edge case. The changes affect pattern collection in `sparse_checkout_list()` and two locations in `write_cone_to_file()`, all within builtin/sparse-checkout.c's cone mode handling. This is a localized performance tweak within the broader sparse-checkout/sparse-index optimization efforts.
