This is a bugfix for the `git subtree` contrib script, specifically addressing validation of the `--prefix` argument during split operations.

The patch modifies the `cmd_split` function to validate that the specified prefix directory exists in the commit being split, rather than checking the working tree. Currently, the script only verifies prefix existence for other operations like `add` and `merge`, but not for `split`. This can lead to confusing behavior where a split operation proceeds even if the prefix doesn't exist in the target commit.

The change adds a check using `git ls-tree` to verify the directory exists in the specified revision before proceeding with the split. The validation is skipped during argument parsing (where it was previously done for other commands) and moved to the split implementation itself, since the working tree state isn't relevant for this operation.

The patch is small and focused, touching only the necessary logic while maintaining the existing code style. It addresses a clear gap in the validation logic that could lead to user confusion. The commit message could be more explicit about the problem scenario this fixes, but the code change itself looks correct.
