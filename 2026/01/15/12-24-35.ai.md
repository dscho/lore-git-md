Bugfix for the `git subtree` contrib script, addressing validation of the `--prefix` argument during split operations. This is version 2 of the patch that follows up on earlier discussion about validating subtree paths.

The patch fixes an inconsistency where `git subtree split` validates the prefix path against the working tree rather than the specified commit. This causes problems when splitting older commits where the subtree existed but has since been removed from the working tree. The solution changes the validation to use `git ls-tree` against the target commit instead.

The change is small and focused, touching only the split command's validation logic while maintaining the existing style. The commit message clearly explains the problem scenario with a concrete example. This addresses a real gap in behavior that could confuse users when working with historical commits.

Key technical details for future reference:
- Modifies `contrib/subtree/git-subtree.sh`
- Adds commit-based validation using `git ls-tree -d`
- Keeps working tree validation for other commands (add/merge)
- Error message matches existing style ("fatal: ...")
- The validation happens after argument parsing but before the main split logic

The patch appears well-targeted and correctly implements the described fix. It follows the established pattern of validation while adjusting it to the appropriate context for split operations.
