This is a patch in the ongoing effort to align `git add` behavior with other commands when dealing with submodules configured with `ignore=all`. The patch (v3 2/5) implements the core behavior change, requiring `--force` to add such submodules when explicitly specified.

The change makes `git add` consistent with `git status` and `git diff` by skipping `ignore=all` submodules by default, only allowing updates when forced. The implementation introduces a new `skip_submodule()` helper that handles path verification, config checking, and `--force` flag validation. A warning message guides users to use `--force` when needed, similar to how ignored files are handled.

Kristoffer Haugsbakk's email points out several typos in the commit message ("simular" -> "similar", "more reason" -> "more reasons", "handle" -> "handling"). These are minor documentation nits rather than technical issues with the implementation itself. The patch appears well-tested with dedicated test cases in t2206 and maintains compatibility with existing workflows while adding the new `--force` requirement.

This is part of a mature series that has gone through multiple iterations with input from several contributors (Claus Schneider, Phillip Wood, Junio Hamano, Ben Knoble). The technical approach seems settled, with the main remaining work being final documentation polish and series submission timing.
