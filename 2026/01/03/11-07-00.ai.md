Bug report confirmation about `git status -z` and `status.relativePaths` interaction.

Pushkar Singh confirms Artur Pyrogovskyi's bug report about inconsistent path formatting in `git status` output. The issue occurs when combining `--porcelain=2 -z` with `status.relativePaths=true` - while the non-NUL-terminated output correctly shows paths relative to the current directory, the NUL-terminated version unexpectedly switches to showing paths relative to the repository root.

The confirmation includes clear reproduction steps showing the divergence in behavior between the two output formats. Pushkar tested this with Git 2.52.0 on Linux/WSL, expanding the platform scope beyond Artur's original ARM64 Darwin report. The core observation remains that the `-z` flag appears to bypass the relative path conversion that `status.relativePaths` enables, despite documentation suggesting it should only affect record termination.

This confirmation moves the thread forward by establishing the issue is reproducible across different platforms, though no analysis of the underlying cause in `status.c` is provided yet. The next steps would involve examining why the path formatting diverges between regular and NUL-terminated output modes when relative paths are requested.
