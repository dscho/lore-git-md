This is the first patch in a two-part series implementing push tracking display in `git status`. The series has gone through 13 iterations with extensive review, and this refactoring patch prepares the groundwork by restructuring the branch comparison formatting logic.

The patch extracts the core comparison formatting from `format_tracking_info()` into a new standalone `format_branch_comparison()` function. This separation makes the code more modular by:
- Moving all the message generation logic into one place
- Keeping the existing behavior while making it reusable
- Separating the comparison formatting from advice generation
- Preserving the single ref resolution optimization

The refactoring maintains identical output while enabling the second patch to reuse this logic for push tracking information. The changes are mechanical and well-contained within `remote.c`, touching only the branch comparison formatting code. The patch follows Git's conventional commit organization, with a clear separation between refactoring (this patch) and new functionality (next patch).

This preparatory work has been reviewed by Phillip Wood and incorporates all technical refinements from the 13-iteration review process. The implementation is now conceptually sound and consistent with Git conventions, with Junio C Hamano having approved the technical direction. The patch series is ready for inclusion in the next integration cycle.
