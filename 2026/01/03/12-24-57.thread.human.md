This thread began as an RFC proposal to add warnings when `git format-patch` silently skips merge commits during patch generation. The initial version received feedback from Junio Hamano, Jeff King, and Dominique Martinet, with Junio suggesting refinements to make the warnings more informative by either tracking skipped merges or showing a count.

However, after deeper analysis prompted by a real-world case, Dominique has reconsidered the proposal's value. The key insight is that in normal Git usage, it's actually quite difficult to specify a range that would include only merge commits, making the warning scenario rare. The original case that prompted the idea came from a Jujutsu (jj) user encountering confusion, but Dominique now believes the root issue lies with jj's behavior rather than Git's. Additionally, the warning would interfere with existing patch counting in tests.

With these considerations, Dominique suggests dropping the proposal unless new compelling use cases emerge. The thread appears to be concluding with consensus that while the warning might help some users, the implementation tradeoffs and limited practical benefit make it not worth pursuing further. The original author has not yet responded to this latest analysis.
