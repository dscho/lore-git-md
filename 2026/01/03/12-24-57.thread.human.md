This RFC thread explores adding warnings when `git format-patch` silently skips merge commits during patch generation. The original proposal suggested a simple warning when no patches are produced due to skipped merges. Junio Hamano and Jeff King provided initial feedback - Junio recommended limiting warnings to cases where no patches are generated at all, while Peff spotted a potential NULL-deref bug with root commits.

In the latest exchange, Dominique Martinet voiced support for the warning concept, prompting Junio to refine the approach further. Junio now suggests two alternatives: either tracking skipped merges in a list to enable more detailed reporting if needed, or simply counting them for a "skipped %d merges" message. The discussion shows consensus on warning users when merges prevent patch generation, but explores how to balance clarity with verbosity. The author is expected to incorporate this feedback in a v2 patch that will include test coverage for the new warning behavior.
