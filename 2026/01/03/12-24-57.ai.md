This is a follow-up to an RFC patch proposing to add warnings about skipped merge commits in `git format-patch`. The discussion has refined the approach based on feedback from Junio Hamano and Jeff King.

Junio suggested that warnings should only appear when *no* patches are generated (to avoid noise for expected cases like back-merges), while Jeff noted a potential NULL-deref bug in the original implementation. The new version addresses both points:

1. Only showing the warning when no patches are generated and at least one merge commit was skipped
2. Adding a NULL check for root commits (commit->parents)
3. Using a generic message rather than per-commit details to avoid verbosity

The patch modifies `builtin/log.c` to track seen merges separately from the patch count. The warning is concise: "No patch generated. Note merge commits are skipped."

This appears to be a well-considered refinement of the original idea, with clear attention to edge cases and usability concerns. The author plans to send a v2 with test updates when time permits. The change is small and focused, touching only the format-patch command's merge commit handling.
