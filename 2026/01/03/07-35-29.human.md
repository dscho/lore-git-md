This is a bugfix for the reftable backend, addressing undefined behavior in the indexed table reference iterator. The patch fixes `indexed_table_ref_iter_next()` in `reftable/iter.c` which was accessing union members without properly checking the reference type (REFTABLE_REF_VAL1/REFTABLE_REF_VAL2), potentially leading to memory corruption on malformed input.

The fix properly validates `value_type` before accessing `val1` or `val2` union members, matching the established pattern used elsewhere in the code. This addresses a known issue that was previously marked with a "BUG" comment in the original implementation. The change improves robustness against invalid input while maintaining all existing functionality.

Pushkar Singh has reviewed the patch and confirmed the fix makes sense, noting it matches the pattern already used in `filtering_ref_iterator_next()`. The change is part of the ongoing reftable work led by Patrick Steinhardt and Karthik Nayak, though this particular fix is relatively small and focused. It touches only iterator implementation internals with no API or format changes.
