This is the second patch in a two-part series implementing push tracking branch comparison in `git status`. The feature shows divergence from both upstream and push tracking branches when they differ, addressing a common workflow where developers track both an upstream branch (like `main`) and a feature branch they push to.

The patch introduces a new helper function `get_remote_push_branch()` that resolves the push tracking reference using Git's existing `branch.<name>.pushRemote` configuration. It extends `format_tracking_info()` to show both comparisons when they differ, with the push comparison appearing on a new line after the upstream status. The output maintains Git's conventional format and only shows push advice when relevant.

Key technical details:
- Uses `pushremote_for_branch()` to resolve the push tracking branch
- Adds 168 lines of test coverage verifying various scenarios (ahead/behind/diverged states, different remote configurations, edge cases)
- Preserves existing behavior when push and upstream branches match
- Shows push comparison only when it differs from upstream
- Maintains consistent advice messages

The implementation follows the approach approved by Junio C Hamano after earlier iterations, with all feedback from Phillip Wood addressed in this v13 version. The patch is well-tested and ready for inclusion, completing the feature enhancement that began with the refactoring in patch 1/2.
