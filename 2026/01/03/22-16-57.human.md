This is a bugfix patch addressing Unicode handling in `.gitignore` files. Currently Git silently fails when reading non-UTF-8 encoded ignore files, which particularly affects Windows users where PowerShell creates UTF-16LE files by default.

The patch adds proper encoding detection and conversion for ignore files:
1. First checks for a BOM (Byte Order Mark) to detect UTF-16/32 encodings
2. Falls back to UTF-8 parsing if no BOM is found
3. If UTF-8 fails, attempts to use the working tree encoding from `.gitattributes`
4. Finally emits a clear warning if the file cannot be decoded

The changes include new UTF-8 validation utilities in `utf8.c` and extensive tests covering various Unicode encodings (UTF-8/16/32 with and without BOMs) and working tree encoding scenarios. The implementation appears thorough, with clear test cases demonstrating both success and warning cases.

This addresses a real pain point for users, particularly on Windows, where the silent failure mode has led to confusion (as noted in the linked GitHub issues). The patch provides a robust solution while maintaining backward compatibility.
