This is a technical discussion about the push tracking branch display feature in `git status`, specifically addressing how to properly handle refspec mappings when determining which remote branch to compare against.

Phillip Wood follows up on Harald Nordgren's implementation, pointing out a gap in how the code handles refspec mappings between local branches and their remote tracking counterparts. The current approach assumes a direct mapping (local `$branch` to `refs/remotes/$remote/$branch`), but Phillip notes this breaks when custom refspecs are configured that transform the branch names during push/fetch operations.

He explains the full refspec resolution process: Git first applies push refspecs to determine the destination ref on the remote, then applies fetch refspecs to map that back to a local tracking branch. Phillip suggests two potential solutions - using either `remote_ref_for_branch()` plus `tracking_for_push_dest()`, or `branch_get_push()` (though he notes the latter does more than just ref mapping).

This is a subtle but important edge case that needs addressing before the feature can be considered complete. Phillip's explanation provides the technical background needed to properly handle these mappings, which is particularly relevant for repositories using non-standard refspec configurations. The discussion shows the patch is nearing completion but still requires this final refinement to handle all cases correctly.
