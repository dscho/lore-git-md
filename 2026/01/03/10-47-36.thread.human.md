This thread examines a bug in `git status` where the `status.relativePaths` configuration interacts unexpectedly with NUL-terminated output (`-z`). Originally reported by Artur Pyrogovskyi and confirmed by Pushkar Singh, the issue manifests differently across output modes: porcelain v2 with `-z` unexpectedly switches to absolute paths despite normally honoring the config, while `--short -z` ignores the path prefix entirely. Jeff King (Peff) clarified that porcelain v1's behavior (ignoring configs with `-z`) is intentional but identified these as genuine inconsistencies in other modes.

Peff proposed a partial fix introducing a `print_with_nul` helper function to standardize NUL-terminated output handling for the `--short` case, though it needs expansion. The discussion has shifted from bug reporting to design questions: should porcelain v2 respect `status.relativePaths` at all (currently does but undocumented), and should historical quirks be preserved or fixed? Pushkar Singh has offered to assist with further investigation once the intended behavior is clarified. The thread now awaits input from status.c subsystem experts to determine the correct semantics before proceeding with implementation. The interaction between these features appears undertested, and porcelain v2's config handling lacks documentation, suggesting this may prompt broader cleanup work once the immediate issues are resolved.
