Bugfix targeting `git status` porcelain output formatting, specifically the interaction between `-z` and `status.relativePaths`. Jeff King (Peff) analyzes the reported inconsistency where `--porcelain=2 -z` shows repository-root-relative paths while `--porcelain=2` alone respects `status.relativePaths`.

Peff confirms this is partially expected behavior since `-z` defaults to porcelain v1 mode which ignores config options, but identifies two actual bugs: (1) `--short -z` ignores the prefix entirely when it should respect relative paths, and (2) porcelain v2 with `-z` unexpectedly switches to absolute paths despite v2 normally honoring the config. He provides a potential fix for the `--short` case using a new `print_with_nul` helper function, though notes it would need expansion to other printing functions.

The analysis reveals deeper questions about intended behavior - whether porcelain v2 should respect `status.relativePaths` at all (it currently does, undocumented), and whether to preserve historical quirks or fix them. The thread now needs input from status.c experts to determine the correct semantics before proceeding with fixes. Peff's response shifts the discussion from bug report to design clarification, with implications for both documentation and implementation.
