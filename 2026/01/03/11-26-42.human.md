This is a bugfix discussion about inconsistent path formatting in `git status` output when using `-z` with `status.relativePaths`.

Jeff King (Peff) confirms the reported behavior where `-z` causes `git status --porcelain=2` to ignore `status.relativePaths`, but notes this is somewhat expected since `-z` implicitly enables porcelain v1 mode which traditionally ignores such configs. However, he identifies two actual bugs:

1. `--short -z` mode also ignores relative paths when it shouldn't, and he provides a potential fix involving a new `print_with_nul` helper function.

2. The porcelain v2 output respecting `status.relativePaths` may itself be a bug since this isn't documented behavior, and if it's intentional, then the `-z` variant should match.

Peff notes these are edge cases that likely went unnoticed because combining `-z` with these output formats is uncommon. The thread now needs input on whether to:
- Fix the inconsistencies (requiring changes to multiple output functions)
- Document the current behavior as intentional quirks

The discussion reveals subtle interactions between output formats, NUL termination, and path formatting that weren't fully considered in the original implementations. As a core contributor with deep knowledge of Git's internals, Peff's analysis carries significant weight in assessing these behaviors.
