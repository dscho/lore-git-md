This is a bug report about inconsistent behavior in `git status` when using the `-z` option with `status.relativePaths=true`. The reporter, Artur Pyrogovskyi, demonstrates that while `git status --porcelain=2` correctly shows relative paths when `status.relativePaths` is enabled, adding the `-z` flag causes it to unexpectedly switch to showing absolute paths.

The issue appears in Git version 2.52.0 on an ARM64 Darwin system. The reporter provides clear reproduction steps showing the discrepancy between expected (relative paths with NUL termination) and actual behavior (absolute paths with NUL termination). The bug report is well-structured, including system information and demonstrating the problem with concrete examples.

This looks like a genuine inconsistency in the porcelain output formatting - the `-z` flag appears to be bypassing the relative path conversion that normally happens when the status.relativePaths config is set. The report is technically sound and provides all the necessary details for someone to investigate the issue in the status.c implementation.
