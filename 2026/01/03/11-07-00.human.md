Bug report confirmation about `git status -z` and `status.relativePaths` interaction. Pushkar Singh confirms Artur Pyrogovskyi's original report that the `-z` flag causes `git status` to unexpectedly switch to absolute paths when `status.relativePaths` is enabled, despite the documentation suggesting `-z` should only affect line termination.

The issue is reproducible across different platforms (Linux/WSL and ARM64 Darwin) and Git versions (tested on 2.52.0). The behavior occurs when running `git status` from a subdirectory - without `-z` it correctly shows relative paths, but with `-z` it shows paths relative to the repository root instead.

This appears to be a clear inconsistency in the porcelain output formatting where the NUL-termination option bypasses the relative path conversion. The confirmation from another user strengthens the case that this is a genuine bug rather than a platform-specific issue. The thread now has two independent reproductions but no proposed fixes yet.
