Thread identity: Bug report about inconsistent path formatting in `git status --porcelain=2 -z` when `status.relativePaths=true`, originally reported by Artur Pyrogovskyi and confirmed by Pushkar Singh.

Core problem: The `status.relativePaths` config interacts unexpectedly with NUL-terminated output (`-z`) in `git status`. While `--porcelain=2` normally shows relative paths, adding `-z` switches to repository-root-relative paths. Jeff King (Peff) has identified two actual bugs: (1) `--short -z` ignores the path prefix entirely when it should respect relative paths, and (2) porcelain v2 with `-z` unexpectedly switches to absolute paths despite v2 normally honoring the config. The discussion has evolved from bug report to design clarification regarding intended behavior.

Current status: Peff has provided a potential fix for the `--short` case using a new `print_with_nul` helper function, though notes it needs expansion. Pushkar Singh has confirmed Peff's analysis and offered to assist with further testing once behavior is clarified. The thread now awaits input from status.c experts to determine correct semantics for porcelain v2's interaction with `status.relativePaths`.
