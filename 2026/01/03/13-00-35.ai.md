This is the first patch in a 2-part series implementing push tracking branch status in `git status`. The series has gone through 14 iterations with extensive review, particularly from Phillip Wood who helped resolve key technical issues around refspec handling.

The current patch is a refactoring step that extracts the branch comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` helper function. This prepares for the second patch which will add push tracking support. The refactoring:

1. Separates the message formatting from advice generation
2. Maintains all existing behavior while making the code more modular
3. Preserves the single ref resolution optimization
4. Cleans up variable initialization and memory management

The changes are mechanical - no behavior is altered yet. The patch shows careful attention to detail, with all edge cases (gone upstream, quick mode, diverged branches) handled consistently. The test coverage (added in patch 2) will verify this refactoring doesn't introduce regressions.

This is part of a mature series that has addressed all reviewer feedback and is now functionally complete. The separation of concerns introduced here will make the push tracking addition in the next patch cleaner and more maintainable.
