Bugfix targeting `git status` path handling. Artur Pyrogovskyi reports that `git status -z` ignores the `status.relativePaths=true` configuration and always shows absolute paths, contrary to the documentation which states that `-z` should only change the line terminator from LF to NUL. 

The bug is easily reproducible with a simple test repository - creating a file in a subdirectory shows relative paths without `-z` but absolute paths with it. The behavior affects both regular and `--porcelain=2` output formats. 

The report includes clear steps to reproduce, expected vs actual behavior, and full system information showing this occurs on macOS with Git 2.52.0. The discrepancy between documented and actual behavior suggests this is a genuine bug rather than a documentation issue. The patch would likely need to modify the path formatting logic in `wt-status.c` to respect the relative paths setting regardless of NUL termination.
