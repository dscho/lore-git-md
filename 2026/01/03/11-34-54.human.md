This is a follow-up discussion about path formatting inconsistencies in `git status` when using NUL-terminated output (`-z`) with the `status.relativePaths` configuration. Pushkar Singh responds to Jeff King's analysis, agreeing that there are two distinct issues: 

1. `--short -z` incorrectly ignores `status.relativePaths` when it should respect it
2. `--porcelain=v2 -z` unexpectedly switches to absolute paths despite porcelain v2 normally honoring the config

Pushkar expresses willingness to help investigate further or write tests once the intended behavior is clarified. The thread is currently waiting for input from status.c experts to determine whether porcelain v2 should respect `status.relativePaths` at all (currently does but undocumented) and whether to handle these cases consistently. Jeff King had previously proposed a partial fix introducing a `print_with_nul` helper function, noting it would need expansion to cover all output modes.

The discussion highlights an undertested interaction between NUL-terminated output and path formatting configurations, with implications for script authors who rely on these behaviors. The next steps require maintainer guidance on the intended semantics before implementation can proceed.
