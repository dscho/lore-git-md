This thread documents a discussion about clarifying git-gui's Tcl/Tk dependencies in its README. Oskar Jaskólski authored the initial patch to explain that Tk provides the GUI while Tcl is the scripting language, with `wish` executing Tk code, and that users typically need only a single `tcl/tk` package. The patch aimed to address real user experience issues.

Junio C Hamano responded with technical concerns about platform-specific implications. He noted that on Debian-based systems, `wish` is a virtual package requiring explicit `tk` installation, and questioned marking gitk as optional since git-gui's menus integrate gitk functionality. Junio also pointed out that building from source requires `tclsh` for steps like po2msg processing, making the "no separate Tcl/Tk needed" claim incorrect for source builds.

The discussion reveals platform-specific considerations for dependency documentation, particularly around Debian's package structure and build requirements. Junio suggests keeping the `wish` clarification while addressing these technical nuances. The thread remains open with these unresolved questions about how to balance simplicity and accuracy in documenting these dependencies across different platforms and installation methods.
