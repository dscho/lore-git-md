Bugfix for shallow repository handling, specifically addressing relative-depth fetching (`--deepen`). This is the second patch in Samo Pogačnik's v4 series, which has undergone thorough review from Patrick Steinhardt, Junio Hamano, and Kristoffer Haugsbakk.

The patch fixes an edge case where fetching with `--deepen` beyond a merged branch could leave unreachable shallow commits. The solution introduces a new `get_shallows_depth()` function that properly tracks minimum depths of existing shallow commits, unifying the logic between absolute and relative deepening. The implementation removes redundant code (`get_reachable_list()`) and adds comprehensive test coverage.

Key technical changes:
- Modified `get_shallow_commits()` to handle both absolute and relative depth calculations
- Added new test case in t5500-fetch-pack.sh demonstrating the fixed behavior
- Uses a new `commit_depth` slab to track depths
- Properly handles graft points during depth calculations

The patch series is well-tested (including leak checks) and has cleared all review feedback through four iterations. The changes are minimal in v4, primarily refining commit message clarity while maintaining the solid technical approach from v3. This represents a mature solution to a subtle but important edge case in shallow repository handling.
