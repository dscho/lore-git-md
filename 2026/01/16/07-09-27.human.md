This is a post-merge discussion about terminology in the `git last-modified` command's error messages, following up on Kristoffer Haugsbakk's question about why Patrick Steinhardt was surprised that "revision" is defined as a synonym for "commit" in the Git glossary.

Patrick explains his view that "revision" should be a more general term that can refer to any object type (not just commits), using examples like `HEAD^{tree}` which resolves to a tree object. He also distinguishes between the way to name a commit (like `HEAD~10`) and the commit itself, arguing these concepts should remain separate.

The exchange shows how carefully Git contributors think about terminology even after a patch series has been merged. While this doesn't change any code, it provides useful context for future discussions about error messages and documentation. The thread demonstrates Git's culture of precision in language, with experienced contributors like Patrick weighing in on subtle distinctions might affect user understanding.
