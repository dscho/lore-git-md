This is a security patch that introduces an escape hatch for the ANSI escape sequence injection protection added in the previous commit. It's part of a series addressing CVE-2024-32002 and CVE-2024-52005/GHSA-7jjc-gg6m-3329.

The patch adds a new `sideband.allowControlCharacters` configuration option that lets users opt out of the security protections when needed (e.g. for servers that deliberately use colored output). The default remains secure (blocking control characters), but this gives users flexibility when they trust the remote server. The implementation checks this config early in the color handling logic and bypasses the sanitization when enabled.

Test coverage verifies both the default blocking behavior and the opt-in case where control characters are allowed through. The documentation explains the security implications and purpose of the new setting. This maintains the security model while accommodating legitimate use cases for colored remote messages, following feedback from brian m. carlson.

The patch is technically sound and fits into the broader security hardening effort, representing a carefully balanced compromise between security and usability. It's part of a well-reviewed series that has already seen production testing in Git for Windows and Red Hat environments.
