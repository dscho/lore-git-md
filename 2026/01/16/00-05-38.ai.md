This is a test patch (part 2/2) in a bugfix series addressing UTF-8 filename truncation in diffstat output, submitted by Lorenzo Pegorari as part of Google Summer of Code. The patch adds comprehensive test coverage for the UTF-8 handling improvements made in the first patch of the series.

The new test file `t4073-diff-stat-name-width.sh` systematically verifies how diffstat truncates paths containing Chinese characters ("你好" for directory and "再见" for filename) at various width settings. It checks edge cases including:
- Paths that fit entirely within the name-width
- Cases where only the directory name needs truncation
- Scenarios where the slash separator or filename components must be shortened
- Minimum-width boundary conditions (down to 1 character)

The tests use `--stat-name-width` to control truncation and verify the output formatting remains correct when handling multi-byte UTF-8 sequences. This complements the core fix in the first patch which properly accounts for display width versus byte count when truncating.

The patch appears well-constructed with clear, focused test cases that validate both the happy path and edge conditions. It follows Git's testing conventions and integrates cleanly with the build system via the meson configuration update. The test coverage gives confidence that the UTF-8 handling improvements work as intended across the full range of possible width settings.
