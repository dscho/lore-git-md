This is part 4 of Patrick Steinhardt's 14-part series on object database (ODB) abstraction, which is in final integration stages. The patch introduces a new iteration interface for loose objects as part of the broader effort to create a unified object iteration mechanism across all ODB backends.

The patch adds `odb_source_loose_for_each_object()` to provide a consistent way to iterate through loose objects, using the existing `struct object_info` to handle backend-specific data through its union field. This prepares for a future `for_each_object()` that will work across all object sources (loose, packed, and potential future backends). Justin Tobler's review confirms the approach and raises a question about extensibility - Patrick clarifies that new backends would indeed require adding new types to `struct object_info`'s union.

The change is mechanical but strategically important, as it eliminates one of the divergent iteration interfaces that currently make ODB abstraction difficult. It touches `object-file.c` and is part of the systematic replacement of direct storage access with the pluggable backend interface. The series has been thoroughly reviewed, with Justin having examined multiple patches including this one, and is now awaiting final procedural updates before merging.
