This is the second patch in Samo Pogačnik's v4 series addressing shallow repository issues, specifically focusing on correct relative-depth fetching (`--deepen`). The patch builds on the memory leak fix from part 1/2 and introduces a new `get_shallows_depth()` function to properly handle edge cases when deepening beyond merged branches.

The key changes unify absolute and relative deepening by:
1. Modifying `get_shallow_commits()` to optionally track minimum depth of existing shallow commits via a new `shallows` parameter
2. Adding comprehensive test coverage in t5500-fetch-pack.sh that demonstrates the fixed behavior
3. Removing the redundant `get_reachable_list()` function since its logic is now handled by the enhanced `get_shallow_commits()`

The implementation ensures that when deepening beyond merged branches, we no longer end up with unreachable shallow commits. The patch includes clear test cases showing both the problematic scenario and the corrected behavior. 

Technical highlights:
- New `commit_depth` slab tracks minimum depth of shallow commits
- Proper handling of graft points during depth calculation
- Shared logic between absolute/relative cases to avoid duplication
- Documentation improvements from previous rounds (fixing "allways summ" typo)
