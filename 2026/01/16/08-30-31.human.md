Performance optimization for sparse-checkout pattern handling, addressing an edge case in duplicate pattern suppression.

This is the latest in a thread about optimizing sparse-checkout pattern sorting from O(n^2) to O(n log n) by switching from `string_list_insert()` to `string_list_append()` followed by sorting. The patch author, Amisha Chhajed, is responding to René Scharfe's confirmation that the optimization needs to preserve duplicate suppression for patterns from user input (via `git sparse-checkout add --stdin`).

The core issue is that while the parent_hashmap entries are guaranteed unique, the recursive_hashmap can contain duplicates from user input. The original code used `string_list_insert()` which automatically removes duplicates, but the new optimized version with `string_list_append()` needs explicit duplicate handling. Amisha notes confusion about why tests passed without this check, suggesting the test coverage may need improvement.

The technical discussion has converged with input from Jeff King and René Scharfe, both affirming the optimization's correctness. The remaining question is whether Amisha will send a v4 with the duplicate handling fix or if Junio will apply it during merge. This is a localized performance improvement within the broader sparse-checkout/sparse-index work.
