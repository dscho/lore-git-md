This is a follow-up discussion in the submodule `ignore=all` behavior thread, specifically addressing the documentation and rationale for the changes. Claus Schneider responds to Kristoffer Haugsbakk's feedback on the commit message from patch 2/5 in the v3 series.

The email clarifies the motivation behind making `git add` respect `ignore=all` submodule configurations (requiring `--force` to override), explaining it enables better support for branch tracking workflows where users want to follow a submodule branch (`submodule.<name>.branch`) without tracking every SHA1 update. The response incorporates Kristoffer's suggested wording fixes ("similar" instead of "simular", "more reasons" instead of "more reason", etc.) while expanding on the use case.

Key points in this follow-up:
- Explains the branch tracking workflow scenario more clearly
- Compares behavior to the "repo" tool's approach
- Describes how this reduces friction for loosely coupled submodule dependencies
- Maintains the core technical approach (skip by default, require `--force` to override)
- Confirms adoption of Kristoffer's suggested wording improvements

The discussion remains focused on documenting the rationale rather than changing the implementation, which has already been settled in previous iterations. This email serves to refine the explanation that will appear in the final commit message.
