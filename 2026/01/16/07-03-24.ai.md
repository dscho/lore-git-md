This is part 3 of Patrick Steinhardt's 14-part series on object database (ODB) abstraction, which is now in final integration stages. The patch refactors path handling in the object-file subsystem, extracting the logic to read object information from a path into a new function `read_object_info_from_path()`. 

Justin Tobler's review noted that the change makes the code more efficient by avoiding redundant path lookups - where `open_loose_object()` previously recomputed the path that was already available, the patch now directly uses the precomputed path with `git_open()`. Patrick clarifies that while the path was being computed before, it wasn't actually being reused efficiently in the original code.

This is a mechanical refactoring that improves code organization while maintaining identical behavior, part of the larger effort to make Git's object storage layer support pluggable backends. The change touches `object-file.c` and follows the pattern seen throughout this series of breaking down monolithic functions into more modular components that can work with different storage backends. Justin has confirmed the technical correctness of this specific change in his review.
