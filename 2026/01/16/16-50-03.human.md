This is a performance optimization patch for the sparse-checkout feature, addressing an O(n^2) pattern sorting issue. Amisha Chhajed's patch converts three locations in `builtin/sparse-checkout.c` from using `string_list_insert()` (which performs an insertion sort) to `string_list_append()` followed by sorting, reducing the complexity to O(n log n).

The patch follows up on earlier discussion where Jeff King and René Scharfe identified a regression with duplicate pattern handling in the recursive hashmap case. This version explicitly adds `string_list_remove_duplicates()` to maintain the original behavior while keeping the performance improvement. The changes are focused on cone mode pattern handling when listing or writing sparse-checkout patterns.

The optimization itself is straightforward and clearly beneficial - the main consideration was ensuring it didn't break edge cases with duplicate patterns. The patch appears to have addressed those concerns while delivering the intended speedup. This is a localized improvement within the ongoing sparse-checkout/sparse-index optimization efforts.
