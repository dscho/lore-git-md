This is a security patch series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation provides configurable sanitization through `sideband.allowControlCharacters`, evolving from a simple boolean to a more granular system that now includes per-URL configuration.

The series introduces layered protections: default allowance for ANSI color sequences (SGR format ESC[..m) while blocking other control characters, with options to permit cursor movement (ESC[nA) and erase sequences (ESC[K) via comma-separated values. The final patch adds URL-specific configuration through `sideband_apply_url_config()`, implementing Junio Hamano's suggestion for server-specific policies that mirror `http.<url>.*` patterns.

Key technical components include `strbuf_add_sanitized()` for core sanitization, dedicated sequence handlers (`handle_ansi_color_sequence()`, cursor/erase handlers), and enum-based policy tracking. The implementation avoids allocations during validation and maintains backward compatibility. Test coverage in `t/t5409-colorize-remote-messages.sh` verifies all sequence types and URL-specific behavior.

The series has undergone extensive review and validation, with production use in Git for Windows (1+ year) and Red Hat (6+ months). Patrick Steinhardt and Phillip Wood confirmed implementation soundness, while brian m. carlson endorsed the security/usability balance. Documentation covers the expanded configuration options and URL scoping while maintaining warnings about server trust boundaries.

This v3 iteration focuses on rebasing to newer Git releases and minor documentation adjustments (converting config docs to AsciiDoc format). The implementation appears mature, with thorough test coverage and no outstanding review items. The per-URL configuration in patch 5 completes the architectural vision for server-specific trust boundaries.
