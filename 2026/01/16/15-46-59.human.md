This is a small feature patch in the translation (l10n) category, adding gettext support detection to Git's version reporting. Jiang Xin, the Chinese translation maintainer, proposed adding a "gettext: enabled|disabled" line to `git version --build-options` output to help diagnose localization issues. The patch follows the existing pattern for reporting other build options like fsmonitor and Rust support.

Junio C Hamano, the maintainer, generally approves the idea but suggests simplifying the output by omitting the "disabled" line entirely (showing only "enabled" when gettext is available), noting that absence of the line would be sufficient to indicate lack of gettext support. He also points out this would require a matching change to the Rust support reporting that was added in an earlier commit.

The change is straightforward - just a few lines added to `help.c` - and addresses a real diagnostic need for users experiencing localization issues. As a small, focused improvement from a domain expert, it's likely to be accepted after incorporating Junio's feedback about the output format. The thread is just starting, but given the patch's nature and size, discussion will probably focus on the presentation details rather than the core functionality.
