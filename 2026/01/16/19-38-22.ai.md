[Security] Sideband ANSI escape sequence handling - color sequences now allowed by default

This patch (v2 3/4 in the series) modifies the default behavior of Git's sideband channel to permit ANSI color sequences while continuing to block other potentially dangerous control characters. The change responds to real-world use cases where `pre-receive` hooks rely on color output, while maintaining security against cursor movement sequences that could hide malicious activity.

The implementation introduces three configuration states for `sideband.allowControlCharacters`:
- `default`/`color`: Permits colors, line feeds and tabs (new default)
- `false`: Blocks all control characters except basic formatting
- `true`: Allows all control characters (original behavior)

Technical discussion between Johannes Schindelin and Patrick Steinhardt confirms the buffer size handling matches Git's pkt-line limits (64KB) and that the color sequence validation correctly handles SGR (Select Graphic Rendition) codes. The security model balances compatibility with existing hooks against the risk of terminal manipulation, accepting that color sequences could theoretically hide text via matching foreground/background colors but preventing more dangerous cursor movement attacks.

This patch represents a compromise position in the ongoing security debate - maintaining permissive defaults for compatibility while providing granular control through configuration. The implementation is technically complete with URL-specific scoping added in earlier patches, leaving only documentation of the security philosophies as remaining work before finalization.
