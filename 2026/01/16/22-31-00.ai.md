This is a bugfix patch addressing a memory leak in the shallow repository handling code. It's the first of two patches in Samo Pogačnik's v4 series that improves shallow clone/fetch behavior.

The patch fixes a memory leak in `get_shallow_commits()` where the `object_array 'stack'` was not being properly freed before function return. The leak was caught by Git's leak-checking test infrastructure (linux-leaks and linux-reftable-leaks tests). The fix is straightforward - adding a single `object_array_clear(&stack)` call to clean up allocated elements.

The patch is well-motivated and clearly explained in the commit message, which notes that this fix is also required for proper functioning of the second patch in the series (which adds relative-depth fetching). The change is minimal (just one line added) and focused, touching only shallow.c. The patch has already gone through multiple rounds of review from Patrick Steinhardt, Junio Hamano, and Kristoffer Haugsbakk, with all feedback addressed in previous iterations.

This appears to be a solid, uncontroversial fix that's ready for integration. The patch demonstrates good development hygiene - it was tested against leak-checking infrastructure, has a clear commit message explaining both the problem and solution, and is part of a well-reviewed series addressing related shallow repository issues.
