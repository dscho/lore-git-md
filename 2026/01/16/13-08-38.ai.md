This is a bugfix patch for the `git last-modified` command, part of a series addressing memory leaks and input validation issues. The patch specifically fixes a memory leak in `populate_paths_from_revs()` where a `struct pathspec` wasn't being cleared when the function exited early due to multiple revisions being provided.

The change restructures the error handling to ensure `clear_pathspec()` is called in all code paths, including the error case where multiple revisions are detected. The patch maintains the existing behavior of rejecting multiple revisions while properly cleaning up resources. This follows the series' pattern of hardening edge cases in the relatively new `last-modified` command.

The implementation uses a `goto out` pattern for resource cleanup, which is a common Git idiom. The error message remains unchanged from previous versions, though later patches in the series will refine the terminology from "revision" to "tree" based on subsequent discussion. This patch represents the technical fix independent of those documentation improvements.
