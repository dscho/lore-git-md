This is part 5/7 of a bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses on restoring detailed error messages in `git fetch` when reference updates fail.

The change modifies the rejection handler in `builtin/fetch.c` to first check for detailed error messages (passed via the new `details` parameter) before falling back to generic error messages. This matches the behavior restored in earlier patches for `update-ref`. The patch updates several tests in `t5510-fetch.sh` to expect the more specific error messages now being produced.

Key technical aspects:
- The `ref_transaction_rejection_handler` callback now properly handles the new `details` parameter
- Error output now shows specific lockfile and refname conflict messages rather than generic "reference already exists" or "refname conflict" text
- Test cases verify both lockfile conflicts and case-insensitive filesystem edge cases
- Maintains backward compatibility by falling back to generic messages when no details are provided

This continues the series' pattern of restoring pre-batched-update error reporting while maintaining the benefits of batched operations. The changes are straightforward and well-tested, with clear improvements to debuggability when reference updates fail during fetch operations.
