[Security] Per-URL control for sideband character sanitization

This final patch in the series adds URL-specific configuration for Git's sideband character sanitization, addressing a key concern raised during review. The security model now allows administrators to specify different sanitization policies for different Git servers - for example, permitting full control sequences for a trusted internal server while maintaining strict sanitization for public repositories.

The implementation follows the same pattern as `http.<url>.*` configuration, introducing `sideband.<url>.allowControlCharacters` to override the global setting. The patch includes thorough test coverage demonstrating how URL-specific rules interact with the existing sanitization framework. Transport initialization now automatically applies any URL-specific sideband configuration.

This completes the security hardening effort that began with CVE-2024-32002, providing both strong default protections and the flexibility needed in real-world deployments. The solution has been validated in production at Git for Windows and Red Hat for over a year, with the final iteration incorporating feedback from Patrick Steinhardt and Phillip Wood on the implementation details. Documentation updates explain the new URL-scoped configuration options while maintaining clear warnings about security implications.
