This is a post-merge discussion about terminology in the `git last-modified` command's error messages, following a bugfix series that has already been merged. Patrick Steinhardt responds to Kristoffer Haugsbakk's question about why he was surprised that "revision" is defined in the glossary as a synonym for "commit".

Patrick explains his mental model where "revision" is a broader concept than just commits - it can refer to any object type when used with type specifiers (like `HEAD^{tree}`), and includes expressions (like `HEAD~10`) that may not resolve to a concrete commit. He argues for keeping the concepts of commits and revision specifications distinct, suggesting the glossary definition may be too narrow.

The exchange demonstrates how terminology discussions can continue even after technical changes are complete, with contributors refining their understanding of Git's conceptual model. This particular thread doesn't propose any code changes but serves as documentation of the reasoning behind the terminology choices made in the merged patches. The discussion touches on core Git concepts (revisions vs commits, object type specifiers) that are relevant beyond just the `last-modified` command.
