This is a discussion thread about Git terminology, specifically around the meaning of "revision" versus "commit" in the context of the `git last-modified` command.

The exchange between Junio C Hamano and Patrick Steinhardt explores the historical and conceptual differences between these terms. Patrick argues that "revision" should be considered separate from "commit" since a revision can resolve to any object type (commit, tree, blob, tag) and may not even resolve at all (like "HEAD~10" before evaluation). Junio notes that while "revision" was historically used more broadly, in practice it most often refers to commits, as seen in core components like revision.c which handles commit DAG traversal.

The discussion stems from earlier patches that updated error messages in `git last-modified` to use "revision" instead of "tree" terminology, showing how terminology choices can affect both implementation clarity and user understanding. This is a conceptual follow-up to the now-completed technical fixes for the command, demonstrating how even merged patches can spark valuable discussions about Git's internal vocabulary.
