This is a security patch in the ongoing discussion about ANSI escape sequence handling in Git's sideband channel. Johannes Schindelin responds to Junio C Hamano's position on making the security filtering opt-in rather than opt-out by default.

Schindelin provides new evidence from Git for Windows and Microsoft Git deployments showing that restrictive defaults (blocking potentially dangerous sequences by default) have been in production for over a year without any reported issues. He challenges the notion that this is merely a "feature" discussion, framing it instead as a security necessity given known attack vectors using ANSI sequences to mislead users.

The email highlights a fundamental philosophical divide: Schindelin and other security-focused contributors argue safe defaults are essential for security, while Hamano maintains that working setups shouldn't be broken regardless of security benefits. Schindelin notes the current implementation already preserves color sequences by default while blocking more dangerous cursor and erase sequences, suggesting this balanced approach addresses most legitimate use cases.

The exchange shows the technical implementation is stable (with bitmask controls for different sequence types), but the policy debate remains unresolved. Schindelin's new production evidence strengthens the case for restrictive defaults, though Hamano's position as maintainer suggests the opt-in approach will likely prevail in the near term.
