This is a bugfix series for the `git last-modified` command, addressing issues when non-commit revisions are passed as input. The series has gone through three iterations, with v3 splitting out fixes into clearer, more focused commits.

The core issue stems from `git last-modified` failing with a BUG() when given a tree OID rather than a commit. The series fixes this by properly validating input revisions to ensure they resolve to commits, while also addressing memory leaks and improving error messages. Key changes include:

1. Rewriting error messages to use accurate "revision" terminology rather than "tree" when rejecting multiple inputs
2. Fixing a memory leak in the pathspec handling when multiple revisions are provided
3. Removing duplicate error messages in the error path
4. Adding validation to ensure revisions peel to commits, preventing the BUG() when given tree or blob OIDs

The patches touch `builtin/last-modified.c` and its test file `t/t8020-last-modified.sh`, with test coverage verifying the command now handles edge cases properly. The series has already been merged, with this version representing post-merge refinements to the commit messages and organization.

Notably, this thread has sparked a broader discussion about Git's terminology around "revisions" versus "commits", with Patrick Steinhardt clarifying the distinction between general object specifiers (revisions) and concrete commit objects. While this conceptual discussion doesn't require code changes, it provides important context for future documentation work.
