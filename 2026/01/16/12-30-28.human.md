This is a follow-up discussion in the now-merged `git last-modified` bugfix series, focusing on terminology around "revision" versus "commit" in error messages. The technical changes from the series are already merged, so this exchange serves as post-merge documentation refinement.

Toon Claes responds to Patrick Steinhardt's observation that the Git glossary defines "revision" as synonymous with "commit", which surprised both of them. Patrick argues that revisions can resolve to any object type (like trees via `HEAD^{tree}`) and should conceptually remain distinct from commits. Toon maintains that for `git last-modified` specifically - which only accepts single revisions - the error message wording is still appropriate despite the broader terminology discussion.

The thread demonstrates Git's attention to precise documentation even after technical consensus is reached. While no code changes result from this exchange, it surfaces an ongoing tension between Git's formal glossary definitions and how contributors intuitively understand terms like "revision" in different contexts. The discussion may inform future documentation updates but doesn't require any immediate action on the merged patches.
