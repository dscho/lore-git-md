Jiang Xin's patch series to add gettext support detection to `git version --build-options` has reached v2, implementing Junio Hamano's suggested simplification to only show "gettext: enabled" when support exists (remaining silent when disabled). This diverges from the Rust detection precedent that shows both states, but Junio approved the simpler approach as sufficient for troubleshooting localization issues.

Patrick Steinhardt has now offered a thoughtful counterpoint, suggesting there's diagnostic value in explicitly showing "disabled" states to distinguish between intentionally disabled features and older versions that lack detection entirely. He extends this reasoning to libcurl version reporting as well, though notes he doesn't feel strongly about it. The discussion remains technical and collegial, with Patrick's input serving more as design philosophy than a challenge to the current approach.

The patch itself is straightforward and ready for inclusion as-is, having already incorporated Junio's feedback. The broader conversation about feature detection visibility may inform future similar additions, but doesn't block this change. Jiang Xin's v2 implementation in `help.c` cleanly solves the original problem of determining gettext support status when needed.
