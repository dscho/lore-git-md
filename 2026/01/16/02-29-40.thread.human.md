Jiang Xin has updated the patch to simplify how Git reports gettext support in version output. The thread began with a proposal to add "gettext: enabled|disabled" to `git version --build-options`, following the pattern used for Rust support detection. Maintainer Junio Hamano suggested showing only the positive case ("enabled" when present), arguing this is sufficient for troubleshooting localization issues.

The v2 patch implements Junio's preferred approach, adding a single line when gettext is available while remaining silent otherwise. This differs from the Rust detection output (which explicitly states "disabled") but keeps the interface cleaner. The change is minimal, touching only `help.c` to check the `NO_GETTEXT` define. While the patch appears technically sound, the thread remains open for any final input about whether the Rust output should be updated to match this simpler style - Ezekiel Newren, who implemented the Rust detection, was CC'd but hasn't yet weighed in. Unless that discussion surfaces new concerns, this seems ready to move forward.
