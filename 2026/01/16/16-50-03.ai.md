This is a performance optimization patch for the sparse-checkout feature, addressing an O(n^2) pattern sorting issue. It's version 4 of a series (though not explicitly marked as such in the subject line) that follows up on feedback about duplicate pattern handling.

The patch converts three locations in `builtin/sparse-checkout.c` from using `string_list_insert()` (which performs an insertion sort with O(n^2) complexity) to using `string_list_append()` followed by `string_list_sort()` (O(n log n)). The key addition in this version is explicitly calling `string_list_remove_duplicates()` after sorting, addressing the regression identified in previous reviews where duplicate patterns from user input were appearing in the output.

The changes affect:
1. Pattern listing in `sparse_checkout_list()`
2. Two locations in `write_cone_to_file()` where patterns are collected

The optimization is sound and maintains correctness while improving performance, particularly noticeable with large pattern sets. The patch now properly handles the edge case where duplicate patterns exist in the recursive_hashmap (which can occur when users add patterns via `git sparse-checkout add --stdin`). This version appears complete and addresses all feedback from the previous round, making it likely ready for merging.
