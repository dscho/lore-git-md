This is a security patch in the ongoing sideband control character sanitization effort (CVE-2024-32002, CVE-2024-52005). Johannes Schindelen implements per-URL configuration for ANSI escape sequence filtering, addressing Junio Hamano's request to scope control character policies by server trust level.

The patch introduces URL-specific overrides for `sideband.allowControlCharacters` using the same matching logic as `http.<url>.*` settings. The implementation adds:
- New `sideband_apply_url_config()` function called during transport initialization
- Configuration callback infrastructure mirroring HTTP transport
- Comprehensive test coverage for URL-specific behavior
- The core sanitization remains unchanged, still honoring the bitmask flags (ALLOW_ANSI_COLOR_SEQUENCES etc.)
- Windows maintains its stricter historical defaults
- Backward compatibility preserved for comma-separated config values

The thread context reveals this is part of a fundamental security model debate:
- Schindelen presents production evidence (Git for Windows + Red Hat deployments) showing restrictive defaults work
- Hamano maintains an opt-in compatibility stance despite security arguments
- Technical implementation is stable but policy disagreement persists on defaults

This patch represents a middle ground - keeping permissive defaults while enabling stricter policies where needed. The URL scoping satisfies Hamano's architectural concern about transport-layer integration while preserving the security team's filtering capabilities. Documentation will need to capture both security philosophy positions when this lands.
