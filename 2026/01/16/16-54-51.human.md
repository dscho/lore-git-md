This is a follow-up discussion in the performance test infrastructure thread, focusing on the deeper architectural question of `GIT-BUILD-OPTIONS` handling. Jeff King (Peff) responds to Ramsay Jones' earlier email about the limitations of the current build options mechanism.

The conversation has shifted from the immediate performance test fixes (which remain valid) to a broader design question about how build options should be overridden. Ramsay had proposed a prototype solution from an old `meson-wip` branch that would allow environment variables to override certain build options, but flagged it as a "disgusting hack" that doesn't resolve the core policy question of which options should be overrideable.

Peff agrees with the need for a more comprehensive solution and suggests an alternative approach using shell variable assignment syntax (`: ${GIT_FOO:=some-value}`) that would let the build system itself specify which options can be overridden. He notes this would need to be implemented consistently across all places that read `GIT-BUILD-OPTIONS` (test-lib.sh, perf-lib.sh, and t/perf/run).

The discussion remains open-ended, with both contributors recognizing the need for a solution but not yet proposing concrete patches. This appears to be one of those subtle but important infrastructure questions that may require input from multiple stakeholders, particularly as it relates to the ongoing meson build system integration work.
