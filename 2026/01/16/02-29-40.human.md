This is a small feature patch that adds build-time gettext support detection to Git's version reporting.

Jiang Xin proposes adding a "gettext: enabled|disabled" line to the output of `git version --build-options` (which also appears in `git bugreport`). The change helps diagnose localization issues by making it immediately clear whether the Git binary was compiled with gettext support, rather than requiring users to dig into build configurations.

The implementation is straightforward - it checks for the `NO_GETTEXT` define and adds the appropriate status line to the version info output. The patch touches only `help.c` with a simple 5-line addition. As the Chinese translation maintainer, Jiang Xin has clear motivation for improving gettext-related diagnostics.

This seems like a useful quality-of-life improvement for internationalization support, particularly for users troubleshooting why localized messages aren't appearing. The change is small, focused, and unlikely to be controversial.
