Bugfix completing a series to restore detailed error messages in batched reference updates, now addressing `git receive-pack`. This is the sixth patch in a seven-part v2 series co-authored by Karthik Nayak and Jeff King, building on their earlier work for `git update-ref` and `git fetch`.

The patch fixes a regression introduced in 9d2962a7c4 where `receive-pack` switched to batched reference updates but lost detailed error messages, providing only generic error codes. The change propagates backend-specific error details through the `rp_error` mechanism, showing users the actual problem rather than just an error category. For example, attempting to push a tag object to a branch now shows the specific error about writing a non-commit object, though the message formatting could be cleaned up in future work (as noted in the commit message).

Key technical changes include modifying the `ref_transaction_rejection_handler` to output details when available, updating the error string ownership handling, and adding a test case that verifies the detailed error message appears when pushing a tag to a branch. The implementation maintains the existing error reporting structure while adding the new detail capability.

This completes the error reporting restoration for the three main commands affected by the batched updates regression (`update-ref`, `fetch`, and now `receive-pack`), with all major technical questions resolved in earlier patches. The series has been progressing smoothly through review, with Junio Hamano already merging parts of it.
