Bugfix for `git fetch` error message reporting, completing a 7-part series addressing regression in batched reference updates.

This final patch in the series fixes a regression where detailed error messages from `git fetch` reference updates were lost after the introduction of batched updates in Git 2.50. The patch restores the error messages by introducing a new `ref_update_display_info` structure to collate update outcomes and display them after the transaction completes, rather than during individual reference parsing.

Key changes:
- Adds infrastructure to track success/failure status and error details for each reference update
- Modifies `update_local_ref()` to store display information in a strmap rather than printing immediately
- Updates the transaction commit handler to process and display the collected information
- Includes benchmark results showing minimal performance impact (1-2% slower for 1000 refs)
- Adjusts test expectations to match the new output ordering

The patch maintains backward compatibility while restoring the detailed error reporting that was present before batched updates. This completes the series' goal of fixing error message reporting across `update-ref`, `fetch`, and `receive-pack`.

The implementation takes a pragmatic approach using strmap for tracking updates, avoiding more invasive changes to the ref transaction infrastructure. Karthik Nayak and Jeff King have collaborated closely on this series, with all major technical questions resolved in earlier patches.
