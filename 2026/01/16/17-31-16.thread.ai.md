Thread summary:

Johannes Schindelin (Dscho) initiated a CI optimization to skip git-svn tests during leak-checking jobs via NO_SVN_TESTS in ci/lib.sh, saving ~42 minutes of runtime from Perl-based tests irrelevant to C memory leak detection. Junio C Hamano approved this approach and extended it to CVS/Perforce tests (24-minute savings) by introducing NO_CVS_TESTS and NO_P4_TESTS variables with early-exit checks in t/lib-cvs.sh and t/lib-git-p4.sh, following the established pattern for linux-leaks and linux-reftable-leaks jobs. Phillip Wood confirmed the technical approach and raised whether these exclusions should also apply to ASan (AddressSanitizer) jobs. Junio agreed with Phillip's ASan suggestion and proposed considering a more general NO_FOREIGN_CODE_TESTS variable instead of individual SCM-specific flags, noting the underlying rationale is about skipping tests that exercise minimal Git code rather than their foreign-SCM nature. The discussion remains open on both extending the optimization to ASan jobs and potentially generalizing the skip mechanism. Key files modified are ci/lib.sh, t/lib-cvs.sh, and t/lib-git-p4.sh, with possible future changes to ASan job configuration. Kristoffer Haugsbakk's earlier documentation polish about email address conventions in trailers (unrelated to the CI changes) was also discussed but resolved. The thread demonstrates consensus on practical CI optimizations while thoughtfully considering broader applicability and mechanism design.
