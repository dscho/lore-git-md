Thread summary:

Johannes Schindelin (Dscho) initiated a CI optimization to skip git-svn tests during leak-checking jobs via NO_SVN_TESTS in ci/lib.sh, saving ~42 minutes of runtime from Perl-based tests irrelevant to C memory leak detection. Junio C Hamano approved this approach and extended it to CVS/Perforce tests (24-minute savings) by introducing NO_CVS_TESTS and NO_P4_TESTS variables with early-exit checks in t/lib-cvs.sh and t/lib-git-p4.sh, following the established pattern for linux-leaks and linux-reftable-leaks jobs. Phillip Wood confirmed the technical approach and raised whether these exclusions should also apply to ASan (AddressSanitizer) jobs. Junio agreed with Phillip's ASan suggestion and proposed considering a more general NO_FOREIGN_CODE_TESTS variable instead of individual SCM-specific flags, noting the underlying rationale is about skipping tests that exercise minimal Git code rather than their foreign-SCM nature.

In follow-up discussion, Phillip Wood responds to Junio's generalization suggestion, agreeing with the technical approach but highlighting the naming challenge - the tests are skipped because they're scripted and exercise minimal C code (where leaks would occur), not primarily because they interface with foreign SCMs. He notes that if `git svn` were implemented in C, it would still need leak checking despite calling foreign programs. The discussion remains open about finding the right abstraction for these test exclusions, with participants carefully distinguishing between the incidental characteristic (foreign SCM interaction) and the actual rationale (minimal C code coverage).

Key files modified are ci/lib.sh, t/lib-cvs.sh, and t/lib-git-p4.sh, with possible future changes to ASan job configuration. Kristoffer Haugsbakk's earlier documentation polish about email address conventions in trailers (unrelated to the CI changes) was also discussed but resolved. The thread demonstrates consensus on practical CI optimizations while thoughtfully considering broader applicability and mechanism design, with the current focus on properly naming and scoping the test exclusion variables.
