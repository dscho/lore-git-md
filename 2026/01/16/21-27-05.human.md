This is a bugfix series addressing regression in error message reporting for batched reference updates. The series restores detailed error messages that were lost when batched updates were introduced to `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The core issue is that batched updates currently only return generic error codes, making it harder for users to debug failed reference updates. The series fixes this by propagating detailed error messages through the refs code while maintaining backward compatibility. 

Key changes in v2:
- Improved commit messages and API cleanliness by passing strbufs instead of char pointers
- Better control flow in refname conflict detection with a new `next_ref` label
- Different approaches for each command:
  - `update-ref`: Preserves structured format while showing errors on stderr
  - `receive-pack`: Uses sideband for detailed errors while keeping status table machine-readable
  - `fetch`: Proposes delaying status updates until transaction completion to reconstruct the status table with error details

The series builds on Jeff King's initial patch and addresses feedback from Elijah Newren who reported the regression. Karthik Nayak and Jeff King are co-authoring the solution, with Jeff providing key reviews of the control flow changes. The changes touch multiple ref backends and include expanded test coverage with 20 new test cases.
