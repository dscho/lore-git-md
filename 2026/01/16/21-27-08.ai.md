This is part 3 of a 7-patch bugfix series addressing regression in error message reporting for batched reference updates. The patch extends the callback function signature for rejected reference updates to include detailed error messages, though the actual usage of these details will come in later patches.

The change modifies the `ref_transaction_for_each_rejected_update_fn` callback to accept a `details` parameter, which will contain the rejection message stored in the `rejection_details` field of `struct ref_update`. While the current patch only adds the parameter (marked as UNUSED in the callbacks), it lays the groundwork for the subsequent patches that will implement the detailed error reporting.

The patch affects multiple commands (`fetch`, `receive-pack`, and `update-ref`) by updating their rejection handler callbacks, though they don't yet use the new parameter. The implementation is straightforward and mechanical, with no behavior changes in this patch itself - it's purely preparatory work for the actual error message restoration coming in the series.

This continues the series' approach of maintaining backward compatibility while restoring the detailed error reporting that was lost in the batched updates implementation. The patch is well-established ground, with Jeff King's co-authorship indicating solid technical review.
