This is a feature patch series for the experimental `git-last-modified` command, addressing user confusion around its default behavior. The series comes from Toon Claes and builds on previous discussions about the command's depth controls.

The core issue is that `git-last-modified` currently defaults to only examining the root tree, producing confusing results when users specify subdirectories. For example, running it on `t/lib-bash.sh` would blame the top-level `t/` directory rather than the actual file. The series changes this by:

1. First documenting existing features like NUL termination (`-z`) and depth control (`--max-depth`) in patches 1-4
2. Then changing the default `--max-depth` to 0 in the final patch, which makes the command behave more intuitively by default

The v2 iteration splits the changes into smaller commits and adds more tests. The discussion thread shows Patrick Steinhardt has been actively involved in shaping the UX design, considering different depth control combinations. The series appears well-structured and addresses a clear pain point, though as an experimental command there's still room for further refinement of the behavior.
