This is a security patch that extends the sideband control character sanitization feature to support per-URL configuration. It's part of the ongoing effort to protect against ANSI escape sequence injection (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329).

The patch implements Junio Hamano's suggestion to allow scoping the `sideband.allowControlCharacters` setting to specific URLs, similar to how `http.<url>.*` works. This addresses concerns about blanket policies by letting users maintain stricter security for untrusted servers while allowing more permissive settings for trusted ones.

Key technical changes include:
- New `sideband_apply_url_config()` function that applies URL-specific settings when a transport is created
- Modified configuration parsing to handle both global and URL-scoped settings
- Updated documentation explaining the new URL-matching capability
- Test cases verifying URL-specific behavior works as expected

The implementation maintains backward compatibility while adding the new flexibility. The default remains secure (only allowing ANSI color sequences by default), with explicit opt-in required for more permissive settings. This balances security needs with real-world use cases like server-side hooks that want to send colored error messages.

The patch appears well-constructed with thorough test coverage and documentation updates. It represents the final piece of the sideband sanitization series, addressing all raised concerns while maintaining strong security defaults.
