This is a security-related discussion thread about ANSI escape sequence handling in Git's sideband channel, continuing the debate over default behavior for control character filtering.

Junio Hamano clarifies his position in response to Johannes Schindelin's push for stricter defaults. While acknowledging the security benefits of filtering, Hamano maintains that any such changes should be opt-in to avoid breaking existing workflows. He frames the disagreement as being about implementation approach rather than fundamental opposition to the feature itself.

The exchange highlights the ongoing tension between:
1. Schindelin's security-first perspective (backed by production evidence from Git for Windows and Red Hat)
2. Hamano's compatibility-first stance (prioritizing avoiding regressions for existing users)

Hamano suggests the disagreement may be narrower than it appears - he's not against the filtering mechanism itself, but insists it should default to permissive behavior with users explicitly opting into restrictions. This maintains the status quo while still providing the security controls Schindelin wants to implement.

The technical implementation appears settled (bitmask flags for granular control, comprehensive sequence validation), leaving the policy question of defaults as the remaining open issue. Given Hamano's role as maintainer, his preference for opt-in behavior is likely to prevail despite the security arguments, though the discussion may influence how prominently the security implications are documented.
