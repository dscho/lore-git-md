This is a security discussion thread regarding ANSI escape sequence handling in Git's sideband channel. Patrick Steinhardt weighs in to strongly support Johannes Schindelin's position for stricter default security controls, opposing the more permissive approach favored by Junio C Hamano and Jeff King.

Patrick makes a security-focused argument that:
1. Terminal emulators have a history of vulnerabilities (CWE-150) from ANSI escape sequences
2. The attack surface increases significantly if Git doesn't sanitize by default
3. Niche use cases can be accommodated via opt-out rather than making security opt-in
4. References multiple security advisories demonstrating real-world risks of terminal escape injection

The core disagreement remains philosophical - security-by-default (Schindelin/Steinhardt) versus compatibility-by-default (Hamano/King). Patrick's intervention strengthens the security case by citing concrete vulnerabilities and arguing that rare use cases shouldn't dictate insecure defaults for all users. The thread shows no signs of converging yet, with fundamental differences in priorities between the two camps.
