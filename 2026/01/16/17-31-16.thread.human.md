This thread began with Johannes Schindelin (Dscho) proposing a CI optimization to skip git-svn tests during leak-checking jobs, saving significant runtime by avoiding Perl-based tests irrelevant to C memory leak detection. Junio C Hamano quickly approved and expanded this to CVS/Perforce tests, introducing NO_CVS_TESTS and NO_P4_TESTS variables following the existing pattern.

Phillip Wood then raised whether these exclusions should also apply to ASan (AddressSanitizer) jobs, which Junio agreed with while suggesting a more general NO_FOREIGN_CODE_TESTS variable might be preferable to individual SCM flags. In the latest message, Phillip supports the technical approach but notes the naming challenge - the tests are skipped because they exercise minimal C code (where leaks occur), not because they interface with foreign SCMs. He points out that even a C-based `git svn` would need leak checking despite calling foreign programs.

The discussion remains open on finding the right abstraction for these test exclusions, with participants carefully distinguishing between the incidental characteristic (foreign SCM interaction) and the actual rationale (minimal C code coverage). The changes so far (modifying ci/lib.sh, t/lib-cvs.sh, and t/lib-git-p4.sh) have clear consensus, while the broader naming and generalization question continues to be thoughtfully considered.
