This thread explores optimizations to Git's CI pipeline by skipping certain tests in contexts where they provide little value. Johannes Schindelin (Dscho) originally proposed excluding git-svn tests from leak-checking jobs, saving about 42 minutes of runtime, which Junio C Hamano extended to CVS and Perforce tests (adding another 24 minutes of savings). The approach uses specific `NO_*_TESTS` variables to skip these Perl-based tests during memory leak detection.

Phillip Wood raised whether similar exclusions should apply to ASan (AddressSanitizer) jobs, prompting Junio to agree while also questioning if the current per-SCM variables could be replaced with a more general mechanism like `NO_FOREIGN_CODE_TESTS`. The discussion highlights that the optimization isn't about the tests being for foreign SCMs, but rather that they exercise minimal Git code that would benefit from leak checking or sanitization.

While the initial changes to skip tests in leak-checking contexts have been implemented (affecting `ci/lib.sh`, `t/lib-cvs.sh`, and `t/lib-git-p4.sh`), the thread remains open on two fronts: whether to extend these exclusions to ASan jobs, and whether to consolidate the skip variables into a more general mechanism. The conversation demonstrates Git's pragmatic approach to CI optimization while carefully considering the underlying rationale for test exclusions.
