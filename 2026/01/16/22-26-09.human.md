Security patch addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). This is the first of five patches in a series that introduces configurable sanitization of control characters in remote output.

Johannes Schindelin's patch adds basic sanitization by replacing control characters (except tabs and newlines) with caret notation (e.g. `^[` for escape). The implementation introduces a new `strbuf_add_sanitized()` function that handles the conversion while preserving basic formatting. A test case verifies that color escape sequences from a remote server are properly sanitized during clone operations.

This initial patch takes a conservative approach, blocking all control characters by default. Subsequent patches in the series will add more granular controls through configuration options (`sideband.allowControlCharacters`) and per-URL settings. The implementation has been tested in production environments (Git for Windows and Red Hat) for over a year.

The patch is well-structured with clear commit message explaining the security implications (terminal state manipulation, hidden information, input buffer injection). Test coverage demonstrates the sanitization behavior. This represents the first step in hardening Git's remote protocol handling against malicious server output.
