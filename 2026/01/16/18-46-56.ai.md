This is a security patch in the ongoing discussion about ANSI escape sequence handling in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin responds to Junio Hamano's position on making the security filtering opt-in rather than opt-out, citing production evidence from both Git for Windows (1+ year) and Red Hat distributions (6+ months) showing no user issues with restrictive defaults.

The technical implementation remains stable, with the `sideband.allowControlCharacters` configuration providing granular control via bitmask flags (color/cursor/erase). Schindelin emphasizes this isn't binary - the default already allows color sequences while blocking more dangerous cursor/erase controls. He challenges the framing of "opt-in vs opt-out" as misleading, since the current proposal represents a balanced middle ground.

The core disagreement is philosophical: Schindelin frames this as a security necessity (preventing terminal injection attacks), while Hamano prioritizes not breaking existing workflows. New empirical data from production deployments strengthens the security case, but Hamano maintains the compatibility-first stance will likely prevail as maintainer. Windows remains a special case with historically stricter defaults.

The thread shows the security implementation itself is uncontroversial, but the default policy remains unresolved. Schindelin's response sharpens the debate by distinguishing between security-by-default (current proposal) versus maximal permissiveness (status quo), while disputing claims about widespread legitimate uses of unfiltered control sequences. Documentation of both positions appears to be the next step before resolution.
