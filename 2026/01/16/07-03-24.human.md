This is a technical follow-up in Patrick Steinhardt's object database (ODB) abstraction series, specifically addressing a review comment on patch 3/14. The patch extracts path-handling logic into a new function as part of the larger effort to make Git's object storage pluggable.

Justin Tobler had noted that the code could be simplified by calling `git_open()` directly rather than going through `open_loose_object()`, since the path was already available. Patrick clarifies that this wasn't actually the case - `open_loose_object()` was still needed to both generate the path via `odb_loose_path()` and assign it to the output pointer.

This is a minor clarification in an otherwise well-reviewed patch that's part of a major architectural change. The series has already received thorough technical review from Justin across multiple patches and is in final integration stages, with only minor procedural items remaining before merge. The exchange demonstrates the careful attention to detail in this foundational refactoring work.
