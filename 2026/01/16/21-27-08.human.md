This is part 3 of a 7-patch bugfix series addressing regression in error message reporting for batched reference updates. The series is co-authored by Karthik Nayak and Jeff King, with the first 2 patches already merged.

The current patch adds a `details` parameter to the callback function that handles rejected reference updates, passing through the rejection details that were stored in the previous patch. While the details aren't yet used by the callers (marked with `UNUSED`), this sets up the plumbing needed in subsequent patches where the error messages will be properly integrated into `git fetch`, `git receive-pack`, and `git update-ref`.

The changes are mechanical but important groundwork - they modify the callback signature in all three commands that use batched reference updates, plus the underlying refs infrastructure. The patch maintains backward compatibility while enabling richer error reporting that was lost in the regression. This is part of the ongoing effort to improve ref backend error handling across Git's commands.
