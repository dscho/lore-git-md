This is a documentation patch discussion about clarifying git-gui's Tcl/Tk dependencies in the README. Junio C Hamano is responding to Oskar Jaskólski's proposed changes with specific technical concerns about the patch's approach.

Junio identifies two potential issues with the proposed README update. First, he notes that hiding Tcl/Tk mentions could be problematic for Debian-based systems where "wish" is just a virtual package and users actually need to install "tk". Second, he questions whether gitk should really be marked as optional, since git-gui's menus include gitk functionality that would break without it.

The maintainer also points out that the build process itself requires "tclsh" (from the Tcl package) for certain build steps like po2msg processing, making the claim that "no separate Tcl or Tk installation is required" technically incorrect for those building from source. He suggests the clearer wording about "wish" could be kept while addressing these other concerns.

This is a typical maintainer review focusing on technical accuracy and completeness - Junio is flagging real issues that would affect users on certain platforms or build scenarios, while acknowledging the value of some of the proposed clarifications.
