Security patch addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). This is the first of five patches implementing configurable sanitization of control characters in remote protocol output.

Johannes Schindelin introduces a new `strbuf_add_sanitized()` function that replaces control characters (except basic formatting like tabs and newlines) with caret notation (e.g. `^[` for escape). The change affects all sideband output, which previously passed through unmodified from remote servers. A new test case verifies that color sequences from a malicious pack-objects hook are properly sanitized during clone.

This initial patch takes a conservative approach by blocking all non-formatting control characters, with follow-up patches planned to add fine-grained controls. The implementation builds on prior discussion establishing the security risk of unvalidated sideband content, particularly for terminal state corruption and hidden information attacks. Phillip Wood provided assistance on the implementation.

The patch touches core sideband handling in `sideband.c` and adds test coverage in `t/t5409-colorize-remote-messages.sh`. This represents the foundational security measure that subsequent patches will build upon with configuration options and exception cases. The thread context shows this approach has already seen production validation in Git for Windows and Red Hat deployments.
