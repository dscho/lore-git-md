Performance optimization for sparse-checkout pattern sorting, addressing a regression in duplicate handling.

This is a follow-up to Amisha Chhajed's v3 patch that optimized sparse-checkout pattern sorting from O(n^2) to O(n log n) by switching from string_list_insert() to string_list_append() followed by sorting. The current discussion focuses on an edge case where the optimization could allow duplicate patterns to appear in the output when they shouldn't.

René Scharfe confirms Jeff King's earlier finding that removing the string_list_remove_duplicates() calls was incorrect, as the recursive_hashmap can contain duplicate patterns from user input (e.g. via `git sparse-checkout add --stdin`). Amisha notes confusion about why tests weren't catching this, suggesting the original code may have had redundant deduplication.

The core optimization remains sound - the performance improvement from avoiding O(n^2) insertion sort is uncontested. However, the patch needs to restore duplicate handling for the recursive_hashmap case while keeping the new sorting approach. This affects three locations in builtin/sparse-checkout.c that process cone-mode patterns.

The thread shows consensus on the technical solution - maintain the sorting optimization but preserve duplicate removal where needed. This is part of ongoing sparse-checkout optimizations, though the change is localized to pattern list construction rather than broader architectural work. The patch appears ready for finalization once this edge case is addressed.
