This is patch 4/7 in a bugfix series from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series restores detailed error messages that were lost when batched updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

This particular patch focuses on `git update-ref`, making it output detailed error messages to stderr while maintaining the existing machine-parsable output format on stdout. The changes ensure users get actionable error information (like "trying to write non-commit object...") while preserving backward compatibility with scripts that parse the structured output.

The patch updates the callback that handles rejected ref updates to print detailed error messages when available, and significantly expands the test suite to verify both the machine-readable output and the new human-readable error messages. The tests now check complete output strings rather than just grepping for error reasons.

This is part of a well-structured series that has already seen in v1 (6 patches merged) and is now in v2 with all major technical questions resolved. The implementation maintains consistency with how errors were reported before the regression while adding proper plumbing for error details through the ref transaction machinery.
