This is a patch series (v2) changing the default behavior of the experimental `git-last-modified` command, making it non-recursive by default (depth=0) rather than operating only on top-level subtrees. The change addresses user confusion where the command would unexpectedly report modification times for parent directories rather than the specified files.

The series comes from Toon Claes, who has been iterating on this command's behavior based on multiple user reports. Kristoffer Haugsbakk points out a minor issue with the Cc list in this version. The thread shows the command evolving through multiple versions, with this being the second iteration that splits changes into smaller commits and adds more tests.

The key change here makes the command behave intuitively when run on specific files or subdirectories, rather than requiring users to understand and specify depth parameters. The patch maintains backward compatibility by keeping the old behavior available via explicit options. Documentation and help text have been updated to reflect the new defaults and make options more discoverable.
