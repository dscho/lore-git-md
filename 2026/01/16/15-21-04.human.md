This is a security-related discussion about ANSI escape sequence handling in Git's sideband channel, continuing the debate over default behavior for the new `sideband.allowControlCharacters` configuration.

Junio C Hamano responds to Ondrej Pohorelsky's report that Fedora/CentOS/RHEL have successfully deployed Johannes Schindelin's restrictive ANSI sequence filtering patches for six months with an opt-in approach. While acknowledging the value of the filtering mechanism itself, Junio firmly opposes making it mandatory by default, arguing that even niche use cases should not be broken if they currently work for users. He emphasizes that downstream maintainers like Ondrej correctly chose to make the feature opt-in rather than imposing restrictions on existing setups.

The email highlights the ongoing philosophical divide: security advocates (Schindelin/Steinhardt/Pohorelsky) want restrictive defaults given demonstrated terminal vulnerabilities, while Junio and Jeff King maintain that compatibility should prevail when existing workflows function, regardless of whether they seem "broken by design." Junio's position is that the mere existence of a configuration knob to enable restrictions is sufficient improvement, without needing to change default behavior that might break obscure but functional setups.

The exchange shows the security debate has progressed from theoretical to having real-world deployment data (Pohorelsky's report), but core disagreements about defaults remain unresolved. The technical implementation appears settled, but the policy question of whether security should be opt-in or opt-out continues, with Junio's maintainer perspective favoring maximal backward compatibility.
