Performance optimization for sparse-checkout pattern handling, now addressing duplicate patterns.

Junio C Hamano follows up on Amisha Chhajed's v4 patch that optimized the sparse-checkout pattern list construction from O(n^2) to O(n log n). The optimization initially missed handling duplicate patterns in the recursive_hashmap case, which Jeff King identified. Amisha has now fixed this by adding explicit duplicate removal with string_list_remove_duplicates() after sorting.

Junio notes that while the tests pass, they may lack coverage for the duplicate pattern case. He suggests adding a test case based on Jeff King's earlier example to verify this edge case, though this would be a follow-up improvement rather than a blocker for the current optimization. The core performance improvement is now correctly handling both unique (parent_hashmap) and potentially duplicate (recursive_hashmap) cases while maintaining the O(n log n) speedup.

This appears to be merged once any final test coverage questions are resolved, continuing the sparse-checkout performance work led by Derrick Stolee and Elijah Newren. The changes affect pattern collection in sparse_checkout_list() and write_cone_to_file() in builtin/sparse-checkout.c.
