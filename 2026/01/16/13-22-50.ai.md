This is a documentation and UX improvement patch for the experimental `git-last-modified` command, part of a v2 series that changes the default behavior to be non-recursive (depth=0). The patch moves the handling of the `-z` NUL-termination option from the diff machinery to the command's own option parsing, making it visible in the help output.

The change is straightforward: instead of relying on the diff options' `line_termination` field (which wasn't actually used by the diff code itself), the command now tracks NUL termination with its own `null_termination` boolean. This makes the option properly appear in `git last-modified -h` and aligns with how other Git commands document their `-z` options.

The implementation swaps the output logic to check the new flag rather than the diff option, maintaining identical behavior while improving discoverability. This is part of broader documentation improvements in the v2 series that address user confusion points while the command remains experimental. The patch follows the project's preference for small, focused changes - it touches only the option handling and output formatting without altering the core functionality.
