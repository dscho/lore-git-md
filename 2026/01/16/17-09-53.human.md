This is a documentation patch discussion about clarifying git-gui's Tcl/Tk dependencies. Junio C Hamano is responding to Oskar Jaskólski's proposed README update with specific technical concerns.

Junio identifies two potential issues with the proposed changes. First, he notes that hiding Tcl/Tk mentions could be problematic for Debian-based systems where "wish" is just a virtual package and users actually need to install "tk". Second, he questions whether gitk should really be marked as optional, since git-gui has menu items that invoke gitk functionality.

The maintainer also points out that the build process itself requires "tclsh" (from the Tcl package) for certain build steps, making the proposed "no separate Tcl installation needed" claim inaccurate for those building from source. He suggests keeping the clearer explanation about "wish" but being more precise about build requirements versus runtime requirements.

This is a thoughtful review that balances the original goal of clearer documentation with the practical realities of different platforms and build scenarios. The discussion shows the careful attention to detail that goes into even small documentation patches in the Git project.
