This is patch 4/7 in a bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses on `git update-ref --batch-updates`, restoring detailed error messages that were lost when the batched updates feature was introduced.

The key change makes `update-ref` output detailed error messages to stderr while maintaining the machine-readable rejection reasons on stdout. This provides users with actionable error details while preserving backward compatibility with scripts parsing the structured output. The patch updates the test suite to verify both the machine-readable output format and the new human-readable error messages.

Technical details:
- Modifies `print_rejected_refs()` to output error details to stderr when available
- Updates 20+ test cases in t1400-update-ref.sh to check both stdout and stderr
- Maintains existing machine-readable format (rejected <ref> <old> <new> <reason>)
- Adds verification of detailed error messages like "trying to write non-commit object" and "cannot lock ref"

This is part of a coordinated fix across `update-ref`, `fetch`, and `receive-pack` to restore pre-regression error reporting behavior. The implementation follows the pattern established in earlier patches of the series, using the new `rejection_details` field in `struct ref_update`.

The patch appears well-tested and maintains backward compatibility while improving debuggability. It represents a clear improvement over the regression state where only generic error codes were available.
