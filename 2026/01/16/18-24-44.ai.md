This is a follow-up bugfix patch for the `git last-modified` command, addressing a BUG() that could be triggered by passing a tree OID as input. The patch adds validation using `repo_peel_to_type()` to ensure the revision argument resolves to a commit object, preventing the crash and providing a proper error message.

The maintainer (Junio C Hamano) suggests a slight improvement to the error message wording - recommending "commit expected, got a tree" instead of the current "revision argument is not a commit-ish" - to be more specific about what was received versus expected. This follows the pattern seen elsewhere in Git where error messages explicitly state the type mismatch.

The patch includes test coverage in t/t8020-last-modified.sh to verify both the error case (tree OID input) and proper handling of valid commit-ish inputs. This represents the final hardening of the command's input validation after earlier fixes for memory leaks and terminology improvements in the series. The change is small but important for robustness, preventing crashes from invalid inputs while maintaining the command's behavior for valid cases.
