This is a security patch in a series addressing ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). The patch expands the configurable sanitization options for control sequences, allowing more granular control over which ANSI escape sequences are permitted.

The patch introduces two new allowed sequence types beyond just color sequences: cursor movement sequences (like ESC[nA for cursor up) and erase sequences (like ESC[K for line erasure). These can be enabled via comma-separated values in `sideband.allowControlCharacters` (e.g. "cursor,erase"). The implementation validates sequences against policy without allocations, with careful handling of the various sequence types.

The changes maintain backward compatibility while adding flexibility for legitimate use cases where hooks might need these sequences. Test coverage in t5409 verifies the new behaviors, showing how sequences are filtered or passed through based on configuration. Windows maintains stricter defaults as previously established in the thread.

This represents a refinement of the security model that emerged from earlier discussion - allowing more control sequences by explicit opt-in while keeping sensible defaults. The implementation has been reviewed by Patrick Steinhardt and Phillip Wood, with brian m. carlson supporting the balanced approach between security and usability.
