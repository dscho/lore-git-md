This is a feature patch series for the experimental `git-last-modified` command, addressing user confusion around its default behavior. The series evolves from earlier discussions about NUL termination and depth controls, now focusing on making the command more intuitive.

The key change in v2 is adjusting the default `--max-depth` behavior to better match user expectations. Currently, when users run `git last-modified` on subdirectories, it unexpectedly blames the top-level tree instead of the requested path. The series documents this quirk and proposes changing the default to depth=0 (non-recursive) to make the behavior more predictable.

The 5-patch series follows a careful progression:
1. Documents the existing `-z` NUL-termination option
2. Adds `-z` to the command's help output
3. Documents the `--max-depth` option
4. Adds `--max-depth` to the help output
5. Changes the default max-depth to 0

The implementation builds on the diff machinery's depth controls while addressing specific UX pain points. The author (Toon Claes) cites real user reports showing confusion with the current behavior. The changes are well-motivated and the series structure demonstrates thoughtful iteration, with each commit standing on its own while building toward the behavior change.

This continues an ongoing discussion about how the experimental command should handle depth controls, with Patrick Steinhardt previously proposing alternative approaches. The current series represents a pragmatic solution that makes the command more usable while maintaining backward compatibility through explicit options.
