This is a behavior change patch for the experimental `git-last-modified` command, part of a series improving its depth control and documentation. The patch changes the default behavior to be non-recursive (max-depth=0) when examining paths, meaning it will now show modification information for the exact path specified rather than its parent directory.

The key change makes `git-last-modified` output more intuitive when given a file path - it will now show when that specific file was last modified rather than its containing directory. The patch maintains backward compatibility by keeping the `-r` flag to enable recursion, and adds new tests to verify the behavior with various depth settings.

The documentation is updated to reflect that the default depth is now 0, and the `--recursive` option is clarified as being equivalent to `--max-depth=-1`. The implementation changes are relatively straightforward, mainly adjusting the diff machinery flags that control recursion depth.
