This is a feature patch that adds build-time gettext support detection to Git's version reporting. Jiang Xin proposes adding a "gettext: enabled|disabled" line to the output of `git version --build-options` (which also appears in `git bugreport`). The change helps diagnose localization issues by making it immediately clear whether the Git binary was compiled with gettext support.

The patch is straightforward - it adds a simple conditional block to `help.c` that checks for the `NO_GETTEXT` define and reports the gettext status accordingly. The implementation follows the existing pattern used for other build options like fsmonitor and libcurl. This is particularly useful for troubleshooting since users experiencing missing translations can now easily verify whether their Git build even supports localization.

The change is small (5 lines added) and well-contained, touching only the version reporting functionality. As the Chinese translation maintainer, Jiang Xin is well-positioned to identify this diagnostic gap. The patch appears ready for merging with no obvious issues - it fills a clear need without introducing complexity.
