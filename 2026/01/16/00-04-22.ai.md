This is a bugfix patch series addressing UTF-8 filename handling in diffstat output, submitted as part of Google Summer of Code (GSoC). The second version adds test coverage as requested in review and fixes an edge case where very small name-width values could cause an infinite loop.

The core issue is that diffstat truncation incorrectly assumed byte count equals display width for filenames containing multi-byte UTF-8 characters (like Chinese "你好"). The fix uses `utf8_width()` to properly account for character display width when calculating truncation in `show_stats()`. The patch is small (17 lines changed) but impacts international users who work with non-ASCII filenames.

Version 2 introduces a new test script `t4073-diff-stat-name-width.sh` that verifies the behavior with various UTF-8 characters and name-width settings. The author also fixed a boundary condition where name-width values of 2 or less could cause an infinite loop due to negative length calculations.

The changes look well-contained and address the specific issue while maintaining backward compatibility. The test coverage addition is particularly valuable for preventing regressions in this i18n-sensitive area. As part of GSoC, this may be the first in a series of patches improving diffstat's internationalization support.
