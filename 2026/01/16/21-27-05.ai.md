This is a bugfix series addressing regression in error message propagation for batched reference updates. The series from Karthik Nayak and Jeff King (v2, 7/7) restores detailed error messages that were lost when batched updates were introduced to `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`.

The core issue is that batched updates previously only returned generic error codes, making debugging harder when reference updates failed. The series fixes this by:
1. Adding a `rejection_details` field to `struct ref_update` to store error messages
2. Modifying callback signatures throughout the refs code to pass these details
3. Implementing different error display approaches for each command:
   - `update-ref`: Preserves structured format while showing errors on stderr
   - `fetch`: Tracks failed refs during processing to reconstruct status table
   - `receive-pack`: Uses sideband to send detailed errors while keeping status table machine-readable

Notable technical changes include:
- Using `goto next_ref` for clearer control flow in refname conflict detection
- Passing `strbuf` instead of `char*` for error details to simplify memory management
- Expanding test coverage with 20+ test cases across multiple test files
- Updating all three ref backends (files, packed, reftable) to handle error propagation

The series builds on prior work introducing batched updates (commit 0e358de64a) and is part of ongoing ref backend unification efforts. It maintains backward compatibility while restoring the more informative error reporting that existed before batched updates were introduced.

Jeff King identified a regression in `fetch`'s status table output format, and Karthik has proposed a solution that tracks failed refs during processing to reconstruct the table at commit time. The implementation looks thorough, with careful attention to preserving existing behavior while fixing the regression.
