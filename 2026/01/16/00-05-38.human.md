This is the second patch in a two-part bugfix series addressing UTF-8 filename truncation in diffstat output, submitted as part of Google Summer of Code. The first patch fixed the core issue in `diff.c` where byte count was incorrectly equated with display width for UTF-8 characters. This follow-up adds comprehensive test coverage.

The new test file `t4073-diff-stat-name-width.sh` systematically verifies how diffstat handles Chinese UTF-8 filenames ("你好" meaning "hello") across different `--stat-name-width` settings. It checks various truncation scenarios: when the full path fits, when only the directory name needs truncation, when the slash separator is dropped, and edge cases with very small widths. The tests confirm the fixed behavior where multi-byte UTF-8 characters are properly accounted for in width calculations.

The patch appears well-constructed, with clear test cases that cover both normal operation and boundary conditions. As noted in the thread summary, this addresses Junio's request for test coverage in the v1 review. The changes are focused and mechanical, solving a real internationalization pain point without introducing new edge cases. With the test coverage now in place, this series looks ready for merging.
