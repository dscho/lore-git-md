This thread reports a bug in `git difftool --dir-diff` behavior on Windows with Git LFS repositories. Dr. Amilcar Lucas found that despite documentation stating `--no-symlinks` should be the default on Windows, the command attempts to create symlinks and fails with "Function not implemented" errors when working with LFS-tracked files. The reporter provided detailed system information showing Git for Windows 2.52.0.windows.1 on Windows 10, along with clear reproduction steps.

The immediate workaround of explicitly passing `--no-symlinks` resolves the issue, but the core problem remains - either the documentation is incorrect about the default behavior, or the implementation fails to properly honor it. Since this involves Git for Windows (a separate project from core Git), the next steps would likely involve verifying whether the behavior persists in current Git for Windows releases and determining where the fix should be applied - whether in the core Git documentation or the Windows-specific implementation.
