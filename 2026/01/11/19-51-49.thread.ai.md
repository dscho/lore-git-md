Thread identity: Platform compatibility patch series addressing macOS iconv bug in ISO-2022-JP character encoding conversion, originating from t3900 test failures. First patch in a two-part series.

Core problem: macOS 14/15's iconv implementation fails to maintain conversion context when the output buffer grows during ISO-2022-JP to UTF-8 conversion, corrupting the output. This affects Git's reencode_string_iconv() function in utf8.c.

Current status: First patch introduces a workaround that resets the conversion state when buffer resizing is needed, controlled by new ICONV_RESTART_RESET compile-time flag. Second patch (not yet seen) will presumably add build system support.

Key technical details: Modifies utf8.c's reencode_string_iconv() to handle buffer growth by saving input state, resetting the converter, and retrying from scratch when ICONV_RESTART_RESET is enabled. Preserves original input pointers and converter state during retries. Documents the workaround clearly in code comments.

Open questions: Whether to make this workaround default-on for affected macOS versions. Alternative solution of using different iconv implementation (via package managers) remains available but requires manual setup.

Participant positions: Only initial patch submission so far - no reviews or discussion yet recorded. Author has identified the issue clearly and proposed a solution that maintains backward compatibility while fixing the macOS-specific bug.

Related work: Builds on existing iconv handling in Git's utf8.c, which already has platform-specific workarounds. Connects to broader character encoding conversion infrastructure used throughout Git.
