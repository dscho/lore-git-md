This thread addresses a macOS-specific bug in the ISO-2022-JP character encoding conversion, where macOS 14/15's iconv implementation fails to maintain conversion context when the output buffer grows. The original author proposed a two-part solution: a workaround in Git's utf8.c (ICONV_RESTART_RESET) and build system integration to enable it automatically.

The first patch introduced the core workaround in utf8.c, which saves input state and resets the converter when buffer growth occurs. The second patch, now being discussed, completes the solution by adding build system support to detect whether a known-good libiconv is available via package managers like Homebrew, MacPorts, or Fink. If not found on affected macOS versions, it automatically enables the workaround.

René Scharfe and Junio Hamano have reviewed both patches, with the author incorporating their feedback to improve commit message clarity. The solution is technically sound and follows established patterns for platform-specific fixes. The only remaining question is whether to enable the workaround by default for affected macOS versions, though the series appears ready for merging pending final maintainer approval. The changes are narrowly scoped to utf8.c and the build system, maintaining backward compatibility while solving this specific macOS iconv issue.
