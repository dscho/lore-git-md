This thread discusses a platform-specific bug in macOS's iconv implementation affecting ISO-2022-JP character encoding conversion. The first patch in the series, from Torsten Bögershausen, introduces a workaround for macOS 14 (Sonoma) and 15 (Sequoia) where iconv fails to maintain state during buffer resizes when converting ISO-2022-JP to UTF-8, leading to corrupted output.

The solution involves resetting the conversion state and restarting from scratch when the output buffer needs to grow, controlled by a new `ICONV_RESTART_RESET` compile-time flag. The patch includes detailed analysis of the issue, test failures from t3900, and careful preservation of input pointers and converter state during retries. The change is localized to utf8.c's reencode_string_iconv() function with clear documentation of the workaround's purpose.

A second patch is expected to follow with the makefile configuration to enable this workaround. The solution balances technical correctness with practical considerations, acknowledging that while linking against a different iconv implementation is possible via package managers, this workaround provides a more maintainable solution for most users.
