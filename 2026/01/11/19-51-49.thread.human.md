This thread addresses a macOS-specific bug in Git's character encoding conversion, where macOS 14/15's iconv implementation fails to maintain conversion context during ISO-2022-JP to UTF-8 conversion when the output buffer needs to grow. The issue was discovered through test failures in t3900.

The initial patch proposed a workaround that resets the conversion state when buffer resizing is needed, controlled by a new ICONV_RESTART_RESET compile-time flag. The second version refines this approach, carefully preserving input positions and converter state during retries while adding clear documentation of the workaround. The solution maintains backward compatibility while specifically addressing the macOS issue.

The author has identified two potential solutions: using a different iconv implementation (already possible through package managers like Homebrew) or applying this new workaround. The current patch implements the latter approach, with a follow-up expected to handle build system integration. The change is narrowly focused on utf8.c's reencode_string_iconv() function. So far there hasn't been any review discussion, but the patch appears well-documented and maintains the existing behavior for non-affected platforms.
