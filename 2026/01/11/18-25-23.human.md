Maintainer feedback on HTTP backend logging fix. Junio C Hamano responds to KJ Tsanaktsidis's patch that adds newlines to error messages in git-http-backend. The patch addresses a real issue where error messages could concatenate without newlines when logged through wrappers like fcgiwrap.

Junio agrees with the approach of having the HTTP backend functions handle newline termination rather than expecting wrappers to fix the formatting. He notes the design makes sense since these NORETURN functions are only called once per invocation. However, he suggests a minor optimization - using `putc('\n', stderr)` instead of `fprintf(stderr, "\n")` to output the newline character, as it would be more lightweight for this simple case.

The feedback indicates the patch is conceptually sound and addresses a genuine logging issue, with only a small implementation detail to potentially improve. This suggests the patch is likely to be accepted with that minor change.
