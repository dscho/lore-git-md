This is a bug report about `git difftool --dir-diff` behavior on Windows with Git LFS repositories. The reporter, Dr. Amilcar Lucas, describes a discrepancy between documented and actual behavior regarding symlink handling.

The key points:
- When using `git difftool --dir-diff` on a Windows system with Git LFS files, the command attempts to create symlinks despite documentation stating `--no-symlinks` should be the default on Windows
- The error occurs when trying to symlink an LFS-tracked file (KUS.a2l) between paths with different drive letters
- The workaround of manually adding `--no-symlinks` works, but the reporter notes this shouldn't be necessary according to the docs

The bug appears specific to Windows systems (reported on Windows 2.52.0.windows.1) and involves interaction between difftool's symlink behavior and Git LFS. The reporter provides clear reproduction steps and system information, making this a well-documented issue that likely affects other Windows/LFS users.
