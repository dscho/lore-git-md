This is a platform compatibility patch addressing a bug in macOS's iconv implementation that affects character encoding conversion, specifically for ISO-2022-JP text. The issue manifests in Git's test suite failures where commit messages in this encoding are only partially converted to UTF-8.

Torsten Bögershausen proposes a workaround that modifies `reencode_string_iconv()` in utf8.c to handle the case where iconv needs a larger output buffer. When enabled (via a future makefile knob), the patch will reset the conversion state and retry from scratch when expanding the buffer, rather than continuing from where it left off. This compensates for macOS's iconv losing state during partial conversions.

The patch is part of a two-patch series, with the second commit expected to add the build configuration option. The approach is conservative - it preserves the existing behavior by default and only activates the workaround when explicitly enabled. René Scharfe suggested the solution, indicating it has received some review attention already.

This affects macOS 14 (Sonoma) and 15 (Sequoia) users who don't have alternative iconv implementations installed via package managers like Homebrew. The change is narrowly targeted at a specific platform quirk rather than introducing broader functionality.
