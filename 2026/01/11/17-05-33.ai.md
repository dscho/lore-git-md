This is a bug report about unexpected behavior with `git difftool --dir-diff` on Windows when working with Git LFS repositories. The reporter, Dr. Amilcar Lucas, describes a discrepancy between documented and actual behavior regarding symlink handling.

The key points are:
1. When running `git difftool --dir-diff` on Windows with an LFS repository, Git attempts to create symlinks and fails with "Function not implemented"
2. The documentation states `--no-symlinks` should be the default on Windows, but this doesn't appear to be the case
3. The workaround of explicitly using `--no-symlinks` resolves the issue
4. The report includes detailed system information showing Git for Windows 2.52.0.windows.1 running on Windows 10

The bug appears to be specific to the interaction between Git LFS and the Windows symlink behavior in `git difftool`. The reporter has provided clear reproduction steps and system details that should help diagnose whether this is a documentation issue (incorrect claim about default behavior) or an implementation bug (failing to honor the documented default). The version information suggests this may be an older Git for Windows release, so it would be worth checking if the behavior persists in current versions.
