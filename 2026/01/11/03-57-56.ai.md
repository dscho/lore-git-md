This is a UI improvement for `git add -p` that shows previous hunk decisions during interactive staging, now in its 7th iteration. The patch comes from a GSoC participant with guidance from Junio C Hamano, who originally reported the usability issue.

The change makes `git add -p` display whether each hunk was previously marked for inclusion (y) or skipping (n) when navigating between hunks, addressing a pain point where users couldn't track their prior selections. The implementation in `add-patch.c` tracks decisions via a new `hunk_use_decision` string and modifies prompt formatting to append "(was: y)" or "(was: n)" while preserving the existing interface.

Version 7 tightens up the implementation by reducing prompt width, removing redundant checks, and improving readability of the prompt format. The changes are well-contained and tested in `t/t3701-add-interactive.sh`, including both regular and colored output cases. With Junio's approval pending final review from others, this appears ready for merging as a straightforward quality-of-life improvement to a core interactive command.
