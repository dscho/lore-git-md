This is a platform compatibility patch addressing a bug in macOS's iconv implementation that affects character encoding conversion, specifically for ISO-2022-JP. The patch is part of a two-patch series, with this first commit introducing a workaround for the buggy iconv behavior in macOS 14 (Sonoma) and 15 (Sequoia).

The issue manifests when converting ISO-2022-JP encoded text to UTF-8, where iconv fails to maintain state between buffer resizes, resulting in corrupted output. The patch adds a workaround that resets the conversion state and restarts from scratch when the output buffer needs to grow, controlled by a new `ICONV_RESTART_RESET` compile-time flag.

The commit message provides detailed context including test failures from t3900, analysis of the underlying issue (iconv losing state during piecemeal conversions), and two potential solutions - linking against a different iconv (already supported via package managers) or implementing this buffer-reset workaround. The implementation carefully preserves the original input pointers and converter state when retrying.

This appears to be a well-motivated and carefully implemented platform-specific fix. The next patch in the series will presumably add the makefile knob to control the workaround. The change is localized to utf8.c's reencode_string_iconv() function and includes clear documentation of the workaround's purpose.
