Thread summary:

User support thread initiated by Alan Mackenzie about rebase difficulties when working with Linux kernel stable repository (linux-6.13.y). Using Git 2.52.0 (2021 release) which may lack recent rebase fixes. Pushkar Singh provides first substantive response explaining the root cause: conflicts arise from attempting to rebase against a moving target branch rather than fixed base commit. Key technical insight shows `git status` "ahead by 2012 commits" indicates upstream changes being incorrectly included in rebase scope.

Pushkar offers specific solutions:
1. Locate original fork point with `git merge-base`
2. Use `--onto` to rebase only local commits against correct base
3. Preview changes with `git range-diff`

Technical details focus on proper rebase base selection and commit range isolation. Thread remains open for Alan's confirmation of solution effectiveness. Core issue identified as misunderstanding rebase mechanics with frequently-updated stable branches rather than Git version limitations. Potential follow-ups may include:
