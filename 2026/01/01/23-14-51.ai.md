This is a brief confirmation from the maintainer (Junio C Hamano) regarding a memory leak fix in the fsmonitor daemon's client handling code. The patch addresses a 40-byte per-request leak caused by incorrect use of the khash API (`kh_release_str()` instead of `kh_destroy_str()`) in `builtin/fsmonitor--daemon.c`.

Junio notes that this fix is already included in v4 of a larger fsmonitor-linux patch series, implying this standalone fix may not need separate merging. The thread context shows the patch has been through two versions, with v2 narrowing its focus to just the khash API correction after René Scharfe's review questioned some of the original changes.

The technical details are well-established in the thread: the leak occurs in `do_handle_client()` during pathname deduplication, and the solution (using `kh_destroy_str()`) is uncontested. This appears to be a straightforward cleanup that will likely be handled as part of the larger fsmonitor series rather than as an independent patch.
