Git interactive patch selection UI improvement (GSoC) - v2

Core problem/goal: Improve usability of `git add -p` and related interactive patch commands by showing users their previous hunk selection decisions (use/skip) when navigating between hunks, as originally requested by Junio C Hamano. This affects all interactive patch operations (stage, stash, reset, checkout).

Current status: Second version of patch series, with v3 planned to address test compatibility issues. Changes from v1 include more descriptive subject line, support across all front-ends, clearer wording ("previous decision: use/skip"), and moved indicator position before prompt choices. Junio identified a potential breakage in test t3701 (interactive patch functionality tests) that needs resolution.

Key technical details:
- Modifies prompt strings in all patch mode structs (`add_p`, `checkout_p`, `reset_p`, `stash_p`) to include decision text placeholder
- Updates display logic in `patch_update_file()` to show indicator based on hunk's `use` field
- Shows either "(previous decision: use)", "(previous decision: skip)", or nothing for new hunks
- Changes touch `add-patch.c` with 47 insertions and 37 deletions
- Test t3701 requires updates to account for modified prompt output
