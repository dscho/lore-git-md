Git interactive patch selection UI improvement (GSoC) - v2

Core problem/goal: Improve usability of `git add -p` and related interactive patch commands by showing users their previous hunk selection decisions (use/skip) when navigating between hunks. Originally reported by Junio C Hamano.

Current status: Second version of patch, with changes from v1 including more descriptive subject line, support across all front-ends, clearer wording ("previous decision: use/skip"), and moved indicator position before prompt choices. Junio has raised a concern about potential breakage in test t3701 (interactive patch functionality tests), indicating the patch may need test updates or adjustments to maintain backward compatibility.

Key technical details:
- Modifies prompt strings in all patch mode structs (`add_p`, `checkout_p`, `reset_p`, `stash_p`) to include decision text placeholder
- Updates display logic in `patch_update_file()` to show indicator based on hunk's `use` field
- Affects all interactive patch operations (stage, stash, reset, checkout)
- Shows either "(previous decision: use)", "(previous decision: skip)", or nothing for new hunks
- Changes touch `add-patch.c` with 47 insertions and 37 deletions
- Test t3701 identified as potentially affected by the changes

Implementation approach: Mechanical changes to prompt strings and display logic while maintaining consistency across modes. The changes are localized to the interactive patch machinery but may require test updates to account for modified prompt output.
