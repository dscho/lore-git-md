Test fix for flaky fsmonitor event tests in t7527-builtin-fsmonitor.sh.

Paul Tarjan addresses race conditions in the fsmonitor test suite where grep checks for filesystem events could fail because the fsmonitor daemon hadn't finished writing events to the trace file yet. The solution introduces a new `retry_grep()` helper function that repeatedly attempts a grep with a 5-second timeout, replacing the previous approach of using `test-tool fsmonitor-client query` as a delay mechanism.

The patch modifies t7527-builtin-fsmonitor.sh to use this new helper consistently across all event-checking tests (edit, create, delete, rename, directory operations). The implementation follows a pattern similar to `retry_until_success` from lib-git-p4.sh. The change removes 24 lines (query calls) and adds 27 (new helper and calls).

This appears to be a well-motivated fix prompted by actual CI failures rather than just theoretical flakiness. The v2 iteration improves on v1 by applying the retry logic to all event checks rather than just the first one, as any event could be delayed. The implementation looks clean and focused on solving the specific race condition without introducing new complexity.
