This is a UI improvement patch for `git add -p` and related interactive patch commands, submitted as part of Google Summer of Code (GSoC). The patch modifies the interactive hunk selection interface to show the user's previous decision (use/skip) for each hunk when navigating between them.

The change affects all interactive patch modes (stage, stash, reset, checkout, etc.) by adding a "previous decision" indicator before the prompt choices. The indicator shows either "(previous decision: use)" or "(previous decision: skip)" based on the user's prior selection, or nothing if no decision has been made yet. This helps users keep track of their selections when moving back and forth between hunks.

The patch was originally reported by Junio C Hamano and is now in its second version. Changes from v1 include:
- More descriptive subject line indicating GSoC participation
- Support for detecting decisions across all front-ends using the interactive patch machinery
- Changed wording from "Selected/Deselected" to "previous decision: use/skip"
- Moved the decision indicator before the prompt choices rather than after

The implementation modifies the prompt strings in all patch mode structs to include a placeholder for the decision text, and updates the display logic in `patch_update_file()` to show the appropriate indicator based on the hunk's `use` field. The changes are mechanical but touch many prompt strings across different modes.

This appears to be a well-motivated quality-of-life improvement for interactive patch selection, with clear benefits for users who need to navigate between multiple hunks. The implementation looks straightforward and maintains consistency across all interactive patch operations.
