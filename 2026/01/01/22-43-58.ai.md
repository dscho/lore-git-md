This is the third patch in a four-part documentation series improving the `git reset` man page. The patch focuses on clarifying the behavior of different reset modes (`--soft`, `--mixed`, `--hard`, etc.) based on user feedback about confusion in the existing documentation.

The key changes include:
1. Standardizing terminology from "index file" to just "index"
2. Reordering mode descriptions to put `--mixed` (the default) first
3. Restructuring each mode's description to consistently cover working directory impact first, then index changes
4. Adding concrete example for `--soft` showing commit squashing
5. Clarifying `--merge` is for obscure cases like unmerged index entries
6. Making `--hard` behavior more explicit about file overwrites

The patch maintains all technical accuracy while improving pedagogical clarity, building on Julia Evans' initial work and incorporating Junio Hamano's technical review. It's part of a collaborative effort to make `git reset` documentation both precise and accessible, with all technical concerns already resolved in previous iterations. The changes touch only `Documentation/git-reset.adoc` with no behavior modifications.
