This thread discusses a Google Summer of Code project to improve Git's interactive patch selection interface (`git add -p` and related commands). The goal is to make it clearer to users what decisions they've previously made about hunks (whether to use or skip them) as they navigate between them. The patch modifies the prompt strings across all interactive patch modes to show "(previous decision: use)" or "(previous decision: skip)" where applicable.

The student contributor has sent a second version of the patch, incorporating feedback from the first round. Changes include better wording, support for all front-ends, and moving the decision indicator before the prompt choices rather than after. The implementation touches the core interactive patch machinery in `add-patch.c`.

Junio Hamano, who originally identified the usability issue being addressed, has now raised a concern that the changes might break test t3701, which verifies interactive patch behavior. While not rejecting the patch outright, this suggests the contributor should verify test compatibility and potentially update the tests or implementation. The thread remains open while this test-related question is addressed.
