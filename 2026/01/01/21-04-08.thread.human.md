This thread introduces a user interface improvement for Git's patch selection interface (`git add -p` and related commands) as part of a Google Summer of Code project. The patch adds a visual indicator showing the user's previous decision (use/skip) for each hunk when navigating between them, helping users keep track of their selections.

The change affects all interactive patch operations (stage, stash, reset, checkout) by displaying a "(previous decision: use/skip)" message before the prompt choices. Junio Hamano originally reported the need for this feature, and the GSoC contributor has now submitted a second version of the patch. Key improvements in v2 include broader support across all front-ends, clearer wording, and better placement of the decision indicator.

The implementation involves modifying prompt strings across various patch modes to include the decision text, with the actual display logic handled in `patch_update_file()`. While the changes are mechanical, they touch multiple prompt strings to maintain consistency. This appears to be a well-considered quality-of-life improvement that should help users better navigate interactive patch selection.
