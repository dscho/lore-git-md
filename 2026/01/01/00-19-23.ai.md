Test fix addressing flaky fsmonitor event tests in t7527-builtin-fsmonitor.sh. This is version 2 of the patch that replaces an earlier approach using `test-tool fsmonitor-client query` as a delay mechanism.

The patch introduces a new `retry_grep()` helper function that repeatedly attempts a grep with a 5-second timeout, waiting for expected fsmonitor events to appear in the trace file. This addresses race conditions where the fsmonitor daemon hadn't finished writing events before the test checked for them. The implementation follows a pattern similar to `retry_until_success` from lib-git-p4.sh.

Key changes in v2:
- Applies the retry logic consistently across all event checks in the test file, not just the first one
- Removes 24 lines of query calls and adds 27 lines for the new helper and its calls
- Covers all event types: edit, create, delete, rename, and directory operations

The fix was prompted by an actual CI failure, not just theoretical flakiness. The patch appears well-constructed with clear commit messages and thorough coverage of the problematic test scenarios. The change is focused specifically on the test infrastructure without modifying the fsmonitor functionality itself.
