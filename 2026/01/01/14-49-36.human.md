Bugfix for a flaky Windows test in the difftool suite. Johannes Schindelin confirms and expands on Paul Tarjan's analysis of a racy test in `t7800-difftool.sh` where files with identical sizes (12 bytes) could fail detection due to Windows filesystem quirks. The test checks whether `git difftool --dir-diff` properly syncs worktree changes, but was intermittently failing because Windows' unreliable fstat() behavior and NTFS timestamp issues could prevent detection of same-size modifications.

The fix changes the test content from "new content\n" (12 bytes) to "modified content\n" (17 bytes) to ensure size differences trigger immediate detection, avoiding the problematic code paths. Schindelin notes this isn't just a test issue - similar problems affect real-world usage, pointing to open Git-for-Windows issues about stat information mismatches. He offers his Reviewed-by for the straightforward fix, which touches only 3 lines while addressing a genuine platform-specific edge case.
