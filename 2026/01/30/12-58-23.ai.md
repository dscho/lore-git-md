This is a follow-up discussion in Patrick Steinhardt's series fixing exact ref matching in bitmap and bisect operations. The thread has already established technical consensus on the fixes, with remaining discussion focused on documentation and interface design.

Patrick responds to Taylor Blau's concerns about the ref matching semantics for `pack.preferBitmapTips`. While the immediate BUG() is clearly a bug that needs fixing, Taylor questions whether the current prefix-matching behavior (where "refs/heads/foo" matches both "foo" and "foobar") is desirable, noting it contradicts the direction taken in commit 10e8a9352bc for exclude patterns.

Patrick outlines two possible approaches: (1) maintain the current prefix-matching behavior (his current implementation), or (2) require explicit trailing slashes for hierarchy matching. He leans toward (1) for its broader flexibility, but acknowledges the inconsistency with other parts of Git and commits to documenting the behavior more clearly in git-config(1). He remains open to changing the approach if consensus favors stricter hierarchy matching.

The exchange highlights an ongoing tension in Git's interface design between backward compatibility and consistency. While the technical solution is settled, the discussion surfaces deeper questions about how ref matching should behave across different Git commands. Patrick's pragmatic stance suggests he'll follow whatever direction the maintainers prefer, with documentation being the minimum required change.
