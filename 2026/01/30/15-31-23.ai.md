This is the first patch in a two-part series modernizing `git show-index`, focusing on warning behavior when falling back to SHA-1 outside a repository. The patch adds a warning message when `show-index` defaults to SHA-1 due to lack of repository context, making the implicit assumption explicit. The warning guides users toward the `--object-format` option when they need to specify a different hash algorithm.

The change is minimal - just adding a warning call when the fallback occurs - but serves an important UX improvement by removing silent behavior. The patch notes this could become obsolete if future index file versions encode the hash algorithm in their headers (as Brian m. carlson's SHA-256 interoperability work might enable), but that remains separate future work.

This version reflects Junio's feedback to split the original series into distinct technical and i18n changes. The warning text is already marked for translation (using `_()`), with the actual i18n support coming in the second patch. The discussion thread shows Patrick Steinhardt and brian m. carlson still debating whether warning suppression should be handled via flags or left as-is, but that question doesn't affect this patch's core behavior.
