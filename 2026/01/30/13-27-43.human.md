Bugfix for bitmap generation with exact ref matches in pack.preferBitmapTips. This patch from Patrick Steinhardt addresses a BUG() that occurs when users specify an exact reference (like "refs/heads/main") rather than a prefix (like "refs/heads/") in the pack.preferBitmapTips config. The fix replaces refs_for_each_ref_in() with refs_for_each_fullref_in() to avoid the problematic refname trimming behavior, while maintaining the existing prefix-matching semantics where "refs/heads/base" matches both itself and "refs/heads/base-something".

The patch includes comprehensive tests demonstrating the fix works for both regular pack bitmaps and multi-pack-index bitmaps. Documentation is updated to clarify the matching behavior. This is part of a larger series that also consolidates bitmap tip iteration code and fixes a similar issue in the bisect code, with all technical aspects already approved by Karthik Nayak and Junio Hamano. The remaining discussion focuses on whether to maintain the current prefix-matching behavior or switch to stricter hierarchical matching, with Patrick leaning toward backward compatibility.
