This is a feature patch introducing a new `@{default}` shorthand for referring to a repository's default branch (typically "main" or "master"), following the pattern of existing shorthands like `@{upstream}`. The v2 iteration addresses Junio Hamano's earlier concerns by restricting the syntax to repository-wide use (rejecting per-branch forms like `branch@{default}`) and adding more test coverage.

The implementation adds a new `branch_get_default_ref()` function that resolves the default branch name via `init.defaultBranch` config (falling back to "main" or "master"), then verifies the branch exists. The patch touches revision parsing logic in `object-name.c`, adds documentation, and includes tests demonstrating both successful usage and error cases.

While the technical implementation appears sound, the thread has revealed a significant practical concern: many repositories have `init.defaultBranch` values that don't match any existing branch (due to renaming, deletion, or non-standard initialization). This raises questions about the feature's reliability in real-world use, though the current implementation does fail gracefully in such cases by rejecting the reference. The patch positions this as solving workflow pain points when working across repositories with different default branch names, but the discovered prevalence of config/branch mismatches may undermine that value proposition.
