This is a technical discussion about the object database (ODB) abstraction effort, specifically around how to expose backend-specific information to callers. Patrick Steinhardt responds to Jeff King's analysis of two potential approaches for handling object storage details like filesystem paths and mtimes.

Patrick outlines a planned extension to `struct object_info` that would allow callers to identify and query specific object sources without needing backend-specific knowledge. The proposal builds on existing infrastructure - the `whence` pointer and `u` union in `object_info` - to provide a unified way to access object location details across different storage backends. For loose objects, this would maintain the current deterministic path handling, while packed objects would use the existing `u.packed.pack` identifier.

The discussion represents an important design decision point in the ODB abstraction work, as it addresses how to balance clean interfaces with the need for specialized operations in tools like fsck and repack. Patrick's approach suggests a middle ground that could satisfy both requirements while keeping the abstraction boundaries intact.
