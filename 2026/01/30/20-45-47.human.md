This is a feature patch introducing a new `@{primary}` shorthand for referring to a repository's primary branch. The v3 iteration responds to Junio Hamano's concerns by shifting from a config-based approach (using `init.defaultBranch`) to instead track the remote's HEAD (via `refs/remotes/origin/HEAD`), which better matches real-world usage patterns.

The patch adds the new syntax alongside existing shorthands like `@{upstream}` and `@{push}`, implemented through a new `branch_get_primary_ref()` function. The implementation reuses infrastructure from the upstream tracking code to resolve the primary branch name from the remote's HEAD reference rather than local configuration. Documentation and tests are included to verify the behavior.

Key changes from previous versions:
- Renamed from `@{default}` to `@{primary}` to better reflect the actual behavior
- Switched resolution mechanism from `init.defaultBranch` to remote HEAD tracking
- Added more thorough testing of the feature in various scenarios

The patch appears well-constructed with clear commit messages and appropriate test coverage. However, the fundamental design question remains open - as noted in the thread summary, there are still concerns about whether this shorthand is truly needed given existing mechanisms like `git var GIT_DEFAULT_BRANCH` and whether it might cause confusion between local and remote branch naming conventions.
