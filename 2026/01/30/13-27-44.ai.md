Bugfix for bisect ref handling, part of a series addressing `refs_for_each_ref_in()` misuse. This patch specifically fixes the bisect case where the function was being called without a trailing slash, which could trigger a BUG() when processing exact ref matches. Patrick Steinhardt replaces `refs_for_each_ref_in()` with `refs_for_each_fullref_in()` and adds the required trailing slash to "refs/bisect/", eliminating the need for manual prefix stripping in the callback.

The change simplifies the code by removing redundant string manipulation - instead of stripping and re-adding the prefix, it now directly uses the full refname. This follows Jeff King's earlier suggestion to clean up the string_list memory management, though this patch predates that refinement. The fix maintains the same functionality while being more robust against edge cases.

This is the third patch in a v2 series that also addresses similar issues, with all technical aspects already approved by Karthik Nayak and Junio Hamano. The series as a whole deals with subtle ref iteration bugs that affect both bisect and bitmap functionality, with this particular change focused on the bisect cleanup path.
