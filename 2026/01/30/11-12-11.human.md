This is a follow-up in the ongoing discussion about adding a `@{default}` shorthand for referring to a repository's default branch. Harald Nordgren reports encountering unexpected behavior when testing the proposed feature - many repositories on his system fail to recognize `@{default}` as a valid reference, despite presumably having a default branch configured.

The email highlights a practical implementation concern with the feature: it appears many repositories in the wild may not properly handle the default branch resolution as expected. This could indicate either a bug in the implementation or that the assumption about repositories always having a clearly defined default branch may not hold universally.

The brief message suggests this issue might be serious enough to reconsider the viability of the feature ("maybe this is a showstopper"). This comes after previous discussion where Junio Hamano had raised conceptual concerns about the feature's utility and design.

The thread remains unresolved, with this new technical observation adding weight to the skepticism about whether the shorthand would work reliably in practice. The feature appears to be in jeopardy unless these reference resolution issues can be addressed or explained.
