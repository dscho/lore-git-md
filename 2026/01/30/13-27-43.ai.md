This is a bugfix targeting the bitmap and MIDX subsystems, addressing an issue with exact reference matching in `pack.preferBitmapTips`. The patch is part of Patrick Steinhardt's v2 series that consolidates bitmap tip iteration logic while fixing related bugs.

The core issue occurs when `pack.preferBitmapTips` is set to an exact reference name (like `refs/heads/main`) rather than a prefix (like `refs/heads/`). The current implementation using `refs_for_each_ref_in()` attempts to strip the full reference name, triggering a BUG() when it would leave an empty string. The fix replaces this with `refs_for_each_fullref_in()`, which preserves the full reference name while still matching prefixes.

The patch includes comprehensive tests in both t5310-pack-bitmaps.sh and t5319-multi-pack-index.sh that verify the fix works for exact reference matches. It also updates the documentation to clarify that the configuration matches reference prefixes rather than suffixes, though the commit message notes this remains an area of discussion about whether to maintain prefix-matching behavior or require explicit trailing slashes for hierarchy matching.

This change maintains backward compatibility while fixing the immediate bug, with the series having already been approved by Karthik Nayak and Junio Hamano for the technical approach. The remaining open question is about finalizing the documentation wording around matching semantics.
