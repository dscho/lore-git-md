This is a bugfix series for the `git last-modified` command, addressing an issue where passing a tree-ish (like a tree OID) would trigger a BUG() instead of showing a proper error message. The series is now in its sixth iteration (v6) and has been through extensive review and refinement.

The core fix adds validation to ensure the input is a commit-ish (something that can be peeled to a commit) rather than accepting any object type. The series also includes several related improvements that emerged during review:
- Fixed memory leaks in error paths
- Cleaned up duplicate error messages
- Improved error messaging when multiple revisions are given
- Added test coverage for annotated tags and tree objects

Notably, this version specifically addresses a CI failure on Windows/Meson builds by adjusting how tag names are excluded during test verification. The series has already been merged by Junio, with this final version incorporating the last remaining fixes.

The discussion around this patch also sparked a broader conversation about Git's terminology - specifically whether "revision" should be considered synonymous with "commit" (as defined in gitglossary(7)) or if it should encompass all object types that can be named via revision syntax. That conceptual discussion remains ongoing but doesn't block these technical fixes.
