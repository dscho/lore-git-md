This is a feature proposal for a `@{default}` shorthand to reference a repository's primary branch, currently in active discussion about its fundamental design. Kristoffer Haugsbakk weighs in with practical experience that complicates the proposal's assumptions.

The thread has evolved from implementation details to questioning whether tracking the configured default branch (`init.defaultBranch`) is the right approach at all. Junio Hamano raised concerns that local config often diverges from reality due to branch renames or non-standard setups, suggesting remote HEAD tracking (`@{primary}`) might be more reliable. Testing has revealed widespread mismatches between configured defaults and actual branch names.

Haugsbakk shares his personal experience that simply using the remote name (`origin` or his shorthand `o`) suffices for his workflow, and notes `git var GIT_DEFAULT_BRANCH` already provides the configured value without new syntax. His comment reinforces Junio's skepticism about the feature's utility given existing alternatives, while acknowledging the original author's goal of branch-agnostic workflows.

The discussion now faces core questions: whether to pivot to remote-based tracking, rename the feature to better reflect its behavior, or reconsider if branch naming hygiene would address the underlying problem more effectively than new syntax. The patch appears stalled until these architectural questions are resolved.
