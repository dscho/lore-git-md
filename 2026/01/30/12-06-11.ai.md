This is a bugfix patch series addressing regression in batched ref update error reporting. The series, originally submitted by Karthik Nayak, fixes several code paths that lost detailed error messages when using the batched ref update API (introduced in Git 2.51). The changes affect `fetch`, `receive-pack`, and `update-ref` commands.

The patch series adds rejection details to the ref transaction callback function and ensures these errors are properly propagated to users. Karthik confirms in this email that all review feedback has been addressed and the series is ready for merging into the 'next' branch. Junio Hamano had previously indicated this was likely to be merged.

Key technical details include modifications to the refs API to carry rejection information through the transaction process, with specific attention to cases where non-commit objects are pushed to refs/heads/. The changes touch the refs subsystem internals while maintaining backward compatibility with existing callers. This appears to be a straightforward fix for a regression that affected error reporting quality in common workflows.
