This is a discussion about the proposed `@{default}` shorthand for referencing a repository's default branch, part of an ongoing thread about branch naming conventions and reference resolution.

Junio Hamano responds to Harald Nordgren's defense of the `@{default}` shorthand, arguing that the name is misleading because it doesn't actually represent the repository's configured default branch (from `init.defaultBranch`) in many common workflows. Junio points out that users who rename their default branch (e.g., from 'master' to 'main') or follow upstream naming conventions are not well-served by the current implementation, which relies too heavily on `init.defaultBranch`.

Junio suggests that what users really want is a way to reference their "primary" branch (which he jokingly proposes calling `@{dumbo}`), and that `refs/remotes/origin/HEAD` would be a better source of truth than `init.defaultBranch` for this purpose. He also raises the possibility of per-branch syntax (like `$branch@{dumbo}`) to handle cases where different remotes might have different primary branches.

The exchange highlights the tension between the simple shorthand Harald proposed and the more complex reality of how branches are actually named and used in practice. Junio's comments suggest the current approach may need rethinking to better match user expectations and real-world branch naming patterns. The discussion remains unresolved, with fundamental questions about the feature's design and naming still open.
