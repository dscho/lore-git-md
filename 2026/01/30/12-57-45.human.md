This is a technical discussion about the ongoing object database (ODB) abstraction effort, specifically addressing how to expose backend-specific information to callers like `fsck` and `repack`. Patrick Steinhardt responds to Jeff King's concerns about handling object mtimes and filesystem paths in a pluggable ODB architecture.

The exchange focuses on two design approaches for exposing backend details: either keeping the interface opaque (Option 1) or providing queryable information (Option 2). Peff had argued for Option 2 to keep specialized logic in callers rather than pushing it into the ODB layer. Patrick agrees with the general direction and outlines his plan to extend `struct object_info` to handle this, leveraging the existing `whence` field and union structure to identify object sources without callers needing backend-specific knowledge.

This is part of the larger ODB abstraction work (v4 0/14 series) that has already consolidated object iteration interfaces. The discussion doesn't require changes to the current patch series but informs future interface evolution. The technical depth and clear articulation from both sides suggest this is a well-considered design discussion between two of Git's most experienced contributors.
