This is an RFC patch series continuing the modernization of `git show-index`, focusing on warning behavior and i18n support. The series builds on previous discussion about hash algorithm detection when operating outside repository contexts.

The first commit adds a warning when `show-index` falls back to SHA-1 due to missing repository context, maintaining the technical approach already agreed upon in the thread. The second commit wraps error messages with gettext for internationalization, addressing a separate code quality issue.

The series has been restructured from v1 based on Junio C Hamano's feedback, splitting the changes into two distinct patches - one for the warning behavior and one for i18n support. The core technical implementation remains unchanged from the settled approach using size-based hash detection with SHA-1 fallback.

Notable context from the ongoing thread includes Patrick Steinhardt's position that the warning's current behavior provides sufficient flexibility without needing new flags, contrasting with brian m. carlson's preference for explicit control via `--quiet`. The patches don't yet resolve this UX question but focus on the agreed technical implementation while keeping the warning behavior discussion open.

The changes are narrowly scoped to `builtin/show-index.c`, modifying how hash algorithm fallback is reported to users and preparing error messages for translation. The series appears ready for final review pending resolution of the warning suppression discussion, with clean separation between the warning implementation and i18n improvements.
