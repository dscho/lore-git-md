Feature proposal for a `@{default}` shorthand to reference a repository's default branch. This is the second iteration of Harald Nordgren's patch to add syntax similar to `@{upstream}` that resolves to whatever branch is configured as default (via `init.defaultBranch`), falling back to "main" or "master". The implementation adds a new `branch_get_default_ref()` function and integrates it with Git's revision parsing.

The thread has revealed practical concerns about repositories where the configured default branch name doesn't match any existing branch (a surprisingly common case). While the feature would be convenient for switching between repositories with different default names, Junio Hamano has expressed skepticism about edge cases and whether this might encourage lax branch naming practices. The current version restricts the syntax to standalone use (`@{default}`) rather than per-branch (`branch@{default}`), addressing one of Junio's earlier objections.

The patch itself is well-constructed with documentation updates and tests, but the discussion suggests the concept may need more vetting around real-world repository states before proceeding. The core question remains whether the convenience justifies adding syntax that could fail silently in mismatched config cases.
