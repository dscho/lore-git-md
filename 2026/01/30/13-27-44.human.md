This is a bugfix patch in Patrick Steinhardt's series addressing incorrect usage of `refs_for_each_ref_in()` in both bitmap and bisect functionality. The patch specifically focuses on fixing the bisect case.

The issue stems from how `refs_for_each_ref_in()` handles ref prefixes - it requires a trailing slash to properly match ref hierarchies, and incorrectly processes exact ref matches by trimming prefixes in a way that can trigger a BUG(). The patch makes two key changes: first, it adds the required trailing slash to "refs/bisect/", and second, it switches to using `refs_for_each_fullref_in()` which avoids the problematic prefix-stripping behavior entirely.

The change simplifies the code by eliminating redundant string manipulation where the prefix was being stripped only to be re-added later. This follows up on earlier feedback from Jeff King about cleaning up the string handling. The patch has already received approvals from both Karthik Nayak and Junio Hamano, indicating the technical approach is sound.

This is part of a larger effort to properly handle ref matching semantics across Git's codebase, with parallel fixes being made to the bitmap functionality in other patches of the series. The changes maintain backward compatibility while making the behavior more robust.
