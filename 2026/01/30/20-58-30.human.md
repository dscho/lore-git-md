This is a feature patch from Harald Nordgren proposing a shorthand syntax for referencing a repository's primary branch, now using `@{primary}` after earlier iterations considered `@{default}`. The patch builds on previous discussion in the thread where the approach shifted from using `init.defaultBranch` configuration to instead resolve via upstream tracking infrastructure (typically `origin/HEAD`), addressing concerns about config reliability.

The implementation adds new infrastructure including `branch_get_primary_ref()` and supporting code to handle the shorthand resolution. Tests verify the behavior works as expected in common commands like `rev-parse`, `checkout`, and `status`. The documentation describes this as resolving to "the primary branch via upstream tracking."

While technically sound, the patch still leaves open questions about whether this sufficiently captures the "primary branch" concept across all workflows, particularly in repositories without clear remote tracking or with multiple primary branches. The discussion has evolved from implementation details to semantic questions about what "primary branch" should mean in Git's reference system.

This represents a thoughtful iteration on a useful shorthand feature, though some design questions remain about edge cases and whether the remote-HEAD-based resolution matches user expectations in all scenarios. The patch appears well-constructed with proper test coverage, making it a solid candidate for further review and discussion.
