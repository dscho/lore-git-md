This is a bugfix patch in Patrick Steinhardt's series addressing ref iteration issues in bisect and bitmap code. The patch simplifies memory management in the bisect cleanup code by Jeff King, who originally authored this change.

The patch changes how string allocations are handled when collecting bisect refs for removal. Previously, the code used a confusing pattern where it manually allocated strings for a NODUP string_list, then flipped the list to DUP mode just for cleanup. Now it consistently uses STRING_LIST_INIT_DUP from the start, letting the string_list handle all allocations automatically.

This is a straightforward cleanup that follows from an earlier change that made xstrfmt() calls unnecessary. The patch maintains all existing functionality while making the code more maintainable. It's part of a larger series that has already received technical approval from both Karthik Nayak and Junio Hamano, with this particular change coming from Jeff King's review feedback.

The change is small (6 lines net reduction) and focused purely on internal memory management, with no user-visible effects. It demonstrates the kind of incremental quality improvement that often comes from thorough code review on the Git list.
