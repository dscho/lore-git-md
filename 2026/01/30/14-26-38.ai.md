This is a bugfix patch in the completed `git last-modified` series from Toon Claes. The patch adds validation to ensure the input revision is commit-ish (can be peeled to a commit) rather than accepting any object type, which previously triggered a BUG() when given a tree object. The fix uses `repo_peel_to_type()` to explicitly check the object type before processing.

The patch also includes a test case demonstrating the command works with annotated tags, requiring a tweak to the test setup to avoid ambiguous tag resolution when calling `git name-rev`. A new test verifies the error message when a tree object is provided. This completes the hardening of input validation for the command, building on earlier patches that fixed memory leaks and error handling.

The implementation now properly distinguishes between revision syntax (which can name any object) and the requirement for commit objects in this particular command, with clear error messaging. This aligns with the ongoing discussion about "revision" terminology in Git's documentation while providing immediate practical improvements to the command's robustness.
