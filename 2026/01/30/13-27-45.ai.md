This is a memory handling cleanup patch in the bisect subsystem, part of Patrick Steinhardt's v2 series fixing `refs_for_each_ref_in()` usage. The patch simplifies string_list memory management in `bisect_clean_state()` by using `STRING_LIST_INIT_DUP` instead of manual string duplication and cleanup.

The change builds on Jeff King's earlier suggestion to clean up the string_list pattern where strings were manually allocated but then relied on string_list_clear() to free them. The patch removes this confusing approach by letting the string_list handle all string duplication automatically through its DUP flag. This makes the code more straightforward while maintaining identical functionality.

The modification affects how bisect-related refs are collected for removal, including both packed refs under "refs/bisect/" and special bisect refs like "BISECT_HEAD". The patch follows naturally from the preceding commit's switch to xstrdup(), allowing full use of the string_list's built-in memory management capabilities.

This is the final patch in the series, with all technical aspects already reviewed and approved by both Karthik Nayak and Junio Hamano. The change is purely a cleanup with no behavior modification, so it should land cleanly as part of the overall fix for the ref iteration issue.
