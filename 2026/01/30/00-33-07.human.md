This is a documentation patch improving the `--expire` option explanation for `git worktree prune` and `git worktree list`. The change clarifies that `--expire` only affects missing worktrees (those where the underlying directory no longer exists), not all stale worktrees.

The patch has gone through three iterations (v3) and appears ready for merging, having addressed feedback from both Eric Sunshine and Junio Hamano. The improvement is straightforward and uncontroversial - it simply makes the documentation more precise about the option's behavior. 

This is part of ongoing worktree documentation improvements, though it's a small standalone change rather than part of a larger series. The patch looks well-considered and ready to progress to the 'next' integration branch.
