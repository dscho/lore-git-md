This is a follow-up discussion about the proposed `@{default}` shorthand feature for referencing a repository's default branch. The original patch aimed to add syntax like `git checkout @{default}` as a shortcut for checking out whatever branch is configured as the default (via `init.defaultBranch` or falling back to "main"/"master").

The author, Harald Nordgren, responds to Junio Hamano's concerns about the feature's design. Key points in this reply:

1. **Syntax clarification**: Agrees that per-branch syntax like `topic1@{default}` doesn't make sense (since default branch is repository-wide) and will update the code to reject such usage.

2. **Use case defense**: Argues the feature remains useful even when users rename default branches locally, as it would still resolve to whatever the local default is. Shares personal workflow where they frequently clone repositories with varying default branch names ("master", "main", "develop") and currently uses an awkward shell pipeline to check out the default branch.

3. **Motivation**: Counters Junio's suggestion that users should standardize their default branch names globally, noting that when cloning others' repositories, you inherit whatever default branch name they use. The shorthand would eliminate the need to manually rename branches or remember repository-specific defaults.

The discussion remains unresolved, with the author making a case for the feature's utility while addressing some (but not all) of Junio's conceptual concerns. The patch appears technically sound but still faces questions about whether the use case justifies adding new syntax to Git's revision parsing machinery.
