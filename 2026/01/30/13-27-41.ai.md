This is a bugfix series addressing issues with `refs_for_each_ref_in()` usage in bitmap and bisect functionality. The series consolidates bitmap tip iteration logic and fixes cases where exact ref matches would trigger a BUG() due to incorrect prefix stripping.

Patrick Steinhardt's v2 series incorporates feedback from v1 and adds Jeff King's simplification of bisect string_list handling. The key changes are:

1. Deduplicates bitmap tip iteration logic between pack-objects and midx into a new `for_each_preferred_bitmap_tip()` function, making `bitmap_preferred_tips()` private to pack-bitmap.c.

2. Fixes the bitmap case by replacing `refs_for_each_ref_in()` with `refs_for_each_fullref_in()`, allowing exact ref matches while maintaining the existing behavior where "refs/heads/base" also matches "refs/heads/base-something". The documentation is updated to clarify the prefix matching semantics.

3. Fixes a similar issue in bisect.c by using `refs_for_each_fullref_in()` with proper "refs/bisect/" prefix handling.

4. Incorporates Jeff King's cleanup that simplifies bisect's string_list memory management by switching from NODUP to DUP mode.

The series has received positive reviews from Karthik Nayak and Junio Hamano on the technical changes, with ongoing discussion about whether to maintain the current prefix-matching behavior or align with stricter hierarchical matching (where "refs/heads/foo" would only match "refs/heads/foo/bar" with a trailing slash). Patrick leans toward keeping the current behavior for backward compatibility but remains open to change if consensus favors hierarchy matching.

The patch set includes comprehensive tests in t5310-pack-bitmaps.sh and t5319-multi-pack-index.sh to verify the fixes work for exact refs in pack.preferBitmapTips. All technical aspects appear sound, with the remaining work focused on finalizing documentation wording around the matching semantics.
