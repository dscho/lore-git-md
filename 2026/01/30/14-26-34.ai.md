This is a bugfix series for the `git last-modified` command, addressing several issues that surfaced after the initial implementation was merged. The core problem was that passing a tree object ID would trigger a BUG() due to insufficient input validation, but the series has expanded to cover related error handling and memory management issues.

The v6 iteration specifically fixes a CI failure on Windows/Meson builds where the test output differed from expectations in recursive mode (-r). The series now includes comprehensive validation to ensure the input is a commit-ish (not a tree), proper error messaging, and complete resource cleanup. Key technical changes include using `repo_peel_to_type()` for commit validation, fixing memory leaks in pathspec handling, and refining error messages to use consistent terminology ("commit-ish" rather than "revision").

The patches also demonstrate careful attention to test coverage, including adding tests for annotated tag handling and explicit verification of error message content. The Windows/Meson issue was addressed by modifying the test to exclude a specific tag when calling `git name-rev` to avoid ambiguous results.

This represents the final iteration of fixes for this functionality, with all technical requirements now met and the series ready for merging. The remaining loose ends are documentation discussions about Git's terminology for "revision" versus "commit" that surfaced during review, but these don't block the technical improvements.
