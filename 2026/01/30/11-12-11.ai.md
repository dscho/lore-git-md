This is a follow-up in the ongoing discussion about adding a `@{default}` shorthand for referring to a repository's default branch. Harald Nordgren reports encountering unexpected behavior when testing the proposed feature - many repositories on his system fail to recognize `@{default}` as a valid reference, despite presumably having a default branch configured.

The email highlights a practical issue with the implementation: the shorthand doesn't gracefully handle cases where the default branch name (from `init.defaultBranch` config) doesn't match any existing branch in the repository. This could occur if the default branch was renamed or deleted, or if the repository was initialized with a non-standard default name.

This observation strengthens Junio Hamano's earlier concerns about edge cases where the configured default name might not match reality. The problem appears more widespread than initially thought, with Harald finding "quite a few" repositories exhibiting this behavior during testing. The issue could significantly impact the usefulness of the proposed shorthand, as it would fail in many real-world scenarios rather than falling back gracefully.

The technical details remain unchanged from the previous discussion - the shorthand would still resolve via `init.defaultBranch` (falling back to "main"/"master"), but this email surfaces a concrete problem with that approach. The discovery may influence the ongoing debate about whether the feature's benefits outweigh its edge cases and implementation challenges.
