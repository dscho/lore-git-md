This is a bug report about inconsistent behavior in `git add` when dealing with invalid paths. The reporter, Jon Forrest, notes that while `git add` fails to stage any files when given a non-existent path (even if other paths are valid), it *does* stage valid files when some paths are ignored (via .gitignore). This inconsistency in error handling appears unintentional - the reporter reasonably expected both cases to be treated the same way (either failing completely or proceeding partially).

The issue is well-documented with clear reproduction steps and demonstrates a real behavioral discrepancy that could trip up users. While not a critical bug, it affects the principle of least surprise in Git's CLI behavior. The report follows up on a previous discussion with Jeff King (Peff) about related `git add` behavior, showing the reporter has done due diligence in researching the issue before reporting.
