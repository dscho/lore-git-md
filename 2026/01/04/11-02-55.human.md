This is a UI improvement patch for `git add -p`, part of Abraham Samuel Adekunle's Google Summer of Code project. The patch enhances the interactive hunk selection interface by showing whether each hunk was previously marked for use ('y') or skip ('n') when navigating between hunks.

The change modifies the prompt strings in `add-patch.c` to include a "previous decision" indicator, showing either "(previous decision: use)" or "(previous decision: skip)" when revisiting hunks. This helps users keep track of their selections as they navigate through hunks using the K/J' keys. The patch includes corresponding test updates to verify the new behavior.

Junio C Hamano reported the original issue, and this is the fourth iteration of the patch. The v4 changes focus on fixing a test case that was skipped in v3 due to macOS-specific behavior. The implementation appears clean and focused, with thorough test coverage across different `add -p` modes (stage, stash, checkout, etc.).

This is a well-motivated quality-of-life improvement for a commonly used interactive Git command. The patch series has clearly gone through several rounds of review and refinement, suggesting it's likely to be in good shape for inclusion.
