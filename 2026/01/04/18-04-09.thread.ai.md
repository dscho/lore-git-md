Documentation style discussion about formatting command-line options in man pages, focusing on whether to use backticks (`` `--option` ``) versus plain (`--option`). Thread starter noted inconsistencies between commands like `git-am` (uses backticks for rerere options) and `git-prune`/`git-name-rev` (no backticks). Junio C Hamano clarified the project's direction is toward *adding* more backticks for proper AsciiDoc markup, not removing them, citing commit f7316a66 and Jean-Noël Avila's synopsis-style conversion work as the reference implementation. This establishes that even individual option descriptions should get proper markup, and contributors should study Avila's work when making documentation improvements. The discussion is part of broader documentation standardization but distinct from the main synopsis-style conversion project. Would affect Documentation/rerere-options.adoc and potentially other files. No open questions remain - Junio's response provides clear guidance to follow the more-fully-marked-up style seen in f7316a66.
