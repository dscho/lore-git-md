This is a follow-up discussion about an RFC patch to add warnings for skipped merge commits in `git format-patch`. The original patch proposed showing a warning when merge commits are silently skipped during patch generation, particularly when no patches are produced at all.

Junio Hamano responds to Dominique Martinet's suggestion of using a generic warning message ("No patch generated. Note merge commits are skipped"). While agreeing with the basic approach, Junio suggests some implementation refinements: either tracking merge commits in a separate list to allow more detailed warnings later, or simply counting skipped merges to show a count in the message. 

The discussion shows consensus on the warning being useful when no patches are generated, but with care needed to avoid being overly verbose. Junio's suggestions aim to keep the implementation flexible for future enhancements while maintaining simplicity. The thread indicates this is a small, focused change that will likely proceed to a v2 with test coverage and the NULL-deref fix Jeff King identified earlier.
