This is a bug report about the `git last-modified` command, which appears to be a third-party Git extension (not part of core Git) that aims to show the last modification time of files. The reporter, working on Forgejo (a Git hosting platform), found three issues:

1. **Performance regression**: `git last-modified` is significantly slower (151ms vs 87ms) than the equivalent `git log --max-count=1` for checking when a file was last modified.

2. **Directory handling**: The command doesn't properly distinguish between a directory and its contents - it returns the same commit hash for both `web_src` and `web_src/svg`.

3. **Crash on invalid input**: Passing a tree object ID directly causes the command to crash with a BUG() message rather than handling the error gracefully.

The report is well-structured with clear reproduction steps and benchmark comparisons. The issues suggest the command may have incomplete path handling and input validation. Since this isn't a core Git command, the next step would likely be to contact the maintainers of whatever provides `git-last-modified`.
