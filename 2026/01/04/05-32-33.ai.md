Maintainer feedback on xdiff refactoring series.

Junio C Hamano provides review comments on the first patch of Ezekiel Newren's xdiff refactoring series, focusing on coding style issues in the new `ivec` (interoperable vector) implementation. The patch introduces C-side infrastructure for Rust/C interoperability as part of preparing xdiff for future optimizations.

Junio notes two specific deviations from Git's coding conventions in the `ivec` implementation:
1. The pattern for handling zero-capacity cases should use Git's standard `FREE_AND_NULL` macro rather than explicit `free()` and NULL assignment.
2. Single-line comments should use `/* */` style rather than C++-style `//` comments.

These are mechanical style issues that don't affect functionality but need addressing to pass Git's automated style checks (`coccicheck`). The feedback suggests the technical direction is acceptable but the implementation needs minor polishing to meet project conventions before merging.

The review doesn't raise concerns about the architectural approach or the placement of Rust-interop code in `compat/` (which was flagged as a potential issue in the cover letter discussion), focusing instead on straightforward style fixes for this initial patch.
