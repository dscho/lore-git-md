This is a bugfix discussion thread about handling non-UTF-8 encoded `.gitignore` (exclude) files, particularly UTF-16LE files with BOM created by Windows PowerShell. The original patch proposed comprehensive Unicode handling with BOM detection and conversion to UTF-8, but Torsten Bögershausen raises several concerns in this reply.

Torsten questions whether Git should attempt universal Unicode handling at all, suggesting instead that it might be better to either bail out on files containing null bytes (like UTF-16) or implement minimal BOM detection for the specific UTF-16LE case reported by Windows users. He notes that PowerShell can be configured to use UTF-8, implying the problem might be better solved at the tooling level rather than in Git.

The reply also highlights technical issues with the proposed solution, including problems with iconv's encoding names and the questionable value of checking working-tree encoding from `.gitattributes`. Torsten provides an alternative code snippet for handling UTF-16LE BOM detection more directly.

This moves the discussion toward deciding whether Git should handle this as a special case for Windows users or take a more conservative approach that fails clearly on non-UTF-8 files. The thread appears to be heading toward a narrower solution focused on the immediate Windows/PowerShell case rather than comprehensive Unicode support.
