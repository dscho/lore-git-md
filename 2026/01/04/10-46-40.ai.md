This is a bugfix patch for the reftable backend, addressing undefined behavior in the indexed table reference iterator. The patch comes from Tsahi Elkayam, a relatively new contributor to the project.

The issue involves the `indexed_table_ref_iter_next()` function in `reftable/iter.c` which was accessing union members without first checking the reference type, potentially leading to undefined behavior. The function handles two types of refs - single-value (REFTABLE_REF_VAL1) and double-value (REFTABLE_REF_VAL2) - but was only properly checking the type for VAL2 refs.

The fix follows the pattern already established in `filtering_ref_iterator_next()`, properly checking the `value_type` before accessing the corresponding union members. This includes:
1. Adding a check for REFTABLE_REF_VAL2 before accessing val2 members
2. Adding a previously missing check for REFTABLE_REF_VAL1 refs

The patch is small (13 lines changed) and focused, touching only the iterator implementation in the reftable subsystem. It addresses a known issue that was previously marked with a "/* BUG */" comment. The change appears straightforward and low-risk, following established patterns in the codebase. This is the second version of the patch (v2), suggesting it has already undergone some review iteration.
