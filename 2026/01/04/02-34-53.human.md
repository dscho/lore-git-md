This is a follow-up in a thread about a bugfix for a racy test in the difftool test suite. The original issue involved Windows CI failures where files with identical sizes (12 bytes) could be misdetected due to filesystem quirks. The fix modified the test to use different-sized content (17 bytes) to ensure reliable detection.

Junio Hamano notes that while the test fix is sound, the underlying issue with difftool's change detection on systems without inodes (like Windows and some network filesystems) remains. He suggests renaming "inode" to "inode number" in the commit message for precision, and hints that a deeper fix for the difftool command itself might be needed long-term. The patch is already queued for merging, having gone through three iterations with review from Johannes Schindelin (Git for Windows maintainer) and technical discussion with Phillip Wood.

The thread revealed that difftool's temporary index initialization can fail to detect same-size modifications on systems without inodes, which remains an open issue for scripted use cases. While this particular test fix is uncontroversial and merges as-is, the discussion surfaces a broader platform-specific challenge in Git's stat-based change tracking.
