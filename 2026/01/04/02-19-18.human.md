This is a bugfix for a memory leak in Git's fsmonitor daemon client handling code. The patch addresses a 40-byte leak per client request that occurs when using the wrong cleanup function (`kh_release_str()` instead of `kh_destroy_str()`) for a khash table in `do_handle_client()`.

The fix is minimal (5 lines) and well-contained, switching to the proper cleanup function and ensuring safe handling on all exit paths. The issue was discovered by Paul Tarjan, who submitted it separately from a larger fsmonitor-linux patch series since it fixes an existing bug that may warrant quicker merging.

Junio C Hamano notes this fix is already included in v4 of the larger series but acknowledges the rationale for submitting it independently. The thread shows consensus on the technical solution, with René Scharfe having reviewed and confirmed the correctness of the approach. This appears to be a straightforward, uncontroversial fix for a clear memory leak in production code.
