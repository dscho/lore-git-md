This thread discusses performance and behavior issues in the relatively new `git last-modified` command, which was designed to optimize last-modified queries for multiple files. Gusted@Codeberg.org initially reported three problems when testing on a Forgejo repository: a performance regression for single-file queries compared to `git log`, inconsistent behavior when checking parent vs. child directories, and a crash when passing tree commit IDs directly.

Toon Claes, the command's author, responded with clarifications about the design tradeoffs. While acknowledging the single-file case is slower (151ms vs 87ms for `git log`), he demonstrated the command's strength lies in bulk queries where it outperforms `git log` by 6x. For the directory handling, he proposed changing the default behavior to properly distinguish between parent and child directories when using `-r --max-depth=0`. The crash when passing tree IDs was confirmed as a genuine bug needing fixing.

The discussion reveals this is an actively maintained command where real-world usage is helping refine its behavior. While optimized for its primary multi-file use case, there's room to improve edge cases and error handling based on user feedback. The author appears receptive to addressing the reported issues while explaining the command's intended optimization strategy.
