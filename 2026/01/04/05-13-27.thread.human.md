This thread discusses performance and behavior issues with the relatively new `git last-modified` command, reported by Gusted@Codeberg.org while testing on a Forgejo repository. Command author Toon Claes has been actively responding to the feedback point by point.

The discussion centers on three key issues. First, while the command is slower than `git log` for single-file queries (151ms vs 87ms), Claes demonstrates it's actually 6x faster for bulk operations - its intended use case. Second, the current behavior returns identical commit hashes for parent and child directories, which both parties agree is confusing; Claes proposes changing this to match `-r --max-depth=0` behavior, and Gusted supports this as more intuitive. Third, they've identified and confirmed a crash when passing tree commit IDs directly, which needs proper error handling instead of the current BUG() assertion.

The thread shows good collaboration between a user encountering real-world issues and a maintainer willing to address them. While the performance characteristics are working as designed for bulk operations, the directory behavior change and crash fix appear to be moving toward implementation based on the constructive discussion.
