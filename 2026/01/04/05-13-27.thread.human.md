Here's a human-readable thread summary:

This thread reports performance and correctness issues in the relatively new `git last-modified` command, which is meant to quickly find the last commit that modified a file. Gusted from Codeberg.org found three problems while testing on the Forgejo repository: first, the command is actually slower (151ms) than just using `git log --max-count=1` (87ms), defeating its performance optimization purpose. Second, it incorrectly returns the same commit for a directory and its subdirectory (`web_src` vs `web_src/svg`), when these should have distinct modification times. Third, passing a tree object ID crashes Git with a BUG() assertion rather than handling the error gracefully.

The report includes reproducible test cases and timing data from Git 2.52.0 on Arch Linux. These appear to be genuine bugs - the directory behavior contradicts how `git log` works, and the crash on tree objects is clearly unintended. This is a resend as the original report may not have reached the mailing list. The command's author or maintainers will need to address these issues to make `git last-modified` reliable for its intended use case.
