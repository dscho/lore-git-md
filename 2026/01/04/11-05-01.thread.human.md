This thread reports a bug in `git stash` where untracked files can be silently overwritten during a reset operation when they share a name with a previously tracked file. The current implementation uses `reset --hard`, which destroys the untracked content, while the contributor suggests switching to `reset --merge` to fail safely instead. 

The issue is reproducible and already documented in the test suite (`t/t2500-untracked-overwriting.sh`) as a known but unresolved problem. The proposed fix would modify `builtin/stash.c` to use `--merge`, preventing data loss while maintaining the same behavior in non-conflicting cases. The contributor, who identifies as a beginner, is seeking feedback on whether this is the right approach. Given the existing test case marked for this issue, it appears the problem has been recognized but not yet addressed by the project. The change seems well-motivated as it makes the operation safer without breaking expected behavior.
