This thread addresses a style question in Git's documentation: whether command-line options in man pages should be wrapped in backticks (like `` `--option` ``) or left plain. The original poster noted inconsistencies between commands, with `git-am` using backticks for rerere options while `git-prune` and `git-name-rev` do not.

Junio C Hamano clarified that the project's direction is actually toward *more* consistent use of backticks for proper AsciiDoc markup, not less. He pointed to Jean-Noël Avila's ongoing synopsis-style conversion work as the reference implementation, citing commit f7316a66 as an example of the preferred style where even individual option descriptions get proper markup. This means contributors working on documentation improvements should follow Avila's lead in adding backticks where appropriate, rather than removing them for consistency with older, less-marked-up pages.

While this discussion is related to the broader documentation standardization effort, it appears to be a distinct subtopic from the main synopsis-style conversion project. The takeaway is that when in doubt, contributors should err on the side of more complete AsciiDoc markup, using backticks for options as shown in recent examples from Avila's work.
