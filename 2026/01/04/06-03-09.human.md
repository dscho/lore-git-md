UI improvement for `git add -p` showing previous hunk decisions. This is the third iteration of a patch from a GSoC student that adds visual feedback to `git add -p`'s interactive interface, showing whether each hunk was previously marked for staging ('y') or skipping ('n') when navigating between hunks.

The patch modifies prompt strings in `add-patch.c` to include state information, with the prompt now showing "(previous decision: use/skip)". The change affects all interactive patch modes (stage, stash, reset, checkout) while maintaining existing functionality. Test expectations in `t3701-add-interactive.sh` have been updated to verify the new behavior.

Junio Hamano has identified a test failure in the PAGER output where the test expectations don't match the actual output with the new decision indicator. This appears to be the only remaining issue before the patch can be merged. The change is well-scoped and addresses a real usability pain point where users lose track of their decisions when moving between hunks.
