Feature enhancement for `git status` showing push tracking branch comparison. This is the second and final patch in a series that adds push tracking information to `git status` output when it differs from the upstream tracking branch.

The patch implements the core functionality after the preparatory refactoring in part 1. It adds a new `get_remote_push_branch()` helper to resolve the push tracking reference, then extends `format_tracking_info()` to show both upstream and push comparisons when they differ. The output maintains Git's existing format but adds a second status line when appropriate, with push-specific advice.

Key aspects:
- Only shows push comparison when it differs from upstream
- Preserves all existing behavior and output formats
- Handles custom refspec mappings through full resolution chain
- Adds extensive test coverage (210 lines) for various scenarios
- Includes edge cases like diverged branches and remapped refspecs

The implementation has gone through 14 iterations with thorough review from Phillip Wood and maintainer guidance from Junio C Hamano. All technical concerns have been addressed, including proper refspec handling identified during review. The patch is now complete and ready for inclusion.

Example output shows the new dual-status format when branches diverge between upstream and push destinations, providing clearer visibility into both tracking relationships. This fulfills the original use case of tracking progress against both an upstream branch and a feature branch push destination.
