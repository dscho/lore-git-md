This thread reports an inconsistency in `git add`'s behavior when handling different types of invalid files. Jon Forrest found that while `git add` fails completely when given a mix of existing and non-existent files, it partially succeeds (adding the non-ignored files) when given a mix of ignored and non-ignored files. The report includes clear reproduction steps demonstrating this difference in behavior.

The core question is whether this discrepancy is intentional design or a bug that should be fixed. The behavior touches on error handling in `git add` and whether ignored files and missing files should be treated consistently - either failing completely or succeeding partially in both cases. The report is well-documented with test cases that make the issue easy to verify. No responses or resolutions have been posted yet.
