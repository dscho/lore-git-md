This is a bugfix discussion about handling non-UTF-8 encoded `.gitignore` (exclude) files, particularly focusing on UTF-16LE files with BOM created by Windows PowerShell. The thread shows Torsten Bögershausen responding to Matthieu Beauchamp-Boulay's initial patch proposal.

Torsten raises several key points in his review. He questions whether Git should universally handle UTF-8 conversion for exclude files, suggesting this might be too broad a solution for what appears to be a Windows-specific edge case. He notes that PowerShell can be configured to use UTF-8, implying the issue might be better addressed through user education rather than code changes.

The review proposes alternative technical approaches, including simply detecting and rejecting UTF-16 files (those containing null bytes) rather than attempting conversion. Torsten also questions whether Git should consult `.gitattributes` for working tree encoding at all in this context, suggesting the patch's scope may be overreaching.

The discussion highlights the tension between robust Unicode support and Git's traditional handling of platform-specific encoding expectations. Torsten's comments indicate this may need more design discussion before implementation details are settled, particularly around whether UTF-8 conversion should be universal or platform-dependent. The thread remains open on fundamental questions about Git's encoding strategy for exclude files.
