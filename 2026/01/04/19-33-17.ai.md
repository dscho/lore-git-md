This is a bug report about inconsistent behavior in `git add` when dealing with ignored versus missing files. Jon Forrest reports that while `git add` fails completely (adding nothing) when given a mix of existing and non-existent files, it partially succeeds (adding the non-ignored files) when given a mix of ignored and non-ignored files.

The report includes clear reproduction steps showing that `git add file1 jon` (where file1 is ignored but jon exists) adds jon to the index while warning about the ignored file1, whereas a similar command with a non-existent file would add nothing. The author questions whether this difference in behavior is intentional.

The issue touches on the error handling logic in `git add` and whether it should treat ignored files and missing files as equivalent cases where the command should either fail completely or succeed partially. This could be considered a bug (if the behaviors should be consistent) or a documentation issue (if the difference is intentional but not clearly explained). The report is well-structured with clear test cases, making it easy to verify the described behavior.
