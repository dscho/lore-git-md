Refactoring patch for `git status` tracking info display. This is the first of two patches implementing a feature to show divergence from both upstream and push tracking branches, following Junio C Hamano's guidance to use Git's existing branch tracking mechanisms.

The patch extracts the branch comparison formatting logic from `format_tracking_info()` into a new `format_branch_comparison()` function, keeping the same behavior but making the code more modular. The refactoring:

1. Separates message formatting from advice generation
2. Maintains all current output cases (ahead, behind, diverged, quick mode)
3. Preserves single ref resolution while preparing for dual tracking display
4. Cleans up variable initialization and memory management
5. Handles edge cases like gone upstream branches

The changes address Junio's review feedback by removing redundant parameters, simplifying conditionals, fixing style violations, and verifying output equivalence. The refactoring is a clean preparatory step that enables the subsequent patch to add push tracking display without duplicating formatting logic.

This patch has already been merged with maintainer feedback incorporated, and the technical direction has been approved. The implementation demonstrates careful attention to preserving existing behavior while improving code structure for future extension.
