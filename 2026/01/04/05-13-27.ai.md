This is a bug report about performance and behavior issues in the `git last-modified` command. The contributor Gusted from Codeberg.org identifies three specific problems while testing the command on the Forgejo repository:

1. **Performance regression**: `git last-modified` is significantly slower (151ms) than the equivalent `git log --max-count=1` (87ms) when checking modification times for individual files, which defeats its purpose as a performance optimization.

2. **Directory handling bug**: The command fails to properly handle paths within directories, returning the same commit hash for both a directory (`web_src`) and its subdirectory (`web_src/svg`), when it should return distinct modification times.

3. **Crash on invalid input**: Passing a tree commit ID directly to the command triggers a BUG() assertion and crashes Git with an IOT instruction (core dumped), rather than gracefully handling the invalid input.

The report includes reproducible test cases and timing measurements from Git v2.52.0 on Arch Linux. The issues appear to be genuine bugs rather than misunderstandings of the directory behavior should differ from `git log`'s, and the crash on tree objects is clearly unintended.
