Patch review from Jeff King (Peff) addressing a potential segfault in Dominique Martinet's RFC patch about warning for skipped merge commits in `git format-patch`. 

This is a bugfix suggestion for the merge commit warning patch. Peff points out a subtle but important edge case - the current implementation would crash when encountering a root commit (one with no parents) because it unconditionally dereferences `commit->parents->next`. He suggests adding a null check for `commit->parents` first.

The fix is straightforward but critical - root commits are rare in practice but must be handled correctly. Peff's review demonstrates his characteristic attention to edge cases and memory safety, though he notably avoids weighing in on the larger debate about whether the warning behavior itself is desirable. This keeps the focus narrowly technical while ensuring any future implementation will be robust.

The thread context shows this is part of an ongoing discussion about making `format-patch`'s merge commit handling more transparent. The core question of when/if to warn about skipped merges remains open, but Peff's input ensures that whatever solution emerges will properly handle all commit types.
