This is a bugfix patch for the reftable backend, addressing undefined behavior in the indexed table reference iterator. The issue occurs when accessing union members without first checking the reference type, which could lead to memory corruption or crashes when processing malformed input.

The patch fixes `indexed_table_ref_iter_next()` to properly check `value_type` before accessing either `val1` or `val2` members of the union, matching the pattern already used elsewhere in the codebase. The change handles both single-value (REFTABLE_REF_VAL1) and double-value (REFTABLE_REF_VAL2) reference types correctly.

The fix is straightforward and appears well-justified - it addresses a known issue marked with a "BUG" comment in the original code. The patch touches only the reftable iterator implementation in `reftable/iter.c`, with no user-visible behavior changes beyond making the code more robust against invalid input. This is part of the ongoing reftable backend work led primarily by Patrick Steinhardt and Karthik Nayak.
