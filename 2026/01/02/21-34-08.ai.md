This is the first patch in a 2-part series (v12) implementing a feature enhancement for `git status` to show divergence from both upstream and push tracking branches. The series has undergone extensive review and refinement, with this version incorporating feedback from Phillip Wood and others.

The patch refactors `format_branch_comparison()` in `remote.c` to prepare for the push tracking branch display. Key changes:
- Extracts the comparison formatting logic into a standalone function that can be reused for both upstream and push comparisons
- Separates the message formatting from the advice generation
- Maintains all existing behavior while making the code more modular
- Preserves the optimization of single ref resolution from earlier versions

The refactoring follows Git's conventional style and appears well-tested, with 167 lines of test coverage verifying all scenarios. This is a mechanical preparation step for the actual feature implementation in patch 2/2, which will use this refactored code to show push remote comparisons when they differ from upstream.

The thread history shows this approach was refined based on Junio Hamano's feedback to use existing branch tracking mechanisms rather than introducing new configuration. The implementation now leverages `branch.<name>.pushRemote` when configured, falling back to tracking branch if unset.
