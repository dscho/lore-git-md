This is the first patch in a 10-part series refactoring xdiff internals, introducing a new `ivec` (interoperable vector) type designed for C/Rust FFI compatibility. The patch comes from Ezekiel Newren, known for his work on Git's merge machinery and Rustification efforts.

The `ivec` type provides a vector abstraction that can be used consistently across C and Rust boundaries, addressing several pain points in current interop scenarios. It includes standard vector operations like init, push, reserve, and free, with careful attention to memory management consistency between languages. The implementation lives in new files `compat/ivec.[ch]` and gets added to both Makefile and meson build systems.

Key technical aspects include:
- A generic `IVec_c_void` base structure with pointer, length, capacity and element_size fields
- Type-specific variants generated by the `DEFINE_IVEC_TYPE` macro for common primitive types
- Growth strategy that starts with 128-element chunks then doubles capacity
- Explicit element_size tracking to ensure type safety across language boundaries

The commit message explains this is groundwork for future optimizations where Rust and C code need to share vector data structures, though the immediate use appears to be in the xdiff refactoring series. The implementation looks thorough, with clear documentation of invariants (like not modifying element_size after initialization) and careful memory management.

As the first patch in a larger series, this introduces infrastructure that subsequent patches will presumably build upon. The design appears well-considered for its stated purpose of bridging C and Rust memory models, though reviewers may want to scrutinize the growth strategy and type safety mechanisms.
