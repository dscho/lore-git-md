This is the first patch in a 10-part series refactoring Git's xdiff subsystem, introducing a new interoperable vector (ivec) type designed to work across C and Rust boundaries. The patch adds a new `ivec` implementation in `compat/ivec.[ch]` that provides vector operations (push, reserve, free, etc.) with a consistent interface between C and future Rust code. The motivation stems from difficulties in sharing vector operations between the languages - Rust's Vec isn't be used directly in C, and Git's ALLOC_GROW macros would be awkward to expose to Rust.

The implementation includes type-specific vector definitions (IVec_u8, IVec_i32, etc.) via macros, with core operations that track length, capacity, and element size. The design explicitly considers future migration - the commit notes these could eventually be replaced by Rust Vec once interoperability isn't needed. This appears to be groundwork for the series' later xdiff optimizations and part of Ezekiel Newren's broader Rustification efforts.

The patch is cleanly implemented with thorough documentation of the design rationale. As the first in a series, its value will become clearer as subsequent patches build on it, but it stands as a reasonable foundation for cross-language vector operations. Reviewers will likely scrutinize whether this abstraction is truly necessary versus using existing Git allocation patterns.
