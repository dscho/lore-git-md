Feature enhancement for `git status` showing push remote divergence. This is the final v11 patch in a series that has evolved through multiple iterations based on feedback from Junio C Hamano, Ben Knoble, and others.

The patch modifies `git status` to show an additional comparison with the push remote's tracking branch when configured (via `branch.<name>.pushRemote` or `remote.pushDefault`). The output appears on a separate line after the existing upstream tracking info, using the same format for ahead/behind/diverged states. For example:
```
On branch feature
Your branch is ahead of 'upstream/main' by 2 commits.
  (use "git pull" to integrate)

Ahead of 'origin/feature' by 5 commits.
```

Key implementation details:
- Uses `pushremote_for_branch()` to determine the push remote
- Falls back to tracking branch if pushRemote is unset
- Renamed functions from earlier versions to reflect pushRemote approach
- Maintains all optimizations from previous iterations
- Includes comprehensive test coverage (167 lines added) for various scenarios:
  * Ahead/behind/diverged states
  * Remote configurations (origin vs upstream)
  * Edge cases and output format verification

The patch represents the culmination of the discussion, having addressed all technical feedback and maintainers' concerns. The only remaining open question is about commit organization philosophy (Git's conventional logical progression vs GitHub-style squashing), but the implementation itself appears ready for potential inclusion.
