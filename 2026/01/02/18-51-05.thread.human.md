This thread follows a Google Summer of Code student's proposal to improve `git add -p` by adding visual feedback about previous hunk decisions (whether each hunk was marked for staging or skipping). The patch series has progressed through three versions, with the latest (v3) appearing technically sound after incorporating feedback from Phillip Wood, the resident `git add -p` expert.

The core change adds a "(previous decision: use/skip)" indicator to the interactive prompt, addressing a common usability issue where users lose track of their selections. The implementation affects all interactive patch modes and maintains backward compatibility. While the series seemed ready for merging, Junio Hamano spotted a minor oversight - a test case involving the PAGER wasn't updated to expect the new prompt format.

The fix should be straightforward - updating the test expectation to match the new prompt text. Given Phillip Wood's prior approval of the technical approach and the narrow scope of the remaining issue, this series appears likely to be merged once the test is addressed. The change represents a clear usability improvement for a frequently used interactive command.
