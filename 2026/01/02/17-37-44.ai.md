Performance optimization follow-up in the byte-swapping modernization series. Rostislav Krasny responds to Jeff King's detailed performance analysis of the initial patch that replaced manual bit-twiddling with `memcpy`-based byte swapping in `compat/bswap.h`.

Krasny clarifies the primary motivation is code simplicity and consistency rather than performance gains, noting the inconsistency between using optimized `ntoh*` macros for values while having more complex pointer-handling code in `get_be*` functions. He acknowledges Jeff's point about -O0/-O1 benchmarks being less meaningful for production builds but maintains that easier compiler optimization at lower levels still indicates no performance regression.

The exchange reveals differing perspectives on the patch's value: Jeff sees potential in the Clang -O2 speedup but questions real-world impact, while Rostislav emphasizes code quality improvements beyond just performance. The technical discussion remains focused on whether the changes provide enough benefit to justify touching these low-level, critical-path functions. No new benchmarks or code changes are proposed in this response - it primarily serves to align expectations about the patch's goals.
