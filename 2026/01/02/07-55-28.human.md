This is a technical discussion about Git's handling of directory permissions, specifically the SGID bit, in response to a reported issue with rootless Podman containers.

Jeff King (Peff) responds to Hadmut Danisch's report that Git 2.43.0 on Ubuntu 24.04.3 appears to strip the SGID bit (mode 2770) during clone operations, breaking container workflows that rely on fixed permissions and automatic group inheritance. Peff provides a detailed test case showing that on his system, the SGID bit is correctly preserved and propagated to subdirectories during a clone operation.

The response suggests the behavior may be system-dependent or that there may be differences in the exact workflow being used. Peff's reproduction shows the expected behavior where:
- The initial directory has mode 2770 (SGID set)
- After cloning, both the top-level directory and all subdirectories maintain the SGID bit
- New files and directories inherit the correct group ownership

This contrasts with the original report where the SGID bit was reportedly lost. The thread continues to investigate whether this is a platform-specific issue, a difference in Git versions, or perhaps a misunderstanding of the exact steps being performed. The discussion remains technical and focused on reproducing and understanding the behavior rather than proposing solutions at this stage.
