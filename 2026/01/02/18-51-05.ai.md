This is a UI improvement patch for `git add -p`'s interactive hunk selection interface, part of a Google Summer of Code (GSoC) project. The patch is in its third iteration.

The change makes `git add -p` show whether each hunk was previously marked for use ('y') or skipping ('n') when navigating between hunks. This helps users keep track of their decisions as they move through the hunks. The patch modifies the prompt strings in `add-patch.c` to include this state information and updates the corresponding tests in `t3701-add-interactive.sh`.

The implementation adds a new `hunk_use_decision` string that shows either "(previous decision: use)" or "(previous decision: skip)" in the prompt, depending on the hunk's state. The change affects all interactive patch modes (stage, stash, reset, checkout, etc.) consistently.

The patch appears well-scoped and focused on its stated goal. It follows Git's coding style and includes test updates to verify the new behavior. The commit message clearly explains the motivation (requested by Junio C Hamano) and the benefit to users. The changes are mechanical but meaningful for the interactive workflow.

Key technical details:
- Modifies prompt strings in all patch_mode structs to accommodate the decision indicator
- Adds logic in `patch_update_file()` to determine and display the previous decision
- Updates test expectations to include the new decision text in prompts
- Maintains all existing functionality while adding the new feature
