This is the first patch in a v2 series improving error handling in `git replay`. The patch removes dead code and reorganizes a function that handles both `--onto` and `--advance` modes. 

The main discussion point is the function's name - the original `determine_replay_mode()` was changed to the more verbose `populate_for_onto_or_advance_mode()` in v2. Elijah Newren suggests this is too long and potentially confusing since the function handles both modes. Kristoffer Haugsbakk proposes `set_up_replay_mode` as an alternative. 

The patch itself is otherwise ready, having been reviewed by both Elijah Newren and Junio Hamano. It's part of a series that has evolved through multiple rounds of feedback, now focused on final polishing touches like this naming clarification. The series as a whole improves validation and error messages when invalid commit-ish arguments are given to `git replay`.
