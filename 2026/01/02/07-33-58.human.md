Bugfix suggestion for format-patch merge commit warning.

Jeff King (Peff) responds to Dominique Martinet's RFC patch about warning when `git format-patch` skips merge commits. While not commenting on the overall approach, Peff points out a potential segfault in the implementation - the current check for merge commits via `commit->parents->next` would crash if given a root commit (which has no parents).

This is a technical correction rather than a position on the thread's main discussion about when/if to warn about skipped merges. The fix is straightforward: add a null check for `commit->parents` before dereferencing it. This matches Git's typical pattern for handling root commits throughout the codebase.

The exchange shows the patch is receiving careful technical review from experienced contributors, even as the higher-level design questions about warning behavior remain open. Peff's note doesn't advance the thread's core debate but ensures any eventual solution will be technically sound.
