This is a bugfix patch addressing a memory leak in Git's fsmonitor daemon client handling code. The patch corrects improper cleanup of a khash table used for pathname deduplication in `do_handle_client()` by switching from `kh_release_str()` to `kh_destroy_str()`, fixing a 40-byte leak per client request.

The change is minimal (5 lines) and well-contained, with consensus already reached on the technical solution. Junio notes this fix is also included in v4 of a larger fsmonitor-linux series, but the author Paul Tarjan submitted it separately since it addresses an existing bug that could be merged independently.

The patch follows good practices by moving cleanup to the cleanup section and initializing variables to NULL for safe exit paths. While small, this fixes a clear memory leak that would accumulate during normal fsmonitor daemon operation. The fix is straightforward and unlikely to be controversial, though it may be folded into the larger fsmonitor series rather than merged separately.
