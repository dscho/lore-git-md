Bugfix for undefined behavior in reftable iterator. This patch addresses a known issue in the reftable backend's indexed_table_ref_iter_next() function where it was accessing union members without first checking the value_type, which could lead to undefined behavior. The fix follows the same pattern already used elsewhere in the codebase, properly checking the ref type before accessing the appropriate union fields (REFTABLE_REF_VAL1 or REFTABLE_REF_VAL2).

The change is straightforward and clearly motivated - the original code even had a "/* BUG */" comment marking the problematic section. The patch appears well-scoped and correctly implements the safety check pattern used in similar iterator code. This is part of the ongoing reftable backend work, though it stands alone as a clear correctness fix rather than a feature or refactoring.
