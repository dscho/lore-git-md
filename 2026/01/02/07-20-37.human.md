This is a UI improvement patch for Git's interactive patch selection interface, part of a Google Summer of Code project. The patch aims to `git add -p` and related commands by showing users their previous hunk selection decisions (use/skip) when navigating between hunks - a feature originally suggested by Junio Hamano.

The second version of the patch makes several improvements over v1: clearer subject line, support across all front-ends, more descriptive wording ("previous decision: use/skip"), and repositioning the indicator before the prompt choices. The changes are mechanical but touch multiple prompt strings and display logic in `add-patch.c`.

Junio has flagged a concern that the changes break test t3701 (which verifies interactive patch functionality), indicating the patch may need test updates to maintain backward compatibility. The author acknowledges this and plans to send an updated version with fixed tests.

The patch looks like a genuine usability improvement that makes interactive patch selection more intuitive. While the implementation appears straightforward, the test breakage suggests the changes may have subtle effects on existing behavior that will need careful verification. Given Junio's involvement in both suggesting the feature and reviewing the test impact, this seems likely to progress once the test issues are resolved.
