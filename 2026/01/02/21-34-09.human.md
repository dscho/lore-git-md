Feature enhancement for `git status` showing push tracking branch comparison. This is the second and final patch in a series that adds push tracking branch status to `git status` output when it differs from the upstream branch.

The patch implements the actual push tracking display using the refactored infrastructure from patch 1/2. When a branch's push destination differs from its upstream, `git status` now shows both comparisons - first the upstream status (unchanged from current behavior) followed by the push branch status on a new line. The output uses the same familiar format for both comparisons, only showing the push comparison when relevant (when it differs from upstream).

The implementation handles all edge cases through comprehensive test coverage (168 new test lines) including:
- Diverged upstream but ahead of push branch
- Different remotes for upstream vs push
- Up-to-date scenarios
- Custom refspecs
- Various ahead/behind states

The patch follows Git conventions by using existing branch tracking mechanisms (`branch.<name>.pushRemote`) rather than introducing new config. It builds on Phillip Wood's thorough review feedback to ensure consistent messaging and proper handling of all edge cases. This appears ready for final review and potential inclusion, completing the feature enhancement that began with Harald Nordgren's initial proposal.
