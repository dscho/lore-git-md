Performance optimization and modernization of Git's byte-swapping functions in `compat/bswap.h` (initial patch from Rostislav Krasny). The series replaces manual bit-twiddling implementations with `memcpy`-based type punning for better performance and maintainability while avoiding undefined behavior. Key technical scope: complete network byte order API including new 16-bit variants (`bswap16`, `ntohs`, `htons`, `put_be16`), renamed functions for consistency (`default_swab32` -> `default_bswap32`), and optimized implementations of `get_be32/64`/`put_be32/64` using compiler intrinsics (GCC/Clang `__builtin_bswap*`, MSVC `_byteswap_*`) with portable fallbacks.

Jeff King (Peff) has conducted a detailed analysis of the benchmark results, focusing particularly on the Clang performance improvements. His key observations: (1) -O0 results are not meaningful for real use, (2) -O3 speedups appear to be loop optimization artifacts, (3) Clang -O2 shows 1.8x speedup but may be test-case specific, (4) aligned 8-byte reads show no performance difference. Peff concludes that while the patch improves readability/maintainability, the performance benefits may not materialize in real-world usage. He remains open to the changes but suggests refining the justification.

Current status: initial submission with thorough benchmarking on x86-64 (GCC 15.2.1, Clang 21.1.7) awaiting more comprehensive review. Open questions/needs: verification of portability across additional architectures (ARM, PPC, RISC-V) and compilers, review of type-punning safety in edge cases, and potential refinement of the performance-focused rationale based on Peff's detailed analysis. The implementation appears carefully crafted but touches critical data integrity paths requiring careful scrutiny from multiple reviewers. Peff's analysis provides concrete methodology for evaluating the real-world impact of these low-level changes.
