This is a bugfix patch addressing an interactive patch selection UI issue in `git add -p` and related commands, part of a Google Summer of Code project. The patch improves usability by showing users their previous hunk selection decisions (use/skip) when navigating between hunks, a feature originally requested by Junio C Hamano.

The v2 iteration makes several improvements over v1: more descriptive subject line, support across all front-ends, clearer wording ("previous decision: use/skip"), and moving the indicator position before prompt choices. The changes modify prompt strings in all patch mode structs and update display logic in `patch_update_file()`, affecting all interactive patch operations (stage, stash, reset, checkout).

Junio has identified a compatibility issue with test t3701 (interactive patch functionality tests), which the author acknowledges and plans to address in a v3. The patch touches `add-patch.c` with 47 insertions and 37 deletions, showing the author is making focused but non-trivial changes to the interactive patch machinery. This appears to be a well-motivated usability improvement that maintains consistency across modes while adding valuable context for users during interactive patch selection.
