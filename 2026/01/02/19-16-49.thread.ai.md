Reftable backend bugfix addressing undefined behavior in indexed table reference iterator. Thread concerns `indexed_table_ref_iter_next()` in `reftable/iter.c` which could access union members without checking reference type (REFTABLE_REF_VAL1/REFTABLE_REF_VAL2), risking memory corruption on malformed input. Patch properly validates `value_type` before accessing `val1` or `val2` union members, matching established patterns elsewhere in code. Fix targets a known issue marked with "BUG" comment in original implementation. No user-visible changes except improved robustness against invalid input. Part of ongoing reftable work led by Patrick Steinhardt and Karthik Nayak. Touches only iterator implementation internals with no API or format changes.
