This is a performance investigation thread about `git pack-refs --all` slowness in large repositories with millions of refs. Jeff King responds to Martin Fick's challenge that object verification alone doesn't fully explain the performance gap between Git and JGit (20s vs 5+ minutes on the same Gerrit server environment).

Jeff confirms that both Git and JGit perform similar object verification (including tag peeling) with comparable I/O patterns, as verified by strace traces. He notes that writes to the packed-refs file should be fully buffered in 4K chunks, making it unlikely that small unbuffered writes are the bottleneck. The discussion is shifting focus from read-path verification to potential write-path inefficiencies, though Jeff observes that write time should scale with total ref count rather than just changed refs if that were the primary issue.

The thread continues to explore why Git's implementation performs so much worse than JGit's in this specific high-refcount scenario, with the reftable backend remaining a potential long-term solution but immediate optimizations for the files backend still under investigation. Jeff's analysis suggests the performance gap may not be as straightforward as initially hypothesized.
