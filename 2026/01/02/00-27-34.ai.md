This is a performance optimization patch targeting Git's byte-swapping functions in `compat/bswap.h`. The author, Rostislav Krasny, proposes simplifying the implementation by using `memcpy` to avoid undefined behavior from pointer type punning, while also making the code more readable and potentially faster.

The key observation is that Git currently uses two different approaches for byte swapping: the `htonl` macro (which compiles to efficient built-ins on GCC/Clang) and the more complex `get_be32()` function. The patch replaces the manual bit-twiddling in these functions with `memcpy`-based implementations that the compiler can optimize similarly to the `htonl` case.

Performance measurements show significant improvements at lower optimization levels (-O0 and -O1), with the new implementation being 4x faster than the original in -O0 builds. At higher optimization levels (-O2/-O3), the performance is comparable or slightly better, particularly with Clang where the new code shows a ~45% speedup in the -O2 case.

The patch touches a sensitive area - byte order operations are fundamental to Git's object handling - but the approach appears sound. Using `memcpy` for type punning is a well-established technique to avoid undefined behavior while maintaining performance. The benchmark results suggest this could be particularly beneficial for debug builds and platforms where compiler optimizations are less aggressive.

This appears to be a well-motivated change with clear performance data backing it up. The implementation follows modern C practices for safe type punning and maintains compatibility with existing callers. Reviewers will likely want to verify the portability claims across different compilers and architectures, but the approach seems promising.
