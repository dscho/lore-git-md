Refactoring patch in the xdiff subsystem, part of a series preparing for Rust interoperability and optimizations. This is patch 4/10 from Ezekiel Newren's series targeting the diff algorithm internals.

The patch simplifies the patience and histogram diff algorithms by removing redundant context optimization code. It makes them benefit from the existing `xdl_trim_ends()` function that was previously only used by the classic diff algorithm. The change:
- Deletes the now-unused `xdl_optimize_ctxs()` function that previously handled this optimization
- Updates the patience diff to use the trimmed ranges from `xdf1` and `xdf2` directly
- Moves the `xdl_trim_ends()` call earlier in the preparation flow so all diff algorithms can use it

This appears to be a straightforward cleanup that removes duplicate code while maintaining the same behavior. The patch is small (13 lines removed, 5 added) and focused, typical of the incremental refactoring approach seen in this series. As with previous patches, it maintains compatibility with both C and existing callers while preparing the codebase for potential future Rust components.
