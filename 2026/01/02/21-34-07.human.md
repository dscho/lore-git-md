This is the final version (v12) of a feature enhancement for `git status` that shows divergence from both the upstream and push tracking branches. The patch series has evolved through extensive review and now cleanly integrates with Git's existing branch tracking mechanisms.

The implementation now uses `branch.<name>.pushRemote` when available, falling back to the tracking branch if unset. It shows the push branch comparison only when it differs from the upstream branch, maintaining the familiar status output format but adding the additional context when relevant. For example, when working on a feature branch tracking `main` but pushing to a different branch, `git status` will show both relationships.

The series has been thoroughly reviewed, with Phillip Wood providing detailed feedback that led to final refinements in message wording, test case standardization, and handling of edge cases. The test suite has been expanded to 167 lines covering all scenarios. Junio Hamano has approved the technical direction, and the remaining discussion focuses on commit organization philosophy (mailing-list style progression vs GitHub-style squashing).

This represents the culmination of a long thread that began with a custom configuration approach but now cleanly leverages Git's existing infrastructure. The patch is well-tested and addresses all major feedback, making it likely to be merged soon.
