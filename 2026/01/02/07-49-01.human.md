This is a performance investigation thread about `git pack-refs --all` slowness in large repositories with millions of refs. Jeff King (Peff) responds to Martin Fick's latest analysis, which challenges the initial assumption that tag-peeling verification was the primary bottleneck.

Peff confirms that both Git and JGit perform similar object access patterns (opening each loose object once) when packing refs, despite JGit being significantly faster in Martin's Gerrit server environment. He suggests the performance difference likely isn't due to small unbuffered writes, as the packed-refs writes use fully buffered `fprintf()` calls with 4K chunks.

The discussion has shifted from focusing on read-path inefficiencies (object verification) to examining potential write-path issues, though Peff notes the write time should scale with total ref count rather than just changed refs if that were the bottleneck. The thread continues to investigate why Git's implementation performs so much worse than JGit's under similar conditions, with the reftable backend remaining a potential long-term solution but immediate optimizations still unclear.
