Performance optimization and modernization of Git's byte-swapping functions in `compat/bswap.h`. This patch replaces manual bit-twiddling implementations with `memcpy`-based type punning for better performance and maintainability while avoiding undefined behavior. The changes affect fundamental object handling code but use well-established safe techniques.

The patch introduces several improvements: adding missing 16-bit network byte order conversions (`bswap16`, `ntohs`, `htons`), renaming functions for consistency (`default_swab32` -> `default_bswap32`), and completing the API with `put_be16()`. Benchmark results show significant speedups - up to 4x faster at -O0 and 45% improvement with Clang at -O2 on x86-64, with comparable or better performance at higher optimization levels.

The implementation leverages compiler intrinsics where available (GCC/Clang's `__builtin_bswap*`, MSVC's `_byteswap_*`) while providing portable fallbacks. The `get_be*` and `put_be*` functions now use `memcpy` for type-safe byte swapping through the network order conversion macros. This approach is both more readable and potentially faster than the previous manual bit manipulation.

While the patch appears well-crafted with thorough benchmarking, reviewers will likely want to verify portability across additional architectures and compilers beyond the tested (x86-64 with GCC 15.2.1 and Clang 21.1.7). The changes touch low-level code that's critical for Git's data integrity, so careful review of the type-punning approach will be important.
