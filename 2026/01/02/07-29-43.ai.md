This is a performance optimization discussion thread about Git's byte-swapping functions in `compat/bswap.h`. Jeff King (Peff) is responding to Rostislav Krasny's patch that proposed modernizing these functions using `memcpy`-based type punning for better performance and maintainability.

Peff conducts a detailed analysis of the benchmark results, focusing particularly on the Clang performance improvements that Rostislav reported. He reproduces the tests with some modifications to better understand the performance characteristics, including examining generated assembly code. His key observations are:

1. The -O0 results are too slow to be meaningful for real-world use.
2. The -O3 results show dramatic speedups but appear to be artifacts of loop optimizations rather than fundamental improvements to the byte-swapping itself.
3. For Clang at -O2, Peff confirms the patch provides a speedup (about 1.8x) but suspects this may be specific to the test case's overlapping memory access pattern rather than reflecting typical usage.
4. When testing aligned 8-byte reads (more representative of real usage), the performance difference between old and new implementations disappears.

Peff concludes that while he's not opposed to the patch for readability/maintainability reasons, he's skeptical about the claimed performance benefits in real-world scenarios. The discussion remains technical and constructive, with Peff providing detailed analysis methodology that could help refine the patch's justification. This continues the thread's focus on careful performance evaluation of low-level operations that are critical for Git's data integrity.
