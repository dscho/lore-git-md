This is a bug report about a regression in `git subtree` functionality that affects Arch Linux package maintainers' workflows. The reporter, Christian Heusel, has bisected the issue to commit 28a7e27cff ("contrib/subtree: detect rewritten subtree commits") which was introduced in Git 2.53.0-rc1.

The problem occurs when pushing subtree updates to Arch User Repository (AUR) package repositories. After upgrading to 2.53.0-rc1, subtree pushes that previously worked (showing "Everything up-to-date") now fail with a non-fast-forward error, suggesting the remote is somehow out of sync when it shouldn't be. The reporter notes this affects many Arch Linux packagers who rely on this workflow.

The bug appears to be well-documented with clear reproduction steps and bisection results. The impact is significant for a specific but important user community (Arch Linux package maintainers), making this worth prompt attention from subtree maintainers. The regression was introduced by a change meant to improve subtree commit detection, suggesting the new logic may be too strict or incorrectly handling some edge cases in the AUR workflow.
