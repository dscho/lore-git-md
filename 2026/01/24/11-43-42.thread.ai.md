Thread identity: bug report and regression fix discussion for `git subtree push` functionality broken in Git 2.53.0-rc1, originating from Christian Heusel with maintainer response from Junio C Hamano.

Core problem: Commit 28a7e27cff ("contrib/subtree: detect rewritten subtree commits") introduced a regression causing `git subtree push` to incorrectly fail with "non-fast-forward" errors in previously working cases, particularly impacting Arch Linux AUR package repository synchronization workflows where subtree pushes maintain consistency between monorepos and individual package repos.

Current status: Regression confirmed via bisect between 2.53.0-rc0 (working) and 2.53.0-rc1 (broken). Junio has committed to reverting the problematic commit in 2.53.0-rc2 unless a proper solution is developed first, correcting his initial "if" to "unless" in follow-up communication. The issue is being treated as release-critical for 2.53.0.

Key technical details: The rewritten commit detection logic in `contrib/subtree` is too aggressive, rejecting valid no-op pushes that maintain synchronization between repositories. Christian Heusel provided clear reproduction steps demonstrating the failure mode. The regression specifically breaks workflows where subtree pushes are used to propagate identical changes across related repositories.

Open questions: Whether the fix will take the form of a simple revert or a more nuanced correction of the commit detection logic. The technical root cause of the false positives in rewritten commit detection remains to be fully diagnosed.

Participant positions: Christian Heusel reported the regression with bisect evidence and reproduction case. Junio C Hamano confirmed it as a regression requiring prompt resolution before 2.53.0 final, with revert as the fallback option. No other contributors have yet proposed technical solutions.

Related work: Commit 28a7e27cff is the identified regression source. The Arch Linux AUR packaging system serves as the primary affected use case demonstrating real-world impact. This follows previous subtree stability work in the contrib/ area.
