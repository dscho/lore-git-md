This is part 3 of a patch series in the ongoing `the_repository` removal effort, migrating the `branch.autoSetupMerge` configuration from a global variable to repository-specific storage in the new `struct repo_config_values`. The patch comes from an Outreachy intern (Olamide Caleb Bello) mentored by Christian Couder.

The change moves the `git_branch_track` global variable into `the_repository->config_values.branch_track`, updating all callers to use the new location. This affects several commands including `git branch`, `git checkout`, `git push`, and submodule operations. The implementation follows the same pattern as previous patches in the series, with initialization handled via `repo_config_values_init()`.

While the patch itself is straightforward and well-executed, the thread context shows that core architectural questions about config scoping and initialization across multiple repositories remain unresolved. The series has gone through five iterations with only minor refinements, suggesting the technical approach is sound but the broader design questions need resolution before this work can be merged.

This continues the pattern established in earlier parts of the series (which migrated `core.attributesFile` and `core.sparseCheckout`), demonstrating how individual configurations can be moved while highlighting the remaining challenges in the `the_repository` removal effort.
