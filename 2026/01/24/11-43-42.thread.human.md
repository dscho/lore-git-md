Git's `contrib/subtree` command has a regression in version 2.53.0-rc1 that breaks subtree pushes to the Arch Linux AUR repositories, causing "non-fast-forward" errors. Christian Heusel reported the issue, which was bisected to commit 28a7e27cff that introduced rewritten commit detection. This interacts poorly with an earlier optimization (98ba49ccc2) that subtly changed subtree split behavior while violating the command's documented stability guarantees.

Junio C Hamano has committed to reverting the problematic commit in 2.53.0-rc2 as an immediate fix. Colin Stagner confirmed this is the right short-term solution while acknowledging the deeper issue - the optimization's output variations break the subtree command's guarantee of identical outputs for identical inputs. Christian verified that reverting restores the expected behavior where subtree commit hashes match the repository state.

The discussion reveals an ongoing tension between performance optimizations and maintaining stable behavior in the subtree command. While the immediate regression will be fixed, the team still needs to decide whether to make the optimization opt-in or find another way to reconcile speed improvements with behavioral consistency. The Arch Linux AUR's google-chrome subtree remains the key test case for verifying any future solutions.
