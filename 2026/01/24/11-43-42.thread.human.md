Christian Heusel reported a regression in `git subtree push` that broke synchronization workflows, particularly affecting Arch Linux's AUR package repositories. The issue was traced to commit 28a7e27cff, which introduced overly aggressive rewritten commit detection. Junio C Hamano confirmed this as a release-critical regression and plans to revert the commit in 2.53.0-rc2 unless a proper fix emerges.

Colin Stagner has now weighed in, confirming they won't have a solution ready in time for the rc2 deadline. Their analysis reveals deeper issues with the subtree split logic - an optimization meant to exclude unrelated subtrees has been subtly altering output commit IDs despite documentation promising consistent output for identical inputs. Colin suggests this behavior might be unavoidable and proposes making the optimization opt-in via a new flag to preserve backward compatibility that users like Arch Linux rely on.

The immediate path forward remains Junio's planned revert, but Colin's technical analysis shows this is more than a simple regression - it exposes a tension between optimization and stability guarantees in the subtree command. While the revert will restore expected behavior for now, the discussion suggests the long-term solution may need to either drop the optimization or make it as an opt-in feature to maintain the documented guarantees.
