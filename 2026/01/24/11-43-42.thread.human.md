The issue was traced via bisect to commit 28a7e27cff, which modified subtree commit detection logic. 

Maintainer Junio Hamano confirmed this is a legitimate regression and stated the commit will be reverted in 2.53.0-rc2 unless a proper solution is found first. The problem occurs when pushing between synchronized monorepos and package repos, where the new detection logic incorrectly flags valid no-op pushes as non-fast-forward. 

Junio corrected his initial wording in a follow-up, making clear the revert will happen unless ("not if") a fix is developed in time. The prompt response indicates this will be resolved before the final 2.53.0 release, either through reverting the problematic commit or implementing a targeted fix. The regression particularly impacts Arch Linux's AUR packaging system where subtree pushes are used to synchronize repositories.
