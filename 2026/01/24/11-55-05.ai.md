This is part 2 of a 3-part RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) that moves configuration values from global variables to repository-specific storage in `struct repo_config_values`. The series is part of the ongoing `the_repository` removal effort.

This patch specifically migrates the `core.sparseCheckout` config value from the global `core_apply_sparse_checkout` variable to the new `repo_config_values` struct embedded in `struct repository`. The change affects 12 files across multiple commands that interact with sparse checkout functionality.

The implementation maintains current behavior by only accessing the value through `the_repository` while laying groundwork for future multi-repo support. The patch incorporates naming improvements from Phillip Wood's earlier reviews, removing the `_path` suffix (now just `apply_sparse_checkout`) and improving commit message explanations.

A key limitation remains from earlier reviews - config values are currently only properly initialized for `the_repository`, which creates issues when accessed through other repository structs. This architectural challenge persists as the primary blocker for the series, particularly affecting the `apply_sparse_checkout` functionality that touches 12 files.

The changes demonstrate continued progress in the Outreachy mentorship under Christian Couder's guidance, with each iteration refining the approach while the fundamental multi-repo initialization limitation remains across all parts of the series. The structural changes to `struct repository` and new initialization patterns established here will serve as the foundation for subsequent config migrations in the series.
