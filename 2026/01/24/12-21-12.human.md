This is part 2 of a 3-part RFC series by Olamide Caleb Bello (an Outreachy intern) that aims to eliminate global configuration variables as part of the ongoing `the_repository` removal effort. The patch specifically migrates the `core.sparseCheckout` configuration from a global variable to repository-specific storage in the new `struct repo_config_values` embedded in `struct repository`.

The changes touch 12 files across various commands that interact with sparse checkout functionality (`grep`, `mv`, `sparse-checkout`, etc.), updating them to access the config value through `the_repository->config_values` rather than the global `core_apply_sparse_checkout`. The implementation follows the pattern established in part 1 (which handled `core.attributesFile`), though like that patch, it still only properly initializes config values for `the_repository` itself.

While the patch series has gone through 5 iterations with minor refinements, fundamental questions from Junio C Hamano about config scoping across multiple repositories remain unresolved. The work represents incremental progress in the larger `the_repository` removal effort, though the core architectural challenges around multi-repo initialization will need to be addressed before merging.
