This is patch 2/6 in a bugfix series addressing regression in error message reporting for batched reference updates. The patch extends the callback function signature for handling rejected reference updates to include detailed error messages, though the actual message handling will be implemented in later patches.

The change adds a `details` parameter to `ref_transaction_for_each_rejected_update_fn` and updates all callers (in `fetch.c`, `receive-pack.c`, and `update-ref.c`) to accept this new parameter. The parameter is currently marked UNUSED in these callbacks, as the full error message integration comes in subsequent patches. The patch maintains backward compatibility while preparing the infrastructure for detailed error reporting.

This is a straightforward plumbing change that enables the more substantive fixes in later patches. The implementation follows the project's typical pattern for extending callback signatures, and the patch has been reviewed and co-authored by Jeff King, indicating technical soundness. The change is part of a well-structured series that has already gone through multiple iterations (now at v5) with thorough review.
