This is the first patch in a completed bugfix series (v5, 6/6) from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series has already been merged by Junio Hamano in v3 form and is now being finalized with v5 optimizations.

The patch fixes a specific issue in `refs_verify_refnames_available()` where rejected reference updates weren't properly skipping to the next reference in batched operations. The bug caused duplicate rejection messages when a reference conflicted with existing filesystem entries. The fix changes the control flow to use `goto` statements to properly skip to the next reference in the outer loop rather than just continuing the inner loop.

Key technical changes:
- Modifies `ref_transaction_maybe_set_rejected()` to accept error details via a `strbuf`
- Updates all backend implementations (files, packed, reftable) to pass through error details
- Adds `rejection_details` field to `struct ref_update` to store error messages
- Uses `goto next_ref` pattern to properly skip conflicting references
- Maintains backward compatibility with existing error reporting

The patch is part of a larger effort to restore detailed error messages that were lost when batched reference updates were introduced, affecting `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`. The series has undergone multiple rounds of review and optimization, with this final version incorporating Phillip Wood's `ALLOC_GROW()` suggestion and Junio's stylistic preferences around pointer usage.
