This is the final patch (6/6) in a bugfix series from Karthik Nayak and Jeff King that restores detailed error messages for batched reference updates in `git fetch`. The series addresses a regression where specific error details were lost when reference updates were batched together.

The patch introduces a `ref_update_display_info` structure to collate update outcomes and delays displaying them until after the transaction commits. This allows proper error reporting while maintaining the performance benefits of batched updates. Benchmarking shows only a 1% overhead for repositories with 1000 refs.

Key changes include:
- New data structures to track update status and failure details
- Modified display logic in `do_fetch()` to show updates after transaction completion
- Restored specific error messages for various failure cases (file conflicts, invalid objects, etc.)
- The implementation builds on Phillip Wood's suggested optimizations and addresses Junio Hamano's stylistic preferences from earlier review feedback.

The patch completes the series by fixing the fetch-specific output, following earlier patches that addressed similar issues in `git update-ref` and `git receive-pack`. With this change, users once again see detailed error messages when reference updates fail during fetch operations.
