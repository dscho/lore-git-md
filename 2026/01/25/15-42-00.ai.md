This is a discussion thread about a feature proposal for handling intentionally missing objects in Git repositories, with specific use cases from Debian's packaging workflow. Philip Oakley responds to Simon Richter's initial proposal by referencing prior discussions about object redaction from Git Merge 2020, noting that no clear solution emerged from those talks.

The email explores technical challenges around maintaining repository integrity while allowing certain objects to be omitted or replaced with "counterfeit" versions that preserve the commit graph structure. Oakley suggests potential approaches for handling blob and tree objects, including creating specially-formatted replacement objects that could be verified against authenticated parts of the graph. However, he acknowledges these are still speculative ideas without concrete implementation.

The discussion touches on several key technical constraints: Git's hash-based integrity model, the distinction between metadata and content, and the difficulty of creating exceptions to Git's object model without breaking fundamental properties. Oakley positions this as an early-stage exploration rather than a ready solution, emphasizing the need to find a minimal viable feature that could work within Git's design principles while addressing Debian's use case of excluding non-redistributable files from packaged repositories.
