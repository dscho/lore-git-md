This is the third patch in a completed bugfix series (v5, 6/6) from Karthik Nayak and Jeff King that restores detailed error messages for batched reference updates. The series addresses a regression where `git update-ref --batch-updates`, `git fetch`, and `git receive-pack` lost their detailed error reporting, only returning generic error codes.

This specific patch focuses on `git update-ref`, modifying its error reporting to:
1. Output detailed error messages to stderr while maintaining the machine-parsable format on stdout
2. Improve test coverage by verifying both the machine output and detailed error messages for various failure cases (nonexistent objects, invalid ref types, ref conflicts, etc.)

The changes are straightforward - the patch modifies `print_rejected_refs()` to output details when available and updates 15 test cases to check both stdout and stderr output. The implementation builds on infrastructure added in earlier patches that propagates error details through the ref transaction callback chain.

This is part of the larger ref backend unification effort and maintains compatibility with existing scripts while restoring the more helpful error messages that were lost in the batched updates implementation. The series has already been merged by Junio after several iterations incorporating feedback from reviewers.
