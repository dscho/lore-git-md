Bugfix patch (4/6) in a completed series restoring detailed error messages for batched reference updates in `git fetch`. This patch specifically modifies the fetch machinery to use the new error reporting infrastructure introduced earlier in the series.

The key changes are in `ref_transaction_rejection_handler()` where it now checks for and uses detailed error messages when available, falling back to generic messages only when no details are provided. The patch updates four test cases in t5510 to expect the more specific error messages that were present before the batched updates regression.

This builds on the infrastructure from patch 2/6 which added the callback signature with `details` parameter, and aligns with the approach taken for `update-ref` in patch 3/6. The test updates verify that fetch now properly reports:
- File locking conflicts with specific OS-level messages
- Case-insensitive filesystem conflicts with clear path descriptions
- Directory/file conflicts with exact blocking paths

The implementation maintains backward compatibility while restoring the more helpful error messages that existed prior to the batched updates change. This is part of a coordinated fix across multiple commands (fetch, update-ref, receive-pack) to ensure consistent error reporting behavior.
