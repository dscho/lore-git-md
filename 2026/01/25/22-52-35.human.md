This is the cover letter for v5 of a bugfix series from Karthik Nayak and Jeff King, addressing a regression in error message reporting for batched reference updates. The series has already been merged in v3 form by Junio Hamano, with v4 and now v5 adding optimizations and style adjustments.

The core issue fixed is that batched reference updates (used by `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`) had lost detailed error messages that were previously available, only returning generic error codes. This made debugging reference operation failures more difficult. The series restores detailed error reporting while maintaining backward compatibility with existing output formats.

Key improvements in v5:
- Drops `const *` usage in the `ref_update_display_info` structure to better match project conventions around pointer ownership
- Builds on Phillip Wood's `ALLOC_GROW()` optimization from v4
- Maintains the v4 improvements that delay all fetch status information to the end while preserving order

The series shows careful attention to both functionality and code style, with thorough test coverage and benchmarking showing minimal overhead (1% for 1000 refs). The changes touch multiple commands and ref backends while maintaining compatibility with existing behavior. This looks like a well-executed fix for an important regression.
