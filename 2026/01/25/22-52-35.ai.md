This is the fifth iteration of a bugfix series from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series has already been merged in v3 form by Junio Hamano, with v5 now completing the solution with some final optimizations and style adjustments.

The core issue is that batched reference updates (used by `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`) had stopped providing detailed error messages when operations failed, only returning generic error codes. This made debugging harder. The series restores the detailed error reporting while maintaining backward compatibility with existing output formats.

Key changes in v5:
- Drops the use of `const *` for fields in the `ref_update_display_info` structure to better indicate memory ownership, aligning with project's common practice
- Builds on Phillip Wood's `ALLOC_GROW()` optimization from v4
- Maintains the v4 improvements that delay all fetch status information to the end while preserving order
- The series now fully restores detailed error messages in:
  - `update-ref` (to stderr while keeping machine-parsable stdout)
  - `fetch` (with new display logic showing updates after transaction)
  - `receive-pack` (via `rp_error()` while maintaining current output)

The implementation introduces a `ref_update_display_info` structure to collate update outcomes and delays display until after transaction commits. Benchmarks show only 1% overhead for 1000 refs. The solution maintains backward compatibility while fixing the regression reported by Elijah Newren.

This appears to be the final polished version of the series, with all technical issues resolved and only minor style adjustments remaining (switching to non-const pointers to match project conventions). The changes are well-tested across t1400, t5510 and t5516.
