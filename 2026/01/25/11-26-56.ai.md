This is a documentation discussion thread about terminology in Git's error messages, specifically around the `git last-modified` command.

The thread continues a discussion about whether "revision" is the most accurate term to use in error messages when referring to Git objects. Patrick Steinhardt notes that while gitglossary(7) defines "revision" as a synonym for "commit", he finds this surprising since revisions can resolve to any object type (like trees via `HEAD^{tree}`) and are really about naming syntax rather than object types. Kristoffer Haugsbakk responds that they've always understood "revision" as a generic term similar to "commit", not specifically tied to the gitrevisions(7) syntax.

This discussion emerged from earlier patches that improved error messages in `git last-modified`, where the terminology was refined from "revision" to be more precise about object types. While the technical patches have already been merged, this follow-up discussion may influence future documentation updates, particularly around gitglossary(7) and gitrevisions(7).
