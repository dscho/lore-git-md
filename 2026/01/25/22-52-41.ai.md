This is the final patch (6/6) in a bugfix series from Karthik Nayak and Jeff King that restores detailed error messages for batched reference updates in `git fetch`. The series addresses a regression where batched updates lost specific error reporting, making failures harder to diagnose.

The patch introduces a `ref_update_display_info` structure to collate update outcomes and delays status display until after the transaction commits. This allows proper error reporting while maintaining the performance benefits of batched updates. Benchmarking shows only 1% overhead for 1000 refs. The implementation uses a dynamic array and strmap to track updates, with Phillip Wood's `ALLOC_GROW()` optimization incorporated.

Key technical changes include:
- New `struct ref_update_display_info` to hold per-update status
- Modified `update_local_ref()` to append to display list rather than print immediately
- Final output phase showing all updates with status in deterministic order
- Integration with existing rejection handling via `strmap rejected_refs`
- Expanded test coverage in t5516 to verify error message restoration

The patch completes the series by fixing the specific regression where `git fetch` would lose detailed error messages when pushing non-commit objects to refs/heads. It maintains backward compatibility while restoring the pre-batched-update behavior where error messages appeared in context with the reference update status.

This is a well-structured patch that builds on the infrastructure changes from earlier in the series. It has thorough test coverage and includes performance measurements showing minimal overhead.
