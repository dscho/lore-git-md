This is a discussion about extending Git to support repositories with intentionally missing objects, particularly for Debian's use case where they want to exclude non-redistributable files while maintaining repository integrity. Philip Oakley responds to Simon Richter's initial proposal by referencing past discussions about object redaction from Git Merge 2020, noting that no clear solution emerged.

Oakley explores technical challenges around maintaining graph integrity when objects are omitted, suggesting a mechanism for marking leaf objects as 'removed' while preserving commit parent information. He proposes the concept of 'counterfeit' objects that could stand in for redacted content while maintaining verifiability through facsimile objects with proper hashes. The email highlights the tension between Git's object model and practical needs for partial repository distribution.

The discussion remains conceptual, with Oakley acknowledging this is a "big ask" that would require careful design to avoid violating Git's fundamental principles. He suggests starting with a minimal viable feature (perhaps around blob objects) as a proof of concept. The thread represents an early-stage exploration of whether and how Git might accommodate such use cases while maintaining its integrity guarantees.
