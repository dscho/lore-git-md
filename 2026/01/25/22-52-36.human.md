This is the first patch in a completed bugfix series (v5, 6/6) from Karthik Nayak and Jeff King that addresses a regression in error message handling for batched reference updates. The series has already been merged by Junio Hamano.

The patch fixes a specific issue in `refs_verify_refnames_available()` where rejected reference updates weren't properly skipping to the next reference in batched operations. Previously, a `continue` statement would only skip the inner loop, causing the same reference to be repeatedly rejected. The fix uses a `goto` to properly skip to the next reference in the outer loop.

Key technical changes:
- Modifies the error handling flow to properly advance past rejected refs
- Updates `ref_transaction_maybe_set_rejected()` to accept error details
- Adds `rejection_details` field to `struct ref_update`
- Makes corresponding changes across all ref backends (files, packed, reftable)

This is a well-contained fix that's part of a larger effort to restore detailed error reporting that was lost when batched reference updates were introduced. The patch shows careful attention to maintaining consistency across different ref backends.
