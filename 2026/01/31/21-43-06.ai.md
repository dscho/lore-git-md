This is the second patch in a 5-part series adding new traversal options to `git submodule foreach`. The patch implements the `--reverse-traversal` flag, enabling post-order processing where nested submodules are visited before their parents.

The core change extends `for_each_listed_submodule()` to accept a `reverse` parameter and modifies the recursion logic in `runcommand_in_submodule_cb()` to handle both pre-order (current) and post-order (new) traversal. When `--reverse-traversal` is specified with `--recursive`, nested submodules are processed first, which is useful for dependency-aware operations like builds or cleanups.

The implementation touches several key areas:
- Adds a `reverse_traversal` field to `struct foreach_cb`
- Modifies the submodule iteration order in `for_each_listed_submodule()`
- Splits the recursive logic to handle both traversal orders
- Updates the command-line parsing in both C and shell layers

The patch also enables two previously failing tests in `t7425-submodule-reversion.sh` that verify the flag parsing and execution. The test suite uses a 10-repository hierarchy to validate the post-order behavior.
