This is a bugfix targeting Git's pathspec handling, specifically addressing how excluded pathspecs interact with `.gitignore` rules. The patch comes from Remy D. Farley and fixes an inconsistency where `git add :!x .` would incorrectly fail when file `x' is both present and listed in `.gitignore`.

The core issue is that Git was applying `.gitignore` checks even for explicitly excluded pathspecs (those with `:!` prefix), which contradicts the intuitive expectation that excluded pathspecs should bypass ignore rules entirely. The fix modifies `dir.c` to skip the pathspec matching check when the pathspec contains exclude magic (`PATHSPEC_EXCLUDE`).

The commit includes a thorough reproduction script demonstrating the problem, showing how both `git add` and `git stash` operations are affected when trying to exclude ignored files. The patch is small (just a one-line change) but appears well-motivated and correctly targeted - it preserves the existing behavior for non-excluded pathspecs while fixing the specific edge case where exclusion and ignore rules overlap.
