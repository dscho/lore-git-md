Feature proposal for a `@{primary}` branch shorthand, now in its fourth iteration. This patch introduces a new syntax to reference a repository's primary branch (typically "main" or "master") through the upstream tracking infrastructure, resolving to what `origin/HEAD` points to rather than using `init.defaultBranch` as originally proposed. The implementation reuses existing branch tracking machinery with new parsing logic in object-name.c and supporting tests.

Key technical changes from v3 include refactoring the upstream resolution logic into a shared `branch_get_upstream_options()` function that handles both traditional upstream lookups and the new primary branch case. The documentation describes this as resolving to "the primary branch via upstream tracking" with examples of usage in checkout and rev-parse contexts.

The thread has evolved from discussing implementation details to fundamental design questions about the feature's purpose and naming. Junio Hamano has raised concerns about the terminology shift from "default" to "primary" and whether the remote-tracking approach sufficiently captures the concept across all workflows. Testing continues to validate the technical soundness while higher-level semantics remain unresolved. The patch appears technically solid but the conceptual alignment with user expectations and existing mechanisms like `git var GIT_DEFAULT_BRANCH` remains an open discussion point.
