Feature patch adding `--append-superproject` flag to `git submodule foreach`. This is patch 3/5 in a series enhancing submodule traversal options, building on the `--reverse-traversal` flag introduced in patch 2/5.

The new flag makes `git submodule foreach` execute the given command in the superproject after processing all submodules, but only at the top-level invocation (not during recursion). This enables full post-order traversal from deepest submodules up to the superproject when combined with `--recursive` and `--reverse-traversal`. The superproject execution sets the same environment variables as submodule executions (name, sm_path, displaypath, sha1, toplevel) for consistency, with displaypath formatted as `../<name>` to visually indicate the parent relationship.

Implementation adds an `append_superproject` field to `struct foreach_cb`, parses the new flag in both `module_foreach()` and `git-submodule.sh`, and includes a new execution block after submodule traversal. The patch converts several previously failing tests in `t7425-submodule-reversion.sh` to success states, covering parsing, execution order, variable setting, and edge cases like empty repositories. The changes are focused and well-contained, touching only the expected files (`builtin/submodule--helper.c`, `git-submodule.sh`, and the test file).

This continues the series' pattern of clean, incremental additions to submodule traversal capabilities, with clear motivation for dependency-ordered workflows like builds and cleanup operations. The implementation appears straightforward and maintains backward compatibility while adding the requested functionality.
