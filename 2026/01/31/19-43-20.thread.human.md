Here's a human-readable summary of the thread so far:

Remy D. Farley has identified and fixed a subtle bug in Git's pathspec handling where excluded pathspecs (those starting with `:!`) were incorrectly still being checked against `.gitignore` rules. The issue manifests when trying to explicitly exclude a file that's also listed in `.gitignore` - commands like `git add :!x .` would fail even though the user clearly intended to bypass ignore rules for that specific exclusion.

The fix is a focused one-line change in `dir.c` that makes Git skip the pathspec matching check when the pathspec contains exclude magic (`PATHSPEC_EXCLUDE`). Remy included a comprehensive test script demonstrating the problem, showing how both `git add` and `git stash` operations were affected. The patch maintains all existing behavior for non-excluded pathspecs while fixing this specific edge case where exclusion and ignore rules overlap. This appears to be a clean, well-motivated fix for an inconsistency that went unnoticed until now.
