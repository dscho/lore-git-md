This thread tracks a refactoring effort to eliminate global variables in Git's working tree status machinery (`wt-status.c`), specifically targeting `the_repository` and `the_hash_algo` dependencies. Shreyansh Paliwal has led the work through three versions, with substantive review input from Karthik Nayak, Junio Hamano, Phillip Wood, and Kristoffer Haugsbakk.

The latest patch (part 2 of v3) makes significant progress by restructuring how repository context flows through the rebase and bisect status checking functions. Instead of deriving the repository from worktree structures - which risked NULL dereferences - the code now passes repository pointers directly through function parameters. This architectural shift resolves earlier test failures while maintaining all existing behavior. The changes span multiple files and subsystems, including stash handling and porcelain output formatting.

Only two minor global dependencies remain (`comment_line_str` and `DEFAULT_ABBREV`), which the author has explicitly marked for future work. The discussion has been productive, with reviewers validating the technical approach while emphasizing testing rigor. Phillip Wood in particular has stressed the importance of thorough testing for such refactors, while Kristoffer Haugsbakk contributed workflow suggestions about using range-diffs between versions.

The patch series serves as a reference implementation for similar global-variable elimination work elsewhere in the codebase. With the NULL safety issues now addressed and tests passing, this appears ready for merging once any final review feedback is incorporated. The remaining loose ends are well-scoped for follow-up patches.
