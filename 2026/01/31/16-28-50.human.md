Bugfix for `--shallow-since` edge case in shallow clone functionality. This third version of Samo Pogačnik's patch addresses an issue where some boundary commits could become unreachable after a shallow clone based on a date.

The problem occurs when using `--shallow-since` with repositories containing merge commits. The original implementation could incorrectly mark some boundary commits as shallow when they had parents that were also boundary candidates, leading to unreachable commits in the cloned repository. The patch modifies the boundary detection logic in `shallow.c` to ensure all boundary commits remain reachable by:

1. Only marking a commit as shallow if none of its parents are in the candidate list
2. When a commit has both listed and unlisted parents, marking only the unlisted parents as boundaries
3. Adding comprehensive test coverage with the new 'clone shallow-since all shallows reachable' test case

Version 3 primarily improves documentation and terminology (changing "border" to "boundary" consistently) based on Junio C Hamano's feedback from previous versions. The core technical approach remains unchanged from v2, which had already addressed initial review concerns. The patch appears technically sound and ready for integration pending final confirmation from shallow code experts.
