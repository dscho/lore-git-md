This is a feature patch series introducing new traversal options for `git submodule foreach`. The cover letter introduces three new flags that enable post-order (dependency-ordered) submodule traversal, allowing nested submodules to be processed before their parents and optionally including the superproject in operations.

The series comes from William Hatfield and appears well-structured, with each commit focusing on a specific aspect of the new functionality. The changes span documentation updates, core implementation in both C and shell code, and a comprehensive new test file (t7425) that validates the behavior. The motivation is clearly stated - to support dependency-sensitive workflows like cleanup, builds, and deployments where processing submodules in reverse order is necessary.

The implementation touches both the C helper (`builtin/submodule--helper.c`) and the shell wrapper (`git-submodule.sh`), suggesting this is a user-facing change rather than just an internal refactoring. The documentation updates indicate these will be properly exposed to end users. The test coverage looks thorough with over 300 lines of new test cases.
