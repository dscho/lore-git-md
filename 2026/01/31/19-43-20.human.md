This is a bugfix patch addressing an inconsistency in how `git add` handles excluded pathspecs when files are present in `.gitignore`. The issue occurs when using the `:!x` exclude syntax - the command incorrectly fails when the excluded file exists and is ignored, even though the user explicitly asked to exclude it.

The patch modifies `dir.c` to make excluded pathspecs bypass the gitignore check entirely, which matches the intuitive expectation that an explicit exclusion should override ignore rules. The change is small (just one line) but fixes a real behavioral inconsistency that could affect users trying to script operations like `git stash` with excluded paths.

The author provides a thorough reproduction script demonstrating the issue and notes they've already worked around it by using `core.excludesFile` instead, but correctly identifies this as a bug worth fixing for consistency with the documented behavior of pathspecs. The fix is straightforward and unlikely to be controversial.
