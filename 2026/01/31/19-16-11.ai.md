This is a discussion about the proposed `@{default}` shorthand for referencing a repository's primary branch, now in its fourth iteration. Junio Hamano raises several key concerns about the current implementation's design and naming.

Junio questions the semantic alignment between the shorthand's name (`@{default}`) and its actual behavior (resolving to the remote-tracking branch pointed by `refs/remotes/origin/HEAD`). He argues this creates confusion with `init.defaultBranch` and `git var GIT_DEFAULT_BRANCH`, which represent different concepts. The maintainer suggests the remote-tracking approach might be more accurately named something like `@{dumbo}` to avoid implying it relates to local configuration.

The email outlines a detailed workflow scenario where tracking a project's primary branch (via `origin/HEAD`) would be useful for comparing topic branch progress against the main integration line. However, Junio notes this doesn't naturally translate to needing a local branch name derived from stripping the remote prefix, making the current implementation's utility questionable.

Junio also revisits the original motivation for using `init.defaultBranch`, suggesting `repo_default_branch_name()` might have been a better foundation for an `@{default}` shorthand since it handles unconfigured repositories gracefully. The discussion has shifted from implementation details to fundamental questions about the feature's purpose and naming, with Junio's persistent concerns indicating the conceptual foundation may need reworking before proceeding.
