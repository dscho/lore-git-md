This is the fourth iteration of a patch series introducing a new shorthand `@{primary}` to reference a repository's primary branch via upstream tracking (typically `origin/HEAD`). The author, Harald Nordgren, has pivoted from an initial approach based on `init.defaultBranch` to the current remote-tracking implementation after finding the original approach impractical for scaling across multiple repositories.

The key change in this version is a pragmatic shift to rely on remote-tracking branches rather than local configuration, which the author found more convenient for their workflow. The implementation appears technically sound with expanding test coverage, but fundamental questions remain about the feature's conceptual boundaries and relationship to existing branch-naming mechanisms like `git var GIT_DEFAULT_BRANCH`.

Maintainer Junio Hamano continues to question whether the remote-HEAD resolution adequately represents "primary" across all repository types and whether the terminology shift from "default" introduces unnecessary conceptual divergence. The thread has evolved from implementation refinement to re-examining the feature's core purpose and naming, with the convenience value of the shorthand weighed against potential confusion with established terminology.
