This is the fourth iteration of Harald Nordgren's patch introducing a `@{primary}` shorthand for referencing a repository's primary branch via upstream tracking (typically `origin/HEAD`). The implementation reuses existing branch tracking infrastructure with new parsing logic in object-name.c.

The key change in v4 is a conceptual pivot - rather than relying on local `init.defaultBranch` configuration (which would need to be set per-repository), the patch now resolves the primary branch through remote-tracking (origin/HEAD). This addresses the author's original use case of convenient branch switching across multiple repositories without requiring per-repo configuration.

While the technical implementation appears sound with expanding test coverage, fundamental questions remain about the feature's conceptual boundaries. Junio Hamano continues to question whether remote-HEAD resolution adequately represents "primary" across all repository types and whether the terminology shift from "default branch" introduces unnecessary divergence from existing mechanisms like `git var GIT_DEFAULT_BRANCH`.

The author demonstrates the practical utility of the feature through a script that successfully checks out the primary branch across multiple repositories on their system. However, the thread has shifted from implementation refinement to re-examining first principles - particularly the relationship between this shorthand and Git's existing branch-naming mechanisms, and whether the remote-tracking approach best serves the originally stated use case.
