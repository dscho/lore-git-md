This is the fourth patch in a five-part series adding new traversal options to `git submodule foreach`. The patch introduces a `--reversive` shorthand flag that combines three behaviors: recursive traversal, reverse (post-order) processing, and including the superproject after submodules. This is a convenience for workflows that need full dependency-ordered execution from deepest submodule up through the superproject.

The implementation adds the new flag to both the C helper (`builtin/submodule--helper.c`) and shell wrapper (`git-submodule.sh`), setting all three underlying flags when `--reversive` is used. The test file (`t7425-submodule-reversion.sh`) is updated to verify the new flag works as expected, converting three previously failing tests to success states.

The patch appears mechanically sound, with consistent changes across both implementations and thorough test coverage. The commit message clearly explains the motivation for the shorthand - it simplifies commands for build systems and cleanup scripts that need to process dependencies before dependents. This follows naturally from the earlier patches in the series that implemented the individual components.
