This is a refactoring patch series from an Outreachy intern, proposing a new approach to handling global configuration variables. The series aims to move several config values (core.attributesFile, core.sparseCheckout, branch.autoSetupMerge) out of global scope and into a new `struct config_values` that would be part of the repository struct.

The motivation comes from ongoing work to reduce global variables, where previous attempts ran into issues around when to call `prepare_repo_settings()` and behavior changes from lazy loading. Phillip Wood suggested this alternative approach of creating a dedicated config struct to store these values per-repository while maintaining the existing behavior patterns.

The cover letter clearly explains the context and design considerations, showing the author has done their homework by referencing previous discussions. The approach looks promising for maintaining behavior while making progress on the global variable cleanup effort. As an RFC, the author is specifically seeking feedback on the direction before expanding it to more variables.
