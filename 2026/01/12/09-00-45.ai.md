This is patch 5/7 in Patrick Steinhardt's v5 series refactoring Git's object info handling as part of the ODB abstraction effort. The patch simplifies the return value of `packed_object_info()` from an overloaded object type/enum to a simple success/failure indicator (0/-1).

The key change is that `packed_object_info()` no longer returns the object type (which was previously overloaded to also indicate delta status). Since the preceding patch removed the last caller that needed this return value, the function can now focus purely on success/failure reporting. This enables future optimizations by allowing callers to skip object type parsing when not needed.

The patch updates all error paths to return -1 consistently and adds clarifying comment to the function's documentation in packfile.h. The changes are mechanical but improve interface clarity and maintainability. This continues the series' trend of cleaning up object info handling while preparing for more substantial ODB abstraction work.

The patch has already been reviewed and approved by Karthik Nayak (GitLab ODB team) in previous iterations, with no outstanding technical concerns. It represents another incremental improvement in the larger effort to make Git's object storage layer more flexible and maintainable.
