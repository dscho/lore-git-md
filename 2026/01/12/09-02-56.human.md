This is part of Patrick Steinhardt's ongoing refactoring of Git's ref backend validation, specifically targeting the files backend. Patch 7/17 in the series extends consistency checks to root refs (like HEAD) that were previously skipped.

The patch introduces a new helper function `files_fsck_root_ref()` that validates root refs by:
1. Properly constructing refnames for worktrees
2. Checking the ref's filesystem path exists
3. Delegating to the existing `files_fsck_ref()` for actual validation

Two new test cases verify the behavior catches invalid root refs in both the main repository and worktrees. The changes are mechanical but important - they close a gap where root refs could be corrupted without detection while maintaining the series' trajectory toward unified validation across ref backends.

The patch follows the established pattern of careful, incremental refactoring with thorough test coverage. It builds on previous patches that restructured validation logic and prepares for upcoming shared validation infrastructure. Review feedback from Shejialuo on earlier versions suggests this is progressing smoothly toward the series' goal of consistent ref verification.
