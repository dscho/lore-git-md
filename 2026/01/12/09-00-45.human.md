This is patch 5/7 in Patrick Steinhardt's series refactoring Git's object info handling as part of the ODB abstraction effort. The patch simplifies the return value of `packed_object_info()` to just indicate success (0) or failure (negative error code), rather than also encoding object type information. 

The change is possible because the only caller that relied on the object type return value was removed in the previous patch. This cleanup enables future optimizations by allowing callers to skip reading object types when they aren't needed. The patch updates all error paths to return -1 consistently and adds clarifying comment to the function's header.

The series has received thorough review from Karthik Nayak and addresses all prior feedback, with regression tests added for edge cases. This particular patch is a straightforward cleanup that improves code clarity while maintaining all existing functionality. The changes are well-contained to the packfile subsystem and follow the series' overall goal of making object storage handling more robust and maintainable.
