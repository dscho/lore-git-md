This is a bugfix patch addressing a limitation in submodule fetching behavior. The patch removes a hardcoded assumption that submodule remotes are always named "origin" when fetching missing submodule commits. This was originally identified as a NEEDSWORK item in commit be76c21282 from 7 years ago.

The author, Nasser Grainawi, encountered this issue when working with repositories managed by the 'repo' tool, which uses non-"origin" remote names. The fix introduces a new `submodule--helper get-default-remote` command to properly determine the remote name for each submodule, falling back to "origin" if needed.

The patch includes extensive test coverage in new test files t7425-submodule-get-default-remote.sh and additions to existing submodule test files. The tests verify behavior with custom remote names, nested submodules, and edge cases like submodules with no remotes. The implementation appears thorough and well-tested, addressing a real-world use case that has likely affected others working with non-standard remote configurations.

This change improves the robustness of `git fetch --recurse-submodules` in environments where submodules use different remote names, making Git more flexible in real-world multi-repository workflows.
