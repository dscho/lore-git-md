This is a test modernization patch in an ongoing thread about fixing exit code suppression in test scripts. Patrick Steinhardt weighs in on a technical discussion between Junio C Hamano and GSoC participant Shreyansh Paliwal about how to handle object IDs in test #365 of t5500-fetch-pack.sh.

The thread started with Shreyansh proposing to pre-compute object IDs into files to avoid exit code suppression, but Junio raised concerns about portability (avoiding bashisms) and whether the approach would actually solve the exit code issue. Shreyansh then revised the approach to use explicit error checking.

Patrick now suggests a further simplification - replacing the `echo | packetize` pipeline with a direct call to `packetize` with the formatted string. This eliminates both the bashism concern and the unnecessary pipe, while maintaining the test's core verification of shallow fetch behavior with commit graphs.

The discussion shows active collaboration between a new contributor and experienced maintainers to find an optimal solution that balances test robustness (proper error propagation) with portability (shell compatibility). Patrick's suggestion appears to be moving the solution toward cleaner, more idiomatic test code.
