This is the first patch in Patrick Steinhardt's 17-part series refactoring Git's ref backend validation. It's a bugfix targeting the files backend's root ref iteration logic.

The patch simplifies how Git iterates through root refs (refs at the top level of the ref hierarchy) in the files backend. Currently, it unnecessarily retrieves the root directory name from the loose ref cache (which is always empty) and passes it through `files_ref_path()`. This creates confusion and could segfault since the loose ref cache might not be initialized when called. The fix removes this indirection and directly passes an empty string to `files_ref_path()`.

The change is straightforward and clearly motivated - it removes redundant code while fixing a potential crash. The patch is small (8 lines removed, 3 added) and focused, touching only `refs/files-backend.c`. As the first in a larger series, it sets up cleaner infrastructure for the subsequent validation work. The commit message explains both the technical issue and why the solution makes sense.
