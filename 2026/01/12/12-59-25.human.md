This is part 3 of an RFC patch series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) continuing the effort to eliminate global configuration variables as part of the `the_repository` removal project. The patch moves the `branch.autoSetupMerge` config value from the global `git_branch_track` variable into the new per-repository `struct config_values`.

The change follows the same pattern established in earlier patches for `core.attributesFile` and `core.sparseCheckout`, maintaining the same behavior while making it repository-specific. The patch updates several commands that use this value (`branch`, `checkout`, `push`, and `submodule--helper`) to access it through `the_repository->cfg_values` instead of the global variable.

The implementation includes proper initialization of the default value in `config_values_init_defaults()` and cleanup in `config_values_clear()`. The patch touches 8 files with relatively straightforward mechanical updates, though the changes span core branch-handling commands. This continues the series' approach of demonstrating the pattern for migrating configuration values out of global state while addressing Phillip Wood's earlier concerns about initialization timing.

As an RFC, this appears to be a well-structured continuation of the series, showing how the `struct config_values` approach scales to another important configuration setting.
