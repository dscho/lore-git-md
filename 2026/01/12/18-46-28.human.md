This is part 7 of an 11-patch series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series introduces a new `extensions.submodulePathConfig` mechanism and related tooling.

This particular change moves the `is_rfc3986_unreserved()` helper function from being a static function in `builtin/credential-store.c` to being a public function in `url.[ch]`. The function checks if a character is safe to use in URLs without encoding (alphanumerics plus `-_.~`). 

The change is needed because subsequent patches will use this function when encoding submodule names to avoid path conflicts. The function was originally made static when it was used only by credential-store, but now needs to be shared more widely. The patch maintains the exact same implementation while just changing its visibility and location.

This is a straightforward refactoring that enables the path encoding work in later patches. The change is cleanly isolated and well-explained in the commit message, showing the rationale for moving from a credential-specific location to the more general URL utilities.
