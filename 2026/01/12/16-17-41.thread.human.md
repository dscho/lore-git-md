This thread documents the completion of a bugfix series for the `git last-modified` command, originally authored by Toon Claes and now merged after five iterations. The technical work focused on hardening the command with comprehensive input validation (including a new commit-ish check), fixing memory leaks (now covering pathspec cleanup in all error paths), and refining error messages (removing duplicates and standardizing on "commit" terminology). 

While the implementation is now complete, the discussion uncovered a deeper question about Git's documentation: whether the gitglossary(7) definition of "revision" as a commit synonym accurately reflects how revision syntax can name any object type. Patrick Steinhardt questioned this definition while Kristoffer Haugsbakk defended the current wording, a conceptual debate that continues post-merge. Junio Hamano has now queued the final version, which demonstrates Git's characteristic blend of immediate technical fixes alongside ongoing refinement of core concepts - in this case showing particular attention to error message clarity and thorough resource cleanup.
