Toon Claes submitted a bugfix for the relatively new `git last-modified` command, which was hitting an assertion failure when given tree objects (like HEAD^{tree}) instead of commits. The patch adds proper input validation to reject non-commit objects with a clear error message, while also addressing a memory leak in the pathspec handling code. 

Maintainer Junio Hamano has responded positively to the approach, noting that since `last-modified` needs to work with commit histories, validating the input as commit-ish makes technical sense. While not an explicit ACK yet, Junio's brief reply suggests the fix is conceptually sound and headed in the right direction. The patch includes new tests verifying the improved error handling and appears ready for broader review. This would make the command more robust when users accidentally pass the wrong type of object.
