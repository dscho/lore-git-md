This thread documents the complete hardening of the `git last-modified` command, which has now been merged after multiple iterations. The series began with technical fixes for input validation and memory leaks, then evolved into discussions about Git terminology ("revision" vs "commit" semantics), and concluded with final UX polish.

Toon Claes authored all patches, with Junio C Hamano merging the series and suggesting key error message improvements. The command now robustly validates inputs using `repo_peel_to_type()`, rejecting non-commit objects like trees and blobs with clear error messages (e.g., "revision argument X is a Y, not a commit-ish"). The implementation properly cleans up resources in error paths and includes expanded test coverage for both positive cases (annotated tags) and negative cases (tree OIDs).

A post-merge discussion clarified that "revision" in Git refers to naming syntax that typically resolves to commits, though the term can name any object type. While no immediate documentation changes were required, there was consensus that `gitrevisions(1)` could eventually be updated to better reflect this distinction.
