This is a bugfix in the reftable backend, part of Patrick Steinhardt's larger series refactoring ref backend consistency checks. The patch corrects how the reftable backend handles worktree-specific verification during ref consistency checks.

The issue stems from the reftable backend incorrectly verifying refs across all worktrees when it should only check the specified worktree. This not only violates the expected behavior (which the files backend gets right) but also leads to inefficient repeated checks. The fix uses the newly introduced `backend_for_worktree()` helper to properly scope the verification.

Karthik Nayak, who originally wrote this code, confirms the oversight in his review response, noting he wasn't aware the fsck function was called per worktree. The patch is a straightforward correction that aligns reftable behavior with the files backend while eliminating redundant work. As part of a well-reviewed series with clear incremental improvements, this change looks like a solid step toward unified ref validation across Git's storage backends.
