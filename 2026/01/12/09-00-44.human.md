Performance and refactoring patch in the ODB abstraction effort. This is patch 4/7 in Patrick Steinhardt's series to improve object info handling, which has already received approval from Karthik Nayak and addresses all prior feedback. The series is now ready for integration.

This patch ensures consistent behavior when reading object information from packfiles by always populating the pack-specific fields in the object info structure. Previously, some code paths would leave these fields unset, leading to subtle inconsistencies depending on which function was called. The change moves the field population into `packed_object_info()` where it logically belongs, removing duplicate code block from `packfile_store_read_object_info()`.

The patch is part of a larger effort to abstract Git's object database that has already shown measurable performance improvements (9% speedup in disk size lookups from an earlier patch in the series). This particular patch doesn't introduce new functionality but makes the code more maintainable by eliminating an inconsistency that could lead to bugs. The series as a whole includes regression tests covering edge cases like a segfault in `git archive` that was incidentally fixed by these changes.
