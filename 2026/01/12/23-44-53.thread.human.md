Taylor Blau has sent a two-patch series fixing an issue where Git could fail to detect corrupt multi-pack-index (MIDX) files that need rewriting. The first patch exposed the bug by fixing a test infrastructure issue in t5319 that was masking the problem, while marking the test as an expected failure. This second patch implements the actual fix.

The core problem occurs when using `--stdin-packs` with MIDX writes - the code would compare against an existing MIDX to avoid unnecessary writes, but wasn't properly validating the checksum first. This could cause Git to incorrectly skip updates for corrupt MIDX files. The solution adds checksum validation in `midx_needs_update()` to ensure corrupt MIDXs always trigger a rewrite. The change is minimal but effective, and the previously failing test now passes.

This fix was split from Blau's larger MIDX compaction work to ensure it could land in Git 2.53.0 if the main series gets delayed. The changes focus specifically on the corruption detection case while maintaining the existing optimization behavior for valid MIDX files.
