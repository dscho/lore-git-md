This is part 5 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation. The series aims to centralize consistency checks for both files and reftable backends.

This patch extracts the logic for checking a single reference from the directory iteration loop into a new standalone function `files_fsck_ref()`. The motivation is to make this validation logic reusable - a subsequent patch will introduce another path that needs to verify references. The extraction is clean, with the new function taking the same parameters that were previously used within the loop (refname, path, and mode).

The changes are mechanical but well-justified, continuing the series' pattern of careful refactoring to support the goal of unified validation. The patch maintains all existing behavior while making the code more modular. This is a typical preparatory change in Steinhardt's architectural work - small, focused, and building toward a larger goal.
