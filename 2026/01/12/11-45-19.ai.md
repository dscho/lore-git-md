This is a bugfix in the reftable backend, part of Patrick Steinhardt's ongoing ref backend validation refactoring series. Karthik Nayak (the original author of the problematic code) confirms the issue and thanks Patrick for the fix.

The patch corrects how the reftable backend handles consistency checks across multiple worktrees. Currently, the reftable backend incorrectly verifies refs from all worktrees when it should only check those belonging to the specified worktree. This leads to redundant checks and incorrect behavior, as the implementation also fails to properly populate the worktree stack map.

The fix ensures the backend only verifies the stack of the passed-in worktree by using the newly introduced `backend_for_worktree()` helper. This aligns the reftable behavior with the files backend's correct implementation and eliminates the N^2 checking inefficiency.

This patch builds on the shared validation infrastructure established earlier in the series, demonstrating how the refactoring enables consistent behavior across different storage backends. Karthik's acknowledgment of the oversight suggests the change will be uncontroversial when merged.
