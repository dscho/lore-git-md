This is a bugfix patch addressing a limitation in submodule fetching behavior. The patch removes a hardcoded assumption that submodule remotes are always named "origin", implementing a new submodule helper command `get-default-remote` to properly handle submodules with differently-named remotes.

The change fixes cases where `git fetch --recurse-submodules` would fail when the submodule's default remote wasn't named "origin". The implementation falls back to "origin" if determining the actual default remote fails, maintaining backward compatibility.

The patch includes extensive test coverage in three test files:
- New tests in t5526-fetch-submodules.sh and t5572-pull-submodule.sh demonstrate the fix works with custom remote names
- A new test file t7425-submodule-get-default-remote.sh provides dedicated testing for the new helper command, covering cases like:
  - Initialized vs uninitialized submodules
  - Nested submodules
  - Submodules with multiple remotes
  - Error cases (invalid paths, wrong arguments)

The change is well-motivated by a real-world use case (the "repo" tool using non-"origin" remotes) and addresses a 7-year-old NEEDSWORK comment. The implementation is clean and maintains the existing fallback behavior while adding the more flexible default remote detection.
