This is a bugfix patch in Patrick Steinhardt's ongoing ref backend validation series, specifically addressing an issue in the reftable backend's worktree handling during consistency checks.

The patch fixes a problem where the reftable backend was incorrectly checking all worktree refs regardless of which worktree was specified, while also not properly iterating through the worktree stacks. The fix makes the backend properly verify only the specified worktree's refs by using the `backend_for_worktree()` helper introduced earlier in the series.

The changes in `reftable-backend.c` replace the incorrect strmap iteration with direct worktree-specific backend lookup, properly handling both main and secondary worktrees. The accompanying test in `t0614-reftable-fsck.sh` verifies the fix by creating a worktree, deliberately breaking its reftable stack, and confirming the verification catches the errors only for the intended worktree.

This patch continues the series' pattern of mechanical refactoring while fixing a real behavioral issue. The test coverage is thorough, including both valid and invalid cases for both main and worktree repositories. The changes maintain the architectural direction of the validation work while correcting a specific implementation flaw in the reftable backend.
