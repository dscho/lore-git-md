This patch is part of Patrick Steinhardt's ongoing refactoring of Git's ref backend validation system, specifically targeting the reftable backend. It wires up generic ref validation checks that were introduced in earlier patches to work with reftable storage.

The patch implements two key validations for reftable backend:
1. Direct ref validation through `refs_fsck_ref()`
2. Symref validation through `refs_fsck_symref()`

The implementation carefully avoids using the high-level reftable iterator that might hide broken refs, instead using a low-level iterator to catch all potential issues. The validation handles both SHA-1 and SHA-256 hash algorithms properly and includes proper cleanup of resources.

A new test case verifies that invalid symrefs are correctly detected and reported. The patch maintains the series' pattern of mechanical refactoring while fixing real implementation issues, with comprehensive test coverage. This continues the progression toward unified backend checking that works consistently across both files and reftable storage.
