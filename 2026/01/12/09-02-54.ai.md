Refactoring patch in Patrick Steinhardt's files/reftable validation series. This is patch 5/17 in the second iteration of the series, which aims to centralize ref validation checks across both backend types.

The patch extracts the per-ref validation logic from `files_fsck_refs_dir()` into a new standalone function `files_fsck_ref()`. This prepares for sharing validation between the files and upcoming reftable backends by:

1. Modifying the callback signatures to take path/mode directly rather than a dir_iterator
2. Moving the file type checking and verbose logging into the new function
3. Simplifying the directory iteration loop to just handle path construction before delegating to `files_fsck_ref()`

The changes are mechanical and focused on code organization rather than behavior modification. This continues the series' pattern of incremental refactoring to establish shared infrastructure before introducing the reftable-specific validations in later patches. The patch maintains all existing error handling and reporting behavior while making the validation logic more reusable.
