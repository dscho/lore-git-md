This is part 2 of a 3-patch RFC series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) that continues the effort to eliminate global variables by moving repository-specific configuration into `struct config_values`. The series is part of the broader `the_repository` removal project.

This patch specifically targets the `core.sparseCheckout` configuration, moving it from the global `core_apply_sparse_checkout` variable into the per-repository `struct config_values`. The change affects 12 files across core commands (clone, mv, worktree), sparse-checkout handling, and repository infrastructure. Key changes include adding a `sparse_checkout` field to `struct config_values` and updating all access points to use the repository-specific value instead of the global.

The implementation maintains the existing eager loading behavior while providing a path to reduce global state, with proper cleanup in `repo_clear()`. The patch follows a design suggested by Phillip Wood to avoid pitfalls from previous attempts involving `prepare_repo_settings()` timing issues.

This appears to be a well-scoped change that cleanly handles the transition from global to per-repository storage for this particular config value. The patch touches several commands that interact with sparse-checkout functionality but keeps the behavioral changes minimal. The series as a whole represents a thoughtful approach to the `the_repository` elimination effort, focusing on one config value at a time while establishing a pattern for future conversions.
