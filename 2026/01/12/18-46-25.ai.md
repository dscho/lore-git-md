Feature: Submodule gitdir path configuration via repository extension

This patch introduces the `extensions.submodulePathConfig` extension, which changes how Git determines the location of submodule gitdirs. When enabled, the `submodule.<name>.gitdir` config becomes the authoritative source for each submodule's gitdir path, replacing the default `.git/modules/<name>` convention. This addresses filesystem conflicts that can occur with case-insensitive systems or nested submodule names.

The implementation automatically sets the gitdir config for new submodules when the extension is enabled, while requiring manual migration for existing submodules. The patch includes comprehensive documentation explaining the use case and migration process, plus new test coverage verifying the behavior with both legacy and new-style submodules.

Key technical details:
- New repository extension flag `repository_format_submodule_path_cfg`
- Centralized path resolution through enhanced `submodule_name_to_gitdir()`
- Validation logic to prevent path conflicts
- Automatic config creation during submodule init/add
- New test script `t7425-submodule-gitdir-path-extension.sh` covering:
  - Mixed extension/non-extension submodules
  - Path validation
  - Cloning behavior
  - Relative vs absolute URLs
  - Update/push workflows

This is patch 4/11 in a series that has undergone extensive review over 9 iterations, with all feedback now addressed. The implementation has been validated in production at Google and received maintainer approval. The series represents a significant architectural change to submodule handling, with this patch introducing the core configuration mechanism.
