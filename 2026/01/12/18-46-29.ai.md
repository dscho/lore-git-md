This is part 8 of an 11-patch series implementing path encoding for submodule gitdirs via the new `extensions.submodulePathConfig` mechanism. The series has already received extensive review and is approved for merging.

The current patch specifically addresses filesystem collisions by URL-encoding gitdir paths when the path configuration extension is enabled. The encoding uses RFC3986 rules (via shared functionality now in `url.[ch]`) to safely handle nested submodule names that would otherwise create invalid filesystem hierarchies. The implementation:

1. Attempts first with the plain module name (legacy behavior)
2. Falls back to URL-encoded version if validation fails
3. Centralizes path validation in `validate_submodule_git_dir()` with separate logic for encoded vs legacy paths
4. Adds comprehensive tests for nested submodules, parallel cloning, and extension toggling

Key technical details:
- New helper: `validate_submodule_encoded_git_dir()` for path validation under the new regime
- Shared URL encoding via `is_rfc3986_unreserved()` from `url.[ch]`
- Test coverage for edge cases like `hippo/hooks` submodule names
- Maintains backward compatibility when extension is disabled

The patch builds on design input from Junio Hamano and Patrick Steinhardt, with production validation by Josh Steadmon. All prior review feedback has been addressed, including moving URL encoding utilities to a shared location. This is a polished final version of the collision resolution mechanism for the submodule path encoding feature.
