This is part 6 of an 11-patch series implementing submodule gitdir path encoding via a new repository extension. The series introduces `extensions.submodulePathConfig` to prevent filesystem conflicts in submodule gitdirs by requiring explicit path configuration.

This patch adds a `git submodule--helper migrate-gitdir-configs` command to automate migration of existing submodules to the new configuration scheme. The command scans `.git/modules/`, validates paths, and creates the required `submodule.<name>.gitdir` config entries for each submodule. It also sets the repository format version and enables the extension.

Key technical details:
- New helper function module_migrate() implements the migration logic
- Validates paths using existing create_default_gitdir_config()
- Sets core.repositoryformatversion=1 if needed
- Enables extensions.submodulePathConfig
- Includes comprehensive tests for migration scenarios and clone behavior

The implementation addresses earlier feedback by:
- Using the centralized path validation from create_default_gitdir_config()
- Adding detailed error messages for configuration steps
- Testing both migrated and non-migrated clone scenarios
- Verifying the extension state after migration

This is a well-polished addition to the series, with thorough test coverage and clear documentation updates. The command provides a practical migration path for existing repositories adopting the new submodule path configuration scheme.
