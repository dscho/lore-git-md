This thread discusses a regression in pre-push hook behavior where commit 3e2836a742d redirected hook output from stdout to stderr, breaking existing workflows. Chris Darroch from Git LFS first reported the issue, noting it affects tools and test suites that rely on stdout output, a behavior stable since 2017. 

brian m. carlson has now responded, confirming the technical cause - the `stdout_to_stderr` flag in `pick_next_hook()` - and tracing it to commit 96e7225b31. They suggest this may have been inadvertently copied from hooks needing sideband communication, while noting many existing tools (including GitHub-based frameworks) depend on stdout output. The discussion remains constructive, balancing API consistency with backward compatibility concerns, with brian m. carlson recommending avoiding `stdout_to_stderr` unless specifically required. The thread awaits maintainer input on whether this change was intentional or should be reconsidered.
