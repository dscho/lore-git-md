This thread addresses a regression in pre-push hook behavior where output was incorrectly redirected from stdout to stderr, breaking existing workflows that had relied on this behavior since 2017. The issue was introduced in commit 3e2836a742d8b2b2da25ca06e9d0ac3a539bd966 when converting the pre-push hook to use the hook API, inadvertently inheriting stderr redirection meant for other hook types like pre-receive that require sideband communication.

Chris Darroch (Git LFS maintainer) first reported the issue, noting it broke test suites and production tools. brian m. carlson confirmed the technical cause, tracing it to commit 96e7225b31. Adrian Ratiu has now provided a fix that restores the original stdout behavior specifically for pre-push hooks while maintaining stderr redirection for other hook types. The patch modifies `hook.c` to skip setting the `stdout_to_stderr` flag for pre-push hooks. Adrian has verified the fix against Git LFS's test suite as part of his ongoing config-based hooks work.

The solution has consensus from participants as the right approach - preserving backward compatibility while keeping the stderr behavior for other hook types. The regression's impact on production tools is now clearly established, and the fix appears well-scoped to address the immediate issue without blocking future standardization of hook output streams.
