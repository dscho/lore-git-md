This is a bug report about a regression in pre-push hook behavior. Chris Darroch, a Git LFS maintainer, reports that after commit 3e2836a742d8 ("transport: convert pre-push to hook API"), messages from pre-push hooks that previously went to stdout are now being redirected to stderr. 

The change appears to stem from how the new hook API implementation in `stdout_to_stderr` flag being set in `pick_next_hook()`. While Git LFS can adapt their tests to expect stderr output instead of stdout, Chris raises a valid concern about backward compatibility for other users who may rely on the previous stdout behavior.

The email is written as a constructive heads-up rather than a demand for immediate reversion. Chris is seeking community input on whether this behavior change was intentional (in which case Git LFS will adapt) or if it might be reconsidered to maintain backward compatibility with existing hook implementations. The tone is collaborative, noting that while Git LFS's use of stdout for progress messages may not be ideal, it's been consistent since 2017.
