This is the second patch in Taylor Blau's two-part series fixing MIDX (multi-pack-index) corruption handling. The patch addresses a bug where Git could incorrectly skip rewriting a corrupt MIDX file when using `--stdin-packs`.

The issue occurs because the MIDX write machinery compares against an on-disk MIDX to determine if an update is needed, but wasn't properly validating the checksum of that MIDX first. The fix adds a checksum validation check in `midx_needs_update()`, ensuring corrupt MIDX files always trigger a rewrite rather than potentially being skipped.

The patch also updates the corresponding test case from `test_expect_failure` to `test_expect_success`, showing the fix works. This is a focused, well-explained change that closes a subtle hole in MIDX corruption handling. The commit message clearly explains both the current behavior and why this minimal fix is appropriate for now, while acknowledging a more comprehensive solution might be possible in the future.

This is part of Taylor's ongoing work on MIDX and packfile optimizations, and the fix is being split out from a larger series to ensure it can land in the upcoming v2.53.0 if the main work isn't ready. The change is small but important for data integrity when using MIDX files.
