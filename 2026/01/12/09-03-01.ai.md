Refactoring patch in Patrick Steinhardt's reftable backend validation series. This is patch 12/17 in the second iteration of the series, which aims to centralize ref validation checks across both files and reftable backends.

The patch extracts the worktree-specific backend retrieval logic from `backend_for()` into a new `backend_for_worktree()` helper function. This is a preparatory change that:
1. Moves the worktree backend lookup and initialization into a dedicated function
2. Maintains the same behavior but with cleaner separation of concerns
3. Will be reused in subsequent patches for validation purposes

The changes are mechanical - the diff shows the logic being moved verbatim from one function to another, with the calling code updated to use the new helper. The function handles both cached backends (via strmap lookup) and initialization of new ones, including error handling.

This continues the series' pattern of incremental refactoring before introducing new validation logic. The patch follows Git's coding style and maintains the existing error handling patterns seen in earlier parts of the series.
