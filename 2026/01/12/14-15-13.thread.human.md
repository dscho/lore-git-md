This thread introduces a new `git history` command, part of Patrick Steinhardt's ongoing work to expand Git's history manipulation capabilities. The current patch (v10, 1/8) extracts the core revision replay logic from `builtin/replay.c` into a standalone `replay_revisions()` function, preparing it for library use. The refactoring introduces new structures (`replay_revisions_options` and `replay_result`) to encapsulate the operation's configuration and outcomes while maintaining existing behavior.

The extracted logic handles both `--onto` and `--advance` modes, records reference updates, and uses Git's existing merge machinery internally. Some limitations remain (noted in FIXMEs) regarding root and merge commit support. This appears to be foundational work for a broader history manipulation feature, with this patch specifically focused on making the replay operation available as library code. The changes are well-contained and the commit message provides clear motivation for the refactoring.
