This is a v2 bugfix patch addressing logging format issues in git-http-backend. The patch ensures error messages from the `not_found` and `forbidden` functions are properly newline-terminated when written to stderr, particularly when run through wrappers like fcgiwrap where missing newlines can cause log entries to concatenate incorrectly in journald systems.

The changes respond to Junio Hamano's feedback on the initial version, replacing `fprintf(stderr, "\n")` with the more efficient `putc('\n', stderr)` for newline output. The core approach remains the same - wrapping existing `vfprintf` calls with conditionals and adding explicit newline output without altering the HTTP response behavior. The patch maintains its narrow focus on the two NORETURN functions in http-backend.c.

The discussion confirms this is a real-world issue affecting log readability, and the v2 implementation appears technically sound with Junio's optimization suggestion incorporated. The changes are minimal (6 insertions, 2 deletions) and well-contained, making this a straightforward improvement to git-http-backend's error reporting that should be ready for acceptance.
