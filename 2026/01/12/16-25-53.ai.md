This is the second patch in a two-part platform compatibility series addressing a macOS-specific iconv bug in ISO-2022-JP character encoding conversion. The patch builds on the first one (which introduced the ICONV_RESTART_RESET workaround in utf8.c) by adding build system support to automatically enable the workaround when needed.

The patch detects whether a known-good libiconv is available from common macOS package managers (Homebrew, MacPorts, Fink) by checking for their installation directories and libiconv.dylib presence. If no good libiconv is found on affected versions (macOS 14/15+), it automatically enables the ICONV_RESTART_RESET workaround via compiler flag. The implementation carefully handles different installation paths for each package manager, including Fink's recent switch from /sw to /opt/sw as default prefix.

The changes are narrowly scoped to the Makefile and config.mak.uname, introducing two new macros (HAS_GOOD_LIBICONV and NEEDS_GOOD_LIBICONV) to control the workaround logic. The patch follows established patterns for platform-specific build configuration while maintaining backward compatibility. It represents the build-system counterpart to the utf8.c changes in the first patch, completing the solution for the macOS iconv issue.
