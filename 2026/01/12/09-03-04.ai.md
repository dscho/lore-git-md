Bugfix patch in Patrick Steinhardt's ref backend validation series (15/17). This moves the zero-OID ref validation from `fsck_head_link()` into the shared `refs_fsck_ref()` infrastructure that both files and reftable backends use. The change makes this check consistent across backends and allows it to be disabled via fsck configuration.

The patch removes the special-cased zero-OID check from `fsck_head_link()` and adds it to `refs_fsck_ref()` with proper fsck message reporting (new `FSCK_MSG_BAD_REF_OID`). It also drops the unused return value from `fsck_head_link()` since callers weren't checking it. Test updates verify the new error message format while maintaining the same validation behavior.

This continues the series' pattern of centralizing validation logic while maintaining backward compatibility. The change is mechanical but meaningful - it eliminates one of the last remaining direct ref checks outside the shared validation infrastructure. Subsequent patches in the series will build on this foundation to further unify the validation paths.
