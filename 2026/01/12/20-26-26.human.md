This is the second patch in a 2-part series that enhances `git status` to show divergence from both upstream and push tracking branches. The feature is now ready for merging into `next` after 23 iterations of review.

The patch adds push tracking comparison to `git status` output when the push destination differs from the upstream branch. The output appears on a new line using the same format as the existing upstream status. For example, when tracking origin/main but pushing to origin/feature, it shows both relationships:

```
Your branch and 'origin/main' have diverged...
Your branch is ahead of 'origin/feature' by 1 commit.
```

The implementation introduces a new `get_remote_push_branch()` helper to resolve the push tracking branch, extends `format_tracking_info()` to handle both comparisons, and adds comprehensive test coverage in t6040-tracking-info.sh. The patch maintains all existing behavior including the `--no-ahead-behind` quick mode.

Key technical points:
- Uses BRANCH_MODE_PULL/PUSH flags to control advice display
- Handles remapped push refspecs
- Preserves output format consistency
- Includes 262 lines of new test cases covering various scenarios

The patch has been reviewed by Phillip Wood (who pushed for consistent advice display) and approved by Junio Hamano for merging. While it currently assumes `push.default=current`, any follow-up work on other push.default settings can be addressed separately. This represents a clean, well-tested extension to `git status` that provides useful information for workflows where upstream and push branches differ.
