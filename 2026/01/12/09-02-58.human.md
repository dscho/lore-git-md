This is part of Patrick Steinhardt's ongoing ref backend validation refactoring series (patch 9/17). The patch extracts generic symref validation checks from the files backend into a new `refs_fsck_symref()` function that can be shared across all ref backends. 

The key changes are:
1. Moves validation of symref targets (checking for valid refname format and proper refs/ prefix) into a reusable function in refs.c
2. Improves error reporting by avoiding redundant messages when both the format and target type are invalid
3. Leaves some parameters marked UNUSED for now, as they'll be used in later patches

This continues the series' pattern of centralizing validation logic that should apply equally to both files and reftable backends. The changes are mechanical but well-justified, with clear commit message explaining the shared nature of these checks. The patch builds on previous files backend refactoring while setting up for future reftable integration.
