This is part 9 of an 11-patch series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series introduces a new `extensions.submodulePathConfig` option that enables stricter path handling for submodule gitdirs.

This particular patch adds case-folding collision detection and resolution for filesystems that ignore case (like NTFS and HFS+). When a collision is detected between submodule names that differ only in case (e.g. "Foo" vs "foo"), the system will automatically apply stricter URL encoding that percent-encodes uppercase letters to ensure distinct paths.

The implementation:
- Adds a new `is_casefolding_rfc3986_unreserved()` helper in url.[ch] that treats uppercase as reserved
- Implements collision detection in `check_casefolding_conflict()`
- Falls back to appending digits if encoding alone doesn't resolve conflicts
- Includes comprehensive tests demonstrating the collision handling

This appears to be a well-considered solution to a tricky filesystem compatibility issue, with thorough test coverage showing it handles various edge cases (mixed case, already-encoded names, multiple collisions). The patch builds on previous work in the series and addresses all review feedback from earlier versions.
