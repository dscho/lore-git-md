This is part 15 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation. The series aims to centralize consistency checks for both files and reftable backends.

This patch moves the zero-OID ref validation from `fsck_head_link()` into the shared `refs_fsck_ref()` function, making it available to both ref backends. The change includes:

1. Adding a new `badRefOid` fsck message ID for reporting invalid object IDs
2. Removing the return value from `fsck_head_link()` since callers weren't checking it
3. Updating tests to expect the new error message format

The patch continues the series' pattern of moving validation logic into shared infrastructure while maintaining existing behavior. It's a clean change that removes some special-case handling from `fsck_head_link()` in preparation for its eventual removal in a later patch. The test updates confirm the validation still works as expected, just through the new shared path.
