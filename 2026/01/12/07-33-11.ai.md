This is a documentation-style follow-up email in the long-running thread about enhancing `git status` to show both upstream and push tracking branch divergence. Kristoffer Haugsbakk provides a clarification about patch series versioning conventions, specifically addressing Harald Nordgren's confusion about Junio Hamano's earlier comment regarding change explanations in cover letters.

The email explains that when sending updated versions of a patch series (like Harald's v20 iteration), it's conventional to include a "Changes in vX" section in the cover letter (PATCH 0/2) that summarizes what differs from the previous version. This helps reviewers quickly understand the evolution of the series without having to parse range-diffs. Kristoffer notes this is particularly valuable given that range-diffs can be difficult to read for complex changes.

While the core technical discussion about the `git status` enhancement is effectively closed (with Junio having approved the series for inclusion), this email serves as a helpful documentation pointer about Git contribution norms. Kristoffer acknowledges the uncertainty around how this convention applies when using gitgitgadget (a common tool for GitHub-based contributors to send patches to the mailing list), suggesting this aspect of the workflow might benefit from clearer documentation.

The exchange highlights how even after technical consensus is reached, there remains value in clarifying process and communication expectations for contributors navigating Git's mailing-list-based development model.
