This is part 3 of an RFC patch series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) continuing the effort to eliminate global configuration variables as part of the `the_repository` removal project. The series introduces `struct config_values` to hold previously global config values on a per-repository basis.

This patch specifically targets the `branch.autoSetupMerge` config value, moving it from the global `git_branch_track` variable into the new `struct config_values`. The change affects several commands that deal with branch tracking behavior (`branch`, `checkout`, `push`, and `submodule--helper`), requiring them to access the value through `the_repository->cfg_values->git_branch_track` instead of directly.

The implementation follows the pattern from previous patches in the series, maintaining the same behavior while removing global state. It includes proper initialization of the default value (`BRANCH_TRACK_REMOTE`) in `config_values_init_defaults()` and updates the access patterns throughout the codebase. The patch demonstrates the approach can handle enum-type configuration values in addition to the string and boolean cases shown in earlier patches.

This continues the series' goal of establishing a repeatable pattern for migrating configuration values out of global scope while addressing prior concerns about initialization timing. The changes are mechanical but touch multiple files, requiring careful updates to maintain consistent behavior across all affected commands.
