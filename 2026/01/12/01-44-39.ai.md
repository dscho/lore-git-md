Bugfix for git-http-backend logging format. This patch addresses an issue where error messages from the `not_found` and `forbidden` functions in `http-backend.c` could appear concatenated without newlines when logged through wrappers like fcgiwrap. The problem particularly affects deployments using journald or similar logging systems.

The v2 patch follows Junio Hamano's suggestion to use `putc('\n', stderr)` instead of `fprintf(stderr, "\n")` for newline output, optimizing away format string parsing overhead. The changes are minimal but important - wrapping the existing `vfprintf` calls with conditionals and adding explicit newline output while maintaining all existing error handling behavior.

This is a straightforward improvement to log readability that doesn't modify the actual HTTP response behavior or error handling logic. The patch remains narrowly focused on the two NORETURN functions in http-backend.c, with clean diffstat (6 insertions, 2 deletions). The change is well-motivated by real-world deployment issues and has already received positive feedback from the maintainer.
