Feature: This patch adds the `extensions.submodulePathConfig` extension to handle submodule gitdir path conflicts through explicit configuration.

The patch introduces a new repository extension that makes `submodule.<name>.gitdir` the single source of truth for submodule paths when enabled. This solves filesystem conflicts that occur with case-sensitive names (like "foo" vs "Foo") or nested paths (like "foo/bar"). The extension is opt-in and requires manual migration of existing submodules by setting their gitdir configs.

Key changes include:
- New `repository_format_submodule_path_cfg` flag in repository structs
- Automatic configuration of gitdir paths for new submodules
- Strict validation requiring gitdir configs when the extension is enabled
- Documentation updates explaining the feature and migration process
- Comprehensive tests covering mixed legacy/new submodules, cloning behavior, and path validation

The implementation centralizes path resolution through `submodule_name_to_gitdir()` and adds validation to prevent conflicts. Error messages guide users through migration when needed. The patch is part of a larger series (v9 04/11) that has undergone extensive review, with this being the core configuration piece that enables the path encoding functionality.

Production validation from Google confirms the approach works at scale. The patch appears well-polished after nine iterations, with clear documentation and thorough test coverage. It addresses a real pain point for users dealing with submodule path conflicts while maintaining backward compatibility.
