This is a refactoring patch from Patrick Steinhardt that moves the core logic of `git replay` into libgit.a as part of the larger `git-history` command series. The patch extracts the replay functionality from `builtin/replay.c` into new `replay.c` and `replay.h` files, making it available as a library function.

The changes are mechanical but substantial - 369 lines removed from the builtin and 355+64 lines added to the new library files. Key technical details:
- Introduces `replay_revisions()` as the main library interface
- Defines `struct replay_revisions_options` and `struct replay_result` for configuration and output
- Preserves all existing functionality including reference updates and merge conflict detection
- Removes dependency on `the_repository` (a `#define` remains but will be handled in the series)
- Maintains the same error handling and edge case behavior

The patch appears well-structured and clearly motivated as infrastructure for the upcoming `git-history` command. It follows Git's pattern of moving functionality from builtins to libraries when reuse is needed. The implementation looks solid with comprehensive error handling and clean separation of concerns.

This is part of the v10 series that has seen extensive review, with Elijah Newren's recent fixup patches addressing detached HEAD handling and interface refinements. The changes here appear to incorporate those improvements while maintaining the series' focus on non-conflicting operations.
