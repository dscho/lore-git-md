This patch is part of Patrick Steinhardt's ongoing ref backend validation refactoring series (v2, patch 9/17). It extracts generic symref validation checks from the files backend into a shared `refs_fsck_symref()` function that can be used by all ref backends.

The key changes are:
1. Moves symref target validation (checking for valid refname format and proper ref/ prefix) from `files_fsck_symref_target()` to a new `refs_fsck_symref()` in refs.c
2. Improves error reporting by avoiding redundant messages when a target has both format and prefix issues
3. Keeps files-backend-specific checks (like newline validation) in the original function
4. Adds `UNUSED` parameters that will be used in later patches

The patch continues the series' pattern of centralizing validation logic while maintaining backend-specific behavior where needed. It touches core refs infrastructure (`refs.c`, `refs.h`) while modifying the files backend implementation. The changes are mechanical but important for the series' goal of unified validation - this establishes the shared symref checking that the upcoming reftable backend patches will use.
