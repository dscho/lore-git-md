This is part 5 of an 8-patch series introducing a new `git-history` command, focused on supporting detached HEAD updates in the replay infrastructure. The patch comes from Patrick Steinhardt with a contribution from Elijah Newren.

The change enables the replay machinery to properly handle detached HEAD states when rewriting history. Previously, the code only updated local branch refs (`DECORATION_REF_LOCAL`) but ignored HEAD when it was detached. The patch adds detection of detached HEAD state and includes `DECORATION_REF_HEAD` in the refs to be updated. The ref iteration logic is also refactored for clarity.

A new test case verifies the behavior by creating a detached HEAD, making a commit, and confirming the replay operation properly updates the detached HEAD position. The change is part of the larger effort to build robust foundation for the upcoming `git-history` command while maintaining compatibility with existing replay operations.

The patch appears well-constructed with clear motivation, clean implementation, and appropriate test coverage. It builds on previous work in the series and addresses a specific gap in the replay functionality. The change is relatively small but important for ensuring consistent behavior across all ref types.
