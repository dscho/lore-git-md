This is a two-part platform compatibility patch series addressing a macOS-specific bug in character encoding conversion, specifically for ISO-2022-JP encoding. The patches build on previous discussion about test failures in t3900 related to macOS 14/15's iconv implementation.

The core issue involves macOS's iconv implementation failing to maintain conversion context when the output buffer grows during ISO-2022-JP to UTF-8 conversion in Git's reencode_string_iconv() function. The series introduces a workarounds: first preparing the infrastructure for the fix (patch 1), then enabling it (patch 2).

The solution involves saving input state, resetting the converter, and retrying from scratch on buffer growth, while maintaining backward compatibility. The patches modify utf8.c and add build system support via Makefile changes. The author has refined the commit messages across versions based on feedback from René Scharfe and Junio Hamano, clarifying that alternative iconv implementations (via Homebrew, Macports or Fink) remain viable options.
