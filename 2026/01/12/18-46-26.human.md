Feature patch introducing runtime configuration for submodule path encoding. This is patch 5/11 in a well-polished series that has gone through 9 iterations with extensive review from key contributors like Patrick Steinhardt and Junio Hamano.

The patch adds `init.defaultSubmodulePathConfig`, a new config option allowing users to enable the submodule path extension (`extensions.submodulePathConfig`) by default for new repositories created via `git init` or `git clone`. Importantly, this only affects new repositories - existing ones require explicit migration.

The implementation is thorough, with comprehensive coverage of different scenarios in the test suite:
- Verifying `git init` behavior with and without the config
- Testing `git clone` and `--recurse-submodules` in both configurations
- Ensuring proper inheritance of the setting from global config
- Checking that existing repositories remain unaffected

The patch represents the culmination of significant design work and review, with all feedback from previous iterations addressed. It's part of a larger effort to improve submodule path handling that has already received merge approval from Junio Hamano. The series is production-tested at Google and appears to be in final form, ready for merging.
