This is a refactoring series that completes the unification of ref consistency checks across Git's files and reftable backends. Patrick Steinhardt's 17-patch series moves fsck checks from `builtin/fsck.c` into the refs subsystem, introducing shared validation functions (`refs_fsck_ref()`, `refs_fsck_symref()`) and new error codes that work identically for both storage formats. The work has undergone thorough review from Shejialuo, with all major feedback addressed in this v2 iteration.

The series progresses through three logical phases: first cleaning up files backend validation (patches 1-8), then introducing shared verification infrastructure (9-14), and finally migrating fsck checks (15-17). Key technical changes include proper root ref iteration, improved symref verification error handling, and removal of the now-unused `errors_found` field. The implementation maintains consistent behavior across worktrees via the new `backend_for_worktree()` infrastructure.

While most architectural questions were resolved in v1, one remaining discussion point concerns whether to centralize HEAD detection logic between `refs_fsck_symref()` and `reglog.c` - Patrick prefers keeping explicit checks for now due to potential confusion between main repository and worktree HEADs. The series touches `refs/files-backend.c`, `refs/reftable-backend.c`, `refs.c`, and `builtin/fsck.c` while adding test coverage in t0602 (reftable) and t1450 (fsck).

With all major review comments addressed and the implementation proven across both backends, this appears ready for merging. The work establishes unified ref checking infrastructure that will benefit current and future ref backends, marking the completion of a significant refactoring effort in Git's ref storage layer.
