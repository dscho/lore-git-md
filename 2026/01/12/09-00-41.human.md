Refactoring patch in the ODB abstraction effort. This is the first of seven patches in Patrick Steinhardt's v5 series improving object info handling, which has already received approval from Karthik Nayak and addresses all prior feedback.

The patch restructures `odb_source_loose_read_object_info()` in `object-file.c` to ensure the `whence` field is always set to `OI_LOOSE` for successful returns. The main changes are:

1. Reorganizing the function to use a single exit path via `goto` for better control flow
2. Adding proper cleanup guards for resources like mapped memory and zstream
3. Moving scratch pointer setup closer to where they're used
4. Renaming variables to match Git's style (`status` -> `ret`)
5. Consolidating object info cleanup (including delta_base_oid reset) in one place

The diff is somewhat noisy due to the structural changes, but the result is more maintainable code with clearer error handling. This is part of the larger effort to abstract Git's object database layer, with measurable performance improvements (9% speedup in disk size lookups) already demonstrated in later patches of the series.
