Feature: This is the 7th patch in Patrick Steinhardt's v10 series introducing the new `git history` command, which provides an alternative to `git rebase` for common history editing operations.

The patch adds the basic scaffolding for the new command, including:
- Documentation explaining the experimental nature of the command and its differences from rebase (works in bare repos, no hooks, updates dependent branches)
- Implementation skeleton in builtin/history.c with basic argument parsing
- Build system integration (Makefile, meson.build)
- A simple test verifying basic command behavior

Key technical details:
- Currently implements no actual subcommands (placeholder for future functionality)
- Explicitly documents current limitations (no merge support, no conflict handling)
- Designed to work with the replay infrastructure from earlier patches in the series
- Follows Git's standard command implementation pattern

The command is positioned as a more opinionated alternative to rebase for common history editing tasks like reordering, splitting, or dropping commits. The documentation emphasizes this is experimental and may change, particularly around conflict handling which remains a point of discussion in the thread.

This patch builds on the extensive infrastructure work in previous patches (now moved to libgit.a) while keeping the initial command implementation minimal. The real functionality will come in subsequent patches that add specific subcommands like `reword` and `split`.
