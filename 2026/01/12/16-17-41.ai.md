This is a bugfix for the `git last-modified` command, addressing two issues when passed invalid input. The patch comes from Toon Claes, who is known for work on ref backends and `git replay`.

The main fix prevents a BUG() from occurring when `git last-modified` is given a tree OID (like `HEAD^{tree}`) instead of a commit. Previously this would trigger an internal assertion failure with an unhelpful error. The command now properly validates that the input is a commit-ish and gives a clear error message.

A secondary fix addresses a memory leak in the `populate_paths_from_revs()` function where the pathspec wasn't being cleared in error paths. The patch adds test coverage for both fixes, verifying the new error message appears when given a tree object.

The changes are straightforward - adding input validation before the diff operation and ensuring proper cleanup. The commit message clearly explains the problem and solution, including a real-world report that motivated the fix. This appears to be a well-contained improvement to error handling in a relatively new builtin command.
