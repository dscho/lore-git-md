This is a refactoring patch from Patrick Steinhardt's ongoing `git-history` command series (v10 6/8). It introduces a new function to the working tree status subsystem that compares two arbitrary trees rather than the working tree/index.

The patch adds `wt_status_collect_changes_trees()` which diffs two tree objects and formats the changes in the same style as staged index changes. This will be used by the upcoming `git-history` command to show changes between commits during history editing operations. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic.

The implementation reuses the existing callback infrastructure from `wt_status_collect_updated_cb` and handles rename detection configuration consistently with other status operations. The function signature takes two treeish OIDs and a `wt_status` struct to store results.

This is a straightforward plumbing change that enables the higher-level history editing functionality while maintaining Git's existing diff presentation. The patch appears cleanly implemented with no obvious issues, though its real test will come when the calling code is introduced in subsequent patches of the series.
