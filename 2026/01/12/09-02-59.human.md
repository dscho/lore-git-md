This is part 10 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation to unify consistency checks between the files and reftable backends. The series is methodically moving shared validation logic out of backend-specific code into common infrastructure.

This patch introduces a new empty function `refs_fsck_ref()` in refs.c that will eventually contain generic validation checks for direct (non-symbolic) references. Currently it just returns 0, but the infrastructure is being set up for future patches to populate it with shared validation logic. The function follows the same pattern as the previously introduced `refs_fsck_symref()` for symbolic ref validation.

The changes are straightforward plumbing - adding the function declaration in refs.h, an empty implementation in refs.c, and a call site in the files backend that will use the function once it's implemented. This continues the series' careful approach of first establishing the framework before filling in functionality, ensuring each step remains reviewable and bisectable.

The patch maintains the series' high quality with clean separation of concerns and clear commit message explaining the temporary nature of the empty function. Reviewers can expect subsequent patches to build on this foundation by adding the actual validation logic.
