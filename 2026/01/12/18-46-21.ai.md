This is the final version (v9) of a feature series implementing runtime configuration of submodule gitdir paths through a new `extensions.submodulePathConfig` extension. The series has been through 8 previous iterations with extensive review, and Junio Hamano has already given final approval for merging pending these last polish fixes.

The key changes in v9 are minor cleanups addressing Patrick Steinhardt's final review comments:
1. Replaced `git config --global` with `test_config_global` in tests
2. Split `die()` messages to multiple lines for better readability
3. Fixed some whitespace issues introduced in v8

The core functionality remains unchanged from v8 - this is purely a polish update. The series implements:
- A four-tier fallback system for submodule gitdir paths (plain -> encoded -> numbered -> hashed)
- Case-folding protection via RFC3986 encoding
- Atomic migration command with version checking
- Comprehensive test coverage including nested submodules and edge cases

Josh Steadmon has confirmed successful testing against Google's internal use cases (which sponsored this work), providing real-world validation. The architectural approach of centralized path resolution through `submodule_name_to_gitdir()` is now fully implemented and tested, with all technical and documentation issues resolved.

Files touched include `submodule.c`, `builtin/submodule--helper.c`, `setup.c`, and `url.[ch]`, plus extensive new tests in `t7425-submodule-gitdir-path-extension.sh`. The series adds three new config options: `extensions.submodulePathConfig`, `submodule.<name>.gitdir`, and `init.defaultSubmodulePathConfig`.

With these final polish fixes, the series appears ready for merging into Git's main branch. The changes are well-tested, thoroughly reviewed, and address a longstanding limitation in submodule path handling.
