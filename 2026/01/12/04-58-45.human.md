This is a platform compatibility patch addressing a macOS-specific bug in character encoding conversion. It's the first of a two-part series fixing test failures in t3900 when converting ISO-2022-JP to UTF-8 on macOS 14/15.

The patch introduces a workaround for a bug in macOS's iconv implementation where the converter loses state when the output buffer grows during piecemeal conversion. The solution saves the input state, resets the converter, and retries from scratch when buffer resizing is needed, controlled by a new ICONV_RESTART_RESET compile-time flag.

The commit message clearly explains the issue with test output examples and discusses two potential solutions: linking against a different iconv (already supported via package managers) or applying this workaround. The patch takes the latter path for cases where alternative iconv isn't available.

This appears to be a well-motivated fix for a real platform-specific issue, with clear documentation of both the problem and solution. The code change is focused and maintains backward compatibility. The second patch in the series will presumably add build system support for the new flag.
