This RFC thread explores Olamide Caleb Bello's work (mentored by Christian Couder and Usman Akinyemi) to migrate Git's global configuration variables into repository-specific storage as part of the broader `the_repository` removal effort. The series introduces a `struct repo_config_values` and demonstrates its use with three key variables: `core.attributesFile`, `core.sparseCheckout`, and `branch.autoSetupMerge`. The implementation includes safety mechanisms like validity assertions, initialization flags, and BUG checks for double-initialization.

Phillip Wood recently weighed in with technical feedback on the `core.attributesFile` migration, raising important considerations about memory management when repositories are freed and documenting the zero-initialization requirement. While generally supportive of the approach, his review highlights remaining edge cases that need addressing, particularly around proper cleanup and initialization guarantees as the project moves away from global variables.

The discussion has surfaced key architectural questions that still need resolution before this work can progress beyond RFC status. Junio Hamano has questioned whether all the runtime checking is truly necessary, while the thread has identified config scoping across multiple repositories and initialization pattern variations as primary blockers. The current state shows a technically sound approach for individual migrations, but broader consensus is needed on repository lifecycle management before considering additional migrations or merging this work.
