This thread documents Olamide Caleb Bello's Outreachy internship project (mentored by Christian Couder) to eliminate global configuration variables as part of Git's ongoing `the_repository` removal effort. The series demonstrates how to move different types of configuration values from global variables into a new `struct repo_config_values` embedded in `struct repository`.

The three-part series shows the pattern for each major configuration type: part 1 moved the string-valued `core.attributesFile`, part 2 handled the boolean `core.sparseCheckout`, and the final patch completes the set by converting the enum-type `branch.autoSetupMerge`. Each conversion follows the same approach - removing the global variable, adding a field to the repository's config struct, updating all access points, and ensuring proper initialization and cleanup.

Phillip Wood provided key early review feedback that shaped the design, particularly the decision to embed the config values directly in the repository struct rather than using pointer allocation. The changes affect numerous commands (branch, checkout, push, submodule, etc.) and demonstrate how to make them properly repository-aware.

While the series successfully shown the technical approach for all three configuration types, it leaves open some architectural questions about the long-term organization of these values - particularly whether they should live in `config.[ch]` or `environment.[ch]`, and how to scale this approach to Git's many remaining configuration variables. As an Outreachy contribution, this represents meaningful progress on a challenging, multi-year effort to eliminate Git's reliance on global state.
