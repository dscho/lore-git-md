This RFC thread follows Olamide Caleb Bello's work (an Outreachy intern mentored by Christian Couder) to eliminate global configuration variables as part of the broader `the_repository` removal effort. The series introduces `struct repo_config_values` embedded in `struct repository` to store repository-specific configs like `core.sparseCheckout` and `branch.autoSetupMerge`, affecting 20+ files across three focused patches.

The v3 iteration incorporates Phillip Wood's suggestion to use a dedicated config struct rather than `repo-settings`, resolving earlier concerns about initialization timing. Technical implementation now ensures proper sequencing - particularly for `git_branch_track` defaults - and avoids heap allocation by storing values directly in the repository struct. While steady progress has been made on the immediate changes, two broader architectural questions remain open from Junio Hamano's feedback: establishing formal criteria for determining config variable scope (repository vs global) and developing patterns for mixed-scope initialization. These are acknowledged as future work rather than blockers.

The thread demonstrates how this series serves both as a concrete migration of specific config variables and as a template for future global-state elimination. With design consensus largely reached on the current scope, Bello appears ready to proceed with implementation refinements while keeping an eye on the larger patterns that will shape dozens of similar migrations to come. The changes maintain existing behavior while paving the way for eventually passing repository parameters to `git_default_config()` callbacks.
