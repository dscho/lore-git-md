This thread documents Olamide Caleb Bello's work (as an Outreachy intern mentored by Christian Couder) to eliminate global configuration variables as part of Git's ongoing `the_repository` removal effort. The patch series introduces `struct repo_config_values` to store repository-specific configuration, migrating three variables (`core.attributesFile`, `core.sparseCheckout`, and `branch.autoSetupMerge`) from global scope into this new struct embedded in `struct repository`.

The implementation follows Phillip Wood's suggestion to create a dedicated config struct rather than reusing `repo-settings`, with careful attention to initialization sequencing to maintain existing behavior. The changes affect over 20 files across multiple commands, updating them to access config values through `the_repository->config_values`. Through three iterations, the series has improved in organization and commit message clarity while addressing technical concerns about edge cases like submodule handling.

While larger architectural questions remain open (particularly around formal criteria for determining config variable scope), the series has built steady consensus and appears ready for merging. It serves both as a specific migration of three config variables and as a template for future work in the broader `the_repository` removal effort. The patches maintain existing behavior while carefully handling initialization and repository-scoped access, representing a concrete step forward in this long-term project.
