This RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) introduces `struct config_values` to systematically eliminate global configuration variables as part of the ongoing `the_repository` removal effort. The series demonstrates the approach by converting three key configuration values from global to repository-specific storage: `core.attributesFile` (part 1), `core.sparseCheckout` (part 2), and now `branch.autoSetupMerge` (part 3).

The design creates per-repository configuration storage that avoids the initialization timing issues of `prepare_repo_settings()`, following Phillip Wood's earlier suggestion. Each patch follows a consistent pattern: moving a global variable into `struct config_values`, updating all access points to use the repository-aware version, and ensuring proper cleanup. The latest patch handles the enum-type `branch.autoSetupMerge` configuration, affecting branch-related commands like checkout and push, while maintaining the default `BRANCH_TRACK_REMOTE` behavior.

The series has shown the approach works across different configuration types (string, boolean, and now enum) while touching numerous files - 20+ for attributes, 12 for sparse-checkout, and several branch-related commands in this latest iteration. Open questions remain about scaling this to all configuration values, but the series successfully establishes a repeatable migration pattern that addresses prior design concerns. Next steps will likely involve applying this approach to additional configuration values based on feedback from the RFC discussion.
