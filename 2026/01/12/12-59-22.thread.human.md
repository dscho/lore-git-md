Olamide Caleb Bello, an Outreachy intern mentored by Christian Couder, is working on eliminating global configuration variables as part of the ongoing `the_repository` removal effort. The latest patch series introduces `struct repo_config_values` to store repository-specific configuration, starting with migrating `core.attributesFile` from the global `git_attributes_file` to the new struct. This first part establishes the pattern for the series, with subsequent patches planned to handle `core.sparseCheckout` and `branch.autoSetupMerge`.

The implementation follows Phillip Wood's suggestion to use a dedicated config struct rather than extending `repo-settings`. Toon Claes provided helpful review feedback on documentation clarity and NULL-safety, which the author has acknowledged will be addressed in the next version. While this specific migration appears technically sound, Phillip Wood has raised a broader architectural concern about how non-primary repository instances will handle these configuration values - a question that affects the entire series and remains unresolved. The changes maintain existing behavior while moving toward the long-term goal of repository-scoped configuration storage.
