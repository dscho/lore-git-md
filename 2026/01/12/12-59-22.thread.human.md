This RFC thread explores moving Git's configuration variables from global storage into repository-specific structures as part of the broader `the_repository` removal effort. Olamide Caleb Bello, an Outreachy intern mentored by Christian Couder and Usman Akinyemi, has proposed a series introducing `struct repo_config_values` to hold these migrated settings. The work demonstrates successful migrations for three key configurations: `core.attributesFile`, `core.sparseCheckout`, and most recently `branch.autoSetupMerge` (which controls automatic upstream branch behavior).

The implementation has evolved through six versions, adding progressively stronger safety mechanisms like repository validity assertions, initialization flags, and BUG() checks for double-initialization. Phillip Wood has contributed naming improvements throughout the series. While the technical approach works - shown by the test suite passing with new checks - Junio Hamano has questioned whether all these runtime checks are truly necessary. The bigger unresolved questions center around handling initialization patterns across multiple repositories and config scoping, particularly for cases involving libgit2-style embedding.

The latest patch completes the migration of `branch.autoSetupMerge`, affecting several commands (`branch`, `checkout`, `push`, and submodule handling) while maintaining the same behavior through repository-specific storage. Though this series demonstrates the technical path forward for individual migrations, the architectural discussion about the right level of runtime checking and cross-repository initialization guarantees remains open before this approach could be merged.
