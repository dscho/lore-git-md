This RFC thread explores Olamide Caleb Bello's (Outreachy intern) series introducing `struct repo_config_values` to eliminate global configuration variables as part of the `the_repository` removal effort. The series demonstrates the approach across three config value types (string, boolean, enum) affecting 30+ files, with each part moving a different config variable into the repository struct.

Junio C Hamano has now weighed in with a fundamental architectural question about the series' core assumption - whether all these config values should indeed be repository-scoped. He points to other nearby globals (whitespace handling, compression levels) that may need different treatment, suggesting some settings might legitimately remain system-wide. This feedback could require the series to distinguish between repository-specific and truly global config values rather than applying a uniform pattern.

The series currently shows a clean, consistent approach under Christian Couder's mentorship, having incorporated Phillip Wood's earlier naming feedback. But Junio's intervention raises questions that may reshape the effort's scope before it proceeds further. The thread now awaits the author's response to this high-level design feedback.
