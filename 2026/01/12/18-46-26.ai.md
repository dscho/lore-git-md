This is part 5 of an 11-patch series implementing runtime configuration for submodule gitdir paths via the new `extensions.submodulePathConfig` extension. The series has gone through 9 iterations with extensive review and is now in its final polished form.

The patch adds a new `init.defaultSubmodulePathConfig` configuration option that allows enabling the submodule path extension by default for new repositories (those created via `git init` or `git clone`). Importantly, this does not globally enable the extension - existing repositories remain unaffected and would need explicit migration. The implementation modifies `setup.c` to check this config during repository initialization and adds comprehensive test coverage in `t7425-submodule-gitdir-path-extension.sh` for both init and clone scenarios.

Key technical details:
- The extension requires repository format version 1, so the patch ensures this minimum version when enabling
- Tests verify behavior with and without the global config setting
- Includes cases for both direct submodule creation and recursive cloning
- Maintains backward compatibility - existing repositories continue working as before

The patch addresses all feedback from previous rounds, including suggestions from Patrick Steinhardt and Junio Hamano. It's part of a well-tested series that has already received merge approval, with this being one of the final polishing patches to complete the implementation. The series as a whole provides a robust solution for submodule gitdir path encoding while maintaining compatibility with existing repositories.
