This is a review comment on patch 4/10 in Patrick Steinhardt's series refactoring packfile storage for pluggable ODB backends. Karthik Nayak provides feedback on the `unuse_one_window()` function changes, agreeing with Patrick's analysis that the function's previous behavior was misleading.

The key observation is that `unuse_one_window()` previously took a `packed_git` parameter that could theoretically be NULL, but in practice never was after a 2019 change. Patrick's patch simplifies the function to take the object database directly instead, making the code clearer by removing the unused NULL check. Karthik confirms this is an improvement, noting the new version is "much nicer indeed."

The change is part of the larger effort to move packfile store ownership from the ODB layer to individual ODB sources. This particular patch focuses on cleaning up the window management code while maintaining the same behavior. Karthik's review indicates the change is well-justified and correctly implemented.
