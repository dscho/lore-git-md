This is a refactoring patch in Patrick Steinhardt's ongoing `git-history` command series (v10, patch 4/8). The change prepares the replay infrastructure to handle empty commit ranges, which will be needed for the new command's implicit HEAD-based range detection.

The patch fixes an edge case where `replay_revisions()` would incorrectly report merge conflicts when given an empty commit range. Currently, the `merge_result` struct is zero-initialized, causing the `.clean` flag to remain 0 (indicating a conflict) even when no merges occurred. The change explicitly initializes `.clean` to 1 (success) while keeping other fields zeroed via the struct initialization syntax.

This is a small but important technical refinement that enables the subsequent introduction of implicit range handling in the history command. The change is straightforward and well-contained, with no behavioral impact on existing `git-replay` usage since that command already rejects empty ranges explicitly. The patch maintains the series' high quality with clear commit message explanation and minimal, focused changes.
