This is part 4 of Patrick Steinhardt's 7-patch series refactoring Git's object info handling as part of the ODB abstraction effort. The patch ensures consistent population of pack-specific fields in the object info structure regardless of which code path is taken.

The change moves the pack-specific field population (offset, pack pointer, and delta type) from `packfile_store_read_object_info()` to `packed_object_info()`, guaranteeing these fields are always set when reading from a pack. This eliminates an inconsistency where the same object could have different info depending on the lookup path.

The patch is a straightforward refactoring that:
- Moves the field initialization code to a single location
- Maintains the same behavior but with more predictable results
- Follows the series' theme of cleaning up object info handling

As with the rest of the series, this has been reviewed by Karthik Nayak and addresses all prior feedback. The change is part of the larger effort to abstract Git's object database while improving code quality and maintainability.
