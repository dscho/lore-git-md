This is a follow-up in the ongoing discussion about bugfixes for the `git last-modified` command's behavior with refspec paths in bare repositories.

Toon Claes confirms and clarifies the bug behavior reported earlier by Gusted. The issue occurs when using refspec-style paths (like `HEAD:LICENSES`) with `git last-modified`. He notes that on Git 2.52.0, this triggers a BUG assertion crash, while on the current master branch it fails silently with no output. 

The email reveals an additional nuance: the same underlying bug manifests differently depending on whether the `--` separator is used. Without `--`, the refspec resolves to a tree OID but still hits the same crash. Toon indicates he's actively working on a fix for these cases.

This continues the thread's focus on making `git last-modified` more robust when handling different path specifications, particularly in bare repository contexts. The discussion remains technical and collaborative, with Toon building on previous reports to clarify the exact failure modes. The fix for the original crash has already landed in master, but this follow-up identifies related cases that still need attention.
