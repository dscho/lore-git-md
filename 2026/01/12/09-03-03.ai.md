This is part 14 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation to centralize consistency checks. The series aims to unify validation logic between the traditional filesystem-based ref backend and the newer reftable backend.

This patch wires up the generic ref validation checks (introduced in earlier patches) for the reftable backend. It implements low-level iteration through reftable records to perform both direct ref validation (checking object IDs) and symref validation (checking symbolic reference targets). The implementation carefully avoids using higher-level iterators that might hide broken refs, ensuring all inconsistencies are caught.

The changes include comprehensive error handling and proper cleanup of resources. A new test case verifies that invalid symrefs are correctly detected and reported. The patch maintains the series' pattern of mechanical refactoring while fixing real implementation issues, with test coverage for both valid and invalid cases.

This continues the architectural progression toward unified backend checking, building on the shared validation infrastructure established in previous patches. The implementation handles both main worktree and secondary worktree cases correctly, using the `backend_for_worktree()` helper introduced earlier in the series.
