This is a follow-up discussion in the long-running thread about enhancing `git status` to show divergence from both upstream and push tracking branches. Phillip Wood provides review feedback on Harald Nordgren's implementation, focusing on two main technical points:

First, Phillip questions the current approach to push reference resolution, suggesting `branch_get_push()` might be preferable to the current `remote_ref_for_branch()`/`tracking_for_push_dest()` combination. He notes this would better respect `push.default` configuration while simplifying the code, though acknowledges the need to handle cases where push refspecs exist but don't match the current branch.

Second, Phillip examines the advice message display logic, arguing the divergence advice should show regardless of mode (PULL/PUSH) rather than being guarded by `BRANCH_MODE_PULL`. He points out the current implementation might suppress useful advice in some push-only divergence cases, though Harald counters that duplicate advice could result when both upstream and push branches diverge.

The exchange reveals some remaining design questions about edge case behavior, though the core functionality has already been approved by Junio for inclusion. Phillip's comments focus on refining the implementation details rather than challenging the overall approach, suggesting this is late-stage polishing of an otherwise settled feature.
