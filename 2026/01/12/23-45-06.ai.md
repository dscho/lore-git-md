Bugfix targeting the MIDX (multi-pack-index) corruption handling. This is the second patch in a two-part series from Taylor Blau addressing an issue where Git could fail to detect corrupt MIDX files that need rewriting. The first patch exposed the bug by fixing a test issue; this one implements the actual fix.

The core issue occurs when using `--stdin-packs` with MIDX writes. The code compares against an existing MIDX to avoid unnecessary writes, but wasn't properly validating the checksum of that MIDX first. This could lead to Git incorrectly skipping updates for corrupt MIDX files. The patch adds a checksum validation check in `midx_needs_update()` to ensure corrupt MIDXs always trigger a rewrite.

The change is minimal and focused - it adds the validation guard while acknowledging that a more robust solution would involve reworking how MIDX reuse works with `--stdin-packs`. The accompanying test that was previously marked as `test_expect_failure` is now updated to `test_expect_success`, confirming the fix works.

This is part of Taylor Blau's ongoing work on the MIDX subsystem and was split from a larger MIDX compaction effort to ensure the fix could land in Git 2.53.0 if the main series gets delayed. The patch touches `midx-write.c` and the MIDX test script, with careful attention to maintaining the existing optimization behavior for valid MIDX files.
