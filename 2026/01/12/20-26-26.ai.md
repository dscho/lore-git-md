This is the second patch in Harald Nordgren's 2-part series to enhance `git status` with push tracking branch comparison, now ready for merging into `next`. The implementation adds push tracking information when it differs from the upstream tracking branch, showing both comparisons in the status output.

The patch introduces:
- A new `get_remote_push_branch()` helper to resolve push tracking references
- Extended `format_tracking_info()` to handle both upstream and push comparisons
- BRANCH_MODE_PULL/PUSH flags to control display behavior
- Comprehensive test coverage (262 lines) in t6040-tracking-info.sh
- Support for remapped push refspecs
- Consistent output formatting with the new push info on a separate line

Key behaviors:
- Only shows push comparison when it differs from upstream
- Maintains existing advice messages (push/pull hints) for each branch
- Preserves quick mode (`--no-ahead-behind`) behavior
- Handles edge cases like remapped refspecs and multiple remotes

The implementation follows Junio's feedback on variable naming (`cmp_fetch`/`push_cmp_fetch`) and Phillip Wood's input on advice display consistency. While the current version assumes `push.default=current`, this limitation is noted for potential follow-up work.

With 23 iterations of review and final approval from Junio, this represents a polished feature addition that cleanly extends `git status`'s tracking information capabilities while maintaining backward compatibility.
