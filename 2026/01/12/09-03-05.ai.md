This is part 16 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation. The patch moves the HEAD symref validation from `builtin/fsck.c` into the shared `refs_fsck_symref()` infrastructure in `refs.c`, continuing the series' goal of centralizing ref consistency checks.

The change introduces a new `FSCK_MSG_BAD_HEAD_TARGET` error for HEAD refs that don't point to a branch (under `refs/heads/`), replacing the previous direct error message. The validation now happens during the generic symref checking phase rather than as a special case in fsck. Test updates verify the new error message format while maintaining the same validation behavior.

This follows the pattern established in earlier patches - moving backend-specific checks into shared infrastructure while preserving existing behavior. The patch touches core ref handling code (`refs.c`), fsck plumbing (`builtin/fsck.c`), and related tests, with careful attention to worktree handling through the `parse_worktree_ref()` helper. The series continues its systematic elimination of backend-specific validation paths in favor of unified checks that work consistently across both files and reftable storage.
