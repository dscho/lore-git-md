This is the second version of a platform compatibility patch addressing a macOS-specific iconv bug affecting ISO-2022-JP character encoding conversion. The issue manifests when Git's reencode_string_iconv() function needs to resize its output buffer during conversion, causing macOS 14/15's iconv implementation to lose state and corrupt the output.

The patch introduces a workaround controlled by a new ICONV_RESTART_RESET compile-time flag. When enabled, it handles buffer growth by saving the input state, resetting the converter, and retrying from scratch rather than continuing the conversion. The implementation carefully preserves original input positions and converter state during retries, with clear documentation of the workaround in code comments.

The author notes two potential solutions: linking against a different iconv implementation (already supported via package managers like Homebrew) or using this new workaround. This patch implements the latter approach, with a follow-up patch expected to add build system support for enabling the workaround. The change is narrowly scoped to utf8.c and maintains backward compatibility while fixing the macOS-specific issue.
