Refactoring patch in Patrick Steinhardt's ref backend validation series. This is patch 8/17 in the ongoing effort to centralize ref consistency checks across both files and reftable backends.

The patch removes two unused fields from `struct fsck_ref_report` in `fsck.h` and their corresponding display logic in `fsck.c`. The fields (`oid` and `referent`) were intended to show additional context about broken refs (the object ID or target reference) in error messages, but were never actually populated. The removal is straightforward since the fields weren't being used, and the commit message clearly explains the rationale.

This continues the series' pattern of cleaning up the ref validation infrastructure before introducing shared validation functions. The change is mechanical and uncontroversial, aligning with the overall goal of simplifying the codebase while maintaining functionality. The patch follows the series' high standard for commit message clarity and focused scope.
