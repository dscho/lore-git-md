This is part 2 of a 3-patch RFC series from Outreachy intern Olamide Caleb Bello, mentored by Christian Couder, that continues the effort to eliminate global variables by moving repository-specific values into a new `struct config_values` within `struct repository`. The series is part of the broader `the_repository` removal effort.

This patch specifically targets the `core.sparseCheckout` config value, which was previously stored in the global variable `core_apply_sparse_checkout`. The change moves this into the per-repository config struct while maintaining the same eager loading behavior. The implementation touches 12 files across core commands (clone, mv, worktree), sparse-checkout handling, and repository infrastructure.

The changes are mechanical but widespread, updating all access points to use the new repository-specific storage location. The patch appears well-scoped and maintains existing behavior while making progress on the global variable elimination goal. Phillip Wood provided design input to avoid pitfalls from previous attempts at similar changes.

This continues the approach demonstrated in patch 1 (which handled `core.attributesFile`) and sets up for patch 3 to address `branch.autoSetupMerge`. The series represents solid incremental progress on a challenging architectural change.
