This is the first patch in Patrick Steinhardt's v5 series refactoring Git's object info handling as part of the ODB abstraction effort. The patch focuses on improving the loose object reading logic in `object-file.c`.

The main change restructures `odb_source_loose_read_object_info()` to use a single exit path via `goto` statements, ensuring the `whence` field in `struct object_info` is always set to `OI_LOOSE` for successful operations. This addresses an issue where some early return paths weren't properly indicating the object format.

Key technical changes include:
- Converting multiple return paths to a single exit point via `out` and `corrupt` labels
- Moving scratch pointer setup closer to where they're used in `parse_loose_header()`
- Adding guards for cleanup operations to only run when needed
- Consolidating `oi->delta_base_oid` clearing with other object info cleanup
- Renaming `status` to `ret` to match Git's coding style

The patch demonstrates careful attention to error handling and resource cleanup, though the diff is somewhat noisy due to the structural changes. This refactoring makes the code more maintainable by eliminating subtle bugs where the `whence` field could be left unset, while also improving compiler warnings about uninitialized values.

As part of the larger ODB abstraction series that has already received approval from Karthik Nayak, this change helps standardize object info handling in preparation for pluggable backends. The single-exit pattern introduced here will likely serve as a model for future work in this area.
