Bugfix for git-http-backend logging format. This patch addresses an issue where error messages from the `not_found` and `forbidden` functions in git-http-backend could appear concatenated without newlines when logged through wrappers like fcgiwrap. The problem particularly affects systems using journald for logging, where multiple error messages would run together in the log output.

The patch modifies `http-backend.c` to ensure proper newline termination of error messages written to stderr. It wraps the existing `vfprintf` calls with conditionals and adds explicit newline output via `putc('\n', stderr)` (following Junio Hamano's suggestion to avoid format string parsing overhead). The change maintains the same error handling logic while fixing log readability.

This is a straightforward, focused fix that has already received positive feedback from the maintainer. The patch is in its second iteration, having incorporated Junio's optimization suggestion, and appears ready for merging. The change is small but meaningful for anyone running git-http-backend through CGI wrappers with centralized logging.
