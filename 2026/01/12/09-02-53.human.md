This is part 4 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation. The patch removes an unnecessary function indirection in the files backend by inlining `files_fsck_refs()` into its only caller, `files_fsck()`. 

The change simplifies the code by eliminating a function that was passing all arguments through unchanged. It also fixes the error handling - instead of bitwise OR-ing return values (which could mask errors), it now properly propagates any failure from either the loose or packed ref checks. 

This is a straightforward cleanup that follows logically from the previous patches in the series. The change is mechanical and low-risk, touching only the files backend implementation. It continues the series' pattern of simplifying the codebase in preparation for introducing shared validation infrastructure across both ref backends.
