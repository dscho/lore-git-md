This is a platform compatibility patch addressing a macOS-specific issue with iconv character encoding conversion, specifically affecting ISO-2022-JP to UTF-8 conversion in Git's utf8.c. It's part of a two-patch series (this being the first) that provides a workaround for a bug in macOS 14/15's iconv implementation.

The patch introduces a careful workaround for when iconv's output buffer needs to grow during conversion. The macOS iconv loses state when the buffer is resized, corrupting the output. The solution saves the input state, resets the converter, and retries from scratch with the larger buffer while preserving input positions. The workaround is gated behind ICONV_RESTART_RESET to maintain backward compatibility.

The commit message is thorough, explaining the test failures that revealed the issue and detailing two possible solutions (linking against alternate iconv implementations or this new workaround). The implementation follows established patterns for platform-specific fixes in utf8.c and has already incorporated feedback from René Scharfe and Junio Hamano in previous iterations. The patch is narrowly scoped to the buffer growth case in reencode_string_iconv() and includes clear documentation block explaining the workaround's purpose.
