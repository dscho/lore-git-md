This is part of Patrick Steinhardt's ongoing ref backend validation refactoring series, specifically moving HEAD validation checks into the shared refs_fsck infrastructure. 

The patch relocates the check that ensures HEAD points to a valid branch (under refs/heads/) from builtin/fsck.c to refs.c, making it part of the backend-agnostic validation system. This continues the series' pattern of centralizing ref validation logic that should apply equally to both files and reftable backends.

Key changes include:
- Adding a new FSCK_MSG_BAD_HEAD_TARGET error type for when HEAD points to a non-branch
- Moving the actual validation into refs_fsck_symref() where it can handle both regular and worktree HEAD refs
- Updating tests to expect the new error message format while maintaining the same validation behavior

The patch is mechanically sound and follows the established pattern of the series. It's a straightforward migration of existing functionality into the new validation framework, with appropriate test coverage. This brings Git one step closer to having consistent ref validation across all backends.
