Refactoring and bugfix series for Git's object info handling, now with regression test.

This is the fifth iteration of Patrick Steinhardt's series to refactor how Git reads object information, part of the ongoing ODB abstraction effort. The series has already received thorough review from Karthik Nayak and others, with all feedback addressed in previous versions. The main changes in v5 are:

1. The discovery and fix of a segfault in `git archive` when handling deltified blobs larger than core.bigFileThreshold. This was an incidental bug fix uncovered during development.

2. Addition of a regression test to prevent this specific segfault from recurring. The test creates a repository with delta chains of large files and verifies `git archive` can handle them correctly.

The series continues to improve object info handling by:
- Simplifying the interface between loose and packed object handling
- Making packed object type tracking more precise with a 4-state enum
- Ensuring consistent field population in packed object info
- Optimizing disk size lookups (9% speedup)
- Removing redundant parameters

With the new regression coverage and all prior review feedback addressed, this appears ready for integration. The changes touch core object-handling code in `object-file.c`, `packfile.c`, and related headers, with impacts on commands like `git cat-file` and `git pack-objects`.
