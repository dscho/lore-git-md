This is the final patch in Patrick Steinhardt's 17-part series refactoring Git's ref backend validation. The series has systematically moved consistency checks from `builtin/fsck.c` into shared infrastructure in the refs subsystem that works across both files and reftable backends.

Patch 17 removes the now-obsolete `fsck_head_link()` function, which previously performed HEAD ref validation. The commit message explains that all its checks are now handled by the new `refs_fsck()` infrastructure, either through refname format validation or symref resolution checks. The remaining NULL pointer check in `fsck_head_link()` is redundant since the cases it would catch are already covered elsewhere.

The patch is a straightforward cleanup that inlines the remaining `refs_resolve_ref_unsafe()` call at the one remaining call site. This completes the series' goal of centralizing ref validation logic while maintaining all existing checks. The changes follow the series' established pattern of mechanical refactoring that preserves behavior while enabling future validation improvements.
