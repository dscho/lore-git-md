This is part of Patrick Steinhardt's ongoing effort to create a new `git history` command (patch 1/8 in v10 of the series). The patch extracts the core revision replay logic from `builtin/replay.c` into a new `replay_revisions()` function in preparation for moving it into libgit.a.

The new function encapsulates the replay operation's three main phases: taking input revisions and options, performing the replay, and recording reference updates. It introduces a `replay_revisions_options` struct for configuration and a `replay_result` struct to track outcomes (including reference updates and merge conflicts). The change is purely structural - no behavior changes are intended.

Key technical details for future reference:
- The extracted logic handles both `--onto` and `--advance` modes
- Records ref updates in a `replay_result` structure with `replay_ref_update` entries
- Still has limitations noted in FIXMEs (no root commit or merge commit support)
- Uses existing merge machinery (`merge_options`, `merge_result`) internally
- Maintains the same error handling semantics (returns 0/1/128 for success/conflict/error)

The patch is part of a larger series that appears to be building infrastructure for a new history manipulation command, with this step focused on making the replay logic library-accessible. The changes are well-contained and the commit message clearly explains the motivation.
