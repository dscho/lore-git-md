This is a refactoring patch from Patrick Steinhardt that moves the core logic of `git replay` into libgit.a as part of the larger `git-history` command series. The patch extracts 355 lines of replay functionality from `builtin/replay.c` into new `replay.c` and `replay.h` files, making it available as a library function.

The changes are mechanical - the code is moved nearly verbatim with minimal interface adjustments. Key aspects:
- The new `replay_revisions()` function takes a `rev_info` struct and options, producing a `replay_result` with reference updates
- The header file documents the API and data structures
- The patch eliminates sign-comparison warnings and `the_repository` dependencies
- All existing functionality is preserved, just relocated

This is patch 2/8 in the v10 series introducing `git-history`, which aims to provide flexible history editing operations. The refactoring enables sharing the replay logic between commands while maintaining clean separation. The implementation appears solid and well-contained, following Git's typical patterns for moving builtin code into the library.
