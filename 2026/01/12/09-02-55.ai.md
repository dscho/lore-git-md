This is part 6 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation. The patch focuses on improving error handling when verifying symbolic refs in the files backend.

The changes address two specific issues in `files_fsck_symref_target()`: first, the function was potentially swallowing previous errors when ignoring certain conditions, and second, it would bail out early on invalid target references without checking for other problems. The fix replaces direct assignments with bitwise OR operations (`|=`) to accumulate all errors and removes the early return path, ensuring all validation checks run regardless of previous failures.

The patch maintains the same error reporting behavior but makes it more robust by ensuring no errors are lost. This continues the series' pattern of careful refactoring to prepare for shared validation infrastructure between the files and reftable backends. The changes are mechanical but important for correctness - they ensure fsck catches all possible issues with symbolic refs rather than stopping at the first problem.
