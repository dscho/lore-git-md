This is the final patch in Patrick Steinhardt's v10 series introducing the experimental `git history` command, specifically implementing the "reword" subcommand. The series builds on Git's replay infrastructure to provide fast, in-memory history editing capabilities inspired by Jujutsu's functionality.

The "reword" subcommand allows modifying commit messages without checking out the commit, working even with dirty working trees. Key characteristics:
- Operates entirely in-memory for speed
- Updates all local branches containing the rewritten commit by default (configurable via --ref-action)
- Preserves authorship and tree content while excluding GPG signatures
- Includes comprehensive test coverage (391 lines across 18 test cases)
- Explicitly marked as such in documentation

Notable implementation details:
- Uses new `wt_status_collect_changes_trees()` for tree-to-tree diffs
- Handles detached HEAD cases through DECORATION_REF_HEAD
- Moves core replay logic to libgit.a while preserving functionality
- Currently skips hook execution (may change in future)
- Follows standard Git command patterns for argument parsing

The patch completes the technical implementation started in earlier patches, with all review feedback addressed. Remaining open questions (documented in earlier patches) about future conflict handling don't block this initial non-conflicting subcommand. The series appears ready for merging to gather user feedback, pending resolution of SZEDER's forward-compatibility concerns about future subcommands that might introduce conflicts.
