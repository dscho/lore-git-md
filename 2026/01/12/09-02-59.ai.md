This is part 10 of Patrick Steinhardt's 17-patch series refactoring Git's ref backend validation to create shared consistency checks for both files and reftable backends. Following the previous patch that introduced shared symref validation, this patch lays groundwork for direct ref validation by adding a new `refs_fsck_ref()` function in refs.c.

The function is empty in this patch (returning 0 unconditionally) but will be populated with direct ref validation logic in subsequent patches. It follows the same pattern as the earlier `refs_fsck_symref()` - a backend-agnostic validation function that individual backends will call during their fsck operations. The patch adds the function declaration to refs.h and wires it into the files backend's `files_fsck_refs_content()` where it will eventually perform checks on non-symbolic refs.

This continues the series' careful progression: first refactoring the files backend, then extracting common functionality. The empty function here is a clear marker for where direct ref validation will be centralized, keeping the architectural direction visible while allowing incremental implementation. The series remains focused on its goal of unified validation across backends while maintaining files backend stability throughout the transition.
