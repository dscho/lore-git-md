RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) introducing `struct config_values` to eliminate global configuration variables as part of `the_repository` removal effort. Series demonstrates approach with three config values: `core.attributesFile` (part 1), `core.sparseCheckout` (part 2), and now `branch.autoSetupMerge` (part 3).

Core design creates per-repository `struct config_values` to hold previously global values, following Phillip Wood's suggestion to avoid `prepare_repo_settings()` timing issues. Implementation maintains eager loading while providing path to reduce global state, with proper cleanup in `repo_clear()`. For `branch.autoSetupMerge`, patch moves global `git_branch_track` enum into repository struct, affecting branch-related commands (`branch`, `checkout`, `push`, `submodule--helper`). Earlier patches handled `core.attributesFile` (removing global `git_attributes_file`, affecting 20+ files) and `core.sparseCheckout` (moving `core_apply_sparse_checkout`, affecting 12 files).

Technical changes include new fields in `struct config_values` (`attributes_file_path`, `sparse_checkout`, `git_branch_track`), updates to access patterns (all affected commands now repository-aware), and removal of global variable declarations. Series demonstrates pattern works for string, boolean, and enum configuration types. Establishes repeatable approach for future migrations while addressing initialization timing concerns. Open questions remain about scaling to all configuration values and interaction with other global elimination efforts. Next steps likely include extending approach to additional config values pending feedback on RFC.
