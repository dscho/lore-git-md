RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) introducing `struct repo_config_values` to eliminate global configuration variables as part of `the_repository` removal effort. The v3 iteration migrates `core.attributesFile`, `core.sparseCheckout`, and `branch.autoSetupMerge` configuration values stored in the new struct embedded in `struct repository`, affecting 30+ files across multiple commands.

The implementation follows Phillip Wood's suggestion to create a dedicated config struct rather than using `repo-settings`, with initialization via `repo_config_values_init()` during repository setup. Part 1 introduces `struct repo_config_values` and migrates `core.attributesFile` from global `git_attributes_file` to `the_repository->config_values.attributes_file_path`, updating `attr.c` and `git_default_core_config()`. Phillip Wood's review of part 1 suggested improvements including concrete examples of global variable issues and reconsidering the `_path` suffix. Toon Claes provided earlier feedback on NULL-safety, comments, and commit message focus.

Part 2 migrates `core.sparseCheckout` from global `core_apply_sparse_checkout` to `the_repository->config_values.sparse_checkout`, updating 12 files including sparse-checkout command behavior, clone initialization, and submodule handling. Phillip Wood identified a critical flaw: config values are only populated for `the_repository`, leaving other repository structs with defaults regardless of actual configuration. He suggested fixes including clarifying limitations, fixing unsafe usage in backfill.c, improving documentation, and refining naming (`apply_sparse_checkout` or `sparse_checkout_apply`). Toon Claes noted minor issues like a duplicate commit message line and typo in variable name.

Part 3 moves `branch.autoSetupMerge` to `the_repository->config_values.git_branch_track` (later renamed to drop `git_` prefix per Phillip Wood's suggestion), affecting branch, checkout, push, and submodule--helper commands. The v3 iteration shows improved commit message clarity and better organization with struct initialization moved to part 1. Phillip Wood's review reiterates core concerns about repository-scoped access validity and proper handling of non-primary repository instances, suggesting this architectural challenge must be resolved across all three migrated variables.

Junio C Hamano's open questions remain deferred: (1) formal criteria for config variable scope (repository vs global), with Bello maintaining only repository-dependent variables are being moved, and (2) comprehensive solution for initialization when mixing scoped/global configs. The implementation maintains existing behavior while handling edge cases like submodule grep and cone mode interactions, though Phillip Wood's reviews reveal the critical gap in non-primary repository handling that blocks progress.

The series establishes patterns for future migrations in the `the_repository` removal effort. While most technical concerns from Toon Claes and Phillip Wood have been addressed through iteration, Phillip's latest reviews identify the unresolved architectural issue regarding non-primary instance handling as the current blocking point. This otherwise well-reviewed series has made substantial progress in eliminating global configuration variables, with the remaining challenge being proper support for multiple repository instances.
