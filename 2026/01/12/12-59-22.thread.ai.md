RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) introducing `struct config_values` (proposed to be renamed `repo_config`) to eliminate global configuration variables as part of `the_repository` removal effort. Series demonstrates approach with three config values: `core.attributesFile` (part 1), `core.sparseCheckout` (part 2), and `branch.autoSetupMerge` (part 3).

Core design creates per-repository configuration storage, with Phillip Wood suggesting key architectural improvements: embed directly in `struct repository` (avoiding allocation, matching `repo_settings` pattern), rename to `repo_config` for clarity, and consider moving to `environment.[ch]`. Implementation preserves eager loading while eliminating globals, with proper cleanup in `repo_clear()`. 

For `core.attributesFile` (part 1), patch moves global `git_attributes_file` into repository struct, affecting 20+ files. Phillip's review emphasizes that eager loading is the key invariant, not `git_default_core_config()`'s exact implementation. Author acknowledges feedback and plans revisions.

For `core.sparseCheckout` (part 2), moves `core_apply_sparse_checkout` global, affecting 12 files. For `branch.autoSetupMerge` (part 3), moves global `git_branch_track` enum into repository struct, affecting branch-related commands (`branch`, `checkout`, `push`, `submodule--helper`).

Technical changes include new fields in config struct (`attributes_file_path`, `sparse_checkout`, `git_branch_track`), updates to access patterns (all affected commands now repository-aware), and removal of global declarations. Demonstrates pattern works for string, boolean, and enum configuration types. Open questions remain about final struct location (`config.[ch]` vs `environment.[ch]`), naming (`config_values` vs `repo_config`), and scaling to all configuration values. Next steps will involve revising RFC approach based on Phillip's feedback before extending to additional config values.
