RFC patch series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) introducing `struct config_values` (now proposed to be renamed `repo_config`) to eliminate global configuration variables as part of `the_repository` removal effort. Series demonstrates approach with three config values: `core.attributesFile` (part 1), `core.sparseCheckout` (part 2), and `branch.autoSetupMerge` (part 3).

Core design created per-repository heap-allocated `struct config_values`, but Phillip Wood suggests architectural improvements: embed directly in `struct repository` (avoiding allocation, matching `repo_settings` pattern), rename to `repo_config` for clarity, and consider moving to `environment.[ch]`. Implementation currently maintains eager loading while eliminating globals, with proper cleanup in `repo_clear()`. For `branch.autoSetupMerge`, patch moves global `git_branch_track` enum into repository struct, affecting branch-related commands (`branch`, `checkout`, `push`, `submodule--helper`). Earlier patches handled `core.attributesFile` (removing global `git_attributes_file`, affecting 20+ files) and `core.sparseCheckout` (moving `core_apply_sparse_checkout`, affecting 12 files).

Technical changes include new fields in config struct (`attributes_file_path`, `sparse_checkout`, `git_branch_track`), updates to access patterns (all affected commands now repository-aware), and removal of global declarations. Series demonstrates pattern works for string, boolean, and enum configuration types. Phillip's review emphasizes that preserving eager loading is the key invariant, not `git_default_core_config()`'s exact implementation. Open questions remain about final struct location (`config.[ch]` vs `environment.[ch]`), naming (`config_values` vs `repo_config`), and scaling to all configuration values. Next steps will likely involve revising the RFC approach based on Phillip's feedback before extending to additional config values.
