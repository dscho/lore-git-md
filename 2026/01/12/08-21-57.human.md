This is a bugfix for HTTP authentication in remote-curl, specifically addressing Bearer token authentication failures during filtered clones. The issue occurs when probe_rpc() makes subsequent requests without proper auth headers, even though initial authentication succeeds. The fix is minimal - just 2 lines adding auth header handling to match existing patterns in post_rpc().

Patrick Steinhardt confirms the test approach proposed by Aaron Plattner (using 2000 branches and a dummy Bearer token credential helper) is reasonable for validating the fix. The discussion reveals this is Bearer-token-specific since curl handles Basic auth automatically. While there's some exploration of whether to use CURLOPT_XOAUTH2_BEARER (like imap-send.c does), the immediate focus remains on test coverage for the current approach.

The patch appears straightforward and well-motivated, with Lucas De Marchi having already tested and confirmed it works. The test case will help ensure this edge case doesn't regress, particularly for users of git-credential-msal and other Bearer token flows. This seems like a solid fix for a real-world authentication issue affecting filtered clone operations.
