This is a feature proposal for a new Git configuration mechanism to handle template files. The author suggests adding a `.gittemplates` file (or configuration parameter) that would work similarly to `.gitignore`, but with a key difference: files listed there would be indexed in the repository but their changes would not be tracked. This would allow committing template versions of files (like `.env` or machine-specific configs) while letting users modify local copies without those changes being committed.

The proposal aims to solve a common workflow pain point where developers currently need to maintain two versions of such files - a committed version with a different name and a local ignored version. The author suggests this would be particularly useful for pipeline configurations and personalized setups.

The email is a first proposal rather than a patch submission, so there's no implementation details or code changes to evaluate. The idea appears to target a real workflow issue, though the mailing list may want to discuss whether this functionality could be achieved through existing mechanisms (like `--assume-unchanged` or `--skip-worktree`) before considering a new feature. The proposal is brief and would benefit from more concrete examples of the problem and solution.
