This is the first patch in Patrick Steinhardt's 17-part series refactoring Git's ref backend validation. It targets the files backend's root ref iteration logic.

The patch simplifies how Git iterates through root refs in the files backend by removing an unnecessary indirection through the loose ref cache. Currently, the code retrieves the root directory path via `refs->loose->root->name` (which is always empty) before passing it to `files_ref_path()`. This creates both confusion and a potential segfault since the loose ref cache may not be initialized when this code runs.

The change makes the code more straightforward by directly passing an empty string to `files_ref_path()`, which is the correct way to get the root refs directory. It also fixes the segfault risk by eliminating the dependency on the loose ref cache. The patch includes cleanup of related string buffer handling, removing now-unnecessary length tracking.

This is a clean, focused improvement that removes fragile code while maintaining the same functionality. As the first step in a larger refactoring series, it establishes a more solid foundation for the subsequent changes to ref validation.
