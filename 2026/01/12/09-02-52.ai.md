Refactoring patch in Patrick Steinhardt's ref backend validation series. This is the third patch in a 17-part effort to centralize ref consistency checks across both files and reftable backends.

The patch simplifies the files backend's reference checking logic by removing the `refs_check_dir` parameter from `files_fsck_refs_dir()`, since the function always checks the complete "refs" hierarchy. The parameter was redundant as callers always passed "refs" anyway. The change hardcodes this path while maintaining identical behavior, cleaning up the interface.

Key changes:
- Removes parameter from function signature and all call sites
- Updates path construction to use hardcoded "refs" instead
- Preserves special worktree path handling when needed
- Keeps existing fsck output format and verbosity

This continues the series' pattern of streamlining the backend code in preparation for introducing shared validation infrastructure. The change is mechanical but meaningful - eliminating an unnecessary parameter that could only ever have one value in practice. The patch follows the series' careful approach of making incremental improvements to the files backend before introducing cross-backend functionality.
