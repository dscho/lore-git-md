This is part of Patrick Steinhardt's ongoing refactoring of Git's ref backend validation, specifically addressing an inconsistency in how the reftable backend handles worktree verification. 

The patch fixes a bug where the reftable backend was incorrectly verifying refs across all worktrees rather than just the specified one, unlike the files backend which handles this correctly. The current implementation also had a secondary issue where it wasn't properly iterating through worktree reftable stacks due to an incorrectly populated strmap.

The solution involves:
1. Using the newly introduced `backend_for_worktree()` helper to properly scope verification
2. Distinguishing between main and worktree backends
3. Adding proper error handling when worktree stacks are broken

The patch includes new test cases that verify the fixed behavior by:
- Creating a worktree
- Manipulating its reftable stack to simulate corruption
- Confirming the verification catches these issues only for the intended worktree

This continues the series' pattern of careful, incremental refactoring while maintaining existing behavior where correct. The changes are well-motivated and the test coverage appears thorough, exercising both successful and error cases.
