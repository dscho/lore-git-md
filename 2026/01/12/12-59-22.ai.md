This is a refactoring patch series that's part of the ongoing effort to reduce global variables in Git's codebase. The cover letter introduces an RFC (Request for Comments) approach for moving configuration values that are currently stored globally into a new per-repository config struct.

The series comes from an Outreachy intern (Olamide Caleb Bello) who has been working on eliminating global variables, specifically those in environment.h. Previous attempts ran into design questions about when to call `prepare_repo_settings()` and behavior changes from lazy loading. Phillip Wood suggested creating a new config struct within the repository struct as an alternative approach.

The current implementation stores parsed values in `the_repository` via `git_default_*_config()` functions, with plans to later pass the repository parameter to `git_default_config()`. The series demonstrates this approach with three configuration values: `core.attributesFile`, `core.sparseCheckout`, and `branch.autoSetupMerge`.

The changes touch a wide range of files (20 modified) including core commands like checkout, clone, and push, plus configuration and repository handling code. The approach looks like a promising direction for reducing globals while maintaining existing behavior, though as an RFC it's explicitly seeking feedback before proceeding further with this strategy. The patch series appears well-motivated and carefully considered, with clear references to prior discussion threads that shaped the current approach.
