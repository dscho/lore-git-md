This is part 2 of an 11-patch series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series has gone through 9 iterations with extensive review and is now in its final polished form.

The patch centralizes validation of submodule gitdir paths by moving checks into `submodule_name_to_gitdir()`, which now always validates paths before returning them. This eliminates redundant validation calls and ensures all paths (including those from config) get validated. The change simplifies the API while maintaining safety - two validation calls remain in `builtin/submodule--helper.c` to handle parallel clone races.

Key technical details:
- Removes validation checks from 3 call sites (submodule move/relocate operations)
- Adds validation directly in `submodule_name_to_gitdir()`
- Preserves two validation calls in clone operations for race protection
- Touches `submodule.c` and `builtin/submodule--helper.c`

The change is part of a larger effort to implement path encoding via repository extension (`extensions.submodulePathConfig`), with case-folding protection and comprehensive test coverage. The series has received maintainer approval and real-world validated via Google's internal use. This particular patch represents a clean-up of the validation logic that was identified during review.
