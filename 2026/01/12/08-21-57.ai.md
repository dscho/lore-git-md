This is a bugfix discussion thread about HTTP authentication in remote-curl, specifically addressing an issue where probe_rpc() requests fail with 401 errors during filtered clones when using token-based authentication. The conversation builds on previous analysis that identified the problem occurs with Bearer tokens but not Basic auth, since curl handles Basic auth automatically.

Patrick Steinhardt confirms that Aaron Plattner's proposed test approach - creating a repository with 2000 branches to trigger the probe_rpc() path and using a dummy Bearer token credential helper - would be a valid way to test the fix. He notes this can be done efficiently with a single update-ref call, avoiding performance concerns. The discussion also touches on deeper HTTP authentication considerations, particularly around whether to use CURLOPT_XOAUTH2_BEARER (as imap-send.c does) versus the current approach, though this remains an open question.

The thread shows the patch is moving toward a v2 version that will include test coverage, with the core fix being a simple 2-line change to remote-curl.c that mirrors existing auth handling from post_rpc(). The conversation reveals nuanced understanding of how different authentication methods interact with curl's automatic handling versus Git's explicit header management.
