Refactoring patch in Patrick Steinhardt's ref backend validation series. This is patch 4/17 in the second iteration of the series, which aims to centralize ref consistency checks across files and reftable backends.

The patch removes an unnecessary wrapper function `files_fsck_refs()` that simply forwarded all arguments to `files_fsck_refs_dir()`. Since there was only one callsite, the patch inlines the function call directly into `files_fsck()`. It also changes the error handling from a bitwise OR of return values to explicit error checking, which is more readable and intentional.

The change is part of the broader effort to clean up the files backend implementation before introducing shared validation infrastructure. While small, it demonstrates the series' attention to code quality - removing indirection and making error handling more explicit. The patch maintains all existing functionality while simplifying the call graph.
