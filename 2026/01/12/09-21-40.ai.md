This is a technical discussion about the placement of a constant in the ongoing `the_repository` removal effort. Patrick Steinhardt questions why `DEFAULT_MAX_ALLOWED_TREE_DEPTH` was added to the global `git-compat-util.h` header rather than being scoped to the repository settings subsystem where it's actually used.

Patrick suggests two alternatives: moving the definition to `repo-settings.h` (making it available to other files that might need the default value) or to `repo-settings.c` (keeping it entirely internal to the settings implementation). He notes that since repository settings must be initialized before use, the default could simply be set during config parsing rather than being exposed as a compile-time constant.

This is a minor but thoughtful critique of René Scharfe's patch series that removes implicit repository dependencies from tree parsing. The discussion focuses on proper code organization rather than functionality, with Patrick offering concrete suggestions to reduce global visibility of implementation details. The exchange reflects the project's ongoing attention to clean architecture in the multi-year effort to eliminate `the_repository` global.
