This is a refactoring patch in Patrick Steinhardt's series to unify ref validation across Git's storage backends. Karthik Nayak reviews patch 4/17, which removes an unnecessary wrapper function in the files backend code.

The change eliminates `files_fsck_refs()`, which was just passing through to `files_fsck_refs_dir()`, inlining the call directly in `files_fsck()`. It also fixes the error handling - the original used a bitwise OR to combine return values, which could mask errors. The new version properly tracks failure with an explicit `ret` variable.

Karthik confirms the change looks correct, though he initially wondered about using logical OR before realizing the direct return approach is better. The patch is a straightforward cleanup that maintains behavior while simplifying the code structure, part of the larger effort to standardize validation between files and reftable backends.
