This is a documentation discussion thread follow-up regarding improvements to Git's "MyFirstContribution" guide. Shreyansh Paliwal responds to Pushkar Singh's earlier suggestion about test parallelism tradeoffs in the tutorial.

The exchange clarifies the rationale behind including `-j$(nproc)` in the test execution instructions. Shreyansh explains they added this note based on personal experience where full parallelization caused system strain, leading them to suggest adjusting rather than eliminating parallelism. They argue that while parallel tests can make failures harder to read, the time savings justify keeping parallelism as the default, with users able to reduce job count if needed.

This reply provides useful context about the practical considerations behind the documentation choice, showing how real-world contributor experience informed the guide's recommendations. The discussion remains focused on optimizing the new contributor experience while acknowledging the tradeoffs between test speed and debuggability.
