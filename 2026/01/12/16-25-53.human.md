This is the second part of a platform compatibility patch series addressing a macOS-specific iconv bug in ISO-2022-JP character encoding conversion. The patch builds on the first part's technical workaround by adding build system support to automatically detect and handle the problematic macOS iconv implementation.

The patch introduces two new macros (HAS_GOOD_LIBICONV and NEEDS_GOOD_LIBICONV) to detect whether a working iconv implementation is available from common macOS package managers (Homebrew, MacPorts, Fink). If no good iconv is found, it enables the ICONV_RESTART_RESET workaround from the first patch. The changes are narrowly scoped to the Makefile and config.mak.uname, maintaining backward compatibility while adding the new detection logic.

The series has already gone through review iterations, with feedback from René Scharfe and Junio Hamano incorporated into improved commit messages. The technical approach appears sound and follows established patterns for platform-specific fixes in Git's character encoding infrastructure. This second patch completes the solution by making the workaround automatic when needed while still allowing users to opt for alternative iconv implementations if available.
