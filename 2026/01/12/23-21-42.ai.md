This is a bug report about a regression in pre-push hook behavior introduced by a recent change to Git's hook API. Chris Darroch from the Git LFS project reports that after commit 3e2836a742d8b2b2da25ca06e9d0ac3a539bd966 ("transport: convert pre-push to hook API"), messages from pre-push hooks that previously went to stdout are now being redirected to stderr.

The issue stems from `pick_next_hook()` in hook.c setting `stdout_to_stderr` in the child_process arguments. While Git LFS could adapt their test suite to expect stderr output instead of stdout, Chris raises the valid concern that this behavioral change might break other users' workflows that depend on the previous stdout behavior.

The email notes this behavior has been consistent in Git LFS since at least 2017 (referencing specific commits and PRs). Chris is seeking guidance on whether this change was intentional (in which case Git LFS will adapt) or if it might be reconsidered to maintain backward compatibility. The tone is constructive - reporting an observed issue while acknowledging their own code could be adjusted if needed.
