Performance investigation of `git pack-refs` on NFS with high ref counts. Martin Fick follows up on Jeff King's analysis with new findings from strace timing data, ruling out earlier hypotheses about write buffering and pack file counts being the bottleneck. 

Key technical observations: The actual write operations (8192-byte chunks) execute quickly, but the process spends ~4 minutes of its 4m15s runtime in gaps between writes. This suggests the slowdown occurs in memory operations rather than I/O - likely either mmap access patterns over NFS or inefficient in-memory ref lookups. Martin speculates about two potential causes: slow NFS-backed mmap reads of the packed-refs file, or an inefficient search algorithm for ref lookups (though he notes Git likely doesn't use binary search here).

The thread continues to narrow down the performance discrepancy between Git and JGit in high-refcount environments, with this email shifting focus from write behavior to memory access patterns. The NFS storage environment remains a key factor, but the specific interaction between Git's mmap usage and NFS performance characteristics emerges as a new area for investigation.
