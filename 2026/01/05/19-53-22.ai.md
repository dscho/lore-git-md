This is the final patch in a 6-part bugfix and test coverage series for `git replay` error handling, specifically addressing invalid commit-ish inputs. The series has been through multiple rounds of review with feedback from Junio Hamano, Phillip Wood, and Elijah Newren incorporated.

The patch adds comprehensive test coverage for various failure conditions in `git replay`, including:
- Mandatory `--onto` or `--advance` option requirement
- Error when attempting to replay from root commit
- Incompatibility between `--advance` and `--contained` options
- Ill-defined ordering when advancing with multiple sources
- Current lack of support for merge commits

The tests use the new test setup with additional commits (N, O, P) to exercise these edge cases. Each test verifies both the error condition and the exact error message output. Phillip Wood helped refine the test approach to properly capture return values and standardize the expected output format.

This completes the series' goal of robust error handling with clear diagnostics and comprehensive test coverage. All prior feedback has been addressed, and the series appears ready for merging. The changes focus on `t/t3650-replay-basics.sh`, building on earlier architectural improvements to `builtin/replay.c`.
