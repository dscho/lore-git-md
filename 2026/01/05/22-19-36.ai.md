This is a discussion about configuring Git for triangular workflows (where you pull from one remote and push to another). D. Ben Knoble responds to Harald Nordgren's query about their setup, providing a detailed configuration approach.

Knoble describes a personal workflow configuration that uses two remotes (typically "origin" for pulling and "benknoble" for pushing, though it works with a single remote too). The setup involves several global Git config settings: `push.default=current` to enable the `@{push}` ref, `pull.rebase=true`, and `branch.autoSetupRebase=always`. Per-repository, they set `remote.pushDefault` to their push remote.

The key benefit highlighted is the automatic setup of both `@{upstream}` (pointing to the pull remote) and `@{push}` (pointing to the push remote) when creating new branches with `git switch -c`. This provides clear tracking relationships without manual branch configuration. The approach is presented as a practical solution for developers who regularly work with multiple remotes, though it assumes comfort with rebase-based workflows.
