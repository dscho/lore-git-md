This is a bug report about unexpected behavior in `git diff --relative=<path>`. Harrison McCullough demonstrates that when using `--relative=foo`, Git strips the "foo" prefix from all matching paths, even when it's just part of a filename (like "foo.txt" becoming ".txt"), rather than restricting the output to files under the "foo/" directory as one might expect.

The report includes clear reproduction steps showing the discrepancy between expected behavior (only showing modified files under the specified directory) and actual behavior (stripping the prefix from any matching path component). Harrison suggests this might be better named `--strip-prefix` if the current behavior is intentional, and notes that adding a trailing slash (`--relative=foo/`) does produce the expected directory-relative output.

The issue appears to be a documentation/behavior mismatch - the man page implies directory-based filtering while the implementation does simple prefix stripping. Harrison proposes either fixing the behavior or clarifying the documentation to explicitly describe the current prefix-stripping approach. The bug is well-documented with specific examples and shows careful consideration of the interface's design intent.
