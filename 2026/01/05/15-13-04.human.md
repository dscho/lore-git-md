This is a follow-up discussion in the ongoing ref backend selection thread, where Patrick Steinhardt provides review feedback on Karthik Nayak's v3 patch series. The series implements configurable reference storage backends to support zero-downtime migrations between files and reftable formats.

Patrick notes that while the v3 patches have addressed several technical issues (code cleanup, string localization, and removing unnecessary checks), there remains an important gap in worktree reference handling. He argues that if the main reference store location is configurable, the worktree reference locations should logically follow the same configuration rather than remaining hardcoded. This would maintain consistency when the main ref store is relocated (e.g., to `/tmp/dir`).

The feedback suggests the series needs another iteration to properly integrate worktree reference stores with the new configuration mechanism. Patrick indicates this should be addressed before the semantics of the extension are finalized, as changing them later would be more difficult. The comment comes from an internal GitLab review, with the expectation that Karthik will incorporate this feedback in a v4 submission after the holiday period.
