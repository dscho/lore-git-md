This is the first of two patches in a series implementing push tracking display in `git status`. The patch refactors the branch comparison formatting logic in preparation for adding push tracking support.

The key change extracts the branch comparison message formatting into a new `format_branch_comparison()` function from `format_tracking_info()`, separating the message generation from the upstream tracking logic. The refactoring:

- Moves all message formatting cases (up-to-date, ahead, behind, diverged) into the new function
- Takes the comparison state (sti), counts (ours/theirs), and formatting flags as parameters
- Preserves all existing behavior including quick mode (`--no-ahead-behind`) and advice messages
- Maintains the same output strings and conditions
- The original function now handles just the upstream tracking resolution and "upstream gone" case
- Memory management remains unchanged with `base` still freed by the caller

This is a pure refactoring with no behavior changes, as confirmed by the extensive test coverage mentioned in the thread context. The separation of concerns will allow the second patch to reuse the comparison formatting for both upstream and push tracking branches while keeping the logic clean.

The patch has gone through 17 iterations with thorough review from Junio C Hamano and others, addressing all feedback around control flow, edge cases, and style. The extracted function will be used in the next patch to show divergence from both upstream and push tracking branches.
