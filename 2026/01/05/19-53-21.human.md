This is part 5 of a 6-patch bugfix series improving error handling in `git replay` when given invalid commit-ish arguments. The series has gone through multiple rounds of review with feedback from Junio Hamano, Phillip Wood, and Elijah Newren.

This particular patch switches from `parse_object()` to `parse_object_or_die()` when peeling commit-ish references, ensuring immediate failure with a descriptive error message if the object cannot be parsed. The change was suggested by Junio Hamano in a previous review round to simplify error handling at call sites.

The series as a whole has addressed all prior feedback and appears merge-ready, with comprehensive test coverage and polished error messages. This patch continues the theme of robust error handling by using the standard `*_or_die` pattern that provides better user feedback when things go wrong.
