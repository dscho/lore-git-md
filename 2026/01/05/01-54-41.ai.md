This is a documentation patch discussion about formatting consistency in man pages, specifically whether command-line options should be wrapped in backticks. The thread starter noticed inconsistencies between commands like `git-am` (which uses backticks for rerere options) and `git-prune`/`git-name-rev` (which don't). 

Junio C Hamano responds that the current trend is actually to *add* more backticks for proper AsciiDoc markup, not remove them, pointing to Jean-Noël Avila's ongoing synopsis-style conversion work as the reference implementation. He cites commit f7316a66 as an example of the preferred style, where even individual option descriptions get proper markup. 

This clarifies that while the original question was about removing backticks, the project's direction is actually toward more consistent and complete markup. The thread suggests contributors should study Avila's work when making similar documentation improvements, as it represents the current standard being applied across Git's man pages. The discussion is part of the broader documentation standardization effort but appears to be a distinct subtopic from the main synopsis-style conversion project.
