This is a bugfix discussion thread about the `git last-modified` command's behavior in bare repositories. Patrick Steinhardt confirms that the issue where `git last-modified` fails to find files in bare repos was fixed in commit 05491b90ce ("last-modified: support sparse checkouts", 2025-11-29) on Git's master branch. The original reporter, Gusted, had encountered the problem while trying to integrate the command with Forgejo.

The thread reveals two distinct issues with `git last-modified`:
1. A memory safety bug causing crashes when processing refspec format paths (HEAD:path)
2. Suboptimal error messaging when paths are missing (showing "unknown revision or path" even when `--` disambiguates the input as a path)

Patrick's response focuses on the bare repo case, confirming it works correctly in current master. The discussion has drawn in refspec expert Toon Claes and UX-focused contributor Kristoffer Haugsbakk to address the remaining issues. This appears to be part of ongoing work to improve the command's robustness and user experience.
