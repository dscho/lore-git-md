This is a bugfix and test coverage series for `git replay`'s error handling when given invalid commit-ish arguments. The v3 series from Kristoffer Haugsbakk builds on earlier work by Elijah Newren to improve error messages and validation logic.

The key improvements in this version:
- Renames a core function to the more accurate `set_up_replay_mode()` (addressing Junio Hamano's feedback)
- Improves commit messages and error wording (e.g. changing "replaying down to root commit" to "replaying down from root commit")
- Adds more regression tests for failure conditions
- Makes object parsing more robust by using `parse_object_or_die()`

The series maintains its focus on catching invalid inputs early with descriptive errors, while keeping root commit support as a future consideration (marked with FIXME comments). The changes are well-contained to `builtin/replay.c` and its test file `t/t3650-replay-basics.sh`.

All prior review feedback appears addressed, and the series looks ready for merging. The changes are clean, focused, and thoroughly tested - a solid incremental improvement to `git replay`'s error handling.
