This is a bug report and discussion about performance and behavior issues in the `git last-modified` command, which is part of an ongoing effort to optimize last-modified queries for multiple files. The thread involves Toon Claes (the command's author) responding to Gusted's findings from testing on a Forgejo repository.

Key points from this response:
1. Performance: Toon acknowledges the single-file performance regression (151ms vs 87ms for `git log`) but shows the command shines when querying multiple files (6x faster than equivalent `git log` pipeline). This aligns with its design purpose as a bulk query tool.

2. Directory handling: The current behavior returns the same commit for parent and child directories unless using `-r --max-depth=0`. Toon proposes changing the default to behave this way, seeking feedback on the approach.

3. Crash bug: Confirms the BUG() assertion when passing tree IDs directly is a real issue that needs fixing, thanking Gusted's report.

The discussion reveals design tradeoffs in the command's optimization strategy and surface area. Toon defends the multi-file performance while acknowledging room for improvement in edge cases and error handling. The thread shows active maintenance of this relatively new command, with the author receptive to real-world feedback about its behavior.
