This is the final version of a feature enhancement series that adds push remote tracking information to `git status` output. The 2-patch series by Harald Nordgren has gone through 17 iterations and is now ready for merging.

The first patch refactors the branch comparison formatting code in `remote.c` to prepare for the new functionality. It extracts `format_branch_comparison()` from `format_tracking_info()` while maintaining all existing behavior. The refactoring includes fixes for control flow issues identified by Junio C Hamano, ensuring quick mode (`--no-ahead-behind`) works correctly.

The second patch implements the core feature - showing comparison with the push remote tracking branch when it differs from the upstream branch. The implementation:
- Adds a new `get_remote_push_branch()` helper that resolves push tracking references through the full refspec resolution chain
- Extends `format_tracking_info()` to handle both upstream and push comparisons
- Only shows push comparison when it differs from upstream
- Maintains existing advice messages while adding push-specific advice when relevant

The series now includes comprehensive test coverage (262 lines of tests) that verifies:
- All edge cases (gone upstream, quick mode, diverged branches)
- Correct behavior with `--no-ahead-behind` option
- Various push/upstream divergence scenarios
- Custom refspec mappings

Key reviewers Junio C Hamano and Phillip Wood have approved the technical approach after addressing all concerns, including a critical control flow issue and refspec mapping solution. The implementation cleanly integrates with Git's existing branch tracking mechanisms and output conventions.

This represents the culmination of significant design iteration and review feedback, with all technical requirements now satisfied. The feature will help users better understand their local branch state relative to both upstream and push destinations.
