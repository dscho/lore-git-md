This is a bugfix patch series addressing a protocol violation in Git's upload-pack when the ref-in-want feature is enabled. The issue causes shallow clones to fail when both `uploadpack.allowRefInWant` is true and the client requests a shallow clone/fetch.

Patrick Steinhardt confirms the bug report from Matthew Dodd, noting that the protocol violation has existed since the ref-in-want feature was introduced in 2018. The core issue is that upload-pack sends wanted-refs before shallow-info, while the protocol specification (and fetch-pack implementation) expect the reverse order. This mismatch causes clients to fail with "fatal: expected 'packfile', received 'shallow-info'".

The fix itself is straightforward - swapping two lines in upload-pack.c to correct the section ordering. Patrick suggests combining the two patches (the fix and its test) into one, as the test directly verifies the fix's correctness. The test creates a shallow clone with ref-in-want enabled and verifies the remote ref points to the expected commit, guarding against regression of the protocol error.

This appears to be a well-justified bugfix with clear technical details and test coverage. The issue affects a specific combination of features (shallow clone + ref-in-want) that has been broken since 2018. Patrick's review confirms the technical correctness of both the diagnosis and solution.
