This is a documentation patch in the final v4 series improving the `git reset` man page. It's part of a collaborative effort between Julia Evans (who provided the pedagogical foundation), D. Ben Knoble (shepherding the series), and Junio Hamano (providing technical review).

The patch clarifies the introductory text of `git reset`'s documentation based on user feedback. It addresses several points of confusion by:
1. Replacing the vague "Reset current HEAD" description with "Set `HEAD` or the index to a known state"
2. Explicitly separating the two main use cases (changing commits vs updating staged files)
3. Avoiding obscure terms like "tree-ish" in the introduction
4. Adding concrete examples of when you'd use reset to undo operations

The changes are purely explanatory - no technical content is altered from the already-merged v3 version. This represents the final polish on a well-reviewed documentation improvement that has gone through four iterations to balance technical precision with accessibility.
