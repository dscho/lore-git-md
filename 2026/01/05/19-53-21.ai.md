This is the fifth patch in a v3 bugfix series improving `git replay`'s error handling when given invalid commit-ish arguments. The series has already incorporated feedback from Junio Hamano, Phillip Wood, and Elijah Newren, with all prior review comments addressed.

The current patch switches from `parse_object()` to `parse_object_or_die()` in the `peel_committish()` function, ensuring immediate failure with a descriptive error message if an object cannot be parsed. This change was suggested by Junio to simplify error handling by removing the need for explicit NULL checks at call sites. The implementation follows the established pattern of the series by failing fast with clear diagnostics when invalid input is encountered.

The patch is a straightforward mechanical change that builds on the series' architectural improvements, which have already consolidated error handling and removed dead code paths. Test coverage for this case was added in earlier patches of the series. With all technical feedback addressed and the change being a clear improvement to robustness, this appears ready for merging as part of the complete series.
