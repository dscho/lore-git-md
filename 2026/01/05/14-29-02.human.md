This is a review response in Patrick Steinhardt's series refactoring Git's object info handling. The patch in question (v2 2/7) proposes eliminating the OI_DBCACHED enum value, simplifying the interface by always reporting OI_PACKED for objects read from packfiles.

Toon Claes agrees with the change, noting that the distinction between OI_PACKED and OI_DBCACHED was an implementation detail that callers didn't meaningfully use. The patch had already explained that the three affected callers either benefit from the simplification or were arguably incorrect in their previous behavior.

The change is part of a larger effort to clean up object storage interfaces while improving performance - this particular patch doesn't introduce new functionality but removes a distinction that complicated the code without providing value. The series as a whole has received thorough review, with this being one of the simpler mechanical changes in the set.
