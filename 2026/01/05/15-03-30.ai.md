Bugfix for `git last-modified` command's handling of bare repositories and refspec paths.

Patrick Steinhardt responds to Gusted's bug report about two issues with the `git last-modified` command. First, he clarifies that the initial failure in a bare repository was due to a typo in the filename (LICENSE vs LICENSES) rather than a bare repo limitation. The more serious issue is a crash when using refspec syntax (HEAD:LICENSES), which triggers a BUG assertion in builtin/last-modified.c line 456, producing a core dump in both bare and non-bare repositories.

The response confirms the refspec case is a genuine bug and CCs Toon Claes, likely because he has expertise in this area of the codebase. The thread now has clear confirmation of a crash-worthy bug that needs fixing, with the path resolution issue in bare repos being a red herring due to user error. The BUG assertion suggests insufficient boundary checking during refspec path parsing, which could indicate memory safety concerns. This will likely require a patch to properly handle refspec input formats and add appropriate error checking.
