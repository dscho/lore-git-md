This is a discussion about Git workflow practices in the context of Harald Nordgren's patch series to enhance `git status` with push tracking information. D. Ben Knoble responds to Harald's concerns about restructuring commit history during development.

Knoble reassures Harald that Git's reflog preserves local history automatically, eliminating the need to manually maintain backup branches. His recommended workflow involves making changes normally, then using `range-diff` to review iterations before force-pushing updates - a method he has documented on his blog.

The exchange highlights differing perspectives on commit hygiene between GitHub's squash-centric model and Git's mailing list culture that values well-structured patch series. Knoble positions this as part of the broader thread where Harald has been iterating on his `git status` enhancement through 17 versions with extensive review feedback.
