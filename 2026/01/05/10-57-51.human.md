This is a bug report and discussion about performance and behavior issues in the `git last-modified` command. The original reporter, Gusted, found three problems: a performance regression where `git last-modified` is slower than equivalent `git log` commands for single files, inconsistent directory handling that returns the same commit for parent and child directories, and a crash when passing tree commit IDs directly.

Toon Claes, the command's author, acknowledges the issues. He explains that while the performance difference is expected for single files (since `git last-modified` is optimized for batch operations), the directory behavior and crash are genuine bugs. He proposes changing the default directory handling to be more intuitive and confirms he'll investigate the crash.

The thread shows a productive exchange between a user encountering real-world problems and a maintainer receptive to feedback. The performance characteristics and directory behavior appear to be design choices that may need reconsideration, while the crash is clearly unintended and will be fixed.
