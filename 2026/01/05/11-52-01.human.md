This is a bug report and discussion about the relatively new `git last-modified` command, focusing on three specific issues. The command's author Toon Claes is actively responding to feedback from Gusted about performance characteristics, directory handling behavior, and a crash condition.

For performance, Claes confirms the command is slower than `git log --max-count=1` for single files (151ms vs 87ms) but defends this as a design tradeoff - the command is optimized for bulk operations, showing a 6x speedup when querying multiple files. The directory handling currently returns identical commit hashes for parent and child directories, which Claes acknowledges is confusing and proposes changing the default to match `-r --max-depth=0` behavior (different commits for different levels). 

Gusted discovered a crash when passing a tree commit ID directly, which triggers a BUG() assertion rather than proper error handling. Claes confirms this is a legitimate bug that needs fixing. The thread shows active maintenance of this new command, with the author receptive to real-world feedback about both performance tradeoffs and behavioral quirks. Key open questions remain about the proposed directory behavior change and crash fix implementation.
