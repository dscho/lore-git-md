Son Luong Ngoc has proposed adding Bazel build support to Git, initially suggesting in-tree integration similar to the existing Meson build system. The initial implementation worked for Linux and ran most tests, but brian m. carlson raised significant objections about its hardcoded paths (SHELL_PATH, PERL_PATH, PYTHON_PATH) and platform assumptions that don't match Git's flexible build system standards.

In response to these concerns, the author has now shifted direction. They acknowledge that Bazel's toolchain system could theoretically handle these configuration needs properly, but their current implementation was tailored for a specific use case (building libgit for Go integration) rather than being general-purpose. Facing the maintenance burden of supporting another build system in-tree, they now plan to distribute the Bazel configuration through the Bazel Central Registry as an unofficial, community-maintained option. This represents a step back from the original proposal, though the technical discussion continues about how Bazel could potentially meet Git's requirements in the future. The core issues of configurability and platform support remain unresolved, with no concrete implementation yet addressing brian m. carlson's objections.
