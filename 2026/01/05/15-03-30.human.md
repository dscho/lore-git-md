This is a bug report response about issues with the `git last-modified` command in bare repositories. Patrick Steinhardt confirms that the command should work in bare repositories, pointing out that the initial error was due to a typo in the filename (LICENSE vs LICENSES). However, he acknowledges a more serious bug when using refspec syntax (HEAD:LICENSES), which triggers an assertion failure and crashes Git with a core dump. The crash occurs in builtin/last-modified.c line 456, indicating a boundary checking issue during path parsing.

Patrick's response suggests this is a legitimate bug (not just user error) and involves Toon Claes in the discussion, likely because Toon has worked on related ref backend and path handling code. The thread now has clear reproduction cases for both the bare repository path resolution issue and the refspec parsing crash, though no patch has been proposed yet. This appears to be an early-stage bug report that will likely lead to follow-up investigation and fixes.
