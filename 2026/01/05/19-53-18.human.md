This is part 2/6 of a bugfix series improving error handling in `git replay` when given invalid commit-ish arguments. The series was originally identified by Elijah Newren and is being led by Kristoffer Haugsbakk, with feedback incorporated from Junio Hamano, Phillip Wood, and Elijah Newren.

The current patch focuses on ensuring clear error messages when `--advance` is given a non-existent ref. It reorders the validation steps in `builtin/replay.c` to first check if the argument is a valid ref name (using `repo_dwim_ref`) before attempting to peel it as a commit-ish. This ensures users get the more specific "must be a reference" error rather than a generic commit-ish error when the ref doesn't exist. The change is accompanied by a new test case that verifies this error message behavior.

The patch follows Junio Hamano's suggestion from earlier discussion and maintains the series' focus on robust error handling. It's a straightforward change that improves the user experience when invalid arguments are provided, while the test ensures this behavior won't regress. The series as a whole appears to be in good shape, with all prior feedback addressed in this v3 iteration.
