This is a follow-up discussion about improving error messages in `git last-modified` when handling path resolution in bare repositories. The thread started with a bug report about crashes with refspec paths, but this particular email focuses on a different aspect - the quality of error messages.

Kristoffer Haugsbakk points out that when `git last-modified` fails to find a path in a bare repository (in this case due to a typo from LICENSE vs LICENSES), the error message is too generic. It shows the standard "unknown revision or path" message even though the `--` separator was used, which should indicate this is specifically a path resolution issue.

The suggestion is that the error message could be more precise when it knows the user is specifying a path (due to the `--` separator), saying "unknown path" rather than the more ambiguous "unknown revision or path". This would help users understand the nature of the problem more quickly.

This is a documentation/UX improvement suggestion rather than a bugfix, and it's noted as being a separate issue from the original refspec crash bug that was reported. The email is directed to Patrick Steinhardt (who confirmed the original bug) and Gusted (who reported it), suggesting this as a follow-up improvement once the more serious crash issue is addressed.
