The thread concerns a bug in the relatively new `git last-modified` command, where passing a refspec path (like HEAD:LICENSES) causes a crash with a BUG assertion in builtin/last-modified.c. Initial confusion about bare repository behavior was resolved when Patrick Steinhardt identified it as a user typo (LICENSE vs LICENSES), leaving the refspec crash as the confirmed issue.

The crash occurs universally across repository types during refspec parsing, suggesting a memory safety or input validation problem rather than a working tree assumption. Toon Claes, known for refspec expertise, has been brought in to help diagnose and fix the issue. While no patch has been submitted yet, the discussion has narrowed the problem to the command's handling of HEAD:path syntax, which will likely require changes to the parsing logic in builtin/last-modified.c. The thread remains open while awaiting technical analysis from the refspec specialists.
