This thread reports issues with the `git last-modified` command's behavior in bare repositories. Gusted, who is working on integrating this feature into Forgejo, found two problems: 

First, the command fails when given a file path in a bare repository, incorrectly assuming a working tree exists even when the `--` separator is used correctly. More seriously, when given a refspec (like HEAD:LICENSES) instead of a plain path, the command crashes with a "BUG" message, indicating an assertion failure in the parsing logic (line 456 of builtin/last-modified.c). This crash occurs in both bare and non-bare repositories, suggesting a fundamental issue with how the command handles refspec inputs.

The report provides clear reproduction steps but no proposed fix, so this open for investigation by someone familiar with the command's implementation. Given that Gusted is working on real-world integration with Forgejo, these issues likely affect actual deployments.
