This thread addresses two distinct but related issues with the `git last-modified` command. The original report from Gusted identified both a crash when using refspec paths (like HEAD:path format) and confusing error messages when paths are missing. 

Patrick Steinhardt has confirmed the refspec crash was a genuine memory safety bug, now fixed in commit 05491b90ce ("last-modified: support sparse checkouts"). Users experiencing this issue should update to the latest master branch. The second issue - where Git shows "unknown revision or path" even when `--` clearly indicates a missing path - remains open for discussion. Kristoffer Haugsbakk had flagged this as a UX problem worth addressing separately.

Toon Claes, an expert on refspec handling, has been brought into the conversation to help with the now-fixed crash issue, while the error message improvement may become its own follow-up work. The thread shows how one bug report can surface both technical and usability concerns, with the community addressing each appropriately.
