This is a documentation patch follow-up in an ongoing thread about man page formatting standards. Jean-Noël Avila, who is leading the project-wide effort to convert all Git man pages to a consistent "synopsis-style" format using AsciiDoc markup, responds to clarify the conversion process.

The email confirms that the standard is to use backticks for inline code (like `--option`) in the new format, as seen in already-converted pages like `git-commit` and `git-add`. Avila notes the conversion is proceeding in the order pages appear on git-scm.com and invites others to help, though warns the process isn't yet fully formalized - contributors may need a few iterations to get the style right.

This provides useful context for anyone wanting to contribute documentation patches, directing them to study the converted pages as examples and coordinate with Avila to avoid duplicated work. The response reinforces Junio's earlier guidance in the thread about standardizing on the more-fully-marked-up style.
