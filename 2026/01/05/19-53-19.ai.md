This is the third patch in a 6-part bugfix and test coverage series for `git replay` error handling, now in its third iteration. The series addresses how `git replay` handles invalid commit-ish arguments, with this patch specifically focusing on improving error messages when an invalid commit-ish is given to `--onto`.

The patch modifies `peel_committish()` to die immediately with a descriptive error message when an invalid commit-ish is provided, rather than returning NULL and letting the error propagate. The error message now includes both the invalid input and which option (`--onto` or `--advance`) it was provided to. This provides clearer feedback when users accidentally pass invalid arguments or forget to provide a required argument.

Key technical details:
- Adds a `mode` parameter to `peel_committish()` to provide context for error messages
- Updates call sites in `set_up_replay_mode()` to pass the appropriate mode
- Removes the old "replaying down to root commit" error path since NULL is no longer returned
- Adds a test case verifying the new error message format
- Maintains the same functionality while improving user experience

The patch follows Junio Hamano's earlier suggestion to provide better context in error messages, and addresses all feedback from the v2 review. The series as a whole appears to be in good shape, with this patch representing one of the core improvements to error handling in the command.
