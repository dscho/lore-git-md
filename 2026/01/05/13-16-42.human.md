This is the second patch in Patrick Steinhardt's series to fix geometric repacking with promisor remotes, part of his ongoing repack machinery overhaul. The patch is a refactoring that extracts the core logic for computing repacking splits into a separate function.

The change moves the geometric progression calculation from `pack_geometry_split()` into a new static function `compute_pack_geometry_split()`. This prepares for future addition of promisor pack handling by making the split computation reusable. The actual behavior remains unchanged - this is purely structural preparation.

The refactoring is clean and mechanical, with the new function taking the pack array, count, and split factor as parameters rather than accessing them through the geometry struct. This makes the computation more self-contained and easier to test independently. The patch maintains all existing error checking for overflow conditions when calculating pack sizes.

As part of a larger series, this patch builds on the foundation laid in the first patch (which modified pack-objects.c) and will be followed by changes to handle promisor packs specifically. The commit message clearly states the motivation - enabling reuse of this logic by a second caller that will be introduced later in the series.
