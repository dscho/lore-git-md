This is a proposal for adding Bazel build support to Git, similar to the existing Meson build system. The author, Son Luong Ngoc, has already implemented a working Bazel configuration in their personal fork but is seeking co-maintainers before considering upstream integration.

The current implementation is described as a "giant commit" that adds BUILD files throughout the repository, making it fairly invasive. While it currently only supports Linux, the author notes it can already run most unit and integration tests. They're willing to maintain the configuration for major releases but not for every upstream topic.

The proposal presents two paths forward: either finding co-maintainers to support in-tree maintenance, or publishing the configuration to the Bazel Central Registry as an overlay that would be applied post-checkout. The author is clearly signaling they don't have capacity to single-handedly maintain this as a first-class build system in Git's main repository.

This touches on Git's ongoing build system modernization, which has seen Meson added alongside the traditional Makefile. The proposal is at an early stage - the implementation exists but needs polish and broader platform support. The key question for the community members will be whether there's sufficient interest and maintenance capacity to justify adding another build system to the core repository.
