This thread discusses configuring Git for triangular workflows (pull from one remote, push to another), initiated by Harald Nordgren's query. D. Key technical details include:

- Per-repo: `remote.pushDefault` set to push remote
- Automatic setup of both `@{upstream}` (pull) and `@{push}` (push) tracking when using `git switch -c`
- Workflow commands: `git pull` (rebases), `pf` alias (force-push with lease), `rdup` (range-diffs between upstream/push refs), `git sbup`/`git div` (branch visualization)
- Dotfiles reference provided for implementation

The solution assumes rebase-based workflows and handles PR-style review well, though notes limitations with Git's own repository structure where topic branch merges complicate divergence visualization. The approach provides clear tracking without manual per-branch configuration while maintaining separation between pull and push remotes.
