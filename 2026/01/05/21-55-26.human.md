This is a discussion about Git workflow practices, specifically around maintaining clean commit histories while iterating on patches. D. Ben Knoble responds to Harald Nordgren's concerns about restructuring patch series history, offering reassurance and practical advice.

Knoble explains that Git's reflog provides built-in protection against losing work, so there's no need to maintain separate backup branches out of fear. He gently discourages "fear-driven development" as counterproductive. Regarding Nordgren's mention of GitHub's "squash and merge" approach at work, Knoble acknowledges others have already commented on this but shares his personal workflow for maintaining clean history while iterating: making changes and using `git range-diff` with force-pushes to update branches.

The exchange is part of the broader thread about Nordgren's `git status` enhancement series, where Knoble had previously suggested using Git's existing branch tracking mechanisms. Here he shifts focus to the process side, offering guidance that aligns with Git's mailing list conventions of iterative refinement with clean patch series.
