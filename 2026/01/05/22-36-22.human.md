This is a follow-up email in the thread about configuring Git workflows for triangular workflows (pull from one remote, push to another). D. Ben Knoble shares his personal configuration approach in detail, building on his earlier response to Harald Nordgren.

Knoble describes a comprehensive setup that uses two remotes (typically "origin" for pulling and a personal remote like "benknoble" for pushing). The configuration involves both global Git settings (`push.default=current`, `pull.rebase=true`, `branch.autoSetupRebase=always`) and per-repo settings (`remote.pushDefault`). The key benefit is automatic setup of both upstream (`@{upstream}`) and push (`@{push}`) tracking when creating branches with `git switch -c`.

The email then dives into Knoble's workflow practices, including aliases for common operations like `git sbup` (show-branch comparison) and `git div` (divergence visualization). He notes this setup allows him to use simple commands like `git pull` and `git push` without arguments while maintaining clear separation between pull and push remotes. The approach assumes comfort with rebase workflows and includes some custom tooling for visualizing branch relationships.

Knoble acknowledges one limitation - his divergence visualization tool can become noisy in repositories with many topic branch merges (like git.git itself). He invites suggestions for improvements to handle such cases better. The email provides links to his blog and dotfiles for reference implementations of his custom tooling.
