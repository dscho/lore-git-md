This is a discussion about configuring Git for triangular workflows (where you pull from one remote and push to another). D. Ben Knoble shares his personal setup in response to Harald Nordgren's query about branch configuration.

Knoble describes a configuration that uses two remotes (typically "origin" for pulling and a personal remote like "benknoble" for pushing). His global Git settings include `push.default=current`, `pull.rebase=true`, and `branch.autoSetupRebase=always` to streamline the workflow. He then sets `remote.pushDefault` to his personal remote at the repository level.

The key benefit of this setup is that it automatically configures both `@{upstream}` (for pulling) and `@{push}` (for pushing) references when creating new branches. Knoble notes this works even with a single remote, though the push target would just be the same as the pull remote in that case.
