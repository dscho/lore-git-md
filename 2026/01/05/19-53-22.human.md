This is the final patch in a 6-part bugfix and test coverage series for `git replay` error handling, specifically addressing invalid commit-ish inputs. The series has gone through multiple rounds of review from Junio Hamano, Phillip Wood, and Elijah Newren, with all feedback incorporated in this v3.

The patch adds comprehensive test coverage for various failure conditions in `git replay`, including:
- Mandatory `--onto` or `--advance` options
- Invalid base/negative ref cases
- Conflicting `--advance` and `--contained` options
- Ill-defined ordering when advancing with multiple sources
- Unsupported merge commit replaying

The tests are straightforward and focused on error conditions, using the established pattern of comparing actual output against expected error messages. Phillip Wood helped improve the test for mandatory options by avoiding pipe-related issues and normalizing the expectation format.

This completes the series' goal of robust error handling with clear messaging and thorough test coverage.
