Proposal to add Bazel build support to Git, initially as an out-of-tree option via Bazel Central Registry after technical objections to in-tree inclusion. Author Son Luong Ngoc acknowledges brian m. carlson's concerns about the current implementation's limitations - hardcoded paths (SHELL_PATH, PERL_PATH, PYTHON_PATH) and platform assumptions that don't match Git's build system flexibility. The email clarifies these would normally be handled through Bazel toolchain definitions (referencing existing rules for shell/Python/Perl) but concedes the current work is specialized for libgit/Go integration rather than general-purpose. The scaled-back approach reflects maintenance burden realities for Git's fourth build system alongside Make, Meson, and contrib/CMake. Core technical questions remain open about whether Bazel's toolchain system could meet Git's configurability requirements, though no implementation addressing this is yet proposed. brian m. carlson's objections establish the technical bar for any future in-tree proposal, while the current path focuses on unofficial registry distribution with clear labeling. The discussion surfaces tension between Bazel's opinionated toolchain model and Git's platform-flexible build philosophy.
