Proposal to add Bazel build support to Git, similar to existing Meson integration. Author Son Luong Ngoc has implemented a working but invasive Bazel configuration in their fork, adding BUILD files throughout the repository. Current implementation supports Linux and runs most unit/integration tests but faces significant technical objections from brian m. carlson regarding loss of configurability (hardcoded SHELL_PATH, PERL_PATH, PYTHON_PATH) and platform-specific assumptions (strlcpy availability). Two distribution paths remain under discussion: 1) in-tree maintenance requiring co-maintainers to address flexibility concerns, or 2) Bazel Central Registry publication as post-checkout overlay. Core open questions now include whether configurability gaps can be resolved to match Git's existing build system standards, and if community maintenance capacity exists for a fourth build system alongside Make, Meson, and contrib/CMake. The implementation requires both technical polish (path handling, platform defines) and broader platform coverage before either upstream or registry distribution would be viable. brian m. carlson's objections establish a clear technical bar for any future proposal.
