This is a bugfix and test coverage series for `git replay` error handling, now in its third version. The series addresses confusing error messages when invalid commit-ish arguments are given to `--onto` or `--advance` options, originally identified by Elijah Newren. Kristoffer Haugsbakk has taken over the series, incorporating feedback from Junio Hamano, Phillip Wood, and Elijah Newren.

The 6-patch v3 series makes several improvements:
1. Removes dead code and renames a function to set_up_replay_mode() (final naming settled after Junio's feedback)
2. Restructures `--advance` validation to check ref names before peeling commits
3. Improves error messages to die immediately with mode-specific errors when invalid commit-ish is given
4. Adds a new patch to improve code comments and die messages (responding to Elijah's feedback)
5. Makes object parsing more robust by using parse_object_or_die()
6. Expands test coverage for all error paths

Key technical changes focus on `builtin/replay.c` and `t/t3650-replay-basics.sh`, with the series now handling root commit messaging more clearly (using "replaying from root commit" instead of "replaying down to root commit"). The implementation maintains parallel validation flows for `--onto` vs `--advance` while removing unnecessary NULL handling code paths.

All review feedback appears addressed in this version, with only minor wording refinements remaining regarding root commit messages. The series looks ready for merging with comprehensive test coverage and clean architectural improvements to error handling.
