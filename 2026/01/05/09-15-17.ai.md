This is a follow-up in the ongoing thread about enhancing `git status` to show divergence from both upstream and push tracking branches. The discussion focuses on a regression in the refactoring patch where the control flow for reporting branch status was incorrectly reordered, causing false divergence reports in quick mode.

Harald Nordgren acknowledges Junio C Hamano's observation that the refactoring accidentally reversed the order of checks in `format_branch_comparison()`. The original version first checked if there were no divergence (`!sti`) before handling quick mode case, while the refactored version checks quick mode first. This causes the function to incorrectly claim divergence exists even when branches are actually in sync.

Nordgren agrees to revert this change and restore the `sti` parameter to maintain the correct control flow, despite earlier efforts to eliminate it. This addresses the last remaining issue in the refactoring patch before the series can be merged. The exchange demonstrates the careful attention to behavior preservation required in Git's core code, even during seemingly mechanical refactoring.
