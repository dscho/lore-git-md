Test modernization follow-up in post-checkout hook tests. This is a response to Junio C Hamano's suggestion to enhance the test coverage beyond just checking file existence.

Deveshi Dwivedi proposes extending their earlier patch (which modernized the test by replacing `test -f` with `test_path_is_file`) to also validate the contents of the post-checkout hook's argument file. The test currently only checks that the hook creates an arguments file during clone, but doesn't verify what's in it.

The proposed enhancement would make this test consistent with others in t5403 by:
1. Reading the three arguments passed to the hook (old ref, new ref, and flag)
2. Verifying the old ref is the null OID (test_oid zero)
3. Checking the new ref matches HEAD
4. Confirming the flag is set to 1 for clone operations

This follows the pattern seen in other tests in the same file and aligns with the documented behavior in githooks.adoc. The change would provide more thorough validation of the hook's behavior while maintaining the test modernization benefits of using the test_path_is_file helper.
