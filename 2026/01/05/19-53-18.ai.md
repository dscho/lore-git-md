This is the second patch in a 6-part bugfix and test coverage series for `git replay` error handling, now in its third iteration. The series addresses how `git replay` handles invalid commit-ish inputs, with this particular patch focusing on improving the order of validation checks when using `--advance`.

The patch moves the ref existence check before the commit peeling operation when processing `--advance` arguments. This ensures users get a clear "must be a reference" error when the input isn't a valid ref, rather than a more obscure commit-ish error that would occur during peeling. The change follows Junio Hamano's suggestion to maintain better error messaging hierarchy.

A new regression test verifies this behavior by attempting to use a raw object ID with `--advance` and confirming the expected reference validation error appears. The test protects against future changes that might accidentally reorder these checks.

This is a straightforward improvement that makes error messages more user-friendly while maintaining all existing functionality. The patch builds on the series' foundation of strengthening `git replay`'s error handling, with all prior feedback from Junio, Phillip Wood, and Elijah Newren incorporated in this v3 iteration.
