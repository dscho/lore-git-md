This is a review response in Patrick Steinhardt's object info refactoring series, specifically addressing patch 2/7 which simplifies the object info interface by removing the OI_DBCACHED distinction. Toon Claes agrees with the change to always report OI_PACKED for packfile objects, noting that the delta base cache distinction was an implementation detail that callers didn't need to know about.

The patch eliminates the OI_DBCACHED enum entirely, as the three callers that check the whence field either benefit from or are unaffected by treating cached objects the same as regular packed objects. The key points are that this provides more consistent information to callers (particularly around promisor pack checks) and simplifies the interface without losing meaningful functionality. Toon's review confirms the technical soundness of this change, which is part of a larger effort to improve Git's object storage layer.
