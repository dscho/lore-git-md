This is a review comment on patch 3/7 of Patrick Steinhardt's series refactoring object info handling. Toon Claes raises a question about the need to distinguish between offset deltas and reference deltas in the new `is_delta` enum, while generally agreeing with the introduction of an "unknown" state.

The patch introduces a 4-state enum (unknown/full/ref-delta/ofs-delta) to replace a simple boolean, allowing callers to distinguish between different delta types when the information is available. Toon notes that while the "unknown" state makes sense (for cases where we skip parsing the actual object), he's unclear why the distinction between ref-delta and ofs-delta is necessary at this interface level.

The thread context shows this is part of a larger effort to clean up object info handling, with performance improvements (9% speedup for size-only queries) and interface simplifications. Toon had previously approved patch 2/7's removal of the OI_DBCACHED flag, and this review continues his careful scrutiny of the interface changes. His question about delta type distinction doesn't appear to block progress - he frames it as informational for other readers rather than a blocking concern.
