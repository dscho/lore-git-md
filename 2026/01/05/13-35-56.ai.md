This is a bug report about the `git last-modified` command's behavior on bare repositories. The contributor Gusted, who appears to be working on integrating this feature into Forgejo (a Git hosting platform), reports two issues:

1. The command fails on bare repositories when given a file path, with an error suggesting it can't resolve the path (despite the `--` separator being used correctly). This implies the command may incorrectly assume a working tree is present.

2. When given a refspec (HEAD:LICENSES) instead of a plain path, the command hits an assertion failure and crashes with a "BUG" message, dumping core. This occurs on both bare and non-bare repositories, indicating a more fundamental parsing issue.

The report suggests `git last-modified` may have incomplete handling of bare repository use cases and potentially unsafe path parsing logic. The crash in particular warrants investigation as it could indicate memory corruption or an unhandled edge case in the boundary checking code (as referenced by the BUG message pointing to line 456 in builtin/last-modified.c).

No patch is included - this is purely an issue report that would need follow-up from someone familiar with the last-modified command's implementation. The reporter is clearly working on real-world integration (Forgejo) and has identified concrete reproduction steps.
