This is a documentation-focused whitespace checking feature, part of an ongoing effort to improve Git's documentation quality. Adrian Ratiu is implementing a new `tab-between-non-ws` whitespace rule that detects when tabs appear between non-whitespace characters in AsciiDoc documentation files, as these can indicate formatting errors.

The feature was suggested by Junio Hamano to catch documentation typos where tabs are accidentally used instead of spaces in running text. The implementation carefully avoids false positives by only flagging tabs that would expand to a single space (not those at tab stops). Adrian reports that after Junio's review, he's now completed the remaining work on colored output highlighting and whitespace fixing functionality, and will soon send an updated patch series.

The change is well-motivated and appears to be nearing completion, with comprehensive test coverage already in place. This should help maintain consistency in Git's documentation formatting.
