This is a follow-up discussion about error messaging in the `git last-modified` command, which was recently found to crash when handling refspec paths (HEAD:path format). The thread started with a bug report about behavior in bare repositories, which Patrick Steinhardt identified as a user error (typo in filename), but also confirmed a separate memory safety issue in refspec parsing.

Kristoffer Haugsbakk points out that the error message for missing files is overly generic - it says "unknown revision or path" even when the user has already used `--` to indicate they're specifying a path, not a revision. He suggests the message could be more specific ("unknown path") in this case to avoid confusion. This is presented as a separate issue from the refspec crash that Toon Claes is being consulted about.

The observation is relevant to user experience but doesn't directly address the core memory safety bug. It's a small documentation/UX suggestion that could be addressed independently of the more serious refspec parsing issue. The comment maintains the thread's technical focus while identifying an orthogonal improvement opportunity.
