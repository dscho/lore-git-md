This is a bugfix patch in a series improving error handling for `git replay` when given invalid commit-ish arguments. It's the third patch in a six-part v3 series led by Kristoffer Haugsbakk, with feedback incorporated from Junio Hamano, Phillip Wood, and Elijah Newren.

The patch changes `git replay` to fail immediately with a descriptive error when an invalid commit-ish is given to `--onto`, rather than propagating a NULL value and failing later with a confusing message about root commits. The new error clearly indicates when an argument isn't a valid commit-ish and which option it was given to. The change includes a test verifying the improved error message.

The series has gone through multiple rounds of review, with this version addressing Junio's feedback about error message context and Elijah's comments about root commit handling. The implementation touches `builtin/replay.c` and adds test coverage in `t/t3650-replay-basics.sh`. With all reviewer feedback addressed in v3, the series appears ready for merging.
