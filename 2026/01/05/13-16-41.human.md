Performance patch from Patrick Steinhardt addressing an incompatibility between geometric repacking and promisor remotes. This is the first of five patches in a series that aims to enable geometric repacking (a space-efficient way to combine packfiles) to work with promisor packs (partial clones where some objects are stored remotely).

The core change modifies `pack-objects.c` to allow combining `--stdin-packs` (which specifies exactly which packs to repack) with `--exclude-promisor-objects` (which avoids packing objects that are stored remotely). The patch handles two cases: when explicitly given promisor packs (which now fails with a clear error) and when following object references from non-promisor packs (which now properly excludes promisor objects). The change comes with new tests in `t5331` that verify the behavior.

This is a technical but important change that enables future work on geometric repacking with partial clones. The patch is well-structured with clear commit message explanations and thorough test coverage. As the first in a series from a key contributor to Git's repack machinery, it's worth attention from anyone working on or using large repository optimizations.
