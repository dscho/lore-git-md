This is a platform compatibility patch addressing a bug in macOS's iconv implementation that causes incorrect character encoding conversions, specifically affecting ISO-2022-JP to UTF-8 conversion in Git test suite. The patch comes from Torsten Bögershausen with input from René Scharfe.

The issue manifests when Git's `reencode_string_iconv()` function tries to convert text in chunks when the output buffer is too small. The macOS 14/15 iconv implementation fails to maintain proper state between these chunked conversions, corrupting the output. The patch introduces a workaround that, when enabled via `ICONV_RESTART_RESET`, resets the conversion state and starts over with a larger buffer rather than continuing from where it left off.

The change is contained to `utf8.c` and adds about 13 lines of conditional code. While the immediate motivation is fixing test failures (t3900 tests 17, 25, and 38), the underlying issue could affect any Git operation that needs to convert between these encodings on affected macOS versions. The patch notes that alternative solutions exist (linking against third-party iconv implementations from Fink/MacPorts/Homebrew), but this provides a built-in fallback.

The implementation is straightforward - when buffer expansion is needed, it resets the conversion state and retries from the beginning with the new buffer size. This appears to be a well-contained fix for a specific platform quirk, though the next patch in the series will presumably add the makefile knob to control the workaround.
