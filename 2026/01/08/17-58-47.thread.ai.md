Reftable performance optimization proposal for object-to-ref lookups. Tsahi Elkayam identifies inefficiency in `indexed_table_ref_iter` where it scans entire ref blocks rather than properly leveraging the reftable index structure. Current implementation reads object records containing ref block offsets, then scans and filters blocks via OID comparison. Proposed approach would seek to first matching object record, read only relevant ref blocks, properly yield matching refs, and maintain iterator state. Targets reftable subsystem (`reftable/refs.c`), maintaining on-disk format while improving lookup performance. Seeks feedback on architectural approach before implementation. Reftable development primarily driven by Patrick Steinhardt and Karthik Nayak. Open question: whether proposed stateful iterator approach is the right direction for optimizing this lookup path.
