This is a bugfix for the HTTP backend that addresses a logging issue when error messages are concatenated without newlines. The patch modifies `http-backend.c` to ensure error messages written to stderr by the `not_found` and `forbidden` functions are properly terminated with newlines.

The problem occurs when git-http-backend is invoked through wrappers like fcgiwrap, where multiple error messages can get merged into a single line in logging systems (e.g. journald). The author argues this formatting should belong to git-http-backend rather than being handled by the wrapper.

The change is straightforward - it wraps the existing `vfprintf` calls in both functions with a conditional check and adds explicit `fprintf(stderr, "\n")` calls. The patch maintains the same error handling behavior while fixing the output formatting. This appears to be a well-scoped, clearly motivated fix for a real-world logging issue.
