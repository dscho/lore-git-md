This is a performance optimization proposal for the reftable backend's object-to-ref lookup functionality. The email identifies an inefficiency in how `indexed_table_ref_iter` handles object-to-reference lookups, where it currently reads entire ref blocks and manually filters records rather than properly leveraging the index structure.

The current implementation reads one object record containing ref block offsets, then inefficiently scans entire ref blocks and filters records by OID comparison. Tsahi Elkayam proposes a more targeted approach that would:
1. Seek to the first matching object record
2. For each matching object record, read only the relevant ref blocks
3. Properly yield refs matching the target OID
4. Advance through object records as needed

The key insight is that the iterator should maintain the object iterator state rather than just processing a static list of offsets. This would better utilize the reftable index structure and avoid unnecessary block reads. The email is framed as an RFC seeking feedback on whether this is the correct architectural approach before implementing it.

This touches the reftable subsystem, which has been an active area of development led primarily by Patrick Steinhardt and Karthik Nayak. The proposed change would affect the low-level iteration logic in `reftable/refs.c` and would need to maintain compatibility with the existing reftable on-disk format while improving lookup performance.
