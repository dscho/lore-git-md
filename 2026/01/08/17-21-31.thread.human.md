This thread discusses a proposal to add `--config` support to `git init`, mirroring the existing `git clone --config` functionality. The original author, David Miguel Susano Pinto, presented a use case for setting different default email addresses when initializing work versus personal repositories. Currently, using `git -c` doesn't persist the configuration, and the workaround involves repository templates.

brian m. carlson has now responded with a detailed analysis of why this might not be strictly necessary. They explain that most repository initialization doesn't require early configuration, and suggest three alternative approaches: a shell alias combining `git init` and `git config`, a custom script with proper argument parsing, or leveraging Git's `includeIf` mechanism to automatically apply different configurations based on repository location. The `includeIf` solution is highlighted as particularly elegant for the email use case.

While the response doesn't outright reject the feature request, it presents multiple existing solutions that may satisfy the need without modifying `git init`. The discussion now awaits either a response from the original author addressing these alternatives, or other participants weighing in on whether the proposed feature would still provide value beyond these workarounds.
