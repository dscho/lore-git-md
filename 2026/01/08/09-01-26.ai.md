This is a documentation patch in its final iteration, with Johannes Sixt providing the last round of review feedback on Adrian Ratiu's whitespace checking feature for documentation files. The patch series introduces a new check that detects when tabs appear between non-whitespace characters in documentation (particularly .adoc files) where a space was likely intended, while preserving legitimate tab usage for indentation and alignment.

Johannes Sixt raises some thoughtful concerns about the practical utility of this check, noting that while he has occasionally missed tabs that should have been spaces, such occurrences are rare compared to other whitespace issues. He questions whether applying this check to all documentation files is appropriate, pointing out that in tables where tabs are used for column alignment, a tab at the 8th position would be flagged even when intentionally used for formatting. This could create false positive warnings where tabs are deliberately used for visual alignment rather than as mistaken spaces.

The discussion appears to be wrapping up, with all technical aspects already addressed in previous iterations. Johannes Sixt's comments here seem to be more philosophical in nature, questioning whether the feature's benefits outweigh its potential to flag legitimate tab usage in certain formatting contexts. This final exchange may help inform future decisions about where to enable this check via .gitattributes, even though the implementation itself is technically sound and ready for merging.
