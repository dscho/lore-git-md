This is a discussion about extending `git init` to support persistent configuration settings via a `--config` option, similar to what `git clone` already offers. The thread was started by David Miguel Susano Pinto, who wants an easier way to set different default user.email values for work vs personal repositories during initialization.

brian m. carlson responds with technical context about why `git clone --config` exists (to set config before operations like index creation) and why `git -c` doesn't work for this case (it only affects the current command). They explain that `git init` doesn't need this as urgently since it doesn't perform as many operations during initialization.

The response offers several workarounds: a shell alias that runs `git init` followed by `git config`, a custom shell script using `git rev-parse --parseopt`, and the `includeIf` config feature to automatically apply different configs based on repository location. The tone is helpful and technical, though it doesn't directly address whether the feature request itself is worth implementing.

This appears to be an early-stage discussion - the original feature request is clear but hasn't yet attracted broader discussion or implementation suggestions beyond workarounds.
