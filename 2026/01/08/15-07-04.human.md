Feature improvement to `git add -p`'s interactive interface. This patch enhances the hunk selection UI by showing whether each hunk was previously marked for inclusion (y) or skipping (n) when navigating between hunks. The change was requested by Junio C Hamano to improve clarity during interactive staging/unstaging operations.

The patch modifies the prompt strings in all patch modes (stage, stash, reset, checkout) to append "(was: y)" or "(was: n)" when a hunk has been previously decided. The implementation adds this state tracking while maintaining the existing prompt structure and test coverage.

This is the seventh iteration of the patch, with refinements to prompt formatting and code cleanup based on review feedback. The changes are focused and well-contained, touching only the prompt display logic in `add-patch.c` and updating corresponding test expectations. The patch appears ready for consideration, with thorough test coverage demonstrating the new behavior.
