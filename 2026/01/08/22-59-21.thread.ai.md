This thread addresses a logging formatting issue in git-http-backend where error messages from the `not_found` and `forbidden` functions could be concatenated without newlines when run through wrappers like fcgiwrap. The patch modifies `http-backend.c` to ensure proper newline termination of error messages written to stderr, arguing this formatting responsibility belongs in git-http-backend rather than wrapper scripts. The change wraps existing `vfprintf` calls with conditionals and adds explicit newline output, maintaining the same error handling while fixing log readability.

Junio Hamano agrees with the patch's core premise and suggests optimizing the newline output by using `putc('\n', stderr)` instead of `fprintf(stderr, "\n")` to avoid format string parsing overhead. The discussion confirms this is a legitimate issue affecting real-world deployments (particularly with journald logging) and that the proposed approach is architecturally sound. The patch remains narrowly focused on the two NORETURN functions in http-backend.c, with no changes to the actual error handling logic or HTTP response behavior. Junio's feedback indicates this is ready for acceptance with the suggested optimization.
