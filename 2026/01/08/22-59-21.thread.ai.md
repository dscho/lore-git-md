Thread summary:

This thread addresses a logging formatting issue in git-http-backend where error messages from the `not_found` and `forbidden` functions could be concatenated without newlines when run through wrappers like fcgiwrap. The patch modifies `http-backend.c` to ensure proper newline termination of error messages written to stderr, arguing this formatting responsibility belongs in git-http-backend rather than wrapper scripts. The change wraps existing `vfprintf` calls with conditionals and adds explicit newline output, maintaining the same error handling while fixing log readability. The fix is narrowly scoped to the HTTP backend functions and addresses a real-world issue observed with journald logging systems.
