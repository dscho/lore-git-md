This is a feature request for `git init` to support the `--config` option, similar to what `git clone` already offers. The author, David Miguel Susano Pinto, describes their use case of wanting to set different default user.email values for work versus personal repositories. They currently work around this limitation by using repository templates but would prefer a more direct solution.

The key technical detail is that while `git -c 'user.email=...' init` might seem like it should work, it doesn't actually apply the configuration to the new repository - the author suspects this is because `git init` only honors certain configuration options mentioned in its documentation. The request is straightforward and well-motivated by a clear workflow need, though the implementation might require careful consideration of how configuration options are processed during repository initialization.

This would be a small but useful quality-of-life improvement for users who maintain separate identities across different projects. The change would align `git init`'s functionality with `git clone`, creating more consistency in the command-line interface. The author's workaround using templates shows they've investigated existing solutions before proposing this enhancement.
