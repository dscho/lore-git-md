This is a bugfix patch that finalizes the implementation of PID files for Git lock debugging, addressing Junio Hamano's review comments on the previous version. The patch adds PID files alongside lockfiles to help diagnose stale locks, with the format "foo~pid.lock" for a lockfile "foo.lock".

The key changes in this version are:
1) Simplified configuration to a boolean `core.lockfilePid` (true/false) instead of per-component settings, as suggested by Jeff King and Patrick Steinhardt
2) Fixed error handling to properly clean up PID files on write failures
3) Clarified documentation about the file format ("pid <value>" line)
4) Added Windows support via mingw_kill() updates
5) Maintained backward compatibility - existing PID files are read even when the feature is disabled

The implementation creates PID files when locks are acquired (if enabled) and automatically cleans them up when locks are released. When lock conflicts occur, Git checks for PID files and uses kill(pid, 0) to determine if the holding process is still running, providing more informative error messages. The tilde separator in filenames avoids refname collisions.

Junio's review notes some remaining concerns about the error message wording (suggesting "remove lock file" may be too casual) and potential PID reuse cases, but the core implementation appears solid with comprehensive test coverage (139 lines across 7 test cases). The patch is well-structured and addresses all previous feedback, making it likely ready for merging.
