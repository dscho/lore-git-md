This thread addresses macOS iconv compatibility issues, specifically targeting potential bugs in macOS 14/15 (Darwin 24) system iconv. Torsten Bögershausen has proposed a two-patch series introducing a workaround (`ICONV_RESTART_RESET`) for these systems when using the system iconv rather than known-good versions from MacPorts or Homebrew.

The first patch introduced the workaround mechanism, while this second patch adds build system logic to detect affected configurations and automatically enable the workaround. René Scharfe has reviewed the changes, suggesting improvements to the commit message style, questioning whether the MacPorts detection might be too optimistic (as it doesn't verify libiconv is actually installed), and recommending more precise variable naming to better reflect the specific workaround being enabled. The technical changes center on adding conditional compiler flags when building on affected macOS versions without third-party iconv libraries.

The series now appears functionally complete, with René's feedback focusing on making the implementation more precise and maintainable. The changes maintain compatibility with existing builds while addressing the platform-specific issue through careful conditional flag setting.
