This thread documents a successful Google Summer of Code (GSoC) project to improve the `git add -p` interface by showing users their previous hunk decisions (y/n) when navigating between hunks during interactive staging. The feature was originally suggested by Junio C Hamano to address a common usability pain point, and has been implemented by a GSoC participant under Junio's guidance.

After seven iterations of refinement, the patch is now in its final form. The implementation cleanly modifies prompt strings in `add-patch.c` to append "(was: y)" or "(was: n)" indicators while maintaining the existing interface. Version 7 specifically tightened the implementation by reducing prompt width and improving readability. The changes are well-contained with comprehensive tests verifying both regular and colored output formats.

The thread shows a textbook example of mentored contribution, with the GSoC participant carefully incorporating feedback through multiple revisions. Junio has indicated the patch appears ready for merging to the 'next' branch, marking the successful conclusion of this small but useful UI improvement. The change requires no configuration and doesn't affect other commands, making it a low-risk enhancement to the interactive staging workflow.
