This thread discusses a usability improvement to `git add -p` that would show users their previous hunk decisions (y/n) when navigating between hunks during interactive staging. The feature was originally suggested by Junio C Hamano to address a common pain point where users lose track of their selections. A Google Summer of Code participant has implemented the change over seven iterations, with guidance from Junio.

The current implementation (v7) modifies `add-patch.c` to track decisions via a new `hunk_use_decision` string and displays "(was: y)" or "(was: n)" in the prompt while preserving the existing interface. The latest version tightens up the implementation by reducing prompt width and improving readability. Tests in `t/t3701-add-interactive.sh` verify the behavior works with both regular and colored output.

After multiple rounds of review addressing prompt formatting and implementation details, the patch appears ready for final review. Junio has been involved throughout the process and seems likely to approve this straightforward quality-of-life improvement to a core interactive command once any remaining reviewers give their feedback. The changes are well-contained and don't affect the underlying hunk selection logic.
