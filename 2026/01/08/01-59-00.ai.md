This is the final bugfix patch in a series implementing PID file debugging for Git locks, addressing Junio Hamano's documentation accuracy feedback. The feature creates `~pid.lock` files alongside lockfiles to help diagnose stale locks, with the tilde separator ensuring no refname collisions.

The patch simplifies the configuration to a boolean `core.lockfilePid` after earlier discussion with Jeff King and Patrick Steinhardt, removing per-subsystem granularity. It adds Windows support via mingw_kill() updates and includes a comprehensive 139-line test suite (t0031) covering PID file creation, cleanup, and error messaging across platforms.

Key technical details: 1) PID files use `pid <value>` format, 2) Existing PID files are read for diagnostics even when disabled, 3) Automatic cleanup via tempfile registration, and 4) Context-aware error messages distinguish running vs stale processes. The implementation handles edge cases like write failures and PID file parsing while maintaining backward compatibility.

Junio's review notes two remaining theoretical concerns about PID reuse and lock-breaking safety, but these don't block merging as they reflect inherent limitations of PID-based debugging rather than implementation flaws. The patch appears production-ready with all prior feedback addressed.
