This thread discusses optimizing object-to-ref lookups in Git's reftable backend. Tsahi Elkayam has identified a performance bottleneck where the current `indexed_table_ref_iter` implementation inefficiently scans entire ref blocks when looking up references by object ID, rather than properly leveraging the reftable index structure.

The proposal suggests restructuring the iterator to maintain state about object records, allowing it to seek directly to relevant ref blocks and skip unnecessary reads. This would particularly benefit operations that need to map objects back to their references, like `git branch --contains` or `git tag --contains`. The change would focus on `reftable/refs.c` while maintaining compatibility with the existing on-disk format.

As this is an RFC, the author is seeking feedback on the architectural approach before implementation. Given that Patrick Steinhardt and Karthik Nayak have been the primary drivers of reftable development, their input will likely be key in evaluating whether this fits with the subsystem's direction. The optimization could meaningfully improve performance for repositories using the reftable backend, especially those with many references.
