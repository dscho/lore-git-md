Thread identity: Feature request for `git init` to support `--config` option, similar to `git clone`. Originating author is David Miguel Susano Pinto. Thread type is feature request/enhancement.

Core problem: Currently `git init` lacks direct support for setting configuration values during repository initialization, unlike `git clone` which accepts `--config`. The specific use case is setting different default user.email values for work vs personal repositories. While `git -c` can pass config to the command itself, these settings don't persist in the new repository's config.

Current status: Initial proposal with clear use case presented. No implementation yet. Workaround exists using repository templates but is less convenient than direct `--config` support.

Key technical details: The `git -c 'user.email=...' init` doesn't work as expected because `git init` only honors certain documented configuration options during initialization. The change would need to modify how config options are processed when creating a new repository.

Open questions: How should the implementation handle config precedence between `--config`, template configs, and system/user configs? Should there be any restrictions on which config options can be set this way?

Participant positions: Only the author (David Miguel Susano Pinto) has contributed so far, presenting the use case and current workaround. No other participants have responded yet.

Related work: The existing `git clone --config` functionality provides a model for how this could work. Repository templates are the current workaround but require more setup.
