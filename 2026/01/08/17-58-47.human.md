This is a performance optimization proposal for the reftable backend's object-to-ref lookup functionality. Tsahi Elkayam identifies an inefficiency in how `indexed_table_ref_iter` handles object-to-reference lookups, where it currently reads entire ref blocks and manually filters records rather than properly utilizing the index structure.

The current implementation reads one object record and then scans all referenced ref blocks exhaustively, performing OID comparisons for each ref. Tsahi suggests a more targeted approach that would:
1. Seek to the first matching object record
2. Only process ref blocks referenced by matching object records
3. Stop when object records no longer match the prefix

This appears to be part of the ongoing reftable backend work led by Patrick Steinhardt and Karthik Nayak. The proposal shows good technical insight into the reftable internals, though as Tsahi notes, they're still getting familiar with the codebase. The suggested approach seems reasonable at first glance, but would need review from the reftable experts to confirm it aligns with the intended design. This could be a worthwhile optimization if implemented correctly, as it would reduce unnecessary I/O during ref lookups.
