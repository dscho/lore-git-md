Bugfix for undefined behavior in reftable's object ID lookup. This is part of the ongoing reftable backend work led by Patrick Steinhardt and Karthik Nayak.

Tsahi Elkayam's patch fixes a type safety issue in the indexed_table_ref_iter_next() function, which maps object IDs to references. The original code could trigger undefined behavior by accessing the wrong union member (val2) when dealing with unpeeled references (which use val1). The fix properly checks the reference type before accessing the union fields.

While addressing this immediate issue, the patch also acknowledges a deeper design problem - the current implementation scans all references in a block rather than using more efficient reverse lookups. Patrick Steinhardt suggested adding a TODO comment about this optimization opportunity, which the patch includes while keeping the focused fix.

The change is small (13 lines) but important, fixing a marked "BUG" in the reftable subsystem. The patch follows the pattern used in similar iterator code and has received maintainer approval with the TODO addition. This appears ready for merging as part of the reftable stabilization effort.
