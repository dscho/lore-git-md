This is a platform compatibility patch addressing a bug in macOS's iconv implementation that causes incorrect character encoding conversions, specifically for ISO-2022-JP text. The issue manifests in Git's test suite failures where commit messages are only partially converted from ISO-2022-JP to UTF-8.

Torsten Bögershausen proposes a workaround that modifies `reencode_string_iconv()` in utf8.c to handle the case where iconv needs a larger output buffer. The key change is that when the buffer is resized, the conversion now restarts from scratch (with state reset) rather than continuing where it left off. This avoids corruption from the macOS iconv's apparent state management bugs during piecemeal conversions.

The patch introduces a new `ICONV_RESTART_RESET` compile-time flag to enable this behavior, with a follow-up patch promised to add a Makefile knob for it. The change is well-motivated by specific test failures and includes a clear explanation of both the problem and solution. René Scharfe is credited with suggesting the approach.

This appears to be a focused, technically sound fix for a real platform-specific issue. The patch targets a narrow problem (iconv behavior on macOS 14/15) while maintaining compatibility with other platforms. The implementation is straightforward and the commit message provides good context about alternative solutions (linking against third-party iconv implementations) and why this approach was chosen.
