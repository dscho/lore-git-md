Thread identity: Platform compatibility patch addressing macOS iconv bug in ISO-2022-JP to UTF-8 conversion, originating from Torsten Bögershausen with input from René Scharfe.

Core problem: macOS 14/15's iconv implementation fails to maintain proper state during chunked conversions when the output buffer is too small, corrupting text encoding conversions. This affects Git's `reencode_string_iconv()` function and manifests in test failures (t3900 tests 17, 25, 38).

Solution: Introduces `ICONV_RESTART_RESET` workaround in `utf8.c` that resets conversion state and retries with larger buffer when expansion is needed, rather than continuing from partial state. About 13 lines of conditional code added.

Technical details: Impacts encoding conversion path in `utf8.c`. While focused on test suite failures, could affect any Git operation needing ISO-2022-JP <-> UTF-8 conversion on affected macOS versions. Alternative solutions exist (third-party iconv from package managers) but this provides built-in fallback.

Status: Initial patch in series - implements core fix but does not yet include makefile knob to control the workaround. Expected to be followed by configuration patch.

Participants: Torsten Bögershausen (author), René Scharfe (input/feedback).

Related work: Builds on existing encoding conversion infrastructure in Git. Follow-up patch expected to add build configuration for the workaround.
