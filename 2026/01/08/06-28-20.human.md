This is the final patch in a documentation series improving the `git-patch-id` man page. The patch clarifies the interaction between the `--verbatim` and `--stable` options, noting that `--verbatim` automatically implies `--stable` and cannot be used with `--unstable`. 

The change documents existing behavior that was implemented in commit 2871f4d4 but not fully explained in the documentation. The rationale is that users of `--unstable` care about compatibility with old Git versions, and allowing `--verbatim` with `--unstable` would break that compatibility while providing no clear use case.

This is a straightforward documentation improvement that matches the style and quality of the previous patches in the series. The author, Kristoffer Haugsbakk, has established a pattern of sending well-crafted documentation patches that polish wording and clarify technical details without changing behavior. The change is small but meaningful, helping users understand an otherwise implicit constraint in the command's behavior.
