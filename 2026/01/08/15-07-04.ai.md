This is a UI improvement patch for `git add -p` (interactive patch staging) that shows the user's previous hunk decision when navigating between hunks. The patch is in its 7th iteration, indicating it has undergone significant review and refinement.

The change makes it clearer when reviewing hunks whether each hunk was previously marked for inclusion (y) or exclusion (n) by appending "(was: y)" or "(was: n)" to the prompt. This helps users keep track of their decisions as they navigate through hunks using the K/J keys or other navigation commands.

The patch touches both the core logic in `add-patch.c` (modifying prompt strings and adding decision tracking) and updates related tests in `t/t3701-add-interactive.sh`. The implementation is clean and focused, with changes limited to:
1. Adding a new `hunk_use_decision` string that shows the previous choice
2. Modifying prompt format strings to include this new state indicator
3. Updating test expectations to match the new prompt format

The patch was originally suggested by Junio C Hamano (the Git maintainer) and has clearly gone through multiple rounds of review, with v7 showing refinements to prompt width and readability. The changes are well-contained and the test updates demonstrate the new behavior works as expected, including in colored output scenarios.
