This is a documentation patch that introduces a whitespace check for tabs appearing between non-whitespace characters in documentation files, where a space was likely intended. The patch has gone through several iterations with review feedback from Johannes Sixt and Junio Hamano, and appears ready for merging.

The check is designed to catch cases where tabs might visually appear as single spaces due to tab expansion, which could lead to subtle formatting issues in documentation. The implementation modifies Git's existing whitespace checking infrastructure, adding a new WS_TAB_INSTEAND_OF_SPACE flag and updating the emit_middle_section() function to handle tab highlighting.

Johannes Sixt raises some final concerns in this email, questioning how frequently this type of whitespace issue actually causes problems in practice. He notes that while he has encountered the issue a handful of times, it's much less common than other whitespace problems. He also points out a potential false positive case where tabs used for table formatting might be incorrectly flagged when they're actually intended behavior. The discussion appears to be wrapping up, with all technical feedback addressed in previous iterations. This seems like a well-considered addition to Git's documentation quality tools, though Johannes' comments suggest the feature might see limited practical use compared to other whitespace checks.
