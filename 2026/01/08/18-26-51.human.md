This is the final patch in a documentation series improving the `git-patch-id` man page and related code comments. The patch clarifies the interaction between the `--verbatim` and `--stable` options, documenting that `--verbatim` implicitly enables `--stable` and prevents `--unstable` - behavior that was introduced in commit 2871f4d4 but not fully explained in the documentation.

The change reflects the design rationale that users of `--unstable` care about compatibility with old Git versions, and allowing `--verbatim` with `--unstable` would break that compatibility while adding maintenance burden. The patch fixes a minor typo in the original submission (missing backtick) and has already received positive review from Pushkar Singh.

This completes Kristoffer Haugsbakk's v1 series of small but meaningful documentation improvements for `git-patch-id`, which has standardized terminology, improved grammar, and clarified subtle option interactions.
