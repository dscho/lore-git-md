This is a feature request for `git init` to support the `--config` option, similar to what `git clone` already offers.

David Miguel Susano Pinto notes that while `git clone` allows setting configuration values like `user.email` at creation time via `--config`, the same functionality is missing from `git init`. They've tried using `git -c` as a workaround but found it doesn't work for repository initialization, likely because `git init` doesn't process the configuration in the same way.

The author describes their current workflow using different email addresses for work vs personal projects, with `clone` aliases to handle the distinction. They'd like similar convenience for `init`, either through `-c` support or another mechanism, rather than their current solution of using different templates.

The request appears well-motivated by a real workflow need, though the patch would need to address why the existing `-c` mechanism doesn't work for `init` and whether there are technical constraints preventing this functionality. The email is clear and concise, making a straightforward case for the feature without overcomplicating it.
