This thread addresses a logging formatting issue in git-http-backend where error messages from the `not_found` and `forbidden` functions could appear concatenated without newlines when run through wrappers like fcgiwrap. The original patch from KJ Tsanaktsidis proposed modifying `http-backend.c` to ensure proper newline termination of error messages, arguing this responsibility belongs in Git rather than wrapper scripts.

Junio Hamano has now weighed in, agreeing with the core approach but suggesting a minor optimization: using `fputc('\n', stderr)` instead of `fprintf` for the newline to avoid unnecessary format string parsing. The discussion confirms this is a real issue affecting deployments (particularly with journald logging) and that the solution is architecturally sound. With Junio's suggested tweak, the patch appears ready for merging - it remains narrowly focused on the two HTTP backend functions without changing any error handling logic. The thread shows consensus that Git should own its message formatting rather than relying on external wrappers.
