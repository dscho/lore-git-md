Here's a human-readable summary of the thread so far:

Martin Fick raised a question about unexpected behavior when configuring Git's delta islands feature to treat each branch head as its own island for delta compression optimization. He observed that objects not covered by reachability bitmaps seemed to be ignored by the delta islands mechanism, leading him to wonder if this was a technical limitation.

Jeff King (Peff) clarified that delta islands don't actually depend on reachability bitmaps to function, despite some implementation details that might suggest otherwise. He provided the correct configuration syntax using a regex pattern (`[pack] island = refs/heads/(.*)`) to create per-head islands and explained this is independent of on-disk bitmap coverage. 

While this approach does what Martin wanted, Jeff noted it comes with significant storage tradeoffs since it prevents delta reuse across branches. The response suggests the original issue was likely a configuration misunderstanding rather than a fundamental limitation. The thread appears resolved with Jeff's explanation, though users should be aware that per-head islands may substantially increase packfile sizes unless they primarily fetch branches individually.
