Feature implementation for configurable branch comparison in `git status`. This is the final patch in Harald Nordgren's series adding the `status.compareBranches` configuration option, which has now been merged into Git's integration branches after extensive review and refinement.

The patch introduces a new config setting that allows users to specify multiple branches (including `@{upstream}` and `@{push}`) to compare against in `git status` output. The implementation handles triangular workflows where upstream and push branches differ, showing context-aware advice messages (pull advice for upstream, push advice for push branches). The core changes are in `remote.c` with comprehensive test coverage in `t6040-tracking-info.sh`.

Key technical aspects include:
- New `resolve_compare_branch()` function to handle branch name resolution
- Enhanced `format_branch_comparison()` with flags for different advice contexts
- Deduplication of branch comparisons using a `strset`
- Support for remapped push refspecs and multiple remote configurations

The implementation appears thorough and well-tested, with all feedback from previous rounds addressed. The feature is particularly useful for developers working with complex workflows involving multiple remotes or triangular push/pull configurations. The extensive test suite (337 lines) covers various edge cases and ensures backward compatibility with the default `@{upstream}` behavior.
