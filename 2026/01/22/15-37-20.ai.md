This is the final implementation patch in Harald Nordgren's series to make `git status` branch comparisons configurable, adding the `status.compareBranches` configuration option. The feature allows users to specify multiple branches (including `@{upstream}` and `@{push}`) to compare against in status output, with context-aware advice messages for each comparison type.

The patch introduces a new `resolve_compare_branch()` helper that handles branch-to-ref resolution for the configured names, and refactors the comparison formatting into `format_branch_comparison()` (extracted in the previous patch). The implementation handles triangular workflows where upstream and push branches differ, with proper de-duplication of refs via a `processed_refs` string list to avoid duplicate output when multiple specs resolve to the same ref.

Key technical details:
- Configuration is read via `repo_config_get_string()` with space-separated branch specs
- Default behavior remains `@{upstream}` for backward compatibility
- Advice messages are context-sensitive (pull advice for upstream, push advice for push branches)
- The test suite (t6040-tracking-info.sh) is expanded with 15 new test cases covering:
  - Basic functionality with multiple comparisons
  - Triangular workflow scenarios
  - Remapped push refspecs
  - Edge cases like diverged branches and up-to-date states
  - Interaction with `--no-ahead-behind`

The implementation has been through 27 iterations with all memory management issues addressed (Jeff King confirmed fixes in v26). This final version focuses on the configurable comparison feature itself after the preparatory refactoring in the first patch of v27. The feature is now complete and ready for merging pending final documentation updates.
