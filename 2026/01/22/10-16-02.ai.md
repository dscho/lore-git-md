This is a discussion about error handling tradeoffs in the xdiff refactoring series, specifically patch 3/10 which removes error checking from line classification.

Phillip Wood points out that the patch silently removed error handling from `xdl_classify_record()` calls, which could fail on memory allocation. While Git currently uses `xmalloc()` that die on failure, Phillip notes this change would break compatibility with other allocators that expect error propagation. He requests this design decision be explicitly documented in the commit message rather than being an unstated change.

Ezekiel Newren had previously justified the removal by explaining Rust's memory allocation model (where failures panic rather than propagate errors), but Phillip counters that since there's no Rust code in xdiff yet, the C behavior should be preserved. The discussion highlights a tension between Git's current error handling patterns and the Rust interoperability goals of the series.

This exchange represents an ongoing thread about how to balance C and Rust idioms in the xdiff refactoring. Phillip advocates maintaining existing behavior until a proper transition plan is established, while Ezekiel appears focused on the eventual Rust implementation's requirements. The disagreement centers on whether to make breaking changes now in service of future compatibility.
