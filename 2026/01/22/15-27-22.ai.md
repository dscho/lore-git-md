This is a bugfix patch addressing submodule fetching behavior when submodules use non-"origin" remote names. It's the third version of a series that implements a 7-year-old NEEDSWORK comment from commit be76c21282.

The patch adds a new `get-default-remote` subcommand to `submodule--helper` to properly handle submodules with custom remote names, fixing cases where `git fetch --recurse-submodules` would fail. The implementation maintains backward compatibility by falling back to "origin" if default remote detection fails.

Key technical details:
- New helper command in builtin/submodule--helper.c
- Changes to submodule.c to use the helper instead of hardcoded "origin"
- Comprehensive test coverage across multiple test files
- Fixes a single-quote syntax error in t5572 caught after v2
- Renames test file from t7425 to t7426 to avoid conflict with another series
