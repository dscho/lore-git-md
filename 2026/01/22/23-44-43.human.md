This is a follow-up discussion in Patrick Steinhardt's ODB abstraction series, specifically about the typing of flags parameters in the object database interface. Taylor Blau weighs in on the enum vs unsigned debate that arose in patch 02/14 of the series.

Taylor agrees with Jeff King's earlier position that enum flags are preferable to unsigned integers for new code, citing better documentation and type safety. While acknowledging there are 219 existing instances of "unsigned flags" in the codebase (versus 56 enum-based ones), he suggests establishing enum flags as the preferred pattern moving forward rather than undertaking a mass conversion of existing code.

The exchange represents a settled discussion point in the larger ODB abstraction effort, with consensus forming around using enum types for new flag parameters. This aligns with the series' broader goal of modernizing Git's object storage interfaces while maintaining compatibility with existing code. The thread shows the project's typical pattern of evolving conventions through discussion while avoiding unnecessary churn in stable code.
