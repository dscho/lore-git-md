This is a feature patch adding the `--maximal-only` option to `git rev-list`, now in its second iteration with all feedback addressed and ready for merging. The option helps identify "frontier" commits that are not reachable from others in a given range, which is useful for bundle URIs and bitmap optimizations.

The patch has evolved through discussion, settling on the `--maximal-only` name after considering alternatives. It now includes explicit documentation about its incompatibility with `--boundary` and thorough test coverage. Junio C Hamano's latest response confirms the technical explanation distinguishing this from `git merge-base --independent` - while both find maximal elements, they operate on different sets (union vs intersection of histories).

The implementation is clean, using bit 28 in the commit flag field, and the author (Derrick Stolee) has addressed all review feedback.
