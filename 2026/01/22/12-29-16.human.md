[Security] This is a continuation of the discussion about ANSI escape sequence filtering in Git's sideband channel, specifically addressing whether the security hardening should be opt-in or enabled by default.

Johannes Schindelin strongly advocates for keeping the current default behavior where only color sequences are allowed by default, with other control sequences requiring explicit opt-in. He argues that making sanitization opt-in would leave most users vulnerable to terminal escape injection attacks from compromised remotes. The thread has seen extensive discussion about trust models and backward compatibility, with brian m. carlson arguing for more permissive defaults while Patrick Steinhardt and D. Ben Knoble support stronger security protections.

Schindelin specifically challenges Junio Hamano's suggestion of trust-based defaults, pointing out that a frequently-used remote could still be compromised. He notes that color sequences are already allowed by default in the current implementation, while more dangerous cursor movement and erase sequences remain opt-in. The email seeks clarification on whether Junio is proposing to make all filtering opt-in (which Schindelin opposes) or just maintaining the current color-only default (which he supports).

The technical implementation itself appears settled, with URL-specific configuration available via `sideband.<url>.allowControlCharacters`. The debate has now narrowed to the security philosophy question of whether to prioritize hardening by default versus backward compatibility. Schindelin's position is firmly on the side of security-by-default, citing the risk that most users won't enable protections if they're not automatic.
