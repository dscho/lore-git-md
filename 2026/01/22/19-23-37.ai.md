This is a technical discussion about enum vs unsigned types for flag parameters in Git's ODB abstraction series.

Jeff King (Peff) responds to Junio Hamano's concerns about using enum types for bit flags in function interfaces. While agreeing that enums are generally preferable to `#define` constants, Peff notes that compiler warnings for enum mismatches (`-Wenum-conversion`) only catch some cases - they work for direct enum assignments but not for bit operations or `#define` values. He provides concrete examples showing when the warnings do and don't trigger.

The discussion stems from patch 02/14 in Patrick Steinhardt's ODB abstraction series, where flag parameter typing became a point of debate. Peff argues that despite the limitations, using enum types in function declarations provides useful documentation for humans and catches at least some incorrect usage. He also addresses Junio's concern about unsignedness, suggesting it may not be critical for flag parameters since enum values shouldn't need shifting.

This email represents the tail end of a resolved discussion - the technical merits have been aired, and the focus has shifted to documenting enum preferences in CodingGuidelines rather than blocking the series. The exchange demonstrates Git's attention to API design details even in mechanical refactoring work.
