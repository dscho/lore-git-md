This is a bugfix patch targeting the refs subsystem, specifically addressing an issue with how rejected ref updates are handled in batched operations. The patch is part of a larger series (1/6) from Karthik Nayak.

The core issue is in `refs_verify_refnames_available()` where a `continue` statement was incorrectly skipping only the inner loop when detecting filesystem conflicts, causing the same reference to be repeatedly rejected. The fix replaces this with a `goto` to properly skip to the next reference in the outer loop. The patch also enhances error handling by preserving rejection details in the transaction structure rather than discarding them.

Key technical changes:
- Modifies `ref_transaction_maybe_set_rejected()` to accept and store error details
- Updates all backend implementations (files, packed, reftable) to pass through error messages
- Adds a new `rejection_details` field to `struct ref_update`
- Fixes the loop control flow in refname verification

The changes are mechanical but touch multiple files in the refs subsystem. The patch appears well-contained and focused on the specific issue, with consistent changes across all ref backends. This is part of ongoing work to improve ref transaction reliability, particularly for batched operations.
