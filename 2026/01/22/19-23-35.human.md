This is the final version of a bugfix/feature patch implementing PID file debugging for Git locks, now ready for merging after five iterations of review. The patch adds an optional feature that creates companion PID files alongside lock files to help diagnose stale locks left by crashed processes.

When enabled via `core.lockfilePid`, Git creates a `~pid.lock` file (e.g. `index~pid.lock` next to `index.lock`) containing the holding process's PID. The feature provides more informative error messages when lock conflicts occur, distinguishing between active processes and stale locks. The implementation handles edge cases like PID reuse and maintains cross-platform compatibility, with special attention from Windows experts Eric Sunshine and Johannes Sixt.

The patch includes comprehensive tests covering 7 scenarios: stale lock detection, default behavior without PID files, running process detection, cleanup behavior, and backwards compatibility. Key reviewers Jeff King, Patrick Steinhardt, and Junio Hamano have signed off on the implementation, with Junio providing final cleanup of redundant file descriptor handling while preserving Windows-specific requirements. The solution is now considered complete with all technical discussions resolved.
