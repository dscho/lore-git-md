This is a follow-up discussion on the recently merged `status.compareBranches` feature, addressing Junio Hamano's suggestion about expanding branch name resolution. The feature allows configuring multiple branches for comparison in `git status` output, currently limited to remote-tracking branches with `refs/remotes/` prefixing.

Harald Nordgren acknowledges Junio's idea to leverage Git's existing DWIM (Do What I Mean) rules from `ref_rev_parse_rules[]` to support additional ref types like tags and local branches, while maintaining the current remote-tracking behavior. He suggests this would be a natural follow-up enhancement since it wouldn't require interface changes - the additional resolution logic could be added transparently while preserving backward compatibility.

The exchange confirms the current implementation is production-ready with its remote-tracking focus, while identifying a clear path for future improvement. This positions the feature for potential expansion in a subsequent release without blocking the initial rollout. The thread shows the maintainer and contributor aligning on an incremental approach to feature evolution.
