This is the final iteration (v27) of Harald Nordgren's feature to make `git status` branch comparisons configurable via `status.compareBranches`. The patch series has been through 26 previous versions with extensive review and is now queued for inclusion.

The key change in v27 is the addition of branch de-duplication - when multiple configured branches resolve to the same ref (a common case when `@{upstream}` and `@{push}` point to the same remote branch), the status output will now avoid showing duplicate information. The implementation uses a `processed_refs` string list to track which refs have already been reported.

The series introduces:
- A new `status.compareBranches` config accepting space-separated branch specs
- Support for comparing against multiple branches including `@{upstream}` and `@{push}`
- Context-aware advice messages that adapt based on which branches are being compared
- Comprehensive test coverage in t6040-tracking-info.sh

Junio's email serves as a gentle reminder to properly summarize changes in cover letters, noting that while he could deduce the v27 changes from context, others may not need to reverse-engineer them from the range-diff. The feature itself appears solid after 27 iterations and is now documentation-complete.
