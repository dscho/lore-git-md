This is a reply in the ongoing ODB abstraction series, specifically addressing Taylor Blau's concern about patch 03/14's path-based object access interface. Patrick Steinhardt acknowledges that the path-based approach is indeed a leaky abstraction, but defends it as being confined to the loose object backend where paths are inherently part of the storage model. He clarifies that other storage formats (like database-backed ones) won't be exposed to this interface.

The exchange highlights a key tension in the abstraction effort - balancing clean interfaces with practical implementation needs. While the discussion remains technical and constructive, it shows Patrick's willingness to accept some abstraction leakage when justified by the specific backend requirements. This reply doesn't introduce new code changes but helps clarify the design rationale for reviewers following the thread.
