This is part 2/3 of a patch series in the `the_repository` removal effort, specifically migrating the `core.sparseCheckout` configuration from a global variable to repository-scoped storage in `struct repo_config_values`. The patch follows Phillip Wood's suggestion to use a dedicated config struct rather than `repo-settings`.

The changeset updates 12 files to reference `the_repository->config_values.sparse_checkout` instead of the global `core_apply_sparse_checkout`. Key modifications include adjusting sparse-checkout command behavior, clone initialization, submodule handling in grep, and worktree operations. The patch maintains existing functionality while ensuring configuration is properly scoped per-repository.

Toon Claes provides review comments noting two minor issues: a duplicate "environment:" in the commit message subject line and a typo in the variable name `core_appy_sparse_checkout`. He also questions the removal of the `core_` prefix from the new struct field, suggesting it might be clearer to keep the prefix since the struct will contain configs from various sections.

The technical implementation appears sound, with careful attention to initialization sequencing and behavior preservation. This continues the pattern established in part 1 (which migrated `core.attributesFile`) and sets up part 3 (which will handle `branch.autoSetupMerge`). The series represents concrete progress on the broader `the_repository` removal goal while leaving larger architectural questions about config scoping for future work.
