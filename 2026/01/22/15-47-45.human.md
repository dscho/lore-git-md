This is a bugfix patch targeting the `git reset` command's reflog behavior. The patch addresses a case where `git reset` would unnecessarily write a reflog entry when the target commit matches HEAD (a no-op reset).

Pushkar Singh identifies that currently, even when resetting to the same commit, Git updates ORIG_HEAD and writes a reflog entry. The patch adds a check to detect this no-op case and skip the reflog update entirely. The change is small (4 lines in `builtin/reset.c`) but meaningful for users who care about keeping clean reflogs.

The patch includes a new test case in `t/t1410-reflog.sh` that verifies no reflog entry is written for a no-op reset. The test creates a repository, makes a commit, then checks that the reflog count remains unchanged after a `git reset HEAD`.

This appears to be a well-contained, focused improvement. The commit message clearly explains the problem and solution, and the test provides good coverage of the new behavior. The change seems uncontroversial and likely to be accepted, though reviewers may want to confirm there aren't any edge cases where the no-op detection could cause problems.
