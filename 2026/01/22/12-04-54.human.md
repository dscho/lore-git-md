This is a bugfix series (v4, 6/6) from Karthik Nayak and Jeff King addressing a regression in error message reporting for batched reference updates. The series has already been merged in its v3 form by Junio Hamano, with this v4 version implementing a post-merge optimization suggested by Phillip Wood.

The core issue was that batched reference updates (used by `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`) had lost detailed error messages that were previously available, only returning generic error codes. This made debugging reference operation failures more difficult. The series restores detailed error reporting while maintaining backward compatibility with existing output formats.

Key improvements in this version:
- Implements Phillip Wood's suggestion to use `ALLOC_GROW()` for the display list allocation in `fetch.c`, simplifying the code by wrapping the list in a `struct ref_update_display_info_array`
- Maintains all previous functionality from v3 including:
  - Comprehensive test coverage
  - Preserved output formats for `update-ref` and `receive-pack`
  - Deterministic ordering of `fetch` status output
  - Detailed error reporting for various failure cases (reference locks, case sensitivity conflicts, etc.)

The series is now complete and merged, with this final optimization being a clean-up of the implementation rather than a functional change. Benchmarks show only 1% overhead for repositories with 1000 refs.
