This is part 10 of Adrian Ratiu's 12-part series refactoring Git's hook subsystem to support parallel execution. The patch addresses a performance bottleneck in the parallel execution infrastructure where child processes could experience artificial 100ms delays due to output polling timeouts. The solution implements bidirectional I/O polling in `run-command.c` via a new `pp_buffer_io()` helper, allowing simultaneous monitoring of both input and output file descriptors.

The change resolves two specific issues: Kristoffer Haugsbakk's report of throughput limitations and Jeff King's deadlock concern when pipes fill up. The implementation maintains backward compatibility with sequential execution (ungroup=1) while optimizing parallel operation. Junio Hamano questions the use of positive integer checks for file descriptors, prompting Adrian to acknowledge this as a quirk of `run-command.c`'s current design that would require a larger refactor to address properly.

With this patch, the technical implementation appears complete, having addressed all major feedback from reviewers. The series has maintainer approval and is now in its final polishing stage before expected merging. This represents a significant modernization of Git's hook execution infrastructure that will enable future features like config-based hooks.
