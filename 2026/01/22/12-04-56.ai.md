This is part 2 of a 6-patch bugfix series addressing a regression in error message reporting for batched reference updates. The series is a collaboration between Karthik Nayak and Jeff King, now in its fourth iteration.

The patch extends the callback function signature for handling rejected reference updates to include detailed error messages. While the actual error message integration comes in subsequent patches, this change lays the groundwork by modifying the callback interface to accept a `details` parameter. The existing callback implementations in `fetch.c`, `receive-pack.c`, and `update-ref.c` are updated to handle the new parameter (currently marked as UNUSED), and the `ref_transaction_for_each_rejected_update()` function is modified to pass through the rejection details stored in the transaction.

This is a mechanical change that enables the more substantive error reporting improvements in later patches. The patch maintains backward compatibility while preparing the plumbing needed for detailed error propagation. The changes touch core refs infrastructure (`refs.c`, `refs.h`) and the three main commands that use batched reference updates (`fetch`, `receive-pack`, `update-ref`), showing the wide impact of the regression being fixed.
