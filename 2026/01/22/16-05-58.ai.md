This is a feature patch from Derrick Stolee adding a new `--maximal-only` option to `git rev-list`. The option filters commits to show only those that are not reachable from any other commit in the specified range, which is useful for identifying "frontier" commits in the reachability graph.

The patch resolves an earlier naming debate by settling on `--maximal-only` (rather than just `--maximal`) and explicitly documents the option's incompatibility with `--boundary`. The implementation uses a new `CHILD_VISITED` flag (bit 28) in the object flags, bringing Git to 28/32 bits used. While this raises some long-term concerns about flag bit exhaustion, the author notes that earlier bits appeared too risky to reuse.

The patch includes thorough test coverage demonstrating the feature's behavior with positive-only ranges, ranges with negative references, and walk-modifying flags like `--first-parent`. The primary use case is for bundle URIs where selecting maximal commits can help define smaller reference sets, though the technique could also be useful for reachability bitmap optimization.

This appears to be a well-considered addition with clear documentation and testing. The naming debate has been resolved through discussion, and the implementation addresses the mathematical properties needed while maintaining interface clarity. The patch is now in its second iteration with all feedback incorporated, making it ready for maintainer consideration.
