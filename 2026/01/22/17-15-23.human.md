This is the second patch in an RFC series introducing a combined sort+deduplicate utility for string lists. The patch converts several call sites that currently use separate `string_list_sort()` and `string_list_remove_duplicates()` calls to use the new `string_list_sort_u()` function instead.

The changes are mechanical and touch several important commands: clone, fast-export, pack-objects, sparse-checkout, help, and notes. Each conversion replaces two lines with one, making the code more concise while maintaining the same behavior. The patch appears well-targeted, only touching cases where both sorting and deduplication were explicitly requested.

The pack-objects conversion is particularly interesting as it handles two string lists (include_packs and exclude_packs) and was previously flagged in the thread as a case where tests might depend on sorting without deduplication. The author has proceeded with the conversion here, suggesting they believe deduplication is safe in this context.

This patch builds on the first in the series (which introduced the new function) and demonstrates its practical application. As an RFC, it's seeking feedback on whether these conversions are appropriate before proceeding further. The changes are straightforward but touch core functionality, so careful review will be needed to ensure no subtle behavioral changes are introduced.
