This is a follow-up bugfix to Harald Nordgren's recently completed configurable branch comparison feature in `git status`. The patch addresses a memory leak and duplicate status reporting issue that surfaced after the v26 series was queued by Junio Hamano.

The specific problem occurs when both `@{upstream}` and `@{push}` resolve to the same branch (like `origin/main`). In this case, the status comparison would redundantly report the same divergence twice. Harald has identified the issue and has a fix ready that implements branch de-duplication to prevent this double reporting.

This appears to be a straightforward cleanup of an edge case that wasn't caught during the extensive review of the 26-iteration series. Since Jeff King had already confirmed all memory management issues were resolved in v26, this represents a newly discovered case. The fix maintains the feature's backward compatibility while improving its behavior in common triangular workflow scenarios where upstream and push branches are identical.

The patch is in its final testing phase (awaiting CI results) and will presumably be sent as a follow-up to the now-queued v26 series. Given the feature's maturity and the focused nature of this fix, it's likely to be quickly integrated without further discussion.
