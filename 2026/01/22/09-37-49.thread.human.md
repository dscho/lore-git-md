Harald Dunkel raised an issue about inconsistent pager behavior across Git commands, particularly noting that setting `core.pager=cat` breaks the `git -p` flag functionality. The thread began as a user experience complaint about unpredictable paging defaults between commands like `log` and `branch`.

Maintainer Junio Hamano responded by explaining the current design: the `-p` and `-P` flags intentionally override each command's default pager behavior, and the `pager.<cmd>` configuration provides per-command control. He demonstrated how to disable paging for specific commands (like `git branch`) while preserving the ability to force paging with `-p`. Junio framed this as a documentation and configuration matter rather than a code issue, maintaining Git's philosophy of granular control through configuration. While acknowledging the complexity, he indicated no plans to change the current behavior, suggesting users leverage existing mechanisms to achieve their desired paging setup.
