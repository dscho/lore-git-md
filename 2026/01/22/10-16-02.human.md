This is a discussion about patch 3/10 in Ezekiel Newren's xdiff refactoring series aimed at Rust interoperability. The patch removes line-count guessing and changes error handling in the xdiff classifier.

Phillip Wood points out two key issues with the patch: (1) it introduces an extra pass over the input lines (though saves some work by avoiding line-count guessing), and (2) it removes error handling for memory allocation failures without explanation in the commit message. Phillip notes this change assumes the Rust-style behavior where allocation failures panic rather than propagating errors, which differs from Git's current error-handling approach.

Ezekiel had previously defended the change by explaining Rust's panic-on-failure model and the series' goal of Rust compatibility. Phillip counters that this is a substantive change that should be explicitly proposed and discussed, not silently introduced, especially since xdiff currently supports non-fatal allocation failures when used with custom allocators.

The discussion highlights a tension between Git's current error handling patterns and Rust's different approach. Phillip's position reflects Git's traditional emphasis on explicit error propagation, while Ezekiel is prioritizing Rust interoperability. This is part of the broader Rustification effort's challenge in bridging C and Rust idioms.
