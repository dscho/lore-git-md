This is part 2 of a 6-patch bugfix series addressing a regression in error message reporting for batched reference updates. The series is a collaboration between Karthik Nayak and Jeff King, now in its fourth iteration and already merged by Junio Hamano.

The patch extends the callback function signature for handling rejected reference updates to include detailed error messages. While the actual error message integration comes in subsequent patches, this change lays the groundwork by modifying the callback interface in `refs.h` and updating all callers (`fetch.c`, `receive-pack.c`, and `update-ref.c`) to accept the new parameter. The patch is mechanical but necessary plumbing for restoring the detailed error reporting that was lost in the batched updates implementation.

The changes are straightforward and well-contained, touching only the rejection handling paths. The patch is part of a larger effort to improve debuggability when reference operations fail, particularly important for operations like `git fetch` and `git push` where understanding why a reference update failed is critical. The series as a whole has been through multiple rounds of review and optimization, with this particular patch being a clear prerequisite for the functionality added in later patches.
