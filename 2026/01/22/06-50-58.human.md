This is a technical discussion about code style in the ongoing ODB abstraction series. Patrick Steinhardt responds to Jeff King's review feedback about whether flag parameters should use `enum` types or plain `unsigned` integers in the Git codebase.

Jeff had argued that enums provide better type safety and readability when flags are defined in an enum, even for bitfields. Patrick counters that while he agrees for single-value enums, using enums for bitfields feels less clean, and notes that `unsigned flags` is far more common in the existing codebase (219 vs 56 occurrences). He's willing to standardize on enums if there's consensus but suggests updating the coding guidelines if so.

The exchange is cordial and focused on establishing consistent patterns - a typical code style discussion between experienced contributors.
