This is a bugfix series (v4, 6/6) from Karthik Nayak and Jeff King addressing the loss of detailed error messages in batched reference updates. The series has already been merged in v3 form, with this v4 iteration implementing a post-merge optimization suggested by Phillip Wood.

The core issue fixed is that batched reference updates (used by `git update-ref --batch-updates`, `git fetch`, and `git receive-pack`) were only returning generic error codes rather than the detailed messages that existed before batched updates were introduced. The series restores these detailed error messages while maintaining backward compatibility with existing output formats.

Key technical changes in this final version:
- Replaces the manual array management in `fetch.c` with a `struct ref_update_display_info_array` that uses `ALLOC_GROW()` for dynamic growth, as suggested by Phillip Wood
- Maintains all other improvements from v3 including deterministic output ordering and comprehensive test coverage
- Continues to show detailed errors for various failure cases (reference locks, case sensitivity conflicts, etc.)

The series builds on commit 0e358de64a (introducing batched updates) and fixes a regression from 9d2962a7c4. Performance impact remains minimal (1% overhead for 1000 refs). With this optimization now implemented, the series appears complete with no outstanding loose ends beyond some future message formatting cleanup in `receive-pack`.

This represents the culmination of work originally reported by Elijah Newren and builds on Jeff King's initial patch. The thorough approach and responsiveness to review feedback (particularly from Phillip Wood) demonstrates the patch's maturity and readiness for inclusion.
