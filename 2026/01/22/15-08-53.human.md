This is a feature patch from Derrick Stolee adding a new filtering option to `git rev-list`. The patch is in its final stages, with the implementation complete and tested, but the naming of the new option is still being debated.

The new option (currently called `--maximal` but likely to be renamed `--maximal-only` in v2) filters commits to show only those that are not reachable from any other commit in the input range - essentially the "frontier" commits in the reachability graph. This has applications for bundle URIs and reachability optimizations. The implementation uses bit 28 in Git's object flag space and includes thorough test coverage.

Junio Hamano has weighed in on the discussion, confirming that the new option is mathematically incompatible with `--boundary` (which shows the opposite - minimal commits that reach others). The naming debate has considered alternatives like `--hide-reachable` and `--range-head-only`, but the author is settling on `--maximal-only` as the most precise term, despite concerns about it being too mathematical for some users.

The patch appears well-considered and addresses a real need, with the naming being the last point of discussion before it can be merged. The author plans to send a v2 incorporating the feedback about making the option incompatible with `--boundary` and moving the documentation. This looks like a solid addition that will be merged once the naming is finalized.
