This thread introduces a new utility function `string_list_sort_u` that combines sorting and deduplication of string lists into a single operation. The RFC patch series from Amisha Chhajed follows up on a suggestion from Junio Hamano to simplify the common pattern where code currently calls `string_list_sort` followed by `string_list_remove_duplicates`.

The first patch adds the new function to the string-list API, while the second updates several built-in commands (clone, fast-export, pack-objects, and sparse-checkout) to use it. An interesting observation emerged during development: tests for pack-objects failed when the sort step was removed but not when just deduplication was skipped, suggesting some deduplication calls may be unnecessary.

The author is seeking feedback on both the API design and implementation approach, particularly around testing since the string-list operations currently lack dedicated unit tests. The changes appear technically sound but would benefit from review of whether all the converted cases genuinely need both operations. This could lead to follow-up discussions about potentially removing redundant deduplication in some spots.
