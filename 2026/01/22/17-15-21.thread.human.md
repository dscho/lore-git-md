Amisha Chhajed has proposed an RFC patch series to simplify a common pattern in Git's codebase - sorting and deduplicating string lists. Currently, this requires two separate function calls (`string_list_sort()` followed by `string_list_remove_duplicates()`), but the series introduces a new `string_list_sort_u()` function that combines both operations. The idea originated from Junio Hamano's suggestion to merge these frequently paired operations.

The first patch introduced the new function, while the second patch (just received) converts several existing call sites across important commands like clone, fast-export, pack-objects, and sparse-checkout. The changes are mechanically straightforward - replacing two lines with one - but some cases warrant closer examination. In pack-objects, the change might affect test behavior that implicitly depends on the current sort-without-deduplicate behavior. The sparse-checkout changes touch performance-sensitive cone mode pattern handling code.

As an RFC, the series is seeking feedback on both the API design and the specific conversions. Key questions remain about whether all converted cases actually need deduplication, how to test the new behavior, and whether to proceed with all conversions or keep this as an optional utility. The author is particularly interested in feedback on the pack-objects case and whether additional test coverage would be helpful before proceeding.
