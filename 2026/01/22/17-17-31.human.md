Junio C Hamano responds to a user's complaint about inconsistent pager behavior across Git commands. The maintainer clarifies that `-p` and `-P` flags work as designed by overriding each command's default paging behavior, but acknowledges the defaults may not match user expectations.

He points to existing configuration options in `git help config` that allow per-command pager control via `pager.<cmd>` settings. As a concrete example, he suggests setting `pager.branch = false` to prevent `git branch` from automatically paging while still allowing manual paging with `git -p branch`.

The response maintains that the current behavior is intentional but provides workarounds for cases where the defaults don't suit users' needs. No plans for deeper changes to the pager system are indicated, though the thread remains open for further discussion.
