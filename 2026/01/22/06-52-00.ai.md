This is a technical discussion about naming conventions in Patrick Steinhardt's ODB abstraction series, specifically around patch 04/14 which introduces a new function to iterate through objects. The exchange focuses on whether the verbose function name `odb_source_loose_for_each_object()` is justified or if a simpler `for_each_loose_object()` would suffice.

The length conveys specificity, guiding callers toward the appropriate abstraction level.

The discussion surfaces a tension between clarity through verbosity and simplicity through brevity, with Patrick arguing the explicit naming helps prevent misuse by making abstraction boundaries obvious. This is part of the broader ODB abstraction effort to make object storage pluggable, where such interface design choices have long-term implications for maintainability. The exchange remains constructive, with both sides articulating their perspectives on how naming conventions serve (or hinder) different audiences.
