This is a feature patch from Derrick Stolee adding a `--maximal-only` option to `git rev-list`, now in its second iteration. The option helps identify "maximal" commits - those not reachable from others in a given set - which is useful for bundle URIs and bitmap optimizations.

The patch has evolved through discussion, with the naming settled on `--maximal-only` (originally proposed as `--maximal`) and clear documentation added about its incompatibility with `--boundary`. Junio Hamano raised a conceptual question about how this relates to `git merge-base --independent`, which Stolee clarifies here: while both find commits not reachable from others, `--maximal-only` operates on the union of histories (for the input set) whereas `--independent` works on their intersection.

The implementation uses bit 28 in revision.c/commit.c's flag space and includes comprehensive tests covering various edge cases. Stolee notes this could potentially be optimized further for the bundle URI use case, but the current approach maintains `rev-list`'s expressiveness while solving the core problem. The patch appears ready for consideration, having addressed all feedback from the initial version.
