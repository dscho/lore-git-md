This is the final implementation patch in Harald Nordgren's multi-year effort to make `git status` branch comparisons configurable. The feature introduces a new `status.compareBranches` config option that allows users to specify multiple branches (including `@{upstream}` and `@{push}`) to compare against in status output.

The patch builds on previous iterations that resolved memory leaks and edge cases, now adding comprehensive test coverage in t6040-tracking-info.sh. The implementation handles triangular workflows where upstream and push branches differ, showing context-aware advice messages (pull advice for upstream, push advice for push branches). The default behavior remains backward compatible with single upstream comparison when the config is unset.

Key technical aspects include a new `resolve_compare_branch()` helper for branch-to-ref resolution, refactored comparison formatting via `format_branch_comparison()`, and deduplication of identical refs. The test suite verifies behavior across various scenarios: diverged branches, remapped push refspecs, multiple remotes, and different output modes (normal vs --no-ahead-behind).

With all implementation issues resolved and Junio Hamano having queued the series, this feature is ready for release pending final documentation updates. The patch represents the culmination of extensive discussion and refinement, providing flexible branch comparison while maintaining compatibility with existing workflows.
