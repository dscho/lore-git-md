This is the final patch (6/6) in a bugfix series addressing a regression in error message reporting for batched reference updates during fetch operations. The patch focuses specifically on restoring detailed error messages that were lost when reference updates became batched in Git 2.50+.

The key change introduces a `ref_update_display_info` structure to collate update outcomes and delay their display until after the transaction commits. This allows showing detailed error messages (like "trying to write non-commit object") in the proper context alongside the reference update status, matching pre-2.50 behavior. The implementation uses a dynamic array and strmap to track updates, with minimal performance impact (benchmarks show ~1% overhead for 1000 refs).

The patch modifies `update_local_ref()` to store rather than immediately display update information, and adds comprehensive display logic in `do_fetch()` that shows all updates in order after transaction completion. It maintains backward compatibility while fixing the regression where error details appeared after rather than with their corresponding reference updates.

Test coverage is expanded in t5516 to verify the restored error message behavior. The solution builds on earlier patches in the series that established the infrastructure for detailed error propagation through the reference transaction stack.

This completes the series' goal of restoring pre-batched-update error reporting quality while maintaining the performance benefits of batched operations. The approach was reviewed and optimized based on feedback from Phillip Wood, using `ALLOC_GROW()` for the display array. With this patch merged, the regression is fully resolved.
