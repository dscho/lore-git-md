This is a technical follow-up in the ongoing discussion about branch comparison behavior in `git status`. Jeff King (Peff) dives deeper into the implementation details needed to properly handle missing upstream refs when using DWIM (Do What I Mean) rules for branch comparisons.

The key technical challenge addressed here is how to handle cases where an upstream branch is configured but the actual tracking ref is missing. Peff proposes two specific code changes:

1. Modifying `repo_dwim_ref()` to return the branch name (without an OID) when a ref is missing but `nonfatal_dangling_mark` is set, which would allow the tracking-info code to still recognize the upstream relationship.

2. Adding a `do_not_shorten` option to `interpret_branch_name()` to preserve the fully-qualified refname when expanding @-marks, preventing information loss that could confuse the tracking-info code.

While Peff acknowledges these changes represent significant plumbing work ("how deep the rabbit-hole has gone"), he notes they might actually improve Git's ref handling more generally by smoothing out some existing rough edges. The changes would support the DWIM-based approach that Junio Hamano prefers for branch comparisons, though they add complexity to the implementation.

This email continues the technical discussion from earlier in the thread, providing concrete implementation paths rather than making new design arguments. The changes proposed here would be prerequisites for implementing the more flexible branch comparison behavior that maintains consistency with Git's standard DWIM rules.
