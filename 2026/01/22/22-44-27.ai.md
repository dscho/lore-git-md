This is a technical follow-up in the ongoing discussion about branch comparison behavior in `git status`. Jeff King (Peff) presents a concrete implementation approach for making the `status.compareBranches` feature more flexible by using Git's standard DWIM (Do What I Mean) rules for refname resolution.

The key proposal is to replace the current hardcoded remote-tracking branch resolution with a more dynamic system that can handle patterns like "%s@{upstream}" where "%s" expands to the current branch name. This would allow comparisons against derived branch names using Git's existing refspec logic rather than special-casing @{upstream} and @{push}.

Peff identifies two implementation challenges: 
1. A race condition in branch config caching during `git checkout -b` that would need to be fixed by clearing the remote state cache
2. The need to extend `repo_dwim_ref()` to handle missing upstream refs similarly to how `branch_get_upstream()` currently does

The patch demonstrates this approach would eliminate special cases and make the feature behave more consistently with Git's other ref resolution mechanisms, though at the cost of some additional complexity in the DWIM machinery. This continues the thread's progression toward a more flexible design that maintains consistency with Git's existing behavior patterns.
