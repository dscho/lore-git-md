This is a bugfix patch addressing submodule fetching behavior when submodules use non-"origin" remote names. The patch implements a `get-default-remote` submodule helper to properly handle these cases, fixing a 7-year-old NEEDSWORK comment from commit be76c21282.

The implementation adds the new helper command in `builtin/submodule--helper.c` and modifies `submodule.c` to use it instead of hardcoding "origin". The change maintains backward compatibility by falling back to "origin" if default remote detection fails. Test coverage is thorough, with new tests in `t5526-fetch-submodules.sh`, `t5572-pull-submodule.sh`, and a dedicated test file `t7425-submodule-get-default-remote.sh`.

Junio Hamano's review identifies a few minor concerns: the parse_options() usage in the helper seems unnecessary, potential edge cases around remote name validation, and some test verbosity. However, he confirms the core implementation is sound and the tests properly validate the functionality. The patch has already been reviewed by Jacob Keller and addresses all feedback from v1 and v2.

This appears ready for integration, solving a real limitation in submodule handling with comprehensive test coverage. The discussion demonstrates a complete review cycle from technical validation through presentation polish, with all identified issues resolved in v3.
