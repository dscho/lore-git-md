Thread identity: RFC patch series by Amisha Chhajed introducing `string_list_sort_u` - a combined sort+deduplicate utility for string lists.

Core problem: The string-list API currently requires separate calls to `string_list_sort` and `string_list_remove_duplicates` for the common case of wanting both operations. This series proposes combining them into a single function to simplify call sites.

Current status: Initial version (v1) with two patches - (1) adds the new API function, (2) converts existing two-step patterns to use the new function. RFC status indicates seeking design feedback before proceeding.

Key technical details:
- New function `string_list_sort_u` added to string-list.h/c
- Changes touch multiple commands: clone.c, fast-export.c, pack-objects.c, sparse-checkout.c
- Pack-objects case reveals tests depend on sorting but not necessarily deduplication
- No existing unit tests for similar string-list operations

Open questions:
- Is the combined function API design appropriate?
- Are all the converted cases actually correct (some deduplications may be unnecessary)?
- How should the new functionality be tested given current test patterns?

Participant positions:
- Junio Hamano suggested the original idea to combine these operations
- Author (Amisha Chhajed) seeking feedback on approach and testing strategy

Related work: This builds on the existing string-list API which is widely used throughout Git's codebase for managing collections of strings. The changes are mechanical but touch several important commands.
