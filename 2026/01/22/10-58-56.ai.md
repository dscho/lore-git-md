This is a performance-focused patch in the ongoing hook subsystem refactoring series, specifically addressing I/O bottlenecks in parallel hook execution. The patch modifies `run-command.c` to implement bidirectional polling of child processes' stdin and stdout file descriptors, eliminating a 100ms latency issue reported by Kristoffer Haugsbakk and preventing potential deadlocks identified by Jeff King.

The core change introduces a new pp_buffer_io()` helper that replaces the output-only polling approach, allowing the parent process to simultaneously monitor both input and output file descriptors. This maintains the existing sequential execution behavior (when ungroup=1) while significantly improving parallel hook throughput. The implementation doubles the pollfd array size to accommodate both directions and includes explicit state checking via `child_is_working()`.

Junio Hamano questions the logic of checking for positive file descriptors, noting the unusual assumption that .err cannot be 0. Adrian Ratiu acknowledges this as a quirk of run-command.c's current design but suggests fixing it would require a larger refactoring outside this series' scope. The discussion indicates this is a known limitation that Patrick Steinhardt previously raised.

This patch represents the final technical hurdle in the parallel hook execution infrastructure, with only minor documentation refinements remaining for the series. The changes have received maintainer consensus and CI validation, positioning the multi-year hook modernization effort for completion in the next iteration.
