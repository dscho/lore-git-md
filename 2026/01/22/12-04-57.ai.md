This is part 3 of a 6-part bugfix series addressing regression in error message reporting for batched reference updates. The patch focuses specifically on `git update-ref --batch-updates`.

The patch improves error reporting by propagating detailed error messages from the refs namespace to stderr while maintaining the existing machine-parsable output format on stdout. Previously, only generic error codes were shown, making it harder for users to understand and act on failures. The key changes are:

1. Modified `print_rejected_refs()` callback to output detailed error messages to stderr when available
2. Updated all test cases in t1400 to verify both the machine-readable stdout output and the detailed stderr messages
3. Added checks for specific error messages covering various failure cases:
   - Invalid object types
   - Reference existence checks
   - Symref conflicts
   - Case sensitivity issues
   - Directory/file conflicts

The patch maintains backward compatibility with existing scripts that parse the stdout format while providing more detailed diagnostics for human users via stderr. Test coverage is comprehensive, verifying both output channels for each type of reference update failure.

This builds on infrastructure changes from earlier patches in the series that added the ability to propagate detailed error messages through the refs stack. The implementation is clean and focused, with no observable performance impact for the common case where updates succeed.
