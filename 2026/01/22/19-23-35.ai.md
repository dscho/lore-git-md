This is the final version of a bugfix/feature patch implementing PID file debugging for Git locks, now ready for merging after five iterations of review. Paulo Casaretto's implementation adds companion PID files alongside lock files to help diagnose stale locks, with contributions from Jeff King, Patrick Steinhardt, Taylor Blau, and others addressing configuration, naming, Windows compatibility, and edge cases.

The patch introduces a `core.lockfilePid` config (default false) that creates `~pid.lock` files containing the locking process's PID. When lock conflicts occur, Git checks these files to provide more informative error messages distinguishing between active processes and stale locks. The solution handles Windows compatibility through mingw_kill() updates and maintains backward compatibility by reading existing files even when the feature is disabled.

Key technical details include: the `LOCK_PID_INFIX` naming scheme using tilde to avoid refname collisions, PID file format (`pid <value>`), tempfile registration for cleanup, and cross-process status checking via kill(pid, 0). The 139-line test suite (t0031) verifies behavior across platforms, including Windows-specific PID handling. Error messages carefully note PID reuse limitations to avoid implying certainty about process identity.

The implementation now addresses all review feedback, with Junio Hamano's final cleanup removing redundant file descriptor handling while preserving Windows-specific requirements confirmed by Eric Sunshine and Johannes Sixt. The patch no longer includes unrelated whitespace changes from earlier versions. All architectural concerns about NFS behavior, error handling, and Windows compatibility have been resolved through the review process.
