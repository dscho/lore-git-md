This is a follow-up discussion on the now-merged `status.compareBranches` feature, which allows configuring multiple branch comparisons in `git status` output. The technical implementation has been completed through 27 iterations, with all feedback addressed, and the core functionality is now in Git's integration branches.

Jeff King (Peff) notes a potential optimization opportunity - replacing the current `string_list` used for de-duplicating branch comparisons with a `strset` to avoid quadratic behavior when checking for duplicates. While acknowledging this isn't likely to be a practical performance issue given the expected small number of configured branches, he suggests the `strset` would be the more correct data structure choice since it provides atomic insert-and-check operations.

Harald Nordgren, the feature's author, agrees with the suggestion and indicates he will implement this change after completing CI testing. He mentions an interesting testing wrinkle - running CI from two separate GitHub pull requests to properly test both the main feature and an accompanying memory leak fix from Peff.

This exchange represents typical post-merge refinement discussion where non-critical optimizations are identified but don't block the feature's inclusion. The thread shows the project's attention to detail even after code acceptance, with contributors continuing to suggest improvements to data structures and algorithms. The `strset` optimization, while not urgent, would make the code more robust against future use cases where many branch comparisons might be configured.
