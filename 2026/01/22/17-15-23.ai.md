This is the second patch in a two-part RFC series introducing a combined sort+deduplicate utility for string lists. The patch converts several existing call sites that currently use separate `string_list_sort()` and `string_list_remove_duplicates()` calls to use the new `string_list_sort_u()` function introduced in patch 1.

The changes are mechanical replacements across multiple commands: clone, fast-export, pack-objects, sparse-checkout, help, and notes. Each conversion follows the same pattern - replacing two lines of code with one. The patch demonstrates the intended simplification of call sites that need both operations.

Notably, the pack-objects conversion shows this may affect test behavior since it changes how include/exclude packs are processed. The sparse-checkout changes are particularly interesting as they occur in the cone mode pattern handling code, which is performance-sensitive for large repositories. The notes.c change affects the notes merging logic.

As an RFC, this patch is seeking feedback on whether these conversions are appropriate - some cases may only need sorting without deduplication. The pack-objects case in particular that some tests may implicitly depend on the current behavior of sorting without deduplication. The patch doesn't include new tests specifically for the sort+dedupe behavior, which would help verify the changes.

The changes are straightforward but touch several important commands, so careful review of each conversion's context is warranted. The series builds on Junio Hamano's original suggestion to combine these common operations, and the author is looking for feedback on both the API design and the specific conversions before proceeding.
