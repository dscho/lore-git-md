This is part 3 of a 3-patch series in the `the_repository` removal effort, specifically addressing the migration of the `branch.autoSetupMerge` configuration from a global variable to repository-specific storage. The patch moves the `git_branch_track` enum (which stores the `branch.autoSetupMerge` setting) into the new `struct repo_config_values` that was introduced in part 1 of the series.

The author (Olamide Caleb Bello, an Outreachy intern mentored by Christian Couder) acknowledges Phillip Wood's review feedback about dropping the `git_` prefix from the variable name now that it's no longer global. However, the more substantial architectural concern raised in the thread - about proper handling of non-primary repository instances - remains unaddressed in this response. Phillip Wood had previously noted that the current implementation only properly initializes config values for `the_repository`, which could cause issues when code paths access config through other repository structs.

This patch follows the pattern established in parts 1 and 2 of the series, which migrated `core.attributesFile` and `core.sparseCheckout` respectively. The changes are mechanical in nature, preserving existing behavior while moving the storage location. The series as a whole represents significant progress on eliminating global configuration variables, though the non-primary repository initialization issue identified by Phillip Wood remains the key outstanding challenge that needs to be resolved in future iterations.
