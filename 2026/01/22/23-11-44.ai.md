This is a feature patch adding the `--maximal-only` option to `git rev-list`, now in its second iteration with all feedback addressed. The thread has reached consensus on the interface and implementation, with Junio C Hamano providing final conceptual clarification.

The option selects "frontier" commits - those that are maximal in reachability order within a given range, meaning they are not reachable from any other commit in the set. This is distinct from `git merge-base --independent` which finds maximal elements in the intersection of histories, not the union. The patch includes thorough documentation of this distinction and explicitly notes the incompatibility with `--boundary`.

Derrick Stolee has implemented all requested changes from the first version, including renaming from `--maximal` to `--maximal-only` per Johannes Sixt's suggestion, expanding test coverage, and adding the set-theoretic explanation of how this differs from `--independent`. The implementation uses bit 28 in the commit flag space (with acknowledgement this is a limited resource) and includes comprehensive tests for various graph topologies and edge cases.

The primary use case is optimizing bundle URI selection and bitmap generation by identifying these frontier commits.
