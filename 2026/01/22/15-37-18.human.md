This is a feature patch series that completes the multi-year effort to make branch comparison in `git status` configurable. The v27 iteration from Harald Nordgren addresses a final edge case where duplicate branch comparisons could appear when `@{upstream}` and `@{push}` resolve to the same ref.

The series introduces a `status.compareBranches` config option that accepts space-separated branch specs (like `@{upstream}` or `@{push}`) to control which branches `git status` compares against. The implementation now properly de-duplicates comparisons when multiple configured branches resolve to the same underlying ref.

Key technical improvements in this version:
- Added a `processed_refs` string list to track already-reported branches
- Skips duplicate comparisons when `@{upstream}` and `@{push}` point to same ref
- Maintains all existing functionality including triangular workflow support
- Includes comprehensive test coverage in t6040-tracking-info.sh

The patch has already gone through 26 previous iterations with extensive review, including memory leak fixes from Jeff King. Junio Hamano has queued v26, making this v27 a follow-up fix for the final edge case. With this change, the feature appears technically complete and ready for release pending documentation updates.

This represents the culmination of a long effort to make branch comparisons more flexible while maintaining backward compatibility. The implementation handles all the edge cases reviewers identified through the extensive discussion, making this a robust addition to Git's status reporting capabilities.
