This is a refactoring patch from Harald Nordgren, part of the v28 series implementing configurable branch comparison in `git status`. The patch extracts the branch comparison formatting logic from `format_tracking_info()` into a new standalone `format_branch_comparison()` function, preparing for upcoming changes that will add push remote tracking branch support.

The key change is splitting the original function into two parts: one that handles the upstream tracking state (`format_tracking_info`) and another that purely formats the comparison message (`format_branch_comparison`). The new function takes explicit parameters for branch state (up_to_date, ahead/behind counts) rather than computing them internally. This makes the formatting logic reusable for both upstream and push comparisons while keeping the message generation consistent.

The patch touches only `remote.c`, modifying 82 lines with a net +14 line change. It maintains all existing behavior while making the code more modular. This is a preparatory step that enables the subsequent patch in the series to add push branch comparison without duplicating formatting logic. The changes have already been reviewed and optimized in previous iterations, with Jeff King's suggestion to use `strset` for de-duplication implemented in v28.

This refactoring is part of the larger effort to make `git status` branch comparisons more flexible through the new `status.compareBranches` configuration. The thread indicates this feature is now code-complete and merged into Git's integration branches, with only non-technical items like final wording remaining before release.
