This is an RFC patch proposing a new utility function for Git's string-list API. The patch introduces `string_list_sort_u` which combines sorting and deduplication into a single operation, addressing a common pattern where these operations are currently performed separately.

The change is straightforward - it adds a new function that simply calls the existing `string_list_sort` followed by `string_list_remove_duplicates`. The patch includes both the implementation and header declaration with appropriate documentation. The function signature matches the existing deduplication function by including the `free_util` parameter to control whether utility pointers should be freed when removing duplicates.

As noted in the thread context, this was inspired by Junio Hamano's suggestion to combine these frequently paired operations. The RFC status indicates the author is seeking feedback on the design before proceeding further. The patch appears clean and focused, though as an RFC the main questions are around whether this is the right API design and whether all current two-step callers should actually be doing both operations.
