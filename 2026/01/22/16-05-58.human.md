This is a feature patch from Derrick Stolee adding a new `--maximal-only` option to `git rev-list`. The option filters commits to show only those that are not reachable from any other commit in the specified range, which is useful for identifying "frontier" commits in the reachability graph.

The patch comes after discussion about naming (originally proposed as `--maximal`) and now settles on `--maximal-only` as the final name. The implementation uses a new `CHILD_VISITED` flag (bit 28) in the object flags, which brings Git to using 28 of its 32 available flag bits. The documentation clearly states this option is incompatible with `--boundary` since they serve conflicting purposes.

Derrick's motivation comes from bundle URI use cases where this helps select a minimal set of reference points. The patch includes thorough test coverage showing the option works with positive/negative ranges and interacts correctly with `--first-parent`. The implementation appears clean and well-tested, with the naming concerns from earlier discussion now resolved. This looks ready for maintainer consideration.
