This is part 2/3 of a patch series by Olamide Caleb Bello (Outreachy intern) moving Git configuration variables from global storage into `struct repo_config_values` as part of the `the_repository` removal effort. The patch specifically migrates `core.sparseCheckout` from the global `core_apply_sparse_checkout` variable to `the_repository->config_values.sparse_checkout`.

The change affects 12 files across various commands that interact with sparse checkouts (`sparse-checkout`, `clone`, `grep`, `mv`, etc.), updating them to access the config value via the repository struct instead of the global variable. The implementation maintains existing behavior while making the configuration properly repository-scoped.

Toon Claes provides review feedback noting two minor issues: a duplicate "environment:" in the commit message subject line and a typo in the variable name (`core_appy_sparse_checkout`). He also questions the decision to drop the `core_` prefix from the new struct field name, suggesting it might be clearer to keep the full config section name given that the struct will contain settings from multiple config sections.

The patch appears technically sound and follows the pattern established in part 1 of the series (which migrated `core.attributesFile`). With Toon's suggested improvements addressed, this looks ready to proceed as part of the broader `the_repository` removal effort.
