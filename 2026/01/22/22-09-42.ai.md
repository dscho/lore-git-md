This is a follow-up email in the RFC thread about introducing `string_list_sort_u` to combine sorting and deduplication of string lists. Junio C Hamano responds to the author's concern about lacking unit tests for the new function.

Junio points out that while there may not be tests for `string_list_sort`, the test file `t/unit-tests/u-string-list.c` does contain tests for `string_list_remove_duplicates`. He encourages adding test coverage, noting that unit tests are relatively inexpensive to run compared to the shell-based integration tests.

The response suggests that test coverage should be addressed before the RFC moves forward, though Junio doesn't comment yet on the technical merits of the proposed API change itself. His guidance implies that demonstrating the new function's behavior through tests would strengthen the case for its inclusion.

This email doesn't introduce new technical discussion about the design or implementation, but does establish an expectation that test coverage should be part of the RFC's evolution. The thread remains in RFC status awaiting both test improvements and broader technical review.
