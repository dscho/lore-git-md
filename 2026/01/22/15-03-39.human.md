This is a follow-up bugfix from Harald Nordgren addressing a memory leak and duplicate branch reporting issue in the recently completed `status.compareBranches` feature. The feature, now queued for inclusion in v26, allows configuring which branches `git status` compares against (defaulting to both `@{upstream}` and `@{push}`). 

Harald noticed that when the upstream and push branches point to the same ref (a common case), the status was being reported twice. He's preparing a small fix to deduplicate these cases, which will be sent once CI passes. This appears to be a final polish on the technically complete feature, addressing a real but non-critical edge case that emerged from real-world usage. The fix should make the output cleaner without changing the underlying functionality.
