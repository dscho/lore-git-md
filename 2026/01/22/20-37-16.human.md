This is a final review comment from the maintainer on the now-merged `status.compareBranches` feature. Junio Hamano notes that while the current implementation handles remote-tracking branches (via `refs/remotes/` prefixing) and special cases like `@{upstream}` and `@{push}`, it may be too restrictive for comparing against other ref types like tags (`v2.52.0`). He suggests considering whether to reuse Git's existing DWIM (Do What I Mean) rules from `ref_rev_parse_rules[]` to allow more flexible branch specifications while still supporting the current remote-tracking branch syntax.

The comment comes after the feature's 28-iteration development cycle and its merge into Git's integration branches, indicating this is a blocking concern for future improvements rather than the current implementation. The observation builds on the feature's solid foundation - it already handles the core use cases with remote branches and push/upstream tracking while opening the door for enhanced flexibility in follow-up work. The maintainer's tone is thoughtful rather than critical, recognizing the current design's rationale while proposing a direction for potential expansion.
