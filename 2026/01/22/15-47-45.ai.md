This is a bugfix patch targeting the `git reset` command's reflog behavior. The patch addresses a case where `git reset` would unnecessarily write a reflog entry when the target commit matches HEAD (a no-op reset). The change prevents updating ORIG_HEAD and HEAD in this scenario, avoiding the redundant reflog entry.

The patch modifies `builtin/reset.c` to check if the target OID matches HEAD before proceeding with the reflog update, and includes a new test in `t/t1410-reflog.sh` that verifies no reflog entry is written for no-op resets. The test creates a repository, makes an initial commit, then checks that the reflog count remains unchanged after a `git reset HEAD`.

The change is straightforward and well-contained, touching only the specific behavior it aims to fix. The commit message clearly explains the motivation (avoiding unnecessary reflog entries) and the test provides clear regression protection. This appears to be a clean, focused improvement to Git's behavior.
