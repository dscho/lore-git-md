Performance optimization suggestion for the finalized branch comparison in git status.

Jeff King (Peff) notes that while Harald Nordgren's v27 implementation of `status.compareBranches` works correctly, it uses a quadratic string_list for de-duplicating branch comparisons. He suggests replacing it with the more efficient strset data structure, which handles insertion and checking in a single operation. 

This is a minor optimization - the current implementation is unlikely to cause performance issues in practice since the number of configured branches is typically small. However, Peff raises it as a matter of code hygiene, noting that quadratic string_list usage could trigger false positives during performance audits. The patch shows the exact changes needed in remote.c to make the switch.

The suggestion comes late in the process - the feature is already queued for the next release - so it's unclear whether Harald will respin the series for this change. The optimization doesn't affect functionality, just implementation efficiency. This appears to be Peff's characteristic attention to detail in reviewing code, even for already-approved patches.
