This is part 10 of a 12-part series refactoring Git's hook subsystem to support parallel execution. The patch addresses performance issues in the I/O polling mechanism when running hooks in parallel.

The key change here is modifying the run-command I/O loop to poll both child input and output file descriptors, fixing a throughput bottleneck that could cause 100ms delays when feeding data to multiple parallel hooks. This prevents potential deadlocks where parent and child processes might block waiting for each other.

The issue was originally reported by Kristoffer Haugsbakk, with input from Jeff King about the deadlock risk. The solution maintains backward compatibility - sequential hook execution (the default) remains unaffected since it uses different I/O handling.

Adrian notes a minor documentation fix needed for v8 (correcting "stdout" to "stderr" in the commit title) but the technical implementation is sound. The series as a whole has maintainer approval and is nearing finalization after addressing all major technical concerns. This particular patch represents one of the last performance optimizations needed before the series can be merged.
