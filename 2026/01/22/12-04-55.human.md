This is a bugfix patch in the refs subsystem, part of a 6-patch series addressing reference verification issues. The patch fixes a problem where rejected ref updates in batched operations would incorrectly retry the same reference multiple times due to a misplaced `continue` statement.

The issue occurs in `refs_verify_refnames_available()` where nested loops check for reference conflicts. When a conflict is found, the code was only skipping to the next iteration of the inner loop rather than moving to the next reference in the outer loop. The fix replaces the `continue` with a `goto` to properly skip to the next reference.

The patch also makes related changes to error handling, ensuring rejection details are properly stored in the transaction object rather than being lost. This affects multiple ref backends (files, packed, and reftable) and requires updates to the refs internal API to pass along error details.
