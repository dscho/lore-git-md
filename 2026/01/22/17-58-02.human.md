This is a security-related discussion about ANSI escape sequence handling in Git's sideband channel, continuing the thread about CVE-2024-32002 and CVE-2024-52005/GHSA-7jjc-gg6m-3329.

Junio Hamano weighs in on the ongoing debate about default security settings for sideband control character handling. He aligns with brian m. carlson's position advocating for backward-compatible "opt-in" behavior, citing real-world usage patterns observed at GitHub and Red Hat distributions. This directly counters Johannes Schindelin's strong stance that security protections should be enabled by default.

The core disagreement centers on whether to maintain the current behavior (which filters all but color sequences by default) or revert to historical unfiltered behavior. Junio makes clear he favors the latter approach, expressing concern about breaking workflows that might depend on non-color control sequences. He rejects the notion that allowing colors while filtering other sequences represents a coherent middle ground, calling this approach inconsistent.

Notably, Junio acknowledges Schindelin's security concerns but prioritizes compatibility, suggesting that if the proposed trust-based filtering isn't practical, the alternative would be to disable all filtering by default rather than maintain partial filtering. The exchange highlights the tension between security hardening versus maintaining existing behavior, with Junio as maintainer signaling his inclination toward preserving backward compatibility even at some security cost.

The thread remains technically unresolved, with Junio inviting further discussion about what exactly "opt-in" should mean in this context. His references to GitHub and Red Hat experiences suggest he's looking for concrete data about real-world impact to inform the final decision.
