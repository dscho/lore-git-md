This is a review comment on the final patch (7/7) in a completed bugfix series about restoring detailed error messages in batched reference updates. Phillip Wood raises concerns about the implementation's output ordering being dependent on `strmap_for_each()` iteration, which could change in the future. He suggests an alternative approach using an array to maintain deterministic ordering while still collecting errors in a separate strmap.

The patch being discussed implements delayed output of fetch status messages by introducing a `ref_update_display_info` structure to collate update outcomes. While this successfully restores the detailed error messages that were lost in batched updates, Phillip notes two issues: the message order is now implementation-dependent, and the test expectations had to be updated to match the new output sequence.

Phillip proposes modifying the approach to:
1. Store updates in an array to preserve original order
2. Keep errors in a strmap for lookup
3. Print by iterating the array and checking the strmap for failures

This would maintain the restored error details while making the output order predictable and stable across future implementation changes. The suggestion comes late in the series (after the patches have been merged) but identifies a potential robustness concern worth considering for future iterations.
