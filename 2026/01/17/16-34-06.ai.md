This is part of the ongoing xdiff refactoring series aimed at Rust interoperability, specifically addressing René Scharfe's question about memory allocation in patch 9/10. The patch removes xdlclassifier dependence from xdl_cleanup_records() by introducing a new IVec-based approach.

Ezekiel Newren defends the IVec implementation choice over CALLOC_ARRAY, explaining it serves dual purposes: (1) providing a familiar interface for C developers that mirrors Rust's Vec behavior, and (2) easing future conversion to Rust. He details the technical differences - IVec's ivec_zero() handles both memory allocation and initialization while tracking length/capacity, unlike CALLOC_ARRAY which only allocates. The response includes Rust equivalents showing both safe and unsafe versions of similar operations.

The exchange highlights the series' broader tension between C standards compliance and Rust compatibility goals. Newren's justification suggests this pattern may recur as more subsystems are adapted for Rust interop. The technical merits of each approach remain under discussion, with the IVec method offering Rust-aligned semantics at the cost of introducing non-standard C patterns.
