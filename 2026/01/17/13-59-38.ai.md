This is a feature patch adding gettext support detection to Git's version reporting. Jiang Xin's v2 follows up on Junio's feedback from the initial version, simplifying the output to only show "gettext: enabled" when support is compiled in (rather than explicitly showing "disabled" when absent).

The patch adds a line to `git version --build-options` (and consequently `git bugreport`) to indicate whether the binary was built with gettext support. This helps diagnose localization issues by letting users confirm whether missing translations stem from build configuration rather than runtime settings. The implementation checks the `NO_GETTEXT` define and adds a single positive affirmation when gettext is available.

Notably, this diverges from the precedent set by Rust support detection (which shows "disabled" when absent) but aligns with Junio's suggestion that negative states need not be reported. The patch is small and focused, touching only `help.c` to add the conditional output line. It appears ready for inclusion pending any further discussion about output format consistency with other build options.
