This is a CI optimization patch that builds on Johannes Schindelin's earlier change to skip git-svn tests during leak-checking jobs. Junio C Hamano now proposes extending the same approach to CVS and Perforce (p4) tests, which Phillip Wood noted also consume significant CI time (24 minutes) without contributing meaningfully to C memory leak detection.

The patch introduces `NO_CVS_TESTS` and `NO_P4_TESTS` environment variables, mirroring the existing `NO_SVN_TESTS` mechanism. When set during leak-checking jobs (`linux-leaks` and `linux-reftable-leaks`), these variables cause the corresponding test suites to skip execution entirely. The implementation follows the established pattern of adding early-exit checks in the test library files (`t/lib-cvs.sh` and `t/lib-git-p4.sh`).

This change continues the thread's theme of practical CI runtime optimizations by excluding tests that don't align with the specific goals of leak-checking jobs. The patch is straightforward and uncontroversial, with Junio indicating general approval of the direction. Phillip Wood's original suggestion about potentially broader exclusions via `NO_PYTHON`/`NO_PERL` remains as a possible future optimization path, but this patch focuses specifically on the CVS and Perforce test suites.
