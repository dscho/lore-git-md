This is the third and final patch in a series by Olamide Caleb Bello (an Outreachy intern mentored by Christian Couder) that moves configuration variables from global scope into `struct repo_config_values` as part of the ongoing `the_repository` removal effort. The patch migrates the `branch.autoSetupMerge` configuration, which controls whether new branches are automatically set up to merge with their upstream counterparts.

The change removes the global `git_branch_track` variable and moves it into the repository-scoped `repo_config_values` struct, updating all callers to access it via `the_repository->config_values.git_branch_track`. The patch touches several commands that use this setting, including `branch`, `checkout`, `push`, and `submodule--helper`. The initialization sequence ensures the default BRANCH_TRACK_REMOTE value is set before `git_default_config()` is called.

This completes the series' goal of demonstrating the pattern for repository-scoped configuration by migrating three representative variables (`core.attributesFile`, `core.sparseCheckout`, and now branch.autoSetupMerge`). The implementation follows Phillip Wood's suggestion to use a dedicated config struct rather than overloading `repo-settings`. While broader architectural questions about config scoping remain open (as noted by Junio C Hamano in earlier discussion), this concrete migration appears ready for merging as it maintains existing behavior while advancing the `the_repository` removal effort.
