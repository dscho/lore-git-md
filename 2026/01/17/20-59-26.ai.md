Part of the `the_repository` removal effort, this patch migrates the `core.attributesFile` configuration from a global variable to a per-repository struct. This is the first in a 3-part series by Olamide Caleb Bello (Outreachy intern mentored by Christian Couder) that establishes patterns for moving repository-dependent config values out of global scope.

The patch introduces `struct repo_config_values` embedded in `struct repository` to hold config values that vary per-repository. It moves the `git_attributes_file` global into this struct as `attributes_file_path`, with initialization handled by a new `repo_config_values_init()` function. The change maintains existing behavior while enabling future libification by removing global state.

Key technical aspects:
- The struct avoids heap allocation by being directly embedded in `struct repository`
- Initialization happens during repository setup via `initialize_repository()`
- Access patterns remain similar but now go through `the_repository->config_values`
- The change touches core config handling in `git_default_core_config()`

This serves as a template for future config migrations in the broader `the_repository` removal effort. The series shows careful attention to initialization sequencing and maintains backward compatibility while making architectural progress. The implementation follows Phillip Wood's suggestion to use a dedicated config struct rather than overloading `repo-settings`.
