This is a technical discussion about type safety in the xdiff refactoring series, specifically around the `ivec` implementation that's part of the Rustification effort.

Phillip Wood and René Scharfe are discussing undefined behavior concerns in the current `ivec` implementation, which casts between different pointer types (`IVec_c_void*` and `IVec_u8*`) in ways that violate C standards. While this works in practice on Git's supported platforms, it's technically undefined behavior that could theoretically cause problems with aggressive compiler optimizations.

Phillip proposes an alternative approach that would be standards-compliant by passing individual struct members as function parameters rather than casting whole structs. René confirms this would work but notes it would require more boilerplate code. Both acknowledge they don't know how this would affect the Rust side of the implementation.

The discussion represents one of three parallel technical threads in this patch series (along with performance characteristics and simplification opportunities). It highlights the careful balancing act required when refactoring core infrastructure to support both C and Rust while maintaining standards compliance and performance. The outcome here may set important precedents for future Rust interop work in Git.
