This is a feature patch adding gettext support detection to Git's version reporting. Jiang Xin's v2 follows up on maintainer feedback to simplify the output format - it now only shows "gettext: enabled" when support is compiled in, remaining silent otherwise, rather than explicitly stating "disabled".

The change helps diagnose localization issues by letting users confirm whether their Git binary was built with gettext support. The implementation adds a simple conditional block in `help.c` that checks the `NO_GETTEXT` define. The patch is clean and focused, touching just three lines to add the new output alongside similar build option reports like fsmonitor and libcurl.

Junio had suggested this simpler approach in response to v1, preferring it over the initial design that mirrored Rust's "enabled/disabled" reporting style. The thread remains open on whether Rust's output should be updated to match this new convention, but that's treated as a separate question. This version appears ready for merging as it addresses the maintainer's feedback directly.
