This is part of Patrick Steinhardt's ongoing refactoring series to centralize packfile management in `struct packfile_store`. Patch 06/15 moves the migration of the "kept packfile cache" from `struct object_database` to `struct packfile_store`, completing the transition of all packfile-related state.

The patch relocates the `kept_pack_cache` structure and its associated flags from `object_database` to `packfile_store`, renaming it to `kept_cache` in the process. It updates all access sites in `packfile.c` to use the new location, including the existing invalidation logic in `maybe_invalidate_kept_pack_cache()` and the cache population in `kept_pack_cache()`. The changes are mechanical with no behavioral modifications.

The commit notes this completes the migration of all packfile-related state from the object database to the packfile store, as reflected in the updated comment for the `packfiles` pointer in `struct object_database`. The patch maintains the existing optimization behavior where the cache is invalidated when flags mismatch, just now operating on the new location.

This continues the architectural work established in earlier patches, with the same careful attention to preserving existing behavior while moving implementation details. The changes touch the same key files as previous patches in the series (odb.[ch], packfile.[ch]) and follow the established pattern of mechanical relocation with minimal interface changes.
