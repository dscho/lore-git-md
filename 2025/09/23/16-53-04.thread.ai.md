Thread identity: Subject is about localization of git-format-patch email headers ("Range-diff:" and "Interdiff:"). Originating author is Kristoffer Haugsbakk. Thread type is a design discussion about l10n edge cases in technical workflows.

Core problem: These technical email headers are being translated based on user locale, which may be problematic when patches are sent to international mailing lists where English is the standard. The behavior dates to 2018 implementations but lacks documented rationale. Discussion now centers on whether these specific headers should be exempt from translation.

Current status: Eric Sunshine has provided historical context that the 2018 translation was intentional but acknowledges this is only the second time the decision has been questioned. No changes made yet, but Sunshine indicates openness to reverting the behavior.

Key technical details: Affects git-format-patch output headers that are part of patch submission workflow, specifically the `_("Interdiff against v%d...")` and similar range-diff format strings. Localized strings come from translation infrastructure that otherwise makes sense for user-facing messages. Discussion references Junio Hamano's prior rejection of diffstat translation as precedent for keeping technical outputs in English.

Open questions: Should these headers remain translatable given some projects may prefer non-English technical headers? What's the right balance between localization consistency and technical workflow needs? Is there sufficient justification to change the current behavior?

Participant positions: Kristoffer Haugsbakk raised the concern as potentially counterproductive. Eric Sunshine provided historical context and indicated he wouldn't oppose a change, while noting the original decision had arguments on both sides. No other positions stated yet.

Related work: References original 2018 commits introducing these headers (with translations) but finds no discussion about the localization aspect. Connects to broader questions about what should/shouldn't be translated in technical outputs, with diffstat translation rejection as precedent.
