Documentation patch reorganizing git-push rules into a dedicated section. This is the first of two patches in a series that has already gone through review and iteration, with maintainer approval pending.

The patch extracts all push validation rules from their previous location embedded in the refspec documentation and moves them to a new standalone "PUSH RULES" section at the end of git-push.adoc. This creates better referenceability and allows the --force documentation to focus specifically on branch updates while deferring tag/other ref details to the new section. The changes are purely organizational - 45 lines added and 49 removed - with no behavioral changes.

Key improvements in this version (v2) incorporate Junio Hamano's feedback: clarifying that the source for branch updates must be a commit, simplifying tag object explanations, and making creation/deletion rules more explicit. The patch also adds proper cross-references between sections, including from the refspec description to the new rules section.

The technical discussion around man page formatting (indentation styles) has been resolved with consensus to maintain current formatting, making this patch ready for merge. The series as a whole demonstrates careful attention to review feedback while achieving its goal of improving documentation structure and clarity around push behaviors.
