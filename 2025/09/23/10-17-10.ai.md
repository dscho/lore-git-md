This is part of Patrick Steinhardt's packfile store refactoring series (v6 11/15), which centralizes packfile management in `struct packfile_store` as part of the ODB abstraction effort.

The patch introduces a new helper function `packfile_store_load_pack()` that combines the common pattern of checking if a packfile exists in the store and adding it if not. The function handles the key reconstruction (converting .idx to .pack path) and hashmap lookup internally. This replaces several instances of manual packfile loading and addition across the codebase.

Key technical details:
- New function signature: `packfile_store_load_pack(store, idx_path, local)`
- Handles path conversion from .idx to .pack for hashmap lookups
- Combines `add_packed_git()` and `packfile_store_add_pack()` operations
- Updates callers in fast-import.c, index-pack.c, midx.c, and packfile.c
- Maintains all existing behavior while reducing code duplication
- Part of establishing clear packfile/ODB separation in the architecture

The changes are mechanical refactoring with no functional impact, continuing the series' goal of clarifying architectural boundaries. The patch follows the established pattern of moving packfile-specific logic into the packfile store abstraction.
