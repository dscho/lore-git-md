This is a governance discussion email in the ongoing Rust transition thread, focusing on LTS (Long-Term Support) repository management models. Johannes Schindelin responds to Patrick Steinhardt's proposal for keeping LTS releases within the canonical Git repository rather than maintaining them in a separate fork.

Schindelin strongly supports Steinhardt's position against Junio Hamano's separate-repository proposal, framing the issue as fundamentally about trust - both in terms of code quality and user perception. He raises concerns that external LTS maintenance would be unprecedented in successful open source projects and could lead to confusion, reduced oversight, and potential hard forks.

The email introduces a concrete counter-proposal: appointing a trusted "LTS lieutenant" (specifically nominating Steinhardt for this role) following the Linux kernel model. This approach would maintain centralized governance while providing dedicated maintenance for older releases. Schindelin emphasizes this would satisfy professional users' demands for predictable LTS policies while avoiding the risks of fragmentation.

Key technical governance points:
- Rejects the separate-repository model as impractical and untrustworthy
- Proposes formalizing LTS maintenance as a project role rather than community effort
- Suggests the LTS maintainer could help prevent compatibility-breaking fixes
- Notes professional user demand for structured LTS policies

The email represents a significant escalation in the LTS discussion, moving from abstract models to specific personnel proposals while maintaining the Rust transition context (where LTS would support platforms unable to adopt Rust). Schindelin's lieutenant proposal attempts to bridge the gap between Hamano's separation approach and Steinhardt's integration preference by institutionalizing LTS within the core project structure.
