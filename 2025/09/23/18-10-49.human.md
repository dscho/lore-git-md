This is the second patch in a documentation series reorganizing the git-push man page's refspec section. It follows up on the first patch (already merged) that extracted push rules into a dedicated "PUSH RULES" section.

Julia Evans rewrites the refspec specification to be more structured and example-driven, addressing user feedback that the previous version was hard to understand. The new version presents refspec forms as a clear bulleted list with concrete examples for each case, including two previously undocumented forms (pattern refspecs with `*` and negative refspecs with `^`). The rewrite maintains all technical accuracy while making the syntax and expansion rules more approachable.

Key improvements include:
- Explicit documentation of pattern matching (`refs/heads/*`)
- Coverage of negative refspec exclusions (`^refs/heads/dev-*`)
- Clearer explanation of the `+` prefix as equivalent to `--force`
- More precise wording around ref expansion rules
- Better examples throughout

The patch has already incorporated feedback from Junio Hamano in v2, simplifying tag object explanations and clarifying commit vs branch reference wording. The changes are purely documentation - no behavior is altered - and the patch appears ready for merging as the final piece of this refspec documentation improvement.
