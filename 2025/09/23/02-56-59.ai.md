Feature patch adding machine-parseable output format to `git repo stats`, part 3/4 in the repository health metrics series. This implements the `--format=keyvalue` option previewed in the roadmap, producing output with `key=value` pairs for each statistic. The default `table` format remains unchanged for human consumption.

The implementation introduces a new `stats_print()` function that emits the same metrics as the table format but in a parseable layout. Keys follow a structured naming scheme like `references.branches.count` and `objects.commits.count`. The patch maintains the existing architecture by cleanly separating format handling from data collection, with the stats gathering code unchanged. Tests verify the key-value output matches expectations in a sample repository.

This builds on the object counting infrastructure from patch 2, completing one of the planned output formats while leaving NUL-delimited output for future work. The implementation is thorough, with careful attention to string formatting (using `PRIuMAX` for portability) and clear error handling for unsupported format combinations. The documentation updates explain both formats while noting the table format remains unstable for scripts.
