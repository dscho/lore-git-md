This is a documentation patch series aimed at improving the clarity of `git-pull`'s man page, specifically focusing on the DESCRIPTION section. Julia Evans proposes four changes based on feedback from 15 Git users, with the goal of better explaining `git pull`'s relationship with fetch/merge/rebase, clarifying the current default behavior (--ff-only), and helping users quickly find the commands they need for different integration strategies.

The series takes an "aggressive" approach to streamlining the documentation, removing some content (including an example) while keeping what Evans considers the most important information. The changes reference another pending documentation patch about upstream branches, so the approach may need adjustment if that isn't merged first.

The patches reorganize parameter descriptions, clarify integration options, remove an example, and add guidance for handling merge conflicts. The changes appear well-motivated by user feedback and focus on practical usability concerns rather than theoretical completeness. The author explicitly invites feedback on whether the cuts go too far, suggesting this is a starting point for discussion rather than a final proposal.
