This is a cover letter for a feature series introducing a new `git repo stats` subcommand to analyze repository health metrics. The series aims to bring git-sizer-like functionality into core Git, starting with basic object and reference counting before expanding to more complex metrics in future work.

The patch series adds a new `stats` subcommand to `git-repo` that currently provides counts of repository objects (blobs, trees, commits, tags) and references. It supports three output modes: human-readable, key-value pairs, and NUL-delimited for scripting. The implementation includes thorough documentation and tests covering all output formats.

Key technical details include:
- New `builtin/repo.c` implementation with `cmd_repo_stats()` entry point
- Three output formats via `--format` option (default human-readable, plus keyvalue and nul)
- Stats collection via `for_each_*` iterators over objects and references
- New test file `t/t1901-repo-stats.sh` verifying all functionality
- Planned future additions noted in cover letter (size metrics, concern levels, reference filtering)

The author positions this as an initial step toward git-sizer parity, with clear extension points for more sophisticated analysis. The implementation appears thorough, including multiple output formats from the start and comprehensive tests. The cover letter thoughtfully outlines both immediate capabilities and future directions, suggesting this is a well-planned feature introduction.
