This thread raises a question about Git's localization approach for patch email headers. Kristoffer Haugsbakk notes that "Range-diff:" and "Interdiff:" headers in git-format-patch output are translated according to the user's locale, which may cause confusion when these emails are sent to international mailing lists where English is the common language.

The behavior dates back to 2018 when these features were introduced, but there doesn't appear to have been prior discussion about whether these technical headers should be treated differently from other user-facing strings. The core issue is that while translating error messages and help text makes sense for local use, these particular headers serve as machine-readable markers in a workflow where English is effectively the standard.

This seems to be an edge case where Git's general localization policy may need refinement. The thread invites discussion about whether these specific headers should be exempt from translation to maintain consistency in the patch submission workflow. No solutions or alternatives have been proposed yet - the email primarily seeks to surface what appears to be an overlooked aspect of Git's internationalization approach.
