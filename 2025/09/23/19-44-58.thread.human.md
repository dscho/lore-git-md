Julia Evans has proposed a documentation patch series to improve the clarity of the `git-pull` man page, based on research with 15 Git users. The series aims to address common pain points by restructuring content and making key information more accessible while maintaining technical accuracy.

The first patch, which just arrived, focuses on parameter documentation. It moves the descriptions of `<repository>` and `<refspec>` parameters from the DESCRIPTION section to OPTIONS, where they more naturally belong. The explanations are expanded to be clearer about terminology (using "upstream" instead of "remote/merge configuration") and what these parameters can accept (branch, tag, or other reference for refspec; URLs or remote names for repository). This restructuring lets the DESCRIPTION section focus on `git pull`'s high-level behavior (fetch + merge/rebase) without mixing in parameter details.

The series as a whole will restructure `git-pull.adoc` with a net reduction in lines while improving clarity around key topics: the relationship between `git pull` and underlying commands, current default behavior (--ff-only), choosing between merge/rebase/squash, and conflict resolution guidance. Julia acknowledges the changes are "aggressive" in their streamlining and is seeking feedback on whether they might oversimplify. The work depends on a pending upstream branch documentation change.
