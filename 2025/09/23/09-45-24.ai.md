This is a refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust implementation by standardizing integer widths.

The patch changes the varint implementation to use explicit integer widths (`uint64_t` for values, `uint8_t` for lengths) instead of platform-dependent types like `uintmax_t` and `int`. This is motivated by two factors: the known maximum values in the varint encoding scheme (16 bytes max), and the upcoming Rust reimplementation which benefits from fixed-width types. The changes touch four files (`dir.c`, `read-cache.c`, `varint.c`, `varint.h`) with straightforward mechanical conversions of type declarations and function signatures. The most notable changes are in `varint.h` where the public interface now declares fixed-width returns (`uint8_t` for encode length, `uint64_t` for decode value).

This appears to be a well-contained preparatory change that follows the pattern of Ezekiel Newren's earlier work (credited in Suggested-by). The patch maintains the existing varint encoding/decoding logic while making it more portable and Rust-friendly. As part of the larger Rust transition effort, this helps establish clear type boundaries between C and Rust code, particularly important since varints are slated to become the first mandatory Rust component in Git 3.0. The changes are focused and don't introduce new behavior, just more precise type specifications where the value ranges were already constrained by the varint format.
