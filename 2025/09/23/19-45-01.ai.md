This is the third patch in Julia Evans' documentation series improving the `git-pull` man page. The patch removes a historical example that showed `git pull` performing a merge, which is misleading since the default behavior is now `--ff-only`. The example was identified as confusing in user research, as it implied merges were the default integration strategy.

The removal simplifies the documentation by eliminating 26 lines of example text that no longer matches current behavior. The author considered replacing it with a fast-forward example but decided against it, noting fast-forwards are simple enough to understand without illustration. This change aligns with the series' goal of making the documentation more accurate and focused on current behavior.

Key technical points for future reference: the example showed a merge scenario with commit history visualization (A-B-C vs D-E-F-G leading to merge commit H), which is now been removed entirely. The patch maintains the surrounding text about conflict resolution and Git version compatibility that follows the example. This continues the series' pattern of streamlining while preserving technical accuracy.
