This is a follow-up discussion on part 1 of a two-part series fixing `git format-patch`'s inconsistent notes display between commit messages and range-diff output. The patch adds a `rdiff_other_arg` strvec member to `rev_info` to properly handle notes arguments for range-diff subprocesses.

The email addresses Junio C Hamano's review feedback on the initial submission. Key points:
1. Clarifies the motivation - ensuring notes namespaces match between commit message output and range-diff sections when using `--notes` options.
2. Acknowledges and fixes the initialization oversight in `REV_INFO_INIT` by adding `.rdiff_other_arg = STRVEC_INIT`.
3. Discusses potential renaming of `rdiff_other_arg` (suggesting `log_arg` or `log_args`) since it's not just for notes but also handles other arguments like `--merges`.
4. Notes the member's purpose is to pass arguments verbatim to the `git log` subprocess in range-diff.c.

Technical context:
- The strvec passes arguments like `--notes=custom` and `--merges` to range-diff's log subprocess
- Current implementation in `builtin/range-diff.c` uses similarly named `other_arg`
- Recent change f8043236 added `--merges` support via this mechanism

Open questions from discussion:
- Final naming of the struct member (`rdiff_other_arg` vs alternatives)
- Whether to split the naming change into a preliminary patch
- Need to update commit message to better explain the consistency goal

The exchange shows the patch is moving toward acceptance but needs minor refinements before v2. The technical approach appears sound, with the discussion focusing on proper initialization and naming conventions rather than fundamental design.
