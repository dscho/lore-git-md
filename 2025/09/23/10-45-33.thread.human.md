This thread discusses the proposal for a new `git refs get` plumbing command, which would provide direct reference lookup without DWIM (Do What I Mean) expansion. The command is positioned as part of a broader effort to consolidate reference-related operations under a unified `git-refs` subcommand family.

The discussion has revealed three main perspectives: Patrick Steinhardt and the original authors advocate for the new command as part of a long-term organization of reference operations, while Ben Knoble has raised concerns about discoverability and suggested adding optional DWIM behavior via flags. Junio Hamano has strongly questioned the need for a new command, arguing that extending `git show-ref` with similar functionality would be preferable and expressing skepticism about the benefits of command consolidation.

In the latest exchange, Patrick has defended the architectural approach, emphasizing that grouping all ref operations under `git-refs` would improve discoverability through tab completion and unified documentation. He contrasts this with the current situation where users must remember multiple specialized commands (`show-ref`, `symbolic-ref`, etc.). While open to adding DWIM behavior based on feedback, Patrick maintains that the new command family offers better long-term organization.

The fundamental question remains unresolved: whether this functionality should live in a new command as part of Patrick's consolidation vision or be added to the existing `show-ref` tool as Junio prefers. The discussion continues to weigh the tradeoffs between architectural purity, discoverability, and practical usability.
