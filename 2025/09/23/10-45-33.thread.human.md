This thread introduces a new plumbing command, `git refs get`, developed during GSoC to provide predictable reference reading without DWIM (Do What I Mean) expansion—unlike `git rev-parse`. The command requires exact refnames, shows symref targets directly (without dereferencing), and returns raw OIDs for regular refs. The initial patch is well-tested and documented, with the design choice to avoid DWIM behavior highlighted as a feature for scripting reliability.

Ben Knoble has raised concerns about whether the strict no-DWIM approach might limit usability in scripts, where `rev-parse`'s DWIM behavior can simplify handling user input. He suggests a potential `--dwim` flag as a compromise, though this would reintroduce some of the complexity the new command aims to avoid. The discussion now centers on whether the trade-off between strictness and convenience is justified, or if a middle ground (like an optional flag) should be considered. This revisits earlier design decisions and may prompt further debate on the command's intended use cases.
