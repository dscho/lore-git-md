This thread discusses the introduction of a new `git refs get` plumbing command, developed during GSoC with mentorship, that provides strict reference lookup without DWIM expansion (unlike `git rev-parse`). The command shows direct symref targets without dereferencing and returns raw OIDs for regular refs.

The discussion has seen three main perspectives emerge: Ben Knoble questioned whether removing DWIM might hurt scripting use cases, suggesting a future `--dwim` flag; Junio Hamano challenged creating a new command, proposing instead to extend `git show-ref` with a `--no-deref` option; while Patrick Steinhardt defended the new subcommand approach as better organizing reference operations long-term, while remaining open to optional DWIM support.

In the latest email, Patrick provides detailed code review feedback on the implementation, focusing on documentation wording (making it algorithm-agnostic), error message improvements, and code organization. The review maintains the architectural vision while refining implementation details, shifting the discussion from high-level design to specific improvements needed before merging. The core question of command organization (new subcommand vs extending show-ref) remains open, though Patrick's position favoring the new command appears to be carrying the day given his role as mentor and the implementation's progress.
