This thread introduces a new plumbing command `git refs get` as part of a GSoC project. The command provides a predictable way to read reference values without DWIM expansion (unlike `git rev-parse`) and with clearer discoverability than `git show-ref --verify`. It requires exact refnames, shows direct symref targets without dereferencing, and returns raw object IDs for regular refs.

The implementation adds a new `cmd_refs_get()` function in `builtin/refs.c`, documents the subcommand in `git-refs.adoc`, and includes comprehensive test coverage in a new test file `t/t1464-refs-get.sh`. The tests verify basic ref reading, symref handling (including dangling symrefs), error cases, and explicitly confirm the non-support for DWIM behavior.

The patch appears well-considered and cleanly implemented, with a clear commit message explaining the motivation and advantages over existing alternatives. The design choice to show symref targets rather than dereferencing them is explicitly called out as a feature. This looks like a useful addition to Git's refs plumbing interface, particularly for scripting use cases where predictable behavior is important.
