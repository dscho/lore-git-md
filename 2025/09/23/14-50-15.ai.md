This is a continuation of the discussion about handling deprecated commands in Git's build system, specifically focusing on documentation aspects when `WITH_BREAKING_CHANGES` is enabled.

Patrick Steinhardt responds to Junio Hamano's technical assessment about the challenges of maintaining documentation for deprecated commands. While Patrick had previously suggested keeping man pages with deprecation notices, he acknowledges Junio's point about the significant build system changes this would require due to the current tight coupling between binary installation and man page generation.

The email shows Patrick conceding to a more incremental approach - first focusing on simply not installing manpages for deprecated commands (like `git-whatchanged`) when they are excluded via `EXCLUDED_PROGRAMS`. He leaves open the possibility of someone implementing his more comprehensive documentation approach later, but accepts that the current system's architecture makes this non-trivial.

This moves the thread toward resolution on the immediate issue while keeping the door open for future improvements to how Git handles documentation for deprecated commands. The technical constraint remains that the build system currently treats binary exclusion and documentation exclusion as inseparable operations.
