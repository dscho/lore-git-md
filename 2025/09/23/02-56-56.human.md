Feature proposal: introducing a `git repo stats` subcommand to analyze repository health.

Justin Tobler proposes adding a new `stats` subcommand to `git-repo` to help users assess repository health by surfacing key metrics. The initial implementation focuses on counting reference and object types, with plans to expand functionality to match third-party tools like git-sizer. The patch series (4 parts) adds basic counting capabilities plus output formatting options (key-value and NUL-terminated formats).

The motivation is solid - currently users need specialized knowledge or external tools to assess repository structure, while this would make key metrics readily available. The commit messages and test coverage (a new 157-line test script) appear thorough. The author clearly outlines future directions including concern-level indicators, object links, reference filtering, and progress meters.

This looks like a well-considered initial step toward bringing repository analysis capabilities into core Git. The scope is appropriately limited for a first version while laying groundwork for future expansion. The implementation appears clean and follows Git's established patterns.
