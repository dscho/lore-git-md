This is a follow-up discussion in the dangling symrefs thread, where Jeff King provides additional guidance on proper deletion patterns for dangling symrefs.

Jeff responds to Toon Claes' agreement about avoiding the double-null-oid invocation pattern, suggesting a more precise approach using `symref-delete` when dealing with dangling symrefs. He explains that while a simple `delete` would work, it's less safe as it operates unconditionally. The `symref-delete` command allows specifying the expected target, providing atomic verification that the symref hasn't changed unexpectedly before deletion.

The email serves as a practical recommendation for the Gitaly team's implementation, suggesting they use the more precise API when they know the symref's expected target. This continues the thread's theme of encouraging proper usage patterns while maintaining the original technical solution in the patch series. The discussion appears to be wrapping up with consensus on both the API design and downstream adoption.
