This is a bugfix patch addressing inconsistency in `git format-patch`'s handling of Git notes when used with range-diff for single-commit cases. The patch is part 2 of a series that has already seen review and naming approval from Junio C Hamano.

The core issue is that when generating a single-patch format-patch with range-diff, notes display behaves inconsistently between the main commit message and the range-diff section. Currently, `--no-notes` has no effect on the range-diff output, which always shows default notes like regular `git log` would, while the main message respects the notes options.

The patch fixes this by properly propagating notes arguments to the range-diff subprocess. Junio confirms this will also address the `--no-notes` case. There's some minor cleanup needed in the commit message wording (noted with a typo correction about `--[no-]--notes` formatting), but the technical approach appears sound.

This builds on part 1's preparatory refactoring that added a `log_args` member to `rev_info` for passing these arguments. The series has active review participation, with naming settled and only commit message clarifications remaining before likely acceptance. The fix maintains existing behavior for multi-commit cases while resolving the single-commit inconsistency.
