This is a governance discussion in the ongoing Rust infrastructure thread, specifically about how to handle LTS (Long-Term Support) releases for users who cannot or do not want to use Rust-mandatory versions. Junio Hamano responds to Patrick Steinhardt's concerns about maintaining LTS releases outside the main Git repository.

Hamano advocates for a "friendly fork" model similar to Git for Windows, where LTS would be maintained by trusted, competent developers in a separate repository, with clear coordination points (like security disclosures) but without requiring main project approval. He strongly disagrees with Steinhardt's apparent assumption that LTS maintainers would be less competent, arguing this would only harm Git's reputation if the project rubber-stamped their work.

The exchange reveals a philosophical divide: Steinhardt wants LTS tightly integrated with the main project's workflow and branding, while Hamano prefers a more decentralized approach that trusts external maintainers. This discussion doesn't introduce new technical elements but clarifies governance positions as the Rust transition approaches its final stages. The tone remains constructive, with both sides seeking a workable model for post-Rust-mandate support.
