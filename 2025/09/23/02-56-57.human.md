Feature patch introducing the first part of a new `git repo stats` subcommand, focused on counting repository references. This is the initial patch in a series that aims to bring git-sizer-like functionality into core Git.

The patch adds a `stats` subcommand to `git repo` that currently counts and categorizes references (branches, tags, remotes, and others) in a repository, presenting the results in a human-readable table format. The implementation uses Git's existing ref-filter infrastructure and includes automatic column width adjustment to accommodate the data. 

The commit message clearly explains this as a first step toward more comprehensive repository health metrics, with future patches planned to expand the functionality. The implementation appears solid, with thorough test coverage in `t/t1901-repo-stats.sh` that verifies both empty repositories and those with various reference types. The documentation is updated to describe the new subcommand while noting the output format may change.

This looks like a well-structured foundation for the planned feature expansion, with clean code and good attention to detail in both implementation and testing. The reference counting functionality is straightforward but useful, and the table formatting shows thoughtful design for human consumption.
