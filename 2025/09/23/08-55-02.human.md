This is a bugfix patch addressing an inconsistency in `git rebase -i`'s behavior with the `fixup -C` command. Currently, while `fixup -C` keeps the commit message from the current commit, it incorrectly preserves the author information (name, email, and date) from the previous commit. The patch changes this to use the current commit's author metadata as well, which better matches the expected workflow where fixup commits are typically ephemeral and the main commit's metadata should be preserved.

The change affects three files: updates the help text in `rebase-interactive.c`, modifies the author handling logic in `sequencer.c`, and adds/updates tests in `t/t3437-rebase-fixup-options.sh`. A new test is added to verify the author date preservation, while some existing tests are simplified since they no longer need to verify the old behavior.

The patch appears well-constructed with a clear commit message explaining both the current behavior's shortcomings and the rationale for the change. The test coverage seems thorough, including both the new desired behavior and verification that other related functionality (like `fixup -c`) continues to work as expected. This looks like a straightforward quality-of-life improvement for users who split commits and use `fixup -C` during interactive rebases.
