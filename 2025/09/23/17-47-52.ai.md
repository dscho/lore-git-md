This is part 1 of a 2-part series fixing an inconsistency in `git format-patch`'s handling of Git notes between the main commit message and range-diff output. The thread discussion focuses on naming the new `rdiff_other_arg` strvec member in the `rev_info` struct that will be used to properly propagate notes arguments to the range-diff subprocess.

Kristoffer Haugsbakk responds to Junio C Hamano's review, agreeing that the naming could be improved from "other_arg" to something more descriptive like "log_arg" or "log_args". They note the plural form may be more with Git's style for strvec members. The initialization issue with `STRVEC_INIT` has already been addressed in Junio's integration branch.

The discussion clarifies that the core goal is ensuring range-diff shows the same notes configuration as the main format-patch output when comparing patches. This affects both specific notes requests (like `--notes=custom`) and `--no-notes` cases. The technical approach involves passing these arguments through the new struct member to the range-diff subprocess.
