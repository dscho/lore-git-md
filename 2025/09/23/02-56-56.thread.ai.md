Key technical details:

    - `stats_table_print()` takes `const` table parameter per Patrick's review
    - Direct stdout printing considered as alternative to strbuf intermediary
  - Machine-readable formats include:
    - `keyvalue`: newline-delimited key=value pairs (documentation incorrectly claims `core.quotePath` handling)
    - `nul`: NUL-delimited with newline separating keys/values (matching existing `git repo info` behavior)
- Ref-filter interface enhanced to accept NULL filter patterns with NULL treated equivalently to empty array
  - Defensive programming in reference counting logic handles all `FILTER_REFS_*` cases with `BUG()` for unexpected types
- Progress meter implementation updated per latest feedback:

  - Test override via `GIT_PROGRESS_DELAY=0` supported
  - Progress message changed to lowercase "objects" for consistency
  - Object count calculation to be deduplicated into helper function
  - Two distinct messages: "Counting references" (known count) and "Counting objects" (indeterminate)
  - Enabled by default when stderr is a TTY, controllable via `--[no-]progress`
  - Requires repository context passing through call chain
  - Uses `count_objects_data` struct to carry stats and progress state
- Implementation cleanly separates data collection (path-walk API, reference traversal) from presentation
- Core functions prefixed with `cmd_` per Git conventions
- Careful memory management throughout with proper cleanup
