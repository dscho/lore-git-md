New subcommand `git repo stats` to analyze repository health metrics, starting with reference statistics. Initial implementation focuses on counting and categorizing references (branches, tags, remotes, and miscellaneous refs) with human-readable table output modeled after git-sizer's format. Introduces `cmd_repo_stats()` in `builtin/repo.c` using `for_each_*` iterators to collect counts, with a `stats` struct to track data and `stats_table` for auto-sizing table formatting. Leverages existing ref-filter infrastructure for categorization. Output is explicitly human-readable (not machine-parseable), reserving machine formats for future work. Includes comprehensive tests in `t/t1901-repo-stats.sh` covering empty and populated repository cases, including edge cases like notes refs under "Others". 

The implementation represents the first step toward git-sizer-like functionality in core Git, following the cover letter's phased approach. Future work will extend this to object statistics (blobs, trees, commits, tags) with three output formats (human-readable, key-value pairs, NUL-delimited) and eventually size metrics and concern levels. Current implementation shows careful attention to maintainability with clean separation between counting logic and presentation, and thorough test coverage.
