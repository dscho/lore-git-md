Documentation formatting issues in multiple man pages (config/extensions.adoc, pretty-formats.adoc, refStorage.adoc) initially reported by Kristoffer Haugsbakk (bug 4704), with Jean-Noël Avila and Jeff King collaborating on fixes. The core problem involved definition lists with nested bullet items and continuation paragraphs incorrectly rendering "+" characters in HTML output under Asciidoctor. Avila's solution replaced single colons (`::`) with triple colons (`:::`), removed open block markers (`--`), and properly nested bullet lists within explicit blocks, affecting configuration options (`compatObjectFormat`, `noop`, `objectFormat`) and `%(decorate)` pretty format syntax.

Jeff King confirmed the diagnosis using `doc-diff` and validated the approach, then identified an orthogonal indentation issue in the `refStorage` documentation affecting both Asciidoctor and asciidoc.py output. After initially misdiagnosing the asciidoc.py behavior, King proposed wrapping the included `ref-storage-format.adoc` content in explicit AsciiDoc block markers (`--`) to ensure consistent rendering at level 2 indentation for the main `refStorage` definition. This fixed a misaligned "Note that..." warning paragraph while maintaining semantic correctness.

Junio C Hamano initially requested clarification about the "straight plus sign" rendering artifact, which Avila demonstrated via concrete URLs in `git-config` and `git-log` documentation. In the final refinement, King's solution for the `refStorage` indentation was accepted by both Avila and Hamano, resolving the interaction between warning paragraphs and nested bullet lists in `extensions.adoc`. The changes preserve documentation semantics while fixing visual hierarchy for the experimental `reftable` format and its initialization constraints.

Hamano's follow-up confirms the solution will be incorporated into the `next` branch, marking the thread's conclusion with consensus among all reviewers (Avila, King, Hamano). The thread demonstrates careful cross-validation of documentation rendering across AsciiDoc processors (asciidoc.py and Asciidoctor), with particular attention to backward compatibility and semantic preservation.
