This is part of Patrick Steinhardt's packfile store refactoring series (v6 13/15), which centralizes packfile management in `struct packfile_store` as part of the ODB abstraction effort. The patch refactors `get_packed_git()` to operate directly on the packfile store rather than a repository, renaming it to `packfile_store_get_packs()` to better reflect its scope.

The changes update callers in gc.c, grep.c, and object-name.c to use the new interface, passing the packfile store directly from the repository's object store. The function's behavior remains unchanged - it still prepares the packfile store and returns its packfiles - but the interface now more clearly indicates it operates on packfile store state rather than repository state broadly. The patch also adds documentation clarifying that this function does not load MIDX or its referenced packs.

This is a mechanical refactoring that follows the series' architectural goal of separating packfile management from object database responsibilities. The changes are straightforward updates to call sites with no functional impact, consistent with the series' approach of preserving behavior while clarifying boundaries. The patch appears well-contained, touching only the expected callers and maintaining the existing functionality.
