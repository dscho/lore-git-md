Review feedback on `git repo stats` format implementation (patch 3/4).

Patrick Steinhardt provides detailed code review for the keyvalue format implementation in the `git repo stats` series. The feedback focuses on error handling patterns, naming consistency, and defensive programming approaches that would make the code more maintainable.

Key technical points:
- Suggests deduplicating format error messages by using a single "format '%s' not supported" message
- Recommends changing error checks to fail closed (`if (format != FORMAT_X && format != FORMAT_Y)`) rather than requiring updates when new formats are added
- Proposes renaming `stats_print()` to `stats_keyvalue_print()` for consistency with `stats_table_print()`
- Notes a nit about the BUG() message wording for unsupported formats ("not valid" vs "not supported")

The review continues the pattern from earlier patches of identifying small but important improvements in error handling and naming. These changes would make the code more maintainable when additional output formats are added in the future. The feedback is narrowly focused on implementation details rather than design, suggesting the overall approach remains sound.
