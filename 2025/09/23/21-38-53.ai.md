This is a response in the ongoing discussion about `git rebase -i` fixup command behavior with `-C` flag, where Junio Hamano weighs in against Mathias Rav's proposed change to preserve author metadata from the current commit rather than the previous one.

Junio argues that fixup operations should maintain the original commit's authorship since the command's purpose is to amend/improve prior work, not replace it. He suggests the current behavior properly credits the author of the main content (tree) over the commit message author, even if message authorship differs. While acknowledging some commits have extensive messages, he maintains the content author deserves primary credit.

The response firmly opposes changing fixup's established behavior, proposing instead that if a "replacement" workflow is needed (where new authorship should override), it should be a separate command rather than modifying fixup's semantics. This aligns with Phillip Wood and Kristoffer Haugsbakk's earlier arguments about preserving original authorship during amendments.

Key technical context remains:
- Current implementation takes author from previous commit
- Proposed change would take from current commit
- Debate centers on whether fixup implies amendment (keep original) vs replacement (take new)

This authoritative maintainer perspective significantly shifts the discussion's balance against the proposed change, suggesting it would break established workflow expectations around fixup operations. The suggestion of a new command for replacement scenarios offers a potential compromise path forward.
