Feature completion for `git repo stats` output formats. This final patch in the series adds NUL-delimited output (`--format=nul`) as previewed in earlier discussions, complementing the existing table and keyvalue formats. The implementation shares the same underlying data collection as previous patches but modifies the output routine to use NUL characters between key-value pairs instead of newlines, making it safer for scripts processing values containing special characters.

The change is straightforward - the existing `stats_print()` function gains a delimiter parameter that switches between newlines and NULs, while maintaining identical key-value content. Documentation updates clarify the new option, and tests verify correct NUL-delimited output matches the expected format. The patch also removes a now-unneeded error check that previously blocked NUL format support.

This completes the core output format options for the new `git repo stats` command, delivering on the series' goal of providing both human-readable and script-friendly repository metrics. The clean separation between data collection and presentation established in earlier patches makes this addition particularly clean, with no changes needed to the printing logic beyond the delimiter character.
