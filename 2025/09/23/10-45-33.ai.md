This is a feature patch introducing a new plumbing command `git refs get` as part of the `git-refs` subcommand family. The patch comes from a GSoC project with two mentors listed.

The new command provides a predictable way to read reference values without DWIM expansion (unlike `git rev-parse`) and with clearer discoverability than `git show-ref --verify`. Key behaviors:
- Requires exact refnames (no DWIM)
- Shows direct symref targets without dereferencing (e.g. shows "ref: refs/heads/main" for HEAD)
- Returns raw object IDs for regular refs
- Files modified:
  - `builtin/refs.c`: Adds new `cmd_refs_get()` function implementing the core logic
  - `Documentation/git-refs.adoc`: Documents the subcommand
  - New test file `t/t1464-refs-get.sh` with comprehensive test coverage

The implementation appears clean and well-considered, with thorough tests covering:
- Basic ref reading
- Symref handling (including dangling symrefs)
- Error cases (invalid refs, wrong number of arguments)
- Explicit non-support for DWIM

The commit message clearly explains the motivation and advantages over existing alternatives. This looks like a well-executed addition to the refs plumbing interface that should be useful for scripting. The only notable design choice is the decision to show symref targets rather than dereferencing them, which is explicitly called out as a feature.
