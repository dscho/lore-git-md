This is a refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust conversion by standardizing integer widths.

Patch 5/9 in the v6 series replaces implicit integer types in the varint encoding/decoding code with explicit fixed-width types (`uint64_t` for values, `uint8_t` for lengths). The change is motivated by two factors: platform independence (since `int` and `uintmax_t` sizes vary) and making the upcoming Rust reimplementation simpler, as Rust requires explicit integer widths. The patch touches four files with straightforward mechanical changes to function signatures and variable declarations.

The changes are well-contained and clearly explained, with the maximum varint size already limited to 16 bytes, there's no risk of overflow from using smaller types. This appears to be a safe preparatory change that doesn't affect functionality, just making the code more precise and portable. As part of the larger Rust effort, it helps establish patterns for future C-to-Rust conversions where type explicitness matters.
