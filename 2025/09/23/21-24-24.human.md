This is a refactoring patch in the final stages of Ezekiel Newren's xdiff modernization series, specifically removing a redundant hash array from the xdiff internals. 

The patch eliminates `xdfile_t.ha`, a duplicate array that stored the same hash values already available in `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. While this change makes the code about 5% slower due to the extra indirection needed to access the hash values, the author notes this is temporary - future cleanups will restructure the code to make this more efficient. 

The changes touch core diff algorithm files (xdiffi.c, xprepare.c) and type definitions (xtypes.h), modifying hash access patterns throughout the Myers diff implementation. The author mentions this is part of preparatory work for eventually creating a dedicated struct for classic diff algorithms, with more cleanups to come in subsequent patches (including removal of the `chastore cha` field).

This appears to be a well-considered change in a mature patch series that has already gone through several rounds of review. The performance impact is acknowledged and deemed acceptable as a transitional step toward better long-term structure. The patch maintains all existing behavior while simplifying the codebase by removing redundant data storage.
