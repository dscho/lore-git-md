This is a follow-up discussion in the ongoing thread about fixing `git format-patch`'s inconsistent handling of Git notes in range-diff output for single-commit cases. The patch series aims to ensure notes display consistently between the main commit message and range-diff section.

Kristoffer Haugsbakk responds to Junio C Hamano's review questions about whether `--no-notes` would be ineffective in this scenario (it would be) and whether the commit message should more clearly state that notes may appear when suppressed. The author agrees the message could be clearer and proposes revised wording that better explains the behavior mismatch.

The technical discussion centers on how range-diff currently inherits notes behavior from git-log by default when processing single patches, which can contradict explicit notes options passed to format-patch. This is part 2 of a series that already introduced infrastructure in part 1 to properly propagate notes arguments to the range-diff subprocess.

The exchange shows the patch is moving toward acceptance after addressing initialization and documentation concerns raised in review. The remaining open question appears to be whether the commit message needs further refinement to fully capture the behavior being fixed.
