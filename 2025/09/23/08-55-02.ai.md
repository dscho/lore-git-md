This is a bugfix patch addressing an inconsistency in `git rebase -i`'s fixup command behavior. The patch changes how the `-C` flag works with fixup commits to make author metadata handling consistent with commit message handling.

Currently, when using `fixup -C`, Git keeps the current commit's message but takes the author information (name, email, date) from the previous commit. Mathias Rav argues this is counterintuitive - when splitting a commit and using `fixup -C` to merge part of it into a later commit, we'd want to preserve the later commit's author metadata along with its message.

The patch modifies three key areas:
1. Updates the help text in `rebase-interactive.c` to clarify the new behavior
2. Adjusts `try_to_commit` in `sequencer.c` to properly handle author metadata when AMEND_MSG is set
3. Adds a new test case verifying the date preservation and updates existing tests that assumed the old behavior

The changes are relatively small (15 lines added, 9 removed across 3 files) but address a clear inconsistency in behavior. The commit message provides a thorough explanation of the current behavior's shortcomings and the rationale for the change. The patch includes test coverage for both the new behavior and regression protection for related functionality.

This appears to be a well-considered change that makes the behavior more consistent with user expectations when using `fixup -C`. The author acknowledges there might be workflows depending on the current behavior and invites discussion if that's the case.
