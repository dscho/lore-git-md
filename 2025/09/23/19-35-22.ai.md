This is a bug report for gitk, the Git repository browser GUI. The reporter (Marcin Wisnicki) describes a platform-specific issue where right-clicking on a commit in gitk on macOS (ARM64, Darwin 24.6.0) fails to show the expected context menu, while the same action works correctly on Windows. The bug occurs with Git version 2.51.0 built with clang 17.0.0.

The report includes detailed system information showing this is occurring on an Apple Silicon Mac (arm64) running a recent Darwin kernel. The reproduction steps are minimal and clear - create a simple repo with one commit, launch gitk, and right-click on the commit. The expected Windows-like context menu does not appear, though no error messages or alternative behavior is described.

This appears to be a GUI interaction bug specific to macOS's handling of right-click events in gitk's Tk interface. The report doesn't mention whether this is a regression or long-standing behavior, nor does it suggest any workarounds. The bug affects basic gitk functionality (context menus are commonly used for commit actions) on a mainstream platform, making it likely to draw attention from macOS-using developers and maintainers familiar with gitk's Tk code.
