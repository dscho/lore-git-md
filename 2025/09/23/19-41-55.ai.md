This is a follow-up in the Git release notification discussion thread. Velocifyer responds to Christian Couder's suggestion about using mailing list archives for release announcements by proposing a dedicated "git-announce" mailing list for release notes and important announcements. 

The email questions why release notes distributed via the existing mailing list couldn't instead be sent to a separate announcement-only list. This suggests Velocifyer is looking for a more focused notification channel than the general git@vger.kernel.org list. The proposal implies this could help users who want release notifications without subscribing to the high-traffic main list.

The thread context shows this is one of several notification method proposals being discussed, alongside GitHub feeds, git-scm.com RSS, and script-based solutions. Previous technical constraints around tag-based solutions and performance considerations have been well-covered earlier in the thread. This new suggestion introduces a mailing-list-based approach that would require list administration changes rather than technical modifications to Git itself.

The email maintains the thread's focus on finding practical ways to deliver release notifications, though it doesn't address the technical implementation details or moderation requirements that a new mailing list would entail. The signature includes some personal notes and an unrelated link about WiFi reception.
