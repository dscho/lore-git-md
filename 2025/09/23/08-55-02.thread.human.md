Mathias Rav's patch to change how `git rebase -i`'s `fixup -C` command handles authorship has sparked a nuanced discussion about the semantics of fixup operations. The original proposal would have made fixup preserve the current commit's author information rather than taking it from the commit being fixed up, but this met strong resistance from several contributors including Phillip Wood and Kristoffer Haugsbakk, who argued it violated the established principle that fixups should maintain original authorship. Maintainer Junio Hamano weighed in decisively against the change, stating that fixups exist to amend prior work while preserving attribution, and that any workflow needing different behavior should use a separate command.

Johannes Sixt ("Hannes") has now introduced a new perspective, describing a scenario where the proposed behavior would be useful: when commits that were fixups for later work get misordered and need to be reorganized, causing conflicts. He suggests this isn't about fixing previous commits (which aligns with Junio's stance) but rather about properly attributing work that was originally mispositioned. Hannes proposes extending the `squash` command with similar metadata control as an alternative path forward, keeping the discussion alive despite Junio's clear position on the original proposal.

The thread now presents both a maintainer's design principle (fixups preserve original authorship) and a contributor's proposed alternative approach (extending `squash` for cases where authorship needs updating). While Junio's position makes it unlikely the original patch will be accepted as-is, Hannes' suggestion may provide a way forward for the underlying use case through different means. Documentation updates remain needed regardless of the outcome.
