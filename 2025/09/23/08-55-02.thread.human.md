Here's the updated human-readable thread summary:

Mathias Rav identified an inconsistency in how `git rebase -i`'s `fixup -C` command handles author metadata versus commit messages. Currently, it keeps the current commit's message but takes author information from the previous commit, which can be confusing when splitting commits. His patch proposes making this behavior consistent by preserving both the message and author info from the current commit when `-C` is used.

Karthik Nayak has reviewed the changes and generally agrees with the approach. He confirmed the technical implementation looks sound and the test coverage is adequate, though he suggested a minor wording improvement for the help text. Karthik also raised an open question about whether commit dates should receive the same treatment as author metadata, noting this aspect wasn't explicitly addressed in the original patch.

The discussion is still early, with Mathias's initial proposal now having one generally positive review that surfaces a few technical points for clarification. The core idea of making author handling consistent with message handling appears uncontested so far.
