This thread centers on Mathias Rav's proposed change to how `git rebase -i`'s fixup command with `-C` flag handles authorship information. The current behavior preserves the original commit's author when amending, while the patch would instead take the author from the current commit. 

The discussion has revealed a clear divide between design principles and practical use cases. Junio Hamano has taken a firm stance that fixup operations should maintain original authorship since their purpose is to amend prior work, not replace it. This position has been reinforced by historical context from Oswald Buddenhagen's referenced thread. Phillip Wood and Kristoffer Haugsbakk have supported this view, with Phillip proposing compromise solutions like adding a `--use-author` flag rather than changing the default behavior.

On the other side, Johannes Sixt presented a valid use case where the proposed behavior would be useful when reordering commits that were originally fixups for later commits. Mathias Rav has acknowledged the design concerns while maintaining that the behavior has practical value, sharing their custom shell script workaround using `git cherry-pick -n` with `git commit --amend -nC`.

The thread appears to be converging toward rejecting the behavioral change while leaving room for alternative solutions - either through Phillip's suggested flag approach or Mathias' external tooling method. Junio's latest email serves to confirm that historical context supports maintaining the current behavior, effectively closing the door on changing fixup's default semantics while keeping open the exploration of alternative implementations for those who need different behavior.
