This thread explores how `git rebase -i` should handle author metadata when using the `fixup -C` command. The original patch proposed changing the behavior to take the author from the current commit rather than preserving the original author, but this met with significant pushback from maintainers and experienced contributors.

Junio Hamano has made the project's position clear: fixup operations should preserve the original authorship since their purpose is to amend prior work, not replace it. Phillip Wood and Kristoffer Haugsbakk reinforced this view, with Kristoffer suggesting `git commit --amend --reset-author --no-edit` as an alternative for cases where users want to change authorship. However, Johannes Sixt presented a valid counter-use-case involving misordered commits that need to act as fixups for later commits while preserving their own authorship.

In the latest development, Phillip Wood has offered compromise solutions that respect Junio's design principles while addressing Johannes' scenario. He suggests either extending the `squash` command with metadata control options or adding a `--use-author` flag to `fixup` as an opt-in mechanism. This middle ground maintains the expected behavior for normal fixup operations while providing an escape hatch for special cases like Johannes' misordered commits.

The discussion has effectively moved from debating whether to change the default behavior to exploring how best to support edge cases without violating core design principles. The technical implementation of the original patch remains sound, but the consensus is forming around alternative approaches that better align with Git's established conventions.
