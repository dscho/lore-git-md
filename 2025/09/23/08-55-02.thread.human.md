This thread explores a proposed change to `git rebase -i`'s `fixup -C` behavior, where it would preserve the current commit's author information rather than taking it from the previous commit. The discussion has revealed deeper questions about the intended semantics of fixup operations.

Junio Hamano has taken a firm position that fixups should maintain original authorship since their purpose is to amend prior work, not replace it. Johannes Sixt presented a counter-use-case where the proposed behavior would be useful for "reverse fixups" when reordering commits causes conflicts. Phillip Wood proposed compromise solutions: either extending the `squash` command with metadata options or adding a `--use-author` flag to `fixup` rather than changing its default behavior.

In the latest email, patch author Mathias Rav acknowledges Junio's stance and reveals they had been using a custom shell script to achieve the desired behavior through `git cherry-pick -n` followed by `git commit --amend -nC`. This provides a working alternative that doesn't require core Git changes, though Mathias still sees value in built-in support for cases where author date preservation isn't critical.

The discussion appears to be converging toward maintaining the current fixup semantics while exploring alternative approaches for the "reverse fixup" scenario, either through Phillip's proposed extensions or via external tools like Mathias's script. The core question remains how to best support workflow needs while respecting Git's design principles around authorship attribution.
