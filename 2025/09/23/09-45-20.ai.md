This is the foundational patch for introducing Rust infrastructure into Git's build system, part of the ongoing Rust integration series (v6, patch 1/9). It adds Meson build system support for compiling an optional internal Rust library, serving as a test bed for non-critical features and alternative subsystem implementations before the planned mandatory Rust requirement in Git 3.0.

The patch establishes several key technical components: a Cargo.toml configuration (using Rust 2018 edition for gcc-rs compatibility), Meson build rules with a `-Drust=` toggle for optional inclusion, and a custom build script (`cargo-meson.sh`) to handle artifact placement. It also wires up Rust's native unit testing framework through Meson's test runner. The implementation auto-detects Rust toolchain availability while allowing distributors to explicitly disable it, and adds Rust support to the build summary output.

Notable technical constraints include the Rust 2018 edition lock (targeting gcc-rs compatibility) and the temporary workaround for cargo's artifact directory handling (pending stabilization of `--artifact-dir`). The patch explicitly positions this as experimental infrastructure, with the varint subsystem (introduced later in the series) serving as the first mandatory component. Build system interactions are carefully managed through the `WITH_RUST` compile-time define and Meson feature detection.

This initial infrastructure patch sets up the architectural framework that subsequent patches will populate with actual Rust implementations, beginning with the varint subsystem. It represents the technical foundation for the series' phased adoption plan (optional in 2.52, default in 2.53, mandatory by 3.0) while maintaining build system flexibility through the Meson/Makefile dual support.
