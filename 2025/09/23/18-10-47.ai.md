This is a documentation patch series (2 parts) reorganizing and clarifying the refspec section of git-push man page (Documentation/git-push.adoc). It follows up on previous work from pull request #1964, with the primary goal of improving discoverability by moving push rules into a dedicated "PUSH RULES" section while making less-common cases more skippable.

The first patch (already merged) extracted all push validation logic into a standalone "PUSH RULES" section at the end of the man page, moving 91 lines while preserving content. It updated `--force` documentation to reference the new section and added cross-references from the refspec section. Julia Evans incorporated Junio Hamano's feedback on wording precision and coverage.

The current second patch (v2) rewrites the refspec specification section to provide:
- Structured list of all refspec forms with examples
- Clear documentation of pattern refspecs (`*` globbing) and negative refspecs (`^` prefix)
- Explicit clarification that `+` prefix behaves like `--force`
- Special `tag <tag>` syntax documentation

Key changes in v2 address Junio's feedback:
- Simplified tag object explanation to just state "source can be any object"
- Added both exceptions to `--force` behavior (non-commit objects and receiver-side configuration)
- Clarified wording around commit vs branch references
- Fixed awkward punctuation and made creation/deletion rules more explicit

The series represents 102 insertions and 96 deletions total with no behavior changes. All substantive discussion points appear resolved, with maintainer approval indicated. The technical discussion about man page indentation (4-space vs 2-space) concluded with consensus to maintain current formatting rather than modify toolchain behavior. The patch demonstrates careful attention to feedback while achieving its goal of improved documentation structure and clarity.
