This is a localization (l10n) question about patch formatting headers. Kristoffer Haugsbakk questions why `Range-diff:` and `Interdiff:` headers in `git format-patch` output are translated, noting these strings have been marked for translation since their introduction in 2018.

The concern is that translated headers in patch emails might cause issues when shared internationally, since the recipient's Git may expect the untranslated English headers. Kristoffer contrasts this with error messages, where translation makes sense as they're user-facing, while these headers seem more like machine-readable metadata.

The email includes references to the original patches that introduced these translations, but notes there was no discussion about the translation aspect at the time. This appears to be raising a legitimate question about Git's localization boundaries rather than proposing a specific change. The thread context suggests this is the initial inquiry on the topic.
