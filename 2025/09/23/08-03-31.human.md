This is a follow-up discussion in the thread about build system changes for handling deprecated commands when `WITH_BREAKING_CHANGES` is enabled. Patrick Steinhardt responds to Junio Hamano's suggestion about excluding deprecated commands from documentation generation.

Patrick agrees with the core idea of adding `git-whatchanged` to `EXCLUDED_PROGRAMS` when `WITH_BREAKING_CHANGES` is set, which would stop linting its documentation. However, he raises an interesting alternative approach: instead of completely removing the man pages for deprecated commands, they could be kept with a notice about the deprecation and information about replacement commands. This would provide better user guidance during the transition period.

The discussion continues to explore the balance between cleanly removing deprecated functionality and maintaining good user experience. Patrick's suggestion shows thoughtful consideration of how deprecations impact end users, not just build system cleanliness. The thread remains focused on technical implementation details while considering the broader implications of breaking changes.
