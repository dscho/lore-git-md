Refactoring patch in the xdiff modernization series, removing redundant hash array storage. This is patch 7/13 in v5 of Ezekiel Newren's series to clean up xdiff internals for Rust compatibility.

The patch eliminates the `xdfile_t.ha` array which stored duplicate hash values that were already available via `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. This change makes the code about 5% slower but simplifies the data structures in preparation for further cleanups. The modification affects the classic diff algorithms (Myers and minimal) by replacing direct array access with a new `get_hash()` helper function.

Key technical changes:
- Adds `get_hash()` helper to centralize hash value lookup
- Updates all hash comparisons in xdiffi.c to use the helper instead of direct array access
- Removes `ha` array allocation and storage from xprepare.c
- Simplifies record cleanup logic by removing redundant hash storage
- Removes `ha` field declaration from xdfile_t struct in xtypes.h

The change is part of a larger effort to eliminate redundant data structures in xdiff, with a follow-up patch planned to remove the `chastore cha` field. The performance impact is noted but considered acceptable given the structural simplification benefits. All tests continue to pass with the modified code.
