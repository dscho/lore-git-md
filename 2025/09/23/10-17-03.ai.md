This is part of Patrick Steinhardt's packfile store refactoring series (v6, 04/15), which has already been merged. The patch moves the packfile path-to-struct mapping from `struct object_database` to the new `struct packfile_store`, completing the centralization of packfile management state.

The key changes are:
1. The `pack_map` hashmap and its comparison function `pack_map_entry_cmp()` are relocated from odb.[ch] to packfile.[ch]
2. The comparison function is made static since it's now only used within packfile.c
3. MIDX access is updated to use the new location, with a note in odb.h acknowledging this as an expected implementation detail
4. Initialization and cleanup of the map is moved to `packfile_store_new()`/`packfile_store_free()`

The changes are mechanical with no functional impact, continuing the architectural goal of separating packfile management from the object database. The patch follows the established pattern from previous patches in the series, with all access sites updated consistently. The direct MIDX access remains as noted in the thread summary, to be addressed by future backend work.
