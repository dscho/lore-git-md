First patch in a series introducing a new `git repo stats` subcommand for repository health metrics. This initial implementation focuses on counting and categorizing references (branches, tags, remotes, and miscellaneous refs) with human-readable table output modeled after git-sizer's format. The implementation adds a new `cmd_repo_stats()` function in `builtin/repo.c` that uses `for_each_*` iterators to collect counts, formats them in an auto-sizing table, and includes comprehensive tests in `t/t1901-repo-stats.sh` verifying empty and populated repository cases.

Key technical details: The patch introduces a `stats` struct to track counts, a `stats_table` for formatting with dynamic column widths, and uses existing ref-filter infrastructure to categorize references. The output is explicitly marked as not intended for machine parsing, leaving room for future machine-readable formats. Test coverage verifies both empty repositories and those with multiple reference types (including notes refs under "Others").

This appears to be a well-structured foundation for the planned git-sizer-like functionality, with clean separation between counting logic and presentation. The implementation steps align with the cover letter's phased approach, starting with basic reference statistics before moving to more complex metrics.
