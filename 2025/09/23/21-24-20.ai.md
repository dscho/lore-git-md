Refactoring patch in the xdiff modernization series, removing unused fields from core data structures.

This patch (3/13 in v5) continues Ezekiel Newren's systematic cleanup of xdiff internals by eliminating three fields that were initialized but never actually used: `xrecord_t.next`, `xdfile_t.hbits`, and `xdfile_t.rhash`. The changes are straightforward removals with no behavioral impact, as confirmed by the author's testing. The patch touches xdiff's core data structures in `xtypes.h` and their initialization/usage in `xprepare.c`.

Key technical details:
- Removes unused linked-list `next` pointer from `xrecord_t` struct
- Eliminates hash-related fields `hbits` and `rhash` from `xdfile_t` that were allocated but never utilized
- Simplifies `xdl_classify_record()` signature by removing unused hash parameters
- Maintains identical diff algorithm behavior while reducing memory usage
- Part of the broader effort to modernize xdiff internals for potential Rust integration

This appears to be a well-justified cleanup - the fields were clearly vestigial with no actual usage in the codebase. The patch follows the established pattern of the series by making surgical, behavior-preserving changes to the diff algorithm internals. As with previous patches in the series, this has been reviewed and approved by Junio Hamano with no outstanding objections.
