This is part of Patrick Steinhardt's packfile store refactoring series (v6 08/15), continuing the migration of packfile management from `struct object_database` to the new `struct packfile_store`. The patch refactors the `prepare_packed_git()` family of functions to operate directly on the packfile store rather than taking a repository parameter.

The key changes:
- Renames `prepare_packed_git()` to `packfile_store_prepare()` and updates its implementation to work with `struct packfile_store`
- Similarly renames `prepare_packed_git_mru()` to `packfile_store_prepare_mru()`
- Inlines the small `rearrange_packed_git()` helper into `packfile_store_prepare()`
- Updates all callers (7 sites) to use the new function names and pass the packfile store
- Maintains identical behavior while shifting the architectural boundary

The patch follows the series' pattern of mechanical transformations that preserve existing functionality while moving state management to the new abstraction layer. It touches core packfile operations like MRU list initialization, alternate handling, and pack/MIDX preparation. The changes are straightforward with no behavioral impact, just API adaptation to the new packfile store architecture.

This continues the series' progression through the packfile management code, having already migrated the pack list, MRU list, and kept pack cache in previous patches. The direct MIDX access pattern noted in earlier patches remains present here in `get_multi_pack_index()`, which is documented as a transitional implementation detail.
