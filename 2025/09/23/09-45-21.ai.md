Build system refactoring patch in the Rust infrastructure series.

This is the second patch in Patrick Steinhardt's v6 series introducing Rust infrastructure to Git. It performs a mechanical reordering of Makefile variables to prepare for conditional Rust compilation. The change moves variable definitions that depend on config.mak includes (like `GITLIBS` and compiler flags) after those includes, while keeping generated headers and test objects before them. This enables future patches to use `WITH_RUST` flags defined in config.mak.

The patch is purely structural - it splits the Makefile content into two blocks (pre-include and post-include) without changing any logic or adding new functionality. The diff shows 176 lines moved with no substantive changes beyond reordering. This appears to be a straightforward preparatory change for the Rust build system integration, maintaining compatibility with existing Makefile behavior while enabling the conditional compilation approach planned for subsequent patches.

Key technical points:
- Moves build configuration variables (CFLAGS, LDFLAGS, etc.) after config.mak includes
- Keeps generated headers (GENERATED_H) and test objects (CLAR_TEST_OBJS) before includes
- No logic changes - only reordering of existing Makefile content
- Enables future use of `WITH_RUST` from config.mak
- Part of broader Rust infrastructure effort but standalone in effect

The change is well-contained and appears uncontroversial, serving as infrastructure for the more substantive Rust integration work to follow in the series.
