This is a refactoring patch in Patrick Steinhardt's packfile store series (v6 09/15). It splits responsibilities between object database and packfile management by introducing a new odb_reprepare()` function.

The patch moves alternate object directory reloading and loose object cache clearing from `reprepare_packed_git()` into the new `odb_reprepare()` function, leaving `packfile_store_reprepare()` (the renamed `reprepare_packed_git`) to focus solely on packfile management. This better aligns with the series' goal of separating packfile state from the object database.

Key technical changes:
- New `odb_reprepare()` in odb.[ch] handles alternates and loose caches
- Renames `reprepare_packed_git()` to `packfile_store_reprepare()`
- Updates 13 call sites across various commands (gc, repack, fetch-pack etc.)
- Maintains existing behavior while clarifying architectural boundaries
- Touches core packfile operations and object database management

The change is part of the completed packfile store refactoring that centralizes packfile management in `struct packfile_store`. All technical discussions were resolved in earlier iterations, with this patch introducing new architectural separation while preserving behavior. The direct MIDX access pattern noted in previous patches remains as an acknowledged transitional implementation detail.
