This is the final resolution in a refactoring series to modernize xdiff internals for Rust compatibility. Junio C Hamano confirms acceptance of Ezekiel Newren's approach to handling the `changed` array (formerly `rchg`) as a boolean type, addressing the last remaining question in the series. 

The key point settled here is that while the diff algorithm uses three states (0, 1, and MAYBE=2), the `changed` array itself only needs to store binary states (0/1), with the MAYBE state handled separately via a `u8 current_state` variable. This clean separation allows using `bool` for the array while preserving all existing behavior.

Junio clarifies that his earlier concern wasn't about the boolean type itself, but rather about potentially storing the value 2 in a boolean. Since the code only compares the boolean against 2 (rather than storing it), this is safe. He notes Ezekiel's previous response was actually tactful and acceptable.

With this resolution, the 12-patch v4 series - which has already seen its preparatory patches (1-10) merged to 'next' - is now cleared for merging in its entirety. The work systematically modernizes xdiff's data structures while maintaining identical performance and behavior, positioning the codebase better for future Rust integration efforts.
