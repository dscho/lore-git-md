This is the second patch in a documentation series reorganizing the git-push man page's refspec section. It follows up on the first patch (already merged) which extracted push rules into a dedicated "PUSH RULES" section.

The patch completely rewrites the refspec specification section to be more structured and example-driven. Key changes include:
- Organizing all possible refspec forms into a clear bulleted list with examples for each
- Documenting previously missing pattern refspecs (`*` globbing) and negative refspecs (`^` prefix)
- Explicitly stating that `+` prefix is equivalent to `--force`
- Clarifying the special `tag <tag>` syntax
- Making deletion rules and ambiguous ref handling more explicit

The rewrite addresses user confusion about the original dense prose, particularly around refspec expansion rules. It maintains the same technical content but presents it in a more skimmable format. The patch incorporates feedback from Junio Hamano on the v1 submission, including simplifying tag object explanations and clarifying commit vs branch reference wording.

This represents the final patch in the series, with 58 insertions and 47 deletions. The changes are purely documentation improvements with no behavior impact. The thorough rewrite and responsive handling of feedback suggest this is ready for merging to improve the git-push man page's usability.
