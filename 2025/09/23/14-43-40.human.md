This is a follow-up in the ongoing discussion about handling deprecated commands in Git's build system and documentation. Junio Hamano responds to Patrick Steinhardt's suggestion about potentially keeping man pages for deprecated commands with replacement notices.

Junio acknowledges Patrick's idea but notes it would require significant changes to the current assumptions in the build system. The current approach assumes that excluded programs (listed in `EXCLUDED_PROGRAMS`) shouldn't have man pages built or installed at all. This allows the system to consistently handle both the binaries and their documentation for deprecated commands like `git-whatchanged` and `git-http-fetch`.

The email also includes a brief aside about diff prefixes ("i/" and "w/") that came up earlier in the thread, though this is just a minor clarification that doesn't affect the main discussion. The core issue remains how to best handle documentation for deprecated commands while maintaining consistency with the build system's current architecture. Junio suggests that Patrick's proposal, while interesting, would require disentangling some fundamental assumptions in how excluded programs are handled.
