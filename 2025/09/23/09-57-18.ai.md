This is a licensing policy proposal in the context of the ongoing Rust infrastructure discussion, specifically addressing compatibility between Git's Rust code and the Gitoxide project. Johannes Schindelin responds to Phillip Wood's concerns about license fragmentation by advocating for proactive license alignment to avoid repeating the libgit2/Git incompatibility situation.

The email makes a historical case for license compatibility, noting how libgit2's GPL-incompatible license created barriers to code sharing that ultimately weakened both projects. Schindelin proposes adding a GPLv2+exception license header to new Rust code that would explicitly allow use in Gitoxide (dual-licensed MIT/Apache), framing this as learning from past mistakes rather than relicensing existing code.

Key technical/licensing points raised:
- Suggests using Git's existing "GPLv2 or later at Linus's discretion" template for new Rust files
- Proposes adding an explicit exception clause permitting Gitoxide use
- Distinguishes between ported C code (keeping original licenses) and new Rust implementations
- Notes Gitoxide's MIT/Apache dual license as more permissive than GPLv2

The discussion represents a policy fork in the Rust adoption path, with Schindelin positioning license compatibility as essential to avoid ecosystem fragmentation, while Wood expresses concerns about gradual relicensing effects. The exchange highlights tensions between maintaining Git's GPL purity versus enabling broader Rust ecosystem collaboration, with implications for how the project manages contributions and derivative works going forward.
