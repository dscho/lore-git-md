This is the v6 cover letter for the Rust infrastructure series, now expanded to 9 patches. Patrick Steinhardt continues to refine the proposal for introducing Rust into Git core, with several notable updates from previous versions.

The series serves as a test balloon for Rust adoption, starting with converting the simple varint subsystem to Rust to validate C/Rust interoperability. Key technical changes in v6 include fixing varint.rs to use `u64` instead of `usize` (caught by cbindgen) and giving attribution to Ezekiel Newren for kickstarting Rust adoption. The build system now supports both Meson and Makefile builds with Rust enabled via `WITH_RUST`.

The accompanying BreakingChanges document has been updated to clarify that Rust has been in-tree since Git 2.49 (via contrib/) and adds a new caveat that the project will evaluate downstream distribution impact before making Rust mandatory in Git 3.0. The LTS maintenance language has been slightly reworded to indicate tags will remain in the canonical repository even if maintenance is handed to distributors.

The series remains focused on infrastructure rather than features, with acknowledged gaps in CI tooling for Rust formatting verification. The roadmap maintains the phased approach (optional in 2.52, default in 2.53, mandatory by 3.0) while now explicitly stating the timeline may adjust based on real-world adoption pain. The varint conversion serves as both technical proof point and policy test case for the broader Rust transition.
