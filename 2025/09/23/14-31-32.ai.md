This is a governance discussion in the ongoing Rust infrastructure series, specifically addressing the relationship between main Git development and potential LTS (Long-Term Support) branches that would avoid Rust requirements. The email exchange between Junio Hamano and Patrick Steinhardt reveals a fundamental disagreement about how such LTS branches should be managed.

Hamano advocates for a "friendly fork" model similar to Git for Windows, where LTS would be maintained independently by trusted, competent maintainers outside the main project's workflow. He argues that if LTS maintainers need the main project's endorsement to gain trust, they likely aren't qualified in the first place, and forced integration would risk the main project's reputation.

Steinhardt counters with concerns about maintainer competence and trust, proposing a hybrid model where LTS development happens externally but final releases are tagged in the canonical repository after mailing list review. Hamano rejects this as ineffective given Steinhardt's own assumptions about LTS maintainer quality.

The discussion highlights key tensions in the balance between project control and ecosystem diversity, with Hamano favoring decentralized trust in competent maintainers while Steinhardt seeks more centralized quality control. This governance question remains unresolved in the Rust adoption plan, though the technical implementation continues to progress separately.
