This is a licensing discussion in the ongoing Rust infrastructure thread, specifically addressing Schindelin's proposal for GPLv2+exception licensing of new Rust code to enable Gitoxide compatibility.

Jeff King (peff) raises important legal concerns about Schindelin's licensing proposal. While supportive of the goal to improve Gitoxide interoperability, peff notes that even non-verbatim ports of C code to Rust could create licensing complications, drawing parallels to libgit2's historical challenges. The key issue is that any Rust code - even when rewritten - might still be considered derivative work of the original GPLv2 C code, requiring either clean-room implementation or explicit relicensing from all contributors (which becomes impractical over time).

The email highlights how this could recreate the same Git/libgit2 silo situation, and notes that corporate legal teams (like Microsoft's experience with libgit2) tend to be cautious about such licensing gray areas. While the technical implementation of the Rust xdiff work remains stable, this licensing discussion represents a significant policy hurdle that could impact both enterprise adoption and ecosystem coordination. The exchange shows the tension between practical interoperability goals and the legal realities of open source licensing.
