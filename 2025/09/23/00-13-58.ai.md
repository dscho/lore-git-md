Final decision point in xdiff refactoring series regarding boolean type usage.

This email from Ezekiel Newren responds to Junio C Hamano's concerns about using `bool` for the `changed` array (formerly `rchg`) in the xdiff refactoring series. The key technical point is that while the code uses NO (0), YES (1), and MAYBE (2) constants in xprepare.c, the `changed` array itself only ever stores 0 or 1 - the MAYBE state is handled separately and never written to this array. Newren strongly asserts this invariant and plans to clarify it in the commit message.

The discussion centers on whether to:
1. Keep the current `bool` type for `changed` (Newren's position, now with stronger justification)
2. Switch to `unsigned char` (Junio's suggestion for safety)

Newren provides specific guidance to review xdl_cleanup_records() and xdl_clean_mmatch() to verify the usage pattern. This represents the final technical decision needed before merging the series, which has already modernized xdiff's data structures and type usage while maintaining identical behavior and performance. The resolution will determine whether the code proceeds with strict boolean typing or maintains byte-level storage for the changed markers.
