This is a discussion about the behavior of `git rebase -i`'s fixup command with the `-C` flag, specifically regarding author attribution. Junio Hamano weighs in on Mathias Rav's proposed change to make `fixup -C` take both message and author from the current commit rather than just the message.

Junio argues that the current behavior (keeping the original commit's author) makes sense for fixups, since the primary purpose is to amend an existing commit - the original author should retain credit for the work. He suggests that for cases where a commit is being completely rewritten (not just fixed up), a separate command might be more appropriate rather than changing fixup's established behavior.

The email highlights a key philosophical difference in the thread: Mathias sees `fixup -C` as a way to combine commits while keeping the later author's metadata, while Junio and others (Phillip Wood, Kristoffer Haugsbakk) view it primarily as an amendment tool where preserving original authorship is more important. This appears to be the central point needing resolution before any code changes proceed.

Junio's position as Git's maintainer carries significant weight in this discussion, suggesting the patch may need substantial revision or justification to move forward. The thread has already established that documentation updates would be needed regardless of the outcome.
