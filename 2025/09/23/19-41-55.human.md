This is a follow-up in the Git release notification discussion thread. Velocifyer responds to Christian Couder's suggestion of using the `getreleases` script by proposing a new idea: creating a dedicated "git-announce" mailing list that would only contain release announcements and other important updates, rather than having them mixed in with the general git@vger.kernel.org traffic.

The suggestion comes after extensive discussion in the thread about various ways to track Git releases, including GitHub feeds, git-scm.com RSS, and script-based solutions. While the idea of a dedicated announcement list is new to this thread, it's worth noting that the Git project already has established notification mechanisms, and creating new infrastructure might face similar adoption challenges as the previously discussed tag-based solutions. The email maintains the thread's focus on making release information more accessible while introducing a more radical approach than the incremental solutions proposed so far.
