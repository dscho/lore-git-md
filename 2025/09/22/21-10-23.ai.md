This is the second part of a bugfix series addressing inconsistent Git notes display in `git format-patch` output. The patch completes the fix by properly propagating notes-related arguments to the range-diff subprocess when generating single-commit patches, using the `rdiff_other_arg` struct member introduced in part 1.

The core issue is that single-commit range-diff operations weren't receiving the same notes display settings as the main commit message output, causing notes to appear differently (or not at all) in the range-diff section. The fix modifies `log-tree.c` to pass the notes arguments through the new struct member when setting up the range-diff.

Test coverage is added in `t3206-range-diff.sh` with a new case specifically for single-commit scenarios, verifying that custom notes appear consistently in both the commit message and range-diff output. The test follows recent conventions by using `test_when_finished` cleanup properly. The change is small (3 lines of code changes plus test additions) and builds cleanly on the preparatory refactoring from part 1.

Key technical details for future reference:
- Modifies `show_diff_of_diff` in `log-tree.c` to pass `opt->rdiff_other_arg` to range-diff
- Adds test case for single-commit scenario with `--notes=custom`
- Maintains existing behavior for multi-commit cases
- Follows same notes filtering pattern as other tests in the file
