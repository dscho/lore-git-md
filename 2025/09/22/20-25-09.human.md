This is a bugfix patch addressing a memory leak in `git stash show` when using `--` arguments. The patch fixes an issue where `setup_revisions()` would modify the argument vector without properly freeing removed elements, particularly when encountering a `--` delimiter.

The patch adds the `free_removed_argv_elements` option to `setup_revisions()` in the stash code to ensure proper cleanup. The accompanying test is designed to detect leaks (using SANITIZE_LEAK) without checking output behavior, since the test uncovered some pre-existing quirks in how `git stash show` handles arguments after `--`. 

Jeff notes these behavioral oddities (like `--` changing the output format from --stat to --patch) are separate from the memory management issue and should be addressed in future changes if desired. The current patch focuses narrowly on fixing the leak while maintaining existing behavior.

This is the first patch in a larger series addressing strvec memory management issues, but stands alone as a complete fix for the specific stash case. The test approach was refined based on feedback from Junio Hamano to use SANITIZE_LEAK rather than output comparison.
