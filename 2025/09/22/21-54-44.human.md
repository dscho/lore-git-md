This is a documentation patch addressing a case-sensitivity issue with lockfiles. Alan Da Costa adds a note to the lockfile error message to help users on case-insensitive filesystems (like macOS) understand why they might see "existing lock" errors during fetch/pull operations.

The patch explains that when multiple case variants of the same remote ref exist (e.g., "main" and "Main"), they map to the same lockfile path on case-insensitive systems. Git will fail when trying to lock both variants. The new error message suggests resolving this by ensuring remote refs use a single case variant.

The change is minimal (4 lines added to lockfile.c) but provides valuable context for a potentially confusing error case. The commit message clearly explains the scenario and solution, though it doesn't propose any code changes to automatically handle the case collision. This appears to be a straightforward documentation improvement that could save users debugging time.
