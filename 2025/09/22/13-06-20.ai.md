Refactoring patch in a completed series improving `git config get --type=color` functionality. This is patch 3/5 in Patrick Steinhardt's series that has gone through four iterations and is now marked ready for inclusion.

The patch modifies `get_color()` in builtin/config.c to return error codes instead of dying when encountering invalid color values. This makes the function more flexible for future callers that need their own error handling. The change is mechanical but important for the series' goal of improving color handling robustness - it allows the subsequent patch (4/5) to properly handle empty key cases without fatal errors.

Key technical changes:
- Converts `get_color()` from void to int return type
- Replaces `die()` with `error()` for invalid default color parsing
- Maintains same stdout output behavior while adding error propagation
- Updates the ACTION_GET_COLOR caller to check the return value
- No functional change to existing successful code paths

The change is straightforward and well-contained (15 lines modified). It serves as necessary plumbing for the more user-visible fixes in patches 4/5 (empty key handling) and 5/5 (pager behavior). The patch follows the series' pattern of first modernizing infrastructure before changing behavior.
