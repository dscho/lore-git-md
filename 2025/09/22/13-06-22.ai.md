Bugfix for `git config get --type=color` pager behavior. This is the final patch in Patrick Steinhardt's 5-part series addressing color handling in `git config get`, now marked as ready for inclusion after four iterations.

The patch fixes an inconsistency where `git config get --type=color` would spawn a pager for color output, unlike the older `git config --get-color` it's meant to replace. The change makes three key improvements:
1. Disables pager usage specifically for color output, since ANSI codes are meant for direct terminal display
2. Maintains consistency with the older `--get-color` behavior
3. Adds a new test case in t1300-config.sh that verifies pager bypass works in a terminal context

The implementation is minimal (3-line change in builtin/config.c) but effectively solves the problem by checking the display type before setting up the pager. The test uses the terminal test infrastructure to verify the pager bypass works as expected. This completes the series' goal of fixing all known issues with color handling in `git config get`.

Junio Hamano had previously acknowledged this pager bypass as the correct solution despite some architectural trade-offs, and the author has incorporated all feedback from the review process. The series as a whole addresses user-reported issues while modernizing test infrastructure and improving error handling.
