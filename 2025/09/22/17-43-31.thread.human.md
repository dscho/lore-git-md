This thread explores options for automated Git release notifications, sparked by Velocifyer's inquiry about alternatives to manually checking RelNotes files. Jeff King provided detailed technical context, explaining existing options like GitHub's release feed and git-scm.com's RSS while outlining constraints around embedding changelogs in tags (backward compatibility, immutability, and performance). 

Junio Hamano has now responded, suggesting an alternative approach: RSS generators could track updates to the `RelNotes` symbolic link (which always points to the current release notes) for change detection. This builds on King's earlier points while offering a new angle that avoids modifying existing tag practices. The discussion remains conceptual, with no concrete implementation plans, but has thoroughly covered the technical landscape - from GitHub feeds to symbolic link tracking - while respecting Git's distributed philosophy of leveraging existing infrastructure rather than creating new notification systems. All key technical questions about release notification mechanisms now appear addressed.
