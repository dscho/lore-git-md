This is a final discussion about type safety in the xdiff refactoring series, specifically the conversion of the `rchg` field to a boolean type. Junio C Hamano raises concerns about the boolean conversion approach in the `xdfile_t.changed` array (formerly `rchg`), arguing that using C99 `_Bool`/`bool` for a field that historically could hold three states (0/1/2 for NO/YES/MAYBE) is problematic.

The key technical issue is that while most uses of the field treat it as binary (changed/unchanged), some parts of the xdiff code use a third MAYBE state (value 2). Junio suggests keeping the array as `char` or `unsigned char` for clarity and safety, with explicit 0/1 assignments where binary states are intended, while allowing the MAYBE state where needed. This maintains the existing behavior while avoiding potential portability issues with `_Bool` implementations that might not preserve values beyond 0/1.

The discussion represents the final review feedback on the v4 series, which otherwise completed all planned structural simplifications of xdiff internals. Junio's comments focus specifically on this one type-safety question, suggesting an alternative approach that would preserve the three-state capability while still achieving the naming and clarity improvements. This appears to be the last open question before the series could be considered for merging.
