This is a policy discussion in the ongoing Rust integration thread, specifically addressing concerns about hash interoperability and the Rust transition timeline.

Junio Hamano responds to SZEDER Gábor's concerns about SHA-1/SHA-256 interoperability in Rust-less environments. He confirms Brian m. carlson's position that nothing will work without Rust in Git 3.0, including hash conversion operations, though single-hash operations would remain possible in earlier versions. The discussion reveals that the varint subsystem rewrite (Patrick Steinhardt's initial work) will become mandatory infrastructure in 3.0, making Rust a hard requirement for building Git at all.

Hamano expresses concern about the aggressive timeline (estimated at ~18 months to 3.0) and suggests the hash compatibility feature could be implemented as Rust-only opt-in before the mandatory transition. He notes this wouldn't solve the core issue for Rust-less platforms but might provide more gradual adoption. The email also contains an interesting aside questioning how Brian m. carlson's policy document became incorporated into Ezekiel Smith's patch series without prior visibility.

Key technical points:
- Confirms Rust will be absolute requirement in 3.0 (no WITH_BREAKING_CHANGES opt-out)
- Varint subsystem (varint.rs) will be first mandatory Rust component
- Hash interoperability specifically called out as Rust-dependent feature
- Timeline concerns remain open despite documentation refinements

This continues the thread's tension between forward progress and platform inclusivity, with Hamano advocating for more gradual adoption while acknowledging the technical realities of the Rust transition. The discussion surfaces important questions about how policy decisions are incorporated into the technical implementation.
