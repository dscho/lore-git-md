This is part of the ongoing xdiff refactoring series preparing the codebase for Rust integration. Patch 9/12 in v4 series removes the `chastore` arena allocator from `xdfile_t`, simplifying the code and making it more FFI-friendly while maintaining performance.

The patch eliminates the dual data setup where records were stored both in an array and a linked list via `chastore_t`. Performance measurements show removing `chastore` gives a 5% speedup, which offsets the 5% slowdown from removing the `ha` array in previous patches, resulting in neutral overall performance impact.

The change touches multiple xdiff files, converting pointer-based record handling to direct array access. This continues the series' pattern of simplifying xdiff's data structures while preserving behavior, making the codebase more maintainable and better suited for eventual Rust integration. The patch appears well-tested with thorough performance measurements provided.
