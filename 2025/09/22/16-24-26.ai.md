This is a discussion about the maintenance strategy for Rust-free LTS releases of Git after Rust becomes mandatory in the core. The conversation focuses on where these LTS releases should be hosted and how they should be coordinated with the main project.

Junio Hamano responds to Patrick Steinhardt's concerns about maintaining LTS versions in the canonical repository. Hamano argues that community-supported LTS releases should have their own official site rather than being mixed with the main project's repository. He suggests the main repository could simply point to this separate location via a README entry.

Key technical points:
- Hamano proposes a clear separation between main project releases (Git 3.0+) and community LTS releases (Git 2.98)
- He emphasizes the importance of coordinated security disclosures listing all update locations
- Both agree that LTS maintainers should be part of git-security@ for embargoed fixes
- The discussion touches on tag management between repositories while maintaining clear separation

The exchange reveals differing views on repository organization, with Steinhardt favoring keeping LTS in the main repository to avoid fragmentation, while Hamano advocates for clearer separation with well-defined pointers. This represents an ongoing discussion about the practical aspects of the Rust transition's long-term maintenance implications.
