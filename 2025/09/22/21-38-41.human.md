This is a follow-up in the SHA-1/SHA-256 interoperability series, specifically addressing tag signature validation rules.

Brian responds to Junio's feedback on patch 7/9, which deals with GPG signature headers in tag objects. The key points are:

1. Brian will fix a long line formatting issue in the next version of the patch, as requested by Junio.

2. More substantively, Brian clarifies the rules for signature headers in tags. The v2 patch will enforce that `gpgsig` headers are only allowed when SHA-1 is not the primary hash algorithm, and `gpgsig-sha256` headers only when SHA-256 is not primary. This prevents duplicate signature headers while allowing for future hash algorithm additions.

3. An important nuance is that a tag might have a signature header without a corresponding trailing signature in the body. This can happen during hash algorithm conversion - for example, when converting a SHA-1 signed tag to SHA-256 format.

The discussion shows Brian incorporating Junio's feedback while maintaining the series' focus on clear rules for signature handling across hash algorithms. The response suggests the implementation is stabilizing, with only minor adjustments needed before the next revision.
