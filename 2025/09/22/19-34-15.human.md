This is a discussion about Rust integration implications for SHA-1/SHA-256 interoperability in Git 3.0. SZEDER Gábor follows up on Brian m. carlson's explanation of how hash algorithm transitions will work when Rust becomes mandatory.

The key point is that while single-hash operation (either SHA-1 or SHA-256 alone) will continue working without Rust, the interoperability between different hash algorithms will require Rust. Brian clarifies that users on platforms without Rust support can still convert repositories by using a Linux VM, though this creates a "flag day" situation where the repository becomes incompatible with older Git versions until fully converted.

SZEDER suggests this limitation should be explicitly documented in the BreakingChanges notice, as it represents a significant constraint for some platforms. While Brian considers this an acceptable trade-off, SZEDER expresses reservations about this being "not a problem," hinting at ongoing concerns about the impact on platforms that can't support Rust.

The exchange highlights an important technical consequence of the Rust transition that affects users planning hash algorithm migrations, particularly those on niche platforms. The discussion suggests this interoperability constraint may need more prominent documentation to set proper expectations.
