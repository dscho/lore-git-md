This is a discussion thread about the maintenance strategy for Git's Rust transition, specifically focusing on how to handle LTS (Long-Term Support) releases for users who cannot or choose not to upgrade to Rust-based Git versions.

Junio C. Hamano and Patrick Steinhardt are debating where community-supported LTS releases should be hosted. Steinhardt argues they should remain in Git's canonical repository to avoid fragmentation, while Hamano believes they should live in a separate, clearly-marked location with proper pointers from the main project. Both agree that LTS maintainers need access to security coordination channels.

The exchange reveals differing philosophies about project boundaries - Steinhardt wants tighter integration to prevent chaos, while Hamano prefers clearer separation between the main project and community-supported legacy versions. This is part of the larger Rust infrastructure RFC (now at v5) that will make Rust mandatory in Git 3.0, with current discussion focusing on the transition's logistical implications for users who need to stay on older versions.

The thread shows healthy project governance discussion about how to balance innovation with support obligations, with both parties agreeing on core security coordination needs while differing on repository organization strategy.
