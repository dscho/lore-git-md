This is a documentation patch addressing case-insensitive filesystem behavior in Git's locking mechanism. The patch adds a note to the error message in `lockfile.c` that explains how case-insensitive filesystems (like macOS's default) can trigger "existing lock" errors when dealing with mixed-case refs. The issue occurs because different case variants of the same ref name resolve to the same lock file path, causing collision errors during operations like `git fetch` or `git pull`. The new message suggests resolving the issue by ensuring remote refs use a single case variant.

The change is minimal (4 lines added, 1 removed) and targets the error message that appears when Git fails to acquire a lock. While the patch doesn't fix the underlying case-sensitivity issue, it helps users diagnose and resolve the problem more quickly by explaining the filesystem behavior and suggesting remediation. The commit message clearly describes the scenario and solution, though it doesn't mention whether this is a common or rare occurrence in practice.
