This is a follow-up discussion in the dangling symrefs thread, focusing on edge case handling in `git update-ref`. Jeff King responds to Toon Claes' proposal to allow null-to-null updates of dangling symrefs, which would preserve a pattern used in Gitaly.

Key technical points:
- The current patch series enforces old-oid matching for symref operations
- Claes' use case involves `update FOO_HEAD 000...000 000..000` to delete dangling symrefs
- Jeff identifies this as a redundant pattern (equivalent to simple `delete` or single-null `update`)
- The proposed diff would modify `check_old_oid()` to allow null-to-null updates only for symrefs

Jeff expresses reservations about the solution:
- Prefers standardizing on `delete` or single-null `update` commands
- Concerned about adding complexity to already intricate refs code
- Acknowledges the change would technically work but questions its necessity
- Notes the pattern may be Gitaly-specific and not widely used

The discussion highlights a tension between:
1. Maintaining strict ref update semantics from the original series
2. Accommodating existing (if unusual) usage patterns
3. Keeping the refs API simple and predictable

Jeff leaves the door open to accepting the change but clearly prefers callers to adapt to the more standard deletion patterns. The thread now awaits further input on whether this edge case warrants special handling or if callers should update their code.
