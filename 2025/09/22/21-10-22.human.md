This is the first patch in a two-part series addressing an inconsistency in `git format-patch`'s handling of Git notes between the commit message and range-diff output for single-commit series.

The patch lays groundwork by converting a local `other_arg` variable in `builtin/log.c` into a new `rdiff_other_arg` member of the `rev_info` struct. This prepares for fixing the core issue where notes display differs between the main commit message and range-diff section when formatting a single commit. The current behavior causes range-diff to follow `git-log` defaults rather than matching the notes display specified for `format-patch`.

The change is mechanical with no functional impact yet - it just moves where the notes arguments are stored. The implementation appears careful, maintaining memory safety by properly clearing the new strvec member in cleanup. The 21-line diff touches just two files (`builtin/log.c` and `revision.h`) and includes a thorough commit message explaining both the current problem and the preparatory nature of this change.

This looks like a well-constructed first step in addressing the inconsistency, with the actual behavior fix presumably coming in patch 2/2. The change is focused and unlikely to be controversial, though reviewers may want to verify the memory management approach.
