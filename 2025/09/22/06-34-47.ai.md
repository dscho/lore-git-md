This is the second patch in a series improving gitk window geometry handling, specifically addressing the Tags and Heads window persistence. Johannes Sixt (the series author) is reviewing Michael Rappazzo's implementation and raising several technical questions about the approach.

The patch adds geometry persistence for the Tags/Heads window by storing its position/size in gitk's config under `geometry(showrefs)`. Key changes include new helper procs (`manage_showrefs_geometry`, `destroy_showrefs`), binding window events, and modifying the save/restore logic. The implementation tracks window movements via `<Configure>` events and saves geometry before destruction.

Johannes identifies potential timing issues in the restoration logic - he questions whether the `after idle` handler might capture default geometry rather than restored values. He also asks why the solution needs multiple close-event bindings and why the geometry management uses a single function with sub-commands rather than separate functions. These appear to be genuine technical queries rather than outright objections, suggesting the patch may need refinement in its event handling approach.
