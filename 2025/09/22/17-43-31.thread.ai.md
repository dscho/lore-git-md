Git release notification inquiry thread summary:

Velocifyer's original question about automated Git release changelog delivery has evolved into a comprehensive discussion of notification mechanisms, now covering four approaches: GitHub's release feed, git-scm.com RSS, Christian Couder's `getreleases` script, and the proposed "git-announce" list. Technical constraints around tag-based solutions were established by Jeff King and Junio Hamano, citing script compatibility, immutable tags, object size concerns (14K vs 1K), and design principle violations.

Christian Couder's latest contribution clarifies the project's preference for a single mailing list (git@vger.kernel.org) to maintain community cohesion, arguing against specialized lists due to the subjective nature of "important" announcements. Examples like Git for Windows updates and Git Rev News illustrate how relevance varies by reader. This reinforces the status quo where technical alternatives (RSS, scripts) coexist with the unified list, requiring manual filtering but avoiding fragmentation.

The thread now contains complete arguments on both sides, with Christian representing the maintainer perspective favoring the current model. Key unresolved points include: 1) the tension between unified discussion and specialized notification needs, 2) the subjective definition of announcement importance, and 3) whether existing technical solutions adequately address the original push-notification use case. The discussion remains technically grounded while acknowledging philosophical differences in communication preferences.
