Git release notification inquiry thread summary:

Velocifyer's original question about automated Git release changelog delivery via email/RSS has evolved into a comprehensive technical discussion of notification mechanisms. Jeff King and Junio Hamano established three core approaches: 1) GitHub's native feed (https://github.com/git/git/releases.atom), 2) git-scm.com RSS, and 3) potential `RelNotes` symlink tracking. Christian Couder has now contributed a fourth option - the `getreleases` Python script (https://github.com/chriscool/getreleases) used by Git Rev News to query mailing list archives for `[ANNOUNCE]` emails with release information.

Technical constraints preventing tag-based solutions remain fully explained: script compatibility, immutable tags, object size concerns (14K vs current ~1K tags), and design principles against data duplication. Performance impacts of larger tag objects and GitHub's potential use of tag contents were previously analyzed, with consensus that tag-embedded release notes lack justification without specific tool requirements.

The discussion now presents a spectrum of notification methods from fully automated feeds (GitHub, git-scm.com) to script-based solutions (`getreleases`) to manual approaches (RelNotes tracking). While the original push-based email/RSS request remains unaddressed, all technically viable alternatives have been documented with their tradeoffs. The thread has reached comprehensive coverage of the problem space, with historical context about early tag practices and multiple production-proven solutions now available for different use cases.
