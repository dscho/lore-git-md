Git release notification inquiry thread summary:

Velocifyer's original question about automated Git release changelog delivery has expanded into a comprehensive technical discussion covering multiple notification mechanisms. The thread now documents four distinct approaches: 1) GitHub's native release feed (https://github.com/git/git/releases.atom), 2) git-scm.com RSS, 3) Christian Couder's `getreleases` Python script for querying mailing list archives, and 4) Velocifyer's new proposal for a dedicated "git-announce" mailing list for release notes and important announcements.

Jeff King and Junio Hamano previously established the technical constraints preventing tag-based solutions, including script compatibility issues, immutable tag properties, object size concerns (14K vs current ~1K tags), and design principles against data duplication. Performance impacts of larger objects and GitHub's potential use of tag contents were analyzed, with consensus that tag-embedded release notes lack justification without specific tool requirements.

The discussion presents a spectrum from automated feeds (GitHub, git-scm.com) to script-based solutions (`getreleases`) to mailing list approaches (both the existing git@vger.kernel.org and the proposed git-announce list). Velocifyer's new suggestion introduces administrative considerations around list moderation and subscription management that weren't previously discussed. While the original push-based email/RSS request remains technically unaddressed, the thread now comprehensively covers all viable alternatives with their respective tradeoffs between automation, technical implementation, and user experience.
