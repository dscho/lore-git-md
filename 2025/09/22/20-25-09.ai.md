This is a bugfix patch addressing memory leaks in `git stash show` when using `--` arguments, part of a larger series fixing strvec memory management issues in `setup_revisions()`. The patch focuses on a specific leak case where `setup_revisions()` modifies argv by dropping `--` markers, causing the original strings to be leaked.

The key technical change adds `free_removed_argv_elements = 1` to the `setup_revision_opt` struct when calling `setup_revisions()` in `show_stash()`. This ensures proper cleanup of strings that get removed during argument parsing. The test case is simplified to focus solely on leak detection under SANITIZE_LEAK, avoiding any assertions about output behavior which has known historical quirks.

The commit message carefully documents two pre-existing behavioral oddities with `git stash show --` that it changes the output format (--stat vs --patch) and handles pathspecs incorrectly, but explicitly scopes this patch to only the memory leak fix. The test uses the SANITIZE_LEAK prerequisite to validate the leak is fixed without making assertions about the output format.

This is the first patch in a 6-part series that will ultimately introduce architectural improvements to strvec handling in revision parsing. The immediate fix here follows the pattern established in commit f92dbdbc6a for similar cases, while the later patches will introduce safer APIs and more comprehensive cleanup.
