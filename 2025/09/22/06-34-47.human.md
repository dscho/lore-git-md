This is part 2 of a series improving gitk window geometry handling, specifically addressing the Tags and Heads window persistence. Johannes Sixt (the series author) is reviewing Michael Rappazzo's patch submission that makes the Tags/Heads window remember its position and size between sessions.

The patch stores window geometry in gitk's config under `geometry(showrefs)` and adds new helper procedures (`manage_showrefs_geometry`, `destroy_showrefs`) to handle saving and restoring the window state. Johannes raises several technical questions about the implementation details:

1. He questions whether the `after idle` approach for geometry restoration might conflict with initial window creation events, potentially saving default geometry before the restored position is applied.

2. He asks why multiple close-event bindings are needed when the window already tracks geometry changes via `<Configure>` events.

3. He wonders about the design choice of combining save/restore logic in one function rather than using separate functions.

The discussion reveals Johannes has been maintaining a personal branch reverting the original 2008 removal of position restoration for 17 years, indicating this is a long-standing usability issue. While the technical review is ongoing, the patch appears to be a well-motivated improvement to gitk's window management behavior.
