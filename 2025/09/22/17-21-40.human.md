This is a technical discussion about refs backend behavior, specifically around dangling symref handling in `git update-ref`. Jeff King responds to Junio Hamano's question about whether Toon Claes' proposed patch to null symref updates should also affect the `symref-delete` command path.

Jeff explains that all ref updates (regular refs, symrefs, deletions) ultimately go through the same "check old value" code path. He then digresses into a critique of the `update-ref --stdin` command design, suggesting it would be more logical to have all commands accept either old-oid or old-target parameters, with symref-* commands only needed when creating new symrefs. 

While acknowledging this design discussion is somewhat off-topic, Jeff notes that Toon's patch would correctly handle the dangling symref case if the project decides to allow such updates for historical compatibility.
