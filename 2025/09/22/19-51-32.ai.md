This is a refactoring patch in the ongoing xdiff internals cleanup series preparing for Rust compatibility. It removes three unused fields from xdiff`'s core data structures: `xrecord_t.next`, `xdfile_t.hbits`, and `xdfile_t.rhash`. The changes are straightforward - the fields are deleted from the struct definitions in `xtypes.h` and all related initialization and cleanup code is removed from `xprepare.c`.

The patch is part of Ezekiel Newren's v4 series (3/12) that builds on the already-merged preparatory cleanups (patches 1-10). This continues the pattern of simplifying xdiff's data structures while maintaining identical runtime behavior. The changes here are purely removal of dead code - the fields were initialized but never actually used in the diff algorithm. The patch follows the series' approach of making incremental, behavior-preserving changes to pave the way for future Rust integration.

From a technical perspective, this affects the xdiff data preparation phase, removing hash-related fields that appear to be legacy from an earlier implementation. The `xdl_classify_record()` function signature is simplified as it no longer needs the hash parameters, and memory management is slightly simplified by not having to allocate/free the unused hash array. The changes are localized to xdiff's internal implementation and don't affect any external interfaces.
