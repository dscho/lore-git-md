This is a technical discussion about Git release notification mechanisms, specifically addressing the idea of embedding release notes in Git tags.

Jeff King responds to Junio Hamano's skepticism about including release notes in tags by acknowledging that historical examples are rare (only v0.99.5 and v1.4.3.2 show this pattern). He agrees with Hamano's strong objection to duplicating release notes between tags and the working tree, calling it "unseemly."

The email suggests the only potential justification would be for third-party tools that might automatically extract information from tags but don't know how to access Documentation/RelNotes. However, King notes that GitHub's release page might be better served through their API rather than tag contents. This exchange effectively closes the door on tag-based solutions for release notifications, reinforcing the thread's earlier conclusion that existing alternatives (GitHub feed, git-scm.com RSS, RelNotes symlink tracking) are preferable.
