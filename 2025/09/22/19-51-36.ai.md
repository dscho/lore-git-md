Refactoring in the ongoing xdiff internals cleanup series, specifically removing the redundant `xdfile_t.ha` array. This is patch 7/12 in v4 of the series preparing xdiff's data structures for potential Rust integration.

The patch eliminates the `ha` array from `xdfile_t` since its contents can always be derived from `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. This change makes the code about 5% slower but simplifies the data structure in preparation for future work. The commit notes this is part of a larger cleanup effort that will eventually lead to creating a dedicated struct for classic diff algorithms (Myers and minimal).

Key technical changes:
- Adds a new `get_hash()` helper function to access hashes indirectly
- Modifies `xdl_split()` and `xdl_recs_cmp()` to work with `xdfile_t` directly rather than hash arrays
- Updates `xdiff/xdiffi.c`, `xdiff/xprepare.c`, and `xdiff/xtypes.h` to remove all `ha` references
- Maintains the same 5% performance impact noted in earlier patches (speedup from `chastore_t` removal offsetting this slowdown)

The change follows logically from previous patches in the series and continues the pattern of simplifying xdiff's internals. The commit message notes this is one of several preparatory steps needed before creating a dedicated struct for classic diff algorithms. A follow-up patch will investigate removing the `chastore` field and examine the combined impact of these removals.
