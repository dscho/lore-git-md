This is the final patch in a series adding configurable index restoration to `git stash`. The feature addresses a long-standing inconsistency where `stash push` saves staged changes but `apply/pop` doesn't restore them by default. The patch implements a `stash.index` config option (defaulting to false) that makes these commands behave as if `--index` was supplied.

Phillip Wood confirms the updated tests look good and raises no objections to the functionality. He notes this change will also affect `merge/pull/rebase --autostash` behavior, suggesting this should be mentioned in the commit message since it's likely what users would expect when setting the config.

The implementation is clean and well-tested, with:
- Clear config documentation
- Proper handling of config vs command-line flag precedence
- Comprehensive test coverage of all interaction cases
- Backward compatibility maintained via the `--no-index` override

The series has been approved by the maintainer and appears ready for merging. This represents a thoughtful quality-of-life improvement that makes stash behavior more intuitive while preserving all existing functionality.
