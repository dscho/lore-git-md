This is a test refinement patch in the ongoing strvec memory management fix series. Junio Hamano proposes simplifying the test case for the `git stash show --` memory leak by removing an output comparison that was incorrectly assuming identical behavior between `git stash show` and `git stash show --`. The change marks the test with SANITIZE_LEAK to clearly indicate its purpose is leak detection rather than output validation.

The patch removes the problematic output comparison that Jeff King had noted could be misleading due to pre-existing differences in output format between the two invocations (diffstat vs patch format). Instead, it focuses solely on verifying the absence of memory leaks when using `--` arguments, which was the core issue being addressed in this part of the series.

This change aligns with the thread's earlier consensus to keep behavior changes separate from memory fixes. The simplified test better documents the leak-fixing purpose while avoiding any assumptions about command output formats. The SANITIZE_LEAK prerequisite makes the test's intent clear while allowing it to be skipped in non-leakSanitizer builds where it wouldn't provide value.

The modification is straightforward and uncontroversial, maintaining the series' focus on memory safety while cleaning up a test case that could have led to confusion about the patch's scope. It follows Jeff King's suggestion to either keep the leak-only test or modify it to avoid output comparison, opting for the simpler approach that better matches the actual fix being tested.
