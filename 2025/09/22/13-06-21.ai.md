Bugfix patch restoring color parsing functionality in `git config get`. This is the fourth patch in a completed 5-patch series addressing issues with `git config get --type=color` behavior.

The patch specifically fixes a regression where `git config get --type=color --default="reset" ""` would fail with an error about empty section names, despite being a documented way to get color reset sequences. The regression was introduced in commit 4e51389000 when the new `get` subcommand was added. The fix adds a special case in `builtin/config.c` to handle empty key + color type + default value combinations by directly calling `get_color()`.

The implementation adds 13 lines of code (2 in the main logic, 11 in tests) to handle this edge case while maintaining consistency with the older `--get-color` behavior. The test additions verify both the new `get` subcommand matches the old behavior and that the empty key case works as expected. The patch follows the series' pattern of first modernizing tests (patches 1-2) before making functional changes (patches 3-5).

This was the last functional issue in the series, with all prior review feedback addressed. The author has marked the series as ready for inclusion, and Junio Hamano has approved the solution despite noting the architectural suboptimality of using `git config` for color parsing. The fix addresses a user-reported issue from SZEDER Gábor and maintains backward compatibility with documented behavior.
