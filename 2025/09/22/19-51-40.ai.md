Refactoring patch in the xdiff preparation series for Rust compatibility. This is patch 11/12 in v4 of the series, continuing the effort to simplify xdiff's internals before potential Rust integration.

The patch converts the remaining numeric literals (0, 1, 2) used for the `xdfile_t.rchg` field into named boolean constants (NO, YES, MAYBE) defined as an enum. This affects several xdiff algorithm implementations (xdiffi, histogram, patience) and the xprepare code. The changes are mechanical replacements that make the code more readable while maintaining identical behavior.

Key technical details:
- Introduces `#define` macros for NO(0), YES(1), MAYBE(2) in xprepare.c
- Updates all assignments and comparisons of `xdfile_t.rchg` to use these named constants
- Affects core diff operations in xdiffi.c (recs_cmp, group_slide_down/up), histogram.c, and patience.c
- Maintains the same logic flow - NO/YES/MAYBE map directly to the previous 0/1/2 values
- Follows naturally from earlier patches that converted `rchg` from char to bool type

This continues the series' pattern of making xdiff's data flow more explicit while preparing for future Rust integration. The change is purely about code clarity with no expected performance impact. It builds on previous patches that removed redundant data structures and simplified memory management.
