Bugfix for `git config get --type=color` pager behavior. This is the final patch in Patrick Steinhardt's 5-part series addressing color handling issues in `git config get`, now marked as ready for inclusion after four iterations of review.

The patch fixes an inconsistency where `git config get --type=color` would spawn a pager for color output, unlike the older `git config --get-color` command it's meant to replace. Color escape sequences are meant for direct terminal output, and piping them to a pager (which might not handle them properly) doesn't make sense. The change simply skips pager setup when outputting color codes.

The patch includes a new test case that verifies the pager isn't used for color output, even when core.pager is set. This matches the behavior of thorough test coverage seen throughout the series. The change is small (3 lines in the main code plus test additions) but completes the series' goal of making color handling in `git config get` robust and consistent with existing behavior.

With all review feedback addressed across four versions, this final patch wraps up the series that fixes several color-related issues while modernizing test infrastructure. The changes are focused and well-justified, maintaining backward compatibility while improving error handling and consistency.
