This thread addresses an inconsistency in `git format-patch` where notes attached to commits were being displayed differently in the main commit message versus the range-diff output for single-commit series. The issue occurs when using `--no-notes` or custom notes namespaces, as these arguments weren't properly propagated to the range-diff subprocess.

The proposed solution comes in two parts: first refactoring to add a new `rdiff_other_arg` member to the `rev_info` struct to handle these arguments, then using it to ensure consistent notes display. Junio C Hamano reviewed the initial patches, noting several areas needing attention - particularly the struct member's initialization, its potentially too-generic name, and the commit message's clarity about the `--no-notes` implications.

In the latest discussion, the author responds to Junio's feedback by fixing the initialization oversight in `REV_INFO_INIT` and considering alternative names like `log_arg` since the member handles more than just notes (including arguments like `--merges`). The technical approach remains sound, with the conversation now focused on naming conventions and commit message improvements rather than fundamental design. A v2 addressing these remaining points appears likely to gain acceptance, as the core solution effectively resolves the original inconsistency while maintaining existing behavior for multi-commit cases.
