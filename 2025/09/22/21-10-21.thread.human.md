This thread addresses an inconsistency in how `git format-patch` displays Git notes when used with range-diff for single-commit cases. Currently, notes appear differently in the main commit message versus the range-diff output, and `--no-notes` is ignored in the range-diff section.

The proposed solution comes in two parts. The first (already reviewed) refactors the code to add a new `rdiff_other_arg` member to the `rev_info` struct to properly pass arguments to the range-diff subprocess. The second part will use this to ensure notes arguments are correctly propagated. Junio C Hamano and Kristoffer Haugsbakk have reviewed the series, resolving an initialization issue and now discussing the best name for the new struct member - considering alternatives like `log_arg` or `log_args` to better reflect its purpose.

The discussion has clarified that the fix needs to handle both specific notes requests (like `--notes=custom`) and `--no-notes` cases, ensuring range-diff shows the same notes configuration as the main output. A test case already exists to verify the behavior for single-commit cases with custom notes. While the technical approach is sound, the series awaits final naming decisions and commit message refinements before being ready for merging.
