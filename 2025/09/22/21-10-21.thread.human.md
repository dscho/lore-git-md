This thread addresses a subtle inconsistency in how `git format-patch` displays Git notes when used with range-diff for single-commit cases. The core issue is that notes arguments (like `--no-notes` or `--notes=custom`) weren't being properly passed to the range-diff subprocess, causing notes to appear differently in the main commit message versus the range-diff section.

The two-part series introduces a new `log_args` member in the `rev_info` struct (part 1) and uses it to properly propagate notes arguments (part 2).
