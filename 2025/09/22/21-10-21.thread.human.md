This thread addresses an inconsistency in how `git format-patch` displays Git notes when generating range-diffs for single-commit patch series. The core issue is that notes-related flags (like `--no-notes` or `--notes=custom`) weren't being properly passed to the range-diff subprocess, causing notes to appear differently in the main commit message versus the range-diff section.

Junio C Hamano has reviewed the two-part patch series (currently at v1) that fixes this by introducing a new `rdiff_other_arg` member in the `rev_info` struct to properly propagate these arguments. The technical approach appears sound, but there's ongoing discussion about naming (whether `rdiff_other_arg` is the clearest name) and how to best explain the fix in the commit message.

The latest email clarifies that the current behavior means `--no-notes` has no effect on range-diff output for single patches, since the subprocess defaults to showing notes. The author is working to improve the commit message to better explain this inconsistency - both for cases where users request specific notes and when they try to suppress notes entirely. While the implementation seems correct, the focus now is on ensuring the documentation clearly captures the problem and solution before the series progresses further.
