This thread addresses an inconsistency in `git format-patch` where Git notes attached to commits were displayed differently between the main commit message and the range-diff output for single-commit series. The issue occurred because `--no-notes` was being ignored and notes arguments weren't properly propagated to the range-diff subprocess.

The proposed solution comes in two parts: first refactoring the argument handling by adding a new `rdiff_other_arg` member to the `rev_info` struct, then using this to properly propagate notes arguments. Junio C Hamano has reviewed both patches, identifying several areas for improvement including initialization, naming, and commit message clarity. The initialization issue has since been addressed, but there's ongoing discussion about whether to rename the new member to something like `log_arg` for clarity.

Kristoffer Haugsbakk has joined the discussion, helping refine the technical details. The core goal remains ensuring range-diff shows the same notes namespaces as the main commit output when comparing patches. While the technical approach is considered sound, the patches will likely need minor revisions to finalize the naming and improve the commit message explanation before being accepted. The changes affect the revision walking code that handles notes display and range-diff argument passing.
