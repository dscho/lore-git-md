This thread addresses a subtle inconsistency in `git format-patch` where notes display behavior differed between the main commit message and range-diff output for single commits. The original issue was that `--[no-]notes` options weren't properly propagated to the range-diff section when processing individual commits, though they worked correctly for cover letters and multi-commit cases.

The three-part patch series (now at v2) systematically fixes this by introducing a new `rdiff_log_arg` member in the `rev_info` struct to properly carry notes arguments through to the range-diff machinery. The first two patches laid the groundwork with structural changes and proper initialization, while this final patch completes the solution by modifying `show_diff_of_diff` to use the new infrastructure. The series has evolved based on feedback from Junio C Hamano and Kristoffer Haugsbakk, with improvements to variable naming (changing `other_arg` to `log_arg` for clarity) and commit messages. 

Test coverage has been thorough, with new cases added to verify both custom notes display and suppression behavior in single-commit scenarios while maintaining existing coverage for other cases. All technical concerns appear resolved, and the series seems ready for final review and inclusion. The changes are self-contained, focusing specifically on the notes display consistency issue without broader implications for other ongoing Git development efforts.
