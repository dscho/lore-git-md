This is the final patch in Ezekiel Newren's v4 refactoring series preparing xdiff internals for Rust compatibility. The patch completes the type modernization by converting the `char *rchg` field in `xdfile_t` to a `bool *changed` array, following through on earlier changes that introduced named boolean constants (NO/YES/MAYBE) in patch 11/12.

The change is mechanical but wide-reaching, updating all xdiff algorithm implementations (histogram, patience, and standard diff) to use the new field name and type. Key modifications include:
- Renaming `rchg` to `changed` in `xdfile_t` struct definition (xtypes.h)
- Updating all array access patterns in xdiffi.c's core diff logic
- Adjusting memory allocation/initialization in xprepare.c
- Modifying the fallback diff implementation in xutils.c
- Updating histogram and patience diff algorithms to use the new field

The patch builds on prior structural simplifications that removed redundant `ha` array, `chastore_t` allocator, and various field aliases. It represents the last step in making xdiff's data structures more explicit and type-safe before the planned Rust integration work. Performance impact remains neutral as confirmed by earlier benchmarking in the series.

This concludes the current phase of xdiff refactoring, having systematically eliminated all major redundant data structures and converted key fields to proper boolean types. The changes maintain strict behavior preservation while making the codebase more amenable to both static analysis and eventual Rust porting.
