Refactoring patch in the xdiff preparation series for Rust compatibility. This patch (v4 09/12) removes the `chastore_t` arena allocator from `xdfile_t`, completing the transition to direct array allocation for xdiff records that began in earlier patches.

The change eliminates the dual data model where records were both in an array and linked list, simplifying memory management. Performance measurements show removing `chastore` gives a 5% speedup, which offsets the 5% slowdown from removing the `ha` array in previous patches, resulting in neutral net performance impact. The patch updates all xdiff algorithm implementations (myers, histogram, patience) to work with the simplified structure.

Key technical changes:
- Removes `xdfile_t.rcha` field and all `xdl_cha_*` calls
- Converts `xrecord_t**` to direct `xrecord_t*` array access
- Updates record access patterns in xdiffi.c, xemit.c, xhistogram.c, xmerge.c, xpatience.c, xprepare.c
- Maintains identical diff behavior while reducing FFI complexity for future Rust integration

This builds on prior work removing redundant fields (patch 7/12 removed `xdfile_t.ha`, patch 8/12 simplified `xdlclass_t`). The series continues to maintain clear separation between structural simplifications (this patch) and upcoming Rust-specific type changes.
