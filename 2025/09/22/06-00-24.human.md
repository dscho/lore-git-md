This is a follow-up discussion about a bugfix patch for gitk's geometry persistence. The patch (v2 1/2 in the series) addresses an issue where gitk's main window would restore its position between sessions, only remembering the size. The fix uses Tcl/Tk's `after idle` callback to ensure proper timing for position restoration across different operating systems.

Johannes Sixt notes he's been carrying a revert of an older 2008 patch (22d37f865268) in his personal branch for 17 years, suggesting this has been a long-standing issue. He asks if Mark (presumably Mark Levedahl, original author of the 2008 patch) can explain why the original position-restriction change was made. This indicates some historical context may be needed to understand the tradeoffs around window positioning behavior.

The technical solution itself appears straightforward - a two-line change that defers the geometry restoration until after window mapping. The patch builds on gitk's existing geometry persistence system but adds proper position handling. This is part of a broader effort (v2 series) to make all gitk windows (main and secondary) properly remember their layouts between sessions.
