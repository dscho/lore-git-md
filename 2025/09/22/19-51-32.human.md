Refactoring patch in the xdiff preparation series for Rust compatibility.

This is patch 3/12 in v4 of Ezekiel Newren's series to clean up xdiff internals ahead of potential Rust integration. The patch removes three unused fields from xdiff data structures: `xrecord_t.next`, `xdfile_t.hbits`, and `xdfile_t.rhash`. The commit message notes these fields were initialized but never actually used in the code.

The changes are straightforward - the fields are deleted from the struct definitions in xtypes.h, and all related initialization and cleanup code is removed from xprepare.c. The `xdl_classify_record()` function is simplified since it no longer needs to maintain the unused hash chain via the `next` pointer.

This continues the series' pattern of simplifying xdiff's data structures while maintaining identical behavior. The changes appear well-contained and low-risk, focusing only on removing dead code. The patch follows the established approach of the series by making incremental, behavior-preserving changes to prepare for future Rust integration work.
