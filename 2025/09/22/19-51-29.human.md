This is a refactoring series preparing xdiff internals for Rust compatibility, now in its 4th iteration. Ezekiel Newren continues the effort to simplify xdiff's data structures by removing redundant fields and aliases from `xdfile_t` and `xrecord_t`. The series builds on the already-merged v3 (patches 1-10) that was recently merged to 'next', with this version addressing review feedback and splitting some changes for clarity.

Key changes in v4 include:
- Splitting the deletion of `xdl_get_rec()` into two commits for better reviewability
- Moving NO/YES/MAYBE macros into xprepare.c and using bool literals
- Refactoring the `rchg` field from `char*` to `bool* changed` for clearer semantics
- Maintaining the net-neutral performance impact noted in previous versions

The series shows careful attention to review feedback, with clean commit messages documenting each change's rationale. The preparatory cleanups are now nearly finished, with the Rust-specific type changes still planned for a future series. One remaining open question from Phillip Wood about potential performance impact of removing local `rchg` aliases appears partially addressed in this version with additional justification about code consistency and tooling benefits.
