This is a reply in the ongoing RFC discussion about making Rust mandatory in Git, focusing on package management concerns. Sam James from Gentoo strongly supports Michael Orlitzky's earlier arguments about Rust's ecosystem instability causing problems for Linux distributions. The key points reinforce that Rust's dependency model forces distributions to bundle outdated crates against their policies, undermining core package management principles.

James emphasizes that while Gentoo can technically support Rust (contrary to some earlier claims), the real issue is the maintenance burden Rust imposes on distribution maintainers. They highlight the practical difficulties of source-based builds on niche platforms (like riscv/musl) and the broader systemic problem where Rust's ecosystem churn requires manual dependency management akin to Windows-style workflows.

The reply solidifies the opposition's case by connecting technical build challenges (previously discussed) with operational realities of distribution maintenance. It positions Rust adoption as threatening fundamental Linux distribution values - particularly the ability to manage system-wide dependencies coherently through package managers. This moves the discussion beyond just technical feasibility into systems administration tradeoffs, with Git's centrality making the stakes particularly high for distro maintainers.
