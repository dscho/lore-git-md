This is a technical discussion about Git release notification mechanisms, specifically addressing the feasibility of embedding release notes in Git tags. Junio Hamano responds to Jeff King's earlier points about potential downsides of this approach, focusing particularly on-disk efficiency concerns.

The email clarifies historical context around tag contents, with Hamano questioning whether release notes were ever actually embedded in tags (contrary to King's suggestion). He then strongly emphasizes that the storage overhead (#3 in King's list) would be prohibitive, since release notes would be duplicated between tags and the working tree without clear benefit.

Key technical points raised include: the immutability of tags once created, the efficiency of Git's tag-peeling operations, and the fact that `RelNotes` files are continuously updated in-tree. Hamano frames this as a fundamental design question - rather than asking why we don't duplicate information, we should question why we would want to duplicate it at all.

This continues the thread's exploration of release notification options while effectively ruling out tag-based solutions due to performance impacts. The discussion remains advisory with no patches proposed, maintaining focus on Git's existing notification channels (GitHub feeds, git-scm.com) and the `RelNotes` symlink tracking idea previously suggested.
