This is a documentation refinement discussion in the ongoing Rust infrastructure series. Phillip Wood follows up on Patrick Steinhardt's BreakingChanges announcement patch, clarifying his earlier feedback about build system error messages.

Phillip explains he's not advocating for earlier mandatory Rust requirements (which are planned to become default in Git 2.53 and mandatory by 3.0). Instead, he wants clearer user guidance when the build system fails to find a Rust compiler during the transition period. His specific suggestion is that when Rust is enabled by default in 2.53, the Makefile should proactively tell users how to build without Rust (using `WITH_RUST=NoThanks`) rather than making them search documentation.

This is a practical UX consideration during the phased transition, showing attention to real-world user experience as the project moves toward mandatory Rust. The exchange demonstrates careful coordination between documentation and build system behavior as the Rust integration progresses.
