This is a bugfix patch in the ongoing strvec memory management series, specifically addressing a leak in `git stash show` when using `--` arguments. Junio Hamano points out an issue with the test case in the original submission - it incorrectly assumes `git stash show` and `git stash show --` should produce identical output, which only happens to be true in the test's artificial scenario where the stash contains no changes.

The core fix (telling `setup_revisions()` to free allocated strings) remains valid, but the test needs adjustment. Hamano suggests either creating a more realistic test case that properly handles the output difference, or simply verifying the command runs without leaks. He also notes the broader oddity in `stash show`'s argument parsing behavior (treating arguments after `--` as stash options rather than pathspecs), though this patch deliberately avoids changing that existing behavior.

This is patch 1/6 in a series that has already been merged, addressing both immediate memory safety issues and broader architectural improvements to strvec usage. The discussion here is about refining the test case to properly reflect Git's actual behavior while still verifying the leak fix works.
