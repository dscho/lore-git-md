This is a refactoring patch in Ezekiel Newren's ongoing series to prepare xdiff internals for Rust compatibility. It removes the redundant `xdfile_t.ha` array, which stored hash values that could already be accessed via `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. The change makes the code about 5% slower, though the series as a whole maintains neutral performance due to offsetting optimizations elsewhere. The patch is part of a larger effort to simplify xdiff's data structures before introducing Rust-specific types.

The commit explains that while this change has a performance cost, keeping the redundant array would complicate future cleanups. A follow-up patch will investigate removing the `chastore` field and analyze the combined impact. The changes touch core diff algorithms (Myers and minimal) but maintain identical behavior while making the codebase more straightforward for the planned Rust integration.

This continues the pattern seen in earlier patches of removing redundant data structures and simplifying access patterns. The work appears carefully considered, with the performance tradeoffs clearly documented and balanced across the series. The patch follows logically from previous structural simplifications and keeps the code moving toward the eventual Rust integration target.
