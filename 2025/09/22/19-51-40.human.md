Refactoring patch in the xdiff series preparing for Rust compatibility. This is patch 11/12 in v4 of the series, which continues the work of simplifying xdiff's internals by replacing numeric literals with boolean values and clearer enum-style macros.

The patch converts the `xdfile_t.rchg` field (which tracks changed lines in the diff algorithm) from using `0`/`1`/`2` literals to `false`/`true` and introduces `NO(0)`, `YES(1)`, `MAYBE(2)` macros for the `dis1`/`dis2` fields. This makes the code more readable by giving semantic meaning to the numeric values. The changes touch four files (xdiffi.c, xhistogram.c, xpatience.c, xprepare.c) but are purely mechanical transformations with no behavior change.

This continues the pattern seen in earlier patches of the series - removing implicit assumptions and making the code's intent more explicit. The changes are straightforward and unlikely to be controversial, following the same approach as previous refactorings that have already been merged to 'next'. The patch maintains the series' careful attention to keeping performance neutral while improving code structure.

The work fits into the larger goal of preparing xdiff for potential Rust integration by eliminating C-isms that would be problematic in Rust. With only one patch remaining in the series, the structural simplifications appear nearly complete, having systematically removed redundant data structures and now cleaning up the remaining low-level value representations.
