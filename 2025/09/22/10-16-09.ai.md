This is a historical clarification in the gitk window geometry persistence thread. Mark Levedahl provides context about why position restoration was originally removed in 2008 (b9bee11526ec), explaining it was due to bugs in Cygwin's outdated Tcl/Tk 8.4.1 port. He notes this became irrelevant after 2011 when Cygwin switched to a modern X11-based Tcl/Tk implementation (now at 8.6). The response confirms there are no longer platform-specific concerns blocking window position restoration, validating the current approach in Michael Rappazzo's patch to use `after idle` for geometry restoration. This settles Johannes Sixt's historical inquiry and removes any lingering doubts about whether the original removal rationale might still apply to modern systems. The thread can now proceed with confidence that the technical solution in v2 series is sound, with only the Tags/Heads window implementation details (from patch 2/2) remaining for discussion.
