This is a discussion about the Rust transition timeline and its implications for hash interoperability, specifically responding to concerns raised by SZEDER Gábor.

Junio C Hamano clarifies that when Rust becomes mandatory in Git 3.0, the entire Git binary will require Rust to build - not just for hash interoperability features. He confirms Brian m. carlson's statement that "nothing will work" without Rust at that point, as even basic components like the varint subsystem will be Rust-only. 

The email reveals some tension around the transition schedule. While the current documentation outlines a phased approach (optional in 2.52, default in 2.53, mandatory by 3.0), Hamano expresses concern that the ~18 month timeline may be too aggressive for some platforms to adapt. He also notes his preference that hash compatibility features could have been made Rust-only earlier, while keeping core Git functional without Rust for longer.

A minor mystery emerges about how Brian m. carlson's policy document became incorporated into Ezekiel Smith's patch series without Hamano having seen it directly. The discussion remains technical but shows the maintainer's careful attention to both the practical impacts on users and the process by which these decisions are being made.
