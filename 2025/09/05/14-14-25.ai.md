This is a reply in the ongoing Rust infrastructure thread, where Phillip Wood provides feedback on Patrick Steinhardt's RFC patch series introducing Rust to Git core. The email focuses on two key aspects of the transition plan.

Phillip agrees with the general approach of a gradual introduction period for Rust, but questions the timeline that waits until Git 3.0 to make Rust mandatory. He suggests instead a 6-month transition period from announcement to mandatory status, arguing that Git 3.0 has traditionally been for user-facing changes rather than build requirements. This would give distributors clearer expectations about when they need to adapt their build processes or limit their support to security updates.

The second major point is about the test balloon implementation. While appreciating that Makefile support has been added (contrary to Patrick's initial statement that it being missing), Phillip argues the test balloon would be more effective if Rust building were enabled by default with clear opt-out instructions when builds fail. This would better surface potential platform issues during the transition period.

The email references Phillip's previous message [1] where he originally proposed the 6-month transition period. The technical discussion remains focused on the transition strategy rather than implementation details, as the build system questions appear resolved from previous exchanges in the thread. The reply maintains a constructive tone while pushing for a more aggressive adoption timeline than originally proposed.
