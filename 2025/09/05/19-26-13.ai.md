Bugfix patch addressing a segfault in multi-pack-index operations, part of a larger series (1/6) that's now in its third iteration. This specific patch fixes uninitialized memory access in `fill_packs_from_midx()` that could occur when closing packfiles during MIDX operations, particularly visible under SANITIZE=address with many packfiles.

The core issue stems from fcb2205b77's refactoring which introduced conditions where packfiles might be properly initialized in some cases but not others. The fix:
- Reverts to unconditionally loading packfiles while maintaining incremental MIDX scanning capability
- Moves `open_pack_index()` calls closer to their actual usage points
- Adds an EXPENSIVE test case with 100 packfiles that reliably reproduces the issue
- Maintains error reporting while fixing the error return value check

The patch shows careful attention to both the immediate segfault and related error handling paths. The test demonstrates real-world conditions where this could occur (background maintenance operations with many packfiles). This appears to be a well-justified fix for a concrete problem, with the test providing good validation. The changes align with the series' broader goal of hardening MIDX error handling while maintaining existing functionality.
