Bugfix for upload-pack's protocol v2 ACK behavior, addressing duplicate non-commit object handling. This is the second patch in a series where the first (test modernization) has already been merged.

Patrick Steinhardt fixes an edge case where upload-pack would repeatedly store and ACK non-commit objects in protocol v2 when clients sent duplicate "have" lines. While commits were properly deduplicated using the THEY_HAVE flag, other object types weren't, causing two issues: unnecessary ACKs in v2 and potential (though slow) memory growth in the have_obj array.

The patch restructures do_got_oid() to apply THEY_HAVE consistently across all types while maintaining commit parent processing. Tests demonstrate the fixed behavior - v2 now ACKs non-commits once like commits, while v0 preserves the old duplicate-ACK behavior for compatibility. The memory growth concern, while not severe (4MB/s in testing), is now fully addressed.

This builds on the merged test modernization from part 1, adding new protocol-specific test cases. The solution is clean and focused, maintaining v0/v2 behavior differences while fixing the v2 regression. The patch appears well-considered, with clear commit message and thorough test coverage of both protocol versions.
