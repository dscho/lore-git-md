This thread addresses a platform-specific build issue affecting HP-UX systems when building Git 2.51.0's test suite. The problem initially appeared to require both Makefile change (adding compatibility objects to the link line) and header inclusion to resolve linking failures for the `gitmkdtemp()` compatibility function. 

Michael Osipov reported the original fix, but Jeff King questioned whether the Makefile change was truly necessary. Further testing by Osipov confirmed King's suspicion - the issue was resolved simply by including `compat/posix.h` in the test framework's headers, as the compatibility functions were already properly linked through `libgit.a`. This leaves the thread with one resolved technical issue (the HP-UX build now works) but an open architectural question about how best to handle such cases long-term.

The remaining discussion centers on whether Git should modify its local copy of the clar test framework (by including Git-specific compatibility headers) or whether this class of portability issues should be addressed upstream in the clar framework itself. Patrick Steinhardt's input is awaited, as the maintainer of Git's clar integration, to guide whether this should be treated as a Git-specific workaround or a general improvement to the test framework's portability design.
