This is a bugfix patch in the midx-write series addressing a segfault in multi-pack-index operations. The patch focuses on fixing `fill_packs_from_midx()` to properly handle packfile initialization, correcting a regression introduced in Git 2.47.0 that could lead to uninitialized memory access during packfile closing.

The key changes revert some packfile handling behavior while maintaining incremental midx scanning capabilities. The fix ensures we always prepare MIDX'd packfiles (though not necessarily open them) and properly handle allocation failures. A new EXPENSIVE test with 100 packfiles reliably reproduces the issue under SANITIZE=address.

Patrick Steinhardt's review raised questions about the design rationale for packfile opening conditions, which Derrick Stolee clarifies in this response. The discussion reveals some subtle points about when packfiles should be opened versus just prepared, with Stolee confirming the test cases need to work even when .idx files disappear. While the patch addresses the immediate segfault issue, there's ongoing discussion about whether some aspects (like error return handling) might warrant separate commits for clarity.

This appears to be a well-justified fix for a concrete problem, with thorough testing and clear explanations of the tradeoffs involved in the solution. The patch is part of a larger series that has already received positive reviews from multiple maintainers.
