Bugfix for `git subtree` addressing a regression in squashed subtree merges under prefixes during split operations. This is the final v2 patch in a thread that has reached technical consensus, targeting the maint-2.44 branch.

The patch fixes a regression introduced in commit 98ba49ccc2 where squashed merges of nested subtrees (e.g. `subA/subB`) were being incorrectly ignored during split operations. The root cause was `should_ignore_subtree_split_commit()` examining parent commits via `git log -1 --grep` when it should only check the specified commit. The fix rewrites this function to use `git show` with trailer parsing to examine just the target commit, while maintaining the same logical conditions for ignoring commits.

Key technical changes:
- Replaces three `git log` calls with a single `git show` that extracts both `git-subtree-dir:` and `git-subtree-mainline:` trailers
- Adds `--no-show-signature` for consistency with existing code
- Removes non-POSIX `local` usage in the rewritten function
- Adds comprehensive tests for nested subtree behavior with both regular and squashed merges

The patch includes new test cases in t7900-subtree.sh that verify correct handling of nested subtrees under split prefixes, covering both initial `subtree add` and follow-up `subtree merge` operations with and without `--squash`. The test helper `test_create_subtree_add` was added to support this testing.

All technical points from the discussion have been addressed in this version, including trailer handling, recursion behavior, and test coverage. The patch maintains the conservative approach of keeping the `git-subtree-dir:` trailer check despite its unclear purpose, as agreed in the thread.
