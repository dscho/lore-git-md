This is a two-part bugfix series addressing duplicate ACK behavior in upload-pack's protocol v2. The series builds on previous discussion where the first patch (test modernization) was already approved, and the second patch was revised to handle an edge case in commit parent processing.

The core issue is that upload-pack was storing and ACKing duplicate non-commit object IDs from clients, wasting memory and bandwidth. The fix modifies `do_got_oid()` in upload-pack.c to properly deduplicate these objects while ensuring commit parent relationships are still tracked correctly.

The v2 revision changes the order of operations to always process commit parents before checking the THEY_HAVE flag, addressing Junio's concern about potential regression with non-chronological commit ordering. The implementation remains focused on the memory optimization goal while maintaining protocol correctness.

The first patch modernizes test infrastructure in t5530-upload-pack-error.sh, which received explicit approval in previous discussion. The second patch's changes are now more conservative about edge cases while still achieving the deduplication goal. The series appears well-considered, with the author addressing feedback and maintaining focus on the specific optimization rather than broader protocol changes.
