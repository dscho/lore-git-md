This is a discussion thread about the Rust transition documentation in Patrick Steinhardt's RFC series. Matthias Aßhauer raises several questions and concerns about the proposed timeline for making Rust mandatory in Git's build process.

Key points from Matthias' response:
1. Questions the distinction between platforms that "haven't implemented a Rust toolchain" vs those with "no support for Rust at all", suggesting all platforms could theoretically support Rust tooling.

2. Points out unclear wording in the documentation about Rust detection ("detected by Rust" vs likely meaning "detected by Meson").

3. Notes apparent contradiction in the phase 2 description where Rust is called "mandatory" but still has an opt-out mechanism.

4. Suggests making the phase 3 wording more explicit about default Rust builds even without breaking changes.

5. Raises concerns about committing to LTS support until gccrs is ready, proposing either a time limit or additional criteria given the uncertainty around gccrs development.

The discussion focuses on refining the transition plan's clarity and feasibility, particularly around platform support timelines and LTS commitments. This follows the technical implementation work in previous patches (v1-v7) and addresses the policy aspects introduced in v5's BreakingChanges.adoc documentation.

The exchange highlights important practical considerations for the Rust transition that weren't fully addressed in the original proposal, particularly around platform support guarantees and LTS policy wording. These are precisely the kinds of ecosystem concerns the RFC process is meant to surface before finalizing such a significant change.
