This is a documentation patch proposing Rust as a mandatory build requirement for Git 3.0, part of Patrick Steinhardt's ongoing RFC series introducing Rust infrastructure to Git core. The patch adds a formal announcement to BreakingChanges.adoc outlining the planned transition timeline.

The document describes a phased approach over multiple Git versions (2.52-3.0) to make Rust mandatory, starting with optional support in 2.52 and progressing to full requirement in 3.0. Key milestones include initial auto-detection, optional breaking changes in 2.53, default-enabled Rust in 2.54, and finally mandatory Rust in 3.0. The proposal acknowledges platform challenges and offers an LTS release before 3.0 for distributions needing more time to adopt Rust toolchains.

The patch serves as both a heads-up to the ecosystem and a concrete plan for maintainers, though it notes the timeline estimates are non-binding. It builds on previous infrastructure work in the series while focusing on the human/organizational aspects of the Rust transition. The careful staging reflects Git's role as critical infrastructure and the need to accommodate diverse platform constraints.
