This is a build system discussion about Git's version string format for snapshot builds. The thread centers on whether to maintain Git's long-standing dotted format (e.g. `2.51.0.178.g2462961280`) or switch to the standard `git describe` hyphenated format (`2.51.0-178-g2462961280`).

Junio Hamano weighs in supporting the status quo, agreeing with brian m. carlson's position that Git shouldn't change its version format to accommodate newer tools like b4. He notes that Git has never followed SemVer (despite Jonas Rebmann's earlier mention of it) and that the current format has 17 years of established usage. Hamano suggests that tools needing different formats can use Git's existing escape hatch of providing a custom version file.

The discussion has evolved from a technical compatibility issue into a broader policy question about whether Git should adapt to modern tooling expectations or maintain historical consistency. While the technical change would be simple (removing one sed substitution), the maintainers appear to favor stability over format standardization at this time.
