Bugfix and test modernization series addressing duplicate ACK behavior in upload-pack protocol v2. This is the second version of a two-patch series that has already seen significant discussion and iteration.

The cover letter explains the series fixes an issue where upload-pack would store duplicate object IDs in its `have_obj` array when clients send repeated "have" lines for non-commit objects, leading to redundant ACKs. The key change in v2 is reordering the parent commit processing in `do_got_oid()` to ensure grandparents are properly marked as `THEY_HAVE` even when commits are sent non-chronologically, addressing a potential regression identified in v1.

The first patch modernizes test infrastructure in t5530-upload-pack-error.sh, which has already received maintainer approval for its test pattern updates. The second patch modifies upload-pack.c to deduplicate non-commit objects while preserving commit parent processing. The implementation now checks the `THEY_HAVE` flag after processing commit parents rather than before, ensuring correctness while maintaining the memory optimization benefits.

Technical details include:
- Test modernization follows current Git conventions (&& chaining, git -C usage)
- Protocol v2-specific behavior change in upload-pack.c
- Restructured `do_got_oid()` to process parents before deduplication
- Maintains distinction between protocol v0 (preserves duplicates) and v2 (deduplicates)
- Builds on commit c44beea485 (Git 2.51)

The series appears technically sound after addressing the edge case in v1, with consensus forming around this focused optimization while leaving broader protocol behavior changes for potential future work. The changes are conservative and maintain backward compatibility.
