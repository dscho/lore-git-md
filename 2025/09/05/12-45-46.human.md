This is a discussion about Rust transition documentation in Patrick Steinhardt's RFC series introducing Rust infrastructure to Git. Matthias Aßhauer raises several clarifying questions about the proposed timeline for making Rust mandatory in Git builds.

The email focuses on patch 5/7 in the series, which documents the planned transition in BreakingChanges.adoc. Aßhauer identifies several points needing clarification in the documentation:

1. Questions the distinction between platforms without Rust toolchains versus those where Rust is theoretically possible but not yet implemented
2. Points out a potential wording issue about Rust auto-detection (possibly meaning Meson should be mentioned instead)
3. Notes confusion around the "mandatory but opt-out" phrasing for Git 2.53
4. Suggests being more explicit about Rust becoming default in Git 2.54 even without breaking changes
5. Raises concerns about committing to LTS support until gcc-rs is ready, suggesting a time limit might be safer

The discussion highlights the careful balancing act needed in documenting this major change - between providing clear guidance to packagers while not over-committing to timelines that might slip or technical solutions that might not materialize. Aßhauer's questions show engagement with the practical implications of the transition plan, particularly around platform support and distribution packaging concerns.
