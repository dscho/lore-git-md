This thread discusses a proposed change to how Git formats version strings for snapshot builds. Currently, Git converts the standard hyphenated output from `git describe` (like "2.51.0-178-g2462961280") to use dots instead ("2.51.0.178.g2462961280"), a transformation added in 2007 for RPM compatibility. D. Ben Knoble proposed removing this conversion to improve compatibility with modern tools like b4 that expect the standard format.

The discussion has revealed differing perspectives. Jonas Rebmann provided evidence that modern RPM packaging no longer requires the dotted format, supporting the change. However, brian m. carlson and now Junio Hamano argue for maintaining the status quo, emphasizing Git's long-standing versioning practices and the potential disruption to existing users. Junio noted that the version file provides a way for specific tools to get alternative formatting without changing the default behavior.

The technical change itself is straightforward - removing one sed substitution in the build script - but the debate has shifted to project policy questions. Key considerations include whether 17 years of consistent behavior should be preserved, and whether there are still critical use cases requiring the dotted format. With Junio's input, the discussion appears to be leaning toward keeping the current format unless stronger evidence emerges of widespread tooling issues beyond b4's needs.
