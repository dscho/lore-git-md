This thread discusses a proposed change to how Git formats version strings in snapshot builds. Currently, the build system converts `git describe` output (like "2.51.0-178-g2462961280") to use dots instead of hyphens ("2.51.0.178.g2462961280"), a transformation added in 2007 for RPM compatibility. D. Ben Knoble proposed removing this conversion to improve compatibility with tools like b4 that expect standard version string formats.

The discussion has revealed two main perspectives. Brian M. Carlson argues for maintaining the 17-year-old dotted format, noting Git doesn't follow SemVer and that tools should adapt to Git's established behavior. Jonas Rebmann has countered that the current dotted format doesn't match any modern versioning scheme, including current RPM standards, and that the hyphenated format would be more widely recognizable. Rebmann also notes the immediate b4 compatibility issue could be solved either way, shifting the focus to which format makes more sense long-term.

The core questions remain unresolved: whether to prioritize tool compatibility or historical consistency, and whether the original RPM packaging needs that motivated the dotted format still exist today. The technical change itself is straightforward (removing one sed substitution), but the decision involves weighing Git's versioning philosophy against modern tool expectations.
