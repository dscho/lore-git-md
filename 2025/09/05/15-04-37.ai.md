Post-merge discussion about default branch name advice messages. This is a follow-up to the recently merged series that changed Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES.

Junio Hamano raises two distinct scenarios for advice messages: (1) the existing "preference" case (helping users who want to change from master to another name) and (2) a new "usability" case (helping users who need master temporarily to follow old tutorials). He suggests these require different advice messages, with the latter being particularly important for new users encountering old documentation.

Phillip Wood expresses skepticism about the value of continuing advice messages post-3.0, finding them annoying but acknowledging they served a transitional purpose. He questions whether enough users will need to customize branch names to justify new advice. However, Junio counters that the advice serves different purposes - the existing messages addressed personal preference during transition, while the proposed new message would address practical usability for following old tutorials.

Key technical points under discussion:
- Current advice system in advice.c/h
- Distinction between permanent configuration (init.defaultBranchName) and one-time branch renaming
- Backward compatibility considerations for tutorial materials
- Different user personas: those wanting to modernize vs those needing compatibility

The discussion reveals differing perspectives on the ongoing need for branch name advice, with Junio advocating for usability-focused messaging even after the default change, while Phillip questions whether the messages' value justifies their persistence. This touches on broader questions about how long transitional aids should remain and how to best support users navigating version-specific documentation.
