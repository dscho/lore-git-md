This is a feature proposal introducing Rust infrastructure to Git core, now in its second version as an RFC patch series. Patrick Steinhardt proposes making Rust a mandatory dependency starting with Git 3.0, with this series serving as an experimental test balloon similar to past C99 introductions.

The series focuses on build system integration, currently supporting meson (with Makefile support added in v2) and demonstrating Rust interoperability by converting the simple varint.c subsystem (92 lines) to Rust while maintaining C ABI compatibility. Key additions include a `WITH_RUST` build option flag, CI job updates, and documentation of the transition plan in BreakingChanges.adoc.

The proposal outlines a three-phase adoption strategy: current auto-detection, future opt-out configuration, and eventual mandatory requirement for Git 3.0. This addresses earlier concerns about silent fallback behavior while giving distributors time to adapt. The implementation remains deliberately minimal (just varint conversion) to allow infrastructure experimentation without committing to broader Rust adoption yet.

Notable changes in v2 include expanded build system support, better version reporting, and CI integration. The patch appears well-structured with clear incremental goals, though several open questions remain about platform compatibility (especially NonStop/embedded systems) and long-term build system unification between meson and Cargo. The RFC status and phased approach suggest this is a serious but cautious proposal inviting community feedback.
