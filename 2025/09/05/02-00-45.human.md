This is a technical discussion about Rust build system approaches in Git, specifically comparing meson vs Cargo implementations. Eli Schwartz (Gentoo maintainer) responds to Ezekiel Newren's preference for Cargo by defending meson's capabilities and raising concerns about Cargo's behavior.

Schwartz makes several key points in favor of meson:
1. Meson can import Rust crates via Cargo.toml, potentially allowing Makefile compatibility through subprojects
2. Challenges with crates in meson are limited to build.rs scenarios, which most crates avoid anyway
3. Meson handles file installation better than Cargo for Git's needs
4. Cargo's test behavior is problematic for distro packaging (citing a Gentoo example)
5. Meson has rust-analyzer support since 0.64, questioning RustRover's relevance

The email highlights an emerging technical split in the Rust integration strategy, with Schwartz providing concrete counterpoints to Newren's Cargo advocacy. As a package maintainer, Schwartz brings practical concerns about build reliability and long-term maintenance that complicate the "Rust supplanting C" vision. The tone is technical but pointed, with clear skepticism about Cargo's suitability for Git's needs. This continues the thread's expansion into build system implementation tradeoffs while maintaining focus on practical deployment concerns.
