This is a discussion response in the ongoing thread about version string formatting in Git's build system. The thread began with a patch proposing to stop converting `git describe` output from hyphen-separated to dot-separated format, citing SemVer compatibility issues with tools like b4.

Brian M. Carlson pushes back against the original rationale, making two key points: First, that Git doesn't follow Semantic Versioning (SemVer) in general, so SemVer compliance shouldn't drive version string formatting decisions. Second, they argue that since Git's dotted format has been stable for 17 years, newer tools like b4 should adapt to Git's existing conventions rather than vice versa.

The response doesn't address the technical merits of the patch itself (which modifies `GIT-VERSION-GEN`), but instead challenges the motivation. This introduces a new dimension to the thread - whether version string changes should prioritize tool compatibility or maintain historical consistency. The exchange suggests this may become a philosophical debate about Git's versioning policies rather than just a technical build system change.
