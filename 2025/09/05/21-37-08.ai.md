Platform compatibility follow-up discussing HP-UX test build fixes.

Jeff King responds to Michael Osipov's patch addressing mkdtemp() linking failures in the unit test framework on HP-UX systems. While agreeing with the inclusion of compat/posix.h in clar/sandbox.h as a general improvement, he questions the necessity of explicitly adding $(COMPAT_OBJS) to the test program's link line since these objects should already be available through libgit.a. King notes that on Linux with NO_MKDTEMP=1, gitmkdtemp() is found without this change, suggesting the HP-UX behavior might indicate a deeper linking issue.

The response highlights two key technical points: (1) the tension between modifying imported clar framework code versus relying on Git's existing compatibility layer, and (2) uncertainty about why HP-UX requires explicit compat object linking when other platforms don't. This moves the thread from a straightforward bugfix to investigating platform-specific build system behavior, with Patrick Steinhardt (pks) now cc'd for clar framework expertise. The core question becomes whether the solution should live in Git's build system or require clar framework modifications.
