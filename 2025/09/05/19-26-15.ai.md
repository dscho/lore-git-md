Bugfix patch in the midx-write series addressing error handling in incremental multi-pack-index operations. This is patch 3/6 in version 3 of the series that fixes a segfault introduced in Git 2.47.0.

The patch converts direct `return -1` statements in `write_midx_internal()` to proper cleanup paths using `goto cleanup` when incremental MIDX operations fail. This ensures proper resource cleanup during error conditions that occur when:
- Creating temporary MIDX layers
- Adjusting shared permissions
- Opening chain files
- Linking MIDX to chain
- Renaming temporary files

The changes follow the error handling pattern established earlier in the thread, where errors are captured in the `result` variable before jumping to cleanup. While the commit notes these error conditions are difficult to reproduce in tests, the changes provide important memory safety guarantees during failure scenarios.

This continues the series' focus on robust error handling standardization, building on Patrick Steinhardt's earlier recommendations. The patch maintains the thread's pattern of using `error()` for both user feedback and status capture while ensuring proper resource cleanup paths.
