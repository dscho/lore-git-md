This is a cover letter for an RFC patch series introducing Rust infrastructure to Git core, now at version 2. Authored by Patrick Steinhardt, the series aims to make Rust a mandatory dependency starting with Git 3.0, currently in experimental RFC stage.

The series builds on previous discussion by adding Makefile support (previously meson-only) and introduces several key technical changes:
- A `WITH_RUST` preprocessor define to report Rust status in `git version --build-options`
- Relaxed meson version requirement from 1.9.0 to 0.42.0
- Added roadmap documentation in BreakingChanges.adoc
- Expanded CI testing with full build-and-test runs including Rust

The implementation demonstrates Rust integration by converting the simple varint.c subsystem (92 lines) to Rust (varint.rs) while maintaining C ABI compatibility. The cover letter emphasizes this is a test balloon for infrastructure development, not a feature push, with explicit goals to:
1. Allow experimentation time
2. Give distributors transition time
3. Announce the Git 3.0 mandatory Rust plan

Notable open items include pending Makefile support timeline, CI coverage for older meson versions, and platform-specific concerns (particularly NonStop). The phased transition approach (detect -> opt-out -> mandatory) addresses earlier feedback about silent fallback masking platform issues.

The series represents continued technical refinement while maintaining RFC flexibility, with build system choices becoming more concrete. Key files touched include build infrastructure (meson.build, Makefile), CI configs, and the new Rust implementation files (src/lib.rs, src/varint.rs). The BreakingChanges.adoc update formally documents the Rust adoption roadmap.
