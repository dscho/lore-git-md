This is a documentation patch proposing Rust adoption timeline as part of the ongoing Rust infrastructure series. Patrick Steinhardt adds a BreakingChanges.adoc entry formalizing the planned transition to mandatory Rust support in Git 3.0, following the current test balloon approach with optional Rust builds.

The document outlines a phased 4-step transition:
1. Git 2.52: Initial optional auto-detected Rust support (current state)
2. Git 2.53: Rust required when building with breaking changes flag
3. Git 2.54: Rust enabled by default (but still optional via flags)
4. Git 3.0: Rust becomes unconditional requirement

Key technical details include the build system flags (`WITH_RUST=YesPlease` for Makefile, `-Drust=enabled` for meson) and the plan to maintain Git 2.x as an LTS release for platforms needing more time to adopt Rust toolchains. The document acknowledges platform challenges (NonStop, bootstrapping) and positions the current varint conversion as a test case for ecosystem readiness.

This represents a significant policy declaration in the Rust adoption effort, establishing concrete milestones while leaving flexibility for platform-specific concerns. The phased approach balances forward momentum with ecosystem accommodation, though the NonStop compatibility question from Randall Becker remains unaddressed in this specific patch. The documentation follows Git's breaking change format while introducing novel concepts like the LTS bridge release for Rust transition.
