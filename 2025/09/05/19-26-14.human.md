Bugfix patch in the midx-write series, restoring error handling behavior.

This is the second patch in version 3 of a series fixing a segfault in multi-pack-index operations. The patch restores an error code that was accidentally dropped in a previous commit (fcb2205b77), ensuring that failures in `fill_packs_from_midx()` properly propagate as command failures. The change is small but important - it adds back a `result = 1` before cleanup when the pack loading fails.

The patch includes an enhanced test case that verifies both the error propagation and the error message content. The test deletes a packfile and confirms that the multi-pack-index write fails with the expected "could not load pack" message, using the modern `test_grep` helper instead of raw `grep`.

This appears to be a straightforward and well-tested fix that completes the error handling improvements in the series. The commit message clearly explains the change and its context within the larger midx-write cleanup effort.
