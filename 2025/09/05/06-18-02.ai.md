This is the second patch in a two-part series addressing duplicate ACK behavior in upload-pack protocol v2, following the already-merged test modernization in patch 1/2. The patch fixes a protocol v2-specific issue where non-commit objects (like trees and blobs) were being redundantly stored in the `have_obj` array when clients sent duplicate "have" lines, leading to unnecessary ACKs and potential memory growth.

The key changes restructure `do_got_oid()` in upload-pack.c to:
1. Process commit parents before checking the THEY_HAVE flag, ensuring grandparents are properly marked when clients send commits non-chronologically (fixing a regression from v1)
2. Apply the THEY_HAVE flag consistently to all object types, not just commits
3. Maintain protocol v0's behavior of sending duplicate ACKs while making v2 deduplicate all object types

The patch includes new tests in t5530 that verify:
- Protocol v0 still sends duplicate ACKs for non-commits (backward compatibility)
- Protocol v2 now properly deduplicates ACKs for all object types
- The tests use the modernized patterns from patch 1/2 (git -C, && chaining)

The memory growth issue, while not catastrophic (measured at ~4MB/s), is now fully addressed by preventing unbounded growth of the `have_obj` array. The solution maintains the original memory optimization goals while fixing edge cases, particularly around non-chronological commit sending. This completes the series' goal of fixing protocol v2's ACK behavior without requiring broader protocol changes.
