This is a policy discussion email in the ongoing Rust infrastructure thread, where Sam James (Gentoo maintainer) reinforces Phillip Wood's concerns about Rust adoption timelines and platform support. The email focuses on the distinction between optional Rust bindings (already present since Git 2.49.0) and mandatory Rust requirements for core Git functionality.

Key technical points raised:
- Notes that distributions treat language bindings as low-priority optional components, not indicators of future core requirements
- Highlights practical issues with system-wide Rust library installations and Meson build system integration
- Points out the current Rust bindings live in contrib/ (lower visibility) rather than core build system

Policy arguments:
- Supports Wood's position that release notes haven't properly signaled impending mandatory Rust requirements
- Emphasizes need for clear security update commitments for non-Rust platforms
- Argues prior mailing list discussions don't constitute sufficient notice for the broader ecosystem
- Reinforces distinction between developer discussions and formal announcements to downstreams

The email strengthens the conservative position in the thread by adding concrete distribution maintainer perspectives on build system realities and package management concerns. It particularly highlights the gap between developer intentions and downstream interpretation of feature flags. The technical observations about Rust's packaging model and Meson integration provide new dimensions to the discussion beyond the core policy debate.
