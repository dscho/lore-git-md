This thread addresses a bug in the new `git last-modified` command that triggers a BUG() when processing criss-cross merges. The root cause traces back to 2006, when `diff_tree_combined()` began unconditionally forcing recursive mode, conflicting with `last-modified`'s path tracking in non-recursive mode. 

The discussion has evolved through several iterations, with Patrick Steinhardt and Toon Claes as the primary participants. Earlier versions proposed removing the recursive override entirely, but the current v3 patch takes a more conservative approach by introducing a new `no_recursive_diff_tree_combined` flag that lets `last-modified` opt out of the forced recursion while maintaining backward compatibility for other callers like `diff-tree -c`. This addresses Patrick's concerns about broader impacts while preserving the 2x performance improvement for `last-modified`.

The solution demonstrates careful consideration of Git's diff machinery history - the patch now modifies behavior only where needed rather than making sweeping change. Test coverage has been expanded to specifically verify criss-cross merge handling. While the technical debate has largely concluded, the thread illustrates the challenges of modifying long-standing behaviors in core Git components, particularly when balancing bugfixes against backward compatibility.
