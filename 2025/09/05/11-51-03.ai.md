CI / build system patch extending Rust testing infrastructure in the Git CI pipeline. This is the final patch in Patrick Steinhardt's RFC series introducing Rust to Git core, specifically focusing on testing the breaking-changes configuration with Rust enabled.

The patch modifies two CI scripts to ensure Rust tooling is available and enabled for breaking-changes test jobs. In `install-dependencies.sh`, it adds `rustc` to Fedora/AlmaLinux package lists and `cargo` to Ubuntu/Debian lists. In `run-build-and-tests.sh`, it sets `WITH_RUST=YesPlease` and adds `-Drust=enabled` to meson flags for breaking-changes jobs, ensuring the Rust build infrastructure and converted subsystems (like the varint example from earlier patches) are properly tested.

This completes the CI testing refinements started in v6 of the series, now ensuring Rust components are actually exercised in the breaking-changes test environment that replaced the old pedantic job. The changes are straightforward plumbing - adding package dependencies and build flags - but critical for validating the Rust integration work across the series. The patch maintains consistency with the dual build system approach (meson + Makefile) seen throughout the RFC.
