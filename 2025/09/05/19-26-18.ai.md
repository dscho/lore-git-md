This is the final patch in the midx-write bugfix and cleanup series, focusing on error handling standardization in `write_midx_internal()`. The patch simplifies the error case management by initializing the `result` variable to -1 (error) at the start and only setting it to 0 (success) in the success paths. This eliminates several redundant error assignments and makes the control flow more consistent - all error conditions now fall through to the same cleanup section with the default -1 value.

Key technical changes:
- Initializes `result = -1` at function start rather than 0
- Removes 7 redundant `result = 1` or `result = -1` assignments before `goto cleanup`
- Adds explicit `result = 0` for two success cases that previously jumped to cleanup without setting a value
- Maintains all existing error reporting via `error()` calls while streamlining the status tracking
- The changes implement the final piece of error handling standardization discussed in the thread, following Patrick Steinhardt's preference for using `error()` to both report and capture errors in one operation while addressing Junio Hamano's concern about uninitialized variables.
