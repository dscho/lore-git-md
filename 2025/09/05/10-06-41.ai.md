Final documentation refinement for the default branch name change series.

This email from Phillip Wood addresses the last remaining documentation tweaks for the merged series that changes Git's default branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The changes respond to Junio Hamano's suggestions about wording improvements in BreakingChanges.adoc, specifically adding a comma after the introductory phrase and clarifying that "many of the big Git forges" refers to their new repositories.

The discussion also explores whether a new advice message might be needed post-Git 3.0 for users following older tutorials that assume "master" as the default branch. Phillip expresses skepticism about the need for this, noting the long warning period and that the current advice already serves its purpose. The email confirms the CI changes are correct and that linux-TEST-vars will continue testing with "master" to ensure no implicit assumptions about branch names exist in the test suite.

Technical details remain unchanged from the merged series, with all test infrastructure updated and final decisions made about remaining "master" references in tests (particularly the reftable test case requiring explicit 6-byte names). The MAYBE_UNUSED annotation on the 'quiet' parameter in refs.c is noted as potentially removable if new advice were added later.
