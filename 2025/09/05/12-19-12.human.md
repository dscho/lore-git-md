This is a discussion about a proposed change to Git's build system version string formatting. The original patch suggested reverting from a dotted format (e.g. `2.51.0.178.g2462961280`) back to the standard `git describe` hyphenated format (`2.51.0-178-g2462961280`) for better SemVer compatibility, particularly to help the b4 tool parse version strings.

Brian m. carlson pushes back on this rationale, noting that Git doesn't follow Semantic Versioning in general and makes breaking changes without major version bumps. They argue that since Git has used this dotted format for 17 years, newer tools like b4 should adapt to Git's conventions rather than vice versa.

The exchange highlights a tension between maintaining long-standing behavior versus adapting to modern tooling needs. While the original change was motivated by practical parsing issues, carlson suggests the burden of compatibility should fall on the newer tool rather than altering Git's established version string format.
