This is part of the ongoing Rust infrastructure RFC series (v3), specifically addressing the transition policy debate around optional Rust components. Elijah Newren points out that Rust has already been an optional component in Git for three releases (since v2.49.0), countering Sam James' suggestion that making components optional would be a new transition mechanism. 

The email highlights that the infrastructure for optional Rust support exists and has been tested in production, with Newren providing concrete references to the v2.49.0 release notes and GitHub blog post as evidence. This suggests the policy discussion may be reframing existing capabilities as new proposals.

The exchange shows the continuing tension between those wanting a more gradual transition (James representing Gentoo's packaging concerns) and those noting the transition is already underway (Newren pointing to established precedent). The technical implementation appears stable enough that the debate has shifted to governance questions about how and when to make components mandatory rather than whether to support Rust at all.
