Bugfix for `git subtree` addressing a regression in squashed subtree merges under prefixes during split operations. This fixes a case where nested subtrees (like `subA/subB`) merged with `--squash` were being incorrectly ignored during splits of their parent directory (`subA/`), causing missing files and incorrect commit hashes since Git v2.44.0-rc0.

The patch rewrites the `should_ignore_subtree_split_commit()` function to properly examine individual commits rather than searching parent commits with `git log -grep`. It now uses a single `git show` call to extract commit trailers, adding `--no-show-signature` for consistency with previous security fixes. The core logic for identifying ignored subtrees remains the same - it still checks for the `git-subtree-dir:` trailer and absence of `git-subtree-mainline:` - but does so more accurately.

Colin Stagner's v2 incorporates review feedback by removing non-POSIX `local` usage in the rewritten function while keeping other `local` instances in untouched code. The patch includes new test cases that verify correct handling of nested subtrees, both with and without `--squash`, covering both initial subtree adds and follow-up merges. The fix is targeted for maint-2.44 and later versions.

The technical discussion appears settled, with Phillip Wood and Colin reaching consensus on the implementation approach. The patch looks well-constructed with thorough test coverage for the specific issue, though broader test coverage for subtree trailer behavior remains as future work.
