This is a follow-up discussion about a build system patch that proposes changing how Git's version strings are formatted. The original patch (from Jonas Rebmann) suggested removing a conversion that changes hyphens to dots in `git describe` output, arguing it breaks SemVer compatibility and causes issues with tools like b4.

Kristoffer Haugsbakk's email doesn't directly engage with the technical debate between Rebmann and brian m. carlson about whether to change the version string. Instead, it focuses on commit message formatting conventions, pointing out that the original patch used kernel-style trailers and commit references that don't match Git project norms. The email helpfully shows how to trace the historical context of the version string change and notes that Git typically places references in the message body rather than using trailers (except for attribution).

While not taking a position on the version string debate itself, this email serves as useful meta-commentary about project conventions that could help improve the patch's presentation in a future revision. The core technical discussion about version string formats remains unresolved from earlier in the thread.
