This is a follow-up email in the ongoing discussion about Patrick Steinhardt's `git-history` command proposal. The thread has progressed to version 3 of the RFC series, which introduces new history editing subcommands inspired by Jujutsu (jj).

Kristoffer Haugsbakk points out that the cover letter incorrectly lists `reword` as a future addition when it was actually implemented in v2. Patrick acknowledges this oversight and notes the correction has been made locally.

The exchange is brief but serves as an important documentation fix for the series. The `reword` subcommand, which allows changing commit messages while preserving other metadata, has been part of the implementation since v2 and includes features like hook execution and handling of edge cases (merge commits, dirty worktrees, root commits). This clarification helps maintain accurate tracking of the feature set as the discussion continues.
