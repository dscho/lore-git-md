This is a bugfix patch in the midx-write series addressing error handling in multi-pack-index operations.

The patch restores a missing error code assignment that was accidentally dropped in commit fcb2205b77. When `fill_packs_from_midx()` fails, the code now properly sets `result = 1` before jumping to cleanup, ensuring the error propagation matches the original intended behavior. The change is minimal - just a single line addition in midx-write.c.

The test case is enhanced to verify this error case by:
1. Moving a packfile out of the way to trigger the failure condition
2. Confirming `git multi-pack-index write` fails as expected
3. Checking the error message contains "could not load pack" using the modern `test_grep` helper

This patch follows Patrick Steinhardt's earlier recommendation to use `test_grep` rather than raw `grep` in tests, continuing the test modernization effort in this series. The change is straightforward and uncontroversial, maintaining consistency with the series' goal of robust error handling in midx operations. The test provides clear validation that the restored error path works as intended.
