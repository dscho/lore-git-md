This is the final patch in Karthik Nayak's v4 reftable fsck validation series, implementing the actual fsck integration for table name validation in the reftable backend. The patch adds glue code in `refs/reftable-backend.c` that connects Git's fsck infrastructure with the reftable library's validation checks introduced earlier in the series.

Key technical elements:
1. Introduces `badReftableTableName` as a new fsck warning ID in `fsck.h` and documents it in `fsck-msgids.adoc`
2. Implements `reftable_be_fsck()` to validate both main and worktree reftable stacks using the callback-based API from patch 6/7
3. Adds error mapping between reftable's `REFTABLE_FSCK_ERROR_TABLE_NAME` and Git's `FSCK_MSG_BAD_REFTABLE_TABLE_NAME`
4. Includes comprehensive test cases in `t0614-reftable-fsck.sh` that verify detection of malformed table names (non-hex-hex-hex.ref patterns)
5. Maintains lexicographical ordering when adding fsck.h include in reftable-backend.c

The implementation enforces the reftable spec's suggested naming convention (`${min_update_index}-${max_update_index}-${random}.ref`) but treats violations as warnings rather than errors. The test cases cover various invalid patterns including wrong extensions, missing components, and non-hex values.

This completes the series' goal of adding basic fsck validation to the reftable backend, with the callback architecture designed to accommodate future checks. The patch follows the established pattern of keeping reftable validation separate from Git's core fsck while maintaining consistent error reporting.
