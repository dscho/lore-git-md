This thread explores the deprecation of the legacy `git whatchanged` command and migration paths to modern `git log` alternatives. Kristoffer Haugsbakk initiated the discussion by establishing that `git whatchanged` is essentially a wrapper around `git log` with specific defaults, proposing `git log --no-merges --raw` as the closest replacement. Junio C Hamano later suggested simplifying this to just `git log --raw`, questioning whether `--no-merges` adds enough value to justify its inclusion in the standard recommendation.

Neal Miller's recent contribution provides a concrete user perspective, showing that their personal `git whatchanged` alias (using `-p --abbrev-commit --pretty=medium`) works perfectly when simply replaced with `git log` using the same flags. This demonstrates that some existing configurations may not need any flag adjustments beyond the command name change, particularly when using patch-style output rather than the default `whatchanged` format.

The discussion has reached consensus on deprecating `git whatchanged` in favor of `git log`, with the remaining questions focusing on optimizing the standard recommendation. Junio's position suggests leaning toward simpler substitutions where possible, while Neal's experience shows that some users may already have configurations that require no flag changes at all. The thread remains focused on user experience considerations rather than technical objections to the deprecation itself.
