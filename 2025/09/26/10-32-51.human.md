This is the second patch in a 3-part bugfix series addressing type safety issues in curl interactions, specifically for IMAP message size handling. The series was prompted by build failures on Git for Windows ARM64 due to type mismatches with libcurl's API.

The patch modifies `imap-send.c` to use the new `cast_size_t_to_curl_off_t()` helper function (introduced in patch 1) when setting the message size via `CURLOPT_INFILESIZE_LARGE`. This ensures proper type conversion from `size_t` to `curl_off_t`, preventing potential truncation issues. The change is minimal (just one line) but important for correctness.

The series has already been reviewed and approved by the maintainer, with this v2 incorporating minor documentation improvements requested after the initial submission. The patch appears straightforward and well-justified, completing the type-safety improvements for IMAP operations that were started for HTTP in the first patch.
