Bug report: Git Bash on Windows fails to properly detach GUI processes when launched with & in version 2.51.0.

Tiago Gomes reports a regression in Git for Windows 2.51.0 where backgrounding GUI applications with & no longer works as expected. The issue specifically affects workflows that launch GUI tools (like Vivado) from Git Bash while maintaining console interactivity. 

The reporter provides a clear before/after comparison: In version 2.45.2, using & would properly detach GUI processes, allowing the shell to remain responsive while the GUI application ran. In 2.51.0, the shell becomes blocked until the GUI application exits, breaking existing automation workflows. The report includes detailed system information showing the test environment as Windows 10 with Git 2.45.2.windows.1 (though the issue occurs with 2.51.0).

This appears to be a Windows-specific shell behavior regression in the interaction between Git Bash and GUI applications. The report doesn't include technical details about the underlying cause, but the symptom suggests a change in how process groups or terminal handling works in the newer version. The impact is significant for users who rely on non-blocking GUI launches from their shell, particularly in development workflows involving tools like Vivado.

The bug report follows the project's template well, providing clear reproduction steps and version comparison. No workaround is mentioned, and the reporter doesn't speculate about root cause. This seems like a legitimate regression that would affect Windows users who depend on this backgrounding behavior.
