Bugfix in the reftable fsck validation series (v4 3/7) - tightening parser validation for 'tables.list' format.

This patch modifies the `parse_names()` function in the reftable basics module to enforce stricter validation of the 'tables.list' file format. The key change is requiring a trailing newline in the file, which was optional before. The function now returns a proper error (REFTABLE_FORMAT_ERROR) if the final newline is missing, rather than silently accepting the malformed input.

The implementation changes `parse_names()` to use an output parameter pattern (taking a `char***` parameter) rather than returning the array directly, allowing it to return error codes. This matches the error handling approach used elsewhere in the series. The patch includes corresponding updates to the function's documentation and adds new test cases in the unit test suite to verify the stricter validation, including a specific test for the missing-newline case.

The changes touch core reftable parsing logic (basics.c), its header, the stack implementation that uses it, and the test suite. This is part of the broader effort to strengthen reftable's validation layer while maintaining the separation between Git's fsck and reftable internals. The patch follows the series' pattern of focused, incremental improvements to validation, with this change specifically addressing a previously overlooked edge case in file format parsing.
