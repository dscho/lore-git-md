This is a documentation patch addressing Asciidoctor rendering issues in Git's documentation. Jean-Noël Avila follows up on the earlier discussion about incorrect "+" character rendering in definition lists when paragraphs follow nested items, providing concrete fixes for two documentation files.

The patch modifies `extensions.adoc` and `pretty-formats.adoc` to work around Asciidoctor's known bug #4704 by restructuring definition list syntax. Key changes include replacing single colons (`::`) with triple colons (`:::`), removing unnecessary open block markers (`--`), and properly nesting bullet lists within explicit blocks. The changes maintain semantic structure while avoiding the problematic rendering.

The fixes demonstrate proper Asciidoc syntax that works consistently across processors, particularly for the edge case of paragraphs following nested list items in definition lists. The patch handles several configuration sections (`compatObjectFormat`, `noop`, `objectFormat`, etc.) and the `%(decorate)` pretty format documentation. While the changes are purely presentational, they ensure consistent rendering between asciidoc.py and Asciidoctor processors.

This continues the thread's focus on documentation formatting consistency, building on Jeff King's earlier identification of additional problematic cases. The changes are surgical and well-targeted to the specific rendering issue, with no functional impact on the documented features themselves.
