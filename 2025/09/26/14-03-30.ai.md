Bug investigation update regarding `git merge --no-ff` failure with "stash failed" error. Original reporter Nikolay Shustov provides additional context about their environment, noting they can consistently reproduce the issue. The key new detail is that their repository contains files with trailing dots in their names (e.g., "/something/blah."), which were originally imported from a Perforce depot via `git p4` on Windows. This caused filename normalization issues where Git initially showed the file as both removed and untracked, requiring manual intervention to resolve.

The reporter confirms that running `git stash create` directly doesn't fail in their case, suggesting the issue may be specific to how stash operations interact with merge rather than stash itself. They note another repository without such dot-terminated filenames doesn't exhibit the problem, hinting this may be the trigger. The platform-specific nature of the issue (Windows) and the interaction with `git p4`-imported paths with trailing dots emerges as a likely contributing factor, though not yet confirmed as the root cause. The investigation remains in the diagnostic phase, with the reporter offering to conduct further experiments if this path seems relevant.
