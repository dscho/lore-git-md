Post-merge discussion about `push.default=simple` behavior edge case. This email from Junio Hamano revisits the implementation history of `push.default=simple` after the documentation patch series was merged, uncovering an apparent divergence between the original design and current behavior.

Junio traces the behavior change to commit ed2b18292b (2013) which modified `simple` mode to allow pushing to same-named branches without upstream configuration - contrary to the original 2012 design that explicitly rejected such pushes. He notes this behavior is now effectively baked in due to 10+ years of user expectations, making it impractical to "fix" back to the original design.

The discussion reveals two key insights about current behavior:
1. `simple` mode now effectively allows pushing to same-named branches without upstream configuration in many cases
2. The only time upstream configuration is required is when the user has specifically configured an incompatible upstream

Junio questions whether the documentation needs special warnings about upstream requirements, given that the mode now works automatically for most common cases. This suggests the recently merged documentation may need future updates to better reflect the actual implementation behavior rather than just the original design intent.

The email provides important historical context about how the behavior evolved through several key commits (ed2b18292b, 00a6fa07, e291c75a) and establishes that the current permissive behavior is effectively now the de facto standard due to long-standing usage patterns. This discussion could inform future documentation updates to better match reality.
