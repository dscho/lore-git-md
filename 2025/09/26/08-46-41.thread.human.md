The thread investigates a regression in Git for Windows 2.51.0 where backgrounding GUI applications with `&` in Git Bash no longer properly detaches processes, causing the shell to block until the GUI exits. Tiago Gomes originally reported the issue, noting it worked correctly in version 2.45.2 and broke developer workflows relying on non-blocking GUI launches.

Johannes Schindelin (Git for Windows maintainer) has now responded with test results from a preview build (2.51.0.windows.1.77.gade1f1c136) where the issue does not occur - `git gui &` detaches as expected while maintaining shell interactivity. This suggests the problem may be specific to the official 2.51.0 release rather than a fundamental change. Schindelin has asked Tiago to verify using a provided GitHub Actions preview build, moving the investigation toward version/build-specific factors. The thread remains open pending confirmation from the original reporter.
