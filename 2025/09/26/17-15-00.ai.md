Maintainer response in boolean config implementation discussion. Junio Hamano weighs in on Phillip Wood's architectural feedback about the Rust libgit boolean parsing implementation.

This email confirms the architectural direction for the boolean config parsing in the Rust libgit bindings. Hamano strongly agrees with Wood's position that the implementation should wrap Git's native `git_configset_get_bool()` through the FFI layer rather than reimplementing the logic in Rust. He emphasizes this is critical for maintaining compatibility with Git's core behavior, particularly noting edge cases like numeric string parsing ("00", "100") where a Rust implementation might diverge.

Hamano frames this as a fundamental design principle for the libgit-rs project - it should provide safe Rust wrappers around Git's existing C functionality rather than reimplementing core logic. He contrasts this with projects like gitoxide that aim for native Rust implementations. The response suggests the original patch will need significant restructuring to move the boolean parsing logic to the libgit-sys FFI layer while maintaining the existing test coverage and safety guarantees.

This authoritative input from the Git maintainer effectively settles the architectural question raised in the initial reviews, making it clear the v2 implementation should follow Wood's suggested approach. The email also provides useful context about the project's design boundaries between wrapper libraries (libgit-rs) and reimplementation efforts (gitoxide).
