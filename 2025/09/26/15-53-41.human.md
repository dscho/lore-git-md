Hook subsystem refactoring (part 3/10): post-rewrite hook conversion

This patch continues Adrian Ratiu's series modernizing Git's hook infrastructure by converting the post-rewrite hook in sequencer.c to use the new `hook.h` interface. The change replaces custom child process handling with the standardized `run_hooks_opt` API, reducing code while maintaining functionality.

Key technical changes include:
- Introducing a `pipe_from_strbuf` helper to feed hook stdin (though Adrian notes this could be simplified to a single write)
- Removing redundant signal handling now managed by `run_processes_parallel()`
- Cleaning up a leftover variable rename from previous implementations

Phillip Wood raised several points in review:
- Questioned the efficiency of the recursive stdin feeding approach
- Noted potential blocking in `write_in_full` for parallel execution
- Identified style issues and an unnecessary strbuf reset
- Spotted an unrelated variable rename that should be dropped

Adrian provides detailed technical responses explaining the stdin feeding mechanism and acknowledges the valid points, promising fixes in v2 including:
- Simplifying `pipe_from_strbuf` to a single write
- Removing the redundant strbuf reset
- Dropping the unrelated variable rename
- Addressing style nits

The patch appears technically sound overall, with clear room for refinement based on the review feedback. Adrian demonstrates good engagement with reviewers while maintaining the series' goal of reducing hook-related boilerplate.
