This is a v2 bugfix series addressing curl_easy_setopt() type mismatches, building on the already-approved v1 series. The changes focus on type safety when passing size values to libcurl APIs, particularly affecting Git for Windows ARM64 builds where clang now catches previously undetected type mismatches.

The series introduces a centralized helper function `cast_size_t_to_curl_off_t()` in http.h to safely handle size-to-curl-off-t conversions, replacing ad-hoc solutions. It affects three subsystems: HTTP (patch 1), IMAP (patch 2), and HTTP push (patch 3). The main change from v1 is incorporating Junio's suggested documentation improvements in the commit messages.

Key technical details:
- Replaces CURLOPT_INFILESIZE with CURLOPT_INFILESIZE_LARGE where possible
- Adds bounds checking via `maximum_signed_value_of_type()`
- Updates error messages with platform-specific size limits (PRIuMAX format)
- Requires gettext.h inclusion in http.h for translatable error messages
- Maintains compatibility back to Git v2.22

The series appears complete and well-vetted, with all patches already reviewed and approved in v1. The v2 updates are minor documentation tweaks requested by the maintainer. This represents the final piece of a broader effort to improve type safety across Git's curl interactions, with no remaining open questions or controversies.
