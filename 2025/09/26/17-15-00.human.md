This is a follow-up discussion in the thread about adding boolean config handling to the Rust libgit implementation. Junio C Hamano weighs in to strongly support Phillip Wood's earlier architectural feedback.

The core issue remains whether to implement boolean parsing natively in Rust (as the original patch did) or to properly wrap Git's C implementation through the FFI layer. Junio clearly endorses Wood's position that the Rust bindings should act as safe wrappers around Git's existing C functionality rather than reimplementing behavior that might diverge. He specifically highlights the risk of subtle incompatibilities in how numeric values like "00" or "100" would be parsed differently between implementations.

Junio's response reinforces that this is a matter of design principle - the libgit-rs project's purpose is to provide Rust access to Git's functionality, not to reimplement it. His comment about being "distracted by prettier syntax" suggests this is an easy trap to fall into when porting functionality between languages. The feedback makes clear that any v2 of this patch series will need to restructure the implementation to use Git's C-level `git_configset_get_bool()` through the FFI layer.

This email doesn't introduce new technical arguments but provides important project leadership validation of the architectural direction suggested in earlier reviews. The thread now appears to have clear consensus on how the boolean parsing should be implemented.
