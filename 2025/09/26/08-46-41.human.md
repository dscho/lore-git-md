Bug report: Git Bash on Windows fails to properly detach GUI processes when using `&` operator in version 2.51.0.

Tiago Gomes reports a regression in Git for Windows 2.51.0 where backgrounding GUI applications (like Vivado) with the `&` operator no longer works as expected. In previous versions (2.45.2), this would properly detach the GUI process, keeping the Bash console interactive. Now the shell becomes unresponsive until the GUI application exits, breaking workflows that rely on non-blocking GUI launches.

The report provides clear reproduction steps and version comparison, noting this affects Makefile targets that launch GUI tools. System info shows this occurs on Windows 10 with the standard Git Bash shell. The behavior change suggests a potential issue with process handling in the Windows-specific components of Git 2.51.0.

This appears to be a legitimate regression that affects Windows users who rely on backgrounding GUI applications from Git Bash. The report is well-structured with clear before/after comparisons, making it easy to understand the impact. Windows maintainers will likely want to investigate the process management changes between 2.45.2 and 2.51.0 that caused this behavior difference.
