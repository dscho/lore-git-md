This is a follow-up discussion in the documentation patch series about `git-push` behavior, specifically focusing on the nuances of `push.default=simple`. Julia Evans and Junio Hamano are exploring the gap between the original design intent and current implementation behavior of this push mode.

The conversation reveals that while `push.default=simple` was originally designed to require upstream configuration (as a safety measure), implementation changes since 2013 have made it more permissive in practice - it now allows same-name pushes without upstream configuration in many common cases. Junio notes this divergence is effectively baked in due to 10+ years of usage, making it impractical to "fix" back to the original behavior.

Julia shares concrete examples where the current behavior sometimes requires upstream configuration (like with newly created branches) and sometimes doesn't, suggesting the actual rules are complex enough that they may not belong in the introductory documentation. Both maintainers express some confusion about the current edge cases, with Julia proposing to keep the documentation somewhat vague about when exactly upstream is required, while still providing clear guidance about basic push operations.

The discussion highlights the tension between documenting intended behavior versus actual behavior, especially when the two have grown apart over time. Junio's historical perspective shows how implementation decisions can subtly shift functionality away from original designs, while Julia focuses on making the documentation useful for practitioners working with the current reality.
