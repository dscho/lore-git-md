This is a review response regarding a Rust implementation of boolean config parsing in libgit-rs. Phillip Wood provides constructive feedback on the second patch of a series that adds boolean configuration handling to Git's Rust bindings.

Phillip notes that while it's encouraging to see the Rust bindings being used, the current implementation takes the wrong approach by reimplementing boolean parsing logic in Rust. He points out that the libgit-rs code should instead wrap Git's existing C implementation through libgit-sys to ensure consistent behavior, citing specific examples ("00" and "100") where the current Rust implementation would diverge from Git's standard parsing rules.

The review suggests restructuring the implementation to first expose git_configset_get_bool() in libgit-sys (the unsafe C bindings layer) and then create a safe wrapper in libgit-rs. This maintains consistency with Git's core behavior while preserving Rust's safety guarantees. The feedback doesn't challenge the usefulness of the feature itself but rather focuses on architectural alignment with the project's approach to Rust bindings. The author will need to decide whether to revise the implementation to use the C function or justify why independent parsing is preferable.
