Final patch in xdiff modernization series: type safety conversion for changed[] array.

This is the concluding patch (12/12) in Ezekiel Newren's v6 series modernizing xdiff internals. It changes the `xdfile_t.changed` array from `char` to `bool` type, completing the field's transition after its rename from `rchg` in patch 10/12. The change is justified by the field only ever holding 0/1 values representing false/true states, making `bool` the semantically correct type.

The patch updates all assignments and comparisons across xdiff's diff algorithms (xdiffi.c, xhistogram.c, xpatience.c) and preparation code (xprepare.c), converting numeric 0/1 literals to `false`/`true` constants. Documentation comments are also updated to reflect the boolean nature of the field. The change maintains identical runtime behavior while improving type safety and code clarity, particularly when contrasted with the nearby `action1`/`action2` arrays that legitimately use `char` type for their DISCARD/KEEP/INVESTIGATE states.

This concludes the series' systematic elimination of legacy types and structures (chastore_t, diffdata_t, etc.), having now modernized memory management, field naming, type usage, and documentation while preserving the original diff algorithm's behavior. The series is marked complete and ready for merging to 'next'.
