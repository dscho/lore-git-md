Bugfix follow-up for Windows process detachment issue. Tiago Gomes confirms that the preview build of Git for Windows 2.51.0 fixes the basic `git gui &` case as Johannes Schindelin reported, but discovers a more subtle regression when the same operation is performed through a Makefile. The minimal test case shows that while direct `git gui &` works in both versions, a Makefile wrapper that routes through `cmd.exe` still blocks the console in 2.51.0 where it didn't in 2.45.2.

The key new information is that the issue appears context-dependent - simple cases work in the new version, but more complex process chains (specifically those involving Make and cmd.exe redirection) still exhibit the blocking behavior. Tiago provides a reproducible test case showing the difference between versions when running `make open_git_gui`, where 2.51.0 blocks until GUI closure while 2.45.2 returns control immediately.

This suggests the underlying fix in the preview build may not fully address all process detachment scenarios, particularly those involving intermediate command processors. The report maintains the focus on Windows-specific behavior while adding the wrinkle of Makefile integration, which appears to be the actual workflow where the regression causes problems. Next steps would likely involve debugging why the cmd.exe redirection path behaves differently between versions.
