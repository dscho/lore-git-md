This is a v4 patch series (7/7) introducing consistency checks for the reftable backend, focusing on table name validation. The series represents significant refinement from previous versions, with key changes including:

1. Simplified validation approach that now only checks tables listed in the stack rather than scanning the entire reftable directory, avoiding race conditions with temporary files
2. Dropped the update index validation patch since it was redundant with existing runtime checks
3. Improved error handling in `parse_names()` by making it return errors directly rather than through an output parameter
4. Made table name validation non-fatal (emitting warnings) since the reftable spec only suggests rather than enforces naming conventions

The current patch specifically:
- Adds fsck infrastructure for reftable validation via new `reftable/fsck.[ch]` files
- Implements table name validation that checks for malformed names like "invalid.ref" instead of the expected format
- Maps reftable-specific errors to Git's fsck messaging system
- Includes comprehensive tests in t0614-reftable-fsck.sh

Notable technical details:
- Uses `strtoull()` for parsing table name components with proper error checking
- Maintains separation between reftable internals and Git's fsck system
- Handles edge cases like missing newlines in tables.list
- Preserves lexicographic ordering in Makefile/meson.build additions

The implementation appears robust, with careful attention to error handling and platform compatibility. The series has evolved through multiple rounds of review, addressing concerns about race conditions and validation scope while maintaining the layered validation approach. The current focus on table names (rather than all files in the directory) represents a pragmatic simplification that still catches important corruption cases.
