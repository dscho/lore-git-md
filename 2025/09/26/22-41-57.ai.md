Refactoring patch in the xdiff modernization series, specifically renaming the `rchg` field to `changed` in xdiff's core data structures.

This patch is part of Ezekiel Newren's v6 series (10/12) modernizing xdiff internals for Rust compatibility and maintainability. It renames the `rchg` field in `xdfile_t` to the more descriptive `changed`, which marks whether lines in a file have been changed during diff operations. The commit message notes this is preparatory work for a follow-up change converting the field from `char` to `bool` for clearer type semantics.

The change is mechanical but widespread, touching all major xdiff algorithm implementations (xdiffi.c, xhistogram.c, xpatience.c) and core infrastructure files (xprepare.c, xtypes.h, xutils.c). The rename maintains identical behavior while improving code readability. This continues the series' pattern of structural simplifications and naming improvements, following earlier patches that removed redundant structures and allocators.

Key technical details for future reference:
- Field renamed in `xdfile_t` struct (xtypes.h)
- All access patterns updated across xdiff implementation files
- Temporary variable `rchg1/rchg2` in xdl_build_script() renamed to `changed1/changed2`
- Memory management adjusted in xdl_free_ctx() and xdl_prepare_ctx()
- Part of broader effort to clarify xdiff internals while preserving behavior

The patch is well-contained and follows the series' established pattern of incremental, behavior-preserving improvements to xdiff's data structures and interfaces.
