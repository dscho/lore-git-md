Feature implementation feedback on Rust libgit boolean config parsing.

Phillip Wood responds to the v1 patch series adding boolean config support to the Rust libgit implementation. While acknowledging the usefulness of the contribution, he raises an architectural concern about the implementation approach. The current patch implements boolean parsing directly in Rust (`libgit-rs`), but Wood suggests this should instead be handled by first exposing Git's native `git_configset_get_bool()` through the FFI layer (`libgit-sys`) before wrapping it in Rust. This would ensure consistent behavior with Git's C implementation, particularly noting that the current Rust implementation would parse values like "00" or "100" differently from Git's C code.

The feedback doesn't challenge the technical correctness of the boolean parsing logic itself, but rather its architectural placement. Wood's position reflects the project's design principle that `libgit-rs` should primarily provide safe wrappers around Git's existing C functionality rather than reimplementing core logic. This suggests the patch may need significant restructuring to move the boolean parsing implementation down to the FFI layer before being exposed in Rust.

The response also serves as positive encouragement for the contributor ("It's nice to know that someone is using the rust bindings"), indicating the feature itself is welcome if implemented according to the project's architectural guidelines. This feedback likely means the patch series will need a v2 that reorganizes the implementation across both `libgit-sys` and `libgit-rs` layers.
