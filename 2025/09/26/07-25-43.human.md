This is a v4 patch series introducing reftable consistency checks, focusing on validating table names in the reftable backend. The series has evolved through several iterations based on reviewer feedback, with notable changes in this version:

The key change in v4 is shifting from scanning all files in the reftable directory to only checking tables listed in the stack's 'tables.list' file. This avoids race conditions with temporary/lock files and simplifies the validation scope. The series also drops a now-redundant patch for checking update indices since that validation already exists in the stack addition code.

Karthik Nayak has addressed previous concerns by:
1. Restructuring the validation to only examine tables in the stack
2. Simplifying the table name validation logic
3. Improving error handling flow in parse_names()
4. Maintaining lexicographic ordering in Makefile additions

The implementation adds a new 'reftable/fsck.[ch]' module that keeps reftable-specific validation separate from Git's fsck infrastructure while providing proper error mapping. The table name check is treated as a warning since the reftable spec only suggests (rather than enforces) naming conventions.
