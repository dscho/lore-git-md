This is a feature patch for the experimental `git replay` command, finalizing the design for atomic reference updates after extensive community discussion. The patch makes atomic ref updates the default behavior, addressing server-side workflow needs where transaction safety is crucial.

Siddharth Asthana's v2 series responds to feedback from v1 by simplifying the interface - atomic updates are now the default rather than requiring an `--update-refs` flag. The traditional pipeline behavior (outputting commands for `git update-ref`) is preserved via a new `--output-commands` flag for compatibility. This resolves earlier concerns about naming collisions with `git rebase --update-refs` and provides cleaner semantics.

The implementation builds on consensus from key contributors including Junio Hamano and Elijah Newren, who agreed that the experimental nature of `git replay` justifies changing defaults to favor the atomic behavior. The patch includes thorough documentation updates and test coverage (166 lines of tests added/modified) to reflect the new behavior and warn about the command's experimental status.

Notable technical aspects include using the ref transaction API for batching updates, fixing exit code behavior for `--allow-partial`, and consistent error reporting. The changes touch core functionality in `builtin/replay.c` but maintain backward compatibility, making this a well-considered evolution of the feature that addresses performance concerns raised about individual ref updates in the reftable backend.
