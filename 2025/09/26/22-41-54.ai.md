This is a refactoring patch in the xdiff modernization series, specifically removing the redundant `xdfile_t.ha` array which stored duplicate hash values that could be derived from `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. 

The patch introduces a new `get_hash()` helper function to access the hash values directly from the records array rather than maintaining a separate parallel array. This change makes the code about 5% slower but simplifies the data structures in preparation for future cleanups. The `ha` field was specific to the classic diff algorithms (Myers and minimal) and its removal helps pave the way for restructuring the classic diff code.

Key technical changes:
- Adds `get_hash(xdf, index)` helper that replaces direct `ha` array access
- Updates all hash comparisons in `xdl_split()` and `xdl_recs_cmp()` to use the new helper
- Removes `ha` array allocation and cleanup code from `xdl_prepare_ctx()` and `xdl_free_ctx()`
- Simplifies `xdl_cleanup_records()` by removing redundant hash assignments
- Deletes the `ha` field declaration from `xdfile_t` struct

The commit message notes this is part of a larger cleanup effort and that a subsequent patch will investigate removing the `chastore` structure. The performance impact is acknowledged but considered acceptable given the structural benefits. This change follows the series' pattern of removing redundant data structures while maintaining identical diff algorithm behavior.
