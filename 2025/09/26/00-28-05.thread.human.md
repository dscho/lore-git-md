This thread documents an ongoing effort to standardize Git's documentation formatting, specifically focusing on header styles in commit-graph.adoc. The discussion began with a proposal to switch to atx-style headers (`====`), but Junio C Hamano preferred maintaining underlined headers for readability. Ramsay Jones then proposed a compromise using `~` for second-level headers while keeping first-level underlines, aligning with gitworkflows.adoc.

A key technical challenge emerged around how different AsciiDoc processors handle escaped characters (like `\{hash\}`) in underlined headers. Through experimentation, Ramsay discovered that while AsciiDoc tolerates underlines slightly longer than the header text, Asciidoctor strictly requires exact-length underlines when escaped characters are present. Junio confirmed these findings, referencing existing documentation examples that demonstrate how markup characters affect underline length calculations.

The latest email solidifies the implementation approach: underlines must precisely match the visual length of escaped text to ensure compatibility across processors. This resolves one open question about escaped character handling, though the broader stylistic debate between atx and underlined headers remains. The discussion has produced concrete guidelines for documentation maintenance while highlighting the challenges of maintaining markup that renders correctly across different processors. The changes remain documentation-focused, with Ramsay and Junio as the primary participants working through these formatting nuances.
