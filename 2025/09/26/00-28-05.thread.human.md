This documentation formatting thread has taken an interesting turn. The original patch series from Ramsay Jones proposed converting the commit-graph documentation to use atx-style headers (= prefixes) and other formatting cleanups as part of Jean-Noël Avila's ongoing standardization effort. While technically sound, Junio Hamano has now raised concerns about diverging from Git's current documentation norms, where most man pages use underlined headers. 

Junio acknowledges the maintenance benefits of atx-style headers but personally finds underlined headers more readable in source form. His response suggests this change might need broader discussion rather than being treated as a straightforward mechanical update. The core question now is whether Git should standardize on atx headers going forward despite the existing documentation predominantly using underlines. Importantly, this discussion doesn't affect the technical content or behavior of commit-graph functionality - it's purely about documentation source formatting preferences. The thread has shifted from implementation to style policy, with the maintainer signaling this may not be as simple as it first appeared.
