This thread centers on a documentation formatting patch series (part 4) focused on standardizing the commit-graph.adoc man page, part of Jean-Noël Avila's broader effort to unify Git's documentation style. The initial proposal sought to convert underlined headers to atx-style (`====` to `=`) for easier maintenance, but maintainer Junio C Hamano expressed a strong preference for keeping underlined headers due to their readability in source form. Ramsay Jones revised the approach to use `~` for second-level headers while preserving first-level underlines.

New technical findings from Ramsay reveal a key compatibility challenge: while AsciiDoc tolerates approximate underline lengths, Asciidoctor strictly requires underlines to match the *visual* length of escaped characters like `\{hash\}` in headers. This forces precise length calculations in the patch to ensure cross-processor compatibility. Junio has acknowledged the maintenance tradeoffs but maintains his stylistic preference for underlines if the technical hurdles can be resolved.

The discussion now hinges on two questions: the exact rules for escaped character counting in different AsciiDoc implementations, and whether Git should prioritize maintainability (favoring atx headers) or source readability (keeping underlines). With Ramsay providing concrete data on processor behavior and Junio guiding the stylistic direction, the thread illustrates the project's careful balancing act between documentation consistency and toolchain constraints—all while affecting only formatting, not commit-graph functionality.
