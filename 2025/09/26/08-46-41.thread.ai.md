Bug report: Git Bash on Windows fails to properly detach GUI processes when launched with & in version 2.51.0. Tiago Gomes reports a regression in Git for Windows 2.51.0 where backgrounding GUI applications with & no longer works as expected, initially demonstrated with Vivado` workflows. Johannes Schindelen (Git for Windows maintainer) tested preview build 2.51.0.windows.1.77.gade1f1c136.20250926063933 showing `git gui &` works correctly, suggesting the issue was specific to the official release. 

New testing reveals the regression is more nuanced: while direct `git gui &` works in both versions, a Makefile-wrapped invocation via `cmd //c` shows blocking behavior in 2.51.0 that doesn't occur in 2.45.2. The minimal Makefile test case demonstrates version-dependent behavior despite identical syntax, indicating the issue involves process chain handling between Make, cmd.exe, and Git Bash rather than direct backgrounding. 

Current status: The preview build resolves the simple case but the Makefile scenario remains untested there. Key technical details involve Windows process handling differences when commands are nested through cmd.exe versus direct Bash invocation. Open questions are whether the preview build also fixes the Makefile case, or if this reveals a separate issue in the process chain. Next steps should verify the preview build against the Makefile test case to determine if this requires additional fixes beyond what's already in development.
