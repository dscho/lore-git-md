This is a v2 bugfix series addressing curl type safety issues, following up on a now-completed v1 series that was already maintainer-approved. The patches fix a curl_easy_setopt() type mismatch that started causing CI failures in Git for Windows ARM64 builds after a libcurl update.

The core issue involves incorrect type handling when passing values to curl's CURLOPT_INFILESIZE option. While GCC didn't catch the problem, clang in ARM64 builds started flagging it. The series replaces CURLOPT_INFILESIZE with CURLOPT_INFILESIZE_LARGE where possible and introduces consistent type-casting helpers.

Changes since v1 are minor documentation tweaks to commit messages as suggested by Junio Hamano. The series:
1. Moves a size-to-curl_off_t casting helper to http.h for wider use
2. Makes IMAP message size handling more type-safe
3. Fixes the original HTTP push compile error with a 3-line change

The patches apply cleanly back to v2.22, though testing older versions would be difficult. The author notes this continues Git's pattern of improving curl type safety beyond just the immediate fix needed. With the v1 series already approved and these being minor follow-ups, this appears ready for integration.
