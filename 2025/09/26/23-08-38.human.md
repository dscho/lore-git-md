Feature patch finalizing atomic ref updates for `git replay`. This is the implementation-ready version of a change that has been through extensive review on the mailing list, making atomic reference updates the default behavior for the experimental `git replay` command.

The patch switches from the previous model where `git replay` output update commands to be piped to `git update-ref`, to directly performing atomic ref updates by default. This better serves the command's primary use case in server-side workflows where atomic operations are critical. The old behavior remains available via `--output-commands` for compatibility.

Key changes include using `ref_store_transaction_begin()` for atomic updates, improved error handling with a "strict success" model for `--allow-partial`, and extensive test coverage (166 new test lines). The implementation addresses performance concerns by using batched transactions and avoids naming conflicts with similar `git rebase` options. Documentation has been thoroughly revised to explain the new defaults and provide clear usage examples.

The patch has already incorporated feedback from multiple reviewers including Junio Hamano, Elijah Newren, and Patrick Steinhardt, resolving all outstanding issues from the RFC phase. It's now in final form for merging into the experimental `git replay` command.
