This is a follow-up in the `git repo stats` series addressing an i18n issue in the table formatting code.

Justin Tobler responds to Eric Sunshine's review of patch 4/7, which introduced the reference statistics reporting functionality. The key issue identified was that the table column width calculation used `strlen()` on potentially translated strings, which doesn't account for multi-byte characters in some languages. Eric correctly pointed out this could lead to misaligned output when the command is used with non-ASCII locales.

The author acknowledges the problem and confirms the solution will be to use `utf8_strwidth()` from Git's utf8.h header instead. This function properly handles display width calculation for internationalized text. The change affects only the presentation layer - the core statistics collection and calculation remain unchanged.

This appears to be a straightforward fix that addresses a real localization concern.
