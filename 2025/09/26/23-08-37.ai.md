This is the cover letter for a patch series finalizing the atomic reference updates feature for `git replay`, marking the transition from RFC to implementation-ready state. The series makes atomic ref updates the default behavior while maintaining backward compatibility.

The patch follows extensive discussion on the mailing list that resolved key design questions around default behavior, naming, and compatibility. The new design makes atomic updates the default (using `ref_store_transaction_begin()` internally) while providing `--output-commands` for the previous pipe-to-update-ref workflow. This addresses performance concerns with individual updates in reftable backends while maintaining server-side transaction safety.

Key technical changes in v2 include:
- Default atomic behavior replacing the previous opt-in `--update-refs` approach
- Removal of confusing option variants that overlapped with `git rebase`
- Fixed exit code handling for `--allow-partial` cases
- Consistent error reporting via `die_for_incompatible_opt2()`
- Documentation updates reflecting the new defaults

The implementation touches `builtin/replay.c` for the core changes, adds extensive test coverage in t3650, and updates the git-replay.adoc manpage. The changes are well-motivated by the experimental nature of `git replay` and its primary server-side use cases where atomic transactions are critical. The series has already incorporated feedback from multiple reviewers (Christian Couder on naming, Patrick Steinhardt on performance, Andrei Rybak on docs) and maintainer approval of the design direction from Junio Hamano and Elijah Newren.
