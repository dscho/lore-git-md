This is a feature patch finalizing atomic reference updates for `git replay`, making atomic behavior the default while maintaining backward compatibility. The patch represents the culmination of extensive mailing list discussion and review, addressing all previous feedback.

The key change switches `git replay` from outputting ref update commands (requiring piping to `git update-ref`) to performing atomic ref updates directly by default. The implementation uses `ref_store_transaction_begin()` with batched transactions for optimal performance across ref backends. The old behavior remains available via `--output-commands`, while `--allow-partial` enables partial failure tolerance while still maintaining strict success criteria (exit code 1 if any updates fail).

Technical details include:
- New `--output-commands` and `--allow-partial` options with mutual exclusion enforced via `die_for_incompatible_opt2()`
- Empty commit ranges now treated as success cases (exit code 0)
- Comprehensive test coverage in t3650 (12 new tests) verifying atomic behavior, option validation, bare repo support, and edge cases
- Documentation updates clarifying new defaults and reorganizing examples
- Fixed test isolation issues and improved error reporting consistency
- The implementation avoids naming conflicts with `git rebase --update-refs` and maintains C89 compliance

The patch touches `builtin/replay.c` (114 lines changed), `Documentation/git-replay.adoc` (76 lines changed), and `t/t3650-replay-basics.sh` (166 lines changed). It builds on prior consensus from maintainers including Junio Hamano, Elijah Newren, and Patrick Steinhardt, addressing all outstanding concerns from the RFC phase. The changes are particularly significant for server-side workflows where atomic updates are critical.
