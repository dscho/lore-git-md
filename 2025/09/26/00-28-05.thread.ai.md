Thread summary:

Documentation formatting cleanup patch series (part 4) targeting commit-graph.adoc, part of Jean-Noël Avila's ongoing effort to standardize man page formatting. The patch series initially proposed converting heading styles from underline to atx format (`====` -> `=`), normalizing code block delimiters to `----`, fixing section level consistency (`##` -> `===`), escaping special characters (`{hash}` -> `\{hash\}`), and adding whitespace around lists. Junio C Hamano questioned the header style change from underlined to atx format, noting that while atx headers offer maintenance benefits, he personally finds underlined headers easier to read in source form and that most Git manual pages currently use underlined headers.

In response to maintainer feedback, Ramsay Jones has revised the patch to propose a compromise approach that better matches Git's documentation conventions. The new version uses `~` for underlining second-level headers (matching gitworkflows.adoc style) while keeping first-level sections with single-line underlines, maintaining all other formatting improvements from the original (whitespace fixes, code block delimiter normalization, special character escaping). The patch demonstrates proper escaping of curly braces in section titles (`\{hash\}`).

The discussion highlights two competing concerns: 1) practical benefits of atx-style headers (easier maintenance, no need to match underline lengths) versus 2) consistency with Git's predominant documentation style and readability in source form. Ramsay's revised patch suggests the underlined header approach may be more acceptable to the maintainer while still achieving formatting normalization goals. The thread remains open on whether Git should standardize on atx headers long-term or maintain its current underlined header convention. Key participants are Ramsay Jones (patch author) and Junio C Hamano (maintainer). The changes are purely documentation formatting with no impact on commit-graph functionality or behavior.
