This thread explores the idea of adding Git-native support for sharing files that must live in repository roots, such as `.pre-commit-config.yaml`, autoconf's `config.guess`/`config.sub`, and organizational root certificates. The discussion was started by George Ogden and expanded by Randall Becker, who proposed two potential implementation approaches: extending submodules to allow "linking upwards" or leveraging sparse-checkout infrastructure.

George has now responded, confirming that Randall's additional use cases strengthen the original proposal and expressing appreciation for the technical ideas. While George lacks the expertise to evaluate the implementation details, they reinforce the core motivation: eliminating the need for manual file copying across repositories when tools require these files at root level.

The thread currently awaits technical input from Git contributors on whether either proposed approach (submodule extensions or sparse-checkout integration) would be feasible, or if alternative solutions should be considered. Key unresolved questions include versioning semantics, conflict resolution, and whether this functionality belongs in core Git or should remain as external tooling.
