This thread explores a proposal for Git-native support to share root-level files across repositories, originally suggested by George Ogden with `.pre-commit-config.yaml` as the motivating example. Randall Becker has now expanded the discussion with additional compelling cases: GNU autoconf's platform detection files (`config.guess` and `config.sub`) and organizational root certificates - all files that tools require at repository roots but which would benefit from centralized version control.

The technical discussion is considering two potential implementation directions: extending submodules to allow "upward linking" of files, or adapting sparse-checkout infrastructure to handle this use case. While no concrete design has emerged yet, the expanded set of examples strengthens the argument that this is a genuine pain point affecting multiple workflows. The thread remains open for technical feedback on whether and how Git's core could support this functionality while maintaining its versioning model and handling potential conflicts. Key participants so far are George Ogden (original proposal) and Randall Becker (use case expansion), with the community's reaction still forthcoming.
