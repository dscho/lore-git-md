Bug investigation update regarding `git merge --no-ff` failure with "stash failed" error. Nikolay Shustov confirms the issue is reproducible and provides new context about an unusual edge case in their repository: files with trailing dots in their names that were handled specially during a git-p4 import on Windows. 

The key new information is that while `git stash create` works fine when run (since there are no actual changes to stash), the problematic repository contains files that originally had trailing dots in their p4 depot, which git-p4 on Windows handled by creating dot-less versions, leading to rename confusion. Nikolay notes this is the only unusual aspect they can identify, and helpfully points out that their other git-p4 repositories (which don't have this file naming issue) don't exhibit the merge problem.

This suggests the "stash failed" error during merge may be related to how Git handles these specially-named files in the repository state, though the exact connection isn't yet clear. The investigation continues to focus on platform-specific filesystem behavior, now with this concrete lead about dot-terminated filenames. Nikolay offers to run further experiments if this angle seems promising.
