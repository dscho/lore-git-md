Thread identity: Feature request for root-level file sharing between repositories, initiated by George Ogden, now expanded by Randall Becker. The thread explores Git-native support for sharing individual files that must live in repository roots, with `.pre-commit-config.yaml`, GNU autoconf's `config.guess`/`config.sub`, and organizational root certificates as key use cases.

Core problem: Multiple tools (linters, CI systems, platform detection, security) require configuration files at repository roots, creating maintenance challenges when these files need consistency across repositories. Current solutions (submodules, subtrees) cannot place files at roots without breaking tool expectations or requiring manual synchronization.

Key technical details: The problem specifically targets root-level files where tools enforce location requirements. Randall Becker suggests two implementation directions: extending submodules with "link upwards" capability or leveraging sparse-checkout infrastructure. The sparse-checkout connection is notable as it might reuse existing partial checkout mechanisms. The examples strengthen the case by showing diverse scenarios involving platform scripts and security certificates that are external to project content yet must reside at roots.

Open questions: No concrete design exists yet. Key unresolved aspects include versioning semantics (tracking shared file versions), conflict resolution (diverging local changes), and whether to implement in core Git or keep as external tooling. The thread now has richer use cases to evaluate whether the need justifies core support. Technical feedback is still needed on the sparse-checkout and submodule extension ideas.
