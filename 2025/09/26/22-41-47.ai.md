This is the final version (v6) of Ezekiel Newren's xdiff internals refactoring series, now ready for merging. The series modernizes the xdiff diff algorithm implementation through structural simplifications and type safety improvements while preserving identical runtime behavior.

Key changes in this version:
- Dropped the controversial "delete rchg aliasing" patch after finding similar patterns useful elsewhere
- Renamed similarity matching macros from NONE/SOME/TOO_MANY to DISCARD/KEEP/INVESTIGATE for better semantic clarity
- Finalized the bool conversion of xdfile_t.changed field
- Addressed all remaining review feedback on commit messages and documentation

The series has evolved through extensive discussion, particularly around:
- The balance between Rust porting motivations and readability improvements
- Whether variable alias removal was justified purely for Rust compatibility
- The semantic meaning of similarity matching states in the diff algorithm

Technical highlights include:
- Elimination of redundant structures (xdlclass_t field duplication, chastore_t allocator)
- Type safety improvements with enum macros and bool conversions
- Better documentation of the 'changed' field's purpose as a boolean array
- Clearer naming for variables tracking line matching states

The changes touch xdiff/xdiffi.c and related files, with the core refinements being:
- xdfile_t.changed converted from char to bool
- Similarity matching logic now uses DISCARD/KEEP/INVESTIGATE macros
- All feedback from Phillip Wood and Junio C Hamano incorporated
- Performance impact measured and documented

The series is now fully complete with all structural simplifications finished, naming improvements made, type safety enhanced, and performance impact measured. While some philosophical discussions about Rust porting motivations remain, the technical implementation has consensus and is ready for merging.
