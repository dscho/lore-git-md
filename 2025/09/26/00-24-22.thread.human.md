This thread concerns a documentation formatting patch (part 2/4 of an RFC series) that standardizes AsciiDoc syntax in Git's technical documentation about rename detection caching. The initial patch from Ramsay Jones mechanically updated the `remembering-renames.adoc` file, converting subsection headers and adjusting indentation without changing the technical content about how Git caches rename information during operations like rebase and cherry-pick.

Maintainer Junio C Hamano has responded with feedback, seeking clarification about which specific AsciiDoc warnings motivated the changes. He notes two syntax adjustments: removing periods after outline numbers (which he finds slightly awkward but acceptable if standard) and correctly demoting subsection headers. Junio also observes improved readability from added blank lines in bullet-point examples, though this wasn't presented as fixing a warning. While the changes appear technically sound, the maintainer wants explicit rationale for the syntax choices to properly evaluate them. The thread still lacks context about the overall RFC series goal, as no cover letter was provided with the initial submission.
