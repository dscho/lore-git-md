This is patch 6/7 in a series adding fsck validation for the reftable backend, focusing on table name consistency checks. The patch introduces new infrastructure in `reftable/fsck.c` and `reftable/reftable-fsck.h` to validate reftable files independently of Git's internals, with a callback-based design for reporting issues.

The core addition is a check that validates reftable filenames follow the expected format (hex-hex-hex.ref/log pattern). The implementation carefully handles the reftable library's independence from Git while integrating with the existing stack validation framework. The patch also maintains build system hygiene by keeping Makefile entries in lexicographic order.

This continues the series' trend of thorough, well-architected validation code with clear separation of concerns. The callback-based reporting system appears designed to support future expansion of checks while keeping the core library independent. The change is part of bringing reftable's validation up to parity with the files backend's fsck capabilities.
