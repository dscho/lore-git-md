This thread discusses the deprecated `git whatchanged` command and migration paths to modern alternatives. The original discussion established that `git whatchanged` is effectively a legacy wrapper around `git log` with specific defaults. Kristoffer Haugsbakk now suggests concrete replacement commands: `git log --no-merges --raw` for direct output parity, with `--stat` or `--name-only` as more readable alternatives. The thread shows consensus that `git whatchanged` should be phased out in favor of these more flexible `git log` invocations, though no technical objections to the command itself have been raised. The discussion remains focused on command-line usage patterns rather than implementation details.
