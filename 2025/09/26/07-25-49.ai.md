Feature and bugfix patch (6/7 in reftable fsck validation series) introducing consistency checks for the reftable backend.

This patch adds core infrastructure for reftable fsck validation, implementing the first concrete check for valid table names. The new `reftable/fsck.[ch]` files provide a framework where callers (like `git fsck`) can register callback functions to handle error reporting and verbose output. The initial validation enforces a strict naming pattern for reftable files (hex-hex-hex.ref/log format) through the `table_has_valid_name()` helper.

Key technical elements:
- New public API `reftable_fsck_check()` takes a stack and callbacks
- Error reporting uses `reftable_fsck_info` struct with error codes and messages
- Current implementation only checks table names (REFTABLE_FSCK_ERROR_TABLE_NAME)
- Makefile/Meson build system updates maintain lexicographic ordering
- Designed to work independently from Git's fsck infrastructure

The patch continues the series' pattern of keeping reftable validation separate from Git's core while providing integration points. It builds on previous patches' work with error handling and parsing, though the actual name validation logic appears new to this patch. The implementation includes verbose progress reporting but currently only implements one check, leaving room for future expansion of the validation suite.

This represents a significant step in making reftable's fsck support parallel to the files backend's capabilities. The callback-based design suggests future checks could be added without API changes. The strict name validation helps catch corrupted or malformed tables early.
