This thread discusses a refactoring of Git's alias execution mechanism to better align with the documented API in `run-command.h`. The patch modifies how Git runs commands invoked via aliases, removing an explicit `strvec_push(&cmd.args, "git")` call in favor of setting `cmd.git_cmd = 1`, which is the preferred way to indicate a command should be treated as a Git subprocess.

The change is focused on the `run_argv` function in `git.c` and appears to be a straightforward cleanup rather than fixing any specific bug. The author investigated similar patterns elsewhere in the codebase, finding one case in `upload-pack.c` where explicitly pushing "git" is intentional, and another historical reference that wasn't relevant. While the change is small (just two lines modified) and doesn't affect user-facing behavior, the lack of accompanying tests for this core command dispatch logic might warrant discussion.
