Bugfix follow-up confirming the `safe.directory` configuration needs to be set server-side. Marc-Jano Knopp confirms Carlo Arenas Belón's diagnosis that the security check triggering the "dubious ownership" error occurs on the server (`my.server`) rather than the client. The reporter verifies that setting the configuration on the server resolves the issue when accessing the repository via SSH.

This closes the thread by confirming the root cause and solution - the security check happens during remote repository access by the server-side Git process, not during the local clone operation. The key takeaway is that for shared repositories accessed remotely, `safe.directory` must be configured where Git executes (on the server in this case), not just on the client. The solution works when tested via direct SSH access to the server.
