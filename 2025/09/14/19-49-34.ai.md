This is the v5 cover letter for a series improving the command deprecation system, specifically focusing on better error messages and alias handling for deprecated commands like `whatchanged` and `pack-redundant`. The series builds on the previously approved technical implementation of the deprecation framework, now adding user-facing improvements.

Key changes in v5 include:
- Fixing a memory leak identified by Jeff King
- Addressing a regression where deprecated builtin names could cause infinite alias loops
- Restoring a BUG check for mutually exclusive list command options
- Adding comprehensive tests for alias shadowing of deprecated commands, including test cases for infinite loops and chained deprecated commands

The user-facing improvements now provide:
- Clearer error messages suggesting concrete alternatives (like using `git log --raw --no-merges` instead of `whatchanged`)
- Instructions for creating aliases to maintain workflow continuity
- Multiple action items beyond just reporting usage (reading docs, checking mailing list discussions)
- Documentation updates reflecting these changes

The implementation moves alias tracking into `handle_alias()` as suggested by Jeff King, while maintaining all the recursion detection and cycle handling from previous versions. The series has maintainer approval for the core technical approach and is now focused on final polish of the user experience.

Files modified include git.c (alias handling), t/t0014-alias.sh (new test cases), and several documentation files. The changes are backward-compatible and maintain all existing deprecation warnings while making them more actionable.
