Feature patch in the command deprecation framework series, specifically enabling alias shadowing for deprecated builtins.

This patch (3/8 in v5) implements the core functionality allowing users to create aliases that shadow deprecated Git commands like `whatchanged` and `pack-redundant`. The change modifies `run_argv()` in git.c to check if a command is deprecated before applying the usual alias shadowing restrictions, calling a new `is_deprecated_command()` helper that checks the `DEPRECATED` flag (1<<6) on builtins.

Key technical aspects:
- Documents the new behavior in alias.adoc with a specific exception for deprecated commands
- Adds comprehensive test coverage including:
  - Detection of alias loops involving deprecated commands (with preserved `==>` marker format)
  - Validation that all deprecated commands can be shadowed
  - Edge cases with chained deprecated command aliases
- Maintains the v4 architecture's recursion detection in `handle_alias()`
- Preserves Jeff King's original loop detection approach while adding deprecated command handling

The implementation addresses a specific user experience pain point - allowing interactive users to create transitional aliases for deprecated commands they're accustomed to, like suggesting `git log --raw --no-merges` as a `whatchanged` replacement. The tests verify both the happy path and edge cases, including the infinite loop detection from patch 2/8.

Files modified:
- git.c (core alias handling logic)
- Documentation/config/alias.adoc (user-facing docs)
- t/t0014-alias.sh (expanded test coverage)

This patch builds on the series' foundation while introducing no new architectural changes, focusing on completing the user-facing functionality for deprecated command handling. It maintains consistency with the v4 approach that received maintainer approval while adding the final piece needed for practical user migration from deprecated commands.
