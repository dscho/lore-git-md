This is a documentation clarification regarding mergetool variable behavior, continuing the thread about BASE/LOCAL/REMOTE/MERGED variables not being passed to custom scripts.

Junio Hamano weighs in on the discussion, confirming that the current implementation is working as designed for tools integrated into Git's mergetool infrastructure. He explains that the documentation refers to shell variables (not environment variables) intended for tools that are dot-sourced from the mergetools/ directory, not standalone custom tools. The expected usage pattern is to add new tools to the mergetools/ directory where they can access these variables directly through shell sourcing.

Key technical points:
- Variables are shell variables, not environment variables
- Proper integration requires adding tools to mergetools/ directory
- Tools must be dot-sourceable like existing mergetool implementations
- git-mergetool--lib sources tool definitions using MERGE_TOOLS_DIR

This response clarifies the design intent behind the variable passing mechanism, suggesting the documentation should be updated to better explain the expected integration pattern rather than focusing on environment variable exports. The thread appears to be moving toward consensus that the current behavior is correct but under-documented, with Randall Becker's workaround (explicit exports) being an acceptable but non-standard solution for custom tools.
