This is a follow-up discussion in the worktree safety checks thread, specifically addressing an edge case in testing methodology. Ben Knoble responds to Kristoffer Haugsbakk's observation about advice messages not appearing when using `git` aliases during testing.

The key technical detail is that aliases execute the system `git` binary (from PATH) rather than the development version being tested, which explains why new advice messages don't appear when testing via aliases. Ben confirms this is expected behavior and notes that using `bin-wrappers/git` would provide the correct test setup.

This exchange doesn't require changes to the patch series but documents an important testing consideration - developers need to be aware that alias testing requires either using the direct command or the wrapper script to see new advice messages. The discussion helps clarify the behavior without blocking the series' progress.
