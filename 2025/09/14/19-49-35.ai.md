This is the first patch in the final v5 series implementing command deprecation with alias shadowing support. It introduces the foundational infrastructure for identifying deprecated commands by adding a new `DEPRECATED` flag (1<<6) and extending `--list-cmds` to include a `deprecated` category.

The patch modifies `git.c` to:
- Add the `DEPRECATED` flag constant
- Mark `pack-redundant` and `whatchanged` as deprecated (guarded by `WITH_BREAKING_CHANGES`)
- Refactor `list_builtins()` to support both inclusion and exclusion filtering
- Add a BUG check for mutually exclusive filtering options
- Update documentation for the new `deprecated` category in `--list-cmds`

Key technical details:
- The refactored `list_builtins()` now takes both `include_option` and `exclude_option` parameters
- The deprecated` category uses inclusion filtering (`DEPRECATED` flag) while existing categories like `parseopt` use exclusion filtering
- Maintains backward compatibility with existing callers by defaulting both filters to 0

This patch was previously reviewed in v4, with v5 changes including:
- Restoring the BUG check for mutually exclusive options (from v3)
- Incorporating Patrick Steinhardt's suggestions on code formatting
- Adjusting commit message to reflect actual usage in upcoming patches

The changes are straightforward plumbing for the larger deprecation system, with no apparent technical issues. The patch has already received Acked-by from Patrick Steinhardt and builds on maintainer-approved architecture from v4.
