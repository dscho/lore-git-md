This is a documentation clarification request regarding Git's mergetool behavior.

Randall Becker follows up on the mergetool environment variables discussion, confirming that adding explicit `export` statements for BASE, LOCAL, and other variables resolves the issue when the mergetool script is installed in Git's installation area. This workaround was suggested earlier in the thread by Johannes Sixt, who found the current implementation too complex to modify directly.

The email suggests documenting this requirement, as the current behavior differs from what the documentation might lead users to expect. The core issue remains that built-in mergetools (in mergetools/*) receive variables as shell variables while custom tools need them exported as environment variables.

This appears to be a straightforward documentation fix rather than a code change, given the implementation complexity noted earlier in the thread. The patch would help future users avoid confusion when writing custom mergetools, though it would be good to see if any maintainers weigh in on whether this workaround is the intended long-term solution.
