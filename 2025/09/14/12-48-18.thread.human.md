This thread explores the deprecation of `git whatchanged` and how to transition users to its modern equivalent, `git log --raw --no-merges`. Kristoffer Haugsbakk has been the primary contributor, first demonstrating the exact functional equivalence between the commands and proposing practical aliases (like `gwh` or `wh`) to maintain the original command's brevity. 

The discussion has uncovered a technical limitation: while aliases work for new names, Git currently prevents shadowing built-in commands like `whatchanged` with aliases. However, Haugsbakk notes this restriction is expected to be lifted specifically for deprecated commands in a future Git version, which would allow users to keep typing `git whatchanged` while it transparently maps to the new implementation. 

The thread has now addressed both the technical migration path and the user experience considerations, suggesting this case may serve as a model for future command deprecations. The remaining open question is whether the project will officially document these alias-based transition strategies as recommended practice. Maintainers have not yet weighed in on this approach, but the discussion appears to be converging on a solution that balances correctness with usability.
