This is a follow-up in the ongoing discussion about deprecating `git whatchanged` and providing user-friendly migration paths. Kristoffer Haugsbakk clarifies a technical limitation in the alias-based transition strategy that was previously proposed.

The key new information is that while users can create Git aliases for the `git log --raw --no-merges` equivalent (like `wh`), they cannot currently create an alias with the exact name `whatchanged` due to Git's restriction on aliases shadowing builtin commands. However, Haugsbakk notes this restriction is expected to be lifted specifically for deprecated commands in a future Git version, which would allow for a completely seamless transition where users could keep typing the exact same command name.

This email advances the technical discussion by identifying a current limitation in the proposed solution while pointing to its likely resolution. The thread has now covered both the functional equivalence between the commands and the ergonomic transition path, with this email addressing the final technical hurdle for maintaining identical command-line behavior during deprecation.
