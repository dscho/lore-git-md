Patch 5/8 in the command deprecation series focuses on improving user-facing error messages when deprecated commands are invoked. This is part of the ongoing effort to implement alias shadowing for deprecated commands.

The patch enhances the `you_still_use_that()` function in usage.c to provide more actionable guidance when users attempt to run deprecated commands. Instead of just telling users to add a flag and email the list, it now offers a structured multi-step approach: first suggesting users check the BreakingChanges documentation, then search mailing list archives (with a pre-populated search URL using percent-encoding), and finally email the list if no suitable replacement is found. The error message drops the previous "please add" phrasing and "Thanks" closing for a more direct tone.

Key technical changes include:
- Adding a `strbuf` to properly percent-encode the command name for the search query
- Restructuring the error message into clear bullet points
- Removing the `--i-still-use-this` mention from the message body (kept only in the final `die()` call)
- Adding proper URL references to documentation and mailing list archives

The patch builds on Eric Sunshine's feedback from v2 regarding the email suggestion wording and URL formatting. It maintains the series' focus on user experience while addressing the specific case of helping users transition away from deprecated commands. The changes are well-contained to usage.c with no impact on the core deprecation machinery established in earlier patches.
