This is a follow-up discussion about the advice messaging in the worktree branch checking patch series. Ben Knoble responds to Kristoffer Haugsbakk's observation that the new `ADVICE_BRANCH_USED_IN_OTHER_WORKTREE` message doesn't appear when using the `co` alias for `checkout`, while other advice messages do work with aliases.

The issue stems from how Git handles aliases - they're executed as subprocesses using the system `git` in `PATH rather than the development version where the new advice is implemented. Ben suggests this would work correctly when using the `bin-wrappers/git` test harness, which properly sets up the development environment.

This exchange highlights an edge case in testing the new advice system that wasn't caught earlier. While not a blocker for the patch series, it's useful feedback about real-world usage patterns (many developers rely on aliases) and testing methodology. The discussion doesn't require any changes to the patch itself, but serves as a reminder to consider alias behavior when implementing new advice messages.
