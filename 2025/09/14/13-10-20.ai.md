This is a follow-up in the ongoing discussion about the deprecated `git whatchanged` command. Kristoffer Haugsbakk responds to Bjoern Bastian's preference for the command's brevity by suggesting a practical alternative.

The email proposes creating a custom alias (`wh = log --raw --no-merged`) as a replacement that maintains the typing convenience while using the non-deprecated `git log` command. This directly addresses the core user experience concern raised in the thread - the command's popularity due to its short invocation length.

Key technical details include the specific `--no-merged` flag being suggested as part of the alias, which wasn't mentioned in previous comparisons between `whatchanged` and `log --raw`. The suggestion implicitly acknowledges that while the functionality can be replicated, the ergonomic factor is a legitimate consideration in command deprecation decisions.

The response maintains a constructive tone, offering a concrete solution rather than debating the deprecation itself. This moves the discussion forward by providing a migration path that preserves the valued aspect (brevity) while aligning with the project's deprecation direction. The thread now has a specific technical proposal to consider regarding how to handle user transitions from deprecated commands.
