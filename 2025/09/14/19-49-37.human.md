This is the third patch in a series extending Git's command deprecation system with alias shadowing support. The patch allows users to create aliases that shadow deprecated builtin commands (like `whatchanged` and `pack-redundant`), which was previously prohibited.

The key change is modifying the alias handling logic to make an exception for deprecated commands, letting users create aliases that replace them. This provides a smoother transition path for users who want to keep using familiar command names while migrating to alternatives (like replacing `whatchanged` with `git log --raw --no-merges`).

The implementation adds a new `is_deprecated_command()` helper and modifies `run_argv()` to check for deprecated commands before rejecting alias shadowing. The patch includes comprehensive tests covering:
- Basic alias shadowing of deprecated commands
- Chained aliases between multiple deprecated commands
- Proper error reporting for alias loops involving deprecated commands

This builds on the deprecation infrastructure established in earlier patches, now giving users a way to work around the deprecation warnings while maintaining their workflows. The patch appears well-tested and addresses a specific user experience pain point in the deprecation process.
