This is a test patch in the command deprecation framework series, specifically adding validation for alias shadowing behavior with regular (non-deprecated) builtins.

The patch extends the test suite in t/t0014-alias.sh to verify that regular Git commands cannot be shadowed by aliases, as documented in git-config(1). It tests a representative sample of builtins (`grep`, `check-ref-format`, `interpret-trailers`, `checkout-index`, `fast-import`, `diagnose`, `rev-list`, `prune`) rather than all commands to avoid excessive test runtime (about 600ms savings).

The test uses a new helper function `cannot_alias_regular_builtin` that:
1. First runs the command normally (with `-h` flag) to establish baseline behavior
2. Then attempts to shadow it with an alias pointing to `status`
3. Verifies the original behavior persists despite the alias definition

This complements the earlier tests for deprecated command shadowing (added in previous patches) by validating the inverse case where shadowing should *not* occur. The implementation maintains consistency with the series' approach to test coverage while being performance-conscious about test runtime.

Key technical details:
- Tests both successful and failing command invocations (using `test_might_fail`)
- Validates output content matches between original and aliased invocations
- Covers a mix of plumbing and porcelain commands
- Maintains the series' focus on comprehensive edge case validation

The patch builds on the established test infrastructure from earlier in the series while adding new validation for the core alias shadowing behavior's boundary conditions. It represents the final piece of test coverage needed to fully validate the deprecation framework's alias handling.
