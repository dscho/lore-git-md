This is a follow-up in the ongoing discussion about deprecating `git whatchanged`. Kristoffer Haugsbakk responds to Bjoern Bastian's feedback about the command's continued usage, clarifying technical details and proposing a concrete migration path.

The email confirms that `git log --raw --no-merges` (correcting the earlier `--no-merged` typo) is indeed the exact functional equivalent of `whatchanged`. Haugsbakk provides specific instructions for creating both shell aliases (for direct terminal use) and Git aliases (for `git wh` usage), addressing the ergonomic concern that made `whatchanged` popular.

Key technical clarification notes that `whatchanged` shares the same backend as `log`, reinforcing that no functionality would be lost in migration. The email also references the project's stated deprecation rationale on git-scm.com, though Haugsbakk suggests removing that particular justification as unconvincing.

This reply moves the thread forward by solidifying the technical basis for migration (the exact equivalent flags) and providing actionable alias configurations.
