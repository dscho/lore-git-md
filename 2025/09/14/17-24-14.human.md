This is a follow-up discussion about the final refinements to the command deprecation and alias shadowing feature. Kristoffer Haugsbakk responds to Jeff King's suggestions about improving recursive alias error reporting in the v4 patch series.

The thread has already established the core functionality, with maintainer approval for handling all recursion cases (both simple self-referential aliases and complex inter-command cycles). The current discussion focuses on minor presentation details of error messages when recursive aliases are detected.

Jeff King had proposed two alternative approaches for reporting recursive aliases: one that would show intermediate alias expansions with `==>` markers, and another that would maintain the simpler "recursive alias" message. Kristoffer tried implementing these but found test suite failures with the first approach. After realizing the output changes only affect help text (`-h` flag) in specific edge cases, they decided to keep the current behavior for v5, treating the message format as a minor footnote rather than a core change.

The exchange represents final polishing of an otherwise complete and approved feature. The technical substance of the alias shadowing implementation remains unchanged from v4, which relocated recursion detection to `handle_alias()` as previously suggested by Jeff King and confirmed correct by Junio Hamano.
