This is a documentation clarification regarding mergetool variables from Junio Hamano, responding to Randall Becker's question about environment variable behavior.

Junio explains that the documentation's mention of BASE/LOCAL/REMOTE/MERGED variables was never intended to describe environment variables, but rather shell variables for tools integrated into Git's mergetool infrastructure. The intended usage is to add new tools by creating shell script fragments in the mergetools/ directory that get sourced by git-mergetool--lib, similar to existing tools in that directory. This differs from Becker's approach of trying to use these as environment variables in standalone scripts.

The response suggests the current behavior is working as designed, though the documentation could be clearer about the distinction between shell variables for integrated tools versus environment variables. Junio notes he's not a mergetool user himself but provides the architectural context for how the system was meant to work. This appears to close the technical discussion by confirming the original design intent, leaving any documentation updates as the remaining action item.
