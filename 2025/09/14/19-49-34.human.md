This is the final version of a feature series improving Git's command deprecation system, specifically focusing on better user experience when deprecated commands like `whatchanged` and `pack-redundant` are used. The series has already received maintainer review and approval through several iterations.

The key improvements in v5 include:
1. More helpful error messages that suggest concrete alternatives (like using `git log --raw --no-merges` instead of `whatchanged`) and explain how to create aliases for deprecated commands
2. Fixes for memory leaks and infinite loop cases found by Jeff King
3. Expanded test coverage for alias handling of deprecated commands
4. Documentation updates clarifying the transition path for users of deprecated commands

The implementation now properly handles all identified edge cases around alias recursion and shadowing, with the core logic moved to `handle_alias()` as suggested by Jeff King. The error messages strike a balance between being informative and not too verbose, with special attention given to the common `whatchanged` case where users have been actively reporting continued usage.

This appears ready for final merging, representing a thoughtful improvement to the deprecation workflow that both maintains technical correctness and provides better guidance for users transitioning away from old commands.
