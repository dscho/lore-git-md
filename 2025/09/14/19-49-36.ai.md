This is part 2/8 of the command deprecation framework series, focusing on alias handling infrastructure. The patch moves alias loop detection bookkeeping from `run_argv()` into `handle_alias()`, where it more logically belongs as the series prepares to support shadowing deprecated builtins with aliases.

The key change relocates the `expanded_aliases` tracking (renamed from `cmd_list` for clarity) into `handle_alias()`, which will be called recursively when handling deprecated commands. This prevents blind spots in loop detection when aliases chain through deprecated builtin names. The patch maintains all existing functionality while better organizing the code for the upcoming alias-shadowing feature.

Technical details include:
- Modified `handle_alias()` signature to accept the tracking list
- Preserved identical loop detection output format with `==>` markers
- Keeps Jeff King's original architectural approach from earlier versions
- Sets up for the next commit which will test edge cases of alias loops involving deprecated commands

The change is a preparatory refactor with no user-visible behavior differences yet, though it will enable proper handling of the special case where both ends of an alias loop are deprecated commands. The patch carries forward Jeff King's original work and maintains the series' careful approach to recursion detection.
