This is a follow-up in the mergetool environment variables thread, offering an alternative solution to the integration of custom merge tools.

Phillip Wood points out that users can define custom merge tools without modifying Git's installation directory by using the `mergetool.<tool>.cmd` configuration. The approach involves:
- Setting up a config entry that evaluates a shell command with the standard mergetool variables (`$BASE`, `$LOCAL`, `$REMOTE`)
- Having Git expand these variables when invoking the tool via `git mergetool`

The key technical detail is that this method bypasses the need to install scripts in Git's `mergetools/` directory by leveraging Git's existing configuration system for tool integration. The variables remain shell variables (not environment variables) but are properly expanded through the eval mechanism.

This provides a cleaner alternative to Randall Becker's workaround of manually exporting variables, though both approaches remain valid. The discussion continues to highlight the need for clearer documentation about the various ways to integrate custom merge tools with Git's mergetool infrastructure.
