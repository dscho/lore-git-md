This is part of the command deprecation framework series, focusing on improving user-facing error messages when deprecated commands are used. Patch 5/8 enhances the error output to provide concrete guidance rather than just refusing execution.

Kristoffer Haugsbakk's patch revamps the error message shown when users attempt to run deprecated commands like `git whatchanged`. Instead of a terse refusal, it now offers a structured action plan: first consult the breaking changes documentation, then search mailing list discussions, and finally email the list if no suitable replacement is found. The message includes properly encoded search links and drops some of the more polite but less actionable phrasing from earlier versions.

The implementation adds string buffer handling to properly encode command names for URL searches while maintaining the same core behavior of refusing to run without the override flag. This represents the user experience polish phase of the deprecation framework, building on the technical foundations established in earlier patches. The approach has been refined through feedback, with Eric Sunshine contributing to the messaging structure.

This change aligns with the series' goal of making command deprecations more user-friendly while still maintaining the project's ability to remove unmaintained functionality. The patch appears well-considered, with attention to both technical details of URL encoding and the human factors of error message design.
