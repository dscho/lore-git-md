Part of the command deprecation framework series, this patch enhances user guidance for the deprecated `git whatchanged` command. It adds specific instructions for users to either replace it with an equivalent `git log` command (`--raw --no-merges`) or create an alias, addressing real-world reports from users still relying on the deprecated command.

The changes include:
1. Adding concrete `git log` replacement syntax to both the error message and documentation
2. Showing how to create an alias for those who want to keep the familiar command name
3. Updating the `you_still_use_that()` function to accept an additional hint parameter
4. Maintaining consistency by applying similar changes to `git pack-redundant` (though without hints, as it lacks a direct replacement)

This is the 6th patch in an 8-part series that has already been through multiple rounds of review, with the core technical approach approved in v4. The focus here is on improving the user experience when encountering deprecated commands, particularly addressing feedback from actual users who have struggled with the transition. The patch is well-constructed with thorough documentation updates and maintains consistency with the series' established patterns.
