Bugfix for gitk (Git GUI tool) regarding deleted remote branches. This is a follow-up email in an existing thread where Johannes Sixt (not the original author) is acknowledging Michael Rappazzo's patch that fixes an issue with gitk's handling of deleted remote tracking branches.

The patch addresses a specific scenario where gitk would fail to open its "Tags and Heads" view after a remote branch was deleted (via `git push --delete`). The root cause was an inconsistency between gitk's internal data structures tracking branch heads (`headids`) and remote relationships (`upstreamofref`). The fix adds a simple existence check before accessing these references.

Johannes Sixt, who appears to be involved in gitk maintenance, has reviewed the patch and deemed it reasonable, stating "Thank you, this looks reasonable. Queued." This suggests the fix will likely be incorporated into gitk. The original patch included a detailed reproduction recipe demonstrating the error case, which helps verify both the problem and solution.
