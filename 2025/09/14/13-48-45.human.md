This is a follow-up in the mergetool environment variables discussion, offering an alternative solution to the integration question.

Phillip Wood chimes in with a simpler approach for custom mergetool integration, suggesting that users can bypass the mergetools/ directory entirely by using the `mergetool.<tool>.cmd` configuration. He demonstrates how to directly specify a command line that receives the standard merge variables (BASE, LOCAL, REMOTE) as shell arguments rather than relying on them being set as variables.

The solution involves:
1. Configuring a custom tool via `git config mergetool.my-tool.cmd`
2. Having the command string properly quote and reference the variables
3. Letting `git mergetool` evaluate this string with the correct file paths

This provides a cleaner alternative to the previously discussed workarounds (modifying installed scripts or manually exporting variables). The thread has now surfaced two viable patterns for custom tool integration - either through the mergetools/ directory with sourced variables, or via direct command configuration with passed arguments. Both approaches appear to work with the current implementation while waiting for documentation updates to clarify the intended usage patterns.
