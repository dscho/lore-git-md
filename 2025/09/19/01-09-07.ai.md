Documentation patch adding loose object format specification as part of SHA-1/SHA-256 interoperability preparation.

This patch introduces a new `gitformat-loose.adoc` document that formally specifies Git's loose object storage format. It's part 5 of 9 in brian m. carlson's series laying groundwork for hash function interoperability. The document describes the file structure, naming convention, and content format of loose objects, including the header prefix (type, size, null byte) and zlib compression details. It provides concrete examples for both SHA-1 and SHA-256 repositories, showing how the empty tree and a simple blob would be stored.

The documentation covers key technical details needed for understanding object storage during the transition period where repositories may contain both hash types. It explains the relationship between uncompressed content and the resulting object ID, and shows the filesystem layout where objects are stored under `objects/` with the first two hex digits as a subdirectory.

This is straightforward technical documentation that fills a gap in Git's format specifications. The content appears accurate and matches existing implementation behavior. As part of the larger interoperability effort, having this formally documented will help developers and future maintainers understand the storage format requirements when working with multiple hash algorithms.
