[PATCH] git whatchanged deprecation user feedback

Thread identity: User report from James Puleo about `git whatchanged` deprecation in Git 2.51.0, questioning the removal of this file-change tracking tool.

Core problem: The `git whatchanged` command, deprecated since 2020 and now requiring `--i-still-use-this` flag, remains useful for tracking file changes across refs - particularly for locating deleted files' history. User argues the deprecation creates unnecessary friction for a simple, functional tool.

Current status: `git whatchanged` has been in deprecation path since 2020 (commit a8e2394704), with users directed to use `git log --name-status` or similar alternatives. No active development on the command itself.

Key technical details: The reporter's specific use case involves finding which ref last contained a deleted file - functionality that could be replicated with `git log --name-status --diff-filter=D -- <path>` or similar `git log` invocations.

Open questions: Whether the deprecation warning's friction is justified given the command's continued utility for some workflows. No technical objections raised beyond usability concerns.

Participant positions: James Puleo reports real-world usage where `git whatchanged` provides simpler workflow than current alternatives. No maintainer or other user responses yet.

Related work: Original deprecation discussion from 2020, ongoing efforts to modernize and simplify Git's command-line interface.
