This is a comprehensive patch series addressing the strvec memory management issues in `setup_revisions()` that were uncovered by the `git stash show` double-free bug. Jeff King presents a multi-pronged solution that both fixes immediate problems and introduces safer patterns for future usage.

The series starts with two critical fixes: patch 1 plugs a small leak in `git stash`, while patch 2 directly addresses the double-free issue by properly managing memory ownership during `setup_revisions()` operations. These form the essential bugfixes for the reported crash.

Patches 3-5 introduce a new `setup_revisions_from_strvec()` wrapper API that provides a safer interface for strvec callers, though Jeff notes these are more about preventing future issues than fixing current bugs. The wrapper helps maintain strvec invariants by handling memory management automatically.

The final patch enforces NULL termination in `setup_revisions()` for all callers, which revealed several edge cases - including many callers passing NULL argv and strvec users making assumptions about untouched arguments. The solution carefully balances backward compatibility with proper memory management.

The series shows deep consideration of the complex interactions between `setup_revisions()` and strvec usage across Git's codebase. Jeff has validated the full test suite under multiple sanitizers (LSan, ASan, UBSan) to ensure no new issues are introduced. The changes touch numerous commands that use revision parsing, including bisect, rebase, submodules, and more.

- New `setup_revisions_from_strvec()` API provides safer strvec handling
- Maintains backward compatibility with existing call patterns
- Fixes both leaks and double-free scenarios
- Adds test coverage for the original stash crash case
- Modifies 17 files across core and builtin commands
