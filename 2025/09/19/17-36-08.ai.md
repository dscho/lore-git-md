This is a response to a controversial RFC proposing to make Rust mandatory in Git. The email strongly opposes the idea, arguing it would be disastrous for systems without Rust support.

The author Sergey Fedorov raises several concrete concerns: the change would break Git functionality on non-Rust platforms, disrupt build systems and package managers that rely on Git for source fetching, and make Git-based services like GitHub unusable. They note that while local version control could theoretically switch to alternatives, there are no viable replacements for the build system and service integration use cases.

The personal impact is emphasized in a postscript - the author states this change would effectively end their ability to contribute to open source as they currently do, since their platform lacks Rust support. The tone is urgent and the objections are framed as existential threats to both the ecosystem and individual contributors.

Key technical points for future reference: the objection centers on platform compatibility (specifically systems without Rust), build system integration, and service dependencies. The "mandatory Rust" proposal being responded to appears to be a significant architectural change that would affect core Git functionality across multiple use cases. The strong pushback suggests this would be a contentious change if pursued.
