Bugfix addressing a memory leak in `git stash show` when using `--` arguments. This is the first patch in a series fixing strvec memory management issues in `setup_revisions()`.

The patch focuses on `git stash show`'s handling of revision arguments passed via strvec. Currently, when `setup_revisions()` modifies the argv (like dropping `--` markers), it can leak the removed elements. The fix follows the pattern from commit f92dbdbc6a by setting `free_removed_argv_elements` in the `setup_revision_opt` struct.

Jeff King notes the current argument parsing in `show_stash()` has questionable behavior regarding `--` handling, where arguments after `--` are treated as stash options rather than pathspecs. However, this patch deliberately avoids changing that behavior, focusing only on the memory leak. A test is added to verify the leak is fixed when using `--` with no additional arguments.

The changes are minimal - just 3 lines modified in `builtin/stash.c` to pass the new option, plus a simple test case. This appears to be a straightforward fix for a clear memory leak, though it leaves open the larger question of whether `git stash show`'s argument parsing should be made more consistent with other Git commands.
