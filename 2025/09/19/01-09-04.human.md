This is a documentation patch that's part of a larger series (2/9) about pack index format changes. The patch updates the technical documentation to reflect a proposed change in how offsets are stored in pack index version 3.

The current v3 format stores some data in object ID order and some in pack order, which creates inefficiencies when looking up objects. The proposed change would make offset values consistently follow pack order, allowing simpler and more cache-friendly lookups. The author notes this would eliminate the need for the revindex (reverse index) in v3.

The patch itself is straightforward - it updates just one documentation file to describe the new offset ordering scheme. The change appears well-motivated by performance considerations, though as documentation it doesn't include any implementation or benchmarks. Since this is part of a larger series, readers will want to look at the other patches (and likely the cover letter) for the full context of the changes affect the pack format.
