This is a technical discussion about man page formatting details in the ongoing documentation patch series for `git-push`.

Jeff King responds to Brian m. carlson's concerns about list indentation in man pages by digging into the toolchain specifics. He explains that both AsciiDoc and Asciidoctor implementations in Git's documentation system ultimately generate XML that gets converted to roff via DocBook XSL stylesheets. Jeff provides a concrete diff showing how the indentation width could theoretically be adjusted by modifying the `manpage-normal.xsl` file, pointing to the relevant DocBook documentation for the `man.indent.width` parameter.

The email notes that while Asciidoctor could generate roff directly, Git's build system doesn't currently use this capability to maintain compatibility with AsciiDoc. Jeff agrees with Brian's assessment that deep customization of man page styling may not be worth the effort, given the toolchain constraints and the traditional 4-space indentation standard for man macros.

This exchange represents a low-level implementation discussion that doesn't affect the substantive content of Julia Evans' documentation improvements, which have already received maintainer approval. The conversation is focused on formatting minutiae that could be addressed separately if desired, but appears unlikely to block the patch series' progression.
