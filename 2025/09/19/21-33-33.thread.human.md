This thread discusses how to handle deprecated commands like `git-whatchanged` in the build system when `WITH_BREAKING_CHANGES` is enabled. The initial proposal was to add `git-whatchanged` to `EXCLUDED_PROGRAMS`, which would exclude it from both binary installation and documentation generation, matching its existing exclusion from `BUILT_INS`. 

Patrick Steinhardt raised the idea of keeping man pages for deprecated commands with replacement notices rather than removing them entirely, arguing this would provide better user guidance. Junio Hamano acknowledged this approach but noted it would require significant changes to the build system's current assumptions, where `EXCLUDED_PROGRAMS` tightly couples binary exclusion with documentation exclusion. The current system also conveniently skips documentation linting for excluded commands.

The discussion now balances two paths: either proceed with the simpler approach of complete removal (both binary and documentation) or undertake more complex build system changes to support keeping documentation with deprecation notices. Junio's response suggests the latter would require decoupling several interconnected behaviors around `EXCLUDED_PROGRAMS`, making it a non-trivial undertaking. The thread remains open on whether the user communication benefits justify the implementation effort.
