This thread continues the discussion about how to handle deprecated commands in Git's build system and documentation when `WITH_BREAKING_CHANGES` is enabled. The core issue revolves around whether to completely remove man pages for deprecated commands like `git-whatchanged` or keep them with deprecation notices, along with technical implementation details in the Makefile.

Junio Hamano and Patrick Steinhardt have been the primary participants, with Junio focusing on the technical aspects of the `EXCLUDED_PROGRAMS` implementation while Patrick has raised additional considerations about user communication. There's emerging consensus to add `git-whatchanged` to `EXCLUDED_PROGRAMS` when `WITH_BREAKING_CHANGES` is set, matching its existing exclusion from `BUILT_INS`.

Ben Knoble contributed a minor clarification about diff output formatting (the meaning of "i/" and "w/" prefixes when `diff.mnemonicPrefix` is enabled), which Patrick Steinhardt acknowledged as useful information though not directly relevant to the main discussion.
