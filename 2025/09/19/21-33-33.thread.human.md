This thread discusses improvements to how the build system handles documentation for deprecated Git commands when `WITH_BREAKING_CHANGES` is enabled. The original patch proposed adding `git-whatchanged` and `git-pack-redundant` to the `EXCLUDED_PROGRAMS` list to match their existing exclusion from the build process, while also making the documentation linting respect these exclusions.

Junio Hamano suggested properly excluding these deprecated commands from documentation generation, which Patrick Steinhardt has now responded to. Patrick agrees with the technical approach but notes this would stop linting for excluded commands. He also proposes an alternative idea: rather than completely removing man pages for deprecated commands, they could be kept with notices explaining the deprecation and suggesting alternatives. This would maintain better user communication while still marking the commands as obsolete.

The discussion remains focused on build system mechanics but now includes consideration of how to best handle user-facing documentation for deprecated features. The core question is whether to completely exclude these commands from documentation or maintain them with deprecation notices. No final decision has been reached yet, but the conversation is moving toward balancing technical cleanliness with user experience.
