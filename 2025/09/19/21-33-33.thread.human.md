This thread discusses how to handle documentation for deprecated Git commands when `WITH_BREAKING_CHANGES` is enabled, focusing particularly on `git-whatchanged`. The initial proposal considered keeping man pages with deprecation notices, but Junio Hamano identified significant technical constraints in the build system that tightly couple binary installation with man page generation.

Patrick Steinhardt, who originally advocated for maintaining documentation with deprecation notices, has now acknowledged the implementation challenges and conceded to a simpler approach - excluding man pages entirely for deprecated commands via the `EXCLUDED_PROGRAMS` mechanism. This matches the existing behavior where excluded programs aren't built as binaries. While Patrick leaves open the possibility of someone implementing his more comprehensive documentation approach in the future, he recognizes this would require substantial build system restructuring to decouple binary and documentation handling.

The discussion has reached practical consensus on the immediate path forward while highlighting architectural constraints that may need addressing for more flexible deprecation handling in the future. The thread demonstrates Git's careful balancing act between user experience considerations and implementation realities in its build system.
