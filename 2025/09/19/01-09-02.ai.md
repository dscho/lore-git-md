This is a cover letter for a multi-part series about SHA-1/SHA-256 interoperability, with this first part focusing on documentation updates and test infrastructure preparation. The series represents foundational work for Git's planned hash function transition in version 3.0.

The cover letter outlines two main components in this initial 9-patch series. First, it updates various documentation files to correct inaccuracies and improve clarity, particularly around pack file formats and tag signatures. A new `gitformat-loose.adoc` document is introduced to describe loose object storage, with more details to come in future patches. Second, it adds test infrastructure to support compatibility hash testing, including new prerequisites and adjustments to handle cases where certain tests can't run in interoperability mode.

Key technical elements include:
- Documentation updates for pack index v3 format and tag signature handling
- New `gitformat-loose.adoc` documenting loose object storage
- `rev-parse` gains ability to print compatibility hash
- Fsck now expects GPG signature headers in tags
- Test infrastructure for compatibility hash testing
- New test prerequisites (`COMPATIBILITY_HASH`) for future interoperability tests

The author notes this series is intentionally non-controversial, with more substantive changes (including Rust code) planned for part 2 after prerequisite work lands. The changes appear well-motivated and carefully considered, with thorough documentation updates and test coverage. The series touches core areas (pack files, object storage, fsck) but focuses on non-disruptive groundwork for the larger hash transition effort.
