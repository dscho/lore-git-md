RFC proposing mandatory Rust in Git continues with platform-specific objections from Gentoo maintainers. The thread spans compatibility concerns (NonStop, PowerPC Mac OS X, OpenBSD/macppc via Collin Funk and Florian Märkl) and distribution packaging impacts, now with Michael Orlitzky responding to brian m. carlson's Rust/Haskell bootstrap comparison.

Technical objections include compiler support gaps (NonStop, Gentoo's 23 arch/libc combinations vs pandoc's 5 glibc-only architectures), build system challenges, and Rust's dependency churn. Orlitzky provides concrete data from Gentoo's experience bootstrapping GHC on riscv/musl, arguing Rust adoption would similarly limit Git's availability. While acknowledging Rust's safety benefits (static typing, memory safety), he maintains transition costs outweigh advantages for source-based distributions.

Unresolved issues persist: Ezekiel Newren's request for constraints remains open, platform gaps (NonStop, PowerPC variants, riscv/musl) lack solutions, and distribution impacts are only partially addressed. The discussion has expanded to include comparative analysis with Haskell ecosystem challenges, with Gentoo's experience providing concrete evidence of portability tradeoffs. Core tensions remain between Rust's safety advantages and its ecosystem impact on packaging stability and niche platform viability, particularly for source-based distributions maintaining broad architecture support. brian m. carlson's proposed mrustc bootstrap solution and conservative dependency management (targeting Debian stable crate versions) have not fully addressed these concerns.
