RFC proposing mandatory Rust in Git continues with Ezekiel Newren seeking specifics on platform compatibility objections. The thread centers on whether Rust can be made mandatory without breaking existing Git functionality, particularly for platforms lacking Rust support. Original objections cited three areas: breaking Git on non-Rust platforms (including PowerPC MacOS via Collin Funk's LLVM observation and now expanded to OpenBSD/macppc by Florian Märkl), disrupting build systems and package managers, and impacting Git-based services. The discussion now includes implications for projects that use Git as a dependency while needing to support older architectures. Technical focus remains on compiler support gaps (expanded list: PowerPC Mac OS X, OpenBSD/macppc, NonStop, Gentoo) and build system integration challenges, while allowing for subjective factors like language preference. Core tension persists between Rust advocates seeing it as essential for memory safety and opponents viewing mandatory adoption as threatening platform support and ecosystem stability, with new data points about actively maintained legacy systems.
