RFC proposing mandatory Rust in Git now encompasses platform compatibility, build system impacts, and distribution packaging stability as three major concerns. Original objections centered on platform support gaps (NonStop, PowerPC Mac OS X, OpenBSD/macppc via Collin Funk and Florian Märkl). Michael Orlitzky and Sam James from Gentoo expanded the scope to include Rust's ecosystem churn forcing distributions to bundle outdated crates against their policies, undermining Linux package management principles. 

Technical objections now span: 1) Compiler support gaps (NonStop, Gentoo, PowerPC variants including OpenBSD/macppc - Märkl notes Rizin project's active use of these for architecture testing), 2) Build system integration challenges, and 3) Distribution packaging instability (Orlitzky and James highlight Rust's dependency churn requiring Windows-style manual management). James clarifies Gentoo can technically support Rust but emphasizes the unsustainable maintenance burden on source-based builds, especially for niche platforms (riscv/musl). 

Ezekiel Newren's earlier request for specific constraints remains open, with responses now covering corporate policies, missing toolchains, practical maintenance burdens, and distribution workflow impacts. Core tension persists between Rust advocates prioritizing memory safety and opponents citing platform/ecosystem stability threats, with new data points about actively maintained legacy systems and downstream packaging workflows. The discussion has evolved from purely technical compatibility to include systems administration and distribution policy considerations, with Git's centrality amplifying the stakes for Linux distributions.
