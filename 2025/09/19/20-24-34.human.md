Build system patch with Windows/MSVC linker workaround. This is part of Ezekiel Newren's 18-part Rust integration series, specifically addressing PATH manipulation needed for Windows/MSVC builds. The patch includes a workaround that temporarily reorders PATH to ensure the Microsoft linker (LINK.exe) is found before Unix's `link` command during Rust builds.

Eric Sunshine provides feedback on two aspects: first, he suggests removing IDE-specific `.idea/` entries from `.gitignore` (which Newren agrees to), and second, requests clarification about the Windows PATH manipulation. Newren explains the issue stems from cargo accidentally finding Unix's `link` command instead of Microsoft's linker, and proposes moving standard Unix paths to the end of PATH as a solution.

The discussion highlights the careful balance needed in cross-platform build systems, particularly when integrating new toolchains like Rust. The PATH workaround appears to be a pragmatic solution to a real Windows/MSVC-specific issue, though the explanation could be clearer in the commit message (as noted by Sunshine).
