This is a bugfix patch addressing memory management issues in `setup_revisions()`, part of a larger series fixing strvec-related problems. The patch specifically prevents memory leaks and double-frees that occur when invalid options are passed to commands like `git stash show`.

The core issue stems from how `setup_revisions()` handles argument shifting - it was overwriting argv entries without properly managing memory ownership when those entries came from allocated strvecs. Jeff King's solution introduces a new `overwrite_argv()` helper that carefully moves (rather than copies) arguments while maintaining proper NULL termination and memory cleanup.

The patch demonstrates the fix with a test case where `git stash show -p --invalid` would previously crash due to a double-free. The command now fails gracefully with a usage message while properly cleaning up memory. The changes are contained to revision.c and maintain backward compatibility while fixing the immediate issue.

This is technically complex work touching core revision parsing logic, but the patch is well-explained with detailed commit message analysis and includes a regression test. It represents the second of six patches in a series addressing both immediate bugs and broader architectural concerns around strvec usage in Git.
