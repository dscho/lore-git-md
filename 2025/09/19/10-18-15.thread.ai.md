Technical core expanded with part 5 details:
- `git stash show` memory leak when using `--` arguments (first patch in series)
- `setup_revisions()` argument shifting violates strvec invariants by modifying `.nr` count without NULL termination
- Causes both leaks (unfreed removed elements) and double-frees (when strvec cleanup encounters consumed elements)
- Jeff King's analysis revealed this affects multiple commands (`stash`, `bisect`, `rebase`, submodules, pack-objects, sequencer, upload-pack) through shared revision parsing
- New `overwrite_argv()` helper function introduced to properly manage memory ownership during argument shifts
- New `setup_revisions_from_strvec()` wrapper API provides safer interface for strvec-based calls
- Part 5 converts pack-objects, rebase, sequencer, shallow, and upload-pack to use strvec directly
- Solution handles both option consumption and movement cases while maintaining strvec invariants
