Bug report: double-free crash in `git stash show -p` with invalid options. Thread originated by Lauri Niskanen documenting a crash when passing invalid arguments (e.g. `--invalid`), with regression identified by Kristoffer Haugsbakk as introduced in commit 748bd094 ("builtin/stash: fix leak in `show_stash()`", 2024-06-11). Core issue is in `show_stash()` where `strvec_clear()` attempts to free already-freed memory during error cleanup after option parsing fails, triggering "free(): double free detected in tcache 2".

Technical details: crash occurs at `builtin/stash.c:1047` during cleanup path. Valgrind traces confirm memory originally allocated via `strdup()` is freed twice. Backtrace shows flow through `strvec_clear()` from `show_stash()` error handling. System context: Git 2.51.0 (c44beea), glibc 2.42. The regression stems from a leak-fix commit that inadvertently disrupted strvec ownership semantics during error conditions.

Current status: regression source identified but fix strategy remains open - either adjust error handling in `show_stash()` or revise strvec management from 748bd094. Narrow scope (only affects invalid-option cases in `show_stash()`) makes this a strong backport candidate once fixed. Open questions: whether similar issues exist elsewhere in argument parsing cleanup paths, and exact ownership semantics needed for correct strvec management during error cases.
