Bug report: double-free crash in `git stash show -p` with invalid options. Thread originated by [reporter] documenting a reproducible crash when passing invalid arguments to `git stash show -p` (e.g. `--invalid`). Core issue is in `show_stash()` where `strvec_clear()` attempts to free already-freed memory during error cleanup after option parsing fails, triggering "free(): double free detected in tcache 2". 

Technical details: crash occurs at `builtin/stash.c:1047` during cleanup path. Valgrind traces confirm memory originally allocated via `strdup()` is freed twice. Backtrace shows flow through `strvec_clear()` from `show_stash()` error handling. System context: Git 2.51.0 (c44beea), glibc 2.42. Expected behavior would be graceful error reporting for invalid options rather than abort.
