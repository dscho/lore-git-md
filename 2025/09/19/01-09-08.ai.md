This is part 6/9 of the SHA-1/SHA-256 interoperability series, adding a new feature to `git rev-parse` to expose compatibility hash information. The patch introduces a `compat` mode to `--show-object-format` that prints the compatibility hash algorithm when one is configured (via `extensions.compatobjectformat`), or an empty line when none exists.

The change extends the existing `--show-object-format` option to handle four cases: `storage` (current default), `input`, `output`, and the new `compat` mode. The implementation checks `the_repository->compat_hash_algo` and prints its name if set, otherwise outputs just a newline. This behavior is specifically to support scripts that may chain multiple `--show-object-format` queries while maintaining unambiguous output.

Test coverage is thorough, verifying behavior in both SHA-256 repositories with and without a configured SHA-1 compatibility mode. The tests confirm proper output for all format types and error handling for invalid modes. Documentation updates clearly explain the new option and its behavior.

This patch continues the series' pattern of building infrastructure for hash interoperability while avoiding controversial changes. It touches `builtin/rev-parse.c` for the core implementation, updates the man page, and adds comprehensive tests in `t1500-rev-parse.sh`. The change is logically independent from other parts of the series while contributing to the overall goal of supporting multiple hash algorithms.
