This is a comprehensive fix series addressing memory management issues in `setup_revisions()` that were exposed by a double-free` crash in `git stash show -p`. The series comes from Jeff King after extensive analysis of the problem's scope and implications.

The root issue involves how `setup_revisions()` handles argument parsing when called with strvecs, where it can leave memory in an inconsistent state by shifting arguments without properly managing ownership. The initial patches (1-2) fix the immediate double-free and related leaks, while later patches (3-6) introduce safer abstractions and clean up callers.

Key aspects of the solution include:
- A new `setup_revisions_from_strvec()` wrapper that properly maintains strvec invariants
- Careful management of memory when `setup_revisions()` consumes arguments
- Fixes for various callers that were relying on the old behavior
- Additional test coverage for the stash case

The series appears thorough, with testing under multiple sanitizers, and addresses both the immediate crash and broader architectural concerns. Jeff notes some of the solutions were tricky to implement without breaking existing code, and there's an interesting open question about whether `setup_revisions()` should avoid modifying argv entirely.

This represents a significant improvement to Git's memory safety, particularly affecting commands that use revision parsing (stash, bisect, rebase, etc.). The patches look well-considered and tested, making this an important series for maintainers to review.
