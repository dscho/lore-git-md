Bugfix for double-free in `git stash show` error handling. Junio C Hamano responds to the reported regression where invalid options trigger a double-free crash, analyzing the root cause and proposing two potential fixes.

The issue stems from how `setup_revisions()` modifies the strvec array during option parsing, leaving duplicate entries that later cause cleanup problems. Hamano explains the current behavior in detail: when given an invalid option like `--no-such-option`, the array gets reshuffled but maintains its original length, leading to duplicate references that `strvec_clear()` tries to free twice.

Two solutions are presented: (1) a minimal fix that NULLs unused array slots after `setup_revisions()` returns, preserving the current API contract, or (2) modifying `setup_revisions()` itself to NULL unused slots as part of its operation. The first approach is more performant and maintains backward compatibility, while the second might be safer long-term at the cost of changing API behavior.

This appears to be a well-analyzed response from the Git maintainer, directly addressing the regression with clear technical explanations and practical solutions. The proposed fixes are narrowly targeted to resolve the specific crash while considering broader implications for the revisions API.
