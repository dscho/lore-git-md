Platform compatibility concern from a Debian ports maintainer regarding Rust adoption in Git.

John Paul Adrian Glaubitz, who maintains Git for several Debian ports architectures (alpha, hppa, m68k, sh4, sparc64), raises concerns about the planned mandatory Rust requirement in Git 3.0. Four of these architectures currently cannot build Rust (alpha, hppa, m68k, sh4), with m68k being a special case where alignment issues prevent LLVM/rustc builds despite theoretical support.

While not opposed to Rust in principle, Glaubitz suggests waiting for GCC-based Rust solutions (rustc_codegen_gcc or GCC's Rust frontend) to mature, which would ease porting to these architectures and potentially to Non-Stop systems. He notes ongoing work to address m68k alignment issues but emphasizes the broader challenge of Rust adoption on niche platforms.

This email highlights a real-world constraint for the Rust transition, particularly for distribution maintainers supporting older or less common architectures. The concern is well-articulated and grounded in practical packaging experience, though it doesn't propose specific changes to Git's plans beyond a general plea for patience. The thread context shows this intersects with ongoing discussions about build system flexibility and platform support.
