Thread identity: Documentation patch (1/9 in series) updating pack index v3 format specification to support very large repositories.

Core problem: Current pack index v3 format uses 32-bit integers for file offsets and trailer positions, limiting repositories to ~67 million objects. The patch documents planned expansion to 64-bit integers to handle larger repositories, along with using full 32-byte SHA-256 checksums (matching v2 behavior) rather than truncated hashes.

Key technical details:
- Pack index v3 format changes:
  - 4-byte -> 8-byte integers for file offsets and trailer positions
  - 32-byte SHA-256 checksums (was 20-byte truncated hashes)
- Documentation updates in Documentation/technical/pack-format.txt
- Justifications:
  - Practical need (repositories with >55M commits)
  - Consistency with SHA-256 pack checksums
  - Security compliance (full hashes preferred)

Current status: Documentation-only patch (1/9 in series). No implementation changes yet, but lays groundwork for subsequent patches.

Participant positions: None yet (first patch in series). Author is documenting planned changes before implementation.

Related work: Part of ongoing pack format improvements (see multi-pack-index, geometric repacking efforts). Builds on SHA-256 hash algorithm support work.
