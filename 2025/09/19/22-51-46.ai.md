This is the final patch in Jeff King's series addressing strvec memory management issues in `setup_revisions()`. The patch focuses on maintaining the NULL-termination invariant in argv arrays when they are processed by `setup_revisions()`.

The key technical detail is that while `setup_revisions()` shrinks the argc count to reflect consumed options, it doesn't properly NULL-terminate the resulting argv array. This isn't currently causing bugs since callers are aware of this behavior, but it violates a common C convention and could be a future maintenance hazard. The patch adds NULL termination while carefully handling the case where `free_removed_argv_elements` is set (freeing the element before NULLing it out).

The solution is narrowly scoped - it only NULL-terminates at the new argc boundary rather than trying to clean up all trailing elements, as that would require more invasive refactoring. The patch notes that the more comprehensive `setup_revisions_from_strvec()` API (introduced earlier in the series) already handles this case properly for strvec users.

This completes the architectural improvements started in the series, ensuring all paths through `setup_revisions()` maintain proper memory invariants. The change is minimal (6 lines) but important for long-term code health, and builds on the earlier work to systematically convert callers to safer interfaces. The patch maintains backward compatibility while closing a potential maintenance hazard in the core revision parsing code.
