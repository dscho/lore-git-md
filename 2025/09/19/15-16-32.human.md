This is the final patch (10/10) in a refactoring series preparing xdiff internals for potential Rust integration. The patch introduces named constants (NO, YES, MAYBE) for the previously magic-numbered values 0, 1, and 2 used in the `rchg` array that tracks changed lines during diff operations.

The change makes the code more readable by replacing numeric literals with meaningful names, though the author notes the array name `rchg` itself could perhaps be improved to `changed`. The patch touches several xdiff algorithm implementations (xdiffi.c, xhistogram.c, xpatience.c, xprepare.c) to consistently use these new constants.

While some changes might appear to alter behavior by explicitly checking for YES while ignoring MAYBE, the commit message explains this is safe because MAYBE is only used temporarily during diff calculation and never persists in the final `rchg` array. The patch maintains identical runtime behavior while improving code clarity.

This completes the preparatory cleanups in the series, which Junio Hamano has indicated will be merged to 'next'. The Rust-specific type changes will follow in a separate series. The changes are performance-neutral and have been thoroughly benchmarked.
