This is a proposed fix for the double-free bug in `git stash show -p`'s argument parsing, offering two approaches to resolve the issue. Junio Hamano presents both a targeted fix for the stash command and a more comprehensive solution modifying `setup_revisions()`'s behavior.

The first approach (local fix) simply NULLs out unused slots in the strvec after `setup_revisions()` returns in `show_stash()`. This matches the current API contract where callers shouldn't examine slots beyond the returned argc, but prevents double-frees during strvec cleanup.

The second approach (systemic fix) modifies `setup_revisions()` itself to NULL unused slots, changing its API contract to actively clean up after itself. This would prevent similar issues in other commands using the same pattern. The patch includes this implementation with a new test case verifying proper error handling with invalid options.

Key technical details:
- The bug occurs when `setup_revisions()` shifts arguments left without NULLing originals, creating duplicate pointers
- `strvec_clear()` then frees these duplicates, causing double-frees
- The systemic solution modifies `revision.c` to NULL unused slots during processing
- A new test in `t3903-stash.sh` verifies proper error handling with invalid options

The discussion continues weighing tradeoffs between a quick local fix versus a more thorough API change that would prevent similar issues elsewhere. The systemic solution appears more robust long-term but requires careful review of the `setup_revisions()` changes. The patch includes test coverage for the error case but doesn't address potential performance impact of the additional NULL assignments.
