**Documentation patch adding loose object format specification**

This is the fifth patch in brian m. carlson's SHA-1/SHA-256 interoperability series, focusing on documenting Git's loose object storage format. The patch introduces a new `gitformat-loose.adoc` file that precisely describes how loose objects are structured on disk, including their header format, compression, and storage location.

The documentation covers both the logical format (type/size header plus content) and physical storage (zlib compression and directory layout). It provides concrete examples for both SHA-1 and SHA-256 repositories, making this particularly relevant for the hash transition work. The examples include the empty tree object and a simple blob, showing the complete object ID and storage path for each.

As part of the larger interoperability effort, this documentation serves as important groundwork by formally specifying behavior that was previously only implicit in the_repository implementation. The patch is cleanly focused and well-explained, with no implementation changes - just documentation that will help both future contributors and users understand the storage format.
