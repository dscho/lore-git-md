Bugfix for a double-free crash in `git stash show -p` when given invalid options. 

Lauri Niskanen reports that passing an invalid option to `git stash show -p` (like `--invalid`) triggers a double-free memory corruption that aborts with a "free(): double free detected in tcache 2" error. The crash occurs in `show_stash()` when `strvec_clear()` tries to free memory that was already freed. Valgrind traces confirm the double-free occurs during option parsing failure handling.

The expected behavior would be for Git to show a usage error and exit cleanly when given unrecognized options, as most Git commands do. Instead, this triggers a low-level memory corruption crash. The bug appears in Git 2.51.0 and likely affects other recent versions.

The report includes detailed reproduction steps starting from a fresh repo, along with both GDB and Valgrind backtraces pinpointing the issue in the interaction between option parsing and the strvec cleanup in `builtin/stash.c`. This looks like a genuine memory safety bug that needs fixing, though the report doesn't include a proposed patch. The clear reproduction case and diagnostic output make this easy to verify and should help with developing a fix.
