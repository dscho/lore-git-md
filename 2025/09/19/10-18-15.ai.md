This is a bug report documenting a double-free crash in `git stash show -p` when given an invalid option. The issue occurs in `show_stash()` when `strvec_clear()` attempts to free memory that was already freed, leading to an abort with "free(): double free detected in tcache 2". Both GDB and Valgrind traces confirm the double-free occurs during cleanup after option parsing fails.

The bug is reproducible with a simple sequence: create a repo, make a stash, then run `git stash show -p --invalid`. Instead of cleanly reporting the invalid option, Git crashes. The backtrace shows the crash originates in `strvec_clear()` called from `show_stash()`, suggesting improper handling of the argument vector during error cleanup.

The report includes detailed debugging information (full backtraces, Valgrind output) and system details (Git 2.51.0 built from commit c44beea, glibc 2.42). The crash appears to be a clear memory management bug in the stash command's error path rather than a more subtle logic error. The reporter expects Git to handle invalid options gracefully with a usage message rather than crashing.

Key technical details for future reference: the crash occurs in `builtin/stash.c:1047` during `strvec_clear()` cleanup, involves the stash command's argument vector handling, and manifests when option parsing fails. The Valgrind output shows the problematic memory block was originally allocated via `strdup()` in the stash handling code.
