Test infrastructure patch for SHA-1/SHA-256 interoperability. This is the final patch in a 9-part series preparing Git's test suite for the upcoming hash function transition.

The patch introduces a new `COMPAT_HASH` test prerequisite that detects when tests are running in SHA-256 mode with SHA-1 compatibility requirements. It also modifies the existing `BROKEN_OBJECTS` prerequisite to be automatically disabled when `COMPAT_HASH` is active, since creating deliberately broken objects isn't possible in compatibility mode (where SHA-1 values must be maintained).

The change is small but important for the test suite's behavior - it ensures tests that try to create older pack formats (v1/v2) will be skipped when running in compatibility mode, since those formats don't support multiple hash algorithms. The implementation cleanly builds on the test infrastructure variables (`test_repo_compat_hash_algo`) introduced earlier in the series.

This completes the test preparation work for the hash transition, providing the last piece needed to properly skip incompatible tests when running with SHA-1 compatibility requirements. The patch follows the series' pattern of focused, well-explained changes to the test infrastructure.
