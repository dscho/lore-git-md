This is the 8th patch in a 9-part series preparing Git's test infrastructure for SHA-1/SHA-256 interoperability. It focuses on test suite enhancements to support testing repositories with both hash algorithms.

The patch introduces a new `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax to explicitly specify both the storage hash (SHA-256) and compatibility hash (SHA-1) for testing scenarios. It modifies test infrastructure to track these separately via new variables: `test_hash_algo` (storage), `test_compat_hash_algo` (per-test compatibility), and `test_repo_compat_hash_algo` (global compatibility). 

A key addition is the `BROKEN_OBJECTS` prerequisite that detects when deliberately broken objects can be created (disabled when compatibility hashes are in use since they can't map nonexistent objects). The changes touch test helper functions in `t/test-lib-functions.sh` and prerequisite definitions in `t/test-lib.sh`.

This builds on previous work in the series by enabling more precise testing of the hash transition scenarios, particularly around edge cases where SHA-1 compatibility is required. The patch maintains the series' careful approach of test infrastructure changes from core functionality, with clear separation between what's implemented now (`GIT_TEST_DEFAULT_HASH` parsing) and future work (actual `GIT_DEFAULT_HASH` support in Git itself).
