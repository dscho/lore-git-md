This is the final patch (10/10) in the v3 series of xdiff refactoring cleanups preparing for Rust integration. It introduces named constants (NO/YES/MAYBE) for the previously magic-numbered `rchg` array values in xdiff's diff algorithm implementation.

The patch standardizes the boolean-like `rchg` field (which marks changed lines) with explicit enum-style values, replacing direct 0/1/2 usage throughout xdiff's core files (xdiffi.c, xhistogram.c, xpatience.c, xprepare.c). The author notes this makes no behavioral change since MAYBE` was only ever used in temporary arrays before finalizing to YES/NO in `rchg`.

Key technical details:
- Adds `#define NO 0`, `YES 1`, `MAYBE 2` to xdiff.h
- Updates all direct numeric comparisons to use the named constants
- Maintains identical control flow and error handling
- Follows earlier standardization work from patch 9/10
- Touches core diff algorithms but preserves all existing behavior
- Files modified: xdiff/xdiff.h, xdiff/xdiffi.c, xdiff/xhistogram.c, xdiff/xpatience.c, xdiff/xprepare.c

The patch completes the preparatory cleanups for Rust integration by making the code's intent clearer through named constants, while keeping the changes minimal and behavior-preserving.
