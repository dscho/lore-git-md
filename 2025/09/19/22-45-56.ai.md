This is a bugfix patch addressing memory management issues in `setup_revisions()` when handling strvec arguments, part of a series fixing crashes in `git stash show` and related commands.

The patch focuses on fixing a double-free scenario that occurs when `setup_revisions()` processes invalid options while consuming arguments from a strvec. The core issue is that the function modifies the argv array by shifting unknown options to the front, which can lead to both memory leaks (when overwritten elements aren't freed) and double-frees (when strvec cleanup encounters consumed elements).

Jeff King introduces a new helper function `overwrite_argv()` that properly manages memory ownership during these shifts. The solution ensures that overwritten elements are freed (when needed) and NULLed out, while preserving the original elements that weren't consumed. This maintains strvec invariants and prevents both leaks and double-frees.

The patch includes a test case demonstrating that `git stash show -p --invalid` no longer crashes with a double-free. The implementation carefully handles edge cases where options are consumed versus moved, and maintains backward compatibility with existing callers. The changes are contained within revision.c, with minimal impact on the wider codebase.

This is the second patch in a 6-part series that started with fixing a specific `git stash` memory leak and is evolving into broader strvec safety improvements. The solution here builds on previous work from commit f92dbdbc6a but extends it to cover the movement of unknown options, not just "--" handling.
