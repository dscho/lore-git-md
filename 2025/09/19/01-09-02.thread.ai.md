SHA-1/SHA-256 interoperability series (17 patches) by brian m. carlson continues foundational work for hash algorithm compatibility, now in part 1 of several planned series targeting Git 3.0. This installment focuses on documentation improvements, test infrastructure groundwork, and new plumbing commands while expanding pack index v3 format specifications and loose object format documentation, with the latest patch adding GPG signature header handling in `fsck` and enhanced test infrastructure for compatibility hash scenarios.

Technical scope includes:
- Pack index v3 format documentation specifying 8-byte integers for offsets/lengths (supporting >67M objects) with Junio-approved clarification on object ID computation, updated to use pack order rather than shortened object ID order for offset table
- New `gitformat-loose.adoc` documenting loose object storage format (approved by Junio) covering file structure, object ID calculation, naming conventions, and SHA-1/SHA-256 distinctions
- Updated tag signature documentation matching Git 2.29+ behavior (current algorithm in-body, alternate in header)
- New `rev-parse --show-object-format=compat` plumbing command reporting configured compatibility hash (via `extensions.compatobjectformat`) or empty line when none exists
- Enhanced `fsck` validation for GPG signature headers (including continuation lines) with new error messages (`badGpgsig`, `badHeaderContinuation`) and strict validation of `gpgsig`/`gpgsig-sha256` headers
- Test infrastructure supporting `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax with thorough coverage of new `rev-parse` compat mode and expanded `t1450-fsck.sh` tests for signature header validation
- `COMPAT_HASH` and `BROKEN_OBJECTS` test prerequisites with confirmed compatibility mode behavior
- Modified `t1010-mktree.sh` now properly using `BROKEN_OBJECTS` prerequisite to skip broken object tests in compatibility mode, wrapping broken object creation (`git update-index --add --info-only`) in prerequisite check and explicitly marking `--missing` test with `BROKEN_OBJECTS`
- Pack format clarifications in `gitformat-pack.adoc` covering CRC32 checksums, packed/loose object encoding differences, and size field interpretation
- New test infrastructure parsing `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax to store both storage and compatibility hashes in `test_hash_algo`/`test_compat_hash_algo`
- Global compatibility mode tracking via `test_repo_compat_hash_algo`
- `COMPAT_HASH` prerequisite checking for active compatibility mode
- `BROKEN_OBJECTS` prerequisite skipping tests that create deliberately broken objects when in compatibility mode
- Backward compatibility maintained for existing `sha256`/`sha1` values
