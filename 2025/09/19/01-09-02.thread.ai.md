Part 3/9 provides crucial historical context for the tag signature header design, explaining the strict mutual exclusivity between `gpgsig` and `gpgsig-sha256` headers. This emerged from Git 2.29's accidental omission of SHA-256 signature support, leading to a backward-compatible solution where signatures move between body and headers during conversion. The only scenario allowing both headers would be future support for a third algorithm like SHA-3-512. This design is now documented in Git's official documentation.
