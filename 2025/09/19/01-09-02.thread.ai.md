SHA-1/SHA-256 interoperability series (15 patches) by brian m. carlson continues foundational work for hash algorithm compatibility, now with enhanced test infrastructure including new prerequisites for broken object handling in compatibility mode alongside prior GPG signature validation, pack format documentation, and loose object storage specifications. The series spans core functionality, documentation, and comprehensive test coverage.

Technical scope includes:
- Pack index v3 format documentation (updated per Junio C Hamano's review) specifying offset ordering by pack position rather than object ID, enabling direct indexing, with expanded 8-byte offset support for large repositories (>55M objects) and explicit hash length specifications (32 bytes for SHA-256, 20 for SHA-1), plus Junio's latest clarification on object ID computation from packed objects (reconstructing type/length prefix when needed)
- New `gitformat-loose.adoc` (approved by Junio in v2) documenting loose object storage format (`$GIT_DIR/objects/[0-9a-f][0-9a-f]/*`), object file structure (type/size prefix + zlib-compressed data), and object ID computation, with improved explanations of loose-to-packed lifecycle and sharding rationale
- Tag signature documentation updated to match Git 2.29+ behavior: current algorithm's signature in body, alternate algorithm's in header (`gpgsig` or `gpgsig-sha256`)
- `rev-parse --show-object-format=compat` plumbing command reporting configured compatibility hash (via `extensions.compatobjectformat`) with empty output when none exists
- Enhanced `fsck` validation for GPG signature headers in tags with new error messages (`FSCK_MSG_BAD_GPGSIG`, `FSCK_MSG_BAD_HEADER_CONTINUATION`) documented in `fsck-msgids.adoc`
- New test infrastructure supporting `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax for compatibility mode testing
- Two new test prerequisites: `COMPAT_HASH` (detects SHA-256 with SHA-1 compatibility mode) and `BROKEN_OBJECTS` (checks for ability to create malformed objects, now with explicit compatibility mode handling)
- Test infrastructure split into `test_compat_hash_algo` (per-test) and `test_repo_compat_hash_algo` (repository-wide) variables
- Modified `t1010-mktree.sh` to properly handle broken object tests in compatibility mode by wrapping test cases with `BROKEN_OBJECTS` prerequisite

Implementation details:
- Pack index v3 uses pack order for offset access, eliminating revindex need, with documentation now accurately reflecting 8-byte offset support, hash length specifications, and explicit object ID computation details (per Junio's latest suggestion)
- Loose object storage now fully documented with Junio-approved explanations of file structure, naming scheme, and lifecycle
- Trailer checksums use repository's primary algorithm at full length (SHA-1 repositories in SHA-256 compatibility mode still use SHA-1 for checksums)
- `BROKEN_OBJECTS` prerequisite for testing malformed objects in compatibility mode (now explicitly disabled in compatibility mode due to object mapping limitations)
- `COMPAT_HASH` prerequisite checks for `test_repo_compat_hash_algo` presence
- Tag signature handling matches shipped behavior since Git 2.29 with enhanced `fsck` validation
- `rev-parse --show-object-format=compat` uses `the_repository->compat_hash_algo` and outputs newline when unset
- `fsck` now validates both initial signature line and continuation lines with algorithm-agnostic rules
- Test infrastructure parses compatibility hash syntax and sets up prerequisites in `test-lib-functions.sh` and `test-lib.sh`
- `t1010-mktree.sh` broken object tests now properly conditional on `BROKEN_OBJECTS` prerequisite
