SHA-1/SHA-256 interoperability series (11 patches) by brian m. carlson continues foundational work for hash algorithm interoperability, now with additional pack format and loose object storage documentation. The series spans documentation updates (pack format, loose object storage, tag signatures), test infrastructure (`COMPAT_HASH`, `BROKEN_OBJECTS` prerequisites), and GPG signature validation in tags.

Technical scope includes:
- Pack index v3 format documentation specifying offset ordering by pack position rather than object ID, enabling direct indexing
- 8-byte offset support for large repositories (>55M objects) with MSB flag for secondary 8-byte table
- New `gitformat-loose.adoc` documenting loose object storage format (`$GIT_DIR/objects/[0-9a-f][0-9a-f]/*`), object file structure (type/size prefix + zlib-compressed data), and object ID computation
- Tag signature documentation updated to match Git 2.29+ behavior: current algorithm's signature in body, alternate algorithm's in header (`gpgsig` or `gpgsig-sha256`)
- `rev-parse --show-object-format=compat` plumbing command
- GPG signature validation for both signature types in tags
- Test infrastructure for compatibility mode (`COMPAT_HASH`, `BROKEN_OBJECTS`)

Documentation clarifications:
- CRC32 checksums cover entire packed object (header, base object name/offset, compressed data) using zlib algorithm
- Packed objects omit loose object-style "<type> <size>\0" prefix in compressed form (though still used for object ID computation)
- Size fields in packs always represent uncompressed sizes (raw objects or deltas), distinct from offset encoding
- Base object references excluded from size calculation
- Loose object examples showing empty tree and simple blob storage cases
