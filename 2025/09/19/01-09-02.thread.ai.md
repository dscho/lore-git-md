SHA-1/SHA-256 interoperability series part 1 (9 patches) by brian m. carlson completes its test infrastructure updates for Git's planned hash function transition in version 3.0. The final patch adds a `COMPAT_HASH` test prerequisite to handle cases where tests need different behavior under SHA-256 storage with SHA-1 compatibility mode, reworking the existing `BROKEN_OBJECTS` prerequisite to depend on it since deliberately invalid objects cannot be created in compatibility mode.

The series now includes all nine patches, with comprehensive documentation updates (pack file formats, tag signature handling, loose object storage) and test preparation with new infrastructure for dual-hash testing. Key additions are the `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax for specifying storage and compatibility hashes, test variables (`test_hash_algo`, `test_compat_hash_algo`, `test_repo_compat_hash_algo`), and fsck validation for both gpgsig/gpgsig-sha256 headers. Test coverage in t1450-fsck.sh and t1500-rev-parse.sh verifies behavior using test_oid_cache for SHA-1/SHA-256 differences.

Technical details include the loose object format specification in `gitformat-loose.adoc` and changes to `t/test-lib-functions.sh`, `t/test-lib.sh`, `Documentation/`, `builtin/rev-parse.c`, and core commands. The series focuses on non-controversial groundwork, separating documentation and test preparation from substantive interoperability implementation. Each patch remains logically independent while contributing to the overall goal of enabling precise testing of hash transition edge cases where SHA-1 compatibility is required, particularly around object existence validation. The final patch ensures tests that create invalid objects will automatically skip in compatibility mode, completing the test infrastructure portion.
