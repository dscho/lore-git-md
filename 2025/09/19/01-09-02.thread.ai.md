SHA-1/SHA-256 interoperability series part 1 (9 patches) by brian m. carlson focuses on documentation updates and test infrastructure preparation for Git's planned hash function transition in version 3.0. The series introduces non-controversial groundwork before more substantive changes in part 2.

Core changes include comprehensive documentation updates for pack file formats (v3 index) and tag signature handling, plus a new `gitformat-loose.adoc` describing loose object storage. Technical infrastructure adds `rev-parse --output-hash` for compatibility hash printing and updates fsck to expect proper GPG signature headers in tags. Test infrastructure gains `COMPATIBILITY_HASH` prerequisite and support for interoperability testing scenarios.

The series carefully avoids disruptive changes, focusing on documentation accuracy and test readiness for the larger hash transition. Future parts will build on this foundation with more substantive interoperability work, including potential Rust components. Key files touched include `Documentation/` (multiple format docs), `t/` (test infrastructure), and core commands (`rev-parse`, `fsck`). The author positions this as uncontroversial prerequisite work that can merge independently of the more complex interoperability implementation to follow.
