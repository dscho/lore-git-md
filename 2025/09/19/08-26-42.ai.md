This is a refactoring patch that converts `git pack-refs` to use the new `refs_optimize()` API as part of the ongoing ref storage optimization work. The change is minimal but significant - it replaces the backend-specific `refs_pack_refs()` call with the new generic `refs_optimize()` interface in builtin/pack-refs.c.

The patch builds on the established architectural framework where both files and reftable backends now implement the optimize operation (files via packing, reftable via compaction). The commit message explains that "optimize" is a more accurate term than "pack" since the operation behaves differently across backends while serving the same conceptual purpose of reference storage maintenance.

The implementation is straightforward - a one-line change that swaps the API call while maintaining all existing option handling and behavior. This maintains compatibility with existing `pack-refs` usage while aligning with the new backend-agnostic API design. The change paves the way for the new `git refs optimize` subcommand to share the same core logic.

This patch represents the final piece of converting the existing `pack-refs` command to use the new API, following the completion of both backend implementations (files and reftable) in earlier patches. The shared test infrastructure (t/pack-refs-tests.sh) ensures behavioral equivalence between the old and new implementations.
