This thread addresses a critical memory management issue in Git's revision parsing code, specifically around `setup_revisions()` and its interaction with strvecs. The problem first surfaced as a double-free crash in `git stash show -p` with invalid options, but deeper investigation revealed broader architectural concerns about strvec usage patterns across Git's codebase.

Jeff King (Peff) has led the technical response, introducing both immediate fixes and long-term architectural improvements. The solution involves two key components: an `overwrite_argv()` helper to safely manage memory during argument shifts, and a new `setup_revisions_from_strvec()` API that enforces proper memory management. The series has progressed through careful stages - first plugging the immediate memory leaks and double-free issues, then systematically converting callers to the safer API.

The latest patch (part 5 of 6) continues this conversion work, focusing on functions in pack-objects, rebase, sequencer, shallow handling, and upload-pack that receive argc/argv parameters originating from strvecs. While this makes the functions slightly less flexible (they can now only be called with strvec-backed arguments), the tradeoff is justified by the memory safety guarantees. The changes have been thoroughly tested across Git's command surface area and are expected to prevent similar issues in future development while maintaining backward compatibility.

The series is now nearing completion, with all major callers converted to the safer API. The changes demonstrate Git's approach to addressing both immediate bugs and underlying architectural concerns in a way that maintains stability while improving long-term maintainability.
