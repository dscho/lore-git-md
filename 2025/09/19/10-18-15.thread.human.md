This thread documents a serious double-free crash in `git stash show -p` when invalid arguments are passed, traced to memory management issues in `setup_revisions()`. The bug was introduced in commit 748bd094 and reported by Lauri Niskanen, with Kristoffer Haugsbakk identifying the regression. 

Junio Hamano's analysis revealed the root cause: `setup_revisions()` shifts arguments without NULL-terminating unused slots, causing `strvec_clear()` to encounter duplicates during cleanup. Jeff King expanded this to note broader strvec management issues affecting other commands. Three solution approaches emerged: a local fix for `stash`, modifying `setup_revisions()` itself, or creating a new wrapper API.

In the latest email, Jeff King confirms Junio's NULL-termination fix is correct despite initial concerns, suggesting a simpler alternative that only NULL-terminates at the new boundary. He notes this passes tests but reveals memory leaks under SANITIZE=leak, affecting multiple test cases. The discussion now focuses on balancing minimal fixes versus comprehensive solutions, considering leak detection impacts and the need to properly handle the free_removed_argv_elements flag. Jeff is preparing alternative patches to address these issues while maintaining robust memory management across Git's revision parsing infrastructure.
