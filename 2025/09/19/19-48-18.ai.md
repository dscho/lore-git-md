Build system patch addressing Rust linking issues with libgit.a.

This is a follow-up to Eric Sunshine's review pointing out the missing motivation in the original patch. The author explains that adding `-fPIE` to the Makefile is necessary to resolve linking errors when the Rust compiler tries to use libgit.a. The error message indicates position-independent executable (PIE) compatibility issues on x86_64 systems, specifically relocation problems with `.rodata` sections. 

The Meson build system already handles this case correctly without modification, but the Makefile-based build requires explicit `-fPIE` flags. This patch is part of the larger Rust integration effort where libgit.a needs to be consumable by Rust code. The author acknowledges the commit message should have included this rationale originally.

The technical details involve:
- Makefile modification to add `-fPIE` compiler flag
- x86_64 relocation errors (R_X86_64_32 against `.rodata`)
- Build system divergence between Meson (working) and Makefile (needing fixes)
- Context of Rust compiler linking against libgit.a

This appears to be a straightforward technical solution to a concrete build problem, though it highlights the ongoing Rust integration work's need to maintain compatibility across both build systems. The patch now has proper motivation documented in the thread, addressing the original review feedback.
