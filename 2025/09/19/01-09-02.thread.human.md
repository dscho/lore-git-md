This thread introduces a foundational series preparing Git for SHA-1/SHA-256 interoperability, a key step toward Git 3.0's planned hash function transition. The initial 9-patch set focuses on documentation improvements and test infrastructure, deliberately avoiding controversial changes to establish common ground first.

The series makes two main contributions: comprehensive documentation updates (including a new `gitformat-loose.adoc` for object storage details) and enhanced test infrastructure for compatibility testing. Technical changes include `rev-parse` gaining hash compatibility support and fsck becoming stricter about GPG signature headers in tags. The author emphasizes this is preparatory work, with more substantive interoperability changes - including potential Rust components - planned for part 2.

The changes appear carefully scoped to touch core areas (pack files, object storage) while maintaining backward compatibility. Documentation improvements address long-standing inaccuracies, and the new test prerequisites (`COMPATIBILITY_HASH`) will support future interoperability validation. The series sets up critical infrastructure for the larger hash transition while minimizing disruption to current behavior.
