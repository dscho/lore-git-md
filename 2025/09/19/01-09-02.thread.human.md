This thread documents the preparatory work for Git's upcoming SHA-1/SHA-256 interoperability features, focusing on test infrastructure updates needed for version 3.0. brian m. carlson has led this effort with a nine-patch series that carefully separates non-controversial groundwork from the more complex interoperability implementation.

The series establishes comprehensive test support for repositories using both hash algorithms, introducing key infrastructure like `GIT_TEST_DEFAULT_HASH="sha256:sha1"` to specify storage and compatibility hashes separately. Recent additions refined the test prerequisites system, with the final patch adding a `COMPAT_HASH` marker and adjusting the `BROKEN_OBJECTS` prerequisite to automatically skip invalid-object tests when in compatibility mode. This completes the test preparation portion of the work.

The changes span documentation updates (particularly around pack formats and signature handling), core command modifications (like `rev-parse`'s hash display), and extensive test coverage in t1450-fsck.sh and t1500-rev-parse.sh. The work remains focused on uncontroversial foundation layers that can merge independently, leaving the more complex interoperability implementation for future series. With this final test prerequisite patch, the infrastructure is now in place to properly validate the hash transition when those subsequent changes arrive.
