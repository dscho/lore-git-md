This is the foundational patch in a 9-part series introducing a new ref optimization API, part of the effort to create a backend-agnostic way to optimize reference storage. The patch establishes the core `refs_optimize()` function in the refs API, which will dispatch to backend-specific implementations (files and reftable) through a new vtable method.

The change introduces three key components: the public `refs_optimize()` declaration in refs.h, its implementation in refs.c that delegates to backends, and the new `optimize_fn` callback in the ref_storage_be vtable. The commit explains that while `pack-refs` is files-backend-specific in name, its behavior is actually generic (like triggering reftable compaction), making the current naming confusing.

The patch maintains the existing `pack_refs_opts` structure for compatibility while introducing the more accurately named `optimize` terminology. This is the architectural foundation for the rest of the series, which will implement the backend-specific versions and eventually expose this via a new `git refs optimize` subcommand. The implementation follows Git's standard patterns for refs API additions, with appropriate documentation in the header about backend-specific behavior.
