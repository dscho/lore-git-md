The RFC discussion about making Rust mandatory in Git has expanded from its initial focus on platform compatibility to now include significant concerns from Linux distribution maintainers. The thread began with objections about compiler support gaps on platforms like NonStop and PowerPC variants, with contributors like Collin Funk and Florian Märkl highlighting active use cases on these systems. Michael Orlitzky then raised concerns about how Rust's dependency churn creates packaging instability, forcing distributions to bundle outdated crates.

Sam James from Gentoo has now reinforced these package management concerns, emphasizing that while Gentoo can technically support Rust, the maintenance burden undermines core Linux distribution principles. The discussion has evolved to show that the issue isn't just technical feasibility, but a fundamental conflict between Rust's ecosystem model and the system-wide dependency management that distributions rely on. With Git being a critical infrastructure component, these packaging concerns carry significant weight alongside the original platform compatibility objections. The core tension remains between Rust advocates prioritizing memory safety and opponents citing broader ecosystem impacts, with no clear resolution yet in sight.
