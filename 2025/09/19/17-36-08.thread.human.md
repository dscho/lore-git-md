This RFC thread continues to explore the implications of introducing Rust into Git, with the discussion now focusing on dependency management concerns. The thread began with platform-specific objections from Gentoo maintainers, highlighting compatibility issues on NonStop, PowerPC Mac OS X, and OpenBSD/macppc systems, along with broader distribution packaging impacts.

Patrick Steinhardt has now weighed in, reinforcing brian m. carlson's position about conservative Rust crate usage. He agrees that Git should minimize external dependencies when introducing Rust, citing supply chain security risks, vulnerability surface expansion, potential version conflicts, and knowledge externalization as key concerns. Steinhardt references an existing draft policy that already advocates for dependency caution, suggesting this will be formalized after Rust integration.

While the core tension remains between Rust's safety advantages and its ecosystem impact on packaging stability, the discussion appears to be shifting toward policy refinement. Platform-specific objections from Gentoo (particularly regarding riscv/musl support) and Ezekiel Newren's request for constraints remain open issues, but the thread is now converging on implementation constraints rather than fundamental objections to Rust adoption. The emerging consensus suggests Git would adopt Rust with strict limitations on third-party crate usage, maintaining the project's historical minimal-dependency philosophy.
