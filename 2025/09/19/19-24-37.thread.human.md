The thread discusses user feedback about the deprecation of `git whatchanged` in Git 2.51.0, which now requires a `--i-still-use-this` flag. James Puleo reported that this command remains useful for tracking file changes, particularly for finding which ref last contained a deleted file, and questioned whether the deprecation creates unnecessary friction for a simple, functional tool. 

Kristoffer Haugsbakk confirmed the deprecation is intentional, as the functionality is fully covered by `git log` variants like `git log --raw --no-merges`, and provided specific alternatives for different use cases. Ben Knoble later contributed a simpler suggestion for James's specific need: using `git log -- path/to/deleted/file` (or `git rev-list`) to locate the last ref containing a deleted file, offering a more minimal alternative to Kristoffer's earlier `git log --name-status --diff-filter=D` suggestion.

While the thread has now documented clear migration paths from `git whatchanged` to `git log` alternatives, the broader question of whether the deprecation warning's friction is justified remains unresolved. The discussion has stayed technical, with maintainers providing solutions but not addressing the usability concerns raised by the original reporter.
