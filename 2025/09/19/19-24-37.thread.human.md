James Puleo started this thread by questioning the deprecation of `git whatchanged` in Git 2.51.0, noting its continued usefulness for tracking file changes - particularly for finding which ref last contained a deleted file. While the command has been deprecated since 2020 with users directed to `git log --name-status`, James found the new requirement to use `--i-still-use-this` created unnecessary friction for his workflow.

Kristoffer Haugsbakk responded, confirming the deprecation path while offering specific `git log` alternatives to replicate the functionality. He recommended `git log --raw --no-merges` as a direct replacement for the file-change listing behavior, noting that `git log` actually provides more flexible output options like `--stat` or `--name-only`. The response positioned this as part of Git's broader interface simplification efforts where redundant commands are being phased out in favor of more versatile alternatives.

While Kristoffer provided clear technical migration paths, the thread remains open on the usability question - whether the deprecation warning's friction is justified given that some users still find `whatchanged` simpler for certain workflows. No maintainers have yet weighed in on whether the deprecation timeline or warning mechanism might be adjusted in response to this real-world usage feedback.
