This is a review comment on patch 7/9 in the SHA-1/SHA-256 interoperability series. Junio Hamano provides feedback on the fsck changes for handling GPG signature headers in tag objects.

The patch adds validation for `gpgsig` and `gpgsig-sha256` headers in tags, ensuring they have proper continuation lines and don't malform the object. Junio suggests wrapping a long line for better readability and raises an important design question about whether tags should be allowed to contain both signature types simultaneously.

Junio proposes future-proofing considerations - suggesting the validation should enforce that header signatures must be unique (not including the primary hash algorithm) and must correspond to an inline signature in the body. This maintains consistency with how the system might expand to support additional hash algorithms later.

The feedback continues the series' pattern of careful technical review, now focusing on the signature validation aspects of the interoperability work. While the core functionality appears sound, Junio is ensuring the design remains clean and extensible.
