This is a documentation patch that's part of a larger series (2/9) about pack index format changes, specifically addressing version 3. The patch updates the technical documentation to reflect a proposed change in how offsets are stored in the pack index.

The key change involves reordering the offset table to use pack order rather than shortened object ID order. This modification aims to improve efficiency by allowing direct lookup of pack offsets once the pack order index is known, eliminating the need for intermediate lookups through object IDs. The patch notes this will make many operations more efficient and removes the need for the revindex with pack index v3.

The documentation update removes text describing the old offset lookup method (using sorted shortened object names) and replaces it with text explaining the new pack-order-based approach. The technical details about 31-bit offsets and large offset handling remain unchanged, just recontextualized for the new ordering scheme.

This appears to be a well-motivated change that aligns with existing packfile code expectations and should improve performance by reducing lookup steps and improving cache usage. The patch is focused and clearly explains both the problem and solution in the commit message.
