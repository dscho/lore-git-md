Final patch in strvec memory management series, completing NULL termination enforcement in `setup_revisions()`. This email contains Jeff King's proposed follow-up refinement to the just-merged patch 6/6, which addressed NULL termination at the boundary of consumed arguments. The new suggestion would extend the cleanup to all arguments beyond the revised argc, not just the boundary case.

The key technical aspects are:
1. Modifies the `--` handling to free and NULL all arguments after the dash-dash (not just the dash-dash itself)
2. Changes the final NULL termination loop to walk backwards from argc to left (rather than just handling left)
3. Simplifies `setup_revisions_from_strvec()` by removing its explicit cleanup loop since the core function now handles it
4. Maintains the same memory safety guarantees while being more thorough

The patch appears to be a logical extension of the series' goals, though Jeff King expresses uncertainty about whether the additional complexity is worthwhile given that the current solution already prevents memory issues. The change would provide more complete cleanup of the strvec's memory while still preserving the invariants established in the series.
