This is the foundational patch in a series introducing a new ref optimization API, part of the effort to create a backend-agnostic way to optimize reference storage. The patch adds a new `refs_optimize()` function that provides a generic interface for reference backends to implement their own optimization logic, replacing the files-backend-specific `pack_refs` terminology.

The change introduces three key pieces:
1. A new `optimize_fn` vtable method in the refs backend interface
2. The public `refs_optimize()` API function that dispatches to backends
3. Documentation noting this is equivalent to packing for the files backend

The patch sets up the architectural framework that subsequent patches will build upon to implement the actual optimization behavior in both files and reftable backends. It's a clean, focused change that follows Git's established patterns for backend APIs. The commit message clearly explains the motivation (confusing terminology with reftable) and the approach (generic API with backend-specific implementations). This looks like a solid foundation for the rest of the series.
