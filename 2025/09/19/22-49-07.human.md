This is part 4 of a 6-part series addressing strvec memory management issues in Git's revision parsing code. The patch converts several remaining callers to use the new `setup_revisions_from_strvec()` wrapper API introduced in the previous patch.

The change updates three commands (`describe`, `http-push`, and submodule handling) to use the safer interface when parsing revisions with strvec arguments. While these particular call sites weren't known to trigger the memory management bugs (since they don't perform the problematic argument shuffling), the conversion future-proofs them against potential issues if `setup_revisions()` becomes more aggressive about argument manipulation.

The patch is straightforward, with minimal changes to each caller - mostly just swapping the direct `setup_revisions()` call for the new wrapper. The series as a whole shows careful attention to both fixing immediate bugs and preventing similar issues in the future, with Jeff King systematically working through affected code paths. This middle patch in the series represents the transition from core fixes to broader adoption of the safer API.
