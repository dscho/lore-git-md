This is a build system and documentation patch addressing how deprecated Git programs are handled when `WITH_BREAKING_CHANGES` is enabled. Junio C. Hamano points out that while the build system has infrastructure to exclude deprecated commands from documentation via `EXCLUDED_PROGRAMS`, it's not being properly utilized for commands like `git-whatchanged` and `git-pack-redundant` when they are marked as breaking changes.

The patch proposes two main changes: First, it adds these deprecated commands to `EXCLUDED_PROGRAMS` when `WITH_BREAKING_CHANGES` is set, ensuring they appear in neither the build nor documentation. Second, it makes the `check-docs` target depend on `Documentation/GIT-EXCLUDED-PROGRAMS` to ensure documentation linting respects these exclusions.

The change appears straightforward and well-motivated, cleaning up a minor inconsistency in how deprecated commands are handled. The RFC nature suggests Junio is looking for feedback on whether this is the right approach before finalizing the change. The patch touches build system logic but doesn't introduce any user-facing changes - it just makes the internal handling of deprecated commands more consistent.
