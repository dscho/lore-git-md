This is part 3 of a 6-part series addressing strvec memory management issues in `setup_revisions()`. The patch introduces a new wrapper API `setup_revisions_from_strvec()` to safely handle strvec arguments when setting up revision walks.

The core problem is that `setup_revisions()` was designed for OS-provided argc/argv pairs, but is often called with strvec-constructed arguments. This creates two hazards: (1) potential leaks when options are reshuffled unless `free_removed_argv_elements` is set, and (2) inconsistent strvec state after calls where `.nr` doesn't match the actual retained arguments. While no active bugs exist from (2), the current behavior is fragile.

The new wrapper function automatically sets `free_removed_argv_elements` and properly shrinks the strvec to only contain retained arguments, freeing any consumed elements immediately. This makes the API safer and more intuitive for callers while maintaining backward compatibility. The patch converts several existing callers (in bisect, stash, submodule, and remote code) to use the new wrapper, with no functional changes expected for these cases.

Key technical details:
- New function `setup_revisions_from_strvec()` in revision.c handles both memory management concerns
- Takes optional `setup_revision_opt` struct but always forces `free_removed_argv_elements`
- Properly updates strvec's `.nr` and frees consumed elements
- Touches 6 files with 27 lines added and 19 removed
- Part of broader effort to make strvec usage in revision parsing more robust
- Builds on earlier fixes for specific crash cases while providing architectural improvement

The change is well-contained and maintains existing behavior while removing subtle pitfalls in the API. It represents a step toward potentially changing `setup_revisions()` itself to handle memory management more cleanly in the future.
