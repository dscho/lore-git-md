This is the 8th patch in a 9-part series preparing Git's test infrastructure for SHA-1/SHA-256 interoperability. The patch focuses on test suite enhancements to support testing repositories with both hash algorithms.

The change allows specifying a compatibility hash via `GIT_TEST_DEFAULT_HASH="sha256:sha1"` to test scenarios where a SHA-256 repository has SHA-1 compatibility enabled. The patch introduces logic to parse this format, storing both the storage hash (SHA-256) and compatibility hash (SHA-1) in separate test variables. It also adds a new `BROKEN_OBJECTS` prerequisite to skip tests that create deliberately broken objects when running in compatibility mode, since these tests wouldn't work without proper object rewriting support.

The changes are limited to test infrastructure (`t/test-lib-functions.sh` and `t/test-lib.sh`) and maintain the series' focus on non-controversial groundwork. The patch is well-contained and follows the established pattern of the series, though it notes that full Git support for the dual-hash format will come in a future commit. This appears to be another solid step in the hash transition preparation, specifically addressing test suite needs for interoperability scenarios.
