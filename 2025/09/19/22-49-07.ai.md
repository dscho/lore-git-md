This is part 4 of a 6-part series addressing strvec memory management issues in `setup_revisions()`. The patch converts three remaining call sites to use the new `setup_revisions_from_strvec()` wrapper API introduced in the previous patch.

The changes affect `builtin/describe.c`, `http-push.c`, and `submodule.c`, replacing direct `setup_revisions()` calls with the safer wrapper. As Jeff King notes, these particular conversions are more about future-proofing than fixing current bugs, since these callers weren't triggering the problematic argument re-shuffling that could lead to memory issues. The wrapper ensures consistent memory management by properly handling the `free_removed_argv_elements` flag and maintaining strvec invariants.

The patch is straightforward mechanical conversion work, with each change following the same pattern: replacing the direct call while keeping the surrounding logic intact. The `describe_blob()` case includes an additional check for argument count that needed adjustment to use the strvec's `.nr` directly rather than the setup_revisions() return value.

This continues the series' progression from immediate bug resolution to broader architectural improvements, systematically eliminating potential footguns in revision parsing while maintaining backward compatibility. The changes are minimal but meaningful, touching core commands (describe, push) and submodule handling.
