This is the final patch in a series addressing strvec memory management issues in `setup_revisions()`. The patch focuses on maintaining the NULL-termination invariant in argv arrays after option parsing.

Jeff King fixes a subtle but important invariant violation where `setup_revisions()` would shrink the argc count when consuming options but not NULL-terminate the resulting argv array. While not causing any known bugs (since callers already work around this), it's a potential footgun for future development. The change ensures argv[argc] is properly NULL-terminated after option parsing, with careful handling of the `free_removed_argv_elements` flag to avoid leaks.

The patch is a straightforward 6-line addition to `revision.c` that:
1. Checks if argv exists (protecting against NULL inputs)
2. Frees the element at the new argc position if requested
3. Sets argv[argc] to NULL

This completes the series' architectural improvements to strvec handling in revision parsing, following earlier patches that introduced safer APIs and converted callers. The change is low-risk but important for long-term code health, maintaining consistency with C convention while preserving all existing behavior.
