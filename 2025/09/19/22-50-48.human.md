This is the fifth patch in a series addressing strvec memory management issues in `setup_revisions()`. The patch converts remaining functions that receive argc/argv parameters (but ultimately come from strvecs) to use the new `setup_revisions_from_strvec()` API introduced earlier in the series.

The changes affect several key areas: pack-objects, rebase, sequencer, shallow commit handling, and upload-pack. Each modified function now takes a strvec directly rather than argc/argv pairs, ensuring proper memory management when these arguments are passed to `setup_revisions()`. While this makes the functions slightly less flexible (they can no longer be called with stack-allocated argv arrays), the tradeoff is worthwhile since all current callers use heap-allocated strvecs anyway.

Jeff King notes this change enforces type safety - the strvec type guarantees heap allocation, preventing potential misuse of the `free_removed_argv_elements` option with stack arrays. The patch is mechanical in nature, systematically applying the safer API pattern across the codebase following the architectural improvements made in earlier patches.

This continues the series' progression from immediate bug fixes to broader architectural improvements, now completing the conversion of all strvec-based callers to the safer API. The changes are low-risk since each modified function has only one caller that already uses strvecs.
