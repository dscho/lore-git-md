This is part 5 of a 6-part series converting Git's codebase to use the safer `setup_revisions_from_strvec()` API for revision parsing. The patch focuses on functions that receive argc/argv parameters that ultimately come from a strvec, converting them to take the strvec directly. This ensures memory safety by maintaining the strvec invariants throughout the call chain.

The changes affect several key areas: pack-objects, rebase, sequencer, shallow handling, and upload-pack. Each modified function now takes a strvec parameter instead of argc/argv, passing it through to `setup_revisions_from_strvec()`. While this makes the functions slightly less flexible (they can now only be called with strvec-backed arguments), the tradeoff is justified by the memory safety guarantees. The patch notes that all affected functions have only one caller anyway, so the reduced flexibility isn't a practical concern.

- Updates to `get_object_list()` in pack-objects.c
- Changes to rebase's interaction with the sequencer
- Modification of `sequencer_make_script()`'s signature and implementation
- Conversion of shallow commit handling functions
- Updates to upload-pack's deepen functionality
