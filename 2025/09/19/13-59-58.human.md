This is a discussion about the Rust transition documentation in the BreakingChanges file, part of the ongoing Rust infrastructure series. Phillip Wood raises two main points about Patrick Steinhardt's proposed text announcing Rust becoming mandatory in Git 3.0.

First, Wood questions the phrasing about "due diligence," suggesting the purpose is actually to give platforms advance warning to either adopt Rust or plan for LTS maintenance, rather than further evaluation. Second, he suggests improving user experience by having the build systems automatically display the Rust enablement commands when compilation fails due to missing Rust in the 2.53 phase.

Wood also references an earlier concern from Junio Hamano about the LTS maintenance handoff process, noting the maintainer had suggested distributors would coordinate via the security list and manage their own LTS branch pushes rather than having the Git maintainer pull in their backports.

The exchange shows active refinement of both the technical transition plan and its documentation, with Wood providing constructive feedback to make the messaging clearer and the user experience smoother during the phased Rust adoption. This patch appears to be progressing toward consensus, with the discussion focused on polishing details rather than fundamental objections.
