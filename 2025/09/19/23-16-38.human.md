Documentation refinement in the SHA-1/SHA-256 interoperability series. Junio C Hamano provides detailed feedback on brian m. carlson's patch adding documentation for Git's loose object format. This is part 5 of 9-patch series establishing infrastructure for hash algorithm interoperability.

Junio suggests several wording improvements to increase precision: clarifying that most repositories start with packfiles rather than loose objects, using "object name" instead of "object ID" to match glossary terminology, and being explicit about hashing the entire uncompressed contents (prefix + data) in hexadecimal. He approves the core explanation of the loose object format (type/size prefix + zlib-compressed data) but wants to ensure readers won't misinterpret which parts are hashed.

The review continues the pattern of careful documentation scrutiny seen throughout this series, with all feedback focused on technical accuracy and clarity rather than substantive objections. These refinements will likely be incorporated in the next revision as the series progresses toward Git 3.0.
