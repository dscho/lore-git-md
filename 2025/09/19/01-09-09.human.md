This is part 7 of a 9-part series preparing Git for SHA-1/SHA-256 interoperability, focusing on a bugfix for tag signature validation in `git fsck`. The patch ensures proper handling of GPG signature headers (`gpgsig` and `gpgsig-sha256`) in tags, which previously could trigger false positives in strict checking modes.

The change makes `git fsck` properly validate the structure of signature headers in tags, adding specific error messages for malformed signatures and documentation for the new error types (`badGpgsig` and `badHeaderContinuation`). The implementation includes thorough test coverage that verifies both valid signature header formats and rejection of malformed ones.

This appears to be a well-justified change that addresses a real inconsistency in Git's object validation. The patch is carefully implemented with documentation updates and comprehensive tests, maintaining the series' pattern of focusing on non-controversial groundwork for the hash transition. As with previous patches in the series, this change could likely be merged independently of the larger interoperability work.
