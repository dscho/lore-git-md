This email continues the discussion about the `git stash show` double-free issue, focusing on broader implications for `setup_revisions()` usage across Git. Junio Hamano and Jeff King identify additional memory leaks when `-p` arguments are rearranged, revealing systemic problems in how `setup_revisions()` handles strvec cleanup.

- Current behavior leaks memory when rearranging arguments (e.g., `git stash show -p --`)
- Discussion shifts toward creating a `setup_revisions()` wrapper that would:
  - Automatically enable `free_removed_argv_elements`
  - Correct the strvec's `.nr` field
  - Maintain NULL termination of the array
- Junio confirms his earlier "alternative" patch only addressed the NULL termination aspect

The conversation reveals the issue affects more commands than just `stash`, with `setup_revisions()`'s current behavior violating strvec invariants in multiple ways. Test suite gaps are noted, as current leak checking doesn't catch these rearranged-argument cases.
