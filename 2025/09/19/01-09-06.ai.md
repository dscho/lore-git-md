This is a documentation patch in a 9-part series (position 4/9) that clarifies ambiguous aspects of Git's pack file format. The patch focuses on three specific areas where the existing documentation was unclear or missing important details.

The changes specify exactly what data is covered by CRC32 checksums in pack files (the entire packed object including headers and compressed data) and notes that Git uses zlib's specific CRC32 algorithm. It also clarifies that packed objects don't store the type/size prefix that loose objects do, though this prefix is still used in object ID computation. Finally, it documents that size fields in pack files always represent uncompressed sizes - for undeltified objects this means the full object size, while for deltas it's the size of the delta data itself.

The patch is well-motivated by the need to help both Git contributors and alternative implementation authors understand these subtle format details. The changes are focused and technical, adding clear explanations without altering any actual behavior. The commit message thoroughly explains each change and its rationale.
