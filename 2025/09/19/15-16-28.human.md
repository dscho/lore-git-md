Refactoring patch in the xdiff series preparing for Rust compatibility. This is patch 6/10 in the preparatory cleanup series (v3) that's being merged to 'next', with Rust-specific changes deferred to a follow-up.

The change removes the redundant `xdfile_t.ha` array from xdiff's internal data structures, since its contents can always be derived from `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. The patch introduces a `get_hash()` helper function to access this derived value and updates all call sites. 

Ezekiel Newren notes this change makes the code about 5% slower, but explains that keeping the redundant array would complicate future cleanups. The commit message indicates this is part of a larger effort to simplify xdiff internals before introducing Rust-specific struct for classic diff algorithms. 

The change touches core diff comparison logic in xdiffi.c and preparation code in xprepare.c, removing array allocations and simplifying record cleanup. While this particular change has a performance cost, the overall series includes other optimizations (like patch 8's contiguous array change) that provide net performance improvements.

This continues the pattern of the preparatory series - making independent, behavior-preserving simplifications to xdiff internals while maintaining separation from the type system changes needed for Rust compatibility.
