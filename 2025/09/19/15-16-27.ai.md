This is a refactoring patch in the xdiff preparation series for Rust compatibility, specifically removing the redundant `diffdata_t` wrapper struct.

The patch eliminates the `diffdata_t` struct which was simply aliasing fields from `xdfile_t` (`nrec`->`nreff`, `ha`->`ha`, `rindex`->`rindex`, `rchg`->`rchg`). The main changes are:

1. Updates `xdl_recs_cmp()` to take `xdfile_t` pointers directly instead of `diffdata_t` pointers
2. Removes temporary `diffdata_t` structs from `xdl_do_diff()` and passes `xdf1/xdf2` directly
3. Deletes the `diffdata_t` struct definition from xdiffi.h

The changes simplify the code by removing an unnecessary abstraction layer while maintaining identical behavior. This continues the series' pattern of cleaning up xdiff internals to make them more straightforward before potential Rust integration. The patch follows the established approach of the series by being a pure refactoring with no behavior change.

Key technical points:
- Files modified: xdiff/xdiffi.c, xdiff/xdiffi.h
- Removed struct: `diffdata_t` (previously containing `nrec`, `ha`, `rindex`, `rchg`)
- Updated function signature: `xdl_recs_cmp()` now takes `xdfile_t*` instead of `diffdata_t*`
- Simplifies `xdl_do_diff()` by removing temporary struct setup code

This change is part of the preparatory cleanups (patches 1-10) that have already been approved for merging to 'next', with the Rust-specific changes deferred to a follow-up series. The patch maintains the series' focus on behavior-preserving simplifications of xdiff internals.
