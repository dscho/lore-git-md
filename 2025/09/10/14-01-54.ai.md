This is a code review comment on a preparatory patch in Patrick Steinhardt's `git-history` RFC series, specifically addressing sequencer infrastructure changes. Phillip Wood suggests a simplification to the `skip_commit_summary` option introduced in v3 patch 01/18.

The patch adds a new `skip_commit_summary` flag to `struct replay_opts` that controls whether `print_commit_summary()` is called after certain operations. Currently it checks both the new flag and `!is_rebase_i(opts)`. Phillip proposes making rebase set this flag directly and removing the `is_rebase_i()` check, which would make the logic more straightforward. The flag is already properly integrated with the sequencer's config handling, including serialization via `save_opts()`.

This is a small but meaningful refinement to the preparatory work that underpins the history editing commands. Phillip's suggestion would slightly simplify the control flow while maintaining the same behavior, as rebase is the primary case where commit summaries are currently suppressed. The change would affect the sequencer's behavior for both existing commands and the new `git-history` operations being introduced.
