This is a bugfix patch addressing a regression in the `git subtree` contrib command. The patch fixes an issue where squashed merges of nested subtrees (like `subA/subB`) were being incorrectly ignored during split operations when using `--prefix=subA/`. The regression was introduced in Git v2.44.0-rc0.

The fix rewrites the `should_ignore_subtree_split_commit()` function to use a single `git show` call with trailer parsing instead of multiple `git log` calls, while maintaining all the original logic for determining which commits to ignore. The patch includes comprehensive new test coverage that verifies the fix works for both regular and squashed merges of nested subtrees.

This is the third version of the patch (v3) and incorporates all feedback from Phillip Wood and Junio Hamano, including stylistic improvements and more precise shell variable handling. The patch is now considered ready for inclusion and is targeted for maint-2.44 and later versions.

The changes are focused on `contrib/subtree/git-subtree.sh` and its test file, with the main improvements being:
- More efficient commit examination using `git show` instead of multiple `git log` calls
- New test helper function `test_create_subtree_add` for easier test construction
- Expanded test coverage for nested subtree scenarios
- Better shell script style and variable handling

The patch appears well-crafted with thorough test coverage and has gone through multiple rounds of review, suggesting it's ready for merging.
