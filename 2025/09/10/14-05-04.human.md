Feature implementation in the `git-history` series, specifically adding a "reword" subcommand. This is part of Patrick Steinhardt's ongoing RFC v3 series proposing a new `git-history` command with various history editing capabilities.

Phillip Wood provides a concise but important review note, pointing out that the implementation could be simplified by reusing existing sequencer functionality rather than reimplementing the reword logic. The current patch adds 104 lines of new code in `builtin/history.c` plus extensive tests, when the same behavior could likely be achieved through the sequencer's existing reword capabilities.

The implementation as shown allows rewriting commit messages either via `-m` flag or interactively through an editor, with tests covering various scenarios: working with branch tips/middle/root commits, handling worktree/index changes, merge commit rejection, hook execution, and empty message validation. Phillip's suggestion implies this functionality could be more maintainable if integrated with Git's existing infrastructure rather than implemented separately.

This continues the pattern seen in earlier reviews where Phillip has been suggesting ways to better integrate the new `git-history` functionality with Git's existing codebase. The suggestion is particularly relevant given that the sequencer already handles similar functionality for `rebase -i`.
