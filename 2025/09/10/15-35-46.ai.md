This is the cover letter for v4 of Patrick Steinhardt's series introducing Rust infrastructure to Git core, now expanded to 9 patches. The series represents a major architectural shift, proposing Rust from an optional test balloon to a mandatory component by Git 3.0.

Key technical changes in v4:
- The varint subsystem conversion now uses explicit integer widths (u8/usize) in both C and Rust, avoiding direct C type dependencies in Rust code
- Meson build system unconditionally uses Cargo with a wrapper script to avoid unstable `--out-dir` flag
- Accelerated timeline removes intermediate step tying Rust to `-Dbreaking_changes`, making Rust default-enabled sooner
- Added Cargo.lock to .gitignore and fixed CI dependencies to install cargo rather than rustc

The series continues to use varint.c conversion as a test case while establishing core infrastructure. Notable open questions from discussion include:
- Type safety at Rust/C boundaries (addressed here via explicit integer widths)
- Build system conflicts between Meson and Cargo (now favoring Cargo-first approach)
- Windows platform support timeline (acknowledged as outstanding work)
- Coordination with parallel SHA-1/SHA-256 interoperability work

Steinhardt positions this as a consensus-building effort, adapting the proposal based on feedback while maintaining the trajectory toward mandatory Rust. The technical implementation appears thorough, with test coverage for overflow behavior and CI integration. The accelerated timeline reflects responsiveness to concerns about prolonged transition periods.
