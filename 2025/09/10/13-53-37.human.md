This is a discussion about the planned removal of `git whatchanged`, focusing on practical alternatives for current users. Kristoffer Haugsbakk responds to Chirayu Desai's use case for `git whatchanged -1` to quickly view changed files in a commit.

The email provides specific replacement commands: `git log --no-merges --raw` for general `whatchanged` use and `git show --raw` for the single-commit case. It notes minor output differences with empty commits and suggests these alternatives produce similar output, though personally prefers `git show --stat` for better readability.

Kristoffer acknowledges the muscle memory aspect but explains that while users can't alias the exact `whatchanged` command (due to core command restrictions), they could create a similar alias like `watchanged`. The tone is helpful and solution-oriented, focusing on easing the transition rather than debating the removal itself.

The exchange shows the community's thoughtful approach to deprecation - not just removing functionality but ensuring users have clear migration paths. This follows Git's tradition of maintaining backward compatibility where practical while still modernizing the codebase.
