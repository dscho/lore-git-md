This is a completed 4-patch series that implements the switch of Git's default initial branch name from "master" to "main" when built with the WITH_BREAKING_CHANGES flag enabled. The change follows through on a deprecation warning that's been in place since 2020 (commit 675704c74dd).

The series has already been merged with all technical questions resolved, and this version includes minor post-merge refinements:
- Patch 1 rewrites documentation to clarify the change only affects new repositories
- Patch 3 fixes a typo in its commit message
- Patch 4 adds a helper function for initializing test repositories with "master" where needed

The bulk of the changes are mechanical test updates (particularly in t4013) to use "main" instead of "master" as the default branch name. Phillip Wood notes they're still undecided about whether to add advice about renaming branches for users following "master"-based tutorials, but consider that a separable future decision.

This represents the culmination of a multi-year effort to align Git's defaults with the broader ecosystem, where major Git forges have already switched to "main". The implementation is carefully gated behind a breaking changes flag to maintain backward compatibility.
