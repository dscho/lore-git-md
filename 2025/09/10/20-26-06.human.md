This is a documentation update for the atomic reference updates feature in `git replay`, part of the ongoing effort to improve server-side workflows.

Siddharth Asthana responds to Christian Couder's feedback about the `--update-refs` interface design, agreeing that the naming collision with `git rebase --update-refs` is problematic. The discussion has led to a simplified design where atomic updates become the default behavior, eliminating the need for a separate `--update` flag. The new approach will use `--output-commands` for backward compatibility (producing update-ref commands) and `--allow-partial` for non-atomic failure cases.

The email confirms the thread's consensus on making atomic behavior the default, which addresses both performance concerns (batched transactions are more efficient) and reliability needs for server-side operations. The documentation will be updated to clearly explain when users would want each mode, with the default atomic behavior being recommended for most cases.
