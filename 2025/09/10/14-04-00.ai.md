This is a code review comment on a sequencer infrastructure patch in Patrick Steinhardt's `git-history` RFC series. Phillip Wood suggests applying the new `restore_head_target` option to `git rebase` as well, to avoid adding more conditionals to the already complex sequencer code.

The patch in question (02/18 in v3 series) introduces a new sequencer option to rewind HEAD after non-rebase operations like cherry-picks, which will be needed for the new `git-history` command. Phillip's review focuses on code organization rather than functionality - he's not questioning the need for the feature, but suggesting its implementation could be more widely useful by also applying it to rebase.

Key technical details:
- The patch adds `restore_head_target` field to `struct replay_opts`
- Implements config persistence for the option
- Adds HEAD reset logic in `pick_commits()`
- Modifies `sequencer_pick_revisions()` to account for the new option

This is part of the larger `git-history` effort that builds on sequencer infrastructure while taking inspiration from Jujutsu (jj). The thread shows active engagement from multiple reviewers at both architectural and implementation levels, with Phillip Wood focusing here on keeping the sequencer code clean as new functionality is added.
