This is a technical discussion about Rust build system integration in Git, specifically addressing concerns around Cargo.lock inclusion and Meson/Cargo compatibility. Patrick Steinhardt responds to Brian m. carlson's critique of the proposed Rust infrastructure, particularly around three key issues:

1. **Cargo.lock inclusion**: carlson argues against committing Cargo.lock due to potential security update conflicts with Git's Rust 1.49 support target. Steinhardt acknowledges the concern but frames the 1.49 target as temporary until concrete needs for newer versions emerge, while noting Cargo.lock's security benefits for reproducible builds.

2. **Build system conflicts**: carlson reports a concrete failure where Meson cannot handle a `build.rs` file needed to link tests against `libgit.a` in his SHA-1/SHA-256 interoperability work. Steinhardt concedes this as a practical limitation, suggesting they may need to prioritize Cargo compatibility over Meson integration.

3. **Unstable compiler flags**: The discussion reveals the Meson`-Z unstable-options` flag (used for artifact directory control) doesn't work on stable Rust versions, including both the proposed 1.49 target and carlson's 1.89.0 environment. Steinhardt expresses frustration at this basic functionality being gated behind nightly features.

The exchange highlights growing technical debt in the build system approach, with carlson's real-world test linking failure demonstrating concrete interoperability problems between the proposed Meson-based Rust build and existing Cargo workflows. Steinhardt's responses show willingness to adapt the approach (dropping Meson integration if needed) while maintaining the Rust 1.49 target as a temporary measure until stronger requirements emerge. The unresolved tension between build system choices (Meson vs Cargo) and version support constraints continues to complicate the Rust integration effort.
