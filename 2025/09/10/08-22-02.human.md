This is a technical discussion thread in the ongoing Rust infrastructure series, focusing on type safety at the Rust/C boundary. Patrick Steinhardt responds to concerns raised by Brian m. carlson and Ezekiel Newren about using C types (`c_int`, `c_uchar`) in Rust code versus using Rust-native types (`usize`, `u8`) with corresponding C standard types (`size_t`, `uint8_t`).

The key points from this exchange:
- carlson highlights concrete problems with `c_ulong` portability between 32/64-bit systems and shares painful experience with `mode_t` handling
- Newren advocates avoiding C types in Rust entirely except for `c_void`
- Steinhardt acknowledges the concerns and proposes an intermediate step - making integer widths explicit in C first, with eventual unification toward Rust types if the approach is agreed upon

This discussion reveals important technical considerations for the Rust integration, particularly around FFI type safety and cross-platform compatibility. The thread shows the project working through real-world implementation challenges as they convert subsystems like varint encoding between languages. Steinhardt's response indicates willingness to adapt the approach based on maintainer feedback while maintaining forward progress.
