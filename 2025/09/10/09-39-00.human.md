Bugfix for the `git subtree` contrib command, finalizing a fix for a regression in squashed subtree merges. This is the third version of the patch, now ready for inclusion in maint-2.44 and later branches.

The patch addresses a specific case where nested subtree merges (like `subA/subB`) were being incorrectly ignored during split operations when they were squashed merges. The fix rewrites the commit examination logic to use a single `git show` call with trailer parsing instead of multiple `git log` invocations, which was causing the original bug by searching parent commits incorrectly.

Phillip Wood, who reviewed the patch, confirms this version looks good despite not being deeply familiar with git-subtree. The patch includes comprehensive test coverage for both regular and squashed merge scenarios of nested subtrees, with new test helpers to verify the behavior. All previous review feedback has been addressed except for one minor shell syntax preference.

This is a straightforward bugfix that maintains all existing behavior while correcting the regression. The changes are focused and well-tested, making it a low-risk candidate for backporting to affected versions (v2.44.0-rc0 and later). The thread shows consensus among contributors that this is ready to be applied.
