This is a code review comment on a preparatory patch in Patrick Steinhardt's `git-history` series. Phillip Wood suggests a small improvement to the sequencer infrastructure changes that add a `skip_commit_summary` option.

The patch adds a new `skip_commit_summary` flag to `struct replay_opts` to control whether commit summary output should be suppressed. Phillip notes that since rebase already skips these summaries (via the `!is_rebase_i(opts) check), it would be cleaner to have rebase explicitly set this new flag rather than keeping both checks. This would make the behavior more explicit and potentially simplify future maintenance.

The change is part of the larger preparatory work for the `git-history` command, which builds on Git's sequencer infrastructure. The suggestion doesn't challenge the overall approach but offers a small refinement to the implementation details. Phillip's tone is constructive and the suggestion appears technically sound.
