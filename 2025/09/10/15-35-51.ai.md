This is a refactoring patch in the Rust infrastructure series, specifically addressing type safety in the varint subsystem. The patch changes the varint implementation to use explicit integer widths (uint64_t for values and uint8_t for lengths) instead of implicit types like uintmax_t and int. This change serves two purposes: it ensures platform-independent behavior (important for the Rust port) and prepares for the upcoming Rust reimplementation of varint.c.

The patch modifies four files (dir.c, read-cache.c, varint.c, varint.h) with straightforward mechanical changes to type declarations and function signatures. The varint subsystem is used in several core areas including untracked cache handling and index reading/writing. The explicit widths reflect the actual constraints of the varint format (maximum 16-byte encoding) while eliminating platform-dependent behavior.

This change directly addresses earlier type safety concerns raised in the thread, particularly from Brian m. carlson, by making integer handling more precise. The patch follows the series' pattern of incremental, well-justified changes that both improve the codebase and facilitate the Rust transition. The changes are minimal (19 lines added/15 removed) and focused, with no behavior modifications beyond the type safety improvements.
