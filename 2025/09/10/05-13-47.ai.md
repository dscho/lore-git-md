This is a bugfix for the command deprecation framework series, specifically addressing a memory leak in the alias shadowing implementation for deprecated commands.

Jeff King (Peff) identifies a memory leak in the alias shadowing code from patch 2/7 of the series. The current implementation calls `alias_lookup()` which allocates memory for the returned alias string, but doesn't free it. This would be caught by Git's SANITIZE=leak test infrastructure.

The problematic code is in the deprecated command handling path where it checks for aliases that could shadow the deprecated command. Peff suggests two potential fixes: either capturing and freeing the string returned by `alias_lookup()`, or creating an `alias_exists()` wrapper that handles the memory management internally. He also notes that `handle_alias()` itself might provide the needed information through its return value, though he hasn't fully analyzed that path's implications on the `done_alias` flag behavior.

This is a relatively minor but important fix needed before the series can be merged, as the project maintains a strict no-leaks policy. The issue doesn't affect the core functionality of the deprecation system but needs resolution for correctness. The fix would likely involve changes to `git.c` and possibly updates to the test coverage in `t/t0014-alias.sh` to verify proper memory handling.

The context shows this is part of the larger, already-approved deprecation framework that introduces the `DEPRECATED` command flag and alias shadowing for commands like `whatchanged` and `pack-redundant`. The series has received extensive review and is otherwise ready for integration, making this one of the final technical issues to address.
