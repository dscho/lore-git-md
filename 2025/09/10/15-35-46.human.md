This is a feature patch series (v4) introducing Rust infrastructure to Git core, with an announcement that Rust will become mandatory in Git 3.0. Patrick Steinhardt continues his incremental approach to adding Rust support, now focusing on build system integration and type safety improvements.

The series converts the varint subsystem to Rust as a test balloon, demonstrating C/Rust interoperability while avoiding complex dependencies. Key changes in v4 include:
- Using Rust-native integer types (u8, usize) instead of C types in the varint implementation
- Unconditionally using Cargo in Meson builds (with a wrapper script to handle output paths)
- Accelerating the rollout timeline by removing an intermediate step that tied Rust support to breaking changes
- Adding explicit integer width specifications in C to improve type safety at the FFI boundary

The series now includes both Meson and Makefile support, CI integration, and build status reporting via `git version --build-options`. The roadmap in BreakingChanges.adoc outlines the transition path to mandatory Rust in Git 3.0.

Technical implementation appears solid, with thorough test coverage and careful attention to backward compatibility. The accelerated timeline reflects responsiveness to earlier feedback, though Windows support remains an open question. This represents a significant but well-scoped step toward Git's Rust future, with clear documentation of both technical changes and project policy implications.
