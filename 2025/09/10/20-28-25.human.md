This is a documentation update for the `git replay --update-refs` feature, part of the ongoing effort to improve atomic reference updates in server workflows.

Siddharth Asthana responds to Andrei Rybak's feedback about example organization in the `git replay` documentation. The original patch showed three separate examples with different flags (`--update`, `--update-refs`, and `--batch`), but the explanatory text about their differences was separated from the examples. 

Asthana notes that with the now-agreed-upon default behavior (atomic updates by default), the examples can be simplified to just show the default case versus the traditional pipeline output using `--output-commands`. This change will make the documentation flow better while still covering both usage patterns.

The response confirms the documentation will be updated in v2 to reflect the simplified interface, where atomic updates are the default and `--output-commands` provides backward compatibility with the old pipe-to-update-ref behavior. This aligns with the thread's consensus that server-side users should get atomic behavior by default while maintaining compatibility for existing scripts.
