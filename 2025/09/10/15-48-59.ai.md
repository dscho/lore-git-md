This is a technical follow-up in the command deprecation series, specifically addressing the memory leak issue in patch 2/7. Jeff King proposes a solution to fix the leak in the deprecated command alias shadowing logic by restructuring the code to avoid the separate `alias_lookup()` call entirely.

The key change replaces the two-step check (first verifying an alias exists with `alias_lookup()`, then processing it with `handle_alias()`) with a direct call to `handle_alias()`. This works because `handle_alias()` already handles memory management internally and returns appropriate status codes: 0 for no alias found, 1 for a found alias that should be processed (with the command arguments updated), or exits directly for shell aliases.

The solution maintains all existing functionality while eliminating the leak path where the `alias_lookup()` result wasn't being freed. It also correctly handles edge cases like deprecated aliases that resolve to other deprecated commands by preserving the `done_alias` flag behavior.

This appears to be the simpler of the two potential fixes (the other being an explicit free or new wrapper function), and since `handle_alias()` already has the necessary memory management, it's likely the preferred approach. The change is localized to git.c's `run_argv()` function where the alias shadowing logic lives.
