Feature implementation for default branch name change, part of the completed series switching from "master" to "main" when built with WITH_BREAKING_CHANGES. This is the first patch in a 4-patch series that has already been merged, now in post-merge refinement phase.

The patch implements the core change to make "main" the default branch name when WITH_BREAKING_CHANGES is enabled, while maintaining "master" as the default otherwise. Key technical changes include:
- Updates repo_default_branch_name() in refs.c to return "main" when WITH_BREAKING_CHANGES is set
- Modifies the advice system to remove the default branch name warning when WITH_BREAKING_CHANGES is active
- Updates git-init documentation with conditional asciidoc markup showing both states
- Adds test coverage in t0001-init.sh for both build configurations
- Removes GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME=main from CI since it's now the compiled-in default

The patch leaves several aspects for future work:
- Documentation outside git-init.adoc (like user-manual.adoc) remains unchanged due to impracticality of mass ifdef usage
- The advice message for non-breaking-changes builds is updated to explicitly mention the Git 3.0 transition
- Remote branch detection in guess_remote_head() intentionally remains unchanged for compatibility with older servers

The implementation follows the previously agreed approach of gating the change behind WITH_BREAKING_CHANGES, with all test infrastructure updates completed in this series. The thread context shows this was merged with technical consensus, though some documentation wording and advice system details remain under discussion in follow-up emails.
