This is a refactoring patch in Patrick Steinhardt's Rust infrastructure series, specifically addressing type safety in the varint subsystem. The patch changes the varint implementation to use explicit integer widths (uint64_t for values and uint8_t for lengths) rather than implicit types like uintmax_t and int. 

The change makes the code more platform-independent and prepares for an upcoming Rust reimplementation of varint.c. The patch affects several files that use varint encoding/decoding, including dir.c (untracked cache handling) and read-cache.c (index operations). 

The refactoring is straightforward and mechanical, with Ezekiel Newren credited for the suggestion. It's part of the broader effort to make Git's codebase more amenable to Rust integration by eliminating implicit type behaviors that could cause issues when interfacing with Rust's stricter type system.

This patch follows the series' pattern of making incremental, well-justified changes that both improve the current code and pave the way for Rust integration. The changes are focused and unlikely to be controversial, though reviewers will want to verify the type choices match the actual requirements of the 16-byte varint encoding scheme.
