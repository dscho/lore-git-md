This is the final version of a bugfix patch for the `git subtree` contrib command, addressing a regression in handling squashed subtree merges under prefixes during split operations. The patch has gone through review and incorporates all feedback from Phillip Wood.

The key changes in this version include:
- A complete rewrite of the `should_ignore_subtree_split_commit()` function to use `git show` for trailer parsing
- Removal of non-POSIX `local` usage
- Expanded test coverage with new helper functions and more comprehensive scenarios
- The patch maintains all agreed-upon logical conditions for ignoring commits while fixing the regression introduced in v2.44.0-rc0.

Colin has addressed all of Phillip's review comments except for one technical point about using `git checkout @{-1}` - he found it doesn't work as expected with Git 2.44 when used after `--orphan`. The remaining changes (removing unnecessary semicolons, using `test_path_is_file`, and setting `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME`) will be incorporated in a v3.

The patch appears well-tested and ready for merging, with Phillip Wood having confirmed the technical approach is sound. It fixes a real regression while maintaining compatibility with existing subtree workflows.
