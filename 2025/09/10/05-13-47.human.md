This is a bugfix for the command deprecation series, specifically addressing a memory leak in the alias shadowing implementation for deprecated commands. Jeff King (Peff) points out that the current code in patch 2/7 of the SANITIZE=leak test suite because `alias_lookup()` allocates memory that isn't freed when checking for deprecated command aliases.

The issue was caught by the automated leak detection tests, showing the series still needs minor polishing before final integration. Peff suggests two potential fixes: either properly capturing and freeing the alias string returned by `alias_lookup()`, or creating a new `alias_exists()` helper that handles the memory management internally. He also notes that `handle_alias()` might already provide the needed functionality through its return value, though this approach would require careful consideration of the `done_alias` flag behavior.

This is a relatively straightforward fix for an edge case in the otherwise complete and approved deprecation framework series. The feedback comes from one of Git's core maintainers, indicating the high standards for code quality even in final review stages. The fix will likely be incorporated before the series hits 'next'.
