Thread identity: Refactoring patch simplifying callers of `get_oid_with_context()` by switching to `repo_get_oid_with_flags()` where context isn't needed. Authored by René Scharfe.

Core problem/goal: Reduce boilerplate in object lookup code by using simpler `repo_get_oid_with_flags()` API when callers don't need the additional context information provided by `get_oid_with_context()`. This supports Git's move toward repository-aware APIs.

Current status: Initial version of refactoring patch affecting multiple commands (`ls-tree`, `rev-parse`, `stash`, list-objects filter). Patrick Steinhardt has reviewed and confirmed the technical correctness of the changes while noting broader API design questions that remain unaddressed.

Key technical details:
- Replaces `get_oid_with_context()` calls with `repo_get_oid_with_flags()` when `object_context` output parameter isn't used
- Removes unused `struct object_context` declarations and corresponding `object_context_release()` calls
- Affects 5 files: builtin/ls-tree.c, builtin/rev-parse.c, builtin/stash.c, list-objects-filter.c, object-name.c
- Net reduction of 33 lines (50 removed, 17 added)
- Two pre-existing API design quirks identified but not addressed: inconsistent return types between related functions (`int` vs `enum get_oid_result`)

Participant positions:
- Patrick Steinhardt reviewed and approved the technical approach while noting:
  - The inconsistency between `repo_get_oid_with_flags()` returning `int` vs `get_oid_with_context()` returning `enum get_oid_result`
  - Similar return type issues in related functions like `repo_get_oid_committish()`
  - Considers these separate issues that shouldn't block current changes

Related work: Part of broader effort to simplify object lookup code paths and migrate to repository-aware APIs. Connects to `the_repository` removal project and ODB abstraction work. The review discussion suggests potential future cleanup directions for the object lookup API layer.
