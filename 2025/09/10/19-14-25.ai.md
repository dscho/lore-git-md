Documentation patch refining the branch switching explanation in `git-checkout.adoc`. This is part 3 of Julia Evans' v4 series to improve the command's documentation, following extensive review from Junio Hamano and D. Ben Knoble.

The patch addresses specific user confusion points in the DESCRIPTION section about branch switching behavior. Key changes include:

1. Replaces the phrase "pointing HEAD at the branch" with clearer language about setting the current branch, removing potential confusion that this was something the user needed to do manually.

2. Explicitly states when the checkout will fail (when there are uncommitted changes to files that differ between the current commit and target branch), addressing feedback that the previous wording made it seem like local changes were always preserved.

3. Simplifies the explanation of running `git checkout` without arguments, replacing the confusing "glorified no-op" phrasing with a direct statement that it only prints tracking information.

The changes maintain all technical accuracy while improving clarity, particularly for users who may not understand Git's internal concepts like HEAD manipulation. The patch follows the series' established pattern of using more direct language while preserving precise descriptions of Git's behavior.

This iteration appears to resolve all outstanding user confusion points identified in the feedback while keeping alignment with the technical consensus established in earlier versions of the series. The changes are focused on phrasing improvements rather than substantive behavior modifications.
