Feature/Rust infrastructure discussion focusing on type safety at the Rust/C boundary. This email from Patrick Steinhardt responds to Brian m. carlson and Ezekiel Newren's concerns about type handling between Rust and C in the varint subsystem proof-of-concept. The discussion centers on whether to use Rust's native types or C's FFI types (`std::os::raw`) at the interface boundary.

Key technical points in this exchange:
- carlson highlights concrete problems with `c_ulong` portability between 32/64-bit systems and signedness mismatches
- Newren advocates for using Rust native types (`usize`, `u8`) on both sides with C standard types (`size_t`, `uint8_t`) as counterparts
- Steinhardt acknowledges the concerns and proposes an intermediate step of making integer widths explicit in C before potentially unifying towards Rust types
- The unresolved issue of Rust lacking `uintmax_t` FFI support remains noted

This continues the architectural debate about how to handle type safety at the Rust/C boundary, with Steinhardt showing willingness to adapt the approach based on the feedback while maintaining forward progress on the varint subsystem as a test case. The email demonstrates the practical challenges of type system interoperability that emerge when converting Git subsystems to Rust.
