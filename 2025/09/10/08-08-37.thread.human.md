This thread centers on Christian Couder's patch series adding signature handling controls to `git fast-import`, mirroring existing `git fast-export` capabilities. The first patch (infrastructure refactoring) has already been merged after positive reviews from Junio and Patrick Steinhardt. The second patch, now in its second version, implements the actual signature handling for commits.

The discussion has been thorough, with Christian promptly addressing all technical feedback. Junio initially raised detailed implementation concerns about signature parsing, warning messages, and behavior across different modes (ABORT, STRIP, etc.), all of which Christian has incorporated in V2. The most recent exchange refined the STRIP mode behavior to be more lenient with malformed signatures while keeping ABORT mode strict, aligning with user expectations. The warning message wording was also improved to include "verbatim" for clarity.

While Junio expressed mild skepticism about starting with commit support rather than tags (which are more commonly signed), he acknowledges this as a philosophical preference rather than a blocking issue. The technical implementation appears sound, with comprehensive test coverage in t9305. Christian has confirmed tag handling will follow in future work. With all review feedback addressed, this series seems ready for merging, representing another step in Christian's ongoing work to improve GPG signature handling across Git's plumbing commands.
