Feature patch implementing the switch from "master" to "main" as Git's default branch name when built with WITH_BREAKING_CHANGES enabled. This is part of the completed 4-patch series that has already been merged, now in post-merge refinement.

The patch makes several key changes:
1. Updates the default branch name to "main" when WITH_BREAKING_CHANGES is set, while keeping "master" as the default otherwise
2. Modifies the advice message to warn that the default will change to "main" in Git 3.0
3. Updates documentation in git-init.adoc and BreakingChanges.adoc to reflect the change
4. Adds conditional compilation blocks around advice system changes
5. Includes test updates to verify behavior under both configurations

The implementation leaves some documentation (like user-manual.adoc) unchanged for now due to the impracticality of mass updates with ifdefs. The patch maintains backward compatibility with older servers that might still use "master" by keeping the guess_remote_head() behavior unchanged.

This appears to be a well-considered implementation of a long-planned change (first warned about in 2020), with thorough test coverage and clear documentation updates. The patch is now in post-merge discussion phase focusing on test improvements and advice messaging refinements.
