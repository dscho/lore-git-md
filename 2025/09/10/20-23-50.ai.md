This is a follow-up discussion on the command deprecation system series, specifically addressing patch 1/7 which introduces the `deprecated` category to `--list-cmds`. The email focuses on finalizing the include/exclude semantics for command listing.

Kristoffer Haugsbakk responds to Junio Hamano's feedback about the include/exclude flag behavior in the command listing interface. After reconsideration, Kristoffer agrees that include and exclude flags should remain mutually exclusive (reverting an earlier position) since using both simultaneously doesn't make logical sense. This maintains the design where commands are filtered based on either inclusion criteria (only show matching commands) or exclusion criteria (hide matching commands), but never both at once.

The discussion confirms the current implementation's approach where the deprecated command listing uses only the include flag (with DEPRECATED bit) without any exclude option. Kristoffer notes this design is acceptable but remains open to alternative suggestions from others. The exchange shows consensus forming around the current implementation while leaving room for final tweaks before integration.

Key technical points:
- The include/exclude semantics in `--list-cmds` interface
- DEPRECATED flag bit usage (1<<6)
- Confirmation of mutual exclusivity between include/exclude flags
- Openness to potential alternative designs from other contributors
