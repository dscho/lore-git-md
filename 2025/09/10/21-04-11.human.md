This is a technical discussion about type safety changes in the varint subsystem as part of the Rust infrastructure series. Junio C Hamano responds to Patrick Steinhardt's patch that refactors varint encoding to use explicit integer widths (`uint64_t` for values and `uint8_t` for lengths) rather than implicit types like `uintmax_t`.

Junio acknowledges the technical merits of the change - it makes the code more platform-independent and prepares for Rust implementation. He raises no objections to the `uint64_t` change for values, noting we wouldn't need 128-bit integers for packfiles anyway. For the length parameter, while he notes `uint8_t` isn't strictly necessary (255 bytes would suffice), he's willing to accept it.

The key point of discussion is about future consistency - Junio prefers `uint64_t` over Rust's `u64` to maintain consistency with non-Rust parts of the codebase, anticipating this will come up when Ezekiel Newren's related work merges. This is a minor but important detail in the larger Rust integration effort, showing the maintainer's focus on long-term codebase consistency even during transitional changes.
