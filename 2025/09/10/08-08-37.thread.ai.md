Thread identity: Feature patch series introducing signature handling controls in `git fast-import`, building on existing `git fast-export` capabilities. Authored by Christian Couder, who specializes in GPG signature handling and fast-import/fast-export plumbing. Current series consists of two patches: infrastructure refactoring (1/2) and feature implementation (2/2), with Junio C Hamano now questioning scope completeness regarding tag signature support.

Core problem/goal: Enable signature management during repository filtering operations by adding parallel signature control options to `git fast-import`. Initial implementation focuses on basic signature preservation/removal with warning variants for commits, matching fast-export's existing behavior, though infrastructure supports tags as well.

Current status:
- Patch 1/2 refactors shared signature handling infrastructure with positive review from Junio:
  * Moves `enum sign_mode` and parsing logic from fast-export.c to gpg-interface.{c,h}
  * Introduces parse_sign_mode() helper function supporting both commit and tag modes
  * Review feedback noted improved readability and expected implementation
- Patch 2/2 implements `--signed-commits=<mode>` option in fast-import with:
  * Modes: verbatim/ignore (keep), strip (remove), plus warn- variants
  * Default mode is verbatim (unlike fast-export's default abort)
  * Comprehensive tests in new t9305 test script covering all modes and signature types
  * Junio's review raises:
    - Architectural concerns about function boundaries and stream handling
    - New question about scope consistency - why only commit support when infrastructure handles tags?
    - Suggestion to clarify warning messages with "verbatim" context

Key technical details:
- Shared components now in gpg-interface plumbing:
  * `enum sign_mode` definition (abort, verbatim/ignore, strip, warn- variants)
  * parse_sign_mode() function for consistent mode parsing
  * Infrastructure designed to support both commit and tag signatures
- Fast-import changes:
  * New --signed-commits option (commit-only in current patch)
  * Adds `signed_commit_mode` global variable and option parsing
  * Implements signature processing in `import_signature()` with revised stream handling
  * Touches gpg-interface, fast-import frontend, and documentation
- Test coverage in t9305 verifies all commit signature modes with multiple signature types

Open questions/design decisions:
- Architectural concerns about function boundary and stream handling in patch 2/2
- Scope gap identified: infrastructure supports tags but only commits implemented
- Whether to maintain "ignore"/"verbatim" synonym pairing
- Whether warning variants should remain mode-tied or use separate verbosity control
- Future plans may include validation and re-signing capabilities
