Thread identity: Feature patch series introducing signature handling controls in `git fast-import`, building on existing `git fast-export` capabilities. Authored by Christian Couder, who specializes in GPG signature handling and fast-import/fast-export plumbing. Current series consists of two patches: infrastructure refactoring (1/2) and feature implementation (2/2).

Core problem/goal: Enable signature management during repository filtering operations by adding parallel signature control options to `git fast-import`. Initial implementation focuses on basic signature preservation/removal with warning variants, matching fast-export's existing behavior.

Current status:
- Patch 1/2 refactors shared signature handling infrastructure with positive review from Junio C Hamano:
  - Moves `enum sign_mode` and parsing logic from fast-export.c to gpg-interface.{c,h}
  - Introduces parse_sign_mode() helper function
  - Review feedback noted improved readability and expected implementation
  - Minor question raised about "unset" codepath behavior (acknowledged as out of scope)
  - Maintains identical behavior while enabling code reuse
- Patch 2/2 implements `--signed-commits=<mode>` option in fast-import with:
  - Modes: verbatim/ignore (keep), strip (remove), plus warn- variants
  - Default mode is verbatim (unlike fast-export's default abort)
  - Comprehensive tests in new t9305 test script covering all modes and signature types
  - Junio C Hamano's review raises architectural concerns about:
    * Division of responsibility between `import_signature()` and `parse_new_commit()`
    * Data stream consumption patterns differing by mode
    * Maintainability impact of manual stream advancement in switch cases
    * Potential optimization tradeoffs in STRIP mode handling
    * Suggestion to clarify warning messages with "verbatim" context

Key technical details:
- Shared components now in gpg-interface plumbing:
  - `enum sign_mode` definition (abort, verbatim/ignore, strip, warn- variants)
  - parse_sign_mode() function for consistent mode parsing
- Fast-import changes:
  - New --signed-commits option mirroring fast-export's signature handling
  - Adds `signed_commit_mode` global variable and option parsing
  - Implements signature processing in `import_signature()` with revised stream handling
  - Touches gpg-interface, fast-import frontend, and documentation
- Test coverage in t9305 verifies all modes with multiple signature types

Open questions/design decisions:
- Architectural concerns about function boundary and stream handling in patch 2/2
- Whether to maintain "ignore"/"verbatim" synonym pairing
- Whether warning variants should remain mode-tied or use separate verbosity control
- Future plans may include validation and re-signing capabilities
