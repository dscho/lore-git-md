This is a feature proposal for `git fast-import` that's part of an ongoing effort to improve signature handling in repository filtering tools. Christian Couder introduces a new `--signed-commits=<mode>` option for `git fast-import`, mirroring existing functionality in `git fast-export`. The goal is to give tools like `git-filter-repo` more control over how commit signatures are handled during repository rewriting operations.

The patch series starts with a refactoring of the enum parsing code shared between fast-export and the new fast-import functionality, then adds the new option with initial modes that match fast-export's behavior ("verbatim", "warn-verbatim", "strip", "warn-strip"). The author mentions plans to add more sophisticated modes in the future (like "re-sign" and validation-based options) but wants to validate the basic design first.

The author specifically seeks feedback on two design questions: whether to keep certain mode aliases ("ignore" for "verbatim") that exist in fast-export, and whether warning variants should remain as separate modes or be controlled by a global verbose flag. The implementation includes thorough test coverage (a new 108-line test file) and has passed CI testing.

This appears to be a carefully considered extension of existing functionality, with clear motivation from the git-filter-repo use case. The patch structure suggests good separation of concerns, starting with refactoring shared code before adding new features. The explicit request for design feedback early in the process indicates thoughtful development.
