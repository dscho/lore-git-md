This is a feature patch series introducing new signature handling controls to `git fast-import`. The cover letter outlines a two-patch series that begins implementing signature management capabilities similar to those in `git fast-export`, with plans for future expansion.

The series starts by refactoring the `enum sign_mode` parsing code in gpg-interface.c to make it reusable, then adds a new `--signed-commits=<mode>` option to `fast-import` that initially mirrors `fast-export`'s behavior. The supported modes include "verbatim" (keeping signatures as-is), "ignore" (same as verbatim), "strip" (remove signatures), and their "warn-" variants that add warning messages.

The author seeks feedback on two design decisions before expanding the feature set: whether to keep the potentially confusing "ignore"/"verbatim" synonym pairing, and whether warning variants should remain tied to modes or be controlled by a separate verbosity flag. The implementation includes comprehensive tests in a new t9305 test script covering all initial modes.

This appears to be a well-structured proposal with clear motivation (enabling tools like git-filter-repo to manage signatures during repository filtering) and the author demonstrates awareness of potential design tradeoffs. The patches touch gpg-interface plumbing, fast-import's frontend, and documentation while maintaining backward compatibility. Future plans mentioned include more sophisticated modes like signature validation and re-signing capabilities.
