This is a documentation patch in the Rust infrastructure series, specifically addressing formatting issues in the BreakingChanges documentation. Kristoffer Haugsbakk points out a minor but technically important formatting inconsistency in the HTML output of the numbered list in the Rust adoption timeline section. The current markup causes the explanatory text after point 3 to be indented as if it were a continuation of that point, when it should return to the main document flow.

The suggested fix involves using AsciiDoc's `--` block syntax to properly scope the list items, which would make the subsequent explanatory text appear at the correct indentation level in the rendered HTML output. This is a purely presentational concern that doesn't affect the technical content about Rust's phased adoption (auto-detection in 2.52, default-enabled in 2.53, mandatory in 3.0) or the build system flags (`-Drust=enabled` and `WITH_RUST=YesPlease`).

The email references an earlier message (linked via Message-ID) where the formatting issue was presumably first noticed, though the context isn't fully reproduced here. The correction maintains the existing technical accuracy while improving document readability, following the series' pattern of iterative refinement based on community feedback. This comes as the BreakingChanges documentation is under particular scrutiny from Junio Hamano regarding clarity of mandatory transition implications.
