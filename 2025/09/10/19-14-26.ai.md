This is a documentation patch in Julia Evans' ongoing series to improve `git-checkout.adoc`. The patch focuses specifically on clarifying the `-b` and `-B` options, addressing user confusion about their differences and behavior.

The changes restructure the documentation to separate `-b` and `-B` into distinct sections rather than combining them with conditional explanations. For `-b`, it now clearly states it creates a new branch at the specified start point (defaulting to current commit) and checks it out, while `-B` is described as doing the same but resetting an existing branch rather than failing. The patch removes redundant explanations about transactional behavior, assuming Git will fail cleanly by default.

Key technical changes include:
- Splitting combined `(-b|-B)` syntax into separate option descriptions
- Adding explicit default for `<start-point>` (current commit)
- Simplifying failure condition explanations
- Removing implementation details about internal `git branch -f` behavior
- Maintaining consistency with earlier patches' terminology improvements

This continues the series' trend of improving clarity while preserving technical accuracy, with particular attention to making the branch creation/reset behaviors more immediately understandable to users. The changes align with the v4 series' focus on final editorial polish after technical consensus was established in earlier versions.
