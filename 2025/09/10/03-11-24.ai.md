Bugfix for `git subtree` addressing a regression in squashed subtree merges under prefixes during split operations. This is the final v3 patch in the series, incorporating all review feedback and now ready for application.

The patch fixes a specific regression introduced in v2.44.0-rc0 where squashed subtree merges under prefixes (like `subA/subB`) were being incorrectly ignored during split operations. The root cause was in `should_ignore_subtree_split_commit()` which was examining parent commits when it should only look at the specified commit. The new implementation uses a single `git show` call with trailer parsing instead of multiple `git log` invocations, maintaining all the same logical conditions for ignoring commits but doing so more accurately.

Key technical changes include:
- Complete rewrite of `should_ignore_subtree_split_commit()` to properly examine only the target commit
- New test helper `test_create_subtree_add` for constructing test cases
- Expanded test coverage in t7900-subtree.sh for both regular and squashed merge scenarios
- Maintained all existing behavior checks while fixing the regression
- Incorporated all stylistic feedback from reviewers including precise `${var-}` syntax for unset variables

The patch includes comprehensive test coverage for the fixed scenario, verifying that nested subtrees under prefixes are properly handled during splits regardless of whether they were added with `--squash`. All parties involved in the review (Colin Stagner, Phillip Wood, and Junio Hamano) have confirmed this version addresses all concerns and is ready for inclusion. The fix targets maint-2.44 and later versions.
