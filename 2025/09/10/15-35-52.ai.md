Feature and test balloon patch for Rust infrastructure, part of the ongoing Rust integration series (v4 6/9). This patch reimplements Git's varint encoding/decoding subsystem in Rust as a low-risk test case, building on the type safety work from v4 5/9. The varint subsystem was chosen for its simplicity and isolation from other Git components.

The implementation provides direct C-compatible exports (`decode_varint` and `encode_varint`) using Rust's FFI, with explicit type handling (usize/u8) matching the C side's uint64_t/uint8_t. The Rust version includes comprehensive unit tests validating edge cases like overflow behavior, mirroring the C implementation's constraints (16-byte maximum encoding). Build system changes conditionally exclude varint.c when Rust is enabled, adding varint.rs to both Makefile and meson build configurations.

Key technical points for future reference:
- Maintains identical ABI through `#[no_mangle]` and pointer-based buffer handling
- Uses Rust's native overflow detection via `leading_zeros()` and wrapping arithmetic
- Includes 16 test cases covering basic encoding/decoding and edge conditions
- Build system integration follows the pattern established in v4 3/9 (Makefile) and meson.build
- Positioned as a "test balloon" to validate the Rust infrastructure without introducing new functionality

This continues the series' pattern of incremental, well-scoped additions that both advance the Rust integration and provide concrete examples for review. The patch appears carefully implemented with attention to type safety and test coverage, though its ultimate value as a test case may depend on how representative varint handling is of Git's broader needs.
