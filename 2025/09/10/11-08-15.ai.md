Technical clarification about shallow clone implementation post-grafts removal.

Patrick Steinhardt clarifies that while the user-facing `.git/info/grafts` mechanism is being removed in Git 3.0, the underlying shallow clone functionality (`git clone --depth=1`) will remain intact. The key point is that this is purely about removing the grafts interface, not the capability itself. 

He confirms that `git-replace` will become the exclusive user-facing mechanism for this type of history manipulation, though he doesn't detail how exactly shallow clones will be reimplemented internally. This suggests the change is more about interface cleanup than architectural overhaul.

The email implies that unshallowing operations (`git fetch --unshallow`) will continue to work as before, since the core shallow clone capability isn't being removed. The focus is specifically on deprecating the grafts file interface in favor of `git-replace`.

Steinhardt proposes updating the BreakingChanges document to make this distinction clearer - that grafts removal affects only the user interface, not the underlying shallow clone functionality. This addresses the original concern about compatibility while maintaining the project's direction toward removing grafts.

Key technical details:
- `.git/info/grafts` removal is interface-only change
- Shallow clone internals will be preserved via different implementation
- `git-replace` becomes sole user-facing mechanism
- BreakingChanges doc needs update to clarify this distinction
- No changes to unshallowing behavior expected
