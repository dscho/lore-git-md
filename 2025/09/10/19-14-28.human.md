Documentation patch refining the file restoration section of `git-checkout.adoc`. This is part 6/7 of Julia Evans' series to clarify `git checkout` documentation, now in its fourth iteration after extensive feedback.

The patch splits the "restoring files" section into two distinct cases: (1) when a tree-ish is provided (which updates both index and worktree) and (2) when no tree-ish is given (which updates only the worktree from the index). This reorganization addresses user confusion about the negative phrasing in the original text and better matches the command's SYNOPSIS structure. 

A notable technical clarification is that the `-f` option only applies to the index->worktree case, not the tree-ish case, which the documentation now correctly reflects. The patch also updates the description of the interactive patch mode to reference both restoration modes rather than just one.

This change exemplifies the series' goal of making complex behaviors more accessible while maintaining technical precision. The split helps users understand the different restoration mechanics at play, particularly the distinction between restoring from a commit versus from the staging area. As with previous patches in the series, this refinement emerged from real user feedback and careful review.
