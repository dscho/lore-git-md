This is a clarification about shallow clone support following the grafts removal in Git v3.0. Patrick Steinhardt responds to concerns about how shallow clones will work without the grafts mechanism, explaining that while the user-facing `.git/info/grafts` file is being deprecated, the underlying shallow clone functionality will remain intact - it's just being reimplemented internally.

The key point is that `git-replace` is being positioned as the sole user-facing mechanism for history rewriting, while shallow clone operations (`--depth` and `--unshallow`) will continue working as before, just with different internals. This addresses concerns raised earlier in the thread about whether shallow clones would break with grafts removal.

The email suggests updating the BreakingChanges documentation to make this distinction clearer - that while grafts are going away as a user feature, the shallow clone capability itself isn't being removed. This helps clarify the scope of the grafts deprecation and should reassure users that their shallow clone workflows won't break.
