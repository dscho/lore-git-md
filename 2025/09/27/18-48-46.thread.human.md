This thread explores adding wildcard path matching to Git's credential configuration, addressing a limitation where currently only exact path matches are supported. The original use case came from git-credential-oauth users needing distinct credentials for different paths under the same domain (like `example.com/org1` vs `example.com/org2`).

The latest email strengthens the case with a clearer example: distinguishing personal credentials for `git.example.com` from enterprise credentials under `git.example.com/syscorp/`. Two syntax options are being considered - an explicit `*` wildcard or an implicit trailing slash - with the latter gaining favor as it resembles directory path conventions. The proposal emphasizes maintaining backward compatibility so existing exact-match configurations continue working.

Implementation would require changes to credential.c's URL matching logic and config parsing, with careful attention to security implications. The goal is to prevent credential leakage while solving the real-world problem of managing credentials for different paths under the same domain. No maintainer feedback or other participant positions have been noted yet, but the discussion appears to be converging toward the implicit wildcard approach.
