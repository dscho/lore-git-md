Thread identity: user question about git-worktree behavior regarding untracked worktree directories, with authoritative response from Junio C Hamano.

Core problem: why worktree directories (created via `git worktree add`) appear as untracked files in the main repository's status, and whether they should be automatically ignored. Original example showed `base/` appearing in `git status` after `git worktree add base` in Git 2.51.0.

Current status: Junio has clarified this is intentional design - worktree directories are treated like any directory containing a Git repository (similar to nested clones) and not special-cased for ignoring. The behavior is consistent across Git versions.

Key technical details: worktree directories contain their own `.git` files pointing to the main repository, making them appear as untracked in the main worktree. Junio recommends creating worktrees in sibling directories (e.g. ../git.maint) rather than within the main working tree if the untracked status is problematic. The `--detach` option can be used with this approach.

Open questions: none remaining - Junio's response presents this as settled design. The thread could be referenced if reconsideration of this behavior is proposed in future.
