Proposed feature to enable wildcard path matching in Git credential configuration, addressing limitations in current exact-path-only behavior. Originated from git-credential-oauth issue #83 but applies generally to credential management. Core use case: distinguishing credentials for different paths under same domain (e.g. `git.example.com/syscorp/` vs `git.example.com/personal/`). Brian M. Carlson initially clarified that URL prefix matching may already be implemented using urlmatch patterns (Git's internal URL comparison mechanism), though undocumented, with test coverage in t0300.

Tests demonstrate `credential.https://example.com/org` correctly matches subpaths like `https://example.com/org/repo.git` while avoiding false matches on similar paths like `https://example.com/organ/repo.git`. This validates the path-aware matching behavior and its security characteristics.
