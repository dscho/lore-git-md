Proposed feature to enable wildcard path matching in Git credential configuration, addressing limitations in current exact-path-only behavior. Originated from git-credential-oauth issue #83 where users need distinct credentials for different paths under same domain (e.g. `example.com/org1` vs `example.com/org2`). Current implementation in credential.c requires exact path matches when paths are specified, documented in gitcredentials man page.

Two syntax options proposed for wildcard support: explicit (`credential.https://example.com/org1/*.key`) or implicit (`credential.https://example.com/org1/.key`). Would modify URL matching logic to recognize path prefixes while maintaining existing exact-match behavior for non-wildcarded paths. Security considerations needed for wildcards - must not inadvertently match shorter prefixes or allow credential leakage across security boundaries. Implementation would require changes to:
1. credential.c matching logic
2. config parsing for wildcard detection
3. gitcredentials documentation updates
4. potential helper protocol extensions

Key constraints:
- Backward compatibility with existing exact-match configurations
- Clear documentation of wildcard matching rules
- Security review of prefix matching behavior
- Integration with credential helper protocol

Next steps would likely involve discussion of preferred syntax, security implications, and implementation approach.
