Feature patch adding object counting to the `git repo stats` command. This is patch 5/7 in the series introducing repository health reporting functionality.

The patch extends the existing reference counting infrastructure to also report reachable object counts by type (commits, trees, blobs, tags). It uses the path-walk API to traverse all objects reachable from regular references, categorizing them by type. The counts are displayed in the same formatted table as the reference statistics, maintaining the existing output style.

Key technical details:
- Introduces `struct object_stats` to track counts by object type
- Adds `struct repo_stats` to combine reference and object statistics
- Implements `count_objects()` callback for path-walk traversal
- Uses `walk_objects_by_path()` with pending objects from all references
- Extends test coverage in t1901-repo-stats.sh with object count verification
- Updates documentation in git-repo.adoc to mention the new object counting feature

The implementation builds on the table formatting and i18n support added in earlier patches, and follows the same pattern of comprehensive testing seen throughout the series. The tests verify both empty repository behavior and counts in a populated repository (with specific expected values for 42 test commits plus tags/notes).

This patch represents a logical extension of the repository statistics functionality, providing more complete insight into repository health by including object data alongside the existing reference counts. The implementation appears thorough, with proper cleanup of allocated resources and BUG() assertions for unexpected cases.
