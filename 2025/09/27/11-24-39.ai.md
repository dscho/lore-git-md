This is a documentation patch addressing a discrepancy in how `push.default=simple` is described between Git's configuration and push documentation.

The patch highlights that git-config's description of `push.default=simple` is misleading compared to git-push's more accurate version. The key difference is that git-config's wording ("if you are working on a centralized workflow...") incorrectly suggests configuring an upstream branch is only sometimes needed, when in fact it's always required for this mode to work.

The git-push documentation correctly states that `simple` always requires the upstream branch to have the same name as the local branch, and will abort if this isn't the case. This safety measure is a core part of the `simple` mode's design, particularly important since it's the default push behavior since Git 2.0.

The patch doesn't propose specific wording changes but clearly identifies the inconsistency. This appears to be a straightforward documentation clarification that would help users better understand the `simple` push mode's actual requirements. The issue affects the official Git documentation at git-scm.com, which is widely referenced by users.
