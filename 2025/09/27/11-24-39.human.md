This is a documentation patch addressing a discrepancy in how `push.default=simple` is described across Git's documentation.

雨 欣 points out that the description of `push.default=simple` differs between the `git-config` and `git-push` man pages, with the `git-config` version being potentially confusing. The key issue is that `git-config` suggests configuring an upstream branch is only needed "if you are working on a centralized workflow," while `git-push` correctly states that the upstream branch name must always match the local branch name as a safety measure.

The patch highlights an important documentation inconsistency for a fundamental Git configuration that affects many users, since `simple` is the default push mode since Git 2.0. The current wording in `git-config` could mislead users about when upstream branches are required. This seems like a straightforward documentation improvement that would help clarify behavior for users, particularly beginners who rely on the default settings.
