Feature patch expanding Rust libgit configuration parsing to include unsigned long and pathname types, following the established FFI-wrapped pattern from the boolean implementation.

This final patch in the v3 series adds two new methods to the Rust libgit ConfigSet API: `get_ulong()` for parsing unsigned 64-bit integers and `get_pathname()` for handling filesystem paths (returning Rust's `PathBuf` for type safety). Both follow the same FFI-wrapping approach used for boolean parsing in `get_bool()`, calling through to Git's C functions (`git_configset_get_ulong()` and `git_configset_get_pathname()`) via the `libgit-sys` FFI layer.

Key technical details:
- `get_ulong()` returns `Option<u64>` and handles large values (test case shows 4294967296 to verify 64-bit handling)
- `get_pathname()` returns `Option<PathBuf>` and properly frees the C-allocated string
- Both methods include comprehensive test coverage in `config4` test file:
  - Normal cases (small/large numbers, relative/absolute paths)
  - Missing key handling
- Maintains same error behavior as C implementation (fatal error on parse failure)
- Updates FFI bindings in `libgit-sys` with new function declarations
- Follows same memory safety patterns as boolean implementation (proper string freeing for paths)

The implementation appears technically sound, matching the project's requirement to wrap rather than reimplement Git's config parsing logic. This expands the scope beyond the originally discussed functionality (which focused only on boolean parsing), so maintainer approval of the expanded scope is the primary open question. The patch builds on the v3 series' established pattern where the boolean implementation served as the reference model.
