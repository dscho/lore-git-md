Feature patch (part 2/3) implementing boolean config parsing in Rust libgit, still showing transitional state between native Rust and FFI-wrapped approaches.

This patch adds a `get_bool()` method to the Rust `ConfigSet` API, implementing boolean value parsing for Git configuration. The method accepts standard Git boolean formats (true/yes/on/1 and false/no/off/0) through case-insensitive comparison. The implementation currently builds on the existing `get_string()` infrastructure rather than directly wrapping Git's native `git_configset_get_bool()` as previously directed by maintainers.

The 24-line change in `config.rs` shows a Rust-native parsing approach, converting the config value to a string and performing boolean interpretation in Rust rather than using the FFI-wrapped C function. This appears to be an interim state in the transition, as the maintainer feedback in the thread clearly indicated the need to use `git_configset_get_bool()` through the FFI layer for consistency with Git core behavior.

The patch includes basic test coverage through modifications to `config3`, adding a boolean test case and verifying both successful parsing and handling of missing keys. However, the test doesn't yet exercise the full range of boolean formats (yes/no/on/off variants) that Git supports, nor does it validate edge cases around whitespace or invalid values.

This appears to be work-in-progress toward the maintainer's requested architecture, but hasn't yet fully transitioned to the FFI-based approach. The implementation maintains Rust safety practices with proper pointer handling and string conversion, but the core architectural question of whether to parse in Rust or wrap the C implementation remains unresolved in this version.
