Refactoring patch in the `git repo stats` series (2/7) to improve NULL pattern handling in ref-filter.

This small but important change makes the ref-filter subsystem more robust by properly handling NULL `name_patterns` in `struct ref_filter`. Currently, callers must provide an empty array even when no patterns are needed. The patch modifies two key functions (`filter_pattern_match()` and `for_each_fullref_in_pattern()`) to treat NULL the same as an empty array, which simplifies calling code and prevents potential NULL dereferences.

The change is straightforward - just adding NULL checks before array access - but touches core reference filtering logic. It's part of the infrastructure work needed for the new `git repo stats` command's reference counting functionality. The patch follows the series' established pattern of small, focused changes (only 4 lines modified) and maintains consistency with Git's existing error handling patterns.

This is still under review in the v4 series, with no outstanding questions raised about the NULL pattern handling approach. The change appears uncontroversial but merits careful review since it affects reference traversal behavior.
