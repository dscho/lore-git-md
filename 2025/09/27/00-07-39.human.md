This is the final patch in a 3-part series implementing boolean config handling in Rust libgit, now addressing maintainer feedback to use Git's native C implementation rather than reimplementing the logic in Rust.

The patch fully transitions to using `git_configset_get_bool()` through FFI as directed by Junio Hamano, removing the previous Rust-native string parsing code. It improves error messages and adds comprehensive test coverage in a new `config4` file that exercises all boolean formats (true/false, yes/no, on/off) and edge cases like "00", "100", and "007". The implementation now properly delegates to Git's core logic for boolean parsing rather than maintaining a separate implementation.

This completes the architectural shift requested in v1 reviews, though the series still includes an unrelated documentation fix that could potentially be split out. The changes show good attention to detail in test coverage and error handling, and the patch appears ready for final review now that it properly wraps Git's native functionality.
