This is the final patch in a 3-part series implementing boolean config handling in Rust libgit, now addressing key review feedback by fully transitioning to FFI-wrapped C implementation. The patch completes the architectural shift from Rust-native parsing to using Git's `git_configset_get_bool()` through the FFI layer, as required by maintainers.

The changes focus on the boolean parsing implementation in `config.rs`, replacing the previous string-based approach with direct FFI calls to the C function. A new test file `config4` is added with comprehensive boolean test cases covering all valid formats (true/false, yes/no, on/off) and edge cases like numeric values (1/0, 00, 100). The implementation now properly frees allocated memory and includes more descriptive error messages.

Key technical details include:
- Removal of Rust-native string parsing logic in favor of FFI-wrapped `libgit_configset_get_bool()`
- New FFI binding in `libgit-sys/src/lib.rs` for the boolean function
- Expanded test coverage with 9 distinct boolean test cases in new `config4` file
- Cleaned up test organization by moving boolean tests to dedicated config file
- Improved error handling with more specific `.expect()` messages

The patch successfully addresses the core architectural concern from v1 reviews by eliminating the Rust reimplementation and properly using Git's native boolean parsing through FFI. The comprehensive test suite should ensure behavior matches Git core exactly, including edge cases like "007" parsing as true. This appears to complete the series' main objective while maintaining the documentation fix from earlier patches.
