This thread addresses a documentation inconsistency regarding `push.default=simple` behavior between Git's configuration and push documentation. The git-config description misleadingly suggests configuring an upstream branch is only sometimes needed for this mode, while git-push correctly states it's always required - the local and upstream branch names must match, otherwise the push aborts. This safety mechanism is particularly important since `simple` has been the default push behavior since Git 2.0.

The patch highlights this discrepancy but doesn't yet propose specific wording changes. The issue affects the in-tree documentation as well as the widely-referenced content on git-scm.com. Given that this is a straightforward documentation clarification about a fundamental behavior (especially relevant since it's the default), it will likely be quickly addressed once proper wording is proposed.
