This is a refactoring patch in the `git repo stats` series that makes the ref-filter interface more flexible by allowing NULL filter patterns.

The patch modifies two functions in ref-filter.c to treat a NULL `name_patterns` field the same as an empty array of patterns. Currently, callers must provide an allocated array even when they don't want any pattern matching. The changes are minimal but improve the API by removing this artificial requirement.

The modifications affect `filter_pattern_match()` and `for_each_fullref_in_pattern()`, both core functions in the ref-filter machinery. The change is straightforward - each function now checks for NULL before dereferencing the patterns array. This maintains all existing behavior while adding the NULL case as equivalent to "no patterns".

This appears to be a preparatory change for the repo-stats feature, though the commit message doesn't explicitly state the connection. The patch is small (4 lines changed) and focused, with no apparent downsides to the change. It follows the pattern of the series where infrastructure improvements are made incrementally before building new functionality on top.

The patch is currently under review as part of the v4 submission of the repo-stats series. It addresses a minor but real API wart in the ref-filter code that could benefit other callers beyond just the new stats command. The change is low-risk since it only relaxes requirements without altering the core pattern matching logic.
