This is part 2/3 of a series implementing boolean config handling in the Rust libgit implementation (`contrib/libgit-rs`). The patch adds a `get_bool()` method to the `ConfigSet` API, following Git's standard boolean parsing rules (accepting true/yes/on/1 and false/no/off/0).

The implementation builds on existing `get_string()` infrastructure, adding case-insensitive parsing logic in Rust. It includes basic test coverage with a new boolean value in the `config3` test file. However, this appears to be a Rust-native implementation rather than using the FFI-wrapped `git_configset_get_bool()` as previously directed by maintainers - a key architectural requirement that was established in earlier feedback.

The patch is technically sound for what it implements, with proper memory management (freeing the C string) and test coverage. But it seems to be going against the maintainer's clear guidance to wrap the C implementation rather than reimplementing the logic in Rust. This may need to be reworked in a future version to align with the project's FFI-first approach for core functionality.
