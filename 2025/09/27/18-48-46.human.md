This is a feature request for partial URL matching in Git's credential configuration system. The author, M Hickford, identifies a use case where users might want different credentials for different path prefixes under the same host (e.g., `example.com/org1` vs `example.com/org2`). Currently, Git's credential matching requires exact path matches or matches only at the host level.

The request comes from a real-world need in the git-credential-oauth project, where users want to manage credentials for different organizations under the same domain. The author proposes two possible syntax options for wildcard matching: an explicit wildcard (`*`) or an implicit wildcard (trailing slash).

This appears to be a well-motivated request that would add useful flexibility to Git's credential system. The proposal is clearly explained with concrete examples and links to relevant documentation. The change would likely require modifications to Git's credential URL matching logic but seems conceptually straightforward.
