This is a feature patch adding machine-readable output formats to the `git repo stats` command, part of the ongoing series introducing repository health reporting functionality.

The patch introduces two new output formats alongside the existing human-readable table format: `keyvalue` (newline-delimited `key=value` pairs with c-quoting for special characters) and `nul` (NUL-delimited records with newline-separated keys/values, avoiding the need for quoting). The implementation includes a new `stats_keyvalue_print()` helper function that handles both formats with configurable delimiters, and extends the option parsing in `cmd_repo_stats()` to support the `--format` parameter.

The changes affect three files: builtin/repo.c (core implementation), Documentation/git-repo.adoc (updated command syntax and format descriptions), and t/t1901-repo-stats.sh (new tests verifying format parsing and output correctness). The tests create a repository with known quantities of objects and references, then verify both formats produce the expected output with proper delimiter handling.

This builds on the reference and object counting infrastructure from previous patches in the series, maintaining the same statistical categories (branches, tags, remotes, other refs, commits, trees, blobs). The implementation follows Git's established patterns for machine-readable output formats, with the NUL variant being particularly suited for scripting as it avoids quoting complexities. The patch appears complete with thorough documentation and test coverage, suggesting it's ready for review.
