Feature patch implementing boolean config parsing in Rust libgit via FFI.

This patch (v3 2/3 in the series) adds boolean configuration value parsing to the Rust libgit implementation by wrapping Git's native `git_configset_get_bool()` C function through FFI. The implementation handles all Git boolean formats (true/false, yes/no, on/off, 1/0) and edge cases like "00" and "100" consistently with core Git behavior. 

The patch adds a new `get_bool()` method to the `ConfigSet` struct that returns `Option<bool>`, with `None` indicating a missing key. It includes comprehensive test coverage in a new `config4` test file that verifies all supported boolean formats and edge cases. The FFI binding is added to `libgit-sys/src/lib.rs` to expose the C function to Rust.

This implementation follows the maintainer-required approach of using FFI-wrapped C functions rather than reimplementing the logic in Rust, as confirmed in previous discussion rounds. The boolean handling matches Git's native behavior exactly, including edge case treatment where "00" evaluates to false and "100" to true. The patch appears technically sound with thorough test coverage and clean integration into the existing codebase.

As part of the v3 series that expands beyond the original boolean-only scope to include ulong and pathname parsing, this patch represents the already-approved core functionality that other methods now follow. The boolean implementation serves as the model for the additional methods in patch 3 of the series.
