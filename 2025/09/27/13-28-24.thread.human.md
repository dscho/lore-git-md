This thread focuses on improving the `git worktree` documentation to address common usage pitfalls, particularly around nested worktrees and bare repository setups. Michal Suchánek has submitted two patches: one adding warnings about nested worktree creation, and another demonstrating recommended branch checkout patterns from bare repositories.

The discussion has converged on several key principles. First, nested worktrees should be avoided due to complications with untracked directories and gitignore behavior. Second, when working with bare repositories, worktrees should be created as siblings rather than subdirectories to prevent conflicts with Git's internal structures. Junio Hamano recently reinforced this by rejecting an alternative approach that would place worktrees inside bare repositories, citing safety concerns.

The patches are in good shape but still need some refinements. Kristoffer Haugsbakk has provided detailed formatting feedback and suggested adding more motivation text for the bare repository examples. Junio has tentatively queued the current version while leaving room for these final improvements. The thread demonstrates how documentation can address UX concerns even when behavior changes aren't feasible, while respecting Git's underlying design constraints.
