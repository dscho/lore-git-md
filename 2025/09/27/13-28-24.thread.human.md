This thread began with a user question about why `git worktree add` creates directories that show up as untracked in the main repository's status. The user, who has been using Git since 2010 but only recently started using worktrees, expected these directories to be automatically ignored.

Junio C Hamano, Git's maintainer, provided the authoritative answer. He explained that this behavior is intentional - worktree directories are treated like any other directory containing a Git repository (similar to a nested clone), and they aren't special-cased for ignoring. Junio noted that automatically ignoring them would actually be inconvenient for some workflows. 

Instead of expecting Git to ignore worktree directories, Junio recommended creating worktrees outside the main working tree directory if their untracked status is problematic. He shared his own workflow as an example, where he creates worktrees in sibling directories (like ../git.maint and ../git.next) rather than within the main working tree.

The response effectively resolves the original question by clarifying that this is working as designed, though it leaves open whether this behavior might be reconsidered in future Git versions. For now, users who find the untracked status bothersome should either create worktrees elsewhere or manually add them to .gitignore.
