This thread documents improvements to `git worktree`'s user experience through clearer manual pages, sparked by questions about worktree behavior in Git 2.51.0. The discussion has produced two concrete documentation patches from Michal Suchánek, with active review from Kristoffer Haugsbakk and Junio Hamano.

The first patch adds explicit warnings against creating nested worktrees (noting they can cause gitignore complications) and establishes EXAMPLES section formatting. The second patch demonstrates recommended directory layouts for parallel branch checkouts from bare repositories. Junio recently suggested revising the bare repo example to avoid naming it `.git` (which could confuse users) in favor of clearer names like `project.git`. He also presented an alternative workflow using a primary worktree, acknowledging both patterns exist in practice.

Kristoffer Haugsbakk has provided detailed formatting reviews, pushing for simpler examples and motivation text. Junio has tentatively queued the current version pending these refinements, maintaining the thread's documentation-only approach. The patches now need final wording adjustments around nested worktree warnings, example simplification, and cross-references to related commands like `git clone`.

This effort connects to broader documentation consistency work led by Jean-Noël Avila and represents Git's typical pattern of addressing UX concerns through improved docs when behavior changes are constrained by design decisions.
