This is a follow-up discussion about Git worktree behavior, specifically questioning the consistency of how worktree directories are treated in `git status` output.

Michal Suchánek responds to Junio Hamano's earlier explanation that worktree directories are intentionally treated like any other directory containing a Git repository. While acknowledging that worktrees are separate repositories, Michal points out an apparent inconsistency: a worktree's own `.git` directory doesn't appear as untracked in its own status output, yet worktrees created from the main repository do show up as untracked in the main worktree's status.

The email doesn't propose any changes but raises this observation as a potential design inconsistency. This follows Junio's authoritative response in the thread that established the current behavior as intentional. The discussion remains technical and focused on understanding the rationale behind the implementation choices.
