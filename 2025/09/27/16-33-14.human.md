This is a clarification on the i18n handling in the `git repo stats` series. Junio Hamano points out that while Justin Tobler correctly switched from `strlen()` to `utf8_strwidth()` for table formatting (to properly handle multi-column Unicode characters), there was some confusion in the explanation. The key distinction is that `utf8_strwidth()` measures display columns (important for alignment), not just byte length or character count. 

The note serves to prevent reader confusion without requiring a resend, since the technical implementation is correct. This comes as part of ongoing review of the series' internationalization support, following earlier feedback from Eric Sunshine. The series remains under review with all core functionality implemented, including proper Unicode-aware table formatting.
