This is a discussion about the Rust integration rollout strategy and Git 3.0 planning. Phillip Wood responds to Patrick Steinhardt's proposed transition plan for making Rust mandatory in Git, expressing skepticism about the effectiveness of the current opt-in approach for gathering feedback.

Phillip argues that making Rust builds default from the start (with opt-out) would provide more meaningful feedback than the current plan of auto-detection in Meson and default-disabled in Makefile. He references Elijah Newren's similar argument elsewhere in the thread. The concern is that the current approach might not surface platform-specific issues early enough, as many users on unsupported platforms might simply skip Rust builds entirely.

The email also touches on Git 3.0 release planning, with Phillip suggesting that firming up the 3.0 release date would help focus efforts on other potential breaking changes like config defaults for commit, merge, and rebase behaviors. This connects to the broader context where Patrick had proposed making Git 2.55 become 3.0 in about a year's time.

The discussion reflects ongoing tensions in the Rust integration - balancing the need for early feedback against the risk of overwhelming maintainers with bug reports, while also coordinating with other major changes planned for Git 3.0. Phillip's perspective as a core contributor adds weight to the argument for a bolder rollout strategy.
