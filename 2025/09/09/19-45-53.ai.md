This is a test patch in the command deprecation framework series, specifically adding coverage for alias shadowing behavior. It builds on the previous patch which tested shadowing of deprecated commands, now extending the test suite to verify that regular (non-deprecated) builtins cannot be shadowed, as documented in git-config(1).

The patch adds a new test case that exercises a representative sample of Git commands (`grep`, `check-ref-format`, `interpret-trailers`, `checkout-index`, `fast-import`, `diagnose`, `rev-list`, `prune`) to confirm they cannot be overridden by aliases. The test helper `cannot_alias_regular_builtin` checks that attempting to shadow these commands with aliases fails as expected, maintaining the original command behavior.

Key technical details:
- Tests verify the documented behavior that only deprecated commands can be shadowed by aliases
- Uses `test_might_fail` to handle commands that may legitimately fail when run with `-h`
- Samples commands from different Git subsystems to ensure broad coverage
- Avoids testing all builtins due to performance concerns (600ms overhead mentioned in notes)

This patch completes the test coverage for the alias shadowing functionality introduced earlier in the series, ensuring both deprecated and regular command behaviors are properly validated. The implementation follows the pattern established in previous patches while addressing the performance consideration by testing a representative subset rather than all builtins.
