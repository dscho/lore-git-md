This is a bugfix patch in the ODB transaction refactoring series, addressing an edge case in `git update-index --verbose` behavior. The patch comes from Justin Tobler and is part of Patrick Steinhardt's larger ODB abstraction effort.

The patch fixes an awkward interaction between `update-index --verbose` and ODB transactions. Currently, when --verbose is used, each object write is flushed (but not committed) to make objects visible to callers parsing the verbose output. This defeats the transaction benefits while keeping the transaction open. The patch changes this to properly end the transaction when --verbose is first encountered, then proceed with non-transactional writes.

Key technical changes:
- Removes `flush_odb_transaction()` call from report() function
- Adds early transaction end when --verbose is detected in command processing
- Updates transaction handling to be NULL-safe at final cleanup
- Maintains backward compatibility for callers relying on verbose output synchronization

The change simplifies the code while better matching user expectations - once verbose output is requested, all subsequent writes are explicitly non-transactional. This is a focused improvement to a specific edge case in the larger ODB transaction refactoring work. The patch appears well-contained with clear commit message explanation of both the problem and solution.
