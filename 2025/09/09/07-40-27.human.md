This is a discussion about submodule path handling in the ongoing series to encode submodule gitdir paths for better filesystem compatibility. Patrick Steinhardt raises concerns about how the proposed move of encoded submodules to `.git/submodules/` (while keeping legacy paths in `.git/modules/`) might affect alternative Git implementations like libgit2, JGit, and Gitoxide.

The key points are:
1. While Git will handle both old and new paths, other implementations may not automatically recognize the new `.git/submodules` location, potentially making this a backwards-incompatible change for them.
2. Steinhardt suggests a more robust solution would be a `submodule.*.repoPath` config key that explicitly records where each submodule is stored, eliminating the need to guess paths. However, he notes this doesn't currently exist.

This email doesn't propose any code changes but highlights an important interoperability consideration for the series. The discussion suggests the current approach may require coordination with other Git implementations, though the config override mechanism mentioned in the thread summary (submodule.<name>.gitdirpath) may already address some of these concerns. The thread context indicates this is part of a well-tested, production-ready series that's already incorporated significant reviewer feedback.
