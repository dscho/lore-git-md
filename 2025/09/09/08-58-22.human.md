Refactoring patch in the xdiff internals series, adding enum-style constants for rchg values. This is patch 9/17 in Ezekiel Newren's series preparing xdiff for Rust compatibility.

The patch introduces NO/YES/MAYBE macros (0/1/2) to replace magic numbers when working with the rchg array, which tracks line change status in the diff algorithm. The change is mechanical but makes the code more readable. The author suggests 'rchg' could be renamed to 'changed' in a follow-up.

Elijah Newren's review notes several places where the patch assumes MAYBE values won't occur in certain contexts, suggesting this assumption should be documented in the commit message. He also points out that some changes in xdl_build_script() appear unrelated to the enum conversion and might belong in a separate cleanup patch.

The changes are widespread but straightforward, touching xdiffi.c, xhistogram.c, xpatience.c and xprepare.c. The patch maintains existing behavior while making the code's intent clearer through named constants. This continues the series' pattern of incremental improvements to xdiff's internal data structures.
