This thread continues work on refactoring Git's object database (ODB) transaction handling as part of the larger effort to enable pluggable storage backends. Patrick Steinhardt and Justin Tobler are leading the technical work, with the series now focusing on cleaning up edge cases in the transaction API.

The core of the work moves transaction code from the specialized bulk-checkin subsystem into object-file.c while establishing clearer separation between generic ODB interfaces and filesystem-specific implementations. Recent patches have removed transaction nesting capability and standardized function naming (using `odb_transaction_begin/end` for the generic layer and `object_file_transaction_begin/commit` for the files backend).

The latest patch addresses a subtle interaction in `git update-index --verbose` where the verbose output behavior was creating awkward intermediate transaction states. Justin Tobler proposes ending transactions immediately when `--verbose` is encountered, since subsequent object writes need to be immediately visible for the output to be useful. This maintains transactional safety for earlier writes while simplifying the control flow. The change responds to Patrick Steinhardt's earlier review questions about transaction purpose in different modes.

The series appears technically sound with broad agreement on direction, though reviewers should pay particular attention to the edge cases around transaction timing with verbose output. Remaining work includes finalizing some API details (like the `_end` vs `_commit` naming for files-backend functions), adding documentation for the new interfaces, and verifying all transaction edge cases are handled properly in the new location. This work builds toward the larger goal of making Git's object storage fully pluggable.
