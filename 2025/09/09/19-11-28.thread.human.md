This thread continues the ongoing refactoring of Git's object database (ODB) transaction interfaces, part of the larger effort to enable pluggable backends. The series, primarily authored by Patrick Steinhardt with contributions from Justin Tobler, has progressed to version 2 with several key improvements.

The core work relocates transaction handling code from the bulk-checkin subsystem to object-file.c, establishing clearer API boundaries between generic ODB operations and filesystem-specific implementations. Recent patches have simplified the transaction model by removing support for partial flushing and nesting, enforcing a cleaner all-or-nothing commit model. The latest change eliminates the now-unused `flush_odb_transaction()` function, folding its remaining operations into `end_odb_transaction()` for a more straightforward interface.

Justin Tobler has addressed several edge cases in v2, including making transaction cleanup NULL-safe, improving documentation, and refining how `git update-index --verbose` handles transactions. The series has drawn careful review from Patrick Steinhardt, who has confirmed the architectural direction while noting some temporary awkwardness in the mixed ODB/files-backend code that will be resolved as pluggable backends mature. With all callers already migrated away from partial flushing, this latest removal completes the simplification of the transaction API.

The changes pave the way for future work where transactions will route through the source->backend interface when pluggable backends are implemented. Some loose ends remain around verifying no hidden dependencies exist and confirming backward compatibility, but the core refactoring appears complete and well-reasoned.
