This thread documents a 6-part refactoring series by Patrick Steinhardt and Justin Tobler that restructures Git's object database (ODB) transaction handling. The work transitions from the old "bulk-checkin" terminology to a clearer "transaction" model while separating the public API from files-backend implementation details.

The series establishes a clean ODB transaction interface with NULL-safe operations, relocates code from bulk-checkin.[ch] to object-file.[ch], and removes the partial flush API. The final patch introduces public-facing `odb_transaction_{begin,commit}()` functions in odb.[ch] while renaming the implementation-specific versions to `object_file_transaction_*()`. This completes the architectural separation needed for pluggable ODB backends.

All patches have been reviewed, with Junio Hamano validating the safety guarantees and Taylor Blau initially raising concerns about nesting behavior that were addressed. The changes are mechanical renames and caller updates (affecting 9 files) with no behavior modifications. The work builds on prior bulk-checkin refactoring and connects to the broader ODB abstraction effort that will enable alternative storage backends like reftable.
