This is a brief follow-up in the ongoing thread about fixing color handling in Git's interactive patch mode. Patrick Steinhardt is responding to Jeff King's explanation about why the patch series continues using `-1` for uninitialized color states rather than switching to `GIT_COLOR_UNKNOWN`.

The exchange clarifies that while `GIT_COLOR_UNKNOWN` would be a more semantically meaningful choice, the current codebase widely uses `-1` for this purpose, and standardizing on a proper enum would require a much broader refactoring. Jeff argues this cleanup is better deferred to avoid scope creep in the current regression fixes, and Patrick concurs with this approach.

This email doesn't introduce new technical changes - it's simply confirming agreement on a design decision made in the patch series. The thread remains focused on fixing the interactive mode color regressions while leaving larger color system cleanups for future work.
