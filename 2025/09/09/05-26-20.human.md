This is a technical discussion about reftable compatibility with Git's dumb HTTP protocol, continuing the thread about repository path handling. Patrick Steinhardt acknowledges Junio Hamano's point that his earlier reftable-based solution proposal (using "tables.list" to replace `info/refs`) doesn't fully address the dumb HTTP requirements. While tables.list could handle ref storage atomically, it doesn't solve the separate problem of pack file discovery, which would still require `git update-server-info` to list available pack files. This confirms that even with reftable adoption, the fundamental limitations of dumb HTTP's file discovery mechanism would remain unchanged. The exchange reinforces the technical constraints that make the current behavior necessary rather than a bug to be fixed.
