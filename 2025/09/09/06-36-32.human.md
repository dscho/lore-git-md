This is a documentation patch in a series introducing atomic reference updates for `git replay`. The author, Siddharth Asthana, responds to Christian Couder's review of the initial documentation, agreeing to combine the docs with the implementation patch in v2 and reconsider the flag design.

The discussion reveals several design questions about the new `--update-refs` functionality:
- Whether to keep both `--update` and `--update-refs` flags or consolidate to a single flag with modes
- How to clarify the atomicity differences between modes (default atomic vs `--batch` partial updates)
- Potential naming conflicts with `git rebase --update-refs`
- Need for clearer documentation about failure handling behavior

Asthana leans toward simplifying to a single `--update-refs` flag with optional batch mode, dropping the separate `--update` flag that mimics `git update-ref --stdin` behavior. The response shows good engagement with reviewer feedback and willingness to refine both the implementation and documentation approach.

This patch represents the documentation half of a 2-part series that aims to provide atomic ref updates for server-side workflows. The discussion has progressed from high-level design to specific implementation concerns, with this email focusing on documentation clarity and flag naming. The next version will likely show a more consolidated approach based on the feedback received.
