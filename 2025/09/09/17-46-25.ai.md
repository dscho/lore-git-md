This is a technical discussion about the submodule gitdir path encoding series, specifically addressing Patrick Steinhardt's concerns about cross-implementation compatibility. Adrian Ratiu clarifies that the config override mechanism (`submodule.<name>.gitdirpath`) is not intended as a universal solution for alternative Git implementations, but rather as a simple override capability.

- Plans to improve error messaging when path conflicts occur, suggesting users enable the extension
- Considers eliminating the separate `.git/submodules/` directory in favor of using `.git/modules/` with random suffixes when the feature is enabled via extension
- Acknowledges the config override's limited role while maintaining focus on the extension-based approach for v3

The discussion shows alignment on moving forward with repository extensions as the primary compatibility mechanism, while keeping the config override as an auxiliary feature.
