This is a refactoring patch series (v4, 15 patches) that introduces a new `struct packfile_store` to centralize packfile management in Git's object database. The series is part of the larger effort to enable pluggable object databases by cleaning up the current scattered packfile tracking across `struct packed_git` and `struct object_database`.

Patrick Steinhardt has addressed all major technical feedback from previous rounds, with Karthik Nayak providing thorough reviews. The v4 changes are minor style and commit message improvements based on Junio and Karthik's suggestions. The series is in final polishing state with no outstanding architectural concerns.

Key changes in this version:
- Dropped the meaningless `inline` hint from `pack_map_entry_cmp()` (callback functions can't be inlined)
- Improved commit message clarity around the packfile map movement
- Small code style tweaks

The series systematically moves packfile-related fields and functions into the new `struct packfile_store`, touching many parts of the codebase (31 files modified). This foundational work will enable future patches to make packfiles work with pluggable object databases by decoupling them from the core object database structure.

With all major review feedback addressed and only minor nits remaining, this series appears ready for maintainer consideration. The careful multi-round review process has resulted in a clean, well-documented refactoring that paves the way for future object database improvements.
