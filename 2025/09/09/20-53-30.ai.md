This is a follow-up discussion about gitk's Tk widget theming, specifically addressing the removal of classic widget support. The email builds on a previous bug report where disabling "Themed widgets" broke gitk's preferences dialog, which was fixed in Git 2.50.0.

Mark Hills points out that while the immediate bug was fixed, commit cb9fa4d9ecd9 in Git 2.51.0 completely removed support for classic Tk widgets (non-themed) from gitk. He questions this decision, arguing that removing a feature just because it's not the default seems excessive, especially since users had actively contributed fixes for this functionality. The commit in question, by Mark Levedahl, justified the removal by citing reduced maintenance burden since themed widgets (ttk) are now well-tested as the default path and Tk 8.4 (which lacked ttk) is no longer common.

The discussion highlights a tension between code maintenance and backward compatibility, with Hills suggesting the removal may have been too aggressive given that at least one user (himself) actively uses and maintains the non-themed widget path. The email references specific commits (904b36b815ff for the bug introduction, daa364cfb7a1 for the fix, and cb9fa4d9ecd9 for the removal) and versions (Git 2.48.0 through 2.51.0) that trace this functionality's lifecycle.
