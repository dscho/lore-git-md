This is a technical discussion about the submodule gitdir path encoding series, specifically addressing the need for a version marker to prevent compatibility issues with older Git versions and other implementations.

Adrian Ratiu responds to Phillip Wood's concerns about older Git versions potentially failing to locate submodule gitdirs under the new `.git/submodules/` path. While initially unsure about the necessity, Adrian now agrees with Phillip's assessment that an `extensions.submoduleEncoding` config key is the safest approach. The key insight is that the issue extends beyond just Git core - other implementations like JGit and libgit2 would also be affected by the path structure change.

The discussion confirms that simply relying on the `.git` file in the working tree isn't sufficient for all access patterns, making the extension key necessary to prevent potential corruption when different Git versions or implementations interact with the repository. This aligns with the series' goal of maintaining backward compatibility while introducing the encoded path scheme.

The email reinforces the technical justification for the version marker that Phillip Wood had previously identified, moving this aspect of the design closer to resolution while other architectural questions about the migration strategy remain open from Patrick Steinhardt's earlier feedback.
