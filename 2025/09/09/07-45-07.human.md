Platform compatibility discussion about test framework integration strategy.

Patrick Steinhardt weighs in on the HP-UX build fix thread, proposing an alternative approach to handling the mkdtemp() compatibility issue in the clar test framework. Rather than including Git's compat/posix.h (which modifies the imported clar code), he suggests extending clar's existing platform-specific handling to support HP-UX using mktemp() where available.

The email notes clar already has special cases for Windows, MinGW, Solaris, and Tandem systems, and proposes adding HP-UX to that list. Patrick acknowledges uncertainty about the exact preprocessor macro HP-UX defines, but outlines the general approach that would work if mktemp() is present on HP-UX. He offers to implement and upstream this change to clar if it proves viable.

This moves the discussion toward a more maintainable long-term solution that would benefit both the Git codebase and other projects using clar, rather than having Git maintain local modifications to the test framework. The proposal appears technically sound but awaits confirmation about HP-UX's specific capabilities and defines before proceeding.
