This is part 3 of a 6-part refactoring series simplifying Git's object database transaction interface, building on Patrick Steinhardt's earlier work. Justin Tobler contributes this patch to clean up the transaction API by removing the `flush_odb_transaction()` function, which allowed partially committing a transaction without properly finalizing it.

The change eliminates an awkward intermediate state in the transaction API where objects could be made visible without properly completing the transaction. Now all transaction finalization must go through `end_odb_transaction()`, making the behavior more predictable. The patch removes both the function implementation and its declaration from the header file, showing this was a deliberate design simplification rather than just dead code removal.

The change is straightforward - it moves the flushing logic directly into `end_odb_transaction()` and removes the now-unused intermediate function. This continues the series' trend of making the transaction model more strict and explicit. The patch appears well-contained, touching only the bulk-checkin implementation files, and follows logically from the earlier work in the series.
