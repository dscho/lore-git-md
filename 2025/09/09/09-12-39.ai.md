Phillip Wood responds to Patrick Steinhardt's Rust transition plan in the ongoing RFC series about making Rust mandatory in Git. This is part of the broader Rust infrastructure discussion that has spanned 10 versions with extensive technical debate.

Wood expresses skepticism about the proposed gradual rollout" approach where Rust would be auto-detected in Meson but disabled in Makefile builds initially. He argues this won't generate enough early feedback from users, echoing Elijah Newren's earlier suggestion to make Rust enabled by default from the start to properly test platform compatibility. The concern is that without broad testing, problems might only surface when Rust becomes mandatory.

The email also touches on Git 3.0 release timing, with Wood sees as an opportunity to align other potential breaking changes like config defaults for commit.verbose, merge.conflictStyle, and rebase behavior. He suggests having a firm 3.0 deadline would help prioritize these changes.

This continues the rollout strategy debate started by Newren, adding Wood as another voice advocating for more aggressive early testing of Rust integration. The discussion remains focused on practical concerns about getting sufficient real-world testing before the mandatory switch, rather than the deeper technical debates about type safety and build systems that dominate other parts of the thread. Wood's mention of other potential 3.0 changes hints at the broader scope of decisions that need coordination around the Rust transition timeline.
