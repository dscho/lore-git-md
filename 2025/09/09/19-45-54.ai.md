This is the fourth patch in a 7-part series implementing command deprecation with alias shadowing support, focusing on improving user-facing error messages when deprecated commands are used. The patch enhances the `you_still_use_that()` function in usage.c to provide more actionable guidance when users attempt to run deprecated commands like `whatchanged` or `pack-redundant`. Instead of just telling users to email the list, it now offers a structured set of next steps: checking BreakingChanges documentation, searching mailing list archives, and only then contacting the list if no solution is found.

Key technical changes include:
- Adding a strbuf to properly percent-encode the command name for mailing list search URLs
- Restructuring the error message into clear bullet points (though rendered without actual bullet characters)
- Removing the "--i-still-use-this" option mention since it would appear redundant next to the new guidance
- Maintaining the same fatal error outcome while making the messaging more helpful

The patch addresses Eric Sunshine's feedback from earlier versions about making the messaging more actionable. It also resolves Kristoffer Haugsbakk's own concern about documentation discoverability by directly linking to BreakingChanges.html. The implementation handles URL encoding properly and maintains clean memory management with strbuf_release().

This represents the user experience polish component of the larger deprecation framework, working in concert with the technical infrastructure added in earlier patches. The changes are focused and well-contained to the error reporting mechanism, with no impact on the core deprecation logic.
