This is a refactoring patch in the xdiff Rust compatibility series, specifically patch 8/17. It removes the redundant `chastore_t` from `xdfile_t` and converts all record access from pointer-based to direct struct access.

The key technical changes are:
- Removes `xdfile_t.rcha` (chastore allocator) and converts `recs` from `xrecord_t**` to `xrecord_t*`
- Updates all record access sites to use direct struct access (`recs[i].field`) instead of pointer dereferencing (`recs[i]->field`)
- Affects multiple xdiff files: xdiffi.c, xemit.c, xhistogram.c, xmerge.c, xpatience.c, xprepare.c, xtypes.h, xutils.c
- The change is motivated by Rust FFI compatibility needs and redundancy (recs was already a growable vector)

The patch maintains identical behavior while simplifying the data structure. Elijah Newren provides positive feedback but suggests improving the commit message by:
1. Moving the "--color-words" note to the end
2. Including more explanation about the redundant dual-layering between chastore_t and recs from the original RFC discussion

This continues the series' pattern of structural cleanups before introducing Rust-specific changes. The changes are mechanical but widespread, touching record access patterns across the xdiff implementation. The patch appears well-executed with comprehensive updates to all affected call sites.
