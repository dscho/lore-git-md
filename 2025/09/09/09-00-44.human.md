This is a technical discussion about interface design for the `git replay --update-refs` feature, part of the ongoing effort to enable atomic reference updates for server-side workflows.

Patrick Steinhardt responds to Siddharth Asthana's proposal to simplify the update modes in `git replay`. The discussion centers around two competing approaches for handling partial ref updates: using a separate `--allow-failures` flag versus an optional `--update-refs[=<mode>]` parameter syntax. Steinhardt advocates for the parameter syntax, arguing it better groups related functionality and prevents invalid flag combinations.

The exchange follows up on earlier performance concerns about individual ref updates, with Asthana agreeing to remove that code path. Both participants now focus on finding the clearest way to expose the batched transaction behavior while allowing for partial failures when needed.
