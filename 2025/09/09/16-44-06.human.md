Junio Hamano weighs in on the debate about making `--update-refs` the default behavior for `git replay`. This is part of the ongoing discussion about atomic reference updates for this experimental command.

Hamano agrees with Elijah Newren's position that the command's prominent experimental markings (in both documentation and help output) justify making behavior changes, even after 18 months of existence. He notes that end-user documentation is what matters most when considering breaking changes, and confirms that `git replay` does clearly advertise its experimental status there.

The key point is Hamano's endorsement of changing the default behavior if it's clearly better for most use cases, while still preserving the old behavior via an option. This moves the discussion forward by providing maintainer approval for the direction Newren has been advocating, while acknowledging Christian Couder's concerns about existing usage.

This email doesn't introduce new technical details but provides important maintainer perspective on the interface debate. Hamano's position as Git's maintainer gives this input particular weight in the discussion.
