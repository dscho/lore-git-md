This is a feature patch introducing atomic reference updates for `git replay`, part of an ongoing series to improve server-side workflows. The email is a response to Christian Couder's documentation review, clarifying that both `--update` and `--update-refs` are new options being introduced in this series, not just `--update-refs` as initially stated in the cover letter.

The thread has seen active discussion about the flag design, with reviewers suggesting simplifications from three flags (`--update`, `--update-refs`, `--batch`) to a single `--update-refs` with mode parameters. The current implementation provides atomic transactions by default (all refs update or none) using the ref transaction API, targeting bare repositories for server use cases like GitLab/Gitaly.

Key open questions remain about final flag naming and reftable backend performance, but the discussion shows good progress in refining both the design and documentation. The patch appears well-motivated for server workflows and has attracted detailed review from multiple Git contributors, suggesting it's a serious proposal worth watching.
