Refactoring patch in the ODB transaction interface series, removing transaction nesting capability. This is part of Patrick Steinhardt's larger effort to refactor Git's object database subsystem for pluggable backends.

The patch eliminates the nesting behavior of ODB transactions, where only the outermost begin/end calls would start/complete a transaction. Instead, it enforces a strict one-transaction-at-a-time model, requiring callers to explicitly check for existing transactions before starting new ones. This makes the interface more predictable but requires updates to several callers (cache-tree.c, object-file.c, read-cache.c) to handle the new behavior.

Key technical changes include:
- Removes `nesting` field from `struct odb_transaction`
- Replaces nested transaction logic with BUG() checks for duplicate transactions
- Updates documentation in bulk-checkin.h to reflect new single-transaction model
- Modifies call sites to conditionally start transactions only when none exist

The change appears well-motivated by the awkwardness of the nested transaction model and aligns with the series' goal of simplifying the ODB interface. The patch maintains existing functionality while making the behavior more explicit, though it does require careful review of all transaction usage sites to ensure no edge cases are missed. The changes are mechanical but touch multiple subsystems that interact with bulk-checkin operations.
