Refactoring patch in the xdiff Rust compatibility series, specifically addressing the chastore_t removal from xdfile_t.

This email from Phillip Wood is a review response to patch 8/17 in Ezekiel Newren's series preparing xdiff for Rust integration. The patch removes the redundant chastore_t arena allocation system in favor of storing xrecord_t objects directly in a contiguous array. Phillip agrees with the change but suggests improving the commit message to better explain the dual allocation system being removed and the implications of switching to contiguous storage.

Key technical details:
- Removes chastore_t from xdfile_t struct (xtypes.h)
- Changes xdfile_t.recs from xrecord_t** to xrecord_t*
- Updates all xdiff algorithm implementations to use direct array access
- Maintains identical behavior while simplifying memory management
- Affects xdiff/xdiffi.c, xemit.c, xhistogram.c, xmerge.c, xpatience.c, xprepare.c, xutils.c

Phillip notes the change means records are now stored contiguously rather than via an arena+pointer system, which may increase copying during array growth but shouldn't cause allocation issues given xrecord_t's small size. He praises the overall cleanup quality while suggesting the commit message could better explain the motivation and implications of the change. The review indicates general approval of the technical approach while requesting minor documentation improvements.
