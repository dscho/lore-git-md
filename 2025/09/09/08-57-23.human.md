This is a refactoring patch in the xdiff internals series preparing for Rust compatibility. Patch 6/17 removes the redundant `xdfile_t.ha` array, which stored hash values that could already be accessed via `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. The change replaces direct array lookups with a new `get_hash()` helper function that performs the double indirection.

Elijah Newren raises a performance concern about introducing this double indirection in what appears to be a hot codepath (nested within three levels of loops). The patch otherwise appears mechanically sound, following the series' pattern of simplifying xdiff's internals while maintaining identical behavior. The commit message clearly documents the invariant being enforced and the changes are straightforward, though the performance impact remains an open question that may need benchmarking.

This continues the series' incremental refactoring approach, with Elijah having previously approved similar mechanical changes in earlier patches. The change aligns with the overall goal of making xdiff code more Rust-friendly by reducing redundant data structures.
