Refactoring patch simplifying Git's ODB transaction interface by removing nesting support. This is part of Patrick Steinhardt's ongoing series to prepare Git's object database for pluggable backends.

The patch removes the ability to nest ODB transactions, which was previously used to allow internal codepaths to use transactions without worrying about whether one was already active. The new approach requires callers to explicitly check for existing transactions before starting new ones, making the behavior more predictable. This affects several core operations including `index_blob_bulk_checkin`, `cache_tree_update`, and `add_files_to_cache`.

The changes touch multiple files (bulk-checkin.[ch], cache-tree.c, object-file.c, read-cache.c) with about 30 lines changed total. The commit message clearly explains the motivation for removing nesting support, noting it made the interface "awkward to use" since transactions weren't guaranteed to actually start/end when the functions were called.

This appears to be a well-considered change that simplifies the transaction model as part of the larger ODB abstraction effort. The patch maintains functionality while making the behavior more explicit, and updates all relevant callers to handle the new contract.
