This is a discussion thread about `git add`'s behavior with invalid pathspecs, focusing on the limitations of the `--ignore-errors` option. Junio C Hamano clarifies that `--ignore-errors` is designed to handle permission-related errors (like trying to add a read-only file) rather than missing file errors. He demonstrates this with an example where `--ignore-errors` successfully adds a writable file while skipping a read-only one, contrasting with Jeff King's earlier example showing it doesn't help with missing files.

The exchange highlights an important distinction in Git's error handling - `--ignore-errors` addresses file access issues during staging, not pathspec validation failures. This helps explain why the option doesn't solve the original issue of mixed valid/invalid pathspecs. The thread continues to explore Git's conservative design philosophy around error handling while surfacing potential documentation gaps around what different "ignore" options actually cover.
