This is part of the command deprecation framework series, specifically adding a new `deprecated` category to `--list-cmds` for programmatic discovery of deprecated commands. The patch marks `pack-redundant` and `whatchanged` as deprecated (with the new `DEPRECATED` flag) and extends the `list_builtins()` function to support filtering by inclusion criteria, not just exclusions.

The change is well-motivated - with 145 builtins, users need a way to programmatically identify deprecated commands rather than scanning documentation. The implementation is clean, building on the existing `--list-cmds` infrastructure while maintaining backward compatibility. Patrick Steinhardt has reviewed and acked the changes, which include his suggested loop restructuring and formatting improvements.

This is a foundational piece for the larger deprecation framework, enabling both user-facing tools and internal code (via the new `is_deprecated_command` helper coming in later patches) to identify deprecated commands. The documentation is updated to reflect the new `deprecated` category option.
