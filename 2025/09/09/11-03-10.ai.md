This is patch 11/15 in Patrick Steinhardt's packfile store refactoring series, continuing the effort to move packfile management into a dedicated `packfile_store` structure as part of the ODB abstraction work.

The patch introduces a new helper function `packfile_store_load_pack()` that combines the common pattern of checking if a packfile exists in the store, loading it if not, and adding it to the store. This replaces several instances of manual packfile lookup and insertion that were previously duplicated across the codebase. The function handles the non-trivial logic of converting between .idx and .pack filenames and managing the hashmap lookup/insertion.

Key technical details:
- New function takes an index path and returns the corresponding `packed_git` struct
- Handles the .idx -> .pack name conversion internally
- Performs hashmap lookup to avoid duplicate loading
- Updates callers in fast-import.c, index-pack.c, midx.c, and packfile.c
- Maintains identical behavior while reducing code duplication
- Adds documentation for the new public interface

The changes are mechanical refactoring with no user-visible impact, continuing the series' pattern of clean, focused improvements to packfile code organization. All call sites are updated to use the new helper, removing ~40 lines of duplicated logic while preserving all existing functionality. The patch fits naturally into the series' progression toward better separated packfile management.
