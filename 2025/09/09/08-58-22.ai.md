Refactoring patch in the xdiff Rust compatibility series, focusing on making rchg values more readable through enum-like macros. This is patch 9/17 in the ongoing effort to prepare xdiff internals for potential Rust integration.

The patch introduces NO/YES/MAYBE macros (0/1/2) to replace magic numbers when working with xdfile_t.rchg values, which track line change states during diff operations. The changes are mechanical but reveal several subtle assumptions in the code where MAYBE values were implicitly excluded from certain conditions. Elijah Newren's review identifies multiple locations where the conversion from implicit boolean checks to explicit YES comparisons might affect behavior if MAYBE values were present, suggesting these invariants should be documented in the commit message.

The patch also includes an orthogonal cleanup in xdl_build_script() that removes temporary rchg pointer variables, which Elijah suggests might belong in a separate patch with its own justification. Changes span xdiff's core algorithms (xdiff, histogram, patience) and affect how changed lines are marked during diff calculation, though behavior-preserving. The review indicates the technical changes are sound but could benefit from clearer documentation of the MAYBE-value invariants.
