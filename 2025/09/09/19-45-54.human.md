This is the fourth patch in a v4 series implementing command deprecation with alias shadowing support. It focuses on improving the user experience when encountering deprecated commands.

The patch rewrites the error message shown when running a deprecated command to be more helpful and actionable. Instead of just telling users to email the mailing list, it now provides a structured set of next steps: checking the BreakingChanges documentation, searching mailing list discussions, and only then emailing if no suitable replacement is found. The message also includes direct links to these resources, with the command name properly URL-encoded for the search query.

The implementation adds a strbuf to handle the percent-encoding of the command name for the search URL. It removes some of the more pleading language ("please add", "Thanks") in favor of a more direct but still polite tone. The patch maintains the same core behavior of refusing to run without the override flag.

This appears to be the final polish on the user messaging aspect of the deprecation system, incorporating feedback from Eric Sunshine about making the instructions more practical. The changes are focused and well-contained, touching only the usage.c file to improve the error reporting while keeping the same underlying enforcement mechanism.
