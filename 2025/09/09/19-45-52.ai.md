Feature: Command deprecation system with alias shadowing support (part 2/7 of series)

This patch implements the core functionality for allowing deprecated builtins to be shadowed by aliases, addressing a key user experience issue in the command deprecation framework. The change specifically targets interactive users who want to maintain muscle memory for deprecated commands like `git whatchanged` by creating aliases to their modern equivalents.

The technical implementation adds an `is_deprecated_command()` helper that checks the new `DEPRECATED` flag (introduced in patch 1) and modifies `run_argv()` to bypass the normal alias shadowing restriction for deprecated commands. The patch includes comprehensive test coverage in t0014-alias.sh that verifies all deprecated commands can be properly shadowed, with careful handling of edge cases like commands that fail with `-h`.

Documentation in alias.adoc is updated to clarify the new exception for deprecated commands. The implementation builds on Jeff King's original proposal and maintains backward compatibility while solving the specific user pain point where aliases for deprecated commands were previously blocked until full removal.

This is a key piece of the overall deprecation framework that enables smoother transitions for interactive users while keeping the deprecation warnings in place for direct usage. The patch follows the series' established pattern of treating all deprecated commands consistently, even though the immediate demand comes primarily from `git whatchanged` users.
