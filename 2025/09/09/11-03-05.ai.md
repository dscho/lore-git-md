This is patch 6/15 in Patrick Steinhardt's ongoing refactoring series to move packfile-related state from `struct object_database` to the new `struct packfile_store`. The patch relocates the "kept packfile" functionality, which is used by `git-pack-objects` to handle cruft objects.

The change moves the `kept_pack_cache` structure (containing an array of packfiles and flags) from `struct object_database` to `struct packfile_store`, renaming it to `kept_cache` in the process. This completes the migration of all packfile-related state from the ODB to the packfile store, as noted in the updated comment for the `packfiles` pointer in `struct object_database`.

The implementation updates all callers in packfile.c to use the new location while maintaining identical behavior. The patch follows the same pattern as previous patches in the series - a mechanical move of state with no functional changes, touching the same set of files (odb.h, packfile.c, packfile.h) and maintaining backward compatibility.

Key technical details:
- The kept pack cache is used to track packfiles marked with .keep files or in-memory "kept" flags
- Cache invalidation logic remains unchanged, just relocated
- All access continues through the `kept_pack_cache()` helper function
- The change removes the last packfile-related field from `struct object_database`

This continues the series' high-quality approach with clean, focused changes that advance the architectural goal of separating packfile management from the core object database. The patch appears uncontroversial and follows the established pattern from previous patches in the series.
