This is part of the ongoing submodule gitdir path encoding series, specifically addressing cross-implementation compatibility concerns. Adrian Ratiu responds to Patrick Steinhardt's feedback about how the new `.git/submodules/` directory structure affects alternative Git implementations (libgit2, JGit, Gitoxide).

The key points are:
1. Confirmation that older Git versions and alternative implementations won't automatically handle the new path structure, making this a backwards-incompatible change
2. Plans to add an `extensions.submoduleEncoding` marker in v3 to explicitly signal the new path format
3. Discussion of human-readable vs hashed naming schemes (URL encoding will remain default per Junio's request, though hash options could come later)
4. Explanation that the existing config override mechanism (`submodule.<name>.gitdirpath`) serves a different purpose than Patrick's suggested `submodule.*.repoPath` idea
