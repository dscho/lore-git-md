Refactoring patch in the xdiff Rust compatibility series. This is patch 8/17, removing the redundant `chastore_t` from `xdfile_t` and converting all record accesses to use direct array indexing rather than pointer indirection.

The change eliminates a dual storage mechanism where records were kept both in a `chastore_t` allocation pool and in the `recs` array. The patch updates all access sites across xdiff to use the now-direct `recs` array access, requiring numerous mechanical changes from `->` to `.` dereferencing. The diff is large (63 insertions, 69 deletions across 8 files) but straightforward, with Elijah Newren noting it's easier to review with `--color-words`.

This continues the series' pattern of simplifying xdiff internals for Rust compatibility. The change appears well-scoped and mechanically sound, though as with previous patches, the commit message could better explain the motivation for newcomers unfamiliar with xdiff's internals. The review suggests incorporating more context from an earlier explanation about the redundant storage.
