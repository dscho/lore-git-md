This is a follow-up discussion in the ongoing submodule gitdir path encoding series, specifically about the config override mechanism introduced in patch 3/9. Adrian Ratiu clarifies that the `submodule.<name>.gitdirpath` config override was intended as a complementary feature rather than a core requirement for cross-implementation compatibility. He notes it's primarily useful for testing and custom encoding schemes, not automatically set to avoid config clutter.

The email confirms that future versions (v3) will use a repository extension for core compatibility, making the config override more of an optional feature. Ratiu acknowledges Phillip Wood's concern about the feature's role and commits to rewording the commit message in v3 to better reflect this distinction. The exchange shows the careful consideration being given to both technical implementation and clear communication of design decisions in this complex series.
