This is a brief follow-up in the ongoing discussion about Git's dumb HTTP protocol limitations.

Jeff King responds to Brian M. Carlson's concerns about the security and implementation challenges of parsing HTTP directory listings in C. While maintaining his earlier position about the technical feasibility (with a lighthearted Rust reference), King now more clearly aligns with Carlson's view that this approach would be unwise to implement in Git proper. He suggests that anyone wanting this functionality would be better served by implementing it themselves rather than proposing it for inclusion in Git.

The email reinforces the thread's emerging consensus against modifying dumb HTTP to support directory scraping, while acknowledging the theoretical possibility of third-party implementations. This continues the pattern of maintainers and contributors steering discussion away from protocol changes that would require parsing server-generated directory listings.
