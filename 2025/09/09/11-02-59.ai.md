This is a refactoring patch series (v4, 15 patches) that introduces a new `struct packfile_store` to centralize packfile management in Git's object database. The series is part of the larger effort to enable pluggable object databases by cleaning up how packfiles are tracked.

The key change moves packfile-related data from being scattered across `struct packed_git` and `struct object_database` into the new dedicated `struct packfile_store`. This includes:
- The linked list of packfiles
- The packfile path map
- The MRU (most recently used) list
- The kept pack cache

The series has gone through multiple review iterations with:
- Code style improvements from Junio Hamano
- Commit message refinements from Karthik Nayak
- Resolution of an `inline` keyword question in patch 4
- Rebase conflicts addressed with other in-flight series

Notable technical changes in v4:
- Small code style tweaks
- Commit message clarifications
- Removal of the meaningless `inline` hint from `pack_map_entry_cmp()` (it's a callback and can't be inlined)

The series appears well-polished at this point, with all major architectural questions settled in previous rounds. It touches a wide range of files (31 modified) but focuses on internal refactoring without changing user-visible behavior. The changes pave the way for future work to move packfile management into pluggable object database backends.
