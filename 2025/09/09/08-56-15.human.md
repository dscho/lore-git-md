This is a refactoring patch in the ongoing xdiff internals cleanup series aimed at Rust compatibility. It's patch 3/17 in the series, following two already-reviewed preparatory patches.

Ezekiel Newren removes three unused fields from xdiff's core data structures: `xrecord_t.next`, `xdfile_t.hbits`, and `xdfile_t.rhash`. The changes are straightforward - the fields are initialized but never actually used in the code, so they can be safely deleted along with their supporting code. The patch simplifies the code by removing dead hash table infrastructure that was apparently vestigial.

Elijah Newren (no relation) responds positively to the change, noting it's good to see unused code being cleaned up. The patch appears uncontroversial and aligns with the series' goal of simplifying xdiff internals before introducing Rust-compatible types. It follows the incremental approach seen in earlier patches, where each change focuses on one clear improvement while maintaining identical runtime behavior.
