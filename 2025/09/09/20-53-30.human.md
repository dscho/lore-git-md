This is a discussion about gitk's Tk widget theming support, following up on a recently fixed bug. Mark Hills notes that while the specific combobox bug was fixed in Git 2.50.0, commit cb9fa4d9ecd (Git 2.51.0) went further by completely removing support for non-themed widgets in gitk. 

The patch author's rationale was that themed widgets (ttk) have been the default for years and are well-tested, while maintaining both code paths increases complexity. However, Hills argues this removal seems excessive, pointing out that non-default features still have value when users specifically want them (as demonstrated by his earlier bug report when the feature broke).

The discussion highlights a tension between code maintenance and user choice. While the themed widgets are clearly the preferred path, the complete removal of the classic widget option - just one month after fixing a related bug - may have been premature from a user perspective. The thread serves as a useful case study in balancing technical debt reduction against preserving user configuration options.
