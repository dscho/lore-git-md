This is the first patch in the v4 series implementing command deprecation with alias shadowing, focusing on adding a `deprecated` category to `--list-cmds`. The patch introduces a new `DEPRECATED` flag (1<<6) and modifies the command listing infrastructure to support querying deprecated commands programmatically.

The technical changes include:
- Adding the `DEPRECATED` flag to `builtin.h` and marking `pack-redundant` and `whatchanged` commands as deprecated
- Extending `list_builtins()` to support both include and exclude filters, enabling the new `--list-cmds=deprecated` option
- Updating documentation to advertise the new category alongside existing ones
- Maintaining backward compatibility with existing command listing behavior

The patch addresses Kristoffer Haugsbakk's earlier concern about discoverability of deprecated commands by providing a direct query mechanism. It builds on Patrick Steinhardt's suggestions from v3, incorporating loop restructuring and dropping unnecessary function documentation. The implementation will be used in subsequent patches to implement `is_deprecated_command()` checks.

Key files modified:
- `git.c`: Core changes to command listing and flag handling
- `Documentation/git.adoc`: Documents the new `deprecated` category
- Command definitions for `pack-redundant` and `whatchanged` updated with `DEPRECATED` flag

This foundational change enables the rest of the deprecation framework by establishing the flag-based identification system that subsequent patches will build upon. The implementation appears clean and well-integrated with existing command listing infrastructure.
