This is part 9/15 of Patrick Steinhardt's packfile store refactoring series, continuing the effort to move packfile management into a dedicated `packfile_store` structure as part of the ODB abstraction work.

The patch splits the responsibilities of `reprepare_packed_git()` by introducing a new `odb_reprepare()` function that handles the broader object database reloading tasks (alternates, loose object cache clearing), while the packfile-specific portion is moved to `packfile_store_reprepare()`. This better aligns functionality with the new architectural boundaries - packfile operations stay in the packfile store, while cross-cutting ODB concerns are handled at the object database level.

Key technical changes:
- New `odb_reprepare()` function in odb.c consolidates alternates reloading and loose cache clearing
- `packfile_store_reprepare()` now focuses solely on packfile reloading
- Updates 13 call sites across various commands (gc, repack, fetch, etc.) to use the new API
- Maintains identical behavior while improving separation of concerns

The change is a mechanical refactoring with no user-visible impact, continuing the series' pattern of clean, focused improvements to the packfile code organization. All existing functionality is preserved while better isolating responsibilities between the object database and packfile subsystems. The patch follows the established pattern of the series and appears ready for merging.
