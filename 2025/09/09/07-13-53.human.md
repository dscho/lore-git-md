This is a feature proposal for `git replay` that adds atomic reference updates via a new `--update-refs` option, with discussion about making it the default behavior.

Elijah Newren responds to Siddharth Asthana's patch series introducing `--update-refs` for `git replay`. While generally supportive of the feature (which enables atomic ref updates without piping to `git update-ref`), Newren questions why atomic updates shouldn't be the default behavior given that `git replay` is still experimental. He suggests dropping or clarifying the vague statement about server-side benefits, noting it's unclear whether the value comes from atomicity, ergonomics, or other factors.

The response highlights a key design question: whether to make atomic updates opt-in (current approach) or opt-out (Newren's suggestion). This touches on the command's experimental nature and target audience (server workflows where atomicity is typically preferred). The exchange shows the patch is technically sound but may need refinement in its interface design philosophy.
