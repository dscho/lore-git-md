This is a discussion about submodule path encoding in the ongoing submodule gitdir path encoding series. Patrick Steinhardt raises concerns about interoperability with other Git implementations (libgit2, JGit, Gitoxide) regarding the move of encoded submodule paths from `.git/modules/` to `.git/submodules/`.

The email identifies two key issues: 1) Git's ability to handle alternate implementations continuing to use `.git/modules/`, which is confirmed to work, and 2) the need for those implementations to adapt to the new path structure, which would constitute a backwards-incompatible change. Steinhardt suggests a more robust solution would be a `submodule.*.repoPath` config key to explicitly track submodule locations rather than relying on path conventions.

This touches on the series' config override mechanism (`submodule.<name>.gitdirpath`) that was previously discussed as the interoperability path. The email doesn't propose concrete changes but highlights an important consideration for the design that wasn't fully addressed in prior discussion - the impact on non-reference implementations. The thread had previously established version checking via `extensions.submoduleEncoding` as the protection mechanism, but this email questions whether that sufficiently addresses cross-implementation concerns.
