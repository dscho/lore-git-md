This is a refactoring patch in the xdiff internals series, specifically addressing redundant data storage in the xdiff algorithm implementation. Patch 6/17 removes the `xdfile_t.ha` array which stored hash values that were already accessible via `xdfile_t.recs[xdfile_t.rindex[i]]->ha`. The change replaces direct array access with a new `get_hash()` helper function that performs a double indirection to fetch the same value.

The patch modifies three files, with the bulk of changes in `xdiff/xdiffi.c` where hash comparisons are frequent. Elijah Newren's review question focuses on potential performance impact, noting that the change replaces single array lookups with function calls performing double indirections in nested loops that may be hot paths. The mechanical nature of the change is otherwise straightforward, following the series' pattern of simplifying xdiff structures while maintaining identical behavior.

Key technical details for future reference:
- New helper function `get_hash(xdfile_t*, long)` introduced
- `xdfile_t.ha` array removed from struct definition
- Changes affect core diff algorithm functions like `xdl_split()` and `xdl_recs_cmp()`
- Performance-sensitive paths now do two lookups (`recs[]` then `rindex[]`) per hash access
- Memory savings from removing redundant array (one `unsigned long` per diff line)

The review raises an important open question about whether the indirection overhead is acceptable in what may be performance-critical sections, while acknowledging the code simplification benefits. This continues the series' theme of balancing Rust compatibility goals with maintaining xdiff's performance characteristics.
