Bugfix discussion regarding `git add` behavior with invalid pathspecs.

Jeff King clarifies that while `--ignore-errors` works as documented for permission-related errors (as Junio demonstrated), it doesn't address the original issue raised by Jon Forrest about handling invalid pathspecs. The current behavior where `git add` fails completely when given a mix of valid and invalid pathspecs remains unchanged.

The key distinction here is between two types of errors: permission/access issues (which `--ignore-errors` handles) versus pathspec validation failures (which it doesn't). Jeff suggests what's really needed would be more like an `--ignore-missing` option to handle the pathspec case, though no such option currently exists.

This continues the thread's technical discussion about Git's conservative error handling philosophy, with maintainers clarifying the boundaries between different error types and existing mitigation options. The exchange helps frame the core question: whether Git should maintain its current strict behavior or consider adding new options for partial success cases.
