This is a submodule path encoding patch in the ongoing series to prevent filesystem conflicts in submodule gitdir paths. Adrian Ratiu responds to Patrick Steinhardt's concerns about cross-implementation compatibility, confirming that older Git versions and alternative implementations (libgit2, JGit) would indeed be affected by the new `.git/submodules/` path structure without proper version detection.

Key technical points in this response:
- Confirms Phillip Wood's suggestion to use an `extensions.submoduleEncoding` marker will be implemented in v3 to handle version compatibility
- Maintains URL encoding as the default human-readable format per Junio Hamano's request, while leaving door open for future configurable encoding schemes
- Notes the `submodule.<name>.gitdirpath` config override exists but is insufficient for broad compatibility
- Acknowledges this is effectively a breaking change that requires explicit version detection

The email reinforces the series' direction toward using repository extensions as the primary compatibility mechanism while addressing Patrick's architectural concerns. It also hints at future possibilities like hash-based naming schemes while keeping the current focus on URL encoding. The response shows the design is converging on a solution that balances human readability, cross-platform needs, and implementation interoperability.
