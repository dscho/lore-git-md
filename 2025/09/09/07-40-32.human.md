This is a discussion about submodule gitdir path encoding and cross-implementation compatibility, part of an ongoing 12-patch series to prevent filesystem conflicts in submodule paths.

Patrick Steinhardt raises concerns about the migration strategy for the new submodule gitdir path encoding scheme, particularly regarding how alternative Git implementations (like JGit, libgit2, Gitoxide) will handle the changes. While the current patch introduces a `submodule.<name>.gitdirpath` config override as a compatibility mechanism, Patrick worries this may not be sufficient to prevent breakage during the transition period.

He suggests two alternative approaches: 1) using a repository extension (potentially opt-in via `init.useSubmoduleGitdirExtension`) to ensure only compatible clients access repositories with encoded paths, or 2) avoiding the new `.git/submodules` directory entirely and instead adding random suffixes to paths in the existing `.git/modules` location when conflicts occur.

The email continues an important thread about how to balance forward progress with cross-implementation compatibility, with Patrick playing devil's advocate to ensure the solution works for the broader Git ecosystem. His suggestions add weight to the migration concerns first raised in earlier reviews, though he acknowledges his proposals might be "overboard" and invites pushback. The core team will need to weigh these compatibility considerations against the technical merits of the current approach.
