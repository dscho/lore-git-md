Refactoring patch in Patrick Steinhardt's packfile store series (v4 12/15), moving `get_multi_pack_index()` from packfile.c to midx.c where it logically belongs. This is part of the ongoing effort to cleanly separate packfile management into its own subsystem.

The patch relocates the function while making `packfile_store_prepare()` public since it's needed by the moved function. The change is mechanical with no behavior changes - it just moves code to a more logical location and exposes one previously internal function. The commit message explains this is preparatory work for adding another caller outside packfile.c in a future commit.

- Makes `packfile_store_prepare()` public by moving its declaration to packfile.h
- Updates includes and declarations in packfile.h and midx.h
- Maintains all existing functionality while improving code organization
- Part of broader packfile store refactoring to separate concerns

This continues the series' pattern of careful, incremental refactoring to improve code organization while maintaining backward compatibility. The change is straightforward and uncontroversial, fitting naturally into the architectural progression of the series.
