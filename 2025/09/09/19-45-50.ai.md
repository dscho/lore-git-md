This is the fourth version of a series improving the command deprecation system, focusing on user messaging and troubleshooting for deprecated commands like `git whatchanged` and `git pack-redundant`. The series builds on the established deprecation framework with new features for alias shadowing and better error reporting.

Key technical changes in v4 include:
- Refined implementation of `is_deprecated_command()` using the new `DEPRECATED` flag (suggested by Junio and Jeff King)
- Improved `list_builtins()` function with Patrick Steinhardt's suggested loop restructuring
- Expanded test coverage in t0014-alias.sh for alias shadowing behavior

The user experience improvements are significant:
- More actionable error messages now show both the `git log` equivalent command and how to create an alias
- Documentation updates clarify replacement commands and remove outdated claims
- The `--list-cmds=deprecated` interface provides programmatic discovery
- Error messages now guide users to BreakingChanges documentation and mailing list discussions

Files modified span core command handling (git.c, builtin.h), documentation (BreakingChanges.adoc, man pages), and test infrastructure (t0014-alias.sh). The implementation maintains backward compatibility while providing clearer paths for users to modern alternatives.

This version incorporates all major feedback from previous rounds, with the technical foundation now using flag-based deprecation checks and optimized command listing. The series appears ready for integration, having addressed concerns from Junio, Jeff King, and others while maintaining the three-step deprecation pattern.
