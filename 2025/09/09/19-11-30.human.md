This is a bugfix patch in a series refactoring Git's object database transaction handling. It addresses an issue in `git update-index --verbose` where objects were being flushed but not committed when verbose output, creating an awkward intermediate state.

The patch changes the `--verbose` behavior to instead fully end the transaction early when verbose output is requested, since subsequent object writes wouldn't benefit from being transactional anyway. This simplifies the code by removing the partial `flush_odb_transaction()` call and replacing it with a clean transaction termination.

The change maintains compatibility with any hypothetical callers that might be parsing verbose output to track object writes, while making the behavior more straightforward. The patch is part of a larger series (2/6) working on ODB transaction interfaces, though it stands alone as a focused improvement to `update-index`.

The change is well-motivated and cleanly implemented, with clear commit message explaining both the current awkwardness and the proposed solution. The diff shows a straightforward replacement of the flush mechanism with early termination, plus some additional null checks for safety.
