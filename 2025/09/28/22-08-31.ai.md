Refactoring patch in the `tb/incremental-midx-part-3` series, continuing the modularization of `builtin/repack.c` with a focus on pack installation logic.

This patch extracts the pack file installation procedure into a new `generated_pack_install()` function, handling the complex sequence of operations needed to move temporary pack files into their final locations. The function manages:
- File mode adjustments (removing write permissions)
- Error handling for missing required files
- Cleanup of unneeded extensions
- Atomic renames via tempfiles

The extracted logic was previously inline in `cmd_repack()`, operating on the `struct generated_pack` that was renamed in patch 20. The new function maintains all existing behavior while preparing for future relocation to a module (as noted in the commit message). Key technical points:
- Processes all pack extensions (`.idx`, `.pack`, `.mtimes` etc.) uniformly
- Uses the same `exts` array and error handling as before
- Preserves the temporary-to-permanent file transition safety
- Keeps the packdir/packtmp path handling unchanged

This continues the series' pattern of:
1. Identifying cohesive functionality
2. Extracting it with minimal changes
3. Preparing for eventual module relocation
4. Maintaining strict behavioral equivalence

The change reduces `cmd_repack()`'s complexity by 30 lines while making the pack installation logic more self-contained and testable. As with prior patches in the series, this appears to be a well-executed mechanical refactoring with clear documentation of both the change and its future purpose.
