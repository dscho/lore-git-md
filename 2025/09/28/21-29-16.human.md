This is the final patch in a three-part series introducing optional file specifications in Git, extending the `:(optional)` prefix support to command-line options that take pathnames. The series builds on Junio Hamano's original work and has been refined through previous iterations.

The patch adds support for marking pathname-type command-line options as optional, similar to the config variable support added earlier. When a file is prefixed with `:(optional)` and doesn't exist, Git will behave as if the option wasn't specified at all. The implementation includes documentation updates in gitcli.adoc explaining the new syntax, modifications to parse-options.c to handle the optional prefix, and a new test case verifying the behavior with a non-existent template file.

The changes appear well-contained and maintain backward compatibility. The test coverage is thorough, checking both the happy path and edge cases. This completes the series' goal of providing a consistent way to handle optional files across both configuration and command-line interfaces. The implementation looks clean and follows the established pattern from the config variable changes in previous patches.
