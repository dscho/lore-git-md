Refactoring patch in the ongoing modularization of `builtin/repack.c`, part of Taylor Blau's 49-part series to modernize Git's repacking machinery. This is patch 26/49, which moves the promisor object repacking functionality out of the monolithic builtin file and into a new `repack-promisor.c` module.

The patch relocates `repack_promisor_objects()` and its helper `write_oid()` to a dedicated file, following the series' established pattern of:
1. Parameterizing functions (done in previous patches)
2. Extracting them to new modules
3. Maintaining all existing behavior

The promisor-specific code joins other repack utilities that have already been modularized, like the `existing_packs` and `generated_pack` APIs. The implementation is moved verbatim with no functional changes, preserving the existing behavior around:
- Streaming OIDs to pack-objects
- Creating .promisor files
- Handling pack generation output

Two `NEEDSWORK` comments remain in the relocated code, noting potential improvements around delta optimization and promisor file contents that were present in the original implementation. The change is straightforward and follows the series' methodology, continuing the systematic breakdown of the large repack builtin into focused components.
