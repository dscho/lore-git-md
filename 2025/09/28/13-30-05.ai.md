This is a technical follow-up in the gitk window geometry persistence series, specifically addressing cross-platform behavior of the Tags/Heads window restoration. Mike Rappazzo responds to Johannes Sixt's question about why the `after idle` callback works for geometry restoration despite potential race conditions.

The email provides important platform-specific insights: MacOS handles immediate geometry setting during window creation correctly, while Windows and Gnome require the deferred `after idle` approach to avoid conflicts with window manager placement logic. This explains the earlier testing results where MacOS worked without the callback while other platforms needed it.

Key technical details include the analysis of window manager behavior differences and confirmation that the `after idle` solution properly handles the timing issues on problematic platforms. Mike also confirms his intention to proceed with splitting the `manage_showrefs_geometry` function as previously discussed, indicating this will be part of the upcoming v3 revision.

The discussion remains focused on implementation details rather than introducing new functionality, maintaining the series' goal of reliable cross-platform window geometry persistence. This email helps validate the current approach while setting up the next iteration of the patch series.
