This is the final patch in a v2 series implementing optional file specifications in Git, extending the `:(optional)` prefix support to command-line options that take pathnames. The patch builds on Junio Hamano's original work and previous patches in the series that handled configuration variables.

The key changes in this patch:
- Adds `:(optional)` prefix support for pathname-type command-line options in parse-options.c
- Documents the new syntax in gitcli.adoc with examples
- Adds test coverage in t7500 for optional template files on the command line
- Maintains consistent behavior with config variables (missing files are silently skipped)
- Uses the existing `is_empty_or_missing_file()` helper from wrapper.c

The implementation handles both direct path arguments and optional-prefixed paths, with proper memory management. The test verifies that a commit with a non-existent optional template file proceeds normally, matching the behavior seen with config variables in earlier patches.

This completes the series' goal of providing uniform optional file handling across both configuration and command-line interfaces. The changes are well-contained, with thorough documentation and testing. The series appears ready for merging with comprehensive coverage of both use cases and clear documentation in both config and CLI contexts.
