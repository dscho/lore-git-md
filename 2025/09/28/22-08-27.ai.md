Refactoring patch in the ongoing `builtin/repack.c` modularization series, specifically addressing naming conventions for pack-related structures and functions.

This is the 20th patch in Taylor Blau's 49-part series to refactor Git's repack machinery. The change focuses on renaming `struct generated_pack_data` to the more concise `struct generated_pack`, along with updating all associated functions to follow the convention of prefixing with the struct name. The motivation is to reduce redundancy in naming while making the code more readable - for example, changing `has_pack_ext()` to `generated_pack_has_ext()`.

The patch touches several key areas of pack handling:
- The core structure tracking temporary pack files
- Functions for populating pack extensions (`generated_pack_populate`)
- Pack extension checking logic (`generated_pack_has_ext`)
- Call sites throughout `builtin/repack.c` that interact with these structures

This continues the series' pattern of methodical improvements, maintaining all existing behavior while improving code organization. The changes are mechanical renames with no functional impact, keeping in line with the series' goal of making the repack codebase more maintainable for future MIDX-related work. All modified functions remain within `builtin/repack.c` rather than being moved to the new modules, suggesting this is preparatory cleanup before potential future relocation of this functionality.
