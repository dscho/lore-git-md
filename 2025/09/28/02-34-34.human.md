Bugfix confirmation for Windows path handling issue. Nikolay Shustov confirms Eric Sunshine's diagnosis that `git merge --no-ff` failures on Windows are indeed caused by filenames ending with dots, originally imported from Perforce. The reporter experimentally verified this by reintroducing such filenames into a previously working repository, reproducing the failure.

The email notes that while Windows shell/UI functions fail on these filenames, lower-level Windows APIs (as used by Cygwin) can handle them correctly, suggesting potential implementation approaches. This moves the discussion from root cause analysis toward solution exploration, with the reporter now aligned on the technical explanation after initial skepticism about why unchanged files would affect merges.

The thread remains focused on Windows-specific behavior, with the next steps likely involving either modifying Git's path handling or documenting the limitation. The confirmation strengthens the case for addressing this edge case in Git's Windows compatibility layer.
