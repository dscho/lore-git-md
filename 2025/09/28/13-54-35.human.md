This is the second patch in a two-part series improving window geometry persistence in gitk. It focuses on making the Tags and Heads window remember its size and position between sessions, building on the first patch's restoration of main window geometry handling.

The patch adds persistence for the Tags/Heads window by storing its geometry in gitk's config file as `geometry(showrefs)`. The window position is saved relative to the main window, maintaining spatial relationships when moving monitors or restarting. The implementation includes new Tcl procedures for saving, restoring, and tracking the window geometry, plus proper cleanup on window close.

This version (v3) adopts a more robust approach from Johannes Sixt's existing code rather than the author's initial solution. The changes are well-contained to gitk's Tcl code (39 lines modified) and don't affect core Git functionality. The patch appears technically sound with thorough handling of window state management.

This completes the series' goal of restoring full window geometry persistence that was previously limited by an obsolete Cygwin workaround. The changes address a long-standing UX issue where users had to reposition windows manually each session.
