This is patch 42/49 in Taylor Blau's series refactoring `builtin/repack.c` to eliminate global variables and prepare for incremental MIDX-based repacking. The patch moves the `find_pack_prefix()` function out of the builtin and into the new `repack.c` module, renaming it to `write_pack_opts_pack_prefix()` to better reflect its role.

The key change is shifting the responsibility for computing the pack prefix from callers to callees. Previously, callers had to manually compute the prefix by passing `packdir` and `packtmp` to `find_pack_prefix()` before constructing the `write_pack_opts` struct. Now, the prefix is computed internally by the new `write_pack_opts_pack_prefix()` function using the fields already present in the `write_pack_opts` struct.

This change:
1. Reduces boilerplate at call sites by eliminating redundant parameter passing
2. Prevents potential parameter-swapping bugs since the function now accesses fields directly from the struct
3. Maintains the same validation logic (checking that packtmp begins with packdir)
4. Updates all call sites to use the new helper function

The patch follows the series' established pattern of methodically encapsulating functionality while maintaining behavior. It removes the `pack_prefix` field from `struct write_pack_opts` since it's now computed on demand rather than stored. The diff shows updates to both filtered pack and cruft pack writing paths to use the new helper.
