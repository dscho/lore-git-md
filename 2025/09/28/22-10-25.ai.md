Part of the ongoing refactoring of `builtin/repack.c` into modular components (tb/incremental-midx-part-3 series), specifically focusing on the `the_repository`/`the_hash_algo` removal effort.

This patch (46/49) moves the `pack_kept_objects` variable from being a static in `builtin/repack.c` to becoming a field in `struct pack_objects_args`, continuing the series' pattern of encapsulating configuration. The change affects several key functions:

1. `write_cruft_pack()` now explicitly sets `pack_kept_objects=0` since it always wants to honor pack keep flags
2. `write_filtered_pack()` no longer handles the `--honor-pack-keep` flag directly, instead relying on `prepare_pack_objects()`
3. The default value logic (based on bitmap/MIDX writing) is preserved but moved into the struct initializer
4. The pack geometry initialization is simplified by removing its direct `pack_kept_objects` parameter

The patch maintains all existing behavior while cleaning up the code organization. It follows the series' established methodology of first parameterizing functionality (done in earlier patches) before relocating it. The changes touch core repack operations but don't introduce new behavior - this is purely structural improvement preparing for future MIDX work.

Key technical details:
- Adds `pack_kept_objects` to `struct pack_objects_args` with default value -1
- Updates all related functions to use the struct field
- Modifies `PACK_OBJECTS_ARGS_INIT` to include the new field
- Simplifies `pack_geometry_init()` signature
- Maintains all existing conditional behavior around bitmaps and MIDX

The change is consistent with the series' goals of eliminating global state and modularizing the repack code. It doesn't address any of the remaining `NEEDSWORK` items noted in previous patches.
