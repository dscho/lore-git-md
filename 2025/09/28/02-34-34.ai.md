Bugfix investigation update regarding Windows path handling with dot-terminated filenames. Nikolay Shustov confirms Eric Sunshine's diagnosis that the `git merge --no-ff` failure is indeed caused by dot-terminated filenames in the repository, which were manually renamed from their original `git p4` import form. The reporter notes that while Windows shell/UI has limitations with such filenames, lower-level Windows APIs (as used by Cygwin) can handle them correctly, suggesting potential avenues for a Git-side fix.

This email marks a transition from root cause analysis to potential solution exploration, with the reporter validating the problem by recreating it in a previously working repository. The confirmation that Cygwin successfully handles these filenames hints at possible implementation approaches, though no specific code changes are proposed yet. The thread now appears ready for solution proposals that would either modify Git's Windows path handling to use appropriate APIs or implement filename normalization during operations like merge and stash.
