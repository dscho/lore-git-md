This is part of the ongoing `the_repository` and `the_hash_algo` removal effort within the major repack.c refactoring series (tb/incremental-midx-part-3). The patch continues converting global variable access patterns, now targeting the `write_oid()` callback function in `builtin/repack.c`.

The change introduces a new `write_oid_context` struct to pass both the child process handle and hash algorithm pointer through the callback's data parameter, eliminating direct use of `the_hash_algo`. The modification affects promisor object repacking, where object IDs are written to pack-objects' stdin. The hash algorithm is now obtained from the repository pointer via `repo->hash_algo` in the calling function `repack_promisor_objects()`.

Key technical details:
- New struct `write_oid_context` bundles `cmd` (child process) and `algop` (hash algorithm)
- Callback signature remains unchanged but now expects context struct instead of direct cmd pointer
- `write_oid()` now uses `ctx->algop->hexsz` instead of `the_hash_algo->hexsz`
- Call site in `repack_promisor_objects()` initializes context with repository's hash algorithm
- Promisor object handling behavior remains identical, just with explicit parameter passing

This follows the series' pattern of methodically converting global accesses while maintaining existing functionality. The change is straightforward but important for the larger goal of removing repository-global state. The patch maintains clean separation of concerns by keeping the hash algorithm knowledge at the caller level rather than having the callback reach for globals.
