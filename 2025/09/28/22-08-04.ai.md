Refactoring patch in the `the_repository` removal and repack modularization series. This is patch 14/49 in Taylor Blau's incremental MIDX preparation work.

The patch moves the `prepare_pack_objects` function from `builtin/repack.c` to the new `repack.c` module, making it available as a shared utility. The function assembles the command-line arguments for `git pack-objects` based on configuration stored in a `pack_objects_args` struct. This relocation is now possible because the function no longer depends on any static variables - all its configuration comes through the args struct parameter.

Key technical details:
- Function signature remains identical: takes `child_process*`, `pack_objects_args*`, and output path
- Handles all pack-objects options: window/depth settings, threading, delta behavior, hash version, etc.
- Now declared in `repack.h` for cross-module access
- Follows the series pattern of moving functionality out of the monolithic builtin
- Maintains existing behavior while removing implementation from the builtin

This continues the systematic decomposition of `builtin/repack.c` into focused modules with well-defined interfaces. The change is straightforward and mechanical, building on the foundation established in prior patches where configuration was moved into structs. The series remains focused on both removing globals and preparing for future MIDX work.
