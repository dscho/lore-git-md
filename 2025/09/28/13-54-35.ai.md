This is the second patch in a two-part series improving gitk's window geometry persistence, focusing on the Tags/Heads window. It builds on the first patch's foundation of restoring main window geometry handling.

The patch makes the Tags/Heads window remember its size and position between sessions by storing its geometry in the config file as `geometry(showrefs)`. The window position is maintained relative to the main gitk window, preserving spatial relationships across monitor changes. The implementation adds several Tcl procedures: `save_showrefs_geometry`, `restore_showrefs_geometry`, `setup_showrefs_geometry_tracking`, and modifies the window destruction handling via `destroy_showrefs`.

Key technical details: The geometry is saved when the window is destroyed and restored when recreated, with a delayed `Map` event binding to avoid race conditions. The patch replaces direct window destruction with a new procedure that saves geometry first. The changes are confined to gitk's Tcl code (39 lines modified) and don't affect core Git functionality.

This version adopts Johannes Sixt's pre-existing geometry management approach rather than the author's initial solution, making it more robust. The patch completes the series' goal of comprehensive window geometry persistence in gitk, addressing a long-standing UX issue where users had to reposition windows manually each session.
