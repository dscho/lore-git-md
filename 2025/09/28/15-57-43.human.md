This is the second patch in a two-part series improving window geometry persistence in gitk, specifically focusing on the Tags/Heads window. The patch makes this secondary window remember its size and position relative to the main gitk window between sessions, storing the geometry in the config file as `geometry(showrefs)`.

Junio Hamano provides a review note, questioning whether the "Currently" in the commit message properly reflects the state of the code - whether the behavior existed before the series' first patch (a revert of an old workaround) or was introduced by that revert. This is a minor clarification request about commit message accuracy rather than a technical concern with the patch itself.

The patch appears technically sound and well-explained, with Junio praising the clear explanation of why this change improves user experience. The series has already gathered sign-offs from key contributors including Johannes Sixt, and addresses a long-standing UX limitation that was previously constrained by old Tcl/Tk compatibility issues.
