This is the second patch in a two-part series improving gitk's window geometry persistence, specifically addressing the Tags/Heads window behavior. The patch builds on the first patch's revert of an old Cygwin Tcl/Tk 8.4.1 workaround to now properly persist both position and size for the Tags/Heads window.

The implementation stores the geometry as `geometry(showrefs)` in gitk's config file, maintaining the window's relative position to the main gitk window across sessions. This addresses a long-standing UX issue where users previously had to reposition this window manually each time. The 39-line Tcl modification includes proper save/restore logic for the relative positioning system.

Junio Hamano notes the patch is well-explained and technically sound, though he questions whether the "Currently" description in the commit message should clarify if this behavior predated or resulted from the reverted workaround. As this touches a subsystem with an official maintainer (Paul Mackerras), Junio indicates he'll defer to the maintainer's pull request process rather than applying directly.

The patch appears ready for inclusion pending any minor commit message clarification about historical context. It completes the series' goal of full window geometry restoration now that modern Tcl/Tk versions no longer require the old Cygwin-specific compromises. With Johannes Sixt's sign-off on the foundational revert and Mark Levedahl's confirmation of safety, the technical solution has broad consensus.
