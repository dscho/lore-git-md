Refactoring patch in the `tb/incremental-midx-part-3` series, continuing the modularization of `builtin/repack.c`. This is patch 24/49, moving the `generated_pack` API out of the builtin and into `repack.c`/`repack.h`.

The patch relocates three key components of pack file handling:
1. The `generated_pack` struct that tracks temporary pack files and their extensions (`.pack`, `.idx`, `.rev`, etc.)
2. The `generated_pack_populate()` function that initializes the struct by registering tempfiles
3. The `generated_pack_install()` function that performs the atomic rename of tempfiles into their final locations

The move follows the series' established pattern of:
- Extracting cohesive functionality
- Maintaining existing behavior (including error handling and file permission preservation)
- Adding declarations to `repack.h` for the new module interface
- Removing the code from `builtin/repack.c`

Key technical details:
- Preserves all safety checks from the original implementation
- Keeps the same extension handling (required vs optional files)
- Maintains atomic rename behavior via `rename_tempfile()`
- Continues using the same `exts` array to track pack file types
- The `generated_pack_has_ext()` helper is also moved, though its use appears limited to internal checks

This builds on previous work that parameterized the pack directory handling (patches 22-23) and follows the series' architectural approach of incremental extraction. The patch appears mechanically sound, with no functional changes beyond the relocation. Future patches in the series will likely continue extracting other components from `builtin/repack.c` following this same pattern.
