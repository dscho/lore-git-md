`the_repository` removal patch in the repack modularization series.

This second patch in Taylor Blau's 49-part series continues the dual-purpose refactoring of `builtin/repack.c`, focusing on eliminating `the_repository` usage from the existing packs API. The change adds a `repo` field to `struct existing_packs` and updates four functions to use this stored repository pointer rather than the global `the_repository`. The affected functions handle pack collection, geometry initialization, and cruft pack combination.

Key technical details:
- Adds `struct repository *repo` to `struct existing_packs`
- Modifies `collect_pack_filenames()`, `init_pack_geometry()`, and `combine_small_cruft_packs()` to use the stored repo pointer
- Updates `cmd_repack()` to initialize the new field with its `repo` parameter
- Maintains identical behavior while removing direct `the_repository` access
- Touches packfile storage access points that interact with object directories and pack indices

The patch follows the pattern established in the first patch of the series, systematically converting repository access to use explicit parameters. The changes are mechanical but important for both the modularization effort and the broader `the_repository` removal initiative. No functional changes or new tests are introduced, as this remains preparatory work for the larger MIDX-based repacking functionality.
