This is part 23 of Taylor Blau's major refactoring series for `builtin/repack.c`, continuing the modularization effort that combines `the_repository` removal with repack machinery modernization. 

The patch parameterizes the `generated_pack_install()` function to explicitly take `packdir` and `packtmp` locations rather than accessing them as static variables. This follows the pattern established in previous patches of removing implicit dependencies to prepare for relocating functions out of the monolithic `builtin/repack.c` file.

The change is straightforward - it adds two parameters to the function declaration and updates the single call site to pass them through. The author notes a minor concern about the function's three consecutive `const char*` parameters being error-prone, but considers a dedicated struct overkill at this stage.

This continues the series' disciplined approach of making small, focused changes that incrementally improve the code structure while maintaining behavior. The patch builds cleanly on the previous extraction of pack installation logic in patch 21 and naming standardization in patch 20. While not flashy, these systematic changes are exactly what's needed to untangle the complex repack machinery.
