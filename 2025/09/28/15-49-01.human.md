This is a revert patch in the ongoing effort to restore full window geometry persistence in gitk. It's the first of a two-patch series (now at v3) that aims to properly save and restore both window position and size for gitk's main and Tags/Heads windows.

The patch specifically reverts commit b9bee115 from 2008, which had limited gitk to only restoring window size (not position) due to bugs in Cygwin's outdated Tcl/Tk 8.4.1 implementation. Junio Hamano notes in his reply that the commit message could better highlight this as fixing a long-standing historical workaround rather than a recent issue. The original limitation became obsolete in 2011 when Cygwin upgraded to modern Tcl/Tk versions.

The patch has strong historical justification, with input from both the original author (Mark Levedahl) and Johannes Sixt who worked on the initial window restoration code. The thread shows consensus that this is a worthwhile cleanup now that the technical constraints no longer exist. The series appears well-vetted, with previous versions having addressed timing sensitivity in window management.

This change will improve user experience by making gitk remember window positions across sessions, something that was intentionally disabled due to platform limitations that have long been resolved. The clean revert suggests the change is low-risk while providing clear UX benefits.
