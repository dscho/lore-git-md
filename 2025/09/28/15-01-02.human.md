This is a follow-up discussion in the gitk window geometry persistence thread, specifically about Patch 1/2 which reverts an old workaround for Cygwin's Tcl/Tk 8.4.1 issues. 

Mark Levedahl clarifies the historical context, explaining that while the original fix (e9937d2a03) addressed Cygwin's Tcl/Tk 8.4.1 problems by restoring full window geometry, commit b9bee11526 later scaled this back to only restoring window size (not position) due to complaints about overriding window manager behavior. He confirms he's fine with restoring full geometry now that the Cygwin Tcl/Tk issues are long resolved.

Michael Rappazzo notes a technical difference in his v2 version of the patch - it uses `after idle` when restoring geometry, which he says relates to timing concerns addressed in his second patch (for the Tags/Heads window persistence). This suggests the geometry restoration needs to be carefully sequenced to avoid race conditions.

The discussion shows the patch is well-grounded in historical context and the technical approach appears sound, with both original authors (Johannes Sixt and Mark Levedahl) supporting the change. The minor implementation detail about `after idle` shows attention to subtle timing issues in the window management code.
