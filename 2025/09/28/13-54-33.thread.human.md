This thread addresses a long-standing issue in gitk where window geometry (position and sizes) wasn't properly persisted across sessions. The two-patch series modernizes this behavior by fully restoring both the main window and Tags/Heads window layouts.

Johannes Sixt (Hannes) has led the effort, building on earlier work by Michael Rappazzo. The first patch reverts an old Cygwin workaround from 2008 that only saved window sizes. The second patch - now in its second version - implements proper persistence for the Tags/Heads window, with special attention to Windows-specific behavior. The solution stores geometry in gitk's config, handles Tcl scoping carefully, and ensures the window positioning works correctly across platforms.

The v2 changes specifically fix a Windows issue where only size was being restored in the initial version. The refined approach modifies the `make_transient` procedure to accept geometry parameters while maintaining fallback behavior. With all technical concerns addressed and consensus reached, the series appears ready for inclusion. Junio Hamano has provided some editorial suggestions but will defer to gitk maintainer Paul Mackerras for final merge. This concludes a multi-year effort to properly restore gitk's window persistence capabilities.
