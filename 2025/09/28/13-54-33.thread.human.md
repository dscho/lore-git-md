This thread addresses a two-patch series improving window geometry persistence in gitk, the Git repository browser. The first patch reverts an old workaround that limited window restoration to size-only (due to Cygwin Tcl/Tk 8.4.1 issues from 2008), while the second patch adds proper position and size persistence for the Tags/Heads window. Together they restore complete window state management now that modern Tcl/Tk versions no longer require the old compromises.

Johannes Sixt (Hannes) provided the foundational revert patch, while Michael Rappazzo contributed the Tags/Heads window persistence solution. The implementation stores window geometry in gitk's config file and maintains the Tags/Heads window's relative position to the main window. Mark Levedahl, who originally implemented the size-only compromise, confirmed that full restoration is now safe. Junio Hamano suggested minor commit message clarifications about the historical context but found the technical solution sound. As gitk has an official maintainer (Paul Mackerras), Junio indicated he'll defer to the maintainer's pull request process rather than applying the patches directly.

The series has broad consensus with Johannes Sixt's sign-off and no outstanding technical objections. It addresses a long-standing user experience issue where users previously had to manually reposition windows each session. With the patches technically complete and only awaiting minor documentation tweaks, the series appears ready for inclusion once the commit messages are finalized.
