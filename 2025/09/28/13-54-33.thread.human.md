This thread addresses a long-standing limitation in gitk's window management, where the main window and Tags/Heads window would only remember their sizes but not positions due to old workarounds for Cygwin Tcl/Tk 8.4.1 issues (fixed since 2011). Johannes Sixt (Hannes) and Michael Rappazzo collaborated on a two-patch solution to restore full geometry persistence.

The first patch reverts the 2008 workaround that limited the main window to size-only restoration. The second patch, now in its third iteration, handles the Tags/Heads window. Michael Rappazzo's initial 39-line implementation has been refined by Johannes Sixt into a more minimal 12-line version that properly handles variable scoping through explicit `unset` and `global` declarations. The solution stores window geometry as `geometry(showrefs)` in gitk's config file and uses Tcl's `bindtags` to manage window events cleanly.

All participants agree the architectural approach is sound, with Junio Hamano providing editorial suggestions and deferring to gitk maintainer Paul Mackerras for final inclusion. The patches represent a complete solution to restore gitk's window management behavior now that the original Cygwin limitations are obsolete. The only remaining discussion points were implementation details around variable scoping in the Tcl code, which Johannes Sixt has now addressed in this version.
