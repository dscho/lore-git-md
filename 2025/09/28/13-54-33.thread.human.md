This thread discusses a two-patch series to improve gitk's window geometry persistence, now in its third iteration. The core issue involves restoring both position and size for gitk's main window and Tags/Heads window, reversing a 2008 compromise that only saved window size due to limitations in Cygwin's outdated Tcl/Tk 8.4.1. These constraints became obsolete when Cygwin upgraded to Tcl/Tk 8.6 in 2011.

The series combines Johannes Sixt's (Hannes) work on main window restoration with Michael Rappazzo's solution for the Tags/Heads window. Mark Levedahl, who originally implemented the full geometry restoration that was later scaled back, has confirmed that restoring complete window state is now safe. The technical solution uses four new Tcl procedures and Map event binding to avoid race conditions.

Junio Hamano, the Git maintainer, has now suggested a minor formatting improvement to the revert commit message to better indicate it addresses historical code. This is purely a documentation tweak - the implementation remains unchanged and continues to have Johannes Sixt's sign-off. There's clear consensus that removing this long-standing workaround is appropriate, with no remaining technical objections. The series appears ready for merging once the commit message is adjusted as suggested.
