This is a refactoring patch in the ongoing `tb/incremental-midx-part-3` series, continuing the modularization of `builtin/repack.c`. Patch 40/49 introduces a new `struct write_pack_opts` to consolidate common parameters used by pack-writing functions.

The patch addresses the repetitive parameter passing between `write_filtered_pack()` and `write_cruft_pack()` by bundling their shared arguments (`pack_objects_args`, `destination`, `pack_prefix`) into a new struct. It also includes two previously static variables (`packdir` and `packtmp`) that these functions need to access. The changes are purely structural - no behavior is modified.

Key technical points:
- New `struct write_pack_opts` defined in `repack.h` with five fields covering all shared pack-writing parameters
- `write_filtered_pack()` modified to take the struct instead of individual parameters
- Call sites updated to use the new struct interface
- Maintains all existing functionality while reducing parameter duplication
- Follows the series' pattern of encapsulating related parameters into dedicated structs

This continues the series' systematic approach to breaking down the monolithic repack implementation into more maintainable components. The change reduces parameter passing complexity and provides a more consistent interface for pack-writing operations, setting up future patches to more easily modify this behavior. The patch fits cleanly into the established refactoring methodology while making measurable progress in reducing code duplication.
