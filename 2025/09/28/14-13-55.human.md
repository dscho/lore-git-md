Feature proposal for wildcard path matching in Git credential configuration, building on the initial thread about partial URL matching. M Hickford provides a clearer example demonstrating the need exists beyond just OAuth use cases: distinguishing between personal (`git.example.com`) and enterprise (`git.example.com/syscorp/`) credentials under the same domain.

The example shows how implicit wildcard syntax (`/syscorp/.username`) could work alongside existing exact matches, allowing different credentials for path prefixes while maintaining backward compatibility. This addresses a real configuration pain point where users currently must either use separate domains or accept credential sharing across security boundaries.

The proposal remains at the discussion stage, with key questions still open about syntax preference (explicit `*` vs implicit `/` termination) and security implications of prefix matching. No implementation has been proposed yet, but the concrete examples help clarify the use case and potential behavior. The change would require careful handling in credential.c's matching logic and updates to gitcredentials documentation.
