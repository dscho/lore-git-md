This is part 41 of Taylor Blau's 49-part series refactoring `builtin/repack.c` to eliminate globals and prepare for incremental MIDX-based repacking. The patch continues the systematic encapsulation pattern by applying the new `write_pack_opts` struct to the `write_cruft_pack()` function, following the same approach used for `write_filtered_pack()` in the previous patch.

The changes replace five individual parameters with a single `write_pack_opts` struct containing `po_args`, `destination`, `pack_prefix`, `packtmp`, and `packdir`. This reduces parameter passing complexity while maintaining identical behavior. The patch updates all call sites of `write_cruft_pack()` to use the new struct-based interface, including both the main cruft pack creation path and the expiration path.

Key technical details include:
- The `write_cruft_pack()` function signature changes to take `struct write_pack_opts*` instead of individual parameters
- Call sites now initialize the struct with consistent field values
- The expiration path reuses the same struct by just updating the `destination` field
- All pack-objects preparation and cruft pack writing logic remains functionally equivalent

This continues the series' methodology of identifying cohesive functionality, parameterizing dependencies, and standardizing interfaces before potential relocation to new modules. The changes demonstrate careful attention to maintaining behavior while simplifying the code must traverse.
