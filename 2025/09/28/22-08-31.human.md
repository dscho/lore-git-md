Refactoring patch in the ongoing repack.c modularization series. This is part 21 of Taylor Blau's 49-part effort to modernize Git's repacking machinery while removing global variables like `the_repository`.

The patch extracts the pack installation logic into a new `generated_pack_install()` function. This handles the multi-step process of moving newly created pack files from temporary to permanent locations, including:
- Adjusting file permissions before rename
- Error handling for missing required extensions
- Cleanup of unused extension files

The change continues the series' pattern of breaking down the monolithic `builtin/repack.c` into focused, reusable components. While this patch doesn't yet move the function to a module (that's planned for a future commit), it creates a clear boundary for that eventual move. The implementation appears thorough, maintaining all existing behavior while making the code more maintainable.

This is a typical incremental step in the larger refactoring - not particularly controversial on its own, but part of the important groundwork for the MIDX-based repacking functionality the series is working toward. The patch follows the established pattern of the series, with clear commit messages and careful attention to detail.
