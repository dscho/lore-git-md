This is part of the ongoing `the_repository` removal effort and refactoring of `builtin/repack.c`. The sixth patch in Taylor Blau's 49-part series continues converting global variable usage to explicit repository-based access patterns.

The change focuses on pack deletion logic, specifically modifying `mark_packs_for_deletion_1()` to avoid using the global `the_hash_algo` variable. Instead, it now takes a `git_hash_algo` pointer from the repository structure. This maintains the same safety check (preventing accidental deletion of newly written packs with identical checksums) while further eliminating global state.

The patch is small (6 lines added, 4 removed) and mechanically straightforward - it passes the hash algorithm through the existing repository pointer rather than accessing it globally. This continues the series' pattern of behavior-preserving changes that incrementally modernize the codebase. The change appears well-contained and low-risk, touching only pack deletion paths that were already being modified in earlier patches of the series.

As with previous patches, this contributes to both the immediate goal of removing `the_repository` usage and the larger effort to modularize repack functionality for future MIDX-based improvements.
