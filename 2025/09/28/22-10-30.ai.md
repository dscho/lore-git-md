Refactoring patch in the ongoing `builtin/repack.c` modularization series. This is patch 47/49 in Taylor Blau's incremental MIDX preparation work, continuing the systematic extraction of functionality from the monolithic repack builtin into focused compilation units.

The patch moves `write_filtered_pack()` from `builtin/repack.c` to a new `repack-filtered.c` module, making it part of the repack.h API. The function handles pack filtering operations during repacking, including processing kept/non-kept packs and cruft packs. The implementation remains behaviorally identical, just relocated with its dependencies properly parameterized through the `write_pack_opts` and `existing_packs` structs.

Key technical details:
- Creates new `repack-filtered.c` compilation unit
- Preserves all existing pack filtering logic including:
  - `--stdin-packs` handling
  - Kept pack processing (with `pack_kept_objects` flag from previous work)
  - Cruft pack inclusion
  - Pack prefix handling
- Maintains interface with `finish_pack_objects_cmd()` for pack finalization
- Updates build systems (Makefile and meson.build) to include new module

The change follows the series' established methodology of:
1. Identifying cohesive functionality (`write_filtered_pack`)
2. Ensuring proper parameterization (already done via structs in earlier patches)
3. Extracting with minimal changes
4. Maintaining behavioral equivalence
5. Adding to the growing repack.h API

This continues the pattern seen in patches 1-46 of systematically breaking down the 1700+ line `builtin/repack.c` into logical components while eliminating global state. The series remains focused and methodical, with each patch handling one clear extraction or refactoring step.
