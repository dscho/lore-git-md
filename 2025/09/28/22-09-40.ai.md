This is patch 38/49 in Taylor Blau's series refactoring `builtin/repack.c` to modularize the code and prepare for incremental MIDX functionality. The patch continues the series' pattern of encapsulating functionality and reducing parameter passing.

The change inlines the pack list handling within `write_midx_included_packs()`, removing the need for callers to first compute and pass the list of packs to include. The key technical changes are:
- Removes the `include` field from `repack_write_midx_opts` struct
- Moves the `string_list include` declaration into `write_midx_included_packs()`
- Calls `midx_included_packs()` directly within the function
- Updates all callers to no longer manage the pack list themselves

This refactoring prepares for future incremental MIDX functionality by establishing a pattern where each MIDX-writing function is responsible for determining which packs to include, rather than having that logic split between caller and callee. The commit message explains this will avoid awkward duplication when incremental MIDX support is added later.

The patch maintains all existing functionality while simplifying the control flow. It follows the series' established methodology of first relocating then integrating code, with no behavioral changes. The change is focused and mechanical, continuing the systematic elimination of parameter passing in favor of encapsulated operations.

This work builds on previous patches that parameterized pack directory handling and introduced configuration structs, while paving the way for future patches that will further abstract pack tracking and complete the encapsulation of pack-objects configuration.
