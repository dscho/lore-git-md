The sixth patch in Taylor Blau's 49-part series continues the dual refactoring of `builtin/repack.c`, combining modularization with `the_repository` removal. This patch specifically targets the elimination of `the_hash_algo` global variable usage in pack deletion logic.

The change modifies `mark_packs_for_deletion_1()` to accept a `git_hash_algo` pointer parameter rather than using the global `the_hash_algo`. This function is responsible for safely identifying packs for deletion by checking their checksums, using the hash algorithm's hex size to isolate the checksum portion of pack filenames. The patch propagates this change through the call chain, now obtaining the hash algorithm from the repository pointer stored in the `existing_packs` struct.

This continues the series' pattern of methodically replacing global variable access with explicit parameter passing. The modification maintains identical behavior while removing another instance of implicit global state. The change is localized to pack deletion safety checks and doesn't affect the actual pack deletion mechanism itself.

The patch is part of the larger effort to both modularize repack functionality and eliminate `the_repository`/`the_hash_algo` globals, preparing the codebase for future incremental MIDX-based repacking work. The change is straightforward and maintains existing behavior while progressing the series' architectural goals.
