This is a documentation patch proposing a breaking change announcement for mandatory Rust support in Git 3.0, as the third part of Patrick Steinhardt's RFC series introducing Rust infrastructure to Git core.

The patch adds a new section to BreakingChanges.adoc declaring the project's intent to make Rust a mandatory build dependency starting with Git 3.0, currently estimated for second half of 2026. It explains the current transitional approach where Rust usage is optional (via meson configuration flags) while distributors prepare for the change. The announcement notes that Git 2.52 (the last pre-3.0 release) will become a long-term support version to accommodate platforms needing more time to implement Rust support.

Key technical details include:
- Current optional Rust usage via `meson configure -Drust=(enabled|disabled|auto)`
- Two current use cases for Rust (interop testing via parallel implementations and non-critical new features)
- Explicit mention of gcc-rs as a potential future alternative backend
- The patch ties back to the series' first two patches (build system support and varint.c conversion) as initial test balloons
- Maintains consistency with the RFC's phased approach while signaling the eventual mandatory requirement
- Acknowledges platform concerns while setting a clear timeline for ecosystem adaptation

The announcement represents a significant policy decision that will likely generate discussion about:
- Impact on platforms without Rust support (NonStop, embedded systems)
- The 18-month timeline for mandatory adoption
- Maintenance burden of the LTS 2.52 release
- Whether gcc-rs maturity aligns with the projected timeline
- Alternative approaches like maintaining optional Rust support longer-term
