This thread reports a bug in how `git rebase --continue` interacts with the `prepare-commit-msg` hook. The issue specifically prevents environment variables and temporary config settings (passed via `-c`) from being properly propagated to the hook during rebase continuation, despite other parameters like the repository path working correctly. The reporter provides clear reproduction steps showing that neither `$FOO` environment variables nor `hooks.foobar` config settings are accessible in the hook during rebase, though they work fine in normal operation.

The problem appears limited to the rebase continuation scenario and affects Git 2.51.0 (and likely other versions). This could impact workflows that rely on `prepare-commit-msg` hooks for automated commit message processing during conflict resolution. The well-structured report makes the issue easy to verify, with clear expected/actual output comparisons. A fix would need to address how rebase passes context to hook invocations during continuation.
