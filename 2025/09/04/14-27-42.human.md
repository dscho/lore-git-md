This is a refactoring patch in Patrick Steinhardt's ongoing `git-history` command series (v3, patch 12/18). It reorganizes the interactive add/patch code to better separate concerns between the "add -i" and "add -p" subsystems.

The patch introduces a new `struct interactive_options` to hold common configuration that was previously passed around via `struct add_p_opt`. This clarifies which options apply to which parts of the interactive code. The change moves color handling and other configuration into a new `interactive_config` structure, cleaning up the tangled initialization paths.

While this is primarily a code organization improvement, it's part of the larger effort to build the new `git-history` command. The changes touch several builtin commands (add, checkout, commit, reset, stash) that use the interactive add/patch infrastructure, updating them to use the new interface. The patch maintains all existing functionality while making the codebase more maintainable.

The refactoring appears thorough and well-motivated, with clear commit messages explaining the current confusion and how this change helps. It's a typical preparatory patch in a larger series - not flashy, but important groundwork for future features.
