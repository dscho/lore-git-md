Patrick Steinhardt is leading a refactoring effort to prepare Git's commit graph handling for the pluggable object database (ODB) work. The series currently consists of four patches that systematically change how commit graphs are accessed, moving away from direct access through `r->objects->commit_graph` to instead receive graph pointers from helper functions. This change is necessary because commit graphs will soon be stored in the new `odb_source` structure rather than `object_database`.

The first two patches cleaned up redundant commit graph existence checks in bloom filter code. The third patch modified `prepare_commit_graph()` to return the graph pointer directly, updating all callers to use this new pattern. The latest fourth patch follows the same approach with `repo_find_commit_pos_in_graph()`, changing it to return the relevant graph instance rather than just a boolean. Both bloom filter loading and commit graph info loading code have been updated to use the returned pointers.

The changes are mechanical but important for the larger ODB work, with each patch carefully updating callers while maintaining existing behavior. The series demonstrates Patrick's characteristic thoroughness - every affected caller is updated, documentation is kept current, and the changes preserve all edge cases. While the immediate impact is limited to internal APIs, these changes lay crucial groundwork for the pluggable ODB backend system that will allow alternative object storage implementations.
