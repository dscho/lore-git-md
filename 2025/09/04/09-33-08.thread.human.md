This thread explores how to improve partial clone usability, with a focus on making blobless clones (which omit file contents initially) the default behavior. The discussion builds on existing `--filter=blob:none` functionality and Scalar's current implementation of blobless-by-default clones.

Derrick Stolee provided important context about existing tooling, noting that `git backfill` handles blobless clones well, while treeless clones would require more expensive operations. He highlighted Scalar's role as an incubator for clone optimizations before they might graduate to mainline Git.

Junio Hamano has now weighed in on the feature adoption strategy, arguing against creating new commands like `git big-clone` for mature features. Instead, he advocates integrating proven optimizations into existing commands like `git clone`, either as new options or smart defaults (with appropriate user consent). This approach balances discoverability of new features with Git's stability requirements, using Scalar as a testing ground before potential core integration.
