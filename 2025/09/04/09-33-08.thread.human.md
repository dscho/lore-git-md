This thread explores making partial clones more user-friendly, with a focus on blobless clones (which omit file contents) as a potential default. The discussion has evolved through several key points:

Derrick Stolee and Patrick Steinhardt have provided deep technical analysis, establishing that blobless clones (which can efficiently fetch missing files later) are practical for most workflows, while treeless clones (which omit directory structures) are only viable for specialized cases like CI builds where speed matters more than full history access. Stolee notes that Scalar already implements blobless-by-default behavior, serving as a testing ground for these optimizations before they might graduate to core Git.

Junio Hamano has weighed in on the broader strategy, arguing against creating parallel commands (like `git big-clone`) and instead advocating for integrating proven optimizations into existing commands when ready. The discussion has narrowed to focus on blobless clones as the primary optimization path, with treeless clones relegated to niche CI use cases where their limitations are acceptable tradeoffs.

Key questions remain about how to surface these features to users - whether through Scalar's specialized commands or by gradually enhancing core Git's `clone` and `fetch` with smarter defaults. The technical consensus is coalescing around blobless clones as the most promising direction, with clear recognition of their adoption path through Scalar first.
