This thread explores proposals to improve partial clone workflows by making blobless clones the default and adding better tooling for fetching missing history. The original proposal suggests new config options, commands for downloading missing objects with progress tracking, and conversion between clone types. Kristoffer Haugsbakk noted similarities to the existing `git backfill` command, though it's unclear how well it handles treeless clones.

Derrick Stolee provided important context about the project's current approach: `scalar clone` already implements blobless-by-default behavior, serving as a testing ground for optimizations before they might graduate to core Git. He clarified that `git backfill` works for blobless clones but isn't well-suited for treeless scenarios. The discussion highlights the tension between Scalar's rapid iteration and core Git's stability requirements, with Stolee suggesting `scalar clone` may already address much of what's being proposed, though discoverability remains a concern.

Key open questions include how to better surface these features for users not using Scalar, whether treeless clone workflows need different tooling, and how to balance innovation with backward compatibility in core Git commands. The thread continues to explore these usability improvements while grounding discussions in existing tooling and the project's incremental development philosophy.
