This thread explores proposals to improve partial clone usability, with a focus on making blobless clones (`--filter=blob:none`) the default via config options and adding better tooling for fetching missing objects. The discussion originated from a feature proposal that included commands to convert between clone types and fetch missing history with progress tracking.

Derrick Stolee provided important context about existing tooling, noting that `git backfill` handles blobless clones well but isn't optimized for treeless clones, while `scalar clone` already implements blobless-by-default behavior as a testing ground. Junio Hamano weighed in on feature adoption strategy, advocating for integrating proven optimizations into main Git commands rather than creating specialized variants, with Scalar serving as an incubator.

In the latest contribution, Patrick Steinhardt reinforces the challenges with treeless clones, proposing but ultimately dismissing a depth-based batching approach for tree backfilling due to fundamental limitations. His analysis suggests treeless clones may be a dead end for this effort, narrowing the viable options to blobless clones. The thread now centers on how to best integrate these optimizations - whether through Scalar's incubation path or direct changes to core Git commands - while addressing discoverability and backward compatibility concerns.
