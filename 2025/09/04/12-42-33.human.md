This is a bugfix follow-up to a protocol v2 upload-pack patch that aimed to deduplicate ACKs for non-commit objects. Patrick Steinhardt acknowledges Junio Hamano's concern that the original patch could break parent commit processing in edge cases where clients send commits non-chronologically.

The key issue is that the initial patch moved the `THEY_HAVE` flag check too early, potentially skipping grandparent marking when a parent commit is seen multiple times. While this didn't surface in normal client behavior (since clients typically stop advertising parents of ACKed objects), it could cause problems in edge cases.

Patrick proposes moving the duplicate check after commit parent processing, which should maintain the deduplication benefits while properly handling all commit ancestry chains. The change is minimal and focused - just reordering two code blocks in `do_got_oid()` to ensure parent commits are always processed regardless of whether we've seen them before.

This appears to be a legitimate protocol edge case that needs fixing, though it's notable that no test failures caught the original oversight. The fix seems straightforward and maintains the original goal of reducing redundant network traffic in protocol v2.
