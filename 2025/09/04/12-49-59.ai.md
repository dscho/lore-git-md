This is the fifth patch in Patrick Steinhardt's series refactoring commit graph handling for the pluggable ODB effort. The patch continues the established pattern of moving away from direct repository access by modifying commit graph merge functions to accept the graph to be merged as a parameter rather than fetching it from the repository context.

The key change is converting `split_graph_merge_strategy()` and `merge_commit_graphs()` to take a `struct commit_graph *` parameter, eliminating their direct access to `ctx->r->objects->commit_graph`. This prepares for future changes where determining the graph to merge may become more complex. The patch updates all call sites to pass the graph explicitly, with `write_commit_graph()` now passing the graph it already has rather than letting the functions fetch it themselves.

The changes are mechanical and follow the same careful, behavior-preserving approach seen in previous patches. The diff shows straightforward parameter additions and caller updates, with no logic changes beyond the access pattern modification. This continues the series' progression toward proper multi-backend commit graph handling by further decoupling graph operations from direct repository access.
