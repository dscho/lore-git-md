This is a preparatory patch in the `git-history` command series, focusing on hook execution infrastructure for the_repository removal and history editing operations.

The patch wires up the "rewritten-hook" execution for the new `REPLAY_HISTORY_EDIT` mode in the sequencer. Previously this hook was only triggered during interactive rebases, but now it will also run for history editing operations. The implementation refactors several sequencer functions to handle both rebase and history-edit cases, passing the `replay_opts` parameter through call chains to determine which mode is active.

Key technical changes include:
- Adds new path functions for rewritten-list and rewritten-pending files in the sequencer directory
- Modifies `flush_rewritten_pending()` and `record_in_rewritten()` to accept `replay_opts` and select appropriate paths based on operation mode
- Updates hook execution to use "history" as the argument for history edit operations (vs "rebase")
- Ensures consistent behavior between rebase and history-edit modes for commit rewrites
- Maintains the existing rebase behavior while adding history-edit support

The changes touch core sequencer operations including commit picking, continuation, and unnecessary-pick skipping. The patch demonstrates careful attention to maintaining existing behavior while extending functionality, with thorough updates to all affected code paths. This continues the series' pattern of preparing sequencer infrastructure for the planned history editing commands while aligning with Git's architectural direction of removing global state.
