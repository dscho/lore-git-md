This is a preparatory patch for the `git-history` command series, focusing on sequencer infrastructure changes. It allows callers to provide custom commit ID mappings when using the rewritten-hook, which will be needed for upcoming `git-history` subcommands that pre-rewrite commits before using the sequencer.

The patch adds a new `old_oid_mappings` field to the `replay_opts` struct and corresponding logic in `record_in_rewritten()` to handle cases where commits are being reinserted at new positions without their content changing. This solves a specific edge case where the original and rewritten commit IDs would otherwise be identical, which would make the hook output unhelpful.

The change is small (21 lines) but important for the planned functionality, adding a new `replay_oid_mapping` struct and integrating it with the existing oidmap infrastructure. This continues the series' pattern of carefully extending sequencer capabilities to support history editing operations while maintaining compatibility with existing hooks.
