This is a preparatory refactoring patch for the `git-history` command series, adding infrastructure to the working tree status subsystem. The patch introduces a new function `wt_status_collect_changes_trees()` that can show changes between two arbitrary trees, rather than just between the working tree/index and HEAD as the existing status functions do.

The function follows the same pattern as the existing working tree status collection, but takes two tree OIDs as input instead of examining the repository state. It uses the same callback mechanism to collect changes, supporting rename detection and other diff options configured in the `wt_status` struct. The implementation is clean and straightforward, reusing existing diff machinery.

While this functionality is a bit of a stretch for the "working tree" status subsystem, the patch makes a reasonable case that it's better to centralize this logic rather than duplicate it. The change is unused in this patch but will be needed for upcoming history editing operations in the `git-history` command series.

This continues the series' pattern of careful infrastructure preparation before implementing user-facing features. The patch is well-contained and clearly motivated, though it might benefit from a test case showing the new function's behavior (which may come in a later patch that actually uses it).
