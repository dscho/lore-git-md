This thread addresses a bug in Git's combine-diff machinery that was uncovered by the new `git last-modified` command. The core issue stems from `diff_tree_combined()` forcibly setting the recursive flag in diff options since 2006 without proper justification. The initial patch proposed removing this behavior, which would fix a BUG() in `git last-modified` when processing merge commits while also providing a 2x performance improvement on git.git repository.

Junio Hamano has now raised important concerns about backward compatibility, noting that the patch would alter `git diff-tree -c` output that has been stable for nearly two decades. While the technical improvements are clear - including corrected diff output, fixed hashmap corruption, and better performance - there's tension between fixing the underlying issue and preserving expected behavior. Hamano suggests either maintaining backward compatibility for `diff-tree -c` while still fixing `last-modified`, or explicitly documenting the breaking change by updating tests to show the new behavior with `-r` flag usage.

The discussion has shifted from the technical implementation (which was thoroughly addressed in earlier emails) to weighing the user experience impact of changing long-standing output formats. The resolution will need to balance these considerations while maintaining the command's correctness and performance gains.
