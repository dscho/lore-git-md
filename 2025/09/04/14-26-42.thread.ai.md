RFC PATCH series introducing Rust infrastructure to Git core, now at v4 with 10 patches (expanded from 9), transitioning Rust from optional to mandatory by Git 3.0. Authored by Patrick Steinhardt, tracking meson implementation (v1), Makefile preparation (v2), Makefile integration (v3), varint subsystem conversion (v4), and CI completion (v4 10/10). Key technical progression includes:

- Build system: Unconditional Cargo usage via wrapper script (cargo-meson.sh) with complete meson and Makefile integration (v4 3/9) including `WITH_RUST` toggle, Rust source tracking, and quiet build output. New v4 4/9 adds Rust build status reporting to `git version --build-options` and `git bugreport`. Final CI patch (v4 10/10) ensures Rust tooling in breaking-changes CI jobs. SZEDER Gábor and Junio C Hamano note a minor oversight in Makefile cleanup - `Cargo.lock` is now properly ignored but missing from `clean` target, a simple housekeeping addition. Brian m. carlson's review of the meson build system patch (v4 1/9) acknowledges the pragmatic approach of the cargo-meson.sh wrapper, noting it handles debug/release builds while properly placing the library, and suggests it could potentially abstract mrustc functionality if that compiler becomes viable. They humorously approve the empty lib.rs as a minimal starting point, indicating acceptance of this build system approach.

- Type safety: Varint conversion (v4 5/9) uses explicit Rust types (u8/usize) with matching C integer widths (uint64_t for values, uint8_t for lengths) in dir.c, read-cache.c, varint.c, varint.h. Changes ensure platform-independent behavior while maintaining varint format constraints. Directly addresses Brian m. carlson's earlier type safety concerns. Junio C Hamano's feedback on this patch accepts the technical approach while noting `uint8_t` for length is acceptable but not strictly necessary, and anticipating future discussions about Rust's `u64` vs C's `uint64_t`.

- Infrastructure: Test wiring added using Rust's native unit testing capabilities, plus new build visibility for transitional debugging. CI now tests breaking changes path via unified test execution logic with expanded platform coverage through new `fedora-breaking-changes-meson` job replacing obsolete "pedantic" job.

- Documentation: Junio C Hamano's latest feedback on the BreakingChanges documentation patch (v4 7/9) questions the classification of Rust features and the "test balloon" terminology given the mandatory transition. Raises practical concerns about the proposed LTS maintenance handoff model.
