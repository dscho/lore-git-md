RFC PATCH series introducing Rust infrastructure to Git core, now at version 4 with refined build system integration and transition planning. Authored by Patrick Steinhardt, with responses from multiple contributors. The series proposes Rust as a mandatory dependency starting Git 3.0, currently in RFC stage with experimental status.

Build system changes focus on meson integration (initially) to compile Rust as static lib (`libgit_rs`) with basic test harness. Key technical updates include `RUST` preprocessor define for conditional compilation, meson 0.42.0 requirement (down from 1.9.0), and now a proposed three-phase transition plan for Rust adoption. Current implementation rewrites varint.c (92 lines) in Rust (varint.rs) maintaining C ABI compatibility through `#[no_mangle]` extern functions.

Patrick Steinhardt's latest email introduces a phased transition approach in response to Eric Sunshine's concerns about silent fallback masking platform issues. The plan progresses from current auto-detection to opt-out configuration, then mandatory for Git 3.0, with documentation in BreakingChanges. This maintains RFC flexibility while addressing visibility concerns for packagers.
