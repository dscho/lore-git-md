RFC PATCH series introducing Rust infrastructure to Git core, now at v4 with 10 patches (expanded from 9), transitioning Rust from optional to mandatory by Git 3.0. Authored by Patrick Steinhardt, tracking meson implementation (v1), Makefile preparation (v2), Makefile integration (v3), varint subsystem conversion (v4), and CI completion (v4 10/10). Key technical progression includes:

- Build system: Unconditional Cargo usage via wrapper script (cargo-meson.sh) with complete meson and Makefile integration (v4 3/9) including `WITH_RUST` toggle, Rust source tracking, and quiet build output. New v4 4/9 adds Rust build status reporting to `git version --build-options` and `git bugreport`. Final CI patch (v4 10/10) ensures Rust tooling in breaking-changes CI jobs by adding `cargo` to dependency lists (Fedora/AlmaLinux and Ubuntu/Debian) and setting `WITH_RUST=YesPlease` with `-Drust=enabled` Meson flags for breaking-changes testing. CI now fully exercises Rust infrastructure under breaking-changes conditions via unified test execution logic.

- Type safety: Varint conversion (v4 5/9) uses explicit Rust types (u8/usize) with matching C integer widths (uint64_t for values, uint8_t for lengths) in dir.c, read-cache.c, varint.c, varint.h. Changes ensure platform-independent behavior (19 lines added/15 removed) while maintaining varint format constraints (16-byte max encoding). Directly addresses Brian m. carlson's type safety concerns. Junio C Hamano's feedback on this patch accepts the technical approach while noting `uint8_t` for length is acceptable but not strictly necessary, and anticipating future discussions about Rust's `u64` vs C's `uint64_t` when Ezekiel Newren's related work merges, with a maintainer preference for maintaining `uint64_t` consistency in C portions.

- Infrastructure: Test wiring added using Rust's native unit testing capabilities, plus new build visibility for transitional debugging. CI now tests breaking changes path via unified test execution logic (removing `run_tests` conditional) with expanded platform coverage through new `fedora-breaking-changes-meson` job replacing obsolete "pedantic" job.

- Documentation: Junio C Hamano's latest feedback on the BreakingChanges documentation patch (v4 7/9) questions the classification of Rust features (subsystems vs new features) and the "test balloon" terminology given the mandatory transition. Raises practical concerns about the proposed LTS maintenance handoff model regarding security embargo processes and mailing list review requirements. Maintains support for the transition while seeking clearer language about mandatory implications and more realistic LTS expectations.

- Timeline: Accelerated rollout removes intermediate `-Dbreaking_changes` step
- CI: Cargo.lock added to .gitignore, CI now installs cargo directly and adds Meson/ninja dependencies for Fedora
- Build control: Meson rules auto-enable Rust if cargo is found, controllable via `-Drust=` option, with `-Dbreaking_changes=true` for Meson builds
