This is a preparatory patch for the `git-history` command series, focusing on sequencer infrastructure changes. It introduces a new `skip_commit_summary` option in the sequencer to control whether commit summaries are printed after operations like cherry-pick.

The patch adds a boolean flag to `struct replay_opts` and persists it in the sequencer configuration file. The main change is modifying `do_commit()` to respect this flag when deciding whether to call `print_commit_summary()`. The configuration handling is added to both the parsing (`populate_opts_cb()`) and saving (`save_opts()`) logic.

Key technical details:
- New `skip_commit_summary` field in `struct replay_opts`
- Configuration stored as `options.skip-commit-summary` in sequencer state
- Changes affect `sequencer.c` and `sequencer.h`
- Will be used by upcoming `git-history` command where commit summaries would be less useful

The patch appears well-contained and focused, with clear motivation stated in the commit message. It follows standard Git patterns for sequencer configuration handling. This is a straightforward infrastructure change that enables the more complex history editing operations planned in later patches of the series.
