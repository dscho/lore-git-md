Feature implementation for changing default branch name to "main" when built with WITH_BREAKING_CHANGES. This is the first patch in a 4-part series that follows up on the 2020 deprecation warning about changing the default branch name from "master".

The patch modifies several components to implement the change:
- Updates `repo_default_branch_name()` in refs.c to return "main" when WITH_BREAKING_CHANGES is enabled
- Removes the default branch advice when breaking changes are enabled
- Documents the change in BreakingChanges.adoc and git-init.adoc
- Adds conditional compilation blocks (ifdef/endif) around "master" references
- Updates test infrastructure to handle both branch names conditionally

Key technical details:
- Maintains backward compatibility - existing repos keep using "master"
- Only affects new repositories when built with breaking changes
- Keeps GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME for test flexibility
- Documents that the change will take effect in Git 3.0
- Leaves remote branch detection logic unchanged for compatibility with older servers

The patch handles the most critical documentation (git-init.adoc) but defers updates to other docs like user-manual.adoc due to the volume of changes needed. The implementation uses conditional compilation rather than parameterization due to technical limitations with asciidoc attribute expansion.

This represents the core implementation of the long-planned default branch name change, now gated behind the WITH_BREAKING_CHANGES flag as previously discussed in the thread. The patch appears thorough and well-tested, with clear conditional handling of both old and new behaviors.
