This is a feature proposal for improving Git's partial clone functionality. The email suggests three main changes to make blobless clones more user-friendly and practical for common workflows.

The proposal focuses on making blobless clones the default behavior via a config option, adding commands to fetch missing history (with progress reporting and resumable downloads), and providing commands to convert between full/partial clone types. The author argues that since most clones are done to work with files rather than history, defaulting to blobless clones would speed up initial cloning while still allowing users to fetch additional data when needed.

Key technical points include:
- New config option to set blobless clone as default
- New command to download missing history (blobs/trees) with progress tracking
- New command to convert between clone types (potentially deleting local data)
- References existing `--filter=blob:none` functionality and StackOverflow workarounds

The proposal appears well-motivated, addressing real performance and bandwidth concerns, though it doesn't provide implementation details. This would likely be a significant behavioral change that could impact many users, so discussion would need to cover backward compatibility, documentation updates, and potential edge cases in the conversion between clone types. The progress reporting and resumption features for fetching missing data would be particularly valuable quality-of-life improvements.
