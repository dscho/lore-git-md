This is a preparatory refactoring patch for the `git-history` command series, modifying the cache-tree infrastructure to support writing arbitrary in-memory indexes as trees.

The patch generalizes `write_in_core_index_as_tree()` to accept any `struct index_state` rather than always using the repository's index. This is a straightforward change that adds flexibility needed for upcoming history editing operations, where the command will need to work with temporary in-memory indexes during rewrites.

The implementation is clean and minimal - just adding a parameter and updating the single caller in `builtin/checkout.c`. The commit message clearly explains the motivation and that this will be used by subsequent patches in the series. This appears to be a well-contained infrastructure improvement that enables more flexible index manipulation while maintaining the existing behavior for current callers.
