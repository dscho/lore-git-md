Here's a human-readable summary of the current state of the Rust infrastructure discussion:

The Git project is moving forward with integrating Rust into the core codebase, with a clear adoption timeline now being finalized. The plan calls for optional Rust support to appear in version 2.49 (in the contrib area), core integration in 2.52, and making it mandatory by Git 3.0. This timeline has maintainer approval from Junio Hamano, though some implementation details are still being worked out.

Recent discussion has focused on properly documenting this transition, with Elijah Newren noting a few wording corrections needed in the BreakingChanges document to accurately reflect the phased rollout. There's also a proposal to separate the timeline announcement from other technical work - merging the policy decision first while letting implementation components like Windows support and varint conversion proceed in parallel under their respective maintainers.

A significant development is the confirmation that Rust will be required for SHA-1/SHA-256 interoperability in Git 3.0, though single-hash operation will remain possible without it. Brian m. carlson has been actively explaining this technical dependency and defending the Rust implementation approach.

Key contributors are now working on separate but related tracks: Newren on the build system and Windows support, carlson on documentation, and Ezekiel Newren on varint integration. While some packaging and platform support questions remain (particularly around Linux distributions and the cbindgen tool), the core decision appears settled with attention now turning to execution details and proper documentation of the transition plan.
