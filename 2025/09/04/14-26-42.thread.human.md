This RFC thread discusses the introduction of Rust infrastructure to Git core, now at version 5 with 9 patches. The series has Junio's conditional approval but is undergoing build system redesign. Patrick Steinhardt leads the effort with a varint subsystem proof-of-concept, CI modernization, and a phased transition timeline (optional in 2.52, default in 2.53, mandatory by 3.0).

Key technical considerations include SHA-1/SHA-256 interoperability requiring Rust (confirmed by brian m. carlson), Windows support challenges being addressed by Elijah Newren and Johannes Schindelin, and build system improvements for better error messaging. The latest documentation patch responds to Phillip Wood's feedback, clarifying that the BreakingChanges announcement serves as advance notice for platforms to adapt, while maintaining flexibility in the timeline if ecosystem impact proves too disruptive.

Platform compatibility remains a major concern, particularly for older architectures like m68k (where John Paul Adrian Glaubitz is actively working on alignment issues). The team has chosen Rust 2018 edition specifically for GCC-based compiler compatibility. While the 3.0 target aligns with potential GCC-Rust maturity, Patrick emphasizes the timeline could adjust based on three factors: experience maintaining optional Rust support, progress of GCC-based Rust compilers, and feedback from affected platforms.

The discussion shows the project balancing technical progress with practical ecosystem concerns. Documentation is being split for early merge while other components continue development. Multiple workstreams are now owned by different maintainers, with Junio monitoring overall progress. The thread demonstrates Git's characteristically careful approach to major changes, with extensive consideration of downstream impacts and a willingness to adapt plans based on real-world feedback.
