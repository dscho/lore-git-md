# Git Rust Infrastructure Thread Summary

This thread discusses the foundational work to introduce Rust infrastructure into Git's core, led by Patrick Steinhardt. The RFC patch series (now at version 8) proposes a comprehensive plan for Rust integration with dual build system support (meson and Makefile), CI testing, and a gradual transition timeline targeting Git 3.0.

The latest version (v8) addresses several technical concerns raised during review:
- Fixed Makefile dependency tracking and variable ordering issues
- Added varint safety enhancements with `wrapping_add()` and overflow tests
- Resolved CI configuration problems on AlmaLinux
- Clarified the 2-year LTS documentation policy

Key debates center around:
1. **Transition timeline**: Patrick proposes a phased approach (auto-detection in 2.52, default-on in 2.53, mandatory in 3.0) while Elijah Newren advocates for immediate default-on in 2.52. Junio Hamano has expressed concerns about the proposed 6-month adoption period.
2. **LTS support**: There's ongoing discussion about whether to provide C-only security fixes for a fixed period (1.5-2 years proposed by Patrick) or handle them case-by-case as suggested by Newren.
3. **Platform support**: macOS has known meson Rust module limitations, Windows support is explicitly deferred, and NonStop platform concerns remain unaddressed.

Technical implementation has progressed well, with varint subsystem conversion serving as infrastructure validation (not just a "test balloon" as initially characterized). Performance parity with C has been confirmed by multiple reviewers. The build system now properly reports Rust status and handles dependencies, though some Makefile error handling improvements remain outstanding.

Notable participants include:
- Patrick Steinhardt (author) driving the technical implementation and policy proposals
- Junio Hamano providing maintainer perspective on timeline and safety
- Elijah Newren advocating for more aggressive adoption
- Various contributors (SZEDER Gábor, Ben Knoble) improving technical details

The thread shows consensus forming around core infrastructure but ongoing debate about adoption strategy. SHA-256 interoperability has emerged as a key dependency for Git 3.0 readiness. The discussion remains productive with each iteration addressing reviewer feedback while maintaining the vision for gradual Rust adoption.
