This RFC patch series, now at version 4, proposes making Rust infrastructure mandatory in Git core by version 3.0. Patrick Steinhardt has led the implementation, which has progressed through build system integration (meson and Makefile), type safety improvements in the varint subsystem, and CI testing infrastructure. The series has received broad technical approval, with Brian m. carlson recently confirming compatibility with the parallel SHA-256 interoperability work.

The latest exchange focuses on final build system polish - specifically ensuring proper cleanup of Rust artifacts like `Cargo.lock`. Both SZEDER Gábor and Junio C Hamano noted this minor oversight, which Steinhardt has acknowledged will be fixed. This represents the last remaining housekeeping item for the build system work, which otherwise includes complete integration with reporting through `git version --build-options` and comprehensive CI testing.

Key open questions center around Windows platform support, Rust/C type alignment decisions, and the practicalities of the proposed LTS maintenance model - the latter requiring broader discussion with the security team. The technical implementation appears sound, with only platform-specific work remaining before this foundational change to Git's architecture can be finalized.
