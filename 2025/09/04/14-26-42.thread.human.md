This RFC thread continues to explore the implications of introducing Rust infrastructure into Git core, now at version 5 with 9 patches. The series has Junio Hamano's ack and focuses on a phased transition plan (optional in 2.52, default in 2.53, mandatory by 3.0) with significant work on build system redesign, Windows support, and platform compatibility.

The latest discussion centers on maintenance strategy for Rust-free LTS releases after Rust becomes mandatory. Junio Hamano has weighed in against maintaining these LTS versions in the canonical repository, proposing instead that community-supported LTS releases should have their own official site with clear pointers from the main project. He emphasizes the need for coordinated security disclosures and inclusion of LTS maintainers in git-security@ for embargoed fixes. Patrick Steinhardt had advocated keeping LTS in the main repository to avoid fragmentation, but Junio's position reflects a preference for clearer separation.

Technical progress continues on multiple fronts: build system UX refinements (addressing Phillip Wood's feedback), Windows support work led by Ezekiel Newren and Johannes Schindelin, and m68k alignment fixes by John Paul Adrian Glaubitz. The Rust 2018 edition remains the target for GCC-based implementation. Open questions persist around final build system architecture, dependency management, and niche platform support timelines, with the mandatory transition date remaining flexible based on ecosystem readiness.
