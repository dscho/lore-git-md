This RFC patch series, now at version 5, proposes integrating Rust infrastructure into Git core, with Patrick Steinhardt leading the effort and Junio C Hamano providing oversight. The plan outlines a phased transition: optional Rust support in Git 2.52, enabled by default in 2.53, and mandatory by Git 3.0. Key technical work includes build system redesign (with Ezekiel Newren developing a `build_rust.sh` wrapper), Windows support improvements (with Johannes Schindelin), and platform-specific fixes like John Paul Adrian Glaubitz's work on m68k alignment issues.

A recent discussion has surfaced regarding how Rust integration affects SHA-1/SHA-256 interoperability. Brian m. carlson clarified that while single-hash operation will remain possible without Rust, converting between hash algorithms (via `extensions.compatObjectFormat`) will require Rust and fail gracefully if unavailable. SZEDER Gábor expressed concerns about this limitation, particularly the "flag day" scenario where repositories become temporarily unusable during transition without Rust support. Brian maintains this is a reasonable tradeoff, while SZEDER suggests more prominent documentation of these limitations.

The thread continues to debate several open questions, including final build system architecture, Windows platform specifics, and LTS maintenance strategy - with Junio proposing separate hosting for Rust-free releases while Patrick advocates for integration. Documentation refinements from Phillip Wood have improved build system messaging, particularly around transition-period UX. The timeline remains flexible based on ecosystem readiness, with Rust 2018 edition compatibility and GCC-based Rust compiler progress being key factors.
