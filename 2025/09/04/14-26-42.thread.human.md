This RFC series proposes introducing Rust infrastructure to Git's core, with Patrick Steinhardt leading the initial effort and Ezekiel Newren now taking ownership of build system revisions and Windows support. The current v5 series has maintainer approval from Junio Hamano but is undergoing significant redesign, particularly around build system architecture (transitioning from Meson-first to a hybrid model) and platform support.

The discussion has expanded to include multiple dimensions of the transition. Technical concerns raised include Windows compatibility, CI coverage, header generation strategies, and how to map Git's C components to Rust's crate model. Newren has clarified that the Rust toolchain can use system packages rather than requiring rustup, addressing some packaging concerns raised by Ramsay Jones regarding Linux distributions.

Sam James (Gentoo) has joined the conversation, highlighting additional distribution maintainer concerns about dependency management - particularly around licensing complexity and offline build requirements for external crates. This adds to the growing list of implementation constraints that must be resolved while maintaining the proposed transition timeline (optional in 2.52, default in 2.53, mandatory by 3.0).

The varint subsystem remains as a validated proof-of-concept for Rust/C interop, while the broader architectural questions continue to be worked through. The discussion shows the project carefully considering all aspects of this major change, with different contributors focusing on their areas of expertise - Steinhardt on overall direction, Newren on build systems, and now distribution maintainers on packaging implications.
