This RFC thread proposes introducing Rust infrastructure to Git core, with Patrick Steinhardt leading the effort through an 8-part patch set. The series has progressed from initial build system preparation to now including the first concrete Rust implementation - a varint encoding/decoding subsystem conversion that demonstrates FFI compatibility, memory safety, and build integration while maintaining the C API.

The latest addition is a documentation patch that formalizes the transition timeline, proposing Rust as optional in Git 2.52 (with `WITH_RUST=YesPlease` build flag) and making it mandatory by Git 3.0 in the second half of next year. The plan includes four clear milestones and designates the final pre-3.0 release as a long-term support version to ease adoption for distributors. While this represents a significant commitment to Rust adoption, the series maintains its incremental approach - the varint conversion serves as a controlled proof point before tackling more complex subsystems.

All previously noted platform concerns (particularly around NonStop compatibility) remain unaddressed in this update. The thread shows steady technical progress but has yet to resolve the broader policy questions about mandatory Rust requirements across all supported platforms. The transition plan's publication suggests the project is moving toward formalizing Rust as part of Git's future, with the technical foundation now sufficiently demonstrated through the varint implementation.
