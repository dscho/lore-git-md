This RFC thread proposes introducing Rust infrastructure to Git core, with the goal of making Rust mandatory by Git 3.0. Patrick Steinhardt leads the effort, now at version 5 of the 9-patch series. The work has progressed through several technical phases: build system support (Meson and Makefile integration), type safety improvements, and documentation updates.

The latest patch focuses on the varint subsystem, converting it to use explicit integer widths (uint64_t for values, uint8_t for lengths) to ensure platform independence and prepare for Rust reimplementation. This clean, mechanical change follows Ezekiel Newren's suggestion and has Junio's technical approval, though he noted the uint8_t length isn't strictly necessary. The change affects four files while maintaining existing behavior.

Key participants have weighed in: Brian m. carlson verified compatibility with their SHA-256 work and offered potential follow-up contributions, while Junio continues providing maintainer guidance - particularly on documentation phrasing like the "test balloon" terminology. The build system work is now complete after v5's final additions, and the technical approach has broad approval.

Remaining questions center on Windows platform support (pending Ezekiel's work), finalizing documentation language, and practical details of the LTS maintenance model. The series appears technically sound and is stabilizing, with focus now to platform-specific concerns and documentation polish rather than core implementation issues.
