This RFC patch series proposes introducing Rust infrastructure to Git core, with Patrick Steinhardt as the primary author. The discussion has evolved through seven versions covering build system integration, transition documentation, and CI testing. The latest patch (7/7) enables Rust compilation in CI's breaking-changes test jobs, which brian m. carlson previously reviewed positively.

Key debates center on transition timing and platform support. Phillip Wood advocates for a 6-month adoption period and default-enabled Rust compilation, while Patrick prefers version-tied transition (potentially aligned with Git 3.0). The LTS policy discussion has produced competing proposals - Phillip and Eli Schwartz favor a fixed 2-3 year support window for non-Rust platforms, while Patrick suggests gcc-rs-dependent support. Technical reviews have been largely positive, with brian m. carlson approving Rust status reporting in `git --version` while identifying a minor Makefile issue.

Junio Hamano has now weighed in on the CI patch, noting potential interactions with other Git 3.0 changes and requesting coordination. This maintains the thread's focus on whether Rust adoption should be tied to the major version bump. Outstanding questions include NonStop platform support (Randall Becker's input pending) and macOS test guard rationale (Justin Tobler's inquiry). The technical implementation appears sound, but policy decisions around timeline and LTS strategy await maintainer guidance.
