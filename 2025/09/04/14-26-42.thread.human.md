This RFC thread continues to explore the introduction of Rust infrastructure to Git core, with Patrick Steinhardt leading the effort. The discussion has progressed through four versions, focusing on build system integration (meson initially, with Makefile support planned) and the implications of making Rust a mandatory dependency starting with Git 3.0.

The latest development is Patrick's response to Eric Sunshine's concern about the current silent fallback to C when Rust is unavailable. Patrick proposes a three-phase transition: first auto-detecting Rust in meson (current state), then making it opt-out rather than opt-in, and finally removing the toggle entirely for Git 3.0. This phased approach aims to make the Rust requirement more visible to packagers while allowing time for ecosystem adaptation.

Key technical details remain centered around meson integration, particularly how to handle Cargo.toml dependencies without experimental features. The implementation currently includes a small test case (varint.c rewritten in Rust) with C ABI compatibility.

Several significant questions remain unresolved, including build system divergence (meson vs Cargo), platform support for NonStop and embedded systems (where Randall Becker's input is still expected), and the overall timeline for mandatory adoption. The discussion remains technical and constructive, with Patrick demonstrating responsiveness to feedback while maintaining the RFC's experimental status. The thread represents an important architectural decision point for Git's future, balancing technical modernization with broad platform compatibility.
