This RFC thread proposes introducing Rust infrastructure to Git core, now in its sixth iteration with all nine patches complete. Patrick Steinhardt leads the effort, demonstrating mixed C/Rust compilation through a varint subsystem replacement while modernizing CI and the build system. The series outlines a phased transition: optional Rust in Git 2.52, default in 2.53, and mandatory by 3.0.

Key technical components include Meson build support, Makefile refactoring, varint implementation with overflow protection, and documentation of the breaking changes policy. Recent discussions have focused on governance, particularly around long-term support (LTS) management. Steinhardt and Hamano have now aligned on keeping LTS handover mechanics flexible, removing specific backporting procedures from the policy document to be decided when needed. This resolves a remaining governance question while preserving the transition timeline.

Windows/MSVC build concerns were addressed by Ezekiel Newren, confirming library naming conventions and approving a crate rename to avoid collisions. The series has complete CI validation with remaining technical gaps being actively resolved. While Steinhardt has expressed conditional willingness to serve as LTS maintainer, concrete decisions on that role will be deferred until closer to need. The thread shows steady progress toward consensus on both technical implementation and project governance for this significant architectural change.
