This RFC thread explores introducing Rust infrastructure to Git core, now in its sixth iteration with 9 patches. Patrick Steinhardt leads the effort, which has Junio Hamano's conditional approval. The series establishes build system support (both Makefile and Meson) for optional Rust compilation, with a phased rollout plan: optional in 2.52, default in 2.53, and mandatory by 3.0 (with some timeline flexibility). The latest patch (6/9) marks a significant milestone by introducing the first concrete Rust component - a reimplementation of Git's varint subsystem.

The varint implementation serves as a test case, replacing `varint.c` with Rust code that maintains identical functionality while adding compile-time safety checks. It follows preparatory work standardizing integer types across the codebase. The patch includes comprehensive unit tests and integrates cleanly with both build systems. This demonstrates the technical viability of mixed C/Rust compilation while keeping the change isolated and low-risk.

Ongoing discussions balance technical implementation with governance concerns. Key technical questions remain around Windows support, niche platform compatibility, and CI tooling gaps. The governance debate focuses on long-term maintenance models, particularly how LTS branches will be managed and what criteria should trigger the Rust mandate. Participants like Johannes Schindelin advocate for a lieutenant model, while Junio Hamano prefers keeping Rust development in a separate repository.

The thread has evolved to address real-world adoption concerns, with added assessments of downstream impact and assurances about tag maintenance continuity. While the varint work proves the technical approach, open questions remain about how broadly Rust will be adopted across Git's codebase and what organizational structures will support this transition.
