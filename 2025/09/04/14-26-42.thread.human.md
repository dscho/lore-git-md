This RFC thread proposes introducing Rust infrastructure to Git's core, starting with build system support and converting varint.c as a proof of concept. Patrick Steinhardt leads the effort with a 3-patch series that would make Rust a mandatory build requirement for Git 3.0 (targeting late 2026). The first two patches add meson build support for Rust and rewrite varint.c in Rust while maintaining C ABI compatibility. The newest patch formally documents this breaking change in BreakingChanges.adoc, announcing that Git 3.0 will require Rust while offering Git 2.52 as an LTS release for platforms needing more time to adapt.

Key technical aspects include maintaining parallel C/Rust implementations during transition, comprehensive test coverage, and using meson build flags to control Rust usage. The proposal acknowledges platform concerns (particularly Randall Becker's NonStop port) while setting an 18-month timeline for ecosystem adaptation. Open questions remain about build system fragmentation (meson vs Makefile), the mandatory nature of the change, and how more complex subsystems might be integrated. The thread awaits feedback from both Rust advocates like Ezekiel Newren and platform maintainers with compatibility concerns.
