This RFC patch series introduces Rust infrastructure to Git core, now at version 8 with all 9 patches complete. Authored by Patrick Steinhardt, the series demonstrates mixed C/Rust compilation viability through a varint subsystem replacement, with a phased transition plan (optional in Git 2.52, default in 2.53, mandatory by 3.0 in H2 2026). The latest addition provides build status reporting in `git version --build-options` and `git bugreport`.

The most recent patch refactors the varint subsystem to use explicit-width integer types (`uint64_t` for values, `uint8_t` for lengths) instead of platform-dependent types. This change, touching `varint.[ch]`, `dir.c`, and `read-cache.c`, ensures consistent behavior across platforms and simplifies the upcoming Rust interface. While maintaining identical functionality, it clarifies theoretical limits (16-byte varint maximum) and updates all call sites.

Junio Hamano has signaled readiness to merge the varint implementation, and Ezekiel Newren has confirmed his pending Rust work depends on this series. Technical concerns around Windows/MSVC and Cygwin builds have been addressed, with Ramsay Jones verifying Cygwin support. The series now includes comprehensive CI validation and build status reporting, completing the Rust infrastructure foundation.

Open discussions remain about compilation speed impacts and broader language choice debates, though these aren't blocking implementation. The series stands ready for inclusion, having addressed both technical requirements and community process considerations through its eight iterations.
