This RFC thread continues to explore the complex transition to making Rust a mandatory part of Git's build system, now in its 10th iteration. Patrick Steinhardt's series has evolved to include comprehensive build system coverage, CI testing, and transition documentation, but faces growing scrutiny from multiple angles.

The technical debate has expanded to include type safety concerns (Ezekiel Newren and brian m. carlson), build system conflicts (carlson with concrete test linking failures), arithmetic behavior at the FFI boundary (Ben Knoble), and now rollout strategy (Newren and Phillip Wood). Wood's recent contribution reinforces Newren's earlier argument against the gradual approach, warning that optional early adoption won't generate enough real-world testing before the mandatory switch. He suggests aligning this with other potential breaking changes for Git 3.0, including config defaults for commit and merge behaviors.

Key concerns remain unresolved: how to handle type conversions safely across platforms, whether the Meson/Cargo workflow conflicts can be resolved, and how to ensure sufficient testing before the mandatory transition. The discussion has also revealed process concerns from Newren about how Rust-related work from new contributors is being integrated. While the technical implementation has progressed through multiple versions, these architectural and social questions continue to shape the path forward.
