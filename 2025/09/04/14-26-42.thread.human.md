This RFC thread explores introducing Rust infrastructure to Git, starting with build system support and converting varint.c as a proof of concept. Patrick Steinhardt's initial proposal uses meson for Rust compilation, but faces pushback over version requirements conflicting with Git's platform support policy. The discussion has since expanded into two competing approaches - meson versus Cargo - with Ezekiel Newren advocating for Cargo's crate handling and IDE support, while Eli Schwartz (a Gentoo maintainer) counters with meson's packaging advantages and test reliability.

Key technical concerns center around build system compatibility, with Schwartz offering a potential solution to lower meson version requirements. The mandatory Rust adoption timeline for Git 3.0 remains contentious, particularly regarding platforms like NonStop that lack Rust support. Junio Hamano has validated the build system compatibility concerns as legitimate, elevating this to a potential blocking issue. Meanwhile, Eric Sunshine argues the current silent fallback to C won't properly surface platform issues, suggesting an enabled-by-default with opt-out approach instead.

The thread now reached a critical juncture with two viable technical paths (meson vs Cargo) on the table, each with distinct tradeoffs. Schwartz's latest contribution provides concrete solutions to some meson concerns while introducing new considerations about test reliability. As a distro maintainer, his perspective carries weight in the packaging workflow discussion. However, fundamental questions about platform support and the mandatory adoption timeline remain unresolved as the implementation alternatives multiply.
