This RFC thread, initiated by Patrick Steinhardt, proposes making Rust infrastructure mandatory in Git core by version 3.0. The series has evolved through four versions, with the latest (v4) completing the technical groundwork: build system integration (via meson and Makefile), type safety measures in the varint subsystem, and comprehensive CI testing. Key contributors have weighed in - Brian m. carlson on type safety, Phillip Wood on rollout strategy, and Ezekiel Newren on platform compatibility.

Junio C Hamano, while accepting the technical approach, has now turned attention to the policy implications in the BreakingChanges documentation patch. He questions the framing of Rust features and the "test balloon" terminology given the mandatory transition, and raises practical concerns about the proposed LTS maintenance handoff process. His feedback suggests the documentation should more clearly reflect that Rust will become a hard requirement, while acknowledging the challenges of coordinating with distributors on long-term support.

The series appears technically complete, with open questions now centering on project policy rather than implementation. The discussion has shifted to how to communicate this transition to the broader ecosystem, particularly regarding maintenance expectations and distributor coordination. Junio's latest input indicates the documentation will need refinement before final merge, but doesn't signal any blocking concerns about the technical work itself.
