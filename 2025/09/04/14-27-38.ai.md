This patch introduces management subcommands (`abort`, `continue`, `quit`) for the proposed `git-history` command, building on the sequencer infrastructure changes from earlier in the series. The subcommands mirror similar functionality in `git rebase` for handling interrupted operations, though they currently just fail when no edit is in progress (as the actual history editing commands aren't implemented yet).

Key technical details:
- Adds three subcommand implementations in builtin/history.c:
  - `abort`: Uses `sequencer_rollback()` with new `REPLAY_HISTORY_EDIT` mode
  - `continue`: Uses `sequencer_continue()` with same mode
  - `quit`: Combines `sequencer_remove_state()` and `remove_branch_state()`
- All subcommands use the new `REPLAY_HISTORY_EDIT` action flag introduced in earlier patches
- Includes basic tests verifying:
  - Argument handling
  - Error messages when no edit is active
  - `quit` succeeds silently when no edit is active
- Updates documentation stub to describe the new subcommands

The patch is straightforward plumbing work that follows established patterns from the rebase implementation, though its utility won't be fully realized until the actual history editing commands are added. The test coverage is minimal but appropriate for this scaffolding stage.
