This is a refactoring patch in Patrick Steinhardt's `git-history` series, adding support for in-memory index patching to the interactive add-patch subsystem. 

The patch introduces a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always using the repository's main index. This is a preparatory change that will be used by subsequent patches in the series. The implementation carefully maintains all existing behavior while adding the new capability, with 110 lines of new code across `add-patch.c` and its header.

The changes are mechanical but important for the series' goal of building robust history editing operations. The patch follows the established pattern of the series by extending existing infrastructure rather than rewriting it. While the immediate use case isn't shown here (it's promised for a later commit), the change is clearly motivated and well-contained.
