Refactoring patch adding tree-based status collection to support the git-history command series.

This patch introduces a new function `wt_status_collect_changes_trees()` that extends the working tree status subsystem to compare and format changes between two arbitrary trees, rather than between the working tree/index and HEAD. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic that will be needed for the upcoming git-history command's tree manipulation operations.

The implementation reuses the existing `wt_status_collect_updated_cb` callback and diff machinery, configuring a diff between the provided tree OIDs with the same rename detection and formatting options as regular working tree status. The function signature follows the pattern of existing wt-status collectors, taking a `wt_status` struct to store results.

This is a preparatory change for the git-history series, building infrastructure needed to display changes when manipulating commit history. The patch maintains clean separation from existing working tree status functionality while leveraging its formatting capabilities. As noted in the commit message, this will be used in a follow-up patch, suggesting it's part of enabling one of the history editing subcommands (likely `reorder` or `split` given the tree comparison focus).

The change is mechanical and well-contained, adding 24 lines to wt-status.c and 3 to the header. It follows the series' pattern of careful infrastructure preparation before implementing user-facing features.
