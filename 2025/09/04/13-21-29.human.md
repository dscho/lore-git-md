Feature patch implementing the long-planned switch from "master" to "main" as Git's default branch name when built with WITH_BREAKING_CHANGES enabled. This is the first of a 4-patch series that follows through on the deprecation warning introduced in 2020.

The patch makes several key changes:
- Updates the default branch name to "main" when WITH_BREAKING_CHANGES is set
- Modifies the advice system to remove the default branch warning when breaking changes are enabled
- Updates documentation in BreakingChanges.adoc and git-init.adoc to reflect the change
- Maintains backward compatibility for older servers that may still use "master"
- Adds tests to verify behavior with and without the breaking changes flag

The implementation is clean and well-documented, with clear attention to backward compatibility. The patch leaves some documentation (like user-manual.adoc) unchanged for now, noting that updating those would be too cumbersome with the current ifdef approach. This seems reasonable given they can be updated in the 3.0 release cycle.

This represents a significant but carefully managed change that aligns Git with current industry practice while maintaining flexibility for users who need to work with older systems.
