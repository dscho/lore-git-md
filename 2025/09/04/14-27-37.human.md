This is a feature patch introducing the scaffolding for a new `git history` command, part of Patrick Steinhardt's RFC series for flexible history editing operations. The patch establishes the basic command structure but does not yet implement any functionality - it's essentially a placeholder that will be built upon in subsequent patches.

The new command aims to provide a more straightforward interface for common history rewriting operations like reordering, splitting, dropping, and squashing commits, which currently require interactive rebase or multiple steps. The documentation notes this is experimental and doesn't yet support merge commits, directing users to `git rebase --rebase-merges` for those cases.

The patch adds all the boilerplate needed for a new Git command:
- Documentation stub in git-history.adoc
- Build system integration (Makefile, meson.build)
- Command registration (builtin.h, command-list.txt, git.c)
- Basic implementation file with option parsing
- Initial test file with one failing test case

The implementation is minimal at this stage - the command will fail when run since no subcommands are yet implemented. This appears to be a clean, well-structured foundation for the history editing functionality that will follow in later patches of the series. The documentation clearly marks this as experimental, setting appropriate expectations for users.
