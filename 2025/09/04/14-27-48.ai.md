This is a feature implementation patch adding the `reword` subcommand to the proposed `git-history` command, part of Patrick Steinhardt's ongoing RFC series (now at 31 patches in v3). The subcommand allows rewriting commit messages while preserving all other commit metadata, similar to interactive rebase's "reword" action.

The implementation handles edge cases including:
- Rejecting merge commits and dirty working trees
- Supporting root commits and middle-of-chain rewording
- Preserving original authorship and commit relationships
- Proper hook execution (prepare-commit-msg, post-commit, post-rewrite)
- Empty message detection
- Comprehensive test coverage (202 lines across 7 scenarios)

Key technical details:
- Uses existing sequencer` infrastructure including the new post-rewrite hook mapping support from earlier patches
- Implements commit message editing workflow matching Git's standard (editor invocation, message validation)
- Reuses the series' shared commit collection/replacement logic
- Adds documentation and test scaffolding
- Follows the established pattern of other subcommands in the series

The patch appears well-integrated with the larger series' infrastructure and maintains consistent quality with thorough test coverage. It completes the core set of history editing operations alongside previously implemented `drop`, `reorder`, and `split` subcommands.
