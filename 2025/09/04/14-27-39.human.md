Feature implementation for the proposed `git-history` command. This patch adds the `drop` subcommand to Patrick Steinhardt's RFC series, which provides a simpler way to remove commits from history compared to interactive rebase. The command handles both regular commits and root commits (with special logic for the latter), while preserving commit ordering and executing hooks properly.

The implementation builds on Git's sequencer infrastructure and includes thorough test coverage of edge cases: merge commits, empty history prevention, worktree changes, root commit handling, and conflict resolution. The command syntax is straightforward (`git history drop <commit>`) and the documentation provides clear examples of its use.

This is patch 9/18 in the v3 RFC series, which continues to expand the capabilities of the proposed `git-history` command. The implementation appears robust, with careful attention to error handling and edge cases. The tests suggest the author has considered real-world usage scenarios, including conflict resolution workflows.
