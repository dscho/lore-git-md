This is a refactoring patch series that's part of the ongoing pluggable object database effort. The main goal is to move commit graph tracking from the object database level (`struct object_database`) to the object source level (`struct odb_source`), since commit graphs are inherently tied to individual object sources rather than the database as a whole.

The series consists of 6 patches that systematically refactor commit graph handling:
1. Removes redundant commit graph checks in blame and revision code
2. Modifies `prepare_commit_graph()` and `repo_find_commit_pos_in_graph()` to return the graph directly
3. Changes graph merging to pass graphs explicitly as parameters
4. Finally moves the commit graph storage from `object_database` to `odb_source`

The changes touch core commit graph handling code across multiple files (commit-graph.[ch], odb.[ch], packfile.c) and clean up some related code in blame.c and revision.c. The patch notes a trivial conflict with another topic branch (tc/last-modified) that's easily resolved.

This appears to be a well-structured preparatory series for the pluggable ODB work, with each patch making logical, incremental changes. The commit messages explain the rationale clearly - commit graphs belong at the source level since different backends may store commit information differently. The changes are focused and the diffstat shows a net reduction in code (-105/+118 lines).
