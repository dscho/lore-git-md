Refactoring patch for pluggable ODB work, part 4/6 in Patrick Steinhardt's series. This changes `repo_find_commit_pos_in_graph()` to return the commit graph pointer rather than just a success/failure boolean, in preparation for moving commit graph storage from `object_database` to `odb_source`.

The function currently assumes callers can access the graph via `r->objects->commit_graph`, but this won't hold when graphs move to object sources. The patch updates the function signature and all callers (in bloom.c, commit-graph.c) to handle the returned graph pointer directly. The changes are mechanical but important for the series' goal of proper multi-backend commit graph handling.

The patch maintains all existing functionality while making the plumbing more flexible for the upcoming structural changes. Like previous patches in the series, it demonstrates careful, behavior-preserving refactoring with clear commit message explanation of both the current state and future needs.
