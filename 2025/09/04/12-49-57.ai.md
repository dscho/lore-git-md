This is the third patch in Patrick Steinhardt's 6-part series refactoring commit graph handling for the pluggable ODB effort. The patch modifies `prepare_commit_graph()` to return the prepared commit graph pointer directly, rather than just indicating success/failure via an integer return value.

The key change is converting `prepare_commit_graph()` from returning `int` to returning `struct commit_graph *`, which allows callers to directly use the returned graph rather than accessing it through `r->objects->commit_graph`. This prepares for the upcoming move of commit graph storage from `object_database` to `odb_source` by centralizing graph access through this function. The patch updates all 8 callers to use the new return value pattern.

The diff shows careful mechanical conversion of each caller to:
1. Store the graph pointer from `prepare_commit_graph()`
2. Check for NULL before proceeding
3. Use the local pointer rather than `r->objects->commit_graph`

Notable changes include:
- Simplifying control flow in functions like `generation_numbers_enabled()` by combining NULL checks
- Converting while loops to for loops when walking commit graph chains
- Maintaining all existing error handling and edge cases

This is a well-executed preparatory change that maintains identical behavior while making the codebase ready for the deeper structural changes coming in later patches. The conversion is thorough and handles all call sites consistently.
