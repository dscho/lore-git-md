This is a refactoring patch in Patrick Steinhardt's `git-history` RFC series (v3 14/18), focusing on the add-patch subsystem. It introduces support for applying patches to an in-memory index rather than just the repository's main index.

The patch adds a new `run_add_p_index()` function that parallels the existing run_add_p() but accepts an explicit `index_state` and `index_file` parameter. This allows callers to specify which index to modify, rather than always using `r->index`. The implementation shares most logic with the existing function but makes key adjustments:
- Stores the provided index in the `add_p_state` struct
- Uses `read_index_from()` instead of `repo_read_index()` when refreshing
- Only calls `repo_refresh_and_write_index()` when operating on the main index
- Maintains identical user-facing behavior (prompts, help text) to the existing function

The changes are mechanical and focused - mostly plumbing the index parameter through existing code paths. The patch notes this will be used in a future commit, suggesting it's preparatory work for more advanced history editing operations that may need to manipulate temporary indexes.

This continues the series' pattern of careful subsystem refactoring to support the new history editing commands. The change is well-contained (68 lines net) and maintains existing behavior while expanding functionality. It follows the series' ongoing work to separate concerns in the interactive add/patch code.
