This is a feature proposal for changing Git's clone behavior and adding repository conversion commands. Дилян Палаузов suggests making blobless clones the default to optimize for the common case where users clone primarily to build/change code rather than inspect history. The proposal includes three main components:

First, adding a config option to make `git clone` perform blobless clones by default, which would speed up initial clones and reduce bandwidth. The author argues this better matches typical workflows where users need file contents more than full history.

Second, introducing a new command to download missing history (blobs or trees) for partial clones, with progress reporting and resumable downloads. This would help users who later need the full history after an initial partial clone.

Third, adding commands to convert between full, blobless, and treeless clones, allowing users to optimize disk space usage after cloning. The author notes they're unaware if such commands already exist.

The rationale focuses on performance benefits for source code workflows, suggesting the current default full clones download unnecessary data. The proposal acknowledges trade-offs between clone types but argues the defaults should favor the more common build/edit use case over history inspection. No implementation details or patches are provided - this appears to be an RFC-style exploration of the idea.
