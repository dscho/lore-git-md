This is a feature patch implementing the `drop` subcommand for the proposed `git-history` command, part of Patrick Steinhardt's RFC v3 series (patch 9/18). The subcommand provides a simpler way to drop commits compared to interactive rebase, handling edge cases like root commits.

The implementation:
- Takes a single commit argument to drop
- Verifies the commit is reachable and not a merge
- Handles special cases (dropping HEAD, root commits)
- Uses sequencer` infrastructure with new `REPLAY_HISTORY_EDIT` mode
- Preserves commit order and executes hooks
- Includes comprehensive tests covering:
  - Merge commit rejection
  - Empty history prevention
  - Dirty worktree detection
  - Tip/middle/root commit dropping
  - Hook execution
  - Conflict handling

Key technical details:
- Uses `collect_commits()` to verify and gather commits to replay
- `apply_commits()` handles the actual rebase operation
- Special root commit handling via empty tree commit
- Integrates with existing sequencer conflict resolution
- Respects `commit.verbose` config
- Test file `t3451-history-drop.sh` verifies all major functionality

The patch appears well-structured with thorough documentation and test coverage. It builds on previous infrastructure work in the series (sequencer changes, hook execution) while introducing the first actual history-editing operation. The implementation mirrors rebase behavior where appropriate while adding specific handling for the drop use case.
