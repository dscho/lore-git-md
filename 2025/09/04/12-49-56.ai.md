This is the second patch in Patrick Steinhardt's 6-part refactoring series to move commit graph handling from object_database to odb_source. The patch removes a redundant commit graph existence check in `check_maybe_different_in_bloom_filter()` in revision.c, where the code was verifying `revs->repo->objects->commit_graph` before checking generation numbers. The commit message explains this check is unnecessary because the subsequent generation number check (which looks at the commit graph data slab) would already catch cases where no commit graph exists, and the performance impact of the redundant check is negligible since the slab lookup would be constant-time when unpopulated.

The change is a straightforward 3-line deletion that doesn't affect behavior, continuing the series' theme of cleaning up commit graph access patterns in preparation for the odb_source transition. The patch touches core revision walking code but is limited to bloom filter path filtering logic. Like the first patch, this appears to be a well-justified, mechanical change that removes unnecessary code while maintaining the same functionality. The series continues to demonstrate careful attention to incremental, behavior-preserving refactoring.
