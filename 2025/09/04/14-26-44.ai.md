Rust infrastructure proof-of-concept: varint.c rewrite. This is the second patch in Patrick Steinhardt's RFC series introducing Rust to Git core, focusing on a concrete implementation after the initial build system support in patch 1.

The patch replaces Git's varint.c implementation (92 lines) with a Rust equivalent (varint.rs) that maintains identical C ABI compatibility through `#[no_mangle]` extern functions. The subsystem was chosen for its isolation - it has no dependencies on other Git components, making it a safe test case. The build system now conditionally compiles either the C or Rust version based on Rust availability.

Key technical details:
- Exports two C-compatible functions: `decode_varint` and `encode_varint`
- Includes comprehensive test cases validating edge cases (0, 127, 128, 255) and overflow handling
- Maintains pointer-based C interface while using Rust's safety features internally
- Build system toggle ensures backward compatibility when Rust is disabled

The implementation appears thorough, with careful attention to maintaining the existing behavior while leveraging Rust's type system. The test coverage is solid, though reviewers may want to verify the overflow handling matches Git's existing behavior exactly. This serves as a concrete example of how Rust integration would work for isolated subsystems, though the larger questions about mandatory adoption and platform support (raised in the cover letter) remain unresolved.
