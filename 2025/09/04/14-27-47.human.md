Feature implementation for the `git-history` command, adding a new `split` subcommand to simplify splitting commits. This is part of Patrick Steinhardt's ongoing RFC series (now at v3) introducing Jujutsu-inspired history editing operations to Git.

The `split` subcommand provides an interactive way to break a single commit into two commits by selecting which changes should move to a new parent commit. This replaces the manual 7-step rebase process with a single command that handles the workflow automatically. The implementation builds on Git's existing sequencer infrastructure and interactive add-patch functionality.

Key aspects:
- Presents changes from the target commit interactively (like `git add -p`)
- Creates a new commit with selected changes, then rewrites the original commit on top
- Preserves authorship and allows custom commit messages
- Handles edge cases (empty commits, merge commits, dirty worktree)
- Includes comprehensive tests covering various scenarios (root commits, path limiting, hook execution)
