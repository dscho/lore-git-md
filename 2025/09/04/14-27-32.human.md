This is a preparatory patch for the `git-history` command series, adding sequencer infrastructure to support rewinding HEAD after non-rebase operations. Currently, the sequencer only rewinds HEAD after rebases, not after cherry-picks or similar operations. The patch introduces a new `restore_head_target` option that will be used by the upcoming `git-history` command to return HEAD to its original branch after history editing operations.

The implementation adds the new option to `struct replay_opts`, persists it in the sequencer state file, and handles the actual HEAD resetting at the end of operations. The change is cleanly integrated with existing sequencer infrastructure, including proper reflog messages. This appears to be a well-considered infrastructure change that will enable the planned history editing functionality while maintaining Git's existing behavior for other operations.

The patch is part of a larger RFC series (now 19 patches) proposing a new `git-history` command inspired by Jujutsu (jj). This particular change demonstrates attention to detail in preparing the sequencer for the new functionality while avoiding unnecessary coupling with rebase-specific behavior. The series is still in discussion, with some open questions about scope and implementation details, but this infrastructure piece seems uncontroversial and useful on its own.
