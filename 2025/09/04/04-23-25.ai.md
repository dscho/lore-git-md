Junio C Hamano raises a technical concern about the protocol v2 ACK deduplication patch, questioning whether the new implementation properly handles commit parent marking in all cases. The core issue revolves around the interaction between the `THEY_HAVE` flag setting and parent commit processing when duplicate objects are encountered.

The maintainer's analysis suggests the patch might break an edge case where a commit's parents wouldn't get marked with `THEY_HAVE` if the commit itself was already marked. In the original code, even when seeing a duplicate commit, its parents would still be processed, while the new version would skip this entirely for already-seen objects. This could affect protocol behavior when clients send commits in non-chronological order.

The discussion focuses specifically on upload-pack.c's `do_got_oid()` function, where the flag checking was moved before the commit-specific logic. Junio's example walks through the sequence of operations when processing commit A (with parent B) to illustrate the potential behavioral difference. The concern remains unresolved in this email, suggesting the patch may need revision to maintain all existing protocol semantics while achieving the deduplication goals.
