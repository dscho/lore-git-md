This is the second patch in Patrick Steinhardt's RFC series introducing Rust infrastructure to Git core, focusing on a proof-of-concept implementation by converting the varint subsystem from C to Rust.

The patch replaces `varint.c` (92 lines) with an equivalent Rust implementation in `varint.rs`, maintaining the same C-compatible interface through `extern "C"` functions. The varint subsystem was chosen as it's self-contained component without dependencies, making it a safe first target for Rust conversion. When Rust support is enabled in the build (currently meson-only), Git will compile and use the new Rust version instead of the C original.

The implementation includes thorough test coverage, with Rust-native unit tests verifying both encoding and decoding behavior matches expectations. The patch maintains backward compatibility by keeping the C version as a compile-time fallback when Rust isn't available.

As part of the broader RFC, this serves as a concrete example of how Rust integration would work, though several open questions remain about the mandatory Rust requirement's impact on platforms without Rust toolchains and the meson/Makefile build system fragmentation. The implementation appears clean and well-tested, though the larger policy questions around mandatory Rust adoption will likely dominate discussion.
