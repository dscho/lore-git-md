This is a bugfix for the upload-pack protocol v2 ACK deduplication issue. Patrick Steinhardt acknowledges Junio C Hamano's concern about the previous patch's regression where parent commits of already-seen commits weren't properly marked with THEY_HAVE flags. The new version moves the duplicate check after commit parent processing, ensuring grandparents still get marked while maintaining the deduplication benefits.

Key technical changes:
- Restructures `do_got_oid()` in upload-pack.c to process commit parents before checking the THEY_HAVE flag
- Preserves the original deduplication behavior for non-commit objects
- Maintains protocol v2's ACK optimization while fixing the parent traversal edge case
- Keeps the same test coverage from the approved t5530 test modernization

The fix addresses the specific scenario where clients send commits non-chronologically, ensuring all necessary parent commits still receive proper THEY_HAVE marking. This maintains protocol correctness while achieving the original goal of reducing redundant ACKs in protocol v2. The solution appears technically sound, directly responding to Junio's identified regression case.
