This is the fourth patch in Patrick Steinhardt's series refactoring commit graph handling for the pluggable ODB effort. The patch modifies `repo_find_commit_pos_in_graph()` to return the commit graph pointer where a commit is found, rather than just a boolean success/failure. This change prepares for moving commit graph storage from `object_database` to `odb_source` by ensuring callers have direct access to the relevant graph instance.

The key technical changes include:
- Changing the function signature to return `struct commit_graph *` instead of `int`
- Updating all callers (in bloom.c and commit-graph.c) to use the returned graph pointer
- Modifying the function documentation to reflect the new behavior
- Maintaining the same NULL-check pattern established in previous patches

The patch affects bloom filter loading and commit graph info loading, with callers now using the returned graph pointer directly rather than accessing `r->objects->commit_graph`. This continues the series' pattern of carefully refactoring commit graph access patterns in preparation for the odb_source transition, with clean mechanical changes and thorough updates to all affected call sites.
