This is a major infrastructure proposal introducing Rust into Git's core, presented as a test balloon before making it mandatory in Git 3.0. The RFC comes as a 3-patch series from Patrick Steinhardt, starting with build system support and a trivial varint implementation as proof of concept.

The series aims to:
1. Establish Rust build support (currently only meson)
2. Convert the simple varint.c subsystem to Rust to validate C interop
3. Document the future mandatory Rust requirement in BreakingChanges

Key technical details include:
- Initial meson.build changes to compile Rust code into a static library
- A 92-line varint.rs implementation replacing varint.c
- Explicit acknowledgement this will break some platforms' builds
- Missing pieces like Makefile support and CI jobs noted as future work

The proposal frames this as an experimental playground to develop infrastructure before committing to wider adoption, separating the build system changes from later feature work (like xdiff integration). The BreakingChanges addition signals this will become mandatory, giving distributors time to adapt.

This is clearly a significant architectural shift that will likely spark discussion about platform support, toolchain requirements, and the Rust migration strategy. The choice of varint.c as a test case is sensible (isolated, dependency-free), but the mandatory nature may prove controversial for environments where Rust tooling is unavailable.
