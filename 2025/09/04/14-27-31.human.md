This is a preparatory patch for the `git-history` command series, focusing on sequencer infrastructure. It introduces a new `skip_commit_summary` option to control whether the sequencer prints commit summaries after operations like cherry-pick. The change is motivated by upcoming `git-history` subcommands where this output would be undesirable.

The patch adds the new flag to `struct replay_opts` and ensures it persists across sequencer operations by saving to the sequencer configuration file. The implementation is straightforward - it simply skips the `print_commit_summary()` call when the flag is set. The change touches both the sequencer's commit handling and its persistence logic.

This appears to be a clean, focused change that lays groundwork for the larger series. The commit message clearly explains the change's purpose and relationship to the broader `git-history` effort. The implementation follows existing patterns in the sequencer code for handling similar options.
