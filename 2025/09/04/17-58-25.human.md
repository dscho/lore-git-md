Refactoring patch improving type safety in object-name.c.

René Scharfe proposes a small but meaningful change to the `extend_abbrev_len()` function in object-name.c. The function currently takes a `void*` parameter that's immediately cast to a `struct min_abbrev_data*`, which is the actual type used by all callers except one. The patch changes the parameter type directly to `struct min_abbrev_data*`, removing the need for the internal cast and letting the compiler enforce type safety.

This is a straightforward improvement that follows good C programming practices by being explicit about types rather than using `void*` unnecessarily. The change is minimal (just 3 lines modified) and low-risk since it doesn't affect behavior - it just makes the interface more type-safe. The commit message clearly explains the change and its motivation. This appears to be a clean, well-justified refactoring.
