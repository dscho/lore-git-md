This is a response in the ongoing thread about introducing Rust infrastructure to Git core, specifically addressing the build system requirements for the initial Rust support patch.

Brian m. carlson raises two key concerns about the proposed meson-based Rust build infrastructure. First, they note the patch only implements Rust support in meson while many users (including Debian and their workplace) rely on the Makefile build system. Second, they point out the meson version requirement (1.9.0) is too recent - it's unavailable in current Debian stable (1.7.0) and Ubuntu releases, while Git's platform support policy suggests targeting meson 0.56.2 (available in Debian 11 with LTS through 2026).

The response highlights practical adoption barriers, suggesting the current approach would prevent most users from trying the Rust integration. It references Git's documented platform support policy to argue for targeting older meson versions. This feedback directly addresses the "test balloon" goal by pointing out how the implementation choices might limit the very testing the RFC seeks.

Key technical points:
- Current patch lacks Makefile support despite many users relying on it
- Meson 1.9.0 requirement is too strict per Git's platform support policy
- Suggests targeting meson 0.56.2 instead (Debian 11 LTS baseline)
- Implies CI testing should cover these build configurations

This response adds concrete platform compatibility concerns to the thread's open questions, particularly around build system requirements and real-world testability. It comes from an experienced contributor (brian m. carlson) with specific knowledge of packaging and platform support constraints.
