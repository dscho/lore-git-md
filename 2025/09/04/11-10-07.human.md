This is a proposal for Rust adoption strategy in the Git project, continuing the ongoing discussion about how to introduce Rust code while maintaining compatibility. Patrick Steinhardt responds to Junio Hamano's concerns about finding suitable areas for optional Rust features by suggesting an alternative approach: converting a small, stable subsystem ("varint.c") as a test balloon while keeping both C and Rust implementations temporarily.

The email acknowledges the maintenance burden of dual implementations but argues this would be manageable for a trivial, rarely-changed component like varint encoding (30 lines of code). This contrasts with earlier proposals to make Rust features optional additions, as it instead demonstrates Rust interoperability within core functionality while minimizing risk. Steinhardt plans to follow up with concrete implementation patches.

The proposal represents a middle ground in the ongoing debate - more ambitious than keeping Rust purely optional for new features, but less disruptive than converting critical subsystems like xdiff. It aims to provide real-world experience with Rust integration while maintaining stability, though the long-term implications for other subsystems remain open.
