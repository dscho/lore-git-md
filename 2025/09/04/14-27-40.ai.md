Feature implementation for the `git-history` command's `reorder` subcommand, part of Patrick Steinhardt's RFC v3 series introducing flexible history editing operations. This patch builds on the preparatory infrastructure from earlier in the series to implement commit reordering functionality.

The `reorder` subcommand allows moving a commit to come before (`--before`) or after (`--after`) another specified commit, with comprehensive edge case handling. Key implementation details include:
- Rejects merge commits and dirty worktrees
- Requires exactly one of `--before` or `--after` options
- Uses the series' existing `collect_commits()` and `apply_commits()` infrastructure
- Introduces new `replace_commits()` helper for manipulating commit sequences
- Handles root commits and branch tips
- Executes hooks (prepare-commit-msg, post-commit, post-rewrite)
- Includes 278 lines of tests covering:
  - Basic reordering in both directions
  - Edge cases (root commits, branch tips)
  - Conflict detection
  - Hook execution verification
  - Error conditions (merges, dirty state, invalid arguments)

The implementation appears thorough, with careful attention to edge cases and good test coverage. It builds logically on the series' existing infrastructure while introducing the first concrete history-editing operation beyond the management commands implemented earlier. The patch maintains the series' focus on providing Jujutsu-inspired history editing while working within Git's existing sequencer framework.
