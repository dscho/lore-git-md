This is a documentation patch announcing the future mandatory requirement of Rust in Git's build process, part of Patrick Steinhardt's RFC series introducing Rust infrastructure.

The patch adds an entry to BreakingChanges.adoc stating that Rust will become mandatory starting with Git 3.0, expected in the second half of next year. Currently, Rust usage is optional (as demonstrated by the varint.c conversion in previous patches), allowing distributors time to prepare. The documentation explains the transition plan, including that the final pre-3.0 version will be maintained as an LTS release until alternate Rust backends like gcc-rs can build Git.

The announcement acknowledges platform challenges (some lacking Rust toolchains entirely) while framing the change as necessary for broader Rust adoption across Git's codebase. The documentation is thorough, covering current optional status, build system behavior (meson's auto-detection), and the planned timeline.

This completes the RFC series' documentation component after the technical implementation patches. The proposal is clearly stated but will likely generate discussion about platform support implications and the mandatory nature of the change versus an opt-in approach.
