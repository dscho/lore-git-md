Patrick Steinhardt's 6-patch series refactoring commit graph handling for the pluggable ODB effort continues to generate design debate. The series moves commit-graph storage from `struct object_database` to `struct odb_source` (patch 6/6), with Taylor Blau identifying two behavior changes needing reconsideration: 1) `read_commit_graph_one()` now returns NULL on subsequent calls even if a graph was previously loaded, unlike the old `prepare_commit_graph()` which returned cached graphs, and 2) alternate handling semantics where commit graphs from alternates may now be returned where previously only the main object store's graph was considered.

Junio Hamano now weighs in, directly challenging Steinhardt's position that commit graphs should be backend-specific optimizations. Hamano aligns with Taylor Blau's view that graphs represent fundamental repository metadata, arguing core operations (commit traversal, reachability checks) fundamentally rely on graph data structures that must be repository-wide to be useful. His key technical concern is that generic code paths need consistent graph access regardless of storage backend. Hamano suggests treating auxiliary data (graphs, bitmaps) as repository-level concepts that backends must support standardized, opposing Steinhardt's vision where backends could implement their own optimization structures.

The architectural debate centers on whether commit graphs are fundamental abstractions (Junio/Taylor view) or implementation details (Patrick view). Taylor Blau had earlier made a nuanced distinction - while graph structure caching is tied to packfile storage, generation numbers and Bloom filters provide semantic information valuable across backends. The exchange reveals deeper philosophical differences about graph ownership and cross-source behavior.

Key technical details include modified files (commit-graph.c, commit-graph.h, odb.c, odb.h, packfile.c), new behavior around `commit_graph_attempted` flag, and alternate ODB graph loading semantics. While mechanical changes proceed, the unresolved design question remains open. Steinhardt plans a design document after two more patch series to formalize the source-specific approach, with Junio and Taylor pushing for repository-level treatment. The discussion highlights tension between the ODB abstraction goals and maintaining consistent behavior for core operations that depend on commit graph data.
