Patrick Steinhardt's 6-patch series refactoring commit graph handling for the pluggable ODB effort continues with patch 6/6 moving commit-graph storage from `struct object_database` to `struct odb_source`. Taylor Blau's review identifies two behavior changes needing reconsideration: 1) `read_commit_graph_one()` now returns NULL on subsequent calls even if a graph was previously loaded, unlike the old `prepare_commit_graph()` which returned cached graphs, and 2) the patch introduces alternate handling semantics by potentially returning commit graphs from alternates where previously only the main object store's graph was returned. Taylor suggests separating these behavior changes from the core refactoring.

The architectural debate continues between Steinhardt's source-specific model (treating commit graphs as implementation details of storage formats) and Junio Hamano/Derrick Stolee's repository-wide view (treating graphs as fundamental structured caches). Taylor Blau's latest response pushes back on Steinhardt's position, making a nuanced distinction between the graph's roles: while its structure caching is tied to packfile storage, generation numbers and Bloom filters provide semantic information that would remain valuable with alternative backends. He argues these features transcend any single storage format.

Blau highlights an important behavior change in patch 6/6 - it would allow falling back to alternate ODB commit graphs where previously only the main object store's graph was considered, a semantic shift that appears unintentional. The exchange reveals deeper philosophical differences about whether commit graphs represent fundamental repository metadata (Junio/Derrick/Taylor's view) or backend-specific optimizations (Patrick's view).

Key technical details include modified files (commit-graph.c, commit-graph.h, odb.c, odb.h, packfile.c), new behavior around `commit_graph_attempted` flag, and alternate ODB graph loading semantics. While mechanical changes proceed, the unresolved design question about graph ownership and cross-source behavior remains open. Steinhardt plans a design document after two more patch series to formalize the source-specific approach, with open questions about graph ownership, cross-source coherence, and whether to treat graphs as fundamental abstractions or implementation details.
