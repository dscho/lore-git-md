This is a preparatory patch for the `git-history` command series, focusing on sequencer infrastructure changes to support history editing operations. The patch adds flexibility to the sequencer's post-rewrite hook handling by allowing callers to provide explicit commit ID mappings.

The core change introduces a new `old_oid_mappings` field in `struct replay_opts` that points to an oidmap of `replay_oid_mapping` structs. This allows callers to specify what the "original" object ID should be reported as when the sequencer records rewritten commits, even when the actual rewritten commit has the same ID. The implementation checks this map in `record_in_rewritten()` before writing the rewritten-pending file.

The motivation stems from upcoming `git-history` subcommands that will pre-create commits before using the sequencer to position them in the graph. Without this change, the post-rewrite hook would receive identical old/new commit IDs in these cases, which would be confusing and potentially misleading for hooks. The 21-line change (7 in sequencer.c, 14 in sequencer.h) is straightforward and maintains the existing behavior when no mappings are provided.

This patch continues the series' pattern of carefully extending sequencer infrastructure to support new history editing operations while maintaining backward compatibility. The change is well-contained and appears to be a logical preparation for the history command's needs, though its full utility will only become clear when the calling subcommands are implemented in later patches.
