This is a preparatory patch for the `git-history` command series, adding sequencer infrastructure to support rewinding HEAD after non-rebase operations. The patch introduces a new `restore_head_target` option in `struct replay_opts` that allows cherry-pick-like operations to reset HEAD to its original branch after completion, similar to how rebase handles it. The option is persisted in the sequencer state file to survive across processes.

The change adds the new field to `struct replay_opts` and implements the necessary plumbing: memory management in `replay_opts_release()`, configuration handling in `populate_opts_cb()`, persistence in `save_opts()`, and the actual HEAD reset logic in `pick_commits()`. The reset uses Git's existing `reset_head()` machinery with `RESET_HEAD_REFS_ONLY` flag to avoid touching the working tree.

This infrastructure will be used by the upcoming `git-history` command which needs to detach HEAD during operations but wants to restore the original branch afterward. The patch carefully maintains existing behavior by only performing the reset when explicitly requested via the new option, and it includes a condition in `sequencer_pick_revisions()` to preserve the fast-path optimization for simple cherry-picks when the option isn't set.

The implementation appears thorough, with proper error handling and reflog message generation. It fits into the broader series by providing one of the foundational pieces needed for the history editing operations to work correctly while maintaining a clean state.
