Feature implementation for the `git-history` command series. This patch adds three management subcommands (`abort`, `continue`, `quit`) to handle interrupted history rewrites, similar to existing sequencer commands in `git rebase`. 

The patch builds on the preparatory work from earlier in the series, using the new `REPLAY_HISTORY_EDIT` mode and refactored sequencer infrastructure. The subcommands provide the expected workflow for recovering from conflicts or abandoning edits: `abort` resets everything, `continue` resumes after fixing conflicts, and `quit` stops the operation while preserving the current state. 

Implementation is straightforward, wrapping existing sequencer functions (`sequencer_rollback`, `sequencer_continue`, `sequencer_remove_state`) with the new history-edit mode. The patch includes basic tests verifying argument handling and error cases, though the commands aren't yet useful without the history-editing operations they'll manage. 

This is patch 8/18 in the v3 RFC for `git-history`, following the command scaffolding patch. The implementation appears clean and well-integrated with Git's existing sequencer machinery, though its real utility will become apparent when the actual history-editing subcommands are added in later patches.
