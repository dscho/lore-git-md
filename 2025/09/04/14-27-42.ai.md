This is a refactoring patch in Patrick Steinhardt's `git-history` RFC series (v3, patch 12/18). It reorganizes the interactive add/patch code by splitting out a new `struct interactive_options` to better separate concerns between the "git add -p" and "git add -i" subsystems.

The patch moves color configuration and diff-related options from `struct add_i_state` into a new `struct interactive_config`, which is initialized via new `interactive_config_init()` and `interactive_config_clear()` functions. The key changes are:

1. Introduces `struct interactive_options` (containing context/interhunkcontext) and `struct interactive_config` (containing color/diff settings)
2. Moves color initialization and diff configuration logic from `add-interactive.c` to `add-patch.c`
3. Updates all callers to use the new structures instead of the old `add_p_opt`
4. Renames variables and parameters from `add_p_opt` to `interactive_opts` throughout

The changes are mechanical and don't modify behavior - this is purely a code organization improvement. The commit message notes this doesn't fully detangle the subsystems yet, with `init_add_i_state()` still being called from the add-patch code (to be fixed in a later patch).

This refactoring is part of the larger effort to build the new `git-history` command with history editing subcommands. The patch series has been through several iterations with active discussion about implementation details and feature scope. This particular change helps clean up the interactive add/patch infrastructure that the history command will build upon.
