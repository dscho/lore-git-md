This is a response in the ongoing thread about introducing Rust infrastructure to Git, focusing on build system concerns. Brian m. carlson raises two practical issues with Patrick Steinhardt's initial meson-based Rust support patch.

First, they note the patch only addresses meson builds while many users (including Debian and their workplace) rely on the traditional Makefile system. They argue Rust detection needs to work there too for proper testing. Second, they challenge the meson 1.9.0 version requirement, pointing out this excludes current stable Debian/Ubuntu releases. They suggest targeting meson 0.56.2 instead to match Git's platform support policy.

The response comes from an experienced contributor (carlson maintains Git's hash algorithm transition code) and focuses on real-world deployment concerns rather than opposing Rust itself. Their points about build system fragmentation and version requirements are likely to require addressing before the RFC can move forward, as they affect the community's ability to test the proposed changes. The tone is constructive but firm about compatibility expectations.
