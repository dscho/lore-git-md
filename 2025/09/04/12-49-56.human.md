This is the second patch in Patrick Steinhardt's 6-part refactoring series to move commit graph handling from object_database to odb_source. The change removes a redundant commit graph existence check in `revision.c`'s bloom filter path.

The patch eliminates an explicit check for `revs->repo->objects->commit_graph` in `check_maybe_different_in_bloom_filter()`, since the subsequent generation number test (which checks `commit_graph_generation()`) would already fail if there were no commit graph. The commit message argues this isn't a meaningful performance optimization since commit graph slab lookups are constant-time when unpopulated.

This is another clean, mechanical change that doesn't affect behavior while simplifying the code. Like the first patch in the series, it helps untangle commit graph handling from the object database structure in preparation for the larger odb_source transition. The change is small (3 lines removed) and focused, touching only revision.c's bloom filter path. The series continues to show careful, incremental refactoring with each patch making a single-purpose change toward the broader goal.
