This is a cover letter for a 4-patch series implementing the long-planned switch of Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES enabled. The series follows up on a 2020 deprecation warning and aligns with industry practice where major Git forges have already made this change.

The first patch is the main implementation, switching the default branch name to "main" when WITH_BREAKING_CHANGES is set, while maintaining backward compatibility. It updates documentation in BreakingChanges.adoc and git-init.adoc, modifies repo_default_branch_name() in refs.c, and adds tests in t0001-init.sh. The remaining three patches clean up test cases that still relied on the "master" default branch name, removing the last instances of GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME=master from the test suite.

Key technical details include:
- Changes gated behind WITH_BREAKING_CHANGES compile-time flag
- Updates to advice system removing default branch advice when breaking changes enabled
- Maintains backward compatibility path for "master" default
- Documents change applies only to new repositories
- Test updates in t0001-init.sh, t4013-diff-various.sh, t9902-completion.sh, t0613-reftable-write-options.sh
- 107 files modified across series, mostly test file renames from "master" to "main"

The series represents the culmination of a multi-year effort to change this default, with most technical questions now resolved. The remaining open point is whether the reftable backend specifically requires "master" or could use any 6-byte branch name, which Junio Hamano suggested testing with "banana". The patches have been revised based on previous feedback, particularly around maintaining GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME for test flexibility while removing specific "master" references.
