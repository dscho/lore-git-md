This is the initial scaffolding patch for the new `git-history` command in Patrick Steinhardt's RFC v3. It introduces the basic command structure without implementing any actual functionality yet.

The patch components:
- Adds `git-history` to the command list and build system (Makefile, meson)
- Creates a minimal builtin implementation that just a usage message
- Adds documentation stub noting this is experimental and similar to rebase but focused on specific history editing operations
- Includes a basic test that verifies the command fails without a subcommand

Key technical details:
- Command will use Git's sequencer infrastructure (established in earlier preparatory patches)
- Documented as experimental with behavior subject to change
- Explicitly states it doesn't yet handle merge commits
- Currently empty subcommand list in docs (to be filled by subsequent patches)
- Basic test infrastructure in place with one test case

The patch is part of the larger effort to provide Jujutsu-inspired history editing operations (`drop`, `reorder`, `split`, `reword` etc) as discussed in the thread. This is patch 7/18 in the current series, following preparatory infrastructure work and preceding the actual subcommand implementations. The empty implementation here serves as a foundation for the specific history editing operations to be added in later patches.
