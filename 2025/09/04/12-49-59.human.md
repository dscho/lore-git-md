This is the fifth patch in Patrick Steinhardt's series refactoring commit graph handling for the pluggable ODB effort. The patch modifies how commit graphs are merged by passing the graph to be merged as an explicit parameter rather than accessing it through the repository context.

The change prepares for upcoming work where determining the graph to merge will become more complex. By making the graph parameter explicit now, future changes can avoid code duplication. The patch updates two functions (`split_graph_merge_strategy` and `merge_commit_graphs`) to take the graph as a parameter, and updates their call sites accordingly.

This continues the series' pattern of mechanical refactoring to establish proper access patterns for when commit graphs move to odb_source. The changes are straightforward - passing an additional parameter and removing repository access - while maintaining all existing behavior. Like previous patches in the series, this appears to be a well-considered, incremental step toward the larger goal.
