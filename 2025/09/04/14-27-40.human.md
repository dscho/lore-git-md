Feature implementation for the `git-history` command series. This patch adds the "reorder" subcommand to Patrick Steinhardt's proposed history editing tool, allowing users to move commits before or after specified anchor points in the commit graph.

The implementation provides two modes: `--before` to place a commit immediately before another, and `--after` to place it immediately after. The command handles various edge cases including merge commit rejection, dirty worktree detection, and proper hook execution. The patch includes comprehensive tests covering basic reordering, root commit handling, hook execution, and conflict resolution scenarios.

This is part of a larger RFC series (now at v3 with 25 patches) introducing a Jujutsu-inspired history editing tool. The "reorder" functionality builds on earlier infrastructure work including sequencer modifications and `the_repository` removal. The implementation appears thorough, with clear documentation and extensive test coverage (278 lines of new tests). The command fills a common need that currently requires interactive rebase, providing a more direct imperative interface for commit rearrangement.
