This is a preparatory infrastructure patch in Patrick Steinhardt's RFC v3 series introducing the new `git-history` command. It adds a new `REPLAY_HISTORY_EDIT` mode to the sequencer machinery, which will be used by the upcoming history editing operations.

The patch makes several key changes to support the new mode:
1. Introduces `REPLAY_HISTORY_EDIT` as a new `enum replay_action` value
2. Adds parallel handling for `HISTORY_EDIT_HEAD` ref alongside existing `CHERRY_PICK_HEAD` and `REVERT_HEAD` refs
3. Updates error messages and advice to reference `git-history` commands instead of cherry-pick/revert
4. Modifies sequencer operations to properly clean up `HISTORY_EDIT_HEAD` refs
5. Adds new helper `action_to_command()` to map replay actions to todo commands

The changes are extensive but focused - touching sequencer operations, ref handling, and user messaging while maintaining the existing behavior for other sequencer operations. The patch follows the pattern of cherry-pick/revert infrastructure but adds the new mode cleanly with minimal disruption to existing code paths.

This is part of the larger effort to build history editing capabilities inspired by Jujutsu (jj), with this particular patch laying groundwork for the sequencer to understand and manage history editing operations distinctly from rebase/cherry-pick/revert. The implementation appears thorough, with proper attention to ref cleanup and error handling.
