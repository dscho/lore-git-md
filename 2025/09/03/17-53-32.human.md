This is a follow-up discussion about the recently merged series on deprecating `git whatchanged`. The thread focuses on improving user guidance, particularly for interactive use cases.

Kristoffer Haugsbakk responds to Eric Sunshine's observation that the current deprecation hints may not adequately address interactive users who rely on muscle memory or the command's mnemonic value. While acknowledging the validity of the concern, Haugsbakk expresses caution about expanding the error message further, citing past experiences where lengthy hints sometimes overwhelmed users rather than helping them.

The author suggests addressing interactive use cases through documentation rather than in the error message itself, proposing a new "For Users" section in the BreakingChanges documentation. This would provide space to discuss alternatives like creating aliases without cluttering the immediate deprecation warning.

The exchange reveals an ongoing tension in the project between providing comprehensive guidance and avoiding information overload. While the technical implementation of the deprecation is settled, this post-merge discussion shows the team continuing to refine how best to communicate changes to users, particularly for commands with strong interactive use cases.
