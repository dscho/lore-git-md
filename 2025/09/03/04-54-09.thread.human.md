This thread addresses a two-part series fixing duplicate ACK behavior in Git's upload-pack protocol v2. The first patch modernized test infrastructure in t5530-upload-pack-error.sh, receiving explicit approval from maintainer Junio C Hamano for its use of current Git test conventions. The second patch tackled the core issue where repeated non-commit objects in "have" lines caused redundant ACKs, implementing deduplication while preserving backward compatibility with older protocol versions.

Junio has now raised a technical concern about the second patch's interaction with commit parent marking. He points out that moving the `THEY_HAVE` flag check before commit processing might prevent parent commits from being properly marked when duplicate objects are encountered, particularly when clients send commits out of chronological order. This could affect protocol behavior in edge cases. The discussion currently focuses on upload-pack.c's `do_got_oid()` function, where the change was made, with Junio providing a concrete example to illustrate the potential issue. The author will need to address this concern before the series can proceed, either by revising the implementation or demonstrating that the current behavior is actually correct in all cases.
