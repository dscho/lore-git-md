This thread addresses a fix for duplicate ACK behavior in Git's upload-pack protocol v2. The issue stemmed from non-commit objects being stored multiple times in the `have_obj` array when sent repeatedly in "have" lines, causing redundant ACKs and potential memory growth. 

The first patch modernized the test infrastructure in t5530-upload-pack-error.sh to prepare for testing the fix, cleaning up test patterns while maintaining coverage. The just-arrived second patch implements the core fix by moving the `THEY_HAVE` flag check outside commit-specific logic in `do_got_oid()`, ensuring all object types are deduplicated. The changes maintain backward compatibility with protocol v0/v1 while fixing the v2 behavior, and include new test cases showing the corrected operation.

The solution both improves protocol correctness (eliminating unnecessary network traffic) and incidentally addresses a memory growth issue observed at 4MB/s in testing. The changes are confined to upload-pack.c's object handling logic and build on the test infrastructure improvements from the first patch.
