Follow-up discussion about interactive usage guidance for deprecated commands, particularly regarding alias limitations.

This email continues the discussion about how to guide users transitioning from the deprecated `git whatchanged` command. Eric Sunshine responds to Jeff King's observation that Git currently prevents aliases from shadowing builtin commands, meaning users can't create a `whatchanged` alias while the builtin still exists. Eric acknowledges Jeff's earlier proposal (from August 2025) that would allow exceptions for deprecated commands, though notes he didn't explicitly reference it in his previous message.

The key point here is that the current alias system limitations create a gap in the deprecation strategy - users can't set up transitional aliases until the command is fully removed. This technical constraint may lead to continued user confusion and support requests despite the deprecation warnings and documentation. The discussion suggests the need for either system changes (like Jeff's proposal) or alternative guidance approaches to handle this transition period.
