This is a v4 bugfix patch addressing a dangling pointer issue in Git's slab allocator API. The patch follows up on previous discussion that identified a problem where `clear_alloc_state()` would free memory slabs but leave tracking fields non-zero, creating potential undefined behavior if the alloc_state was reused.

The solution combines several improvements:
1. Renames `allocate_alloc_state()` to `alloc_state_alloc()` to follow Git naming conventions
2. Replaces `clear_alloc_state()` with `alloc_state_free_and_null()` which handles both clearing and freeing atomically
3. Updates all callers in object.c to use the new API

The v4 version specifically fixes a minor but technically incorrect NULL check pattern in `alloc_state_free_and_null()` where the function was dereferencing the double pointer before checking for NULL. This was the last remaining issue identified in the v3 review.

The patch has been thoroughly reviewed by multiple Git maintainers (Junio C Hamano, Torsten Bögershausen, and Jeff King) and appears ready for merging. It provides better encapsulation of the allocator interface and prevents the original state bug while removing redundant `FREE_AND_NULL()` calls at call sites. The only potential missing piece is a test case for the original NULL dereference scenario, but this hasn't been raised as a blocking concern.
