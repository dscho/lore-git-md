This is a bugfix patch series addressing an issue in the Git protocol v2 implementation. The problem occurs in `git-upload-pack` when clients send "have" lines referring to non-commit objects (like tags or trees) multiple times. Currently, the server stores each duplicate in its `have_obj` array and sends redundant "ACK" responses, which is inefficient.

The series consists of two patches: first modernizing some related tests in t5530, then fixing the core issue in upload-pack.c. The fix appears straightforward - modifying the logic to avoid storing duplicate non-commit objects. The commit message clearly explains the problem and solution, and the test modernization suggests good attention to maintainability.

This seems like a clean, focused improvement to protocol behavior that should be uncontroversial. The impact is likely small in practice (since clients typically send commit objects in "have" lines), but it's a sensible optimization that makes the protocol more robust.
