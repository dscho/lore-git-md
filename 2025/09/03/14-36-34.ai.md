This is a brief acknowledgment in the ongoing performance optimization and security hardening discussion around `git describe`'s depth computation.

Jeff King (peff@peff.net) approves René Scharfe's v2 patch that replaces a custom khash implementation with oidset for storing commit OIDs in `finish_depth_computation()`. The change maintains the 1.4x speedup demonstrated in benchmarks while simplifying the code by using Git's standard oidset rather than a custom khash. 

The approval comes after previous discussion about security implications of hash functions, where Jeff King and René Scharfe debated deterministic XOR versus randomized bit selection approaches for hardening against collision attacks. This particular patch doesn't modify the security aspects but focuses on the structural change to oidset.

The thread context shows this is part of broader optimizations across multiple subsystems (describe, topological sorting, object flag storage) with security considerations now being operationalized. The oidset approach here represents one validated solution for the sparse-access use case in `git describe`, with its performance characteristics and security properties being weighed against other alternatives.
