Follow-up discussion about the `split` subcommand's diff display behavior in the `git-history` RFC series. D. Ben Knoble reports not seeing the expected diff output between old and new trees when using the interactive `split` operation, despite Patrick Steinhardt confirming this should work. Knoble provides a detailed reproduction case showing the issue persists even when manually editing hunks or adding new diff lines. The discussion suggests potential bugs in the wt-status interface that Patrick acknowledges as problematic, though he couldn't reproduce the issue. This exchange highlights an important usability gap in the `split` subcommand's feedback mechanism, which is meant to show users the changes being split between commits. The technical focus remains on the interaction between the history editing operations and Git's status reporting infrastructure.
