This is the second patch in a two-part series fixing duplicate ACK behavior in upload-pack protocol v2. The patch addresses a protocol v2 issue where non-commit objects sent repeatedly in "have" lines would be stored multiple times in the `have_obj` array, causing redundant ACKs and potential memory growth.

The key technical changes move the `THEY_HAVE` flag check outside the commit-specific logic in `do_got_oid()`, applying it to all object types. This ensures non-commit objects are deduplicated like commits already were. The patch includes new test cases showing the fixed behavior: protocol v0 still ACKs duplicates (preserving backward compatibility) while v2 now ACKs each non-commit object only once.

The commit message notes this also mitigates a mild memory growth vector (4MB/s in testing) but focuses primarily on the protocol correctness aspect. The changes are contained to upload-pack.c's object handling logic and maintain backward compatibility with protocol v0/v1. The test additions build on the infrastructure cleanup from patch 1/2, verifying both the old and new behaviors.
