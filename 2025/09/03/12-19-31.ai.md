Refactoring patch in the `git-history` RFC series, addressing code duplication in the sequencer.

This patch responds to D. Ben Knoble's observation about repeated switch statements mapping `replay_action` to `todo_command` values in sequencer.c. Patrick Steinhardt introduces a new helper function `action_to_command()` that centralizes this logic, replacing three identical switch statements with function calls. The change affects the core sequencer operations used by both rebase and the proposed history editing commands.

The refactoring:
1. Extracts the action-to-command mapping into a dedicated function
2. Handles the same cases as before (PICK/HISTORY_EDIT -> TODO_PICK, REVERT -> TODO_REVERT)
3. Adds a BUG() case for unexpected values
4. Applies the change to three call sites: `read_populate_todo()`, `walk_revs_populate_todo()`, and `single_pick()`

This is a straightforward code organization improvement that doesn't change behavior but makes the sequencer's internals more maintainable. The change fits naturally into the ongoing `git-history` work since it touches the same sequencer infrastructure that the new history editing commands will use. The patch demonstrates responsiveness to code review while maintaining the series' focus on sequencer modifications.
