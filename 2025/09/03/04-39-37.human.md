This is a follow-up discussion in the ongoing CI thread about Windows Defender causing false positives in GitLab CI. Patrick Steinhardt responds to Junio Hamano's question about whether similar issues might affect other CI platforms like GitHub Actions.

Patrick suggests that other CI providers likely already disable realtime monitoring by default, since these are ephemeral build machines where security scanning provides little benefit. He reiterates that the GitLab Windows runners in particular seem under-optimized, referencing the significant performance improvements (nearly 2x faster test execution) seen from disabling Defender scanning in his original patch.

The exchange remains lighthearted - Patrick doesn't provide concrete data about other platforms but offers a reasonable assumption based on the nature of CI environments. The core solution (disabling Defender scanning for Windows CI) remains unchanged from the original patch, with this follow-up simply addressing a speculative question about applicability to other services. No new technical changes or investigations are proposed.
