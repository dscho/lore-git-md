Thread identity: Bug report about reference transaction hook behavior when updating existing refs, reported by elhmn, with authoritative response from Jeff King.

Core problem: The reference transaction hook shows CREATE-formatted lines (with zero old_oid) when existing refs are force-updated without specifying an old value, rather than showing the ref's current value. This behavior was initially reported as potentially unexpected but is now confirmed as correct per the documented interface.

Current status: Jeff King has authoritatively explained that the behavior is intentional and matches the githooks(5) documentation. The hook shows the old value *passed to the transaction* (which is zero when no old value is specified for a force update), not necessarily the ref's current value. This resolves the original question while acknowledging the interface's limitations.

Key technical details:
- Hook output shows transaction input (zero old_oid when force-updating) rather than current ref state
- Documented behavior in githooks(5) matches current implementation
- Semantic limitation: hooks cannot distinguish between creates and force updates when no old value specified
- Behavior consistent across all ref backends by design

Open questions:
- No remaining technical questions about current behavior (confirmed as correct)
- Potential future work could address the semantic limitation, but would require careful interface design to maintain backwards compatibility
