Thread identity: Bug report about reference transaction hook behavior when updating existing refs, reported by elhmn.

Core problem: The reference transaction hook receives CREATE-formatted lines (with zero old_oid) when existing refs are updated, rather than the expected UPDATE format showing the ref's previous value. This occurs consistently across both file and reftable backends, demonstrated by updating `refs/heads/master` where the hook shows `0000000... <new_oid>` instead of `<old_oid> <new_oid>`.

Current status: The behavior is reproducible in Git 2.51.0 on Ubuntu 20.04.6 LTS. The existing test suite (`t1416-ref-transaction-hooks.sh`) appears to expect this zero-OID behavior for updates, raising the possibility this may be intentional rather than a bug.

Key technical details:
- Hook output format discrepancy: CREATE (`0000000... <new_oid> <name>`) vs expected UPDATE (`<old_oid> <new_oid> <name>`)
- Behavior consistent across both file and reftable backends
- Demonstrated via ref update from commit B to A showing zero OID instead of B's OID

Open questions:
- Is this zero-OID behavior for updates intentional (as suggested by test suite) or a bug?
- If intentional, what is the design rationale?
- If a bug, what would be the correct behavior?
