This is a follow-up discussion about the recently merged deprecation guidance series for `git whatchanged`. Eric Sunshine raises concerns about the current deprecation hints being too focused on scripted usage (`git log --raw --no-merges`) and suggests adding simpler guidance for interactive users who might want to maintain muscle memory via aliases. Kristoffer Haugsbakk prefers documenting this in BreakingChanges.adoc rather than expanding runtime messages, citing concerns about information overload from lengthy hints.

Key technical points:
- Current implementation provides script-focused alternatives via `you_still_use_that()` helper
- Eric proposes minimal alias suggestion for interactive use cases
- Kristoffer maintains position against expanding runtime messages
- Discussion reveals tension between thorough guidance and user attention/behavior patterns

The exchange highlights an emerging post-merge consideration about how to best serve different user patterns (scripted vs interactive) while balancing message clarity. Eric's concrete proposal suggests a middle ground with very concise alias advice, while Kristoffer remains concerned about overwhelming users even with brief additions. This reflects the broader challenge noted in the thread of balancing deprecation communication effectiveness with user support burden.
