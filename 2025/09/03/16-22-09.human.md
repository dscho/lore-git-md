This is a response in the ongoing Rust infrastructure discussion, focusing on platform compatibility concerns. Ramsay Jones weighs in on Patrick Steinhardt's proposal for making Rust optional until Git 3.0, strongly supporting the gradual adoption approach. 

Jones agrees with Steinhardt's position that making Rust mandatory immediately would be disruptive, particularly for platforms like Cygwin where Rust isn't currently available. He notes he's already stopped building Git on Cygwin due to the lack of Rust support there, though he clarifies this isn't an objection to having optional xdiff implementations in both C and Rust. The email contains a wry observation that xdiff might not have been the ideal first candidate for Rust integration since diff functionality is so fundamental to Git's operation.

The response reinforces the practical challenges facing platforms without Rust support, adding Cygwin to the growing list of affected systems (alongside NonStop discussed earlier in the thread). While Jones doesn't oppose the technical direction, his experience highlights real-world impacts of the Rust transition that align with Steinhardt's caution. The tone suggests this is more a pragmatic acknowledgement of constraints than ideological opposition to Rust adoption.
