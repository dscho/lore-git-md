Bugfix for color configuration fallback in interactive patch mode. This is the third patch in Jeff King's series addressing color handling regressions in commands like `checkout -p` and `stash push -p that stem from the 2021 Perl-to-C conversion.

The patch reviews Jeff's solution for ensuring interactive commands properly fall back to `color.ui` when specific color settings like `color.diff` aren't set. The fallback wasn't working consistently because some commands weren't initializing color configuration properly. Jeff's approach centralizes the fallback logic in `add-interactive.c` rather than requiring each command to handle it individually.

Patrick Steinhardt provides minor review feedback, suggesting two small improvements: using `GIT_COLOR_UNKNOWN` instead of the numeric `-1` for uninitialized states (consistent with his earlier suggestions in the thread), and clarifying the documentation about color config keys. He approves of the overall approach and test coverage, calling the new test case "nice and straight-forward."

This patch has already been acknowledged by Junio Hamano, and with Patrick's minor suggestions addressed, it appears ready to be part of the final solution for the color handling regression. The series as a whole provides a comprehensive fix while maintaining backward compatibility and proper separation between plumbing and porcelain color handling.
