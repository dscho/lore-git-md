This is a technical discussion about alias handling for deprecated commands, specifically regarding the `git whatchanged` deprecation effort. Jeff King (Peff) responds to Eric Sunshine's suggestion about recommending users create an alias for interactive use of the deprecated command.

Peff points out a key technical limitation: Git's current behavior prevents shadowing builtin commands with aliases, meaning users can't create a `git whatchanged` alias while the builtin command still exists. He references his earlier proposal (from August 2025) that would allow exceptions to this rule specifically for deprecated commands.

The discussion reveals an important implementation constraint for the deprecation workflow - the alias-based transition path can't be fully realized until either the command is completely removed or the alias shadowing restriction is modified. This affects how useful alias-based guidance can be during the deprecation period before removal.
