This is a follow-up discussion in the thread about deprecating `git whatchanged`. Jeff King (Peff) responds to Eric Sunshine's suggestion about using aliases for interactive use of the deprecated command.

Peff points out a technical limitation: Git currently prevents aliases from shadowing built-in commands, so users can't create a `whatchanged` alias while the command still exists (even in its deprecated form). He references his earlier proposal that would allow exceptions to this rule specifically for deprecated commands.

The exchange highlights an important practical consideration in the deprecation process - while the technical implementation of deprecation warnings is complete, there are still open questions about how to best guide users in transitioning away from deprecated commands, particularly for interactive use cases where aliases would be the natural solution.

This discussion builds on the already-merged series that implemented the three-step deprecation pattern (notice/alternatives/contact) for `git whatchanged`, now focusing on the edge cases and user experience aspects of the initial implementation.
