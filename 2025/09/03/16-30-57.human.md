René Scharfe responds to Jeff King's earlier suggestion about using oidset instead of khash, noting they could take the optimization further by using a uint32_t khash set of commit indexes. This would reduce memory usage by eliminating pointers, though René reports no significant performance difference in benchmarks. The observation highlights an implementation detail that could theoretically improve efficiency, though it doesn't materially change the current performance profile.

The exchange continues the thread's technical exploration of tradeoffs between different data structures (khash, commit-slabs, oidsets) while maintaining the 1.4x speedup already achieved.
