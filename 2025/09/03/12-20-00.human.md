This is a response in the ongoing RFC discussion about the new `git-history` command, specifically addressing questions about the interactive-only nature of the `split` subcommand.

Patrick Steinhardt clarifies that the `split` subcommand is intentionally designed as an interactive porcelain command rather than a scriptable plumbing command. He acknowledges Kristoffer Haugsbakk's positive feedback about the current interactive workflow, which allows splitting commits with intuitive commands like `git history split :/'The second batch'`.

While open to future additions, Patrick explains that the current focus is on establishing a solid baseline for common interactive history editing tasks. He expresses uncertainty about how a stateful split session for external tools might work, but leaves the door open for such functionality if someone proposes a clear design.

The exchange shows the project maintaining its porcelain-first approach while considering potential future extensibility. This comes as part of the larger v3 RFC series that's actively incorporating feedback on various subcommands and their interfaces.
