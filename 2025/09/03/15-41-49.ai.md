Security discussion on hash collision hardening for Git's data structures.

This email continues the technical debate between René Scharfe and Jeff King about hardening Git's hash functions against collision attacks. The discussion focuses on two competing approaches to improve the security of `oidhash()` while maintaining performance in data structures like khash and oidset.

René argues that Jeff's proposed deterministic XOR-ing of additional hash bits doesn't fundamentally increase security against attackers, since they can incorporate the same deterministic function into their brute-force search for colliding hashes. He maintains that his runtime-selected random bitmask approach would provide better security by making the hash function unpredictable to attackers.

Jeff counters that XOR-ing provides sufficient security by forcing attackers to control more bits, while being simpler to implement. The exchange includes concrete examples showing how each method would process sample hashes, with René demonstrating that deterministic approaches don't actually increase the attacker's work factor when they can incorporate the function into their search criteria.

The discussion remains technical but collegial, with both sides providing clear examples to support their positions. This represents a key decision point in the broader performance optimization effort, as the security hardening approach chosen will affect multiple subsystems currently using vulnerable hash functions. The thread shows no clear consensus yet, suggesting this debate may require input from other security-conscious contributors.
