Bugfix for the `git-history reword` subcommand's error message. This is a follow-up to Kristoffer Haugsbakk's report of an incorrect error message when providing an invalid commit reference to the `reword` subcommand - it was showing "commit to be split" instead of "commit to be reworded".

The fix is straightforward - a one-line change correcting the copy-paste error in the error message string. This doesn't affect functionality, just improves the error reporting accuracy. The patch maintains the existing behavior where invalid commit references trigger an error exit, but now with proper terminology matching the subcommand being used.

This is part of Patrick Steinhardt's ongoing RFC v3 series introducing the new `git-history` command with various subcommands for history operations. The series has seen active discussion around usability and documentation issues, with this being a minor but important polish to the `reword` subcommand's user experience. The fix addresses one of the error message consistency issues noted in the thread's open questions.
