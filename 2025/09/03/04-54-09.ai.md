This is a bugfix patch series targeting the upload-pack protocol v2 behavior. The issue addresses duplicate ACKs being sent for non-commit objects when clients send repeated "have" lines.

The series consists of two patches: first modernizing some related tests in t5530, then fixing the core issue in upload-pack.c. The problem occurs when clients repeatedly send the same non-commit object ID in "have" lines - upload-pack stores these duplicates in its `have_obj` array and consequently sends redundant ACKs. The fix modifies this behavior to avoid storing and acknowledging duplicate non-commit objects.

The changes touch the protocol negotiation logic in upload-pack.c and update the corresponding test suite. The test modernization appears to be preparatory work for the main fix, updating older test patterns to current standards. The main fix focuses specifically on protocol v2 behavior, suggesting this may be a regression from earlier protocol versions or an oversight in the v2 implementation.
