This is a bug report regarding the reference transaction hook behavior. The author (elhmn) observes that when updating an existing ref, the hook receives a transaction line formatted as CREATE (with zero old_oid) rather than the expected UPDATE (with the ref's previous value). This occurs consistently across both file and reftable backends.

The issue is demonstrated through a test case where updating `refs/heads/master` from commit B to A shows a zero OID instead of B's OID in the hook output. The author notes this contradicts their expectation but acknowledges the existing test suite (`t1416-ref-transaction-hooks.sh`) appears to expect this zero-OID behavior for updates.

Key technical details:
- Hook receives CREATE format (`0000000... <new_oid> <name>`) when updating existing refs
- Expected UPDATE format (`<old_oid> <new_oid> <name>`)
- Affects both file and reftable backends
- Tested with Git 2.51.0 Ubuntu 20.04.6 LTS
- Existing test suite may be enforcing current behavior

The report leaves open whether this is an intentional design choice (given the test) or an actual bug, presenting it for discussion. The clear reproduction steps and backend coverage suggest this is a well-investigated report, though the author doesn't propose a specific fix.
