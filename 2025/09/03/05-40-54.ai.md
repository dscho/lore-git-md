This is a policy discussion email in the ongoing Rust infrastructure thread, specifically addressing the timeline and adoption strategy for Rust in Git. Patrick Steinhardt responds to Brian Carlson's arguments for immediate Rust adoption by proposing a more gradual approach.

Steinhardt acknowledges Carlson's points about Rust's productivity benefits (like BTreeMap efficiency) but expresses concerns about ecosystem stability and platform support. He suggests making Rust optional until Git 3.0 to allow for: (1) build system iteration, (2) platform maintainer preparation time, and (3) community adaptation. Importantly, he clarifies this doesn't mean maintaining dual C/Rust implementations - rather, new Rust features would be optional additions during the transition period.

The email reveals key tensions: Carlson wants to leverage Rust now for faster development of planned Git 3.0 features, while Steinhardt prioritizes minimizing disruption to distributions and platforms. Steinhardt also notes the current series' precarious position - building on Rust infrastructure that isn't yet officially accepted. This reply maintains the cautious stance seen in earlier messages while offering a concrete transition path that balances innovation with stability concerns.
