This is a bugfix patch addressing duplicate ACK behavior in Git's upload-pack protocol v2. It's the second part of a two-part series, following test infrastructure modernization in patch 1/2.

The patch fixes an issue where upload-pack would repeatedly store and acknowledge non-commit objects when clients sent duplicate "have" lines in protocol v2. While commits were properly deduplicated using the `THEY_HAVE` flag, other object types (like trees and blobs) were being stored multiple times in the `have_obj` array. This led to redundant network traffic from duplicate ACKs and potential memory growth, though the author notes the memory impact is relatively mild (~4MB/s growth rate).

The solution applies the same `THEY_HAVE` flag deduplication logic to all object types, not just commits. The patch includes new tests verifying the fixed behavior in protocol v2 while confirming protocol v0 maintains its existing behavior (which intentionally ACKs duplicates). The changes are focused in upload-pack.c with straightforward logic changes to the object handling code.

This appears to be a well-constructed fix for a protocol v2 oversight, with clear commit message explaining both the problem and solution, plus thorough test coverage showing the before/after behavior. The changes are minimal and targeted, building on the test modernization from the first patch in the series.
