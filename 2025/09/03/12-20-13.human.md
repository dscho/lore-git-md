Bugfix for the `git-history reword` subcommand in Patrick Steinhardt's RFC series. This is part of the larger `git-history` proposal that introduces new history editing operations inspired by Jujutsu (jj).

Kristoffer Haugsbakk reported that when providing an invalid commit reference to `git-history reword`, the error message incorrectly refers to "split" instead of "reword". Patrick confirms this is a copy-paste error from the `split` subcommand implementation and provides a one-line fix to correct the error message.

The fix is straightforward - changing "split" to "reword" in the error string. This doesn't affect functionality but improves the user experience by providing accurate error messaging. The patch is part of the v3 series which has grown to 26 patches addressing various aspects of history editing operations and their infrastructure.

This minor fix comes amidst broader discussions about the design and usability of the `git-history` command, particularly around the `split` subcommand's interactive workflow and error handling. The series remains in RFC state with active review and refinement ongoing.
