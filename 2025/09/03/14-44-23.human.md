This is a clarification about reference transaction hook behavior in response to a bug report. Jeff King explains that the observed behavior (showing a zero OID for updates) is actually working as documented, not a bug. 

The key insight is that the hook shows the old value *to the transaction*, not necessarily the ref's current value. When using `git update-ref` without specifying an old value (a force update case), the transaction receives a zero OID as documented in githooks(5). The hook can still check the ref's actual current value via `git rev-parse` if needed.

Jeff acknowledges the interface could be improved to distinguish between "create new ref" and "force update existing ref" cases, but notes this would require careful backwards-compatible design. The current behavior appears intentional based on both documentation and test suite expectations. This response effectively closes the original question while identifying a potential (but non-trivial) area for future improvement in the hook interface.
