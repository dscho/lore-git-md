This is a follow-up in the `git repo info` feature series, specifically about the `-z` flag design reconsideration.

Lucas Seiki Oshiro acknowledges Junio Hamano's feedback about the `-z` flag implementation needing redesign to properly handle option parsing semantics. The current approach incorrectly treats `-z` and `--format` as mutually exclusive options. Junio suggested using `-z` as exactly equivalent to `--format=nul` with "last one wins" behavior when combined with other format options.

The author agrees to implement this change, noting they'll also update tests and documentation to match the new behavior. This addresses the last major open question in the v2 series, which otherwise has mentor sign-offs and appears technically sound. The patch remains part of a two-part series adding enhancements to `git repo info`, with the object format field implementation already settled.
