This is a v3 feature patch series from GSoC contributor Lucas Seiki Oshiro, continuing work on enhancements to `git repo info`. The series builds on previous versions that were already technically merge-ready but needed some design refinements.

The major change in v3 is a complete reimplementation of the `-z` flag handling. Instead of treating it as mutually exclusive with `--format`, the new version allows them to be used together with "last one wins" semantics (e.g. `-z --format=text` will use text format). The implementation now uses `OPT_CALLBACK_F` with a shared parsing function, dropping the previous approach that used `die_for_incompatible_opt2()`. Documentation and tests have been updated to match this new behavior.

The second patch remains unchanged from v2, adding the `objects.format` field that exposes the repository's object format (SHA-1 or SHA-256). This was already settled in previous discussion with the singular naming (`objects.format` rather than `object.format`) confirmed.

The series has mentor sign-offs from Karthik Nayak and Patrick Steinhardt, and addresses all the technical feedback from Junio Hamano about the `-z` flag implementation. The only remaining open question from previous discussion is the naming of the `references.format` field (whether to rename it to `reference.format` or `ref.format`), but that isn't touched in this series.

This appears ready for final review, with clean implementation and thorough test coverage. The redesign of the `-z` flag handling follows Git's standard option parsing patterns and provides more flexible behavior than the original version.
