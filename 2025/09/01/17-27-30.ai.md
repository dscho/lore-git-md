This is a v3 feature patch series from GSoC contributor Lucas Seiki Oshiro, continuing work on enhancements to `git repo info`. The series builds on previous versions that were technically merge-ready but required redesign of the `-z` flag implementation per Junio's feedback.

The key change in v3 is a complete redesign of the `-z` flag handling to properly implement "last one wins" semantics when combined with `--format`. The implementation now uses `OPT_CALLBACK_F` with a shared parsing function, making `-z` exactly equivalent to `--format=nul` and allowing them to be used together (with the last specified format taking precedence). This addresses Junio's concerns about the previous implementation's use of `die_for_incompatible_opt2()`.

The second patch remains unchanged from v2, adding the `objects.format` field to expose the repository's object format (SHA-1/SHA-256). This was previously settled in the thread with the singular `object.format` naming confirmed.

Technical details:
- New callback-based parsing handles both `--format` and `-z` through `parse_format_cb()`
- Tests updated to verify the new "last format wins" behavior
- Documentation syntax fixed (proper spacing around `-z` flag)
- Maintains backward compatibility with existing format types
- `objects.format` field reads from `repo->hash_algo->name`

The series appears well-constructed with thorough test coverage and follows Git's established patterns for option parsing. Both patches have mentor sign-offs from Karthik Nayak and Patrick Steinhardt. The remaining open question from previous versions (naming of `references.format` field) is not addressed here as it's orthogonal to these changes.
