Security note regarding hash function vulnerabilities in Git's object storage.

René Scharfe raises an important security consideration regarding the use of `oidhash()` in Git's data structures. He points to a real-world tool (lucky-commit) that demonstrates how an attacker could deliberately create commits with specific hash prefixes in just fractions of a second. This capability could be weaponized to force worst-case O(N) performance in hash table operations by creating collisions.

The concern specifically relates to ongoing discussions about using khash for various Git operations, where performance optimizations have been evaluated. While the immediate context is the `git describe` optimization thread, the implications are broader - any Git operation using `oidhash()`-based structures could potentially be vulnerable to this class of performance degradation attacks.

This email doesn't propose a solution but serves as an important reality check on the security implications of hash function choices in Git's internals. The demonstrated feasibility of hash collision attacks suggests that performance optimizations need to consider both best-case and worst-case scenarios when selecting data structures and hash functions.
