This is patch 12/15 in Patrick Steinhardt's ongoing packfile store refactoring series, moving the `get_multi_pack_index()` function from packfile.c to midx.c where it more logically belongs. The change is motivated by the need to expose `packfile_store_prepare()` (which the function calls) for future use outside the packfile system.

The patch makes several mechanical changes:
1. Moves the function implementation to midx.c
2. Adds its declaration to midx.h
3. Makes `packfile_store_prepare()` public by moving it from static to extern in packfile.h with added documentation
4. Removes the now-redundant declaration from packfile.h

This continues the series' pattern of carefully reorganizing packfile-related code while maintaining identical behavior. The change is well-contained and follows the established refactoring approach seen in previous patches. As with other patches in the series, no test changes are needed since this is purely a code movement with no functional impact.

The patch appears straightforward and uncontroversial, though reviewers may want to verify that all callers are properly handling the now-public `packfile_store_prepare()` function. It sets up for subsequent patches that will further refactor the packfile store interface.
