This is a policy discussion email in the ongoing Rust infrastructure thread, specifically responding to Patrick Steinhardt's LTS proposal for managing the Rust adoption transition. Sam James from Gentoo expresses strong support for Steinhardt's suggestion to designate the last pre-Rust Git version as an LTS release that would receive security and critical bug fixes until gccrs stabilizes (projected 2026). 

James particularly endorses the idea of versioning this as Git 3.0 to clearly signal the compatibility break, noting this would both properly frame the Rust dependency as a breaking change and potentially give developers more freedom to make other changes during the transition. While supportive, James also cautiously notes willingness to help with backporting if still needed when gccrs stabilizes, suggesting conditional rather than blanket commitment to the maintenance burden.

The email reinforces the emerging consensus around Steinhardt's LTS proposal while adding Gentoo's perspective on version numbering implications. It represents a significant policy alignment between two key stakeholders (Gentoo and Steinhardt) on the transition mechanics, though the ultimate decision still rests with Junio Hamano and other core maintainers weighing this against platform exclusion concerns. The response notably doesn't address NonStop's specific situation or the deeper questions about long-term maintenance sustainability that Junio raised, focusing instead on the practical versioning and backporting aspects of the proposal.
