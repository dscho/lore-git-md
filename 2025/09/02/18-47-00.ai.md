This is a policy discussion email in the ongoing Rust infrastructure thread, specifically addressing timeline concerns around Rust adoption in Git. Sam James from Gentoo responds to Brian Carlson's arguments for immediate Rust adoption rather than waiting for Git 3.0 as proposed in Patrick Steinhardt's LTS plan.

Sam makes several technical corrections regarding gccrs portability, pointing to active development work on libgccjit-based Rust compilation (citing three specific GitHub issues) and clarifying that architecture support issues would primarily manifest in upstream crates rather than gccrs itself. He maintains that Rust adoption constitutes a compatibility break comparable to recent C99 transitions, which the project handled cautiously with test balloons.

While acknowledging Carlson's productivity benefits from Rust (simpler code, better data structures like BTreeMap), Sam argues the transition still warrants Git 3.0 timing to properly handle platform compatibility issues. He notes the current xdiff Rust series doesn't yet use Meson's Rust integration like QEMU does, suggesting more integration work remains. The email reinforces Gentoo's position favoring the LTS plan while providing more nuanced technical context about gccrs development status than previously discussed in the thread.
