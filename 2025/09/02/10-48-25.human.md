This is a cover letter for a 15-patch series that introduces a new `struct packfile_store` to better organize packfile management in Git's object database (ODB) layer. The series is part of Patrick Steinhardt's ongoing effort to refactor the ODB code to support pluggable backends.

The key change is moving all packfile-related state from `struct object_database` into a new dedicated `struct packfile_store`. This includes:
- The main packfile list
- MRU (most recently used) list
- Packfile hashmap
- Kept pack cache
- Initialization flag

The series systematically migrates functions like `prepare_packed_git()`, `install_packed_git()`, and `get_all_packs()` to operate on the packfile store rather than directly on the ODB. This is preparation for future work where the packfile store will be moved down into individual ODB sources rather than being part of the main ODB structure.

Changes in v3 include:
- Rebased on master with some conflict resolutions
- Added NULL assignment after freeing packfiles to prevent dangling pointers
- Added documentation for the kept cache struct
- Fixed a missing lock acquisition
- Dropped a controversial patch about MRU handling (moved to future series)
- Improved commit messages and line length handling

The series affects many parts of the codebase that interact with packfiles, including builtins like `cat-file`, `fsck`, `gc`, and `pack-objects`, as well as HTTP and MIDX handling code. Each patch is focused and builds logically on the previous ones to gradually migrate functionality to the new structure while maintaining identical behavior.

This appears to be a well-structured and carefully implemented series that moves Git toward better code organization for the pluggable ODB work. The changes are mechanical but important for the larger architectural goal. The v3 iteration addresses feedback from previous rounds while keeping the core approach intact.
