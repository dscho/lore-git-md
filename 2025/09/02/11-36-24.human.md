This is the final patch in a 6-part series implementing the long-planned change from "master" to "main" as Git's default branch name when built with WITH_BREAKING_CHANGES. Patrick Steinhardt provides feedback on Phillip Wood's implementation, focusing mostly on documentation and testing aspects.

The key technical change in this patch is gating the default branch name behind the WITH_BREAKING_CHANGES flag, removing the advice about future changes (since they're now implemented), and updating tests accordingly. Patrick suggests a few minor improvements:

1. Clarifying in BreakingChanges.adoc that the new default only applies to new repositories
2. Using MAYBE_UNUSED attribute instead of a cast for the quiet parameter
3. Adding a test to verify the "main" branch name when WITH_BREAKING_CHANGES is set

The discussion acknowledges the awkwardness of the conditional documentation blocks but accepts this as unavoidable given AsciiDoc's limitations. Patrick expresses strong support for the change overall, noting the ecosystem has already moved in this direction.

This patch appears well-considered, with thorough test coverage and careful attention to backward compatibility. The remaining discussion points are minor refinements rather than fundamental objections. The series represents the culmination of a 5-year effort to modernize Git's default branch naming.
