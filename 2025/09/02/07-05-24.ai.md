Reftable fsck validation series (4/5) - checking for trailing newline in tables.list. This patch adds validation that the reftable stack's `tables.list` file ends with a newline, which is the expected format when written by Git but could be missing if manually tampered with. The implementation checks the last character via `fseek/ftell` and reports `REFTABLE_FSCK_ERROR_STACK_LIST_MISSING_NEWLINE` through the existing fsck callback mechanism, with corresponding documentation and test updates.

Key technical details: The check is implemented in `reftable_fsck_stack_contains_newline()` which reads the last byte of the file, with error handling for missing files and I/O issues. The error message uses the relative path `reftable/tables.list` per Git conventions. The test case modifies `tables.list` to remove the newline and verifies the error is detected. This continues the pattern from earlier patches of keeping reftable-specific checks in `reftable/fsck.c` while integrating with Git's fsck framework through the `reftable_fsck_info` callback structure.

This is part of Karthik Nayak's v2 series adding comprehensive fsck validation for reftable stack integrity, following Shejialuo's v1 review feedback. The patch follows the established pattern of the series with clear error reporting and test coverage for the specific validation case.
