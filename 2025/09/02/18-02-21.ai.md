Bugfix/feature proposal for remote group functionality in push operations.

Junio C Hamano reports that while `git fetch group` works as expected when a remote group is defined in the config (executing fetches for each member in sequence), the equivalent `git push group` does not work at all. He suggests this is a missing feature that should be implemented for symmetry between fetch and push operations.

The proposed solution involves refactoring the existing group handling code from builtin/fetch.c to make it reusable. Specifically, the `get_remote_group()` function and `struct remote_group_data` would need to be moved to remote.c to be accessible by both fetch and push implementations. This would allow push to gain the same group expansion behavior that fetch already has.

The email characterizes this as a "#leftoverbits" project - suggesting it's a small but worthwhile cleanup/enhancement that's been overlooked. The change appears non-trivial but manageable, requiring coordination between the fetch and push command implementations while maintaining the existing group behavior for fetch. The lack of push group functionality seems like an inconsistency in Git's remote handling that this change would address.
