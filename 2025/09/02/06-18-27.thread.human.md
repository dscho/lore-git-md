This thread discusses the deprecation of `git whatchanged` and the user experience of transitioning to its replacement. A user has raised concerns that the current suggested alternative, `git log --raw`, doesn't clearly communicate the "what changed" functionality. They propose adding a `--whatchanged` option to `git log` as a more intuitive migration path if the standalone command is indeed being phased out.

The discussion appears to be in early stages, with the core question being how to best guide users from the deprecated command to its modern equivalent while maintaining clarity in Git's interface. The proposal focuses on discoverability and user expectations rather than implementation details, suggesting this is primarily a UX design consideration. No maintainers or regular contributors have weighed in yet on either the deprecation plan or the suggested alternative.
