This thread discusses the ongoing deprecation of `git whatchanged` in favor of `git log --raw`, which has encountered user resistance due to perceived UX shortcomings. The original user, jorg@ml1.net, maintains that the transition path is poorly explained in documentation and that the project's refusal to consider a more intuitive alias (`--whatchanged`) makes the change unnecessarily difficult. They've stated they'll continue using the deprecated command rather than adopt `--raw`.

Junio C Hamano, the maintainer, has firmly upheld the 20-year-old `--raw` name despite acknowledging it's not ideal, emphasizing naming consistency over immediate UX improvements. Kristoffer Haugsbakk questioned why one would keep using a deprecated command when alternatives exist, pointing to official documentation. However, jorg@ml1.net notes this documentation only states the deprecation decision without explaining the rationale, leaving some users feeling their concerns were dismissed.

The discussion highlights a tension between maintaining long-established interfaces and making transitions user-friendly. While no technical changes to the functionality are proposed, the core issue remains: how to better communicate and implement deprecations when the replacement's naming or documentation doesn't fully address user needs. The thread currently shows no movement toward resolution, with the user opting out of the recommended migration path and the project maintaining its position.
