This thread discusses the deprecation of `git whatchanged` in favor of `git log --raw`, initiated by a user who finds the `--raw` name unintuitive for showing file changes. The user proposed adding a `--whatchanged` alias to improve discoverability.

Junio C Hamano has now responded, acknowledging the naming issue but firmly rejecting the rename proposal due to `--raw`'s 20-year history. While he agrees the name isn't ideal, he considers changing it now too disruptive. The discussion has effectively concluded with the status quo maintained: users should use `--raw` as the replacement, and the focus should be on improving documentation rather than renaming options. This highlights the project's prioritization of stability over perfect naming for long-established features.
