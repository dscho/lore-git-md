A bug report from Cristian Dinu describes `git ls-remote` failing in container environments where a Git worktree is mounted read-only. The command incorrectly checks the local repository state (via the worktree's gitdir pointer that references an inaccessible host path) even when operating on an explicitly provided remote URL, causing it to fail with "not a git repository" errors.

The issue occurs in a specific but important workflow: when a bare repository's worktree is mounted into a container and someone tries to query a different remote repository. This affects real-world automation tools like Ansible's git module. The report suggests `git ls-remote` should skip local repository validation when given an explicit remote URL, as the local repository state shouldn't matter for remote-only operations.

The bug appears in Git 2.51.0 and demonstrates a clear edge case in the command's repository validation logic that particularly impacts containerized environments where worktrees are mounted read-only. The report provides detailed reproduction steps and context about the practical impact.
