This is the second patch in a 5-part series adding fsck validation for the reftable backend. It introduces infrastructure and a specific check for validating reftable table names.

The patch establishes the fsck framework by adding new files `reftable/fsck.c` and `reftable/reftable-fsck.h` to maintain separation between Git internals and the reftable library. The core function `reftable_fsck_check()` takes callbacks for reporting issues and verbose output. The implementation validates that table names in `tables.list` follow the expected format (hex min/max timestamps with random suffix and `.ref` extension).

The patch adds a new fsck error ID `badReftableTableName` and includes tests that verify the check catches both malformed table names and incorrect extensions. The implementation follows the pattern established in v1 feedback, using relative paths in error messages and maintaining reftable's independence from Git internals.

This appears to be a well-structured addition to the reftable validation system, with clear error reporting and thorough test coverage. The changes are focused and maintainable, building toward the series' goal of comprehensive reftable integrity checking.
