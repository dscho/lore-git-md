This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems introduced in Git 2.51 when reference updates switched to batched transactions. The series fixes two key issues in the files backend: (1) incorrect error handling for case conflicts between references (e.g. refs/heads/foo vs refs/heads/Foo), now properly returning REF_TRANSACTION_ERROR_CREATE_EXISTS rather than aborting the entire transaction, and (2) a filesystem lock leak during file/directory case conflicts (e.g. refs/heads/foo vs refs/heads/Foo/bar) through case-folding checks during availability verification.

Karthik Nayak's latest patch modifies `lock_raw_ref()` in refs/files-backend.c to lowercase reference names when checking for conflicts on case-insensitive filesystems, enabling proper F/D conflict detection in `refs_verify_refnames_available()` without leaking filesystem details. Junio Hamano's review requests stronger justification for how lowercasing solves F/D conflicts and provides a test case demonstrating a D/F conflict scenario (Foo/bar vs foo) that fails on macOS CI, suggesting the solution may need refinement. The test addition complements Karthik's earlier test for the inverse F/D case (foo/bar vs Foo), with Junio indicating the current implementation may not fully address all directory/file case conflict permutations while not rejecting the technical approach outright.

The change uses STRING_LIST_INIT_DUP for proper string handling and maintains the partial-update behavior where non-conflicting refs remain unchanged. Test coverage in t/t5510-fetch.sh verifies the fix by creating repositories with conflicting cases ('foo/bar' and 'Foo', 'Foo/bar' and 'foo'), confirming fetch fails with refname conflict while preserving existing references. The change affects `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`, with user-facing warnings in `builtin/fetch.c` recommending reftable migration.

Patrick Steinhardt previously reviewed the technical approach, suggesting refinements: moving command context in commit messages, using `string_list_append_nodup()` with `strbuf_detach()` for memory efficiency, and improving warning message attribution. Karthik acknowledged these points, with Patrick clarifying formal credit wasn't necessary though a "Helped-by" tag will be added. The first patch addressed F/D conflicts through case-folding checks in refs/files-backend.c, preventing lock file leaks during transaction aborts, which Patrick confirmed as sound while suggesting documentation improvements. Chris Torek noted a commit message wording issue ("intimated" -> "informed") that was addressed in a follow-up exchange where Karthik agreed to the change.

Technical changes span refs/files-backend.c transaction handling, case-folding checks, and error messaging in builtin/fetch.c, with comprehensive test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh.
