This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems from Git 2.51's switch to batched transactions. Karthik Nayak's patch series (now at v4) provides comprehensive fixes for the files backend, handling four key problems: (1) direct case collisions (foo vs Foo), (2) file/directory conflicts (foo vs Foo/bar), (3) directory/file conflicts (Foo/bar vs foo), and (4) pre-existing lock file conflicts, with proper error reporting while allowing non-conflicting updates to proceed.

The first patch of v4 series focuses on direct case collisions, introducing a new error type `REF_TRANSACTION_ERROR_CASE_CONFLICT` and modifying `lock_raw_ref()` in refs/files-backend.c to detect these conflicts using the helper `transaction_has_case_conflicting_update()`. The solution fails only conflicting operations while allowing non-conflicting updates to proceed, with user warnings recommending reftable backend migration. Comprehensive test coverage in t1400-update-ref.sh and t5510-fetch.sh verifies case conflict detection, partial update success, reftable backend behavior, and warning messages.
