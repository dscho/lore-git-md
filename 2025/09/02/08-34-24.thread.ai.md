This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems introduced in Git 2.51 when reference updates switched to batched transactions. The series fixes two key issues in the files backend: (1) incorrect error handling for case conflicts between references (e.g. refs/heads/foo vs refs/heads/Foo), now properly returning REF_TRANSACTION_ERROR_CREATE_EXISTS rather than aborting the entire transaction, and (2) a filesystem lock leak during file/directory case conflicts (e.g. refs/heads/foo vs refs/heads/Foo/bar) through case-folding checks during availability verification.

Karthik Nayak's latest patch modifies error handling in `lock_raw_ref()` to properly handle case conflicts while allowing partial application of non-conflicting references. The change affects `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`, preserving the first conflicting reference while rejecting case-variant updates. User-facing warnings in `builtin/fetch.c` explain the limitation and recommend reftable migration. Test coverage in `t/t1400-update-ref.sh` verifies the new partial-update behavior.

Patrick Steinhardt's review confirmed the technical approach but suggested several refinements: moving command context earlier in commit messages, using `string_list_append_nodup()` with `strbuf_detach()` for memory efficiency, expanding tests to cover preexisting refs and reftable behavior, and improving warning message attribution. Karthik acknowledged these points for the next version, with Patrick clarifying in a follow-up that formal credit for the warning text suggestion wasn't necessary, though a "Helped-by" tag will be added. This exchange confirms the warning text will remain technically unchanged while properly attributing contributions.

The series' first patch addressed F/D conflicts through case-folding checks in refs/files-backend.c, preventing lock file leaks during transaction aborts. Patrick confirmed this solution as sound while suggesting similar documentation and test improvements. Chris Torek previously noted a minor commit message wording issue ("intimated" -> "informed") that was addressed.

Technical changes span refs/files-backend.c transaction handling, case-folding checks, and error messaging in builtin/fetch.c, with comprehensive test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh. The thread maintains focus on files-backend solutions while consistently recommending reftable migration as the long-term solution for case-insensitive environments. The implementation provides graceful handling of both case conflicts and F/D conflicts while preserving transaction semantics.
