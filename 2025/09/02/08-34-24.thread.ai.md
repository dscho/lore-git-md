This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems introduced in Git 2.51 when reference updates switched to batched transactions. The series fixes two key problems in the files backend: (1) incorrect error handling for case conflicts between references (e.g. refs/heads/foo vs refs/heads/Foo), now properly marked as REF_TRANSACTION_ERROR_CREATE_EXISTS rather than aborting the entire transaction, and (2) a filesystem lock leak during file/directory case conflicts (e.g. refs/heads/foo vs refs/heads/Foo/bar) by implementing proper case-folding checks during availability verification.

The first patch modified the error type returned from `lock_raw_ref()` to `REF_TRANSACTION_ERROR_CREATE_EXISTS` when case conflicts are detected, allowing batched updates to reject just the conflicting reference while applying others. It included enhanced error messaging in builtin/fetch.c warning case-insensitive users about the limitation and suggesting migration to reftable, with test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh.

The second patch completes the solution by addressing file/directory conflicts through modifications to `refs/files-backend.c`, lowercasing reference names when checking for F/D conflicts on case-insensitive filesystems. This prevents lock file leaks during transaction aborts by implementing case-folding at the files-backend level while maintaining backend separation. The patch adds a test case in t/t5510-fetch.sh verifying clean failure with appropriate error messages when fetching conflicting references (foo/bar and Foo) into a case-insensitive repository, using `STRING_LIST_INIT_DUP` for proper memory management of lowercased strings.

The series collectively provides graceful handling of both case conflicts and F/D conflicts during batched reference updates on case-insensitive filesystems, while maintaining backward compatibility and continuing to recommend reftable migration as the long-term solution that avoids these filesystem-specific issues entirely. Key technical changes span refs/files-backend.c transaction handling, case-folding checks, and error messaging in builtin/fetch.c, with comprehensive test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh.
