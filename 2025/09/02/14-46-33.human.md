This is a follow-up to a bug report about `git fetch` lock errors on ARM64 macOS. The original report described failures when fetching from an Azure Pipelines repository, with Git 2.51.0 creating spurious lock files for references under `refs/remotes/origin/users/`.

Kristoffer Haugsbakk identifies a potential cause: case-sensitivity issues in the reference names. They show that the repository contains two similar refs differing only in case (`sqlServerModuleImportM146` vs `sqlservermoduleimportM146`), which could explain the locking conflict when using the default filesystem-based ref storage. The suggestion is to try cloning with `--ref-format=reftable` to avoid filesystem case-sensitivity problems.

This appears to be a plausible explanation for the original issue, though it's unclear if this fully accounts for the regression between Git 2.50.1 and 2.51.0. The reftable suggestion offers a practical workaround while the underlying filesystem case-sensitivity issue remains to be investigated.
