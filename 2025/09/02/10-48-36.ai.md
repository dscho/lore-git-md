Packfile store refactoring (11/15): introduces packfile loading helper

This patch continues Patrick Steinhardt's series to separate packfile management from the object database by introducing a new `packfile_store_load_pack()` function. The function consolidates the common pattern of checking if a packfile exists in the store, loading it if not, and adding it to the store - replacing several manual implementations of this logic.

The key technical changes are:
- New `packfile_store_load_pack()` function that handles the packfile existence check, loading, and store addition in one operation
- Updates callers in fast-import.c, index-pack.c, midx.c, and packfile.c to use the new helper
- Maintains identical behavior while reducing code duplication
- Handles the packfile path conversion from .idx to .pack internally
- Preserves all existing error handling and edge cases

The patch follows the series' established pattern of mechanical refactoring while maintaining external behavior. It builds on previous work that moved packfile management to the packfile store, with this being the first new function added to the store's API rather than just migrating existing functionality.

Affected files:
- packfile.[ch] (new function implementation and declaration)
- builtin/fast-import.c (simplified pack registration)
- builtin/index-pack.c (removed manual pack store addition)
- midx.c (eliminated manual pack path manipulation)
- packfile.c (streamlined pack preparation logic)

The changes are straightforward and well-contained, with no test modifications needed since this is purely a code organization improvement. The patch continues the series' steady progress toward fully separating packfile management from the object database.
