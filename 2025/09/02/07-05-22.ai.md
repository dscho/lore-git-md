Refactoring and bugfix for reftable fsck validation. This is patch 2/5 in Karthik Nayak's series adding comprehensive fsck checks for reftable stack integrity, following up on Shejialuo's v1 review feedback.

The patch introduces the core infrastructure for reftable fsck validation while maintaining the reftable library's independence from Git internals. It adds:
- New `reftable/fsck.c` and `reftable/reftable-fsck.h` files providing the validation entry point `reftable_fsck_check()`
- Glue code in `refs/reftable-backend.c` to map reftable errors to Git's fsck system
- A specific check for validating reftable table names in `tables.list` with new error `badReftableTableName`
- Test cases in `t0614-reftable-fsck.sh` verifying the table name validation

Key technical details:
- Uses callback pattern (`reftable_fsck_report_fn`, `reftable_fsck_verbose_fn`) to keep reftable library independent
- Validates table names match expected format (hex min/max hashes with `.ref` extension)
- Distinguishes between malformed names (`invalid reftable table name`) vs bad extensions (`invalid reftable table extension`)
- Handles both main and worktree backends
- Includes verbose output when requested via fsck options

The implementation cleanly separates concerns between Git's fsck infrastructure and reftable internals while providing the first concrete validation check. This sets up the framework for subsequent patches to add more checks (stack count, newlines, update indexes) while maintaining the same architectural approach.
