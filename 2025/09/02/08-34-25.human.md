Bugfix for case-insensitive filesystem reference handling. This is the first of two patches addressing issues with batched reference updates on case-insensitive filesystems, a regression introduced in Git 2.51.

The patch fixes how the files backend handles reference name collisions (e.g. refs/heads/foo vs refs/heads/Foo) by changing the error type from REF_TRANSACTION_ERROR_GENERIC to REF_TRANSACTION_ERROR_CREATE_EXISTS when locking fails due to case conflicts. This allows batched updates (used by fetch, receive-pack, and update-ref --batch-updates) to reject just the conflicting references rather than failing the entire transaction.

The change means that on case-insensitive systems, the first reference in a batch will now succeed while subsequent case-colliding references are rejected, rather than either silently overwriting (pre-2.51 behavior) or failing completely (current behavior). The patch also adds user-friendly messaging about the limitation and suggests migrating to the reftable backend as a solution.

Test cases are added to verify the new error handling behavior. The fix is focused and well-explained, with clear motivation from real-world regression reports. This appears to be a solid improvement to a known pain point for users on case-insensitive filesystems.
