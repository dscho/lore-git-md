This is a follow-up in the ongoing discussion about Meson build system integration for Git's GUI components (gitk and git-gui). Patrick Steinhardt clarifies his earlier comments about architectural tradeoffs between Meson's `subproject()` and `subdir()` approaches in response to Junio Hamano's questions.

Steinhardt explains the key technical distinction: `subproject()` allows standalone builds of gitk/git-gui but requires specific directory placement, while `subdir()` would permit flexible source locations but eliminate standalone build capability. He defends the current `subproject()` choice as the better fit despite requiring directory reorganization, noting this was a one-time change that incidentally helps clean up Git's top-level directory structure.

The email reinforces that this is fundamentally a Meson limitation rather than an ideal design, but argues the practical benefits outweigh the costs. Steinhardt acknowledges Junio's architectural concerns but maintains the current approach is the most workable solution given Meson's constraints. The discussion remains open-ended, with Steinhardt leaving the door open to reconsider if this proves problematic, while clearly stating his preference for the implemented solution.
