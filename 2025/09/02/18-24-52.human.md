Performance optimization for `git describe`'s depth computation, building on recent security-hardened hash discussions.

René Scharfe follows up on the khash vs commit-slab performance comparisons with a concrete implementation using `oidset` to track unflagged commits in `git describe`'s depth calculation. This replaces both the original quadratic scan and the khash approach discussed earlier, providing a 40% speedup over the previous version (1.4x faster in benchmarks) while maintaining security properties.

The patch cleverly avoids the need for a dedicated object flag by using an oidset to track which commits in the queue still need processing. This preserves all flag bits for tag selection while eliminating the worst-case O(N^2) behavior when checking remaining commits. The implementation handles all edge cases around queue manipulation and flag propagation, with Jeff King credited for suggesting the oidset approach.

This appears to be a well-considered optimization that addresses both performance and code complexity concerns raised in the ongoing thread. The benchmarks show substantial real-world improvement, and the use of the standard oidset type (rather than custom khash) aligns with Git's existing patterns. The patch is cleanly separated from the security hardening work on `oidhash()` but will benefit from those improvements when they land.
