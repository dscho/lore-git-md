Thread identity: Bug report about `git ls-remote` failing in container-mounted worktrees, reported by Cristian Dinu.

Core problem: `git ls-remote` incorrectly fails with "not a git repository" when run in a container where a Git worktree is mounted read-only. The command validates the local worktree's gitdir (which points to an inaccessible host path) rather than operating purely on the explicitly provided remote URL.

Current status: Unresolved bug affecting Git 2.51.0, with clear reproduction case provided.

Key technical details:
- Reproduction involves creating a bare repo with worktree, mounting just the worktree into container
- Fails because gitdir path validation checks host filesystem location
- Affects Ansible git module workflows
- Suggestion to skip local repo checks when remote URL provided

Open questions:
- Should `git ls-remote` skip local repo validation when remote URL given?
- Need to confirm behavior with current Git versions
- Potential fix path needs discussion
