This is a continuation of the discussion about Meson build system integration for Git's GUI components (gitk and git-gui), specifically addressing architectural concerns about source organization.

Patrick Steinhardt clarifies the technical distinction between Meson's `subdir()` and `subproject()` approaches in response to Junio Hamano's questions about the architectural implications. The current implementation uses `subproject()` which requires moving gitk/git-gui to a specific subdirectory but enables standalone builds, while `subdir()` would allow flexible placement but remove standalone build capability. Steinhardt argues the current approach is preferable despite requiring directory restructuring, viewing it as a one-time cost that also helps clean up Git's top-level directory structure.

The email reveals the core tension between maintaining Git's traditional source organization versus adapting to Meson's build system requirements. Steinhardt acknowledges this is a Meson limitation but considers the tradeoff acceptable given the benefits. He also hints at broader source reorganization possibilities (like moving code to lib/) that could make the architectural changes more palatable. The discussion remains unresolved on whether this represents an appropriate direction for the project, with Steinhardt defending the practical benefits while Junio's architectural concerns about build systems dictating source structure remain unaddressed.
