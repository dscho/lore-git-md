A bug report describes `git fetch` failing with lock errors on ARM64 macOS (Darwin 24.6.0) when fetching from a Microsoft Azure Pipelines repository, specifically under `refs/remotes/origin/users/`. The issue appears in Git 2.51.0 but not in 2.50.1, suggesting a regression. 

Kristoffer Haugsbakk identified a likely root cause: case sensitivity conflicts in the repository's reference storage. The repository contains references with similar names but different casing (`sqlServerModuleImportM146` vs `sqlservermoduleimportM146`), which can cause problems on case-insensitive filesystems. This explains the lock file creation failures, as Git's reference handling may conflict with the filesystem's case-insensitive behavior. 

The suggested workaround is to use the reftable backend instead of files-based storage, which case sensitivity isn't an issue. While this doesn't yet explain why the behavior changed between Git 2.50.1 and 2.51.0, it provides a clear diagnostic path forward. The presence of duplicate references with different casing is itself problematic and worth addressing regardless of the regression.
