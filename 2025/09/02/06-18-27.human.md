This is a user-facing feature request regarding the deprecation of `git whatchanged`. The author argues that the current alternative (`git log --raw`) is unintuitive when trying to see what changed in commits, and suggests that if `git whatchanged` is to be removed, it should be replaced with a more logical `git log --whatchanged` option instead.

The email is brief and doesn't provide much technical detail, but makes a straightforward usability argument. The request appears to be motivated by personal workflow preferences rather than any deeper technical rationale. The tone is polite but the argument is somewhat underdeveloped - there's no discussion of why `--raw` is problematic beyond it being "not logical," nor any exploration of potential implementation challenges for the proposed alternative.

This seems like a minor ergonomic request that might appeal to users who still rely on `git whatchanged`, though it's unclear how widespread this need is. The Git project has generally been moving away from `whatchanged` in favor of `log` with `whatchanged` documentation noting it's essentially the same as `git log --raw --no-merges --pretty=oneline`.
