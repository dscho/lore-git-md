Thread identity: Discussion about deprecating `git whatchanged` and improving its replacement in `git log --raw`, initiated by a user concerned about UX of the transition path.

Core problem: The standalone `git whatchanged` command is being deprecated in favor of `git log --raw`, but this transition path presents discoverability and intuitiveness issues. While `--raw` is the direct functional equivalent, its name doesn't clearly communicate the "what changed" functionality that users associate with the standalone command.

Current status: Junio C Hamano has confirmed `--raw` as the current recommended alternative to `whatchanged`, while acknowledging it may not be the most intuitive choice. The deprecation timeline remains unspecified. Alternative output formats exist (`--name-only`, `-p`, `--compact-summary`) for different detail levels, with Hamano personally preferring `--compact-summary`.

Key technical details:
- `git log --raw` produces output compatible with `whatchanged`
- Other format options available depending on user needs (`--name-only` for just filenames, `-p` for patches, `--compact-summary` for concise changes)
- The core functionality is preserved across these options

Open questions:
- Whether to implement `--whatchanged` as an alias for `--raw` in `git log` to improve discoverability (original proposal not directly addressed)
- How to better document/signpost the transition path for users
- Whether the deprecation should proceed without a more intuitive alternative name

Participant positions:
- Original poster raised UX concerns about the `--raw` transition path
- Junio C Hamano maintains neutral stance, explaining current technical rationale while acknowledging UX shortcomings
- No other participants have weighed in yet on the specific proposal
