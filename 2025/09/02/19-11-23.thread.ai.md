Gitweb security fix thread summary:

Subject: [PATCH] gitweb: prevent command-line injection via user-controlled parameters

Core problem: Gitweb's Perl code passes user-provided input (from URLs) directly to Git commands without proper argument separation, allowing malicious users to inject arbitrary Git command-line options by crafting special URLs. Demonstrated vulnerability where `hpb=--output=/tmp/pwned` creates arbitrary files.

Solution: Systematically add `--end-of-options` before any user-provided input in Gitweb's Perl code, leveraging Git's existing `--end-of-options` feature (introduced in 51b4594b40) to safely delimit where options end and arguments begin.

Affected areas: All Gitweb operations that spawn Git subprocesses with user-controlled input, including blob viewing, diff generation, blame, and archive creation. Changes follow consistent pattern of inserting `--end-of-options` before parameters from URL query strings.

Status: Initial patch from Moritz Sanft (reporter) addressing a real security vulnerability. The changes are mechanical but comprehensive across Gitweb's Git command invocations. Commit message clearly explains both vulnerability and solution approach.

Technical details: Patch modifies multiple Gitweb.pm subroutines that interface with Git commands, particularly focusing on parameters derived from URL query strings (hpb, hash_base, file_name, etc.). Each modification follows same safety pattern of inserting `--end-of-options` delimiter.

Open questions: None raised yet - appears to be a straightforward security fix. May need review from Gitweb maintainers (typically Junio Hamano and other regular contributors) to confirm completeness of the fix.
