Gitweb security fix thread summary:

Subject: [PATCH] gitweb: prevent command-line injection via user-controlled parameters

Core problem: Gitweb's Perl code passes user-provided URL parameters directly to Git commands without proper argument separation, allowing command-line injection. Demonstrated vulnerability where `hpb=--output=/tmp/pwned` creates arbitrary files.

Solution: Systematically add `--end-of-options` before user-controlled input in Gitweb's Git command invocations, using Git's existing `--end-of-options` feature (51b4594b40) to safely delimit options from arguments.

Affected areas: All Gitweb operations spawning Git subprocesses with user input - blob viewing, diffs, blame, archives. Changes follow consistent safety pattern across Gitweb.pm.

Status: Initial patch from Moritz Sanft identified vulnerability. Taylor Blau provided comprehensive fix adding `--end-of-options` protection throughout Gitweb. Eric Sunshine contributed minor typo fix ("agains" -> "against") in commit message, indicating technical consensus on approach.

Technical details: Patch modifies multiple Gitweb.pm subroutines handling URL parameters (hpb, hash_base, file_name etc.). Each modification inserts `--end-of-options` before user-controlled input when spawning Git commands.

Open questions: None remaining - typo fix was last outstanding issue. Patch appears ready for merging pending final maintainer review.
