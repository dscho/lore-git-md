This thread addresses problems with batched reference updates on case-insensitive filesystems, which were introduced in Git 2.51 when reference updates switched to batched transactions. The series provides two key fixes for the files backend.

First, it corrects error handling for case conflicts between references (like refs/heads/foo vs refs/heads/Foo), now properly marking them as REF_TRANSACTION_ERROR_CREATE_EXISTS rather than aborting the entire transaction. This allows other non-conflicting references in the batch to proceed. The implementation includes improved error messaging in fetch operations, warning users about the limitation and suggesting migration to reftable.

The latest patch completes the solution by addressing file/directory conflicts (like refs/heads/foo vs refs/heads/Foo/bar). It modifies the files backend to lowercase reference names when checking for these conflicts, preventing lock file leaks that previously occurred during transaction aborts. The fix maintains backend separation by handling case-folding at the files-backend level rather than modifying shared utilities.

Test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh verifies both types of conflicts are now handled cleanly, with transactions failing gracefully while preserving existing references. The series maintains backward compatibility while providing a clear path forward via reftable, which doesn't suffer from these case-sensitivity issues.
