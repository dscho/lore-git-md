This thread addresses batched reference update issues on case-insensitive filesystems, a problem introduced in Git 2.51 when reference updates switched to batched transactions. Karthik Nayak's patch series fixes four key problems in the files backend: direct case collisions, file/directory conflicts, directory/file conflicts, and pre-existing lock file conflicts. The solution properly reports conflicts while allowing non-conflicting updates to proceed.

The technical implementation modifies core refs handling code to add case-folding checks and distinct error codes for different conflict types. Patrick Steinhardt has provided thorough review feedback throughout the series, driving refinements in error handling, test coverage, and documentation. His latest review approves patch 2/4 with only a trivial style suggestion, indicating the technical content is solid. Junio Hamano has also reviewed the complete solution, which affects several Git commands that perform batched reference updates.

While the reftable backend remains the preferred long-term solution for case-insensitive systems, this series provides comprehensive fixes for the current files backend. All patches maintain the key invariant that non-conflicting updates proceed while conflicts are properly identified, with the series now nearing final approval after addressing all reviewer feedback.
