This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems introduced in Git 2.51 when reference updates switched to batched transactions. The series fixes two key problems in the files backend: incorrect error handling for case conflicts between references, and filesystem lock issues during file/directory case conflicts.

Karthik Nayak's patches modify the files backend to properly handle these cases, with Patrick Steinhardt providing thorough reviews. The first patch ensures case conflicts (like refs/heads/foo vs refs/heads/Foo) are properly marked as errors rather than aborting the entire transaction. The second patch, currently under discussion, addresses file/directory conflicts (like refs/heads/foo vs refs/heads/Foo/bar) by implementing case-folding checks to prevent lock file leaks.

Patrick has confirmed the technical approach of the second patch is sound but suggests some optimizations around memory allocation and additional test coverage for preexisting refs with case differences. The existing tests in t/t5510-fetch.sh already demonstrate correct behavior by showing only one reference remains after a conflict. Throughout the thread, there's consensus that while these fixes improve the files backend, migrating to the reftable backend remains the better long-term solution for case-insensitive filesystems.
