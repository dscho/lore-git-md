This thread addresses batched reference update issues on case-insensitive filesystems, specifically problems introduced in Git 2.51 when reference updates switched to batched transactions. The series fixes two key problems in the files backend: incorrect error handling for case conflicts between references and filesystem lock leaks during file/directory case conflicts. Karthik Nayak's latest patch modifies the reference locking mechanism to lowercase names when checking for conflicts, which Junio Hamano initially reviewed positively while requesting stronger justification.

His test fails on macOS, showing the need for further refinement. The test complements Karthik's earlier verification of the inverse case (foo/bar vs Foo), providing concrete evidence of remaining edge cases rather than just theoretical objections.
