This thread addresses batched reference update issues on case-insensitive filesystems, a problem introduced in Git 2.51 when reference updates switched to batched transactions. Karthik Nayak's patch series fixes three key problems in the files backend: direct case collisions, file/directory conflicts, and directory/file conflicts, ensuring proper conflict reporting while allowing non-conflicting updates to proceed.

The latest iteration refines error handling in `lock_raw_ref()` and `ref_transaction_maybe_set_rejected()`, incorporating Patrick Steinhardt's review feedback. Key improvements include better documentation of validation list behavior and more precise error type usage for directory/file conflicts. An edge case involving leftover lock files was identified during review, prompting Karthik to add test coverage and update the commit message to document this behavior.

The changes affect core reference transaction logic used by `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`. The implementation maintains the existing behavior of skipping problematic refs while processing others, now with more accurate error classification. With Junio Hamano having reviewed the edge case handling and Patrick Steinhardt's feedback addressed, the series appears ready for merging, with the final test and documentation updates being the remaining items. The thread consensus recommends the reftable format as the long-term solution for these case-sensitivity issues.
