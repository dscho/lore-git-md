This is the final patch in Karthik Nayak's v2 series adding fsck validation for reftable stack consistency. The patch introduces a check that verifies reftable update indices are sequential across tables in the stack.

The validation ensures that each table's update index (encoded in its filename) follows the previous table's index, catching cases where tables are out of order or have inconsistent numbering. The implementation adds a new `REFTABLE_FSCK_ERROR_UPDATE_INDEX` error type and corresponding `badReftableUpdateIndex` message, following the same pattern as previous checks in the series.

The patch includes two test cases that verify detection of both inter-table and intra-table index inconsistencies by manually manipulating table names in the stack. Like the rest of the series, this maintains a clean separation between Git's fsck infrastructure and reftable internals.

This completes the initial set of basic stack integrity checks, though the commit notes that future work will add validation for table internals (matching indices between filenames and table headers). The implementation appears thorough and well-tested, continuing the careful approach seen throughout the series.
