This is part 3/5 of Karthik Nayak's reftable fsck validation series, focusing on stack integrity checks. The patch adds validation to ensure the number of reftable files on disk matches what's recorded in 'tables.list'.

The implementation counts files in the reftable directory (excluding 'tables.list' itself) and compares against the stack's recorded length. A mismatch triggers a new 'badReftableStackCount' fsck error. The change follows the series' pattern of keeping reftable validation independent from Git internals while integrating with Git's fsck framework.

Test coverage verifies both the happy path and the error case where an extra table is manually added to the directory. This continues the series' thorough approach to testing, with clear error messages that help diagnose issues. The patch appears well-contained and builds logically on the previous table name validation work.
