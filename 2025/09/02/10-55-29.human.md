This is a technical follow-up in the ongoing discussion about spurious lock file errors during fetches in bare repositories. Patrick Steinhardt responds to Jeff King's observations about cgit compatibility with the reftable backend.

The key point clarifies that older Git versions should still recognize reftable-formatted repositories due to backward compatibility measures (like the dummy HEAD value), even if they can't actually read the refs. If cgit fails to detect the repository entirely, this would indicate a bug in reftable's compatibility layer rather than just missing functionality.

The exchange maintains the thread's technical focus while narrowing the specific issue with cgit - it's not just about cgit being unable to read reftable refs (which would be expected for an old version), but potentially failing at the more basic level of repository detection. This distinction could help guide future debugging if the reftable team needs to investigate the compatibility layer.
