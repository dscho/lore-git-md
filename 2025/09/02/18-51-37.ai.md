Security discussion thread continuation regarding hash collision vulnerabilities in Git's data structures.

This email continues the security-focused discussion about hash collision resistance in Git's internal data structures, specifically responding to Jeff King's proposed hardening of the `oidhash()` function. - Jeff King's proposed patch XORs an additional 32 bits for more entropy
- René observes minimal performance impact from the change (within noise levels)
- Raises fundamental limitation: deterministic mixing can be reverse-engineered by attackers
- Proposes alternative approach using runtime-randomized bit selection masks
- Security implications extend beyond `git describe` to all khash-based operations

The discussion has evolved from performance optimization to hardening against deliberate collision attacks, with both participants contributing concrete technical analysis.
