This is patch 4/15 in Patrick Steinhardt's series refactoring packfile storage by moving packfile-specific state from `struct object_database` to the new `struct packfile_store`. The patch relocates the packfile hashmap that tracks loaded packfiles by their paths.

The key changes are:
- Moves the `pack_map` hashmap from `struct object_database` to `struct packfile_store` (renamed to just `map`)
- Makes the comparison function `pack_map_entry_cmp()` static since it's now only used within packfile.c
- Updates all references to use the new location (`objects->packfiles->map` instead of `objects->pack_map`)
- Initializes and clears the map in the packfile store's lifecycle functions
- Maintains identical functionality while changing only the storage location

The patch follows the series' pattern of cleanly separating packfile concerns from the generic object database infrastructure. It touches the same core files as previous patches (packfile.c/h, odb.c/h) and updates midx.c which needs to access the pack map. No behavior changes are introduced - this is purely an internal code organization improvement.

This continues the architectural goal of enabling pluggable ODB backends by keeping packfile-specific state together. The changes are straightforward and mechanical, similar in nature to the previous patches in the series. All references to the map are updated consistently, and the patch maintains the existing functionality while improving code organization.
