This is part 4/5 of Karthik Nayak's reftable fsck validation series, focusing on stack integrity checks. The patch adds validation for a trailing newline in the reftable `tables.list` file, which the backend expects but doesn't currently verify.

The change introduces a new fsck check that detects when `tables.list` lacks a trailing newline, treating this as a sign of potential manual tampering. The implementation reads the last character of the file to verify it's a newline, reporting the error through the existing reftable fsck infrastructure with a new `REFTABLE_FSCK_ERROR_STACK_LIST_MISSING_NEWLINE` error code and corresponding `badReftableStackListNewline` message ID.

The patch follows the series' established pattern of keeping reftable validation independent from Git's core fsck implementation while providing clear error messages. It includes thorough test coverage that verifies both the happy path and the error case where the newline is missing. This continues the series' trend of well-contained, focused validations that incrementally improve reftable's robustness.
