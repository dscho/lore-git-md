This thread addresses a security vulnerability in Gitweb that could allow command-line injection attacks through specially crafted URLs. The patch systematically adds `--end-of-options` markers before any user-provided input in Gitweb's Perl code to prevent malicious input from being interpreted as Git command-line options.

The vulnerability, reported by Moritz Sanft, could allow attackers to inject arbitrary Git options - demonstrated by an example where a crafted parameter like `hpb=--output=/tmp/pwned` could create arbitrary files. The fix leverages Git's existing `--end-of-options` feature to safely delimit where options end and arguments begin.

The changes are comprehensive, covering all major Gitweb operations that spawn Git subprocesses with user-controlled input - including blob viewing, diffs, blame, and archive creation. While the changes are mechanical (following the same pattern of inserting `--end-of-options` before potentially unsafe parameters), they address a real security risk across Gitweb's interface with Git commands. The commit message provides clear documentation of both the vulnerability and the solution approach.
