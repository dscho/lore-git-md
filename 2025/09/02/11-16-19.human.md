This is a policy discussion email in the ongoing Rust infrastructure thread, focusing on long-term maintenance implications of introducing Rust. Patrick Steinhardt responds to Junio Hamano's concerns about backporting security fixes to C versions for platforms without Rust support.

Steinhardt proposes designating the last pre-Rust Git version as an LTS release that would receive security and critical bug fixes until gccrs matures (estimated in 1-2 years). He suggests this could ease the transition while maintaining support for platforms like NonStop that currently lack Rust compilers. The email acknowledges this would require additional maintenance effort but frames it as a manageable interim solution, with potential help from platform maintainers.

The proposal represents a middle ground between Taylor Blau's position (accepting reduced portability for Rust's benefits) and Junio's concerns about unsustainable dual maintenance. Steinhardt emphasizes careful adoption, suggesting making Rust mandatory only in Git 3.0 with the previous version as LTS. This continues the thread's shift from technical implementation questions to long-term project policy decisions about platform support and maintenance models.
