This is a bug report about `git fetch` failing with a lock error in Git 2.51.0, where the same operation succeeds in Git 2.50.1. The reporter is encountering an issue when trying to fetch from a Microsoft Azure Pipelines tasks repository, specifically failing to lock a reference under `refs/remotes/origin/users/`.

The error suggests a file lock conflict, with Git detecting what appears to be another Git process running (though none actually is). The error message indicates the lock file exists for a specific remote reference path, and suggests manual removal of the lock file as a workaround. The system info shows this is occurring on an ARM64 macOS system (Darwin 24.6.0) with Git 2.51.0 built with clang 17.

Notably, this appears to be a regression from Git 2.50.1 to 2.51.0, as the same steps work in the older version. The report doesn't indicate whether the manual lock file removal workaround was attempted or successful. The bug appears complete with reproduction steps and system information, though it lacks details about whether this occurs consistently or under specific timing conditions that might suggest a race condition.
