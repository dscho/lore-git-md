This is a cover letter for a 15-patch series refactoring packfile management into a new `struct packfile_store`. The series is part of the ongoing effort to enable pluggable object databases by moving packfile-specific state out of the generic object_database structure.

The key technical changes in v3 include:
- Rebased on current master with conflicts resolved
- Added NULL assignment after freeing `o->packfiles` to prevent dangling pointers
- Added documentation for the `kept_cache` struct members
- Fixed a missing `obj_read_lock()` call in `odb_reprepare()`
- Dropped the controversial MRU list change (moved to a future series)
- Added stack variables to avoid overly long lines when accessing the packfile store
- Clarified the difference between `get_all_packs()` and `get_packed_git()`

The series systematically moves all packfile-related state and operations from `struct object_database` to the new `struct packfile_store`, including:
- Packfile lists and MRU tracking
- Packfile hashmap and initialization state
- Kept pack cache
- Related functions like `prepare_packed_git()` and `install_packed_git()`

Notable discussion points from previous versions that have been addressed:
- Memory safety in patch 2 (NULL assignment after free)
- Documentation for `kept_cache` members
- Locking issue in `odb_reprepare()`
- Naming of `install_packed_git()` vs `add_packed_git()`

Open questions still under discussion:
- The removal of convenience wrappers in patch 15 (Taylor prefers keeping them for now)
- Future MRU list handling strategy
- Final documentation updates

The changes affect packfile.c/h, odb.c/h, midx.c/h and numerous callers across the codebase. Each patch moves specific packfile state/operations to the new store while maintaining identical behavior, paving the way for future pluggable ODB backends.
