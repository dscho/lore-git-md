This is a policy discussion email in the ongoing Rust infrastructure thread, focusing on maintenance and backporting strategies for platforms without Rust support. Patrick Steinhardt responds to Junio Hamano's rhetorical questions about long-term maintenance by proposing a concrete LTS (Long-Term Support) approach for the last pre-Rust Git version.

Steinhardt suggests declaring the final major release before Rust introduction as an LTS version that would receive security and critical bug fixes until gccrs stabilizes (projected in 1-2 years). He frames this as a compromise between Rust adoption and platform support, noting it would allow impacted platforms to maintain security while the Rust ecosystem matures. The proposal includes potential distribution of backporting work to platform maintainers.

The email reveals two key technical timelines: gccrs stabilization expected in 2026 (per Pierre-Emmanuel's reference), and a possible Git 3.0 milestone for mandatory Rust dependency. Steinhardt positions this as a cautious transition path that maintains security support while allowing Rust adoption.

This response directly addresses Junio's implicit challenge about backport sustainability by offering a structured phase-out plan rather than assuming platforms will "naturally" gain Rust support. It introduces new concrete elements to the policy debate (LTS versioning, Git 3.0 milestone) while acknowledging the maintenance burden through proposed mitigation strategies. The reference to gccrs stabilization timeline provides a technical anchor for the proposed LTS duration.
