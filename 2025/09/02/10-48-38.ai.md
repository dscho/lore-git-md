Refactoring patch in Patrick Steinhardt's packfile store series, removing redundant packfile accessor function.

This is patch 13/15 in the v3 series reorganizing packfile handling. It removes `get_packed_git()` in favor of `get_all_packs()`, which provides identical functionality but with slightly more MIDX-related metadata preparation. The patch argues this is a clearer API since both functions ultimately return the same packfile list, just with different levels of MIDX metadata initialization that has negligible performance impact.

The change touches several call sites in builtin/gc.c, builtin/grep.c, and object-name.c, updating them to use `get_all_packs()`. The implementation removes the now-unused function from packfile.c and its declaration from packfile.h. This continues the series' pattern of simplifying the packfile interface while maintaining all existing behavior.

Key technical details:
- Both functions returned same packfile list
- `get_all_packs()` additionally initializes MIDX pack indices
- MIDX data was already mostly loaded by `packfile_store_prepare()`
- No test changes needed (behavior-preserving)
- Follows series' architectural goal of interface simplification

The removal of this redundant function helps clean up the packfile API surface as the series progresses toward its final goal of fully encapsulating packfile state management. This change was likely anticipated given the earlier refactoring of related functions in patches 8-11.
