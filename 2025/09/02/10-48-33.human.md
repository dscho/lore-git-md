Refactoring patch in the packfile store series. This is patch 8/15 in Patrick Steinhardt's ongoing effort to cleanly separate packfile state management from the object database. The patch renames and refactors `prepare_packed_git()` to work directly on the new `packfile_store` structure rather than taking a full repository parameter, continuing the architectural shift established in earlier patches.

The changes are mechanical but important - the function is renamed to `packfile_store_prepare()` and updated to operate on the store directly, with similar changes applied to its MRU list helper. All callers are updated to use the new interface. The behavior remains identical, but the code now better reflects the actual dependencies (the function only needs packfile store access, not the whole repository).

This follows through on the preparatory work done in patch 7's function reordering. The changes are straightforward and maintain the series' careful approach - each patch makes one logical change while keeping the external interface working. Reviewers will likely focus on whether the new function signatures properly capture the required dependencies and whether any call sites might need additional locking considerations.
