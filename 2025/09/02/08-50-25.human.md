This is a follow-up discussion about locking in Patrick Steinhardt's ongoing series to abstract packfile management into `struct packfile_store`. The exchange focuses on patch 9/16, which splits `reprepare_packed_git()` into ODB and packfile components.

Taylor Blau identified a locking inconsistency where `packfile_store_reprepare()` expects to be called under `odb_read_lock`, but the new `odb_reprepare()` function (which calls it) doesn't acquire the lock. Patrick confirms this is an oversight, noting that most Git commands don't use the ODB lock except for `git grep`. He agrees the lock should be acquired within `odb_reprepare()` rather than requiring callers to handle it.

The discussion highlights an important implementation detail in this architectural refactoring - maintaining proper synchronization between the ODB and packfile store layers. While the locking issue doesn't affect most commands today, fixing it ensures correctness for concurrent operations and future extensions. Patrick indicates he will address this in a revision.
