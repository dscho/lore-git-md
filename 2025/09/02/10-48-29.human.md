Refactoring patch in Patrick Steinhardt's packfile store series. This is patch 4/15 in the v3 series that continues moving packfile-specific state from `struct object_database` to the new `struct packfile_store`. 

The patch relocates the packfile hashmap (previously in `objects->pack_map`) to its new home in `objects->packfiles->map`. This map tracks which packfiles have already been loaded by their path names. The change includes moving the initialization and cleanup of the hashmap to the packfile store's constructor/destructor functions, and converting the comparison function `pack_map_entry_cmp()` to be static since it's now only used within packfile.c.

The changes are mechanical and behavior-preserving, following the same pattern as previous patches in the series. All references to the map are updated to use the new location, including one in midx.c that looks up packfiles. The patch continues the architectural goal of separating packfile concerns from the generic object database to eventually enable pluggable ODB backends.

This appears to be another well-executed step in the larger refactoring effort, with no obvious issues in the implementation. The series continues to make steady progress toward its goal while maintaining careful attention to detail in each incremental change.
