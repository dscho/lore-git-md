This is part 3/5 of Karthik Nayak's reftable fsck validation series, focusing on stack count verification. The patch adds a new check that ensures the number of physical reftable files matches what's recorded in `tables.list`, detecting potential corruption or manual tampering.

The implementation introduces `reftable_fsck_valid_stack_count()` which scans the reftable directory (excluding `tables.list`) and compares the file count against `st->tables_len`. A mismatch triggers the new `REFTABLE_FSCK_ERROR_STACK_COUNT` error, surfaced to Git's fsck as `badReftableStackCount`. The test in `t0614-reftable-fsck.sh` verifies this by artificially creating an extra table file.

Key technical details include: the use of direct `opendir/readdir` to maintain reftable's filesystem independence, error reporting through the established callback pattern (`reftable_fsck_report_fn`), and relative path formatting (`reftable/tables.list`) in error messages. The patch follows the series' architectural approach of keeping validation logic in `reftable/fsck.c` while exposing errors through Git's fsck infrastructure.
