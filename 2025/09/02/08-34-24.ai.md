This is a bugfix patch series addressing issues with batched reference updates on case-insensitive filesystems. The changes target the files backend's handling of case conflicts during fetch operations.

The series fixes two specific problems introduced in Git 2.51 when reference updates were changed to use batched transactions. First, it properly handles case conflicts between references (like refs/heads/foo vs refs/heads/Foo) by marking them as REF_TRANSACTION_ERROR_CREATE_EXISTS errors rather than aborting the entire transaction. Second, it fixes a filesystem lock leak that could occur when there's a file/directory case conflict (like refs/heads/foo vs refs/heads/Foo/bar) by ensuring proper case-folding checks during the availability check phase.

The patches modify the files backend's reference handling and add corresponding test cases. The first commit focuses on error type correction while the second implements the case-insensitive filesystem handling. The changes are well-motivated by a real-world regression and include tests covering both scenarios. The commit messages clearly explain the behavioral changes and reference prior discussion about the issue.
