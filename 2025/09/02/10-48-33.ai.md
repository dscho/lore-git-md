This is patch 8/15 in Patrick Steinhardt's packfile store refactoring series, continuing the structural reorganization of packfile handling code. The patch refactors `prepare_packed_git()` and related functions to operate on the new `packfile_store` structure rather than directly on a repository object, marking a key step in separating packfile management from the object database.

The changes rename `prepare_packed_git()` to `packfile_store_prepare()` and modify its signature to take a `packfile_store` parameter. Similar changes are made to the MRU (Most Recently Used) list preparation function, now called `packfile_store_prepare_mru()`. The patch updates all callers of these functions throughout packfile.c to use the new interface while maintaining identical behavior.

Key technical details include:
- The `initialized` flag moves from repository objects to the packfile store
- Packfile sorting is now done directly in `packfile_store_prepare()` rather than via a separate `rearrange_packed_git()` helper
- All packfile-related operations now go through the store's ODB pointer rather than repository objects
- The changes affect core packfile operations including MRU list management, object count estimation, and pack entry lookup

The patch builds on the foundation laid in previous patches (particularly patch 6 which completed the state migration to packfile_store) and sets up for further refactoring in subsequent patches. No test changes are needed as this is a behavior-preserving refactor. The changes maintain the series' architectural goal of cleanly separating packfile state management while keeping all existing functionality intact.
