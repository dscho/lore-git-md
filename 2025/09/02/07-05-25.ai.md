Final patch in the reftable fsck validation series, adding update index consistency checks. This implements validation that reftable table names in `tables.list` must have sequential update indices (each table's min/max range must start where the previous table left off). The patch introduces `REFTABLE_FSCK_ERROR_UPDATE_INDEX` and `badReftableUpdateIndex` error codes, with validation logic in `reftable_fsck_check()` that tracks the expected sequence using `prev_max`. Two test cases verify detection of both inter-table sequence breaks (jumping from 0003 to 0009) and intra-table violations (changing 0003 to 0002). The implementation maintains the series' architectural approach of keeping fsck logic in reftable/fsck.[ch] while integrating with Git's fsck framework via `refs/reftable-backend.c`. Notably, this check only validates the naming sequence - future work will validate the actual table contents against these indices. The tests use careful table manipulation (via lock files and sed) to simulate corruption scenarios while avoiding race conditions. This completes the v2 series' core stack integrity checks while leaving deeper table-internal validation for later work.
