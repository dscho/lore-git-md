This is a patch in the `git sparse-checkout clean` series that adds safety mechanisms matching `git clean` behavior. It's part of both the sparse-checkout feature development and the ongoing `the_repository` refactoring effort.

The patch introduces force/dry-run requirements for the `sparse-checkout clean` command, mirroring `git clean`'s safety features. It requires either `--force` or `--dry-run` unless `clean.requireForce` is disabled, preventing accidental deletions. The implementation adds corresponding options and config handling while maintaining the command's focus on removing entire directories outside the cone-mode sparse-checkout scope.

Key technical additions include:
- New `--dry-run` option showing what would be removed (using `msg_would_remove`)
- `--force` requirement matching `git clean`'s safety model
- `clean.requireForce` config option support
- Expanded test coverage verifying:
  - Force requirement enforcement
  - Dry-run output format
  - Config override behavior
  - Merge conflict handling
  - Interaction with staged/unstaged changes

The patch builds on the series' foundation while addressing feedback about safety concerns. It maintains the existing sparse index conversion behavior and directory-focused cleaning approach while adding these user-facing protections. The implementation continues the `the_repository` refactoring by using the passed `repo` parameter rather than global state.

This middle patch in the 7-part series focuses specifically on the force/dry-run behavior while leaving other aspects (like verbose output and edge case handling) to other patches in the sequence. The tests demonstrate both the new safety features and how they interact with the command's core functionality.
