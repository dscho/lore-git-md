Feature patch adding signature handling to `git fast-import`, now in its second version with all review feedback addressed. This is the second and final patch in Christian Couder's series, following the infrastructure refactoring that was already merged.

The patch introduces a `--signed-commits=<mode>` option to `git fast-import`, mirroring the signature handling capabilities already present in `git fast-export`. The implementation supports four modes for dealing with commit signatures: abort (fail on signed commits), verbatim (preserve signatures), strip (remove signatures), and warn variants that preserve while warning. The current focus is commit signatures only, with tag support planned for future work.

Review feedback from Junio Hamano and Patrick Steinhardt has been fully incorporated in this V2. Notable changes include inlining the signature handling logic rather than using a helper function, improving warning messages, and ensuring consistent parsing behavior across all modes. The implementation maintains fast-import's streaming nature while adding SHA-1 and SHA-256 signature support, with comprehensive test coverage in t9305.

The discussion thread reveals some technical nuances, like how the code handles multiple signatures (warning on duplicates rather than failing) and the removal of an unhelpful comment about "up to 2" signatures. The patch appears technically sound with all major concerns addressed, and the author has clarified that tag signature handling will come as a follow-up.

This completes the series' goal of enabling signature management during repository filtering operations, building on the shared infrastructure from patch 1/2. The work looks ready for merging, providing a useful feature for users who need to preserve or modify signatures when rewriting history through fast-import.
