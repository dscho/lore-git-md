This thread reports a case where `git apply` can misapply patches when files contain structurally similar code blocks, particularly when line numbers shift between patch creation and application. The original reporter demonstrated this with HTML components having identical button markup, where a text change meant for one component incorrectly applied to another due to matching context lines.

Junio C Hamano has responded, acknowledging the behavior but framing it as an expected limitation of patch application heuristics rather than a bug. He explains that when context lines match multiple locations (as with repeated UI patterns), patch application becomes inherently ambiguous. While suggesting wider context (via `git diff -U8`) can help, he notes there's no perfect solution since independent changes can always create new ambiguous matches. The maintainer has effectively closed this as "working as designed," though he suggests detecting and warning about ambiguous applications could be a worthwhile future improvement.
