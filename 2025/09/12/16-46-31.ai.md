This is a bugfix patch series addressing edge cases in git-clone's bundle-URI handling. The cover letter describes two scenarios where git-clone could unnecessarily abort when receiving malformed responses from servers during bundle-URI negotiation, even though bundle-URI usage is meant to be optional.

The first patch makes git-clone ignore bundle advertisements that lack a URI field, rather than failing. The second patch prevents git-clone from aborting when it encounters invalid packet lines in the bundle-URI response. Both changes make the clone operation more resilient by allowing it to fall back to regular clone behavior when bundle-URI information is malformed.

The series includes new tests in t5558 that verify the clone operation continues properly when faced with these malformed responses. The changes are relatively small (7 lines of code) but touch both the bundle-URI parsing logic and the underlying packet line handling in connect.c. The test additions are substantial (49 lines) and appear to thoroughly exercise the new failure modes.

This appears to be a well-motivated change that improves robustness without introducing complexity - the patches simply make git-clone behave as one would expect when optional bundle-URI information is corrupted. The test coverage suggests the edge cases are properly validated.
