Bugfix proposal for Git's merge conflict detection in independent method additions.

Guo Tingsheng reports an issue where Git incorrectly flags a merge conflict when two branches add different methods at the same location in a Java class. The current behavior forces manual resolution even though the changes are semantically independent and could be automatically combined.

The report includes a clear reproduction case showing that when branch A adds an `add()` method and branch B adds a `subtract()` method at the same position in a `Calculator` class, Git reports a conflict rather than producing the expected merged file containing both methods. The author notes this behavior could negatively impact productivity in collaborative development.

This appears to be a legitimate limitation in Git's line-based merge algorithm, which currently doesn't recognize that these adjacent but independent additions could be safely combined. The report is well-structured with clear reproduction steps and expected/actual behavior, making it easy to evaluate. While the issue is specific to certain programming languages and file formats, it represents a meaningful quality-of-life improvement for developers working in those contexts.
