Feature patch adding signature handling to `git fast-import` to match `git fast-export`'s capabilities. This is the second patch in a two-part series, implementing the new `--signed-commits=<mode>` option for fast-import.

The patch introduces the same set of signature handling modes as fast-export (verbatim, strip, warn variants, and abort), though with a different default (verbatim rather than abort). The implementation builds on the shared gpg-interface infrastructure from patch 1/2, cleanly integrating with the existing fast-import parsing logic.

The tests are thorough, covering:
- All supported signature types (OpenPGP, X.509, SSH)
- All handling modes
- Both SHA-1 and SHA-256 cases
- Warning message verification
- Dual-signature handling for SHA-1/SHA-256 commits

The implementation appears solid, with careful error handling and clear warning messages. The test coverage is particularly comprehensive, giving confidence in the behavior across different signature formats and modes. The patch maintains consistency with fast-export's functionality while making the sensible choice of defaulting to verbatim rather than aborting on signatures during import.

This completes the feature parity between fast-import and fast-export for signature handling, with the shared gpg-interface code ensuring consistent behavior between the two commands. The patch is ready for review, with the remaining open questions (about synonym modes and warning verbosity) being minor design considerations rather than technical issues.
