Bugfix for git-clone's bundle-URI handling when receiving malformed server responses. This is the second patch in a series addressing edge cases in bundle-URI negotiation, complementing Patrick Steinhardt's earlier work on the same subsystem.

The patch fixes a case where git-clone would fail with "fatal: expected 'packfile'" when receiving bundle advertisements with empty or missing URIs, even though the intention was for such errors to be non-fatal. The root cause was unprocessed packet data remaining after the bundle-URI error. The solution changes the error handling in `get_remote_bundle_uri()` to continue reading packet data after invalid lines (converting the error to a warning), allowing the operation to proceed without bundle URIs.

The change is well-motivated with clear error message examples and includes two new test cases in t5558 that verify the fix for both missing and empty URI cases. The patch is small (4-line code change) but addresses a real usability issue, and the test coverage is thorough. This appears to be a straightforward improvement to the bundle-URI feature's robustness.
