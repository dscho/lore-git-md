SHA-256 transition implementation update from Brian Carlson, detailing current status and areas needing assistance for the Git 3.0 target.

Brian provides a comprehensive status update on the SHA-256 interoperability work, noting they have 93 patches in their `sha256-interop` branch with core functionality working (legacy loose object maps, pack index v3, basic push/fetch). The email outlines several concrete areas where help would be valuable: (1) polishing existing patches for submission (some marked WIP), (2) adding test coverage (especially for scale testing and compatibility mode), (3) implementing `git gc` integration for new binary loose object maps, (4) fixing numerous test suite failures in compatibility mode, and (5) developing additional protocol tests (HTTP, Git protocol variants, edge cases).

The email also identifies major unimplemented features needing attention: partial clone support, submodule handling (particularly tricky due to cross-repo hash mapping requirements), and repository conversion tools (both in-place and clone-based). Brian plans to organize remaining work into a public task list and suggests using GitHub/GitLab issues for coordination between multiple contributors. They emphasize the scale of work remaining (200-300 patches expected) and the desire to avoid last-minute large patch series.

Key technical specifics mentioned include the new binary loose object map format replacing legacy maps, pack index v3 support, and various interoperability constraints (like inability to accept broken objects in compatibility mode). The email also references ongoing work by Patrick Steinhardt on Rust integration that serves as the base for these changes. Brian confirms they'll have dedicated work time starting in October but welcomes assistance given the project's ambitious 2026 target and their other responsibilities maintaining Git infrastructure.
