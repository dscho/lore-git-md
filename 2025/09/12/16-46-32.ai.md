Bugfix for bundle-URI handling in git-clone, addressing a segmentation fault case. This is the first patch in a 2-part series (though note the author differs from the thread's original patch series).

The patch fixes a crash that occurs when a bundle advertisement contains a 'creationToken' heuristic but lacks the required 'uri' field. Currently this triggers a segfault; the patch makes Git gracefully skip such malformed entries by adding an explicit check in `fetch_bundle_uri_internal()`. The change is minimal (3 lines) but important for robustness.

A new test case in t5558 verifies the fix by creating a bundle list with the problematic configuration (creationToken present but uri missing) and confirming clone succeeds rather than crashing. The test checks that the expected bundle refs are still created despite the malformed entry.

This appears to be a straightforward, well-tested fix for a clear edge case. The patch aligns with the thread's original goal of making bundle-URI handling more resilient, though it addresses a different failure mode than Patrick Steinhardt's original series (which focused on packet line parsing). The test coverage is thorough, exercising both the error case and verifying correct ref creation.
