Bugfix report regarding `git update-ref` and pseudorefs, specifically `MERGE_HEAD`. Johannes Sixt reports a discrepancy between Git's suggested advice and actual behavior when dealing with merge operations. The commit message template suggests using `git update-ref -d MERGE_HEAD` to abort a merge, but since commit 8e4f5c2dc26e ("refs: refuse to write pseudorefs", 2024-05-15), this command fails with "refusing to update pseudoref 'MERGE_HEAD'". The same restriction prevents manually setting `MERGE_HEAD` to a specific commit, which the author found useful in some workflows.

The current workaround involves directly writing to `.git/MERGE_HEAD`, which becomes cumbersome in secondary worktrees where the path must be constructed manually. This contradicts the original intention behind b6d2558c9ea3 ("builtin/commit: suggest update-ref for pseudoref removal", 2020-08-21), which aimed to provide a backend-agnostic solution. The email raises the need to either restore the functionality or update the advice to reflect current limitations, though it doesn't propose a specific solution. The issue affects both merge abort scenarios and advanced use cases requiring manual `MERGE_HEAD` manipulation.
