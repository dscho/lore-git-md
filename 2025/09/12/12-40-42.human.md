Feature patch adding signature handling to `git fast-import` to match `git fast-export`'s capabilities. This is the second patch in a 2-part series, implementing the new `--signed-commits=<mode>` option for fast-import after the shared infrastructure was refactored in patch 1/2.

The patch adds support for the same signature handling modes as fast-export: "verbatim" (default), "strip", "abort", and warning variants of each. It properly handles both SHA-1 and SHA-256 signatures, with comprehensive tests covering OpenPGP, X.509, and SSH signature formats. The implementation appears robust, building on the refactored gpg-interface code from the first patch.

The test suite is thorough, verifying behavior across different signature types and modes, including edge cases like dual SHA-1/SHA-256 signatures. The documentation is updated to match fast-export's, though the default mode differs (fast-import defaults to "verbatim" while fast-export defaults to "abort").

This completes the symmetry between import/export signature handling that was identified as missing in the thread discussion. The implementation looks clean and well-tested, with no obvious issues. The two open design questions from the cover letter (about synonym modes and warning verbosity) remain unresolved but don't block this technically sound implementation.
