This is a feature patch in the `git sparse-checkout clean` series that adds safety mechanisms matching `git clean` behavior. It's the third patch in v3 of a 7-part series combining Victoria Dye's sparse-checkout cleaning functionality with Derrick Stolee's `the_repository` refactoring work.

The patch introduces force/dry-run requirements for the `sparse-checkout clean` command to prevent accidental deletions. Like `git clean`, it now requires `-f/--force` unless `clean.requireForce` is disabled, and supports `--dry-run` to preview deletions. The implementation includes:
- Configurable force requirements matching `git clean`'s safety model
- Dry-run mode showing what would be removed
- Documentation updates explaining the new safety features
- Comprehensive tests covering force requirements, dry-run output, and edge cases

The tests verify behavior with staged changes, merge conflicts, and various file states, ensuring the command remains safe while still being useful. This builds on the series' foundation of removing tracked-but-sparse directories while preserving untracked files and respecting in-progress work.
