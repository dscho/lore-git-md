Guo Tingsheng has reported a concerning bug in Git's merge functionality where indentation in newly added code blocks can be lost during merges. The issue occurs when merging a branch that adds properly indented code with another branch that made no changes to the same file - the merged result sometimes incorrectly strips the indentation from the new blocks. This affects both the ort and recursive merge strategies and appears to be independent of core.whitespace settings.

The problem has been observed with Java-style code blocks, though the underlying issue may affect other languages where indentation is significant. Notably, the bug manifests non-deterministically, making it particularly troublesome for teams working with strictly formatted codebases. The report includes clear reproduction steps using Git 2.43.0 on Ubuntu 24.04, though it's unclear whether the issue exists in other versions or platforms.

This appears to be a genuine merge algorithm issue rather than a configuration problem. The report provides good before/after examples but leaves some open questions about whether the problem occurs with different indentation styles (tabs vs spaces) or more complex nesting scenarios. The non-deterministic nature suggests it may be an edge case in how Git handles indentation preservation for new blocks during merges.
