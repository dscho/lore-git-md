Feature and refactoring patch series for `git sparse-checkout clean` command, now at v3. This combines Victoria Dye's original sparse-checkout cleaning functionality with Derrick Stolee's ongoing `the_repository` refactoring work in `builtin/sparse-checkout.c`.

The series introduces a new `git sparse-checkout clean` command that removes tracked-but-sparse directories outside the sparse-checkout scope, addressing performance issues caused by these directories when using sparse index. Key technical aspects include:

1. Core functionality that removes files in tracked directories outside sparse-checkout definition, including ignored/excluded files (more aggressive than `git clean`)
2. Protection against removing files with staged/unstaged changes or merge conflicts
3. Integration with `--force`/`--dry-run` options matching `git clean` behavior
4. New `--verbose` option showing files to be deleted
5. Comprehensive test coverage for edge cases including:
   - Files with unstaged changes
   - Staged sparse files
   - Merge conflict states
   - Interaction with `reapply` command
   - Verbose output behavior

Notable changes in v3:
- Removed dependency on stalled sparse-checkout globals series
- Expanded documentation to better explain file removal conditions
- Significantly enhanced test coverage
- Added note about potential future `--verbose` output enhancements
- Dropped problematic patch (v2 8/8) due to unresolvable edge cases around SKIP_WORKTREE bits and file status reporting after directory removal

The implementation now matches `git clean` behavior for force requirements while being more surgical - it removes tracked sparse files but preserves untracked files not in sparse directories. The series represents a collaboration addressing edge cases identified by Elijah Newren and others, with remaining technical challenges deferred to future work.
