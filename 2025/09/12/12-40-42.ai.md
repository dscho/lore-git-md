Feature patch implementing signature handling in `git fast-import` to match existing `git fast-export` functionality. This is the second patch in a 2-part series, building on the refactoring in patch 1/2 that moved signature mode parsing into shared gpg-interface code.

The patch adds a `--signed-commits=<mode>` option to `git fast-import` with the same modes as fast-export: "verbatim", "warn-verbatim", "warn-strip", "strip", and "abort". The default is "verbatim" (unlike fast-export's "abort"). The implementation handles both SHA-1 and SHA-256 signatures, with appropriate warning messages when configured to warn about signature handling.

Key technical details:
- New `signed_commit_mode` global in fast-import.c using the SIGN_* enum from gpg-interface
- Modified `parse_new_commit()` to handle signatures according to the selected mode
- New test file t9305-fast-import-signatures.sh with comprehensive coverage of:
  - OpenPGP, X.509, and SSH signature formats
  - All signature handling modes
  - Dual SHA-1/SHA-256 signature cases
  - Warning message verification

The implementation appears robust with thorough test coverage. The tests verify both signature preservation/stripping behavior and warning message correctness. The patch maintains consistency with fast-export's signature handling while making the default behavior more import-friendly (verbatim rather than abort).

Open design questions from the cover letter remain unresolved regarding synonym modes and warning verbosity control, but this implementation provides a complete working solution matching fast-export's current behavior. The tests specifically verify the warning variants work as expected, which may help inform the ongoing discussion about their design.
