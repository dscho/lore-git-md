This is a follow-up discussion in the feature patch series adding signature handling to `git fast-import`. The exchange focuses on implementation details of signature parsing behavior in different modes (STRIP vs ABORT) and warning message wording.

Junio C Hamano responds to Christian Couder's V2 changes, agreeing with the approach to signature parsing but suggesting a more lenient behavior in STRIP mode where malformed signatures should still be processed rather than skipped. Christian had originally optimized for speed by avoiding parsing in STRIP mode, but Junio argues that users in this mode likely want to handle problematic signatures gracefully. Christian has implemented this change in V2 while maintaining the stricter ABORT mode behavior.

The discussion also confirms Christian incorporated Junio's suggestion to add "verbatim" to the warning message about importing signatures. This appears to be the final resolution of all technical feedback on the patch, with Junio expressing satisfaction with the changes. The exchange reinforces that all review feedback has been addressed in V2, leaving only Junio's mild philosophical preference about starting with commits rather than tags as an open but non-blocking consideration.
