This is a follow-up in the ongoing discussion about Git's permissive handling of `user.email` configuration values. Randall Becker responds to usharerose's question about whether the current behavior (allowing non-email values like GitHub SSO tokens) was an intentional design choice or an emergent property that became useful later.

Randall confirms the practical use case (GitHub SSO integration using the field for tokens) but cannot speak to Git's original design intent, noting this specific customer implementation began about four years ago without requiring Git changes. The response suggests the behavior may have been discovered and utilized rather than explicitly designed for, though GitHub's role in enabling it remains unclear.

The exchange continues the thread's shift from technical considerations to historical/philosophical questions about Git's design evolution. While the technical consensus appears settled (maintaining the permissive approach), the discussion now explores whether this flexibility was deliberate or emergent - a question that may remain unanswered without input from Git's early contributors.
