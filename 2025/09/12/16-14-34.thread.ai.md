Enhanced conflict output proposal for merge/rebase operations. Author requests Git explicitly label which is "--ours" and "--theirs" during conflicts to aid resolution. Current behavior shows standard conflict markers without branch identification. Proposal would add clear branch labeling before conflict output, particularly helpful for `git checkout --ours|--theirs` commands.

Key scenarios addressed:
- Rebase: "ours" is branch being rebased onto, "theirs" is feature branch
- Merge: roles are reversed ("ours" is current branch, "theirs" is incoming changes)

Rationale: Reduces confusion in conflict resolution workflows by making branch roles explicit in output. Currently users must remember/deduce branch identities. Presented as feature request (not bug report) from Git 2.43.0/Linux user. No implementation provided yet - initial proposal stage seeking feedback.
