Bugfix for bundle-URI handling in git-clone, making it more resilient to malformed server responses. This is the second patch in a 2-part series (the first being from Patrick Steinhardt) that addresses different failure modes in bundle-URI negotiation.

The patch fixes a case where git-clone would fail with "expected 'packfile'" when receiving invalid bundle-URI data from the server, specifically when bundle advertisements contain empty or missing URI fields. Instead of erroring out, the code now continues processing by downgrading the error to a warning and reading remaining packet data. This allows the clone to proceed without bundle-URIs rather than failing entirely.

Key technical changes:
- Modifies `get_remote_bundle_uri()` in connect.c to continue reading packet data after invalid lines
- Changes error() to warning() for invalid bundle-uri response lines
- Adds two new test cases in t5558-clone-bundle-uri.sh covering:
  - Missing URI field (bundle.bundle-1.uri not set)
  - Empty URI field (bundle.bundle-1.uri="")

The patch complements Patrick's earlier work by addressing a different failure mode (protocol-level packet reading vs. graceful fallback) while maintaining the same goal of robust handling of malformed bundle-URI data. The substantial test coverage (25 new lines) verifies both edge cases. This appears to be a well-contained fix with clear motivation and thorough testing.
