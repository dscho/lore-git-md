Feature request for clearer branch identification during merge/rebase conflicts.

Darko Veberic proposes adding explicit branch identification to merge/rebase output to help users better understand which branch corresponds to `--ours` and `--theirs` during conflict resolution. Currently, when conflicts occur, Git shows which files conflicted but doesn't clearly indicate which branch is which in the conflict context.

The suggested output format would show something like:
```
Rebasing branches:
  --ours = "main"
  --theirs = "my_great_feature_branch"
```
or vice versa for merge operations. This would help users make more informed decisions when using commands like `git checkout --ours` or `git checkout --theirs` to resolve conflicts.

The proposal is well-motivated by a common pain point in conflict resolution, where users can be confused about branch identities, especially in complex workflows. The email includes clear examples of both current behavior and desired output. While not a bug fix, this would be a quality-of-life improvement for users dealing with merge conflicts. The request appears technically straightforward to implement, though it would need to be evaluated for consistency with Git's existing output conventions.
