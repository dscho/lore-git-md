Thread identity: Question about mergetool environment variables (BASE, LOCAL, REMOTE, MERGED) not being passed to custom mergetool scripts as documented, raised by Randall Becker.

Core problem: Initial report suggested documented environment variables for mergetool invocation weren't being set for custom mergetool scripts. Johannes Sixt clarified this is a documentation misunderstanding - the variables are shell variables, not environment variables, so they wouldn't appear in `env` output but should be available in the shell context. Randall Becker's follow-up confirms this understanding but notes it creates a functional difference between built-in mergetools (which get variables) and custom ones (which don't).

Current status: Behavior appears to be working as implemented but not as documented. The variables are shell variables passed to included fragments from mergetools/ directory, not exported environment variables. This means custom mergetools not packaged with Git cannot access them through the documented mechanism.

Key technical details:
- Variables in question: BASE, LOCAL, REMOTE, MERGED
- mergetool implementation uses shell variable passing for included fragments (mergetools/*)
- Variables are not exported to sub-shells (explains `env` output absence)
- Custom mergetools must work around by parsing working index files (file_BASE_num etc.)
- Reference implementations in mergetools/ directory demonstrate intended usage pattern

Open questions:
- Should documentation be updated to clarify shell vs environment variable distinction?
- Should the implementation be changed to export variables for custom tools?
- Is the current behavior (different treatment of built-in vs custom tools) intentional?

Participant positions:
- Randall Becker initially reported issue and has now confirmed understanding of implementation
- Johannes Sixt provided key clarification about shell vs environment variables
- No maintainer response yet on whether current behavior is intended

Related work: mergetools/ directory reference implementations show shell fragment inclusion pattern.
