This is the second patch in Julia Evans' documentation series improving `git-push` man page clarity, now focusing on upstream branch explanations. The patch adds a new "UPSTREAM BRANCHES" section to the shared documentation included by `git-push`, `git-pull`, and `git-fetch`, renaming the include file from `urls-remotes.adoc` to `urls-remotes-upstreams.adoc` to reflect its expanded scope. The new section consolidates scattered information about upstream branches from various man pages (`git branch --track`, glossary, and `git-config`) into one place, explaining how upstream branches are used by multiple Git commands (`status`, `pull`, `push`, `fetch`) and how they get automatically set in common workflows.

Key technical changes include documenting the upstream branch storage format in `.git/config`, listing commands that use upstream branches by default, and showing how upstreams get automatically configured during clone, first push, and branch checkout. The patch standardizes on "upstream branch" terminology despite some internal Git usage of "tracking", since this matches predominant documentation usage. The file rename preserves all existing remote/URL documentation while adding the new upstream content.

This builds on the v1 discussion where the need for better upstream documentation was identified from user research. The implementation follows the documentation style established in patch 1 (merged) with glossary cross-references, while deferring the more invasive refspec rewrite to future work. The patch addresses feedback about edge cases by including details about automatic upstream configuration scenarios and clarifying the relationship between upstream branches and various Git commands' default behaviors.
