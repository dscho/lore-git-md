This is a feature patch introducing the `git sparse-checkout clean` command, part of a series combining sparse-checkout improvements with `the_repository` refactoring. The command removes tracked-but-sparse directories outside the sparse-checkout scope, addressing performance issues where lingering sparse directories cause index expansion.

The implementation is surgical - it only removes directories that are both tracked and outside the sparse definition, while preserving untracked files not in sparse directories. The patch carefully documents edge cases where files might be retained (due to modifications, staging, or merge conflicts) and recommends follow-up steps with `reapply`. 

The current version is intentionally minimal - it lacks safety features like dry-run or force flags that will come in later patches. The tests demonstrate core functionality including handling of modified/staged files and verifying status output after cleaning. This foundational work enables more efficient sparse index operation while being more targeted than `git clean -fx`.
