This is a feature patch adding verbose output to `git sparse-checkout clean`, part of the ongoing series combining sparse-checkout cleanup with `the_repository` refactoring.

The patch introduces a `--verbose` option that shows each individual file that would be removed (with `--dry-run`) or is being removed (with `--force`), rather than just listing directories. This helps users who want to understand why certain directories are being targeted for cleanup, particularly when files remain due to ignore patterns, Windows file handles, or merge conflicts. The implementation uses a new `list_every_file_in_dir()` helper that leverages the previously introduced `for_each_file_in_dir()` function.

The change includes documentation updates explaining when the verbose output might be useful, plus test cases verifying the new output format. This builds on the series' existing safety features like `--dry-run` and `--force` options that match `git clean` behavior. The patch appears well-integrated with the rest of the series, maintaining the refactoring work to eliminate `the_repository` usage while adding this user-facing improvement.
