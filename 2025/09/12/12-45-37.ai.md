Feature patch implementing signature handling in `git fast-import` with new `--signed-commits=<mode>` option, matching existing `git fast-export` functionality. This is patch 2/2 in the series, building on the gpg-interface refactoring from patch 1/2.

The patch adds signature handling modes (verbatim, warn-verbatim, warn-strip, strip, abort) to `git fast-import`, with default behavior being "verbatim" (unlike fast-export's "abort" default). Implementation shares the core parsing logic via the refactored gpg-interface code from patch 1. The main changes are in `parse_new_commit()` to handle signatures according to the selected mode, plus command-line option parsing.

Key technical details:
- New `signed_commit_mode` global in fast-import.c using shared SIGN_* enum
- Modified signature processing in `parse_new_commit()` with switch statement for different modes
- Comprehensive test coverage in new t9305-fast-import-signatures.sh covering:
  - OpenPGP/X.509/SSH signature formats
  - All handling modes (verbatim, strip, abort etc.)
  - SHA-1/SHA-256 cases
  - Warning message verification
  - Dual-signature handling (SHA-1 + SHA-256)

The implementation appears robust with thorough test coverage. The patch maintains consistency with fast-export's signature handling while accounting for fast-import's different default needs. The thread context shows this is v2 of the series, with improvements to error handling, warning messages, and test coverage since v1. Two open design questions remain about mode naming and warning verbosity control.
