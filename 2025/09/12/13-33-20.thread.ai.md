New bug report about `git apply` incorrectly matching patches when files contain similar code blocks and line numbers shift. The reporter demonstrates a case where a patch modifying button text in a HeaderComponent gets misapplied to a structurally identical FooterComponent instead, due to line number changes and identical context lines. The issue stems from the patch application algorithm's matching heuristics failing when (1) multiple code blocks share identical structure, (2) line numbers shift between patch creation/application, and (3) context lines match multiple locations. The well-structured report includes clear reproduction steps using HTML components with identical button markup, showing expected vs actual behavior when changing text (e.g. `Click Me` -> `点击`). This appears to be a legitimate bug that could affect files with repeated patterns (UI components, configs, generated code). No prior related discussions referenced - this is a new report that merits attention from git-apply maintainers, though fixing the matching heuristics will require care to avoid new edge cases.
