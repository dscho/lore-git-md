Thread identity: Bug report about `git apply` misapplying patches when files contain structurally similar code blocks (HTML components, JavaDoc comments). Original report demonstrated with HTML button markup; follow-up shows Java method documentation case.

Core problem: The patch application algorithm can incorrectly match patches to structurally identical but semantically wrong locations when (1) multiple code blocks share identical structure, (2) line numbers shift, and (3) context lines match multiple locations. Demonstrated cases include UI components (Header/Footer with identical button markup) and JavaDoc for overloaded methods (`List<String>` vs `List<Object>` documentation swapped).

Current status: Maintainer Junio C Hamano maintains this is an expected limitation of heuristic matching. The tool cannot guarantee correct placement when context lines match multiple locations after line number shifts. Wider context (`git diff -U8`) helps but doesn't eliminate ambiguity. New example confirms problem affects real-world Java codebases through patch fragmentation workflows.

Key technical details: Issue manifests in files with repeated patterns (UI components, generated code, overloaded method docs). Problem stems from fundamental limitations in patch application heuristics when facing identical context matches, particularly when original line numbers become unreliable (e.g. when applying split patch fragments to parallel branches). Java case shows even documentation changes can be misapplied.

Open questions: Potential UX enhancement to detect/warn about ambiguous patch applications remains the most viable path forward. No current plans to modify core matching algorithm. New example strengthens case for warning system by demonstrating real-world impact in Java documentation maintenance.

Participant positions: Original reporter and Guo Tingsheng provided clear reproduction cases (HTML/Java). Junio Hamano consistently positions this as working-as-designed given inherent ambiguity. Consensus forming around value of warning system for ambiguous applications, though implementation remains a starter project idea.

Related work: No prior discussions referenced. Current thread establishes this as a known limitation affecting multiple language ecosystems (HTML templating, Java documentation) through distinct but related failure modes.
