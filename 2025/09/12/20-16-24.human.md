This is a user question about mergetool environment variables not being available as documented.

Randall Becker reports that when configuring a custom mergetool with a shell wrapper script, the documented environment variables (BASE, LOCAL, REMOTE, MERGED) are not present when the script runs. They provide a minimal test case using a simple shell script that just prints the environment and exits, showing these variables are missing during a merge conflict resolution.

The user describes seeing correct temporary files in the directory during execution, but the environment variables themselves don't appear. They note this behavior occurs in both Cygwin (Git 2.45.1) and NonStop (Git 2.51.0) environments, with a simple test repository containing a one-line conflict.

The question appears well-formed and demonstrates a clear discrepancy between documented behavior and actual behavior. The user provides enough technical detail about their setup and test case that this seems like a genuine issue rather than a configuration error. The mention of NonStop suggests this may involve platform-specific considerations, though the Cygwin case indicates it's not limited to that environment.

This looks like either a documentation bug (if the variables are no longer provided this way) or an actual bug in the mergetool invocation logic. The question is likely to interest both Git maintainers and users who rely on custom mergetool integrations.
