This is a key response in the ongoing discussion about removing `git-new-workdir` from Git's contrib directory. Junio Hamano provides the maintainer perspective on why the script should be removed despite Gabriel Scherer's arguments for keeping it based on his workflow needs.

Junio clarifies that the removal isn't primarily about lack of usage (as Scherer suggested), but rather about maintenance burden and technical debt. He explains that `git worktree` was specifically designed to replace the "hacky" `git-new-workdir` script, and that keeping the old script requires ongoing effort to maintain compatibility with core Git changes (like the recent reftable support).

The email reinforces the project's position that users should migrate to the modern `git worktree` alternative, though it doesn't directly address Scherer's specific workflow needs around remote configuration sharing that `git-new-workdir` currently handles uniquely. This maintains the impasse between the project's maintenance priorities and real-world usage patterns, with Junio's response suggesting the project is unlikely to reverse course on the removal.
