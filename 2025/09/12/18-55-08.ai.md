Documentation patch (part 3/4) in Julia Evans' series improving `git-push` man page clarity. This patch focuses on the "where to push" section, restructuring the explanation of how Git determines the target repository.

The change replaces a negative formulation ("when the command line does not specify...") with a positive step-by-step flow: Git first checks the explicit `<repository>` argument, then falls back to the branch's upstream configuration, and finally defaults to 'origin'. The content remains technically identical but presents the information more clearly by showing the actual decision path rather than describing the absence of specification.

This continues the series' pattern of making documentation more approachable while maintaining accuracy. The patch builds on the upstream branch concepts introduced in patch 2 (now approved) and follows the same style of using concrete examples (`git push dev`) to illustrate abstract concepts. The change is small but meaningful, addressing a common documentation pain point where users struggle to understand Git's fallback behavior.

Technical details remain unchanged - still referencing `branch.*.remote` configuration internally while presenting it as "upstream configuration" to users, consistent with the terminology standardization. The patch touches only the "where to push" section of git-push.adoc, leaving the subsequent "what to push" discussion (patch 4's focus) unchanged.
