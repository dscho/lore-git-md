This is the second patch in a feature series adding signature handling to `git fast-import`, now in its second version. The patch implements the actual `--signed-commits=<mode>` option after the infrastructure refactored in patch 1/2 (already merged).

The V2 changes respond to Junio's review by:
1. Removing the `import_signature()` helper function and moving its logic inline
2. Always parsing signatures (even in STRIP mode) for better code consistency
3. Keeping immediate abort behavior in ABORT mode
4. Adding "verbatim" to the warning message as suggested
5. Maintaining the warning/action pairing (WARN_VERBATIM/VERBATIM etc.)

Key technical details:
- The core change is in `parse_new_commit()` where signature handling is now controlled by the new `signed_commit_mode` enum
- Signature processing handles both SHA-1 and SHA-256 cases
- Error messages are marked for translation
- The implementation preserves fast-import's streaming nature while adding signature awareness

The patch maintains the current scope of only handling commit signatures (not tags) despite the infrastructure supporting both, as previously discussed. The changes show good responsiveness to review feedback while keeping the original design goals intact. The implementation appears solid with comprehensive test coverage in t9305.

Open questions from the thread about future directions (tag support, re-signing capabilities) remain deferred, but this version seems ready for inclusion as it addresses all raised technical concerns.
