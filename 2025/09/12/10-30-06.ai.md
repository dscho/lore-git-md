This is the foundational patch for the new `git sparse-checkout clean` command, part of a series combining sparse-checkout functionality with `the_repository` refactoring. The command removes tracked-but-sparse directories outside the sparse-checkout scope while preserving untracked files in non-sparse directories.

The implementation converts the index to a sparse index (in-memory if not already) and deletes worktree directories matching sparse directory entries. The patch carefully documents edge cases where files might be retained: modified/staged files, merge conflicts, or when SKIP_WORKTREE bits are modified. The command is more aggressive than `git clean` in removing tracked sparse files but more conservative in preserving untracked files not in sparse directories.

Key technical details include:
- New `clean` subcommand in `builtin/sparse-checkout.c`
- Core logic that walks sparse index entries and removes corresponding directories
- Documentation of edge cases and interaction with other commands
- Initial test cases covering basic functionality and staged/modified file scenarios
- The implementation currently lacks safety features (dry-run, force flags) which will come in later patches
- Requires cone mode and active sparse-checkout
- Preserves untracked files in non-sparse directories to avoid breaking editor/build tool caches

The patch establishes the core behavior while deferring more complex cases (SKIP_WORKTREE bit management, post-clean status reporting) to future work. It's part of a larger effort that also removes `the_repository` usage from sparse-checkout code.
