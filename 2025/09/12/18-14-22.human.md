This is a discussion about workflow alternatives following the planned removal of `git-new-workdir` from Git's contrib directory. The thread has established that while detached HEAD mode (suggested by Kristoffer Haugsbakk and confirmed by Junio Hamano) works for inspection workflows, Gabriel Scherer has raised concerns about its impact on active development workflows where multiple checkouts of the same branch are needed.

D. Ben Knoble suggests two alternative approaches to replace `git-new-workdir` functionality. First, using `git clone --shared` with appropriate branch options, possibly aliased for convenience. Second, maintaining a personal copy of the script outside the Git distribution. These suggestions aim to minimize workflow disruption while respecting the project's decision to remove unmaintained contrib scripts.

The email highlights the ongoing tension between the project's cleanup efforts and real-world developer workflows. While the technical removal is proceeding, there remains active discussion about practical alternatives for users who relied on the script's unique behavior (allowing multiple same-branch checkouts, which `git worktree` intentionally prohibits). The suggestions offered represent pragmatic workarounds rather than fundamental objections to the removal.
