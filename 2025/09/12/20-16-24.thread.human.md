The thread discusses a discrepancy in how Git passes BASE, LOCAL, REMOTE, and MERGED variables to merge tools. Initially reported by Randall Becker, the issue centered on these variables not being available as environment variables in custom merge scripts despite documentation implying they would be. Johannes Sixt clarified that the variables are actually shell variables only available to tools included via Git's mergetools/ directory infrastructure.

Junio Hamano has now confirmed this is the expected behavior - the variables are designed as shell variables for tools that are dot-sourced from mergetools/, not as environment variables for standalone scripts. The proper way to integrate a new tool is to add it to the mergetools/ directory where it can access these variables directly. While Randall found a workaround using explicit exports in custom scripts, Junio's response indicates this isn't the intended usage pattern.

The discussion is converging on updating the documentation to better explain:
1) The shell variable vs environment variable distinction
2) The expected integration method via mergetools/ directory
3) The dot-sourcing mechanism used by git-mergetool--lib

While the current behavior won't change, the documentation improvements should prevent similar confusion in the future. Randall's workaround remains viable for those needing standalone custom tools, though it's not the recommended approach.
