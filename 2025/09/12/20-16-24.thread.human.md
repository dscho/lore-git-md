This thread explores why custom Git mergetool scripts can't access the BASE, LOCAL, REMOTE, and MERGED variables as documented. Randall Becker initially reported the issue, thinking these should be environment variables. Johannes Sixt clarified they're actually shell variables passed to built-in mergetools (included via fragments from Git's mergetools/ directory), not exported to the environment - explaining why they don't appear in `env` output but work for Git's bundled tools.

The discussion has hit a snag. Johannes, while knowledgeable about the shell/environment distinction, now finds the mergetool implementation too complex to analyze further. He suggests a practical workaround: copying an existing mergetool script from Git's source rather than writing a custom one from scratch. This implies the current behavior - where built-in tools get these values automatically but custom ones must find workarounds - may be too entrenched to easily change.

The core questions remain open: should the documentation be updated to clarify this distinction, or should the implementation change to support custom tools better? With Johannes unable to dig deeper and no maintainer input yet, the thread may need fresh eyes to move forward. For now, custom mergetool authors must either adapt existing scripts or parse working index files directly.
