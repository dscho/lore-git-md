This thread explores an issue Randall Becker encountered with Git's mergetool functionality, specifically around how variables like BASE, LOCAL, REMOTE, and MERGED are passed to custom mergetool scripts. Initially, Randall thought these were environment variables that should appear in `env` output, but Johannes Sixt clarified they are actually shell variables passed directly to script fragments included from Git's mergetools/ directory.

In his follow-up, Randall synthesizes the current understanding: built-in mergetools (those packaged with Git) get these variables through shell inclusion, while custom mergetools don't have access to them through the documented mechanism. He notes this forces custom tools to work around the limitation by parsing working index files instead. The discussion has revealed a potential documentation mismatch - the variables are shell variables for included fragments, not environment variables available to all mergetools.

The thread now centers on whether this behavior is intentional (requiring documentation clarification) or a bug in variable scoping. While Johannes' explanation about shell vs environment variables makes technical sense, Randall's follow-up highlights the practical consequence: custom mergetools can't use the documented variables as expected. The next steps would be confirming whether the variables are properly available in the shell context for included fragments, and deciding whether to adjust the documentation or the implementation to better match user expectations.
