Randall Becker reported that the documented mergetool environment variables (BASE, LOCAL, REMOTE, MERGED) weren't being passed to custom mergetool scripts on Cygwin and NonStop platforms. He provided detailed reproduction steps showing the variables missing from the environment during merge conflict resolution.

Johannes Sixt clarified that this appears to be a documentation misunderstanding - the variables are meant to be passed as shell variables (directly available in the script's scope) rather than environment variables (which would appear in `env` output). He pointed to the example scripts in the mergetools/ directory, which are shell fragments rather than standalone executable scripts, as evidence of this intended behavior.

The discussion now centers on whether the documentation should be clarified to better explain this distinction between shell variables and environment variables. While the original report suggested a potential bug, Johannes' response indicates the behavior may be working as designed, just not clearly documented. The platform-specific aspects may be relevant only if further investigation shows the shell variables aren't being set correctly in those environments.
